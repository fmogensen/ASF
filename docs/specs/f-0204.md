# F-0204 — "no Actions job has that name" is not evidence the name belongs to Actions

`merge_skipped: path-filtered` (the default) lets a PR merge on its checks while a required check
is *missing* — never created on the head — on one test:

```python
for n in missing:
    if not any(required_name(j.get('name'), (n,)) for j in jobs):
        out[n] = f'{n} not created by the workflow — satisfied (run completed, {gate} success)'
```

`asf/harvest/lane.py:3290-3293`. `jobs` there is every job of every **GitHub Actions** run on the
head. So the test reads: *no Actions job answers for this name*. The conclusion drawn from it is:
*the workflow's own path filter never created it*.

Those are not the same sentence. A required check that Actions never creates because it is not
Actions' at all — a third-party app's check run (a coverage bot, a code-quality app, a
deploy-preview), or a plain commit status posted by an external CI — matches the test exactly, at
every moment before it reports. Branch protection requires it; the lane counts it satisfied; the
PR merges on its checks with a required check that never ran. The one thing that check was for is
the one thing it did not do. A slow third-party app is an ordinary event, and every PR in the
product is exposed for as long as that app takes to post.

This card is not "stop counting missing checks". The parking incident `path-filtered` fixed
(`e0f09258d`) is real and stays fixed. It is: **"missing" is satisfied only against positive
evidence that the name is a check GitHub Actions creates — and the head's own workflow files are
that evidence.** A job a `paths:` filter never ran is still written down in `.github/workflows` on
the head; a third-party check is written down nowhere there.

| # | Chosen | Against | Why |
| --- | --- | --- | --- |
| C1 | **The workflow files at the PR head are the evidence**: a missing required check is satisfied only when some workflow at that sha declares a job answering for its name. | The card's other suggestion — "it appeared as an Actions check on an earlier run" (walk the trunk's recent runs and their jobs). | The workflow files are *complete and authoritative at the sha being judged*: every job Actions can create on that head is in them, including the one a `paths:` filter kept from running — precisely the case that must stay merging. ### In and out

**In.** The `missing` clause of `path_filtered`; the workflow-file reader and its name scan; the
per-head memo; the refusal and satisfaction lines; the three documents of P15; the tests.

**Out.** The `skipped` clause (C7). `merge_skipped: never`. The completed-runs guard (P2). The
`landing_checks_missing` clock and the local-gate fallback behind it (P4) — this card decides
whether a missing check is *satisfied*, never what happens to one that is not. Deploys, which
never count a skipped job green. The merge queue's own required-set judgement. `parse_runs_on`
and everything else the CI pool does with these files. No new config key (C9), no new state file,
no new command.

## The design

### 1. `asf/ci_pool.py` — the constant, and the scan beside `parse_runs_on` (`:559`)

`WORKFLOW_DIR` is lifted out of `GitHubBackend` to module scope (P16: nothing but `runs_on` reads
it, and `runs_on` keeps working word for word), so a second module can name the same path:

```python
#: Where GitHub Actions reads a repository's workflows, and the extensions it reads there.
WORKFLOW_DIR = '.github/workflows'
WORKFLOW_EXT = ('.yml', '.yaml')
```

```python
_JOB_KEY = re.compile(r'^([A-Za-z_][\w.\-]*):\s*(.*?)\s*$')


def parse_job_names(text):
    """The check names one workflow file can put on a commit: every key of its top-level
    ``jobs:`` block, and each of those jobs' own literal ``name:``. A line reader, not a YAML
    parser (this package takes no dependency): the job keys are the lines at the first indent
    under ``jobs:``, and a job's own keys are the lines at the first indent inside it — so a
    step's ``name:`` (deeper) and a ``run: |`` body are never read as one. A name built from an
    expression (``${{ … }}``) is not a literal and is left out; its job key still stands. Empty
    for a file with no ``jobs:`` block. Used to tell a required check GitHub Actions can create
    from one it never will (F-0204)."""
    rows = [(len(l) - len(l.lstrip()), l.strip()) for l in (text or '').splitlines()
            if l.strip() and not l.lstrip().startswith('#')]
    at = next((k for k, (ind, c) in enumerate(rows) if ind == 0 and c == 'jobs:'), None)
    if at is None:
        return []
    names, job_indent, inner = [], None, None
    for ind, content in rows[at + 1:]:
        if ind == 0:
            break
        if job_indent is None:
            job_indent = ind
        m = _JOB_KEY.match(content)
        if ind == job_indent:
            inner = None
            if m:
                names.append(m.group(1))
        elif names and ind > job_indent:
            inner = ind if inner is None else inner
            if ind == inner and m and m.group(1) == 'name' and m.group(2):
                value = m.group(2).strip('\'"')
                if value and '${{' not in value:
                    names.append(value)
    return list(dict.fromkeys(names))
```

### 2. `asf/harvest/lane.py` — the read, at the head, once per pass

`ci_pool` joins the module imports (`:108`, P17). The `MERGE_SKIPPED_PATH` comment (`:207-216`)
gains its clause: *a workflow that never created a job **it declares***.

`GitHubHost.__init__` (`:3112`) gains one memo beside `_trunk_runs` (`:3123`):

```python
        self._wf_jobs = {}     # head -> ({job name: file}, why): the workflows there, one pass
```

```python
    def workflow_jobs(self, head):
        """``({name: file}, why)``: every check name the workflows at ``head`` can create — each
        job key under a workflow's ``jobs:``, and each job's literal ``name:``
        (:func:`asf.ci_pool.parse_job_names`) — read off ``.github/workflows`` at that sha, once
        per head per pass. ``(None, why)`` when the directory, or any one file in it, did not
        read: a partial list is not evidence that a name is not Actions', and nothing is
        satisfied off it (F-0204)."""
        if head in self._wf_jobs:
            return self._wf_jobs[head]
        base = f'repos/{self.slug}/contents'
        listing = H.gh_json(['api', f'{base}/{ci_pool.WORKFLOW_DIR}?ref={head}'], None)
        got = (None, f'{ci_pool.WORKFLOW_DIR} did not read at {head[:9]}')
        if isinstance(listing, list):
            out = {}
            for e in [e for e in listing if isinstance(e, dict) and e.get('type') == 'file'
                      and str(e.get('name') or '').endswith(ci_pool.WORKFLOW_EXT)]:
                rc, text, _err = H._gh(['api', f'{base}/{e.get("path")}?ref={head}',
                                        '-H', 'Accept: application/vnd.github.raw'])
                if rc != 0 or not text.strip():
                    out, got = None, (None, f'{e.get("path")} did not read at {head[:9]}')
                    break
                for n in ci_pool.parse_job_names(text):
                    out.setdefault(n, e.get('name'))
            if out is not None:
                got = (out, None)
        self._wf_jobs[head] = got
        return got
```

### 3. `asf/harvest/lane.py` — the rule (`path_filtered`, `:3256`)

Its docstring's missing sentence becomes: *a missing one when no completed run has a job of that
name **and some workflow at the head declares a job that answers for it** — a path filter that
never created a job the CI does have. A required check no workflow at the head declares is not
Actions' to skip (a third-party app, a commit status from outside Actions): it is never
satisfied.* The method gains a third return, `refused`.

```python
        gate = ', '.join(sorted(passed))
        out, refused = {}, {}
        for n in skipped:                                   # unchanged (C7)
            ...
        declared, unread = self.workflow_jobs(head) if missing else ({}, None)
        for n in missing:
            if any(required_name(j.get('name'), (n,)) for j in jobs):
                continue
            src = required_name(n, declared) if declared else None
            if src:
                out[n] = (f'{n} declared in {declared[src]} and not created by the workflow — '
                          f'satisfied (run completed, {gate} success)')
            elif unread:
                refused[n] = (f'{n} is not green and the workflows at the head did not read '
                              f'({unread}) — nothing vouches it is a check Actions creates: '
                              f'it waits')
            else:
                refused[n] = (f'{n} is not green and no workflow at the head declares a job for '
                              f'it — it is not a check Actions skipped (a third-party check, a '
                              f'commit status): it waits')
        return out, None, refused
```

Every early return of `path_filtered` gains the third element: `return {}, None, {}` for no head,
no runs and unreadable jobs; `return {}, f'workflow run(s) …', {}` for a run still going.

### 4. `asf/harvest/lane.py` — the callers

`not_green` (`:3239`) returns `(passed, skipped, missing, satisfied, running, refused)`, with
`refused` `{}` unless `path_filtered` ran:

```python

                merge_skipped(self.product.conventions) == MERGE_SKIPPED_PATH:

                                                             passed)

                [n for n in missing if n not in satisfied], satisfied, running, refused)
```

`check_gate` (`:3445`) unpacks the sixth and prints it right after the satisfied lines, before the
skipped branch:

```python

                                                                                checks)
        ...
        for why in satisfied.values():
            lane.out(f'harvest: {b}: PR #{number} {why}')

```

`recheck` (`:3232`) ignores it: `_passed, skipped, missing, _ok, running, _why = self.not_green(…)`.

### 5. What it looks like when it is there

A PR whose CI path-filters `p1-e2e`, a job `ci.yml` declares — unchanged behaviour, one better
line:

```
harvest: worker/T-0001: PR #7 m8-e2e skipped by the workflow — satisfied (run completed, gate, gate-tests success)
harvest: worker/T-0001: PR #7 p1-e2e declared in ci.yml and not created by the workflow — satisfied (run completed, gate, gate-tests success)
```

The same PR, where `p1-e2e` is a third-party app's required check that has not reported — today it
merges, after this card it waits:

```
harvest: worker/T-0001: PR #7 m8-e2e skipped by the workflow — satisfied (run completed, gate, gate-tests success)
waiting worker/T-0001: PR #7 p1-e2e is not green and no workflow at the head declares a job for it — it is not a check Actions skipped (a third-party check, a commit status): it waits
waiting worker/T-0001: PR #7 required check(s) not run — p1-e2e (landing_checks_missing: wait, 0/30 min)
```

## Records

| What | Where | What it says |
| --- | --- | --- |
| **The satisfied line** | the tick's stdout, the harvest log | `PR #N <check> declared in <file>.yml and not created by the workflow — satisfied (run completed, <passed> success)` — the file that vouched for the name is now part of the record of why a PR merged with a check that never ran. |
| **The refusal line** | the tick's stdout, the harvest log | `PR #N <check> is not green and no workflow at the head declares a job for it — it is not a check Actions skipped (a third-party check, a commit status): it waits`, or `… the workflows at the head did not read (<why>) …`. One per refused name, per pass. |
| **The lane record** | the branch's row: `WAITING_CI`, reason `required checks missing: <names>` | Unchanged in shape and in wording. A refused name stays in `missing` and takes the path that already exists for it, including the `landing_checks_wait_min` clock (P4). Nothing about provenance is persisted. |
| **The workflows at a head** | memory only: `GitHubHost._wf_jobs`, one pass | `{head: ({job name: file}, why)}`. Never written to `state_dir`, never carried across passes — a head's workflows are read again next pass, and a new head is a new key. |
| **What is not written** | — | No state file, no record card, no new config key, no new command, no doctor row, no schema change, no `sessions.jsonl` entry, no forge write. The only new forge traffic is a `GET` of `.github/workflows` at a head, and only for a PR with a missing required check under `merge_skipped: path-filtered`. |

## Stories

- S-51850: A missing required check is counted path-filtered only against a job the head's own workflows declare — `ci_pool.parse_job_names` scanning a workflow file's `jobs:` block for its job keys and their literal names (a line reader beside `parse_runs_on`, no parser and no dependency), `WORKFLOW_DIR` lifted to module scope, `GitHubHost.workflow_jobs` reading `.github/workflows` at the PR head through the contents API once per head per pass, `path_filtered` satisfying a missing name only when `required_name` matches it to a declared job and refusing it in words otherwise, an unreadable listing or file satisfying nothing, the skipped half and `merge_skipped: never` untouched and paying no call, the refusals carried by `not_green`'s new `refused` and printed by `check_gate`, and the three documents stating the provenance clause — acceptance: `python3 -m unittest -v tests.test_ci_pool.WorkflowJobNames tests.test_lane.PathFilteredRequiredCheck`

  - [ ] A required check absent from every completed Actions run on the head and declared by no workflow file at that head is not satisfied: the gate returns no merge and the branch records WAITING_CI naming that check
  - [ ] The lane prints one line per refused name saying no workflow at the head declares a job for it, so an operator can tell a third-party check from a path-filtered one
  - [ ] A required check absent from every run but declared by a job of a workflow at the head is still satisfied and the PR merges on its checks, and the satisfied line names the file that declared it
  - [ ] A declared job's literal name answers for a required check, and a required name whose first word is a declared job (a matrix leg, a called workflow's caller/inner) is satisfied by that job
  - [ ] When the head's workflow directory, or any single file in it, does not read, no missing required check is satisfied: each waits, with a line saying the workflows at the head did not read
  - [ ] A skipped required check whose every answering job concluded skipped is still satisfied with no workflow read, in the same pass in which an undeclared missing check is refused
  - [ ] A PR with no missing required check makes no workflow-contents read, and under merge_skipped: never neither the runs nor the workflows at the head are read
  - [ ] The workflow scan yields a file's job keys and each job's literal name only: a step's name, a run-block body's jobs-shaped lines and an expression name are not yielded (the expression job's key still is), and a file with no jobs block yields nothing
  - [ ] The workflows at a head are read once per head per pass: the gate and the recheck before MERGING reach the same verdict off one read
