# F-0075 — Redaction is a gate on every write path

> Operator names and secrets never reach a record or a public repo. Every path that commits or
> pushes — the tick, the harvest, a session, a human — runs one redaction check and refuses when
> a line it would publish carries an operator name or a secret.

## 1 · Decisions

### Where this starts from (the checkout on `origin/main`, b0a50d2)

- The only name check is `tools/check_generic.sh`: a shell script that greps **every tracked file
  of the ASF repo** against `tools/forbidden-names.txt` (plus an optional `--extra` private list).
  It runs from `.githooks/pre-commit`, i.e. only when a human commits in this repo. It is not in
  the installed package (a pipx install has no `tools/`), so no product repo, no record and no
  factory code path can call it.
- The tick commits the record clone in `asf/tick/shadow.py:commit_local` and pushes it in
  `shadow.push` (callers: `tick.commit_and_push`, `tick.run_shadow`, and `migrate` in
  `asf/schema.py:222`). Neither looks at content. Since `6de95c9` (B-0030, B-0044) `push` is not
  one push: it is `_push_once`, then up to `PUSH_RETRIES` (3) rounds that fetch, rebase onto a
  moved `origin/<branch>` — re-deriving through `_resolve_by_ownership` when the rebase conflicts
  — and `_push_once` again. Every round can publish commits that did not exist when the first
  attempt was scanned. That this one function is now the only way the clone reaches origin is
  what makes a single in-process gate here cover the tick's every push.
- `asf/hermetic.py` is now the one builder of a child's environment (`hermetic.build`): it drops
  the git-hook variables (`hermetic.GIT_HOOK`) and the caller's identity
  (`hermetic.CALLER_IDENTITY` — `ASF_PRODUCT`, `ASF_JOB`, `BACKLOG_ID_RANGE`) and pins
  `init.defaultBranch`. `harvest.gate_env` delegates to it. It keeps `ASF_HOME` and every other
  variable, so a scanner running as a gate's child still sees the operator's secret variables
  (D6) and private list.
- The harvest pushes from two places in `asf/harvest/harvest.py`. `harvest_branch` (a worker
  branch) commits `harvest: regenerate index.json` on a record branch, runs `run_gate`, and
  pushes with `push_ff` to the trunk or `push_branch` for a code branch; a failure is a plain
  `hold(job, reason)`. `land_ff` (a pushed `origin/<branch>` landing on the trunk) runs
  `product_gate` and pushes with `push_ff`; a failure is `hold_with_correction`, which since
  `7c8c756` asks `asf/workers/lifecycle.py:hold` for the correction, the round and the cap. None
  of these gates looks for names or secrets.
- A session commits and pushes its own branch in its worktree; the worktree shares the product
  repo's hooks, and the product repo has none from ASF.
- The source of the 2026-09-21 leak is already closed: `03728fd` took `account` out of the
  `launch` event and `50846e3` made session lines carry `account_index` (`a<n>`) rather than a
  name (B-0023). That commit's own subject says *"the redaction gate is the rest"*: this Feature
  is that gate. The stale docstring at `asf/tick/step_wave.py:14` still says a launch event carries
  the account, and is corrected as part of this Feature.

### In

- One scanner, in the package: `asf/redact.py` and the `asf redact` command.
- The tick's commit and push call it in-process; they cannot skip it.
- The harvest calls it before every push; a finding holds the branch.
- `asf hooks install` also writes a git `pre-commit` and `pre-push` hook into the product repo
  and the record checkout; a session's worktree inherits them, and `spawn` makes sure they are
  there before it launches a session.
- `asf doctor` shows whether the hooks are in place.
- ASF's own repo: `tools/check_generic.sh` becomes a thin wrapper over the scanner, and
  `.githooks/` gets a `pre-push`, so there is one list and one matcher everywhere.
- A local ledger of refusals.

### Out

- **Transcripts and tool output** — the redaction hook on what a session *prints or reads* is
  F-0062. This Feature gates what is *committed or pushed*. F-0062 may call the same scanner.
- **Scanning history and dependencies in CI** — F-0069. This Feature scans what is about to be
  published, not what already is.
- **Rewriting history** that already carries a leak. The gate refuses new lines; a cleanup of
  published history is an operator action, not a gate.
- **Text sent through the forge's API** (PR titles and bodies, issue comments). Nothing in the
  factory sends one today (`pr_create_line` only prints a command). The first path that does
  must call `redact.scan_text` before it sends; that is recorded here, not built.
- **Commit metadata**: author, committer and the `Signed-off-by:` / `Co-Authored-By:` trailers.
  Those carry the identity the operator chose to publish under, and every commit is required to
  carry the sign-off.
- **`--no-verify`.** A git hook can be skipped by the one who runs git. The tick and the harvest
  do not depend on hooks (they call the gate in-process), and the harvest re-scans every commit
  before it lands, so a skipped hook cannot reach the trunk. A session that skips its hook can
  still publish its own branch; the standing rules forbid `--no-verify`, and the deny rule that
  makes it impossible for a session is F-0062's.

### Preconditions

- The account names come from `worker_pool.accounts[].name` in `~/.ASF/config.yaml`. With no
  config (CI, a fresh machine) that source is empty, not an error.
- The operator's private list, when kept, is `$ASF_HOME/redact-names.txt` — `ASF_HOME` is the
  home `asf/env.py:18` already resolves, default `~/.ASF` — same format as
  `tools/forbidden-names.txt`. It is never committed. Absent → empty, not an error.
- Git ≥ 2.9 (`core.hooksPath`, `git rev-parse --git-path hooks`), which every supported platform
  has.

### Choices

| # | Choice | Chosen | Against | Why |
|---|---|---|---|---|
| D1 | Where the gate sits | At the git operations: before every commit (the staged diff) and before every push (the unpublished commits) | At every file writer (`Context.event`, `asf new`, groom, file-bugs…) | A line in a working tree is not published; a commit or a push is. Two choke points per repo instead of a dozen writers, and a writer added later is covered without anyone remembering. |
| D2 | What a refusal does | Refuse, and say where | Replace the match with `[redacted]` and commit | The card says refuse. A silent rewrite hides the writer that produced the line, and it would go on producing it. |
| D3 | What is scanned on a commit / a push | Added lines only (`git diff -U0`), plus the commit message minus trailers | The whole tree, as `check_generic.sh` does | One old line would otherwise block every later commit of every path, including the tick. The whole-tree mode stays, as `asf redact --tree`, for ASF's own check and for an operator auditing a repo. |
| D4 | Which commits a push scans | Every commit reachable from the pushed sha and from no `refs/remotes/origin/*` ref, each against its parent | The range `origin/<branch>..sha` | One rule serves a new branch, an existing branch, a rebased branch and the trunk; the rebased commits the harvest lands are new shas, so they are scanned again. |
| D5 | Where the operator's names come from | Three sources, merged: the pool's account names; the private list; the scanned repo's own tracked `tools/forbidden-names.txt` when it has one | One list the operator maintains by hand | The account names are already in config: copying them into a list is the "has to be remembered" the card rules out. The private list keeps what config does not hold (people, hosts). The repo list is how ASF's public list keeps working. |
| D6 | What counts as a secret | Built-in rules for well-known token shapes, plus the literal value of every environment variable whose name says it is a secret (`TOKEN`, `SECRET`, `KEY`, `PASSWORD`, `PASS`, `CREDENTIAL`; value ≥ 12 characters) | Built-in shapes only; or an entropy heuristic | Shapes catch the common vendors. The environment catches the operator's own secrets whatever shape they are, with no false positive. Entropy flags hashes and ids that the record is full of (shas, `index.json`). |
| D7 | Is there an inline allow marker | No | `# redact: allow` on the line | A gate that the line it checks can switch off is not a gate: a session could write the marker too. A false positive is fixed in the private list or in the rule. Test fixtures build a token from parts, as `tests/test_check_generic.py` already does for names. |
| D8 | What a finding prints | `<file>:<line>: <kind> (<source>)`, never the matched text | The line, as `grep -H` prints it today | The refusal is printed into tick logs and session transcripts; echoing the secret there is the leak the gate prevents. |
| D9 | Only for public repos? | Always on, for every repo the factory writes | A `public: true` product key | A private repo becomes public (this one did). Being wrong costs a refused commit; being right costs nothing. |
| D10 | How the hooks are installed | `asf hooks install` writes them; `spawn` installs them itself when missing and refuses to launch when a hook file that is not ASF's is in the way | Documentation telling the operator to install them | "Nothing has to be remembered": a session is never launched into a repo with no push gate. A hook file ASF did not write is never edited or overwritten — the operator adds one line, and is told which. |
| D11 | ASF's own `check_generic.sh` | Keep the script and its interface; it calls `python3 -m asf.redact --tree` from the checkout | Delete it; or keep two matchers | One matcher. The script's callers (`.githooks/pre-commit`, `tests/test_check_generic.py`) keep working unchanged. |
| D12 | Git's own variables in the installed hook | Keep them — the hook `exec`s the scanner with `GIT_DIR`, `GIT_WORK_TREE` and `GIT_INDEX_FILE` as git set them | `unset` them, as ASF's tracked `.githooks/pre-commit` does (`hermetic.GIT_HOOK`) | Those three name the repo and the index that are being committed, which is exactly what must be scanned; `git commit --only <path>` stages into a *temporary* index, and a scanner that unset `GIT_INDEX_FILE` would clear the real commit and scan the wrong one. ASF's tracked hook unsets them for a different reason — it also runs the suite, which makes temporary repos. |

## 2 · The design

### 2.1 `asf/redact.py` — the one scanner

```python
class Finding(NamedTuple):
    path: str      # repo-relative file, or 'commit <sha7> message'
    line: int      # 1-based line in the new file / the message
    kind: str      # 'name' | 'secret'
    source: str    # 'worker_pool.accounts' | 'redact-names.txt' | 'tools/forbidden-names.txt'
                   # | 'env:<VAR>' | 'rule:<rule-id>'

class Refused(Exception):
    findings: list[Finding]

def patterns(repo=None, cfg=None, environ=None, extra=()) -> list[Pattern]
def scan_text(path, text, pats) -> list[Finding]
def scan_staged(repo, pats) -> list[Finding]          # git diff --cached -U0
def scan_unpublished(repo, head, pats) -> list[Finding]  # D4
def scan_tree(repo, pats) -> list[Finding]            # every tracked file but LICENSE
def gate(findings, where, product=None) -> None       # raises Refused; writes the ledger (§4)
def format_findings(findings) -> list[str]            # D8
```

**Patterns.** Each carries `kind`, `source` and a compiled regex, all case-insensitive.

- *Names* (D5): each pool account name as `\b<re.escape(name)>\b`; each line of the private list
  and of the repo's `tools/forbidden-names.txt` as an extended regex (blank lines and `#` comments
  skipped — the format `check_generic.sh` reads today). `extra` is the `--names <file>` option.
- *Secrets* (D6), the built-in rules, each with an id:
  `private-key` (`-----BEGIN [A-Z ]*PRIVATE KEY-----`), `aws-access-key` (`AKIA[0-9A-Z]{16}`),
  `github-token` (`gh[pousr]_[A-Za-z0-9]{36,}`, `github_pat_[A-Za-z0-9_]{50,}`),
  `anthropic-key` (`sk-ant-[A-Za-z0-9_-]{20,}`), `openai-style-key` (`sk-[A-Za-z0-9]{32,}`),
  `slack-token` (`xox[abprs]-[A-Za-z0-9-]{10,}`),
  `jwt` (`eyJ[A-Za-z0-9_-]{10,}\.eyJ[A-Za-z0-9_-]{10,}\.`),
  `url-password` (`[a-z][a-z0-9+.-]*://[^/\s:@]+:[^/\s:@]+@`). Each rule is written so that its
  own source text does not match it; `test_the_real_repo_is_clean` holds that.
- *Environment values* (D6): for every variable in `environ` (default `os.environ`) whose name
  matches `TOKEN|SECRET|KEY|PASSWORD|PASS|CREDENTIAL` and whose value is ≥ 12 characters, the
  value as a literal. The source is `env:<VAR>` — the name, never the value.

**What is read.**

- `scan_staged`: the `+` lines of `git diff --cached -U0 --no-color --no-ext-diff`, with their
  new-file line numbers from the hunk headers. Binary files are skipped.
- `scan_unpublished(head)`: `git rev-list <head> --not --remotes=origin`, and for each commit the
  `+` lines of `git show -U0 --format= <sha>` plus its message (`%B`) with the trailer block
  (`git interpret-trailers --parse` lines) removed.
- `scan_tree`: every file of `git ls-files` except `LICENSE`, every line.

**The command.**

```
asf redact --staged              [--product p] [--names FILE]...
asf redact --pre-commit          [--product p]   # --staged, recorded as where='hook-pre-commit'
asf redact --unpublished [REV]   [--product p] [--names FILE]...   # REV defaults to HEAD
asf redact --pre-push            [--product p]   # reads git's pre-push stdin
asf redact --tree                [--names FILE]...
```

Runs in the cwd's repo. It is **not** a record command and does not go through
`cli.resolve_record` (8c25fa7): the repo it scans is whichever one it was invoked in — a product
repo, a record checkout, or ASF itself — and it prints no `record: <path>` line. `--product` is
only how the ledger (§4) finds its product; without it the scan still runs and writes nothing.
Clean → `redact: clean`, exit 0. Findings → one line per finding
(`format_findings`), then `redact: refused — N finding(s); no line above is printed as it was`,
exit 1. Not a git repo, or an unreadable list → exit 2 with the reason. `--pre-push` reads
`<local ref> <local sha> <remote ref> <remote sha>` lines, skips deletions (local sha all zeros),
and runs `scan_unpublished` for each local sha. It is registered in `asf/cli.py` like every other
command, so `plugin_build` picks it up.

### 2.2 The tick — `asf/tick/shadow.py`

- `commit_local(path, message)`: after `git add -A` and the no-change check, and before
  `git commit`, it calls `redact.gate(redact.scan_staged(path, pats), where='tick-commit', …)`.
  On `Refused` it unstages (`git reset -q`) and re-raises. No commit is made.
- `push(path, out=None, retries=PUSH_RETRIES)`: before **each** `_push_once` — the first, and the
  one at the end of every retry round — `redact.gate(redact.scan_unpublished(path, 'HEAD', pats),
  where='tick-push', …)`. Scanning once at entry would not do: a round rebases onto a moved
  origin and may re-derive the tree through `_resolve_by_ownership`, so the shas that the later
  `_push_once` publishes are new ones that no earlier scan saw (D4).
- `tick.commit_and_push` catches `Refused` and prints:

  ```
  tick: commit refused — redaction: 1 finding
    metrics/events/2026-09-22.jsonl:3: name (worker_pool.accounts)
  NEEDS OPERATOR: a line the tick wrote carries an operator name or a secret — find its writer; `git add -A && asf redact --staged` in <clone> shows it again
  ```

  and returns 1. The clone is derived state: the next run resets it (the lines that tick appended
  are lost, as they already are on a refused push). `run_shadow` and `schema.py`'s migrate print
  the same lines and return 1.
- The docstring at `step_wave.py:14` is corrected: a launch event carries item, job, model and
  brief kind — no account.

### 2.3 The harvest — `asf/harvest/harvest.py`

Both push paths scan every unpublished commit, after their own gate and before their push (and
before their dry-run line), with the repo of the branch (the product repo or the record) as
`repo`. The reason text is `redaction: <n> finding(s) — <first finding>` (formatted per D8), and
the gate writes its ledger lines (§4) with `where='harvest'`.

- `harvest_branch`: after the rebase, the index regeneration and `run_gate`, and before `push_ff`
  or `push_branch`, `scan_unpublished(tmp, sha, pats)`. Findings →
  `hold(job, 'redaction: …')`, as its other gate failures are, and no push.
- `land_ff`: after `product_gate`, and before `push_ff`, the same scan. Findings →
  `hold_with_correction(state_dir, branch, record, 'redaction', <every formatted finding, one per
  line>, out)`, and no push. `lifecycle.hold` hands the branch back to its session with the
  findings as the correction, so the session that wrote the line removes it. At `ROUND_CAP` it
  already stops climbing, marks the correction `at_cap` for the ADJUDICATE row, and flags the
  operator on a second hold at the cap (B-0048). A redaction hold goes through that rule like any
  other hold, with no special case.

### 2.4 Sessions and humans — the git hooks, `asf/hooks.py`

`asf hooks install --product p` keeps writing the Claude Code settings and now also writes two
git hooks into each of `product.repo_dir` and `product.backlog_dir` (when set):

```sh
#!/bin/sh
# written by asf hooks install — the redaction gate (F-0075)
exec "<absolute asf>" redact --pre-commit --product <p>
```

(`--pre-commit` is `--staged` with `where='hook-pre-commit'`; the `pre-push` file runs
`redact --pre-push`, which gets git's stdin through `exec`.)

The hook does **not** unset git's `GIT_DIR` / `GIT_WORK_TREE` / `GIT_INDEX_FILE` (D12): they name
the very repo and index it has to scan. `exec` keeps them, and `scan_staged` runs `git diff
--cached` against the index git is actually committing.

- The hooks directory is `git rev-parse --git-path hooks` in that repo, so `core.hooksPath` is
  honoured and every worktree of the repo shares the hooks.
- A hook is *installed* when its file contains the line `asf redact --pre-commit` (resp.
  `--pre-push`) or `asf.redact --pre-commit` (resp. `--pre-push`), in any form. Installed → left
  alone. Absent → written, mode 0755. Present and not installed → not touched; the command prints
  `NEEDS OPERATOR: <path> is not asf's — add the line: "<asf>" redact --pre-push --product <p>`
  and exits 2.
- Running it twice changes nothing.

`spawn.make_worktree` calls `hooks.ensure_git_hooks(product)` first — after the `repo_dir` check
and before `lifecycle.may_launch` or any of its four paths: the worktree of an ended run that
it takes over as it stands (B-0025, B-0051), a worktree on a held branch already on origin
(B-0046, B-0048), a local branch with no worktree that is reused when it carries nothing and
refused with its commit count when it does (B-0025), and a fresh branch off the trunk. One call
before the branching covers all four, so no path can reach `git worktree add` without the hooks.
Missing hooks are written; a foreign hook in the way raises `SpawnError` carrying the same
`NEEDS OPERATOR` line, and the wave does not launch that row (D10).

`asf doctor` gains a row appended in `doctor.run` alongside the others as
`('redaction-hooks', True, ok, detail)`: ok with `pre-commit, pre-push in <n> repos`; not ok
naming each missing or foreign hook and the command `asf hooks install --product <p>`.

### 2.5 ASF's own repo

- `tools/check_generic.sh` keeps its usage (`[--extra <file>]`), its exit codes (0 clean, 1
  found, 2 usage or missing list) and its final `check_generic: clean` line. Its body becomes:
  `PYTHONPATH="$HERE/.." python3 -m asf.redact --tree --names "$PATTERNS_FILE"
  ${EXTRA_FILE:+--names "$EXTRA_FILE"}`, run from the repo root, with its own messages around it.
  The difference a reader will see: a finding prints `file:line: name (tools/forbidden-names.txt)`,
  not the offending line (D8).
- `.githooks/pre-commit` keeps the suite and `check_generic.sh`, and adds
  `python3 -m asf.redact --pre-commit` (staged lines against every source, including the pool
  accounts and the private list, which the tree check does not load without `--extra`).
- A new tracked `.githooks/pre-push` runs `python3 -m asf.redact --pre-push`, with the same
  `unset GIT_DIR GIT_WORK_TREE GIT_INDEX_FILE` preamble as `pre-commit` (the three names are
  `hermetic.GIT_HOOK`). That preamble is there because this hook also runs the suite, which
  makes temporary repos; the scanner alone does not need it, and the hooks of §2.4 do not carry
  it — see D12.

## 4 · Records

- **The refusal ledger** — `~/.ASF/state/<product>/redactions.jsonl`, local, never committed.
  One line per finding of a refused gate:
  `{"ts", "where": "tick-commit|tick-push|harvest|hook-pre-commit|hook-pre-push|cli", "repo": "<product repo|record>", "path", "line", "kind", "source", "job"?}`.
  Never the matched text. Written only when a product resolves; `asf redact` outside a product
  prints and writes nothing. Nothing reads it yet — it is the evidence a later metrics card or
  `asf status` can count.
- **The record** — nothing new is committed by this Feature. A refused tick commits nothing, so
  there is no event of the refusal in `metrics/events` (a refusal event could itself be what is
  refused). The tick's printed line and the ledger carry it.
- **Tick output** — the `tick: commit refused — redaction: …` block and its `NEEDS OPERATOR` line
  (§2.2), in the tick log.
- **Harvest output** — from `harvest_branch`, `HARVEST HOLD <job> redaction: <n> finding(s) —
  <first finding>`; from `land_ff`, `lifecycle.hold`'s line
  `held <branch>: redaction: … — back to its session (round <n>)` (or `— adjudicate pending` at
  the cap). The session registry gets the run's `correction` (`kind: redaction`, the formatted
  findings) and `rounds`, as for any other hold.
- **Files written into repos** — `pre-commit` and `pre-push` in the hooks directory of the product
  repo and the record checkout (untracked, local); in ASF's own repo the tracked
  `.githooks/pre-push`.
- **Files the operator keeps** — `~/.ASF/redact-names.txt` (optional, private).
