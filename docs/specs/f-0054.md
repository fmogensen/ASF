# F-0054 — the class is decided before anything is launched again

A session dies. The tick's health step reads the pid, finds it gone, and launches the work again
with a `CORRECTION:` paragraph on top of its brief (`asf/tick/step_health.py:96`,
`asf/workers/stall.py:238`). It does that whether the session died because the coder's own step
failed, because the network dropped in the middle of a `git fetch`, because the account's window
was spent, or because the account's login expired three days ago. Only the first of those four is
a failure of the work, and only the first can be answered by running the work again.

The other three are answered by a relaunch in the sense that a promise is answered by repeating
it. A spent window relaunches on the same stopped account until the reset; a dropped connection
gets a full cold retry with a correction brief, which reads as an accusation against a session
that did nothing wrong; and a missing credential relaunches for ever — the launcher refuses it
in `auth_env_values` (`asf/workers/runtime.py:311`) *every tick*, prints `NEEDS OPERATOR` every
tick (`asf/workers/wave.py:91`: the line is re-printed whenever it starts with that marker), and
nothing about the world changes between one tick and the next.

The pieces to tell those four apart are already in the tree, each owned by the caller that needed
it: `runtime.FAILURE_SIGNATURES` names `auth`, `quota-exhausted`, `permission` and
`unknown model` in a session's own result text (`asf/workers/runtime.py:465`);
`lifecycle.NETWORK_RE` names a transport error, but only for a push (`asf/workers/lifecycle.py:128`,
read only by `push_failure`, `:1547`); `headroom.LIMIT_RE` names a spent window
(`asf/workers/headroom.py:42`). What is missing is one vocabulary that says what to *do* with each
of them, one place that decides it, and the class printed where an operator can see it.

This spec adds that: a pure `asf/failure.py` with four classes — `credential`, `quota`,
`transport`, `work` — a retry policy per class, and one entry point, `classify`, fed by the two
sources the card names: the launcher's own result text, and the session's last beat. The stall
check prints the class on every failure line. The health step routes on it: a credential failure
raises one needs-operator line naming the product and stops that lane, and never relaunches; a
quota failure stops the lane until its reset and the item goes to another lane of the pool; a
transport failure gets one plain relaunch on the original brief, and the second in a row is the
operator's; only a work failure gets the correction, the hold and the round we write today.

## 1. Decisions

### 1.1 Preconditions

- **The four signatures already exist, in three modules, with one reader each.**
  `runtime.FAILURE_SIGNATURES` (`asf/workers/runtime.py:465`) is `(name, regex)` pairs over a
  session's own result text — `unknown model`, `auth`, `headroom.QUOTA_EXHAUSTED`, `permission`
  — read by `failure_reason` (`:474`), which reads the factory's structured `asf.cap` /
  `asf.run_cap` objects first because a session's own `result` prose is forgeable (F-0028 D9).
  `headroom.LIMIT_RE` (`asf/workers/headroom.py:42`) is the spent-window text, the session limit,
  the usage limit, a 429. `lifecycle.NETWORK_RE` (`asf/workers/lifecycle.py:128`) is the transport
  text, and its only reader is `push_failure` (`:1547`) — a *push*'s failure, never a launch's and
  never a session's.
- **`lifecycle.outcome_class` is a signature vocabulary, not an action one.**
  `OUTCOME_CLASSES` (`asf/workers/lifecycle.py:150`) is composed from the constants that write the
  strings — `finished`, `not pushed`, `empty branch`, `dead pid`, `pushed after stop`, the
  `FAILURE_SIGNATURES` names, `hook refused`, `network error`, `token cap`, `run cap`, `other` —
  and `outcome_class(result)` (`:1526`) maps an `end_reason` onto it. It has no consumer in the
  tree today. It is the right input to a classifier and the wrong thing to extend: twelve
  signatures do not tell a caller how many times to try again.
- **A retry with no round already exists, for exactly one case.** `push_retry` +
  `NETWORK_ERROR` (`asf/workers/health.py:434`, B-0097) retries a push the network dropped,
  prints `retry … — published again next pass`, and spends no round. `RETRY_CLASSES`
  (`asf/workers/lifecycle.py:127`) is that idea's name. This spec generalises the shape it
  already proved to a launch and to a session.
- **A quota failure of a *session* is already routed, and nothing routes a launch's.**
  `lifecycle.quota_exhausted(run)` (`:763`) is `end_reason == 'failed: quota-exhausted'`;
  `health` (`asf/workers/health.py:445`) calls `headroom.note_exhausted`
  (`asf/workers/headroom.py:188`), which records the reset in `~/.ASF/state/quota-limits.json`
  (`record_limit`, `:165`) and returns the line *"the item relaunches after the reset or on
  another account … no round spent"*. `attempts` (`asf/workers/lifecycle.py:769`) excludes such a
  run, and `hold_failed_corrections` (`asf/tick/step_health.py:250`) skips it. A launch that dies
  on a 429 has none of this.
- **The pool has exactly one door for "this account takes nothing".** `Pool.band(account)`
  (`asf/workers/pool.py:353`) returns `(state, why)`: a session-limit stop (`Pool.limit`, `:348`,
  over `headroom.active_limits()`) first, then `quota.band`. `pick_account` (`:444`) sorts every
  candidate through it and an account at `STOP` launches nothing and is named in the wait
  (`:526`). `asf capacity` (`asf/capacity.py:219`) and `asf quota`
  (`asf/workers/__init__.py:107`) print it. A new reason for an account to take nothing belongs
  there and nowhere else.
- **A credential is refused before anything is made, per account and per product.**
  `spawn` calls `runtime.auth_env_values(account, product_auth_env)` first — *"the account's
  credential files, read before anything is made: a refusal leaves nothing"*
  (`asf/workers/spawn.py:682`) — which raises `AuthEnvError` (`asf/workers/runtime.py:292`) with
  a `clear` hint and a message that already distinguishes the two scopes: `worker account <name>`
  versus `the product's conventions.auth_env` (`:337`). `asf doctor` probes the same credentials
  per account against the real remote (`asf/doctor.py:329`), so the clear command for a
  credential line exists already.
- **A repeated launch failure is already remembered, and a `NEEDS OPERATOR` one is exempted from
  the memory.** `wave.Failures` (`asf/workers/wave.py:58`) keeps `{job: {reason, count}}` in
  `~/.ASF/state/<product>/spawn-failures.json`: the first failure prints, the second identical one
  prints once as `NEEDS OPERATOR` with the clearing command, and after that the row waits
  silently — *except* that `note` returns the reason unconditionally when it starts with
  `NEEDS OPERATOR` (`:91`), which is precisely what an `AuthEnvError` message does. So a missing
  credential prints every tick today, by construction.
- **The correction is one function, and it is the only relaunch the health step makes.**
  `stall.correct_once(product, session, error_text, runtime)` (`asf/workers/stall.py:238`) writes
  `<brief>.correction.md` (the original plus `CORRECTION_HEAD` plus the error), launches it as
  `<job>-correction` under its own ledger line, marks `corrected: 1` on the original, and returns
  True for *launched*, not for *passed* (B-0085). `handle_dead` (`asf/tick/step_health.py:72`)
  is the router that calls it and counts `ctx.counts['relaunches'] += 1` (`:104`); a second death
  is the B-0062 hold, never a question to the operator (D-0049).
- **A run's own fields are enumerated.** `RUN_FIELDS` (`asf/workers/lifecycle.py:108`) lists what
  belongs to one launch and must never fold into the next (B-0041) — `corrected` and
  `operator_flagged` among them. A new per-run mark must be added there or it will be inherited
  by the next launch on the same job.
- **The stall check's failure lines are two, and neither carries a class.** `stall`
  (`asf/workers/stall.py:95`) prints `{STALL|DEAD:<5} {job:<24} silent {n}m` and returns
  `[(job, state, minutes)]`; `capped` (`:187`) prints `CAP {job} {measure} {value} over {limit}
  ({kind})`. The return tuple is unpacked positionally in three places:
  `step_health.dead_jobs` (`asf/tick/step_health.py:59`), `tests/test_workers.py:1916` and
  `tests/test_session_identity.py:577`.
- **The session's last beat is not read anywhere.** `runtime.read_result` (`:410`) returns the
  *result* line of the log's last run, rewinding at every `init` (B-0028); `init_line` (`:438`)
  the opening one. A session that died has no result line at all — that is what `DEAD` means —
  and the only thing read of it today is `step_health.log_tail` (`:31`), five raw lines pasted
  into a correction brief.
- **A session log is not masked; the worktree-setup log is.** `spawn.run_worktree_setup` runs
  every captured byte through `runtime.mask(…, secrets)` before writing (`asf/workers/spawn.py:650`).
  The runtime's own session log is the CLI's stream-json, written by the CLI. So any text taken
  from a beat may carry a secret, and may never be copied into a record or an event.
- **Whatever enters the record is redaction-gated.** `ctx.event` appends to
  `metrics/events/<day>.jsonl` *in the record clone* (`asf/tick/tick.py:171`), which the tick
  commits; every commit runs `asf.redact`, whose name patterns include the worker pool's own
  account names, and whose instruction is *"replace with lane-N"* (`asf/redact.py:457`). An
  account name in an event message would refuse the tick's own record commit. `needs-operator` is
  already an event kind (`asf/tick/tick.py:381`); the events stream has no schema.
- **The per-day, per-product relaunch count already exists.** The `ticks` stream carries
  `relaunches` as a required int (`asf/metrics/metrics.py:137`), written from `ctx.counts`
  (`asf/tick/tick.py:158`) by `tick_line` (`:604`) into `metrics/ticks/<day>.jsonl` (`:618`).
  `validate` refuses an undeclared key (`:169`) and requires every declared one (`:178`), and
  `import_sessions` builds the same line from a transcript (`asf/metrics/import_sessions.py:144`).
  `ctx.counts` has exactly two touch points in the tree.
- **`asf.size`, `asf.budget`, `asf.tokens` are the precedent for a pure top-level module** —
  stdlib only, no `Product`, no filesystem — and `tools/check_generic.sh` plus
  `tools/check_conventions.sh` refuse a product name or a path-shaped default anywhere in a
  tracked file. The gate is `python3 tools/run_tests.py` (one module per process, `ASF_GATE_MODULES`
  to narrow it) plus those two scripts.

### 1.2 In

- **`asf/failure.py`** (new, stdlib only, pure, importing nothing of `asf`) — the four classes,
  the three signature patterns, the signature-name table, the retry policy, and the printed
  forms: `CLASSES`, `RETRIES`, `CREDENTIAL_RE`, `QUOTA_RE`, `TRANSPORT_RE`, `SIGNATURE_CLASS`,
  `of_signature`, `of_text`, `classify`, `retries`, `may_relaunch`, `label`, `operator_text`.
- **`asf/workers/runtime.py`** — `last_beat(log_path)` and `beat_signature(rec)`: the last
  parsable record of the log's last run, and the signature its text carries. `FAILURE_SIGNATURES`
  keeps its names and takes its `auth` and quota patterns from `asf.failure`.
- **`asf/workers/headroom.py`, `asf/workers/lifecycle.py`** — `LIMIT_RE` and `NETWORK_RE` become
  references to `failure.QUOTA_RE` and `failure.TRANSPORT_RE`, so each pattern has one owner;
  every existing name keeps working. `RUN_FIELDS` gains `transport_retry`.
- **`asf/workers/stops.py`** (new, ~60 lines) — the credential stop table,
  `~/.ASF/state/credential-stops.json`: `record`, `active`, `clear`, `stop_path`. One file for the
  machine, as `quota-limits.json` is, and a stop that clears itself when the file it names reads.
- **`asf/workers/pool.py`** — `Pool.credential_stop(account)` and one branch in `Pool.band`;
  `lane_label(cfg, name)` → `lane-<n>`, the account's 1-based place in `worker_pool.accounts`.
- **`asf/workers/stall.py`** — `failure_class(session)`; `stall` returns `Stalled` namedtuples and
  prints the class; `capped` prints it too; `correct_once` gains `error_text=None` (relaunch on the
  original brief) and `mark=` (which field records the try).
- **`asf/tick/step_health.py`** — `handle_dead` routes on the class before it corrects anything;
  `credential_line`, `quota_route`, `transport_retry` beside today's `operator_line`.
- **`asf/workers/spawn.py`, `asf/workers/wave.py`** — the class of a refused launch, from the
  launcher's own result text; a credential refusal records the stop and prints once; `Failures`
  keys its memory on `(class, reason)`.
- **`asf/tick/tick.py`, `asf/metrics/metrics.py`, `asf/metrics/import_sessions.py`** —
  `ctx.counts['failures']`, the `failures` dict on the `ticks` stream and its validation.
- **`asf/cli.py`** — `asf failures [--days N] [--json]`: relaunches and failures by class, per day
  and per product, the read the card's third acceptance line is measured on.
- Tests: §3.1–§3.9, `tests/test_failure.py` (new), and the three positional-unpack sites of
  `stall()` updated.

### 1.3 Out

- **A new signature.** The patterns that name a spent window, an expired login and a dropped
  connection are the ones already in the tree; this change moves them to one owner and maps them
  onto an action. Widening `CREDENTIAL_RE` to catch a provider's new wording is a later one-line
  change against a failure we have actually seen.
- **Judging a *finished* session.** `failure_reason`, `judge`, `push_retry`, the hook-refusal
  hold, the unpushed-work hold and `widen_footprint` keep their present logic entirely. This spec
  classifies a *failed launch or session*; a run that wrote its result and ran to its end
  (`ran_to_its_end`, `asf/tick/step_health.py:230`) is publish's to route, as B-0150 settled.
- **Retrying a credential failure after a delay.** There is no delay after which a missing file
  exists. The stop clears when the file reads, or when the operator deletes the stop.
- **Asking the operator anything.** A needs-operator line states what the factory cannot decide
  and the command that clears it (D-0049). It is never a question, and a work failure never
  produces one — that is still the B-0062 hold's job.
- **A second retry for transport.** One. A transport error that is still there on the next tick is
  the host's or the network's, not a blip, and the operator is told once.
- **Holding the *item* on a credential or quota failure.** Neither is the work's fault: no round,
  no correction, no `rounds` increment, and nothing written onto the item's card. The lane stops;
  the item waits or goes to another lane.
- **Changing how a launch is *placed*.** `pick_account`, `headroom`, the S1 reserve, the cloud
  lane and the seat accounting are untouched. A credential stop reaches them the way a session
  limit does, through `band`.
- **A per-account view of credentials.** `asf doctor` already probes them. `asf failures` counts
  classes; it does not test a login.
- **Proving that the relaunch count actually falls.** A count that falls over weeks is not a
  property of a commit (D12). What a test holds is that a credential failure relaunches zero
  times, that a transport failure relaunches exactly once, and that the number is computed
  correctly from the record — including for days recorded before this change.
- **A new stream, a new item field, a new card key.** `failures` is one dict on the existing
  `ticks` stream; the needs-operator line is the existing event kind.

### 1.4 The choices

| # | Chosen | Against | Why |
| --- | --- | --- | --- |
| D1 | A new pure module `asf/failure.py` owning the four classes and the policy | extending `lifecycle.OUTCOME_CLASSES` and `outcome_class` | Those twelve names are *signatures* — what the text said — and the card asks for *actions*: never retry, route, retry once, correct. Two vocabularies at different altitudes; one maps onto the other, many-to-one. And the classifier must be importable by `runtime`, `headroom`, `lifecycle`, `spawn`, `wave`, `stall` and the CLI, which rules out any module that imports them: `asf.failure` imports nothing of `asf`, exactly as `asf.size` and `asf.budget` do. |
| D2 | `classify(signature=None, text='', default=WORK)` → `(cls, why)`: the signature's class when it names one, else the text's, else `work` | one function per call site, each matching its own regexes | One entry point is what makes the class *the same* class in the stall line, the launch line, the health route, the event and the report. `work` as the default is the safety property: an unrecognised failure keeps today's behaviour exactly — the correction, the hold, the round — so this change can only ever *remove* relaunches, never add one. |
| D3 | `why` is a name (`signature auth`, `text: transport`, `no signature`), never matched text | quoting the matched fragment, which reads better in a log | A session log is not masked (§1.1) and the class travels into an event in the record, where `asf.redact` gates every commit. A `why` built only from pattern names cannot leak a token, so the same string is safe on stdout, in the state dir and in the record. |
| D4 | `unknown model` and `permission` are `credential` | a fifth class, `configuration` | The card says "a credential **or configuration** failure" and gives them one policy: a needs-operator line, zero relaunches. A model label that does not exist and a login that expired are the same fact for the factory — the operator must change something before any run can succeed — and they arrive on the same code path. One class, two `why` values. |
| D5 | The credential stop is scoped: `worker account <name>` stops that lane; `the product's conventions.auth_env` and `unknown model` stop nothing and name the product | stopping the whole product on any credential failure | `AuthEnvError`'s own message already carries the scope (`asf/workers/runtime.py:338`). A broken login on one lane must not idle the other three; a product credential is broken on every lane, and stopping them all would be the same statement as stopping none, only louder. In both cases the needs-operator line names the product, which is what the card asks for. |
| D6 | The credential stop is a `quota.STOP` band with its own reason, through `Pool.band` | a check inside `pick_account`, or refusing the feeder row | `band` is the pool's single door for "this account takes nothing" (§1.1), and everything that shows the pool — `asf quota`, `asf capacity`, the wait line — reads it. One branch there makes a stopped lane visible in three views and routable in one, and lets a quota stop and a credential stop compose without either knowing the other. |
| D7 | The stop names the `var` and its file and clears itself when that file reads non-empty | an operator command to clear it, or a timed expiry | "Never retried" must not mean "never retried again, ever". The precondition the failure names is a file with a value in it; when that is true the reason to refuse is gone, and the launcher's own `auth_env_values` is the check — already paid for, already called before anything is made. No new command, no promise that time will help. |
| D8 | A transport failure relaunches **on the original brief**, through `correct_once(…, error_text=None)`, marked `transport_retry` | reusing the correction brief, or adding a second launcher | Everything about the launch is right except that the network dropped: the brief, the worktree, the ledger line and the new-job-and-new-log discipline (D-0048 part b) all still apply. What must not apply is `CORRECTION: the step failed with:` — that text tells a session its work was at fault, and it would be read as an accusation and answered as one. One parameter, not a second code path. |
| D9 | The second transport failure in a row is a needs-operator line, not a hold | falling through to the work path and holding the item | A hold spends a round and writes a correction onto the item: it says the work is at fault. Two dropped connections in a row say the host is. Paired with D2's default, this is the only place the change can *add* an operator line, and it costs one line per job per outage. |
| D10 | A credential needs-operator line prints **once** per unchanged cause; the state stays visible in the pool's band and in `asf failures` | re-printing every tick, as today | `Failures`' own doctrine is that a failure repeating identically is not news (`asf/workers/wave.py:58`), and the current `NEEDS OPERATOR` exemption (`:91`) is what makes a missing credential the loudest thing in every tick log for days. Silence is not "resolved" only because the stop is *visible*: the band names it in `asf quota` and `asf capacity`, and the class is counted per day. A changed cause prints again. |
| D11 | `stall()` returns `Stalled(job, state, quiet, cls, why)` namedtuples | a parallel `classes` return value, or a class computed again by the caller | The class must be printed by the stall check and routed on by the health step, and computing it twice off the same log invites the two disagreeing. A namedtuple widens once and is then free to widen again; the three positional-unpack sites are named in §1.1 and updated here. |
| D12 | The fall in relaunches is **measured** by `asf failures`, over the `ticks` stream *and* the `sessions` stream's own `result` texts, and is not asserted by a test | a test that fails when the count does not fall | A rate over weeks is not a property of a commit. Because `of_signature` classifies any historical `end_reason`, the days *before* this change are classifiable from the record already in hand — so the before-and-after is one command, not a wait. |

## 2. The design

### 2.1 `asf/failure.py` — four classes and what each may do

```python
"""asf.failure — the class of a failed launch or session, and what the factory may do about it.

A missing credential is not a flaky transport, and retrying it is a promise that something might
change. Four classes, one policy each:

* ``credential`` — a login, a token, a permission or a model label the operator must change.
  Zero relaunches, ever. One needs-operator line naming the product, and the lane is stopped
  until the credential reads (:mod:`asf.workers.stops`).
* ``quota`` — a window is spent. Zero relaunches on this account; the account is stopped until
  its reset and the item goes to another of the pool (:mod:`asf.workers.headroom`). No round.
* ``transport`` — the network dropped. Exactly one relaunch, on the original brief, no round;
  the second in a row is the operator's.
* ``work`` — everything else, and everything unrecognised. The correction, the hold and the
  round the factory writes today.

Two sources, both named by the card: the launcher's own result text (a ``SpawnError``, an
``AuthEnvError``, the text a worktree setup printed) and the session's last beat
(:func:`asf.workers.runtime.last_beat`). Nothing here opens a file, runs git, knows a product or
imports anything of ``asf``: it is a table, three patterns and a policy.

``why`` is always a pattern *name*, never matched text — a session log is not masked and this
string travels into the record (F-0054 D3).
"""

CREDENTIAL, QUOTA, TRANSPORT, WORK = 'credential', 'quota', 'transport', 'work'
CLASSES = (CREDENTIAL, QUOTA, TRANSPORT, WORK)

#: Relaunches each class may have. ``None`` (work): the existing correction path decides
#: (one cold retry, then the B-0062 hold).
RETRIES = {CREDENTIAL: 0, QUOTA: 0, TRANSPORT: 1, WORK: None}

#: An expired login, a rejected key, a model label that does not exist, a permission the account
#: does not hold, and an ``auth_env`` file that is missing, empty or unreadable.
CREDENTIAL_RE = re.compile(
    r'invalid api key|please run /login|authentication[_ ]error|oauth token|'
    r'not permitted to use|issue with the selected model|model .* (?:not found|does not exist)|'
    r'auth_env \S+ file .* (?:does not exist|is empty|cannot be read)', re.I)
#: A spent window: the session limit, the usage limit, a rate limit, the API's own 429.
#: :data:`asf.workers.headroom.LIMIT_RE` is this pattern.
QUOTA_RE = re.compile(r"hit your (?:\w+ )?limit|(?:session|usage|weekly) limit|rate[ _]limit|"
                      r"API Error: 429|quota (?:exceeded|exhausted)", re.I)
#: A dropped connection. :data:`asf.workers.lifecycle.NETWORK_RE` is this pattern.
TRANSPORT_RE = re.compile(r'could not resolve host|connection (?:reset|refused|timed out|closed)|'
                          r'network is unreachable|unable to access|operation timed out|early eof|'
                          r'remote end hung up|ssl_error|gnutls', re.I)

#: Every signature name the tree writes → its class. A name absent from this table classifies by
#: text, then by the default: a signature this table does not know is never silently ``work`` —
#: :func:`of_signature` returns None and the caller's text is read.
SIGNATURE_CLASS = {
    'auth': CREDENTIAL, 'permission': CREDENTIAL, 'unknown model': CREDENTIAL,
    'quota-exhausted': QUOTA,
    'network error': TRANSPORT,
    'hook refused': WORK, 'not pushed': WORK, 'unpushed work': WORK, 'empty branch': WORK,
    'token cap': WORK, 'run cap': WORK, 'dead pid': WORK, 'other': WORK,
}
```

The four functions, and nothing else:

```python
def of_signature(name):
    """The class of a signature name (:data:`SIGNATURE_CLASS`), or None for one it does not
    know — including ``''``, ``finished`` and ``None``."""

def of_text(text):
    """The class the raw text carries, or None: credential, then quota, then transport. The order
    is the ranking, not an accident — an authentication error is never a blip, and a 429 is a
    window and not a dropped connection."""

def classify(signature=None, text='', default=WORK):
    """``(cls, why)``. The signature's class first (``why``: ``signature <name>``), else the
    text's (``why``: ``text: <cls>``), else ``default`` (``why``: ``no signature``). Pure."""

def retries(cls):
    """:data:`RETRIES` — how many relaunches ``cls`` may have; None: the caller's own rule."""

def may_relaunch(cls, tried):
    """True when a failure of ``cls`` that has already been relaunched ``tried`` times may be
    relaunched again. ``work`` is always True: its own path counts its tries."""

def label(cls, why):
    """``class credential (signature auth)`` — the suffix every failure line prints, so the
    stall check, the cap line and the launch line cannot word it three ways."""

def operator_text(cls, product, item, job, lane='', why=''):
    """The needs-operator sentence, naming the product — and a lane only as ``lane-N``, never an
    account (F-0054 D3). No path, no value, no matched text: the console line adds the clearing
    command beside this, and the event carries only this."""
```

`operator_text` reads, for the card's second acceptance line:

```

T-0244 (task-t-0244) was not relaunched — run `asf doctor` for the lane's credential check
```

### 2.2 One owner per pattern

Three constants become references, so a signature is written once:

```python

# asf/workers/lifecycle.py
```

### 2.3 The session's last beat

```python
# asf/workers/runtime.py
def last_beat(log_path):
    """The last parsable JSON record of the log's **last run**, or None — the same scan
    :func:`read_result` makes, rewinding at every ``init``. A session that died wrote no
    ``result`` line; its last beat is all there is of why."""

def beat_signature(rec):
    """The signature name a beat's text carries (:data:`FAILURE_SIGNATURES`), or ''. The text is
    the record's ``result``, else its ``error``, else the ``text`` of its last content block —
    whatever the runtime wrote last. Never returned to a caller: only its name is."""
```

`beat_signature` returns a *name*, not the text, which is what keeps D3 true by construction:
no caller of the beat can print what the beat said.

### 2.4 The stall check prints the class

```python
Stalled = collections.namedtuple('Stalled', 'job state quiet cls why')

def failure_class(session):
    """``(cls, why)`` for one failed session: its result line's signature
    (:func:`runtime.failure_reason`) when it wrote one, else its last beat's
    (:func:`runtime.beat_signature`), else ``work``."""
    rec = runtime_mod.read_result(session.get('log'))
    sig = runtime_mod.failure_reason(rec) if rec is not None else \
        runtime_mod.beat_signature(runtime_mod.last_beat(session.get('log')))
    return failure.classify(signature=sig)
```

`stall` appends `failure.label(cls, why)` to every line it prints and returns `Stalled`
namedtuples; `capped` appends it too, with the class of its own measure (`token cap` and
`run cap` are both `work`):

```
DEAD  task-t-0244             silent 3m  class credential (signature auth)
STALL spec-f-0054             silent 41m  class work (no signature)
CAP   plan-f-0021  output 210000 over 200000 (plan)  class work (signature token cap)
```

`stall: none` and `cap: none` are not failure lines and carry no class.

### 2.5 The health step routes on the class

`handle_dead` (`asf/tick/step_health.py:72`) gains one branch before it corrects anything. Its
present order — `operator_flagged`, `closed_state`, `reaped_empty`, `corrected`/`is_correction`,
`pending_correction`, the hold — is unchanged below it, and the four new returns join the
documented set (`corrected` | `operator` | `flagged` | `closed` | `released` | `held`, plus
`credential` | `quota` | `retried`):

```python
cls, why = stall_mod.failure_class(session)
ctx.counts['failures'][cls] = ctx.counts['failures'].get(cls, 0) + 1
if cls == failure.CREDENTIAL:
    return credential_stop(ctx, session, why, out=out)      # zero relaunches, one line, one stop
if cls == failure.QUOTA:
    return quota_route(ctx, session, why, out=out)          # the lane stops, the item waits
if cls == failure.TRANSPORT and not session.get('transport_retry'):
    return transport_retry(ctx, session, why, runtime_fn, out=out)   # one, on the original brief
if cls == failure.TRANSPORT:
    return operator(ctx, session, cls, why, out=out)        # the second in a row (D9)
# work: exactly what this function does today
```

- **`credential_stop`** — `stops.record(account, var, path, job, product)` when the scope is the
  account's (D5); the console line is `failure.operator_text(...)` plus the `AuthEnvError`'s own
  `clear` hint; the event is `ctx.event('needs-operator', failure_class=cls, why=why,
  message=<operator_text>, item=…, job=…, lane='lane-2')` — the message only, so nothing
  unredacted reaches the record; `operator_flagged` is marked so the next tick returns `flagged`.
  No `correct_once`, no `hold`, and `ctx.counts['relaunches']` is **not** touched.
- **`quota_route`** — `headroom.note_exhausted(product, session, rec)` and its line, exactly as
  `health` writes it for a run that *ended* on a spent window (`asf/workers/health.py:445`). No
  correction, no round, no hold; the account is stopped until the reset and the item's own feeder
  row places it on another lane next wave.
- **`transport_retry`** — `stall.correct_once(product, session, None, runtime_fn(),
  mark='transport_retry')`: the original brief unchanged, a new job `<job>-retry`, its own log and
  its own ledger line (D-0048 part b), `transport_retry: 1` on both the original and the retry so
  a second transport failure on either cannot buy a third launch. It counts as a relaunch
  (`ctx.counts['relaunches'] += 1`): it is one.

`correct_once`'s two new parameters are the whole change to it:

```python
def correct_once(product, session, error_text, runtime, mark='corrected', suffix='-correction'):
    """One retry, cold: its own job and log, its own ledger line — never the dead session's.
    ``error_text`` None: the original brief, unchanged, under ``<job><suffix>`` — a transport
    failure is not the work's fault and must not be handed a CORRECTION paragraph (F-0054 D8).
    ``mark`` is the field set on the original (and inherited by the retry) so a second failure of
    the same class cannot buy a third launch."""
```

`RUN_FIELDS` gains `transport_retry` (B-0041), and `hold_failed_corrections`
(`asf/tick/step_health.py:236`) keeps its `-correction` suffix test: a `-retry` run is judged as
an ordinary run, and a *work* failure on it is corrected the ordinary way. `ROLE_PREFIX`
(`asf/record/match.py:30`) and `KIND_PREFIXES` (`asf/metrics/metrics.py:44`) match a job's
*prefix*, and `session_kind` reads the record's own `kind`, so a `-retry` suffix needs no
registration — the retry is read as the same kind and the same item as the run it repeats,
exactly as `-correction` is.

### 2.6 The credential stop, and the lane it stops

```python
"""asf.workers.stops — the lane a credential stopped, and until what.

``~/.ASF/state/credential-stops.json``: one file for the machine, as ``quota-limits.json`` is,
since the accounts are. ``{account: {var, path, at, product, job, why}}``.

A stop has no reset: there is no time after which a missing file exists. It clears when the file
it names reads non-empty — the same read :func:`asf.workers.runtime.auth_env_values` makes before
a launch — or when the operator deletes it (F-0054 D7).
"""

def record(account, var, path, job='', product='', why=''):
    """Stop ``account``'s lane; a later record for the same account and var replaces it."""

def active(now=None):
    """``{account: rec}`` for every stop whose file still does not read. A file that now reads
    non-empty is dropped from the table as it is read."""

def clear(account=None):
    """Drop one account's stop, or every one."""
```

`Pool` loads it beside the quota limits and `band` consults it first — a credential outranks a
window, because no reset will help:

```python
def credential_stop(self, account):
    """``(var, why)`` of the credential stop on ``account``, or None."""
    rec = self.credential_stops.get(account.name)
    return (rec.get('var'), rec.get('why') or '') if rec else None

def band(self, account):
    stop = self.credential_stop(account)
    if stop:
        return quota_mod.STOP, f'credential {stop[0]} — {lane_label(self.cfg, account.name)}, see asf doctor'
    until = self.limit(account)
    ...
```

`pick_account` then treats the lane as stopped without a line of its own, `asf quota` and
`asf capacity` print the reason, and a row whose every lane is stopped waits with all of them
named (`asf/workers/pool.py:526`) — the state D10 keeps visible in place of a repeated line.

`lane_label(cfg, name)` is `lane-<1-based index in worker_pool.accounts>`, `lane-?` for a name the
config does not hold. It is the only form an account may take in anything printed into the record.

### 2.7 The launcher: the class of a refused launch

`spawn` already refuses a launch before it makes anything (`asf/workers/spawn.py:682`). What it

## 3. Acceptance tests

### 3.1 The four classes, the table and the policy

`of_signature` over every name in `SIGNATURE_CLASS` returns its class; over `''`, `None`,
`finished` and `wat` returns None. `of_text`: `'API Error: 429'` → `quota`;
`'connection reset by peer'` → `transport`; `'Invalid API key · Please run /login'` →
`credential`; `'auth_env CLAUDE_CODE_OAUTH_TOKEN file … does not exist'` → `credential`;
`'model claude-nope does not exist'` → `credential`; `'the test failed'` → None. Ranking: a text
carrying both an authentication error and a connection reset is `credential`; one carrying both a
429 and a timeout is `quota`. `classify(signature='auth', text='connection reset')` is
`credential` — the signature outranks the text; `classify(text='')` is `(work, 'no signature')`.
`RETRIES` is `{credential: 0, quota: 0, transport: 1, work: None}`; `may_relaunch` is False for
credential and quota at 0 tries, True for transport at 0 and False at 1, True for work at any.
`label` and `operator_text` are single lines naming the class, the product and — where a lane is
named at all — only `lane-N`: over an `AuthEnvError` message carrying an account name and an
absolute home-directory path, neither the account name nor the path appears in the output, and no
`why` any function returns contains a character of matched text.
`asf.failure` imports nothing of `asf` (`ast` over its own source).

## 4. Records

**The stall check's lines** are the card's first acceptance line: every `STALL`, `DEAD` and `CAP`
line carries ` class <c> (<why>)`, from one owner (`failure.label`), with `why` a pattern name and
never matched text.

**`~/.ASF/state/credential-stops.json`** — new, one file for the machine, beside
`quota-limits.json`: `{<account>: {var, path, at, product, job, why}}`. It is the state that
replaces a needs-operator line repeated every tick. Untracked, so a path and an account name are
at home in it; it clears itself when the file it names reads.

**The `needs-operator` event** — the existing kind, in `metrics/events/<day>.jsonl` in the record
clone — gains `failure_class`, `why`, `lane` (as `lane-N`) and `job` beside its `message`. Nothing
in it carries an account name, a machine path or a byte of a session's text, because the record
clone's own commit runs `asf.redact` and because `why` is a pattern name by construction.

**The registry line** gains `transport_retry` on a run the network cost a launch, and
`RUN_FIELDS` lists it so it belongs to that launch alone (B-0041). `corrected`,
`operator_flagged` and every other field keep their meaning. No `end_reason` string changes, so
every ledger already on disk reads exactly as it does now.

**The `ticks` stream** gains `failures: {class: count}` beside `relaunches`, validated against
`failure.CLASSES`. Together they are the card's third acceptance line: relaunches per day per
product, with the classes that no longer buy one beside them.

**`asf failures` stdout** is the read — per day, per product, the relaunches and the four classes,
from the `ticks` dicts where they exist and from the `sessions` stream's own `result` texts where
they do not.

**Nothing else.** No new stream, no new card key, no change to `index.json`, no change to a PR
body, no new `end_reason`, no new lane state, and no existing ledger, review file or metrics day
becomes unreadable.
