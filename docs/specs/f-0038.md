# F-0038 — the change classifier decides what CI owes a push

Thirty-five of the last eighty commits on the trunk changed nothing but a document or a factory
script: a spec, a plan, a hotfix to `tools/run_tests.py`, a test of `tools/cutover.sh`. Each of
them ran the whole circuit. `.github/workflows/tests.yml` is one job over a two-version matrix,
and each leg of that matrix installs the package with pipx, runs the conventions check, the
genericity check, the plugin check, the full suite, the sample product end to end, and then the
full suite a second time under `env -i` with a synthetic operator home. A commit that adds one
Markdown file under `docs/specs/` pays for four full suite runs and two end-to-end runs.

Nothing about that is wrong; it is simply not owed. A document cannot turn a test red — harvest
already knows this and drops the test command for an inert branch (`is_inert`, `docs_only`,
`asf/harvest/harvest.py:845`) — and a change to `tools/cutover.sh` is exercised by
`tests/test_cutover.py`, not by the sample product's end-to-end run.

This spec adds the missing half of that idea on the CI side: a **change classifier** that maps
the paths a push touched to one of two classes, and a workflow whose heavy jobs are gated on the
class it returns. `FACTORY_ONLY` runs lint and a factory-test job, each under a five-minute
timeout. Everything else runs the matrix exactly as today.

The per-product path list is **configuration, never code**. F-0002 already ruled on the key
(`docs/specs/f-0002.md:116`, `:157`): `product:ci.factory_only_paths`, with the classifier's
mirror named as the product's `product:ci.workflow`. `tools/check_conventions.sh` enforces the
same thing mechanically — a path-shaped literal under `asf/` fails the build — so the classifier
*cannot* carry the list even if someone wanted it to.

This changes code under `asf/`, `tests/`, `.github/workflows/tests.yml` and
`docs/products.example.yaml` in this repository. It changes no card in any record.

## 1. Decisions

### 1.1 In

- **`asf/ci.py`** — a new module: two class names, one pure `classify(paths, globs)`, and the
  glob rule the rest of the repo already uses (§2.1).
- **`ci.factory_only_paths`** — a new `CI_FIELDS` key (`asf/env.py:229`), a list of globs, read
  as `Product.factory_only_paths`, documented in `docs/products.example.yaml` (§2.2).
- **`asf ci class`** — the command CI calls: a base and a head, or a path list on stdin, and it
  prints the class (§2.3).
- **The workflow, re-cut into five jobs** (§2.4): `classify`, `lint`, `factory-tests` — which
  always run — and `tests` (the matrix) and `sample` (end to end, hermetic re-run), which run
  only when the class is not `FACTORY_ONLY`.
- **The five-minute bound made mechanical**: `timeout-minutes: 5` on `lint` and on
  `factory-tests`. A factory-only run that takes longer is red, which is the only form of that
  acceptance a machine can hold (§2.4).
- **The mirror test** (§3.4): the workflow's copy of the class — the glob list, the gate
  expression, the module list of the factory-test job — checked against the classifier's, in
  `tests/test_workflow.py`.
- **One `asf doctor` row** (§2.5): the operator's `ci.factory_only_paths` against the list in the
  product's `ci.workflow`. A test cannot reach the operator's home; doctor can, and this is the
  only place the two copies of the *list* can be compared for a real product.

### 1.2 Out

- **Harvest's landing gate.** `run_gate` (`asf/harvest/harvest.py:416`) and the inert-branch rule
  that drops the test command are untouched. The gate decides whether a branch may land on the
  trunk; this card decides what a push already on the trunk owes CI. Folding `is_inert` and
  `classify` into one vocabulary is worth doing and is not this card — it changes what lands.
- **A `DOCS_ONLY` class.** Two classes, not three (D4).
- **Any product but this one.** The classifier and the key are generic; the glob list, the job
  names and the factory-test module list in §2.4 are this repository's own configuration. No
  other product's workflow is written here.
- **The pipx install proof.** `asf --version` after `pipx install .` stays in the matrix job. It
  proves a clean install, which a factory-only push does not put at risk, and it costs the
  install a fast job must not pay.
- **Caching, runner labels, a shorter matrix.** Making the *full* circuit cheaper is F-0100's
  subject. This card only stops charging it to pushes that do not need it.

### 1.3 Preconditions

- The operator's `products/<p>.yaml` for this product names `ci.workflow: tests.yml` and carries
  `ci.factory_only_paths` with the list of §2.4. Without the second, §2.5's doctor row skips and
  nothing else changes; the workflow still classifies, because its copy is what the runner reads.
- The trunk's landing path is harvest's push, not a pull request (`.github/workflows/tests.yml`
  header, B-0053). Where a product lands through pull requests instead, its required checks must
  name jobs that are *skipped*, never jobs that never start — which is D1's whole reason.
- `actions/checkout@v4` can fetch the full history of this repository in the classify job. It is
  a small repository; `fetch-depth: 0` is affordable and is what a two-point diff needs.

## 2. The design

### 2.1 The classifier — `asf/ci.py`

```python
FACTORY_ONLY = 'FACTORY_ONLY'
FULL = 'FULL'
CLASSES = (FACTORY_ONLY, FULL)


def matches(path, globs):
    """True when ``path`` (repo-relative, forward slashes) matches any glob. The repo's one
    glob rule: ``fnmatch.fnmatchcase`` over the whole path, and a glob with no ``/`` matches
    the base name — the same rule ``amendable_paths`` and ``customer_paths`` are read by."""


def classify(paths, factory_only_globs):
    """``FACTORY_ONLY`` when ``paths`` is non-empty and every one of them matches a glob;
    ``FULL`` otherwise — including an empty ``paths``, an empty glob list, and any path the
    list does not name (D5)."""


def unmatched(paths, factory_only_globs):
    """The paths that forced ``FULL``, in first-seen order — what the command prints so the
    operator sees *why* a run went full, without re-deriving the diff."""
```

Pure functions over plain lists, no filesystem, no configuration, no product convention: the
module is `asf/feeder/footprint.py`'s neighbour in shape and `asf/approvals.py`'s in its glob
rule. `tools/check_conventions.sh` is the standing proof that no path list ever lands in it.

### 2.2 The key — `ci.factory_only_paths`

`CI_FIELDS` (`asf/env.py:229`) gains one entry, `'factory_only_paths': _LIST`, so a scalar or a
map under that key is a schema error the existing `validate_product_text` reports with its line
number. `Product` gains:

```python
@property
def factory_only_paths(self):
    """``ci.factory_only_paths`` — the globs a push may touch and still be FACTORY_ONLY.
    Empty (the default) means the product has no such class: every push is FULL."""
    ci = self._get('ci')
    return (ci.get('factory_only_paths') or []) if isinstance(ci, dict) else []
```

`ci: none` — a product without CI — keeps answering `[]` rather than raising, as `has_pr_host`
already does for the same shape (`asf/doctor.py:48`).

`docs/products.example.yaml` documents it under `ci:`, beside `budgets:`, with D6's consequence
written where the operator will read it:

```yaml
ci:
  provider: gh-actions
  workflow: ci.yml
  dev_job: test
  # F-0038: path globs a push may touch and still be a factory-only change — process
  # documentation, the factory's own scripts, review inputs and the tests that cover them.
  # A push whose changed paths all match runs only the workflow's lint and factory-test jobs.
  # Anything unmatched — or an empty diff — runs the full matrix. Globs are fnmatch over the
  # repo-relative path, as customer_paths and amendable_paths are, so `*` crosses `/`:
  # `docs/*` and `docs/**` name the same set. Unset, or empty: every push is FULL.
  # Keep this list identical to the one the workflow named in `workflow:` carries;
  # `asf doctor` has a row that says so when they drift.
  factory_only_paths:
    - docs/**/*.md
    - tools/**
```

### 2.3 The command — `asf ci class`

```
asf ci class [--product P] [--base REF] [--head REF] [--paths-from FILE|-]
             [--globs-from FILE|-] [--json]
```

- **Paths**: `--paths-from` wins (a file, or `-` for stdin, one path per line). Otherwise
  `git diff --name-only <base>..<head>` for a two-point range, `<base>...<head>` when `--base`
  ends in `...` — the workflow passes the range it wants (D10). A base that does not resolve, or
  is all zeros, yields no paths and therefore `FULL` (D5), with the reason on stderr.
- **Globs**: `--globs-from` wins — this is how the runner passes the workflow's copy without an
  operator home. Otherwise the resolved product's `ci.factory_only_paths`.
- **Output**, one line on stdout, so a shell reads it with no parsing:

```
FACTORY_ONLY
```

and, on stderr, the reason, always:

```
ci class: 3 changed paths, 3 matched — docs/specs/f-0038.md, docs/plans/f-0038.md, tools/cutover.sh
```

- `--json` puts the whole answer on stdout instead:

```json
{"class": "FULL", "paths": ["asf/env.py", "docs/specs/f-0038.md"],
 "unmatched": ["asf/env.py"], "globs": ["docs/**/*.md", "tools/**"],
 "base": "abc1234", "head": "def5678"}
```

- Exit `0` for either class (D12); exit `2` only for a bad invocation or an unreadable
  repository, through the `ConfigError` path `asf/cli.py` already owns.

Registration follows the one nested command this CLI already has — `plugin_build.register(sub)`
(`asf/cli.py:180`) — so `ci` is a group with `class` under it, and room for the next question CI
asks the factory.

### 2.4 The workflow — `.github/workflows/tests.yml`

The triggers do not change: `push` on the trunk only (B-0053), `pull_request` kept. What changes
is that the one `tests` job becomes five, and the list arrives in one `env:` block at the top of
the file — the workflow's copy of the class, and the only literal path list in it:

```yaml
env:
  # F-0038: the workflow's copy of ci.factory_only_paths. Keep identical to the operator's
  # products/<p>.yaml; tests/test_workflow.py checks this copy against the factory-test job
  # below, and `asf doctor` checks it against the operator's.
  FACTORY_ONLY_PATHS: |
    docs/*.md
    docs/**/*.md
    README.md
    tools/**
    tests/test_run_tests.py
    tests/test_cutover.py
    tests/test_check_generic.py
    tests/test_workflow.py

jobs:
  classify:
    runs-on: ubuntu-latest
    timeout-minutes: 3
    outputs:
      class: ${{ steps.c.outputs.class }}
    steps:
      - uses: actions/checkout@v4
        with: {fetch-depth: 0}
      - id: c
        run: |
          printf '%s' "$FACTORY_ONLY_PATHS" > /tmp/globs
          if [ "${{ github.event_name }}" = pull_request ]; then
            RANGE="--base ${{ github.event.pull_request.base.sha }}... --head ${{ github.sha }}"
          else
            RANGE="--base ${{ github.event.before }} --head ${{ github.sha }}"
          fi
          CLASS="$(python3 -m asf.cli ci class $RANGE --globs-from /tmp/globs)"
          echo "class=$CLASS" >> "$GITHUB_OUTPUT"
          echo "class: $CLASS" >> "$GITHUB_STEP_SUMMARY"

  lint:                       # always; no install, no gate on the class
    timeout-minutes: 5
    steps: [checkout, setup-python 3.13,
            bash tools/check_conventions.sh,
            bash tools/check_generic.sh,
            python3 -m asf.cli plugin check]

  factory-tests:              # always; the modules that cover the paths on the list
    timeout-minutes: 5
    steps: [checkout, setup-python 3.13, git config user.name/email,
            python3 -m unittest -v tests.test_run_tests tests.test_cutover
                                   tests.test_check_generic tests.test_workflow]

  tests:                      # the matrix, as today, minus the two lint steps lint now owns
    needs: classify
    if: needs.classify.outputs.class != 'FACTORY_ONLY'
    strategy: {matrix: {python: ["3.12", "3.13"]}}
    steps: [checkout, setup-python, pipx install ., asf --version,
            python3 tools/run_tests.py]

  sample:                     # the end-to-end run and the hermetic re-run, as today
    needs: classify
    if: needs.classify.outputs.class != 'FACTORY_ONLY'
    steps: [checkout, setup-python 3.13,
            python3 -m unittest -v tests.test_sample_product,
            the `env -i` operator-home re-run of tools/run_tests.py]
```

Three properties this shape is chosen for:

1. **A gated job is skipped, not absent.** GitHub reports a job skipped by `if:` as skipped, and
   a skipped job satisfies a required status check of that name. A workflow filtered out by
   `on: paths:` reports nothing at all, and a required check that never reports blocks a pull
   request for ever (D1).
2. **One gate expression, everywhere** (D9), so §3.4 compares strings.
3. **The always-jobs pay no install** (D8), which is what makes the five-minute timeout a bound
   with room in it rather than a tripwire.

The `env -i` hermetic re-run and the sample product's end-to-end run move into `sample`
unchanged, text for text: this card re-homes them, it does not edit them.

### 2.5 The doctor row

`asf doctor` gains `ci:factory-paths`, `required=False` (an optional row never turns doctor red,
the rule F-0079 set for the capacity rows, `asf/doctor.py:274`):

- **skip** — the product declares no `ci.factory_only_paths`, or no `ci.workflow`, or the
  workflow file is not in `repo_dir`. A product without the class is not a product in error.
- **ok** — the workflow's `FACTORY_ONLY_PATHS` block, read as one glob per line, equals the
  product's list as a set.
- **red** — they differ; the detail names the difference in both directions, e.g.
  `workflow has 2 the config does not (tools/**, README.md); config has 1 the workflow does not
  (docs/**/*.md)`.

The tick's existing `NEEDS OPERATOR` path carries it from there. This is the only check that can
see both copies of the *list*; §3.4 is the only check that can see both copies of the *class*.
Between them, neither copy can drift silently.

## 3. Acceptance tests

Each block runs from the repository root.

### 3.1 The classifier

```bash
python3 -m unittest -v tests.test_ci_class
```

Covers: every path matched → `FACTORY_ONLY`; one unmatched path among ten matched → `FULL`;
an empty path list → `FULL`; an empty glob list → `FULL` (D5); `unmatched()` returning exactly
the paths that forced `FULL`, in first-seen order; the glob rule of D6 over a bare name
(`README.md`), a directory glob (`tools/**`), a nested one (`docs/**/*.md`) and a path that
matches none; and that `CLASSES` holds exactly the two names the workflow may be gated on.

### 3.2 The key

```bash
python3 -m unittest -v tests.test_env
```

Covers, beyond what the module already asserts: `ci.factory_only_paths` accepted as a list and
reported at its line number when it is a scalar or a map; `Product.factory_only_paths` returning
the list, `[]` when the key is absent, and `[]` for `ci: none`; and
`docs/products.example.yaml` still validating clean with the key documented in it
(`tests/test_env.py:264`, which is the test that makes the example config a checked artifact).

### 3.3 The command

```bash
python3 -m unittest -v tests.test_cli.CiClassTests
```

Covers, over a temporary git repository: a two-point range whose diff is all documents →
`FACTORY_ONLY` on stdout, exit 0; the same range with one `asf/` file added → `FULL`, exit 0
(D12); `--paths-from -` reading stdin and never touching git; `--globs-from` beating the
product's configuration; a base of forty zeros → `FULL` with the reason on stderr; a base that
does not resolve → `FULL`, not a traceback; and `--json` carrying `class`, `paths`, `unmatched`,
`globs`, `base` and `head`.

Then the same command over this repository's real history, which is what the classify job runs:

```bash
python3 -m asf.cli ci class --base HEAD~1 --head HEAD --json
```

### 3.4 The mirror — both copies of the class agree

```bash
python3 -m unittest -v tests.test_workflow
```

The module keeps its two trigger tests (B-0053) and gains the mirror. Parsing
`.github/workflows/tests.yml` with `env.loads`, it asserts:

1. every job other than `classify`, `lint` and `factory-tests` carries `needs: classify` and the
   condition `needs.classify.outputs.class != 'FACTORY_ONLY'`, character for character, with the
   class name taken from `asf.ci.FACTORY_ONLY` and not written in the test (D9);
2. `lint` and `factory-tests` carry no `if:` at all, and both declare `timeout-minutes: 5` —
   the five-minute acceptance, mechanically;
3. `classify` declares `fetch-depth: 0`, outputs `class`, and computes it by calling the
   factory's own classifier — no second implementation of the rule in shell;
4. every `tests/test_*.py` path in `FACTORY_ONLY_PATHS` is named as a module by the
   `factory-tests` job's command, and every module that job names appears in the list: the test
   of a factory script and the script itself travel together, or the class is a way to skip a
   test;
5. `asf.ci.classify` over the paths of `FACTORY_ONLY_PATHS`, expanded against the tracked file
   list (`git ls-files`), returns `FACTORY_ONLY`; the same set plus `asf/env.py` returns `FULL`;
   and `.github/workflows/tests.yml` itself returns `FULL` (D7 — a workflow edit runs what it
   edits).

Point 5 is the acceptance's second row — *a push mixing factory and product paths runs the full
matrix as today* — asserted over the workflow as it actually stands, not over a fixture.

### 3.5 The doctor row

```bash
python3 -m unittest -v tests.test_doctor
```

Covers the three outcomes of §2.5 over a temporary repository and product file — skip with no
key, skip with no workflow file, ok when the lists match in any order, red with both directions
named in the detail — and that the row is `required=False`, so a drifted list reports without
turning `asf doctor` red.

### 3.6 The bound, measured on a real run

Structural proof is §3.4/2. The measured one, for the operator, after the first factory-only push
lands:

```bash
gh run list --workflow tests.yml --branch main --limit 5 \
  --json databaseId,conclusion,createdAt,updatedAt,displayTitle
gh run view <id> --json jobs \
  --jq '.jobs[] | {name, conclusion, started: .startedAt, ended: .completedAt}'
```

A factory-only run shows `classify`, `lint` and `factory-tests` with a conclusion, `tests` and
`sample` as `skipped`, and `updatedAt - createdAt` under five minutes.

### 3.7 The gate

```bash
python3 tools/run_tests.py
bash tools/check_conventions.sh && bash tools/check_generic.sh && python3 -m asf.cli check
```

`check_conventions.sh` is the standing test that D2 held: the day someone moves the glob list
into `asf/ci.py`, this is what goes red.

## 4. Records

**Config, new** — `products/<p>.yaml`, under `ci:` (the key F-0002 named at
`docs/specs/f-0002.md:157`):

```yaml
ci:
  factory_only_paths:
    - docs/*.md
    - docs/**/*.md
    - README.md
    - tools/**
```

**The workflow** — `.github/workflows/tests.yml`: one `env.FACTORY_ONLY_PATHS` block, five jobs

**Per run, in GitHub's own record** — the `classify` job's output `class`, one line in
`$GITHUB_STEP_SUMMARY` (`class: FACTORY_ONLY`), and the reason line on the step's stderr naming

what the class bought.

**`asf doctor`** — one new row, `ci:factory-paths`, `required=False`.

**Not written.** No new metrics stream and no new event: the run's class is GitHub's record, and
a minutes-saved number belongs to the budget rollup that already reads `ci.budgets`, not to this
card. No new state file. No field on any card. No change to `index.json`, to the tick's steps, or
to what harvest gates and lands.

## Stories

- S: The classifier — `asf/ci.py` maps changed paths and a glob list to `FACTORY_ONLY` or `FULL`, and names what forced `FULL` — acceptance: `python3 -m unittest -v tests.test_ci_class`
- S: The list is configuration — `ci.factory_only_paths` is a validated `CI_FIELDS` key, read as `Product.factory_only_paths`, documented in the example product — acceptance: `python3 -m unittest -v tests.test_env`
