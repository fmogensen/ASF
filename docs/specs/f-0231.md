# F-0231 — one command releases a correction, and a correction nothing can answer is dropped

A lane's spec session for F-1129 was killed 36 s in on 2026-09-27 (`blockedBy` was not yet
honoured). Health reaped its worktree empty — no commit, no branch — the cold retry then failed on
the missing worktree, and the run was held **died twice**. `2fabf6c` fixed the rule that wrote it:
a first death whose worktree health reaped empty is released, and the item's own feeder row
relaunches it. What `2fabf6c` did not do is touch the line already in the ledger.

So the correction sits there, pending, on `cloud/spec-F-1129` — a branch that never reached origin
and no longer exists anywhere. It is invisible today only because B-0058 gives a **blocked** item no
correction row (`asf/feeder/rows.py:719`), and F-1129 is blocked by B-1382. When B-1382 closes the
row appears: `FIX → CORRECT`, `would launch`, on that branch (P1, P2 — measured).

And there is no way to take it out. `asf unpark` is the only command an operator has over a pending
correction, and it releases a **park** — a plain hold makes it print `is not parked — nothing to
undo` and exit 1, leaving the ledger byte-for-byte as it was (P3, measured). Every other writer that
clears a correction is automatic, and each is keyed on an event this correction will never see (P4).

This card is: **`asf correction drop <item>` releases what the ledger is holding, and a correction
whose branch is nowhere is dropped by the lane without waiting for an operator to notice.**

| # | Chosen | Against | Why |

## The design

### §1 `asf/workers/correction.py` — the operator's release

```python
"""``asf correction drop <item>`` — the operator's way out of a correction (F-0231).

A pending correction is cleared only by a later run of the item starting, and a correction whose
branch is gone starts nothing that can answer it: it is permanent until this command records the
exit. ``asf unpark`` releases a park; this releases whatever the ledger is holding, park included.
The exit is one appended ledger line per held job — every hold and its undo stay in the file."""
import datetime

from asf import env
from asf.workers import lifecycle
from asf.workers import pool as pool_mod


def pending_jobs(path, item):
    """Every pending correction on ``item``: ``[(job, correction), ...]`` oldest first, one entry
    per job. Read once, before any line is appended — the order and the count the operator is
    told are this list's."""
    held = {}
    for run in lifecycle.item_runs(path, item):
        corr = lifecycle.pending_correction(run, path)
        if not corr:
            continue
        job = run.get('job')
        prev = held.get(job)
        if prev is None or (corr.get('at') or '') >= (prev.get('at') or ''):
            held[job] = corr
    return sorted(held.items(), key=lambda jc: ((jc[1].get('at') or ''), jc[0]))


def cmd_drop(args):
    product = env.load_product(getattr(args, 'product', None))
    item = (args.item or '').strip().upper()
    path = pool_mod.sessions_path(product)
    known = any(r.get('item') == item for rs in lifecycle.runs(path).values() for r in rs)
    if not known:
        print(f'asf correction drop: {item} is not in the ledger — nothing to drop')
        return 1
    held = pending_jobs(path, item)
    if not held:
        print(f'asf correction drop: {item} holds no correction — nothing to drop')
        return 1
    now = datetime.datetime.now(datetime.timezone.utc).strftime('%Y-%m-%dT%H:%M:%SZ')
    why = getattr(args, 'why', None) or ''
    for job, corr in held:
        fields = {'correction': None, 'dropped': now, 'drop_why': why}
        if corr.get('parked'):  # P13: a park released without its stamp is re-parked next tick
            fields.update(unparked=now, unpark_why=why)
        pool_mod.update_session(product, job, **fields)
        what = 'park' if corr.get('parked') else corr.get('kind') or 'correction'
        text = corr.get('reason') or corr.get('text') or ''
        print(f'dropped {what} on {item} ({job}): {text}'.rstrip(': '))
    left = pending_jobs(path, item)
    line = f'dropped {len(held)} correction{"s" if len(held) != 1 else ""} on {item}'
    print(line + (f' — {len(left)} still holds it' if left else ''))
    for job, corr in left:
        print(f'still held ({job}): {corr.get("reason") or corr.get("text") or ""}'.rstrip(': '))
    if why:
        print(f'why: {why}')
    return 0


def register(sub):
    """``asf correction drop <item> [--why TEXT] [--product P]``."""
    p = sub.add_parser('correction', help='the corrections the ledger is holding')
    csub = p.add_subparsers(dest='correction_command', required=True)
    d = csub.add_parser('drop', help='release every correction an item is holding')
    d.add_argument('item')
    d.add_argument('--why', help='why the correction is released (recorded beside it)')
    env.add_product_arg(d)
    d.set_defaults(func=cmd_drop)
    return p
```

Three things are load-bearing. The holds are gathered **before** the first append and the loop walks
that fixed list. Every line of one call carries the one `now` and the one `--why` (F-0218 §C5: one
operator decision is one stamp). `left` is a second read of the file after the last append — a
re-read really re-folds, because the fold cache is keyed on the file's bytes (F-0218 §P6) — so what
it names is what the next tick will see, and in practice it is empty: the only thing that can be
left is a hold written while the command ran.

`asf/cli.py`, beside `unpark`'s two lines (`:290-291`):

```python
    from asf.workers.correction import register as register_correction
    register_correction(sub)
```

### §2 `branch_is_gone` — nothing left to correct

`asf/workers/health.py`, beside `prune_branches`:

```python
def branch_is_gone(product, branch, heads=None):
    """True when ``branch`` is nowhere: not a head on origin, not a local ref, and held by no
    worktree. A correction on such a branch can never be answered — a launch on it would not
    resume the work, it would cut a fresh branch off the trunk (`spawn._branch_exists_on_origin`)
    and hand the session a hold about work that does not exist. False whenever the answer is not
    certain: an `ls-remote` that failed says nothing, and nothing is dropped on a guess."""
    repo = product.repo_dir
    if not branch or not repo:
        return False
    sha = (heads or lifecycle.RemoteHeads()).sha(repo, branch)
    if sha is None or sha:           # unanswerable, or origin carries it
        return False
    if _git(['rev-parse', '--verify', '--quiet', f'refs/heads/{branch}'], repo).returncode == 0:
        return False                 # a local ref still holds the commits
    return not any(wt for b, wt in _lane_branches(product) if b == branch)
```

The three questions are asked in cost order: the pass's one `ls-remote` first (P8), then two local
git calls only for a branch origin does not carry — which, on a healthy product, is almost none.
`sha is None` is the failure case `RemoteHeads` documents (a glob, an unplaceable checkout, a failed
`ls-remote`), and it returns False: **nothing is dropped on an answer the snapshot could not give.**

### §3 The lane's drop

`asf/tick/step_health.py`, beside `hold_failed_corrections` and called from `run` right after it:

```python
def drop_unanswerable_corrections(ctx, sessions, out=print, items=None):
    """A correction whose branch is nowhere is dropped (F-0231): the session it asks for cannot
    resume work that never reached origin and no longer exists locally, so the lane releases the
    hold and the item's own feeder row relaunches it — `2fabf6c`'s rule for a first death,
    applied to the rows it left behind.

    Never a park: a park waits for a person by design, and `asf unpark` (or `asf correction
    drop`) is its exit. Never a live run: only a run that has ended is judged."""
    product = ctx.product
    path = pool_mod.sessions_path(product)
    heads = lifecycle.RemoteHeads()  # one ls-remote for the step
    now = pool_mod.now_iso()
    for item, corr in sorted(lifecycle.corrections(path).items()):
        if corr.get('parked'):
            continue
        branch = corr.get('branch')
        if not branch or not health_mod.branch_is_gone(product, branch, heads):
            continue
        for job, held in correction_mod.pending_jobs(path, item):
            if held.get('at') != corr.get('at') or not (sessions.get(job) or {}).get('ended'):
                continue
            why = f'{branch} is on no remote, no worktree and no local ref'
            pool_mod.update_session(product, job, correction=None, dropped=now, drop_why=why)
            line = f'dropped {item} ({job}): {corr.get("kind")} — {why}'
            ctx.event('dropped', job=job, item=item, text=line)
            out(line)
    return 0
```

It reads the same `lifecycle.corrections` map the feeder reads, so what it drops is exactly what
would have become a row. The inner loop matches on the correction's `at` so a second hold written on
another job of the same item is left alone — one judgement, one release.

### What it looks like when it is there

F-1129, released by hand before B-1382 closes:

```
$ asf correction drop F-1129 --why "2fabf6c: the branch never existed" --product <p>
dropped died on F-1129 (spec-f-1129): died twice: the session and its cold retry both ended without a result
dropped 1 correction on F-1129
why: 2fabf6c: the branch never existed
$ echo $?
0
```

One line is appended to `sessions.jsonl`, the hold's own line stays in it, and a second call says
`F-1129 holds no correction — nothing to drop` with code 1.

The same correction, if nobody gets there first — the tick's `health` step, on its own:

```

dropped F-1129 (spec-f-1129): died — cloud/spec-F-1129 is on no remote, no worktree and no local ref
```

and the row that would have launched on that branch is gone from the next wave.

## Records

- **`<state>/sessions.jsonl`** — one appended line per released hold:
  `{"job": "<job>", "correction": null, "dropped": "<one stamp per call>", "drop_why": "<--why, or
  the lane's own sentence>"}`, plus `"unparked"`/`"unpark_why"` on that same line when the hold was
  a park (C5). Every hold line and every earlier undo stays in the file; the record only grows.
  `dropped` and `drop_why` are **not** added to `RUN_FIELDS` — they fold at job level, as
  `unparked` does (P7), so the next launch on the job does not wipe the fact that a hold was
  released.
- **The tick's event stream** — one `dropped` event per lane drop: `ctx.event('dropped', job=…,
  item=…, text=…)`, the shape `hold_failed_corrections` already uses for `held`. The operator's own
  `asf correction drop` writes no event: it is the operator, at a terminal, reading the output.
- **stdout** — the command: one `dropped <what> on <ITEM> (<job>): <text>` per release, then
  `dropped N correction(s) on <ITEM>` with its `— N still holds it` tail when anything remains,
  then one `still held (<job>): …` per remainder, then `why: …` when `--why` was given. Exit 0 on
  any release, 1 for `holds no correction` and for `is not in the ledger`. The step: one
  `dropped <item> (<job>): <kind> — <branch> is on no remote, no worktree and no local ref` per
  drop, under the tick's `== health` heading.
- **The feeder's rows** — no write, and one row fewer. The `FIX → CORRECT` row P1 measured is gone
  the moment the hold is; the item falls back to whatever row its own state asks for, which for
  F-1129 is the `CARD → SPEC` row it should have had all along (C8).
- **`asf/surface.py`** — one new row, `'correction': ('release a correction the ledger is holding',
  RECORD, None)`, taking the table to 50.
- **Nothing is written to the record.** No Bug is filed, no card changes state; a dropped hold is a
  ledger fact and a printed line (C8).
