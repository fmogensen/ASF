# F-0235 — thirty-nine sessions died on a check any of them could have run at any point

Thirty-nine runs ended `failed: hook refused` over fourteen days — 19.5 a week against a threshold
of 5 — for $118.73 and 14.1 hours that landed nothing. That is $3.04 and 21.7 minutes per run: these
are not stubs that fell over on the first tool call, they are whole sessions that did their work and
then lost it.

Lost it to what? `push_retry` (`asf/workers/health.py:495-511`) is the one place the class is
written, and it reads exactly two things — so the thirty-nine split into exactly two populations:

- **`said`** — the run's own REPORT line, `pushed: no — <something hook-shaped>`. The session
  pushed, the product's `pre-push` hook refused, the hook printed what was wrong, and the session
  **wrote that down as its ending** instead of fixing it. It was standing in front of the answer,
  with its whole context live and a file:line in hand, and it stopped.
- **`published`** — the factory's own publish push refused (B-0056). The session never pushed at
  all, so the hook's verdict arrived after the session's process was gone and there was nobody left
  to answer it.

Both are the same defect wearing two coats: **the only moment this factory lets a session learn what
its pre-push hook thinks is the last moment, when it is too late to do anything about it.** A fix in
the run is a handful of tool calls. A fix after the run is a whole new session — $3, twenty-two
minutes, and a relaunch that then has to re-derive context the first session already had.

This factory has made this exact move once before, and it worked. F-0035: a worker account name
landed in a product spec, the product's redact `pre-push` hook refused the push with nothing more
useful than *push refused*, and one item burned 7+ rounds. The answer was not a better hook — it was
`_redaction_findings` (`asf/workers/lifecycle.py:1312-1330`), the factory running *the same scan the
hook would run* before it ever pushes, so the refusal is precise and up front. F-0235 is F-0035's
move applied to the leg F-0035 never covered: **the session's own push**, and the session's own
response when it is refused.

Three things, in the order they pay:

1. **The gate the session can run** — the brief names the exact push-free command that runs what its
   `pre-push` hook runs, so the verdict is available at minute one, not at minute twenty-two.
2. **The refusal that ends no turn** — a refused push is a thing to fix, not a thing to report; and
   when a session says it already retried and the hook said the same thing twice, the factory
   *believes it* and routes the refusal on the first hold instead of launching a second session to
   learn what the first already wrote down.
3. **The word for what refused** — the correction records the class, so when the card's own verify
   re-reads this number in two weeks, which class did not move is a fact on the ledger.

### In

- **`preamble.PRE_PUSH_RULE`, and `pre_push_rule(product, repo_facts)`** — one standing rule,
  carried beside `REDACTION_RULE` whatever `rules_tail` says, naming the exact push-free command
  that runs what this product's `pre-push` hook runs. Derived from the product the way
  `full_suite_rule` is (P9).
- **`repo_facts['pre_push']`** — a tenth key of `REPO_FACT_KEYS`: `{'present': bool, 'ours': bool,
  'path': str}`, filled by `asf.briefs.facts.repo_facts`, which is the one place allowed to run the
  git that `hooks.git_hooks_dir` needs (P7, P8).
- **`hooks.pre_push_hook(repo)`** — `(present, ours, path)` for a repo's installed `pre-push`, on
  top of `git_hooks_dir` and `is_git_hook_ours`. The hook-path knowledge stays in the one module
  the convention fence exempts for it (P13).
- **`preamble.HOOK_REFUSAL_RULE`** — a standing rule, carried unconditionally: a refused push is not
  the end of a turn. Fix what the hook named, commit, push again. Only a second refusal of the same
  thing ends the turn, and then the report says so in a shape the factory can read.
- **`report.hook_retried(rep)`** — pure over a parsed report: True when the `pushed:` value declares
  the session already retried and the hook refused the same thing twice (P12).
- **`lifecycle.hook_refusal_hold(..., retried=False)`** — when `retried` is True, the first hold is
  treated as the cap: the redaction park and the `at_cap` routing fire immediately, because the
  session has already spent in-run exactly the retry the second session would have been launched to
  make. `health` passes it through from `push_retry`.
- **`correction['refusal']`** — the class that refused, one of `redaction`, `footprint`, `gate`,
  written by `hook_refusal_hold` and named in health's lane line.

### Out

- **No scorecard edit of any kind** — not the cause keys, not `failure_class`, not `DEAD_PREFIXES`,
  not the thresholds. P5 is the whole mechanism: the reading falls because fewer runs end
  `failed: hook refused`, and the key keeps meaning exactly what it meant. Regrouping or renaming it
  would make this card's own verification — the loop re-reading the same key over the two weeks
  after landing — impossible.
- **No change to the free first relaunch for a session that did *not* retry.** B-0097's reason
  stands: a session that never saw the hook's output is not at fault for the hook, and spends no
  round. Only a session that *says* it retried and was refused the same thing twice skips the second
  run — and it skips it because it already did that run's work.
- **`asf` does not write, edit, wrap or re-run a product's own `pre-push` hook.** `hooks install`
  already refuses to touch a hook asf did not write (P7); this card only *reads* where it is and
  tells the session. A hook that is not asf's is named by path, never executed by the factory.
- **Nothing rests on `git push --dry-run`.** P14: the behaviour is unverified on this host, and a
  gate that silently stopped running would be worse than no gate.
- **No new hold kind, no new `end_reason`, no new outcome class.** `hook refused` stays one class
  with one meaning. This card lowers its count; it does not redefine it.
- **The footprint class is not re-handled.** P11 already takes it off the budget the same tick, and
  this card must not race it: `refusal_facts` keeps first claim on a footprint-shaped refusal.
- **`STORY_ID_RE`'s four-digit shape is not fixed here** (P15).

| # | Chosen | Against | Why |
| --- | --- | --- | --- |

What costs $118.73 is not that the second session is badly briefed; it is that a *first* session died. Only moving the verdict earlier removes a run instead of discounting one. |

| D3 | **`asf redact --unpublished` for asf's own hook; the hook's path, named not run, for a product's own** | One uniform "run the hook file with the pre-push stdin protocol" | For asf's hook the push-free equivalent already exists, is exactly as strict or stricter (P6), and needs no protocol at all. ## The design

### 1. `hooks.pre_push_hook(repo)` — where the hook is, and whose it is

New in `asf/hooks.py`, beside `git_hooks_dir` (`:66`) and `is_git_hook_ours` (`:117`):

```python
def pre_push_hook(repo):
    """``(present, ours, path)`` for ``repo``'s installed ``pre-push`` hook: whether the file
    exists, whether asf wrote it (:func:`is_git_hook_ours`), and its absolute path. Runs git
    (:func:`git_hooks_dir`), so only a caller that already does may call it. ``(False, False, '')``
    for a repo that is not a git repo, has no hooks dir, or has no ``pre-push``."""
```

No new path convention is introduced: `GIT_HOOK_NAMES` (`:63`) already owns the name, and this
module is the convention fence's documented exception for exactly this knowledge (P13).

### 2. `repo_facts['pre_push']` — the fact, carried the one legal way

`REPO_FACT_KEYS` (`asf/briefs/preamble.py:234`) gains `'pre_push'`, making ten. `repo_facts`
(`asf/briefs/facts.py:335-338`) initialises it to `{'present': False, 'ours': False, 'path': ''}`
and, inside the existing `if repo and os.path.isdir(repo):` block at `:344`, fills it from
`hooks.pre_push_hook(repo)`. The contract test at `tests/test_brief_facts.py:96-105` keeps the two
in step by construction — it is the reason this is one edit in two files and not a drift.

`preamble.collect` (`:404`) carries it into `facts['pre_push']` the way it carries `outlines` at
`:445`, unread anywhere else.

### 3. The pre-push gate, in `### Standing rules`

Two new module constants in `asf/briefs/preamble.py`, beside `REDACTION_RULE` (`:117`):

```python
#: Carried by every brief whose product has a pre-push hook (F-0235): the command that runs what
#: that hook runs, without a push — so the hook's verdict arrives at minute one, not at the last
#: minute of the run, when a session has nothing left to do with it but write it down as its
#: ending. asf's own hook has a push-free twin (``redact --unpublished``, at least as strict as
#: ``--pre-push``); a hook asf did not write is named by path and never run by the factory.
PRE_PUSH_GATE_OURS = ("- Before your first push, run `asf redact --unpublished` and make it clean: "
                      "it scans exactly the commits your push would add, and it is what your "
                      "pre-push hook will run. A finding it names is a finding the hook will "
                      "refuse.")
PRE_PUSH_GATE_THEIRS = ("- Before your first push, run this repo's own pre-push check — `{path}` "
                        "is the hook that will judge it. A refusal at push time is the same "
                        "refusal, bought a whole run later.")
```

and the function that picks between them, shaped like `full_suite_rule` (`:141-149`):

```python
def pre_push_rule(facts):
    """The pre-push gate line for a brief, or None when the repo has no ``pre-push`` hook or the
    fact was never filled. Pure: reads ``facts['pre_push']``, never git (P8)."""
```

The `Section('rules', …)` assembly at `:698-700` becomes:

```python
rules_block(product, main).splitlines() + [subject_rule(row, facts['item'])]
+ [REDACTION_RULE] + [r for r in (pre_push_rule(facts), HOOK_REFUSAL_RULE) if r]
+ ci_rules(product)
```

`REDACTION_RULE`'s own trailing sentence — *"Run the redaction check before you push"* (P10) — is
left exactly as it stands: it is the *why*, and the new line is the *how*. A brief for a product
with no pre-push hook carries the redaction rule as it does today and no gate line.

### 4. The refusal that ends no turn

The second new rule, carried unconditionally — the one line in the whole factory that tells a
session what a refused push actually is:

```python
#: Carried by every brief, whatever ``rules_tail`` says (F-0235): 39 runs in 14 days ended because
#: a session treated its hook's refusal as its ending. The hook prints a file and a line; fixing it
#: is a handful of tool calls inside a run that already has the context, and a whole session
#: otherwise. The second clause is what the factory reads back (:func:`asf.workers.report.hook_retried`).
HOOK_REFUSAL_RULE = ("- A push your pre-push hook refuses is not the end of your turn: it printed "
                     "what is wrong and where — fix that, commit, and push again, then report "
                     "`pushed: yes <sha>`. Only if the hook refuses the *same* thing a second "
                     "time do you stop, and then the report reads "
                     "`pushed: no — hook refused twice: <what it said>`.")
```

### 5. The retry the factory never spends twice

`asf/workers/report.py` gains one pure reader beside `unpushed` (`:65-68`):

```python
#: The shape :data:`asf.briefs.preamble.HOOK_REFUSAL_RULE` asks a session for when it fixed what
#: the hook named, pushed again, and was refused the same thing: the session has already spent the
#: retry, so the factory does not spend a session on it (F-0235).
HOOK_RETRIED_RE = re.compile(r'\bhook\s+refused\s+twice\b', re.I)


def hook_retried(report):
    """True when the report's own ``pushed:`` line declares a refusal the session already retried."""
```

`asf/workers/health.py` reads it once, where it already parses the same report (`:501`), and carries
it into the hold at `:675`:

```python
fields, line = lifecycle.hook_refusal_hold(registry, s, text, now, retried=retried)
```

`lifecycle.hook_refusal_hold` (`:2163`) takes `retried=False` and changes one line — the cap test:

```python
if same < HOOK_REFUSAL_CAP and not retried:
    return {'correction': corr}, f'held {branch}: {text} (no round spent)'
```

Everything below it is untouched: a redaction finding parks with `operator_flagged`, anything else
takes `at_cap` and goes to ADJUDICATE. `corr['retried'] = True` is written beside `same` so the
ledger says why the first hold routed.

**What this removes, run for run:** a session that fixes the refusal in-run costs zero dead runs
where it cost two. A session that retries and is genuinely blocked costs one where it cost two. A
session that never pushed at all is unchanged — it still gets its free relaunch (D5).

### 6. The class that refused

`hook_refusal_hold` writes `corr['refusal']`, computed from the text it already has:

| text matches | `refusal` |
| --- | --- |
| `HOOK_REDACTION_RE` (`lifecycle.py:145`) | `redaction` |
| anything else | `gate` |

`widen_footprint.refusal_facts` (`asf/tick/widen_footprint.py:158`) overwrites it with `footprint`
on the corrections it turns, in the same tick and before any wave reads them (P11) — it keeps first
claim, so the three classes stay disjoint. Health's lane line names it: `held <branch>: <text>
(no round spent, gate)`.

Nothing keys off `refusal` in this card. It exists so that the verify clause — *"the loop reads this
number over the 2 weeks before this card lands and the 2 weeks after; it must fall by 20 %"* — has
something to read when it does not fall.

### What it looks like when it is there

A coder brief for a product whose repo carries asf's pre-push hook ends:

```
### Standing rules
- Commit with `git commit -s`; the sign-off is the record that you did this work.
- Never push to `main`, never force-push, never `--no-verify`, never open a pull request.
- Push your own branch before your turn ends — after every commit, and once at the end even if
  nothing changed.
- Keep a heartbeat: print a progress line as you go; a silent session is read as a dead one and
  relaunched on top of you.
- Finish with the typed REPORT below, as the last thing you print.
- Anything a human must decide or run: `NEEDS OPERATOR: <what> — <the command or the answer>`.
- Every commit subject names the item: `task(T-0999): <what>`. …
- Never write a worker account name or a machine path into the product; refer to a lane as
  `lane-N`. Run the redaction check before you push.
- Before your first push, run `asf redact --unpublished` and make it clean: it scans exactly the
  commits your push would add, and it is what your pre-push hook will run. A finding it names is a
  finding the hook will refuse.
- A push your pre-push hook refuses is not the end of your turn: it printed what is wrong and
  where — fix that, commit, and push again, then report `pushed: yes <sha>`. Only if the hook
  refuses the *same* thing a second time do you stop, and then the report reads
  `pushed: no — hook refused twice: <what it said>`.
- Locally, run only the targeted checks for what you changed, then push: …
```
