# F-0315 — the hold is a shared file, not a shared Feature

The pass that forms deliveries writes one kind of `after:` edge it never justifies. `deliveries`
(`asf/record/slice.py:226-233`):

```python
started = started_tasks(metas, fid, busy)
...
covered = {a for m in members for a in (metas[m].get('after') or ())}
extra = [t for t in started if t not in covered and t not in members]
```

`started` is *every* Task of the Feature that is under way. Nothing between that line and the
write asks whether the delivery and the started Task would ever touch the same file. Membership of
the same Feature is taken as a reason to wait — and the Feature is precisely the unit the delivery
mechanism exists to parallelise.

The card's requirement is the one sentence that line is missing: **a delivery lead waits on a
started Task when and only when their footprints name a common path.** Beside it, the card names a
second defect with the same cause — the pass bundles Tasks an `asf undeliver` has already ruled
out of a delivery, so the ruling is undone by the next tick and the false edges come back with it.

Both halves are measured below against the reporting product's own record, as it stands today
(§1, P1–P5): the pass would add **14** edges on the next tick, **none** of which names a shared
path, and **all five** deliveries it would form are re-bundles of cards an `asf undeliver` already
took out.

* **P10 — `asf check` says nothing about a lead's `after:`.** `check_deliveries`

### Preconditions the work depends on

* `conventions.delivery: feature` — the pass does not run for a product that did not opt in
  (`tick.py:130`), so neither does any of this.
* The card's `writes:` is the footprint. A Task with no `writes:` intersects nothing and binds
  nothing: `first_intersection` of an empty list is `None`, and the pass draws no edge. That is
  the honest answer — a plan that declared no footprint declared no claim on a file — and it is
  what `unordered_overlaps` already does (`invariants.py:305`: `and t.get('writes')`).
* `## History` is the card's own section and the pass only reads it. A product whose cards carry
  no `## History` has no undelivered Tasks to exclude.
* The pass keeps running inside `stage.guarded` with `product=`, so I3 still sees its writes (P9).

## The design

Four files. One new helper in the feeder's footprint module, one new reader in `undeliver.py`, the
rule and the line in `slice.py`, and the test module's fixture re-cut.

### 1. `asf/feeder/footprint.py` — one owner for "they share this path"

```python
def first_intersection(writes_a, writes_b, shared=()):
    """The first ``(glob_a, glob_b)`` pair of two footprints naming a common path by ``asf
    check``'s own test (:func:`asf.record.core.writes_intersect`), or None — the witness, so a
    caller can say *which* path made it wait. A glob the product declared ``shared``
    (:func:`is_shared`) names no common path: every Task writes the lockfile, so the lockfile
    orders nothing.

    The narrow test, beside :func:`overlaps`' wider one. ``overlaps`` errs on waiting for two
    open-ended globs that *may* name a common file, which is right for a gate whose false
    positive costs one tick and wrong for an ``after:`` edge written into the record (F-0315
    D2)."""
```

`invariants.unordered_overlaps` loses its inlined double loop (`invariants.py:308-320`) and calls
this instead — same test, same `shared` skips, same first-pair witness, so `ordered` and the
`(owner, held, glob_owner, glob_held)` rows it returns are unchanged. `tests/test_invariants.py`
run whole is what says so.

### 2. `asf/record/undeliver.py` — the line, read back

```python
#: :data:`HISTORY` with ``{who}`` empty — the **member's** own line, the one that says *this card*
#: was taken out of a delivery. The lead's line carries the member's id where this one carries
#: nothing, so a lead that lost its last member does not read as a card that was undelivered
#: itself (F-0315 D5).
MEMBER_RE = re.compile(r'(?m)^\s*-\s+\S+\s+undeliver:\s+undelivered from\s+(\S+?):')


def undelivered_from(text):
    """The lead ids ``text``'s ``## History`` records this card as undelivered from, first-seen
    order; ``[]`` for a card no ``asf undeliver`` ever touched. The read-back of :data:`HISTORY`,
    and the one answer to "has this Task been ruled out of a delivery" — :mod:`asf.record.slice`
    asks it of every Task before it bundles one."""
```

### 3. `asf/record/slice.py` — the rule, and the line that says why

A `skip` set threaded through the two readers, defaulting to `()` so the preview and the tests
that call them keep working unchanged:

```python
def undelivered_tasks(canonical):
    """The Task ids an ``asf undeliver`` took out of a delivery — the ones the pass never bundles
    again (F-0315 D4, D6). Reads each card's ``## History``
    (:func:`asf.record.undeliver.undelivered_from`), because ``undeliver`` deletes the
    ``delivered_by:`` the frontmatter would otherwise carry."""


def free_tasks(metas, fid, busy=(), skip=()):      # ... and ``tid in skip``: never again
def plan_slices(metas, fid, conv, busy=(), skip=())
```

and the pass's own body, where the fourteen edges come from:

```python
from asf.feeder import footprint        # lazy: the record does not import the feeder at module scope
shared = footprint.shared_globs(product)
skip = undelivered_tasks(canonical)
...
for n, (lead, members) in enumerate(slices, 1):
    waits = [a for a in (metas[lead].get('after') or ()) if isinstance(a, str)]
    covered = {a for m in members for a in (metas[m].get('after') or ())}
    binds, loose = [], []                      # (started, member, glob_pair) | started
    for t in started:
        if t in covered or t in members:
            continue
        hit = next(((m, g) for m in members
                    for g in [footprint.first_intersection(metas[t].get('writes'),
                                                            metas[m].get('writes'), shared)]
                    if g), None)
        binds.append((t, *hit)) if hit else loose.append(t)
    extra = [t for t, _m, _g in binds]
```

`extra` is what it always was — the list written to the lead's `after:` — now filtered to the
started Tasks that share a path with a member. Everything downstream (`set_typed`, the
`delivered_by:` writes, the returned `{lead: members}`) is untouched.

The line keeps its one-per-delivery shape and gains the witness per edge (D5). Each clause is
`<started> (<member> shares <glob>)`, with ` ~ <started glob>` appended when the two globs are not
the same string, and a trailing clause names the started Tasks that bound nothing:

```python
def _edge_clause(t, member, glob):
    mine, theirs = glob                        # (the started Task's glob, the member's)
    return f'{t} ({member} shares {theirs if theirs == mine else f"{theirs} ~ {mine}"})'
```

```

A glob matching a path:

```

```

P1's fixture, which is the defect:

```

## Acceptance tests

Run from the checkout root. The classes named below **do not exist yet**: the plan that follows
this spec mints one Task per Story to write them. `MigrationTests` and `tests.test_invariants` do

**S-80904 — the intersection, with its witness, and one owner.**

```bash
python3 -m unittest tests.test_shared_paths.FirstIntersectionTests tests.test_invariants -v
```

Asserts `first_intersection(['a.py'], ['b.py'])` is `None`; `(['asf/record/slice.py'],
['asf/record/*.py'])` returns that pair in that order, the first one of each list that matches;
that a later matching pair is not returned once an earlier one has matched; that an empty or
absent footprint on either side is `None`; that a glob `shared=('uv.lock',)` covers is skipped on
*either* side, so two footprints whose only common glob is the lockfile are `None`; that
`'asf/record/'` against `'asf/record/slice.py'` is `None` where `globs_overlap` is `True` (P7, the
one divergence D2 accepts); and — the one-owner half — that `tests/test_invariants.py` passes
whole, `OrderedOverlapTests` and `OverlapYieldsToProgressTests` included, with
`unordered_overlaps` calling the new helper.

**S-80905 — a lead waits on a started Task only when they share a path.**

```bash
python3 -m unittest tests.test_feature_delivery.SharedPathBindingTests \
                    tests.test_feature_delivery.MigrationTests -v
```

`SharedPathBindingTests` asserts, on the record fixture: a Feature with a two-Task bundle and one
started Task whose `writes:` are disjoint from both members leaves the lead's `after:` exactly as
it was (the card's first acceptance — written, not merely absent: a lead that already declared
`after: T-0009` still declares it and nothing else); a started Task whose glob *matches* a
member's path binds the lead; a started Task sharing a path with a **non-lead** member binds the
lead, not the member; a started Task a member already declares `after:` is not added to the lead
again, overlapping or not; a started Task whose only common glob is the product's declared
`shared_paths` entry does not bind (D3); a Task with no `writes:` binds nothing and is bound by
nothing; and that the whole of P1's fixture now returns `{'T-0002': […]}` with no `after:` on the
lead.

`MigrationTests` is the card's second acceptance, re-cut (D7, P6): its started `T-0002` and a
member share a path and the edge is asserted as it is today, and a second started Task with
disjoint writes is asserted to add nothing — the overlap case and the disjoint case in the class
that owns the migration.

### S-80904: one owner for two footprints sharing a path, and the witness glob that says which

Design §1 — `footprint.first_intersection`, and `invariants.unordered_overlaps` refactored onto it
(D2, D3; P7). Acceptance is the first fenced block of `## Acceptance tests`. The helper returns the
glob pair, not a boolean, because §3's line has to name the path that caused the wait: a hold whose
reason cannot be printed is how the 43 edges went unnoticed for fifteen releases.

- [ ] two footprints naming no common path return nothing at all
- [ ] a glob and a path it matches come back as a pair, in the order the two footprints were given
- [ ] the first matching pair is the one returned, and a later matching pair is not
- [ ] an empty footprint, or none at all, on either side returns nothing
- [ ] a glob the product declared a shared path is skipped on either side, so two footprints whose only common glob is the lockfile return nothing
- [ ] a bare directory glob against a path beneath it returns nothing, where the feeder's wider overlap test says it overlaps
- [ ] the overlap invariant's own tests pass whole with the invariant calling the new helper instead of its own inlined loop

### S-80905: a delivery lead waits on a started Task only when they share a path

Design §3's rule — the `binds` / `loose` split that replaces `extra = [t for t in started …]`
(D1, D2, D3; P1, P2). Acceptance is the second fenced block of `## Acceptance tests`, and it is
the card's first two requirements together: the disjoint case in a new class, the overlap case in
`MigrationTests`, whose fixture is re-cut because all three of its current edge assertions are the
defect written down as expected behaviour (D7, P6).

- [ ] a Feature with a two-Task bundle and one started Task whose writes are disjoint from both members leaves the lead's after list exactly as it was
- [ ] a lead that already declared an after edge of its own still declares it, and nothing more
- [ ] a started Task whose glob matches a member's path binds the lead
- [ ] a started Task sharing a path with a member that is not the lead binds the lead, not that member
- [ ] a started Task that a member already declares an after edge on is not added to the lead a second time, whether their paths meet or not
- [ ] a started Task whose only common glob is the product's declared shared path does not bind the lead
- [ ] a Task declaring no footprint at all binds nothing and is bound by nothing
- [ ] the migration case still binds the lead on a started Task that shares a path with a member, and adds nothing for a second started Task that shares none

### S-80906: the pass names each edge it adds, the member and the path that caused it

Design §3's line and `_edge_clause` (D5). Acceptance is the third fenced block of
`## Acceptance tests`. The pass is the only thing that sees both halves of the decision, so it is
the only thing that can say why; and the count of started Tasks it declined to wait on is the
operator's parity signal — the difference between a delivery that launched because nothing was
running and one that launched because nothing was shared.

- [ ] the pass still prints exactly one line per delivery it writes
- [ ] each edge on that line names the started Task, the member, and the glob they share
- [ ] two globs that are not the same string are both printed, the member's first
- [ ] two globs that are the same string are printed once
- [ ] the started Tasks that bound nothing are named on the line with their count
- [ ] both clauses are absent from the line when there is no edge and no unbound started Task
- [ ] the slice prefix naming the Feature and the slice number, and the proves clause naming the Stories, are unchanged — proven by tests/test_feature_delivery.py
