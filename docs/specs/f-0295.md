# F-0295 — the two infra reds are answered on two paths, and the gate is not one of them

The card names two CI reds that judge no code and asks that each be re-run once instead of held
for a hand re-run:

1. a **phantom failure** — a run reports `status=completed, conclusion=failure` while some of its
   jobs are still `queued`, some required jobs have no job at all, and no job failed;
2. a **lost runner** — a job ended `failure` with no `runner_name`, no failed step, and logs that
   return `BlobNotFound`.

Most of that machinery is already on the trunk. `59e7cd36a` (the fix for F-0287, PR #1042, landed
2026-10-07 21:30Z — *after* this card's own sighting that morning) added the classifier
(`flake.classify_red`), the one re-run (`flake.infra_rerun`) and the reader that joins them
(`flake.infra_class`), and wired them into the review path and the `asf land` path. The card's
exact shape — one run behind the head's checks, a required job missing, another queued — is
answered there today, measured (P8). So this spec is **residual only**: it does not re-specify the
classifier, and it mints no second one.

What is left is where the two reds are still read as reds, and two shapes of the same red the
landed reader cannot see:

* the **landing gate** — `GitHubHost.check_gate`, the method that decides MERGING or BACK — never
  asks the classifier at all. A lost-runner red there is sent BACK as a correct round (P4): a
  session is launched against a head nothing is wrong with. A phantom there is waited out for good
  (P5), or waited out and then gated locally.
* the landed reader answers only when **exactly one run** sits behind the checks it is given
  (P7), and the land path's pending probe **stands down whenever any waiting check is
  `in_progress`** (P6) — though such a run is still a phantom (P2). A real head carries checks
  from more than one workflow and usually has something running, so both guards fire on the very
  incident the card describes.
* when the factory does re-run, **nothing says so where the operator looks** (P10): the `infra`
  claim is written to a ledger that only partitions *cancelled* runs, and `asf status` shows the
  flake triage's quarantine and held re-runs but not the infra re-run or its watchdog breach.

### In

1. **The landing gate answers both infra reds.** `GitHubHost.check_gate` gets one helper and three
   call sites: after `cut_short` in the red branch (so a lost-runner red is re-run once instead of
   sent BACK), in the `pending` branch before it waits, and in the `skipped or missing` branch
   before the clock that ends in a local gate. The budget is the landed one — one re-run per head,
   shared with the review path and the land path (C5).
2. **The reader reads every run behind the checks it is given.** `infra_class` groups the checks by
   run id, reads each (each throttled by its own `probe|<rid>` record), and answers for the first
   run that is an infra red in the order the ids appear. A link with no run id is skipped instead
   of killing the whole answer.
3. **The land path's pending probe stops standing down on a running check.** The run's own
   `completed`/`failure` is the phantom test (P2); `PHANTOM_PROBE_S` is what keeps the read cheap.
4. **The re-run and the breach are visible.** `flake.status_cell` names the live infra re-runs and
   any breach, so `asf status` says the factory re-ran a head once and says when it refused to
   re-run it twice.

### Out

- **The classifier.** `classify_red`, `_lost_job`, `INFRA_CLASSES`, `_UNFINISHED`, `INFRA_RERUNS`
  and `infra_rerun`'s own answers (`rerun`/`refused`/`breach`/`held`) are untouched: P1 and P2
  measured them right, and P8 is the card's own shape passing.
- **A second re-run.** The budget stays one per head across every path (C5). The gate's new call
  can only re-run a head no path has re-run yet.
- **The merge-queue batch path.** It already answers a lost runner and a non-verdict batch (P11),
  with its own per-`(sha, job)` budget; a second mechanism there would collide with it.
- **`recheck`.** The pre-MERGING re-read refuses a merge and nothing more; the next pass's
  `check_gate` is where that head is answered, now including its infra reds.
- **The trunk red watch.** `asf.trunk_red` and `asf.trunk_watch` reading a phantom on the trunk as
  a trunk red is a different card: it holds every PR rather than one, and it reads a sha nobody's
  gate is waiting on.
- **`BlobNotFound` as a signature.** No log read is added (C6).
- **A new cancel cause, a new state file, a new config key.** `ci_cancels.CAUSES` and `GROUPS` are
  unchanged, the records stay `flake-triage.json` and `ci-cancels.json`, and `PHANTOM_PROBE_S`
  stays a constant (C7).
- **The flake budget.** Quarantine, `reproduced`, the deterministic-job rule and
  `QUARANTINE_RERUNS` are not touched: an infra red spends no flake attempt today and still does
  not.
- **`docs/design`, `docs/KNOWN-ISSUES.md`, `CHANGELOG.md`.** This session creates
  `docs/specs/f-0295.md` and nothing else.

## The design

Three files: **`asf/flake.py`** (the reader and the status row), **`asf/harvest/lane.py`** (the
gate), **`asf/merge_queue.py`** (one guard removed), plus `tests/test_ci_red_class.py`,
`tests/test_merge_queue.py` and a new `tests/test_gate_infra_red.py`.

### 1. `asf/flake.py` — the reader answers for every run behind the checks

```python
def _run_ids(checks):
    """The workflow run ids behind ``checks``, first-seen order — a check with no readable run
    id is skipped, never an answer of its own."""
    out = []
    for c in checks or ():
        if not isinstance(c, dict):
            continue
        rid = _ids(c.get('link') or c.get('html_url') or c.get('details_url'))[0]
        if rid and rid not in out:
            out.append(rid)
    return out


def infra_class(slug, checks, required=None, gh=None, state_dir=None, now=None):
    """``(class, run id, attempt)`` for the first run behind ``checks`` that is an infra red
    (:func:`classify_red`: a phantom or a lost runner), else None — every run reads as a test
    red, no link carries a run id, or none can be read.

    A head carries checks from more than one workflow, so every run id the links name is read,
    in the order they first appear (F-0295 C3). With ``state_dir`` each run is read at most once
    per :data:`PHANTOM_PROBE_S` (the caller polls a pending head every pass); a run inside its
    interval is skipped, and the others are still read."""
    now = now or _now()
    data = load(state_dir, now) if state_dir else None
    answer = None
    for rid in _run_ids(checks):
        if data is not None:
            seen = _parse((data['infra'].get(f'probe|{rid}') or {}).get('at'))
            if seen is not None and (now - seen).total_seconds() < PHANTOM_PROBE_S:
                continue    # read inside its interval: the other runs are still read
            data['infra'][f'probe|{rid}'] = {'at': _iso(now)}
        run, jobs = run_jobs(slug, rid, gh)
        if run is None:
            continue
        cls = classify_red(run, jobs, required)
        if cls in INFRA_CLASSES:
            try:
                attempt = int(run.get('run_attempt') or 1)
            except (TypeError, ValueError):
                attempt = 1
            answer = (cls, rid, attempt)
            break           # one head, one answer, one re-run (C5)
    if data is not None:
        save(state_dir, data)
    return answer
```

Two properties the acceptance pins: a run id read gets its own `probe|<rid>` record (so a head
with four workflows costs four reads per interval, not four per pass), and the loop stops at the
first infra red in check order — one head has one answer, because it has one re-run.

### 3. `asf/harvest/lane.py` — the gate asks the same question

One method on `GitHubHost`, beside `cut_short`:

```python
    def infra_gate(self, f, number, required, checks, probe=False):
        """True (and the gate judges nothing this pass) when ``checks`` sit under an infra red
        (:func:`asf.flake.infra_class`: a phantom run or a lost runner) and the factory answered
        it — re-run once on this head, or one watchdog breach on the second. A lost-runner red
        sent to a correct round is a session against a head nothing is wrong with, and a phantom
        waited out is a PR held until someone re-runs it by hand (F-0295).

        ``probe``: a head that is not red is re-read at most once per
        :data:`asf.flake.PHANTOM_PROBE_S`. False when there is no infra red, when the re-run was
        refused, or when nothing could be read: the gate judges exactly as before."""
        from asf import flake
        lane, out = self.lane, self.lane.out
        head = exact_head(f) or f.get('head')
        if not head or not checks:
            return False
        try:
            infra = flake.infra_class(self.slug, checks, required, gh=H._gh,
                                      state_dir=lane.state_dir if probe else None)
        except Exception:   # noqa: BLE001 — unreadable: judged as before
            return False
        if not infra:
            return False
        cls, rid, attempt = infra
        got = flake.infra_rerun(lane.state_dir, self.slug, head, rid, cls,
                                where=f'PR #{number}', out=out, gh=H._gh, attempt=attempt)
        if got == 'refused':
            return False
        said = {'rerun': 're-run queued', 'held': 're-run queued, awaiting it',
                'breach': 'watchdog breach — re-run once already, not again'}
        out(f'waiting {f["branch"]}: PR #{number} infra red ({cls}) at {head[:9]} — '
            f'{said.get(got, got)}, never a correct round')
        wait(lane, f, f'infra red ({cls}): {said.get(got, got)}', state=WAITING_CI)
        return True
```

`judged_pending` is a new module-level helper beside `not_required_red`, the same filter
`pr_checks` uses for its own `pending` list — the gate hands the reader the checks it is actually
waiting on, so a run nothing is waiting on is never read:

```python
def judged_pending(checks, required=()):
    """The required checks of ``checks`` that have not reached a verdict — what the gate is
    waiting on, and the only runs its phantom probe reads."""
    return [c for c in checks or () if c.get('bucket') == 'pending'
            and (not required or required_name(c.get('name'), required))]
```

Ordering is the point: `stale_red` first (a merge ref from before the trunk moved is re-run by
`stale_ref`, not here), then `cut_short` (a cancel's own answer), then `infra_gate`, then the
trunk-red read and `send_back`. The review path (`head_red`, `asf/harvest/lane.py:4848`) keeps its
single landed call and its order, unchanged.

### 4. `asf/merge_queue.py` — the guard goes


The `not any(c.get('status') == 'in_progress' for c in waiting)` clause is deleted (C4). Nothing

behind it and the batch path all stay.

### What it looks like when it is there

A head whose required job failed with no runner is re-run once by whichever path reads it first,
and the lane says so — `waiting worker/T-0001: PR #7 infra red (lost-runner) at 47be7bdd1 — re-run
queued, never a correct round` — instead of launching a correction against it. A head whose run
concluded `failure` with jobs still queued is re-run once instead of waiting for a person, whether
it is land-requested, under review, or sitting at the gate, and whether or not something else on
it is still running. A second infra red on the same head is one `watchdog: BREACH` line and no
second re-run, on every path. `asf status` carries the row that says it happened:
`Quarantine: 1 infra re-run(s): phantom @ 47be7bdd1 re-run once`.

## Acceptance tests

### The landing gate re-runs a lost-runner red instead of sending it back (S-80804)

`tests/test_gate_infra_red.py`, on `tests.test_lane.SkippedRequiredCheck`'s gate harness
(`_host`), with a `gh` that answers by argument: the check list for `pr checks`, `[]` for
`/annotations` (the card's lost runner has none), the run and its jobs for
`/actions/runs/<id>[/jobs]`.

- [ ] one required check `fail`, its job `failure` with `runner_name: ''` and no failed step →
      `check_gate` returns None, `send_back` is **not** called, `gh run rerun <rid> --failed` is
      called exactly once, the lane line reads `infra red (lost-runner) … re-run queued, never a
      correct round`, and the branch is `WAITING_CI` — the P4 probe, inverted
- [ ] the same red read again on the same head after the re-run: no second `run rerun`, one
      `watchdog: BREACH infra red (lost-runner)` line, still no `send_back` (C5)
