# F-0176 — the factory stopped calling a ruling a corpse

The card is one loop with two halves, and both halves are still live on `d005de847`. B-0123 was
adjudicated at least six times in a day; each round ended with `asf` holding `fix/B-0123` under

```
died twice: the session and its cold retry both ended without a result
```

while both job logs ended in a `"type":"result"` record carrying a full ruling — a ruling that
said the branch was ready and `blocked_on: none`, and that the only thing between that HEAD and
`origin/fix/B-0123` was a push the sandbox cannot make.

Both halves reproduce against this checkout.

**The hold text quotes the record it says does not exist.** `hold_failed_corrections`
(`asf/tick/step_health.py:236`) skips a correction that "ran to its end" — but
`ran_to_its_end` (`:230`) reads the result's *verdict*, not its *presence*:

```python
return bool(rec) and not rec.get('is_error') and rec.get('subtype', 'success') == 'success'
```

A result record with `is_error: true` is still a result record. Driving the B-0123 shape through
the real function — two ledger rows, two logs each ending in an `is_error` result carrying the
ruling — produces, verbatim:

```
held fix/B-0123: died twice: the session and its cold retry both ended without a result —
{"type": "result", "subtype": "error", "is_error": true, "result": "REPORT\nitem: B-0123\n…
ruling: the branch is ready; only the missing push credential stands between this HEAD and
origin/fix/B-0123\nblocked_on: none\nwrites: none\n"} — back to its session (round 1)
```

The sentence and the evidence appended to it contradict each other inside one line. B-0150's fix
(`857d3907a`, 2026-09-27, one day after the card was proven) closed the *clean-result* case and
left this one open.

**A ruling that says ready opens no publish.** `publish_gap` (`asf/workers/health.py:352`) and
`republish_steps` (`:474`) both gate on the run's `end_reason` class:

```python
result_ok = reason == lifecycle.FINISHED or (reason or '').startswith(UNPUSHED_REASON_PREFIXES)
```

`UNPUSHED_REASON_PREFIXES` (`:71`) is `('failed: not pushed', 'failed: unpushed work')`. What
`lifecycle.judge` writes for an adjudicate run whose result record is an error record depends
entirely on the `pushed:` line of its own REPORT:

| the REPORT's `pushed:` line | `judge` | publish opens |
| --- | --- | --- |
| `pushed: no — the sandbox has no push credential` | `failed: unpushed work` | **yes** |
| `pushed: rebased abc1234 — the factory publishes` | `failed` | **no** |
| `pushed: yes abc1234` | `failed` | **no** |

Rows two and three are the loop. `report.failure` (`asf/workers/report.py:100`) names a failure
only for `pushed: no`; anything else returns None, `runtime.failure_reason` returns None, and
`judge` falls through to a bare `failed` — which matches no prefix, so neither `publish_gap` nor
`republish_steps` ever touches the worktree. The branch stays off origin. The next session is
launched onto the same unpublished branch, cannot push either, and writes the same ruling.
Row two is the line this repo's own brief instructs a session to write
("`pushed: rebased <sha> — the factory publishes`"), which is how a rule meant to route work to
the factory became the reason the factory never looked.

A bare `failed` run is held by nothing in `health` (`:704`–`:757` handle the retry, empty-branch
and unpushed classes only), so the only hold in the whole loop was the false one above. Fixing the
text alone would leave the branch unpublished for ever; fixing the publish alone would leave the
lie on the ledger. Both are in this card.

## Decisions

### In

1. The phrase "without a result" becomes a function of the log, not of a result's verdict: no hold
   and no correction text claims a session died when `runtime.read_result` returns a record.
2. A ruling that declares the branch ready — a `ruling:` paragraph with no `blocked_on:` claim —
   opens the factory's publish for that run's worktree, whatever `end_reason` class the run fell
   into.
3. A publish (or the commit that precedes it) refused by git is reported with git's own error
   line, not the `hint:` that usually sits last and not the `error: failed to push some refs`
   summary.

### Out

* **Push rights for the adjudicate sandbox** — the card's own alternative. B-0056 already decided
  the other way ("the factory publishes, never the session"), a rebased lane branch needs the
  force the standing rules forbid a session, and a credential is operator configuration, not
  product code. Named here so the plan does not re-open it.
* **Putting `adjudicate` in `lifecycle.NO_LANDING_KINDS`** (`asf/workers/lifecycle.py:1829`). It
  would silence the judgement by declaring the branch not the run's work — the exact opposite of
  what the card asks, which is that the branch be *published*.
* **Re-judging a ruling-ready run `finished`.** Its result record is an error record and that
  failure is real; `health` holds a bare `failed` run nothing, so the loop ends once the branch is
  out. Left alone.
* **The retry class of a 403.** `lifecycle.NETWORK_RE` matches `unable to access`, so a credential
  refusal already classes as a network blip and is retried without a round. Unchanged by this card
  — the text it classes on gets more precise, the classification rule does not move.
* **The feeder's adjudicate row rule** (`asf/feeder/rows.py:756`–`:767`), which decided B-0123
  deserved a seventh adjudication. With the branch published the item leaves the fix loop by
  landing; the row rule is not re-cut here.

## The design

### 1 — a result record is never a death (`asf/tick/step_health.py`)

One predicate, and both text producers branch on it. Nothing else in the module moves.

```python
def wrote_a_result(session):
    """True when the session's log ends its last run in a result record — whatever that record
    says. A run that wrote one did not die: B-0123's two adjudicate logs both ended in a
    ``"type":"result"`` carrying a full ruling while the hold said they "both ended without a
    result" and then quoted one of them (F-0176). This is the presence of the record, never its
    verdict — ``ran_to_its_end`` reads the verdict, and an ``is_error`` result slipped past it."""
    return runtime_mod.read_result(session.get('log')) is not None


def outcome_text(session):
    """What a run that wrote a result actually came to: the ledger's own ``end_reason``, else the
    failure the result declares (:func:`asf.workers.runtime.failure_reason`), else that it
    declared none."""
    reason = (session.get('end_reason') or '').strip()
    if not reason:
        reason = runtime_mod.failure_reason(runtime_mod.read_result(session.get('log'))) or ''
    return reason or 'no failure declared'
```

`error_text` (`:40`) — the correction brief a cold retry is handed — keeps its log tail and
replaces only its claim:

```python
def error_text(session):
    tail = log_tail(session.get('log'))
    if wrote_a_result(session):
        head = (f"the session (pid {session.get('pid')}) wrote a result and then failed: "
                f"{outcome_text(session)}")
    else:
        head = f"the session's process (pid {session.get('pid')}) died before it wrote a result"
    return head + (f"; the last lines of its log:\n{tail}" if tail else '.')
```

`died_text` (`:46`) likewise:

```python
def died_text(session):
    """The correction a twice-dead session hands its next run (B-0062) — or, when its log does
    carry a result, what that run actually came to (F-0176). The phrase "without a result" is
    never written about a log that holds one."""
    last = (error_text(session).strip().splitlines() or ['no log lines'])[-1].strip()
    if wrote_a_result(session):
        return (f'the retry ended with a result, not a death: {outcome_text(session)} — {last}')
    return 'died twice: the session and its cold retry both ended without a result — ' + last
```

Both call sites (`handle_dead:111`, `hold_failed_corrections:265`) are unchanged: the invariant
lives in the one function that writes the phrase, so a third call site cannot reintroduce the lie.
`ran_to_its_end` and its B-0150 skip stay exactly as they are — a clean result still holds nothing
at all; this is only about what the *held* ones say.

When it is there, B-0123's hold reads:

```
held fix/B-0123: the retry ended with a result, not a death: failed: unpushed work — {"type": …
```

and the correction handed back to the session says the same. The round, the `ADJUDICATE` row and
the cap are untouched.

### 2 — a ruling that says ready is a publish instruction (`asf/workers/health.py`)

One predicate beside `UNPUSHED_REASON_PREFIXES`:

```python
def ruling_ready(run):
    """B-0064's ruling, read as a publish instruction (F-0176): an ``adjudicate`` run whose REPORT
    carries a ``ruling:`` and claims no ``blocked_on:`` has declared its branch ready. The session
    cannot put it on origin — it has no push credential, and a rebased lane branch needs the force
    the rules forbid it (B-0056) — so the factory publishes the head the ruling ruled on, whatever
    the run's own ``end_reason`` class. Read off the log, not off git: no subprocess runs here."""
    if (run or {}).get('kind') != 'adjudicate':
        return False
    rec = runtime_mod.read_result((run or {}).get('log'))
    text = str(rec.get('result') or '') if isinstance(rec, dict) else ''
    return bool(report_mod.ruling(text)) and report_mod.ruling_fields(text)['blocked_on'] is None
```

The kind check is deliberate belt-and-braces: only an adjudicate brief carries a `ruling:` field,
and a stray one in another kind's prose must not open a push.

`publish_gap:360` gains it as a third opener, and skips the leftover commit on that path:

```python
    ready = ruling_ready(run)
    result_ok = (reason == lifecycle.FINISHED
                 or (reason or '').startswith(UNPUSHED_REASON_PREFIXES) or ready)
    if not result_ok or not branch:
        return reason, ev, None
    if not wt or not os.path.isdir(wt):
        return reason, ev, None
    lines = []
    if ev.uncommitted and not ready:   # F-0176: the ruling ruled on the committed HEAD
        ok, line = lifecycle.commit_leftovers(wt, branch)  # B-0094
        …
```

`republish_steps:485` gains the same opener, so an adjudicate run already ended on an earlier tick
is published on the next pass rather than waiting for a whole new session (the F-0094 rule this
function exists for):

```python
    if not (reason.startswith(UNPUSHED_REASON_PREFIXES) or ruling_ready(run)) \
            or run.get('harvested') or not branch:
        return
```

Everything downstream is unchanged. `publish_gap`'s tail re-judges through `lifecycle.judge`, so a
ruling-ready run whose result record is an error record stays `failed` — honest, and held by
nothing (`health` holds only the retry, unpushed and empty-branch classes). The publish itself is
recorded the way every other publish is: `found.append((job, 'published', line))`, the
`publish_refused` field on a refusal, `refusal_text` to the next session. Once the head is on
origin, `publish_gap` returns `None` on the next pass (`ev.unpushed` is 0 and the head is on the
remote), so nothing republishes for ever.

The branch B-0123 spent six adjudications not publishing goes out on the first tick after this
lands.

### 3 — a refusal names git's own error (`asf/workers/lifecycle.py`)

```python
#: git's own error lines in a push's or commit's output. ``hint:`` is not one of them — git prints
#: its fast-forward hint last, so "the last line" is a hint more often than an error.
GIT_ERROR_RE = re.compile(r'^(?:fatal|error|remote)\s*:', re.I)
#: git's summary of a failed push: that there was an error, never which one.
GIT_PUSH_SUMMARY_RE = re.compile(r'^error:\s*failed to push some refs\b', re.I)
#: the most error lines one refusal carries — a refusal is one line on a tick's output
GIT_ERROR_LINES = 3


def git_error(output, limit=GIT_ERROR_LINES):
    """The exact git error in a push's or commit's output (F-0176): its ``fatal:`` / ``error:`` /
    ``remote:`` lines in git's own order, joined with ``; ``. A refusal that named none falls back
    to the last line that is neither a hint nor the ``failed to push some refs`` summary — a local
    pre-push hook's own message has no prefix at all, and it is the one thing worth reading.
    ``'push failed'`` when git printed nothing."""
    lines = [ln.strip() for ln in (output or '').splitlines() if ln.strip()]
    named = [ln for ln in lines if GIT_ERROR_RE.match(ln) and not GIT_PUSH_SUMMARY_RE.match(ln)]
    if named:
        return '; '.join(named[:limit])
    rest = [ln for ln in lines
            if not ln.lower().startswith('hint:') and not GIT_PUSH_SUMMARY_RE.match(ln)]
    return (rest or lines or ['push failed'])[-1]
```

Both refusal sites lose their inline `why[-1]`:

```python
    if p.returncode != 0:                                   # publish, :1593
        hook_findings = redact.parse_finding_lines(f'{p.stderr or ""}\n{p.stdout or ""}')
        if hook_findings:
            return False, f'publish {branch} refused: ' + '; '.join(redact.correction(hook_findings))
        return False, f'publish {branch} refused: {git_error((p.stderr or "") + "\\n" + (p.stdout or ""))}'
```

```python
    if p.returncode != 0:                                   # commit_leftovers, :1227
        return False, f'commit {branch} refused: {git_error((p.stderr or "") + "\\n" + (p.stdout or ""))}'
```

Both sites read `stderr` **and** `stdout` now (publish read `p.stderr or p.stdout`, so a hook that
writes to stdout while git writes a summary to stderr was invisible). The redaction branch is
untouched and still wins: a `redact:` finding is a precise correction, not a git error.

What changes on screen, for the three refusals this factory actually meets:

| git printed | today's refusal | after |
| --- | --- | --- |
| `! [rejected] HEAD -> fix/B-0123 (stale info)` / `error: failed to push some refs to '…'` | `… refused: error: failed to push some refs to '…'` | `… refused: ! [rejected] HEAD -> fix/B-0123 (stale info)` |
| `remote: Permission to …/asf.git denied to lane-2.` / `fatal: unable to access '…': … 403` | `… refused: fatal: unable to access '…': … 403` | `… refused: remote: Permission to …/asf.git denied to lane-2.; fatal: unable to access '…': … 403` |
| `pre-push: lint failed on x.py:12` / `error: failed to push some refs to '…'` | `… refused: error: failed to push some refs to '…'` | `… refused: pre-push: lint failed on x.py:12` |

Row three is what `lifecycle.hook_refusal_hold` has been holding sessions on with nothing to act on.
`push_failure`'s classification is unaffected in every row (P7): row two still matches `NETWORK_RE`
on `unable to access`, row three now matches `HOOK_RE` on `pre-push` where before it matched
nothing, and row one matches neither, as before.

## Records

Nothing new is persisted. What this card changes is what three existing records **say**:

| record | field | before | after |
| --- | --- | --- | --- |
| `<state dir>/sessions.jsonl` | `correction.text` on a run whose retry wrote a result | `died twice: the session and its cold retry both ended without a result — <the result record>` | `the retry ended with a result, not a death: <its end_reason> — <the result record>` |
| `<state dir>/sessions.jsonl` | `publish_refused` on a refused ruling-ready publish | (never written: no publish was attempted) | `publish <branch> refused: <git's own error lines>` |
| the `held` event (`ctx.event('held', …)`, `metrics/events`) | `text` | the same false sentence | the same corrected sentence |
| the brief a cold retry is handed (`<brief>.correction.md`) | its `CORRECTION:` tail | `the session's process (pid N) died before it wrote a result` | `the session (pid N) wrote a result and then failed: <reason>` when the log holds one |

The one new *event* is a line on the tick's health output, through the path that already prints
every publish:

```
published  adjudicate-b-0123        published fix/B-0123 at 9a1c2f0 (rebased; lease held)
```

`correction.kind` stays `died` — the kind is what the feeder's round counting reads, and this card
changes the words, not the routing. No ledger line is rewritten, no migration is needed, and a
`correction.text` written before this card is still read exactly as it is today.

## Stories
