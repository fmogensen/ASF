# F-0043 — two CI numbers with a target, and a week over it is a defect

The daily scorecard already prints both numbers this card is about, and neither has a target.
`scorecard_rows` writes `red rate 21 %` into the *note* column of the `ci runs` row, and
`cancelled: branch 610 (14 %) … — 18 % of the minutes` into the note column of the
`runner-minutes` row. A note is a fact. Nobody can read a note and say whether the factory is
behaving: `18 %` is not *over* or *under* anything, only a number, and it is the day's number —
one bad Tuesday and one quiet Sunday read alike.

The learning loop on the other side is already built, three sources deep: `asf file-bugs` files
or bumps one Bug per typed `signature`, once a day, from CI failures, refused files and rule
violations. Nothing in it measures a rate against a number the product chose.

This spec gives the two numbers a target in the product's `ci:` block, prints each as value
against target on the daily scorecard over a seven-day window, and adds one source to the bug
filer that files a Bug per number that misses its target — at most once a week, not once a day,
because a seven-day mean does not move fast enough to be worth a Bug every morning.

## 1. Decisions

### 1.1 Preconditions

- The `ci` stream already carries everything both numbers need per run: `conclusion`, `minutes`,
  `cancelled_minutes` (default `0`), `branch`, `batch`, `jobs` and `ts`
  (`metrics.SCHEMAS['ci']`). Nothing is added to it and nothing is backfilled.
- `metrics.render_daily` already reads the seven-day CI window — `week = days_back(day, 7)`,
  `read_stream(root, 'ci', week)` — for the cost table. This spec reads that same list; it does
  not open a second window.
- `metrics.scorecard_rows(ci, sessions, ticks, conv=None, events=())` already takes the
  product's `Conventions`, and `cmd_rollup` already falls back to `DEFAULTS` so a rollup over a
  bare checkout still renders. The two new rows inherit both properties.
- `env.Product.conventions` already copies three keys out of the yaml's `ci:` block into the
  conventions (`ci.test_command` → `test_command`, `ci.workflow` → `ci_workflow`,
  `ci.dev_job` → `ci_dev_job`), because more than the conventions read them. The targets are
  copied the same way, and for the same reason: the rollup holds a `Conventions`, never a
  `Product`.
- `env.CI_FIELDS` is the declared field list for the `ci:` block, checked by
  `validate_product_text`; a key not in it is a config error today.
- `file_bugs._file_or_bump_bug` already gives "same signature = same Bug", a `count` bump with
  one `## History` line, and a `last_filed` guard that makes a second run of the same day a
  no-op. It keeps the title as first filed and rewrites only `count`, `last_filed` and `links`.
- `file_bugs._conventions(args)` already resolves the product's `Conventions` for the filer,
  falling back to `DEFAULTS` when there is no product config to read.
- `approvals` already gates the whole command through the `file_bug` class, so a product that
  holds bug filing holds these two as well, with no change here.
- F-0101 (`model spend` row + `spend_signatures`) and F-0103 (three session/tick sources) are
  specified but **not landed**: neither `heavy_share_pct` nor `outcome_share_pct` is a field of
  `Conventions` in this tree. This spec assumes neither, collides with neither — it adds its own
  rows at the end of the waste table and its own source at the end of `cmd_file_bugs` — and
  follows both in shape, so whichever lands first the second reads as the same pattern.

### 1.2 In

- **`asf/conventions.py`** — five typed fields with documented defaults:
  `ci_cancelled_target_pct` (15), `ci_red_target_pct` (15), `ci_min_minutes` (60),
  `ci_min_runs` (20), `ci_provider` (None).
- **`asf/env.py`** — `CI_FIELDS` gains `targets: _MAP`; `Product.conventions` copies
  `ci.provider` and the four keys of `ci.targets` into the conventions beside the three it
  copies today.
- **`asf/metrics/metrics.py`** — `ci_waste_numbers(ci, conv=None)`, one pure function returning
  the two numbers over one window of CI events, and two rows appended to `scorecard_rows` built
  from it: the seven-day value against the target, with today's value in the note.
  `render_daily` hoists the seven-day CI read it already does and hands it to `scorecard_rows`.
- **`asf/tick/file_bugs.py`** — `ci_target_signatures(root, now, conv)`, a fourth signature
  source over `metrics/ci/*.jsonl`, and a `refile_days` key on the info dict that lets a source
  say how often its Bug may be bumped. `CI_TARGET_REFILE_DAYS = 7` is this source's.
- **`docs/products.example.yaml`** — the `ci.targets:` block, documented with its defaults.
- Tests for the configuration (§3.1), the two numbers (§3.2), the two rows (§3.3), the Bugs
  (§3.4) and the weekly cap (§3.5).

### 1.3 Out

- **A retro component.** The card says "the retro computes the seven-day mean"; this factory has
  no retro and this spec does not invent one. The once-a-day pass over the seven-day window
  already exists and already runs both halves in order — `asf tick`'s `daily` step runs
  `file-bugs` and then `rollup` (`step_daily.parts`). That is the retro. No new step, no new
  clock entry, no new command.
- **A new stream, state file or card field.** Everything read here is already written;
  everything written is a Bug card and two lines of a Markdown table.
- **Changing what `red rate` or the cancelled share *mean*.** Both keep the definitions the
  `ci runs` and `runner-minutes` rows use today, verbatim (§1.4). A number an operator has been
  watching must not move because it grew a target.
- **The `ci runs` and `runner-minutes` rows.** They are untouched, notes included. The target
  rows are additional, not a rewrite.
- **A third number.** `budgets.minutes_per_day` is already in the `ci:` block and stays
  unmetered here; the card names two numbers.
- **A per-lane or per-job target.** The two numbers are whole-window. Which lane lost the
  minutes and which job went red are evidence lines, not targets of their own.
- **Closing the Bug when the number recovers.** A signature that stops being produced simply
  stops bumping. Closing is the groom's and the fix session's, as for every other filed Bug.
- **Escalation.** A number over target for a month is the same Bug with `count: 4`. The count is
  the escalation; the severity is not raised and no second Bug is filed.
- **An `asf doctor` row for the targets.** They are two integers with documented defaults, and a
  value that is not a number reports itself where it is read — in the note column of the row it
  broke (§2.4) — rather than in a health check nobody runs on the day the yaml is edited.
- **Multiplying the rows per provider.** A product's `ci:` block holds exactly one `provider:`,
  so *per product, per CI provider* is two rows, labelled with that provider (§1.4).

### 1.4 The choices

| Choice | Against | Why |
| --- | --- | --- |
| The targets live in `ci.targets` in the product yaml, copied into `Conventions` | a top-level `targets:` block; a constant in `metrics.py` | The card says the targets live in the product's configuration, and the block they belong to is the one that already names the provider, the workflow and the budgets. They reach the rollup as conventions because the rollup holds a `Conventions` and must still render with none (`cmd_rollup`'s `DEFAULTS` fallback) — the same route `ci.workflow` already takes. |
| The seven-day number is the pooled ratio — cancelled minutes over all minutes in the window, red runs over all runs | the unweighted mean of the seven daily percentages | A mean of percentages gives a two-run Sunday with one red (50 %) the same weight as a 60-run Tuesday. The pooled ratio *is* the mean weighted by the day's volume, and it is the number an operator would compute by hand from the week's runs. |
| Both numbers keep the definitions already on the scorecard: `red / all runs`, `cancelled_minutes / minutes` | red over concluded runs only; cancelled over branch-lane minutes only | One definition per number, printed twice. A target row whose number disagrees with the note two rows above it is worse than no target. If the definition is wrong it is wrong in both places and moves in both places, in its own card. |
| A floor under each number — `ci_min_minutes` (60), `ci_min_runs` (20) | the target alone | Three runs, one red, is 33 % and means nothing. Below the floor the row prints `no verdict` and the filer files nothing, which is the same shape F-0103 gives `outcome_min_sessions`. |
| The row's value is the **seven-day** number; today's is in the note | the day's number as the value | The Bug fires on the seven-day number. Row and Bug must be the same number, or the scorecard argues with the record. Today's number is worth one phrase, not the headline. |
| Severity `S3` | `S2` (F-0101's choice for its spend threshold) | An `S2` is `decided: true` and goes to FIX without a groom (B-0089). A red trunk earns that; a seven-day mean that drifted three points over target does not — it is a trend, and a trend is exactly what the groom prioritises against everything else in the record. The weekly cap already guarantees it will not be re-filed before the groom has seen it. |
| The provider labels the row and titles the Bug, but is **not** in the signature | the provider in the signature | A `ci:` block holds one provider, so the signature is already per provider. Putting it in means an operator renaming `gh-actions` forks the Bug and loses its `count` history. The day a product holds two providers, the signature gains the provider — that day, not before. |
| `refile_days` on the info dict; the existing sources default to 1 | a second guard field on the Bug card; a `weekly` flag on the filer | The existing guard is "`last_filed` is today"; `refile_days: 1` **is** that guard, so the three existing sources keep behaving byte for byte. A source that wants a slower cadence says so in the dict it already returns. |
| The rows are printed unless the product has neither a CI provider nor a single run in the window | always print; print only when `ci.provider` is set | `sample/` is `provider: none` and has no CI at all — two rows saying `no verdict` on its scorecard would be noise in the dogfood test. A product that has a provider but a quiet week still wants to see its two lines. |
| The evidence is rebuilt on every bump from the window as it stands | evidence appended forever | The Bug's body is the case for it *now*. Seven day-lines and a split is the whole case; each bump writes the newest window line into `## History`, which is where the movement is read. |

## 2. The design

### 2.1 `asf/conventions.py` — the two targets, the two floors, the provider

Beside the other documented defaults:

```python
#: The share of runner minutes lost to cancelled runs at or above which the seven-day rate is a
#: defect. Spelt ``ci: {targets: {cancelled_pct: …}}`` in the product yaml.
DEFAULT_CI_CANCELLED_TARGET_PCT = 15
#: The share of CI runs ending red at or above which the seven-day rate is a defect.
DEFAULT_CI_RED_TARGET_PCT = 15
#: No verdict on the cancelled share below this many runner-minutes in the window.
DEFAULT_CI_MIN_MINUTES = 60
#: No verdict on the red rate below this many runs in the window.
DEFAULT_CI_MIN_RUNS = 20
#: Which provider ran them — it labels the two target rows and titles the Bugs they file.
#: None (and the string the yaml writes for a product without CI) label nothing.
DEFAULT_CI_PROVIDER = None
```

and five fields on `Conventions`:

```python
    ci_cancelled_target_pct: int = DEFAULT_CI_CANCELLED_TARGET_PCT
    ci_red_target_pct: int = DEFAULT_CI_RED_TARGET_PCT
    ci_min_minutes: int = DEFAULT_CI_MIN_MINUTES
    ci_min_runs: int = DEFAULT_CI_MIN_RUNS
    ci_provider: str = DEFAULT_CI_PROVIDER
```

All five are typed fields, so they leave `extra` empty and `conv.get('ci_red_target_pct')` reads
as the attribute does. None of them is path-shaped, so `forbidden_patterns()` generates nothing
new and `tools/check_conventions.sh` is unaffected.

### 2.2 `asf/env.py` — the yaml block

`CI_FIELDS` gains one key, so `targets:` stops being "not a field of the product file":

```python
CI_FIELDS = {
    'provider': _STR, 'workflow': _STR, 'test_command': _STR, 'budgets': _MAP,
    'runner_org': _STR, 'labels': _LIST, 'dev_job': _STR, 'targets': _MAP,
}
```

`Product.conventions` copies the provider and the targets beside the three keys it copies today,
each only when the product named it, so an absent key keeps its documented default:

```python
            if isinstance(ci, dict):
                for src, dst in (('workflow', 'ci_workflow'), ('dev_job', 'ci_dev_job'),
                                 ('provider', 'ci_provider')):
                    if ci.get(src):
                        data.setdefault(dst, ci[src])
                targets = ci.get('targets')
                if isinstance(targets, dict):
                    for src, dst in (('cancelled_pct', 'ci_cancelled_target_pct'),
                                     ('red_rate_pct', 'ci_red_target_pct'),
                                     ('min_minutes', 'ci_min_minutes'),
                                     ('min_runs', 'ci_min_runs')):
                        if targets.get(src) is not None:
                            data.setdefault(dst, targets[src])
```

A `conventions:` key of the same name still wins, as the docstring already says of the other
three. `docs/products.example.yaml` grows the block, with the defaults in its comments:

```yaml
ci:
  provider: gh-actions   # gh-actions | other | none
  budgets:
    minutes_per_day: 500
  # F-0043: the two waste numbers the daily scorecard prints as value against target, and the
  # volume below which it prints no verdict at all. Shown at their defaults.
  targets:
    cancelled_pct: 15    # cancelled runner minutes, as a share of all runner minutes
    red_rate_pct: 15     # CI runs ending red, as a share of all runs
    min_minutes: 60      # no verdict on cancelled_pct below this many runner-minutes in 7 days
    min_runs: 20         # no verdict on red_rate_pct below this many runs in 7 days
```

### 2.3 `asf/metrics/metrics.py` — the two numbers, once

```python
CI_TARGET_WINDOW_DAYS = 7
#: The most lane/job lines one number's `split` carries.
CI_SPLIT_CAP = 4


def ci_waste_numbers(ci, conv=None):
    """The two tracked CI numbers over one window of `ci` events. Pure: no clock, no io.

    Returns a two-element list in scorecard order, `cancelled` then `red`::

        {'key': 'cancelled', 'label': 'ci cancelled minutes', 'provider': 'gh-actions',
         'num': 760, 'den': 4210, 'unit': 'runner-minutes', 'pct': 18, 'target': 15,
         'floor': 60, 'verdict': 'over', 'config': None,
         'by_day': [('2026-09-17', 90, 610), …],      # oldest first, days with runs only
         'split': [('branch', 610, 14), ('batch', 120, 2)]}

    `pct` is `None` and `verdict` is `'no verdict'` when `den` is under `floor` (an empty window
    included); otherwise `verdict` is `'over'` when `pct >= target`, else `'ok'`. `config` is a
    sentence when the product's target is not a number and its default was used instead, else
    None. `split` is the lane a cancelled minute was spent in (`_kind_of_branch`) for
    `cancelled`, and the job a red run failed in for `red` — largest first, at most
    `CI_SPLIT_CAP` entries.
    """
```

The numerators and denominators are the ones the table already computes, lifted unchanged:

| key | num | den | unit | target | floor |
| --- | --- | --- | --- | --- | --- |
| `cancelled` | `sum(r.get('cancelled_minutes') or 0)` | `sum(r['minutes'])` | `runner-minutes` | `ci_cancelled_target_pct` | `ci_min_minutes` |
| `red` | `sum(1 for r in ci if r['conclusion'] == 'failure')` | `len(ci)` | `runs` | `ci_red_target_pct` | `ci_min_runs` |

`pct` is `_pct(num, den)`, the same integer-floor percentage the rest of the table prints.
`by_day` buckets on `parse_ts(r['ts']).date().isoformat()`; a run whose `ts` will not parse is
counted in the totals and left out of `by_day`, never dropped from the number. The target and
floor are read through one guard, which is also what fills `config`:

```python
def _conv_int(conv, key, default):
    """(value, complaint) — the conventions' integer for `key`, or `default` and a sentence
    naming what the product wrote instead."""
```

`verdict` uses `>=`, so a product that sets `cancelled_pct: 0` gets a verdict every week rather
than a number that can never be met. The card's "below 15 %" is `pct < target` — `ok`.

### 2.4 The two rows — `scorecard_rows` and `render_daily`

`scorecard_rows` gains one keyword, defaulted so every existing caller and test is unchanged:

```python
def scorecard_rows(ci, sessions, ticks, conv=None, events=(), ci7=None):
```

`ci7` is the seven-day window; `None` means "the caller has only the day", and the day's list is
used for both. After the `bandwidth` row and the intake-latency rows, one row per number, in
`ci_waste_numbers(ci7 or ci, conv)` order, skipped entirely when the window holds no runs **and**
the conventions carry no provider (or the string a product without CI writes there):

```
| ci cancelled minutes (gh-actions) | 18 % of 4210 runner-minutes (7d) | target 15 % — over; today 9 %; branch 610, batch 120, trunk 30 |
| ci red rate (gh-actions)          | 21 % of 143 runs (7d)            | target 15 % — over; today 12 %; gate 18/143, install 9/143 |
```

with, in order of what the window allows:

- under target → the note's verdict word is `ok`;
- `den` under the floor → the value is `18 runs (7d) — under the 20-run floor` and the verdict
  word is `no verdict`;
- no runs at all → the value is `no runs in 7 days`, the verdict word `no verdict`, no split;
- no provider → the label is `ci cancelled minutes`, with no parenthesis;
- a target that is not a number → the note opens `target 15 % (config: 'fifteen' is not a
  number)` and carries on with the default's verdict.

`render_daily` hoists the read it already makes, so the seven-day window is read once and both
readers see the same list:

```python
    week = days_back(day, 7)
    ci7 = read_stream(root, 'ci', week)
    …
    for m, v, n in scorecard_rows(ci, sessions, ticks, conv, read_stream(root, 'events', week), ci7=ci7):
    …
    out += cost_table(items, ci7, read_stream(root, 'sessions', week))
```

Nothing else in `render_daily` changes: the heading, the generated line, the cost table and its
preamble are untouched, and the two rows are the last two of the `## Waste` table.

### 2.5 The fourth source — `file_bugs.ci_target_signatures`

```python
CI_TARGET_WINDOW_DAYS = 7
#: How often the two CI-waste Bugs may be bumped: a seven-day mean is not news every morning.
CI_TARGET_REFILE_DAYS = 7
CI_TARGET_SIGS = {'cancelled': 'ci waste: cancelled minutes', 'red': 'ci waste: red rate'}


def ci_target_signatures(root, now, conv=None):
    """One signature per tracked CI number whose seven-day rate misses its target. Reads
    `metrics/ci/*.jsonl` and computes through `metrics.ci_waste_numbers` — the scorecard's own
    function, so the Bug and the row are the same number."""
```

It reads the stream with the module's own `_jsonl_lines`, the way the other three sources read
theirs, and keeps the lines whose `ts` parses inside `CI_TARGET_WINDOW_DAYS` of `now`. A number
whose `verdict` is `over` yields:

```python
{'ci waste: cancelled minutes': {
    'title': 'CI cancelled minutes are 18 % of runner time over 7 days '
             '(target 15 %, gh-actions)',
    'severity': 'S3', 'found_in': 'ci', 'runs': [], 'refile_days': CI_TARGET_REFILE_DAYS,
    'evidence': ['2026-09-17 … 2026-09-23: 760 of 4210 runner-minutes cancelled (18 %), '
                 'target 15 %, provider gh-actions',
                 'by lane: branch 610 (14 %), batch 120 (2 %), trunk 30 (0 %)',
                 '2026-09-17: 90 of 610',
                 '2026-09-18: 210 of 980',
                 '…one line per day with runs, oldest first']}}
```

and, for the other, `'ci waste: red rate'` with `'CI red rate is 21 % over 7 days (target 15 %,
gh-actions)'` and `by job: gate 18, install 9`. `(gh-actions)` is dropped from both titles when
the product names no provider. `verdict` of `ok` or `no verdict` yields nothing at all — a floor
that is not met is silence, never a Bug saying the number could not be computed.

`cmd_file_bugs` adds it as its fourth source, after the three that exist:

```python
    signatures.update(ci_target_signatures(root, now, conv))
```

Everything else is the existing filer's, unchanged: the `S3`'s `decided: false` sends it to the
groom, `conventions.default_bug_epic` parents it, `file_bug: human-now` prints
`NEEDS OPERATOR: held file_bug on ci waste: red rate` instead of filing, and the summary line
stays `file-bugs: N filed, M bumped, K unchanged`.

### 2.6 The weekly cap — `file_bugs._file_or_bump_bug`

The guard that is today "already filed today" becomes "filed inside this signature's own
window", with a default that is exactly today's behaviour:

```python
#: How many days must pass before a source's Bug may be bumped again. 1 is "not again today",
#: which is what the guard has always meant.
DEFAULT_REFILE_DAYS = 1


def _too_soon(last_filed, date, refile_days):
    """True when `last_filed` is inside the window: a bump now would be double-counting a
    problem still open. Falls back to string equality when either date will not parse, so a
    hand-edited card is never re-filed by accident."""
```

`_file_or_bump_bug` calls it with `info.get('refile_days', DEFAULT_REFILE_DAYS)` in place of the
`typed.get('last_filed') == date` test and returns `'skipped'` as before. With `refile_days: 1`,
`(date - last_filed).days < 1` is true only for the same day — the three existing sources are
unchanged by construction. With `7`, a Bug filed on the 17th is skipped through the 23rd and
bumped on the 24th. A Bug the number has stopped producing is simply never visited.

The first filing is not delayed: a number that goes over target files the day it does, and only
the *re*-filing is weekly. `count` therefore reads as "weeks over target", and each bump appends
the usual one line under `## History`:

```
- 2026-10-01 file-bugs: count 1 → 2 (2026-09-24 … 2026-09-30: 812 of 3990 runner-minutes cancelled (20 %), target 15 %, provider gh-actions)
```

### 2.7 What does not change

`SCHEMAS`, `validate`, `append_event`, `compute_costs`, `cost_table`, `write_costs`,
`write_release` and the backfill are untouched. The `ci runs` and `runner-minutes` rows keep
every character of their value and note columns. `step_daily.parts` keeps its four parts in
their order — `file-bugs` before `rollup`, both already once a day. No clock entry, no step, no
CLI command and no brief template changes.

## 3. Acceptance tests

From the repository root, stdlib only, hermetic. The whole suite must stay green:

```bash
cd "$(git rev-parse --show-toplevel)"
python3 tools/run_tests.py
```

**T1 — the targets are product configuration.** `Conventions()` gives 15, 15, 60, 20 and
`ci_provider` None; `Conventions.from_mapping({'ci_red_target_pct': 5})` overrides that one and
leaves the other four at their defaults with `extra` empty. A `Product` built from a dict whose
`ci:` block carries `provider: gh-actions` and `targets: {cancelled_pct: 8, min_runs: 5}` reads
back `ci_provider == 'gh-actions'`, `ci_cancelled_target_pct == 8`, `ci_min_runs == 5` and the
two unnamed keys at their defaults; a `conventions:` key of the same name still wins over the
`ci:` block. `validate_product_text` accepts a `ci:` block carrying `targets:` as a map, still
rejects `targets: 3` as "must be a map", and still rejects an unknown `ci:` key.

```bash
python3 -m unittest -v tests.test_conventions.CiTargetConventionTests tests.test_env.CiTargetsFieldTests
```

**T2 — the two numbers, computed once.** `ci_waste_numbers` over a hand-built list of CI events
returns `cancelled` then `red`; 760 cancelled minutes of 4210 is `pct 18`, `verdict 'over'` at
target 15, and 30 red of 143 runs is `pct 21`, `verdict 'over'`; at target 25 both read `ok`; a
number exactly at its target reads `over` (`>=`). 59 runner-minutes against `ci_min_minutes: 60`
gives `pct None`, `verdict 'no verdict'`, and an empty list gives `den 0` and the same verdict
for both numbers. A run missing `cancelled_minutes` counts as 0 and still contributes its
`minutes`; a run whose `ts` will not parse stays in `num`/`den` and out of `by_day`. `by_day` is
oldest first and holds only days with runs; `split` is largest first, at most `CI_SPLIT_CAP`,
and groups cancelled minutes by lane (`branch`/`batch`/`trunk`, `_kind_of_branch`) and red runs
by failing job. A target of `'fifteen'` yields the default and a `config` sentence naming it.
The function touches no clock and no filesystem: the same input twice gives equal output.

```bash
python3 -m unittest -v tests.test_metrics.CiWasteNumberTests
```

**T3 — two target lines on the daily scorecard.** A record whose `metrics/ci` holds seven days
of runs: `cmd_rollup` writes `metrics/daily/<day>.md` with exactly two rows beginning
`| ci cancelled minutes` and `| ci red rate`, each labelled `(gh-actions)` from the product's
`ci.provider`, each value carrying the seven-day percentage and `(7d)`, each note carrying
`target 15 %`, the verdict word and `today`. With the day's runs clean and the week's over
target, the value is the week's number and the note's `today` is the day's — the two differ, and
the value is the one the Bug fires on. Under target the verdict word is `ok`; under the floor
the value names the floor and the verdict word is `no verdict`; with no runs in the window and
no provider configured neither row is printed at all, and the rest of the `## Waste` table is
byte-identical to the same rollup before this change. The `ci runs` and `runner-minutes` rows
are unchanged in both columns.

```bash
python3 -m unittest -v tests.test_metrics.CiTargetRowTests
```

**T4 — a seven-day mean that misses a target files a Bug.** A record whose `metrics/ci` window
is 18 % cancelled and 21 % red against targets of 15: `asf file-bugs` files two Bugs,
`signature: ci waste: cancelled minutes` and `ci waste: red rate`, `severity: S3`,
`decided: false`, `found_in: ci`, parented under `conventions.default_bug_epic`, each title
carrying its percentage, the target and the provider, each body carrying the window line, the
split line and one line per day with runs. The same record with both numbers under target files
nothing; with the window under its floor files nothing; with only the red rate over target files
exactly one Bug. Runs older than seven days count towards neither. With
`file_bug_level='human-now'` nothing is written and one `NEEDS OPERATOR: held file_bug on ci
waste: …` line is printed per number.

```bash
python3 -m unittest -v tests.test_file_bugs.CiTargetBugTests
```

**T5 — at most once a week, and the other sources still once a day.** With a Bug already
carrying `signature: ci waste: red rate` and `last_filed` six days back, a run over target
prints `0 filed, 0 bumped, 1 unchanged` and rewrites nothing; at seven days back it bumps
`count` 1 → 2, sets `last_filed` to today and appends one `## History` line, leaving the title
as first filed. A CI-failure Bug filed yesterday still bumps today, and one filed today is still
unchanged — `_too_soon` with the default `refile_days` of 1 is the old guard exactly. A
`last_filed` that will not parse as a date falls back to string equality and is skipped only on
an exact match.

## 4. Records

**The daily scorecard** (`metrics/daily/<day>.md`, in the record clone) gains two rows at the end
of its `## Waste` table:

```markdown
| ci cancelled minutes (gh-actions) | 18 % of 4210 runner-minutes (7d) | target 15 % — over; today 9 %; branch 610, batch 120, trunk 30 |
| ci red rate (gh-actions) | 21 % of 143 runs (7d) | target 15 % — over; today 12 %; gate 18/143, install 9/143 |
```

**Two Bugs**, at most, filed once and bumped at most weekly, under
`conventions.default_bug_epic`:

```yaml
type: bug

severity: S3
decided: false
found_in: ci
signature: 'ci waste: cancelled minutes'
count: 1
last_filed: 2026-09-24
parent: <conventions.default_bug_epic>
```

and the same shape with `signature: 'ci waste: red rate'`. Each body is the evidence lines that
made it — the window line, the split, one line per day with runs — and each bump appends one
line under `## History` carrying the window line as it stood that week.

**The product yaml** gains an optional `ci.targets:` block. A product that writes none keeps the
documented defaults, so no existing product file has to change for the rows to appear.

**Not written.** No new stream and no new key on an existing one: the `ci` stream is read and
never written here. No state file, no stamp — the cap is `last_filed` on the Bug card, which is
committed with the record. No event in `metrics/events`. No change to any item's `cost:` or to
`releases/`.
