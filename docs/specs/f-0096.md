# F-0096 — the wave says why it is idle, and which decisions would end it

On 2026-09-23 `asf backlog` showed 73 cards, 12 landed, 3 building, 1 spec-approved: 73 of the 89
Features under E-0001 were cards with no spec. The three building Features were the whole of the
factory's work. When they finish, the wave prints

```
wave: nothing to launch
```

and stops — with a full roadmap, free slots, and 73 cards it will not touch, because
`feature_rows` mints a `CARD → SPEC` row only for a Feature whose `decided` is `true`
(`asf/feeder/rows.py:feature_rows`) and drops every other one without a word. `bug_rows` does the
same to an undecided S1 (`b.get('decided') is not True: continue`), and both drop a `blocked:`
item just as silently.

Four sentences of the card, in order, are what this spec answers. *Nothing moves a card toward a
spec* — that mover exists and is not this card's to build (§1.2, §1.4/D1). *The wave has nothing
left to launch while the roadmap is still full* — true, and invisible. *The wave tells the
operator how many decisions it is waiting on and which ones* — §2.1 to §2.4. **It should never go
quiet without saying why** — §2.2, and the one property this spec is built around: the accounting
is *total by construction*, so a card that produces no session lands in a named bucket or in a
residue bucket that prints its id. A reason list that is merely long goes quiet again the first
time someone adds a gate; a residue bucket cannot.

This changes code under `asf/` and `tests/` in this repository. It writes to no card in any
record, and it decides nothing.

## 1. Decisions

### 1.1 In

- `asf/feeder/rows.py`: a row kind `UNDECIDED → DECIDE` — non-launching, one per open Feature or
  open S1/S2 Bug whose `decided` is not `true`, ranked, capped at `conventions.decision_rows`
  (default 5) so the table stays readable (§2.1).
- `asf/feeder/idle.py`, new: the accounting (§2.2). Every open Feature and open S1/S2 Bug that no
  session and no launching row speaks for is put in exactly one bucket — `in flight`, `no slot`,
  `held`, `blocked`, `undecided`, `waiting`, `landed` — or in `other`, which prints its ids. Plus
  the one-to-three line render and the operator sentence.
- `asf/tick/step_wave.py`: the bare `wave: nothing to launch` replaced by that render, printed
  whenever a slot is free after the launches — not only when nothing launched (§2.3); one `idle`
  event per dry tick; one `NEEDS OPERATOR` line per product per day.
- `asf/feeder/render.py`: the `NEXT` table's footer names the undecided cards the cap hid, and
  `asf next --all` prints every one (§2.4).
- `asf/views/status.py`: a `Decisions` row — `73 undecided — next: F-0012, F-0013, F-0021`
  (§2.5).
- `conventions.decision_rows` (default 5), the single knob for both the rows minted and the ids
  named (§2.6).
- Tests in `tests/test_feeder.py`, a new `tests/test_idle.py`, `tests/test_tick_steps.py` and
  `tests/test_views.py`.

### 1.2 Out

- **A policy that decides a card.** The card's Expected paragraph offers two examples joined by
  *or*: the groom's policy/adjudicate pass deciding the top-ranked cards, or the wave naming the
  decisions it waits on. The first arm already has an owner and a refusal behind it — F-0085
  built the policy pass, the adjudicate session and the answers file, and F-0099 §1.2 rules out
  "a fifth *decide anything new* policy" as *a way to decide things wrongly at speed*. This spec
  takes the second arm whole, and D1 records the trade. Nothing here blocks the first arm: the
  accounting is what would tell anyone whether an auto-decider was working.
- **Changing what the groom asks, or how often.** Every undecided open item becoming a question
  from its first groom is F-0099 §2.5; the every-tick intake and policy pass landed with
  `1fb04d1`. This spec reads the same cards and asks nothing of the groom.
- **Ranking the groom's questions by the wave's idle slots.** Feeding "which decision would fill
  a slot" back into which question the adjudicator is given first is a real improvement and a
  different change: it edits `groom_state` and the adjudicate brief (F-0085 §2.5, F-0099 §2.7).
  The rank is printed here, which is the fact that change would need.
- **A scorecard row.** `metrics.scorecard_rows` reads the `ci`, `sessions` and `ticks` streams,
  and a new count in the `ticks` stream means a `metrics.SCHEMAS` entry and a migration of the
  stream. The `idle` event (§4) is the raw material; a row over it is worth its own card once
  there are enough days of it to plot.
- **Launching anything new.** No row this spec adds launches a session, so no capacity, no model
  choice and no brief changes. The `UNDECIDED → DECIDE` row costs no slot (P2).
- **Unblocking, closing or re-ranking anything.** The accounting reads the record and writes
  nothing to it. A `blocked:` card stays blocked; it is merely counted out loud.
- **The `daily` rollup, `asf improve` and the tick's own summary tables.** They read the events
  stream; a new event kind needs nothing of them (P5).

## 2. The design

### 2.1 `asf/feeder/rows.py` — the card that needs a decision gets a row

```python
UNDECIDED = 'UNDECIDED → DECIDE'
NEEDS_DECISION = 'NEEDS DECISION'
DECISION_ROWS = 5  #: `conventions.decision_rows` — rows minted, and ids named in the wave's line


def decision_rows(product):
    """``conventions.decision_rows`` (default 5): how many undecided cards get a row (D6)."""
    v = _conventions(product).get('decision_rows')
    return v if isinstance(v, int) and v >= 0 else DECISION_ROWS


def undecided_rows(items, product, busy, limit=None):
    """A non-launching row per open card the feeder would start work from if it were decided:
    an open Feature, or an open S1/S2 Bug (D4). Ranked — an undecided S1 first, then the
    roadmap's own order (``ix.rank``, then id) — and cut to ``limit`` (``None``: the product's
    ``decision_rows``; ``0``: every one, ``asf next --all``).

    P3 is the defect: today both gates drop these cards without a word, so the wave's roadmap
    can be full and its output empty. The row launches nothing and costs no slot (P2); it is
    the sentence "this card is what a free slot is waiting for", in the one table that says
    what the tick would start.
    """
```

Each row carries `action=NEEDS_DECISION`, `waits_on='decision'`, `brief_kind='spec'` for a
Feature and `'fix-bug'` for a Bug (the session it *would* get — the row launches nothing, and the
kind is what makes `asf next --json` legible), and

```python
reason=f"undecided {ix.age(v.get('stage_since'))} — {CARD_SPEC if … else BUG_FIX} waits for decided: true"
```

`candidates()` appends them after `feature_rows` and before `hold_unlanded`, and `hold_unlanded`
leaves them alone — its `keeps` grows `NEEDS_DECISION` beside `ON_TRUNK` and `PARKED` (D11). A
card that is `blocked:` gets no decision row: it is in the accounting's `blocked` bucket, and two
rows for one card would be two answers to the same question.

`candidates()` and `plan_rows()` take `decision_limit=None`, passed through to `undecided_rows`.

### 2.2 `asf/feeder/idle.py` — the accounting, total by construction

```python
"""asf.feeder.idle — why a free slot is free, as an accounting no card falls out of.

The wave's old answer was ``wave: nothing to launch``, and for 73 undecided cards that sentence
was true and useless (F-0096). This module takes the roots the feeder starts work from — every
open Feature, every open S1/S2 Bug (D4) — and puts each in exactly one bucket. The last bucket
is ``other``: a root that matched no rule is *named*, not dropped, so a gate added later is
visible the tick it starts hiding cards (D3).
"""

#: In classification order — the first that matches wins, and the order is the operator's:
#: what is happening, what a slot would start, what a person must do, what waits on itself.
BUCKETS = ('launching', 'in flight', 'no slot', 'held', 'blocked', 'undecided', 'waiting',
           'landed', 'other')
```

```python
@dataclasses.dataclass
class Idle:
    slots: int                    #: free session slots once the launches are counted
    launched: int
    buckets: dict                 #: {bucket: [(item id, why)]}, BUCKETS order, empty ones kept
    undecided: list               #: [(id, rank, age)] every undecided root, ranked — not cut
    shown: int                    #: how many of them got a row (conventions.decision_rows)

    @property
    def dry(self):
        """A tick with a free slot and nothing launched — the card's own failure."""
        return self.slots > 0 and self.launched == 0
```

```python
def account(items, product, candidates, selected, inflight, busy, capacity, held=None):
    """The ``Idle`` for this tick. ``candidates`` is every row the index supports,
    ``selected`` the rows after the capacity cut, so a root whose row launches but was cut is
    ``no slot`` rather than a mystery."""
```

For a root `R`, `mine = [r for r in candidates if r.item_id == R['id'] or r.feature_id == R['id']]`
— a Feature's Tasks answer for it — and the first rule that holds wins:

| bucket | holds when | the `why` |
|---|---|---|
| `launching` | some row of `mine` in `selected` launches | `T-0031 PLAN → CODE` |
| `in flight` | `R` or anything in `ix.subtree(items, R)` is in `inflight` or `busy` | `task-t-0030 12m` / `awaiting harvest` |
| `no slot` | some row of `mine` launches in `candidates` but is not in `selected` | `would launch: capacity {n}` |
| `held` | `R['id']` in `held` | `held touch_production (human-now)` |
| `blocked` | `R.get('blocked')` | `blocked by B-0031` (`blocked_by_open`) |
| `undecided` | `R.get('decided') is not True` | `undecided 6d, rank 3` |
| `waiting` | some row of `mine` is non-launching | its `waits_on` — `WAITS ON T-0029` |
| `landed` | stage `landed`/`on-prod`, or state Resolved/Closed | `landed` |
| `other` | nothing above | `no row, no reason` |

`held` is passed by the wave step (P6) and defaults to `{}` for the views, which have no ledger of
holds to read — a view's `held` card therefore reads `waiting` or `undecided`, which is true of
it too.

The render, at most three lines and never none:

```python
def lines(idle, product=None, top=None):
    """``wave:`` lines — the counts, the ranked decisions, the residue."""
```

```
wave: 0 launched, 4 slots free — 73 undecided, 5 blocked, 3 in flight, 2 waiting, 1 held
wave: decide next — F-0012 (rank 1, undecided 6d) · F-0013 (rank 2, undecided 6d) · F-0021
      (rank 3, undecided 5d) — +70 more (asf next --all)
wave: unaccounted — F-0033 F-0044 (no row and no reason: a gate this accounting does not know)
```

Line 1 lists only the non-empty buckets, in `BUCKETS` order, `launching` first. Line 2 appears
only when something is undecided, and names `decision_rows` of them, ranked. Line 3 appears only
when `other` is non-empty — it is a defect report about this module, and §3.2 asserts it is empty
over a fixture that exercises every other bucket.

```python
def needs_operator(idle, product, groom_file):
    """The one sentence a person must act on, or None: what is waiting, and the two ways to
    end it — the groom line the next tick applies, or ``asf set`` on the top card."""
```

```
NEEDS OPERATOR: 73 cards await a decision and 4 slots are idle — answer their lines in
groom/2026-09-24.md (the next tick applies them), or decide the top one:
`asf set F-0012 decided=true --product asf`
```

`asf set <id> decided=true` is the operator's existing typed write (`asf/record/setfield.py`), and
the groom file is where the same answer is already asked for as `→ answer: yes`. The sentence
names both because they differ in where the commit lands: the groom file is the record clone the
tick owns, `asf set` the operator's own checkout.

### 2.3 `asf/tick/step_wave.py` — the wave says why

`run()` keeps its shape; the accounting is built once, from what the tick already has:

```python
    idle = idle_mod.account(items, product, feeder_rows.candidates(items, product, running,
                                                                   **plan_inputs(product, root)),
                            planned, running, awaiting_harvest(product), r.sessions, held=held)
    for line in idle_mod.lines(idle, product):
        out(line)
    if idle.dry:
        ctx.event('idle', slots=idle.slots, undecided=len(idle.undecided),
                  top=[i for i, _rank, _age in idle.undecided[:feeder_rows.decision_rows(product)]],
                  buckets={k: len(v) for k, v in idle.buckets.items() if v}, flagged=flag)
```

Three rules make the output bearable and the memory honest:

- the lines print when `idle.slots > 0` — after the launches, so a tick that fills every slot
  prints nothing new (D7). The bare `wave: nothing to launch` is gone: a wave with no rows and no
  free slot prints `wave: 0 launched, 0 slots free — 3 in flight`, which is the true sentence;
- the `idle` event is written only on a dry tick (D9);
- `flag` is true only when `idle.undecided` is non-empty and the day's events file holds no
  earlier `idle` event with `flagged: true` (D8) — `_flagged_today(root)`, one read of
  `metrics/events/<day>.jsonl`. When it is true, and only then, `out(needs_operator(...))`.

`candidates()` is called once more than today (the cut rows are what `no slot` means); it reads
the in-memory index and no git, so the cost is a list comprehension over the items (P1).

### 2.4 `asf/feeder/render.py` — the table's footer, and `asf next --all`

`table()` grows one footer line when the cap hid rows:

```
— 68 more cards await a decision (asf next --all)
```

`cmd_next` gains `--all`, which passes `decision_limit=0` into `plan_rows`; without it the
product's `decision_rows` applies, and `--json` carries exactly the rows the table shows, footer
or not. The header's `N rows · M would launch` is unchanged, so every existing golden file holds
except the fixtures that now carry a decision row — which is the point of them.

### 2.5 `asf/views/status.py` — the `Decisions` row

Beside `Ready to launch`, one more cell, from the same `plan_inputs` (P4):

```python
def decisions_cell(root, product):
    """``73 undecided — next: F-0012, F-0013, F-0021`` — the decision debt and what to spend it
    on first; ``0`` when every open card is decided."""
```

It reads the index the cell above it already loaded logic-for-logic (`ready_cell`'s pattern,
including its `not_configured('backlog_dir (no index.json)')` guard), and the row is rendered
through `render()`'s existing table loop, which already catches a cell that raises.

### 2.6 Config

`asf/conventions.py`, one optional key with the shape `attempt_limit` has (P8):

| key | default | what it moves |
|---|---|---|
| `decision_rows` | `5` | undecided cards given a row, and ids named in the wave's line and the status cell |

`0` means *every one* — the same meaning `asf next --all` passes — and a non-integer or negative
value falls back to the default rather than raising, as every other convention reader does.

### 3.2 The accounting is total — and its residue is a defect it prints

```bash
python3 -m unittest -v tests.test_idle
```

`AccountingTests` builds one index carrying a root for every bucket — a launching Feature, one
whose Task is in flight, one whose row the capacity cut dropped, one held by `touch_production`,

## 4. Records

**Events** — `<record>/metrics/events/<day>.jsonl`, through `ctx.event`, schema-free (P5), one
line per dry tick:

```json
{"kind": "idle", "slots": 4, "undecided": 73, "flagged": true,
 "top": ["F-0012", "F-0013", "F-0021", "F-0022", "F-0030"],
 "buckets": {"in flight": 3, "blocked": 5, "undecided": 73, "waiting": 2, "held": 1},
 "product": "asf", "ts": "2026-09-24T09:10:04Z"}
```

That line is the card's own observation made countable: dry ticks per day, the decision debt over
time, and — against the `launch` events — the slots the debt cost. `flagged` says which tick told
the operator, so the once-a-day rule is auditable rather than assumed.

**Printed.** Per tick with a free slot, from the wave step: the counts line, the decisions line
when anything is undecided, and the residue line when the accounting has a hole. Once per product
per day: the `NEEDS OPERATOR` line. From `asf next`: the `UNDECIDED → DECIDE` rows in the table
and in `--json`, with the footer naming what the cap hid. From `asf status`: the `Decisions` row.

**Files.** None. This spec adds no file to the record and edits no card: it decides nothing,
closes nothing, and unblocks nothing. Everything it knows is derived from `index.json`, the
session ledger and the approvals ledger, each tick, from scratch.
