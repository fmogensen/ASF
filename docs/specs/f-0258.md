# F-0258 — the check that could have caught it runs against the trunk alone

Two open pull requests can each claim the same numbered resource — a migration number, a register
band. Each one passes its own pre-push check and each one is right, because that check compares the
branch against the trunk and the trunk is the one place the other claim is not. The clash shows up
when both meet in a batch, which is the most expensive moment to find it: a red batch, two sessions
to unpick, and a number that has to move in a file and in everything that references it.

Seen 2026-10-06: a Task's brief named migration `0320`, and the coder booked `0319` — which an open
replan's pull request already held. Both halves of that sentence are a defect of their own.

**The pre-push check gives the product no list of open pull request heads.**
`conventions.pre_push_check` is a shell string a session runs itself (`asf/conventions.py:232-240`,
`asf/approvals.py:388-400`, named into every brief by `asf/briefs/preamble.py:101-121`). The factory
hands it nothing. A product script that wanted to check a migration number against other open work
has no way to learn what the other open work is, so it checks the trunk, and passes.

**Nothing makes the coder keep a reserved identifier the brief names.** The number was in the brief
— inside the footprint list, as one glob among several (`Writes (the footprint this job may
touch): …`, `asf/briefs/preamble.py:627-629`). It was never stated as a reservation and nothing
compared the branch's booking against it.

F-0208 built the reader this needs and stopped one Task short of the moment that matters.
`asf.reservations` merges what every open ref books — from the files a branch adds, from the
`writes:` globs its open cards declare, and from a product command that is handed every ref — into
one map, with a deterministic holder and the words for a refusal (`asf/reservations.py`, F-0208
T-0599, Closed). It runs nowhere: **T-0600 (`the lane holds the newer claimant`) and T-0602 (`one
definition of "open lane branch", and the config key`) are both still `New`** (measured below), so
nothing calls `snapshot`, `save` or `refusal`, and even once T-0600 lands its hold arrives *after*
the push — a correction round, not a clean push.

So this card is not the lane's hold. It is **the same map, computed live at the pre-push moment, in
one command a session runs before its one push; the open heads printed plainly so a product's own
check can read them; and the number a card reserves named in the brief as a reservation and refused
when the branch books another.**

### In

* One new command, `asf reservations`, read-only: the holdings in words, `--heads` for the open
  pull request heads as a plain list, and `--check` for the verdict on one branch.
* `--check` computes the map **live** — one `git fetch` + `ls-remote`, one `gh pr list`, one run of
  the product's own `reservations` command with every open head in its argv — and refuses on two
  grounds: a number another open head holds, and a number other than the one the branch's card
  reserves.
* Four new readers in `asf/reservations.py`, so that both the brief and the check read one rule:
  `declared`, `booked`, `pending_added`, `unhonoured`, and the words `honour_refusal`.
* Two new lines in a brief, both conditional on the product declaring a sequence: the reservation
  this card holds, stated as a reservation, and a standing rule naming the command.

### Out

* **The lane's hold and the landing's refusal.** `asf/harvest/lane.py`, `asf/workers/lifecycle.py`
  and `asf/tick/land_spec.py` are T-0600's footprint (`docs/plans/f-0208.md:249-251`), still `New`
  (P1). Nothing here touches them, and nothing here writes `reservations.json` — that writer is
  T-0600's too. This card's predicates are deliberately pure so T-0600 can call them unchanged.
* **The `conventions.reservations` field, `docs/products.example.yaml` and `asf/reserve.py`'s
  unified open-branch scan.** T-0602's footprint (`docs/plans/f-0208.md:549-551`), still `New`. The
  key is readable today through `extra` (P5), which is all `--check` needs.
* **Renumbering.** Nothing here renames a file or rewrites a reference. A refusal names the holder
  and the next free number; the session re-books.
* **Feeding the open heads into `conventions.pre_push_check` itself** — as an environment variable,
  an argv tail or a temp file. The session runs that string in its own shell; the factory has no
  hook into it. `--heads` is the list, and a product script that wants it calls for it.
* **A new field in the typed REPORT.** `asf.workers.report`'s parser has nine production callers
  and nineteen kinds; a reservation verdict is not worth that blast radius. The record is the
  command's own output and the brief (`## Records`).

### Consequences, named not fixed

| # | Consequence |
| --- | --- |
| C1 | **The honour check has no lane backstop.** A session that does not run `--check` can still push a branch that booked a number other than the one its card reserves, and nothing downstream refuses it — T-0600's hold is for the *clash* half only (`docs/plans/f-0208.md:249-258`). The predicates here are pure and importable so that T-0600, or a later card, can add that hold without touching this work; this card does not, because `asf/harvest/lane.py` is T-0600's footprint. |
| C2 | **A five-digit card id in a branch name defeats `--check`'s honour half.** `lane.item_of` returns `None` for `worker/T-36950` (P12), so no card is found, so no number is declared, so the sequence is open and the branch is free. `--check` prints which card it read, and `(no card id in the branch name)` when it read none, so the gap is visible rather than silent. The regex is `asf/harvest/lane.py:248` and is not this card's to widen. |
| C3 | **A product whose `reservations` command is broken is checked by two readers, not three.** F-0208 C9 holds unchanged: a non-zero exit, a timeout or no command is `([], <why>)`, printed as a warning and never a refusal. A number that only that command knows about is then unseen. |
| C4 | **`--check` costs one `git fetch`, one `ls-remote` and one `gh pr list` per push,** for every brief of a sequence-declaring product including the kinds that book nothing (D9). At the measured pull request volume this is well inside `gh`'s rate limit, but it is a real cost and it is per push, not per session. |
| C5 | **Two branches that have each pushed nothing are ordered by name.** Inherited from `reservations.rank` (`asf/reservations.py:67-79`), already named in F-0208. At the pre-push moment this is the common case — neither branch has a pull request yet — so `--check` may name the *other* branch as the holder on a basis that is deterministic and arbitrary. The refusal says so in its own words. |

## The design

### 1. `asf/reservations.py` — the readers both the brief and the check use

`declared` is lifted out of `writes_bookings`'s inner loop (`:132-138`) unchanged, and
`writes_bookings` calls it (D10):

```python
def declared(item, seqs):
    """``[(sequence, number)]``, sorted — the numbers one card's ``writes:`` globs name. A glob
    books only when its filename half matches the sequence's regex, so ``db/migrations/*`` and
    ``029[01]_*.sql`` name none. The inner half of :func:`writes_bookings`, lifted so the brief
    that states a reservation and the check that enforces it can never read it differently."""
    out = set()
    for glob in (item or {}).get('writes') or []:
        dirname, filename = reserve.split_pattern(glob)
        for name, (seq_dir, regex, _width) in (seqs or {}).items():
            if dirname == seq_dir:
                out.update((name, n) for n in reserve.numbers_in([filename], regex))
    return sorted(out)
```

`added_files` keeps its signature and its one caller; the command is factored out so any revision
can be read, which is what the pre-push moment needs (P8):

```python
def _added(repo, trunk, rev):
    r = H.sh(['git', 'diff', '--name-only', '--diff-filter=A', f'origin/{trunk}...{rev}'], cwd=repo)
    return [l for l in r.stdout.splitlines() if l.strip()]


def added_files(repo, trunk, ref):
    """…unchanged docstring…"""
    return _added(repo, trunk, f'origin/{ref}')


def booked(repo, trunk, rev, seqs):
    """``[(sequence, number)]``, sorted — the numbers the commits of ``rev`` *add* under a
    sequence's directory since they left the trunk. ``rev`` is any revision: ``HEAD`` in a
    session's own worktree for a branch not yet on origin (P15), ``origin/<ref>`` for one that is,
    so the lane can read the same rule off a pushed branch."""
    return _numbers_under(_added(repo, trunk, rev), seqs)


def pending_added(repo, seqs):
    """``[(sequence, number)]`` for a file this worktree has added but not committed — one
    ``git status --porcelain --untracked-files=all``, ``A``/``??`` entries only (D7). A session
    that runs the check before ``git add`` is still told about the migration it just wrote."""


def _numbers_under(paths, seqs):
    """``[(sequence, number)]`` for ``paths``, each matched against its sequence's directory and
    regex — the loop :func:`added_bookings` runs per ref (`:106-108`), as one reader."""
```

The honour predicate is pure, and is D4 and D5 in code:

```python
def unhonoured(reserved, booked_pairs):
    """``[(sequence, reserved_numbers, number)]`` — one row per number ``booked_pairs`` carries in
    a sequence that ``reserved`` (:func:`declared`) names at least one number in, and that is not
    one of them. A sequence ``reserved`` names no number in is open and yields nothing (D4); a
    sequence it names numbers in that the branch has not booked at all yields nothing either — the
    work is not done yet, which is not a reservation defect (D5)."""


def honour_refusal(rows, seqs):
    """``(RESERVED, text)`` for a non-empty :func:`unhonoured`, else None — the same pair
    :func:`refusal` returns, so one correction kind covers both grounds (D6). The words name the
    card's number first and the branch's second: ``reserved: this card holds migrations 0320;
    this branch books 0321. Rename the file to the reserved number and every reference to it, and
    push it again. A number the card does not hold is a number another open branch may hold.``"""
```

### 2. `asf reservations` — the command

Registered in `asf/cli.py` beside `reserve` (`:329-332`, dispatched at `:656-658`), and
`cmd_reservations` lives in `asf/reservations.py` beside `reserve.cmd_reserve`'s precedent:

```
asf reservations [--product P] [--branch B] [--check] [--heads] [--json]
```

* **no flag** — the holdings in words: `brief_lines(snap, limit=0)` with no cap, one line per
  sequence, then one `warning: <why>` per entry of `snap['errors']`. Exit 0.
* **`--heads`** — one line per open ref, the trunk first, `<ref>\t<pr number or ->`: exactly
  `open_refs(product, heads, prs)` with its rank. This is the list the card says the pre-push check
  never had; a product's own script reads it with two lines of shell. Exit 0.
* **`--check`** — the verdict for one branch (`--branch`, default the cwd's
  `git rev-parse --abbrev-ref HEAD`):
  1. the clash: `refusal(snap, branch)` — a number another open head holds (D2, live);
  2. the honour: `unhonoured(declared(item, seqs), booked(cwd, trunk, 'HEAD', seqs) + pending_added(cwd, seqs))`, where `item` is `items.get(lane.item_of(branch, None))` (C2);
  3. both empty → `reservations: clean — <n> open refs read, <k> held for <card>`, exit 0;
     either non-empty → its text on stderr, exit 1.

  A product with no declared sequence prints `reservations: no sequence declared — nothing to
  check` and exits 0 (D8).

The reads, each once per invocation and each lazily imported:

| what | from | why |
| --- | --- | --- |
| `heads` | `evidence.remote_heads(product=product)` | `{branch: sha}`, one fetch + `ls-remote` (P10) |
| `prs` | `lane.host(product).prs()` | `{branch: pr}`, one `gh pr list`, uncached (P9, D3) |
| `items` | `match.load_index(product.backlog_dir)` | the items map, `{}` for no record (P11) |
| the branch's own bookings | the **cwd's** repository, at `HEAD` plus the working tree | the session's commits are only `HEAD` in its own worktree (P15, D7) |

`cmd_reservations` writes nothing: no `save`, no state file, no ref (the writer is T-0600's — `##
Out`).

### 3. The brief — the reservation stated, and the rule that enforces it

In `state_lines` (`asf/briefs/preamble.py:631-638`), inside the branch that is already conditional
on a declared sequence (P13), above the existing `Reserved in flight:` line:

```python
    if conventions(product).map_of('sequences'):
        seqs = reservations.sequences(conventions(product))
        mine = reservations.declared(facts['item'], seqs)
        if mine:
            out.append('Reserved for this card: ' + '; '.join(
                f'{name} {reserve.format_number(n, seqs[name][2])}' for name, n in mine)
                + ' — book exactly this; the next free number is not yours to take.')
        snap = facts.get('reservations') or {}
        ...                                   # unchanged
```

And one standing rule, modelled on `PRE_PUSH_GATE_OURS` (`:147-151`) and carried next to it in the
`rules` Section (`:766-769`), for every kind of a sequence-declaring product (D9):

```python
#: F-0258: carried by every brief of a product that declares a numbered sequence. The product's own
#: pre-push check compares the branch against the trunk, which is the one place another open claim
#: is not — two branches each passed it and clashed in a batch. This command reads every open pull
#: request's head instead, and the number the card above reserves.
RESERVATION_RULE = ("- Before your one push, run `asf reservations --check`: it reads every open "
                    "pull request's head, not only the trunk, and refuses a number another open "
                    "branch already holds or a number other than the one reserved above. A number "
                    "it names is a number you must change on this branch before the push, not "
                    "after it.")


def reservation_rule(product):
    """:data:`RESERVATION_RULE` when the product declares a sequence, else None. Pure: reads the
    conventions, never git."""
```

Nothing else in the brief moves, and no golden fixture moves: the golden test product declares no
sequence, so neither line is emitted for it (P14). `tests/fixtures/briefs/golden/*.md` is **not** in
any footprint here, and if `ASF_UPDATE_GOLDEN=1` produces a diff then a line is being emitted
unconditionally and that is the bug, not the fixture.

## Records

Nothing new is persisted. That is a choice, and these are the records the change does leave:

| what | where | written by |
| --- | --- | --- |
| the reservation a card holds, in words | the brief, under `Writes (…)` — `Reserved for this card: <sequence> <number> — …` | `state_lines`; the brief is kept as `<state dir>/briefs/<job>.md`, so what a session was told is readable after the fact |
| the rule naming the command | the brief's `### Standing rules` | `reservation_rule(product)` |
| the verdict | the command's own stdout (`reservations: clean — <n> open refs read, <k> held for <card>`) and stderr (the refusal text, naming the holder, its pull request number and the next free number) | `cmd_reservations`; it goes into the session log the runtime already keeps |
| a product command's failure | one `warning: <why>` line on stdout, never a refusal | `command_bookings`' existing `(bookings, why)` (C3) |

Explicitly **not** written: no `reservations.json` (T-0600's, `## Out`), no claim ref on origin
(`asf reserve`'s, untouched), no jsonl event, no field in the typed REPORT (`## Out`), no card
state change. `asf reservations` is read-only in every mode — the acceptance test
`test_the_command_writes_nothing` is that claim.
