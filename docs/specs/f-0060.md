# F-0060 — the cheap pass reads the diff first

A code branch today goes straight from `PR_OPEN` to `REVIEW` (`asf/harvest/lane.py:1076`, T3/T4/T5)
and the first thing that reads its diff is the expensive round. That round spends its budget twice
over: once on the mechanical findings any careful reader would catch — a path outside `writes:`, a
test that was never run, an error branch with no caller, a secret in a log line — and once on the
question only judgement answers, whether the change is the change the plan asked for. The
mechanical half is the cheaper half of the work and it is paid for at the expensive rate, every
round, on every branch.

Worse, some branches get no reading at all. `review_waived` (`asf/harvest/lane.py:364`) lets a
small Feature's Task under `review.skip_under_lines` land on CI and the gate alone, and
`lane.review: {code: none}` waives the class outright. Those diffs reach the trunk unread by
anything but a test suite.

This spec puts one cheap session in front of the expensive one. A new lane state `PRECHECK` sits
between `PR_OPEN` and `REVIEW`; a new feeder row launches a `precheck` brief on the branch at a
**level** derived from the Task's own size class and the diff's size — `low` for a small Task,
`high` for a medium or a large one, `max` for a pull request over the line threshold. The session
writes one file on the branch, `{reviews_dir}/precheck-{slug}.md`, holding one table: one row per
dimension it was asked to check, one row per finding it made, each with a confidence. The lane
reads that table. A `high`-confidence finding sends the branch `BACK` to its coder as a
correction — no review round is spent, and the expensive session is never launched. No
`high`-confidence finding and the branch goes on to `REVIEW`, and the reviewer's brief opens with
the table: a finding already in it is the precheck's, never a new C.

## 1. Decisions

### 1.1 Preconditions

- **The lane is the state machine and the feeder only reads it.** `next_state`
  (`asf/harvest/lane.py:992`) returns `(state, reason)` per branch; `LANE_STATES`
  (`:123`) is the whole vocabulary, `OPEN_STATES` and `BUSY_STATES` derive from it, and
  `asf/invariants.py:572` refuses a lane record whose state is not in it. Exactly two modules
  outside `lane.py` name a state directly — that invariant, and
  `asf/workers/lifecycle.py:855`, which sorts a held branch into the `review` or the `landing`
  bucket. A new state is therefore a contained change, not a sweep.
- **A launch row needs a bucket of its own.** `occupancy` (`asf/workers/lifecycle.py:810`)
  returns `review` (→ a `PUSHED → REVIEW` launch) and `landing` (→ a `PUSHED → LAND` row that
  launches nothing), and `lane_rows` (`asf/feeder/rows.py:616`) turns those two dicts into rows.
  A state that must launch a session cannot reuse `landing`.
- **The size class is already mechanical, and already derived from `writes:`.**
  `asf.size.classify(writes, cfg)` (`asf/size.py:69`) returns `(class, kind, why)` over
  `SMALL/MEDIUM/LARGE`, with `conventions.size_config()` the resolved thresholds. It is pure: no
  filesystem, no `Product`. An uncountable footprint — a glob, a cross-repo entry, an empty
  `writes:` — is `LARGE` with the blocker as its `why` (`countable`, `:55`).
- **The diff's own size is already read on this code path.** `changed_lines(repo, trunk, branch)`
  (`asf/harvest/lane.py:337`) sums `git diff --numstat` adds plus removes, and `touched_files`
  (`:331`) lists the files. `branch_facts` already calls `changed_lines` — but only for a small
  Feature's Task, and only to answer `review_waived` (`asf/harvest/lane.py:1274`).
- **The review file's name is a convention, and a path literal in code fails the build.**
  `DEFAULT_REVIEW_PATTERN` is `{reviews_dir}/{n}-{slug}.md` (`asf/conventions.py:99`), and
  `tools/check_conventions.sh` generates a forbidden pattern for every path-shaped default in
  `asf.conventions`, so the precheck's path must be a `Conventions` field too.
- **`{n}` is `\d+`, so a numbered file in the reviews directory *is* a review round.**
  `review.pattern_rx` (`asf/evidence/review.py`) substitutes `(?P<n>\d+)` for `{n}`, and
  `pick` (`:122`) takes the highest round. A precheck file named `0-<slug>.md` would be read by
  `review_at` (`:198`) as round 0 of the review, and its verdict would drive T4/T5. A name that
  is not `<digits>-<slug>.md` and not the legacy `<prefix>-review-r<n>.md` is invisible to that
  reader — which is what this pass needs.
- **A file in the reviews directory never invalidates a review.** `is_current` (`:218`),
  `same_code` (`:258`) and `only_reviews_since` (`:275`) all exclude `reviews_dir` from the diff
  they look at, so a precheck commit on the branch does not reset a review of the same head, and
  does not make the branch look changed to the gate.
- **A hold already carries a finding and already escapes a loop.** `enter_back`
  (`asf/harvest/lane.py:2122`) calls `hold_with_correction(…, kind, text, …, finding=…)`
  (`:928`); `finding_of(kind, text, keys=…)` (`asf/workers/lifecycle.py:1938`) takes the caller's
  keys — a review passes `c_items`' file list (`asf/evidence/review.py:180`) — and `same_finding`
  counts a repeat. At the cap the correction turns to an adjudicate row. `MECHANICAL`
  (`asf/workers/lifecycle.py:1806`) is the opt-out from that: `naming` and `copies` spend no round
  and never reach adjudicate.
- **A correction round is not a review round.** A review round is the `{n}` of a file in the
  reviews directory; a correction's `rounds` lives on the lane record. Sending a branch back on a
  precheck finding spends the second and not the first.
- **A brief kind is four registrations.** `build.KINDS` (`asf/briefs/build.py:48`), a
  `templates/<kind>.md` whose every `{placeholder}` is a key of `build.context`,
  `MODEL_TABLE[kind]` (`:64`), and `roles.BINDINGS[kind]` (`asf/roles/roles.py:47`) — `for_kind`
  raises `RoleError` on a kind the table does not know (`:273`).
- **The model label is picked by kind × class, and the classes are the item's.**
  `model_for(product, kind, item)` (`asf/briefs/build.py:215`) reads `item_class(item)` (`:200`)
  — a Bug's severity, else its type — against `MODEL_CLASSES` (`:54`), with
  `conventions.models.<kind>` overriding as one label or a map by class. `model_table` (`:231`)
  builds a fake item per class for the doctor's view (`_class_item`, `:238`).
- **`build` never runs git; `facts.repo_facts` does.** `repo_facts(product, row, index, inflight)`
  (`asf/briefs/facts.py:214`) returns exactly the keys the preamble reads, and the caller fills it.
  Any text the precheck's table contributes to a reviewer's brief must arrive that way.
- **`prereview` is already a session-name token** read as a review by `match.ROLE_PREFIX`
  (`asf/record/match.py:30`) and `metrics.KIND_PREFIXES` (`asf/metrics/metrics.py:44`), and
  `RECORD_KINDS` (`:53`) maps a feeder row kind onto the `sessions` stream's `kind`
  (`metrics.KINDS`, `:42`). A row kind absent from `RECORD_KINDS` is not counted as anything.
- **`review:` is already a map convention with room in it.** `conventions.map_of('review')` backs
  `review_skip_under_lines()` (`asf/conventions.py:662`, default 80). The `lane:` block's keys are
  a fixed table (`LANE_KEYS`, `:227`).
- **F-0053 is a sibling, not a dependency.** `docs/specs/f-0053.md` gives the *review* file two
  check tables and derives the round's verdict from them; nothing of it has landed
  (`asf/reviews.py` does not exist, and `templates/review.md` still asks for a typed verdict).
  It governs a different document from this one — §1.4 D8.
- **The gate is `python3 tools/run_tests.py`** (one module per process, `ASF_GATE_MODULES` to
  narrow it) plus `tools/check_generic.sh` and `tools/check_conventions.sh`.

### 1.3 Out

- **A verdict.** The precheck never approves anything. Its file carries no `verdict:` line and its
  path is invisible to `asf.evidence.review`, so it can bounce a branch and it can inform a
  reviewer, but it can never land code unread. Approval stays the expensive round's.
- **Replacing the expensive review.** A clean precheck moves the branch to `REVIEW`, exactly as
  today; it removes findings from that round, not the round.
- **Re-running the pass per round.** One precheck per head. The head moving is R4's reset
  (`asf/harvest/lane.py:1047`) and the next pass is a new head's, so a coder who answers a bounce
  gets one more cheap read and no more.
- **A vendor's review runner.** A "level" here is ASF's own: a dimension list and a reading
  discipline the brief states, and a model label. ASF may not depend on one agent harness's
  orchestration tool — the same genericity rule that keeps a product path out of `asf/**/*.py`.
- **A fourth size class.** `asf.size` keeps `SMALL/MEDIUM/LARGE`. "Very large" is the card's word
  for a *pull request*, and it is measured on the diff, not on the footprint — D3.
- **Docs branches.** `landing_class` (`asf/harvest/lane.py:320`) sorts a branch touching only docs
  roots into `docs`. The card says every *code* row; a docs branch is not one.
- **Changing what a review round is, or what an approval means.** `review_at`, `is_current`, T4,
  T5, `stalemate_round` and the adjudicate row keep their present logic untouched.
- **A new metrics stream or a new item field.** `asf precheck report` reads the branches and the
  reviews directory; nothing new is appended to `metrics/events` and no machine key is added.
- **Unticking, re-scoring or reopening a landed branch.** A precheck of a merged branch is
  history.
- **Proving that the count of critical findings actually falls.** The change makes that number
  readable per round and per level (§2.7, §4); whether it falls is an operator reading over weeks
  of the record, not an assertion a unit test can make — D10.

## 2. The design

### 2.1 `asf/precheck.py` — the level, the dimensions, the table

```python
"""asf.precheck — the mechanical pass that reads a code branch before the expensive review.

The level is derived, not configured per branch: the Task's own size class
(:func:`asf.size.classify`) and the diff's changed lines decide it, and the level decides the
dimensions the pass must cover and the model that covers them. The findings land as one table;
this module is the only thing that parses it, and the only thing that says which of its rows
sends a branch back. Nothing here opens a file, runs git or knows a path.
"""

LOW, HIGH, MAX = 'low', 'high', 'max'
LEVELS = (LOW, HIGH, MAX)
PASS, FAIL, NA = 'pass', 'fail', 'n/a'
RESULTS = {PASS, FAIL, NA}
#: The confidence a finding is stated at; only HIGH sends a branch back (D6).
CONF_HIGH, CONF_MED, CONF_LOW = 'high', 'medium', 'low'
CONFIDENCES = {CONF_HIGH, CONF_MED, CONF_LOW, NA}
HEADER = ('check', 'result', 'confidence', 'evidence')

Row = collections.namedtuple('Row', 'check result confidence evidence line')

#: The dimensions each level must cover, cumulative: HIGH is LOW's plus its own, MAX is HIGH's.
DIMENSIONS = {
    LOW: (
        'the diff stays inside the declared footprint',
        'every changed function is reachable, and every caller it changed still compiles',
        'the tests the change names were run, and their last line is green',
        'no secret value, no host name and no account name is printed or committed',
    ),
    HIGH: (
        'every error path added is reached by something, and raises or returns what its caller reads',
        'every value read from outside the process is checked before it is used',
        'a changed behaviour has a test that fails when the change is reverted',
        'nothing added duplicates something the repo already has',
    ),
    MAX: (
        'each touched file was read whole, not only its hunks',
        'each finding was re-derived from the code before it was written down',
        'the change holds under concurrency, retry and partial failure',
    ),
}


def dimensions(level):
    """The dimension list for ``level``, cumulative and in order — LOW's first."""


def level_for(size_class, changed_lines, max_lines):
    """``(level, why)`` (D3/D4). ``max`` when ``changed_lines`` is known and over ``max_lines``;
    else ``low`` for :data:`asf.size.SMALL` and ``high`` for anything else, an unknown class
    included. ``why`` is the sentence the row, the brief and the lane line all print."""
```

`level_for` is the whole rule and it is four lines:

```python
def level_for(size_class, changed_lines, max_lines):
    if changed_lines is not None and max_lines and changed_lines > max_lines:
        return MAX, f'{changed_lines} changed lines > {max_lines}'
    if size_class == size.SMALL:
        return LOW, f'size class {size.SMALL}'
    return HIGH, f'size class {size_class or "unknown"}'
```

The grammar, over the file's text:

- `parse(text)` → `([Row, …], [fault, …])`. The table begins at a line whose four cells,
  lowercased and stripped of `*` and backticks, are `HEADER`; the next line must be a separator;
  rows run to the first line not starting with `|`. A row whose cell count is not 4 is a fault. A
  result outside `RESULTS`, or a confidence outside `CONFIDENCES`, is a fault naming the line — and
  a cell still carrying the skeleton (holding `<` or an inner `|`) is reported as *unfilled*, so a
  row nobody answered can never read as a pass. A `fail` row with an empty evidence cell is a
  fault: a finding with no `file:line` is not a finding.
- `covered(rows, level)` → the dimensions of `dimensions(level)` that no row's `check` matches,
  normalized (lowercased, whitespace collapsed, backticks and trailing punctuation stripped) —
  the pass's own completeness.
- `findings(rows)` → the `fail` rows, in file order.
- `blocking(rows)` → the `fail` rows at `CONF_HIGH`. Non-empty is the bounce (D6).
- `keys(rows)` → the sorted, unique `file:line` paths the blocking rows' evidence opens with —
  the hold's finding, the shape `asf.evidence.review.c_items` gives a review (D7).
- `faults(text, level)` → the lines `asf precheck` prints: the parse faults, then one
  `dimension not covered: "<name>"` per uncovered dimension, then `no head: line` when the file
  names no head.
- `render_table(level)` → the skeleton the brief carries: the header, the separator, and one
  `| <dimension> | <pass\|fail> | <n/a\|high\|medium\|low> | ` per dimension of the level.
- `head_of(text)` → the sha the file's `head:` line names. The same one-line rule as
  `asf.evidence.review.head_of`; when F-0053's `asf/reviews.py` lands, both call it.

### 2.2 The conventions

```python
#: ``{reviews_dir}`` and ``{slug}`` are substituted. The precheck's file is deliberately NOT of
#: the review pattern's shape: ``asf.evidence.review`` must never read it as a round (F-0060 D2).
DEFAULT_PRECHECK_PATTERN = '{reviews_dir}/precheck-{slug}.md'
#: ``review: {precheck: required|none}`` — whether a code branch waits for a precheck of its head.
DEFAULT_PRECHECK_POLICY = 'required'
#: ``review: {precheck_max_lines: …}`` — a diff over this many changed lines is checked at the
#: deepest level whatever its footprint says. 0 turns the rule off.
DEFAULT_PRECHECK_MAX_LINES = 1500
```

`Conventions` gains `precheck_pattern` and the two readers `precheck_required()` and
`precheck_max_lines()`, both off `map_of('review')` and both defaulting on a malformed value,
exactly as `review_skip_under_lines()` does today; and `precheck_path(slug)`, the peer of
`review_path(slug, n)`.

### 2.3 The lane: one state, three transitions

`PRECHECK = 'PRECHECK'`, placed in `LANE_STATES` between `PR_OPEN` and `REVIEW` and added to
`LANDING_WAITS` (a pending correction turns it `BACK`, as it does for `REVIEW`). `OPEN_STATES`,
`BUSY_STATES` and the invariant derive.

`branch_facts` gains, for a `code`-class branch whose `review.precheck` is `required`:

```python
f['precheck'] = precheck_mod.at(repo, conv, f'origin/{b}', item)   # {rows, faults, head, path, text} | None
f['precheck_current'] = bool(rv) and review_mod.same_code(repo, conv, rv['head'], f'origin/{b}',
                                                          f'origin/{trunk}')
f['lines'] = changed_lines(repo, trunk, b)     # read once; review_waived reuses it
f['level'] = precheck_mod.level_for(size_class_of(self.items, item), f['lines'],
                                    conv.precheck_max_lines())
```

`same_code` is the currency rule the review already uses, so a precheck stays current across the
lane's own reword, sign-off and restack. `size_class_of` is one call to `asf.size.classify` over
the item's `writes:` and `conv.size_config()`.

In `next_state`, the `s in (PR_OPEN, REVIEW)` arm becomes `s in (PR_OPEN, PRECHECK, REVIEW)` and
opens with the precheck, before the review is consulted at all:

```
Tq  PR_OPEN/PRECHECK → PRECHECK   the branch is code class, review.precheck is required, and
                                  there is no precheck of this head: the pass is wanted
                                  reason: 'precheck wanted: level <l> (<why>)'
Tq' PRECHECK → BACK               the precheck of this head holds a fail row at high confidence
                                  reason: 'kind=precheck'
Tq'' PRECHECK → REVIEW | GATE     the precheck of this head holds none: on to the review the
                                  branch already owed (or straight to GATE when it owes none)
```

`Tq` does not fire when the branch is `foreign` with no card and no footprint — there the level is
`high` by D4 and the pass runs all the same; it does not fire when `conv.precheck_required()` is
false, and it does not fire for a `docs`-class branch. A precheck file whose own `faults` are
non-empty (a table with an unfilled row, an uncovered dimension) is treated as **no precheck**:
the state stays `PRECHECK` with `reason: 'precheck incomplete: <first fault>'`, and the loop guard
(`lifecycle.LOOP_CAP`, three sessions of one kind on one head) is what stops a session that cannot
write a table. `enter` prints the level and the path, as the `REVIEW` arm prints the round.

`enter_back` gains the kind:

```python
elif kind == precheck_mod.KIND:          # 'precheck'
    pc = f.get('precheck') or {}
    n = len(precheck_mod.blocking(pc.get('rows') or ()))
    text = (f"{pc.get('path')} holds {n} high-confidence finding(s) at level {f['level']}: "
            f"answer each one on {b}, then push")
    finding = precheck_mod.keys(pc.get('rows') or ())
```

which reaches `hold_with_correction(…, kind='precheck', text, finding=finding)` unchanged. Because
`precheck` is not in `MECHANICAL`, `same_finding` counts the repeats and the third sends the row to
adjudicate — the escape from a false positive (D7).

### 2.4 The occupancy bucket and the feeder row

`lifecycle.occupancy` gains one branch beside the `REVIEW` one (`:855`):

```python
if state == lane_mod.PRECHECK:
    out['precheck'][item] = {'branch': branch, 'level': rec.get('level') or precheck_mod.HIGH,
                             'pr': rec.get('pr'), 'why': rec.get('reason') or ''}
elif state == lane_mod.REVIEW:
    ...
```

and `out` gains the empty `'precheck': {}` beside `'review': {}`. `lane.set` writes `level` onto
the record when it enters `PRECHECK`, as it writes `round` for `REVIEW`.

`feeder/rows.py` gains `PUSHED_PRECHECK = 'PUSHED → PRECHECK'`, a `precheck_level: str = ''` field
on `Row`, and — in `lane_rows`, over the new bucket, on the same terms as the review bucket (the
item open, not `busy`, not blocked, no correction speaking for it) — the launch:

```python
Row(tier=review_tier(item), kind=PUSHED_PRECHECK, item_id=iid, feature_id=fid, action=LAUNCH,
    brief_kind='precheck', branch=branch, precheck_level=level,
    reason=f"{what} has no precheck of its head: level {level} ({h.get('why')})")
```

The tier is the review's, so the cheap pass is scheduled with the same urgency as the round it
replaces a part of. Because the bucket is neither `review` nor `landing`, no `PUSHED → REVIEW` row
is raised for the same item in the same tick: the item is in exactly one bucket, as it is today.

### 2.5 The brief: the level is the scope

`build.KINDS` gains `'precheck'`; `KIND_ALIASES` maps `'pre-check'` and `'prereview'` onto it;
`MODEL_CLASSES` gains the three level names; `MODEL_TABLE` gains

```python
'precheck': {'default': CHEAP, LOW: CHEAP, HIGH: LIGHT, MAX: LIGHT},
```

— never `HEAVY`, which is the guarantee the card asks for: the pass is always cheaper than the
round it precedes. `model_for(product, kind, item=None, cls=None)` uses `cls` when given, and
`model_table` calls it with the class directly instead of building a fake item (D11). The launcher
passes `row.precheck_level` as the class for this kind.

`context()` gains `precheck_level`, `precheck_why`, `precheck_dimensions` (the numbered list),
`precheck_path` and `precheck_table` (`render_table(level)`). `templates/precheck.md`:

````markdown
## Your job: the mechanical pass on {branch} — level {precheck_level}

{precheck_why}. You are the cheap read that runs before the expensive one. Find what a careful
reader finds mechanically; do not judge whether the change is the right change — that is the round
after you, and a paragraph of opinion from you costs it time.

Read the diff against `origin/{main}`, then each file it touches.

Answer every dimension below by running or reading something, in this order:

{precheck_dimensions}

Write `{precheck_path}` — the `head:` line, then exactly this table, one row per dimension and one
extra row per finding you make. A row with no evidence is not a finding:

{precheck_table}

`confidence` is `high` only when you have the `file:line` and the fix and you would stake the
branch on it — a `high` row sends this branch back to its writer with no review round spent. When
you are not that sure, say `medium` or `low`: the reviewer after you reads every row, so nothing
you write is lost.

Then run the self-check and fix what it names:

```bash
asf precheck {precheck_path} --level {precheck_level}
```

Commit the file on `{branch}` — the subject names the item — and push. Write no other file.
````

`ID_RANGE_KINDS` is not touched: the pass mints nothing.

### 2.6 The reviewer starts from the table

`facts.repo_facts` gains one key for a `review` row — `precheck`, the text of the precheck file at
the branch's head, or `''`. `build.context` renders it as `{precheck_block}`, and
`templates/review.md` opens with it:

````markdown
A mechanical pass already read this branch at level {precheck_level} and wrote
`{precheck_path}`. Its table is below. Start from it: a finding already in it is the precheck's,
and is **never** a new C in your round — cite the row and move on. Your round is for what a
mechanical read cannot answer.

{precheck_block}
````

When there is no precheck (the policy is off, or the file is missing) the block is one line saying
so, and the round runs exactly as it does today. Every placeholder is a context key, so the
golden briefs are regenerated in this change.

### 2.7 `asf precheck` — the self-check and the report

```
usage: asf precheck PATH --level {low,high,max} [--json]
       asf precheck report [--days N] [--json]
```

The first is the pass's own last act, the mirror of `asf review-checks` in F-0053. Human output:

```
== PRECHECK docs/reviews/precheck-t-0244.md  level high, 11 rows, 2 findings (1 high), 1 fault
docs/reviews/precheck-t-0244.md:19: row 6: confidence is unfilled (`<n/a|high|medium|low>`)
docs/reviews/precheck-t-0244.md: dimension not covered: "nothing added duplicates something the repo already has"
blocking: 1 — this branch will be sent back
```

Exit 1 on a fault, 0 with none — and a clean run still prints its `blocking:` line, because
finding something is the pass working, not the pass failing. `--json` prints
`{"path", "level", "head", "rows": [...], "findings": n, "blocking": n, "faults": [...]}`, keys
sorted.

`asf precheck report` is the measurement D10 leaves to the operator, made readable: over the last
`--days N` (default 30), one row per item whose branch carried both a precheck and a review,
printing the level, the precheck's finding counts by confidence, the expensive rounds that
followed, and the C items those rounds raised — with the C items whose `file:line` the precheck
already named counted separately, as `repeated`. The number the card asks about is the last
column's total over time; the number this change must keep honest is `repeated`, which should be
zero.

### 3.1 The level, from the class and the diff

`level_for` over: `(SMALL, 40, 1500)` → `low`; `(MEDIUM, 40, 1500)` → `high`;
`(LARGE, 40, 1500)` → `high`; `(SMALL, 4000, 1500)` → `max` — the diff rule beats the class;
`(LARGE, 4000, 1500)` → `max`; `(SMALL, None, 1500)` → `low` — an unreadable diff never lifts the
level; `(None, 40, 1500)` → `high` (D4); `(SMALL, 4000, 0)` → `low` — the rule is off. Every `why`
names the number that decided it. `dimensions(LOW)` is four names, `dimensions(HIGH)` is those
four then four more in order, `dimensions(MAX)` is those eight then three more, and no name
appears twice across the three.

### 3.2 The grammar, and what it refuses

`parse` over a file with a four-column table returns one `Row` per line in file order, with an
escaped `\|` in a check name unescaped and no fault. Faults, each naming its line number: a row of
three cells; a result of `approved`; a confidence of `certain`; a result still reading
`<pass|fail>` reported as *unfilled*, never as a pass; a `fail` row with an empty evidence cell; a
header with no separator under it (no table found, no rows, no fault). `covered` returns the
uncovered dimensions in level order and `()` for a table with one row per dimension.
`findings` is the `fail` rows and `blocking` only the `high` ones — a table of three `fail` rows at
`low`, `medium` and `high` gives `findings` 3 and `blocking` 1. `keys` over that table is the
sorted unique paths the high rows' evidence opens with. `render_table(HIGH)` re-parses through
`parse` into eight rows, eight *unfilled* faults and no other fault. `head_of` reads the `head:`
line and returns None without one.

```bash
python3 -m unittest -v tests.test_precheck.TableTests
```

## 4. Records

**The precheck file** — `conventions.precheck_path(slug)`, one per branch, rewritten by each pass —
is the artefact the card asks for. A `head:` line, then one table:

```markdown
# Precheck — T-0244, level high

head: 4f2a9c1b8e03d7a6

| check | result | confidence | evidence |
| --- | --- | --- | --- |
| the diff stays inside the declared footprint | pass | n/a | asf/precheck.py, asf/cli.py — both declared |
| the tests the change names were run, and their last line is green | pass | n/a | `OK (ran 41 tests)` |
| every value read from outside the process is checked before it is used | fail | high | asf/precheck.py:118 — `int(cells[1])` on a cell the table never validated; guard with `RESULTS` first |
| nothing added duplicates something the repo already has | fail | low | asf/precheck.py:62 — `normalize` is close to `evidence.cells`' stripping; may be worth merging |
```

**The lane record** gains `level` on a `PRECHECK` state, beside the `round` a `REVIEW` state
already writes. No new lane field otherwise, and the review `round` is untouched by this pass.

**The correction** is an ordinary one, of kind `precheck`: its text names the file, the count and
the level; its `finding` is the `file:line` paths of the high rows, so `same_finding` reads a
repeat the way it reads a repeated C item. It spends a correction round and no review round.

**`asf precheck` stdout** is the self-check's record — the `== PRECHECK` header, one line per
fault, the `blocking:` line — and `--json` the same as one typed object. **`asf precheck report`**
is the read the card's second acceptance line is measured on.

**The `sessions` stream** carries the pass as any other session, through
`RECORD_KINDS['precheck'] = 'review'` and the `precheck` token in `match.ROLE_PREFIX` and
`metrics.KIND_PREFIXES`, so its cost lands in the existing per-Feature cost table and the saving is
visible against the review spend it is meant to reduce.

**Nothing else.** No new metrics stream, no new machine key on any card, no change to `index.json`,
no change to a PR body, and no existing review file becomes unreadable.
