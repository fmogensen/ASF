# F-0179 — the jobs nobody judged

A product's PR #849 moves 13 heavy jobs to one expression:

```yaml
runs-on: ${{ fromJSON(format('["self-hosted","{0}"{1}]', vars.X || 'heavy', github.event_name == 'pull_request' && ',"class-pr-heavy"' || '')) }}
```

`asf/ci_pool.py` reads `runs-on` with a line reader and one regex. That regex matches
`${{ … || 'literal' }}` and nothing else, so this value resolves to `None` — and `None` is the
reader's word for *not judged*. Both consumers drop such a job silently: `drift` builds its jobs
list as `[ro for ro in runs_on if ro.self_hosted]` and `self_hosted` is false when `labels is
None`, and `plan` builds the same list for the one question that protects capacity — *does a
current `runs-on` still need this label on this runner?*

So after that PR, on that product: the doctor's `unsatisfiable` check no longer sees 13 jobs, and
`asf ci reconcile --apply` no longer sees that `self-hosted`, the heavy role and `class-pr-heavy`
are labels in use. Every one of them is a candidate for removal, from every runner, with no row
saying why. The reader's silence is the defect: it does not say *I could not read this*, it says
*there is nothing here*.

The same silence has a second face the card names. `${{ vars.X || 'heavy' }}` is read today as
`heavy` **always**, without ever asking the repo what `X` is. A repo that sets `vars.X` to
anything else has a label in use that this reader has never heard of, and `--apply` strips it.
A guess is worse than a refusal here, because the refusal is recoverable and the write is not.

This spec is the reader: a small evaluator over the four things these expressions are made of
(`fromJSON`, `format`, `vars.*`, a `github.event_name` comparison), one label set per event class,
a union across events wherever "needed" is asked, and — for everything it still cannot read — a
visible row and a reconcile that removes nothing.

## Decisions

### In scope

- `fromJSON(format(…))` resolved over literal arguments, `vars.*` arguments and
  `github.event_name` comparisons, including `&&`/`||`/`==`/`!=` and parentheses.
- One `RunsOn` per **event class** for a job whose labels depend on the event; a label wanted
  under any event counts as needed by both `drift` and `plan`.
- The repo's Actions variables read once per `runs_on()` call and passed to the parser.
- An unresolved `runs-on` made loud: an advisory doctor row per job, a `cmd_reconcile` line, and
  **no label removed by any step of the plan** while one stands.
- The class label a resolved expression now reveals not counted as provider-like drift.

### Out of scope, and why

- **Partial resolution.** `[self-hosted, "${{ matrix.tier }}"]` stays wholly unresolved rather
  than yielding `{self-hosted}` as a floor. A floor would have to answer "is this set satisfied"
  and "is this label needed" with a set known to be incomplete, which is two new meanings for
  `_satisfies` and for the `blocked` decision; the freeze (C7) already makes it safe, and a floor
  only makes it less blunt. A separate card's work.
- **Organisation-level variables.** The card says the repo's; `repos/<slug>/actions/variables` is
  one call and one permission. A variable set only at org level reads as unset, which is the same
  answer this reader gives today for any `vars.*` — with the difference that it is now recorded as
  a known-empty set rather than a guess (C3).
- **An ignore list** (`ci.runs_on_ignore`, a per-workflow opt-out of the freeze). A new product
  key, and nothing in the card asks for one. The escape hatch for a `${{ matrix.os }}` job is to
  resolve it or accept that removals wait; the doctor row names the job either way.
- **`matrix`, `inputs`, `needs`, `runner`, `env`, `secrets`.** Every other context is unresolved,
  and now unresolved even under a `|| 'default'` (C3).
- **Any change to what a role or class label *means*.** `docs/decisions/0002` stands.

## The design

Everything is in `asf/ci_pool.py`, plus one docstring in `asf/doctor.py` and one section of the
guide.

### 1. The evaluator (new, after `_strip_comment`)

```python
EVENT_OTHER = 'other'           #: the event class standing for every event the text does not name
_EVENT_CTX = 'github.event_name'


class _Unresolved(Exception):
    """This reader cannot read that expression."""


def event_classes(text):
    """The event classes one ``runs-on`` value must be evaluated under: every literal it compares
    ``github.event_name`` to, in order, then :data:`EVENT_OTHER`; ``('',)`` when it names no
    event at all."""


def resolve_expr(body, variables=None, event=''):
    """The value of one ``${{ … }}`` body under one event class. ``variables``: the repo's Actions
    variables, ``None`` when the set is unknown (then any ``vars.*`` is unresolved; an absent name
    in a known set is ``''``). Raises :class:`_Unresolved` for anything outside the grammar."""
```

The grammar, lowest precedence first: `||`, `&&`, `==`/`!=`, unary `!`, then a primary — a
single-quoted string (`''` is one quote), `true`/`false`/a number, `vars.<NAME>` (looked up
case-insensitively), `github.event_name`, `( … )`, `fromJSON(x)` or
`format(tmpl, …)`. Truthiness is GitHub's: `''`, `false`, `0` and `None` are falsy; `a || b` is
`a` when `a` is truthy else `b`; `a && b` is `b` when `a` is truthy else `a`. `format` substitutes
`{0}`, `{1}`, … and honours `{{`/`}}`; `fromJSON` is `json.loads` and must yield a string or a
list of strings (C2). A trailing token, an unknown word, an unknown call or a bad JSON payload is
`_Unresolved`.

`_label_token(tok, variables=None, event='')` replaces its regex with a call to `resolve_expr` for
a token that is wholly `${{ … }}`, returning `_norm` of the value (a one-element list resolves to
its element) and `None` on `_Unresolved`. `_EXPR_DEFAULT` goes.

### 2. `parse_runs_on(workflow, text, variables=None)`

Unchanged in its line reading (P2). At each `runs-on:` it now:

1. reads the raw value (scalar, flow list or block list) as today, keeping the text as `raw`;
2. computes `classes = event_classes(raw)`;
3. for each class, resolves every token under that class — a scalar `${{ … }}` whose value is a
   list becomes that list of labels;
4. emits one `RunsOn(workflow, job, labels, event=cls, expr='' if labels else raw)` per class,
   collapsed to a single `event=''` row when every class gave the same `labels` (C5). An
   unresolved class is `labels=None` and keeps `expr=raw`.

`RunsOn` gains `event: str = ''` and `expr: str = ''` (P8), and `text()` becomes
`f"{workflow}:{job}{f' ({event})' if event else ''} [{', '.join(sorted(labels or ()))}]"`.

The card's expression, with no variables known, is one unresolved row. With `variables={}` or
`{'X': 'heavy'}` it is two rows:

```
ci.yml:heavy (pull_request) [class-pr-heavy, heavy, self-hosted]
ci.yml:heavy (other) [heavy, self-hosted]
```

### 3. `GitHubBackend.variables()` and `runs_on()`

```python
    def variables(self):
        """The repo's Actions variables, upper-cased names → values; ``None`` when they cannot be
        read (then a ``vars.*`` in a ``runs-on`` is unresolved, C3/C9)."""
```

One `gh api --paginate repos/<slug>/actions/variables?per_page=100 --jq '.variables[]'` through
`_lines`, wrapped so a `BackendError` (and only that) returns `None`. `runs_on()` calls it once,
before the file loop, and passes the result to every `parse_runs_on`.

### 4. The doctor

```python
def unresolved(runs_on):
    """The rows whose ``runs-on`` this reader could not resolve, one per workflow+job."""


def unresolved_rows(runs_on):
    """``[(False, ok, detail)]``, advisory: one row per unresolved ``runs-on`` (C6)."""
```

Row text, one per job, `workflow:job` order:

```
runs-on unresolved: ci.yml:mat — ${{ matrix.os }} — its labels are not judged, and asf ci reconcile removes no label while it stands
```

`doctor_rows` returns `drift rows + unresolved_rows(runs_on) + reserve_rows(…) + class_rows`, and
`asf/doctor.py:check_ci_pool`'s docstring names the new row kind. `drift` changes in exactly one
place: the provider-like flag skips a declared class label (C8) —

```python
    declared_classes = {e.class_label for e in pool if e.class_label} | set(owned)
    ...
        if is_default(label) or label in role_set or label in declared_classes or …:
            continue
```

### 5. The plan

`Step` gains `held: list = dataclasses.field(default_factory=list)` between `blocked` and `note`
(P8), and `action` gains one clause after `blocked`'s:

```python
        if self.held:
            parts.append('keep ' + ', '.join(self.held) + ' — an unresolved runs-on may need them')
```

In `plan`, `frozen = bool(unresolved(runs_on))`, and the removal decision becomes:

```python
        for label in sorted(have - target):
            if label in owned:
                remove.append(label)                    # the reservation's own decision
            elif frozen:
                held.append(label)
            elif any(label in ro.labels and ro.labels <= after for ro in jobs):
                blocked.append(label)
            else:
                remove.append(label)
```

`apply` is untouched: it writes `s.remove`, which is now empty. `cmd_reconcile` prints, after the
table and before the trial verdicts, one line per unresolved job:

```
ci reconcile: runs-on unresolved — removing nothing: ci.yml:mat ${{ matrix.os }}
```

### 6. The guide

`docs/guide/ci-runner-pool.md` — the paragraph at `:80-82` is rewritten: what the reader now
resolves (`fromJSON`/`format`/`vars.*`/`github.event_name`, one label set per event class, a label
needed under any event), that a `vars.*` is read from the repo's Actions variables and is
unresolved when they cannot be read, and that an unresolved `runs-on` is one advisory row and a
reconcile that removes nothing. The doctor table gains the `runs-on unresolved:` row, the
`unsatisfiable` row's format gains its `(<event>)`, and the "capacity is never lost" list gains
the `held` line.

## Acceptance tests

Four blocks, all in `tests/test_ci_pool.py`, no `gh` and no network (P12).

**The evaluator and the card's own expression.** A new class `Expressions` — `resolve_expr` over
string literals and `''` escapes, `==`/`!=`/`&&`/`||`/`!`/parens with GitHub's truthiness,
`format` with `{0}`/`{1}` and `{{`/`}}`, `fromJSON` yielding a string and a list, and

and an unclosed paren; `event_classes` over the card's text (`('pull_request', 'other')`), over a
three-way `schedule`/`pull_request` text (C4) and over a text naming no event (`('',)`); and
`vars.X` unresolved with `variables=None`, `''` with `variables={}`, its value with
