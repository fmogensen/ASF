# F-0110 — the product a view shows, and saying so

On 2026-09-24 the first customer ran `/asf:next` in their own product's Claude Code session and
read `0 rows`. `ASF_PRODUCT` was not set, so the skill fell through to `config.yaml`'s
`default_product` — another product — and printed that product's empty table. `asf next --product
<p>` showed six rows. Two separate failures produced one symptom: the resolution did not consider
where the command was run, and the table never said which product it was.

The first half has since landed. `b4fc8df8d` ("fix(env): a bare command resolves the product whose
checkout holds the cwd", #198) added `env.product_of_dir` and put it in `default_product_name`
between `$ASF_PRODUCT` and `default_product` (`asf/env.py:422-474`), so the order this card asks
for is already the order the code walks. What is still missing is everything that makes it
trustworthy: the order lives as a convention repeated at nine call sites rather than in one
function, the cwd match is a string comparison that demonstrably misses on the operator's own
machine, no view prints the product it is showing, the installer still ends by telling the
operator to set `ASF_PRODUCT`, and the `/asf:*` skills and the guide still describe the
three-step order that #198 replaced.

After this change there is one function that answers "which product, and why that one", every
record command and every view opens with a line naming the record and the product and the input
that chose it, and an operator who lands in the wrong product sees it in the first line instead of
inferring it from an empty table.

### In

- **One function owns the order.** `env.resolve_product(explicit=None, path=None)` returns
  `Resolution(name, source)` — a `collections.namedtuple` — and walks, in this order: `explicit`
  (`--product`), `$ASF_PRODUCT`, `product_of_dir(path)`, `config.yaml`'s `default_product`.
  `source` is one of the four literal tokens `'--product'`, `'$ASF_PRODUCT'`, `'cwd'`,
  `'default_product'`: the *name of the input that chose the product*, so a wrong fallback can be
  read off one line and grepped for. When none answers it raises `ConfigError` naming all four
  inputs (today's message names three — `asf/env.py:471-473`).
- **`default_product_name()` stays exactly what it is**, reduced to
  `return resolve_product().name`. Its twenty-odd callers are not touched; nothing that only needs
  a name has to learn a tuple.
- **The seven `--product`-first call sites (P3) become `env.resolve_product(args.product)`**, so the
  order is walked in one place instead of being re-asserted by argument position. `load_product`
  and `state_dir` keep their current signatures (a name or a `Product`).
- **The cwd match is containment by directory identity, not by string.** `product_of_dir` collects
  `(st_dev, st_ino)` for each candidate root that exists, then walks the realpath of `path` and its
  parents once, stopping at the first level whose `(st_dev, st_ino)` is in that set. The card's
  rule is unchanged — the realpath is still what is resolved, and the deepest matching root still
  wins (measured, as today, by the length of the root's realpath) — but the comparison is made
  against the directory itself rather than its spelling, which is what P11 requires. A root that
  does not exist, or a `stat` that fails, is skipped exactly as an unparseable product file is:
  this is a guess made before any product is loaded, never a reason to fail one.
- **`cli.product_line(product, source, record=None)`** is the single formatter:
  - with a record: `record: <path> · product <p> (<source>)`
  - without one:   `product <p> (<source>)`
  - when the cwd is itself a record that no product claims: `record: <path> · product (none) (cwd is a record)`
  The prefix the card names — `record: <path> · product <p>` — is the literal head of the line, so
  the card's format is satisfied and the source is an appended parenthetical.
- **`resolve_record` prints it** (`asf/cli.py:392,399`), keeping its existing `announce` seam: to
  stdout for a table, to stderr when the command's stdout is a value a script reads (`new`,
  `inbox`, `set`, `reopen`, `stale`, and any view under `--json`). That covers every record command
  and the nine views of P4 at once.
- **The four commands that bypass it print it too**, from the same helper and with the same
  stdout/stderr rule: `next` (`asf/feeder/render.py:102`), `brief` (a brief is a value — stderr,
  like `stale`), `capacity` (the record-less form: it reads config and product files, never the
  record, so printing a record path there would be a lie), and `doctor`, whose caption becomes
  `== DOCTOR <product> (<source>)`. `asf capacity --all` shows every product, one per row, and
  prints `products: all — <n> declared` instead.
- **`tools/install.sh`'s closing lines stop asking for `ASF_PRODUCT`.** The last two lines become
  a statement of the rule and a conditional, not an instruction:

  ```
  install: /asf:* resolves the product from the working directory — a session started in
  install: <product>'s repo or its record needs no ASF_PRODUCT.
  install: set ASF_PRODUCT=<product> only for a session that runs outside both.
  ```

  The installer names no path of its own: it knows only `$PRODUCT` (P10), and a wrong path printed
  here would be worse than none.
- **The generated skills and the guide catch up with the order.** `asf/plugin_build.py`'s preamble
  becomes "`--product` if you give one, else `$ASF_PRODUCT`, else the product whose repo or record
  holds the working directory, else `default_product` in `~/.ASF/config.yaml`", and
  `plugin/skills/*/SKILL.md` is regenerated with `asf plugin build` (P9 makes this mandatory, not
  optional). The same four steps replace the three in `asf/cli.py`'s module docstring
  (`asf/cli.py:3-6`), `README.md:26-27`, and `docs/guide/getting-started.md:30,113-117`.
- **The audit matrix grows to one row per view.** `tests/test_path_resolution.py`'s `COMMANDS`
  gains `capacity`, `tokens`, `scorecard` and `release-readiness`, and the first-line assertion
  stops exempting `view` rows.

### Out

- **Changing the order itself.** `--product` → `$ASF_PRODUCT` → cwd → `default_product` is the
  card's order and P2 already walks it. This change makes it one function, one line of output and
  a test; it does not renegotiate the sequence.
- **Case-folding paths.** P11 is fixed by comparing directory identity, not by lowercasing: a
  case-insensitive comparison would be wrong on a case-sensitive filesystem, where `~/a` and `~/A`
  are two directories.
- **Reading the cwd for a `repo` command's working directory.** `harvest`, `tick`, `workers *` and
  `scheduler` run in the product's repo, not the cwd, and `tests/test_path_resolution.py` already
  holds that line. They resolve their product through the same function, and they gain no header:
  their output is a log, not a view.
- **A new `asf where`/`asf config get` for the installer.** Tempting (it would let the installer
  name the actual `repo_dir`), but it is a new command and a new surface for one sentence of prose.
  The rule stated without a path is enough.
- **Making `$ASF_PRODUCT` unnecessary for worker sessions.** The tick sets it for every session it
  spawns (`asf/tick/tick.py:85`) and will keep doing so: a worker's cwd is a worktree, and an
  explicit variable beats an inference for a session nobody is watching.

### The choices

| # | Chosen | Against | Why |
| --- | --- | --- | --- |
| D1 | `resolve_product` returns `(name, source)`; `default_product_name` becomes a wrapper | a second function `product_source()` that re-walks the order | two functions walking the same order is the bug this card is about, one level up |
| D2 | The four sources are the literal tokens `--product`, `$ASF_PRODUCT`, `cwd`, `default_product` | prose (`"from the working directory"`) | they are the names of the four inputs, they are what an operator would grep, and they are the card's own words |
| D3 | The source is appended in parentheses to the card's format | the card's bare `record: <path> · product <p>` | "0 rows" for the right product and "0 rows" for the wrong one look identical without it; the card's string stays the literal head of the line |
| D4 | Containment by `(st_dev, st_ino)`, walking up from the cwd once | `commonpath` over realpaths (today), or `os.path.samefile` per (level, root) pair | P11 shows the string compare missing on the operator's own machine; the stat-set walk is O(depth + roots) where the pairwise `samefile` is O(depth × roots) |
| D5 | `capacity` prints the record-less form of the line | give it the record path anyway, for a uniform line | it never reads the record; a path it did not use is a false statement in the one line meant to be trusted |
| D6 | `doctor` keeps its caption and gains `(<source>)` | prefix it with a `record:` line | its first line already names the product, and two headers on one table is noise; the source is the only thing it was missing |
| D7 | `brief`'s line goes to stderr | stdout, with the brief | `asf brief`'s stdout is a value — the brief text a worker is handed; `new` and `stale` already take this seam (`cli._announce_stderr`) |
| D8 | The installer states the rule and names no directory | print the product's `repo_dir` | it cannot read it (P10) without a new command (Out) and a guessed path is worse than a stated rule |
| D9 | The six exact-equality assertions of P8 are updated in place | keep the old line and print the product on a second line | one line per view is the card's requirement; a second line is one more thing to miss |
| D10 | `COMMANDS` gains its four missing views, and each Story extends the assertion only for the commands it makes true | one Story flips the assertion for every row at once | the matrix stays green at every commit, and the two Stories keep disjoint writes |

## The design

### `asf/env.py`

```python
Resolution = collections.namedtuple('Resolution', 'name source')

#: The four inputs that can name a product, in the order they are tried. The token is printed
#: in every view's first line, so a wrong fallback is visible (F-0110).
PRODUCT_SOURCES = ('--product', '$ASF_PRODUCT', 'cwd', 'default_product')


def resolve_product(explicit=None, path=None):
    """Which product a command acts on, and what chose it: ``--product``, else
    ``$ASF_PRODUCT``, else the product whose repo or record holds ``path`` (default: the cwd —
    :func:`product_of_dir`), else ``config.yaml``'s ``default_product``. Raises
    :class:`ConfigError` naming all four when none answers."""
```

`product_of_dir` keeps its signature and its contract, and swaps its comparison:

```python
    ids = {}                      # (st_dev, st_ino) -> (name, len(root))
    for f in files:               # every ~/.ASF/products/*.yaml, unparseable ones skipped
        ...                       # roots: repo_dir, backlog_dir, <ASF_HOME>/state/<name>
        try:
            st = os.stat(root)    # a root that does not exist is not a root
        except OSError:
            continue
        key = (st.st_dev, st.st_ino)
        if len(root) > ids.get(key, (None, -1))[1]:
            ids[key] = (name, len(root))
    here = os.path.realpath(path or os.getcwd())
    while True:                   # the deepest matching root wins: walk up from the cwd
        try:
            st = os.stat(here)
        except OSError:
            return None
        hit = ids.get((st.st_dev, st.st_ino))
        if hit:
            return hit[0]
        parent = os.path.dirname(here)
        if parent == here:
            return None
        here = parent
```

Two roots that are the same directory (a product whose `backlog_dir` is inside its `repo_dir`,
say) collapse to one key, and the longer spelling wins the name — the same tie-break as today.

### `asf/cli.py`

```python
def product_line(product, source, record=None):
    """The first line of every view: ``record: <path> · product <p> (<source>)``, or
    ``product <p> (<source>)`` for a view that reads no record (``capacity``). ``product`` is
    ``None`` when the cwd is a record no product claims."""
```

`resolve_record` (`asf/cli.py:377`) keeps every branch it has; only what it announces changes:

| cwd | `--product` | The first line |
| --- | --- | --- |
| a product's repo | — | `record: /p/backlog · product bot (cwd)` |
| a record `bot` claims | — | `record: /p/backlog · product bot (cwd)` |
| a record no product claims | — | `record: /some/record · product (none) (cwd is a record)` |
| anywhere | `--product asf` | `record: /a/backlog · product asf (--product)` |
| nowhere, `ASF_PRODUCT=asf` | — | `record: /a/backlog · product asf ($ASF_PRODUCT)` |
| nowhere, nothing set | — | `record: /a/backlog · product asf (default_product)` |

## Records

Nothing new is written to the record, to `~/.ASF` or to any ledger: this change only reads the
inputs that already exist and prints what it read.

- **The first line of every view, on stdout** — `record: <path> · product <p> (<source>)`, or
  `product <p> (<source>)` for `capacity`, or `== DOCTOR <p> (<source>)` for the doctor. For a
  command whose stdout is a value (`new`, `inbox`, `set`, `reopen`, `stale`, `brief`, and any view
  under `--json`) the same line goes to stderr. This is the record of the change: every table an
  operator or a session ever pastes now carries the product it came from.
- **`ConfigError`'s message**, when no input names a product: the four inputs, in order, in one
  sentence — `no --product, no $ASF_PRODUCT, no product whose repo or record holds <cwd>, and
  config.yaml has no default_product`.
- **`plugin/skills/*/SKILL.md`** — regenerated, twelve files, one changed sentence each. The tree
  is generated output under `tests/test_plugin.py`'s byte-parity check, so it is committed with the
  builder change, never after it.
- **`tools/install.sh`'s closing lines**, `asf/cli.py`'s module docstring, `README.md` and
  `docs/guide/getting-started.md` — the four-step order, replacing the three-step one.
- No migration, no new config key, no new state file. An operator who has `ASF_PRODUCT` exported
  keeps exactly today's behaviour, and now sees `($ASF_PRODUCT)` saying so.
