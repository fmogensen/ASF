# F-0217 — a factory publish is progress, and the guard must see it

On 2026-09-27 the loop guard parked F-0003. Its session had done the work: the commits were on the
branch, and the factory published them in that same tick — `b7331004f` reached
`origin/<branch>` before the tick was over. The park was written anyway, because the decision was
made from the heads the *launches* were read on, and every one of those was read before the
publish. An operator unparked it by hand.

The guard is right to exist. `same_head_loop` was written for `adjudicate-b-1377` ×14 and
`correct-t-0338` ×12, each launch on a head nothing had moved, and it saves those sessions. What it
must not do is call a branch unmoved when the factory itself moved it an hour earlier in the same
pass.

The mechanism is in one line. `same_head_loop` has two ways to know the branch moved — the `head`
argument ("where the branch sits now") and the `main` argument (the worktree HEAD is a rebase or a
fast-forward past the launch head) — and **both are optional**. Three of the seven
`lifecycle.hold` call sites pass neither, and two of those three are the ones the health step
reaches *after* it has published (P2, P3). With neither argument the guard decides from
`launch_head` alone, and `launch_head` is by construction the head as it stood **before** the run
it belongs to ever committed anything.

This card is: **a factory publish that lands the session's commits is recorded as the progress it
is, the guard counts it, and no hold site decides a loop from launch-time heads alone.**

### In scope

- The factory's own publish of a lane branch in the health pass is recorded on the run's ledger
  line as the sha it put on origin.
- `same_head_loop` counts such a record as a session having added a commit: no park.
- Every `lifecycle.hold` call site hands the guard the trunk it knows, and the head it already
  holds — plus a test that refuses a new call site that does not.

### Out of scope

- `LOOP_CAP` itself, and the other three parks (`EMPTY_CAP`, `INCOMPLETE_CAP`, `BLOCKED`,
  `RELAUNCH_CAP`). None of them reads a head; none is implicated.
- The rounds counter, `next_finding`, the cap-to-adjudicate escalation.
- The lane's two hold sites. They already pass `head` and `main` (P3) and are not touched beyond
  the invariant test's reach.
- Spawn's launch-time publish (B-0056): `launch_head` is read after it and already carries its
  result (P10).
- Whether `hold_failed_corrections` should hold at all a run the same pass just re-judged
  `finished` — a real question, and B-0085's, not this card's. This card stops the *park*.
- Releasing any park already written. F-0003 was unparked by hand; `asf unpark` is the operator's
  verb and stays it.

### The choices

| # | Chosen | Against | Why |
| --- | --- | --- | --- |
| C1 | **Record the publish on the run line (`published_head`), and have the guard read it.** | Fix only the call sites — pass `head`/`main` everywhere. | P5: the call-site fix is blind the moment the worktree is gone, and health reaps worktrees in the same step that holds. The ledger is the only witness that survives the tree. It is also the card's own first sentence: a publish that lands the session's commits *is* progress, and progress belongs in the record, not in an argument one caller remembers to pass. |
| C2 | **Do the call-site fix as well.** | The ledger record alone. | They fail apart. The record covers a publish with no worktree; `main` covers a session that committed and was never published at all (the run died before the push, the branch is not on origin, `ev.remote_sha` is `''` — P2's falsy-head case). Neither is a subset of the other, and each is one line. |
| C3 | **The published sha is computed by the caller from the evidence it already has** — `before = ev.remote_sha` captured before the yield, `after = ev.remote_sha` after it — through one pure helper, `lifecycle.published_sha(before, after, line)`. | (a) `publish_gap` writes the ledger line itself; (b) `publish_gap` returns a fourth tuple element; (c) parse `published <branch> at <head>` out of the line. | (a) is refused by `run_steps`' own contract: publishes run on a thread pool and *only* publishes do — "every judgement and registry write stays serial" (`health.py:460-470`). (b) changes the generator protocol at three resume points for a fact the callers can already see. (c) makes a printed sentence load-bearing. The helper is pure, testable, and the callers each already make an `update_session` call to carry the field. |
| C4 | **Progress is `published_head` present and *different from the loop head*.** | Any `published_head` at all. | A publish that pushed the very head the launches were read on moved nothing, and a presence test would disarm the guard on it. The guard's question is "did anything move", so the answer is a comparison. The same reasoning as `head`'s own test one line below (`if head and head != sha`), which P2 measured both ways. |
| C5 | **`published_head` is not added to `RUN_FIELDS`.** | Add it, for symmetry with `publish_refused`. | P9: `RUN_FIELDS` is the list of keys that may be written `null` to clear them, and nothing clears a publish — it happened. The fold already confines the field to its own run, measured. Adding it would declare a null write that never comes. |
| C6 | **The seventh-call-site problem is closed by a test, not by a required argument.** An AST walk asserts every `lifecycle.hold(` call in `asf/` passes `main=`. | Make `main` a required parameter of `hold`. | A required parameter is the stronger guarantee and the bigger blast radius: `hold`'s signature is read by `hold_with_correction`, `footprint_hold`, `hook_refusal_hold` and `rebase_conflict_hold`, and every existing test that calls `hold` positionally would have to change. The AST test is the shape this repo already uses for exactly this (`tests/test_lifecycle.py:803-813`), it names the offender by `file:line`, and it fails on the *next* head-less site rather than on this one. `head=` cannot be demanded this way — a caller with no evidence has no head to give — so `main=` is the invariant and `head=` is passed wherever evidence exists. |

## The design

### 1. The publish is recorded — `asf/workers/health.py`, `asf/workers/lifecycle.py`

One pure helper beside `publish` in `lifecycle`:

```python
def published_sha(before, after, line):
    """The sha the factory's publish put on ``origin/<branch>`` this pass, or ''.

    ``before``/``after`` are ``Evidence.remote_sha`` read either side of :func:`publish` — the
    second from the re-gather :func:`asf.workers.health.publish_gap` already makes — and ``line``
    is the publish's own. A refusal, a sha that did not move and a pass that published nothing
    are all ''. F-0217: a publish that lands the session's commits is progress, and the loop
    guard must be able to read that off the ledger long after the worktree is gone."""
    if not after or after == before or not line or ' refused: ' in line:
        return ''
    return after
```

Each of health's three resume points captures `before = ev.remote_sha` on the line above its
`yield` and folds `published_head` into the `update_session` it already makes:

- `republish_steps` (`:530`) — into the `fields` dict at `:535-536`, beside `end_reason` and
  `publish_refused: None`, on the arm that runs when the line is not a refusal.
- the dead-pid re-judge (`:705`) — into the `update_session(product, job, end_reason=…, rc=…)`
  at `:709`.
- the ordinary end-of-run pass (`:722`) — into the `update_session(product, job, ended=now,
  end_reason=reason, …)` at `:732`, which is written **before** every `elif` arm that holds.

`published_head` is written only when it is non-empty: a pass that published nothing appends no
key. The run's `s` dict is updated in step with the ledger, as the surrounding code already does.

### 2. The guard counts it — `asf/workers/lifecycle.py:2355-2388`

Inside `same_head_loop`, immediately after the single launch head is known:

```python
    sha = heads.pop()
    if any((r.get('published_head') or '') not in ('', sha) for r in rs):
        return None  # F-0217: the factory published a session's commits off that head
    if head and head != sha:
        return None
```

and the docstring gains the third way a window is not a loop, in the voice of the other two:

> A run of the window whose factory publish put another sha on ``origin/<branch>``
> (``published_head``) moved the branch, whatever head the launches were read on — a product's
> F-0003, 2026-09-27: the guard parked an item on the head read before that same tick's publish,
> and an operator unparked it by hand.

Nothing else in the function changes: the window, the `unparked` boundary, the kind test, the
quota skip and the `rebase_of` escape all stand.

### 3. No hold site decides a loop from launch-time heads — the three call sites

| site | today | after |
| --- | --- | --- |
| `asf/workers/health.py:796` (`UNPUSHED`) | `main=product.main` | `head=ev.remote_sha, main=product.main` |
| `asf/workers/health.py:693` (`PUSHED_AFTER_STOP`) | `main=product.main` | `head=ev.remote_sha, main=product.main` |
| `asf/workers/health.py:804` (`EMPTY`) | neither | `head=ev.remote_sha, main=product.main` |
| `asf/tick/step_health.py:111` (`died`, `handle_dead`) | neither | `main=product.main` |
| `asf/tick/step_health.py:278` (`died`, `hold_failed_corrections`) | neither | `main=product.main` |

`ev` at each health site is the post-publish evidence (P7); an `ev.remote_sha` of `''` — a branch
origin does not hold — is falsy and skips the head test exactly as today (P2), leaving
`published_head` and `main` to carry it. The two `step_health` sites gain `main` only: they hold no
evidence, and reading origin for one would buy an `ls-remote` per dead run.

And the invariant, in `tests/test_lifecycle.py` beside the AST test already there:

```python
class EveryHoldHandsTheGuardTheTrunk(unittest.TestCase):
    """F-0217: `same_head_loop`'s two escapes are optional arguments, and a caller that passes
    neither parks on launch-time heads. `main=` is the one every caller can always give."""
```

It walks `asf/**/*.py`, collects every `ast.Call` whose func is `lifecycle.hold`, and asserts the
list of `(file, line)` whose keywords lack `main` is empty.

What each new test must assert, so the plan cannot mint a test that passes on the old code:

- `PublishedShaIsTheFactorysOwnPush` — `published_sha('', 'b733', 'published worker/X at b733')`
  is `'b733'`; a branch already on origin that moved gives the new sha; `before == after` gives
  `''`; a line containing `' refused: '` gives `''`; an empty `after` and an empty `line` give
  `''`.
- `test_a_publish_records_the_sha_it_put_on_origin` — an ended, unpushed run with commits in its
  worktree, through one `health.health(product, fix=True)`: the ledger's line for the job carries
  `published_head` equal to `git rev-parse origin/<branch>` after the pass, and the run is
  re-judged `finished`. `test_a_refused_publish_records_no_sha` — the same pass with the push
  refused (a pre-push hook that exits 1): no `published_head` key, and `publish_refused` set as
  today.
- `SameHeadLoopGuard` (extended, not replaced) — the fixture of P1, plus `published_head` on the
  third run: `hold(...)` with no `head` and no `main` returns a **held** correction with no
  `parked` key, and the same fixture with `published_head` equal to the launch head still parks
  (C4). The class's existing cases — three launches on one head park; a moved head, another kind,
  an unrecorded head or two runs do not; a `NAMING` hold is no exemption — must all still pass
  unchanged.
- `EveryHoldHandsTheGuardTheTrunk` — the AST walk asserts the offender list is `[]`, and asserts
  it found **seven** call sites, so a walk that silently matches nothing cannot pass. It matches
  `lifecycle.hold(…)` and any bare `hold` a module imported from `asf.workers.lifecycle` — today
  no module does, and `harvest/harvest.py`'s and `harvest/lane.py`'s own local `hold(job, …)`
  closures must not be counted.

## Records

- **`<state>/sessions.jsonl`** — one new key on the line health already appends for a run it
  published: `"published_head": "<the sha origin/<branch> now holds>"`. Written only when the
  publish moved origin and was not refused; never written `null`, never in `RUN_FIELDS` (C5), and
  never carried across a launch line (P9). Read by `same_head_loop` and nothing else.
- **The park that is no longer written** — no `correction.parked`, no `correction.loop_head`, no
  `operator_flagged: 1` on a run whose branch the factory moved in the pass. The item keeps the
  ordinary held correction and its round, exactly as a first hold does.
- **stdout, the tick's health step** — one line fewer of the form `parked <branch>: <kind>
  launched 3 times on <sha> and no session added a commit …`, and the ordinary `held <branch>: …
  — back to its session (round N)` in its place. The `published <branch> at <sha>` line the pass
  already prints is unchanged; it is now also a ledger fact.
- **The feeder** — one `PARKED … waits_on=operator` row fewer, and the item's own `FIX → CORRECT`
  row in its place. No write of any kind to the record: no card changes state, no Bug is filed.
  A park a human must lift is a real cost, and this card's whole effect is not to charge it
  wrongly.
