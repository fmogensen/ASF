# F-0172 — the ladder word a retired Feature leaves behind

A Feature with `removed:` or `moved_to:` is **retired**: `asf.record.core.is_retired` says so, and
the factory honours it in most places — no Tasks are minted for it, no session is launched on it,
no `## Children` or `## Backlinks` are derived onto it. Its derived `stage`, though, is not
recomputed and not cleared: `ingest` skips a retired Feature outright and *leaves its machine block
as it stands*, so whatever the ladder last said — `plan-approved`, `building 1/3` — stays on the
card, is copied verbatim into `index.json`, and is published to every reader of the index.

The first customer install reported it as a display fault. Measured in this checkout, it is two:

```
index F-0001: stage='plan-approved' state='Active' removed='superseded by F-0009'
index F-0002: stage='building 1/3'  state='Active' moved_to='other:F-0009'
```

and, for the moved card, a row in the board and a row in the **feeder**:

```
| F-0002 elsewhere | building 1/3 | — | — | — | — | — | 272d | — |

rows (moved): [('APPROVED → LAND', 'F-0001', 'WAITS ON landing: plan approved on plan/F-0001')]
```

The second is why this is not cosmetic. `asf.views.index_reader.live` — the one reader every table
and the feeder go through — drops a card on `removed:` **alone**, never on `moved_to:`. So a moved
Feature is still in the live set, and the stale `plan-approved` on its card is read as a live
instruction: the factory offers to land the plan of a Feature whose work moved to another record.

The obvious repair is the wrong one. `_ingest_fields` already treats "no stage" as *drop the key*,
and `asf/feeder/rows.py:1079` reads `f.get('stage') or 'card'` — so clearing the field turns a
display defect into a launch defect. Measured, all three cases on one fixture:

| the moved Feature's `stage` | what the feeder does with it |
| --- | --- |
| `plan-approved` (today) | `APPROVED → LAND` — offers to land a moved Feature's plan |
| absent (the naive fix) | `CARD → SPEC`, `would launch` — offers to spec it from scratch |
| `moved → other:F-0009` | `[]` — nothing |

So the stage of a retired Feature must be **a word that says it is retired**: present, honest, and
inert to every consumer of the ladder. That is what the card asks for — "no derived stage, shown as
`removed` / `moved → <target>`" — and it is also the only one of the three that is safe.

### In

- **`retired_stage(meta)` in `asf.record.core`**, beside `is_retired`: the one place the retired
  vocabulary is spelled — `'moved → <target>'` when `moved_to:` is set, else `'removed'` when
  `removed:` is set, else `None`.
- **`ingest` derives it and writes it.** `derive`'s retired branch sets `stage_val[iid]`; the write
  loop gains a **stage-only** branch for a retired Feature — `stage`, `stage_since`, `updated` and
  one `## History` line, and nothing else.
- **`build_index_data` derives it too**, so a retired card's index entry can never publish a ladder
  word whatever its machine block holds (P13: `asf index` and the record pre-commit run with no
  ingest in between).
- **One retirement rule in `index_reader`**: `live` drops a card on `removed:` *or* `moved_to:`, and
  `retired_done` keeps the retired-and-done ones aside on the same test (P12) — with a fence test
  pinning the local predicate against `asf.record.core.is_retired` over all four field
  combinations, because P14 forbids importing it and P3 is what two silent spellings cost.
- **The three docstrings that state the old rule as "removed"**: `index_reader`'s module header, the
  `Items` class docstring, and `live`'s own.

### Out

- **The derived `state:` of a retired Feature.** It stays exactly as it stands. `retired_done` keys
  on `state` being `Resolved`/`Closed` (P12), so recomputing it would move `after:` and `blockedBy`
  resolution for every retired card; and "its machine block is left as it stands" is a deliberate
  rule, narrowed here to everything *but* `stage`, not abandoned.
- **`evidence:`, `blocked:`, `blocked_by_open:`, `cost:` on a retired Feature.** Same reason. The
  stage-only write is stage-only.
- **Every type but Feature.** `stage` is derived for a Feature and for a delivery lead
  (`asf/record/ingest.py:836-859`); a Task, Story, Bug or Epic has none to be stale. A delivery
  lead is not retired by this card's rule because `derive`'s delivery loop has no retirement test
  today either — noted, and left, because the card reports a Feature and a delivery lead's ladder
  runs off a different gate.
- **`asf/tick/stale.py`'s retirement test.** It skips `typed.get('removed')` and not `moved_to:`
  (`:110`) — the same divergence as P3, in a tick alarm rather than in the index or a table. This
  card's label happens to silence the *stage* alarms for a moved Feature (`stage_limit_key` returns
  `None` for a non-ladder word, `:85-94`), but `card_undecided` and `undecided_close` still fire on
  a moved card. It is a real defect of the same class and it wants its own card; it is not the
  index and it is not a table, so it is not this one.
- **Bringing removed Features back into the tables.** They are already out and the card does not ask
  for them. After this change the removed and the moved are out together — which is what "no
  derived stage in the tables" means here (C2).
- **Any new file, command, config key, record field or schema change.** Three functions edited, one
  added, four docstrings, no migration: an existing record heals at its next `asf index` (P13) and
  its next ingest.

## The design

Four edits, in three files. One new function; no new module, file or field.

### 1. `retired_stage`, beside `is_retired` in `asf/record/core.py`

```python
def retired_stage(meta):
    """The derived ``stage`` of a retired card (:func:`is_retired`): the retirement itself, never a
    ladder word — ``'moved → <target>'`` for ``moved_to:``, else ``'removed'`` for ``removed:``,
    else None for a card that is not retired.

    A retired card runs no ladder, so the ladder's last word on it is stale the moment it is
    retired (F-0172). It is *labelled* rather than cleared because an absent ``stage`` is read as
    ``card`` by the feeder (``asf/feeder/rows.py``: ``f.get('stage') or 'card'``), which would offer
    to spec a Feature whose work moved to another record; the label matches no arm of that ladder
    and is scored like an absent stage by the board's ``stage_idx``. ``moved_to:`` wins when a card
    carries both fields — the pair is the normal shape of a move, and the target is worth saying.
    """
    m = meta or {}
    if m.get('moved_to'):
        return f"moved → {m['moved_to']}"
    if m.get('removed'):
        return 'removed'
    return None
```

### 2. `build_index_data` derives it — same file

The entry is built from `dict(typed)` updated with `machine`; one statement after that update
replaces whatever `stage` the machine block carried:

```python
def build_index_data(canonical, derived):
    items = {}
    for iid, rec in canonical.items():
        typed, machine = frontmatter.split_machine(rec['meta'])
        entry = dict(typed)
        entry.update(machine)
        if is_retired(rec['meta']):
            # a retired card publishes its retirement, never the ladder word it was left on: the
            # index is rebuilt by `asf index` and by the record pre-commit with no ingest in
            # between, so the entry cannot be left to follow the card alone (F-0172)
            entry['stage'] = retired_stage(rec['meta'])
        entry['folder'] = rec['folder']
        entry['children'] = list(derived[iid]['children'])
        entry['backlinks'] = list(derived[iid]['backlinks'])
        items[iid] = entry
    return {'generated': now_iso(), 'items': items}
```

This applies to every type, not only Features: a retired card of any type that somehow carries a
`stage` publishes the retirement instead. `retired_stage` returns a value for every retired card by
construction, so the key is never set to `None` here.

### 3. `ingest` derives it and writes it — `asf/record/ingest.py`

`retired_stage` joins the module's existing `from asf.record.core import ...` line (`:24` — the one
that already brings in `canonicalize`, `load_items`, `now_iso`; the module has no `core` alias, and
`is_retired` arrives on its own line above as `core_is_retired`). `derive`'s retired branch then
gains one line — the `retired.add` and the `continue` stay:

```python
        if is_retired(rec['meta']):
            # removed, or moved to another record: no ladder is derived for it — its stage is the
            # retirement itself (F-0172, `asf.record.core.retired_stage`), and the rest of its
            # machine block is left as it stands (the feeder skips it the same way)
            stage_val[iid] = retired_stage(rec['meta'])
            retired.add(iid)
            continue
```

and the write loop's guard becomes a branch. Today:

```python
        if type_ not in EVIDENCE_TYPES or (type_ == 'feature' and is_retired(rec['meta'])):
            continue
```

after:

```python
        if type_ not in EVIDENCE_TYPES:
            continue
        if type_ == 'feature' and is_retired(rec['meta']):
            # the retirement is the one derived field a retired Feature gets: `state`, `evidence`
            # and `blocked` stand as they were, and `closings` holds no entry for it to settle
            _typed, machine = frontmatter.split_machine(rec['meta'])
            want = stage_val.get(iid)
            if machine.get('stage') != want:
                frontmatter.merge_machine(rec['path'], {'stage': want, 'stage_since': now,
                                                        'updated': now},
                                          order=MACHINE_KEY_ORDER)
                _append_history(rec, f"- {now[:16].replace('T', ' ')} ingest: stage "
                                     f"{machine.get('stage') or 'card'} → {want} (retired)")
            continue
```

`_append_history(rec, line)` is the three-statement read/parse/`append_history_lines`/write block
the loop already runs verbatim a few lines below, lifted to a helper so it is written once — the
ordinary path calls it too, unchanged in behaviour.

Two properties of this write, both from the preconditions: `merge_machine` re-renders only the keys
whose value differs and never rebuilds the block (P8), and `stage_since` is restamped exactly once —
at the retirement — because the guard is `machine.get('stage') != want` (P18, same effect by a
narrower route).

### 4. One retirement rule in `asf/views/index_reader.py`

```python
def retired(entry):
    """True for an index entry the record retires: ``removed:`` or ``moved_to:``.

    The same rule as :func:`asf.record.core.is_retired`, spelled again here because this module is
    stdlib-only by contract and imports nothing from ``asf.record``. The two are pinned equal by
    ``tests.test_views``' fence: a card that ``is_retired`` and a card this drops must always be the
    same card. Before F-0172 they were not — this tested ``removed:`` alone, so a *moved* Feature
    stayed in the live set and the board and the feeder both read the stale ladder word on it.
    """
    return bool(entry.get('removed') or entry.get('moved_to'))


def live(raw):
    """``raw`` (``{id: card}``, retired cards included) as an :class:`Items`: the cards not retired
    (:func:`retired` — ``removed:`` or ``moved_to:``), with the retired ones that are done kept
    aside in ``retired_done`` (and any ``raw`` already carries)."""
    out = Items((k, v) for k, v in raw.items() if isinstance(v, dict) and not retired(v))
    kept = dict(getattr(raw, 'retired_done', {}))
    kept.update((k, v) for k, v in raw.items()
                if isinstance(v, dict) and retired(v) and v.get('state') in DONE_STATES)
    out.retired_done = kept
    return out
```

The module header's third paragraph and the `Items` docstring say "removed" where they now mean
retired, and are corrected to name both fields; `Items`' explanation of *why* the done ones are kept
(`landed_ids`, `after:`) is true of a moved card for the same reason and stands.

## Records

- **A retired Feature's card**: `stage` becomes the retirement label, `stage_since` and `updated`
  are restamped once at that transition, and one `## History` line is appended —
  `- <stamp> ingest: stage plan-approved → removed (retired)`. `state`, `evidence`, `blocked` and
  `cost` are not written.
- **`index.json`**: each retired card's entry carries `"stage": "removed"` or
  `"stage": "moved → <target>"` instead of the ladder word, written by `build_index_data` whether
  the rebuild came from `ingest`, from `asf index`, or from the record pre-commit's
  `stage_derived`. Every other key of the entry is unchanged, the `removed:`/`moved_to:` fields
  included — they were already copied through, and they are what the label is derived from.
- **The tables**: a moved Feature loses its row in every view that reads through `index_reader` —
  the board, the roadmap, the README's and the status table's counts — as a removed one already has
  none. No table gains a column, a row or a word.
- **The feeder**: a moved Feature stops producing rows, so `asf next` and the tick stop offering
  work on it. No row *kind* is added or removed; the population shrinks by the retired cards.
- **No event, no metric, no config key, no schema bump.** `ON_PROD_EVENT` is written only when a
  stage becomes `on-prod`, which a retired card's never does; nothing in `metrics/events` records a
  retirement, and this card does not add it.
- **Nothing is migrated.** An existing record heals in place: `asf index` fixes its `index.json`
  entries and the next ingest fixes its cards. `asf check` will name the index stale in between and
  the record pre-commit regenerates it (P13) — a rewrite, not a refusal.
- **`docs/specs/f-0172.md`** — this document, the record of the decisions above.
