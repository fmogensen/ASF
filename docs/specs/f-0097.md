# F-0097 — the status table learns to say what the factory is actually working on

`asf status` prints eight rows and not one of them is about the work. Runners, Prod, Agents,
Capacity, Ready to launch, Quota, Cron, Groom — every row is about the *machine*: how many workers
are alive, how much quota is left, whether the cron job is loaded. An operator reading that table
knows the factory is running and has no idea whether it is getting anywhere.

To answer "are Bugs being fixed, are Features moving" they run three more commands — `/asf:backlog`
for the board, `/asf:next` for the feeder's plan, `/asf:sessions` for the registry — and do the
counting in their head. Operator, 2026-09-23: *"the tick status should say something about bugs and
features"*.

Two rows fix it, and the same two counts, taken as deltas, become two lines in the per-tick digest
so an operator watching the tick log sees the work move without opening anything.

The counting itself is the only real content here: everything else is two rows and two lines. So it
is written once, in one module, as pure functions over `index.json` and the session ledger, and both
callers read it. Nothing new is written to the record.

## 1. Decisions

### 1.1 In

- `asf/views/work.py` — a new module, the one place that counts the work: `bugs(items, runs, now)`
  and `features(items, runs, now, window_days)` returning plain count objects, the two cell
  renderers `bugs_cell` / `features_cell`, and `digest(items, runs, since, now)` returning the two
  delta lines. Read-only, stdlib only, no git, no network, no subprocess.
- `asf/views/status.py` — two rows in `render`'s tuple, **Bugs** and **Features**, placed after
  `Ready to launch` and before `Quota 5h/7d`: the work first, the machine's ceilings after.
- `asf/views/index_reader.py` — `span(seconds)` split out of `age(ts)` (`age` becomes
  `span(now - ts)`), so a duration that is not an age off the wall clock renders in the same
  `25m` / `5h` / `3d` buckets as every other age in every other table.
- `asf/tick/summary.py` — a third block, `WORK since <ts>`, carrying the two delta lines, printed
  above `IN FLIGHT` in the same best-effort `run()` that already owns the window and the stamp.
- `conventions.land_window_days` (default 7) — the window the median time to land is measured over,
  read through `Conventions.get`.
- Tests in `tests/test_views.py` (the counts and the two rows) and `tests/test_tick_summary.py`
  (the two delta lines and their failure paths).
- `plugin/README.md` is untouched (its line names the table, not its rows); `asf/views/status.py`'s
  module docstring grows the two bullets it keeps for every row.

### 1.2 Out

- **Any new field on a card, and any new writer of one.** Every count in this spec is derived from
  what the record already carries. A `filed_at` / `fixed_at` / `landed_at` stamp would be a second
  writer of an item's history beside ingest, and §1.3 P2 shows the clock that exists is enough.
- **A `work` event stream, or two new keys on the `metrics/ticks` line.** The card asks for a status
  row and a digest line — both are *views*. Making the counts durable so 0.2 can chart them is a
  real want and a different card: the streams have a schema (`metrics.SCHEMAS`), a rollup and a
  backfill, and adding to them is not a side effect of printing a row. §4 records what already
  exists to reconstruct these numbers from.
- **Counting Tasks, Stories or Epics.** The card names Bugs and Features, and the board
  (`/asf:backlog`) already carries `n Closed / m` per Feature. Two rows that fit on two lines are
  the deliverable; a third row about Tasks would push the table past what a glance reads.
- **Cost, spend or quota in these rows.** `ix.usd` is right there and the Quota row is two lines
  below. Money is not "is the work moving".
- **Time to land measured from when the card was written.** The index carries no creation timestamp
  (P6) — only a `## History` prose line. Measuring from the first *session* is what the two sources
  the card names can actually answer; §1.4 records the trade and the cell says which it is.
- **Backfilling the median over ledgers older than the window.** The measure is "the last 7 days",
  computed each time it is printed; nothing is cached and nothing is migrated.
- **A `--json` mode for `asf status`.** It has none today for any row, and adding one for two rows
  would make the table's shape half-typed.

### 1.4 The choices

| Choice | Chosen | Against | Why |
|---|---|---|---|
| Where the counting lives | one new module `asf/views/work.py`, pure functions over `(items, runs, now)` | the counting inline in `status.py`, and again in `summary.py` | Two callers, two shapes (a table cell, a delta line), one definition of "open S2". Written twice they drift, and the digest's "2 fixed" stops agreeing with the row's "fixed today 2" — which is exactly the confusion the card exists to end. |
| What "fixed today" means | a Bug in `DONE_STATES` whose `stage_since` falls on **today, local** | the day the fix merged, read from the PR; the day the harvest landed the branch | P3 makes `stage_since` the exact moment the Bug's state last changed, and for a done Bug that is the moment it closed. The alternatives need `gh` (the Runners and Prod rows already pay that price; a work row should not) or a timestamp the ledger does not carry (P8). |
| Local day, not UTC day | the operator's local day, via `parse_ts(...).astimezone()` | the UTC day | "Today" in a row a person reads at 08:00 is their today. `index_reader.local_stamp` already makes the same choice for the BOARD's `generated`. |
| What "landed today" means | a Feature whose `stage` is `landed` or `on-prod` **and** whose `stage_since` is today | `stage == 'landed'` alone | A Feature that landed and deployed on the same day is at `on-prod`, and its `stage_since` is the deploy — counting only `landed` would make it vanish from the row on the day it shipped. The cell says `landed today`, and a Feature at `on-prod` did land. |
| What "in fix now" counts | distinct Bug **ids** with at least one live run in the ledger | live runs; feeder rows that *would* launch a fix | A Bug with a fix session and a correction session is one Bug being fixed, not two. `Ready to launch` is the row that already answers "what would start"; this one answers "what is under way". |
| What "time to land" is measured from | the earliest `started` of any ledger run on the Feature or its subtree | from the card's creation | P6: creation is prose in `## History`, not a field, and no count may rest on parsing it. First session → landing is what the two sources the card names can answer, it is the number an operator can act on (how long the *factory* takes), and the cell labels it so nobody reads it as calendar age. |
| A Feature with no run in the ledger | skipped from the median, and the cell prints the `n` it measured | counted as zero; counted from `stage_since` alone | A Feature the ledger never saw (migrated, hand-landed) has no measurable factory time. Counting it as zero would drag the median toward a lie; printing `n=` makes the sample size visible, so a median over one Feature is read as one Feature. |
| The median of an even sample | the mean of the two middle values | the lower middle | The ordinary definition. With `n=2` the lower middle is the faster of two, which reads as better than the factory did. |
| How a duration renders | `index_reader.span(seconds)` — `25m` / `5h` / `3d`, the buckets every other age in every table uses | `summary.age`'s finer `2d04h` | A view must not import the tick. `span` is `age`'s own body with the subtraction lifted out, so the refactor adds no vocabulary and the median reads in the same units as the Age column of the BOARD beside it. |
| A Bug with no `severity` | counted in its own `S?` clause, printed only when non-zero | counted as S3; dropped | Dropping it makes the clauses not add up to the bugs in the record — a row you cannot reconcile is worse than one that admits an untyped card. Printed only when non-zero, so a healthy record never sees it. |
| Where the rows sit in the table | after `Ready to launch`, before `Quota 5h/7d` | at the end, after `Groom` | The table reads top-down as the machine, then its plan, then its limits. The work belongs beside `Ready to launch` — what would start, then what is moving — not below the cron job. |
| What the rows say with no `index.json` | `not_configured('backlog_dir (no index.json)')`, exactly as `ready_cell` | `? (FileNotFoundError: …)` via P10 | P14 requires every row to name the key that would fill it. A missing record is a configuration fact, not a crash, and `ready_cell` already has the one spelling for it. |
| Where the digest lines go | `asf/tick/summary.py`, as a `WORK since <ts>` block above `IN FLIGHT` | a new `step_digest` step; the `tick:` line | P12: `summary` already computes "since the last tick on this clock", keeps the stamp, and is already best-effort and already printed at the end of every tick. A new step would duplicate the window and need its own entry in the manifest. |
| What "features started" counts in the digest | distinct Features with a ledger run **launched** in the window | Features that changed stage in the window | The other three deltas come from the record and lag a tick behind the work; "started" is the one the ledger answers immediately, and a launch is the unambiguous moment a Feature started moving. |
| Whether the block is suppressed when every count is zero | printed always, with its zeros | printed only when something moved | A quiet tick is information. A block that disappears is indistinguishable from a block that failed to render — and P11 means a failure prints one line, which a reader must be able to tell apart from `0 filed, 0 fixed`. |

## 2. The design

### 2.1 `asf/views/work.py` — the counts, once

```python
"""asf.views.work — what the factory is working on: Bugs and Features, counted in one place.

Two callers read this module and no third computes these numbers itself: the FACTORY STATUS
table's ``Bugs`` and ``Features`` rows (:mod:`asf.views.status`) and the tick's ``WORK since``
block (:mod:`asf.tick.summary`), which prints the same counts as deltas over the tick's window.

Everything comes from two sources and nothing else:

* the record's ``index.json``, through :mod:`asf.views.index_reader` — a Bug's ``state`` and
  ``severity``, a Feature's ``stage`` and ``decided``, and for both the one clock ingest keeps,
  ``stage_since`` (F-0097 P2: rewritten only when the tracked field changed, so for a Bug it is
  the moment of its last state change and for a Feature the moment it entered its stage);
* the session ledger, through :mod:`asf.workers.lifecycle` — what is being fixed right now, when
  a Feature's first session started, and which Features started in a window.

Read-only and stdlib only: no git, no ``gh``, no subprocess, no clock but the ``now`` it is given.
"""
```

Constants and shape:

```python
DONE = rows.DONE_STATES                      # P7: the one spelling
SEVERITIES = ('S1', 'S2', 'S3')
UNTYPED = 'S?'
SPEC_PLAN_STAGES = ('spec-draft', 'spec-review', 'spec-approved',
                    'plan-draft', 'plan-review', 'plan-approved')
LANDED_STAGES = ('landed', 'on-prod')
DEFAULT_LAND_WINDOW_DAYS = 7


@dataclasses.dataclass
class Bugs:
    open_by_sev: dict      # {'S1': 1, 'S2': 4, 'S3': 9, 'S?': 0}
    in_fix: list           # bug ids with a live run, sorted
    in_fix_s1: list        # the S1 subset — the ids the row names
    fixed_today: int
    oldest: tuple          # (id, severity, age) of the oldest open S1/S2, or ()
    total: int             # every Bug in the record: the row says so when it is 0


@dataclasses.dataclass
class Features:
    landed_today: list     # ids, newest stage_since first
    building: int
    spec_plan: int
    decided_waiting: int
    undecided: int
    median_to_land: int    # seconds, or None
    measured: int          # the sample the median rests on
    window_days: int
    total: int
```

The four predicates, each spelled once:

```python
def is_open(item):
    return item.get('state', 'New') not in DONE


def severity(bug):
    sev = bug.get('severity')
    return sev if sev in SEVERITIES else UNTYPED


def on_day(ts, now):
    """True when ``ts`` falls on ``now``'s LOCAL day. ``now`` is aware; an unparseable or
    absent ``ts`` is False, never today."""
    t = ix.parse_ts(ts)
    return bool(t) and t.astimezone().date() == now.astimezone().date()


def within(ts, since, now):
    """Half-open ``since < ts <= now``, the window ``summary.done_rows`` already uses."""
```

`bugs(items, runs, now)` walks `ix.of_type(items, 'bug')` once: `total`, the open counter by
`severity()`, `fixed_today` by `not is_open and on_day(stage_since)`, and the oldest open S1/S2 by
the smallest `parse_ts(stage_since)` (ties → lowest id, so the row is stable between ticks).
`in_fix` is the intersection of the live runs' `item` ids with the Bug ids in the index — a Bug the
index does not carry is not counted, and a Bug with two live runs is counted once.

`features(items, runs, now, window_days)` walks `ix.of_type(items, 'feature')` once for the five
counts, then measures the median:

```python
def time_to_land(feature_id, items, first_started):
    """``(seconds, landed_at)`` for one Feature, or None when the ledger never saw it.

    From the first session the ledger holds for the Feature or anything beneath it, to the moment
    it entered `landed`/`on-prod` (its `stage_since`, P2). NOT from the card's creation: the index
    carries no creation timestamp (P6), and this is the number the two sources can answer — how
    long the *factory* took, not how long the card sat.
    """
```

`first_started` is built in one pass over the ledger: `{item id: earliest started}`, folded up to
the Feature by the run's own `feature` field and, failing that, by `ix.epic_of`-style parent walk
through the index, so a Task's run counts for its Feature. Features with no entry are skipped;
`measured` is how many were not.

`digest(items, runs, since, now)` returns the two strings, from the same walks:

```python
def digest(items, runs, since, now):
    """``('bugs      +1 filed, 2 fixed', 'features  1 landed (F-0095), 3 started')``."""
```

- *filed* — a Bug with `state == 'New'` whose `stage_since` is in the window. P2 and P4: a card
  ingest has not moved still carries the `stage_since` it was written with, so a Bug filed this
  tick dates itself, and one ingest has since moved is no longer `New`.
- *fixed* — a Bug in `DONE` whose `stage_since` is in the window.
- *landed* — a Feature at a `LANDED_STAGES` stage whose `stage_since` is in the window; the newest
  id is named in parentheses.
- *started* — distinct Features over ledger runs whose `started` is in the window.

### 2.2 `asf/views/work.py` — the two cells

```python
def bugs_cell(root, product, now=None):
    """``open S1 1 · S2 4 · S3 9 · in fix 2 (S1 B-0091) · fixed today 3 · oldest open S1/S2 B-0091 S1 4d``"""
```

Clause by clause, always in this order, nothing dropped but the two noted:

| Clause | Always | Empty form |
|---|---|---|
| `open S1 n · S2 n · S3 n` | yes | zeros are printed |
| `· S? n` | only when non-zero | absent |
| `in fix n` | yes | `in fix 0` |
| ` (S1 B-0091 B-0093)` | only when an S1 is being fixed | absent |
| `fixed today n` | yes | `fixed today 0` |
| `oldest open S1/S2 <id> <sev> <age>` | yes | `oldest open S1/S2 none` |

With no Bugs at all in the record the whole cell is `no Bugs in the record`. With no `index.json`
it is `not_configured('backlog_dir (no index.json)')` — P14, the same string `ready_cell` uses.

```python
def features_cell(root, product, now=None):
    """``landed today 2 (F-0095) · building 3 · spec/plan 4 · decided, waiting 6 · undecided 11 ·
    median to land 3d (7d, n=5)``"""
```

| Clause | Always | Empty form |
|---|---|---|
| `landed today n` | yes | `landed today 0` |
| ` (F-0095)` — the newest of them | only when `n > 0` | absent |
| `building n` | yes | `building 0` |
| `spec/plan n` | yes | `spec/plan 0` |
| `decided, waiting n` | yes | `decided, waiting 0` |
| `undecided n` | yes | `undecided 0` |
| `median to land <span> (<w>d, n=<measured>)` | yes | `median to land unknown (7d, n=0)` |

With no Features at all: `no Features in the record`.

Both cells load the index through `ix.load` and the ledger through `lifecycle.runs`, each once, and
`status.render`'s per-row guard (P10) covers anything else that goes wrong.

### 2.3 `asf/views/status.py` — two rows

The docstring grows two bullets in the list it keeps for every row:

```
* **Bugs** — the work itself, from the record's ``index.json`` and the session ledger
  (``asf.views.work``): open by severity, in fix now, fixed today, and the oldest open S1/S2;
* **Features** — the same two sources: landed today, building, spec/plan in flight, decided and
  waiting, undecided, and the median time to land over ``conventions.land_window_days``;
```

and `render`'s tuple grows two entries, between `Ready to launch` and `Quota 5h/7d`:

```python
('Ready to launch', lambda: ready_cell(root, product)),
('Bugs', lambda: work.bugs_cell(root, product)),
('Features', lambda: work.features_cell(root, product)),
('Quota 5h/7d', lambda: quota_cell(cfg)),
```

Nothing else in `status.py` changes. The import is local to the lambdas' module scope, as
`ready_cell`'s already is.

### 2.4 `asf/views/index_reader.py` — `span` under `age`

```python
def span(seconds):
    """A duration in the tables' buckets: 25m, 5h, 3d. Negative is clamped to 0."""
    s = max(seconds, 0)
    return f"{int(s // 60)}m" if s < 3600 else f"{int(s // 3600)}h" if s < 172800 else f"{int(s // 86400)}d"


def age(ts):
    """``stage_since`` as a short age: 25m, 5h, 3d."""
    t = parse_ts(ts)
    return span((dt.datetime.now(dt.timezone.utc) - t).total_seconds()) if t else '—'
```

Byte-identical behaviour for `age`; the median gets the same buckets without importing the tick.

### 2.5 `asf/tick/summary.py` — the `WORK since` block

`render` takes one more argument and prints one more block, first:

```python
def render(inflight, done, titles_by_item, since, now, first, work_lines=()):
    ...
    for title, columns, records, suffix in (...):
```

becomes, ahead of that loop:

```python
lines = []
if work_lines:
    lines.append('')
    lines.append(f'WORK since {since}' + (' (first tick on this clock)' if first else ''))
    lines.extend(work_lines)
```

so the tick ends with:

```
WORK since 2026-09-24T09:00:00Z
bugs      +1 filed, 2 fixed
features  1 landed (F-0095), 3 started

IN FLIGHT — 2 sessions
job            item    kind  …

DONE since 2026-09-24T09:00:00Z — 1 session
job            item    kind  …
```

`run()` builds the lines beside the rows it already builds, from the record clone it already reads
for the titles:

```python
def work_lines(product, since, now):
    """The two delta lines, or () when the record clone or the ledger cannot be read — the block
    is then absent and the two session tables are unaffected."""
    try:
        items, _generated = index_reader.load(shadow.record_dir(product))
        runs = lifecycle.runs(pool.sessions_path(product))
    except (OSError, ValueError, KeyError, TypeError):
        return ()
    return work.digest(items, runs, since, now)
```

The same narrow catch `titles()` already uses, for the same reason: an unreadable record must cost
the block, not the tick (P11). Everything outside it is still inside `run`'s own guard.

### 2.6 Config

```yaml
conventions:
  land_window_days: 7    # the window `asf status`'s Features row measures time-to-land over
```

One key, one default (`DEFAULT_LAND_WINDOW_DAYS = 7` in `asf/conventions.py` with the rest), read as
`product.conventions.get('land_window_days')` and nowhere spelled a second time (P13). The window is
printed in the cell, so a product that changes it is not misread.

## 3. Acceptance tests

All run from the repo root.

### 3.1 The counts, against a hand-built index and ledger

```bash
python3 -m unittest tests.test_views.WorkCountsTests -v
```

Covers, over an index carrying four Bugs (S1 open, S2 open, S3 open, S2 Closed with `stage_since`
today) and five Features (one `card` decided, one `card` undecided, one `spec-review`, one
`building`, one `landed` today) plus a ledger with two live runs and one ended:

- `open_by_sev` is `{'S1': 1, 'S2': 1, 'S3': 1, 'S?': 0}` — the Closed S2 is not open, and a
  `removed` Bug in the raw index is not in `items` at all (P1);
- a Bug with no `severity` lands in `S?` and is not silently an S3;
- `fixed_today` counts the Closed Bug whose `stage_since` is today and not the one closed
  yesterday, with `now` injected — the boundary is the **local** midnight, asserted from both sides
  with a fixed `now` and a `stage_since` one minute either side of it;
- `in_fix` holds each Bug id once for a Bug with two live runs, excludes an ended run, and excludes
  a live run whose `item` is not a Bug in the index; `in_fix_s1` is the S1 subset;
- `oldest` is the open S1/S2 with the earliest `stage_since`, and ties break to the lower id;
- `features`: `building`, `spec_plan` (all six stage words, each asserted), `decided_waiting`
  (`stage == 'card'` and `decided is True`), `undecided` (`decided` absent **and** `decided: false`),
  and `landed_today` for a Feature at `landed` *and* one at `on-prod` today;
- `median_to_land`: three Features landed in the window with ledger runs 1d, 3d and 6d before their
  `stage_since` → `3d` and `measured == 3`; a fourth with no run is skipped and `measured` stays 3;
  an even sample takes the mean of the two middles; a Feature landed 9 days ago is outside the
  7-day window; a Task's run counts for its parent Feature; with no measurable Feature the median
  is `None`;
- every function is pure: called twice with the same arguments it returns the same thing, and it
  opens no subprocess (asserted by patching `subprocess.run` to raise).

### 3.2 The two rows in the table

```bash
python3 -m unittest tests.test_views.StatusWorkRows -v
```

Covers, through `status.render` and the existing `rows()` helper that parses the markdown table:

- `rows['Bugs']` is exactly
  `open S1 1 · S2 1 · S3 1 · in fix 1 (S1 B-0091) · fixed today 1 · oldest open S1/S2 B-0091 S1 3d`
  for the §3.1 fixture, and `rows['Features']` is exactly
  `landed today 1 (F-0095) · building 1 · spec/plan 1 · decided, waiting 1 · undecided 1 · median to land 3d (7d, n=3)`;
- the `S?` clause is absent for that fixture and present as `· S? 2` once two untyped Bugs are
  added;
- the `(S1 …)` parenthetical is absent when only an S2 is in fix;
- `oldest open S1/S2 none` when every open Bug is S3;
- `median to land unknown (7d, n=0)` when no Feature landed in the window;
- an index with no Bugs gives `no Bugs in the record`, one with no Features `no Features in the
  record` — and neither is a bare `—`;
- the row order is `… Ready to launch, Bugs, Features, Quota 5h/7d …`, asserted on the rendered
  table's line order;
- `land_window_days: 14` in the product's conventions changes both the window and the `(14d, …)`
  the cell prints.

### 3.3 The rows survive what they read

```bash
python3 -m unittest tests.test_views.StatusViewTests.test_unconfigured_rows_name_their_key_never_a_bare_dash \
                    tests.test_views.StatusViewTests.test_no_index_names_the_backlog \
                    tests.test_views.WorkFailureTests -v
```

The two existing tests are the regression: every row, the two new ones included, names its key and
none is a bare `—` (P14). `WorkFailureTests` adds: no `index.json` → both rows are
`— (not configured: backlog_dir (no index.json))`; a *corrupt* `index.json` → both rows are
`? (JSONDecodeError: …)` through `render`'s guard and the other seven rows are still in the table
(P10); an unreadable ledger → the rows still render, with `in fix 0` and the median measured over
nothing; a Bug whose `stage_since` is absent or unparseable is open, is not `fixed today`, and is
not the oldest.

### 3.4 The digest's two lines

```bash
python3 -m unittest tests.test_tick_summary.WorkDigestTests -v
```

Covers, over the existing `SummaryTestCase` fixture:

- the block's title is `WORK since <the same since the DONE block names>`, and it is printed
  **above** `IN FLIGHT`;
- `bugs      +1 filed, 2 fixed` for a Bug created inside the window (`New`, `stage_since` in it) and
  two Closed in it; a Bug filed *before* the window is not counted, nor is one that is no longer
  `New`;
- `features  1 landed (F-0095), 3 started` — one Feature at `landed` in the window (named), three
  distinct Features with a run launched in it; a fourth run on a Feature already counted does not
  make it four, and a run launched before the window is not counted;
- the window is half-open on both counts: `since` exclusive, `now` inclusive, asserted at both
  edges;
- a quiet tick still prints the block, as `bugs      +0 filed, 0 fixed` /
  `features  0 landed, 0 started`;
- `first` (no stamp — the 24h fallback window) is marked on this block as it is on `DONE`;
- an unreadable record clone and an unreadable ledger each drop the block and leave `IN FLIGHT` and
  `DONE` intact; `tests.test_tick_summary.FailureTests` is the regression that a failure past that
  is still one line and the stamp is still written.

## 4. Records

**Files.** None. Nothing in this spec writes to the record, to a card, or to the state directory.
That is §1.2's deliberate refusal: every number here is derived from what ingest and the ledger
already wrote, and a second writer of an item's history is how a record stops being one.

**Rows.** Two, in the FACTORY STATUS table, between `Ready to launch` and `Quota 5h/7d`:

```
| Bugs | open S1 1 · S2 4 · S3 9 · in fix 2 (S1 B-0091) · fixed today 3 · oldest open S1/S2 B-0091 S1 4d |
| Features | landed today 2 (F-0095) · building 3 · spec/plan 4 · decided, waiting 6 · undecided 11 · median to land 3d (7d, n=5) |
```

**Printed.** Per tick, one block of two lines at the head of the summary:

```
WORK since 2026-09-24T09:00:00Z
bugs      +1 filed, 2 fixed
features  1 landed (F-0095), 3 started
```

**Events.** None. There is no `work` event and no new key on the `metrics/ticks` line — §1.2. What
0.2 reads back instead is what is already written: `stage_since` on every card is the moment its
state or stage last changed (P2), so the same counts are reconstructible for any past day from the
record's own git history, and `metrics/sessions` plus the ledger already carry every launch and
every landing the "started" and "time to land" numbers rest on.

## Stories

- S: The work is counted in one module — `asf/views/work.py`, pure functions over `index.json` and the session ledger, with one spelling of open, fixed, landed and started — acceptance: `tests.test_views.WorkCountsTests` (§3.1)
- S: `asf status` grows a Bugs row: open by severity, in fix now with the S1 ids, fixed today, and the oldest open S1/S2 — acceptance: `tests.test_views.StatusWorkRows` for the Bugs cell and its empty forms (§3.2)
- S: `asf status` grows a Features row: landed today with the latest id, building, spec/plan in flight, decided and waiting, undecided, and the median time to land over `land_window_days` — acceptance: `tests.test_views.StatusWorkRows` for the Features cell and the `land_window_days: 14` case (§3.2)
- S: The per-tick digest carries the same two counts as deltas since the last tick, in a `WORK since` block above the session tables — acceptance: `tests.test_tick_summary.WorkDigestTests` (§3.4)
- S: Neither row nor the block can cost its reader anything: a missing index names the key, a corrupt one is one cell, an unreadable ledger drops only the block — acceptance: `tests.test_views.WorkFailureTests` with the two existing status tests and `tests.test_tick_summary.FailureTests` as the regression (§3.3, §3.4)
