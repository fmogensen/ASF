# F-0292 — half the watchdog is in the package, and the half that answers an OOM kill is not

`asf ci stall-watch` (`asf/ci_stall.py`, F-0286) was written to replace the operator's host
script: it reads every pool box's per-slot heartbeat files over one ssh, judges a busy slot
silent past its job's *measured* p95, cancels the run the queue's one way, claims the cancel in
`ci-cancels.json` and re-runs its failed jobs once. All of that is landed and green.

The script has a second half the module never got. It watches the box's own OOM kills, maps each
kill to the runner slot that was running when the kernel fired, and re-runs that run's failed
jobs once. Nothing in the package watches an OOM kill: `grep -ci oom asf/ci_stall.py` is `0`
(P1). So the operator cannot unload the host unit — doing it would trade a stall watch that
claims and re-runs for no OOM recovery at all — and two watchdogs stay installed on the box,
which is the state the stall half degrades to `report` for (`LEGACY_QUIET_S`, "one watcher acts
at a time"): the script holds the timer, so the *landed* stall watch does not act either.

This feature ports that half, and it ports it better than the script could. The script ran
outside the package, so it could not know that the factory already re-runs a lost-runner red once
(`asf.flake.infra_rerun`, P7) — an OOM kill that takes the runner with it is exactly that red.
Inside the package, the OOM half can read that claim and stand down, so the port adds OOM
recovery without adding a second re-run of one run.

### In

1. **Every box's OOM kills are read in the same ssh, and each is mapped to the slot and job that
   was running.** The remote command gains a marked second section — whether the kernel log can
   be read at all, then its OOM lines inside the window — and the watch keeps a `slots` block of
   what each busy slot was last seen running, which is the only thing that can tie a kernel line
   to a job (P3, P4).
2. **A mapped kill's failed run is re-run once, in `act`.** The kill is claimed in this watch's
   own file before anything is done, and the claim is finished by `_advance`: once the run
   completes, its failed jobs are re-run once and the re-run is claimed `infra` in
   `ci-cancels.json` with `by: oom-watch`. A run that survived the kill is not re-run; a run
   another path already answered (P7) is not re-run; a kill the watch cannot map is reported and
   acted on by nothing.
3. **The OOM half is visible and tunable, so the script's OOM half has nothing left to do.** One
   summary line per pass, one new config key `ci.stall_watch.oom_window_s` documented beside the
   other five, and a module docstring that says what the operator's remaining step is.

### Out

- **The stall judgement.** `judge`, `measure`, `_p95`, `job_max`, `refresh_max` and all five
  existing thresholds are untouched. An OOM kill is a fact off the kernel, not a judgement.
- **Cancelling anything.** An OOM kill has already ended the job; there is nothing to cancel, so
  the OOM half never calls `ci_queue._cancel_run` and `cancels` keeps its one meaning (C3).
- **A new cancel cause.** `ci_cancels.CAUSES` and `GROUPS` are unchanged (C4) — no published
  number moves.
- **A doctor row.** `asf doctor` has no stall-watch row at all today (P10) and adding one is
  F-0286's third item, specced there with its own staleness key. This feature writes its findings
  as pass lines and as claims in `ci-stall.json`, in the shape that row will read (C9).
- **The box side.** No new file on a box, no change to the box-side heartbeat timer, no second
  ssh, and nothing installed: the OOM read is a read of what the kernel already logged.
- **The host script, its timer and the host unit.** The product still never writes, installs,
  unloads or deletes any of them (F-0286 C7). This feature removes the *reason* the operator
  cannot unload the unit; the unload itself stays their one step, and `LEGACY_QUIET_S` keeps
  today's yield exactly while both are installed (C7).
- **A second mode surface.** No `oom-mode` file, no `--oom-only`, no `--no-oom` (C6): the one
  `mode` file governs both halves and `--apply` stays the whole CLI surface.
- **Memory pressure, limits and prevention.** How much memory a job may use, which labels a box
  may carry and when a box should be taken off a label are F-0255's subject, not this card's.
- **`docs/design` and `docs/KNOWN-ISSUES.md`.** This session creates `docs/specs/f-0292.md` and
  nothing else.

## The design

All of it is in **`asf/ci_stall.py`**, plus one line in `asf/config_keys.py`, one in
`docs/config.example.yaml`, the `fetch_fn` fake in `tests/test_ci_stall.py`, and a new
`tests/test_ci_stall_oom.py`.

### 1. The read: one ssh, two sections

The remote command is named in pieces, so the OOM half is legible and the window is the tunable's:

```python
#: how far back each box's kernel log is read, and the oldest kill this watch answers
OOM_WINDOW_S = 30 * 60
#: at most this many OOM lines are read off one box in one pass
OOM_LINES = 40
#: a busy slot's observation is kept this long, so a kill can still be mapped to its job
SLOT_RECALL_S = 2 * 60 * 60
#: the line that separates the heartbeat files from the kernel's answer in one box's payload
MARKER = '--- asf-oom ---'

REMOTE_BEATS = ('for f in /var/lib/ci-heartbeat/*.json; do [ -f "$f" ] && cat "$f" && echo; '
                'done')
REMOTE_OOM = ("journalctl -k -n 0 >/dev/null 2>&1 && echo 'journal ok' || echo 'journal "
              "unreadable'; journalctl -k --since '{since} seconds ago' -o short-unix "
              "--no-pager 2>/dev/null | grep -iE 'oom-kill|out of memory: kill' | tail -{n}")


def remote(window_s=None, lines=OOM_LINES):
    """The one command this watch runs on a box: the heartbeat files, the marker, then whether
    the kernel log can be read and every OOM line inside the window."""
    return (f"{REMOTE_BEATS}; echo '{MARKER}'; "
            + REMOTE_OOM.format(since=int(window_s or tunable('OOM_WINDOW_S')), n=int(lines))
            + '; true')
```

`-o short-unix` is chosen so a stamp is epoch seconds and needs no timezone (the boxes' journals
are not all one zone); `journalctl -k -n 0` answers *can this account read the kernel log at all*,
which a grep over an empty result cannot — a box whose journal is unreadable would otherwise read
as a box with no OOM kills for ever.

`fetch` splits the payload and returns one more value:

```python
class Journal(NamedTuple):
    readable: bool          # the box said 'journal ok'
    lines: tuple            # the OOM lines as read, oldest first


def fetch(box, target, window_s=None):
    """``(heartbeats, journal, None)`` off one box in one ssh, or ``(None, None, why)``."""
```

`TUNABLES` gains `'OOM_WINDOW_S': 'ci.stall_watch.oom_window_s'`; `asf/config_keys.py` gains
`'ci.stall_watch.oom_window_s': (NUM, 1, None)` beside the other five; and
`docs/config.example.yaml` gains one commented line at `:509`'s block (P11):

```yaml
#     oom_window_s: 1800      # how far back a box's kernel log is read for OOM kills
```

A box that answers with `journal unreadable` is one `ALARM` per pass — the one state in which
this watch silently loses OOM recovery, so it is never silent:

```
ci stall: ALARM box box-1 — the kernel log is unreadable, OOM kills are not seen
```

### 2. The parse and the mapping

Two pure functions and one observation block, all testable without ssh, `gh` or a clock:

```python
class Kill(NamedTuple):
    at: float               # epoch seconds, off journalctl's short-unix stamp
    task: str               # the killed process's name, or ''
    pid: str                # its pid, or ''
    cgroup: str             # the task's cgroup, or ''
    line: str               # the line as read, trimmed: the record's own evidence


def kills(journal, now, window_s=None):
    """Every OOM kill in ``journal``, oldest first, inside the window — both kernel shapes:
    the cgroup kill (``oom-kill:…,task_memcg=…,task=…,pid=…``) and the global one
    (``Out of memory: Killed process <pid> (<comm>)``). A line whose stamp or shape cannot be
    read is skipped, never guessed at."""


def observe(data, box, hb, now):
    """Record what a busy slot is running, under ``slots[f'{box}/{runner}']``: the job, the run
    and job ids, the repo, the job's start, and when this watch first and last saw it. The one
    memory a kill can be mapped against (P3, P4)."""


def map_kill(data, box, kill, now):
    """``(key, obs, how)`` — the slot a kill belongs to:

    * ``'cgroup'`` — the kill's cgroup names one of this box's observed runners;
    * ``'window'`` — exactly one observed slot of this box has
      ``started <= kill.at <= last_seen + HEARTBEAT_STALE_S``;

    else ``(None, None, why)``: ``'no slot observed'``, ``'<n> slots match'``, or
    ``'before this watch saw the box'`` when no observation of that box is older than the kill."""
```

`observe` is called for every busy heartbeat whose beat is fresh — **before** the repo filter
(P5), so a kill that belongs to another repo's job maps to a slot that says so and is reported
rather than counted as unmapped. `slots` is pruned at `SLOT_RECALL_S` on every pass, and keyed
`box/runner` rather than by runner alone (P3) so two boxes can never shadow one another.

The `data['cpu']` block keeps its own shape and its own job: it answers *is this job burning
CPU*, per pass. Nothing about it changes.

### 3. The act: one re-run per kill, and one per run

Inside `watch`, after the heartbeat loop for a box (so this pass's observations are already
recorded), each kill is printed and, in `act`, claimed:

```python
for k in kills(journal, now):
    key, obs, why = map_kill(data, box, k, now)
    ...
```

- **mapped** →
  `ci stall: OOM kill on box-1 at 2026-10-08T07:31:02Z — task pytest (pid 12345) → gate-tests on
  <runner>, run 37670494471 (by cgroup); mode act`
- **not mapped, and the watch was watching the box then** →
  `ci stall: ALARM OOM kill on box-1 at … — task pytest; not mapped (2 slots match)`
- **not mapped, and it predates every observation of the box** →
  `ci stall: OOM kill on box-1 at … — before this watch saw the box; nothing to map`
- **mapped to another repo's job** →
  `ci stall: OOM kill on box-1 at … → <other slug>'s job on <runner>; not this product's run`

In `act`, with a `run_id` and this product's repo, the kill becomes a claim in the same `claims`
dict the stall half uses, under a key that is the kill's identity:

```python
ckey = f"oom:{box}:{int(k.at)}:{k.pid or k.task or '?'}"
data['claims'][ckey] = {'kind': 'oom', 'run': obs['run_id'], 'job': obs['job'],
                        'runner': obs['runner'], 'box': box, 'oom_at': k.at, 'task': k.task,
                        'how': how, 'claimed_at': now, 'state': 'oom'}
save(product, data)                     # claim before acting, as the stall half does
```

Three guards, in this order, each a `continue` that claims nothing:

1. **the same kill** — `ckey in data['claims']`: a kill stays in the journal window for 30
   minutes and is read by every pass inside it;
2. **the same run** — any claim with this `run` whose state is `cancelled`, `rerun` or `oom`:
   one re-run per run, whichever half asked for it;
3. **another path's claim** — `ci_cancels.claims(env.state_dir(product.name))` holds this run
   with a `HONOURED` cause (C5, P7). The claim is written as `state: 'oom-answered'` with the
   other cause named, so the kill is not lost, and one line says so:
   `ci stall: OOM kill on box-1 → run 37670494471, already answered as infra — nothing re-run`.

A claim with no `kind` is a stall claim, so nothing about the landed claims changes.

`_advance` gains the `oom` state beside `cancelled`, and one read:

```python
def _run_state(src, product, run):
    """``(status, conclusion)`` of one run — one ``gh run view --json status,conclusion``."""
```

- `state == 'cancelled'` (the stall half) → today's path exactly: `completed` → `run rerun
  --failed` once → `rerun` / `rerun-failed`; `GIVE_UP_S` after the cancel → `gave-up`;
- `state == 'oom'` → the run must have *failed*, because an OOM kill is not this watch's doing:
  - not `completed` → wait; `GIVE_UP_S` after the kill → `gave-up`;
  - `completed` with conclusion `success` → `oom-survived`, nothing re-run, one line:
    `ci stall: run 37670494471 survived the OOM kill on box-1 — nothing re-run`;
  - `completed` otherwise → guard 3 again (another path may have claimed it while we waited),
    then `run rerun <id> --failed`, `claim_cancel(..., 'infra', by='oom-watch', box=…,
    runner=…, task=…, oom_at=…)`, `state='rerun'`, one line:
    `ci stall: re-ran the failed jobs of run 37670494471 after the OOM kill on box-1
    (<runner>)`.

The pass closes with one summary line whenever at least one box's journal was read, so a pass
that saw nothing still says the half ran:

```
ci stall: oom 1 kill(s), 1 mapped, 1 owed a re-run (window 1800s)
```

`watch` keeps returning `(stalls, cancels)` — the OOM counts are printed, not returned, so no
caller and no landed assertion changes shape (C8 keeps the diff to the two lines F-0286 also
touches).

### What it looks like when it is there

The module's docstring gains the OOM half beside the stall half, and the sentence the operator
needs: both halves act on the one `mode`, both yield to the script while it still writes
`claims.json`, and once the host timer is theirs alone the script's OOM half has nothing left
that the package does not do. `asf ci stall-watch --apply` on a cut-over host answers a box OOM
kill the way the script did — mapped to its slot and job, re-run once — and, unlike the script,
says so in the ledger (`infra`, `by: oom-watch`) and stands down when the factory already
re-ran that run.

## Acceptance tests

### S-75454: Every box's OOM kills are read in one ssh and mapped to the slot and job

- [ ] `remote()` is one command carrying the heartbeat loop, the `MARKER` line, the

      read capped by `tail -40`; `remote(window_s=60)` carries `'60 seconds ago'`, and
      `ci.stall_watch.oom_window_s: 60` in the config does the same through `tunable`
- [ ] `fetch` on a payload of two heartbeat objects, the marker, `journal ok` and three OOM lines
      returns the two heartbeats, `Journal(readable=True, lines=(…3…))` and `None`
- [ ] a payload with no marker at all (a box that has not been re-read yet) returns the
      heartbeats, `Journal(False, ())` and `None` — never an exception
- [ ] `journal unreadable` → `Journal(readable=False, …)`, and the pass prints one
      `ALARM box box-1 — the kernel log is unreadable` line and claims nothing
- [ ] an ssh failure still returns `(None, None, why)` and is still one `ALARM box … unreachable`

- [ ] `kills` reads the cgroup shape (`oom-kill:constraint=…,task_memcg=/…/<runner>.service,
      task=pytest,pid=12345`) into `Kill(at, task='pytest', pid='12345', cgroup=…)` and the

- [ ] `map_kill` prefers the cgroup: a kill whose cgroup names `r-2` maps to `box-1/r-2` with

- [ ] `map_kill` falls back to the window: one observed slot with

## Records

What the change writes down, and where:

| record | written by | shape |
| --- | --- | --- |
| the slot observation | `ci_stall.observe` → `<state>/ci-stall.json` | `slots[f'{box}/{runner}'] = {'job', 'run_id', 'job_id', 'repo', 'started_at', 'first_seen', 'last_seen'}` — every busy, fresh beat, every pass, either mode; pruned at `SLOT_RECALL_S` |
| the OOM claim | `ci_stall.watch` (before the re-run) and `_advance` (after it) → the same file | `claims[f'oom:{box}:{at}:{pid}'] = {'kind': 'oom', 'run', 'job', 'runner', 'box', 'oom_at', 'task', 'how', 'claimed_at', 'state', 'rerun_at'}`; `state` ∈ `oom`, `rerun`, `rerun-failed`, `oom-survived`, `oom-answered`, `gave-up`. A claim with no `kind` is a stall claim, unchanged |
| the re-run's cause | `ci_queue.claim_cancel` → `<state>/ci-cancels.json` | `{'cause': 'infra', 'by': 'oom-watch', 'box', 'runner', 'task', 'oom_at', 'at'}` — an existing cause, honoured, in `GROUPS['sound']` (C4) |
| the pass's lines | `watch`'s `out` → the tick log, or the operator's terminal | `OOM kill on <box> at <iso> — … → <job> on <runner>, run <id> (by cgroup\|window); mode <m>`, `ALARM OOM kill … not mapped (<why>)`, `ALARM box <box> — the kernel log is unreadable …`, `run <id> survived the OOM kill …`, `… already answered as <cause> — nothing re-run`, `re-ran the failed jobs of run <id> after the OOM kill on <box> (<runner>)`, and one `oom <k> kill(s), <m> mapped, <r> owed a re-run` summary |
| the config key | `docs/config.example.yaml` + `config_keys.KEYS` | `ci.stall_watch.oom_window_s`, `(NUM, 1, None)`, default 1800 |

Nothing new is written to origin: no ref, no branch, no commit, no PR comment. The `gh` calls
this feature adds are one `run view --json status,conclusion` per owed claim per pass and one
`run rerun <id> --failed` per OOM-failed run — never a cancel, and never a second re-run of a run
this factory already re-ran.
