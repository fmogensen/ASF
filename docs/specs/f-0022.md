# F-0022 — The preamble: every brief opens with facts the runner already knows

Epic: E-0001 — ASF 0.1 — a working factory. Branch: `spec/F-0022`.

The preamble already exists as text. `asf/briefs/preamble.py` renders it, `asf/briefs/build.py`
puts it under the `Backlog item:` line of every brief, and `tests/test_briefs.py` holds a golden
brief per kind. What does not exist is the other half of the bargain: **the runner never hands it
the facts.** `preamble.collect` reads `head`, `branch_exists`, `files`, `tests` and `last_report`
off a `repo_facts` dict (`asf/briefs/preamble.py:245-250`); the only caller that fills one,
`asf.tick.step_wave.repo_facts` (`asf/tick/step_wave.py:113-122`), returns
`{branch, pushed, remote_sha, last_commit}`. Not one key matches. `asf brief` passes no facts at
all (`asf/briefs/build.py:282`).

So every brief this factory has launched opens with unknowns. The brief that asked for *this
spec* is the evidence:

```
Branch: `spec/F-0022` (exists: (not known here))
Head: (not known here)
Spec: not in the record — its place is `docs/specs/f-0022.md`
```

The head is one `git log -1` away in a clone the tick already has open. Whether the branch is on
origin was fetched by `ls-remote` in the same function and thrown away. The sizes of the documents
the session is about to open are a file read. The last report for the item sits in
`~/.ASF/state/<product>/sessions.jsonl` and its job log. Every one of them is a fact the runner
holds, and every one of them is printed as `(not known here)` — which is an instruction to go and
find it. That is the 93 % this card exists to remove (`docs/CONSTITUTION.md:57-59`,
`docs/research/prior-art-prototype.md:49`).

After this change the facts are gathered in one place (`asf/briefs/facts.py`), the keys are a
declared contract a test holds both sides of, every brief carries the branch state, the document
and test sizes and the previous session's report — and the cost of a session is measured, because
`in_tokens` lands on the `sessions` stream and `asf tokens` prints the before and the after.

## Decisions

### In

- `asf/briefs/facts.py` (new): the one place in `asf.briefs` that runs git and reads the session
  ledger. It returns exactly the keys `preamble.collect` reads, named by
  `preamble.REPO_FACT_KEYS`.
- Both callers use it: `step_wave.run` (the launch path) and `build.cmd_brief` (`asf brief`), so
  what an operator previews is what a session is handed.
- The five facts, filled: `head` (the commit the work starts from, with the ref it was read at),
  `branch_exists`, `files` (line counts for the documents and tests the brief names),
  `tests` (the test files that already exist inside the item's footprint), `last_report` (the
  typed REPORT of the newest ended session for this item).
- `preamble.wanted_paths(facts)`: the pure function that says which paths' sizes matter, so the
  gatherer measures what the brief will actually print and nothing else.
- The `Tests named by the card:` line carries each test's size, or `(new)` when the path is not
  in the tree — a session no longer opens a file to find out whether it exists.
- `conventions.preamble_max_files` (default 12): the ceiling on measured paths, so one card with
  a large footprint cannot turn a launch into a hundred file reads.
- A contract test: `set(facts.repo_facts(...)) == set(preamble.REPO_FACT_KEYS)`. The defect this
  card closes was two dicts drifting apart in silence; nothing but a test stops it recurring.
- A guard that the preamble is code: `asf/briefs/preamble.py` and `asf/briefs/facts.py` may not
  import a model client, and `preamble.build` is deterministic — same inputs, byte-identical text,
  twice.
- The measurement: `in_tokens` and `turns` on the `sessions` stream, filled by
  `metrics.session_event` from the job log's result record, and so backfilled for every session
  whose log still exists.
- `asf tokens`: the TOKENS table — median input tokens and turns per session, per brief kind,
  before and after a split day, with the delta. This is the *reading*; putting the number on the
  daily scorecard beside cost is F-0028's card (`docs/CONSTITUTION.md:69-70`).
- The `launch` event gains `preamble_lines` and `facts_unknown`: how long the preamble was, and
  how many of its facts still printed as unknown. `facts_unknown: 0` is this card's acceptance,
  measured on every launch rather than once.

### Out

- **Changing what the preamble says.** Its sections, order, cap and trim order stand
  (`asf/briefs/preamble.py:285-332`). This card fills the facts and sizes the test line; it does
  not redesign the text. The golden briefs change because the facts arrive, not because the shape
  moved.
- **The interrogator.** A rule that bounces a brief which asks a session to find something is
  F-0023 (`docs/CONSTITUTION.md:46-47`). Here the guard is the `facts_unknown` counter and the
  contract test, not a rule engine.
- **The scorecard row.** `scorecard_rows` (`asf/metrics/metrics.py:405`) is untouched. F-0028
  owns the row; this card owns the fact it will read.
- **Fetching.** The gatherer runs one `ls-remote` per launching row, as the tick does today, and
  reads everything else from refs the clone already has. A brief is never worth a `git fetch` of
  the whole repository, and a launch must not wait on one.
- **Reading the card's linked documents into the brief.** The preamble names `docs/specs/x.md`
  and its line count; it does not paste it. Pasting a plan's task bodies is exactly what R-0061
  forbids, and it would spend the tokens this card saves.
- **A per-session token budget or a refusal on a big brief.** Recording the number comes first.
  Acting on it is a later card.
- **Changing the runtime's log format.** `in_tokens` is read out of the result record the runtime
  already writes (`asf/workers/runtime.py:126-151`); nothing new is asked of the CLI.
- **Redacting the preamble.** The brief is written under `~/.ASF/state/<product>/briefs/`
  (`asf/workers/spawn.py:117-118`), which is the operator's own state, not the public record, so
  B-0023's account-name rule does not reach it. The report the preamble quotes is the same text
  the harvest already reads back.

### Preconditions

Each was checked in this worktree at `c8dff94`; none of the cited files differ from `origin/main`
at `9790fdb`.

- `named_tests` already merges `repo_facts['tests']` into the card's own named tests, once each,

- `build.build` takes `repo_facts` and passes the collected facts to `preamble.build`
  (`asf/briefs/build.py:242-253`), so a caller is the only thing missing.
- **Not yet true:** `step_wave.repo_facts` returns four keys, none of which `collect` reads
  (`asf/tick/step_wave.py:113-122`). Its only assertions are in
  `tests/test_tick_steps.py:318-320, 338-341`, which this spec rewrites.
- **Not yet true:** `build.cmd_brief` calls `build(product, row, index, inflight)` with no facts
  (`asf/briefs/build.py:282`), so `asf brief` prints a strictly poorer brief than the tick does.
- `lifecycle.item_runs(path, item)` returns the ledger's runs for one item

  record (`asf/workers/runtime.py:126-151`), and `report.parse(text)` returns the typed REPORT
  (`asf/workers/report.py:31-50`). The last report needs no new bookkeeping, only assembling.
- `asf.briefs` already imports `asf.workers` (`asf/briefs/build.py:22`, `workers.stall`), and
  `asf.workers` imports no part of `asf.briefs`. A gatherer in `asf/briefs/` that reads the

- `footprint.globs_overlap` is a pure fnmatch over two globs, and a concrete path is a glob with

- `Conventions.from_mapping` keeps unknown keys in `extra` (`asf/conventions.py:96-110`), so a new
  named field breaks no existing product file.
- `metrics.SCHEMAS['sessions']` rejects unknown keys and fills declared ones from a default

  re-read still validates.
- `session_event` already reads `total_cost_usd` and `duration_ms` off the same result record
  (`asf/metrics/metrics.py:893-903`), and `cmd_backfill` re-derives sessions from the registry and
  its logs (`asf/metrics/metrics.py:1043-1073`). The before reading is recoverable from logs that
  already exist.
- `ctx.event` writes free-form JSON with no schema (`asf/tick/tick.py:139-148`), so two new fields
  on `launch` need no migration.
- The view commands take `(args, view_root)` off `resolve_record` (`asf/cli.py:301-320`), which is
  the shape `asf tokens` follows.

### Choices

| # | Choice | Chosen | Against | Why |
|---|---|---|---|---|
| D1 | Where the gathering lives | `asf/briefs/facts.py`, a named exception to the package's "no git" rule, stated in its docstring | leaving it in `asf/tick/step_wave.py`; a new `asf/views/` module | Two callers need it and one of them is `asf brief`, in `asf.briefs`. Importing `asf.tick` from the brief CLI would point the dependency backwards. `preamble.py` stays pure — one module runs git, and it is not the one that renders. |
| D2 | The contract between them | `preamble.REPO_FACT_KEYS`, a tuple `collect` reads through and `facts.repo_facts` returns exactly, asserted equal by a test | a dataclass; leaving it a loose dict | A dataclass is the stronger shape, but `repo_facts` is an optional argument every test builds by hand as a literal (`tests/test_briefs.py:43-50`) and passes as `None`. A named tuple of keys plus an equality test catches the exact defect that shipped — drift — without rewriting every caller. |
| D3 | Which commit `head` names | `origin/<branch>` when that ref resolves, else `origin/<main>`, and the string says which: `9790fdb fix(asf): … (origin/main — spec/F-0022 is not on origin yet)` | the worktree's own HEAD; empty when the branch is unpushed | A session cut from trunk starts at trunk's head, and that is the fact it needs. Saying which ref was read is what stops the number being read as the branch's own tip. The worktree does not exist yet when the brief is built. |
| D4 | How the sizes are read | one `git cat-file --batch` fed `<rev>:<path>` for every wanted path, newlines counted from the blob | one `git show` per path; `os.path.getsize`; `wc -l` on the checkout | One process for up to twelve paths. The blob at the rev the session will start from is the true answer; the clone's working tree may sit on another branch. A byte size does not answer "how long is this document". |
| D5 | Which paths get measured | `preamble.wanted_paths(facts)`: spec, plan, the review file for a review kind, each named test, each literal `writes:` entry — deduped, capped at `preamble_max_files` (12) | every path in `writes:`, globs expanded; nothing but spec and plan | Measure what the brief prints, and nothing else. A glob is not a path, and expanding one can mean thousands of stats for a line the preamble never writes. The cap makes the cost per launch a constant. |
| D6 | What `tests` adds | the test files already in the tree that fall inside the item's `writes:` footprint, at most six, sorted, from one `ls-tree -r --name-only` | a filesystem walk; nothing (card-named tests only) | The card names the tests it wants; the runner knows which already exist, and "the tests that already exist" is the card's own wording. One `ls-tree` at the same rev is cheaper than a walk and sees exactly what the session will check out. Six is enough to orient and small enough not to push the cap. |
| D7 | Where `last_report` comes from | the newest **ended** run for this item in the ledger, its job log's result text, `report.parse`, rendered as the typed fields (`status`, `pushed`, `tests`, `left out`, `ruling`), each capped at 200 characters, under a `<job> ended <ts> — <end_reason>` line | the full result text; the PR body; nothing | The typed block is the part a next session acts on, and it is already parsed by code the harvest trusts. The full text is a transcript — it would blow the 120-line cap and be trimmed away anyway. When the log is gone, the ledger's `end_reason` line still says what happened. |
| D8 | A fact that cannot be read | left out of the dict, so the preamble prints its existing unknown marker, and `facts_unknown` on the `launch` event counts it | guessing; failing the launch | A missing repository, a branch no one has pushed and a log that was rotated are all normal. The rule the module was built on — "a fact nobody passed is printed as unknown, never guessed" (`asf/briefs/preamble.py:23-27`) — stands. Counting the unknowns is what turns a silent gap into a number someone sees. |
| D9 | Where the test's size is rendered | in `state_lines`, on the existing `Tests named by the card:` line — `tests/test_briefs.py (476 lines); tests/test_tokens.py (new)` | a new section listing tests | One line stays one line. The cap is 120 and the identity block is never trimmed; a new section would compete with the description for room it does not need. |
| D10 | What `in_tokens` counts | `input_tokens + cache_creation_input_tokens + cache_read_input_tokens` of the result's `usage`, `None` when none is present | `input_tokens` alone | "Looking is charged too — every file a session opens is re-sent on every turn after it" (`docs/CONSTITUTION.md:52-53`). Cached input is re-sent input; counting only the uncached part would report a win the moment the cache warms and hide the growth this card exists to stop. |
| D11 | The reading | `asf tokens`, a view over `metrics/sessions/*.jsonl`, medians per brief kind, two windows split at `--split` (default today) | a scorecard row now; a one-off script | The card asks for a before and an after against the day the facts landed, which is a split, not a rolling average. Median, not mean: one 12-million-token session would otherwise be the whole reading. The daily row is F-0028. |
| D12 | The before reading | recovered by `asf metrics backfill --days N` re-deriving the `sessions` stream from job logs that already exist | recording a baseline number in a document | A number typed into a document is not evidence. The logs hold the usage records of every session this factory has run; once `session_event` reads them, the before is a query, not a memory. |

## The design

### `asf/briefs/facts.py` (new)

```python
"""asf.briefs.facts — the facts the runner holds, gathered once, so no session goes looking.

The one module of asf.briefs that runs git and reads the session ledger: asf.briefs.preamble
renders, this gathers, and the keys between them are preamble.REPO_FACT_KEYS. One ls-remote,
three local git calls and one ledger read per launching row; a fact that cannot be read is
left out of the dict and printed as unknown, never guessed.
"""

def repo_facts(product, row, index, inflight=None): ...   # -> dict over REPO_FACT_KEYS
def head_of(repo, branch, main): ...                      # (head_string, branch_exists, rev)
def line_counts(repo, rev, paths): ...                    # {path: lines} — one cat-file --batch
def tests_under(tree_paths, writes, limit=6): ...         # pure; footprint.globs_overlap
def last_report(product, item_id): ...                    # the typed REPORT, capped
```

`repo_facts` runs in this order, and every step is allowed to fail into nothing:

1. `facts = preamble.collect(product, row, index, inflight)` with no repo facts — the cheap pass
   that says which documents and tests this brief will name;
2. `head_of` — `git ls-remote --heads origin <branch>` (the call `step_wave` already makes) gives
   `branch_exists`; `git rev-parse --verify -q origin/<branch>^{commit}` picks the rev, falling
   back to `origin/<main>`; `git log -1 --format=%h %s <rev>` gives the head line, to which the
   ref is appended (D3);
3. `line_counts(repo, rev, preamble.wanted_paths(facts))` — one `git cat-file --batch`, a path
   the rev does not carry is simply absent from `files`;
4. `tests_under(ls_tree(repo, rev), facts['writes'])` — the existing tests inside the footprint;
   their paths join `wanted_paths` for the same batch, so they arrive sized;
5. `last_report(product, row.item_id)` (D7).

### `asf/briefs/preamble.py`

- `REPO_FACT_KEYS = ('head', 'branch_exists', 'files', 'tests', 'last_report')`, with the
  docstring naming `asf.briefs.facts` as the caller that fills it.
- `collect` keeps the map it was given: `'files': dict((repo_facts or {}).get('files') or {})`.
- `wanted_paths(facts, limit=None)` (new, pure): `spec_path`, `plan_path`, `review_path` when
  `facts['kind'] in REVIEW_KINDS`, each of `facts['tests']` with any `::node` suffix cut, and each
  entry of `facts['writes']` that carries no wildcard — deduped, in that order, cut to
  `limit or conventions.preamble_max_files`.
- `_test_line(name, files)` (new, pure) and `state_lines`: the tests line becomes
  `Tests named by the card: tests/test_briefs.py (476 lines); tests/test_tokens.py (new)`. A test
  whose path is not in `files` and whose rev could not be read keeps its bare name — `(new)` is
  claimed only when the tree was actually read, which `facts['files']` having entries proves.

### `asf/tick/step_wave.py`

- `repo_facts(product, branch)` is replaced by a delegate to `facts.repo_facts(product, row,
  items, running)` — the row, not the branch, because the gatherer needs the item and the kind.
- `run` passes the row (`asf/tick/step_wave.py:174-175`), and the `launch` event gains
  `preamble_lines=<int>` and `facts_unknown=<int>`, counted off the built brief by
  `preamble.unknown_count(text)` — the number of `(not known here)` markers in the preamble.
- The module docstring's step 4 stops promising "two `git` calls at most" and says what it now
  does: one `ls-remote`, three local reads, one ledger read.

### `asf/briefs/build.py`

- `cmd_brief` fills the facts: `build(product, row, index, inflight,
  repo_facts=facts_mod.repo_facts(product, row, index, inflight))`, so `asf brief` and the tick
  print the same brief.
- The module docstring names `asf.briefs.facts` as the caller that fills `repo_facts`, and keeps
  its own promise that `build` runs no git.

### `asf/conventions.py`

- `preamble_max_files: int = DEFAULT_PREAMBLE_MAX_FILES` (12), beside `preamble_max_lines`, with a
  one-line doc comment. `docs/products.example.yaml` lists it commented out at its default.

### `asf/metrics/metrics.py`

- `SCHEMAS['sessions']` gains `'in_tokens': (('int', 'null'), None)` and
  `'turns': (('int', 'null'), None)`.
- `in_tokens(result)` (new): the sum of `usage.input_tokens`,
  `usage.cache_creation_input_tokens` and `usage.cache_read_input_tokens` that are present;
  `None` when none is (D10).
- `session_event` fills both: `in_tokens` from the helper, `turns` from the result's `num_turns`
  when it is an int.

### `asf/views/tokens.py` (new) and `asf/cli.py`

`asf tokens [--product P] [--split DAY] [--days N] [--json]` — the TOKENS table, one row per
brief kind over `metrics/sessions/<day>.jsonl`, `--days` (default 14) each side of `--split`
(default today; sessions on the split day count as *after*):

```
TOKENS — input tokens per session, 14 d either side of 2026-09-23

| kind | before | in/session | after | in/session | Δ | turns |
| --- | --- | --- | --- | --- | --- | --- |
| coder | 12 | 4,118,000 | 9 | 1,050,000 | −74 % | 78 → 31 |
| spec | 4 | 2,900,000 | 3 | 980,000 | −66 % | 40 → 18 |
| all | 31 | 3,400,000 | 22 | 1,010,000 | −70 % | 61 → 26 |
```

Every number is a median over the sessions in the window; a window with no session prints `—` and
its delta is `—`. `--json` prints the same rows as a list of objects. `cmd_tokens(args, root)`
joins the other views in `asf/cli.py`'s `resolve_record` block and its `('roadmap', 'backlog',
'parity', 'prod', 'sessions', 'status')` tuple.

### The golden briefs

`tests/fixtures/briefs/golden/*.md` are regenerated (`ASF_UPDATE_GOLDEN=1`). The diff is the point
of this card and is read before it is committed: every `(not known here)` gone, `(N lines)` on the
documents, sizes on the tests, a `### The last report for this item` block where the fixture has
one.

## Acceptance tests

The suite is stdlib `unittest`, run from the checkout root. The git-backed tests use
`tests/gitfixture.py`, as `tests/test_tick_steps.py` does.

### `tests/test_brief_facts.py` (new)

```sh
python3 -m unittest tests.test_brief_facts -v
```

- `ContractTests`
  - `test_keys_match_what_the_preamble_reads`: `set(facts.repo_facts(product, row, index)) ==
    set(preamble_mod.REPO_FACT_KEYS)` — the defect this card closes, asserted in one line.
  - `test_no_product_repo_returns_the_keys_empty`: a product whose `repo_dir` does not exist →
    every key present, `branch_exists` False, `files` and `tests` empty, and no exception.
- `HeadTests` (a fixture repo with an `origin`, `main` at a known sha, `fix/B-0001` pushed)
  - `test_pushed_branch_reads_its_own_head`: `branch_exists` is True and `head` starts with the
    short sha of `origin/fix/B-0001` and ends with `(origin/fix/B-0001)`.
  - `test_unpushed_branch_reads_trunk_and_says_so`: for `fix/B-9999`, `branch_exists` is False and
    `head` ends with `(origin/main — fix/B-9999 is not on origin yet)`.
- `SizeTests`
  - `test_named_documents_are_measured`: with `docs/specs/f-0001.md` at 42 lines on the rev →
    `files['docs/specs/f-0001.md'] == 42`.
  - `test_a_missing_document_is_absent_not_zero`: a plan the rev does not carry → the path is not
    a key of `files`.
  - `test_wanted_paths_are_capped_and_ordered`: a card with twenty literal `writes:` entries and
    `preamble_max_files: 3` → `len(files) <= 3`, spec first, plan second.
  - `test_globs_are_never_measured`: `writes: [asf/feeder/**]` → no key of `files` contains `*`.
- `ExistingTestTests`
  - `test_tests_inside_the_footprint_are_found`: tree carries `tests/test_a.py`,
    `tests/test_b.py`, `asf/feeder/rows.py`; `writes: [tests/**]` → `tests` is
    `['tests/test_a.py', 'tests/test_b.py']`.
  - `test_tests_outside_it_are_not`: `writes: [asf/feeder/**]` → `tests` is empty.
  - `test_limit_holds`: nine test files under the footprint → six returned, sorted.
- `LastReportTests`
  - `test_the_newest_ended_session_report_is_carried`: a ledger with two ended runs for B-0001 and
    a job log whose result text ends in a REPORT → `last_report` names the newer job, carries
    `status:` and `pushed:` and not the transcript above the REPORT block.
  - `test_a_running_session_is_not_a_report`: the only run has no `ended` → `last_report` is `''`.
  - `test_a_missing_log_falls_back_to_the_ledger_line`: the log file is deleted →
    `last_report` is the one `<job> ended <ts> — <end_reason>` line.
  - `test_a_field_is_capped`: a `left out:` of 5000 characters → no line of `last_report` is over
    200 characters.
- `PreambleIsCodeTests`
  - `test_no_model_client_is_imported`: an AST scan of `asf/briefs/preamble.py` and
    `asf/briefs/facts.py` finds no import of a model client or HTTP module (`http`, `urllib`,
    `socket`, `requests`).
  - `test_preamble_never_runs_git`: an AST scan of `asf/briefs/preamble.py` finds no `subprocess`
    import and no `os.popen`.
  - `test_the_text_is_deterministic`: `preamble.build(...)` twice over the same facts → the two
    strings are equal, and equal again after a `collect` in between.

## Records

- **The brief file** `~/.ASF/state/<product>/briefs/<job>.md` (`asf/workers/spawn.py:245`) is the
  record of what a session was told. After this change its preamble carries the head and its ref,
  whether the branch is on origin, the spec/plan/review paths with their line counts, the tests
  with their sizes or `(new)`, and the previous session's typed REPORT.
- **The `launch` event** (`metrics/events/<day>.jsonl`) gains `preamble_lines` and
  `facts_unknown`. A run of ticks with `facts_unknown: 0` throughout is the standing evidence for
  this card's first acceptance line; a non-zero value names a fact that stopped arriving.
- **The `sessions` stream** (`metrics/sessions/<day>.jsonl`) gains `in_tokens` and `turns`, filled
  for new sessions by `asf metrics backfill` and for past ones from the job logs it re-reads.
- **No new file in the record.** `asf tokens` reads the stream and prints; it writes nothing.
- **Config**: `conventions.preamble_max_files` (default 12), optional, in `products/<name>.yaml`.
  `config.yaml` is unchanged.
- **The goldens** `tests/fixtures/briefs/golden/*.md` are the committed record of the brief's
  shape, and their diff in this change is the before-and-after of the preamble itself.
- Nothing is written to the product repository by the gatherer: it reads refs, and it reads them
  read-only.
