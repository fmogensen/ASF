# F-0041 — the footprint decides the size, and a small Task rides a train

A Task's cost is not its diff. `asf/metrics/metrics.py, tests/test_metrics.py` is a two-file
Task; it still costs a coder session, a branch, a pull request, a whole CI run and — where a
product reviews before it merges — a review round. Look at the plans on this trunk: most Tasks
carry two or three literal paths in `writes:`. The gates were built for a Task that changes
fifteen files, and they are charged in full to one that changes two.

Half of the answer is already here on the fast-forward path. Harvest gates once per tick over a
combined head, bisects on red, holds the one red branch and lands the rest
(`asf/harvest/harvest.py:1066`, B-0040). A product that lands through pull requests gets none of
that: its `prs` step opens one pull request per finished branch
(`asf/tick/step_prs.py:1`), and every one of them buys its own CI run.

This card gives that product the same economy, and makes the decision mechanical at both ends.
A **size class** is derived from the Task's own `writes:` footprint and the kind of file that
footprint names — no model, no operator, no judgement. A **train** is one open branch per lane
per product that small Tasks' commits accumulate on, one commit per Task. The tick's **cutter**
closes the train at six Tasks or two hours, and the train pays for one CI run, one review and one
merge on behalf of every Task in it. A red Task is reverted off the train, re-run, and sent back
as a medium Task with its own pull request — the train is never held by one member.

This changes code under `asf/`, `tests/`, and `docs/products.example.yaml` in this repository. It
adds one step to the tick, one derived field to every Task card, and one state file per product.
It changes no card in any record, and it changes nothing for a product that does not name a train
lane in its configuration.

## 1. Decisions

### 1.1 In

- **`asf/size.py`** — a new pure module: the three class names, the five kind names, and
  `classify(writes, cfg)` → `(class, kind, why)` over a footprint and a threshold table (§2.1).
- **`conventions.size` and `conventions.train`** — two nested configuration blocks, mapped onto
  flat `Conventions` fields exactly as `harvest:` already is (`asf/conventions.py:90`), each with
  a documented default, documented in `docs/products.example.yaml` (§2.2).
- **The derived field.** Ingest writes `size` and `size_kind` into every Task's machine block, so
  `index.json` carries them and the feeder — which may read nothing else (`asf/feeder/rows.py:3`)
  — can act on them (§2.3).
- **`asf/train.py`** — the train registry and its pure rules: which train is open for a lane, when
  it is due to be cut, what its Tasks are. One append-only `trains.jsonl` per product, folded the
  way `sessions.jsonl` is (§2.4).
- **The small Task's coder** — the feeder's PLAN → CODE row for a small Task carries the open
  train; its branch is cut from the train's head instead of the trunk, and its brief asks for one
  commit whose subject opens with the Task id (§2.5).
- **`asf/tick/step_train.py`** — a new tick step, `train`, between `wave` and `prs`: it appends
  every finished small Task's commit to its lane's train, cuts the train that is due, raises the
  train's review, and handles a red train (§2.6, §2.7, §2.8).
- **`asf train status` / `asf train cut`** — the operator's read of the open trains and a manual
  cut, `--dry-run` on both (§2.9).
- **One review per train** — a new `review-train` brief whose check table carries one block per
  Task, built from each Task's acceptance lines, raised by the cutter (§2.8).
- **The measurement** — one scorecard row, `runner-minutes per small Task`, off the `ci` stream
  the rollup already reads, so acceptance row 4 is a number somebody can print (§2.10).

### 1.2 Out

- **Sizing a Bug.** A Bug carries a `signature`, not a `writes:` footprint
  (`asf/record/check.py:149`), so nothing about it can be derived from a footprint. Bugs keep
  their own branch and their own landing, which is why `train.lanes` is a list and why the only
  lane on it today is `code` (D3).
- **Changing what harvest does.** The combined head, the bisection, the approval gate and the
  fast-forward push are untouched. The cutter *calls* `land_set` for a fast-forward product
  (§2.7) and adds no second implementation of a gate.
- **Merging Tasks into one commit, or re-shaping a Task.** F-0086's `merge`, `batch` and `split`
  proposals change the *cards*; a train changes only how the code of unchanged cards is
  delivered. Two Tasks on one train stay two Tasks, two commits and two rows in the review table.
- **A per-Task code review.** The factory launches no code review today — `review` is a brief kind
  with a template and no caller. This card adds exactly one caller, for a cut train (D10). It does
  not introduce the per-Task review it is cheaper than.
- **Deciding the merge.** Where a product lands through pull requests, the merge queue (the tick's
  `batch` step) merges the train's pull request like any other. "One merge per train" is a
  consequence of there being one pull request, not a new merger.
- **Trains across products or across lanes.** One train is one lane of one product. A Task whose
  footprint names another repository (`record:…`, as F-0002's Tasks do) is never small (D6).
- **A second CI configuration.** The train's run is the product's own workflow. "Path-scoped"
  means F-0038's classifier over the union of the train's footprints
  (`asf/ci.py`, `docs/specs/f-0038.md:106`) — a docs-only train runs the cheap class for free.

### 1.3 Preconditions

- **F-0038 has landed.** §2.6 reads `asf.ci.classify` for the train's CI class and §2.10 reads the
  `ci` stream's `items` list. Without F-0038 the train still cuts and still buys one run; only the
  class line in the pull request body and the cheap-class saving are absent.
- **The product names its lanes.** `conventions.train.lanes` is empty by default: no train opens,
  every Task keeps the branch and the landing it has today, and the only visible change is the
  derived `size` field on the cards. Turning trains on is one key.
- **The record's ingest runs with the product resolved.** `cmd_ingest` already loads it
  (`asf/record/ingest.py:231`); a record ingested with no product uses the documented defaults and
  every Task sizes from those.
- **Sessions of one lane do not share a footprint.** The feeder's `writes:` gate already
  guarantees it (`asf/feeder/rows.py:394`), which is what makes the cutter's cherry-pick onto a
  moving train head conflict-free in the normal case (D5).
- **`git` can push the train branch to origin.** The train is an ordinary branch under a prefix
  the product's conventions name; nothing about it needs a force push, ever.

## 2. The design

### 2.1 The classifier — `asf/size.py`

```python
SMALL, MEDIUM, LARGE = 'small', 'medium', 'large'
CLASSES = (SMALL, MEDIUM, LARGE)
#: The kinds a footprint can be, most specific first; ``code`` is the fallback (D8).
KINDS = ('docs', 'test', 'config', 'copy', 'code')


def kind_of(writes, kind_globs):
    """The one kind every entry of ``writes`` matches, else ``'code'`` — the safe class (D8).
    ``kind_globs`` is ``{kind: [glob, …]}``; matching is
    :func:`asf.feeder.footprint.globs_overlap`, the repo's one footprint-matching rule."""


def countable(writes):
    """``(n, blocker)``: how many files the footprint names, or ``(None, why)`` when it cannot
    be counted — a wildcard entry (D1), a cross-repo entry (``record:features/**``), or an
    empty footprint (D6)."""


def classify(writes, cfg):
    """``(class, kind, why)``. ``cfg`` is the resolved :class:`SizeConfig`:
    ``small_max_files``, ``small_max_files_by_kind``, ``medium_max_files``, ``kind_globs``,
    ``never_small_globs``. ``why`` is one sentence naming what decided it — the count and the
    threshold, or the blocker and the entry that matched it — and it is what the card, the
    brief and ``asf train status`` all print."""
```

Pure functions over plain lists: no filesystem, no `Product`, no path literal of its own —
`tools/check_conventions.sh` is the standing proof of the last one. It is
`asf/feeder/footprint.py`'s neighbour in shape and borrows its matcher, so an operator who writes
`writes:` and an operator who writes `kind_paths:` are writing the same kind of glob.

The order inside `classify` is fixed, because a blocker must beat a small count:

1. any entry matching `never_small_globs` (migrations, routes, `amendable_paths`) → at least
   `MEDIUM`, with `why` naming the entry;
2. `countable` returns no count → `LARGE`;
3. `n <= small_max_files_by_kind.get(kind, small_max_files)` → `SMALL`;
4. `n <= medium_max_files` → `MEDIUM`; else `LARGE`.

### 2.2 The configuration — `conventions.size` and `conventions.train`

Two nested blocks, folded onto flat `Conventions` fields by the mechanism `harvest:` already uses
(`HARVEST_KEYS`, `asf/conventions.py:90`), so an unknown key inside them is kept rather than
dropped and every field keeps a documented module-level default:

```python
SIZE_KEYS = {'small_max_files': 'size_small_max_files',
             'small_max_files_by_kind': 'size_small_max_files_by_kind',
             'medium_max_files': 'size_medium_max_files',
             'kind_paths': 'size_kind_paths',
             'never_small_paths': 'size_never_small_paths'}
TRAIN_KEYS = {'lanes': 'train_lanes', 'max_tasks': 'train_max_tasks',
              'max_age_s': 'train_max_age_s'}

DEFAULT_SMALL_MAX_FILES = 3          # the card's threshold
DEFAULT_SMALL_MAX_FILES_BY_KIND = {'docs': 15, 'copy': 15}   # D7
DEFAULT_MEDIUM_MAX_FILES = 15
DEFAULT_KIND_PATHS = {}              # no product's tree is known here
DEFAULT_NEVER_SMALL_PATHS = []       # plus amendable_paths, always (D6)
DEFAULT_TRAIN_LANES = []             # D15: no train until an operator names a lane
DEFAULT_TRAIN_MAX_TASKS = 6          # the card's seat count
DEFAULT_TRAIN_MAX_AGE_S = 7200       # the card's two hours
```

`Conventions.size_config()` returns the resolved `SizeConfig` `classify` takes, with
`never_small_globs = size_never_small_paths + amendable_paths` — the union is built here, once, so
neither the classifier nor the cutter has to remember it.

`docs/products.example.yaml`, under `conventions:`, beside `area_depth`/`batch_max_globs`:

```yaml
  # F-0041: the size class every Task derives from its own writes: footprint. A Task at or under
  # small_max_files entries (small_max_files_by_kind raises it for a kind whose files cannot turn
  # a test red) is small and rides its lane's train; medium keeps its own pull request; large is
  # unchanged. A footprint with a wildcard entry, one naming another repo, or none at all is
  # never small — a glob is not a file count. never_small_paths names the changes that must never
  # be batched behind someone else's; the product's amendable_paths are added to it for free.
  size:
    small_max_files: 3
    medium_max_files: 15
    small_max_files_by_kind: {docs: 15, copy: 15}
    kind_paths:
      docs: [docs/**, README.md]
      test: [tests/**]
      config: ['*.yaml', '*.toml']
      copy: [locales/**]
    never_small_paths: [db/migrate/**, app/routes/**]
  # F-0041: the lanes that run a train, the seats one train holds, and how old its first commit
  # may get before the cutter closes it. No lane named: no train — every Task keeps the branch
  # and the landing it has today.
  train:
    lanes: [code]
    max_tasks: 6
    max_age_s: 7200
```

### 2.3 The derived field — `size` on every Task

`MACHINE_KEY_ORDER` (`asf/record/ingest.py:19`) gains `size` and `size_kind`, written for Tasks
only, from `size.classify(meta['writes'], conv.size_config())`. `build_index_data` copies the
machine block into `index.json` wholesale (`asf/record/core.py:265`), so nothing else has to
change for the feeder, the board or the cutter to read it. A Task whose card carries
`size_floor: medium` (§2.7, a typed field an author or the cutter may write) never derives a class
below it; the floor is named in the `why`.

`asf check`'s index comparison (`asf/record/check.py:213`) keeps holding: the field is derived by
the ingest like every other machine field, and `do_index` re-derives nothing.

One `## History` line per change, as for any tracked machine field: `size: small → medium
(size_floor)`.

### 2.4 The train registry — `asf/train.py`

One append-only file per product, `~/.ASF/state/<product>/trains.jsonl`, folded by `train` id the
way `sessions.jsonl` is folded by job (`asf/workers/lifecycle.py:24`):

```json
{"train": "code-20260924-0930", "lane": "code", "branch": "train/code-20260924-0930",
 "opened": "2026-09-24T09:30:11Z", "first_commit": "2026-09-24T09:41:02Z",
 "tasks": [{"item": "T-0101", "job": "task-t-0101", "branch": "worker/t-0101",
            "sha": "9c1f…", "subject": "T-0101 the classifier"}],
 "state": "open", "cut": null, "pr": null, "landed": null}
```

States: `open` (accepting commits) → `cut` (its pull request or its gate is running; no new
Task joins) → `landed` (merged or pushed to the trunk) or `abandoned` (every Task reverted off it).
The pure half of the module — `open_train(records, lane)`, `due(train, now, cfg)`,
`tasks_of(train)` — takes plain dicts and a clock, so the rules are tested without a git
repository. The branch name is `conv.branch('train', f'{lane}-{stamp}')`, which gives
`train/code-20260924-0930` from the new `train` entry in `DEFAULT_BRANCH_PREFIXES`.

The train branch itself carries no session record, so harvest's product loop skips it where it
skips every unknown branch (`record is None`, `asf/harvest/harvest.py:1258`) — the registry is the
only thing that knows a train exists, and the cutter is the only thing that writes it.

### 2.5 The small Task's coder — the feeder row and the brief

`task_rows` (`asf/feeder/rows.py:350`) gains one fact per launching PLAN → CODE row: when the
Task's `size` is `small`, the product names its lane in `train.lanes`, and a train is open for
that lane, the row carries `train` (the id) and `base` (the train branch). The row's own branch is
unchanged — `worker/<id>`, the one prefix harvest scans for code (B-0067). The train's facts reach
the feeder the same way the groom's day does (`asf/tick/step_wave.py:plan_inputs`, P5): the tick
reads the registry and passes it in; the feeder runs no git and opens no file.

`spawn.make_worktree` cuts a row's branch from `origin/<main>`; with `base` set it cuts from
`origin/<base>` instead. Nothing else about the session changes: its worktree, its footprint
boundary, its gate and its report are what they are today.

The coder brief (`asf/briefs/templates/coder.md`) gains one block, rendered only for a train row:

```
THIS TASK RIDES A TRAIN — {train}
Your branch `{branch}` is cut from `origin/{base}`, not from the trunk: the Tasks already on that
train are the ground you build on. Leave exactly one commit on it, subject `{item_id} <what you
did>`. You open no pull request and you do not wait for one: the tick puts your commit on the
train, and the train is reviewed, gated and merged with up to {train_max_tasks} other Tasks.
```

### 2.6 The cutter — `asf/tick/step_train.py`

`STEPS` becomes `['record', 'health', 'wave', 'train', 'prs', 'harvest', 'batch', 'daily']` and
`ASF_CALLABLES` gains `'train': 'asf.tick.step_train:run'`. A product that declares no `train:`
step gets the `asf` implementation, which does nothing at all when `train.lanes` is empty.

The step runs three passes, in this order, all of them in one throwaway worktree
(`tempfile.mkdtemp(prefix='train-')`, removed in a `finally`, as `land_set` already does):

**1 — append.** For each lane in `train.lanes`, for each session that is `finished`, not landed,
whose item's `size` is `small`, whose branch is on origin and ahead of the train head, oldest
session first:

- open the lane's train when there is none (`git push origin origin/<main>:refs/heads/<branch>`);
- `git cherry-pick` the branch's commits onto the train head (a fast-forward when the head has not
  moved). More than one commit is squashed into one with the Task id kept in the subject; a
  conflict, or a commit whose subject does not name the Task, demotes the Task (D5) — the session
  is left exactly as it is, so `prs` opens its ordinary pull request in the same tick;
- push the train, append a `tasks` row to the registry, and mark the session `harvest: train`
  (D14) with the appended sha.

One line per append: `train: T-0101 → train/code-20260924-0930 (3/6)`.

**2 — cut.** A train whose `len(tasks) >= train.max_tasks`, or whose `first_commit` is older than
`train.max_age_s`, is cut. The registry row moves to `cut`, and:

- **`landing: pull-request`** — `gh pr create -R <slug> --base <main> --head <train branch>`,
  titled `train <lane> — <n> Tasks`, its body one row per Task (id, title, card link) and the CI
  class F-0038's classifier gives for the union of the Tasks' footprints (`asf ci class
  --paths-from -`). That one pull request is the one CI run;
- **`landing: fast-forward`** — the cutter calls `harvest.land_set` with a single entry, the train
  branch and a synthetic record. That is one gate for the whole train, run by the code that
  already runs every gate. Green: the push lands, every Task's session is marked
  `harvested: <sha>` and its `harvest: train` mark is cleared. Red: §2.7.

**3 — red.** A cut train whose run came back red (the gate's verdict, or `gh run view` on the
train head for a pull-request product) is narrowed and repaired — §2.7.

`asf train status` prints what this step would do without doing it; the step prints one line per
train per pass, so a tick log says what the trains did without anyone reading the registry.

### 2.7 A red Task never holds the train

Narrowing, in order (D11):

1. the gate's own output — `red_modules(text)` first, then `gate_files(text)` — intersected with
   each Task's `writes:` through `footprint.overlaps`. One Task matches: it is the culprit;
2. more than one matches, or none: the newest Task on the train, then the next newest.

Then, for the culprit:

- `git revert --no-edit <its commit>` on the train branch, pushed. The revert's subject names the
  Task and the run: `revert: T-0101 — red on train/code-20260924-0930 (run 41)`. CI re-runs on the
  new head; for a fast-forward product the cutter re-runs `land_set` once in the same tick;
- the registry row for that Task moves to `reverted`, and the train's `tasks` count drops, so a
  train that empties completely becomes `abandoned` rather than being merged as a no-op;
- the Task goes back to its own session through the path that already exists:
  `hold_with_correction(state_dir, branch, record, 'gate', line, out, files, item_writes, touched,
  conv)` — the same call harvest makes for a red branch, with the same foreign-red and timeout
  rules (`asf/harvest/harvest.py:958`). Its branch still exists (D14), so the FIX → CORRECT row the
  feeder raises next tick lands its correction on the work that is already there;
- `size_floor: medium` is written on the Task's card in the record clone (through
  `asf.record.setfield`, the one writer of a typed field), so the corrected Task gets its own
  branch off the trunk and its own pull request. It never rejoins a train.

A train that goes red twice in a row with no Task attributable is `abandoned`: every remaining
Task is demoted the same way, and the lane opens a fresh train. That is the terminating case, and
it is why the narrowing falls back to newest-first rather than to nothing.

### 2.8 One review per train

When a train is cut, the cutter builds one brief of the new kind `review-train`
(`asf/briefs/templates/review-train.md`, registered in `briefs.build.KINDS` with the `review`
model) and launches it with `workers.wave.wave(product, [row], 1, …)` — the same launcher the
wave step uses, so the pool, the quota and the S1 reserve still decide whether it runs now.

The row: `job = f'review-{train}'`, `item` the train's first Task (so the registry and the
preamble have an item to hang on), `branch` the train branch.

The template is the existing review table (`asf/briefs/templates/review.md`) with one addition —
the table is repeated per Task, and the Tasks come from the brief, not from the reviewer's
reading:

```
THE VERDICT IS A TABLE PER TASK. This train carries {n} Tasks. Write {review_path} with one
`### {item_id} — {title}` section per Task below, each with the full check table, and no row
without evidence. A Task you cannot find a commit for is a `fail` row, not a missing section.

{task_blocks}          one block per Task: its id, its title, its writes:, its commit sha, and
                       its acceptance lines — the proves lines the check table must cover
```

The verdict line is per train (`verdict: approved` / `changes requested`) and the C list names the
Task each finding belongs to, because that is the unit the cutter can revert.

### 2.9 The commands

```
asf train status [--product P] [--json]     the open and cut trains, their Tasks, what is due
asf train cut [--product P] [--lane L] [--dry-run]    cut now, whatever the seat count says
```

`status` prints one block per train — the branch, the seat count, the age of the first commit,
what each Task is and where its commit sits — and exits 0 whether or not a train exists. `cut`
without `--lane` cuts every due train, which is exactly what the step's second pass does; with
`--lane` it cuts that lane's open train even when it is not due, which is the operator's escape
hatch before a release. Registration follows the one nested command this CLI has already
(`plugin_build.register(sub)`, `asf/cli.py:181`).

### 2.10 The measurement

`compute_costs` already splits a CI run's minutes evenly over the items the run names
(`asf/metrics/metrics.py:356`), and the `ci` event carries `items` and `branch`. The train's run
names every Task on the train, through the existing matcher: `asf/record/match.py` rule 1 finds
every `T-nnnn` token in the pull request title and body, and §2.6 writes one row per Task into
that body. Nothing in the `ci` schema changes.

`scorecard_rows` gains one row, computed over the window the rollup already reads:

```
| runner-minutes per small Task | 4.1 (was 26.0) — 84 % down | 37 small Tasks merged on 7 trains; 12 medium, 3 large |
```

The number is `sum(minutes of runs naming a small Task) / count(small Tasks merged)`, with the
comparison drawn against the same figure for the window before trains were switched on — the
`ci` stream holds both, so the two-week acceptance is a `rollup` run, not a new collector.

## 4. Records

**Config, new** — `products/<p>.yaml`, under `conventions:` (§2.2): the `size:` block (five keys,
all optional) and the `train:` block (three keys, all optional). Absent, every default holds and
no train opens.

**The card** — two new machine fields on every Task, `size` and `size_kind`, and therefore two new
keys in `index.json`; one typed field, `size_floor`, written by an author or by the cutter; one
`## History` line per change of the derived class.

**Per product, new** — `~/.ASF/state/<product>/trains.jsonl`: one append-only record per train
(§2.4), one line per state change and per Task appended or reverted. Nothing in it is a fact
about the world that git does not also hold — the branch, its commits and its pull request are the
truth; the registry is the index over them, and a lost registry costs the open trains, not the
work.

**Per session** — two existing fields used for a new value: `harvest: train` while a Task's commit
sits on an open train (cleared when it lands, D14), and the ordinary `correction` a reverted Task
is held with.

**In the product repo** — one branch per train under the `train/` prefix, one commit per Task on
it, one revert commit per red Task, and one pull request per cut train (or one fast-forward push
for a product with no merge queue). One review file per train at the product's `review_pattern`.

**In the metrics streams** — no new stream and no new event. The train's CI run is an ordinary
`ci` event whose `items` list names every Task on the train, matched by the ids in its pull request
body; the new scorecard row is computed from it at rollup time.

**Not written.** No new card in any record. No change to the `ci` or `sessions` event schema. No
change to what harvest gates, what the approval classes refuse, or what `asf check` enforces. No
second copy of the size anywhere: one derivation, in the machine block.
