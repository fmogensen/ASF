# F-0200 — an S1 card stuck on a signature question is not allowed to be quiet

Two S1 intake cards sat all night on an intake `## Question` — "add signature: …" — and nobody
saw it. One of them blocked prod. The groom ruled six cards that morning; neither of those two
became a Bug, because neither of them was ever a card the factory could type, and nothing in any
view said so.

Three things are wrong, and they compound into that night:

1. **Severity is read only from a `severity:` header.** A title prefix `S1:` is a word in the
   title and nothing else — probed live in this checkout: `# S1: p1-e2e is flaky on main` parses
   to `title='S1: p1-e2e is flaky on main'`, `headers={}`, and a Bug minted from it carries
   `severity: S3`. The prefix then rides into the record's `title`, and — for a `type: bug` card
   with no signature — into the signature `declared()` derives from that title.
2. **An intake question is silent.** It is written into the card file, it is rendered as one
   `- [ ] inbox:<file> …` line in the groom file, and under `approvals.groom: auto` it is handed
   to the clerk. None of that is a line an operator reads. Worse: the every-tick groom returns
   before it prints anything when the merged file equals the existing one and intake neither
   created nor asked (`asf/groom/groom.py:1295-1297`) — which is precisely the state of a card
   that is stuck. The card that most needs saying is the one the tick is quietest about.
3. **A card carrying its evidence is still asked for it.** A body that opens `Error: expected
   200, got 500`, or names a failing spec, holds exactly the one header the card is missing, and
   intake reads none of it.

This spec is not "make intake smarter". It is three narrow reads and one loud line: **the title
prefix is a severity, a body error or failing-spec line is a signature, and an S1 card sitting on
a question is a `NEEDS OPERATOR` line — in the tick's groom output and in `asf status` — naming
the file, every tick, until it is answered.**

### The choices

| # | Chosen | Against | Why |
| --- | --- | --- | --- |
| C1 | **The title prefix is read by a header filler, `graded(card)`, applied at intake beside `declared` and `scrub_title`** — it fills the `severity` header when the title opens with one and cuts the prefix from the title, always. `shape.derive` is not touched by it. | Teaching `parse_inbox_file` to split the prefix; teaching `derive` to read titles. | P3: intake already owns "what the headers are" and `shape` owns "what the type is". A filler keeps that line where it is, keeps `derive` pure over headers, and makes the new read one small testable function rather than a branch inside a parser two other things depend on. |
| C2 | **The prefix is cut from the title whether or not it was the source of the severity.** A card carrying both `severity: S2` and a title `S1: …` mints at S2 with the title `…`. | Leaving the prefix in the title when a header already set the severity. | P2: the title is written into the record, into `title_signature` and into the `done/` slug. A severity is a field; carrying it in the title as well is a field written twice, in two places that can disagree — and the signature it leaks into is the key a Bug is deduplicated on. Cutting it is unconditional, so there is one rule, not two. |
| C3 | **The header wins a disagreement, and the disagreement is not a question.** | Asking a `## Question` when `severity:` and the title prefix disagree; letting the prefix win. | It mirrors I13's existing rule for `type:` — an explicit header line decides, and the shape reading only fills what is missing. A question here would park a card over a contradiction that has an obvious reading and costs nothing to get wrong: the operator who typed the header meant the header. The prefix is still cut (C2), so the card is not left saying two things. |
| C4 | **The prefix grammar is `S1:` / `S2:` / `S3:` at the head of the title, case-insensitive, with optional space before the colon** — `^\s*(S[123])\s*:\s*(?P<rest>.+)$`, and the severity is upper-cased. Nothing else. | `[S1]`, `S1 -`, `S1 —`, `P1`/`SEV1`, a prefix anywhere but the head, a prefix with an empty remainder. | The card names one form. A wider grammar is a wider way to mis-read a title that legitimately starts with a token and a colon (`S3: the third option we considered`) — which is why the match must also leave a non-empty title behind, and why `S4:` is just a title. An operator who wants another form has the `severity:` header, which is documented and exact. |
| C5 | **Severity is read through one function, `severity_of(card)`, which upper-cases before the membership test and defaults `S3`** — and both readers use it: the Bug that intake mints, and the stuck-card line (C7). | Leaving the exact-case test at the mint site and adding a second read for the new line. | P1 shows the current test is case-sensitive, so `severity: s1` mints an S3 today — the same class of silent downgrade this card is about, one header away. One function means the fix lands once, and the loud line and the minted field can never disagree about what a card's severity is. This is the "one definition of the predicate, every reader on it" shape the repo has applied before. |
| C6 | **A body signature is filled by a second intake filler, `signed(card)`, and only when the card carries no `signature:`, no `writes:`, no `## Acceptance` list, and no `type:` other than `bug`.** Defect *words* are not part of the gate. | Gating on `DEFECT_WORDS_RE`, the way `derive`'s existing defect question is gated. | P4 is decisive: `flaky` is not a defect word, so the very card that opened this Feature would be missed by a defect-word gate. A body line that *is* an error or a named failing spec is stronger evidence than a word in prose, and the three negative conditions are what keep it safe: a card with an acceptance list is work (the existing `defect_words_with_acceptance_is_work` rule, unchanged), a card with `writes:` is a Task, and `type: feature` settles the reading exactly as it does today. |
| C7 | **An S1 card sitting on a question is one `NEEDS OPERATOR` line, computed once by `inbox.stuck_s1_lines(root, intake_dir, groom_file=…)` and printed by two surfaces** — the tick's groom step, and a new `Intake` row in `asf status`. Repeated every tick, with no ledger and no "announced once" marker. | Announcing once through the approvals ledger, the way a hold is; a new command; a new state file. | The defect is silence over a whole night, so the cure is a line that keeps being said until the card stops being stuck. A once-only announcement is the wrong shape for a condition that persists and that the reader may not have been present for. No ledger also means no new state to get wrong: the intake directory *is* the state, and the line is derived from it. |
| C8 | **The line is printed above `_write_incremental`'s early returns**, in `cmd_groom`, immediately after `groom_path` is computed and before the `if incremental:` branch. | Printing it inside `_write_incremental`, or inside `process_inbox`. | P6: those early returns are the reason the cards were quiet. A line printed below them is a line that never fires in the exact case it exists for. `cmd_groom` is also the one place that holds `root`, `intake_dir`, `date` and `groom_path` at once, so both the daily and the every-tick path get it from one insertion. |
| C9 | **The line names the intake file by record-relative path, quotes the question, and ends in the remedy — answering the card's `inbox:<file>` line in the groom file.** With no groom file yet, the remedy is `asf groom --product <name>`. | Naming an absolute path; telling the operator to edit the card by hand; naming no remedy. | P13 forbids a machine path in a tracked file, and the record-relative path is what every other record line uses. "Nobody edits a card by hand" is already this module's rule (`apply_answer`'s docstring) — the answer grammar is the supported way in, and it is what the next tick applies. |
| C10 | **S1 only.** An S2 or S3 card on a question stays where it is: one groom line, the clerk's to answer. | Making it S1 and S2; making the threshold a product convention. | The card says S1. A `NEEDS OPERATOR` line is the factory's most expensive sentence — it is a claim that nothing moves until a person acts — and spending it on the ordinary backlog is how it stops being read. S2 is not idle: it is in the groom file and in the clerk's list (P5). |
| C11 | **The groom's inbox question line carries the severity when it is not S3**: `- [ ] inbox:<name> S1 <title> — <question> → answer: ____`. | Leaving `question_lines` untouched; using `[S1]`. | The clerk and the operator read that line to choose what to answer first, and today it is the one place in the groom file where a card's urgency is invisible. The token goes after the `inbox:` token, where `policy`'s `^- \[ \]\s+(?P<id>…\|inbox:\S+).*→\s*answer:\s*____$` reads it as part of the `.*` and `_LINE_ID_RE` never sees it. Bare `S1`, not `[S1]`, so nothing downstream can mistake it for a checkbox. |
| C12 | **A failing-spec line's signature is `flaky.test_key`'s bare form — `<file>:<line> › <title>` — reusing `flaky._TEST_RE` to parse it, but never `flaky.SIG_PREFIX`.** The import is function-local (P9). | Prefixing `flaky e2e: ` so a hand-dropped card dedupes onto the CI-filed flake; writing a second spec-line regex here. | P8: `flaky e2e:` asserts that a retry passed the test — a fact about a CI run that a card dropped by a person does not carry, and that would be a false claim in the record's own key. Reusing the *parse* and the *format* means the two signatures read alike and compare by eye, and a genuine duplicate is what the groom's near-duplicate section is for. Writing a second regex would be a second definition of "a failing spec line". |
| C13 | **`derive`'s defect question gains one clause naming the body forms it now accepts**, and is otherwise unchanged. | Rewriting the defect branch; removing the question. | The question still fires for a card with defect words and no evidence, and an operator told "add `signature:`" should also be told that pasting the error line is enough. One string, one test. |
| C14 | **No new command, no new record card, no new event, no new state file, no change to what the clerk is handed.** | An `asf inbox stuck` command; a tick event counting stuck S1 cards; bumping an S1 card to the head of the clerk's list. | Everything here is a read over files that already exist, surfaced through lines that already print. The clerk's ordering is a real question and a different one — named out, not overlooked. |

### In, and out

**In.** `severity_of`, `graded`, `signed`, `body_signature` and `stuck_s1_lines` in
`asf/groom/inbox.py`; the filler chain in `process_inbox` and the Bug's severity read; the
severity token in `question_lines`; the `NEEDS OPERATOR` print in `cmd_groom` above the
incremental early return; an `Intake` row in `asf/views/status.py`; one clause added to
`shape.derive`'s defect question; the module docstrings that describe each.

**Out, deliberately.** S2 and S3 stuck cards (C10); the clerk's ordering and its brief (C14); any
new command, event, ledger or state file (C7, C14); `found_in`, which stays `dev` for every
intake Bug; the answer grammar in `parse_answer`, which already has `S1|S2|S3` and needs nothing;
prefix forms beyond `S<n>:` (C4); and `flaky.SIG_PREFIX` on a hand-dropped card's signature (C12).

## The design

### 1. `asf/groom/inbox.py` — three reads and one line

```python
#: A title may open with its severity: `S1: p1-e2e is failing on main` (C4). Case-insensitive,
#: and the match must leave a non-empty title behind — `S3: the third option` is a title, so the
#: `rest` group is what guards it, not a lookahead.
_SEVERITY_PREFIX_RE = re.compile(r'^\s*(S[123])\s*:\s*(?P<rest>\S.*?)\s*$', re.IGNORECASE)

SEVERITIES = ('S1', 'S2', 'S3')


def severity_of(card):
    """The card's severity — its ``severity:`` header, upper-cased, when that names one of
    :data:`SEVERITIES`; ``S3`` otherwise. The one reader of the field: the Bug intake mints and
    the stuck-card line (:func:`stuck_s1_lines`) both come through here, so a card cannot be S1
    in one view and S3 in the other (C5). ``severity: s1`` is S1, which it was not before."""


def graded(card):
    """A card whose title opens with ``S1:``/``S2:``/``S3:`` (C4), with that prefix cut from the
    title and — when no ``severity:`` header says otherwise (C3) — recorded as one. The prefix
    is cut either way (C2): a severity is a field, and a title that also carries it is the same
    fact written twice. A title with no prefix comes back unchanged (identity, not a copy)."""


def body_signature(description):
    """The signature a card's body offers, or ``None``: the first line that is an error line or
    a named failing spec, whitespace-folded.

    Two grammars, in this order:

    * ``<Name>Error: <text>`` — ``Error:``, ``TypeError:``, ``AssertionError:``,
      ``asf.env.ConfigError:`` — taken whole, as the operator wrote it.
    * a failing spec line, parsed by :data:`asf.tick.flaky._TEST_RE` and formatted by
      :func:`asf.tick.flaky.test_key` as ``<file>:<line> › <title>``, so it reads as the
      signature a CI-filed flake carries — without ``flaky.SIG_PREFIX``, which claims a retry
      passed the test and is not this card's to claim (C12). The import is function-local:
      ``asf.groom`` stays out of ``asf.tick`` (P9).

    Capped at :data:`SIGNATURE_MAX` characters with a trailing ``…``."""


def signed(card):
    """A card with no ``signature:`` whose body names one (:func:`body_signature`) gets it —
    the one header between a card that carries its own evidence and a Bug (C6).

    Filled only when the card carries no ``signature:``, no ``writes:``, no ``## Acceptance``
    list and no ``type:`` other than ``bug``: a card with an acceptance list is work, a card
    with ``writes:`` is a Task, and ``type: feature`` settles the reading as it does today.
    Deliberately *not* gated on ``shape.DEFECT_WORDS_RE`` — ``flaky`` is not one of its words
    (P4), so a defect-word gate would miss the card this rule exists for."""
```

`process_inbox`'s one composed line becomes, in this order — scrub, then grade (so `declared`'s
`title_signature` sees a clean title, P2), then sign (so a body signature beats the title one),
then declare:

```python
card = declared(signed(graded(scrub_title(parse_inbox_file(body), root))))
```

and the Bug branch's two lines collapse to one:

```python
if type_ == 'bug':
    typed['severity'] = severity_of(card)
    typed['found_in'] = 'dev'
    typed['signature'] = card.headers.get('signature')
```

The loud reader, beside `question_lines` and reading the same files:

```python
def stuck_s1_lines(root, intake_dir=None, groom_file=None, product=None):
    """One ``NEEDS OPERATOR`` line per intake card sitting on a ``## Question`` whose severity
    reads ``S1`` (C10), in file-name order; ``[]`` when there is none. Pure over the intake
    directory — no ledger, no marker, said again every tick until the card stops being stuck
    (C7)::

        NEEDS OPERATOR: S1 intake card inbox/p1-e2e-on-main.md is stuck on an intake question —
        "This reads as a defect. A Bug carries a signature — …" — answer its
        `inbox:p1-e2e-on-main.md` line in groom/2026-09-29.md (the next tick applies it)

    The file is named record-relative, never by machine path (P13). With no groom file yet the
    remedy is ``asf groom --product <name>``, which writes one. The question is folded to one
    line and capped at :data:`QUESTION_MAX`."""
```

`question_lines` gains the severity token (C11) — one interpolation, empty at S3:

```python
sev = severity_of(card)
grade = f'{sev} ' if sev != 'S3' else ''
out.append(f"- [ ] {TOKEN_PREFIX}{name} {grade}{title} — {question} → answer: ____")
```

### 2. `asf/groom/shape.py` — one clause

The defect question keeps its trigger and its wording, and names the body forms intake now reads:

```python
return Question(
    'This reads as a defect. A Bug carries a signature — add signature: <the failing '
    'test or error line>, or paste that line into the body (an `Error:` line or a '
    '`file:line › test` line is read as one); or an ## Acceptance list if it is new work.'
)
```

### 3. `asf/groom/groom.py` — the line, above the early return

In `cmd_groom`, between `groom_path = …` and `if incremental:` (C8, P6):

```python
for line in inbox_mod.stuck_s1_lines(root, intake_dir,
                                     groom_file=os.path.relpath(groom_path, root),
                                     product=product):
    print(line)
if incremental:
    return _write_incremental(...)
```

Printed before the branch, so the every-tick groom says it on a tick where nothing else changed
— which is every tick of the night this card is about.

### 4. `asf/views/status.py` — one row that only speaks when something is wrong

```python
def intake_cell(root, product):
    """``Intake``: the first ``NEEDS OPERATOR`` line for an S1 intake card stuck on a question
    (:func:`asf.groom.inbox.stuck_s1_lines`), with ``+N more`` when there are others; ``None``
    when there is none, so the row does not print (P7). One cell is one line."""
```

registered in `render`'s list directly after `('Decisions', …)`:

```python
('Intake', lambda: intake_cell(root, product)),
```

`intake_dir` comes off the product's conventions, falling back to `DEFAULT_INTAKE_DIR` — the same
resolution `_intake_dir` already does, and any `ConfigError`/`OSError` is already swallowed by
`render`'s per-cell `try` (P7).

### What it looks like when it is there

A card dropped as `inbox/p1-e2e-on-main.md`:

```
# S1: p1-e2e is flaky on main

Error: expected 200, got 500
Blocks the prod deploy.
```

is minted, on the next tick, as a Bug titled `p1-e2e is flaky on main`, `severity: S1`,
`signature: Error: expected 200, got 500` — no question, no night. The same card without the
error line is asked one question, and from that tick on every `asf groom` prints:

```
NEEDS OPERATOR: S1 intake card inbox/p1-e2e-on-main.md is stuck on an intake question — "Which Epic is this under? No open Epic shares a title word with it." — answer its `inbox:p1-e2e-on-main.md` line in groom/2026-09-29.md (the next tick applies it)
```

and `asf status` carries the row:

```
| Intake | NEEDS OPERATOR: S1 intake card inbox/p1-e2e-on-main.md is stuck on an intake question — … |
```

## Acceptance tests

New module `tests/test_intake_severity.py`, four classes. The fixtures are this suite's own —
`tests.test_groom.make_repo` / `write_item` / `run` for the record root and the subprocess CLI,
`tests.test_inbox_shape.card` / `seeded_canonical` for the pure shape probes.

**The title prefix is a severity, and the title stops carrying it.**

```bash
python3 -m unittest -v tests.test_intake_severity.SeverityFromTitle
```

Covers: `# S1: p1-e2e is flaky on main` → `severity_of` is `S1` and the title is
`p1-e2e is flaky on main`; `s2:` and `S2 :` are read the same; `severity: S3` beats a title
`S1:` and the prefix is cut anyway; `severity: s1` reads `S1` (the case bug, P1); `S4:`,
`[S1]`, `S1 - x` and `S1:` with nothing after it are titles, untouched; a `type: bug` card
titled `S1: checkout down` gets the signature `checkout down`, not `S1: checkout down` (P2);
and end to end through `asf groom --default-bug-epic <id>`, the minted Bug's frontmatter carries
`severity: S1` and the clean title while `inbox/done/` keeps the original text (P11).

**A body error or failing-spec line is a signature.**

```bash
python3 -m unittest -v tests.test_intake_severity.BodySignature
```

## Records

What this change writes down, and what it deliberately does not:

* **The minted Bug's `severity` field** now carries what the title said — the record fact this
  card is about. Written by `write_new_item` as before; no new field, no migration. Cards already
  minted are not revisited.
* **The minted item's `title`** no longer carries the `S1:` prefix, and neither does the
  signature `declared()` derives from it (P2) or the `done/` file's slug.
* **The minted Bug's `signature`** may now be a line from the body. The History line stays
  `created (inbox) — shape: signature → bug`: the rule *is* `signature`, and the record does not
  distinguish a header one from an inferred one. The audit trail is `inbox/done/<slug>.md`, which
  holds `→ <id>` and the operator's original text, prefix and error line intact (P11).
* **The groom file's `Inbox cards with a question` lines** gain a leading `S1`/`S2` token after
  the `inbox:<file>` token (C11). Still one line per asked card, still ending `→ answer: ____`,
  still answered by `apply_answer` through the unchanged grammar.
* **No new file, row, ledger, marker or event.** The `NEEDS OPERATOR` lines are printed by the
  groom step and rendered by `asf status`; they are derived from the intake directory on every
  read and stored nowhere (C7). The tick's existing `groom_open` event is unchanged.
