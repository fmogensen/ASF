# F-0318 — the cards are minted by the spec that declares them

The stories-first gate and the Story-minting pass each wait for the other.

`asf/feeder/rows.py:421` holds a Feature behind `has_stories`, which counts Story **cards**:

```python
def has_stories(items, feature):
    """Does ``feature`` carry a Story the record still holds? A Story enters the record only
    with its acceptance list (``asf new story --acceptance``; ``asf check`` refuses a Story card
    without one), so a Story child is a Story with checkbox acceptance lines."""
    return any(not ix.retired(s) for s in ix.children(items, feature or {}, 'story'))
```

Its own docstring is the reason D4 exists: the gate counts Story cards *with* acceptance lines,
so a card minted without them clears the gate on a technicality and is refused by the check that
follows.

A session that cannot reach the record — which today means every cloud session — cannot run
`asf new story`, so it does the one thing the briefs offer instead: it *declares* each Story in
the spec as a `### S-nnnnn: <title>` heading with checkbox acceptance lines under it, from its own
`BACKLOG_ID_RANGE`. That declaration is minted in exactly one place, `asf/record/plan_tasks.py`,
and only inside the branch that a **landed plan** opens:

```python
ref = plan_ref(fev)
if not ref:
    continue
...
candidates.append((fid, ref, plan_path))
if fev.get('spec') and fev.get('spec_on_main'):
    specs[fid] = fev['spec']
```

`specs[fid]` is only ever written for a Feature that already reached `candidates`, and
`candidates` requires a plan on the trunk. So the spec's declarations wait on a plan; the plan
row waits on `has_stories`; `has_stories` waits on the cards. Nothing in the loop breaks the
cycle, and nothing prints a word about it (P1).

The card names the cost: on 2026-10-08 the cycle stalled F-0280, F-0303, F-0306, F-0293, F-0295,
F-0254 and F-0290, each re-firing a spec-amend, adjudicate or correct session that ends
"needs input" and spends budget for nothing, until the cards were minted on the host by hand.

This change moves the minting to the moment the declaration becomes a decision: **a Story a
Feature's landed spec declares becomes a card in the next tick's record step, with no plan
required.** The gate keeps counting cards; the cards simply arrive in time.

### In scope

1. A new record pass that mints the Stories a Feature's landed spec declares, with no plan
   required, and names every declaration it will not mint.
2. Its place in the tick's record step, before the wave decides any row — and its name in the
   writer order that step's docstring and `stage.WRITERS` both claim to list.
3. The acceptance-less declaration (P4): named, not minted — **on the new pass only** (P17, D4).
4. The two brief texts that steer a session into the dead end (P5, P8).
5. The first tests of the declaration reader itself: `idcheck.declared_stories`' heading grammar
   and the per-declaration claim check have no test anywhere in the suite today (P18), and §1
   rests on both.

### Out of scope

* **`has_stories` and `feeder.stories_before_plan` are not touched.** No row kind changes, no
  new config key, no new default.
* **The 67 specs of P6 that cite ids nothing declares.** A citation is not a declaration; the
  record will not invent a heading for one. Repairing them is a spec-amend's work, card by card.
* **A Bug filed for a skipped declaration.** The pass prints its line; it files nothing, and it
  needs no exemption to: a skip line is a tick-log line, and no source `cmd_file_bugs` reads is
  the tick log — it files from CI, refusals, rule checks, record errors, outcomes, repeats, the
  README and the invariants (`asf/tick/file_bugs.py`). The repair is an amendment to the spec, and
  the line is what asks for it (D10).
* **`asf new story`** keeps working exactly as it does, and stays the better route on a host that
  reaches the record: the id it prints is authoritative.
* **The host-side stopgap.** This removes the need to mint by hand; it does not script it.
* **Task minting from a plan.** The plan path's Tasks, order, duplicate and decision checks are
  untouched.
* **The plan path's acceptance-less declaration (P4, P17).** It keeps minting the empty card
  exactly as it does today, and `asf check`'s story-shape rule keeps naming it. Making that path
  skip instead would be *quieter*, because the refusal it would need cannot fire (P17a, P17b) and
  there is no later tick to fire it on (P17c) — so `asf/record/idcheck.py` is not edited by this
  change either, and D4 binds the new pass alone.
* **Re-linking the Tasks of the 16 `building …` Features to the Stories this mints (P13, P14).**
  The 102 `story … has no Task listing it in stories:` findings the backfill adds are true, and
  their cause — a Task minted before its Story was a card, its `stories:` id dropped by
  `stories_of` — is a defect of its own standing on the trunk. Writing those links back is a
  card of its own, not this one.

### The choices

## The design

### §1 — `asf/record/spec_stories.py`, the new pass

One module, one public function, shaped like `mint_plan_tasks`: a staged writer whose refused
cards are dropped from the returned list.

```python
"""asf.record.spec_stories — the Story cards a landed spec declares (F-0318).

A session that cannot reach the record declares each Story in the spec as a
``### S-nnnnn: <title>`` heading with its checkbox acceptance lines under it, from its own
claimed block. Until F-0318 those declarations were minted in one place only —
:mod:`asf.record.plan_tasks`, inside the branch a landed *plan* opens — while the feeder's
stories-first gate (:func:`asf.feeder.rows.has_stories`) held the plan behind the cards. This
pass closes that cycle: it runs in the tick's record step after the ingest and mints a declared
Story as soon as the Feature's **spec** is on the trunk, with no plan required.

A declaration it will not mint is named on its own line and skipped, and the rest of the spec
still mints: an id no claim covers, and a heading with no acceptance line (a Story is a card
with checkbox acceptance — ``asf check`` refuses one without).
"""
```

`mint_spec_stories(root, product, ev, out=print, read_ref=None)` is `mint_plan_tasks`'s wrapper,
verbatim in shape, under its own writer name so a refused card is attributed to this pass in the
`INVARIANT <id>: spec-stories refused <path> — <message>` line and in the tick's Bug filer:

```python
def mint_spec_stories(root, product, ev, out=print, read_ref=None):
    from asf.record import stage
    made, staged, _findings = stage.guarded(root, 'spec-stories', _mint,
                                            (product, ev, out, read_ref),
                                            product=product, out=out)
    refused = set(staged.refused)
    return [i for i in made if not any(p.endswith(f"/{i}.md") for p in refused)]
```

`_mint` is two passes, the same split `plan_tasks._mint` uses so every ref is read in one batch:

**The collection pass** reads metadata only. For each `fid` in `sorted(canonical)`:

* not `type == 'feature'`, or `state` in `DONE_STATES`, or `is_retired(meta)` → skip. (No
  `has_task_child` guard — D8.)
* `_slug, fev = match_feature(meta, {**(ev or {}), 'features': features})`, then
  `ref = spec_ref(fev)` — a `spec_ref` beside `plan_ref` in `plan_tasks` (§2.2), the same two
  lines against the `spec`/`spec_on_main` pair: `(fev or {}).get('spec')`, then
  `ref if ref and fev.get('spec_on_main') else None`. The guard on `fev` is not decoration.
  `match_feature` returns `(slug, None)` for a Feature the evidence has no entry for
  (`asf/record/ingest.py:242`) — **11 of today's 145 live Features** (`F-0296`, `F-0297`,
  `F-0298`, `F-0299`, `F-0302`, `F-0304`, `F-0309`, `F-0316`, `F-0317`, `F-0319`, `F-0322`) — and
  §1's loop reaches those where the plan path's `has_task_child` guard never does. An unguarded
  `fev.get('spec_on_main')` raises `AttributeError` on the first of them (measured: `F-0296`, all
  11), inside the collection pass, which runs to completion *before* anything is minted:
  `stage.guarded` catches nothing (`asf/record/stage.py:216-228`) and `run_record_fast` has no
  handler, so the exception would take the whole record step with it and **zero** cards would be
  minted on the very first tick. Without a ref, skip (D9).
* `if meta.get('decided') is not True and not own_doc(fid, ref, ev, 'spec'): continue` — the same
  rule and the same reason as the plan path's (a migrated record links dozens of old documents to
  cards nobody ordered), but **silent where the plan path prints** (`plan_tasks.py:139-142`,
  "… is on the trunk but names `<fid>` nowhere — not decided, so nothing minted"). That is a
  deliberate departure, not an inheritance: this guard is reached by a candidate set of 121
  Features (D16) where the plan path's is reached by a handful, and D10's arithmetic — a line here
  repeats on every tick for ever — applies to it with the most force. A migrated record would
  otherwise print dozens of lines a tick about documents nobody ordered.
* else `candidates.append((fid, ref, spec_path))`.

**The read** is one batch, with the tests' per-ref seam kept:

```python
refs = [ref for _fid, ref, _path in candidates]
texts = {ref: read_ref(ref) for ref in refs} if read_ref is not None \
    else evidence.read_refs(refs, product=product)
```

**The minting pass**, per candidate:

```python
if not text:
    out(f'spec-stories: {fid}: {spec_path} could not be read — nothing minted')
    continue                                   # the plan path's own line, `plan_tasks.py:158-160`
declared = idcheck.declared_stories(text)
fresh = {s: d for s, d in declared.items() if s not in canonical and s not in seen}
if not fresh:
    continue                                  # the steady state, and silent (D10)
minted = []
for sid, d in fresh.items():                   # declaration order
    if not d['acceptance']:                    # the free check first (D15)
        out(f"spec-stories: {fid}: {spec_path} declares {sid} with no acceptance line — "
            f"not minted (put `- [ ] <line>` under its heading; a Story is a card with "
            f"checkbox acceptance)")
        continue
    if claimed is None:
        claimed = _claim_view(root)            # one fetch per tick, lazily (P15, D15)
    bad = idcheck.check_doc(f'### {sid}: {d["title"]}', canonical, claimed, fid)
    if bad:
        out(f"spec-stories: {fid}: {spec_path} declares {sid}, an id no claim covers: "
            f"{'; '.join(bad)} — not minted (take ids from the session's BACKLOG_ID_RANGE)")
        continue
    write_new_item(root, canonical, 'story', sid,
                   {'title': d['title'] or f'{fid} {sid}', 'parent': fid}, '', today(),
                   f'declared in {spec_path}', acceptance=d['acceptance'],
                   shape=('parent-feature', 'story'))
    seen.add(sid)
    minted.append(sid)
if minted:
    out(f"spec-stories: {fid}: {len(minted)} Story(ies) declared in {spec_path}: "
        f"{', '.join(minted)}")
    made.extend(minted)
```

**There is no record reload between Features**, and this is where the pass departs from the plan
path on purpose. `write_new_item` inserts the card it writes into `canonical` in place
(`asf/record/ids.py:217-221`), with the `meta` it was given — which is everything the next
Feature's two reads of `canonical` want: `fresh`'s `s not in canonical`, and `check_doc`'s
`canonical.get(iid)['meta']['title']` for the already-exists branch (`idcheck.py:48-49`). The
plan path reloads the whole record after each minting Feature anyway, and it has never cost
anything there because it runs over the handful of Features with no Task child. Over §1's
candidate set it would: `load_items` + `canonicalize` is **1.4 s** over today's 2478 cards (3.9 s
on the first, cold read), and the 23 minting Features of the backfill tick (P13) make that
**~32 s** added to a tick, for a view the in-place insert has already produced. The inserted record is the same shape `load_items`
builds — the identical seven keys, `meta` the frontmatter it was written with
(`core.py:139-142` against `ids.py:217-221`) — so this is not a thinner view of the record, it is
the same one.

So the pass reads the record once, at the top. `seen` is then belt and braces rather than the
mechanism: `fresh`'s own `s not in canonical` already excludes an id an earlier Feature minted in
this same pass, and `seen` is what keeps "two specs declaring the same id mint it once" true
without depending on `write_new_item` to keep inserting in place. It is one `set`, and S-91005
pins the behaviour either way.

`spec_path` is `ref.split(':', 1)[1] if ':' in ref else ref` — the same derivation
`plan_tasks.py:135` uses for `plan_path`, and the reason the module holds no `docs/specs` literal
for `tools/check_conventions.sh` to find (P9).

`seen` is the ids minted in this pass: two specs declaring the same id mint it once, for the
first Feature that declares it, and the second is left to `fresh`'s own filter on the next tick
once `canonical` holds it. `_claim_view`, `DONE_STATES`, `own_doc` and `spec_ref` are imported
from `plan_tasks` rather than copied — they are the same view of the same thing.

When it is there: a Feature whose spec landed this tick and declares three sound Stories has
three Story cards under it before the wave runs, one tick log line naming them, and
`needs_stories` reading `False`.

### §2 — `asf/record/plan_tasks.py`, two additive edits and no behaviour change at all

1. `doc_alias(ev, path, field='plan')` and `own_doc(fid, ref, ev, field='plan')` replace the
   bodies of `plan_alias` and `own_plan`, which become one-line callers (D7). Both keep their
   names, their signatures and their docstrings' three routes. The `field` has to reach **two** of
   those routes, not one: `own_doc`'s **second** route reads `lane_docs[fid][field]` in place of
   the literal `'plan'` (`:80`), and its **third** — the H1 alias — goes through `doc_alias`,
   which keys the features entry by `_path_only(f.get(field))` in place of the literal
   `f.get('plan')` (`:58-65`). `own_plan`'s own docstring (`:69-75`) is what orders them — named
   after its id (`:70`), landed by a merged lane PR (`:70-71`), headed `# F-0047` (`:71-72`) — and
   its body takes them in that order at `:78`, `:80` and `:82`; P7 reads them the same way.
   Neither edit changes behaviour: the same three routes, the same answers, for `field='plan'`.
2. `spec_ref(fev)` joins `plan_ref` (`:52-55`) — two lines against the `spec`/`spec_on_main` pair,
   `fev`-guarded exactly as `plan_ref` is, and the function §1's collection pass calls. It is
   additive: no caller of `plan_ref` moves, and nothing in this module calls `spec_ref`.
3. The spec-declaration step inside `_mint` stays exactly as it is (D5), **including** the
   acceptance-less declaration it mints with an empty `- [ ] ` list (P4). Its `fresh` set is
   empty once §1 has run, which the existing `if fresh:` already handles.

Why the acceptance rule stops at §1 is P17, and it is worth stating where the edit would have
gone. A `continue` inside `for sid, d in fresh.items():` (`:210-215`) would skip the write — and
then say so nowhere: the loop's report is `len(fresh)` / `', '.join(fresh)` (`:216-217`), which
counts and names the declaration it did not write; `phantom_stories` cannot catch the Task that
cites it (a heading declares the id whether or not acceptance follows, `idcheck.py:134`, and a
Task's `stories:` line is not read by `cited_stories` at all); and `has_task_child` (`:125`)
means the Feature is never revisited. The card that is minted today is at least named, by id, on
every `asf check` run (`check.py:388-392`). So this path keeps minting it, the asymmetry with §1
is deliberate, and S-91006 pins **both** halves so neither drifts.

### §3 — `asf/tick/tick.py`, the record step

Inside `run_record_fast`'s `if product.repo_dir:` block, between the ingest and `plan-tasks`
(D12):

index" — so it becomes "ingest → **spec-stories** → plan-tasks → replan → slice → index". The
sentence after it ("Every one of them changes which rows may launch … so they run on every tick,

### §5 — `asf/briefs/templates/spec.md` and `asf/briefs/build.py`

The spec template's item 5 (P5) asks for both forms — the one-line block a human reads for
coverage, and the heading the record mints from:

```
5. **`## Stories`** — REQUIRED, and last. One line per Story:
   `- <id>: <title> — acceptance: <the test that proves it>`, with ids from this session's
   `BACKLOG_ID_RANGE`; then, below those lines, each Story again as a
   `### <id>: <title>` heading with its acceptance as `- [ ] <line>` lines beneath it.
   That heading is what the record mints the Story card from when this spec lands — a line
   without one is prose, and the Feature's plan stays blocked behind the missing card.
   A spec without the block is not reviewable, because the plan that follows mints one Task per
   Story from it and the review checks coverage against it.
```

`STORIES_FIRST` (`build.py:690`; the paragraph at `:707-712`) keeps both routes and corrects the
landing (P8):

* "The record mints those cards from the claimed block when the plan lands" becomes "The record
  mints those cards from the claimed block in the next tick after **this spec** lands — no plan
  is needed, and none can start until they exist."
* The paragraph gains the acceptance rule D4 makes binding: a heading with no `- [ ] ` line
  under it mints nothing and the tick log names it.

No other template changes, and no `{placeholder}` is added or removed — `tests/test_briefs.py`'s
`PlaceholderTest` and `GenericTest` hold both.

## Records

What the change writes down:

* **Story cards.** One `stories/S-nnnnn.md` per sound declaration: `parent` the Feature,
  `title` the declaration's, `state: New`, the checkbox lines as its `## Acceptance` list, and a
  History line `- <date>: created (declared in <spec path>) — shape: parent-feature → story`.
  The id is the spec's own, from its session's claimed block — never minted from the counter.
* **The index.** `do_index` derives the Feature's `children` from each card's `parent:`
  (P3), so the minted Story appears in `index.json` under the Feature in the same record step.
  That list is what `has_stories` counts; nothing writes it directly.
* **The tick log.** One line per Feature that minted — `spec-stories: F-nnnn: 3 Story(ies)
  declared in docs/specs/f-nnnn.md: S-…, S-…, S-…`, naming only what was written — and one line
  per declaration skipped, naming the id, the spec and the reason (no acceptance line; an id no
  claim covers), plus the plan path's own line for a spec ref that could not be read. A Feature
  whose declarations are all cards already is silent, and so is one whose spec names it nowhere
  (D10, §1). A **skip line repeats on every tick** until the spec is amended: 9 lines a tick
  across 2 specs on today's trunk (P16). The step is timed as `spec-stories`, beside `ingest` and
  `plan-tasks`.
* **The first tick: one sweep of the corpus — 126 Story cards across 23 Features against the
  record's own `origin/main`, which is the root that tick reads (P13) — then nothing.** The pass is
  a backfill as well as a fix, and the record it writes on the tick it lands is those cards, 86 of
  which are immediately counted by the standing
  `story … has no Task listing it in stories:` class — 152 findings today, 238 after (P14). One
  class, already standing, so `file-bugs` files no Bug for it. Every tick after that writes only
  what a spec newly declares. The count is a measurement of one moment against one named root and
  grows with the corpus (157 across 29 on the day-old record clone, 125 across 22 earlier the same
  day — and 238 for the class either way); what the record will show is one backfill tick, then
  the steady state.
* **A refusal.** A card a record invariant refuses is put back by `stage.guarded` and printed as
  `INVARIANT <id>: spec-stories refused <path> — <message>`, kept in `stage.REFUSED` for the
  tick's existing filer. The pass leaves its id out of the list it returns.
* **The writer order.** `stage.WRITERS` gains `'spec-stories'` between `'ingest'` and
  `'plan-tasks'`, and `run_record_fast`'s docstring names it in the same place (§3, §4). Neither
  is read as a gate; both are the record's own statement of what runs in what order.
* **No new configuration, and no new row kind.** Nothing is written to a product yaml, and
  `asf/feeder/rows.py` is not edited.
