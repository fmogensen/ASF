# F-0318 — the cards are minted by the spec that declares them

The stories-first gate and the Story-minting pass each wait for the other.

`asf/feeder/rows.py:421` holds a Feature behind `has_stories`, which counts Story **cards**:

```python
def has_stories(items, feature):
    return any(not ix.retired(s) for s in ix.children(items, feature or {}, 'story'))
```

A session that cannot reach the record — which today means every cloud session — cannot run
`asf new story`, so it does the one thing the briefs offer instead: it *declares* each Story in
the spec as a `### S-nnnnn: <title>` heading with checkbox acceptance lines under it, from its own
`BACKLOG_ID_RANGE`. That declaration is minted in exactly one place, `asf/record/plan_tasks.py`,
and only inside the branch that a **landed plan** opens:

```python
ref = plan_ref(fev)
if not ref:
    continue
...
candidates.append((fid, ref, plan_path))
if fev.get('spec') and fev.get('spec_on_main'):
    specs[fid] = fev['spec']
```

`specs[fid]` is only ever written for a Feature that already reached `candidates`, and
`candidates` requires a plan on the trunk. So the spec's declarations wait on a plan; the plan
row waits on `has_stories`; `has_stories` waits on the cards. Nothing in the loop breaks the
cycle, and nothing prints a word about it (P1).

The card names the cost: on 2026-10-08 the cycle stalled F-0280, F-0303, F-0306, F-0293, F-0295,
F-0254 and F-0290, each re-firing a spec-amend, adjudicate or correct session that ends
"needs input" and spends budget for nothing, until the cards were minted on the host by hand.

This change moves the minting to the moment the declaration becomes a decision: **a Story a
Feature's landed spec declares becomes a card in the next tick's record step, with no plan
required.** The gate keeps counting cards; the cards simply arrive in time.

## Decisions

### Preconditions — measured in this worktree at `c599985a2`, re-verified against `origin/main` at `adf00a222`, 2026-10-10

Every number below came out of this checkout, not from a prior document. The trunk moved between
the two measurements (`asf/feeder/rows.py` among the files it touched, for B-0070's
`in_progress_by` row filter) and not one citation below moved with it: `has_stories` is still
`asf/feeder/rows.py:421`, and `plan_tasks.py`, `check.py`, `stage.py`, `tick.py`, `idcheck.py`
and both brief files are byte-identical across the two shas.

* **P1 — a landed spec that declares a Story mints nothing, and says nothing.** A fixture record
  holding `E-0001` and a decided `F-0001`, evidence carrying
  `spec: origin/main:docs/specs/f-0001.md`, `spec_on_main: True`, `alias: F-0001`, and no plan at
  all; the spec text declares `### S-29501: the reader reads` with two checkbox lines.
  `plan_tasks.mint_plan_tasks` returns `[]`, its `out` receives **zero** lines, and
  `stories/` on disk is **empty**. The silence is itself a defect: the deadlock leaves no trace
  in the tick log for an operator to read.
* **P2 — the gate is on by default and reads `True` for that Feature forever.**
  `rows.stories_before_plan(product)` is `True` with no `feeder` key at all;
  `rows.has_stories` is `False` and `rows.needs_stories` is `True` for a Feature whose
  `children` list is empty.
* **P3 — one card is the whole difference.** Add `S-29501` to the same index with
  `parent: F-0001` and list it in the Feature's `children`: `rows.needs_stories` reads `False`.
  The Feature's `children` list is not written by anything a session does — it is derived from
  each card's `parent:` at index time (`asf/record/core.py:277-281`, `:413`), so minting the card
  is sufficient and `do_index`, which already runs after the record's passes
  (`asf/tick/tick.py:138`), publishes it.
* **P4 — a declaration with no acceptance line mints a card the record then refuses.** The same
  fixture *with* a landed plan, whose spec declares a Story heading with a title and nothing
  beneath it: `mint_plan_tasks` returns that Story's id and the plan's Task, and the card's
  `## Acceptance` section is `'\n- [ ] \n\n'`. `check.ACCEPTANCE_ITEM_RE`
  (`asf/record/check.py:24`, `^- \[[ x]\]\s+\S`) does **not** match it, so
  `asf check`'s story-shape rule (`:388-392`) flags the card the pass just minted. The record
  invariants that run at stage time (I1, I2, I3, I10, I11, I14 — `asf/invariants.py:55`) do not
  cover card shape, so nothing refuses it on the way in.
* **P5 — a spec written to the brief's own template declares nothing.** `asf/briefs/templates/spec.md:21-24`
  asks for `## Stories` as `- S: <title> — acceptance: <the test that proves it>` — no id and no
  heading. `idcheck.declared_stories('## Stories\n\n- S: the reader reads - acceptance: tests.test_reader\n')`
  returns `{}`. A first-pass spec therefore cannot mint a Story card by any route, before or
  after this change, which is why every new Feature costs at least one spec-amend round.
* **P6 — the corpus says the same.** Of the **228** specs tracked under `docs/specs/`, **54**
  carry a Story declaration heading, **67** cite Story ids in a `## Stories` section with no
  declaration behind any of them — each one a phantom that refuses a plan whole
  (`plan_tasks._mint`'s `phantom_stories` step) — and **107** neither declare nor cite.
* **P7 — the evidence has a spec route for every rule the plan route uses.**
  `evidence.lane_docs` returns `{ID: {"spec": [path], "plan": [path], "prs": [n]}}`
  (`asf/evidence/evidence.py:1329-1331`), so `own_plan`'s third route (a doc a merged lane PR
  brought onto the trunk, `asf/record/plan_tasks.py:80`) generalises to the spec by changing one
  key.
* **P8 — the spec-amend brief promises the wrong landing.** `asf/briefs/build.py:710` (inside
  `STORIES_FIRST`, `:690`) tells the session "The record mints those cards from the claimed block
  when the plan lands" — the sentence that describes the deadlock as if it were the mechanism.
  Its paragraph is `:707-712`.
* **P9 — a new `asf/` module sits inside two whole-tree fences, and the shape §1 describes clears
  both.** `tests/test_lifecycle.py:1035` (`test_no_module_but_lifecycle_derives_a_state_word`)
  walks every `asf/**/*.py` and forbids a session-lifecycle word
  (`STATE_WORDS = (lc.DEAD, lc.DEAD_PID, lc.WORKING, lc.ENDED_AWAITING_TICK)`, `:1002`) as a
  string literal outside `asf/workers/lifecycle.py`; §1 holds none — the card states it reads are
  `plan_tasks.DONE_STATES` (`('Resolved', 'Closed')`, `asf/record/plan_tasks.py:32`), which that
  tuple does not cover. `tools/check_conventions.sh` scans the same tree for a hardcoded product
  convention, which includes a document-tree path: §1 therefore takes `spec_path` from the
  evidence ref (`ref.split(':', 1)[1]`, the way `plan_tasks.py:135` takes `plan_path`) and writes
  no `docs/specs` literal.
* **P10 — a closed hotfix branch already tried a different remedy.** `fix/F-0318-stories-gate`
  (PR #1262, **closed**, titled "do not merge") made the record's "story … has no Task listing it
  in `stories:`" refusal a warning and taught `declared_stories` to read `- S-n: title` bullets as
  declarations. It is not on the trunk (`git merge-base --is-ancestor` says so) and nothing in it
  is a precondition of this change. It is named here so the coder does not resurrect it: see D13.
* **P11 — driving the record step leaks `$ASF_PRODUCT` into every later test in the process, and
  the suite is already red on it.** `asf/tick/tick.py:107` (`_record_env`, `:102`) does
  `os.environ['ASF_PRODUCT'] = product.name` and nothing restores it; no test under `tests/`
  sets or clears that variable. So `python3 -m unittest tests.test_tick tests.test_record_stage`
  fails today — `tests.test_record_stage.R11I2AfterRestamp.test_r11_i2_after_restamp` errors with
  `asf.env.ConfigError: no product config at <its own temp home>/products/sample.yaml`, because
  its `cmd_ingest(product=None)` falls back through `env.PRODUCT_SOURCES` (`asf/env.py:431`) to
  the name `test_tick` left behind. Each module is green alone (`tests.test_record_stage` on its
  own: 3 tests, OK; with `tests.test_lifecycle`: 294 tests, OK). This is pre-existing and nothing
  in this change causes it — but `tests/test_spec_stories.py` drives the same record step (S-91008
  asserts the pass's place in it), so written the way `tests/test_tick.py` is, it would widen the
  leak to a second module. The new module therefore saves and restores `$ASF_PRODUCT` around any
  call that reaches `_record_env`. Repairing `_record_env` itself is out of scope — it is a Bug of
  its own, and this spec changes no line of it.
* **P12 — a prose-wide claim check refuses most of the corpus, and the existing code already
  checks a synthesised heading instead.** `idcheck.check_doc(spec_text, canonical, claims, <id>)`
  over each of the **228** specs of P6, against the live record and the live claim refs, returns
  findings for **141** of them — every one an id the spec names that no claim of that Feature's
  covers (`S-5800` in `f-0002.md`, `S-28500` in `f-0010.md`, and so on): prior-art rows,
  superseded ids, a sibling Feature's Stories. That is the measurement behind D6, and it is why
  the whole-spec route is not taken. The refinement matters: `idcheck._prose` (`:27`) replaces
  every fenced block and every inline code span with a space before parsing, so an id a spec
  quotes **inside backticks** is invisible to the check and an id in plain prose is not — the
  rate above is the plain-prose ids alone. This very document's own foreign quote (`S-29501`, P1
  and P3) is backticked, so the whole-text check over *this* spec returns zero findings; it is
  not evidence either way, and D6 does not rest on it. The pattern §1 uses is already in the
  tree: `plan_tasks.py:203` claim-checks a **synthesised** `### <id>: <title>` block for the
  freshly declared Stories rather than the document's prose — as one batch for the whole set,
  where §1 runs it per declaration so one uncovered id cannot take the sound ones with it (D3).

### In scope

1. A new record pass that mints the Stories a Feature's landed spec declares, with no plan
   required, and names every declaration it will not mint.
2. Its place in the tick's record step, before the wave decides any row — and its name in the
   writer order that step's docstring and `stage.WRITERS` both claim to list.
3. The acceptance-less declaration (P4): named, not minted — on both the new pass and the
   existing plan path.
4. The two brief texts that steer a session into the dead end (P5, P8).

### Out of scope

* **`has_stories` and `feeder.stories_before_plan` are not touched.** No row kind changes, no
  new config key, no new default.
* **The 67 specs of P6 that cite ids nothing declares.** A citation is not a declaration; the
  record will not invent a heading for one. Repairing them is a spec-amend's work, card by card.
* **A Bug filed for a skipped declaration.** The pass prints its line; it files nothing.
  (B-0138 is the standing rule against a record-error Bug for a self-healing class.)
* **`asf new story`** keeps working exactly as it does, and stays the better route on a host that
  reaches the record: the id it prints is authoritative.
* **The host-side stopgap.** This removes the need to mint by hand; it does not script it.
* **Task minting from a plan.** The plan path's Tasks, order, duplicate and decision checks are
  untouched.

## The design

### §1 — `asf/record/spec_stories.py`, the new pass

One module, one public function, shaped like `mint_plan_tasks`: a staged writer whose refused
cards are dropped from the returned list.

```python
"""asf.record.spec_stories — the Story cards a landed spec declares (F-0318).

A session that cannot reach the record declares each Story in the spec as a
``### S-nnnnn: <title>`` heading with its checkbox acceptance lines under it, from its own
claimed block. Until F-0318 those declarations were minted in one place only —
:mod:`asf.record.plan_tasks`, inside the branch a landed *plan* opens — while the feeder's
stories-first gate (:func:`asf.feeder.rows.has_stories`) held the plan behind the cards. This
pass closes that cycle: it runs in the tick's record step after the ingest and mints a declared
Story as soon as the Feature's **spec** is on the trunk, with no plan required.

A declaration it will not mint is named on its own line and skipped, and the rest of the spec
still mints: an id no claim covers, and a heading with no acceptance line (a Story is a card
with checkbox acceptance — ``asf check`` refuses one without).
"""
```

`mint_spec_stories(root, product, ev, out=print, read_ref=None)` is `mint_plan_tasks`'s wrapper,
verbatim in shape, under its own writer name so a refused card is attributed to this pass in the
`INVARIANT <id>: spec-stories refused <path> — <message>` line and in the tick's Bug filer:

```python
def mint_spec_stories(root, product, ev, out=print, read_ref=None):
    from asf.record import stage
    made, staged, _findings = stage.guarded(root, 'spec-stories', _mint,
                                            (product, ev, out, read_ref),
                                            product=product, out=out)
    refused = set(staged.refused)
    return [i for i in made if not any(p.endswith(f"/{i}.md") for p in refused)]
```

`_mint` is two passes, the same split `plan_tasks._mint` uses so every ref is read in one batch:

**The collection pass** reads metadata only. For each `fid` in `sorted(canonical)`:

* not `type == 'feature'`, or `state` in `DONE_STATES`, or `is_retired(meta)` → skip. (No
  `has_task_child` guard — D8.)
* `_slug, fev = match_feature(meta, {**(ev or {}), 'features': features})`, then
  `ref = fev.get('spec') if fev.get('spec_on_main') else None`; without one, skip (D9).
* `if meta.get('decided') is not True and not own_doc(fid, ref, ev, 'spec'): continue` — silent,
  the same rule and the same reason as the plan path's: a migrated record links dozens of old
  documents to cards nobody ordered.
* else `candidates.append((fid, ref, spec_path))`.

**The read** is one batch, with the tests' per-ref seam kept:

```python
refs = [ref for _fid, ref, _path in candidates]
texts = {ref: read_ref(ref) for ref in refs} if read_ref is not None \
    else evidence.read_refs(refs, product=product)
```

**The minting pass**, per candidate:

```python
declared = idcheck.declared_stories(text)
fresh = {s: d for s, d in declared.items() if s not in canonical and s not in seen}
if not fresh:
    continue                                  # the steady state, and silent (D10)
if claimed is None:
    claimed = _claim_view(root)                # read once, and only when a card is about to mint
minted = []
for sid, d in fresh.items():                   # declaration order
    bad = idcheck.check_doc(f'### {sid}: {d["title"]}', canonical, claimed, fid)
    if bad:
        out(f"spec-stories: {fid}: {spec_path} declares {sid}, an id no claim covers: "
            f"{'; '.join(bad)} — not minted (take ids from the session's BACKLOG_ID_RANGE)")
        continue
    if not d['acceptance']:
        out(f"spec-stories: {fid}: {spec_path} declares {sid} with no acceptance line — "
            f"not minted (put `- [ ] <line>` under its heading; a Story is a card with "
            f"checkbox acceptance)")
        continue
    write_new_item(root, canonical, 'story', sid,
                   {'title': d['title'] or f'{fid} {sid}', 'parent': fid}, '', today(),
                   f'declared in {spec_path}', acceptance=d['acceptance'],
                   shape=('parent-feature', 'story'))
    seen.add(sid)
    minted.append(sid)
if minted:
    out(f"spec-stories: {fid}: {len(minted)} Story(ies) declared in {spec_path}: "
        f"{', '.join(minted)}")
    by_id, _errors = load_items(root)
    canonical, _dupes = canonicalize(by_id)
    made.extend(minted)
```

`spec_path` is `ref.split(':', 1)[1] if ':' in ref else ref` — the same derivation
`plan_tasks.py:135` uses for `plan_path`, and the reason the module holds no `docs/specs` literal
for `tools/check_conventions.sh` to find (P9).

`seen` is the ids minted in this pass: two specs declaring the same id mint it once, for the
first Feature that declares it, and the second is left to `fresh`'s own filter on the next tick
once `canonical` holds it. `_claim_view` and `DONE_STATES` are imported from `plan_tasks` rather
than copied — they are the same view of the same thing.

When it is there: a Feature whose spec landed this tick and declares three sound Stories has
three Story cards under it before the wave runs, one tick log line naming them, and
`needs_stories` reading `False`.

### §2 — `asf/record/plan_tasks.py`, three edits and no behaviour removed

1. `doc_alias(ev, path, field='plan')` and `own_doc(fid, ref, ev, field='plan')` replace the
   bodies of `plan_alias` and `own_plan`, which become one-line callers (D7). Both keep their
   names, their signatures and their docstrings' three routes; `own_doc`'s third route reads
   `lane_docs[fid][field]` instead of the literal `'plan'` (P7).
2. The spec-declaration step inside `_mint` stays exactly as it is (D5). Its `fresh` set is
   empty once §1 has run, which the existing `if fresh:` already handles.
3. The acceptance-less declaration is named, not minted, on this path too (D4, P4) — the one
   line that changes behaviour here:

```python
for sid, d in fresh.items():
    if not d['acceptance']:
        out(f"plan-tasks: {fid}: {plan_path} declares {sid} with no acceptance line — "
            f"not minted (put `- [ ] <line>` under its heading)")
        continue
    write_new_item(..., acceptance=d['acceptance'], ...)
```

A Task that cites a Story skipped this way is then refused by the existing `phantom_stories`
step on the next tick — loudly, by id, which is the outcome D4 is for.

### §3 — `asf/tick/tick.py`, the record step

Inside `run_record_fast`'s `if product.repo_dir:` block, between the ingest and `plan-tasks`
(D12):

```python
if product.repo_dir:
    from asf.evidence import evidence
    from asf.record.spec_stories import mint_spec_stories
    ev = evidence.load(product=product)
    with timed('spec-stories'):   # F-0318: a landed spec's declared Stories, before any plan
        mint_spec_stories(root, product, ev)
    from asf.record.plan_tasks import mint_plan_tasks
    with timed('plan-tasks'):     # B-0060: a landed plan's Tasks become cards, once
        mint_plan_tasks(root, product, ev)
```

The `evidence.load(product=product)` call that `mint_plan_tasks` makes today is hoisted and
shared: both passes read the same evidence, and the tick does one load where it did one.

`run_record_fast`'s docstring names its parts in order — "ingest → plan-tasks → replan → slice →
index" — so it becomes "ingest → **spec-stories** → plan-tasks → replan → slice → index". The
sentence after it ("Every one of them changes which rows may launch … so they run on every tick,
before the wave") is already true of this pass: a minted Story is what clears the gate.

### §4 — `asf/record/stage.py`, the writer order

`WRITERS` (`:30`) is by its own comment "the record writers in the order the tick runs them", so
`'spec-stories'` goes in ahead of `'plan-tasks'`:

```python
WRITERS = ('backfill', 'ingest', 'spec-stories', 'plan-tasks', 'plan-order', 'file-bugs',
           'rollup', 'index', 'widen', 'set', 'groom', 'reopen')
```

This is a documenting edit, not a gate: the same comment says "a writer not listed here still
runs, staged under its own name", so §1 works without it — and the tuple's claim about order would
be false. Its only reader is `tests/test_contracts.py:226`, which asserts `'ingest'` is a member
and counts nothing, so the entry is safe to add.

### §5 — `asf/briefs/templates/spec.md` and `asf/briefs/build.py`

The spec template's item 5 (P5) asks for both forms — the one-line block a human reads for
coverage, and the heading the record mints from:

```
5. **`## Stories`** — REQUIRED, and last. One line per Story:
```

## Records

What the change writes down:

* **Story cards.** One `stories/S-nnnnn.md` per sound declaration: `parent` the Feature,
  `title` the declaration's, `state: New`, the checkbox lines as its `## Acceptance` list, and a
  History line `- <date>: created (declared in <spec path>) — shape: parent-feature → story`.
  The id is the spec's own, from its session's claimed block — never minted from the counter.
* **The index.** `do_index` derives the Feature's `children` from each card's `parent:`
  (P3), so the minted Story appears in `index.json` under the Feature in the same record step.
  That list is what `has_stories` counts; nothing writes it directly.
* **The tick log.** One line per Feature that minted — `spec-stories: F-nnnn: 3 Story(ies)
  declared in docs/specs/f-nnnn.md: S-…, S-…, S-…` — and one line per declaration skipped,
  naming the id, the spec and the reason (an id no claim covers; no acceptance line). A Feature
  that minted nothing is silent (D10). The step is timed as `spec-stories`, beside `ingest` and
  `plan-tasks`.
* **A refusal.** A card a record invariant refuses is put back by `stage.guarded` and printed as
  `INVARIANT <id>: spec-stories refused <path> — <message>`, kept in `stage.REFUSED` for the
  tick's existing filer. The pass leaves its id out of the list it returns.
* **The writer order.** `stage.WRITERS` gains `'spec-stories'` between `'ingest'` and
  `'plan-tasks'`, and `run_record_fast`'s docstring names it in the same place (§3, §4). Neither
  is read as a gate; both are the record's own statement of what runs in what order.
* **No new configuration, and no new row kind.** Nothing is written to a product yaml, and
  `asf/feeder/rows.py` is not edited.
