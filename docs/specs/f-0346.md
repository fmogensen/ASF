# F-0346 — Flow conservation: every step has a required successor, checked each tick

Epic: E-0003 — ASF 0.3 — autonomous delivery
Base: `edce03798` (`origin/main`)

An item moves through the factory because some rule, every tick, names what comes next for it.
When no rule names one, the item does not fail — it goes **quiet**. The wave launches other work,
the board shows nothing red, and the card sits at the step it reached until a person happens to
look. Nothing in the product asserts that this cannot happen.

This Feature states the assertion as a law and runs it every tick:

> **Flow conservation.** Every open work item has a required successor this tick — a row, a
> session, work beneath it, or a *declared* reason it is parked. An item with none of those is a
> **sink**, and a sink is reported by name.

It is a conservation law in the physical sense: work put into the factory comes out of it or is
accounted for standing still. Nothing is created and nothing silently disappears.

**F-0346 reports sinks. It does not drain them.** Measured against the record clone at
`6e471a400` (2026-10-09), the law fails for **54 open items** today (§1.2, P1). Each of those is
a separate defect with a separate cause; this Feature's deliverable is that the next tick says
their names out loud, every tick, instead of a person finding them by accident. The 54 are the
check's *output*, not this spec's claim about their causes.

---

## 1. Decisions

### 1.1 In and out

**In**

- `asf/flow.py` — the law: the classes an open item can be in, the `PARKED` table of declared
  reasons, and `sinks(items, rows, inflight, occupancy)` → the items in none of them. Pure: no
  git, no gh, no filesystem, no clock.
- A fourth invariant scope, `flow`, with `FlowContext` and one check `I16`, registered beside the
  existing ten.
- One tick check point, `invariants.flow_report(...)`, called once per wave from
  `step_wave.launch` — over `candidates()`, **not** over the capacity-cut plan.
- A line per sink (`INVARIANT I16: <id> — <why>`) and a durable row per sink per tick in
  `invariants-report.jsonl`, under `flags.flow_conservation: report | off` (default `report`).
- The forward half of B-0043: a `WAITS ON <id>` row whose target is a sink makes the *target* the
  finding, every tick — not only in `tests/test_feeder.py`.
- `asf check --invariants` runs the `flow` scope read-only and exits 1 on a sink.
- `rows.BUG_SEVERITIES` — one name for the severities the feeder opens a fix row for, so the law
  and the row cannot drift (§1.3, C7).

**Out**

- **Draining the 54.** No row kind is added, no Feature is closed, no Task is launched. A Feature
  stuck at `stage: landed` with open Stories stays stuck; I16 names it. Each family needs its own
  card, and the law is what will keep raising them.
- **Filing Bugs for sinks.** `tick.file_invariant_bugs` drains `stage.drain()` — `record` scope
  only (P9). Teaching it a second source is a change to the record step's commit, not to the law.
  A sink is a line and a jsonl row here; the operator's loop over that file is the next card.
- **Wiring `asf/feeder/idle.py`.** It has no production caller (P4) and classifies *roots* only.
  §1.3, C1.
- **A `refuse` mode.** I14 has one because a close is a write that can be put back. A sink is not
  a write; there is nothing to refuse. Modes are `report` and `off`.
- **Re-deriving the pipeline.** The law reads the rows the feeder emits. It does not model
  `(type, state, stage)` → next step in a second table; see C2.

## 2. The design

### 2.1 `asf/flow.py` — the law

A new module, stdlib-only, pure. It imports `asf.views.index_reader` for `subtree` and
`asf.feeder.rows` for `is_open`, `inflight_ids` and `BUG_SEVERITIES`, and nothing else — no git,
no gh, no filesystem, no clock, so the same answer comes out of the tick, `asf check` and a test.

```python
"""asf.flow — flow conservation: every open work item has a required successor, or a declared
reason it has none.

The factory moves an item because some feeder rule names what comes next for it. When no rule
does, the item does not fail — it goes quiet, and stays at the step it reached until a person
notices. This module is the assertion that this cannot happen silently: every open work item
falls into exactly one class, and the last class is named ``SINK`` rather than dropped.

It reads the rows the feeder emits (:func:`asf.feeder.rows.candidates` — every row the index
supports, uncut by capacity) rather than re-deriving what should come next from an item's state:
a second copy of the feeder's 24 row kinds and their gates would drift, and drift here is
invisible by definition (§1.3 C2). The one thing the rows cannot say is why an item is *meant* to
stand still, and that is :data:`PARKED`, three entries long.
"""

#: The item types the feeder ever opens a row for. A Story, Rule or Decision card is not work
#: the factory launches (P16): it is never a sink and never counted.
WORK_TYPES = ('epic', 'feature', 'task', 'bug')

#: In classification order — the first that holds wins. The two that say "this item is not the
#: factory's to move" come first, so a card that is both parked and carries a row reads parked;
#: ``SINK`` is last and is the violation.
CLASSES = ('done', 'parked', 'row', 'session', 'subtree', 'SINK')

#: Why an item is parked: the fact that decides it, and what ends the park. Every entry is a
#: standing state a person or another item ends — never a step the factory takes itself.
PARKED = (
    ('removed', 'removed: the card says so', 'nothing — a removed card is answered for'),
    ('blocked', 'blocked by an open item', "the blocker's own successor"),
    ('severity', "a Bug below the feeder's bar", 'a person raising it, or closing it'),
)
```

`conserved(item, by_item, busy, items)` → `(class, detail)`, the first class of `CLASSES` that
holds:

| class | holds when | detail |
| --- | --- | --- |
| `done` | `state` in `invariants.DONE_STATES`, or `type` not in `WORK_TYPES` | the state, or the type |
| `parked` | a `PARKED` entry's fact holds | the entry's reason and what ends it |
| `row` | `by_item` has a row with this `item_id` | the row's kind and action |
| `session` | the id is in `busy` — `rows.inflight_ids(inflight)` ∪ occupancy's `busy`, `waiting_landing` and `corrections` | which of them |
| `subtree` | some item of `ix.subtree(items, item)` is in `by_item` | the first such id and its row's kind |
| `SINK` | none of the above | the step it sits at: `f"{type} {state}/{stage or '—'}"`, plus `waited on by <id>` when a row's `waits_on` names it |

`sinks(items, rows, inflight=(), occupancy=None)` → `[(item, detail)]` in id order: every item
whose class is `SINK`. `by_item` is built once from `rows`; `busy` once from `inflight` and
`occupancy`. The `waits_on` back-index is built once, so the forward read of the wait chain (C10)
costs nothing extra: a sink that some row waits on carries that in its detail, which is B-0043's
pair said from the end that matters.

Order matters and is asserted: `done` and `parked` come before `row`, so a card the feeder emits
a row for *and* that is `removed` is counted parked, not conserved by a row it should not have.
`row` comes before `subtree`, so a detail names the item's own row when it has one.

### 2.2 `asf/invariants.py` — `I16`, the `flow` scope, and the check point

Four additions, all additive; the existing ten checks and three check points are untouched.

```python
#: The points of the tick an invariant runs at.
SCOPES = ('record', 'feeder', 'lane', 'flow')
```

```python
@dataclass
class FlowContext:
    """What a ``flow``-scope check reads — the wave's own facts, before any cut:

    - ``items``: the tick's overlaid ``{id: item}`` (``index_reader.load`` plus the wave's
      ``blockedBy`` and ``after:`` overlays), the same map the feeder planned from;
    - ``rows``: :func:`asf.feeder.rows.candidates`' output — every row the index supports,
      uncut by capacity (§1.3 C5: with ``decision_limit=0``);
    - ``inflight``: the running sessions, one dict each;
    - ``occupancy``: :func:`asf.workers.lifecycle.occupancy`'s answer, or None."""
    items: dict = field(default_factory=dict)
    rows: list = field(default_factory=list)
    inflight: list = field(default_factory=list)
    occupancy: dict = None
    product: object = None


def _flow_only(check):
    def run_it(ctx):
        if not isinstance(ctx, FlowContext):
            return []
        return check(ctx)
    run_it.__name__, run_it.__doc__ = check.__name__, check.__doc__
    return run_it


def check_i16(ctx):
    """I16 — flow conservation: every open work item has a required successor this tick (a row
    of its own, a session, a row beneath it) or a declared reason it has none
    (:data:`asf.flow.PARKED`). One finding per sink, naming the step it sits at. Reported, never
    refused: a sink is a standing state, not a write, and no row is dropped or reworded —
    ``subject`` is an item id, which matches no :func:`row_key` (P8)."""
    from asf import flow
    return [Finding('I16', 'flow', item['id'], why)
            for item, why in flow.sinks(ctx.items, ctx.rows, ctx.inflight, ctx.occupancy)]


INVARIANTS.append(Invariant('I16', 'flow', _flow_only(check_i16)))
```

and the check point, beside `feeder_gate` and `lane_report`:

```python
#: ``flags.flow_conservation``: ``report`` (a line per sink + ``invariants-report.jsonl``) or
#: ``off`` (not checked). No ``refuse``: a sink is not a write (§1.3 C6).
FLOW_MODES = ('report', 'off')

#: The arguments `plan_inputs` and `candidates` share (P12) — the rest of `plan_inputs` is for
#: `plan_rows` and would raise.
CANDIDATE_KEYS = ('attempts', 'occupancy', 'groom_state', 'landed_shas', 'adjudicated',
                  'unverified_landed', 'unverified_on_trunk', 'waived')


def flow_mode(product):
    """``flags.flow_conservation`` as one of :data:`FLOW_MODES`; ``report`` when unset or
    unreadable, ``off`` on a yaml ``off`` (False) or any other value."""


def flow_context(product, items, inputs, inflight):
    """The :class:`FlowContext` for this wave: ``candidates`` over ``items`` with
    ``decision_limit=0`` and only the keys it takes, every fact read-only and soft."""


def flow_report(product, items, inputs, inflight, out=print, now=None):
    """The flow check point, once per wave: ``INVARIANT I16: <item> — <why>`` per sink and one
    ``invariants-report.jsonl`` record each (``{'at','invariant':'I16','mode':'report','item',
    'message'}``, through :mod:`asf.state.store`). Report only: returns the findings, drops no
    row, never raises. ``flags.flow_conservation: off`` returns ``[]`` and prints nothing."""
```

Soft, like every other check point (R9): a `flow_report` that raises is one
`INVARIANT flow: not checked (<error>)` line and an empty list. A store that will not take the
rows costs the record, never the tick — I14's own wording.

### 2.3 The tick's call site

`asf/tick/step_wave.py`, in `launch`, immediately after the feeder check point at `:1317`, so
every `INVARIANT` line of a wave is printed together:

```python
    # the feeder check point: a violating row is dropped, logged, and its slot goes to the next
    planned, dropped = gated_plan(items, product, running, r.sessions + extra, inputs, out=out)
    # the flow check point (F-0346): every open item has a successor or a declared park. Over
    # `candidates`, not `planned` — the capacity cut is not a missing successor (§1.3 C5, P10).
```

### S-134705: the law is a module with one answer per item

Design §2.1. Pure text over an item map: no product, no git, no record, no clock.

- [ ] asf/flow.py exists and imports nothing outside the standard library, asf.views.index_reader and asf.feeder.rows
- [ ] WORK_TYPES is exactly epic, feature, task and bug, the types the feeder ever opens a row for

- [ ] PARKED has one entry per declared park reason, each carrying the fact that decides it and what ends the park
- [ ] conserved returns a class from CLASSES and a detail string for every item of an index, never None and never a class outside the tuple
- [ ] the first class that holds wins, asserted by an item that satisfies two of them at once
- [ ] done comes before parked and parked before row, so a removed card is counted parked rather than conserved by a row it should not have
- [ ] an item whose state is Resolved or Closed reads done, and so does an item whose type is not one of WORK_TYPES

- [ ] conserved is pure: called twice on the same input it returns the same answer, and it mutates neither the item nor the item map
