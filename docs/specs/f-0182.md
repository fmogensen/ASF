# F-0182 — two clocks, one number printed

`954ee3e` gave the CI start queue a head guard: the head of the line that has waited **at the
head** past `ci.queue.head_wait_max_min` (default 20) minutes is admitted whatever is free. The
clock it counts is `head_since` — stamped when an entry *becomes* the head, cleared on every
other entry, so an admission never cascades down the line
(`asf/ci_queue.py:1813-1817`, `:2102-2120`, `:1900-1905`).

The status row prints a different clock. `_waits` renders `wait_text`, which is the age of
`since` — how long the entry has been **in line**, counting the whole time it spent behind other
entries (`asf/ci_queue.py:3600-3603`, `:1820-1823`). So the Capacity row says

```
ci queue 1, head T-0084 waits 129 min — heavy 1 free, needs 4 (Task F-0113 rank 2, 1st in line)
```

and an operator reads `129 min` against the threshold they know is `20`, concludes the guard is
broken, and asks why a head six times past the limit has not been admitted. The head had been at
the head for 12 minutes. Nothing was wrong. An operator session asked exactly this at 21:32.

The two numbers are equal only when an entry has been the head since it joined the line — the
single-entry case, which is most of what anybody has looked at, which is why the divergence was
not noticed when the guard landed. The moment a head is admitted and the entry behind it takes
over, they separate permanently, and the line goes on printing the one the guard does not use.

The fix is text. The guard is correct and is not touched. The row prints **both** clocks and the
threshold beside them, so the comparison an operator is making is the comparison the code makes:

```
ci queue 1, head T-0084 waits 129 min (12 min at the head; admitted at 20) — heavy 1 free, needs 4 (Task F-0113 rank 2, 1st in line)
```

## The design

One helper's signature in `asf/ci_queue.py`, its two callers, three docstrings, one guide
paragraph, and `tests/test_ci_queue.py`. No other module.

### 1. `_waits` — `asf/ci_queue.py:3600`

```python
def _waits(entry, now, at_head_s=None, head_max_min=None):
    """``waits 129 min (12 min at the head; admitted at 20)``: the head's hold — how long it has
    waited *in line* (``since``), and, when the head guard governs this entry, the age the guard
    actually counts (:func:`head_wait_s`, from ``head_since``) against
    ``ci.queue.head_wait_max_min``.

    The two are equal only while an entry has been the head since it joined the line; once a head
    is admitted the entry behind it starts its own clock (:meth:`Queue._mark_head`), and printing
    the in-line wait alone made a head 12 minutes old read as one starved for 129 (F-0182). The
    at-head minutes are rendered as the guard renders them — ``int(s // 60)``, the same integer
    its ``admitted after <n> min at the head`` line prints.

    ``at_head_s``/``head_max_min`` are None where the guard does not govern the entry (a batch the
    ci ceiling holds is printed as the head but is never admitted by the guard): then the wait
    alone, as before."""
    waited = wait_text(entry, now)
    text = f'waits {waited}' if waited else 'waits'
    if at_head_s is None or at_head_s == math.inf or head_max_min is None:
        return text
    return f'{text} ({int(at_head_s // 60)} min at the head; admitted at {head_max_min})'
```

`math` is already imported by the module and `math.inf` is already how `wait_text` spells an
unknown age (`:1821`), so an entry whose `since` and `head_since` are both unparseable renders
`waits` exactly as it does today.

### 2. The live path — `_status_clause`, `asf/ci_queue.py:3558-3561`

```python
        key, ok, why = line.decisions[0]
        head = line.entries[key]
        pos = f" ({head.get('label') or 'other'}, 1st in line)"
        # the guard's clock, beside the in-line wait, for the entry the guard governs: a batch
        # the ceiling holds is printed as the head but is in `skip`, and no wait admits it

            f'{_waits(head, line.queue.now, head_wait_s(head, line.queue.now) if guarded else None, head_wait_max_min(product))} — {why}')
        return f"ci queue {len(line.order)}{tag}, head {head.get('item')} {said}{pos}"
```

`ceiling_held` is recomputed with `admitted=0`, which is what `live_line` passes to `decide`
(`:3511-3517`), so `skip` here is the same set `decide` used to reach `why` — the gate cannot
disagree with the reason printed beside it.
