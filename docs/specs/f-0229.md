# F-0229 — the lane merged PR #None, and said the same thing every tick

Two failures in one tick's log, both of them a reader that never asks whether what it read exists.

The lane took `plan/T-0189` out of the gate, wrote `MERGING` with the PR number it had — `None` —
and handed that to the host:

```
held plan/T-0189: PR #None merge refused — no pull requests found for branch "None"
lane: plan/T-0189 MERGING → WAITING
```

`gh pr merge None -R <slug> --squash --delete-branch`: the number went in as the string `None`,
and `gh` read it as a *branch name*. The refusal is then an ordinary refusal — `wait(..., 'held',
green=f.get('green'))` — so the branch keeps its green, comes back to the gate next tick, reaches
`MERGING` again and is refused again, for as long as it lives. This is the shape B-0149 and the
conflict path (`AMergeConflictGoesBack`) each closed once already for a different cause: a landing
wait on a condition that no clock and no session can change.

And under it, every tick, the same three lines:

```
EVENT I9: fix/merge-refused-conflict-back merged outside the lane (no MERGING intent)
EVENT I9: fix/merge-refused-conflict-mergeable merged outside the lane (no MERGING intent)
EVENT I9: fix/quota-stale merged outside the lane (no MERGING intent)
```

`i9_events` is a pure fold over `sessions.jsonl`, which is append-only. A branch merged outside the
lane in February is merged outside the lane in every fold that comes after, so the event is re-said
— and re-recorded into `metrics/events/<day>.jsonl` — every tick, forever.

This card is: **`MERGING` is never written without a PR number a merge can use, and a merge found
outside the lane is recorded once per branch.**

## The design

### §1 `pr_number` — the one reader of a branch's PR number

`asf/harvest/lane.py`, beside `merge_prs`:

```python
def pr_number(lane, f):
    """The PR number a merge of ``f``'s branch would name, or None — the one reader of it
    (:func:`precheck`, :func:`merge_prs`). The facts' live PR first, then the lane record
    (the order :meth:`Lane.record` and :func:`asf.merge_queue._pr` already read them in), and
    failing both the host's own open PR for the branch (``gh pr view <branch>``:
    :meth:`Host.status`) when its head is the head the lane holds — a PR at another head is
    another branch's merge, and a merged or closed one is nothing to merge. A number found on
    the host is written onto the facts, so every record this pass writes carries it. A
    fast-forward lane has no PR by design (T2): None, and no lookup."""
    number = (f.get('pr') or {}).get('number') or (f.get('prev') or {}).get('pr')
    if number or isinstance(lane.host, FastForwardHost):
        return number
    got = lane.host.status(f['branch']) or {}
    number, state, head = got.get('pr'), str(got.get('state') or '').upper(), got.get('head')
    if not number or state != 'OPEN' or (head and f.get('head') and head != f['head']):
        return None
    f['pr'] = dict(f.get('pr') or {}, number=number, state='OPEN', head=head or f.get('head'))
    lane.out(f"{f['branch']}: no PR number in the lane record — the host's open PR #{number} "
             f"is at this head")
    return number
```

### §2 `back_to_pushed` — a branch nothing can name goes back to be given a PR

```python
#: why a branch leaves a landing state without merging: nothing knows its PR number
NO_PR = 'no PR number: nothing can merge it'


def back_to_pushed(lane, f, why):
    """A branch the lane cannot merge because no PR number exists for it anywhere goes back to
    PUSHED — the one state whose transition opens a PR (T2), and one that adopts the open PR
    when the number was merely unreadable this pass (:meth:`GitHubHost.open`). Never PR_OPEN:
    from there the table goes straight on to GATE with the number still missing, and the branch
    arrives at this same refusal every tick."""
    lane.out(f"held {f['branch']}: {why} — back to PUSHED, a PR is opened for it next pass")
    lane.set(f, PUSHED, why, result='held')
```

### §5 The I9 ledger

`asf/invariants.py`, under `i9_events`:

```python
#: the branches an I9 event has already been recorded for, beside the session ledger the events
#: are folded out of (:func:`_sessions_path`): ``{branch: {'pr', 'at'}}``
I9_SEEN = 'i9-seen.json'


def _i9_path(product):
    return os.path.join(os.path.dirname(_sessions_path(product)), I9_SEEN)


def i9_seen(product):
    """The branches an I9 event has already been recorded for. Missing or unreadable: ``{}`` —
    a de-duplicator fails into saying it again, never into silence."""
    import json      # the module imports it per function (:func:`lane_history`), not at the top
    try:
        with open(_i9_path(product), encoding='utf-8') as fh:
            data = json.load(fh)
    except (OSError, ValueError):
        return {}
    return data if isinstance(data, dict) else {}


def i9_unseen(product, events, now=None):
    """The events of ``events`` this product has not recorded before — one per branch, ever —
    with the ledger written to carry them. The fold they come from is over an append-only file
    (:func:`lane_history`), so without the ledger a merge found outside the lane is re-said
    every tick for as long as the product lives. Never raises: an unwritable ledger only means
    the event is said again next tick."""
    import datetime
    import json
    seen = i9_seen(product)
    new = [ev for ev in events if ev.get('branch') not in seen]
    if not new:
        return new
    at = now or datetime.datetime.now(datetime.timezone.utc).strftime('%Y-%m-%dT%H:%M:%SZ')
    seen.update({ev['branch']: {'pr': ev.get('pr'), 'at': at} for ev in new})
    path = _i9_path(product)
    try:
        with open(path + '.tmp', 'w', encoding='utf-8') as fh:
            json.dump(seen, fh, sort_keys=True)
        os.replace(path + '.tmp', path)
    except OSError:
        pass
    return new
```

`lane_report` filters once, inside the `try` it already has — one line, and the docstring's
`per merge from outside the lane` becomes `per merge from outside the lane not recorded before`:

```python

```

Everything after it is unchanged: the `EVENT I9:` line and the `event('foreign-merge', …)` call
are both driven by `events`, so both happen exactly once per branch. `asf/record/check.py`'s
`invariant_findings` keeps calling `i9_events` and gains the clause "…the I9 events are printed,
never counted **and never marked seen: the audit lists every foreign merge the history holds,
where the tick says each one once**".

### What it looks like when it is there

The incident branch, the pass after: nothing is merged under a name nobody has, and the branch is
on its way to a PR instead of into another refusal.

```
held plan/T-0189: no PR number: nothing can merge it — back to PUSHED, a PR is opened for it next pass
lane: plan/T-0189 GATE → PUSHED (no PR number: nothing can merge it)
```

…and on the next in-process pass:

```
prs: opened PR #423 for plan/T-0189
lane: plan/T-0189 PUSHED → PR_OPEN (PR #423)
```

The same branch when the number was only missing from the record — the host has the PR, at this
head, and the lane adopts it and merges:

```
plan/T-0189: no PR number in the lane record — the host's open PR #423 is at this head
landed plan/T-0189 → PR #423 4b825dc642cb
```

The three repeating events are each said one last time, and then never again:

```
EVENT I9: fix/merge-refused-conflict-back merged outside the lane (no MERGING intent)
EVENT I9: fix/merge-refused-conflict-mergeable merged outside the lane (no MERGING intent)
EVENT I9: fix/quota-stale merged outside the lane (no MERGING intent)
```

```console
$ asf check --invariants   # the audit still lists all three, every time it is run
EVENT I9: fix/merge-refused-conflict-back merged outside the lane (no MERGING intent)
...
invariants: 0 violation(s)
```

## Records

- **`<state>/<product>/i9-seen.json`** — new, and the only new file. One JSON object,
  `{"<branch>": {"pr": <n|null>, "at": "<iso>"}}`, written `.tmp` + `os.replace` like
  `gate-visits.json`, beside `sessions.jsonl`. It grows by one key the first time a branch is
  found merged outside the lane and never shrinks; it is not part of the record and nothing but
  `i9_seen`/`i9_unseen` reads it.
- **`<state>/<product>/sessions.jsonl`** — unchanged in shape. Two lane records change what they
  say: a branch that cannot be merged for want of a PR number is written `{"state": "PUSHED",
  "reason": "no PR number: nothing can merge it"}` where it used to be written `{"state":
  "MERGING", "pr": null}` and then `{"state": "WAITING", "reason": "merge refused: …", "green":
  {…}}`; and a `MERGING`/`MERGED` record whose number was found on the host now carries `"pr":
  <n>` where it carried `null`.
- **`metrics/events/<day>.jsonl`** (the record clone) — the same `{"kind": "foreign-merge",
  "branch": …, "pr": …}` line, once per branch for the life of the product, where it was once per
  branch **per tick**. Nothing reads these lines back (P11), so no metric moves; the file stops
  growing by three lines a tick.
- **The tick's log** — `EVENT I9: <branch> merged outside the lane (no MERGING intent)` once per
  branch instead of every tick. New lines: `held <branch>: no PR number: nothing can merge it —
  back to PUSHED, a PR is opened for it next pass`, and `<branch>: no PR number in the lane
  record — the host's open PR #<n> is at this head` when the host had it after all. Gone:
  `held <branch>: PR #None merge refused — …` and the `MERGING → WAITING` line under it.
- **`asf check --invariants`** — unchanged: every foreign merge the history holds, every run,
  and `invariants: <n> violation(s)` counting none of them.

## Stories

- S: A merge is never attempted under a PR number nobody has — `pr_number` as the one reader (the facts' live PR, then the lane record, then the host's open PR for the branch at this head, written back onto the facts), `back_to_pushed` for a branch that has none anywhere, both called from `merge_prs` before `MERGING` is written and from `precheck` before the gate is spent, and the `PR_OPEN → PUSHED` row that stops an unnamed branch reaching the gate at all — acceptance: `python3 -m unittest -v tests.test_lane.AMergeNeedsAPRNumber tests.test_lane.Transitions`
- S: A merge found outside the lane is recorded once per branch, not once per tick — `I9_SEEN`/`i9_seen`/`i9_unseen` as a ledger beside the session ledger the events are folded out of, `lane_report` printing and forwarding only what it has not recorded before, `i9_events` left pure so `asf check --invariants` still lists every foreign merge, and a ledger that cannot be read or written costing noise rather than silence — acceptance: `python3 -m unittest -v tests.test_invariants.R12AnI9EventIsSaidOncePerBranch tests.test_invariants.R12I9IsAnEvent tests.test_invariants.R13TestsOnlyInvariants`
