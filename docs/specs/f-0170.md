# F-0170 — an audit that can never go green, and a step that never ran

`asf check --invariants --product asf` reports 32 I3 violations. They are 16 pairs of Active Tasks
whose `writes:` intersect — two findings per pair, one filed at each card of it (P1, reproduced
below). None of them was introduced by the fix package that started reporting them; the audit is
new, the pairs are not.

The card asks for the record to resolve them **by policy, not by hand edits**, and offers two
remedies: serialize the pair with `after:`, or make I3 ignore a Task's own card file in `writes:`.
Both were tested against the checkout before this spec was written:

- **The first remedy clears nothing today.** `_intersecting` does not read `after:` at all, so a
  pair that *is* serialized is reported exactly like one that is not. Verified live (P2): three
  Active Tasks all writing `lib/x.py`, one of them carrying `after: [T-0001]`, produce all six
  findings — the ordered pair included. An operator who followed the card's own advice would edit
  16 cards and watch the number stay at 32.
- **The second remedy rests on a misread line.** The path in the finding is the **card** the
  finding is filed at, not the intersecting glob: `INVARIANT I3: T-0001 — writes: intersects
  Active task T-0002's writes: (tasks/T-0001.md)` while the intersecting path is `lib/x.py` (P2).
  No Task in the fixture has a record path in its `writes:`, and `tasks/T-0183.md` in the card's
  example is T-0183's own card, printed because the finding is *about* T-0183. There is nothing
  for I3 to start ignoring.

So the card's want is right and its two remedies are one short step from being wrong. What holds is
this: a pair of **Active** Tasks is a pair that already has two branches. No writer can un-declare
it — I3 at the tick only judges a writer that changed a card's `writes:` (P3), which is why the
tick has never refused one of these 32 and the audit reports every one of them forever. The record
cannot answer an audit whose only remedy is a hand edit, and a permanently red `asf check
--invariants` is not a gate.

This spec makes the two halves agree on one definition — **an overlap violates I3 when the record
has not ordered the pair** — and then lets the tick write that order itself, where a pass that does
exactly this for a widened path already lives (P7). The same audit then goes green because the
record says something new and true, not because the rule looked away.

The card's second half — `asf doctor` saying `NEEDS OPERATOR: step groom is on no clock` — is one
line in the operator's own product file, outside this repo (P10). What belongs here is that
`asf install` installed those clocks, read them back, called itself `ok`, and never said that the
step which applies inbox answers, retires landed cards and marks reshapes was on none of them.

### The choices

| # | Chosen | Against | Why |
| --- | --- | --- | --- |
| C1 | **An overlap violates I3 only when the record has not ordered the pair** — one of the two reachable from the other through `after:`, in either direction, transitively. | Keeping I3 as "no two Active Tasks' `writes:` intersect, full stop". | As written the rule is unachievable once two branches exist (P3): no writer can clear it, so it reports 32 forever and gates nothing. Ordered is a fact with teeth, not a label: the record has said which of the two lands first and the feeder holds the later one's next row until it does (P6). It is also the standard the planner already works to — a plan orders Tasks by wave and requires disjoint footprints only among the Tasks that may run in one wave. |
| C2 | **One definition, three readers**: `invariants.unordered_overlaps()` is the only implementation; `check_i3`, `check.py`'s plain-check loop and the new tick pass all call it. | Narrowing `invariants._intersecting` alone. | P4: the plain check is a second copy of the rule and files a Bug class of its own (P5). | C3 | **I3 also judges a writer that changed an Active Task's `after:`** while its `writes:` still intersects another's — the pair that *becomes* unordered is refused at the card that un-ordered it. | Judging only a `writes:` change, as today. | Without it C1 is a loophole: one `after+=` silences a live overlap for good. | C4 | **The later-minted Task waits: `after: <the lower id>`** — one edge per pair, always from the higher id to the lower. | Ordering by how far each branch is through the lane (the one nearer landing leads), or by plan ordinal. | The direction decides which of the two branches waits (P6), so it is a real choice — but both orders cost the same one rebase, and the wrong order costs a delay, never lost work: the waiting branch is already pushed and burns no session, and two branches that land in parallel on one file reach the same rebase through `CONFLICT → REBASE` anyway. ### In and out

**In.** The one definition of an overlap that violates I3 and its two existing readers (C1, C2, C3);
the tick pass that writes the order (C4, C5, C6); the install step that names a step no clock runs
(C7).

**Out, deliberately:**

- **The shared-paths divergence.** `footprint.overlaps` exempts `conventions.shared_paths`
  (lockfiles) from an overlap and `writes_intersect` does not, so the feeder lets a pair through
  that I3 would refuse. Real, independent of this card, and a narrowing that may clear none of the
  32 (`DEFAULT_SHARED_PATHS` is empty). Not touched here.
- **Whether `hold_unlanded` should hold a *review* row at all.** Reviewing a pushed branch blocks
  nothing and costs no lane seat, so holding that one row behind an unlanded predecessor (P6) is
  arguably a defect of B-0080 in its own right. Changing it would change what `after:` means for
  every Task in the record, not only a serialized pair, and this card is not the place to decide
  that — here the hold is accepted as the serialization, with its release condition named (P6b).
- **Teaching the widening rule about `after:`.** `widen.decide` returns `waits` when a path overlaps
  an open Task's `writes:` and consults no order (`asf/feeder/widen.py:199-220`). It stays strict:
  this spec changes what the *invariant* calls a violation, never what a widening may take.
- **The directory and nested-glob reach** `footprint.globs_overlap` adds on top of
  `writes_intersect`. I3 keeps `writes_intersect` exactly: widening the path test would *create*
  violations, which is the opposite of this card.
- **Anything in the operator's own home** (C8).

## The design

### 1. One definition of the overlap that violates I3

`asf/invariants.py` — `_intersecting` becomes the public `unordered_overlaps`, reading the pair's
order as well as its paths:

```python
def _after_edges(tasks):
    """``{id: [after ids]}`` over every Task in the record — a chain may run through a Closed one."""

def ordered(edges, a, b):
    """True when ``a`` is reachable from ``b`` through ``after:``, or ``b`` from ``a``: the record
    has said which of the two comes first, so they are not in flight together."""

def unordered_overlaps(tasks):
    """``[(a, b, glob_a, glob_b)]`` — every pair of Active Tasks whose ``writes:`` intersect
    (``core.writes_intersect``) that the record has **not** ordered, `a` < `b`, first glob pair.

    ``tasks`` is ``{id: {'type', 'state', 'writes', 'after', 'removed'}}`` — every Task, Active or
    not: a Closed Task is no pair of its own but is still a link in an ``after:`` chain."""
```

Reachability is a memoised DFS over `after:` edges, run only for a pair whose globs already
intersect, so the cost is the number of intersecting pairs, not the square of the record.

Two shapes the callers must respect, because both are easy to get wrong:

- **`tasks` is normalised, not a meta.** A frontmatter meta keeps its `state` in the machine block
  and an index item keeps it at the top, so the pair rule takes neither: `check_i3` builds
  `{id: {'type', 'state', 'writes', 'after', 'removed'}}` from `_record(ctx)` through the existing
  `_state`/`_machine` helpers, and the tick pass passes the index items it already holds.
- **`check_i3`'s "did this writer create it" diff is over pairs, not over tuples.** It keeps
  comparing `{(a, b) for a, b, *_globs in unordered_overlaps(…)}` before and after; diffing the
  4-tuples would report a pair again whenever a different glob of the same two cards happened to be
  found first.

Its three readers:

- `check_i3` keeps its message and its two-findings-per-pair shape (P1), and gains C3: the
  `continue` that skips an unchanged card now compares `after:` as well as `writes:`, so a writer
  that un-orders a live overlap is judged at the card it wrote. The docstring says which of the two
  facts each half guards.
- `asf/record/check.py`'s Active×Active loop is deleted and replaced by a call to
  `unordered_overlaps`, keeping its own finding text (`writes: 'lib/x.py' intersects Active task
  T-0002's 'lib/x.py'`) and its line number from `find_line(rec, 'writes')`. Two behaviour changes
  come with it, both narrowings and both wanted: an ordered pair is no longer a finding, and a
  `removed:` card is no longer judged (`_active_writes` already excludes it; the loop in `check.py`
  did not).
- the new pass below.

Nothing else moves: `record_audit` keeps staging every card (it is the read-only view of the same
rule), `cmd_check_invariants` keeps its line format and its exit code, and the seeded-violation
tests keep failing exactly as they do — a pair with no `after:` is still refused before commit.

### 2. The tick writes the order

`asf/tick/widen_footprint.py` gains a third pass, beside the two that already repair a footprint:

```python
def serialize_overlaps(ctx, items, out=print):
    """Order every standing overlap the record has not ordered: for each pair of Active Tasks whose
    ``writes:`` intersect with no ``after:`` either way (:func:`asf.invariants.unordered_overlaps`),
    the later-minted card gets ``after: <the earlier>`` and one History line
    ``serialized behind <owner>: writes: overlaps <glob>``, committed alone (:func:`write_card`).

    Never a cycle: an edge is proposed only where neither Task reaches the other, so the edge it
    adds cannot close one. Idempotent: the ordered pair is not a candidate again. ``items`` is
    updated in place; the index is re-derived once when anything was written. Returns
    ``{task: owner}``."""
```

- `asf/feeder/widen.py` gains the one new message beside `HISTORY` and `REVERTED`:
  `SERIALIZED = 'serialized behind {owner}: writes: overlaps {glob}'`.
- `run()` calls it last: `report_facts` → `apply` → `revert_overlaps` → `serialize_overlaps`. A
  widening reverted in the same tick has already removed its path, so that pair never reaches the
  new pass — the narrower repair runs first and the order is only written for what is left.
- The health step needs no change: `widen_footprints` already wraps `run()` in the try/except that
  makes a failure one line (P7).
- **What the edge does to the lane.** It is not a formality: `hold_unlanded` (P6) turns the later
  Task's next launching row — its correction, its rebase, its close, its `PUSHED → REVIEW` — into
  `WAITS ON <owner>` until the owner is done, and releases it the moment the owner lands, is closed,
  is retired or reaches the trunk (P6b). That is the serialization, and it is why the edge is
  written once, in one direction, and never the reverse: the pair now lands one branch at a time
  instead of colliding at the merge. Nothing is written onto a **New** card, so no plan's parallel
  wave and no delivery slice is re-cut by this pass (P9).
- The History line is what keeps the edge honest: a reader sees an order the factory wrote on a
  date, for a named overlapping glob — not a plan-declared dependency the Task was built under.

What the operator's record looks like afterwards: `asf check --invariants --product asf` →
`invariants: 0 violation(s)`, `asf check` → no `intersects Active task` line, 16 cards each
carrying one more `after:` id and one more History line, and 16 record commits named
`T-nnnn: serialized behind T-mmmm: writes: overlaps <glob>`.

### 3. A step no clock runs fails the install that left it there

`asf/doctor.py` — the step names and the lines about them stop being the same thing, so a caller
that needs the names does not read them back out of a sentence:

```python
def clockless_steps(product):
    """The ``asf``-owned steps (:data:`asf.tick.steps.ASF_STEPS`) no clock of ``product`` names, in
    manifest order: a step owned by a command or declared ``off`` is the operator's own, and a
    product whose clocks do not load has nothing to compare (``[]``)."""

def check_clock_steps(product):
    """One ``NEEDS OPERATOR`` line per :func:`clockless_steps` — the message, unchanged."""
```

`asf/install.py` `_step_scheduler`, after the read-back it already does (P11):

```python
    try:
        product = env.load_product(args.product)
        clockless, lines = doctor.clockless_steps(product), doctor.check_clock_steps(product)
    except Exception:        # an unreadable product is the config step's row, not this one
        clockless, lines = [], []
    if clockless:
        for line in lines:
            print(f'install: {line}', file=sys.stderr)
        return 1, 'step(s) on no clock: ' + ', '.join(clockless)
```

No new module, no new command, no new config key: `install.py` already imports `doctor`, and the
line already carries the exact yaml edit. `asf doctor`'s own row is byte-identical
(`tests/test_doctor.py::TestCheckClockSteps` is the proof).

And the edit itself, which is not in this repo (C8):

```
NEEDS OPERATOR: step groom is on no clock — add it to the dispatch clock in
$ASF_HOME/products/asf.yaml (steps: [health, groom, wave, prs, harvest, batch]), then
`asf scheduler install --product asf` and confirm with `asf doctor --product asf`
```

## Records

  <glob>`. Written through `set_typed`, so the card round-trips or it is not written (P8).
- **One record commit per serialized card**, subject `T-nnnn: serialized behind T-mmmm: writes:
  overlaps <glob>`, touching that card alone (R14).
- **One tick event per pair**: `ctx.event('serialized', item=<task>, text='after: <owner> — writes:
  overlaps <glob>')`, beside the `reverted` event the same module already files.
- **One tick log line per pair**: `serialized T-nnnn: after: T-mmmm — writes: overlaps <glob>`.
- **`index.json`** re-derived once per pass that wrote anything (`_reindex`), so the same tick's

- **In the wave's rows** (read, not written): the later Task of each ordered pair shows
  `WAITS ON <owner>` with `reason: after: <owner> has not landed` until the owner is done — the
  serialization made visible where the operator already reads it (`asf next`, the tick's wave line).
- **What stops being written**: the 32 `INVARIANT I3:` lines of `asf check --invariants`, the 16

  intersects Active task …'s …` Bug class those findings file (P5).
- **`asf install`**: one `install: NEEDS OPERATOR: step <s> is on no clock — …` line per clock-less

- **No new file, no new state file, no new module, no new command, no new config key.**
