# F-0305 — the move is said out loud, not inferred from the text

The F-0282 staged guard refuses a record commit that deletes an intake note the trunk still
carries, unless the note's `HEAD` text turns up **verbatim** inside something the same commit
writes. That last clause is the hole. The groom edits an answered note *before* it moves it: the
answer's header lines go in, the `## Question` block comes out. By the time the note reaches
`<intake>/done/`, its text is not the text `HEAD` has — so the guard sees a bare deletion and
refuses the commit.

The refusal is not a decline. `asf groom --apply` dies on it, and `_put_back` restores every
path the commit would have carried, so the mint, the card, the groom file and the applied answer
are all **lost** — and the same answer is read and refused again on the next tick. No answered
inbox card can be minted at all.

The fix is to stop inferring the move. A `done/` note's header line gains the one thing the
guard actually needs — the path of the note it came from — and the guard reads that token
instead of guessing from bytes that are allowed to change. The guard stays armed: a commit that
moves one note still cannot excuse the loss of another.

### In

* **The provenance.** `asf/groom/inbox.py` — `move_to_done` ends the header line it writes with
  the note's own record-relative path, through one function shared with the guard.
* **One writer.** `process_inbox`'s inline `done/` write is deleted and becomes a `move_to_done`
  call with an `as_name=` for the title slug, so the format has exactly one writer.
* **The reader.** `asf/record/staged_guard.py` — a new constant and `moved_from(rel)`, a
  `_moved_to_done` helper, and one extra `continue` in `check()`; the module docstring's fourth
  bullet is rewritten, because it currently describes the check being replaced.
* **The tests.** A new `tests/test_intake_move_guard.py`: the answered note end to end through
  `asf groom --apply` in a record checkout with the real pre-commit installed (P12 says nothing
  else reaches a record commit), the header's exact shape, the retired note's head still opening
  with `retired`, the pre-commit returning 0, and the two tests that prove the guard is still
  armed — one note's move never excusing another's loss, and prose never forging the token.

### Out

* **The verbatim-text check is not removed.** It stays as the first chance (D6), so a plain card
  rename and a `done/` note an older `asf` wrote both keep passing.
* **No migration of `done/` notes already in a record.** The guard only ever reads blobs the
  commit in front of it writes; a note already committed is never judged (D7).
* **The four cards stuck on another product's record** (the card's `2bfcf6f84`) are not re-landed
  by this change. `_put_back` reverted the answers (P3) and `_previous_groom_file`
  (`asf/groom/groom.py:69-77`) only ever reads the newest groom file *before* today, so answers
  written days ago are no longer in reach. `question_lines` is pure over the intake directory and
  re-asks each question every tick, so the lines come back unanswered on their own: the remedy is
  to answer them again in the then-current groom file, once this lands. Nothing to migrate, and
  nothing a person must do before this lands.
* **Widening the guard to a nested intake dir** (P13). It is unguarded today; making it guarded
  is a separate judgement about `guarded()`'s two-segment rule, not an S1 regression fix.
* **Renaming or folding away `staged_guard.DEFAULT_INTAKE`.** It duplicates
  `asf.conventions.DEFAULT_INTAKE_DIR` and that is untouched here.
* **What the groom does when a commit is legitimately refused.** Losing the pass and retrying
  next tick is the right behaviour for a *real* stale tree; the defect is being refused when the
  tree is not stale.

## The design

Three files. The reader and the writer cannot land apart — the writer's new header would fail
the old guard's text check just as it does today, and the new guard would find no token to read.

### 1. `asf/record/staged_guard.py` — the token, and one more `continue`

The shared token, next to `DEFAULT_INTAKE`:

```python
#: What opens the provenance :func:`asf.groom.inbox.move_to_done` writes on a ``done/`` note's
#: header line (F-0305) — the one token that tells intake's own move from a stale tree's loss,
#: whatever the note under ``done/`` is named and however the note's own text was edited on the
#: way there. It is the end of that header line, never merely somewhere in it.
MOVED_FROM = '— from '


def moved_from(rel):
    """The provenance token a ``done/`` note's header carries for the intake note ``rel``
    (record-relative). The writer appends it, last on the line; :func:`check` reads it there."""
    return MOVED_FROM + rel
```

The reader, after `guarded()`:

```python
def _moved_to_done(repo, path, written, intake):
    """``path`` is an intake note this commit moved to ``done/`` itself: a written
    ``<intake>/done/*.md`` whose header line *ends* in the provenance for it
    (:func:`moved_from`). The note's own text is edited on the way — an answer's header lines
    go in, its question comes out (F-0305) — so the header's provenance is the link, never the
    text and never the name. The match is the end of the line and nothing less: a header also
    carries prose nobody here controls (``asf retire --why``), and prose that merely *contains*
    the token must never excuse another note's loss."""
    if path.split('/')[:1] != [intake]:
        return False
    done, token = f'{intake}/done/', moved_from(path)
    for w in written:
        if not (w.startswith(done) and w.endswith('.md')):
            continue
        if (_blob(repo, f':{w}') or '').split('\n', 1)[0].rstrip().endswith(token):
            return True
    return False
```

In `check()`, the intake dir is resolved once and passed down, and the new clause follows the
text clause:

The refusal line itself is unchanged: when it fires now, it means what it says.

The module docstring's fourth bullet currently reads *"its text survives nowhere in the commit:
intake's own move (`<intake dir>/done/<slug>.md` carries the note's text under a `→ <id>` line)
and a plain move both keep it, and pass."* That describes the check being fixed, so it is
rewritten: a plain move passes by its text; **intake's own move passes because the `done/` note
ends its header line with the path of the note it came from** — intake edits a note on the way out
(an answer's headers in, its question out), so its text is not the trunk's and cannot be the link.

### 2. `asf/groom/inbox.py` — one writer, and the header says where the note came from

`move_to_done` gains `as_name`, writes the provenance, and is documented as the one way a note
leaves intake — including a mint:

```python
def move_to_done(inbox_dir, name, header, text, free=True, as_name=None):
    """Move the note ``<inbox_dir>/<name>`` to ``<inbox_dir>/done/`` as ``header``, a blank line,
    then its ``text`` — the one way a note leaves intake (a mint, a ``close`` answer, ``asf
    retire``, a note retired once already). ``free``: a name ``done/`` already holds gets a
    ``-2``, ``-3`` … suffix rather than overwriting what is there. ``as_name`` names the file
    under ``done/`` when it is not the note's own (a mint files it under the card's title slug).
    The path written.

    The header line ends in the note's own path (:func:`asf.record.staged_guard.moved_from`):
    the record's staged guard refuses a deleted intake note unless this commit says where it
    went, and it cannot read that off the text — an answer edits the note before it is moved —
    nor off the name, which a mint and a collision both change (F-0305). The provenance is last
    on the line, after whatever prose the header carries, because that is where the guard reads
    it (D2)."""
    done_dir = os.path.join(inbox_dir, 'done')
    os.makedirs(done_dir, exist_ok=True)
    out = as_name or name
    stem, n = out[:-3] if out.endswith('.md') else out, 2
    while free and os.path.exists(os.path.join(done_dir, out)):
        out = f"{stem}-{n}.md"
        n += 1
    target = os.path.join(done_dir, out)
    rel = f"{os.path.basename(inbox_dir.rstrip('/'))}/{name}"
    with open(target, 'w', encoding='utf-8') as f:
        f.write(f"{header} {moved_from(rel)}\n\n{text}")
    os.remove(os.path.join(inbox_dir, name))
    return target
```

### What it looks like when it is there

An intake note the trunk carries, asked a question by a previous tick, answered `bug tick: no
push` in the groom file. `asf groom --apply` exits 0, pushes one commit, and
`inbox/done/the-daily-tick-never-pushes.md` opens:

```
→ B-0001 — from inbox/tick-no-push.md

# the daily tick never pushes
signature: tick: no push

It stops after the gate.
```

The question is gone, the answer's header is in, the card is minted, and the header line says
which note this was — which is the one thing the guard asked for. A note `asf retire` moves
reads `→ retired as B-0001 (2026-10-08) — from inbox/tick-no-push.md`: still opening with
`retired`, so `retired_keys` reads it exactly as before.
