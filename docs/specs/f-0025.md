# F-0025 — Typed envelopes: every job ends with a machine-readable report beside its prose

Epic: E-0001 — ASF 0.1 — a working factory. Branch: `spec/F-0025`.

The card, as the requirement: *a report as prose is testimony. Every job ends with a typed
report — JSON, one schema per job kind — beside its prose; ingest reads the JSON; a parse failure
goes back to the same session to be corrected rather than being re-run. The report contract is
generated from the schema, so a template cannot invent its own.*

Today the contract is prose and the reader is a regular expression. Every brief ends with the
same hand-written block (`asf/briefs/build.py:51-92`), and `asf.workers.report` reads it back by
matching `^\s*REPORT\s*$` and then `key: value` lines until a fence
(`asf/workers/report.py:25-49`). Three facts are pulled out of that text and acted on: `pushed:`
decides whether a run failed at the source (`asf/workers/runtime.py:164-171`), `ruling:` is filed
on an item's card as history (`asf/tick/step_health.py:99-137`), and the whole text becomes the
session's `reason` in `metrics/sessions` (`asf/metrics/metrics.py:910`). Nothing else in a report
is read by anything, because nothing else in it has a shape. `NO_RE` matching `no|none|not
pushed|unpushed` against free text (`asf/workers/report.py:27`) is the whole of the factory's
type system for a session's own account of what it did.

On top of that, each template ends with its own improvised contract — eleven different `Final
message:` lines (`asf/briefs/templates/*.md`), naming things the REPORT block has no field for:
"the verdict line, the failing rows", "the Task count and the wave order", "the part ids with
their writes". A session is asked for facts in one shape and read in another, and the facts in
between are lost.

After this change there is one schema per job kind, in one module; the block a brief prints is
rendered from that schema; a session ends with its prose and, beside it, one fenced
`json asf-report` object; and every reader in the factory reads the object. A report that will
not parse, or that the schema refuses, ends the run `failed: bad report: <why>` and holds the
branch back to its own worktree for a correction that re-prints the report — once, so a typo can
never make a landed branch unlandable.

## Decisions

### In

- **The schema** — `asf.workers.report` grows from a regex reader into the module that owns the
  report: the common fields, one field table per job kind, the checker, the renderer, the reader
  and the contract text. It imports `json` and `re` and nothing of ASF's, so every module that
  reads a result may import it.
- **One schema per job kind**, keyed by `asf.briefs.build.KINDS` — the same twelve words the
  registry's `kind` field already carries (`asf/workers/spawn.py:306`, `kind=brief.kind`), so the
  reader always knows which schema a run's result must satisfy.
- **The typed report is a fenced block in the session's final message**, beside the prose one:
  a fence whose info line carries the token `asf-report`, holding one JSON object. The prose
  REPORT block stays, unchanged and unread — it is what a human reads in a log.
- **The contract is generated** — `report.contract(kind)` renders the block a brief prints from
  the kind's own schema: every field, its type, and the one line that says what goes in it.
  `build.TAIL` prints it; no template prints one.
- **A template may not carry a contract of its own** — the eleven `Final message:` lines are
  deleted, and each becomes the instruction text of a field in its kind's schema. A test refuses
  a template that carries `REPORT`, `Final message` or a fenced `asf-report` block.
- **Every reader reads the object** — `runtime.failure_reason` (the `pushed` verdict),
  `step_health.file_rulings` (the ruling), `metrics.session_event` (the session's `reason`), and
  the new bad-report verdict in `lifecycle.judge`. The prose readers `report.parse`,
  `report.unpushed` and `report.NO_RE` are deleted, not deprecated.
- **A bad report is a failure of the run and a correction on its branch** —
  `failed: bad report: <why>`, then `lifecycle.hold(..., 'report', ...)`, which the feeder's
  FIX → CORRECT row hands back to the same worktree on the same branch.
- **Once per branch** — a branch that has already spent a report correction is never held for
  its report again: the run is judged on its work, `report: unreadable` is written on its
  registry line, and one `bad-report` event is appended.
- **`report.render(kind, **fields)`** — the inverse of the reader, used by `FakeRuntime` and by
  every fixture that scripts a result, so a test declares a report rather than pasting one.

### Out

- **A file.** The typed report is text in the session's final message, not a file in the worktree
  and not a file under `~/.ASF` (D3). No new grant, no new path, nothing for a session to forget
  to write.
- **Reading the prose as a fallback.** There is none. A result with no `asf-report` block is a
  bad report, and it is corrected. "Ingest reads the JSON, never the prose" has no *unless*, or
  the prose is still the contract and this card bought nothing.
- **Rewriting a log.** A result line already in a job log keeps its bytes. A run that ended
  before this change is already ended; nothing re-judges it.
- **Making the review verdict a report field's business.** The `review` schema carries `verdict`
  and the review path, and they are recorded — but the gate stays where it is: the review
  document on the branch, read by `asf.evidence` (`asf/record/ingest.py:403-416`, B-0059). Two
  authorities for one verdict is a defect, and the document is the one that is committed.
- **A total rewrite of the correction loop.** A report hold is an ordinary hold: the same
  `lifecycle.hold`, the same round counter, the same FIX → CORRECT row. Nothing new is invented
  for it (D6).
- **New config.** No product field, no `config.yaml` key, no doctor row. The schema is a closed
  table in code and a test is what proves it covers every kind — an operator has nothing to set
  and so nothing to get wrong.
- **Carrying the typed report into the next brief.** `repo_facts['last_report']` is filled by no
  caller today (`asf/briefs/preamble.py:247` — only tests pass it), and filling it from the typed
  report is its own card.
- **Validating a field's *content*.** The schema checks types, required keys and the three
  cross-field rules of D5. It does not check that a `sha` is a real sha or that a `commits` entry
  is on the branch — health and harvest already measure the branch against git, and a report is
  testimony about it, not a second source.

### Preconditions

Checked against `origin/main` at `dfe10fe`.

- A run's result is one JSON line in the job log, and `runtime.read_result` returns the **last
  run's** (`asf/workers/runtime.py:126-153`, B-0028). The session's final message is that
  record's `result` string — the only place a session's own words reach the factory.
- The registry's `kind` on a launch line is the *brief* kind (`asf/workers/spawn.py:306`
  ← `asf/tick/step_wave.py:144-149`, `kind=brief.kind`), so `build.KINDS` is already the
  vocabulary a reader has in hand.
- `lifecycle.judge(run, ev, landing=None)` is the one function that turns a result and its
  evidence into an `end_reason` (`asf/workers/lifecycle.py:465-490`), and `landing` is already
  the precedent for a fact the *caller* resolves against the registry because `judge` itself is
  pure.
- `health.health` writes the `ended` line and then holds on two reasons already
  (`asf/workers/health.py:294-322`); a third reason is one more `elif`.
- `lifecycle.hold` counts rounds over every run of the item and marks `at_cap` at `ROUND_CAP`
  (`asf/workers/lifecycle.py:592-609`), and `lifecycle.corrections` feeds the feeder's FIX →
  CORRECT row (`asf/feeder/rows.py:223-247`) — the loop this card's correction rides on exists.
- `RUN_FIELDS` is what keeps a terminal field from folding into the next run
  (`asf/workers/lifecycle.py:82-83`, B-0041), so a new per-run field joins it or it leaks.
- `report.parse` already stops at a line starting with ` ``` ` (`asf/workers/report.py:41-42`),
  so a prose block followed by a fenced object is what the old reader would have read anyway —
  the two blocks do not collide during the change.
- The brief goldens under `tests/fixtures/briefs/golden/` are byte-compared per kind
  (`tests/test_briefs.py`), and regenerate with `ASF_UPDATE_GOLDEN=1`. Every one of the twelve
  changes here, because the tail changes for every kind.
- `asf.metrics.metrics` already has a schema checker of exactly this shape
  (`_CHECK` / `_apply`, `asf/metrics/metrics.py:100-157`) — the idiom to follow, not the module
  to import (D2).

### Choices

| # | Choice | Chosen | Against | Why |
|---|---|---|---|---|
| D1 | Where the typed report lives | a fenced block carrying the token `asf-report` in the session's final message, beside the prose REPORT | a file in the worktree; a file under `~/.ASF/state/<product>/reports/<job>.json` | A file in the worktree is an uncommitted file, and an uncommitted file is already how a run fails (`push_gap`, B-0051) — the report would fail the run it describes. A file under `~/.ASF` needs a grant on every job, a path every template must get right, and it still is not written by a session that stops early. The final message is what `read_result` already returns, so every reader has it in hand and nothing new can be forgotten. The cost is truncation: a result cut short is a bad report, and is corrected like any other. |
| D2 | The checker | a local `_CHECK`/`_check` pair inside `asf/workers/report.py`, fifteen lines, mirroring `asf.metrics.metrics` | importing `metrics._apply` | `asf.workers.report` is imported by `runtime`, which is imported by everything that launches or judges a session. Importing the metrics module there drags the event streams, the matcher and the scorecard into the worker path for a type check. The duplication is a page of table-driven code and is kept honest by a test asserting both modules refuse the same shapes. |
| D3 | The schema's key | the brief kind (`build.KINDS`: `spec`, `plan`, `coder`, `review`, `fixer`, `rebase`, `close`, `adjudicate`, `fix-bug`, `correct`, `groom`, `reshape`) | the feeder's row kinds; `metrics.KINDS` | It is the word the brief was built from *and* the word the registry recorded, so the writer and the reader name the same thing without a mapping. `metrics.KINDS` is the scorecard's coarser vocabulary (`code` covers four kinds) and could not tell a `review` report from a `fixer` one. |
| D4 | What a missing typed report is | a bad report — the same verdict as one that will not parse | `finished`, with the absence recorded | "Every session emits it" is the acceptance. A session that emits nothing and a session that emits `{` are the same fact for every reader downstream: there is no report. One verdict, one correction, one path to test. |
| D5 | What the schema checks beyond types | required keys, no unknown key, plus three cross-field rules: `pushed: yes\|rebased` needs a `sha`; `pushed: no` needs a `why`; `status: blocked` needs a `needs_operator` or a `left_out` entry | types only; a full constraint language | Each of the three is a hole the prose contract leaks through today — `pushed: yes` with no sha, `pushed: no` with no reason, `blocked` with nothing naming the blocker — and each is one line to check. Anything richer belongs to the reader that cares, not to a schema every kind must pass. |
| D6 | Where a bad report is caught | `lifecycle.judge`, last — after the result's own failure and after the push checks | `runtime.failure_reason`, so `result_ok` is False | `failure_reason` is a pure function of a result's *text* and knows no kind, and it is what the fake runtime and every text-level test run through. `judge` is where a run meets its registry line, so the kind is there; and putting the clause last means a run that already failed for a real reason is judged on that reason, not on the report it never got to write. |
| D7 | What a bad report does | ends the run `failed: bad report: <why>` and holds the branch back to its own worktree (`lifecycle.hold`, kind `report`) | leave it `finished` and file a Bug; a cold re-run (`stall.correct_once`) | The card's words are "corrected in the session that produced it … rather than being re-run". `correct_once` re-runs the original brief from the top, which is exactly the re-run being refused. The hold hands the *same branch in the same worktree* to a `correct` session whose whole job is to re-print the report — the work is done and untouched. |
| D8 | How often | once per branch: a branch that already spent a report hold is never held for its report again | every time, up to `ROUND_CAP`, then adjudicate | A report is testimony about work that is already pushed. Letting a session that cannot write JSON block its own landing for three rounds and then reach an adjudication would spend a heavy model on a syntax error. One correction, then the run is judged on its work and `report: unreadable` stands on the registry line as the record that the testimony is missing — which is itself a fact worth having. |
| D9 | What the correction is told | the parse error, the kind's full contract, and the raw tail of the result's own text | "your report was malformed" | The session must be able to transcribe what it already said into the shape that was asked for, without re-reading the repository or re-doing the work. The contract is generated for the kind, so the correction and the original brief cannot disagree. |
| D10 | The prose REPORT block | kept in the brief and in the session's output, read by nobody | deleted, leaving only JSON | A job log is read by a human when something has gone wrong, and a JSON object is a poor thing to read at that moment. Keeping it costs one block of a brief and buys a legible log. What changes is that it is no longer *evidence*: no reader consults it, and a test proves it by contradicting the two blocks and asserting the JSON wins. |
| D11 | `report.parse` and friends | deleted | kept as a fallback for an old result | A fallback is the prose contract surviving under another name, and the first reader that hits it stops being typed. Nothing re-judges an already-ended run, so there is no old result for a fallback to serve. |
| D12 | Fixture migration | `report.render(kind, **fields)` and a `FakeRuntime` that appends a valid report to every scripted result | a per-kind JSON blob pasted into each test | Five test files script results (`tests/test_workers.py`, `tests/test_lifecycle.py`, `tests/test_tick_steps.py`, `tests/test_session_identity.py`, `tests/test_sample_product.py`). Rendering keeps them one line each, and it makes the schema round-trip — what `render` writes, `typed` reads — a property a test can assert instead of a convention a fixture can drift from. |

## The design

### `asf/workers/report.py` — rewritten

The module keeps its place as a leaf (`json`, `re`, nothing of ASF's) and becomes the one owner of
the report.

```python
REQ = object()                    #: no default: the field must be there
STATUSES = ('done', 'partial', 'blocked')
PUSHED = ('yes', 'rebased', 'no')
FENCE_TOKEN = 'asf-report'
UNPUSHED = 'unpushed work'        #: unchanged — health matches this end_reason prefix
BAD_REPORT = 'bad report'

#: field -> (types, default, the one line the contract prints for it)
COMMON = {
    'item':    (('str',), REQ, 'the card id this session worked, as the brief gave it'),
    'kind':    (('str',), REQ, 'the job kind, as the brief gave it'),
    'status':  (STATUSES, REQ, 'done | partial | blocked'),
    'branch':  (('str', 'null'), REQ, 'the branch you worked, or null for a job with none'),
    'pushed':  (PUSHED, REQ, 'yes | rebased (the factory publishes) | no'),
    'sha':     (('str', 'null'), None, 'what origin/<branch> now points at; required unless pushed is no'),
    'why':     (('str', 'null'), None, 'why nothing was pushed; required when pushed is no'),
    'commits': (('list',), REQ, '[{"sha": "...", "subject": "..."}] — [] when you committed nothing'),
    'tests':   (('list',), REQ, '[{"command": "...", "last_line": "..."}] — [] when you ran nothing'),
    'left_out':(('list',), REQ, '["<what and why>", ...] — [] when nothing was left out'),
    'needs_operator': (('list',), REQ, '["<what> — <the command or the answer needed>", ...]'),
}
```

A type name is a key of `_CHECK` (`str`, `int`, `bool`, `list`, `dict`, `null`); a tuple of plain
strings that are not type names is an enumeration of allowed values, which is how `status` and
`pushed` are declared.

`KIND_FIELDS` adds the per-kind half. One entry per `build.KINDS` word, and the instruction text
of each field is the `Final message:` line it replaces:

| kind | fields |
|---|---|
| `spec` | `spec` (str, the path written), `sections` (list of str), `stories` (list of `{id, title, acceptance}`) |
| `plan` | `plan` (str), `tasks` (list of `{id, title, stories, writes, wave}`), `coverage` (str) |
| `coder` | `files` (list of str), `assumptions` (list of str) |
| `review` | `review` (str, the path written), `round` (int), `verdict` (`approved` \| `changes requested`), `findings` (list of `{file, fix}`) |
| `fixer` | `files` (list of str), `addressed` (list of str, one per C) |
| `fix-bug` | `files` (list of str), `cause` (str), `regression_test` (str) |
| `rebase` | `files` (list of str, the ones resolved) |
| `close` | `line` (str), `reopen` (bool) |
| `adjudicate` | `ruling` (str, required, non-empty), `upheld` (list of str), `overruled` (list of str) |
| `correct` | `fixed` (str, what the failure named and what you did), `files` (list of str) |
| `groom` | `answers` (str, the answers file), `answered` (int), `asked` (int) |
| `reshape` | `parts` (list of `{id, title, writes}`), `coverage` (str) |

- `schema(kind)` — `COMMON` merged with `KIND_FIELDS[kind]`. An unknown kind raises
  `ReportError`; the table covers `build.KINDS` exactly, and a test is what holds that.
- `fence(text) -> str|None` — the body of the **last** fenced block in `text` whose info line
  carries `FENCE_TOKEN`, else `None`. Fences are ` ``` ` or longer, and the closing fence is the
  first line of at least the opening run of backticks.
- `typed(text, kind=None) -> dict` — the parsed, checked object. Raises `ReportError` with one
  sentence naming what is wrong: `no ```json asf-report block in the final message`,
  `the asf-report block is not JSON: <json error>`, `the asf-report block is not an object`,
  `unknown key(s) x, y`, `missing required key 'pushed'`, `'status' must be one of done, partial,
  blocked — got 'finished'`, `'pushed' is yes but 'sha' is missing`. With `kind=None` only
  `COMMON` is checked, and unknown keys are allowed — that is the shape a caller who does not
  know the kind (`failure`) needs.
- `check(kind, text) -> str|None` — the `ReportError`'s sentence, or `None` when the report is
  good. The one function `judge` calls; it never raises.
- `failure(text) -> str|None` — `UNPUSHED` when the typed report's `pushed` is `no`, else `None`.
  A report that will not parse is **not** a failure here (D6): `check` is what catches it, where
  the kind is known.
- `ruling(text) -> str` — the typed report's `ruling`, stripped, or `''`. Never reads prose.
- `summary(obj) -> str` — the one line `metrics` records as a session's `reason`: `'<status>'`,
  `'<status> — <why>'` when `pushed` is `no`, `'<status> — needs operator: <first>'` when
  `status` is `blocked`.
- `render(kind, **fields) -> str` — a fenced, schema-valid block. Every required field the caller
  did not give takes a documented placeholder (`item` → `'X-0000'`, a list → `[]`, `pushed` →
  `'yes'` with a `sha`), so a fixture names only what its test is about. Raises `ReportError` on
  a field the kind's schema does not have — a fixture cannot invent one either.
- `contract(kind) -> str` — the text a brief prints, rendered from the schema:

  ````
  Then, beside it, the typed report — this is the one the factory reads:

  ```json asf-report
  {
    "item": "<the card id this session worked, as the brief gave it>",
    "kind": "<the job kind, as the brief gave it>",
    "status": "done | partial | blocked",
    "branch": "<the branch you worked, or null for a job with none>",
    "pushed": "yes | rebased (the factory publishes) | no",
    "sha": "<what origin/<branch> now points at; required unless pushed is no>",
    "why": null,
    "commits": [{"sha": "...", "subject": "..."}],
    "tests": [{"command": "...", "last_line": "..."}],
    "left_out": [],
    "needs_operator": [],
    "spec": "<the path you wrote>",
    "sections": ["<the sections you wrote>"],
    "stories": [{"id": "S-0000", "title": "...", "acceptance": "..."}]
  }
  ```

  It must parse and it must match this shape exactly — an unreadable report comes back to you
  as a correction, and nothing else about your work is re-done.
  ````

  Field order is `COMMON` then the kind's own, so the twelve contracts share a prefix and a
  session reads the same first eleven lines in every brief.

### `asf/briefs/build.py`

- `TAIL` loses its fenced REPORT block's monopoly: the block stays (it is what a human reads,
  D10) and `{contract}` is appended after it. `context()` gains `'contract':
  report_mod.contract(kind)` — the one new key, and `placeholders()`'s existing test proves no
  template can reach for it and then modify it.
- The import is `from asf.workers import report as report_mod`, beside the `stall` import already
  there (`asf/briefs/build.py:32`).

### `asf/briefs/templates/*.md`

Eleven files lose their `Final message:` line; what each named becomes the instruction text of a
field in its kind's schema:

| template | the line, now | where it went |
|---|---|---|
| `spec.md` | the pushed sha, the spec path, the sections written, the Story count | `sha`, `spec`, `sections`, `stories` |
| `plan.md` | the plan path, the Task count and the wave order, the coverage line | `plan`, `tasks[].wave`, `coverage` |
| `coder.md` | the files written, the gate lines, the assumptions recorded | `files`, `tests`, `assumptions` |
| `review.md` | the verdict line, the failing rows, the gate lines | `verdict`, `findings`, `tests` |
| `fixer.md` | one line per C, the gate lines | `addressed`, `tests` |
| `fix-bug.md` | the test's name and the run's last line, what you changed | `regression_test`, `tests`, `cause`, `files` |
| `rebase.md` | the files resolved, the gate lines | `files`, `tests` |
| `close.md` | the one line, and whether the item should be re-opened | `line`, `reopen` |
| `adjudicate.md` | the REPORT with `ruling:` filled, the findings upheld and overruled | `ruling`, `upheld`, `overruled` |
| `groom.md` | how many questions you answered, how many you sent to NEEDS OPERATOR | `answered`, `asked`, `needs_operator` |
| `reshape.md` | the part ids with their writes, the coverage line | `parts`, `coverage` |

`correct.md` has no such line and gains no field beyond its kind's two.

### `asf/workers/runtime.py`

- `failure_reason(rec)` is unchanged in shape: the CLI's error signatures first, then
  `report.failure(text)` — whose body now reads the typed object. Nothing here learns about
  kinds, and `result_ok` keeps its meaning.

### `asf/workers/lifecycle.py`

- `RUN_FIELDS` gains `'report'` (B-0041: the verdict on one run's testimony never folds into the
  next run of the same job).
- `REPORT = 'report'` — the `hold` kind, beside `UNPUSHED`.
- `report_spent(path, run) -> bool` — True when any run on this run's branch already carries a
  `correction` of kind `report`, or a `report` field of its own. The registry read that `judge`
  may not do itself, resolved by the caller exactly as `landing` is.
- `judge(run, ev, landing=None, report_done=False)` gains one clause, **last**, before
  `FINISHED`:

  ```python
  if not report_done:
      why = report.check(run.get('kind'), ev.result and ev.result.get('result'))
      if why:
          return f'failed: {BAD_REPORT}: {why}'
  ```

  A run whose `kind` names no schema (a hand-built registry line, a job the factory did not
  brief) is not judged on its report: `report.check(None, …)` is `None`.
- `derive(run, ev, cap, path)` passes `report_done=report_spent(path, run)`, as it already passes
  `landing=lands(run, path)`.
- `report_text(kind, why, tail)` — the correction a bad report hands its next session (D9): the
  sentence `why`, then *"your work is pushed and is not being re-done — print the report again,
  in this shape"*, then `contract(kind)`, then the last 20 lines of the result's own text under
  *"what you said"*.

### `asf/workers/health.py`

- `health()` gains a third hold, beside the unpushed and empty-branch ones
  (`asf/workers/health.py:307-322`):

  ```python
  elif reason.startswith(f'failed: {lifecycle.BAD_REPORT}'):
      fields, line = lifecycle.hold(registry, s, lifecycle.REPORT,
                                    lifecycle.report_text(s.get('kind'), why, tail), now)
  ```

  and, when `lifecycle.report_spent(registry, s)` is already true, holds nothing: it writes
  `report='unreadable'` on the run, re-judges it with `report_done=True`, and appends
  `(job, 'bad-report', why)` to `found` (D8).
- `UNPUSHED_REASON_PREFIXES` is untouched: a bad report is not unpushed work.

### `asf/tick/step_health.py`

- `file_rulings` reads the ruling through `report_mod.ruling(rec.get('result'))` — same call,
  typed body. A run whose report has no `ruling` is still marked `adjudicated: none` and named
  once; nothing else in that function changes.
- `run(ctx, …)` emits one event per `(job, 'bad-report', why)` in `found`:
  `ctx.event('bad-report', job=…, item=…, kind=…, why=…)`.

### `asf/metrics/metrics.py`

- `session_event`'s `reason` becomes `report.summary(obj)` when the result carries a readable
  typed report, else the result's text as today (`asf/metrics/metrics.py:910`) — an ended run
  from before this change still reads. The `sessions` schema is unchanged: no new key, no
  migration.

### `asf/workers/runtime.py` — `FakeRuntime`

- The scripted result's text becomes `step.get('result', '') + '\n\n' + report.render(kind, …)`,
  with the kind taken from `step.get('kind')` and defaulting to `coder`. A step may pass
  `report=False` to write no report at all — which is how the bad-report tests script one.
  `Result.text` is unchanged (the step's own string), so every existing assertion on it holds.

## Acceptance tests

The suite is stdlib `unittest`, run from the checkout root. Nothing here touches a real account,
a real process or the machine's `~/.ASF`; the worker tests use the temp `ASF_HOME` of
`tests/test_workers.py`.

### `tests/test_report.py` (rewritten)

```sh
python3 -m unittest tests.test_report -v
```

- `SchemaTest`
  - `test_every_brief_kind_has_a_schema`: `sorted(report.KIND_FIELDS) == sorted(build.KINDS)`,
    and `report.schema(k)` returns for each without raising.
  - `test_every_field_declares_types_a_default_and_a_line`: for every kind, every field's tuple
    is `(types, default, instruction)` with a non-empty instruction and types that are either all
    `_CHECK` names or all plain values.
  - `test_a_kind_field_never_shadows_a_common_one`:
    `set(KIND_FIELDS[k]) & set(COMMON) == set()` for every kind.
  - `test_an_unknown_kind_refuses`: `report.schema('preflight')` raises `ReportError`.
- `ParseTest`
  - `test_the_block_is_read_out_of_the_final_message`: prose, then a fenced `json asf-report`
    object → `typed(text, 'spec')` is that object.
  - `test_the_last_block_wins`: two blocks → the second.
  - `test_no_block_is_a_named_failure`: `check('spec', 'I did the thing.')` names
    `asf-report`.
  - `test_broken_json_is_a_named_failure`: a block holding `{"item":` → the message carries the
    JSON error.
  - `test_an_unknown_key_is_refused`: a `spec` report with `"plan": "…"` → `unknown key(s) plan`.
  - `test_a_missing_required_key_is_refused`: no `pushed` → names `pushed`.
  - `test_a_bad_enum_is_refused`: `"status": "finished"` → names `done, partial, blocked`.
  - `test_the_three_cross_field_rules`: `pushed: yes` with no `sha`; `pushed: no` with no `why`;
    `status: blocked` with empty `needs_operator` and `left_out` → each refused, each named; and
    each satisfied → accepted (D5).
  - `test_a_good_report_of_every_kind_parses`: `typed(render(k), k)` for every
    `build.KINDS` → no raise, and `check` is `None`.
- `RenderTest`
  - `test_render_round_trips_through_typed`: for every kind, `typed(render(k, item='F-0025'),
    k)['item'] == 'F-0025'`.
  - `test_render_refuses_a_field_the_kind_does_not_have`: `render('close', stories=[])` raises.
  - `test_render_fills_every_required_field`: for every kind, the rendered object's keys are a
    superset of the required ones.
- `ContractTest`
  - `test_the_contract_names_every_field_of_the_kind`: for every kind, `contract(k)` contains
    each field name of `schema(k)` and each field's instruction text.
  - `test_the_contract_is_the_shape_it_asks_for`: the JSON in `contract(k)`, with its
    `<…>` placeholders replaced by `render(k)`'s values, passes `typed(…, k)`.
  - `test_the_common_fields_come_first_in_every_kind`: the first eleven lines of the object in
    `contract(k)` are the same for all twelve kinds.
- `ReadersTest` — the card's second acceptance, stated as a contradiction
  - `test_the_json_wins_over_the_prose`: a text whose prose REPORT says `pushed: no — waiting for
    the suite` and whose typed report says `"pushed": "yes", "sha": "abc1234"` →
    `report.failure(text)` is `None` and `runtime.result_ok(rec)` is True.
  - `test_and_the_other_way_round`: prose `pushed: yes abc1234`, typed `"pushed": "no", "why":
    "the suite is still running"` → `report.failure(text)` is `report.UNPUSHED` and
    `runtime.failure_reason(rec)` is the same.
  - `test_the_ruling_is_read_off_the_json`: a text whose prose `ruling:` says one thing and whose
    typed `ruling` says another → `report.ruling(text)` is the typed one.
  - `test_the_prose_reader_is_gone`: `report` has no attribute `parse`, `unpushed` or `NO_RE`.
  - `test_a_malformed_report_is_not_a_failure_reason`: a result with no block →
    `report.failure(text)` is `None` and `runtime.result_ok(rec)` is True (D6: `judge` catches
    it, not this).
  - `test_summary_is_one_line`: `summary` of a done report, a `pushed: no` report and a blocked
    report → three one-line strings naming the status and, where there is one, the reason.

## Records

- **The job log** `~/.ASF/logs/jobs/<product>/<job>.jsonl` — unchanged in shape. What changes is
  what a session writes into the result record's `result` string: its prose, then one fenced
  `json asf-report` object. No line in any log is edited, and no ended run is re-judged.
- **The session registry** `~/.ASF/state/<product>/sessions.jsonl` — a run whose report was
  unreadable gains, in order: the ordinary `ended` line with
  `end_reason: failed: bad report: <why>`; a `correction: {kind: 'report', text: …, at: …}` with
  `rounds` bumped, exactly as an unpushed hold is written. A branch whose report correction is
  already spent gains `report: 'unreadable'` instead, and `report` is a run field — it never
  folds into the next run of the job (B-0041).
- **`metrics/events/<day>.jsonl`** in the record clone — one `kind: bad-report` line per run that
  had no readable report and no correction left, with the job, the item, the brief kind and the
  why. The `ruling` event is unchanged; its text now comes from the typed field.
- **`metrics/sessions/<day>.jsonl`** — no new key. The existing `reason` becomes the typed
  report's one-line summary where there is one, and the result's text where there is not.
- **The briefs** `~/.ASF/state/<product>/briefs/<job>.md` — every brief gains the generated
  contract block for its kind; eleven templates lose their `Final message:` line. The twelve
  goldens under `tests/fixtures/briefs/golden/` are regenerated in the same commit as the change
  that moves them.
- **The item card** — unchanged, except that an adjudication's `## History` line now comes from
  a typed `ruling` field rather than a prose one. No machine-block key is added.
- **Config** — nothing. No product field, no `config.yaml` key, no schema-version bump: the
  record's files are untouched.
- **Printed lines**, the operator's trail: `ended <job> failed: bad report: <why>` and
  `held <branch>: bad report … — back to its session (round 1)` from health; `bad-report <job>
  <why> — judged on its work` for the second one.

## Stories

- S-14850: One report schema per job kind, in one leaf module, covering every kind the factory briefs — acceptance: `python3 -m unittest tests.test_report.SchemaTest -v`
- S-14851: A typed report is read out of a session's final message and every way it can be wrong is named in one sentence — acceptance: `python3 -m unittest tests.test_report.ParseTest -v`
- S-14852: The factory can render a schema-valid report for any kind, which is what the fake runtime and every fixture emit — acceptance: `python3 -m unittest tests.test_report.RenderTest tests.test_workers.FakeRuntimeReportTest -v`
- S-14853: The contract a brief prints is generated from the schema, and no template carries one of its own — acceptance: `python3 -m unittest tests.test_report.ContractTest tests.test_briefs.ContractInBriefTest -v`
- S-14854: Every reader reads the typed object, never the prose, and the prose readers are gone — acceptance: `python3 -m unittest tests.test_report.ReadersTest -v`
- S-14855: A run with no readable report ends `failed: bad report`, after its real failures and never before them — acceptance: `python3 -m unittest tests.test_lifecycle.BadReportJudgeTest tests.test_lifecycle.ReportTextTest -v`
- S-14856: A malformed report is corrected on its own branch by a session that re-prints it, once, and is recorded rather than re-held the second time — acceptance: `python3 -m unittest tests.test_workers.BadReportHoldTest -v`
- S-14857: The ruling, the session's reason and the bad-report event all come off the typed report — acceptance: `python3 -m unittest tests.test_tick_steps tests.test_metrics -v`
