# F-0013 — the tick starts one kind of process, and reads one kind of convention

The feeder is already what the factory wants: `asf/feeder/rows.py`, `footprint.py`, `tiers.py`
and `idle.py` touch no filesystem and start no process, and F-0095 P3 wrote that down as a rule —
"the feeder reads no git and no filesystem; a fact it needs arrives from its caller"
(`asf/feeder/rows.py`'s module docstring). The tick is the opposite. It starts a git command in
**five** private helpers, each with a different failure convention:

| where | returns on success | returns on failure |
| --- | --- | --- |
| `asf/tick/step_wave.py:416` `_git` | `stdout.strip()` | `''` |
| `asf/tick/step_prs.py:21` `_git` | `stdout` | `''` |
| `asf/tick/widen_footprint.py:52` `_git` | `stdout` | `None` |
| `asf/tick/land_spec.py:56` `_git` | the `CompletedProcess` | the `CompletedProcess` |
| `asf/tick/shadow.py:28` `_sh` | the `CompletedProcess` | raises (`check=True` by default) |

plus three calls written inline (`asf/tick/dry_run.py:101`, `asf/tick/step_wave.py:548`, `:552`).
Not one of them takes an injectable runner, so not one of them can be exercised without a real
repository on disk — while `asf/tick/flaky.py:263` `GitHubRuns(product, run=None)`, two files
away, is the house shape and says so: *"a test passes a fake with the same three methods"*.

None of the eight passes an `env`. That is not a style question. `asf/harvest/harvest.py:72`
`clean_env` exists because *"a `git` child that inherits GIT_DIR/GIT_WORK_TREE ignores its `cwd`
and writes into the hook's repo"*, and `asf/hermetic.py` opens by naming that leak as one of the
five its one builder was written to end. The tick's eight git calls are outside that builder. And
the rule it is outside of is itself written down three times, in three different lengths:

| list | entries |
| --- | --- |
| `asf/hermetic.py:68` `GIT_HOOK` — *"the one place those rules live"* | `GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE` |
| `asf/harvest/harvest.py:68` `GIT_HOOK_VARS` | `= hermetic.GIT_HOOK` (the same three) |
| `asf/gitpush.py:30` `_HOOK_VARS` (private) | those three **plus** `GIT_PREFIX`, `GIT_OBJECT_DIRECTORY`, `GIT_ALTERNATE_OBJECT_DIRECTORIES`, `GIT_QUARANTINE_PATH` |

The module that documents itself as the single owner strips four fewer variables than the private
copy beside it. Under a `pre-push` hook git exports `GIT_QUARANTINE_PATH` and
`GIT_OBJECT_DIRECTORY`; a child that inherits them writes its objects into a quarantine that is
discarded when the hook returns. `hermetic.build` — the environment of the harvest gate, of every
worker session and of the suite itself — does not remove either.

Four places build a child's environment by hand rather than asking the builder:
`asf/tick/file_bugs.py:138`, `asf/tick/step_harvest.py:137`, `asf/gitpush.py:57` and
`asf/rules/rules.py:141`. Two of them re-derive the package root by counting `dirname`s
(`asf/tick/file_bugs.py:132`, `asf/tick/step_harvest.py:135`) although
`asf/hermetic.py:68`'s neighbour `package_parent()` is exactly that value.

One of those four is a live silent failure. `asf/tick/file_bugs.py:142` runs the factory's own
rule pass as a subprocess of itself with `timeout=60`; inside it, `asf/rules/rules.py:38` gives
**each** check 60 s and runs them 8 at a time (`MAX_WORKERS = 8`). A record with nine rule cards
needs two batches, and `$ASF_RULE_CHECK_TIMEOUT` raises the inner budget without touching the
outer one. When the outer timeout fires, `rule_check_results` returns `None`,
`rule_violation_signatures` returns `{}` — and the tick files no Bug for any violation, reports no
broken check, and prints nothing at all. The whole rule → Bug loop the module's docstring
describes is lost without a word.

The second half is the conventions. `tools/check_conventions.sh` is green, and it cannot be
otherwise: `asf.conventions.forbidden_patterns()` keeps only the defaults containing `/`, `{` or
`#`, and anchors each to an opening quote. So a policy *number* is invisible to it, and so is a
path-shaped default quoted as part of a longer string. Both blind spots are occupied:

- `asf/feeder/rows.py:112` `DECISION_ROWS = 5` and `:113` `MAX_SPECS_IN_FLIGHT = 2` carry comments
  naming `conventions.decision_rows` and `conventions.feeder.max_specs_in_flight` — keys that are
  not `Conventions` fields. With `:204` `stalemate_round` and `:210` `attempt_limit`, four of the
  feeder's policy numbers are read out of `Conventions.extra` by `.get()`: no field, no single
  home for the default, no row in `validate_mapping`, no doctor finding. A product that writes
  `decisions_rows: 8` gets 5 and is never told.
- `asf/tick/step_prs.py:14` declares `DEFAULT_PRS_PER_TICK = 6` — a second copy of
  `asf.conventions.DEFAULT_PRS_PER_TICK`, whose field already exists at `asf/conventions.py:469`.
- `asf/tick/stale.py:24` holds `DEFAULT_LIMITS`, eleven durations, with its own `DURATION_RE`,
  `_DURATION_SECS` and `limit_seconds` — duplicates of `asf/conventions.py`'s `DURATION_RE`,
  `DURATION_UNITS` and `duration_seconds`. `Conventions.stage_limits` is declared
  (`asf/conventions.py:498`) and **read by nobody**: every one of the block's six readers goes to
  the top-level key through `env.Product.stage_limits` (`asf/env.py:736`) instead, and each
  invents its own grammar — `stale` wants `'3d'`, `asf/feeder/render.py:27` wants an integer of
  hours (`s1_hours`), `asf/workers/continuation.py:60` and `asf/workers/stall.py:50` want an
  integer of minutes, `asf/evidence/closing.py:44` wants `'3d'` again. Nothing validates any of
  them, so a typo is silently the default.
- `asf/feeder/rows.py:126` `PLAN_ON_TRUNK = 'plan on origin/main'` — the trunk's name, inside a
  string the gate's anchored pattern cannot see. `asf/record/ingest.py:766` writes that exact
  sentence, and `asf/feeder/rows.py:649` matches it with `in`. For a product whose `main:` is
  `master` the sentence never matches, so the STARVED → SPEC row loses both its reason and its
  `branch=carrier` override: instead of landing the spec that already exists on its own branch,
  the feeder launches a spec session to write it again. That is the one defect in this spec that
  changes a launch.

This spec closes all of it, in the shape the repo already uses twice: one runner behind one
interface (`asf/harvest/lane.py:2837` `class Host`, `asf/tick/flaky.py:263` `GitHubRuns`), one
environment builder (`asf/hermetic.py`), one home per default (`asf/conventions.py`).

## 1. Decisions

### 1.1 Preconditions

- **`asf/hermetic.py` is the declared single owner of every environment ASF hands a child**: its
  docstring names the five leaks it was written to end, one of them *"a git hook's `GIT_DIR` into a
  child that then wrote into the wrong repo"*, and `tests/test_hermetic.py:167`
  `class OneBuilderTests` is the standing proof, one test per caller (*"the gate and the worker
  session are the builder, not their own copies of its rules"*). A new caller adds a row there; it
  does not add a copy of the rules.
- **`asf/gitpush.py` already owns the write half of git** — every push, bounded by
  `conventions.git.push_timeout_s`, hook-skipping decided by `refs_only`. It is the shape a read
  half is modelled on, and `_HOOK_VARS` (`:30`) is the list that has been right in production.
- **`asf/tick/flaky.py:263` `GitHubRuns(product, run=None)` is the house shape for an injected
  runner inside the tick**, and `asf/harvest/lane.py:2837` `class Host` / `:2880 FastForwardHost` /
  `:2907 GitHubHost` the house shape for an interface with two implementations. This spec copies
  both and invents neither.
- **`asf/tick/tick.py:149` `class Context` is what one tick's steps share**, and
  `ctx.record_root()` (`:164`) is the idiom: a lazily made, once-per-tick resource reached as an
  attribute. Every step already takes `ctx`, so a provider on `Context` needs no signature change
  anywhere.
- **`asf.conventions` is the only module where a product-differing default may be a literal**, by
  `tools/check_conventions.sh`, and `Conventions` keeps unknown keys in `extra` on purpose so an
  older reader does not lose a newer product's block. `.get()` therefore *works* for an undeclared
  key and silently returns the default for a misspelt one — the field is what makes it checkable.
- **`asf/conventions.py:331` `validate_mapping` is where a shaped convention is checked** (eight
  keys today), and `asf/doctor.py:518` is the precedent for validating an unknown key *inside* a
  block: `conventions.savings.<key> is not a known threshold`. `asf/doctor.py:793` is the
  `conventions` row that carries such findings.
- **`asf/rules/rules.py` is already callable in process**: `load_rules(root)` (`:78`),
  `partition(rules)` (`:102`) and `run_all(root, enforced)` (`:169`) all take `root` as an
  argument, are stdlib-only, and `cmd_check` (`:196`) does nothing but call the three and render
  them. No import cycle: `asf.rules.rules` imports nothing from `asf`.
- **`asf/feeder/rows.py:649` reads ingest's sentence, it does not read git.** The producer is
  `asf/record/ingest.py:761` and `:766`. A one-sided fix is not a fix, so the producer changes with
  the consumer (D8) — that is the only file outside `asf/feeder/**`, `asf/tick/**`,
  `asf/conventions.py`, `asf/hermetic.py`, `asf/gitpush.py` and `asf/gitrun.py` that this spec
  touches in the package.
- **CI already runs the suite against a host whose default branch is not `main`**
  (`.github/workflows/tests.yml:57`, `init.defaultBranch master`), but every product fixture in the
  tree still names `main: main` (`sample/product.yaml:7`). The host's default branch and a
  product's trunk are different things, and only the second one is what `PLAN_ON_TRUNK` assumes.
- **`tests/gitfixture.py:36` `Template.fresh` builds a real origin + clone once per module and
  `copytree`s it per test** — the read seam's concrete implementation is tested against a real
  repository through it, so nothing about it needs a recorded fixture.
- **F-0010 (P3 wave 2) is specified and not built**: `asf/evidence/sources.py` does not exist in
  the tree. Wave 5 therefore depends on nothing of it, and must not pre-empt it (D2).
- **The gate is** `python3 tools/run_tests.py`, `tools/check_generic.sh`,
  `tools/check_conventions.sh`, `python3 -m asf.cli plugin check`.

### 1.2 In

- **`asf/gitrun.py`** (new, stdlib only) — the read half of git: `class Git(repo, run=subprocess.run,
  timeout=…)` with one failure convention, `FakeGit(answers)` beside it, and `hermetic.git_env` for
  every invocation.
- **`asf/hermetic.py`** — `GIT_HOOK` gains the four variables `asf/gitpush.py:30` already strips,
  and a new `git_env(base=None)` is the one function that removes them. `package_parent()` gains
  its second and third caller.
- **`asf/gitpush.py`** — `_HOOK_VARS` deleted, `push` builds its environment with
  `hermetic.git_env`. No behaviour change: the list it strips is the same list.
- **`asf/harvest/harvest.py`** — `clean_env` becomes a one-line delegation to `hermetic.git_env`;
  `GIT_HOOK_VARS` stays as the alias its readers use. It strips four more variables than before.
- **The tick's eight git call sites** — `step_wave.py:416`, `:548`, `:552`, `step_prs.py:21`,
  `widen_footprint.py:52`, `land_spec.py:56`, `shadow.py:28`, `dry_run.py:101` — go through
  `ctx.git` (or a `Git` built from the product where there is no `ctx`). Every public function's
  name, signature and return value stays as it is.
- **`asf/tick/file_bugs.py`** — `rule_check_results` calls `asf.rules.rules` in process; the
  subprocess, its 60 s outer timeout, its hand-built environment and `_ASF_REPO_ROOT` all go.
- **`asf/rules/rules.py`** — one new function, `check_data(root)`, returning the payload
  `cmd_check --json` prints; `cmd_check` renders it instead of building it (D5).
- **`asf/tick/step_harvest.py`** — `spawn_background`'s environment comes from `hermetic.build`
  and its `pkg_parent` from `hermetic.package_parent()`.
- **Eight new `Conventions` fields with a documented default each** — `decision_rows`,
  `attempt_limit`, `stalemate_round`, `correction_rounds`, `max_specs_in_flight` (under the
  existing `feeder:` block), `ci_refusal_window_h`, `check_failure_runs`, `stage_limits`'s
  grammar — and `asf/tick/step_prs.py:14`'s duplicate default deleted.
- **`stage_limits` as one shaped convention** — one grammar (`<n>s|m|h|d`), one key set, one
  reader (`Conventions.stage_limit(key)`), a `validate_mapping` row and a doctor finding for an
  unknown key; read from `conventions.stage_limits` with the top-level block still honoured.
- **`conventions.main` in the evidence vocabulary** — `asf/record/ingest.py:761`/`:766` write the
  product's trunk name, `asf/feeder/rows.py:126` becomes a function of the product, and a fixture
  product whose trunk is not `main` proves the row still fires.
- **Tests** — `tests/test_tick_git.py` (new), the §3 blocks over `tests/test_hermetic.py`,
  `tests/test_feeder.py`, `tests/test_stale.py`, `tests/test_file_bugs.py`,
  `tests/test_conventions.py`, `tests/test_land_spec.py`, `tests/test_tick_steps.py`,
  `tests/test_widen.py`, `tests/test_gitpush.py`, `tests/test_doctor.py`.

### 1.3 Out

- **Changing what any row decides, or any line of `asf next` reads.** Every row kind, its wording,
  its tier and its order stay byte-identical, with one exception named in §2.5: the STARVED → SPEC
  row for a product whose trunk is not `main` starts firing correctly, which is the defect.
- **Making the feeder impure.** `asf/feeder/rows.py`, `footprint.py`, `tiers.py` and `idle.py` gain
  no import of `asf.gitrun`, no filesystem read and no `Product` reach they do not already have.
  `ctx.git` lives on the tick's side of the line; the feeder is handed facts (F-0095 P3).
- **`asf/harvest/harvest.py:82` `sh` moving onto `gitrun`.** Harvest is not this wave's module, and
  `sh` has ~200 call sites in `harvest.py` and `lane.py`. It gains the corrected hook list through
  `clean_env` and nothing else. `gitrun`'s docstring names it as the next caller, in the idiom of
  `asf/proves.py`.
- **`asf/rules/rules.py:141`'s own child environment.** What a *rule check script* inherits is
  wave 4's (F-0012) question; this spec only stops the tick from spawning the rule pass at all.
  `run_check`'s `dict(os.environ)` is left exactly as it stands, and named here so the next wave
  does not have to find it.
- **A second host.** `asf/tick/flaky.py:263` is already injected and already goes through
  `ci_pool._gh_env`; it gets a docstring cross-reference and no new class.
- **`asf/evidence/sources.py`, `GitSource`, `LocalGit` and anything else F-0010 declares.** Wave 5
  does not create the evidence pass's read interface, does not pre-name its methods, and does not
  touch `asf/evidence/evidence.py` (D2).
- **Deleting `env.Product.stage_limits`.** A product file that writes the block at the top level
  keeps working, for ever: it is documented and in use. `conventions.stage_limits` wins when both
  are present, in the shape `asf/env.py:694` already uses for the six values that live at the top
  level (D11).
- **New keys on any card, any new event kind, any new `metrics/` stream.** This change writes
  nothing to the record that is not written today (§4).
- **`asf/tick/migrate.py`'s literals.** `:666` `origin/main:` and `:497`/`:679`/`:735`'s `.get()`
  conventions are a one-off importer for a record that predates the factory, run by hand, never by
  the tick. Making it generic would be work on a path no product takes twice.
- **A timeout on the whole rule pass.** With the pass in process, its clock is its own per-check
  budget (`asf/rules/rules.py:38`), which is the only budget that was ever correct.

### 1.4 The choices

| # | Chosen | Against | Why |
| --- | --- | --- | --- |
| D1 | A new top-level module `asf/gitrun.py` — the read half of git beside `asf/gitpush.py`'s write half | a `asf/tick/git.py`, or a helper inside `asf/tick/tick.py` | The five helpers being replaced are not all in the tick's own layer (`shadow` runs from `asf init` too, `widen_footprint` from a rule pass, `land_spec` from the lane), and `asf/gitpush.py` already proves a top-level module is where "every git *verb* the factory runs" belongs. A module under `asf/tick/` would make the lane import the tick to read a ref. |
| D2 | `gitrun` is the *runner* — argv, environment, timeout, one failure convention — and knows nothing of what is being read | one seam that also answers `cat_file`, `prs`, `ancestry` (F-0010's `GitSource`) | F-0010 is specified and unbuilt; two specs racing to define one interface is how two interfaces get built. A runner and a read interface are different layers: F-0010 D3 already says `LocalGit.run` is "`sh`'s `subprocess.run` with the argv form", which is precisely `gitrun.Git.run`. Whichever lands second composes; neither is blocked on the other. `gitrun`'s docstring names `LocalGit` as a future caller. |
| D3 | One failure convention: `Git.run(args)` → `CompletedProcess`, `Git.out(args)` → stdout stripped or `''`, `Git.ok(args)` → bool. Never a raise, never `None` | keeping each caller's present convention behind a shared runner | The five conventions are the reason a caller cannot be moved without reading it: `widen_footprint`'s `None` *means* "no repo to read" (`tracked_paths` returns `None` for it) while `step_prs`'s `''` means the same thing. Three named verbs make the intent explicit at the call site, and `''`/`False` as the failure lets every existing `if not x` guard stand. `shadow._sh`'s `check=True` raise is the one behaviour kept, as `Git.run(..., check=True)`. |
| D4 | `hermetic.GIT_HOOK` grows to the seven variables `asf/gitpush.py:30` strips, and `hermetic.git_env(base=None)` is the one remover | keeping two lists and documenting the difference | There is no argument for the shorter list: `GIT_QUARANTINE_PATH` and `GIT_OBJECT_DIRECTORY` under a `pre-push` hook send a child's objects into a discarded quarantine, which is why the push path has stripped them all along. Widening is strictly safer for every caller of `hermetic.build` (the gate, a worker session, the suite), and `tests/test_hermetic.py:40` already asserts *"no caller identity and no hook variable survives any base"* — the assertion gets stronger without changing shape. |
| D5 | `asf/rules/rules.py` gains `check_data(root)`; `file_bugs` calls it in process | keeping the subprocess and raising its timeout to `8 × TIMEOUT` | Any outer timeout is a second clock over a pass that already has one per check, and the guess is what silently swallowed every violation. In process there is no second clock, no `PYTHONPATH` to compute, no `sys.executable` to find (a `pipx` install has no repo root to point at, and `_ASF_REPO_ROOT` computes one anyway) and no JSON to re-parse. `cmd_check` rendering `check_data`'s payload keeps one producer for the `--json` shape the CLI already promises. |
| D6 | Every policy number the feeder and the tick read becomes a declared `Conventions` field with its default in `asf/conventions.py` | leaving them as `.get()` reads off `extra` with a module-level fallback | A field is the only form that has one home for its default, a row in `validate_mapping`, a doctor finding for a bad shape and a name a typo can be checked against. Four of the feeder's numbers already carry a comment claiming to be conventions (`asf/feeder/rows.py:112`, `:113`); the comment is the intent and the field is the implementation of it. |
| D7 | `stage_limits` becomes a shaped convention: one grammar (`<n>s\|m\|h\|d`), a declared key set, and `Conventions.stage_limit(key)` as the one reader | six readers, three grammars, one bag of unchecked keys | A block whose six readers disagree on whether `24` means hours, minutes or nothing is not a configuration surface, it is six. One grammar means `s1_hours: 2` becomes `s1: 2h` — so the two integer readers (`render.s1_hours`, `continuation.heartbeat_min`, `stall.silent_min`) keep accepting their present integer form for ever (D12), and the key set makes `asf doctor` able to say `stage_limits.tsak_active is not a known limit` the way it already says it for `conventions.savings` (`asf/doctor.py:518`). |
| D8 | The trunk's name comes from `conventions.main` on **both** sides of the sentence — ingest writes it, the feeder builds its match from the product | matching with a regex that accepts any trunk name, on the reader's side alone | A reader-only fix leaves the record carrying a sentence that names a branch the product does not have, which every other reader of `evidence` (the views, the groom's digest, a human) then reads. A regex would also match `plan on origin/some-other-branch` and turn a plan on a *feature* branch into "on the trunk" — the opposite of what the row means. |
| D9 | `ctx.git` — a lazily built `Git` on `asf/tick/tick.py:149` `Context`, in the shape of `ctx.record_root()` | passing a `git=` keyword down through every step | Every step already takes `ctx` and nothing else; a keyword would change eight signatures and every caller of them to reach one object. The lazy property also means a step that reads no git starts no process and a product with no `repo_dir` builds nothing. |
| D10 | A `FakeGit(answers)` keyed by `(verb, argv-tuple)`, raising `KeyError` naming the call for an unrecorded key | a fake that answers `''` for anything it was not given | An empty answer for an unasked question turns "the step stopped reading git" into a passing test — the exact failure the current module-attribute patching hides. `tests/test_dry_run.py:113` and `tests/test_tick_steps.py:330` patch `step_wave`'s privates today; a loud fake is what lets them stop. |
| D11 | `conventions.stage_limits` wins over the top-level `stage_limits:`, both are read, neither is deprecated in this change | moving the block and failing the old spelling | `asf/env.py:694` already does exactly this for the six values that live at the top level of a product file *"because more than the conventions read them"*, resolving `conventions:` first. Copying that resolution costs one line and breaks no product file in existence. |
| D12 | An integer where a duration is expected keeps its present unit, per key, and `Conventions.stage_limit` is the one place that knows which | one grammar, enforced, with a migration of every product file | `s1_hours: 2`, `heartbeat_min: 30` and `silent_min: 30` are in product files now and their key names carry the unit. Refusing them would turn an upgrade into an operator errand; reading them where the unit is documented costs one table. New keys take durations only, and `asf doctor` says so for an integer under a key that has no unit in its name. |
| D13 | The source-level guards are unit tests over the tracked tree, in the modules that own the rule (`tests/test_tick_git.py`, `tests/test_hermetic.py`) | new patterns in `tools/forbidden-conventions.txt` | `check_conventions.sh` greps for a *literal*; what has to be forbidden here is a *shape* — `subprocess.run([...'git'...])` anywhere under `asf/tick/`, a second hook-variable list, a `.get()` read of a name that is a `Conventions` field. An AST-shaped assertion belongs in Python, beside the interface it protects, where its failure message can name the replacement. |

## 2. The design

### 2.1 `asf/gitrun.py` — every git command the factory reads

Stdlib only. No path literal, no product name, no convention default of its own.

```python
"""asf.gitrun — every ``git`` the factory *reads*, one runner.

The write half is :mod:`asf.gitpush` (every push, bounded by ``git.push_timeout_s``); this is
everything else — a ref resolved, a remote listed, a tree read, a log line. One environment
(:func:`asf.hermetic.git_env`: no variable a git hook exports, so a child never ignores its
``cwd``), one timeout, one failure convention.

Callers today: :mod:`asf.tick.step_wave`, :mod:`asf.tick.step_prs`, :mod:`asf.tick.land_spec`,
:mod:`asf.tick.widen_footprint`, :mod:`asf.tick.shadow`, :mod:`asf.tick.dry_run`. Next:
``asf.harvest.harvest.sh`` (§1.3) and F-0010's ``LocalGit``, which is this runner with the
evidence pass's reads on top of it.
"""


class Git:
    """``git`` in one repository. ``run`` is the spawner, injected for tests (the shape of
    :class:`asf.tick.flaky.GitHubRuns`)."""

    def __init__(self, repo, run=None, timeout=DEFAULT_TIMEOUT_S):
        ...

    def run(self, args, check=False, timeout=None, cwd=None):
        """``git <args>`` in the repo: a :class:`subprocess.CompletedProcess` (text). A spawn
        failure or a timeout is returncode 1 with the reason on stderr — never a raise, unless
        ``check``. ``cwd``: another root (the record repo beside the product's)."""

    def out(self, args, **kw):
        """Its stdout, stripped — ``''`` on any failure, for any reason."""

    def ok(self, args, **kw):
        """True when it exited 0."""


class FakeGit(Git):
    """``{(verb, args-tuple): answer}``. An unrecorded call raises
    ``KeyError("gitrun fake: no answer for out ('rev-parse', 'origin/main')")`` (D10)."""
```

`Git.run` is the only place a `git` process is started: `['git', '-C', repo, *args]`, `text=True`,
`capture_output=True`, `env=hermetic.git_env()`, `timeout=` the instance's. `DEFAULT_TIMEOUT_S` is
