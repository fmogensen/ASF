# F-0306 — rehearse the release on a record shaped like the real one

Every test in this suite runs against a record somebody wrote by hand to be tidy. `sample/backlog`
holds eleven cards — `E-0001`, `F-0001`, `F-0002`, `S-0001`…`S-0003`, `T-0001`, `T-0002`, `B-0001`,
`D-0001` — every id four digits wide, every card a few lines long, no intake note half-groomed, no
annotated tag, no hook, no pin. `tests/e2e/product/record` is the same shape with a fake forge
beside it. They are good fixtures: they are fast, they are readable, and a test that fails in one
names its own defect.

They also agree with the code about everything the code gets wrong. A record whose ids are all
four digits wide never asks whether `\d{4}` was the right width. A repo with no tags never asks
whether a tag is a tag object or a commit. A fixture that never installs a dispatcher never asks
which binary a hook runs. So a defect in exactly those places reaches a real product's record
untested, and the card names where it is found: on a running lane, one defect every hour or two,
and the newest of them — the 2026-10-08 staged-guard regression — shipped inside the hardening pass
that was supposed to stop exactly this.

The four classes the card names are not hypothetical. Every one of them is live on the trunk right
now and this spec measures it:

* **five-digit ids.** `asf/record/core.py:43` already carries the rule in a comment — *"wrote
  `\d{4}` read `S-29501` as nothing, or as `S-2950` — import these, never respell them"* — and
  `ID_DIGITS = r'\d{4,}'` beside it. Four sites in `asf/` respell it anyway (P1). The worst,
  `asf/scorecard/score.py:30`, does not fail: it *truncates*, and a job for `T-78306` is counted
  under `coder-t-7830`.
* **the staged guard against the record's own writers.** The guard (`asf/record/staged_guard.py`)
  refuses a staged deletion unless the deleted text survives somewhere in the same commit. Nothing
  in the product ever sets its escape hatch (P4), and the one writer that legitimately deletes —
  intake's move to `done/` — passes only by a substring test over the commit's other blobs (P5).
  No test runs that test against a record of real size from a stale index, which is the shape the
  regression had.
* **hooks pinned to a stale binary.** The session's `pre-push` shim looks for the dispatcher and,
  when it finds none, **skips the trunk check and leaves `rc` at 0** (P6). A dangling pin does not
  refuse a push; it silently stops gating it. `tools/hook-smoke.sh` exists to catch exactly this
  and is run by hand, by nobody, from no CI job (P7).
* **annotated tags.** Every release tag this repo cuts is annotated (`git tag -a`,
  `asf/version.py:317`), and four readers get it right by naming `^{commit}` or `%(contents)`.
  `asf/install.py:58` picks the newest tag off `git ls-remote --tags`, whose annotated tags come
  back twice — the tag object and `^{}` — and keeps whichever line it saw (P8). No fixture has a
  tag at all (P9).

And the gate the card asks for does not exist in either direction. `tests.yml` runs the suite on a
push to `main`; `release.yml` cuts that push's version tag and files its changelog entry. They are
two workflows on the same event with no edge between them (P10): a push whose suite is red is
versioned anyway, and the version is offered — `pipx install …@v<x.y.z>` — before anything has run
the CLI or the hooks end to end against anything.

This card closes both halves at once, and deliberately as *one* pass rather than four fixes: the
four defects above are this card's **evidence**, not its deliverable. Fixing them one at a time
leaves the fixture that hid them in place and the next one of their kind arrives on the same path.
What lands here is the rehearsal — a snapshot shaped like a real record, a runner that drives the
CLI and the hooks over it end to end, and an edge from that runner to the version — so the fifth
defect of these classes is found by CI on the push that writes it, and never by a product.

### In

1. **A snapshot shaped like a real record, built by a command, carrying no real prose.**
   `tests/rehearsal/` — a record (`record/`) and a code-repo seed (`repo/`) whose *shapes* are the
   real product's and whose *text* is none of it: every id kept verbatim at its real width, every
   structural field kept (type, state, stage, parent, `delivers:`, `removed:`, dates, the shape of
   each History line), every prose run replaced by deterministic ASCII filler of the same length
   and line count; intake notes half-groomed, some already moved to `done/`; the repo seed carrying
   **annotated** `v<x.y.z>` tags at the real tag names, one pre-release tag, a `CHANGELOG.md` with
   their entries, and lane branch names under `worker/`, `spec/`, `plan/` and `fix/` whose ids are
   as wide as the real ones. A `manifest.json` states what the snapshot claims — card count per
   type, widest id per prefix, tag count, how many of them are annotated, the builder's `asf`
   version and the day it was built — and the rehearsal asserts the snapshot still meets its own
   manifest, so a hand edit that flattens a shape is caught by the rehearsal rather than by a
   product. `asf rehearse --build` is how it is refreshed; the operator runs it, because it reads a
   real record.
2. **A runner that drives the CLI and the hooks over that snapshot, end to end.**
   `asf/rehearsal.py` and `asf rehearse`: lay the snapshot down as a throwaway product under a
   temp `HOME` — two bare origins, two checkouts, a product file, a config, a **real pinned venv**
   and the real dispatcher at `<home>/.local/bin/asf`, never a stub — then run an ordered list of
   *acts*, each a named end-to-end exercise with an expected verdict, and print one line per act.
   Exit 0 only when every act passed. Four of the acts are the card's four defect classes, and each
   is written so that it is **red on this trunk today**:
   * `ids` — the read and write commands over the snapshot's five-digit ids, plus the ratchet of
     P1: no id-shaped `\d{4}` in `asf/**/*.py` outside `ID_DIGITS`;
   * `record` — a groom pass and a replan committed through the record's own pre-commit from a
     **stale index**, the regression's own shape: the commit goes, and the guard names nothing;
   * `hooks` — the three dispatcher replays plus the record's pre-commit through the pin, and then
     the same run with the pin **removed**, which must be red (P6: today it is quietly green);
   * `tags` — every version reader over the snapshot's annotated tags, and a `cut` and a
     `prerelease` into a scratch clone.
3. **No version is offered until the rehearsal is green on that sha.**
   `release.yml` gains a `rehearsal` job that runs `asf rehearse` on a push to `main` and on a pull
   request, and the two jobs that offer a version — `release` (the patch tag and the changelog
   entry) and `preview` (the pre-release tag and its GitHub release) — gain `needs: [rehearsal]`.
   That is the edge P10 says is missing, in the idiom P11 says the repo already uses.
4. **The readiness gate carries the rehearsal as a criterion.**
   `release.ci_steps.rehearsal` (default `'release rehearsal'`, the job's step name) and criterion
   12, *release rehearsal*: the newest finished trunk run that ran the step has it green. Same
   shape as criteria 4 and 6 (P12), `n/a` when a product configures neither the step nor
   `requires.rehearsal`, and the same key added to `release_preview.STEPS` so the `preview` gate
   reads it too — because a pre-release is a version offered.

### Out

- **Fixing the four defects.** `lane.ITEM_ID_RE`, `score._JOB_RE`, `ingest._MERGED_INTO`,
  `runtime._ITEM_RE`, the `else`-less `if` at `githooks.py:182-193`, `install.newest_tag`'s pairing
  and whatever the `record` act turns up are **not** written here (C1). They are what the rehearsal
  *catches*; each becomes its own Bug card filed from the rehearsal's first red run, with the
  rehearsal's own act as its acceptance. A spec that both builds the detector and fixes what it
  detects cannot be reviewed for either.
- **Replacing the tidy fixtures.** `sample/`, `tests/e2e/product/` and `tests/gitfixture.py` are
  untouched. They are fast and readable and the suite keeps them; the rehearsal is a second,
  slower, hand-refreshed fixture beside them, not a migration (C2).
- **Shipping any real record text.** The snapshot carries ids, dates, states and structure. No
  title, no body, no History prose, no intake note text, no commit message, no branch belonging to
  a worker account (a lane is `lane-N`), no path from any machine. The builder's filler is
  deterministic from a hash of the cleared text's length, so the snapshot is reproducible and
  diffable, and `asf redact --tree` over it is an acceptance test (P17, C4).
- **Running a real session, a real runtime, or the network.** The rehearsal drives the CLI and the
  hooks. It launches no worker, authenticates against nothing, and reaches no forge:
  `tools/smoke_isolated_session.sh` is the live smoke and stays a hand-run step with its own
  recorded result (P7), and this card neither replaces it nor counts it (C5).
- **`asf trunk-check`, `asf.approvals.pre_push_check` and `tools/run_tests.py`.** The rehearsal runs
  the hooks; it does not become the product's pre-push check, does not replace the suite, and does
  not run on a worker's push. It runs in CI and by hand.
- **The merge queue, `asf/attestation.py` and `asf/tree_green.py`.** The gate here is a workflow
  edge and a readiness criterion, not a new commit status, not a new attestation, and not a new
  state file (C3).
- **Any change to the four correct tag readers** (P8) and to `asf/snapshot.py`, whose name this
  card deliberately does not reuse (P14).

### The choices

| # | the choice | chosen | against | why |
| --- | --- | --- | --- | --- |
| C1 | What this card delivers | the rehearsal, and Bug cards for what it finds | the rehearsal **and** fixes for the four defects | The four are evidence that the fixture lied, not the work. Fixing them here hides the only honest measure of whether the rehearsal works — that it goes red on the trunk it lands on — and makes the review judge a detector and four unrelated patches at once. Each defect's Bug card gets the rehearsal's own act as its acceptance, which is a better acceptance than any of them would get on its own |
| C2 | What happens to the tidy fixtures | kept, untouched, beside the snapshot | the snapshot replaces them | `sample/` is the first-user story (the README's Quick start runs it) and `tests/e2e/product/` is the lane harness's seed; both are fast and both name their own defects when they fail. A fixture of real size run by every test module would cost the suite its speed for no finding the rehearsal does not make once per push |
| C3 | How the version learns the rehearsal passed | a `needs:` edge in `release.yml`, plus a readiness criterion | a commit status the rehearsal posts and `asf.version cut` reads | `version.py` is stdlib-only and runs *before* anything is installed (its own module docstring), so it cannot read a forge. A `needs:` edge is the mechanism GitHub already gives for "not until", it is visible in the workflow file, and P11 shows the repo already gates a tag this way. The readiness criterion is the second, slower reader, for the operator and for the preview gate |
| C4 | What the snapshot carries | ids, dates, states, structure; deterministic filler for every prose run | the real record, redacted by pattern | A redaction over real prose is only as good as its pattern list, and P17's list is explicitly the *public* one — the operator keeps a private extension that is never committed. A snapshot built the other way round, keeping only what is structurally load-bearing, cannot leak what it never copied, and `asf redact --tree` over it is then a test that passes for a reason rather than by luck |
| C5 | Whether the rehearsal runs a session | no | yes, one scripted session over the snapshot | The card says *the CLI and hooks*. A session needs a runtime, credentials and a few cents per run, which is why `tools/smoke_isolated_session.sh` is hand-run with a recorded result. Adding one to every push buys the lane's own behaviour, which `tests/e2e` already covers against a scripted runtime, at the price of a CI job that can fail for an auth reason on a push that changed nothing |
| C6 | Where the snapshot lives | `tests/rehearsal/`, committed | a generated artifact fetched in CI; or `sample/rehearsal/` | Committed means `asf redact --tree` and `tools/check_privacy.sh` scan it on every push (P17), the diff of a refresh is reviewable, and CI needs no credential to fetch it. `sample/` is the first-user product and must stay eleven readable cards. `tests/rehearsal/` sits beside `tests/e2e/product/`, which is the same kind of thing (P16) |
| C7 | The command's name | `asf rehearse` | `asf smoke`, `asf snapshot`, a `tools/` script | `snapshot` already means the tick's immutable worktree (P14) and reusing it would make two unrelated things share a word in the one place a reader looks. A `tools/` script cannot be called by `release-readiness`, is not in the surface, and is the shape P7 shows gets run by nobody. `rehearse` is free across all 76 subcommands |
| C8 | How the snapshot's fidelity is kept honest | a `manifest.json` the rehearsal asserts against | trust the builder | A snapshot is a file people edit: a merge resolution or a quick fix can flatten a five-digit id back to four and silently turn the `ids` act green. The manifest makes the snapshot state its own claims, and the rehearsal's first act checks them — so the failure mode is a red act, not a quiet loss of coverage |
| C9 | When the four acts are expected to pass | never all four, on this trunk | all green at landing | Three of the four acts are red at landing by construction (P1–P2, P6, P8), and that is the proof the rehearsal works. The `release`/`preview` edge therefore lands **after** the Bug cards it would otherwise block close — the plan sequences the edge last, and until then the `rehearsal` job runs with `continue-on-error: true` and the criterion reads unmet with its evidence. A gate that must be bypassed on its first day teaches everyone to bypass it |

## The design

### 1. `tests/rehearsal/` — the snapshot

```
tests/rehearsal/
  README.md         what this is, what it must preserve, how to refresh it, what never goes in it
  manifest.json     the snapshot's own claims (C8)
  record/           a record of real shape: index.json, the item folders, intake, groom, streams
  repo/             a code-repo seed: annotated tags, a CHANGELOG, lane branch names, a merge line
```

`record/` is laid out by the product's own conventions, read from `manifest.json` — never a path
spelled in `asf/` (P19). It carries, per item type, as many cards as the real record has, each one:

* its **id verbatim**, at its real width — this is the whole point, and the manifest's
  `widest_id` per prefix is what the `ids` act asserts;
* its frontmatter keys and values where they are structural (`type`, `state`, `stage`, `parent`,
  `priority`, `area`, `delivers`, `removed`, `moved_to`, `decided`, `legacy_id`, dates);
* a History section with one line per real line, each keeping its real date, its real leading verb
  (`created`, `groom: <field> → <value>`, `landed`, `removed → merged into <id>`) and its real
  id references — and filler for everything after them;
* a title and body of filler: `filler(n, seed)` → `n` characters of ASCII lowercase words wrapped
  at the real line width, seeded by a hash of the cleared run's length so the snapshot is
  reproducible and its diffs readable.

Intake is carried in its three real states: notes still in `<intake>/`, notes already moved to
`<intake>/done/` with their `→ <id>` header, and at least one note whose `done/` copy is **not** a
byte-for-byte superstring of the note — the shape P5 says the guard's one escape depends on.

`repo/` is a seed directory, not a git repo (the builder records the ref plan in the manifest and
the runner lays it down): the file tree, plus `manifest.json`'s `refs` — for each `v<x.y.z>` tag
its target commit, its annotation text (a CHANGELOG entry, as `version.cut` writes it) and
`annotated: true`; one pre-release tag; the lane branch names; and a first-parent line of merge
commits whose subjects carry real five-digit ids and `(#<n>)` PR suffixes.

### 2. `asf/rehearsal.py` — the builder, the lay-down, the acts

Four parts, each testable alone:

```python
def build(record_dir, repo_dir, out, product=None):
    """Write a snapshot of `record_dir`/`repo_dir` to `out`: shapes kept, prose cleared.
    Returns the manifest it wrote. Reads a real record; never writes to one."""

def manifest_holds(snapshot):
    """[] when the snapshot still meets its own manifest.json — card count per type, widest
    id per prefix, tag count, annotated count, intake states — else one line per claim it
    no longer meets (C8)."""

def lay(snapshot, root, product='rehearsal'):
    """Lay the snapshot down under `root` as a throwaway product: origins/record.git and
    origins/repo.git seeded from the snapshot, the two checkouts, `home/` with
    products/<p>.yaml and config.yaml, the refs of manifest['refs'] created as the manifest
    says (an annotated tag with `git tag -a -m <its annotation>`), a real venv pinned in
    state/<p>/install.json and the real dispatcher written at home/.local/bin/asf
    (asf.dispatch.install). Returns the laid-down paths. No stub CLI anywhere (P16)."""

def rehearse(snapshot, root=None, acts=None, out=print):
    """Run each act against a fresh lay-down. Returns [(name, ok, detail)]; `out` gets one
    line per act, `ok`/`FAIL`, its name, and on a failure what it saw."""
```

The acts are an ordered tuple of `Act(name, what, run)`, so one can be run alone (`--act ids`) and
so the list is the thing a plan adds to:

| act | what it drives | red on this trunk because |
| --- | --- | --- |
| `manifest` | `manifest_holds(snapshot)` | — (green; it guards the others) |
| `ids` | `asf index`, `asf next`, `asf status --json`, `asf backlog`, `asf groom`, `asf harvest --dry-run`, `asf scorecard`, `asf release-readiness --json` over the snapshot; then every id in the snapshot through `lane.item_of` (from a `worker/<id>` branch name with no session row), `ingest`'s `merged into <id>`, `runtime`'s job name and `score`'s job key; then the P1 ratchet over `asf/**/*.py` | P1, P2 — four patterns, three silent misses and one truncation |
| `record` | `asf groom` writes its pass; a replan is applied; both are committed through the record's own pre-commit (`asf redact --pre-commit`, which runs `staged_guard.check`) with the index read at the commit's **parent** and the tree at its head — a stale index over a record of real size — and once more with an intake note whose `done/` copy is not a superstring of it | P4, P5 — no writer sets the escape, and the one escape is a substring test |
| `hooks` | `asf hooks install` into the laid-down home, then the three `tools/hook-smoke.sh` replays (`hook approvals` on a `PreToolUse` payload, `hook unpushed` on a `Stop` payload, `redact --pre-push` on a ref list) plus the record's `pre-commit`, each asserted to have been answered by the **pinned** venv via `ASF_DISPATCH_TRACE=1`; then one `pre-push` of a branch outside `ASF_PUSH_ALLOW` which must be refused; then the whole set again with the pinned venv's `bin/asf` removed, where every call must be **red** | P6, P7 — a missing dispatcher skips the trunk check and leaves `rc` 0, and nothing runs the replays |
| `tags` | over the laid-down repo: `version.of_commit`, `version.label`, `version.plan`, `version.tag_entries`, `version.health`, `install.newest_tag` — each asserted against `manifest['refs']`, so an answer that is a tag object's sha rather than its commit's is a failure; then `version.cut` and `version.prerelease` into a scratch clone of it, and `version.health` green after | P8, P9 — one reader pairs a name to a tag object, and no fixture has a tag |

`rehearse` lays the snapshot down **once per act** (a `shutil.copytree` of a template built once,
the `tests/gitfixture.py` shape of P16), so an act that writes cannot change what the next one
reads, and removes each root on the way out unless `--keep`.

The module is stdlib-only apart from `asf` itself, hardcodes no record path, no branch prefix and
no item id (P19), and names a lane `lane-N` wherever it needs one.

### 3. `asf rehearse` — the command

```
asf rehearse [--snapshot DIR] [--act NAME]... [--keep] [--json]
asf rehearse --build --from-product <p> [--snapshot DIR]
```

Default `--snapshot` is `tests/rehearsal/` under the repo root the command is run from. One line
per act; exit 0 only when every act passed, 1 on a red act, 2 on a usage or lay-down error.
`--json` prints `{"snapshot": …, "acts": [{"name", "ok", "detail"}], "ok": bool}`. `--build` is the
operator's refresh: it reads the named product's real record and writes the snapshot plus its
manifest, and prints the diff summary a reviewer reads.

Registered in `asf/cli.py` beside `release-readiness`, in `asf/surface.py` with scope `REPO`
(*"rehearse the release: run the CLI and the hooks end to end on a record-shaped snapshot"*), and
**not** in `plugin_build.VIEWS` — it is not a table. The plugin is regenerated in the same commit,
because `asf plugin check` is a CI step (P15).

### 4. `.github/workflows/release.yml` — the gate

A new job, and two `needs:`:

```yaml
  rehearsal:
    if: github.event_name != 'workflow_dispatch' || github.ref == 'refs/heads/main'
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with: {fetch-depth: 0}
      - uses: actions/setup-python@v5
        with: {python-version: "3.12"}
      - run: python3 -m pip install --quiet .
      - name: release rehearsal          # release.ci_steps.rehearsal reads this name
        run: |
          git config --global user.name ci
          git config --global user.email ci@localhost
          asf rehearse
```

`release` and `preview` each gain `needs: [rehearsal]`. Per C9 the step carries
`continue-on-error: true` while the Bug cards the first red run files are open, and the plan's last
Task removes it — that removal is the moment the gate starts biting, and it is one line in one
file, reviewable on its own.

The job runs on a push to `main` and on a pull request, so a change that would break the rehearsal
is red on the PR rather than on the trunk. It does **not** run on the `workflow_dispatch` of a
non-`main` ref, where `preview` would not run either.

### 5. `asf/release.py` and `asf/release_preview.py` — criterion 12

`DEFAULTS['ci_steps']` gains `'rehearsal': 'release rehearsal'`; `config`'s `configured` gains
`'rehearsal': bool(req.get('rehearsal') or steps.get('rehearsal'))`; and criterion 12, in the shape
of criteria 4 and 6:

* not configured → `n/a`, *"not configured (release.requires.rehearsal,
  release.ci_steps.rehearsal)"*;
* configured → the newest finished trunk run that ran the step, that step green, and
  `requires.rehearsal` landed; its evidence names the run, the step and its conclusion.

`release_preview.STEPS` gains `'rehearsal': 'release rehearsal'` and the `preview` gate gains it as
a sixth criterion, read the same way over the same lookback. The module docstrings,
`docs/config.example.yaml`'s `release:` block and the guide's release page are updated in the same
commit. No `asf/env.py` change is needed (P13).

### What it looks like when it is there

A push lands on `main`. The `rehearsal` job lays a record of the real product's size down under a
temp `HOME`, with a real venv pinned and the real dispatcher in front of it, and drives the CLI and
the hooks over it: five acts, one line each. While it is green, `release` runs and the push gets its
version. When it is red — an id the CLI drops, a deletion the guard refuses, a hook answered by the
wrong binary, a tag read as an object — the job says which act, on what input, with what answer,
and **no tag is cut and no changelog entry filed**: the version is not offered. `asf
release-readiness` shows criterion 12 beside the other eleven, met or not, with the run and step it
read. And the snapshot is refreshed by one command whose output a reviewer can diff, because the
only thing in it that moves is a shape.
