# F-0185 — the factory knows six vendor tools by name and nothing at all about what a product uses them for

A product's external services are, today, six facts scattered across four files and one hardcoded
list:

- **What tools exist** is a literal in code. `_CLI_TOOLS` (`asf/doctor.py:370-378`) names six
  command-line tools and one probe each, and `check_cli_sessions` runs them for *every* product —
  a product that uses none of the five optional ones still gets five `skip` rows, and a product
  that uses a seventh gets no row at all. Adding a service is a code change to a public,
  genericity-fenced package.
- **What a service is *for*** is nowhere. Not a field, not a list, not a word. So every reader that
  needs it hand-sets its own key: the Runners row reads `ci.runner_org` (`asf/views/status.py:99`),
  the Prod row reads `deploy_sha.workflow` through a three-way alias fold
  (`asf/views/status.py:112-121`, `asf/env.py:793-806`), and neither can say *which login* those
  keys depend on or what to run when it has lapsed.
- **What a command against a service means** is guessed. `approvals` classifies a deploy only by
  the two things it can derive from the product — a trunk push and the one `deploy_sha.workflow`
  name (`asf/approvals.py:491-493`) — so a hosting CLI's own deploy verb, or a database CLI's
  `migrate`, matches nothing and passes the gate as an ordinary command. A product can add a
  pattern by hand (`approval_signals`, `asf/approvals.py:199-221`), but it is a second, unrelated
  declaration with no link to the login it acts through.
- **Whether a session can use a service** is a per-account, per-variable arrangement made three
  files away: `auth_env` (`asf/env.py:401-419`), `home_seed` (`asf/workers/runtime.py:204-240`),
  `isolate_home` (`asf/workers/pool.py:88-89`). A worker session runs on its own HOME and its own
  config dir and inherits *no* operator login unless somebody wired that variable or that path in
  by hand for that account.
- **Whether a login is still valid** is the one half that is already generic — `asf.credentials`
  (F-0042) — and it is declared in a *different file* (`config.yaml: credentials.providers`) from
  every other fact above, keyed by a name the product file then repeats as a bare string
  (`asf/env.py:858-861`).

Five readers, five declarations, no line between them. The operator who added the first external
CI, hosting platform and hosted database hit all five gaps in one sitting, and each was a separate
hand edit in a separate file.

This card declares the service **once, in the product file, as data** — what it is, what proves it
is logged in, what logs it in, what it is used for, what its commands mean, and whether a session
gets it — and turns each of the five readers above into a reader of that one block. Nothing new is
invented where something generic already exists: the probe contract is `asf.credentials`'s, the
command→class mechanism is `approval_signals`'s, the session-auth mechanisms are `auth_env` and
`home_seed`. What is new is the single place they are all named from, and a catalogue that makes
adding a service a data change.

> The card as it reached this session is truncated mid-sentence inside piece 2 (`asf connect`); its
> title line — *"`asf connect` sets up auth, doctor/status/approvals/sessions all read it"* — names
> the four readers, and the four capability words in the body (CI, deploy, database, preview) name
> the vocabulary. The design below covers exactly those and adds nothing the title does not name.
> D12 records this.

### In

- **`connectors:`, a new top-level map of the product file** — one entry per external service,
  free-named by the operator, carrying `kind`, `template`, `check`, `login`, `secret`, `home`,
  `provides`, `actions` and `sessions`. Validated by a new module, through P3's call-out seam.
- **`asf/connectors.py`** — the whole model and its readers, in one module that names no vendor:
  `load(product)` → `{name: Connector}` with the catalogue template applied under the product's own
  keys; `product_problems(value)` for `env.validate_product_text`; `provided(product, capability)`
  → `(connector, settings)`; `approval_signals(product)`; `session_auth_env(product)` and
  `session_home_paths(product)`; `as_provider(connector)`; `rows(product)` for the doctor.
- **`asf/connectors/catalogue/*.yaml`, shipped as package data, overridden by
  `~/.ASF/connectors/*.yaml`** — one file per service, each the default body of a connector block.
  The six entries `_CLI_TOOLS` hardcodes today are moved there verbatim, so the move loses nothing
  and adding the seventh is a data change. `$ASF_CONNECTOR_CATALOGUE_DIR` overrides the shipped dir
  for tests, exactly as `$ASF_CORE_RULES_DIR` does (P11).
- **`asf connect [<name>] --product P`** — read-only, idempotent, and the one place the operator is
  told what to run: per connector, is the tool installed (else the catalogue's `install:` line), is
  it authenticated (`check:` under the credentials probe contract), and is its secret reachable.
  Exit 0 when every connector checked is authenticated, 1 when any needs the operator, each such
  connector printing one `NEEDS OPERATOR:` line and one `! <login>` line. `--template <t> --print`
  emits the yaml block to paste into the product file.
- **The doctor's `cli:` rows become `connector:` rows** for a product that declares a `connectors:`
  block; a product that declares none keeps exactly today's rows, from the catalogue rather than
  from code (D4).
- **`approvals.signals` gains a second source** — every `actions:` entry of every connector, as a
  `commands` pattern under the class it names. The classifier, the doctor's approvals row and
  `asf approvals` all inherit it unchanged (P6).
- **Session inheritance, through the two carriers that already exist** (P8) — a connector with
  `sessions: inherit` and a `secret:` contributes its variable to the spawn's `product_auth_env`;
  one with `sessions: inherit` and `home:` contributes its paths to `seed_home`. `sessions: none`
  is the default and contributes nothing.
- **The two status cells read `provides:` when their hand-set key is unset** — `provides: {ci:
  {org: …}}` fills `runners_cell`, `provides: {deploy: {workflow: …}}` fills `prod_cell`. The
  hand-set key still wins; a disagreement between the two is a doctor finding.
- **The daily credential check covers connectors** — `credentials.for_product` also returns
  `as_provider(c)` for every connector with a `check:`, so F-0042's rule, its `NEEDS OPERATOR` line
  and its doctor row cover a connector with no new daily pass and no second probe runner.

### Out

- **No secret value, ever, anywhere.** `secret:` names a *location* (`env:VAR`, `file:PATH`,
  `keychain:SERVICE`) and is validated to be one of those three shapes; a value that scrubs
  differently from itself is refused with P15's existing words. No connector field is ever printed
  by `connect`, written to the record, logged, or carried in a brief. The only text a check may
  emit is its last non-empty line, through `run_probe`'s scrub-and-truncate (P4).
- **`asf connect` runs no `login:`, edits no product file, installs no tool.** It prints. Three
  reasons and they are independent: an interactive login cannot be driven by a command the tick may
  call; the product file is operator config and editing it from a session is `touch_security`; and
  a command that both checks and mutates is not idempotent in the sense the card asks for.
  `surface.COMMANDS` records this as effect `None` (P13).
- **No oauth flow is performed by asf.** `kind: oauth` is declared, validated and checked like any
  other; its `login:` is printed for the operator, who runs it in a browser. asf mints, refreshes
  and stores no token.
- **No new approval class, and no change to the classifier.** `actions:` may only name a class in
  `approvals.CLASSES`; an unknown one is a validation error. The one edit is a second source inside
  `signals()` (P6) — `_command_matches`, `_classify_command` and `classify` are untouched.
- **No change to `config.yaml: credentials.providers`.** It stays exactly as F-0042 shipped it, for
  a login shared across products. A connector is the per-product form of the same thing, and
  `for_product` returns both.
- **No change to what the status cells *do* once configured.** The live `gh run list`, the
  `git rev-list` count and `deploy.lines` are untouched; only where an unset key's value comes from
  moves.
- **No migration of any existing product file.** A product with no `connectors:` block behaves
  today's way, and nothing in this card writes one for it (D4).
- **`STORY_ID_RE`'s four-digit shape is not fixed here** (P16).

## The design

### `asf/connectors.py` — the model, and every reader's one entry point

The module is new, and it is the only place the shape is written down. It names no vendor and no
product: every service word in it is a value read from data (P12).

```python
#: what a capability word may be — the closed half of `provides:` (D11)
CAPABILITIES = ('ci', 'deploy', 'db', 'preview', 'secrets', 'code')
#: what `kind:` may be
KINDS = ('cli', 'token', 'oauth')
#: what `sessions:` may be; the default is the first
SESSION_POLICIES = ('none', 'inherit')
#: the three shapes `secret:` may take — a location, never a value (D8)
SECRET_SCHEMES = ('env', 'file', 'keychain')


@dataclasses.dataclass(frozen=True)
class Connector:
    name: str
    kind: str                     # one of KINDS
    check: tuple = ()             # argv; rc 0 = authenticated (D2)
    login: tuple = ()             # argv the operator runs, once, interactively
    install: str = ''             # the line that installs the tool, from the catalogue
    secret: str = ''              # '<scheme>:<locator>'
    home: tuple = ()              # the paths a `cli` login writes (P8's second carrier)
    provides: dict = ...          # {capability: {settings}}
    actions: dict = ...           # {action name: {'match': regex, 'class': approval class}}
    sessions: str = 'none'
    template: str = ''            # the catalogue entry this was filled from
```

`load(product)` reads `product._get('connectors')`, resolves each entry's `template:` through
`catalogue_entry(name)`, and merges — **the product's own key always wins over the template's**,
key by key, no deep merge inside `provides` or `actions` (a declared `actions:` replaces the
template's outright, so an operator can narrow one). It raises `env.ConfigError` on anything
`product_problems` would report, so no caller has to re-validate.

`catalogue_entry(name)` is `rules.resolve_script`'s rule over files: `~/.ASF/connectors/<name>.yaml`
first, then `<catalogue dir>/<name>.yaml`, `None` when neither exists — and the catalogue dir is
`$ASF_CONNECTOR_CATALOGUE_DIR` when set, else `catalogue/` beside `__file__` (P11).

`product_problems(value)` returns `[(dotted key, problem)]` for `env.validate_product_text`'s
call-out list (P3), reporting: a `connectors:` that is not a map; an entry that is not a map; a
`kind` outside `KINDS`; a `template` no catalogue file defines; a `check`/`login`/`home` that is
not a list of non-empty strings; a `secret` outside `SECRET_SCHEMES`; a `secret` whose text scrubs
differently from itself (P15's words, verbatim); a `provides` naming a capability outside
`CAPABILITIES`; **two connectors providing one capability** (D5); an `actions` entry missing
`match`, carrying an uncompilable regex, or naming a class outside `approvals.CLASSES_BY_NAME`; a
`sessions` outside `SESSION_POLICIES`; and `sessions: inherit` with a non-`file:` secret (D8),
whose problem text names the `file:` form to use instead.

The readers, each one function, each pure over `load(product)`:

| function | returns | read by |
| --- | --- | --- |
| `provided(product, capability)` | `(Connector, settings dict)` or `(None, {})` | `views/status.py` |

### `asf/connectors/catalogue/` — the six, moved out of code

One file per service, each named for the service and carrying the default body. The shipped set is
the six entries of `_CLI_TOOLS` (P1), each written as:

```yaml
# asf/connectors/catalogue/<service>.yaml
kind: cli
legacy: true                  # part of the pre-connectors default set (D4)
required: false               # `required: true` only for the code host, and only when has_pr_host
```

`legacy: true` is read by nothing but D4's fallback. An operator's own file in `~/.ASF/connectors/`

### `asf/doctor.py` — one list shrinks to one entry, and the rows come from data

`connectors.rows(product)` runs each connector's `check:` through `credentials.run_probe` under

`findings` reports D6's disagreements (`ci.runner_org` set *and* a `ci` connector carrying a

### `asf/connect.py` — the command

```
asf connect [<name>] --product P [--template <t> --print]
```

Per connector (all of them when `<name>` is omitted), in this order, stopping at the first that
fails and printing one line for it:

1. **Installed?** `shutil.which(check[0])`. If not: `NEEDS OPERATOR: <name> is not installed — <the
   catalogue's install line>`.
2. **Secret reachable?** For `file:`, the file exists and is non-empty; for `env:`, the variable is
   set in the operator's own environment; for `keychain:`, the service name is non-empty. Never the
   value, never a byte of it. If not: `NEEDS OPERATOR: <name>'s secret is not readable — <the
   location, not its content>`.
3. **Authenticated?** `run_probe(as_provider(c), probe_env(...), now)`. `valid` prints the probe's
   own scrubbed last line as the identity. `invalid` or `broken` prints
   `NEEDS OPERATOR: <name> is not authenticated — run: ! <shlex.join(login)>`.

Then one line per connector naming what it provides and its session policy, so the operator can see
the whole product's external surface in one screen. Exit 1 if any connector printed a
`NEEDS OPERATOR:` line, else 0 (D10). `--template <t> --print` skips all of it and writes the
catalogue entry's body to stdout as the yaml block to paste under `connectors:`.

Registered the established way: `connect.register(subparsers)` called from `cli.build_parser`, and
declared in `surface.COMMANDS` as
`'connect': ("check each declared connector's auth and print what the operator must run", None, None)`
— effect `None`, because it writes nothing (P13, and the Out list's first two entries).

## Records

**The product file** (`~/.ASF/products/<name>.yaml`, operator config — outside every tracked tree,
P2) gains one block, and it is the only thing an operator writes:

```yaml
connectors:
  <name>:
    kind: cli | token | oauth
    template: <catalogue entry>
    check: [<argv>]
    login: [<argv>]
    secret: file:<path> | env:<VAR> | keychain:<SERVICE>
    home: [<path>]
    provides: {<capability>: {<setting>: <value>}}
    actions:
      <action>: {match: "<regex>", class: <approval class>}
    sessions: inherit | none
```

**Files this change adds:** `asf/connectors.py`, `asf/connect.py`,
`asf/connectors/catalogue/<service>.yaml` (six shipped, one per entry `_CLI_TOOLS` held),
`tests/test_connectors.py`, `tests/test_connect.py`. **Files it edits:** `asf/doctor.py`,
`asf/approvals.py`, `asf/credentials.py`, `asf/env.py`, `asf/cli.py`, `asf/surface.py`,
`asf/views/status.py`, `asf/workers/spawn.py`, `asf/workers/runtime.py`, `pyproject.toml`,
`docs/products.example.yaml`, `README.md` (its generated span only).

**Rows:** `connector:<name>` and `connectors` in `asf doctor`; `signal command: …` lines in
`asf approvals` and the doctor's approvals row; a connector-named clause in the Runners and Prod
cells' `not configured` text.

**Events:** none new. A connector-derived refusal is an ordinary approvals-ledger entry, written by
the code that already writes them, under a class that already exists. An expired connector login is
F-0042's existing `NEEDS OPERATOR` line.

**What is never written down:** any secret value; any `env:` variable's content; any `keychain:`
lookup's result; any byte of a `file:` secret. The only connector-derived text that reaches a log,
a report, the record or a push is a probe's last non-empty line after `run_probe`'s scrub and
160-character truncation (P4), and — for a `file:` secret carried into a session — that value is a
redaction pattern, which is what D8 exists to guarantee.
