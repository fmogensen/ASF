# F-0188 — the reference is the product's, the mechanism is the factory's

Every product is built against something: a competitor to match, a contract or RFP, a regulation
checklist, a system being replaced. ASF already carries exactly one hard-coded instance of that
idea — `conventions.matrix_path`, a single markdown table, read for Story status — and one table
named after one product's word for it, `asf parity`. The card asks for the generic mechanism: the
product declares its references and supplies their content; the factory measures rows → Stories →
Tasks → evidence, and closes a row only on the evidence that reference asks for.

Three things were checked against the checkout before this spec was written, and each one moves the
shape:

- **`asf parity` today is not a parity table at all.** `asf/views/parity.py` reads `index.json` and
  prints *every* Story in the record grouped by its `area`, with no reference, no percentage and no
  test evidence (P6). It shares nothing with `conventions.matrix_path` but the word. So this card is
  not "add a column to the parity table" — it is the first reference table the product has had.
- **The command has already been retired.** `surface.RENAMED` maps `parity → stories` and
  `tests/test_surface.py` asserts no `RENAMED` key is a declared command, so `asf parity` **cannot
  be declared** in `surface.COMMANDS` as the card's §4 asks (P7). It survives today only because
  `surface.apply` — the function that would refuse a registered-but-undeclared command — has no
  caller (P8). The alias is kept, and the retirement is re-pointed at `coverage` rather than fought.
- **A reference Story closes today on a merge alone, and the machinery to close it on a test
  already exists.** `closing.state_of('story', Ev(children=('Closed',), in_prod=True))` returns
  `Closed / tasks-closed` with no test anywhere in the question (P9, run live). Meanwhile
  `asf.proves` already binds a named test to a Story's acceptance line, and `evidence.landed_proves`
  already refuses a claim that is not on the trunk (P10). §3 of the card is therefore one closing
  rule over evidence the record already collects, not a new evidence pass.

What this spec does **not** do is invent a second definition of anything. The reference's shape is a
declared product field checked where every other one is checked; the row's trace is two typed
frontmatter fields that need no schema change at all (P11); the closing rule is a row in
`closing.RULES`, because that module is the only thing allowed to choose a state (P12); and
`decide: need` is a row in `policy.POLICIES`, because that tuple is the only place a card is decided
by code.

### In and out

**In.** The `references:` declaration, its per-entry shape check, `Product.references` with the
`matrix_path` fallback, and its documentation in the example yaml (C1, C2). The row trace as two
typed Story fields (C4). Closing by the reference's declared evidence kind, as two rules in
`closing.RULES` over two new `Ev` fields (C5, C10). `asf coverage [--reference <id>]`, the `parity`
alias and the retirement re-point (C6, C7, C11, C12). `decide_reference_gap` as a groom policy over
the gap Story's Feature (C8, C9).

**Out, deliberately:**

- **A generic reference *file* format** — declared columns, a declared row matcher, a declared
  status vocabulary. `source: file` is exactly today's `matrix_path` and today's `parse_rows`, hard
  `| F-` prefix and all (C3, P18). Generalising it needs a second real reference file to design
  against; naming it here is the whole of what this spec does about it.
- **The tick's PARITY shadow table.** It keeps rendering `views/parity.py` (P23, C6). Making the
  tick's table the coverage table changes a golden-compared surface and is its own card.
- **`plugin_build.VIEWS` and the generated `plugin/skills/`.** No new skill directory; the existing
  `parity` skill prints coverage through the alias (C6, P20).
- **A defect filer for coverage mismatches.** Reported as table rows, not filed (C11).
- **`asf stories`.** `surface.COMMANDS` declares it and no parser registers it (P8) — F-0084's
  residue, found while reading the surface for C6, and not this card's to clean up. It is left
  exactly as it is; `RENAMED` simply stops pointing `parity` at it.
- **Retiring the word `parity` from `asf/evidence/evidence.py`, `asf/groom/policy.py` and
  `asf/tick/migrate.py`.** `docs/plans/f-0084.md` PD7 already ruled that those eleven lines are the
  parity *matrix* and a legacy id prefix (`upsert`'s dedupe key — changing it re-mints cards), and
  that retiring the word there is a card of its own. Unchanged here.
- **Any edit to the operator's own `products/<p>.yaml`.** A product that wants a reference declares
  one; nothing in this repo writes that file.

## The design

### 1. The product declares its references

`asf/env.py`. One new key in `PRODUCT_FIELDS`, one new per-entry checker, one new `Product` property.

```python
PRODUCT_FIELDS = {
    ...
    'release': _MAP, 'cloud': _MAP, 'credentials': _LIST, 'references': _LIST,
}

#: `references:` — what a reference row may declare. `source` says where the rows come from;
#: `decide` is the groom policy for a gap row; `evidence` is what closes one (F-0188 §1).
REFERENCE_SOURCES = ('stories', 'file')
REFERENCE_DECIDES = ('need', 'ask')
REFERENCE_EVIDENCE = ('test', 'merge')
REFERENCE_FIELDS = {'id': _STR, 'name': _STR, 'source': _STR, 'epic': _STR, 'path': _STR,
                    'decide': _STR, 'evidence': _STR}
```

`_reference_problems(references)` returns `[(dotted key, why)]` and is appended in
`validate_product_text` beside `_deploy_problems` and `ci_pool.pool_problems` (P3). It refuses:

- `references:` that is not a list → `references must be a list, not <v>`;
- an entry that is not a map → `references[<n>] must be a map, not <v>`;
- a missing or empty `id`, and a duplicate one → `references[<n>].id is already declared`;
- a key outside `REFERENCE_FIELDS` → `references.<id>.<key> is not a field of a reference`;
- `source` outside `REFERENCE_SOURCES`, `decide` outside `REFERENCE_DECIDES`, `evidence` outside
  `REFERENCE_EVIDENCE` → `must be one of a | b, not <v>`;
- the two combinations that cannot be read: `source: stories` with no `epic`, and `source: file`
  with no `path`. A `source: stories` entry carrying `path`, or a `source: file` entry carrying
  `epic`, is refused as `is not read when source: <s>` — a key that would silently do nothing.

A `None` value stays "not filled in yet", as everywhere else in this table.

The defaults, applied in `Product.references`, not in the checker: `source: stories`,
`decide: ask`, `evidence: test`, `name` falling back to the `id`.

```python
@dataclasses.dataclass(frozen=True)
class Reference:
    id: str
    name: str
    source: str       # stories | file
    epic: str = ''    # source: stories — the Epic whose Stories are the rows
    path: str = ''    # source: file — the old conventions.matrix_path
    decide: str = 'ask'
    evidence: str = 'test'
```

`Product.references` → a tuple of `Reference`, in declared order. When the yaml declares none and
`conventions.matrix_path` is set, it yields the single synthesised legacy reference (C2):
`Reference(id='parity', name='parity', source='file', path=<matrix_path>, evidence='merge',
decide='ask')`. When it declares none and there is no `matrix_path`, it is empty — the product has
no such thing, and nothing looks for one.

`Product.reference(ref_id=None)` → the named reference, or the first declared one when `ref_id` is

`docs/products.example.yaml` gains a documented `references:` block at the top level — the Epic id
written as a comment placeholder, never a literal `E-nnnn` in any `asf/**/*.py` (P19) — and
`conventions.matrix_path`'s comment gains the sentence that it now reads as one `source: file`
reference and that `references:` supersedes it.

### 2. A row is traced, and closes on the evidence its reference asks for

**The trace.** A reference row's Story carries two typed frontmatter fields (C4, P11):

```yaml
reference: parity
ref_row: "3.2.4"
```

`ref_row` is `"<section>.<row>"`: the section is the text before the **last** `.`, the row is what
follows. A `ref_row` with no `.` is all row and the section falls back to the Story's `area`; no
`ref_row` at all falls back to `area` for the section and the Story id for the row. Nothing rejects
a Story that carries `reference:` and no `ref_row` — it is a traced row in an unnamed section, and
`asf coverage` says so.

**The closing rule.** `asf/evidence/closing.py`. `Ev` gains two fields, and they only mean anything
together:

```python
ref_evidence: str = ''    #: the reference's declared evidence kind, for a Story traced to one
ref_proven: bool = False  #: every acceptance bullet proven by a named test green on the trunk
```

Two `story` rules are inserted **immediately before** `tasks-closed` (C5 — position is the
mechanism):

```python
('story', 'ref-tested',
 lambda ev: ev.ref_evidence == 'test' and ev.ref_proven and _all(ev, (CLOSED,)) and ev.in_prod,
 CLOSED, 'a reference row: every Task Closed, in prod, and its acceptance proven by a green test'),
('story', 'ref-untested',
 lambda ev: ev.ref_evidence == 'test' and not ev.ref_proven and _all(ev, _DONE),
 RESOLVED, 'a reference row whose acceptance is not proven by a green test on the trunk'),
```

A Story with `ref_evidence != 'test'` — every Story in every product that declares no reference, and
every legacy `matrix_path` row (C2) — matches neither and falls through to exactly today's five
rules. `reconciled` still leads (C10).

**Where the two fields come from.** `asf/record/ingest.py`, in `derive`'s Story loop, beside the
`review_claims` block that is already there. For a Story whose typed `reference:` resolves to a
declared reference:

- `ref_evidence` is that reference's `evidence`;
- `ref_proven` is `bullets and every bullet has a landed claim whose sha is green` —
  `ev['proves'][iid]` gives the landed claims (P10: a claim is not evidence until it is on the
  trunk), `proves.bullets(rec['body'])` gives the denominator, and `_green_after(ev, product)`
  answers green-at-or-after for each claim's sha. A Story with no `## Acceptance` bullet is not
  proven — there is nothing for a test to prove.

The existing evidence line gains one more: `reference <id> row <ref_row>: <n>/<m> acceptance lines
proven green`. `settle` is still the only place a state is chosen (P12); `story_state` is not touched
(P13).

### 3. `asf coverage`

A new module `asf/views/coverage.py`, in the shape of `views/parity.py`: `index_reader`, no git, no
network (C12). No `E-nnnn` and no `feature-matrix` literal anywhere in it (P19).

```python
def render(root, product, ref_id=None, full=False):
    """The COVERAGE table for one reference: rows built / tested / missing, a % per section,
    gaps first."""
```

**The rows.**

- `source: stories` — every Story whose `parent`'s Epic is the reference's `epic`, plus every Story
  carrying `reference: <id>` (a row traced explicitly but parented elsewhere). Ordered by section
  through `parity.area_key` (P6 — it already sorts `1.2.10` numerically), then by row.
- `source: file` — the rows of `evidence.parse_rows(open(<path>).read())` (C3), joined to Stories on
  `ref_row`, then on the row's own `id` for the legacy matrix whose rows *are* item ids.

**The three states per row**, read from the record, never recomputed (C12):

| state | means |
| --- | --- |
| `missing` | no Story for the row, or a Story with no Task |
| `built` | a Story with a Task, not yet Closed |
| `tested` | the Story is `Closed` — which under `evidence: test` is §2's `ref-tested` rule, and under `evidence: merge` is today's `tasks-closed` |

**The shape.** A header naming the reference, its source, its evidence kind and the totals; then
`GAPS FIRST` — every `missing` row, then every `built` row, each with its section, row, Story id (or
`—`), state and title; then `BY SECTION`, one row per section with built / tested / missing / total
and a `%` that is `tested / total`; then a `MISMATCHES` block (C11) naming, by class: a Story whose
`reference:` names no declared reference, a `ref_row` matching no row of a `source: file` reference,
and a row claimed by two Stories. An empty `MISMATCHES` block is not printed.

`--reference <id>` selects; absent, the first declared reference (C6). A product that declares none
prints one line saying so and exits 0.

**The registrations**, all in one commit:

- `asf/cli.py`: `sub.add_parser('coverage', ...)` with `--product`, `--reference` and `full`, and
  `coverage` added to the view-dispatch tuple at `cli.py:539` beside `parity`; the existing
  `parity` parser's dispatch at `:548` becomes the alias — the first declared reference, falling
  through to `views.parity.render(root)` when the product declares none (C7).
- `asf/surface.py`: `'coverage': ('print every row of a reference, what is built, what is tested
  and what is missing', None, None)`, and `RENAMED['parity'] = 'coverage'` (C6). `tests/test_surface.py`'s
  `49` becomes `50` (P22).
- `asf/views/header.py`: `TITLES['coverage'] = 'COVERAGE'` — legal because the parser is registered
  in the same commit (P20). `plugin_build.VIEWS` is not touched.

### 4. `decide: need` is a groom policy

```python
def decide_reference_gap(item_id, rec, canonical, derived, ctx):

```

It answers `Answer('yes', 'decided', True, f'reference {ref.id} row {ref_row}: decide: need')` when,
and only when: the item is a `feature`, `_undecided(rec)`, and it has a child Story whose typed

Task, or a Task set that is not all Closed. Otherwise `None`.

**after** `decide_on_approved_doc` and **before** `decide_or_close_ci_red` — a close always wins over
a decide, and an approved document on the trunk is a stronger reason than a reference asking. The
same name is added to `groom.POLICY_NAMES` at the same index, because the test asserts list equality
(P15). `policy_on` gives it `groom.policies.decide_reference_gap: off` for free (P16), and `barred`
is unchanged — deciding a non-Epic card crosses no approval class (P16).

The feeder is not touched (C8, C9). The decided Feature with `stage: card` gets the ordinary
`CARD → SPEC` row, "decided card, no spec", with no operator step in it.

## Records

- **In the product file** (the operator's, not this repo's): a new top-level `references:` list, one
  entry per reference, each declaring `id`, `name`, `source`, `epic` or `path`, `decide` and
  `evidence`. Nothing in this repo writes it; `docs/products.example.yaml` documents it.
- **On a reference row's Story card**: two typed frontmatter fields, `reference: <id>` and
  `ref_row: "<section>.<row>"`. No new folder, no schema bump — `index.json` carries both the moment
  the card is indexed, because `build_index_data` copies every typed field (P11).
- **In `index.json`**: `reference` and `ref_row` per traced Story, and each reference Story's
  `state` as §2's rule derived it.
- **On each reference Story, at ingest**: the state and `evidence:` rule name written by `settle` —
  `ref-tested` or `ref-untested` where it used to be `tasks-closed` / `tasks-resolved` — plus one
  new evidence line, `reference <id> row <ref_row>: <n>/<m> acceptance lines proven green`, and the
  matching `## History` line the ingest writer already appends on a state change.
- **What stops being written**: a `Closed` state on a reference Story whose named test is not green
  on the trunk. Under `evidence: test` that Story now holds at `Resolved` until the test lands green
  — the one behaviour change to an existing record, and only for a product that declares a
  reference (C2 keeps every legacy `matrix_path` row on `tasks-closed`).
- **In the groom file**: for a gap row, `→ answer: controller: decide_reference_gap yes` on the
  card's line in every decision section it appears in, and the applier's `by: rule:decide_reference_gap`
  written through `apply_groom_answers` — `decided: true` on the Feature, with its History line.
- **In the feeder's rows** (read, not written): one `CARD → SPEC` row per decided gap Feature,
  `reason: decided card, no spec`, with no operator step (C9).
- **On stdout only, never a file**: the `COVERAGE` table — the header line, `GAPS FIRST`,
  `BY SECTION` with a `%` per section, and `MISMATCHES` when there are any. `asf coverage` writes
  nothing; its `surface.COMMANDS` row declares no effect.
- **No new state file, no new record folder, no schema migration, no new config key outside
  `references:`, and no change to the tick's six shadow tables or the generated plugin skills.**
