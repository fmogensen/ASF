# F-0152 — the round comes off the branch, not off a stage that never carried one

The adjudicate brief hands a session the wrong file. On the reporting product's T-0141 it printed

```
Review file to answer: `.sdd-input/reviews/1-t-0141.md` (round 1)
```

while the branch carried rounds 1 through 5 and round 5 was the approval. The adjudicator read the
first round's findings — four rounds of argument, and the verdict, invisible to the one session
whose whole job is to end the argument.

This is not a formatting slip. **The brief derives the round from the record and never looks at the
branch.** `collect` asks `feeder_rows.review_round(feature or item)` (P1), whose regex matches
`spec-review rN` and `plan-review rN` only (P2) — and a *Task* is never given a stage at all, by
design (P3). So for every Task the answer is `(None, 0)`, `read_round` falls back to `1` (P4), and
the path is `<reviews_dir>/1-<slug>.md` whatever the branch holds. Reproduced in this checkout at
`a6a4277ea` (P5).

The path the reviewer writes is right by a different route: the `PUSHED → REVIEW` row carries
`review_round=` off the lane's occupancy (P6). The `STALEMATE → ADJUDICATE` rows carry no such
field (P7) — which is why the write side works and the answer side does not.

Everything needed to fix it is already in the tree and already used elsewhere:
`asf.evidence.review.pick` returns the newest review of a slug among a list of repo paths, under
the product's own `review_pattern` and the legacy form alike (P8, P9); and `facts.repo_facts`
already holds the branch's whole tree listing, read with the one `ls-tree` it already runs (P10).
The card is the wiring between the two.

The fixer template already promises this in words — *"The binding list is the newest review on
`{branch}` — `{review_path}`"* (P11). This card makes the sentence true. No template changes.

### In

- **A tenth repo fact: the newest review the branch actually carries.** `facts.repo_facts` fills
  `newest_review` — `{'round': n, 'path': p}`, or `{}` when the branch's tree holds none — from the
  listing it already has (P10), through `asf.evidence.review.pick` (P8) so the product's own
  `review_pattern` and the legacy form both count and no path convention is written into the code
  (P14).
- **An answering kind reads that round.** `fixer` and `adjudicate` — `preamble.ANSWER_KINDS` — name
  the newest round the branch carries and its real path. The record's stage round stays as the
  fallback for a branch with no review on it, and for every caller that passes no `repo_facts` at
  all.
- **The fallback line agrees with it.** Because the same round reaches `facts.branch_review`, the
  `review round N (path): verdict V` stand-in in `last_report` (P16) names the same file the brief
  names, instead of round 1.
- **One rule, one place.** The choice lives in a single `preamble` function that both `collect`
  (for the brief) and `repo_facts` (for `wanted_paths` and the fallback reader) call — so the
  brief's text, the file whose size it counts, and the verdict line under it cannot disagree.

### Out

- **The write side.** `Review file to write:` and `next_round` are unchanged. A reviewer's round
  comes off the lane's occupancy and is already right (P6); deriving it from the branch instead
  would change which file a reviewer *creates*, which is a different decision from which file an
  adjudicator *reads*, and the card asks only for the second.
- **Every template.** Including `fixer.md`, which already says the right thing (P11). No file under
  `asf/briefs/templates/` is in this card's footprint, so no `CONSOLE → AMEND` is needed.
- **The `correct` brief kind.** It is not in `REVIEW_KINDS` and prints no `Review file` line at all;
  giving it one is new behaviour, not this defect.
- **`facts.branch_review`'s own path derivation.** It still builds candidate paths with
  `review_path_for`, so a review whose name is the *legacy* form yields no verdict fallback line.
  That is today's behaviour, it is a fallback for a run that left no REPORT, and widening it is a
  separate card.
- **`feeder_rows.review_round` and `REVIEW_RE`.** Teaching the record a code-review stage would
  move `stage_since` off a Task's state changes, which `asf/record/ingest.py:762-764` refuses on
  purpose (P3). The branch is the cheaper and more truthful source.

## The design

### 1. The fact — `asf/briefs/facts.py`

A finder over a listing the caller already holds, beside `branch_review`:

```python
def newest_review(product, tree_paths, slug):
    """``{'round': n, 'path': p}`` for the newest review of ``slug`` among ``tree_paths``, or
    ``{}`` for a tree that carries none.

    One contract — ``conventions.review_pattern``, with the legacy ``<prefix>-review-r<n>.md``
    form behind it (:func:`asf.evidence.review.pick`) — so the round a brief names is the round
    the harvest lane and the evidence pass read off the same file names. Runs no git: the caller
    already holds the listing (:func:`repo_facts`)."""
    hit = review_mod.pick(preamble.conventions(product), tree_paths or (), slug)
    return {'round': hit[0], 'path': hit[1]} if hit else {}
```

`repo_facts` gains one key in its opening literal and two lines where the tree is already read:

```python
     facts = {'head': '', 'branch_exists': False, 'files': {}, 'tests': [], 'last_report': '',
-             'outlines': {}, 'commits': {'total': 0, 'lines': []}, 'progress': '', 'relaunch': {}}
+             'outlines': {}, 'commits': {'total': 0, 'lines': []}, 'progress': '', 'relaunch': {},
+             'newest_review': {}}
     plain = preamble.collect(product, row, index, inflight)
     item_id = getattr(row, 'item_id', '') or ''
+    slug = (item_id or 'item').lower()
     ...
         if rev:
             tree = _git_text(repo, ['ls-tree', '-r', '--name-only', rev]).splitlines()
+            facts['newest_review'] = newest_review(product, tree, slug)
+            plain.update(preamble.answering_review(plain['kind'], plain['round'],
+                                                   plain['review_path'], facts['newest_review']))
             facts['tests'] = tests_under(tree, plain['writes'])
```

The update sits **before** `wanted_paths` (`:350`) and before the `facts.branch_review` call
(`:368`), so the size the brief counts and the round the verdict line walks down from are the same
round the brief prints. The existing `(item_id or 'item').lower()` at `:368` becomes `slug`.

The module docstring's *"the nine keys … always all nine"* (`:336`) becomes ten.

### 2. The rule — `asf/briefs/preamble.py`

```python
def answering_review(kind, round_, review_path, newest):
    """``{'round': n, 'review_path': p}`` — the review an answering kind reads.

    A reviewer writes the next round; a fixer and an adjudicator answer the one already on the
    branch, and **the branch is what says which one that is**. The record's round is derived from
    a Feature's ``<doc>-review rN`` stage, which a Task never carries, so it reads 1 however many
    rounds the branch holds (F-0152). ``newest`` — :func:`asf.briefs.facts.newest_review` — wins
    whenever it is non-empty; with no repository behind the brief, or a branch with no review on
    it, the arguments stand as they are."""
    if kind in ANSWER_KINDS and (newest or {}).get('round'):
        return {'round': newest['round'], 'review_path': newest['path']}
    return {'round': round_, 'review_path': review_path}
```

`collect` keeps its existing derivation as the fallback and passes it through the rule:

```python
     read_round = rnd or 1
     review_path = review_path_for(product, slug,
                                   read_round if kind in ANSWER_KINDS else rnd + 1 if rnd else 1)
+    answered = answering_review(kind, read_round, review_path,
+                                (repo_facts or {}).get('newest_review'))
     ...
-        'round': read_round,
+        'round': answered['round'],
         'next_round': rnd + 1 if rnd else 1,
-        'review_path': review_path,
+        'review_path': answered['review_path'],
```

`REPO_FACT_KEYS` gains `'newest_review'` — ten keys, and `ContractTests` holds both halves equal
(P12).

Nothing else moves: `state_lines` (`:562-565`) still prints
`Review file to answer: \`{review_path}\` (round {round})`, and `build.context` still passes
`review_path` and `round` to the templates unchanged.

### What it looks like when it is there

For the card's own case — a Task branch carrying rounds 1–5, its Feature at `plan-approved`:

```
Branch: `worker/T-0141` (exists: yes)
Head: 4f1c2ab record the fifth round
Spec: `docs/specs/f-0009.md` (312 lines)
Plan: `docs/plans/f-0009.md` (188 lines)
```

and, where the previous run left no REPORT, the line under it reads
`review round 5 (.sdd-input/reviews/5-t-0141.md): verdict APPROVED` rather than round 1's.

With no repository behind the brief — `asf brief` against a product with no clone, and every test
that passes `repo_facts=None` — the text is exactly what it is today.

### The card's own test, end to end

The card asks for exactly this: *a branch with review files for rounds 1–5 → the brief names round
5*. One test in `NewestReviewTests` builds the whole brief off a real repository rather than a
literal — `briefs.build(product, row, index, [], facts.repo_facts(product, row, index))` for an
adjudicate row on `fix/B-0001` with rounds 1–5 committed — and asserts the text carries
``(round 5)`` and does not carry ``1-t-0001.md``. That is the regression the defect would have to
get past.
