# F-0157 — the factory has no word for "there was nothing to commit, and that was right"

Twenty-four runs ended `failed: empty branch: nothing to land` over fourteen days — 12 a week against
a threshold of 5 — for $14.42 and 8.9 hours that landed nothing. The card reads that as sessions
dying. Most of them did not die: they did their job, their job did not produce a commit, and the
factory has exactly one verdict for a pushed branch with no commit on it.

`judge` writes that verdict for every kind but `groom` (P1, P2). Two kinds reach it by doing the
right thing:

- an **`adjudicate`** session that overrules a finding. Its brief forbids the commit that would save
  it — *overruled: one sentence on why*, and *you never commit a ruling* — because its deliverable is
  the `ruling:` line of its REPORT, which the tick files on the card (P3);
- a **`correct`** session sent back to answer a review finding that the lane's own restack already
  cleared under it. There is nothing left to change (P4, B-0149).

The cost is not the one wasted run. Three separate mechanisms in this factory were written
*specifically* to recognise a session that correctly committed nothing — `settled` (B-0128, no second
adjudicate over one hold), `overruling` (B-1377, whose second clause tests `commits: none` in so many
words), and `review_answered` (B-0149, "a `correct` run that answered the review hold without a
commit"). **All three gate on `finished(run)`, and `judge` can never return `finished` for such a
run** (P4). Every one of them is unreachable in production, and each one's failure re-opens the loop
it was written to close: the ruling never settles the hold, so the feeder raises another ADJUDICATE
row; the review is never answered, so the lane sends the same review file back. Each turn is another
empty end.

Underneath that, the brake is disconnected. `hold` parks an item at `EMPTY_CAP` empty ends, but only
for a correction of kind `EMPTY`, and the one production caller for an empty branch passes `UNPUSHED`
instead. Nothing in `asf/` passes `EMPTY` to `hold` (P5). So the documented "two empty ends and the
item parks" has never fired, and an item that keeps coming back empty walks the full round cap to
adjudication and then the loop cap — six runs and more where the design says two.

This card is three things, in that order: **a word for the outcome**, **the three readers taught to
read it**, and **the park wired to its switch**.

### In

- **`lifecycle.NOTHING_TO_LAND`** — a fourth thing an ended run can be, beside `finished`, `failed: …`
  and `dead`: the session's deliverable was never a commit, and it delivered it. Named in
  `OUTCOME_CLASSES`, excluded from `FAILING_CLASSES`, returned by `outcome_class`, given its own
  `Status` by `classify` and its own `State` by `derive`.
- **`lifecycle.delivered_off_branch(path, run, text)`** — pure over the ledger and the REPORT text;
  the reason an empty branch is not a failure, or `None`. The only place the judgement is made.
- **Health rewrites the verdict, in the chain where `landed_earlier` and F-0126's park already
  live** — one `elif`, before the empty-branch hold.
- **`lifecycle.delivered(run)`** — `finished(run) or end_reason == NOTHING_TO_LAND` — swapped into the
  three readers of P4, which is what makes each of them reachable for the first time.
- **Health passes `lifecycle.EMPTY`** where it passes `UNPUSHED` today, so `EMPTY_CAP` fires.
- **`EMPTY_CAP`'s comment stops naming a knob that does not exist** (P7).

### Out

- **No scorecard edit of any kind.** Not the cause keys, not `failure_class`, not the thresholds, not
  `DEAD_PREFIXES`. P8 is the whole mechanism: the reading falls because fewer runs end `failed: …`,
  and `failure:failed: empty branch` keeps meaning what it meant, so this card's own verification —
  the loop reading the same key over the two weeks after landing — still works. Regrouping the key
  would make the card unverifiable.
- **No new kind is forgiven.** `spec`, `plan`, `coder`, `fix-bug`, `review`, `reshape`, `close` keep
  `failed: empty branch` for an empty branch. A spec session that wrote no spec failed.
- **`NO_LANDING_KINDS` is not touched.** See the choices table: adding kinds there would drop the
  **push** check as well as the commit check.
- **F-0126's blocked park keeps winning.** A report carrying `NEEDS OPERATOR` is never read as a
  clean no-op, whatever else it says.
- **No prevention work.** Not launching a session that has nothing to do — the feeder's guard for a
  New Task the trunk already names (F-0095 §3.2) and `landed_earlier` for a squash-merged lane — is
  the other half of this problem and is already built. This card is about what the factory does with
  the sessions that get launched anyway.
- **No ledger rows are rewritten.** Runs already recorded `failed: empty branch` stay as they are;
  the card's before-window is read off them and must not move.
- **No `conventions.empty_cap` knob is built.** The comment is corrected instead.

### Choices

| Chosen | Against | Why |
| --- | --- | --- |
| A new `end_reason`, `nothing to land` | Returning `FINISHED` | B-0076 is the reason the empty verdict exists at all: a branch with no commits read `finished` sits `eligible` for ever and blocks every task waiting on the item's footprint. `finished` must keep meaning *pushed commits* (P11). |
| A new `end_reason` | Adding `adjudicate` and `correct` to `NO_LANDING_KINDS` | `lands()` false drops **both** gates in `judge`, not one: an upholding adjudicate session that commits the edit and fails to push it would then be read as a clean finish and its work lost silently. The new outcome is reached only *after* `ev.pushed` has passed (P1), so the push gate is untouched. |
| The judgement lives in `lifecycle.delivered_off_branch`, the ledger write in health | Putting the carve-out in `judge` | `judge` is pure over one run and its git evidence; deciding that a `correct` run's review finding is gone needs the item's other runs, which only the registry has. Health is already where an empty verdict gets rewritten on better evidence — `landed_earlier` at `:678`, the hook `retry` at `:681`. Same chain, same shape. |
| Two kinds, each with its own proof | Believing any report that says `commits: none` | Then a `spec` session that wrote nothing would pass. The proof is per kind: an `adjudicate` run must carry a `ruling:` paragraph; a `correct` run must be answering a review hold. |
| A `correct` run answering a review hold is believed | Requiring it to prove the finding is gone | It cannot cheaply, and it does not need to: the lane's answer to `review_answered` is *"answered without a commit — review it again"* (`asf/harvest/lane.py:1148`) — a **fresh review round**, not a pass. The reviewer still gates the code, so believing the session costs nothing and saves a round. A `correct` run answering any *other* hold (a red gate, a footprint) is **not** believed: there the hold is still true and nothing else would catch it. |
| Health passes `EMPTY` | Lowering `ROUND_CAP`, or a new cap | The park is written, documented and unit-tested already (`tests/test_lifecycle.py:1002-1008`); only its caller is wrong. One argument changes, and P6 shows nothing else moves. |
| Correct `EMPTY_CAP`'s comment | Building `conventions.empty_cap` | No operator has asked for the knob, `hold` already takes `empty_cap=` for tests, and a new product-config field is three shipped yamls and a fence. A comment that names a key nobody reads is the defect; the knob is not the fix. |
| `derive` maps it to `PUSHED` | Leaving it at `ENDED` | `ENDED`'s legal transitions include `LAUNCHED` — relaunched. The branch genuinely *is* pushed by the time this outcome is reachable (P1), and P12 shows nothing in `asf/` reads `derive`, so `PUSHED` is both the true statement and the safe one. |

## The design

### 1. A word for the outcome — `asf/workers/lifecycle.py`

Beside `FINISHED` (`:112`):

```python
#: A session whose deliverable was never a commit, and which delivered it: not a failure, and not
#: a landing. `finished` means "pushed commits"; this means "there was nothing to push, the session
#: said so, and what it did produce is somewhere the branch cannot show" — an adjudicate ruling on
#: the item's card, or a review finding the lane's own restack already cleared (F-0157).
NOTHING_TO_LAND = 'nothing to land'
```

Four vocabulary edits follow from it:

- `OUTCOME_CLASSES` (`:150`) gains `NOTHING_TO_LAND`;
- `FAILING_CLASSES` (`:153`) becomes every class that is neither `FINISHED` **nor** `NOTHING_TO_LAND`;
- `outcome_class` (`:1589`) returns it, as an early equality beside the `FINISHED` one at `:1596`;
- `SESSION_STATES` (`:162`) gains it, `classify` (`:1701`) returns
  `Status(NOTHING_TO_LAND, result=NOTHING_TO_LAND, source='ledger')` for it — placed beside the
  `FINISHED` arm at `:1706`, so it is decided before `is_dead_reason` and before the `FAILED`
  fall-through of P9 — and `Status.label` prints it verbatim through its existing `return self.name`.
- `derive` (`:1775`) returns `State(PUSHED, NOTHING_TO_LAND, rounds)` for it.

`judge` does **not** change. It still writes `failed: empty branch: nothing to land`, on the same two
conditions in the same order; the evidence that the verdict is wrong is not in `judge`'s reach.

### 2. The proof, and the rewrite — `lifecycle.py` and `asf/workers/health.py`

```python
def delivered_off_branch(path, run, text):
    """Why ``run``'s empty branch is not a failure — the deliverable it produced somewhere its
    branch cannot show — or None. Pure: the ledger and the REPORT text, no git and no clock.

    Two kinds have such a deliverable. An ``adjudicate`` run's is the ``ruling:`` paragraph of its
    REPORT, which :func:`asf.tick.step_health.file_rulings` files on the item's card; its brief
    forbids the commit that would leave a mark on the branch, because an overruled finding is not
    edited. A ``correct`` run answering a **review** hold has none to produce when the lane's own
    restack already cleared the finding under it (B-0149): there is nothing to change, and the
    lane's answer is a fresh review round, not a pass.

    Either way the run must say so itself, in its own REPORT: ``status: done``, ``commits:`` claiming
    nothing (:func:`asf.workers.report._claim`), and no ``NEEDS OPERATOR`` — a question is F-0126's
    blocked park, which keeps winning over this."""
```

The shape, in order: parse the REPORT; return `None` unless `status` is `done`, `commits` claims
nothing and `report.needs_input(text)` is falsy; then dispatch on `run['kind']` —

- `'adjudicate'` → `f'ruling filed: {ruling[:60]}…'` when `report.ruling(text)` is non-empty, else
  `None` (a ruling session with no ruling did fail, and `file_rulings` already marks it
  `adjudicated: none`);
- `'correct'` → `f'{review_path}: the finding is gone'` when the item's latest correction of kind
  `REVIEW` names a review path — found exactly as `review_answered` finds it today
  (`:2106-2112`: the item's `REVIEW` corrections, the one with the newest `at`, its `text` up to the
  first space) — else `None`;
- anything else → `None`.

In health's chain (`asf/workers/health.py:672-713`), one `elif` immediately **before** the final
empty-branch hold at `:708`, and after both `landed_earlier` (`:678` — a landed lane is a landing,
not a no-op) and the `question` park (`:683` — F-0126 keeps winning, belt and braces to the
`needs_input` clause above):

```python
elif reason == f'failed: {lifecycle.EMPTY_BRANCH}' and lifecycle.delivered_off_branch(
        registry, s, str((ev.result or {}).get('result') or '')):
    why = lifecycle.delivered_off_branch(registry, s, str((ev.result or {}).get('result') or ''))
    pool_mod.update_session(product, job, end_reason=lifecycle.NOTHING_TO_LAND)
    s.update(end_reason=lifecycle.NOTHING_TO_LAND)
    found.append((job, 're-judged', f'{lifecycle.NOTHING_TO_LAND} — {why}'))
```

No hold is raised, no round is spent, no correction is written and no next session is asked for —
P10 is what makes that true by omission rather than by a new branch. The `('ended', reason)` row
health already appended at `:660` keeps the original verdict, and this adds the `re-judged` row
beside it, which is how the `dead pid` revisit at `:638` already reads.

### 3. The three readers, and the park

```python
def delivered(run):
    """Ended with its work delivered: :func:`finished` — pushed commits — or
    :data:`NOTHING_TO_LAND`, a deliverable the branch cannot show (F-0157). What a reader asking
    "did this session do its job" wants; :func:`finished` alone means "and it is on the branch"."""
    return finished(run) or (bool(run) and bool(run.get('ended'))
                             and run.get('end_reason') == NOTHING_TO_LAND)
```

Swapped in at three call sites, and nowhere else — every other `finished(...)` reader is asking about
the branch and keeps asking:

| Site | Reader | What becomes reachable |
| --- | --- | --- |
| `lifecycle.py:614` | `_settling_run`, hence `settled` | The feeder's B-0128 arm at `asf/feeder/rows.py:724`: a hold an adjudicate session has already ruled on raises no second adjudicate row. |
| `lifecycle.py:670` | `overruling` | The lane's B-1377 arm at `asf/harvest/lane.py:1371` — and specifically `overruling`'s `commits: none` clause at `:685-687`, which is written for a run that committed nothing and can never be reached while such a run is never `finished`. |
| `lifecycle.py:2116` | `review_answered` | The lane's B-0149 arm at `asf/harvest/lane.py:1148`: *answered without a commit — review it again*, a fresh review round instead of another correction. |

And the park, at `asf/workers/health.py:712` — one argument:

```python
fields, line = lifecycle.hold(registry, s, lifecycle.EMPTY, lifecycle.empty_branch_text(), now)
```

By P6 that changes nothing but the one thing it is for: the item's second genuine empty end parks it
(`empty_ends(path, item) >= EMPTY_CAP`, with the just-written `end_reason` counted, since health
writes it at `:658` before calling `hold`) rather than spending a third, fourth and fifth session on
its way to the round cap. `EMPTY_CAP`'s comment loses `(conventions.empty_cap)` and names `hold`'s
`empty_cap=` parameter instead (P7).

## Records

- **The run ledger** — the one durable change. A run that delivered off its branch carries
  `end_reason: nothing to land` in place of `end_reason: failed: empty branch: nothing to land`. No
  new field: the existing `end_reason` takes a fourth value, and by P8 that single string is what
  drops the run out of the scorecard's `by_failure`, out of `is_dead`, and out of this card's
  reading.
- **No new correction row.** Where health writes `correction: {kind: unpushed, …}` today for such a
  run, it now writes none at all. The rounds counter on the item does not climb, and the feeder
  raises no FIX → CORRECT row from it.
- **The park row, for the first time.** An item at its second genuine empty end gets
  `correction: {kind: 'empty', text: <empty_branch_text()>, parked: True, reason: <park_text(n)>}`
  and `operator_flagged: 1` — the shape `hold` already writes for every other park, and the one an
  operator clears with `asf unpark <item>`.
- **Health's printed pass** gains one line per rewritten run —
  `<job> re-judged: nothing to land — ruling filed: …` / `— <review path>: the finding is gone` —
  beside the `ended` line it already prints, so the tick's own output says why a run that landed
  nothing was not sent back.
- **The card** — unchanged by this work. `file_rulings` already writes the adjudicate `## History`
  line whatever the run's verdict (P3); this card makes the ledger agree with what the card was
  already told.
- **Nothing is backfilled.** Ledger rows written before this lands keep `failed: empty branch`, which
