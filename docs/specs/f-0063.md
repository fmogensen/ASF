# F-0063 — the branch is the handover; the brief has to say so

A session that crashes, is killed on a cap, or goes silent past its heartbeat leaves its work
where the factory put it: on its own lane branch, pushed. Nothing is lost. What is lost is the
*knowledge* that it is there. The relaunch builds the same brief the first launch got — the card,
the spec path, the standing rules — and hands it to a fresh conversation that has never seen the
branch. So the new session opens the spec it already wrote half of, re-reads the plan, re-derives
the footprint, and often re-cuts the work its own predecessor pushed forty minutes ago. That is
the cold-restart cost, and it is paid per relaunch, every time.

The machinery to remove it is already here, and half-wired. `asf/briefs/preamble.py` prints a
`Head:` line and a `### The last report for this item` section. `asf/briefs/facts.py` exists for
exactly one purpose — to run the git and the ledger reads the preamble is forbidden to make — and
its docstring says it serves "the tick's launch path and for `asf brief` alike, so what an
operator previews is what a session is handed."

It does not. The tick's launch path never calls it. `asf/tick/step_wave.py:431` defines a second,
older `repo_facts(product, branch)` returning `{branch, pushed, remote_sha, last_commit}` — four
keys, none of which is one of the six the preamble reads (`asf/briefs/preamble.py:234`) — and
passes *that* to `briefs.build` at both launch sites (`:624`, `:727`). Every brief the factory has
launched therefore prints `Head: (not known here)`, `exists: (not known here)`, no file sizes, no
"Where to look", and no last report. The brief this very spec was written from prints exactly
that. `asf brief`, which does call the right filler (`asf/briefs/build.py:537`), shows the
operator a brief no session has ever received.

So this Feature is one wiring fix and four facts. The fix makes the head and the last report
arrive at all. The facts are the two the card names that nothing computes yet — the commit list
between the trunk and the branch head, and the last progress line the dead run printed — plus the
report scoped to the branch that actually holds the work, plus the paragraph that tells the
session what to do with all four: continue from that head, do not re-cut, do not redo what the
subjects show done, and push within fifteen minutes so the next relaunch starts from *your* work.

## 1. Decisions

### 1.1 In

- **The launch path uses the one filler** (§2.1). `asf/tick/step_wave.py`'s local `repo_facts` is
  deleted and both launch sites call `asf.briefs.facts.repo_facts(product, row, items, running)`.
  Nothing else reads its `remote_sha`/`last_commit` keys (verified: P2). This is the whole of the
  card's first item — the branch head — and it is a deletion plus an import.
- **The head is the sha origin holds** (§2.2). `head_of` already pays one `git ls-remote` to learn
  whether the branch is on origin; it throws away the sha that call returns and reads the local
  `refs/remotes/origin/<branch>`, which the wave's process has not fetched this tick. It keeps the
  sha instead, and when the clone does not hold that object yet, says so rather than naming a
  stale commit as the head.
- **C2, the commit list** (§2.2). `facts.commits_on(repo, branch, main)` — one
  `git log --format='%h %s' origin/<main>..<head>`, newest first, capped at
  `COMMIT_LIMIT = 10` with a count of what was cut. `{'total': n, 'lines': [...]}` on the facts
  dict under a new `commits` key. Empty for an unpushed branch, for a branch level with the trunk,
  and for a head the clone does not hold.
- **C4, the last progress line** (§2.3). `facts.last_progress(run)` — the last text an assistant
  turn printed in the predecessor run's log, first non-empty line, whitespace squeezed, capped at
  the existing `FIELD_CAP`. Read from the **tail** of the log (the last `PROGRESS_TAIL_BYTES`,
  256 KiB), because a spent session's log is hundreds of megabytes and no brief may read one whole.
  New `progress` key.
- **C3, the last report on the branch** (§2.4). `last_report` is scoped to the runs on *this
  branch* (it reads every run of the item today, on any branch), and when the newest ended run on
  the branch left no typed REPORT — the ordinary shape of a crash — it falls back to the verdict
  line of the newest review file the branch carries. Both halves are "the last writer or review
  report on the branch", which is what the card asks for.
- **The predecessor, and what makes a brief a relaunch** (§2.5). `facts.predecessor` — the newest
  **ended** run of this item, on this branch, of this kind, that did not land. Its existence is
  the switch: a brief with one is a relaunch brief and carries the block; a brief with none is a
  first launch and is byte-identical to today's. `relaunch` is the third new key
  (`{'job', 'ended', 'end_reason', 'attempt'}` or `{}`).
- **The instruction** (§2.5). One `### The branch already holds your work` section in the
  preamble, right after the state block: the commit list, the progress line, and the paragraph —
  continue from the head, never re-cut the branch, never redo what those subjects did, push within
  fifteen minutes. It names the rebase: the worktree is rebased onto the trunk before the session
  starts, so the shas in the brief are origin's and the subjects are what carry over (P10, P11).
- **On a relaunch the last report is not trimmable** (§2.5). `### The last report for this item`
  is in `TRIM_ORDER` today and is the first casualty of a long card. A relaunch brief that loses
  it carries three of four items, so on a relaunch the section keeps its lines.
- **The measure** (§2.6). `improve.measure.Run` gains `attempt` — the run's 1-based index among
  its job's runs, which `ended_runs` is already iterating — and `measure.table` gains a
  `relaunches` block (sessions, hours, usd, and usd/hours per session, split first launch vs
  relaunch). The daily scorecard's Waste table gains one `relaunch` row beside `landing`. Two
  windows of that one row are the card's third acceptance.
- **Acceptance 2 is asserted, not built** (§3, T6). A relaunch's worktree is already created at
  `origin/<branch>` and rebased onto the trunk (P10), and the launch line already records
  `launch_head` (P9). The card's "first commit sits on top of the old head" therefore holds today
  and has no test. It gets one.

### 1.2 Out

- **Nothing about the live half.** A session that is still alive gets its findings on its own
  conversation through `asf.workers.continuation` (F-0039), and a relaunch is by definition what
  happens when that refused (P8). This Feature adds no kind to `ANSWERING`, removes none from
  `NEVER`, and does not touch `continuation.prompt`. The same-session correction the card names as
  this one's pair is a separate Feature, in flight as a spec; neither waits on the other.
- **No fetch is added.** `asf/briefs/facts.py`'s first rule is that a launch never waits on a
  `git fetch` — one `ls-remote` per call and local refs for the rest. The commit list is computed
  from what the clone holds and is empty when it holds nothing; it is never made correct at the
  cost of a network round trip per launch.
- **A non-relaunch brief gets no commit list.** A reviewer reading the coder's branch would also
  be cheaper with the subjects in hand, and a first launch of a `fixer` likewise. Both are real,
  and both are a different card: the block here is gated on a predecessor of the same kind so that
  the instruction it carries ("do not redo what these commits did") is never told to a session
  whose work those commits are not.
- **No new golden brief file.** `tests/test_briefs.py` holds the golden set equal to the kind set
  (P15), and a relaunch is not a kind. The whole rendered block is asserted as one string in a
  unit test instead — the same coverage, inside the existing contract.
- **No new ledger field, and no new metrics stream.** `launch_head` is already on every launch
  line and the run order is already in the fold; the relaunch classification is derived, not
  stored. The `sessions` metrics stream and its schema are untouched.
- **Nothing is refused.** A relaunch whose worktree is somehow not at the old head is not blocked
  at launch. The catch-up path already handles it (P10); a second gate over it would be a new way
  to park an item.
- **The fifteen minutes is an instruction, not a timer.** No code measures it, nothing holds a
  session that misses it. The number is in the brief because the loss it bounds is real; enforcing
  it is a heartbeat question and belongs to whatever card owns the heartbeat.

## 2. The design

### 2.1 `asf/tick/step_wave.py` — one filler for the brief's facts

`repo_facts(product, branch)` (`:431-441`) and its `_git` helper (`:426-428`, no other caller) go.
Both launch sites change from

```python
brief = _build(product, row, items, running, repo_facts=repo_facts(product, row.branch))
```

to the filler the contract test covers, reached the same late-import way `_build` and `_wave`
already are, so the step keeps its import shape:

```python
def _repo_facts(*a, **kw):
    from asf.briefs import facts
    return facts.repo_facts(*a, **kw)
...
brief = _build(product, row, items, running,
               repo_facts=_repo_facts(product, row, items, running))
```

Cost per launch: the `ls-remote` the old path also made, plus one `log`, one `ls-tree`, one
`cat-file --batch` and one `cat-file -p` per literal `writes:` path — the exact set `asf brief`
makes today, and no fetch. `tests/test_tick_steps.py:683` moves onto the new call.

After this change the brief carries `Head:`, `exists:`, the document sizes, the named tests,
"Where to look" and the last report — the card's first item and five facts that were already
written and never delivered.

### 2.2 `asf/briefs/facts.py` — the head origin holds, and the commits to it

`head_of` keeps its signature and its contract (`(head, branch_exists, rev)`, every step may fail
into nothing) and changes what `rev` is for a pushed branch: the sha `ls-remote` printed, verified
present with `cat-file -e`.

```python
def head_of(repo, branch, main):
    ...
    ls = _git_text(repo, ['ls-remote', '--heads', 'origin', branch]) if branch else ''
    sha = ls.split()[0] if ls else ''
    exists = bool(sha)
    rev = sha if sha and _git(repo, ['cat-file', '-e', f'{sha}^{{commit}}']) is not None else ''
    if sha and not rev:
        # origin has moved and this clone has not fetched it: never pass the older ref off as
        # the head — the commit list would then read as the whole of what was done
        return f'{sha[:9]} (origin/{branch} — not in this clone yet)', True, ''
    ...
```

The trunk fallback for an unpushed branch, and its `(… — <branch> is not on origin yet)`
parenthetical, are unchanged.

New beside it:

```python
#: The most commits the brief lists between the trunk and the branch head; over it the block
#: prints the count and names the `git log` that has the rest.
COMMIT_LIMIT = 10


def commits_on(repo, rev, main, limit=COMMIT_LIMIT):
    """``{'total': n, 'lines': ['<short sha> <subject>', ...]}`` for ``origin/<main>..<rev>``,
    newest first, ``lines`` cut to ``limit``. ``{'total': 0, 'lines': []}`` for a rev the clone
    does not hold, a branch level with the trunk, and every failure — one ``git log``, no fetch."""
```

`repo_facts` fills `commits` from it whenever `rev` is the branch's own head, and leaves it empty
when `rev` fell back to the trunk (there is no branch, so there is nothing above the trunk).

### 2.3 `asf/briefs/facts.py` — the last progress line

```python
#: How much of a run's log the progress line is read from. A spent session's log is the largest
#: file this factory writes; the last assistant turn is at the end of it either way.
PROGRESS_TAIL_BYTES = 256 * 1024


def last_progress(log, tail=PROGRESS_TAIL_BYTES):
    """The last line an assistant turn printed in ``log``, squeezed and capped — what the run was
    doing when it stopped. Reads the last ``tail`` bytes only, drops the first partial line, and
    scans the parsed records backwards for a ``text`` block. ``''`` for no log, no readable
    record, and every failure."""
```

A record is read as a turn when `rec['type'] == 'assistant'` and its `message.content` holds a
`{'type': 'text', 'text': …}` block (P12); the value taken is that text's first non-empty line,
`' '.join(split())`, through the existing `_cap`-style truncation at `FIELD_CAP`. A `result` line
is not a progress line: the REPORT it carries is C3's job, and §2.4 reads it with the parser that
owns it.

### 2.4 `asf/briefs/facts.py` — the last report *on the branch*

`last_report(product, item_id)` becomes `last_report(product, item_id, branch='', review=None)`:

- the runs considered are those with `run.get('branch') == branch` when a branch is given (every
  run of the item, as today, when it is not — `asf brief --kind` over a row with no branch keeps
  working);
- the newest `ended` one still gives the `<job> ended <ts> — <end_reason>` line and the five
  capped fields;
- when `report.parse` finds none of those fields — a crash, a cap, a kill — one further line is
  appended from `review`, the newest review file the branch carries:
  `review round <n> (<path>): verdict <v>`, the verdict read with
  `asf.evidence.review`'s own parser, never a second one.

The review file is found the way the preamble already names it — `conventions.review_path(slug, n)`
for the rounds at or below the item's own round — and read with `git cat-file -p <rev>:<path>`, one
call for the highest round the tree holds. A branch with no review file adds no line.

### 2.5 `asf/briefs/preamble.py` — the block, and what it says

`REPO_FACT_KEYS` becomes nine — the six it holds plus `commits`, `progress` and `relaunch`. `collect` carries each through unchanged, plus

```python
'commits': dict((repo_facts or {}).get('commits') or {}),
'progress': (repo_facts or {}).get('progress') or '',
'relaunch': dict((repo_facts or {}).get('relaunch') or {}),
```

`facts.repo_facts` fills `relaunch` from

```python
def predecessor(product, item_id, branch, kind):
    """The run this launch is a relaunch of: the newest **ended**, unlanded run of ``item_id`` on
    ``branch`` whose ``kind`` is this row's, or ``{}``. The tuple `same_head_loop` classifies a
    relaunch by (`asf/workers/lifecycle.py:1900`), read through `lifecycle.item_runs`."""
```

and `progress` from that run's `log`, so a first launch pays neither read.

The new section, between `state` and `conventions`, present only when `facts['relaunch']`:

```
### The branch already holds your work

This item has run before: spec-f-0063 ended 2026-09-27T14:02:11Z — stopped (attempt 2).
Its work is on `spec/F-0063` and is yours to continue. 4 commits above origin/main, newest first:
- 9f1c4ab spec(F-0063): the decisions and the preconditions
- 3ac0e21 spec(F-0063): the design, §2.1 and §2.2
- …
(2 more — `git log --oneline origin/main..origin/spec/F-0063`)
Where it stopped: writing §2.3 — the tail read for the progress line
Your worktree was rebased onto origin/main before you started, so its shas are not the ones
above; the subjects are. Continue from that head: never recut the branch, never open another,
never redo what those subjects already did — read them first and pick up after the last one.
Commit and push within fifteen minutes, then keep pushing: what is not on origin is what the
next relaunch loses.
```

`Where it stopped:` is dropped when the progress line is empty. When `commits['total']` is 0 the
commit list and the rebase line are replaced by one line — `Nothing was pushed: the previous run
left no commit on the branch, so there is nothing to continue from — start the work, and commit
and push within fifteen minutes so this does not repeat.` — and the "never redo" clause goes with
it (D15).

Two edits carry the rest:

- `Section('last_report', …, trimmable=not facts['relaunch'])` — D10. `TRIM_ORDER` itself is
  unchanged; `fit` already skips a section it cannot find in the list, and a non-trimmable one is
  simply never cut.
- the new section is not trimmable and is bounded by construction: one lead line, at most
  `COMMIT_LIMIT + 1` list lines, one progress line, four lines of instruction.

### 2.6 The measure — relaunch cost per session, on the page that already exists

`asf/improve/measure.py`:

```python
@dataclasses.dataclass(frozen=True)
class Run:
    ...
    attempt: int = 1        # 1-based, among this job's ended runs in ledger order
```

filled in `ended_runs` by the `enumerate` of the loop it already runs (`:118`), and read by
`table`:

```python
'relaunches': {
    'sessions': n, 'share': share(n, len(runs)),
    'usd_per_session': …, 'hours_per_session': …,          # attempt >= 2
    'first_usd_per_session': …, 'first_hours_per_session': …,   # attempt == 1
},
```

`asf/metrics/metrics.py`: `render_daily` passes the block through beside `landing`, and
`scorecard_rows` renders one row after it —

```
| relaunch | 7 of 31 sessions were relaunches | $2.10 per relaunch vs $3.40 per first launch (7 days) |
```

## 3. Acceptance tests

All from the root of this repository, stdlib only, hermetic — every test builds its own git
fixture and points `ASF_HOME` at a tmpdir, as `tests/test_brief_facts.py:77-93` already does. No
network, no `gh`. The whole suite stays green:

```bash
cd "$(git rev-parse --show-toplevel)"
python3 tools/run_tests.py
```

**T1 — the launch path hands over the facts it has.** The wave, run over the fixture product with
a real repo and a pushed branch, builds its brief with a `repo_facts` whose keys are exactly
`preamble.REPO_FACT_KEYS`; the brief's text carries a `Head:` line naming the branch's own sha and
an `exists: yes`; `step_wave` has no `repo_facts` attribute left; and `asf brief` over the same row
produces the same text the wave produced. The card's first item, and P2's defect, as one test.

```bash
python3 -m unittest -v tests.test_tick_steps.WaveFactsTests tests.test_brief_facts.ContractTests
```

**T2 — the head, and the commits above the trunk.** `head_of` on a pushed branch returns the sha
`ls-remote` gave, not the local ref, and still reports the trunk with its parenthetical for an
unpushed one; a head whose object the clone lacks reads `not in this clone yet` and yields an empty
commit list. `commits_on` over a branch with three commits returns three lines, newest first, each
`<short sha> <subject>`; over a branch level with the trunk, none; over twelve commits with
`limit=10`, ten lines and `total: 12`; over a rev that does not resolve, empty and no raise.

```bash
python3 -m unittest -v tests.test_brief_facts.HeadTests tests.test_brief_facts.CommitListTests
```

**T3 — the last progress line.** `last_progress` over a log whose last assistant turn printed two

ellipsis; a log larger than `PROGRESS_TAIL_BYTES` whose last turn is inside the tail is found, and
the function reads no more than the tail (asserted on the byte count it seeks); a missing log, an

```bash
python3 -m unittest -v tests.test_brief_facts.ProgressLineTests
```

**T4 — the last report is the one on the branch, and the predecessor is the run whose work it is.**
`last_report` with a branch given ignores an ended run of the same item on another branch and takes
the newest on this one; a run that left no REPORT falls back to the branch's newest review file's
verdict line, naming its round and path; a branch with neither adds nothing. `predecessor` returns
the newest ended, unlanded run of this item, branch and kind, and `{}` for: a live run, a landed
one, a run of another kind on the same branch (the reviewer's case), a run of the same kind on

## 4. Records

**Files, in this repository** — the footprint of §2.7 and nothing else. No template, no golden, no
fixture record card.

**Rows, per product** — none new. The relaunch is derived from rows the ledger already carries:
`<state>/<product>/sessions.jsonl`'s launch lines (`job`, `item`, `kind`, `branch`, `started`,
`log`, `launch_head`) and the `ended`/`end_reason`/`harvested` fields that fold onto them. No
field is added, no schema changes, and `metrics.STREAMS` is untouched.

**What the brief now writes down** (the record a session reads, `<state>/<product>/briefs/<job>.md`):

- `Head:` — the sha `origin/<branch>` holds, or the trunk's with its parenthetical, or
  `not in this clone yet`.
- `### The branch already holds your work` — the predecessor's job, end stamp, end reason and
  attempt number; the commit list with its cut count; `Where it stopped:`; the instruction.
- `### The last report for this item` — scoped to the branch, with the review verdict line when the
  run left no REPORT, and not trimmable on a relaunch.

**Events the console sees**

- the daily scorecard (`metrics/daily/<day>.md`) gains one `relaunch` row in its Waste table.
- `asf brief` is unchanged in behaviour and is now, for the first time, what a session is handed.
