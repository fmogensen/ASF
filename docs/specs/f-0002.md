# F-0002 — P0b — the card-evaluation pass for multi-product wording

Parent: E-0001 — ASF 0.1 — a working factory. Stage: card → spec.

The card, as the requirement: *read every card of the first product's factory Epic against the
multi-product isolation table and re-word the ones that assume one product, one repository, one CI
provider, one runner pool or one path, naming the config key the behaviour would read instead. A
card that cannot be made product-agnostic stays where it is. The output is the re-worded cards plus
one note per card in the groom.*

This is a pass over **record content**, not over code. It changes cards in the ASF record (the
directory the `asf` product's `backlog_dir` names) and adds one notes file there. It changes
nothing under `asf/`, `tools/`, `plugin/` or `tests/` in this repository.

## 1. Decisions

### In

- Every item in the ASF record whose `## History` carries the line
  `migrated from the first product's backlog` — the factory Epic's cards as they arrived here. On
  2026-09-21 that is **42 items**: 37 Features and 5 Bugs (listed in §2.1).
- For each of them: a verdict, a re-word where the verdict is `reworded`, one History line on the
  card, and one note line in the notes file.
- The config key each re-worded behaviour reads, written by its dotted path, and a list of every
  key the pass names that does not exist yet.

### Out

- The phase cards F-0001–F-0021 and the prior-art cards F-0022–F-0033: written for ASF from the
  start, never cards of the first product's Epic.
- The first product's own record. Cards that stayed behind there at migration belong to that
  product; under the isolation table a job launched for `asf` reads and writes only `asf`'s record.
- Any code change: new keys named by the pass are not added to `asf/env.py`,
  `asf/conventions.py` or the example yamls here. They go to the notes file's `## New keys`
  section for F-0004 (P0d), F-0059 and F-0007 (P1) to pick up.
- Stories and Tasks under the evaluated cards (there are none today). Decomposing the cards is
  not part of this pass.
- Changing `asf groom` so it carries this pass's notes. See D5.

## 2. The design

### 2.1 The evaluated set

Selector: an item file under `features/` or `bugs/` of the record whose text contains
`migrated from the first product's backlog`. On 2026-09-21:

```
F-0034 F-0035 F-0036 F-0037 F-0038 F-0039 F-0040 F-0041 F-0042 F-0043
F-0044 F-0045 F-0046 F-0047 F-0048 F-0049 F-0050 F-0051 F-0052 F-0053
F-0054 F-0055 F-0056 F-0057 F-0058 F-0059 F-0060 F-0061 F-0062 F-0063
F-0064 F-0065 F-0066 F-0067 F-0068 F-0069 F-0070
B-0008 B-0009 B-0010 B-0011 B-0012
```

The pass works from the selector, not from this list. If the selector yields a different set on
the day, the pass evaluates what it yields and the note file's header records the count. Test T1
pins the list, so any difference is visible.

### 2.2 The rubric — the multi-product isolation table

One rule: **everything that is data belongs to exactly one product; everything that is code belongs
to ASF.**

| Thing | Scope | Where | How it stays separate |
| --- | --- | --- | --- |
| Items (E/F/S/T/B/D), id space, `index.json` | per product | the product's record (`product:backlog_dir`) | ids are unique within a record; a cross-product reference is `<product>:F-0019`, never a bare id |
| Metrics streams, scorecards, releases, groom | per product | the record's `metrics/`, `groom/`, `releases/` | every event line carries `product:`; a stream file never mixes products |
| Rules | core (ASF) + per product | ASF `rules/` + the record's `rules/` | `asf rules check` runs core ∪ product; a product rule can add, never override |
| Decisions | ASF ADRs + per product | ASF `docs/decisions/` + the record | same |
| Conventions, CI, deploy-sha, runner labels, size classes, stage limits | per product | `~/.ASF/products/<name>.yaml` | no convention lives in code |
| In-flight sessions, id ranges, caches, worktrees | per product | `~/.ASF/state/<product>/` | a job is launched *for* a product; its worktree, range and record say which |
| Worker pool, quota guards, scheduler | shared (operator) | `~/.ASF/config.yaml` | one pool; each launch is tagged with its product, so cost per product is a sum and a product can be given a share |
| The tick | one loop, per product | `asf tick [--product X]` | each iteration reads and writes only that product's state; one product's failure never stops the next |
| Operator views | cross-product | `asf status`, the scorecard's first line, `/asf:*` with `--product` or `all` | read-only joins over per-product data; nothing written |

### 2.3 The five assumptions, and the keys they map to

The card lists five single-valued assumptions. For each one, the questions the reader asks and
the keys that exist today. A key not in this table may be named, but it carries `(new key)`.

| Assumption | The card says or implies… | Re-word to read | Existing keys |
| --- | --- | --- | --- |
| one product | "the product", a product name, one record, one metrics stream, one scorecard number | per product, with a cross-product total only in an operator view | `product:product`, `product:backlog_dir`, `state:` (per product) |
| one repository | "the repo", `--repo`, one slug, a fixed checkout | the product's repo, from its config | `product:repo_slug`, `product:repo_dir`, `product:main`, `product:conventions.branch_prefixes`, `product:conventions.specs_dir`, `…plans_dir`, `…reviews_dir`, `…review_pattern` |
| one CI provider | GitHub Actions by name, one workflow file, one budget | the product's CI provider and workflow | `product:ci.provider`, `product:ci.workflow`, `product:ci.budgets.minutes_per_day`, `product:deploy_sha.provider`, `product:deploy_sha.workflow` |
| one runner pool | "the runners", self-hosted boxes, one runner org, one worker account set | CI runners per product; worker accounts shared, with a share per product | `product:ci.runner_org`, `product:ci.labels`, `config:worker_pool.accounts`, `config:worker_pool.quota_guard.max_5h`, `…max_7d` |
| one path | a literal directory, `~/…`, `/tmp/…`, a fixed file name | the config key, or a per-product state path | `config:paths.home`, `config:paths.state_dir`, `config:paths.log_dir`, `product:conventions.*` (every field of `asf/conventions.py`), `product:customer_paths`, `product:size_classes`, `product:stage_limits`, `product:approvals`, `product:app_host` |

Worked examples, from cards as they stand today:

- **F-0038** says "the per-product path list lives in the product's configuration" but names no
  key. Verdict `reworded`. Name `product:ci.factory_only_paths (new key)`. Name the classifier's
  mirror as the product's `product:ci.workflow`, not "the CI workflow".
- **F-0042** says "which providers a product needs comes from its configuration". Verdict
  `reworded`. Name `product:credentials (new key)` for the per-product provider list. The probe
  set is shared across products, so the note says the probes are code and the list is data.
- **F-0041** already says "one open train branch per lane, per product" and "thresholds live in
  the product's configuration". Verdict `reworded`: add `product:size_classes` (exists) and
  `product:conventions.branch_prefixes.batch`.

### 2.4 What a re-worded card looks like

Only the wording that assumes one of the five changes. Intent, acceptance meaning and scope stay.
Every named key appears in the card's own body in backticks, so a reader of the card alone finds
it. One History line is appended:

```
- 2026-09-22 F-0002: reworded — reads `product:ci.provider`, `product:ci.workflow`
- 2026-09-22 F-0002: clean — reads only the record and the tick's rows
```

A `product-bound` card gets no History line. D3 leaves it byte-for-byte untouched, and its only
trace is its note line.

### 2.5 The notes file — `groom/f-0002-card-evaluation.md` in the record

```
# Card evaluation — F-0002

base: <the record's HEAD sha before the pass>
evaluated: <n> items (selector: "migrated from the first product's backlog")
rubric: docs/specs/f-0002.md §2.2 in the ASF repository

## Notes

- F-0034 Harvest by code … — reworded — `product:repo_dir`, `product:main` — "a product repository" → the product's `repo_dir`; harvest takes `--product`, not `--repo`
- F-0035 Thin controller … — clean — the read loops are the tick's; nothing single-valued
- F-00NN <title> — product-bound — binds to <what> → answer: ____

## New keys

- `product:ci.factory_only_paths` — F-0038 — path globs a factory-only push may touch
```

Grammar, which the tests parse:

- a note line is `- <ID> <title> — <verdict> — <rest>`, where `<verdict>` is one of `reworded`,
  `clean`, `product-bound`;
- for `reworded`, `<rest>` begins with one or more backticked keys, comma-separated;
- for `product-bound`, the line ends in `→ answer: ____`;
- a `## New keys` line is `` - `<key>` — <ID>[, <ID>…] — <what it holds> ``, and every key a
  note marks `(new key)` appears there exactly once.

### 2.6 The run

1. Record `base:` (the record's HEAD). Run the selector.
2. For each item, in id order: read it against §2.2 and §2.3, choose a verdict, edit it (D7), append
   its History line, write its note line. Print one progress line per item: `F-0002: <ID> <verdict>`.
3. Write `## New keys`.
4. Run `asf index` and `asf check` from the record. Both must exit 0.
5. Append to F-0002's own History: `- <date> F-0002: pass run — <r> reworded, <c> clean, <p> product-bound; notes in groom/f-0002-card-evaluation.md`.
6. Commit in the record (`git commit -s`) and push the job's branch. For every `product-bound`
   item, print `NEEDS OPERATOR: <ID> is product-bound — answer its line in groom/f-0002-card-evaluation.md (move to the first product's record | close | keep)`.

## 3. Acceptance tests

All blocks run from the root of this repository on the operator's machine (P5). Each block
resolves the record itself, exits non-zero on failure and prints `ok` on success. Set
`ASF_PRODUCT` if the ASF product's config file is not named `asf.yaml`.

**T2 — one note per card, each with a verdict, and the header is complete.**

```bash
python3 - <<'EOF'
import os, re, sys
from asf import env
rec = env.load_product(os.environ.get('ASF_PRODUCT', 'asf')).backlog_dir
text = open(os.path.join(rec, 'groom', 'f-0002-card-evaluation.md')).read()
assert re.search(r'^base: [0-9a-f]{7,40}$', text, re.M), 'no base: sha'
notes = re.findall(r'^- ([FB]-\d{4}) .+? — (reworded|clean|product-bound) — (.*)$', text, re.M)

want = {f'F-{n:04d}' for n in range(34, 71)} | {f'B-{n:04d}' for n in range(8, 13)}
if len(ids) != len(set(ids)): sys.exit('an item has more than one note')
if set(ids) != want: sys.exit(f'notes differ: missing {sorted(want - set(ids))}, extra {sorted(set(ids) - want)}')

assert m and int(m.group(1)) == len(want), 'evaluated: count wrong'
for iid, verdict, rest in notes:
    if verdict == 'reworded' and not re.match(r'`[a-z]+:[^`]+`', rest): sys.exit(f'{iid}: reworded note names no key')
```

**T3 — every named key is real or declared new, and a re-worded card carries its keys.**

```bash
python3 - <<'EOF'
import os, re, sys, dataclasses
from asf import env, conventions
rec = env.load_product(os.environ.get('ASF_PRODUCT', 'asf')).backlog_dir
def paths(d, pre=''):
    out = set()
    for k, v in (d or {}).items():
        out.add(pre + k)
        if isinstance(v, dict): out |= paths(v, pre + k + '.')
    return out
known = {'product:' + p for p in paths(env.load_file('docs/products.example.yaml'))}
known |= {'config:' + p for p in paths(env.load_file('docs/config.example.yaml'))}
known |= {'product:conventions.' + f.name for f in dataclasses.fields(conventions.Conventions)}
known |= {'product:product'}
text = open(os.path.join(rec, 'groom', 'f-0002-card-evaluation.md')).read()
notes_part, _, newkeys_part = text.partition('## New keys')
declared = re.findall(r'^- `([^`]+)` — ', newkeys_part, re.M)
if len(declared) != len(set(declared)): sys.exit('a new key is listed twice')
for iid, verdict, rest in re.findall(r'^- ([FB]-\d{4}) .+? — (reworded|clean|product-bound) — (.*)$', notes_part, re.M):
    if verdict != 'reworded': continue
    body = open(os.path.join(rec, 'features' if iid[0] == 'F' else 'bugs', iid + '.md')).read().split('## History')[0]
    for key, new in re.findall(r'`([a-z]+:[^`]+)`( \(new key\))?', rest):
        if key.startswith('state:'): continue
        if new and key not in declared: sys.exit(f'{iid}: {key} marked new but not under ## New keys')
        if not new and key not in known: sys.exit(f'{iid}: {key} is neither an existing key nor marked (new key)')
        if key not in body: sys.exit(f'{iid}: {key} named in the note but absent from the card')
print('ok')
EOF
```

**T4 — no single-product wording survives outside a `product-bound` card.**

```bash
python3 - <<'EOF'
import os, re, sys
from asf import env
rec = env.load_product(os.environ.get('ASF_PRODUCT', 'asf')).backlog_dir
text = open(os.path.join(rec, 'groom', 'f-0002-card-evaluation.md')).read()
bound = set(re.findall(r'^- ([FB]-\d{4}) .+? — product-bound — ', text, re.M))
trip = re.compile(r"--repo\b|\bthe product repo(sitory)?\b|self-hosted|\bGitHub Actions\b|~/|/tmp/|\bthe runner (pool|box(es)?)\b|\bthe worker accounts?\b", re.I)
bad = []
for iid in re.findall(r'^- ([FB]-\d{4}) ', text, re.M):
    if iid in bound: continue
    body = open(os.path.join(rec, 'features' if iid[0] == 'F' else 'bugs', iid + '.md')).read().split('## History')[0]
    body = re.sub(r'`[^`]*`', '', body)  # a key or a quoted literal in backticks is not an assumption
    bad += [f'{iid}: {m.group(0)}' for m in trip.finditer(body)]
if bad: sys.exit('single-product wording left:\n' + '\n'.join(bad))
print('ok')
EOF
```

**T5 — `clean` and `product-bound` cards were not reworded (D3, D9).**

```bash
import os, re, sys, subprocess
from asf import env
rec = env.load_product(os.environ.get('ASF_PRODUCT', 'asf')).backlog_dir
```
