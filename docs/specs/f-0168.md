# F-0168 — `failed: unpushed work` is a verdict taken on a session's word

Fifteen runs over fourteen days ended `failed: unpushed work` without landing — 7.5 a week against a
threshold of 5, $14.02 and 4.2 h of session time, plus one correction session apiece. The class is
not measured. It is written when a session's own REPORT opens its `pushed:` line with `no`:

```python
def failure(text):
    """The failure a result's own report declares, or None: UNPUSHED for ``pushed: no``."""
    if unpushed(parse(text)):
        return UNPUSHED
```

and `judge` returns that word as the run's `end_reason` **before** it ever looks at git:

```python
    if not runtime_mod.result_ok(ev.result):
        sig = runtime_mod.failure_reason(ev.result)
        # a run that lands nothing may say `pushed: no` truthfully: that is not unpushed work
        if not (not landing and sig == runtime_mod.report.UNPUSHED and ...):
            return f'failed: {sig}' if sig else 'failed'
    if run.get('branch') and landing:          # ← the evidence, never reached
        if not ev.pushed:
            return f'failed: {push_gap(ev)}'
```

So the factory holds a run, spends a round on its item and launches a correction session on the
strength of one word, in a tree that everywhere else insists on the opposite. B-0051 exists because
a report that says *done* is not believed until `origin/<branch>` contains the worktree's HEAD. This
is the same claim in the other direction, and it is believed without a check.

Two shapes of run pay for that, and both are in the record.

**A run with nothing to push.** The brief's REPORT block is one template for every kind
(`briefs.build.TAIL`), and its `pushed:` line offers three forms: `yes <sha>`, `rebased <sha>`,
`no — <why>`. A session whose work is not a commit — an `adjudicate` that rules (*"a ruling is never
a commit in this repo"*, and B-0128 already records that an adjudicate "rules, it does not touch the
branch") — has only the third form available, writes the honest thing, and is failed for it. The one
`failed: unpushed work` row in the checkout's own improve fixtures is exactly that:

```json
{"job": "adjudicate-b-0016-correction", "kind": "adjudicate", "item": "B-0016",
 "end_reason": "failed: unpushed work", "harvested": "superseded"}
```

— and it is a *correction*, i.e. the second session on that hold, failing the same way the first one
did. `lands()` already excuses this, but only for two kinds named in a literal list (`groom`,
`groom-clerk`), so every other kind with nothing to commit walks into the hold.

**A run whose work is already on origin.** `publish_gap` (B-0056, B-0094) accepts this class
already: it commits a run's leftovers and publishes its branch, then re-judges. It returns the
reason *unchanged* on exactly one path — when there was nothing to commit and nothing to push. That
path is the definition of "the work is on origin". Every one of the fifteen went through it, which is
what makes the population knowable without the ledger: a run that survived `publish_gap` with the
class intact had no uncommitted file and no unpushed commit. It was finished, and it was held.

This card makes the `pushed:` word start a look rather than end one. `judge` falls through to the
branch checks that B-0051 already owns, and `failed: unpushed work` is written in exactly one case:
a run whose worktree git could not read, where the session's word is the only evidence there is.

### In

- **`lifecycle.judge` stops taking the `pushed:` word as a verdict.** When the only failure signature
  a result carries is `report.UNPUSHED`, and the process exited cleanly, the failure branch falls
  through to the branch checks B-0051 already owns (D1, D2). What those checks say is what the run
  ends as: `finished`, `failed: not pushed: <n> uncommitted file(s), <m> unpushed commit(s)`, or
  `failed: empty branch: nothing to land`.
- **A run with no branch has nothing a push could carry**, so its `pushed: no` declares no failure —
  the excuse `lands()` gives two named kinds becomes an evidence test that covers every kind (D3).
- **One case still writes the class**: a run with a branch that lands, whose worktree git could not
  read (`not ev.worktree`). There the session's word is the only evidence, so it stands (D4).
- **A result that also ended badly** (`is_error`, or a non-success `subtype`) whose only signature is
  the push word ends bare `failed` — the push is not what went wrong (D5).
- **`health.result_reason` goes.** It is the second writer of the same verdict and has no callers
  (P15); the rule gets one owner (D6).
- **F-0126's park is keyed on what the report declared**, not on the verdict class: a run that
  prints `NEEDS OPERATOR:` and says `pushed: no` still parks its item, whatever git then says about
  its branch (D7).
- **The brief stops asking for the word.** `TAIL`'s `pushed:` line gains a fourth form,
  `nothing — <why>`, for a session whose work is not a commit; the paragraph above it says the
  factory checks git rather than believing the line; `report.py` recognises the new form as a claim
  of no work rather than leaving it to fall through `NO_RE` by accident (D8). The 18 golden briefs and
  the two tests that pin the wording move with it (P7).
- **The prose that states the old rule**: `asf/workers/report.py`'s module docstring (*"That is a
  failed session at the source … before health measures the same thing against git"*),
  `asf/workers/health.py`'s module docstring (the `failed: not pushed` bullet), and
  `docs/guide/operating.md`'s `failed: not pushed: …` line.

### Out

- **`report.failure`, `runtime.failure_reason`, `result_ok`.** A report that says `pushed: no` goes on
  declaring exactly that; only `judge` stops treating the declaration as the verdict. Changing what
  `result_ok` returns would move `finished_unrecorded`, `schema`, `runtime.Result.ok` and every view
  that renders a session before health has judged it (P20, D2).
- **`publish_gap`, `commit_leftovers`, `publish`, `republish_steps`, `push_retry`, the hook and
  network retry classes, `hold`, `hook_refusal_hold`, rounds, the round cap.** Untouched. They are
  what already rescues the measurable cases, and this card's whole effect is to let their verdicts be
  the run's verdict.
- **The `empty branch` class and its loop** (B-0076, D-0048), and `empty_on_a_landed_lane`. A run
  that now reaches them reaches them as they already are — including the drop-the-correction
  shortcut a `failed: unpushed work` run could never reach (P14).
- **`NO_LANDING_KINDS`.** Not extended with `adjudicate`, `close` or anything else: it has a second
  consumer (`groom.answers.carry_staged_answers`) and a list of kinds is the thing D3 replaces.
- **Sub-classing the failure** (`failed: unpushed work: hook refused`, …). It cannot move the reading
  (P18) and it would describe a verdict this card stops writing.
- **A new metric, event or card for the honesty of the move.** The loop already files a cause for any
  failure class over 5 runs/week (P17), so a reclassification files its own card; and `publish_gap`
  has already tried to commit and publish every run in the population, which is what makes the
  survivors provably not push gaps (P8, D9).
- **Backfilling the ledger.** Rows already written `failed: unpushed work` stay as they are, and both
  `outcome_class` and `UNPUSHED_REASON_PREFIXES` keep reading them (D10).
- **The reap race.** A run whose worktree is already gone when it is first judged keeps today's
  behaviour (D4); making `gather` read `origin/<branch>` from the product checkout when the worktree
  is missing is a change to the evidence, not to this verdict, and is not made here.

## The design

### `asf/workers/lifecycle.py` — the rule

`judge`'s failure branch gains the fall-through and its docstring gains the sentence that branch is:

```python
def judge(run, ev, landing=None):
    """The ``end_reason`` health records for a run whose session is over, or None while it runs.

    **The report's ``pushed:`` word is not a verdict** (F-0168). A session that says ``pushed: no``
    is saying where to look, not what happened: the branch checks below are what decide, exactly as
    they do for a session that says it pushed and did not (B-0051). A run with no branch has nothing
    a push could carry, so the word declares nothing at all — the excuse :func:`lands` gives a
    ``groom`` becomes an evidence test that covers every kind whose work is not a commit (an
    ``adjudicate`` rules and never touches its branch, B-0128). ``failed: unpushed work`` is written
    for one run only: one with a branch, whose worktree git could not read, where the word is the
    only evidence there is.

    A result that says ok is ``finished`` only when the branch is pushed; ...
    """
    if landing is None:
        landing = lands(run)
    if ev.result is None:
        return None if ev.alive else DEAD_PID
    if not runtime_mod.result_ok(ev.result):
        sig = runtime_mod.failure_reason(ev.result)
        if sig != runtime_mod.report.UNPUSHED:
            return f'failed: {sig}' if sig else 'failed'
        if not clean_exit(ev.result):
            return 'failed'                      # it failed, and not at the push (D5)
        if run.get('branch') and landing and not ev.worktree:
            return f'failed: {sig}'              # nothing to measure: the word stands (D4)
        # else: fall through — git decides (D1, D3)
    if run.get('branch') and landing:
        if not ev.pushed:
            return f'failed: {push_gap(ev)}'
        if not ev.has_commits:
            return f'failed: {EMPTY_BRANCH}'
    return FINISHED
```

with the one predicate the old excuse spelled inline lifted out, because `judge` now asks it on its
own line and `UNPUSHED` is not the only caller that will want it:

```python
def clean_exit(rec):
    """True when the runtime's own record says the process came to a normal end — not
    ``is_error``, and a ``success`` subtype. Nothing about what the session achieved."""
    return bool(rec) and not rec.get('is_error') and rec.get('subtype', 'success') == 'success'
```

Nothing else in the module moves. `lands`, `NO_LANDING_KINDS`, `push_gap`, `EMPTY_BRANCH`,
`unpushed_text`, `hold`, `outcome_class`, `OUTCOME_CLASSES` and `Evidence` are untouched; `ev.worktree`
is a field `gather` has always set (P16).

What the fifteen become, by the evidence that was already gathered for them:

| The run | Today | After |
| --- | --- | --- |
| no branch (an `adjudicate` that ruled, a `groom-clerk`) | `failed: unpushed work` → hold, round, correction | `finished` |
| branch on origin, HEAD contained, commits of its own | `failed: unpushed work` → hold, round, correction | `finished` |
| branch on origin, its work already landed and the branch empty | `failed: unpushed work` → hold, round, correction | `failed: empty branch: nothing to land` → `landed`, correction dropped (P14) |
| a real gap — uncommitted files, or commits origin lacks | published by the factory, then re-judged (P8) | unchanged |
| a publish the repo's hook or the redaction scan refused | `failed: hook refused: <output>`, no round (P10) | unchanged |
| a rebase that conflicted, a stale head | `failed: unpushed work` → hold with the conflicting files named | `failed: not pushed: …` → the same hold, with the same files named |
| its worktree unreadable | `failed: unpushed work` → hold | unchanged (D4) |
| an errored result that also said `pushed: no` | `failed: unpushed work` | `failed` (D5) |

### `asf/workers/health.py` — one owner, and the park

### `asf/briefs/build.py` and `asf/workers/report.py` — the grammar the failure came from

`TAIL`'s closing paragraph and its `pushed:` line:

```
Run the gate in the foreground and wait for it. Your last act is `git push`. Never start a
background task you do not wait for. A result with uncommitted or unpushed work is a failed
session (B-0051) and comes back to you as a correction. Say so yourself in the report's
`pushed:` line — the factory then checks git, not the word: a branch whose commits are on origin

#: A ``pushed:`` line claiming there was nothing to push — a session whose work is not a commit (a

#: branch is on origin: like every other form, git decides (:func:`asf.workers.lifecycle.judge`).
NOTHING_RE = re.compile(r'^\s*(nothing|no work|n/a)\b', re.I)
```

## Records

- **`sessions.jsonl` gains no field.** What changes is the value of one that already exists: a run
  whose report said `pushed: no` now carries the `end_reason` git supports — `finished`,
  `failed: not pushed: <n> uncommitted file(s), <m> unpushed commit(s)`,
  `failed: empty branch: nothing to land`, `failed: hook refused: <output>`, or bare `failed` — and
  `failed: unpushed work` only when its worktree could not be read (D4, D5).
- **Fewer `correction` objects, fewer rounds.** A run that ends `finished` writes no `correction` and
  spends no round on its item, so the hold, the `corrected` flag and the correction session that
  followed each of these runs all stop being written. A run that reaches `failed: empty branch` on a
  landed lane has its pending correction **dropped** (`harvested: <sha>`, `correction: null`) — a
  transition `failed: unpushed work` could never reach (P14).
- **A held run's correction text stops quoting itself.** The hold on this family now always carries
  the measured gap — `unpushed work: not pushed: 1 uncommitted file(s), 0 unpushed commit(s) — commit
  and push what you have` — instead of `unpushed work: unpushed work — …` (P12).
- **The parked-item record is unchanged in shape and preserved in reach**: `blocked_park`'s
  correction, its `card` fingerprint and its `parked` row are written for the same runs as before,
  keyed now on the report rather than on the verdict (D7).
- **The scorecard.** `state/asf/scorecard.jsonl` and `scorecard-causes.json` keep their shape. The
  `failure:failed: unpushed work` cause's reading falls because the reason is written less often, not
  because it is renamed: the runs it counted move to `finished` (which leaves the dead population
  entirely, `score.is_dead` requiring `not landed`) rather than to another failure class — and if any
  of them did move to `failed: not pushed`, that class's own 5/week threshold files its own card
  (P17, D9). The card's own verify step reads the same number before and after, and this card adds no
  number of its own.
- **`health`'s printed output loses rows rather than gaining them**: no `held … unpushed work: …`
  line for a run whose work is on origin, and no `ended … failed: unpushed work` for one with no
  branch. Nothing new is printed.
- **No new event, card, gate or config key.** `unpushed work` remains a correction kind
  (`lifecycle.UNPUSHED`) and an outcome class (`OUTCOME_CLASSES`), both read as they are today.
- **The brief text every session is handed changes**, and with it the 18 golden fixtures under
  `tests/fixtures/briefs/golden/` — the `pushed:` line's fourth form and the paragraph that says git
  decides.
