# F-0261 — fifty free numbers, reported as none

A job is handed a block of ids before it starts. `asf/workers/spawn.py:162` claims it on the
record's `origin` above every id the record then holds and above every block any other job then
holds, and the launch carries it into the session as `BACKLOG_ID_RANGE=S:60954-61003,…`. Fifty
numbers, nobody else's, reserved for exactly this session's Stories.

Then the session runs `asf new story …` and is told:

```
new: id range S:60954-61003 exhausted
```

Not one of the fifty has been used. What happened is that some *other* job — one whose block was
claimed after this one's, so it sits above it — minted and landed its Stories first, and the
record's highest Story number is now `S-61200`. `asf/record/ids.py:89` does not ask what the
*block* holds. It asks what the *record* holds:

```python
    if rng:
        lo, hi = rng
        n = max(lo, max_n + 1) if max_n >= lo else lo          # max_n is the whole record's tip
        if n > hi:
            raise SystemExit(f"new: id range {prefix}:{lo:04d}-{hi:04d} exhausted")
```

`max_n` is accumulated at `asf/record/ids.py:75-86` over every card of the type in `canonical`
and every `<P>-<nnnn>.md` in the folder — the record's tip, not the block's. Once that tip passes
`hi`, `max_n + 1 > hi` for every call, and the block is reported exhausted for the rest of the
session's life. The reservation is destroyed by someone else's success.

The contract the code was written to is already stated two lines above it, at
`asf/record/ids.py:67`: *"Inside `BACKLOG_ID_RANGE`: the next free number of the job's claimed
block."* The block. This spec makes the code say that.

The arithmetic is prefix-general — `S`, `T` and `B` all go through the same branch — so a plan
session's Tasks and a groom's Bugs fail the same way; `S` is simply where it was seen, because
the `STORIES_FIRST` brief (`asf/briefs/build.py:674-675`) mints Stories one `asf new story` at a
time in a local worktree, which is the one place a long-lived ranged session mints repeatedly
with real time passing between mints.

### In

1. **The ranged branch of `asf/record/ids.py:mint_id` reads the block, not the record.** The next
   id inside `BACKLOG_ID_RANGE` is one above the highest number of `[lo, hi]` the record already
   holds, and `lo` when it holds none. Numbers outside `[lo, hi]` are not consulted.
2. **A block is exhausted only when its own numbers are gone**, and the refusal says which
   condition it is refusing on.
3. **One named helper**, `ids.next_in_block(taken, lo, hi)`, so the rule is a thing with a name
   that a test can call directly and a future caller can reuse.
4. **Every prefix**, because it is one branch: `S`, `T` and `B` get the same correction with no
   per-prefix code.
5. **The rule written down** in `docs/guide/product-config.md`'s id section (P10).
6. **A test module that fails on today's code**, `tests/test_id_range_block.py`, including the
   fence that the number the block hands out is one `idcheck` accepts at land (P5).

### Out

| not done | why |
| --- | --- |
| Claiming a **fresh block** when one genuinely fills up | A different failure with a different fix: the block is spent, not stolen. It needs a claim push from inside a mint, an origin a cloud session does not have, and a decision about what a session's `BACKLOG_ID_RANGE` even means once it holds two blocks. The card is about a block that is *not* spent. |
| Changing how a block is **claimed** (`idclaim`, `reserve_id_range`, the floors) | P3/P4/P8: claim-time behaviour is correct, and `record_top` as a floor is exactly right there. Touching it would widen the diff into the one part of this machinery nothing is wrong with. |
| Changing the **land gate** (`idcheck`) | P5: it already reads block membership. The fix makes `mint_id` agree with it, not the other way round. |
| Making the block size or `DEFAULT_ID_SIZE` adaptive | Nothing observed says 50 is too few. Fifty numbers reported as none is the bug. |
| **Back-filling holes** in a block (reusing a number a card once had) | A deleted or renamed card leaves a number that prose, history lines and backlinks may still name. Minting above the block's own top is monotone and never resurrects an id. Stated as a choice below, and fenced by a test. |
| Warning when a block is **nearly** spent | Speculative: with the block read correctly, a 50-id block spent by one session has not been seen. It can be added when it is. |
| A **new state file, event, metric, config key or `asf` command** | The whole change is a pure function of `(what the record holds, lo, hi)`. Nothing needs to be remembered between calls. |

### The choices

| # | the choice | against | why |
| --- | --- | --- | --- |
| C1 | The block's next number is **one above the block's own top**, `max(n for n in taken if lo <= n <= hi) + 1` | always `lo`, then stepping forward while taken | Both give the same answer on an untouched block. They differ when a number inside the block is already in the record — under `conventions.flags.id_claim: off` the host-local reservation (`id-ranges.tsv`) is computed from the tsv's tops alone, so a locally-computed block *can* overlap ids the record already holds. "Above the block's own top" is monotone there; "first free from `lo`" would hand out a number below one already written. |
| C2 | A **hole inside the block is not refilled** | scan for the first free number in `[lo, hi]` | A number the record once held is named in history lines, backlinks and prose that outlive the card. Refilling it makes two different cards answer to one id across the record's history. The cost is at most a few wasted numbers in a 50-wide block. |
| C3 | The rule is a **named module-level function**, `next_in_block(taken, lo, hi)` | three lines inline in `mint_id` | `mint_id` is already a four-branch function; the one branch this card is about should be readable on its own and testable without a temp record. | C7 | The guide gains **one bullet** in the existing id section | a new subsection, or a troubleshooting entry | P10: the gap is one sentence wide — the section says how a block is claimed and never how it is spent. A bullet next to the other three is where a reader already is. |

## The design

### 1. `asf/record/ids.py` — the rule, named

A new module-level function above `record_top`:

```python
def next_in_block(taken, lo, hi):
    """The next free number of a claimed block ``[lo, hi]``: one above the highest number of the
    block ``taken`` already holds, and ``lo`` when it holds none. Numbers outside the block are
    not read — a block claimed later lands its ids above this one's ``hi``, and the record's tip
    is not this block's tip. Returns ``hi + 1`` when every number of the block is taken."""
    inside = [n for n in taken if lo <= n <= hi]
    return max(inside) + 1 if inside else lo
```

Returning `hi + 1` for a full block (rather than raising) keeps the function total: the caller
owns the refusal, and a test can assert the boundary without catching anything.

### 2. `asf/record/ids.py:mint_id` — one gathering pass, one branch changed

`max_n = 0` and its two `max_n = max(...)` updates become a set, and `max_n` is derived from it
so the three unranged branches below are untouched (C4):

```python
     rng = _id_range(prefix)
-    max_n = 0
+    taken = set()
     for iid, rec in canonical.items():
         if rec['meta'].get('type') == type_:
             m = re.match(rf'^{prefix}-(\d+)$', iid)
             if m:
-                max_n = max(max_n, int(m.group(1)))
+                taken.add(int(m.group(1)))
     d = os.path.join(root, folder)
     if os.path.isdir(d):
         for name in os.listdir(d):
             m = re.match(rf'^{prefix}-(\d+)\.md$', name)
             if m:
-                max_n = max(max_n, int(m.group(1)))
+                taken.add(int(m.group(1)))
+    max_n = max(taken, default=0)
     if rng:
         lo, hi = rng
-        n = max(lo, max_n + 1) if max_n >= lo else lo
+        n = next_in_block(taken, lo, hi)
         if n > hi:
-            raise SystemExit(f"new: id range {prefix}:{lo:04d}-{hi:04d} exhausted")
+            raise SystemExit(f"new: id range {prefix}:{lo:04d}-{hi:04d} exhausted — every number "
+                             f"of the block is in the record")
         return f"{prefix}-{n:04d}"
```

Everything from `worktree = _in_worktree(root)` down is unchanged, and `max_n` still feeds
`idclaim.claim_one(root, prefix, who, floor=max_n)` and the local `n = max_n + 1` with the same
value it has today. `record_top` is not touched (P8).

The docstring of `mint_id` gains the one clause the code was missing — that the block is read and
the record's tip is not — so `asf/record/ids.py:67-69` and the branch below it agree (P6).

### 3. `docs/guide/product-config.md` — the rule, written down

A fourth bullet in **Ids are claimed by push**, after the `asf new` bullet:

```markdown
- **Inside a block**, the next id is the next free number *of that block*: one above the
  highest number of `lo..hi` the record already holds, and `lo` when it holds none. The
  record's tip outside the block is read nowhere — a block claimed later lands its ids
  above this one, and that must not take a number away from a block nobody has used. A
  block is `exhausted` only when its own numbers are gone.
```

### What it looks like when it is there

A session handed `S:60954-61003` mints `S-60954`, `S-60955`, `S-60956` … in order, from the
first `asf new story` to the fiftieth, whatever any other job has landed in the meantime. The
record's tip being `S-61200`, or `S-99999`, changes nothing it sees. Fifty mints in, the
fifty-first says

```
new: id range S:60954-61003 exhausted — every number of the block is in the record
```

and that sentence is now true.

## Acceptance tests

One new module. Every block below is runnable from the repository root and needs no network, no
`git`, and no `~/.ASF`.

### `tests/test_id_range_block.py` — new

```python
"""F-0261: a job's claimed id block is its own. The next id inside ``BACKLOG_ID_RANGE`` is the
next free number *of the block* — the record's tip, which a block claimed later pushes above
this one's ``hi``, never exhausts a block nobody has used. Hermetic: temp dirs, no git, no
network, and the ambient ``BACKLOG_ID_RANGE`` of a ranged worker never leaks in (B-0012)."""
import os
import shutil
import tempfile
import unittest
from unittest import mock

from asf.record import idcheck, idclaim, ids

RANGE = 'S:60954-61003,T:60950-60999,B:60950-60999'
FOLDER = {'S': 'stories', 'T': 'tasks', 'B': 'bugs'}


class Record:
    """A bare record directory holding one card file per id given — no git, no frontmatter
    beyond the id, because ``mint_id`` reads nothing else off the folder."""

    def __init__(self, tc, *iids):
        self.root = tempfile.mkdtemp(prefix='idrange_')
        tc.addCleanup(shutil.rmtree, self.root, ignore_errors=True)
        for folder in FOLDER.values():
            os.makedirs(os.path.join(self.root, folder))
        for iid in iids:
            self.hold(iid)

    def hold(self, iid):
        with open(os.path.join(self.root, FOLDER[iid[0]], f'{iid}.md'), 'w',
                  encoding='utf-8') as fh:
            fh.write(f'---\nid: {iid}\n---\n')
        return iid

    def mint(self, type_='story', canonical=None):
        return ids.mint_id(self.root, canonical or {}, type_)


class TheBlockIsNotTheRecordsTip(unittest.TestCase):
    def test_a_tip_above_the_block_does_not_exhaust_it(self):
        r = Record(self, 'S-61200')  # a block claimed after ours landed its Stories first
        with mock.patch.dict(os.environ, {'BACKLOG_ID_RANGE': RANGE}):
            self.assertEqual(r.mint(), 'S-60954')

    def test_the_block_is_spent_in_order(self):
        r = Record(self, 'S-61200')
        got = []
        with mock.patch.dict(os.environ, {'BACKLOG_ID_RANGE': RANGE}):
            for _ in range(3):
                got.append(r.hold(r.mint()))
        self.assertEqual(got, ['S-60954', 'S-60955', 'S-60956'])

    def test_a_number_inside_the_block_is_stepped_over(self):
        r = Record(self, 'S-60960', 'S-61200')
        with mock.patch.dict(os.environ, {'BACKLOG_ID_RANGE': RANGE}):
            self.assertEqual(r.mint(), 'S-60961')

    def test_a_hole_in_the_block_is_never_refilled(self):
        r = Record(self, 'S-60954', 'S-60956')
        with mock.patch.dict(os.environ, {'BACKLOG_ID_RANGE': RANGE}):
            self.assertEqual(r.mint(), 'S-60957')

    def test_an_id_only_the_canonical_map_holds_counts_as_taken(self):
        r = Record(self)
        canonical = {'S-60954': {'meta': {'type': 'story', 'id': 'S-60954'}}}
        with mock.patch.dict(os.environ, {'BACKLOG_ID_RANGE': RANGE}):
            self.assertEqual(r.mint(canonical=canonical), 'S-60955')

    def test_every_prefix_reads_its_own_block(self):
        r = Record(self, 'T-61500', 'B-61500')
        with mock.patch.dict(os.environ, {'BACKLOG_ID_RANGE': RANGE}):
            self.assertEqual(r.mint('task'), 'T-60950')
            self.assertEqual(r.mint('bug'), 'B-60950')


class AFullBlockIsStillRefused(unittest.TestCase):
    def test_a_block_whose_every_number_is_taken_is_exhausted(self):
        r = Record(self, *[f'S-{n}' for n in range(60954, 61004)])
        with mock.patch.dict(os.environ, {'BACKLOG_ID_RANGE': RANGE}):
            with self.assertRaises(SystemExit) as cm:
                r.mint()
        self.assertIn('S:60954-61003 exhausted', str(cm.exception))
        self.assertIn('every number of the block is in the record', str(cm.exception))

    def test_the_last_number_of_the_block_is_mintable(self):
        r = Record(self, *[f'S-{n}' for n in range(60954, 61003)])
        with mock.patch.dict(os.environ, {'BACKLOG_ID_RANGE': RANGE}):
            self.assertEqual(r.mint(), 'S-61003')


class TheHelper(unittest.TestCase):
    def test_an_untouched_block_starts_at_lo(self):
        self.assertEqual(ids.next_in_block({1, 2, 70000}, 60954, 61003), 60954)

    def test_a_used_block_goes_above_its_own_top(self):
        self.assertEqual(ids.next_in_block({60954, 60955, 99999}, 60954, 61003), 60956)

    def test_a_full_block_returns_the_number_past_hi(self):
        self.assertEqual(ids.next_in_block(set(range(60954, 61004)), 60954, 61003), 61004)


class TheMintedIdLands(unittest.TestCase):
    """``idcheck`` refuses an id no claim covers. The number the block hands out must be one the
    land gate accepts — and the number the record's tip would have handed out must not be."""

    CLAIM = idclaim.Claim('S', 60954, 61003, 'spec-f-0261', 'refs/asf/ids/S-60954')

    def test_the_block_number_is_covered_by_the_claim(self):
        r = Record(self, 'S-61200')
        with mock.patch.dict(os.environ, {'BACKLOG_ID_RANGE': RANGE}):
            iid = r.mint()
        self.assertEqual(idcheck.check_doc(f'- {iid}: a Story\n', {}, [self.CLAIM],
                                           'spec-f-0261'), [])

    def test_the_tip_plus_one_would_not_have_been(self):
        bad = idcheck.check_doc('- S-61201: a Story\n', {}, [self.CLAIM], 'spec-f-0261')
        self.assertEqual(len(bad), 1)
        self.assertIn('no claim covers', bad[0])


class NothingOutsideTheRangedBranchChanges(unittest.TestCase):
    def test_without_a_range_the_record_tip_still_decides(self):
        r = Record(self, 'S-61200')
        with mock.patch.dict(os.environ):
            os.environ.pop('BACKLOG_ID_RANGE', None)
            self.assertEqual(r.mint(), 'S-61201')

    def test_a_range_without_this_prefix_is_no_range_at_all(self):
        r = Record(self, 'S-61200')
        with mock.patch.dict(os.environ, {'BACKLOG_ID_RANGE': 'T:60950-60999'}):
            self.assertEqual(r.mint(), 'S-61201')


class TheGuideSaysIt(unittest.TestCase):
    def test_the_id_claim_section_states_the_block_rule(self):
        root = os.path.dirname(os.path.dirname(os.path.abspath(__file__)))
```

## Records

Nothing new is persisted, and that is a choice: the next id is a pure function of what the record
holds and the two numbers of the block, so there is nothing to remember between calls. These are
the records the change does leave.

| what | where | written by |
| --- | --- | --- |
| the card itself | `<record>/stories/S-60954.md` and its siblings — a file per minted id, inside `[lo, hi]` | `write_new_item`, unchanged; only the *number* in its name differs from today |
| the refusal, when a block really is spent | the session's stdout, as `new: id range <P>:<lo>-<hi> exhausted — every number of the block is in the record` | `mint_id`; nothing parses it (P9), a human reads it |
| the claim the number falls under | `refs/asf/ids/<P>-<lo>` on the record's origin, written at launch and **not** touched here | `idclaim.claim` via `spawn.reserve_id_range` |
| the land verdict on that number | the plan-tasks line, which now never reads `mints id(s) no claim covers` for an id this branch handed out (P5) | `idcheck.check_doc`, unchanged |
| the rule, in prose | `docs/guide/product-config.md`, **Ids are claimed by push**, one new bullet | this change |

Explicitly **not** written: no new state file, no `id-ranges.tsv` field, no jsonl event, no metric,
