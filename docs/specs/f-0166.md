# F-0166 — the card's last heading is not a tombstone

On 2026-09-26 a session tried to append a note to `features/F-0092.md`. The record pre-commit
refused it:

> `## Backlinks section is stale (run `asf index`)`

The session did what the message said. `asf index` rewrote the card — and **deleted the note**.
It tried three times; three times the note was written, refused, "fixed" away.

Both halves of that loop are one defect, and it is not in the backlink computation. It is in
`parse_sections`:

```python
parts = re.split(r'(?m)^(## .+)$', body)          # asf/record/core.py:147
```

A section's *content* is everything between its heading and the next `## ` heading — or, for the
last section, **everything to the end of the file**. Every card this factory mints ends with
`## Backlinks` (`asf/record/new.py:177`, `asf/record/ids.py:96`), so `## Backlinks` is the last
section of essentially every card in the record. Therefore:

- **Text appended to the end of a card is, by construction, "the content of `## Backlinks`."**
- `expected_body` replaces that content wholesale with `section_content(blines, is_last)` — the
  derived bullets and nothing else (`core.py:315-316`). The note is not "dropped"; it is
  *regenerated away*, because the product genuinely believes it was derived text.
- `check.py:279` compares the same content and reports `## Backlinks section is stale`. It is not
  lying either. By its own definition the section *is* stale — it contains a line the derivation
  did not put there.

So the refusal and the deletion are the same sentence read twice. The card names them as two
defects, and they are fixed in two places, but there is one cause and the fix has one shape:
**a derived section owns the bullets the index writes, and nothing else under that heading.**

The second defect is real on its own terms too, and survives the first fix. `stage_derived` —
the auto-heal 69380aa added — is armed by a trigger that only ever looks at `index.json`:

```python
if now[2] - base[2]:                               # asf/record/check.py:430
    if stage_derived(repo, prefix, ...):
```

`now[2]` is `index_wrong`, the set of `index.json` entries that disagree with the record. A
card's own `## Children` / `## Backlinks` section going stale **without** an `index.json` entry
changing — a title edited, a scrub changed, a bullet deleted by hand, a note parked under the
heading — arms nothing, and the finding goes to `_report_staged` as a new blocking error. P3
below shows that refusal happening today, at HEAD, in three separate ways.

### In

- **`section_content` gains a `current=None` keyword.** When `current` is given, the returned
  content is the section's existing lines with the **derived bullets replaced in place**: every
  line that matches the derived-bullet shape (P5) is removed, the new derived bullets are inserted
  at the position where the first one stood (or at the top of the section when there was none),
  and every other line is kept verbatim and in order. With `current=None` the function renders
  exactly what it renders today, so `ingest.py` is untouched (P10).
- **`expected_body` passes the section's current content through.** `section_content(clines,
  is_last, current=content)` and the same for `blines`. That is the whole of defect (1): a note,
  a History line, an HTML comment, a hand bullet pointing outside the item folders — all survive
  `asf index`, in place, while the derived bullets are brought to what the record derives.
- **A `DERIVED_LINE_RE` in `asf/record/core.py`, built from `ITEM_FOLDERS`** (P12), with the
  backreference that ties the link text to the link target (P5). It is the single definition of
  "this line belongs to the index", and the three readers below all use it.
- **`scan_text` narrows its exclusion from the section to the bullet.** Inside `## Children` and
  `## Backlinks` it drops the lines matching `DERIVED_LINE_RE` and keeps the rest, so a mention
  written by hand under those headings counts like a mention anywhere else (P7). A derived
  bullet's own *title* still creates no backlink, which is the property the exclusion existed for.
- **`check.py`'s bare-decision scan narrows the same way** (P8): under those two headings it skips
  a line only when it matches `DERIVED_LINE_RE`.
- **The hook's heal is armed by any new derived staleness, not only `index.json`'s.**
  `cmd_check_staged` computes the set of `(path, msg)` pairs whose `msg` is a derived-staleness
  message — `INDEX_STALE` or the `## <Section> section is stale` line — and calls `stage_derived`
  when the staged state has one that `HEAD` has not, by the **same new-vs-standing rule
  `_report_staged` already applies** (a staleness `HEAD` already carries stays a warning and arms
  nothing). That is defect (2): the hook stops telling the operator to run a command that would
  have eaten their note, and does the regeneration itself, into the commit's index (P9).
- **A shared predicate for "this finding is derived staleness."** One module-level helper in
  `check.py` used by both the arming test and nothing else; the message text stays exactly what it
  is today, because `_report_staged`'s standing-debt matching keys on it (`check.py:499`).

### Out

- **`parse_sections` is not changed.** Splitting only on `^## ` and letting the last section run
  to EOF is right for every other reader in the product (`check.py`'s size and History readers,
  `shape`, `ingest`); the defect is not that the *split* is wrong, it is that `expected_body`
  treated "the section's content" as "the index's property". Adding a terminator sentinel to every
  card — `<!-- /backlinks -->` — was considered and rejected (D2).
- **The derived bullets' position is not normalised.** A card whose note sits above its Backlinks
  list keeps it above; the bullets are spliced where they already are (P6). `asf index` is not a
  formatter.
- **A hand bullet that *looks* derived is not protected.** If someone writes
  `- [F-0001](../features/F-0001.md) my own note` under `## Backlinks`, it matches
  `DERIVED_LINE_RE` and the index will take it. That line is indistinguishable from a derived one
  by construction, and a rule that guessed would be worse than one that is stated.
- **No migration of the record.** Every card in the record today is already consistent with the
  new rendering wherever it has no hand text under a derived heading — which, P2's `cards
  written=[]` case aside, is the whole record. `asf index` after this change rewrites nothing that
  is not already stale. No `schema-migrate` step, no version bump.
- **The hook's refusal for real errors is untouched.** Everything that is not derived staleness —
  a bare decision reference, a duplicate id, a missing `blockedBy` target, a deleted parent — is
  judged exactly as it is today, and P9's fourth case shows the heal does not fire on a commit
  with nothing stale.
- **`asf index`'s output contract is unchanged.** It still returns the relpaths written, still
  skips a card that fails to parse, still writes `index.json` under the same conditions.

### Choices

| # | Chosen | Against | Why |
| --- | --- | --- | --- |
| D1 | Recognise the **derived bullet** by its own shape and keep every other line | Recognise the *section* and keep everything after the last bullet | "Everything after the last bullet" cannot handle P2's third shape — a note wedged between the heading and the list — and it makes the rule positional, so re-running `asf index` after a backlink is added moves the note. The bullet is self-identifying (P5): the link text *is* the target's basename, which nothing else in a card does by accident. Idempotence over all ten prototype shapes (P6) is a property of matching the line, not the position. |
| D2 | No sentinel comment delimiting the derived region | Write `<!-- backlinks:begin -->` / `<!-- backlinks:end -->` into every card | A sentinel is a migration of every card in the record, and it is load-bearing: a card that loses its end marker — by a hand edit, a merge conflict, a copy-paste — silently reverts to today's behaviour and eats the note again, with no error anywhere. The bullet shape needs no migration and degrades to "the index took a line that looked exactly like its own", which is stated and visible. |
| D3 | `current=` as a keyword with a `None` default on `section_content` | A new function, `merge_section_content` | One caller (`ingest.py:300`) wants today's rendering and one (`expected_body`) wants the merge, and the two differ by one input, not one algorithm — the `None` branch *is* the merge over an empty section. A second function would duplicate the trailing-blank-and-`is_last` handling, which is the fiddly part (P6's stability depends on it). |
| D4 | Narrow `scan_text` in the same change | Leave the exclusion by heading and ship only the preservation | Preserving a note under `## Backlinks` while refusing to read it creates a place in the record where `[[F-0001]]` is invisible — the record would hold text it cannot see, which is worse than dropping it, because nothing reports it. P7 shows the narrowing costs nothing: the sample record's derived state is byte-identical and the property the exclusion existed for (a derived title must not create a backlink) still holds. |
| D5 | Arm the heal on the **finding message**, reusing `_report_staged`'s new-vs-standing rule | Arm it on a recomputed diff of every card's expected body | The finding is already computed, once, by `record_findings` over both trees; recomputing `expected_body` for every card a second time doubles the hook's cost on a large record for an answer it is holding. Reusing the standing-debt rule also means the heal and the report can never disagree about what counts as new — today they are two different tests over two different values (P4), which is how this hole opened. |
| D6 | Fix both halves under one card | Split the hook half to its own Bug | They are one sentence read twice (the opening), they share `DERIVED_LINE_RE`, and shipping the index half alone leaves the hook refusing P3's other two shapes with a message whose remedy is now harmless but still not automatic. Shipping the hook half alone would auto-run the note-eating `asf index` **into the commit**, which is strictly worse than refusing. The order matters and the card is right to hold both. |

## The design

### 1. The derived bullet, named once — `asf/record/core.py`

Beside `rel_link`, one regex built from `ITEM_FOLDERS` (P12), with the backreference that makes it
exact:

```python
DERIVED_LINE_RE = re.compile(
    r'^- \[([^\]]+)\]\(\.\./(?:' + '|'.join(re.escape(f) for f in ITEM_FOLDERS) + r')/\1\.md\)(?: |$)')
"""A bullet :func:`children_lines` / :func:`backlinks_lines` wrote: the link text is the target's
own id and the folder is an item folder. The index owns these lines inside ``## Children`` and
``## Backlinks``; every other line under those headings is the card's own."""
```

### 2. `section_content` keeps the card's own lines — `asf/record/core.py:166`

```python
def section_content(lines, is_last, current=None):
    """The derived section's content. ``current`` (the section's existing content) splices
    ``lines`` in where its derived bullets stood and keeps every other line verbatim, in order;
    without it the section is rendered as ``lines`` alone, as it always was."""
```

Today's body is the `current is None` branch, unchanged. The merge branch: strip the leading
newline that ended the heading line, split into lines, find the index of the first
`DERIVED_LINE_RE` match, drop every match, insert `lines` at that index adjusted for the matches
removed before it (or at `0` when there were none), drop trailing blanks, and re-render with the
same `'\n' + ''.join(f'{l}\n' …)` and the same `is_last` trailing blank. P6's ten cases are the
acceptance.

### 3. `expected_body` stops owning the whole section — `asf/record/core.py:310-317`

```python
         if h == '## Children':
-            content = section_content(clines, is_last)
+            content = section_content(clines, is_last, current=content)
         elif h == '## Backlinks':
-            content = section_content(blines, is_last)
+            content = section_content(blines, is_last, current=content)
```

Two lines. `asf index`, `asf check`, `asf set`'s refresh and `stage_derived` all go through
`expected_body`, so all four gain the preservation at once — and, because `check.py:274` compares
against the *same* function, a card carrying a note stops reading stale the moment it stops being
rewritten.

### 4. The two readers narrow with it

`scan_text` (`core.py:191-196`) keeps the non-bullet lines of a derived section instead of
dropping the section:

```python
     for heading, content in sections:
         if heading.strip() in ('## Children', '## Backlinks'):
-            continue
+            # the index's own bullets are a mirror of another card's title, not this card's prose;
+            # anything else under the heading is the card's own text and mentions from it count
+            content = '\n'.join(l for l in content.split('\n') if not DERIVED_LINE_RE.match(l))
+            body_text += content
+            continue
         body_text += heading + content
```

`check.py`'s bare-decision loop (`:262-263`) skips a line under those headings only when
`DERIVED_LINE_RE.match(l)`, instead of skipping every line.

### 5. The hook heals what it used to refuse — `asf/record/check.py:430`

```python
SECTION_STALE_RE = re.compile(r'^## \S+ section is stale ')

def _derived_stale(findings):
    """The findings that are a derived section or index out of date — what the hook regenerates
    (:func:`stage_derived`) rather than refuses."""
    return Counter((p, m) for p, _l, m in findings if m == INDEX_STALE or SECTION_STALE_RE.match(m))
```

and the trigger becomes the same new-vs-standing subtraction `_report_staged` performs:

```python
-        if now[2] - base[2]:
+        if _derived_stale(now[0]) - _derived_stale(base[0]) or now[2] - base[2]:
             if stage_derived(repo, prefix, os.path.join(staged_dir, prefix), scrub):
                 now = record_findings(os.path.join(staged_dir, prefix), scrub, layout=False)
```

`Counter.__sub__` keeps only positive counts, so a staleness `HEAD` already carries subtracts to
nothing and arms nothing — the standing-debt rule, applied once, to the same values
`_report_staged` will apply it to when it reports. `index_wrong` stays in the test because an
`index.json` entry can move without any card's section text moving (a frontmatter field the entry
carries but the bullets do not).

### What it looks like when it is there

The session that filed this card appends its note to `features/F-0092.md`, `git add`s it, and
commits. The hook regenerates the Backlinks bullets of whatever cards the note's mentions touched,
prints `backlog/…: regenerated from the staged cards and staged`, and the commit lands — with the
note in it. `asf index`, run at any later time, leaves the note exactly where it is.
