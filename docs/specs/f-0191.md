# F-0191 — "finished, landed 548fe32" on a run that committed nothing

The first customer install read its DONE table and saw two correction runs finish with
`landed 548fe32`. Neither had made a commit. `548fe32` was not their work at all — it was another
item's plan merge, which happened to be the trunk tip at the moment the harvest pass ran.

The operator's DONE table is the one place the factory says, in one line, what a session came to.
`landed <sha>` is the strongest claim it can make: *this run put that commit on the trunk*. Handing
that claim to a run with nothing of its own spends the operator's trust on a row that cannot be
checked — and when they do check it, the sha leads to someone else's card.

The item itself stays Active, so nothing downstream acts on the false credit. That is what makes
this a display defect and keeps it small. It is also what makes it worth fixing cheaply: the record
is right, only the sentence about it is wrong.

**Where it comes from.** `asf/harvest/lane.py:1362-1369` — a branch with nothing past the trunk
(`ahead == 0`) whose item already has a commit on the trunk is judged `on_trunk`, which
`asf/harvest/lane.py:1128` turns into `MERGED, method=on-trunk`. `enter_merged`'s third arm
(`asf/harvest/lane.py:1911-1919`) has no merge sha to name for such a branch, so it falls back to
`self.trunk_sha` — **the trunk tip, whatever it is** — and writes it as `harvested:` on the run.
`asf/tick/summary.py:124` then credits it, because its one guard against exactly this
(`credits_landing`) rests on `lifecycle.finished(run)` and the claim in its own docstring —
"which health writes only for a pushed branch with commits of its own" — **is false**.

The design below closes it in the only place that can answer the question after the fact: the lane
already knows how much the branch carried of its own, and now writes it down.

## Decisions

(a bare origin, a checkout, a worker clone) and deleted before this spec was committed.

### In

* One new field on the lane record — how many commits of its own the branch carried past the trunk
  — written wherever the lane already writes a record.
* `asf/tick/summary.py`: a landing is credited only to the run that earned it; a run that ends
  `finished` carrying a sha that is not its own says `finished, nothing of its own`.

### Out

| # | Not in this spec | Why |
| --- | --- | --- |
| R1 | Changing what `enter_merged` writes as `harvested:` for an `on-trunk` landing. | The card scopes this to display. `harvested:` is read by the ingest, by `prune_branches`, by the metrics' landing events and by `reap_verdict`; changing the value changes the record. A wrong *sentence* is this card's defect; a wrong *fact* would be another. |
| R2 | The sha shown when a branch **with** its own commits lands `on-trunk` (`already_on_trunk`: its changes reached the trunk under another card's commit). It is still the trunk tip, not the commit that carried the work. | The card's rule credits it: it has "a commit on the run's branch that is not an ancestor of the base it was cut from". Naming a better sha means finding it, which is a different piece of work. Worth a card; not this one. |
| R3 | What the record does with a `merge_facts` entry whose sha is the trunk tip (P8). | The card states the item correctly stays Active. Re-deriving the record's whole closing ladder to confirm it is out of proportion to a display fix — but the hazard is named here so the next reader does not have to find it twice. |
| R4 | `asf/workers/trunkclose.py`'s own foreign sha, beyond refusing to credit it. | Its `harvested:` is deliberately another card's commit (that is what "closed on verified trunk evidence" means) and it marks itself `trunk_closed:`. The display must not credit it; the write itself is correct and stays. |

### The choices

| # | Chosen | Against | Why |
| --- | --- | --- | --- |
| C1 | Record the branch's own-commit count on the lane record at write time, and read it back from the ledger. | Ask git at render time (`rev-list origin/main..origin/<branch>`). | Impossible, not merely slow: `enter_merged` pushes a branch delete in the same pass for `method in ('on-trunk', 'ff')` (`asf/harvest/lane.py:1921-1923`), so by the time the DONE table prints there is no branch to count. The trunk has also caught up (P5). The fact must be captured while it is still readable. |
| C2 | Refuse the credit when the lane record says `method == 'on-trunk'` **and** the count is `0`. | Refuse on the count alone, ignoring `method`. | A fast-forward landing recorded across two passes (R8: `MERGING` in one pass, `MERGED` in the next) re-reads `ahead` *after* the trunk caught up and records `0` on a landing that was entirely its own. `method` is what separates "the sha is the trunk tip" from "the sha is this run's push" (P2). |
| C3 | An absent count means *credit* — the field is unknown, not zero. | Refuse without positive evidence of own commits. | Every ledger line written before this change lacks the field, as does a branch already gone from origin when the lane first saw it (`gone_merged`, no `ahead` to read). Refusing on silence turns one wrong sentence into a different wrong sentence on real landings. The defect is the *known-empty* case, and P5 shows the lane knows it exactly there. |
| C4 | Carry the count forward from the previous lane record when the branch is gone. | Leave it absent on those records. | `Lane.record` already does exactly this for `heavy`/`heavy_at`, and `head_since` for `head_at`. The last pass that could see the branch counted it; the landing pass should not throw that away just because the branch has since been deleted. |
| C5 | `trunk_closed:` on the run also refuses the credit. | Leave `asf/workers/trunkclose.py`'s runs credited. | Same defect, same rule: its branch holds nothing past the trunk (`evidence()` requires `not unlanded(...)`) and its sha is another card's commit by construction. It is one `.get` on a field that already exists and already means precisely "this sha is not this run's own work". |
| C6 | `credits_landing` keeps its name and its contract; its current body becomes `claims_landing`, and the new ownership test is a second predicate. | Grow `credits_landing`'s condition in place. | The renderer needs both answers, not one: "should this row say `landed <sha>`" and "is this a row that *claims* a landing at all" — the second is what decides whether to print `nothing of its own` rather than leaving the result bare. Two named predicates say that; one boolean cannot. |
| C7 | The word for the refused case is the card's: `nothing of its own`. | `landed elsewhere`, `no commits`, `not its landing`. | The card names the string. It is also the honest one: the factory knows the run carried nothing of its own, and does *not* know whose commit the trunk tip is. |

## The design

### 1. The lane writes down what the branch carried — `asf/harvest/lane.py`

`Lane.record` (`asf/harvest/lane.py:1736`) gains one field, `own`: the branch's own commits past
the trunk as `branch_facts` counted them this pass, inherited from the previous record when this
pass could not count them (the branch is gone from origin), and absent when neither is known.

```python
def record(self, f, state, reason, **extra):
    pr = (f.get('pr') or {}).get('number') or (f.get('prev') or {}).get('pr')
    now = now_iso()
    rec = {'state': state, 'head': f.get('head'), 'pr': pr, 'at': now,
           'head_at': head_since(f.get('prev'), f.get('head'), now),
           'reason': reason, 'item': f.get('item')}
    prev = f.get('prev') or {}
    # what the branch carried of its own, counted while origin/<trunk>..origin/<b> still shows
    # it (PD6). A branch gone from origin cannot be counted: the last pass that could, stands.
    own = f.get('ahead', prev.get('own'))
    if own is not None:
        rec['own'] = own
    if prev.get('heavy') and prev['heavy'] == f.get('head') and state not in HEAVY_DROPS:
        ...
```

Beside it, one named constant for the word the record already writes, so the reader below is not a
second spelling of it:

```python
#: `method` on a MERGED record whose sha is the trunk tip, not a merge of this branch: the
#: branch's work was already there. The one landing the DONE table may not credit (F-0191).
ON_TRUNK = 'on-trunk'
```

`_judge`'s two `'method=on-trunk'` sites (`asf/harvest/lane.py:1128`, `:1133`) and
`enter_merged`'s `method in ('on-trunk', 'ff')` test (`:1921`) are re-spelled through it.

### 2. The DONE table credits the run that earned it — `asf/tick/summary.py`

`credits_landing` keeps its name, its callers and its contract. Its present body becomes
`claims_landing` — *this row asserts a landing* — and the new question is asked separately.

```python
def claims_landing(run):
    """True when the DONE table has a landing to say something about: the run was harvested at a
    real sha and ended ``finished``. An archived run (:data:`~asf.workers.lifecycle.NOT_A_LANDING`)
    and the lane's synthetic ``adopted`` row are neither landings nor sessions."""
    sha = (run or {}).get('harvested')
    return (bool(sha) and sha not in lifecycle.NOT_A_LANDING and lifecycle.finished(run)
            and not run.get('adopted'))


def own_landing(run):
    """True when the harvested sha is the run's own landing, and not a commit it merely sat behind.

    Two answers count as its own (F-0191): the branch carried a commit past the base it was cut
    from, or the sha is the lane's mark for this run's own merge — a merged PR's sha, or the tip
    it pushed. What is left is the lane's ``on-trunk`` arm, which has no merge to name and writes
    the trunk tip instead (:meth:`asf.harvest.lane.Lane.enter_merged`): credited only when the
    branch did carry something of its own.

    An absent ``own`` is unknown, not zero — a ledger line written before the count existed, or a
    branch already gone from origin when the lane first read it — and unknown is credited: the
    factory does not call a real landing empty on silence. A run closed on another card's trunk
    commit (:mod:`asf.workers.trunkclose`) says so on its own line and is never credited."""
    from asf.harvest import lane  # lane imports lifecycle; the tick summary runs once a tick
    if (run or {}).get('trunk_closed'):
        return False
    rec = lifecycle.lane_of(run)
    if rec.get('method') != lane.ON_TRUNK:
        return True
    return rec.get('own') != 0


def credits_landing(run):
    """True when the DONE table may say a run ``landed <sha>``: it claims a landing
    (:func:`claims_landing`) and the landing is its own (:func:`own_landing`)."""
    return claims_landing(run) and own_landing(run)
```

The renderer says the second half of the card's sentence — the row that claims a landing it did not
earn stops being silent about it:

```python
for r in done:
    result = r.get('end_reason')
    if credits_landing(r):
        result = f"{result}, landed {r['harvested'][:7]}"
    elif claims_landing(r):
        result = f'{result}, nothing of its own'
```

A run with no `harvested:` at all, an archived run and an adopted row are untouched: they claim no
landing, and their result reads exactly as it does today.

## Acceptance tests

All three run from the repo root and need no network, no `gh` and no product install.

**A1 — the lane records what the branch carried.** New class `OwnCommits` in `tests/test_lane.py`,
over `LaneFixture`'s real origin: a branch with one commit records `own: 1` on every lane record
through to `MERGED method=ff`; a branch pushed at the trunk tip records `own: 0` on its
`MERGED method=on-trunk`; a branch gone from origin carries the previous record's count forward;
a record with neither has no `own` key at all.

```bash
python3 -m unittest tests.test_lane.OwnCommits -v
```

**A2 — the predicates, pure.** The existing
`tests/test_lane.py::FeederAndOutcomes::test_the_done_table_credits_only_a_run_with_its_own_commits`
is extended with the F-0191 table — `{method: on-trunk, own: 0}` not credited,
`{method: on-trunk, own: 1}` credited, `{method: ff, own: 0}` credited, `trunk_closed` not
credited, no lane record credited (unknown) — and asserts the rendered text: the refused row reads
`finished, nothing of its own`, and a run with no `harvested:` still reads a bare `finished`.

```bash
python3 -m unittest tests.test_lane.FeederAndOutcomes -v
```

**A3 — the card's test, end to end: a branch with no own commits → no landed sha.** New class
`EmptyLaneBranchIsNotCredited` in `tests/test_lane.py`, over `LaneFixture`, reproducing P1 exactly:
an earlier commit naming the item on the trunk, a lane branch pushed at the trunk tip with nothing
of its own, a run ended `finished`, then another item's commit as the new trunk tip. One
`harvest.run_product_harvest` pass, then `summary.render` over the run: the row contains
`nothing of its own`, and contains neither `landed` nor any 7-character prefix of the trunk tip.

```bash
python3 -m unittest tests.test_lane.EmptyLaneBranchIsNotCredited -v
```

The two suites that own the touched modules must stay green:

```bash
python3 -m unittest tests.test_lane tests.test_harvest tests.test_tick -v
```

## Records

| What | Where | Shape |
| --- | --- | --- |
| The branch's own-commit count | `<state>/sessions.jsonl`, on the run's `lane` record | `"lane": {..., "own": 0}` — an integer, absent when unknown. Written on every lane transition, by the same `Lane.write` call that already writes `lane:` and `harvested:`; no new file, no new line, no second write. |
| The DONE table's result cell | the tick's console output | `finished, landed <sha7>` when the landing is the run's own; `finished, nothing of its own` when it claims one that is not; unchanged otherwise. Console only — `asf/tick/summary.py` writes nothing to the record and its failure never changes the tick's exit code. |

Nothing is written to `docs/`. No event, no card field and no metric changes: `harvested:` keeps the
value it has today (R1), so `merge_facts`, `prune_branches`, the landing events in
`asf/metrics/metrics.py` and `reap_verdict` all read exactly what they read now.
