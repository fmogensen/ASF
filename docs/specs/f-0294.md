# F-0294 — a leftover never moves a load-bearing head, and the record sync finishes what it owns

Two places where the factory's own tidying-up costs more than the mess it tidies.

**One.** B-0094 taught the factory to commit what a finished session left uncommitted: 19% of
sessions ended `failed: not pushed: N uncommitted file(s)` and each one cost a correction
session, so `health.publish_gap` now commits the leftovers on the session's behalf and publishes
them. It commits them *on the checked-out lane branch*, which moves the branch head. When that
head is load-bearing — the PR is a member of a batch in flight, or it carries an `asf land`
request — the move is read exactly as an owner's own push: `merge_queue.judge` lists the member
as `head moved` and drops the whole batch, every batch stacked on it with it, and the chain is
cut again from scratch. Three times on 2026-10-07 on one product's goal PRs (#1070 at 21:30Z,
wip commit `537670860`; #1238; #1143), for files no check reads — a review's
`.sdd-input/reviews/*.md`, a report leftover. F-0287 already fixed the *other* commit that moved
a batched head, a session's report commit, by letting the batch stand when the head advanced by
marker commits onto the same tree. A leftover commit changes the tree, so that door is shut to
it: the answer here is not to widen what counts as a marker, it is to stop making the move.

**Two.** The operator's record checkout is brought level with origin every tick
(`sync_operator_checkout`, F-0260). It refuses to touch a dirty tree, says so once, and then
waits for a hand — for ever. On 2026-10-07 it carried staged record writes from about 21:16 and
sat there for three hours, saying nothing after the first line, until the operator stashed them
by hand. The writes were the record's own; the checkout's drift, the Decisions row and `asf
next` were all frozen behind them. A sync that cannot finish a write a *human* started is right
to wait. A sync that cannot finish a write its own writer staged is not finishing its own job,
and a silence that long is how it went unnoticed.

### In

1. **The pin is read before any leftover is committed.** `merge_queue.head_pinned(state_dir,
   branch, pr)` answers, from the two state files alone (P6), whether this branch's head is
   load-bearing: it is a member of a batch in flight, or its PR carries an `asf land` request.
2. **A pinned branch's leftovers are filed off the branch, not committed onto it.** They become
   one commit object parented on HEAD, kept under `refs/asf/leftovers/<branch>/<stamp>` and
   pushed there (P9), and the worktree is then cleaned — so the tree is clean for the judge (P7),
   the head never moves, and the batch stands.
3. **An unpinned branch is unchanged.** `commit_leftovers` runs exactly as it does today; B-0094
   keeps every bit of its win on the branches where the commit costs nothing.
4. **The filing is recorded.** The ref, the sha, the file count, the pin's reason and whether the
   push took are one block on the run's ledger line and one line on the tick's output, so the
   leftovers are findable without knowing they happened.
5. **The record sync finishes a dirty tree it owns.** A dirty record checkout whose every entry
   is a *staged* change under `record_paths()` (P12) is a record writer's interrupted work: the
   sync re-derives `index.json`, commits it signed off, and carries it to origin through the
   `ahead` path that already exists (P11).
6. **A dirty tree the sync cannot finish is named on a cadence, not once.** The marker grows a
   `said` stamp; the line is printed again every `record.dirty_say_hours` (default 1) and carries
   how long the tree has been dirty. A three-hour silence becomes impossible.

### Out

| not in this spec | why |

A floor kind is a `FLOOR_KINDS` change with its own `release.floor.*` key and its own evidence — a separate card if the cadence proves too quiet |
| an `asf` command that restores a filed leftover into a worktree | the recovery is `git fetch origin <ref> && git checkout FETCH_HEAD -- <path>`, and the line prints the ref. Nothing is lost, so nothing needs a command yet |

| redacting a leftover before the ref is pushed | the ref is pushed `refs_only=True` exactly as the archive and recovery refs already are (P9) and never merges, so nothing it carries reaches the product. See C6 for the local-first ordering that bounds the risk |

### The choices

| # | chosen | against | why |
| --- | --- | --- | --- |
| C1 | file a pinned branch's leftovers off the branch | commit then revert the branch head; or leave them uncommitted as a hold | a revert is two moves of a pinned head, not none, and each restarts the PR's CI. Leaving them is P7: the correction session B-0094 exists to prevent. Filing is the only option that moves nothing and judges clean |
| C2 | a git ref (`refs/asf/leftovers/<branch>/<stamp>`) | a directory of copies under the state dir, as `review_store` uses | a commit object needs no copy-verify to be trusted, diffs against the head it sat on, and is recovered with one `git checkout`. `review_store` copies because a review is one known file at a known path; a leftover is an unknown set, and a tree object is the honest container for one |
| C3 | clean the worktree after the ref resolves | leave the files in the tree | P7: an uncommitted file is `failed: not pushed`, whatever else is true. The files are reachable from the ref before anything is removed, so the clean loses nothing; and `git clean -fd` without `-x` leaves ignored files (a `.sdd-input/` an exclude already hides) alone |
| C4 | read the pin from the state files | ask the forge for the PR's queue membership | P6: both files are on disk and the health pass already runs under a forge rate budget. A pin read from state is also the same answer `judge` will act on, read from the same place |
| C5 | an `asf land` request pins the head too, not only batch membership | pin only a member of a batch in flight | the card names both. A request is a green the operator asked to land as it is; moving the head throws that green away and restarts the heaviest run the product has, batch or no batch (`asf/tree_green.py:6`, B-0275: 45–60 min on a saturated queue) |
| C6 | write the ref locally, then push it; a refused push keeps the local ref and is named | push first and only then write a local ref; or never push | the local ref lives in the repo's common git dir, so it survives the worktree's reaping with no network at all — that is the durability the clean depends on. The push is what makes it readable from another host, and it is allowed to fail |
| C7 | the sync finishes only a tree whose every entry is *staged* and under `record_paths()` | finish any dirty record checkout; or keep waiting for a hand | a staged write is a record writer's own interrupted work and was already shaped by its writer; an unstaged change is a hand in the file, and a path outside `record_paths()` is not the record's. One unstaged entry, one foreign path, one `U` — the whole tree stays the operator's, as today |
| C8 | say it again on a cadence | raise it to a floor kind, or a `NEEDS OPERATOR` park | the failure the card records is a silence, not a missing escalation: the line was printed, once, three hours before anyone looked. Repeating it with an age is the smallest change that fixes exactly that |
| C9 | the leftover commit is built with a scratch index and `commit-tree` | `git stash create`; or `git add -A && git commit` then `git reset --hard HEAD~1` | `commit-tree` writes an object and touches neither HEAD, nor the branch ref, nor the worktree's index — there is no window in which the branch is moved. `stash create` cannot carry untracked files, which is most of what a leftover is |
| C10 | `record.dirty_say_hours`, a new `record.*` key | a constant in the module | P13: the namespace is free, and an operator whose record checkout is dirty for a reason wants to turn the line down without a patch. The code's own default (1 h) is what it does with the key unset or malformed |

## The design

### 1. The pin — `asf/merge_queue.py`

```python
def head_pinned(state_dir, branch, pr=None):
    """Why ``branch``'s head must not move, or ``''`` when it may (F-0294).

    A head is pinned while the merge queue is standing on it: the branch is a member of a batch
    in flight (a move is read as ``head moved`` and drops the batch and everything stacked on
    it, :func:`judge`), or its PR carries an ``asf land`` request (the operator asked for *that*
    green to land, and a move throws it away with the PR's whole CI). Read from the two state
    files alone — no forge call, no network — so the answer is the one :func:`judge` will act on.
    An unreadable file is no pin: the caller then does what it did before this function existed.
    """
```

Returns one clause, fit to be dropped into a line: `'it is a member of refs/asf/mq/1 in the
merge queue'`, or `'PR #1070 is an asf land request'`. Batch membership wins when both hold.
`pr` is the run's PR number when the caller has one; a request is matched on its `branch` as
well, so a request made before the run's line carried a PR still pins.

### 2. Filing — `asf/workers/lifecycle.py`

```python
#: where a pinned branch's leftovers are kept instead of being committed onto it (F-0294)
LEFTOVER_PREFIX = 'refs/asf/leftovers'


def file_leftovers(product, wt, branch, why, repo=None, now=None):
    """File what a finished session left uncommitted in ``wt`` under ``LEFTOVER_PREFIX`` and
    leave the worktree clean, without moving ``branch`` (F-0294). ``(ok, ref, line)``.

    ``why`` is :func:`asf.merge_queue.head_pinned`'s clause — the reason the head may not move,
    said in the line. Nothing is removed from the worktree until the ref resolves to a commit
    whose tree holds every path ``git status`` listed.
    """
```

The order is the whole of the safety argument, and nothing in it may be reordered:

1. `git status --porcelain --untracked-files=all` in `wt`. Empty → `(True, '', '')`, nothing to
   do. Otherwise the listed paths are *the set*, remembered for step 4.
2. The commit is built beside the worktree, never in it: a scratch `GIT_INDEX_FILE`,
   `git read-tree HEAD`, `git add -A`, `git write-tree`, then `git commit-tree <tree> -p HEAD`
   with
   ```
   leftover(<branch>): the session ended with this uncommitted — filed off the branch (F-0294)

   Its head is pinned: <why>. Committing it here would move the head and drop the batch
   (B-0094 would have committed it onto <branch>).

   ASF-Leftover-Of: <branch>
   ASF-Leftover-Head: <HEAD sha>
   ASF-Pinned-By: <why>
   ```
   HEAD, `refs/heads/<branch>` and the worktree's own index are untouched (C9).
3. `git update-ref <LEFTOVER_PREFIX>/<branch>/<YYYYmmddTHHMMSSZ> <sha>`, in the repo's common
   git dir, so the ref outlives the worktree. `refguard.refusal(ref, …)` is asked first, as
   `recover_stray` asks it (P9); a refused ref refuses the filing.
4. Verify before anything is destroyed: `git rev-parse <ref>^{commit}` resolves, and
   `git diff --name-only <sha>^ <sha>` covers every path of step 1. A gap refuses the filing —
   `(False, '', line)`, the worktree untouched, and the caller falls back to today's hold.
5. Only now the tree is cleaned: `git checkout -- .` for the tracked modifications,
   `git clean -fd` for the untracked (no `-x`: an ignored file was never a leftover, C3).
6. `gitpush.push(['-q', 'origin', f'{sha}:{ref}'], repo, refs_only=True, guard=…,
   timeout=gitpush.push_timeout(product.conventions))`, then `git ls-remote origin <ref>` to
   confirm, exactly as `recover_stray` does. A refusal or a gap is named in the line and leaves
   `ok` true: the local ref already holds everything (C6).

The line, for the health pass to print:

```
filed 3 leftover file(s) of worker/T-0724 to refs/asf/leftovers/worker/T-0724/20261008T091500Z
 — its head is pinned: it is a member of refs/asf/mq/1 in the merge queue; the head stands at
 537670860 (push: ok)
```

### 3. The branch in `publish_gap` — `asf/workers/health.py`

`asf/workers/health.py:499-503` becomes, with everything around it unchanged:

```python
if ev.uncommitted and not ready:   # F-0176: the ruling ruled on the committed HEAD
    why = merge_queue.head_pinned(env.state_dir(product), branch, (run.get('pr')))
    if why:   # F-0294: a batched or land-requested head must not move for a leftover
        ok, ref, line = lifecycle.file_leftovers(product, wt, branch, why)
    else:
        ok, line = lifecycle.commit_leftovers(wt, branch)  # B-0094
    if not ok:
        return reason, ev, line
    lines.append(line)
    ev = lifecycle.gather(product, run, alive=alive, worktree=wt, status=status)
```

What the pass then does, with nothing else changed: the re-`gather` reads `ev.uncommitted == 0`
and a HEAD that did not move, so `ev.unpushed` is 0 and `ev.head_on_remote` is true (the branch
has a PR), and `publish_gap` returns at its existing `if not (ev.unpushed or (ev.remote_sha and
not ev.head_on_remote))` with the line and the reason it was given. The caller's `judge` sees a
clean tree against a pushed head and reads `finished`. No publish, no head move, no correction —
and `judge` in the merge queue finds the member's head where it left it, so the batch stands.

`merge_queue` is imported locally in the function, as `lane.land_requested` imports it
(`asf/harvest/lane.py:1746`): the merge queue imports the lane, and the lane imports health.

### 4. The record sync finishes what it owns — `asf/tick/shadow.py`

`sync_operator_checkout`'s dirty-tree block (`:231-236`) gains one question ahead of it:

```python
dirty = _sh(['git', 'status', '--porcelain', '--untracked-files=no'], cwd=repo,
            check=False).stdout
if dirty.strip():
    rels = _finishable(repo, dirty)
    if rels is not None and _commit_staged_writes(repo, rels, out):
        ahead += 1            # the sync's own commit joins the stranded ones
    else:
        _say_dirty(repo, ahead, behind, out)
        return False
_drop(repo, DIRTY_MARKER)
```

```python
def _finishable(repo, porcelain):
    """The relative paths of a dirty record checkout the sync may finish itself, or None.

    A tree is the sync's to finish only when *every* entry is a staged change (an index status
    of ``A``, ``M`` or ``D`` with a blank worktree column) to a path under
    :func:`asf.record.tree.record_paths` — a record writer's own interrupted work, already
    shaped by its writer. One unstaged edit, one path the record does not own, one rename and
    one unmerged entry make the whole tree the operator's, as it was before F-0294: nothing is
    committed and nothing is reset.
    """
```

```python
def _commit_staged_writes(repo, rels, out):
    """Commit the staged record writes ``rels`` the checkout was left holding (F-0294).

    The derivation is re-run first and staged with them (``do_index`` then ``git add -u``, as
    :func:`_rederive_index` already does mid-rebase), so the record pre-commit (``asf check
    --staged``) sees a record whose ``index.json`` matches its cards. Committed signed off, as
    the factory identity (:func:`factory_identity`). A commit the pre-commit refuses leaves the
    tree exactly as it arrived — still staged, nothing reset — and is named. True when it
    committed.
    """
```

The subject: `record: a staged record write a prior run left behind, committed by the tick
(F-0294)`. The commit then falls into `_rebase_and_push`, which was already going to run for the
`ahead` commits (P11), and the pass ends on the two lines it already prints:

```
record: committed 2 staged record write(s) a prior run left behind
record: pushed 3 stranded commit(s)
```

### 5. The cadence — `asf/tick/shadow.py`

`DIRTY_MARKER`'s content becomes JSON and is read back:

```json
{"at": "2026-10-07T21:16:04Z", "said": "2026-10-07T21:16:04Z", "what": "2 ahead, 1 behind"}
```

`_say_dirty(repo, ahead, behind, out, now=None)` prints when the marker is absent, unparseable
(an old plain-text one counts as said now, and is rewritten), or `now - said >=
record.dirty_say_hours` hours — then updates `said`, keeping `at`. `at` is what the age in the
line is measured from. Clearing is unchanged: `_drop(repo, DIRTY_MARKER)` once the tree is
clean. The line:

```
record: /path/to/record not fast-forwarded — working tree has local changes that are not the
 tick's to finish (2 ahead, 1 behind; dirty for 3 h 12 m; said again every 1 h)
```

`record.dirty_say_hours` is registered in `config_keys.KNOWN_CONFIG_KEYS` and in `TYPED` as
`(INT, 1, None)`, and documented in `docs/config.example.yaml` under a new `record:` block
(P13). Unset or malformed → 1, the code's own default.

## Records

| what | written where | shape |
| --- | --- | --- |
| a filed leftover, kept | `refs/asf/leftovers/<branch>/<YYYYmmddTHHMMSSZ>` in the product repo, and the same ref on origin | one commit parented on the head the session left, carrying `ASF-Leftover-Of`, `ASF-Leftover-Head` and `ASF-Pinned-By` trailers |
| a filed leftover, on the run | the session ledger line, via `pool_mod.update_session(product, job, leftovers=…)` | `{'ref', 'sha', 'files': <n>, 'why', 'at', 'pushed': bool}` — written once, when the block changes, as `run['mechanical']` is (`asf/workers/health.py:512-517`) |
| a filed leftover, on the pass | one health line, through `publish_gap`'s existing `lines` | `filed <n> leftover file(s) of <branch> to <ref> — its head is pinned: <why>; the head stands at <sha> (push: ok\|refused: <what>)` |
| a filing that was refused | the same line, with `ok` false and the reason unchanged | `<branch> leftovers not filed: <what> — left uncommitted` (the hold a refused `commit_leftovers` already is) |
| a staged record write the sync finished | one commit on the record trunk | `record: a staged record write a prior run left behind, committed by the tick (F-0294)`, signed off, authored as `factory_identity()` |
| a dirty record checkout | `.git/asf-record-dirty` in the checkout | `{'at', 'said', 'what'}` JSON; `at` is when it was first seen dirty, `said` when the line last went out |

No card is minted, no Decision is recorded, no event kind is added, and no `NEEDS OPERATOR`
stands: both halves are a behaviour change inside the factory, and the one new tunable is a
registered config key with the code's own default.

### S-76554: The pin is readable from state before any leftover is committed

- [ ] `merge_queue.head_pinned(state_dir, branch, pr)` returns `''` for a branch no batch holds and no request names
- [ ] it returns a clause naming the batch ref for a branch that is a member of a batch in the chain
- [ ] it returns a clause naming the PR for a branch whose PR number is in `land-requests.json`, and for a request matched on its `branch` with no `pr` passed
- [ ] batch membership wins when both hold, and an unreadable or absent state file is no pin
- [ ] it opens no socket: `python3 -m unittest -v tests.test_leftover_hold.HeadPinned tests.test_merge_queue`

### S-76555: A pinned branch's leftovers are filed off the branch and the head never moves

- [ ] `lifecycle.file_leftovers` on a worktree with tracked modifications and untracked files leaves `refs/asf/leftovers/<branch>/<stamp>` resolving to a commit parented on the session's HEAD whose diff covers every path `git status` listed
- [ ] `refs/heads/<branch>` and `HEAD` are the same shas after the call as before it
- [ ] the worktree is clean afterwards, and a git-ignored file in it is untouched
- [ ] a ref that cannot be written, or a verify that finds a gap, refuses the filing and leaves the worktree exactly as it was
- [ ] a refused push leaves the local ref, names the refusal, and still returns ok
- [ ] `python3 -m unittest -v tests.test_leftover_hold.FileLeftovers`

### S-76556: The run and the pass record where the leftovers went

- [ ] `publish_gap` on a pinned branch with uncommitted files files them, publishes nothing, and returns a reason the caller's `judge` reads as `finished`
- [ ] the branch head on origin is unchanged, and no `wip(` commit exists on the branch
- [ ] the run's ledger line carries a `leftovers` block with the ref, the sha, the file count, the pin's reason and the push's outcome, written once
- [ ] the same run on an unpinned branch still goes through `commit_leftovers` and publishes, exactly as B-0094 does today
- [ ] `python3 -m unittest -v tests.test_leftover_hold.PublishGapUnderAPin tests.test_lifecycle -k leftover`

### S-76557: The record sync finishes a staged record-only tree instead of waiting for a hand

- [ ] a record checkout holding only staged changes under `record_paths()` is committed by the sync, signed off as the factory identity, with `index.json` re-derived and staged alongside
- [ ] that commit is then rebased onto `origin/<trunk>` and pushed by the path that already exists, and the checkout ends level with origin and clean
- [ ] a tree with one unstaged edit, one path outside `record_paths()`, one rename or one unmerged entry is left alone and named — nothing committed, nothing reset
- [ ] a commit the record pre-commit refuses leaves the tree staged as it arrived, and says so
- [ ] `python3 -m unittest -v tests.test_operator_checkout_sync`

### S-76558: A dirty tree the sync cannot finish is said again, with its age

- [ ] the dirty marker holds `at`, `said` and `what`; an old plain-text marker is read as said now and rewritten, never crashed on
- [ ] the line is printed again once `record.dirty_say_hours` has passed since `said`, and carries how long the tree has been dirty since `at`
- [ ] within the interval the pass is silent, as it is today
- [ ] the marker is dropped the moment the tree is clean, and `record.dirty_say_hours` is in `KNOWN_CONFIG_KEYS`, in `TYPED` and in `docs/config.example.yaml`
- [ ] `python3 -m unittest -v tests.test_operator_checkout_sync tests.test_config_keys`
