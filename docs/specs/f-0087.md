# F-0087 — failure-class invariants, and the dogfood tick walks the failure paths

The card is the requirement. Each Bug so far was fixed with a failing-first test, so that exact
defect cannot come back. A different defect of the same kind still can. This spec turns each of
the card's six classes into one invariant test. Each test is written to also catch *the next
member* of its class: a census test fails when a new command, a new push, a new env variable or
a new state appears without a test. It also makes the sample product's tick in CI walk three
failure paths, and adds a weekly measure to the scorecard.

`7c8c756` (on `origin/main`, the base of this branch) already landed the lane state machine
under this Feature's id (`asf/workers/lifecycle.py`, `tests/test_lifecycle.py`,
`docs/design/lane-state-machine.md`). Two classes, registry semantics and most of branch
lifecycle, therefore hold today. This spec names the tests that hold them and specifies what is
still missing.

## 1. Decisions

### What still fails the card, and this spec fixes

1. **Nothing tests that every transition is walked.** `StateMachineInvariants` checks the shape
   of `TRANSITIONS` (every state has a successor). It does not check that every edge is ever
   taken, or that what `derive` produces over a run's life only moves along edges. The unpushed
   hold is an example: `ended(failed: not pushed)` → `held` happens (`health` holds it), yet
   `TRANSITIONS[ENDED]` is `(PUSHED, REAPED, LAUNCHED)`, which has no `HELD`.
2. **The suite is hermetic only in `ASF_HOME`.** `tests/test_00_home.py` replaces `ASF_HOME`, and
   only when it is not under the temp dir. It leaves `ASF_PRODUCT`, `ASF_JOB`,
   `BACKLOG_ID_RANGE`, `BACKLOG_ROOT`, the git config and every other variable asf reads as they
   are. A foreign `init.defaultBranch` is guarded in one fixture (B-0038), not suite-wide.
   CI never runs the suite under `env -i` or under an operator's variables.
3. **The harvest gate strips three variables by name** (`CALLER_IDENTITY_VARS`). asf reads
   eleven (listed under D3). A new one leaks by default.
4. **No path matrix exists.** Six commands (`new`, `check`, `index`, `ingest`, `stale`,
   `file-bugs`) take no `--product` and act on the cwd, so run from a product repo or from the
   temp dir they write there. No command prints `repo:`. `record:` is printed by
   `resolve_record` only. The card cites "the audit's matrix", but no audit document is in the
   tree (`docs/` has none); the matrix is built from the CLI's own parser (D6).
5. **A correction brief does not end with the closing paragraph.** `stall.correct_once` writes
   `original + CORRECTION_HEAD + error`. That puts the correction *after* the `REPORT` block,
   whose own text says *"Finish with this, and nothing after it"*. `wave.default_brief` (the
   `asf workers wave` default) has no tail at all.
6. **Two push paths lose the race.**
   - `harvest.push_ff` fetches (line 354), then pushes (359). If origin moves in between, the
     push is refused and `land_ff` prints `held <branch>: push to main refused`. It does not
     retry and writes no correction.
   - `land_ff` deletes the landed branch with a bare `git push origin --delete` (658). A commit
     pushed to that branch after harvest fetched it is deleted with it.
   - Neither path, nor `push_branch`, has any test that moves origin between the fetch and the
     push. The only mover is `test_tick`'s nested `commit_then_origin_moves`.
7. **The dogfood tick walks only the happy launch.** `tests/test_sample_product.py` runs one tick.
   `FakeRuntime` writes a log line and nothing else: it cannot commit or push. `spawn` builds a
   new runtime per launch, so the script restarts at entry 0 every time.
8. **Nothing measures the classes.** The tick line's `merges` is never incremented. Harvest
   writes no event. The scorecard reads `ci`, `sessions` and `ticks` only, and nothing counts
   Bugs filed, landings or rounds.

### Preconditions

- `7c8c756` is on `main`: `lifecycle.fold`, `derive`, `hold`, `judge`, `TRANSITIONS`,
  `by_branch`, `corrections`. Every design point below builds on it.
- B-0032 is on `main`: a red gate or a rebase conflict is a correction to the branch's session,
  not a filed Bug. That is what makes held → correct → land a walk the sample can do.
- B-0039 is on `main`: a correction relaunches cold under its own job and log, in the held
  branch's worktree (B-0046).
- A CI change to `.github/workflows/tests.yml` is pushed by a worker. If the credentials a
  worker pushes with lack the `workflow` scope, the push is refused and an operator pushes that
  commit (see the report's NEEDS OPERATOR).
- The sample's S1 card `B-0001` names `tests/test_count.py::test_empty`, which `sample/repo`
  does not yet have. The walks' scripted sessions add it.

### Choices

| # | Chosen | Against | Why |
|---|---|---|---|
| D1 | One invariant test per class, **plus a census** that fails when a new member of the class appears untested: a new `TRANSITIONS` edge, a new env variable read, a new CLI command, a new `git push` call site, a new brief kind | One test per class, enumerating today's members | The card's point is *the next kind*. A test that lists today's members passes when tomorrow's command or push site is added without one. The census compares the list against the code, so a new member fails until it is tested. |
| D2 | Transition coverage is two tests: (a) every edge in `TRANSITIONS` has a named `(run, evidence)` pair whose `derive` is the source state and a successor pair whose `derive` is the target, walked in the test; (b) over generated walks (a registry grown one line at a time, evidence drawn from `evidences()`), each change of derived state from one prefix to the next is an edge in `TRANSITIONS`. Edges (b) finds are added to the table. | Hand-listing transitions in the design note only | (a) proves each edge can happen; (b) proves nothing happens that is not an edge. Together they catch `ENDED → HELD` (the unpushed hold) today. |
| D3 | `asf.env.OPERATOR_ENV`: one tuple of every variable asf reads, today `ASF_HOME, ASF_PRODUCT, ASF_JOB, BACKLOG_ID_RANGE, BACKLOG_ALLOW_MINT, BACKLOG_ROOT, ASF_CORE_RULES_DIR, BACKLOG_PRODUCT_REPO, ASF_DEFAULT_BUG_EPIC, PRH_TICK_S, PRH_CACHE_DIR`. With one list and a census, adding a variable means listing it, and both the suite and the gate strip it from then on. |
| D4 | The suite strips all of `OPERATOR_ENV` except `ASF_HOME`, which it replaces with its own home. That home is marked by a file `.asf-tests-home`, and an inherited `ASF_HOME` is reused only if it carries the marker (`ASF_TESTS_HOME` still wins) | Keep "reuse any `ASF_HOME` under the temp dir" | An operator whose home sits under `/tmp` would have it reused, which is B-0043 again. The marker is what subprocess suites (`test_sample_product`, the gate running asf's own suite) need to share one home, and nothing else carries it. |

A census against the parser catches a new command, which a copied list cannot (D1). |
| D7 | The first line is `record: <abs path>`, `repo: <abs path>`, or `record: <abs> · repo: <abs>`, whichever the command touches. It is printed once, by `cli._main`, from a table `WHERE = {command: ('record',) / ('repo',) / ('record', 'repo')}` before the command runs. With `--json` it goes to stderr | Each command prints its own line | One place means "first line" cannot drift, and a command missing from `WHERE` fails the census (D6). JSON on stdout must stay parseable (`asf next --json` feeds the sample test). |
| D8 | `new`, `check`, `index`, `ingest`, `stale`, `file-bugs` take `--product` and resolve through `resolve_record`, as B-0050 did for `groom`. `doctor` and `scheduler` stop being handed the cwd as root and use the product's record. `init` with no `--repo` from a cwd that is not a git repo exits 2 with one `NEEDS OPERATOR` line and creates nothing | Leave the cwd commands as they are and exempt them | They are the same defect as B-0050, in the six commands it did not reach. | D9 | "Creates nothing under /tmp" is tested as: cwd = a fresh empty `mkdtemp()`, `TMPDIR` = a *different* fresh dir, and after the command the cwd is still empty | Assert on the real `/tmp` | The real `/tmp` is shared with every other process on the host, so a test on it would be flaky. | D13 | Race outcomes required: a raced `push_ff` returns `not_ff=True` after a re-fetch shows origin moved, so `land_ff` rebases once more and lands. | D14 | A push-site census: every `'push'` argument inside a `git` argv in `asf/**/*.py` (found through the AST) must map to a race test in `tests/test_push_races.py` `SITES` | A list in a comment | D1. | D15 | `FakeRuntime` script entries gain `job` (an `fnmatch` pattern), `write` (`{relpath: text}` written into the job's worktree), `commit` (a message; stages everything and commits with `-s`) and `push` (defaults to true when `commit` is given, false otherwise; `push: true` alone pushes what is already committed). | D16 | A walk ticks until its outcome, with a bound (6 ticks). It asserts end state and the tick's tables, not which tick each step happened in | Assert tick by tick | The order within a tick (health → wave → prs → harvest) decides whether a landing takes 2 or 3 ticks. That is scheduling, not the invariant. The bound still catches a lane that never lands. |

A week's window read daily shows the trend as it moves. `created` exists on filed Bugs, and the History line covers cards written by hand. |

## 2. The design

### 2.1 Branch lifecycle: every transition walked (S-7600)

`tests/test_lifecycle.py` gains `TransitionCoverage`:

- `EDGE_FIXTURES = {(src, dst): (run_src, ev_src, run_dst, ev_dst)}`, one entry per edge.
  `test_every_edge_is_walked` asserts `set(EDGE_FIXTURES) == {(s, t) for s, ts in
  TRANSITIONS.items() for t in ts}` and, for each entry, `derive(run_src, ev_src).name == src`
  and `derive(run_dst, ev_dst).name == dst`, with `run_dst` reached from `run_src` by appending
  registry lines only (the registry is append-only).
- `test_generated_walks_only_step_along_edges`: for seeds 0..99, grow a registry one line at a
  time (`generate`'s lines, in order). At each prefix fold with `lc.fold`, derive every job's
  latest run under each evidence from `evidences()` that is consistent with the prefix, and
  assert that consecutive distinct states `(a, b)` of one run satisfy `b in TRANSITIONS[a]`.

`asf/workers/lifecycle.py`: `TRANSITIONS[ENDED]` gains `HELD` (the unpushed hold), and any other
edge the walk finds is added with a comment naming its cause. The design note's diagram and
table gain the same edge.

### 2.2 The suite and the gate are hermetic (S-7601, S-7602, S-7603)

`asf/env.py`:

```python
#: Every environment variable asf reads (census: tests.test_env.EnvCensusTest). The suite and
#: the harvest gate strip all of them but ASF_HOME (F-0087 D3).
OPERATOR_ENV = ('ASF_HOME', 'ASF_PRODUCT', 'ASF_JOB', 'BACKLOG_ID_RANGE', 'BACKLOG_ALLOW_MINT',
                'BACKLOG_ROOT', 'ASF_CORE_RULES_DIR', 'BACKLOG_PRODUCT_REPO',
                'ASF_DEFAULT_BUG_EPIC', 'PRH_TICK_S', 'PRH_CACHE_DIR')
SYSTEM_ENV = ('PATH', 'HOME', 'TMPDIR', 'PYTHONPATH', 'GIT_DIR', 'GIT_WORK_TREE', 'GIT_INDEX_FILE')
```

`tests/test_00_home.py` `hermetic_home()`, with `tests/__init__.py` calling the same function
rather than repeating it:

1. `ASF_TESTS_HOME` if set, else the inherited `ASF_HOME` if it holds `.asf-tests-home`, else a
   new `mkdtemp(prefix='asf-tests-home-')`. The marker is written into whichever is chosen.
2. Every `OPERATOR_ENV` name but `ASF_HOME` is popped from `os.environ`.
3. `<home>/gitconfig` is written (D5). `GIT_CONFIG_GLOBAL` points at it and
   `GIT_CONFIG_NOSYSTEM=1` is set.
4. `asf.env.ASF_HOME` is patched as today.

`asf/harvest/harvest.py`: `CALLER_IDENTITY_VARS` becomes
`tuple(v for v in env.OPERATOR_ENV if v != 'ASF_HOME')`. The existing comment's ruling stays:
`ASF_HOME` is the operator's home, not an identity, and asf's own gated suite replaces it
(it has no marker, D4).

`tools/hermetic.sh <leg>` runs `python3 -m unittest discover -s tests` from the repo root:

- `clean`: `env -i PATH="$PATH" HOME="$(mktemp -d)" LANG=C.UTF-8 python3 -m unittest discover -s tests`.
- `operator`: builds a leaky operator home under `mktemp -d`:
  - `config.yaml` with `default_product: leaky`;
  - `products/leaky.yaml` pointing `repo_dir`/`backlog_dir` at paths that do not exist;
  - a `gitconfig` with `[init] defaultBranch = trunk` and a `[user]`.

  It then exports `ASF_HOME=<it>`, `ASF_PRODUCT=leaky`, `ASF_JOB=leak-job`,
  `BACKLOG_ID_RANGE=S:1-1`, `BACKLOG_ROOT=/nonexistent` and `GIT_CONFIG_GLOBAL=<its gitconfig>`,
  and runs the suite. Afterwards `find "$leak_home" -newer "$stamp"` must print nothing, else it
  prints `hermetic: the suite wrote into the operator's home: <paths>` and exits 1.
- The script's last line is the suite's own summary, and it exits with the suite's code.

`.github/workflows/tests.yml` gains a job:

```yaml
  hermetic:
    runs-on: ubuntu-latest
    strategy:
      matrix:
        leg: [clean, operator]
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: "3.12"
      - run: python -m pip install -e .
      - run: bash tools/hermetic.sh ${{ matrix.leg }}
```

### 2.3 Path resolution: the matrix (S-7604)

- `asf/cli.py`:
  - `WHERE` (D7) and a `where_line(args, product)` that `_main` prints before dispatch. It goes
    to stdout, or to stderr when `getattr(args, 'json', False)`.
  - `--product` (via `env.add_product_arg`) and `resolve_record` for `new`, `check`, `index`,
    `ingest`, `stale`, `file-bugs` (D8).
  - `doctor` and `scheduler` get the product's record, not `root`.
- `asf/init.py`: with `--repo` absent and a cwd that is not a git work tree, it prints
  `NEEDS OPERATOR: <cwd> is not a git repo — run from the product repo or pass --repo <path>`,
  exits 2, and writes nothing.
- `tests/sample_fixture.py` holds the sample setup that `tests/test_sample_product.py` has
  today: copy, `_publish`, `_fill`, env, the offline `gh`, and `asf()`. That test, the path
  matrix and the walks (2.6) all use it. `SampleProductTest` keeps its tests unchanged.
- `tests/test_path_matrix.py`:
  - `MATRIX`: one row per command, `(argv, expected_exit)`, for example
    `('tick', '--product', 'sample')`, `('harvest', '--product', 'sample', '--dry-run')`,
    `('workers', 'health', '--product', 'sample')`, `('new', 'bug', '--product', 'sample', …)`.
    The plan fixes every row's argv against the parser.
  - `EXEMPT = {'upgrade', 'plugin'}`.
  - `test_every_command_is_in_the_matrix`: the parser's commands equal `MATRIX ∪ EXEMPT`, and
    every `MATRIX` command is in `cli.WHERE`.
  - `test_from_a_foreign_cwd`: one `subTest` per row. cwd is a fresh `mkdtemp()` and `TMPDIR` is
    another (D9). It checks the exit code, that the first line of stdout (or of stderr for
    `--json`) matches `^(record|repo): /`, that the named paths are the sample's record/repo, and
    that the cwd is still empty afterwards.

### 2.4 Worker behaviour: the tail is last (S-7605)

- `asf/briefs/build.py`:
  - `TAIL_HEADING = '## The heartbeat, the marker, and the report'`.
  - `ends_with_tail(text, ctx=None) -> bool`: the last `## ` heading is `TAIL_HEADING`. With
    `ctx`, the text from it to the end must equal `render(TAIL, ctx).strip()`.
  - `tail_for(item_id, kind, branch) -> str`: the rendered tail, for callers outside `build()`.
- `asf/workers/stall.py` `correct_once`: splits the original at `TAIL_HEADING` and writes
  `head.rstrip() + CORRECTION_HEAD + error.rstrip() + '\n\n' + tail` (D11).
- `asf/workers/wave.py` `default_brief`: its one line plus `'\n\n' + tail_for(row.item,
  row.kind or 'coder', row.branch or '')`.
- `asf/workers/spawn.py`: `write_brief` raises
  `SpawnError('brief for <job> does not end with the closing section — refusing to launch')`
  when `not ends_with_tail(text)`.
- `tests/test_briefs.py` `BriefEndingTest.test_every_brief_ends_with_the_tail`: for every
  `KINDS` entry × {no correction, correction `'FAIL: t'`} × {as built, through
