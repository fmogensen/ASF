# F-0341 — a test the product does not run proves nothing

A `Proves:` trailer is how a Task says which Story acceptance line its test proves, and the tick of
that line is the one thing that makes a Story done — "no test, no done" (`asf/proves.py:484`). The
factory already refuses two kinds of claim before it ticks anything:

* a claim whose own prose qualifies it (`only`, `partial`, `half`, …) is `partial claim`, because a
  line is proved whole or it is not proved (F-0257);
* a claim naming an id the record holds no Story card for is `unknown story`, because a spec that
  cited ids nobody minted cannot be proved against them (F-0285).

There is a third kind, and it is the one that hurts most: a claim naming a test the product's CI
**does not run**. A quarantined test is skipped by construction. Nothing executed it on the sha the
claim landed on, so nothing about it went green, so the line it names is not proved — and today the
factory ticks it anyway, writes `ingest: proved line N` into the Story's `## History`, and lets the
Story and its Feature close over a test that is switched off. That is the worst available failure:
the record says *proved* with more confidence than any unproved line carries, and the only way back
is `asf untick` by hand.

This card closes it. `asf/proves.py` gains the list and the predicate; the product says where its
quarantine list lives (`conventions.ci.quarantine_file`); and the pass that reads landed claims
reads that file **at the sha the claim landed on**, so the question asked is the right one — *was
this test quarantined when this claim merged?* — and not *is it quarantined now?*

Nothing here is about ASF's own flake quarantine (`asf/flake.py:75`). That quarantines a **CI job**
in ASF's own state file for a number of days, and it is a different fact about a different subject
living in a different place. The file this card reads is the **product's**, in the product's repo,
listing the **tests** the product's own CI skips — a `pytest` deselect list, a `.mocharc` exclude
file, a plain list a test runner reads. ASF never writes it and never decides what is in it.

### In

* `asf/proves.py`: the refusal name, the quarantine-list parse, the match predicate, and a
  `quarantined=` keyword on `parse_all` beside the existing `known=`.
* `asf/conventions.py`: `ci.quarantine_file`, documented in the module docstring's `ci:` block,
  read by one accessor, with **no default path**.
* `asf/evidence/evidence.py`: `landed_proves` reads the product's quarantine file at each sha it
  holds a claim for, in one batch, and passes the list to the parse for that sha.
* `tests/test_proves.py`, `tests/test_conventions.py`, `tests/test_evidence.py`,
  `tests/test_no_test_no_done.py`: the cases, each in the module that owns the file it covers.

### Out

* **The pull-request body.** `harvest.lane.commits_note` renders `## Proves` / `## Not proved` for
  an **open** pull request, where no merge sha exists yet. Reading the quarantine file at the branch
  head or the trunk tip instead is a different fact from the one this card names, and a body
  re-rendered every lane pass would flip as either moved. The refusal still reaches a human, on the
  Story card's `evidence:` lines (P9, `## Records`) — the surface where the tick is decided. The
  body is the natural next card, and it is not this one.
* **The pre-push rule.** `asf/rules/story_proof.py` runs `proves.validate` against the working tree
  before a session pushes. It could refuse a quarantined claim earlier — and it would be reading the
  worktree's quarantine file, which is a third sha again. `validate`'s signature and its five
  problem words are untouched here.
* **Writing or maintaining the quarantine file.** ASF never adds to it, never expires an entry and
  never opens a card about one. Which tests a product quarantines is the product's decision, taken
  in the product's repo; this card only reads the answer.
* **ASF's own flake quarantine** (P10): no change to `asf/flake.py`, its state shape,
  `ci.quarantine_days`, `ci.reference_class`, `flake.status_cell` or `views.status.quarantine_cell`.
* **Directory and glob entries.** An entry is a test id — a path, optionally `path::node`. A
  quarantine file naming `tests/e2e/` or `tests/**/slow_*.py` matches nothing here. Named because it
  is the obvious extension and because silently half-supporting it would be worse than not: a glob
  that looks like it works and does not is how a quarantined test gets credited anyway.
* **Path-suffix matching.** `tests/a.py` and `a.py` are two different ids. Both sides are
  repo-relative as the product writes them, compared after the one normalisation D3 names.
* **`markers=` wiring, `unproved`, `tick`, `untick`, `validate`, `proved_lines`.** Untouched.
* **Any record shape.** No new card, no new `## History` grammar, no ledger event, no state file, no
  metrics row, no doctor row, no `config_keys` entry (`ci.quarantine_file` is a product convention,
  not operator config), no `asf` subcommand.

### Preconditions the work depends on

1. The product declares `conventions.ci.quarantine_file` as a repo-relative path. Unset — which is
   every product today (P3) — means nothing is quarantined and no claim is refused for it.
2. The merge sha a claim landed on is in the product checkout. It always is, because `ancestry`
   already required it before the claim was read at all (P7).
3. The quarantine file is a list of test ids, one per line, in the same spelling a `Proves:` claim
   uses for its test. A product whose claims say `tests.test_x` (module path) and whose quarantine
   file says `tests/test_x.py` (file path) matches nothing — the two sides must agree, and this card
   does not translate between spellings.

## The design

Three files in the package, four test modules. No new module, no new command, no signature change
outside `parse_all` and one test fixture helper.

### 1. `asf/proves.py` — the list, the predicate, the refusal

The sixth word of the `why` vocabulary, beside the five of P1:

```python
#: Why a claim whose named test the product's quarantine file lists proves nothing (F-0341): a
#: quarantined test is one the product's CI does not run, so no run of it made its line green.
QUARANTINED = 'quarantined test'
```

The list, pure over the file's text — which file it was, and at which sha, is the caller's (C6):

```python
#: A quarantine file's comment: a whole line, or the tail of one after whitespace. A ``#`` with no
#: space before it is part of the id (a test name may carry one).
_QUARANTINE_COMMENT_RE = re.compile(r'(?:^|(?<=\s))#.*$')
#: The list marker a yaml sequence of ids carries (``- tests/a.py``), stripped so one parse reads
#: a bare list file and a yaml list of strings alike (C3).
_QUARANTINE_MARKER_RE = re.compile(r'^[-*+][ \t]+')


def quarantine_entries(text):
    """The test ids a product's quarantine file lists, in file order, duplicates collapsed.

    One id per line: a ``#`` comment dropped, a leading list marker and surrounding quotes
    stripped, a leading ``./`` stripped, blank lines yielding nothing (C3). A line this parse
    cannot make an id of yields a token that matches nothing, never an exception: an unreadable
    quarantine file refuses no claim (C9)."""
```

The predicate, one rule in both directions (C4):

```python
def quarantined_by(test, entries):
    """The first entry of ``entries`` that quarantines ``test``, else ``''``.

    An entry quarantines a claim's test when the two name the same file and neither names a node
    outside the other's: the same id; an entry naming the file alone against a claim on a node in
    it; an entry naming a node against a claim on the file whole; either one a ``::``-boundary
    prefix of the other. A line is proved whole or it is not proved (F-0257), and a named test one
    of whose cases the product does not run is not a whole proof."""
```

and `parse_all` gains the third keyword, checked after the two that are already there (C2):

```python
def parse_all(text, markers=None, known=None, quarantined=None):
    ...
        if not refusal and quarantined:
            entry = quarantined_by(test, quarantined)
            if entry:
                refusal = f'{QUARANTINED}: {entry}'
```

`render_not_proved` is untouched and renders it already (P2). The module docstring gains a sentence
for the third refusal; the module stays pure — `quarantine_entries` takes text and `quarantined_by`
takes a list, so no product convention, no path and no git enters `asf/proves.py`.

### 2. `asf/conventions.py` — `ci.quarantine_file`

The docstring's `ci:` block gains the key, which is where this product documents one per field:

```
      ci:
        quarantine_file: tools/quarantine.txt   # the tests this product's CI does not run, one
                                  # id per line; a Proves: claim naming one is refused at the sha
                                  # it landed on (F-0341). Unset: nothing is quarantined
```

and one accessor beside the six of P4:

```python
    def quarantine_file(self):
        """``ci.quarantine_file``: the repo-relative path of the list of tests this product's CI
        does not run, read at the sha a claim landed on
        (:func:`asf.evidence.evidence.landed_proves`). ``''`` unless set — and ``''`` means the
        product quarantines nothing, so no claim is refused for it (C5, C9). No default: a
        path-shaped default here becomes a pattern ``check_conventions.sh`` refuses in every other
        module (P5), and a product that chose no quarantine file must not have claims refused
        against one."""
        value = self.map_of('ci').get('quarantine_file')
        return value.strip() if isinstance(value, str) and value.strip() else ''
```

No field on the dataclass, no module-level constant, no `MAP_CONVENTIONS` or `NESTED_FIELDS` entry,
no `validate_mapping` clause (P4). A product file that sets it loads today and is read after this.

### 3. `asf/evidence/evidence.py` — at the sha the claim landed on

One helper, beside `record_since`:

```python
def _quarantined_at(product, shas):
    """``{sha: (entry, ...)}`` — the product's quarantine file
    (``conventions.ci.quarantine_file``) as it stands at each of ``shas``, one ``cat-file
    --batch`` pair for the lot (P8). ``{}`` when the product names no quarantine file; a sha whose
    tree has no such file, or an empty one, maps to ``()`` and refuses nothing (C9)."""
```

and `landed_proves` in two phases (C7). Phase one is today's two loops with their last two lines
moved out — the merged pull requests in number order, then the trunk's `Proves:` commits — each
appending `(sha, text, task, pr, source)` to one list in the order it is read. Phase two is the one
blob read and the parse:

```python
    quarantined = _quarantined_at(product, {sha for sha, *_rest in pending})
    for sha, text, task, pr, source in pending:
        counted, claims_refused = proves.parse_all(text, quarantined=quarantined.get(sha))
        for claim in counted + claims_refused:
            add(claim, task, pr, sha, source)
```

`quarantined.get(sha)` is `None` for a product that names no file and `()` for a sha whose tree has
none — the same answer either way (C8). `add`, `seen`, the `refused` fill, the two sorts and the
returned dict are exactly as they are: for a product with no quarantine file this function answers
what it answers today, claim for claim and key for key, which is what keeps `LandedProvesTests`
green with no edit.

Nothing downstream changes. `discover` publishes `proves_refused` as it does (`:950`, `:968-969`);
`ingest.unproved_of` reads the new `why` because it reads whatever `why` says (P9);
`ingest.refused_claim_line` prints it; `ingest.tick_proven` never sees the claim, because a refused
claim is never in `ev['proves']`.

### 4. The test fixture

`tests/test_evidence.py::ProductRepo.product` gains one keyword so a case can set the convention
(P11), leaving every existing call identical:

```python
    def product(self, ci="gh-actions", prefixes=None, conventions=None):
        conv = dict(conventions or {})
        if prefixes:
            conv["branch_prefixes"] = prefixes
```

### What it looks like when it is there

The product's quarantine file, at the sha a claim merged on:

```
# tools/quarantine.txt — tests our CI skips. B-1204.
tests/test_upload.py::SlowPath       # times out on the small runner
- "tests/test_flaky.py"
```

A Task lands `Proves: S-124005 line 1 — tests/test_upload.py::SlowPath::test_resume` beside
`Proves: S-124005 line 2 — tests/test_parse.py`. The second ticks. The first does not, and the
Story card says why, where `asf ingest` writes its evidence:

```
evidence:
  - claim refused, line 1 not proved — quarantined test: tests/test_upload.py::SlowPath — T-1 (tests/test_upload.py::SlowPath::test_resume)
  - unproved line 1 — the resume path survives a restart (quarantined test: tests/test_upload.py::SlowPath)
```

The line stays `- [ ]`, `## History` gets no `proved line 1`, and the Story does not close.

| the proof entry | the Story card's `## History` | **Not written.** No `ingest: proved line N` for a refused claim, so `proves.proved_lines` never credits it and `asf untick` has nothing to reverse |

| the quarantine file | the product's repo | **Never written.** Read only, at one sha, through `cat-file` |
| `index.json`, the tables, the feeder rows, the ledger, the metrics | — | Unchanged. No derived section moves and no event is emitted |
| the product file | `conventions.ci.quarantine_file` | **New key, operator-set.** Unset in every product today (P3), and unset is the behaviour the factory has now |

## Stories

Two Stories, from this session's range `S:124005-124054`. Each is **declared** below as a
`### S-…: <title>` heading with its acceptance lines under it — that heading is what
`asf.record.idcheck.declared_stories` reads and what `asf.record.plan_tasks` mints the card from, so
a cited id with no declaration is a phantom and the plan citing it is refused whole.

Each acceptance line is one physical line of plain text with no backticks, on purpose: the reader is
line-anchored (`asf.record.idcheck.CHECKBOX` matches a single line) and `_prose` replaces every
inline code span with one space before parsing, so a wrapped line reaches the minted card truncated
and an identifier inside backticks reaches it missing.

They are independent in the one direction that matters: the first changes `asf/proves.py` and
`tests/test_proves.py` only and is provable with no product, no git and no record; the second adds
the convention and its one reader and is the only one that needs the git fixture. The second does
depend on the first's `quarantined=` keyword, so the plan should order them.

- S-124005: a claim whose named test the quarantine list holds is refused, and one whose test it does not hold is counted — acceptance: `python3 -m unittest tests.test_proves`
- S-124006: the product says where its quarantine list lives, and a landed claim is judged against that list at the sha it landed on — acceptance: `python3 -m unittest tests.test_conventions tests.test_evidence tests.test_no_test_no_done`

### S-124005: a claim whose named test the quarantine list holds is refused, and one whose test it does not hold is counted

Design §1. Pure text: no product, no convention, no git, no record.

- [ ] one parse of one text counts the claim whose named test the quarantine list does not hold and refuses the claim whose named test it does, which is the acceptance the card names
- [ ] a refused claim carries the reason quarantined test and names the entry that quarantined it
- [ ] a refused claim is never among the counted ones, so nothing that reads the counted half can tick its line
- [ ] the quarantine list is read one id per line, in file order, with duplicates collapsed
- [ ] a whole-line comment and the tail of a line after whitespace are dropped, and a blank line yields nothing
- [ ] a leading list marker and surrounding quotes are stripped, so a plain list file and a yaml list of strings read the same
- [ ] a leading dot-slash is stripped from both an entry and a claim before they are compared
- [ ] an entry naming a file quarantines a claim on that file and a claim on any node inside it
- [ ] an entry naming a node quarantines a claim on the file whole, because a named test one of whose cases does not run is not a whole proof
- [ ] an entry and a claim match only on a node-separator boundary, so an entry naming one case does not quarantine a claim on a case whose name merely starts with it
- [ ] an entry and a claim naming different files never match, and no path-suffix or glob match is made
- [ ] an empty quarantine list refuses nothing, and so does no list at all
- [ ] a claim that is both qualified in its prose and on a quarantined test is refused as a partial claim, because the claim's own words are read before any product file
- [ ] a claim on a story the record holds no card for is still refused as unknown story when both checks apply
- [ ] the refusal renders in the not-proved block with its reason and the test it refused, through the renderer that already exists
- [ ] the claim grammar, the partial-marker rules, the acceptance-bullet reader, the tick and the untick are unchanged

### S-124006: the product says where its quarantine list lives, and a landed claim is judged against that list at the sha it landed on

Design §2, §3 and §4.

- [ ] a product that names a quarantine file has that path read from its conventions, stripped of surrounding whitespace
- [ ] a product that names none reads as the empty string, and the empty string refuses no claim
- [ ] a value that is not a string, or is blank, reads as the empty string rather than raising
- [ ] the convention carries no default path, so the check that forbids a hardcoded convention finds no new pattern for it
- [ ] a merged pull request whose body claims a quarantined test has that claim refused, and a claim on a non-quarantined test in the same body counted
- [ ] a proof trailer on a trunk commit is judged the same way, from the same list
- [ ] the list is read at the sha the claim landed on: a claim that merged before the test was quarantined is counted, and one that merged at or after it is refused
- [ ] a sha whose tree holds no quarantine file refuses nothing, and neither does an empty one
- [ ] the quarantine file is read for every sha in one batch, with no new forge call and no new git process per claim
- [ ] a product that names no quarantine file gets back exactly what it gets back today, claim for claim, which is why the landed-claim suite passes unedited
- [ ] the refused claim reaches the evidence with its reason beside the line, the test, the task, the pull request and the sha
- [ ] the story card's acceptance bullet is not ticked and its history gains no proved-line entry
- [ ] the story card's evidence says the claim was refused and why, while the story is still active
- [ ] the unproved line names the quarantine as its reason rather than no proof, so the operator is sent to the claim and not to a missing test
- [ ] a story whose only claim is refused does not close, and neither does the feature above it
- [ ] the same claim on a test that is not quarantined ticks its line and says no refusal, which is the other half of the card's acceptance
- [ ] the ingest, the tick, the untick and the record's own writers are unchanged, because the refusal travels as data they already carry
