# F-0223 — the factory's largest failure class is the one it never named

The scorecard's top factory cause is `failure:failed`: **13 runs over 14 days, 6.5 a week against a
threshold of 5, $30.28 and 45.7 h spent on them.** It has stayed at #1 because the cause key is a
catch-all. Every other failure class in the register names something a person can act on —
`failed: not pushed`, `failed: empty branch`, `token cap`, `auth`, `permission`, `quota` — and each
was fixable *because it was named*. This one says only "failed".

It is the fallback branch of one expression, `asf/workers/lifecycle.py:1935`:

```python
sig = runtime_mod.failure_reason(ev.result)
...
return f'failed: {sig}' if sig else 'failed'
```

So a run reads bare `failed` under exactly one condition, and it is worth stating precisely, because
the whole of this spec follows from it:

> `runtime.result_ok(ev.result)` is False **and** `runtime.failure_reason(ev.result)` is None
> (`asf/workers/runtime.py:474-500`). `failure_reason` returns None only when the record carries no
> `asf.cap` and no `asf.run_cap`, matches none of the four `FAILURE_SIGNATURES`, and has no
> parseable typed REPORT. `result_ok` is False anyway. Therefore the *only* thing that can be
> false is the pair it tests first: **`rec['is_error']` is truthy, or `rec['subtype']` is not
> `success`.**

The runtime itself declared the error, in a structured field, on the result line — and the factory
throws that field away. `subtype` is read in exactly two places in the tree, and neither is this
one: `rec.get('subtype') == 'init'` when scraping the model (`runtime.py:431`, `tokens.py:117`,
`progress.py:183`), and the `subtype == 'success'` test inside `result_ok`. `grep -rn
'error_max_turns\|error_during_execution\|max_turns' asf docs` returns **nothing**. The factory has
no handling, no name and no record for any error the runtime raises about itself.

Naming it is necessary but it is not the whole card, because the bare reason also costs the work.
Two mechanisms drop it:

* **The branch is never published.** `publish_gap` opens with
  `result_ok = reason == lifecycle.FINISHED or (reason or '').startswith(UNPUSHED_REASON_PREFIXES)`
  and returns `reason, ev, None` when that is false (`asf/workers/health.py:396-400`). Bare `failed`
  is neither, so a dead run's commits are never pushed off its worktree.
* **The item is never sent back.** The ladder at `health.py:742-792` has an arm for `retry`, for
  `failed: empty branch`, for a parked question, and for `UNPUSHED_REASON_PREFIXES`. Bare `failed`
  matches none of them. The run is recorded `ended`, `rc=1`, and that is the end of it: no hold, no
  correction, no park, no round. The worktree is reaped later with the commits still in it.

At 45.7 h over 13 runs these are **3.5-hour sessions on average**, not instant crashes. They are
sessions that did most of a job and hit something the runtime called an error. Both the diagnosis
and the work are thrown away.

This spec names the failure from the field the runtime already wrote, stops abandoning the branch,
puts the item back in the correction loop that every other failure class already uses, and resumes
the one class of run that is not a failure at all — a session the runtime merely cut off.

### In

* Naming a bare-`failed` run's reason from the runtime's own structured result fields, recorded on
  the run row and folded into the cause card's detail line as sub-causes.
* Publishing the branch of a run that died mid-flight, on the same terms as an unpushed run.
* An arm in health's end-of-run ladder for a bare `failed` reason, so the item goes back instead of
  going nowhere.
* Resuming, once, a run whose result says the runtime cut the session off rather than that the work
  failed.

### Out

* **Renaming, splitting or regrouping the `failure:failed` cause key.** D1 — this is the decision
  the rest of the spec hangs on.
* Extending the `scheme` guard to `failure:` causes (P13). It is a real gap, but D1 means nothing
  here changes a `failure:` key, so this card does not need it and must not be the one to invent it.
  Named in Records as a follow-up, not built.
* The four `FAILURE_SIGNATURES` and the typed-REPORT path. They already name what they match; this
  card only covers what falls past them.
* `failed: not pushed`, `failed: empty branch`, the cap reasons, quota and the hook-refusal path.
  Untouched.
* Changing thresholds, `min_move`, `verify_weeks` or anything else in the scorecard's config.
* Raising the runtime's turn limit, or any change to how a session is launched. S-36553 resumes a
  cut-off session; it does not give sessions more room up front.

### How this card's own acceptance can honestly be met

The acceptance is `failure:failed` below 5 runs/week over the two weeks after landing, measured by
`diagnose.metric` against `is_dead`. D1 forbids the cheap way. What is left are the two honest ones,
and they are worth separating because only one of them is immediate:

* **S-36553 removes runs from the population outright.** A session the runtime cut off, resumed and
  finished, ends `finished`. It is never dead, in any window.
* **S-36551 + S-36552 remove runs retroactively, through P8.** A dead run's branch is published, the
  item goes back, the correction finishes the work, harvest lands the branch and sets `harvested` on
  the run — and `measure.ended_runs` then reads `landed=True` for it, so `is_dead` is false and it
  leaves the count in *every* window that reads it, including windows already past. This is not a
  trick: a run whose work reached the trunk was not a wasted run, and P8 is the tree's own existing
  statement of that. It is the same move health already makes at `health.py:749-752`.

**What this spec does not claim:** S-36551 and S-36552 alone, without a landing, do not move the
number. P12 is explicit — a held run keeps its `failed` reason and still reads dead until its work
lands. If the correction rounds do not land the work, the count stands and the card is correctly
reopened with both numbers. That is the right outcome and it is left in place.

## The design

### 1. The runtime's own word for what happened — `asf/workers/runtime.py`

A new pure function beside `failure_reason`, reading only the structured fields (D2):

```python
#: The runtime's own error subtypes, mapped to the words the factory uses. A subtype not named
#: here reads as its own text, sanitised; a record that carries only `is_error` reads
#: `RUNTIME_ERROR`.
ERROR_SUBTYPES = {
    'error_max_turns': 'max turns',
    'error_during_execution': 'during execution',
}
RUNTIME_ERROR = 'runtime error'


def error_subtype(rec):
    """The runtime's own name for the error it declared on ``rec``, or None when it declared
    none. Structured fields only (D2): ``subtype`` first, then ``is_error``. Pure."""
```

`error_subtype` returns None for a record whose `subtype` is `success` and whose `is_error` is
falsy — so it is None for every run that does not read bare `failed`, and non-None for every run
that does. That biconditional is what S-36550's first test asserts, and it is what lets the rest of
the design key on the function instead of re-deriving the condition.

`failure_reason` is **not** changed. It keeps returning None here, so `judge` keeps returning bare
`failed`, so the cause key is untouched (D1).

### 2. The reason on the row, and the sub-cause fold

**`asf/workers/health.py`** — where the run is recorded (`:729-732`), a bare `failed` reason also
writes the runtime's word to a new registry key:

```python
pool_mod.update_session(product, job, ended=now, end_reason=reason,
                        runtime_error=runtime_mod.error_subtype(ev.result) or '',
                        runtime_session=...)
```

**`asf/improve/measure.py`** — `Run` gains the third scorecard-only field (P9), read straight off
the registry row:

```python
runtime_error: str = ''  #: the registry's `runtime_error` key; read by diagnose's sub-causes and nothing else
```

**`asf/scorecard/diagnose.py`** — the fold in `rank` gains the sibling of P10's, and `causes` gains
the sibling of the `failed: not pushed` detail clause:

```python
if k == 'failed: not pushed':
    c['sub'][sub_cause(r)] = ...
elif k == 'failed':
    c['sub'][dead_sub_cause(r)] = c['sub'].get(dead_sub_cause(r), 0) + 1
```

`dead_sub_cause(run)` is pure and total, in this precedence, disjoint so the line sums to the count
above it:

1. a non-empty `run.runtime_error` — the runtime said what it was;
2. a falsy `run.runtime_error` on a run recorded before this lands — `'not recorded'`.

The detail line the card carries becomes, for example:

```
13 runs ended 'failed' without landing over 14 days, $30.28 and 45.7 h spent on them;
threshold 5/week. of the 13 runs: 8 ran out of turns, 3 errored during execution,
2 ended before this was recorded.
```

That sentence is the deliverable of S-36550. It is the first time the factory's largest failure
class says anything.

### 3. The branch is published — `asf/workers/health.py:396`

One boolean widens (D3):

```python
result_ok = (reason == lifecycle.FINISHED
             or (reason or '').startswith(UNPUSHED_REASON_PREFIXES)
             or reason == lifecycle.FAILED_BARE)          # F-0223: a mid-flight death still has work
```

with `FAILED_BARE = 'failed'` named in `lifecycle` beside the other reason constants, so the two
sites that test for it cannot drift apart. Everything downstream of the gate is untouched: the same
rebase, the same hook-refusal capture into `publish_refused`, the same network retry.

### 4. The item goes back — `asf/workers/health.py:742-792`

A new arm on the ladder, after the `UNPUSHED_REASON_PREFIXES` arm and before the `EMPTY_BRANCH`
one, reached only when nothing above it matched:

```python
elif reason == lifecycle.FAILED_BARE and s.get('branch'):
    # the runtime killed the session mid-flight; its branch now holds whatever it had done
    # (D3). The same loop an unpushed run gets: finish the work, or say why it cannot (D4).
    fields, line = lifecycle.hold(registry, s, lifecycle.UNPUSHED,
                                  lifecycle.died_text(s.get('runtime_error')), now,
                                  main=product.main)
```

`died_text(word)` is a pure one-liner beside `unpushed_text` and `empty_branch_text`, naming the
runtime's word when there is one:

```
the session was cut off mid-flight (max turns) — its branch holds what it had done; pick the
work up from there, finish it, and push; if it cannot be finished, say why in the report
```

A run with no branch keeps today's behaviour exactly: nothing to publish, nothing to hand back, the
ladder ends as it does now. The `question`-parked arm sits **above** this one and keeps precedence,
so a session that asked a person a question is still parked rather than relaunched (F-0126).

### 5. A cut-off session is resumed, not buried — `asf/workers/health.py`

Before the ladder's arms, for a run whose `error_subtype` is in `RESUMABLE` and whose record shows
no resume yet (D5):

```python
#: The runtime's own errors that mean "this session ran out of room", not "this work failed".
RESUMABLE = ('max turns',)
```

the run is handed back to `runtime.continue_run(job)` once, its registry row marked `resumed: 1`,
and **no `ended` is written** — the run continues and is judged on its next end like any other.
`continue_run` returning None (P11) means this runtime cannot resume: fall straight through to §4's
arm, which is the behaviour without this Story. A run already carrying `resumed: 1` also falls
through — once, then the hold (D5).

This is the Story that removes runs from the population outright, and it is deliberately the last
one: D6 lands the naming first so `RESUMABLE` is set against a measured split.
