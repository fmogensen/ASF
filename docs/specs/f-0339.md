# F-0339 — Kernel: resolve the next two most frequent session questions in code

Epic E-0002 (ASF 0.2 — self-improvement). The kernel already answers six classes of session
question from facts instead of handing them to the console: `id-claim`, `trunk-tests`, `symbol`,
`gate`, `inbox-bug` and `needs-writes` (`asf/kernel/resolvers.py`). This Feature takes the next
two classes off the console's desk the same way — code, not an LLM, and never a guess.

The source of truth for *which* two is the operator's own answer log,
`~/.ASF/state/asf/operator-answers.jsonl` (62 records, 2026-10-07 → 2026-10-10, 37 of them
carrying the question text verbatim). §1 reads it; everything below follows from that reading.

### 1.2 In scope

- Two new classes in `asf/kernel/resolvers.py`: `pushed` (pure — read off facts the kernel
  already holds) and `trunk-base` (one new probe branch).
- One new probe in `asf.kernel.trunk.TrunkProbe`: the merge base of a branch with origin's trunk.
  Refs only — no worktree, no test run.
- Two knobs under `kernel.resolve` (`asf/kernel/settings.py`), both default on, and both wired
  through the one gate `decide._resolving`.
- `tests/kernel/test_question_pushed_base.py` — the fixtures are the question texts and answers
  above, verbatim.

### 1.3 Out of scope

- **Granting a round.** 6 records, the most frequent remaining class, and deliberately left to
  the console (D1).
- **Acting, as against answering.** The resolver states the fact; it never archives a branch,
  closes a PR, rebuilds an item or pushes anything. The rebuild under the config knob
  `kernel.stuck.rebuild_after_h` (read in `decide.py:904`, `:946`) already owns the act, and
  `ports.archive_and_reset` (`asf/kernel/ports.py:1569`) is its hand.
- Any change to the brief, to the host's own push of a rebased branch, or to the Stop gate.
- Any new record write. An answer reaches the card through the existing `A.ApplyAnswer`.

## 2. The design

### 2.1 `asf/kernel/resolvers.py` — the two classes

New constants beside the six:

```python
PUSHED, TRUNK_BASE = 'pushed', 'trunk-base'
#: the classes the host's trunk probe answers
PROBED = (TRUNK_TESTS, SYMBOL, GATE, TRUNK_BASE)
```

**`pushed`** is field-read, like `needs-writes`. Two shapes reach it, and one answer function
serves both:

```python
#: a REPORT's `pushed:` value, carried by the recorded Stuck reason
PUSHED_RE = re.compile(r'\bpushed:\s*(.+?)(?:\n|$)', re.I)
#: the prose form: committed here, but the session cannot see it on origin
LOCAL_RE = re.compile(r'\b(?:committed|clean locally|rebased and ready|commits? locally)\b', re.I)
ORIGIN_RE = re.compile(r'\b(?:not|never|still not)\s+(?:yet\s+)?on origin\b'
                       r'|\bon origin\b|\breached origin\b|\bpush(?:ed|ing)? (?:was )?(?:refused|denied)\b',
                       re.I)

def pushed_question(text):
    """Whether ``text`` asks whether the session's committed work is on origin: the prose form
    (committed here, and origin named), or a REPORT ``pushed:`` value that claims no push."""

def pushed_answer(session, main='main'):
    """The kernel's answer from ``session``'s own facts, or None when they do not tell:

    - ``claim_landed`` (origin's branch head is, or descends from, the sha the REPORT named):
      ON_ORIGIN;
    - ``unpushed`` set and ``push_refused`` empty — the host may overwrite origin's tip under a
      lease: HOST_PUSHES;
    - ``push_refused`` set — origin holds a commit this history never had: REBASE_FIRST.
    """
```

The three answers, each naming the next act, as the console's own did:

```python
ON_ORIGIN = ('%s is on origin %s (head %s): the work was pushed — proceed to review, no rebuild '
             'and no second push. Read fresh by the kernel.')
HOST_PUSHES = ('%s is committed but not on origin yet; the host publishes it itself (its HEAD %s, '
               'force-with-lease, checked) on this tick — do not push by hand and never force. '
               'Continue on the same branch.')
REBASE_FIRST = ('%s cannot fast-forward: origin holds a commit this branch never had (%s). '
                'Rebase onto origin/%s and continue; never merge the trunk in and never force.')
```

**`trunk-base`** is matched from prose and answered from the probe. Its branch comes from the
existing `branch_of(item_id, sessions, prs)`; with no branch there is no match:

```python
#: the session says the trunk moved under it, or that it cannot reach the trunk at all
REWRITTEN_RE = re.compile(r'\b(?:rewritten|rewrote|rewrit\w*)\b[^.]*\b(?:main|trunk|origin)\b'
                          r'|\b(?:no|without any) merge[- ]base\b|\bunrelated histor\w+\b'
                          r'|\bno fast[- ]forward path\b', re.I)
```

placed in `match()` ahead of the `WHETHER_RE` gate (D10), returning `Probe(TRUNK_BASE, (branch,))`.

`answer()` gains its branch, over the probe's `{sha, base, ahead, behind, linear}`:

```python
BASE_OK = ('origin/%s was not rewritten: its history is linear and %s shares the merge base %s '
           'with it (the branch is %d ahead, %d behind the trunk at %s). Rebase onto '
           'origin/%s and continue; never merge the trunk in. Checked by the kernel.')
NO_BASE = ('%s has no merge base with origin/%s at %s: it is unrelated history and can never '
           'fast-forward. Rebuild the item fresh from the trunk; the old work stays readable at '
           'archive/%s. Checked by the kernel.')
```

`linear` false, no `sha`, or an `error` → None: the question stays the console's (D9).

### 2.2 `asf/kernel/trunk.py` — the probe

One branch in `TrunkProbe.probe`'s dispatch and one method:

```python
def _base(self, cache, branch):
    """``trunk-base``: ``git fetch origin <main> <branch>``, then the merge base of
    ``origin/<branch>`` with ``origin/<main>``, each side's distance from it, and whether the
    trunk's first-parent history is linear. ``{sha, base, ahead, behind, linear}``; ``error``
    when either ref is missing. Refs only: no worktree, no test run, so it does not count
    against ``test_runs_per_tick`` (D4). Cached by branch and trunk head sha."""
```

`self.enabled` gains `R.TRUNK_BASE: trunk_base`, and `for_product` reads it off
`product.kernel['resolve']`. A dry run (`asf.mutation_guard` active) fetches nothing and answers
from the local `origin/<main>` and the cache, exactly as `symbol` does today.

### 2.3 `asf/kernel/settings.py` — the knobs

```yaml
      resolve:    {…
                   pushed: true,            # a session that committed its work and cannot tell
                                            # whether origin holds it: answered from the branch
                                            # head the host already reads fresh
                   trunk_base: true}        # a session that says the trunk was rewritten or that
                                            # it has no merge base: the kernel reads the merge
                                            # base and answers (rebase, or rebuild fresh)
```

### 2.4 `asf/kernel/decide.py` — the wiring

`_resolving(config)` gains both classes, so `trunk-base` is matched, probed and answered on the
path every probed class already takes. `pushed` gets one function beside `_needs_writes`:

```python
def _pushed(it, facts, config):
    """``(answer, 'pushed')`` for a question about whether this item's committed work is on
    origin (:func:`asf.kernel.resolvers.pushed_question`), read off the item's latest session's
    own facts, or None — the knob off, no such question, no session the facts name, or the
    answer already on the card."""
```

called from `_auto_answer` after the id-claim branch and before `resolvers.resolve`, so a probed
class never shadows a fact already in hand. An answer lands as today:
`A.ApplyAnswer(it.id, text, by=resolvers.PUSHED)`.

## 4. Records

What the change writes down, and nowhere else:

- **The card** — one `answers:` entry per resolved question, through the existing
  `A.ApplyAnswer(it.id, text, by=…)`, with `by` the new class name (`pushed`, `trunk-base`). No
  new record field, no new write path.
- **`state/<product>/kernel-resolve.json`** — one more entry per probed branch, keyed
  `trunk-base:<branch>` by `Probe.key`, holding `{sha, base, ahead, behind, linear}` and dropped
  by the existing 7-day TTL. A question asked twice is answered from the cache.
- **The tick line** — `questions: resolved by code N, to the console M (P% by code)`, unchanged
  in shape; the two classes move counts from `M` to `N`.
- **The answer log** — `~/.ASF/state/asf/operator-answers.jsonl` gains *nothing*: an answer the
  kernel gives is not an operator answer, and `asf answer` stays the only writer.
- **No file in the repo** beyond the five this Feature touches: `asf/kernel/resolvers.py`,
  `asf/kernel/trunk.py`, `asf/kernel/settings.py`, `asf/kernel/decide.py` and
  `tests/kernel/test_question_pushed_base.py`.

## Stories

Four Stories: one per new class, one for the refusal rule both share, one for the card's own
measure. Each is **declared** below as a `### S-…: <title>` heading with its acceptance lines
under it, with ids from this session's range `S:125105-125154` — that heading is what
`asf.record.idcheck.declared_stories` reads and what `asf.record.plan_tasks` mints the card from,
so a cited id with no declaration is a phantom and the plan citing it is refused whole.

Each acceptance line is one physical line of plain text with no backticks, on purpose: the reader
is line-anchored (`asf.record.idcheck.CHECKBOX` matches a single line) and `_prose` replaces every
inline code span with one space before parsing, so a wrapped line reaches the minted card
truncated and an identifier inside backticks reaches it missing.

### S-125107: an unsure fact is never an answer

Design §2.1 and §2.4 (D8, D9; P4, P5). The rule the six existing classes already keep, extended
to both new ones: when the facts do not tell, the question stays the console's, and nothing is
written to the card.

- [ ] a pushed question whose item has no session in the facts is left to the console
- [ ] a trunk-base probe result carrying an error is left to the console
- [ ] a trunk-base probe result missing its trunk sha is left to the console
- [ ] a trunk whose first-parent history is not linear is left to the console, because a rewrite cannot then be ruled out
- [ ] the pushed knob turned off resolves no pushed question, and the trunk-base knob turned off resolves none of its own
- [ ] a knob turned off means the class is never probed, not probed and discarded
- [ ] an answer already on the card is never given a second time
- [ ] a failing probe leaves every other class's answer intact on the same tick
- [ ] both knobs default on, so the floor is the behaviour the trunk has today
