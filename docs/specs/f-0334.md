# F-0334 — the kernel landed; the clock it runs on is not measured, and only one product can use it

ASF 0.2 moved the factory onto a kernel: one tick, one pure `decide`, one launch path, one lock
(`asf/kernel/__init__.py:1-5`). The card's own measurements say what that bought and what it cost.
Throughput nearly tripled — 70.7 Tasks and Bugs done a day against an old floor of 21.6 — at 94 %
first-push green, no silent stuck and no red main. And the median code PR took **249 minutes**
from open to merged, against the old floor's **46**.

Nothing in the kernel measures that number. The gate has four criteria and none of them is a
clock: silent stuck, owned stuck, first-push green and landed Tasks/Bugs
(`asf/kernel/gate.py:171-178`). The wait ledger measures every *class* of wait per item — seat,
ci, review, train, merge, conflict, stuck, after, parked — and reports a p50 and a p90 per class
(`asf/kernel/waits.py:273`), but no record it writes carries a PR number, a PR's open time or a
merge time (`:184-185`), and the kernel's own `PR` value carries no clock at all
(`asf/kernel/model.py:177-191`; `PR_FIELDS`, `asf/kernel/ports.py:658-660`, does not ask GitHub
for `createdAt`). So the one figure 0.3 is judged on is the one figure the kernel cannot print.

Three more absences have the same shape — the machinery exists, and the kernel does not reach it:

* **The console.** The tick already prints `questions: resolved by code N, to the console M
  (P% by code)` (`asf/kernel/loop.py:105-112`) over the six classes code answers today
  (`id-claim`, `trunk-tests`, `symbol`, `gate`, `inbox-bug`, `needs-writes`). Nothing persists
  that count, so no window can be read from it and no gate can hold it — and `asf status` says
  the operator is answering about 15 questions a day.
* **Intake and grooming.** The decision step itself landed on the trunk while this spec was being
  written — #1383, `asf/kernel/intake.py`, one commit past this branch's base (P18). Every tick
  now mints the inbox and decides every undecided card, by code where the card's own text settles
  it and by one light `intake-decide` session otherwise. Two things it does not do: a **note**
  whose sessions are spent is left in the inbox undecided for ever (`spent` answers `None` for a
  note and the plan loop skips it), which is the one human step left in the path; and nothing
  persists the step's own figures, so no window reads it and no gate holds it — the tick prints
  `intake: minted M, decided N, launched K` and that line is rotated text. The Definition of Ready
  is written, tested and still **off** (`kernel.dor.enabled` default `False`,
  `asf/kernel/settings.py:227`; `:237` on the trunk).
* **The host.** `asf.capacity` already resolves how many sessions a product may hold *as one of
  several*: the operator's machine total less the sessions in flight elsewhere, this product's
  own ceiling, its fair share of the usable pool by weight, and the quota band under it
  (`asf/capacity.py:668-706`). The kernel resolves its own number instead — `kernel.launch`
  plus the account caps, over **one product's** session ledger
  (`asf/kernel/ports.py:1521-1538`, `:1559-1581`) — and launches by calling `spawn.spawn`
  directly (`:1706-1719`), so the host-wide seat claim that `asf.workers.pool.Pool.take` takes
  under a `flock` (`asf/workers/pool.py:655`) is never taken. Two kernels on one host each read
  an account as free and each fill it to its cap.

This spec closes those four in the two places they belong — **the ledger that measures and the
gate that holds** — then walks the card's remaining list: the Stage-4 sweep over 181 parked
Features, the parity items the second product's swarm has and the kernel does not, a GitHub App
so a busy floor cannot exhaust one person's token, and the risk flag's own evidence so it is
extended on a measurement rather than on a feeling.

### In

* **The PR's own clock.** `opened_at` and `merged_at` on `asf.kernel.model.PR`, filled from
  `createdAt` / `mergedAt` in the two `gh pr list` calls the ports already make — no third call.
* **The lead-time sample.** A wait-ledger record gains `pr` (the open PR's number) and
  `pr_opened`; the record that closes an item's run of spells gains `lead_s`. `waits.lead` folds
  the ledger into the p50, the p90 and the per-class attribution of each landed code PR over a
  window; `asf kernel waits` prints it; two gate criteria hold it.
* **The lead-time breach.** A wait class already breaches its target and takes an action
  (`decide.breaches`, `asf/kernel/decide.py:1920`). A *pull request* gains one too: an open PR
  whose age passes `kernel.gate.lead_p90_max` is first in every queue the kernel owns — its
  review, its rerun, its place in the train — and is named on the tick line.
* **Intake's last human step closed, and intake measured.** The mechanism is on the trunk
  (P18); 0.3 adds the two things it lacks. `asf.kernel.intake.spent` decides a **note** whose
  sessions are spent instead of leaving it in the directory — by code, `later`, filed as a card
  so the record holds it and the Stage-4 sweep can reach it. And the step's own figures become
  readable: `undecided` keys and the oldest one's age go on the per-tick record §5 writes, and a
  new gate criterion, `intake decided`, holds the oldest undecided key under
  `kernel.gate.undecided_max_age`.
* **The Definition of Ready, on.** `kernel.dor.enabled` defaults to `True`.
* **The Stage-4 sweep.** `asf/kernel/sweep.py`: on a tick with free seats and nothing to launch,
  the oldest parked items are retired or revived by a rule over the record, at most
  `kernel.sweep.max_per_tick` a tick, each with its reason written to the card.
* **The console's share, measured and held.** `state/<p>/kernel-questions.jsonl`, one record a
  tick; `asf kernel questions` over it and over `operator-answers.jsonl`, which buckets the
  answers a person gave into classes with counts; a `console share` gate criterion; and one new
  resolver class, `host-command`.
* **The kernel's seats from `asf.capacity`.** `Facts.seats` becomes `capacity.resolve(...)`'s
  number; the tick writes its demand and claims its share; a launch takes the host-wide seat
  claim; `capacity.wave_active` learns that a kernel tick is an active wave.
* **Stories-first ordering**: one term in the launch key, under a flag.
* **The flake-vs-defect check in the kernel's red path**, through `asf/flake.py` as it stands.
* **Pace control**: a cap on new launches per tick, measured against the CI the product can
  really run.
* **The factory's GitHub App identity**: `asf/ghapp.py` mints and caches an installation token
  with `openssl`, offered through the one `auth_env` channel that already exists.
* **The risk flag's own evidence**: `state/<p>/kernel-incidents.jsonl` and `asf kernel risk`,
  which is the Stage-5 trigger's reading.
* **The documentation of all of it**: `docs/products.example.yaml`, `docs/RELEASE-NOTES.md` and
  `docs/KNOWN-ISSUES.md`.

### Out

* **Rewriting the decide core.** The card says so. Every rule below is a new term in an existing
  key, a new action beside the existing ones, or a new module `decide` calls — never a change to
  what `decide` *is*. `asf/kernel/decide.py`'s rules as its docstring states them hold unchanged
  except where a Story below names the line.
* **New product features**, in this product or any other. The card says so.
* **Batching green PRs behind a strict trunk.** The kernel's landing is non-strict by design: a
  green PR merges behind a moved main with no update and no re-run (P14), which is the capability
  the card's "green batch landing on a moved main without a full re-run" asks for, reached by not
  needing a batch rather than by building one. For a product whose ruleset *is* strict the merge
  train serialises updates and CI re-runs — and wiring `asf/merge_queue.py`'s 3,114 lines into
  `decide` is exactly the rewrite the card puts out of scope. S-120817 proves the non-strict path
  and names the strict one as the one configuration 0.3 does not serve; a `NEEDS OPERATOR` asks
  which the second product's trunk is.
* **Per-account cloud environments.** Already shipped and already inherited by the kernel (P13).
  Nothing to build; S-120817's acceptance pins it so it cannot regress.
* **Extending the risk flag past its two levels.** The card's outcome 7 is the condition, not the
  change: the flag is extended "only if measured incidents justify it". 0.3 ships the
  measurement and the trigger; whatever the measurement then justifies is its own card, with the
  incident ledger as its evidence.
* **Retuning the four gate criteria that exist.** `silent_stuck_max`, `first_push_green_min` and
  `landed_min` keep their numbers and their readings; four rows are added beside them (`lead
  p50`, `lead p90`, `console share`, `intake decided`).
* **Re-specifying the intake step.** #1383 landed it, on by default, with its own tests (P18, D7).
  0.3 changes one branch of `spent`, adds one count and one gate row, and touches no other rule
  of that module: not the shape shortcut, not the session lane, not the verdict grammar, not the
  caps.
* **The old floor's own groom run** (`asf/tick/step_groom.py`, `asf groom`, the adjudicate
  session and the daily digest). It keeps working for products still on the floor. The kernel's
  intake step already calls the floor's own minting path and answer grammar; it does not replace,
  delete or re-plumb the floor's path.
* **A second quota, pace or seat policy.** Everything the kernel needs is in `asf.capacity`,
  `asf.workers.quota` and `asf.workers.seats`. The work is to *call* them; a new ceiling of the
  kernel's own would be the fifth definition of a seat on one host.
* **Changing how a question is asked.** `NEEDS OPERATOR:` keeps its grammar and the brief keeps
  its rule. What changes is how many of them a fact answers before a person sees one.
* **Moving the second product.** The move is the operator's run, against the kernel this card
  delivers. This spec's job is to leave nothing in the kernel that names one product.

### Preconditions the work depends on

1. **The ports are the only door.** `RecordPort`, `GitHubPort` and `SessionPort`
   (`asf/kernel/ports.py:118-148`: `RecordPort` at `:118`, `SessionPort`'s two writes at
   `:146-147`) are protocols a test fills with fakes. Every new fact below —
   a PR's clock, the capacity number, the quarantine ledger — arrives as a port read, so `decide`
   stays pure and every new rule is testable with no network and no clock. The intake notes are
   already such a read (`RecordPort.notes`, `mint_inbox`, `inbox_count`, landed by #1383).
2. **One tick writes one ledger line per change.** `waits.record` already appends only on a
   change and reads the whole ledger first (`asf/kernel/waits.py:196-210`). The lead-time sample
   is a field on records that are already written, so the ledger's size and shape of growth do
   not change.
3. **The settings block validates and defaults.** A new `kernel.<section>.<key>` needs a line in
   `SPEC` (`asf/kernel/settings.py:198`), its documented comment in the module docstring, and its
   commented line in `docs/products.example.yaml`; `problems` then refuses a wrong type and
   `read` fills the default (`:328-353`). `tests/test_env.py` walks the example configs.
4. **`asf.capacity` is the one reader of the capacity keys** — its own docstring says so — and
   it never raises: a fact it cannot read is `None` (`asf/capacity.py:317-344`). The kernel can
   therefore adopt it without a new failure mode: an unreadable capacity leaves
   `Config.max_sessions` holding, exactly as `Facts.seats = None` does today
   (`asf/kernel/decide.py:1678-1682`).
5. **`asf.workers.seats` is already the host's claim ledger**, locked, with one definition of a
   live claim, and already registered in the state registry
   (`asf/state/registry.py:124-125`). Taking a claim is a call, not a design.
6. **`asf.flake` is product-generic**: it takes a state dir, a slug and a `gh` runner, and it
   names no product (P12). It is called, not copied.
7. **`asf.kernel.intake` is already pure and already decides by code.** It reads nothing but its
   arguments; `spent` is the one function that answers "this key's sessions are gone", `plan` the
   one that turns an undecided key into a decision or an ask, and the groom's own answer grammar
   (`answer_words`, `note_clauses`) is how a verdict reaches a card or a note. The delta in §2 is
   a branch in `spent` and a count the plan already has — no new module and no second grammar.
8. **The repository has no dependencies and takes none** (P15). The GitHub App's RS256 signature
   is therefore an `openssl` subprocess, the way every other external tool in this repository is
   a subprocess.
9. **The record holds no Story for F-0334**, and this session's range is `S:120805-120854`
   (P17).

### 1. The lead time: the PR's own clock, the sample, the gate, the breach (S-120805–S-120807)

**The clock.** `PR` gains two fields, both ISO-8601 UTC and both `''` when unread:

```python
opened_at: str = ''     # GitHub's createdAt: when the pull request was opened
merged_at: str = ''     # GitHub's mergedAt: when it landed ('' while it is open)
```

`PR_FIELDS` gains `createdAt` (so `_open_pr` fills `opened_at`), and the merged listing asks for
`createdAt,mergedAt` beside the three fields it reads now, so `_prs`'s merged branch fills both.
No third call: both are fields of calls `asf/kernel/ports.py:999-1022` already makes.

**The sample.** `waits.classify` already finds an item's open PR (`_open_pr`,
`asf/kernel/waits.py:93-95`). `changes` gains two keys on every record it writes, when the item
has one:

```
{"item": "T-0012", "from_state": "review", "to_state": "landing", "reason": "ci",
 "at": "...", "why": "PR #41: build, test", "pr": 41, "pr_opened": "2026-10-10T09:04:00Z"}
```

and the record that ends the run — `to_state: done`, written when the PR merged — carries
`lead_s`, the seconds from `pr_opened` to the PR's `merged_at` (never to the tick's clock: D2).
A record for an item with no open PR carries neither key, so the ledger's shape for a New, Ready
or parked item is byte-identical to today's.

**The reading.** `waits.lead(records, now, since, prefixes=('T-', 'B-'))` returns

```python
{'n': 23, 'p50': 3310.0, 'p90': 9120.0, 'max': 18240.0,
 'prs': [{'pr': 41, 'item': 'T-0012', 'lead_s': 3310.0,
          'classes': {'ci': 1180.0, 'review': 900.0, 'building': 1000.0, 'merge': 230.0}}, …],
 'by_class': {'ci': 14200.0, 'review': 11050.0, …}}
```

over every PR whose `lead_s` is on a record in the window and whose item id starts with one of
`prefixes` (D3). `classes` is `item_hours`' own arithmetic restricted to the one item's spells
between `pr_opened` and the merge, with `building` counted — inside a PR's life a fix round is
not a wait but it *is* lead time (D6). `by_class` sums them, so the biggest term in the median is
named. `percentile` is the module's own, unchanged (`asf/kernel/waits.py:246-253`).

`render` gains a block under the class table:

```
## Lead time (23 code PRs merged since 2026-10-09T14:00Z)

| | p50 | p90 | max |
| --- | --- | --- | --- |
| open → merged | 55m | 2.5h | 5.1h |

by class: ci 3.9 item-h, review 3.1 item-h, building 2.6 item-h, seat 0.8 item-h, merge 0.3 item-h
```

and `tick_line` gains `lead p50 <d>, p90 <d>` after the biggest-wait term, so the tick log carries
the figure the release is judged on, every tick.

**The gate.** `evaluate` gains two rows, read from the ledger the gate already has a state dir
for — no new GitHub call:

| criterion | value | target |
|---|---|---|
| `lead p50` | `55m` over 23 PRs | `≤ 60m` (`kernel.gate.lead_p50_max`) |
| `lead p90` | `2.5h` | `≤ 4h` (`kernel.gate.lead_p90_max`) |

A window with no merged code PR reads `-` and is information, never a FAIL — the same rule
`owned stuck` already follows (`asf/kernel/gate.py:173`), and for the same reason: a gate that
fails for want of data tells a person nothing they can fix.

**The breach.** `decide.breaches` takes the wait classes over their targets and reorders the
actions the kernel already has (`asf/kernel/decide.py:1920`). It gains one more input: an open
PR whose age (`Facts.now` less `opened_at`) is past `config.lead_p90_max`. Its item joins `due`,
which is the first term of the launch key (P5), so its review or fix round launches before
anything else; its place in the merge train is the front (`train_key`'s first term already has
that shape for a long auto-merge wait); and the tick logs

```
LEAD BREACH T-0012 PR #41 4.6h > 4h -> review first
```

one line per breached PR, in `Plan.breaches` beside the wait breaches. The breach takes no action
the kernel does not already take — that is D5 — so a product with `lead_p90_max` unset (0) sees
nothing change.

### 2. Intake: the last human step closed, and the step measured (S-120808)

The intake step itself is the trunk's (P18, D7). This section is the delta: one branch in
`asf/kernel/intake.py`, one count the plan already knows, and one gate row. Nothing else in that
module moves — not `shortcut`, not the session lane, not `parse_verdict`, not `check`, not
`answer_words` or `note_clauses`, and none of its caps.

**The spent note.** `spent` answers `None` for a note today, which is why the plan loop
`continue`s past it and the note is never decided again (P18). It answers a `Verdict` instead:

```python
def spent(key, tries, config, intake_epic=''):
    """The code's decision for a key whose sessions are spent, or None (tries left)."""
    if tries < config.intake_max_tries:
        return None
    if is_note(key) and not intake_epic:
        return Verdict('close', reason=SPENT_CLOSED % tries)
    if is_note(key):
        return Verdict('later', 'feature', intake_epic, reason=SPENT % tries, set_priority=True)
    return Verdict('later', reason=SPENT % tries, set_priority=True)
```

The `is_note(key)` early `None` goes, and with it the `continue` at `plan`'s line 294. A note's
decision needs one fact a note does not carry, which is why it cannot simply reuse the card's: a
note Item is `(id, type='note', title, body, question)` and nothing else (`RecordPort.notes`), so
it has no kind and no parent — and `check` already refuses a feature note with no parent Epic
(*"a feature note needs a parent Epic"*). The parent therefore has to be **declared by the
product**, exactly as the Bug Epic already is:

* **`conventions.default_intake_epic`**, beside `default_bug_epic` (`asf/conventions.py:869`,
  documented at `:18`), resolved through `asf.tick.file_bugs.usable_bug_epic`'s own pattern
  (`asf/tick/file_bugs.py:514`) — an Epic that is on the record and open, or nothing, with a
  `why` either way.
* **Declared** — the note is minted as a Feature under that Epic with `priority: later`, by
  `note_clauses`' existing `feature` / `parent <id>` clauses and `priority_of`'s `later`. Its
  file moves to `done/` with the verdict in its header and the `## History` line carries `SPENT`'s
  reason (`no valid intake verdict after 2 session(s)`). It is then a parked card like any other
  — which is the population §4's sweep retires or revives (D8), so the idea has a reader again.
* **Not declared** — the note is decided `close` with the same reason, through `note_clauses`'
  existing `close` clause. The product that wants its unanswerable notes kept declares one line;
  the product that declares nothing gets a decision rather than a note nobody will read, and the
  note's text is preserved under `done/` in both cases.

The `INTAKE` line says which of the three happened, so the choice is never silent. **The apply
door does not change**: a note verdict already goes through `RecordPort.decide_intake` →
`_decide_note`, which applies the inbox answer, mints the card and decides it
(`asf/kernel/ports.py:705-712`). `spent` supplies a kind and a parent where it had supplied
nothing; everything downstream of it is the path #1383 shipped.

**The count.** `intake.plan` already walks exactly the keys `undecided` is true of, so the
population is computed and then thrown away. It returns one more value: `waiting`, the
`[(key, created)]` it walked, so a caller can say how many keys are undecided and how old the
oldest is without re-deriving the predicate. It stays pure — `created` is a field of the Item it
was handed.

That value is written down twice, in the two places that already exist:

* **`kernel-plan.json`**, by `loop.save_plan`, as a new `intake: {waiting: n, oldest: <iso>}` key
  beside `states`, `idle` and `breaches`. This is the one the gate reads (below).
* **`kernel-questions.jsonl`**, the per-tick record §5 writes, as `intake: {waiting: n,
  oldest_s: m}` — one line a tick, beside the figures the console share is read from, which is
  what makes a *window* readable rather than only the latest tick.

**The gate row.** `gate.criteria` gains one more row, in the shape the two point-reading rows
already have — `silent stuck` and `owned stuck` are read straight off the saved plan
(`silent_stuck(plan)` over `plan['states']`, `asf/kernel/gate.py:36-42`), not folded over a
window:

```
| intake decided | oldest undecided 12m (3 waiting) | ≤ 1h | ✓ |
```

It reads `plan['intake']` out of the same `kernel-plan.json` the gate is already handed, against
`kernel.gate.undecided_max_age` (default `1h`, a `duration` like the `waits` block's own times,
D4) — so the row costs the gate no call and no file it does not already open. A plan file written
before this release has no `intake` key; the row then reads as information with no verdict, the
way `owned stuck` does, rather than failing a gate on a missing fact.

A transient undecided key is normal — a card minted this tick is decided on the next — so the
criterion is an **age**, not a count: it fails only when something has been waiting longer than
the hour the release's other clock is also set to. With the spent note closed there is no key the
step cannot eventually decide, so this row failing means the step itself stopped, which is the
one thing about intake worth holding a release for.

### 3. The Definition of Ready, held (S-120809)

`kernel.dor.enabled` defaults to `True` (D9). Nothing else in `asf/kernel/dor.py` changes: the

### 4. The Stage-4 sweep: parked work retired or revived (S-120810)

`asf/kernel/sweep.py`, pure:

```python
def sweep(items, idle, config, now):
    """[(item_id, 'retire'|'revive', why)] — at most config.sweep_max_per_tick."""
```

It returns nothing at all unless `idle` is set — the kernel's own idle alarm, which means seats
are free and nothing wanted them (D10) — and `config.sweep_enabled` is on. Over the parked items
(`State.PARKED`: the item's own `priority: later`, or an ancestor's), oldest first by the age of
the park:

* **retire** when the item is parked, older than `config.sweep_retire_after`, has no open PR, no
  landed spec, no child that is not parked, and nothing waits on it through `after:`. The `why`
  names all five facts.
* **revive** when the item is parked and something that is *not* parked waits on it through
  `after:` — a park that holds live work is a park that was a mistake, and the sweep says so.
* nothing otherwise: a parked item that is neither retirable nor blocking stays parked, and is
  counted on the tick line so the number is visible without a session.

`A.Retire(item_id, why)` writes through `asf.record.retire`'s own path — `removed: retired:
<reason>`, the `## History` line, the note moved to `done/`, through the record's writer (D11).
`A.Revive(item_id, why)` clears the item's own `priority: later` through the same writer and
writes the reason; it never touches an *ancestor's* park, because that would unpark a subtree
nobody asked about.

The tick line is `sweep: 181 parked -> 4 retired, 1 revived, 176 held (3 seats idle)`.

### 5. The console's share: the ledger, the gate, the classifier, the class (S-120811–S-120812)

**The ledger.** `asf/kernel/questions.py` writes one record a tick to
`state/<p>/kernel-questions.jsonl`:

```json
{"at":"2026-10-10T14:30:00Z","by":{"trunk-tests":2,"needs-writes":1},"console":["T-0101"],
 "resolved":3,"left":1}
```

`by` is the resolver class of every `ApplyAnswer` with a `by` this tick (the figure `summarize`
already computes, `asf/kernel/loop.py:93`); `console` is the items left on an operator Stuck
(`:94`'s population, now named rather than counted). A tick with neither writes nothing, so the
ledger holds only the ticks where a question existed.

**The share.** `questions.share(records, since)` is `Σ resolved / (Σ resolved + Σ left)` over the
window, with the per-class counts beside it. `loop.questions_line` reads the window instead of
the tick alone, so the line becomes

```
questions: resolved by code 3, to the console 1 (75% by code); 24h: 41 of 48 (85%)
```

and `evaluate` gains the criterion `console share` — `41/48 = 85%`, target
`≥ 80%` (`kernel.gate.console_share_min`, default 0.8). An empty window is information, not a
FAIL, for the reason §1 gives.

**The classifier.** `asf kernel questions [--classify] [--since …]` prints the window's share and
its classes; `--classify` reads `operator-answers.jsonl` (`asf/workers/answer.py:26`) and buckets
every answered question by the one thing a bucket may be keyed on — the shape of the *question*,
never the answer:

| class | what the question's own text carries |
|---|---|
| `host-command` | a backticked command and a "confirm / run on the host" clause |
| `record-write` | an order to mint, file, retire or set a field on a card |
| `config-value` | a named config key and a value to choose |
| `id-claim`, `trunk-tests`, `symbol`, `gate`, `inbox-bug`, `needs-writes` | already coded (P10) |
| `judgement` | none of the above: a question only a person can answer |

Each row is `class, n, share, the newest example (truncated)`, most frequent first, and a row
whose class is already coded is marked so. That table is the reading the next class is chosen
from (D14), and it is `## Records`' first `NEEDS OPERATOR`.

**The class.** `host-command` joins `asf/kernel/resolvers.py`'s classes. It is the `gate` class
widened: `gate` matches only a command that is a step of the product's `pre_push_check`
(`asf/kernel/resolvers.py:14-19`), and the questions this factory's own sessions ask name other
read-only commands too. `match` returns a `Probe('host-command', (command,))` when the question
carries a backticked command, a host clause (`NOT_RUN_RE` / `HOST_RE`, `:78-80`) and the command's
first token is on `config.resolve_host_commands` — a product-declared allow list
(`kernel.resolve.host_commands`, default `()`: no command runs anywhere until a product names
one). `TrunkProbe` runs it on a fresh detached worktree of the branch head, under
`resolve.test_timeout_s`, and the answer is its last line and the sha, in `GATE_GREEN`'s own
words. An empty allow list means the class matches nothing, so the default changes no behaviour.

### 6. One host, many products (S-120813–S-120814)

**The seats.** `SessionPort.capacity` (`asf/kernel/ports.py:1559`) becomes

```python
def capacity(self):
    r = capacity.resolve(self.product, self.cfg())          # the one reader of the keys
    lanes = sum(lane_seats(self.product, self.cfg()))       # what this kernel is configured for
    return min(lanes, r.sessions) if r.sessions is not None else lanes
```

so every ceiling `asf.capacity` knows — the operator's machine total less the sessions in flight
elsewhere, this product's own `capacity.sessions`, its fair share by weight, and the quota band
under all of them — bounds a kernel launch (D16). `seat_line` (`asf/kernel/loop.py:316-325`,
printed by a dry run) gains `r.sessions_bound` and `r.fair_share_reason`, so the number says
which term held it. An unreadable capacity is `None` and the lane number holds, which is exactly
today's behaviour (precondition 4).

**The demand.** The tick writes `capacity.write_demand(product.name, inflight, wanted)` once per
tick — `inflight` the live sessions, `wanted` the launchable Ready rows `decide` could not seat —
so a partner product's `claim` can read what this one is holding or waiting for
(`asf/capacity.py:478-497`). Without it a kernel product lends its whole share to any partner
that asks (P7).

**Active.** `capacity.wave_active` gains one branch: a product whose kernel tick job is installed
competes for the pool, read the way the watch reads it (`asf/kernel/host.py:59-60` and the job's
plist path). The old `wave`-step branch is untouched, so a floor product's answer does not move;
a kernel product's answer goes from false to true, which is what makes `fair_share` exist for a
host of them (D17).

**The claim.** `SessionPort._spawn` takes the host-wide seat claim before it spawns and releases
it when the launch fails:

```python
with seats.held() as ledger:                 # the flock asf.workers.pool.Pool.take holds
    if not seats.take(ledger, acct.name, job, cap=acct.cap):
        raise NoSeat('account %s is at its host cap (%d)' % (acct.name, acct.cap))
self._spawn(...)                             # the claim is the launch's, from here
```

(the shape; the call is `asf.workers.pool.Pool.take`'s own, reused rather than re-written, D18).
`_live`'s per-account count becomes the claim ledger's, which is every product's, and `_account`
refuses an account at its host cap rather than at this product's share of it.

**No product special-cased.** `asf kernel install --product P` is already per product and already
labels its jobs `asf.<p>.kernel` (`asf/kernel/host.py:1-11`). What this Story adds is the test
that says so: two products' configs, installed on one host, with different seats, different
accounts, different conventions and different `kernel:` blocks, each ticking from the other's
facts without reading them — and `tools/check_generic.sh` green over the tree, which is the
mechanical statement that no product's name is in the code (P16, D26).

### 7. Parity, generic (S-120815–S-120817)

**Stories-first ordering** (S-120815). `_launches`' `first` key gains one term, between the
relaunch term and the rank:

```python
first = lambda iid: ((iid not in due,),
                     (0, -blocks.get(iid, 0)) if relaunch(items[iid]) else (1, 0),
                     (0 if started_story(iid) else 1) if config.stories_first else 0,
                     rank(iid))
```

`started_story(iid)` is true when another Task of the same Story (through `parent`, or a
`stories:` naming, which is `decide`'s own definition of a Story's children) is Building, in
Review or in Landing. With `kernel.launch.stories_first` off the term is the constant 0 and the
order is byte-identical to today's (D19). The effect is the one the card names: the factory
finishes the Story it started before it opens another, which is what makes a Story's worth of work
land as a Story rather than as scattered Tasks.

**The flake-vs-defect check** (S-120816). The kernel's required-red rule
(`decide`'s "Red" paragraph) gains one clause *before* the fix round: a required red whose
`asf.flake.classify_red` verdict is a flake candidate and whose job has not already been re-run
on this exact sha takes `A.Rerun` once, as the off-PR red already does. The re-run green writes
`A.Quarantine(job, step, test, sha, until)` — `asf.flake`'s own entry, through its own
`save`, with its own `ci.quarantine_days` expiry and its own owner card (D20). The re-run red is
a defect and goes to the fix round exactly as today, with the first red's log tail as its finding.
Nothing is skipped, disabled or quarantined *out* of a suite: the entry is a record that the job
flaked, and `asf status`' `Quarantine` row already prints it.

**Pace** (S-120817a). `_launches` stops at `config.launch_per_tick` new launches when the key is
set, after the breach-first and relaunch classes have had their places — so a pace never delays
work that is already late. With the default 0 it never stops (D21). When the product has a CI
read, the cap is `min(launch_per_tick, capacity.bandwidth(product)['ci_free'])` and the tick says
`pace: 3 of 7 launches this tick (ci_free 3)`.

**A green PR on a moved main** (S-120817b). No code. The capability is the non-strict landing
path the kernel already has (P14, the `Out` row), and this Story is the test that holds it:
`Facts.strict` false, a green approved PR, the trunk's head moved past its base — no
`UpdateBranch`, no `Rerun`, auto-merge enabled, and the item Done when it merges; with
`Facts.strict` true, the merge train as today. The strict case is written into
`docs/KNOWN-ISSUES.md` as the one configuration 0.3's lead-time target is not specified for.

### 8. The factory's GitHub App identity (S-120818)

`asf/ghapp.py`, one job: turn an app's private key into an installation token, and cache it.

```python
def token(product, cfg=None, now=None):
    """The installation access token for ``product``'s github_app:, minted when the cached one
    has under RENEW_MARGIN left. Returns (token, expires_at); raises AppError with the reason."""
```

* **The block** (`products/<p>.yaml`, under `conventions:` so an older reader tolerates it):
  `github_app: {app_id: <n>, installation_id: <n>, private_key: <path>}`.
* **The JWT**: header and claims as JSON, base64url, signed `RS256` by
  `openssl dgst -sha256 -sign <key>` over the signing input, read from the subprocess's stdout
  (D22). `iat` is one minute back and `exp` nine minutes on, GitHub's own bounds.
* **The exchange**: `gh api -X POST /app/installations/<id>/access_tokens` with the JWT as the
  bearer — the one `gh` call, so `asf.gh_limit`'s guard and `asf.github`'s result shape apply
  unchanged.
* **The cache**: `state/<p>/github-app-token.json`, mode 0600, `{token, expires_at, app_id,
  installation_id}`, re-minted under `RENEW_MARGIN` (10 minutes, D23). The file is an ordinary
  `asf.state.registry` entry — `_s('asf.ghapp')`, kind `json` — written mode 0600: the registry's
  `Spec` is `(owner, kind, ttl_days, schema, shared)` with kinds `json|jsonl|stamp|lock|text`
  (`asf/state/registry.py:26-27`) and has no secret category to declare. What covers the secret
  itself is `asf.hermetic`'s secret-shaped-variable rule, over the variable the token becomes.
* **The reach**: `env.product_auth_env` resolves a `GH_TOKEN` whose value is the literal
  `github-app` to the minted token rather than to a file's contents. Every existing caller —
  `ci_pool._gh_env` and so the tick, the gate, the lane, the queue, every session's watcher —
  then runs `gh` under the app's own hourly limit, with no caller changed (D22).
* **The verbs**: `asf github-app check --product P` prints the app id, the installation, the
  cached token's remaining life and the installation's own rate limit; `asf doctor` gains one
  non-required row saying which identity this product's GitHub calls use.
* **Never the identity a session commits as.** `asf.identity`'s `agent_identity` is unchanged: a
  worker still commits as the agent, never as the app and never as the operator.

## Stories

Fifteen Stories, grouped by the card's seven outcomes: three for the lead time, three for intake
and grooming, two for the console, two for the host, three for the parity list, one for the GitHub
identity and one for the risk trigger. Each is **declared** below as a `### S-…: <title>` heading
with its acceptance lines beneath it, with ids from this session's range `S:120805-120854` — that
heading is what `asf.record.idcheck.declared_stories` reads and what `asf.record.plan_tasks` mints
the card from, so a cited id with no declaration is a phantom and the plan citing it is refused
whole.

Each acceptance line is one physical line of plain text with no backticks, on purpose: the reader
is line-anchored (`asf.record.idcheck.CHECKBOX` matches a single line) and `_prose` replaces every
inline code span with one space before parsing, so a wrapped line reaches the minted card
truncated and an identifier inside backticks reaches it missing.

exceptions, both of them deliberate. The lines of S-120817 marked as held are the two

### S-120805: the pull request's own clock, read in the two calls the ports already make, and the lead-time sample on the wait ledger

Design §1 (D1, D2; P2, P3). Two fields on the model, two field names on two existing `gh` calls,
two keys on every ledger record that has a PR, and one key on the record that closes a merged
PR's run. No new call, no new file.

- [ ] a PR read from the open listing carries the time it was opened, from the listing's own field
- [ ] a PR read from the merged listing carries both the time it was opened and the time it merged
- [ ] a PR whose listing carries neither time reads as empty strings and breaks no rule that uses it
- [ ] the ports make no more GitHub calls than before this change
- [ ] a ledger record for an item with an open PR carries that PR's number and the time it opened
- [ ] a ledger record for an item with no open PR carries neither key, byte for byte as today
- [ ] the record that ends a merged PR's run carries the seconds from its open time to its merge time
- [ ] the lead seconds are read from the PR's own merge time, never from the tick's clock
- [ ] a PR that opened before the ledger's first record for its item still yields its own interval
- [ ] two PRs on one item over time yield one sample each, not one sample spanning both
