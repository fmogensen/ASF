# F-0279 — the beat was a precondition, and a refused beat parked the work

A review session's brief opens with a command it must run before the work:

> `- As your very first command, start it exactly like this (one Bash call, in the background):`

followed by a `nohup` that writes `NOTES.asf.md` into `$(git rev-parse --git-common-dir)/info/exclude`
and leaves a shell loop running (`asf/workers/heartbeat.py:200`, the `brief_lines` loop block).
A session whose sandbox refuses a detached process answers "Unauthorized Persistence"; one whose
git common dir sits outside the sandbox cannot write the exclude file at all. Either way the
session reads its own brief as gated: it stops, and the only thing it files is a question —
`NEEDS OPERATOR: the heartbeat loop could not start — …`. No verdict table, no `verdict:` block,
nothing on the branch.

The factory then reads that question as a question. `report.needs_input` returns it, and health's
F-0126 path writes a `blocked` park on the item (`asf/workers/health.py:1021`,
`lifecycle.blocked_park`). A park is a pending correction: the row shows `PARKED <reason>`, no
session is launched on it, and only a card edit or `asf unpark` lifts it. The PR stops moving with
its seats free, for a reason that says nothing whatsoever about the code under review.

Per the card, 2026-10-07 on ASF: B-0351 (#926), T-0312 (#878), T-0745 (#848) and T-0248 were
parked this way, and T-0528 spent its cap of 6 launches in 24 h on it. (Those rows are the
operator's record, not this repo's: this spec cites the card for them and measures only what is
in the tree.)

Half of this is already closed, and it is the half that is easy to mistake for all of it.

- **The runtime is already the beat.** F-0265's liveness hotfixes landed both lanes' own signal
  *ahead* of the beat ref: `heartbeat.log_alive_at` for a local run (`heartbeat.sweep` →
  `alive by job log (last event <n>m ago); no beat needed`) and `remote.alive_at` over the
  routine's `worker_status` for a claude-remote run (`cloud.sync` →
  `alive by remote status (…); no heartbeat needed`). Measured in this worktree at `b0d41d9a4`:
  `tests.test_heartbeat` already proves a beatless local run with a 2-minute-old log event is not
  stalled, and a remote one alive by `worker_status` likewise.
- **The relaunch cap already ignores such a run.** `relaunch.cause_key` strips a heartbeat-start
  refusal from a correction's cause, `relaunch.counted` drops a run health marked
  `heartbeat_refused`, and `_assess` refuses to read the refusal as the run's terminal claim
  (`asf/workers/relaunch.py:57,75,91,276`; `tests.test_relaunch.HeartbeatStartRefusalTests`).
- **The remote brief already asks for no loop.** `remote.py:490` passes `runtime_liveness=True`.

What is left is the two ends the hotfixes did not reach, and they are exactly the two the card
names. The **local brief still asks for the loop** (`runtime.brief_text` calls
`heartbeat.brief_lines` with no `runtime_liveness`, `asf/workers/runtime.py:672`), so a local
session is still handed a precondition its sandbox may refuse — and the Actions brief
(`actions.py:379`) asks for it with no word anywhere in that block that a refusal is survivable.
And the **park is still written**: health gates it on `report.needs_input`, which today returns
the refusal verbatim. Probed in this worktree at `b0d41d9a4` over a review-shaped report
(`status: partial`, `commits: none`, the refusal as its one `NEEDS OPERATOR:`):
`needs_input` → `'the heartbeat loop could not start — Unauthorized Persistence: …'`. So the cap
steps aside and the park takes the row anyway, and the four rows the card names stay parked until
someone types `asf unpark`.

This feature closes those two ends: no brief makes the beat a precondition, and no park is ever
written for a beat that could not start.

## Decisions

### Preconditions — measured in this worktree at `b0d41d9a4`

| # | precondition | how it reads today |
| --- | --- | --- |
| P1 | A local run's liveness does not need the beat | `heartbeat.sweep` reads `log_alive_at(run.log, now, limit_min)` on the stalled path and clears the stall, recording the event as `moved` (`asf/workers/heartbeat.py:731`) |
| P2 | A claude-remote run's liveness does not need the beat | `cloud.sync` reads `remote.alive_at(diagnose(run), now, limit_min)` on the stalled path (`asf/workers/cloud.py:673`) |
| P3 | An **Actions** run has no such signal | `cloud.sync` consults the runtime only `if stalled and remote.is_remote(run)`; an Actions run falls through to the beat ref and the branch ref alone |
| P4 | The local brief asks for the loop | `runtime.brief_text` → `heartbeat.brief_lines(job.name, job.session or '', beat)`, `runtime_liveness` defaulting False; the rendered block carries `nohup` and `As your very first command` |
| P5 | The Actions brief asks for the loop | `actions.py:379` → `cloud.cloud_brief(f.read(), job, product=product)`, `runtime_liveness` defaulting False |
| P6 | `report.needs_input` reads the refusal as a question | probed above; `relaunch.terminal` therefore reads `needs input — the heartbeat loop could not start …` |
| P7 | Health's park is gated on that question | `asf/workers/health.py:980` computes `question = report_mod.needs_input(…)`; the F-0126 branch at `:1021` is `elif question and items is not None and …` |
| P8 | Health's `heartbeat_refused` mark is gated on it too | the same `question` gates `if question and relaunch_mod.ended_on_heartbeat(…)` at `:981` — so narrowing `needs_input` alone would silently drop the mark the cap depends on |
| P9 | A released park re-reads the run's report | `rejudge.release_answered` releases a `blocked` park whose run's text `needs_input` now reads as no question (`asf/tick/rejudge.py:78`) |
| P10 | The refusal text is already recognised | `relaunch.HEARTBEAT_REFUSED_RE` matches "Unauthorized Persistence", "heartbeat … could not start", "git-common-dir … outside … sandbox" |

### In

1. No brief makes the beat a precondition. The **local** brief stops asking for the loop (P1 is
   its beat). The block that still asks for one — the Actions lane's (P3) — says in the same
   block that a refusal is survivable and is never a stop, a `needs input` or a `NEEDS OPERATOR`.
2. A heartbeat-start refusal is not a question for a person. It joins the list of things
   `report.needs_input` already declines to read as one (`NEEDS OPERATOR: none`, a reshape's
   `does not split`), so no `blocked` park is written for it, no `INPUT` row is drawn for it
   (`asf.workers.stall`) and `asf answer` is not offered it — while the raw reading the relaunch
   cap's mark depends on (P8) stays available and the line itself stays in the report text, where
   an operator can read it.
3. A park already written for one is released by the next tick, with its own reason, no
   `asf unpark` — the four rows the card names come back by themselves.

### Out

- **The beat's machinery.** `SCRIPT`, `Beats`, `observe`, `last_beat`, `land_snapshot`,
  `delete_ref`, `clear_ended`, `resume`, `launch` and the continuation's CONTINUE block are
  untouched. Beat refs written by runs launched before this change still exist on origin and are
  still read, landed and deleted exactly as today.
- **The heartbeat config keys.** `heartbeat_min`, `heartbeat_missed`, `heartbeat_grace_min` and
  `heartbeat_resumes` all stay and keep their meaning: `interval_min * missed` is still the
  quiet limit every lane is judged by, loop or no loop.
- **The relaunch cap's own rules.** `CAP`, `HEAD_CAPPED`, `streak`, `head_streak`, `loop_guard`
  and `counted` keep today's behaviour; this feature only keeps feeding `counted` the mark it
  already reads (P8).
- **The review template.** `asf/briefs/templates/review.md` names no heartbeat; the precondition
  is in the HEARTBEAT block, not the template. Nothing in the verdict table, the C/I lists or the
  round rules changes.
- **Dropping the loop from the Actions lane** — see C1.
- **Making the job log the primary signal** (reading it before `observe` rather than on the
  stalled path) — see C4.
- **`docs/design` and `docs/KNOWN-ISSUES.md`.** This session creates `docs/specs/f-0279.md` and
  nothing else; the design note follows the code.

### The choices

| # | chosen | against | why |
| --- | --- | --- | --- |
| C1 | The local lane loses the loop; the **Actions** lane keeps it | dropping the loop from every lane and deleting `SCRIPT` | P3: an Actions run has no event-level liveness, so the beat ref is its only proof of movement short of a branch push, and its runner is a VM that allows a background process — the refusals the card names are the sandboxed CLI's and the remote session's. Deleting `SCRIPT` would trade this bug for a relaunch storm on a lane that never had it |
| C2 | The loop block, where it remains, says a refusal is survivable | leaving that sentence only in the brief's TAIL, where it already is | the TAIL's sentence is two sections away from the imperative that causes the stop. A session reads `As your very first command, start it exactly like this` as a gate; the answer belongs in the block that carries the ask |
| C3 | `report.needs_input` declines the refusal, and a new `report.declared_question` keeps the raw reading | gating only health's park branch on a heartbeat predicate | the park is not the only consumer: `stall.py` draws an `INPUT` row from `needs_input`, `answer.py` offers to answer it, `lifecycle` reads it for the nothing-to-land shortcut, and `rejudge` releases on it. One narrowing fixes them together, in the module and the grammar that already own "what a report declares" — and P8 is why the raw reading must survive beside it |
| C4 | The stalled-path order stays: `observe` first, the run's own signal second | reading the job log before `observe` now that the local lane leans on it | `observe` must run to record branch movement in `heartbeat.json`; the outcome is identical either way (P1), and reordering would move tested behaviour this card did not ask about |
| C5 | The refusal line stays in the report and in the tick's output | stripping it from the report text, or from the cause, so nothing sees it | the refusal is real diagnostic information about the sandbox. It stops being a *question for a person* (nobody is asked to do anything) without stopping being visible: health prints it, and the released park's reason names it |
| C6 | `heartbeat_refused(text)` and its regex move to `asf/workers/report.py`, re-exported from `relaunch` | duplicating the regex, or importing `relaunch` from `report` | `relaunch` already imports `report`, never the reverse; the predicate is a reading of a report's text, so `report` is its home. The re-export keeps `relaunch.heartbeat_refused` and its tests as they are |
| C7 | The mark means "the refusal was the end of it": raw-terminal **and** nothing else asked | marking on `heartbeat_refused(text)` alone | a run that hit the refusal, said so in one line and then did the work must keep counting as a launch — that is what `ended_on_heartbeat`'s terminal gate buys today, and C3 makes `needs_input is None` the second half of the same sentence so a report asking a *real* question too is parked on it and counted |

## The design

### 1. No brief makes the beat a precondition

**`asf/workers/runtime.py`** — `brief_text` passes `runtime_liveness=True`:

```python
return text.rstrip('\n') + '\n' + '\n'.join(
    heartbeat.brief_lines(job.name, job.session or '', beat, runtime_liveness=True)) + '\n'
```

Its docstring gains the reason: a local session's liveness is its own run log
(`heartbeat.log_alive_at`), never a loop it starts.

**`asf/workers/heartbeat.py`** — `brief_lines` keeps both forms and both branches. The
`runtime_liveness` block's first bullet is reworded so it is true of both lanes that take it
(the keeper being the `Liveness comes from the runtime` opening, which a test pins):

```
- Liveness comes from the runtime: the factory reads this session's own events itself (its run
  log on this host, its worker status off it). Do NOT start a detached or background process (no
  loop, nothing left running after its command returns), for a heartbeat or anything else.
- Commit and push your work on your branch as each piece stands: a run that is neither running
  nor moving for <limit> minutes is ended and continued by a new session from your branch.
```

The loop block — now the Actions lane's alone — keeps its `nohup`, and gains one bullet
immediately after the fenced command:

```
- If that command is refused — your sandbox allows no background process ("Unauthorized
  Persistence"), or the git common dir is outside it — say so in one line and carry on with the
  job. The beat is never a precondition: not a reason to stop, not a `needs input`, not a
  `NEEDS OPERATOR`.
```

`brief_lines` stays pure and golden-tested. Nothing in `asf/briefs/` changes: the HEARTBEAT block
is appended by the runtime, not by `briefs.build`, so every golden brief under
`tests/fixtures/briefs/golden/` is byte-identical after this change.

When it is there: a local session's brief carries the HEARTBEAT heading, the two
runtime-liveness bullets and no `nohup`, no `asf-heartbeat.sh`, no `git-common-dir` write; an
Actions session's carries the loop *and* the sentence that makes it optional.

### 2. A heartbeat-start refusal is not a question

**`asf/workers/report.py`** gains the predicate and splits the reading in two.

- `HEARTBEAT_REFUSED_RE` and `heartbeat_refused(text)` move here verbatim from `relaunch`
  (C6), documented as what they are: a session saying its sandbox refused the beat loop.
- `declared_question(text)` is today's `needs_input` body — every `NEEDS OPERATOR:` line that
  asks something, else a `status: blocked` report's own words. It is the raw reading: what the
  session declared.
- `needs_input(text)` becomes the same reading with one more entry in the list of things that
  are not a question, beside `NO_QUESTION_RE` and `NO_SPLIT_RE`: a `NEEDS OPERATOR:` line that
  is a heartbeat-start refusal is skipped, and a `status: blocked` report whose words are one is
  no question either. A report that declares *both* the refusal and a real question returns the
  real one — the skip is per line, not per report.

Both share one private body (`_question(text, heartbeat_asks=…)`); the module docstring gains the
sentence that says which is which, and why there are two.

**`asf/workers/relaunch.py`** re-exports `heartbeat_refused` (and the regex) from `report`, so
every present caller and `tests.test_relaunch` stay as they are. `terminal(text)` reads
`report.declared_question` — the raw one — so the cap's claim and its mark keep today's meaning.
`ended_on_heartbeat(text)` becomes the full sentence of C7: the report's terminal claim, read
raw, is a heartbeat-start refusal **and** `report.needs_input(text) is None`.

**`asf/workers/health.py`** loses one gate and gains one line. The mark is computed from the raw
reading, independent of `question` (P8):

```python
question = report_mod.needs_input(str((ev.result or {}).get('result') or ''))
if relaunch_mod.ended_on_heartbeat(str((ev.result or {}).get('result') or '')):
    pool_mod.update_session(product, job, heartbeat_refused=1)
    s['heartbeat_refused'] = 1
    found.append((job, 'heartbeat', 'the sandbox refused its beat loop: no question, no park'))
```

The F-0126 branch at `:1021` is not touched at all: `question` is already `None`, so the park is
never reached. The run falls through to the path its end reason actually deserves — an unpushed
run becomes a correct round, an empty branch `nothing to land` — and the row is launchable again
next tick.

When it is there: a review session that could not start its beat and filed no verdict ends with
its reason recorded, no park, and its row drawn again on the next wave; the cap still does not
count it (`counted` reads the mark), so the round it buys is a real round.

### 3. A park already written for one is released

**`asf/tick/rejudge.py`** — `release_answered` needs no new condition: `needs_input(text)` is now
`None` for such a run, so `asked(corr)` finds the `blocked` park and the park is released on the
next `health` step, `unparked` written the way `asf unpark` writes it. Only the reason is made
truthful, so the tick log does not claim the report asked nothing when it plainly printed a
`NEEDS OPERATOR:` line:

```python
why = ('its only question was a heartbeat-start refusal (re-judged)'
       if report_mod.heartbeat_refused(text) else 'its report asks no question (re-judged)')
```

When it is there: the next tick after this lands prints one `unparked <item> (job <job>)` line
per row parked on a refused beat, and those rows launch again without anyone typing
`asf unpark`.

## Records

What the change writes down, and where:

| record | written by | shape |
| --- | --- | --- |
| the session's brief | `runtime.brief_text` → `<brief>.session.md`; `cloud.cloud_brief` → the brief ref | the HEARTBEAT block: two runtime-liveness bullets (local, claude-remote) or the loop plus its refusal bullet (Actions) |
| `heartbeat_refused: 1` | `health` on the run's registry line (`lifecycle.RUN_FIELDS`, already a member) | the one field `relaunch.counted` reads; written while the job's log is still that run's own |
| the health line | `health`'s `found` → `f'{what:<9} {job:<24} {detail}'` | `heartbeat <job> the sandbox refused its beat loop: no question, no park` |
| **no** pending correction | `health` — the F-0126 branch is not reached | the registry line carries no `correction`, so the feeder draws the row as launchable instead of `PARKED <reason>` |
| `unparked`, `unpark_why` | `rejudge.release_answered` | `unpark_why` = `its only question was a heartbeat-start refusal (re-judged)`, beside the existing `its report asks no question (re-judged)` |
| the `unparked` event | `ctx.event('unparked', job=…, item=…, text=why)` | one per released row, in the tick's event stream, as `asf unpark` writes it |
| the refusal itself | the session's own REPORT, unchanged | the `NEEDS OPERATOR:` line stays in the report text: diagnostic, no longer a question (C5) |

Nothing new is written to origin: no ref, no file, no commit. A beat ref already on origin is
still landed and deleted by `clear_ended` and the stalled path exactly as today.
