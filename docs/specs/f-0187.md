# F-0187 — a shared path is exempt in one reader of four

The first customer install reported the symptom the card names: a lockfile is touched by almost
every Task that adds a dependency, so as a `writes:` path it overlaps nearly every other Task,
the feeder serialises unrelated Tasks, and `widen_footprint` refuses to add it. The card's want
is `conventions.shared_paths`: globs the product declares as merge-serialised shared files,
outside footprint overlap, serialised by harvest at merge instead, with an optional
`shared_regenerate` command and an empty default.

Read against the tree at `d005de847`, three things have to be said before the work can be cut.

**Half of it is already built, and that half is the half the card's first test names.**
`conventions.shared_paths` is a real field with an empty default, validated, documented in the
module docstring and declared by the e2e product fixture; `footprint.overlaps` and
`first_conflict` take a `shared` argument, both feeder call sites pass it, and
`tests/test_lane.py:2216` already proves that two Tasks sharing only `uv.lock` both launch. The
lane already refuses to gate two shared-path branches in one tick. Writing this spec as if the
key did not exist would re-cut work that is on the trunk and green (P1, P2, P3).

**The half that is missing is not one gap but four readers of the same overlap.** The feeder
asks `footprint.overlaps(..., shared)`. The widening rule asks `footprint.first_conflict` with
no `shared` and refuses (P5), and would revert the path on the next tick if it did not (P6).
`asf check` and the I3 invariant pair Active Tasks' `writes:` through `core.writes_intersect`
directly and know nothing of the key — and I3 runs *before any writer commits*, so it refuses
the widening that the rule would allow, on a path where the product is not even in scope to be
asked (P7, P8). The groomer's merge and split proposals are a fourth reader, and with the
feeder fixed and the groomer not, it proposes folding every dependency-adding Task of a Feature
into one session — the same serialisation, back as a proposal (P10). A key honoured by one
reader of four is not a feature; it is a trap.

**The exemption as written opens a hole the card did not ask for.** `is_shared` matches in both
directions, so with any non-empty `shared_paths`, `is_shared('*', ['uv.lock'])` is **True** — a
Task whose footprint contains `*` or `**` stops overlapping anything at all (P9). Declaring a
lockfile must not disarm the footprint gate for the widest glob there is. The fix is one
direction, and it costs nothing the feature wants.

`shared_regenerate` is the only genuinely new mechanism here, and the lane already knows its
shape: rebuild a branch with no session, publish it over a lease, put it back to PUSHED so its
checks run again — twice over, in `repair_signoff` and `drop_copies` (P13).

### In

- **One reader of the key** — `footprint.shared_globs(product)` — tolerant of a `Product`, a
  `Conventions` or a plain mapping, used by every caller that needs the set. The two existing
  predicates keep their jobs (P11): `footprint.is_shared` for a declared glob,
  `lane.shared_hits` for a changed file.
- **`is_shared` matched one direction only** (P9): a declared glob is shared when the shared set
  covers it, never when it covers the shared set. `writes: ['*']` overlaps everything again.
- **`widen.decide(..., shared=())`** — a shared path is exempt from the overlap test and does
  not count toward `widen_max_files`; **`widen.overlapping_widenings(..., shared=())`** — a
  widening that added a shared path is never reverted for it.
- **`record_findings(root, ..., shared=())`** and I3 reading `ctx.product`, so `asf check` and
  the pre-commit invariant agree with the feeder.
- **`set_typed(..., product=None)`**, threaded from the widen writer and from `cmd_set`, so the
  widening the rule allows is actually written (P8).
- **The groomer's three overlap calls given the shared set** (P10).
- **Harvest serialising per shared glob**, not per tick: `shared_taken` becomes
  `{glob: branch}`, and the wait reason names the glob.
- **`conventions.shared_regenerate`** — a command string, default unset, validated the way
  `worktree_setup` is, documented in the conventions docstring, the products example and the
  operator guide alongside a `shared_paths` row (P17).
- **`Lane.regenerate_shared(f)`** — the third instance of P13's shape: a branch whose shared
  path the trunk has moved under is rebuilt on the new trunk with the trunk's side of that
  file, the declared command run, the result scanned and committed as one commit naming the
  item, the old tip archived, the branch published over a lease and put back to PUSHED.
- **A test for each half**, including the two the card names that nobody runs today: harvest
  landing two shared-path branches one after another (P3), and widen adding a shared path (P5).

### Out

- **A non-empty default.** `DEFAULT_SHARED_PATHS` stays `()`. No product gets a lockfile
  exemption it did not write down (P1).
- **The containment uses of `footprint.overlaps`.** `lane.py:1003,1011` ask whether a red file
  lies inside *one* branch's reach, and `briefs/facts.py:210` asks which test files sit inside a
  footprint. Neither is a two-Task collision, and a lockfile red inside a branch's reach is that
  branch's red. They keep no `shared` argument.
- **`core.writes_intersect`.** The one definition of *two globs name a common path* does not
  learn about products. Every exemption is applied by the caller, above it.
- **Merging lockfile text.** `try_resolve_conflict` gains no lockfile case (P14). A generated
  file is regenerated or it is a conflict.
- **Ordering beyond one-at-a-time.** No priority, no queue position, no "biggest first". The
  existing tick order decides who goes first, as it does today.
- **Running `shared_regenerate` in worker worktrees.** That is `worktree_setup`'s job and it is
  unchanged; `shared_regenerate` runs in the lane's own checkout, at merge, and nowhere else.
- **Teaching a coder anything.** No brief template changes: a coder declares the lockfile in
  `writes:` exactly as it does now and nothing about its session differs.
- **`shared_paths` affecting approvals, `amendable_paths`, review classing or landing class.** A
  lockfile is code and stays code.

## The design

### `asf/conventions.py` — the second key

```python
#: The command that rewrites a product's ``shared_paths`` after the trunk moves under a branch
#: (the install command that regenerates the lockfile); unset: the shared paths are serialised
#: at merge and nothing is regenerated.
DEFAULT_SHARED_REGENERATE = None
```

and the field, beside `shared_paths`:

```python
    #: ``shared_regenerate``: the command run in the lane's own checkout when a branch's
    #: ``shared_paths`` are behind the trunk (:data:`DEFAULT_SHARED_REGENERATE`).
    shared_regenerate: str = DEFAULT_SHARED_REGENERATE
```

`validate_mapping` gains the same clause `worktree_setup` has — a command string, not a dict, a
list, a bool or blank — so a misshapen value is a doctor row, never a silent default. The
module docstring's example gains one line under `shared_paths`:

```yaml
      shared_paths: [uv.lock]                # lockfiles: no footprint overlap, one per merge
      shared_regenerate: uv lock             # run when the trunk moves one under a branch
```

### `asf/feeder/footprint.py` — one reader, one direction

```python
def shared_globs(product):
    """``conventions.shared_paths`` for ``product`` — a Product, a Conventions, or the plain
    ``conventions:`` mapping — as a tuple; ``()`` for None and for a product that declares none.
    The one reader of the key: the feeder, the widening rule, ``asf check``, I3, the groomer and
    the lane all ask here, so a product cannot be exempt in one of them and not the others."""
```

and `is_shared` loses its second direction:

```python
def is_shared(glob, shared):
    """True when the ``shared_paths`` set covers ``glob`` — ``uv.lock`` against ``uv.lock``, and
    ``apps/web/package-lock.json`` against ``**/package-lock.json``.

    One direction only: a glob *wider* than the shared set is never shared. Matched both ways,
    ``*`` would be covered by any declared lockfile (``fnmatch('uv.lock', '*')``), and a Task
    declaring ``writes: ['*']`` would overlap nothing at all — the footprint gate off for the
    widest footprint there is (D2)."""
    return any(fnmatch.fnmatch(glob, s) for s in shared or ())
```

`overlaps` and `first_conflict` are unchanged; `rows.py`'s two call sites become
`footprint.shared_globs(product)`.

### `asf/feeder/widen.py` — a shared path is added freely

`decide` takes `shared=()` and applies it twice: the paths that are shared are set aside before
the cap is counted (D3), and `first_conflict` is asked with the set.

```python
def decide(task_id, paths, limit=MAX_FILES, protected=None, running=(), widened_before=0,
           shared=()):
    """… ``shared``: the product's ``conventions.shared_paths``. A path the set covers is a
    lockfile the product has declared merge-serialised: it never makes this widening wait on
    another Task, and it is not counted toward ``limit`` — the cap judges a mis-cut plan, and
    the one file every dependency-adding Task touches is no evidence of one (D3). Every other
    refusal still applies to it: a second widening is still a RESHAPE, and an approvals-protected
    path is still an approval."""
    paths = tuple(dict.fromkeys(p for p in paths or () if p))
    scoped = tuple(p for p in paths if not footprint.is_shared(p, shared))
    if widened_before or len(scoped) > limit:
        return Verdict(RESHAPE, paths, RESHAPE_REASON.format(paths=' '.join(paths)))
    ...
    other = footprint.first_conflict(list(paths), [...], shared)
```

`overlapping_widenings` takes the same argument and skips a shared path when it looks for a
widening to revert — without it, the tick would add the lockfile and strip it again on the next
pass (P6):

```python
def overlapping_widenings(writes, widened, others, shared=()):
    """… A path the ``shared`` set covers is never named: the product has declared it
    merge-serialised, so it is not this Task's to give back."""
```

`asf/tick/widen_footprint.py` passes `footprint.shared_globs(product)` at both call sites

```python
    def regenerate_shared(self, f):
        """A branch whose ``conventions.shared_paths`` the trunk has moved under, rebuilt on the
        new trunk with the product's ``shared_regenerate`` command: the branch's own commits
        replayed onto ``origin/<trunk>`` taking the trunk's side of every shared path, the
        command run in the ref checkout, the result scanned for protected names and committed as
        one signed-off commit naming the item, the old tip archived as
        ``archive/<branch>-regen-<sha9>``, the branch pushed over a lease on it and put back to
        PUSHED so its checks run again on the tree that will actually land (D8).

        None — and nothing pushed — when: the product declares no command; the branch touches no
        shared path the trunk moved (D9); the branch is under no factory prefix, is foreign,
        already landed, held by a live session, or the ref is protected; ``--dry-run``; the
        replay conflicts outside the shared paths; the command exits non-zero or leaves them
        unchanged; the scan finds a protected name; the lease push is refused. Every one of those
        is one line out and today's behaviour after it (D10, D11)."""
```

The replay takes the trunk's side of the shared paths only — `git checkout --ours -- <shared
hits>` inside the rebase, every other conflict aborts as it does now (P14) — so the command
regenerates from the merged manifests rather than from a text merge of two lockfiles. The
regenerate commit's subject is `<item>: regenerate <paths> on <trunk> <sha9>`, which
`commits_name_item` accepts (P15), and it carries `-s`.
