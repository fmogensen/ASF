# F-0053 — the table is the verdict

A reviewer today writes `verdict: approved` and the factory believes it. `evidence.verdict_of`
greps the first review file it finds for `APPROVED|CHANGES REQUESTED|BOUNCE|REVISE` anywhere in
its first 20 000 bytes (`asf/evidence/evidence.py:222`); `pr_hygiene.parse_verdict` keeps a second
copy of the same vocabulary, preferring a line that starts with the word `verdict`
(`asf/harvest/pr_hygiene.py:123`). Neither looks at what was checked. A review that says
`verdict: APPROVED` over a table whose every row reads `fail` approves the branch, and a review
that checked nothing at all approves it just as fast.

The table already exists. `asf/briefs/templates/review.md` opens with **THE VERDICT IS A TABLE**
and prints six `| check | result | evidence |` rows — then asks for a typed verdict line
underneath, and that line is the only thing the machine reads. So the table is decoration and the
word is the contract, which is exactly backwards.

This spec inverts it. One module owns the check-table grammar and the checklist each review kind
must cover. The reviewer's brief renders that checklist as the table's skeleton — the mechanical
pass first, the judgement pass second — and a code review's skeleton carries one row per Story
acceptance line. A pre-review command parses the file and refuses it when the table is missing, a
row is unfilled or a required check is absent. `evidence` derives the round's verdict from the
rows instead of grepping for a word, and `ingest` ticks the Story acceptance lines a passing code
review proved, naming the review file as the evidence.

## 1. Decisions

### 1.1 Preconditions

- **`conventions.review_path(slug, n)` already names where a round lives**
  (`asf/conventions.py:273`, default `{reviews_dir}/{n}-{slug}.md`), and
  `preamble.review_path_for` already hands the reviewer the next round's path
  (`asf/briefs/preamble.py:77`, `:269`). No path is invented here and none is written down in
  code: `tools/check_conventions.sh` generates a forbidden pattern for every path-shaped default
  in `asf.conventions`, so a literal review path inside `asf/**/*.py` fails the build.
- **One `review` template serves all three kinds.** `build.KINDS` has a single `review` entry
  (`asf/briefs/build.py:46`) and `preamble.REVIEW_KINDS` is `('review', 'fixer', 'adjudicate')`
  (`:135`). A spec review, a plan review and a code review are the same brief kind with a
  different branch, so the kind must be *derived*, not configured.
- **The branch prefix says which kind it is.** `conventions.branch_prefixes` maps
  `spec`/`plan`/`code`/`fix` to prefixes, and `feeder_rows.review_round(item)` already reads
  `spec-review r3` / `plan-review r4` off the Feature's stage (`asf/feeder/rows.py:162`). Between
  them the review kind is derivable without a new field on the row.
- **`evidence` has no record.** It is read-only against the *product* repo
  (`asf/evidence/evidence.py:21`) and never opens an item file. It can therefore check a
  mechanical checklist, but it cannot know a Story's acceptance lines — those live on the card.
- **`evidence.cells(line)` already splits a markdown row on unescaped `|`**
  (`asf/evidence/evidence.py:326`), with `\|` unescaped back to a literal pipe and
  `tests.test_evidence.ParseRowsTests` holding it to that. A second table parser in this repo
  would be the third copy of the same eight lines.
- **A task row's review already loses its file.** `evidence` computes
  `row["review"] = (round, verdict_of(blob))` and drops the file name it read
  (`asf/evidence/evidence.py:582`); the spec/plan tuple keeps it as a third element (`:589`).
  Ticking an acceptance line needs the path, so something must carry it.
- **`ingest` writes a body only when the machine block changed.** `_ingest_fields` returns
  `None` for "no change, skip the write" and the write loop `continue`s on it
  (`asf/record/ingest.py:196`, `:471`), so a body edit that is not accompanied by a machine
  change is silently dropped today. `append_history_lines` is the only body writer.
- **A Story is required to carry an acceptance checklist.** `record.check` fails an item typed
  `story` whose `## Acceptance` has no `- [ ]` item (`asf/record/check.py:155`), and
  `record.ids.new_card` seeds one. `tick.step_prs.acceptance` already reads those bullets out of
  a card file (`asf/tick/step_prs.py:129`) for the PR body.
- **`ingest` already knows which Tasks list which Stories.** It builds `story_any_active` from
  every Task's `stories:` field (`asf/record/ingest.py:285`) and has `task_ev[cid]` for each.
- **A golden brief per kind is asserted byte-for-byte.** `tests/fixtures/briefs/golden/review.md`
  is compared whole (`tests/test_briefs.py:130`) and regenerated with
  `ASF_UPDATE_GOLDEN=1`. Every template placeholder must be a key of `build.context`
  (`tests/test_briefs.py:439`), so a new placeholder without a context key is a test failure.
- **`prereview` is already a session-name token**, not a brief kind: `record.match` and
  `metrics.KINDS` classify a session named `prereview…` or `rr2` as a review
  (`asf/record/match.py:31`, `asf/metrics/metrics.py:43`). Nothing builds such a brief, and
  nothing needs to.
- **The gate is `python3 tools/run_tests.py`** (one module per process, `ASF_GATE_MODULES` to
  narrow it) plus `tools/check_generic.sh` and `tools/check_conventions.sh`.

### 1.2 In

- **`asf/reviews.py`** (new, stdlib only, no path literal, no product name) — the one owner of
  the check table: `cells`, `parse`, `normalize`, `verdict`, `typed_verdict`, `faults`,
  `render_table`, `required`, and the `CHECKLIST` per kind.
- **`asf/cli.py`** — one new subcommand, `asf review-checks <path> --kind <k> [--card <id>]
  [--json]`: the mechanical pre-review, exit 1 on a fault.
- **`asf/briefs/templates/review.md`** — the check table becomes `{check_table}`, rendered from
  the reviewed kind's checklist; the typed verdict line goes away; the pre-review command is the
  reviewer's last act before the commit.
- **`asf/briefs/preamble.py`** — `facts['review_kind']`, and the review-file line names it.
- **`asf/briefs/build.py`** — `context()` gains `review_kind`, `check_table`, `prereview_cmd`.
- **`asf/evidence/evidence.py`** — `verdict_of(blob, required=())` delegates to `asf.reviews`;
  `cells` becomes a one-line delegation; every task row gains a `checks` dict.
- **`asf/harvest/pr_hygiene.py`** — `parse_verdict` delegates to `asf.reviews`, keeping its
  signature.
- **`asf/record/ingest.py`** — the acceptance tick: a Story's `- [ ]` line proven by a passing
  row of a code review becomes `- [x] … — <review path>`, with one `## History` line and one
  `evidence:` line; the write loop writes a body edit even when the machine block is unchanged.
- **`asf/record/core.py`** — `acceptance_items(body)`, the one parser of a card's `## Acceptance`
  checklist; `tick.step_prs.acceptance` uses it.
- Tests: §3.1–§3.6, `tests/test_reviews.py` (new), and the regenerated golden review brief.

### 1.3 Out

- **A new brief kind or a second session per round.** The mechanical pass is a *pass inside the
  review*, run by the same session before it forms an opinion, and a command anyone can run. A
  `prereview` session would double the cost of every round to re-read the same diff.
- **A vendor workflow runner.** The card asks for "a scripted workflow with a schema per step".
  In this repo the script is the brief and the schema is `CHECKLIST[kind]` validated by
  `asf review-checks`; ASF may not depend on one agent harness's orchestration tool — that is the
  same genericity rule that keeps a product path out of `asf/**/*.py`.
- **Changing who launches a review.** No `review` row is raised by the feeder today
  (`asf/feeder/rows.py` emits no `brief_kind='review'`); the brief is built by
  `asf brief --kind review`. That gap is not this card's.
- **Changing what an approval *means*.** `feature_stage`, `feature_state`, `review_state` and the
  stalemate round keep their present logic; only the string they are handed changes its
  provenance.
- **Unticking.** A tick records that a round proved a line. A later red is a new round, not an
  erasure — §2.5.
- **Feature and Bug acceptance lines.** The card says Story. A Task's own acceptance is the
  plan's fences, already checked by a mechanical row.
- **The fixer's and adjudicator's templates.** They read the failing rows, which they already do
  through the C list. Their wording is untouched.
- **A new metrics stream, item field or schema version.** Nothing here appends to
  `metrics/events` and no machine key is added.

### 1.4 The choices

| # | Chosen | Against | Why |
| --- | --- | --- | --- |
| D1 | One new top-level module `asf/reviews.py` owns the grammar, and `evidence` / `pr_hygiene` / `briefs` all call it | extending `asf/evidence/evidence.py`, where `verdict_of` lives today | `evidence` is read-only-against-git plumbing and cannot be imported by `briefs` without dragging that in; `pr_hygiene` already proves what happens without an owner — two copies of the verdict vocabulary, one of which ignores the table. A peer of `asf/tokens.py` and `asf/approvals.py`: pure, stdlib, unit-testable, imported by all three. |
| D2 | The header stays `check \| result \| evidence`, and `ok` is accepted as a synonym for the result column | renaming the column to the card's `ok` | Every review already on a branch was written from the shipped template's `result` header. Accepting `ok` costs one entry in a set and makes the card's own wording parse. |
| D3 | Two tables, one per pass — mechanical first, judgement second — and `parse` tags each row with the block it came from | one table with a fourth `pass` column | "Run the mechanical pass before the human-standard review" has to be visible in the file, and a heading between two tables is how a reader sees it. A fourth column is a cell a reviewer fills with the wrong word. Blocks are numbered by order of appearance, so the order is the ordering. |
| D4 | No table at all → `reviews.verdict` returns `''` and the legacy typed word answers; a table present but malformed, or missing a required check → `BOUNCE` | bouncing every file with no table at once | The table speaks first; when it is silent the old word still moves the rounds already open. | D5 | `--kind` is required on `asf review-checks` | guessing it from the path or the branch | The review path is `{n}-{slug}.md`; the slug says the card, never the kind. | D6 | `evidence` requires only the mechanical rows; Story-acceptance coverage is checked by `asf review-checks --card` and by `ingest` | teaching `evidence` to read the record | `evidence` has no record and opening one would invert the pass order (ingest reads evidence, not the other way). | D7 | An acceptance line is matched to a check row by its normalized text — lowercased, whitespace collapsed, backticks and trailing punctuation stripped | prefixing the row with the Story id (`S-19950: …`) | The brief renders the acceptance lines verbatim into the skeleton, so there is nothing for the reviewer to type and nothing to mistype. An id prefix is a second thing to keep in step, and `check_conventions.sh` forbids an id-shaped literal in code anyway. |
| D8 | The tick is additive: `- [x] <text> — <path>`, the text kept byte-identical | rewriting the line, or unticking on a later `fail` | `record.check` reads those bullets and the PR body renders them; keeping the text means both keep working, and re-running ingest is a no-op. |
| D9 | An empty evidence cell reads `fail`, not a fault | bouncing the file for it | The shipped template already rules "a result with no evidence counts as `fail`". A row a reviewer half-filled is a failed check, and telling them so costs one round less than a bounce. |
| D10 | The pre-review is a command (`asf review-checks`), not a session kind | a `prereview` brief and row | The mechanical checks are answerable by the session already holding the diff. ## 2. The design

### 2.1 `asf/reviews.py` — the grammar and the checklist

```python
"""asf.reviews — the table a review ends in, and the verdict derived from it.

A gate returns one check per thing it looked at. A review file carries one or two tables of
`| check | result | evidence |`; this module is the only thing in the factory that parses them,
the only thing that knows which checks a kind of review must cover, and the only thing that
turns rows into a verdict. Nothing here opens a file, runs git or knows a path.
"""

MECHANICAL, STANDARD = 1, 2
PASS, FAIL, NA = 'pass', 'fail', 'n/a'
APPROVED, CHANGES, BOUNCE = 'APPROVED', 'CHANGES REQUESTED', 'BOUNCE'
RESULTS = {PASS, FAIL, NA}
#: The result column may be headed `result` or the card's `ok`.
HEADERS = (('check', 'result', 'evidence'), ('check', 'ok', 'evidence'))
KINDS = ('spec', 'plan', 'code')

Check = collections.namedtuple('Check', 'name result evidence block line')

CHECKLIST = {
    'spec': ((  # the mechanical pass
        'the five sections are present, in order',
        '`## Stories` is last, and every Story line names a test',
        'every acceptance test is a fenced block that can be run',
        'every id the spec mints is inside the session range',
        'no section is empty and no decision row is missing its why',
    ), (        # the standard
        'the spec is the card, no wider and no narrower',
        'a plan could be cut from this without asking a question',
    )),
    'plan': ((
        'one Task per Story, and no Story unclaimed',
        "every Task declares `writes:`, and no two Tasks' footprints overlap",
        "every Task's acceptance fences are byte-identical to the spec's",
        'the stated order is acyclic and every `after:` names a real Task',
    ), (
        'each Task is one session of work',
        'the order is the order the work actually needs',
    )),
    'code': ((
        'the diff stays inside `writes:`',
        'every Step of the Task is implemented',
        "the acceptance tests are byte-identical to the plan's",
        'those tests were run and are green',
        'the Gate commands are green',
        'no secret value printed, no background process, no skipped check',
    ), (
        'the change reads like the code around it',
        'the test would fail if the change were reverted',
    )),
}
```

- `cells(line)` — the splitter lifted from `evidence.cells`, unescaping `\|`.
- `parse(text)` → `([Check, …], [fault, …])`. A table begins at a line whose cells, lowercased
  and stripped of `*` and backticks, are one of `HEADERS`; the next line must be a separator
  (`| --- | --- | --- |`); rows run until the first line that does not start with `|`. Blocks are
  numbered from 1 in order of appearance. A row whose cell count is not 3 is a fault, not a row.
  A result cell that is not in `RESULTS` is a fault naming the line — **and a cell still carrying
  the skeleton (`<pass|fail>`, or anything holding `|` or `<`) is reported as unfilled**, so a
  review that never answered a row cannot be read as having passed it. An empty evidence cell
  makes the row `fail` (D9).
- `normalize(name)` — lowercase, collapse whitespace, strip backticks, `*`, a leading `-` and
  trailing `.,;:`. The one comparison used for coverage and for acceptance matching.
- `required(kind)` → the normalized mechanical names of `CHECKLIST[kind]`.
- `missing(checks, required)` → the required names no row covers, in checklist order.
- `verdict(text, required=())` → `''` when no table is present at all; `BOUNCE` when `parse`
  returned a fault or `missing` is non-empty; `CHANGES` when any row is `fail`; else `APPROVED`.
- `typed_verdict(text)` → the legacy word, the `verdict`-prefixed line first, as
  `pr_hygiene.parse_verdict` reads it today.
- `faults(text, required)` → every line the pre-review prints: the parse faults, then one
  `required check missing: "<name>"` per missing name.
- `render_table(rows)` → the skeleton: `| check | result | evidence |`, the separator, and one
  `| <name> | <pass\|fail> | ` per row.
- `passed(checks)` → the normalized names of every `PASS` row.

### 2.2 `asf review-checks` — the mechanical pre-review

```
usage: asf review-checks PATH --kind {spec,plan,code} [--card ID] [--json]
```

`PATH` is read as given (the session is in its worktree). `--card` is a Story or Task id in the
record; for `--kind code` its Stories' acceptance lines join the required set, so a code review
that quietly dropped an acceptance line is a fault. Human output:

```
== REVIEW 2-f-0053.md  kind spec, 7 checks, 2 faults
2-f-0053.md:22: row 3: result is unfilled (`<pass|fail>`)
2-f-0053.md: required check missing: "every acceptance test is a fenced block that can be run"
verdict: BOUNCE
```

Exit 1 when there is a fault, 0 when there is none — and the green run still prints its verdict
line, because `CHANGES REQUESTED` is a well-formed review, not a failure of the reviewer. `--json`
prints `{"path", "kind", "verdict", "faults": [...], "checks": [{"name", "result", "evidence",
"block", "line"}]}`, keys sorted — the typed output the tick reads.

### 2.3 The brief: the skeleton, and the pass order

`preamble.collect` gains `review_kind`: the branch prefix decides
(`conventions.branch_prefixes['spec' | 'plan']` → that kind, anything else → `code`), with
`feeder_rows.review_round(feature)[0]` as the fallback when the row carries no branch. The
review-file line names it:

```
Review file to write: `docs/reviews/2-f-0053.md` (round 2, spec checks)
```

`build.context` gains three keys — `review_kind`, `prereview_cmd` (the whole command, kind and
card filled in) and `check_table`, which is `render_table` over the mechanical rows, a blank line,
the standard rows, and — for `code` — one extra mechanical row per acceptance line of the card's
Stories. `templates/review.md` keeps its opening and its round-1 rule, and replaces the
hardcoded table with:

````markdown
A GATE RETURNS ONE CHECK PER THING IT LOOKED AT, NOT A VERDICT. Write `{review_path}` ending in
these two tables, in this order — one row per check, none removed, none added without evidence.
The verdict is derived from the rows by the tick; never type one.

### Pass 1 — mechanical
Answer every row by running something. Finish this table before you form an opinion.

{check_table}

Then run the pre-review on your own file and fix what it names:

```bash
{prereview_cmd}
```
````

The `## Stories` line the preamble already prints for a review kind (`STORY_KINDS`) is what a
code review's extra rows are built from, so the reviewer sees the same acceptance text twice —
once as the Feature's Stories, once as a row to answer.

### 2.4 `evidence` and `pr_hygiene`: the table decides

```python
def verdict_of(blob, required=()):
    """The round's verdict, derived from the check table; the legacy typed word only when the
    file carries no table at all (F-0053 D4)."""
    if not blob:
        return ""
    text = blob[:20000].decode("utf-8", "replace")
    return reviews.verdict(text, required) or reviews.typed_verdict(text)
```

`cells` becomes `return reviews.cells(line)`. The spec/plan lookup passes
`reviews.required(kind)`; the task rows pass `reviews.required('code')` and gain a second key:

```python
row["review"] = (r, verdict_of(blob, reviews.required("code")))
row["checks"] = {"path": f, "round": r, "passed": reviews.passed(checks)}   # or None
```

The `review` tuples keep their present shapes (2 for a task row, 3 for spec/plan), so
`ingest`'s `spec_review[:2]`, `feature_stage` and the board are untouched.
`pr_hygiene.parse_verdict(text)` becomes `reviews.verdict(text, reviews.required('code')) or
reviews.typed_verdict(text)`, keeping its one-argument signature and its callers.

### 2.5 `ingest`: the acceptance tick

`record.core.acceptance_items(body)` returns `[(index, checked, text, suffix)]` for every
`- [ ]` / `- [x]` bullet under `## Acceptance`; `step_prs.acceptance` keeps its own return shape
and reads it from there.

For each Story, ingest collects the Tasks whose `stories:` name it (the map it already builds),
takes each Task's `checks`, and builds `{normalized check name: review path}` over the passing
rows. Every unticked acceptance line whose normalized text is a key is rewritten:

```
- [ ] the table is parsed and the round's verdict comes from it
- [x] the table is parsed and the round's verdict comes from it — docs/reviews/3-t-0176.md
```

Two Tasks proving the same line: the first by Task id order wins, and a line already ticked with
a path is left alone (idempotent). The Story gains one evidence line and one History line:

```
evidence:
  - matrix status done (F-53-1)
  - acceptance 2/3 proven (docs/reviews/3-t-0176.md)
```

```
- 2026-09-24 07:12 ingest: acceptance ticked 2/3 (docs/reviews/3-t-0176.md)
```

The write loop changes shape: `body_edits` and `history` are computed per item, and the body is
written when either is non-empty even if `_ingest_fields` returned `None` — today a tick with no
machine change would be dropped (§1.1).

## 3. Acceptance tests

### 3.1 The grammar, and what it refuses

`reviews.parse` over a file with one table returns three `Check`s with `block == 1`, the
`\|`-escaped pipe in a check name unescaped, and no fault. Over two tables under two headings:
six rows, blocks `1,1,1,2,2,2`, in file order. A table headed `| check | ok | evidence |` parses
the same. Faults, each naming its line number: a row of two cells; a result of `approved`; a
result still reading `<pass|fail>` reported as *unfilled*, never as a pass; a header with no
separator line under it (no table found at all, no rows, no fault). A row with an empty evidence
cell parses as `fail`. `normalize` folds `` `The Gate commands are green.` `` and
`- the  gate commands are GREEN` to the same string; `required('code')` is the six mechanical
names and none of the standard ones; `missing` returns them in checklist order.
`render_table(required('spec'))` re-parses through `parse` into five rows and no fault.

```bash
python3 -m unittest -v tests.test_reviews.TableTests tests.test_reviews.NormalizeTests
```

### 3.2 The verdict is the rows

`reviews.verdict` over: every mechanical row `pass` → `APPROVED`; one row `fail` → `CHANGES
REQUESTED`; every row `pass` but one required check absent → `BOUNCE`; a table with an unfilled
result cell → `BOUNCE`; **a table whose rows all read `fail` under a typed `verdict: APPROVED`
line → `CHANGES REQUESTED`** (the word never wins); prose with a verdict word and no table →
`''`, with `typed_verdict` returning `APPROVED` for it; an empty string → `''`. `n/a` rows are
neither a fail nor a missing check: a table of `pass` and `n/a` with full coverage → `APPROVED`.
A `pass` row with an empty evidence cell → `CHANGES REQUESTED`.

```bash
python3 -m unittest -v tests.test_reviews.VerdictTests
```

### 3.3 The pre-review bounces a review with no table

`asf review-checks` through `cli.main`, over files written into a temp dir: a file with a
complete `pass` table and `--kind spec` exits 0 and prints `verdict: APPROVED`; the same file
with one row deleted exits 1 with a `required check missing:` line naming it and
`verdict: BOUNCE`; a review of nothing but prose and `verdict: APPROVED` exits 1 with
`no check table` and `verdict: BOUNCE`; a malformed row exits 1 naming its line number; a
complete table with one `fail` exits **0** and prints `verdict: CHANGES REQUESTED`. `--kind code
--card S-19950` over a fixture record whose Story has three acceptance lines requires all three:
a table missing one exits 1 naming that line's text. `--json` output parses, has sorted keys, and
its `checks` length equals the row count. A missing path exits 2 with one line and no traceback;
`--kind` omitted exits 2. No git, no network: the whole class runs with `ASF_HOME` pinned to the
temp dir.

```bash
python3 -m unittest -v tests.test_reviews.PreReviewCommandTests
```

### 3.4 Every review brief carries its kind's table

`build.build` over the fixture record for `--kind review`: on a `spec/…` branch the brief
contains all five spec mechanical checks and neither of the code ones; on a `plan/…` branch the
plan checks; on a `worker/…` branch the six code checks **plus one row per acceptance line of the
Feature's Stories**, verbatim. The `Pass 1 — mechanical` heading precedes `Pass 2`, and
`reviews.parse` over the brief's own text finds two blocks with no fault. The brief contains the
`review-checks` command with its `--kind` filled in, and the string `verdict: approved` appears
nowhere in any template. Every placeholder is still a context key, no placeholder survives into a
built brief, and no template carries a forbidden name. The golden review brief matches (it is
regenerated in this change).

```bash
python3 -m unittest -v tests.test_briefs
```

### 3.5 `evidence` derives it, and carries the passing checks

`verdict_of(blob, required('spec'))` over the six cases of §3.2 as bytes, including the
`b"Verdict: APPROVED\n"` and `b"just some prose"` of the present `VerdictOfTests` — both keep
their answers, via the legacy fallback. `cells` keeps every assertion of `ParseRowsTests`,
escaped pipe included. Over a two-branch git fixture — a spec branch carrying round 1 and 2
review files, a worker branch carrying a code review with four `pass` rows — `discover` returns
`spec_review == (2, 'CHANGES REQUESTED', '2-f-0001.md')` for a table with a `fail`, and the task
row's `checks` is `{'path': …, 'round': 1, 'passed': [the four normalized names]}`, with `checks`
`None` for a task with no review file. `pr_hygiene.parse_verdict` over the same texts answers the
same as `verdict_of` minus the bytes.

```bash
python3 -m unittest -v tests.test_evidence tests.test_pr_hygiene
```

### 3.6 The round's verdict, and the acceptance line that was proven

End to end through `cmd_ingest` on a fixture record and a stubbed evidence dict. A Feature whose
spec review's table is complete and all `pass` → `stage: spec-approved`; the same table with one
