# F-0080 — closing is derived and total

An item that stayed open is not a cosmetic defect. The feeder reads the record, and the record
says this item is not done, so the factory develops it again. The cost of a card that cannot
close is the same work twice.

Closing today is a set of arms scattered through `asf/record/ingest.py`, each reaching into
`asf/evidence/evidence.py` for one of five per-type functions, with no rule that every arm
together covers every item. Walked against the tree, four holes:

| Hole | Where | What stays open |
| --- | --- | --- |
| A Story with no Task | `evidence.story_state` (`evidence.py:926`) needs a `matrix_status`; `ingest.py:296` falls back to id tokens | every Story of a landed Feature whose Tasks named the Feature, not the Story |
| A Feature with no children | `evidence.feature_state`'s `all_tasks_closed` is `bool(child_ids) and all(...)` (`ingest.py:381`) — no children, never true | every Feature whose work landed as Bugs, or as one commit nobody named it in |
| A Bug never closes at all | `evidence.bug_state` (`evidence.py:977`) returns `Resolved` on a merge and has no `Closed` arm — "that half is T10's" | every Bug the factory has ever fixed through a typed `links:` match |
| An Epic closes only by hand | `evidence.epic_state` (`evidence.py:988`): `Closed` only if `closed: true` is typed | every Epic — and a typed status is exactly the lie this Feature exists to remove |

Under all four sits the same absence: nothing in the tree asserts that the rules are *total*.
There is no function that, given a type and its evidence, must return a state and must name the
rule that produced it — so a case with no rule falls through silently, and the only way anyone
learns is a card that is still open months later.

This spec puts one table and one function between the evidence and the record, closes the four
holes through it, gives work that predates the id-in-subject convention one groom question, and
caps the re-emission of every row kind rather than Bugs alone.

## 1. Decisions

### 1.1 In

- **`asf/evidence/closing.py`** — the definition of done, as one table (`RULES`) and one total
  function, `state_of(type_, ev) -> Closing`. Every `(type, evidence)` pair returns a state and
  the name of the rule that decided it; there is no fall-through. `Closing.rule == NO_RULE` is
  the named residue, not a silent one.
- The five per-type rules, each now reaching `Closed`: Task and Story and Feature as today plus
  the arms below, **Bug** closing on CI green plus a quiet period, **Epic** closing on its
  children.
- **Descent** — a Feature that closes closes the evidence-free children beneath it: a Story with
  no Task of its own, a Task with no branch and no commit. A child whose own evidence contradicts
  (an Active Task, an open PR) is never closed by its parent.
- **`Closed` is terminal.** `ingest` never derives an item back out of `Closed`; the attempt is
  recorded as one `evidence:` line. This is the guard that makes "nothing re-emitted" hold
  against an evidence source that goes quiet (a deleted branch, a pruned CI history).
- **Reconciliation** — work that predates the id-in-subject convention gets exactly one groom
  question, in one new section, and the answer writes *evidence*, never a state:
  `landed: <sha>`, `reconciled: <date>` or `removed:`. A question answered once is never asked
  again.
- **The attempt cap over every launching row kind**, not `BUG → FIX` alone: `CARD → SPEC`,
  `STARVED → SPEC`, `STARVED → PLAN`, `PLAN → CODE`, `CONFLICT → REBASE`, `STALE → CLOSE`.
  At the limit, one `STALEMATE → ADJUDICATE`; above it, silence.
- **`asf status`'s totality line** — the count of items no rule can see, so a new hole is visible
  the day it opens rather than in a quarter's retrospective.
- `tests/test_closing.py`, plus the arms in `tests/test_ingest.py`, `tests/test_groom.py`,
  `tests/test_groom_policy.py` and `tests/test_feeder.py`.

### 1.2 Out

- **Changing what the evidence pass collects.** `evidence.discover`, `evidence.id_evidence`,
  `evidence.main_commits` and the `--since` window are untouched. This spec changes how the
  collected evidence is *read*, never what is read. One exception is additive and named in §2.5:
  `id_evidence` also reads the typed `landed:` sha, so a reconciled item's evidence arrives
  through the same map as everyone else's.
- **The `Resolved → Closed` production step for a product that deploys.** `prod_sha`, the
  operator's checked ✓ and B-0077/B-0078's "the trunk IS production where nothing deploys" stay
  exactly as `ingest.py:348-398` has them. Closing is made *total*; what "in production" means is
  still the product's own.
- **Reopening.** Nothing here reopens a Closed item. A card closed wrongly is corrected by the
  operator editing the record, which is a person's act on a person's field, and the History line
  says who.
- **The groom's existing sections.** `Features without Stories` and `Stories without Tasks after
  plan-approved` already ask about a shapeless *new* Feature. Reconciliation is only for what
  predates the marker; the two never ask about the same item (§2.5, the `predates` predicate).
- **B-0026's cap on `BUG → FIX`.** It is already in the tree (`rows.bug_rows`, `rows.py:190`) and
  is not rewritten — it is the shape the other kinds are brought up to.
- **A second definition of "open".** `asf.feeder.rows.is_open` (`Resolved` counts as done) and
  `asf.record.core.is_open` (`Resolved` counts as open) both stay. They answer different
  questions — "should a session run on this" and "is this item still live in the record" — and
  the choice row below says why collapsing them is the wrong move in this Feature.
- **Closing a Feature from an Epic.** Descent runs downward from a Feature only. An Epic's own
  closing is derived from its children and never pushed onto them.

### 1.4 The choices

| Choice | Chosen | Against | Why |
|---|---|---|---|
| Where the definition of done lives | a new `asf/evidence/closing.py` | more arms in `ingest.py`; more functions in `evidence.py` (1056 lines) | The card's word is *total*: totality is a property of the table taken together, and a property needs a place to be asserted. Split across five functions and eight `ingest` branches, "every case is covered" is not a statement anything can test. |
| Total, or best-effort | total — `state_of` returns a `Closing` for every input, `NO_RULE` included | returning `None` when no rule matches, as `id_state` does today | `None` is how the four holes stayed invisible: the caller shrugged and kept the old state. A named `NO_RULE` is counted by `asf status` (§2.7) and read by reconciliation (§2.5); a hole becomes a number on a screen. |
| How a rule is identified | every `Closing` carries `rule`, and the rule name goes into the `evidence:` lines and the History line | the state alone | "Closed (derived)" tells an operator nothing. `Closed (rule: parent-closed; F-0021 Closed 2026-09-14)` tells them which clause fired and what to argue with. It is also what makes the acceptance tests assertions about *rules* rather than about states. |
| Does a Bug close | yes — green CI on its fix plus `bug_quiet` (default 3d) with the signature unseen | leave it at `Resolved` and wait for T10 | `evidence.bug_state`'s own docstring defers the closing half to a Task that is not in the tree, and the result is that no Bug matched through typed `links:` has ever closed. The quiet period is two facts the record already holds: the merge date and `count`/`last_seen` on the card. Deferring it again is the exact "stays open forever" this Feature exists to end. |
| A Bug with no `signature` | closes on green CI alone | never closes | A Bug filed by hand has no signature to go quiet. Making the quiet period mandatory would swap one permanently-open class for another. |
| Does an Epic close by hand | no — derived from its children; `closed: true` is read only as an *early* close | keep `closed: true` as the only route | The card: "an operator names nothing by hand (a typed status lies)". A typed `closed: true` remains honoured, because an operator closing an Epic early is a decision and not a lie about evidence; what is removed is the *requirement* for it. |
| Descent | a closing Feature closes its evidence-free children | leave every child to its own evidence | This is what makes closing total without inventing evidence. A Story exists because a spec named it; when the Feature that spec described is on the trunk, closed and green, the Story's work is in that trunk whatever the commit subjects said. A child with contradicting evidence is excluded, so descent can never close live work. |
| Descent's direction | downward from a Feature only | Epic → Feature as well | An Epic is a business outcome; its Features are separately deployable and separately abandonable. "Everything under this Epic is done because the Epic is done" is circular — the Epic is derived from those Features. |
| `Closed` terminal | yes — ingest never derives out of `Closed` | pure derivation both ways | Pure derivation re-opens a card when an evidence source goes quiet, and a re-opened card is a re-emitted row, which is the Feature's third clause. `Closed` is the one state where the cost of being wrong in one direction (work done twice) exceeds the other (a card an operator edits once). Every other state stays freely derived in both directions. |
| Who answers "did this pre-marker work land" | the operator or the adjudicator, through one groom question | a heuristic over commit subjects and dates | The marker is precisely what is missing; a heuristic over its absence is a guess, and a guess here closes a card that is not done. The groom already has the grammar, the suppression pass, the adjudicate row and the answers file — the question costs one section. |
| What the answer writes | a typed *evidence* field — `landed: <sha>` | a typed `state: Closed` | The card's last line: "an operator names nothing by hand (a typed status lies)". The operator supplies the evidence they can see and the derivation stays the only thing that names a state. It also means the answer is checkable: `landed:` is a sha, and `asf check` verifies it exists on the trunk. |
| The third answer | `reconciled: <date>` — "asked, genuinely still to do" | ask again next groom | An item that really is unfinished must not be asked about every groom day forever; that is the re-emission defect wearing a groom's clothes. One typed date ends the question and leaves the item's state entirely to the ordinary rules. |
| When the marker date comes from | `conventions.id_in_subject_since`, per product, unset by default | a constant `2026-09-21` in the code | The date is this product's own history. A constant in a package that other products install would ask every one of them about work that was never ours. Unset means no item predates the marker and no question is ever asked — the timid default the groom's D11 already chose for its policies. |
| The attempt cap's shape | one `attempts` map threaded to every row builder, reusing `conventions.attempt_limit` | a new per-kind limit; a cap on the wave instead | `bug_rows` proved the shape and the tick already computes the map (P7). One limit for "how many sessions does the factory spend on one item before a human-shaped judgement" is the honest knob; a per-kind table is configuration nobody can reason about. |
| Above the cap | silence, after exactly one `STALEMATE → ADJUDICATE` | silence at the limit, with no adjudicate row | Identical to `bug_rows` today: the adjudicate session is itself the next attempt, so the row disappears once it has run. Silence with no adjudication would hide a stuck Feature entirely. |
| Collapsing the two `is_open`s | no | one shared predicate | They are two questions: the feeder asks "should a session run", where `Resolved` is done; the record asks "is this live", where `Resolved` is not. Collapsing them in this Feature would either re-emit every Resolved item or make a Resolved item invisible to the groom that must still close it. The names are already distinct modules; a comment in each pointing at the other is the whole fix warranted here. |
| Where the residue is surfaced | one line in `asf status` | a new command; a report file | Nothing new to remember to run. The number is 0 in a healthy record; a non-zero one is the only signal that a rule is missing, and it belongs beside the other counts an operator already reads every tick. |

## 2. The design

### 2.1 `asf/evidence/closing.py` — the table and the one function

```python
"""asf.evidence.closing — the definition of done, one table, total.

Every item's state comes from exactly one rule of RULES, and RULES is exhaustive: for any
(type, evidence) pair `state_of` returns a Closing naming the rule that decided it, NO_RULE
included. `asf.record.ingest` matches items to evidence; it derives no state of its own."""

NEW, ACTIVE, RESOLVED, CLOSED = 'New', 'Active', 'Resolved', 'Closed'
NO_RULE = 'no-rule'          #: named residue — reconciliation's input, and `asf status`' count

@dataclasses.dataclass(frozen=True)
class Closing:
    state: str                #: New | Active | Resolved | Closed
    rule: str                 #: the clause that decided it — written into evidence: and History
    lines: tuple = ()         #: the evidence lines, as ingest writes them today

@dataclasses.dataclass
class Ev:
    """What a rule is handed. Null per field, so a test states exactly the evidence it means."""
    commit: str = ''          #: a commit on the trunk naming it (evidence.id_evidence)
    green: bool = False       #: CI green at or after that commit; True when the product has no CI
    merged_sha: str = ''      #: a PR of its own, merged
    branch: str = ''
    pr_state: str = ''
    open_prs: tuple = ()
    children: tuple = ()      #: the derived states of its own children
    child_evidence: bool = False   #: any child carries a branch, an open PR or an Active state
    spec_on_main: bool = False
    plan_approved: bool = False
    matrix_status: str = ''   #: a Story's row in the plan's matrix
    in_prod: bool = False     #: merges in the deploy AND the operator's ✓ (or no deploy at all)
    signature: str = ''
    quiet_for: float = 0.0    #: seconds the signature has been unseen
    quiet_limit: float = 0.0  #: stage_limits.bug_quiet, in seconds
    landed: str = ''          #: the typed reconciliation sha (§2.5)
    parent_closed: bool = False
```

`RULES` is a tuple of `(type, name, predicate, state)` read in order — the first whose predicate
holds decides, and the prose column is the same text `docs/README` and `asf rules` render:

| type | rule | holds when | → |
| --- | --- | --- | --- |
| any | `reconciled` | `ev.landed` and `ev.green` | `Closed` |
| any | `parent-closed` | `ev.parent_closed` and no evidence of its own | `Closed` |
| task | `landed-green` | `ev.commit` (or `ev.merged_sha`) and `ev.green` | `Closed` |
| task | `landed` | `ev.commit` or `ev.merged_sha` | `Resolved` |
| task | `in-flight` | `ev.branch` or `ev.pr_state` | `Active` |
| task | `planned` | otherwise, when the Task is in a plan | `New` |
| story | `tasks-closed` | `ev.children` and every one `Closed`, and `ev.in_prod` | `Closed` |
| story | `tasks-resolved` | `ev.children` and every one in `(Resolved, Closed)` | `Resolved` |
| story | `matrix-done` | `ev.matrix_status == 'done'` | `Closed` |
| story | `matrix-doing` | `ev.matrix_status == 'doing'` | `Resolved` |
| story | `task-active` | any child `Active`, or `ev.child_evidence` | `Active` |
| story | *(else)* | — | `NO_RULE`, state carried |
| bug | `quiet` | `ev.merged_sha or ev.commit`, `ev.green`, and (`not ev.signature` or `ev.quiet_for >= ev.quiet_limit`) | `Closed` |
| bug | `fixed` | `ev.merged_sha` or `ev.commit` | `Resolved` |
| bug | `fixer` | `ev.branch` or `ev.open_prs` | `Active` |
| bug | `filed` | otherwise | `New` |
| feature | `children-closed` | `ev.children`, every one `Closed`, and `ev.in_prod` | `Closed` |
| feature | `children-resolved` | `ev.children` and every one in `(Resolved, Closed)` | `Resolved` |
| feature | `landed-green` | no children, `ev.commit`, `ev.green` and `ev.in_prod` | `Closed` |
| feature | `landed` | no children and `ev.commit` | `Resolved` |
| feature | `documented` | `ev.spec_on_main` or `ev.plan_approved` | `Active` |
| feature | `card` | otherwise | `New` |
| epic | `children-closed` | `ev.children` and every one `Closed` | `Closed` |
| epic | `typed-closed` | the operator typed `closed: true` | `Closed` |
| epic | `children-resolved` | `ev.children`, every one in `(Resolved, Closed)` | `Resolved` |
| epic | `child-active` | any child `Active` | `Active` |
| epic | `typed` | otherwise | `New` |

`state_of(type_, ev, current)` walks the rules for `type_`, returns the first match, and
otherwise returns `Closing(current, NO_RULE)` — the item keeps the state it had and is counted
as residue. The Bug and Epic rows are the two holes of the opening table closed; the Story's
`tasks-closed`/`tasks-resolved` and the Feature's `landed-green`/`landed` rows are the other
two, and descent (§2.4) is what reaches a Story or Task that has nothing at all.

`sticky(old, new)` is the terminal rule, applied by `ingest` to every derivation:

```python
def sticky(old, closing):
    """`Closed` never derives backwards (§1.4). Returns the closing that gets written."""
    if old == CLOSED and closing.state != CLOSED:
        return dataclasses.replace(closing, state=CLOSED, rule='closed-terminal',
                                   lines=closing.lines + (f"held Closed; {closing.rule} would say "
                                                          f"{closing.state}",))
    return closing
```

### 2.2 `asf/record/ingest.py` — matching only

The five per-type blocks keep every line that *matches* an item to evidence (`match_task`,
`match_story`, `match_bug`, `match_feature`, `match_ids`) and every line that builds the
`evidence:` prose. What each block loses is its own state choice: `evidence.task_state(...)`,
`evidence.story_state(...)`, `evidence.bug_state(...)`, `evidence.feature_state(...)` and
`evidence.epic_state(...)` are each replaced by filling an `Ev` and calling `closing.state_of`.
The five functions stay in `evidence.py` as the rules' bodies where the logic is unchanged, and
`closing.RULES` calls them; nothing in `evidence.py` is deleted in this Feature.

The B-0074 arm is unchanged in its meaning and becomes a rule rather than an early `continue`: a
trunk landing outranks a plan's task table, because `landed-green`/`landed` are read before
`in-flight` for a Task.

The pass order gains one step:

```
tasks → stories → bugs → features → descent → epics → write
```

### 2.3 What a closed item's record looks like

```yaml
# ---- machine ----
state: Closed
stage: landed
stage_since: 2026-09-23T18:40:12Z
evidence:
  - commit 9f2ac41 names T-0052 (PR #318)
  - CI green on main at or after it
  - rule: landed-green
updated: 2026-09-23T18:40:12Z
```

and one History line:

```
- 2026-09-23 18:40 ingest: state Resolved → Closed (rule: landed-green; commit 9f2ac41 names T-0052; CI green on main at or after it)
```

The `rule:` line is the last `evidence:` entry for every item, so `grep -c 'rule: no-rule'` over
the record is the residue and needs no tooling.

### 2.4 Descent — closing what a landing covered

After the Feature pass and before the Epic pass:

```python
def descend(canonical, new_state, closings, derived):
    """A Feature that closed closes the children beneath it that have no evidence of their own.

    A child is evidence-free when `closing.rule == NO_RULE`, or its state is New with no branch,
    no PR and no commit naming it. A child with any evidence of its own — an Active state, an
    open PR, a branch — keeps the state its own rule gave it: descent may not overrule evidence,
    only reach where there is none."""
```

Descent is one level at a time and runs to a fixed point within the Feature's subtree (Feature →
Story → Task), so a Task hanging off a Story of a closed Feature closes too. Its rule name is
`parent-closed`, and its evidence line names the parent and the sha that closed it:

```
- rule: parent-closed
- F-0021 Closed 2026-09-14 (commit 3b91ce7)
```

A Bug is never closed by descent: a defect under a landed Feature is still a defect, and its own
`quiet` rule is what says it is gone.

### 2.5 Reconciliation — one question, once

**The marker.** `conventions.id_in_subject_since` — an ISO date, unset by default. An item
`predates` it when its `created` (falling back to `stage_since`) is earlier **and** the evidence
pass found no commit, no PR and no branch naming it, **and** it is not `Closed`, **and** it
carries none of `landed:`, `reconciled:` or `removed:`. The predicate lives in
`closing.predates(item, ev, since)` so the groom and the status line ask it the same way.

**The question.** One new groom section, after the two shape sections:

```python
GROOM_SECTIONS = [
    ...
    ('Landed before the id convention', 'predates'),
    ...
]
```

rendered as one line per item, in `created` order:

```
- [ ] F-0031 the harvest publishes a rebased lane branch — created 2026-09-11, before the id
  convention (2026-09-21); no commit, PR or branch names it → answer: ____
```

`policy.suppress` runs over it unchanged, so an item a session is on right now is marked
`(spoken for: <ROW KIND>)` and asked of nobody. No policy answers this section — the marker's
absence is exactly what no rule can see (§1.4) — so its questions go to the adjudicate row and,
above `groom.adjudicate_attempts`, to the operator's digest.

**The answers.** `groom._parse_answer` gains two words:

| answer | field written | meaning |
| --- | --- | --- |
| `landed <sha>` | `landed: <sha>` (typed) | it is on the trunk at this sha; derive from there |
| `no` | `removed: groom <date>` (as today) | it never landed and is not wanted |
| `open` | `reconciled: <date>` (typed) | genuinely still to do — never ask again |

`apply_groom_answers` writes each through `frontmatter.write_typed` (P2) with the usual History
line and the usual `groom_answer` event, `section: predates`.

**The derivation.** `evidence.id_evidence` reads the typed `landed:` sha as one more source for
that id — the same map, the same `green` computation through `ancestor_of` — so a reconciled
item closes by the ordinary `reconciled` rule at the next `asf ingest`, with the same
`CI green on main at or after it` line every other closed item carries. Nothing about
reconciliation is a special path through closing; it supplies the evidence the marker would have
supplied, and then stands aside.

**Asked once.** All three answers make `predates` false, permanently. An item answered `open` is
asked no more and is left to the ordinary rules; if its work later lands with its id in the
subject, it closes like anything else.

### 2.6 Nothing re-emitted

Three guards, in the order they bite:

1. **A done item is not a row.** `rows.is_open` treats `Resolved` and `Closed` as done (P8), so
   every item this Feature closes leaves the feeder in the same tick. This is the whole of the
   first clause: the closing rules *are* the re-emission fix.
2. **`Closed` is terminal** (§2.1's `sticky`), so an item cannot fall back out of done and be
   emitted again when an evidence source goes quiet.
3. **The attempt cap over every launching kind.** `attempts` is threaded to `feature_rows`,
   `task_rows` and `branch_rows` exactly as `bug_rows` takes it today:

```python
def _capped(row, attempts, limit, product):
    """None above the limit; the STALEMATE row at it; the row itself below it (rows.bug_rows)."""
    n = attempts.get(row.item_id, 0)
    if n > limit:
        return None
    if n == limit:
        return dataclasses.replace(
            row, kind=STALEMATE, brief_kind='adjudicate', action=LAUNCH,
            reason=f"{row.kind} after {n} sessions: adjudicate, not another attempt")
    return row
```

`candidates` applies it to every row whose `action` is `LAUNCH` and whose kind is not already
`STALEMATE` or `GROOM → ADJUDICATE`; a `WAITS ON …` row is never capped, because it launches
nothing and its text is how an operator sees why a Task is held.

### 2.7 The residue is visible

`asf status` gains one line under the record's counts:

```
**RECORD** — 41 open · 12 Active · 0 blocked · 0 no rule
```

`0 no rule` is the healthy record. A non-zero count links nothing and explains nothing on the
status screen; `asf check` is where the list is, one finding per item:

```
backlog/stories/s-0104.md:1: no closing rule sees this item (type story, no Task, no matrix row,
  parent F-0021 is Active) — it can never close; see docs/specs/f-0080.md §2.1
```

This is the property the four holes of the opening table were missing. A Story added tomorrow
whose shape no rule covers is a `check` finding on the day it is written.

## 3. Acceptance tests

All run from the repo root.

### 3.1 The table is total

```bash
python -m unittest tests.test_closing -v
```

`TotalityTests` covers, over hand-built `Ev`s, with no git and no clock:

- `state_of` returns a `Closing` whose `state` is one of the four states for **every** `(type,
  Ev)` pair the generator produces — types crossed with the presence/absence of each `Ev` field
  — and never raises;
- every returned `rule` is a name in `RULES` for that type, or `NO_RULE`;
- the four holes of the opening table, each as one test: a Story with no Task and a closed
  parent; a Feature with no children and no naming commit; a Bug with `merged_sha` and green CI
  past `bug_quiet`; an Epic whose every child is `Closed` with no `closed: true` typed — all
  four return `Closed`, and each names its rule (`parent-closed`, `landed-green`/`reconciled`,
  `quiet`, `children-closed`);
- a Bug with no `signature` closes on green alone; one with a signature seen `quiet_for` under
  the limit stays `Resolved`;
- an Epic with `closed: true` typed and an Active child is `Closed` by `typed-closed` — the
  early close is still honoured;
- `sticky`: `Closed` + a rule saying `Active` yields `Closed` with rule `closed-terminal` and an
  evidence line naming what the rule would have said; every other transition passes through
  untouched, both directions;
- the rule *order* is what B-0074 asserts: a Task with both a merged trunk commit and an open PR
  is `Closed`, not `Active`.

### 3.2 Ingest derives no state of its own

```bash
python -m unittest tests.test_ingest -v
```

Covers, on the existing fixtures: `CmdIngestEndToEndTests` still passes unchanged for every case
it already holds (a Task landing, a Feature building, `ProductionIsTheProductsOwn`'s deploy and
no-deploy products, `LandingOutranksThePlan`, `RemovedTaskTests`); plus new cases — every closed
item's `evidence:` ends with a `rule: <name>` line; the History line quotes the rule; a second
`asf ingest` with the same evidence writes nothing (P10); and a structural test asserting
`ingest.py` calls no `evidence.*_state` function directly, so a sixth state choice cannot grow
back into it.

### 3.3 Descent closes what a landing covered

```bash
python -m unittest tests.test_ingest.DescentTests -v
```

Covers: a Feature Closed on a green trunk commit, with one Story that has no Task and one Story
whose Task is `Active` → the first closes with rule `parent-closed` and an evidence line naming
the Feature and its sha, the second does not move; a Task under the childless Story closes too
(the fixed point); a Bug under the closed Feature stays open; and descent writes nothing when the
Feature is merely `Resolved`.

### 3.4 Reconciliation asks once and writes evidence

```bash
python -m unittest tests.test_groom tests.test_groom_policy -v
```

Covers:

- with `conventions.id_in_subject_since` unset, the `predates` section is empty and no question
  is asked — the timid default;
- with it set, an item created before it and named by nothing gets exactly one line; an item
  created after it, an item with a branch, and an item already `Closed` get none;
- `policy.suppress` marks the line `(spoken for: CARD → SPEC)` when the feeder would launch on
  that item, and leaves it open otherwise;
- `landed 9f2ac41` writes typed `landed: 9f2ac41`, one History line and one `groom_answer` event
  with `section: predates`, `field: landed`; `open` writes `reconciled: <date>`; `no` writes
  `removed:` as every `no` does today;
- re-running `--apply` for the same date changes nothing (the field is already at its value);
- after any of the three answers the next `asf groom` renders no line for that item — the
  question is never re-asked.

### 3.5 A reconciled item closes through the ordinary rules

### 3.6 Nothing is re-emitted

```bash
python -m unittest tests.test_feeder -v
```

Covers:

- an item this Feature closes produces no row of any kind in the next `candidates()`;
- the cap over every launching kind: a Feature at `card` with `attempts = 3` yields one
  `STALEMATE → ADJUDICATE` instead of `CARD → SPEC`, and with `attempts = 4` yields nothing;
  the same for `STARVED → SPEC`, `STARVED → PLAN`, `PLAN → CODE`, `CONFLICT → REBASE` and
  `STALE → CLOSE`;
- a `WAITS ON …` row is never capped and never turned into an adjudicate row;
- `bug_rows`' existing behaviour is byte-identical — its own tests, including B-0026's ordering
  test (`tests/test_feeder.py:428`), pass unchanged;
- a `Closed` item whose evidence has vanished from the index stays `Closed` and stays unemitted
  (the `sticky` rule, end to end through ingest and the feeder).

## 4. Records

**Machine block.** No new key. `evidence:` gains one last entry per item, `rule: <name>`, and
`state` reaches `Closed` for the four types that could not reach it. `stage_since` moves on the
transition exactly as it does today.

**Typed fields.** Two new, both written only by `apply_groom_answers` through
`frontmatter.write_typed`, both carrying their own History line:

```yaml
landed: 9f2ac41            # a sha on the trunk — the evidence the marker would have carried
reconciled: 2026-09-23     # asked, and genuinely still to do: never ask again
```

`asf check` validates `landed:` as a 7–40 character hex sha and reports it when the commit is not
on the trunk. Neither field is ever written by `ingest`, and neither names a state.

**History.** One line per transition, as today, with the rule quoted:

```
- 2026-09-23 18:40 ingest: state Active → Closed (rule: parent-closed; F-0021 Closed 2026-09-14 (commit 3b91ce7))
- 2026-09-23 09:12 groom: landed → 9f2ac41 (operator)
```

**The groom file.** One new section, `## Landed before the id convention`, rendered only when it
has lines — empty for every product that leaves `id_in_subject_since` unset, and empty forever
after the one groom day that answers it.

**Events.** No new event kind. `groom_answer` carries `section: predates` and
`field: landed | reconciled | removed`, so `asf metrics` counts the reconciliation pass with the
counter it already has.

**Printed.**

| Where | Was | Is |
| --- | --- | --- |
| `asf status`, RECORD | `41 open · 12 Active · 0 blocked` | `41 open · 12 Active · 0 blocked · 0 no rule` |
| `asf check` | silent on a Story no rule sees | one finding naming the item, the gap and §2.1 |
| `asf ingest`, History | `state Active → Closed (derived)` | `state Active → Closed (rule: parent-closed; …)` |

**Not written.** Nothing rewrites a card already on disk. An item whose state does not change is
not touched (P10), so this Feature's first ingest writes only the items it actually closes, and
the diff is the audit.

## Stories

- S: `closing.state_of` is total — every (type, evidence) pair returns a state and names the rule that decided it, `no-rule` included — acceptance: `tests.test_closing.TotalityTests` (§3.1), the generated cross-product of types and evidence fields
- S: Each of the five types has a definition of done that reaches `Closed`, and the four holes — a Story with no Task, a Feature with no children, a Bug at `Resolved` forever, an Epic that closes only by hand — close through it — acceptance: `tests.test_closing.TotalityTests` (§3.1), one test per hole asserting the state and the rule name
- S: A Bug closes on green CI plus `stage_limits.bug_quiet` with its signature unseen, and a Bug with no signature closes on green alone — acceptance: `tests.test_closing.TotalityTests` (§3.1), the quiet-period cases
- S: An Epic closes when every child is Closed, derived; a typed `closed: true` is honoured as an early close and is no longer required — acceptance: `tests.test_closing.TotalityTests` (§3.1), the Epic rows of §2.1
- S: `ingest` matches evidence and derives no state of its own — every closed item's `evidence:` and History line quote the rule — acceptance: `tests.test_ingest` (§3.2), including the structural test that `ingest.py` calls no `evidence.*_state` directly
- S: Closing descends — a Feature that closes closes the evidence-free Stories and Tasks beneath it, and never a child whose own evidence contradicts — acceptance: `tests.test_ingest.DescentTests` (§3.3)
- S: `Closed` is terminal — no derivation moves an item back out of it, and the attempt is recorded as an evidence line — acceptance: `tests.test_closing.TotalityTests` (§3.1, `sticky`) and `tests.test_feeder` (§3.6, end to end)
- S: Work that predates `conventions.id_in_subject_since` is asked about exactly once, in one groom section, and never when a session is already on it — acceptance: `tests.test_groom` and `tests.test_groom_policy` (§3.4)
- S: A reconciliation answer writes evidence and never a state — `landed: <sha>`, `reconciled: <date>` or `removed:` — each with its History line and its `groom_answer` event — acceptance: `tests.test_groom` (§3.4), including `--apply` idempotence
- S: An item carrying `landed:` closes through the ordinary rules at the next ingest, with the same evidence lines any landed item carries — acceptance: `tests.test_evidence` and `tests.test_ingest.ReconciledTests` (§3.5)
- S: Every launching row kind is capped at `conventions.attempt_limit` — one adjudicate row at the limit, silence above it — and a closed item produces no row at all — acceptance: `tests.test_feeder` (§3.6)
- S: The residue is visible — `asf status` counts the items no rule sees and `asf check` reports one finding each — acceptance: `tests.test_views` and `tests.test_backlog` (§3.7)
