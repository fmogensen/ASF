# F-0232 — the card's headline remedy landed as a hotfix; this spec is the complement

The card asks for a Task whose `writes:` touches the amendable set to be routed to the console at
plan time instead of spent on a refused worker launch. **That is already built.** It landed as a
hotfix on the same day the card's own cited sha was HEAD:

```
1b0fadcdd 2026-09-27 fix(feeder): route amendable-set Tasks to the console at plan time;
                     the hook judges runs, not text (#173)
```

The card cites `origin/main` at `3465cf21d` (`2026-09-27`, `T-0236 — the deployed sha has one
owner`, #116) and states that "the only check is the run-time hook refusal". `1b0fadcdd` post-dates
that sha by hours, and its own commit body names the same five refusals the card does (T-0183,
T-0259, T-0288, T-0301, T-0303 on 2026-09-27). It shipped exactly the design the card's first
proposal sketches — `amendable.reaches` glob-vs-glob, a non-launching row, `waits_on`, no session,
no slot — plus an announce pass the card does not ask for. `F-0126` (`c6558fcb8`, `2026-09-28`) then
extended it to the delivery union and the correction path.

## The residual defect: the bundled Task

`amendable.reaches` returns **the first** `writes:` glob that overlaps the set, and
`console_amend_row` routes the **whole Task** on that one hit. A Task whose footprint mixes an
amendable path with ordinary code therefore drags the ordinary code to the console — where no
coder will ever write it, and a human must hand-write the lot. Reproduced in this worktree at
`2ee21d8ae` against the live product:

```console
$ python3 -c "
from asf import env, amendable
p = env.load_product(None)
print(amendable.reaches(p, ['asf/briefs/build.py', 'asf/briefs/templates/plan.md']))
print(amendable.reaches(p, ['asf/briefs/build.py']))
"
asf/briefs/templates/plan.md
None
```

One glob in ten sends all ten to the console. Nothing in the row, the reason, or the
`NEEDS OPERATOR` line tells the operator that nine of them did not have to come — the reason names
only the hit:

```python
reason=f'writes: {hit} is in the amendable set — no worker session edits it; the '
       f'console makes the edit on {branch}'
```

And nothing upstream stops the planner writing that Task in the first place, because no planner
brief has ever mentioned the amendable set:

```console
$ if grep -ln amendable asf/briefs/templates/*.md; then echo 'a brief names it'; else echo 'none does'; fi
none does
```

This spec closes those three gaps: **name** the bundling where the operator already reads it,
**report** it at plan time, and **tell the planner** not to write it.

## The design

### 1. `amendable.partition` — the two-way split

New, in `asf/amendable.py`, next to `reaches` (after `:152`). `reaches` keeps its exact signature,
semantics and callers; it is re-expressed over `partition` so there is one matcher, not two.

```python
def partition(product, globs):
    """``(inside, outside)`` — the globs of ``globs`` that reach the amendable set
    (:func:`reaches`'s own two-way test) and those that do not, each in the order given.
    A Task whose ``writes:`` splits non-empty on both sides is *bundled*: the console must
    edit the ``inside`` half and no worker session may, so the ``outside`` half is dragged
    to a writer that should never have had it (F-0232)."""
    inside, outside = [], []
    for g in globs:
        (inside if reaches(product, [g]) else outside).append(g)
    return inside, outside
```

`reaches(product, globs)` is unchanged in behaviour: it still returns the **first** reaching glob or
None. (`partition(product, globs)[0][:1]` is the same answer; `reaches` is not rewritten in terms of
it, because `reaches` short-circuits on the first hit and `partition` must not.)

`bundled(product, globs)` is **not** added: the two-element test `inside and outside` reads plainly
at each of the three sites and a third name over the same two lists is one more thing to keep true.

### 2. The row and the announce name the dragged globs

`asf/feeder/rows.py`, `console_amend_row` (`:638-652`). The row gains no field — `Row.amend`
already carries the hit — but its `reason` names the split when there is one:

```python
hit = amendable.reaches(product, list(writes or ()))
if not hit:
    return None
_inside, outside = amendable.partition(product, list(writes or ()))
reason = (f'writes: {hit} is in the amendable set — no worker session edits it; the '
          f'console makes the edit on {branch}')
if outside:
    reason += (f'; split first: {", ".join(outside)} '
               f'{"is" if len(outside) == 1 else "are"} outside the set and needs no console')
```

A Task wholly inside the set renders the reason it renders today, byte for byte. `tier`, `kind`,
`action`, `waits_on`, `amend`, `branch` and `brief_kind` are untouched, so nothing about capacity,
holds, or which rows are launching moves.

`asf/approvals.py`, `announce_console_amends` (`:1128-1146`). The `NEEDS OPERATOR` line gains the
same clause, and only when there is one:

```
NEEDS OPERATOR: T-0601 writes asf/briefs/templates/plan.md (amendable set) — no worker session
  edits it: the console makes the edit on worker/T-0601 and pushes it; split first:
  asf/briefs/build.py is outside the set and needs no console
```

The dedupe is unchanged: the `amend-announced` ledger line still keys on `item`, still carries no
`hold` key, and the line is still said once however many ticks show the row. The function needs the
row's `writes:` to compute the split, which the `Row` does not carry — so it reads it from the item
the way the rest of the module reads items, or `console_amend_row` stores the outside list on the
row. **Chosen: the row carries it**, as `Row.amend_outside` (a tuple, default `()`), because
`announce_console_amends` takes `rows` and no index, and threading an index into it to re-derive a
list the row-builder already computed is a second traversal for no gain.

### 3. `asf check` reports every bundled Task

`asf/record/check.py`. A new check in the house shape (P8), called from `record_findings` beside the
other two at `:292-293`:

```python
def check_amendable_bundles(canonical, warn, find_line, amendable_globs=()):
    """F-0232: a Task whose ``writes:`` mixes the amendable set with paths outside it sends the
    whole footprint to the console — a human then hand-writes code a coder should have. A
    warning, not a finding (D5): the footprint is the planner's to split, and a Task wholly
    inside the set is correctly served by the console today."""
```

It is a warning, so it prints and never changes the exit code (D5, P8). The matcher is
`amendable.partition` over the resolved globs — `record_findings` stays product-free (D9), so the
signature threads the set the way `shared` is threaded:

- `record_findings(root, scrub=None, layout=True, shared=(), amendable_globs=())`
- `cmd_check` (`:139`) resolves it beside `shared`, and passes it at `:146`;
- `cmd_check_staged` (`:395`) takes it and threads it into all three `record_findings` calls
  (`:425-430`), so the staged comparison judges both trees with the same set.

Resolving it at the edge needs a product-free pair, since `amendable.partition` takes a product.
`asf/amendable.py` gains the thin accessor the edge calls —

```python
def glob_set(product):
    """``(paths, excluded)`` for ``product`` — what an edge resolves once and threads to a
    product-free reader, as ``footprint.shared_globs`` does for ``conventions.shared_paths``."""
    return (paths(product), excluded(product))
```

— and `partition`/`reaches` gain an optional `glob_set=None` that, when given, is used instead of
re-reading the product. `product` stays the first positional parameter of both, so every landed
caller is unchanged.

Only an **open** Task is judged (`is_open(rec)`, as the size check at `:297` does): a Closed Task's
footprint is history, and warning about it every run is noise no one can clear.

### 4. The planner is told, with the set in front of it

`asf/briefs/build.py`, `context` (`:365-400`). One new key:

```python
'amendable_globs': ', '.join(amendable.paths(product)) or '(none)',
```

Absent from no brief and read by two (P12). A ctx key no template names is inert — `render` errors
only the other way round (P11) — so this lands green on its own, which is what makes S4 orderable
behind it (D7).

`asf/briefs/templates/plan.md` and `asf/briefs/templates/spec-plan.md` — **a console amendment, not
a coder** (P14). Under the TASK LINES block that defines `writes:` (P13), after the line about two
Tasks whose `writes:` intersect:

```
A path in the amendable set — {amendable_globs} — is edited by the console, never by a coder
session. Give every such path its own Task: a Task whose `writes:` mixes one in with ordinary
code sends the whole footprint to the console, and a human then hand-writes the code a coder
should have written.
```

The set is interpolated rather than spelled out, so a product that names its own
`conventions.amendable_paths` gets its own list and not this product's (P3, `source='default'` here
and `'yaml'` there).
