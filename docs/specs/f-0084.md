# F-0084 — one surface, one voice, and the writes marked

The card was evaluated on 2026-09-21 over 30 commands. On 2026-09-28 `asf --help` prints **49**,
and the longest description runs 139 characters — a paragraph argparse wraps onto three lines.
Nineteen commands arrived in a week, each with a description written by whoever added it, in
whatever voice they were in. That is the real defect: not the nineteen lines, but that nothing in
the tree has an opinion about what a description is, so every new command widens the gap.

Walked against the current surface, the card's five findings all still hold:

| Finding | Where it stands today |
| --- | --- |
| `migrate` collides with `schema-migrate` | both registered; four modules carry a prose disclaimer to tell them apart — `asf/schema.py:2` ("not ``asf migrate``, which adopts items"), `pyproject.toml:3`, `asf/record/plan_tasks.py:4`, `asf/tick/migrate.py:1` |
| `backlog` prints the BOARD | `asf/cli.py:304` registers `backlog`; `asf/views/header.py:9` titles it `BOARD`; the renderer is already `asf/views/board.py` — only the operator's word is wrong |
| `parity` carries the first product's concept | `asf/cli.py:307`, `asf/views/parity.py`, `plugin/skills/parity/`; the table is one row per Story and has nothing to do with parity |
| descriptions name a path or an internal | `stale` → "the product's `stage_limits`"; `hook` → "`tools/checks/<name>.sh`"; `evidence` → "the evidence pass" (the word explaining itself) |
| the voice mixes three grammars | imperative (`new`: "mint a new work item"), noun phrase (`roadmap`: "the ROADMAP table: …"), question (`doctor`: "is this product's ASF install sound — one table") |
| nothing says which commands write | 49 descriptions, not one of them says whether running it changes anything |

The descriptions are not decoration. `asf/plugin_build.py:64` reads `sub._choices_actions` and
writes each command's `help` verbatim into that command's `plugin/skills/<name>/SKILL.md` — the
same sentence a stranger reads in `--help` is the sentence an assistant reads to decide whether
to run it. A description that does not say "this writes the record" is a description that lets an
agent write the record by accident.

So the fix cannot be a one-time pass over 49 strings. It is a declared surface with a gate.

## 1. Decisions

### 1.1 Preconditions

- `build_parser()` (`asf/cli.py:171`) is the one place the surface exists. Fifteen modules
  register into its `sub` (`plugin_build.register`, `ci_pool.register`, `actions.register`,
  `deploy.register`, `tick.register`, `init.register_commands`, …), and every one of them has
  returned by the time `build_parser` returns its parser. A single post-pass at the end of
  `build_parser` therefore sees all 49, whoever added them.
- `asf/plugin_build.py:64` already treats `sub._choices_actions` as the single source of the
  descriptions, and `tests/test_plugin.py:38` already asserts the plugin is generated from the
  CLI. Mutating `action.help` in that post-pass reaches the plugin for free.
- `tools/check_conventions.sh:105` scans every tracked `asf/*.py` and `asf/**/*.py` against
  `tools/forbidden-conventions.txt`, which is explicitly the list for *concepts one product
  happens to use* — the file's own header says so. It is the existing home for a retired word.
- `asf/views/header.py:7` (`TITLES`) is the registry of table titles, keyed by the command as an
  operator types it. A command rename moves its key.
- `asf/tick/tick.py:131` renders six tables into `{name: markdown}` and
  `asf/tick/tick.py:143` writes each as `tables/<name>.md`. The key is the artifact name.

### 1.2 In

- One declared surface: `asf/surface.py`, one row per top-level command — its description and its
  effect. `build_parser` renders `--help` from it and refuses to build a parser that disagrees
  with it.
- Rewriting all 49 descriptions to one voice, one line each.
- Marking every command that writes, with what it writes.
- The three renames the card names, each reaching the command, its table title, its artifact and
  its generated skill — and each retired name failing loudly rather than silently.
- The gate: a test that a new command cannot pass without declaring itself.

### 1.3 Out

- **Second-level subcommands** (`ci reconcile`, `cloud install`, `deploy record`, `plugin build`,
  `rules check`). The card is about `asf --help`, which lists only the 49 top-level names. A
  subcommand's own `--help` is a second surface with its own drift; declaring it here would
  double the table for a page a stranger reaches only after finding the right command. The
  parent's row carries the parent's worst effect (`ci` is marked as writing this host, because
  `ci reconcile --apply` does), so the marker never under-reports.
- **`--help` for flags.** Only the `help=` of each `add_parser` is in scope; per-flag help is
  untouched.
- **Grouping `--help` into sections** (reads / writes). argparse has no supported way to group
  subparser choices, and the private route is more fragility than the marker is worth.
- **Renaming any other command.** Three names are wrong and the card names all three. `hooks`
  versus `hook` is a near-collision but each is correctly named for what it does; leave it.
- **A cache is not a write.** `asf evidence` writes `cache-prs.json` under the host state dir
  (`asf/evidence/evidence.py:70`). The marker answers "will this change something I have to
  review, or cannot undo" — a cache is neither, and marking it would train the reader to ignore
  the marker.

### 1.4 The choices

| # | Chose | Against | Why |
| --- | --- | --- | --- |
| D1 | A declared table (`asf/surface.py`) that `--help` renders *from* | hand-editing 49 `help=` strings in place | Editing the strings fixes today and nothing else: the surface grew from 30 to 49 in seven days, and the 50th command would arrive in whatever voice its author had. A table the parser must agree with makes the next command declare itself or fail the build. |
| D2 | Descriptions live in the table, not at the `add_parser` call | descriptions stay at each `add_parser`, table holds only the effect | Two half-sources is how `TITLES` and `add_parser` already drifted (`backlog`/`BOARD`). One row per command, one place to read the whole surface, and the reviewer of a new command sees it beside its 48 neighbours — which is what makes a voice hold. |
| D3 | `migrate` → **`import-items`** | `adopt` · `adopt-items` · taking the name `migrate` for `schema-migrate` | `adopt` is `init`'s verb already ("adopt a product"), and the two adoptions differ (a product, versus that product's items) — the same confusion in new words. `import-items` pairs with the `import-sessions` already on the surface, so the surface gains a family instead of a singleton. Giving `migrate` to `schema-migrate` is the one genuinely dangerous option: an operator with `asf migrate` in muscle memory would silently run a schema migration instead of an error. |
| D4 | `backlog` → **`board`**, artifact and title too | rename the table `BOARD` → `BACKLOG` instead | In ASF "the backlog" is the whole record (`backlog_dir`; `check` "validate the backlog"), so a command naming one *table* `backlog` is wrong twice over. The renderer is already `asf/views/board.py`; the title is already `BOARD`. The command and `tables/backlog.md` are the only two places still out of step, and leaving the artifact behind re-creates the exact disagreement the card filed. |
| D5 | `parity` → **`stories`** | `matrix` · `coverage` | The table is one row per Story (`asf/views/parity.py:1`), and `stories` says that with no concept borrowed from anywhere. It joins `sessions`, `roadmap`, `prod` — the surface's existing shape for "one row per X". |
| D6 | A retired name exits 2 with the new name printed | letting argparse say `invalid choice: 'migrate'` | argparse's list of 49 choices is not an answer to "where did my command go". One line — `asf: 'migrate' is now 'import-items'` — costs three rows in a dict and is the whole migration story for every operator and every script. |
| D7 | `\bparity\b` added to `tools/forbidden-conventions.txt` | trusting the rename to hold | That file is the existing gate for a word one product happens to use, and it already scans every `asf/**/*.py`. One line there is the difference between fixing this instance and closing the class. |
| D8 | Marker is a `[writes …]` suffix; read-only carries nothing, and the epilog says so | marking both (`[reads]` / `[writes]`) · a leading tag | Forty-nine lines are already the problem; a tag on all 49 is noise on the 30 that are safe. The marker should be the thing that catches the eye, which means only the dangerous rows carry it. One epilog line makes the absence mean something. |
| D9 | Four effect targets: the record, the product repo, this host, a pull request | one boolean `writes` | "Writes" without a target does not let anyone act on it. `asf index` writing the record and `asf upgrade` writing this host are different risks, and the operator can tell them apart at a glance for four extra words. |
| D10 | Voice rule = opens with a verb from a **closed list** | "write it in the imperative", checked by review | An open instruction is what produced today's three grammars. A closed list of verbs is one `assertIn` and cannot be argued with at review time; adding a verb to it is a deliberate, visible act. |
| D11 | 100-character cap | no cap · argparse's own wrap | The card asks for "one line". 100 characters is one line in argparse's layout at the default width for every name on the surface; today's longest is 139 and wraps to three. |
| D12 | The forbidden-token check bans a path, an extension and an asf config field name | banning paths only | The card names three offenders and only one is a path: `stage_limits` is a config field and "the evidence pass" is a word explaining itself. All three are the same defect — a description written from inside the code — so all three are checked. |

## 2. The design

### 2.1 The declared surface — `asf/surface.py` (new)

One module, no imports from the rest of `asf`, so `build_parser` can use it with no import cycle.

```python
"""asf.surface — what every ``asf`` command is called, what it does, and what it writes.

One row per top-level command. ``asf --help`` is rendered from this table, and
``tests/test_surface.py`` refuses a parser that disagrees with it: a command registered and not
declared here, or declared here and not registered, fails the build. That is the whole point —
the surface grew from 30 commands to 49 in one week, and the descriptions grew apart.
"""

#: What running a command changes. ``None`` is read-only: it prints and exits.
RECORD = 'the record'          # the backlog checkout: items, index, tables
REPO = 'the product repo'      # files in the product's own checkout
HOST = 'this host'             # the install, the schedule, the pool
PRS = 'a pull request'         # state on the product's open pull requests

#: The only verbs a description may open with. One voice is a closed list, not an instruction.
VERBS = frozenset({
    'adopt', 'bring', 'build', 'check', 'claim', 'compare', 'file', 'follow', 'import',
    'land', 'list', 'mint', 'print', 'read', 'record', 'reinstall', 'release', 'reopen',
    'render', 'run', 'scan', 'set', 'sort', 'type', 'write',
})

#: command -> (description, effect, flag)
#: ``effect`` is ``None`` for read-only. ``flag`` names the flag or subcommand that makes it
#: write, when it does not write by default; ``None`` means it always writes.
COMMANDS = {
    'new':      ('mint a work item and print its id', RECORD, None),
    ...
}

#: A name that was retired, and the name that replaced it (F-0084).
RENAMED = {
    'migrate': 'import-items',
    'backlog': 'board',
    'parity': 'stories',
}
```

`effect` and `flag` render the marker:

```python
def marker(effect, flag):
    """The ``[writes …]`` suffix for one row, or `''` when it only reads."""
    if effect is None:
        return ''
    return f" [writes {effect}]" if flag is None else f" [writes {effect} with {flag}]"
```

### 2.3 The post-pass — `asf/cli.py`

`build_parser` ends with one call, after every `register(sub)` has run:

```python
    surface.apply(sub)      # descriptions and [writes …] markers, from the declared table
    p.epilog = ('A command with no [writes …] marker only reads: it prints and exits.\n'
                'Every command takes --product; without it, the record is the current directory.')
    p.formatter_class = argparse.RawDescriptionHelpFormatter
    return p
```

and `surface.apply` is the seam that makes the table binding:

```python
def apply(sub):
    """Set every registered command's ``help`` from :data:`COMMANDS`, marker included.

    Raises ``SurfaceError`` naming any command registered but not declared, so a new command
    cannot reach ``--help`` without a description and an effect (F-0084).
    """
    for action in sub._choices_actions:
        row = COMMANDS.get(action.dest)
        if row is None:
            raise SurfaceError(f"{action.dest!r} is registered but not declared in asf.surface")
        text, effect, flag = row
        action.help = text + marker(effect, flag)
```

The `_choices_actions` reach is the one `asf/plugin_build.py:68` already takes, and because
`apply` mutates those same actions, `asf plugin build` picks up the new descriptions and the
markers with no change to `plugin_build.py`.

### 2.4 A retired name answers for itself — `asf/cli.py`

`_main` checks the first positional before `parse_args` refuses it:

```python
def _main(argv=None):
    argv_list = list(sys.argv[1:] if argv is None else argv)
    if argv_list and argv_list[0] in surface.RENAMED:
        old = argv_list[0]
        print(f"asf: {old!r} is now {surface.RENAMED[old]!r} — run: asf {surface.RENAMED[old]}"
              f"{' ' + ' '.join(argv_list[1:]) if argv_list[1:] else ''}", file=sys.stderr)
        return 2
```

Exit 2 is what the CLI already returns for an operator-fixable refusal
(`needs_operator_line`). Nothing runs.

The two artifact renames mean a reference tables directory captured before this change no longer
matches a shadow run after it. `asf shadow-diff` reports the two renamed files as one added and
one removed on the first run against an old reference; a reference captured after the change is
clean. This is stated here rather than worked around: a one-run diff is the honest cost of the
artifact name catching up with the command.

### 2.6 The gate — `tests/test_surface.py` (new)

Five checks, all mechanical, all over the live parser:

1. **Coverage, both ways.** Every registered command is in `COMMANDS`; every key in `COMMANDS` is
   registered. This is what a new command trips.
2. **One voice.** Every description's first word is in `VERBS`; every description is lowercase at
   the start, has no terminal period, contains no `?`, and is ≤ 100 characters.
3. **No internals.** No description matches `/`, `\.(json|ya?ml|sh|py|md)\b`, `<[a-z]+>`, or any
   field name of `asf.conventions.Conventions` — the three the card found (`tools/limits.json`,
   `tools/checks`, `stage_limits`) and the class they belong to.
4. **Nothing explains itself.** A description does not contain its own command name as a word —
   the `evidence` → "the evidence pass" defect.
5. **The marker is rendered, never typed.** For every command, the `help` argparse holds equals
   `text + marker(effect, flag)` for that row, and no description in the table itself contains
   the substring `[writes`.

Plus the rename tests: each retired name exits 2 and names its replacement on stderr; each new
name parses and dispatches.

## 4. Records

- **`asf/surface.py`** — the new record of what the surface is: 49 rows of
  `(description, effect, flag)`, the four effect targets, the closed verb list, and `RENAMED`.
  Nothing in the repo describes a command anywhere else after this lands.
- **`asf --help`** — 49 lines, one line each, with `[writes …]` on the nineteen that write, and
  an epilog saying what no marker means.
- **`plugin/skills/<name>/SKILL.md`** — regenerated for all 49 (`asf plugin build`), each
  carrying the new description and its marker. `plugin/skills/backlog/` and
  `plugin/skills/parity/` are deleted; `plugin/skills/board/` and `plugin/skills/stories/` are
  added. Committed, because `asf plugin check` compares the committed files to the CLI.
- **`tables/board.md`, `tables/stories.md`** — what the tick writes each turn, in place of
  `tables/backlog.md` and `tables/parity.md`. The first shadow-diff against a pre-change

- **`tools/forbidden-conventions.txt`** — one added line, `\bparity\b`, under a comment naming
  F-0084 as the reason.
- **stderr, on a retired name** — one line: `asf: 'migrate' is now 'import-items' — run: asf
  import-items …`, exit 2. No record write, no table, no partial run.
