# F-0316 — the note was not misread, it was deleted

The card reads the symptom off one minted card: groom turned the inbox note
`delivery-pass-binds-…` into F-0315, copied the note's body into `## Description`, left
`## Acceptance` as an empty `- [ ]`, and lost the note's four acceptance lines and its
`Severity: S1` line. A human put all five lines back by hand.

The lines were not misparsed into the wrong place. They were **removed from the note and written
nowhere**. `_lift_section` (`asf/groom/inbox.py:68-91`) cuts the whole `## Acceptance` block out of
the body — `lines[:start] + lines[end:]` at `:91` — and then takes from that block only the lines
matching `^-\s*\[[xX ]\]\s*(.*)$` with a non-empty group (`:85-88`). A plain `- the pass binds the
free lane` matches nothing, so it is in neither list: not in `card.acceptance`, and not in
`card.description`, because the block it lived in is already gone. The same cut takes the
`Severity: S1` line the operator wrote under the bullets, because the block ends only at the next
`## ` heading (`:78`) and nothing between is kept.

The severity has a second, independent reason to vanish: the header block stops at the first body
line (`parse_inbox_file`, `:115-135`), so a `severity:` line written **below** the body is not a
header at all — and `severity:` is a Bug's field and nothing else's, so even read, it had nowhere
to go on the Feature this note minted.

Measured in this worktree at `76a4469` (P6), the card's own note shape through `asf groom`:

```
## Description
The delivery pass binds a seat to lane-2 while lane-1 is free.

## Acceptance
- [ ] 
```

Four acceptance lines, one grade, gone — the card's wording made exact. A reviewer has nothing to
prove against, and `asf check`'s size pass is satisfied by the empty `- [ ]`, so nothing says so.

## Decisions

### What is in

* **An acceptance item is any ordinary Markdown list item.** `- x`, `* x`, `+ x`, `1. x`, `1) x`,
  indented or not; under `Acceptance` a `[ ]`/`[x]` checkbox in front of the text is the list's
  syntax and never part of the item. `- [ ] x` and `- x` are one acceptance line, where only the
  first was.
* **The section heading is read at any ATX depth and in any case**, and a lifted block ends at the
  next heading of *any* depth — not only at `## ` (`:78`), which swallowed a `### …` and everything
  under it into the block, and deleted all of it.
* **Nothing a lifted block holds is dropped.** A line the item grammar cannot read — a prose line,
  a stray header — stays in the body under its own heading. The items still lift. `- [ ]` with no
  text (the placeholder `write_new_item` writes into every fresh card, `asf/record/ids.py:196`) says
  nothing, is read as nothing, and is not an unread line either.
* **`severity:` is read from below the header block as well as inside it** — one strict grammar,
  `^severity:\s*(S[123])\s*$` on a line of its own — and the line leaves the body when the severity
  the card ends up with is the one it names. Read once, in `parse_inbox_file`, so the mint
  (`process_inbox:361`), the groom line (`question_lines:504`) and the stuck-S1 line
  (`stuck_s1_lines:531`) all see it: the invariant `severity_of`'s own docstring states (C5 —
  "a card cannot be S1 in one view and S3 in the other") now holds for a note that writes its grade
  under its body.
* **A declared severity the minted type has no field for reaches the card's `## Description`** as
  the line the operator wrote. `severity:` is settable on a Bug and nothing else
  (`asf/record/new.py:28`; `asf/record/check.py:304` requires it of a Bug only), so a note that
  grades itself and mints as a Feature kept it nowhere. This is the hand remedy F-0315 needed,
  done by the pass.
* **One consequence, in and intended:** the widened acceptance grammar is read by `shape.derive`
  too. A card under a Feature with plain-bullet acceptance is now the Story it is
  (`shape.py:130`), where it was asked for an acceptance list it already had; and a defect-worded
  card with a plain-bullet acceptance list now reads as work (`shape.py:141`) and as carrying its
  own evidence (`inbox.signed`, `:236`), as a checkboxed one already did. The operator's list
  decides the type either way — that is the rule the product already has, applied to lists it
  could not previously see.

### What is out, and why

| out | why |
| --- | --- |
| writing `severity:` as a typed field on a Feature, Story, Task or Epic | `review_tier` (`asf/feeder/rows.py:1115-1119`) reads `item.get('severity')` for **any** type, so a minted `severity: S1` would re-tier that item's review ahead of everything else. Whether an operator's note may set factory priority on a non-Bug is a policy this card does not make. The Description keeps the line; nothing is lost and nothing is re-ordered. |

The others stay in the body, where nothing now deletes them. |

  ```python
  def _lift_section(lines, heading):
      """Pull a `## <heading>` block out of `lines`, returning (items, remaining_lines)."""
      start = None
      for i, l in enumerate(lines):
          if l.strip() == f"## {heading}":
              start = i
              break
      if start is None:
          return [], lines
      end = start + 1
      while end < len(lines) and not lines[end].startswith('## '):
          end += 1
      items = []
      for l in lines[start + 1:end]:
          s = l.strip()
          if not s.startswith('- '):
              continue
          if heading == 'Acceptance':
              m = re.match(r'^-\s*\[[xX ]\]\s*(.*)$', s)
              if m and m.group(1):
                  items.append(m.group(1))
          else:
              items.append(s[2:])
      return items, lines[:start] + lines[end:]
  ```

## The design

Three edits, all in `asf/groom/inbox.py`. No new module, no new config key, no new record field, no
change to `Card`'s shape, no change to `asf.groom.shape`.

### 1. Four grammars, beside the two intake already has

Above `_is_header_line` (`:49`), next to `INBOX_KV_RE` and `_UNKNOWN_HEADER_RE`:

```python
#: A section heading intake lifts (`## Acceptance`, `## Features`), at any ATX depth and
#: whatever its case — the operator's heading is prose, not a key (F-0316 C3).
def _heading_re(heading):
    return re.compile(r'^#{1,6}[ \t]*' + re.escape(heading) + r'[ \t]*$', re.IGNORECASE)


#: Any ATX heading: where a lifted section ends. Depth-2 only (`## `) left a `### …` inside the
#: block, and everything under it, inside the block too (F-0316 C3). ATX wants a space, a tab or
#: the line's end after the hashes, and this asks for exactly that: `#tag`, `#1 priority` and a
#: seven-hash line are not headings, and a looser `#{1,6}[ \t]*\S` read each of them as one and
#: ended the block there — the bullets under it stayed in the body instead of becoming acceptance
#: lines, the same loss by a different route (measured; A1). Seven hashes are refused here as
#: `_heading_re` already refuses them, so the two grammars agree on what a heading is.
_ANY_HEADING_RE = re.compile(r'^#{1,6}(?:[ \t]|$)')

#: An ordinary Markdown list item — `- x`, `* x`, `+ x`, `1. x`, `1) x`, indented or not. The
#: bullet is the list's syntax; `item` is what the operator wrote (F-0316 C1).
_LIST_ITEM_RE = re.compile(r'^[ \t]*(?:[-*+]|\d+[.)])[ \t]+(?P<item>\S.*?)[ \t]*$')

#: The checkbox an acceptance item may carry in front of its text — optional, and not part of
#: the item: `- [ ] x`, `- [x] x` and `- x` are the same acceptance line (F-0316 C1).
_CHECKBOX_RE = re.compile(r'^\[[ xX]\][ \t]*(?P<item>.*?)[ \t]*$')

#: A `severity:` line, alone on its line and naming one of :data:`SEVERITIES` — the one header
#: intake reads from below the header block as well (F-0316 C2). Nothing else is: the value is
#: a closed three-token set, so prose cannot be mistaken for it.
_SEVERITY_LINE_RE = re.compile(r'^[ \t]*severity:[ \t]*(S[123])[ \t]*$', re.IGNORECASE)
```

### 2. `_lift_section` reads every list form, and gives back what it cannot read

Replacing `:68-91` whole:

```python
def _lift_section(lines, heading):
    """Pull a `## <heading>` block out of `lines`, returning (items, remaining_lines).

    The heading is matched at any ATX depth and whatever its case (`_heading_re`), and the block
    ends at the next heading of any depth (`_ANY_HEADING_RE`). An item is any ordinary Markdown
    list item (`_LIST_ITEM_RE`); under `Acceptance` it may carry a `[ ]`/`[x]` checkbox, which is
    the list's syntax and never part of the item (`_CHECKBOX_RE`). So `- [ ] x`, `- [x] x`,
    `- x`, `* x` and `1. x` are all one acceptance line, where only the first two were
    (F-0316 C1).

    Nothing the block holds is dropped (F-0316 C4). A line the grammar cannot read — a prose
    line, a stray header — stays in the body under its own heading, so the operator's words are
    where the operator put them. An item whose text is empty (`- [ ]`, the placeholder a card
    template carries) says nothing and is read as nothing, which is not the same as unread.
    """
    rx = _heading_re(heading)
    start = next((i for i, l in enumerate(lines) if rx.match(l.strip())), None)
    if start is None:
        return [], lines
    end = start + 1
    while end < len(lines) and not _ANY_HEADING_RE.match(lines[end]):
        end += 1
    items, unread = [], []
    for l in lines[start + 1:end]:
        if not l.strip():
            continue
        m = _LIST_ITEM_RE.match(l)
        if m is None:
            unread.append(l)
            continue
        item = m.group('item')
        if heading == 'Acceptance':
            box = _CHECKBOX_RE.match(item)
            if box:
                item = box.group('item').strip()
        if item:
            items.append(item)
    if unread:  # the heading and what intake could not read stay where they were written
        return items, lines[:start + 1] + unread + [''] + lines[end:]
    return items, lines[:start] + lines[end:]


def _lift_severity(lines, headers):
    """Read a `severity:` line standing below the header block, and take it out of `lines`.

    Returns the lines that are left. The card said `Severity: S1` and the minted card came out
    ungraded (F-0316): the header block stops at the first body line (P2), and a severity written
    under the body — or inside the `## Acceptance` block, where it was deleted with the block
    (P1) — was never read. This runs over the whole body *before* any section is lifted (P3), so
    a line inside such a block is read too.

    `severity:` is the only key read this way (F-0316 C2): its value is the closed set
    :data:`SEVERITIES`, so a prose line cannot be mistaken for it. A line is taken out only when
    the severity the card ends up with is the one it names — so a `severity:` header, or two body
    lines that disagree, leaves every line where it is and nothing is guessed (C5).
    """
    found = [(i, m.group(1).upper()) for i, m in
             ((i, _SEVERITY_LINE_RE.match(l)) for i, l in enumerate(lines)) if m]
    if not found:
        return lines
    named = {s for _i, s in found}
    declared = (headers.get('severity') or '').strip().upper()
    if not declared and len(named) == 1:
        headers['severity'] = found[0][1]
        declared = found[0][1]
    drop = {i for i, s in found if s == declared}
    out, i = [], 0
    while i < len(lines):
        if i in drop:
            # the blank line that followed it goes too, so the body does not keep a gap where
            # a field used to be written twice
            if out and not out[-1].strip() and i + 1 < len(lines) and not lines[i + 1].strip():
                i += 1
            i += 1
            continue
        out.append(lines[i])
        i += 1
    return out
```

class AnAcceptanceListIsAnyOrdinaryList(unittest.TestCase):

    factory with none of them — not in its acceptance list, not in its Description."""

    def acc(self, section):

        return inbox.parse_inbox_file('# t\nparent: F-0001\n\nBody.\n\n' + section).acceptance

    def test_plain_bullets_are_acceptance_lines(self):
        self.assertEqual(self.acc('## Acceptance\n- the pass binds the free lane\n- a seat is released\n'),
                         ['the pass binds the free lane', 'a seat is released'])

    def test_every_ordinary_list_marker_reads_the_same(self):

                        '## Acceptance\n+ a\n+ b\n', '## Acceptance\n1. a\n2. b\n',
                        '## Acceptance\n1) a\n2) b\n', '## Acceptance\n  - a\n  - b\n'):

                self.assertEqual(self.acc(section), ['a', 'b'])

    def test_a_checkbox_is_still_read_and_is_not_part_of_the_item(self):

    def test_an_empty_checkbox_is_the_template_placeholder_and_yields_nothing(self):

        from asf.groom import inbox
        c = inbox.parse_inbox_file('# t\n\nBody.\n\n## Acceptance\n- [ ]\n')
        self.assertEqual((c.acceptance, c.description), ([], 'Body.'))

    def test_the_heading_is_read_at_any_depth_and_in_any_case(self):
        for heading in ('## Acceptance', '### Acceptance', '#### acceptance', '## ACCEPTANCE'):
            with self.subTest(heading=heading):
                self.assertEqual(self.acc(heading + '\n- a\n'), ['a'])

    def test_a_nested_heading_ends_the_block(self):

    def test_a_hash_that_is_not_a_heading_does_not_end_the_block(self):
        """ATX needs a space, a tab or the line's end after the hashes, so `#tag` and a
        seven-hash line are not headings. A grammar that ended the block on them left the
        bullets under them out of the acceptance list (F-0316 C3)."""
        for line in ('#1 priority', '#deliverypass', '####### not a heading'):
            with self.subTest(line=line):
                self.assertEqual(self.acc(f'## Acceptance\n- a\n{line}\n- b\n'), ['a', 'b'])

    def test_a_features_list_reads_the_same_markers(self):
        from asf.groom import inbox
        for section in ('## Features\n- Plan tiers\n- Invoicing\n', '## Features\n* Plan tiers\n* Invoicing\n'):
            with self.subTest(section=section):
                c = inbox.parse_inbox_file('# t\n\nBody.\n\n' + section)
                self.assertEqual(c.features, ['Plan tiers', 'Invoicing'])

    def test_an_acceptance_list_types_the_card_a_story_under_its_feature(self):

## Stories

**One Story, on purpose.** The three edits of `## The design` are three edits to one module:
`_lift_section` and `_lift_severity` sit twenty lines apart, `parse_inbox_file` calls both on one
line, and `process_inbox`'s `if` reads the header the second of them filled. A plan that cut them
into two Tasks could not give those Tasks disjoint `writes:` — every one of them is
`asf/groom/inbox.py`, plus `tests/test_inbox_shape.py` and `tests/test_intake_severity.py` — and a
plan whose footprints overlap is refused whole. They are also one session of work: three edits and
five test classes over fixtures the two modules already have, with the defect reproduced end to end
before the first of them (P6).

The id is from this session's range `S:99255-99304`.

grade and the three views that must agree on it.
