# F-0039 — the findings go back to the session that wrote the thing

*A near miss is corrected in place, never restarted — the session that produced it holds the
context.* That is [[R-0067]] and the Constitution's §7, which names this Feature as the mechanism
that was never built (`docs/CONSTITUTION.md:192`).

What is built instead, today, is a relaunch. Every round of review ends with a **new model
session**, and the new session's first job is to buy back what the last one already knew: the
card, the spec, the plan, its own diff. Two lanes do it:

- **the doc lane** — a reviewer writes `docs/reviews/<n>-f-0039-review-r1.md` with a check table
  and a C list; ingest turns that into the Feature's `spec-review r1` stage
  (`asf/evidence/evidence.py:971`); the feeder emits `STARVED → SPEC`
  (`asf/feeder/rows.py:312`); the wave builds a **whole brief from scratch** and launches
  `spec-f-0039` again. Round 1 → new session → round 2 → new session.
- **the code lane** — harvest holds a branch, `lifecycle.hold` writes the correction and prints
  `held spec/F-0039: … — back to its session (round 1)` (`asf/workers/lifecycle.py:608`), and
  then the feeder's `FIX → CORRECT` row launches `correct-f-0039`: a different job, a different
  conversation. The line already says *back to its session*. Only the launcher disagreed.

The mechanism to do what the line says is one flag on a command line that is already a pure
function. `runtime.build_command` (`asf/workers/runtime.py:77`) never emits `--resume`, and the
runtime's own session id — which the coding-agent CLI writes into every log's `system`/`init`
line — is read by nobody. `asf.workers.lifecycle.session_id` mints ASF's *own* id
(`<product>/<job>@<stamp>`), which names a launch and cannot be resumed.

This spec records that id, sends a review's findings into the session that holds the context, and
keeps today's launch as the fallback for a session that is dead.

## 1. Decisions

### 1.1 In

- `runtime.runtime_session(log_path)` — the runtime's own session id off the log's **last run's**
  `init` line; recorded on the run by health as `runtime_session`, beside the `ended` line.
- `runtime.Job.resume` and `build_command` emitting `--resume <id>`; `Runtime.continue_run(job)`,
  implemented by `ClaudeCodeRuntime` and `FakeRuntime`, declined (`None`) by any runtime that
  cannot continue — the seam the remote half fills (§1.2).
- `asf/workers/continuation.py` — the one module that answers *may this row be answered by
  continuing a session, and with what text*: `target`, `resumable`, `findings`, `prompt`,
  `continue_run`. One rule, one reason string, three readers.
- `stage_limits.heartbeat_min` (default **6**) — how long a run that is supposed to be beating may
  be silent before it is read as dead (§1.4, §2.6).
- The wave asking `continuation` before it builds a brief, for every row that **answers** a branch
  already on origin (`correct`, and a `spec`/`plan` row whose Feature sits at `<doc>-review rN`);
  a fallback that launches today's session in the **same tick**, never the next.
- The continuation line in `sessions.jsonl`: a launch line (its own `pid`, its own outcome)
  carrying the **writer's** `session` and `resumed: <runtime session id>`, so the ledger holds a
  run and the metric counts one session.
- `metrics.RECORD_KINDS['correct'] = 'fix'`, without which a `correct-<item>` session derives to
  `other` (`metrics.KIND_PREFIXES` matches no `correct`) and acceptance #3 cannot be read at all.
- The scorecard's `fixer sessions per merged PR` row, beside today's `launches per merged PR`
  (`asf/metrics/metrics.py:444`).
- `asf brief --continue` — the continuation prompt the tick would send for a row, or the one-line
  reason there is none. The operator's window into the decision, and the acceptance surface.
- `docs/products.example.yaml`, `sample/product.yaml` and `docs/design/lane-state-machine.md`
  carrying `heartbeat_min` and the `continued` transition.

### 1.2 Out

- **A cloud runtime.** The card says both halves already exist in the harness; in *this product*
  only the local half does. `worker_pool.backend` is `claude-code | api-key`
  (`docs/config.example.yaml:20`), `ClaudeCodeRuntime` and `FakeRuntime` are the only two, and
  `Account.role: cloud` (`asf/workers/pool.py:8`) gates capacity and nothing else. So this spec
  builds the **seam** — a runtime that declines to continue falls back, and the caller never knows
  which kind it has — and the local implementation. A runtime that reaches a remote session
  through its trigger is a Feature of its own, and it inherits every decision below unchanged.
- **Resuming an adjudication.** `ADJUDICATE` always launches fresh (§1.4). The cap exists because
  three rounds of the same head did not converge.
- **Changing what a review finds, or how it is written.** The check table is
  `asf/briefs/templates/review.md`'s, read as it stands. Machine-readable checks are F-0053.
- **Merging or skipping a round.** A continuation is a round: `rounds` still climbs, `ROUND_CAP`
  still bites, the ADJUDICATE row still arrives at 3.
- **Shrinking a first launch's brief.** A session with no context gets the whole brief, as today.
- **Reviving a reaped worktree, or resuming onto a branch another session has moved.** Both are
  fallbacks, not recoveries (§2.3).
- **Relaunching on top of a wedged writer.** A run that is live and silent is refused by
  `may_launch` exactly as today (`asf/workers/spawn.py:172`); this spec adds the *reason* to the
  wave's line and changes nothing about the refusal.
- **Token accounting of a resumed session.** F-0028 and F-0091 own it; F-0091 §74 already reads a
  resumed job as one session id with many result lines, and §4 below writes the field it keys on.

### 1.4 The choices

| Choice | Chosen | Against | Why |
|---|---|---|---|
| What "the writer's session" is | the **runtime's own** session id, read off the log's last `init` line and recorded on the run as `runtime_session` | ASF's minted `ASF_SESSION`; the job name | `ASF_SESSION` names a launch, not a conversation, and `<product>/<job>@<stamp>` is not a thing any runtime can resume. The id that can be is already written to the log on every run — nobody was reading it |
| What makes a session **dead** | it should be beating and is not: a run with **no `ended` line** whose log has been silent longer than `stage_limits.heartbeat_min` (6) | the heartbeat measured against every run, whatever its state | A run that *finished* is not dead — its conversation is precisely what we want. Measured against a finished run, a 6-minute heartbeat would make every doc-lane review a fallback and acceptance #1 unreachable: a reviewer takes longer than six minutes to write. The heartbeat is the liveness test for a run that is still supposed to be running |
| What makes an **ended** session resumable | three facts about the world it would wake into: its worktree is still there, no *other* session's commit sits on the branch above the trunk (P6), and the runtime did not decline | asking the runtime whether the id still resolves; a transcript-age limit | Those are the facts that make the session's context *true*. A transcript the runtime has forgotten is caught anyway — `continue_run` fails and the fallback runs in the same tick — and asking a vendor first would put a network call inside a decision the feeder's table has to be able to explain |
| Six minutes | the card's number, as a product field with that default | 30 (`stall.silent_min`); no limit | It is the code lane's own clock: a writer ends, health writes `ended`, harvest gates and holds, and the wave continues the session — all inside one tick. `silent_min` answers a different question (is this session worth an operator's look) and answers it for a live run over a much longer window; one number cannot be both |
| The fallback | today's row, launched in the **same tick**, with the reason on the line | a retry next tick; a `NEEDS OPERATOR` | A continuation that cannot happen must cost nothing. The row is the one the feeder already emitted and the brief is the one it already had; the only difference is a printed reason |
| What is sent | the review's **check table**, its verdict line and its C/I lists — the file's own rows, verbatim | the whole review file; the whole brief again; a path to open | The session already holds the card, the spec, the plan and its own diff. What it does not hold is the findings. A path would make it re-read the file — which is the cost this Feature exists to remove — and a second brief would make it re-read everything |
| Which round's file | round **N**, the one just written, not N+1 | reusing `preamble.collect`'s `review_path` | `collect` points a writer kind at the *next* round's file to write and an answer kind at the current one (`asf/briefs/preamble.py:218`). A continued `spec` row is an answer kind, so it must read N. Deriving it in `continuation` rather than bending `collect` keeps the reviewer's own path untouched |
| Whether an adjudication may continue | never | resuming at the cap too | `ROUND_CAP` exists because three rounds of one head did not converge. Handing the adjudicator the loser's context is the one place where a cold session is the cheaper one |
| Whether a continuation counts as a round | yes, unchanged | resetting the counter | `rounds` measures how many times the work came back, not how many processes ran. A Feature that made the cap unreachable would have bought its saving from the wrong pocket |
| The registry line | a **launch** line carrying its own `pid` and the **writer's** `session`, plus `resumed: <runtime id>` and `continued: 1` | a non-launch line folding into the writer's run | A continuation has its own pid, its own result and its own verdict — by P2 that is a run. What it shares is the session, and that field is what makes acceptance #3 countable (P10) |
| Where the decision is made | `asf/workers/continuation.py`, asked by the wave before it builds a brief | inside `spawn`; inside the feeder | The feeder may not read the ledger or git (P5); `spawn` is per-row mechanics below the decision. The wave is where a row becomes a launch, so it is where *do not launch, continue* belongs |
| Why `correct` → `fix` in the metric | one line in `RECORD_KINDS` | leaving it, and counting job-name prefixes in the scorecard | `derive_kind('correct-f-0039')` returns `other` today — `KIND_PREFIXES` has no `correct` pattern. Without this line the acceptance that fixer sessions halve cannot be read from the stream at all, before or after |

## 2. The design

### 2.1 The runtime's own session id, recorded

```python
# asf/workers/runtime.py
def init_line(log_path):
    """The last run's ``system``/``init`` record, or None — the same scan
    :func:`read_result` makes, rewinding at every ``init``."""

def runtime_session(log_path):
    """The runtime's own session id for the log's last run: ``init_line``'s ``session_id``,
    else ''. This is the id a continuation resumes; ``ASF_SESSION`` is ours and names a
    launch (F-0076, D1)."""
```

`FakeRuntime` already writes an `init` line (`asf/workers/runtime.py:236`) and now writes
`session_id` with it — `fake:<job>:<n>` — so every test exercises the real read.

`health.health` records it once, in the same pass that writes the `ended` line
(`asf/workers/health.py:304`):

```python
pool_mod.update_session(product, job, ended=now, end_reason=reason,
                        runtime_session=runtime_mod.runtime_session(s.get('log')) or None)
```

`runtime_session` joins `lifecycle.RUN_FIELDS`: it belongs to one run and must not fold into the
next (P2).

### 2.2 `Job.resume`, and the run that continues

`Job` gains one field, `resume` (default `None`), and `build_command` one clause:

```python
cmd = [binary, '-p', '--permission-mode', job.permission_mode]
if job.resume:
    cmd += ['--resume', job.resume]
```

```python
class Runtime:
    def continue_run(self, job):
        """Continue ``job.resume``'s conversation with the text at ``job.brief_path`` on stdin.
        ``None`` from a runtime that cannot — the caller falls back (§1.2)."""
        return None
```

`ClaudeCodeRuntime.continue_run` is `run(job)` with `resume` set; a `Popen` that raises, or a
process that exits non-zero before writing an `init` line, returns `None` and is the fallback's
trigger. `FakeRuntime.continue_run` replays the next scripted step and appends a second `init`
line to the **same** log — the shape P1 already reads.

### 2.3 `asf/workers/continuation.py` — the rule

```python
#: Row kinds that may answer a branch by continuing its session. Everything else launches.
ANSWERING = ('correct', 'spec', 'plan')
#: Never continued, whatever the branch says (§1.4).
NEVER = ('adjudicate', 'review', 'groom', 'reshape', 'rebase', 'close', 'fix-bug', 'task')

DEFAULT_HEARTBEAT_MIN = 6
```

```python
def heartbeat_min(product) -> float:
    """``stage_limits.heartbeat_min`` — an int is minutes, a duration string
    (``90s``/``6m``/``1h``) works too, exactly as ``stall.silent_minutes`` reads its own."""

def writer(product, branch):
    """The latest run on ``branch`` (:func:`lifecycle.by_branch`), or None. A branch's writer is
    whoever holds it now — a held ``spec/F-0039`` is corrected on ``spec/F-0039`` (the lane state
    machine's own ruling), so this is the same run the correction was written on."""

def dead(run, product, now):
    """The card's dead session: live (no ``ended`` line) and its log silent past
    :func:`heartbeat_min`. ``(True, 'heartbeat stale (14m > 6m)')`` or ``(False, '')``."""

def resumable(product, run, now, repo=None):
    """``(session_id, '')`` when ``run``'s conversation may be continued, else ``(None, why)``.
    The tests, in order, each with the reason it prints:

        no run on the branch              →  'no session on <branch>'
        dead(run)                         →  'heartbeat stale (Nm > Mm)'
        lifecycle.is_live(run)            →  'still running'
        not run['runtime_session']        →  'no runtime session id recorded'
        worktree gone                     →  'worktree reaped'
        another ASF-Session on the branch →  'another session moved the branch'
        lifecycle.landed(run)             →  'already landed'
    """

def target(product, row, root, runs=None, now=None):
    """``(run, session_id, round, review_path)`` for a row that may be continued, else
    ``(None, None, 0, why)``. ``row.brief_kind`` in ``NEVER`` → ``'kind <k> never continues'``;
    a ``spec``/``plan`` row whose Feature is not at ``<doc>-review rN`` → ``'no review round'``
    (nothing to send: that row is a first draft, not an answer)."""
```

`another session moved the branch` is one `git log` on the product repo:
`git log --format=%(trailers:key=ASF-Session,valueonly) origin/<main>..origin/<branch>` — a
trailer that is neither empty nor this run's `session` means somebody else has written here since,
and the writer's memory of the branch is wrong. This is the only git call the decision makes, and
it is made once per candidate row, beside the two the wave already runs (`step_wave.repo_facts`).

### 2.4 The prompt — the findings, and nothing it already knows

```python
def findings(text):
    """A review file → ``{'verdict', 'table', 'criticals', 'improvements', 'missed'}``.
    ``verdict`` is :func:`harvest.pr_hygiene.parse_verdict`'s (P8, the one parser); ``table`` is
    the contiguous block of ``|`` lines under the check header, verbatim; ``criticals`` and
    ``improvements`` are the ``C``/``I`` items, each kept whole."""

def prompt(product, run, row, round_n, review_path, text):
    """The continuation message. Never a brief: the session holds the card, the spec, the plan
    and its own diff already."""
```

What is sent, for a `spec` row on `F-0039` at `spec-review r1`:

```
CORRECTION — round 1 of the review of F-0039 is in. verdict: changes requested

This is your own session, your own worktree and your own branch `spec/F-0039`, rebased onto
origin/main before this message. Do not re-read what you wrote; read the findings.

Review: docs/reviews/1-f-0039-review-r1.md

| check | result | evidence |
| --- | --- | --- |
| scope: the diff stays inside `writes:` | pass | docs/specs/f-0039.md only |
| every Story has an acceptance test | fail | S-15353 names none |

C1 docs/specs/f-0039.md:117 — §2.4 names no parser for the C list; name it or drop the claim.
C2 …

I1 …

Fix every C exactly as it specifies; apply the I's you agree with; never widen the scope — a
change the review did not ask for buys another round. Re-run the acceptance tests and the Gate.
Commit with `git commit -s`, push `spec/F-0039`, and finish with the typed REPORT, one line per C:
what it asked, where it is now closed.
```

A `correct` row sends the same shape with the harvest's correction text under
`stall.CORRECTION_HEAD` in place of the review block when the branch carries no review file — the
red gate's own output is the finding.

The whole message is capped at `conventions.preamble_max_lines` (the cap the brief already runs
under); the check table and the C list are kept whole and the I list is trimmed first, worst last.

### 2.5 The wave: continue, then launch

`step_wave.run`, between the held check and `_build`:

```python
run_, sid, rnd, why = continuation.target(product, row, ctx.record_root())
if sid:
    rec = continuation.continue_run(product, row, run_, sid, rnd, why_path=why)
    if rec:
        out(f"continued {rec['job']:<24} {row.item_id:<10} → session {rec['session']} "
            f"(round {rnd})")
        ctx.event('continue', item=row.item_id, job=rec['job'], session=rec['session'],
                  round=rnd, kind=row.brief_kind)
        continue
    why = 'runtime declined to continue'
brief = _build(product, row, items, running, repo_facts=repo_facts(product, row.branch))
if why:
    out(f"cold     {job_name(row.brief_kind, row.item_id):<24} {row.item_id:<10} — {why}")
```

`continuation.continue_run` writes the message to `<state>/briefs/<job>.continue-r<n>.md`, calls
`runtime.continue_run`, and appends the ledger line of §4. It takes **no pool slot beyond the
row's own**: the wave's `n` and the account pick are unchanged, because a continuation is still
one session against the cap.

The fallback path is the code that was already there. A row that cannot be continued is briefed
and launched in the same pass, one `cold` line naming why — so the operator reads the rate of
fallback off the tick's own output, not off a metric that arrives a day later.

### 2.6 The heartbeat limit

`stage_limits.heartbeat_min: 6` — minutes, or a duration string. It is a **product** field
because the right number is the length of that product's own tick-to-hold loop, and a product
whose harvest gate takes twenty minutes must be able to say so.

It answers one question and it is not `silent_min`'s: `silent_min` (30) asks *is this live session
worth an operator's look* and prints a `STALL` row; `heartbeat_min` (6) asks *may I put findings
into this conversation*. A run that is live and past `heartbeat_min` is the card's dead session:
the wave falls back, and whether the launch then succeeds is `may_launch`'s answer, unchanged
(§1.2) — a wedged run still owns its worktree and the wave still prints `spawn failed:`.

`asf doctor` gains nothing; `asf stale`'s limits are untouched.

### 2.7 Where it shows

- **`asf brief --continue`** — the prompt the tick would send for the next row (or `--item <id>`),
  or one line: `no continuation for F-0039: heartbeat stale (14m > 6m)`. Exit 0 either way; the
  prompt goes to stdout and the reason to stderr, as `asf new` and `asf stale` already split them.
- **`metrics.RECORD_KINDS['correct'] = 'fix'`**, and the scorecard's `agents` row gains a sibling:

  ```
  | fixers | 11 fixer sessions, 6 continued | 5 cold → 0.8 cold fixers per merged PR |
  ```

  counted over the `sessions` stream: a session of `kind: fix` whose `resumed` is absent is cold;
  one carrying `resumed` is a continuation. The denominator is the `merges` the `ticks` stream
  already sums (`metrics.scorecard_rows`).
- **`docs/design/lane-state-machine.md`** gains the transition in its own table:
  `held ─► continued ─► running`, with the one-line rule — *a held run's findings go into its own
  session; a dead one's go into a new one* — and the `runtime_session` row beside `stop_tip`.
- **`docs/products.example.yaml`** and **`sample/product.yaml`** carry
  `stage_limits: {heartbeat_min: 6}` with the comment distinguishing it from `silent_min`.

## 4. Records

**Rows** — `~/.ASF/state/<product>/sessions.jsonl`, two new shapes beside today's:

```json
{"job": "spec-f-0039", "ended": "2026-09-23T18:40:11Z", "end_reason": "finished",
 "runtime_session": "e3f1c0a2-7b44-4f0e-9a21-5c6d8e0b1f33"}
{"job": "spec-f-0039", "item": "F-0039", "feature": "F-0039", "kind": "spec",
 "account": "acct-a", "model": "opus", "pid": 91733, "pgid": 91733,
 "worktree": "/…/worktrees/spec-f-0039", "branch": "spec/F-0039",
 "started": "2026-09-23T18:44:02Z", "log": "/…/logs/jobs/asf/spec-f-0039.jsonl",
 "brief": "/…/briefs/spec-f-0039.continue-r1.md", "id_range": "S:15350-15399,…",
 "runtime": "claude_code", "product": "asf",
 "session": "asf/spec-f-0039@20260923T182614Z",
 "resumed": "e3f1c0a2-7b44-4f0e-9a21-5c6d8e0b1f33", "continued": 1}
```

The second is a **launch** line by P2 — its own `pid`, its own result, its own `ended` — and it
carries the *writer's* `session`, not a new one. That one field is the whole of acceptance #3:
the metric counts sessions, and a continuation is not a new one. `resumed`, `continued` and
`runtime_session` join `lifecycle.RUN_FIELDS`.

**Files.**

| Path | Written by | Shape |
| --- | --- | --- |
| `~/.ASF/state/<product>/briefs/<job>.continue-r<n>.md` | `continuation.continue_run` | §2.4 — the message as sent, one file per round, kept for the operator exactly as a brief is |
| `~/.ASF/logs/jobs/<product>/<job>.jsonl` | the runtime | the continued run appends its own `init`+`result` pair to the writer's log (P1): one file, one conversation |

**Events** — `<record>/metrics/events/<day>.jsonl`, one new kind beside `launch`:

```json
{"kind": "continue", "item": "F-0039", "job": "spec-f-0039", "round": 1, "brief_kind": "spec",
 "session": "asf/spec-f-0039@20260923T182614Z"}
```

**Stream** — `metrics/sessions`: a continued run's event carries `resumed` beside `session`
(`metrics.session_event`, P10). A `kind: fix` line without `resumed` is a cold fixer; with it, a
continuation. That pair is the whole seven-day measurement of acceptance #3, and the scorecard's
`fixers` row (§2.7) is its reading.

**Printed.** One `continued <job> <item> → session <id> (round n)` line per continuation and one
`cold <job> <item> — <reason>` per fallback, in the tick's wave step — so the rate is visible in
the tick's own output the day it changes, not a week later in the scorecard.

## Stories

- S: The runtime's own session id is read off the log's last run and recorded on the run, never folded into the next — acceptance: `tests.test_continuation.RuntimeTests` (§3.1)
- S: A job carries a `resume` id, `build_command` emits `--resume`, and a runtime that cannot continue says so instead of failing — acceptance: `tests.test_continuation.RuntimeTests` (§3.1), the command and seam half
- S: One rule decides whether a session may be continued, and names the reason when it may not — acceptance: `tests.test_continuation.RuleTests` (§3.2)
- S: A review file becomes a findings message — the check table and the C/I lists, never a second brief — and an adjudication is never continued — acceptance: `tests.test_continuation.PromptTests` (§3.3)
- S: A round-one review with findings reaches the writer's own session and no new session is launched, in both lanes — acceptance: `tests.test_continuation.WaveTests` (§3.4)
- S: A dead writer session falls back to today's fixer launch in the same tick, with the reason printed — acceptance: `tests.test_continuation.FallbackTests` (§3.5)
- S: Fixer sessions are countable — `correct` counts as a fixer, a continuation carries the writer's session, and the scorecard prints cold fixers per merged PR — acceptance: `tests.test_continuation.MetricTests` and `tests.test_metrics` (§3.6)
