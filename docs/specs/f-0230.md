# F-0230 — 74 runs cancelled in eleven hours, and nothing says why

Over one product's `ci.yml`, one eleven-hour window, the heavy end-to-end job: **125 runs, 74 of
them cancelled.** Six on the trunk (a superseded-pass defect, since fixed), three on non-trunk
pushes, **65 on pull requests**. The CI queue's own log accounts for **13** of the PR cancels as
relief. The other ~52 have no explanation anywhere — not in the queue file, not in the lane's log,
not in the metrics stream. Each one held four to five heavy runners while it ran.

The guesses in the card are good guesses: `ci.yml`'s `cancel-in-progress` firing when the lane
force-pushes a branch whose run is mid-flight, and the lane's own `cancel_ci` after a merge. But
they are guesses, and the remedy the card proposes — hold a re-push while a run is in flight —
costs latency on every branch in the factory. **Nobody should pay that on a guess.**

So this card is the *find* half, done properly: **every cancelled run gets exactly one cause, from
a closed list, and a cause the factory itself caused is claimed by the code that caused it rather
than inferred afterwards.** The two halves of the answer come from two different places and this
spec keeps them apart:

* **the four cancels the factory makes with its own `gh run cancel`** — relief, step-silence stall,
  duplicate-push dedupe, and the post-merge cancel — write a durable claim the moment they are
  made, so they can never again be a hole in the accounting;
* **every other cancel** — the host's, which is what `cancel-in-progress` is — is told apart by
  reading the **pair of head shas**: the cancelled run's, and that of the run that superseded it.
  A superseding head that carries no commit the old one lacked except the trunk's own is a
  **content-free re-push** and its minutes are pure waste. One that carries work is a sound
  supersede. One whose shas the clone cannot resolve is **unknown**, and says so.

And the *cut* half is already written down, approved and planned, under a Feature this card never
names: **F-0203**. See C1. This spec does not re-spec it; it builds the instrument that will say
whether it worked, and the table names it by id in its own verdict line.

## The design

### §1 `asf/ci_cancels.py` — the causes

```python
#: every cause a cancelled run can have, in the order they are tried: the factory's own claims
#: first (it knows), then the run's own limit, then the two inferences, then the head pair, then
#: the honest nothing. First match wins; a run has exactly one.
CAUSES = ('relief', 'stall', 'dedupe', 'merged', 'timeout', 'rewrite', 'newhead',
          'unresolved', 'unclaimed')

#: what the operator does about each. `wasted` is the one this card exists to drive to zero.
GROUPS = {
    'traded':  ('relief', 'stall'),        # thrown away on purpose, to buy the trunk its runners
    'saved':   ('dedupe', 'merged'),       # the run was moot; the cancel kept the minutes
    'wasted':  ('rewrite',),               # a content-free re-push cut it short — nobody chose it
    'sound':   ('newhead', 'timeout'),     # the head is gone, or the job hit its own limit
    'unknown': ('unresolved', 'unclaimed'),
}
```

* **`relief`, `stall`, `dedupe`, `merged`** — a claim in the ledger names the run id.
* **`timeout`** — the run holds a job whose `started_at → completed_at` reaches its declared limit
  (`ci_pool.parse_timeouts` over the workflow file, else `DEFAULT_JOB_TIMEOUT_MIN`), within one
  minute. Tried **before** the supersede rules (C4).
* **`merged`** (inferred) — the run's PR has a `merged_at` at or before the run's `updated_at`.
* **`dedupe`** (inferred) — the run's `event` is `push`, its branch is not the trunk, and a
  `pull_request` run in the window has the same `head_sha`.
* **`rewrite` / `newhead` / `unresolved`** — a *superseding run* exists: the oldest run on the same
  branch whose `created_at` is after this run's `created_at` and at or before this run's
  `updated_at` (it started before this one was cut short — which is what `cancel-in-progress`
  means, and is strictly stronger than the `superseded` flag of P6). Its head sha and this run's
  go to `head_kind`.
* **`unclaimed`** — none of the above. The number the card is really about.

### §2 `head_kind(repo, old, new, trunk)` — the whole of the discrimination

```python
def head_kind(repo, old, new, trunk='origin/main', fetch=True, run=None):
    """``'rewrite'`` when ``new`` is ``old`` re-pushed with no new work — a rebase onto a moved
    trunk, a reword, a sign-off trailer, a rebuild that dropped trunk copies; ``'newhead'`` when
    it carries a commit ``old`` did not; ``'unresolved'`` when the clone cannot resolve one of
    them, or any git read fails. Never raises.

    The rule, measured on all four shapes (F-0230 P8): nothing of ``old``'s was dropped
    (``git cherry <new> <old>`` has no ``+``) **and** everything ``new`` gained is already on the
    trunk (every ``+`` of ``git cherry <old> <new>`` is an ancestor of ``trunk``). A rebase gains
    exactly the trunk's own commits; a reword and a sign-off gain nothing; a real push gains a
    commit that is not on the trunk.

    A sha the clone lacks is fetched once by sha (``git fetch -q origin <sha>``) and re-checked,
    the shape :func:`asf.workers.lifecycle.lost_commits` keeps for the same question; ``fetch``
    False skips even that.
    """
```

Four `git` reads in the resolved case, no network. `repo` is `product.repo_dir`; with no
`repo_dir` every pair is `unresolved` and the footer says so.

### §3 The claim — four one-line call sites

```python
CANCELS_FILE = 'ci-cancels.jsonl'
MAX_CLAIM_LINES = 5000

def claim(state_dir, run, cause, branch='', sha='', item='', workflow='', detail='', now=None):
    """Append one line saying the factory cancelled run ``run`` for ``cause``. Called on the line
    after the cancel succeeded, never on a dry-run path (F-0230 P4). Never raises: a ledger that
    cannot be written costs an ``unclaimed`` row in one table, never a refused cancel."""
```

One JSON object per line:

```json
{"run": 4821, "cause": "relief", "at": "2026-09-30T00:42:34Z", "branch": "worker/T-0629",
 "sha": "1f4c2ab9e", "item": "T-0629", "workflow": "ci.yml",
 "detail": "trunk run 4830 waited 21m for runners"}
```

The four sites, each immediately after the `out(…)` that already reports the cancel (P3, P4):

| site | cause | `detail` |
| --- | --- | --- |
| `asf/ci_queue.py:1531` (step-silence stall) | `stall` | the step it was silent in, and for how long |
| `asf/ci_queue.py:2254` (duplicate push) | `dedupe` | the PR run id that covers the sha |
| `asf/ci_queue.py:3037` (trunk/S1 relief) | `relief` | the `what` line the cancel already built |
| `asf/harvest/lane.py:3370` (`GitHubHost.cancel_ci`) | `merged` | `PR #<n> merged; the trunk run judges it now` |

`cancel_ci` reaches the state dir as `self.lane.state_dir`, which is how it already reaches the
session ledger. Its two callers (P3) are untouched.

`claims(state_dir, since=None)` reads the file back as `{run_id: claim}`, newest line per run id
winning, dropping anything unparsable. `claim()` rewrites the file keeping the newest
`MAX_CLAIM_LINES` when it grows past that, and only then (Out (g)).

### §4 The table — `asf ci cancels`

```
**CI CANCELS asf** — 2 days, 74 of 125 runs cancelled, 612 runner-minutes thrown away

| cause      | group   | runs | minutes | share |
| ---------- | ------- | ---: | ------: | ----: |
| rewrite    | wasted  |   41 |     318 |  52 % |
| relief     | traded  |   13 |     104 |  17 % |
| merged     | saved   |    9 |      61 |  10 % |
| newhead    | sound   |    6 |      74 |  12 % |
| unresolved | unknown |    3 |      41 |   7 % |
| dedupe     | saved   |    2 |      14 |   2 % |
| stall      | traded  |    0 |       0 |   0 % |
| timeout    | sound   |    0 |       0 |   0 % |
| unclaimed  | unknown |    0 |       0 |   0 % |

RED — 52 % of the cancelled runner-minutes were thrown away by a content-free re-push
(cause `rewrite`); F-0203 Tasks 2-4 cut exactly this. unknown 7 %.
```

Every one of the nine causes is a row, always, zeros included: a cause that never appears is a
cause the operator can see is zero, and `unclaimed` at zero is this card's own success condition.
The share column is of runner-minutes, not of runs, because runners are what the card is spending.
The footer is `RED` when the `wasted` share of minutes is at or above `WASTED_ALERT_PCT`, else
`OK`, and always names the `unknown` share beside it.

Flags: `--days N` (default 2), `--product P` (`env.add_product_arg`), `--no-fetch` (C7),
`--json` for the rows as a list of objects.

### What it looks like when it is there

An operator who sees a cancel storm runs one command and gets the answer the card had to guess at.
If `rewrite` dominates, F-0203's three unlanded Tasks are the cut, already written, and the same
table measures them afterwards. If `relief` dominates, the queue is over-cancelling and the
threshold is the dial. If `unclaimed` is non-zero, something outside the factory is cancelling
runs and nobody knew.

## Records

- **`<state>/<product>/ci-cancels.jsonl`** — new, and the only new file. Append-only, one JSON
  object per line (§3), beside `ci-queue.json` and `gate-visits.json`. It gains one line every
  time the factory cancels a run of this product and is truncated to the newest
  `MAX_CLAIM_LINES`. It is not part of the record; nothing but `claims()` reads it, and nothing
  refuses because it could not be written.
- **`<state>/<product>/ci-queue.json`** — unchanged in shape. Its `relief` and `stalls` records
  keep doing exactly what they do; the claim is written beside them, not instead of them, so
  `rerun_ids` and `_rerun_cancelled` are untouched.
- **The tick's log** — unchanged. Every `ci queue: cancelled …` and `harvest: <branch>: cancelled
  N CI run(s) …` line is byte-for-byte what it is today; the claim is silent. A rehearsal
  (`--dry-run`) prints its `would cancel …` lines and writes no claim (P4).
- **`asf ci cancels`** — new stdout, a table and nothing else (§4), read-only (C11). Its first
  line comes from `header.TITLES['ci cancels'] = 'CI CANCELS'`.
- **The `ci` metrics stream** — untouched (Out (d)). `cancelled_minutes` and `superseded` keep
  their current meaning; this table is a second, sharper reading of the same host, not a rewrite
  of that one.
