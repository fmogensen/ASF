# F-0257 — half a proof that reads as a whole one

From a product session on 2026-10-06. A coder wrote, in a pull-request body:

    Proves: S-0021 line 6 — tests/guard.test.ts (type guard, size guard, EXIF strip only)

and the tests behind it asserted the type guard and the size guard. The EXIF strip — the third
clause of acceptance line 6 — was not covered at all. The coder said so, in the claim, in the one
word `only`, and nothing read it. Under *no test, no done* that claim ticks line 6 whole: the
bullet flips to `- [x]`, History records `proved line 6`, and the Story is one line closer to done
on evidence its author had already labelled partial. It was fixed by hand in the PR body.

This is the one failure mode *no test, no done* cannot catch by construction. The rule asks
whether a line has a proof; it has no opinion about whether the proof covers the line. Every other
guard in the family is about absence — no claim, unknown Story, no such line, no such test, a
`proven by` path that is not a file — and absence is cheap to detect. A claim that is *present,
well-formed, truthful about its own incompleteness, and counted whole* passes every one of them.

So the claim's own text becomes evidence about itself. A `Proves:` line whose prose carries a
partial qualifier — `only`, `partial`, `partly`, `half`, `except`, `not yet`, `minus` — is not a
claim; it is a report of a gap. It is refused, the line stays unproved, the refusal is said out
loud on the Story's evidence and in the pull request, and the briefs stop teaching a grammar in
which a qualified claim is writable at all: a line is proved whole, or it goes under *Not proved*
with what is missing.

Four things:

1. **The grammar refuses it.** `asf.proves` reads the claim's *prose* — its text with the
   citations taken out — for a marker, and `parse` never returns a claim that carries one.
2. **The landing path reports it and never ticks it.** The refusal travels with the evidence to
   the record, where it becomes a line on the Story's `Ev` and the reason the acceptance line is
   still unproved. `tick_proven` never sees it.
3. **The pull request says it.** The body's `## Proves` block gains a sibling, `## Not proved`,
   carrying every refused claim with its reason — and every gap the coder declared deliberately.
4. **The briefs say whole or Not proved.** With a trailer to say it in: `Not proved: <S-id> line
   <n> — <what is still missing>`.

### Out

- **`proves.validate` and `proves.claims_on_branch` are not changed, and not deleted.** They are
  the natural-looking home for the refusal and they are dead (P2); a refusal written there would
  run nowhere. Their deletion is a cleanup card of its own, not this one's scope. The module
  docstring's stale "four callers" / "`asf proves`" sentence **is** corrected, because this card
  rewrites the paragraph above it.
- **`asf review_checks.py` is not touched** (P10). The card's phrase *review-checks flags it on
  the PR* names a command that reads one review file and cannot reach a commit, a branch or a
  claim; flagging on the PR is delivered by the body's `## Not proved` block, which is the lane's
  only PR-writing surface. See D10.
- **No new REPORT field.** The report block is shared by every brief kind; `left out:` already
  carries what was not done, and the briefs point a partial proof at it. The machine-read channel
  is the `Not proved:` trailer, which the lane and the evidence both already read.
- **The PR body is not rewritten on a later push** (P11). A refusal in a commit pushed after the
  PR opened is not in its body. The evidence path is the backstop: it re-reads the trunk and the
  merged PR body every tick, so the refusal still reaches the Story's `Ev` and the line still
  never ticks. Keeping the body current is `pr edit` work and a card of its own.
- **No change to `## Proves`, to `render`, or to what a counted claim does.** A claim with no
  marker parses, counts, ticks and renders exactly as it does today (P5).
- **A marker inside a quoted test name is not detected** (P4, D4). `tests/g.test.ts "EXIF strip
  only"` is counted, because the quoted span is the citation's own name by construction and
  nothing can tell a name from a qualifier inside it. The briefs' rule — a `Proves:` line is the
  path and nothing else — is the only guard for that case, and it is why the briefs are in scope.
- **`plan_tasks.STORY_ID_RE`'s four-digit limit is not fixed here** (P14). It is a live defect in
  the neighbour this card's own Stories will be linked through, found while checking which ids
  were safe to mint. It belongs to a Bug of its own; this spec records the measurement and raises
  it as a `NEEDS OPERATOR` line below.
- **No deferral grammar, no severity, no per-marker behaviour.** Every marker in the list refuses
  the same way, with the same reason, and the reason names which marker fired.

## The design

### 1. `asf/proves.py` — the partial marker, and what a refused claim is

The module's opening paragraph is rewritten: `parse` no longer returns every well-formed claim,
and the stale caller list goes with it (P2).

```python
"""asf.proves — the claim, its grammar and its idempotent tick (F-0040). A ``Proves:`` git
trailer on a Task's commits names the Story acceptance line the test proves; this module parses
it, counts the bullets ``line <n>`` counts against, validates one Task's claims against the
record, reads git for a branch's claims through an injected callable (never ``subprocess``,
D11), and flips a bullet from ``- [ ]`` to ``- [x]`` — once, never in reverse (D7).

A claim proves a line **whole** (F-0257). One whose prose qualifies it — ``only``, ``partial``,
``half`` and the rest of :data:`PARTIAL_MARKERS` — is refused: :func:`parse` does not return it,
so nothing counts it and nothing ticks, and :func:`parse_all` hands it back with its reason so
the landing and the pull request can say what was refused and why. A line a session knows it has
only part of is said in the other direction, with a ``Not proved:`` trailer
(:func:`parse_not_proved`).

Two callers read :func:`parse`: :mod:`asf.evidence.evidence` (which claims have landed) and
:mod:`asf.harvest.lane` (the pull-request body). Pure functions over text; no product
convention, no branch prefix, no card folder.
"""
```

The marker list, the reason, and the tunable:

```python
#: The words that make a ``Proves:`` claim a *qualified* one — a claim whose own prose says it
#: covers part of its line. Read in the claim's prose only (:func:`claim_prose`), never in the
#: commit subject and never in a path or a quoted test name: every separator a real path uses is
#: a word boundary, so a whole-text scan refuses ``tests/only-guard.test.ts`` and
#: ``tests/e2e/half/upload.spec.ts`` (F-0257 P3).
PARTIAL_MARKERS = ('only', 'partial', 'partly', 'half', 'except', 'not yet', 'minus')

#: Why a line with a refused claim against it is unproved — the fourth member of the ``why``
#: vocabulary beside :data:`NO_PROOF`, :data:`PATH_MISSING` and :data:`NAME_MISSING`.
PARTIAL_CLAIM = 'partial claim'


def partial_markers():
    """:data:`PARTIAL_MARKERS`, or the operator's ``proves.partial_markers`` where it is set and
    well-formed. Replaces the list wholesale (D6): the reason to set it is a word a product's
    prose uses normally, and appending could not remove one."""
    from asf import config_keys
    markers = config_keys.value('proves.partial_markers', PARTIAL_MARKERS)
    return tuple(str(m) for m in markers if str(m).strip())
```

`claim_prose` and `partial_marker` are the rule. A citation is a token with `::` or `/` in it, or
one ending in an extension — the same test `_PATHLIKE_RE` already applies to a `proven by` path,
plus `::`:

```python
#: A quoted span: a test's own name, never prose (D4). Blanked before the prose is read.
_QUOTED_RE = re.compile(r'"[^"\n]*"|“[^”\n]*”|`[^`\n]*`')
#: What a token must be stripped of before it is judged a citation or read as prose.
_EDGE = '`"\'()[]{},;.:'


def claim_prose(test):
    """The words of a claim's text that are **not** citations: quoted spans blanked, then every
    token holding ``::`` or ``/`` or ending in an extension dropped (:data:`_PATHLIKE_RE`), the
    rest stripped of edge punctuation and joined with single spaces — so a two-word marker
    (``not yet``) matches across tokens. ``''`` for a claim that is nothing but citations, which
    is what a well-written claim is."""
    text = _QUOTED_RE.sub(' ', test or '')
    words = []
    for token in text.split():
        bare = token.strip(_EDGE)
        if not bare or '::' in bare or _PATHLIKE_RE.search(bare):
            continue
        words.append(bare)
    return ' '.join(words)


def partial_marker(test, markers=None):
    """The first marker of ``markers`` (:func:`partial_markers` when None) that appears as a
    whole word in :func:`claim_prose` of ``test``, else ``''``. Case-insensitive."""
    prose = claim_prose(test)
    if not prose:
        return ''
    for marker in (markers if markers is not None else partial_markers()):
```

and `parse` splits:

```python
def parse_all(text, markers=None):
    """``(counted, refused)`` — every claim in ``text``, in first-seen order, duplicates
    collapsed on ``(story, line, test)``. A claim whose prose carries a partial marker
    (:func:`partial_marker`) goes in ``refused`` with ``refusal`` set to
    ``'partial claim: "<marker>"'`` and never in ``counted``: a line is proved whole or it is not
    proved (F-0257). A line that says ``Proves`` but names no id, no line or no test is in
    neither and raises nothing."""
    seen = set()
    counted, refused = [], []
    for m in CLAIM_RE.finditer(text):
        story = m.group('story').upper()
        line = int(m.group('line'))
        test = m.group('test')
        key = (story, line, test)
        if key in seen:
            continue
        seen.add(key)
        marker = partial_marker(test, markers)
        claim = Claim(story=story, line=line, test=test, raw=m.group(0),
                      refusal=f'{PARTIAL_CLAIM}: "{marker}"' if marker else '')
        (refused if marker else counted).append(claim)
    return counted, refused


def parse(text, markers=None):
    """The claims of ``text`` that count — :func:`parse_all`'s first half. A qualified claim is
    not among them, so no caller of this function can tick a line off one."""
    return parse_all(text, markers)[0]
```

The declared gap, with the same shape:

```python
#: A ``Not proved:`` trailer — the other half of the grammar (F-0257): the line this Task did
#: *not* prove, and what is missing. Same shape as :data:`CLAIM_RE`, no test path.
NOT_PROVED_RE = re.compile(
    r'^[ \t>*-]*Not proved:[ \t]*(?P<story>[A-Za-z]+-\d{4,})[ \t]+line[ \t]+(?P<line>\d+)'
    r'[ \t]*[-–—]+[ \t]*(?P<missing>\S.*?)[ \t]*$', re.M | re.I)

    ``refusal`` the stated gap, first-seen order, duplicates collapsed on ``(story, line,
    missing)``. Refused-by-the-parser and declared-by-the-author are the same fact about the same
    line, so they are the same type and :func:`render_not_proved` renders both (D11)."""
```
