# F-0263 — the escape an operator types four times, as one command

An item wedges: the lane holds a verdict nothing moves, a correction sits where the next session
cannot see it, the same rewrite comes back round after round. Every guard the factory has is
counted *per item* — the correction rounds, the relaunch cap, the loop head, the park — so the
one escape that works is to stop being that item. On 2026-10-06 a product's operator did it by hand:
T-42278 was retired and T-44931 minted to carry `worker/T-42278` forward.

By hand it is four commands and a fifth thing no command writes:

1. `asf retire T-42278 --why …` — the card leaves the board;
2. `gh pr close <n>` — its pull request must not land a removed card's work;
3. `asf new task --parent … --writes … --title …` — a sibling with the same footprint;
4. and then the part no command does: get the new item's session onto the *old* branch, so the
   work already pushed is carried and not re-done.

Between steps 1 and 3 the record says the branch belongs to a removed card, and the lane's own
answer to that is to archive it (P5, P6): the carry is a race against the next tick. Step 4 has no
command at all — the operator writes the branch onto the new card by hand, or writes a brief that
says "start from `worker/T-42278`", and the feeder's own row for a New Task overrules both (P2).

This card is: **one command that does all four, in an order where no tick can eat the branch in
between — and the three places that must honour a carried branch for the carry to be worth
anything.**

### In scope

- `asf reslot <item> --why TEXT [--title TEXT] [--keep-pr] [--product P]`: one command that retires
  a wedged **Task**, mints the sibling that carries its branch, hands the branch over in the
  ledger, and closes the pull request the retired card leaves behind — one record commit, and the
  refusals that stop it before it writes anything.
- The carry reaching a session: a Task's code row names the branch its card declares, on the New
  path as on the Active one.
- The carried branch surviving the carry: its commits are not rewritten, and the pull request the
  reslot closed is not read as the branch's own state.

### Preconditions the work depends on

- The record is a checkout with an `origin` (`_published` commits and pushes; `mint_id` claims an
  id by push when no `BACKLOG_ID_RANGE` is set) and at the package's schema version
  (`schema.require`, as every writing command checks first).
- The wedged item is a Task whose branch is on origin. A Task is the factory's unit of one
  session, one branch and one `writes:` footprint, and the only carded type a command may mint
  (P11).
- `links.branches` stays a list whose first entry is the card's branch (P1), and `links.supersedes`
  stays the record's word for "this card replaces that one" (`asf/groom/policy.py:354-371`).

### Out of scope

- **Bugs and Features.** A fresh Bug is not mintable by any command (P11) and a Feature's wedge
  sits on a spec or plan lane, which `asf correct` at the round cap and the adjudicate row already
  answer. `bug_rows` keeps its derived `fix/` branch; nothing can carry it.
- **Deciding that an item *is* wedged.** `asf reslot` is an operator's verb, like `asf correct`,
  `asf park` and `asf reset`: a person reads the loop and types it. No row, no tick step, no
  automatic reslot — a command that retires cards on its own judgement is a different card.
- **Releasing a park.** A hand-parked item is refused with `asf unpark` named, exactly as
  `asf correct` refuses one (`asf/workers/correct.py:100-102`).
- **`asf reset`.** It voids a *landing claim* and starts the same item over from the trunk, archive
  and all; reslot keeps the work and changes the item. Neither reads the other.
- **The retention and archive rules** (`archive_days`, `legacy_prefixes`, the `settled` census
  class). P6 says a carried branch is held while the sibling is open; the sweep itself is untouched.
- **Rewording a carried branch's subjects into something prettier.** P8's doubled
  `feat(T-0002): feat(T-0001): …` is the existing reword's shape; after C6 no reword runs on a
  carried branch at all, and the reword's own form is its card's business, not this one's.
- **Retitling or re-describing the pull request the reslot closes.** It is closed with a comment
  naming the new item (C5); a PR left open by `--keep-pr` keeps the title it has.

## The design

### 1. `asf reslot <item>` — a new module, `asf/workers/reslot.py`

```
asf reslot <item> --why TEXT [--title TEXT] [--keep-pr] [--product P]
```

`register(sub)` beside its neighbours in `build_parser` (`asf/cli.py:364-370`), one row in
`asf.surface.COMMANDS` (C9), and `tests/test_surface.py:50`'s count to 59.

`cmd_reslot(args)` is wrapped the way every record writer is — `_published(cmd_reslot, args,
resolve_record(args), f'record: reslot {old} → {new}')` — so both cards and the derived index land
in **one** signed-off commit and one push (P12).

**The refusals, all of them before the first write** (each one line to stderr, exit 2; the item is
untouched):

| refused when | the line |
| --- | --- |
| `--why` is empty | `asf reslot: --why is required — it is the reason written into the record` |
| the id is no item id, or no card | `asf reslot: <id> is no item id` / `asf reslot: <id> is not in the record` |
| the card is not a Task | `asf reslot: <id> is a <type> — reslot carries a Task's branch; a Feature's lane is asf correct's, and a Bug is minted by the groom` |
| the card already carries `removed:` | `asf reslot: <id> is already removed: <removed>` |
| a session of the item is running | `asf reslot: <id> has a session running — reslot it when it ends` |
| the item is parked by hand | `asf reslot: <id> is parked by hand — asf unpark <id> first` |
| the branch is not on origin | `asf reslot: <branch> is not on origin — there is nothing to carry; asf correct <id> --why … asks for another round on it` |
| the record is behind the schema | `schema.require`'s own `NEEDS OPERATOR` line, exit 3 |

The branch is the card's declared one when it has one, else the item's newest run's, else
`conventions.branch(code, <id>)` — one `git ls-remote --heads origin refs/heads/<branch>`
(`gitops.head_ref`, never a bare pattern) for the head and for the refusal above.

**The writes, in C3's order.** Each step prints its own line; a step that fails stops the rest and
says what the earlier ones already wrote.

1. **The sibling.** `mint_id(root, canonical, 'task', claim=True)`, then `write_new_item` with the
   old card's `parent`, `writes`, `stories`, `after`, `rank`, `area` and `priority`, the old
   title (or `--title`), `links.branches: [<branch>]`, `links.supersedes: [<old>]`, `state='New'`
   (P3: Active would not survive the next ingest), and a `## History` line
   `- <date>: created (reslot) — carries <branch> from <old>`. Its `## Description` opens with
   the carry: what wedged, in `--why`'s words, and the old id.
2. **The hand-over**, C4's one line, appended to the product's registry
   (`pool.sessions_path(product)`) through `lifecycle`'s own append — never an edit of a line
   already there.
3. **The retirement.** retire's own writer, so the card reads as every other retired card does:
   `removed: retired: <why> (reslot → <new>)` through `retire.removal(why, refs)` and `set_typed`,
   with the `## History` line `- <date> reslot: retired, removed — <why> (carried <branch> → <new>)`.
   The old card's standing correction is dropped as `asf correct --drop` drops one
   (`update_session(product, job, correction=None, dropped=…, drop_why=…)`): the wedge's record is
   closed, not left pending.
4. **The pull request**, unless `--keep-pr`: the number off the branch's newest lane record, else
   the old card's `links.prs`, through `forge.for_product(product).close_pr(number, reason)` with
   `reason` = `reslot: <old> retired, <new> carries <branch> — <why>`. A forge with no pull
   requests, or no number to close, is one line, never a failure.

Last line, always:

```
reslot T-42278 → T-44931 on worker/T-42278 (PR #972 closed): wedged — looping review round 7
```

### 2. The carry reaches the session — `asf/feeder/rows.py`

In `task_rows`, one local beside the loop's other facts:

```python
    for t in sorted(tasks, key=lambda v: (ix.rank(v), v['id'])):
        # F-0263: the branch a Task's code is on is the card's to declare (`links.branches`) —
        # a reslotted sibling carries the retired item's branch, and every row for it, launching
        # or not, must name the branch its work is actually on.
        code = _branch_of(t, product, 'task')
```

and `code` in place of `branch_for(product, 'code', t['id'])` at all ten sites
(`:1715`, `:1730`, `:1737`, `:1743`, `:1754`, `:1763`, `:1774`, `:1783`, `:1789`). The two
`branch_for(product, 'plan', t['id'])` reshape rows (`:1771`, and the `no writes:` recut) are
unchanged (C8). `_branch_of`'s docstring gains the second reason the field is read: *a reslotted
sibling carries the branch of the item it replaces (F-0263)*.

Nothing else moves: `branch_rows` already reads it (P2), the brief is rendered from the row (P10),
and `push_allow` from the row's branch (P9).

### 3. The carried branch keeps its history — `asf/harvest/lane.py`

`lane_refusal` takes the ids the card says it carries:

```python
def lane_refusal(repo, trunk, branch, item, conv=None, members=(), carried=()):
    ...
    ids = ([item] if item else []) + [m for m in members if m != item] + \
          [c for c in carried if c != item]
```

and the refusal text names them the way it names members: `commits do not name <item>, nor <the
carried ids>`. One reader for the fact, beside `delivery_members`:

```python
def carried_ids(items, item):
    """The ids ``item``'s card says it replaces (``links.supersedes``) — F-0263: `asf reslot`
    carries a wedged item's branch into a fresh sibling, and the commits on it name the item
    they were written for. A commit naming an id this card supersedes is traceable through the
    record that wrote the link; the lane therefore does not refuse it, and does not reword a
    carried branch's every subject to say the same thing twice (P8)."""
```

passed at the five `lane_refusal` call sites (`:1828`, `:2675`, `:2710`, `:2895`, `:2949`) exactly
as `delivery_members(self.items, item)` already is.

### 4. The PR the reslot closed is not the carried branch's state — `asf/harvest/lane.py`

One pure predicate, and one line in `branch_facts` before the facts are built:

```python
def reslot_closed(run, pr):
    """True when ``pr`` is the pull request ``asf reslot`` closed as it carried this branch into
    a fresh item: CLOSED, unmerged, and the number the run's own ``reslot`` record names.

    Such a PR is the retired item's last act, never the carried branch's state. Read as the
    branch's own, it sends a branch with work on it straight to STALE — a terminal state — and
    the carry is over before the first session (F-0263 P7)."""
    rs = (run or {}).get('reslot')
    if not isinstance(rs, dict) or not pr or not rs.get('pr'):
        return False
    return (str(pr.get('state') or '').upper() == 'CLOSED' and not pr.get('merge_sha')
            and str(pr.get('number')) == str(rs.get('pr')))
```

```python
    def branch_facts(self, b, run, head, pr, prs, running):
        conv, trunk, repo = self.conv, self.trunk, self.repo
        if reslot_closed(run, pr):
            pr = None          # F-0263: the carry's own close is not this branch's PR
```

placed above the `land_requested` read, so no later fact — the record's remembered `pr`, the
foreign-PR test, the head's checks — is built on a pull request the carry closed. The branch's
next pass therefore reads a head with work on it, an ended run and no PR, which is `PUSHED` and
then `PR_OPEN` "open a PR": a fresh pull request for the fresh item (P7).

## Records

- **`<record>/tasks/<new>.md`** — one new card: `parent`, `writes`, `stories`, `after`, `rank`,

- **`<record>/tasks/<old>.md`** — `removed: retired: <why> (reslot → <new>)` and `## History` →

  landed. The card leaves the feeder (`items_of` drops it) and keeps its runs, its rounds and the
  lane record that wedged it, which is the only place the loop can still be read.
- **One record commit** — `record: reslot <old> → <new>`, signed off, carrying both cards and the
  derived index, pushed once (P12). The hand sequence left two commits and two pushes, with a
  window between them in which the branch was a removed card's (P5).
- **`<state>/<product>/sessions.jsonl`** — one appended line, C4's: `job: reslot-<old>`,
  `item: <new>`, `kind: reslot`, `branch: <the carried branch>`, `started` and `ended` the same
  stamp, `end_reason: reslot`, and `reslot: {at, from: <old>, pr: <the number closed or carried>,
  head: <the branch head read>, why}`. It holds no seat, carries no lane record and names no
  account; `asf sessions` shows it as one ended `reslot` row with no result — the record of the
  carry, where the next reader of the branch looks. Plus the old item's correction cleared, as
  `asf correct --drop` clears one (`correction: null`, `dropped`, `drop_why`).
- **The pull request** — closed with one comment: `reslot: <old> retired, <new> carries <branch> —
  <why>`. Nothing is force-pushed, no branch is archived and no ref is deleted: the whole point is
  that the head on origin is the same head after the command as before it.
- **stdout** — the per-step lines and the one summary line of §1. No `NEEDS OPERATOR`: every case a
  person must decide is a refusal that names the command to type instead.
- **What is no longer written** — no `archive/<branch>` commit and no branch delete from the lane's
  STALE arm (P5), no `STALE … PR #<n> closed unmerged` on the carried branch (P7), and no reworded
  branch head: the carried commits keep their shas, so the new pull request's first CI run is the
  first one anybody pays for (P8, C6).
