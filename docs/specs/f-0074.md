# F-0074 — Generic by construction: no product convention in code, proven by a second product in CI

Epic: E-0001 — ASF 0.1 — a working factory. Branch: `spec/F-0074`.

The card was written when 14 modules carried the first product's conventions as literals. Most
of that purge has since landed under other cards (`e4e39df` the dataclass, `7bba7a0` the strict
check, `ce0b3ee` the sample product, `3d61ced` the goals file). What is on `origin/main` at
`b0a50d2` today, checked against the checkout, not the index:

- `asf/conventions.py` is the one conventions object — 14 fields, one documented default each —
  and `Product.conventions` (`asf/env.py:323-342`) builds it from the yaml's `conventions:`
  block plus `main`, `stage_limits` and `ci.test_command`.
- `tools/check_conventions.sh` greps `asf/**/*.py` for `tools/forbidden-conventions.txt` and is
  a required CI step (`.github/workflows/tests.yml`, "check conventions") and a test
  (`tests/test_conventions.py::CheckConventionsScriptTests::test_the_whole_package_is_clean`).
- `sample/` is a second product with `feature/`/`bugfix/` branches and `specs/`/`plans/` at the
  repo root; `tests/test_sample_product.py` drives `init`, `tick`, `next`, `doctor` on it, as
  its own CI step.

The card is not done, because the check passes by looking away and the proof stops short:

1. The script's `excludes=(…)` (`tools/check_conventions.sh:23-33`) skips four files "another
   card is rewriting right now", with a `TODO(B-0020)`. Today `asf/evidence/evidence.py` still
   carries 17 matching lines — `docs/superpowers/{plans,specs,briefs}`, `.sdd-input/…`,
   `docs/research/feature-matrix.md`, `/tmp/board-prs.json`, `/tmp/backlog-evidence.json`, and
   `~/.claude-workers/tools/*.py` in its docstring — and `asf/record/match.py:17` one;
   `asf/record/ingest.py` and `asf/tick/stale.py` carry none and are excluded for nothing.
2. The evidence provider hardcodes the first product's workflow names (`deploy-prod.yml`,
   `ci.yml`, the `deploy-dev` job — `asf/evidence/evidence.py:630-642`; `asf/metrics/metrics.py:
   625-628,667`) though the product yaml already has `ci.workflow` and `deploy_sha.workflow`.
   The pattern list cannot see those names.
3. Five modules keep their own copy of a default instead of reading the object:
   `asf/briefs/preamble.py:31-34` (`DEFAULT_SPECS_DIR`, `DEFAULT_PLANS_DIR`,
   `DEFAULT_REVIEWS_DIR`, `DEFAULT_REVIEW_PATTERN`), `asf/briefs/build.py:192-197`,
   `asf/tick/step_prs.py:31` (`WORKER_PREFIX = 'worker/'`), `asf/feeder/rows.py:197,202,222`
   (`default='fix/'`), `asf/evidence/evidence.py:44` (`DEFAULT_BRANCH_PREFIXES`),
   `asf/groom/inbox.py:67` and `asf/init.py:27` (`'inbox'`, though the object has
   `intake_dir`). The pattern list cannot see those either: they *are* the defaults, so a
   hand-kept list of the first product's literals never names them, and a change to one default
   in `conventions.py` silently leaves the copy behind.
4. The sample product proves the branch prefix (`bugfix/B-0001`) and nothing about paths: no
   assertion reads a brief's `Specs live in …` line, no evidence pass runs against `specs/`,
   and the sample's `intake_dir` and `reviews_dir` are the defaults, so a literal `inbox` or
   `docs/reviews` would pass.

This spec closes those four gaps. After it, the check has no per-card exclusions, its pattern
list is two sources (the first product's literals, and every path-shaped default generated from
`asf.conventions` itself), and the sample product differs from the defaults on every kind of
convention the card names — branch prefix, document tree, file name, id — with a test on each.

## Decisions

### In

- The four pending excludes go. `asf/evidence/evidence.py` and `asf/record/match.py` are
  purged; `ingest.py` and `stale.py` just leave the list. The list is the three documented
  adapters and nothing else; `--exclude` stays for an operator's own run.
- Every path the evidence provider reads becomes a field of `Conventions`: `briefs_dir`,
  `matrix_path`, `design_spec_name`, `decisions_file`, `reports_dir`, `report_pattern`. Each
  defaults to `None`, and `None` means *this product has no such thing*: the provider does not
  look, and the reader that needed it says so (the `goals_file` precedent, `3d61ced`).
- The workflow names move with them: `ci.workflow` → `ci_workflow`, `ci.dev_job` (new key) →
  `ci_dev_job`, `deploy_sha.workflow` → `deploy_workflow`, folded into the object the way
  `ci.test_command` already is. `None` → that `gh` query is not made and the sha is `None`.
- The `/tmp` cache bases go; the evidence cache lives only under `env.state_dir(product)`.
- The copies of defaults in the five modules go; each reads `product.conventions`.
- `tools/check_conventions.sh` gains a second pattern source, generated at run time by
  `python3 -m asf.conventions --forbidden`: one anchored regex per string default that has a
  separator in it (`/`, `{`, `#`). A copy of `'docs/specs'`, `'worker/'` or
  `'{reviews_dir}/{n}-{slug}.md'` anywhere in `asf/` outside the adapters fails the build.
- `tools/forbidden-conventions.txt` gains the workflow names and the sdd file names
  (`deploy-prod\.yml`, `\bci\.yml\b`, `deploy-dev`, `hotfix-.*-report`, `ci-diag-`).
- The sample product sets `intake_dir: cards`, `reviews_dir: reviews`, `review_pattern:
  reviews/{slug}-r{n}.md`, `default_bug_epic: E-0001` (already), and `test_sample_product`
  asserts the spec brief, the record layout and the evidence pass on those values.
- `.github/workflows/tests.yml`: the stale `TODO … continue-on-error` comment goes (the step
  has been required since `7bba7a0`), and `bash tools/check_generic.sh` becomes a step beside
  `check conventions` rather than only a test inside the suite.
- `docs/products.example.yaml` documents every new key under `conventions:` / `ci:` /
  `deploy_sha:`.

### Out

- The three adapters' exemption. `asf/conventions.py` holds the defaults; `asf/metrics/
  import_sessions.py` reads a foreign log format; `asf/hooks.py` writes the worker runtime's own
  settings file. Their literals describe something that is not this factory's convention.
- Bare-word defaults (`main`, `inbox`) in the generated patterns. `'main'` is git's word as
  much as ours, and `'inbox'` is a groom section key (`asf/groom/groom.py:240`) as well as a
  directory. They are proven by the sample product using different values, not by grep (D4).
- The *formats* `asf migrate` parses — D-row tables in a design spec, the hotfix report shape,
  the parity matrix table (`parse_rows`). Only their *locations* move to conventions; the
  parsers stay as they are. A product without those files gets empty sources and a line in the
  migrate report, as it does for the goals file today.
- Validating the `conventions:` block against a schema. Unknown keys are kept on purpose
  (`asf/conventions.py:20-23`); this card adds fields, not a rejection.
- Other CI providers' run queries. `ci_green_runs` reads `gh-actions` only, as today; a product
  on another provider still has no green-run evidence.
- The rule card that `forbidden-conventions.txt` cites ("Code carries no product convention").
  It lives in the product record, not in this repo.
- `~/.ASF` and `env.ASF_HOME` (`checked.txt`, `products/`). That is the operator's home, not a
  product's convention, and the check allows it by construction.

### Preconditions

Each checked against `origin/main` at `b0a50d2`:

- `Conventions.from_mapping` keeps unknown keys in `extra` and `.get()` reads fields and extras
  alike, so adding a field is source-compatible for a caller that already does
  `conv.get('briefs_dir')` (`asf/conventions.py:97-111,189-193`).
- `Product.conventions` folds top-level values into the block with `setdefault`, and a
  `conventions:` key of the same name wins (`asf/env.py:331-342`). The three new folds follow
  that exact pattern; `ci: none` is a string there and is already handled.
- `env.state_dir(product)` exists (`asf/env.py:391`) and `evidence._cache_file` already uses it
  whenever the product has a name (`asf/evidence/evidence.py:73-82`); the `/tmp` base is only
  reached with `product=None`, which `discover()`/`pr_list()` never pass because they call
  `env.load_product()` first.
- `tests/test_conventions.py::test_the_pattern_list_is_the_cards_inventory` pins ten patterns
  in `forbidden-conventions.txt`; this spec adds lines and removes none.
- `check_generic.sh` scans every tracked file for names; `check_conventions.sh` scans
  `asf/**/*.py` for conventions. Neither reads the other's list. This spec keeps that split.
- The sample record's `index.json` and ten cards are copied verbatim by the test; a new
  `intake_dir` changes what `asf init` creates in the record clone, not the cards.
- `python3 -m asf.conventions` is runnable from the checkout root (the script `cd`s to
  `git rev-parse --show-toplevel`, and CI runs it from the checkout with the package on the
  path). With `asf` installed via pipx and no checkout on `sys.path`, the module still resolves
  because the script sets `PYTHONPATH="$ROOT"` for that one call.

## The design

### `asf/conventions.py`

New fields, each with a documented default and `None` meaning *no such convention*:

```python
DEFAULT_BRIEFS_DIR = None        # where a product keeps brief documents on its trunk
DEFAULT_MATRIX_PATH = None       # the parity matrix file, read for Story status
DEFAULT_DESIGN_SPEC_NAME = None  # the one spec `asf migrate` reads as the design spec
DEFAULT_DECISIONS_FILE = None    # a decisions file `asf migrate` mines for D-rows
DEFAULT_REPORTS_DIR = None       # a directory of hotfix / diagnostic reports `asf migrate` adopts
DEFAULT_REPORT_PATTERN = None    # regex over a file name in reports_dir; None → every .md
DEFAULT_CI_WORKFLOW = None       # the workflow whose runs on the trunk are the green evidence
DEFAULT_CI_DEV_JOB = None        # the job in that workflow whose success marks the dev sha
DEFAULT_DEPLOY_WORKFLOW = None   # the workflow whose newest success marks the prod sha
```

and the dataclass gains the matching fields (`briefs_dir`, `matrix_path`, `design_spec_name`,
`decisions_file`, `reports_dir`, `report_pattern`, `ci_workflow`, `ci_dev_job`,
`deploy_workflow`). `field_names()` and `as_dict()` pick them up unchanged.

New at module level:

```python
def forbidden_patterns():
    """One extended regex per path-shaped string default (D4, D5), for
    tools/check_conventions.sh — a copy of a default in code is a convention in code."""
```

It walks `DEFAULT_BRANCH_PREFIXES` (the string values; `legacy` is a list and is skipped) and
every `DEFAULT_*` string that contains `/`, `{` or `#`, and returns
`['"]` + `re.escape(value)` + (`\b` if `value[-1]` is a word character else ``). With today's
defaults that is nine patterns: `worker/`, `fix/`, `spec/`, `plan/`, `docs/specs`,
`docs/plans`, `docs/reviews`, `{reviews_dir}/{n}-{slug}.md`, `### Task`.

`python3 -m asf.conventions --forbidden` prints them one per line; any other argv prints the
defaults as `name = value` lines and exits 0 (a small `__main__` at the bottom of the module).

### `asf/env.py`

`Product.conventions` folds three more values, each `setdefault`, each only when present:

```python
if isinstance(ci, dict):
    for src, dst in (('workflow', 'ci_workflow'), ('dev_job', 'ci_dev_job')):
        if ci.get(src):
            data.setdefault(dst, ci[src])
deploy = self._get('deploy_sha')
if isinstance(deploy, dict) and deploy.get('workflow'):
    data.setdefault('deploy_workflow', deploy['workflow'])
```

`CI_FIELDS` gains `'dev_job': _STR`. `deploy_sha` is not shape-checked today and stays so.

### `tools/check_conventions.sh`

- `excludes=(asf/conventions.py asf/metrics/import_sessions.py asf/hooks.py)`. The comment
  above it names the three and why; the `TODO(B-0020)` paragraph is gone.
- After the file patterns are loaded:
  ```sh
  while IFS= read -r line; do
    [ -n "$line" ] && patterns+=("$line")
  done <<< "$(PYTHONPATH="$ROOT" python3 -m asf.conventions --forbidden)"
  ```
  A failure of that command (non-zero, or no lines) is `check_conventions: could not read the
  defaults from asf.conventions` on stderr, exit 2 — the check must not pass because its second
  source went missing.
- The failure text names both sources: `… move it to the product yaml's conventions: block and
  read it through asf.conventions.Conventions — or, if it is the default itself, read it from
  asf.conventions rather than copying it`.
- `--print-patterns` (new) prints the merged list and exits 0, for a test to read.

### `tools/forbidden-conventions.txt`

```
deploy-prod\.yml
\bci\.yml\b
deploy-dev

hotfix-.*-report
ci-diag-
```

The header comment's "two documented exceptions" becomes "three" and names `asf/hooks.py`; a
paragraph says the path-shaped defaults are generated from `asf.conventions` at run time and
are not listed here.

### `asf/evidence/evidence.py`

- Module docstring: the three `~/.claude-workers/tools/*.py` provenance lines become "lifted
  from the first product's pre-asf board, parity and tick-table scripts" — no path.
- Gone: `PR_CACHE`, `EVIDENCE_CACHE`, `PLANS_DIR`, `SPECS_DIR`, `BRIEFS_DIR`, `REVIEWS_DIR`,
  `MATRIX_PATH`, `SDD_DECISIONS`, `HOTFIX_RE`, `DESIGN_SPEC_NAME`, `DEFAULT_BRANCH_PREFIXES`,
  `conv_dir`.
- `_cache_file(name, product)` → `os.path.join(env.state_dir(product), f'cache-{name}')`;
  `pr_list` uses `'prs.json'`, `load` uses `'evidence.json'`. No product → `ValueError`.
- `branch_prefixes(product)` returns `product.conventions.branch_prefixes` completed by
  `Conventions.prefix(kind)` for `code`, `fix`, `spec`, `plan` and `legacy_prefixes()` for
  `legacy` — the same dict shape as today, the values from the object.
- `discover()`:
  ```python
  conv = product.conventions
  plans_dir, specs_dir, reviews_dir = conv.plans_dir, conv.specs_dir, conv.reviews_dir
  briefs_dir, matrix_path = conv.briefs_dir, conv.matrix_path
  ```
  The `read_trees` call lists `briefs_dir` only when it is not `None`; `main_briefs` is `{}`
  otherwise and `brief_dirs` stays empty. The parity-matrix block runs only when `matrix_path`
  is set; otherwise `stories = {}` and every Story's `matrix_status` is `None` (which
  `story_state` already treats as "no matrix").
- The deploy-sha block:
  ```python
  prod = _newest_success(conv.deploy_workflow) if conv.deploy_workflow else None
  dev = _newest_with_job(conv.ci_workflow, conv.ci_dev_job, branch=product.main) \
        if conv.ci_workflow and conv.ci_dev_job else None
  ```
  the two helpers being today's inline code with the workflow and job name as parameters.
  `ci_green_runs` is unchanged: it already asks for successful runs on the trunk without
  naming a workflow (`asf/evidence/evidence.py:690-698`).
- `migrate_sources(product)`: `design_spec_name` from `conv.design_spec_name`; the decisions
  text from `conv.decisions_file` (`None` → `None`); hotfix reports from `conv.reports_dir`
  with names matching `re.compile(conv.report_pattern)` when set, else every `*.md`
  (`None` dir → `{}`). The specs tree it lists uses `conv.specs_dir`, not the module constant.
  The `design_spec_name=` parameter stays for `migrate`'s tests.

## Acceptance tests

The suite is stdlib `unittest`, run from the checkout root. Nothing below touches the network:
the sample tests use the stub `gh` from `tests/test_sample_product.py`, and the evidence test
builds its own repo and origin in a temp dir.
