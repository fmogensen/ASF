# F-0253 — a freeze that lives only in a file CI cannot open

The hand-build freeze went on on 2026-10-06. The operator's product config says
`conventions.merge: {mode: auto, factory_only: true}`, and the rule it turns on has existed since
round E: `python3 -m asf.factory_only` (#780) refuses a pull request into the trunk whose head
branch is under none of the product's factory prefixes, with two escapes — a release tag and a PR
that touches nothing but the changelog the release bot writes.

Nothing runs it. `.github/workflows/tests.yml` has no step that calls it, and it could not read the
key if it did: the key lives in `~/.ASF/products/<product>.yaml`, on the operator's machine, which
a GitHub runner never sees. So the freeze is a sentence in a file that the only process able to
enforce it cannot open, and a hand pull request into `main` goes green today exactly as it did
before the freeze.

There is a second hole, and it is the one that would survive the obvious fix. `fix/` is a *factory*
prefix — the fix lane's own. A person who names their branch `fix/anything` is under a factory
prefix and passes a prefix-only rule. This is not hypothetical: of the 108 live branches on origin
outside `archive/`, two are hand branches sitting under a factory prefix right now
(`fix/cloud-unknown-trunk-red-leak`, `fix/exact-path-overlap`), and the card names that case in its
own acceptance. A freeze with a four-character bypass is not a freeze.

Four things, in the order they pay:

1. **The inputs get committed.** `.asf/product.yaml` — generic, no slug, no path, no product name —
   carries `main`, the factory `branch_prefixes` and the `merge` map. CI reads the repository, not
   the operator.
2. **A factory prefix stops being enough.** `merge.require_item_id` (opt-in, off by default) asks
   that the name after the prefix start with an item id, because every branch the factory makes
   does and no hand branch does.
3. **The check runs where it already gates.** One step in the existing `tests` job — the job whose
   two matrix names are the required checks this repository's own merge script will not land
   without — so the rule is required today, with nothing outside the repository to change.
4. **The guide says how a product turns it on.** Two files and one key, and what the three escapes
   are.

### In

- **`.asf/product.yaml`** — a committed, generic product file holding exactly what the rule reads:
  `main: main`, `conventions.branch_prefixes` (the five kinds and an empty `legacy`), and
  `conventions.merge: {mode: auto, factory_only: true, require_item_id: true, bot_paths:
  [CHANGELOG.md]}`. No `product`, no `repo_slug`, no `repo_dir`, no `backlog_dir`: nothing a
  machine or an account is named in.
- **`conventions.merge.require_item_id`** — a new boolean in the `merge` map, default false, added
  to `MERGE_MAP_KEYS` (P4) and to `Conventions` as `merge_require_item_id`. Meaningful only when
  `factory_only` is on.
- **`factory_only.ITEM_RE` and one clause in `verdict`** — with `require_item_id` on, a head under a
  factory prefix must also have `ITEM_RE` match `conv.strip_prefix(head)`; the regex is
  `^[A-Za-z]+-\d{4,}`, anchored at the start so a suffix is allowed (P6) and five-digit ids match
  (P8). When the prefix matches and the id does not, the refusal says so in those words and names
  the prefix it did match.
- **`tools/check_factory_only.sh`** — the workflow's one-line entry point, in the `check_*.sh`
  family and named away from the CI class (P14). It forwards every argument to the module and
  supplies `--files` itself, from `git diff --name-only HEAD^1 HEAD`, only when the caller passed
  none and `GITHUB_BASE_REF` is set (P12). A diff it cannot read is exit 2 with its own line, never
  an empty file list.
- **One step in the `tests` job of `.github/workflows/tests.yml`** — `run: bash
  tools/check_factory_only.sh`, a single line so it is readable through `env.loads` (P13), placed
  before `install with pipx` so a refused pull request costs seconds and no install.
- **`tests/test_factory_only.py`** — two classes: the committed file's content and its drift pin,
  and the entry point's refusal and pass cases driven through `--head`/`--base`/`--files`.
- **`tests/test_workflow.py`** — one class: the step is in the job whose matrix names are the
  required checks, and it runs the script.
- **`docs/guide/operating.md`** — one subsection after *The trunk ruleset*: what a product commits,
  where the step goes, the escapes, and how the rule comes off.
- **`docs/products.example.yaml`** — the commented merge map gains the new key and a line saying the
  rule's inputs must be committed for CI to read them.

### Out

- **No change to how the rule decides anything else.** The tag escape, the bot-paths escape, the
  *not a pull request* case, the *a PR into `<base>`, not the trunk* case and the off-by-default
  are P1's, untouched. The one new clause fires only under a new key that is off unless a product
  sets it.
- **No standalone `factory-only` check, job or workflow** (P10). It would not be required until a
  person edited the operator's product file and the trunk ruleset — the exact *config CI cannot
  read* this card exists to end.
- **No ruleset, branch-protection or `landing_checks` change.** `asf ruleset` and the merge queue
  are the server-side door and are their own cards; this one adds a check inside the door that is
  already required.
- **`asf.factory_only._diff_files` is not changed or deleted** (P12). It is the right default for a
  product whose workflow checks out with `fetch-depth: 0`; this repository's workflow does not, so
  its step passes `--files` and never reaches it.
- **No doctor row, and no comparison against the operator's product file.** CI cannot read that
  file and neither can a test; a row that claims the two agree would be a row that cannot know. The
  disagreement is named in *What a person decides* below, and carried as a `NEEDS OPERATOR` line in
  this session's report.
- **`lane.ITEM_ID_RE` is not fixed here** (P8). It is a real defect in landing attribution's
  neighbour, found while looking for a regex to reuse, and it belongs to a Bug of its own — not to
  a card about CI enforcement. This spec only declines to reuse it.
- **`asf.ci`'s `FACTORY_ONLY` class, `FACTORY_ONLY_PATHS` and `globs_from_workflow` are untouched**
  (P14). Nothing here changes how much CI a push owes.
- **No `env.loads` block-scalar work.** P13's limit is worked around by keeping the step's `run` to
  one line, which is also how every other cheap check in this workflow is written.
- **The pull_request trigger is not narrowed, and outside contributions are not exempted.** Under
  the freeze an outside contributor's PR into `main` is refused like any other hand branch; the
  refusal line says how to land it. Narrowing the trigger would hide the refusal rather than make
  it.

### What a person decides, and nothing here can

The committed file and the operator's product config are two copies of one rule, and only a person
may make them agree. Read on 2026-10-07, the operator's `~/.ASF/products/<product>.yaml` carries
`conventions.merge: {mode: auto, factory_only: true}` and neither of the other two keys. So on the
day this lands, CI refuses `fix/typo` and the tick — which reads the operator's file, not the
committed one — still allows it. Nothing in the repository can see that difference and no test can
assert it (Out, above): a product file CI cannot open is this card's premise, not something it ends.

The decision, carried as a `NEEDS OPERATOR` line in this session's report and not taken here:
whether the operator's own `conventions.merge` gains `require_item_id: true` and `bot_paths:
[CHANGELOG.md]` so the tick's gate and CI read one rule, or the two stay deliberately apart — CI
strict on the branch name, the tick permissive because it has the lane's own evidence and CI has
only a name. Both answers are implementable exactly as specified below; neither changes a line of
the committed file, which is the product's statement about itself and not a mirror of the operator's.

## The design

### 1. `.asf/product.yaml` — the rule's inputs, committed and generic

New file, at the repository root, the path the module's own docstring already names:

```yaml
# .asf/product.yaml — the conventions this repository's CI must read for itself.
#
# `conventions.merge.factory_only` is enforced by a CI step (tools/check_factory_only.sh), and a
# GitHub runner cannot see the operator's ~/.ASF/products/<product>.yaml. So the inputs the rule
# needs live here, in the repository, and nothing machine-, account- or product-specific does:
# no repo_slug, no repo_dir, no backlog_dir, no product name. The operator's own product file
# stays the tick's source of truth for everything else.
main: main
conventions:
  branch_prefixes:
    code: worker/
    fix: fix/
    spec: spec/
    plan: plan/
    direct: cloud/direct-
    legacy: []
  merge:
    mode: auto
    factory_only: true
    require_item_id: true
    bot_paths: [CHANGELOG.md]
```

Measured in this worktree: `env.load_file` reads it, `env.product_problems` returns `([], [])`,
`env.validate_product_text` returns `[]`, and `Conventions.shape_findings()` is `[]` once
`require_item_id` is in `MERGE_MAP_KEYS` (P3, P4).

### 2. `merge.require_item_id` — a factory prefix is not a factory branch on its own

`asf/conventions.py`, beside the two keys that are already there:

```python
#: ``merge.require_item_id`` (:data:`DEFAULT_MERGE_REQUIRE_ITEM_ID`): under ``factory_only``, a
#: head branch under a factory prefix must also be named after an item (``worker/T-0123``, a
#: suffix allowed) — every branch the factory makes is, and a hand branch under a factory prefix
#: (``fix/typo``) is not. Off by default: a product whose branches are named for the work rather
#: than for a card (``worker/add-login``) keeps passing.
DEFAULT_MERGE_REQUIRE_ITEM_ID = False
MERGE_MAP_KEYS = ('mode', 'factory_only', 'bot_paths', 'require_item_id')
```

the field on `Conventions`:

```python
    #: ``merge.require_item_id`` (:data:`DEFAULT_MERGE_REQUIRE_ITEM_ID`).
    merge_require_item_id: bool = DEFAULT_MERGE_REQUIRE_ITEM_ID
```

and one line in `from_mapping`'s `merge` branch, in the shape the two keys beside it use:

```python
            if 'require_item_id' in merge:
                kwargs['merge_require_item_id'] = _truthy(merge['require_item_id'])
```

`asf/factory_only.py` gains `re` to its imports, the regex, and one condition on the test that is
already there. With the key off `named` is True and `verdict` reads exactly as it does today:

```python
#: A branch named after an item: the prefix stripped, what is left starts with an item id.
#: ``\d{4,}`` — four digits is the floor, not the ceiling (B-0273), and the match is anchored at
#: the start only, so a retry or replan suffix (``plan/F-0097-replan``) is still that item's.
ITEM_RE = re.compile(r'^[A-Za-z]+-\d{4,}')
```

The id test is folded into the existing prefix test rather than returning from inside it, so the
bot-paths escape keeps its place: a branch that fails the id test but touches only `CHANGELOG.md`

refusals then differ only in their reason — `merge.require_item_id` names the lane whose prefix was
matched, `merge.factory_only` lists the prefixes none of which was. Measured over the thirteen

two files, a tag, a PR into `next`, and the key off), each reads as stated above.

### 3. `tools/check_factory_only.sh` — the one-line CI entry point

```bash
#!/usr/bin/env bash
# tools/check_factory_only.sh — the factory-only MERGE rule: what may land on the trunk.
#
# Not asf.ci's FACTORY_ONLY *class*, which says how much CI a push owes and is deliberately not
# the landing gate (asf/ci.py). This is the other one: `asf.factory_only` refuses a pull request
# into the trunk whose head branch is not one of the factory's, reading its inputs from the
# committed .asf/product.yaml because a runner cannot see the operator's config.
#
#   check_factory_only.sh                      a CI run: --head/--base/--ref from GitHub's own
#                                              variables, --files from the merge ref's diff
#   check_factory_only.sh --head … --base … --files …   every argument forwarded; no git is read
set -euo pipefail

HERE="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
ROOT="$(git rev-parse --show-toplevel)"
PRODUCT_FILE="${FACTORY_ONLY_PRODUCT_FILE:-$ROOT/.asf/product.yaml}"

if [ ! -f "$PRODUCT_FILE" ]; then
  echo "check_factory_only: missing $PRODUCT_FILE — the rule's inputs are committed, not configured" >&2
  exit 2
fi

args=("$@")
given=0
for a in "$@"; do [ "$a" = "--files" ] && given=1; done

# A pull_request run checks out the merge ref, whose first parent is the base tip: HEAD^1..HEAD is
# the PR's own diff and depth 2 is enough (the client ratchet in tests.yml fetches the same way).
# The module's own origin/<base>...HEAD default needs a merge base, which this checkout has not got.
if [ "$given" -eq 0 ] && [ -n "${GITHUB_BASE_REF:-}" ]; then
  git -C "$ROOT" fetch --no-tags --depth=2 origin "${GITHUB_SHA:-HEAD}" >/dev/null 2>&1 || true
  if ! changed="$(git -C "$ROOT" diff --name-only HEAD^1 HEAD 2>&1)"; then
    echo "check_factory_only: cannot read the pull request's diff against HEAD^1 — the base tip is" >&2
    echo "not in this checkout (actions/checkout fetch-depth, or a fetch that failed):" >&2
    printf '%s\n' "$changed" >&2
    exit 2
  fi
  mapfile -t files <<< "$changed"
  args+=(--files)
  for f in "${files[@]}"; do [ -n "$f" ] && args+=("$f"); done
fi

cd "$ROOT"
exec env PYTHONPATH="$HERE/..${PYTHONPATH:+:$PYTHONPATH}" \
  python3 -m asf.factory_only --product-file "$PRODUCT_FILE" "${args[@]+"${args[@]}"}"
```

Three exit codes, each its own thing: 0 the rule passes, 1 the rule refuses, 2 the checker could not
run — the same three `check_generic.sh` uses, and the reason an unreadable diff is never an empty
file list (D10).

### 5. The docs

`docs/guide/operating.md`, a new subsection immediately after *The trunk ruleset: one door to the
trunk* and before *Merging an agent PR*:

> **The factory-only rule: a hand branch into the trunk is refused.** The ruleset above decides
> *how* a change reaches the trunk; this decides *whose* changes may. With
> `conventions.merge.factory_only: true` a CI check refuses a pull request into the trunk whose head
> branch is under none of the product's `branch_prefixes`. Three escapes stand: a release tag (no
> pull request), a PR touching nothing but `merge.bot_paths` (default `CHANGELOG.md`, the file the
> release bot writes), and a PR into any branch but the trunk.
>
> A runner cannot read `~/.ASF/products/<product>.yaml`, so turning the rule on takes two committed
> files, not one config key:
>
> 1. `.asf/product.yaml` — `main`, the factory `branch_prefixes`, and
>    `conventions.merge: {factory_only: true, bot_paths: [CHANGELOG.md]}`. Nothing else: no
>    `repo_slug`, no `repo_dir`, no account. This file is the rule's only input.
> 2. One step in the workflow job whose check is already required — for this repository the `tests`
>    job, whose `tests (3.12)` / `tests (3.13)` names `tools/merge-pr.sh` will not land without:
>
> ```yaml
>       - name: the factory-only merge rule (a hand branch into main is refused)
>         run: bash tools/check_factory_only.sh
> ```
>
> Put it in an *already required* job. A job of its own is a check nobody requires until someone
> adds its name to `conventions.landing_checks` and to the trunk ruleset — and those live outside
> the repository, which is the hole this rule would otherwise still have.
>
> `conventions.merge.require_item_id: true` adds the second half: a head under a factory prefix must
> also be named after a card (`worker/T-0123`, a suffix allowed). Without it `fix/` is a factory
> prefix and `fix/typo` passes, which is a four-character way round the rule. Leave it off for a
> product whose branches are named for the work rather than for a card (`worker/add-login`).
>
> The rule comes off the way it went on: `factory_only: false` in the committed file, one line, one
> pull request — which the rule itself lets through, because that PR is on a factory branch.
