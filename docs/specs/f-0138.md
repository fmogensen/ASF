# F-0138 — the pool asks whether a launch can *start*, and the account dies because it could not *finish*

`asf.workers.headroom` already made the first half of this move. A quota reading says how full an
account's window is *now*, so a wave that put five heavy specs on one account at 51% learned what
they cost only when they all died on `You've hit your session limit`. The fix was an estimate:
each launch carries its share of the window, and `Pool.headroom` places a launch only while
`five_h_pct + this wave's committed launches + an allowance for the running ones + this launch`
stays under the guard.

Three things that estimate does not know:

1. **It only knows one window.** `asf/workers/pool.py:378-398` reads `five_h_pct` and nothing
   else. `asf.workers.quota` bands three windows — `five_h`, `seven_d`, `seven_d_model` — and a
   launch spends all three at once. An account at 94% of `seven_d` against a stop of 95 has a
   **free 5h window**, so it looks like the best seat in the pool; the run is placed, works for
   fifty minutes, and dies `quota-exhausted` on the weekly limit. The band catches that account
   only once the reading has already crossed 95 — i.e. after the run that crossed it was lost.
2. **It does not know the account's plan.** `quota_guards.five_h_usd` is one scalar for the whole
   pool: the dollars of 100% of *a* 5h window. Two accounts on different plan sizes do not have
   the same window. Put one number on both and every share is wrong on both — too small on the
   smaller plan (the pool over-loads it and loses runs) and too large on the larger one (the pool
   under-loads it and leaves capacity idle). This is the card's `by provider kind`: the scale
   belongs to the kind of account, not to the pool.
3. **It does not know when the window resets, or how long the run takes.** The source already
   prints `five_h_resets_at` and `quota.stale_stop` already reads it — but only for a *stale*
   reading. A live account at 93% whose 5h window resets in six minutes is the single best place
   for a fifty-minute run, and today it is the one account the pool refuses while it loads a
   60% account further.

All three are the same defect: **the pool predicts a launch's first minute and places on that.**
This card makes it predict the run — every window it spends, at that account's own scale, over
the span the run actually takes.

### In

1. **`worker_pool.accounts[].provider`** — a provider-kind label on an account: an opaque operator
   string naming which sort of account it is, so accounts that share a window scale share an
   estimate. Unset is the kind `default`. Validated by `asf.env.validate_worker_pool`, carried on
   `Account.provider`.
2. **`quota_guards.window_usd.<provider>.<window>`** — the dollars of 100% of that window, for
   that provider kind. The existing scalar `quota_guards.five_h_usd` stays exactly what it is: the
   pool-wide `five_h` fallback for every kind that names none.
3. **A learned `five_h_usd` per provider kind.** `five_h_usd_from_samples` today pools every
   account's intervals into one median. It becomes `five_h_usd_by_provider`, grouping the same
   intervals by the provider kind of the account they came from. A kind with too few intervals
   falls back to the pool-wide value, then to the fixed table.
4. **The long windows are derived, never learned.** A 7-day window is
   `WINDOW_LENGTH['seven_d'] / WINDOW_LENGTH['five_h']` = 33.6 five-hour windows long, so absent a
   configured `window_usd`, a kind's `seven_d` dollars are its `five_h` dollars × that ratio. The
   ratio is computed from P3, not written down twice.
5. **Every readable window is projected**, each against its own stop (P2), each at its own share.
   The binding window names itself in the wait line — except `five_h`, whose line is left byte for
   byte as it is (P11).
6. **The reset is credited.** When the source names `<window>_resets_at` and it falls inside the
   run's expected duration, only the fraction of the launch's share spent *before* the reset counts
   against the reading; the remainder lands in a window that will be empty.
7. **The run's expected duration** — `CostTable.minutes(kind, model)`: the median span
   (`ended − started`) of that `(kind, family)`'s recent runs when history is thick enough,
   else the fixed `DEFAULT_MINUTES` table, measured from this product's own runs.
8. **The samples record every window and the provider kind**, so a later reading can be scaled and
   attributed. A sample line written before this card folds into `default`.

### Out

| Not in this card | Why |
| --- | --- |
| A dollar-budget capacity model for an account with no percentage window | Nothing reads a remaining balance: `NoQuotaSource` prints `0/0` and such an account is simply not under the guard. That is today's behaviour and it stays. A provider kind is a *scale* here, not a second capacity model. |
| Per-provider `stop` / `cooldown` | The guard is a safety margin below the vendor's own 100%, and 95% of a window means the same thing on every plan. Only the *size* of the window differs, and `window_usd` is where size lives. |
| Any change to `quota.band` | The band judges a reading against a threshold; it is already per window and already correct. This card changes only what the pool *projects* on top of a reading. |
| Any change to `pick_account`'s ordering, the reserve, the cooldown rule or `banded_seats` | Free beats cooling, lowest load wins, an unreadable account is stopped. Untouched — and P12 pins that the fair share does not read headroom, so no capacity figure moves. |
| A launch whose share alone exceeds the guard | It fits no account, empty window or not, and today it waits with the `headroom: …` line naming the closest. Unchanged: making the pool say so distinctly is its own card. |
| Naming the provider kind in `asf status`' quota cell | The cell is already dense (`acct-a 51%/10% cooldown stale since 14:02 — resets 15:20`). The kind is config, and `asf doctor` is where config is read back. |
| Learning `seven_d_usd` from samples | A 7-day window moves ~1.5 points per fully-burned 5h window, and an interval needs `MIN_DELTA` = 2 points inside `MAX_GAP` = 90 minutes to count. The intervals do not exist; a value pretending to be learned from three of them would be noise. Derived (In 4) or configured (In 2). |

### The choices

| # | Chosen | Against | Why |
| --- | --- | --- | --- |
| D1 | `provider:` on the account, an opaque operator label | an enum of known plan kinds; deriving the kind from `auth_env` or `config_dir` | The product names no vendor and no plan (`tools/check_generic.sh`). An opaque label is the only form that keeps the knowledge in operator config, which is exactly where `window_usd` also lives. |
| D2 | Percent-of-window as the unit throughout | dollars as the unit, converted once at the guard | Every guard, reading and existing test is in percent. Dollars are the *bridge between* kinds, not the currency of the arithmetic; keeping percent means the 5h path is provably unchanged. |
| D3 | `Pool._committed` becomes the list of `(kind, model)` taken, not a float | a float per window | A wave's committed launches must be re-priced per window, and per provider. The list is the input; a float is a projection of it and cannot be re-projected. P9 says nothing outside reads it. |
| D4 | The 5h wait line stays byte-identical; a non-5h window prefixes its own name | one uniform line naming the window always | P11: three assertions pin the current string, and the operator has read it for weeks. A new window is new information and announces itself; the line that was already right does not change. |
| D5 | `over` carries `(projected − guard, why, projected)`; the reason is `min` over the overshoot | keep `min` over the raw projection | The projection is only comparable across accounts while every guard is equal. The overshoot is comparable across differing guards and windows, and with equal guards it orders identically — so no current behaviour moves. |
| D6 | A window with no `<window>_usd` and no default share is **not projected** | guess a share | Unknown is unknown. `five_h` has `DEFAULT_COST` (a real fixed table) and the long windows have the ratio, so in practice every window is priced; the clause is the floor that keeps a future fourth window from being invented into existence. |
| D7 | The reset credit is linear in the run's span | model the burn curve; or treat any reset inside the run as full relief | Linear needs only two numbers we have (the reset, the duration) and errs toward *holding* the launch back, since real burn is front-loaded. Full relief would place a run on an account it drains before the reset arrives. |
| D8 | `DEFAULT_MINUTES` from this repo's own measured table | a single constant | `docs/config.example.yaml:39-48` already carries the measurement — hours and runs per kind. Dividing them is a real per-kind duration, not a guess, and it is the same source the cost table's defaults came from. |
| D9 | `five_h_usd_from_samples` stays, as a wrapper over the per-provider function | rename it | It is public, tested at `tests/test_quota_headroom.py:102`/`:110`, and its meaning (the pool-wide value) survives as the fallback. Back-compat by addition, never by rename. |
| D10 | A stale reading still short-circuits to `fits=True` | project a stale reading per window | A stale percentage under its stop is history, not state (`quota.py` module docstring). That contract is the band's, and this card does not reopen it. |

## The design

### 1. The provider kind, on the account

`asf/workers/pool.py` — `Account` gains one field, `Account.from_dict` one key:

```python
DEFAULT_PROVIDER = 'default'
```

```python
#: ``provider``: the provider *kind* — an opaque operator label naming what sort of account this
#: is, so accounts that share a window scale share one estimate (F-0138). The window's dollars are
#: read per kind (``quota_guards.window_usd.<provider>``); accounts that name none are one kind,
#: :data:`DEFAULT_PROVIDER`.
self.provider = str(provider or DEFAULT_PROVIDER)
```

and a map the wave can hand to the sample recorder:

```python
def providers(self):
    """``{account name: its provider kind}`` — what a sample line is attributed to."""
    return {a.name: a.provider for a in self.accounts}
```

`asf/env.py` — `validate_worker_pool` gains one check per account, in the shape of its neighbours:

```python
provider = acct.get('provider')
if provider is not None and (not isinstance(provider, str) or not provider.strip()):
    problems.append((label + '.provider', f'must be a provider-kind name, not {provider!r}'))
```

`docs/config.example.yaml` gains the key on `acct-a`, commented, and the `window_usd` block under
`quota_guards`:

```yaml
    - name: acct-a
      role: local
      cap: 2
      config_dir: ~/.ASF/accounts/acct-a
      # provider: plan-small   # the provider *kind*: accounts of one kind share one window scale.
      #                        # Unset = the kind `default`. See quota_guards.window_usd.
```

```yaml
quota_guards:
  # five_h_usd: 45        # the dollars of 100% of a 5h window, pool-wide (unchanged)
  # window_usd:           # …and per provider kind, which overrides it. A window not named is
  #                       # derived from that kind's five_h × the window-length ratio (7d = 33.6×).
  #   plan-small: {five_h: 12}
  #   plan-large: {five_h: 48, seven_d: 1200}
```

### 2. `CostTable` — dollars in, a share of any window out

`asf/workers/headroom.py`. The table keeps `shares` and `cost` (D9, P11) and gains three things:

```python
#: The length of each window as a multiple of the 5h one — where a long window's dollars come
#: from when the operator names none (F-0138 In 4). Computed from
#: :data:`asf.workers.quota.WINDOW_LENGTH`, so the two can never drift.
WINDOW_RATIO = {w: quota.WINDOW_LENGTH[w] / quota.WINDOW_LENGTH['five_h']
                for w in quota.WINDOW_KEYS}

#: Minutes one run of a kind takes: the six kinds ``docs/config.example.yaml`` measured over this
#: product's own build, as its session hours ÷ its runs. A kind that table does not measure takes
#: ``*``. The median of recent history replaces an entry once :data:`MIN_RUNS` of that
#: ``(kind, family)`` have both ends.
DEFAULT_MINUTES = {'spec': 53, 'spec-amend': 53, 'plan': 32, 'coder': 82, 'task': 82,
                   'fix-bug': 66, 'correct': 30, 'adjudicate': 41, '*': 45}
```

```python
class CostTable:
    """``cost(kind, model)`` → percent of a 5h window, as before. ``share(kind, model, provider,
    window)`` → percent of *that* window on *that* provider kind, or None when the window has no
    known dollars and no default share (D6). ``minutes(kind, model)`` → how long the run is
    expected to take.

    ``window_usd`` is ``{provider: {window: usd}}`` — the operator's
    ``quota_guards.window_usd`` merged over the per-provider estimate merged over the pool-wide
    ``five_h_usd``; ``usd`` is ``{(kind, family): median dollars}``; ``spans`` is
    ``{(kind, family): median minutes}``."""
```

`share` is the whole of the new arithmetic, and it is four lines:

* the launch's dollars for `(kind, family)` and the window's dollars for `(provider, window)` are
  both known → `usd × 100 / window_usd`;
* else, for `five_h`, the fixed `DEFAULT_COST` share (`cost`) — today's answer;
* else, for a longer window, `cost(kind, model) / WINDOW_RATIO[window]` — the 5h share spread over
  a window that many times longer;
* else `None` (D6).

`window_usd` resolution, per `(provider, window)`, first hit wins: the operator's
`quota_guards.window_usd[provider][window]`; that kind's `five_h` × `WINDOW_RATIO[window]`; the
pool-wide `quota_guards.five_h_usd` × the ratio; the learned per-kind `five_h` × the ratio; the
learned pool-wide `five_h` × the ratio; `None`.

`estimate(runs, window_usd=None, allowance=…, five_h_usd=None)` keeps its old keyword and gains the
new one; it now records medians in **dollars and minutes** and lets `share` do the division, rather
than baking one scale into `shares`. `five_h_usd_from_samples(samples, runs)` becomes a wrapper
over `five_h_usd_by_provider(samples, runs)` → `{provider: usd}`, returning that dict's `default`
— or, when no sample carries a provider, the single pool-wide median it returns today (D9).

`record_samples(usage, providers=None, now=None)` writes every window it was given, and the kind:

```python
{"ts": "…", "account": "acct-a", "provider": "plan-small",
 "five_h_pct": 51, "seven_d_pct": 22, "seven_d_model_pct": null}
```

`table_from_config(cfg, now=None)` maps each run's `account` (P7) through
`{account: provider}` before grouping the samples, so a kind's dollars are learned from its own
accounts' intervals.

### 3. `Pool.headroom` — every window, over the run's span

`asf/workers/pool.py`. Same name, same signature, same triple `(fits, why, projected)`.

```python
def headroom(self, account, kind, model):
    """``(fits, why, projected)``: whether one more ``(kind, model)`` launch lets ``account``
    *finish* it — for every window the source reads, this account's own share of that window
    (its provider kind's scale) added to the reading, to this wave's committed launches, and to
    an allowance for the sessions already running on it, judged against that window's own stop.

    A window whose ``<window>_resets_at`` falls inside the run's expected span is credited: only
    the fraction of the launch spent before the reset counts against the current reading (D7).
    A window with no reading, or no known share, is not judged (D6); a stale reading is the
    band's to judge, as before (D10). ``projected`` is the binding window's projection.
    """
```

The arithmetic, per window `w` with reading `p`, stop `S`, and this launch's share `c`:

```python
held = min(1.0, max(0.0, (resets_at - now) / span))   # 1.0 when the source names no reset
running = sum(share(s['kind'], s['model'], provider, w) for s in live_on_account)
committed = sum(share(k, m, provider, w) for (k, m) in self._taken[account.name])
total = p + round(committed + running * self.costs.allowance, 1) + c * held
```

`fits` is `total < S` for every judged window. The first window that fails, in `WINDOW_KEYS`
order, is the one named:

```python
why = (f'headroom: {account.name}{label} would exceed {S:g}% '
       f'(now {p:g}%, +{committed:g}% committed, +{c*held:g}% this launch)')
```

`label` is `''` for `five_h` and `f' {w}'` for any other window (D4), so the 5h line is the one
P11 pins and a weekly hold reads:

```
waits    spec-f-0138  F-0138  — headroom: acct-a seven_d would exceed 95% (now 92%, +1% committed, +2% this launch)
```

`take` / `untake` append to and remove from `self._taken[name]` (D3); `_committed` goes with the
float it held. The early return loses one clause: an account whose `five_h_pct` is unreadable but
whose `seven_d_pct` is not used to be free and is now judged on the window that *can* be read —
the change the card asks for, stated here because it is the one case whose verdict flips without a
new key in the config.

`over` in `pick_account` and `full_reason` becomes `(projected − guard, why, projected)` and the
`min(over)[1]` on both sides keeps naming the account closest to fitting (D5).

### 4. The wave hands over what it read

`asf/workers/wave.py:350`:

```python
headroom_mod.record_samples(dict(pool._usage), providers=pool.providers())
```

### What it looks like when it is there

An operator with two plan sizes writes two lines of config:

```yaml
worker_pool:
  accounts:
    - name: acct-a
      provider: plan-small
    - name: acct-b
      provider: plan-large
quota_guards:
  window_usd:
    plan-small: {five_h: 12}
    plan-large: {five_h: 48}
```

and the same heavy spec — say $4.80 of model time — costs 40% of `acct-a`'s 5h window and 10% of
`acct-b`'s. The pool puts four of them on `acct-b` and one on `acct-a`, where before it put two and
a half on each and lost the third to a session limit. An account at 92% of its *weekly* window is
skipped before the run is spent, not after. And an account at 93% of a 5h window that resets in six
minutes takes a fifty-three-minute spec worth 10% of that window, because only the eleven percent of
the run that lands before the reset — 1.1 points — is charged to the reading, and the rest lands in
a window that will be empty.

**The card's own number.** Not runnable at landing; it is what the scorecard reads back once the
change has run for a fortnight:

```bash
asf scorecard --product <p>
```

Read the `quota-exhausted` end reason. The card passes when a run lost to a session or weekly limit
is rarer after this change than before it, over accounts whose provider kind and `window_usd` the
operator has configured; a count that does not move means the estimate's dollars are wrong, not
that the prediction is, and reopens as a tuning card against `window_usd`.
