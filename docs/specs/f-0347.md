# F-0347 — a session is judged by whether it is moving, not by what time it is

The kernel ends a live session for one reason only: it has been running too long.

```python
def _over_age(facts, config):
    """``[(session, age in seconds)]``: every live session past its bound
    (:func:`session_bound`; ``Session.started`` against ``Facts.now``)."""
```

That is the whole rule (`asf/kernel/decide.py:2045-2057`). The bound is its wait class's p90 on the
wait ledger — doubled once the item's branch is on origin — else `kernel.waits.max_session_age`
(3 h) or `max_review_session_age` (90 m) (`:2025-2042`, `asf/kernel/settings.py:244-249`). The two
inputs are `Session.started` and `Facts.now`. Nothing else is read: not the log the session is
writing, not the commits it is making, not the branch it is pushing, not the runtime's own view of
it. A session that has written three commits in the last two minutes and a session whose host died
forty minutes ago are the same fact to `_over_age` if they started at the same time, and the
younger of the two is the one that survives.

Both failures follow from that, and both are expensive:

* **A working session is killed.** Past the bound it gets `EndSession(free_worktree=False)` on
  that tick (`asf/kernel/decide.py:376-377`), its item takes the attempt `session ran past its max
  age` against `max_attempts` (`asf/kernel/apply.py:226-227`, `decide.py:279`), and the work is
  relaunched from a brief that starts again. The p90 bound makes this the common case rather than
  the rare one: the bound is a *typical* session's length, so every session longer than typical is
  ended on the clock while it is still working.
* **A dead session is left to rot.** Under the bound, nothing looks at it. A cloud run whose
  container is gone, a session waiting on a prompt nobody will answer, a routine whose worker
  stopped — each holds its seat, its worktree and its item in `building` until its *age* reaches
  the bound. For a kernel cloud run the only other clock is `classify`'s `timed out after
  <timeout_min>m` (`asf/workers/cloud.py:564-565`), elapsed time again.

The evidence the kernel is missing is already being produced and already being written down —
by every runtime, for every session, with no cooperation from the model:

* the job log's newest record carries its own timestamp, and `log_alive_at` already dates it
  (`asf/workers/heartbeat.py:514-539`);
* `asf.progress` samples four signals that only move when work happens — the worktree's commit,
  the digest of `git status --porcelain`, the distinct tool classes used, and the novel tool calls
  — once a minute, with a pure `judge` over them (`asf/progress.py:33-57`, `:250-300`). Every
  launch starts that sampler, the kernel's launches included (`asf/workers/spawn.py:1319`);
* a routine run's `worker_status` and `last_event_at` come off one `list_runs` call, and
  `alive_at` already reads them — written for exactly this case: "Liveness from the runtime: a
  cloud session cannot keep a background beat loop" (`asf/workers/remote.py:597-642`);
* the session's branch on origin moves when it pushes, and `git ls-remote` reads it for nothing
  (`asf/kernel/ports.py:1648-1660`).

The kernel reads none of it. `grep -rn 'asf.progress' asf/kernel/` is **0**. Of the thirteen
mentions of a beat under `asf/kernel/`, twelve are prose about the *floor's* heartbeat and the
thirteenth is the line that switches it off (`asf/kernel/ports.py:2017-2024`) — rightly, because
the floor's beat is a keep-alive: a background loop the session must start and keep running, whose
writes under the shared `.git` are what a sandboxed session is refused (B-0098), and whose absence
from a kernel brief is tested (`tests/kernel/test_no_heartbeat.py:29`). And because a kernel
product's floor is two jobs — `kernel tick` and `kernel watch` (`asf/kernel/host.py:77-93`) — the
old floor's `health`/`stall` step, the one reader of `asf.progress.judge` on a product
(`asf/tick/step_health.py:1-8`, `asf/workers/stall.py:137`), does not run either. The samples the
kernel's own launches write are read by nothing at all.

This card closes that gap, and keeps the half that was right. **Heartbeat, not keep-alive**: the
session starts nothing, remembers nothing and is told nothing. Every running session *beats* by
working, in whatever way its runtime can be observed; the kernel reads the beat each tick, dates
it, writes it down, and judges a session by when it last moved. Elapsed time keeps one job and
loses the other: it stops being the stall rule and stays only as the runaway ceiling for a session
that keeps beating and keeps looping.

## Decisions

### In

* A new leaf, `asf/kernel/beats.py`: the beat sources, the pure judge, the per-job state and the
  spell ledger.
* The session port reads one beat's worth of evidence per live session, per runtime, inside the
  read it already does (`RealSessions.sessions`), with one shared `git ls-remote` for the pass.
* `asf/kernel/loop.py` resolves the evidence against the stored baseline before `decide`
  (`read_beats`) and writes the state and the ledger after `apply` (`measure_beats`) — P15's shape.
* `asf/kernel/decide.py` ends a live session because it stopped beating, and no longer because it
  is older than a measured p90.
* Elapsed time keeps one job: `kernel.waits.max_session_age` / `max_review_session_age` become the
  runaway ceiling, for a session that is beating and still has to be stopped.
* The record and the views: the attempt on the card, the breach line, the tick's `BEAT` lines and
  summary, `asf kernel status`'s beat column, the saved plan's session rows.
* `kernel.beats` in the settings spec, with its defaults, and the same block in
  `docs/products.example.yaml`.

### Out

* **Any beat the session has to emit.** No HEARTBEAT block, no `refs/asf/hb/` ref, no
  `NOTES.asf.md`, no background loop, no brief change at all. P12 stays green as written.
* **The floor's own heartbeat** (`asf/workers/heartbeat.py`) and the cloud lane's beat path
  (`asf/workers/cloud.py:812-830`): untouched, for the products that still run the 0.1 clocks.
  This card adds a reader; it removes nothing the floor uses.
* **A continuation brief.** A stalled session's item is relaunched exactly as an over-age one is
  today — worktree kept, fresh brief, the work that was pushed on the branch. The floor's
  `CONTINUE` block, its notes file and its snapshot ref all depend on the beat loop (Out, above),
  so there is nothing to carry.
* **CI runs.** `ci_bound` / `ci_stalls` keep judging a PR's required checks by elapsed time
  (`decide.py:2060-2084`). A check run's beat is its own steps' timing on GitHub, a different
  source and a different cost; it is a card of its own, not this one.
* **The watch's judgment of the tick** (`kernel.watch.stale_after_s`): the tick is a batch process
  whose beat is the plan file it writes, not a running session. Named here so the next card can
  take it.
* **Per-kind limits.** One quiet limit for every kind (D13).
* **Tuning the limit from the measure.** `asf tune` bounds models and seats
  (`asf/tune.py:8-12`); a beat limit tuned from its own ledger is a later card.

### Preconditions the work depends on

1. The sampler runs for a local kernel session (P6) and `worker_pool.progress_sampler` is not
   `false`. Where it is off, or the sampler died, the beat falls back to the log, the CPU and the
   branch, and the design must not read a missing sample as a stall (D6).
2. The session ledger row carries `log`, `worktree`, `branch`, `pid` and `started` for a local run
   and `pid` (a cloud token), `branch` and `worktree` for a cloud one (`asf/workers/spawn.py:1296-1303`).
3. `git ls-remote origin <ref>…` works from the product checkout, as `branches()` already relies on
   (P13).
4. `cloudpid` holds the last status a sync wrote for a cloud token, with its time
   (`asf/workers/cloud.py:845-847`).
5. A routine run's `list_runs` is reachable through its account's helper when the probe is on
   (P10); when it is not, the probe is unreadable, not a stall.
6. `Facts.now` and `Session.started` are ISO-8601 UTC strings (`asf/kernel/model.py:236`,
   `facts.py:275`), and the ledger's own times are written the same way.

### The choices

| # | Chosen | Against | Why |
| --- | --- | --- | --- |
| D1 | The beat is **read** by the kernel, never written by the session. | Give kernel sessions the floor's HEARTBEAT block and beat loop. | The loop's writes under the shared `.git` are refused in a sandboxed session (P4, B-0098), and a loop the model must remember to start is not evidence of progress — it is a keep-alive. The card says heartbeat, not keep-alive. |
| D2 | Two kinds of source: **dated** ones that carry their own time (the log's newest event, the newest progress sample, the runtime's `last_event_at`) and **observed** ones compared with the last tick's baseline (the branch head, the worktree digest, the process's CPU time). | One `ls-remote` sha comparison, as the floor's `observe` does. | A sha comparison cannot date a beat: at first sight there is no baseline, so the first tick would have to invent a time (the floor gives "benefit of the doubt", `asf/workers/heartbeat.py:395-397`). A dated source needs no baseline and no doubt, and a session that is working without pushing has one. |
| D3 | One duration, `kernel.beats.quiet_limit`, default **30m**. | The floor's `interval_min × missed` arithmetic. | Nothing here beats on an interval, so an interval is a fiction. The limit's real constraint is that it must exceed the longest single tool call a session makes — this product's own pre-push check is one `Bash` call of several minutes — and one number says that plainly. |
| D4 | The live process's **CPU time** is an observed source for a local run. | Log, sample and worktree only. | A twenty-minute test run inside one tool call moves no log record, no sample signal and no worktree digest. It burns CPU. Without this source the most ordinary long step in the factory reads as quiet. |
| D5 | For a cloud or routine run the runtime's own status is a source, probed **only when the free sources say quiet**, at most once per session per tick. | Probe every live cloud session every tick. | It is a paid helper call on the session's own account. The floor already made exactly this call in exactly this order and said why (P10). |
| D6 | An unreadable beat is `UNKNOWN`, and `UNKNOWN` is **never** a stall. | Treat silence from a source as death. | `asf.progress.judge` settled this for the floor (P7), and B-0293 is the cost of the other answer: a transient fetch failure read as an answer ended finished runs `dead pid`, permanently, because neither lane revisits an ended run. |
| D7 | The measured p90 **no longer ends** a live session; `max_session_age` / `max_review_session_age` stay as a ceiling on a session that *is* beating. | Drop every clock and judge by the beat alone. | A session that beats and loops forever would never end. The floor kept the same backstop for the same reason: "a run that keeps beating but loops still ends timed out" (`asf/workers/heartbeat.py:41-42`). |
| D8 | `waits.BOUNDED` narrows to `('ci',)`. | Keep computing the `building` and `review` p90s that nothing then reads. | After D7 they have no reader (P16). A measure nobody reads is the failure the key registry was built to stop (`asf/config_keys.py:4-7`). The p50/p90 per class that `asf kernel waits` prints comes from `report`, not from `bounds`, so the view loses nothing. |
| D9 | Per-job **state** in `state/<product>/kernel-beats.json`, rewritten each tick; one **spell row** per class change in `state/<product>/kernel-beats.jsonl`. | One append-only ledger holding both. | The observed baseline must be rewritten every tick or a stale one reads as movement forever: compare an unchanged sha against a baseline two ticks old and the beat looks alive. With one row per *change* (P14: 720 observations a day per session) the ledger stays a record and not a log, which is what the wait ledger already is (`asf/kernel/waits.py:8-9`). It is the shape `mainmoves` takes (`asf/kernel/loop.py:321-338`). |
| D10 | The beat is resolved in the loop (`read_beats`), the evidence is read in the port, the verdict is read in `decide`. | Resolve it in the port, or in `decide`. | `decide` is pure and the facts read writes nothing (`asf/kernel/facts.py:3`). The state read and the ledger append belong exactly where `read_waits` and `measure_waits` already sit (P15). |
| D11 | A stalled session's attempt is its own text, `session stopped beating`. | Reuse `session ran past its max age`. | The two ends mean different things to the next reader of the card and to the Stuck the attempt count produces; one of them says the session was alive and working and the other says it was not. |
| D12 | The relaunch after a stall is the kernel's existing one: worktree kept, fresh brief. | Port the floor's continuation — notes, snapshot, `CONTINUE` block. | There is no snapshot ref to land (D1) and no notes file (Out). The kept worktree and the commits already on the branch are what the fresh brief starts from, which is what an over-age end does today (P3). |
| D13 | One quiet limit for every kind. | A limit per kind, as `max_review_session_age` is today. | Nothing measured says a reviewer needs a different one, and the ledger this card writes is what would say so. One knob now; the ledger makes the case for a second. |
| D14 | A session the ledger has never seen, with no dated source and no `started`, is `UNKNOWN`. | Seed it with `now`. | Seeding with `now` grants a dead session a full quiet limit of life on every tick that forgets it — which is how a lost run survives. `UNKNOWN` is not a stall either (D6), so it waits for a source, and `started` is almost always there. |

## The design

### 1. `asf/kernel/beats.py` — the sources, the judge, the record

A new leaf. Its licence is the stdlib, `asf.env` and `asf.kernel.model` — no `asf.workers` import at
module level, exactly as `asf.progress` keeps its own (`asf/progress.py:18-20`); the per-runtime
reads that need `asf.workers` are called by the port, which already lives there.

```python
QUIET_LIMIT_MIN = 30        #: kernel.beats.quiet_limit
GRACE_MIN = 15              #: kernel.beats.grace_min — setup before a first beat is due
STATE_FILE = 'kernel-beats.json'
LEDGER_FILE = 'kernel-beats.jsonl'

MOVING, QUIET, STALLED, UNKNOWN = 'moving', 'quiet', 'stalled', 'unknown'

#: the sources, cheapest first; `remote` is the only paid one
SOURCES = ('log', 'sample', 'cpu', 'worktree', 'branch', 'status', 'remote')
```

`Settings(quiet_limit_min, grace_min, probe_remote)` is read from the product's `kernel.beats`
block (§5).

**The evidence.** One value per live session, filled by the port (§2):

```python
@dataclasses.dataclass
class Evidence:
    """What one tick measured off one live session.

    ``dated``    {source: epoch seconds} — a source that carries its own time.
    ``observed`` {source: value} — a sha, a digest, a counter: movement is a change since the
                 baseline the last tick stored, and nothing else.
    ``unreadable`` (source, why) for each source that could not be read: never movement, and
                 never, on its own, a stall.
    """
    dated: dict = dataclasses.field(default_factory=dict)
    observed: dict = dataclasses.field(default_factory=dict)
    unreadable: tuple = ()
```

**The judge** — pure, no clock, no file, no git:

```python
def judge(ev, row, started, now, s):
    """``Verdict(cls, beat_at, quiet_min, source, why)`` for one live session.

    ``row`` is the baseline the last tick stored for this job (``{}`` at first sight), ``started``
    the session's start (epoch, None when unknown), ``now`` a unix time, ``s`` the Settings.

    The beat is the newest of: every dated source, and ``now`` for each observed source whose
    value differs from the baseline's. A source the baseline does not carry is not movement — at
    first sight an observed source says nothing.

    With no beat and no baseline, the beat is ``started``; with neither, the verdict is
    ``UNKNOWN`` (D14). ``UNKNOWN`` is also the verdict when every source was unreadable: a tick
    that could not look has not seen a stall (D6).

    Otherwise the first beat is due ``grace_min`` after the start, and
    ``quiet_min = (now - max(started, beat_at)) / 60``:

    * ``STALLED`` once ``now`` is more than ``quiet_limit_min`` past ``max(started + grace, beat_at)``
    * ``QUIET``   past half the limit, not yet stalled — reported, never acted on
    * ``MOVING``  otherwise

    ``source`` is the source the beat came from, ``why`` the one-line evidence a reader of a
    ``STALLED`` row is owed: the source, what it last said, and how long ago.
    """
```

`Verdict` is a namedtuple, like `asf.progress.Verdict`.

**The record** (D9):

```python
def read_state(state_dir)        -> {job: row}        # {} for a missing or malformed file
def write_state(state_dir, rows) -> None              # atomic, via a temp file and os.replace
def rows_for(verdicts, sessions, now)                 # the baseline each job carries into the next tick
def append(state_dir, spells)    -> None              # one line per class change
def spells(verdicts, state, sessions, now)            # [(job, row)] whose cls changed, plus first sight
def tick_lines(verdicts, sessions)                    # BEAT … lines, quiet and stalled only
def tick_line(verdicts)                               # "beats: 6 moving, 1 quiet, 1 stalled (log 4, branch 2, remote 1)"
def settings_of(product)         -> Settings
```

A state row is `{"session": <sid>, "beat_at": <iso>, "source": <name>, "cls": <word>,
"observed": {<source>: <value>}, "seen": <iso>}`. A row whose `session` is not the live run's own
is dropped and the job starts fresh — the floor's rule for a relaunched job
(`asf/workers/heartbeat.py:366-368`), so a continuation never inherits the dead run's beat.

### 2. `asf/kernel/ports.py` — the evidence, read where the sessions are read

`RealSessions.sessions()` already folds every live run (`:1760-1798`). It gains one call per run,
and one shared reader for the pass:

```python
    def sessions(self):
        ...
        refs = _BranchHeads(self.product)        # one git ls-remote for the whole pass
        for run in pool.load_sessions(self.product).values():
            ...
            out[-1].beat = beat_evidence(self.product, run, refs, self.cfg(), quiet=...)
```

`beat_evidence(product, run, refs, cfg, quiet)` builds the `Evidence` from what the run's runtime
affords, in `SOURCES` order:

| Source | Kind | Read | Runtime |
| --- | --- | --- | --- |
| `log` | dated | the newest record's `timestamp`, failing that the file's mtime — `asf.workers.heartbeat.log_alive_at`'s read, returning the epoch rather than a bool (§4) | local |
| `sample` | dated | the newest `asf.progress` sample's `last_call_at`, and its `at` when any of the four signals differs from the sample before it | local |
| `cpu` | observed | the process's accumulated CPU time, as whole seconds (D4) | local |
| `worktree` | observed | the sample's `commit` and `digest`, else `asf.progress.probe` when there is no sample | local |
| `branch` | observed | `refs/heads/<branch>` on origin, from the pass's one `ls-remote` | every |
| `status` | dated | the time of the last status a cloud sync wrote for this run's token (`cloudpid`) | cloud |
| `remote` | dated | `remote.alive_at(remote.diagnose(...))` — one `list_runs` call, only when `quiet` and `probe_remote` (D5) | routine |

Each read is wrapped: a failure is `(source, why)` on `unreadable`, never an exception and never a
value. A source that does not apply to the runtime is simply absent — absent is not unreadable,
and neither is movement.

`quiet` is the one piece of feedback the port needs from the last tick: the paid probe is for a
session the free sources already called quiet. The port reads it from
`beats.read_state(...)[job]['cls']` — the only state read outside the loop, and a read, not a write.

`_BranchHeads` is the shape of `asf.workers.heartbeat.Beats` (`:252-299`): the live runs' branch
refs collected, one `ls-remote origin <ref>…` for the pass, lazily, once; `None` from `get` while
origin is unreadable, which every caller turns into `unreadable`, never `''` (B-0293's lesson,
D6). It is one git call per tick on top of what the tick already makes (P13).

### 3. `asf/kernel/model.py` — what a session and a config now carry

On `Session`, five fields, all data:

```python
    beat: object = None          # the tick's Evidence (None: not read — an old fake, a dry test)
    beat_at: str = ''            # ISO-8601 UTC, the beat `read_beats` resolved ('' unknown)
    beat_source: str = ''        # which source it came from
    beat_quiet_min: float = None # minutes since it last moved (None: unknown)
    beat_cls: str = ''           # moving | quiet | stalled | unknown ('' not judged)
```

On `Config`:

```python
    beat_quiet_min: float = None   # kernel.beats.quiet_limit (None: the beat judges nothing)
    beat_grace_min: float = 15     # kernel.beats.grace_min
```

`max_session_age_h` and `max_review_age_h` keep their names and their values and change their job:
the docstring says ceiling, not stall — "a live session **that is still beating** and older than
this is ended" (D7).

### 4. `asf/workers/heartbeat.py` — one read, two callers

`log_alive_at(path, now, limit_min)` answers "is it alive?" and throws the time away
(`:536-539`). The beat needs the time. The read splits in two and the floor's caller is unchanged:

```python
def log_event_at(path):
    """The epoch of the job log's newest event — its last record's ``timestamp``, failing that the
    file's mtime — or None for no log, an unreadable one, or one with neither."""

def log_alive_at(path, now, limit_min):
    """Unchanged: :func:`log_event_at` when it is at most ``limit_min`` minutes old, else None."""
    ts = log_event_at(path)
    return None if ts is None or now - ts > limit_min * 60.0 else min(ts, now)
```

Nothing else in the floor's module moves. `remote.alive_at` is already shaped the way the beat
wants it (it returns the event's epoch) and is called as it stands.

### 5. `asf/kernel/settings.py` — the `beats` block

```python
    'beats': {'quiet_limit': ('30m', 'duration'), 'grace_min': ('15m', 'duration'),
              'probe_remote': (True, bool), 'judge': (True, bool)},
```

parsed with the other durations (`:368-370`), and documented in the module's own block comment and
in `docs/products.example.yaml` beside `waits:`:

```yaml
  beats:                    # a running session is judged by evidence of progress, not by its age
                            # (asf.kernel.beats): its log's newest event, its progress sample, its
                            # process's CPU time, its worktree, its branch on origin, its
                            # runtime's own status. The session emits nothing and is told nothing
    quiet_limit: 30m        # no beat from any source for this long: the session is stopped
                            # (worktree kept) and its item relaunched; the attempt reads
                            # "session stopped beating". Must exceed the longest single tool call
                            # a session makes — a full test run is one Bash call
    grace_min: 15m          # setup before a first beat is due (a cloud run clones a repo first)
    probe_remote: true      # a cloud session the free sources call quiet is confirmed against its
                            # runtime's own status (one list_runs call on its account, once per
                            # tick) before it is called stalled. false: the free sources decide
    judge: true             # false: beats are read, recorded and shown, and end nothing — the
                            # ceiling in kernel.waits is then the only rule
```

`kernel.waits.bound_min_samples`' comment loses the two session p90s and keeps CI's (D8).

### 6. `asf/kernel/loop.py` — the beat in the tick

`read_beats` beside `read_waits`, called in the same breath before `decide` (both paths, dry run
included):

```python
def read_beats(facts, state_dir, product=None, now=None):
    """Resolve every live session's beat (:func:`asf.kernel.beats.judge`) against the baseline
    stored in ``state/<product>/kernel-beats.json``, onto ``Session.beat_at``, ``beat_source``,
    ``beat_quiet_min`` and ``beat_cls``. Reads; writes nothing. An unreadable state file is no
    baseline, which is ``UNKNOWN``, which is no stall (D6, D14) — never the tick's end."""
```

`measure_beats` beside `measure_waits`, after `apply`, under the same `try` and the same one-line
failure (P15): it writes the baseline for the next tick and appends the spells, and returns the
tick's `BEAT` lines and its summary line. `write=False` on a dry run, so a dry run judges the same
and writes nothing.

The tick's output gains:

```
BEAT j1-T-0481 T-0481 quiet 18m (log: last event 18m ago, 2 tool classes)
BEAT j4-T-0502 T-0502 stalled 41m (branch: worker/T-0502 at 9f3ab21 since 41m; remote: worker_status=stopped)
beats: 6 moving, 1 quiet, 1 stalled (log 4, sample 1, branch 1, remote 1)
```

A moving session gets no line: eight lines a tick for eight healthy sessions is the noise that
hides the ninth.

### 7. `asf/kernel/decide.py` — the rule

`_over_age` becomes two functions with two meanings:

```python
#: the attempt a session the kernel stopped for want of a beat leaves on its item
STALLED = 'session stopped beating'

def stalls(facts, config):
    """``[(session, quiet seconds, why)]``: every live session the beat calls ``STALLED``
    (``Session.beat_cls``, resolved by :func:`asf.kernel.loop.read_beats`) while
    ``config.beat_quiet_min`` is set. ``UNKNOWN`` and ``QUIET`` are not stalls."""

def over_ceiling(facts, config):
    """``[(session, age in seconds)]``: every live session past the ceiling
    (:func:`session_ceiling`) — the runaway that keeps beating (D7)."""

def session_ceiling(s, config):
    """Seconds a live session may run whatever its beat says: ``config.max_review_age_h`` for a
    reviewer (falling back to ``max_session_age_h``), ``max_session_age_h`` for any other, None
    (unbounded) with neither. The wait ledger's p90 bounds no session any more (D7, D8)."""
```

`decide` ends both, each with its own attempt:

```python
    stalled = stalls(facts, config)
    runaway = [(s, age) for s, age in over_ceiling(facts, config)
               if s.job not in {x.job for x, _q, _w in stalled}]
    actions += [A.EndSession(s.job, free_worktree=False) for s, _q, _w in stalled]
    actions += [A.EndSession(s.job, free_worktree=False) for s, _age in runaway]
```

`A.EndSession` grows one field, `reason=''` — `beats.STALLED` or `''` — so the applier records the
right attempt without re-deriving the verdict: `apply.EndSession` reads `a.reason or OVER_AGE` for
a live session (`asf/kernel/apply.py:226-227`), and everything else in that method is untouched.

`breaches` takes both lists. A stalled session's record carries its **quiet** seconds, not its age,
and names the source:

```
BREACH T-0502 building 41m -> end session j4-T-0502 (no beat: branch 41m)
```

`session_bound` is gone, and with it the only reader of `Facts.bounds['building']` and
`['review']`; `waits.BOUNDED` narrows to `('ci',)` (D8).

### 8. The views

* `asf kernel status`'s session table gains a `beat` column — `3m log`, `quiet 18m branch`,
  `unknown` — in both paths, `rows` and `rows_from_plan` (`asf/kernel/status.py:84-110`), and
  `save_plan` carries `beat_at`, `beat_source`, `beat_quiet_min` and `beat_cls` on each session row
  (`asf/kernel/loop.py:282-283`) so a status read off the saved plan says the same as a live one.
* `asf kernel waits`' own report is untouched: its percentiles come from `report`, not `bounds`.

### What it looks like when it is there

A session pushing commits every few minutes is never ended for being slow: its branch moved, so it
is `MOVING`, and only the ceiling is left above it. A session whose container died at 09:14 is
stopped at 09:45, not at the two-hour mark: its log stopped, its branch stopped, its runtime says
`stopped`, and the ledger holds the row that says so. A twenty-minute test run inside one `Bash`
call is `MOVING` on CPU time alone. A tick that cannot reach origin judges nothing and ends
nothing. And the question "why was this session ended?" has an answer on the card, in the ledger
and on the tick line — the source, what it last said, and when.

## Stories

Six Stories, one per property the card names, cut so each is provable on its own: the beat exists
for every runtime and costs the session nothing (§2), the judge ends a session that stopped moving
(§1, §7), silence is never death (§1), elapsed time keeps only the ceiling (§7), the beat is
written down and shown (§1, §6, §8), and the read stays cheap (§2).

Each is **declared** below as a `### S-…: <title>` heading with its acceptance lines under it, with
ids from this session's block `S:135905-135954` — that heading is what
`asf.record.idcheck.declared_stories` reads and what `asf.record.plan_tasks` mints the card from,
so a cited id with no declaration is a phantom and the plan citing it is refused whole.

Each acceptance line is one physical line of plain text with no backticks: the reader is
line-anchored (`asf.record.idcheck.CHECKBOX` matches a single line) and inline code spans are
replaced by one space before parsing, so a wrapped line reaches the minted card truncated and an
identifier inside backticks reaches it missing.

Every line below is false on the trunk today except where it says it pins behaviour that already
holds.

### S-135905: the beat is read off what a running session already produces, in every runtime

Design §2 and §4 (D1, D2, D4, D5; P6, P9, P10, P13). The session starts nothing, is told nothing,
and its brief does not change.

- [ ] a local run's newest log record dates its beat
- [ ] a local run whose log holds no timestamped record dates its beat by the log's mtime
- [ ] the log read returns the event's time, and the floor's own alive-or-not caller is unchanged
- [ ] the newest progress sample's last tool call time dates a local run's beat
- [ ] a progress sample whose four signals differ from the one before it dates the beat at that sample
- [ ] a progress sample whose four signals stand still dates no beat of its own
- [ ] the process's CPU time is an observed source, and a growing one is movement
- [ ] a twenty minute tool call that writes no log record and no sample signal is moving on CPU time alone
- [ ] a local run with no progress sample at all still has a worktree source
- [ ] the worktree source is the sample's commit and status digest when there is a sample
- [ ] every live session's branch head on origin is an observed source, whatever its branch prefix
- [ ] a cloud run's last recorded sync status dates its beat
- [ ] a routine run's runtime status dates its beat when the probe runs
- [ ] a source that does not apply to the runtime is absent from the evidence, not unreadable
- [ ] a source that raised is on the unreadable list with its reason, and the read returned
- [ ] the session port fills the evidence inside the read it already makes, for every live run
- [ ] a kernel brief still names no heartbeat command, no beat ref and no notes file
- [ ] the session port still spawns with the floor's heartbeat off

### S-135906: a session that stopped beating is stopped and its item relaunched

Design §1 and §7 (D3, D6, D11, D12, D14; P1, P3). The rule the card is about.

- [ ] the judge is pure: the same evidence, baseline, start and clock give the same verdict
- [ ] the beat is the newest of every dated source
- [ ] an observed value that differs from the baseline beats at this tick's time
- [ ] an observed value equal to the baseline beats not at all
- [ ] an observed source the baseline does not carry is not movement at first sight
- [ ] a session with no dated source and no baseline beats at its start time
- [ ] a session with no dated source, no baseline and no start time is unknown
- [ ] a session quiet longer than the limit is stalled
- [ ] a session quiet past half the limit and no further is quiet, not stalled
- [ ] a session whose beat is fresh is moving
- [ ] the first beat is due only after the grace, so a just launched session is never stalled
- [ ] a session whose start is older than the grace and whose beat is older than the limit is stalled
- [ ] a stalled session is ended this tick with its worktree kept
- [ ] a stalled session's item takes the attempt that says it stopped beating
- [ ] that attempt is not the attempt an over age end leaves
- [ ] a moving session is ended by nothing this tick
- [ ] a quiet session is ended by nothing this tick
- [ ] a stalled session of a job whose ledger row names another session id is judged from a fresh baseline
- [ ] the beat judges nothing while the quiet limit is unset, and the ceiling still holds
- [ ] the relaunch after a stall is the kernel's ordinary launch on the kept worktree and branch

### S-135907: a beat nobody could read is never a stall

Design §1, §2 and §6 (D6, D14; P7, and B-0293's cost).

- [ ] a session every one of whose sources was unreadable is unknown, never stalled
- [ ] an unreadable origin makes the branch source unreadable, not an empty sha
- [ ] a session whose only source is an unreadable origin is unknown
- [ ] an unreadable progress store is unreadable, not a standstill
- [ ] a missing job log is unreadable, not a standstill
- [ ] a probe that raised is unreadable, not proof the run is dead
- [ ] a probe the settings turn off leaves the free sources to decide
- [ ] an unreadable state file is no baseline, and no baseline is no stall
- [ ] a malformed state file is no baseline and is not an error
- [ ] a malformed ledger line is skipped, and the rest of the file is read
- [ ] a beat read that raised inside the tick is one logged line and the tick goes on
- [ ] a tick whose beat read failed ends no session for want of a beat
- [ ] a session whose beat time is in the future is read as now, never as negative quiet

### S-135908: elapsed time keeps one job — the runaway ceiling

Design §7 (D7, D8; P2, P16). What the card takes away.

- [ ] a session past the building p90 with a fresh beat is ended by nothing
- [ ] a session past twice the building p90 with a fresh beat is ended by nothing
- [ ] a review session past the review p90 with a fresh beat is ended by nothing
- [ ] a beating session past the configured max session age is ended
- [ ] a beating review session past the configured max review session age is ended
- [ ] the ceiling falls back to the session age when no review age is configured
- [ ] a session with neither age configured has no ceiling
- [ ] a session that is both stalled and past the ceiling is ended once, with the stall's attempt
- [ ] a session ended at the ceiling takes the over age attempt, as it does today
- [ ] the wait ledger's measured bounds no longer carry a building figure
- [ ] the wait ledger's measured bounds no longer carry a review figure
- [ ] the wait ledger's measured bound for CI is unchanged, and CI is still cancelled past twice it
- [ ] the waits report's own percentiles per class are unchanged

### S-135909: every beat and every stall is written down and shown

Design §1, §6 and §8 (D9, D10; P15).

- [ ] the baseline for the next tick is written whole, atomically, once per applied tick
- [ ] the baseline carries each job's session id, beat, source, class and observed values
- [ ] a job no longer live is dropped from the baseline
- [ ] a row is appended when a session's class changes
- [ ] a row is appended the first time a session is seen
- [ ] no row is appended for a session whose class did not change
- [ ] each row carries the job, the item, the kind, the beat, the source, the class and the quiet minutes
- [ ] a dry run judges the same and writes neither the baseline nor a row
- [ ] the tick prints one line per quiet session, naming the source and the evidence
- [ ] the tick prints one line per stalled session, naming the source and the evidence
- [ ] the tick prints no line for a moving session
- [ ] the tick's summary counts the sessions per class and the beats per source
- [ ] a stalled session's breach record carries its quiet time, not its age
- [ ] a stalled session's breach line names the end of that session as its action
- [ ] the status table has a beat column for every live session
- [ ] the status column reads the same off a saved plan as off a live read
- [ ] the saved plan carries each session's beat, source, quiet minutes and class
- [ ] a beat write that failed is one logged line and the tick's result is unchanged

### S-135910: the beat read is cheap, and the paid part is paid once

Design §2 (D5; P13, P14).

- [ ] one git ls-remote serves every live session's branch in a pass
- [ ] a pass with no live session makes no git call
- [ ] the branch heads are read once per pass, however many sessions ask for them
- [ ] the runtime probe is not made for a session the free sources call moving
- [ ] the runtime probe is made for a session the free sources call quiet
- [ ] the runtime probe is made at most once per session per tick
- [ ] the runtime probe is never made for a local session
- [ ] the runtime probe is skipped when the settings turn it off
- [ ] a probe that confirms a fresh event moves the beat and the session is not stalled
- [ ] the beat read makes no GitHub API call
- [ ] the beat read spawns no process per session beyond the git call and the one probe
- [ ] the kernel's GitHub call budget per tick is unchanged by this card
