# F-0092 — an item has a budget, and a run has a cap

Measured 2026-09-23 over this factory's own build: **22 items took three sessions or more and
consumed $164.86 — 62 % of all spend.** Had each stopped at its third session the same items
would have cost about $96, so **roughly $68 of $267 (26 % of everything spent) went to sessions
four and beyond on items that were already in trouble** — 14 sessions on B-0016, 10 on T-0017, 9
on T-0021, 7 on F-0075. A fourth session is almost never a fourth attempt at the same problem; it
is the factory not knowing something (a missing dependency, a stale brief, a spec that cannot be
built as written). More sessions do not supply that knowledge. They pay for it again.

Nothing in the factory counts to three. Two half-measures exist and neither is a budget:

| What is there | What it stops | Why it is not this |
| --- | --- | --- |
| `ATTEMPT_LIMIT = 3` / `STALEMATE → ADJUDICATE` (`asf/feeder/rows.py`) | a Bug with 3 runs behind it, and a Feature at review round ≥ 4 | a Bug and a review round only. A Task, a spec, a correction loop and every dollar are outside it |
| `tokens.DEFAULT_CAPS` + `stall.capped` (`asf/workers/stall.py`) | a run over one token dimension's runaway ceiling | **nothing in the package calls `capped()`** — no tick step, no CLI command. The ceiling has never been enforced |

And there is no cap of any kind on a single run: no wall clock, no turn count. A coder run
averages 82 minutes and nothing ends a longer one.

This Feature gives every item a budget (**3 sessions or $10**, per product, overridable per item),
stops its work when the budget is spent, sends it for a ruling, and gives one run a wall-clock and
a turn cap enforced by the machinery that already knows how to end a run.

## 1. Decisions

### 1.1 Preconditions

- **The card already carries the consumption.** `metrics.write_costs` writes `cost:` into each
  item's machine block — `{sessions, fix_rounds, runner_min, usd, tokens_*}` — from
  `compute_costs` over the record's own `sessions` and `ci` streams, all time, own events only
  (a Feature's Tasks are not folded into it).
- **It is refreshed every tick, not daily.** `tick.run_step0` is `backfill → ingest →
  plan-tasks → plan-order → file-bugs → rollup → index`, and `rollup` is `cmd_rollup`, which
  calls `write_costs`. The `index.json` the wave plans from is written *after* it, in the same
  step, and `record.core.build_index_data` copies every typed and machine key into the entry. So
  the feeder can read a budget and its consumption off the item with no new plumbing.
- **A session event is written when a session ends.** `sessions_from_registry` skips a registry
  record with no `ended`, so `cost.sessions` counts ended runs only. A run in flight is held off
  by `lifecycle.occupancy` (`busy`), not by this gate.
- **The feeder already holds classes of row without launching them.** `hold_classes` rewrites a
  launching row into `WAITS ON hold: <class>` — no session, no slot, still shown — and
  `hold_unlanded` does the same for `after:`. This gate is one more of those, in the same place.
- **The invariant gate is the feeder's backstop.** `invariants.feeder_gate` runs the `feeder`-scope
  invariants over `plan_rows`' answer and drops every launching row a finding names. `I14` is
  free (`I1`–`I13` are taken).
- **The groom is the factory's ruling mechanism.** `groom/<date>.md` carries
  `- [ ] <id> <title> — <why> → answer: ____` lines; `approvals.groom: auto` is the single gate
  (`policy.groom_auto`) that turns on the policy pass and the `GROOM → ADJUDICATE` session that
  answers what no rule answered. Unset, the lines wait for the operator. That is the product's
  autonomy level, and it already exists.
- **`stall.capped` is the shape of ending a run.** It stops the process group (SIGTERM, SIGKILL
  after a grace), appends one `result` line of the factory's own carrying a structured `asf`
  object, and marks the registry line. `runtime.failure_reason` reads that object before any text,
  because a session's own prose is forgeable and the factory's field is not (F-0028 D9).
- **`tokens.meter` already walks the log once per live session**, resetting at each
  `system`/`init` run boundary, and `pool` records `started` on every run line.

### 1.2 In

- **`asf/budget.py`** — one new leaf module (stdlib + `asf.conventions`): what an item may spend,
  what one run may take, the verdict on each, and the one text each verdict prints.
- **`conventions.budget`** — `{sessions, usd, run_minutes, run_turns}` under `conventions:` in
  `~/.ASF/products/<p>.yaml`, each key `off`-able, merged per key over `DEFAULT_BUDGET`.
- **`budget_sessions:` / `budget_usd:` on a card** — the per-item override, written by a ruling or
  by hand.
- **`cost.budget_sessions`, `cost.budget_usd`, `cost.over_budget`** — the resolved budget and the
  verdict, in the block that already carries the consumption (`metrics.write_costs`).
- **`feeder.rows.over_budget`** — every *work* row of an item whose budget is spent becomes one
  non-launching `OVER BUDGET` row; the wave prints it verbatim.
- **`invariants.check_i14`** and `FeederContext.items` — the backstop the property test rests on.
- **The groom's `Over budget` section and the `budget <n>[ $<usd>]` answer** — the ruling: raise
  it, close it (`no: <why>`) or reshape it (`reshape: <how>`), by the operator or by the
  adjudicate session under `approvals.groom: auto`.
- **A wall-clock and a turn cap on one run** — `tokens.Meter.turns`, `budget.run_over`,
  `stall.capped` judging the two run measures beside the four token dimensions, and
  **`step_health` calling `capped()`** — the first caller in the package.
- **`run cap` and `token cap` as outcome classes** — `runtime.failure_reason` tells the two apart;
  `lifecycle.OUTCOME_CLASSES` names both, so `outcome_class` stops filing them as `other`.
- **`asf backlog --sort budget`** and an over-budget marker in its `Cost` column.
- Tests for each of the above (§3), the property test among them.

### 1.3 Out

- **A new stream, a new state file, a new tick-line key.** Every fact read here is already
  written; everything written is two keys on a card, a groom line and a log line.
- **Counting a run in flight against the budget.** `cost.sessions` is ended sessions. A live run
  already holds its item through `occupancy`, and counting it twice would stop an item at 2.
- **A subtree budget.** An Epic keeps `budget_usd` with the meaning it already has — the subtree
  spend the rollup's `budget:` line reports — and an Epic gets no rows, so this gate never reads
  it. A Feature's budget is its own sessions and its own dollars; its Tasks each have theirs.
- **Blocking the lane.** A branch already pushed still lands: the budget holds the rows that
  *start* work, never the harvest, the gate, the merge, or the non-launching rows that describe
  them (`PUSHED → LAND`, `ON TRUNK`, `APPROVED → LAND`, `WAITS ON …`).
- **Holding the three rows that end spending** (§1.4): `PUSHED → REVIEW`, `CONFLICT → REBASE`,
  `STALE → CLOSE`.
- **A new approval class.** Raising a budget is a groom answer, gated by `approvals.groom` like
  every other ruling. `spend_money` is deliberately not reused: a product wanting the factory to
  rule on a budget must not thereby let a session buy a subscription.
- **Refusing a session that edits its own card's `budget_sessions:`.** The approvals hook
  classifies tool calls, not card fields; every raise is a commit on the card with a History line,
  so a raise nobody ruled is visible in `git log` and is a Bug when seen.
- **Per-kind run caps.** One wall clock and one turn count for every kind, as `conventions.budget`
  is one block. `token_caps:` is the per-kind table and stays the only one.
- **A fifth token number.** `run_minutes` and `run_turns` are not token dimensions and never enter
  `tokens.DIMENSIONS`.
- **A `budget` row on `asf status`, a doctor row, a Bug filed on going over budget.** The
  `OVER BUDGET` line, the `cost` block and the groom question are the record; F-0103's own
  sources file Bugs off the streams.
- **Story ids.** This session was given no `BACKLOG_ID_RANGE`, so §Stories names Stories by title
  and the plan session mints their ids from its own range.

### 1.4 The choices

| Choice | Against | Why |
| --- | --- | --- |
| The consumption is read off the card's `cost:` block | the feeder metering the ledger itself, or `lifecycle.attempts` | `cost:` is rewritten at step 0 of the same tick the wave plans in, and it is the one number the operator sees on the card, in `asf backlog` and in the rollup. A second count in the feeder would disagree with it the first time the streams and the registry differed, and the item would stop at a number no page shows. |
| `3 sessions **or** $10`, whichever comes first, each `off`-able | a single measure | they catch different failures: B-0016's 14 sessions were $16.64 (cheap runs, no convergence), F-0075's 7 were $16.59 (expensive runs). Either alone leaves half the table running. |
| The budget lives under `conventions:` | a top-level `budget:` in the product yaml | a reader older than this version keeps an unknown `conventions` key and **rejects** an unknown top-level one (`env.PRODUCT_FIELDS`, R23). A top-level key would make every product file unloadable by the installed version until it is upgraded. |
| Flat `budget_sessions:` / `budget_usd:` on a card | one nested `budget: {sessions, usd}` map | the groom applier writes typed fields with `frontmatter.write_typed({field: value})` and the History line is `<field> → <value>`; two scalars need no nested-value writer and read the same in `asf set`. It also puts the per-item override next to the `budget_usd` an Epic already carries, with the same units. |
| One `OVER BUDGET <id> — <n>/<cap> sessions, $<x>/$<cap>` line, both measures always | naming only the measure that tripped | the reader needs to know which one is over *and* how far the other is from its cap before ruling on a raise. One format, no branch, and the line is the whole verdict. |
| The gate exempts `PUSHED → REVIEW`, `CONFLICT → REBASE`, `STALE → CLOSE` | the literal "no new row of any kind" | those three end spending. A review of a branch already pushed is the last step before it lands; holding it strands the work the budget was overrun producing and guarantees the money was wasted. A rebase and a close are housekeeping on a branch that exists. Everything that starts or continues work — spec, plan, code, fix, correct, direct, adjudicate — is held. |
| The ruling is a groom question | a `STALEMATE → ADJUDICATE` row per over-budget item | one adjudicate session a day answers every open question for every item (`ADJUDICATE_PER_DAY`), where a row per item pays for a session per item — the exact waste this Feature exists to stop. And the groom file is where a ruling is already recorded, with its attribution and its History line. |
| `approvals.groom` is the autonomy level | a new `raise_budget` class | it is already "the single gate" for the policy pass and for the adjudicate session that answers what no rule answers. Unset, the question waits for the operator; `auto`, the factory rules. That is the sentence the card asks for, and it needs no new matrix entry. |
| The gate runs inside `candidates()` | in `plan_rows`, or in the wave | `asf next`, the status cell, `briefs.build` and `groom.policy` all call `candidates()` directly. Anywhere later and those four would each show a row the tick would not launch. |
| I14 as well as the row rewrite | the rewrite alone | the rewrite is what the wave prints; I14 is what makes "no row is launched for an item whose budget is spent" a checked property of the plan rather than of one function. It costs one `items` field on `FeederContext`. |
| `step_health` calls `stall.capped()` | leaving it to a later Feature | the wall-clock cap has no other enforcement point, and `capped()` is the only code that ends a live run cleanly. Wiring it also turns on the token caps for the first time — deliberately: `DEFAULT_CAPS` are runaway ceilings (8 M input, 1 M output), so a run that trips one was never going to finish. |
| `capped()` before `health()` in the step | after it | `capped` stops the run and appends the result line synchronously, so the same tick's `health(fix=True)` ends the session and records `failed: run cap`. After it, the reason would land a tick late. |
| Turns are counted as `assistant` records since the run boundary | the runtime's own `num_turns` | `num_turns` exists only on the result line, i.e. only once the run is over — useless to a cap. `tokens.meter` already walks every `assistant` line of the log in the pass `capped` makes, so the live count is free. The ended-session `turns` in the `sessions` stream keeps its runtime meaning; the cap's record names the count it judged. |
| `run_minutes: 180`, `run_turns: 600` | the 82-minute average, or no default | a cap is a runaway ceiling, not a budget (the budget is the item's). 180 is 2.2× the measured average coder run; 600 turns at 1–2 k output tokens a turn lands near `DEFAULT_CAPS`' 1 M output ceiling, so the two caps bind at the same kind of run. Both are one line of product yaml away from any other number. |
| `run cap` and `token cap` become outcome classes | leaving them to `other` | `OUTCOME_CLASSES` is composed from the constants that write the strings, and `outcome_class` is what F-0103's Bug signatures name. "Ended and recorded with that reason" is not true if the record says `other`. |

## 2. The design

### 2.1 The config — `asf/conventions.py`

One nested block, merged per key, each key `off`-able:

```yaml
conventions:
  budget:
    sessions: 3        # ended sessions an item may take before it stops (off: no limit)
    usd: 10            # dollars an item may take before it stops (off: no limit)
    run_minutes: 180   # one run's wall clock; over it the run is ended `run cap`
    run_turns: 600     # one run's assistant turns; over it the run is ended `run cap`
```

```python
#: An item's budget and one run's caps (F-0092). A product overrides any key; a key it does not
#: name keeps the default here. ``off`` on any key is no limit for that measure.
DEFAULT_BUDGET = {'sessions': 3, 'usd': 10, 'run_minutes': 180, 'run_turns': 600}
```

`Conventions.budget: dict = field(default_factory=lambda: dict(DEFAULT_BUDGET))`,
`'budget'` added to `MAP_CONVENTIONS` (so a misshapen block is a red doctor row, never a silent
default), and `budget_for(conv, key)` beside `savings_for`, with the same one-line body: the
product's own entry when it named one, else `DEFAULT_BUDGET`'s. The `conventions:` example in the
module docstring gains the block above, and `DEFAULT_BUDGET` is the only place those four numbers
appear (`tools/check_conventions.sh`).

### 2.2 The one owner of both verdicts — `asf/budget.py`

```python
"""asf.budget — what an item may spend, and what one run may take.

Two verdicts and the text each prints: an item's budget (ended sessions, dollars) against the
consumption its card already carries, and one run's caps (wall clock, turns) against what the
ledger and the log say. Pure: no clock it is not handed, no io, no git. A leaf — the stdlib and
:mod:`asf.conventions` only — so the feeder, the metrics writer, the health step and the board
view may all import it.
"""
SESSIONS, USD, MINUTES, TURNS = 'sessions', 'usd', 'run_minutes', 'run_turns'
OFF = 'off'                     #: a measure a product turned off, as `asf.tokens` spells it
RUN_CAP = 'run cap'             #: the `end_reason` a capped run is recorded with
OVER = 'OVER BUDGET'            #: the first word of the line the wave prints


@dataclass(frozen=True)
class Budget:
    """What one item may spend. ``None`` is no limit. ``source`` is ``default``, ``product`` or
    ``item`` — whichever set the measure that is lowest, for the groom line to name."""
    sessions: int = None
    usd: float = None
    source: str = 'default'


@dataclass(frozen=True)
class Spent:
    """What the card says it has taken, and the verdict. ``measure`` is the first measure over
    its budget (``sessions`` before ``usd``), or ``''`` when none is."""
    sessions: int = 0
    usd: float = None
    budget: Budget = None
    measure: str = ''

    @property
    def over(self):
        return bool(self.measure)


def of(conv, item):
    """The :class:`Budget` for one item (an ``index.json`` entry or a card's meta): the product's
    ``conventions.budget`` under the card's own ``budget_sessions:`` / ``budget_usd:``.

    An Epic has no budget (``Budget()``): it launches no row, and its ``budget_usd`` is the
    subtree figure the rollup reports (F-0101), not a stop.
    """


def spent(conv, item):
    """:class:`Spent` for one item: ``cost.sessions`` and ``cost.usd`` against :func:`of`.

    A card with no ``cost:`` block has spent nothing. A measure whose budget is ``None``, or
    whose consumption the record has not measured (``cost.usd`` is ``None`` when no log carried a
    cost), is never over — an unmeasured dollar is not a spent one.
    """


def line(item_id, s):
    """The wave's line for an over-budget item, both measures always::

        OVER BUDGET T-0021 — 9/3 sessions, $13.53/$10

    A measure that is off prints ``—`` in place of its cap."""
```

and the run caps, over the same block:

```python
def run_caps(conv):
    """``(minutes, turns)`` — each an int, or None when the product turned it off."""


def run_over(elapsed_min, turns, caps):
    """``(measure, value, limit)`` for the first run cap exceeded — the wall clock before the
    turns — else None. A None on either side is never over, so a run whose ``started`` the
    ledger lost is judged on its turns alone."""


def run_cap_text(kind, measure, value, limit):
    return f'run cap: {measure} {value} over the {limit} cap for a {kind} job'


def run_cap_result(kind, measure, value, limit, at):
    """The result record the factory appends to a run it ended on a cap — the twin of
    :func:`asf.tokens.cap_result`, and the same judgement: the structured ``asf.run_cap`` object
    is what a reader believes, the text says the same for a human. No ``duration_ms`` and no
    ``total_cost_usd``: nothing was measured."""
    return {'type': 'result', 'subtype': 'error', 'is_error': True,
            'result': run_cap_text(kind, measure, value, limit) + ' — stopped by the factory',
            'asf': {'run_cap': {'kind': kind, 'measure': measure, 'value': value,
                                'limit': limit, 'at': at}}}
```

### 2.3 The budget on the card — `asf/metrics/metrics.py`

`write_costs(root, items, all_ci, all_sessions, now=None, conv=None)` — `conv` is the product's
`Conventions` (`DEFAULTS` when the rollup could not resolve a product, exactly as `cmd_backfill`
already falls back), and `cmd_rollup` passes `_resolve_product(args.product).conventions`.

The `new_cost` dict gains, after the token keys:

```python
s = budget.spent(conv, it)
if s.budget.sessions is not None:
    new_cost['budget_sessions'] = s.budget.sessions
if s.budget.usd is not None:
    new_cost['budget_usd'] = s.budget.usd
if s.over:
    new_cost['over_budget'] = s.measure          # 'sessions' | 'usd'
```

`over_budget` is present only while the item is over: the block is written wholesale, so a raise
that puts the item back under its budget removes the key on the next tick. An Epic's `cost:` gains
no budget key (`budget.of` gives it none), so nothing changes for `spend_usd` / `budget_usd` or
the rollup's `budget:` lines.

The first tick after this lands rewrites the `cost:` block of every item that has one, adding two
keys. That is one commit of the record's own derived state, which is what step 0 commits every
tick anyway.

### 2.4 The gate — `asf/feeder/rows.py`

```python
OVER_BUDGET = 'OVER BUDGET'
BUDGET = 'budget'            #: the row's ``waits_on``
#: The launching rows the budget does not hold: each ends the spending on work already done —
#: a review is the last step before a pushed branch lands, a rebase and a close are housekeeping
#: on a branch that exists. Everything else starts or continues work.
FINISHING_KINDS = (PUSHED_REVIEW, CONFLICT, STALE)


def over_budget(rows, items, product):
    """One ``OVER BUDGET`` row per item whose budget is spent, in place of its launching rows.

    Every launching row of the item but a :data:`FINISHING_KINDS` one is dropped; the first of
    them (emit order) becomes the non-launching row that says so — no session, no slot, still
    shown. Its non-launching rows are untouched: a branch the lane holds still lands, and the
    row that says so must not be overwritten by this one. Pure over the items' ``cost:`` blocks.
    """
    conv = _conventions(product)
    verdicts = {}
    out, said = [], set()
    for r in rows:
        if not r.launches or r.kind in FINISHING_KINDS:
            out.append(r)
            continue
        if r.item_id not in verdicts:
            verdicts[r.item_id] = budget.spent(conv, items.get(r.item_id) or {})
        s = verdicts[r.item_id]
        if not s.over:
            out.append(r)
            continue
        if r.item_id in said:            # one line per item, not per row
            continue
        said.add(r.item_id)
        out.append(dataclasses.replace(
            r, action=budget.line(r.item_id, s), waits_on=BUDGET,
            reason=f'budget spent: {s.measure} — a ruling raises it, closes it or reshapes it'))
    return out
```

called in `candidates()` as the last hold, after `hold_classes`:

```python
    rows = hold_unlanded(rows, items, landed_shas)
    rows = hold_classes(rows, product)
    rows = over_budget(rows, items, product)
```

so `asf next`, the status cell, `briefs.build` and the groom's policy pass all see what the tick
sees. The `GROOM → ADJUDICATE` row is not touched: it speaks for a day's questions, not for the
item it happens to be named after — the same exception `hold_unlanded` makes.

### 2.5 The tick's line — `asf/tick/step_wave.py`

In `launch()`, where a non-launching row is printed today:

```python
        if not row.launches:
            if row.waits_on == feeder_rows.BUDGET:      # F-0092: the whole verdict, verbatim
                out(row.action)
            else:
                out(f"waits    {'-':<24} {row.item_id:<10} — {row.action}")
            continue
```

One line per over-budget item per tick:

```
OVER BUDGET T-0021 — 9/3 sessions, $13.53/$10
```

No tick-line key and no event: the line is in the tick log, the verdict is on the card
(`cost.over_budget`), and the question is in the groom file.

### 2.6 The backstop — `asf/invariants.py`

`FeederContext` gains `items: dict = field(default_factory=dict)` and `feeder_context` passes the
`items` it already takes. Then:

```python
def check_i14(ctx):
    """I14 (F-0092) — no launching row for an item whose budget is spent. The three finishing
    kinds (:data:`asf.feeder.rows.FINISHING_KINDS`) are not launches of new work and are not
    judged; an item with no ``cost:`` block has spent nothing."""
```

registered `Invariant('I14', 'feeder', _feeder_only(check_i14))`, so a row that reaches the plan
over budget — from a caller that skipped `over_budget`, or from a race between the rollup and the
wave — is dropped with one line:

```
INVARIANT I14: PLAN → CODE T-0021 @worker/T-0021 — budget spent: 9/3 sessions, $13.53/$10
```

The module docstring's `feeder` list becomes `(I4, I5, I7, I14)`.

### 2.7 The ruling — `asf/groom/groom.py`

**The question.** One `EXTRA_SECTIONS` entry, rendered only when it has lines, built like
`groom_refused_section`:

```python
OVER_BUDGET_QUESTIONS = ('Over budget', 'over_budget')


def groom_over_budget_section(canonical, product):
    """One question per open card whose budget is spent (:func:`asf.budget.spent` over its
    ``cost:`` block): raise it, close it or reshape it. Asked once — an answer changes the card,
    and a card no longer over budget is not asked again."""
```

the line's `why`:

```
- [ ] T-0021 harvest reads the merge classes — 9/3 sessions, $13.53/$10 over budget (product
  default): raise it (`budget 12` or `budget 12 $25`), close it (`no: <why>`) or reshape it
  (`reshape: <how>`) → answer: ____
```

**The answer.** `ANSWER_BUDGET = re.compile(r'^budget\s+(?P<sessions>\d+)(?:\s+\$?(?P<usd>\d+(?:\.\d+)?))?$', re.I)`
→ `('budget', {'budget_sessions': n, 'budget_usd': x})` from `_parse_answer`, and its own branch
in the applier beside `unblock`'s: one `frontmatter.write_typed` of the one or two fields, one
History line `- <date> groom: budget → 12 sessions / $25 <who>`, one `groom_answer` event, and a
no-op when the card already carries those values (so `--apply` stays idempotent). The
unrecognised-answer text gains `budget <n> [$<usd>]` to its list of words.

Under `approvals.groom: auto` the `GROOM → ADJUDICATE` session answers the line like any other
(with its `adjudicator:` attribution); unset, it waits for the operator — the product's autonomy
level, unchanged. Either way the item is stopped while it waits, and the raise is a commit on the
card with a History line saying who ruled.

### 2.8 The run caps — `asf/tokens.py`, `asf/budget.py`, `asf/workers/stall.py`, `asf/tick/step_health.py`

`tokens.Meter` gains `turns: int = 0`, incremented on every `assistant` record and reset to 0 at
each `system`/`init` boundary beside `result` and `by_dim` — the pass `capped` already makes, one
more counter, no new number in `DIMENSIONS`.

`stall.capped` judges the run measures beside the token ones, in the same loop and with the same
line:

```python
        verdict = tokens.over(m.by_dim, caps.get(kind) or caps.get('default') or {})
        run_verdict = None if verdict else budget.run_over(
            elapsed_min(s, now), m.turns, budget.run_caps(conv))
        ...
        # the result line, and what the registry records
        if verdict:                     # a token dimension
            _append_line(s['log'], tokens.cap_result(kind, dim, spent, limit, m.by_dim, at))
            pool_mod.update_session(product, s['job'], capped={...})
        else:                           # a run measure
            _append_line(s['log'], budget.run_cap_result(kind, measure, value, limit, at))
            pool_mod.update_session(product, s['job'], capped={
                'measure': measure, 'value': value, 'limit': limit, 'at': at})
        out(f"CAP   {s['job']}  {measure} {value} over {limit} ({kind}){detail}")
```

`elapsed_min(session, now)` is the run's `started` to `now` in minutes, `None` when the ledger has
no usable `started`. Everything else in `capped` is unchanged: a run that already has a result is
never touched, a pid that is not this run's is never signalled, `stop=False` judges only, and a
malformed `token_caps:` block still stops nothing.

`runtime.failure_reason` tells the two records apart, structured field first as it already does:

```python
    asf = (rec or {}).get('asf')
    if isinstance(asf, dict):
        if isinstance(asf.get('cap'), dict):
            return tokens.TOKEN_CAP          # 'token cap', the constant moved beside cap_text
        if isinstance(asf.get('run_cap'), dict):
            return budget.RUN_CAP            # 'run cap'
```

so health records `failed: run cap` / `failed: token cap`, `lifecycle.OUTCOME_CLASSES` gains both
constants (and `outcome_class` stops calling them `other`), and `metrics.cost_table`'s `capped`
cell counts either (`result in ('failed: token cap', 'failed: run cap')`).

`step_health.run` calls it first, before health reconciles:

```python
    stall_mod.capped(product, out=out)      # F-0092: a run over a cap is ended here, not left
    found = health_mod.health(product, fix=True, out=out)
```

so the same tick that stops the run also ends its session with the reason. The module docstring
gains the sentence.

### 2.9 The view — `asf/views/board.py`

The `Cost` cell keeps the subtree spend it shows today and gains the subtree's over-budget items:

```
$18.40 · over: T-0021
$16.64 · over: 2
```

(one id, else the count), read off each item's `cost.over_budget`. `asf backlog --sort budget`
orders each Epic's group by over-budget items first, then subtree spend, both descending, rather
than by rank; `--sort rank` (the default) is today's order. `render(root, product, sort=None)`,
one flag in `cli.py`.

## 4. Records

**On the card** (machine block, written by the rollup at step 0 of every tick):

```yaml
cost:
  sessions: 9
  fix_rounds: 2
  runner_min: 41
  usd: 13.53
  budget_sessions: 3
  budget_usd: 10
  over_budget: sessions
```

**On the card** (typed, written by a ruling or by hand — the override):

```yaml
budget_sessions: 12
budget_usd: 25
```

with one History line per raise: `- 2026-09-28 groom: budget → 12 sessions / $25 (adjudicator)`.

**In the groom file** (`groom/<date>.md`, under `## Over budget`), one line per over-budget open
card until it is answered, and the `groom_answer` event the applier already writes
(`field: budget`, `section: over_budget`, `by: operator | adjudicator | rule:<name>`).

**In the tick log**, one line per over-budget item per tick:
`OVER BUDGET T-0021 — 9/3 sessions, $13.53/$10`; and, when the invariant caught a row the gate
did not, `INVARIANT I14: <row> — budget spent: …`.

**In a capped run's log**, one `result` line of the factory's own:

```json
{"type": "result", "subtype": "error", "is_error": true,
 "result": "run cap: run_minutes 240 over the 180 cap for a code job — stopped by the factory",
 "asf": {"run_cap": {"kind": "code", "measure": "run_minutes", "value": 240, "limit": 180,
                     "at": "2026-09-28T04:12:00Z"}}}
```

**On the registry line** (`~/.ASF/state/<p>/sessions.jsonl`), `capped: {measure, value, limit,
at}` beside the existing token shape, and `end_reason: failed: run cap` from health — which the
`sessions` stream then carries as `result`, so `outcome_class` and F-0103's repeat signature name
it.

**Not written.** No new stream, no new state file, no key on the tick line, no `metrics/events`
row, no Bug. Nothing here writes a worker account name or a machine path: a lane is `lane-N` and
the `CAP` line names a job, as `stall` already does.
