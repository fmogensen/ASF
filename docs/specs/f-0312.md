# F-0312 — the test that would have caught it, run on the tree that had the defect

The incident lane already tells every fix session the rule, in the imperative, and names the
consequence. `asf/briefs/templates/fix-bug.md`:

> THE TEST THAT CLOSES IT: {tests}
> Write that test FIRST and watch it fail, then make it pass. The harvest requires it by name: a
> fix that lands without a test that failed before it is not a landed fix, it is a claim.

Nothing requires it. `named_test_gate`, the function `F-0071` §2.3 specified for exactly this, is
not on the trunk — not under that name and not under another: no code in `asf/harvest/` asks
whether a branch is a `fix` one at all. So the sentence in the brief is the kind of claim it warns
about: a session that writes the test is obeying a convention, and a session that does not is
landing on the same path, at the same speed, with the same `Resolved`.

The card's requirement is the narrow, mechanical half of that promise: **a fix for a
product-reported defect lands with a test that fails on the product as it was and passes on the
product as the fix leaves it, and the lane is what checks it** — not the brief, not the review, not
the session's own report.

The claim is checkable today, and §1's P9 checks it: the one `fix(` commit on this trunk in sixty
days ships a test module which, grafted onto the tree its own parent had, fails by name twice and
passes at the fix's head. The mechanism this spec specifies is that experiment, run by the lane.

## Decisions

### Preconditions — measured in this worktree at `e5e716f`, 2026-10-08

* **P1 — the brief's claim is unbacked.** `grep -rn 'named_test_gate' asf/ tests/` finds nothing.
  `F-0071` §2.3 specified `named_test_gate(tmp, trunk, tests, conv)` in `asf/harvest/harvest.py`,
  with the card's own §1.2 naming the gap it closed ("The harvest does not require the named
  test ... runs the product's whole test command and never checks that the test the Bug's `## Fix`
  names exists"). That Story did not land. The gap it names is still the live state.
* **P2 — the lane has no fix-specific check of any kind.** `lane_refusal`
  (`asf/harvest/lane.py:1136`) is the branch's one pre-gate mechanical refusal, and it refuses
  exactly three things: a merge commit on a lane branch, a commit subject naming no item, and a
  line added to customer content carrying a forbidden marker. `grep -n "branch_kind(.*) == 'fix'"`
  over `asf/` matches nothing; a `fix/` branch is gated as any code branch is — the product's test
  command on the rebased head, whole and green, which says nothing about whether the green was
  ever red.
* **P3 — the record already states the rule in prose.** `sample/backlog/bugs/B-0001.md`, the
  shipped example of a Bug card, has as its one `## Acceptance` bullet:
  `- [ ] `` `tests/test_count.py::test_empty` `` fails before the fix and passes after.` The
  convention is written down, in the sample a new product copies, and nothing reads it.
* **P4 — the primitives exist, and the shape a heavy check must take is settled.**
  `lane.pre_push_check_at` (`asf/harvest/lane.py:1007`) and `lane.run_check_commands` (`:1047`)
  each run a command on an arbitrary sha in a throwaway detached worktree under the state dir,
  with the product's `worktree_setup` first and the process group killed on timeout.
  `asf/harvest/rebuild_check.py` is the pattern for a check too heavy to run inside the tick:
  a result store keyed by tree-and-command, one `flock` so a product runs one at a time, a
  detached job, and a first pass that answers "deferred" rather than waiting. Its docstring says
  why it exists — a product's tick held its lock 57 minutes, 13+ of them inside one synchronous
  `pre_push_check`.
* **P5 — what a test file is, is already decided.** `widen.is_test_path`
  (`asf/feeder/widen.py:101`): `test_x.py`, `x_test.py`, `x.test.ts`, `x.spec.tsx`, or anything
  under `tests/`, `test/`, `__tests__/`. Product-agnostic, one owner.
* **P6 — which test the card names is already read.** `preamble.named_tests`
  (`asf/briefs/preamble.py:320`): the card's typed `tests:` field, then every test-shaped token in
  its `## Fix`, `## Acceptance` and `## Description`, then whatever the caller found in the
  checkout — once each, in first-seen order. It is what puts `{tests}` in the brief above.
* **P7 — the record has a field for where a defect came from, with three live values.**
  `found_in`: `prod` (`asf/tick/migrate.py:320`), `ci` (`asf/tick/flaky.py:218`,
  `asf/tick/file_bugs.py:533`), `dev` (`asf/groom/inbox.py:362`, `asf/tick/file_bugs.py:376`,
  `:403`). The factory's own bookkeeping Bugs — a flaky test, a CI red rate, an outcome share —
  are the `ci` and the tick's `dev` ones; a human's inbox note is `dev`; a defect met in the
  running product is `prod`.
* **P8 — the lane cannot name a failing Python test case.** `lane.red_tests`
  (`asf/harvest/lane.py:5447`) reads node:test `✖ name`, vitest/jest `✗`/`×`/`FAIL file > name`
  and TAP `not ok N - name`. Its `_FAIL_RE` (`:5440`) requires whitespace after `FAIL`, so
  `unittest`'s own `FAIL: <case>` and `ERROR: <case>` match neither branch. Measured:

  ```
  red_tests on unittest output: []
  matches FAIL: ? False
  matches ERROR: ? False
  ```

  So the one parse the lane owns cannot tell this product's own suite which case went red.
* **P9 — the mechanism works, measured on the one real fix available.** `e5444102c`
  (`fix(F-0305): staged-guard lets an intake note move to done/ after groom rewrote it`, #1194)
  touches `asf/record/staged_guard.py` and `tests/test_staged_guard.py`; its parent is
  `d3ba7924`. Its test module grafted onto that parent, and the module run whole:

  ```
  FAIL: test_groom_apply_then_a_mint_named_by_the_title_slug_passes (tests.test_staged_guard.StagedGuardTests...)
  FAIL: test_groom_apply_then_move_to_done_passes (tests.test_staged_guard.StagedGuardTests...)
  Ran 14 tests in 2.222s
  FAILED (failures=2)
  ```

  The same module at `e5444102c`: `Ran 14 tests in 1.872s` / `OK`. Two seconds a side, no import
  error, two named cases red before and green after.

  The same experiment again with **the command §2 specifies**, the graft committed in the
  worktree and the pre-fix sha substituted for `{base}` (D7) — `python3 tools/run_tests.py
  --touched d3ba79241 --shards 2`:

  ```
  run_tests: 1 touched module(s): test_staged_guard
  FAIL: test_groom_apply_then_a_mint_named_by_the_title_slug_passes (tests.test_staged_guard...)
  FAIL: test_groom_apply_then_move_to_done_passes (tests.test_staged_guard...)
  Ran 18 tests in 2.264s (1 module(s), 2 at a time)
  FAILED (failures=2)
  ```

  So `--touched {base}` in the grafted worktree does select exactly the grafted module and
  nothing else, which is the whole of D7's claim. §3 carries the block that replays both halves.
* **P10 — and it is the only one.** Of the commits on `origin/main` in the last 60 days whose
  subject opens `fix(`, there is exactly one (P9's). No commit subject in 90 days names a `B-`
  card at all: this record files and fixes defects under Feature ids too — P9 is `fix(F-0305)`,
  a defect fix on a Feature card. So the gate is cheap by construction (one module-scoped run per
  fix branch), its sample is small, and the id prefix is not what identifies its subject (D1).
* **P11 — `conventions.flags` is the per-product home, and registration is enforced.**
  `asf/conventions.py` `KNOWN_FLAGS` lists every flag a product yaml may set, dotted names
  included (`groom.reask_days`, `models.cheap_kinds`). `python3 -c` over it: no flag matching
  `regress` exists. The `~/.ASF/config.yaml` equivalent, `asf/config_keys.py`, is held by
  `tests/test_config_keys.py`, which fails both on a key code reads and the registry lacks and on
  a registered key no code reads.
* **P12 — a cause that needs new work from the session is not a mechanical one.**
  `lifecycle.MECHANICAL` is `('naming', 'copies')` — the two the factory fixes itself, with no
  round spent. Measured: `mechanical causes: ('naming', 'copies')`.

### Preconditions the work depends on

* The product declares a `test_command` (`conventions.test_command`); a product with none has no
  gate to extend and `regression.check` stays `off` for it.
* The fix branch is reachable as `origin/<branch>` when the lane reads it — the lane's own
  invariant today (PD6, `delivery_note`), unchanged here.
* The decision register is readable from the product's record clone
  (`asf/record/decisions.py` `register`), as `proves.unproved` already requires for a deferred
  acceptance line.
* `found_in` is set on the cards the gate covers. A card with **no** `found_in` is covered
  (D1): an absent field is not a licence.

### The choices

| # | Chosen | Against | Why |
|---|---|---|---|
| D1 | The gate covers a branch whose lane kind is `fix` (`conv.branch_kind(b) == 'fix'`) and whose card's `found_in` is **not** in `regression.exempt_found_in` (default `('ci',)`) — a missing `found_in` is covered | Every branch that touches code; or only `found_in: prod` | The card says *product-reported defect*. `ci` is the factory reporting on itself (P7). Only-`prod` would gate almost nothing — a human's inbox note is `dev` (P7) and is exactly a reported defect. Keying on the **lane kind, not the id prefix**, is what P10 forces: the one real fix in the window is `fix(F-0305)`, on a Feature id, and a `B-`-prefix rule would have skipped it |
| D2 | The pre-fix tree is `origin/<trunk>` as the gate measures the branch against | The branch's merge-base with the trunk; the branch's first commit's parent | The lane rebases before it gates, so the trunk tip *is* the product without this fix — and it is the tree the fix will actually land on. A merge-base is a tree that no longer exists anywhere the fix will run |
| D3 | Only the branch's test files are grafted onto it (`widen.is_test_path`, P5) | Graft the whole branch and revert its non-test diff | "The test that would have caught it" is the test, on the product as it was. Grafting anything else makes a third tree that is neither side of the fix. Reverting a diff can conflict; a checkout of named paths cannot |
| D4 | The verdict reads the **named failing cases** of the pre-fix run. An inconclusive verdict is said, with the tail, and holds the branch with different words from a missing test |
| D5 | Green is proved per **case**: at least one case red in the pre-fix run must be absent from the head run's failing cases | The gate already proves the head green as a whole, so red-before is enough | A test red on both sides is red for its own reasons, not this defect's. | D7 | The command is `flags.regression.command` with `{base}` substituted, defaulting to `conventions.test_command`. The graft is committed (D2) so `{base}` is a real sha |
| D8 | The failing-case parse lives in the new module, with `unittest`'s `FAIL:` / `ERROR:` shape added beside node/vitest/TAP, and is overridable per product (`flags.regression.fail_re`) | Widen `lane._FAIL_RE` so `red_tests` learns the shape | P8: `_FAIL_RE` feeds `trunk_red` and the merge queue. Teaching it a new shape changes what the factory calls a red test on the **trunk**, which is a different blast radius from one gate on one lane. The new module owns its own parse and leaves that classifier where it is |
| D9 | The hold's cause is `lifecycle.REGRESSION`, spends a round, and is **not** in `MECHANICAL` | A no-round mechanical hold the factory resolves itself | P12: the two mechanical causes are the ones code can fix. ## The design

Six pieces. One new module, one new cause, one new flag group, one line in the lane, one in the
brief, and one parse.

### 1. `asf/harvest/regression.py` — the predicate

The pure half, which the tests in §3 exercise without git or a test run:

```python
def gated(conv, items, item, branch, files):
    """``(True, '')`` when this branch is one the regression gate covers, else ``(False, why)``:
    a `fix` lane branch (`conv.branch_kind(branch) == 'fix'`) whose card's `found_in` is not in
    `exempt_found_in`, carrying both a test file and a non-test change (D1, D11)."""

def test_files(files):
    """The branch's test files, in order — `widen.is_test_path` of each (D3, P5)."""

def failing_cases(log, pattern=None):
    """The test case names a run's output reports as not passing, in order, each once:
    `unittest`'s ``FAIL: <case>`` and ``ERROR: <case>``, node:test ``✖``, vitest ``✗``/``×``,
    TAP ``not ok N -`` — or `pattern`'s first group when the product names one (D8). The name is
    the case's own, trailing parenthesised dotted path and duration stripped."""

def verdict(before, after, pattern=None):
    """``(state, cases, line)`` — `'proved'` with the case names red before and green after
    (D5); `'not-red'` when the pre-fix run names no failing case and exited 0; `'inconclusive'`
    when it exited non-zero naming none (D4); `'red-both'` when every case red before is red
    after. One place decides, so the hold's text and the tick line cannot disagree."""
```

`gated` is the only reader of the card: `found_in` off the index entry, nothing else. It returns
its own `why` so the tick line can say *why* a fix branch was not gated — a silent skip is how P1
happened.

### 2. `asf/harvest/regression.py` — the grafted run, in the background

`asf/harvest/rebuild_check.py`'s shape, function for function (D6), with its store at
`state/<product>/regression-check/`:

* `key(repo, trunk_sha, branch_sha, command)` → `<pre-fix tree>-<test tree>-<command hash>`, the
  three facts that decide the answer. A rebase that changes no content is a cache hit.
* `check(product, repo, state_dir, trunk_sha, branch_sha, …)` → `(state, line)`: the stored
  verdict when a job judged this content, else `(None, why)` — started now, or another check
  holds the lock — and the pass goes on without waiting.
* `run_job(...)` under the lock: one throwaway worktree detached at `origin/<trunk>`, the
  product's `worktree_setup`, then

  ```
  git checkout <branch sha> -- <each test file>
  git -c user.name=asf -c user.email=asf@local commit -q -m 'regression check: the branch's tests on the pre-fix tree'
  ```

  — a commit that exists only in that worktree and is never pushed, so `{base}` in the command is
  the pre-fix sha and a `--touched {base}` run selects exactly the grafted modules (D7). Then the
  command, then `failing_cases` of its output, then `verdict` against the head run's own, then
  `write_result`. The worktree is removed in a `finally`, as `pre_push_check_at` already does.
* `main`/`spawn`: `python3 -m asf.harvest.regression --product <p> --trunk <sha> --branch <sha>
  --key <k>`, detached, output to `logs/regression-check-<product>.log`.

The head run is not a second test run: the gate already runs the product's command on the rebased
head, and its output is what `verdict` reads as `after`. A branch the gate has not yet run is
`None` — deferred, like any other first pass.

### 3. `asf/harvest/lane.py` — where it is asked, and the hold

`lane_refusal` stays as it is: it is pure-git and cheap, and this check is neither. The ask goes
where the branch's facts are gathered (`branch_facts`, beside `f['refusal']`), under the same
`rec.get('state') in (None, PUSHED, BACK)` guard:

```python
if not f['refusal'] and conv.branch_kind(b) == 'fix':
    f['regression'] = regression.ask(self, f)   # (state, line) — None while deferred
    if f['regression'] and f['regression'][0] not in ('proved', 'skipped', 'waived'):
        f['refusal'] = (lifecycle.REGRESSION, regression.hold_text(f))
```

`hold_text` is the session's instruction, not a verdict shouted at it — the file it must write,
the pre-fix sha, the command the lane ran, and the run's last lines:

```
no regression test: the branch's tests pass on origin/main at e5e716f, so nothing on it would
have caught B-0142. Write the case that fails without your fix and passes with it, in
tests/test_staged_guard.py, and push the same branch. The lane ran, in a checkout of e5e716f
with tests/test_staged_guard.py taken from your branch:
  python3 tools/run_tests.py --touched e5e716f --shards 2
  Ran 14 tests in 2.1s
  OK
If this defect genuinely cannot be caught by a test, that is a decision, not a note: it needs a
D- card in the register and a `Regression-waived: D-nnnn` trailer on a commit of this branch.
```

Three other states, three other texts: `inconclusive` prints the non-zero run's tail and says the
grafted test did not run as a test on the pre-fix tree (D4); `red-both` names the cases red on
both sides; a `Regression-waived:` trailer whose id the register lacks says which id was not
found.

### 4. `asf/workers/lifecycle.py` — the cause

```python
#: F-0312: a fix branch whose tests pass on the pre-fix tree — the regression test is missing,
#: inconclusive, or red on both sides. The session's work, so a round is spent and the factory
#: does not try to resolve it itself (never in MECHANICAL).
REGRESSION = 'regression'
```

`MECHANICAL` is left exactly as it is (D9, P12).

### 5. `asf/conventions.py` — the flags

Added to `KNOWN_FLAGS` (P11), under `conventions.flags`:

| Flag | Default | What it does |
|---|---|---|
| `regression.check` | `off` | `on` runs the gate; `off` skips it and prints one line per fix branch saying so. Off by default: a product adopting this release does not have its incident lane start holding branches unasked |
| `regression.exempt_found_in` | `['ci']` | The `found_in` values the gate does not cover (D1) |
| `regression.command` | unset → `conventions.test_command` | `{base}` substituted with the pre-fix sha (D7) |
| `regression.fail_re` | unset → the built-in shapes | A product whose runner names failing cases in its own way (D8) |

`asf check` / `doctor` says a malformed one (a `command` that is not a string, an
`exempt_found_in` that is not a list of strings) rather than acting on it, as `pre_push_check`'s
own validation already does (`asf/conventions.py:584`).

### 6. `asf/briefs/templates/fix-bug.md` — the promise, with the command under it

The brief's existing sentence stops being a claim. Under `THE TEST THAT CLOSES IT`, the two facts
a session needs to run the lane's own check before it pushes:

```
THE TEST THAT CLOSES IT: {tests}
Write that test FIRST and watch it fail, then make it pass. The lane checks it mechanically: in a
checkout of {regression_base} with your branch's test files grafted on, it runs
  {regression_command}
and holds the branch back to you unless a case fails there and passes on your head.
```

`{regression_base}` and `{regression_command}` come from the row the same way `{tests}` does
(`preamble`, P6); for a product with `regression.check: off` the block is empty, as
`{pre_push_check}` already is.

### What it looks like when it is there

A fix branch whose test is red before and green after, over two passes:

```
lane: fix/B-0142 pushed → pr (regression: deferred — started in the background on 1a2b3c4d5)
lane: fix/B-0142 pushed → pr (regression: proved — test_move_to_done_passes red on e5e716f, green on 1a2b3c4d5)
```

One whose test is green on both:

```
lane: fix/B-0142 pushed → back (regression: the branch's tests pass on origin/main at e5e716f)
```

One the gate does not cover, said rather than skipped silently:

```
lane: fix/B-0143 pushed → pr (regression: not gated — found_in: ci)
```

## Acceptance tests

Run from the checkout root. **The blocks naming `tests/test_regression_gate.py` do not pass
today: that module does not exist, and the plan that follows this spec mints one Task per Story to
write it.** The replay block at the end is the exception — it runs against the trunk as it stands,
and §1's P9 is its output.

**S-79904 — the predicate: who is gated, what is a test, which cases failed, what it proves.**

```bash
python3 -m unittest tests.test_regression_gate.PredicateTest -v
```

Asserts, with no git and no test run: a `fix/` branch whose card is `found_in: prod` and whose
files carry both a test and a non-test change is gated; the same branch with `found_in: ci` is
not, and `why` says `found_in: ci`; a `worker/` branch is not gated whatever its card; a card with
no `found_in` **is** gated; a branch whose whole diff is tests is not, and `why` says so (D11);
`test_files` keeps order and picks `tests/test_a.py`, `src/b_test.py`, `ui/c.test.tsx` out of a
mixed list and leaves `tests/fixtures/data.json` alone; `failing_cases` reads `FAIL: test_x
(a.b.C.test_x)` and `ERROR: test_y (a.b.C.test_y)` as `['test_x', 'test_y']` and still reads the
node, vitest and TAP shapes `red_tests` does; and `verdict` returns `proved`, `not-red`,

## Records

The check writes four things, three of them new and all of them under the state dir. Nothing is
written to the record repo, and nothing to the metrics streams (D12).

| What | Where | Shape |
|---|---|---|
| The verdict, by content | `state/<product>/regression-check/<key>.json` | `{"state": "proved"\|"not-red"\|"inconclusive"\|"red-both", "cases": ["test_x"], "line": "…", "trunk": "<sha>", "branch": "<sha>", "at": "<iso>"}` — `<key>` is `<pre-fix tree>-<test tree>-<command hash>`, so a rebase that changes no content reads the same row. Pruned after 2 days, as `rebuild_check.KEEP_S` already does |
| Which check is running | `state/<product>/regression-check/running.lock` | The `flock` holder, its body `{"key", "trunk", "branch", "since", "pid"}` — what a later pass prints instead of waiting |
| The detached job's output | `logs/regression-check-<product>.log` | Appended; one `regression check <sha>: <state>` line per run |
| The hold | `sessions.jsonl`, via `lifecycle.hold` | The existing fields, with `cause: regression`, the `finding` the hold's text carries, and `rounds` advanced by one — no new field |

Two existing records change in **value** only: the tick line for a `fix` branch now carries a
`regression:` clause (the four states, plus `deferred` and `not gated — <why>`), and a held fix
branch's correction brief carries the hold's text as any other cause's does.

No card is written, no acceptance bullet ticked, no `gates.jsonl` row appended, no event emitted.
A product with `regression.check: off` writes none of the above and prints one line per fix branch
saying the gate is off.

## Stories

behind it. The record holds no Story card for F-0312, so each is **declared** below as a
`### S-…: <title>` heading with its acceptance lines under it, with ids from this session's
claimed block (`S:79904-79953`). That heading is what `asf.record.idcheck.declared_stories` reads
and what `asf.record.plan_tasks` mints the card from — a cited id with no declaration is a
phantom and the plan citing it is refused whole.

Each acceptance line below is one physical line of plain text with no backticks, on purpose: the
reader is line-anchored (`asf.record.idcheck.CHECKBOX` matches a single line) and `_prose`

minted card truncated and an identifier inside backticks reaches it missing.

### S-79904: the regression predicate — who is gated, what is a test, which cases failed, what that proves

Design §1 — `gated`, `test_files`, `failing_cases` and `verdict` in the new
`asf/harvest/regression.py`, the four pure functions every other Story calls (D1, D3, D4, D5, D8;
P5, P7, P8, P10). Acceptance is the first fenced block of `## Acceptance tests`: no git, no test
run, no product. `verdict` is the one place the four states are decided, so the hold's text and
the tick line cannot disagree about the same branch.

- [ ] a fix lane branch whose card is found_in prod, carrying both a test file and a non-test change, is gated
- [ ] the same branch whose card is found_in ci is not gated, and the reason returned names found_in ci
- [ ] a branch of the code, plan, spec or direct lane is not gated whatever its card says
- [ ] a card carrying no found_in field at all is gated: an absent field is not a licence
- [ ] a fix branch whose whole diff is test files is not gated, and the reason says there is no change to be red against
- [ ] test_files picks the test paths out of a mixed diff in order and leaves a fixture data file alone
- [ ] failing_cases reads unittest FAIL and ERROR case names, and still reads the node, vitest and TAP shapes
- [ ] verdict returns proved when a case is red before and absent from the failing cases after
- [ ] verdict returns not-red when the pre-fix run exits zero and names no failing case
- [ ] verdict returns inconclusive when the pre-fix run exits non-zero and names no failing case
- [ ] verdict returns red-both when every case red before the fix is red after it as well

### S-79905: the branch's tests run on the pre-fix tree, in the background, stored by content

Design §2 — the grafted worktree, the detached job, the lock and the result store, function for
function after `asf/harvest/rebuild_check.py` (D2, D3, D6, D7; P4). Acceptance is the second
fenced block of `## Acceptance tests`, over a real git fixture whose trunk holds the defect and
whose branch holds the fix and the test. The graft is committed inside the throwaway worktree and
never pushed, which is what makes the pre-fix sha a real base for the command to diff against.

- [ ] the throwaway worktree is detached at the trunk sha the gate measures the branch against
- [ ] the only files in it that differ from that trunk sha are the branch's test files
- [ ] the grafted commit is reachable from no ref in the repo, and the worktree is gone after the run whether it passed or failed
- [ ] the command receives the pre-fix sha wherever the base placeholder stood
- [ ] the store key is unchanged by a rebase that changes no content, and differs when a test file changes
- [ ] a second check started while the first holds the lock returns no verdict and names the sha that is running
- [ ] the first pass over a branch nothing has judged returns no verdict and says the check started in the background

### S-79906: the lane holds a fix branch whose tests were never red, and the text says what to write

Design §3 and §4 — the ask in `branch_facts` beside `f['refusal']`, `hold_text`, and the new
`lifecycle.REGRESSION` cause (D4, D5, D9; P2, P12). Acceptance is the third fenced block of
`## Acceptance tests`. The hold is an instruction, not a verdict: a session that cannot see the
sha and the command the lane ran cannot reproduce the refusal, which is the defect P1 describes in
the other direction.

- [ ] a fix branch whose verdict is not-red goes back to its session with cause regression
- [ ] the hold's text names the test file to write, the pre-fix sha, and the command the lane ran, verbatim
- [ ] the hold advances rounds by one, and the regression cause is not one of the mechanical causes the factory resolves itself
- [ ] a branch whose verdict is proved takes exactly the transition it takes on the trunk today
- [ ] a deferred verdict holds nothing and prints the deferral on the branch's tick line
- [ ] an inconclusive verdict holds the branch with its own text, naming the non-zero run that named no case
- [ ] a red-both verdict holds the branch with its own text, naming the cases red on both sides

### S-79907: a waiver is a decision the register holds, or it is not a waiver

Design §3 — the `Regression-waived: D-nnnn` trailer, read against
`asf.record.decisions.register` (D10). Acceptance is the fourth fenced block of
`## Acceptance tests`. This is the one escape hatch, and it is the same one
`asf.proves.unproved` already honours for a deferred acceptance line: a human's recorded
decision, never a session's prose.

- [ ] a regression-waived trailer naming a decision the register holds lands the branch, and the tick line names that decision
- [ ] the same trailer naming an id the register does not hold holds the branch, and the text says which id was not found
- [ ] a prose excuse on the branch with no trailer at all holds the branch as a plainly missing test
- [ ] a waived branch spends no round: the decision is the answer, not a correction

### S-79908: the four regression flags, off by default, a malformed one said and not acted on

Design §5 — `regression.check`, `regression.exempt_found_in`, `regression.command` and
`regression.fail_re` in `conventions.KNOWN_FLAGS`, with the conventions check naming a malformed
one (D1, D7, D8; P11). Acceptance is the fifth fenced block of `## Acceptance tests`. Off by
default is the point: a product that takes this release does not have its incident lane start
holding branches nobody asked it to hold.

- [ ] the regression check flag defaults to off, and a fix branch under a product with it off is not gated and says so
- [ ] all four regression flags are registered as known flags, so a product may set them and the doctor does not call them unread
- [ ] the command flag falls back to the product's own test command when unset, and the base placeholder is substituted in either
- [ ] a command flag that is not a string comes back as a named problem from the conventions check rather than reaching the runner
- [ ] an exempt found_in flag that is not a list of strings comes back as a named problem the same way

### S-79909: the fix-bug brief carries the pre-fix base and the command the lane will run

Design §6 — the two new substitutions in `asf/briefs/templates/fix-bug.md`, carried the way
