# F-0137 — the only pause today stops the clock, and the clock is what lands the work

An operator who wants one product to stop starting sessions — a release window, a migration under
way, a spend cap reached, a floor being drained by hand — has exactly one instrument:
`asf scheduler pause --product <p> --clock <c>`. It records the pause, then boots the launchd job
out (`asf/scheduler.py:589-604`). That does stop the launches. It also stops **everything else the
tick does**, because the tick is the only thing that does anything:

- **`record`** — the backfill, ingest, plan-tasks, replan, file-bugs, rollup and index all stop, so
  the board freezes at the moment of the pause and the status table goes stale (the `Stale` row is
  the one that says so, `asf/views/status.py:221`).
- **`harvest`** — the gate stops. Every branch a live session already finished and pushed sits
  unlanded. Sessions that were running when the clock stopped keep running, finish, push — and
  land nothing, ever, until somebody resumes.
- **`health`** — dead runs are never reaped, worktrees never released, stalls never seen.
- **`prs`, `batch`, `daily`** — likewise.

So the operator's actual choice today is: let the floor keep starting work, or stop the machine
that finishes it. The thing they want — *stop starting, keep finishing* — cannot be expressed.

The gap is narrow and the fix is narrow with it. The tick already has a **hold** shaped exactly
like this: host pressure (`asf/tick/step_wave.py:696-761`). A host over its load or swap guard
plans the whole wave, prints one `waits … — held: <why>` line per row it will not start, records
the reading as an event, and returns 0 — and `record`, `health`, `groom`, `prs` and `harvest` all
run that tick as usual. "Paused" is that hold, with a durable reason instead of a load average.

This card adds the durable record, the predicate, and the two doors that ask it.

### In

- **`asf/pause.py`** — a leaf module over `asf.env` and the stdlib: the record's path and shape,
  the one predicate `held(product)`, the text every reader renders, and the two commands.
- **`state/<product>/paused-launches.json`** — `{"reason": …, "by": …, "at": …}`, written by
  `asf pause`, removed by `asf resume`.
- **`asf pause --reason "<why>" [--by <who>] [--product <p>]`** and **`asf resume [--product <p>]`**.
- **The wave holds at the launch decision** — plans, prints one `waits … — held: paused …` line
  per row it will not start, emits one `paused` event, and returns 0. The lane pass, the deferred
  pushes, the triage lines, the invariant gate and the capacity event all still run (P3).
- **The demand record reads zero while paused** (P8) — so the partner borrows the slots.
- **The health step's cold retry holds too** (P5), taking the existing spend-nothing outcome (P6),
  never the round-spending hold (P7).
- **`asf tick --dry-run` says it** (P13).
- **The `PAUSED` status row and the doctor row carry it**, beside the clock pauses (P12).

### Out

- **Stopping, signalling or reaping a session that is already running.** A pause starts nothing; it
  never kills. This is the difference between a pause and `asf scheduler pause` followed by a
  `kill`, and it is what makes "keeps harvesting" mean anything — the in-flight work finishes and
  lands under the pause.
- **Pausing `record`, `health`, `groom`, `prs`, `harvest`, `batch` or `daily`.** The card names two
  of these as things that must keep going; none of the rest is a launch, and `asf scheduler pause`
  already exists for the operator who wants the clock stopped.
- **CI.** The `batch` step, `ci_queue`, the harvest gate's own test runs and the deploy pass all
  keep running. The gate *is* the harvesting the card says must continue, and it is made of CI.
- **A hand-run `asf workers spawn` / `asf workers wave` / `asf brief`.** The pause binds the tick's
  automatic doors. An operator typing a launch is not the factory deciding to launch, and a pause
  that refuses the operator's own hands takes away the escape hatch they paused in order to use.
- **A timed or auto-expiring pause.** A pause that lifts itself is how a floor restarts while
  somebody is still standing on it. It ends when `asf resume` ends it.
- **Pausing every product at once.** One product is the card's scope; the operator runs the command
  per product, and the record is per product because every other operational file is (P11).
- **Any change to the `ticks` stream schema** (P14) — see C5.
- **Removing a paused product from `active_products`** (P9) — see C4.

### The choices

| # | Chosen | Against | Why |
| --- | --- | --- | --- |
| C1 | A **state file** under `state/<product>/`, written by a command. | A field in `products/<p>.yaml` (`paused: true`). | The product yaml is version-controlled configuration describing what the product *is*. A pause is an operational act with a reason, an author and a date, taken and lifted many times a month. `asf scheduler pause` already made this call for the same reason (P10), and a command that edits a tracked yaml on the operator's behalf is a merge conflict waiting to happen. |
| C2 | A **new leaf module**, `asf/pause.py`. | Putting it beside the clock pause in `asf/scheduler.py`. | Five readers need the predicate — `step_wave`, `step_health`, `dry_run`, `views/status`, `doctor`. `scheduler.py` is a thousand lines of launchd: making the wave import it to ask one boolean drags `launchctl`, plist rendering and the clock model into the hot path of every tick. A leaf over `asf.env` is importable from anywhere with no cycle. |
| C3 | The hold sits at the **launch decision inside `launch()`**, after the lane pass and after planning. | An early return from `step_wave.run`, or skipping the `wave` step in `tick._run_steps`. | P3: the lane pass is what moves a finished branch to GATE and hands it to the harvest. Skipping the step would mean the paused product stops landing — the exact failure this card exists to remove. Planning anyway also costs nothing and buys the operator the list of what is being held. |
| C4 | The paused product stays in `active_products`; it records **`wanted = 0`**. | Dropping it from the split, so the partner's share is computed over one product. | `claim` already exists for precisely this — a partner that wants nothing lends its slots as `borrowed` (P8, P9). Dropping the product from `active_products` would change the *denominator*, which also changes the partner's base share and every reading derived from it, for a fact that the lending mechanism already expresses. And a paused product still holds seats for its live sessions; `claim`'s `max(…, inflight now)` keeps them. |
| C5 | The pause is recorded as one **`paused` event per tick**, on `metrics/events`. | A `paused: true` field on the `metrics/ticks` line. | P14: `ticks` is a closed validated schema that `scorecard_rows` reads field by field; one boolean is not worth a schema migration. The events stream is exactly where `host_pressure` — the hold this one copies — already goes. The cost is accepted and named: a paused product's ticks still count in the scorecard's `N launches in M ticks`, and the events stream is the join that explains them. |
| C6 | Under a pause, a dead session takes `handle_dead`'s **`released`-shaped outcome**: one line, no retry, no hold, no round. | (a) Letting the cold retry run — it is "finishing", not "starting". (b) Falling through to `lifecycle.hold`. | (a) `correct_once` starts a model session and spends money; a pause the operator cannot trust to stop spend is not a pause. (b) P7: `hold` counts a round against the item and walks it toward an ADJUDICATE row, punishing the card for the operator's pause. P6 is the shipped precedent for "nothing to do here, the item goes back to its own row" — and after `asf resume` its own feeder row launches it. |
| C7 | `asf pause` **requires `--reason`**, and `--by` defaults to `$USER`. | An optional reason. | Copied verbatim from `scheduler.pause` (P10). A pause found six hours later with no reason on it is a pause nobody dares lift. |
| C8 | Two plain verbs, `asf pause` / `asf resume`. | `asf launches pause|resume`, or a third `scheduler` subcommand. | They are the words for the act. The collision risk with `asf scheduler pause` is real and is answered by text, not by naming: each command's help and each output line says which of the two it is — "the clocks keep ticking: record and harvest go on, nothing launches" against "the clock is booted out: nothing ticks". |

## The design

### 1. `asf/pause.py` — the record, the predicate, the words

A leaf: `import datetime, json, os` and `from asf import env`, nothing else (C2).

```python
"""asf.pause — one product's launches held, while its tick goes on recording and harvesting.

``asf pause`` writes ``state/<product>/paused-launches.json`` (reason, who, when); every door the
tick opens onto a new session asks :func:`held` before it opens. Nothing else changes: ``record``,
``health``, ``groom``, ``prs`` and ``harvest`` run as they always did, the lane pass still moves
finished branches to the gate, and the sessions already running are never touched — they finish,
they push, and the harvest lands them under the pause.

This is not :func:`asf.scheduler.pause`, which boots the product's launchd clock out so that
*nothing* ticks. Both are durable, both carry a reason; this one stops starting, that one stops
everything.
"""

PAUSE_FILE = 'paused-launches.json'


def pause_path(product_name):
    return os.path.join(env.ASF_HOME, 'state', product_name, PAUSE_FILE)


def read(product_name):
    """``{'reason', 'by', 'at'}`` while ``product_name``'s launches are paused, else ``None``.
    An unreadable or malformed file is no pause: a pause nobody can read must never be able to
    stop the floor silently."""


def held(product):
    """:func:`read` for a :class:`asf.env.Product` or a name — the one predicate every door asks."""


def text(record):
    """``paused since <at> (<reason>; by <who>)`` — the same sentence shape as
    :func:`asf.scheduler.pause_text`, so the two pauses read alike on one status table."""


def hold_reason(record):
    """The wave's ``waits`` reason: ``launches paused: <reason> (by <who>, since <at>)``."""


def pause(product_name, reason, by, now=None):
    """Write the record; returns the lines to print. Overwrites an existing pause (a new reason
    replaces the old one, and the ``at`` moves) rather than refusing."""


def resume(product_name):
    """Remove the record; returns the lines to print. Resuming what is not paused is not an
    error — it is the operator making sure."""
```

The write is `json.dump` to `path + '.tmp'` then `os.replace`, the shape `write_demand` uses
(`asf/capacity.py:371-377`): a reader never sees a half-written pause.

`register(sub)` adds both parsers; `asf.cli.main` gains the two branches beside `scheduler`'s (P15):

```python
    if args.command in ('pause', 'resume'):
        from asf.pause import cmd_pause, cmd_resume
        return (cmd_pause if args.command == 'pause' else cmd_resume)(args)
```

What the operator sees:

```
$ asf pause --reason "release freeze until 0.2 ships"
pause: asf launches paused — release freeze until 0.2 ships (by <user>)
       record, health, groom, prs and harvest go on; the 3 sessions in flight finish and land.
       `asf resume --product asf` lifts it.

$ asf resume
pause: asf launches resumed — the next wave starts what the feeder plans
```

### 2. The wave holds, and lends its slots

In `asf/tick/step_wave.launch`, the pause is read once, beside the host reading (`:696`):

```python
    host_held, host_why, reading = host_hold(planned)
    paused = pause.held(product)            # F-0137: the operator's own hold, durable
```

and the demand write (`:686-687`) records nothing wanted while it stands (C4, P8):

```python
    capacity_mod.write_demand(product.name, len(running),
                              0 if paused else demand(items, product, running, inputs, extra,
                                                      exclude=dropped))
```

The per-row hold goes **before** the host check in the row loop (`:725`), so a paused product says
"paused", not "host pressure", when both are true — the durable reason is the one the operator
needs to read:

```python
        if paused:                          # F-0137: the pause holds every row, S1 included
            job = job_name(row.brief_kind, row.item_id)
            out(f'waits    {job:<24} {row.item_id:<10} — held: {pause.hold_reason(paused)}')
            continue
```

and the step's own last word, beside the host hold's (`:755`):

```python
    if paused:
        ctx.event('paused', reason=paused.get('reason'), by=paused.get('by'), at=paused.get('at'),
                  rows=sum(1 for row in planned if row.launches))
        out(f'wave: {pause.hold_reason(paused)} — no new session this tick; '
            f'recording and harvesting go on, and the sessions in flight finish and land')
        return 0
```

Returning 0 from `launch()` — not from `run()` — keeps `push_deferred` in the `finally` (P3), so
the lane pass's branch deletes and archives still reach origin. The `capacity` event is emitted
above this point and is unchanged, so the CAPACITY table still reads true for a paused product.

**The S1 bypass does not apply.** The host guard's bypass exists because an S1 must not be held by
load *other sessions created*; a pause is not incidental, it is the operator's instruction, and an
S1 that must be worked is a reason to resume, not a reason to launch under a pause. The `waits`
line for an S1 row under a pause is therefore the same as any other row's, and `s1_refresher` is
never built (the `return 0` above is reached first).

### 3. The second door: the cold retry

In `asf/tick/step_health.handle_dead`, between the `closed_state` test and the `reaped_empty` test
(`:84-90`), taking the outcome P6 established:

```python
    if pause.held(product):                 # F-0137: a pause starts nothing, retries included
        out(f"DEAD  {job:<24} launches paused: no cold retry — "
            f"{session.get('item') or '?'} goes back to its own row")
        return 'paused'
```

No hold is written, no round is spent (C6, P7), and `ctx.counts['relaunches']` does not move. The
session stays ended with its own `end_reason`, exactly as health wrote it; the item has no live run
and no pending correction, so the feeder plans its own row, and the first wave after `asf resume`
launches it.

### 4. The rehearsal, and the two places the operator looks

`dry_run._wave_rows` (P13) asks the same predicate and prints the same two shapes, so
`asf tick --dry-run` on a paused product shows every row it is holding and why:

```python
    paused = pause.held(product)
    ...
        if row.launches and paused:
            out(f'waits        {job:<24} {row.item_id:<10} — held: {pause.hold_reason(paused)}')
    ...
    if paused:
        out(f'wave: {pause.hold_reason(paused)} — no new session this tick; '
            f'recording and harvesting go on')
```

`views/status.paused_cell` (P12) keeps its name and its "silent unless something is paused" rule,
and puts the launch pause first — it is the one that is true while the table is still updating:

```python
def paused_cell(cfg, product):
    """``PAUSED``: the product's launch pause (``asf pause``), then each clock ``asf scheduler
    pause`` holds unloaded — reason, who and when for each. No row while nothing is paused."""
    from asf import pause as pause_mod, scheduler
    parts = []
    record = pause_mod.held(product)
    if record is not None:
        parts.append(f'launches {pause_mod.text(record)} — `asf resume --product '
                     f'{product.name}` lifts it; the tick still records and harvests')
    parts += [f'{scheduler.label_for(product.name, clock, cfg)} {scheduler.pause_text(r)}'
              for clock, r in sorted(scheduler.read_pauses(product.name).items())]
    return '; '.join(parts) or None
```

and `doctor` gains one YELLOW row of the same sentence beside the clock pauses (`asf/doctor.py:748`),
so `asf doctor` on a quiet product answers "why has nothing started in four hours" on its own.

### What it looks like when it is there

The operator types `asf pause --reason "release freeze until 0.2 ships"`. Three sessions are
running. Nothing happens to them.

The next tick records — the backfill, ingest, plan-tasks, replan, file-bugs, rollup and index all
run, the board stays live. Groom runs. The wave plans, prints eleven `waits … — held: launches
paused: release freeze until 0.2 ships (by …, since …)` lines, writes `wanted 0`, and launches
nothing. The partner product's next wave finds those slots lent to it and uses them. The prs step
runs. The harvest starts its gate in the background, and over the next forty minutes the three
sessions finish, push, are moved to GATE by the lane pass, and are **landed** — the freeze is a
freeze on starting, and the work in flight ships.

Two ticks later the last of the three ends. Every following tick records, harvests nothing (there
is nothing left to land), and says the same eleven `waits` lines. `asf status` carries one PAUSED
row and `asf doctor` one YELLOW row, both naming the reason and the command that lifts it.

`asf resume`. The next wave launches what the feeder plans, against a board that never went stale.

## Acceptance tests

New test classes in a new file `tests/test_pause.py` (P16), plus the shipped suites that must stay
green. Each is a plain `unittest.TestCase`, never a subclass of an existing harness.

**S-36400 — the record, the predicate and the two commands.**

```bash
python3 -m unittest -v tests.test_pause.TheRecord tests.test_pause.TheCommands
python3 -m unittest -v tests.test_cli
```

`TheRecord` pins: `held` is `None` with no file; `pause(name, reason, by, now=…)` then `held`
returns exactly that reason, author and timestamp; a truncated or non-JSON file is `None` (a pause
nobody can read never stops the floor, C1's safety clause); `resume` removes it and a second
`resume` is rc 0 with a line, not an error; `text` and `hold_reason` both name the reason, the
author and the date. `TheCommands` runs `asf pause` with no `--reason` and asserts rc 2 with the
`--reason "<why>"` line (C7), runs it with one and asserts the file and the three printed lines,
then `asf resume` and asserts the file is gone. `tests.test_cli` is the shipped surface test and
must accept the two new verbs.

**S-36401 — the tick keeps recording and harvesting, and launches nothing.**

```bash
python3 -m unittest -v tests.test_pause.TheWaveHolds tests.test_pause.TheOtherDoor
python3 -m unittest -v tests.test_tick tests.test_tick_steps
```

`TheWaveHolds` drives `step_wave.launch` over a paused product with a plan holding several
launching rows, one of them S1, and asserts: `_wave` was **never called** (the launcher is patched
to fail the test if it is); every launching row printed a `waits … — held: launches paused: …`
line, the S1 row among them and with the same reason; the `wave: … no new session this tick`
line names recording and harvesting; a `paused` event carrying the reason, the author and the row
count is on the events stream; `lane_pass` **was** called and `push_deferred` ran; and `launch`
returned 0. The same test with no pause asserts `_wave` is called, which is what makes the first
half mean something. `TheOtherDoor` drives `step_health.handle_dead` over a dead session of a
paused product with `stall_mod.correct_once` patched to fail the test if called, and asserts the
return is `'paused'`, the printed line names the item, `ctx.counts['relaunches']` is 0, **no**
`held` event was emitted and no round was written to the ledger (C6, P7). `tests.test_tick` and
`tests.test_tick_steps` are the shipped tick suites and must stay green un-edited — the proof that

## Records

- **`~/.ASF/state/<product>/paused-launches.json`** — new, one object: `reason` (required, the
  operator's words), `by` (`$USER` unless `--by`), `at` (local ISO to the second, the shape
  `scheduler.pause` writes). Absent means not paused. Written atomically; removed by `asf resume`.
  Never in a repo, never in a product yaml.
- **`metrics/events/<day>.jsonl`** — one new event kind, `paused`, appended by the wave once per
  tick while the pause stands: `{kind, product, ts, reason, by, at, rows}`, `rows` being the
  launching rows held. The events stream takes any object (P14), so this needs no schema change.
- **The demand record `state/<product>/…`** — unchanged in shape; `wanted` reads `0` while paused
  (C4), which is what the partners' `claim` and `fair_share` consume.
- **`metrics/ticks/<day>.jsonl`** — **unchanged**, deliberately (C5, P14). `launches` reads 0 on a
  paused tick because nothing launched, which is true; the `paused` event is the join that says
  why.
- **The session ledger** — **unchanged**. No session is ended, marked or held by a pause; a dead
  run under a pause keeps exactly the `ended`/`end_reason` health wrote, and gains no correction,
  no `rounds` and no `corrected` flag (C6).
- **`asf status`** — the existing `PAUSED` row gains the launch pause ahead of the clock pauses; no
  new row, and still silent when nothing is paused.
- **`asf doctor`** — one new YELLOW row in the clock section, naming the reason and `asf resume`.
- **What is no longer written** — while a product is paused: no `launch` event, no new session
  ledger line, no brief file, no worktree, no reserved id range, and no cold-retry correction
  brief. That absence, with the record and harvest lines still being written beside it, is this
  card's acceptance.
