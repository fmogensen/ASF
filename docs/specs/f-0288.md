# F-0288 — the ruling said the PR does not build them, and the record never heard it

An adjudication read a delivery lead's pull request and ruled that it is right as it stands: two of
the lead's members are not in it and will not be. That is a decision about the *record* — those two
Tasks are no longer this delivery's to build — and the factory has a command that writes it:
`asf undeliver <task> --why …` (`asf/record/undeliver.py`, documented at
`docs/guide/operating.md:578-589`, tested at `tests/test_retire.py:208-300`). Nothing ran it. The
tick filed the ruling's paragraph on the lead's card as a `## History` line, closed the row, and
left both edges standing.

So the two members kept `delivered_by: <lead>`, kept reading `WAITS ON delivery <lead>`, and kept
sitting in the lead's union footprint and in the lane's completeness check — until the lead's pull
request finally landed. A ruling whose whole point was "stop waiting on this PR" bought them
nothing but the same wait.

This card is: **the strike is a mechanism, not a paragraph.** The adjudicate brief already says so
in as many words — "Your ruling's *mechanism* is the three fields `blocked_on`, `writes` and
`superseded_by`; the paragraph is its *explanation*. A paragraph with no field behind it changes
nothing" (`asf/briefs/templates/adjudicate.md:26-30`). There are three fields and the strike is a
fourth thing a ruling decides. It gets its field, and the tick carries it out.

## Decisions

### A correction to the card, before anything else

The card says "the only escape is retiring the members and minting copies". That was true when the
card was written down and is not true in this checkout: `asf undeliver` is the escape, it is in the
command surface, it is documented in the operator guide under this exact scenario ("an adjudication
struck it"), and it has a test suite. What is missing is not the escape — it is that **a ruling
cannot ask for it**, so an operator has to notice the stranded members and type it twice by hand.
Everything below is scoped to that gap. The rest of the card — `delivered_by` and `delivers` not
settable, the member reading `WAITS ON delivery <lead>` until the lead lands — is verified below and
stands.

### The choices

| # | Chosen | Against | Why |
| --- | --- | --- | --- |
| C1 | **A fourth ruling field, `undelivers: <id> …`, is the mechanism. The paragraph stays the explanation.** | Parsing ids out of the `ruling:` prose; a new `strike:` block; an operator-only path. | The brief already teaches the adjudicator that a ruling's mechanism is a field and "a paragraph with no field behind it changes nothing" (`adjudicate.md:26-30`). A fourth field is the same sentence with one more name in it, and it is the only shape the existing reader (`ruling_fields`) and the existing writer (`report.FIELDS`) already know how to carry. Mining prose for ids is the opposite rule: it makes an id a session wrote in passing into a record edit, which is exactly what B-0054 forbids. An operator-only path is what we have, and it is the defect. |
| C2 | **`undelivers:` goes *last* among the ruling fields — after `superseded_by:`, before `NEEDS OPERATOR:`.** | Grouping it with `writes:`; putting it first, as the loudest claim. | P8, measured: a session running against a newer brief than its factory's parser writes a line the parser does not know. After `superseded_by:` that line claims nothing, because `superseded_by` is read through `_first_line`. Anywhere earlier it is appended to a multi-line field — measured, it turns `writes: none` into a four-glob footprint claim, which the widening rule then acts on. The safe placement is not a matter of taste; it is the one that fails closed in both directions during a roll-out. |
| C3 | **The tick carries it out, in its own step, through `asf.record.undeliver`'s own writer.** | The adjudicate session running `asf undeliver` itself; folding it into `file_rulings`; a new console command. | A session never publishes to the record — the brief's standing rule, and `file_rulings` exists because of it (B-0064). Its own step rather than inside `file_rulings` so that a strike that fails does not cost the ruling its `## History` line, and is retried on the next tick: `file_rulings` marks `adjudicated` once and never looks again, so a failure folded into it would be lost. The writer is `undeliver`'s, not a second copy: the lead-first order, the restore on a half-write and the `## History` wording (P2, P12) are all load-bearing and all already tested. No new console command, so `tests/test_surface.py`'s pinned count of 59 does not move. |
| C4 | **The named ids are checked against the record, and an id that is not an open member of the ruled item's delivery is refused by name and changes nothing.** | Trusting the ruling; silently skipping what does not match; failing the whole strike on one bad id. | A ruling is a session's text and the record is the fact — the same rule the brief gives the adjudicator about anchors. The one check that makes the claim safe is cheap: the named card must carry `delivered_by: <the ruled item>`. Anything else (a member of another delivery, a closed member, a Task id that is not a member, an id that is not a card) is named in one line and left alone. Per-id, not all-or-nothing, so one typo does not strand the members the ruling got right. |
| C5 | **The strike withdraws a pending `incomplete` correction it makes moot, and nothing else.** | Leaving the correction to be answered; clearing every correction on the run; re-deriving the hold out of band. | The hold that sent the lead's branch back is "no commit names T-51406, T-51407 — build T-51406 next" (`incomplete_refusal`). After the strike those Tasks are not the delivery's to build, so answering that correction means a coder session building work a ruling just removed from the branch. `widen_footprint.apply` already does exactly this withdrawal for a footprint hold whose claim went away (P10), and the test is the same: only an `incomplete` correction, and only when every id in its finding was struck. A correction naming anything else stands. |
| C6 | **The member's `after:` is left exactly as the plan wrote it. The strike drops the delivery edge and nothing else.** | Also clearing an `after:` that names a member of the delivery the card just left, so the member builds in parallel with the lead; a `--free` flag on `undeliver`. | P11: a member's `after:` was backfilled from the plan, and `slice` never writes one on a member — so dropping it is editing the plan's declared dependency order from a ruling, and B-0076's whole point is that `after:` is the declaration. The measured consequence is explicit and acceptable (P5): with no `after:` the struck members launch at once, in parallel with the lead, which is the incident's own case; with one, the member reads `WAITS ON <lead>` and builds the moment the lead lands — the same place `deferred_member_row` has always put a member the delivery leaves out. If a plan's `after:` is wrong, the door for that is a replan or a reshape, not a strike. |
| C7 | **A ruling that strikes members is still a ruling that can overrule a review.** | Adding `undelivers` to the `overruling` gate's refusal list beside `blocked_on` and `superseded_by`. | `lifecycle.overruling` refuses those two because each means the branch is not going anywhere — it waits for another item, or it is replaced. A strike means the opposite: the branch as it stands is right, and the record is being corrected to match it. Refusing to overrule on it would re-raise the same review the ruling just answered, which is the B-1377 loop that gate exists to stop. |

### Out of scope

- A *review* that finds the PR does not build a member. The card names "an adjudication or review"; a
  review's verdict is `changes` and its C list, which the lane turns into a correction and — at the
  round cap — into the adjudicate row that produces the ruling this spec acts on. Giving a review
  its own record-editing field is a second mechanism for one decision; the ruling is the door.
- Making `delivered_by` / `delivers` settable through `asf set`. The edge is paired and `asf set`
  writes one field on one card: two commands, two commits, and `asf check` red in between (P12).
  `asf undeliver` is the one writer and stays so.
- Re-cutting a struck member into a new delivery with its siblings. `slice.deliveries` only cuts
  *free* Tasks, and a struck member is free again the moment its `delivered_by:` is gone — the next
  record step decides that by the existing rule, with no new one.

## The design

### 1. The field (`asf/workers/report.py`)

`'undelivers'` joins `FIELDS` and `FIELD_RE`'s alternation after `'superseded_by'` (C2).
`ruling_fields` gains a fourth key, read like `writes` — whitespace-split ids, `none` and absent
both `None`:

```python
def ruling_fields(text):
    """{'blocked_on': id|None, 'writes': [glob, …]|None, 'superseded_by': id|None,
    'undelivers': [id, …]|None} off the last REPORT block — the ruling's mechanism (F-0090 D10,
    F-0288). `undelivers` names the delivery members this ruling takes out of the ruled item's
    delivery; it is read last of the four because an older parser appends an unknown field to the
    one above it, and after `superseded_by` (read through `_first_line`) that costs nothing."""
```

Nothing else in the package changes shape: `overruling` keeps refusing on `blocked_on` and
`superseded_by` only (C7), and `health.ready` keeps reading `blocked_on`.

### 2. The ask (`asf/briefs/build.py`, `asf/briefs/templates/adjudicate.md`, `asf/procedures/skills/report-shape/SKILL.md`)

One line in `TAIL`, immediately after `superseded_by:` and before `NEEDS OPERATOR:`:

```
undelivers: <adjudicate only — the delivery members this PR does not build, space-separated, or none>
```

The same line is added to the report-shape skill, byte for byte. The adjudicate template's mechanism
paragraph becomes four fields and gains the case:

> Your ruling's *mechanism* is the four fields `blocked_on`, `writes`, `superseded_by` and
> `undelivers`; the paragraph is its *explanation*. … If the answer is "this PR is right and these
> Tasks are not in it", the answer is `undelivers: T-0002 T-0003` — the factory takes each of them
> out of the delivery so it builds on its own lane, instead of waiting for this PR to land.

### 3. The strike (`asf/tick/strike.py`, new; called from `asf/tick/step_health.py`)

A new module, in `rejudge`'s shape and called from `step_health.run` directly after `file_rulings`
and before `rejudge`, wrapped the same way:

```python
def run(ctx, out=print):
    """F-0288: an adjudicate ruling's `undelivers:` ids, carried out on the record — each named
    member leaves the ruled item's `delivers:` and loses its own `delivered_by:`, both cards get a
    `## History` line, and a pending `incomplete` correction the strike makes moot is withdrawn.
    Once per run (`struck`), per id, and never trusting the ruling over the record. {job: [ids]}."""
```

Per ended `adjudicate` run with no `struck` marker:

1. `report.ruling_fields(result)['undelivers']` — `None`, mark `struck='none'`, no line.
2. For each named id, over `index_reader`'s items from `ctx.record_root()`: it is a card, it is
   open, and its `delivered_by` is the run's own item (C4). Anything else → one line naming the id
   and why, and that id alone is skipped.
3. For each surviving id, in the order the ruling named them, through the writer
   `asf.record.undeliver` exposes for both callers — the console command and this step:

```python
def undeliver(canonical, member_id, why, product=None, writer='undeliver'):
    """Take `member_id` out of its lead's delivery: the lead's `delivers:` first (dropped whole
    when only the lead would be left), then the member's `delivered_by:`, a `## History` line on
    each, the lead's text restored if the member's write fails. `(lead_id, None)` or
    `(lead_id, error)`. `cmd_undeliver` is this plus the console's argument handling and refusals;
    `asf.tick.strike` is this plus the ruling's."""
```

`cmd_undeliver` keeps its signature, its refusals and its output and becomes a caller of it — no
behaviour change, so `tests/test_retire.py:208-300` passes untouched.

4. `_reindex(ctx.record_root())` once, when anything was written; the tick's `commit_and_push`
   carries the cards and `index.json` in its own `tick: state <ts>` commit.
5. The pending correction (C5): when the lead's run carries a `pending_correction` of kind
   `lifecycle.INCOMPLETE` and every id in its `finding` was struck on this pass,
   `pool_mod.update_session(product, job, correction=None)` and one line —
   `strike <job>: T-0001's incomplete hold named only struck members — correction withdrawn`.
6. `ctx.event('undeliver', job=…, item=…, members=[…])`, `struck=<stamp>`, and one line per
   outcome. An exception anywhere is one line and no marker: the next tick tries again.

### What it looks like when it is there

The lead's pull request is held BACK, `incomplete`, naming T-51406 and T-51407. An adjudicate
session rules that the PR is right and writes `undelivers: T-51406 T-51407`. On the next tick:

```
ruling adjudicate-t-51405 filed on T-51405: the PR builds what the plan asked of it; T-51406 …
strike adjudicate-t-51405: T-51406 undelivered from T-51405 — T-51405 delivers T-51406's siblings
strike adjudicate-t-51405: T-51407 undelivered from T-51405 — T-51405 delivers none (delivers: dropped)
strike adjudicate-t-51405: T-51405's incomplete hold named only struck members — correction withdrawn
```

and the feeder's next table has `DELIVERY → CODE T-51405` on its way to a pull request, with
`PLAN → CODE T-51406` and `PLAN → CODE T-51407` launching on their own branches — at once if the
plan put no `after:` on them, otherwise the moment the lead lands.

## Stories

### S-75404: `undelivers:` is the ruling's fourth mechanism field, read last so a stray line claims nothing

- [ ] `report.FIELDS` and `FIELD_RE`'s alternation carry `undelivers` between `superseded_by` and `precedent`, and `parse()` reads an `undelivers:` line as its own field rather than a continuation of the field above it
- [ ] `ruling_fields` returns a fourth key `undelivers`: whitespace-split ids for `undelivers: T-0002 T-0003`, and `None` for `none`, `None`, `n/a`, `-`, the em dash, an empty value and an absent line alike
- [ ] an `undelivers:` line placed above `superseded_by:` corrupts the field above it, measured: `writes: asf/a.py` then `undelivers: T-0002 T-0003` reads as the four-glob footprint `['asf/a.py', 'undelivers:', 'T-0002', 'T-0003']`, and `writes: none` reads as `['none', 'undelivers:', 'T-0002', 'T-0003']` — a claim nobody made
- [ ] placed last, after `superseded_by:`, the same line claims nothing in either direction: `ruling_fields` gives `blocked_on`, `writes` and `superseded_by` all `None` both before the field exists (`superseded_by` swallows it and `_first_line` discards it) and after
- [ ] `RulingFieldsTests` compares the dict whole at `tests/test_report.py:181` and `:186`, so the fourth key is added to those two assertions — its absence there is a red test, not a silent pass
- [ ] `lifecycle.overruling` still refuses on `blocked_on` and `superseded_by` only: a ruling whose one mechanism is `undelivers:` still overrules a review, and `health.ready` still reads `blocked_on`

### S-75405: The brief asks for the field it will act on, in every kind's tail and in the adjudicate template

- [ ] `briefs.build.TAIL` carries exactly one `undelivers: <adjudicate only — the delivery members this PR does not build, space-separated, or none>` line, immediately after `superseded_by:` and immediately before `NEEDS OPERATOR:`
- [ ] every kind's brief ends with that tail byte for byte, and the four ruling fields appear in order `ruling`, `blocked_on`, `writes`, `superseded_by`, `undelivers`, all of them before `NEEDS OPERATOR:` — the landed ordering assertion at `tests/test_briefs.py:271` is extended to the fourth name
- [ ] `asf/procedures/skills/report-shape/SKILL.md` carries the same `undelivers:` line byte for byte, in the same position after `superseded_by:`
