# F-0343 — the kernel's own hands on the trunk: what landed, and the work it mints

The kernel's delivery chain is five links: a Feature's spec lands and its Stories become cards; its
plan lands and its Tasks become cards; a Task launches a coder; the coder's PR lands; the Feature
is done when its Tasks are. The kernel holds link one (`asf.kernel.decide._mint`, `decide.py:1591-1598`)
and links three to five. **Link two does not exist in the kernel at all**, and link one reads the
trunk through a directory listing of the operator's working checkout.

So the 0.3 autonomous chain stops at the plan. Three measured facts, in the order they bite:

* `grep -c plan_tasks asf/kernel/*.py` finds the record's minter nowhere in the kernel — only two
  regexes imported from it (`ports.py:238`). There is no `Facts` field holding a plan's text, no
  action that writes a Task card, and no port method that mints one (P1).
* The moment a Feature's plan PR merges, the kernel judges that Feature **Done** — with no Task
  card, no code, and nothing built (`decide.py:597`, `_spec_only` at `:1818-1825` excuses a merged
  *spec* PR and nothing else). The Feature's own `## Stories` stop minting at the same instant,
  because the facts reader drops a Done Feature's spec (`facts.py:239-240`) (P4).
* `RealRecord.specs_landed` is an `os.listdir` of `<repo_dir>/<specs_dir>` (`ports.py:349-369`).
  Its docstring says "every Feature spec on the trunk checkout"; what it reads is whatever that
  working tree happens to hold. A spec merged to the trunk an hour ago and not yet pulled is
  invisible; an uncommitted file in that directory is read as landed and mints Story cards from
  text no reviewer ever approved (P2).

This Feature closes link two and puts both document reads on **origin's trunk**, which is the only
place "landed" means anything. Everything the kernel already does well — the still-needed gate, the
`after:` order, the Definition of Ready — then has cards to work on.

## Decisions

### Preconditions — measured in this worktree at `5c067eb29`, 2026-10-10

Both measurement scripts are in `## Acceptance tests` (`The preconditions, re-measured`), so every
number below can be replayed from the repo root.

* **P1 — the kernel has no surface for minting work from a plan.** `asf.kernel.actions` holds 23
  action classes; `MintStory` is one, `MintTask` is not. `Facts`'s only document field is
  `specs_landed`. `RecordPort`'s methods are `answers`, `card_fields`, `items`, `mint_story`,
  `paused`, `record_review`, `reviews`, `specs_landed`, `widen_writes`, `write_fields` — no
  `plans_landed`, no `mint_task`. `grep -rc plan_tasks asf/kernel/*.py` is 0 everywhere but
  `ports.py` (1: two regexes for `declared_stories_of`).
* **P2 — `specs_landed` reads the working checkout, not the trunk.** With `origin/main` carrying
  `docs/specs/f-0001.md` and `docs/specs/f-0002.md`, the checkout rewound one commit, and an
  uncommitted `docs/specs/f-0003.md` in the tree:
  * `specs_landed()` returns `['F-0001', 'F-0003']`;
  * `F-0002`, **merged on the trunk**, reads as not landed — its Stories are never minted;
  * `F-0003`, **never committed**, reads as landed — its Stories are minted from an unreviewed
    file.
* **P3 — the kernel's other trunk reads already go through origin.** `trunk_files` is
  `git ls-tree -r --name-only origin/<main>` and returns `None` when it cannot read
  (`ports.py:506-517`); `floor_approvals` reads `origin/<branch>` (`:1412-1430`);
  `TrunkProbe` fetches `origin/<main>` and reads blobs at that sha (`trunk.py:124-131`,
  `:141-143`). Only `specs_landed` reads the file system.
* **P4 — a merged plan PR makes the Feature Done.** `decide` on a Feature whose spec PR merged:
  state `ready`, launches `plan` on `plan/F-0001`. The same Feature once its **plan** PR has also
  merged: state **`done`**, launches nothing — with a Story child, still `done`. The rule is
  `decide.py:597` (`open_pr is None and landed(it, prs) and not spec_only` → Done) and
  `_spec_only` (`:1818-1825`), which is True only while *every* merged PR is on the spec prefix.
* **P5 — a Feature whose plan already landed is launched to plan again.** `_kind`
  (`decide.py:1751-1756`) returns `'plan'` for any Feature whose spec is in `specs_landed`; nothing
  in it reads whether the plan landed. A Ready Feature with no children therefore launches
  `plan` every tick a seat is free, for ever.
* **P6 — a Feature with only Story children is not derived from them, by design.** `_derived`
  (`:1475-1481`) returns False for a Feature whose children hold no Task or Bug: "its document lane
  is still its own, so it launches its plan". `BUILDABLE` is `('task', 'bug')` — a Story never
  builds. So with no Task cards, nothing under the Feature can ever launch a coder.
* **P7 — the record's plan reader is pure and already parses what is needed.** On a two-Task plan,
  `asf.tick.migrate.plan_task_records` returns `[('T1', 'lay the port down', ['asf/kernel/ports.py']),
  ('T2', 'wire it into decide', ['asf/kernel/decide.py'])]` (title and `writes` through
  `writes_lines`), and `asf.record.plan_order.task_order` returns `{1: [], 2: [1]}`. Neither reads
  a disk, a network or a clock. `task_like_headings` names the drift when a plan's headings parse
  to no Task (`migrate.py:189-195`).
* **P8 — the record's own minter cannot be called from a kernel tick as it stands.**
  `asf.record.plan_tasks.mint_plan_tasks(root, product, ev)` takes the 0.1 evidence dict and finds
  a plan through `match_feature`/`plan_ref` (`plan_tasks.py:130-140`), i.e. `features[*].plan` and
  `plan_on_main` as the ingest computed them. Its one caller is `asf.tick.run_record_fast`
  (`tick.py:118-124`), which runs `cmd_ingest` first. The kernel tick runs neither: its steps are
  `snapshot`, `sync_cloud`, `mint_inbox`, `read_facts`, `decide`, `apply`, `publish`
  (`loop.py:421-440`).
* **P9 — the record can mint a Task card today.** `write_new_item(root, cards, 'task', id, typed,
  body, date, why, state=…)` writes `writes`, `stories`, `decided`, `links`, `after` and a History
  line (`ids.py:174-214`); `mint_id(root, cards, type_, claimant=…)` is the one id source and
  honours the claim mirror (`ids.py:107-147`). `RealRecord.file_bug` already mints with
  `claimant='asf-kernel'` (`ports.py:489-504`), and `mint_story` already writes a card through
  `write_new_item` (`:608-619`).
* **P10 — the kernel already closes a Task whose work is on the trunk.** The still-needed gate runs
  the tests a card names on a fresh worktree of origin's trunk and marks the item Done with
  `satisfied on main at <sha>` (`needed.py:6-18`), dating the probe from the card's
  `links: {plan: …}` (`needed_probe.py:7`, `:79-82`; `Item.plan`, `model.py:128`).
* **P11 — the object store has one batched reader, and it is the record's.**
  `asf.evidence.evidence.read_trees('<rev>:<dir>')` returns `{name: oid}` and `read_refs(['<rev>:<path>'])`
  returns `{ref: text}`, each in one `git cat-file --batch` process, read-only on `repo_dir`
  (`evidence.py:134-177`, `:185-187`). `asf.record.plan_tasks` reads every plan through
  `evidence.read_refs` (`plan_tasks.py:150-153`), so a kernel read through the same functions sees
  byte-identical text.
* **P12 — a fetch is a read the dry run skips.** `asf.mutation_guard` stops mutating `git push` and
  `gh` calls only; `TrunkProbe` nonetheless fetches nothing while the guard is active, and reads
  the local `origin/<main>` and its cache (`trunk.py:103-131`). `evidence.py`'s own contract is
  "never commit, checkout or fetch anything there but `git fetch --prune origin`" (`:27-28`).
* **P13 — a convention may not be a literal in `asf/**/*.py`.** `tools/check_conventions.sh`
  fails the push on any path-shaped default in the package; `Conventions.doc_dir('spec'|'plan')`
  is the read (`conventions.py:1425-1427`), and `conv.plans_dir` exists beside `conv.specs_dir`
  (`:862-863`).
* **P14 — the record holds no Story for F-0343**, no `docs/specs/f-0343.md` and no
  `docs/plans/f-0343.md`. This session's block is `S:128755-128804`.
* **P15 — one existing test pins the behaviour this card changes.**
  `tests/kernel/test_ports.py:68` asserts `specs_landed() == {'F-0001': '## Stories\n- S-0001: one\n'}`
  from a `repo_dir` that is a bare temp directory with no `.git` at all.

### In

* **`asf/kernel/ports.py` — `RealRecord._landed_docs()`**: one memoised read per port instance of
  `origin/<main>`: one `git fetch -q origin <main>` (skipped while `mutation_guard` is active),
  one `evidence.read_trees` for `<specs_dir>` and `<plans_dir>`, one `evidence.read_refs` for every
  blob in them whose file name carries a Feature id on the record. `specs_landed()` and
  `plans_landed()` slice it. An unreadable trunk (no `repo_dir`, no `origin/<main>`, a failed
  fetch, a failed batch) is `{}` for both — never the checkout.
* **`asf/kernel/ports.py` — `RealRecord.mint_tasks(feature_id, plan_path, tasks)`**: mints one
  Task card per entry in order through `mint_id(claimant='asf-kernel')` + `write_new_item`, then
  writes each card's `after:` as card ids once every id exists. Returns the ids.
* **`asf/kernel/ports.py` — `RecordPort`** gains `plans_landed` and `mint_tasks`.
* **`asf/kernel/model.py` — `Facts.plans_landed`**: Feature id → the text of its plan on the trunk.
* **`asf/kernel/facts.py`**: `plans_landed` read beside `specs_landed`, through the same filter —
  on the record, not Done.
* **`asf/kernel/plans.py`** (new, pure): `PlanTask(tid, title, body, writes, stories, after)`,
  `plan_tasks(plan_text, known_stories)` over `asf.tick.migrate.plan_task_records`/`writes_lines`
  and `asf.record.plan_order.task_order`, and `drift(plan_text)` over `task_like_headings`. The
  shape of `asf/kernel/stories.py`: one module, no I/O.
* **`asf/kernel/actions.py` — `MintTasks(feature_id, plan, tasks)`** and its `describe` line.
* **`asf/kernel/decide.py` — `_mint_tasks(facts, parked, minted_stories)`**: a `MintTasks` for
  every visible, not-Done Feature whose plan is in `facts.plans_landed`, that has no Task or Bug
  child (`_has_work`), and whose plan parses to at least one Task none of its open Tasks duplicates.
* **`asf/kernel/decide.py` — `_doc_only`** in place of `_spec_only`: a Feature whose merged PRs are
  all on a document lane (`config.doc_branches`) is not Done.
* **`asf/kernel/decide.py` — `_kind`**: a Feature whose plan is in `plans_landed` is not launched
  to plan again; it holds until its Tasks are on the record.
* **`asf/kernel/decide.py` — `_judge`**: a Feature whose landed plan yields no Task the kernel can
  mint is Stuck on the operator, with the reason naming the plan and what it found.
* **`asf/kernel/decide.py` — `ORDER`**: `A.MintTasks` directly after `A.MintStory`.
* **`asf/kernel/apply.py` — `MintTasks`**: through the port, logging the ids it wrote.
* **Tests**: two new modules, `tests/kernel/test_landed_docs.py` and
  `tests/kernel/test_plan_mint.py`; `plans_landed` and `mint_tasks` on `tests/kernel/fakes.py`'s
  `FakeRecord`; `tests/kernel/test_ports.py`'s `Record` fixture made a real git repo with an
  `origin` (P15).

### Out

* **The record's own minter.** `asf.record.plan_tasks.mint_plan_tasks` keeps its behaviour, its
  caller and its tests; the 0.1 tick is untouched. The kernel does not call it (D2) and does not
  change it.
* **A Task's decision-register check.** `plan_tasks` refuses a plan whole when a Task cites a
  `D-nnnn` the register lacks (`plan_tasks.py:177-187`). The kernel's mint does not: the decision
  register is a record invariant, the record's write stage already refuses a card an invariant
  rejects, and `mint_story` has no such check today either. Adding one to both minting paths is a
  card of its own.
* **Id claims on the plan's own declarations.** The ids a kernel-minted Task carries are minted by
  the record under its own claimant (P9), not declared in the plan, so `idcheck.check_doc`'s
  "no claim covers this id" refusal has nothing to refuse. The Story-declaration path it does
  cover is `_mint`'s, and that is unchanged.
* **`trunk_check.satisfied_on_trunk` at mint time.** The record mints a Task `Closed` when its
  named tests are already on the trunk. The kernel has a stronger, later answer: the still-needed
  gate probes origin's trunk before every launch and marks the item Done with the sha (P10). A
  second, earlier probe would double the per-tick test budget to answer the same question.
* **Replans and reslices.** `asf.record.replan` (a landed replan rewriting open Tasks) and
  `asf.record.slice` (deliveries) stay the 0.1 tick's. A Feature that already has a Task child
  mints nothing here, so the two never race.
* **Story cards from a plan.** `plan_tasks` mints a `### S-…` heading the plan declares, for a
  session that cannot reach the record. The kernel mints Stories from the **spec** only
  (`_mint`), which is where this product's convention puts them, and a Task citing a Story that
  is neither on the record nor minted from the spec this tick simply carries no `stories:`.
* **The Feature's own done-ness.** This card stops a merged plan from reading as Done; what makes
  a Feature Done stays `_state_of` over its Task children (`decide.py:1511-1512`).
* **Any new config key.** The two reads and the mint are unconditional: a kernel product whose
  plans land and never become Tasks has no state worth keeping configurable.
* **`asf/tick/**` and `asf/record/**` behaviour.** Read from, never changed — `plan_order` and
  `migrate`'s parsers are called, not edited.

### Preconditions the work depends on

1. `asf.evidence.evidence.read_trees`/`read_refs` are read-only on `repo_dir` and need no ingest,
   no evidence file and no product state (P11) — one import inside a method, the idiom
   `ports.py` already uses for every cross-package read.
2. `asf.tick.migrate.plan_task_records`, `writes_lines`, `task_like_headings` and
   `asf.record.plan_order.task_order` are pure functions of the plan's text (P7), so a kernel
   module can call them and `decide` stays decidable from `Facts` alone.
3. `write_new_item` writes every field a Task card needs, including `links` and `after`, and
   `mint_id` is the one id source (P9). Nothing in the kernel needs to invent an id.
4. `_has_work` already answers "is there a Task or Bug under this Feature" (P6), which is the
   mint's once-only guard and needs no new field on a card.
5. `apply`'s `ORDER` is the applied order, and the record's writes come before GitHub's and the launches'
   (`ORDER`, `decide.py:272-277`): a Story minted this tick is on the record before the Task that
   cites it is written.
6. `Item.plan` is read off `links: {plan: …}` (P10), so a Task minted with that link is dated by
   the still-needed gate exactly as a record-minted one is.
7. A failed port read never ends a tick: every optional read in `facts.py` is wrapped and falls
   back to empty (`facts.py:96-126`, `:200-219`), and a GitHub failure already plans blind
   (`loop.py:363-381`).
8. `config.doc_branches` is the document lanes' prefixes, from the product file, and
   `_lane_prefix` already reads one by name (`decide.py:1759-1760`) — `_doc_only` needs no new
   convention.

| D2 | **The kernel mints its own Tasks, from facts, through `decide` and `apply`** | Call `asf.record.plan_tasks.mint_plan_tasks` from the tick, the way `mint_inbox` is called | The record's minter is driven by the 0.1 evidence dict and finds plans through the ingest's `features` map (P8); calling it would drag `cmd_ingest` and the whole evidence pass into every kernel tick, and would mint from the same stale checkout this card is removing. | D3 | **The parsers are reused, not reimplemented**: `plan_task_records`, `writes_lines`, `task_like_headings`, `plan_order.task_order` | A kernel-local plan parser, as `asf/kernel/stories.py` is for Stories | Two readers of `### Task N:` would drift, and the drift would be silent: the kernel would mint a different Task set than the record's minter reads for the same plan. `stories.py` is local because the Stories *grammar* is the kernel's own contract with a spec; a plan's Task heading is already one shared shape, with a drift detector attached (P7). `asf/kernel/plans.py` is the thin, pure adapter over it |
| D4 | **One `MintTasks` action per Feature, carrying its whole Task list; the record mints the ids** | One `MintTask` action per Task, each carrying its id | An `after:` edge is "Task 2 runs after Task 1", and it can only become card ids once every id of that plan exists — which is why the record's minter writes the order after the loop. Reading the lanes off `config.doc_branches` covers both prefixes with no new literal (D8 precondition) |
| D6 | **A Feature whose plan is on the trunk is never launched to plan again** | Leave `_kind` alone: the Tasks will exist next tick and `_derived` will take over | For the tick between the mint and the next read of the facts — and for every tick of a Feature whose plan mints nothing — `_kind` says `plan`, so the kernel spends a seat re-planning a planned Feature, for ever (P5). The fact that stops it is the one this card already reads |
| D7 | **A landed plan that mints nothing makes its Feature Stuck on the operator** | Print one line and move on, as the record's minter does | A Feature whose plan landed, whose Tasks cannot be read and whose state is not Stuck is a Feature with no action and nothing in flight — `LIMBO`, which this kernel treats as a defect (`loop.py:9-12`). ## The design

### 1. `asf/kernel/ports.py` — the landed documents, off origin's trunk

`specs_landed`'s body is replaced; `plans_landed` is its twin. Both are slices of one memoised
read, so a tick fetches once and runs two batch processes whatever the two methods are called in.

```python
    def _landed_docs(self):
        """``{'spec': {F-id: text}, 'plan': {F-id: text}, 'paths': {F-id: plan path}}`` on
        ``origin/<main>``: one fetch, one tree batch, one blob batch. Every map empty for a trunk
        this host cannot read — never the working checkout, whose contents are the operator's and
        may hold a document no reviewer saw (F-0343)."""
        if self._docs is None:
            self._docs = self._read_landed()
        return self._docs

    def _read_landed(self):
        from asf import gitops, mutation_guard
        from asf.evidence import evidence
        out = {'spec': {}, 'plan': {}, 'paths': {}}
        repo = getattr(self.product, 'repo_dir', None)
        if not (repo and os.path.isdir(repo)):
            return out
        if not mutation_guard.is_active():  # a dry run reads the trunk it already has (D9)
            gitops.git(['fetch', '-q', 'origin', self.product.main], repo, timeout=120)
        rev = 'origin/%s' % self.product.main
        if not gitops.rev_parse(repo, rev):
            return out
        conv = self.product.conventions
        dirs = {kind: conv.doc_dir(kind) for kind in ('spec', 'plan')}
        trees = evidence.read_trees(['%s:%s' % (rev, d) for d in dirs.values()],
                                    product=self.product)
        want = {}
        for kind, d in dirs.items():
            for name in sorted(trees.get('%s:%s' % (rev, d)) or {}):
                iid = item_of_branch(name[:-3]) if name.endswith('.md') else None
                if iid and self._is_feature(iid):
                    want['%s:%s/%s' % (rev, d, name)] = (kind, iid)
        for ref, text in evidence.read_refs(sorted(want), product=self.product).items():
            kind, iid = want[ref]
            if text is not None:
                out[kind][iid] = text
        out['paths'].update({iid: ref.split(':', 1)[1]
                             for ref, (kind, iid) in want.items() if kind == 'plan'})
        return out

    def specs_landed(self):
        """Every Feature spec on origin's trunk: ``<specs_dir>/f-<n>.md`` -> ``F-<n>``."""
        return dict(self._landed_docs()['spec'])

    def plans_landed(self):
        """Every Feature plan on origin's trunk, and the path each was read from:
        ``({F-id: text}, {F-id: path})`` (F-0343)."""
        docs = self._landed_docs()
        return dict(docs['plan']), dict(docs['paths'])
```

`self._docs = None` joins `self._cards = None` in `__init__`. The one id reader is the existing
`item_of_branch` (`ports.py:114-118`), so `f-0343.md`, `F-0343.md` and `f-0343-slug.md` all name
`F-0343` exactly as they do today; a file naming no Feature on the record is skipped exactly as it
is today. `RecordPort` gains the two lines:

```python
    def plans_landed(self) -> tuple: ...                # ({Feature id -> plan text}, {id -> path})
    def mint_tasks(self, feature_id, plan, tasks) -> list: ...   # the Task ids written, in order
```

### 2. `asf/kernel/model.py` and `asf/kernel/facts.py` — the plan in the facts

`Facts` gains two fields beside `specs_landed`, documented in its docstring: `plans_landed`
(Feature id → plan text) and `plan_paths` (Feature id → the path on the trunk the text came from,
for the card's `links.plan` and for a Stuck reason that names it). `read_facts` fills them through
the same filter the specs get — on the record, and not Done:

```python
    specs = {fid: text for fid, text in record.specs_landed().items()
             if fid in items and items[fid].state is not State.DONE}
    read_plans = getattr(record, 'plans_landed', None)
    plans, plan_paths = read_plans() if read_plans else ({}, {})
    plans = {fid: text for fid, text in plans.items()
             if fid in items and items[fid].state is not State.DONE}
```

A port without `plans_landed` (an older fake, a product-free unit test) reads as "no plan landed",
which is exactly today's behaviour.

### 3. `asf/kernel/plans.py` — the Tasks a plan declares, and nothing else

def _doc_only(it, prs, config):

## Records

**Cards written.** One Task card per `### Task N:` of a landed plan, under
`<backlog>/tasks/T-<n>.md`, minted by `mint_id` under the claimant `asf-kernel`:
`type: task`, `parent:` the Feature, `title:` the heading's text, `decided: true`,
`links: {plan: <path on the trunk>}`, `writes:` the Task's `writes:`/`Files:` paths,
`stories:` the Story ids it cites that exist, `after:` the card ids of the Tasks it runs after,
`state: New`, the section's text (to 4000 characters) as `## Description`, and a History line
`- <date>: created (kernel: declared by the landed plan <path>) — shape: parent-feature → task`.
No other card's fields change: the Feature's state is derived, not written.

**The tick's log.** One `mint N Task(s) under <F-id> from <path>: <tid> <title>, …` line per
Feature, with `minted T-…, T-…` beneath it, in the record step before the GitHub actions
(`ORDER`). A dry run prints the same line prefixed `would`. The tick's publish commit counts the
new cards: `kernel: tick (N card(s))`.

**The plan file.** `state/<product>/kernel-plan.json` carries the `MintTasks` actions of the last
tick, as it carries every other action, so `asf kernel status` and the next tick's LIMBO
accounting see them.

**Stuck rows.** A Feature whose landed plan mints nothing is Stuck with `owner: operator` and a
reason naming the plan path (§5): one `stuck <F-id> (operator): plan <path> …` line in the tick's
log, the Stuck in that tick's plan file, and the row `asf kernel status` shows. Whether it also
reaches the card is the applier's existing rule, not this card's: a Feature with children is
derived every tick and never stored (`apply.py:549-552`), so the Stuck is re-derived from the
trunk on every tick instead — a Feature with no child yet has it written as every other Stuck is
(`stuck_reason`, `stuck_owner`, `stuck_since`).

**The wait ledger.** `state/<product>/kernel-waits.jsonl` gains the spells of the Tasks the mint
created, from the tick they are first Ready — the same rows any other Task's wait produces.

**Nothing new is kept.** No new state file, no new cache, no new ledger: the trunk read is
memoised for the life of one tick's port and thrown away with it.
