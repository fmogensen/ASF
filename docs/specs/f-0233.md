# F-0233 — the gate nobody can open

A Story is Closed when every Task under it is Closed **and it is in prod**
(`asf/evidence/closing.py:107`). A Feature, the same (`:122`, `:127`). "In prod" is
`_in_prod` (`asf/record/ingest.py:424`), and for a product that configures `deploy_sha` its
last clause is this:

```python
if ev.get('prod_mode') != 'auto':
    checked = ev.get('checked') or ()
    if not all(_child_landing(cid, task_ev, ev)[1] in checked for cid in child_ids):
        return False
```

`ev['checked']` has exactly one producer, `asf/evidence/evidence.py:869-877`:

```python
checked_file = checked_file if checked_file is not None else CHECKED_FILE
checked = set()
if os.path.exists(checked_file):
    with open(checked_file) as f:
        ...
```

and `CHECKED_FILE` is `~/.ASF/checked.txt` (`asf/evidence/evidence.py:45`), under a comment that
has been carrying its own admission since it was written:

```python
# An evidence-file path, not per-product config — no obvious Product field for it.
# TODO(config): no Product field for this yet.
```

**Nothing in this repository writes that file.** There is no `asf` subcommand that creates it, no
tick step that appends to it, no line of any guide that names it, no template that ships it. A
grep over the tree finds readers only: `evidence.py:45`, `:870`, `:872`, `ingest.py:434`,
`ingest.py:444`, and three tests that pass a deliberately absent path to stand the file down.

And `manual` is the default. `deploy.mode(product, 'prod')` (`asf/harvest/deploy.py:196-203`)
returns `'auto'` only for a product that says so or carries the deprecated `auto: true`;
everything else gets `'manual'`, as `docs/products.example.yaml:272` states plainly: *"prod's mode
defaults to manual."*

So: **every Story and every Feature of every product that configures a prod deploy and has not
opted into `auto` sits at `Resolved` forever.** Its Tasks are Closed, its merges are inside the
deployed sha, the board says `landed`, and the one remaining predicate reads a file that cannot
come into existence. There is no operator action that fixes it, because there is nothing to tell
the operator to do — `asf prod` prints a table headed **"ON PROD — check these"** whose empty case
literally reads `(no unticked customer-visible change on prod)` (`asf/views/prod.py:234-245`), and
that table never opens the tick list at all.

The gate was designed. `docs/specs/f-0051.md:14-17` describes it as intended behaviour, and
`:762` records the intent to retire it — *"a Feature … moving to Closed with `rule:
children-closed (probe: pass at <sha7>)` in its History, where before it waited on a tick in
`checked.txt`."* F-0051 has not landed: there is no `asf/probe`, no probe module, no probe test.
Until it does, the tick is the product's only "a person looked at production" signal, and it is a
signal nobody can send.

Reading `_in_prod` closely turns up three more holes behind the first, each of which would still
deadlock an item after a writer exists:

1. **The childless path can never pass in `manual` mode, and no tick reaches it.**
   `ingest.py:440-442` is `return ev.get('prod_mode') == 'auto' and …`. A Story or Feature with
   no children, whose own naming commit is deployed, is hard-`False` under `manual` — and because
   that branch never consults `checked` at all, ticking cannot release it. The `feature`
   `landed-green` rule (`closing.py:127`) needs `in_prod`, so such a Feature is stuck at
   `Resolved` permanently.

2. **A landing with no PR number can never be ticked.** `_child_landing`
   (`ingest.py:380-386`) returns `(sha, pr)`, and `pr` is `None` for a Task that landed as a
   direct trunk commit (the `iev.get('commit')` path, T-0366's case). `None in checked` is False
   for every possible `checked`. One PR-less child holds its whole Feature shut.

3. **One global file serves every product.** `~/.ASF/checked.txt` is not per-product, so PR #123
   of one product would tick PR #123 of another. The comment above it says as much and asks for a
   home.

This Feature builds the writer, gives the list a home and a format, closes the three holes, and
makes the two surfaces that already ask the operator to check — `asf prod` and the tick — tell the
truth about what is waiting and on whom.

## Decisions

**In scope**

- One module that owns the checked list: its path, its format, reading it, writing it, removing
  from it.
- `asf checked` — the operator's command: show what is waiting, tick a landing, tick everything
  one item waits on, undo a tick.
- `_in_prod` made passable: the childless `manual` path, and a PR-less landing.
- The list moved to a per-product home, with the legacy global file still read.
- The wait made visible: an evidence line on the held card, one `NEEDS OPERATOR` line per tick,
  and a `✓` column in `asf prod`'s ON PROD table.
- The two documents that describe the deploy modes gain the sentence that tells an operator the
  tick exists.

**Out of scope**

- F-0051's production probe. When it lands it replaces the human tick; this Feature does not
  anticipate its shape, and deliberately leaves `_in_prod`'s manual clause as the single place a
  later probe verdict would be substituted.
- Any change to `auto` mode. A product on `auto` is unaffected by every line of this Feature.
- Any change to Task closing. Tasks close on `landed-green` (`closing.py:102`), never on
  `in_prod`; nothing here touches them.
- An `asf doctor` row for the legacy file. `asf checked` naming it in its own output is enough,
  and a doctor row for a path that is read either way earns nothing.
- Deploy dispatch, deploy discovery, `deploy_sha` config shape.

**Preconditions**

- `env.state_dir(product)` (`asf/env.py:882`) exists and creates `~/.ASF/state/<product>/`; it is
  already the home of `approvals.jsonl` (`asf/approvals.py:598`, D14). The checked list joins it.
- `evidence.load` caches `discover()`'s result as JSON and round-trips `checked` through
  `sorted(...)` / `set(...)` (`asf/evidence/evidence.py:1645`, `:1649`). Widening the set beyond
  `int` therefore forces the wire format to change with it — mixed `int`/`str` would raise
  `TypeError` in `sorted`.
- `deploy.mode` is the one reader of `deploy_sha.prod.mode`; `evidence.discover` already puts its
  answer on `ev['prod_mode']` (`evidence.py:890`). No new config field is introduced.
- `asf prod` already computes the customer-visible landings and their PR numbers
  (`_check_rows`, `asf/views/prod.py:176-193`). The `✓` column is a join onto rows that exist.

**Choices**

| # | Choice | Against | Why |
|---|---|---|---|
| D1 | Keep the manual tick as a gate; build the writer | Delete the clause and let containment in `prod_sha` close everything | The tick is the only signal in the whole factory that a person looked at production. Deleting it would silently close every Feature of every deploying product on git evidence alone — exactly the failure `docs/specs/f-0051.md:19-25` was written about. The card's own words are that nothing *writes* the list, not that the list is wrong. |
| D2 | Only a person writes a tick; ASF never writes one for itself | A tick step that marks a landing checked once its deploy succeeds | A machine-written tick is not a check. It would make `manual` identical to `auto` while still reading as a human gate — worse than no gate, because the board would claim verification that never happened. |
| D3 | `~/.ASF/state/<product>/checked.txt` | Keep `~/.ASF/checked.txt`; or a field in the product file | Per-product is what the existing `TODO(config)` asks for and what PR-number collisions demand. Not a product-file field: this is operator state, not product configuration — the same reasoning that put `approvals.jsonl` under `state_dir` (D14). The legacy global path is still read and unioned in, so a hand-written file keeps working and nobody loses a tick. |
| D4 | A tick names a **landing**: a PR number *or* a landing sha | PR number only, as today | Hole 2. A Task that landed as a direct trunk commit has no PR, so a PR-keyed list can never speak for it, and one such child holds its Feature shut forever. `_child_landing` already returns both halves; the predicate reads either. |
| D5 | A childless item in `manual` mode is gated on **its own** landing, not hard-`False` | Leave `:440-442` as it is; or return `True` on containment alone | Hole 1 as written is unreachable-by-construction, which is a defect however the gate is judged. Making it symmetric with the child case — containment *and* a tick — is the reading that keeps `manual` meaning one thing everywhere. |
| D6 | `ev['checked']` becomes a set of **strings** on the wire and in memory | Keep `set[int]`; or add a second `checked_shas` key | `sorted()` over mixed `int`/`str` raises, and the evidence cache round-trips through JSON. One string set is one code path. A cache file written before this change holds ints; `load` normalises with `{str(x) for x in …}`, so no cache needs clearing. |
| D7 | A sha argument is resolved to the full trunk sha before it is written; a hand-written short sha matches by prefix, minimum 7 | Exact match only | The writer always produces full shas, so matching is exact in practice; the prefix rule exists only so an operator who typed `git log --oneline` into the file by hand is not silently ignored. Under 7 characters is not a sha, it is a typo, and is refused. |
| D8 | `#<digits>` is a tick; `#` followed by anything else is a comment; `--undo` deletes a line | Keep today's `\s*#?(\d+)` for everything | Today's regex reads `#869 was broken` as a tick of 869, so an operator cannot comment a tick out — the one editing gesture a plain-text ledger invites is the one that silently does nothing. `#<digits>` stays a tick for back-compatibility with any hand-written file; real comments now work; un-ticking has a command instead of a trap. |
| D9 | The tick's operator line is emitted from `step_harvest.deploy_pass`, after the `deploy:` lines | A new tick step; or a line from `asf ingest` | It is where the deploy's own lines already print (`asf/tick/step_harvest.py:141-149`), and it is the position `docs/specs/f-0051.md:756` reserved for exactly this class of line. No new step, no new ordering question. |
| D10 | `_in_prod` keeps its signature's shape — the predicate stays in one function | Split the manual gate into its own module | The next Feature to touch this is F-0051, which substitutes a probe verdict for the human tick. One function to change is the point. |

## The design

### 1. `asf/evidence/checked.py` — the list's one owner (new)

The only module that knows where the file is or what a line means. `evidence.py` stops owning the
path and calls this instead.

```python
LEGACY_PATH = os.path.join(env.ASF_HOME, 'checked.txt')   # read, never written

def path(product):
    """``~/.ASF/state/<product>/checked.txt`` — the operator's ticks for this product."""

def read(product=None, checked_file=None):
    """``set[str]`` of ticked landing tokens: PR numbers as decimal strings, landing shas as
    lowercase hex. The product's own file unioned with :data:`LEGACY_PATH` (D3)."""

def matches(checked, pr, sha):
    """True when ``checked`` carries this landing: ``str(pr)``, or a ticked token that is a
    prefix of ``sha`` of at least 7 characters (D4, D7)."""

def add(product, landings):
    """Append one line per landing not already ticked; return the ones written. Idempotent."""

def remove(product, tokens):
    """Rewrite the product's file without the lines naming ``tokens``; return the ones dropped.
    The legacy file is never rewritten (D3)."""
```

**The file format.** Append-only in normal use, one landing per line, written by `add`:

```
# asf checked — landings verified on production by hand. `asf checked --help`
2026-09-29T21:43Z  F-0119  #869   feat: conversations land in the sidebar
2026-09-30T08:02Z  F-0120  a1b2c3d4e5f6a7b8c9d0e1f2a3b4c5d6e7f8a9b0  chore: the direct landing
```

A line's first non-blank token decides (D8): `#<digits>` or `<digits>` is a PR tick;
`[0-9a-f]{7,40}` is a sha tick; anything else — including a `#` that is not followed by a digit —
is a comment. Everything after the first token on a tick line is a note for the person reading the
file and is never parsed.

### 2. `asf/evidence/evidence.py` — the reader moves out

`CHECKED_FILE` is deleted along with its `TODO(config)`. `discover(product, checked_file=None)`
keeps its parameter (three tests pass it, `tests/test_evidence.py:515`, `:945`,
`tests/test_doc_lane_landing.py:88`) and delegates:

```python
"checked": checked_mod.read(product, checked_file=checked_file),
```

`load` (`:1645`, `:1649`) serialises `sorted(data["checked"])` — now a list of strings — and
normalises on read for a cache written before this change (D6):

```python
data["checked"] = {str(x) for x in data["checked"]}
```

### 3. `asf/record/ingest.py` — the gate becomes passable

`_in_prod` gains `own_pr=None` and reads the list through `checked.matches`:

```python
def _in_prod(child_ids, task_ev, ev, merged=None, own_sha='', own_pr=None, reach=None):
    if not _deploys(ev):
        return True
    if not ev.get('prod_sha'):
        return False
    ticked = ev.get('checked') or frozenset()
    manual = ev.get('prod_mode') != 'auto'
    if not child_ids:
        if not own_sha or not (reach or _prod_reach(ev))(own_sha):
            return False
        return not manual or checked.matches(ticked, own_pr, own_sha)      # D5
    if manual:
        for cid in child_ids:
            sha, pr = _child_landing(cid, task_ev, ev)
            if not checked.matches(ticked, pr, sha):                        # D4
                return False
    return bool(_merged_in_prod(child_ids, task_ev, ev, reach) if merged is None else merged)
```

The two childless call sites (`ingest.py:884-885`, `:909`) pass `own_pr=iev.get('pr')`. `auto`
mode reaches an identical answer to today's on every input — the `manual` guard is the only new
branch.

`_in_prod`'s docstring is rewritten to say where the tick comes from now: *"`manual` — a person
also ticked each child's landing into the product's checked list (`asf checked`)."*

### 4. The wait is named

A held item currently carries no line explaining itself. A new helper returns the landings one
item is still waiting on:

```python
def awaiting_tick(iid, child_ids, task_ev, ev, own_sha='', own_pr=None):
    """[(pr, sha)] — the landings of `iid` that are inside the deploy but not yet ticked. Empty
    for a product on `auto`, one that deploys nothing, or a deploy not yet reached."""
```

When it is non-empty, `settle`'s evidence lines for that Story or Feature gain one line:

```
waiting on your check: #869, #871 — asf checked --item F-0119
```

and `asf/tick/step_harvest.py:141 deploy_pass`, immediately after the `deploy:` lines (D9), emits
one line per held item:

```
NEEDS OPERATOR: F-0119 is on prod and waiting on your check — asf checked --item F-0119
```

Items whose landings are not yet inside the deployed sha are not named: they are waiting on the
deploy, not on a person.

### 5. `asf checked` — the command

Registered in `asf/cli.py` beside `asf prod` (`cli.py:310`), with `--product`.

```
asf checked                      # what is waiting, per item, with its landings
asf checked 869 871              # tick those PRs
asf checked a1b2c3d              # tick a landing sha (resolved to full before writing, D7)
asf checked --item F-0119        # tick every landing F-0119 is waiting on
asf checked --undo 869           # remove a tick
```

Bare `asf checked` is the default and is read-only:

```
CHECKED — landings on prod waiting on your check

| Item | Landing | What | Deployed |
|---|---|---|---|
| F-0119 | #869 | feat: conversations land in the sidebar | yes |
| F-0119 | #871 | feat: the unread badge | yes |
| S-0218 | a1b2c3d | chore: the direct landing | yes |

3 waiting · 12 ticked · ~/.ASF/state/asf/checked.txt
Tick them with: asf checked --item F-0119
```

With nothing waiting it prints `CHECKED — nothing is waiting on your check` and the same footer.
When the legacy `~/.ASF/checked.txt` exists, one further line names it and says it is read, never
written. A write prints one line per landing ticked and one per landing already ticked; ticking
something no item is waiting on is allowed and says so — the list is the operator's, not the
record's.

Exit codes: `0` always for a successful read or write; `2` for an argument that is neither a PR
number nor a resolvable sha (D7).

### 6. `asf prod` — the ON PROD table stops lying

`_check_rows` (`asf/views/prod.py:176-193`) takes the checked set and returns a fifth field per
row; `render` (`:234-246`) gains the column:

```
| Target | What | State | PR | ✓ |
|---|---|---|---|---|
| prod | feat: conversations land in the sidebar | live since 08:02 | #869 | needs your ✓ |
| prod | feat: the unread badge | live since 08:02 | #871 | ✓ |
| prod | fix: the avatar crop | NOT LIVE — merged, prod `a1b2c3d4e` lacks it | #873 | |
```

A `NOT LIVE` row's `✓` is blank: there is nothing on prod to check yet. The empty case's
`(no unticked customer-visible change on prod)` becomes true for the first time, because the
row set it describes is now filtered by the list it names.

### 7. The documents

`docs/products.example.yaml:265-272`, where the modes are described, gains one clause on
`manual`: that a Story or Feature of a `manual` product also waits for `asf checked`, and that
`auto` needs no tick. `docs/guide/operating.md` gains `asf checked` beside `asf prod` in the
operator's command list, with the one sentence that says what a tick means: *you opened
production and the change is there and works.*

## Records

**Files**

| Path | What it holds |
|---|---|
| `~/.ASF/state/<product>/checked.txt` | the product's ticks: one line per landing, `<iso ts>  <item>  <token>  <note>`, newest last. Created by `asf checked` on first write, never by a read. |
| `~/.ASF/checked.txt` | the legacy global list. Read and unioned in; never written, never rewritten, never deleted. |
| `~/.ASF/state/<product>/cache/evidence.json` | `checked` is now a sorted list of strings. A file written before this change holds ints and is normalised on read; no cache is invalidated. |

**Rows**

| Where | What |
|---|---|
| the held Story's or Feature's card, `evidence:` | `waiting on your check: #869, #871 — asf checked --item F-0119`, written by ingest, removed by the ingest after the tick |
| the same card, `## History` | nothing new — the existing `state Resolved → Closed (rule: children-closed)` line already records the transition the tick unblocks |
| `asf prod`'s ON PROD table | a fifth column, `✓` \| `needs your ✓` \| blank |
| `asf checked`'s own table | `Item`, `Landing`, `What`, `Deployed` — one row per waiting landing |

**Events**

| Event | When |
|---|---|
| `NEEDS OPERATOR: <id> is on prod and waiting on your check — asf checked --item <id>` | one per held item, every tick, from `step_harvest.deploy_pass` after the `deploy:` lines |
| `feature-on-prod` (`asf/record/ingest.py:37`) | unchanged — it is keyed on the stage, which `merged_in_prod` already decides without the tick (`ingest.py:912`) |

**What is never written**

No tick is ever written by ASF itself (D2). No product name, no operator path and no worker
account name enters the product repository: the list lives under `~/.ASF/state/`, and the lines
that name it in `asf prod`, `asf checked` and the tick are console output, not files in the tree.

## Stories

- S: The checked list has one owner, a per-product home and a format a person can read and edit — acceptance: `python3 -m unittest -v tests.test_checked.TheList`
- S: `asf checked` writes it — by PR, by sha, by item, idempotently, with an undo — acceptance: `python3 -m unittest -v tests.test_checked.TheCommand`
- S: `_in_prod` can be satisfied — a childless item and a PR-less landing are tickable, and a ticked Feature closes — acceptance: `python3 -m unittest -v tests.test_ingest tests.test_closing tests.test_evidence`
- S: A Story or Feature held only by a missing tick says so, on its card and once per tick — acceptance: `python3 -m unittest -v tests.test_ingest tests.test_checked.TheTickLine`
- S: `asf prod`'s "ON PROD — check these" table reads the list it names — acceptance: `python3 -m unittest -v tests.test_prod_view`
