# F-0165 — 120 s is the right bound for a ref push and the wrong one for a publish

`e2a1803` gave every factory `git push` one clock: `git.push_timeout_s`, default 120 s, its whole
process group killed past it (`asf/gitpush.py:59-79`). It was written for a push that runs no hook —
a product's `archive/…` head sat 8+ minutes in its pre-push hook inside a tick's health step, and
finished sessions piled up behind it — and `--no-verify` for exactly those pushes landed in the same
commit.

The clock is shared with the pushes that *do* run the hook, and there it is a publish killer. Two
real ones (a product's `cloud/T-0091`, and its `docs/brief-templates-backlog-block`) ran the
product's pre-push hook past 120 s on a host at load ~50, were killed with `push timed out after
120s … left as it was`, and session work stopped publishing until the operator set
`conventions.git.push_timeout_s: 900` by hand. That hand fix works and is the wrong shape: it also
hands 900 s to the archive pushes and branch deletes the 120 s was for, so the two failure modes
`e2a1803` was balancing are now both re-armed on one dial.

The two kinds of push are already named and already distinguished at every call site — `refs_only`
picks `--no-verify` (`asf/gitpush.py:39-41`), and 13 of the 20 call sites in `asf/` pass it. What is
missing is that the *budget* does not read the same flag. A hookless push is bounded by the network
and needs seconds; a hooked push is bounded by the product's lint, typecheck and build, and needs
whatever that costs on a loaded host. One number cannot be both.

This card splits the number, points every call site at the kind it is, and puts the measured seconds
on the publish line so the next operator who has to raise the budget raises it from evidence rather
than from a guess.

### In

- **Two budgets where there was one**, both documented defaults in `asf/conventions.py`:
  `DEFAULT_PUSH_TIMEOUT_S = 900` (was 120) for a **hooked** push, and a new
  `DEFAULT_REF_PUSH_TIMEOUT_S = 120` for a **hookless** one.
- **Two yaml keys**: `git.push_timeout_s` keeps its name and becomes the hooked budget (C2);
  `git.ref_push_timeout_s` is new. One `GIT_KEYS` row and one field each (P5).
- **`push_timeout(conv=None, refs_only=False)`** — the kind selects the field. One resolver.
- **`conv=` on `gitpush.push`**, so the budget is resolved *inside* `gitpush` from the same
  `refs_only` that decides `--no-verify`, and `refs_only` is spelled once per call site (C4).
- **All 11 call sites that resolve their own budget** (P3) pass `conv=` instead: `lane.py` ×4,

- **`lifecycle.publish` gains `conv=None`** and keeps `push_timeout_s` as an explicit override of

- **The hook's seconds on the publish line**: `published <branch> at <head> in <n.n>s`, measured in

- **The timed-out line names the key to raise**: `… — left as it was (raise git.push_timeout_s)`
  or `(raise git.ref_push_timeout_s)`, chosen by `refs_only` and appended so all three shipped

- **The four hooked pushes that read no conventions** (P4) take the new hooked default: 900 s
  instead of 120 s, still unconfigurable (C8).
- **The docstrings that state the old single number**: `asf/gitpush.py`'s module header and
  `push_timeout`'s summary, `asf/conventions.py:26`'s yaml example (whose `push_timeout_s: 300`
  now reads as advice to *lower* the budget), `lifecycle.publish`'s paragraph on the timeout, and
  `retention.delete`'s.
- **Four test edits and three new test classes** (P10, P12): the two exact-equality publish-line
  assertions, `tests/test_gitpush.py:83-90`'s defaults assertion, and `tests/test_lane.py:1301`'s
  key.

### Out

- **Scaling the budget with a measured hook p90.** The card offers it as an alternative and it is
  refused, with a reason, in C9. No store of per-product hook durations is added, no percentile is
  computed, and `ci_queue._percentile` is not reused.
- **Threading the conventions into `harvest.push_ff`, `harvest.push_branch`, `metrics`'s changelog
  push and `tick.shadow`** (P4). Four signatures, four call chains, and none of them is the push
  the card is about; each takes the new default instead (C8). Naming "every factory push reads the
  product's number" as a separate card is the honest scope, and this document says so rather than
  half-doing it.
- **Lowering the hookless budget below 120 s.** The card allows 60–120; 120 is kept and nothing
  about a ref push's behaviour changes (C1).
- **A doctor or status row for a slow push**, in the shape of `lane.gate_slow_line` /
  `lane.ref_push_line`. The timeout line naming the key to raise (C7) is what an operator needs at
  the moment they need it; a row needs a state file, a threshold and a "two in a row" rule, and it
  is a card of its own.
- **Folding the lane's four hand-timed `lane: push <ref> <n>s` lines onto `p.seconds`**
  (`lane.py:416`, `:461`, `:1614`, `:1624`). Real duplication, zero behaviour change, four files'
  worth of diff in the modules most in flight. The attribute exists after this card; using it
  there is a tidy, not this card.
- **`git.read_timeout_s`** and anything else on the read half — F-0013's (P19).
- **`harvest.gate_timeout_s`**, `tick.step_timeout_s` and the CI gate's clocks. A gate is a
  process this factory runs; a push is a process a *product's* hook runs inside. One is cited as
  the precedent for a number (P17, C3), none is read or changed.
- **The operator's hand fix.** `conventions.git.push_timeout_s: 900` on the affected product
  becomes exactly the new default and can be deleted; whether it is, is the operator's call
  (`NEEDS OPERATOR`, Records).
- **Any new command, event, record row or state file.** Two constants, two keys, one parameter, one
  attribute, one line.

## The design

Five files change in `asf/`, four test modules in `tests/`. No new module, no new file.

### 1. `asf/conventions.py` — two numbers, two keys

`DEFAULT_PUSH_TIMEOUT_S`'s docstring and value change; a sibling is added beside it:

```python
#: The most seconds one factory ``git push`` that **runs the product's pre-push hook** may take
#: (:mod:`asf.gitpush`) before its process group is killed: the ref is logged and left as it was,
#: and the tick goes on. The hook lints, typechecks and builds — on a loaded host that is minutes,
#: and 120 s killed real publishes (F-0165), so this is the hook's budget, not the network's.
#: One step's worth of time, the same default as ``tick.step_timeout_s``. Spelt
#: ``git: {push_timeout_s: …}`` in the yaml.
DEFAULT_PUSH_TIMEOUT_S = 900

#: The most seconds one factory ``git push`` that **skips the hook** (``--no-verify``: an
#: ``archive/…`` head, a branch delete, a tag, a brief or a reservation ref — ``refs_only``) may
#: take. Nothing but the network is in it, so it is short on purpose: a ref push that hangs holds
#: the tick's own housekeeping, and a product's archive push once sat 8+ minutes in its hook inside
#: the health step. Spelt ``git: {ref_push_timeout_s: …}`` in the yaml.
DEFAULT_REF_PUSH_TIMEOUT_S = 120
```

`GIT_KEYS` gains its row and the dataclass its field:

```python
GIT_KEYS = {'push_timeout_s': 'push_timeout_s', 'ref_push_timeout_s': 'ref_push_timeout_s'}
```

```python
    #: ``git.push_timeout_s`` — a push that runs the hook (:data:`DEFAULT_PUSH_TIMEOUT_S`).
    push_timeout_s: int = DEFAULT_PUSH_TIMEOUT_S
    #: ``git.ref_push_timeout_s`` — a push that skips it (:data:`DEFAULT_REF_PUSH_TIMEOUT_S`).
    ref_push_timeout_s: int = DEFAULT_REF_PUSH_TIMEOUT_S
```

and the module header's yaml example (`:26-27`) stops advising a number below the default:

```yaml
      git:
        push_timeout_s: 1800      # default 900: a factory push that runs the product's pre-push
                                  # hook is killed past it, the ref logged and left as it was
        ref_push_timeout_s: 60    # default 120: the same for a push that skips the hook
                                  # (--no-verify: an archive head, a delete, a tag) — network only
```

Nothing else in the tree spells either number (P7).

### 2. `asf/gitpush.py` — one resolver, the kind, the seconds, the key

```python
def push_timeout(conv=None, refs_only=False):
    """The seconds one push may take, at least 1 — which budget depends on whether the product's
    pre-push hook runs in it (``refs_only``, the same flag that decides ``--no-verify``):

    * a **hooked** push — a session's branch published, the trunk, a lane rewrite — is bounded by
      the product's own lint, typecheck and build: ``conventions.git.push_timeout_s``
      (:data:`asf.conventions.DEFAULT_PUSH_TIMEOUT_S`, 900 s). One number for both kinds meant
      120 s, and 120 s killed real publishes on a loaded host (F-0165).
    * a **hookless** push — an archive head, a delete, a tag, a brief or a reservation ref — has
      only the network in it: ``conventions.git.ref_push_timeout_s``
      (:data:`asf.conventions.DEFAULT_REF_PUSH_TIMEOUT_S`, 120 s), short on purpose.
    """
    key = 'ref_push_timeout_s' if refs_only else 'push_timeout_s'
    default = DEFAULT_REF_PUSH_TIMEOUT_S if refs_only else DEFAULT_PUSH_TIMEOUT_S
    try:
        return max(1, int(getattr(conv, key, None) or default))
    except (TypeError, ValueError):
        return default
```

`push` gains `conv` and resolves its own budget, so `refs_only` is written once per call site:

```python

    push's own ``refs_only``, so the flag that skips the hook is the flag that sizes the clock and

    ``stderr`` names the refs, and a line naming the key to raise goes to ``log``.
    ``seconds`` on the returned process is how long it took, timed out or not."""

    ...
```

```python
def _timed(result, started):
    """``result`` with ``seconds`` on it: how long the push took, the product's hook included. The
    factory's own bound is a guess until somebody measures the hook it is bounding (F-0165), so
    every push reports its own; :func:`asf.workers.lifecycle.publish` puts it on its line."""
    result.seconds = round(time.monotonic() - started, 1)
```

```python
def test_no_call_site_resolves_its_own_push_budget(self):
    """The flag that skips the hook is the flag that sizes the clock: a caller that computes a
    timeout can hand a hooked number to a ref push, which is F-0165's bug."""
    resolvers, explicit = [], []
    for path in sorted(_py_files('asf')):
        tree = ast.parse(open(path, encoding='utf-8').read(), filename=path)
        for node in ast.walk(tree):
            if not isinstance(node, ast.Call):
                continue
            name = getattr(node.func, 'attr', None) or getattr(node.func, 'id', None)
            if name == 'push_timeout' and path != os.path.join('asf', 'gitpush.py'):
                resolvers.append(f'{path}:{node.lineno}')
            if name == 'push' and getattr(getattr(node.func, 'value', None), 'id', '') == 'gitpush':
                explicit += [f'{path}:{node.lineno}' for k in node.keywords if k.arg == 'timeout']
    self.assertEqual(resolvers, [], 'push_timeout is gitpush\'s own: pass conv= instead')
    self.assertEqual(len(explicit), 1, explicit)      # publish's documented push_timeout_s
    self.assertTrue(explicit[0].startswith(os.path.join('asf', 'workers', 'lifecycle.py')), explicit)
```
