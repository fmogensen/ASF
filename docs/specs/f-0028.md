# F-0028 — Prompt budget: four token dimensions itemised, never summed, with a cap per job

Epic: E-0001 — ASF 0.1 — a working factory. Branch: `spec/F-0028`.

The card, as the requirement: *the prototype recorded 11.6 M input tokens for two phases of one
run because the four token dimensions were never separated. `metrics/sessions` carries input,
output, cache-read and cache-write per session; caps are set per job kind; the scorecard shows
tokens per Feature beside the money.*

Today the factory records money and nothing else. A session's result line is read for
`total_cost_usd` and `duration_ms` (`asf/metrics/metrics.py:906,900`), the `sessions` schema has
no token key at all (`asf/metrics/metrics.py:120-126`), and the scorecard's cost table ends at a
USD column (`asf/metrics/metrics.py:472-498`). Nothing bounds a session's spend: a run ends when
it writes a result, when its pid dies, or when it goes silent past `stage_limits.silent_min`
(`asf/workers/stall.py:62-74`) — none of which is a spend limit. A session that reads the whole
repository on every turn burns until it finishes.

After this change every session line carries four separate numbers, a run over its cap is stopped
by the factory and ends with a cap result line, and the scorecard's Feature rows show the four
numbers beside the money. There is no fifth number anywhere: the four are never added together,
because the sum is what hid the 11.6 M in the first place.

## Decisions

### In

- **The meter** — a new leaf module `asf/tokens.py`: the four dimension names, how a usage object
  maps onto them, one pass over a job log that returns the run's result *and* its per-dimension
  tally, the cap table, and the verdict. It is the only module that reads a `usage` key; no
  caller reads one raw.
- **Four keys on the `sessions` event** — `tokens_input`, `tokens_output`, `tokens_cache_read`,
  `tokens_cache_write`, each `int` or `null`, on every line `asf metrics backfill` appends.
- **Caps per job kind** — a built-in table in `asf/tokens.py` and a `token_caps:` block in
  `products/<name>.yaml` that narrows or widens it, keyed by the stream's own job kinds
  (`asf/metrics/metrics.py:37-38`) with a `default` row. One cap per dimension per kind. A run is
  over its cap when **any one dimension** is over that dimension's cap.
- **The stop** — `asf.workers.stall.capped(product)`: over its cap, a live run is signalled dead
  (its own process group, identity-checked), a cap result line is appended to its job log, and
  `capped` is written on its registry line. The tick's `health` step calls it before
  `workers.health`, so the same tick ends the run with `end_reason: failed: token cap`.
- **The scorecard** — `cost_table` gains four columns beside USD; `scorecard_rows` gains one
  `tokens` row itemising the day's four numbers and how many runs were capped.
- **The item's `cost:` block** — four flat keys beside `usd`, written by `write_costs` exactly as
  `usd` is, so a Feature's card carries what its subtree spent in tokens.
- **Doctor** — one `token-caps` row per finding, `required=False`, naming the resolved numbers
  or the refusal.
- `docs/products.example.yaml` and `sample/product.yaml` carry a `token_caps:` block;
  `PRODUCT_FIELDS` learns the key.

### Out

- **A total.** No key, column, row or function anywhere adds two dimensions together. Four
  numbers, always four, named.
- **Money from tokens.** A USD price table per model is a later card (prior art row 17). A capped
  run's `usd` is `null` — nothing computed the cost, because the runtime never wrote a result of
  its own. The four token numbers are what that run leaves behind, which is the point.
- **Rewriting history.** `append_event` is idempotent on `(task, ts)`
  (`asf/metrics/metrics.py:261-262`), so a session line already in the stream keeps its shape
  forever. Lines written before this change carry no token keys and are read as `null`.
- **A live tally in `asf sessions`.** The operator's table of running sessions is unchanged. The
  cap is what bounds a runaway, not a table someone must happen to be watching. A later card.
- **A per-tool-call bound.** See D7: the cap is checked once per `health` tick, so the real bound
  is the cap plus one tick's spend. Tightening that needs a hook, which is its own card.
- **Capping CI minutes, or anything that is not an agent session.** `ci` and `ticks` are
  untouched.
- **Changing what a capped run does next.** A capped run ends `failed: token cap`, and what the
  feeder does with a failed run is the feeder's existing business (D9).

### Preconditions

Checked against `origin/main` at `9790fdb`.

- A session's stdout is streamed to `~/.ASF/logs/jobs/<product>/<job>.jsonl` one JSON object per
  line, a run opening with `system`/`init` and closing with `result`
  (`asf/workers/runtime.py:194-203`, `:126-153`). The meter's one pass reuses that framing.
- `runtime.read_result` already resets at each `init`, so "the log's last run" is a settled
  notion (`asf/workers/runtime.py:126-153`, B-0028). The meter resets on the same line.
- Sessions are launched with `start_new_session=True` (`asf/workers/runtime.py:201`), so a run's
  pid is its own process-group leader and the group can be signalled without touching the tick.
- `observe.identity_alive` (`asf/workers/observe.py`, F-0076 D11) answers "is the process at this
  pid still this run" — the guard the stop needs before it signals anything.
- `runtime.failure_reason` / `result_ok` / `lifecycle.judge` already turn a not-ok result into
  `failed: <signature>` (`asf/workers/runtime.py:155-176`, `asf/workers/lifecycle.py:461-486`).
  The cap needs one new signature, not a new lifecycle state.
- `frontmatter` supports exactly **one** level of `key:` nesting
  (`asf/record/frontmatter.py:1-10`), so the item's `cost:` gains four flat keys, never a nested
  `tokens:` map.
- `env.PRODUCT_FIELDS` rejects an unknown top-level key (`asf/env.py:222-227`), so `token_caps`
  must be added there or every product that uses it fails to load.
- `env._scalar` parses a bare integer and leaves a bare `off` as the string `'off'`
  (`asf/env.py:32-42`) — the two forms a cap value takes.
- `doctor.run` appends capacity findings with `required=False` so they never turn doctor red
  (`asf/doctor.py:448-449`). The token-caps row follows it exactly.

### Choices

| # | Choice | Chosen | Against | Why |
|---|---|---|---|---|
| D1 | The four dimension names | `input`, `output`, `cache_read`, `cache_write` | the wire names (`input_tokens`, `cache_creation_input_tokens`, …) | The wire names are the vendor's and two of them do not say what they hold. One name per dimension, used identically in the config key, the event key, the column and the cap. `asf/tokens.py` owns the one map from wire key to dimension, so a vendor that renames a key is a one-line change. |
| D2 | Where the dimensions come from | the result line's own `usage` when it carries at least one of the four keys; otherwise the per-dimension sum over the run's `assistant` lines' `message.usage` | assistant lines only; result only | The result's usage is the runtime's own count and is what a finished session should be read from. A **capped** run has no runtime result — the factory wrote its result — so the assistant sum is the only count there is. Both paths come out of the same single pass. |
| D3 | The event's shape | four flat keys, `tokens_input` … `tokens_cache_write` | a nested `tokens: {…}` object | `_apply` type-checks per key (`asf/metrics/metrics.py:139-157`); a nested object would be checked as `dict` and nothing inside it. Flat also makes "never summed" structural: there is no object to grow a `total` key on, and the schema's unknown-key refusal rejects one if someone tries. |
| D4 | A missing or unparsable number | `null` for that dimension, never `0` | 0 | `0` is a measurement ("this run read nothing from cache"); `null` is the absence of one. Summing a `null` as `0` is how a dimension goes missing, which is this card. A Feature's column is `—` when no session under it carried that dimension. |
| D5 | Cap vocabulary | the `sessions` stream's job kinds (`spec`, `review`, `fix`, `code`, `plan`, `preflight`, `probe`, `rebase`, `relaunch`, `launch`, `tick`, `other`) plus `default` | the registry's row kinds (`fix-bug`, `task`, `adjudicate`, …) | One vocabulary for the cap, the scorecard and the event, so an operator who reads "spec sessions cost this" sets the cap on the same word. `metrics.session_kind` already normalises a registry row into it (`asf/metrics/metrics.py:886-889`). |
| D6 | An unconfigured product | bounded by a built-in default table, which `token_caps:` widens or narrows; `off` disables one cap explicitly | unbounded (today), or refuse to run without a block | Unbounded *is* the defect. Refusing to launch would stop a factory over a number nobody has evidence for yet. The approvals matrix is the precedent: a closed catalogue with defaults in code, widened or narrowed in one file (`asf/approvals.py`, F-0031). |
| D7 | Where the cap is enforced | the tick's `health` step, over the live registry | a `PreToolUse` hook on every tool call; the wave at launch | A hook fires per tool call and would have to re-read the transcript each time; and it can only refuse one call, not end a run — an agent refused every call flails instead of stopping. The `health` step already reads each live log for its result (`asf/workers/health.py:289` → `lifecycle.gather`), so the meter is the same pass at the same cadence. The cost is the looseness D7 names in **Out**: the bound is the cap plus one tick. |
| D8 | How a capped run ends | the factory appends a `result` line of its own to the job log and signals the process group | kill the pid and leave the log resultless; ask the session to stop | Every reader downstream — `read_result`, `judge`, `session_event`, the `sessions` view — already knows how to read a result line. Killing without one produces `dead pid`, which reads as a crash and buys the run a cold retry (`asf/tick/step_health.py:66-85`) — the factory would relaunch the very run it just stopped for spending too much. |
| D9 | What marks the cap on the result | a structured `asf: {cap: {…}}` object on the result record, read by `failure_reason` before any text | a text marker (`ASF CAP: …`) matched by regex | A session's own report text lands in `result`, so a text marker is forgeable by the thing being capped — B-0084's rule: a leaked marker bypasses nothing. The text still says it, for a human reading the log; the *judgement* rests on the structured field, which only the factory writes. |
| D10 | The unit the cap applies to | one **run** — the log's last run, reset at each `init` | the job across all its runs; the item across all its sessions | The meter can only count what one log's run holds, and it is a run that gets stopped. A job that is relaunched gets a fresh cap, which is correct: the relaunch is a new spend decision. The item's total spend is the scorecard's job, and it is now four columns wide. |
| D11 | A capped run's next move | `failed: token cap`, and nothing else | hold it and hand it back like a red gate (`lifecycle.hold`) | A hold hands the branch back to a *new session on the same worktree*, which is exactly the spend that was just stopped. `failed` leaves the run ended with its work in place; the feeder's existing attempt and round counting decides what happens next, as it does for any other failure. Changing that is a feeder card, not this one. |
| D12 | Built-in default numbers | `input` 8 000 000, `output` 1 000 000, `cache_read` 400 000 000, `cache_write` 40 000 000 per run | numbers derived from the factory's own sessions | There are none yet — this change is what starts recording them. These are **runaway ceilings, not budgets**: below the prototype's measured 12 318 685-input-token phase (`docs/research/prior-art-prototype.md:49`) and far above any session the factory has run. The operator narrows them per kind once `metrics/sessions` holds a week, and doctor prints the resolved numbers every run so they are never invisible. |
| D13 | A malformed `token_caps:` block | refuse the block: one `TokenCapError` naming every bad entry; the `health` step prints it and **stops nothing** this tick; doctor shows it | fall back to the built-in defaults silently | A config error must not become a licence to kill sessions, and it must not become a licence to spend either — so: no stop, loud line, every other health duty unchanged. Doctor is where it is meant to be read. |
| D14 | Signal | `SIGTERM` to the process group, then `SIGKILL` after `stop_grace_s` (default 10 s) if the pid is still there | `SIGKILL` at once | A `SIGTERM` gives the runtime its chance to flush what it has written. The group, not the pid, because a session's tool calls are its children and a killed leader leaves them running. Nothing is signalled unless `observe.identity_alive` says that pid is still this run. |

## The design

### `asf/tokens.py` (new)

The leaf module. Imports `asf.env` only, so both `asf.metrics` and `asf.workers` may import it.

```python
DIMENSIONS = ('input', 'output', 'cache_read', 'cache_write')

#: dimension -> the key a usage object carries it under (D1).
USAGE_KEYS = {'input': 'input_tokens', 'output': 'output_tokens',
              'cache_read': 'cache_read_input_tokens',
              'cache_write': 'cache_creation_input_tokens'}

#: runaway ceilings per run, not budgets (D12). `token_caps:` narrows or widens them.
DEFAULT_CAPS = {'default': {'input': 8_000_000, 'output': 1_000_000,
                            'cache_read': 400_000_000, 'cache_write': 40_000_000}}

STOP_GRACE_S = 10
```

- `usage_of(rec) -> {dimension: int|None}` — the four dimensions of one stream-json record:
  `rec['message']['usage']` for an `assistant` line, `rec['usage']` for a `result` line, `{}`
  otherwise. A key that is missing or not a number is `None` for that dimension (D4); negative is
  `None` too.
- `Meter` — a dataclass: `result` (the last run's result record, or `None`), `by_dim`
  (`{dimension: int|None}`), `lines` (records read), `runs` (how many `init` lines were seen).
- `meter(log_path) -> Meter` — **one** pass over the log. An `init` line resets `result` and the
  running tally (the run boundary, `asf/workers/runtime.py:126-153`); an `assistant` line adds
  each known dimension into the tally; a `result` line is kept as the result. At the end, when the
  result's own `usage` carries at least one of the four keys, it *replaces* the tally
  wholesale — the runtime's count wins over the sum of turns (D2). A missing file, an unreadable
  line or a non-dict record is skipped; the function never raises.
- `of_result(rec) -> {dimension: int|None}` — `usage_of` on a result record, for a caller that
  already has one and wants no second pass.
- `caps(product) -> {kind: {dimension: int|None}}` — `DEFAULT_CAPS` merged with the product's
  `token_caps:` block, per kind and per dimension. `None` means uncapped (`off`). Raises
  `TokenCapError` listing every bad entry (D13). The rules:
  - a key that is not a kind of `metrics.KINDS` nor `default` → `unknown job kind <k>`;
  - a key inside an entry that is not a `DIMENSIONS` name → `unknown dimension <d>`;
  - a value that is not an `int >= 1` and not `off` → `cap <k>.<d> must be a whole number of
    tokens or off, got <v>`;
  - an entry that is not a map → `token_caps.<k> must be a map of dimension: cap`.
- `cap_for(product, kind) -> {dimension: int|None}` — the kind's own value per dimension, else
  `default`'s, else `None`.
- `over(by_dim, cap) -> (dimension, tokens, limit) | None` — the first dimension of `DIMENSIONS`
  whose tally is a number strictly greater than its cap. Dimension order is the tie-break, so the
  verdict is deterministic. A `None` tally or a `None` cap is never over.
- `cap_text(kind, dimension, tokens, limit)` — the one sentence, for the result and the printed
  line: `token cap: <dimension> <tokens> over the <limit> cap for a <kind> job`.
- `cap_result(kind, dimension, tokens, limit, by_dim, at)` — the result record the factory
  appends (D8, D9):

  ```json
  {"type": "result", "subtype": "error", "is_error": true,
   "result": "token cap: input 8123456 over the 8000000 cap for a spec job — stopped by the factory",
   "usage": {"input_tokens": 8123456, "output_tokens": 41233,
             "cache_read_input_tokens": 190446211, "cache_creation_input_tokens": 2044112},
   "asf": {"cap": {"kind": "spec", "dimension": "input", "tokens": 8123456,
                   "limit": 8000000, "at": "2026-09-23T09:12:03Z"}}}
  ```

  No `duration_ms` and no `total_cost_usd`: nothing measured them, and inventing either is the
  habit this card exists to break. `session_event` already falls back to the registry clock for
  `minutes` and leaves `usd` null (`asf/metrics/metrics.py:899-918`).

### `asf/env.py`

- `PRODUCT_FIELDS['token_caps'] = _MAP`. The deep checks stay in `asf/tokens.py`, which knows the
  kinds and the dimensions.

### `asf/workers/runtime.py`

- `failure_reason(rec)` gains a first clause, before the text signatures:

  ```python
  cap = (rec or {}).get('asf')
  if isinstance(cap, dict) and isinstance(cap.get('cap'), dict):
      return 'token cap'
  ```

  Nothing else changes: `result_ok` is already False for an `is_error` record, and
  `lifecycle.judge` already renders `failed: token cap` from the signature
  (`asf/workers/lifecycle.py:474-480`).

### `asf/workers/stall.py`

The module that already owns "a live session the factory must end" gains the cap's half of it.

- `capped(product, now=None, alive=None, caps=None, stop=True, out=print)` →
  `[(job, dimension, tokens, limit)]`:
  1. `caps` defaults to `tokens.caps(product)`; a `TokenCapError` is printed as
     `token cap: <why>` and the function returns `[]` — nothing is stopped (D13).
  2. For each `pool.live_sessions(product)`: `m = tokens.meter(s['log'])`. A run whose
     `m.result` is not `None` is already over — skipped, whatever it spent.
  3. `tokens.over(m.by_dim, tokens.cap_for(product, metrics.session_kind(s)))` → `None` skips.
  4. `alive` (default `health.alive_for(product, live)` — the identity rule, F-0076 D11) must say
     the pid is this run's. If not, nothing is signalled and the run is left to health's
     `dead pid` path.
  5. `stop_session(session, grace_s=tokens.STOP_GRACE_S)`: `os.killpg(os.getpgid(pid), SIGTERM)`,
     poll `alive` every 0.5 s up to `grace_s`, then `SIGKILL`. `ProcessLookupError` and
     `PermissionError` are not errors — the run is gone or not ours, and the cap line is still
     written.
  6. Re-read the log's result. Still `None` → append `tokens.cap_result(...)` as one line.
     A result that arrived in the meantime is left alone (the session finished as the axe fell)
     and the job is reported with a `finished first` detail instead.
  7. `pool.update_session(product, job, capped={'dimension': …, 'tokens': …, 'limit': …,
     'at': now})`. `capped` joins `lifecycle.RUN_FIELDS` so it never folds into the next run
     (B-0041).
  8. Prints `CAP   <job>  <dimension> <tokens> over <limit> (<kind>)`, one per line;
     `cap: none` when there is nothing.

### `asf/tick/step_health.py`

- `run(ctx, …)` calls `stall_mod.capped(product, out=out)` **first**, before
  `health_mod.health(product, fix=True)`. The capped run's log now carries a result, so the very
  same pass ends it `failed: token cap` — no session waits a tick to die.
- One event per capped run: `ctx.event('capped', job=…, item=…, kind=…, dimension=…, tokens=…,
  limit=…)`.
- `ctx.counts` is unchanged: a cap is not a stall, and the `ticks` stream's shape is not this
  card's (`asf/metrics/metrics.py:127-132`).

### `asf/metrics/metrics.py`

- `SCHEMAS['sessions']` gains, each `(('int', 'null'), None)`:
  `tokens_input`, `tokens_output`, `tokens_cache_read`, `tokens_cache_write`.
  No `tokens` key and no total: an event carrying one is refused by the existing unknown-key
  check (`asf/metrics/metrics.py:141-143`).
- `_result_line(path)` is replaced by `tokens.meter(path)` in `sessions_from_registry`, so the
  log is read once and both the result and the tally come back. `session_event(record, result,
  items=None, by_dim=None)` takes the tally and writes the four keys; called without one it uses
  `tokens.of_result(result)`, so every existing caller keeps working.
- `compute_costs` / `subtree_cost` carry `tokens: {dimension: int|None}`, added **per dimension**
  and only where a number exists (D4). Nothing adds across dimensions.
- `fmt_tokens(n)`: `—` for `None`, `f"{n/1e6:.1f} M"` at or above 1 000 000, `f"{n/1e3:.1f} k"`
  at or above 1 000, else `str(n)`.
- `cost_table` header becomes

  ```
  | Feature | Title | Sessions | Fix rounds | Runner-min | USD | In | Out | Cache rd | Cache wr |
  ```

  with the same `(no Feature)` and `**All**` rows extended the same way. Sorting is unchanged
  (USD, then sessions, then id).
- `scorecard_rows` gains one row after `agents`:

  ```
  | tokens | in 11.6 M · out 96.4 k · cache rd 402.1 M · cache wr 7.1 M | 214 sessions, 3 capped |
  ```

  `capped` counts the day's session events whose `result` is `failed: token cap`. `·` because
  `esc` escapes `|` (`asf/metrics/metrics.py:386-387`).
- `write_costs` writes four flat keys into the machine block's `cost:` map beside `usd` —
  `tokens_input`, `tokens_output`, `tokens_cache_read`, `tokens_cache_write` — omitting a
  dimension that is `None`, so a card gains no empty keys. One level of nesting, as
  `frontmatter` allows.
- `render_daily`'s cost-table caption gains one clause: *tokens are four separate numbers and are
  never added together.*

### `asf/doctor.py`

- `check_token_caps(cfg, product) -> [(ok, detail)]`, appended in `run()` as
  `('token-caps', False, ok, detail)` after the capacity rows:
  - `TokenCapError` → one `(False, 'token_caps: <why>')` per refused entry;
  - otherwise one `(True, 'default: in 8.0 M / out 1.0 M / cache rd 400.0 M / cache wr 40.0 M;
    <n> kind(s) overridden')`, and one `(False, …)` line per dimension an operator set to `off`,
    naming it — an uncapped dimension is a decision that should be visible every time doctor
    runs.

### The product file

```yaml
# token_caps: the four dimensions of one run's spend, per job kind. A kind falls back to
# `default`; `off` means that dimension is not capped. A run over ANY dimension is stopped by
# the tick's health step and ends `failed: token cap`. These are runaway ceilings, not budgets —
# narrow them from metrics/sessions once you have a week of your own numbers.
token_caps:
  default:
    input: 8000000
    output: 1000000
    cache_read: 400000000
    cache_write: 40000000
  spec:
    input: 4000000
  review:
    input: 2000000
    output: 300000
```

`sample/product.yaml` carries the same block with the `default` row only, so
`test_sample_product` exercises it.

## Acceptance tests

The suite is stdlib `unittest`, run from the checkout root. The new tests use the temp
`ASF_HOME` of `tests/test_workers.py` and the registry/log fixtures of
`tests/test_metrics.py::write_registry` — nothing touches a real account, a real process or the
machine's `~/.ASF`.

### `tests/test_tokens.py` (new)

```sh
python3 -m unittest tests.test_tokens -v
```

  - `test_assistant_line`: `{"type":"assistant","message":{"usage":{"input_tokens":12,
    "output_tokens":3,"cache_read_input_tokens":900,"cache_creation_input_tokens":40}}}` →

- `MeterTest`

  - `test_the_results_usage_wins`: the same log with a `usage` on the result → `by_dim` is the

  - `test_garbage_and_missing_file`: a log with a blank line, a non-JSON line and a JSON array →

## Records

- **`metrics/sessions/<day>.jsonl`** — every line gains `tokens_input`, `tokens_output`,
  `tokens_cache_read`, `tokens_cache_write`. Lines already written keep their shape: the append is
  idempotent on `(task, ts)` and nothing rewrites a stream file.
- **The job log `~/.ASF/logs/jobs/<product>/<job>.jsonl`** — a capped run gains exactly one line,
  the factory's own `result` record with its `usage` and its `asf.cap` object (D8, D9). No other
  line in any log is ever edited.
- **The session registry `~/.ASF/state/<product>/sessions.jsonl`** — a capped run's line gains
  `capped: {dimension, tokens, limit, at}`, and then health's ordinary `ended` /
  `end_reason: failed: token cap` line. `capped` is a run field (B-0041): it never folds into the
  next run of the same job.
- **`metrics/events/<day>.jsonl`** in the record clone — one `kind: capped` line per stopped run,
  with the job, the item, the kind, the dimension, the tally and the limit.
- **`metrics/daily/<day>.md`** — the waste table's `tokens` row and the cost table's four new
  columns.
- **The item card** — the machine block's `cost:` map gains up to four `tokens_*` keys beside
  `usd`, written by the rollup exactly as `usd` is. An Epic's `spend_usd` is unchanged: there is
  no token equivalent, because there is no single number to put there.
- **Config** — `products/<name>.yaml` gains an optional `token_caps:` block. Nothing in
  `config.yaml` changes.
- **Printed lines**, the operator's trail: `CAP   <job>  <dimension> <tokens> over <limit>
  (<kind>)` and `cap: none` from the health step; `token cap: <why>` for a refused block; the
  `token-caps` doctor row.

## Stories

- S-14300: The meter reads a job log once and returns the run's result and its four dimensions, never a total — acceptance: `python3 -m unittest tests.test_tokens.UsageTest tests.test_tokens.MeterTest -v`
- S-14301: Every `metrics/sessions` line carries the four dimensions separately, and the schema refuses a total — acceptance: `python3 -m unittest tests.test_metrics.SessionTokensTest -v`
- S-14302: Caps are set per job kind over a built-in default, `off` is an explicit choice, and a malformed block is named rather than obeyed — acceptance: `python3 -m unittest tests.test_tokens.CapsTest -v`
- S-14303: A live run over any one dimension's cap is stopped by the factory and ends with a structured cap result line every reader already understands — acceptance: `python3 -m unittest tests.test_tokens.CapStopTest -v`
- S-14304: The tick's health step raises the cap, ends the run in the same pass, gives it no cold retry, and writes the event — acceptance: `python3 -m unittest tests.test_tokens.HealthStepTest -v`
- S-14305: The scorecard shows the four dimensions per Feature beside the money and itemises the day, with no total anywhere — acceptance: `python3 -m unittest tests.test_metrics.ScorecardTokensTest -v`
- S-14306: An item's `cost:` block carries the four dimensions, a dimension nobody measured is absent rather than zero, and an Epic's subtree adds per dimension — acceptance: `python3 -m unittest tests.test_metrics.CostBlockTokensTest -v`
