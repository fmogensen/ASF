# F-0321 — the factory stages the session's work, not the session's notebook

`NOTES.asf.md` is the file a session keeps its progress in so a continuation can pick the work
up. The brief says so in as many words — *"never committed"*
(`asf/workers/heartbeat.py:227-228`). Nothing enforces it.

The only thing that keeps it off a branch is one line the *session* is asked to run as its very
first command, inside the same fenced block as the heartbeat loop
(`asf/workers/heartbeat.py:218-219`):

```sh
mkdir -p "$(git rev-parse --git-common-dir)/info" && echo NOTES.asf.md >> \
  "$(git rev-parse --git-common-dir)/info/exclude"
```

That is advice to a model, not a gate. When the session does not run it — and the review of the
very card this one cites records the whole block being **denied** by the environment's own
auto-mode classifier as *"Unauthorized Persistence"* (`docs/reviews/1-t-0537.md:14`) — the file
sits in the worktree as a plain untracked file. Then the factory's leftover-work commit
(`asf.workers.lifecycle.commit_leftovers`, the `B-0094` mechanism) runs

```python
if _git(['add', '-A'], wt).returncode != 0:
```

and the session's notebook becomes a commit on the session's branch, pushed by
`publish_gap`.

On the reporting product this has already run its full course. The first copy reached the trunk
on 2026-10-08 and **is tracked there today**; once tracked, every later session's notes edit
rides along on every commit it makes, so the path is now a live merge surface on every branch at
once. §1 measures that: nine commits on the trunk touch it, nine independent adds exist across
the refs, 173 origin refs descend from the first landing, and two whole correction rounds have
already been spent on it — one resolving its conflict, one *restoring* it because deleting it read
as a diff outside `writes:`.

The card's requirement is the one the brief already states and cannot keep: **the factory's own
auto-commits stage the session's work and never the session's scratch.** Beside it the card names
the consequence to relieve — the copy on the trunk, and the add/add conflicts it causes on later
branches.

## Decisions

### Preconditions — measured 2026-10-10 at `c599985a2`

* **P1 — the leak is `git add -A` with no pathspec.** `asf/workers/lifecycle.py:1838` stages
  every untracked file in the worktree, the session's notebook among them, under the subject
  `wip(<branch>): the session ended with this uncommitted — committed by the factory (B-0094)`
  (`:1841-1842`). Its caller `asf.workers.health.publish_gap` (`asf/workers/health.py:500`) then
  publishes the branch.
* **P2 — in this repo, two such commits exist and both are the factory's.** `git log --oneline
  --all -- NOTES.asf.md` returns exactly four commits: `fef97f54e` and `519edf717`, both
  `wip(worker/…): … (B-0094)` and both now reachable only from `refs/remotes/origin/archive/worker/T-0591`
  and `…/archive/worker/T-0528`; and `47a36f8cf` / `65948d689`, both `wip: heartbeat <ts>`,
  reachable from no branch at all.
* **P3 — this repo's trunk is clean, and only by accident.** `git ls-tree origin/main` names no
  `NOTES.asf.md`, and `git log origin/main -- NOTES.asf.md` is empty. The file is invisible here
  because *some* session once wrote the brief's line: `git check-ignore -v NOTES.asf.md` answers
  line 19 of this checkout's own `.git/info/exclude`. That file is untracked, per-clone, and
  absent from every fresh clone — so it is not a defence, it is a coincidence.
* **P4 — on the reporting product the file is tracked on the trunk.** `ef2566bf4`
  (`wip(cloud/T-0042): … (B-0094)`, Thu Oct 8 05:53:49 2026, author `Claude (cloud)`) is the
  **oldest** commit on that trunk touching the path — the card's `ef2566bf4`, confirmed an
  ancestor of both `main` and `origin/main`. It swept in two files, the notebook and a review
  document. `git ls-tree origin/main` there names `NOTES.asf.md` today.
* **P5 — once tracked, it is rewritten by every session that keeps notes.** Nine commits on that
  trunk touch the path; six of them are `asf(T-58568): report review-t-58568`, a *review
  session's* own end-marker commits carrying its notes edits onto the trunk copy. Twenty-nine
  commits across all refs touch it; nine of those add it outright, each one an independent
  add/add side. 173 origin refs descend from `ef2566bf4` and so inherit the tracked copy.
* **P6 — two correction rounds have already been paid for it.**
  `1e063b757 task(T-0024): correction round 4 — rebase onto main, resolve NOTES.asf.md conflict`
  and `094cdf7f1 task(T-60353): restore NOTES.asf.md deleted outside writes:` — the second is the
  trap closing: a session that tidied the file away was corrected for writing outside its
  footprint. A branch that conflicts with the trunk is sent `BACK` by the lane
  (`asf/harvest/lane.py:1565-1568`, T2c), which is a correction session each time.
* **P7 — the pathspec fix is available and behaves.** Verified against git 2.54.0 in a scratch
  worktree: `git add -A -- ':/' ':(exclude,top)NOTES.asf.md'` stages `work.py` and `sub/deep.txt`
  and leaves a *tracked and modified* `NOTES.asf.md` unstaged; and
  `:(exclude,glob)**/.b[0-9][0-9][0-9][0-9]_*` excludes the scratch glob at the root and at any
  depth, matching `.gitignore` semantics.
* **P8 — excluding it introduces an empty-commit refusal that must be handled.** Verified: in a
  worktree whose only dirty path is `NOTES.asf.md`, staging with the exclusion leaves nothing
  staged, `git commit` exits 1 with `no changes added to commit`, and today's `commit_leftovers`
  would return `(False, 'commit <branch> refused: …')` — which makes `publish_gap` return early
  (`asf/workers/health.py:502-503`) and **hold the branch**. `git diff --cached --quiet` (exit 0
  when nothing is staged) tells that case apart.
* **P9 — the beat's snapshot is a second way onto a branch.** The beat loop stages with
  `GIT_INDEX_FILE=$idx git add -A` (`asf/workers/heartbeat.py:SCRIPT`, `:174`), and
  `heartbeat.land_snapshot` (`:424-443`) pushes that commit straight to `refs/heads/<branch>` for
  a run off this host. The two `wip: heartbeat <ts>` commits of P2 are this path.
* **P10 — the `runtime_liveness` brief emits no exclude line at all.** `brief_lines`
  (`asf/workers/heartbeat.py:197-205`) returns three lines for a runtime that reports liveness
  itself and none of them is the exclude; yet `heartbeat._local_notes` reads `NOTES.asf.md` out of
  the worktree whatever the runtime, so such a session is asked for notes it has no exclusion for.
* **P11 — this repo's `.gitignore` already carries the same fix for the sibling defect.** The
  entry `.b[0-9][0-9][0-9][0-9]_*` is there with the comment *"the factory's own wip auto-commit
  (`commit_leftovers`, `B-0094`) runs `git add -A` and has swept these into a branch's history
  more than once (`B-0110`, `B-0119`)"*. `NOTES.asf.md` is the one member of that class the list
  omits.
  Nothing in `tests/` asserts the list is complete.
* **P12 — the names this spec introduces are free.** `grep -rn 'workers.scratch\|FACTORY_SCRATCH\|exclude_pathspec\|check_tracked_scratch'`
  over `asf/`, `tests/`, `tools/` and `docs/` returns nothing. `info/exclude` appears in `asf/`
  only at `asf/workers/heartbeat.py:219`.

### In

* `commit_leftovers` stages the session's work with the factory's own scratch paths excluded, and
  a worktree dirty only with scratch is **published, not held** (P1, P8).
* The beat loop's snapshot tree excludes them too, so `land_snapshot` can put none on a branch
  (P9).
* The factory writes the exclude itself when it creates a session worktree, so the session's
  cooperation stops being the defence; and the `runtime_liveness` brief gains the line it lacks
  (P3, P10).
* One owner for "what the factory's scratch paths are", used by all three, plus this repo's
  `.gitignore` and an invariant that the two agree (P11, P12).
* A read-only `asf doctor` row that names a factory-scratch path tracked on the product's trunk
  and prints the exact command to remove it (P4, P5).

### Out

* **Removing the copy from the reporting product's trunk.** That is a push to `main`, which no
  session may make. The doctor row prints the command; the operator runs it. Named as a
  `NEEDS OPERATOR` below.
* **Rewriting the 173 refs that already carry it.** No history is rewritten for this. Once the
  trunk copy is gone, each branch meets the lane's existing conflict → `BACK` → mechanical
  correction path as it comes up, and `lifecycle._resolved_to_trunk`
  (`asf/workers/lifecycle.py:2008-2029`) already accounts for an add/add a rebase resolved in the
  trunk's favour, so no lost-work alarm fires on it.
* **`spawn._commit_leftovers`** (`asf/workers/spawn.py:446-456`). The same `git add -A`, but it
  commits an *orphan* worktree with hooks off purely so `_archive_unpushed` can keep the tree
  under an `archive/` ref before it is deleted. An archive ref carrying a notebook harms nothing
  and the exclusion would discard work the ref exists to preserve. Left alone, deliberately.
* **`harvest.py:657`'s index regeneration** and **`runtime.py:789`'s stub writer**. The first runs
  in harvest's own freshly-added temp worktree, which holds no session's notes; the second is the
  fake runtime used by tests. Neither is a session worktree.
* **Making the notebook a tracked file on purpose**, with a path under `docs/`. A continuation's
  notes are per-session scratch; tracking them would put every session's prose on the trunk by
  design and is a different card.

### Preconditions the work depends on

* `git` understands `:(exclude,top)` and `:(exclude,glob)` pathspec magic with `git add -A`
  (P7, verified on 2.54.0).
* `publish_gap` keeps treating a `(False, line)` from `commit_leftovers` as a hold
  (`asf/workers/health.py:501-503`) — the behaviour P8's new ok-with-nothing-staged return exists
  to avoid triggering.
* The worktree root is `commit_leftovers`' cwd (`_git([...], wt)`), so `':/'` and `top` resolve to
  it.

### The choices

| # | Chosen | Against | Why |
| --- | --- | --- | --- |
| D1 | Exclude the scratch paths in the `git add` **pathspec** | Stage everything, then `git reset <paths>` before committing | One command, no window in which the index holds the file, and it cannot leave a half-staged index behind if the process dies between the two commands. P7 verified it on the tracked-and-modified case too, which is the state the reporting product's worktrees are in today. |
| D2 | A worktree dirty **only** with scratch returns `(True, 'nothing but the factory's own scratch — nothing committed')` | Let `git commit` fail and return the refusal it prints | P8: the refusal path holds the branch. Excluding the file would otherwise convert "a session left only its notebook dirty" from a clean publish into a hold — a new failure introduced by the fix. The exit-0 of `git diff --cached --quiet` is the discriminator. |
| D3 | The factory writes `info/exclude` at worktree creation, and the brief keeps its line too | Move the line out of the brief entirely | A cloud lane's clone is made by the runtime, not by `spawn`, so the brief's line is still the only cover there. Keeping both costs one idempotent append and means neither path depends on the other. |
| D4 | Append to `$(git rev-parse --git-common-dir)/info/exclude`, the path the brief already uses | The per-worktree `$GIT_DIR/info/exclude` | The common-dir file is the one git demonstrably consults from a linked worktree — P3's `check-ignore` resolves a linked worktree's answer to the main checkout's `.git/info/exclude`. Using the same path as the brief also makes the append idempotent across both writers. |
| D5 | One owner module, `asf/workers/scratch.py` | The list inline in each of the three call sites | Three call sites and a `.gitignore` have to agree on the same names; P11 is what disagreement costs — the sibling glob was added to `.gitignore` and to none of the committers. The invariant of S-91158 can only be written against a single list. |
| D6 | The trunk row is a **read-only doctor check** that prints the removal command | Have the factory `git rm` the path and push the trunk | Never push to `main`. The factory may name the defect; the removal is the operator's. The command is printed exactly so harvest can attach its output. |
| D7 | Keep the glob `.b[0-9][0-9][0-9][0-9]_*` in the owner list beside the notebook | Scope the list to `NOTES.asf.md`, the only name the card mentions | The glob is already in this repo's `.gitignore` for exactly this defect class (P11) and so is already a protected name *here* — but a product repo has no such entry, and the same `git add -A` sweeps it there. Covering both costs one list entry and makes S-91158's invariant meaningful rather than a one-element tautology. |
| D8 | Add `NOTES.asf.md` to this repo's tracked `.gitignore` as well | Rely on the factory-side exclusion alone | Defence in depth for the one repo that can have it: the exclusion fixes the factory's committers, the ignore entry also covers a human running `git add -A` by hand in a checkout. It is the entry P11 shows the list was always missing. |

## The design

### 1. `asf/workers/scratch.py` — one owner for the factory's own scratch paths

A new module, no imports beyond `os` and `subprocess`:

* `PATHS` — the names, as the operator-facing strings: `('NOTES.asf.md',
  '.b[0-9][0-9][0-9][0-9]_*')`. The first is `heartbeat.NOTES_FILE`, imported rather than
  repeated.
* `add_pathspec()` → the argument list `git add -A` is given:
  `['-A', '--', ':/', ':(exclude,top)NOTES.asf.md', ':(exclude,glob)**/.b[0-9][0-9][0-9][0-9]_*']`.
  A literal name becomes `:(exclude,top)<name>`; a name holding a glob character becomes
  `:(exclude,glob)**/<name>` so it matches at the root and at any depth, as `.gitignore` does
  (P7).
* `exclude(wt)` → appends every name in `PATHS` that is not already a line of
  `<git-common-dir>/info/exclude` to that file, creating `info/` if needed; returns the names it
  added. Idempotent, and a failure to read or write is returned as "added nothing", never raised:
  it is a hardening step, and a worktree that cannot be hardened still has to run.

### 2. `asf/workers/lifecycle.py` — `commit_leftovers` stages work, not notes

```python
def commit_leftovers(wt, branch):
    if _git(['add', *scratch.add_pathspec()], wt).returncode != 0:
        return False, f'commit {branch} refused: git add failed'
    if _git(['diff', '--cached', '--quiet'], wt).returncode == 0:
        return True, (f'nothing to commit on {branch} but the factory\'s own scratch '
                      f'({", ".join(scratch.PATHS)}) — left in the worktree')
    p = _git(['commit', '-q', '-s', '-m', f'wip({branch}): the session ended with this '
              'uncommitted — committed by the factory (B-0094)'], wt)
    ...
```

The subject, the sign-off and the hook behaviour are all unchanged: a commit the repo's hooks
refuse is still a hold. What changes is the tree it commits and the new middle return (D2, P8).

### 3. `asf/workers/heartbeat.py` — the beat snapshots work, not notes

* `SCRIPT`'s staging line becomes
  `GIT_INDEX_FILE=$idx git add -A -- ':/' ':(exclude,top)NOTES.asf.md' ':(exclude,glob)**/.b[0-9][0-9][0-9][0-9]_*'`,
  built from `scratch.add_pathspec()` at module import so the script and the committer cannot
  drift. The notebook is still *read* for the commit message (`cat NOTES.asf.md`) — that is the
  whole point of the beat — it is only no longer in the tree (P9).
* `brief_lines(runtime_liveness=True)` gains the exclude command and the "keep `NOTES.asf.md`
  current, never committed" line (P10).
* The module docstring's *"never committed"* claim gains the sentence that now makes it true.

### 4. `asf/workers/spawn.py` — the worktree is hardened when it is made

`_add_worktree` calls `scratch.exclude(path)` after a successful `git worktree add`, and prints
the names it added at the same place the spawn's other setup lines are printed. The session's own
first command then finds the line already there and appends nothing (D3, D4).

### 5. `asf/doctor.py` — a tracked scratch path on the trunk is a named row

`check_tracked_scratch(product)` → `(ok, detail)`: `git ls-tree -r --name-only origin/<main>` in
`product.repo_dir`, matched against `scratch.PATHS`. Clean trunk → `(True, 'no factory scratch
tracked on origin/<main>')`. Otherwise `(False, …)` naming each path, the commit that first added
it (`git log --reverse --format=%h --diff-filter=A -1 origin/<main> -- <path>`), how many origin
refs descend from it, and the exact removal command. Wired into the row list beside
`check_redaction_hooks` (`asf/doctor.py:1623`).

### What it looks like when it is there

A session ends with its notebook and a half-finished file uncommitted. The factory commits the
half-finished file alone; the notebook stays in the worktree, where the continuation reads it. A
session ends with *only* its notebook dirty: the factory commits nothing, says so in one line, and
publishes the branch it already had. A beat fires: the snapshot carries the work and the notes
message, and no notebook in its tree, so a continuation's `land_snapshot` puts none on the branch.
A worktree is created: the exclude line is already there, whether or not the session is allowed to
run commands. And `asf doctor` on the reporting product prints one red row naming `NOTES.asf.md`,
`ef2566bf4`, 173 refs, and the `git rm` that ends it.

### S-91155: the leftover-work commit stages the session's work and never its scratch

Design §2 — the pathspec and the new middle return (D1, D2; P1, P7, P8). Acceptance is the second
and third fenced blocks of `## Acceptance tests`. The empty-staging case is the delicate half:
excluding the file turns "only the notebook was dirty" into a `git commit` that exits 1, and the
caller reads a refusal as a hold, so the fix without that return is a new way to strand a branch.

- [ ] a worktree holding an uncommitted work file and an untracked notes file commits the work file alone
- [ ] the notes file is still in the worktree after the commit, with its contents unchanged
- [ ] the commit subject still names the branch and the leftover-work mechanism, and is still signed off
- [ ] a worktree whose only dirty path is the notes file commits nothing and returns ok, not a refusal
- [ ] the line returned for that case says the scratch was left in the worktree and names it
- [ ] the branch head is unchanged when nothing but scratch was dirty, and no empty commit was made
- [ ] a notes file that is already tracked and modified is left unstaged, and the work file beside it is still committed
- [ ] a top-level scratch file matching the session-scratch glob is excluded, and so is one nested in a subdirectory
- [ ] a work file nested in a subdirectory is still staged, so the pathspec did not narrow the add to the root
- [ ] a commit the repo's own hooks refuse is still returned as a refusal and still leaves the files a hold

### S-91156: the beat's snapshot carries the notes as its message and not in its tree

Design §3 (D1, D5; P9, P10). Acceptance is the fourth and fifth fenced blocks of
`## Acceptance tests`. The snapshot is the path that put the two unreferenced heartbeat commits of
P2 on branches, and it is the one that reaches a branch head *while a run is still live*, so a
continuation starts from it.

- [ ] the beat loop's staging command is built from the owner module, so the script and the committer cannot name different paths
- [ ] a snapshot taken in a worktree holding a notes file produces a tree that does not contain that path
- [ ] the snapshot commit message still carries the contents of the notes file
- [ ] the snapshot commit message still carries the session trailer
- [ ] a snapshot of a worktree holding work in progress still contains that work
- [ ] landing a snapshot onto a branch puts no notes file on that branch
- [ ] the brief for a runtime that reports its own liveness now carries the exclude command
- [ ] that brief also tells the session its notes file is never committed
- [ ] the ordinary brief's heartbeat block is otherwise unchanged, so its golden test still passes

### S-91157: the factory excludes the scratch paths itself when it makes the worktree

Design §1's `exclude` and §4 (D3, D4; P3, P10). Acceptance is the sixth fenced block of
`## Acceptance tests`. P3 is the reason this Story exists: the only thing hiding the file in this
very repo is an untracked per-clone line that some session happened to write, which no fresh clone
has and no session can be relied on to write.

- [ ] creating a session worktree leaves every scratch name in the repository's shared exclude file
- [ ] the names are written to the shared exclude file, so a linked worktree reads them
- [ ] the notes file reads as ignored in the new worktree straight after it is created
- [ ] appending a second time adds nothing and leaves the file with one line per name
- [ ] a name a previous writer already put there is not duplicated
- [ ] an exclude file that already holds unrelated lines keeps them all
- [ ] a worktree whose exclude file cannot be written is still created, and the failure is not raised
- [ ] the names that were added are returned, and an append that added none returns none

### S-91158: one owner lists the factory's scratch paths, and this repo's ignore file agrees with it
