# F-0199 — the table that cannot tell an exit from a death

The tick ends with two tables. The second, `DONE`, reads the ledger's `end_reason` and is
accurate. The first, `IN FLIGHT`, derives its own status word in one line
(`asf/tick/summary.py:84-91`):

```python
def inflight_rows(product, alive):
    rows = []
    for run in pool.live_sessions(product):
        row = dict(run)
        row['status'] = 'working' if alive(run.get('pid')) else 'dead pid'
        rows.append(row)
```

There is no third answer. A session is working, or it is a dead pid. But the ledger's "live"
set is every run with no `ended` line, and `ended` is written by **health**, not by the session:
a session that finished at 08:47, wrote its result record, pushed its branch and exited is live
on the ledger until the next health pass reaches it. Every tick in between prints it `dead pid`.

On 2026-09-26 at 09:04 that was six sessions of one product and one of this one, all seven
reading `dead pid 17m`, all seven reconciled at the next health pass as `finished` or `failed`.
None of them was dead.

The age is wrong too. The `since` column is `age(r.get('started'), now)` (`summary.py:143`) —
time since **launch**. `dead pid 17m` therefore does not mean "it died 17 minutes ago"; it means
"it was launched 17 minutes ago", and the session may have exited 16 of those minutes ago or one
second ago. The number that would tell an operator whether health is behind is the one number the
row does not carry.

The repository already knows the answer twice over.

`asf/workers/lifecycle.py` holds the one classifier F-0098 built — `SESSION_STATES`
(`lifecycle.py:168`), `Status`/`classify`/`state_of` (`:2078-2148`) — and it has a name for
exactly this run: `ENDED_AWAITING_TICK`, *"ended, awaiting tick"*. It also holds
`finished_unrecorded` (`:755`), whose docstring is the card's own paragraph:

> Live on the ledger, its pid gone, and its log's last run closed on a success result: the
> session finished and exited normally, and health has not written its `ended` line yet. It
> holds no seat, but it is not dead either — its work waits for health and harvest, not for
> another session. **Only a pid that vanished *without* a result is dead.**

And `asf sessions` — the same ledger, the other view — already splits three ways on it
(`asf/views/sessions.py:63-85`), prints a **Finished** group and counts it `n finished
(awaiting harvest)`. Two views of one ledger disagree, and the one the tick prints every few
minutes is the wrong one.

`asf/tick/summary.py` is on the fence list that records this: `tests/test_lifecycle.py:757`,
`OneClassifierTest.NOT_YET` — *"§2.7: no module but `lifecycle` derives a session state.
`NOT_YET` names the readers this plan has not converted yet"*. Line 88 is the unconverted
reader, and it is the defect.

## Decisions

**In scope**

- The `IN FLIGHT` table's `status` cell: four words, derived through `lifecycle`, never spelled
  by `summary.py`.
- The `IN FLIGHT` table's `since` cell: since the exit for a run whose process is gone, since
  the launch for one still working.
- One git-free classifier entry point in `lifecycle` for a run that is still live on the ledger,
  and one place that words it for a narrow column.
- `asf/tick/summary.py` leaving `OneClassifierTest.NOT_YET`.

**Out of scope**

- The `DONE` table. It reads `end_reason` — health's own judgement, already recorded — and is
  correct today. Nothing in this Feature touches it, and the acceptance tests assert that.
- `asf/views/sessions.py`, `asf/views/status.py`, `asf/capacity.py` and the other nine readers
  on `NOT_YET`. `sessions.py` is already right about this distinction (D3); the rest are F-0098's
  remaining Tasks, not this card's.
- Health's timing. Making health reconcile a clean exit sooner is a different Feature; this one
  makes the table honest about the gap, whatever its width.
- `end_reason`, `judge`, and what health writes. The ledger's vocabulary does not change.
- Recording an exit time on the ledger. A new field would need a writer, and the only process
  that could write it is the one that has already exited (D5).
- The seat count. `occupies` (`lifecycle.py:735`) already says a dead pid holds no seat, and a
  finished-unrecorded run holds none either; both remain true and neither changes.

**Preconditions** — each verified in this worktree at `c2bf7f7f9`:

- `inflight_rows` has exactly one caller, `summary.run` (`summary.py:199`), and
  `IN_FLIGHT_COLUMNS` exactly one (`:162`). `summary.render`'s only test-side caller
  (`tests/test_lane.py:2487`) passes an empty in-flight list, so the row shape may change.
- `lifecycle.result_of(run)` is `runtime.read_result(run['log'])` and returns `None` for a run
  with no `log` key, a log that does not exist, and a log whose last run wrote no `result` line
  (`runtime.py:410-436`). Probed: all three.
- `runtime.result_ok(rec)` is git-free.
- `lifecycle.judge(run, Evidence(result=rec))` returns before it asks anything of git when
  `result_ok(rec)` is False (`lifecycle.py:2058-2064`), so a non-ok result can be judged with no
  evidence but itself. Probed: it returns `'failed'` for `{'is_error': True}`.
- `lifecycle.lands(run, path=None)` reads no file when `path` is None (`:2030-2042`).
- `OneClassifierTest.STATE_WORDS` is `(DEAD, DEAD_PID, WORKING, ENDED_AWAITING_TICK)`; `finished`
  and `failed` are deliberately *not* guarded (`tests/test_lifecycle.py:766-770`), so those two
  may be spelled anywhere. `summary.py` has exactly two violations today, both on line 88, and
  none after the change. Probed with the fence's own AST walker: `after: []`.
- A cloud run carries a local `log` and `asf.workers.cloud` appends a synthetic `result` record
  to it when the remote session finishes (`cloud.py:504-506`), and a non-result `asf`/`cloud`
  line when it dies (`:512-513`). Both arms therefore classify the same way a host run's do.
- `pool.live_sessions` is `lifecycle.latest` filtered by `is_live` — every run with no `ended`
  (`pool.py:254`).

**Choices**

| # | Choice | Against | Why |
|---|---|---|---|
| D1 | Four words: `working`, `finished`, `exited — awaiting harvest`, `dead` | Three (fold the failing exit into `dead`) | The card asks for all four and the incident needs all four: of the seven rows, health judged some `finished` and some `failed`, and **neither** was dead. A failing exit is still an exit — the session wrote a result record and left. `dead` must mean what it says, or the word is worth nothing the next time a session really does vanish. |
| D2 | `exited — awaiting harvest` is the exit whose result record is *not* a success; `finished` is the exit whose result record *is* | Read the card's first sentence as covering every exit | The card's three sentences only reconcile one way: *"a session whose pid has exited reads `exited — awaiting harvest`"*, *"and `finished` when its log ends with a result record"*, *"`Dead` is kept for exits with no result record"*. `finished` is the refinement, `dead` is the exception, and `exited — awaiting harvest` is what is left — the exit health will judge `failed: …`. ## The design

### 1. `asf/workers/lifecycle.py` — one more rung on the evidence ladder

`state_of` (`:2132`) is the impure entry point and its ladder ends at `gather`. For a run that is
still live on the ledger, the tick's summary needs the rung *before* that: the pid and the log,
and nothing else. It is added beside `classify`, and it returns the same `Status` every other
reader prints.

```python
def live_status(run, alive=None, result=None):
    """The :class:`Status` of a run that is still live on the ledger (no ``ended``), from its
    pid and its log alone — no git, no remote. §2.2's ladder stopped one rung short of the
    tick's own summary, which is best-effort console output and must not ``ls-remote`` once per
    row (F-0199 D3).

    ``working`` while the pid answers; ``finished`` for a pid that exited on a success result —
    the session's own claim, which health confirms or contradicts one pass later
    (:func:`finished_unrecorded`); ``ended-awaiting-tick`` for one that exited on a result that
    is not a success, which health will judge ``failed: …``; ``dead`` — :data:`NO_RECORD` —
    only for one that exited having written no result at all. ``result``: ``callable(run) ->
    result line`` (default :func:`result_of`)."""
    if (alive or pid_alive)(run.get('pid')):
        return Status(WORKING, source='pid')
    rec = (result or result_of)(run)
    if rec is None:
        return Status(DEAD, reason=NO_RECORD, source='pid')
    if runtime_mod.result_ok(rec):
        return Status(FINISHED, result=FINISHED, source='report')
    return Status(ENDED_AWAITING_TICK, result=judge(run, Evidence(result=rec)), source='report')
```

`source='report'` is what separates this `FINISHED` from `classify`'s: that one is
`source='ledger'`, health's recorded judgement; this one is the session's claim (D3).

Then the narrow-column wording, next to `Status.label` so the two cannot drift:

```python
#: The tick's IN FLIGHT column for an exit health has not judged yet (F-0199): it left, and the
#: pass that comes next says what it left behind.
EXITED_AWAITING = 'exited — awaiting harvest'

#: ``{state: the word the IN FLIGHT column prints}`` — :attr:`Status.label`'s spelling for a
#: padded column. One owner, so the table cannot word a state the views do not (P11).
INFLIGHT_WORDS = {WORKING: WORKING, FINISHED: FINISHED, NOTHING_TO_LAND: FINISHED,
                  ENDED_AWAITING_TICK: EXITED_AWAITING, FAILED: EXITED_AWAITING, DEAD: DEAD}


def inflight_word(status):
    """What the tick's IN FLIGHT table prints for ``status``. ``status`` may be a
    :class:`Status` or its bare ``name`` string, as :func:`holds_seat` takes either."""
    name = status.name if isinstance(status, Status) else status
    return INFLIGHT_WORDS.get(name, name)
```

`FINISHED`, `NOTHING_TO_LAND` and `FAILED` cannot reach the in-flight table — a run carrying
`ended` is not live — but the map is total over `SESSION_STATES` so that a later caller, or a
later state, does not fall through to a bare name by accident.

### 2. `asf/tick/summary.py` — the two cells

```python
def exited_at(run):
    """When ``run``'s process last wrote its log, as a :data:`LEDGER_FORMAT` stamp — its exit,
    to the second: the result line is the last thing a session writes (F-0199 D5). ``None``
    when there is no log to stat, which the ``since`` column renders ``?`` (D6)."""
    try:
        mtime = os.path.getmtime((run or {}).get('log'))
    except (OSError, TypeError):
        return None
    return datetime.datetime.fromtimestamp(
        mtime, datetime.timezone.utc).strftime(LEDGER_FORMAT)


def inflight_rows(product, alive):
    """One row per live run, its ``status`` and the stamp its ``since`` column counts from —
    the launch for a session still working, the exit for one whose process is gone (F-0199)."""
    rows = []
    for run in pool.live_sessions(product):
        row = dict(run)
        status = lifecycle.live_status(run, alive)
        row['status'] = lifecycle.inflight_word(status)
        row['since_at'] = run.get('started') if lifecycle.holds_seat(status) else exited_at(run)
        rows.append(row)
    rows.sort(key=lambda r: r.get('started') or '￿')
    return rows
```

The sort key stays `started`: the table is still ordered oldest launch first, so a row does not
move up and down the table as health falls behind.

`render` reads the new key and nothing else changes:

```python
'status': r.get('status'), 'since': age(r.get('since_at'), now),
```

`since_at` is `None` for an exited run with no readable log, and `age(None, now)` is already
`'?'` — no new branch in `render`.

### 3. What it looks like when it is there

The 09:04 table, with health 17 minutes behind, and `spec-f-0199` still running:

```

job          item    kind  feature  account  model  status                     since  what
fix-b-0002   B-0002  fix   —        acct-b   opus   finished                   16m    a bug

spec-f-0199  F-0199  spec  F-0199   acct-a   opus   working                    3m     a feature
```

The status column widens to 25 when any row carries it; `what` is last and never padded

## Acceptance tests

All four fixtures were run against `c2bf7f7f9` before this spec was written: each reaches the
row, and each reads `dead pid  12m` today (`working  12m` for the last). That is the defect, and
these are the tests that close it.

### `tests/test_tick_summary.py` — the status cell

New classes beside the existing `ShapeTests`. `SummaryTestCase` already supplies `self.tmp`,
`self.launch` (which forwards `**extra` onto the session record, so `log=` needs nothing new) and
`self.render(alive=…)`, and `NOW` is `'2026-09-22T12:00:00Z'` against a default launch at
`11:48:00Z` — 12 minutes, the number every assertion below is written around. The file gains one
import, `datetime`; `json`, `os` and `summary` are already imported.

```python
OK_RESULT = {'type': 'result', 'subtype': 'success', 'is_error': False,
             'result': 'REPORT\nitem: F-0001\nstatus: done\npushed: yes abc1234\n'}
BAD_RESULT = {'type': 'result', 'subtype': 'error_during_execution', 'is_error': True,
              'result': 'boom'}


class LogRows:
    """A log file at a chosen exit time, and the one row of the IN FLIGHT table it renders."""

    def log(self, name, *recs, at=None):
        path = os.path.join(self.tmp, name)
        with open(path, 'w') as f:
            for rec in recs:
                f.write(json.dumps(rec) + '\n')
        if at:
            ts = datetime.datetime.strptime(at, summary.LEDGER_FORMAT).replace(
                tzinfo=datetime.timezone.utc).timestamp()
            os.utime(path, (ts, ts))
        return path

    def row(self, text, job='spec-f-0001'):
        return [ln for ln in text.split('\n') if ln.startswith(job)][0]


class ExitedNotDeadTests(LogRows, SummaryTestCase):
    """F-0199: `ended` is health's line, not the session's. A session that exited cleanly is
    live on the ledger until the next health pass, and the IN FLIGHT table called all seven of
    them `dead pid` on 2026-09-26."""

    def test_a_clean_exit_with_a_result_record_is_finished_not_dead(self):
        self.launch('spec-f-0001', log=self.log('ok.jsonl', OK_RESULT))
        row = self.row(self.render(alive=lambda pid: False))
        self.assertIn('finished', row)
        self.assertNotIn('dead', row)

    def test_an_exit_on_a_failing_result_is_exited_awaiting_harvest_not_dead(self):
        self.launch('spec-f-0001', log=self.log('bad.jsonl', BAD_RESULT))
        row = self.row(self.render(alive=lambda pid: False))
        self.assertIn('exited — awaiting harvest', row)
        self.assertNotIn('dead', row)

    def test_an_exit_with_no_result_record_is_dead(self):
        # the log exists and the run opened, but nothing closed it: this one really did vanish
        self.launch('spec-f-0001', log=self.log('open.jsonl',
                                                {'type': 'system', 'subtype': 'init'}))
        row = self.row(self.render(alive=lambda pid: False))
        self.assertIn('dead', row)
        self.assertNotIn('exited', row)

    def test_a_live_pid_is_working_whatever_its_log_says(self):
        self.launch('spec-f-0001', log=self.log('ok2.jsonl', OK_RESULT))
        row = self.row(self.render(alive=lambda pid: True))
        self.assertIn('working', row)

    def test_the_done_tables_words_are_unchanged(self):
        # the ledger's own vocabulary: health's `dead pid` still reads `dead pid` in DONE
        self.launch('a', started='2026-09-22T11:00:00Z')
        pool_mod.update_session(self.product, 'a', ended='2026-09-22T11:31:00Z',
                                end_reason='dead pid')
        done = self.render().split('DONE')[1]
        self.assertIn('dead pid', done)
```

`test_dead_pid_is_named_in_flight` (`tests/test_tick_summary.py:73-77`) is rewritten in place
(D9): same fixture — a launch with no `log` at all — asserting `'dead'` and not `'dead pid'`,
renamed `test_an_exit_with_no_log_at_all_is_dead`.

### `tests/test_tick_summary.py` — the since cell

A second class, so each Story has a command of its own. `log` and `row` are the same two helpers,
lifted to a mixin both classes carry.

```python
class ExitAgeTests(LogRows, SummaryTestCase):
    """F-0199: `dead pid 17m` never meant "it died 17 minutes ago" — it meant "it was launched
    17 minutes ago". For a process that is gone, the number that matters is since the exit."""

    def test_the_age_is_since_the_exit_not_since_the_launch(self):
        # launched 11:48, exited 11:57, rendered at 12:00: the row says 3m, not 12m
        self.launch('spec-f-0001', log=self.log('ok.jsonl', OK_RESULT,
                                                at='2026-09-22T11:57:00Z'))
        row = self.row(self.render(alive=lambda pid: False))
        self.assertIn('  3m', row)
        self.assertNotIn('12m', row)

    def test_a_working_session_counts_from_its_launch(self):
        self.launch('spec-f-0001', log=self.log('ok.jsonl', OK_RESULT,
                                                at='2026-09-22T11:57:00Z'))
        self.assertIn('  12m', self.row(self.render(alive=lambda pid: True)))

    def test_an_unreadable_log_renders_the_age_unknown_never_the_launch_age(self):
        self.launch('spec-f-0001', log=os.path.join(self.tmp, 'gone.jsonl'))
        row = self.row(self.render(alive=lambda pid: False))
        self.assertIn('  ?', row)
        self.assertNotIn('12m', row)

    def test_exited_at_is_the_logs_mtime(self):
        log = self.log('x.jsonl', OK_RESULT, at='2026-09-22T11:57:00Z')
        self.assertEqual(summary.exited_at({'log': log}), '2026-09-22T11:57:00Z')
        self.assertIsNone(summary.exited_at({'log': '/nonexistent/x.jsonl'}))
        self.assertIsNone(summary.exited_at({}))
        self.assertIsNone(summary.exited_at(None))
```

### `tests/test_lifecycle.py` — the classifier arm

Added beside the existing `classify`/`state_of` cases (`:640-738`), which already supply `OK`
and a `RUN` dict.

```python
class LiveStatusTest(unittest.TestCase):
    """F-0199: the rung below `state_of` — a run still live on the ledger, judged on its pid and
    its log and nothing else."""

    RUN = {'job': 'j', 'item': 'F-0001', 'kind': 'spec', 'branch': 'spec/F-0001', 'pid': 101,
           'started': 't1'}

    def status(self, alive, rec):
        return lc.live_status(self.RUN, alive=lambda pid: alive, result=lambda run: rec)

    def test_a_live_pid_is_working(self):
        self.assertEqual(self.status(True, None).name, lc.WORKING)
        self.assertEqual(self.status(True, OK).name, lc.WORKING)   # the pid wins

    def test_an_exit_on_a_success_result_is_finished_and_says_it_is_the_report(self):
        status = self.status(False, OK)
        self.assertEqual((status.name, status.result, status.source),
                         (lc.FINISHED, lc.FINISHED, 'report'))

    def test_an_exit_on_a_failing_result_is_ended_awaiting_tick(self):
        bad = {'type': 'result', 'subtype': 'error_during_execution', 'is_error': True,
               'result': 'boom'}
        status = self.status(False, bad)
        self.assertEqual((status.name, status.source), (lc.ENDED_AWAITING_TICK, 'report'))

    def test_an_exit_with_no_result_is_dead_with_no_record(self):
        status = self.status(False, None)
        self.assertEqual((status.name, status.reason), (lc.DEAD, lc.NO_RECORD))

    def test_it_never_reaches_git(self):
        def raises(*a, **k):
            raise AssertionError('gather must not be called')
        with mock.patch.object(lc, 'gather', raises), mock.patch.object(lc, '_git', raises):
            for rec in (None, OK, {'is_error': True, 'result': 'boom'}):
                self.assertIn(lc.live_status(self.RUN, lambda pid: False,
                                             lambda run: rec).name, lc.SESSION_STATES)

    def test_only_working_holds_a_seat(self):
        self.assertTrue(lc.holds_seat(self.status(True, None)))
        for rec in (None, OK):
            self.assertFalse(lc.holds_seat(self.status(False, rec)))

    def test_inflight_word_covers_every_session_state(self):
        for name in lc.SESSION_STATES:
            self.assertIn(lc.inflight_word(name),
                          (lc.WORKING, lc.FINISHED, lc.EXITED_AWAITING, lc.DEAD))
        self.assertEqual(lc.inflight_word(lc.Status(lc.ENDED_AWAITING_TICK)),
                         'exited — awaiting harvest')
        self.assertEqual(lc.inflight_word(lc.DEAD), 'dead')       # never 'dead pid'
```

| where | today | after |
|---|---|---|
| `IN FLIGHT` `status`, pid alive | `working` | `working` |
| `IN FLIGHT` `status`, exited on a success result | `dead pid` | `finished` |
| `IN FLIGHT` `status`, exited on a failing result | `dead pid` | `exited — awaiting harvest` |
| `IN FLIGHT` `status`, exited with no result record | `dead pid` | `dead` |
| `IN FLIGHT` `since`, pid alive | since the launch | since the launch |
| `IN FLIGHT` `since`, pid gone | since the launch | since the exit, or `?` |
| `DONE` `result` | the ledger's `end_reason` | unchanged |

Read consequences, all pre-existing behaviour that this makes visible rather than alters:

- `sessions.jsonl` — read only, through `pool.live_sessions`.
- Each live run's `log` — one `read_result` scan and one `getmtime` per row, per tick. The scan
  is the same one `asf sessions` already makes; the stat is the same one `stall.py:89` makes.
- No `git` process and no network call is added to the tick's summary (D3).

Nothing downstream reads these cells: the seat count is `lifecycle.occupies`/`holds_seat`
(`lifecycle.py:735`, `:2150`), the feeder's in-flight list is `lifecycle.inflight` (`:950`), and
neither consults `summary`.
