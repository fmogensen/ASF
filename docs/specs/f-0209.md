# F-0209 — the refusal was right, and both halves of the answer were half-written

A coder's push was refused by the product's own pre-push hook: a doc quoted a line of a file the
Task changed, the quote went stale, and the doc was outside the Task's `writes:`. The session
did the right thing — a file outside `writes:` is a file it may not touch — and the refusal was
also right. What was wrong was the plan: the `writes:` it minted named the Task's own diff and
not the doc that would have to move with it.

The card asks for two things, and the checkout says they are in two different states.

The **lane half is landed**. `asf/tick/widen_footprint.py` reads a `hook refused` correction,
parses the paths off the refusal, keeps the ones outside `writes:`, widens the card, and sends
the run back as a correction with no round spent — T-0338, with T-0349 narrowing it to a push
that was actually refused. Re-specifying it would be re-writing green code. But the card's
acceptance names two cases, and only one of them has a test: the overlap case is pinned against
a *running session*, not against a Task `Active` in the record, and nothing at all pins the
claim the lane rests on — that a refusal at its cap still widens rather than going to
adjudication.

The **plan half is not landed**. No brief that mints a `writes:` line says anything about a file
the Task does not edit but that a check will demand change with it.

So this Feature is one edit to the briefs, and two tests that make the card's acceptance
something a person can run.

## The design

### 1. The paragraph, in three briefs

One paragraph, the same words in all three files, placed immediately after the existing
sentence that explains what `writes:` is:

```
`writes:` also holds the files the Task does not edit but that a check will demand change with
it: a doc that quotes a changed file, the golden fixture of a changed template, a generated
file. A pre-push check that finds one of those stale refuses the push, and the coder may not
touch a file outside `writes:` — so for each file a Task changes, grep the docs for it and put
every doc that quotes it on that Task's `writes:`.
```

**`asf/briefs/templates/plan.md`** — inserted as a new paragraph after line 22 (the `writes:` /
`after:` paragraph), before the `Every Task carries, besides those three lines:` paragraph, at
column 0 like its neighbours.

**`asf/briefs/templates/spec-plan.md`** — inserted after line 31 (the three-line block) and
before the `Then **Files**, **Steps**, **Gate** …` paragraph, indented three spaces to match the
numbered-list item it sits in.

**`asf/briefs/templates/replan.md`** — inserted after line 35 (the `Every open Task above appears
exactly once …` paragraph) and before the `If the decision cannot be carried out …` paragraph, at
column 0.

The paragraph names no hook, no path prefix and no id, so it passes P9 in every product.

### 2. The three goldens follow

`tests/fixtures/briefs/golden/plan.md`, `spec-plan.md` and `replan.md` each gain the same
paragraph at the corresponding place. They are regenerated, never hand-edited:

```
ASF_UPDATE_GOLDEN=1 python3 -m unittest tests.test_briefs
```

No other golden moves: the paragraph is in three templates and the other eighteen kinds do not
read them.

### 3. `active()` lifted to `WidenStepBase`

`tests/test_widen.py`: the byte-identical `active()` in `WidenStepTests` and in
`SerializeOverlapTests` is deleted from both, and the one copy is added to `WidenStepBase`
beside `card()`. Nothing else moves — `check()` keeps its two copies (C6), and
`SerializeOverlapTests.rows`'s override stands. Every existing test keeps its behaviour: the
method resolves the same way through the base.

### 4. Two tests in `RefusalWidenTests`

Both sit in the existing class, use its existing `REFUSAL` text and its `refused()` helper, and
change no production code.

**The Active-in-the-record overlap** (P4) — the sibling of the running-session test one line
above it, differing only in that T-0002 has no session at all.

**The refusal at its cap** (P3) — the card's "it must not mark the Task dead", stated as what
the record can actually show: the second identical refusal is marked `at_cap`, `derive` on that
run alone says `adjudicate`, and after the widening pass the correction is of kind `footprint`,
carries no `at_cap`, and `derive` says `held` — the run comes back as a `FIX → CORRECT` with
`launches=True`, no round spent. Per P11 the row alone is the same either way, so `derive` is
what the test asserts on both sides of the pass.

Both tests were run verbatim against this checkout, through a scratch subclass that borrowed
`active` rather than editing the tree, and both pass. They are **pins on landed behaviour**, not
red tests — the Task that lands them is green on arrival, and its value is that P3 and P4 stop
being true by accident.

### B — the lane's widening of a refused push, at both edges

The two tests, to be added to `tests/test_widen.py::RefusalWidenTests` verbatim:

```python
    def test_a_refused_path_an_active_task_writes_waits_though_no_session_runs_it(self):
        # the card's acceptance: an overlap with a Task Active in the record — no session at
        # all — holds the Task instead of widening it (open_footprints reads the record too)
        self.active('T-0002', 'lib/shared.py')
        self.refused()
        _held, verdicts = self.tick()
        self.assertEqual(verdicts, {'coder-t-0001': widen.WAITS}, self.lines)
        self.assertEqual(self.writes(), ['src/a.py', 'tests/test_a.py'])
        self.assertEqual([(r.action, r.waits_on, r.launches) for r in self.rows()],
                         [('WAITS ON T-0002', 'T-0002', False)])

    def test_a_refusal_at_the_cap_widens_rather_than_going_to_adjudication(self):
        # B-0140 marks the second identical refusal at_cap, and lifecycle.derive routes an
        # at_cap correction to ADJUDICATE. The widening runs first (step_health: health, then
        # widen_footprints) and footprint_hold writes a fresh correction, so the Task comes
        # back as a correction — it is never marked dead. The feeder's row is FIX → CORRECT
        # either way (P11), so derive is what discriminates.
        self.refused()
        path = pool_mod.sessions_path(self.product)
        corr = lifecycle.latest(path)['coder-t-0001']['correction']
        self.session(job='coder-t-0001', correction=dict(corr, at_cap=True, same=2))
        run = lifecycle.latest(path)['coder-t-0001']
        self.assertEqual(lifecycle.derive(run, lifecycle.Evidence(), path=path).name,
                         lifecycle.ADJUDICATE)  # what the at_cap correction alone would be
        _held, verdicts = self.tick()
        self.assertEqual(verdicts, {'coder-t-0001': widen.WIDEN}, self.lines)
        self.assertEqual(self.writes(), ['src/a.py', 'tests/test_a.py', 'lib/shared.py'])
        run = lifecycle.latest(path)['coder-t-0001']
        self.assertEqual(run['correction']['kind'], lifecycle.FOOTPRINT)
        self.assertNotIn('at_cap', run['correction'])
        self.assertEqual(lifecycle.derive(run, lifecycle.Evidence(), path=path).name,
                         lifecycle.HELD)
        self.assertFalse(self.rounds())  # no round spent
        self.assertEqual([(r.kind, r.brief_kind, r.launches) for r in self.rows()],
                         [(feeder_rows.FIX_CORRECT, 'correct', True)])
```
