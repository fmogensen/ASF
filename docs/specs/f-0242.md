# F-0242 — the gate counted the pipeline's shape, and the two levers that would cut the rest are not pulled

`asf release-readiness --product asf` criterion 2 read

```
116 repair sessions / 17 Features landed in 7 d = 6.8
```

against `release.max_repair_per_feature: 3`. The number was made of about 107 `review` sessions,
16 `correct` and 3 `adjudicate`: `REPAIR_PREFIXES` (`asf/scorecard/score.py:25`) counted every
`review` session as repair, and a Task gets one review by design. The gate was measuring how many
Tasks the week reviewed, not how much of the week was spent doing work twice.

**Half of this Feature has landed since the card was written.** The decision is recorded
(`docs/decisions/0003-a-planned-first-review-is-not-repair.md`), `score.repair_flags`
(`asf/scorecard/score.py:57`) exempts an item's first `review` by time, `score.repair_kinds`
(`:78`) breaks the rest down, `score.window_row` carries `repair_by_kind` (`:277`), and
`asf release-readiness` prints it in criterion 2's evidence cell (`asf/release.py:461`, `:469`,
fed through `release.gather` at `:808-809`). `tests/test_scorecard.py::PlannedFirstReviewTests`
pins both sides of the decision and pins that the scorecard and the gate read the one function.
The card's acceptance boxes 1 and 3 are therefore **preconditions**, not work.

What is left is three concrete things, and they are the reason the ratio is still a guess.

**1. The diagnosis still contradicts the decision.** `asf/scorecard/diagnose.py:180` builds each
`by_kind` row with `'repair': score.is_repair(k)` — the kind-level answer, which is `True` for
`review` — and `causes` (`:290-296`) raises

```
kind:review   Repair sessions 'review' take 17 % of session spend
```

on the **whole** kind's spend, planned first reviews included. So `asf scorecard` says review is
17 % of spend in repair while `asf release-readiness`, reading `repair_flags`, says most of it is
not repair at all. Two surfaces, one decision, two answers — exactly what the card's first
acceptance box forbade. `diagnose.metric(facts, 'kind:review', …)` returns that same kind-level
share, so a cause raised this way cannot be closed by cutting rework; only by cutting reviews.

**2. The mechanical pre-review is built and nothing pulls it.** `asf review-checks`
(`asf/review_checks.py`, registered at `asf/cli.py:317-324`) reads a review file and derives its
verdict from the check table alone — the pass that catches the one fault class that costs a whole
round. `docs/specs/f-0053.md:396-399` and `docs/plans/f-0053.md:263-264` both require that *"the
brief contains the `review-checks` command with its `--kind` filled in"*. It does not:

```
$ grep -rl 'review-checks' asf/
asf/cli.py
asf/review_checks.py
```

No brief template names it, no golden brief carries it, and no test asserts it. The command
exists for a reviewer who already knows to run it, which is nobody. What that costs is written
down in the code it was built for, `asf/reviews.py:174`:

> An approved review whose rows said the checklist in the brief's words once read as a missing
> check: **119 of 121 approved code reviews derived `BOUNCE`, and each sent an approved branch
> back for a correction round.**

A `BOUNCE` (`asf/reviews.py:189-201`) is a round that found nothing and bought nothing: the lane
launches the review again, and under `repair_flags` that second round **is** repair. This is the
single largest avoidable term in the corrected count, and it is one line of brief away.

**3. `docs_review: skip` stops short of a branch it plainly applies to.**
`lane.docs_only_task` (`asf/harvest/lane.py:451-463`) waives the review of a docs-only branch,
and its own guard is

```python
if item.get('type') not in ('task', 'bug') or not writes or landing_class(product, writes) != DOCS:
    return False
```

while `rows.lane_rows` (`asf/feeder/rows.py:1093-1104`) raises a review row for a **direct-lane
Feature** as well as for a Task or a Bug, and consults `docs_only_task` for all of them. A
direct-lane Feature whose `writes:` are all docs therefore gets a review round that the flag was
written to waive, and a send-back on it is repair like any other.

This Feature closes the disagreement, pulls the pre-review lever, finishes the waiver, and makes
the gate say which lever a product has left off — so that criterion 2, when it fails, names both
the kind that drives the ratio and the thing to turn on.

## Decisions

**In scope**

- `asf scorecard`'s diagnosis counts repair the way the gate does: `diagnose.rank`'s `by_kind`
  rows gain the flagged repair numbers, `diagnose.causes` gates and reports on them, and
  `diagnose.metric` answers a `kind:` cause with the number its own sentence claims.
- The review brief names the mechanical pre-review, with `--kind` filled in from the branch and
  `--card` filled in from the item, and the reviewer's last line before the verdict is its output.
- `docs_review: skip` waives the review of a direct-lane Feature's docs-only branch, on the same
  terms as a Task's.
- Criterion 2's evidence cell, when the criterion fails, names the rework-cutting levers the
  product has off.
- One decision row recorded against each choice below; ADR 0003 is amended with nothing — it
  already says what holds.

**Out of scope**

- **Re-deciding ADR 0003.** It is accepted, it is dated, and `REPAIR_PREFIXES`,
  `score.repair_flags`, `score.repair_kinds` and criterion 2's evidence cell implement it. This
  Feature changes no line of `asf/scorecard/score.py` and no line of criterion 2's arithmetic.
- **`release.max_repair_per_feature`.** The threshold is 3 and stays 3. A Feature that moved the
  bar to meet the bar would be the one outcome the card cannot accept.
- **Skipping spec and plan review rounds.** They are the largest block of `review` sessions, and
  under ADR 0003 an item's *first* spec review is not repair, so dropping them would move spend
  (F-0224's subject) and not this ratio. A spec review is also the only read of a spec against
  its card; the mechanical half of it is what `asf review-checks` is for.
- **Re-landing the rest of F-0053's review brief** — its kind-aware `Pass 1 — mechanical` /
  `Pass 2` checklist split (`docs/specs/f-0053.md:390-399`). The current `review.md` carries the
  six code rows for every kind. That is F-0053's unfinished business and a far wider change than
  one command line; this Feature adds the command the same spec promised and nothing else.
- **Any new session kind.** `precheck` is already in `REPAIR_PREFIXES` (F-0224 S-36505) and this
  Feature creates no session that would carry it: the pre-review is a command the review session
  runs, per `docs/specs/f-0053.md:141` D10.
- **Writing the asf product's own configuration.** The products file is not in this repository.
  Turning `flags.docs_review: skip` on for `asf` is an operator act, recorded as a
  `NEEDS OPERATOR` line, and the gate row this Feature adds is what makes its absence visible
  afterwards.
- **`asf tune`.** Its `repair` signal is its own per-kind measure off the run registry
  (`asf/tune.py:183-216`, criterion 11), not `score.repair_flags`, and nothing here touches it.

**Preconditions**

- ADR 0003 is accepted and `PLANNED_FIRST = 'review'` (`asf/scorecard/score.py:54`) is its
  implementation. Every number below is the corrected count.
- `score.repair_flags(sessions)` must be given the **whole** sessions stream, not a window of it
  (`score.py:57-75`): the first review of an item may fall before the window. `window_row`
  (`:253-254`) and `diagnose.rank`'s per-Feature pass (`diagnose.py:226`) already do; the per-kind
  pass at `diagnose.py:176-183` is the one that does not.
- `release.gather` already carries `by_kind` to criterion 2 (`asf/release.py:808-809`), and
  criterion 2 already renders it (`:469`). Story 4 appends to that one f-string; it introduces no
  new key in `gather`'s dict except the levers it reads from the product itself.
- `conventions.Conventions.flag` (`asf/conventions.py:1324`), `.review_required`
  (`:1030`) and `.review_skip_under_lines` (`:1036`) are the three readers Story 4 needs, and
  `lane._conv(product)` (`asf/harvest/lane.py:322`) is how a `Product` yields them. `docs_review`
  is already a recognised flag (`asf/conventions.py:397`), so no validation changes.
- `DEFAULT_DOC_PATHS` (`asf/conventions.py:867`) means a product need not declare `doc_paths` for
  the waiver to apply; only `flags.docs_review: skip` must be set.
- `briefs.build`'s golden fixtures (`tests/test_briefs.py:163 GoldenBriefTest`) compare each
  brief's whole text, so Story 2 regenerates `tests/fixtures/briefs/golden/review.md` in the same
  change. Every placeholder in a template must be a context key and no placeholder may survive
  into a built brief (`tests/test_briefs.py:929 PlaceholderTest`).
- `conventions.branch_kind` (`asf/conventions.py`, `kinds()` at `:1209`) returns `spec`, `plan`,
  `code`, `fix`, `direct` or `legacy`; `reviews.KINDS` (`asf/reviews.py:17`) is
  `('spec', 'plan', 'code')`. The map between them is Story 2's D6.

## The design

### 1. `asf/scorecard/diagnose.py` — the diagnosis counts rework

`rank` (`:170`) builds each per-kind row from the sessions in the window. It gains the flags, over
the **whole** stream (precondition 2), and three keys (D1):

```python
sessions = [s for s in facts.sessions if score.in_window(s.get('ts'), start, end)]
flags = score.repair_flags(facts.sessions)
pairs = [(s, f) for s, f in zip(facts.sessions, flags)
         if score.in_window(s.get('ts'), start, end)]
...
for s, rep in pairs:
    k = score.session_kind(s)
    c = kinds.setdefault(k, {'name': k, 'usd': 0.0, 'sessions': 0, 'minutes': 0.0,
                             'repair': score.is_repair(k),
                             'repair_sessions': 0, 'repair_usd': 0.0})
    c['usd'] += score._num(s.get('usd'))
    c['sessions'] += 1
    c['minutes'] += score._num(s.get('minutes'))
    if rep:
        c['repair_sessions'] += 1
        c['repair_usd'] += score._num(s.get('usd'))
for c in kinds.values():
    c['share'] = round(c['usd'] / usd, 3) if usd else 0.0
    c['repair_share'] = round(c['repair_usd'] / usd, 3) if usd else 0.0
    c['usd'] = round(c['usd'], 2)
    c['repair_usd'] = round(c['repair_usd'], 2)
    c['minutes'] = round(c['minutes'], 1)
```

`repair` stays on the row: it is the kind-level fact ("could a session of this kind ever be
repair"), and it is what gates the cause. For every kind but `review` — the only kind
`PLANNED_FIRST` exempts — `repair_share == share` and `repair_sessions == sessions`, so no other
kind's numbers move (the same invariant F-0224 S-36505 demanded of `precheck`).

`causes` (`:281`) gates and speaks on the repair numbers (D2):

```python
for c in r['by_kind']:
    if c['repair'] and c['repair_share'] > t['kind_share'] and c['repair_usd'] >= t['kind_min_usd']:
        out.append(Cause(
            f"kind:{c['name']}", FACTORY, c['repair_share'], t['kind_share'], 'share of spend',
            f"Repair sessions '{c['name']}' take {c['repair_share'] * 100:.0f} % of session spend",
            f"{c['repair_sessions']} of {c['sessions']} '{c['name']}' sessions are rework and cost "
            f"${c['repair_usd']:,.2f} of ${r['usd']:,.2f} over {days} days "
            f"({c['minutes'] / 60:.1f} h for the kind); threshold {t['kind_share'] * 100:.0f} %."))
```

The key, the scope, the unit and the threshold are untouched; the reading and the detail change.
`metric` (`:249`) answers with the number the threshold compares (D3):

```python
if key.startswith('kind:'):
    name = key[len('kind:'):]
    for c in rank(facts, start, end)['by_kind']:
        if c['name'] == name:
            return c['repair_share'] if c['repair'] else c['share']
    return 0.0
```

`thresholds` (`:54`), the threshold values (`:25-26`) and the per-Feature pass (`:226-235`, which
already uses the flags) are unchanged.

**What an operator sees.** Before, over the card's window: `kind:review — Repair sessions
'review' take 17 % of session spend`, on 107 sessions. After: the cause appears only if the
**rework** reviews cross 15 % of spend, and its detail reads `9 of 107 'review' sessions are
rework and cost $…` — a number that falls when rework falls.

### 2. `asf/briefs/` — every review brief carries the mechanical pre-review

**`asf/briefs/build.py`** gains the map and the key (D6). Beside `delivery_checks` (`:582`):

```python
#: A branch kind → the `asf review-checks --kind` it is reviewed under (`reviews.KINDS`).
REVIEW_KIND = {'spec': 'spec', 'plan': 'plan', 'code': 'code', 'fix': 'code'}


def review_checks_cmd(product, facts, item_id):
    """The mechanical pre-review of the file this brief asks for: ``asf review-checks <path>
    --kind <k> --card <id>``. ``--kind`` comes from the branch's own prefix (D6), never from the
    reviewer; an unmapped or absent kind is ``code``, the widest checklist."""
    kind = REVIEW_KIND.get(preamble_mod.conventions(product).branch_kind(facts['branch'] or ''),
                           'code')
    return f"asf review-checks {facts['review_path']} --kind {kind} --card {item_id}"
```

and in `context` (`:487`, beside `delivery_checks`):

```python
'review_checks_cmd': review_checks_cmd(product, facts, item.get('id')
                                       or getattr(row, 'item_id', '') or 'none'),
```

**`asf/briefs/templates/review.md`** gains one block, between the verdict block's rules and
`THE REVIEW NEVER TOUCHES THE BRANCH`:

```
THE MECHANICAL PRE-REVIEW IS YOUR LAST ACT BEFORE THE VERDICT. Run it on the file you just
wrote, and read what it says:

    {review_checks_cmd}

It derives the verdict from your table alone. A fault it names — a row with no evidence, a
missing required check, no table at all — is a `BOUNCE` the factory would derive after your
session ended, which buys another whole round and finds nothing. Fix the file it names, by
`file:line`, and run it again until it is clean. Its last line goes in your final message.
```

Nothing else in the template moves: the table, its six rows, the verdict block's three keys and
the rounds rule are byte-identical. The template's existing last line gains the pre-review's
output:

```
Final message: the verdict block, the failing rows, the gate lines, and the pre-review's last line.
```

`tests/fixtures/briefs/golden/review.md` is regenerated in the same change (precondition 6), and
its diff is this block, the final-message line, and nothing else.

### 3. `asf/harvest/lane.py` — the waiver reaches the branch it applies to

`docs_only_task` (`:451`) admits a direct-lane Feature (D7, D8). Its guard becomes:

```python
from asf.feeder import rows as feeder_rows   # local: the feeder imports the lane
...
item = (items or {}).get(item_id) or {}
itype = item.get('type')
reviewed = itype in ('task', 'bug') or (itype == 'feature' and feeder_rows.is_direct(item))
if not reviewed or not writes or landing_class(product, writes) != DOCS:
    return False
```

`feeder_rows.is_direct` (`asf/feeder/rows.py:672`) is the one `lane: direct` predicate and is
reached by the same deferred import `small_task` (`asf/harvest/lane.py:440-448`) already uses —
no second predicate, no new constant. The rest of the function is unchanged: `writes:` must be
declared, must all land under a docs root (`landing_class`), `lane.review.docs` must not be
`required`, and the branch's `files`, when given, must stay inside the declared `writes:`.

Its docstring gains the one sentence that says what it now covers: *"a direct-lane Feature's own
branch counts too — it is the one branch a Feature is reviewed on
(`asf/feeder/rows.py:1093-1096`)."*

Neither call site changes. `rows.lane_rows` (`:1102`) already asks for every item it raises a
review row for, and the waived row already becomes `PUSHED_LAND` with
`why='docs-only writes: no review (flags.docs_review)'` (`:1103-1104`); the lane's own waiver
(`asf/harvest/lane.py:1776-1777`) already reads the same function and already writes
`review_waived = 'docs-only writes: flags.docs_review skips the review'`. With the flag unset —
every product's default — the answer is `False` for a Feature exactly as it is today.

### 4. `asf/release.py` — criterion 2 names the lever that is off

A reader beside the criterion (D9, D10):

```python
#: The settings that, left off, buy review rounds criterion 2 then counts. Named, never set.
REPAIR_LEVERS = (
    ('flags.docs_review: skip',
     lambda c: str(c.flag('docs_review') or '').strip().lower() != 'skip'),
    ('lane.review.docs: none', lambda c: c.review_required('docs')),
    ('review.skip_under_lines', lambda c: not c.review_skip_under_lines()),
)


def repair_levers(product):
    """The rework-cutting settings ``product`` has off, in :data:`REPAIR_LEVERS` order — ``[]``
    when every one is on, or when the product yields no conventions to read."""
    conv = getattr(product, 'conventions', None)
    if conv is None:
        return []
    return [name for name, off in REPAIR_LEVERS if off(conv)]
```

and criterion 2 (`:459-469`) appends one clause when it is **not** met:

```python
ok = rp['per_feature'] is not None and rp['per_feature'] <= cfg['max_repair_per_feature']
ev = (f"{rp['sessions']} repair sessions / {rp['landed']} Features landed in {w:g} d = "
      f"{'—' if rp['per_feature'] is None else format(rp['per_feature'], 'g')}"
      + (' (' + ', '.join(f'{k} {n}' for k, n in kinds.items()) + ')' if kinds else ''))
levers = [] if ok else repair_levers(product)
if levers:
    ev += '; off: ' + ', '.join(levers)
out.append(Criterion('repair', name, ok, ev))
```

The met case, the `n/a` case and the `by_kind` clause are byte-identical to today. A failing
criterion on a product with every lever on gains nothing, and says so by saying nothing.

**What the cell reads.** Over the card's own window, by the corrected count and with the asf
product's levers as they stand:

```
| Repair load (≤ 3 per Feature) | ✗ | 28 repair sessions / 17 Features landed in 7 d = 1.6 (correct 16, review 9, adjudicate 3); off: flags.docs_review: skip |
```

— the kinds that drive the ratio, and the thing to turn on, in one cell.

### 5. What is not a code change: the two operator acts

Acceptance box 2's first half is configuration on the factory host, not in this repository:

- `flags: {docs_review: skip}` on the `asf` product's entry in the operator's products file —
  the lever §3 finishes.
- Nothing for the pre-review: §2 makes it unconditional for every review brief of every product.
  There is no flag to set and nothing to turn on.

Both are recorded as `NEEDS OPERATOR` lines (Records, below), with the read-only command that
shows the state they are in.

## Acceptance tests

Every block runs from the repository root, on a clean checkout, with no factory host and no
session ledger.

**The diagnosis counts rework, not the planned first review (S-52604)**

```bash
python3 -m unittest -v tests.test_scorecard.DiagnosisCountsReworkTests \
    tests.test_scorecard.PlannedFirstReviewTests tests.test_scorecard.RepairPrefixTests
```

Covers: a stream of one `review` and one later `review` on the same item gives that kind
`sessions: 2, repair_sessions: 1`, and `repair_usd` is the second session's spend alone;
`repair_share` is that spend over the window's whole spend; for `correct`, `adjudicate`,
`rebase`, `remerge`, `relaunch`, `bounce`, `revise`, `hotfix` and `precheck`,
`repair_share == share` and `repair_sessions == sessions`; for `coder`, `spec` and `plan`,
`repair` is `False` and `repair_sessions` is 0; `share`, `usd`, `sessions`, `minutes` and the
`by_kind` ordering are identical to the pre-change values over the same facts; a `kind:review`
cause is **not** raised when only the first reviews cross `kind_share`, and **is** raised when the
second rounds do; `metric(…, 'kind:review', …)` returns `repair_share` and
`metric(…, 'kind:coder', …)` returns `share`; the existing invariant holds — `metric(…,
'kind:review', …)` is the same number with and without `precheck` in `REPAIR_PREFIXES`
