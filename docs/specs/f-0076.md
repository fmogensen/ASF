# F-0076 — Session identity: every asf worker is distinguishable from every other, and from sessions that are not asf's

Epic: E-0001 — ASF 0.1 — a working factory. Branch: `spec/F-0076`.

Today a worker is known by its bare job name inside one product's registry. `spawn` writes the
launch line to `~/.ASF/state/<product>/sessions.jsonl` (`asf/workers/spawn.py:266-273`), and the
session gets `ASF_PRODUCT` and `ASF_JOB` in its environment (`asf/workers/runtime.py:91`). Every
reader keys on `job` inside that one file:

- the pool's load is `live_sessions(product)`, so it counts one product's sessions only
  (`asf/workers/pool.py:202`);
- the wave's "already running" check is a set of bare job names (`asf/workers/wave.py:33`);
- health, stall, the sessions view and harvest's reap hold call a run alive when `kill(pid, 0)`
  succeeds (`asf/workers/health.py:47-58`), whatever process has that pid now.

As a result, the second product's wave on the same account launches past the cap, and a session
the operator started by hand is invisible to the wave. A reused pid can keep a dead run "live" in
health and stall. A commit on a worker branch carries nothing that names the session that made
it.

After this change every run has one **session id**, `<product>/<job>@<started>`. It is on the
registry line, in the process environment, in the job log and as a trailer on every commit the
session makes. The pool reads the machine's process table and counts every session running on
each account: this product's, other products' and ones asf did not start. A run is alive only
while the process at its pid still carries its id.

## Decisions

### In

- **The session id.** `<product>/<job>@<YYYYMMDDTHHMMSSZ>`, minted once per launch in `spawn`
  (and in `stall.correct_once` for the cold retry) from the same instant as the line's
  `started`.
- **The registry line** gains `session` and `product`. A line written before this change has
  neither. The reader derives both from the registry's own directory and the line's `started`,
  so every run, old or new, has an id. There is no migration.
- **The process.** `ASF_SESSION=<id>` is set in the session's environment next to `ASF_PRODUCT`
  and `ASF_JOB`. It joins `hermetic.CALLER_IDENTITY`, so it never leaks from a tick into a gate
  or another child.
- **The log.** Before the runtime starts, each run's segment of `logs/jobs/<product>/<job>.jsonl`
  opens with one `{"type": "asf", "subtype": "session", ...}` line.
- **Commits.** Every commit a session makes carries an `ASF-Session: <id>` trailer. A per-product
  git hook dir, handed to the session through the environment's `GIT_CONFIG_*`, stamps the
  trailer and then runs the product repo's own hook of the same name.
- **Observation.** A new `asf.workers.observe` lists the sessions running on this machine. For
  each one it gives the pid, the account (from the process's `CLAUDE_CONFIG_DIR`/`HOME`), the
  `ASF_SESSION` if any, and whose it is: `asf` or `foreign`. There are three sources: the
  process table (default), an operator command (`worker_pool.sessions_command`) and a fake.
- **Pool load** counts every live registry run across every product under `ASF_HOME/state/`, plus
  every observed session on a pool account that no registry run accounts for. The wave's
  "already running" check compares `(product, job)`.
- **Alive means the same session.** When observation is readable, a run is alive only if a
  session at its pid carries its id. Health, stall, the sessions view and harvest's reap hold
  all use that rule.
- **Visibility.** `asf workers sessions [--json]` prints every observed session with its owner.
  `asf sessions` gains an **Other** group listing the sessions on the pool's accounts that are
  not this product's.
- **History.** The `sessions` metrics event gains `session`.

### Out

- **Acting on a foreign session.** Nothing stops, signals, registers, adopts or records a session
  that is not asf's. The pool counts it and the view lists it, and that is all.
- **Adopting a legacy launcher's session** into a registry (for example one that used `asf workers
  reserve-id`). It shows as `foreign` unless its launcher sets `ASF_SESSION`. Adopting it is a
  later card.
- **A harvest gate on the trailer.** Harvest does not refuse a commit without `ASF-Session`. The
  trailer is evidence, not a gate.
- **Quota.** `quota_command` already reads the account's own windows, which include every session
  on the account, asf's or not (`asf/workers/quota.py:3-7`). Nothing changes there.
- **Per-run metrics history.** `sessions_from_registry` still emits the latest run per job
  (`asf/metrics/metrics.py:826-855`). This card adds the id to that event. It does not add one
  event per run.
- **Renaming paths.** Worktree, brief and log paths stay `<product>/<job>`. They are already
  product-scoped. The id lives inside the files, not in their names.
- **Sessions of other OS users.** Their environment cannot be read. They are listed `unattributed`
  and count against no account.

### Preconditions

- The runtime runs the agent binary directly (`subprocess.Popen(build_command(...))`,
  `asf/workers/runtime.py:168`), so the registry's `pid` is the session process itself, not a
  shell around it. Checked against `origin/main` at `b0a50d2`.
- `hermetic._git_config` appends `GIT_CONFIG_KEY_n`/`VALUE_n` after whatever the base carried
  (`asf/hermetic.py:37-50`), and `runtime.build_env` goes through `hermetic.build`. So adding a
  `core.hooksPath` pair there reaches every `git` the session runs. This needs git ≥ 2.31
  (`GIT_CONFIG_COUNT`). The machine that wrote this spec has 2.54.
- `git interpret-trailers --in-place --if-exists doNothing --trailer` exists in every git that has
  `GIT_CONFIG_COUNT`.
- **Not verified here:** the exact output of `ps axeww -o pid=,ppid=,command=` on the operator's
  machines. The spec session was not allowed to run `ps`. On darwin and procps this is the BSD
  form that prints the argv followed by the environment. The process-table source is tested
  against a fake `ps` on `PATH`. `worker_pool.sessions_command` is the fallback for a machine
  where the form differs.
- `config.yaml` is one file per `ASF_HOME`, not one per product (`asf/env.py:192`). So every
  product on the machine shares the same `worker_pool.accounts`, and summing load across products
  is summing load on the same accounts.

### Choices

| # | Choice | Chosen | Against | Why |
|---|---|---|---|---|
| D1 | Id format | `<product>/<job>@<YYYYMMDDTHHMMSSZ>` | a UUID; `<product>.<job>.<n>` (run ordinal) | You can read it without a lookup, because product, job and run are all in it. It is unique: `may_launch` refuses a second live run of a job, so two launches of one job never happen in the same second. A product name is a file name and holds no `/`. The parse splits on the first `/` and the last `@`. An ordinal would need a registry count under a race. |
| D2 | Old registry lines | derive the id on read (`product` from the registry's directory, `started` from the line) | a one-shot migration that rewrites the append-only file | The registry is append-only, and derivation gives every run an id with no rewrite. |
| D3 | How commits carry the id | a `prepare-commit-msg` hook that adds the trailer. It lives in a per-product hook dir, set as `core.hooksPath` through the session's `GIT_CONFIG_*`. Every client hook name in that dir passes through to the product's own hook. | ask the session in the brief to add a trailer; set the committer identity to the id; install a hook in the product repo | A brief instruction gets forgotten. The committer identity feeds the `Signed-off-by` line, and the sign-off is the record of who did the work. A hook in the repo would fire for the operator's own commits too. The environment reaches only the session's processes. |
| D4 | Finding the product's own hooks from the shim | at hook time: `core.hooksPath` read with `GIT_CONFIG_COUNT` unset, relative to `git rev-parse --show-toplevel`; otherwise `$(git rev-parse --git-common-dir)/hooks` | freeze the path into the shim at spawn | The product can change its hooks path (`asf init` sets `.githooks`, `asf/init.py:229`) without a respawn. |
| D5 | How sessions are observed | a `SessionSource` like `QuotaSource`: `process` (default: one `ps axeww -o pid=,ppid=,command=` call), `command` (`worker_pool.sessions_command`, one JSON line per session), `fake` | read the runtime's own transcript files under each account's config dir | Transcripts are the vendor's private layout, and a recently written file does not show a live process. The process table is the ground truth for "running now". The command source keeps a machine whose `ps` differs working without a code change. |
| D6 | Which processes are sessions | the command matches `worker_pool.session_match` (default `^(\S*/)?<binary>(\s\|$)`, `<binary>` = `worker_pool.binary` or `claude`), and no ancestor (by ppid) also matches | every process with `ASF_SESSION` in its env | A session's tools (shell, git, test runners) inherit its environment. Counting them would count one session many times. A nested agent under a session is part of that session. |
| D7 | Which account a session is on | `CLAUDE_CONFIG_DIR` (realpath) equals the account's `config_dir`. For an account with no `config_dir`: `HOME` equals its `home`. For an account with neither: `HOME` equals the tick's own `HOME` and no `CLAUDE_CONFIG_DIR`. No match → `account: null`. | attribute unknowns to the default account | A session on no pool account costs the pool nothing. Guessing would take capacity away for nothing. |
| D8 | Whose a session is | `asf` when `ASF_SESSION` is set, `foreign` otherwise. An `asf` session whose id no registry holds as live (a lost or already-ended line) is still `asf` and still counts. | treat an unregistered `asf` session as foreign | It is ours and it is running. It takes a slot either way. Health is what reconciles the registry. |
| D9 | Pool load | live registry runs of every product, plus observed sessions on a pool account whose pid and id match no live registry run | observed sessions only | Launches inside one wave are not in the process table yet (`Pool.take`). A run launched a moment ago may not show in `ps` yet, and the registry covers it. The union never counts one session twice, because both sides carry the pid. |
| D10 | Observation unreadable (`ps` missing or failing, command non-zero) | the pool counts registry runs across products. The wave prints `pool: sessions unreadable (<why>) — counting registered sessions only`. Alive falls back to `kill(pid, 0)`. | refuse to launch, the way an unreadable quota refuses | The quota guard still stands between the pool and an exhausted account. Stopping the whole factory because `ps` failed trades one hidden-load risk for a total outage. The printed line makes the degraded count visible. |
| D11 | Alive | observed session at the run's pid carrying the run's id. A run recorded without a `session` field (older than this change) is alive while any observed session sits at its pid. | `kill(pid, 0)` (today) | A reused pid is someone else's process. Judging it as ours keeps a dead run live, holds its slot, and has stall report a session asf did not start. |
| D12 | The wave's "already running" | `(product, job)` pairs from the pool's live list | bare job names | With load pooled across products, `spec-f-0001` in product `a` must not block `spec-f-0001` in product `b`. |
| D13 | Where the hook dir lives | `~/.ASF/state/<product>/githooks/`, written by `spawn` and rewritten when its content differs | one dir for the whole machine | Everything a spawn writes lives under `state/<product>/`. A per-product dir keeps a product's reset from touching another product's sessions. |
| D14 | The log's identity line | written by the runtime before it starts the process, `type: asf` | a field in the brief | Log readers already skip unknown types (`read_result` looks only at `system/init` and `result`, `asf/workers/runtime.py:120-123`). The log is the file every later reader opens by job. |

## The design

### The id — `asf/workers/lifecycle.py`

```python
def session_id(product, job, started):     # started: '2026-09-22T10:15:00Z'
    return f"{product}/{job}@{started.replace('-', '').replace(':', '')}"

def parse_session(sid):                    # -> (product, job, stamp) | None
    ...                                    # first '/', last '@'
```

- `read_lines(path)` stamps each launch line that has no `session` with
  `product = basename(dirname(path))` and `session = session_id(product, job, started)`. Update
  lines inherit them through `fold`. A registry at a path whose parent is not a product state
  dir (a test's temp file) takes `product` from the line, and gets no id if the line has none
  either.
- New `live_all(state_root)` → `[run]` for every `state/*/sessions.jsonl`. Each run carries
  `product` and `session`.

### Launch — `asf/workers/spawn.py`, `asf/workers/runtime.py`, `asf/hermetic.py`

- `spawn`: `started = pool_mod.now_iso()` is taken **before** `runtime.run` and used for both the
  id and the line (today it is taken after, `spawn.py:269`). `sid = session_id(product.name,
  row.job, started)`. `githooks.ensure(product)` returns the hook dir. The `Job` gets
  `env={'BACKLOG_ID_RANGE': ..., 'ASF_SESSION': sid}` and `hooks_dir=<dir>`. The record gains
  `session` and `product`.
- `stall.correct_once`: the same for the retry's line (`<job>-correction`, its own `started`).
- `runtime.Job` gains `session` (read from `env['ASF_SESSION']`) and `hooks_dir`.
- `runtime.build_env`: `identity` gains `ASF_SESSION` when the job has one. When `hooks_dir` is
  set, `hermetic.build(..., git_config=[('core.hooksPath', hooks_dir)])` is called.
- `hermetic.build` gains `git_config=()`, appended after `init.defaultBranch`.
  `CALLER_IDENTITY` becomes `('ASF_PRODUCT', 'ASF_JOB', 'ASF_SESSION', 'BACKLOG_ID_RANGE')`.
- `ClaudeCodeRuntime.run` and `FakeRuntime.run` both write, before the process or the scripted
  lines:
  ```json
  {"type": "asf", "subtype": "session", "session": "<id>", "product": "<p>", "job": "<job>", "started": "<iso>"}
  ```
  They write it only when the job has a session. A job built by hand without one writes nothing
  new.

### Commit trailer — new `asf/workers/githooks.py`

- `HOOKS`: the client-side hook names from githooks(5): `applypatch-msg pre-applypatch
  post-applypatch pre-commit pre-merge-commit prepare-commit-msg commit-msg post-commit
  pre-rebase post-checkout post-merge pre-push post-rewrite reference-transaction pre-auto-gc
  post-index-change push-to-checkout sendemail-validate`.
- `ensure(product) -> dir`: writes `state/<product>/githooks/asf-hook` (mode 755) and one file per
  name in `HOOKS` that `exec`s `asf-hook` with the hook name. It rewrites only files whose content
  differs.
- `asf-hook` (POSIX sh):
  1. `name=$1; shift`.
  2. If `name` is `prepare-commit-msg` and `ASF_SESSION` is set: `git interpret-trailers
     --in-place --if-exists doNothing --trailer "ASF-Session: $ASF_SESSION" "$1"`.
  3. Find the product's own hooks dir: `own=$(env -u GIT_CONFIG_COUNT git config --get
     core.hooksPath)`. If it is relative, anchor it at `git rev-parse --show-toplevel`. If it is
     empty, use `$(git rev-parse --git-common-dir)/hooks`. If `own` resolves to this dir, there
     is nothing to chain.
  4. If `$own/$name` is executable, `exec "$own/$name" "$@"` with stdin passed through, and its
     exit code is the hook's. Otherwise exit 0.
- `--if-exists doNothing` makes an amend, or a rebase that re-runs the hook, leave one trailer.
  Harvest's rebase keeps messages as they are.

### Observation — new `asf/workers/observe.py`

```python
Observed = namedtuple('Observed', 'pid ppid account session product job owner cwd')
# owner: 'asf' | 'foreign';  account: an Account name or None

class SessionSource:            # .read(accounts) -> [Observed]  (raises ObserveError)
class ProcessSource(SessionSource)   # ps axeww -o pid=,ppid=,command=
class CommandSource(SessionSource)   # worker_pool.sessions_command; one JSON object per line:
                                     # {"pid", "ppid", "env": {CLAUDE_CONFIG_DIR, HOME, ASF_SESSION}}
class FakeSource(SessionSource)      # a list of dicts, for tests

def source_from_config(cfg)
def read(cfg, accounts) -> ([Observed], why)   # why = '' or the ObserveError text
def identity_alive(observed, runs)   # -> callable(pid) -> bool   (D11)
```

- `ProcessSource` parses each line as `pid ppid rest`. A line is a session when `rest` matches
  `session_match` (D6). It drops a session that has an ancestor which is also a session, walking
  `ppid` through the full table. The environment is read from the `KEY=VALUE` tokens of `rest`
  for `CLAUDE_CONFIG_DIR`, `HOME`, `ASF_SESSION`, `ASF_PRODUCT` and `ASF_JOB`. When a key appears
  more than once, the last one wins, because the environment follows the argv. A non-zero exit
  or a missing `ps` raises `ObserveError`.
- The account is assigned as in D7. `product` and `job` come from `parse_session(ASF_SESSION)`.
- `identity_alive(observed, runs)`: `by_pid = {o.pid: o}`. For a pid that belongs to a run in
  `runs`: alive iff `by_pid[pid]` exists and (`run.session` equals `o.session`, or the run has no
  recorded `session`). For a pid that belongs to no run: alive iff it is in `by_pid`.

### Pool and wave — `asf/workers/pool.py`, `asf/workers/wave.py`

- `Pool.from_config(cfg, product, quota_source=None, session_source=None)`:
  - `registered = lifecycle.live_all(<ASF_HOME>/state)`.
  - `observed, why = observe.read(cfg, accounts)`.
  - `extra` = the observed sessions with an account whose pid is not a registered run's pid and
    whose `session` is not a registered run's session.
  - `live = registered + [{'account', 'model': None, 'product', 'job', 'session', 'pid',
    'owner'} for o in extra]`.
  - `self.unreadable = why`.
- `Pool.take` records `product` too. `Pool.load(account, model=None)` is unchanged. A foreign
  session has `model: None`, so it counts toward `cap` and not toward a per-model `caps` ceiling.
  Its model is not known.
- `wave`: `running = {(s.get('product'), s.get('job')) for s in pool.live}`, and a row waits
  `already running` when `(product.name, row.job)` is in it. When `pool.unreadable` is set, the
  wave prints the D10 line once, before the first row.

### Alive — `asf/workers/health.py`, `stall.py`, `asf/views/sessions.py`, `asf/harvest/harvest.py`

- `health(product, fix=False, alive=None, ...)` and `stall(product, ..., alive=None, ...)`: when
  `alive` is None they build `observe.identity_alive(observed, runs)` over the product's runs. If
  observation is unreadable they fall back to `pid_alive`. An `alive` passed by a test is used as
  given.
- `views.sessions.live_rows` and `harvest.reap_hold` use the same function.
- Nothing in these modules ever reads or acts on an observed session that no run of this product
  owns (D8 and Out).

### Visibility — `asf/workers/__init__.py`, `asf/views/sessions.py`

- `asf workers sessions [--json]`. There is one line per observed session:
  ```
  4242  acct-a   asf      asf/spec-f-0076@20260922T101500Z
  5150  acct-a   foreign  —
  6001  —        foreign  — (unattributed)
  ```
  After the sessions comes `load: acct-a 3/3 (asf 2, foreign 1)` for each account. Exit 0. It
  exits 2 with `sessions: unreadable — <why>` when observation fails.
- `asf sessions`: a new **Other** group after **Dead**, with the columns Session, Account, Owner
  and Pid. It lists the observed sessions on a pool account that are not this product's. The
  header line counts them: `… · N other`.

### History — `asf/metrics/metrics.py`

- `session_event` adds `'session': record.get('session')`. The id holds only the product's own
  name and a job name, both already in that product's record. The account stays an index
  (B-0023).

## Acceptance tests

The suite is stdlib `unittest`, run from the checkout root. Tests use the temp `ASF_HOME` and
bare-origin repo of `tests/test_workers.py` (`Home`) and the fake runtime. Where a real process
table is involved, a stub `ps` on `PATH` prints a fixed table (the `fake_launchctl` pattern), so
no test depends on what is running on the machine.

## Records

- **Registry** (`~/.ASF/state/<product>/sessions.jsonl`): every launch line gains `session` and
  `product`. Update lines are unchanged. Older lines are read with a derived id (D2). The file
  stays append-only.
- **Job log** (`~/.ASF/logs/jobs/<product>/<job>.jsonl`): each run's segment opens with the
  `type: asf, subtype: session` line.
- **Hook dir** (`~/.ASF/state/<product>/githooks/`): `asf-hook` plus one pass-through file per
  client hook name. Nothing is written into the product repo or its `.git`.
- **Commits**: `ASF-Session: <id>` trailer on every commit made in a session, next to the
  existing `Signed-off-by`. It survives harvest's rebase onto the trunk, so `git log
  --format=%(trailers:key=ASF-Session)` on `main` says which run wrote each line.
- **Process environment**: `ASF_SESSION=<id>`, never inherited by a child of a tick
  (`CALLER_IDENTITY`).
- **Metrics** (`metrics/sessions/<day>.jsonl` in the product's record): each event gains
  `session`. The account stays an index.
- **Printed lines**: the wave's `pool: sessions unreadable (<why>) — counting registered sessions
  only`, and `asf workers sessions`' table and `load:` lines.
- **Config** (`config.yaml`, all optional): `worker_pool.sessions: process | command | fake`
  (default `process`), `worker_pool.sessions_command`, `worker_pool.session_match`.
  `docs/config.example.yaml` documents all three.
- **Never written**: anything about a foreign session. It appears only in printed output, and is
  never stored in a registry, a log or the record.

## Stories

- S-8150: Every run has one session id — minted at launch, on the registry line with its product, derived for older lines — acceptance: `python3 -m unittest tests.test_session_identity.SessionIdTest tests.test_session_identity.LaunchIdentityTest.test_spawn_writes_session_and_product tests.test_session_identity.LaunchIdentityTest.test_correction_retry_has_its_own_id -v`

- S-8152: Every commit a session makes carries an `ASF-Session` trailer, and the product's own hooks still run — acceptance: `python3 -m unittest tests.test_session_identity.CommitTrailerTest -v`
- S-8153: The pool observes every session on the machine and says whose it is and which account it is on — acceptance: `python3 -m unittest tests.test_session_identity.ObserveTest -v`
