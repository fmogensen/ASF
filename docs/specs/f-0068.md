# F-0068 — the trigger is a number, and the number does not exist yet

The card's first sentence is *not now*. Its second is a trigger: **a week in which the quota guard
held back ready work on three or more days, measured from the tick stream's refused launches.**
Read the tick stream and that measurement is not there. `SCHEMAS['ticks']` has five counters —
`launches`, `merges`, `stalls`, `refusals`, `relaunches` (`asf/metrics/metrics.py:134-140`) — and
`refusals` is the approvals hook's count, not a launch the pool would not make
(`asf/tick/step_health.py`, `asf/approvals.py:626`). The stream's one quota field, `quota`, is
written `{}` by every live tick (`asf/tick/tick.py:614`) and is filled only by the one-shot
importer of a pre-asf runner's logs (`asf/metrics/import_sessions.py:136-138`). So the trigger as
the card words it cannot fire, and cannot fail to fire either: nobody can tell.

Meanwhile the factory *does* hold the guard back-pressure, twice a pass, and throws it away. The
wave step computes every Ready launching row the wave did not start, with a reason for each
(`left_out`, `asf/tick/step_wave.py:359-383`), prints them, and keeps no count. The wave itself
returns `(launched, waits)` and its caller discards the second (`launched, _waits = _wave(...)`,
`:763`). The pool reads each account's band once per wave and memoises it (`Pool.usage`,
`asf/workers/pool.py:343-346`), and `capacity.usable_slots` turns those bands into a seat count —
`0` at stop, `1` in cooldown, `cap` when free (`asf/capacity.py:202-221`). Every term the card's
trigger needs is already in hand, once per tick, at no extra cost. None of it survives the tick.

This Feature writes the two numbers down, gives them a rule, and prints the rule's answer on the
one page an operator reads daily. It does not build a hosted runtime, and it does not decide
anything about one. It also builds the instrument the second acceptance needs — the thing that
turns two runs of one Feature into **cost per Task** and **rounds per pull request** — because an
acceptance that says "compared" with nothing that does the comparing is not an acceptance. The
comparison is throwaway code under `tools/spike/f-0068/`, exactly as F-0065's probe harness is
(F-0065 D8): committed so it can be re-run, named for deletion in the document it produces.

The shape of this card is therefore: **measure now, run later.** Everything in §2.1–§2.5 ships and
runs on every tick from the day it lands. §2.6 and §2.7 ship as an instrument and a protocol that
sit idle until the trigger in §2.4 fires, and the operator who reads that line is the one who
starts the run.

## 1. Decisions

### 1.1 In

- **Two counters on the `ticks` stream, `quota_held` and `quota_seats`** (§2.3). `quota_seats` is
  how many seats the quota guard had taken across the pool when this tick's wave read it —
  `Σ cap` less `capacity.usable_slots`' sum, off the bands the pool already read. `quota_held` is
  `min(ready rows that did not launch, quota_seats)`: the ready work the guard's seats could have
  taken. Both are counts read off the pass; the `min` is arithmetic. `quota_held > 0` means, and
  only means, *ready work waited while the guard held seats* — which is the card's sentence, with
  no judgement in it.
- **`Pool.banded_seats()`** (§2.1) — `(banded, caps)` over the accounts this pool holds, from the
  readings it has already memoised: per account `cap` at stop, `cap − 1` in cooldown, `0` when
  free. No new quota read, no subprocess, no file. A test pins `caps − banded` equal to
  `capacity.usable_slots` over the same config, so the two readings of one fact cannot drift.
- **`wave(..., stats=None)`** (§2.1) — one new keyword. Given a dict, the wave fills
  `banded_seats` and `pool_caps` from the pool it built. Every existing caller passes nothing and
  is untouched (D3).
- **`ready_waiting`, counted by subtraction** (§2.2). The wave step already derives every Ready
  launching row for `left_out`; that derivation becomes its own function, `ready_rows`, and the
  count is `ready launching rows − held by a merge hold − already running − launched this wave`.
  No wait reason is parsed, and no reason string becomes an interface.
- **The rule, pure: `quota_pressure(ticks, day, window=7, need=3)`** (§2.4). Over the ticks of the
  `window` calendar days ending at `day`: a day shows pressure when any of its ticks carries
  `quota_held > 0`; the trigger has fired when `need` or more days do. Returns
  `(fired, days, held, seats, evidence_days)`. No clock of its own, no product, no file — `day` is
  an argument, the events are an argument, and a day with no tick at all is *no evidence*, counted
  neither for the trigger nor against it.
- **The measured line: a `quota pressure` row in the daily scorecard** (§2.5). It names the count,
  the verdict, and the days themselves — `4 of the last 7 days held ready work back — the trigger
  has fired`, with the dates and the totals in the note. `render_daily` reads the week of ticks it
  already computes (`week = days_back(day, 7)`, `asf/metrics/metrics.py:719`) and hands it to
  `scorecard_rows` as a new `ticks7` keyword. One row, in the table that exists.
- **`lane` on the `sessions` stream** (§2.6, D7) — `'local' | 'cloud' | <the runtime's own lane> |
  null`, filled by `session_event` from the registry's `runtime_lane` marker
  (`asf/workers/pool.py:206-212`), `'local'` when it carries none. Without it the comparison
  cannot be computed from the record at all: the record carries the account only as an index
  (`account_index`, B-0023), and which lane ran a session is nowhere on the line. `null` is the
  honest reading of a line written before this card, and every reader says `unknown` for it rather
  than calling it local.
- **The comparison instrument, `tools/spike/f-0068/compare.py`** (§2.6) — over a backlog
  checkout's own streams, for one Feature, grouped by `lane`: sessions, Tasks landed, Tasks not
  landed, metered USD, the four token dimensions, **cost per Task**, branches, and **rounds per
  pull request** (the mean and median of the highest round each branch reached). Markdown out,
  `--json` for a test, a committed fixture pair of stream files so the numbers are provable with
  no run at all.
- **The instrument refuses a half comparison** (§2.6, D9) — `--check` exits 1 when either lane
  landed no Task, when either lane's sessions carry no `usd`, or when one lane's rows carry
  `lane: null`. A table with one side missing is not a comparison, and a number computed from a
  lane that reported no cost is a zero pretending to be free.
- **The metered USD is labelled notional for a flat-cost lane** (§2.6, D8). The local pool is paid
  for by subscription; its `usd` is what the runtime's own result line reports, which is an
  API-equivalent price, not money that moved. The table prints it in a column headed
  `USD (metered)` and the document's stamp says, in one sentence, which lane's figure is money and
  which is a price list. The tokens are printed beside it, four dimensions, never summed
  (`asf/metrics/metrics.py:402-412`), because tokens are the one term both lanes measure the same
  way.
- **The run protocol, `compare.py --protocol`** (§2.7) — the checklist the operator works through
  when the trigger fires: the same plan as it stood at one base sha, the same models per role, the
  same review gate, the two runs never concurrent, the hosted run as a shadow on a scratch remote
  that lands nowhere, and the confounds named rather than hidden. It prints; it does not enforce.
- **The document's shape, and where it goes** — `docs/research/hosted-runtime-vs-the-local-pool.md`,
  written **when the run happens**, not now: the stamp (base sha, dates, host, runtime versions),
  the table `compare.py` printed, the confounds, and the one recommendation. `docs/research/` is
  where a measurement with a date lives (F-0065 D11).

### 1.2 Out

- **No hosted runtime, no new lane, no adapter, no vendor.** Nothing under `asf/workers/` gains a
  runtime, `cloud.runtime` gains no value, and no provider is named anywhere — `tools/check_generic.sh`
  forbids a vendor name in a tracked file and the spec obeys it as the product does. The card says
  *not now*, and this Feature is what makes *not now* an answer with a date on it instead of a
  shrug.
- **The trigger fires nothing.** No Bug is filed, no item is unparked, no card is minted, no
  session is launched, no state is written. It is a row on a page a human reads. The card's own
  next step is a human's decision to spend money with a second vendor, and this factory does not
  make that decision from a counter.
- **No new metrics stream and no new event kind.** `STREAMS` stays the five it is
  (`asf/metrics/metrics.py:41`); two `int` keys join `ticks` and one `str|null` joins `sessions`.
  No `ctx.event` kind is added.
- **`ticks.quota` is not filled.** It is declared, empty on every live tick, and filling it would
  put an account name in a record that deliberately carries only an index (B-0023,
  `account_index`, `asf/metrics/metrics.py:1537`). It stays empty and this card adds its own keys
  beside it rather than repurposing it.
- **No wait reason becomes an interface.** `REASON_NO_QUOTA`, `REASON_COOLDOWN`, `full_reason`'s
  clauses and the headroom miss stay what they are — sentences for an operator
  (`asf/workers/pool.py:64-68`, `:513-530`). Nothing here parses them, so nothing here breaks when
  one is reworded (D2).
- **No quota reading is added and no extra subprocess is run.** `CommandQuotaSource.read` is a
  subprocess per account (`asf/workers/quota.py:186-206`); this card reads only what the wave's own
  pool has already memoised. A tick costs exactly what it costs today.
- **`capacity.usable_slots`, `fair_share` and `resolve` are untouched.** The seat arithmetic is
  read from the pool, not recomputed in `capacity`, precisely so `resolve`'s zero quota reads under
  a single active product stay zero (`asf/capacity.py:354-356`: `fair_share` returns before reading
  anything when fewer than two products are active).
- **No threshold is configurable.** Three days in seven is the card's own sentence, and it is a
  trigger for one decision, once. A key that lets an operator tune the trigger for the spike they
  have not yet run is configuration with nobody to configure it (D6).
- **Nothing is backfilled.** Ticks written before this card carry neither counter, and no pass
  invents one for them. The scorecard row says so in as many words when the window holds no tick
  that carries the key, rather than reading `0 of 7 days` and looking like a calm week (D5).
- **The Feature is not run.** No session is launched by this card, no account with a second vendor
  is created, no money is spent. §2.7 is a checklist and §2.6 an instrument; the run is the
  operator's, after the line in §2.5 says the trigger fired.
- **Rounds are not redefined.** `derive_round` reads `-r<n>` off the job name
  (`asf/metrics/metrics.py:193-196`) and one lane branch is one pull request in this factory. The
  instrument reports what those two facts give; it does not invent a second notion of a round.

## 2. The design

### 2.1 The seats the guard took — `asf/workers/pool.py`, `asf/workers/wave.py`

One method on `Pool`, over the readings it already holds:

```python
def banded_seats(self):
    """``(banded, caps)``: the seats the quota guard has taken across this pool right now,
    and the seats the pool would have with every account free.

    Per account: ``cap`` at stop, ``cap - 1`` in cooldown, ``0`` when free — the complement of
    :func:`asf.capacity.usable_slots`' sum over the same accounts, so ``caps - banded`` is that
    figure exactly (§3.2 pins them). Read off :meth:`usage`, which is memoised per instance
    (:meth:`band`), so this costs no reading, no subprocess and no file."""
    caps = sum(a.cap for a in self.accounts)
    banded = 0
    for a in self.accounts:
        state, _why = self.band(a)
        banded += a.cap if state == quota_mod.STOP else a.cap - 1 if state == quota_mod.COOLDOWN else 0
    return banded, caps
```

An unreadable account bands as `STOP` (`quota.band`, *"unknown ≠ free"*), so its whole cap counts
as taken — which is what the pool does with it anyway.

`wave()` grows one keyword and fills it beside the headroom samples it already records:

```python
def wave(product, rows, n, pool=None, ..., local_seats=None, stats=None):
    """...

    ``stats`` (a dict, or None): what this wave measured, for a caller that records it —
    ``banded_seats`` and ``pool_caps`` from :meth:`asf.workers.pool.Pool.banded_seats`. A
    caller that passes none is unchanged in every respect."""
```

filled in the same `finally`-adjacent tail that records the samples:

```python
    if stats is not None:
        banded, caps = pool.banded_seats()
        stats['banded_seats'], stats['pool_caps'] = banded, caps
    if sample:
        headroom_mod.record_samples(dict(pool._usage))
    return launched, waits
```

It is filled whether or not any row launched and whether or not the wave raised — a wave that
launched nothing because every account is stopped is precisely the wave whose number matters.

### 2.2 The ready work that did not launch — `asf/tick/step_wave.py`

`left_out` derives every Ready launching row inside itself (`:366-367`). That derivation becomes
its own function so the count and the lines read one population:

```python
def ready_rows(items, product, running, inputs, dropped):
    """Every Ready row that launches a session, whatever the seats — the plan at
    :data:`READY_ALL`, the same one :func:`left_out` compares against."""
    return gated_plan(items, product, running, len(running) + READY_ALL, inputs,
                      out=lambda _l: None, exclude=set(dropped or ()), s1_first=False)[0]


def ready_waiting(ready, launched, held, running):
    """How many Ready launching rows ended this tick with no session: the launching rows, less
    those a harvest merge hold parks, less those whose job is already running, less those this
    wave launched. ``running`` is the step's own ``inflight(product)``, keyed by job. A count by
    subtraction over one population — never a sum over the three wait lists, which may each name
    the same row (D4)."""
    held = set(held or ())
    started = {r.job for r, _rec in launched}
    live = {s.get('job') for s in running}
    return sum(1 for row in ready
               if row.launches and row.item_id not in held
               and row_job(row) not in started and row_job(row) not in live)
```

`left_out` keeps its signature and calls `ready_rows`; nothing it decides or prints changes.

In `run()`, after the wave, the two numbers are stamped on the tick:

```python
    stats = {}
    launched, _waits = _wave(product, worker_rows, len(worker_rows), ..., stats=stats)
    ...
    ctx.counts['launches'] += len(launched)
    seats = stats.get('banded_seats') or 0
    waiting = ready_waiting(ready, launched, inputs.get('held'), running)
    ctx.counts['quota_held'] += min(waiting, seats)
    ctx.quota_seats = max(ctx.quota_seats, seats)
    return 0
```

`min` because the seats are a pool-wide figure and the waiting rows are this product's: at most
that many of them could have gone into the seats the guard was holding. `max` for the seats
because one tick has one wave and a later product's wave must not overwrite an earlier reading
with a lower one.

A wave step that returns before the wave — a held host, nothing to launch — leaves both at zero:
a tick that never asked the pool for a seat measured nothing about the guard, and says so.

### 2.4 The rule — `asf/metrics/metrics.py`

```python
#: F-0068: the trigger the card fixes — the quota guard held ready work back on this many days
#: of this window. Constants, not configuration (D6).
PRESSURE_WINDOW = 7
PRESSURE_DAYS = 3


def quota_pressure(ticks, day, window=PRESSURE_WINDOW, need=PRESSURE_DAYS):
    """``(fired, days, held, seats, measured)`` over the ``window`` calendar days ending at
    ``day``.

    ``days``   the days on which some tick carried ``quota_held > 0``, in order
    ``held``   those ticks' ``quota_held``, summed
    ``seats``  the largest ``quota_seats`` seen in the window
    ``measured`` the days on which at least one tick carries the key at all — a day with no
               tick, or with only ticks written before this counter existed, is no evidence
               and is counted neither for the trigger nor against it (D5)
    ``fired``  ``len(days) >= need``

    Pure: ``day`` and ``ticks`` are arguments, no file is read and no clock is asked."""
```

A tick line lacking the key is read with `.get`, never `[...]` — P5 says a line already on disk is
not re-validated and simply does not have it.

### 2.6 The instrument — `tools/spike/f-0068/compare.py`

`lane` first, because without it the instrument has nothing to group by. `SCHEMAS['sessions']`
gains `'lane': (('str', 'null'), None)`, and `session_event` fills it from the registry record:

```python
def record_lane(record):
    """Which lane ran a registry record: its runtime's own ``runtime_lane`` marker, else the
    bare ``lane: cloud`` a cloud launch wrote before that split, else ``'local'``.

    A non-cloud run's ``lane`` key is the *harvest* lane state machine's own map
```

line written before this card has no key at all and reads `None` (D7).

run (`asf/workers/lifecycle.py:413-419`), so a dict there reads as `local`, and only the bare
string an old cloud launch wrote is honoured. `pool.is_cloud_lane` stays the reader for the pool's
own question; this is the record's.

Then the instrument, stdlib only, reading a backlog checkout's streams:

```

```

For each `lane` present on the Feature's subtree sessions, one row:

| column | how |
| --- | --- |
| `sessions` | the lane's sessions on the Feature and its descendants (`descendants`, `:386`) |
| `tasks landed` | the Tasks of that subtree with a `landings` event whose `job` is one of the lane's sessions' `task` (P19) |
| `tasks open` | the subtree's Tasks with none |
| `USD (metered)` | `Σ usd`, `—` when no session reported one (D8) |
| `cost per Task` | `USD ÷ tasks landed`, `—` when either is missing |
| `in / out / cache rd / cache wr` | the four dimensions, each summed on its own (P20) |
| `branches` | distinct `branch` on the lane's sessions |

### 2.7 The protocol — `compare.py --protocol`

What it prints, and what the operator holds constant when the trigger fires:

1. **One base sha.** Both runs start from the same trunk commit and take the plan **as it stood at
   that sha** — not as it was amended during the first run.
2. **The local run is the real one.** It lands; the Feature is delivered by it.
3. **The hosted run is a shadow.** Same plan, same base sha, a scratch remote with the same
   workflows, landing nowhere (D10). Its branches open pull requests against the scratch remote so
   its review rounds are counted the same way the local lane's are.
4. **Not concurrent.** The two runs would contend for CI runners and for the trunk; whichever ran
   second would look slower for a reason that has nothing to do with its runtime.
5. **Same models per role, same review gate, same CI workflows.** A cheaper lane running a smaller
   model is not a measurement of the lane.
6. **Both runs' sessions reach the record's streams with their `lane`** — the shadow's through
   `asf metrics append`, since the pool never launched them.
7. **The confounds, written down, not hidden:** the shadow runs second against a plan the first run
   has already exercised; the scratch remote's CI is warm; the shadow's branches never merge, so it
   is never charged for a conflict the first run paid for; and the local lane's USD is a price
   list, not an invoice (D8).

The document that results — `docs/research/hosted-runtime-vs-the-local-pool.md` — carries the stamp
(base sha, the two date windows, the host, both runtime versions), the table, those confounds, and
one recommendation. It is written when the run happens, and the last line of it names the card that
deletes `tools/spike/f-0068/`.
