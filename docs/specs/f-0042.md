# F-0042 — a credential is a rule, and its failure is a line to the operator

On 2026-09-21 three command-line tools the factory signs in with had expired. Nothing said so.
The sessions that needed them failed one after another — a login error inside a worker log — and
the day was lost until somebody looked. The factory already knows how to check a standing
condition every tick and how to tell the operator once: that is a rule card with a `check:`
script (`asf/rules/rules.py`). This card puts credentials on that path.

Two halves, and the second is what makes the card worth writing. The first is a **read-only
probe** per provider: is the session valid, and when does it expire — never printing a token. The
second is that its failure is **not a Bug and not a red job**: an expired credential is nobody's
defect and no session can fix it, so it travels as one `NEEDS OPERATOR` line carrying the exact
re-authentication command. Today every rule violation becomes an S2 Bug
(`file_bugs.rule_violation_signatures`), which for this rule would file a Bug a day that no
coder can close.

## 1. Decisions

### Preconditions (verified against `origin/main` at `d3ad697`)

- **The rule runner exists and is generic.** `asf/rules/rules.py` reads live rule cards from the
  record's `index.json`, resolves each card's `check:` against the record's own script first and
  ASF's core `rules/` dir second (`resolve_script`, `core_rules_dir`), runs them in parallel with
  a per-check timeout, and holds the contract this spec's script obeys: **exit 0 is a pass, exit 1
  with one line per place is a violation, anything else is a check failure** — never evidence the
  rule was broken.
- **The rules row runs every tick.** `asf/tick/tick.py:113` runs `file-bugs` inside the record
  step, which runs `asf rules check --json` (`file_bugs.rule_check_results`) after re-indexing the
  record. `asf/views/header.py` already titles `rules check` as the `RULES` table. So "every
  tick's rules row" needs no new wiring — only a card in the record.
- **The tick sets `ASF_PRODUCT`.** `tick.py:88` sets it for the record step, and
  `rule_check_results` passes the whole environment through, so a check script can resolve the
  product it is checking without an argument.
- **A check failure already goes to the operator, never to a Bug.** `report_check_failures` prints
  `rule check timed out: R-nnnn` per run and, after `CHECK_FAILURE_RUNS_TO_SURFACE` (3) runs in a
  row, one `NEEDS OPERATOR` line, keyed in `~/.ASF/state/<p>/rule-check-failures.json`. This spec
  reuses that ledger file and that shape for its own once-a-day line.
- **The daily step takes parts with an event hook.** `step_daily.parts(product, root, event=…)`
  returns `[(name, thunk)]`; each part prints `daily: <name> ok|FAILED — <its last line>`.
- **Probing under the session's own environment is a solved problem.**
  `doctor.check_worker_push_auth` already builds a worker account's exact session environment with
  `asf.workers.runtime.build_env` and probes with `GIT_TERMINAL_PROMPT=0`; the operator's own HOME
  and keychain are not what a spawned session gets.
- **Redaction has a string API.** `redact.scrub(text, redact.default_patterns(repo))` replaces a
  secret-shaped match with `SCRUB_TOKEN`.
- **The rule card and its check script are in the amendable set.** `asf/amendable.py` `kinds()`
  covers `rules/*.md`, `rules/index.json`, `rules/*.sh` and `tools/checks/*`. No session writes
  them: the hook refuses `touch_amendable_set` (`human-now`) and `asf propose` is not implemented
  on this trunk. Acceptance 1 therefore has to be reachable *without* a session writing either
  file — see D9.
- **An unknown key in a product file refuses the whole file** (`env.py:591`), so `credentials:`
  must be declared in `PRODUCT_FIELDS`. `config.yaml` has no field table; a section validates
  itself and the doctor reports it, the way `ci_pool.pool_problems` does.

### In / out

| In | Out |
|---|---|
| A read-only probe per provider, run under the environment a session gets, with a timeout | Renewing, refreshing or rotating a credential — the factory never signs in for you |
| The three-day window (`credentials.window_days`, default 3), per-provider override | Warning at more than one threshold (no "7 days: notice, 3 days: warn" ladder) |
| `asf credentials check` — the `CREDENTIALS` table, `--json`, and `--quiet` for the rule contract | A provider's remaining *quota* or spend; that is `asf tokens` |
| The rule card `R-nnnn` and its core script `rules/credentials.sh`, both installed by `asf credentials install` (D9) | A session writing either of them; the amendable set holds and this spec does not widen it |
| `owner: operator` on a rule card: its violation files no Bug and prints one `NEEDS OPERATOR` line a day | Making every operator-owned rule silent — the line still shows in the `RULES` table every tick |
| The daily part, its `credentials` events, and the doctor's `credentials` row | Holding the wave, or refusing a launch, when a provider is invalid (see D8) |
| A cache in the product's state dir so a per-tick check does not re-probe every provider | A probe result shared between machines, or any state in the record |
| Never a token: the probe's output is scrubbed and truncated before it is printed, cached or evented | Reading a credential file's *content* to judge it — validity is what the tool itself says |

### Choices

| # | Chosen | Against | Why |
|---|---|---|---|
| D1 | The probe is an **operator-configured command** per provider (`config.yaml: credentials.providers.<name>.probe`), with its `renew:` command beside it | A built-in probe per known tool | The repo may not name a vendor (`tools/check_generic.sh`, `tools/forbidden-names.txt`): "name the interface, the backend belongs in operator config". It also makes a fourth tool a config edit, not a release. |
| D2 | The probe's contract mirrors the rule contract: **exit 0 valid, exit 1 invalid, anything else (or a timeout) broken**. Its last non-empty stdout line may carry `expires <ISO-8601>` or `expires never`; an unreadable line means "valid, expiry unknown" | A JSON contract; or treating a non-zero exit as expired | One contract in the factory, already documented and already tested. A probe that crashed says *nothing* about the credential — calling that "expired" would raise the operator for a broken probe, which is the failure `report_check_failures` was built to avoid. |
| D3 | An **unknown expiry is not a violation**: it shows as `expiry unknown` and passes | Treat unknown as expiring | Validity is what the tool itself answered (exit 0). A tool with no expiry to report would otherwise raise a line every day for ever, and the operator would learn to ignore the line. |
| D4 | The credential set is **per provider**, probed once per provider per run; `product.yaml: credentials: [<provider>…]` says which ones a product needs | Probe per (product, provider) pair, or probe every configured provider | The card: *the credential set is per provider and shared across products; which providers a product needs comes from its configuration*. A provider no product names is never probed — an unused login is not a stop-the-line condition. |
| D5 | The probe runs under `runtime.build_env` for the worker account the provider names (`account:`), else under `hermetic.worker_base(...)` with `GIT_TERMINAL_PROMPT=0` | Run it under the operator's own environment | The credential that matters is the one a *spawned session* can reach. `check_worker_push_auth`'s finding (2026-09-26: four sessions could not reach the operator's keychain) is the same class of bug one layer down. |
| D6 | Results are **cached** in `~/.ASF/state/<p>/credentials.json` and re-probed only when the entry is older than `credentials.probe_every` (default `1h`); the daily part and `--fresh` always probe | Probe on every tick | A tick runs every few minutes; a read-only probe is still a network call a provider may rate-limit. The *window* arithmetic is recomputed from the cached expiry each run, so a credential ticking into its last three days is caught without a probe. The cache cannot hide an expiry by more than `probe_every`, which is an hour against a three-day window. |
| D7 | A rule card may carry **`owner: factory` (default) or `owner: operator`**. | D8 | An invalid provider does **not** hold the wave or refuse a launch | Refuse to launch sessions while a credential is invalid | Out of the card's scope, and the wrong default: the factory has products and lanes that need no provider, and a probe that is wrong about validity would then stop all work rather than print a line. The card asks for a line, and the line names the fix. |
| D9 | `asf credentials install [--print]` writes the rule card (via `asf new rule`) and `rules/credentials.sh`, and **refuses to run inside a session** (`$ASF_JOB` set) with the operator's command; `--print` writes nothing and prints both files | A session commits the card and the script; or the spec leaves them to be hand-written | The amendable set is the gate over every other gate (F-0024): those two files are the operator's to approve and commit. An installer makes acceptance 1 mechanical and testable (it runs against a temporary record in the test), gives every other product the same rule, and its own refusal keeps the set closed. |
| D10 | `--quiet` exits **2** when any probe is broken, with the reason on stderr | Exit 1 (a violation) on a broken probe | The rule runner then reports `rule check failed exit 2`, prints `rule check failed: R-nnnn`, and after three runs raises one `NEEDS OPERATOR` line about the *check* — a factory-side problem, never a Bug and never "your credential expired". D2's contract, end to end. |
| D11 | Both the daily part and the rules row consult the same per-day ledger key, so the line is printed once a day whichever runs first; the daily part additionally writes the events | Print from the daily part only | The rules row runs every tick and the daily step once; a credential that expires at 02:00 must not wait for tomorrow's daily. | D12 | The daily part **always returns 0** and reports through its printed line | Fail the daily step when a provider is invalid | `step_daily.run` raises when a part fails, the day is not stamped and the step is red — which is the "failed job" the card's second acceptance forbids. |

## 2. The design

### 2.1 `asf/credentials.py` — the probe and its verdict (S-56055)

New module. No third-party import; `subprocess`, `json`, `datetime` only.

```python
PROBE_TIMEOUT_S = 20          # $ASF_CREDENTIAL_PROBE_TIMEOUT overrides
DEFAULT_WINDOW_DAYS = 3       # the card's three days
DEFAULT_PROBE_EVERY = '1h'
DETAIL_MAX = 160              # how much of a probe's own last line is ever kept

@dataclasses.dataclass(frozen=True)
class Provider:
    name: str; probe: str; renew: str
    account: str = ''         # the worker account whose environment the probe runs under (D5)
    window_days: int = DEFAULT_WINDOW_DAYS

@dataclasses.dataclass(frozen=True)
class Result:
    provider: str
    state: str                # 'valid' | 'invalid' | 'broken'
    expires: str = ''         # ISO-8601, '' unknown, 'never' no expiry
    detail: str = ''          # the probe's own last line, scrubbed and truncated — never a token
    probed_at: str = ''
```

- `providers(cfg)` → `{name: Provider}` from `config.yaml: credentials.providers`.
- `config_problems(cfg)` → `[(dotted key, problem)]`: a provider with no `probe:` or no `renew:`, a
  `window_days` that is not a positive integer, a `probe_every` that is not `<n>s|m|h|d`, an
  `account:` no `worker_pool.accounts` entry names. The doctor's row reports them (2.5).
- `product_problems(value)` → `[(dotted key, problem)]` for `product.yaml: credentials:` — not a
  list of non-empty strings, or a duplicate name. Called from `env.py`'s product-file check beside
  `ci_pool.pool_problems` (2.2).
- `for_product(product, cfg)` → the `Provider`s the product names, in the product's order. A name
  no `credentials.providers` entry defines raises `env.ConfigError`
  (`product.yaml credentials: <name> is not a provider in config.yaml credentials.providers`).
- `probe_env(provider, cfg, product)` → the environment (D5).
- `run_probe(provider, env_map, now, run=subprocess.run)` → `Result`:
  - `run` is the probe split with `shlex.split`, `timeout=PROBE_TIMEOUT_S`, output captured.
  - rc 0 → `valid`; rc 1 → `invalid`; any other rc, `OSError` or `TimeoutExpired` → `broken`.
  - `expires` from the last non-empty stdout line matched against
    `^\s*expires[:=]?\s+(never|<ISO-8601>)\s*$`, case-insensitive; no match → `''` (D3).
  - `detail` = `scrub(last non-empty line of stdout else stderr)`, truncated to `DETAIL_MAX` (2.4).
- `days_left(result, now)` → `float | None`; `None` when `expires` is `''` or `never`.
- `verdict(result, now, window_days)` → one of:
  `ok` · `expiring` (valid, `days_left` under the window) · `invalid` · `unknown` (valid, no
  expiry known) · `broken`.
- `bad(results, …)` → the results whose verdict is `invalid` or `expiring` — what raises the line.

### 2.2 Configuration (S-56054)

`~/.ASF/config.yaml`, shared by every product:

```yaml
credentials:
  window_days: 3            # default 3 — the card's three days
  probe_every: 1h           # default 1h — how stale a cached probe may be (D6)
  providers:
    provider-a:
      probe: <a read-only command that exits 0 when the session is valid>
      renew: <the exact command an operator runs to sign in again>
      account: lane-1       # optional: whose session environment the probe runs under
      window_days: 5        # optional: this provider's own window
```

`~/.ASF/products/<p>.yaml` — which providers *this* product needs:

```yaml
credentials: [provider-a, provider-b]
```

`asf/env.py`: `PRODUCT_FIELDS['credentials'] = _LIST`, and in the product-file check, beside the
existing delegations:

```python
from asf import credentials as credentials_mod
for dotted, why in credentials_mod.product_problems(data.get('credentials')):
    problems.append((lines.get('credentials', 0), dotted, why))
```

`Product.credentials` → `self._get('credentials') or []`. A product that names none is a product
with nothing to check: every part of this feature is a no-op for it, and the rule passes.

### 2.3 `asf credentials check` (S-56056)

`asf/cli.py` gains a `credentials` sub-parser with `credentials_command` in
`choices=['check', 'install']`, plus `--product`, `--fresh`, `--json`, `--quiet`.
`asf/views/header.py` `TITLES` gains `'credentials check': 'CREDENTIALS'` (`command_key` already
joins the sub-command).

- `check(product, cfg, fresh=False, now=None)` → `[Result]`, one per provider `for_product`
  returns, taken from the cache when its `probed_at` is within `probe_every` and `fresh` is false,
  probed otherwise; the cache is rewritten after (2.4).
- Default output — the table, one row per provider, sorted by name:

```
**CREDENTIALS asf** — 2 ok, 1 expiring, 0 invalid
provider-a  ok         expires 2026-11-02T09:00:00Z (36d)
provider-b  ok         expiry unknown
provider-c  EXPIRING   expires 2026-09-29T08:00:00Z (2d) — renew: <the renew command>
```

  An `invalid` row reads `INVALID    not signed in — renew: <the renew command>`, a `broken` row
  `BROKEN     probe failed exit 2 — <detail>`. Exit 0 when every verdict is `ok` or `unknown`,
  1 when any is `invalid`/`expiring`, 2 when any is `broken`.
- `--json` → `{"product": …, "window_days": …, "providers": [{"provider", "state", "verdict",
  "expires", "days_left", "probed_at", "detail"}]}`. No token, no `renew` value keyed to a secret
  — `renew` is a command, and it is included.
- `--quiet` → the rule-check contract (D2, D10): nothing and exit 0 on a pass; exit 1 with **one
  line per bad provider**, each ending in its renew command:

```
credential provider-c expires 2026-09-29T08:00:00Z (2d, window 3d) — renew: <the renew command>
credential provider-d is not valid — renew: <the renew command>
```

  and exit 2, with `credentials: probe broken for <name>: <detail>` on stderr, when any probe is
  broken. `rules.py` prefixes each violation line with the rule id itself, so the card's line in
  the `RULES` table reads `R-nnnn credential provider-c expires …`.

### 2.4 Never a token (S-56058)

One funnel, and everything downstream reads `Result.detail`:

- A probe's stdout and stderr are **never** printed, logged or stored raw. `run_probe` keeps the
  last non-empty line only, passes it through `redact.scrub(line, redact.default_patterns(
  product.repo_dir))`, and truncates it to `DETAIL_MAX` with `…`.
- The `expires` field is parsed out of that line and re-rendered as an ISO-8601 timestamp, so a
  probe that prints a token *beside* its expiry contributes a timestamp and a scrubbed detail.
- The cache (2.6) holds exactly the `Result` fields; the events (2.6) hold no `detail` at all.
- The `renew` command comes from operator config and is printed verbatim — it is the command to
  *get* a credential, and a `renew:` that embeds a secret is an operator error the doctor names
  (`config_problems`: `renew` matched by `redact.default_patterns` is reported as
  `credentials.providers.<name>.renew: carries a secret-shaped value — put the secret in a file`).

### 2.5 The doctor's row (S-56062)

`asf/doctor.py`:

```python
def check_credentials(cfg, product):
    """(ok, detail) — the `credentials` row: every provider this product needs, from the cache
    (never a fresh probe: the doctor is a view). Red when any is invalid or inside its window,
    and its detail carries the renew command."""
```

Appended in `run()` as a required row, after `worker push auth`. Config problems from
`credentials.config_problems(cfg)` are reported on the same row, red, before any verdict is
computed. No providers configured, or the product names none: `(True, 'no providers configured')`.

### 2.6 The daily part and its events (S-56061)

`asf/tick/step_daily.parts` gains, after `scorecard`:

```python
('credentials', lambda: credentials_daily(product, root, event=event)),
```

`credentials.daily(product, root, event=None, now=None)`:

1. `check(product, cfg, fresh=True)` — the daily run always probes (D6).
2. One `credentials` event per provider through `event` when it is given (2.7).
3. Prints one summary line — `3 providers: 2 ok, 1 EXPIRING provider-c (2d)` — which becomes the
   daily step's `daily: credentials ok — …`.
4. Raises the once-a-day `NEEDS OPERATOR` line through the shared ledger (2.7, D11), and writes a
   `needs-operator` event with the same message when it printed it.
5. **Returns 0 always** (D12). An exception inside it is caught, printed as
   `credentials: <ExceptionName>: <msg>`, and still returns 0 — a broken credential check never
   fails the day.

### 2.7 Operator-owned rules: one line, no Bug (S-56059)

`asf/record/new.py`: `SETTABLE['rule'] |= {'owner'}`.
`asf/rules/rules.py`:

- `load_rules` carries `owner` through from the index (default `'factory'`); `OWNERS =
  ('factory', 'operator')`; an unrecognised value is read as `'factory'` and reported by
  `asf check`, so a typo never silences a rule.
- `--json` violations gain `"owner"`; the `== RULES` summary line gains `, <k> operator` when any
  operator-owned rule is violated; `cmd_check` prints an operator-owned violation line prefixed
  `NEEDS OPERATOR: ` so the `RULES` table an operator reads says whose problem it is.

`asf/tick/file_bugs.py`:

- `rule_violation_signatures` **skips** a violation whose `owner` is `operator`: no signature, no
  Bug, no bump.
- New `report_operator_rules(violations, ledger, day, out=print)`, called from `cmd_file_bugs`
  beside `report_check_failures`: for each operator-owned rule, one

```
NEEDS OPERATOR: R-nnnn credential provider-c expires 2026-09-29T08:00:00Z (2d, window 3d) — renew: <the renew command>
```

  per rule per UTC day, keyed in `ledger['operator'][rule] = {since, last, day, lines}` in the
  existing `rule-check-failures.json`; when the rule has more than one violating line the first is
  in the line and the rest follow it, one per line, unprefixed. A day already keyed prints nothing.
  An entry whose rule is clean this run is dropped, so the next failure raises the line again.

### 2.8 `asf credentials install` — the card and the script (S-56063)

`credentials.install(record_root, repo_root, print_only=False, job=None)`:

- Refuses when `job` (default `$ASF_JOB`) is set:
  `NEEDS OPERATOR: asf credentials install writes the amendable set — run it yourself:
  asf credentials install --product <p>`, return 2. Nothing is written (D9).
- Otherwise: `asf new rule` for the card (the id is minted by the record, never by this code),
  then `asf set R-nnnn` for `check: rules/credentials.sh` and `owner: operator`, then writes
  `rules/credentials.sh` into the ASF repo's core `rules/` dir when it is not already there, then
  `asf index`. Prints each path it wrote and the two commits the operator still owes:

```
wrote rules/R-nnnn.md (record) — commit it: git -C <record> commit -s rules/
wrote rules/credentials.sh (asf) — commit it: git -C <asf> commit -s rules/credentials.sh
```

- `--print` writes nothing and prints both files to stdout, for an operator who would rather paste
  them.

The card:

```markdown
---
type: rule
title: Every signed-in tool is valid for three more days
scope: factory
owner: operator
check: rules/credentials.sh
---
Every command-line tool the factory signs in with is probed read-only, once an hour at most: is
the session valid, and when does it expire. A session that is invalid, or that expires inside
`credentials.window_days` (3), is one `NEEDS OPERATOR` line carrying the exact re-authentication
command — never a Bug, and never a failed job. Which providers this product needs is
`credentials:` in its product file; each provider's probe and renew commands are
`credentials.providers` in `~/.ASF/config.yaml`.
```

And the script, which is the whole of it (`rules/credentials.sh`, ASF's core `rules/` dir):

```sh
#!/usr/bin/env bash
# R-nnnn — every signed-in tool is valid for three more days (F-0042).
# The rule-check contract: 0 pass, 1 one line per bad provider, 2 a broken probe.
# The product is $ASF_PRODUCT (the tick sets it), else config.yaml's default_product.
set -uo pipefail
exec asf credentials check --quiet
```

## 4. Records

| What | Where | Shape |
|---|---|---|
| The probe cache | `~/.ASF/state/<product>/credentials.json` | `{"providers": {"<name>": {"state", "expires", "detail", "probed_at"}}}` — factory-side, never in the record, never a token |
| The once-a-day operator key | `~/.ASF/state/<product>/rule-check-failures.json` | the existing file gains `"operator": {"R-nnnn": {"since", "last", "day", "lines": [<the violation lines>]}}` |
| The daily credential trail | `metrics/events/<day>.jsonl` in the record clone, via `Context.event` | `{kind: credentials, product, provider, state, verdict, expires, days_left, ts}` — one per provider per daily run, no `detail` |
| The operator line, as an event | same stream | `{kind: needs-operator, message: "<the line>", product, ts}` — the kind `tick.py:381` already writes |
| The rules row | tick stdout, `asf rules check` | `R-nnnn credential provider-c expires … — renew: …`, and `== RULES <n> checked, 1 violations, 0 unenforced, 1 operator` |
| The Bug filer | tick stdout | `file-bugs: 0 filed, …` — an operator-owned violation files and bumps nothing |
| The daily step | tick stdout | `daily: credentials ok — 3 providers: 2 ok, 1 EXPIRING provider-c (2d)` |
| The doctor | `asf doctor` | a `credentials` row, `RED` with the provider and its renew command |
| The rule card | the record's `rules/R-nnnn.md` | `check: rules/credentials.sh`, `owner: operator`, `scope: factory` — written by `asf credentials install`, committed by the operator |
| The check script | this repo's core `rules/credentials.sh` | the six lines of 2.8, mode `0o755` — committed by the operator |
| Operator config | `~/.ASF/config.yaml` | new `credentials:` section (2.2) |
| Product config | `~/.ASF/products/<p>.yaml` | new `credentials: [<provider>…]` list |

No schema version bump: `owner:` is a new typed field on rule cards with a default, and both event
kinds are new lines in an existing stream.

**The two artefacts this spec cannot have a session write.** The rule card and
`rules/credentials.sh` are in the amendable set (`asf/amendable.py`): every session that tries is
refused `touch_amendable_set` (`human-now`). Once the Tasks land, the operator runs
`asf credentials install --product <p>` and commits the two files it names — that, and the
`credentials:` config of 2.2, is the whole of what a person does here. Everything else is code and
tests, which a session may write.
