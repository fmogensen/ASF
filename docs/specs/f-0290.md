# F-0290 — the tick's long steps say what they cost, and the one that is still long is bounded

A tick of the customer product ran 50 minutes and spent 1493 s in `health` and 923 s in
`record-tail`, of which `[record:file-bugs]` alone was 873–1111 s. Nothing in the log said *which*
part of either step the time went to: `health` prints one `[step:health] 1493.1s` line for
fourteen sub-steps, and `file-bugs` prints one `[record:file-bugs] 873.0s` line for six phases.
The record therefore lags a tick behind itself, and an upgrade's drain never finds a gap between
two ticks that each run for half an hour.

Re-measured at HEAD (`76cf9b102`), the two halves have come apart, and this spec is cut to what is
true now rather than to the card's snapshot.

## Decisions

### D1 — health's 25 minutes is already landed; its illegibility is not

T-0660 (`e087a27a8`, 2026-10-07T17:50:29+02:00, "one `git status` per worktree per version of that
worktree") landed **after** the card's `2026-10-07T09:17:24Z` tick. Health has measured
82.9–424.6 s on every tick since. So this spec does not cut health's work.

What the card's health half still names correctly is `Its sub-steps print no timings` — and that
is why nobody could tell whether the 1493 s was the reaper, the retention sweep, the stall check
or the widening rule, and why nobody can tell today what the remaining 425 s is either.

*Chosen against*: capping the worktree reaper or the retention sweep. The card's evidence for
them is `worktrees: reaped 14 — deleting …` and ten stale-archive lines on one tick — a one-off
backlog, not a steady state, and nothing at HEAD shows either costing minutes. A cut with no
measurement behind it is a guess, and the measurement is exactly what S1 supplies.

### D2 — `[record:file-bugs]` is the flaky pass's serial job-log downloads

Measured, not inferred: `load_items` (1893 cards) is 0.4 s, `record_findings` is 1.1 s, and
`record_error_signatures`, `rule_check_results`, `ci_signatures`, `refusal_signatures`,
`outcome_signatures` and `repeat_signatures` are each ≤ 0.1 s — **1.7 s for everything but the
flaky pass**, against a step that takes 788.7–965.2 s.

`collect` reads `MAX_RUNS_PER_PASS` (30) runs and, for each one, one `jobs` call plus **one
`gh api repos/<slug>/actions/jobs/<id>/logs` call per job of that run**, serially. The product's CI
runs about sixteen jobs per run, so a pass is about 510 sequential HTTP calls. The pass's own line
says it finds nothing: `read 30 run(s), 0 flaky test(s)`, every pass.

And it never catches up. `window_from` has stood at `2026-10-05T18:54:28Z` while `last_pass` is
`2026-10-08T06:50:59Z`: two and a half days of lag, growing, because runs arrive faster than
30 a pass. The 13 minutes is therefore not a backlog being worked off — it is the steady state,
paid on every pass for ever.

*Chosen*: narrow what is downloaded **and** bound the pass by wall clock, in one change to one
module.

*Against — narrowing alone*: the cost would still scale with a product's jobs-per-run, so a
product with sixty jobs a run pays twice what this one does. The card's complaint is a duration,
and only a duration bounds a duration.

*Against — bounding alone*: a budget with the per-job cost unchanged reads *fewer* runs a pass, so
the 2.5-day window lag grows faster. The narrowing is what restores throughput.

*Against — parallelising the log reads*: `asf.mutation_guard` is thread-local, so every thread
pool is a hole in the dry-run guard (`asf.metrics.ci_from_api` is already one). Not for a step
whose job is to file Bugs.

*Against — moving the flaky pass out of `file-bugs` onto its own clock*: it would move the 13
minutes rather than remove it, and the card asks for the tick, not for a different log line.

### D3 — a timing line goes to the tick log, never through a step's `out`

Both new prefixes print through `timed`'s default `print`, exactly as the record's parts already
do. Two tests make this the only correct choice: P9 asserts a clean health step's `out` is exactly
`['health: clean', 'stall: none']`, and P10 refuses any seconds token on a rehearsal line. Routing
the timings through `out` would redden the first today, and would redden the second the day a
rehearsal grows a health step.

### D4 — one `timed`, given a group, not three copies of its format string

`timed` hardcodes `[record:{part}]`. It gains a `group` parameter defaulting to `'record'`, so
every existing call site and every existing `[record:…]` byte is unchanged, and health and
file-bugs reuse the same implementation and the same `N.Ns` shape.

*Against*: a private `_timed` in each of the two modules — three format strings to keep in step,
and three places for the rehearsal rule of D3 to be got wrong.

### D5 — the per-pass run cap stays; the budget is added beside it

P8 pins `MAX_RUNS_PER_PASS` as the batch size a truncated listing still reads. The budget is a
second, independent stop, checked *between* runs — so the worst case a pass can reach is the
budget plus one run's own calls, each already bounded by `GH_TIMEOUT_S` (120 s).

### Out of scope, named

**The upgrade window's own constants.** `upgrade.drain_wait_s` (default 180, the card's
"3-minute move bound") and `upgrade.pending_ttl_s` (default 600) are *both* already registered
config keys with readers in the package — `asf/upgrade.py:326` and `asf/upgrade.py:115`, `:226`,
`:262` — so an operator can lengthen either one today without a line of code. The card's cause is
the tick's length, not a missing knob: with `[record:file-bugs]` no longer 790–965 s, the tail's
contribution to a tick falls from 835 s to about 145 s and the worst observed total falls from
1967.6 s toward 400 s, inside the 600 s life of the marker the drain runs under.

Whether the drain then succeeds on its first attempt is a measurement on the host, not something
this spec can prove; the acceptance below names the exact read-only command that settles it. A
window that still misses after this lands is its own card, filed with that command's output.

**Lowering the tick watchdog's floor** (`asf/tick/watchdog.py`, `FLOOR_S = 3600`). That budget
exists for the tick that never ends; a 50-minute tick that finishes is this card's subject and is
answered by D2. Changing the floor is an operator policy change with its own blast radius.

**A `health` step budget that cuts a sub-step short.** Health's parts end, hold and correct runs;
a part killed halfway leaves the ledger half-written. S1 makes the cost visible first — that is
the precondition for any later bound, and this spec stops there deliberately.

## The design

### 1. `asf/tick/tick.py` — `timed` gains a group

```python
@contextlib.contextmanager
def timed(part, out=None, group='record'):
    """``[<group>:<part>] N.Ns`` once the part is done (or has raised): each part of a long step
    says what it cost, so the next regression names itself in the tick log. ``group`` is the
    step the part belongs to (``record``, ``health``, ``file-bugs``).

    The line goes to ``out or print`` — the tick log, never a step's own transcript: a clean
    health step's ``out`` is asserted exact (``tests/test_tick_steps.py``) and a rehearsal's
    transcript may carry no seconds token at all (``tests/test_dry_run.py``)."""
    start = time.monotonic()
    try:
        yield
    finally:
        (out or print)(f"[{group}:{part}] {time.monotonic() - start:.1f}s", flush=True)
```

Every present call site passes no `group`, so every `[record:<part>]` line stays byte-identical.

### 2. `asf/tick/step_health.py` — each part of `run()` is timed

`run` wraps each of its fourteen calls, in the order it already makes them, and prints nothing
else that it did not print before:

```
[health:record-items] 0.3s
[health:spare] 0.1s
[health:sessions] 41.2s
[health:reap-worktrees] 9.8s
[health:rulings] 0.2s
[health:rejudge] 1.1s
[health:widen] 3.4s
[health:parks] 0.6s
[health:stall] 2.0s
[health:dead] 0.0s
[health:corrections] 0.1s
[health:ci-trials] 0.4s
[health:retention] 18.7s
[health:stale] 5.2s
```

Fourteen lines, one per call of `run()`'s body: `spare` is `spare_this_waves_runs`, `sessions` is
`health_mod.health`, and `dead` is the `pool_mod.load_sessions` read, the `empty`/`health_freed`
derivation and the whole `handle_dead` loop together — the ledger read and the loop over its
result are one cost, and splitting them would name a part no reader can act on. Part names are
`[a-z-]+`, the shape `TIMING_RE` already expects. `timed` is imported at module level
(`from asf.tick.tick import timed` — P7: no cycle), so B-0135's rule that a step's modules are
resolved before the step loop runs is unchanged.

### 3. `asf/tick/file_bugs.py` — each phase of `cmd_file_bugs` is timed

Six lines, one per phase, in the order the function already runs them:

```
[file-bugs:items] 1.9s
[file-bugs:rules] 0.1s
[file-bugs:signatures] 1.4s
[file-bugs:flaky] 118.6s
[file-bugs:file] 0.8s
[file-bugs:index] 0.4s
```

`items` covers `load_items` → `do_index` → `load_items` → `canonicalize`; `signatures` covers all
six `signatures.update(...)` calls and `report_check_failures`; `file` covers the
`_file_or_bump_bug` loop; `index` covers the closing `do_index`, and is printed only when that
`do_index` runs, exactly as today. A phase that returns early (`level != 'auto'`) prints the
phases that ran and no more.

### 4. `asf/conventions.py` — `flaky_jobs`

```python
#: Which of a CI run's jobs can carry a flaky-test report: a list of job-name globs. Unset (the
#: default) reads every job's log, as the pass always did; a product that names its e2e job turns
#: ~16 log downloads a run into one.
flaky_jobs: list = field(default_factory=list)
```

documented in the module docstring's product-yaml block:

```yaml
      flaky_jobs: [e2e, 'e2e (*)']   # unset = every job's log is read (slow on a wide matrix)
```

and shape-checked beside the other path lists — `flaky_jobs` joins the
`('doc_paths', 'shared_paths', 'shared_writes')` tuple in `validate_mapping`, so a bare string
where a list belongs is a named problem rather than one matcher per character.

### 5. `asf/tick/flaky.py` — fewer logs, and a wall-clock stop

```python
#: Wall-clock seconds a pass may spend reading runs (config ``flaky.pass_budget_s``). Checked
#: between runs, so the worst case is this plus one run's own calls — each already bounded by
#: :data:`GH_TIMEOUT_S`. The runs left unread set ``window_from``, exactly as the per-pass count
#: cap's leftovers already do.
PASS_BUDGET_S = 120
#: the pass's own clock, named so a test replaces it without touching time.monotonic
_clock = time.monotonic


def job_wanted(name, globs):
    """True when ``name`` matches any glob of ``globs`` — and for an empty ``globs``, which is a
    product that declares no ``conventions.flaky_jobs`` and reads every job's log as before."""
    return not globs or any(fnmatch.fnmatch(name or '', g) for g in globs)
```

`collect` changes in three places and nowhere else:

```python

    deadline = _clock() + tunable('PASS_BUDGET_S')
    read_logs = skipped_logs = 0
    for i, r in enumerate(runs):
        if _clock() >= deadline:
            # out of budget: the rest are unread, so the window stays behind them
            deferred = runs[i:] + deferred
            out(f"file-bugs: flaky — budget spent ({tunable('PASS_BUDGET_S')}s) after {i} "
                f"run(s); {len(runs) - i} left for the next pass")
            runs = runs[:i]
            break
        jobs = source.jobs(r['id'])
        if jobs is None:
            failed.append(r)
            continue
        wanted = [j for j in jobs if job_wanted(j.get('name'), wanted_jobs)]
        skipped_logs += len(jobs) - len(wanted)
        logs = [(j, source.log(j['id'])) for j in wanted]
        if any(log is None for _j, log in logs):
            failed.append(r)
            continue
        read_logs += len(wanted)
        ...
```

and the pass's closing line names what it cost, so the next regression is one `grep` away:

```python
    if runs:
        out(f"file-bugs: flaky — read {len(runs)} run(s), {read_logs} job log(s) "
            f"({skipped_logs} skipped), {len(touched)} flaky test(s)")
```

`state['window_from'] = next_window(deferred + failed, now)` is untouched: a budget stop only
moves runs from `runs` into `deferred`, which is already the set the window is held behind. No new
state file, no new key in `flaky.json`.

`flaky.pass_budget_s` is registered in `asf/config_keys.py` as `(NUM, 1, None)` beside
`flaky.max_runs`, added to `TUNABLES` in `flaky.py`, and documented in
`docs/config.example.yaml` — P6's three places, both directions.

### A4 — the flaky pass reads only the jobs it was told to, and stops on its budget

Add to `tests/test_flaky.py`. `WideMatrixRuns` is a source whose runs carry many named jobs, which
neither `FakeRuns` nor `SinceFilteredRuns` does:

```python
class FakeClock:
    """The pass's clock, so a budget test needs no sleep."""

    def __init__(self):
        self.t = 0.0

    def __call__(self):
        return self.t


class WideMatrixRuns:
    """Runs with a sixteen-job matrix, one of them the e2e job — the shape that made a pass
    ~510 serial log reads. ``clock`` and ``delay``: each log read costs ``delay`` seconds of it."""
    slug = 'o/r'

    def __init__(self, n_runs=2, clock=None, delay=0.0):
        self.clock = clock
        self.delay = delay
        self.log_calls = []
        self.runs_ = [{'id': i + 1, 'name': 'ci', 'branch': 'main',
                       'ts': '2026-10-07T00:00:00Z', 'created': '2026-10-07T00:00:00Z',
                       'url': f'https://ci/{i + 1}'} for i in range(n_runs)]

    def runs(self, workflow, since):
        return [r for r in self.runs_ if workflow == 'ci']

    def jobs(self, run_id):
        names = ['gate', 'lint'] + [f'unit ({i})' for i in range(13)] + ['e2e (chromium)']
        return [{'id': run_id * 100 + i, 'name': n, 'runner_name': 'r', 'labels': []}
                for i, n in enumerate(names)]

    def log(self, job_id):
        self.log_calls.append(job_id)
        if self.clock is not None:
            self.clock.t += self.delay
        return ''


class FlakyJobFilterTests(unittest.TestCase):
    """F-0290: a pass downloaded every job's log of every run it read."""

    def setUp(self):
        self.now = datetime.datetime.now(datetime.timezone.utc)
        self.state_path = os.path.join(tempfile.mkdtemp(prefix='flaky_state_'), 'x.json')
        self.clock = FakeClock()
        self.lines = []

    def collect(self, src, conv, budget=10 ** 6):
        from unittest import mock          # the module's own style: imported where it is used
        state = flaky.read_state(self.state_path)
        with mock.patch.object(flaky, '_clock', self.clock), \
                mock.patch.object(flaky, 'PASS_BUDGET_S', budget):
            flaky.collect(state, src, 'ci', conv, self.now, out=self.lines.append)
        return state

    def runs(self, n, delay=0.0):
        return WideMatrixRuns(n_runs=n, clock=self.clock, delay=delay)

    def test_no_declaration_reads_every_job_as_before(self):
        src = self.runs(1)
        self.collect(src, Conventions(ci_workflow='ci'))
        self.assertEqual(len(src.log_calls), 16)

    def test_a_declared_job_glob_reads_one_log_a_run(self):
        src = self.runs(2)
        self.collect(src, Conventions(ci_workflow='ci', flaky_jobs=['e2e*']))
        self.assertEqual(len(src.log_calls), 2)
        self.assertTrue(any('30 skipped' in l for l in self.lines), self.lines)

    def test_a_glob_matching_nothing_reads_no_log_and_still_sees_the_run(self):
        src = self.runs(1)
        state = self.collect(src, Conventions(ci_workflow='ci', flaky_jobs=['nosuchjob']))
        self.assertEqual(src.log_calls, [])
        self.assertIn('1', state['seen'])


class FlakyPassBudgetTests(FlakyJobFilterTests):
    def test_the_budget_stops_the_pass_and_the_window_stays_behind_what_is_unread(self):
```
