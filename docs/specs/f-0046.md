# F-0046 — the record stops holding two live answers to the same question

The record already knows how to *say* that one ruling replaced another: `migrate` reads a
verdict cell for "supersedes/amends/reverses D42" and writes `supersedes: [D-0042]` onto the new
decision card (`asf/tick/migrate.py:227`, `:457-458`). Nothing reads it back. No check asks
whether `D-0042` exists, whether the two cards point at each other, or whether a ring of three
rulings supersedes itself in a circle. And `rules.load_rules` — which decides what the rule run
enforces — skips a card carrying `removed:` or `moved_to:` and nothing else
(`asf/rules/rules.py:81-82`), so a rule that a later rule replaced keeps running, keeps failing,
and keeps filing bugs against work that obeys its successor.

Underneath that is the larger hole: nobody looks for the conflict in the first place. Two rules
can bind the same scope in opposite directions, or a decision can settle a question a rule
already answered differently, and the record will hold both for ever, because the only pairing
pass the groom runs is `groom_near_duplicates` over *titles* (`asf/groom/groom.py:430-448`) and
two contradictory statements rarely share a title.

This spec closes both halves in one pass and one place:

1. **The supersession graph is checked.** `asf check` fails a `supersedes:`/`superseded_by:`
   that names a card that does not exist, a pair that does not point back at each other, and any
   cycle. `asf rules check` drops a superseded rule the way it already drops a retired one.
2. **The record is paired.** A pass over the live rules and decisions proposes every pair whose
   statements overlap above a half, or that share a scope and a named object, ranked, into a new
   groom section carrying both statements, both sources and a precedence hint.
3. **The groom answers it.** `keep A`, `keep B`, `both` and `merge` — the fourth moving the
   loser's source line and History onto the survivor — all through the applier that already
   writes typed fields and History lines for every other groom answer.

## 1. Decisions

### 1.1 Preconditions

Every one of these was read in this checkout, not recalled:

- **`supersedes:` already exists and is already written.** `migrate.upsert_decision` sets
  `meta['supersedes'] = row['supersedes']` (`asf/tick/migrate.py:457-458`), a sorted list of
  `D-nnnn` ids parsed by `SUPERSEDE_RE` (`:227`). It is a *typed* field, so it survives
  `frontmatter.write_typed` and lands in `index.json` — `build_index_data` merges the typed and
  machine blocks into one entry per id (`asf/record/core.py:265-275`).
- **`superseded_by:` does not exist on any card.** The token appears only in a worker REPORT
  (`asf/workers/report.py:25-27`, `:72-80` parse `superseded_by:` out of an adjudicate report)
  and in `harvest.superseded_by` (`asf/harvest/harvest.py:934-981`), which is about a *branch*
  whose card is Closed or removed — a different thing that keeps its name. `ruling_fields` has
  no consumer in `asf/` at all: grep finds it in `asf/workers/report.py` and in
  `tests/test_report.py`, nowhere else. Nothing today writes a `superseded_by:` field onto a
  card, so this spec defines it rather than reinterpreting it.
- **`check` already validates id references exactly this way.** `cmd_check` walks
  `blockedBy` and `stories`, and for each entry that is an id not in `canonical` appends
  `"blockedBy references missing item {b}"` / `"stories references missing item {s}"` at the
  line the key sits on (`asf/record/check.py:95-101`). A finding is `(relpath, line, message)`,
  printed `path:line: message`, and any finding at all makes `cmd_check` return 1 (`:231-234`).
- **`rules.load_rules` reads `index.json`, not the cards** (`asf/rules/rules.py:65-86`), and
  already has the exact shape a supersession exclusion needs: `if entry.get('removed') or
  entry.get('moved_to'): continue  # a retired card: its check no longer binds this record`
  (`:81-82`). Because `superseded_by:` is typed, it reaches that entry with no schema change.
- **A rule card carries a typed `scope:`.** `SETTABLE['rule'] |= {'scope', 'enforced', 'reason',
  'check'}` (`asf/record/new.py:20`), and the suite writes rules as `scope: tick` beside
  `check: tools/checks/r0001.sh` (`tests/test_rules.py:398-400`). A decision card has no
  `scope:`; every type may carry `area:` (`_COMMON_SET`, `asf/record/new.py:19`).
- **A card's statement lives under one of two body shapes.** A migrated decision gets
  `## Statement` + `## Context` (`asf/tick/migrate.py:114-122`); a rule written by hand carries
  `## Statement`, `## Why`, `## Check`, `## Source` (`tests/test_rules.py:16-23`); anything
  minted by `asf new` gets `## Description`, `## Acceptance`, `## Non-goals`
  (`asf/record/new.py:157-165`). All three exist in this checkout, so the reader must take all
  three.
- **`tokenize` lowercases and drops stopwords**, splitting on `[a-z0-9]+`
  (`asf/record/core.py:52-55`), and `jaccard` is intersection over union (`:57-63`).
  `groom_near_duplicates` already uses exactly this pair over titles at `> 0.6`
  (`asf/groom/groom.py:442-447`). `tokenize` destroys case and punctuation, so it cannot be the
  reader of a *named object* — `` `harvest.py` `` and `harvest py` tokenize identically.
- **A groom section is a list of lines, and the applier only reads lines that match.**
  `GROOM_SECTIONS` is an ordered `[(title, key)]` (`asf/groom/groom.py:464-477`);
  `render_groom_file` joins each key's list under its title (`:599-613`); `apply_groom_answers`
  splits the file and skips every line that matches neither `INBOX_ANSWER_RE` nor
  `ANSWER_LINE_RE` (`:240-260`). A section entry may therefore be a *block* — one list element
  containing newlines — and only its first line will ever be parsed as a question.
- **A multi-id question already exists.** `PROPOSAL_RE` matches `- [ ] <id> merge|batch|split
  <rest> —` (`asf/groom/groom.py:34-35`), `_parse_proposal` splits `<rest>` on `+`
  (`:213-223`), and `apply_proposal` writes several cards for one answer (`:176-210`) through
  `_write_card`, which writes typed fields and appends one History line in one place (`:108-118`).
  `apply_proposal`'s `no` branch appends a key to a `reshape_declined:` list so the same
  proposal is never asked twice (`:196-209`) — a suppression this spec copies for `both`.
- **Dedupe in the every-tick pass is by the line's first token.** `merge_groom_text` collects
  `have` from `_LINE_TOKEN_RE` — `^- \[[ xX]\]\s+(\S+)` (`asf/groom/groom.py:619`) — over the
  section's existing lines and adds only lines whose token is not already there (`:646-654`).
  With the proposal shape (`- [ ] T-0001 merge T-0001+T-0002 …`) the token is the lead id alone,
  so two proposals led by the same card collide. A conflicts line must not inherit that.
- **Three regexes downstream read a groom line, and each has a different appetite.**
  `policy.OPEN_QUESTION_RE` needs `- [ ] <id>` … `→ answer: ____` ending the string
  (`asf/groom/policy.py:23-24`); `policy._SUPPRESSABLE_RE` needs `\s+` immediately after the id
  (`:28`); `digest.ANSWER_LINE_RE` needs the same `\s+` and takes the `why` as everything after
  the last ` — ` (`asf/groom/digest.py:10-11`, `:19`). A line whose id is followed by anything
  but whitespace is invisible to the last two.
- **The adjudicate brief is handed the matched lines, not the file.**
  `build.py` renders `'open_questions': '\n'.join(row.open_questions)`
  (`asf/briefs/build.py:280`), and `policy.open_questions` returns the matched line
  (`asf/groom/policy.py:40-49`). The template enumerates the answer grammar it accepts —
  `yes`, `no`, `rank <n>`, `parent <id>`, `S1/S2/S3`, `unblock <id>`
  (`asf/briefs/templates/groom.md`), with a golden copy at
  `tests/fixtures/briefs/golden/groom.md`. An answer word the template does not name is an
  answer the adjudicator will not write.
- **`run_policy_pass` and `suppress` iterate every section, including unknown ones.**
  `_POLICY_BY_SECTION.get(key)` returns None for a section no policy claims and the line passes
  through untouched (`asf/groom/groom.py:577-580`); `suppress` rewrites only what
  `_SUPPRESSABLE_RE` matches (`asf/groom/policy.py:282-293`). A new section key needs no
  registration in either.
- **`asf.groom` may be imported by `asf.record.check`** — it already is:
  `from asf.groom import shape` (`asf/record/check.py:7`). `asf.groom.policy` is the module with
  the import-cycle constraint (its docstring, `asf/groom/policy.py:4-8`), not the package.
- **`append_history_lines` is a `## History`-only special case of a general operation**
  (`asf/record/ingest.py:163-174`): it splits with `parse_sections`, rebuilds one named section
  with `_section_lines` + `section_content`, and rejoins with `render_sections`. Nothing in it
  is specific to History but the literal `'## History'`.
- **The suite runs module-per-process** (`tools/run_tests.py`), and every test module gets the
  hermetic environment with its own operator home, so a new `tests/test_conflicts.py` is picked
  up by discovery with no registration.

- **`asf/briefs/templates/groom.md`** and `tests/fixtures/briefs/golden/groom.md` — the four
  conflict answer words added to the grammar the adjudicator is given.
- Tests: §3.1–§3.7.

### 1.3 Out

- **Any change to what `is_open` means.** A superseded card is not removed and not Closed; it
  keeps its state, its children and its backlinks. Only two consumers change what they do with
  it: the rule run (§2.4) and the pairing pass (§2.6). `feeder`, `harvest`, `lifecycle` and
  every view see exactly what they see today.
- **Reinterpreting `harvest.superseded_by`.** That function answers "is this *branch's* card
  Closed or removed" (`asf/harvest/harvest.py:937-961`) and is untouched. The name collides; the
  meanings do not, and renaming a harvest gate to make room for a field is not this card's work.
- **Applying an adjudicate REPORT's `superseded_by:` claim.** `report.ruling_fields` parses it
  and no caller consumes it. Wiring the ruling's mechanism is F-0090's; this spec defines the
  field that wiring will eventually write, and writes it from the groom only.
- **A configurable threshold.** The card says "above a half". `CONFLICT_OVERLAP = 0.5` is a
  module constant, not a `groom:` key — `build_groom_sections` would have to grow another
  parameter and `conflicts.py` would stop being pure for a number the card fixes.
- **Reading prose for contradiction.** No negation detection, no antonym list, no model call.
  The pass proposes *candidates* by overlap and by shared object; the groom decides whether they
  actually conflict. That is why every answer is a question, never a policy.
- **Pairing anything but a live rule or decision.** Features, Stories, Tasks and Bugs are not
  statements about how the factory works; the `dupes` section already pairs their titles.
- **A policy that answers a conflict automatically.** No entry is added to `policy.POLICIES`.
  Deciding which of two rulings binds the record is exactly the class of question §2.2's
  "deliberately timid defaults" comment (`asf/groom/policy.py:13-15`) says a rule must not touch.
- **Deleting, closing or rewriting the loser.** `merge` copies the source line and the History
  and marks supersession; the loser's card stays in the record, readable, with its own history
  intact.
- **Back-filling supersession for the pairs already in the record.** No command walks the
  existing decisions and guesses. The first groom after this lands asks about them.

### 1.4 The choices

| Choice | Against | Why |
| --- | --- | --- |
| `superseded_by:` on the loser **and** `supersedes:` on the winner, with `check` enforcing the pair | one field, and derive the other | the record is read from both ends: `rules.load_rules` reads one entry and must answer "is this rule still live" without loading the whole record, while a reader of the winner must see what it replaced. One field forces one of those two to scan every card. Two fields with a check is the same trade `parent:`/`## Children` already makes. |
| The check is type-agnostic — it validates `supersedes:`/`superseded_by:` wherever it finds them | rules and decisions only | a supersession field on a Task is either a mistake or a use nobody has designed yet; in both cases a dangling id or a cycle is still a defect, and a check that silently ignores it teaches the record that the field means nothing there. |
| The cycle graph is one edge set, `loser → winner`, built from **both** fields | two graphs, or the `supersedes:` direction only | a cycle can be written half in one field and half in the other; two graphs would each see an acyclic half. De-duplicating both fields into one directed edge set finds the ring however it was spelled. |
| A superseded rule is skipped by `load_rules`, not reported as unenforced | adding it to the `unenforced` list | the unenforced list is the honest-gap list — a rule nobody wrote a check for. A superseded rule has no gap: its successor is enforced in its place. Counting it as a gap would put a permanent fake number on the `== RULES` line. |
| The statement is the body section **alone**; the title is only the fallback when every section is empty | title + body, always | two cards with similar titles and unrelated statements are the `dupes` section's finding, not this one. Folding the title in would manufacture a conflict pair out of every near-duplicate title and blow the "no false pairs in the top twenty" acceptance. |
| A named object is read by three literal rules — a backticked span, a `[[id]]` link, a path-shaped token | `tokenize`, or a general identifier heuristic | `tokenize` lowercases and splits on non-alphanumerics (`asf/record/core.py:52-55`), so `` `harvest.py` `` and the words "harvest" and "py" are the same thing to it — every pair of cards that mention the factory would share an "object". The three rules match how this record actually writes an object, and each is one regex a test can pin. |
| A pair's score is a Jaccard either way: statement tokens for the overlap rule, named objects for the scope rule | two scales, or a fixed weight per rule | both rules answer "how much of what these two are about is the same", so both land in `[0, 1]` and one ranked list is honest. A fixed weight would need a justification the card does not give. |
| Scope is `scope:`, falling back to `area:` | `scope:` only | only rules carry `scope:` (`asf/record/new.py:20`), so a `scope:`-only rule would never pair a decision with a rule by the second rule at all — and a rule-vs-decision conflict is the case the card opens with. `area:` is the typed field every type may carry and means the same thing. |
| The pair is printed in id order; the precedence hint names the winner separately | printing the winner as A | `A`/`B` must be stable for the answer to mean anything a day later, and the dedupe token, the `conflict_declined` key and the groom line all derive from the same order. Precedence can change (a card is re-dated); id order cannot. |
| `merge` merges into the card the precedence hint names | `merge A` / `merge B` | the card names exactly four answers. The line prints the survivor before it is answered (`merge keeps D-0042`), so nothing is hidden; an answerer who disagrees says `keep B` instead, which is the same write minus the copy. |
| Precedence is the newer `date:`/`stage_since:`, ties broken by the higher id | a rule always beating a decision, or the operator choosing every time | a supersession is chronological — the later statement is the one that was written knowing the earlier one. When the record cannot date them, the higher id is the later mint, and that is a fact the record always has. |
| One section entry per pair is a **block**: a question line plus three indented lines | one long single line, or three separate questions | the card asks for both statements, their sources and the precedence hint on the pair. A single line carrying two statements is unreadable and unanswerable; three questions would be answered three ways for one pair. The applier already ignores every line it does not match (`asf/groom/groom.py:255-257`), so the extra lines cost nothing. |
| The pair's dedupe token is `A+B`, taught to `merge_groom_text` for conflicts lines only | changing `_LINE_TOKEN_RE` for every section | the proposal sections have the same latent collision, but changing their dedupe would change which merge proposals the every-tick pass adds — a behaviour change this card did not ask for. `line_token` special-cases `conflicts` and leaves every other line on today's path. |
| `both` writes `conflict_declined:` on both cards | remembering declines in a groom-local file | `apply_proposal` already suppresses a re-ask by writing `reshape_declined:` on the card (`asf/groom/groom.py:196-209`), and the card is the only state that survives a record re-clone. |
| The section is ranked and uncapped | a hard top-twenty cut | the acceptance is about the *ranking* — "no false pairs among the top twenty". A silent cut would hide real pairs with no line saying so; a threshold this high over a set this small does not produce a long tail. The order is the guarantee. |
| `conflicts.py` is pure and takes `canonical`, never `product` | reading thresholds from the product yaml | the pass has to be testable without a product config and importable by `asf.record.check`, which has none. Everything it needs is in the cards. |
| No policy answers a conflict | an auto-answer at a very high score | an auto `keep A` retires a rule the factory enforces, with no session and no operator in the loop. The timid-default comment names this exact class. |

## 2. The design

### 2.1 The two fields

Typed, on any card; written by `frontmatter.write_typed`, read out of `index.json` like every
other typed field.

```yaml
supersedes: [D-0042, R-0007]   # a list of ids this card replaces
superseded_by: D-0051          # the single id that replaced this card
conflict_declined: [D-0042+R-0007]   # pair keys the groom answered `both`
```

`asf/record/new.py`, beside the two lines that are already there:

```python
SETTABLE['rule'] |= {'scope', 'enforced', 'reason', 'check', 'supersedes', 'superseded_by'}
SETTABLE['decision'] |= {'decided_by', 'date', 'supersedes', 'superseded_by'}
```

`conflict_declined` is written by the applier only, never by hand, so it stays out of `SETTABLE`
— exactly as `reshape_declined` does today.

### 2.2 The graph — `asf/groom/conflicts.py`

```python
def supersession_edges(canonical):
    """``{(loser, winner)}`` — one de-duplicated directed edge set off both fields.

    ``superseded_by: W`` on ``L`` and ``supersedes: [L]`` on ``W`` are the same edge; an edge
    written only one way is still an edge here (the missing half is a finding of its own, §2.3),
    so the cycle search sees the whole graph however it was spelled.
    """


def cycles(edges):
    """Every cycle in ``edges``, each as a list of ids starting at its own lowest id and closing
    on it — ``['D-0001', 'D-0002', 'D-0001']``. A self-edge is a cycle of one. Deterministic:
    nodes are walked in sorted order and each cycle is reported once."""
```

An iterative depth-first walk with the three colours; on a back edge the ring is sliced off the
stack, rotated to start at its lowest id, and added to a set keyed by that rotation, so a ring
reached from three different roots is still one finding.

```python
def is_superseded(entry):
    """True when a card (a ``canonical`` record's ``meta``, or an ``index.json`` entry) carries a
    non-empty ``superseded_by``. A dangling successor still supersedes: the card says it has been
    replaced, `check` says by what is missing, and the rule run must not enforce it meanwhile."""
```

### 2.3 The check — `asf/record/check.py`

```python
def supersession_findings(canonical):
    """``[(relpath, line, message)]`` — the four supersession defects, in the tuple shape
    ``cmd_check`` collects (``asf/record/check.py:34``)."""
```

Called from `cmd_check` right after the per-card loop, `findings.extend(conflicts.
supersession_findings(canonical))`, so its results sort and print with every other finding and
make the command return 1.

The four messages, each anchored at the line the offending key sits on (`find_line`), or at the
`id:` line when the key is on the other card:

```
decisions/D-0051.md:6: supersedes references missing item D-0099
decisions/D-0042.md:5: superseded_by references missing item D-0099
decisions/D-0042.md:2: D-0051 supersedes D-0042, which carries no superseded_by: D-0051 (run `asf set D-0042 superseded_by=D-0051`)
decisions/D-0051.md:2: D-0042 is superseded_by D-0051, which does not list D-0042 in supersedes: (run `asf set D-0051 supersedes=[D-0042]`)
decisions/D-0001.md:2: supersession cycle D-0001 → D-0002 → D-0003 → D-0001
```

A cycle is reported once, on the card whose id opens the ring. A card that supersedes itself
reads `supersession cycle D-0001 → D-0001`. A dangling id is reported and then dropped from the
edge set, so one missing card cannot also produce a phantom cycle.

### 2.4 The rule run — `asf/rules/rules.py`

One clause in `load_rules`, beside the retirement clause it already has:

```python
        if entry.get('removed') or entry.get('moved_to'):
            continue  # a retired card: its check no longer binds this record
        if entry.get('superseded_by'):
            continue  # replaced by another rule: its successor binds the record in its place
```

Nothing else moves. `partition`, `run_all` and the `== RULES <n> checked, <v> violations, <u>
unenforced` line all count what `load_rules` returned, so a superseded rule leaves all three
counts at once and its check script is never run — which is the point: its violations were
against a rule the record has replaced.

### 2.5 What a statement, a source and a named object are — `asf/groom/conflicts.py`

```python
#: The body headings a statement may live under, best first — the three shapes this record
#: actually contains (§1.1).
STATEMENT_HEADINGS = ('## Statement', '## Decision', '## Description')


def statement_of(rec):
    """The card's statement as one whitespace-collapsed string: the first of
    :data:`STATEMENT_HEADINGS` whose section has any text, else the card's title. The title is
    never prepended to a section — a shared title is the `dupes` section's finding, not this
    one (§1.4)."""


def source_of(rec):
    """Where the statement came from, for the groom line: the first non-empty line of the card's
    ``## Source`` section, else its ``date:``/``decided_by:``, else its ``relpath``. Never
    empty."""


def scope_of(rec):
    """``scope:``, else ``area:``, casefolded and stripped; None when neither is set. Two cards
    with no scope never share one."""


NAMED_OBJECT_RES = (
    re.compile(r'`([^`\n]+)`'),                      # a code span
    re.compile(r'\[\[([A-Z]-\d+)\]\]'),              # a record link
    re.compile(r'(?<![\w`./-])((?:[\w-]+/)+[\w.-]+)'),  # a path
)


def named_objects(text):
    """The casefolded set of things ``text`` names: every code span's content, every ``[[id]]``
    link's id, every path-shaped token. Empty matches are dropped."""
```

### 2.6 The pass — `asf/groom/conflicts.py`

```python
#: "above a half" (the card). Strictly above, the way `groom_near_duplicates` is strictly above
#: 0.6 (`asf/groom/groom.py:444`).
CONFLICT_OVERLAP = 0.5


def live(canonical):
    """``{id: rec}`` — every open rule and decision that is not superseded. The candidate set:
    `is_open` (`asf/record/core.py:114`) and not :func:`is_superseded`, so answering a pair
    `keep A` removes it from tomorrow's pass with no other bookkeeping."""


def pair_score(a_rec, b_rec):
    """``(score, reason)`` for one ordered pair, or ``(0.0, None)`` when it is not a candidate.

    - ``overlap``: ``jaccard(tokenize(statement_of(a)), tokenize(statement_of(b))) >
      CONFLICT_OVERLAP`` — score is that Jaccard.
    - ``scope``: the two scopes are equal and non-None **and** they share a named object — score
      is ``jaccard(named_objects(a), named_objects(b))``.
    - both: reason ``overlap+scope``, score the larger of the two.
    """


def pairs(canonical):
    """Every candidate pair of the live set, ranked. Each is a ``Pair(a, b, score, reason,
    winner, why)`` with ``a < b`` by id, sorted by ``(-score, a, b)``.

    Excluded: a pair whose key is in either card's ``conflict_declined`` (the groom answered
    `both`), and a pair already joined by a supersession edge in either direction.
    """


def precedence(a_rec, b_rec):
    """``(winner id, why)``: the newer of ``date:``, else ``stage_since:``, else ``updated:``,
    compared as the ISO strings they are; on a tie or with nothing to compare, the numerically
    higher id, which is the later mint. ``why`` is the phrase the line prints — ``newer,
    2026-09-20`` or ``same date, minted later``."""


def decline_key(a, b):
    """``'<a>+<b>'`` in id order — the `both` answer's suppression key and the line's dedupe
    token, one string derived from the pair alone."""
```

`pairs` is O(n²) over the live rules and decisions, the same shape `groom_near_duplicates`
already runs over every open item (`asf/groom/groom.py:437-447`), and over a much smaller set.

```python
#: A conflicts line's dedupe token is the pair, not its lead id: one rule conflicts with several
#: decisions, and `_LINE_TOKEN_RE`'s first token would collapse them into one line (§1.4).
_CONFLICT_TOKEN_RE = re.compile(r'^- \[[ xX]\]\s+([A-Z]-\d+)\s+conflicts\s+([A-Z]-\d+)\b')


def line_token(line):
    m = _CONFLICT_TOKEN_RE.match(line)
    if m:
        return f"{m.group(1)}+{m.group(2)}"
    m = _LINE_TOKEN_RE.match(line)
    return m.group(1) if m else line
```

Both the `have` set and the new-line loop in `merge_groom_text` call `line_token`, and the block
form (a multi-line entry) matches on its first line because `.match` anchors at the start. Every
other section's token is byte-identical to today's.

### 2.8 The apply step — `asf/groom/groom.py`

```python
#: A conflicts question and its four answers (§2.7). Matched before `PROPOSAL_RE`: the verbs do
#: not overlap, but the answer word `merge` does, and the line decides, not the answer.
CONFLICT_RE = re.compile(
    r'^- \[[ xX]\]\s+(?P<a>[A-Z]-\d+)\s+conflicts\s+(?P<b>[A-Z]-\d+)\b')
CONFLICT_ANSWER_RE = re.compile(r'^(keep\s+[AB]|both|merge)$', re.IGNORECASE)


def apply_conflict(canonical, a, b, answer, date, who, emit=None):
    """One conflicts line's answer. Returns the number of cards written.

    `keep A` / `keep B`  the loser gains ``superseded_by: <survivor>``, the survivor gains the
                         loser in ``supersedes:``; one History line each.
    `both`               both cards gain ``decline_key(a, b)`` in ``conflict_declined:``; the
                         pair is never proposed again.
    `merge`              `keep <the precedence winner>`, and first the survivor's ``## Source``
                         gains every source line of the loser's it does not already carry, and
                         its ``## History`` gains the loser's History lines, each suffixed
                         ``(from <loser>)``.

    Anything else, including a blank slot, writes nothing.
    """
```

Dispatched in `apply_groom_answers` immediately after `_attribution` and before the `PROPOSAL_RE`
arm (`asf/groom/groom.py:265`), so a conflict line never reaches `_parse_answer`:

```python
        cm = CONFLICT_RE.match(line)
        if cm and CONFLICT_ANSWER_RE.match(raw_answer):
            applied += apply_conflict(canonical, cm.group('a'), cm.group('b'), raw_answer,
                                      date, who, emit=emit)
            continue
```

Every write goes through `_write_card` (`:108-118`), so each card gets its typed field and one
History line in one place, and `rec['meta']` is updated in memory for the rest of the run.

The History lines, in the shape every other groom answer writes (`- <date> groom: <field> →
<value> <who>`):

```
- 2026-09-24 groom: superseded_by → D-0042 (operator)
- 2026-09-24 groom: supersedes → D-0042, R-0007 (operator)
- 2026-09-24 groom: conflict declined D-0042+R-0007 (operator)
- 2026-09-24 groom: merged R-0007's source and history, superseded_by → D-0042 (operator)
```

`emit` fires one `groom_answer` event per card written, exactly as `apply_proposal`'s does
(`:268-272`), with `section` `conflicts` and `field` one of `superseded_by`, `supersedes`,
`conflict_declined`.

Two refusals, each printing one line and writing nothing — the shape `merge_tasks` already uses
for a Task that is not ready (`:157`):

```
groom: keep A D-0042+R-0007 skipped — R-0007 is already superseded by D-0051
groom: keep B D-0042+R-0007 skipped — D-0042 would close a supersession cycle through R-0007
```

The second is checked with `conflicts.cycles(edges | {(loser, survivor)})`: an answer that would
create a ring is refused at the point of writing rather than caught by the next `asf check`.

Idempotence, which `--apply` requires of every answer (`:230-232`): `keep`/`merge` return 0 when
the loser already carries that `superseded_by` and the survivor already lists it; `both` returns
0 when both cards already carry the key; `merge` copies only source lines and History lines the
survivor does not already have. Re-applying the same groom file writes nothing and prints
nothing.

## 4. Records

**Item cards** (`rules/R-nnnn.md`, `decisions/D-nnnn.md`, and any card a hand writes one on)
gain up to three typed frontmatter fields:

```yaml
supersedes: [R-0007]
superseded_by: D-0042
conflict_declined: [D-0042+R-0007]
```

Each reaches `index.json` through `build_index_data` with no schema change, because every typed
field already does.

**`## History`** on each card written, one line per answer, in the grammar every other groom
answer uses:

```
- 2026-09-24 groom: superseded_by → D-0042 (operator)
- 2026-09-24 groom: merged R-0007's source and history, superseded_by → D-0042 (operator)
```

**`## Source`** on a `merge` survivor gains the loser's source lines, and `## History` gains the
loser's History lines suffixed `(from <loser>)`. No other section of any card is written.

**`groom/<date>.md`** gains `## Conflicting rules and decisions`, one block per pair, exactly as
§2.7 prints it. **`groom/<date>-digest.md`** needs no change: a conflicts question is an open
question like any other, so it lands under **Spoken for** as `GROOM → ADJUDICATE` under the
attempt cap and under **For you** above it, through `digest._classify_groom_lines` unmodified.

**`metrics/events/<day>.jsonl`** gains no new kind: each card written emits the existing
`groom_answer` kind with `section: conflicts` and `field` one of `superseded_by`, `supersedes`,
`conflict_declined`.

**stdout**: `asf check` gains the five finding shapes of §2.3; `asf rules check`'s `== RULES <n>
checked` line drops every superseded rule from all three counts; `asf groom` prints
`Conflicting rules and decisions: <n>` in its per-section counts, and one `groom: … skipped —`
line per refused answer.

**Nothing else.** No new stream, no new command, no new item type, no schema version bump, and
no card is closed, removed or deleted by anything in this spec.
