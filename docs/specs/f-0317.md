# F-0317 — one branch name, four readers, and a Feature with nowhere to go

`asf.feeder.rows.replan_branch` mints the replan's branch under the plan prefix on purpose, and
its own docstring says why (`asf/feeder/rows.py:1657-1661`):

```python
def replan_branch(product, fid):
    """The replan's branch: the plan lane, under a name that is not the Feature's own plan
    branch — the ingest reads ``<plan prefix><id>`` as the Feature's plan, and a replan is not
    that document (:data:`asf.record.replan.SUBDIR`)."""
    return branch_for(product, 'plan', f'{fid}-replan')
```

The name carries the distinction; nothing reads it back. `Conventions.branch_kind`
(`asf/conventions.py:1276-1287`) matches on the prefix alone, so the replan branch and the
Feature's plan branch both answer `'plan'`, and four readers downstream then treat the replan as
the Feature's plan document. `landed_doc` (`asf/feeder/rows.py:965-974`, called at `:1026`) is the
one that deadlocks:

```python
    doc = _conventions(product).branch_kind(c.get('branch') or '')
    return doc in ('spec', 'plan') and \
        f'{doc} on origin/{trunk_of(product)}' in (item.get('evidence') or ())
```

The reporting product's F-0002 has its *original* plan on the trunk, so its evidence carries
`plan on origin/main`. Its replan branch was sent back by the landing gate. `landed_doc` reads
the branch as a plan, finds a plan on the trunk, and concludes the refusal "was answered by the
landing itself" — so `correction_rows` drops the correction and claims no id for it (`:1026-1029`).
Nothing then launches the branch, and the only row the Feature gets is the non-launching
`PUSHED → LAND` that says the branch is waiting to land: the line the tick printed about 960 times
while the branch sat BACK since 2026-10-07 11:12Z.

The card's requirement is the sentence those four readers are missing: **a replan branch is the
replan's branch, not the Feature's plan branch.** With it, the correction survives, the row that
answers it launches, and the session it launches is a replan session that can do the work — which
is the card's second report: the brief the replan session got named no Story and no acceptance
line, and the session ended `needs input — S-0138 has no acceptance text`.

Every statement below is measured in this worktree at `63da246`, the branch's base, 2026-10-10
(§1, P1–P7). The decisive one is P2/P7: today the Feature's one row is non-launching and
nothing can clear it; reading the replan branch as a replan turns that into exactly one
launching row, and that row still carries the wrong brief kind until §3 lands too.

## Decisions

### Preconditions — measured in this worktree at `63da246`, 2026-10-10

P1–P8 are each one run of `python3 -I <script>` against this checkout, on the fixture product
`Conventions(branch_prefixes={'spec': 'spec', 'plan': 'plan', 'task': 'task'})`. The reporting
product's own prefixes differ; nothing in P1–P8 depends on them, because every name is derived
from `branch_for`/`replan_branch` rather than written out. P9 is the one exception: it is measured
against the reporting product's record and PR cache rather than this checkout, and it is the only
block here whose numbers can move under you — it is a count of live branches, not a property of
the code.

* **P1 — the two branches are indistinguishable to `branch_kind`, and the documents are not the
  same file.**

  ```

  plan branch(F-0002)          = plan/F-0002
  branch_kind(replan branch)   = plan
  branch_kind(plan branch)     = plan
  strip_prefix(replan branch)  = F-0002-replan
  replan doc_path              = docs/plans/replans/f-0002-d41d8cd98f00.md
  ```

  `strip_prefix` already separates them, and `asf.record.replan.doc_path`
  (`asf/record/replan.py:128-131`, `SUBDIR = 'replans'` at `:70`) confirms the replan is its own
  file under its own sub-directory — never `docs/plans/f-0002.md`. The distinction exists in the
  record and in the branch name; only the reader is missing.

* **P2 — the correction is dropped and the Feature is claimed by nobody.** A Feature with
  `evidence: ['spec on origin/main', 'plan on origin/main', '0/3 tasks Closed']`, a pending
  `reshape:`, and a `landing-gate` correction on its replan branch:

  ```

  ```

  No row, and no id in `ids` — so nothing downstream even knows a correction was held.

* **P3 — the only row left says the branch is waiting to land, for ever.** The same Feature, with
  the lane reporting the branch BACK:

  ```

  replan_row launches          = False
  ```

  That is the printed line, and the deadlock in one pair of facts: the row waits on a landing that
  waits on a correction that was dropped.

* **P4 — the `RESHAPE → REPLAN` row cannot launch on a BACK branch, and `STARVED → PLAN` can.**
  `asf.invariants.check_i4` against `LANE_LAUNCH_KINDS['BACK']` (`asf/invariants.py:812-816`):

  ```

  I4 on a BACK replan branch: STARVED → PLAN   -> launches
  I4 on a BACK replan branch: PUSHED → LAND    -> HELD, waits=landing: plan/F-0002-replan BACK
  ```

  This is why the fix cannot simply raise the replan row again: I4 would hold it with the very
  same `WAITS ON landing: … BACK` wording, and the deadlock would come back by another road. It is
  also the reason D3 keeps the row's *kind* as `STARVED → PLAN`.

* **P5 — reading the replan branch correctly is not enough: the row it raises briefs the wrong
  session.** The same correction against a Feature whose plan is *not* on the trunk, so
  `landed_doc` is `False` today:

  ```

  ```

  `brief_kind='plan'` on the replan branch. A `plan` brief tells the session to write
  `docs/plans/f-0002.md` — the Feature's plan, which is on the trunk and approved. The replan
  document the branch exists for is never written, and the gate refuses the branch again.

* **P6 — the replan brief carries no Story at all, and no brief carries acceptance text.**

  ```

  STORY_KINDS                  = ('spec', 'spec-amend', 'plan', 'review', 'adjudicate', 'spec-plan', 'direct')
  ```

  Two separate gaps. `'replan'` is not in `STORY_KINDS` (`asf/briefs/preamble.py:284`), so the

* **P7 — end to end through `plan_rows`, the defect and the fix.** One fixture Epic, one decided

* **P9 — the blast radius on the reporting product today is two Features, not one.** Measured

### Preconditions the work depends on

* `asf.record.replan.SUBDIR` stays `'replans'`, so a replan is never a file the plan scan reads
  (P1). If a replan ever moved into `plans_dir` itself, D4 would have to change with it.
* `replan_branch` stays the only place a replan branch name is minted (P1, D1).
* `LANE_LAUNCH_KINDS['BACK']` keeps `'STARVED → PLAN'` and `'STALEMATE → ADJUDICATE'` (P4). The
  acceptance pins both, because D3 rests on them.
* `asf.proves.card_bullets` stays the single reader of a card's acceptance bullets (D6).
* The row the fix raises carries `correction=`, so all three caps exempt it — `finish_first`
  (`asf/feeder/rows.py:3032`), `plan_ahead_cap` (`:2985`) and `build_cap` (`:2950`), each testing
  `not r.correction`. The deadlocked Feature is therefore not re-held by a cap the moment it gets
  a row.

## The design

### §1 — `REPLAN_SUFFIX` and `is_replan_branch` (`asf/feeder/rows.py`)

Beside `REPLAN_KIND` (`:160`), one constant; beside `replan_branch` (`:1657`), its inverse:

```python
#: the suffix :func:`replan_branch` adds to a Feature id, and the one string
#: :func:`is_replan_branch` reads back: a replan is on the plan lane, under a name that is not
#: the Feature's own plan branch
REPLAN_SUFFIX = '-replan'


def is_replan_branch(product, branch):
    """True for a branch :func:`replan_branch` minted: the plan lane, under a name ending
    :data:`REPLAN_SUFFIX`. The replan is its own document
    (``<plans_dir>/replans/<fid>-<digest>.md``, :data:`asf.record.replan.SUBDIR`) and never the
    Feature's plan, so a reader that asks ``branch_kind(branch) == 'plan'`` in order to say
    something about *the Feature's plan* asks this first (F-0317)."""
    conv = _conventions(product)
    b = branch or ''
    return conv.branch_kind(b) == 'plan' and conv.strip_prefix(b).endswith(REPLAN_SUFFIX)
```

and `replan_branch` mints from the constant: `branch_for(product, 'plan', f'{fid}{REPLAN_SUFFIX}')`.
`branch_kind` and `strip_prefix` are untouched (D2); the predicate is the product's own answer to
"is this branch the Feature's plan document", in one place, for the three readers below.

### §2 — `landed_doc` stops answering for a replan (`asf/feeder/rows.py:965-974`)

```python
    if (c or {}).get('kind') != LANDING_GATE:
        return False
    branch = c.get('branch') or ''
    if is_replan_branch(product, branch):
        # F-0317: the replan is not the Feature's plan — a plan on the trunk answers nothing
        # about the replan the gate refused, and reading it as an answer left the Feature with
        # no row at all
        return False
    doc = _conventions(product).branch_kind(branch)
    return doc in ('spec', 'plan') and \
        f'{doc} on origin/{trunk_of(product)}' in (item.get('evidence') or ())
```

The F-0090 case the function was written for is untouched: a settled spec or plan hold on the
Feature's own document branch still reads as landed once the ingest sees the document on the trunk.
What changes is one branch shape, which never had a trunk line of its own to match (D4).

### §3 — the correction row briefs a replan (`asf/feeder/rows.py:1073-1080`)

```python
        doc = product.conventions.branch_kind(branch) if c.get('kind') == LANDING_GATE else None
        rounds_cap = config_keys.value('harvest.round_cap', CORRECTION_ROUNDS)
        if doc in ('spec', 'plan') and same < rounds_cap:  # a document the gate refused
            # F-0317: the replan is on the plan lane but is not the plan — a `plan` brief here
            # writes the Feature's approved plan instead of the replan the branch exists for
            what = REPLAN_KIND if is_replan_branch(product, branch) else doc
            out.append(Row(tier=tier, kind=STARVED_SPEC if doc == 'spec' else STARVED_PLAN,

                           branch=branch, correction=c['text'],
                           reason=f"the lane held it ({c['kind']}), round {rounds}: the {what} "

```

The row's `kind` stays `STARVED → PLAN`, which I4 admits on a BACK branch and every cap frozenset
already names (D3, P4); `brief_kind` becomes `replan`, which `asf.briefs.build.KINDS` already
holds, `MODEL_TABLE` already prices (`LIGHT`), `roles` already staffs and `NEW_DOC_SESSIONS`
already counts as in flight. The `reason` says `the replan cannot land as it stands`, so the
operator reading the row is told which document is meant, not only which lane.

At or past the round cap the existing path takes over unchanged: `STALEMATE → ADJUDICATE` with
`brief_kind='adjudicate'` (`:1095-1098`), also admitted on BACK (P4). Either way the Feature gets a
row that launches — the one thing it has not had.

### What it looks like when it is there

A Feature whose replan branch the landing gate sent back, whose original plan is on the trunk:

* `asf next --all` shows one row for it — `STARVED → PLAN`, *would launch*, on
  `<plan prefix><fid>-replan`, reason `the lane held it (landing-gate), round N: the replan cannot
  land as it stands`. Not a second row: the correction speaks for the Feature, so no
  `PUSHED → LAND` is raised beside it (P7).
* The session it launches is a replan session: a `replan` brief, the replan document as its
  deliverable, the hold's text as its correction, and the lane's note naming the replan.
* That brief carries `Stories of the Feature, with their acceptance lines:` and, beneath it, one
  numbered block per Story, plus a `stories:` field on every Task line — so the `stories:` the
  document's format demands and the `Acceptance` each section needs are both answerable from the
  brief alone.
* The deadlocked Feature on the reporting product clears on the first tick after the change: no
  migration, no stored field to rewrite. If its hold is already at the round cap, the row is
  `STALEMATE → ADJUDICATE` instead — still a row that launches.

## Acceptance tests

### S-102505: one constant mints the replan branch name and one predicate reads it back
