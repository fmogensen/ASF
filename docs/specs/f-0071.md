# F-0071 — the S1 lane: tiers, reserved capacity, no ladder, a clock

The card is the requirement. Most of the lane is already on `main` (`7dc6ca5`, `06a0a47`):
the feeder tiers, the `fix-bug` brief, the pool's reserve rule, the incident data and the
same-session correction for a dead session. This spec says what already holds, and specifies
the six gaps where the card's acceptance still fails today.

## 1. Decisions

### What already holds (verified against `origin/main` at `689e91c`)

|---|---|---|
| 1 — fixed tiers S1 → S2 → rest; no tier-2 row while an S1 has no session | `asf/feeder/tiers.py` `select`, `asf/feeder/rows.py` `bug_rows` / `candidates` | `tests.test_feeder.TiersTest` (5 tests, green) |
| 2 — the reserve *rule* (`worker_pool.reserve_for_s1`, default 1/1, per lane) | `asf/workers/pool.py` `reserve_from_config`, `Pool.pick_account` | `tests.test_workers.TestPick.test_reserve_rule`, `test_reserve_is_per_lane` |
| 3 — the `fix-bug` brief: no spec, no plan, no review; `## Fix` is the plan | `asf/briefs/templates/fix-bug.md`, `rows.bug_rows` → `brief_kind='fix-bug'` on `fix/<id>` | `tests.test_briefs` `test_a_fix_bug_brief_carries_the_fix_and_the_named_test` |
| 4 — one correction for a dead session before the operator is raised | `asf/tick/step_health.py` `handle_dead`, `asf/workers/stall.py` `correct_once` | `tests.test_tick_steps` `test_dead_session_is_corrected_first` and the B-0028 tests |

### What still fails the card, and this spec fixes

1. **The reserve lapses once the S1 has a session.** `workers.wave` computes "an S1 is open"
   as `pool.s1_open(rows)`, which looks only at the rows it was handed. The feeder never emits a
   row for an S1 a session holds, so from the tick (`step_wave`) the reserve is dropped exactly
   while the incident is being worked. A second S1 filed then finds no reserved slot.
   `test_feature_waits_on_the_reserved_slot` passes only because it hands the running S1's row
   in by hand.
2. **The harvest does not require the named test.** The `fix-bug` brief and the spawn header both
   say *"Harvest requires the named test"*. `asf/harvest/harvest.py` runs the product's whole
   test command and never checks that the test the Bug's `## Fix` names exists.
3. **The wave row never carries the test.** `step_wave.worker_row` builds `pool.Row` without
   `test=`, so `spawn.brief_for` always prints `(name the failing test you add, in your report)`
   even when the card names one.
4. **A red harvest gate files a Bug with no correction.** `land_ff` → `file_gate_bug` files an S2
   straight away. The job's session never gets its one correction attempt.
5. **The clock is not flagged.** `incidents()` computes `starved`, but nothing prints it and the
   tick records nothing when it is true.
6. **No incident row carries time-to-land, and `asf status` has no `INCIDENTS` line.**

### In / out

| In | Out |
|---|---|
| The reserve is held off the record's open S1s, not off the wave's rows | Pre-empting (killing) a running Feature session to free a slot for an S1 |
| A named-test gate on `fix/` branches in the harvest | Running the named test on its own by name (see D4) |
| The card's named test carried on the wave row into the spawn header | Changing the `fix-bug` brief template text |
| One same-session correction on a red harvest gate, before the Bug is filed | Correction for a tick step that throws with no job behind it; that is the same-session-correction Feature's |
| `S1 STARVED` on the `INCIDENTS` line; an `s1-starved` event once per Bug per day | Filing a Bug for a starved S1 |
| An `incident` event on landing, with minutes from filing to landing | The incident event under `landing: pull-request` (the merge queue lands it; see D8) |
| The `INCIDENTS` line first in `asf status` (S-0003) | An `INCIDENTS` line in any other view |

### Preconditions

- An S1 Bug that wants the lane is `decided: true`. `rows.bug_rows` already skips an undecided
  Bug; the `INCIDENTS` line still shows it, so a human sees an undecided incident.
- A Bug card names its test in `## Fix` or `## Acceptance` with a path and a test name, e.g.
  ``Test: `tests/test_checkout.py::test_timeout_is_pending_not_500` `` (the form
  `preamble.TEST_RE` already reads), or in a typed `tests:` field.
- The session ledger keeps `brief`, `worktree` and `corrected` for a job (it does:
  `pool.SESSION_FIELDS`, `RUN_FIELDS`). Health reaps a worktree only once the trunk holds its tip
  (B-0009), so a held branch's worktree is still there for a correction.
- B-0013, B-0014 and B-0015 are the first incidents the lane speeds up. None of them is a
  prerequisite for this work.

### Choices

| # | Chosen | Against | Why |
|---|---|---|---|
| D1 | "An S1 is open" for the reserve = any item with `type: bug`, `severity: S1`, `decided: true`, state not `Resolved`/`Closed` in the index, whether or not a session holds it (`rows.s1_open(items)`) | Keep `s1_open(rows)`; or count undecided S1s too | The card says *while any S1 is open*. The rows only show *unheld* S1s. An undecided S1 cannot launch, so holding a slot for it would idle capacity no row can use. |
| D2 | `wave()` takes `s1_is_open=None`; `None` falls back to `s1_open(rows)` | Change the signature outright | Existing callers and tests (`asf workers wave` from a rows file) keep working. The tick passes the index answer. |
| D3 | The reserved slot may go to any `BUG → FIX` row (S1 or S2), as `pick_account(is_fix=True)` does today | Only an S1 may take the reserve | The card says *never given to non-Bug rows*. The wave orders S1 fixes first (`wave.order`), so an S2 only reaches the reserve after every S1 in the wave got a slot. |
| D4 | Named-test gate = the test's file exists in the rebased tree and holds `def <name>` (the last `::` segment), then the product's whole gate runs as today | Run `<runner> <test id>` per named test | The factory's test command is `unittest discover`; the card's ids are pytest-shaped (`path::name`). A per-test runner would need a new convention for every product. Existence plus the whole suite green is the smallest check that the test is there and passes. |
| D5 | A card that names no test: the branch must add one (`git diff origin/<trunk>...HEAD` adds a `def test_` line under a path the product's test command collects, i.e. a file matching `test_*.py`/`*_test.*`/`*.test.*`) | Hold every Bug with no named test | The brief tells a session with no named test to add one and name it. Holding would stall the incident on a card edit. |
| D6 | Correction on a red gate calls `stall.correct_once` synchronously, then retries the landing once | Queue the correction for the next tick's `health` step | `handle_dead` already corrects synchronously inside the tick; one pattern, not two. A queued correction adds a tick (minutes) to an incident whose point is hours. |
| D7 | The S1 clock runs from the card's `created`, else `stage_since`; `starved` = S1 open, no session holds it, older than `stage_limits.s1_hours` (default 2) | Track "a slot was free" per tick in state | A new S1 blocks every tier-2 row and holds the reserve (D1). So an S1 without a session after 2 h means launching failed (quota, spawn, runtime), which is exactly what the rule exists to catch. `stage_since` moves with state changes, so it would restart the clock. |
| D8 | The `incident` event is written by the tick's `harvest` step when `land_ff` lands a `fix/` branch whose item is an S1/S2 Bug | Write it when ingest first sees the Bug `Resolved` | Harvest knows the landed sha and the moment it landed. Ingest sees neither, only a later record state. PR-lane landing is left to the merge queue and is out of scope here. |
| D9 | `S1 STARVED` shows on the `INCIDENTS` line, and the `wave` step appends one `s1-starved` event per Bug per UTC day | A rule card with a `check:` script, or a filed Bug | `rules check` reads the index, which has no session data, so it cannot see *no session*. A Bug about a Bug that is not moving is noise; the event is what `metrics` counts. |
| D10 | Stories S-5750–S-5755, minted from this session's range `S:5750-5799` | — | S-0003 already exists and is kept as it is. |

## 2. The design

### 2.1 The reserve follows the record (S-5750)

`asf/feeder/rows.py` gains:

```python
def s1_open(index):
    """True while any decided S1 Bug is not Resolved/Closed — held by a session or not (F-0071 D1)."""
    items = items_of(index)
    return any(b.get('severity') == 'S1' and b.get('decided') is True and is_open(b)
               for b in ix.of_type(items, 'bug'))
```

`asf/workers/wave.py`: `wave(product, rows, n, ..., s1_is_open=None)`, with
`s1 = pool_mod.s1_open(rows) if s1_is_open is None else s1_is_open`.

`asf/tick/step_wave.py` `run`: `_wave(..., s1_is_open=feeder_rows.s1_open(items))`.

Once this is in, while B-0013 (S1) is held by `fix-b-0013` in a 3-slot local lane with
`reserve_for_s1: {local: 1}`, the tick launches at most one Feature row in that lane. The third
slot shows `waits … — reserved for S1` until the Bug is `Resolved`.

### 2.2 The row carries the named test (S-5752)

`step_wave.worker_row(row, brief, items, product)` sets
`test=', '.join(preamble.named_tests(preamble.card_sections(product, item), item, None)) or None`
for a `fix-bug` brief. `spawn.brief_for` then prints `Harvest requires the named test: <id>`.

### 2.3 The harvest's named-test gate (S-5751)

In `asf/harvest/harvest.py`:

- `named_test_gate(tmp, trunk, tests, conv) -> (ok, line)`:
  - `tests` non-empty: every entry `path[::…]::name` needs `path` to exist under `tmp` and
    contain `def name` (a bare `path` needs only the file). The first miss returns
    `(False, 'named test missing: <entry>')`.
  - `tests` empty: the branch's diff against `origin/<trunk>` must add a `def test_` line in a
    test file (D5), else `(False, 'no test named on the card and none added on the branch')`.
- `land_ff` runs it after `rebase_and_resolve` and before `product_gate`, only when
  `conv.branch_kind(branch) == 'fix'`. A miss prints `held <branch>: <line>` and goes the same
  red-gate path as a failing test command (2.4).
- `run_product_harvest(..., bug_tests=None)`: `bug_tests(item_id) -> [test ids]`. The tick passes
  a closure over the record clone that reads the Bug card with `preamble.card_sections` /
  `named_tests`. `None` (a hand run with no record) skips the gate and prints
  `harvest: <branch> named-test gate skipped — no record` once.
- The PR lane runs the same named-test check (in a throwaway worktree) before
  `mark_session(harvest='pr')`. A branch with a missing test is held, not handed to the queue.
  CI then runs the test in the merge queue: the card's *pass in CI*.

### 2.4 One correction before a Bug (S-5753)

`land_ff`, on a red gate (named-test or `product_gate`):

1. The session record (`record`, already in hand) is not `corrected` and has `brief` and
   `worktree` → `stall.correct_once(product, record, f'the harvest gate is red on {branch}:\n{line}\n'
   'Fix it on this branch, commit, push.', runtime)`. The ledger gets `correction: 'harvest-gate'`
   next to `corrected: 1`.
2. It returns True → `git fetch origin <branch>` and one more landing attempt (the loop's second
   pass). Line: `corrected <branch>: gate green after one correction` then `landed …`.
3. It returns False, or the session was already corrected, or the rerun is red again →
   `file_gate_bug` exactly as today.

`land_ff` takes a `runtime_fn` (default `step_health._runtime`'s equivalent, via
`runtime.from_config`) so tests inject `FakeRuntime`. The correction's re-run holds the
harvest step, as `handle_dead` already does in `health` (D6).

### 2.5 The clock, flagged (S-5754)

- `render.incidents`: age from `created`, else `stage_since` (D7). `Incident` gains no field;
  `starved` keeps its meaning.
- `render.incidents_line(incidents) -> str | None`: `None` when no S1 is open, else
  ```
  **INCIDENTS** B-0013 S1 3h no session S1 STARVED · B-0014 S1 40m fix-b-0014 · B-0021 S2 1h no session
  ```
  S1 first, then S2, oldest first (the order `incidents()` already returns). The session cell is
  the holding session's job, or `no session`. `S1 STARVED` is appended only when `starved`.
- `step_wave.run`, after the wave: for each starved incident, `ctx.event('s1-starved', item,
  age_minutes, since)` unless today's `metrics/events/<day>.jsonl` already has an
  `s1-starved` line for that item. It also prints `S1 STARVED <id> <age> no session`.

### 2.6 `INCIDENTS` first in `asf status` (S-0003)

`asf/views/status.py` `render`: when `incidents_line(...)` is not `None`, it is the first line of
the output, before `**FACTORY STATUS hh:mm**`, followed by a blank line. The inflight list is
`step_wave.inflight(product)`, the same one `ready_cell` uses. A failure reading it prints
`**INCIDENTS** ? (<ExceptionName>: <msg>)` and the table still renders. With no S1 open, the
output is byte-identical to today's.

### 2.7 The incident row (S-5755)

`step_harvest.run`: for every branch `run_product_harvest` returns as `landed`, if its item is an
S1/S2 Bug in the record clone: `ctx.event('incident', item=<id>, severity=<S1|S2>,
filed=<created|stage_since>, landed=<now ISO>, sha=<harvested sha>,
minutes_to_land=<int>)`. The sha comes from `harvest.sessions_by_branch(state_dir)[branch]
['harvested']`. `run_product_harvest` is unchanged apart from `bug_tests` (2.3).

## 4. Records

| What | Where | Shape |
|---|---|---|
| `incident` event | `metrics/events/<day>.jsonl` in the record clone, via `Context.event` | `{kind: incident, item, severity, filed, landed, sha, minutes_to_land, product, ts}` |
| `s1-starved` event | same stream | `{kind: s1-starved, item, since, age_minutes, product, ts}`, at most one per item per UTC day |
| Correction on a red gate | `~/.ASF/state/<product>/sessions.jsonl` | a field-update line `{job, corrected: 1, correction: "harvest-gate"}` (both already in `RUN_FIELDS`, so a relaunch clears them) |
| The correction brief | `~/.ASF/state/<product>/briefs/<job>.correction.md` | the original brief + `CORRECTION: the step failed with:` + the gate line (as `correct_once` writes it today) |
| A held `fix/` branch | tick output | `held fix/B-nnnn: named test missing: <id>` or `… no test named on the card and none added on the branch` |
| A filed gate Bug | `bugs/B-nnnn.md` in the record | unchanged (`file_gate_bug`), written only after the correction |
| Launch refused by the reserve | tick output | `waits <job> <item> — reserved for S1` (unchanged text, now also while the S1 is held) |
| Config | `config.yaml` | `worker_pool.reserve_for_s1: {local: 1, cloud: 1}` (exists, default 1/1); `stage_limits.s1_hours` (exists, default 2). No new key. |
| `asf status` | stdout | `**INCIDENTS** …` as the first line when an S1 is open |

No schema version bump: the record gains no typed field. The two event kinds are new lines in
an existing stream.
