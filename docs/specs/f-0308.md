# F-0308 — two heads on the remote: what ASF runs, and what a stranger should install

ASF cuts a release tag on **every merge to main that changes the package** — one patch version a
merge, by the `release` workflow, on the push (`asf.version.cut`). There are 263 of them on origin
today and the newest, `v0.1.261`, was cut from a commit whose test suite had not finished running
when the tag went up: nothing in that path reads CI. Every consumer then resolves the same thing,
"the newest `v<x.y.z>` tag on the remote" — the bootstrap with no `[ref]`, `asf.install.newest_tag`,
`asf status`'s Version row — so a first install of ASF pins a tag that is minutes old, ungated, and
sometimes red.

That is the right default for the one machine that *writes* ASF and the wrong one for everybody
else. This card splits the answer in two:

* **edge** — every green tag, no ceremony. What ASF itself runs, named so somebody else can run it.
* **stable** — promoted at most weekly, and only for a tag that has a green rehearsal, has sat on
  edge for 48 hours, and collected no S1 in that time.

A channel is one head on ASF's own remote, `refs/heads/releases/edge` and
`refs/heads/releases/stable`, pointing at the commit of the release tag the channel offers. One
`git ls-remote` reads it, which is what makes it usable by the bootstrap — a script that runs
before `asf`, `gh` or a token exists. The tags themselves are untouched: a channel filters and
delays what is already cut, it never cuts.

### In

* **Two channel heads on ASF's own remote** — `refs/heads/releases/edge` and
  `refs/heads/releases/stable`, each pointing at the **commit** of the release tag the channel
  offers, fast-forward only (D1, D2; P7, P8).
* **One new module, `asf/channels.py`** — the pure line parser that resolves a channel from one
  `git ls-remote` (D3), the publisher through the guard, the edge rule, the stable gate's four
  criteria, the channel log, and the daily part.
* **edge takes every green tag**: the newest tag whose `ci_verdict` is `green` (P9), scanned
  newest-first over at most `lookback_tags` tags, never backwards, never on Unknown (D4).
* **stable is promoted behind four criteria**, each printed met or unmet with its evidence, and
  only when all four are met: the weekly cadence, 48 hours on edge, the rehearsal check, and no
  S1 (D6, D7, D8, D9).
* **The channel log** — `state/<product>/channels.json`, registered (P17): each channel's current
  tag, commit and time, and the bounded list of edge publications that the 48-hour window is
  measured from (D5).
* **`asf channels [--json]`** — read-only: both channels, the candidate, and the gate's rows with
  their evidence. Nothing is written, nothing is pushed (D12).
* **`asf upgrade --to edge` / `--to stable`** — a channel name resolves to its version tag before
  `resolve_target`'s existing steps see it, so the CI guard, the pending marker and the install
  record all carry the tag and the commit they carry today.
* **The bootstrap's default becomes the stable channel** — `tools/install.sh` with no `[ref]`
  resolves `ASF_CHANNEL` (default `stable`), falls back to the newest tag when the channel is
  unpublished, and prints which of the two it used and why (D13; P6).
* **`release.channels`** — four settings under the `release:` block, documented and unchecked
  (D11; P16), and the docs: `docs/products.example.yaml`, the module docstrings, the README's
  Install section where it names the bootstrap.

### Out

* **Moving the factory's own install onto edge.** It runs the trunk head (P12), which is edge's
  own upper bound — every tag edge can offer is an ancestor of it — and that path has its own
  batching, CI refusal, drain and rollback. Pointing the factory at a channel it publishes is a
  second card, and a riskier one than this.
* **The per-product channel switch and the tick that installs a release for a customer product.**
  That is F-0112's unlanded consumer half (P12): `conventions.flags.upgrade` exists and nothing
  reads it. This card publishes the channels and resolves them; the reader of the flag is that
  card's, and it will have two channels to choose from when it is written.
* **Gating the tag cut on CI, or cutting fewer tags.** `asf.version.cut` is untouched (P1): a tag
  per merge is the record of what was merged, and a release workflow that waited for the suite
  would version a merge minutes-to-hours late and leave `version.health` red in between. edge
  filters; it does not ask for fewer tags.
* **Un-promoting a channel.** A head only fast-forwards (D1). Taking stable *back* to an earlier
  tag is one operator push — `git push --force-with-lease origin <older tag's commit>:refs/heads/releases/stable` —
  and is not automated here: a channel that can retreat on its own is a channel whose consumers
  can be downgraded by a bug in this module.
* **A third channel, an LTS line, per-line channels (`0.1`, `0.2`).** `NAMES` is two words.
* **The GitHub Release "latest" marker and the release notes.** `publish_github_release` and the
  CHANGELOG keep naming every version; a channel is a pointer, not a publication.
* **The doctor row and `asf status`'s Version row.** `asf channels` is the report. The Version row
  calls `cli.latest_release()` uncached on every `asf status` (F-0112 P6) and a channel read is a
  second network round trip on a view that must stay fast; a row that says "stable is 9 days old"
  belongs with the doctor's other release rows, after this lands.
* **Reading the rehearsal from anywhere but a named check run** (D8). Not from a workflow file, not
  from a run's steps, not from a file in the repo.

## The design

One new module, five edits. The module holds every rule; the edits are the wiring — a part in the
daily step, a step in `resolve_target`, a resolver in the bootstrap, four documented settings, one
registry entry.

### 1. `asf/channels.py` — the module

```python
"""asf.channels — ASF's own release channels: ``edge`` takes every green tag, ``stable`` is
promoted weekly behind a rehearsal, 48 h on edge and no S1 (F-0308).

A channel is one head on ASF's own remote — ``refs/heads/releases/<name>`` — pointing at the
**commit** of the release tag the channel offers. One ``git ls-remote`` reads it, which is what
makes a channel usable by the bootstrap, before ``asf``, ``gh`` or a token exists. The prefix is
not decoration: ``releases/`` is the one namespace retention never deletes
(:data:`asf.workers.retention.RELEASE_PREFIXES`) *and* :mod:`asf.refguard` does not protect
(``release/*`` is protected — the plural is deliberate).

Nothing here cuts a tag: :func:`asf.version.cut` does that, one patch version per merge, and a
channel only chooses among the tags that exist and delays when it chooses.

* **edge** — the newest tag whose :func:`asf.upgrade.ci_verdict` is ``green``. No ceremony, no
  wait, and never a tag whose CI is red or unread (``clear`` is not green —
  :func:`asf.upgrade.ci_state` answers it for a sha with no runs at all).
* **stable** — :func:`stable_rows`: the weekly cadence, 48 h on edge, the rehearsal check and no
  S1, each met or unmet with its evidence; promoted only when all four are met.

The publisher is a part of the tick's daily step (:func:`advance`) and runs only for a product
whose repo is the factory's own source (:func:`asf.drift.is_factory_source`). ``asf channels``
reports and writes nothing.
"""
#: the two channels, in the order a report prints them
NAMES = ('edge', 'stable')
#: the head namespace: retention-exempt and unprotected (see the module docstring)
PREFIX = 'releases/'
REF = 'refs/heads/' + PREFIX + '{name}'
#: the suffix ``git ls-remote`` puts on the line naming the commit an annotated tag points at.
#: A listing given ref patterns prints it only for a pattern that matches it, and ``--refs``
#: hides it altogether — so it is asked for by pattern and read by name, never assumed (F-0303).
PEEL = '^{}'
#: ``release.channels``: every threshold, with its default
DEFAULTS = {'stable_every_days': 7, 'edge_dwell_h': 48, 'rehearsal_check': 'rehearsal',
            'lookback_tags': 10, 'log_keep': 60}
```

**The resolver, pure.** The one function every consumer shares, over the lines of one listing:

```python
def channel_tag(lines, name):
    """``(tag, commit)`` the channel ``name`` offers, read from the lines of
    ``git ls-remote <url> 'refs/heads/releases/*' 'refs/tags/v*'``: the channel head's commit, and
    the highest version tag whose peel is that commit. ``(None, None)`` when the head is not
    published; ``(None, <commit>)`` when it is published at a commit no version tag names (a hand
    push, or a tag deleted since). Pure: no network, no clock, no config."""
    heads, at = {}, {}
    for line in lines:
        sha, _tab, ref = str(line).strip().partition('\t')
        sha, ref = sha.strip(), ref.strip()
        if not sha or not ref:
            continue
        if ref.startswith('refs/heads/' + PREFIX):
            heads[ref[len('refs/heads/' + PREFIX):]] = sha
        elif ref.startswith('refs/tags/') and ref.endswith(PEEL):
            tag = ref[len('refs/tags/'):-len(PEEL)]
            if cli.RELEASE_TAG.fullmatch(tag):
                at.setdefault(sha, []).append(tag)
    commit = heads.get(name)
    tags = sorted(at.get(commit, []), key=version_key)
    return (tags[-1] if tags else None), commit
```

`version_key(tag)` is the integer tuple of the tag's digits — the ordering `install.newest_tag`
and `cli.latest_release` already use, lifted here so the four readers share one spelling rather
than a fourth copy.

```python
def resolve(url, name, run=subprocess.run):
    """``(tag, commit)`` of the channel ``name`` on ``url`` — one ``git ls-remote`` (D3).
    ``(None, None)`` when the channel is unpublished or the listing could not be read."""
    text = _out(run, ['git', 'ls-remote', url, 'refs/heads/' + PREFIX + '*', 'refs/tags/v*'])
    return channel_tag((text or '').splitlines(), name) if text is not None else (None, None)
```

**The publisher**, one fast-forward through the guard (P19):

```python
def publish(product, name, commit, run=subprocess.run, out=print):
    """Fast-forward ``refs/heads/releases/<name>`` on origin to ``commit``. ``(ok, detail)``; a
    guard refusal, a dry run and a non-fast-forward are each a detail, never an exception."""
    from asf import gitpush, refguard
    target = f'{commit}:{REF.format(name=name)}'
    guard = refguard.Guard(main=product.main, protected=refguard.listed(product.conventions))
    p = gitpush.push(['-q', 'origin', target], product.repo_dir, guard=guard, refs_only=True,
                     log=lambda line: out(f'channels: {line}'))
    return (True, '') if p.returncode == 0 else (False, _last_line(p.stderr) or f'rc {p.returncode}')
```

A non-fast-forward is left as a refusal on purpose: a channel only moves forward (D1), and a push
that git refuses is the backstop for a candidate chosen from a stale log.

**The edge rule.** The tags are read from the factory's own checkout (`product.repo_dir`), newest
first, and asked `ci_verdict` one at a time until one is green:

```python
def edge_candidate(product, url, tags, run=subprocess.run, limit=None):
    """``(tag, commit, detail)``: the newest of ``tags`` (newest first, at most ``limit``) whose
    every landing check succeeded. ``(None, None, <why>)`` when none did — the verdicts examined,
    so the report says what it is waiting for."""
    from asf import upgrade
    seen = []
    for tag, commit in list(tags)[:limit or DEFAULTS['lookback_tags']]:
        verdict, detail = upgrade.ci_verdict(url, commit, run=run)
        if verdict == 'green':
            return tag, commit, f'{tag} {commit[:7]} green ({detail})'
        seen.append(f'{tag} {verdict}' + (f' ({detail})' if detail else ''))
    return None, None, '; '.join(seen) or 'no release tag to examine'
```

**The stable gate**, four rows, `asf.release.Criterion` reused:

```python
def stable_rows(product, root, log, candidate, now, cfg=None, run=subprocess.run):
    """``[Criterion]`` for promoting ``candidate`` (a ``(tag, commit)`` off the edge log) to
    stable: the cadence, the dwell, the rehearsal and the S1 window — in that order, each with
    the evidence an operator reads instead of asking. ``candidate`` ``None`` makes every row
    unmet with one evidence line saying why there is no candidate."""
```

* `cadence` — `now - log['stable']['at'] >= stable_every_days` days. Evidence: `last promoted
  v0.1.244 9 d ago (every 7 d)`, or `v0.1.244 promoted 2 d ago — due in 5 d`. No stable yet: met,
  evidence `no stable release yet`.
* `dwell` — the candidate is the newest tag in the edge log whose publication is at least
  `edge_dwell_h` hours old. Evidence: `v0.1.258 on edge 61 h (48 h)`.
* `rehearsal` — `release.channels.rehearsal_check` on the candidate's commit through
  `upgrade.ci_verdict(url, commit, checks=[name])`: green is met, anything else is not (D8).
  Evidence: `rehearsal success`, or `rehearsal has no run`, or `n/a (release.channels.rehearsal_check off)`.
* `no_s1` — `s1_in_window(root, since)` and `release_preview.open_defects(root, ('S1',))` (D9).
  Evidence: `no S1 since 2026-10-06T09:12:00Z`, or `B-80046 raised 2026-10-07 (S1)`, or
  `B-0007 open (S1)`.

```python
def s1_in_window(root, since, now=None):
    """``[(id, title, when)]`` — every Bug of severity S1 in the record whose ``stage_since`` or
    ``updated`` falls at or after ``since``: an S1 raised, reopened or moved while the candidate
    sat on edge, open or closed again since (D9). The typed fields are read, never ``## History``:
    its dates are days, and the window is hours."""
```
