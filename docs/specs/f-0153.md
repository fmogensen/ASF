# F-0153 — the naming repair retries a refused push every tick

A product's tick log carried **144 lines** of `reword <branch> (naming) push refused` in a day:
three heads under a `cloud/` prefix, 48 lines each, **two per tick** over 24 ticks. The card's own
summary of what went wrong is one sentence: *"Back to its session" never takes effect.*

The repair had nowhere to put the refusal, so it had nothing to remember. It re-read the branch,
re-reworded it, re-pushed it and re-logged it, on an unchanging tip, every tick, for a day.

## Why the count is *two* per tick, and not one

This is the part worth being precise about, because the number names the defect.

The tick runs the naming repair **once** — `step_wave.lane_pass` sets `ctx.lane_passed` and returns
early on a second call (`asf/tick/step_wave.py:132-134`), and the tick's detached harvest passes
`lane_pass=False` (`asf/harvest/harvest.py:961-963`, `:975`). `gate_pass` never reaches
`repair_naming` at all: it gathers branches in `GATE_STATES` and gates them, and runs no transition
loop (`asf/harvest/lane.py:2314-2341`). One pass a tick.

So two lines a tick means **two pushes inside one pass** — and there are, from the
`for attempt in (1, 2)` loop at `asf/harvest/lane.py:2027`. `push_cause` classes a refusal `'lease'`
whenever the text holds `stale info`, `fetch first` or **`non-fast-forward`**
(`asf/harvest/lane.py:621-622`), and a `'lease'` on attempt 1 is read as *a writer pushed under us*:
the pass says so, re-reads, and pushes again (`:2044-2047`).

The word `non-fast-forward` is not evidence that anybody pushed anything. A ref protected against
rewrites refuses a rewrite in exactly those words. Measured in this checkout (§Decisions P5), one
pass against a remote that refuses with that wording issues **two byte-identical pushes — the same
refspec over the same lease sha** — and prints:

```
reword worker/T-0001: the branch moved since d1cd311da was read (…) — read again and retried
reword worker/T-0001: deferred — the branch moved under both reads (…); a writer is pushing it,
  the next pass reads it again
```

Both sentences are false. The branch did not move; no writer is pushing it. Attempt 2 re-fetched
origin and re-read the tip — it **had the disproof in hand**, as the identical lease sha in its own
second push shows — and threw it away in favour of a diagnosis inferred from a substring. That is
the 2, and it is the first thing this card fixes.

## Why it never ends, and why nobody is ever told

Every deferral on this path is a bare `self.out(...)` followed by `return DEFERRED`
(`asf/harvest/lane.py:2048-2053`). No `set`, no `write`, no record. `DEFERRED`'s own definition says
it plainly — *"no session is started and no hold is written"* (`:583-586`) — and `repair_naming`
memoises only within a single pass, on the facts dict (`f['naming_repair']`, `:1983-1985`), which the
next tick rebuilds from scratch.

So the next tick has no idea this was tried. And because the push is what would have moved the tip,
the tip never changes, so the next tick reaches the identical decision from the identical inputs.
The loop is closed and it is silent: measured over two passes, the lane record holds
`{state, head, pr, reason, item, at, head_at}` and no trace of the refusal, and
`lifecycle.corrections` is `{}` (P4). Nothing in the record, nothing in status, nothing in the
doctor — only the log line, twice a tick, forever.

"Back to its session" never takes effect because on this path **nothing ever calls it**.
`_naming_back` — the one route to a session — is reachable only from a rewrite that cannot be
*computed* (no commit to reword, trees differ: `:2029`, `:2032`). A rewrite that computes perfectly
and cannot be *pushed* returns `DEFERRED` and waits for a tip that only a push could move.

## What this card does

Four changes, in the order they pay:

1. **Diagnose the lease from the sha, not from the wording.** Retry the push only when origin's tip
   actually moved. Two pushes become one, and two false lines become none.
2. **Remember the refusal against the tip it was refused over.** While the memo names origin's
   current tip, the repair does nothing at all: no reword, no push, no line.
3. **Route what the lane can never push.** A refusal that survives `--no-verify` is the remote's, not
   a race — it goes to a `correct` session (no round: `NAMING` is `MECHANICAL`), or, for a legacy
   head no card claims, to the reaper.
4. **Keep a standing refusal visible.** One advisory row in status and the doctor, so "logged once"
   does not become "invisible".

## Decisions

### In scope

- `Lane._repair_naming` (`asf/harvest/lane.py:1988-2069`): the lease retry condition, the memo, and
  the routing of a refusal the lane cannot push.
- A `reword_refused` memo on the branch's lane record, and the merge that writes it without a state
  transition.
- One advisory status/doctor row for a standing refusal.
- `push_cause` (`asf/harvest/lane.py:613-625`): one new class for a refusal the lane cannot retry.

### Out of scope

- **The wording of the log lines that are working.** At this sha the refusal line already carries
  git's own reason — measured, P4: `(remote: remote: pre-receive: refs/heads/worker is protected /
  ! [remote rejected] … (pre-receive hook declined))`. The card asks that the reason be logged "once";
  it is already logged *correctly*. Only the repetition is the defect.
- **The `--no-verify` decision and the tree-identity check.** A message-only rewrite going out over a
  lease with the product's pre-push hook skipped is the sibling fix already in place and tested
  (`tests/test_lane.py:1668`, `NamingRewordNeverCostsASession`). This card does not revisit it.
- **`drop_copies` and `repair_signoff`**, which have their own refused-push lines
  (`asf/harvest/lane.py:2150`, `:2207`). They are the same shape of bug and are **not** fixed here
  (§Left out).
- **Retention's own sweep** (`asf/workers/retention.py`). This card routes a branch *to* the existing
  reaper path; it changes no retention rule.
- The three live heads under the `cloud/` prefix. Nothing in this repo can clear them; the fix is the
  code, and the operator's own log is where it is confirmed.

## The design

### 1. `push_cause` gains a class it can only reach with a sha (`asf/harvest/lane.py:613-625`)

`push_cause(r)` keeps its `(cause, text)` shape and its four classes. The caller — which is the only
party holding the two shas — upgrades `'lease'` to `'stuck'`:

```python
#: a lease-worded refusal (git says non-fast-forward) over a tip that did not move: not a race —
#: the remote refuses the rewrite itself, and no number of passes will change its mind
STUCK = 'stuck'
```

### 2. The retry condition becomes a sha comparison (`asf/harvest/lane.py:2027-2053`)

The loop carries the tip the refused push leased. Today `old` is rebound each iteration and the
comparison is never made (P3):

```python
leased = None                       # the tip attempt 1's push leased, carried into attempt 2
for attempt in (1, 2):
    # (the fetch of refs/heads/<b> and the empty-`old` deferral are unchanged)
    old = H.sh(['git', 'rev-parse', '--verify', '-q', f'origin/{b}'], cwd=self.repo).stdout.strip()
    if leased and old == leased:
        # attempt 1 said non-fast-forward; the branch is provably where it was. Not a race:
        # the remote refuses the rewrite. No second push.
        cause, text = STUCK, leased_text
        break
    ...
    r = gitpush.push([... f'--force-with-lease=refs/heads/{b}:{old}' ...])
    if r.returncode == 0:
        break
    cause, text = push_cause(r)
    if cause == 'lease' and attempt == 1:
        leased, leased_text = old, text
        self.out(f'reword {b}: the branch moved since {old[:9]} was read ({text}) — read again '
                 f'and retried')
        continue
    break
```

The attempt-1 "the branch moved" line stays — when the branch *has* moved it is true, and
`test_a_lease_race_is_re_read_and_retried_once` asserts it. What changes is that it is no longer
followed by a push over a sha the pass has just proved unchanged.

### 3. The memo, read first and written last

**Read.** Before any work — before the branch fetch, the reword and the push — `_repair_naming`
compares the memo to the branch's tip and returns `DEFERRED` in silence when they agree:

```python
memo = (f.get('prev') or {}).get('reword_refused') or {}
if memo.get('head') and memo['head'] == f.get('head'):
    return DEFERRED          # refused over this tip already: no reword, no push, no line
```

Keyed on `f['head']` — the tip `gather` read for this pass — so the suppressed path costs no git call
at all. When the tip has moved, `f['head']` differs, the memo is stale, and the repair runs exactly
as it does today.

**Write.** A refusal writes the memo onto the existing lane record **without a state transition** —
the branch's state is not what changed:

```python
def memo_refusal(self, f, **fields):
    """Merge fields onto the branch's lane record, leaving its state and head alone."""
    rec = dict(f.get('prev') or {}, **fields)
    self.write(f, rec)
    f['prev'] = rec
    return rec
```

The memo is `{'head': <the tip refused over>, 'cause': <class>, 'why': <push_why text>, 'at':
<iso>}`. Cleared — set to `None`, and so dropped by `record`'s non-`None` filter (P9) — on a reword
that pushes.

### 4. The routing (`asf/harvest/lane.py:2048-2053`)

| cause | what it means | what happens |
| --- | --- | --- |
| `lease` | the tip genuinely moved under both reads | memo; `DEFERRED`; the next pass reads the new tip — unchanged from today |
| `timeout` | the remote never answered | memo; `DEFERRED`; one advisory row (C5) |
| `remote` | the remote declined it | memo; **route** |
| `stuck` | non-fast-forward over an unmoved tip | memo; **route** |

Routing, in order:

1. A legacy head no card claims — `self.unclaimed_legacy(b, item)` returns a prefix — goes to
   `self.drop_legacy(f, why, prefix)` (P8). This is the card's "retention reaper", and the three
   `cloud/…` heads are its shape: a retired worker system's prefix, no card, no session.
2. Otherwise `_naming_back(f, why)` — the naming correction that spends no round, routed to a
   `CORRECT` session (P7), with the remote's own words in its text (C7):

   ```
   reword <b>: the remote refuses a rewrite of this ref (stuck: <why>) — back to its session
   (naming, no round)
   ```
3. If neither applies — no card, no legacy prefix — the memo stands and the row from §5 carries it.

### 5. The standing-refusal row

One line, in the shape of `ref_push_line` (P10), from the memos on the lane records:

```
reword refused: worker/T-0001 at 55e30ee79 (stuck: the ref is protected) — waiting for the tip to move
```

Advisory, not red: the lane is behaving correctly, and the thing to fix is on the remote.

## Acceptance tests

All four blocks go in `tests/test_lane.py`, in one new class beside
`NamingRewordNeverCostsASession`. Run:

```bash
python3 -m unittest tests.test_lane.ARefusedRewordIsRememberedByItsTip -v
python3 -m unittest tests.test_lane.NamingRepair tests.test_lane.NamingRewordNeverCostsASession -v
```

The fixture mechanics below are **verified working in this checkout** (§Decisions P4, P5): the
server-side `pre-receive` hook installed in the bare origin *after* the setup pushes (a `pre-push`
hook cannot be used — `refs_only=True` passes `--no-verify`, P12), counting pushes by wrapping
`gitpush.push`, `self.lane_of(branch)` for the record and `lifecycle.corrections` for the hold.

```python
class ARefusedRewordIsRememberedByItsTip(LaneFixture):
    """F-0153: 144 log lines in a day — three heads, 48 each, two a tick. The repair kept no
    memory of a refusal, so every tick re-read, re-reworded, re-pushed and re-logged an
    unchanging tip; and a 'lease' diagnosed from the word non-fast-forward pushed a second time
    over a sha the pass had just proved unmoved."""

    B, AUTHOR = NamingRepair.B, NamingRepair.AUTHOR
    tip, push_commits, log, sessions = (NamingRepair.tip, NamingRepair.push_commits,
                                        NamingRepair.log, NamingRepair.sessions)

    def setUp(self):
        super().setUp()
        self.lines = []

    def refusing_remote(self, text):
        """A server-side hook in the bare origin. --no-verify cannot skip it, so this is the one
        way to stand in for a protected ref; it must go in after the setup pushes."""
        hook = os.path.join(self.origin, 'hooks', 'pre-receive')
        with open(hook, 'w', encoding='utf-8') as fh:
            fh.write('#!/bin/sh\necho "' + text + '" >&2\nexit 1\n')
        os.chmod(hook, 0o755)

    def counted_pass(self):
        """One lane pass; the pushes it made."""
        pushes, real = [], gitpush.push

        def counting(args, cwd, **kw):
            r = real(args, cwd, **kw)
            pushes.append(list(args))
            return r
        with mock.patch.object(gitpush, 'push', side_effect=counting):
            lane.lane_pass(self.product(), self.state_dir, out=self.lines.append)
        return pushes
```

### A0 — the reproduction: two pushes over one sha, and the sibling class still green

The one block that **passes today**, pinning P5 so the fix is measured against a number rather than

```python
    def test_a0_today_one_pass_pushes_twice_over_the_same_lease_sha(self):
```

### A2 — the card's named test: a second pass on the same tip does no push and logs nothing new (S-37651)

```python
    def test_a2_a_second_pass_on_the_same_tip_does_no_push_and_logs_nothing_new(self):

        self.write(self.worker, 'z.txt', 'z\n')
        sh(['git', 'add', '-A'], cwd=self.worker)
        sh(['git', 'commit', '-qm', 'tidy again'], cwd=self.worker, env_=self.ident)
        sh(['git', 'push', '-q', 'origin', self.B], cwd=self.worker)
        self.lines.clear()
        self.assertTrue(self.counted_pass())                      # the moved tip is tried
        self.assertTrue(any('trees identical — pushed' in l for l in self.lines), self.lines)
        self.assertIsNone(self.lane_of(self.B).get('reword_refused'))   # cleared by the push
```

## Records

**On the branch's lane record** (`sessions.jsonl`, the run that owns the branch; a synthetic adopted
run when none does — P9). One new field, and no change to any existing one:

| field | value | lifetime |
| --- | --- | --- |
| `reword_refused.head` | the tip sha the refused push leased | until the tip moves, or a reword pushes |
| `reword_refused.cause` | `remote`, `stuck`, `lease` or `timeout` | as above |
| `reword_refused.why` | `push_why(...)` of the remote's words | as above |
| `reword_refused.at` | `now_iso()` of the first refusal over this tip | as above |

`state`, `head` and `head_at` are **not** touched by a refusal: the branch is where it was, and a
memo is not a transition.

**Corrections.** A routed `remote`/`stuck` refusal writes the existing naming correction
(`{'kind': 'naming', 'text': …, 'at': …}`) through `_naming_back` → `hold_with_correction`, routed to
a `CORRECT` session, **no round** (P7). A routed legacy head writes `drop_legacy`'s existing
`STALE` record with `harvested=SUPERSEDED` and `correction=None`.

**Lines.** Per pass, per branch: exactly one, and only when the memo is written or refreshed.

| line | when |
| --- | --- |
| `reword <b>: the remote refuses a rewrite of this ref (<cause>: <why>) — back to its session (naming, no round)` | routed to a session |
| `superseded <b>: … — deleted, not archived (legacy prefix <p>, no card claims it)` | routed to the reaper (existing) |
| `reword <b>: deferred — the push was refused (<cause>: <why>); noted at <sha9>, no retry until the tip moves` | memo, no destination |
| *(nothing)* | a memo already names this tip |

**Status and doctor.** One advisory row while any memo stands (§5), in `ref_push_line`'s shape.

**Not written:** no new convention key (C4), no new state file (C3), no metric.
