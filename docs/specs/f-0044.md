# F-0044 — the scorecard says what shipped before it says what it cost

`metrics/daily/<day>.md` opens with `## Waste`: red rate, cancelled runner-minutes, red jobs,
batches, launches per merged PR, spec rounds, bandwidth, intake latency. Then `## Cost per
Feature (7 days)`, a table of every Feature that spent anything in the window. Every one of those
numbers describes the machine. None of them says whether the machine shipped anything.

Two numbers do: how many Features reached production in the last seven days, and what one of them
cost on average. This spec puts those two at the top of the file, with last week's beside them,
one row per product and a Total across products — and makes the *reached production* moment a
durable event, so last week's number does not move when an item's stage moves today.

The ladder that decides it already exists. `evidence.feature_stage` returns `on-prod` for a
Feature whose Tasks are all Closed and whose merged shas are all ancestors of a `prod_sha`;
`ingest` writes that stage plus `stage_since` into the item's machine block and appends one
`## History` line. What is missing is a record a report can count, and the report itself.

## 1. Decisions

### 1.1 Preconditions

- The stage token is **`on-prod`**, not `on-production`. `evidence.feature_stage` returns
  `card` / `spec-draft` / `spec-review r<n>` / `spec-approved` / `plan-draft` /
  `plan-review r<n>` / `plan-approved` / `building <k>/<n>` / `landed` / `on-prod`. The card's
  prose says "on-production"; the record says `on-prod`, and this spec reads the record.
- `on-prod` already requires a deployment: `ingest` computes
  `on_prod_for_stage = all_merged_in_prod and bool(ev.get('prod_sha'))`, so a product that
  deploys nothing tops out at `landed` and correctly ships nothing here (B-0077).
- `ingest._ingest_fields` already holds both halves of a transition — `machine['stage']` (the
  committed value) and the newly derived `stage`, with `tracked_changed` deciding whether
  `stage_since` is restamped. The transition is detected there today; nothing is written about it
  anywhere a report can read.
- `metrics/events/<day>.jsonl` is an unvalidated stream: `STREAMS` is `('ci', 'sessions',
  'ticks')` and `SCHEMAS` has no `events` entry, so `asf metrics append` neither accepts nor
  rejects an `events` line, and a new `kind` needs no schema change.
- `metrics.intake_latency_rows` already reads that stream and dispatches on `kind` through an
  `if/elif` chain over `intake` / `groom_answer` / `launch`, counting `intake_n` from `intake`
  lines only. A line of any other `kind` is ignored by it. A new kind cannot move an intake
  latency number.
- `render_daily` is already handed the loaded `items` map, and `write_costs` already computes
  all-time `compute_costs` + `subtree_cost` in the same command. Both halves of the first line
  are computable from what `cmd_rollup` already reads.
- `index.json` carries every machine key per item (`core.build_index_data` merges typed and
  machine blocks), so `stage` and `stage_since` are readable from a record without parsing item
  files.
- `~/.ASF/products/<name>.yaml` is the product list (`schema._all_products()`), and each names its
  own `backlog_dir`. One record per product; there is no factory-wide record.
- The suite pins `ASF_HOME` to a temp directory (`tests/__init__.py`, B-0043). Anything that
  enumerates products must be reachable in a test through that pinned home, and must not be
  reached at all by a caller that does not ask for it.

### 1.2 In

- **`asf.record.ingest`** — `ON_PROD_EVENT = 'feature-on-prod'` and a writer that appends one
  line to `metrics/events/<day>.jsonl` in the record when a Feature's stage enters `on-prod`,
  idempotent within the day.
- **`asf.metrics.metrics`** — five pure-or-nearly functions and one constant:
  `ON_PROD_STAGE`, `shipped(events, items, days)`, `throughput(items, costs, ids)`,
  `record_throughput(root, items, day)`, `throughput_records(root, product_name)`,
  `throughput_block(day, rows, skipped)`.
- **`asf.metrics.metrics.render_daily`** — a new first section, `## Features on production`,
  before `## Waste`; one new keyword argument for the product list.
- **`asf.metrics.metrics.cmd_rollup`** — resolves the product list once and passes it in.
- Tests: §3.1–§3.6, and the updated `EXPECTED_DAILY` fixture in `tests/test_metrics.py`.

### 1.3 Out

- **A new stream, a new item field, a new schema.** The event goes into `metrics/events`, which
  exists and is unvalidated; `stage` and `stage_since` keep their present meaning and nobody
  writes a `shipped_on:` field.
- **Changing `evidence.feature_stage`, `feature_state` or `on_prod_for_stage`.** What counts as
  on production is already decided and is not reopened here.
- **Changing the `## Waste` table or the `## Cost per Feature` table.** Both keep their present
  rows, order and wording; the card calls them diagnostic and leaves them alone. F-0101 is
  editing the waste table and must not collide with this change.
- **Backfilling the event stream for days already past.** §2.3's fallback covers the first two
  weeks from `stage_since` without writing anything; no command rewrites history.
- **Counting Stories, Tasks or Bugs.** The card says *Feature cards*. A Task that reached prod is
  part of its Feature's cost and is never its own row here.
- **A per-Feature list of what shipped.** `releases/<day>-<sha7>.md` already names the items of a
  release. The first line is two numbers and their delta.
- **A cost model.** `compute_costs` / `subtree_cost` are reused verbatim: a session's `usd` and a
  CI run's minutes split over the items it names.
- **A target, a threshold or a filed Bug.** The line reports; it does not judge. No Bug is filed
  for a bad week.
- **Reading another product's session registry, job logs or repo.** Only its record —
  `index.json` and `metrics/` under its `backlog_dir`.

### 1.4 The choices

| Choice | Against | Why |
| --- | --- | --- |
| A durable `feature-on-prod` event, written by `ingest` | `stage == 'on-prod'` + `stage_since` as the only source | last week's column is computed today. With `stage_since` alone, a Feature that shipped ten days ago and whose stage moved since (a reopened Task, a prod sha that stopped being an ancestor) silently leaves last week's count, and the week-over-week delta lies about a week that is already over. An event is written once and stays written. |
| `stage_since` is a *fallback* for a Feature at `on-prod` with no event | events only, or a backfill command | the day this ships, the event stream holds nothing, and a first line reading `0 features` would be read as a bad week rather than a new metric. The fallback is a union keyed on the item: an event wins, `stage_since` fills. It needs no command and ages out on its own. |
| `ingest` writes the event, at the one place the transition is already detected | the tick's `Context.event`, or `harvest` | `Context.event` writes into `metrics/events` too, but it is the tick's, and `ingest` runs as step 0 *inside* the tick with no context; `harvest` never sees a Feature's stage. `ingest` already has the old stage, the new stage and `now` in one loop. |
| The event carries no `product` | `product` as a key, like the tick's events | the record the line is in *is* the product. A reader that labels by record cannot mislabel; a key that has to be threaded from `cmd_ingest`'s optional `--product` can be absent, and then the row would be labelled twice. |
| Cost per feature is each Feature's **whole-life** subtree cost | the 7-day slice `cost_table` uses | a Feature that shipped on Monday spent most of its money in the weeks before. A 7-day slice of the cost of shipping it is not the cost of shipping it. The diagnostic table below keeps its 7-day window, and the note says the two differ. |
| The mean skips Features whose cost is unknown (`usd is None`), and the table says how many were priced | counting them as `$0`, or `—` for the whole mean | a session with no `usd` (an imported run, a crashed log) is missing data, not free work. Dropping it biases the mean low only if it is silent — so the `Priced` column makes it loud. |
| The Total's cost per feature is a weighted mean — all priced features' cost over their count | the mean of the per-product means | a product that shipped one expensive Feature would otherwise weigh as much as one that shipped nine cheap ones. Total is the factory's real rate. |
| Windows are `day-6 … day` and `day-13 … day-7`, by the UTC day the item reached prod | rolling 168 h from now | `days_back(day, 7)` is already the rollup's week, `metrics/<stream>/<day>.jsonl` is already day-filed, and the two windows are disjoint so no Feature is in both. |
| A headline sentence **and** a table | the table alone, or the sentence alone | the card says *the first line*, and also *per product and as a total*. The sentence is the first line and carries both numbers and both deltas; the table carries the per-product breakdown. One is not a substitute for the other. |
| The section goes above `## Waste` | a row inside the waste table | the card's last sentence is "everything else on the card is diagnostic". A row among the diagnostics is not the first line, and the waste table's `Metric | Value | Note` shape cannot hold seven numbers. |
| Other products are read from `backlog_dir`, this one from `root` | every product from its `backlog_dir` | `cmd_rollup` runs in the record clone and is writing this file into it; reading this product from anywhere else would print numbers that disagree with the record the file lives in. |
| A product whose record cannot be read is named in the note and left out of the Total | counting it as zero, or failing the rollup | zero is a number an operator will act on. A named omission is not. And a rollup must not fail because another product's checkout is missing. |
| The product list is a keyword argument, default "just this record" | `render_daily` enumerating `~/.ASF/products` itself | every existing caller and test calls `render_daily(root, day, items)`; with no list it must read nothing outside `root` (B-0043). Only `cmd_rollup` opts in. |

## 2. The design

### 2.1 The event — `asf/record/ingest.py`

Beside `MACHINE_KEY_ORDER`:

```python
#: The `metrics/events` kind written when a Feature's stage enters `on-prod` — the durable
#: record of "this Feature reached production", read by the rollup's first line (F-0044).
ON_PROD_EVENT = 'feature-on-prod'


def write_on_prod_event(root, iid, from_stage, now):
    """Append one ``feature-on-prod`` line to ``<root>/metrics/events/<day>.jsonl``.

    A no-op when that day's file already carries this kind for this item, so re-deriving a
    record (the clone is reset and re-derived every cycle) writes it once. Returns True when a
    line was written.
    """
```

The line is `{"from": <from_stage or "">, "item": <iid>, "kind": "feature-on-prod", "ts": <now>}`
— `json.dumps(..., sort_keys=True, ensure_ascii=False)`, one line, the directory created if
absent, exactly as `tick.Context.event` writes its own.

In the write loop, where `_ingest_fields` has just returned and `frontmatter.write_machine` has
run, with `old = machine.get('stage')` captured before it:

```python
if type_ == 'feature' and stage_val.get(iid) == 'on-prod' and old != 'on-prod':
    write_on_prod_event(root, iid, old, now)
```

`old != 'on-prod'` is the transition: a Feature that was already `on-prod` writes nothing (and
`_ingest_fields` returns `None` for it anyway, since nothing changed). A Feature that falls back
to `building 3/4` and later returns to `on-prod` writes a second event — it reached production
twice, and both weeks should say so.

### 2.2 What shipped — `asf/metrics/metrics.py`

```python
ON_PROD_STAGE = 'on-prod'


def shipped(events, items, days):
    """{feature id: the day it reached `on-prod`} over `days`, newest wins.

    An ``ingest.ON_PROD_EVENT`` line is the record; a Feature now at `on-prod` whose id no event
    names at all falls back to its `stage_since` day (the stream is younger than the record).
    Only ids that are Features in `items` count; `days` is a list of ``YYYY-MM-DD``.
    """
```

Two passes and no clock:

1. `seen = {ev['item']: ev['ts'][:10] for ev in events if ev.get('kind') == ON_PROD_EVENT}` over
   **every** day of the stream, not just the window — an item named by an older event must not
   fall back. Keep the newest `ts` per item.
2. For each Feature in `items` with `stage == ON_PROD_STAGE` and `stage_since` set, if it is not
   in `seen`, `seen[fid] = stage_since[:10]`.
3. Return `{fid: d for fid, d in seen.items() if d in set(days) and items.get(fid, {}).get('type') == 'feature'}`.

The caller reads the whole stream once (`read_stream(root, 'events')`) and calls `shipped` twice,
once per window.

```python
def throughput(items, costs, ids):
    """{'features': n, 'priced': k, 'usd': total of the priced, 'mean': mean or None} —
    each id's whole-life `subtree_cost` in USD; an id whose cost is unknown counts in
    `features`, never in `priced`, `usd` or `mean`."""
```

```python
def record_throughput(root, items, day):
    """(this week, last week) for one record: two `throughput` dicts and the two windows.

    Returns ``(week, prev, this_wk, prev_wk)`` where the windows are ``days_back(day, 7)`` and
    ``days_back(day, 14)[:7]``. Reads `metrics/events` (all of it), `metrics/ci` and
    `metrics/sessions` (all of them — the cost is whole-life) under `root`.
    """
```

### 2.3 Which records — `asf/metrics/metrics.py`

```python
def throughput_records(root, product_name=None):
    """``([(label, record root)], [skipped names])`` — this record first, then every other
    product under ``~/.ASF/products`` whose ``backlog_dir`` holds an ``index.json``.

    This record is always read from `root`, labelled with `product_name` (or ``this record``
    when there is none). A product whose config will not load, whose `backlog_dir` is missing or
    which has no `index.json` is returned as a skipped name and read by nobody. With
    `product_name` None the list is this record alone and ``~/.ASF`` is never touched.
    """
```

Products are ordered by name; `label` is the product name. A second product whose `backlog_dir`
resolves to the same path as `root` is dropped as a duplicate (the rollup run over a checkout
rather than a clone).

### 2.4 The section — `asf/metrics/metrics.py`

```python
def _delta_int(now_, then):
    return f"{now_ - then:+d}"


def _money(v):
    return '—' if v is None else f"${v:,.2f}"


def _delta_money(now_, then):
    return '—' if now_ is None or then is None else f"{'+' if now_ >= then else '-'}${abs(now_ - then):,.2f}"


def throughput_block(day, rows, skipped):
    """The scorecard's first section. `rows` is [(label, week, prev)] with the Total's row
    computed here from the priced totals, not from the per-product means."""
```

For the fixture of §3.5 — two products, `sample` shipping 3 Features (all priced, $37.20
together) this week and 1 ($31.00) last week, `demo` shipping none this week and 2 (one priced at
$8.10, one not) last week, and `extra` unreadable:

```markdown
# Factory scorecard 2026-09-21

generated: 2026-09-21 — from metrics/ci (3), metrics/sessions (4), metrics/ticks (2)

## Features on production

**3 features on production this week, $12.40 per feature** — last week 3, $19.55 · Δ features +0 · Δ cost -$7.15. Every section below is diagnostic.

2026-09-15 … 2026-09-21 against 2026-09-08 … 2026-09-14, by the day each Feature's stage reached `on-prod`; cost per feature is that Feature's whole-life subtree cost, so it does not match the 7-day table below. Not read: extra (no index.json).

| Product | On prod | prev | Δ | $/feature | prev | Δ | Priced |
|---|--:|--:|--:|--:|--:|--:|--:|
| sample | 3 | 1 | +2 | $12.40 | $31.00 | -$18.60 | 3/3 |
| demo | 0 | 2 | -2 | — | $8.10 | — | 0/0 |
| **Total** | 3 | 3 | +0 | $12.40 | $19.55 | -$7.15 | 3/3 |

## Waste
```

The headline sentence restates the Total row: the count, the mean, last week's pair, and both
deltas. `Δ features` is `+0` for no change, never `0`. A mean with no priced feature on either
side renders `—`, and so does its delta — never `$0.00`, which would read as free work. `Not
read: …` is omitted when nothing was skipped.

`render_daily` gains the list and puts the block first:

```python
def render_daily(root, day, items, conv=None, records=None, skipped=()):
    ...
    out = [f"# Factory scorecard {day}", '',
           f"generated: {day} — from metrics/ci ({len(ci)}), …", '']
    out += throughput_block(day, [(label, *record_throughput(r, load(r), day)[:2])
                                  for label, r in (records or [('this record', root)])], skipped)
    out += ['## Waste', '', '| Metric | Value | Note |', '|---|---|---|']
```

where each other record's `items` come from `match.load_index(that root)` and this record's from
the `items` already passed in. With `records=None` the block has one row labelled `this record`
and the Total row is that row — printed all the same, so the section is never absent.

`cmd_rollup` resolves the list once, after `conv`:

```python
records, skipped = throughput_records(root, getattr(args, 'product', None) or None)
text = render_daily(root, day, items, conv, records, skipped)
```

and prints one line of its own so the operator sees the headline without opening the file:

```
features: 3 on prod this week, $12.40 each (last week 3, $19.55)
```

## 3. Acceptance tests

From the repository root, stdlib only, hermetic — no network, no live `~/.ASF` (the suite pins
`ASF_HOME`). The whole suite must stay green:

```bash
cd "$(git rev-parse --show-toplevel)"
python3 tools/run_tests.py
```

### 3.1 `ingest` writes the transition down once

A fixture record whose `F-0001` has every Task Closed and a `prod_sha` covering their merged
shas: one `asf ingest` writes `metrics/events/<today>.jsonl` with exactly one line,
`{"from": "landed", "item": "F-0001", "kind": "feature-on-prod", "ts": …}`, keys sorted, `ts`
matching `TS_RE`. A second `ingest` the same day adds no line. A Feature that reaches only
`landed` (no `prod_sha`) writes none. A Feature already recorded at `stage: on-prod` in its
machine block writes none. A Task and a Bug reaching prod write none. The Feature's
`## History` line and its `stage_since` are exactly what they are today — the event is additive.
`metrics.intake_latency_rows` over a stream carrying these lines plus `intake` / `groom_answer` /
`launch` lines returns the same two rows as without them.

```bash
python3 -m unittest -v tests.test_ingest.FeatureOnProdEventTests
```

### 3.2 `shipped` — the event is the record, `stage_since` is the fallback

Over `items` holding `F-0001`…`F-0004` and a `T-0001`:

- an event for `F-0001` at `2026-09-17T08:00:00Z` → in the `2026-09-15 … 2026-09-21` window, and
  not in `2026-09-08 … 2026-09-14`;
- an event for `F-0002` at `2026-09-10T…` → in the previous window only;
- `F-0003` at `stage: on-prod`, `stage_since: 2026-09-16T…`, no event → in this window (the
  fallback);
- `F-0004` at `stage: on-prod`, `stage_since: 2026-09-16T…`, **with** an event dated
  `2026-09-09T…` → in the previous window only, never both (the event wins even when it is
  older, and even when it is outside the window asked for);
- two events for `F-0001`, the newer on `2026-09-19` → that day;
- `T-0001` with a `feature-on-prod` event → excluded, it is not a Feature;
- an id no `items` entry names → excluded;
- `stage: landed` with a `stage_since` inside the window and no event → excluded;
- `stage: on-prod` with no `stage_since` → excluded.

```bash
python3 -m unittest -v tests.test_metrics.ShippedTests
```

### 3.3 `throughput` — the mean names what it could not price

`throughput` over three ids costing $10.00, $12.00 and $15.20 gives
`{'features': 3, 'priced': 3, 'usd': 37.20, 'mean': 12.40}`. Add a fourth whose subtree has no
`usd` at all: `features` 4, `priced` 3, `usd` 37.20, `mean` 12.40 — the unpriced one is not $0.
All four unpriced: `mean` None, `usd` None, `priced` 0. No ids at all: zeros and `mean` None, and
nothing divides by zero. A Feature's cost sums its Stories, Tasks and Bugs (it is
`subtree_cost`), and a Feature counted here is priced from the whole stream, not the window's
slice: the same fixture read with 7 days of streams and with 30 days gives the same
`features` and a larger `usd`.

```bash
python3 -m unittest -v tests.test_metrics.ThroughputTests
```

### 3.4 The records read, and the ones that could not be

On a temp `ASF_HOME` with `products/sample.yaml`, `products/demo.yaml` and
`products/extra.yaml`: `throughput_records(root, 'sample')` returns `sample` → `root` (never
sample's own `backlog_dir`), `demo` → demo's `backlog_dir`, and `['extra (no index.json)']`
skipped when extra's backlog has none; a product whose yaml will not parse is skipped with its
reason and raises nothing; a product whose `backlog_dir` does not exist is skipped; a product
whose `backlog_dir` *is* `root` appears once, not twice. `throughput_records(root, None)` returns
`[('this record', root)]` and `[]`, and does so with `env.ASF_HOME` pointed at a path that does
not exist — nothing outside `root` is opened.

```bash

```

### 3.5 The first line, per product and in total

### 3.6 A quiet week, one product, and no product config

`render_daily(root, day, items)` with no `records` argument still prints the section: one row
labelled `this record`, a `Total` row equal to it, `0 features on production this week, — per
feature — last week 0, — · Δ features +0 · Δ cost —`, and no `Not read:` line. The same over an
empty record (no `index.json`, no streams) prints the same and raises nothing. `asf metrics
rollup <day>` over that record exits 0 and prints its `features: …` line. A record whose only
Feature shipped in *both* windows' worth of history is counted in exactly one. `render_daily`
with `records` given but `ASF_HOME` unreadable raises nothing, because the enumeration already
happened in `cmd_rollup`.


## 4. Records

**`metrics/events/<day>.jsonl`** (in the record `ingest` ran over) gains one kind. One line per
Feature per transition into `on-prod`:

```json
{"from": "landed", "item": "F-0044", "kind": "feature-on-prod", "ts": "2026-09-24T06:51:07Z"}
```

Keys sorted, UTC ISO `ts`, no `product` key (§1.4). The stream is unvalidated, so no schema
changes and every line written before this change stays valid. `intake_latency_rows` ignores the
new kind.

**`metrics/daily/<day>.md`** gains `## Features on production` as its first section, above
`## Waste`, exactly as §2.4 prints it: one headline sentence, one note line, and a table of one
row per product plus `**Total**`. Nothing below that section changes.

**stdout of `asf metrics rollup`** gains one line before `cost:`:

```
features: 3 on prod this week, $12.40 each (last week 3, $19.55)
```

**Nothing else.** No item field is added or rewritten — `stage`, `stage_since`, `cost` and
`spend_usd` keep the values and the writers they have today. No Bug is filed, no release file
changes, no `index.json` key is added.
