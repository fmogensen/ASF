# F-0324 — an empty diff is not evidence of a landing

A session whose work the trunk already holds under another commit has one way out of the
empty-branch loop, and the factory tells it so in as many words
(`asf/workers/lifecycle.py:3400-3403`):

```python
ALREADY_LANDED = ('if the work is already on the trunk under another commit, verify it, run the '
                  'test that covers it, then make one empty signed commit per item naming its id '
                  '— `git commit --allow-empty -s -m "<kind>(<id>): already landed in <sha> — '
                  'verified by <test>"` — and push: a report that only says so closes nothing')
```

The commit that instruction asks for changes no file. The lane's B-0057 trunk test then reads the
branch by its *tree* (`asf/harvest/lane.py:1202-1218`):

```python
    if files is None:
        files = touched_files(repo, trunk, branch)
    ...
    same = [f for f in files if f not in differ]
    ...
    if len(same) == len(files):
        return True, []
```

With no file in `files`, `len(same) == len(files)` is `0 == 0`. The test passes on nothing: the
branch is declared already on main, its PR closed, the branch deleted, and the record stamped
`method=on-trunk` at the trunk tip the branch never reached. The evidence the session was told to
make is thrown away with the ref, and because the one commit that could have closed the card is
the one just deleted, the card stays open and the row launches again. The card's own case: a Task
of a sibling product's lane, deleted as "already on main at `daeef1c`", looping after it.

The requirement is the sentence the tree test is missing: **a branch that changes no file is not
shown to be on the trunk by its tree — its own commits are its deliverable, and the lane lands
them.**

## Decisions

### Preconditions — measured in this worktree at `c599985a2`, 2026-10-10

Every `<file>:<line>` in this spec is against this branch's base, `801a73565` — which for
every file cited here is byte-identical to `origin/main`. The P-numbered outputs below were
measured at `c599985a2`; `asf/harvest/lane.py` and `asf/workers/lifecycle.py` have moved since,

Each is one `tests/test_lane.py::LaneFixture` fixture: a bare origin, the product's checkout and a
worker clone that pushes `worker/T-0001` as a session does — here with one empty commit,
`task(T-0001): already landed in abc1234 — verified by t`, and a finished run on it.

  `5ed2962` is the trunk tip; `2867820` is the proof commit, now unreachable. The trunk's
  subjects are what they were before the session ran.
* **P2 — the landing the lane wrote is no landing of the item.** On the same ledger, straight

* **P3 — a rebuild drops a proof commit even from a branch that has work.** `worker/T-0001`

  The pick of an empty commit produces its parent's tree, which `drop_trunk_copies` reads as

* **P6 — two callers, one function.** `already_on_trunk` is called from

* **P7 — `review_waived` is called positionally by its tests.**
  `tests/test_direct_lane.py:175-189` passes five positional arguments; a sixth, keyword-defaulted

* **P9 — green today, and green on the candidate.** The whole lane surface was run against the

  `tests.test_mechanical` + `tests.test_lane_off_tick` + `tests.test_one_door` +
  `tests.test_pin_defects` + `tests.test_refusals` (184) — `OK` each. No existing test asserts

  (`LaneRepo.test_a_branch_reset_to_the_trunk_tip_with_an_open_pr_is_not_landed`,
  `ReportCommitsAreNoCopies`) both read the other way and stay green.

### In

1. `already_on_trunk` refuses the tree test for a branch that changes no file, and answers it on
   the evidence `empty_branch_landed` already demands of a branch with no commits of its own: a
   trunk commit naming the item.
2. `drop_trunk_copies` keeps a commit that was already empty against its own parent, instead of
   dropping it as a change the trunk has caught up with.
3. A branch whose diff against the trunk is empty needs no ASF review round.

### Out

* The session side. `ALREADY_LANDED` and `asf.workers.trunkclose` stay exactly as they are: this
  is about what the lane does with a proof commit that was pushed, not about when a session
  should make one.
* The gate and CI. A proof-only branch gates and lands like any other branch — the trunk's own
  test command on the rebuilt head, then the product's landing method. Its tree is the trunk's,
  so the gate is a re-run of the trunk's own green; cheap enough that buying a second landing
  path for it would cost more than it saves.
* `empty_branch_landed` (a branch with *no* commit past the trunk). It already waits rather than
  lands on a bare tree match, and it is the source of the rule limb 1 adopts.
* The `landing_class` of an empty diff. It reads `code`, which is wrong-ish for a proof-only
  *spec* branch, but with limb 3 nothing hangs on it. Not touched.
* Retrospective repair of items already looped. No card is re-opened, no deleted proof commit is
  reconstructed; the items concerned come back round the ordinary way once the lane stops
  deleting their next proof.

### Preconditions the work depends on

P1–P9 above. In particular: `item_on_trunk` already exists beside `already_on_trunk`
(`lane.py:1221-1231`) and is already the evidence `empty_branch_landed` reads, so limb 1 adds no
new notion of "the trunk holds this item"; and `_commit_rows`/`marker_commits` already encode
"this commit carries no work of its own" (`lane.py:558-583`), which limb 2 deliberately does
*not* reuse — see the choices.

### The choices

| chosen | against | why |
| --- | --- | --- |
| A no-diff branch is on the trunk only when a trunk commit names its item | reading it as never on the trunk | a proof that already landed (the item looped once before, or its work landed under a named commit) must still close the branch, or the lane would re-land the same proof for ever. This is the rule `empty_branch_landed` already applies one case over |
| The rule lives in `already_on_trunk` | an arm in `branch_facts` | `orphan_facts` calls the same function (P6) and would otherwise keep the defect |
| Land the proof through the ordinary lane (PR/gate/landing method) | a dedicated "proof landing" that pushes the empty commit straight onto the trunk | measured: the ordinary path lands it, rebase included (P9's harvest test lands a proof-only branch that is behind the trunk). A second landing path would be a second place for the trunk to be written |
| Limb 2 keeps a commit that was empty **against its own parent** | keeping every `marker_commits` hit (an empty commit *or* a report-subject commit) | precise: a report commit that did carry a change the trunk has since caught up with is still a copy and is still dropped. The test is "was anything lost here?", not "what does its subject look like?" |
| Limb 3 waives the review round when the branch's diff is empty | leaving the review round in place | a review verdict on an empty diff is a verdict about nothing, and P5 is what it costs: three review sessions on one proof. Narrow by construction — only an empty diff |
| The waiver is a new last parameter of `review_waived` | a new fact key read in `next_state` | one owner for "why this code branch needs no review", already printed in the record's reason (`lane.py:1580-1582`); and P7 says the signature change is free |
| No new lane line when the trunk test is refused | one line per pass saying so | the branch's ordinary transitions (`- → PUSHED`, `PUSHED → PR_OPEN`, …) already narrate it, and a per-pass line on every no-diff branch would print until it lands |

## The design

Three edits, all in `asf/harvest/lane.py`.

### 1. `already_on_trunk` — the tree test needs a file to test

its card, not to land a stranger's commit.

### 2. `drop_trunk_copies` — an empty pick of an already-empty commit is not a dropped change


and the docstring's own account of what is dropped, whose "a commit whose change the trunk
already holds (an empty pick) too" (`lane.py:891`) now needs its exception — one sentence after
it, before `A dict:`:

> A commit that was *already* empty against its own parent — a proof commit, a session's report —
> is kept, as an empty commit on the rebuilt branch: its pick adds nothing because it never

With it, P3's rebuild carries both subjects and P4's rebuilds to the trunk plus its proof. The
rebuild guard is unaffected: an empty commit does not change the tree the guard compares.

### What it looks like when it is there

The same fixture as P1, one `lane_pass`:

```
lane: worker/T-0001 - → PUSHED (finished)
lane: worker/T-0001 PUSHED → PR_OPEN (fast-forward: the branch is its own PR)
lane: worker/T-0001 PR_OPEN → GATE (review: none (no diff against the trunk: nothing to review))
```

and through `harvest.run_product_harvest`, on a product whose trunk has moved since the branch
was cut:

```
harvest: 1 branch(es), one gate
landed fix/B-0001 → 270fdd3d30e11c82e47e9c3ff9d170a2e7774408
```

with `git log --format=%s <before>..main` on the origin reading

```
fix(B-0001): already landed in abc1234 — verified by checks.test_fx
```

The branch is gone from origin *after* its proof is on the trunk, the run's `harvested:` is the
sha the trunk holds, and `merge_facts` now carries the item — so the ordinary evidence rule
closes the card and the row does not come back.

## Acceptance tests

### `tests/test_lane.py` — a new class beside `TrunkCopiesDropped`

Five cases over the lane's own fixture. Four are red on `c599985a2` (`FAILED (failures=4)`);
`test_a_proof_only_branch_whose_item_the_trunk_names_is_landed` is green both before and after —

```python
class ProofOnlyBranchLands(LaneFixture):
    """F-0324 — a branch of only empty proof commits ("already landed in <sha> — verified by
    <test>", the evidence the record reads) changes no file, so B-0057's trunk test held
    vacuously: the branch was read as already on main and deleted with its proof unlanded, the
    lane's own landing fact was then discarded for a tip no trunk commit holds, and the item
    looped. Its commits are its deliverable: the lane lands them."""

    B = 'worker/T-0001'
    PROOF = 'task(T-0001): already landed in abc1234 — verified by t'

    def proof_branch(self):
        sh(['git', 'fetch', '-q', 'origin'], cwd=self.worker)
        sh(['git', 'checkout', '-q', '-B', self.B, 'origin/main'], cwd=self.worker)
        sh(['git', 'commit', '-q', '--allow-empty', '-m', self.PROOF], cwd=self.worker,
           env_=self.ident)
        sh(['git', 'push', '-q', '-f', 'origin', self.B], cwd=self.worker)
        sh(['git', 'fetch', '-q', 'origin'], cwd=self.repo)

    def heads(self):
        return sh(['git', 'for-each-ref', '--format=%(refname:short)', 'refs/heads'],
                  cwd=self.origin).stdout.split()

    def on_trunk(self, item='T-0001'):
        return lane.already_on_trunk(self.repo, 'main', self.B,
                                     self.product().conventions, item)

    def pass_(self, **conv):
        lines = []
        lane.lane_pass(self.product(**conv), self.state_dir, out=lines.append)
        return lines

    def subjects(self, rev):
        return sh(['git', 'log', '--format=%s', f'origin/main..{rev}'],
                  cwd=self.repo).stdout.splitlines()

    def test_a_proof_only_branch_is_not_read_as_already_on_the_trunk(self):
        self.proof_branch()
        self.assertEqual(lane.touched_files(self.repo, 'main', self.B), [])
        self.assertEqual(self.on_trunk(), (False, []))
        self.session('coder-t-0001', 'T-0001', self.B)
        lines = self.pass_()
        rec = self.lane_of(self.B)
        self.assertEqual(rec['state'], lane.GATE, (rec, lines))
        self.assertNotEqual(rec.get('method'), 'on-trunk')
        self.assertIn(self.B, self.heads(), 'never deleted with its proof unlanded')
        self.assertFalse([l for l in lines if 'already on main' in l], lines)

    def test_a_proof_only_branch_whose_item_the_trunk_names_is_landed(self):
        self.proof_branch()
        self.push_main({'z.txt': 'z\n'}, 'task(T-0001): the work, landed another way')
        sh(['git', 'fetch', '-q', 'origin'], cwd=self.repo)
        self.assertEqual(self.on_trunk(), (True, []))
        self.session('coder-t-0001', 'T-0001', self.B)
        lines = self.pass_()
        self.assertEqual(self.lane_of(self.B)['reason'], 'method=on-trunk')
        self.assertNotIn(self.B, self.heads())
        self.assertTrue([l for l in lines if 'already on main' in l], lines)

    def test_the_review_round_is_waived_on_a_branch_with_no_diff(self):
        self.proof_branch()
        self.session('coder-t-0001', 'T-0001', self.B)
        lines = self.pass_(lane={'review': {'code': 'required'}})
        rec = self.lane_of(self.B)
        waiver = 'no diff against the trunk: nothing to review'
        self.assertEqual((rec['state'], rec['reason']),
                         (lane.GATE, f'review: none ({waiver})'), (rec, lines))
        self.assertEqual(lane.review_waived(self.product().conventions, 'code', {},
                                            'T-0001', None, []), waiver)

    def test_a_rebuild_keeps_a_commit_that_was_empty_on_its_own_parent(self):
        sh(['git', 'fetch', '-q', 'origin'], cwd=self.worker)
        sh(['git', 'checkout', '-q', '-B', self.B, 'origin/main'], cwd=self.worker)
        self.write(self.worker, 'a.txt', 'a\n')
        sh(['git', 'add', '-A'], cwd=self.worker)
        sh(['git', 'commit', '-qm', 'task(T-0001): the work'], cwd=self.worker, env_=self.ident)
        sh(['git', 'commit', '-q', '--allow-empty', '-m',
            'task(T-0002): already landed in abc1234 — verified by t'], cwd=self.worker,
           env_=self.ident)
        sh(['git', 'push', '-q', '-f', 'origin', self.B], cwd=self.worker)
        self.push_main({'z.txt': 'z\n'}, 'trunk moves on')
        sh(['git', 'fetch', '-q', 'origin'], cwd=self.repo)
        res = lane.drop_trunk_copies(self.repo, 'main', self.B, always=True)
        self.assertEqual(res['empty'], [], res['why'])
        self.assertEqual(self.subjects(res['new']),
                         ['task(T-0002): already landed in abc1234 — verified by t',
                          'task(T-0001): the work'])

    def test_a_proof_only_branch_with_the_trunk_merged_in_rebuilds_to_its_proof(self):
        self.proof_branch()
        self.push_main({'z.txt': 'z\n'}, 'trunk moves on')
        sh(['git', 'fetch', '-q', 'origin'], cwd=self.worker)
        sh(['git', 'checkout', '-q', self.B], cwd=self.worker)
        sh(['git', 'merge', '-q', '--no-edit', 'origin/main', '-m', 'task(T-0001): merge main'],
           cwd=self.worker, env_=self.ident)
        sh(['git', 'push', '-q', '-f', 'origin', self.B], cwd=self.worker)
        sh(['git', 'fetch', '-q', 'origin'], cwd=self.repo)
        res = lane.drop_trunk_copies(self.repo, 'main', self.B)
        self.assertEqual(self.subjects(res['new']), [self.PROOF])
        self.assertEqual((res['empty'], len(res['merges'])), ([], 1))
```

## Records

No new record key, no new lane state, no new card field. What changes is which rows get written
for a proof-only branch:

* **The run line** (`sessions.jsonl`, the `lane` object): `state: MERGED` with
  `reason: method=on-trunk` and `sha: <trunk tip>` is replaced by the ordinary walk — `PUSHED`,
  then `PR_OPEN`, `GATE`, and `MERGED` with the product's own landing method (`ff`, `squash`,
  `queue`) and `sha` the commit the trunk now holds. `harvested:` becomes that sha.
* **The trunk** gains the proof commit — one empty commit whose subject names the item. That is
  the row every later reader wants: `asf.evidence.evidence.merge_facts` yields the item (P2
  measured `{}` today), so the ordinary closing rule closes the card, and
  `asf.harvest.lane.item_on_trunk` finds it if the item is ever cut again.
* **The lane's own log**: `landed <b>: already on main at <sha>` no longer appears for a
  proof-only branch; `review: none (no diff against the trunk: nothing to review)` appears in the
  record's `reason` when a review round was required and is waived.
* **The rebuild's line**: `dropped N trunk copies …` counts `copies + empty`, and a commit that
  was already empty is no longer in `empty` — so the count tells the truth about what was
  dropped, and no proof commit is ever among it.

## Stories

- S: the lane never reads a branch with no diff as already on the trunk, and lands its proof commits — acceptance: `tests/test_lane.py::ProofOnlyBranchLands::test_a_proof_only_branch_is_not_read_as_already_on_the_trunk` and `tests/test_harvest.py::ProductHarvestTests::test_f0324_a_branch_of_only_empty_proof_commits_lands_its_proof`
- S: a rebuild of a lane branch keeps every commit that was already empty, so a proof commit survives a rebase — acceptance: `tests/test_lane.py::ProofOnlyBranchLands::test_a_rebuild_keeps_a_commit_that_was_empty_on_its_own_parent`
- S: a branch whose diff against the trunk is empty spends no review round — acceptance: `tests/test_lane.py::ProofOnlyBranchLands::test_the_review_round_is_waived_on_a_branch_with_no_diff`

Three Stories, one per limb of `## The design`. All three ids are the ones the record already
carries for this Feature (S-91405, S-91406, S-91407); no new id is minted, so no id of this
session's range is spent. The `### S-…: <title>` heading is what
`asf.record.idcheck.declared_stories` reads and what `asf.record.plan_tasks` mints the card from.

### S-91405: the lane never reads a branch with no diff as already on the trunk, and lands its proof commits

Limb 1 of the design. `already_on_trunk` answers a no-diff branch on `item_on_trunk`, not on a
tree test with nothing in it; both of its callers take the change from the function. The branch
then walks the ordinary lane and its proof commit reaches the trunk, which is what makes the
card closeable and the row stop coming back.

- [ ] a branch whose only commit is empty reads `(False, [])` from `already_on_trunk`, and `touched_files` of it is `[]`
- [ ] one lane pass over it leaves it in `GATE`, not `MERGED`, with no `method=on-trunk`
- [ ] the branch is still on origin after that pass, and no line says `already on main`
- [ ] the same branch, with a trunk commit naming its item, still lands as `method=on-trunk` and is deleted — the on-trunk landing is not broken
- [ ] one harvest of a proof-only branch puts its subject on the trunk, writes `harvested:` at the sha the trunk holds, and deletes the branch only then
- [ ] a second harvest of the same product finds nothing left to do

### S-91406: a rebuild of a lane branch keeps every commit that was already empty

Limb 2. `drop_trunk_copies` drops a pick that adds nothing only when the commit itself carried
something — a change the trunk has caught up with. A commit that was empty against its own parent
is rebuilt as an empty commit, so a rebase, a trunk-copy rebuild or a conflict repair never
deletes the evidence the record reads.

- [ ] a branch carrying one real commit and one empty proof commit rebuilds to both, in order, with nothing in `empty`
- [ ] a proof-only branch with the trunk merged into it rebuilds to the trunk plus its proof commit, its merge dropped
- [ ] a commit whose own change the trunk already holds by another patch is still dropped, and still counted in `empty`
- [ ] `tests/test_lane.py` runs whole and green, `ReportCommitsAreNoCopies` and `TrunkCopiesDropped` included

### S-91407: a branch whose diff against the trunk is empty spends no review round

Limb 3. A review verdict needs a diff to be a verdict about something. `review_waived` gains the
branch's diff and answers for an empty one; the waiver is printed where every other waiver is, in
the record's own reason.

- [ ] `review_waived(..., files=[])` answers `no diff against the trunk: nothing to review`
- [ ] under `lane.review.code: required`, a proof-only branch walks to `GATE` with `reason: review: none (no diff against the trunk: nothing to review)` and asks for no review round
- [ ] a branch with a diff is unaffected: the existing waiver cases (`lane: direct`, `review.skip_under_lines`) answer exactly as before
- [ ] `tests/test_direct_lane.py` runs whole and green with its five positional calls unchanged
