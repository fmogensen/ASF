# F-0227 — an ended run whose pid stays alive blocks its item forever

The card's incident, in the two lines it left on every tick for 54 minutes:

```
keep      review-t-0196            ended: pid still alive
waits     review-t-0196  T-0196  — already running
```

and, at the same moment, `asf status` saying **0 working**, with 0 of 2 sessions in use and the
item ready to launch. That is not one fact reported twice. It is two different answers to "is
`review-t-0196` running?", from two different authorities:

* **the ledger** — `sessions.jsonl` carries the run's `ended` line. `lifecycle.is_live` is false,
  the run holds no seat, and every view that reads the ledger says nothing is working;
* **`ps`** — a `claude -p` process (pid 67546, ppid 1, 0.1% CPU) is still up, and its
  `ASF_SESSION` still says `asf/review-t-0196@…`. Every reader that starts from the process table
  says `review-t-0196` is running.

The process half is the card's subject, and half of it is already fixed. `health.settle_ended`
(T-0196, `7f59d035e`) stops exactly such a process once its grace has passed, and refuses to touch
anything that is not provably the factory's own. That fix ended the first line above.

It did not end the second, because the second is not about the process at all — it is about who is
**believed**. `Pool.from_config` builds its live list from the registry *plus* the observed
sessions no registry knows, and "no registry knows" is decided against the **live** runs only
(`asf/workers/pool.py:320-330`). An **ended** run is not in that set, so its own leftover process
matches nothing, falls through as an *extra* session — and that extra is synthesised carrying
`job: 'review-t-0196'`, straight out of the `ASF_SESSION` the dead run itself wrote. The wave's
`running` set is built from those jobs (`asf/workers/wave.py:164`), so the row for the item waits
`already running` — on a job whose run the ledger ended, held up by a process that is its corpse.

This card is therefore: **a process whose `ASF_SESSION` names a run the ledger has already ended,
past the grace period, is a leftover process — real load on its account, and never a running
job** — plus the one grace period and the one predicate that says so, read by the pool that
attributes it and by the health pass that stops it.

### The choices

| # | Chosen | Against | Why |
| --- | --- | --- | --- |
| C1 | **The fix is the pool's attribution, not a new stop and not a new end.** An observed session whose `ASF_SESSION` names a run the ledger has ended, past the grace, is synthesised with **no `job` and no `product`**. | Re-ending the run; a new health rule; making the wave smarter about processes. | P1: the run is already finished everywhere the ledger is read, and P2/P3: the process is already stopped and the worktree already released. | C2 | **The match is on `session`, the `ASF_SESSION` id, and on nothing else.** | Matching on pid as well (or instead). | P8: the id is unique per launch — `product/job@<launch stamp>` — and cannot come back on a recycled pid, which is exactly the trap a pid match would walk into after 54 minutes. | C3 | **The leftover process still counts as load on its account.** Only its `job` and `product` are dropped; `account`, `session`, `pid`, `owner` and `model: None` stay, so `load`, `headroom` and the foreign tally are byte-for-byte what they are today. | Dropping the extra from `pool.live` altogether, so an ended run's process stops counting at all. | F-0076's rule is the machine's: "a foreign session on one of our accounts spends a seat too" (`pool.py:303-306`). ### In, and out

**In.** `lifecycle.LINGER_GRACE_S` (moved from `health`, which becomes its alias);
`lifecycle.linger_spent(run, now=None, grace_s=None)`; `lifecycle.spent_sessions(state_root,
now=None, grace_s=None)`; `Pool.from_config` synthesising a spent process's extra entry with `job:
None, product: None`; `wave`'s `running` set guarded on `s.get('job')`; the module docstrings of
`asf/workers/pool.py`, `asf/workers/wave.py` and `asf/workers/lifecycle.py` gaining the rule.

**Out, deliberately.** Any change to what `settle_ended` stops or refuses to stop (P2, C10); any
change to `judge`, `occupies`, `live_all`, `reap_verdict` or the `alive` wrapper (C10); the load a
leftover process counts as (C3); settling outside a health pass (C9); a config key (C8); a new
command, doctor row, state file, record card, schema version or migration; and any change to
`asf status`, `asf sessions` or the tick digest — they read the ledger, which was right all along
(P1).

## The design

### 1. `asf/workers/lifecycle.py` — one grace, one predicate, one index

```python
#: Seconds an ended run's own process gets to exit by itself. Until it is up, the process is
#: still the run's — it may be flushing, committing or pushing, and it still holds the run's
#: worktree open. After it, the run is spent: the factory stops believing the process
#: (:func:`spent_sessions`, read by the pool) and stops the process itself
#: (:func:`asf.workers.health.settle_ended`). One number, so the two can never disagree about
#: when (T-0196, F-0227).
LINGER_GRACE_S = 300


def linger_spent(run, now=None, grace_s=None):
    """True when ``run`` has an ``ended`` line and its grace has run out: the run is finished on
    the ledger (:func:`is_live` is already false) *and* enough time has passed that a process
    still answering for it is a leftover, not the run.

    False for a live run, for one whose ``ended`` stamp cannot be read, and for one still inside
    the grace — all three are "not yet", never "no"."""
    ended = headroom.parse_ts((run or {}).get('ended'))
    if ended is None:
        return False
    grace = LINGER_GRACE_S if grace_s is None else grace_s
    return (time.time() if now is None else now) - ended.timestamp() >= grace


def spent_sessions(state_root, now=None, grace_s=None):
    """``{ASF_SESSION id}`` for every spent run (:func:`linger_spent`) under every product's
    registry — the ids a process may still carry that name no running job.

    The mirror of :func:`live_all`, over the same files and the same fold cache, and matched on
    the session id alone: the id is unique per launch, where a pid is a number the kernel hands
    out again (F-0227 C2). A run that recorded no ``session`` contributes nothing."""
```

`spent_sessions` walks `state_root/*/sessions.jsonl` exactly as `live_all` does (`:452-458`),
taking `latest(path).values()` — P9's cache hit — and collecting `r['session']` for each run
`linger_spent` accepts.

### 2. `asf/workers/pool.py` — a leftover process is load, never a job

`Pool.from_config`, at the synthesis (`:326-330`), becomes:

```python
        extra = [o for o in observed
                 if o.account is not None and o.pid not in pids and o.session not in sessions]
        # an extra whose ASF_SESSION names a run the ledger ended, past its grace, is that run's
        # leftover process: real load on the account, and never a running job. The ledger's
        # ``ended`` line is the newer fact; ``ps`` answers for processes, not for jobs (F-0227).
        spent = lifecycle.spent_sessions(os.path.join(env.ASF_HOME, 'state'))
        live = registered + [{'account': o.account, 'model': None,
                              'product': None if o.session in spent else o.product,
                              'job': None if o.session in spent else o.job,
                              'session': o.session, 'pid': o.pid, 'owner': o.owner}
                             for o in extra]
```

Every other field is untouched, so `load`, `headroom`, the per-lane counts and the foreign tally
read exactly what they read today (C3, P6). The `from_config` docstring gains the rule as its own
paragraph, beside the "Each seat is counted once" one it qualifies.

### 3. `asf/workers/wave.py` — the one reader, saying so

```python
    # a live entry with no job is a leftover process, not a running session (F-0227 C1)
    running = {(s.get('product') or product.name, s.get('job'))
               for s in pool.live if s.get('job')}
```

and the module docstring's `already running` paragraph (`:12-16`) gains: *an ended run's leftover
process is not a live session of this product, however long it stays up.*

### 4. `asf/workers/health.py` — reading the one predicate

`LINGER_GRACE_S = lifecycle.LINGER_GRACE_S` beside the existing `pid_alive = lifecycle.pid_alive`
(`:74`), and `settle_ended`'s local branch (`:233-234`) becomes:

```python
        if not run.get('session') or not lifecycle.linger_spent(run, now, grace_s):
            continue
```

`cloud._parse_ts` staying exactly where it is at `:260`, where the `<m>m ago` in the stopped line
is counted (C6). Nothing else in the function moves: the same runs are stopped, under the same
three proofs, at the same minute.

### What it looks like when it is there

The card's tick, with the same lingering process still up and health not yet run:

```
waits    review-t-0196  T-0196  — <a real reason, or no line at all: the row launches>
```

and with health run, the process stopped, as it already is today:

```
stopped   review-t-0196   pid 67546 (SIGTERM): ended finished 54m ago, its process still running
```

`asf status` still says what it said: the ledger never thought the run was working.

| **`asf status`, `asf sessions`, the tick's IN FLIGHT table** | — | Unchanged. They read `ended` off the ledger and were right throughout the incident (P1). |
| **What is not written** | — | No config key, no command, no doctor row, no state file, no record card, no schema version, no migration, no metric. |
