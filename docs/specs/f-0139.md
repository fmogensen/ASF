# F-0139 — `578 open` is three numbers wearing one coat

The status table's Record row prints `<n> open · <n> Active · <n> blocked · <n> no rule`, and
`open` is every live item whose state is not `Closed` (`asf/views/status.py:259`). Three unlike
populations are inside it:

- **work** — a Feature, Story, Task, Bug or Epic somebody still has to do;
- **Resolved** — work that is finished and waiting to close;
- **records** — a `decision` or a `rule`: something the record *says*. Nobody is assigned one, none
  of them lands, and no closing rule ever moves one. They are open for ever by construction.

In the reading the card carries, that is `578 open = 468 work + 7 Resolved + 103 records`
(88 decisions, 15 rules). The number an operator actually wants — how much work is outstanding — is
**468**, and to get it they subtract 110 from 578 in their head. That subtraction is the defect. It
is done every time the row is read, it is done from counts the row does not print, and a rounded or
wrong answer from it looks exactly like a right one.

The fix is arithmetic the row already has the data for, and it needs no new notion of "work":
**the factory already disagrees with itself about what `open` means, and this row is the outlier.**
`asf/feeder/rows.py:456` says an item is open when its state is `not in ('Resolved', 'Closed')`
— the feeder has never counted Resolved as open. `asf/record/core.py:136` says `!= 'Closed'` —
Resolved *is* open to the record. The Record row reimplements core's definition inline, and then
reports it under a word the rest of the factory uses for the other one.

### In

- **Three counts where there was one**, in `record_cell`: `<n> work · <n> Resolved · <n> records`
  replacing `<n> open`, summing to the old total by construction.
- **`work` counted by the feeder's own `is_open`** (P3) — one definition of "open work" in the

- **`Active` and `blocked` narrowed to `work`** — the flags read the population the number beside

### The choices

| # | Chosen | Against | Why |
| --- | --- | --- | --- |
| C1 | Three counts **replace** the total; the word `open` leaves the row. | Keeping `<n> open` and appending the subsets — `578 open (7 Resolved, 103 records)`. | The card's own words: the split *instead of* one total. Leading with `open` leaves the misleading number where the eye lands first and asks for a subtraction — the same by-hand derivation, in the other direction. A sum is recoverable by addition when anyone wants it; the number wanted every time is `work`. |
| C2 | Six ` · `-separated `<n> <word>` fields, one line, population first then flags. | A second line, or a parenthesised sub-clause in the style of `build_cell`'s `(auto: …)`. | The row is already `<n> <word>` pairs joined by ` · ` (P2) — two more pairs is the same idiom and introduces none. One line is also what F-0118's compact status line needs (P12); a cell that wraps becomes five rows of a session's status line. |
| C3 | **Type decides before state.** A `decision` or `rule` counts under `records` whatever its state says, so a hand-written `Resolved` ruling is counted once, as a record. | State first, so a Resolved ruling counts under `Resolved`. | Records are never work, so "done, waiting to close" is not something that happens to them; `Resolved` in this row means *work that is finished*, and a ruling inside it would make one number mean two things. P6 says the case is reachable, so the precedence is written down rather than left to whichever comprehension runs first. |
| C4 | `records` is the **positive** test (`type in RECORD_TYPES`); every other open item is work-typed. | `work` as the positive test (`type in WORK_TYPES`), `records` as the complement. | The two agree on every card the record can hold (P4) and differ on exactly one thing: a row whose `type` is missing or unrecognised. That row belongs in `work`, where an operator is looking, not in `records`, the bucket they have learned to skip. | C5 | `RECORD_TYPES` is a module constant in `asf/views/status.py`, guarded by a test asserting `set(RECORD_TYPES) \| WORK_TYPES == set(TYPES)`. | Importing a shared constant added to `asf/record/core.py`, with the four existing literals folded onto it. | The consolidation is right and is not this card (Out). The fence is what makes the local constant safe without it: a seventh type added to `TYPES` fails this test, so whoever adds one must say which bucket it counts in instead of discovering months later that it was silently work. |
| C6 | `Active` and `blocked` count over **work**. | Leaving both over `opened`, as today — the smaller diff. | The lead number is `work`; a flag counted over a wider population than the number beside it is precisely the trap this card exists to remove — `468 work · 41 Active` where one of the 41 is a ruling nobody is working. By P6 this moves no count on a record nobody has hand-edited, which is the argument for doing it now rather than leaving a second derivation to be found later. |
| C7 | `Resolved` keeps its capital; `work` and `records` are lower case. | All three lower case, for an even-looking row. | `Resolved` is the record's own state word, capitalised everywhere else in the tree; `work` and `records` are this row's words for a population, not states. The row already mixes the two — `0 Active · 0 blocked` (P2). |
| C8 | `Resolved` is computed as `len(typed_work) - len(work)`, not by a second `state == 'Resolved'` test. | Three independent comprehensions, one per bucket. | It makes the partition true *by construction* rather than by three predicates that must agree: whatever `is_open` calls not-open among non-record open items is what `Resolved` counts, so the three can never fail to sum to the total the row replaced. `opened` has already dropped every Closed item, so there is nothing else for the subtraction to catch. |

## The design

One function in `asf/views/status.py`, one constant above it, two docstrings. Nothing else changes.

### 1. `RECORD_TYPES`, above `record_cell`

```python
#: The record-only types: a `decision` and a `rule` are things the record *says*, not work anybody
#: does — nobody is assigned one, none of them lands, and no closing rule ever moves one, so they
#: are open for ever and are never part of "how much work is outstanding" (F-0139). They are the
#: complement of :data:`asf.record.match.WORK_TYPES` in :data:`asf.record.core.TYPES`, written
#: here as the *positive* test so a card whose ``type`` is missing or unrecognised counts as work,
#: where an operator is looking, rather than vanishing into the bucket they skip.
RECORD_TYPES = ('decision', 'rule')
```

### 2. `record_cell`

```python
def record_cell(root):
    """``<n> work · <n> Resolved · <n> records · <n> Active · <n> blocked · <n> no rule`` from
    ``index.json``'s live items.

    The first three are the split of what used to print as one ``open`` total, and they partition
    it: ``work`` is an item somebody still has to do — the feeder's own
    :func:`asf.feeder.rows.is_open`, to which ``Resolved`` is *not* open; ``Resolved`` is work that
    is done and waiting to close; ``records`` is every open ``decision`` or ``rule``
    (:data:`RECORD_TYPES`), which is never work whatever its state says. ``Active`` and ``blocked``
    count over ``work`` — the number they sit beside, not the wider set. ``no rule`` is unchanged:
    an ``evidence:`` list whose last entry is ``rule: no-rule``, the residue, over every live item,
    Closed ones included.
    """
    from asf.feeder import rows as feeder_rows
    from asf.views import index_reader as ix
    if not root or not os.path.exists(os.path.join(root, 'index.json')):
        return not_configured('backlog_dir (no index.json)')
    try:
        items, _generated = ix.load(root)
        live = [v for v in items.values() if isinstance(v, dict)]
    except (OSError, ValueError, KeyError, AttributeError):
        return not_configured('backlog_dir (index.json unreadable)')
    opened = [v for v in live if v.get('state', 'New') != 'Closed']
    records = [v for v in opened if v.get('type') in RECORD_TYPES]
    typed_work = [v for v in opened if v.get('type') not in RECORD_TYPES]
    work = [v for v in typed_work if feeder_rows.is_open(v)]
    resolved = len(typed_work) - len(work)   # C8: `opened` holds no Closed item for this to catch
    active = sum(1 for v in work if v.get('state') == 'Active')
    blocked = sum(1 for v in work if v.get('blocked') is True)
    no_rule = sum(1 for v in live if _residue(v))
    return (f"{len(work)} work · {resolved} Resolved · {len(records)} records · "
            f"{active} Active · {blocked} blocked · {no_rule} no rule")
```

The two `not_configured` branches, the `except` tuple and `_residue` are untouched — the card
changes what is counted and printed, not how an unreadable record is reported (P10 keeps both
fallback assertions un-edited).

### 3. The module header's `Record` bullet

`asf/views/status.py:19-21` reads *"**Record** — the record's counts from `index.json`: open,
Active, blocked, and the items no closing rule sees…"*. It becomes:

> * **Record** — the record's counts from `index.json`, with the open set **split** rather than
>   totalled: work still to do, work Resolved and waiting to close, and the record-only cards
>   (`decision`, `rule`) that are never work (F-0139); then the Active and blocked counts of that
>   work, and the items no closing rule sees (`rule: no-rule`, §2.7 of the closing spec; `asf
>   check` names each).

## Records

- **Nothing is written.** `record_cell` reads `index.json` and returns a string; this card adds no
  row, no field, no file, no event and no config key. The record is the input, never the output.
- **The one artifact whose bytes change** is `asf status`'s rendered table — the `Record` row's
  cell, and nothing else in it. The row keeps its name and its position (pinned un-edited, P10).
- **Once F-0118 lands**, that same cell is one line of the `status.txt` snapshot and of the session
  status line read off it. This card writes neither; it only owes them a single short line (C2).
- **`index.json` is not touched**, and no count this card prints is stored anywhere — each is
  recomputed from the index on every render, so a stale number is impossible by construction and
  the existing `Stale` row remains the only statement about the index's own age.
- **`docs/specs/f-0139.md`** — this document, the record of the decisions above.
