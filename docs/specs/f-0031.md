# F-0031 — The approval matrix as code

Parent: E-0001 — ASF 0.1 — a working factory. Stage: card → spec.

The card, as the requirement: *standing authority is prose today: money, production, security,
customer data, legal and new Epics need a person; everything that cuts errors or time does not. It
becomes `products/<name>.yaml → approvals:` — action classes mapped to `auto`, `groom` or
`human-now` — read by the hooks (which refuse) and by the tick (which raises the line). A human
widens or narrows the factory's authority in one file.*

Acceptance on the card:

- every action class in the matrix is named and mapped
- a hook refuses an action its class marks `human-now`
- the tick raises one line naming the class and the item when it is held

## 1. Decisions

### In

- A closed **catalogue of action classes** in a new module `asf/approvals.py`: each class's name,
  what it covers, its default level, where it is read, and how an action is recognised as it.
- The **matrix**: `approvals:` in `~/.ASF/products/<name>.yaml`, a flat map `class: level`, read
  and validated by `asf/approvals.py`. One optional companion key, `approval_signals:`, adds
  product-specific recognisers to a class. Nothing else about authority is configured anywhere.
- **The hook**: `asf hook approvals`, a Claude Code `PreToolUse` hook built into `asf` (not a
  `tools/checks/*.sh` script). It classifies the tool call, and refuses (exit 2) any action whose
  class maps to `groom` or `human-now`, writing a hold to the per-product ledger.
- **Installing the hook** into every worker account's runtime settings, by `asf hooks install`.
- **The tick**: the `wave` step raises one line per open `human-now` hold naming the class and the
  item, one summary line for open `groom` holds, and does not relaunch a held item. The `harvest`
  step reads the two merge classes before it lands a branch. The bug filer reads `file_bug` on
  both of the tick's paths into it.
- **The operator's side**: `asf approvals` (print the effective matrix), `asf approvals list`
  (open holds), `asf approvals resolve <hold> granted|done|dropped`; and an `approvals` row in
  `asf doctor`.
- The example and sample product files map every class.

### Out

- **Per-item History lines for holds.** A hold is recorded in the ledger and as record events
  (§4); writing into the item's card is left to the groom.
- **Rendering `groom` holds into `groom/<date>.md`.** `asf groom` rewrites that file wholesale;
  teaching it a new section is a change to groom. Until then `groom` holds are visible through
  the tick's summary line and `asf approvals list`. A follow-up card is the groom's to write.
- **A content-reading boundary.** The recognisers match tool names, paths and command text. A
  determined agent can phrase a command the patterns miss; Constitution §3 says *a capability
  list is not a boundary*, and this is a tripwire for the honest path plus a record, not a
  sandbox. Deny rules and redaction are F-0062's; secret scanning is F-0069's.
- **Updating `docs/CONSTITUTION.md` §5's TRIGGERS line** from *recited only* to *checked*. The
  constitution is the amendable set this feature itself puts behind `merge_amendable_set`; the
  line is changed by a person once the feature is on the trunk.
- **Budgets and spend accounting.** `spend_money` refuses the action; it does not meter money.
- **Any change to `ci.budgets`, the worker pool or quotas.**

### Choices

| # | Choice | Chosen | Against | Why |
| --- | --- | --- | --- | --- |
| D1 | Where the list of classes lives | A closed catalogue in `asf/approvals.py`; the yaml maps names from it, and an unknown name is a config error | Classes defined freely in the yaml | A class nobody recognises is a mapping nobody reads — the card's first acceptance line would pass on a class that does nothing. The recognisers are code, so the names they answer to are code. The levels are data |
| D2 | The yaml's shape | A flat map `class: level`, plus an optional `approval_signals: {class: {paths: [...], commands: [...]}}` | Each class a map with its level and its recognisers inline | The card asks for "one file" a human widens or narrows; a flat map is that edit in one word. Recognisers change rarely and are product-bound (a customer database, a billing CLI), so they get their own key rather than cluttering the matrix |
| D3 | A class the yaml does not map | Takes the catalogue default (the prose made code: money, production, security, customer data, legal, new Epics → `human-now`; merging routine work and filing bugs → `auto`). `asf doctor` names every unmapped class | Unmapped → `human-now` (fail closed); unmapped → a load error | Every existing product file has no `approvals:` or a partial one. Failing closed would make `merge_routine_pr` `human-now` and hold every landing on upgrade; a load error would stop every tick. The defaults are exactly today's standing authority, so an unmapped product behaves as the prose says |
| D4 | Whose actions the hook governs | Only a factory session: `ASF_JOB` set in the hook's environment. Without it the hook exits 0 | Every session that loads the settings | The matrix is the factory's authority. A person at the keyboard is the approval; refusing them their own repository would be noise |
| D5 | What `groom` means | The hook refuses, the hold is recorded, the item is parked, and the tick raises it as one summary line rather than a `NEEDS OPERATOR` line per hold | `groom` lets the action through and reports it after | The card says the hooks refuse; an allowed-then-reported level is `auto` with a log. Refusing at both levels and differing only in when a person is asked keeps the ladder `auto < groom < human-now` one-dimensional |
| D6 | Where the hook is installed | Every worker account's user-level runtime settings (`<config_dir>/settings.json`, else the home's runtime settings), by `asf hooks install` | The product repo's settings file, like the rule hooks | A repo-level file must be committed to reach a worktree, and a branch can edit it — the one file that switches the hook off would be inside the footprint it guards. The account's settings are outside every worktree, and D4 keeps the entry inert for a person's own sessions |
| D7 | The hook's failure mode | Fail closed for a factory session: an exception while classifying a `Bash`, `Write`, `Edit`, `MultiEdit` or `NotebookEdit` call exits 2 with `approvals hook error: <why>; not a refusal — retry` — the hook broke, it did not refuse, and the call is worth retrying (B-0125); the traceback goes to the hook’s own log and a run of them into the tick’s raise; a matrix that fails validation makes every classified action `human-now` | Fail open (exit 1, which the runtime treats as non-blocking) | A boundary that opens when it breaks is not one (Constitution §3). A broken hook is loud: every session prints it, and the tick's raise names it |
| D8 | The matrix editing itself | A write to `~/.ASF/products/*.yaml` or `~/.ASF/config.yaml` from a factory session is always refused, whatever the matrix says. It is not a class | A class `edit_operator_config` in the matrix | A class could be mapped `auto` in the very file it protects. Authority is widened by a person, in that file (the card), so the factory never writes it |
| D9 | Hold identity | `<item>/<class>` — one open hold per item and class; a repeat refusal bumps its count | A fresh id per refusal | The operator answers "may F-0031 do X", not "may this one call". The id is typable, and the tick's line names exactly the item and the class the card asks for |
| D10 | Where the tick raises | At the start of the `wave` step, before it launches | A new tick step; the `health` step | The wave is the step that would relaunch a held item, so it is the one that must read the holds; the raise and the parking come from one read. A new step changes the step manifest every product declares against |
| D11 | Where the merge classes are read | In `run_product_harvest`, before a branch is landed or handed to the PR lane; a branch whose diff touches `conventions.amendable_paths` is `merge_amendable_set`, any other is `merge_routine_pr` | In the hook | Sessions do not merge; the tick does. The prior-art finding is *no session edits the amendable set unsupervised — it proposes, a person merges*; the gate belongs where the merge happens |
| D12 | The amendable set | A new `conventions.amendable_paths` list of globs, empty by default — a new field `amendable_paths: list` on the `asf.conventions.Conventions` dataclass (default `[]`), not a key left to fall into its `extra`; `asf doctor` warns when `merge_amendable_set` is mapped but the list is empty | Paths in code | Which files amend the factory's own rules differs per product. The isolation table puts conventions in the product file, and `asf/conventions.py` is the one place a convention's default is declared |
| D13 | How the hold ends | `asf approvals resolve <item>/<class> granted|done|dropped`. `granted` lets that item do that class from then on; `done` records that a person did it; `dropped` records that it will not be done. Any of the three un-parks the item | Editing the matrix as the only release | Widening the matrix grants a class to every item; the card's question is usually about one. Both remain: the file for standing authority, `resolve` for one item |
| D14 | Where holds are recorded | `~/.ASF/state/<p>/approvals.jsonl`, append-only, written by the hook, the harvest, the CLI and the tick | The record | The hook runs inside a session's worktree and cannot commit to the record. The isolation table puts in-flight state under `state/<product>`. The record gets events when the tick sees them (§4) |

## 2. The design

### 2.1 The catalogue — `asf/approvals.py`

```python
LEVELS = ('auto', 'groom', 'human-now')

@dataclasses.dataclass(frozen=True)
class ActionClass:
    name: str
    covers: str          # one line, printed by `asf approvals`
    default: str         # one of LEVELS
    read_by: tuple       # ('hook',) | ('harvest',) | ('hook', 'file_bugs') ...

CLASSES = (...)          # the nine rows below, in this order
```

| Class | Covers | Default | Read by | Built-in recognisers |
| --- | --- | --- | --- | --- |
| `spend_money` | buying, subscribing, raising a paid tier or a spend limit | `human-now` | hook | none — `approval_signals` only |
| `touch_production` | deploying, pushing to the trunk | `human-now` | hook | Bash: `git push` whose refspec targets the product's `main` (`main`, `HEAD:main`, `refs/heads/main` and the `<src>:` forms); `gh workflow run <deploy_sha.workflow>` when `deploy_sha.workflow` is set |
| `touch_security` | secrets, credentials, the runtime's hook and permission settings, the repo's git hooks | `human-now` | hook | paths: `.env`, `.env.*`, `*.pem`, `*.key`, `id_rsa*`, `id_ed25519*`, the git hooks dir `.githooks/*`, and the runtime settings globs `asf.hooks.RUNTIME_SETTINGS_GLOBS`; Bash: `gh secret`, `gh auth`, `git config core.hooksPath`, `--no-verify` |
| `touch_customer_data` | reading or changing customer records, exports, production databases | `human-now` | hook | none — `approval_signals` only |
| `touch_legal` | licences, notices, terms, privacy texts | `human-now` | hook | paths whose file name matches `LICENSE*`, `LICENCE*`, `COPYING*`, `NOTICE*`, `TERMS*`, `PRIVACY*` |
| `new_epic` | opening a new Epic | `human-now` | hook | Write of an `epics/*.md` file that does not exist yet, in a repository that is a record (`harvest.is_record_repo`); Bash: `asf new epic` |
| `merge_amendable_set` | landing a branch that touches the factory's own rules | `human-now` | harvest | the branch's changed files against `conventions.amendable_paths` |
| `merge_routine_pr` | landing any other finished branch | `auto` | harvest | every branch that is not `merge_amendable_set` |
| `file_bug` | filing or bumping a Bug | `auto` | hook, file_bugs | Bash: `asf new bug`; the tick's bug filer |

`RUNTIME_SETTINGS_GLOBS` is a new constant in `asf/hooks.py` (it does not exist there on
2026-09-22), the runtime adapter that `tools/check_conventions.sh` already exempts, so
`asf/approvals.py` carries no runtime path.

**Matching.** A path is made repo-relative against `git rev-parse --show-toplevel` of the call's
`cwd` (the `cwd` itself when that fails), POSIX-separated. A glob containing `/` matches the
whole relative path; a glob without one matches the file name. Both with `fnmatch.fnmatchcase`.
A command recogniser is a regular expression searched in the Bash `command` string.

**`approval_signals`** (new product key, a map, declared in `env.PRODUCT_FIELDS`):

```yaml
approval_signals:
  spend_money:
    commands: ['\bgh api\b.*\bbilling\b']
  touch_customer_data:
    paths: ['data/customers/*']
    commands: ['\bpsql\b.*\bprod\b']
```

Signals add to a class's built-ins; they never remove one. A signal under a class not in the
catalogue is a config error, like an unknown class in `approvals:`.

**`matrix(product)`** returns `{class: (level, source)}` for every catalogue class, `source` being
`yaml` or `default`. It raises `env.ConfigError` naming every unknown class and every level not
in `LEVELS`.

**`classify(product, tool_name, tool_input, cwd)`** returns `[(class, detail)]`, `detail` being
the matched path or the first 120 characters of the command. `Write`, `Edit`, `MultiEdit` read
`file_path`; `NotebookEdit` reads `notebook_path`; `Bash` reads `command`. Any other tool
classifies as nothing.

### 2.2 The matrix in the product file

`docs/products.example.yaml` — the existing block, completed and renamed to the catalogue
(`touch_prod_credentials` becomes `touch_security`, which covers it):

```yaml
# the approval matrix: every class of asf.approvals.CLASSES -> auto | groom | human-now.
#   auto       the factory acts
#   groom      the hook refuses; the item waits for the next groom
#   human-now  the hook refuses; the tick raises a NEEDS OPERATOR line every cycle until resolved
# An unmapped class takes its default (see `asf approvals`). Widen or narrow here, nowhere else.
approvals:
  spend_money: human-now
  touch_production: human-now
  touch_security: human-now
  touch_customer_data: human-now
  touch_legal: human-now
  new_epic: human-now
  merge_amendable_set: human-now
  merge_routine_pr: auto
  file_bug: auto
```

plus a commented `approval_signals:` block as in §2.1 and, under `conventions:`,
`amendable_paths: [rules/*, docs/CONSTITUTION.md]`. `sample/product.yaml` carries the same nine
lines, so the sample product's test run exercises a full matrix.

### 2.3 The hook — `asf hook approvals`

`asf/hooks.py` gains `BUILTIN = {'approvals': ('PreToolUse',)}`. `cmd_hook` runs a built-in by
name instead of looking for `tools/checks/<name>.sh`; the product comes from `--product`, else
`$ASF_PRODUCT`. `approvals.run_hook(stdin_text, environ, out=sys.stderr) -> rc`:

1. No `ASF_JOB` in `environ` → 0 (D4).
2. Parse stdin. A path under `env.ASF_HOME`'s `products/` or its `config.yaml`, as a
   `Write`/`Edit`/`MultiEdit` target or named in a `Bash` command next to a writing token (`>`,
   `tee`, `sed -i`, `perl -i`, `cp`, `mv`, `rm`) → 2 with
   `REFUSED operator config — the factory never edits its own authority (products/<p>.yaml)` (D8).
3. `classify`. Nothing matched → 0.
4. `matrix(product)`; on `ConfigError`, every matched class is `human-now` and the message says
   why (D7).
5. The item: the ledger's `item` for `ASF_JOB` (P3), else `ASF_JOB` itself.
6. For each matched class, in catalogue order: `auto` → continue. A hold `<item>/<class>` whose
   latest resolution is `granted` → continue. Otherwise append a `refused` line (§4) and fail.
7. Any failure → exit 2, one stderr line per refused class:

```
REFUSED touch_production (human-now) on F-0031 — git push origin HEAD:main
  This action needs a person (approvals: in products/<p>.yaml). Do not retry it or work around it.
  Print: NEEDS OPERATOR: F-0031 touch_production — asf approvals resolve F-0031/touch_production granted|done|dropped
  and carry on with every part of the job that does not depend on it.
```

Any exception in steps 2–7 → exit 2, `approvals hook error: <why>; not a refusal — retry` (D7).

**Install.** `hooks.install` always adds `('PreToolUse', 'approvals')` — so the early return
`hooks: 0 rules declare a hook` no longer applies to it — and writes that entry, with no
`--product` (the session's `$ASF_PRODUCT` names it), into the user-level settings of every
account in `config.yaml` `worker_pool.accounts`: `<config_dir>/settings.json`, else the home's
runtime settings. The merge is the existing `hooks.merge`: idempotent, unrelated keys untouched.
One account serves several products, so its entry cannot carry `--product`; today
`hook_command` always appends `--product <p>` and `_is_ours` only recognises that form, so both
gain the product-less form when `product` is `None` (`<asf> hook approvals`, matched by
`(^|/)asf hook approvals$`). The rule hooks keep going to the product repo as today. The message becomes
`hooks: <n> rule hooks in <repo settings>; approvals in <k> worker accounts`.

### 2.4 The tick

**The raise and the parking** — `approvals.open_holds(product)` folds the ledger to the holds
whose latest `refused` has no later `resolved`. At the start of `step_wave.run`:

- one line per open `human-now` hold, oldest first:

  ```
  NEEDS OPERATOR: held touch_production on F-0031 — git push origin HEAD:main — asf approvals resolve F-0031/touch_production granted|done|dropped
  ```

- one line when any `groom` hold is open: `approvals: <n> held for groom — asf approvals list`;
- a `held` event (§4) for every hold not yet announced, and a `hold-resolved` event for every
  hold resolved since it was announced; the tick marks both in the ledger so each is emitted once;
- a launching row whose `item_id` has an open hold of either level is not launched. It prints
  `waits    <job> <item> — held <class> (<level>)` like the feeder's other waits.

**The merge classes** — in `run_product_harvest`, after `commits_name_item` and before the
`LANDING_PR` / `land_ff` branch: the changed files are
`git diff --name-only origin/<main>...origin/<branch>`; any match in `amendable_paths` makes the
class `merge_amendable_set`, else `merge_routine_pr`. Not `auto`, and no `granted` hold for the
branch's item and that class → append a `refused` line (`tool: harvest`), print
`held <branch>: <class> (<level>) — <first matched file or "routine">`, result `held`. No
correction round: the branch is not wrong, it is waiting for a person, so `hold_with_correction`
is not called and the feeder sends nothing back to the session.

**The bug filer** — both of the tick's call sites, `run_step0` and `step_daily.parts`'s
`file-bugs` part, pass `file_bug`'s level to `cmd_file_bugs` as `file_bug_level`; the check lives
in `cmd_file_bugs` itself, so neither path files around it. A namespace without the attribute —
the operator's own `asf file-bugs` — is `auto`, since a person at the keyboard is the approval
(D4). Not `auto` → no Bug is filed or bumped; one line per signature it would have filed,
`held file_bug on <signature> — widen approvals: file_bug in products/<p>.yaml`, and on
`human-now` the line is prefixed `NEEDS OPERATOR: `. No ledger line: the next tick recomputes
the same signatures, so the line recurs by itself until the level changes.

### 2.5 The operator's side

- `asf approvals [--product p]` — the effective matrix as a table:
  `class | level | from (yaml|default) | read by | recognisers (built-in + signals)`.
- `asf approvals list [--product p]` — open holds: `hold | level | first | last | count | detail`.
- `asf approvals resolve <item>/<class> granted|done|dropped [--product p]` — appends a
  `resolved` line; exit 2 when the hold is not open.
- `asf doctor` gains a row `approvals`: fail on an unknown class or level; warn (ok with detail)
  naming every unmapped class, every `human-now`/`groom` class with no recogniser at all
  (`spend_money` and `touch_customer_data` without signals), `merge_amendable_set` mapped with an
  empty `amendable_paths`, and a worker account whose settings lack the approvals entry.

## 3. Acceptance tests

Every block runs from the root of this repository and needs nothing but `python3` (3.11+) and
`git`. The unit blocks live in a new `tests/test_approvals.py`, so the pre-commit gate
(`python3 -m unittest discover -s tests`) runs them on every commit.

**A1 — every action class is named and mapped** (card acceptance 1).

```bash
python3 -m unittest -v \
  tests.test_approvals.CatalogueTest.test_every_class_is_named_and_mapped_in_the_example_and_sample \
  tests.test_approvals.CatalogueTest.test_every_class_has_a_read_point_and_a_known_default \
  tests.test_approvals.MatrixTest.test_unmapped_class_takes_its_catalogue_default \
  tests.test_approvals.MatrixTest.test_unknown_class_or_level_is_a_config_error \
  tests.test_approvals.MatrixTest.test_signal_under_an_unknown_class_is_a_config_error
```

- the example's and the sample's `approvals:` keys equal `[c.name for c in CLASSES]` and every
  value is in `LEVELS`;
- every class has a non-empty `read_by` drawn from `hook`, `harvest`, `file_bugs`, and its
  default is in `LEVELS`;
- a product mapping only `merge_routine_pr: groom` gets `groom` for it and the catalogue default
  for the other eight, each with source `default`.

**A2 — a hook refuses an action its class marks `human-now`** (card acceptance 2), end to end
through the command the runtime calls:

```bash

  > "$H/state/demo/sessions.jsonl"

rc=0; out="$(printf '%s' "$CALL" | ASF_PRODUCT=demo ASF_JOB=code-F-0031 python3 -m asf.cli hook approvals 2>&1)" || rc=$?
[ "$rc" -eq 2 ] || { echo "human-now: expected rc 2, got $rc"; exit 1; }
printf '%s' "$out" | grep -q 'REFUSED touch_production (human-now) on F-0031' || { echo "no refusal line: $out"; exit 1; }
grep -q '"hold": "F-0031/touch_production"' "$H/state/demo/approvals.jsonl" || { echo 'no hold in the ledger'; exit 1; }
rc=0; printf '%s' "$CALL" | ASF_PRODUCT=demo python3 -m asf.cli hook approvals || rc=$?

printf 'product: demo\nmain: main\napprovals:\n  touch_production: auto\n' > "$H/products/demo.yaml"
rc=0; printf '%s' "$CALL" | ASF_PRODUCT=demo ASF_JOB=code-F-0031 python3 -m asf.cli hook approvals || rc=$?
[ "$rc" -eq 0 ] || { echo "auto: expected rc 0, got $rc"; exit 1; }
rm -rf "$H"; echo ok
```
