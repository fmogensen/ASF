# F-0093 — A third model label, `cheap`, and a measure that argues for it

Epic: E-0001 — ASF 0.1 — a working factory. Branch: `spec/F-0093`.

Measured 2026-09-23 over ASF's own build, as minutes of session time per landing:

| kind | model | runs | hours | landed | min/landing |
| --- | --- | --- | --- | --- | --- |
| plan | opus | 11 | 5.8 | 11 | **32** |
| correct | sonnet | 39 | 19.7 | 16 | 74 |
| fix-bug | sonnet | 49 | 53.8 | 36 | 90 |
| adjudicate | opus | 35 | 24.1 | 16 | 90 |
| coder | sonnet | 38 | 52.2 | 19 | 165 |
| spec | opus | 45 | 39.9 | 12 | **200** |

The card reads two findings off that table, and this spec takes both at their word.

The labels are mostly right and the counts are wrong. Planning on the expensive model is the most
efficient thing the factory does — 32 minutes a landing, eleven for eleven — so `plan` does not
move. Specs on the same model are the least efficient, and the cause is the count: 45 runs for 12
landings means a Feature's spec is written from scratch again and again, each run paying the full
price of a document that already exists. So `spec` does not move either; what moves is what the
second run is *told to do* (§2.6).

The pool has two tiers, `heavy` and `light`, and there is nothing below them. `rebase`, `close`
and the clerical half of the groom day are bookkeeping — a merge conflict resolved, a branch
deleted, a card typed `feature` or `bug` — and they all run on the model that writes code. This
spec adds a third label, `cheap`, and routes those three at it.

The larger point the card makes about file reading is deliberately **not** here: the cheap way to
read a file is code, not a cheaper model. That is [[F-0022]], the preamble, and it keeps its own
rank.

## 1. Decisions

### What already holds (verified in this worktree at `b9b8d34`)

- **The two labels are already an indirection, not a model id.** `asf/briefs/build.py:41-43` —
  `HEAVY = 'heavy'`, `LIGHT = 'light'`, with the comment *"``asf.workers`` maps them onto real
  model names, so no vendor's model id is ever written down here."* `DEFAULT_MODELS`
  (`build.py:50-52`) maps all twelve kinds onto one of the two; `model_for(product, kind)`
  (`build.py:164-166`) lets `conventions.models.<kind>` override per kind;
  `spawn.model_arg(model, cfg)` (`asf/workers/spawn.py:251-260`) resolves the label through
  `worker_pool.models` and raises `SpawnError: NEEDS OPERATOR: worker_pool.models has no entry
  for <label>` when it is unmapped. A third label is therefore an addition to three tables, not a
  new mechanism.
- **`rebase` and `close` already have their own kinds and rows.** `DEFAULT_MODELS` gives both
  `LIGHT`; `asf/feeder/rows.py:287` and `:291` mint `brief_kind='close'` and
  `brief_kind='rebase'`; `asf/briefs/templates/close.md` and `rebase.md` exist.
- **A spec row is already gated on `decided: true`.** `asf/feeder/rows.py:316-318` —
  `feats = [f for f in ix.of_type(items, 'feature') if f.get('decided') is True and is_open(f)
  and not f.get('blocked')]`. Every Feature row, `CARD → SPEC` included, comes off that list. The
  first half of the card's spec-discipline bullet needs no change; §2.6 is only the second half.
- **The two spec rows are already distinct.** `rows.py:334` mints `CARD_SPEC` for a Feature at
  stage `card` (`reason='decided card, no spec'`); `rows.py:337` mints `STARVED_SPEC` for stage
  `spec-draft` / `spec-review` (`reason='<stage>, no session'`). Both hand the session the same
  `brief_kind='spec'` and so the same template, which opens *"Write the spec and nothing else"*.
  The distinction the record already draws is the one §2.6 spends.
- **The groom session is not purely judgement.** `rows.py:415-452` mints one `GROOM_ADJUDICATE`
  row per groom day carrying every open question as `open_questions`. Those lines are of two
  shapes (`asf/groom/policy.py:24`): an id line, `- [ ] <id> … → answer: ____`, and an intake
  line, `- [ ] inbox:<file> … → answer: ____` (`asf/groom/inbox.py:180-181`,
  `TOKEN_PREFIX = 'inbox:'`). `templates/groom.md` gives the second its own paragraph — read the
  card in the intake directory, answer `feature`, `bug <line>`, `parent <id>`, `S1`/`S2`/`S3`.
  Typing an untyped card is clerical; both halves run today at `DEFAULT_MODELS['groom'] = HEAVY`.
- **One answers file per day, and the readers assume it.**
  `asf/groom/groom.py:616` and `asf/tick/step_daily.py:27` each hold
  `^(\d{4}-\d{2}-\d{2})\.answers$`; `step_daily.pending_answers_files` already applies *every*
  unapplied file oldest-first, and `carry_staged_answers` (`step_daily.py:73-96`) rebuilds the
  name as `f'{date}.answers'` from the worktree. Two groom sessions on one day need two files, so
  the shape of the name is what changes, not the number of readers.
- **The sessions stream already carries what the measure needs.** `metrics.SCHEMAS['sessions']`
  (`asf/metrics/metrics.py:120-127`) types `kind`, `model`, `minutes` and `result` on every row.
- **`asf improve` is specified and not built.** `docs/specs/f-0091.md` defines
  `asf/improve/measure.py` (`Run`, `ended_runs`, `table`), `asf/improve/classes.py` and
  `asf/improve/improve.py`, with `landed = bool(run.get('harvested'))` and per-kind /
  per-model blocks already in `table`. There is no `asf/improve/` directory in this worktree.
  §2.5 is an addition to those three modules and is the one part of this spec that waits.

### In / out

**In.**

1. A third label `cheap` beside `heavy` and `light`, resolved through `worker_pool.models`, with
   a documented fallback when the operator has not mapped it (§2.1, §2.2).
2. `rebase` and `close` default to `cheap`; `plan` stays `heavy`; nothing else moves (§2.3).
3. The groom day splits into a clerical row on `cheap` and a judgement row on `heavy`, each with
   its own answers file (§2.4).
4. `conventions.models.<kind>` documented as the operator's override, with the measured table in
   the docs so a change can be argued against numbers (§2.5.1).
5. `asf improve` reports minutes-per-landing per kind and per (kind, model), and raises a card for
   a kind whose ratio worsens by half (§2.5.2) — **after F-0091**.
6. A second spec run on a Feature amends the spec it finds instead of writing a new one (§2.6).

**Out.**

- **Reading files with a cheaper model.** The card is explicit that the cheap way to read a file
  is code, not a smaller model. That is [[F-0022]] and it is not touched here.
- **A fourth label, or a per-account model policy.** Three labels is what the card asks for.
- **Naming a vendor's model id anywhere in the tree.** `build.py:41-42` forbids it and
  `tools/check_generic.sh` is the gate; `cheap` is a label like the other two, and the only place
  an id is written is the operator's `worker_pool.models`.
- **Backfilling `improve/history.jsonl` with minutes-per-landing for weeks already past.**
  F-0091's first run is the baseline; the regression class needs two runs and gets its first
  verdict a week after the second.
- **The measured target itself** — *Opus hours down by a third with no drop in landings per day*.
  That is read off `asf improve` a week after this lands; it is the card's acceptance, not a test
  this spec can run.

### Choices

| # | Chosen | Against | Why |
| --- | --- | --- | --- |
| D1 | A third **label**, `cheap`, in the same `worker_pool.models` table as `heavy` and `light` | A numeric tier (`models: [id, id, id]` ordered by price); a per-kind model id in `conventions.models` | The two labels are already the indirection the tree is built on, and `check_generic.sh` forbids a vendor id in a tracked file. A third row in a map nobody has to re-learn beats a second grammar. An ordered list would make the operator's config positional, and a positional config is the kind of thing an operator gets wrong once and debugs for an hour. |
| D2 | "Defaults to the pool's smallest model" is implemented as **falls back to the `light` entry when `cheap` is unmapped** | Shipping a default model id for `cheap`; refusing to spawn until the operator maps it; picking the "smallest" id by a name heuristic | The config carries a label→id map and no size ordering, so the tool cannot know which mapped id is smallest without either reading a vendor's price list or guessing from the id string — and writing either into the tree is exactly what D1 forbids. Refusing to spawn would break every existing pool on upgrade, for a routing change that is meant to save money and not stop the factory. `light` is the smallest tier the config actually declares, so it is the honest answer; `asf doctor` then tells the operator what they are leaving on the table (§2.2). |
| D3 | `plan` stays `heavy`; `spec` stays `heavy` | Moving `spec` to `light` on the strength of its 200 min/landing | The table's own argument. `plan` is the factory's cheapest landing at 32 min and moving it down would be reading the column backwards. `spec` is the most expensive, but 45 runs for 12 landings says the cost is the *count*, not the model — a cheaper model that still rewrites the document from scratch buys a worse spec at the same total price. §2.6 attacks the count. |
| D4 | The groom day becomes **two rows and two sessions**, split on the line's token (`inbox:` → clerical) | One session with a cheaper model for the whole day; one session that decides per line which half it is in; keeping one row and moving `groom` to `cheap` | The split is already in the data — `policy.py:24` distinguishes the two tokens, `templates/groom.md` already gives them separate instructions, and `inbox.TOKEN_PREFIX` is the test. One cheap session for the whole day would rule on policy questions with a bookkeeping model, which is the failure the card is trying to avoid in the other direction. A session that self-selects would still be launched on one label. |
| D5 | Two answers files a day, `<date>.answers` and `<date>.clerk.answers`, both applied | Serialising the two rows so the clerk finishes before the judge launches; one file two sessions append to | `pending_answers_files` already applies every unapplied file oldest-first (P3), so two files cost one widened regex. Serialising would add a whole session's latency to every groom day. Two sessions appending to one path in two worktrees is a lost write. |
| D6 | The second spec run gets its **own brief kind**, `spec-amend`, with its own template | A flag on the `spec` template; a `correct` row for the spec lane; telling the spec brief to check whether the file exists | The feeder already mints two different rows for the two cases — `CARD_SPEC` at stage `card`, `STARVED_SPEC` at `spec-draft`/`spec-review` (`rows.py:334`, `:337`) — and they only look the same because both spend `brief_kind='spec'`. Giving the second its own kind makes the distinction a thing the record carries, the ledger counts and `improve` can measure, instead of a sentence inside a document. A `correct` row is the review lane's and means "a reviewer said this is wrong"; a starved spec is a relaunch, not a correction. |
| D7 | The regression class compares **this run's ratio against the previous run's**, from `improve/history.jsonl`, and needs ≥ 5 landings on each side | Comparing against the table in this document; a rolling mean over four weeks | F-0091 already writes `history.jsonl` for exactly this and already renders movement against `before`. A frozen baseline goes stale the week after it is written. The sample floor is there because 1 landing becoming 2 is a 100 % "regression" and a card nobody should have to read. |
| D8 | The measured table lives in `docs/config.example.yaml`, beside the `worker_pool` block it argues about | A row in `docs/decisions/`; a section in `docs/CONSTITUTION.md`; a comment in `build.py` | The card asks that a change be arguable against numbers, and the place an operator is standing when they change a model label is the config file. `docs/` is where both example files already carry their reasoning as comments. |

## 2. The design

### 2.1 `asf/briefs/build.py` — the third label

```python
#: The operator's three model labels. ``asf.workers`` maps them onto real model names, so no
#: vendor's model id is ever written down here. ``CHEAP`` is the bookkeeping tier: a rebase, a
#: close, the groom's clerical pass — work with a right answer that no judgement reaches.
HEAVY = 'heavy'
LIGHT = 'light'
CHEAP = 'cheap'

KINDS = ('spec', 'spec-amend', 'plan', 'coder', 'review', 'fixer', 'rebase', 'close',
         'adjudicate', 'fix-bug', 'correct', 'groom', 'groom-clerk', 'reshape')

DEFAULT_MODELS = {'spec': HEAVY, 'spec-amend': HEAVY, 'plan': HEAVY, 'adjudicate': HEAVY,
                  'review': HEAVY, 'coder': LIGHT, 'fixer': LIGHT, 'fix-bug': LIGHT,
                  'correct': LIGHT, 'groom': HEAVY, 'reshape': HEAVY,
                  'rebase': CHEAP, 'close': CHEAP, 'groom-clerk': CHEAP}
```

`model_for(product, kind)` is unchanged: `conventions.models.<kind>` first, then this table, then
`LIGHT` for a kind the table does not name. `ID_RANGE_KINDS` gains `spec-amend` (an amendment may
still mint a Story) and does **not** gain `groom-clerk` — the clerk types cards that already
exist and mints nothing.

### 2.2 `asf/workers/spawn.py` — the fallback, and what the operator is told

`model_arg` gains one clause, and only one:

```python
#: A label with no entry of its own falls back to this one. ``cheap`` is new in F-0093 and a pool
#: configured before it has no entry; falling back to ``light`` keeps that pool running at the
#: price it already paid, where refusing would stop the factory over a saving.
MODEL_FALLBACK = {'cheap': 'light'}


def model_arg(model, cfg=None):
    """``worker_pool.models: {heavy: <id>, light: <id>, cheap: <id>}`` maps a row's model label.
    A label with no entry falls back per :data:`MODEL_FALLBACK`; a label with neither is refused —
    the literal label is not a model id the runtime knows, and the session dies at once."""
    if not model:
        return None
    table = (((cfg or {}).get('worker_pool') or {}).get('models')) or {}
    if model not in table:
        alt = MODEL_FALLBACK.get(model)
        if alt and alt in table:
            return table[alt]
        raise SpawnError(f'NEEDS OPERATOR: worker_pool.models has no entry for {model} '
                         '— add it to config.yaml')
    return table[model]
```

The fallback is silent at spawn time — a warning per launch is noise — and loud once, in
`asf doctor`, beside the other `worker_pool` advice at `asf/doctor.py:264`:

```
worker_pool.models has no `cheap` entry — rebase, close and the groom's clerical pass fall back
to `light`. Map it to your pool's smallest model to take the saving F-0093 measures.
```

This is an **advice** line, not a failure: a pool without the key is correctly configured, just
not cheaply. `doctor` says nothing when the key is present.

### 2.3 What routes where

| kind | before | after | why |
| --- | --- | --- | --- |
| `rebase` | light | **cheap** | a merge conflict resolved against the trunk; no design in it |
| `close` | light | **cheap** | a branch deleted, a card moved to Closed |
| `groom-clerk` | — (was part of `groom`, heavy) | **cheap** | typing an intake card `feature` or `bug` |
| `plan` | heavy | heavy | 32 min/landing, 11 of 11 — the table's own argument (D3) |
| `spec` | heavy | heavy | the count is the cost, not the model (D3, §2.6) |
| `spec-amend` | — (was `spec`) | heavy | an amendment argues with a reviewer; the same judgement |
| everything else | — | unchanged | the card says the labels are mostly right |

### 2.4 `asf/feeder/rows.py` — the groom day splits

`groom_row` becomes `groom_rows(index, product, busy, groom_state, inflight) -> [Row]`, returning
at most two rows. Everything that decides *whether* there is a groom session at all — the gate
(`groom_policy.groom_auto`), the live-session check, `groom_state['new']`, the attempt cap — is
unchanged and applies to the pair; the change is only how the day's lines are split between them.

```python
def _split_lines(lines):
    """A groom day's open question lines, partitioned into the clerical half and the judgement
    half. A line whose item token is ``inbox:<file>`` is a card intake could not type — a right
    answer read off the card, not a ruling. Everything else is a policy question."""
    clerk = [l for l in lines if _token(l).startswith(inbox_mod.TOKEN_PREFIX)]
    judge = [l for l in lines if not _token(l).startswith(inbox_mod.TOKEN_PREFIX)]
    return clerk, judge
```

- The judgement row is today's `GROOM_ADJUDICATE`: `brief_kind='groom'`, job `groom-<date>`,
  `answers_file` `<date>.answers`, `open_questions` = the judgement lines. It is **not minted**
  when the judgement half is empty — a day whose every open question is an intake card costs no
  heavy session.
- The clerical row is new: `kind=GROOM_CLERK`, `brief_kind='groom-clerk'`, job
  `groom-clerk-<date>`, branch as the groom row's, `answers_file` `<date>.clerk.answers`,
  `open_questions` = the intake lines. Not minted when there are none.
- Both carry the same `groom_date` and `groom_file`. `KIND_JOB_KEY` in `asf/tick/step_wave.py:32`
  gains `'groom-clerk': 'groom_date'`, and the live-session check widens to both job names, so
  neither row is re-offered while its own session runs.
- `hold_unlanded` (`rows.py:452`) already leaves `GROOM_ADJUDICATE` alone because the row speaks
  for a day, not for the item it names; `GROOM_CLERK` joins it in that `keeps` clause.
- `add_dirs_for` (`build.py:180-186`) grants the groom and answers directories for
  `kind == 'groom'`; the condition becomes `kind in ('groom', 'groom-clerk')`. The clerk needs the
  intake directory most of all — it is the directory its cards are in.

`asf/briefs/templates/groom-clerk.md` is the intake paragraph of `groom.md`, alone, with the four
things that are never the session's (licence, money, security, anything the customer sees)
carried over verbatim and the same `NEEDS OPERATOR` rail. `groom.md` loses the intake paragraph.
Both keep *THE REPOSITORY IS NOT YOUR WORK*: an answers file is the only path an answer takes to a
card.

### 2.4.1 Two answers files a day

One regex, in one place, imported by both readers:

```python
# asf/groom/groom.py
#: A groom day's answers file. The optional part names which of the day's two sessions wrote it
#: (F-0093 §2.4): the judgement session writes ``<date>.answers``, the clerk ``<date>.clerk.answers``.
ANSWERS_FILE_RE = re.compile(r'^(?P<date>\d{4}-\d{2}-\d{2})(?:\.(?P<half>[a-z]+))?\.answers$')
```

`asf/tick/step_daily.py` drops its private `_ANSWERS_FILE_RE` and imports this one.
`pending_answers_files` already returns every unapplied match oldest-first and needs no change
beyond sorting on `(date, half or '')` so a day's two files apply in a stable order.
`_newest_answers_file` returns the newest *file*, not a rebuilt path. `carry_staged_answers`
(`step_daily.py:73-96`) stops building `f'{date}.answers'` and instead carries any file in the
ended session's worktree whose basename matches, to the same basename in the state dir.
`apply_groom_answers` is unchanged — it reads lines, and a clerk's line is in the same grammar.

### 2.5 The numbers

#### 2.5.1 `conventions.models` documented, with the table

`docs/products.example.yaml`, inside the `conventions:` block:


`docs/config.example.yaml`, beside the `worker_pool` block, gains the `models:` key it has never

followed by the six-row table from the head of this document, the two findings it supports in two

#### 2.5.2 `asf improve` — minutes per landing, and the regression class

**Requires F-0091 (P4).** Three small additions to modules that spec creates.

`asf/improve/measure.py`, in `table(runs)`:

- `by_kind[k]` gains `landed` (runs of that kind with `landed`) and `min_per_landing`
  (`Σ minutes of that kind / landed`, `None` when `landed == 0` — an infinity is not a number to
  rank on).
- `by_kind_model[(k, m)]` gains the same two keys. `by_model[m]` gains them too, so the card's
  second column is readable on its own.
- Both are pure arithmetic over the runs list, so both are unit tests with no clock and no file,
  exactly as F-0091 §2.1 requires of everything in `table`.

`asf/improve/improve.py` renders one more block in part (a) of `improve/<date>.md` — the card's
table, recomputed:

```
| kind | model | runs | hours | landed | min/landing |
| --- | --- | --- | --- | --- | --- |
| plan | claude-opus-5 | 11 | 5.8 | 11 | 32 |
```

one row per `(kind, model)` cell with at least one run, sorted by `min_per_landing` descending so
the worst is first and the argument is at the top. `None` prints `—`. The same rows go into the
`history.jsonl` line, under `by_kind_model`, so the next run can compare.

`asf/improve/classes.py` gains a fifth class:

| Class | Measured | Default threshold | Over? |
| --- | --- | --- | --- |
| `kind_ratio_regression` | for each kind with ≥ 5 landings in **both** this run and `before`: `now.min_per_landing / before.min_per_landing` | 1.5 | the largest such ratio, when any kind is at or above it |

- The sentence: `<kind> now takes <now> min per landing, up from <before> — <pct> % worse over
  one week (<landed> landings this week, <before_landed> last).`
- `excess_usd`, the rank key F-0091 sorts proposals by:
  `(now.min_per_landing - threshold × before.min_per_landing) × landed / 60 × usd_per_hour` of
  that kind — the money the extra minutes cost. Never negative; a kind exactly at 1.5 is worth $0
  and is printed, not proposed.
- The card it proposes is F-0091's shape unchanged: a `feature` under `improve.epic`, with
  `source: improve:kind_ratio_regression:<kind>` as the dedupe key, so a kind that stays bad for
  three weeks bumps one card's rank instead of filing three.
- Under the sample floor, or with no `before` (the first run), the class prints
  `not measurable — needs two runs with ≥ 5 landings` and proposes nothing.

### 2.6 A second spec run amends

`asf/briefs/templates/spec-amend.md` is a new template, and `rows.py:336-339` changes one word:
`STARVED_SPEC` mints `brief_kind='spec-amend'`. `CARD_SPEC` still mints `brief_kind='spec'`.

The two briefs differ in their DELIVERABLE paragraph and nowhere else — the same shape, the same
Stories block, the same rails:

> DELIVERABLE: `{spec_path}`, which **already exists on this branch**, amended in place.
>
> READ IT FIRST, in full. Your job is the difference between what it says and what the card now
> asks for — not a better spec. Change the sections that are wrong, add the sections that are
> missing, and leave every section that still holds exactly as it stands, down to its wording: a
> reviewer reads your diff, and a rewritten paragraph that says the same thing costs them the
> same attention as a changed one. A Story the `## Stories` block already carries keeps its line
> and its id. If, having read it, you believe the document should be replaced rather than
> amended, do not replace it — write one line saying so at the top of your report and amend what
> you can, because a rewrite is a decision the reviewer makes and not you.

The template's `{spec_path}` is the existing file, so the session cannot be confused about which
document it is amending; `asf/briefs/facts.py` already supplies the path. A `spec-amend` session's
REPORT keeps `kind: spec`, so the ledger's spec accounting is continuous across the change and the
measured table stays comparable week to week — `improve` learns the split from the *job name*
