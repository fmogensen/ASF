# F-0201 — a worktree is kept because the branch it landed on was deleted

Two plan worktrees of one worker lane, 293 MB each, sat under the product's `worktrees/`
directory nine hours after their heads were on `origin/main`, with no session on them. A code
branch never does this: when the lane lands it, the landing sha is written onto that session's own
row, and the next health pass reads `harvested` and takes the worktree (B-0049). The spec/plan
landing path writes the same sha onto a **different** row.

`asf.tick.land_spec.adopt` adopts an approved spec or plan branch that no run speaks for on a
*synthetic* run — job `land-spec-<id>` / `land-plan-<id>`, no session, no pid, no worktree
(`asf/tick/land_spec.py:109-120`, `asf/harvest/lane.py:2233-2245`). The lane lands that run and
marks **it** `harvested` (`asf/harvest/lane.py:1869-1877`), then deletes the branch from origin.
The session that wrote the document keeps a row with no `harvested`, and it is that row health
finds for the worktree — `by_worktree` maps a tree to the run that recorded it, and the synthetic
run recorded none (`asf/workers/lifecycle.py:539-548`).

So health asks its question of a run that did not land, about a branch that is no longer on
origin, and answers `keep: ended: branch not pushed` — every pass, forever. The local branch stays
with it (`prune_branches` skips a branch a worktree holds), and the job's `BACKLOG_ID_RANGE`
reservation is never released. Reproduced in this checkout, both landing shapes: see P12.

This card is not "make `land_spec` delete a directory". It is: **health's worktree scan decides on
what the tree holds — a clean tree whose HEAD is on the trunk is reaped whatever origin still has
— and the ledger's landing on a branch counts for the tree sitting on it, whichever run carries
the sha.**

| C2 | **The trunk is the evidence; origin's branch is only an explanation.** `reap_verdict` reaps a clean tree with commits whose HEAD is on the trunk whatever `remote_sha`/`head_on_remote` say, and reports the push state only when the tree holds something the trunk lacks. | Keeping the order and adding a fourth rule beside it. | Clean + `in_trunk` + `has_commits` **is** "nothing in this worktree exists only here" — the whole question. `remote_sha` was a proxy for that, and the landing path invalidates the proxy by deleting the branch (P3). "Any run ever" would reap a tree holding unlanded work on a branch that landed a round earlier. `prune_branches` already reads the same map for the same reason (P5), so this is one definition, not a second. |
| C4 | **Both new rules require a clean tree; neither requires anything of the pid beyond what is already checked.** A live run, or a run whose pid still answers, is decided before either rule is reached, and `uncommitted` keeps the tree with a reason that names the count. | Mirroring `landed(run)`'s unconditional reap, which takes a dirty tree too (B-0049). | The card says never a tree with uncommitted files and never a live session. `landed(run)` may be unconditional because the session's own row says its work reached the trunk; a *neighbouring* row's sha is weaker evidence about the files in this tree, and `remove_worktree` would refuse a dirty tree anyway — silently, as a `False` return, listed as `keep` with no reason. ### In, and out

**In.** `lifecycle.reap_verdict`'s order and its two new grounds; one new helper,
`lifecycle.branch_landings`; health's scan resolving each tree's branch once and passing that
branch's landing in; the docstrings that state the reap rules (`asf/workers/lifecycle.py`'s module
header §, `asf/workers/health.py`'s "three rules" list); the corrected B-0019 pin; unit tests for
the verdict and the helper, and an end-to-end test over the `land_spec` sequence, both shapes,
with the dirty / live / later-unlanded-run guards.

**Out.** (a) A run with no `ended` line on its row — it reads as a live session to both passes and
is health's judging half, not the reap's (P14). (b) `land_spec`/`Lane` behaviour: what they write
and when is unchanged (C1, C6). (c) The worktree reaper and its cap, the trash, the background
deleter and the doctor row (C9) — they see one fewer directory and nothing else. (d) Archived
(`superseded`) branches' worktrees (C5). (e) The `asf doctor` / `asf status` wording.

## The design

### 1. `asf/workers/lifecycle.py` — the branch's landings, and an order that reads the tree first

A new reader beside `by_branch`, next to `landed_earlier`:

```python
def branch_landings(path):
    """``{branch: the sha its latest run landed at}`` — the landings the ledger records, by
    branch. The *latest* run on each branch (:func:`by_branch`) and no earlier one: a branch whose
    last run carries no landing has work on it that has not landed, whoever landed it a round ago.
    An archival (:data:`NOT_A_LANDING`) is no landing.

    A lane branch is landed on the run the lane held for it, which is not always the run that
    owns the worktree sitting on that branch: an approved spec or plan the lane adopted lands on a
    synthetic run with no session and no worktree (:mod:`asf.tick.land_spec`), and the session that
    wrote the document keeps a row with no ``harvested``. This is how that tree's reap finds the
    landing (F-0201)."""
    return {b: r['harvested'] for b, r in by_branch(path).items()
            if r.get('harvested') and r['harvested'] not in NOT_A_LANDING}
```

`reap_verdict` gains one keyword — default `''`, so every existing positional call is unchanged —
and its tail is reordered so that what the tree holds is asked before what origin has:

```python
def reap_verdict(run, ev, main, alive, branch_landed=''):
    """``(what, detail)`` for a worktree: ``opening`` | ``keep`` | ``reapable``. ``run`` is None
    for an orphan; ``branch_landed`` is the sha the ledger says this worktree's *branch* landed at
    (:func:`branch_landings`), '' when it says none. Reapable under four rules — landed (the
    harvested sha on this run, B-0049); an ended-not-finished run with nothing in the tree to lose
    (B-0025); a clean tree with commits of its own whose HEAD is on the trunk, whatever origin
    still holds of its branch (B-0019, F-0201); a clean tree with commits whose branch the ledger
    landed under another run (F-0201)."""
    if run is not None and is_live(run):
        return ('opening', 'live session, no commits yet') if not ev.has_commits else (None, None)
    what = 'orphan' if run is None else 'ended'
    if run is not None and alive(run.get('pid')):
        return 'keep', f'{what}: pid still alive'
    if landed(run):
        return 'reapable', f'landed {run["harvested"]}'
    if run is not None and run.get('end_reason') != FINISHED:
        if ev.uncommitted == 0 and ev.in_trunk:
            return 'reapable', 'empty'
        return 'keep', f'{what}: session {run.get("end_reason")}, not finished'
    if ev.uncommitted:
        return 'keep', f'{what}: uncommitted changes'
    if not ev.has_commits:  # B-0019: a fresh branch is an ancestor of the trunk too — opening
        return 'keep', f'{what}: {"no commits yet" if ev.remote_sha else "branch not pushed"}'
    if ev.in_trunk:  # the trunk holds every commit this tree has: nothing here is only here
        return 'reapable', what
    if branch_landed:  # the lane landed this branch on another run — a rebase or a squash
        return 'reapable', f'landed {branch_landed} on its branch'
    if not ev.remote_sha:
        return 'keep', f'{what}: branch not pushed'
    if not ev.head_on_remote:
        return 'keep', f'{what}: local commits not pushed'
    return 'keep', f'{what}: not in origin/{main}'
```

Every string a test or a reader already knows is unchanged, and every keep reason is still reached
by the case it describes: `no commits yet` (pushed, never committed to), `branch not pushed` (no
commits and no remote, or commits the trunk lacks with no remote), `local commits not pushed`,
`not in origin/<main>`, `uncommitted changes`. The one behavioural difference is the pair the pin
names (P7): a clean tree with commits, on the trunk, whose branch origin no longer has — or whose
HEAD origin's branch does not contain — is now `reapable` rather than `keep`.

### 2. `asf/workers/health.py` — one branch per tree, resolved once

The scan reads the landings once for the pass, beside `owners` and `heads`, and resolves each
tree's branch before gathering — which is also the branch the orphan re-gather was there to find,
so that second `gather` goes away:

```python
    owners = lifecycle.by_worktree(registry)
    landings = lifecycle.branch_landings(registry)   # F-0201: landed on whichever run
    heads = lifecycle.RemoteHeads()
    for name in sorted(os.listdir(wdir)):
        ...
        s = owners.get(lifecycle.path_key(path)) or sessions.get(name)
        # an orphan carries no branch on its record: read the one checked out
        branch = (s or {}).get('branch') or _head_branch(path) or ''
        ev = lifecycle.gather(product, s or {'branch': branch}, alive=alive, worktree=path,
                              heads=heads)
        what, detail = lifecycle.reap_verdict(s, ev, product.main, alive,
                                              branch_landed=landings.get(branch, ''))
```

Nothing below it changes: `gone` stays `landed(s) or detail == 'empty'` (C7), the removal, the id
range release and the finding tuple are as they were, and `prune_branches` — already reading the
same landings, already skipping a branch a worktree holds — takes the freed branch later in the
same pass.

The module docstring's "three rules" list becomes four, in the order the code tests them, and says
why the third no longer asks origin anything: *harvest and the lane land a rebased or squashed tip
from their own throwaway checkout and delete the branch, so this worktree's HEAD may never appear
on origin at all — and when the branch was an approved spec or plan the lane adopted, the landing
sha is on the synthetic run that adopted it, not on the session's row.*

### What it looks like when it is there

A tick after the lane lands an adopted spec branch, the health step prints

```
reaped spec-f-0201 (ended)
pruned spec/F-0201 (landed by the lane (29ab973ae))
```

and, for a branch that landed as a squash (this HEAD no ancestor of the trunk),

```
reaped plan-f-0079 (landed 4d2e1b9c0 on its branch)
pruned plan/F-0079 (landed by the lane (4d2e1b9c0))
```

The directory is in `<state>/trash/` for the background deleter, the job's id range is released,
and the next `worktrees.reap` pass counts one fewer tree in `worktrees.json` — so `asf doctor`'s
`worktrees` row falls by one tree and its gigabytes without measuring anything. A tree with
uncommitted files, a live session, an alive pid, or a newer run on its branch that has not landed
is listed exactly as it is today, with the reason that keeps it.

What each must assert:

`ALandingOnTheBranch`
* `branch_landings` over a written registry: a branch whose latest run carries `harvested` maps to
  that sha; a branch whose latest run is a *newer* run with no `harvested` is **absent** even
  though an earlier run on it landed (C3); a branch whose latest run carries `superseded` is
  absent (C5); a branch nobody landed is absent.
* finished run, `Evidence(remote_sha='', head_on_remote=False, has_commits=True, in_trunk=True)` →
  `('reapable', 'ended')`; the same with `uncommitted=1` → `('keep', 'ended: uncommitted
  changes')`; with `has_commits=False` → `('keep', 'ended: branch not pushed')`.
* finished run, `Evidence(has_commits=True, in_trunk=False)`, `branch_landed='4d2e1b9c0'` →
  `('reapable', 'landed 4d2e1b9c0 on its branch')`; the same evidence with `branch_landed=''` →
  `('keep', 'ended: branch not pushed')`; with `remote_sha='s', head_on_remote=True` and no
  landing → `('keep', 'ended: not in origin/main')`; with `uncommitted=1` and the landing →
  `keep`.
* a live run, and a run whose pid answers, are never `reapable` under any `branch_landed`.
* the same three orphan strings as today with `run=None`: `orphan: branch not pushed`,
  `orphan: no commits yet`, and `('reapable', 'orphan')` when the trunk holds its commits.

`LandedByAnotherRunReapTests` (its own `land_from_another_run` helper: push the branch,
fast-forward `main` onto it **or** land a squash of its tree, delete the branch from origin, and
write `harvested` on a later row named `land-spec-<id>` for the same branch — P3, P12)
* fast-forward shape: the first `health(fix=True)` after the landing returns
  `('spec-f-0201', 'reaped', 'ended')`, prints `reaped spec-f-0201 (ended)`, the worktree is gone,
  the local branch is gone from the checkout, and the job's id range is no longer reserved.
* squash shape: `('plan-f-0201', 'reaped', 'landed <sha> on its branch')`, tree and branch gone.
* the same fast-forward shape with one untracked file in the tree: `('spec-f-0201', 'keep',
  'ended: uncommitted changes')`, the tree still there.
* a live session on that branch (no `ended` line, `alive` answering its pid): nothing `reaped` or
  `reapable` for it, the tree still there.
* a **newer** session on the same branch with a pushed commit the trunk lacks, after an earlier
  landing on it: `keep`, both trees still there (C3).
* before this change, the first two cases are `('…', 'keep', 'ended: branch not pushed')` with the
  tree and the branch still there — the assertion that fails today (P12).

## Records

Nothing new is written to the session registry, the record or the product yaml (C6). What the
change moves:

* **The findings and the printed lines of the health step** — one `('<name>', 'reaped', 'ended')`
  or `('<name>', 'reaped', 'landed <sha> on its branch')` tuple per tree taken, printed as
  `reaped <job> (<detail>)`; the `('<branch>', 'pruned', …)` line `prune_branches` then writes for
  the freed branch. No reader parses either detail (P10).
* **The worktree, into `<state>/trash/<name>`**, and `git worktree prune` in the product's
