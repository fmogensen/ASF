# F-0291 — three promises the product has already written down and does not yet keep

Three hardening passes each ended one step short of the thing they established, and each left the
evidence of it in the tree:

* **The one id grammar.** `asf/record/core.py:45` says every parser reads `\d{4,}`, and
  `tests/test_id_pattern.py` holds the line — with eleven sites **allowlisted** out of it. Four of
  them are the package's own (`asf/record/ingest.py:633`, `asf/harvest/lane.py:275`,
  `asf/workers/runtime.py:772`, `asf/scorecard/score.py:30`), each carrying a comment naming the
  workstream that would swap it. Three of the four do not read a five-digit id at all (P4, P5, P7)
  — this session's own block is `S:75204-75253`.
* **The heartbeat belongs to the runtime.** Every brief says so in its tail
  (`asf/briefs/build.py:109-112`): *never run a command in the background*. The local lane's
  HEARTBEAT block then tells the session, as its **very first command**, to `nohup` a loop
  (P10, P11) — although the local lane already reads liveness from the job log and says so in the
  code that does it: `no beat needed` (P12).
* **A `Proves:` line on a Story nobody minted proves nothing.** F-0285 built the refusal, its
  rendering and its tests (P15), and every spec brief already promises it to the session
  (`asf/briefs/build.py:706-711`: *"a `Proves:` line naming it proves nothing
  (`Not proved: unknown story`)"*). Nothing in `asf/` passes `known=`, so no claim is ever refused
  for it (P16) and the line never appears on a pull request.

None of the three is a new rule. Each is the last commit of a rule the product has already made,
and the cost of leaving them is that the written rule and the running code disagree — which is the
expensive kind of leftover, because the next reader has to measure which one is true.

## The design

Four files in the package, plus the ratchet and three test modules. No new file, no new function in
the record, no signature change outside `commits_note`.

### 1. The four sites — one grammar, four contexts

Each gains `ID_DIGITS` from `asf.record.core` and spells nothing itself.

| Site | Today | After |
|---|---|---|
| `asf/record/ingest.py:633` | `r'\bmerged into ([Tt]-\d{4})\b'` | `rf'\bmerged into ([Tt]-{ID_DIGITS})\b'` |
| `asf/harvest/lane.py:275` | `r'\b([A-Za-z]+-\d{4})\b'` | `rf'\b([A-Za-z]+-{ID_DIGITS})\b'` |
| `asf/workers/runtime.py:772` | `r'([a-z])-(\d{4})$'`, `re.I` | `rf'([a-z])-({ID_DIGITS})$'`, `re.I` |
| `asf/scorecard/score.py:30` | `r'^(.*?)-[a-z]-\d{4}'` | `rf'^(.*?)-[a-z]-{ID_DIGITS}'` |

`ingest` already imports from `asf.record.core` (`:24`) — `ID_DIGITS` joins that line. The other
three do not; each takes the import the way its module takes its other cross-package reads
(`asf/scorecard/facts.py:26` is the house precedent: `from asf.record.core import ID_DIGITS`).
`asf.record.core` imports only `asf.record.frontmatter`, so none of the three can cycle.

`ALLOWED` in `tests/test_id_pattern.py` loses exactly those four keys, and the comments above them
— the ones naming the workstream that would swap each — go with them. The remaining seven keys and
both scan tests are untouched. `EveryParserReadsAFiveDigitId` gains four cases, one per site, each
asserting the five-digit answer and keeping the four-digit one.

`asf/factory_only.py:29-31`'s comment stops claiming `lane.ITEM_ID_RE` cannot read a five-digit id;
its `ITEM_RE` does not change.

### 2. The local HEARTBEAT block — the runtime reports its own liveness

One line in `asf/workers/runtime.py:670-672`:

```python
    return text.rstrip('\n') + '\n' + '\n'.join(
        heartbeat.brief_lines(job.name, job.session or '', beat,
                              runtime_liveness=True)) + '\n'
```

and the sentence in `brief_text`'s docstring that describes what the block is. `brief_lines` itself
does not change: the session is handed the text that already exists for a runtime that reports its
own liveness (`asf/workers/heartbeat.py:199-208`) — *"Liveness comes from the runtime … Do NOT start
a detached or background process"*, then the commit-and-push rule and the limit.

Two docstrings follow the fact: `heartbeat`'s module docstring, whose **The beat** paragraph says
the loop is in *"every brief launched with the heartbeat on"* (it is the actions lane's now), and
`brief_lines`' own, which names claude-remote as the runtime-liveness case and should name the local
lane beside it.

What the local lane then rests on, all of it already there (P12, P13, P14): `sweep` judges only runs
whose pid answers; a stalled judgement is overridden by the job log; movement is the branch's sha;
the continuation's notes come from the worktree's `NOTES.asf.md` and its head from the worktree's
`HEAD`. No beat ref is ever created for a local run, `Beats.get` reads the absence as `''` and not as
an unreadable origin, and `clear_ended` has nothing to delete.

### 3. `known=` at the two call sites

**The lane.** `commits_note(repo, trunk, branch, known=None)` passes it straight through:

```python
    claims, refused = proves.parse_all(text, known=known)
```

and its one caller (`asf/harvest/lane.py:4465`) hands it the map it already holds:

```python
        body += commits_note(self.product.repo_dir, self.trunk, branch, known=items or None)
```

`items or None` is P19: `GitHubHost.open` spells `items = (self.lane.items if self.lane else None)
or {}`, and an empty map would refuse every claim on the body.

**The evidence.** `landed_proves` reads the record's ids once, before the two loops, and passes them
to both `parse_all` calls (`:1578`, `:1589`):

```python
    known = _record_ids(product)
```

where `_record_ids` is a small local helper beside `record_since`: `product.backlog_dir`, then
`index.json`'s `items` as it stands — retired cards included (C8) — or `None` for a product with no
record index, an unreadable one, or an empty `items`. It makes no `gh` call and no git call.
