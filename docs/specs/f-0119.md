# F-0119 — the hygiene lanes, one JSON object per line, and a rule check that can ask

A product rule like *no PR sits conflicting* has no way to ask whether ASF's PR-hygiene pass is
already handling the PR it is about to flag. So it flags it: the first customer install retired its
legacy tooling, wrote that rule, and got violations for exactly the PRs the factory had already
sorted into a lane and was working. The card's want is small and precise — a listing the check can
read, off state that is already on disk, with no network call.

Two things the card says are no longer true of the code, and the design below is cut to what is:

- **`--lanes` already exists.** `asf/harvest/pr_hygiene.py` has had a `--lanes` flag since the
  module was cut back to a read-only view; it prints the bare PR number of each row, one per line.
  Its only caller anywhere in the tree is its own test (P2). So this card does not add a flag — it
  gives the flag the shape the card asks for, and the shape has no other reader to break.
- **`asf pr-hygiene --lanes` is refused today.** `asf/cli.py` forwards only `--product` to the
  module, so argparse rejects the flag before anything runs: `asf: error: unrecognized arguments:
  --lanes`, exit 2 (P3). The flag the card names is unreachable from the `asf` surface, and wiring
  it through is half of this change.
- **There is no `pr-hygiene.json`.** No such file exists in the tree or in a product's state
  directory. The cached state the card means — what the `prs` step leaves behind — is the lane
  registry, `sessions.jsonl` under the product's state directory, which the `prs` step's lane pass
  writes and which `pr_hygiene.rows` already reads and nothing else (P4). The card's property holds
  of it exactly: reading it is one file read and no network call (P5).

After this change: `asf pr-hygiene --product P --lanes` prints one JSON object per line —
`{action, branch, lane, pr, since}` — for every PR the hygiene view holds; nothing on stdout and
exit 0 when it holds none; and, so that a check can tell "ASF owns nothing" from "ASF could not be
read", **exit 2 with nothing on stdout** when the product or its state cannot be read. The rule-card
section of the guide names it as the supported way to ask, with a check script a reader can copy.

### In

- **`rows` carries `since`.** One more key on the row `pr_hygiene.rows` already builds:
  `since`, the lane record's `at` (else `head_at`, else `None`) — when the branch entered the lane
  it is in (P6). Nothing else about `rows` moves, and `render` ignores it.
- **`pr_hygiene.lanes(product, state_dir=None)`** — the listing as data: one dict per `rows` row
  that carries a PR number, in the same order, with exactly the card's five keys.
- **One table maps a row kind to its lane token and its action**, and it is the only place those
  four strings exist: `STALE → CLOSE` is `lane: "stale"`, `action: "close"`; `CONFLICT → REBASE` is
  `lane: "conflict"`, `action: "rebase"`.
- **`--lanes` prints that listing**, one `json.dumps(…, sort_keys=True)` per line, and nothing else
  on stdout. No row, no output, exit 0.
- **`--lanes` exits 2 when the state cannot be read**, with the diagnostic on stderr and stdout
  empty — so a check that propagates it becomes a *check failure* and never a false violation
  (P14). Every other invocation of the command keeps exit 0 exactly as it has it (P7).
- **`asf pr-hygiene --lanes` reaches the module**: the parser grows the flag and the dispatch
  forwards it.
- **The guide's `## Rule cards` section names it** as the supported way for a product check to ask
  *does ASF own this PR?* — the command, the five keys, the three exit codes, why `--product` is
  named explicitly, and a copyable check script.

### Out

- **A new lane.** The listing is exactly what the hygiene view already holds: the two lanes of P1.
  The card's "conflicting, stale, awaiting rebase, and so on" describes the idea; `and so on` is
  not a licence to decide that a third lane state is the hygiene pass's, which would change what
  the pass owns rather than report it.
- **The broader question "is this PR under any ASF lane?"** — `REVIEW`, `GATE`, `WAITING_CI`,
  `QUEUED` and the rest. It is a real question with no machine-readable answer today (P17), and it
  is a listing over the whole lane state machine, not over the hygiene view. Its own card.
- **`--close`.** It is unreachable from the `asf` surface for the same reason `--lanes` was (P3) and
  it prints one sentence saying the lane closes nothing. Wiring it is not what the card asks for and
  it is left exactly as it is.
- **`item` on the listing object.** The card fixes the shape at five keys, a check keys on the PR
  number, and `branch` already carries the item id for every branch this factory names. A sixth key
  is a contract change, and adding one later is compatible in a way removing one is not.
- **`--json` anywhere else on `pr-hygiene`.** The default output stays the human rows, unchanged to
  the character; `--lanes` is the machine surface.
- **Filtering, sorting or paging the listing.** Branch order (P1) is stable and the list is the
  length of the hygiene lanes, which is small by construction.
- **Anything that reaches the network, or writes.** The command stays read-only in `surface.py`'s
  sense (P9): one file read, no `gh` call, no state written.

### The choices

| # | Chosen | Against | Why |
| --- | --- | --- | --- |
| D1 | `--lanes` is redefined to print JSON objects | a new `--lanes-json`, leaving the bare numbers alone | the card names `--lanes` and the JSON shape in one sentence; the bare-number form has exactly one caller, its own test (P2), and no caller at all through `asf`, because the flag never reached the parser (P3). A second flag would preserve a form nothing uses and leave two answers to one question |
| D2 | `since` is the lane record's `at`, falling back to `head_at` | a fresh `datetime.now`, or the run's `started` | `at` *is* when the branch entered this lane: the lane writes it on transition and `advance` refuses to rewrite it while state and reason hold (P6) — it is the same field the staleness clock is read off. `started` is when a session launched, which for an adopted or re-corrected branch is a different event |
| D3 | `since` may be `null` | omit the key, or default to the empty string | the five keys are a contract a check reads; a key that sometimes vanishes makes every reader defensive. A registry line from before `at` existed, or a hand-edited one, is honestly `null` — and `null` is the one value a reader cannot mistake for a time |
| D4 | Only rows with a PR number are listed | list every hygiene row with `pr: null` | the listing answers *does ASF own this PR?*; a row with no PR has no PR to answer about, and this is the filter `--lanes` already applies (P2) |
| D5 | The lane tokens are `stale` and `conflict`, the actions `close` and `rebase` | the display strings `STALE → CLOSE` / `CONFLICT → REBASE`, or the lane's own `STALE` / `BACK` | a machine surface wants a bare token, not an arrow a renderer chose; and `BACK` is the lane's state, of which `kind=conflict` is one reason — `conflict` is what the row actually means. Neither token is guarded by the state-word fence (P11) |
| D6 | One table, `LANES`, maps row kind → `(lane, action)` | a literal pair at the call site, or an `if` on the kind | four strings that a product's rule check will switch on should exist once; a reader of the module can then see the whole vocabulary in one place, and a third row would be one line |
| D7 | An unreadable product or state is **exit 2** under `--lanes` | exit 0 with no output, as every other path does (P7) | exit 0 and no output means *ASF owns nothing*, and a check that believes it flags every PR the factory is working — the exact false positive this card exists to remove, reintroduced on the error path. Exit 2 lands on the contract's own third branch: anything but 0 or 1 is a check failure, the factory's problem, never a violation of the product's rule (P14) |
| D8 | `--lanes` catches the error itself rather than letting `ConfigError` escape | drop the `try` and let `cli.main` report it | `cli.main` prints its `NEEDS OPERATOR` line on **stdout** (P8), which would put prose in the middle of a listing a script is parsing. Catching it keeps stdout pure JSONL under every outcome |
| D9 | Non-`--lanes` invocations keep exit 0 on an unreadable product | make the whole command exit 2 | a session or an operator reading the rows is not a rule check, and D7's reason does not apply to them; changing the rc of a path with existing callers is a wider change than this card |
| D10 | `json.dumps(…, sort_keys=True)`, one line, no indent | `print` of a dict, or an indented blob | one object per line is the card's shape and is what `while read` and a line-at-a-time parser want; sorted keys make the output byte-stable, which is what makes it testable and diffable |
| D11 | `lanes()` is a function beside `rows()`, and `main` only prints it | build the objects inside `main`'s `--lanes` branch | the listing is the thing a test should assert and a future caller should import; `main` stays the argv-and-exit-code layer it already is |
| D12 | `rows` gains `since`; `lanes` reads no lane record itself | `lanes` opening the snapshot a second time for the timestamp | one reader of the lane registry in this module, as today (P1). Two readers is two chances to disagree about which record a branch is at |
| D13 | The guide's snippet names `--product` explicitly | rely on the check inheriting `$ASF_PRODUCT` from the tick | `run_check` guarantees `BACKLOG_ROOT` and a cwd, and nothing else (P14). `$ASF_PRODUCT` is whatever the process that ran the checks happened to have, and a check run by hand has none |
| D14 | The contract is documented in `## Rule cards` | a new section, or the connectors guide | that section *is* the rule-check contract in prose — the script, the exit codes, the timeout (P15) — and the card asks for this to be in the contract, beside the exit codes it turns on |
| D15 | The doc's snippet is pinned by a test that also runs `bash -n` over it | assert the prose only, or nothing | "a test nobody can run is not acceptance": a snippet the guide tells an operator to copy should at least be known to parse, and `tests/test_readme.py` already reads guide prose from the checkout (P16) |

## The design

### `asf/harvest/pr_hygiene.py` — the listing

The module docstring's `--lanes` line is rewritten to the new shape, and the rest of the file keeps
every line it has:

```python
STALE_CLOSE = 'STALE → CLOSE'
CONFLICT_REBASE = 'CONFLICT → REBASE'

#: row kind → (the listing's ``lane`` token, its ``action``) — the whole vocabulary a product's
#: rule check switches on, in one place (F-0119, D5/D6). A lane the hygiene view does not hold is
#: not in this table, and adding one is a row here and a branch in :func:`rows`.
LANES = {
    STALE_CLOSE:     ('stale', 'close'),
    CONFLICT_REBASE: ('conflict', 'rebase'),
}
```

`rows` gains one key, `since` — read straight off the lane record, never derived here:

```python
def rows(product, state_dir=None):
    """``[{kind, branch, item, pr, why, since}]`` — the lane's STALE branches whose run did not
    land, and its BACK ``kind=conflict`` ones, in branch order.

    ``since`` is when the branch entered the lane it is in: the record's ``at``, which the lane
    stamps on a transition and does not rewrite while the state and the reason hold, else its
    ``head_at``, else None for a registry line written before either existed (F-0119, D2/D3)."""
```

and one function turns those rows into the listing:

```python
def lanes(product, state_dir=None):
    """``[{action, branch, lane, pr, since}]`` — one entry per :func:`rows` row that carries a PR
    number, in the same order: what ASF's PR-hygiene pass owns, as data.

    This is the answer a product's rule check reads to tell an open PR the factory is already
    working from one its own rule may flag (F-0119). It reads the lane registry the ``prs`` step
    already wrote (:func:`asf.harvest.lane.snapshot_at`) and makes no network call. A row with no
    PR number is not in the listing — it has no PR to answer about (D4)."""
    out = []
    for r in rows(product, state_dir):
        if not r.get('pr'):
            continue
        lane_token, action = LANES[r['kind']]
        out.append({'pr': r['pr'], 'branch': r['branch'], 'lane': lane_token,
                    'since': r.get('since'), 'action': action})
    return out
```

`main` gets the flag's own exit code, and nothing else about it changes:

```python
 def main(argv):
     product_name = None
     if '--product' in argv:
         i = argv.index('--product')
         product_name = argv[i + 1] if i + 1 < len(argv) else None
+    listing = '--lanes' in argv

-        return 0
+        # a listing's caller must be able to tell "ASF owns nothing" from "ASF could not be
+        # read": 2 is a *check failure* to the rule contract, never a pass (F-0119, D7/D8)
+        return 2 if listing else 0
-    if '--lanes' in argv:
-        for r in found:
-            if r.get('pr'):
-                print(r['pr'])
+    if listing:
+        for entry in lanes(product):
+            print(json.dumps(entry, sort_keys=True))

```

The output, for a state holding one branch in each lane:

```
{"action": "close", "branch": "worker/T-0001", "lane": "stale", "pr": 4, "since": "2026-09-21T00:00:00Z"}
{"action": "rebase", "branch": "worker/T-0002", "lane": "conflict", "pr": 5, "since": "2026-09-21T00:00:00Z"}
```

An empty cache prints nothing and exits 0. An unreadable product prints `pr_hygiene: <why>` on
stderr, nothing on stdout, and exits 2.

### `docs/guide/product-config.md` — the contract says how to ask

Into `## Rule cards`, after the `exit 0` / `exit 1` sentence and before the retirement paragraph:

> **Asking what ASF already owns.** A product rule about open pull requests — *no PR sits
> conflicting*, *no PR goes stale* — will otherwise flag the PRs ASF's own PR-hygiene pass is
> already working. `asf pr-hygiene --product <p> --lanes` is the supported way to ask. It prints one
> JSON object per line, one per PR in a hygiene lane, and nothing else on stdout:
>
> ```
> {"action": "close", "branch": "worker/T-0001", "lane": "stale", "pr": 4, "since": "2026-09-21T00:00:00Z"}
> {"action": "rebase", "branch": "worker/T-0002", "lane": "conflict", "pr": 5, "since": "2026-09-21T00:00:00Z"}
> ```
>
> | key | what it is |
> | --- | --- |
> | `pr` | the pull request number |
> | `branch` | the branch it is open from |
> | `lane` | `stale` — the lane found it stale — or `conflict` — the gate could not rebase it |
> | `since` | when the branch entered that lane, or `null` when the state does not say |
> | `action` | what the lane is waiting to do: `close` or `rebase` |
>
> It reads the state the tick's `prs` step already cached and makes no network call, so a check may
> call it every run. The exit codes match the contract above: **0** with output, **0** with no
> output when ASF owns nothing, and **2** when the product or its state cannot be read — propagate
> that 2 and your check becomes a check failure rather than a rule the product broke. Name
> `--product` explicitly: a check gets `BACKLOG_ROOT` and a working directory, and no product in its
> environment.
>
> ```sh
> #!/usr/bin/env bash
> # R-nnnn: no PR sits conflicting — except the ones ASF's hygiene pass already owns.
> set -euo pipefail
> product=your-product                                     # never `<p>`: inside $( ) that is a redirect
> owned=$(asf pr-hygiene --product "$product" --lanes) || exit 2   # 2 is a check failure, never a pass
> owned=$(printf '%s\n' "$owned" | python3 -c 'import json, sys
> print(" ".join(str(json.loads(l)["pr"]) for l in sys.stdin if l.strip()))')
> lines=$(for pr in $(your_conflicting_prs); do
>           case " $owned " in *" $pr "*) continue ;; esac
>           echo "PR #$pr sits conflicting"
>         done)
> [ -z "$lines" ] || { printf '%s\n' "$lines"; exit 1; }
> ```

## Records

- **The listing line**, on stdout, one per PR in a hygiene lane:
  `{"action": …, "branch": …, "lane": …, "pr": …, "since": …}` — `json.dumps(…, sort_keys=True)`,
  so the five keys are always present and always in that order. Written by `pr_hygiene.main` from
  `pr_hygiene.lanes`, and by nothing else.
- **The lane vocabulary**: `pr_hygiene.LANES` — `stale`/`close` and `conflict`/`rebase`. The four
  tokens exist in that table and in the guide's key table, nowhere else in the tree.
- **The exit codes of `--lanes`**: 0 with the listing, 0 and no output when the hygiene lanes are
  empty, 2 with the reason on stderr and stdout empty when the product or its state cannot be read.
  A check that propagates the 2 is recorded by the factory as `rule check failed: R-nnnn` in the
  tick log and in the doctor's `rule-checks` row — the existing check-failure path (P14), with no
  new record of its own.
- **`since`** is copied from the lane record's `at`, and is the lane's own account of when the
  branch entered that state. This command never stamps a time.
- **`docs/guide/product-config.md`**, `## Rule cards`: the paragraph, the two-line example, the
  five-key table, the three exit codes, and the copyable check script.
- **Nothing is written.** No record card, no state file, no metrics event, no `gh` call. The one
  side effect is `env.state_dir`'s `makedirs(exist_ok=True)`, which every `pr-hygiene` invocation
  already performs. `asf/surface.py` keeps `pr-hygiene` read-only.
- **No new config key and no migration.** A product that never calls `--lanes` is bit-for-bit
  unaffected.

## Stories

- S: `pr_hygiene.lanes` is the hygiene lanes as data — one five-key entry per PR the view holds, its lane token and action from the one `LANES` table, and `since` read off the lane record — acceptance: `python3 -m unittest -v tests.test_pr_hygiene.LaneListing`
