# F-0134 — the `type:` line is read; the card that leads with it is still not

Half of this card landed before it had a spec. `9230bf932` — *"fix(groom): an explicit type: line
decides the intake type (I13)"* — made `declared()` fill a `type: bug` card's missing `signature:`
from its title, so such a card is minted a Bug and never read by its shape as a Feature. It is in
the trunk, it has tests, and `docs/specs/f-0200.md:64` already builds on it.

The card is not closed by it. Driven live in this checkout at `feda154b2`, through the real CLI:

```
inbox/urgent.md:
    type: bug
    parent: E-0001
    severity: S1

    Billing is down for every customer.

$ asf groom
→ features/F-0002.md   title: "type: bug"   parent: E-0001   (no severity, no signature)
   ## History
   - 2026-09-30: created (inbox) — shape: default → feature
```

An S1 `type: bug` card, minted as a Feature — F-0134's exact report, still live. The reason is one
line above everything `9230bf932` touched: `parse_inbox_file` takes the **first non-blank line as
the title, unconditionally**, and only starts reading headers from the line *after* it
(`asf/groom/inbox.py:68-69`). A card that leads with `type: bug` therefore has that line eaten as
its title. `headers` never contains `type`, so `declared()` sees nothing to honour, `_typed()` has
no disagreement to catch, and I13 is not violated — because by the time any of them run, the
operator's `type:` line no longer exists. `severity: S1` is dropped the same way.

The remaining two failures are quieter and compound it. When intake *does* refuse a declared type,
its refusal opens with the sentence this card's title is a complaint about — `` `type: story` is
not read`` — and then says *"Remove the line, or change the shape"* without naming the line that
would settle it. And `docs/guide/operating.md:265-266` still tells the customer, in writing, that
*"a `type:` line is not read"*, which has been false since `9230bf932`.

This spec is four narrow things: **a header line is never a title, a refusal names the one line
that would settle the card, the guide says what intake actually does, and I13 is measured against
cards the factory really minted rather than two literal strings in a unit test.**

### The choices

| # | Chosen | Against | Why |
| --- | --- | --- | --- |
| C1 | **A first line that is a header line is a header, not a title.** `parse_inbox_file` tests the first non-blank line against `INBOX_KV_RE` and `_UNKNOWN_HEADER_RE`; when it matches, the title is `''` and the header block starts at that line instead of below it. The header loop itself is untouched. | Reading headers *and* keeping the line as the title; scanning for a later `#` line to use as the title. | P1 is the whole defect, and it is a four-line fix at its source. Keeping the line as the title as well would write the operator's header into the record's `title` — the field that also becomes `title_signature`, the `done/` slug and every view's label. Hunting for a later `#` line adds a second title rule for a card that is already malformed, and would still leave the "no `#` anywhere" case undecided. One rule: a header line is a header wherever it sits, which is exactly B-0111's ruling extended to the one position it did not cover. |
| C2 | **A card with no title is refused, loudly, and never minted** — a `## Question` naming the missing `# <title>` line, through the existing question route. | Taking the first body line as the title; using the file's name; minting with an empty title. | The card offers both remedies — "an explicit `type:` wins" and "intake refuses the card loudly" — and a *title* is not a header the shape rule can fill: it is the card's name in the record forever, and it is copied into the signature, the slug and the Backlinks of other cards. Inferring it from prose is a third inference layer under F-0200's body-signature read, and a file name is a slug, not a sentence. Refusing costs one groom cycle and is reversible; a wrong title is in the record. |
| C3 | **The refusal goes at the head of `shape.derive`, before every other rule.** | A guard in `process_inbox` beside `declared`/`scrub_title`; letting `declared()` fill `signature: 'untitled defect'` and mint. | `derive` already reads `card.title` (`tokenize`, `DEFECT_WORDS_RE`), and it is the one place a question is asked. ## The design

### 1. `asf/groom/inbox.py` — a header line is a header, wherever it sits

```python
def parse_inbox_file(text):
    """A `shape.Card` from one inbox/*.md file's raw text.

    The title is the first non-blank line with its `#` run stripped — unless that line is itself
    a header line, in which case the card has **no** title and the header block starts there
    (C1). A card dropped into the intake dir leading with `type: bug` used to have that line
    eaten as its title, so `headers` never carried the type the operator declared and the card
    was minted by shape alone (F-0134). A header is a header wherever it sits, first or last;
    B-0111 settled the last position, this settles the first. An untitled card is never minted:
    `shape.derive` refuses it (C2, C3).
    """
    lines = text.split('\n')
    idx = 0
    while idx < len(lines) and not lines[idx].strip():
        idx += 1
    first = lines[idx].strip() if idx < len(lines) else ''
    if first and (INBOX_KV_RE.match(first) or _UNKNOWN_HEADER_RE.match(first)):
        title, rest = '', lines[idx:]
    else:
        title, rest = re.sub(r'^#+\s*', '', first), lines[idx + 1:]
    # ... the header loop over `rest`, unchanged
```

A bare first line that is not one of the seven known keys is still a title (`New idea`,
`Note: something`), so `tests/test_groom.py:73-92` and B-0111's fixtures are unaffected. A card
whose title genuinely begins `Writes: …` must carry a `#` — which `asf inbox` always writes (P9).

`question_lines` renders an untitled card by its file name, so the groom line is never a double
space:

```python
title = ' '.join(scrub_title(parse_inbox_file(body), root).title.split()) or name
```

`apply_answer` inserts above a first-line header, and filters it (C8):

```python
idx = next((i for i, l in enumerate(lines) if l.strip()), 0)
head = idx if INBOX_KV_RE.match(lines[idx].strip() if idx < len(lines) else '') else idx + 1
keep = [l for l in lines[head:]
        if not ((m := INBOX_KV_RE.match(l.strip())) and m.group(1).lower() in parsed)]
new = lines[:head] + [f'{k}: {v}' for k, v in parsed.items()] + keep
```

### 2. `asf/groom/shape.py` — no title is a question, and a refusal names the missing line

```python
#: The line or section that would make a card the type its `type:` line declares — the "fix line"
#: F-0134 asks for, one per size, read by `_typed` (C4). Each entry completes the sentence
#: "a <size> needs …".
NEEDS = {
    'bug': 'a `signature:` line, and no `writes:` line — that is a Task',
    'task': 'a `writes:` line and a `parent:` naming a Feature or a Story, and no `signature:`',
    'story': 'a `parent:` naming a Feature, and an `## Acceptance` list',
    'epic': 'a `## Features` list of two or more, and no `parent:` — an Epic has none',
    'feature': 'a `parent:` naming an Epic, and no `signature:` or `writes:` line',
}


def _typed(card, shape):
    """The declared `type:` line, against the shape the card reads as (I13, C4, C5).

    The line **is** read: `declared()` has already filled a `type: bug` card's missing
    `signature:`, so a Bug is minted from it (`9230bf932`). What reaches here is a declared type
    the shape rules could not reach, and the card is refused rather than minted as the other
    type — with the one line that would settle it named, because "remove the line, or change the
    shape" is what left F-0134's operator with a Feature and no idea why.
    """
    t = (card.headers.get('type') or '').strip()
    if not t or t.lower() == shape.type:
        return shape
    if t.lower() not in SIZE:
        return Question(
            f"`type: {t}` is not a card size. The sizes are {', '.join(sorted(SIZE))}. "
            f"Change the line or remove it — nothing is minted from this card until you do."
        )
    return Question(
        f"`type: {t}` is read, and this card is not shaped like one: a {t.lower()} needs "
        f"{NEEDS[t.lower()]}. Add it, or change the `type:` line. The card reads as "
        f"{shape.type} ({shape.rule}: {SIZE[shape.type]}) and is not minted as one."
    )
```

and, first in `derive`, before every other rule (C3):

```python
def derive(card, canonical, default_bug_parent=None):

            'This card has no title — its first line is a header (`type:`, `parent:`, '
            '`signature:`, …). Put a `# <title>` line first: the headers below it are read, '
            'and nothing is minted from a card with no name.'
        )
    headers = card.headers
    # ... unchanged
```

After this, the reproduction of P2 mints nothing, keeps `inbox/urgent.md`, and leaves one groom
line: `- [ ] inbox:urgent.md urgent.md — This card has no title … → answer: ____`. Move the title
to the top and the next tick mints `B-0001` at `severity: S1` — P3's path, unchanged.

### 3. `docs/guide/operating.md` — what intake actually does with `type:`

The paragraph at `:264-269` is replaced (C4, P7). It must say, in the guide's own voice: the body
may carry a `type:` line as well as the other five; a `type: bug` card with no `signature:` gets
one from its title and is minted a Bug; any other declared type the card is not yet shaped like is
refused with a question naming the missing line, never minted as the other type; and every header
line — including `type:` — must come **below** a `# <title>` line, because a card that leads with
one has no title and is refused. The shape rules themselves (Bug ← `signature:`, Task ← `writes:`,
Epic ← a Features list, Story ← a Feature `parent:`, else Feature) stay exactly as written; they
fill what the `type:` line leaves open.

### 4. `asf/invariants.py` — unchanged; the evidence moves

`check_i13` and `TEST_ONLY` are not touched (C7). What changes is where it is called from: a new
acceptance class mints one card per declared type through the real `asf groom`, reads the minted
item's `type` out of the record, and asserts `check_i13(declared, minted) == []` — plus the
negative, that a card refused for a declared type mints nothing at all, which is the case
`check_i13` cannot see because there is no `minted` to compare.

## Records

* **Nothing new is written to the record.** No field, no card, no event, no ledger line, no state
  file (C11). The change is a parse, two sentences and a document.
* **The minted card is unchanged in shape.** A Bug typed from a `type: bug` line keeps
  `created (inbox) — shape: signature → bug`; `RULES` gains nothing (C6). The audit trail that the
  operator's line was read stays `inbox/done/<slug>.md`, which holds their original text (P11) —
  the same answer `docs/specs/f-0200.md:340-343` gave for an inferred signature.
* **What a refused card writes is what a refused card already writes**: the `## Question` block in
  its own file, and one `- [ ] inbox:<file> <title> — <question> → answer: ____` line in
  `groom/<date>.md`. Only the sentence inside it changes, plus the file-name fallback when the
  card has no title.
* **Cards already minted are not revisited.** A Feature minted from a `type: bug` card before this
  lands keeps its type and its title; nothing migrates it. The route back is the groom's
  reshape/adjudicate path, not intake. Cards still *sitting* in an intake dir are re-read on the
  next tick and get every read here for free (P10).
* **`asf check` is unaffected.** It reads the History line's *type* (`asf/record/check.py:304-315`),
  which no longer differs from what it read before, and a Bug typed from a declared line still
  carries the signature its rule requires.
