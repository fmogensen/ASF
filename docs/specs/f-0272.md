# F-0272 — the overlap went away and the hold stayed

The tick's order pass writes one edge per standing overlap: two Active Tasks whose `writes:`
intersect and that the record has not ordered get `after: <owner>` on the held card, with the
History line `serialized behind <owner>: writes: overlaps <glob>`
(`asf/tick/widen_footprint.py:serialize_overlaps`). The edge is a fact about the footprint at the
moment it was written, and the footprint moves: a card edit, a widening, a reshape, a revert all
change `writes:`. Nothing in the factory reads the edge back.

So the hold outlives its reason. Seen 2026-10-07 on a product: T-0659 kept `after: T-0122` after
T-0122's `writes:` no longer held the overlapping test file. The card's row read
`WAITS ON T-0122 — after: T-0122 has not landed`, the Feature's delivery row read the same thing
for every Task bundled with it, and nothing in the record said why — `asf check` is silent,
because I3 judges writers, not standing state. The hold was removed by hand.

The inverse already exists for the *other* `after:` the widen pass writes: `revert_overlaps` undoes
a widening whose paths overlap and files `footprint widening reverted: overlaps <owner>`. There is
no such reader for a serialization. This card writes one.

### In

1. **The rule, over facts only** — two pure functions in `asf/feeder/widen.py`: a reader for the
   `serialized behind <owner>: writes: overlaps <glob>` History lines a card carries, and the
   decision `stale_serializations(...)` → the `(owner, glob)` edges of a card's `after:` that the
   order pass wrote and whose overlap is gone by the same test that wrote them.
2. **The pass that writes it** — `drop_serializations` in `asf/tick/widen_footprint.py`, run by
   `run()` after `revert_overlaps` and before `serialize_overlaps`: the owner leaves `after:`, one
   History line `serialization dropped: <owner> — writes: no longer overlaps <glob>`, that card
   alone in one commit, the ledger event, the index re-derived once, `items` updated in place so
   the same tick's wave sees the freed card.
3. **The regression**, end to end: the 2026-10-07 sequence replayed from both sides — the path
   leaving the *owner's* `writes:` and the path leaving the *held* card's — ending in a launching
   row for the held Task and for the Feature's delivery bundle (P8).

### Out

- **No change to when an edge is written.** `serialize_overlaps`, `unordered_overlaps`, its
  pushed-work tie-break (B-0037) and its shared-path exemption are untouched. This card adds the
  reader, not a second writer.
- **No change to the feeder's footprint gate.** A pair the gate's wider test (P7) still reads as
  colliding keeps waiting at launch, with the row `writes: overlaps <other>` — recomputed every
  tick, never written onto the card. The sticky edge is this card's scope; a wait that is already
  recomputed is not a bug.
- **The `after:` `revert_overlaps` writes is never dropped by this pass.** Its paths left `writes:`
  by construction, so the overlap is gone by construction too, and the edge is the wait that lets
  the rule re-decide once the owner is done (P9). Only an edge a `serialized behind …` line names
  is this pass's.
- **A plan-declared or operator-written `after:` is never dropped.** No History line names it, so
  the reader does not see it. Order a plan chose is not an overlap hold.
- **No new `after:` ever written here.** The pass only removes; nothing it does can close a cycle.
- **Nothing read about the owner's state.** A Closed, Resolved or removed owner whose `writes:`
  still intersect keeps its edge: the feeder already stops waiting on a landed id
  (`rows.after_of`/`landed_ids`), and a dead edge is `rows.dead_after`'s question, not this one.
- **No new command, no new state file, no operator question.** `asf set <item> after-=<owner>`
  keeps working for the by-hand case; this card is the reason nobody has to type it.
- **No change to `asf check` or I3.** P5 shows the guard the pass needs is already there; this card
  relies on it rather than restating it.

|---|---|---|---|
| C1 | The edge is dropped on the current `writes:` of both cards, by `core.writes_intersect` with the `shared_paths` exemption — the exact test `unordered_overlaps` used to write it (P6) | `footprint.globs_overlap` / `footprint.overlaps`, the gate's wider test the `asf set` flip uses (P7) | The drop must be the exact inverse of the write: an edge is dropped iff the order pass would no longer write it. | C2 | The recorded `glob` is read from the History line for the *message only*; the decision re-tests the current `writes:` | Testing whether the recorded glob is still in both footprints | Either card may have been re-cut so a *different* pair of globs now overlaps. | C3 | An edge counts as this pass's only when a `serialized behind <owner>: …` History line names that owner | A standing-state rule: drop any `after:` whose cards no longer overlap | A plan's order, an operator's `after:`, and the revert's wait are all legitimate `after:` with no overlap behind them. | C4 | One `(owner, glob)` per owner, the first line seen | Every line | A pair re-serialized after a drop files a second `serialized behind` line for the same owner; the first glob is enough for the message, and the decision does not use it |

| C6 | A drop the record stage refuses (it would un-order a live overlap reachable through the dropped edge) is left standing: the pass prints `widen: <held> not dropped — <finding>` and the next tick re-asks | Pre-computing reachability in the pass and skipping such an edge | I3 is the one definition of "no two Active Tasks' writes: left unordered", validated before the commit with the card unchanged (P5/P11). | C7 | One commit per dropped edge, that card alone | One commit per card carrying every drop | `serialize_overlaps` and `revert_overlaps` both commit one card per write with the note as the subject; a reader following `git log` for an id sees one subject per edge, written and dropped alike |
| C8 | Judged on the record's own read (`load_items` → `canonicalize` → `invariants.overlap_tasks`), not on the index | `items`, the index | The index drops a removed card, and a removed owner's `writes:` are exactly what decides whether its edge still holds. `serialize_overlaps` reads the record for the same reason |

## The design

### 1. The rule — `asf/feeder/widen.py`

Two constants and two functions beside the existing `SERIALIZED`:

```python
#: The History line that drops a serialization whose overlap has gone.
UNSERIALIZED = 'serialization dropped: {owner} — writes: no longer overlaps {glob}'
#: A serialization's History line, read back: the owner it waits on and the glob it named.
SERIALIZED_RE = re.compile(r'serialized behind ([A-Z]-\d{4,}): writes: overlaps (\S+)')
```

```python
def serialized_edges(body):
    """``[(owner, glob)]`` — every ``serialized behind <owner>: writes: overlaps <glob>`` History
    line in ``body``, first-seen order, one entry per owner (the first glob recorded for it): the
    ``after:`` edges the tick's order pass wrote, and the only ones it may take back."""


def stale_serializations(after, body, writes, others, shared=()):
    """``[(owner, glob)]`` — the owners of ``after`` that the order pass put there
    (:func:`serialized_edges` names them) whose ``writes:`` no longer intersect ``writes`` by
    ``asf check``'s own test, a glob ``shared`` covers left out either side: exactly the pairs
    :func:`asf.invariants.unordered_overlaps` would no longer serialise.

    ``others``: ``{owner: writes}``, the record's own reading. An owner ``others`` does not name
    is never returned — a card the record cannot show is no fact. A plan-declared or
    operator-written ``after:``, and the wait ``revert_overlaps`` writes, name no serialization
    line and are never returned either."""
```

`stale_serializations` normalises both sides through `norm_writes`, and the overlap test is
`any(writes_intersect(x, y) …)` over the non-shared globs — the same expression
`unordered_overlaps` runs, so the two can only ever disagree about a pair if one of them is edited
alone.

### 2. The pass — `asf/tick/widen_footprint.py`

```python
def drop_serializations(ctx, items, out=print):
    """Drop every ``after:`` the order pass wrote whose overlap has gone: for each Task carrying a
    ``serialized behind <owner>: …`` History line whose ``after:`` still holds that owner and
    whose ``writes:`` no longer intersect the owner's (:func:`asf.feeder.widen.stale_serializations`),
    the owner leaves ``after:`` and one History line
    ``serialization dropped: <owner> — writes: no longer overlaps <glob>`` is filed, that card
    alone in one commit (:func:`write_card`).

    Never a new edge: the pass only removes, so it cannot close a cycle. A drop the record stage
    refuses — it would leave a live overlap unordered through the dropped edge (I3's ``after:``
    half) — leaves the card unchanged and is re-asked next tick. A Closed, Resolved or ``removed:``
    card is skipped: there is no hold left to lift. ``items`` is updated in place; the index is
    re-derived once when anything was written. Returns ``{task: [owners]}``."""
```

It reads the record the way `serialize_overlaps` does — `load_items` → `canonicalize` →
`invariants.overlap_tasks` — giving `{id: {'type', 'state', 'writes', 'after', 'removed', …}}`, and
`writes_of = {iid: t['writes'] for iid, t in shaped.items()}` as the `others` map. For each Task
in id order that is not `removed:` and whose state is neither `Resolved` nor `Closed`, it re-reads
the card (`_card`, for its History text), asks the rule, and for each edge it names:

```python
after = [a for a in rec['meta'].get('after') or () if a != owner]
err = write_card(root, iid, {'after': after}, stamp,
                 widen.UNSERIALIZED.format(owner=owner, glob=glob), product=product)
```

The card is re-read between edges of the same card, as `serialize_overlaps` re-reads between
pairs. On `err` the pass prints `widen: {iid} not dropped — {err}` and goes on; on success it
records the event, updates `items[iid]`, and sets the reindex flag.

`run()` gains one line, and the module docstring a fourth numbered entry:

```python
revert_overlaps(ctx, items, out=out)
drop_serializations(ctx, items, out=out)
serialize_overlaps(ctx, items, out=out)
```

### 3. What it looks like when it is there

The 2026-10-07 sequence, from the tick's own output:

```
reverted T-0122: writes: -tests/test_x.py overlaps T-0659 — after: T-0659
dropped  T-0659: after: -T-0122 — writes: no longer overlaps tests/test_x.py
```

and the row the Feature's delivery had been holding:

```
before   WAITS ON T-0122   after: T-0122 has not landed
after    LAUNCH            N Tasks of F-xxxx: one branch, one PR, one review
```

Nothing is printed, written or committed for a pair whose overlap still stands, and a second pass
over the same record writes nothing at all.

Pins, in one class beside `SerializeOverlapTests` (the rule's own cases over plain values, then

- `serialized_edges` reads `(owner, glob)` off a History line, in first-seen order, one entry per
  owner for a card serialized behind the same owner twice; and reads nothing from a
  `serialization dropped: …` line or a `footprint widening reverted: …` one (C10).
- `stale_serializations` returns the edge when the overlapping path left the **owner's** `writes:`,
  and when it left the **held** card's; returns nothing while any non-shared glob pair still
  intersects; returns nothing for an `after:` no History line names (a plan's order, an
  operator's, the revert's wait — C3/P9); returns nothing for an owner absent from `others` (C8);
  and returns the edge when the only remaining common glob is one `shared_paths` covers.
- The pass, over the harness: the owner's `writes:` narrowed, one tick → the held card's `after:`
  is `[]`, its History carries `serialization dropped: T-0001 — writes: no longer overlaps
  lib/shared.py`, the commit subject is `T-0002: serialization dropped: …`, `git show --name-only`
  is `tasks/T-0002.md` alone (C7), and `asf check` is clean.
- A second pass writes nothing: `HEAD` unmoved, `after:` still `[]` (idempotent).
- The overlap standing: one tick writes no commit and leaves `after: ['T-0001']` (P1's state is
  not disturbed).
- A drop that would un-order a live overlap reachable through the dropped edge is refused: the
  card is byte-identical, the pass printed `not dropped — … I3: writes: intersects Active task
  …`, and the tick did not fail (C6/P5).
- A `Closed` held card and a `removed:` held card are both skipped — no commit (C9).
- The pair re-serializes when the overlap comes back: a later tick writes `after: ['T-0001']` and
  a second `serialized behind` line, and the drop then fires again once the path leaves (no flap,
  because every write follows a real `writes:` change).

## Records

- **The held card** — one History line per dropped edge,
  `- <stamp> serialization dropped: <owner> — writes: no longer overlaps <glob>`, and `after:`
  without that owner (the field is dropped when nothing is left). The `serialized behind …` line
  it answers stays: the record keeps both halves, so the card reads as what happened.
- **The record's git log** — one commit per dropped edge, that card alone, subject
  `<held>: serialization dropped: <owner> — writes: no longer overlaps <glob>`, signed off by
  `write_card` as every widen-pass commit is.
- **`metrics/events/<day>.jsonl`** — one new event kind, `unserialized`:
  `{"kind": "unserialized", "item": "<held>", "text": "-after: <owner> — writes: no longer
  overlaps <glob>", "product": …, "ts": …}`, beside the pass's existing `serialized` and
  `reverted`. No metric reads the kinds by name, so nothing downstream changes shape.
- **The tick's own output** — one line per drop,
  `dropped  <held>: after: -<owner> — writes: no longer overlaps <glob>`, and one per refusal,
  `widen: <held> not dropped — <finding>`.
- **`asf next`** — the row the card exists for: a held Task, and the Feature delivery bundling it,
  stop reading `WAITS ON <owner> — after: <owner> has not landed` the tick the overlap goes.
- **No new file, no new state file, no new command, no new convention.** `conventions.shared_paths`
  is read where the pass already reads it.
- **What is no longer written** — an `after:` edge that outlives the overlap that wrote it, and
  the `WAITS ON` rows it produced for the held card and everything bundled with it.
