# F-0234 — eleven runs died of a word the factory never checked

Eleven runs ended `dead pid` over fourteen days — 5.5 a week against a threshold of 5 — for $7.41
and 3.3 hours that landed nothing.

Put those two numbers beside the sibling card's. F-0235's thirty-nine `hook refused` runs cost $3.04
and 21.7 minutes each: whole sessions that did the work and lost it at the push. These eleven cost
**$0.67 and 18 minutes each** — eighteen minutes of wall clock against sixty-seven cents of spend.
A session that is thinking spends money. These were not thinking. Eighteen minutes of a run that
bought almost nothing is not a session that died mid-sentence; it is a session that was *not
working during most of the interval the factory attributes to it* — either because it was over long
before anyone looked, or because it was never the thing the factory was looking at.

Which of the two? **The ledger cannot say, for any of the eleven.** `end_reason` is the bare string
`dead pid` and nothing else is kept. That is the defect this card fixes, and it has a precise shape:

`judge` writes the death from one boolean — `ev.alive` (`asf/workers/lifecycle.py:1835`). That
boolean comes from `observe.identity_alive` (`asf/workers/observe.py:219-243`), whose rule is *a run
is alive only while an observed session sits at its pid carrying that run's own `ASF_SESSION`*. The
observation is one `ps axeww` call parsed for environment variables (`asf/workers/observe.py:46-96`).
So `identity_alive` returns False for two situations that have nothing to do with each other:

- **the process is gone** — a real death; and
- **a process is right there, running, and the observation could not read its session id** — a
  truncated `ps` line, an environment the platform will not show, a run whose env had not been
  published yet when the pass swept. The worker is alive and working.

The factory never distinguishes them, because **it never asks the operating system.** `pid_alive`
(`asf/workers/lifecycle.py:580-595`) is one `os.kill(pid, 0)` away and is not on this path at all:
`alive_for` (`asf/workers/health.py:96-103`) falls back to it only when the observation source is
*unreadable*, never when it reads fine and merely fails to name a process. A readable observation
that cannot identify a live worker is treated as proof of death.

What that costs is not one wasted run. `handle_dead` launches a cold retry into **the same worktree**
(`asf/tick/step_health.py:100-108`) — so a second agent is started on top of a first one that is
still running, in the directory the first one is still writing. Then the retry dies too, or
collides, and its own row is a second `dead pid` on the same metric. One misread pid, two dead runs,
and a worktree two processes were editing at once.

Three things, in the order they pay:

1. **Ask the OS before writing the death.** A pid that still answers, carrying one of the factory's
   own headless workers, is not a corpse just because the observation could not name it. Four
   words where there is one boolean today — `alive`, `gone`, `reused`, `unknown` — and only the
   first two decide anything.
2. **Bound the deferral by the log.** `unknown` must not make a run immortal. The product already
   has a notion of "this session has gone quiet" — `stall.silent_minutes`, 30 minutes by default —
   and that is the bound: a worker that answers but has written nothing for longer than that is
   over, and is recorded as over.
3. **Write down which death it was — and do not touch the word the card is verified on.** The class
   goes on the ledger line as its own field. `end_reason` stays exactly `dead pid`, because
   `loop.verify` recomputes *both* sides of this card's own verdict with the same key, and a renamed
   class would score it as a false victory (the choices, C1).

### In

- **`lifecycle.liveness(...)` — four words for a pid, in the one module allowed to choose them**

- **The deferral, bounded by the log** — `UNKNOWN` keeps a run live; a worker whose log has been

- **`Evidence.liveness`** — a new field with a null default (P2), filled by `gather` from a new
  optional `liveness=` callable, so health can record the class it acted on.
- **`dead_class` on the ledger line** — one new entry in `RUN_FIELDS` (P14), written in the same

- **`health.dead_census(product, days)` and `doctor.check_dead_sessions(product)`** — the split of
  the window's deaths by class, as one non-required doctor row (P17).
- **The stale comment on `DEAD_PID` corrected** (P11).

### Out

- **Any change to `end_reason`, `failure_class`, `outcome_class`, `OUTCOME_CLASSES` or the
  scorecard.** The card's own verification depends on the string not moving (P13). This is the
  hardest line in the document.
- **Any change to `judge`.** Every new fact arrives on the callable behind `ev.alive` (P16).
- **Folding a cold retry's own death onto the incident it retried.** It is a real run and real
  spend; see C6.
- **Preventing host-level deaths** — sleep, reboot, OOM, an operator's `kill`. Those are real

  misreads; it does not try to stop them, and nothing here claims how many of the eleven they are
  (P19).
- **Emptying `OneClassifierTest.NOT_YET`.** `health.py`, `stall.py` and `step_health.py` stay on it;
  this card adds no new literal to them and removes none of the debt.
- **A new module, a new `asf` command, a new config knob.** Everything below lands in files that
  already exist, and the one limit read is one the product already configures (P10).

## The design

### 1. `lifecycle.liveness` — the four words

In `asf/workers/lifecycle.py`, beside `pid_alive` (P8):

```python
#: What a liveness check can conclude about a run's pid. Only :data:`GONE` and :data:`REUSED`
#: end a run; :data:`UNKNOWN` is the honest answer when a process answers at the pid, looks like
#: one of ours, and the observation could not name its session — a worker, not a corpse (F-0234).
ALIVE = 'alive'
GONE = 'gone'
REUSED = 'reused'
UNKNOWN = 'unknown'
LIVENESS = (ALIVE, GONE, REUSED, UNKNOWN)
#: The verdicts under which a run keeps running.
LIVE_VERDICTS = (ALIVE, UNKNOWN)


def liveness(run, observed, exists, is_ours=None, silent_min=None, silent_for=None):
    """Which of :data:`LIVENESS` describes ``run``'s pid. Pure: every fact arrives as an argument.

    ``observed`` is the :class:`asf.workers.observe.Observed` sitting at the pid, or None;
    ``exists(pid)`` is the OS answer (:func:`pid_alive`); ``is_ours`` is True/False/None for
    "the process there is one of the factory's headless workers" (:func:`asf.workers.health.
    is_print_worker` over its command line), None when it was not asked; ``silent_for`` and
    ``silent_min`` are minutes — how long the run's log has been still, and how long it may be.
    """
    pid = run.get('pid')
    if cloudpid.is_token(pid):          # a cloud run is no process here: its status file answers
        return ALIVE if cloudpid.alive(pid) else GONE
    if not exists(pid):
        return GONE                     # the OS has the last word on a pid that answers nothing
    if observed is not None:
        if not run.get('session') or run.get('session') == observed.session:
            return ALIVE
        if observed.session:
            return REUSED               # it names a session, and not ours: the pid was recycled
    if is_ours is False:
        return REUSED                   # something answers there, and it is not a worker of ours
    if silent_min is not None and silent_for is not None and silent_for > silent_min:
        return GONE                     # ours, answering, and it has written nothing since
    return UNKNOWN
```

The order is the argument. The OS is asked **before** the observation is believed, so the one
question that was never asked is asked first; and the observation's identity match is still what
promotes a pid to `ALIVE`, so F-0076 D11's rule is kept whole, not weakened.

### 2. `observe.liveness_for`, and `identity_alive` on top of it

`identity_alive` keeps its signature, its callers and its documented behaviour for a pid **no run
recorded** (alive iff observed at all). What changes is that the run case routes through the four
words:

```python
def liveness_for(observed, runs, exists=None, is_ours=None, silent_min=None, silent_for=None):
    """``callable(pid) -> one of lifecycle.LIVENESS`` for the pids ``runs`` recorded.

    ``exists`` defaults to :func:`asf.workers.lifecycle.pid_alive`. ``is_ours(pid)`` and
    ``silent_for(pid)`` are optional measurements the caller supplies; without them ``liveness``
    is asked with None for those facts and can only answer ALIVE, GONE or UNKNOWN.
    """


def identity_alive(observed, runs, **kw):
    """``callable(pid) -> bool`` (D11) — now the two verdicts a run keeps running under."""
    verdict = liveness_for(observed, runs, **kw)
    by_pid = {o.pid: o for o in observed}
    run_pids = {r.get('pid') for r in runs if r.get('pid') is not None}

    def alive(pid):
        if pid not in run_pids:
            return pid in by_pid          # unchanged: a pid no run recorded
        return verdict(pid) in lifecycle.LIVE_VERDICTS

    return alive
```

Both doors close here (P6): `judge` reads `ev.alive` from this callable through `gather`, and
`stall.classify` calls it directly. Neither file is edited, and neither gains a state-word literal.

`health.alive_for` is where the measurements are supplied, because it is already the place that
holds the product and the config:

```python
def alive_for(product, runs, session_source=None):
    cfg = spawn_mod.load_cfg()
    observed, why = observe.read(cfg, pool_mod.accounts_from_config(cfg), source=session_source)
    if why:
        return pid_alive
    return observe.identity_alive(observed, runs, **_measurements(product, runs))
```

where `_measurements` supplies `is_ours=lambda pid: is_print_worker(command_line(pid))`,
`silent_min=stall.silent_minutes(product)` and `silent_for` off the run's log mtime. `command_line`
is one `ps` per *unmatched* pid — the ordinary tick matches every pid on the first rule and shells
out for none of them.

### What it looks like when it is there

A tick's health pass over a worker whose `ps` line carried no readable env prints nothing and ends
nothing; the run is judged again next pass, and finishes. The same worker, thirty-one minutes after
its log last moved, is ended `dead pid` with `dead_class: gone`. A pid that has been recycled by an
unrelated process is ended `dead pid` with `dead_class: reused`, as promptly as today. And
`asf doctor` carries a row that says which of the three the week's deaths were — the sentence
nobody could write about the eleven.
