# F-0108 — release 0.1 for feedback: the first-user docs, the feedback channel, and the gate a tag is cut behind

Epic: E-0001 — ASF 0.1 — a working factory. Branch: `spec/F-0108`.

The card was written on 2026-09-24, when `tools/install.sh` was the whole story and the README had
three lines of Install. Two of its five acceptance bullets have since been taken by other cards and
one has landed whole, so this spec is narrower than the card and says exactly where the rest went:

- **Bullet 1, the general installer**, is F-0107's — the card itself says it "absorbs the installer
  card", and the absorption went the other way: `docs/specs/f-0107.md` specifies
  `asf install --product <p>` writing `~/.ASF/config.yaml` from the package's own template,
  `asf uninstall`, and zero-to-green in a temp `HOME` against `sample/` in CI, and its plan is in
  flight. Re-specifying it here would mint a second owner for `tools/install.sh` and `asf/install.py`.
- **Bullet 3, release notes**, landed: `asf.metrics.metrics.write_trunk_release` cuts the
  `v<major>.<minor>.<patch>` tag, writes `releases/<day>-<sha7>.md`, publishes the GitHub Release
  with the install line pinned to that tag, and `sync_changelog` merges the note's `## Notes` into
  `CHANGELOG.md` on the trunk. `059c9d36a docs(release): v0.1.61 in CHANGELOG.md` is that path
  running. This card proves it from the gate's side; it does not rebuild it.
- **Bullet 2 (the four first-user docs), bullet 4 (the feedback channel) and bullet 5 (the release
  checklist)** have no owner. They are this card.

After this change a stranger reads four pages that are checked rather than hoped for, an issue they
open becomes a card in the public record and gets answered on it when the card lands, and a `0.1.x`
tag cannot be cut from a sha whose install test did not run green or whose docs carry a dead link.

## 1. Decisions

### 1.1 In

- **Four first-user pages, at the card's own paths**: `docs/quickstart.md`, `docs/concepts.md`,
  `docs/operator.md`, `docs/troubleshooting.md`. Two of them are new writing; two are the existing
  operator guide **moved**, not copied — `docs/guide/getting-started.md` → `docs/quickstart.md`,
  `docs/guide/troubleshooting.md` → `docs/troubleshooting.md`, and
  `docs/guide/product-config.md` + `docs/guide/operating.md` → `docs/operator.md` (D1). Three
  deep-topic pages stay where they are: `docs/guide/upgrading.md`, `docs/guide/ci-runner-pool.md`,
  `docs/guide/connectors.md`.
- **`asf docs check [--product P] [--at <sha>] [--json]`** — a new module `asf/docs.py`, one
  command, the single meaning of "the docs build". Five checks over the page set
  (`conventions.doc_pages`):
  1. every page in the set exists;
  2. every relative markdown link resolves — the file **relative to the page that carries it**,
     and the `#fragment` against that page's own headings under GitHub's slug rule (D2);
  3. every `asf.doctor` row name has a `###` heading in the troubleshooting page (§2.3);
  4. every `/asf:*` skill (`asf.plugin_build.skill_names`) and every `asf <command>`
     (`asf.views.readme._commands_rows`) has a row or a heading in the operator page;
  5. every field of `asf.conventions.Conventions` is named in the operator page.
  Exit 0 and one `docs: clean` line, or exit 1 with one line per complaint, `path:line: what`.
  Nothing is written on any form.
- **`asf.doctor.ROWS`** — a tuple naming all 34 rows `doctor.run` can put in the table, in table
  order, with the one-line meaning of each. `run` appends by that constant, and
  `tests/test_doctor.py` reads `asf/doctor.py` with `ast` and asserts no row name outside `ROWS`
  reaches an `append` in `run` (D3). `ROWS` is what check 3 above reads, so a new doctor row is red
  in CI until it is documented. The 34 are, in order: `config`, `repo`, `backlog`, `scheduler`,
  `one-factory`, `approvals`, `redaction-hooks`, `approvals-hook`, `console permissions`,
  `worker env`, `worker secrets`, `worker push auth`, `clock code`, `drift`, `rule-checks`,
  `briefs`, `worktrees`, `cli:*`, `capacity`, `savings`, `models`, `model table`, `conventions`,
  `deploy`, `customer content`, `token-caps`, `ci pool`, `ci runners`, `cloud lane`, `gate`,
  `lane pushes`, `ab pairs`, `quota lock`, `branches`.
- **Issue templates** — `.github/ISSUE_TEMPLATE/bug.yml`, `idea.yml`, `install.yml` and a
  `config.yml` that turns blank issues off and points a question at the record. Each form labels
  its issue `feedback` plus one of `bug` / `idea` / `install`, and asks for what the intake needs:
  a title, what happened, `asf --version`, and (for install) the OS and the failing doctor row.
- **`asf feedback sync [--product P] [--dry-run]`** — a new module `asf/feedback.py`, run from the
  tick's `groom` step (`asf/tick/step_groom.py`) **before** `cmd_groom`, so an issue opened between
  two ticks is an intake card the same tick types it. One pass, two directions:
  - **in**: every open issue carrying `feedback.label` that no item and no intake file already
    carries becomes `<intake_dir>/issue-<n>.md`, with an `issue: <n>` header, the label's card type
    (`feedback.types`), and the issue's body quoted under `## Reported` — scrubbed, capped, and
    never read as an instruction (D5).
  - **out**: every item carrying `links.issues` whose derived state is `Resolved` or `Closed`
    (`asf.metrics.metrics.LANDED_STATES`) and whose `## History` has no reply line gets one
    `gh issue comment`, and the reply line is written into the item's History — the record is the
    ledger (D6).
- **`issue:` as an intake header** — `asf.groom.inbox.INBOX_KV_RE` gains it, and
  `process_inbox` writes it through `write_new_item` as `links.issues: [<n>]`, beside the
  `links.prs` and `links.branches` the record already carries.
- **`conventions.feedback`** — `repo` (unset: the product's own `repo_slug`), `label`,
  `types` (issue label → card type), `max_per_tick`, `max_body_lines`; merged per key over
  `DEFAULT_FEEDBACK`, and `'feedback'` joins `MAP_CONVENTIONS` so a misshapen block is a red doctor
  row rather than a silent default. Documented in `docs/products.example.yaml`.
- **The tag gate.** `asf.metrics.metrics._cut_trunk_release` asks `asf.release`'s own readers
  before `cut_tag`: the finished trunk run at that sha must carry a step matching
  `release.ci_steps.install_from_zero` and it must be green, and `asf docs check --at <sha>` must be
  clean at that sha. Either failing prints one line naming which and returns `None` — the next
  rollup tries again. A product with no CI provider or an empty `ci_steps.install_from_zero` skips
  the CI half; nothing about the release path changes for a product that is not this one (D7).
- **Two CI steps** in `.github/workflows/tests.yml`: `asf docs check`, and the docs and feedback
  test modules under the existing suite step (they are in `tests/`, so `tools/run_tests.py` already
  runs them — the named step is the one the gate reads).
- **`release.py`'s docs criterion reads the four pages.** `DEFAULTS` gains
  `doc_pages: [docs/quickstart.md, docs/concepts.md, docs/operator.md, docs/troubleshooting.md]`,
  and criterion 7 requires each to exist on the trunk and to be linked from the README, beside the
  `readme_sections` headings and the tag's CHANGELOG notes it reads today. Criterion 7 is the card's
  "first-user docs" bullet, read by a machine.
- **The README and `docs/README.md` link the four pages**, and no second copy of a moved page is
  left behind. `tools/check_generic.sh` stays clean: no operator, product, account, person or host
  name enters any new page, and none enters the record through an issue (D5).

- **Rebuilding the release-note, tag, GitHub-Release or CHANGELOG path.** All four exist and are
  tested (`asf/metrics/metrics.py:1367-1409, 1181-1205, 1331-1364`; `tests/test_metrics.py`). The
  gate is added *in front of* `cut_tag`; nothing downstream of it changes.
- **Extending `asf readme`'s span grammar, budget or link rule to a second page.** That instrument
  is F-0030's, it is one page, and its link rule is repo-root-relative by design. `asf docs check`

- **An in-page anchor generator, a static-site build, a docs theme, a published site.** "The docs
  build" in this repository means `asf docs check` exits 0. No HTML is produced.
- **A new tick step, a new clock, or a new metrics stream.** The pull and the reply run inside the
  `groom` step; the ledger is the item's own `## History`.
- **Reading an issue's author, assignees, reactions or comments.** Number, title, labels, body and
  URL, and nothing else (D5).
- **Acting on an issue.** An issue creates an *undecided* card (`decided: false`, as every intake
  card is) and can never launch a session, decide a card, set a severity above the default, or mint
  an Epic. A stranger's text reaches the groom as text to be decided, never as work to be done.
- **Closing, labelling or editing the issue.** One comment, on landing. The issue's own state stays
  the reporter's and the operator's.
- **A discussion board, a mailing list, a chat channel, a form on a website.** The card says GitHub
  issue templates; that is the channel.

### 2.2 `asf docs check`

`asf/docs.py`, registered through `asf.cli`. Stdlib only, read-only, and it opens nothing outside
the repo root.

```
asf docs check [--product P] [--at <sha>] [--json]
```

- The page set is `conventions.doc_pages` — a list of paths and globs, `DEFAULT_DOC_PAGES`
  = `['README.md', 'docs/README.md', 'docs/quickstart.md', 'docs/concepts.md', 'docs/operator.md',
  'docs/troubleshooting.md', 'docs/guide/*.md']`. It is **not** `doc_paths`, which exists to
  classify a landing branch and would sweep every spec, plan and review into the link check.
- Without `--at`, pages are read from the working tree. With `--at <sha>` every read goes through
  `git show <sha>:<path>` and every link target through `git cat-file -e <sha>:<target>` — no
  checkout, the same shape `asf.customer_content.tree_hits` uses to scan a tree at a sha. That is
  the form the tag gate calls (§2.7).
- `link_complaints(pages, read, exists)` is the one resolver, injected with those two readers so the
  worktree form and the `--at` form share every rule. A target is skipped when it is empty, an
  in-page anchor with no path, absolute, `~`- or `$`-prefixed, or carries a URL scheme
  (`asf.views.readme._skip_target`'s rule, reused as a function).
- `anchors(text)` slugs every `#`-heading GitHub's way (D2): lower-case, drop everything that is
  not a word character, a hyphen or a space, then one hyphen per space. Runs are not collapsed.
- Output is one line per complaint, `path:line: what`, then `docs: N complaint(s)` and exit 1; or
  `docs: clean — <n> pages, <m> links` and exit 0. `--json` prints
  `{"ok": bool, "complaints": [{"path", "line", "what"}], "pages": n, "links": m}`.

### 2.3 `doctor.ROWS`

```python
#: Every row `run` can put in the doctor's table, in table order, with what a red one means.
ROWS = (
    ('config', 'the operator config and the product file parse and name what they must'),
    ('repo', 'the product repo is where the product file says it is'),
    ...
)
```

`run` appends by these names. `doctor.row_names()` returns the tuple's first column;
`asf docs check`'s check 3 requires a `### <name>` heading per name in the troubleshooting page,
and `tests/test_doctor.py` walks `asf/doctor.py` with `ast`, collecting the first element of each of
`run`'s 34 `append` calls — 33 string literals and one f-string, whose literal prefix `cli:` stands
for the one row family the CLI probe fans out (`cli:git`, `cli:gh`, …) — and asserts the set equals
`row_names()`. A new doctor row is therefore red in CI until it has both a `ROWS` entry and a
heading.

### 2.4 The templates

`.github/ISSUE_TEMPLATE/` — GitHub's own path, a forge convention, not a product's:

| File | Title prefix | Labels | Fields |
| --- | --- | --- | --- |
| `bug.yml` | `bug: ` | `feedback`, `bug` | what happened; what was expected; `asf --version`; the doctor row, if any |
| `idea.yml` | `idea: ` | `feedback`, `idea` | what you wanted to do; why the factory cannot do it today |
| `install.yml` | `install: ` | `feedback`, `install` | the OS and version; the command run; the output; `asf doctor`'s failing row |
| `config.yml` | — | — | `blank_issues_enabled: false`, and one contact link to the public record |

Every field is `required: true` except the optional doctor row, so an issue that reaches the intake
has the four facts the intake needs. No field asks for a name, an account or a path.

### 2.5 `asf feedback sync` — in

```python
def pull(root, product, items, conv, day, gh_json=metrics.gh_json):
    """Every open `feedback.label` issue no item and no intake file carries → one intake card.
    Returns the paths written."""
```

- `gh issue list -R <feedback.repo or repo_slug> --state open --label <label> --limit N
  --json number,title,labels,body,url`. `None` (offline, no `gh`, a refused scope) is one line on
  stderr and an empty return — the tick carries on, exactly as `publish_github_release` does.
- An issue is skipped when any item's `links.issues` holds its number, when
  `<intake_dir>/issue-<n>.md` exists, or when `<intake_dir>/done/` holds a file whose `issue:`
  header is that number. The first is the steady state; the second and third close the window
  between the file being written and the item existing.
- The card written is the shape `asf inbox` writes, plus one header:

```markdown
# bug: asf doctor's worker secrets row stays red after install

issue: 412
type: bug
severity: S3

Reported on issue #412 — https://github.com/<slug>/issues/412

## Reported

> asf doctor --product demo prints RED worker secrets after a clean install.
> I ran claude setup-token and the row did not change.
```

  The title is the issue title with the template's prefix kept; both title and body go through
  `redact.scrub(text, redact.default_patterns(root))`, `@mention`s are replaced with the same
  token, and the body is cut to `max_body_lines` with a `> … (<k> more lines on the issue)` last
  line. `type:` comes from `feedback.types[label]`; an `idea` writes **no** `type:` header, so
  `asf.groom.shape.derive` shapes it or asks its question, and a human answers.
- At most `max_per_tick` cards per run, lowest issue number first, so a flood arrives over several
  ticks in the order it was reported.
- Each file is written and `publish`ed the way `cmd_inbox` publishes
  (`asf/groom/inbox.py:150`), so the record's clone and the trunk both carry it.
- `asf.groom.inbox.INBOX_KV_RE` gains `issue`, and `process_inbox` puts it into the minted item's
  typed fields as `links: {issues: [<n>]}`. `## Reported` is body, like any other section: the
  existing `_lift_section` calls are untouched.

### 2.6 `asf feedback sync` — out

```python
def reply(root, product, items, conv, day, gh=metrics.gh):
    """One comment per landed item that carries an unanswered `links.issues`. Returns [(id, n)]."""
```

- An item qualifies when `links.issues` is non-empty, its state is in
  `metrics.LANDED_STATES`, and its `## History` carries no `feedback replied (issue #<n>)` line.
  With `feedback.ack` on (D8), an item whose History carries no `feedback acknowledged` line and
  which is not yet landed gets the intake comment instead.
- The comment is rendered from the index alone — no release read, no second forge call:

```
F-0108 — release 0.1 for feedback … landed (Resolved).

Tracked in the public record as F-0108; the change is in #224.
```

  A `Closed` item with no `links.prs` reads `closed without a change` instead of `landed`, because
  that is what happened and a reporter is owed the true one.
- `gh issue comment <n> -R <repo> --body-file <tmp>`. On failure: one stderr line, no History
  write, and the next tick retries — the History line is written only after the comment is posted,
  so the failure mode is a retry and never a silent drop.
- The History line is appended through `asf.record.ingest.append_history_lines` and the item is
  published in the same commit shape the groom uses.
- `step_groom.run` calls `feedback.sync(...)` before `cmd_groom`, inside its own
  `try`/`except Exception` that prints one `feedback:` line and returns — the channel is never the
  reason a tick fails to groom.

### 2.7 The tag gate

In `_cut_trunk_release`, between `found = commit_items(...)` and `tag = tags_at(...)`:

```python
ok, why = release_gate(product, new, root)
if not ok:
    print(f"release: not cutting a tag at {new[:7]} — {why}", file=sys.stderr)
    return None
```

`metrics.release_gate(product, sha, root)` → `(bool, reason)`:

1. **The install test.** `release.ci_runs(slug, product.main, 1, gh_json)` for the finished run at
   `sha`, then `release.ci_steps` and `release.step_state(steps, cfg['ci_steps']['install_from_zero'])`.
   Not found ⇒ refuse, `"the install-from-zero step did not run"`. Found and not green ⇒ refuse,
   naming it. A product with no CI provider, or an empty `ci_steps.install_from_zero`, skips this
   half — it has no forge to ask.
2. **The docs.** `docs.check_at(product.repo_dir, sha, conv)`; any complaint ⇒ refuse with the
   first three and the count.
3. The forge not answering at all is *not* a refusal to cut — it is `"could not read CI"` and a
   refusal to decide, which is the same `None` return and the same retry next rollup. A tag is
   never cut on an unread gate, and a network blip never fails a release permanently.

An already-tagged sha (`tags_at(repo, new)[0]`) is not re-gated: the tag exists, and the gate's job
is to stop a new one.
