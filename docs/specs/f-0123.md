# F-0123 — a dated plan file mints no Tasks after it lands

A plan on the trunk is the factory's work order: the record turns every `### Task N:` heading
into a Task card and the feeder launches coders from those cards. A Feature whose plan landed
but whose Tasks were never minted sits at `plan-approved` for ever with nothing to launch, and
nothing anywhere says why. That is what F-0019 did: its plan landed as
`docs/superpowers/plans/2026-09-20-free-plan.md` from `cloud/plan-F-0019` and minted nothing,
while F-0079's `f-0079.md` minted all fourteen.

**Most of that is already fixed, and this spec says so with evidence rather than re-specifying
it.** `fix(evidence)` (16a18e0c3, "dated plans mint") and `fix(B-0114)` (b0c711c87) gave the
matcher three routes from a plan back to its Feature, and gave the mint gate two of them. All
twelve tests in `tests/test_doc_lane_landing.py` pass in this worktree, including the card's
stated acceptance.

**One route is still missing from the gate, and it is the route the card names second.** The
matcher (`asf/record/ingest.py:117`, `_own_candidates`) reaches a Feature from a plan whose own
H1 names it — `# F-0019 — Free plan` — through the document's `alias`. The mint gate
(`asf/record/plan_tasks.py:52`, `own_lane_plan`) does not: it knows the id-shaped file name and
`lane_docs`, and nothing else. For a card that is not `decided: true` the two disagree, and the
disagreement is exactly the original bug.

Reproduced live in this worktree against the suite's own fixture (a bare origin, a dated plan
whose only id carrier is its H1, no lane branch, no PR, no ledger run):

```
lane_docs: {}
minted: ['T-38950', 'T-38951']
   T-38950 F-0300 {'plan': 'docs/plans/2026-09-25-thing-plan.md'}
   T-38951 F-0300 {'plan': 'docs/plans/2026-09-25-thing-plan.md'}
F-0300 Active plan-approved | ['spec on origin/main', 'plan on origin/main', 'rule: documented']
F-0301 Active plan-approved | ['spec on origin/main', 'plan on origin/main', 'rule: documented']
own_lane_plan(F-0300, dated, header-only): False
```

F-0300 (`decided: true`) mints because the `decided` short-circuit at
`asf/record/plan_tasks.py:97` runs before the gate is consulted at all. F-0301, identical but
undecided, reaches `plan-approved` and mints **nothing** — and prints nothing. The gate refused
it, and the refusal has no voice: the only `out(...)` on a skip path is the "no `### Task N:`
heading" line at `:105`.

So three things change: the gate learns the header route from the same reader the matcher uses;
a plan on the trunk that mints nothing says why; and the plan briefs ask for the header, so the
route is populated by every plan the factory writes from here on.

### In scope

1. **The mint gate's third route.** `own_lane_plan` is renamed `own_plan` and gains a third
   route: the plan document at `ref` whose `alias` — its H1 — is this Feature's id. An
   undecided Feature whose dated plan names it only in its header mints its Tasks.
2. **The skip says why.** Every path on which `_mint` declines to mint for a Feature **whose
   plan is on the trunk** prints one `plan-tasks: <FID>: …` line naming the plan and the reason.
   Today only one of the four such paths speaks.
3. **The plan briefs ask for the header.** `plan.md`, `delivery-plan.md` and `spec-plan.md` each
   state the H1 the plan opens with — `# <ITEM> — <title>` — in the form `H1_ALIAS` reads, so
   the header route is populated rather than merely available.

### Out of scope

- **Renaming or moving the dated plan files already on the trunk.** The point of this Feature is
  that the record resolves them where they are.
- **`match_feature`, `_own_candidates`, `lane_docs`, `merge_facts`, `id_evidence`.** They are
  P1/P2/P4 and they work. The gate is brought up to the matcher, not the other way round.
- **A new invariant or a doctor row** for "plan-approved with no Task children" — see D4.
- **Back-filling Tasks for a Feature whose plan names it nowhere** — no file name, no lane
  branch, no PR, no ledger merge fact, no header. There is no evidence to resolve; the change is
  that the record now *says* so (scope item 2) instead of staying silent.
- **`asf migrate`.** It is a one-off against a legacy record and mints by its own path.
- **The `decided: true` short-circuit at `:97`.** It stays exactly as it is: a decided card is
  work the operator ordered, and its plan on the trunk mints whatever route found it.

### The choices

| # | Chosen | Against | Why |
| --- | --- | --- | --- |
| **D1** | The gate reads the header from the **evidence** — the `alias` of the `features` entry whose `plan` path is `ref` — not from the plan text. | Re-reading the plan blob in the gate and matching an H1 with its own regex. | **One reader.** The route that brings the Feature to `plan-approved` (`_own_candidates`, `ingest.py:136`) and the route that mints must be the same test, or they can disagree again — and a disagreement between them *is* this bug. A second H1 regex in `plan_tasks` would drift from `H1_ALIAS` (which requires an em-dash, en-dash or hyphen after the token: `# F-0019: Free plan` is not an alias) and the drift would show up as the original silent symptom. It is also free: the alias is already computed in the evidence blob, where reading the text costs a `git show` per skipped Feature, on every tick, for every migrated milestone plan a record links. |
| **D2** | Match `alias.upper() == fid.upper()` **exactly**, against the entry whose plan path is `ref`. | Any looser match — a prefix, an alias stem, the H1 containing the id anywhere. | An exact match cannot mint one Feature's Tasks onto another. It also keeps the migrated-record floodgate shut, which is the reason the gate exists: the fixture's legacy milestone plan `2026-09-03-m3-infra.md` opens `# M3 — infra`, alias `M3`, and no card is called `M3` — so it still mints nothing for the undecided F-0026, as `tests.test_doc_lane_landing` already asserts. |
| **D3** | Look the alias up **by plan path** across `ev['features']`, not off the merged `fev` the caller already holds. | `fev['alias']`, which `_mint` has in hand. | `_merge_docs` (`ingest.py:97`) copies only `DOC_FIELDS` — `alias` stays the **primary** match's, which may have been matched by a spec, a legacy id or a branch and whose alias then belongs to a different document. It happens to be right in the fixture above and that is luck, not design. The entry whose `plan` is this path is the entry whose alias was read from this plan. |
| **D4** | The surface for "a plan landed and minted nothing" is **one `out(...)` line in the tick's `plan-tasks` step**. | A new record-scope invariant (`I14`), or a doctor row. | A record-scope invariant refuses a write (`asf/record/stage.py:168`) and the tick files a Bug per finding — but the condition is legitimate for a plan that genuinely carries no `### Task N:` heading (a `spec-plan` document's spec half, a NO-CHANGE plan), so it would refuse nothing and file noise. The `plan-tasks` step already speaks on one path; making the other three speak in the same form is the smallest change that turns a silent skip into a fact somebody can read, and it needs no new machinery. |
| **D5** | The gate is renamed `own_lane_plan` → `own_plan`, and its docstring restated. | Keeping the name and widening the docstring. | With the header route the predicate is no longer "the lane's own document" — a plan whose H1 names the Feature may have arrived by no lane at all. The name would lie about the thing that just changed. The cost is exactly one call site (`:97`) and no test: `grep -rn own_lane_plan` finds it nowhere outside `asf/record/plan_tasks.py`. |
| **D6** | The brief change is **one stated line per template**, pinned by a test, with no lane gate. | A lane gate that refuses a plan branch whose document has no id-naming H1. | Every plan already on the trunk predates the rule and a gate would refuse legitimate re-work on them; and by P3 the factory's own plans are id-named files, so the header is belt-and-braces, not the load-bearing route. A test that the templates state it — and that `H1_ALIAS` reads what they state — is the right weight. |
| **D7** | Scope item 2 speaks **only when a plan is on the trunk** (`plan_ref` returned a ref). | A line for every Feature the pass skips. | A record's Features are mostly at `card`/`spec-draft` with no plan anywhere; a line each would bury the four that matter. `has_task_child`, the done states and the retired cards stay silent too — those are the normal, correct no-ops. |

## The design

### 1. `asf/record/plan_tasks.py` — the gate's third route

`own_lane_plan(fid, ref, ev)` at `:52` becomes `own_plan(fid, ref, ev)` with three routes. The
first two are unchanged, byte for byte; the third is new:

```python
def plan_alias(ev, path):
    """The id the plan at `path` declares in its own H1, as the evidence read it — the `alias`
    of the features entry that carries this plan — or None."""
    from asf.record.ingest import _path_only
    for f in ((ev or {}).get('features') or {}).values():
        if _path_only(f.get('plan')) == path:
            return f.get('alias')
    return None


def own_plan(fid, ref, ev):
    """True when the plan at `ref` declares this Feature, by any of the three routes the matcher
    knows: named after its id (`f-0047.md`); landed by a merged spec/plan lane PR — or a
    fast-forward lane the ledger records — whose branch names it; or headed `# F-0047 — …`,
    whatever the file is called (F-0123).

    These are the same three routes as :func:`asf.record.ingest._own_candidates`, read through
    the same evidence: a plan that brings a Feature to plan-approved is a plan that mints."""
    path = ref.split(':', 1)[1] if ':' in ref else ref
    name = path.rsplit('/', 1)[-1]
    if evidence.doc_slug(name).lower() == fid.lower():
        return True
    if path in (((ev or {}).get('lane_docs') or {}).get(fid.upper()) or {}).get('plan', []):
        return True
    return str(plan_alias(ev, path) or '').upper() == fid.upper()
```

`_mint`'s call at `:97` becomes `... and not own_plan(fid, ref, ev)`. Nothing else in `_mint`'s
control flow moves: the `decided` short-circuit still runs first, and the gate is still consulted
only for an undecided card.

`plan_alias` is a module-level function so the test can exercise the route directly, the way
`stories_of`, `has_task_child`, `plan_ref` and the gate itself already are.

### 2. `asf/record/plan_tasks.py` — the skip says why

`_mint` has four paths on which a Feature with `plan_ref` set mints nothing. One speaks; three
are silent. All four speak, in the existing `plan-tasks: <FID>: …` form:

| Site | Condition | The line |
| --- | --- | --- |
| `:97` | the gate refused an undecided card | `plan-tasks: F-0301: docs/plans/2026-09-25-other-plan.md is on the trunk but names F-0301 nowhere — not decided, so nothing minted` |
| `:100` | `read_ref` returned nothing | `plan-tasks: F-0301: docs/plans/2026-09-25-other-plan.md could not be read — nothing minted` |
| `:105` | no `### Task N:` heading | *unchanged, byte for byte* — the one existing line, asserted at `tests/test_plan_tasks.py:96` |
| `:122` | Tasks minted | *unchanged, byte for byte* — asserted at `tests/test_plan_tasks.py:85` |

`plan_path` is computed once, above the gate, instead of at `:102`, so the two new lines can name
it; the value is identical.

The `continue` at `:92` (`not ref` — no plan on the trunk) stays silent, per **D7**, as do the
skips above it (`has_task_child`, `DONE_STATES`, `is_retired`).

The two existing assertions on `self.lines` in `tests/test_plan_tasks.py` are exact-equality
against a one-line list, so they constrain the wording of the existing lines and must keep
passing untouched.

### 3. The plan briefs ask for the header

One line, in the same place in each of the three templates that produce a plan document — under
the `DELIVERABLE:` line, before the shape:

```
The document opens with `# {item_id} — <title>`: the record reads that heading to tie the plan
back to this card when the file name does not (a date-prefixed name does not).
```

- `asf/briefs/templates/plan.md` — after `:7`.
- `asf/briefs/templates/delivery-plan.md` — after `:7`.
- `asf/briefs/templates/spec-plan.md` — after the `{plan_path}` bullet at `:9`, naming
  `{plan_path}` as the document it applies to (that brief writes two files).

`{item_id}` is already in the render context, so `PlaceholderTest` holds. The three goldens
`tests/fixtures/briefs/golden/{plan,delivery-plan,spec-plan}.md` are regenerated with
`ASF_UPDATE_GOLDEN=1`; the regenerated text is part of the change, and `GoldenBriefTest` is what
makes the new line visible in review.

The em-dash is the one `H1_ALIAS` reads (`[—–-]`); a colon is not. The test asserts that, so the
brief cannot quietly drift to a form the record does not read.

## Records

What the change writes down, and what it does not.

**Cards.** Task cards, of exactly the shape `_mint` writes today — `parent` the Feature, `writes`
from the section's `writes:`/`Files:` line, `stories` from its `stories:` line, `links.plan` the
plan's path **as it is on the trunk, date prefix and all**, `decided: true`, the section text as
the description, `after` from `plan_order`. The only difference is *which* Features get them: one
more class of Feature — undecided, dated plan, id in the header — now does. Ids come from
`mint_id`, through `stage.guarded`, as today.

**No new fields, no new files, no new events.** No frontmatter key is added; no card is rewritten;
no document is renamed or moved; `lane_docs`, `merge_facts` and the evidence cache keep their
shapes.

**The tick's `plan-tasks` step output** gains two line forms, in the existing
`plan-tasks: <FID>: …` shape (the table in design §2). This is the change's operator-visible
record: a Feature at `plan-approved` with no Tasks now has a line saying which plan was found and
why it minted nothing, where today it has silence.

**Three brief templates and their three goldens** change by one sentence each — a record in the
repo of what a plan document is asked to open with.

**Nothing is written for a Feature the pass already skips**: a Feature with a Task child, a done
or retired card, or a Feature with no plan on the trunk is untouched and unmentioned, exactly as
today.
