# F-0073 — Everything enters through the inbox; the type is derived from the card's shape

Epic: E-0001 — ASF 0.1 — a working factory. Branch: `spec/F-0073`.

Today there are two ways into the record, and in both of them somebody decides the type by hand.
`asf new epic|feature|bug` mints whatever type it is told to (`asf/record/new.py:48-159`). The
inbox intake either honours a `type:` line or guesses the type from words: `broken|red|fails` →
Bug, `goal` → Epic, everything else → Feature (`asf/groom/inbox.py:8-21,82-88`). None of these
paths checks that the card is the size its type claims. On 2026-09-21 F-0071, F-0072 and
S-0001–S-0004 were filed with `asf new` while the operator answered live. The rule broken there
was a remembered one; this card makes it code.

After this change, new work enters the record in one way: an untyped card in the record's intake
directory (`asf inbox` writes one). The groom reads the card's shape — which lines it carries,
which sections, what its parent is — and the shape decides the type. The type is written down
together with the rule that gave it, and `asf check` holds the card to that type's size for the
rest of its life. Stories and Tasks are the one exception. They are cut from an approved spec or
plan, so `asf new story|task` still mints them, but only with the lines that make up their shape.

## Decisions

### In

- **Shape rules** in a new module `asf/groom/shape.py`. `derive(card, canonical,
  default_bug_parent)` returns either `Shape(type, rule, parent)` or `Question(text)`. It is a
  pure function over the parsed card and the record, and the only place a type is chosen.
- **The inbox intake** (`asf/groom/inbox.py`) calls `derive`. It no longer reads a `type:`
  line as the type, and it no longer guesses from words. `INBOX_TYPES`, `infer_inbox_type`,
  `BROKEN_WORDS_RE` and `GOAL_WORD_RE` go. The defect words survive only to trigger a question
  (D5).
- **`asf inbox --title T [--body-file F] [--parent ID]`**, a new CLI command. It writes one
  untyped card into the record's intake directory and prints the card's path. It has no
  `--type` flag.
- **`asf new`** refuses `epic`, `feature` and `bug` with exit 2 and a line naming `asf inbox`.
  `story` needs `--parent <Feature>` and at least one `--acceptance`. `task` needs `--parent
  <Feature|Story>` and at least one `--writes`. `decision` and `rule` are unchanged.
- **The record keeps the reading.** A card that was minted by reading its shape carries a
  History line `created (<origin>) — shape: <rule> → <type>`. The groom file's inbox line names
  the type and the rule, so the operator sees the reading on the day they decide the card.
- **`asf check` checks size.** Every item whose History carries `— shape:` is checked against
  its type's size rule (the table in *The design*). A card that breaks the rule is a finding, as
  a missing parent is today.
- **One intake directory.** `asf inbox` and `process_inbox` both read
  `conventions.intake_dir`, which defaults to `inbox`. Today `process_inbox` hard-codes
  `'inbox'` (`asf/groom/inbox.py:67`), even though `DEFAULT_INTAKE_DIR` exists
  (`asf/conventions.py:47`).
- The suites that use `asf new epic|feature|bug` to build fixtures move to `write_item`, to
  `asf inbox` + `asf groom`, or to `asf new story|task`.

### Out

- **`asf file-bugs`.** It keeps minting Bugs directly (`asf/tick/file_bugs.py:198`). Its
  input is a signature by construction, so its shape is already the Bug shape. Routing it
  through the inbox would put a day's groom delay in front of an S1, and its signature
  deduplication would stop working. It writes the History line `created (file-bugs) — shape:
  signature → bug`, so `asf check` covers what it files.
- **`asf migrate`.** It adopts types the source repo already carries. Adoption is not new work.
- **Decisions and Rules.** They are not work items and have no size. `asf new decision|rule`
  is unchanged.
- **Re-typing a card after it is minted.** If the groom reads the shape wrong, the operator
  answers `no` (the card is closed) and files the card again with the shape fixed. There is no
  `retype` answer (D8).
- **Model-based typing.** The rules are deterministic. The research note's "inbox type as a
  `choice`" (`docs/research/jev-decision-model.md:143`) is a later card, and it would replace
  `derive`'s body, not its contract.
- **An `/asf:inbox` plugin skill.** `asf inbox` is a write command, not a view or a dialogue
  (`asf/plugin_build.py:33-36`), so the plugin does not change.
- **Grandfathering the existing record.** Items without a `— shape:` History line are not
  checked for size. Nothing is back-filled (D6).
- **Committing.** `asf inbox` writes the file and commits nothing, the same as `asf new` today.
  The record's commit path does not change.

### Preconditions (checked against `origin/main` at `b0a50d2`)

- `asf index` rewrites only `## Children` and `## Backlinks` (`asf/record/core.py:234-250`).
  Other sections in a card body — `## Features`, and an `## Acceptance` that has items — survive
  a re-index untouched.
- `inbox_origin_ids` matches on the substring `created (inbox)` (`asf/groom/groom.py:121`).
  The new History line `created (inbox) — shape: …` still contains it, so the groom's
  "Inbox cards to decide" section keeps finding inbox cards.
- `write_new_item` writes `## Description\n{body}` and then an empty `## Acceptance\n- [ ] `
  (`asf/record/ids.py:75-83`). A card whose body carries its own `## Acceptance` would end up
  with two of them, so `write_new_item` must take the acceptance items separately (see *The
  design*).
- The frontmatter parser turns `writes: a/**, b.py` into a list (`frontmatter._parse_value`), and
  `asf check` already reads a Task's `writes` as a list (`asf/record/check.py:144-160`).
- `mint_id` raises in a linked worktree without `BACKLOG_ID_RANGE` (`asf/record/ids.py:35-37`).
  The groom runs in the tick's record clone, not in a worktree, so intake minting is unaffected.
  A session that files work runs `asf inbox`, which mints nothing.
- The spec and plan briefs already tell sessions to mint Stories and Tasks from their range
  (`asf/briefs/templates/spec.md:22`, `plan.md:25`). No brief names `asf new epic|feature|bug`.

### Choices

| # | Choice | Chosen | Against | Why |
|---|---|---|---|---|
| D1 | What "shape" is | Header lines (`signature:`, `writes:`, `parent:`), sections (`## Acceptance`, `## Features`) and the parent's type | Word lists, title length, a model's reading | The card says the type is "a statement about size that the code can check". Each of these is a fact that `asf check` can read again later. A word is not a fact about size. |
| D2 | Rule order | `signature` → `writes` → `features-list` → `parent-feature` → `default` (Feature). A card that carries both `signature:` and `writes:` gets a Question. | Score every type and take the best | First match is explainable in one word, and that word is what the History line records. The only real ambiguity (a defect that also names its fix footprint) is asked, not guessed. |
| D3 | Epic threshold | `## Features` with ≥ 2 bullets | ≥ 1; a word such as `goal` | The card defines an Epic as an outcome "spanning several Features". With one bullet the card is a Feature, and the groom says so in the rule. |
| D4 | A `type:` line in the card | Not read as the type. If it disagrees with the shape → Question naming both. If it agrees → filed, and the line is dropped. | Honour it (today); always refuse it | Honouring it is the hand-typing the card retires. Refusing a line that agrees would punish a correct card. Filing a disagreement quietly would overrule a human who can't see why. |
| D5 | The defect words (`broken`, `red`, `fails`, `failing`) with no `signature:` | Question: add a `signature:` to file a Bug, or an `## Acceptance` list if it is new work | Mint a Bug with no signature (today); mint a Feature | The card says a Bug is "a defect with a signature". A signature-less Bug fails D6's check on its first day. Filing a defect report as a Feature would put it behind a spec and a plan. |
| D6 | Which items `asf check` holds to size | Items whose History carries `— shape:` | Every open item; a date cut-off; a schema bump | The existing record was typed by hand and never promised a shape. Checking it would turn `asf check` red on history. The History line is the record's own statement that "this was typed by shape", and it needs no new field or migration. |
| D7 | `asf new` | Refuse `epic`, `feature`, `bug`. Keep `story` and `task`, each with the lines that make up its shape. | Remove `asf new`; keep all types behind `--force` | Stories and Tasks are cut from an approved spec or plan. Their parent and footprint are known, and the spec/plan review already reviewed their size. Epics, Features and Bugs are *new* work: that is the case the card covers. `--force` would bring back the hand path. |
| D8 | A wrong reading after intake | Operator answers `no`; refile with the shape fixed | A `retype <type>` groom answer | Re-typing moves the file, re-mints the id and rewrites the links. A second path to set a type by hand is what the card removes. The cheap fix is to correct the card, not the type. |
| D9 | A Feature card with no parent | Infer the open Epic with the most shared title words (today's `infer_parent_epic`), else a Question | Always ask | This is unchanged behaviour. The parent is not the type, and the operator still confirms the card in the groom. |
| D10 | Where a session files work it finds | `asf inbox` into the record, the same record `asf new` resolves (`resolve_record`) | A `NEEDS OPERATOR` line; a `## Found` report section | One path in, for humans and sessions alike. The record path resolution is already shared, and it is tested (`tests/test_path_resolution.py`). |
| D11 | A card that is a Story by shape but has no `## Acceptance` items | Question | Mint it with an empty checklist | The card defines a Story as "one PR with one acceptance list". An empty list is not one. |

## The design

### The card

An inbox card is one markdown file in `<record>/<intake_dir>/`. It looks like this:

```markdown
# <title>
parent: <id>            # optional
signature: <text>       # optional — a defect's key (failing test, error line)
severity: S1|S2|S3      # optional, Bug only; default S3 (today's default)
writes: <glob>, <glob>  # optional — a one-session footprint
stories: <id>, <id>     # optional, Task only
type: <word>            # optional, never the type (D4)

<description>

## Features             # optional — the Features an Epic spans, one bullet each
- …

## Acceptance           # optional — one checklist
- [ ] …
```

The header lines are the lines between the title and the first body line, as
`parse_inbox_file` reads them today. `INBOX_KV_RE` widens from `type|parent` to
`type|parent|signature|severity|writes|stories`.

### `asf/groom/shape.py` (new)

```python
Shape = namedtuple('Shape', 'type rule parent')
Question = namedtuple('Question', 'text')

SIZE = {  # the card's definitions, in one place; the History line and asf check quote them
    'epic': 'a business outcome spanning several Features',
    'feature': 'one spec and one plan, landing as one deployable thing',
    'story': 'one PR with one acceptance list',
    'task': 'one session in one worktree with a writes: footprint',
    'bug': 'a defect with a signature',
}

def derive(card, canonical, default_bug_parent=None) -> Shape | Question
```

`card` is the parsed inbox file: `title, headers{}, description, features[], acceptance[]`.
The rules are tried in order, and the first that applies decides:

| rule | applies when | type | parent must be | otherwise → Question |
|---|---|---|---|---|
| — | both `signature:` and `writes:` | — | — | `A card is one thing: signature: makes it a Bug, writes: makes it a Task — drop one.` |
| `signature` | `signature:` present | bug | `parent:` if given (any existing item of a type in `PARENT_TYPES['bug']`), else `default_bug_parent` | `Which item is this Bug under? Add a parent: <id> line.` (today's text) |
| `writes` | `writes:` present | task | `parent:` naming a Feature or Story | `A Task hangs under a Feature or a Story — add parent: <id>.` |
| `features-list` | `## Features` has ≥ 2 bullets | epic | no `parent:` | `An Epic has no parent — drop the parent: line, or it is a Feature under that Epic.` |
| `parent-feature` | `parent:` names a Feature | story | that Feature | if `acceptance` is empty: `A Story is one PR with one acceptance list — add an ## Acceptance checklist.` (D11) |
| — | `parent:` names a Story | — | — | `Under a Story only a Task hangs — add a writes: line, or parent the card to the Feature.` |
| — | defect words, no `## Acceptance` (D5) | — | — | `This reads as a defect. A Bug carries a signature — add signature: <the failing test or error line>; or an ## Acceptance list if it is new work.` |
| `default` | anything else | feature | `parent:` naming an Epic, else `infer_parent_epic` (D9) | `Which Epic is this under? No open Epic shares a title word with it.` (today's text); a `parent:` that doesn't exist or isn't an Epic → `` `parent: X` is a <type> — a Feature hangs under an Epic.`` |

Then the `type:` line (D4): if it is present and differs from `Shape.type`, the result is
`Question("`type: X` is not read — the card's shape reads as <type> (<rule>: <SIZE[type]>). Remove the line, or change the shape.")`.

A `parent:` that doesn't exist gets the same question as today, whichever rule is being tried.

### `asf/groom/inbox.py`

- `parse_inbox_file(text)` returns a `Card` with `title, headers, description, features,
  acceptance`. `## Features` and `## Acceptance` are lifted out of the body. Everything else is
  the description.
- `process_inbox(root, canonical, date, default_bug_parent=None, intake_dir='inbox')`:
  - Skips a file that already has a `## Question`, as today.
  - `derive(...)`. A `Question` is appended as `## Question\n<text>` and the file stays in
    place (today's mechanism).
  - A `Shape` is minted with `mint_id`, then `write_new_item(..., why=f"inbox) — shape:
    {rule} → {type}", acceptance=card.acceptance, sections={'Features': card.features})`.
    Typed fields: `title`, `parent`, `decided: false`. Bug also gets `severity` (header, or S3),
    `found_in: dev` and `signature`. Task also gets `writes` and `stories`.
  - Moving the file to `inbox/done/<slug>.md` with the `→ <id>` first line stays as today.
- Removed: `INBOX_TYPES`, `infer_inbox_type`, `BROKEN_WORDS_RE` (it moves into `shape.py` as
  `DEFECT_WORDS_RE`, used only for D5's question), `GOAL_WORD_RE`.

### `asf/record/ids.py`

- `write_new_item(root, canonical, type_, new_id, typed_fields, body, date, why,
  acceptance=(), sections=None)`:
  - `## Acceptance` takes one `- [ ] <item>` line per item, or today's single empty `- [ ] `
    when there are none.
  - `sections` (an ordered map, heading → bullets) is written between `## Description` and
    `## Acceptance`. It is used only for `## Features`.
  - The History line stays `- {date}: created ({why})`. The callers put the `— shape: …` part
    into `why`, so the line reads `- 2026-09-22: created (inbox) — shape: default → feature`.
- `asf/tick/file_bugs.py:199` passes `why="file-bugs) — shape: signature → bug"`. This is the
  same string format, and the History line reads `created (file-bugs) — shape: signature → bug`.

### `asf/groom/groom.py`

- `groom_inbox_section` reads the `— shape: <rule> → <type>` line from the card's History. Each
  line's why becomes `from inbox as <type> (<rule>), awaiting a decision`. When no shape line is
  present (a card filed before this change), the why stays `from inbox, awaiting a decision`.
- `cmd_groom` passes `intake_dir=product.conventions.intake_dir` when the product loads, and
  `'inbox'` otherwise.

### `asf inbox` (new — `asf/groom/inbox.py:cmd_inbox`, wired in `asf/cli.py`)

```
asf inbox --title T [--body-file F] [--parent ID] [--product P]
```

- Resolves the record with `resolve_record(args, announce=_announce_stderr)`, the same way
  `asf new` does (the `record:` line goes to stderr).
- Writes `<record>/<intake_dir>/<slug>.md`: `# T`, then `parent: ID` if given, a blank line,
  and the body file's text verbatim. The body file can carry any header line or section from
  *The card*, since the groom reads the whole file. The slug is the title lower-cased, with
  runs of non-alphanumerics turned into `-`. When the name is taken, `-2`, `-3`, … is appended.
- Prints the written path, relative to the record, on stdout. Exit 0.
- Mints no id and runs no groom. The card becomes an item at the next `asf groom` (the daily
  step, or an operator's run).
- There is no `--type`. `asf inbox --type feature` exits 2 with argparse's `unrecognized
  arguments`.

### `asf new` (`asf/record/new.py`, `asf/cli.py`)

- `epic`, `feature`, `bug` → stderr `error: <type> is new work — it enters through the inbox:
  asf inbox --title "…" [--body-file F]; the groom derives its type from the card's shape`,
  exit 2, nothing written. This check runs before any other validation.
- New flags: `--acceptance TEXT` (repeatable) and `--writes GLOB` (repeatable).
  - `story`: `--parent` must name a Feature (already enforced by `PARENT_TYPES`), and at least one
    `--acceptance` is required; otherwise exit 2 with `error: a Story is one PR with one
    acceptance list — give --acceptance`. The items become the `## Acceptance` checklist.
  - `task`: at least one `--writes` is required; otherwise exit 2 with `error: a Task is one
    session with a writes: footprint — give --writes`. Written as the typed `writes:` list.
  - Both write the History line `created (new) — shape: parent-feature → story` or
    `created (new) — shape: writes → task`, so `asf check` holds them to size too.
- The Bug-only flags (`--severity`, `--signature`, `--found-in`) go, together with
  `SEVERITIES`' use in `cmd_new`. `SETTABLE['bug']` stays for `--set` symmetry but is
  unreachable. The simpler change is to drop `bug` from `SETTABLE`, and that is what this spec
  asks for.
- `asf/init.py:82`'s cheat-sheet line becomes `asf inbox --title "…"      file new work (the
  groom types it)` and `asf new story|task …      cut a Story or Task from a spec or plan`.

### `asf check` (`asf/record/check.py`)

For every item whose body's `## History` has a line containing `— shape:`:

| type | size rule | finding |
|---|---|---|
| bug | `signature` is non-empty | `<id>: bug without a signature (a Bug is a defect with a signature)` |
| task | `writes` is a non-empty list | `<id>: task without writes: (a Task is one session in one worktree with a writes: footprint)` |
| story | `## Acceptance` has ≥ 1 item with text after `- [ ]` / `- [x]` | `<id>: story without an acceptance list (a Story is one PR with one acceptance list)` |
| epic | `## Features` has ≥ 2 bullets, or the Epic has ≥ 2 Feature children | `<id>: epic spanning fewer than two Features (an Epic is a business outcome spanning several Features)` |
| feature | carries neither `writes` nor `signature` | `<id>: feature carries writes:/signature: — that is a Task's/Bug's shape (a Feature is one spec and one plan, landing as one deployable thing)` |

The finding lines use the existing `(relpath, line, message)` form. The line is the `id:`
line. The texts in parentheses are `shape.SIZE`. Only open items are checked (`is_open`): a
Closed card is not re-sized.

## Records

- **Item files.** Each card minted by intake is written by `write_new_item`, as today, into
  `epics/`, `features/`, `stories/`, `tasks/` or `bugs/`. It carries the typed fields its shape
  gives it (`signature`/`severity`/`found_in` for a Bug, `writes`/`stories` for a Task), a `##
  Features` section (Epic), and the card's own `## Acceptance` items (Story, and any card that
  had them).
- **The History line** is the record of the reading: `- <date>: created (<origin>) — shape:
  <rule> → <type>`. Here `<origin>` is `inbox`, `new` or `file-bugs`, and `<rule>` is one of
  `signature`, `writes`, `features-list`, `parent-feature`, `default`. `asf check` keys on this
  line (D6), and the groom file reads it.
- **The inbox.** `asf inbox` writes `<intake_dir>/<slug>.md`. The groom appends `## Question
  <text>` to a card it cannot type, or moves the card to `<intake_dir>/done/<slug>.md` with a
  first line `→ <id>` (unchanged).
- **The groom file.** `groom/<date>.md`'s "Inbox cards to decide" lines read `- [ ] <id>
  <title> — from inbox as <type> (<rule>), awaiting a decision → answer: ____`. The answers are
  unchanged.
- **`index.json`** carries the new typed fields as it carries every typed field. There are no
  new keys.
- **No events and no metrics.** Intake is a groom step, and the daily line `daily: groom ok —
  groom <date>: applied N, inbox M card(s) — …` stays as it is.
