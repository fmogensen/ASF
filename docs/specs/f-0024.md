# F-0024 — the factory proposes; a person approves and merges

0.1 is a working factory, not a self-improving one. Every error is already logged for learning —
the metrics streams, the bug filer, the incident Bugs — and that is where it stops: **no session
edits the set of files the factory runs under.** It may *propose* a change to that set, as a card
carrying the evidence that provoked it; a person does the change and a person merges it. The
eval-gated loop that closes this circuit is the 0.2 Epic, built on a quarter of real data.

Half the machinery is already here and unused. F-0031 built the **merge** gate: a branch whose
diff touches `conventions.amendable_paths` lands as `merge_amendable_set`, `human-now` by default,
held at the harvest until an operator grants it (`asf/harvest/harvest.py:1117`). What is missing is
the other three quarters of the policy:

- `amendable_paths` defaults to `[]` (`asf/conventions.py:157`), so today **no product has an
  amendable set at all** — the merge gate matches nothing, and `asf doctor` says so
  (`asf/approvals.py:729`). The set is named nowhere in code.
- Nothing stops a session *writing* those files in the first place. The `PreToolUse` hook
  (`asf.approvals.run_hook`) recognises secrets, the trunk push and a new Epic — not a rule card,
  not a check, not a brief.
- There is no proposal channel. A refused session today has nothing to do but print
  `NEEDS OPERATOR` and forget what it wanted to change.

This spec closes those three. It adds one module that names the set, one action class that refuses
a write to it, and one command that turns the refusal into a card with its evidence attached.

## 1. Decisions

### 1.1 In

- `asf/amendable.py` — the amendable set as six named **kinds**, each a `why` and a tuple of globs,
  resolved against a product; the one place every reader calls.
- A tenth action class, `touch_amendable_set`: `human-now`, **unwidenable** (a product yaml may not
  map it to anything else) and **ungrantable** (no hold on it ever opens the write).
- The `PreToolUse` hook recognising a write to the set — `Write`/`Edit`/`MultiEdit`/`NotebookEdit`
  by path, `Bash` by a path next to a writing token, and by command (`asf new rule`,
  `asf set R-nnnn`, `asf hooks install`).
- `asf propose` — one intake card carrying the change, its reason and its evidence, including
  `--from-hold`, which fills the card from the refusal the hook just recorded.
- `conventions.amendable_paths` becoming a three-state field: unset → the defaults in code; a list →
  that list instead; `[]` → an explicit opt-out the doctor names.
- `conventions.evals_dir` (`evals`), so the kind the 0.2 Epic fills has a place named now.
- The merge gate reading the same module, and its held line naming the proposal card.
- `asf check` refusing a Task whose `writes:` footprint reaches the set — work that could only ever
  be refused is not minted.
- `asf approvals` printing the set under the matrix; the `amendable` row of `asf doctor`.
- `sample/product.yaml` and `docs/products.example.yaml` carrying the new class and the new field.

### 1.2 Out

- **The eval-gated loop.** No proposal is measured, scored, ranked or applied. That is the 0.2
  Epic, and it needs a quarter of data this spec's records start collecting.
- **Any automatic amendment, at any level.** There is no level of the matrix at which a session
  edits the set. `touch_amendable_set` is unwidenable precisely so that an operator cannot widen it
  by accident and discover afterwards that the factory has been rewriting its own rules.
- **The factory doing the work of an accepted proposal.** A proposal becomes a Feature; the change
  itself is written by a person. Handing an accepted amendment back to a coder session is 0.2's
  question, not this one's.
- **F-0091's `asf improve`.** That pass proposes *waste* cards off the ledger; this one proposes
  *amendments* off a refusal. They overlap in exactly one line — `new.SETTABLE['feature'] |=
  {'source'}` — which both specs write and which is idempotent whichever lands first.
- **Scrubbing a captured patch.** The redaction gate (F-0075) decides: a patch whose text trips
  `redact.scan_text` is **withheld**, not cleaned, and the card says so.
- **The plugin skills, `docs/`, the specs and the plans.** They are how the factory is described,
  not what it runs under. A spec session that could not write `docs/specs/` would be no factory at
  all.
- **Widening by `job_grants`.** Those are `--add-dir` read grants (`asf/workers/spawn.py:290`);
  they do not touch the matrix, and a granted directory is still refused on write.

### 1.4 The choices

| Choice | Chosen | Against | Why |
|---|---|---|---|
| Where the set is named | a new `asf/amendable.py`: six kinds, each with its globs and one line of why | a longer `_PATH_GLOBS` entry in `approvals.py`; a list in every product yaml | Acceptance #1 is *one place*. Three readers need it (the hook, the harvest, the doctor) and one of them — the harvest — already reads it from elsewhere; a module both can import is the only shape that keeps them from drifting |
| What the kinds are | `rule_cards`, `checks`, `hooks`, `role_agents`, `briefs`, `evals` | one flat glob list | The card names six things. A kind gives each glob a reason a refusal can print, and gives `evals` a place before anything fills it |
| How the globs are spelled | derived — `core.TYPES['rule'][0]`, `hooks.CHECKS_DIR`, `hooks.GIT_HOOK_GLOBS`, `hooks.RUNTIME_SETTINGS_GLOBS`, `conv.briefs_dir`, `conv.evals_dir`, and the package-relative form of `briefs.build.TEMPLATES_DIR` | literals in `amendable.py` | A copy of a path default is a convention in code (P5). Derived, the set cannot drift from the thing it protects, and `.githooks/*` moves out of `approvals._PATH_GLOBS` into `hooks.py` so it is spelled once for both classes |
| The class name | `touch_amendable_set` | `amend_self`; reusing `touch_security` | It reads beside `touch_security`/`touch_legal` in the catalogue and pairs with the merge class already called `merge_amendable_set` |
| Its level | `human-now`, and **unwidenable**: `matrix` raises `ConfigError` on any other mapping | an ordinary mapped class; a bare constant with no class at all | The card is absolute — *no session edits the amendable set*. But the refusal must still land in the ledger, the doctor and `asf approvals`, and that machinery is keyed on a catalogue class. So: a real class, with one legal level |
| A granted hold | never opens the write — `is_granted` is not consulted for an ungrantable class, and `resolve` refuses `granted` on one | letting `asf approvals resolve … granted` release the session | Granting here would be the operator widening the policy one session at a time, which is the thing 0.1 forbids. The human answer to this refusal is a merge, not a permission |
| What closes the hold | a fourth resolution, `proposed`, written by `asf propose` | leaving it open until a human types `done` | Otherwise every tick reprints a `NEEDS OPERATOR` for a refusal the session has already answered properly. `proposed` is the answer, and it is still not `granted` |
| Whether an open hold parks the item | no — `touch_amendable_set` carries `parks: False`; the tick names it but the wave still launches the item | parking it, as every other held class does | A session that brushed the set on a side quest still has a job to finish. Parking would strand ordinary work on a refusal that has nothing to do with the item's own acceptance |
| Where a proposal lands | `<record>/<intake_dir>/propose-<slug>.md` — the groom mints the Feature | straight into `features/`; a Bug | The intake dir is the existing door for "a card someone wants filed", and it keeps a person or the groom between the factory and the backlog. A Feature is work to be planned; a Bug would need a `signature:` for a thing that is not a defect |
| The dedupe key | typed `source: amend:<repo-relative path>` | the title; a `signature:` | One open proposal per amendable file. `signature:` on a Feature is refused by `asf check` (P8), and the groom would shape the card as a Bug |
| The captured patch | the hook records the intended change in the machine-local ledger; `asf propose` copies it into the card only when `redact.scan_text` finds nothing, else writes `patch withheld — the redaction gate found N finding(s)` | scrubbing it; never capturing it; asking the session to retype it | A refused session is the only thing that knows what it wanted to write. The ledger is machine-local; the card is a git repo, so F-0075's gate decides what crosses. Asking the model to retype the diff invites it to retype it *wrong* |
| `amendable_paths` semantics | three-state: unset → the defaults; a list → that list; `[]` → opt out | the defaults always, plus the product's list | Acceptance #1 is one place, not one immovable place. A product that runs a different rule layout says so once; `[]` is a deliberate, visible opt-out rather than today's silent one |
| Turning the default on | yes, and it changes existing behaviour: a branch touching `rules/*` is now held at the harvest where it previously landed | a default that stays empty until an operator opts in | An empty default is why the F-0031 gate has never fired. "Humans approve and merge" that has to be switched on is not a policy |
| The third line | `asf check` errors on a Task whose `writes:` reaches the set | leaving it to the hook at run time | A Task minted with `writes: [rules/*]` is a session that can only be refused — an hour of Opus to reach a wall the record could have named when the plan was written |

## 2. The design

### 2.1 `asf/amendable.py` — the set, named once

```python
@dataclasses.dataclass(frozen=True)
class Kind:
    name: str      # rule_cards | checks | hooks | role_agents | briefs | evals
    why: str       # one line, printed by a refusal and by `asf approvals`
    globs: tuple   # repo-relative, the §P3 glob rule
```

```python
def kinds(product) -> tuple[Kind]:
    """The six kinds, their globs derived from the modules that own those paths (§1.4)."""
```

| Kind | Globs, derived from | Why it is in the set |
|---|---|---|
| `rule_cards` | `<rules>/*.md`, `<rules>/index.json`, where `<rules>` is `core.TYPES['rule'][0]` | the rules the factory is judged by, and the index every check reads |
| `checks` | `<rules>/*.sh`, `<hooks.CHECKS_DIR>/*` | what a rule card's `check:` runs |
| `hooks` | `hooks.RUNTIME_SETTINGS_GLOBS`, `hooks.GIT_HOOK_GLOBS` (`.githooks/*`) | which hooks fire at all — the gate over every other gate |
| `role_agents` | the package-relative form of `briefs.build.TEMPLATES_DIR` + `/*.md`; `hooks.RUNTIME_AGENT_GLOBS` (`.claude/agents/*.md`) | the standing instructions every session is launched with |
| `briefs` | `<conv.briefs_dir>/*` | the product's own briefs, as `asf/evidence/evidence.py:398` already reads them |
| `evals` | `<conv.evals_dir>/*` | empty in 0.1; named now so 0.2 has nothing to decide |

```python
def paths(product) -> tuple:
    """Every glob of the set. `conventions.amendable_paths` when the product named one — an
    empty list is a named one, and means the set is empty — else every kind's globs."""

def source(product) -> str:          # 'default' | 'yaml'
def kind_of(product, relpath) -> Kind | None
def write_target(product, tool_name, tool_input, cwd) -> tuple | None
    """`(relpath, kind)` this call would write in the set, or None — the path tools by their
    path argument, `Bash` by a word next to a `approvals._WRITING_TOKENS` token, exactly as
    `approvals.operator_config_target` reads one."""
def format_set(product) -> list      # kind | globs | why, aligned; `asf approvals` prints it
def reaches(product, globs) -> str | None
    """The first of `globs` (a Task's `writes:`) that overlaps the set — a glob intersection,
    not a file test: `rules/*` and `rules/R-0042.md` both reach `rules/*.md`."""
```

`conventions.amendable_paths`'s default becomes `None` (documented: *unset means the defaults in
`asf/amendable.py`*), and `conventions.evals_dir: str = DEFAULT_EVALS_DIR` (`evals`) joins the
field list. `approvals.merge_class` stops reading `product.conventions.amendable_paths` and reads
`amendable.paths(product)`; nothing else about the merge gate changes.

### 2.2 The class — unwidenable, ungrantable, non-parking

`ActionClass` gains two flags, both defaulting to the behaviour every existing class already has:

```python
levels: tuple = LEVELS     # the levels a product yaml may map this class to
parks: bool = True         # an open hold on it stops the wave launching the item
grantable: bool = True     # `granted` releases it
```

and the catalogue gains, between `touch_legal` and `new_epic`:

```python
ActionClass(
    'touch_amendable_set',
    "a session writing the factory's own rules — rule cards, checks, hooks, role agents,"
    ' briefs, evals',
    'human-now', ('hook',), levels=('human-now',), parks=False, grantable=False),
```

- `matrix` raises `env.ConfigError` for a level outside a class's own `levels`:
  `approvals: touch_amendable_set=auto is not a level this class takes ('human-now') — no session
  edits the amendable set (F-0024)`. Today's message for a level outside `LEVELS` is unchanged.
- `resolve(product, hold, 'granted')` raises `ValueError` when the hold's class is not grantable;
  `asf approvals resolve` prints it and exits 2.
- `RESOLUTIONS` becomes `('granted', 'done', 'dropped', 'proposed')`.
- `raise_holds` builds its returned `{item: (class, level)}` from parking classes only. A
  non-parking hold still prints its `NEEDS OPERATOR` line and still raises its `held` event once.
- `_CODE_RECOGNISERS['touch_amendable_set'] = ('the amendable set — asf approvals names it',)` and
  `_COMMAND_PATTERNS['touch_amendable_set'] = (r'\basf\s+new\s+rule\b', r'\basf\s+set\s+R-\d{4}\b',
  r'\basf\s+hooks\s+install\b')`, so the doctor's "held but unrecognisable" check stays quiet and
  the three commands that write the set without naming a path are caught.

### 2.3 The hook

In `approvals._enforce`, after the operator-config refusal (D8) and before `classify`:

```python
hit = amendable.write_target(prod, tool_name, tool_input, cwd)
if hit:
    relpath, kind = hit
    refuse(prod, item, 'touch_amendable_set', 'human-now', job, tool_name, relpath,
           kind=kind.name, patch=_intended_change(tool_name, tool_input))
    print('\n'.join(_amendable_refusal_lines(item, relpath, kind)), file=out)
    return 2
```

It is checked *before* the matrix and independently of it: a matrix that does not load must not be
the reason the set is writable (D7). `_intended_change` is the call's own payload, truncated to
8 KB — `content` for `Write`, `old_string`/`new_string` as a two-hunk diff for `Edit`/`MultiEdit`,
`new_source` for `NotebookEdit`, the command text for `Bash`.

What the session is shown — `_amendable_refusal_lines`, the one class with its own text:

```
REFUSED touch_amendable_set (human-now) on F-0024 — rules/R-0042.md (rule_cards: the rules the
  factory is judged by, and the index every check reads)
  No session edits the amendable set. The factory proposes; a person approves and merges.
  Propose it: asf propose --from-hold F-0024/touch_amendable_set --why "<one line>"
  Then print: NEEDS OPERATOR: F-0024 touch_amendable_set — <the proposal card asf propose names>
  and carry on with every part of the job that does not depend on it.
```

The other nine classes keep `_refusal_lines` unchanged.

### 2.4 `asf propose` — the card and its evidence

```
asf propose [--from-hold <item>/<class>] [--path P]... [--why LINE] [--evidence LINE]...
            [--patch FILE] [--title T] [--parent ID] [--product P] [--dry-run]
```

1. `--from-hold` reads that hold's latest `refused` line from the ledger and fills `--path` (its
   `path`), the title (`Amend <path> — <why>`) and the patch (its `patch`). An unknown or closed
   hold is an error naming `asf approvals list`.
2. `--why` is required — a proposal with no reason is not evidence.
3. The parent is `--parent`, else `conventions.default_bug_epic`; with neither, the card carries no
   `parent:` and the groom asks its one question, as intake always does.
4. The patch crosses into the record only if `redact.scan_text` finds nothing in it (§1.4).
5. The card is written to `<record>/<conv.intake_dir>/propose-<slug of the first path>.md`,
   overwriting a proposal already there for the same path — one open proposal per file:

````markdown
# Amend rules/R-0042.md — the R-0042 check misreads a multi-line writes: footprint

parent: E-0001
source: amend:rules/R-0042.md

## Description
<the --why line>

The factory may not change this file (F-0024). It proposes; a person approves and merges.

## Evidence
- refused 2026-09-23T17:41:27Z — job spec-f-0024 on F-0024, Edit rules/R-0042.md, 3 attempts
- <each --evidence line, verbatim>

## The change proposed
```diff
<the patch, or: patch withheld — the redaction gate found 1 finding(s)>
```

## Acceptance
- [ ] a person merges the change to rules/R-0042.md
````

6. The ledger gets `{"event": "proposed", "hold": …, "card": "<intake_dir>/propose-….md"}` and,
   when the call came `--from-hold`, `resolve(product, hold, 'proposed')`.
7. One line out: `proposed <intake_dir>/propose-rules-r-0042.md — 1 path, 2 evidence lines, patch
   1.2 KB (hold F-0024/touch_amendable_set resolved: proposed)`.

`--dry-run` prints the card to stdout and writes nothing, neither file nor ledger line.

`asf/groom/inbox.py`'s `INBOX_KV_RE` gains `source`, and `shape._typed` carries it onto the minted
card, so the Feature the groom mints keeps `source: amend:<path>` — the dedupe key survives the
intake. `new.SETTABLE['feature'] |= {'source'}` lets `asf new`/`asf set` write the same field by
hand (§1.2: F-0091 writes this line too).

### 2.5 The merge, which is where a human actually decides

Unchanged in mechanism, and now live because the set is non-empty: a branch whose diff touches the
set is `merge_amendable_set`, `human-now`, held at the harvest with

```
held fix/B-0086: merge_amendable_set (human-now) — rules/R-0042.md — proposed in F-0101
```

where the trailing clause is present when an open item carries `source: amend:<that path>` — the
proposal and the branch that answers it are read together, or the operator is looking at an
amendment nobody proposed. The operator lands it with
`asf approvals resolve <item>/merge_amendable_set granted`, exactly as today.

### 2.6 Where it shows

- **`asf approvals`** prints `format_set(product)` under the matrix table: one row per kind —
  `kind | globs | why` — headed `amendable set (default)` or `amendable set (products/<p>.yaml)`.
- **`asf doctor`** gains an `amendable` row: ok with `6 kinds, 11 globs (default); write: refused,
  merge: human-now`; not ok when the matrix cannot load; ok-with-a-note when the product opted out
  (`conventions.amendable_paths: [] — nothing is protected`) or when `merge_amendable_set` is `auto`
  (`the write gate holds but any branch lands — the set is protected at only one end`). The
  existing "amendable_paths is empty" note now fires only on the explicit `[]`.
- **`asf check`** errors per Task whose `writes:` reaches the set:
  `T-0099: writes: rules/* reaches the amendable set (rule_cards) — no session edits it; file a
  proposal instead (F-0024)`.

### 2.7 Config

`docs/products.example.yaml` and `sample/product.yaml` gain `touch_amendable_set: human-now` in
`approvals:`, and the `amendable_paths` comment becomes the three-state one. `sample/product.yaml`
leaves `amendable_paths` unset, so `tests/test_sample_product.py` exercises the defaults.

`tests/test_approvals.py:508` (`test_an_empty_amendable_set_under_a_held_merge_class_is_named`)
sets `amendable_paths: []` explicitly, since an unset field no longer means an empty set.

## 4. Records

**Files.**

| Path | Written by | Shape |
| --- | --- | --- |
| `<record>/<intake_dir>/propose-<slug>.md` | `asf propose` | §2.4 — title, `parent:`, `source:`, Description, Evidence, the proposed change, Acceptance |
| `<record>/features/F-xxxx.md` | the groom, from that card | a Feature carrying `source: amend:<path>` |
| `~/.ASF/state/<product>/approvals.jsonl` | the hook and `asf propose` | the lines below |

**Rows** — the ledger's two new shapes, beside the `refused`/`resolved` lines F-0031 defined:

```json
{"event": "refused", "hold": "F-0024/touch_amendable_set", "item": "F-0024",
 "class": "touch_amendable_set", "level": "human-now", "job": "spec-f-0024", "tool": "Edit",
 "detail": "rules/R-0042.md", "kind": "rule_cards",
 "patch": "@@ -12 +12 @@\n-  writes: one glob\n+  writes: one or more globs\n",
 "ts": "2026-09-23T17:41:27Z"}
{"event": "proposed", "hold": "F-0024/touch_amendable_set",
 "card": "cards/propose-rules-r-0042.md", "ts": "2026-09-23T17:44:02Z"}
{"event": "resolved", "hold": "F-0024/touch_amendable_set", "resolution": "proposed",
 "ts": "2026-09-23T17:44:02Z"}
```

`patch` is machine-local and never leaves `~/.ASF`; what reaches the record is §2.4 step 4's
decision. `holds()` gains a `proposed` key (the card path, or `None`), read by `raise_holds` and by
`asf approvals list`.

**Events** — `<record>/metrics/events/<day>.jsonl`, through the tick's `raise_holds`, unchanged in
shape and now carrying the new class:

```json
{"kind": "held", "hold": "F-0024/touch_amendable_set", "item": "F-0024",
 "class": "touch_amendable_set", "level": "human-now", "count": 3}
{"kind": "hold-resolved", "hold": "F-0024/touch_amendable_set",
 "class": "touch_amendable_set", "resolution": "proposed"}
```

Those two are what 0.2 reads: how often the factory wanted to amend itself, which file, and whether
the proposal was ever merged. The quarter of data the eval-gated loop needs starts at the first
`held` line this spec makes possible.

**Printed.** One `NEEDS OPERATOR` line per open amendable hold at every tick (`raise_holds`), the
five refusal lines to the session that tried, the `held <branch>: merge_amendable_set` line at the
harvest, and the `amendable` row of `asf doctor`.
