# F-0030 — one page, and every number on it machine-written

The card, as the requirement: *the shape to copy from the public prior art the prototype itself
cited — one page that carries the argument, the mental model and the manual. Ours adds the
measured numbers, because the argument for a factory is its numbers.* Its three acceptance lines
are the page (one, three parts), the numbers (generated from the record, not typed) and the
quickstart (executed by a test).

Today's `README.md` is fifteen lines. It makes no argument, carries no model, and its manual is a
single bullet naming the repository's directories — two of which, `rules/` and `evals/`, **do not
exist in this checkout**. That is the whole problem in one line: a hand-typed page drifts the
moment the thing it describes moves, and nothing in the build notices. A reader who runs
`ls rules` learns in one second that the page cannot be trusted, and stops reading the rest.

The measured half has the same failure mode with a sharper edge. A factory's argument is
`n sessions, $x, y Features shipped`; typed once into prose, that becomes a lie on the next tick
and an embarrassing one after a month. The record already holds every one of those numbers —
`index.json` for the cards, `metrics/{sessions,ci,ticks}` for the events — and
`asf.metrics.metrics` already renders markdown from them for the daily scorecard. So the fix is
not a new data path. It is a marked span in the page, a renderer that fills it, and a test that
proves the committed page is exactly what the renderer produces.

---

## 1. Decisions

### 1.1 In

- **A span grammar for `README.md`.** Inline `<!--asf:n <key>-->…<!--/asf:n-->` for a value in a
  sentence; `<!--asf:block <key>-->` … `<!--/asf:block-->` for a table. HTML comments are
  invisible in GitHub's render, so the page reads as prose to a human and as a template to the
  build.
- **`asf/views/readme.py`** — the span parser, the facts builder, the renderer, the checker, and
  `cmd_readme`.
- **`asf readme [--product P] [--refresh] [--check] [--json]`** — `--refresh` reads the record and
  rewrites both the facts file and the page; the default and `--check` read the *committed* facts
  file, re-render and report drift, touching nothing.
- **A committed facts file** (`docs/readme-numbers.json` by default): every value the page shows,
  each with the source that produced it, plus the record path, the record's `index.json`
  `generated` stamp and the day the numbers cover.
- **The rewritten `README.md`** — three parts in this order: the argument (with the scoreboard),
  the mental model, the manual (install, quickstart, commands, layout, license, credit).
- **`tests/test_readme.py`** — the span round-trip, the facts, the "no typed number" rule, the
  dead-link rule, the one-page budget, the byte-identity of the committed page, and the
  quickstart executed verbatim.
- **Drift is visible without a human reading the page**: an `asf doctor` row, and a Bug filed by
  `asf file-bugs` when the committed numbers fall behind the record by more than
  `README_STALE_DAYS`.
- **The generic path**: the sample product's own README carries two spans, so
  `tests/test_sample_product.py` exercises the renderer on a product that is not this one.

### 1.2 Out

- **The clean-clone CI job.** *"The quickstart is executed by CI from a clean clone"* is
  [[F-0033]]'s card (named as such in `docs/CONSTITUTION.md:256`). F-0030 delivers the test; the
  job that runs it from a fresh clone is F-0033's and is not written here. The test added here is
  in `tests/`, so the existing suite step runs it either way.
- **Rewriting `docs/` or `plugin/skills`.** The three-surfaces rule (`docs/README.md`) stands: the
  README makes the argument, the skills give the procedure, `docs/` holds the specification. This
  card rewrites one of the three. Where the README would explain a mechanism, it links.
- **A new metrics stream, a new event, a new matcher.** Every number comes from readers that exist
  (`asf.views.index_reader`, `asf.metrics.metrics`). Directive 10 — the number this page needs is
  already computed for the daily scorecard.
- **Numbers about this repository rather than the record** — the suite's test count, lines of
  code, contributor count. They are repo trivia, they invite gaming, and the card asks for
  *measured* numbers, which is what the record holds.
- **Any automatic write to the trunk.** The tick never rewrites `README.md`: it checks and, when
  the page has drifted, files a Bug that a session fixes on a branch. Nothing here pushes to
  `main`.
- **Naming the upstream project in the credit line.** ADR-0001 requires the README to credit *"the
  public upstream software-factory project the prototype credited (`docs/prior-art.md:5-12`)"* —
  a file that lived in the prototype and is not in this checkout. The name is not in the record,
  so it is not guessed: see §1.3.

### 1.3 Preconditions

| Precondition | State today |
| --- | --- |
| `index.json` carries every live card with `type` and `stage` | true — `asf.views.index_reader.load()` |
| `metrics/{ci,sessions,ticks}/<day>.jsonl` exist with `minutes` and `usd` on a session | true — `asf.metrics.metrics.SCHEMAS['sessions']` |
| A Feature's spend is summable over its subtree | true — `compute_costs` + `subtree_cost` |
| `write_if_changed` exists, so a re-render with no change is a no-op | true — `asf.metrics.metrics.write_if_changed` |
| The sample product runs the real CLI end to end, hermetically | true — `tests/test_sample_product.py` |
| The upstream project's name for the credit line | **absent from this checkout** |

**NEEDS OPERATOR: the name and URL of the public upstream software-factory project ADR-0001 says
the README must credit — it lived in the prototype's `docs/prior-art.md:5-12`, which is not in
this repository. Until it is given, the credit line reads "the public upstream software-factory
project the 2026-08 prototype credited" and links to `docs/research/prior-art-prototype.md`;
supplying the name is a one-line edit to the credit paragraph, and no test depends on it.**

### 1.4 The choices

| Choice | Chosen | Against | Why |
| --- | --- | --- | --- |
| Where the page's source lives | `README.md` itself, with marked spans | a `docs/readme.template.md` rendered wholesale into `README.md` | the page stays editable in place, a prose edit is a one-line diff, and GitHub's rendered view is the file a contributor already reads. A whole-file generator makes every prose change a two-file change |
| How the test proves "not typed" offline | the facts file is committed; the test re-renders the page from it and asserts byte-identity | re-deriving the numbers from the live record inside the test | the suite is hermetic — no record, no network. Byte-identity proves a machine wrote every span; the facts file's provenance is enforced separately, because only `--refresh` writes it and it carries the record stamp |
| The rule for typed numbers | a digit run in README **prose** is a failure unless it sits in a span, in inline code, in a link target or in the literal allowlist | trusting review | review is what produced the fifteen-line page that names two directories that do not exist |
| What "one page" means | a budget in the test: ≤ 150 lines and ≤ 10 000 bytes | a word count, or nothing | a budget is a number a test can hold. 150 lines is a page a reader scrolls twice, not a manual |
| Who refreshes the numbers | a session, on a branch, prompted by a filed Bug | the tick, committing to the trunk | the trunk is never written by the factory directly; a Bug is the mechanism the factory already has for "a check went red" (`asf.tick.file_bugs`) |
| Whether the command table is generated too | yes — a block span rendered from `asf.cli.build_parser()` | typing the table | the same drift class as `rules/`: it is cheap to generate from the parser, and the parser cannot lie about its own subcommands |
| Scope of the renderer | generic: any product whose README carries spans | a script that only renders this repo's README | `tools/check_generic.sh` — nothing product-specific lives in this repo. The sample product proves the generic path |
| The quickstart's shell | the sample product, the `fake` worker runtime, a temp `ASF_HOME` | a real product and a real agent | the test must run with no account, no network and no money; `tests/test_sample_product.py` already establishes exactly this fixture |

## 2. The design

### 2.1 `asf/views/readme.py` — the spans

```python
"""asf.views.readme — the README's generated spans (`asf readme`).

A page a human writes, with the numbers written by the build. Two markers, both HTML comments,
so GitHub renders the page as prose and the build reads it as a template:

    <!--asf:n sessions-->1,204<!--/asf:n-->        an inline value
    <!--asf:block scoreboard-->                    a table, markers on their own lines
    | Metric | Value | From |
    <!--/asf:block-->

Read-only over the record: every number comes from `asf.views.index_reader` and
`asf.metrics.metrics`, which the daily scorecard already computes with. Stdlib only.
"""

#: The page and the facts beside it, relative to the repo root. Overridable per product
#: (`conventions.readme`, `conventions.readme_facts`) so this is not one repo's layout.
README = 'README.md'
FACTS = 'docs/readme-numbers.json'

#: Digit runs a human may type in the page's prose. Every entry is a name, not a measurement:
#: a measurement belongs in a span.
LITERALS = ('0.1', '2.0')        # the release; Apache-2.0

#: One page: a reader scrolls it twice.
MAX_LINES = 150
MAX_BYTES = 10_000
```

- `spans(text) -> [Span]` — every span in order, each `(kind, key, start, end, body)`. Malformed
  input is an error, never a silent skip: an unclosed marker, a close with no open, a nested span,
  a duplicate key, a block marker that is not alone on its line.
- `render(text, facts) -> str` — replaces each span's body with `facts['numbers'][key]['text']`.
  A key with no fact, and a fact with no span, are both errors naming the key — a blank span is
  never shipped.
- `complaints(text, facts, root) -> [str]` — the checks, one string each, empty when the page is
  sound:
  1. a span whose body differs from the fact (the page has drifted);
  2. a digit run in prose that is not in a span, not in inline code, not in a link target and not
     in `LITERALS`;
  3. a relative link whose target does not exist under `root` (this is what `rules/` and `evals/`
     would have failed on);
  4. over `MAX_LINES` or `MAX_BYTES`;
  5. the three part headings absent or out of order.

### 2.2 The facts — every number, and where it came from

`facts(record_root, repo_root, product=None, now=None) -> dict`. One pass over the record; each
number carries the reader that produced it, so a reader of the facts file can audit the claim
without rerunning anything.

```json
{
  "generated": "2026-09-24T06:11:04Z",
  "record": "ASF-backlog",
  "record_generated": "2026-09-24T05:52:11Z",
  "day": "2026-09-24",
  "numbers": {
    "sessions": {"value": 1204, "text": "1,204", "source": "metrics/sessions"},
    "spend_usd": {"value": 365.08, "text": "$365", "source": "metrics/sessions.usd"}
  }
}
```

*(The values above are the shape, not a reading — the real ones are whatever `--refresh` finds.)*

| key | what it says | source |
| --- | --- | --- |
| `window` | `<first day> … <last day> (<n> days)` | the first and last day with an event in any stream |
| `items` | live cards in the record | `index_reader.load()` |
| `features_shipped` | Features at `landed` or `on-prod` | `index_reader.load()` — `stage` |
| `sessions` | agent sessions run | `len(read_stream('sessions'))` |
| `session_hours` | wall hours those sessions took | `sum(minutes) / 60` |
| `spend_usd` | what they cost | `sum(usd)` |
| `usd_per_feature` | spend per shipped Feature | `subtree_cost` over the shipped Features ÷ their count |
| `ci_runs`, `ci_green_pct` | CI runs and the green share | `read_stream('ci')` — `conclusion` |
| `ticks` | ticks run | `len(read_stream('ticks'))` |
| `scoreboard` (block) | the argument's table: metric, value, source | the keys above |
| `cost_per_feature` (block) | the five costliest shipped Features | `metrics.cost_table`, trimmed |
| `commands` (block) | one row per `asf` subcommand and its help | `asf.cli.build_parser()` — `source: cli` |

Two rules the builder holds. A number with no events behind it renders `—`, never `0` dressed as
a measurement. And `commands` is the one span whose source is the repo rather than the record:
it is marked `source: cli` in the facts file, and §2.5's check requires every *other* span's
source to name a record path.

### 2.3 `asf readme` — refresh, check

```
asf readme [--product P] [--check] [--refresh] [--json]
```

- **`--refresh`** — resolve the product's repo and record, build the facts, `write_if_changed` the
  facts file and the rendered page. Prints one line per file: `readme: README.md rewritten` or
  `readme: README.md unchanged`. Exit 0.
- **default / `--check`** — read the *committed* facts file (no record needed), re-render, and
  print every complaint from §2.1. Exit 1 when there is any. This is the form the gate and a
  contributor run: it is hermetic, offline and fast.
- **`--json`** — `{"ok": bool, "complaints": [...], "day": "...", "stale_days": n}`, for `doctor`
  and `file-bugs`.
- A repo whose README carries no span is not an error: `readme: no spans — nothing to render`,
  exit 0. That is what makes the command safe to put in front of any product.

Wired in `asf/cli.py` beside the other view commands; it resolves the repo through
`env.load_product(...).repo_dir` and the record through `resolve_record`, so it obeys the same
`--product` rules as everything else.

### 2.4 `README.md` — the page

Three parts, in this order, each a `##` heading the test asserts:

**## The argument** — what ASF is in three sentences, then the scoreboard block. The numbers are
the argument: this factory has run `<sessions>` sessions over `<window>`, shipped
`<features_shipped>` Features at `<usd_per_feature>` each, and the record that says so is public.
The status line (0.1 in construction) and the link to the record repository stay.

**## The mental model** — eight to twelve lines, one idea each, each linking to the one place it is
specified: the record is typed intent; state is derived from evidence, never typed
(`docs/CONSTITUTION.md`, `asf/evidence/`); the tick is the loop — groom, wave, harvest
(`docs/design/lane-state-machine.md`); a lane is a branch with a session on it; rules are checks,
not prose (`asf/rules/`); multi-product from day one — every path and vendor name lives in
`~/.ASF`, none in this repo. No mechanism is explained twice: where this section would explain,
it links.

**## The manual** — install; the quickstart block (§2.5); the `commands` block; where things live,
as a table whose every path is link-checked; `~/.ASF` as the operator's configuration; the
license; the credit paragraph (§1.3). The current "Not the Apache Software Foundation"
disambiguation stays — it is the first thing a search engine gets wrong.

The budget is met by cutting, not by moving prose into `docs/`: §2.1's check fails the build if
the page grows past 150 lines.

### 2.5 The quickstart is the test's script

The quickstart is a fenced `sh` block between `<!--asf:quickstart-->` and `<!--/asf:quickstart-->`,
and `tests/test_readme.py` runs *that text*, so the page and the thing that works cannot diverge.
The contract, stated in the module docstring and enforced by the parser:

- every line is blank, a `#` comment, an expected-output line (`# → <text>`), or a command;
- exactly one line carries the trailing marker `# your product` — the operator's own values. The
  test replaces that whole line with the fixture's equivalent, and names the line it replaced in
  any failure message;
- every other line runs **verbatim**, in order, in one shell, and must exit 0;
- each `# → <text>` line asserts that `<text>` appears in the preceding command's stdout.

The page shows, and the test therefore proves:

```sh
export ASF_PRODUCT=my-product              # your product
asf init --product $ASF_PRODUCT
asf tick --once
# → tick 1
asf next
asf doctor
# → doctor: green
```

The fixture is the one `tests/test_sample_product.py` already builds: `sample/` copied to a temp
dir, bare origins for `repo/` and `backlog/`, a temp `ASF_HOME` with the `fake` worker runtime and
no scheduler. The helpers (`_publish`, `_fill`, `SAMPLE`) are imported from that module the way
`tests/test_sample_product.py` already imports `fake_clis` from `tests/test_scheduler.py`, so no
fixture is duplicated. No network, no account, no agent.

### 2.6 The generic path

`sample/repo/README` gains two spans and `sample/product.yaml` gains `conventions.readme:
README` / `conventions.readme_facts: readme-numbers.json`. `tests/test_sample_product.py` runs
`asf readme --refresh --product sample` in its existing end-to-end pass and asserts the spans came
back filled from the sample record's ten cards. A path this repo's own layout hard-codes would
fail there, which is the point.

### 2.7 Drift is visible

- **`asf doctor`** gains one row — `readme` — from `asf readme --check --json`: `ok`, or
  `n complaints — <the first>`. Red only when the page has genuinely drifted, and skipped entirely
  for a product whose README has no spans.
- **`asf file-bugs`** gains a fourth source beside ci, refusals and rules: signature
  `readme/stale`, filed when `--check` is red **and** the committed facts' `day` is more than
  `README_STALE_DAYS = 7` behind the record's newest event day. One signature, so a second tick
  bumps rather than duplicates — the mechanism `_file_or_bump_bug` already implements. A page that
  is merely a day old files nothing.

### 2.8 What does not change

The three-surfaces rule; `docs/`, `plugin/` and their contents; every existing stream, schema and
matcher; the tick's steps and their order (`file-bugs` gains a source, it does not move); the
trunk-write policy.

## 3. Acceptance tests

All hermetic: no network, no account, no record but the fixtures in the tree.

### 3.1 The span grammar and the renderer

```sh
python3 -m unittest -v tests.test_readme.SpanTests tests.test_readme.RenderTests
```

Round-trips a page through `spans`/`render`; asserts each malformed form (unclosed, unopened,
nested, duplicate key, block marker not alone on its line) raises naming the key or the line, and
that a missing fact and an unused fact are both errors.

### 3.2 Every number comes from the record

```sh
python3 -m unittest -v tests.test_readme.FactsTests
```

Builds the facts from `sample/backlog` plus a written metrics fixture; asserts every key in §2.2 is
present, that each carries a `source`, that every source but `commands` names a record path, that
an empty stream renders `—` and not `0`, and that `facts()` opens nothing outside the record root.

### 3.3 The committed page is machine-written

```sh
python3 -m unittest -v tests.test_readme.CommittedPageTests
```

Reads the real `README.md` and the real `docs/readme-numbers.json`, re-renders, and asserts
byte-identity. A number edited by hand in either file fails here.

### 3.4 No typed number, no dead link

```sh
python3 -m unittest -v tests.test_readme.ProseTests tests.test_readme.LinkTests
```

Against the real page: every digit run is in a span, in inline code, in a link target or in
`LITERALS`; every relative link resolves under the repo root. `LinkTests` carries a regression case
for the two paths this card was written over — a README naming `rules/` and `evals/` when neither
exists must fail.

### 3.5 One page

```sh
python3 -m unittest -v tests.test_readme.OnePageTests
```

≤ 150 lines, ≤ 10 000 bytes, and exactly `## The argument`, `## The mental model`, `## The manual`
present and in that order.

### 3.6 The quickstart, executed

```sh
python3 -m unittest -v tests.test_readme.QuickstartTests
```

Parses the block from the real README, replaces the one `# your product` line, runs every other
line verbatim against the sample fixture, asserts each exit status is 0 and each `# → ` line
appears in its command's stdout.

### 3.7 The command surface

```sh
python3 -m unittest -v tests.test_readme.CommandsBlockTests
```

Asserts the `commands` block names exactly the subcommands `asf.cli.build_parser()` registers —
adding a subcommand without refreshing the page fails.

### 3.8 The generic path, and drift

```sh
python3 -m unittest -v tests.test_sample_product.ReadmeRenderTests
python3 -m unittest -v tests.test_doctor.ReadmeRowTests tests.test_file_bugs.ReadmeStaleTests
```

The sample product's README renders from its own record; `doctor` shows the row (and omits it for
a README with no spans); `file-bugs` files `readme/stale` once past seven days and bumps rather
than duplicates on the next run.

### 3.9 The gate

```sh
python3 tools/run_tests.py
bash tools/check_generic.sh
```

The whole suite green, and no product-specific name in a tracked file — including the new page.
