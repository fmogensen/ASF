# F-0293 — the last four-digit readers, and the ratchet that names them

One id grammar already exists. `asf/record/core.py:45-48` is `ID_DIGITS = r'\d{4,}'` with
`ID_RE` and `ID_TOKEN_RE` built from it, and a comment that says what to do with it: *"import
these, never respell them"*. `tests/test_id_pattern.py` is the ratchet that holds the line — two
halves, a behaviour half (every parser reads a five-digit id) and a scan half (no new
four-digit-only id regex anywhere under `asf/`, `tests/`, `tools/`).

The scan half carries an `ALLOWED` dict: *"the sites that still spell four digits, each owned
outside this change … A site is removed here when its owner swaps it to core's pattern; never
added to."* Four of its entries are product code. Three of them are live defects, one is right
by accident, and a fifth four-digit reader sits in a file the scan does not look at. That is
this card: **empty the allow list of its product entries, and close the hole in the scan.**

A branch is the sharpest of them. `worker/T-0891` and `worker/T-49891`, same Closed card shape,
go two different ways:

| branch | `lane.item_of` | `retention.settled_reason` |
| --- | --- | --- |
| `worker/T-0891` | `T-0891` | `T-0891 is Closed in the record` |
| `worker/T-49891` | `None` | `None` |

Every id the minter issues today has five digits. The second row is the only one that happens.

| --- | --- | --- | --- |
| D1 | **Empty `ALLOWED` of all four product entries**, not only the two the card names | the card's literal inventory: `lane` and `ingest` | `ALLOWED` is the record of what remains (P11) and it says of `runtime` and `score` *"next to swap"*. ## The design

Six one-line edits, one scan extension, and four assertions. Nothing's signature changes, no
module gains a dependency it did not already load (P10), and no four-digit input behaves
differently (D6).

### 1. `asf/harvest/lane.py` — the branch's id token

The module's import block (`:148-161`) gains one line in its alphabetical place:

```python
from asf.record.core import ID_DIGITS
```

and `:275` becomes:

```python
ITEM_ID_RE = re.compile(rf'\b([A-Za-z]+-{ID_DIGITS})\b')
```

When it is there, `item_of('worker/T-49891', {})` is `'T-49891'`, `item_of('worker/T-0891', {})`
is still `'T-0891'`, and `retention.settled_reason` — which calls `item_of` and nothing else to
name the card (`asf/workers/retention.py:252-256`) — settles a five-digit head whose card is
Closed, so the branch census puts it in `settled` instead of leaving it unaccounted for.
`branch_facts` and `resolve_item` keep their existing fallbacks; they simply stop needing them
(P5).

### 2. `asf/record/ingest.py` — the merged-into edge

`ingest` already imports from core at module top (`:23-24`); that line gains `ID_DIGITS`, and
`:633` becomes:

```python
_MERGED_INTO = re.compile(rf'\bmerged into ([Tt]-{ID_DIGITS})\b')
```

`_REMOVED_ON` on the line below is a **date** reader (`(\d{4}-\d{2}-\d{2})`) and is not touched.
When it is there, `orphaned_tasks` builds the `into` edge from a `removed: merged into T-49890`
line, follows the survivor chain, and returns the Task whose scope no live Task carries — the
same answer it already gives at four digits.

### 3. `asf/workers/runtime.py` — a scripted session's job name

The import block (`:23-26`) gains `from asf.record.core import ID_DIGITS`, and `:772` becomes:

```python
_ITEM_RE = re.compile(rf'([a-z])-({ID_DIGITS})$', re.I)
```

`stub_writes` then fills `{item}` / `{item_lower}` for `coder-t-49891` as it does for
`coder-t-0891`. Greedy `{4,}` before the `$` anchor takes the whole run of digits, so the
capture is `49891`, not `9891`.

### 4. `asf/scorecard/score.py` — the job name's kind

`score.py` imports from `asf.scorecard.facts`, which already imports `ID_DIGITS` from core
(`asf/scorecard/facts.py:26`); `score.py` gains the same import at module top, and `:30` becomes:

```python
_JOB_RE = re.compile(rf'^(.*?)-[a-z]-{ID_DIGITS}')
```

`session_kind` returns the same kind for every job name it already read (P8) — the expression
stops being a lie about the grammar.

### 5. `tools/forbidden-conventions.txt` — the hardcoded-Epic-id guard

Line 28 becomes `\bE-[0-9]{4,}\b`. The comment above it is unchanged; a second sentence names
why the comma is there, in the file's own voice:

```
# A hardcoded item id → conventions.default_bug_epic (an id in generated prose is data too).
# Four **or more** digits: a claimed id block runs past 9999 (asf.record.core.ID_DIGITS).
\bE-[0-9]{4,}\b
```

`tools/check_conventions.sh` is unchanged — it reads the file.

### 6. `tests/test_id_pattern.py` — the ratchet tightens and widens

Three edits:

- **`ALLOWED` loses its four product entries** — `asf/harvest/lane.py`,
  `asf/record/ingest.py`, `asf/workers/runtime.py`, `asf/scorecard/score.py` — and the two
  comment lines that introduced them. What is left is the six test-only entries, with their
  existing reasons. `test_the_allow_list_holds_only_live_sites` (P11) is what makes the deletion
  mandatory rather than optional.
- **`four_digit_sites()` also reads the conventions pattern file.** The walk keeps taking
  `*.py`; one extra path joins it by name, so the scan is `{*.py under asf, tests, tools} ∪
  {tools/forbidden-conventions.txt}`:

  ```python
  #: a non-``.py`` file the scan reads by name: the conventions check's own pattern list, where a
  #: four-digit-only id pattern lets the id it exists to refuse through unseen (F-0293)
  EXTRA_FILES = ('tools/forbidden-conventions.txt',)
  ```

  with `four_digit_sites()` iterating `EXTRA_FILES` after its walk, through the same
  `FOUR_ONLY.search` per line. No `ALLOWED` entry is added for it: after edit 5 it has no
  four-digit site to allow.
- **`EveryParserReadsAFiveDigitId` gains one method per swapped site**, in the class's existing
  style (import inside the test, assert on the five-digit case and on the four-digit one that
  must still work):

  ```python
  def test_the_lane_and_the_job_name_read_a_five_digit_id(self):
      from asf.harvest import lane
      from asf.record import ingest
      from asf.scorecard import score
      from asf.workers import runtime
      self.assertEqual(lane.item_of('worker/T-49891', {}), 'T-49891')
      self.assertEqual(lane.item_of('worker/T-0891', {}), 'T-0891')
      self.assertEqual(ingest._MERGED_INTO.search('merged into T-49890').group(1), 'T-49890')
      self.assertEqual(runtime._ITEM_RE.search('coder-t-49891').groups(), ('t', '49891'))
      self.assertEqual(score.session_kind({'task': 'spec-f-49891'}), 'spec')
  ```

### 7. The two behaviour tests, in the suites that own the code

- `tests/test_retention.py` gains a case next to its existing settled-head coverage
  (`:274` already documents `settled_reason`): the same Closed card at `T-0891` and `T-49891`,
  and `settled_reason` naming both — the table at the top of this spec, as an assertion.
- `tests/test_ingest.py` gains a case on its `orphaned_tasks` fixtures: a removed Task whose
  `removed:` reads `merged into T-49890`, a five-digit survivor that is itself removed and never
  landed, and the removed Task in the returned set.
