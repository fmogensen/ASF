# F-0023 — The grill: a request is interrogated before it is spent on

Epic: E-0001 — ASF 0.1 — a working factory. Branch: `spec/F-0023`.

There is no front door a person can type into. A sentence becomes work by somebody writing a card
by hand, and a card becomes a spec by a session reading it and inventing the rest. In the prototype
that licence went the whole way: one run took a single sentence and regenerated a 286-line
specification from scratch, shedding eight named tasks in the process. The constitution's first
directive already says where the licence ends — *"a request that names an existing document
**refines** it and never regenerates it"* (`docs/CONSTITUTION.md:33-35`) — and its TRIGGERS line
says honestly that nothing enforces it: *"It becomes `checked` when the interrogator ships
([[F-0023]]) and a rule bounces a brief that names an existing document and produces a rewrite"*
(`docs/CONSTITUTION.md:47-48`).

This card is those two halves. The front door is `asf idea "<text>"`: one interrogator session
turns the sentence into a tree of cards — an Epic, its Features, their Stories, each with its
acceptance — and the deterministic half of the command files that tree into the record's intake,
where the groom types it, mints it and puts every one of its cards to the operator as a question it
already proposes an answer to. A thin card that is already in the record gets the same treatment
without a person asking: the feeder emits `CARD → ENRICH` before it would emit `CARD → SPEC`. And
the seam is enforced where documents actually pass from their writer to their reader: harvest holds
a spec or plan branch that rewrites the document already on the trunk, and hands it back to the
session that wrote it as a correction — before it lands, and therefore before any reviewer spends a
round on it.

## Decisions

### In

- **`asf/idea/` (new package)** — the interrogator's deterministic half, in four modules:
  `tree.py` (the grammar and its parser), `answered.py` (the record-first filter), `apply.py`
  (intake cards from a tree; the enrich writer), `cli.py` (`cmd_idea`).
- **`asf idea "<text>"`** — the front door. It builds the `idea` brief, runs **one** interrogator
  session in the foreground (`asf.workers.runtime.Runtime.run(job, wait=True)`,
  `asf/workers/runtime.py:182`), and then applies the tree that session wrote. It mints no id and
  commits nothing: the cards go into the record's intake directory, and the groom mints them
  (F-0073's one way in).
- **`asf idea --enrich <ID>`** — the same interrogation against a card already in the record. It
  writes that card's `## Description`, `## Acceptance` and `## Assumptions` through the parser (the
  `asf set` round-trip, B-0084) and stamps the typed field `enriched: <date>`.
- **`asf idea apply --tree FILE [--enrich ID]`** — the deterministic writer on its own, which is
  what a factory-launched interrogator session runs as its last act, and what a test runs with no
  session at all.
- **The tree grammar** (`asf/idea/tree.py`): one `## <Epic|Feature|Story> <key> [under <key>]:
  <title>` block per node, `### Acceptance` and `### Assumptions` under it, blocks separated by
  `---`. It has **no question section** (D2): a node's open question is written as an assumption
  with the answer the interrogator proposes, and the question the operator is asked is the card's
  own `decided:` line in the groom.
- **The record-first filter** (`asf/idea/answered.py`): before a node is filed, its title is put to
  the record. A node that an open item already covers is not filed and not asked — it is recorded
  as `answered by <id>` in the run's report, and printed.
- **The forward reference** (`asf/groom/inbox.py`): an intake card may carry `parent: inbox:<file
  name>`, naming a sibling intake file. `process_inbox` resolves it against the ids it minted
  earlier in the same pass. This is what lets one `asf idea` run file a whole Epic → Feature →
  Story tree before a single id exists.
- **`## Assumptions`** joins `## Features` and `## Acceptance` as a section intake lifts off an
  inbox card and `write_new_item` writes back (`asf/groom/inbox.py:27-50,154`).
- **`CARD → ENRICH`** in `asf/feeder/rows.py`: a decided Feature at stage `card` that is *thin* and
  carries no `enriched:` stamp gets an `idea` session instead of the `CARD → SPEC` row.
- **Two derived counts in the index** — `acceptance_items` and `description_words`, computed in
  `compute_derived` and written by `build_index_data` (`asf/record/core.py:189,253`). Thinness is
  a fact the feeder reads off `index.json`, like every other fact it uses.
- **The refine half of a brief** (`asf/briefs/preamble.py`, `templates/spec.md`, `templates/plan.md`):
  when the document the session's kind writes is already recorded, the brief carries a REFINE
  paragraph naming the file, its anchors, and the bounce that follows a rewrite.
- **The bounce** (`asf/harvest/refine.py`, new; called from `asf/harvest/harvest.py:1113`): a
  `spec`/`plan` lane branch whose deliverable exists on the trunk is held with a `rewrite`
  correction when it drops an anchor or deletes more than half the document. The existing
  `hold_with_correction` → `FIX → CORRECT` loop hands it back to the session that wrote it.
- **`asf refine-check`** and the shipped rule script `rules/refine-not-rewrite.sh`: the same verdict
  as a periodic check, so `asf rules check` can carry the rule card that states the directive.
- **`docs/CONSTITUTION.md`**: directive 1's TRIGGERS line and the tally row become `checked`, with
  the mechanism named.

### Out

- **A model call inside `asf idea apply`.** The command parses, filters and writes; the one model
  call is the session the front door starts. A tree in, cards out, is a pure function — which is
  what makes acceptance runnable.
- **A new question grammar in the groom.** `asf idea` adds no section to `groom/<date>.md` and no
  answer word. Its cards arrive as `decided: false`, so they are already the groom's "Inbox cards to
  decide" lines (`asf/groom/groom.py:210-225`); a card intake cannot type still gets intake's own
  `## Question` (`asf/groom/inbox.py:189`). Both paths existed before this card (D2).
- **Enriching anything but a Feature.** A Bug has a signature, a Story is cut from a spec, a Task
  from a plan. Only a Feature card is the thing a spec is written from, so only a Feature is thin.
- **Rewriting a card's title, parent or rank in `--enrich`.** The enrich writer appends to three
  sections and sets one typed field. Re-parenting and re-ranking are groom answers.
- **A review row for a document.** There is none today: *"a document the lane landed on the trunk
  is approved (B-0059): the fast-forward lane has no reviewer row — harvest's gate is its review"*
  (`asf/record/ingest.py:405-408`). That is exactly why the bounce belongs at the harvest and
  nowhere else (D7).
- **A bypass a session can write.** No trailer, no marker, no `--force` on the harvest side. B-0084
  is the standing ruling: a leaked marker bypasses nothing. A deliberate rewrite is an
  adjudication, and harvest already refuses to land a ruling as a commit
  (`asf/harvest/harvest.py:666-673`).
- **Bouncing a code branch that rewrites a file.** `refine.verdict` runs on `spec`/`plan` lanes
  only. What a coder may rewrite is the plan's business and the reviewer's.
- **An `/asf:idea` plugin skill.** `asf idea` already runs an interrogator session; wrapping it in a
  skill would put a second interrogator, in a different harness, in front of the first
  (`asf/plugin_build.py:33-48`). The plugin does not change.
- **Minting the rule card's id here.** `R-nnnn` is minted by `asf new rule` in the record when the
  work lands, never invented in a document (D10).
- **Back-filling `enriched:` or the derived counts.** Existing cards get the counts at the next
  `asf index`, and no `enriched:` stamp — which is correct: they have not been enriched.

### Preconditions (checked against `origin/main` at `9790fdb`)

- `write_new_item` inserts the card it wrote into `canonical` before returning
  (`asf/record/ids.py:103-107`), so a card minted earlier in one `process_inbox` pass is visible to
  `derive` and to `mint_id` for the cards after it. The forward reference needs nothing else.
- `process_inbox` walks the intake directory in `sorted(os.listdir(...))` order
  (`asf/groom/inbox.py:125`). A parent filed with a lower-sorting name is always minted first.
- `derive` types an Epic from `## Features` with ≥ 2 bullets and no parent, a Story from a `parent:`
  naming a Feature plus a non-empty `## Acceptance`, and a Feature from a `parent:` naming an Epic
  (`asf/groom/shape.py:84-121`). A tree whose nodes carry those shapes needs no new rule.
- `asf index` rewrites only `## Children` and `## Backlinks` (`asf/record/core.py:234-250`), so an
  `## Assumptions` section survives a re-index.
- `question_lines` already renders one groom line per intake card carrying a `## Question`, and
  `render_groom_file` renders that section only when it has lines
  (`asf/groom/inbox.py:189-208`, `asf/groom/groom.py:358,433-451`).
- `deliverable_of` already names a spec/plan branch's one document
  (`asf/harvest/harvest.py:749-755`), and `already_on_trunk` runs before any refusal
  (`asf/harvest/harvest.py:1088-1092`), so a branch whose document is byte-identical to the trunk's
  is landed and never reaches `refine.verdict`.
- `lane_refusal` returns `(kind, text)` and its caller feeds that straight to
  `hold_with_correction` (`asf/harvest/harvest.py:725-740,1113-1116`). A second refusal function
  plugs into the same two lines.
- `correction_rows` gives any open non-Bug item a `correct` brief on the held branch
  (`asf/feeder/rows.py:223-249`), so a held `spec/F-nnnn` branch comes back to a session with the
  bounce text. No new row kind is needed for the return leg.
- `render` fails on a placeholder the context has no key for, and ignores context keys a template
  does not use (`asf/briefs/build.py:137-143`). Adding `refine` to `context()` is safe for every
  existing template.
- `Runtime.run(job, wait=True)` returns a finished `Result`, and `FakeRuntime` records every
  `(job, brief text)` in `calls` (`asf/workers/runtime.py:182-244`). A test drives the front door
  with `worker_pool.backend: fake`.
- `_parse_sets` refuses a field that is not in `SETTABLE[type]` (`asf/record/new.py:17-36`), so
  `enriched` must be added there before `asf set` or the enrich writer can write it.
- `mint_id` formats ids as `{prefix}-{n:04d}` and `asf check` holds every id to
  `^[A-Z]-\d{4}$` (`asf/record/ids.py:55`, `asf/record/core.py:40`), while `reserve_id_range`
  climbs by 50 per job with no ceiling (`asf/workers/spawn.py:69-91`) and is now past 9999. This
  spec therefore mints no id at all — see the `NEEDS OPERATOR` line in the session report.

### Choices

| # | Choice | Chosen | Against | Why |
|---|---|---|---|---|
| D1 | Where the model call sits | One session, started by `asf idea`, whose only deliverable is a tree file; the command parses and writes | The command calls a model itself; the session writes the cards | A session that writes cards writes them differently every time. A tree in and cards out is a pure function with a golden test, and the one model call is where the judgement actually is. |
| D2 | What an "open question" is | A proposal. The grammar has no question section; an unsettled point is an `## Assumptions` bullet carrying the answer the interrogator proposes, and the groom question is the card's own `decided:` line | A `### Questions` section whose lines become groom questions | Directive 5 is *never ask without proposing*, and the groom's answer grammar is word-sized (`yes`, `no`, `rank n`, `parent X`) — it has nowhere to put prose. A proposal the operator accepts with `yes` is an answerable question; "what about tax?" is not. |
| D3 | How a child names a parent that has no id | `parent: inbox:<file name>`, resolved during the pass that mints them | Mint ids in `asf idea`; one card per run; a two-pass groom | `asf idea` runs where a human is, not in the record's clone, and F-0073 put minting behind the groom on purpose. The resolution is six lines in `process_inbox` because `write_new_item` already updates `canonical` in place. |
| D4 | A child whose parent card is still unminted (its shape asked a question) | Left in the intake, untouched and unquestioned, until the parent is minted | A `## Question` of its own; file it parentless | The parent's question is the one to answer; a second question about the same gap is noise put to a person. A child that names an intake file which no longer exists *does* get a question — that is a broken tree, not a waiting one. |
| D5 | What "thin" means | `acceptance_items < 1` or `description_words < 40`, both derived into `index.json` | No Story children; a model's judgement; the card's byte size | At stage `card` a Feature has no Stories yet — the spec session mints them — so "no Stories" marks every card thin. What a spec is actually written from is a description and an acceptance list, and both are countable. |
| D6 | Stopping the enrich loop | The typed field `enriched: <date>`, written by the enrich writer; the feeder skips a card that carries it | A ledger lookup for an `idea-<id>` job; a rounds counter | The feeder may use only what `index.json` carries. A typed field is visible in the card, survives a re-index, and says who did what when — a ledger probe says none of that. |
| D7 | Where the rewrite is bounced | At the harvest, before the branch lands | A pre-commit hook in the session; a check the reviewer runs; a tick step | The hook cannot see the trunk's version of a document the session never fetched, and the reviewer is the round this card exists to save. Harvest is the seam every document crosses, and it already has the refusal → correction loop. |
| D8 | What counts as a rewrite | An anchor lost (a `##`-level heading, or an `S-`/`T-` id the trunk's version names), or more than half the trunk's lines deleted | A similarity score; a line-count ratio; any deletion | The prototype's failure was *named things disappearing* — eight tasks. An anchor is exactly that, and it is quotable in the correction. The ratio is the backstop for a rewrite that happens to keep the headings. |
| D9 | The rewrite threshold | `conventions.harvest.rewrite_ratio`, default `0.5` of the trunk document's lines **deleted** | Changed lines (added + deleted); a fixed constant | A refinement adds and edits; it does not delete half a document. Counting additions would bounce an honest expansion, which is the one thing a refine is allowed to be. |
| D10 | Where the rule lives | The check script ships here (`rules/refine-not-rewrite.sh`); the rule card is minted into the record with `asf new rule` when the work lands | Write the rule card's id into this spec; leave the rule recited | A ruling is never a commit in this repo and an id is never invented in a document. What this repo can ship is the mechanism and its check, and it does. |
| D11 | The front door when the session fails | The tree file that exists is applied anyway; a missing or unparseable tree is exit 2 with the parser's own line, and nothing is written | Apply nothing; file the raw text as one card | A tree that parses is work already done and paid for. A tree that does not parse is not something to guess at, and a half-filed tree is worse than none — `apply` writes all nodes or no nodes. |
| D12 | Re-running `apply` on the same tree | Refused: `apply` writes `<tree>.applied` and exits 2 when it exists, unless `--force` | Idempotent re-application; silent overwrite | The intake files it wrote may already have been minted and answered. Re-filing them would duplicate cards the groom has decided, and the duplicate detector only catches the exact ones. |

## The design

### The tree

One file, written by the interrogator session, read by `asf idea apply`:

```markdown
# The ask
Bill customers for what they actually use.

---

## Epic E1: Metered billing

Charging for usage, end to end: the meter, the invoice and the statement a customer can read.

### Assumptions
- one meter per account, not per API key — E-0001 already parents billing to the account

---

## Feature F1 under E1: The usage meter

Every request is counted against the account that made it, durably enough to bill from.

### Acceptance
- [ ] `python3 -m unittest tests.test_meter -v` is green
- [ ] a replayed request is counted once

---

## Story S1 under F1: A request increments its account's meter

### Acceptance
- [ ] `python3 -m unittest tests.test_meter.IncrementTest -v`
```

`parse_tree(text) -> Tree(ask, nodes)`. A node is `Node(type, key, parent_key, title, description,
acceptance, assumptions)`. The rules, each a parse error naming the line when broken:

| rule | error |
|---|---|
| the header matches `^##\s+(Epic\|Feature\|Story)\s+(\w+)(?:\s+under\s+(\w+))?:\s*(.+)$` | `line N: not a node header` |
| a key is unique | `line N: key E1 is already used at line M` |
| `under` names a key defined above | `line N: under F9 — no such key` |
| an Epic has no `under`; a Feature and a Story have one | `line N: a Feature hangs under an Epic` |
| a Feature's parent is an Epic, a Story's is a Feature | `line N: a Story hangs under a Feature` |
| an Epic has ≥ 2 Feature children | `the Epic E1 spans 1 Feature — an Epic is a business outcome spanning several Features` |
| a Story has ≥ 1 acceptance item | `line N: a Story is one PR with one acceptance list` |
| no `### Questions` section | `line N: an interrogation proposes, it does not ask — write it as an ## Assumptions bullet with the answer you propose (D2)` |

The size sentences are `asf.groom.shape.SIZE`, quoted, not restated.

### `asf/idea/answered.py` — the record before the person

```python
Answered = namedtuple('Answered', 'node source text')

def answer_from_record(node, canonical, overlap=DEFAULT_ANSWER_OVERLAP) -> Answered | None
```

A node is answered when an **open** item of the same type shares ≥ `overlap` of its title tokens
(`jaccard`/`tokenize`, `asf/record/core.py`), default `0.8` from `conventions.idea.answer_overlap`.
The answer is `F-0031 — Approvals as code (feature, Active)`. An answered node is not filed, and
neither is any node under it — its subtree is recorded as `answered by <id>` too, because a Story
of an existing Feature is that Feature's spec's business.

This is the whole of "no question is put to a person that the record could have answered": a card
that is filed becomes a groom line, and a groom line is a question. A node the record answers never
becomes one.

### `asf/idea/apply.py` — the tree, filed

`apply_tree(root, tree, canonical, intake_dir, stamp) -> Applied(filed, answered, report_path)`.

- Nodes in tree order. For each, `answer_from_record` first (and its subtree with it).
- Each filed node becomes one intake file, `<intake_dir>/idea-<stamp>-<nn>-<type>-<slug>.md`, with
  `<nn>` the node's index — so a parent always sorts before its children (D3):

  ```markdown
  # The usage meter
  parent: inbox:idea-20260923T1612Z-01-epic-metered-billing.md

  Every request is counted against the account that made it, durably enough to bill from.

  ## Assumptions
  - one meter per account, not per API key — E-0001 already parents billing to the account

  ## Acceptance
  - [ ] `python3 -m unittest tests.test_meter -v` is green
  ```

  An Epic node's file carries no `parent:` and a `## Features` section listing its children's
  titles — the shape `derive` reads as `features-list` (`asf/groom/shape.py:84`). A node whose
  parent is a *record* id (the `--enrich` case, and a tree rooted on an existing Epic) carries that
  id directly.
- Nothing is written until every node has been rendered: one failure writes no file (D11).
- The run's report, `<intake_dir>/done/idea-<stamp>.md`, carries the ask verbatim, one line per
  node (`filed <file>` / `answered by <id>`), and the tree as it was parsed. Nothing the
  interrogator produced is lost, including what the record answered.
- `<tree>.applied` is written last, as JSON: `{"stamp", "filed": [...], "answered": [{"node",
  "id"}], "report"}`. It is the guard against a second run (D12) and what the front door prints.

`enrich_card(root, canonical, item_id, node, date)` is the other writer:

- appends the node's description to `## Description`, its acceptance items to `## Acceptance`
  (replacing a lone empty `- [ ] ` line), and its assumptions to `## Assumptions`, creating that
  section before `## Acceptance` when the card has none;
- sets the typed field `enriched: <date>` (added to `_COMMON_SET`, `asf/record/new.py:17`);
- appends one History line: `- <date>: enriched (idea) — +<n> acceptance, +<m> assumption(s)`;
- writes through the `asf set` round trip: render, re-parse, compare, and write only if the card
  comes back as what was asked (`asf/record/setfield.py`). A card that does not round-trip is left
  untouched and the command exits 2.

### `asf idea` (`asf/idea/cli.py`, wired in `asf/cli.py`)

```
asf idea "<text>" [--tree FILE] [--no-interrogate] [--product P] [--json]
asf idea --enrich <ID> [--tree FILE] [--no-interrogate] [--product P] [--json]
asf idea apply --tree FILE [--enrich ID] [--force] [--product P] [--json]
```

- The record resolves as `asf new` and `asf inbox` resolve it (`resolve_record`, the `record:`
  line on stderr).
- `--tree` defaults to `<state_dir>/idea/<stamp>.tree.md` (`<stamp>` is `%Y%m%dT%H%M%SZ`).
- Without `--no-interrogate`: build the `idea` brief, write it beside the tree, and run one job —
  `Job(product, name=f'idea-{stamp}', cwd=<state_dir>/idea/<stamp>/, brief_path=…, model=
  model_for(product, 'idea'), add_dirs=[record_root, dirname(tree)])` — through
  `runtime.from_config(load_cfg()).run(job, wait=True)`. The session's only deliverable is the tree
  file; it is told so, and it is given no worktree and no branch.
- Then `apply`: parse, filter, file, print. `--json` prints the `.applied` JSON instead of the
  lines.
- Exit codes: 0 filed (even when every node was answered by the record — that is a result, not a
  failure, and it is printed as one); 2 for a tree that does not parse, a missing tree, an
  already-applied tree without `--force`, or an enrich card that does not round-trip.
- The printed form:

  ```
  record: /Users/…/backlog
  idea: 4 node(s) — 3 filed, 1 answered by the record
    filed    inbox/idea-20260923T1612Z-01-epic-metered-billing.md   Epic  Metered billing
    filed    inbox/idea-20260923T1612Z-02-feature-the-usage-meter.md Feature The usage meter
    answered F-0031 — Approvals as code (feature, Active)           Feature Approval classes
  next: asf groom  (the cards are typed and minted there)
  ```

### `asf/briefs/templates/idea.md` (new kind)

Registered in `KINDS`, `DEFAULT_MODELS` (`HEAVY` — this is the judgement the card is about) and
**not** in `ID_RANGE_KINDS`: the interrogator mints nothing. `add_dirs_for` grants
`dirname(row.tree_file)` for a row that carries one, as it grants the groom's two files today
(`asf/briefs/build.py:154-174`). The template's job section:

- names `{tree_path}` as the only file to write, and the grammar above as its shape;
- says the record is to be read first and names what it holds (the preamble's Epics and Features);
- states D2 in one line: *never ask — propose, and write the proposal as an assumption*;
- for `--enrich`, names `{item_id}` and says the tree is exactly one node, rooted on that card;
- ends with `asf idea apply --tree {tree_path}` as the session's last act when the factory started
  it (the front door runs `apply` itself).

### The refine line in a brief

`asf/briefs/preamble.py`, `state_lines` (`:336`): when `facts['kind']` is `spec` and
`facts['spec_recorded']` (or `plan`/`plan_recorded`), one line after the document lines:

```
Refine, do not regenerate: `docs/specs/f-0023.md` is in the record. Your diff amends it — every `##`
heading and every S-/T- id it carries survives unless this card says it is wrong. A branch that
drops one, or deletes more than half of it, is held at the harvest and comes back to you as a
correction before a reviewer reads it.
```

`context()` (`asf/briefs/build.py:194`) gains `'refine'`, the same sentence or `''`, and
`templates/spec.md` and `templates/plan.md` carry `{refine}` immediately above their DELIVERABLE
paragraph. A Feature with no document recorded gets the empty string, and the templates read
exactly as they do today.

### `asf/harvest/refine.py` (new)

```python
ANCHOR_HEADING_RE = re.compile(r'^(#{2,4})\s+(.+?)\s*$', re.M)
ANCHOR_ID_RE = re.compile(r'\b([ST]-\d+)\b')
DEFAULT_REWRITE_RATIO = 0.5          # conventions.harvest.rewrite_ratio

def anchors(text) -> set          # headings (normalised) | S-/T- ids
def verdict(before, after, ratio) -> (kind, text) | None
```

- `before` empty → `None`: there is nothing on the trunk to refine.
- `lost = anchors(before) - anchors(after)` non-empty → `('rewrite', "<n> anchor(s) the document on
  <trunk> carries are gone: <up to five, quoted> — a request that names an existing document
  refines it and never regenerates it; restore them or say on the card why they are wrong")`.
- `deleted / len(before.splitlines()) >= ratio`, where `deleted` counts `-` lines of
  `difflib.unified_diff(before, after, n=0)` → `('rewrite', "<d> of <n> lines of <path> on <trunk>
  are deleted (<pct> %) — that is a regeneration, not a refinement")`.
- else `None`.

In `harvest.py`, one function beside `lane_refusal` and one line at the call site:

```python
def refine_refusal(repo, trunk, branch, item, conv):
    """A spec/plan lane branch that regenerates the document already on the trunk, instead of
    refining it (F-0023). None for every other lane and for a document the trunk does not have."""
    path = deliverable_of(conv, branch, item)
    if not path:
        return None
    before = sh(['git', 'show', f'origin/{trunk}:{path}'], cwd=repo)
    if before.returncode != 0:
        return None
    after = sh(['git', 'show', f'origin/{branch}:{path}'], cwd=repo)
    if after.returncode != 0:
        return None
    return refine.verdict(before.stdout, after.stdout, rewrite_ratio(conv))
```

```python
refusal = lane_refusal(repo, trunk, branch, item) or refine_refusal(repo, trunk, branch, item, conv)
```

The held line reads `held spec/F-0023: <n> anchor(s) … — back to its session (round 1)`, which is
`hold_with_correction`'s own line (`asf/harvest/harvest.py:857-869`). The next tick's

already exists for a red gate.

### `asf refine-check` and the rule script

`asf refine-check [--product P] [--branch B] [--json]` runs `refine_refusal` over every `spec`/`plan`
lane branch on the product repo's origin (existing remote-tracking refs; it fetches nothing, so it
stays inside the rule runner's 10 s), prints one line per rewriting branch and exits 1 when there is
one:

```
spec/F-0023 docs/specs/f-0023.md: 3 anchor(s) the document on main carries are gone: "## Records", …
```

`rules/refine-not-rewrite.sh` — the first file in this repo's core rules directory
(`asf/rules/rules.py:43-51`, `asf/hooks.py:38`) — is three lines: `exec asf refine-check --product
"${ASF_PRODUCT:?}"`. The rule card is minted into the record when the work lands:

```sh
asf new rule --title "A brief naming an existing spec or plan refines it, never regenerates it" \
  --set check=rules/refine-not-rewrite.sh --set scope=product --set enforced=true
```

### `CARD → ENRICH`

`asf/record/core.py`: `compute_derived` adds `acceptance_items` (checklist lines under
`## Acceptance` with text after the box) and `description_words` (words under `## Description`) per
item; `build_index_data` copies both into the entry.

`asf/conventions.py`: `DEFAULT_THIN_ACCEPTANCE = 1`, `DEFAULT_THIN_DESCRIPTION_WORDS = 40`,
`DEFAULT_REWRITE_RATIO = 0.5`, `DEFAULT_ANSWER_OVERLAP = 0.8`, spelt in the yaml as

```yaml
conventions:
  thin_card: {acceptance_items: 1, description_words: 40}
  harvest: {rewrite_ratio: 0.5}
  idea: {answer_overlap: 0.8}
```

`asf/feeder/rows.py`:

```python
CARD_ENRICH = 'CARD → ENRICH'

def thin(item, conv):
    return (item.get('acceptance_items', 0) < conv.thin_acceptance
            or item.get('description_words', 0) < conv.thin_description_words)
```

and in `feature_rows`, where `word == 'card'` (`:308`):

```python
if word == 'card':
    if thin(f, _conventions(product)) and not f.get('enriched'):
        out.append(Row(tier=2, kind=CARD_ENRICH, item_id=fid, feature_id=fid, action=LAUNCH,
                       brief_kind='idea', branch=branch_for(product, 'enrich', fid),
                       reason='thin card: no acceptance list to spec from',
                       tree_file=tree_file_for(product, fid)))
    else:
        out.append(Row(..., kind=CARD_SPEC, ...))   # unchanged
```

`Row` gains `tree_file: str = ''` beside the groom row's fields. `KIND_ORDER` is untouched: an
ENRICH row and a SPEC row are never both emitted for the same Feature, so nothing has to order
them. The module docstring's row table gains the line.

The enrich session writes only the record (its worktree's branch is never pushed, exactly as the
groom session's is not), so no harvest lane changes.

## Records

- **Intake files.** One per filed node, `<intake_dir>/idea-<stamp>-<nn>-<type>-<slug>.md`, carrying
  the title, `parent:` (an `inbox:<file>` reference or a record id), the description, and
  `## Features` / `## Assumptions` / `## Acceptance` as the node has them. The groom mints them and
  moves each to `<intake_dir>/done/<slug>.md` with its `→ <id>` first line, exactly as today.
- **The run's report.** `<intake_dir>/done/idea-<stamp>.md`: the ask verbatim, one line per node
  (`filed <file>` or `answered by <id> — <title>`), and the parsed tree. This is the record that a
  question was answered from the record rather than put to a person.
- **`<tree>.applied`.** JSON beside the tree file: `stamp`, `filed`, `answered`, `report`. Written
  once; its existence is what refuses a second `apply` (D12).
- **The card's History.** A filed card carries intake's own line, `- <date>: created (inbox) —
  shape: <rule> → <type>`. An enriched card gains `- <date>: enriched (idea) — +<n> acceptance,
  +<m> assumption(s)`.
- **The typed field `enriched: <date>`** on an enriched Feature — the record's statement that the
  interrogator has been here, and the feeder's guard against a second ENRICH row (D6).
- **`index.json`.** Two new derived keys per item, `acceptance_items` and `description_words`.
  Generated, never typed; no card is edited to carry them.
- **The groom file.** No new section. Filed cards appear under "Inbox cards to decide" and, when
  intake cannot type one, under "Inbox cards with a question" — both existing sections, both
  existing lines.
- **The session ledger.** An ENRICH row launches job `idea-<id>` on branch `enrich/<id>`; the front
  door's foreground session is `idea-<stamp>` and takes no worktree and no branch.
- **The held branch.** A bounced doc branch gets `correction: {kind: 'rewrite', text: …, rounds: n}`
  on its run in `sessions.jsonl` — `lifecycle.hold`'s existing shape, which the feeder reads back as
  a `FIX → CORRECT` row.
- **`docs/CONSTITUTION.md`.** Directive 1's TRIGGERS line becomes `**TRIGGERS: checked.** The
  interrogator is `asf idea` ([[F-0023]]); the harvest holds a spec or plan branch that drops an
  anchor of the document already on the trunk, and `asf refine-check` is the rule's check.` The
  tally row for directive 1 becomes `checked`, and the closing "four of ten" count becomes three.
- **No new events and no new metric.** The launch of an ENRICH row is a `launch` event like any
  other, with `brief_kind: idea`.
