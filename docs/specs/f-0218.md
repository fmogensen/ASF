# F-0218 — one call, one item, every park

Three items on a product needed `asf unpark` **twice** each on 2026-09-27 (F-0019, F-0011,
F-0094): the first call printed `unparked <ITEM> (job …)` and exited 0, and the item stayed on the
feeder as a row waiting on the operator, still parked.

The command reads one park and releases one park. `parked_job` collects every pending correction on
the item, takes `max` by `at` — the newest — and returns that single `(job, correction)`;
`cmd_unpark` appends one ledger line for that one job (`asf/workers/unpark.py:14-33`, `:35-50`).
An item holding two parks therefore takes two calls, and the operator has nothing in the output
that says so: the same success line, the same exit 0, and the row still there on the next tick.

Two parks on one item is not an exotic state. `pending_correction` answers a correction only with a
run of the same item that **started** at or after it (`asf/workers/lifecycle.py:736-742`), so two
runs that both started before either park was written answer neither, and both parks stay pending
at once. Reproduced in this checkout (P2).

The same single read has a second, worse face. When the newest pending correction on the item is
*not* a park, `cmd_unpark` tests that one, prints `is not parked — nothing to undo` and exits 1 —
while an older park is still holding the item. There is no call that gets the operator out of it
(P3).

This card is: **one call releases every park the item holds, and when anything still holds it the
command says what and how many.**

### The choices

| # | Chosen | Against | Why |
| --- | --- | --- | --- |
| C1 | **Release every park the item holds, in one call.** | Keep releasing the newest and print `1 of 2 — run it again`. | The card allows either, and the operator's cost is the repeat: three items, two calls each, and nothing in the first call's output saying a second was due. "Release every park" makes the command's name true — after it returns, no park on that item is holding it — and the report (C4) is then about what is *left*, which is never another park the command could have taken. |
| C2 | **A pending correction that is not a park is left standing, and named.** | Clear every pending correction on the item. | A plain correction is the next session's instruction: the text it must answer. Clearing it drops the instruction and relaunches the item with an empty brief, which is a worse failure than a park. `unpark` is the park's undo (F-0095 §2.5), not the correction's. |
| C3 | **A park under a newer plain hold is released** — the command looks for parks among *all* the item's pending corrections, never at the newest one only. | Keep today's refusal (P3). | Today that item has no way out: the park is permanent (a park launches nothing, so nothing later starts to answer it) and the one command for it refuses. The plain hold keeps holding the item afterwards, and C4's report says so — the operator learns the park is gone and a correction is next, which is the truth. |
| C4 | **Exit 0 after any release, with a `released N park(s)` line always and a `still held`/`still parked` line per remaining pending correction.** | A third exit code for "released but still held"; printing the summary only when `N > 1`. | One shape, one thing to assert, no branch for the single-park case — and the existing tests (P8) assert *content*, never a line count, so a summary line is free. A new exit code is read by nothing and would turn a successful release into a scripted failure. The two refusals keep code 1 and their exact strings (`not parked`, `not in the ledger`). |
| C5 | **One appended line per parked job, all carrying the one `unparked` stamp of this call and the same `--why`.** | One line naming a list of jobs; a fresh timestamp per line. | The ledger is a stream of per-job lines — `update_session` takes one job, and the fold applies a line to that job's latest run (P5). One stamp is what `max((r.get('unparked') …))` reads when the lane counts launches since the item's latest unpark, so every release of one call is the same release to that reader. |
| C6 | **The parks are read once before the first append; what still holds the item is re-read once after the last.** | Recompute the set after each release; report from the set that was read up front. | Reading once fixes the order and the count the operator is told. Re-reading at the end is what makes the report true rather than predicted — it catches a correction the command was never allowed to touch (C2) and a park health wrote while the command was running, and P6 says the re-read really re-folds. |
| C7 | **`parked_jobs` replaces `parked_job`.** | Keep `parked_job` beside it as the one-park convenience. | It has no other caller (P7), and two functions answering "what park is on this item" is how the two answers drift apart. |
| C8 | **The parks are gathered with `lifecycle.item_runs(path, item)`; the "not in the ledger" gate keeps its raw `runs()` scan.** | `item_runs` for both; the hand filter over `runs()` for both. | `item_runs` is what `correction_of` — the feeder's own reader — uses, so the command and the row it clears read the item's runs the same way, and it drops a reset item's closed runs for free. The `known` gate is deliberately left on the raw scan: `item_runs` hides runs from before an `asf reopen`-style reset, and an item whose only runs are those should keep saying `not parked` (code 1) rather than start saying `not in the ledger` (P8 pins both strings). |
| C9 | **The operator-visible one-liner changes in `register()`; `asf/surface.py` and the README are untouched.** | Editing the surface row; wiring `surface.apply` so the table is the single source. | P9: the parser's `help=` is the string `asf --help` actually prints, and the surface row ('release an item the pool is holding') stays true as written. `surface.apply` having no caller is a real defect — the module docstring claims `asf --help` is rendered from the table — but it is a different card, and fixing it here would change 49 help lines under a spec about one command. |
| C10 | **The operating guide's park bullet gains the clause.** | Leaving the guide alone because it never claimed one-per-call. | `docs/guide/operating.md:210-212` is where the operator is sent when they read `parked <branch>: ended empty 2 times …`, and the thing they need to know is that one call is enough and the output says what is left. One clause, in the place the behaviour is read from. |
| C11 | **Why an item ends up with two parks is not touched.** | Also stopping two runs of one item from both ending parked. | The card is the way *out* of a park, and the concurrency that writes two parks is health's and the lane's judging half. Named as deliberately out, not overlooked. |

### In, and out

**In.** `asf/workers/unpark.py`: `parked_jobs` in place of `parked_job`, `cmd_unpark` releasing
every park it found, the `released N park(s)` line, the `still held` / `still parked` lines from one
re-read, and the parser's `help=`. `tests/test_cli.py`: the existing harness extracted to a base
class with no test methods, and a new class for the multi-park behaviour.
`docs/guide/operating.md`: one clause on the park bullet.

**Out.** (a) Health's own park lift (P10) and everything else that writes a park. (b) The two
refusals — their strings, their exit code 1, and the `known` gate that produces one of them (C8).
(c) `operator_flagged`: not cleared by an unpark today, and the feeder holds the row on the
correction (P11); a card that wants the flag cleared is a card about the flag. (d) Clearing a
pending correction that is not a park (C2). (e) Wiring `surface.apply`, the surface row, the README
(C9). (f) Preventing two parks on one item (C11).

## The design

### §1 `parked_jobs` — every park the item holds, oldest first

`asf/workers/unpark.py`. `parked_job` is replaced by:

```python
def parked_jobs(path, item):
    """Every park ``item`` is holding now: ``[(job, correction), ...]`` oldest first, one entry
    per job (P4: only one park per job is ever pending, and a job takes one undo line whatever
    the ledger holds). Read once, before any line is appended — the order and the count the
    operator is told are this list's."""
    held = {}
    for run in lifecycle.item_runs(path, item):
        corr = lifecycle.pending_correction(run, path)
        if not corr or not corr.get('parked'):
            continue
        job = run.get('job')
        prev = held.get(job)
        if prev is None or (corr.get('at') or '') >= (prev.get('at') or ''):
            held[job] = corr
    return sorted(held.items(), key=lambda jc: ((jc[1].get('at') or ''), jc[0]))
```

A second reader answers the report, over its own fresh read of the same file:

```python
def still_holding(path, item):
    """``[(job, correction), ...]`` of every correction still pending on ``item`` — read after
    the undo lines are appended, so what it names is what the next tick will see (P6)."""
    out = []
    for run in lifecycle.item_runs(path, item):
        corr = lifecycle.pending_correction(run, path)
        if corr:
            out.append((run.get('job'), corr))
    return sorted(out, key=lambda jc: ((jc[1].get('at') or ''), jc[0]))
```

### §2 `cmd_unpark` — one call, every park, then the truth about what is left

```python
def cmd_unpark(args):
    product = env.load_product(getattr(args, 'product', None))
    item = (args.item or '').strip().upper()
    path = pool_mod.sessions_path(product)
    known = any(r.get('item') == item for rs in lifecycle.runs(path).values() for r in rs)
    if not known:
        print(f'asf unpark: {item} is not in the ledger — nothing to unpark')
        return 1
    parks = parked_jobs(path, item)
    if not parks:
        print(f'asf unpark: {item} is not parked — nothing to undo')
        return 1
    now = datetime.datetime.now(datetime.timezone.utc).strftime('%Y-%m-%dT%H:%M:%SZ')
    why = getattr(args, 'why', None) or ''
    for job, corr in parks:
        pool_mod.update_session(product, job, correction=None, unparked=now, unpark_why=why)
        print(f'unparked {item} (job {job}): {corr.get("reason") or ""}'.rstrip(': '))
    left = still_holding(path, item)
    released = f'released {len(parks)} park{"s" if len(parks) != 1 else ""} on {item}'
    if left:
        released += (f' — {len(left)} correction still holds it' if len(left) == 1
                     else f' — {len(left)} corrections still hold it')
    print(released)
    for job, corr in left:
        what = 'still parked' if corr.get('parked') else 'still held'
        line = f'{what} ({job}): {corr.get("reason") or corr.get("text") or ""}'.rstrip(': ')
        print(line + (f' — run `asf unpark {item}` again' if corr.get('parked') else ''))
    if why:
        print(f'why: {why}')
    return 0
```

Three things are load-bearing and each has its precondition: the item's parks are gathered before
the first append (C6) and the loop iterates that fixed list; every line of the loop carries the one
`now` and the one `why` (C5); and `left` comes from a second read of the file after the last append
(P6), so it names what the next tick will see rather than what was predicted.

The module docstring's last sentence — "The exit is one appended ledger line for the job that holds
the park" — becomes "one appended line per parked job: every park the item holds goes in one call,
and the parks and their undos all stay in the file."

### §3 The two lines the operator reads

`register()`'s help, the string `asf --help` prints (P9):

```python
    p = sub.add_parser('unpark', help='release every park an item is holding')
```

`docs/guide/operating.md`, the park bullet (`:210-212`), gains one clause after the command:

> `asf unpark <item> --why "<reason>" --product <p>` — one call releases **every** park the item
> is holding and prints how many; anything still holding it afterwards is named on its own line.

### What it looks like when it is there

The observed case — an item holding two parks — in one call:

```
$ asf unpark F-0019 --why "already on the trunk" --product <p>
unparked F-0019 (job coder-f-0019): ended empty 2 times: the Task is parked
unparked F-0019 (job reviewer-f-0019): ended empty 2 times: the Task is parked
released 2 parks on F-0019
why: already on the trunk
$ echo $?
0
```

Two lines are appended to `sessions.jsonl`, the item's row leaves the feeder, and a second call
says `asf unpark: F-0019 is not parked — nothing to undo` with code 1.

P3's dead end, now a way out that does not lie about the item being free:

## Records

Nothing new is recorded: no field, no file, no event is added.

- **`<state>/sessions.jsonl`** — one appended line **per parked job**, where there was one per
  call: `{"job": "<job>", "correction": null, "unparked": "<one stamp for the call>",
  "unpark_why": "<--why or empty>"}`. Every park line and every earlier undo stays in the file;
  the record only grows (P5). The shape is the one health already writes (P10), so
  `lifecycle.fold`, `RUN_FIELDS` and `max(unparked)` need nothing.
- **What stops being recorded**: the second call. Where the ledger held two `unparked` stamps
  minutes apart for one operator decision, it now holds one stamp on as many lines as there were
  parks — which is what the lane's "launches since the item's latest unpark" guard reads (C5).
- **stdout** — one `unparked <ITEM> (job <job>): <reason>` per released park (today's line,
  unchanged), then always one `released N park(s) on <ITEM>` with its `— N correction(s) still
  hold(s) it` tail when anything remains, then one `still held (<job>): …` or `still parked
  (<job>): … — run \`asf unpark <ITEM>\` again` per remaining correction, then `why: …` when
  `--why` was given. Exit 0 on any release; 1 unchanged for `not parked` and `not in the ledger`.
- **The feeder's rows** — no write. The operator-waiting row for the item goes when the last
  pending correction does, which after this change is the first call whenever only parks held it
  (P11); an item left with a plain correction keeps its row, and the output said so.
