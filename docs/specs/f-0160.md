# F-0160 — the ledger stops guessing that a result is the end

`lifecycle.judge` reads two pieces of evidence about whether a run is over — its log's last result
line and whether its pid still answers — and consults the second one only when the first is absent:

```python
if ev.result is None:
    return None if ev.alive else DEAD_PID
```

A result therefore ends the run outright. The pid is not asked. On 2026-09-26 that put `ended` on
`review-t-0075` (pid 38052) at 13:28Z, on the first result its log carried, while the process went on
working for another thirteen minutes and wrote eight more results, the last at 13:41Z.

`ended` is not a note. It is the one word every other reader keys on: `lifecycle.is_live` is
`not run.get('ended')`, and `occupies` — the seat count the pool, the feeder's in-flight list and
capacity all ask — is `is_live(run) and alive(pid)`. Writing it early does not merely mis-date a row;
it hands the seat back and lets the lane move the item on while the session that owns the worktree is
still writing to it. Both happened: T-0075 went to pushed/PR with its session still running.

The rest of the tree already says the right thing. `lifecycle.classify` — what `/asf:sessions`,
`asf status` and `asf next` print — asks `ev.alive` **first** and calls a live run `working` whatever
its log holds (`asf/workers/lifecycle.py:1717`). `finished_unrecorded` requires the pid to be gone
before a result counts (`:528`). The operator guide defines **Finished** as "its process *exited*
after writing a success result" (`docs/guide/operating.md:143`). One function disagrees with the
three statements of the same rule, and it is the one that writes to the ledger.

This card makes `judge` agree with them, and pays the bill that comes with it: a process that has
written its result and will not exit must now be **stopped**, because the ledger is no longer allowed
to pretend it already has.

### In

- **`lifecycle.judge` never returns a verdict for a live pid.** One guard, moved to the top:
  `if ev.alive: return None`. A result while the process is up is "still working" — D1.
- **`health.settle_quiesced`** — the bill. A **live, local** run whose last run has closed on a
  result and whose log has been quiet for the grace is stopped, with `settle_ended`'s three identity
  guards (P10) and its SIGTERM→SIGKILL (P11), so `judge` can end it on a pid that is actually gone.
  It writes nothing to the ledger.
- **Its wiring, before the judge loop.** `health()` calls `settle_quiesced` after `alive` is built
  and before any run is judged, and wraps `alive` with the pids it stopped (P12), so the pass that
  stops the process is the pass that records the end. `settle_ended` stays exactly where it is (P13).
- **`stall.classify` stops treating a result as the end** (P17). The result test moves inside the
  dead-pid branch — a pid gone after a result is finished-awaiting-health, not `DEAD` — and a live
  run with a result falls through to the silence test, so a process `settle_quiesced` could not stop
  is a visible `STALL` row instead of nothing.
- **The prose that states the old rule**: `asf/workers/health.py`'s module docstring, the opening
  line of `asf/tick/step_health.py`'s, and `docs/guide/operating.md`'s health row and session list.

### Out

- **Changing `classify`, `finished_unrecorded`, `occupies`, `is_live` or any view.** They are already
  right (P3, P4, P5); this card makes `judge` agree with them, and the acceptance pins that agreement
  rather than editing either side of it.
- **Changing what `judge` decides once the pid is gone.** `finished`-means-pushed (B-0051), `empty
  branch` (B-0076), the failure signatures, the no-landing kinds: untouched. The only new input is
  `ev.alive`, and its only effect is to withhold a verdict.
- **A new field on `sessions.jsonl`.** Nothing is recorded about quiescing; the ledger gains no
  column and no new `end_reason`. A stopped-then-ended run ends `finished` (or whatever its evidence
  says) exactly as it would have if it had exited by itself — D4.
- **A new config key.** The quiesce grace is `LINGER_GRACE_S`, the constant that already means "how
  long a process gets to exit by itself" — D3. `stage_limits` gains nothing.
- **Cloud runs in the quiesce path.** A cloud log is quiet by design (P18) and a cloud result implies
  a terminal token (P15), so there is nothing to detect and nothing to stop — D6.
- **Escalating a process that refuses to die.** `settle_quiesced` retries every pass and the run
  keeps its seat while it does, which is honest: the machine is still occupied. The new `STALL` row
  is the operator's signal — D7. No `needs-operator` event is added.
- **The relaunch-on-top-of-a-live-session loop.** The card records nine results in one log (P7, P8);
  whether the extra runs came from a continuation or from the lane relaunching the job whose seat had
  just been freed is not established here, and is not fixed here. Ending the run correctly removes
  the trigger either way — D8.
- **Backfilling the ledger.** Rows already written with an early `ended` stay as they are.

| # | Chosen | Against | Why |
| --- | --- | --- | --- |
| D1 | One guard at the top of `judge` — `if ev.alive: return None` — before the result is looked at | keep the result first and special-case it: `if ev.result is not None and ev.alive and <the result is not final>` | the card's expected behaviour is a single sentence about a single input, and the tree already writes it three times that way (P4, P5, P6). | D4 | A stopped-then-judged run ends on its **own evidence** — `finished`, `failed: not pushed`, whatever `judge` says — never `stopped` or a new reason of its own | end it `stopped`, as `lifecycle.stop` does for an operator's kill | the run did its work and wrote its result; the only thing wrong with it is that its process would not exit. `stopped` means "an operator decided", carries `stop_tip` and `pushed_after_stop`, and is deliberately excluded from `outcome_class` as "not the factory's outcome" — labelling a finished run with it would lose a landing harvest should take. | D5 | `settle_quiesced` runs **before** the judge loop and the `alive` it hands that loop is wrapped with the pids it stopped (P12) | run it after, beside `settle_ended`, and let the run end on the next tick | a stop and the end it enables belong in one pass, or health's output says "stopped a process" this tick and "ended the run" next tick with nothing connecting them. The `alive`-wrapping idiom is already in the file for exactly this (P12), so the cost is one call site. `settle_ended` cannot move for the opposite reason (P13): it settles runs this pass ended. | D6 | The quiesce path is local-only; a cloud run stays live until its **token** is terminal | apply the same silence rule to cloud logs | a cloud log is quiet by design (P18) — silence there measures nothing. | D7 | A process that survives SIGKILL keeps its run live, its seat held, and gets a `STALL` row | force the end after N failed stops; raise a `needs-operator` event | a seat is a claim about a machine, and the machine really is occupied — handing it out because we could not kill the occupant is how two sessions end up in one worktree, which is the failure this card exists to stop. `STALL` is the existing channel for "a live session needs a person" and it already prints in the tick, so the operator learns about it on the next pass with no new event type. The one thing that must not happen — silence — is exactly what P17 causes today and what this card removes |
| D8 | `stall.classify`'s result test moves **into** the dead-pid branch rather than being deleted | delete it; or leave `stall` alone | deleting it makes every run that finished between two ticks a false `DEAD` row, because the pid is legitimately gone and the run legitimately has no `ended` line yet — that is `finished_unrecorded`'s state (P5), not a death. ## The design

### `asf/workers/lifecycle.py` — the rule

`judge` gains one guard and its docstring gains the sentence that guard is:

```python
def judge(run, ev, landing=None):
    """The ``end_reason`` health records for a run whose session is over, or None while it runs.

    **A live pid is never judged** (F-0160). A result record is not the end of a session: a job's
    log may hold several runs (:func:`asf.workers.runtime.read_result`), and between one run's
    result and the next run's ``init`` the log's last record is a result while the process is
    still working. Reading that as the end put ``ended`` on a run at its first result and left the
    process writing for another thirteen minutes, with its seat handed back and its item moved on
    (2026-09-26, review-t-0075). The pid is the only evidence that distinguishes the last result
    from the first; health stops a process that has gone quiet and will not exit
    (:func:`asf.workers.health.settle_quiesced`) rather than recording an end it has not reached.

    A result that says ok is ``finished`` only when the branch is pushed; ...
    """
    if landing is None:
        landing = lands(run)
    if ev.alive:
        return None
    if ev.result is None:
        return DEAD_PID
    ...unchanged from here...
```

Nothing else in the module moves. `classify` keeps its own `if ev.alive` (P4) — it now states the
same rule as the function it calls, which the acceptance pins.

### `asf/workers/health.py` — the stop that pays for it

The three guards come out of `settle_ended`'s loop unchanged (D10):

```python
def own_process(run, pid, observed_by_pid, cmdline, binary):
    """True when the process at ``pid`` is provably the one the factory launched for ``run``: an
    observed ``asf`` session sits there carrying the run's own ``ASF_SESSION``, and its command
    line is the runtime binary with ``-p``. A run with no ``session``, a process with another or
    no ``ASF_SESSION`` (an interactive session), or any other command line is never touched."""
    o = observed_by_pid.get(pid)
    if o is None or o.owner != 'asf' or not run.get('session') or o.session != run.get('session'):
        return False
    return is_print_worker(cmdline(pid), binary)
```

and the new pass beside `settle_ended`:

```python
#: seconds a **live** run's log must have been quiet, its last run closed on a result, before
#: health stops the process that will not exit (F-0160). The same grace an ended run's process
#: gets (:data:`LINGER_GRACE_S`), anchored on the log's last write because a live run has no
#: ``ended`` stamp to measure from.
QUIESCE_GRACE_S = LINGER_GRACE_S


def quiet_for(log_path, now):
    """Seconds since ``log_path`` was last written, or None when there is no readable log."""


def settle_quiesced(product, sessions, now=None, fix=True, session_source=None, cmdline=None,
                    wait_s=STOP_WAIT_S, grace_s=QUIESCE_GRACE_S):
    """F-0160: a live run whose process will not exit is stopped, not ended on paper.
    ``[(job, what, detail)]``, the same shape :func:`settle_ended` returns.

    A candidate is a run with no ``ended`` line, a local pid, a log whose last run has closed on a
    result (:func:`asf.workers.runtime.read_result`) and no write for ``grace_s``. It is stopped
    (SIGTERM, then SIGKILL after ``wait_s``) only when :func:`own_process` holds — ``stopped``;
    without ``fix`` it is only listed ``lingering``. Nothing is written to the ledger: the run is
    ended by :func:`asf.workers.lifecycle.judge` on the next gather, on its own evidence, once the
    pid it names is genuinely gone.

    A cloud run is never a candidate: its log is quiet by design, and
    :func:`asf.workers.cloud.sync` — which is what appends a cloud result line at all — records
    the token terminal in the same pass, so a cloud result never coexists with a live token.
    """
```

`stopped` rows read
`pid 38052 (SIGTERM): its run closed with a result and its log has been quiet 7m, still running`
and `lingering` rows `pid 38052: its run closed with a result and its log has been quiet 7m, still
running` — the second whitespace-separated token is the pid in both, as P12 requires.

`health()` grows one call and one rewrap, immediately after `alive` is resolved and before the
per-run loop:

```python

        alive = alive_for(product, sessions.values(), session_source)
    # F-0160: a live run whose process will not exit is stopped BEFORE anything is judged, so the

    quiesced = settle_quiesced(product, sessions, fix=fix, session_source=session_source)
    found.extend(quiesced)
    alive = not_alive(alive, stopped_pids(quiesced))
```

### `asf/workers/stall.py` — the live run with a result stops being invisible

```python
def classify(session, now, silent_min, alive, verdict=None):
    """``STALL`` | ``DEAD`` | ``STUCK`` | None for one live session.

    A result is not the end (F-0160): a pid **gone** after one is finished awaiting health's tick
    (:func:`asf.workers.lifecycle.finished_unrecorded`), never ``DEAD``; a pid still **alive**
    after one is judged by silence like any other live run, which is how a process
    :func:`asf.workers.health.settle_quiesced` could not stop reaches an operator. A closed run is
    judged by silence alone — ``STUCK`` asks whether a session is moving, which a run that has
    written its result is not trying to do."""
    log = session.get('log')
    result = runtime_mod.read_result(log)
    if not alive(session.get('pid')):
        return None if result is not None else 'DEAD'
    if cloudpid.is_token(session.get('pid')):
        return None  # a cloud session's log is quiet by design: its time limit is the lane's
    if result is not None:
        verdict = None
    try:
        mtime = os.path.getmtime(log)
    except (OSError, TypeError):
        return None
    if (now - mtime) / 60 > silent_min:
        return 'STALL'
    return 'STUCK' if verdict is not None and verdict.cls == progress.STUCK else None
```

## Records

- **Nothing new is persisted.** `sessions.jsonl` gains no field and no new `end_reason`. The only
  change to what is written is **when**: the `ended` / `end_reason` line for a run whose process is
  still up is not written until it is not — the same line, with a later stamp and a truer one.
- **A run stopped for quiescing ends on its own evidence** — `finished`, `failed: not pushed: …`,
  `failed: empty branch: …` — never `stopped`, which stays reserved for an operator's decision and
  its `stop_tip` (D4). Nothing on the ledger distinguishes a run whose process exited by itself from
  one health had to stop; the distinction is a fact about a process, and it is printed, not recorded.
- **Two new lines in health's own output**, in the tick log and in `asf workers health`:
  `<job> stopped pid <n> (SIGTERM|SIGKILL): its run closed with a result and its log has been quiet
  <m>m, still running`, and `<job> lingering pid <n>: …` when health is run without `--fix`.
- **`STALL` can now name a run that has a result.** `<job> STALL … silent <m>m` for a live session
  whose process wrote its result and would not die — the row that used to be suppressed (P17, D7).
  `stall-ack.txt` acks it like any other.
- **No event, no card, no correction, no round.** Quiescing raises no `needs-operator` event and
  spends nothing against the item: the run that is stopped is a run that already did its work.
- **Seats and in-flight counts change value, not shape.** `occupies` keeps returning `is_live and
  alive`; it simply stops returning False for a session that is still running. A product at capacity
  may now show one more session held for up to five minutes longer than it did — which is how long
  that session was actually there.
- **`docs/guide/operating.md`** records the rule an operator reads a session state by: a session that
  wrote a result but whose process is still up is working and holds its slot.
