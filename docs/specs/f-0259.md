# F-0259 — two S1 cards, three hours, and a question the record could already answer

On 2026-10-06 six intake cards sat in ASF's own inbox for two to three hours, two of them S1.
Nothing was broken. `shape.derive` asked each one a question it is entitled to ask —

```
Which Epic is this under? No open Epic shares a title word with it.
This reads as a defect. A Bug carries a signature — add signature: <the failing test or error
line>, or paste that line into the body …
```

— `inbox.question_lines` put each on a `→ answer: ____` line in `groom/<day>.md`,
`inbox.stuck_s1_lines` said the S1s aloud every tick, and then the factory waited for a person.
Three hours later a person answered by hand. Meanwhile the cards did not exist: not in
`index.json`, not in the feeder, not in `asf status` except as a `NEEDS OPERATOR` line.

Two things are wrong with that, and they are different sizes.

The small one is noise. Every tick, `apply_groom_answers` read the *untouched placeholder* as an
answer and refused it:

```
groom: answer not applied — inbox:item-ids-…md: "____" is not a clause. Clauses are close |
feature | bug <signature> | parent <id> | S1|S2|S3, separated by `;`.
```

`groom.unanswered()` exists for exactly this and the id branch of the same loop honours it. The
inbox branch never got it. F-0099's own precondition P3 asserts the opposite is already true —
"`apply_groom_answers` is already idempotent line by line: a blank slot, an unparsed word, or a
field already at its value writes nothing". It is true of one of the two branches.

The large one is the wait itself, and the record already holds the rule that settles it.
`file_bugs._file_or_bump_bug` mints an auto-filed Bug with

```python
# B-0089: an S1/S2 is decided by its severity — BUG → FIX must not wait for the daily groom
'decided': info['severity'] in ('S1', 'S2'),
```

so the identical defect is decided the moment CI finds it and undecided for three hours when a
person files it. And the two questions the incident waited on are not questions about facts only
a person has. "Which Epic is this under?" is answered by the open Epics the record carries, their
title words, the product's `default_bug_epic` and their rank — the same order the feeder itself
works them in. "A Bug carries a signature" is answered by the card's own title, which is what
`inbox.declared()` already does for a card that says `type: bug`.

So this spec does not add a rule that decides things. It supplies, into an urgent card, the one
fact `derive`'s own question was asking for — and then asks `derive` again. The kind is still
`derive`'s, by `derive`'s rules, over a card with one more fact on it. `shape.py` stays what its
docstring says it is: "the only place a type is chosen."

What this buys is not a faster answer to the question. It is that **the question moves from
before the card exists to after** — a card at `decided: false` with a `## Intake` section naming
every fact that was supplied, in the groom's "Inbox cards to decide" list the same tick, where a
person says `no` and it is removed. Three hours of an S1's life, spent in a directory, become a
line in a file a person reads anyway.

### In, and out

**In.**

1. `DECIDED_BY_SEVERITY`, `SUPPLY_MAX`, `Supplied`, and the supply functions in `asf/groom/inbox.py`:
   `nearest_parent`, `best_epic`, `supplied_parent`, `title_acceptance`, `supply`, `supplied`.
2. `BY_RULE` beside `RULES` in `asf/groom/shape.py`, and one comment line on `RULES`.
3. `process_inbox`: the gate, the `## Intake` section, `decided: True` for an urgent Bug, and one
   printed line per supplied card.
4. `apply_groom_answers`: one `unanswered()` guard on the inbox branch.
5. `docs/guide/operating.md`: the rule, and C16's correction.

**Out.**

* (a) **The three residues** (C9). An S1 card with no title, with an unreachable declared `type:`,
  or in a record with no open Epic still waits — loudly, through `stuck_s1_lines`, which is
  unchanged. An S2 residue carries its `S2` token on its `question_lines` line and is not said
  aloud, because `stuck_s1_lines` is S1-only and `test_s2_and_s3_cards_say_nothing` pins that
  (P4); widening it is a different card.
* (b) **`derive`'s own unvalidated `default_bug_parent`.** `cmd_groom` hands it the product's
  `conventions.default_bug_epic` without `usable_bug_epic`, so a Bug with a `signature:` and no
  `parent:` can be minted under a removed, Closed or missing Epic — with no question asked, so it
  is not this card's defect. The supplies validate the parent they supply (C7). A fix belongs with
  `cmd_groom`'s own read.
* (c) **The `decided:` gate for anything but a Bug.** A supplied Feature, Story, Task or Epic is
  minted `decided: False` and reaches the groom's "Inbox cards to decide" list the same tick, as
  every inbox card does today (P10).
* (d) **`question_lines`, `stuck_s1_lines`, `status.intake_cell`, `apply_answer`,
  `parse_answer`** — not a line (P4, C15). The answer grammar, the groom sections and the digest
  are untouched.
* (e) **Re-reading a card that is already stuck.** A card sitting on a `## Question` from before
  this lands is read again without it on the next pass, as it is today (`process_inbox`'s
  `_split_question` path) — so an urgent one is supplied and minted then, with no migration and
  no backfill.
* (f) **Any change to what a type *means*.** `SIZE`, `NEEDS`, `PARENT_TYPES` and
  `record.check`'s size rule are read, never edited.

## The design

### §1 The vocabulary — `shape.py`

```python
RULES = ('signature', 'writes', 'features-list', 'parent-feature', 'default')

#: The prefix intake puts on a rule when it reached it by supplying a fact the record already
#: held rather than by reading the card as the operator wrote it (:func:`asf.groom.inbox.supplied`):
#: `shape: by-rule-default → feature`. The rule names are this module's, so the prefix is too.
BY_RULE = 'by-rule-'
```

Nothing else in `shape.py` changes.

### §2 The gate and the ladder — `inbox.py`

```python
#: The severities at which an intake question is itself the defect: at S1 or S2 the intake
#: supplies the facts the record already holds and mints the card (F-0259); at S3 it asks, as it
#: always has. The same pair `asf.tick.file_bugs` decides a Bug by (B-0089).
DECIDED_BY_SEVERITY = ('S1', 'S2')

#: The ladder's bound: one more pass than :func:`supply` has guards, so a supply that fails to
#: settle its own question cannot spin. Reaching it is a defect in a guard, and the card keeps
#: its question.
SUPPLY_MAX = 14

#: What :func:`supplied` answers with: `result` is `shape.derive`'s own — a `Shape` whose rule
#: carries `shape.BY_RULE` when anything was supplied, or the `Question` of a residue; `card` is
#: the card the supplies built, which is what mints; `clauses` is one line per supply, for the
#: minted card's `## Intake` section, and is empty whenever `result` is a `Question`.
Supplied = namedtuple('Supplied', 'result card clauses')
```

```python
def supplied(card, canonical, default_bug_parent=None):
    """:data:`Supplied` for one urgent card: `shape.derive`'s answer, with the facts the record
    already holds supplied into the card until `derive` stops asking.

    It chooses no type. Every answer is `derive`'s, under `derive`'s own rules, over a card with
    one more fact on it (`shape.py`: "the only place a type is chosen") — so a supplied card is
    only ever a card `derive` would have minted had the operator written that fact down (C1).

    A residue — no title, a declared `type:` the supplies cannot reach, no open Epic — comes back
    as the `Question` `derive` asked, with no card and no clauses: a card that does not mint is a
    card nothing was supplied to (C9).
    """
    clauses = []
    for _ in range(SUPPLY_MAX):
        result = derive(card, canonical, default_bug_parent=default_bug_parent)
        if not isinstance(result, Question):
            if clauses:
                result = result._replace(rule=BY_RULE + result.rule)
            return Supplied(result, card, tuple(clauses))
        filled, why = supply(card, canonical, default_bug_parent)
        if why is None:
            return Supplied(result, card, ())
        card, _ = filled, clauses.append(why)
    return Supplied(derive(card, canonical, default_bug_parent=default_bug_parent), card, ())
```

### §3 The supplies — one pass, in `derive`'s order

```python
def supply(card, canonical, default_bug_parent=None):
    """`(card, why)` — the first fact the record already holds that one of `derive`'s refusals
    was asking for, supplied into `card`, with the clause that says what was supplied and why;
    `(card, None)` when there is nothing left to supply.

    Each guard below is the condition `shape.derive` guards one of its questions with, in
    `derive`'s own order — never the question's *text*, which is prose (C4). That is what keeps
    one supply to one refusal, and keeps a supply from answering a question `derive` did not ask.
    """
```

| # | Guard — `derive`'s own | Supplied | The clause |
| --- | --- | --- | --- |
| 1 | no title | nothing — residue (C9) | — |
| 2 | `signature:` and `writes:` | `writes:` dropped | ``writes: dropped — the card carries a `signature:`, so it is a Bug; the line it was written with is kept in the intake copy`` |
| 3 | `parent:` not in the record | `parent:` dropped | `parent: <id> dropped — the record holds no such item` |
| 4 | `signature:`, and the parent's type is not in `PARENT_TYPES['bug']` | `parent:` ← `supplied_parent(…, PARENT_TYPES['bug'])` | `parent: <id> — <why>; <named> is a <type>, and a Bug hangs under an Epic, a Feature or a Story` |
| 5 | `signature:`, no parent, no `default_bug_parent` | `parent:` ← `supplied_parent(…, PARENT_TYPES['bug'])` | `parent: <id> — <why>` |
| 6 | `writes:` and no legal parent | `parent:` ← `supplied_parent(…, PARENT_TYPES['task'])`, else `writes:` dropped | `parent: <id> — <why>` / ``writes: dropped — no open Feature or Story to hang a Task under; the card is read by the shape it has left`` |
| 7 | two or more `## Features` and a `parent:` | `parent:` dropped | `parent: <id> dropped — a Features list of two or more is an Epic, and an Epic has no parent` |
| 8 | the parent is a Feature and there is no `## Acceptance` | `acceptance` ← `title_acceptance(card.title)` | `acceptance — one item, the card's title: a Story is one PR with one acceptance list, and this is the line to replace` |
| 9 | the parent is a Story and no `writes:` | `parent:` ← that Story's `parent:` | `parent: <id> — under a Story only a Task hangs, so the card is read against that Story's Feature` |
| 10 | defect words, no acceptance, no `type: feature` | `signature:` ← `title_signature(card.title)` | ``signature: <title> — the title, the card named none: the same line `declared()` supplies a `type: bug` card`` |

is reached and never a dropped `parent:`.

    5. :func:`best_epic`

    Tiers 2-5 need ``'epic' in types``, so a Task is only ever supplied a parent by the climb.

## Records

* **The minted card** — the one record this change writes, and the only one. Three fields differ
  from today, all in `asf/groom/inbox.py`'s existing `write_new_item` call: a `## Intake` section
  (one line per supply, plus the closing line, plus the `decided:` clause for an urgent Bug), a
  History shape token prefixed `by-rule-` when anything was supplied, and `decided: true` on an
  intake Bug at S1 or S2. Every other field — `title`, `parent`, `severity`, `found_in`,
  `signature`, `writes`, `stories`, the Description, the `## Features` section, the acceptance
  list, `state: New`, `stage_since`, `updated` — is written exactly as it is written today. No
  card id of this product's own record appears in the section (C13).
* **The intake file** — untouched by the factory (C5). It moves to `<intake_dir>/done/<slug>.md`
  as `→ <id>` plus its original text, headers and all, which is the audit of what the operator
  actually wrote and is what `retired_keys` reads back.
* **The groom file** — one line in "Inbox cards to decide" per supplied card, from the existing
  `groom_inbox_section`, now reading `from inbox as <type> (by-rule-<rule>), awaiting a decision`.
  No new section, no new line shape, no new answer verb. A supplied card that is *not* decided is
  asked about there the same tick; `no` removes it, which is how a wrong supply is withdrawn.
  Nothing is added to "Inbox cards with a question": a supplied card never had one.
* **The tick's log** — one `groom: intake ruled <intake_dir>/<file> → <id> (<Sn>): <clauses>` line
  per supplied card, from `process_inbox`, record-relative and carrying no machine path (P17).
  `cmd_groom`'s own summary lines (`inbox N card(s)`, `asked N`) are unchanged and now count what
  they say: a supplied card counts in `inbox`, not in `asked`.
* **What stops being written** — the `groom: answer not applied — inbox:<file>: "____" is not a
  clause …` line, for all three placeholder shapes (P12). A refusal for an answer somebody really
  wrote is unchanged.
* **No new state file, no new config key, no new metrics stream, no new event, no new policy, no
  new `asf` command, no new module** (C14). The supplies are computed from the card and the
  record in the same pass that mints, and are never stored anywhere but on the card they minted.
* **`docs/guide/operating.md`** — the inbox paragraph gains the S1/S2 rule, the three residues and
  the `## Intake` section, and its stale "a `type:` line is not read" is corrected (C16). No other
  doc changes.
