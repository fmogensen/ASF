# F-0062 — twelve lines of command line are the whole boundary

`build_command` (`asf/workers/runtime.py:98-110`) is the entirety of this factory's launch path.
Eleven flags, four of them variable: a permission mode, an optional resume, the grants, the model,
the settings file. Every session of every role is launched the same way — `bypassPermissions` from
one pool-wide key (`asf/workers/spawn.py:715-716`), one settings file shared by every role
(`asf/workers/spawn.py:598-607`), a model label from the row (`asf/workers/spawn.py:685`), and
nothing else. A reviewer is launched exactly as a coder is. A `close` job, which has one right
answer and no judgement in it, is launched exactly as a spec is.

Meanwhile `asf/roles/` ships twelve role files that parse, validate against nine refusals and are
covered by eight test classes — and have **no production caller at all**. The only mention of the
module anywhere outside its own package is a comment (`asf/briefs/preamble.py:498`). The source
says why, in as many words (`asf/roles/roles.py:61-64`):

> `asf-locator`: no launch path yet — the runtime pipes one brief and picks one model (F-0029 D2);
> a restricted-tool sub-agent needs a launch mechanism this factory does not have, so the role
> ships and binds to nothing.

This Feature is that launch mechanism. It is not a new sandbox: the installed runtime already
carries every flag the card asks for — `--agent`, `--agents`, `--effort`, `--tools`,
`--allowedTools`, `--disallowedTools`, `--strict-mcp-config`, `--max-budget-usd`, `--plugin-dir`,
`--restricted` — and the factory passes none of them. The work is to stop launching every role as
root, to stop paying judgement prices for clerical work, and to stop putting a live credential in
the environment of a session that may print it.

That last one is not hypothetical. `build_env` ends with `out.update(auth)`
(`asf/workers/runtime.py:390`): the account's `CLAUDE_CODE_OAUTH_TOKEN` and the product's
`GH_TOKEN` are real variables in every session's real environment, by design — the session has to
push. A session that runs `printenv` prints them. `asf.redact` can already find both
(`asf/redact.py:69-79`, `:183`) and already knows how to blank them (`scrub`, `asf/redact.py:235`),
and `runtime.mask` exists for exactly this (`asf/workers/runtime.py:354-360`) — but it is called on
one log only, the worktree-setup log (`asf/workers/spawn.py:648-650`). The session's own transcript
is written by handing the child process the log's file descriptor (`asf/workers/runtime.py:531-537`):
no code of ours is between the two, and nothing is scrubbed.

## 1. Decisions

### 1.1 In

- **A launch table, in code, beside the roles** (§2.1) — `asf/roles/launch.py`: one `Launch` row
  per role carrying what the role file is forbidden to carry (`asf/roles/roles.py:43`,
  `asf/roles/__init__.py:12-14`): permission mode, effort, the tool set, the write surface, the
  external-connection list. The role `.md` keeps identity and doctrine and gains not one key.
- **A capability probe before any new flag is passed** (§2.2) — `asf/workers/capability.py`: the
  long-option names of the installed binary, read once from its own `--help`, cached by binary
  path and mtime. A flag the installed version does not carry is **not passed**, and
  `asf doctor` says which and what it costs. A launch that passes an unknown flag dies at once —
  the same failure `model_arg` already refuses to cause (`asf/workers/spawn.py:588-593`).
- **`build_command` grows, flag by flag, each gated by the probe** (§2.3) — the per-role permission
  mode, `--agent`/`--agents`, `--effort`, `--tools`/`--disallowedTools`, `--strict-mcp-config`,
  `--max-budget-usd`, `--plugin-dir`. It stays a pure function of the job, so the golden test
  (`tests/test_workers.py:110`) keeps being the specification.
- **Every role rendered into a runtime agent definition at launch** (§2.4) — one JSON file per
  launch under the job's own state, from `roles.load_all()` and the launch table, passed as
  `--agents <file>` with `--agent <the role for the kind>`. `roles.BINDINGS`
  (`asf/roles/roles.py:47-55`) becomes the live binding it was written to be, and `asf-locator`
  loses its `UNBOUND` entry.
- **Per-job caps at launch, and the turn cap where the runtime has no flag** (§2.5) —
  `--max-budget-usd` per kind, derived from the item's own budget (`asf.budget.of`), passed only
  when the probe finds the flag. There is **no turn-limit flag on the installed version** (§1.3
  P6), so the turn cap stays where it already bites — `budget.run_caps` and the stall step
  (`asf/workers/stall.py:215-231`) — and becomes per kind rather than one number for every job.
  The cap result line the card asks for already exists (`asf/budget.py:188`,
  `asf/tokens.py:203`); what is new is that a `close` job's cap is a `close` job's.
- **The lowest effort for mechanical kinds** (§2.6) — `rebase`, `close` and `groom-clerk` launch at
  the lowest effort level the probe reports, for the same reason they already launch on the
  `cheap` model label (`asf/briefs/build.py:79-81`): there is a right answer and no judgement
  reaches it.
- **A generated per-role worker settings file** (§2.7) — `permissions.deny` for the shapes a glob
  can state: the environment files and secret directories, the environment printers, a fetch whose
  argument is key-shaped, `--no-verify` (the deny rule `docs/specs/f-0075.md:76` hands to this
  card), and a push of the trunk. Generated per role from `console_perms`'s shape
  (`asf/console_perms.py:61-84`), merged **over** the operator's own `worker_pool.settings_file`
  so an operator rule is never dropped.
- **Two built-in hooks: the role guard and the redaction refusal** (§2.8) — `asf/hooks.py`'s
  `BUILTIN` table (`asf/hooks.py:59`) gains `roleguard` and `redactout`. The role guard refuses a
  write outside the role's write surface; the redaction hook refuses the calls whose *output* would
  carry a secret. A hook answers allow or refuse and never rewrites — the decision
  `docs/specs/f-0061.md:104` already took.
- **The factory scrubs the transcript it owns** (§2.9) — `redact.scrub` over every path by which a
  session's own text becomes durable: the job log as any reader of it sees it, the `result` text in
  the session record, the correction brief's head, the tick's summary line. This is the half that
  makes the card's fourth acceptance a fact rather than a hope, and it is the "F-0062 may call the
  same scanner" of `docs/specs/f-0075.md:61`.
- **Four procedure skills, shipped inside the package** (§2.10) — `asf/procedures/`: the review
  standard, the coder's pre-push gate, the spec shape and the report shape, as `SKILL.md` files
  with a plugin manifest beside them, package data like `asf/roles/*.md` already is, loaded per
  launch with `--plugin-dir`.
- **The briefs shrink to the card, the row and the skill names** (§2.11) — the common tail
  (`asf/briefs/build.py:97`, 2,727 characters and 46 lines on every single launch), the standing
  rules (`asf/briefs/preamble.py:42`, 573 characters) and each template's procedure prose become
  citations of the skills that now carry them. The preamble's *facts* are not touched — see D11.
- **The measure** (§2.12) — `asf roles launch` prints the table actually in force per kind, with
  the flags the installed binary accepts and the ones it does not; `asf doctor` gains
  `role-launch` and `worker-deny` rows; `asf briefs size` prints the procedure characters per
  kind against the recorded baseline.

### 1.2 Out

- **No change to which role a kind runs under.** `roles.BINDINGS` is data and is correct; this
  card makes it load-bearing, not different. A kind whose role an operator wants changed is a
  change to that table, reviewed like any other.
- **No new role file, and no new key in one.** The nine refusals of `roles.validate` stand, the
  four forbidden words stand, and `MAX_LINES` stands. A role that named its own model would put
  the operator's cost back inside an identity file, which is the thing
  `asf/roles/__init__.py:12-14` refuses.
- **No sub-agent spawning.** `--agents` gives the *session* its identity; it does not make the
  session launch children. One brief, one session, one role — F-0029 D2's shape is unchanged. The
  locator binds because a launch can now restrict tools, not because a session can now fan out.
- **No sandbox, no container, no syscall filter.** Constitution §3 is explicit that a capability
  list is not a boundary (`docs/CONSTITUTION.md:75-77`); this card ships the capability list, the
  hook behind it and the scrub behind *that*, and says plainly in §2.8 which of the three is the
  boundary. Process isolation is not in this epic.
- **No rewriting of a tool result.** The runtime's hook contract, as this factory has built it, is
  allow (0) or refuse (2) — `asf/approvals.py:847-863`, and `docs/specs/f-0061.md:104` decided it
  in as many words. So the "redaction hook" of the card's part 4 is a *refusal* of the calls that
  would produce a secret, plus §2.9's scrub of what the factory itself stores. A refusal before the
  output exists is strictly stronger than a redaction after it; the one thing it is not is a
  rewrite, and this spec does not pretend otherwise.
- **No rule cards, and no `rules/` directory.** F-0061 ships that directory and the card format;
  it has not landed (`ls rules` fails in this tree). Both hooks here are `BUILTIN` entries, which
  is the mechanism `asf/hooks.py:57-59` already documents for a hook that ships with `asf` and has
  no card. If F-0061 lands first, nothing here moves: a `BUILTIN` name shadows a script of the
  same name by design.
- **No new metrics stream.** `metrics.STREAMS` is closed and validated; the launch's own flags go
  on the session record that `spawn` already appends (`asf/workers/spawn.py:726-747`), and the
  refusals go to the `approvals.jsonl` ledger `approvals.append` already writes.
- **The token cap and the wall-clock cap are not re-decided.** `asf.tokens`'s four dimensions and
  `budget.run_minutes` keep their values, their table and their enforcement. Only `run_turns`
  becomes per-kind.
- **`--restricted` is not used for the working roles.** It ignores project and local settings files
  (its own `--help` text), which is where this card's deny rules live for the operator's console
  copy; using it for a coder would silently discard half of §2.7. It is used for the prober alone,
  which needs neither.
- **The operator's `worker_pool.settings_file` is not replaced.** It is merged over, never
  rewritten, never moved, and a product that sets none still gets the deny rules.

## 2. The design

### 2.1 `asf/roles/launch.py` — the launch table

New module beside the roles. It imports `asf.roles.roles` and the stdlib, nothing else, so the
gate, the doctor and the launcher all read one table.

```python
@dataclasses.dataclass(frozen=True)
class Launch:
    """What a role is launched with — everything the role file is forbidden to say (D1)."""
    role: str                 # the role file's stem, e.g. 'asf-reviewer'
    permission_mode: str      # one of PERMISSION_MODES
    effort: str               # one of EFFORTS, '' for the runtime's own default
    tools: tuple = ()         # the built-in tools the session gets; () is every tool
    deny_tools: tuple = ()    # tools removed even when `tools` is empty
    writes: tuple = ()        # the path patterns the role may write; () is 'its worktree'
    connections: tuple = ()   # external tool connections; () is none, and none is the default
    restricted: bool = False  # the runtime's own --restricted (the prober alone, §1.2)

#: The card's part 2 and part 5, as one table. `effort` is a level name, never a model.
TABLE = {
    'asf-reviewer':      Launch('asf-reviewer', 'plan', 'high',
                                deny_tools=WRITE_TOOLS, writes=('{reviews_dir}/**',)),
    'asf-prober':        Launch('asf-prober', 'plan', 'low', tools=READ_TOOLS,
                                writes=('{reports_dir}/**',), restricted=True),
    'asf-coder':         Launch('asf-coder', 'acceptEdits', 'high'),
    'asf-fixer':         Launch('asf-fixer', 'acceptEdits', 'high'),
    'asf-diagnostician': Launch('asf-diagnostician', 'acceptEdits', 'high'),
    'asf-writer':        Launch('asf-writer', 'acceptEdits', 'high',
                                writes=('{specs_dir}/**', '{plans_dir}/**', '<record>/**')),
    'asf-interrogator':  Launch('asf-interrogator', 'acceptEdits', 'high', writes=('<record>/**',)),
    'asf-harvester':     Launch('asf-harvester', 'acceptEdits', 'low'),
    'asf-builder':       Launch('asf-builder', 'acceptEdits', 'high'),
    'asf-locator':       Launch('asf-locator', 'plan', 'low', tools=READ_TOOLS, writes=()),
    'asf-documenter':    Launch('asf-documenter', 'acceptEdits', 'low'),
    'asf-security':      Launch('asf-security', 'plan', 'high', deny_tools=WRITE_TOOLS),
}
```

Three facts about the table:

- **Every role in `roles_dir()` has a row, and no row names a role that is not there.** A test
  holds the two key sets equal (§3, T1), so a new role file cannot ship unlaunchable and a deleted
  one cannot leave a row behind — the failure `UNBOUND` has been papering over.
- **`writes` is resolved against the product's conventions, never spelled as a path.** `{reviews_dir}`,
  `{specs_dir}`, `{plans_dir}` and `{reports_dir}` are `Conventions` fields; `<record>` is the
  product's `backlog_dir`. `tools/check_conventions.sh` generates a forbidden pattern for each of
  those defaults (`tools/check_conventions.sh:5-8`), so writing `docs/reviews` here would fail the
  lint — the placeholder form is the only form that passes, which is the property that keeps the
  table generic.
- **`connections` is `()` for every role**, and `launch_for` refuses a non-empty one until a
  product's config names it (§2.7). "None by default" is the default *and* the value.

`launch_for(kind, product=None)` is the one entry point: `roles.for_kind(kind)` for the role, the
table row, then the product's own `conventions.roles.<role>` override for `effort` and
`permission_mode` only — never for `tools`, `writes` or `connections`, because widening a boundary
is an operator action through the amendable set (`asf/amendable.py:53`), not a product setting.

`effort_for(kind)` is the one place §2.6's mechanical floor is applied, so the rule is read off one
function by the launcher, the table view and the doctor alike.

### 2.2 `asf/workers/capability.py` — what the installed binary accepts

New module. One job: the set of long-option names the installed runtime carries.

```python
#: How long the probe waits for `<binary> --help`. A binary that cannot answer in this is treated
#: as answering nothing — every new flag is skipped and the doctor row is red.
PROBE_TIMEOUT_S = 20

def flags(binary=None, environ=None):
    """The long-option names ``<binary> --help`` prints (``{'agent', 'agents', 'effort', …}``),
    cached by (resolved path, mtime, size). ``set()`` when the binary is absent, fails, or times
    out — never an exception, because a probe that raises stops a wave."""

def supports(name, binary=None):
    """Whether the installed runtime carries ``--<name>``."""

def missing(names, binary=None):
    """The names of ``names`` the installed runtime lacks, in order — the doctor's row (§2.12)."""
```

The parse is deliberately dull: every `--<name>` at the start of an option line, plus each
comma-separated alias on the same line (`--allowedTools, --allowed-tools` yields both). It reads
option *names* only and never their argument syntax or their help text, so a reworded help page
does not change an answer.

The cache key includes the binary's mtime and size, so an upgrade under a running tick is picked up
without a restart; `capability.reset()` clears it for the tests.

`effort_levels(binary)` is the one exception to "names only": the level list is parsed from
`--effort`'s own parenthesised choices, with a built-in fallback, because §2.6 needs to know which
level is the *lowest* the installed version offers rather than assume a name.

### 2.3 `asf/workers/runtime.py` — the command line

`Job` gains the fields the table fills — `effort`, `tools`, `deny_tools`, `agents_file`,
`agent`, `plugin_dirs`, `max_budget_usd`, `strict_mcp`, `restricted` — each defaulting to the
empty value, so every existing caller and every test constructs the same job it does today.

`build_command` stays pure, and every addition is gated:

```python
def build_command(job, binary=DEFAULT_BINARY, caps=None):
    """The headless command line — a pure function of the job and of the flags the installed
    binary accepts (``caps``: a set of long-option names, default ``capability.flags(binary)``).
    A flag the binary does not carry is left out, never guessed at and never passed (D2, D3)."""
    have = caps if caps is not None else capability.flags(binary)
    cmd = [binary, '-p', '--permission-mode', job.permission_mode]
    if job.resume:
        cmd += ['--resume', job.resume]
    for d in job.add_dirs:
        cmd += ['--add-dir', d]
    if job.model:
        cmd += ['--model', job.model]
    if job.effort and 'effort' in have:
        cmd += ['--effort', job.effort]
    if job.restricted and 'restricted' in have:
        cmd += ['--restricted']
    if job.tools and 'tools' in have:
        cmd += ['--tools', ','.join(job.tools)]
    if job.deny_tools and 'disallowedTools' in have:
        cmd += ['--disallowedTools', *job.deny_tools]
    if job.agents_file and 'agents' in have:
        cmd += ['--agents', job.agents_file]
        if job.agent and 'agent' in have:
            cmd += ['--agent', job.agent]
    for d in job.plugin_dirs:
        if 'plugin-dir' in have:
            cmd += ['--plugin-dir', d]
    if job.strict_mcp and 'strict-mcp-config' in have:
        cmd += ['--strict-mcp-config']
    if job.max_budget_usd and 'max-budget-usd' in have:
        cmd += ['--max-budget-usd', f'{job.max_budget_usd:.2f}']
    if job.settings_file:
        cmd += ['--settings', job.settings_file]
    cmd += ['--output-format', 'stream-json', '--verbose']
    return cmd
```

The order is the order above and is asserted: the golden test is the specification of this command
line, and a reordering that changes nothing functionally still changes the test, which is how a
launch-path change stays visible in a diff.

`spawn` fills the new fields from one call:

```python
launch = roles_launch.launch_for(row.kind, product)
agents_file = roles_launch.write_agents_file(product, row.job, launch)
job = runtime_mod.Job(..., permission_mode=launch.permission_mode,
                      effort=roles_launch.effort_for(row.kind), tools=launch.tools,
                      deny_tools=launch.deny_tools, agents_file=agents_file,
                      agent=launch.role, plugin_dirs=[procedures.plugin_dir()],
                      strict_mcp=True, restricted=launch.restricted,
                      max_budget_usd=budget_mod.of(conv, item).usd,
                      settings_file=worker_settings.path(product, launch, wp), ...)
```

`worker_pool.permission_mode`, when an operator sets it, still wins — it is the operator's
override and predates this card — but `asf doctor` reports it as one, naming the per-role modes it
is flattening, because a pool-wide `bypassPermissions` silently undoes most of §2.1.

The session record `spawn` already appends gains four fields — `role`, `effort`, `permission_mode`
and `flags_skipped` — so what a session was launched with is answerable from the ledger a week
later, which is the question no reading can answer today.

### 2.4 The agent definition, written per launch

`roles_launch.write_agents_file(product, job, launch)` renders one JSON object into
`<state>/<product>/agents/<job>.json` and returns its path:

```json
{
  "asf-reviewer": {
    "description": "one finding per acceptance criterion, each with the evidence for it",
    "prompt": "<the role's own text: Identity, Doctrine, Output, Economy, Boundaries>",
    "tools": ["Read", "Grep", "Glob", "Bash", "Write"]
  }

```

`description` is the role's `purpose` verbatim; `prompt` is `roles.block(role, cap)`
(`asf/roles/roles.py:282-301`) — already written to render a role as brief text, already
truncating by whole sections with a line saying it truncated, and now used for the first time.
`tools` is the launch row's set, resolved after `deny_tools` is removed.

Two properties, both tested:

- **The file is a function of the role file and the table.** Same role text plus same row means
  the same bytes, so a diff in the agents file is a diff in one of the two — never in the writer.
- **It is written before the launch and removed with the job's state.** A session's own agents file
  is a record of what it was allowed; the reaper takes it with the rest of the job's state, the way
  it already takes the brief and the setup log.

`roles.UNBOUND` loses its `asf-locator` entry (D15). The other three entries keep their reasons —
those are about phases, not launches — and a test asserts that no `UNBOUND` reason mentions a
launch path any more, so the next role that ships unbound has to give a real reason.

### 2.5 Per-job caps at launch

Two caps, two places, for the reason P6 gives.

**The dollar cap is a flag.** `--max-budget-usd` takes the item's own budget
(`budget.of(conv, item).usd`) — the number the card, the product default and F-0092 already agree
on. A `Budget` with `usd=None` (a measure the product turned off) passes no flag. The item's
budget is what the *item* may spend across its sessions, so a single run capped at it cannot
overspend the item in one go, which is the failure the flag is for; the multi-session arithmetic
stays where it is, in `budget.spent` and the feeder's hold.

**The turn cap is a table.** `budget.run_caps` grows a kind:

```python
#: The turn cap per brief kind: judgement gets room, clerical work does not. A kind with no entry
#: takes `default`, which is `conventions.budget.run_turns` (P9) — so a product that set that
#: number keeps it, and a product that set nothing gets a cap that fits the job.
RUN_TURNS = {'default': 600, 'close': 60, 'rebase': 60, 'groom-clerk': 120, 'review': 300,
             'correct': 300, 'fix-bug': 400, 'coder': 600, 'spec': 600, 'plan': 600}

def run_caps(conv, kind=None):
    """``(minutes, turns)`` for a run of ``kind``. ``None`` on either side is off."""
```

`conventions.budget.run_turns` stays the `default` entry, so an operator who set 900 gets 900 for
the kinds this table does not narrow, and `conventions.budget.run_turns_by_kind` (a map, optional)
overrides any row. `stall.cap` passes the kind it already computed one line earlier
(`asf/workers/stall.py:214`) and is otherwise untouched: the stop, the cap result line, the
`capped` mark on the registry row and the `CAP` console line are exactly what they are today.
That is the card's third acceptance, and P8 says it already works — what this card fixes is that
a `close` job reached 600 turns before anyone noticed.

### 2.7 The worker settings file, per role

`asf/workers/worker_settings.py`, new, built on `console_perms`'s shape (P17):

```python
#: The deny rules every worker session gets, whatever its role — the card's part 4. Each is a
#: shape a glob can state; the shapes it cannot are §2.8's hook.
FIXED_DENY = (
    'Read(**/.env)', 'Read(**/.env.*)', 'Read(**/*.pem)', 'Read(**/*.key)',
    'Read(**/.aws/**)', 'Read(**/.ssh/**)', 'Read(**/.gnupg/**)', 'Read(**/.netrc)',
    'Bash(env)', 'Bash(env:*)', 'Bash(printenv:*)', 'Bash(set)', 'Bash(export -p)',
    'Bash(cat .env*)', 'Bash(git push --no-verify:*)', 'Bash(git commit --no-verify:*)',
    'Bash(git push -f:*)', 'Bash(git push --force:*)',
    'WebFetch', 'WebSearch',
)

def deny_rules(product, launch):
    """FIXED_DENY, plus a push of the product's own trunk, plus the write tools a read-only role
    does not get, plus one Read rule per secret directory the product's config names."""

def settings(product, launch, operator_path=None):
    """The role's settings object: the operator's own file (worker_pool.settings_file) read first,
    then this role's allow and deny rules merged over it — every unrelated key kept (D6)."""

def path(product, launch, wp):
    """``<state>/<product>/worker-settings/<role>.json``, written when it differs from what is
    there. Returns the path build_command passes as --settings."""
```

Four notes:

- **The environment printers are denied even though the environment is already narrow.**
  `hermetic.build` in worker mode strips everything but the allow-list — and then `build_env` puts
  the live credentials back (P10), because the session must push. So `printenv` in a session prints
  a usable token today. This is the single highest-value rule in the list.
- **`WebFetch` and `WebSearch` are denied for every role**, which is R-0066's rule
  (`docs/CONSTITUTION.md:88`) in the one place that can enforce it. A product that needs one names
  it in `conventions.roles.<role>.tools`, which is an amendable-set change.
- **A rule the operator already has is never duplicated and never dropped.** `merge` is
  `console_perms.merge`'s discipline: append what is missing, keep order, touch no other key. Two
  runs write one file.
- **`--no-verify` is denied here**, closing the handoff `docs/specs/f-0075.md:76` left open: "the
  deny rule that makes it impossible for a session is F-0062's".

`asf worker-permissions offer --product p` prints every rule in full, per role, before anything is
written — the same discipline `console_perms.offer_text` established, for the same reason: a
confirmation of a list has to be of the actual list.

### 2.8 The two hooks

Both are `BUILTIN` entries (P14), so both are installed into every worker account's settings by
the `hooks install` that already runs (P15), and neither needs `rules/` to exist.

```python
BUILTIN = {'approvals': ('PreToolUse',),
           'roleguard': ('PreToolUse',),
           'redactout': ('PreToolUse',)}
```

**`roleguard` — the role's write surface.** `PreToolUse`, every tool. Resolves the job's kind from
the session registry (the row `spawn` wrote carries `kind` and now `role` too), then the launch row,
then refuses a `Write`/`Edit`/`MultiEdit`/`NotebookEdit` whose `file_path` falls outside
`launch.writes` resolved against the product's conventions. An empty `writes` means the role's own
worktree and nothing above it. The refusal names the surface:

```
REFUSED writing asf/hooks.py — a reviewer writes its review and nothing else (asf-reviewer)
  this role's write surface is docs/reviews/**. A reviewer that edits the code it is judging has
  reviewed its own work (B-0009's shape: a step trusted rather than verified).
  instead: put the fix in the review's C list, file:line and the exact change.
  This is not a question for a person: do not print NEEDS OPERATOR for it.
```

**`redactout` — the calls whose output would carry a secret.** `PreToolUse`, `Bash` and `WebFetch`.
Refuses what a glob cannot state (D7): a command whose *argument* is key-shaped — a `curl`
carrying an `Authorization:` header, a `?key=`/`?token=` query, an inline `sk-`/`gh`-shaped literal
— and any command whose text matches one of `redact`'s own secret patterns
(`asf/redact.py:69-79`), because a command that *contains* a secret prints it into the transcript
merely by being echoed. The matcher is `redact.scan_text` over the command string, so there is one
set of secret shapes in this factory and not two; a finding never carries the matched text
(`asf/redact.py:6-8`), so the refusal line can be printed into a transcript safely.

Both hooks follow `approvals.run_hook`'s four rules exactly (`asf/approvals.py:846-862`):
`ASF_JOB` unset returns 0; a clean call returns 0 silently; a refusal returns 2 with the reason on
stderr and one `refused-role` / `refused-secret-output` record appended to the product's
`approvals.jsonl` with no `hold` key; any exception returns 2 naming the hook and not the rule.

### 2.9 The scrub of what the factory stores

The other half of the card's part 4, and the half that is testable end to end.

```python
def scrubbed_lines(log_path, repo=None):
    """Every line of a job log with every protected name and secret replaced by SCRUB_TOKEN —
    the one reader every view, every report and `asf redact --log` goes through (D9)."""
```

Four call sites, all of them places a session's own text becomes durable or public today:

| where | today | after |
| --- | --- | --- |
| the session record's `result` text | `runtime.Runtime.run` puts `rec['result']` straight into `Result.text` (`asf/workers/runtime.py:540-542`) | through `redact.scrub` before it reaches the record or a console line |
| the correction brief | `stall.correct_once` pastes the dead session's `error_text` into a new brief (`asf/workers/stall.py:238-247`) | scrubbed first: a token in a failure message was about to be written into a file and handed to another session |
| the tick summary and every view that prints a report line | the text as the session wrote it | `scrubbed_lines`'s output |
| `asf redact --log <job>` | does not exist | prints the job's transcript scrubbed, for an operator who has to read one |

The log file itself is left as the child wrote it (D9): it is the evidence, it lives under the
operator's own state directory, and rewriting evidence to make a check pass is the shape this
factory refuses everywhere else. What changes is that nothing copies out of it unscrubbed.

A doctor row (`worker-redaction`) is red when a live job's log carries a match: the operator learns
a session printed a credential while the session is still running, which is when it can still be
rotated.

## 4. Records

**Files, in this repository**

- `asf/roles/launch.py` — the launch table *is* the record of what each role is launched with. A
  role's access is not a setting an operator has to remember; it is a reviewable row.
- `asf/procedures/skills/*/SKILL.md` — the four procedures, each in one place. A procedure repeated
  in a brief is a procedure with no owner; these have one.
- `docs/design/brief-baseline.json` — the recorded procedure and fact characters per kind, as of
  this Feature's baseline (P23). The fifth acceptance compares against this file, not a memory.

**Files, per product**

- `<state>/<product>/agents/<job>.json` — the agent definition one launch was handed: the role's
  text, its description and its tool set (§2.4). Removed with the job's state.
- `<state>/<product>/worker-settings/<role>.json` — the role's merged settings, allow and deny
  (§2.7). Rewritten only when it differs; an operator rule in it survives every upgrade.

**Files, per worker account**

- `<account settings>` gains two `PreToolUse` entries, `roleguard` and `redactout`, beside the
  `approvals` entry already there (P15). Merged in place; no other key is touched.

**Rows, per product**

- `<state>/<product>/sessions.jsonl` — the launch line gains `role`, `effort`, `permission_mode`
  and `flags_skipped`. What a session was allowed is answerable from the ledger afterwards, which
  is the question no reading can answer today.
- `<state>/<product>/approvals.jsonl` — the existing ledger, two new `event` values, neither
  carrying a `hold` key, so nothing parks and nothing is relaunched on one:
  - `refused-role` — `{event, role, item, job, tool, detail, ts}`, a write outside the role's
    surface;
  - `refused-secret-output` — `{event, rule, job, tool, ts}`, a call whose output would have carried
    a secret. **No `detail`**: the detail is the secret.
- The `capped` mark `stall.cap` already writes now carries the kind's own limit, so a capped run
  records the cap it actually hit.

**Rows, in the record**

- None written by this Feature.

**Events the console sees**

- `asf roles launch` — the table in force, and the flags the installed runtime lacks (§2.12).
- `asf briefs size` — the procedure and fact characters per kind against the baseline.
- `asf worker-permissions offer` — every deny rule, per role, in full, before anything is written.
- `asf redact --log <job>` — a job's transcript, scrubbed.
- `asf doctor` — the `role-launch`, `worker-deny` and `worker-redaction` rows.
- `asf hooks install` — its summary line now counts `roleguard` and `redactout` per account.
