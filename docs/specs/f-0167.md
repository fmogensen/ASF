# F-0167 — `asf status` stops shelling out ten times per account

`asf.workers.quota.CommandQuotaSource.read` runs the operator's `quota_command` as a subprocess,
with a 60-second timeout, every single time it is asked. `asf.workers.pool.Pool.usage` memoises the
answer — but only **per Pool instance**, and one `asf status` builds a new Pool, or a new bare
source, at every place it needs the same fact:

| the cell | what it calls | reads |
| --- | --- | --- |
| Capacity | `capacity.resolve` → `fair_share` → `usable_slots` (a fresh `Pool`) | N |
| Ready to launch | `step_wave.capacity` (`resolve`) + `plan_inputs` → `bandwidth` (`resolve` + `quota_stopped`) | 3N |
| Features in build | the same two calls again | 3N |
| Decisions | `plan_inputs` → `bandwidth` again | 2N |
| Quota 5h/7d | `quota_cell`'s own `source_from_config` | N |

Measured in this checkout, not reasoned: **ten subprocesses per account per `asf status`** (P1). On
2026-09-27 the operator's adapter was taking 10 s a call because its own usage cache had stopped
refreshing, and `asf status` hung past 150 s for every product — 10 reads × 2 accounts × 10 s is
200 s, and the faulthandler stack the card carries points at exactly that chain. Nothing was wrong
with asf's logic. It asked one question twenty times and waited 60 s for each answer.

Three things are missing, and they are separable:

1. **The reading is not shared.** Not across the six call sites in one process, and not across the
   processes — `status`, `next`, the tick, the capacity table — that ask within seconds of each other.
2. **The per-call wait is unbounded in practice.** 60 s is longer than any command that is working
   needs and shorter than no command at all; a wedged adapter costs the full 60 s, N times over,
   and there is no ceiling on what one `asf` command will spend in total.
3. **An unreadable account has no memory.** A timeout returns `None`, `band` reads `None` as `stop`
   — "unknown ≠ free" — and the row prints `?%/?% stop`. The reading from 40 seconds ago is
   thrown away, though F-0082 already defines what an un-refreshable reading means: it is **stale**,
   and a stale reading has a band, a hold and a status label of its own.

This card fixes all three in one place — the source — so that every reader inherits it and no reader
has to be taught anything. The third is the interesting one: the cache does not merely make the fast
path faster, it gives the slow path something true to say.

### In

- **`quota.CachedQuotaSource`** — one decorator around the configured source, returned by
  `source_from_config`, answering in four steps: this process's memo; the shared table when its
  entry is younger than the TTL; the inner source, charged against this process's read budget;
  and, when the budget is spent or the inner source answered `None`, the shared table's entry
  **however old it is** — which is a stale reading, not an unknown (D3).
- **The shared table**: `~/.ASF/state/quota-cache.json`, one entry per account
  (`read_at` + the reading), written after every successful read, read by every process.
  `cache_ttl_s`, default 60.
- **A `polled_at` the cache stamps** when the source printed none, so an entry served from the
  table carries when the command actually ran and F-0082's stale machinery can judge it (D4).
- **A per-call cap and a per-process budget**: `read_timeout_s` (default **15**, replacing the
  source's 60) and `read_budget_s` (default **30**). The budget is tested before each read, never
  during one, so one `asf` command spends at most `read_budget_s + read_timeout_s` in quota
  subprocesses — 45 s against today's unbounded 10N × 60 (D5).
- **`quota.forget()` and `quota.expire()`** — drop this process's memo and budget; and, on top of
  that, bypass the shared table's TTL here so the next read goes to the vendor — writing and
  deleting nothing, so the entries stay as the fallback (D6, D11). Two names because they are two
  different acts.
- **Two refreshers**: the tick's wave calls `expire()` at the start of its pass, after the lock
  reclaim and before it resolves capacity (P13), and `asf workers quota` calls it before building
  its Pool (P14). The reader that *launches* or is *asked* refreshes; the reader that renders does
  not (D7).
- **`status`'s Quota row says why it is not fresh**: a new `quota_budget_prefix(cfg)` beside
  `quota_lock_prefix` (P10), and per account the `stale since HH:MM` F-0082 already prints.
- **The three config keys documented** in `docs/config.example.yaml` and
  `docs/guide/product-config.md`, and the changed meaning of an unstamped reading with them.
- **`quota.forget()` in `HomeCase.setUp` and `ViewsTestCase.setUp`** (D12), so a process-global memo
  does not leak one test method's mocked reading into the next method that reuses its account name
  (P26).

### Out

- **Changing `band`, `stale_since`, `stale_stop`, `guards_from_config` or what any of them decide.**
  The whole point is that F-0082 already defined what an un-refreshable reading means; this card
  produces one where it used to produce `None`. `stale_after_min` keeps its value and its reader.
- **Collapsing the six call sites.** `usable_slots`, `quota_stopped`, `bandwidth` and `resolve`
  keep their shapes and keep constructing Pools; `Pool.usage`'s per-instance memo stays exactly as
  it is (P4). Threading one reading through the resolver would touch every signature in
  `asf/capacity.py` and every caller of them, to buy what one shared source buys — D2.
- **`bandwidth`'s habit of reloading the config itself** (P2). It is a latent bug — the caller's
  `cfg` is ignored — but it changes no behaviour once the reading is shared, and fixing it moves
  which accounts `quota_stopped` counts in a fixture. Named here so the next reader does not
  re-discover it; not touched.
- **Caching a failure on disk.** A `None` read never overwrites a good entry and never creates one.
  The table holds last-known-good readings only; a failure is memoised **in process** (so a broken
  command is run once per command, not ten times) and forgotten when the process ends — D8.
- **Any retention sweep of the table.** An entry is kept until the account leaves
  `worker_pool.accounts` (dropped on the next write) — a seven-day window's stale stop has to
  outlive seven days of failed reads to mean anything (P8).
- **A lock around the table.** Two processes racing a write is a lost cache entry, which costs one
  re-read. The temp file carries the writer's pid so they cannot corrupt each other's — D9.
- **`observe.source_from_config`** (the *session* source, `asf/workers/observe.py:154`). Same name,
  different question, its own cost; not this card.
- **`asf ci queue`.** The card names it among the sharers; it reads no quota (P16).
- **`capability._CACHE`, `ci_runs_in_flight`'s `gh` calls, `runner_ci_free`.** Other subprocesses in
  the same `status` render, each with its own timeout and its own card if it needs one.
- **Recording anything about a cache hit in `quota-samples.jsonl`.** The TTL is well under the wave
  clock and a duplicate sample is skipped by `MIN_DELTA` anyway (P15).

### The choices

| # | Chosen | Against | Why |
| --- | --- | --- | --- |
| D1 | One `CachedQuotaSource` decorator, returned by `source_from_config`, holding both halves — the process memo and the shared table | memoise higher up (a module-level `usage(cfg, account)` function every caller switches to); or lift `Pool.usage`'s memo to a class attribute | `source_from_config` is already the single factory every production reader goes through (P6), so wrapping it is the one edit that reaches all six call sites and every future one. It also keeps the cache **out of** the paths tests inject — `FakeQuotaSource`, `NoQuotaSource`, and a `source_from_config` that is itself mocked (`tests/test_capacity.py`) all stay exactly as fast and as predictable as they are. A class attribute on `Pool` would miss `usable_slots`' and `quota_cell`'s bare sources, and a new module function would be a second way to ask the same question |
| D2 | The readers are not restructured: `resolve`, `fair_share`, `usable_slots`, `quota_stopped` and `bandwidth` keep asking as often as they like | thread one `Resolved`-like quota snapshot through `asf/capacity.py` so each fact is computed once per command | asking the same question six times is only a defect because the answer is expensive; making the answer cheap fixes the defect at its cause and leaves six call sites, four signatures and their twenty-odd callers alone. It is also the only version that helps `asf next`, the tick and the capacity table without editing any of them — and the only version where a *second* process benefits |
| D3 | A read that cannot be refreshed falls back to the table's last good entry, **however old**, and that entry is a stale reading | keep returning `None` (today's behaviour: `stop`, `?%/?%`); or serve the old entry silently as if it were current | F-0082 already answers "what does an un-refreshable reading mean" with three defined behaviours — a stale reading under its stop does not band, one at or over its stop holds to that window's reset, and the row says `stale since HH:MM` (P8). Returning `None` throws away a 40-second-old fact to reach a verdict of `stop` that is *less* informed, and `?%/?% stop` is what the operator saw during the incident. Serving it silently would be the opposite error: a reading the vendor has not confirmed for an hour must not band a launch |
| D4 | The cache stamps `polled_at` at read time **only when the source printed none**; the source's own `polled_at` always wins | stamp unconditionally; or add a second staleness rule keyed on `read_at` | staleness is about when the *vendor* was asked, which only the source knows — so its own stamp is authoritative wherever it prints one. Where it does not, the moment we ran the command is the best available answer, and it is honest: what changes is that an unstamped reading can now go stale (P9), which today it never can. For a working adapter nothing moves — a fresh read is zero minutes old against a 30-minute limit. A second rule on `read_at` would mean two definitions of stale and two labels to render |
| D5 | The budget is checked **before** each read; the guarantee is `read_budget_s + read_timeout_s` (45 s), stated as such | a hard wall-clock budget that kills a read in flight; or no budget at all, just the 15 s cap | killing a subprocess mid-read buys a tighter number and costs a second timeout mechanism, a partially-read pipe and an answer the source never gave. The cap that matters is per-call, and the budget's real job is bounding *how many* slow calls one command makes: with the memo, N accounts each timing out once is `min(N × 15, 45)`. Against today's 10N × 60 — 1200 s for two accounts — the difference between 45 and a notional 30 is not worth a kill path |
| D6 | Two functions: `forget()` (this process's memo and budget) and `expire()` (those, plus this process bypassing the table's TTL — D11) | one `reset()`; or a `max_age_s` argument on `read` | they are asked for by different callers for different reasons. A test between two mocked readings wants `forget()`; the wave and `asf workers quota` want `expire()`. And `read(account)` must keep its one-argument shape — every existing mock is `lambda self, a` (P18, P19), and a keyword the mocks do not accept would break eleven test sites to express something two call sites need |
| D7 | The wave and `asf workers quota` expire the cache; `status`, `next`, the capacity table and every other tick step are served it | expire on every tick step; or never expire, and let the TTL do it | the line is *what the reader does with the answer*. The wave spends money on it and the lock reclaim immediately above it exists to make it fresh (P13); `asf workers quota` is the operator asking what is true right now (P14). A view rendering a ≤60 s-old reading is rendering the same number. Expiring per tick step would put N subprocesses back into every step of every tick — the cost this card is removing |
| D8 | A failed read is memoised in process, never written to the table | write it (as `capability._CACHE` deliberately caches a failed probe); or do not memoise it at all | not memoising it is the bug all over again: a wedged adapter would be run ten times per `status`, which is precisely the 200 s the card measured. Writing it would let one process's transient failure delete another process's good reading and turn a 5-minute outage into a machine-wide `?%/?% stop` — the table's whole value is being the thing that still has an answer. `capability` caches its failure because a missing binary stays missing; a quota command fails and recovers |
| D9 | The temp file is `<path>.<pid>.tmp`, and a lost race costs one re-read | a lock file; `headroom.record_limit`'s fixed `.tmp` name | `record_limit` writes a *stop* — losing one would let a launch onto an exhausted account, and it still uses a fixed temp name, so the tree's precedent is already loose here. This file is a cache: the worst a lost write costs is the next reader running the command. Per-pid temp names remove the only real hazard (two writers interleaving into one temp file) for the length of one f-string |
| D10 | `read_timeout_s` 15, `read_budget_s` 30, `cache_ttl_s` 60, all in `quota_guards`, all read by a new `reading_from_config` in `asf/workers/quota.py` | fold them into `guards_from_config`; put them under `worker_pool` beside `quota_command` | `guards_from_config`'s result is passed around as `guards` by nine call sites that ask it exactly one kind of question — what a percentage means. Three keys about how a reading is *taken* have no meaning to a band, and `cuxlock.reclaim_enabled` is the shipped precedent for a `quota_guards` key with its own reader (P12). `quota_guards` is the right block because the operator already tunes quota behaviour there, and the card's numbers are guards |
| D11 | `expire()` makes the calling process **bypass the table's TTL** for its next read of each account, and neither writes nor deletes anything: a forced refresh that fails still falls back to the last reading | delete the file, which is what "expire" first suggests; or write a "due" marker into the table | deleting it contradicts D3 in the one place the fallback matters most. A wedged adapter plus a wave every 10 minutes would otherwise *erase* the last good reading on each pass: the wave reads `None` → `stop`, and — worse — the `asf status` that runs a second later has nothing left to be stale about and prints `?%/?% stop`, the exact symptom this card exists to remove. A "due" marker in the file would be the same erasure one indirection later, and would force *every other* process to re-read because one wave wanted a fresh number. A process-local bypass keeps both halves: the wave and `asf workers quota` always go to the vendor (D7), every other reader keeps its TTL, and what the forced reader falls back to when the vendor will not answer is still a reading F-0082 can judge. The launch path does not become reckless by it — a stale reading at or over its stop still holds `STOP` to the window's reset (`stale_stop`), the session-limit stop still applies, and an account with no entry at all is still `None` → `stop` (P7) |
| D12 | `HomeCase.setUp` (`tests/test_quota_headroom.py:173-178`) and `ViewsTestCase.setUp` (`tests/test_views.py:28-48`) each gain one line, `quota.forget()`, placed with the rest of their per-test reset | leave it to each test method to call `forget()` itself, audited site by site; or scope `_MEMO` to the `CachedQuotaSource` instance instead of the module | `forget()` already exists to answer exactly this — D6's own words are "a test between two mocked readings" — and both fixtures already reset every other piece of per-test state (`env.ASF_HOME`, the temp dir) before a method runs, which is the same job (P17). One line in each closes P26 for every quota test that already exists and every one written after, with nothing to audit method by method and nothing for a future test author to remember. Instance-scoping would defeat D1 — "the cache is out of the paths tests inject" stops being true the moment what a test sees depends on whether it built its own `CachedQuotaSource` or reused one `source_from_config` handed it — and it does nothing for `StatusViewTests`, which never holds the source itself (P17: it must never be subclassed, so there is no instance to scope to before the row is rendered) |

## The design

### `asf/workers/quota.py` — the cache, the budget, and the two ways to drop them

The module docstring gains a paragraph after **A stale reading**:

> **One reading, shared.** A configured source is wrapped in :class:`CachedQuotaSource`: an account
> is read at most once per process, and at most once per ``quota_guards.cache_ttl_s`` (default
> :data:`CACHE_TTL_S`) per machine — the readings sit in ``~/.ASF/state/quota-cache.json``, so
> ``asf status``, ``asf next`` and a tick share them. One read waits at most
> ``quota_guards.read_timeout_s`` (default :data:`READ_TIMEOUT_S`), and one command spends at most
> ``quota_guards.read_budget_s`` (default :data:`READ_BUDGET_S`) on quota subprocesses before it
> stops making them. A read that cannot be refreshed — the budget is spent, or the command failed —
> answers with the table's last reading instead of nothing, and that reading is *stale* in the sense
> above: it does not band a launch below its stop, it holds a stop above it, and ``asf status`` says
> ``stale since HH:MM``. The wave (which launches) and ``asf workers quota`` (which is asked)
> :func:`expire` first, so they read the vendor rather than the table; a view is served it.

```python
CACHE_TTL_S = 60        #: seconds an entry in the shared table answers for (``cache_ttl_s``)
READ_TIMEOUT_S = 15     #: the longest one ``quota_command`` call may take (``read_timeout_s``)
READ_BUDGET_S = 30      #: the seconds of quota subprocesses one process may spend (``read_budget_s``)


def reading_from_config(cfg):
    """``{'cache_ttl_s': .., 'read_timeout_s': .., 'read_budget_s': ..}`` — how a reading is
    *taken*, from the same ``quota_guards`` block :func:`guards_from_config` reads what a reading
    *means* from (D10). A key that is not a number keeps its default."""


def cache_path():
    """``~/.ASF/state/quota-cache.json`` — one table for the machine, as the accounts are."""


def read_cache():
    """``{account: {'read_at': iso, 'usage': {..}}}``, ``{}`` for an absent or unparsable file."""


def write_cache(account, usage, keep=None, now=None):
    """Record ``usage`` for ``account`` as read now, and drop every entry whose account is not in
    ``keep`` (the configured accounts). Written to ``<path>.<pid>.tmp`` then ``os.replace``d; a
    write that fails only loses the entry (D9)."""


def forget():
    """Drop this process's memo and reset its read budget. What a long-lived reader, or a test
    between two readings, wants: the shared table is untouched."""


def expire():
    """:func:`forget`, and make **this process** bypass the table's TTL: step 2 of :meth:`read` is
    skipped until each account has been read from the source once here, so the answer comes from
    the vendor and not from an entry another process left. Nothing is written and nothing is
    deleted — the entries stay, and a forced read that fails still falls back to the last one at
    step 4 (D3, D11). The wave calls it before it resolves capacity, ``asf workers quota`` before
    it builds its Pool (D7)."""
```

`CachedQuotaSource` holds the per-process state in the module (not on the instance: one `asf status`
builds six sources and they must share), which is why `forget` is a module function — and why
`HomeCase.setUp` and `ViewsTestCase.setUp` each gain a `quota.forget()` call (D12): without it, a
later test method in the same class reads an earlier method's memo for the same account instead of
its own mock (P26).

```python
_MEMO = {}          # account name -> usage | None, this process only (a failure is memoised: D8)
_SPENT = [0.0]      # seconds of quota subprocesses this process has run


class CachedQuotaSource(QuotaSource):
    """One reading per account per process, and one per ``ttl_s`` per machine.

    :meth:`read` answers with the first of these that has an answer:

    1. this process's memo — including a memoised failure, so a wedged command is run once per
       command and not once per caller;
    2. the shared table, when the entry's ``read_at`` is younger than ``ttl_s``;
    3. the inner source, if this process's read budget has anything left — the reading is memoised
       and written to the table, with ``polled_at`` stamped at read time when the source printed
       none (D4);
    4. the shared table's entry *however old it is*. A reading the vendor has not confirmed is
       stale, not unknown: it bands and holds by :func:`band`'s stale rules and ``asf status``
       says ``stale since HH:MM`` (D3).

    With nothing at (4) either, ``None`` — the account is unreadable, exactly as today (P7).
    """

    def __init__(self, inner, ttl_s=CACHE_TTL_S, budget_s=READ_BUDGET_S, keep=None):
        ...

    def read(self, account):
        ...
```

and the factory hands it the configured caps:

```python
def source_from_config(cfg):
    """The configured source, wrapped so a reading is taken once and shared (F-0167).
    ``NoQuotaSource`` is never wrapped: it runs no command, so there is nothing to cache."""
    cmd = ((cfg or {}).get('worker_pool') or {}).get('quota_command')
    if not cmd:
        return NoQuotaSource()
    r = reading_from_config(cfg)
    from asf.workers import pool as pool_mod
    return CachedQuotaSource(CommandQuotaSource(cmd, timeout=r['read_timeout_s']),
                             ttl_s=r['cache_ttl_s'], budget_s=r['read_budget_s'],
                             keep={a.name for a in pool_mod.accounts_from_config(cfg)})
```

`CommandQuotaSource`'s default timeout moves from 60 to `READ_TIMEOUT_S`, and its docstring names
who bounds it now. Its body does not change — `read(account)` keeps its one-argument shape (D6).

One more function, for the status row:

```python
def reads():
    """What this process has spent on quota, for a view to say so: ``(subprocesses, spent_s,
    budget_s, unread)`` — ``unread`` counting the accounts a spent budget left unread with nothing
    in the table to fall back on."""
```

### `asf/views/status.py` — the Quota row says why it is not fresh

`quota_cell` is unchanged per account: it calls `source.read(a)` as it does today, and by the time
the row is rendered the memo is already warm from the Capacity cell, so the cell costs nothing. What
is added is a second prefix, beside the one that is already there (P10):

```python
    return quota_lock_prefix(cfg) + quota_budget_prefix(cfg) + ', '.join(parts)


def quota_budget_prefix(cfg):
    """``quota read budget spent (30s, 2 read) — the rest is the last reading; `` when this process
    stopped making quota calls before it had asked every account (F-0167). Empty when the budget
    was not reached, which is every ordinary render."""
```

The per-account text does not move: an account served from an expired entry already reads
`w1 38%/89% stale since 14:02` (P8), and an account with nothing cached still reads `w1 ?%/?% stop`.
The row's own docstring bullet gains the sentence that a reading may be served from the shared table
and is then stale, and that the prefix names a spent budget.

### `asf/tick/step_wave.py` — the wave reads fresh, once

```python
    try:  # a wedged account-manager usage lock, reclaimed before the pool reads quota (opt-in)
        from asf.workers import cuxlock
        cuxlock.tick_pass(env.load_config(), out, ctx.event)
    except Exception as e:  # noqa: BLE001 — never a blocker for the wave
        out(f'quota    cux lock reclaim failed — {e}')
    # F-0167: this pass launches, so it reads the vendor and not a table another process filled
    # before the reclaim above — once per account, shared by everything else in this tick
    from asf.workers import quota as quota_mod
    quota_mod.expire()
```

immediately before `items = index_reader.load(...)` and `r = capacity_mod.resolve(product)` — with
the import local to the function, as `cuxlock`'s is directly above it, because `asf/tick/step_wave.py`
imports no quota module today. One call: the bypass sends this pass's first read of each account to
the vendor, that read refreshes the entry, and the memo serves `resolve`, `plan_inputs` →
`bandwidth` and the `Pool` the launch places on —
so the wave's cost goes from "however many times it asks" to one subprocess per account. A vendor
that will not answer this pass leaves the wave on the last reading, which `band` judges by F-0082's
stale rules rather than by `None` (D11).

### `asf/workers/__init__.py` — `asf workers quota` refreshes

def cmd_quota(args):

## Records

- **A new machine-wide file: `~/.ASF/state/quota-cache.json`**, beside `quota-limits.json` and
  `quota-samples.jsonl` (P11). One object, one entry per configured account:
  `{"lane-1": {"read_at": "2026-09-28T12:03:11Z", "usage": {"five_h_pct": 38, "seven_d_pct": 89,
  "polled_at": "2026-09-28T12:03:11Z"}}}`. Only a **successful** reading is written; an entry is
  removed when its account leaves `worker_pool.accounts`. Deleting the file by hand is always safe
  — it costs one read, and costs the fallback only while the command is also failing.
- **`polled_at` is now written by asf** when the source did not print one, and it means "when this
  machine ran the command". A source's own `polled_at` is copied through untouched (D4).
- **Nothing is recorded per process.** The memo, the read budget and the `reads()` counters die with
  the command; no run row, no session field, no metric, no event, no card.
- **`quota-samples.jsonl` is unchanged**, in shape and in cadence: the wave calls `expire()` before
  it reads, so its samples are vendor readings as they are today (P15, D7). The one case that
  changes is a wave whose command failed — it now samples the last reading rather than nothing, and
  a repeated sample is skipped by `MIN_DELTA` (P15).
- **Two new pieces of text, both in `asf status`'s Quota row.** The prefix `quota read budget spent
  (30s, 2 read) — the rest is the last reading; ` when a render stopped asking, and — much more
  often — per account the `stale since HH:MM` F-0082 already writes, now reachable because there is
  a last reading to be stale about. `?%/?% stop` remains what an account with no reading at all
  prints.
- **`asf workers quota`'s Band cell** carries a stale reading's own `why` — `quota stale since
  14:02 — session limits govern`, or `seven_d 96 ≥ 95 when read (stale since 14:02) — until Wed
  09:00` — unchanged text from a newly reachable state.
- **Three documented config keys** — `quota_guards.cache_ttl_s`, `.read_timeout_s`, `.read_budget_s`
  — in `docs/config.example.yaml` and `docs/guide/product-config.md`, with `stale_after_min`
  finally written into the example beside them (P20).
- **No approval class, no new command, no new module, no schema change.** The `quota_guards` block
  gains keys; every one of them has a default, so an operator who changes nothing gets a
  `status` that returns in a second and a wave that reads once.

## Stories

- S: One reading per account per process — a `CachedQuotaSource` memo behind `source_from_config`, a memoised failure among them, so the ten subprocesses per account one `asf status` makes become one and a wedged command is run once per command — acceptance: `python3 -m unittest -v tests.test_quota_cache.TheProcessMemo tests.test_quota_cache.StatusReadsEachAccountOnce`
- S: One reading per account per TTL per machine — `~/.ASF/state/quota-cache.json` written after every good read, served to `status`, `next`, the capacity table and every tick step inside `cache_ttl_s`, bypassed (never erased) by `expire()` and pruned of accounts the pool no longer has — acceptance: `python3 -m unittest -v tests.test_quota_cache.TheSharedTable`
- S: A read that cannot be refreshed answers with the last reading, not with nothing — the per-call cap of `read_timeout_s`, the per-process `read_budget_s` bounding a command at budget + one timeout, and the fallback that hands F-0082's stale machinery a real reading to judge instead of `None` — acceptance: `python3 -m unittest -v tests.test_quota_cache.TheReadBudget tests.test_quota_cache.StaleRatherThanUnknown`
- S: The readers — `asf status` renders `stale since HH:MM` and names a spent budget in its Quota row rather than blocking on it, while the wave and `asf workers quota` expire the table first because one launches and the other was asked — acceptance: `python3 -m unittest -v tests.test_quota_cache.TheStatusRow tests.test_quota_cache.TheReadersThatRefresh`
