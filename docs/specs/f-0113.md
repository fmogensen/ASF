# F-0113 — the S1 gate says its own name, and one plan feeds every view

On 2026-09-24, at the first customer, a product's `NEXT` showed six `BUG → FIX` rows and nothing
else. Ninety-four tier-2 rows — 47 `PLAN → CODE`, 27 `CARD → SPEC`, 12 `STARVED → PLAN`, 8
`STARVED → SPEC` — had been cut by the S1 lane, and no view said so. The operator's session found
it by reading `asf/feeder/tiers.py`. The card names a second failure beside it: `asf next` plans
off the operator's own checkout while the tick plans off its record clone with the
`plan_order` overlay applied, so the two views disagree about what would start.

What has changed since the card was written. The S1 lane no longer takes the whole floor: on
2026-09-26 it was cut back to reserving the *first seat* (`asf/feeder/tiers.py:42-47`), and the
wave learned to print a `waits` line per ready row the S1 lane cut
(`asf/tick/step_wave.py:359-383`). Two of the card's three acceptance clauses are therefore
narrower than they were, and one of its premises — that an S1 nobody is working holds the
wave — is no longer true of the code (P4 below). What is entirely unchanged is the symptom the
card is actually about: **the cut is still silent in every view an operator reads.** `asf next`
with no free seat still prints the S1 rows and nothing else, `asf status` still says
`Ready to launch 1`, and neither names the S1 that took the floor or the ninety-four rows behind
it. And `asf next` still reads a different record than the tick.

After this change: every view that shows rows names the gate that cut them, in the card's own
words; an S1 that nobody and nothing is working is said aloud as `NEEDS OPERATOR` with the count
it stands in front of; and `asf next`, `asf status` and the wave all plan through one function
over one set of inputs, with a test that holds them to it.

**This paragraph is superseded for `asf next` and the tick log by the Ruling below** — T-0438 (the
one-plan unification) was replanned out after T-0437 landed, and three further sessions failed to
re-open it. `asf status`'s `S1 gate` row is what ships; read the Ruling before this paragraph.

## Decisions

### Preconditions — verified in this checkout at `7ec124346`

### In

- **The cut names itself.** `asf/feeder/tiers.py` gains a `Gate` record and one pure function that
  builds it by comparing the plan as it was cut with the same plan made with `s1_first=False`:
  which S1 ids took the floor, how many tier-2 launching rows were dropped, by kind, and how many
  stood behind the lane at all. One formatter, `tiers.gate_line`, writes the card's line and is
  the only place that string exists.
- **Every view that shows rows shows the gate.** `asf next` prints it under the table beside the
  `Features in build` line; `asf status` grows an `S1 gate` row that is absent when no gate holds
  (P11); the wave prints it once in the tick log.
- **The wave's 94 lines become one line and five.** `left_out`'s per-row S1 `waits` lines are
  capped at five and closed with `— +N more (asf next)`, under the gate line that gives the total.
  Every other `waits` reason keeps a line per row.
- **An S1 nobody is working is said aloud.** The same `Gate` carries the open S1s with no session
  that no row launches — P4's blocked, Active-less, undecided, attempt-limited and parked cases —
  and the wave prints one `NEEDS OPERATOR` line per such Bug, naming the reason, the held count it
  stands in front of (`holds <held> of <behind> tier-2 rows`), and the command that ends it.
  A Bug `approvals.raise_holds` already named this tick is not named twice.
- **P4's invariant becomes a test.** An S1 that is not being worked cuts no tier-2 row — asserted
  directly against `plan_rows`, so the day someone widens `s1_rows` past `r.launches` the suite
  says so.
- **One plan, one set of inputs.** `step_wave.plan_now(product, …)` returns a `Plan` — the rows as
  the wave cuts them, the `Gate`, the invariant gate's drops, the items, the inputs, the capacity
  and the in-flight list. It is what `launch` plans with, what `cmd_next` plans with, and what
  `asf status`'s feeder cells plan with (once per `render`, not three times). It reads:
  - the **record clone** as the root (`step_wave.reader_root`): the tick's own clone when there is
    one, else the product's `backlog_dir` with a note saying so;
  - the index **fetched if stale**: `fresh_index` (a fetch and a read of `origin/<branch>:index.json`,
    never a reset), used as the base map when the clone is *behind* origin, and otherwise only as
    `overlay_blockers`' fresh side — which is exactly today's wave behaviour, since a clone reset
    at the tick's start is never behind;
  - `plan_order.overlay` when the product has a `repo_dir`;
  - the ledger reads of `plan_inputs` and `inflight` (P7), unchanged;
  - the capacity as `capacity_mod.resolve(product).sessions` **plus the cloud lane's seats** (P9);
  - `gated_plan`, so a view hands a dropped row's seat on exactly as the wave does (P8).
- **`--capacity`, `--inflight`, `--all` and `--json` keep working.** They are overrides passed into
  `plan_now`; `--inflight` still replaces the live sessions for a what-if, `--all` still lifts the
  decision cap. Under `--json` the rows keep their current list shape on stdout and the gate line
  goes to stderr.
- **`fresh_index` gains a timeout.** Its `git fetch` is now on the path of an interactive `asf
  next`; a fetch that hangs must degrade to "origin unreadable", which is already the function's
  contract for a failure.

### Out

- **`step_wave.plan_now`, the `Plan` the spec's `asf/tick/step_wave.py` and `asf/feeder/render.py`
  design blocks describe, and the tick log's `S1 gate`/`NEEDS OPERATOR` lines.** Moved here from
  **In** by the Ruling below, 2026-10-06: this was T-0438, replanned out after T-0437 landed
  (`docs/plans/replans/f-0113-8266efca4547.md`) and not revived after three further sessions.
  `asf next` and the tick log do not name the gate; the card's third acceptance clause — `asf
  next` and the wave producing the same rows through one function — is not met and stays not met
  under this card. Whether it is worth a Feature of its own is raised to the operator, not
  decided here.
- **Changing the cut.** `tiers.select`'s rule — an S1 row that launches and has no seat holds tier
  2 — is left exactly as 2026-09-26 left it. This card makes the cut *legible*, not different.
  A `WAITS ON a free slot` S1 is launchable; the factory starts it the moment a seat frees, and it
  is not an operator's problem.
- **Wiring `asf/feeder/idle.py`** (P12). It is the right module for "why is this slot free" and it
  is still unwired; wiring it is F-0096's unlanded Task, not this card's, and doing it here would
  put two accountings of the same tick in the same log. The `Gate` is deliberately built from the
  rows, the way `idle.account` is, so the two can be merged later without a third source.
- **A new state file, a latch, or a "seen twice" counter** for the unworked S1. The card says
  "after one tick"; the tick that sees it prints it. Delaying an S1 incident by a tick is the
  wrong direction (D6).
- **Making `asf next` create or reset the record clone.** A view that reset the clone would
  discard the uncommitted record work of a tick running beside it (`ensure_clone` resets hard —
  P6). `asf next` reads the clone; only the tick makes one.
- **Changing `asf next --json`'s shape.** Its stdout is a value a script reads (P14 calls `next`
  read-only and it stays so). The gate goes to stderr rather than wrapping the list in an object.
- **The incident clock.** `render.incidents` and its `starved` flag (`stage_limits.s1_hours`) are a
  different question — *how long* an S1 has gone without a session — and are untouched.

### The choices

| # | Chosen | Against | Why |
| --- | --- | --- | --- |
| D1 | The `Gate` is built by diffing the cut plan against the same plan with `s1_first=False` | `tiers.select` returning what it dropped, or writing it onto the returned list | `select` has one caller and eleven callers of `plan_rows` behind it; a pure function over two lists changes no signature and is the same shape `left_out` already uses |
| D2 | The `Gate` lives in `asf/feeder/tiers.py` | a new `asf/feeder/gate.py`, or `asf/feeder/idle.py` | the cut is in `tiers`; a fact about the cut belongs beside the rule that makes it, and `idle` is unwired (P12, Out) |
| D3 | `by_kind` counts the **held** rows, in the uncut plan's order | counting every tier-2 row, or sorting by count | the card's line is a breakdown of what was *dropped*, and feeder order is the order the operator will see them return in |
| D4 | The unworked S1s ride in the same `Gate` | a second function and a second pass | both answers come from the same two row lists; two passes would be two chances to disagree, which is the class of bug this card is about |
| D5 | "Being worked" is `waits_on in ('session', 'landing', 'branch', 'merge')`, everything else is a person's | reading the ledger again for a session | `bug_rows` already decided this and wrote the reason into the row (P4); the complement is robust — a blocker id is a `waits_on` value we cannot enumerate |
| D6 | The `NEEDS OPERATOR` line prints on every tick the condition holds | a latch that waits for a second sighting, to satisfy "after one tick" literally | an S1 is the one thing that must not wait a tick to be said; the operator sees it one tick after it arises either way |
| D7 | The line says `holds <held> of <behind> tier-2 rows` | `holds N rows`, the card's words | for a not-launchable S1 `held` is 0 (P4) and `holds 0 rows` reads as "nothing is wrong"; `0 of 94` is the same count, plus the blast radius if it ever becomes launchable |
| D8 | A Bug `approvals.raise_holds` already named is skipped | print both lines | `launch` has that set in hand on its first line; two `NEEDS OPERATOR` lines for one Bug train the operator to skim them |
| D9 | The wave keeps per-row S1 `waits` lines, capped at 5 with `+N more (asf next)` | drop them for the gate line, or keep all 94 | "every ready row a wave does not launch says why" (P10) is a standing rule; the cap keeps the rule and the log, and `+N more (…)` is the shape `idle.lines` already uses |
| D10 | `asf status` gains an `S1 gate` row, absent when nothing holds | fold it into `Ready to launch`, or reuse the `Gate` row | `Gate` is taken (P11); a row that appears only under a gate is the `Stale` row's own pattern, and folding it would hide it inside a count |
| D11 | `plan_now` lives in `asf/tick/step_wave.py` | a new module, or `asf/feeder/` | `render.py` and `status.py` already import `step_wave` for exactly these inputs (P7); the record clone is the tick's, so the function that reads it belongs to the tick |
| D12 | "Stale" is `origin/<branch>` not being an ancestor of the clone's `HEAD` | comparing shas | a tick's clone carries the tick's own commits *ahead* of origin; by shas it would read as stale every tick and the wave's base map would change under it. By ancestry a reset-then-commit clone is never stale, so the wave's behaviour is bit-for-bit today's |
| D13 | A diverged clone (origin moved during a tick) plans from origin's map | keep the clone's map, as today | that is F-1129's own rule — the fresher record wins — one level up from `blockedBy`; and a diverged clone's push rebases onto origin anyway |
| D14 | No clone: plan from `backlog_dir` and say so under the table | refuse, or clone one | `asf next` before the first tick, and every fixture test, has no clone; a named fallback is honest and keeps `next` read-only (P14) |
| D15 | `asf status`'s feeder cells share one `Plan` per `render` | leave them as three independent loads | three loads of the index and three ledger reads per `status` is the same divergence one table down; and an `S1 gate` row that disagreed with `Ready to launch` beside it would be worse than no row |

## The design

### `asf/feeder/tiers.py` — the gate, as a fact

```python
#: a tier-0 WAITS row whose ``waits_on`` is one of these is being worked — a live session, a
#: branch, a landing, a merge. Every other reason is a person's (F-0113, D5).
WORKED = ('session', 'landing', 'branch', 'merge')

Gate = collections.namedtuple('Gate', 'holders held behind by_kind unworked')
#: holders  [item id]   the S1 rows that took the floor: tier 0, launching, unparked, no seat
#: held     int         tier-2 launching rows the cut dropped
#: behind   int         tier-2 launching rows behind the S1 lane at all (held + the seated ones)
#: by_kind  [(kind, n)] the held rows by row kind, in feeder order
#: unworked [(id, waits_on, reason)]  open S1s no row launches and nothing is working (D5)


def gate(cut, uncut, held=()):
    """What the S1 lane did to this plan, or ``None`` when it did nothing worth a line.

    ``cut`` is the plan as :func:`select` cut it, ``uncut`` the same plan made with
    ``s1_first=False`` (:func:`asf.feeder.rows.plan_rows`) — their difference in tier-2
    launching rows is what the lane dropped. ``held``: the item ids an approval hold parks.
    ``None`` when no S1 took the floor and no open S1 is going unworked."""


def gate_line(g):
    """The one line every view prints, or ``None``::

        S1 gate: B-0057 holds 94 rows (PLAN → CODE 47, CARD → SPEC 27, STARVED → PLAN 12, STARVED → SPEC 8)

    Two holders read ``B-0057, B-0061 hold 94 rows``. ``None`` when ``g`` is ``None`` or
    ``g.held`` is 0 — a gate with nothing behind it is not news."""


def needs_operator(g, product, skip=()):
    """One line per S1 nothing is working, or ``[]``. ``skip``: ids another line already named
    this tick (D8)::

        NEEDS OPERATOR: B-0057 is S1 and nothing is working it — blocked by B-0041 — the S1
        lane holds 0 of 94 tier-2 rows behind it — asf set B-0057 blockedBy= --product asf
    """
```

The remedy each line ends on, by the row's `waits_on`:

| `waits_on` | the reason as printed | the command |
| --- | --- | --- |
| `decision` | `undecided <age>` | `asf set <id> decided=true --product <p>` |
| `operator` | `adjudicated after <n> sessions` | `asf set <id> severity=S2 --product <p>` — or close it |
| a blocker id, `blocked` | `blocked by <ids>` | `asf set <id> blockedBy= --product <p>` — or close the blocker |
| parked by a hold | `held <class>` | `asf approvals resolve <id>/<class> granted\|done\|dropped` |
| anything else | the row's own `reason` | `asf set <id> severity=S2 --product <p>` |

`select` itself is not touched. `TIER_S1`, `TIER_REST`, `NO_SLOT` and `free_slots` keep their
meaning, and `gate` reads them.

### `asf/tick/step_wave.py` — one plan

```python
@dataclasses.dataclass
class Plan:
    rows: list       #: the plan as the wave cuts it, through the invariant gate
    gate: object     #: asf.feeder.tiers.Gate, or None
    dropped: set     #: the invariant gate's drops — their seats went to the next rows
    items: dict      #: what it planned from (the record clone, overlaid)
    inputs: dict     #: plan_inputs' ledger and record facts
    capacity: int    #: the resolver's sessions plus the cloud lane's seats
    inflight: list   #: the live sessions it took off that
    root: str        #: the root the items came from
    source: str      #: 'record clone' | 'record clone (behind origin — origin\'s index)' |
                     #: 'backlog_dir (no record clone — asf tick makes one)'


#: a fetch on an interactive view's path must not hang (F-0113)
FETCH_TIMEOUT = 15
#: the wave names this many S1-cut rows one by one, then counts the rest (D9)
GATE_LINES = 5


def reader_root(product):
    """The root a *view* plans from: the tick's record clone when there is one, else the
    product's ``backlog_dir``. Never clones and never resets — a view that reset the clone would
    throw away the uncommitted record work of a tick running beside it (D14)."""


def plan_index(product, root, index=None):
    """The items a plan is made from, and how they were got: the clone's ``index.json`` with each
    card's ``blockedBy`` as origin holds it now (:func:`overlay_blockers` over
    :func:`fresh_index` — a fetch and a read, never a reset), origin's whole map instead when the
    clone is behind origin (:func:`behind`, D12/D13), then :func:`asf.record.plan_order.overlay`
    when the product has a repo. ``index`` given: the caller's map, overlays still applied."""


def behind(root):
    """True when ``origin/<default branch>`` is not an ancestor of ``HEAD`` — the clone has not
    seen what origin holds. A clone reset at a tick's start, with or without the tick's own
    commits on top, is never behind (D12). False when the question cannot be asked."""


def plan_now(product, root=None, items=None, capacity=None, inflight=None,
             decision_limit=None, out=None):
    """The plan as this tick's wave would cut it — the one function ``asf next``, ``asf status``
    and :func:`launch` read, so a row in one is a row in the others (F-0113).

    Every argument is an override for a caller that has the answer already (the wave passes its
    own ``root`` and ``items``; ``asf next`` passes ``--capacity`` and ``--inflight``). What is
    not given is read here: :func:`reader_root`, :func:`plan_index`, :func:`inflight`,
    :func:`plan_inputs`, and the resolver's sessions plus the cloud lane's seats. The rows come
    from :func:`gated_plan`, the gate from :func:`asf.feeder.tiers.gate` over a second
    ``s1_first=False`` plan."""
```

`launch` keeps every line it has; its plan is made by `plan_now` instead of by hand:

```python
-   items, _generated = index_reader.load(ctx.record_root())
-   items = overlay_blockers(items, fresh_index(ctx.record_root()))
-   if product.repo_dir:
-       items = plan_order.overlay(items, plan_order.trunk_reader(product))
    running = inflight(product)
    ...
-   inputs = plan_inputs(product, ctx.record_root(), items)
-   planned, dropped = gated_plan(items, product, running, r.sessions + extra, inputs, out=out)
+   plan = plan_now(product, root=ctx.record_root(), inflight=running,
+                   capacity=r.sessions + extra, out=out)
+   items, inputs, planned, dropped = plan.items, plan.inputs, plan.rows, plan.dropped
+   for line in [tiers.gate_line(plan.gate)] + tiers.needs_operator(plan.gate, product, skip=held):
+       if line:
+           out(f'wave: {line}' if line.startswith('S1 gate') else line)
```

The gate line prints exactly when `plan.gate.held > 0`, which by P1 is exactly when the wave
launches no tier-2 row because of the lane — the cut is all-or-nothing, so the two conditions are
one condition.

`left_out` keeps its signature and its reasons; the S1-lane ones are capped:

```python
    for row, why in left_out(...):
        if why.startswith('S1 first'):
            s1_said += 1
            if s1_said > GATE_LINES:
                s1_more += 1
                continue
        out(f'waits    {row_job(row):<24} {row.item_id:<10} — {why}')
    if s1_more:
        out(f'waits    +{s1_more} more row(s) behind the S1 gate (asf next)')
```

### `asf/feeder/render.py` — `asf next`

`cmd_next` loses its own index load and its own capacity default:

```python
def cmd_next(args, root=None):
    product = env.load_product(getattr(args, 'product', None))
    from asf.tick import step_wave
    inflight_path = getattr(args, 'inflight', None)
    plan = step_wave.plan_now(
        product, root=root,                                   # --root wins, as today
        inflight=load_inflight(inflight_path) if inflight_path else None,
        capacity=args.capacity,                               # None: the wave's own seats
        decision_limit=0 if getattr(args, 'all', False) else None)
```

`table()` takes the gate and prints it under the load line:

```
**NEXT** — 6 rows · 6 would launch

| Tier | Row | Item | Feature | Action |
...

Features in build 7 / 6 (auto: sessions 7, quota-stopped 0/5, CI free 3)
S1 gate: B-0057 holds 94 rows (PLAN → CODE 47, CARD → SPEC 27, STARVED → PLAN 12, STARVED → SPEC 8)
```

and, only when `plan.source` is not the clone, one more line:

```
— planned from the product's backlog_dir, which may be behind origin (asf tick makes the record clone)
```

Under `--json` the rows list on stdout is byte-identical to today's; `gate_line` and the source
note go to stderr.
