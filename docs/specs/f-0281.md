# F-0281 — the suite wrote its author into somebody's record, and the rail that was meant to stop it is looking at the wrong thing

On 2026-10-07 a real product record checkout carried a repo-local `user.name = Test`,
`user.email = test@example.com` in its `.git/config` — the exact pair this suite commits as
(`asf.hermetic.SUITE_GIT_NAME`, `SUITE_GIT_EMAIL`). Every record commit from 08:08 local onward
was authored *Test*. The same environment lacked the redaction name lists, so titles were written
back unscrubbed and every record push was refused (F-0273). A test ran `git config user.name` with
a target that resolved to a real repo instead of a temp fixture. The card allows that a *session*
did it instead; it did not, and P14 is why — the leaked pair is the suite's own, and no write in
`asf/` can produce it.

The reason it was silent is git's own: `git config user.name X` run anywhere **inside** a repo
walks *up* to that repo and writes its `.git/config`, exit 0, no output (P1). Run where no repo
encloses the path at all it is a hard `fatal: not in a git directory`, exit 128. So the one
spelling that can leak is the one that cannot fail, and the suite has 221 of them (P4).

Half of this card is landed. `suite_git_identity` gives the suite a global git config file of its
own, so no fixture *needs* a `git config user.*` (P2); `gitfixture.identity` is the one sanctioned
write and refuses a repo outside the suite's temp roots; `operator_files` now watches the
`.git/config` of every product repo and record the operator's config names, and
`guard_operator_files` ends a suite process with `LEAK_EXIT` when it wrote into one (P3).

The other half is not, and the code says so itself. The ratchet that was meant to freeze the old
sites carries the comment *"The zero sweep is a later change"* (`tests/test_hermetic.py:420`).
This spec is that change — and it found two things wrong with the rail meant to hold the line
until it came:

- **The rail is blind to how most of the suite is written.** `test_no_new_git_identity_site`
  matches the line pattern `'config', 'user\.`, which sees the literal argv form only. The loop
  form — `for k, v in (('user.name', 'Test'), ('user.email', 't@example.com')): sh(['config', k, v], repo)`
  — carries no such line, and that is how 114 of the 221 sites are written, across 23 files the
  ratchet caps at **zero** and has never counted (P5). `tests/test_lifecycle.py`, which the card
  names, holds 32 of them and reads as clean today.
- **The sanctioned guard validates the wrong path.** `identity()` checks the string it was handed,
  not the repo git will write. Hand it a directory that is under a suite root but is not itself a
  repo and it accepts, git walks up, and the write lands in whatever real repo encloses it —
  demonstrated (P6). Under a linked worktree the write does not even land in the worktree: it
  lands in the common dir's config, one directory up and outside the worktree the test named (P7).
  Four of the card's own named sites (`tests/test_harvest.py:224-225`) write with a worktree as
  their target.

### In

1. **The guard validates the repo git will write, not the path it was handed.** `identity()`
   resolves its target with `git rev-parse --path-format=absolute --git-common-dir` and requires
   *that* under the suite's roots; a target no repo encloses is refused too, not left to git's
   exit 128. This is the F-0143 `HOOKS_CONFINE` idiom — constrain the *resolution*, because a
   hand-built path cannot fake that step.
2. **The rail reads the call, not the line.** `test_no_new_git_identity_site` counts identity-key
   literals from the AST, so the loop form, a dict value and an argv literal all count the same,
   and its baseline is re-cut at the true 221.
3. **The zero sweep.** Every repo-local identity write in `tests/` goes — the suite's global
   config already carries one — or goes through `identity()` where a test asserts on a *different*
   author. `IDENTITY_SITES` drains to the three files that must keep a literal, and every other
   file in the suite is zero.
4. **The suite's global config states what the sweep relies on.** `commit.gpgsign = false` joins
   `[user]` and `[safe]` in the file `suite_git_identity` writes, so deleting 25 repo-local copies
   rests on something the suite says rather than on git's default (P9).
5. **One source for the suite's roots.** `hermetic.suite_markers()` returns both spellings of both
   roots and `gitfixture.suite_roots()` is the same list; a test pins them equal (P10).
6. **The exit-time guard blames any identity, not only the suite's own.** `_identity_marks` marks a
   `.git/config` that gained *an* identity, so a leaked `Person <p@example.com>` is blamed like a
   leaked `Test <test@example.com>` (P8).

### Out

- **The `-c user.name=v` form stays, uncounted** (100 literals). It writes no config file; it
  cannot do what this card is about. A test that evades the rail by switching to `-c` has fixed
  the leak, which is why the rail does not chase it.
- **A test that *commits* in a repo it should not** is a different defect — a target escape, not a
  config write — and the exit-time guard cannot see it (no operator file changes). Out of scope,
  and named here so the next reader does not read this card as covering it.
- **The `GIT_CONFIG_KEY_n` env channel stays** (`tests/test_session_push_guard.py`, 2 literals,
  allow-listed): it is the subject of that test and writes no file.
- **No new command, no new state file, no new convention, no operator question.**
- **No change to `guard_operator_files`, `operator_files`, `LEAK_EXIT` or either entry point.**
  The landed half stands; only `_identity_marks`' blame widens.
- **`gitfixture`'s hook and housekeeping work is untouched.** `core.hooksPath=/dev/null`,
  `gc.auto`, `gc.autoDetach`, `maintenance.auto` stay repo-local, asserted repo-local by
  `tests/test_gitfixture.py`. Only identity moves to the global file.
- **No behaviour change in `asf/`** beyond `suite_git_identity`'s one added line and
  `_identity_marks`' predicate. This card is about the suite.
- **The session half of the card's own sentence — "a test *or session* ran `git config`" — is
  out, and measured out.** The leaked pair is `SUITE_GIT_NAME`/`SUITE_GIT_EMAIL` exactly, which
  only the suite writes; none of `asf/`'s three identity writes can produce it (P14). So a session
  did not author this leak. What stays true is that `asf/tick/shadow.py:83-84` writes a repo-local
  identity with a `cwd`, the one form that cannot fail (P1), and no rail watches it: the rail this
  card builds walks `tests/`, and `guard_operator_files` runs in suite processes only. That is a
  gap, it is not this card's — the card's title scopes the requirement to tests — and it is the
  `NEEDS OPERATOR` in this session's report rather than a fourth Story, because widening a card
  past its title is the reviewer's call.
- **The fixtures are not rewritten.** Sites are deleted or routed; no fixture is restructured,
  renamed or moved to `Template`, however much some of them would like it.

## The design

### 1. The guard — `tests/gitfixture.py`

```python
def suite_roots():
    """Where a repo the suite made lives — :func:`asf.hermetic.suite_markers`, the one list
    (F-0281 C8). Both spellings of the temp dir and of the suite's ``ASF_HOME``: the temp root is
    reached through a symlink on some platforms while ``mkdtemp`` hands back the unresolved form,
    and a guard that refuses a legitimate temp repo is a guard tests route around."""
    return hermetic.suite_markers()


def identity(repo, name='Test', email='test@example.com'):
    """Set ``repo``'s own git identity — the one sanctioned ``git config user.*`` site in the
    suite (F-0281). The suite's global config already carries an identity
    (:func:`asf.hermetic.suite_git_identity`), so only a test that asserts on a *different* author
    calls this.

    What is validated is the **config file git will write**, not the path handed in:
    ``git rev-parse --path-format=absolute --git-common-dir``. A directory under a suite root that
    is not itself a repo passes a path check and still leaks — git walks up to whatever repo
    encloses it and writes there, exit 0, silently — which is how the suite's identity reached a
    product's record and authored every record commit after it. In a linked worktree the write
    lands in the common dir, outside the worktree the caller named, so the worktree's own git dir
    is not the answer either. A target no repo encloses is refused here rather than left to git's
    exit 128. Raises :class:`OutsideSuite` in both cases."""
    common = subprocess.run(['git', '-C', repo, 'rev-parse', '--path-format=absolute',
                             '--git-common-dir'], capture_output=True, text=True)
    if common.returncode != 0:
        raise OutsideSuite(f'{repo} is not inside a git repository '
                           f'({common.stderr.strip()}) — a test sets a git identity only in a '
                           f'repo it made')
    target = os.path.realpath(common.stdout.strip())
    if not any(target.startswith(root + os.sep) for root in suite_roots()):
        raise OutsideSuite(f'{repo} writes its config to {target}, outside the suite\'s roots '
                           f'{suite_roots()} — a test sets a git identity only in its own repo')
    for key, value in (('user.name', name), ('user.email', email)):
        subprocess.run(['git', '-C', repo, 'config', key, value], check=True,
                       capture_output=True, text=True)
```

`OutsideSuite` keeps its name and its base (`AssertionError`): a refusal reads as a failing test,
which is what it is.

### 2. The suite's roots and its global config — `asf/hermetic.py`

```python
def suite_markers():
    """What a path the suite made starts with: both spellings of this process's temp dir and both
    of the suite's own ``ASF_HOME``. Also :func:`tests.gitfixture.suite_roots` — one list, because
    each spelling was in one of the two copies only (F-0281 C8)."""
    marks = set()
    for root in (tempfile.gettempdir(), os.environ.get('ASF_HOME')):
        if root:
            marks.update((root, os.path.realpath(root)))
    return sorted(m for m in marks if m and m != os.sep)
```

`suite_git_identity`'s file gains one section, and its docstring the reason:

```python
        f.write(f'[user]\n\tname = {SUITE_GIT_NAME}\n\temail = {SUITE_GIT_EMAIL}\n'
                '[commit]\n\tgpgsign = false\n'
                '[safe]\n\tdirectory = *\n')
```

— stated, not inherited: `GIT_CONFIG_NOSYSTEM` already keeps a host `gpgsign = true` out (P9), but
the 25 repo-local `commit.gpgsign = false` writes the sweep deletes were the only thing that said
so, and the sweep should not rest on git's default.

And the blame widens:

```python
#: A gained identity in a repo config is the suite's mark, whoever it names (F-0281 C9): after the
#: zero sweep the suite's surviving writes are exactly the ones with a *non*-suite author, so a
#: predicate naming :data:`SUITE_GIT_EMAIL` would be blind where the risk is. A file is only ever
#: blamed when it **changed** and **gained** a mark, so an operator's own identity, already in
#: their config, is never one.
_USER_EMAIL_RE = re.compile(rb'^\s*email\s*=\s*(\S+)', re.M)


def _identity_marks(path, data):
    if not data or not str(path).endswith(os.path.join('.git', 'config')):
        return set()
    return {b'identity:' + m for m in _USER_EMAIL_RE.findall(data)}
```

Nothing else in the guard moves: `operator_files`, `snapshot_operator_files`, `leaked_files`,
`guard_operator_files` and `LEAK_EXIT` are unchanged, and `_suite_paths` still contributes its
own marks beside these.

### 3. The rail — `tests/test_hermetic.py`

```python
    #: Where a git identity key may be written as a literal, and how many times. Absent means
    #: zero — every other file in the suite (F-0281). The suite's global config carries the
    #: identity, so a fixture needs none; a test that asserts on a *different* author calls
    #: gitfixture.identity, which refuses any repo whose config is not under the suite's roots.
    IDENTITY_SITES = {
        'gitfixture.py': 2,              # identity() itself — the one sanctioned write
        'test_hermetic.py': 8,           # this rail and the guard's own fixtures
        'test_session_push_guard.py': 2, # the GIT_CONFIG_KEY_n channel: writes no config file
    }

    IDENTITY_KEYS = ('user.name', 'user.email')

    def _identity_literals(self, path):
        """Every string constant in ``path`` equal to a git identity key, read from the AST.

        Not a line pattern. This rail began as ``'config', 'user\\.`` and so counted the literal
        argv form only: the loop form — ``for k, v in (('user.name', …), …): sh(['config', k, v],
        repo)`` — carried no such line, and 114 of the suite's 221 sites were written that way, in
        23 files this dict capped at zero and never counted (F-0281 P5). A literal is a literal
        however it reaches the call.

        The ``-c user.name=v`` form is a different literal and is not counted: it writes no config
        file and cannot leak (C2 of the Out list)."""
        tree = ast.parse(pathlib.Path(path).read_text(encoding='utf-8'), str(path))
        return [n for n in ast.walk(tree)
                if isinstance(n, ast.Constant) and isinstance(n.value, str)
                and n.value in self.IDENTITY_KEYS]
```

`test_no_new_git_identity_site` keeps its walk, its `over` list and its message, and counts with
`_identity_literals` instead of the pattern. One test is added beside it: the three allow-listed
files are the whole allow-list, so a fourth entry is a change a reader must justify.

### 4. The sweep — `tests/`, 52 files

One mechanical edit, three shapes:

- **Delete.** A fixture that never asserts on its author loses its identity lines, and the
  `commit.gpgsign = false` beside them (P9, C7). A `for k, v in (…)` loop whose only remaining
  pair was identity loses the loop; one that also set something else keeps the loop without the
  identity pairs. This is the great majority of the 209.
- **Route.** A site that asserts on a specific author — `Person <p@example.com>`, `o@example.com`,
  `hand@example.com`, `seed@example.com`, `sample@example.com`, `tester@example.com`,
  `ci-cancels-fixture` (P13) — becomes `gitfixture.identity(repo, '<name>', '<email>')`. The
  default author needs no call: the global config already names it.
- **Leave.** The three allow-listed files.

No fixture is restructured and no test's assertions change. `tests/test_harvest.py`'s
`git_identity(path)` helper (`:537`) becomes a call to `gitfixture.identity` or goes, and its four
callers follow; the worktree targets at `:224-225` are exactly the shape P7 is about.

## Acceptance tests

Each block is runnable from the repo root as it stands.

**S-75904 — the guard validates the repo git will write, and the rail reads the call**

