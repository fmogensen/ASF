# F-0144 — widening a footprint by hand is one command, and it tells the truth

The card asks for `writes:` and `after:` to be settable through `asf set`, with the same stage and
index refresh every other field gets. **That half is already in the checkout.** A hotfix landed it
on 2026-09-25 — the same day as the incident the card describes — and it names neither the card nor
this Feature:

```
f35e1a3d2 fix(set): writes: and after: are settable list fields — =, += and -= forms
```

Its five tests are green here (P4). So this spec is not about making the field settable. It is
about the two things that commit left behind, both on the exact path the card exists for — an
operator widening an under-scoped footprint after a push refusal names a file outside it.

**The command is wrong on a card whose `writes:` came from a plan.** A plan's Task line is split on
commas only (P6), so `Files: asf/a.py asf/b.py` lands as **one** entry holding two paths. Every
other reader of `writes:` normalises that away through `widen.norm_writes` (P7) — `asf set` is the
one that does not. Verified in this checkout, through the CLI, on a card whose `writes:` is
`[asf/a.py asf/b.py, docs/g.md]`:

```
$ asf set T-0001 writes+=asf/a.py
T-0001: set writes=asf/a.py asf/b.py docs/g.md asf/a.py     # a path already inside it, added again
$ asf set T-0001 writes-=asf/b.py
T-0001: set writes=asf/a.py asf/b.py docs/g.md asf/a.py     # exit 0. Nothing was removed.
```

The second line is the worse one: exit 0, a success line, and a card that did not change. An
operator who runs it reads the footprint as narrowed and it is not.

**And nothing says the command exists.** `asf set --help` prints `FIELD=VALUE` and no more (P9);
the operator guide's only sentence naming `asf set` is about it *not* publishing, and is itself
false (P11, P12). The card was filed because a session hit the refusal and hand-edited the authored
line instead. The forms now exist; the route an operator follows still does not say so anywhere.

### In

- **`asf set` normalises a list field before it operates on it.** A packed entry (P6) is split into
  its paths, de-duplicated, order kept — on `=`, `+=` and `-=` alike, for `writes:` and `after:`.
  After this card `asf set` can no longer write a packed entry, and no longer misreads one.
- **`writes+=<path>` the footprint already covers adds nothing** and says so, using `widen.covered`
  (P7) — the same coverage rule the tick's automatic widening uses. `writes+=asf/feeder/rows.py`
  against `writes: [asf/feeder/**]` is an idempotent no-op, not a redundant entry.
- **A `-=` that removes nothing is refused**, exit 2, card unchanged, saying which of the two it
  is: the path is not there, or a glob covers it and the glob must be replaced. Today it is a
  silent exit 0.
- **The stage and the publish half, pinned by a test.** P2 is verified live and has no test; the
  card names it explicitly, so it gets one.
- **`asf set --help` names the list fields and the three forms**, so the refusal an operator hits
  on a scalar field, and the help they read next, both point at the same thing.
- **The operator guide documents widening by hand**: the command, the push-refusal it answers, the
  I3 refusal when another Active Task holds the path, and that the tick widens automatically from a
  REPORT's `needs writes:` so the hand route is the operator's, not the coder's.
- **The false drift sentence (P12) is corrected** in the same edit.

### Out

- **Making `writes:`/`after:` settable.** Already landed (P1, P4). This card keeps those five tests
  green and adds to them; it does not rewrite them.
- **`asf new --set writes=…`.** `writes` is not in `new.SETTABLE`, and `asf new --writes GLOB`
  (repeatable) is the minting route. Nothing in the card asks for the `--set` spelling, and the two
  would be two ways to write one field at mint time.
- **Normalising the record's existing packed entries.** This card makes `asf set` correct on a
  packed card; it does not sweep the backlog. A card is normalised the first time someone sets it,
  which is exactly when it matters.
- **Fixing `writes_lines` to split on whitespace too** (P6). That is the plan minter's parser, its
  blast radius is every plan ever parsed, and `norm_writes` exists precisely because the tree
  decided to normalise at the reader. See D3.
- **Coverage-aware `-=` that rewrites a glob.** Refused with the glob named (D5), never guessed at.
- **A History line on a hand widening.** The tick's automatic widening files
  `footprint widened: +… (fact)` because a later pass counts those lines to decide reshape
  (`widen.widened_paths`). A hand widening writing one would feed that counter a widening the rule
  never made. See D7.
- **`asf groom`'s half of the drift sentence beyond the sentence itself.** The sentence is corrected
  as a sentence; no groom behaviour is touched.
- **Any new command, flag or config key.** P10.

## The design

### `asf/record/setfield.py` — the list algebra normalises, and coverage decides

`apply_list` grows the tree's two rules and a second return value — what the op actually did — so
the caller can refuse a `-=` that did nothing without re-deriving it:

```python
def apply_list(current, op, value, covers=False):
    """``(new, changed)``: ``current`` with ``value`` put by ``op``. Both sides are flattened
    first (:func:`asf.feeder.widen.norm_writes`), so an entry a plan packed two paths into
    (``writes: [a.py b.py]``) is the two paths it names — the shape every other reader of
    ``writes:`` already sees (D2).

    ``=`` replaces, ``+`` adds what is not there, ``-`` drops what is named. With ``covers``
    (``writes:``, whose entries are path globs) ``+`` also drops a path the footprint already
    covers by :func:`asf.feeder.widen.covered` — the rule the tick's own widening uses, so the
    hand route and the automatic one add the same paths (D3). ``changed`` is False when the op
    left the footprint as it was."""
    from asf.feeder import widen  # the tree's one splitting and coverage rule (D3, D4)
    have = widen.norm_writes(_as_list(current))
    want = widen.norm_writes(value)
    if op == '+':
        add = [v for v in want if v not in have and not (covers and widen.covered(v, have))]
        return have + add, bool(add)
    if op == '-':
        kept = [v for v in have if v not in want]
        return kept, kept != have
    return want, want != have
```

`_why_not_removed` is the whole of D5's message: for each path either the glob that covers it, or
that the field does not name it.

```python
def _why_not_removed(field, item_id, base, value):
    """D5's reason: the glob that covers each path, else that the field does not name it."""
    from asf.feeder import widen
    have = widen.norm_writes(_as_list(base))
    out = []
    for v in widen.norm_writes(value):
        glob = next((w for w in have if w != v and widen.covered(v, [w])), None)
        out.append(f"{glob} covers it; replace the glob ({field}=[…])" if glob
                   else f"{item_id}'s {field}: does not name it")
    return '; '.join(dict.fromkeys(out))
```

and a section follows it:

```markdown
## Widening a Task's footprint

A push is refused because the diff names a file outside the Task's `writes:`. Widening it is one
command, and `asf set` publishes the card itself (above):

    asf set T-0338 writes+=asf/tick/widen_footprint.py

`writes:` and `after:` are the two list fields: `+=PATH` adds, `-=PATH` removes, `=[a, b]`
replaces, and `+=[a, b]` takes several at once. A path the footprint already covers — named, or
under one of its globs — is not added twice, and a `-=` that would remove nothing is refused
rather than reported as done. A Task never ends with an empty `writes:`.

Two refusals are the record protecting itself, not a bug:

- `I3: writes: intersects Active task T-0412's writes:` — another Active Task holds that path. One
  of the two has to finish first; the card is left exactly as it was.
- An approvals-protected path — it goes to its approval class, not into a footprint.

Most widenings are not yours to make. When a coder session's REPORT names `needs writes:`, or its
branch goes red on a file outside the footprint, the tick widens the Task itself and sends the same
session back as a correction with no round spent. The command above is for the card in front of
you — a plan that under-scoped a Task you are about to start, or a footprint you are narrowing.
```

## Records

- **A Task card's `writes:` and `after:`**, written by `asf set` through `set_typed` exactly as
  today — the parser round-trip, the record stage under the writer name `set`, then `cli`'s publish
  commit `record: set <id>` carrying the card and the derived record it implies (P2, P3). What
  changes is only the value written: flat, one path per entry, no path the footprint already covers
  added twice.
- **`asf set`'s stdout**, one line per run: `<id>: set writes=<paths>` as today, or
  `<id>: writes: already covers <paths> — footprint unchanged` when an add was idempotent (D6).
- **`asf set`'s stderr and exit 2**, a new refusal: `error: writes-=<paths> removes nothing — <the
  glob that covers it; replace the glob (writes=[…])|<id>'s writes: does not name it>`. The card is
  unchanged, and no commit is made.
- **No History line, no metrics event, no state file.** A hand widening is deliberately not written
  into the `footprint widened: +…` record the tick's widening rule reads back (D7). The publish
  commit is the record that it happened.
- **No new card, command, flag, config key or file.** `surface.COMMANDS` and its count literal are
  untouched (P10), `index.json`'s schema is untouched (P3).
- **`docs/guide/operating.md`** — a corrected drift sentence and a new `## Widening a Task's
  footprint` section. No other guide page names `asf set`.
- **A footprint the record already holds is not rewritten** until someone sets it: this changes what
  `asf set` writes, never what is already on disk.
