# F-0078 — The tick ends with two tables: in flight, and done since the last tick

The card, verbatim: *"When the tick runs I see one-liners. It would be more useful in table
format with relevant columns and a description of what's being developed, as well as completed
since last tick."*

Today `asf tick` prints one line per thing each step did (`launched …`, `waits …`, `ended …`,
`landed …`, `tick: state committed and pushed …`) and stops. Nothing on the log says what the
factory is working on right now, or what it finished since the operator last looked. This spec
adds a summary at the end of every tick: two plain-text tables over the session ledger, each row
carrying the item's title, so a tick log reads as a status report and not as a trace.

## 1. Decisions

### In

- Every `asf tick` that reaches its steps loop ends with two tables, printed after the tick's
  commit line: **IN FLIGHT** (each job whose *latest run* is live — `lifecycle.is_live`) and
  **DONE since `<ts>`** (every *run*, latest or not, whose `ended` falls after the previous tick
  on the same clock).
- Both tables are read through `asf.workers.lifecycle`, which owns the fold of the append-only
  registry into runs. The summary adds no second reader of `sessions.jsonl`.
- Each row carries the item's title — "what's being developed" — read from the record clone's
  `index.json`.
- The window's start is remembered per product and per clock in a stamp file under the product's
  state dir, so the next tick on that clock reports exactly the sessions that ended in between —
  no session is reported twice, none is skipped.
- The summary is best-effort output: a failure to render it is one `tick: summary not rendered
  (<why>)` line and never changes the tick's exit code.
- The existing tests in `tests/test_tick.py` that assert a tick's exact stdout gain the two
  trailing tables; they are updated, not weakened.

### Out

- The step lines themselves are unchanged. The tables are added after them, nothing is removed
  or reformatted. (A quieter step log is another card.)
- `asf tick --shadow` and `asf tick --manifest` print no tables: the first is record-only, the
  second prints a table of its own and exits before any step.
- A tick refused before its steps (`exit 2`: an unowned step, a `ConfigError`) prints no tables —
  it did not run.
- The markdown `SESSIONS` table (`asf sessions`, `asf/views/sessions.py`) is untouched. It is a
  view over the record for a rendered page; this is the tick's own console output.
- Landings are not a third table. A branch that lands prints its `landed <branch> → <sha>` line
  from the `harvest` step already; the DONE table shows `landed <sha7>` in a session's result
  cell when the harvest has marked it, and nothing more.
- No new event, no new metrics stream, no change to `metrics/ticks`.

### Preconditions

- The session registry `~/.ASF/state/<product>/sessions.jsonl` is the source of truth for what
  runs: a launch line carries `job, item, feature, kind, account, model, pid, branch, started`;
  `health` writes `ended` (ISO-8601 UTC, seconds) and `end_reason`; the harvest writes
  `harvested: <sha>`. All already true.
- The registry is **append-only and folds into runs, not sessions**: a line carrying `started`
  and `pid` opens a new run of its job, every other line updates that job's latest run, and a
  run's terminal fields never carry across the boundary (`lifecycle.fold`, `RUN_FIELDS`, B-0041).
  One job can therefore hold several ended runs — `ENDED → LAUNCHED` is a declared transition, so
  a relaunch is ordinary, not an edge case. `lifecycle.runs(path)` gives every run;
  `lifecycle.latest(path)` (which is what `pool.load_sessions` returns) gives only the last one
  per job.
- `index.json` in the tick's record clone (`asf.tick.shadow.record_dir(product)`) maps item ids
  to `title`. Made by the `record` step; on a clock that never runs `record` it is whatever the
  last `record` tick left — a snapshot, good enough for a title.
- `env.state_dir(product)` exists and is writable (the daily stamp already lives there).

### Choices

| chosen | against | why |
| --- | --- | --- |
| Plain padded-column text, `what` last and unpadded (the `--manifest` table's idiom) | Markdown pipe tables as `asf/views/*` render | The tick log is read raw in a terminal or `tail -f`, never rendered; pipes and dashes are noise there. `--manifest` already set the tick's table idiom. |
| The window's start is a stamp file per product and per clock (`summary-<clock>.stamp`) | One stamp per product; or the last `metrics/ticks` line in the record | The scheduler runs several clocks per product (`record` every 10 min, `health-wave-prs-harvest` less often), each to its own log. One shared stamp would report each ended session in whichever log ticked first and drop it from the others. The `ticks` stream is lost when a push is refused and re-derived; a state-dir stamp is not. |
| No stamp yet → the window opens 24 h before now | An empty window; or "since the epoch" | The first tick on a new clock should still say what finished recently; 24 h is what the operator would ask for, and everything older is in `asf sessions` / the record. |
| A session is DONE when its `ended` is in `(since, now]`; the stamp is written as `now` after the tables print | Keying on `harvested`, or on the log's result line | `ended` is the one terminal timestamp every session gets, written by the tick itself; a half-open window with the stamp at its close means every ended session is reported once. |
| The tables print even when every step was `off` or skipped (`ran` empty) | Only when a step ran, as `finish` does | IN FLIGHT is state, not a step's output — it is as true on a tick that ran nothing. The stamp still advances so the next tick's window is right. |
| Titles come from `<record_dir>/index.json` if the file exists; the summary never clones or resets the record | `ctx.record_root()` (which clones on demand) | A `--steps batch` clock must not clone the record just to print titles; a stale title is fine, a clone is a network round trip and a commit surface. |
| Both tables read the registry through `asf.workers.lifecycle` — `live_sessions`/`is_live` for IN FLIGHT, `runs()` flattened for DONE | A fold of our own over the raw `sessions.jsonl` lines | `lifecycle` is "the one model of a lane job's life" and every other reader (spawn, health, harvest, the feeder, the wave, the PR step) already asks it. A second fold would be a second definition of "a session", and would drift the first time the registry's shape moves. |
| DONE iterates **every run** (`lifecycle.runs`), not the latest run per job (`pool.load_sessions`) | `pool.load_sessions` / `live_sessions`, the obvious pair | `load_sessions` *is* `lifecycle.latest` — one run per job. A job that ended and was relaunched in the same window would have its first, ended run dropped, and no later tick would ever show it: the window has moved past. "None is skipped" is only true over runs. |
| IN FLIGHT carries a `status` column: `working` or `dead pid` (the `asf sessions` split) | Trusting the ledger's "no `ended`" alone | On a clock without `health` a session with a dead pid stays "live" in the ledger for a while; the operator should see that it is not working. Reuses `asf.views.sessions.pid_alive`. |
| Ages and durations as compact `12m` / `1h03m` / `2d04h` | Raw ISO timestamps in both columns | Two ISO stamps per row is a wide table that still makes the reader subtract. `started` is not shown at all in IN FLIGHT: `since` is the answer to the question `started` would be asked for. |
| The tables are the last thing printed, after `tick: state committed and pushed` | Before the commit line | "The tick ends with two tables." The commit line is one line the operator has learned to look for; it stays where it is, one screen up. |
| One new module `asf/tick/summary.py`; `tick._run_steps` calls it once | Growing `asf/tick/tick.py`; or a new `asf/views` page | The views package renders record pages; this renders the ledger for a console. `tick.py` is the orchestration and stays that. |

## 2. The design

### The output

The tick's last lines, on a product with two sessions running and one just ended:

```
tick: state committed and pushed (/Users/op/.ASF/state/sample/record)

IN FLIGHT — 2 sessions
job              item    kind     feature  account  model  status    since  what
spec-f-0078      F-0078  spec     F-0078   acct-a   opus   working   12m    The tick ends with two tables: in flight, and done since the last tick
fix-b-0048       B-0048  fix-bug  F-0031   acct-b   opus   dead pid  1h03m  A held branch is relaunched on top of its own commits

DONE since 2026-09-22T10:00:00Z — 1 session
job              item    kind     result                     took  what
fix-b-0046       B-0046  fix-bug  finished, landed d9a1df0   41m   A correction row spawns on the held branch, rebased onto main
```

With nothing in either:

```
IN FLIGHT — none

DONE since 2026-09-22T10:00:00Z — none
```

Rules of the shape:

- A blank line before each block. The block is a header line, then — when there are rows — a
  column-name line and one line per row. Columns are separated by two spaces and padded to the
  widest cell in the column; the last column (`what`) is never padded.
- The header counts: `1 session`, `2 sessions`, `none`.
- The DONE header names the window's start, the previous stamp, in the ledger's own ISO form
  (`YYYY-MM-DDTHH:MM:SSZ`). With no previous stamp it names the computed start (now − 24 h) and
  appends ` (first tick on this clock)`.
- IN FLIGHT columns: `job item kind feature account model status since what`.
  `status` is `working` when the session's pid answers, `dead pid` otherwise. `since` is the age
  of `started`. Rows sort by `started`, oldest first.
- DONE columns: `job item kind result took what`. `result` is the ledger's `end_reason`
  (`finished`, `failed: <signature>`, `dead pid`, `stopped …` — whatever `lifecycle.judge` wrote,
  never re-worded here), then `, landed <sha7>` when the run carries `harvested`
  (`lifecycle.landed`). `took` is `ended − started`. Rows sort by `ended`, oldest first. A job
  relaunched inside the window has one row per ended run; the rows share a job name and are told
  apart by `took` and `result`, which is what the operator is reading them for.
- `what` is the item's `title` from `index.json`; `—` when the item is not in the index or the
  index is not on disk. Every other missing cell is `—` too; a missing or unparseable timestamp
  renders its age as `?`.
- Ages: below a minute `<1m`; below an hour `12m`; below a day `1h03m`; else `2d04h`.

### The window and the stamp

`<state_dir>/summary-<clock>.stamp` holds one ISO timestamp: the `now` of the last tick that
printed its tables on this clock. `clock` is the steps the tick was asked for, in manifest order
joined by `-` (`record`, `health-wave-prs-harvest`, `daily`), or `all` when `--steps` was not
given — the same slug the scheduler puts in the log's file name, so log and stamp pair up.

- window start `since` = the stamp's value, or `now − 24 h` when the file is absent or empty;
- a **run** is DONE when it has `ended` and `since < ended <= now` (string comparison — the
  ledger's stamps and `now` share one format and one zone). The candidates are every run of
  every job (`lifecycle.runs`), so a job relaunched inside the window contributes one DONE row
  per ended run and still appears in IN FLIGHT for its live latest run;
- the stamp is rewritten with `now` after the tables print, and only then; a render failure
  leaves the old stamp, so the next tick's window still covers what this one did not report.

### The code

New module `asf/tick/summary.py`:

```
clock(chosen)                         -> 'record' | 'health-wave' | … | 'all'
stamp_path(product, clock)            -> <state_dir>/summary-<clock>.stamp
read_stamp(product, clock)            -> ISO string or None
write_stamp(product, clock, now_iso)
window_start(stamp, now)              -> stamp or (now − 24h) as ISO
age(start_iso, end_iso)               -> '<1m' | '12m' | '1h03m' | '2d04h' | '?'
titles(product)                       -> {item_id: title} from <record_dir>/index.json, {} if absent
inflight_rows(product, alive)         -> [run + status] for each job whose latest run is live,
                                         via pool.live_sessions (= lifecycle.is_live over
                                         lifecycle.latest), sorted by started
done_rows(product, since, now)        -> [run] over lifecycle.runs(sessions_path(product)),
                                         flattened across every run of every job, kept when
                                         since < ended <= now, sorted by ended
render(inflight, done, titles, since, now, first) -> str   (pure: no I/O, no clock)
run(ctx, chosen, out=print, now=None, alive=pid_alive)     -> None
```

`run` computes `now` once, reads the stamp, builds both row lists, prints `render(...)` through
`out`, then writes the stamp. Any exception inside it (an unreadable ledger, a bad `index.json`,
an unwritable state dir) is caught and printed as one `tick: summary not rendered (<why>)` line;
`run` never raises and returns nothing — the tick's rc is the steps' and the commit's.

`asf/tick/tick.py`:

- `cmd_tick` passes `chosen` (the parsed `--steps`, or `None`) on to `_run_steps`;
- `_run_steps` calls `summary.run(ctx, chosen)` as its last act, after `finish(ctx, ran)` and
  regardless of whether `ran` is empty; the rc it returns is unchanged.
- The module docstring gains one sentence after the step-log paragraph: *After the commit the
  tick prints its summary — the sessions in flight and the ones that ended since the last tick
  on this clock (`asf.tick.summary`).*

`asf/views/sessions.py`: `pid_alive` is reused as is; nothing changes there.

`tests/test_tick.py`: every assertion of the form `assertEqual(out, '<one line>\n')` or
`assertEqual(out.splitlines()[-1], …)` on a tick that reached its steps loop is updated for the
two trailing blocks. The plan lists them; the cleanest form is a helper that strips the summary
(`out.split('\n\nIN FLIGHT')[0]`) for the tests whose subject is the step lines, plus the new
tests below whose subject is the summary itself.

## 3. Acceptance tests

All in `tests/test_tick_summary.py`, run with:

```sh
python3 -m unittest tests.test_tick_summary -v
```

and the whole suite still green:

```sh
python3 -m unittest discover -s tests -v
```

The file's fixture: a temp `ASF_HOME`, a product built directly (`env.Product('p', {...})` as

```python
# tests/test_tick_summary.py
"""asf.tick.summary — the two tables the tick ends with, over the ledger and the index."""
import json
import os
import shutil
import tempfile
import unittest
from unittest import mock

from asf import env
from asf.tick import shadow, summary
from asf.workers import pool as pool_mod

NOW = '2026-09-22T12:00:00Z'
INDEX = {'generated': '', 'items': {
    'F-0001': {'id': 'F-0001', 'type': 'feature', 'title': 'a feature', 'folder': 'features',
               'state': 'New', 'decided': True, 'rank': 1},
    'B-0002': {'id': 'B-0002', 'type': 'bug', 'title': 'a bug', 'folder': 'bugs',
               'state': 'New', 'decided': True, 'rank': 1, 'parent': 'F-0001'},
}}


class SummaryTestCase(unittest.TestCase):
    def setUp(self):
        self.tmp = tempfile.mkdtemp(prefix='summary_test_')
        self._home = env.ASF_HOME
        env.ASF_HOME = os.path.join(self.tmp, 'home')
        os.makedirs(env.ASF_HOME)
        self.addCleanup(self._restore)
        self.product = env.Product('p', {'repo_dir': self.tmp, 'main': 'main',
                                         'ci': {'provider': 'none'}, 'deploy_sha': 'none'})
        os.makedirs(shadow.record_dir(self.product))
        with open(os.path.join(shadow.record_dir(self.product), 'index.json'), 'w') as f:
            json.dump(INDEX, f)

    def _restore(self):
        env.ASF_HOME = self._home
        shutil.rmtree(self.tmp, ignore_errors=True)

    def launch(self, job, item='F-0001', kind='spec', started='2026-09-22T11:48:00Z', **extra):
        pool_mod.append_session(self.product, dict(
            job=job, item=item, kind=kind, feature='F-0001', account='acct-a', model='opus',
            pid=101, branch=f'{kind}/{item}', started=started, **extra))

    def render(self, chosen=None, alive=lambda pid: True, lines=None):
        lines = [] if lines is None else lines
        summary.run(_ctx(self.product), chosen, out=lines.append, now=NOW, alive=alive)
        return '\n'.join(lines)


class _ctx:
    def __init__(self, product):
        self.product = product
        self.has_record = False


class ShapeTests(SummaryTestCase):
    def test_empty_ledger_prints_two_none_headers(self):
        text = self.render()
        self.assertEqual(text.split('\n'), [
            '', 'IN FLIGHT — none', '',
            'DONE since 2026-09-21T12:00:00Z — none (first tick on this clock)'])

    def test_in_flight_row_carries_the_title_and_the_age(self):
        self.launch('spec-f-0001')
        text = self.render()
        self.assertIn('IN FLIGHT — 1 session', text)
        self.assertIn('job', text.split('\n')[2])           # the column line follows the header
        row = [ln for ln in text.split('\n') if ln.startswith('spec-f-0001')][0]
        for cell in ('F-0001', 'spec', 'acct-a', 'opus', 'working', '12m'):
            self.assertIn(cell, row)
        self.assertTrue(row.endswith('  a feature'), row)   # what is last, never padded

    def test_dead_pid_is_named_in_flight(self):
        self.launch('spec-f-0001')
        text = self.render(alive=lambda pid: False)
        row = [ln for ln in text.split('\n') if ln.startswith('spec-f-0001')][0]
        self.assertIn('dead pid', row)

    def test_columns_pad_to_the_widest_cell(self):
        self.launch('spec-f-0001')
        self.launch('fix-b-0002-a-long-job-name', item='B-0002', kind='fix-bug',
                    started='2026-09-22T09:00:00Z')
        lines = [ln for ln in self.render().split('\n') if ln.startswith(('job', 'spec-', 'fix-'))]
        off = lines[0].index('item')                          # the header's column offset
        self.assertEqual([ln[off:off + 6] for ln in lines[1:]], ['B-0002', 'F-0001'])
        self.assertEqual(lines[1].split()[0], 'fix-b-0002-a-long-job-name')  # oldest first

    def test_unknown_item_and_missing_index_render_a_dash(self):
        self.launch('task-t-0009', item='T-0009', kind='task')
        row = [ln for ln in self.render().split('\n') if ln.startswith('task-t-0009')][0]
        self.assertTrue(row.endswith('  —'), row)
        os.remove(os.path.join(shadow.record_dir(self.product), 'index.json'))
        row = [ln for ln in self.render().split('\n') if ln.startswith('task-t-0009')][0]
        self.assertTrue(row.endswith('  —'), row)


class DoneTests(SummaryTestCase):
    def test_ended_in_the_window_is_done_with_result_and_took(self):
        self.launch('fix-b-0002', item='B-0002', kind='fix-bug', started='2026-09-22T11:00:00Z')
        pool_mod.update_session(self.product, 'fix-b-0002', ended='2026-09-22T11:41:00Z',
                                end_reason='finished', rc=0)
        pool_mod.update_session(self.product, 'fix-b-0002', harvested='d9a1df0abcdef')
        text = self.render()
        self.assertIn('IN FLIGHT — none', text)
        self.assertIn('DONE since 2026-09-21T12:00:00Z — 1 session', text)
        row = [ln for ln in text.split('\n') if ln.startswith('fix-b-0002')][0]
        self.assertIn('finished, landed d9a1df0', row)
        self.assertIn('  41m  ', row)
        self.assertTrue(row.endswith('  a bug'), row)

    def test_failed_and_dead_results_are_the_ledgers_words(self):
        self.launch('a', started='2026-09-22T11:00:00Z')
        self.launch('b', started='2026-09-22T11:00:00Z')
        pool_mod.update_session(self.product, 'a', ended='2026-09-22T11:30:00Z',
                                end_reason='failed: rate-limit')
        pool_mod.update_session(self.product, 'b', ended='2026-09-22T11:31:00Z', end_reason='dead pid')
        text = self.render()
        self.assertIn('failed: rate-limit', text)
        self.assertIn('dead pid', text)
        self.assertNotIn('landed', text)

    def test_window_is_since_the_previous_stamp_half_open(self):
        summary.write_stamp(self.product, 'all', '2026-09-22T11:30:00Z')
        for job, ended in (('old', '2026-09-22T11:30:00Z'), ('edge', '2026-09-22T11:30:01Z'),
                           ('new', '2026-09-22T11:59:00Z'), ('now', NOW)):
            self.launch(job, started='2026-09-22T11:00:00Z')
            pool_mod.update_session(self.product, job, ended=ended, end_reason='finished')
        text = self.render()
        self.assertIn('DONE since 2026-09-22T11:30:00Z — 3 sessions', text)
        self.assertNotIn('(first tick', text)
        jobs = [ln.split()[0] for ln in text.split('\n') if ln.startswith(('old', 'edge', 'new', 'now'))]
        self.assertEqual(jobs, ['edge', 'new', 'now'])         # oldest first, `old` excluded

    def test_a_relaunched_job_reports_its_ended_run_and_stays_in_flight(self):
        # B-0041: a launch line opens a NEW run; the ended run before it is still a session that
        # finished in this window. `pool.load_sessions` is `lifecycle.latest` and would drop it.
        self.launch('spec-f-0001', started='2026-09-22T11:00:00Z')
        pool_mod.update_session(self.product, 'spec-f-0001', ended='2026-09-22T11:20:00Z',
                                end_reason='failed: rate-limit')
        self.launch('spec-f-0001', started='2026-09-22T11:48:00Z')   # relaunched, still running
        text = self.render()
        self.assertIn('IN FLIGHT — 1 session', text)
        self.assertIn('DONE since 2026-09-21T12:00:00Z — 1 session', text)
        done = text.split('DONE')[1]
        self.assertIn('failed: rate-limit', done)
        self.assertIn('  20m  ', done)
        inflight = text.split('DONE')[0]
        self.assertIn('working', inflight)
        self.assertNotIn('failed', inflight)      # the ended run is not in flight

    def test_stamp_is_written_as_now_after_the_tables(self):
        self.render(chosen=['record'])
        self.assertEqual(summary.read_stamp(self.product, 'record'), NOW)
        self.assertIsNone(summary.read_stamp(self.product, 'all'))
        with open(summary.stamp_path(self.product, 'record')) as f:
            self.assertEqual(f.read(), NOW + '\n')

    def test_each_clock_has_its_own_window(self):
        self.launch('a', started='2026-09-22T11:00:00Z')
        pool_mod.update_session(self.product, 'a', ended='2026-09-22T11:50:00Z', end_reason='finished')
        self.assertIn('— 1 session', self.render(chosen=['record']).split('DONE')[1])
        self.assertIn('— 1 session', self.render(chosen=['health', 'wave']).split('DONE')[1])
        self.assertIn('— none', self.render(chosen=['record']).split('DONE')[1])


class ClockTests(unittest.TestCase):
    def test_clock_slug_matches_the_schedulers(self):
        from asf import scheduler
        self.assertEqual(summary.clock(None), 'all')
        self.assertEqual(summary.clock(['health', 'wave']), scheduler.steps_slug(['health', 'wave']))
        self.assertEqual(summary.clock(['daily']), 'daily')

    def test_age_buckets(self):
        self.assertEqual(summary.age('2026-09-22T11:59:30Z', NOW), '<1m')
        self.assertEqual(summary.age('2026-09-22T11:48:00Z', NOW), '12m')
        self.assertEqual(summary.age('2026-09-22T10:57:00Z', NOW), '1h03m')
        self.assertEqual(summary.age('2026-09-20T08:00:00Z', NOW), '2d04h')
        self.assertEqual(summary.age(None, NOW), '?')
        self.assertEqual(summary.age('yesterday', NOW), '?')


class FailureTests(SummaryTestCase):
    def test_a_render_failure_is_one_line_and_the_stamp_is_kept(self):
        summary.write_stamp(self.product, 'all', '2026-09-22T11:30:00Z')
        # NOT a directory in place of the ledger: `lifecycle.read_lines` returns [] for a path
        # that is not a file, so that renders two empty tables and is no failure at all.
        lines = []
        with mock.patch.object(summary, 'render', side_effect=ValueError('boom')):
            summary.run(_ctx(self.product), None, out=lines.append, now=NOW)
        self.assertEqual(len(lines), 1, lines)
        self.assertEqual(lines[0], 'tick: summary not rendered (boom)')
        self.assertEqual(summary.read_stamp(self.product, 'all'), '2026-09-22T11:30:00Z')

    def test_an_unreadable_ledger_is_survived_not_raised(self):
        with mock.patch.object(summary.lifecycle, 'runs', side_effect=OSError('nope')):
            lines = []
            summary.run(_ctx(self.product), None, out=lines.append, now=NOW)
        self.assertEqual(len(lines), 1, lines)
        self.assertTrue(lines[0].startswith('tick: summary not rendered ('), lines[0])
```

The tick-level tests, added to `tests/test_tick.py` (the `TickTestCase` fixture: a temp home, a
bare origin, `run_step0` faked):

```python
from asf.tick import summary   # joins the file's imports


class SummaryTests(TickTestCase):
    def test_every_tick_ends_with_the_two_tables(self):
        rc, out = self.run_tick(steps='record')
        self.assertEqual(rc, 0)
        lines = out.rstrip('\n').split('\n')
        self.assertEqual(lines[0], f'tick: state committed and pushed ({self.record_path()})')
        self.assertEqual(lines[1:3], ['', 'IN FLIGHT — none'])
        self.assertTrue(lines[-1].startswith('DONE since '), lines[-1])
        self.assertTrue(lines[-1].endswith('— none (first tick on this clock)'), lines[-1])
        self.assertTrue(os.path.exists(summary.stamp_path(env.load_product('sample'), 'record')))

    def test_a_tick_with_every_step_off_still_prints_the_tables(self):
        self.write_product('steps:\n  batch: off\n')
        rc, out = self.run_tick(steps='batch')
        self.assertEqual(rc, 0)
        self.assertEqual(out.split('\n')[0], 'tick: step batch off (another job runs it)')
        self.assertIn('\nIN FLIGHT — none\n', out)
        self.assertIn('\nDONE since ', out)

    def test_shadow_and_manifest_print_no_tables(self):
        with mock.patch.object(tick, 'render_tables', return_value={}):
            _, out = self.run_tick(shadow=True)
        self.assertNotIn('IN FLIGHT', out)
        _, out = self.run_tick(manifest=True)
        self.assertNotIn('IN FLIGHT', out)

    def test_a_summary_failure_never_changes_the_rc(self):
        with mock.patch.object(summary, 'render', side_effect=ValueError('boom')):
            rc, out = self.run_tick(steps='record')
        self.assertEqual(rc, 0)
        self.assertEqual(out.rstrip('\n').split('\n')[-1], 'tick: summary not rendered (boom)')
```

## 4. Records

What the change writes, and where:

| what | where | when | who reads it |
| --- | --- | --- | --- |
| The two tables | the tick's stdout → `<ASF_HOME>/logs/tick-<product>-<clock>.log` under the scheduler | the end of every tick that reached its steps loop | the operator |
| `summary-<clock>.stamp` — one line, the ISO `now` of the last summary on that clock | `~/.ASF/state/<product>/` (next to `daily.stamp`) | after the tables print, never on a render failure | the next tick on the same clock, nothing else |
| `tick: summary not rendered (<why>)` | the tick's stdout, in place of the tables | a render or stamp failure | the operator |

Nothing is written to the record clone: no event, no `metrics/ticks` field, no table file. The
ledger is read, never written. Nothing new is committed or pushed by the tick.
