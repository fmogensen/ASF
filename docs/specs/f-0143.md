# F-0143 — the rule the suite enforces, instead of the four tests that were fixed

review-b-0111 failed with `hook refused`: a `pre-commit` naming a hardcoded `/x/asf` — the fixture
path from `tests/test_check_staged.py` — sat in a hooks dir a worker's commit ran. `/x/asf` does not
exist, so every commit through that dir was refused until the hooks were clean again at 17:15. The
card asks for two things: **tests that install hooks must only write into their own git-init'd temp
repo**, and **`ensure_git_hooks` must refuse a `which()` path that doesn't exist**.

The second clause is already in the tree, and so is the first — *for the four tests that existed when
it was written*. All of it landed as one unrecorded hotfix, `3d0d0bb8d`, three days before this spec
(P1–P7). What is **not** in the tree is anything that makes the first clause hold for a test nobody
has written yet:

- **Nothing stops the next one.** Four suite sites resolve a hooks dir today and all four pass a temp
  repo (P8) — because someone edited them, one by one. Fourteen test files write a `pre-commit` or
  `pre-push` file (P9). A fifth site added tomorrow, on a repo that is not temp, reintroduces
  review-b-0111 exactly; the suite goes green and the damage shows up in a worker's commit.
- **The landed refusal does not cover the mechanism that caused it.** `runnable_asf` refuses what
  *asf* writes (P1–P3). review-b-0111's hook was written by the **test**, with a bare `open(...,'w')`
  (`tests/test_check_staged.py:372`, still there and still `/x/asf`), into a dir `git_hooks_dir`
  resolved. No refusal inside `asf.hooks` can see that write. What saved it was the other half of the
  hotfix — dropping the leaked `GIT_DIR` (P4, P5) — and that half is a fix for one cause, not a rail.
- **The blast radius is shared, and it is not `.git/hooks`.** A factory host sets `core.hooksPath`,
  so `git rev-parse --git-path hooks` answers with the factory's own hook dir — one directory, shared
  by every worktree and every lane. That is why a single fixture file refused another session's
  commit, and why "only into its own temp repo" is a rail worth having rather than four careful edits.

So this card delivers the **confine**: a root the suite names, outside which `asf.hooks` will not hand
back a hooks dir at all. Plus the two things that keep a rail honest — the twins cannot install it in
one entry point only, and a write that never went through `git_hooks_dir` still turns the run red.

### In

- **A confine on where a hooks dir may resolve.** `ASF_HOOKS_CONFINE` names an absolute root.
  When it is set, `hooks.git_hooks_dir(repo)` raises `HookDirOutsideConfine` instead of returning a
  directory whose realpath is not under that root, naming the repo asked for, the dir git answered
  with, and the root. Unset — every operator install, every real `asf hooks install` — it changes
  nothing: one comparison, one branch, no new behaviour.
- **Both suite twins set it to the temp root**, beside the variables they already set (P5, P21), so
  it holds for `discover -s tests`, `discover -t .` and `python -m unittest tests.<mod>` alike — and,
  because it is an environment variable in `gate` mode (P11), inside every `asf` subprocess a test
  starts, which a monkeypatch could never reach (P10).
- **The twins cannot drift.** `tests/test_hermetic.py`'s both-entry-points proof (P17) gains the
  confine as a fourth thing it reads out of the child, so installing it in one twin only is red.
- **A backstop for the writes the confine cannot see.** `tools/run_tests.py` records a digest of
  every at-risk hooks dir before the pool and re-reads it after: a file added, changed or removed
  makes the run `FAILED`, naming the dir and the file. "At-risk" is what the checkout itself resolves
  to — `git rev-parse --git-path hooks` and, when the repo sets one, `core.hooksPath` — never a path
  written into this document.
- **A regression case for the original defect**, run through the confine: the fixture at
  `tests/test_check_staged.py:365-386` — a hand-written `pre-commit` naming `/x/asf`, in a temp repo —
  stays green, and the same fixture pointed at a non-temp repo is refused.

### Out

- **Re-doing `3d0d0bb8d`.** `runnable_asf`, the `GIT_HOOK` strip in `git_hooks_dir`, the twins'
  variable drops and the four moved tests are P1–P6 and are not touched. The card's second clause is
  satisfied in the tree; this spec says so and moves on.
- **Deleting `/x/asf` from the fixture.** It is the *right* fixture — a hook naming an `asf` that is
  not there is what that test is about, and `tests/test_install.py:1287-1306` needs bad paths too.
  The defect was never the string; it was the directory it landed in.
- **An AST or grep fence over `tests/`.** Fourteen files write hook files (P9) and the paths are
  built every way Python allows. A fence would be an allow-list that rots, and it would still miss
  the one thing that actually went wrong — a dir that *git* resolved somewhere unexpected.
- **Confining anything but the hooks dir.** A general "the suite writes only under tmp" rail is a
  much larger card (every state dir, every log, every clone) and would need an exemption list on day
  one. This confines the one resolution whose blast radius is another session's commit.
- **Making the confine an operator-facing feature.** No `products.yaml` key, no CLI flag, no guide
  row: it is a suite rail like `ASF_HOST_READING` (P21), documented where it is set and read.
- **Reaching a `worker`-mode subprocess** (D8). `hermetic.build(mode='worker')` strips the variable
  (P11) and this card does not add it to `WORKER_ALLOW`.
- **Repairing a hooks dir the backstop finds dirty.** It reports and reddens; removing another
  process's hook file unasked is worse than the report.
- **A doctor row, a metrics event or an invariant over any of this.** The rail's audience is the
  suite and CI, which already have a verdict channel: a red run.

## The design

### `asf/hermetic.py` — the variable, and the one function that reads it

Beside the other suite-wide rules (`CALLER_IDENTITY`, `GIT_HOOK`, `GIT_CONFIG_NOT_INHERITED`), so both
twins and `asf/hooks.py` have one owner for it (D7):

```python
#: The suite's hooks-dir confine (F-0143): an absolute root outside which
#: :func:`asf.hooks.git_hooks_dir` refuses to resolve. Set by both suite entry points to the temp
#: root; **unset in every operator install**, where the branch it drives is one comparison that
#: never fires.
#:
#: review-b-0111: a fixture ``pre-commit`` naming a nonexistent ``/x/asf`` reached a hooks dir a
#: worker's commit ran, and refused it. On a factory host ``core.hooksPath`` makes that one
#: directory shared by every worktree and every lane, so a single stray file stops other sessions.
#: The four tests that caused it were fixed one by one (``3d0d0bb8d``); this is the rail that makes
#: the fifth impossible, and it constrains the *resolution* because a hand-built path cannot fake
#: that step (D1).
#:
#: It is an environment variable, not a monkeypatch, because the tests most likely to install hooks
#: run ``asf`` as a subprocess and only the environment crosses that boundary (D2). ``gate`` mode
#: carries it; ``worker`` mode strips it with every other unlisted name, and stays unconfined (D8).
HOOKS_CONFINE = 'ASF_HOOKS_CONFINE'


def hooks_confine(env=None):
    """The confine root in ``env`` (default the process's), ``realpath``'d — or None when unset.

    Resolved, because the temp root is reached through a symlink on some platforms while
    ``mkdtemp`` hands back the unresolved form: comparing raw strings passes by luck and refuses a
    legitimate temp repo the moment either side is resolved (D4)."""
    root = (os.environ if env is None else env).get(HOOKS_CONFINE)
    return os.path.realpath(root) if root else None


def confine_hooks_to_temp(env=None):
    """Point :data:`HOOKS_CONFINE` at the temp root, and return it. Called by **both** suite entry
    points — ``tests/__init__.py`` and its twin ``tests/test_00_home.py``, which cannot import each
    other (D6, D7). ``tests/test_hermetic.py`` proves neither is missing it."""
    env = os.environ if env is None else env
    env[HOOKS_CONFINE] = tempfile.gettempdir()
    return env[HOOKS_CONFINE]
```

`tempfile` joins the module's imports (`os`, `re` today).

### `asf/hooks.py` — the refusal, at the one resolution

One exception, and four lines inside the existing function. The `from asf import hermetic` at
`asf/hooks.py:76` is already there for the `GIT_HOOK` strip, so nothing new is imported:

```python
class HookDirOutsideConfine(RuntimeError):
    """:func:`git_hooks_dir` resolved a hooks directory outside :data:`asf.hermetic.HOOKS_CONFINE`.

    Raised only when that variable is set — the suite, never an operator install (F-0143). It is
    raised rather than returned as None because None already means *not a git repo*: a caller would
    report ``is not a git repo`` for a repo that plainly is, and a caller that only reads the
    directory would not notice at all (D3)."""
```

and, at the tail of `git_hooks_dir`, replacing its single `return`:

```python
    out = p.stdout.strip()
    out = out if os.path.isabs(out) else os.path.join(repo, out)
    # F-0143: under the suite's confine, a hooks dir that resolves outside the temp root is the
    # defect review-b-0111 was — a fixture's hook in a directory another session's commit runs.
    # git answers here, not the caller: `core.hooksPath` can point anywhere, so the repo being a
    # temp one is not enough. The offending test fails at its own line, with all three paths.
    confine = hermetic.hooks_confine()
    if confine and not os.path.realpath(out).startswith(confine + os.sep):
        raise HookDirOutsideConfine(
            f'{out} is outside {confine} — git resolved it for {repo}. A test installs hooks only '
            f'into its own git-init\'d temp repo: a hook left anywhere else is run by every commit '
            f'in that repo (review-b-0111). See tests/gitfixture.py:executable_asf.')
    return out
```

`git_hooks_dir`'s docstring gains the one sentence that narrows P19: *"Raises
:class:`HookDirOutsideConfine` when :data:`asf.hermetic.HOOKS_CONFINE` is set and the answer falls
outside it — the suite only."*

The `+ os.sep` matters: the root itself is not a repo's hooks dir, and a sibling directory whose name
merely starts with the root's must not pass.

### `tools/run_tests.py` — the backstop

Three additions. The at-risk dirs, resolved from the checkout so no path is written down (D11):

```python
def hook_dirs(root):
    """Every hooks directory a suite run could damage, resolved from ``root`` itself: what
    ``git rev-parse --git-path hooks`` answers, plus ``core.hooksPath`` when the repo sets one (on a
    factory host that is a directory shared by every worktree, which is why one stray fixture hook
    refuses another session's commits — review-b-0111). Resolved, never configured: the path is
    machine-specific and belongs in no tracked file. ``root`` is **``run``'s own** (``root, package =
    os.path.split(tests_dir)``, `tools/run_tests.py:155`), never the module-level ``ROOT``: the
    runner's own tests drive ``run`` over a fixture ``tests/`` dir, and a check rooted at the real
    checkout would digest the host's live hooks during them — reading another session's writes as
    this run's leak, and reaching outside the fixture besides. A fixture root is not a git repo, so
    its digest is empty and the check is inert there, which is what lets the unit cases below drive
    ``hook_leaks`` directly."""


def hook_digest(dirs):
    """``{path: {name: sha256}}`` for each of ``dirs`` that exists — one digest per file, so an
    overwritten hook is caught and not just an added one (D10)."""


def hook_leaks(before, after):
    """The lines naming every hook file added, changed or removed between two digests; empty when
    the run left them all byte-identical."""
```

and in the runner's exit path, folded into the one line that owns the status (P15):

```python
    leaks = hook_leaks(before, hook_digest(dirs))
    for line in leaks:
        out(f'hook leak: {line}')
    if leaks:
        out('FAILED (hook files changed outside a temp repo — F-0143)')
    return 0 if not leaks and all(rc == 0 and parse(o)[2] == 'OK' for _m, rc, o in results) else 1
```

The confine (S-34600) is the rail; this is the net under it, for a write that never asked git where
the hooks dir was.

## Acceptance tests

Each block is runnable in this checkout, from the repo root.
