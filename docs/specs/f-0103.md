# F-0103 — the factory reads its own ledger

On 2026-09-23 a harvest ledger that never closed held the wave for hours. The wave printed
`wave: nothing to launch` tick after tick; New Tasks sat in the record the whole time; nothing
filed anything. The failures of that day — *not pushed*, *empty branch*, *dead pid*, the stuck
ledger — were found by an operator's assistant reading `metrics/ticks` and the session ledger by
hand.

`asf file-bugs` already is the learning loop. It runs inside the tick's `record` step (step 0,
before `wave` — `steps.STEPS` is `record, health, wave, prs, harvest, batch, daily`) and files or
bumps a Bug keyed on the typed `signature` field from three sources: CI failures seen twice in
24 h, files refused twice, and every current rule violation. All three read the record clone
under `metrics/`. None of them reads the two streams that describe the factory itself:

| Stream | What it already holds | What nothing reads it for |
| --- | --- | --- |
| `metrics/sessions/<day>.jsonl` | one line per ended session: `ts`, `task`, `item`, `branch`, `kind`, `result` (the run's `end_reason`) | how often a session ends badly, and whether one item ends badly the same way twice |
| `metrics/ticks/<day>.jsonl` | one line per tick: `tick`, `launches`, `merges`, `stalls`, `refusals`, `refused_files`, `steps` | `launches: 0` does not say *why* — whether the wave had nothing to launch, and what held the rows it did not launch |

This spec adds three sources to `file-bugs` over those two streams, and adds to the tick line the
one fact the wave knows and nothing else does: what held it.

## 1. Decisions

### 1.1 Preconditions

- `metrics/sessions` is written every tick from the factory's own bookkeeping
  (`metrics.sessions_from_registry`, the registry `~/.ASF/state/<p>/sessions.jsonl` plus each
  job's log) and carries `result` = the run's `end_reason` verbatim. This spec reads it; it does
  not change how it is written.
- `lifecycle` already owns the `end_reason` vocabulary: `FINISHED`, `DEAD_PID`,
  `PUSHED_AFTER_STOP`, `EMPTY_BRANCH`, `push_gap()`'s `not pushed: …`, and
  `runtime.failure_reason`'s four CLI signatures (`unknown model`, `auth`, `quota`,
  `permission`) plus `report.UNPUSHED`.
- `file_bugs._file_or_bump_bug` already gives "same signature = same Bug", a `last_filed`
  guard that makes a second same-day run a no-op, and a `count` bump with one History line.
  Every trigger here is a `signature` and rides that machinery unchanged.
- `feeder.rows.Row` already carries `waits_on` (the gate id, or `trunk` / `operator` /
  `reshape` / `confirm`) beside the `WAITS ON …` action text. The wave does not need to
  re-derive a gate; it needs to write down the one the feeder already computed.
- `approvals` already gates the whole command through the `file_bug` class; the tick passes
  `file_bug_level` into `cmd_file_bugs`.

### 1.2 In

- **`asf.workers.lifecycle.outcome_class(result)`** — the one function that turns an
  `end_reason` string into one of `OUTCOME_CLASSES`, beside the constants it names. `None` for a
  line that describes no outcome (`running`, `unknown`, empty).
- **`asf.conventions`** — four typed fields with documented defaults: `outcome_share_pct` (10),
  `outcome_min_sessions` (20), `repeat_failure_n` (2), `idle_wave_ticks` (6).
- **`asf.tick.file_bugs`** — three new signature sources, each pure over the stream it reads:
  `outcome_signatures`, `repeat_signatures`, `idle_wave_signatures`; and a `found_in` key per
  source, so a Bug found in the factory's own runs does not claim it was found in CI.
- **`asf.tick.step_wave.wave_state(planned, held, items)`** — a pure function returning what
  held this wave; `run` sets it on the context.
- **`asf.tick.tick.Context.wave`** and **`tick_line`** — the tick line gains a `wave` key.
- **`asf.metrics.metrics.SCHEMAS['ticks']`** — `wave` as a `dict` key, default `{}`, so
  `asf metrics append ticks` accepts a line the tick writes.
- Tests for each trigger (§3.2–§3.5), for the vocabulary (§3.1) and for the daily guard (§3.6).

### 1.3 Out

- **A new stream, a new state file, a new card field.** Everything read here is already
  written; everything written is a Bug card and one key on a line that already exists.
- **Reading the registry or the job logs directly.** `file-bugs` runs against the record clone
  and reads `metrics/` only. `~/.ASF/state` is not its to read, and the record clone is what a
  test can build.
- **A rollup row or table.** The card asks for Bugs, not a report. F-0101 is already rewriting
  the waste table; a row here would collide with it for no acceptance.
- **Acting on the Bug.** Filing is the whole job. The Bug enters the pipeline as any other does:
  an `S2` is `decided: true` and goes to FIX at once (B-0089), an `S3` waits for the groom.
- **Escalation.** A signature bumped ten times is the same Bug with `count: 10`; its severity is
  not raised and no second Bug is filed. The count is the escalation.
- **A fourth `found_in` value.** The vocabulary in use is `ci`, `prod`, `dev`
  (`groom.inbox`, `tick.migrate`); nothing validates a fourth, so nothing invents one. A Bug
  from the factory's own runs is `dev`.
- **Re-classifying the 3 sources already there.** `ci_signatures`, `refusal_signatures` and
  `rule_violation_signatures` keep filing `found_in: ci` exactly as today.
- **Naming a culprit.** A Bug says what the ledger shows — the class, the rate, the item, the
  gate — and never why. The fix session reads the evidence lines and decides.

### 1.4 The choices

| Choice | Against | Why |
| --- | --- | --- |
| The streams under `metrics/` are the source | the session registry and job logs under `~/.ASF/state` | `file-bugs` is given a `root` and reads nothing else; a hermetic test writes three JSONL lines instead of a fake home. The streams already carry every field needed. |
| `outcome_class` lives in `lifecycle` | in `file_bugs`, or in `metrics` | `lifecycle` writes those strings (`judge`, `push_gap`, `EMPTY_BRANCH`); a reader that re-parses them elsewhere drifts the day `judge` changes a word. One owner, and `file_bugs` imports it. |
| A rate needs a floor (`outcome_min_sessions`) as well as a share | the share alone | 1 bad session out of 2 on a quiet night is 50 % and means nothing. Below the floor no rate is computed at all. |
| The wave writes its gates onto the tick line | `file-bugs` re-running `feeder.plan_rows` itself | the feeder needs the product, the ledger's in-flight sessions and the repo's trunk shas — none of which `file-bugs` has, and all of which would be *now* rather than at the tick that was idle. The wave already knows; it just never said. |
| The streak is the trailing run of tick lines | a counter in state | the stream is the memory, it is committed with the tick, and a line written before this change (no `wave` key) breaks the streak instead of being guessed at. |
| The gate named is the one holding the most items | every gate | one Bug per gate class per streak is noise; the Bug names the majority gate in its title and lists them all in its body. |
| `S2` for the rate and the stalled wave, `S3` for the repeat | all `S2`, or all `S3` | the first two are the factory as a whole losing sessions or stopping; they should not wait for a groom. One Task failing twice is one Task. |
| The window is 24 h, as the card says | the 7 days the rollup uses | a rate over a week hides a bad day and files late. The card names 24 h; `CI_REFUSAL_WINDOW_H` is already 24 for the same reason. |

## 2. The design

### 2.1 The outcome vocabulary — `asf/workers/lifecycle.py`

Beside `FINISHED` / `DEAD_PID` / `EMPTY_BRANCH` / `PUSHED_AFTER_STOP`:

```python
#: Every class a session's `end_reason` falls into. `finished` is the only one that is not a
#: failure; `other` is a failure whose signature this module does not name.
OUTCOME_CLASSES = ('finished', 'not pushed', 'empty branch', 'dead pid', 'pushed after stop',
                   'unpushed work', 'unknown model', 'auth', 'quota', 'permission', 'other')
FAILING_CLASSES = tuple(c for c in OUTCOME_CLASSES if c != FINISHED)


def outcome_class(result):
    """The class of an ``end_reason`` (the `sessions` stream's ``result``), or None when the
    line describes no outcome — ``running``, ``unknown``, empty. Pure: no clock, no io."""
```

The rules, in order: empty / `running` / `unknown` → `None`; `finished` → `finished`;
`dead pid` → `dead pid`; otherwise strip a leading `failed: ` (a bare `failed` → `other`) and
match the rest — `not pushed…` (the `push_gap` text carries counts) by prefix, `empty branch…`
by prefix, and the remaining names exactly; anything else → `other`. Case-insensitive, stripped.

### 2.2 The thresholds — `asf/conventions.py`

Four fields beside `prs_per_tick`, each with a module-level `DEFAULT_*` and a doc comment, and
named in the `conventions:` example in the module docstring:

```yaml
conventions:
  outcome_share_pct: 10       # a failing outcome class over this share of 24 h files a Bug
  outcome_min_sessions: 20    # no rate below this many ended sessions in the window
  repeat_failure_n: 2         # the same item, the same class, this many times → a Bug
  idle_wave_ticks: 6          # consecutive idle waves with New Tasks → a Bug
```

`file_bugs._conventions(args)` already resolves them, falling back to `DEFAULTS`.

### 2.3 What the wave writes down — `asf/tick/step_wave.py`, `asf/tick/tick.py`

```python
GATE_CAP = 10           #: New Task ids named on the tick line, most starved first
NO_ROW = 'no row planned'


def wave_state(planned, held, items, launching=0):
    """What this wave did and what held it — the tick line's ``wave`` key. Pure.

    ``{'idle': bool, 'new_tasks': int, 'new_task_ids': [...], 'gates': {gate: items}}``

    ``idle`` is true when no row launched. ``new_tasks`` counts the record's New Tasks —
    the work that exists and did not start. A gate is a non-launching row's ``waits_on``, else
    the first word of its action; a row held by an approval class is ``held <class>``; when no
    row was planned at all the single gate is ``no row planned``.
    """
```

`run` collects the held and non-launching rows it already iterates, and before each return sets
`ctx.wave = wave_state(planned, held, items, launching=len(worker_rows))`. The `out()` lines it
prints are unchanged, `wave: nothing to launch` included.

`Context.__init__` gains `self.wave = {}` beside `self.counts`, and `tick_line` carries it:

```python
return dict(ctx.counts, ts=…, tick=…, duration_s=…, quota={}, refused_files={},
            wave=ctx.wave, product=ctx.product.name, steps=ran)
```

A tick whose `wave` step never ran (`--steps record`) writes `wave: {}` — no `idle` key, and
§2.6 treats it as a break in the streak, not as an idle wave.

`SCHEMAS['ticks']` gains `'wave': (('dict',), {})`.

### 2.4 The rate — `file_bugs.outcome_signatures(root, now, conv)`

Reads `metrics/sessions/*.jsonl` through the existing `_jsonl_lines`, keeps lines inside
`SESSION_WINDOW_H = 24` of `now` (`stale.parse_iso` on `ts`, as the other sources do), and
classifies each `result` through `lifecycle.outcome_class`. Lines classed `None` are dropped
from numerator **and** denominator. With `total >= conv.outcome_min_sessions`, every failing
class whose share is **strictly over** `conv.outcome_share_pct` yields:

```
signature: outcome: not pushed
title:     14 % of sessions end "not pushed" (threshold 10 %, 7 of 49 in 24h)
severity:  S2
found_in:  dev
evidence:  one line per session, newest last —
           2026-09-23T14:02:00Z spec-f-0096 (F-0096) on spec/F-0096: failed: not pushed:
           2 uncommitted file(s), 1 unpushed commit(s)
```

The signature carries the class and nothing else: the rate moves every tick, the Bug must not.
Evidence is capped at `EVIDENCE_CAP = 20` lines, newest kept.

### 2.5 The repeat — `file_bugs.repeat_signatures(root, now, conv)`

The same window and the same classification, grouped by `(key, class)` where `key` is the
event's `item` when it has one, else its `task` (the job name). A group of at least
`conv.repeat_failure_n` failing events:

```
signature: repeat: T-0091: dead pid
title:     T-0091 has ended "dead pid" 3 times in 24h
severity:  S3
found_in:  dev
links:     {}                      # runs are a CI notion; a session names its job in the body
evidence:  one line per event: ts, job, branch, the verbatim result
```

Both the item and the class are in the signature, so the same Task failing two different ways is
two Bugs, and a Task that comes back tomorrow with the same failure bumps the same one.

### 2.6 The stalled wave — `file_bugs.idle_wave_signatures(root, canonical, conv)`

Reads `metrics/ticks/*.jsonl` in stream order (`_jsonl_lines` sorts by day file; lines within a
file are appended in tick order) and walks it backwards, counting the trailing run of lines where
`line['wave']['idle']` is true **and** `line['wave']['new_tasks'] > 0`. Any other line — a
launching wave, a tick with no `wave` key, a tick whose wave was idle with no New Tasks — ends
the run. A run of at least `conv.idle_wave_ticks`:

```
signature: wave idle: T-0044
title:     7 ticks launched nothing while 12 New Tasks wait on T-0044 (Closed)
severity:  S2
found_in:  dev
evidence:  one line per tick in the streak, oldest first —
           tick 1420 (2026-09-23T14:20:03Z): nothing to launch, 12 New Tasks,
             gates: T-0044 ×9, trunk ×2, held merge_pr ×1
           …
           New Tasks held: T-0051 T-0052 T-0053 …
```

The gate named is the one holding the most items summed over the streak (ties → lowest key), and
the title says what the record now holds for it — `canonical` is already loaded by
`cmd_file_bugs`, so a gate id that resolves to an item is printed with its `state`, which is how
the 2026-09-23 case reads itself back: `waits on T-0044 (Closed)`. A gate that is not an id
(`trunk`, `operator`, `no row planned`, `held <class>`) is printed as it stands.

### 2.7 The wiring — `file_bugs.cmd_file_bugs`

```python
signatures.update(ci_signatures(root, now, conv))
signatures.update(refusal_signatures(root, now))
signatures.update(rule_violation_signatures(root))
signatures.update(outcome_signatures(root, now, conv))
signatures.update(repeat_signatures(root, now, conv))
signatures.update(idle_wave_signatures(root, canonical, conv))
```

`_file_or_bump_bug` takes `found_in` off the info dict (`info.get('found_in', 'ci')`), leaving
the three existing sources byte-identical. Everything else is untouched: the `last_filed` guard
still makes a second run of the same day a no-op, the `file_bug` approval level still prints
`held file_bug on <sig>` for every new signature instead of filing, and the summary line stays
`file-bugs: N filed, M bumped, K unchanged`.

## 3. Acceptance tests

From the repository root, stdlib only, hermetic. The whole suite must stay green:

```bash
cd "$(git rev-parse --show-toplevel)"
python3 tools/run_tests.py
```

**T1 — the vocabulary has one owner.** `lifecycle.outcome_class` maps `finished` → `finished`,
`dead pid` → `dead pid`, `lifecycle.push_gap(ev)` prefixed with `failed: ` → `not pushed`,
`failed: {EMPTY_BRANCH}` → `empty branch`, `failed: quota` → `quota`, `failed: unpushed work` →
`unpushed work`, `failed: something nobody named` → `other`, bare `failed` → `other`, and
`running` / `unknown` / `''` / `None` → `None`. Every string `judge` can return classes to a
member of `OUTCOME_CLASSES`, and `FAILING_CLASSES` excludes `finished` only.

```bash
python3 -m unittest -v tests.test_lifecycle.OutcomeClassTests
```

**T2 — the thresholds are product config.** `Conventions()` gives 10, 20, 2, 6;
`Conventions.from_mapping({'outcome_share_pct': 25, 'idle_wave_ticks': 3})` overrides those two,
keeps the other two at their defaults, and leaves `extra` empty (they are typed fields, not
survivors); `conv.get('repeat_failure_n')` reads as the attribute does.

```bash
python3 -m unittest -v tests.test_conventions.SelfBugThresholdTests
```

**T3 — an outcome class over its share files one Bug.** A record with 49 session events inside
24 h, 7 of them `failed: not pushed: …`: one Bug is filed, `signature: outcome: not pushed`,
`severity: S2`, `found_in: dev`, the title carrying `14 %` and the threshold, at most 20 evidence
lines. The same run with 4 such events (8 %) files nothing; with 7 of 10 events (70 %, under
`outcome_min_sessions`) files nothing; an event older than 24 h counts for neither numerator nor
denominator; `result: running` lines change no percentage. A second run the same day bumps
nothing (`0 filed, 0 bumped`); a run the next day bumps `count` to 2 and appends one History
line, leaving the title as first filed.

```bash
python3 -m unittest -v tests.test_file_bugs.OutcomeRateTests
```

**T4 — the same Task failing the same way twice.** Two `dead pid` events for `T-0091` in the
window file one Bug, `signature: repeat: T-0091: dead pid`, `severity: S3`, the title naming the
Task and the result and the body both events. One event files nothing. `T-0091` failing once
`dead pid` and once `not pushed` files nothing. An event with no `item` groups on its `task`
(`spec-f-0096`) and is named by it. Raising `repeat_failure_n` to 3 turns the two-event case into
nothing filed.

```bash
python3 -m unittest -v tests.test_file_bugs.RepeatFailureTests
```

**T5 — the wave writes down what held it.** `step_wave.wave_state` over a planned list of one
`WAITS ON T-0044` row, one `ON TRUNK` row and one held row, with no launching row, returns
`idle: True`, the record's New Task count and ids (capped at 10), and
`gates: {'T-0044': 1, 'trunk': 1, 'held merge_pr': 1}`; with a launching row it returns
`idle: False`; with no planned rows at all and New Tasks present, `gates: {'no row planned': n}`.
An `asf tick --steps record,wave` over a fixture whose feeder plans nothing prints
`wave: nothing to launch` and writes a `metrics/ticks` line whose `wave.idle` is true; a tick run
as `--steps record` alone writes `wave: {}`. `metrics.validate('ticks', line, {})` accepts a line
carrying `wave` and defaults it to `{}` when absent.

```bash

```

**T6 — N idle ticks with New Tasks file a Bug naming the gate.** Six tick lines, each

file nothing. Six ticks broken in the middle by one launching tick file nothing. Six ticks with

```bash
python3 -m unittest -v tests.test_file_bugs.IdleWaveTests
```

**T7 — filed once a day, held when the approval says so, and the old sources unchanged.** One
record triggering all three new signatures plus a CI one: `file-bugs` prints `4 filed`, and a
second run the same day prints `0 filed, 0 bumped, 4 unchanged`. With
`file_bug_level='human-now'` nothing is written and one `NEEDS OPERATOR: held file_bug on …`
line is printed per signature, the new ones included. The CI, refusal and rule Bugs still carry


## 4. Records

**The tick line** (`metrics/ticks/<day>.jsonl`, in the record clone) gains one key:

```json
{"tick": 1420, "launches": 0, "merges": 0, "refusals": 0, "relaunches": 0, "stalls": 0,
 "wave": {"idle": true, "new_tasks": 12, "new_task_ids": ["T-0051", "T-0052"],
          "gates": {"T-0044": 9, "trunk": 2, "held merge_pr": 1}},
 "product": "asf", "steps": [], "duration_s": 41.2, "ts": "2026-09-23T14:20:03Z"}
```

Lines already written are unchanged and remain valid; `wave` defaults to `{}`.

**Bugs**, filed at most once a day per signature and bumped thereafter, under
`conventions.default_bug_epic`:

```yaml
type: bug
title: 14 % of sessions end "not pushed" (threshold 10 %, 7 of 49 in 24h)
severity: S2
decided: true
found_in: dev
signature: 'outcome: not pushed'
count: 1
last_filed: 2026-09-24
parent: <conventions.default_bug_epic>
```

and, with `severity: S3` / `decided: false`, `signature: 'repeat: T-0091: dead pid'`; and with
`severity: S2` / `decided: true`, `signature: 'wave idle: T-0044'`. Each body is the evidence
lines that made it, and each bump appends one line under `## History`:
`- 2026-09-25 file-bugs: count 1 → 2 (<the newest evidence line>)`.

**Not written.** No new stream, no new state file, no new field on any card. No event in
`metrics/events`. No change to the `sessions` stream, which is read and never written here.
