# F-0014 — one table shape, one stamp, and the three views the console still lacks

`asf` has 48 commands (`python3 -m asf.cli --help`) and seventeen of them print an operator table.
Those seventeen print it four different ways.

Eight open with a bold title: `**FACTORY STATUS {now}**` (`asf/views/status.py:387`),
`**BOARD {HH:MM}** — …` (`asf/views/board.py:68`), `**PARITY {now}** — …`
(`asf/views/parity.py:50`), `**ROADMAP** (index.json generated …)` (`asf/views/roadmap.py:69`),
`**SESSIONS** — …` (`asf/views/sessions.py:144`), `**NEXT** — …`
(`asf/feeder/render.py:67`), `**SCORECARD {product}** — {as_of}` (`asf/views/scorecard.py:58`),
`**RELEASE READINESS {product}** — {as_of}` (`asf/release.py:441`). Two open with the same words
and no bold at all: `CAPACITY — operator total: …` (`asf/views/capacity.py:96`) and
`TOKENS — input tokens per session, …` (`asf/views/tokens.py:96`). Five open with `== `:
`== DOCTOR {product}` (`asf/doctor.py:967`), `== SCHEDULER {product}` (`:732`),
`== CI QUEUE {name} (…)` (`asf/ci_queue.py:2879`), `== CI RECONCILE {product} ({mode})`
(`asf/ci_pool.py:1179`), `== RULES {n} checked, …` (`asf/rules/rules.py:221`). And three print no
header whatsoever: `asf stale` goes straight to its rows (`asf/tick/stale.py:144`), `asf ci
reserve` straight to `reserve_table` (`asf/ci_pool.py:1188`), and `asf prod` — which *does* have a
`**PROD**` line, but only on the branch where no deploy is configured (`asf/views/prod.py:223`);
the configured branch, the one an operator actually reads, opens with `**Prod app** \`9f1c2b0…\``
(`:244`) and never names itself.

Only five of the seventeen name the product they are about. An operator running three products reads
`**BOARD 14:22** — 12 Features` and cannot tell which.

The stamp is worse. `asf/cli.py:162` declares `stamp(command, repo=None, version=None)` —
"the line every stamped table ends with: `— generated by asf <command>@<sha> <HH:MM>`". Two
callers exist in the whole tree: `asf/doctor.py:1001` and `asf/groom/digest.py:157`. Sixteen of
the seventeen tables carry no stamp, so a table pasted into a card, a PR body or a groom answer
carries no record of which release drew it or when — which is the one thing `stamp` exists for.
No test freezes any header, and no test asserts any stamp but doctor's
(`grep -rn 'generated by asf' tests/` → `tests/test_doctor.py:954`,
`tests/test_groom_policy.py:1083`).

Three views were named and never built. `asf/views/__init__.py` — the package docstring, one line
long — says "the /asf tables (board, parity, health, ci-health, next-work)"; there is no
`health.py` and no `ci-health` anything. S-0004 carries the same three: "Remaining console views
and skills: ci, health, performance". The readers all exist and are all already written and
tested — `asf workers health`'s reconciliation (`asf/workers/health.py:305`, read-only at
`fix=False`), `asf/workers/stall.py:92`, `asf/workers/worktrees.py:405`,
`asf/record/check.py:542`'s `invariant_findings`, `asf/drift.py:109`,
`asf/ci_queue.py:2767`'s `live_line` with its snapshot fallback, `asf/ci_pool.py:860`'s `plan`,
`asf/improve/measure.py:141`'s `table` — but each is reachable only as a sub-command of an admin
verb, or (for `measure.table`) not from the command line at all: its one caller is
`asf/metrics/metrics.py:722`, which folds three of its numbers into a daily markdown file.

And the role agents have no gate. `asf/roles/roles.py:23` states the contract outright — "an
invalid role dir is a red gate and a red doctor row, never a dead wave" — but
`grep -rn 'roles.validate' asf/` finds nothing: the nine refusals at `asf/roles/roles.py:220` are
run by `tests/test_roles.py:112` and by no shipped code path. The doctor's `briefs` row
(`asf/doctor.py:783`, `check_briefs` at `:905`) renders one brief of every kind, which exercises `roles.block` and never
`validate`, so a role file over `MAX_LINES`, missing a section, or naming a forbidden word passes
`asf doctor` green and reaches a worker session.

## 1. Decisions

### 1.1 Preconditions

- **The command surface is complete and this spec adds three commands to it, not a subsystem.**
  `asf/cli.py:11`'s docstring still says the fuller set "lands with the 0.1 spec"; it landed —
  `init`, `roadmap`, `backlog`, `product` and the rest are all registered (`build_parser`,
  `:171`–`:354`). The docstring is stale and §2.6 corrects it.
- **`asf/cli.py:162` `stamp()` is the stamp and needs no change.** It already takes the product's
  `repo` for the sha and a `version` override for a table that reports on asf itself, and
  `asf/doctor.py:1000` already documents why doctor uses the second — "the doctor reports on asf's
  install, so its stamp names asf's version, not the product's HEAD". This spec adds callers, not
  a second stamp.
- **`asf/tables.py` drops `**bold**` when it redraws for a console** (`_BOLD`, `:23`; the module
  docstring, `:5`). A bold title is therefore a *markdown* convention that costs a console reader
  nothing, and `ASF_TABLES=box` — which every skill sets (`asf/plugin_build.py:60`) — strips it.
  A `== ` prefix is not stripped and shows up in a pasted markdown table as literal `==`.
- **`asf/plugin_build.py` generates the whole plugin from the CLI's own parser.**
  `command_help()` (`:64`) reads `build_parser()`'s subparser helps; `VIEWS` (`:34`) is the eleven
  commands that get a skill; `check()` (`:176`) exits 1 on any drift and `tests/test_plugin.py:41`
  runs it. A skill is one `VIEWS` entry plus a `help=` string — there is no hand-written skill
  file to add, and `test_plugin.py:94` already asserts every skill name is a registered command.
- **`tests/test_plugin.py:15` `PENDING_VIEWS` is the documented escape for a skill whose command
  has not landed, and it is empty.** Every skill this spec adds lands with its command in the same
  change, so it stays empty.
- **`asf ci`'s sub-command is required today** (`asf/ci_pool.py:1220`,
  `add_subparsers(dest='ci_command', required=True)`): bare `asf ci` is an argparse error, exit 2.
  A skill named `ci` runs `"$ASF_BIN" ci $ARGUMENTS` (`asf/plugin_build.py:60`) with no arguments,
  so the skill cannot exist until bare `asf ci` prints something (D4).
- **Every reader the three views need exists, is pure or read-only, and is tested.**
  `health.health(product, fix=False, …)` returns `[(job, what, detail)]` and writes nothing
  (`asf/workers/health.py:305`); `stall.stall` returns `[(job, STALL|DEAD, minutes)]` (`:92`);
  `worktrees.dry_run` returns verdicts (`:405`); `retention.sweep(product, fix=False)` reports
  what would go (`asf/workers/retention.py:249`); `check.invariant_findings(root, product,
  deep=False)` is what `asf check --invariants` prints (`asf/record/check.py:564`) and "never
  writes the record or the state directory"; `drift.check(product)` (`asf/drift.py:109`);
  `measure.table(runs)` is pure over `measure.ended_runs` (`asf/improve/measure.py:141`, and its
  own docstring: "touches no file and no clock").
- **`asf/ci_queue.py:2767` `live_line` already falls back to the tick's snapshot when the host is
  unreadable** (`_snapshot_clause`, `:2834`) — the `asf status` CI row is built on exactly that
  pair (`:2820`). The `ci` view reuses the pair; it does not learn to read the host itself.
- **`--json` is already the "a script reads this" contract, and `asf/cli.py:533` already routes
  the `record:` announce line to stderr for it.** A JSON mode that printed a header or a stamp on
  stdout would stop parsing, so §2.2's rule is the one already in force.
- **`asf/views/capacity.py` is the one multi-product view** (`--all`, `asf/cli.py:338`), so a
  header's product slot must accept a plain string, not a `Product`.
- **`asf init` already ends by handing the operator their console**: `console_perms.offer_text`
  plus the command to write it (`asf/init.py:321`–`:324`). The plugin's two install lines exist,
  but only in `tools/install.sh:147`–`:149` — a pipx operator who runs `asf init` directly never
  sees them.
- **`asf/roles/roles.py` has no config and no run-time choice** — "the binding is data"
  (`:23`) — so `validate` over `load_all()` is a pure check that needs no product, no git and no
  host, and can run in a doctor row and in a view alike.
- **The gate is** `python3 tools/run_tests.py`, `tools/check_generic.sh`,
  `tools/check_conventions.sh`, and `python3 -m asf.cli plugin check`.

### 1.2 In

- **`asf/views/header.py`** (new, stdlib only) — `TITLES`, the frozen title per command (§2.1);
  `head(command, product, clause='')`, the one function that builds a first line;
  `command_key(args)`, the registry key for a command that has a sub-command; and
  `STAMP_VERSION`, the commands whose stamp names asf's own version.
- **Twenty renderers' first lines** move onto `head()`. Not one clause's wording changes; the
  title, the product name and the markers do.
- **`asf/cli.py`** — one tail in `_main` prints `stamp(command_key(args), …)` for every command in
  `TITLES`, suppressed under `--json`. `asf/doctor.py:1001`'s own `print(stamp(...))` goes, so the
  stamp has exactly one caller for every command.
- **`asf/views/ci.py`** (new) — `asf ci` with no sub-command: the runner pool, the start queue's
  line, and the CI green rate. `--json`.
- **`asf/views/health.py`** (new) — `asf health`: the factory's live health, read-only.
- **`asf/views/performance.py`** (new) — `asf performance`: `measure.table` over a window.
- **`asf/plugin_build.py`** — `VIEWS` gains `'ci'`, `'health'`, `'performance'`; `asf plugin
  build` writes the three `SKILL.md` files and rewrites `plugin.json` and `marketplace.json`.
- **`asf/doctor.py`** — one new row, `roles`, over `roles.validate`.
- **`asf/init.py`** — the plugin's two install lines and the skills they add, printed beside the
  console-permissions offer.
- **Tests** — `tests/test_views_header.py` (new), `tests/test_views_ci.py` (new),
  `tests/test_views_health.py` (new), `tests/test_views_performance.py` (new), and the §3 blocks
  over `tests/test_plugin.py`, `tests/test_doctor.py`, `tests/test_views.py`,
  `tests/test_tokens.py`, `tests/test_ci_queue.py`, `tests/test_install.py`.

### 1.3 Out

- **Changing what any table says.** Every clause after the title keeps its present wording, every
  row keeps its present columns, every exit code keeps its present meaning (`doctor` 1 on red,
  `release-readiness` 1 when not ready, `rules check` 1 on a violation). This change is the first
  line, the last line, and three new commands.
- **A table renderer.** `asf/tables.py` already draws markdown pipe tables as box tables and is
  not touched. `head()` returns a string; it does not know what follows it.
- **Shipping the role files as Claude Code plugin agents.** A role is a brief block for a worker
  session — five `##` sections, a two-key frontmatter, no `model:` and no `tools:` by refusal 2
  and refusal 8 (`asf/roles/roles.py:9`–`:18`) — and a Claude Code agent file is the opposite
  shape: it names its model and its tools. `plugin/agents/` would be a second, divergent copy of
  twelve files whose whole point is that `BINDINGS` is the only thing that picks one (D8). What
  the console gets instead is the gate the docstring already promises: a red doctor row, and a
  `roles` line in `asf health`.
- **A second hooks entry in the plugin.** `plugin/hooks/hooks.json`'s `SessionStart` hook carries
  the console rules (B-0090, `asf/plugin_build.py:91`) and `asf hooks install` writes the product
  repo's and each worker account's entries (`asf/hooks.py:1`–`:27`). Both are in place and tested
  (`tests/test_plugin.py:98`); this spec adds no event and no hook.
- **Installing the plugin from `asf init`.** `/plugin marketplace add` and `/plugin install` are
  console commands, not shell commands — `asf` cannot run them. Init prints them; a human runs
  them, exactly as `tools/install.sh:147` already does.
- **A skill for `tokens`, `stale`, `rules` or the `ci` sub-commands.** They get a frozen header
  and a stamp because they print tables; `VIEWS` is the operator's *daily* set, and a skill per
  admin verb would put fifteen more `/asf:*` entries in front of the operator for commands they
  run once a quarter.
- **`asf performance` reading the record's `cost:` blocks.** `measure.table` takes `record_usd`
  as an optional second window (`asf/improve/measure.py:142`); the view passes `None`. Reconciling
  the ledger's spend against the record's is the improve pass's question, not a view's.
- **Making `asf health` fix anything.** `fix=True` ends sessions, reaps worktrees and writes
  ledger lines. The view is read-only under every path (D6); `asf workers health --fix` and the
  tick's `health` step (`asf/tick/step_health.py`) keep that job and are untouched.
- **Retiring `asf workers health` or `asf ci queue`.** Both keep their names, their output and
  their flags; the new views read through them, and a script or a clock calling either keeps
  working.
- **A `schema_version` bump, a machine key, or any record write.** No command here writes the
  record (§4).

## 2. The design

### 2.1 `asf/views/header.py` — the registry and the two lines

Stdlib only; imports nothing from `asf` (D10). Three names and one dict.

```python
#: Every command whose whole stdout is an operator table, and the title that table opens with.
#: The key is the command as an operator types it; a sub-command is joined with a space, because
#: that is what the stamp prints back. A command in this dict gets both lines (§2.2) and is
#: covered by tests/test_views_header.py; a command not in it prints neither.
TITLES = {
    'status': 'FACTORY STATUS',   'next': 'NEXT',
    'backlog': 'BOARD',           'roadmap': 'ROADMAP',
    'parity': 'PARITY',           'prod': 'PROD',
    'sessions': 'SESSIONS',       'scorecard': 'SCORECARD',
    'release-readiness': 'RELEASE READINESS',
    'capacity': 'CAPACITY',       'tokens': 'TOKENS',
    'stale': 'STALE',             'doctor': 'DOCTOR',
    'rules check': 'RULES',       'ci': 'CI',
    'ci queue': 'CI QUEUE',       'ci reconcile': 'CI RECONCILE',
    'ci reserve': 'CI RESERVE',   'health': 'HEALTH',
    'performance': 'PERFORMANCE',
}

#: The commands whose stamp names asf's own release rather than the product's HEAD: a table that
#: reports on the install, not on the product (asf/doctor.py:1000).
STAMP_VERSION = frozenset({'doctor'})


def head(command, product, clause=''):
    """``**FACTORY STATUS asf** — 04:11`` — the frozen first line of every table in TITLES.
    `product` is a name, never a Product (D10); `clause` is the renderer's own summary, passed
    through unchanged."""
    title = f"**{TITLES[command]} {product}**"
    return f"{title} — {clause}" if clause else title


def command_key(args):
    """The TITLES key for a parsed command line: ``args.command``, plus the sub-command when the
    parser declares one as ``<command>_command`` (``ci_command``, ``rules_command``)."""
    dest = args.command.replace('-', '_') + '_command'
    return f"{args.command} {getattr(args, dest)}" if getattr(args, dest, None) else args.command
```

`head()` raises `KeyError` on a command with no entry — deliberately: a nineteenth view that
forgets its title fails in its own first test, not in review.

The seventeen renderers change by one line each. Their clauses are unchanged, so what an operator
reads after the ` — ` is byte-identical to today:

| command | today's first line | after |
| --- | --- | --- |
| `status` | `**FACTORY STATUS {now}**` (`asf/views/status.py:387`) | `head('status', p, now)` |
| `backlog` | `**BOARD {HH:MM}** — {n} Features · …` (`asf/views/board.py:68`) | `head('backlog', p, f"{hhmm} · {n} Features · …")` |
| `parity` | `**PARITY {now}** — {done} of {n} …` (`asf/views/parity.py:50`) | `head('parity', p, f"{now} — …")` |
| `roadmap` | `**ROADMAP** (index.json generated …)` (`:69`) | `head('roadmap', p, 'index.json generated …')` |
| `sessions` | `**SESSIONS** — {n} working · …` (`:144`) | `head('sessions', p, '{n} working · …')` |
| `next` | `**NEXT** — {n} rows · …` (`asf/feeder/render.py:67`) | `head('next', p, …)`; the `header=` override argument is kept |
| `prod` | `**PROD** no deploy configured …` (`:223`) / **nothing** (`:244`) | both branches open with `head('prod', p, …)`; the configured branch's `**Prod app**` clause becomes the first clause |
| `scorecard` | `**SCORECARD {product}** — {as_of}` (`:58`, `:171`) | `head('scorecard', p, as_of)`; the by-lane table's clause keeps `by lane, last {days} d` |
| `release-readiness` | `**RELEASE READINESS {product}** — {as_of}` (`asf/release.py:441`) | `head('release-readiness', p, as_of)` |
| `capacity` | `CAPACITY — operator total: …` (`:96`) | `head('capacity', p or 'all', 'operator total: …')` |
| `tokens` | `TOKENS — input tokens per session, …` (`:96`) | `head('tokens', p, 'input tokens per session, …')` |
| `stale` | **nothing** (`asf/tick/stale.py:144`) | `head('stale', p, f'{n} over the stage limit')` |
| `doctor` | `== DOCTOR {product}` (`:967`) | `head('doctor', p)`; the `== SCHEDULER` sub-block (`:732`) becomes `**SCHEDULER {product}**` |
| `rules check` | `== RULES {n} checked, …` (`asf/rules/rules.py:221`) | `head('rules check', p, '{n} checked, …')` |
| `ci queue` | `== CI QUEUE {name} ({what}, …)` (`:2879`) | `head('ci queue', p, '{what}, …')` |
| `ci reconcile` | `== CI RECONCILE {product} ({mode})` (`asf/ci_pool.py:1179`) | `head('ci reconcile', p, mode)` |
| `ci reserve` | **nothing** (`:1188`) | `head('ci reserve', p, f'{n} runners reserved')` |

### 2.2 The stamp, once, in the dispatcher

`asf/cli.py`'s `_main` gains one tail, after the dispatch and before it returns:

```python
def _stamp_tail(args, rc):
    """The last line of every table in `header.TITLES`: `— generated by asf <command>@<sha> <HH:MM>`
    (`asf.cli.stamp`, :162). One caller for all twenty, so a new view cannot ship without it (D5).
    `--json` prints a value a script parses: no header, no stamp."""
    from asf.views import header
    key = header.command_key(args)
    if key not in header.TITLES or getattr(args, 'json', False):
        return rc
    version = version_string() if key in header.STAMP_VERSION else None
    print(stamp(key, repo=_repo_of(args), version=version))
    return rc
```

`_repo_of(args)` resolves the product's `repo_dir` — the sha the stamp names is the *product's*
HEAD, which is why `stamp` takes `repo` at all (`asf/cli.py:23`: "from `/tmp` the shell's own repo
said `@unknown`"). It returns `None` for `capacity --all` and for a product that will not load, and
`stamp` then falls back to the cwd's sha exactly as it does today.

`asf/doctor.py:1001`'s `print(stamp('doctor', version=version_string()))` is deleted; `doctor` is
in `STAMP_VERSION`, so its stamp keeps naming asf's release and `tests/test_doctor.py:954` keeps
passing unchanged.

A command that fails before it prints a table still gets a stamp — the tail runs on any return
code, because a stamped empty table is how an operator knows which release printed nothing.
`env.ConfigError` is the exception: it is caught in `main` (`:445`) and prints the
`NEEDS OPERATOR` line instead, and that path prints no stamp.

### 2.3 `asf ci` — the CI view

`asf/ci_pool.py:1220`'s `required=True` becomes `required=False`, and the `ci` parser gains
`--product`, `--json` and `set_defaults(run=cmd_ci)` so bare `asf ci` reaches the view (D4). The
three sub-commands are untouched.

`asf/views/ci.py` `render(root, product, source=None)`, three blocks under one header:

- **the pool** — `ci_pool.load_pool(product)` and `ci_pool.class_rows(pool)`: one row per runner

## 4. Records

**No record write.** Not one command in this spec writes a card, a machine key, an
`index.json` field or a `## History` line. `header.TITLES`'s twenty commands are reads;
`asf health` is a read by construction (D6, §3.4's byte-identical assertion); `asf ci` and
`asf performance` read the host, the ledger and the metrics streams. No `schema_version` bump, no
migration, no invariant change.

**The stamp line** — `— generated by asf <command>@<sha> <HH:MM>`, appended by
`asf/cli.py:_stamp_tail` to the stdout of every command in `header.TITLES`. It is not written to
any file; a table reaches a card, a PR body or a groom answer only by an operator or an agent
pasting it, and the stamp is what tells the reader which release drew it. `doctor`'s stamp names
asf's release instead of a sha (`STAMP_VERSION`).

**The generated plugin** — three new tracked files, `plugin/skills/{ci,health,performance}/SKILL.md`,
plus the regenerated `plugin/.claude-plugin/plugin.json` and `.claude-plugin/marketplace.json`
(their descriptions list fifteen `/asf:*` names). All five are `asf plugin build`'s output and none
is hand-edited; `asf plugin check` is the gate, in CI and in `tests/test_plugin.py`.

**One new doctor row** — `roles`, in the product-less group, `required=True`. It appears in
`asf doctor`'s table and therefore in the `asf status` Doctor reading and the tick's health log,
with no new stream and no new event kind.

**Two corrected docstrings** — `asf/cli.py:11` and `asf/views/__init__.py:1`, both of which
currently describe a tree that does not exist.

**Nothing else.** No config key is added or read for the first time, no `metrics/events` kind is
appended, no Bug is filed, no brief template changes, no PR body changes, and no evidence line's
wording changes.
