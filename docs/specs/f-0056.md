# F-0056 — the first pass: six remembered things, read out of a console and written into the tree

The factory's own directive 8 says memory is read-**then**-write, and its ruling under that
directive is blunt: *anything the factory relies on an agent remembering is a defect*
(`docs/CONSTITUTION.md:198-206`, [[D-0025]]). Two rules carry it — [[R-0124]] *a memory file older
than a fortnight must point at a card, unless it is style* and [[R-0135]] *write every recurring
factory step as code, never as a line to remember*. The CONSTITUTION states plainly what is
missing: *"The memory-pointer rule becomes `checked` when its check is ported — it is
`enforced: false` today"* (`docs/CONSTITUTION.md:209-211`).

So the rule that says "do not rely on memory" is itself enforced by nothing but memory. That is
the shape this Feature closes, and it has been closed once before at a smaller scale: [[B-0090]]
found the operator's console rules living "in whatever an operator happened to paste into their
own assistant memory", and answered it by generating them into `plugin/hooks/hooks.json` from
`asf/plugin_build.py`, with a test that the checked-in file is byte-identical to what the
generator produces (`docs/plans/b-0090.md:14-38`). The mechanism is not in question. What is
missing is a pass over the memory that is still there.

This is that pass. The source is the console's own memory directory — one markdown file per
remembered fact, plus an index of one-line pointers. Six files sit in it for this product today.
Read against the checkout rather than trusted, they sort into three piles:

| Memory file | What it remembers | Against the checkout |
| --- | --- | --- |
| `groom-epic-assignment-rule` | which Epic an inbox card is parented under, *by what the card changes* | `shape.infer_parent_epic` parents by **shared title words** (`asf/groom/shape.py:34-43`) — the remembered rule is better than the code and exists nowhere in it |
| `groom-inbox-answers-must-carry-no-why` | an `inbox:` answer with a trailing `— why` is silently dropped | true today: `parse_answer` returns `None` for any clause outside its grammar (`asf/groom/inbox.py:283-301`), `apply_answer` returns `False` (`:306-307`), and the caller `continue`s without counting or printing (`asf/groom/groom.py:309-315`) |
| `validate-plan-dag-with-plan-order` | run the real parser over a draft plan before committing; check parallel Tasks' `writes:` are disjoint | every piece exists — `plan_order.task_order` (`asf/record/plan_order.py:135`), `migrate.plan_task_records` / `writes_lines` (`asf/tick/migrate.py:187,209`), `footprint.globs_overlap` (`asf/feeder/footprint.py:25`) — and nothing runs them over a file a session is about to commit |
| `reshape-relaunches-until-record-half-applied` | a relaunched reshape must verify the split already in the plan, not mint fresh ids | `templates/reshape.md` says "ids from `BACKLOG_ID_RANGE`" unconditionally and names nothing already minted; the record already carries `split_from` (`asf/feeder/rows.py:1078`, `asf/groom/shape.py:195`) |
| `verify-spec-preconditions-against-checkout` | an approved spec goes stale; grep every symbol it names before planning | nothing does this. `asf/drift.py` is version drift, `asf/precheck.py` is the pass over a *code* branch — neither reads a spec |
| `t-0103-review-self-trigger-loop` | PUSHED → REVIEW fires forever because a review commit predates its own future HEAD | **already code**: [[B-0147]] taught `review.is_current` that a named head still stands when the code at the tip is the same (`asf/evidence/review.py:218-241`), with `test_the_review_commit_on_top_of_the_head_it_names_is_current` (`tests/test_review_reader.py:178-180`). The file is stale |

Four become code here. One is already code and becomes a pointer. One — the inbox-answer
grammar — is a workaround a session carries, and the code stops needing to be worked around.

And the pass adds the thing that makes the next pass cheap: `asf memory`, the check that names a
memory file carrying no card. The memory directory is a path on the operator's host, so the
product never holds it; the path is a product-config key, the command takes `--dir`, and the
check is what [[R-0124]] gets as its `check:` script.

## 1. Decisions

### 1.1 Preconditions

Each verified in this worktree at `8164e07e9`, the branch's base.

- `shape.infer_parent_epic(canonical, tokens)` is the whole of epic assignment: the open Epic
  sharing the most title words, `None` on a tie at zero (`asf/groom/shape.py:34-43`). Its one
  caller is `derive`, which passes `tokenize(card.title)` (`asf/groom/shape.py:124`). A card's
  `writes:` is already parsed off the inbox file (`INBOX_KV_RE`, `asf/groom/inbox.py:10`) and
  sits in `card.headers['writes']` (`asf/groom/shape.py:60`).
- `parse_answer` grammar is `close` | `;`-separated `feature` / `bug <signature>` /
  `parent <id>` / `S1|S2|S3` (`_CLAUSES`, `asf/groom/inbox.py:274-281`). Any clause outside it
  returns `None` for the **whole** answer. `apply_answer` and `groom.py:309` turn that `None`
  into silence — no line, no count, no event.
- `plan_order.task_order(plan_text)` returns `{task number: [predecessors]}` with ints for plan
  tasks and card ids for outside ones, and `_reaches` already walks the graph
  (`asf/record/plan_order.py:135,176`). `derived_after` needs `{id: meta}` from the record, so it
  is **not** usable on a draft whose Tasks have no cards; `task_order` is.
- `migrate.writes_lines(body)` reads a Task section's `Files:`/`Writes:` line and splits it on
  **commas** (`asf/tick/migrate.py:205-217`). A space-separated line — the form
  `docs/plans/b-0090.md:16` uses — reads back as one glob. The check prints what it parsed, so
  the author sees it; it does not change the parser.
- `footprint.globs_overlap(a, b)` is the repo's one footprint-matching rule and is pure over two
  strings (`asf/feeder/footprint.py:25-35`); `asf.size` already borrows it rather than
  reimplementing (`asf/size.py:11-17`).
- Brief templates are `{placeholder}` markdown filled from the one flat dict `build.context`
  (`asf/briefs/build.py:362`), and a placeholder with no key is a `BriefError`, not an empty
  string (`:190-195`). Adding a placeholder means adding a key, and the existing template test
  enforces it.
- The reshape row is emitted from `rows.py:1067-1076`: a Task carrying `reshape:` waits while a
  session holds it and otherwise LAUNCHes `brief_kind='reshape'`. The field is cleared only when
  the reshape session marks the Task `removed: split into <ids>` — so a session that pushed the
  plan half and died before the record half relaunches into a brief that asks for fresh ids.
- `core.MENTION_ID_RE = re.compile(r'[A-Z]-[0-9]{4}')` (`asf/record/core.py:201`) is the existing
  unanchored form of an item id in prose. Nothing here adds a second one.
- `conventions.py` is the only file under `asf/` where a convention default may be a literal;
  `tools/check_conventions.sh` fails the build on one anywhere else (`asf/conventions.py:1-9`).
  Overrides come from the product yaml's `conventions:` block — operator config, not the
  product repo (`asf/conventions.py:11-13`).
- `asf plugin build` generates a `SKILL.md` only for the commands in `plugin_build.VIEWS`
  (`asf/plugin_build.py:33-34`). `memory`, `plan-check` and `spec-check` are not views, so the
  plugin tree does not change and `plugin_build.diff()` stays empty.
- The top-level `rules/` directory that `rules.core_rules_dir()` resolves
  (`asf/rules/rules.py:56-62`) **does not exist in this repo**. `docs/plans/f-0040.md:37` (P12)
  records the same absence and assigns its creation to that plan's Task 7, which has not landed.
  Either card may create it; both add files and neither deletes one.
- Rule and Decision cards live in the record, not here, and their ids come from `asf new` — not
  from this session's `BACKLOG_ID_RANGE`, which carries `S`, `T` and `B` only. Nothing in this
  spec mints an `R-` or `D-` id.

### 1.2 In

- **`asf.memory`** — a new module: `memory_files(dir)`, `pointer(text)`, `unpointed(dir, now,
  grace_days, style_globs)` and `register(sub)` for `asf memory check`. Pure over a directory
  listing and file text; one `os.stat` per file for age, no network, no record.
- **`asf.conventions`** — four typed fields with documented defaults: `memory_dir` (`None`),
  `memory_grace_days` (`14`, the fortnight [[R-0124]] names), `memory_index` (`MEMORY.md`),
  `memory_style_globs` (`()`), and `epic_routes` (`()`).
- **`rules/memory-pointer.sh`** — the core check script [[R-0124]] gets as its `check:`, creating
  the `rules/` directory the resolver has always named. Paths from the environment, ids from
  nothing: it shells out to `asf memory check` and prints one line per violation.
- **`asf.groom.shape.infer_parent_epic(canonical, tokens, writes=(), routes=())`** — the routes
  decide first, shared title words second.
- **`asf.groom.inbox.parse_answer`** returns a reason instead of a bare `None`, and
  `groom.py`'s inbox branch prints one `groom: answer not applied — <reason>` line per refused
  answer. A trailing `— why` clause is named as what it is.
- **`asf.record.plan_check`** — `asf plan-check <plan>`: the DAG the real parser reads, its
  cycles, its unresolved `after:` targets, and the `writes:` overlap between Tasks with no
  ordering between them. One table, exit 1 on any finding.
- **`asf.record.spec_check`** — `asf spec-check <spec> [--repo R]`: every backticked repo path and
  dotted symbol the spec names, against the checkout. One table of what is absent, exit 1 when
  the list is not empty.
- **`asf.briefs`** — `context` gains `split_parts`, and `templates/reshape.md` gains the
  paragraph that makes a relaunch verify instead of mint.
- **`asf.feeder.rows`** — the reshape LAUNCH row's reason names the parts the record already
  holds, so the operator sees a relaunch is a second attempt at a half-done split.
- Tests for each (§3), and `tests/fixtures/memory/` — one file per row of §4's pointer table.

### 1.3 Out

- **Writing the operator's memory files.** They sit on a console host outside every repo the
  factory may write. This spec ships the check and the item each file points at; replacing the
  files is one `NEEDS OPERATOR` line (§4) and the check is how it is proved, not a session's
  word for it.
- **Naming that directory in the product.** No path, no host, no account: `memory_dir` is unset
  by default, the command takes `--dir`, and `tools/check_generic.sh` runs over the tree
  (`tools/forbidden-names.txt` already makes a console path an unlandable commit).
- **A memory *write* interface.** Directive 8 wants read-then-write; this is the read half of
  that loop — a pass over what is already written. Wiring a session to write memory back is not
  in this card and would be the second half of a different Feature.
- **The second and third passes.** The card says this is the first of three over the same source
  and that merging the three is one parent change per Story, decided at the groom. Nothing here
  reserves ids for them or tries to be exhaustive.
- **Re-litigating the review self-trigger.** [[B-0147]] closed it and a test holds it
  (`tests/test_review_reader.py:178`). This spec adds no code there; it retires the memory file.
- **Changing `migrate.writes_lines`' comma split.** `asf plan-check` reports the globs it
  parsed and lets the author see a space-separated line read as one. Widening that parser
  touches the tick's migrate path, has its own blast radius, and belongs to its own card.
- **An `asf doctor` row.** Doctor is one product's install health. A rule check is where a rule
  runs, and [[R-0124]] is a rule.
- **A new env var.** `$ASF_MEMORY_DIR` is not added: the env census this repo is growing
  (`docs/specs/f-0087.md:108`) has not landed, so a new variable would be one more thing to
  remember — which is the defect this card is about.
- **Deleting a memory file.** The check names a file with no card. What replaces its body is the
  operator's, and an emptied file is not the pass's business.

### 1.4 The choices

| Choice | Against | Why |
| --- | --- | --- |
| The memory directory comes from product config and `--dir` | an env var, or a default path | a default path is a machine path in a public repo, and the redaction check refuses one. Operator config is where the CONSTITUTION's own ruling puts a backend; `default_bug_epic` is already that shape. |
| A pointer is any item-id mention in the file | a typed `item:` frontmatter key | the acceptance asks for "a one-line pointer", not a schema. `core.MENTION_ID_RE` already exists, an index line like `- [Title](file.md) — hook` carries the id as prose, and a check that demands a key would fail every file written before it. |
| Style is a glob list in config | a frontmatter `type:` the check reads | [[R-0124]] exempts style without saying how style is recognised. A glob list is the operator's answer, is visible, and does not make the product guess at a memory format it does not own. |
| Age comes from the file's mtime | a date in the file | there is no date field the product may rely on, and the grace window only decides *when* a file is nagged about. A file that is recent and unpointed is still converted here; it just is not a violation yet. |
| The four conversions are four Stories, one per memory file | one Story "convert the memories" | the card's acceptance is per-Story ("every Story here is produced by a script or a feeder row"), the plan mints one Task per Story, and four small disjoint footprints parallelise where one does not. |
| `epic_routes` routes on `writes:`, and title words stay as the fallback | replacing the word overlap | a card with no `writes:` — most inbox cards — has nothing to route on, and removing the fallback would leave it unparented. The routes are the rule the memory held; the words are the floor under it. |
| A refused inbox answer prints a line | filing a Bug, or refusing the whole groom | the adjudicator is looking at the output when it happens; a line is the shortest path from "nothing happened" to "this is why". The groom applies every other answer on the page regardless. |
| `asf plan-check` takes a path, not an item | reading the plan of `--item F-nnnn` from the record | it is run on a draft in a worktree, before anything is committed, which is the whole point of it. A path needs no record, no product and no clone, and the test is a temp file. |
| `asf spec-check` reads backticked tokens | a typed "preconditions" block the spec must carry | every spec in `docs/specs/` already names its symbols in backticks, so the check works on the 60 specs already written instead of only on ones written after it. |
| The reshape brief gains facts; the row gains a reason | making the row stop launching once parts exist | parts may exist and be wrong — a half-applied split is exactly the case here. The session must look; the brief's job is to make sure it is told what to look at. |
| `rules/memory-pointer.sh` shells out to `asf memory check` | a standalone shell implementation | one owner for what "a memory file with no card" means, testable in Python, and the script stays the thin thing `resolve_script` expects. |

## 2. The design

### 2.1 The memory interface — `asf/memory.py`

One module, named for the interface and not for any backend.

```python
"""asf.memory — the read half of directive 8: what a console still has to remember.

A memory file is one markdown file in the memory directory, holding one remembered fact. Its
pointer is the item that made the remembering unnecessary: any item id mentioned in the file
(``core.MENTION_ID_RE``). R-0124 — a memory file older than a fortnight must point at a card,
unless it is style — is this module, and ``rules/memory-pointer.sh`` is how the rule runner asks.

The directory is a path on the operator's console, never on this repo's side: it comes from
``conventions.memory_dir`` or ``--dir``, and is unset by default.
"""
```

- `memory_files(dir)` → sorted paths of `*.md` directly under `dir`, excluding
  `conventions.memory_index` (default `MEMORY.md`) and any dot-file. No recursion: a memory
  directory is flat, and a subdirectory is not this check's to read.
- `pointer(text)` → the first `MENTION_ID_RE` match in `text`, or `None`.
- `unpointed(dir, now, grace_days, style_globs, index)` → `[(path, age_days)]`, oldest first,
  for every memory file with no pointer, older than `grace_days`, and matching none of
  `style_globs` (`fnmatch` on the base name).
- `cmd_check(args, out=print)` prints one line per entry and a trailing count:

```
memory: 2 files carry no card
  groom-epic-assignment-rule.md        21d
  validate-plan-dag-with-plan-order.md 19d
```

  Exit `1` when the list is not empty, `0` when it is, and `0` with
  `memory: no directory configured — pass --dir or set conventions.memory_dir` when neither is
  given (an unconfigured operator is not a violation).

`register(sub)` follows `plugin_build.register`'s shape exactly (`asf/plugin_build.py:187-192`):
`asf memory check [--dir D] [--product P] [--grace-days N] [--json]`, `set_defaults(run=...)`, wired in
`asf/cli.py` beside the other four registrations (`asf/cli.py:345-352`).

### 2.2 The rule's check — `rules/memory-pointer.sh`

The directory `rules.core_rules_dir()` has always named, with one file in it:

```sh
#!/usr/bin/env bash
# R-0124 — a memory file older than a fortnight must point at a card, unless it is style.
# Paths come from the environment; this script names none.
set -euo pipefail
exec python3 -m asf.cli memory check ${ASF_PRODUCT:+--product "$ASF_PRODUCT"}
```

The rule card in the record gains `check: rules/memory-pointer.sh` and loses
`enforced: false` — a record write, `NEEDS OPERATOR` in §4, not a commit here.

### 2.3 Epic assignment is a route, not a word count — `asf/groom/shape.py`, `asf/conventions.py`

```yaml
conventions:
  epic_routes:
    - {globs: [asf/tick/**, asf/feeder/**], epic: E-0001}
    - {globs: [docs/**], epic: E-0003}
```

`infer_parent_epic(canonical, tokens, writes=(), routes=())`: the first route any glob of which
overlaps any glob of `writes` (`footprint.globs_overlap`, both directions) and whose `epic` is an
open Epic in `canonical` wins. With no route matching, or no `writes`, the shared-title-words
answer stands exactly as today. `derive` passes `card.headers.get('writes')`, split on whitespace
and commas, and `conventions.epic_routes` for the product.

A route naming an Epic the record does not hold, or holds closed, is skipped — the groom is not
the place to discover a typo in config, and the fallback still answers.

### 2.4 A refused inbox answer says so — `asf/groom/inbox.py`, `asf/groom/groom.py`

`parse_answer(answer)` returns `(parsed, reason)`: `('close', None)`, `(headers, None)`, or
`(None, reason)` where `reason` names the first clause that failed and, when that clause carries
an em dash, says so in the words that make it fixable:

```
groom: answer not applied — inbox:billing-tiers: "parent E-0001 — the card changes the feeder"
  is not a clause: an answer carries no why. Clauses are close | feature | bug <signature> |
  parent <id> | S1|S2|S3, separated by `;`.
```

`apply_answer` keeps returning a bool and gains the reason as a second value; `groom.py:309-315`
prints the line when it is set and leaves everything else — the count, the event, the other
answers on the page — as it is. Nothing is applied that was not applied before: the grammar does
not widen. The silence goes.

### 2.5 `asf plan-check <plan>` — `asf/record/plan_check.py`

Four findings over one file, every one of them from a function that already exists:

| Finding | From |
| --- | --- |
| `after: <n>` names a task the plan has no section for | `plan_order.task_order` keys vs. its values |
| a cycle | `plan_order._reaches` over the number graph |
| two Tasks with no ordering between them whose `writes:` overlap | `migrate.plan_task_records` + `migrate.writes_lines` + `footprint.globs_overlap` |
| a Task section with no `Files:`/`Writes:` line | `writes_lines` returning `None` |

"No ordering between them" is the transitive closure of `task_order`: Task 3 after Task 1 may
overlap Task 1 and may not overlap Task 2. The output is one table and the parsed footprint per
Task, so a `writes:` line the comma split read as one glob is visible rather than silent:

```
plan-check docs/plans/f-0056.md — 6 tasks
  T1  asf/memory.py, tests/test_memory.py
  T2  rules/memory-pointer.sh
  ...
  ! T3 and T4 run together and both write docs/guide/*
  ! T5 after: 9 — no such task
== 2 findings
```

Exit 1 on any finding, 0 on none. No record, no product, no git: a path in, a table out.

### 2.6 `asf spec-check <spec>` — `asf/record/spec_check.py`

Only inline backticked tokens are read: a fenced block is an example, and a spec that shows what
an absent path looks like must not be a finding about itself. Each token is one of three things,
and each has one test:

- a repo path (`asf/groom/shape.py`, `tests/test_groom.py`, with or without a `:<line>` suffix) —
  present when the file is in the checkout; a named line is reported when the file is shorter;
- a dotted symbol (`shape.infer_parent_epic`, `asf.memory.unpointed`) — present when its last
  segment is defined (`def `, `class `, or an assignment at column 0) in the module its dots
  resolve to, or anywhere under `asf/` when they do not;
- anything else — a shell word, a yaml key, a phrase — which is not checked and not reported.

Output is the PD-shaped table a plan session pastes into its drift list:

```
spec-check docs/specs/f-0056.md against . — 41 tokens read, 2 absent
| token | kind | what the checkout says |
| --- | --- | --- |
| `asf/groom/shape.py:124` | path | file has 118 lines |
| `rows.reshape_reason` | symbol | no definition under asf/ |
== 2 absent
```

Exit 1 when the table has rows. `--repo R` points it at another checkout; the default is the cwd's
toplevel.

### 2.7 A reshape that was half-applied — `asf/briefs`, `asf/feeder/rows.py`

`build.context` gains one key, `split_parts`: the open Tasks in the record whose `split_from` is
this item, each as `<id> (<writes>)`, or the string `none yet`. `templates/reshape.md` gains one
paragraph under DELIVERABLE:

> The record already holds these parts of {item_id}: {split_parts}. When that is not `none yet`,
> a previous attempt at this split got part-way: **verify and finish it — mint no new id**. Check
> each part against the plan's sections and against {item_id}'s Stories, add only what is
> missing, and mark {item_id} `removed: split into <ids>` so this stops being asked for.

And the row that asks for it says which attempt this is (`asf/feeder/rows.py:1074-1076`):

```
LAUNCH reshape T-0181 — groom: footprint: needs docs/guide/** (parts already minted: T-0190, T-0191)
```

The row still launches: parts may exist and be wrong, which is the case the memory file was
written about. What changes is that the session is told, in the brief and in the line, that the
record has a half-done split in it.

## 3. Acceptance tests

From the repository root, stdlib only, hermetic. The whole suite must stay green:

```bash
cd "$(git rev-parse --show-toplevel)"
python3 tools/run_tests.py
```

**T1 — the memory check.** Over a temp directory: a file with `S-0001` in its body is pointed and
never listed; a file with none and an mtime 20 days old is listed with `20d`; the same file at
3 days old is not (grace 14); `MEMORY.md` is never a memory file, nor is `.hidden.md`, nor
`sub/x.md`; a file matching a `memory_style_globs` entry is exempt however old. `cmd_check`
exits 1 with entries, 0 with none, and 0 with the "no directory configured" line when neither
`--dir` nor `conventions.memory_dir` is set. `Conventions()` gives `None`, `14`, `MEMORY.md`,
`()`; `from_mapping` overrides each and leaves `extra` empty.

```bash
python3 -m unittest -v tests.test_memory.MemoryCheckTests tests.test_conventions.MemoryConventionsTests
```

**T2 — the rule script.** `rules/memory-pointer.sh` exists, is executable, names no path outside
`$ASF_PRODUCT`, and run with `--dir` at a fixture of two unpointed files exits 1 and prints both
names; at a fixture where both carry ids it exits 0. `asf.rules.rules.resolve_script` finds it by
base name through `$ASF_CORE_RULES_DIR`.

```bash
python3 -m unittest -v tests.test_memory.RuleScriptTests tests.test_rules.ResolveTests
```

**T3 — the epic route decides before the word count.** With Epics `E-0001 "a working factory"`
and `E-0003 "the guide"` open and a route `{globs: [docs/**], epic: E-0003}`: a card whose
`writes:` is `docs/guide/x.md` parents to `E-0003` even when every word of its title is `E-0001`'s;
a card with no `writes:` parents by shared words exactly as before; a route naming a closed or
absent Epic is skipped and the words answer; `infer_parent_epic` with no routes is unchanged
against `tests/test_groom.py:91`'s existing case.

```bash
python3 -m unittest -v tests.test_groom_shape.EpicRouteTests tests.test_groom
```

**T4 — a refused answer is a line, not a silence.** `parse_answer('parent E-0001 — because the
card changes the feeder')` returns `(None, reason)` with `an answer carries no why` in the
reason; `parse_answer('feature')` and `parse_answer('close')` are unchanged; a groom page with one
bad inbox answer and one good one applies the good one, counts 1, emits one `groom_answer` event,
and prints exactly one `groom: answer not applied —` line naming the bad clause.

```bash
python3 -m unittest -v tests.test_groom.InboxAnswerGrammarTests tests.test_groom_every_tick
```

**T5 — the plan DAG and the parallel footprints.** Over plan texts written into a temp file: a
