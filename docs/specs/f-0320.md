# F-0320 — the verdict is not dropped, it is never looked up

The card reads the symptom off the lane lines: after ASF rebases a reviewed branch the approved
verdict is gone, `git range-diff` says every commit is identical, and the item re-reviews to the
cap. The obvious suspect is the carry-over that compares the reviewed head with the rebuilt one
(`asf.evidence.review.same_code` → `_own_patch` → `git patch-id --stable`). **It is not the
defect.** Measured below (P6), that carry already holds in exactly the cases the card names: in
every case where `git range-diff` prints `=` it carries the approval, and it fails only where
range-diff prints `!` too.

The verdict is not dropped. It is **never read**. `Lane.branch_facts` reads a branch's review only
when the branch's *previous* lane record is one of `None, PUSHED, BACK, PR_OPEN, REVIEW`
(`asf/harvest/lane.py:1904-1905`). A branch sitting in `WAITING_CI`, `WAITING`, `GATE`, `QUEUED`,
`MERGING` or `STALE` carries no `review` fact at all — and one pass can carry that same branch back
through `PUSHED → PR_OPEN → REVIEW`, because the lane's own rebuild moved its head
(`drop_copies`, `rebase_onto_trunk`, `repair_naming`, the sign-off push) or because its PR
reopened (R6). `review_reason` then reads the missing fact as **`(1, 'no ASF review yet')`** — not
"predates the head". Round 1. Again. Every rebuild.

That is the card's wording made exact: the round the record writes is `1`, so T-0422 "went back to
review round 1", and B-1496 bought a fresh review round after each `dropped N trunk copies` until
the relaunch cap stopped it.

## Decisions

### What is in

* One pure predicate — `reads_review(state, head)` — for when a pass must read the branch's
  review, replacing the inline state tuple at `lane.py:1904-1905`.
* `branch_facts` records that it read it (`f['review_read']`).
* `review_reason` and `next_state` stop treating an *unread* review as *no* review: no
  `no ASF review yet`, no round spent, nothing written.

### What is out, and why

| out | why |
| --- | --- |
| `asf.evidence.review.same_code`, `_own_patch`, `judge`, `is_current` | P6: the patch-id carry is sound in every case the card describes. Touching it would be a change with no defect behind it. |
| adding `git range-diff` to the product | P6: on the same fixtures `range-diff` and the current patch-id check agree, case for case. It would buy nothing and add a git call per pass. |
| `flags.mechanical`'s `carry_review` / `mechanical_from` (`asf/harvest/mechanical.py:450-462`, `lane.py:1940-1949`) | It answers a narrower case (the table's own move, flag on, default off) and answers it correctly. Reading the review is what it was standing in for; it keeps working either way. |
| the review-round cap, the relaunch cap, the daily cap | They counted correctly. They counted real rounds the lane asked for. |
| the lane record's `round` field | P9: `record()` does not carry it forward, so the record cannot restore a lost round. Only reading the review can. |
| the identical state tuple at `lane.py:1874-1875` (the conflict read) | Same shape, different fact, not this card. Named here so the next reader sees it: it is a second copy of the tuple this card is about. |
| the review store (`asf.evidence.review_store`) | P7: the reviews in question were only ever on the branch, as a cloud session's must be. That is by design; nothing here changes it. |

### Preconditions — read in this worktree at `c599985a2`, 2026-10-10

* **P1 — the gate.** `asf/harvest/lane.py:1904-1905`, the whole review read:

  ```python
  if (f['review_required'] or f['class'] == CODE) \
          and rec.get('state') in (None, PUSHED, BACK, PR_OPEN, REVIEW):
  ```

  `rec` is `lifecycle.lane_of(run)` — the branch's **previous** lane record. Nothing below that
  line runs for a branch whose last state was outside the tuple: not `review_at`, not
  `is_current`, not `review_unwaived`, not `overruled`/`ruled`.

* **P2 — absence reads as "no review".** `review_reason` (`lane.py:1450-1454`):

  ```python

  if not rv:

  ```

  There is no third answer for "the pass did not look". `next_state` turns it into
  `(REVIEW, 'round 1 wanted: no ASF review yet')` (`lane.py:1602-1604`) and
  `Lane.enter_*` writes `round=1` on the record (`lane.py:2477-2481`).

* **P3 — four head-moving sites refresh only what was already read.** `repair_naming`
  (`lane.py:2771`), `normalise_commits` (`2956`), `publish_rebuilt` (`3010`) and the sign-off push


  A skipped read leaves nothing to refresh, in all four.

* **P4 — the states outside the tuple are reachable states, not dead ends.**

* **P6 — the carry the card points at already works.** A fixture repo: `main` holds `a.txt`
  (`l1`…`l7`) and `b.txt`; the branch changes `l4`→`L4`; a review committed on the branch names

### The choices

| choice | taken | against | why |
| --- | --- | --- | --- |
| where to fix | widen the read in `branch_facts` | re-read inside each of P3's four head-moving sites | One rule covers all four *and* R6 and Tp', which no rebuild touches. Four copies of a re-read is four places to drift — and this defect **is** such a drift. |
| which states read the review | every state but `MERGED`/`REAPED`, given a head | exactly the states P5's transitions can leave (`GATE_STATES`, `QUEUED`, `MERGING`, `STALE`, `PARKED`) | Enumerating them copies the transition table into a second place, which is the mistake being fixed. "Not landed, not reaped, has a head" needs no maintenance when a state is added. |
| the cost of reading more | accepted | keeping the tuple narrow to save a git read | The read is one `ls-tree` of the reviews dir plus one `git show`, on branches the pass already runs `gh` calls and `git merge-tree` for. The branches it adds are bounded by the pass's own cap (the reporting product: 12 a tick). A terminal record still reads nothing. |
| what an unread review means | a third answer: no round, nothing written | leaving `review_reason`'s two answers and trusting the widened gate | The gate lives in `branch_facts`, the meaning in the pure table; they drifted once already and the cost was four review rounds and a relaunch cap. The guard is provable with no git. |
| restoring the lost round | read the review | carry `round` forward on the lane record | P9: `record()` drops it and `set()` overwrites `f['prev']`. A carried-forward round would be a guess about a review nobody read. |
| the card's `range-diff` | no change | add `git range-diff` as a second equality test | P6: it agrees with the current check, case for case. |

## The design

Three edits, all in `asf/harvest/lane.py`. No new git command, no new config key, no new flag, no
record field.

### 1. One predicate for when the review is read

Beside `reads_red` (`lane.py:1464`), which exists for exactly this reason on the other fact:

```python
#: The lane states no pass can carry a branch out of: a review read for one of these is a read
#: for nothing. Everything else can be back in PR_OPEN/REVIEW before the pass ends — R4 (its head
#: moved: the lane's own rebuild), R6 (its PR reopened), Tp' (its draft is ready).
NO_REVIEW_STATES = (MERGED, REAPED)


def reads_review(state, head):
    """True when this pass must read the branch's review. Every state but a landed or reaped
    one, given a head to read it against.

    ONE pass carries a branch from GATE/WAITING_CI/WAITING/QUEUED/MERGING through PUSHED →
    PR_OPEN → REVIEW when the lane's own rebuild moves its head (:meth:`Lane.drop_copies`,
    :meth:`Lane.rebase_onto_trunk`, :meth:`Lane.repair_naming`, the sign-off push), and from
    STALE when its PR reopens (R6). A pass that did not read the review has no ``review`` fact,
    and :func:`review_reason` read that absence as ``no ASF review yet``: round 1, a fresh review
    round for code no session touched, on a review file that was readable the whole time. A
    product's B-1496 spent four such rounds (2026-10-06/07, three after a ``dropped N trunk
    copies`` and one after its PR reopened) and stopped only at the relaunch cap; T-0422 went
    back to round 1 the same way.
    """
    return bool(head) and state not in NO_REVIEW_STATES
```

### 2. The gate uses it, and says that it read

`lane.py:1904-1905` becomes:

```python
if (f['review_required'] or f['class'] == CODE) and reads_review(rec.get('state'), head):
    f['review_read'] = True
    rv = review_mod.review_at(repo, conv, f'origin/{b}', item, ...)
    ...                      # the body below is unchanged
```

`f['review_read']` is set only here, so "there is no `review` fact and no `review_read`" is
exactly "this pass did not look" — and the four sites of P3 now always have a review to refresh.

### 3. An unread review is not a missing review

`review_reason` (`lane.py:1450`) gains the third answer:

```python
def review_reason(facts):
    """``(round wanted, why)`` for a head no review approved yet — and, for a pass that did not
    read the review at all (:func:`reads_review`), ``(0, …)``: no round is wanted, because none
    was judged. Reading a skipped read as "no ASF review yet" reset the round to 1 and bought a
    review round for code no session touched (F-0320)."""
    rv = facts.get('review') or {}
    if not rv and not facts.get('review_read'):
        return 0, 'the review was not read this pass'
    if not rv:
        return 1, 'no ASF review yet'
    ...
```

and `next_state`'s review arm (`lane.py:1578-1604`) keeps the branch where it is rather than
spending that round:

```python
    if s in (PR_OPEN, REVIEW):
        rv = f.get('review') or {}
        if not rv and not f.get('review_read'):
            return keep   # F-0320: never a round on a review this pass did not read
        if not f.get('review_required'):
            ...
```

With edit 2 in place this arm is unreachable from `branch_facts`; it is what keeps the pure table
and the gate from drifting apart again, and it is provable with no git at all.

### What it looks like when it is there

P10's end-to-end lines become:

```
dropped 1 trunk copies from worker/T-0001: … 2 own commit(s) on origin/main
lane: worker/T-0001 WAITING_CI → PUSHED (dropped 1 trunk copies)
lane: worker/T-0001 PUSHED → PR_OPEN (fast-forward: the branch is its own PR)
lane: worker/T-0001 PR_OPEN → GATE (reviews/1-t-0001.md approved its head)
```

— the same line the control already reaches. No `REVIEW`, no `round`, no session.

### A1 — the pure guard: an unread review spends no round (no git)

Uses the module's own `facts()`/`rec()` helpers. Fails today at the first assertion: `next_state`
returns `(REVIEW, 'round 1 wanted: no ASF review yet')`.

```python
class AnUnreadReviewIsNotAMissingReview(unittest.TestCase):
    """F-0320: ``Lane.branch_facts`` reads a branch's review only from some prior states, and
    ``review_reason`` read the resulting absence as "no ASF review yet" — round 1, a fresh review
    round for code no session touched. A pass that did not read the review wants no round."""

    def test_an_unread_review_keeps_the_branch_where_it_was(self):
        f = facts(review_required=True)              # no 'review', no 'review_read'
        self.assertEqual(lane.next_state(rec(lane.PR_OPEN, reason='PR #7'), f),
                         (lane.PR_OPEN, 'PR #7'))
        self.assertEqual(lane.next_state(rec(lane.REVIEW, reason='round 3 wanted: x'), f),
                         (lane.REVIEW, 'round 3 wanted: x'))

    def test_a_read_review_that_found_none_still_wants_round_one(self):
        f = facts(review_required=True, review_read=True)
        self.assertEqual(lane.next_state(rec(lane.PR_OPEN), f),
                         (lane.REVIEW, 'round 1 wanted: no ASF review yet'))

    def test_review_reason_says_which_of_the_two_it_is(self):
        self.assertEqual(lane.review_reason(facts(review_required=True)),
                         (0, 'the review was not read this pass'))
        self.assertEqual(lane.review_reason(facts(review_required=True, review_read=True)),
                         (1, 'no ASF review yet'))

    def test_reads_review_is_every_state_but_landed_or_reaped(self):
        for state in (None, lane.PUSHED, lane.BACK, lane.PR_OPEN, lane.REVIEW, lane.GATE,
                      lane.WAITING_CI, lane.WAITING, lane.QUEUED, lane.MERGING, lane.PARKED,
                      lane.STALE):
            self.assertTrue(lane.reads_review(state, HEAD), state)
        self.assertFalse(lane.reads_review(lane.MERGED, HEAD))
        self.assertFalse(lane.reads_review(lane.REAPED, HEAD))
        self.assertFalse(lane.reads_review(lane.PR_OPEN, None), 'no head, nothing to read it at')
```

### A2 — the gate: the review is read whatever the prior state was

Fails today for `GATE`, `WAITING_CI`, `WAITING`, `QUEUED`, `MERGING`, `PARKED` and `STALE`

```python
REVIEW_FILE = """# Review

head: {head}

verdict: approved

| check | result | evidence |
| --- | --- | --- |

| every Step of the Task is implemented | pass | ok |

class TheReviewIsReadFromEveryLivingState(LaneFixture):

    to PR_OPEN/REVIEW — the lane's own rebuild moves the head out of WAITING_CI/GATE/QUEUED, and a
    reopened PR brings it back from STALE. It was read only from None/PUSHED/BACK/PR_OPEN/REVIEW,
    so those passes had no verdict to carry."""

    B = 'worker/T-0001'

        return super().product(lane={'review': {'code': 'required'}}, **conv)
```

### A3 — end to end: the lane's own rebuild from WAITING_CI lands at GATE

The production shape of P8/P10: a branch carrying one commit whose patch the trunk also holds, so
`drop_copies` rebuilds and pushes it in the same pass. Fails today with the exact production line
`round 1 wanted: no ASF review yet`.

```python
class ARebuildFromAGateStateKeepsTheApproval(LaneFixture):
    """F-0320, the reported shape: approved at its head, held in WAITING_CI for heavy CI, and the
    lane's own `drop_copies` rebuilds it on the trunk in a later pass. A product's B-1496 bought a
    fresh review round after each of three such rebuilds and stopped at the relaunch cap; T-0422
    went back to round 1. The rebuilt head carries the same own patch, so the approval stands."""

    B = 'worker/T-0001'

    def product(self, **conv):
        return super().product(lane={'review': {'code': 'required'}}, **conv)

    def setUp(self):
        super().setUp()
        self.push_lane(self.B, {'a.txt': 'a\n'}, 'feat(T-0001): a')
        self.write(self.worker, 'c.txt', 'c\n')
        sh(['git', 'add', '-A'], cwd=self.worker)
        sh(['git', 'commit', '-qm', 'chore: c (#99)'], cwd=self.worker, env_=self.ident)
        sh(['git', 'push', '-q', '-f', 'origin', self.B], cwd=self.worker)
        code = sh(['git', 'rev-parse', self.B], cwd=self.worker).stdout.strip()
        self.write(self.worker, 'reviews/1-t-0001.md', REVIEW_FILE.format(head=code))
        sh(['git', 'add', '-A'], cwd=self.worker)
        sh(['git', 'commit', '-qm', 'review(T-0001): round 1'], cwd=self.worker, env_=self.ident)
        sh(['git', 'push', '-q', '-f', 'origin', self.B], cwd=self.worker)
        self.push_main({'c.txt': 'c\n'}, 'chore: c (#99)')   # the branch now carries a copy
        self.session('coder-t-0001', 'T-0001', self.B)
        sh(['git', 'fetch', '-q', 'origin'], cwd=self.repo)
        self.tip = sh(['git', 'rev-parse', f'origin/{self.B}'], cwd=self.repo).stdout.strip()

    def record(self, state):
        harvest.mark_session(self.state_dir, 'coder-t-0001', branch=self.B, lane={
            'state': state, 'head': self.tip, 'item': 'T-0001', 'pr': None,
```
