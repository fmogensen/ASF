# F-0344 — the factory writes two flat-file trees and owns neither

Operator, 2026-10-10: *centralized logging and metrics on flat files*. Stage 1 of three, and the
only stage in 0.3.

The factory already writes everything down on flat files. It writes them in **two trees**. The
transcripts go under `~/.ASF/logs`: a clock's whole stdout and stderr, a worker session's JSONL
run log, the hook's tracebacks, a red gate's output. The metrics go under the record clone's
`metrics/<stream>/<day>.jsonl`: validated events, keys sorted, one object per line, with a rollup
over them (`asf/metrics/metrics.py:1-20`).

Nothing owns either tree. Twelve call sites mint a path to a log under the transcript tree, seven
of them rebuilding `ASF_HOME` + `logs` by hand rather than calling the one helper that exists
(`asf/env.py:1066-1070`); two of them are independent spellings of the same job-transcript path
(P1). The rotation that would bound a file is written twice, with the same cap and the same
single generation, in two modules that cross-reference each other in comments
(`asf/approvals.py:1081`, P2) — and neither copy is on any of the files that actually grow. So the
tree on this host holds **3.7 GiB in 4475 files with no rotated generation anywhere in it**,
its largest single transcript 291 MiB, its oldest byte untouched since 2026-09-21 (P3, P5). One
`asf scorecard` pass reads 342 MiB of it whole into memory (P14). The doctor has 68 rows and not
one of them is about either tree (P7), and the code already says the quiet part out loud: *"The
log is never rotated, so reading all of it to find one line is an unbounded cost on every `asf
doctor`"* (`asf/doctor.py:1441-1443`), and *"a job log is cleaned up well after its registry
row"* (`asf/scorecard/facts.py:469-472`) — by a cleanup that does not exist.

The metrics tree is in better shape and has the same hole. Its largest stream by bytes is
`events`, and `events` is not in `metrics.STREAMS` (`asf/metrics/metrics.py:44`), has no
`natural_key` branch, and is therefore written by two callers that open the day file and append a
line themselves rather than going through the one validating appender — which
`asf/record/ingest.py:129-131` documents as the reason (P13). Nothing reads the shape of that
tree either, so a stream that stopped being appended reads exactly like a quiet week.

This card is one rule for both trees: **one module owns what the factory writes to flat files —
where it goes, how big it may get, how long it is kept, and what is in there now.** Stage 1 puts
that owner in place, bounds the transcript tree, and makes both trees legible. It ships no new
backend and moves nothing off the host; that is what Stages 2 and 3 are for, and the census this
stage writes is the one thing a later stage has to ship.

  `asf/connectors/launchd.py:61-63` puts the path in `StandardOutPath` and `StandardErrorPath`;
  the cron backend renders `>> {log} 2>&1` (`asf/scheduler.py:656`). In both cases the fd is
  opened before asf's code runs and held for the whole run.
* **P7 — no doctor row is about either tree.** `asf/doctor.py` `run()` appends 68 named rows. The

* **P8 — the names this card needs are free.** No `asf/logs.py`; `logs` is not a command in

* **P9 — renaming a clock transcript mid-run sends the rest of that run into the rotated file.**
  Measured directly: open a file, write, `os.replace` it to `.1`, write again. The live path does
  **not exist** afterwards and the second line is in `clock.log.1`. This is P6's consequence, and
  it is why the two existing copies of the rotation are safe only on the files asf itself opens
  per write.
* **P10 — truncating a clock transcript in place leaves a hole and lies about its size.**
  Measured: write 1 MiB through a held fd, `truncate(0)` it from another, write a 10-byte line.
  `os.path.getsize` reports **1048586** — the pre-truncation size plus the new line — the file
  begins with 1048576 NUL bytes, and `du -k` still charges 1028 KiB. A census built on `getsize`
  would never see the file come back under its cap, so the reaper would fire on it every tick for
  ever.
* **P11 — rotating at the end of a run, with the fd the run still holds, is exact.** Measured:
  with the clock's fd open on the inode, `os.replace` to `.1` after the last line moves the whole
  completed transcript; the next invocation's backend `open` creates a fresh live path. No dup2,
  no hole, and no run split across two files.
* **P12 — a cap loses history, and which history decides whether it lies.** Over the real
  `release.parse_tick_log` and `release.upgrade_facts`: a three-link upgrade chain reads as 3
  upgrades and `chain_breaks == []`. Drop the **two oldest** lines and it reads as 1 upgrade and
  still `chain_breaks == []` — it under-reports, it does not lie. Drop the **middle** line and it
  reads as 2 upgrades and one invented `chain_breaks` row, `{'installed': 'ccccccc', 'after':
  'bbbbbbb', …}` — a hand install that never happened. Reading both generations back, in either
  order, restores the full chain.
* **P13 — the metrics tree's largest stream is undeclared and unvalidated.** On this host, one
  product's `metrics/`: `events` 19 day files / 6.84 MiB, `ci` 7 / 2.92 MiB, `sessions` 19 / 1.44
  MiB, `ticks` 19 / 1.10 MiB, `daily` 19 / 0.34 MiB, `landings` 18 / 0.28 MiB, `gates` 12 / 0.16
  MiB. `metrics.STREAMS` is `('ci', 'sessions', 'ticks', 'landings', 'gates')` — `events` and
  `daily` are not in it, though `asf/init.py:27-28` creates both. `natural_key`
  (`asf/metrics/metrics.py:352-361`) has no `events` branch, so `append_event` raises on one; the
  two writers open the day file directly instead (`asf/tick/tick.py:251-260`,
  `asf/record/ingest.py:126-146`), the second one documenting exactly that reason.
* **P14 — one scorecard pass reads a third of a gigabyte whole.** `_tick_logs` on this host: 4
  files / 342 MiB for one product, 6 files / 236 MiB for the other, each read with `f.read()`.
* **P15 — the health step is where the factory already tidies its own host.**
  `steps.STEPS` is `['record', 'health', 'groom', 'wave', 'prs', 'harvest', 'batch', 'watchdog',
  'daily']`, and `asf/tick/step_health.py` already runs `reap_worktrees` (`:314-325`),
  `branch_retention` (`:327-337`) and `stale_acts` (`:339`) — each wrapped so a sweep never stops
  a tick.
* **P16 — the windows a transcript's readers read over.** `metrics.CI_CATCH_UP_DAYS` is 14,
  `CI_TARGET_WINDOW_DAYS` and `scorecard.loop.LANE_DAYS` are 7, `metrics.SESSION_DAYS` is 1. 14 is
  the longest.
* **P17 — the worker environment is an allowlist, so a new clock variable does not leak into a
  session.** `asf/hermetic.py:65-67`: *"`worker` mode strips it with every other unlisted name"*.

### In

1. **`asf/logs.py` — the one owner of the transcript tree.** The tree's root, every path under it
   (a clock transcript, a job transcript, the jobs directory, a named log), the one copy of the
   rotation, the generation reader, the reap rule, and the census. All twelve minters of P1
   delegate to it; the two spellings of the job-transcript path become one.
2. **A cap on every file in the tree, enforced by whoever opens it.** A log asf opens per write
   keeps today's 4 MiB cap and today's behaviour exactly (P2). A clock transcript, whose fd the
   scheduler's backend holds (P6), is rotated **at the end of the run that wrote it**, by that run,
   with the fd it still holds (P11) — never mid-run (P9), never by truncation (P10).
3. **A carry set, so the cap costs no reader its facts.** A rotation of a clock transcript copies
   forward the handful of line kinds that later readers count over a window longer than the cap —
   the upgrade, skip, torn and rollback lines `asf/release.py:99-103` matches, and the offline line
   `asf/scorecard/program.py:52` matches — each preceded by the last ISO stamp seen before it, which
   is how `offline_lines` dates one (`asf/scorecard/program.py:153-165`). A test pins the coupling:
   a line matching any of those readers' own patterns survives a rotation.
4. **Both unbounded readers become bounded and streaming.** `scorecard.program._tick_logs` and
   `release.read_tick_logs` read the generations oldest-first through the module, line by line,
   never `f.read()` on a whole transcript (P4, P14) — and so never present the middle gap that P12
   measured as an invented hand install.
5. **A reap rule for the job transcripts** — the tree's 84% (P5). A transcript is removed when it
   is older than the longest window any of its readers reads over (P16) **and** its job is not a
   live session in the registry. It runs in the health step beside the reapers already there
   (P15), printed, never raised.
6. **Two doctor rows, one per tree.** `logs`: what the transcript tree holds, and whether anything
   in it is over its cap or past its keep window — the two conditions the factory can clear; the
   total bytes are reported, never judged. `streams`: what the metrics tree holds — streams on
   disk, day files, bytes, newest day — read from disk rather than from `STREAMS`, and naming any
   stream on disk that `STREAMS` does not declare (P13). Both advisory.

### Out

* **Any backend that is not a flat file** — a local database, an OTLP exporter, a hosted sink.
  The card says flat files and says this is Stage 1 of 3; this is the line between the stages.
* **Shipping anything off the host.** No upload, no remote write, no retention policy expressed
  anywhere but on this disk.
* **Changing a stream's schema, its location, its rollup, or `metrics.STREAMS`.** Stage 1's
  `streams` row *reports* that `events` is undeclared and unvalidated (P13); giving it a
  `natural_key` and routing its two writers through `append_event` is its own card, because that
  changes what the rollup reads.
* **Turning a clock transcript into JSONL.** It is a tty transcript of a run and stays one. The
  carry set (In 3) is the seam where a later stage lifts its facts into a stream instead.
* **Deleting a transcript by age alone.** Age is never the whole reason: the reap rule needs the
  registry to agree the run is over (In 5). A clock transcript is never deleted at all — it
  rotates.
* **Capping a worker session's transcript.** Its fd is held open by the runtime for the whole
  session, so a cap on it is P9 again, and its last line is the result record every reader of it
  wants (`asf/workers/runtime.py:8`) — a rotation at the wrong moment hides that line from
  health. Its bound is the keep window (In 5); the largest one on this host is 35 MiB (P5).
* **An `asf logs` command.** The census is a library call and two doctor rows in Stage 1 (In 6).
  A command over it is worth having and is not worth a new table surface here.
* **Retro-reaping what the tree already holds beyond the first pass.** The first health step after
  this lands reaps what the rule covers; what the *rotation* brings down is only the **0.57 GiB
  the tree's 23 clock transcripts hold today** (P3 counts the 23; four of their groups are over
  cap), and it comes down over each clock's next two runs, not in one sweep — the first rotation
  renames, the second frees. The rest of the tree's bulk is the reap's (In 5), not the rotation's:
  P3's 1.2 GiB over cap is 96 files tree-wide, mostly job transcripts.

### Preconditions the work depends on

* `env.log_dir()` is the single existing accessor and already creates the tree (P1) — the new
  module's root is that function, not a second definition of it.
* The scheduler's backends put the transcript path in the job definition's `log` key and nothing
  else writes it (P6), so a clock process can be handed its own path through the environment, and
  an unlisted variable does not reach a worker session (P17).
* `os.replace` at the end of a run is exact with the backend's fd held open (P11); mid-run rename
  (P9) and in-place truncation (P10) are both wrong, measured.
* Every reader of a job transcript already tolerates a missing one: `job_denials` *"counts 0,
  never raises — a job log is cleaned up well after its registry row"*
  (`asf/scorecard/facts.py:469-472`).
* The health step already carries three sweeps of the same kind, each wrapped so it cannot stop a
  tick (P15).
* A doctor row that is not `required` prints `skip` when it is `False` and `warn` only when its
  `ok` is the literal string `'warn'` (`asf/doctor.py:2250-2267`) — so an advisory row that wants
  to be seen must return `'warn'`, not `False`.

And the variable must be *popped*, not read: a clock-run tick spawns `asf` children of its own, and an inherited path would have a child rotate the file its parent is still writing — P9 again, from inside the factory rather than from a reaper |

| D6 | **The carried markers are plain substrings in `asf/logs.py`, with each reader named beside it, and a test proves every reader's own pattern still survives** | Import the readers' compiled patterns into `logs`; or give each reader a hook to register its own | Importing `release` and `scorecard.program` into the module every clock calls at the end of every run drags the release machinery into the tick's exit path for four regexes. A substring list is obvious on sight and its one risk — a reader's pattern drifting away from the marker — is exactly what the test pins, so the coupling is enforced rather than hoped for |

## The design

### 1. `asf/logs.py` — the tree, its paths, its cap

A new module, stdlib only, importing `asf.env` and nothing else of the package — it is called from
the installer, from the hook, and from a clock's exit path, none of which can afford a wide import.

```python
"""asf.logs — the factory's flat-file trees: the transcripts it writes and the streams it keeps.

Every path under ``~/.ASF/logs`` is minted here, every cap on one is declared here, and the one
rotation the tree has is implemented here once. The streams (``<record>/metrics/<stream>/<day>.jsonl``)
are :mod:`asf.metrics.metrics`'s to write; this module only reads their shape, for the census.
"""

#: An asf-opened log's cap: the file is rotated to ``.1`` when it is over this at append time.
#: Today's value and today's behaviour for the two logs that already rotate (the approvals hook's
#: traceback log, a red gate's output) — both delegated here, neither changed.
LOG_MAX_BYTES = 4 << 20

#: A clock transcript's cap. Three orders of magnitude more because the writer is different: the
#: scheduler's backend holds the fd for a whole run and everything the run prints goes through it.
#: With one generation kept and both read, this is the floor of history a reader can count on; the
#: facts that outlive it are carried (:data:`CARRY`).
CLOCK_LOG_MAX_BYTES = 16 << 20

#: How many rotated generations are kept, for every log in the tree. One, as both pre-existing
#: rotations kept: the surviving text is then always contiguous, so a cap can drop the oldest
#: history but can never open a gap in the middle of it (F-0344 P12, D4).
GENERATIONS = 1

#: The environment variable a clock's own transcript path is passed in, written by the scheduler
#: backends that already render the path (``asf.connectors.launchd``, the cron line). Unset for a
#: hand-run command, so one rotates nothing. :func:`claim_own` **pops** it from the environment as
#: the run's first act, so no child of the run can inherit it and rotate the file its parent is
#: still writing (D3).
OWN_LOG_VAR = 'ASF_LOG'

#: Line kinds a clock transcript's rotation carries into the fresh file, because a reader counts
#: them over a window longer than the cap. Each is a plain substring; the test
#: ``CarryTests.test_every_readers_own_pattern_survives_a_rotation`` pins that the reader named
#: beside it still matches what a rotation keeps.
CARRY = (
    'tick: ran asf upgrade',              # asf.release._UPGRADE_RE
    'tick: asf upgrade skipped',          # asf.release._SKIPPED_RE
    'rolled back',                        # asf.release._ROLLBACK_RE
    'rollback:',                          # asf.release._ROLLBACK_RE
    'ImportError',                        # asf.release._TORN_RE
    'ModuleNotFoundError',                # asf.release._TORN_RE
    'tick: record failed — offline',      # asf.scorecard.program.OFFLINE_LINE
)

#: An ISO stamp line is carried with the line that follows it: `offline_lines` dates an offline
#: line by the newest stamp printed before it, and the stamp lines themselves are not rare.
_STAMP_RE = re.compile(r'\b\d{4}-\d\d-\d\dT\d\d:\d\d:\d\dZ\b')

#: A job transcript is kept this many days. The longest window any of its readers reads over
#: (`metrics.CI_CATCH_UP_DAYS`), so the reap costs no reader a line it reads today (D7).
JOB_LOG_KEEP_DAYS = 14


def tree():                          # ~/.ASF/logs, created — env.log_dir(), not a second copy
def path(*parts):                    # one path under the tree, parent directories created
def clock_path(product, clock):      # tick-<product>-<clock>.log
def host_clock_path(clock):          # <clock>.log — the host probe's, no product
def kernel_path(product, which):     # kernel-<product>.log / kernel-watch-<product>.log
def jobs_dir(product):               # jobs/<product>/, created
def job_path(product, job):          # jobs/<product>/<job>.jsonl
def claim_own():                     # pop OWN_LOG_VAR, keep the path for this process only
def own_path():                      # what claim_own took, or None
```

`tree()` returns `env.log_dir()` — the existing accessor stays where it is and keeps its callers;
this module is the one that *names* what goes in it. The seven hand-built paths of P1 become

### 2. `asf/logs.py` — the rotation, once

```python
def rotate(path, cap, carry=()):
    """Rotate ``path`` to ``path + '.1'`` when it is over ``cap``; the rotated path, or None.

    One generation (:data:`GENERATIONS`): a previous ``.1`` is replaced. With ``carry`` (line
    substrings), the rotated file's matching lines — each preceded by the last ISO stamp line seen
    before it — are written as the head of the fresh live file, so a reader that counts them over
    a window longer than the cap still finds them (D5).

    Never raises: a log is never a reason to fail (`harvest.keep_red_output`'s rule, kept).
    """
```

Two callers, by who holds the fd:

* **An asf-opened log, at append time.** `approvals._log_traceback` and `harvest.keep_red_output`
  each lose their four inline lines and call `logs.rotate(path, logs.LOG_MAX_BYTES)` before
  appending. Same cap, same single generation, same `.1` name: the two existing tests
  (`tests/test_approvals.py:732` and the gate's) stay green unchanged, which is the proof that
  behaviour did not move.
* **A clock transcript, at the end of the run.** Two calls around the CLI's dispatch, so every
  clock command is covered by construction — the product tick (`asf/tick/tick.py:420`), the host
  probe (`asf/tick/network.py:415`), and the kernel's tick and watch (`asf/cli.py:731`):

  ```python
      logs.claim_own()                     # first act: take the path, and take it out of the env
      try:
          rc = dispatch(args)
      finally:
          logs.rotate_own()                # over CLOCK_LOG_MAX_BYTES -> .1, with CARRY
  ```

  `claim_own` **pops** `OWN_LOG_VAR` rather than reading it, and that is not tidiness. A clock-run
  tick spawns `asf` children of its own — the background harvest (`asf/tick/step_harvest.py:136`),
  the smoke's no-op commands (`asf/scheduler.py:780-794`) — and a child that inherited the
  variable would reach its own `finally` *while its parent is still writing the file*, which is
  exactly P9: the rest of the parent's run would go to `.1` and the live path would not exist.
  Popping it means only the process the scheduler started can rotate, and the worker-session
  environment never has to list it (P17 makes that true anyway; this makes it true for every other
  child too). A hand-run `asf tick` has no variable to claim and rotates nothing.

The scheduler backends write the variable they already render the path for: `env_vars[OWN_LOG_VAR]
= log` in `asf.connectors.launchd`'s plist `EnvironmentVariables` and in the cron line's `envs`,
for a product clock (`scheduler.py:605-630`), the host probe (`:687-700`) and the kernel's two
jobs (`kernel/host.py:84-93`). It is unlisted in the worker environment, so no session inherits it
(P17).

A run killed before its exit — a launchd bootout, a crash — rotates nothing, and the next
completed run of that clock does it instead. The cap is therefore a floor on history and a
ceiling plus one run's output, which at the measured rates is the difference between 16 MiB and
perhaps 17; it is never the 291 MiB of P3.

The carried head is itself carried by the next rotation, so the carried lines accumulate for as
long as the clock exists. They are rare by construction — the five kinds in `CARRY` are an
upgrade, a skipped upgrade, a rollback, a torn tick and an offline tick — so at this host's rates
that head grows by tens of kilobytes a year, and it is the one part of a transcript that is meant
to be kept. If it ever stops being negligible, that is the signal that those lines want to be
stream rows, which is Stage 2 (D5).

The `streams` row stays `warn` until the card that declares `events` lands — which is the point of
printing it.

and the point is the word *settles*, not the number: it has a steady state instead of a slope. 14
days of job transcripts at the measured 164 MiB a day is ~2.3 GiB of it (P5, P16); the 23 clock
transcripts are 0.57 GiB today and 0.09 GiB once each is under its cap, ~0.18 GiB with a
generation each. Stage 1 bounds the tree; it does not make it small. The one lever that would make
it small is the keep window, and the window is pinned to the longest window a reader reads over

should not read this card as a disk-space card, and the `logs` row is deliberately not a budget

In the tree itself: every clock transcript has a `.log` under its cap and, once it has rotated
once, a `.log.1` beside it whose head is the carried lines. `~/.ASF/logs/jobs/<product>/` holds
the last fortnight. The 291 MiB file stops growing at its first rotation and leaves the tree at
its second, and nothing in the tree can become it again.

## Records

**What the change writes to disk.** Nothing new of its own. The transcript tree gains `.log.1`
files — one generation per clock transcript that has rotated at least once, whose head is the
carried lines of the generation before it. It loses job transcripts older than
`JOB_LOG_KEEP_DAYS` whose runs the registry agrees are over. No file is created that was not
being created before.

**What the change writes to the record.** Nothing. No new stream, no new `metrics/` directory, no
new event kind. The `streams` doctor row reads the metrics tree and never writes it.

**The rows it prints.** Two doctor rows, `logs` and `streams`, both advisory, both rendered by
`doctor.format_table` from `(name, required, ok, detail)` with `ok` either `True` or the literal
`'warn'`. Neither can redden `asf doctor` (`is_red` reads `required and ok is False`).

**The tick lines it prints.** One, from the health step, and only when it removed something:
`logs: reaped <n> job transcripts (<bytes>)`. A sweep that fails prints `logs: skipped — <type>:
<message>` and the tick carries on, as the three sweeps beside it do. A rotation prints nothing at
all: it happens on the exit path of a run whose output is the file being rotated.

**The events it does not write.** No `metrics/events` line, no ledger line, no session record. A
reap is a host-tidying sweep, not a decision about an item, and nothing downstream counts it. If a
later stage wants the reap counted, that is the stage that moves transcript facts into streams
(D5, Out).

**What a reader can rely on afterwards.** For any log in the tree: its live file is under its cap
plus at most one run's output, and `logs.generations(path)` is the complete, **contiguous** text
the tree still holds for it, oldest first. For a clock transcript, the line kinds in
`logs.CARRY` survive every rotation. For a job transcript: it exists for at least
`JOB_LOG_KEEP_DAYS` after its run ended, and a reader that finds it missing counts zero rather
than failing, exactly as `scorecard.facts.job_denials` already does.
