# F-0101 — the model follows the need, and the spend says so

Session spend to date is $365. Sessions of kind *other* — corrections, adjudications and grooms —
cost $91.50 of it (25 %, 55 sessions at $1.66 each): almost as much as every spec written
($88.72) and more than twice every bug fixed ($25). Many of those were corrections of mechanical
failures — *not pushed*, *unpushed work*, *empty branch* — which need no judgement at all.

Since 2026-09-21 a per-kind table exists: `briefs.build.DEFAULT_MODELS` maps `correct` and
`fix-bug` to `light`, `spec`/`plan`/`adjudicate`/`groom` to `heavy`, and `step_wave` launches
every feeder row on the label its brief carries. That table is younger than the spend above, and
it is not yet the rule the card asks for. Four things are still true today:

| Today | Why it costs |
| --- | --- |
| The table is keyed on the **kind** alone. One kind, `correct`, covers both "push what you have" and "the gate is red for a reason nobody has read yet" — one rule cannot be right for both. | the card's first line: *the model is chosen by the job's need, not its kind* |
| `models:` is not a field of `Conventions`. It survives in `extra`, undocumented, unvalidated: a typo (`corect: light`) is silently the default, and a label no `worker_pool.models` maps kills the session at launch. | the config half of the card |
| Two other paths launch sessions and neither reads the table: `stall.correct_once` re-runs a dead session on the model **recorded on that session**, and `pr_hygiene.render` writes a vendor model name into its launch line by hand. | the "regardless" in B-0080's title |
| Nothing records which label a session ran on, and the stream's `kind` collapses `correct`, `adjudicate`, `groom`, `close` and `reshape` into `other`/`code`. The 25 % above had to be counted by hand. | the metric half of the card |

This spec makes one resolver the only answer to "which model", teaches it the correction's
*cause*, records the label on every launch, and turns the heavy share into a rollup metric with a
threshold that files a Bug.

## 1. Decisions

### 1.1 In

- **`asf.conventions`** — `HEAVY` / `LIGHT` move there, so the labels have one owner. A new field
  `heavy_share_pct` (default 50) carries the threshold. Whether `models` becomes a typed field
  with `DEFAULT_MODELS` as its default is reconciled against `model_for`'s already-shipped item
  class axis, not landed as originally fenced (P12).
- **`asf.briefs.build.model_for(product, kind, …)`** — the one resolver. It resolves a
  **need key**, then reads `conventions.models` for that key. The only kind that splits is
  `correct`: a mechanical cause resolves `correct` (light), anything else resolves
  `correct/judgement` (heavy) — composed with the item-class axis `model_for` already has (P12).
- **`asf.workers.lifecycle`** — the cause vocabulary it already writes (`unpushed`,
  `pushed after stop`, `conflict`, `merge`, `naming`, `gate`, `died`) named as constants, plus
  `mechanical(kind, text)`: the one place that says whether a correction needs judgement.
- **`asf.feeder.rows.Row.correction_kind`** — the cause carried onto the row beside the text it
  already carries, so the resolver can see it. No logic in the feeder; a pass-through.
- **`asf.workers.stall.correct_once`** — the cold retry stops inheriting the dead session's
  recorded model id and resolves its own, through `model_for` and `spawn.model_arg`.
- **`asf.harvest.pr_hygiene.render`** — the `CONFLICT → REBASE` line prints the resolved label
  for `rebase` instead of the literal it carries today.
- **The record**: every launch writes `model_label` beside `model` (the id) —
  `spawn.spawn`, `stall.correct_once` — and `metrics.session_event` carries it into the
  `sessions` stream, which gains the key in its schema.
- **`metrics.RECORD_KINDS`** — `correct`, `adjudicate`, `groom`, `close`, `reshape`, `coder`,
  `fixer` mapped, so a session's kind in the stream is the kind it ran as.
- **The rollup** — a `## Spend by kind × model (7 days)` table, and one `model spend` row in the
  waste table carrying the heavy share against its threshold.
- **`file_bugs.spend_signatures`** — a fourth source: the heavy share above
  `conventions.heavy_share_pct` files (or bumps) one S2 Bug, on a stable signature.
- **`asf doctor`** — a `models` row: every key of the table is a need key, every value is a label
  `worker_pool.models` maps.
- Tests for model selection **per row** (§3.1), per cause (§3.2) and per launch path (§3.3).

### 1.2 Out

- **Vendor model names.** The card writes `models: {correct: sonnet, adjudicate: opus}`; this
  repo is public and its labels are `light` and `heavy`, mapped to ids in the operator's own
  `worker_pool.models` (`spawn.model_arg`). Read the card's `sonnet` as `light` and its `opus`
  as `heavy` throughout. `pr_hygiene.py`'s hand-written `(Sonnet)` is deleted for the same
  reason, and no vendor id enters a tracked file.
- **A third label.** `heavy` and `light` stay the whole vocabulary. A product that wants a middle
  tier maps a third label in its own config; nothing here needs to change for it, and nothing
  here adds one.
- **Retiring the per-kind table for a per-row cost model.** The need key is derived from the kind
  and, for one kind, the cause. No estimator, no token budget, no learned policy.
- **The cold retry's model.** `stall.correct_once` re-runs the *whole original brief* — a dead
  spec session's retry writes the spec — so its need is its own kind's, not `correct`'s. It
  resolves that need instead of inheriting an id (§2.4); it does not drop to light.
- **Re-labelling the 55 sessions already recorded.** Events on disk carry no `model_label` and
  none is invented for them: §2.6 reports them as `(unlabelled)` and leaves them out of the
  share's denominator, saying how much was left out.
- **Changing what `adjudicate` costs.** Every adjudicate row — the round-limit one and the
  groom's — stays heavy, as the card asks. No split.
- **The budget machinery.** `budget_usd` on an Epic and the rollup's `budget:` lines are
  untouched; the threshold here is about the *mix*, not the total.

### 1.4 The choices

| Choice | Chosen | Against | Why |
|---|---|---|---|
| What the table is keyed on | a **need key**: the kind, or `correct/judgement` for the one kind that covers two needs | a key per kind (today); a key per feeder row kind (`FIX → CORRECT`, `STALEMATE → ADJUDICATE`) | The card's first line is that the need decides. Exactly one kind today serves two needs, so exactly one key splits — a key per row kind would be eleven config keys for one real distinction. |
| How the split is written in config | one flat table, `models: {correct: light, correct/judgement: heavy, …}`, looked up by need key then by the kind before the `/` | a nested `models: {correct: {mechanical: …, judgement: …}}` | A product that only wants "all corrections light" writes one line and the refinement inherits it. The lookup is two `dict.get`s and prints in one table in the doctor row. |
| Which causes are mechanical | `unpushed`, `pushed after stop`, `conflict`, `merge`, `naming`, and `gate` **when its text names a test** | every cause, including `gate` and `died` | These are exactly the card's list — push, commit, rebase, a red gate with a named test. A gate line with no test name (a forbidden name, a lint, a timeout) is a question, not a chore. |
| Who owns "is this mechanical" | `asf.workers.lifecycle`, beside `hold` and the cause strings it writes | `asf.briefs.build`, beside the table | The module that *writes* a cause owns what the cause means; a second copy of the vocabulary in `briefs` drifts the first time harvest adds a cause. `briefs` maps a cause to a label — that is the model policy, and it stays there. |
| What counts as "a named test" | a regex over the correction's one line: a `test_*` token, or a `*.py::*` node id | parsing the gate's whole output; a per-product `test_name_pattern` | The correction carries one line (P7), and both test runners this repo knows print the name on it. A pattern in config is a convention nobody would set and a default nobody would read. |
| `died` (a session dead twice) | judgement → heavy | mechanical → light | Two deaths with no result is the one case where somebody has to read a log. It is also rare and capped: the third hold is the adjudicate row. |
| The cold retry's model (`correct_once`) | the **original kind's** need, resolved fresh | inherit the id recorded on the dead session (today); force `correct` | The retry is handed the original brief plus one line of failure — it writes the spec that never got written, so it is spec work. Resolving fresh (not inheriting) is what makes a product's retuned `models:` reach the retry, and what stops a hand-launched off-table id from propagating. |
| Where the label is recorded | a new `model_label` on the session record and the stream event | inverting `worker_pool.models` at rollup time | The rollup runs in the record clone and is readable with no operator config at all (`cmd_rollup` falls back to `DEFAULTS`); an id→label map that only exists in the operator's config cannot be the metric's input. The launcher knows the label — it writes it down. |
| Events already on disk | `(unlabelled)`, kept in the totals, out of the share's denominator, with their sum printed | backfill a label from the id; drop them from the table | Nothing here can honestly say which label a session from 2026-09-14 ran under. Printing the unlabelled sum is the honest form, and it shrinks to nothing within a week. |
| The threshold's default | `heavy_share_pct: 50`, over the labelled spend of the last 7 days, and only once that spend is at least $20 | the card's 25 %; no floor | 25 % is the *share of one kind group* the card measured, not the heavy share of all spend — a factory whose specs and plans are heavy sits above 25 % while behaving exactly as designed. 50 % of spend on judgement work is the point where the mix is worth a Bug. The floor stops a $3 day from filing on one session. |
| Where the metric lives | one `model spend` row in the waste table, and a kind × model table below the cost table | a new metrics stream; a separate file | The waste table is where a tracked metric with a threshold already lives, and the rollup already reads the 7-day sessions window for the cost table — the new table is the same rows, grouped differently. |
| The Bug's signature | the constant `spend: heavy share over threshold` | one signature per day, or per kind over the threshold | A stable signature is what makes the existing filer *bump* rather than file a second Bug every day (P10). Which kinds are heaviest goes in the evidence lines, where it is re-read on every bump. |
| `RECORD_KINDS`' new entries | added, so the stream's kind is the row's kind | leave `adjudicate → other` and let the rollup group by job-name prefix | The card's own numbers had to be counted out of an `other` bucket. A metric whose rows are named after what they are is the whole point of the table. |

## 2. The design

### 2.1 `asf/conventions.py` — the labels, the table, the threshold

`HEAVY`, `LIGHT` and `heavy_share_pct` below are landed as fenced. `DEFAULT_MODELS` and the
`models` field are not (P12): `DEFAULT_MODELS` stays derived from `asf/briefs/build.py`'s
`MODEL_TABLE`, and `models` stays a `map_of` convention, until the task that reconciles the class
axis lands.

```python
#: The operator's two model labels. worker_pool.models maps them onto real model ids
#: (asf.workers.spawn.model_arg), so no vendor's model id is written down in this repo.
HEAVY = 'heavy'
LIGHT = 'light'
#: need key -> label. A need key is a brief kind, or `<kind>/<refinement>` where one kind
#: covers two needs (see asf.briefs.build.need_key).
DEFAULT_MODELS = {
    'spec': HEAVY, 'plan': HEAVY, 'adjudicate': HEAVY, 'review': HEAVY, 'groom': HEAVY,
    'reshape': HEAVY, 'correct/judgement': HEAVY,
    'coder': LIGHT, 'fixer': LIGHT, 'rebase': LIGHT, 'close': LIGHT, 'fix-bug': LIGHT,
    'correct': LIGHT,
}
#: The share of labelled 7-day spend on HEAVY above which the rollup calls the mix a defect.
DEFAULT_HEAVY_SHARE_PCT = 50
```

and two fields on `Conventions`:

```python
    models: dict = field(default_factory=lambda: dict(DEFAULT_MODELS))
    heavy_share_pct: int = DEFAULT_HEAVY_SHARE_PCT
```

`models` is taken as the product wrote it, exactly like `branch_prefixes`: a key the product does
not name falls back to `DEFAULT_MODELS` in the resolver, not in `from_mapping`, so a product that
sets one key does not lose the other ten. `briefs.build` imports `HEAVY`/`LIGHT`/`DEFAULT_MODELS`
from here and keeps no copy (`check_conventions.sh` exempts `asf/conventions.py` by construction,
and P4 means the dict generates no pattern).

### 2.2 `asf/briefs/build.py` — the need, then the label

Not landed as fenced (P12): `model_for(product, kind, item=None)` already exists, so this task
reconciles `need_key`'s cause with the shipped `item`-carried class rather than replacing `item`
with `row`.

```python
JUDGEMENT = 'correct/judgement'

def need_key(kind, row=None):
    """The need a job has, not the kind it is. Every kind is its own need but `correct`, which
    covers both a mechanical failure (push, commit, rebase, a red gate with a named test) and a
    failure somebody has to read."""
    if kind != 'correct':
        return kind
    cause = getattr(row, 'correction_kind', '') or ''
    text = getattr(row, 'correction', '') or ''
    return kind if lifecycle.mechanical(cause, text) else JUDGEMENT


def model_for(product, kind, row=None):
    """`conventions.models[<need key>]`, else `[<kind>]`, else the default for that need,
    else LIGHT."""
    table = conventions(product).get('models') or {}
    need = need_key(kind, row)
    for key in (need, need.split('/')[0]):
        if table.get(key):
            return table[key]
    return DEFAULT_MODELS.get(need) or DEFAULT_MODELS.get(kind, LIGHT)
```

`build()` passes the row it already has: `model=model_for(product, kind, row)`. Nothing else in
the brief path changes — `Brief.model` is still the label, `step_wave.worker_row` still copies it
onto the worker row, `spawn.model_arg` still maps it to an id.

A correction row with no cause recorded (an older ledger line, a hand-written row) has
`correction_kind=''`, which `mechanical` answers `False` for: it resolves `correct/judgement`,
heavy. The conservative direction is the one that does not write a spec on the wrong model.

### 2.3 `asf/workers/lifecycle.py` — the cause vocabulary

```python
GATE = 'gate'
CONFLICT = 'conflict'
MERGE = 'merge'
NAMING = 'naming'
DIED = 'died'
UNPUSHED = 'unpushed'              # already there
PUSHED_AFTER_STOP = 'pushed after stop'   # already there
CAUSES = (GATE, CONFLICT, MERGE, NAMING, DIED, UNPUSHED, PUSHED_AFTER_STOP)

#: A correction whose text names a test names the work: `FAIL: test_x (tests.test_y.C.test_x)`,
#: `FAILED tests/test_y.py::test_x`. A gate line with no test name — a forbidden name, a lint,
#: `gate timed out after 900 s` — names no work and is read, not fixed.
NAMED_TEST_RE = re.compile(r'\btest_\w+|\b[\w./-]*test[\w.-]*\.py::\S+')

#: Causes a session fixes without judgement: push, commit, rebase.
MECHANICAL = (UNPUSHED, PUSHED_AFTER_STOP, CONFLICT, MERGE, NAMING)


def mechanical(kind, text=''):
    """True when the correction named by `kind` is a chore: the five causes above always, and a
    red `gate` when its text names the failing test."""
    if kind in MECHANICAL:
        return True
    return kind == GATE and bool(NAMED_TEST_RE.search(text or ''))
```

`harvest` and `health` pass the constants where they pass literals today; the strings on disk do
not change, so every ledger already written classifies.

### 2.4 The three launch paths, one rule

| Path | Today | After |
|---|---|---|
| `tick.step_wave` → `briefs.build` → `workers.wave` → `spawn.spawn` | `model_for(product, kind)` | `model_for(product, kind, row)` — the row's cause reaches the table |
| `workers.stall.correct_once` (the cold retry of a dead session) | `model=session.get('model')` — the id recorded on the dead run | `model_arg(model_for(product, session.get('kind')), cfg)` — the kind's need, resolved fresh; the recorded id is never inherited |
| `harvest.pr_hygiene.render` (the `CONFLICT → REBASE` line a person pipes into `asf workers spawn`) | `… → launch rebase-<slug> (Sonnet)` | `… → launch rebase-<slug> ({model_for(product, 'rebase')})` — `render(row, conv=None, product=None)`; with no product it prints the default label |

`correct_once` gains no new argument: it has `product`, and `stall._cfg()` is already the config
reader it needs. The retry's ledger line gains `model_label` beside its `model`, and keeps the
kind of the session it retries (§1.2).

### 2.6 The rollup

`render_daily` gains a section under the cost table, over the same 7-day window:

```

2026-09-17 … 2026-09-23; labelled $118.40 of $131.90 — $13.50 ran before the label was recorded.

| Kind | Model | Sessions | USD | Share |
|---|---|--:|--:|--:|
| spec | heavy | 14 | 48.20 | 37 % |
| adjudicate | heavy | 9 | 21.10 | 16 % |
| correct | light | 22 | 8.40 | 6 % |
| … | | | | |
| (unlabelled) | — | 55 | 13.50 | — |
| **All** | | 112 | 131.90 | |
```

Share is of **all** spend in the window, so the column sums to 100 % with the unlabelled row.
One row joins the waste table (`scorecard_rows`), which is where the tracked metric lives:

```
| model spend | heavy 59 % of $118.40 labelled | threshold 50 % — over; $13.50 unlabelled |
```

Under the threshold the note reads `threshold 50 % — ok`. With no labelled spend at all the
value is `no labelled spend` and the row never claims a share it cannot compute.

```python
def spend_by_kind_model(sessions):
    """{(kind, label or None): {'sessions': n, 'usd': float}} for one window."""

def heavy_share(sessions, heavy=HEAVY):
    """(share_pct or None, labelled_usd, unlabelled_usd) — None when nothing is labelled."""
```

Both are pure functions over the event list, which is what makes §3.4 a unit test and not a
fixture-driven one.

### 2.7 The threshold that files a Bug

```python
SPEND_WINDOW_DAYS = 7
#: No Bug below this much labelled spend in the window: a quiet day is not a defect.
SPEND_FLOOR_USD = 20.0
SPEND_SIG = 'spend: heavy share over threshold'


def spend_signatures(root, now, conv=None):
    """The heavy share of labelled session spend over the last SPEND_WINDOW_DAYS, against
    `conventions.heavy_share_pct`. One signature, or none."""
```

It reads `metrics/sessions/*.jsonl` through `_jsonl_lines` the way the other three sources read
their streams, and yields at most:

```python
{SPEND_SIG: {'title': 'Heavy-model spend is 59 % of the last 7 days (threshold 50 %)',
             'severity': 'S2', 'runs': [],
             'evidence': ['2026-09-17 … 2026-09-23: heavy $69.90 of $118.40 labelled (59 %), '
                          'threshold 50 %',
                          'spec/heavy: 14 sessions, $48.20',
                          'adjudicate/heavy: 9 sessions, $21.10',
                          'correct/light: 22 sessions, $8.40']}}
```

`cmd_file_bugs` adds `signatures.update(spend_signatures(root, now, conv))` as its fourth source.
Everything else — the S2's `decided: true`, the parent Epic, the same-day no-op, the
`file_bug` approval hold — is the existing filer's, unchanged.

### 2.8 `asf doctor`

One more row, appended like `capacity`'s (`required=False`: a wrong table is not a reason to
call the whole factory red, and the launch itself already refuses an unmapped label):

```python
def check_models(cfg, product):
    """[(ok, detail)] — every key of conventions.models is a need key, every value is a label
    worker_pool.models maps."""
```

- an unknown key → `models: 'corect' is not a job need (have: spec, plan, …, correct/judgement)`
- a label with no id → `models: 'medium' for 'plan' is not in worker_pool.models (have: heavy, light)`
- clean → `models: 12 needs, 2 labels — heavy: spec, plan, adjudicate, review, groom, reshape, correct/judgement`

### 2.9 What does not change

`step_wave`, `wave.wave`, `pool.pick_account` and `Pool.caps` are untouched: they take the label
they are handed and the per-model account cap keeps working on it. `spawn.model_arg` still
refuses an unmapped label with `NEEDS OPERATOR`. No brief template changes. No feeder row kind is
added or removed, and no row changes tier.

## 3. Acceptance tests

Each block is runnable from the repo root.

### 3.1 Model selection, per row

```bash
python3 -m unittest -v tests.test_briefs.KindModelGrantTest tests.test_briefs.ModelNeedTests
```

Covers: every kind's default label; a product override of one key leaving the rest default; a
`correct` row whose cause is each of the five mechanical causes → `light`; a `gate` row whose text
names a test → `light`; a `gate` row whose text is `check_generic: forbidden name found` or
`gate timed out after 900 s: …` → `heavy`; a `died` row → `heavy`; a correction row with no cause
→ `heavy`; `models: {correct: heavy}` lifting both correction needs; `models:
{'correct/judgement': light}` lowering only the refinement.

### 3.2 The cause vocabulary

```bash
python3 -m unittest -v tests.test_lifecycle.MechanicalCauseTests tests.test_harvest.HoldCauseTests
```

Covers: `mechanical()` over every constant in `CAUSES`; `NAMED_TEST_RE` over a unittest `FAIL:`

## 4. Records

**Config, new** — `products/<p>.yaml`, under `conventions:`:

```yaml
conventions:
  # need key -> model label; a key not named falls back to the default below.
  models:
    spec: heavy
    plan: heavy
    adjudicate: heavy        # the round limit and the groom's adjudicator both
    review: heavy
    groom: heavy
    reshape: heavy
    correct: light           # push, commit, rebase, a red gate naming its test
    correct/judgement: heavy # a red gate naming no test, a session dead twice
    coder: light
    fixer: light
    fix-bug: light
    rebase: light
    close: light
  # the share of labelled 7-day spend on the heavy label above which a Bug is filed
  heavy_share_pct: 50
```

The labels themselves are mapped to ids where they already are — the operator's `config.yaml`,
`worker_pool.models` — and nothing about that mapping changes.

**The session record** (`~/.ASF/state/<product>/sessions.jsonl`) gains one key on every launch
line:

```json
{"job": "correct-b-0091", "kind": "correct", "model": "<runtime id>", "model_label": "light",
 "account": "…", "pid": 4242, "…": "…"}
```

**The `sessions` stream** (`metrics/sessions/<day>.jsonl`, in the record clone) gains
`model_label` (`str|null`), and its `kind` now carries `correct`, `adjudicate`, `groom`, `close`
and `reshape` instead of folding them into `code`/`other`. Events already written are unchanged
and remain valid.

**The daily rollup** (`metrics/daily/<day>.md`): one new waste row, `model spend`, and one new
section, `## Spend by kind × model (7 days)`.

**A Bug**, filed by `file-bugs` at most once a day, bumped thereafter:

```yaml
type: bug
title: Heavy-model spend is 59 % of the last 7 days (threshold 50 %)
severity: S2
decided: true
found_in: ci
signature: 'spend: heavy share over threshold'
count: 1
last_filed: 2026-09-24
parent: <conventions.default_bug_epic>
```

**Not written.** No new stream. No new state file. No field on any other card. No change to
`metrics/events` or to the `launch` event, which already carries `model` — it keeps carrying the
id, and the label is read from the session stream.
