# F-0091 — `asf improve`, a weekly tick step

D-0050 says every saving spotted becomes a card with a number behind it. The pass that spots
them ran once, today, because someone asked for it. A rule only a session remembers is not a
rule. This spec turns that one sitting into a step the tick runs weekly, off data the factory
already writes every tick.

Nothing here is new measurement infrastructure. The three sources exist: the session registry
(`~/.ASF/state/<product>/sessions.jsonl`), the job logs beside it, and the record's own
`metrics/`. The pass is arithmetic over them, a page in the record, and a proposed card per class
of waste that is over its threshold.

**Verified against the live `asf` registry while writing this spec** (295 launch lines, 296 runs,
288 of them ended at the time of writing). Truncated at the 216th ended run —
`ended <= 2026-09-23T02:47:45Z` — the definitions in §2.1 return exactly the card's three
numbers: **216 ended sessions, 35.4 % of session time landing nothing, 23.7 Opus hours in
adjudication**. Those definitions are not proposed; they are the ones that reproduce.

## 1. Decisions

### 1.1 In

- `asf improve [--product P]` — one command: compute the table, write `improve/<date>.md` in the
  record, append the numbers to `improve/history.jsonl`, propose a card per class over threshold.
- A new `improve` step in the tick's manifest, due weekly off its own stamp.
- A new approval class, `propose_improvement`, default `groom` — the three levels are the three
  ways a proposal can be handled (filed, presented, held).
- A first row on the daily scorecard's Waste table carrying the two numbers this exists to move.
- `tests/test_improve.py`, including a frozen, field-reduced copy of the real registry at the cut
  above, so acceptance #4 is a test and not an anecdote.

### 1.2 Out

- **Fixing `metrics.session_event`'s cost read.** A job log holds one `result` line per assistant
  turn, and `total_cost_usd` is *cumulative within a `session_id`*: `adjudicate-b-0016.jsonl`
  holds 9 result lines over 6 session ids, rising 0.97 → 2.07 → 3.18 → 3.82 → 3.90 inside one id
  and restarting at the next. `metrics.session_event` reads only the file's **last** result line
  (`metrics.py:_result_line`), so that job contributes $1.62 to the record's `cost:` blocks where
  it actually spent $12.80. The improve pass does not inherit that read (§2.1, `job_spend`), and
  its page prints both totals side by side so the gap is a number rather than a suspicion — but
  rewriting `write_costs` is a different card, and this spec does not touch it.
- **A budget, a cap, or any enforcement.** The pass measures and proposes. Nothing it writes
  stops a launch.
- **Per-run spend.** The registry has 296 runs; the job logs have session ids that do not map
  onto them (8 runs, 6 session ids, for the one job above). Spend is per job, split over that
  job's ended runs pro rata by minutes, and the page says so.
- **Backfilling `improve/` for weeks already past.** The first run is the baseline; movement
  starts at the second.

### 1.3 Preconditions

| # | Depends on | Checked how |
|---|---|---|
| P1 | The registry is append-only and a launch line opens a run (`lifecycle.fold`, B-0041) — a job sent back three times is three sessions, and the pass counts runs, not jobs | `lifecycle.runs` is the only reader; folding `latest` instead gives 197 ended, not 216 |
| P2 | A run carries `started`, `ended`, `kind`, `model`, `item`, and `harvested` when it landed | present on every launch line of the live registry (296/296 for the first five, 197 `harvested`) |
| P3 | Job logs live at `~/.ASF/logs/jobs/<product>/<job>.jsonl` (`metrics.job_log_path`) and carry `type: result` lines with `session_id` and `total_cost_usd` | verified on 207 log files, 68 of them with more than one result line |
| P4 | The record clone is writable in the tick and committed by `tick.finish` | the `daily` step already writes `metrics/daily/` there |
| P5 | `approvals.matrix` refuses an unknown class, so a new class must be added to `CLASSES`, not invented in config | `asf.approvals.matrix` |
| P6 | A Feature may not carry `signature:` (`record/check.py:170`), so the dedupe key is the card's own `source:` field — which is what the card's Acceptance already asks each proposal to carry | `asf check` |

### 1.4 The choices

| Choice | Chosen | Against | Why |
|---|---|---|---|
| Unit of measurement | one **run** (a launch line and what folds onto it) | one job; one session id | 216 ended sessions is runs. A job held and sent back three times spent three sessions, and the whole point of the pass is that those three cost something. |
| Landing | `harvested` is set on the run | `end_reason == finished` | `finished` is what the session said; `harvested` is what the trunk got. 90 of the 216 runs ended `finished` but 35 % of the minutes still landed nothing — the gap between the two is precisely the waste. |
| Spend | per job: Σ over distinct `session_id` of that id's **max** `total_cost_usd` | the last result line (what `metrics.session_event` does); the sum of every result line | The field is cumulative within a session id. The last line undercounts a resumed job ~8×; the plain sum double-counts every turn. |
| Default window | **all time** (`--since` narrows, `--as-of` truncates) | the trailing 7 days | D-0050's numbers are all-time, and the ledger is two days old. Movement comes from comparing runs (§2.3), not from windowing. |
| Where the previous run's numbers come from | `improve/history.jsonl` in the record, one JSON line per run | re-parsing the previous `improve/<date>.md`; a `metrics/` stream with a schema | A page is for a person; parsing one back is a second grammar to keep. A stream would need a schema entry in `metrics.SCHEMAS` for one writer and one reader. |
| Card type for a proposal | `feature` under the improve Epic | `bug`; a `task` | A saving is work to be planned, not a defect with a signature, and `check.py` forbids a Feature carrying one. |
| Dedupe key | typed `source: improve:<class>` | the title; a `signature:` | The card's Acceptance already requires `source:` naming the measurement. One field does both jobs. |
| What decides filing | a new approval class `propose_improvement`, default `groom` | reusing `file_bug`; a bare `improve.autofile: true` | "the operator's autonomy level decides" is the approval matrix, and it is already the one file an operator widens. `file_bug` is about defects and is `auto` today — proposals must not ride in on that. |
| Cadence | a step with its own weekly stamp | a fifth part of `step_daily` gated on the weekday | The card says tick step. A part of `daily` cannot be run, skipped, timed or turned `off` on its own; a step can (`asf tick --steps improve`, `steps: {improve: off}`). |
| Scorecard line | a first **row** of the Waste table, `landing` | a prose line under the title | Every other number on that page is a table row, and a row is what `tests.test_metrics` can assert on without parsing prose. |
| Reproducing the card's three numbers | a frozen field-reduced copy of the registry at the cut, in `tests/fixtures/` | asserting against the live `~/.ASF` registry | The live ledger grows every tick and a run ended before the cut can still be harvested after it, so the live non-landing share drifts down. A frozen copy is the same ledger and is green forever. |

## 2. The design

### 2.1 `asf/improve/measure.py` — the arithmetic

```python
@dataclasses.dataclass(frozen=True)
class Run:
    job: str; kind: str; model: str; item: str | None
    started: str; ended: str; minutes: float; landed: bool
    end_reason: str; usd: float | None
```

- `ended_runs(product, *, ledger=None, logs_dir=None, since=None, as_of=None) -> [Run]`
  - spine: `lifecycle.runs(pool.sessions_path(product))` — **every** run of every job, flattened.
  - a run counts when it carries `ended`. `since` keeps `ended[:10] >= since`; `as_of` keeps
    `ended <= as_of` (a full ISO stamp).
  - `minutes = max(0, (ended - started) / 60)`, rounded to 1 dp; an unparseable pair is 0.
  - `landed = bool(run.get('harvested'))`.
  - `usd`: the job's spend, split over that job's ended runs pro rata by `minutes`; `None` when
    the job has no log.
- `job_spend(job, logs_dir) -> float | None` — read the log's `type: result` lines, group by
  `session_id` (a line with none forms the group `'none'`), take each group's **max**
  `total_cost_usd`, and sum the groups. No log, or no line carrying the field → `None`.
- `table(runs) -> dict` — the numbers, one flat dict, every key a number or a list of rows:

| Key | Definition | At the cut |
|---|---|---|
| `sessions` | `len(runs)` | 216 |
| `hours` | `Σ minutes / 60` | 195.2 |
| `usd` | `Σ usd` over runs that have one | 309.75 |
| `landed_sessions` / `landed_items` | runs with `landed`; distinct `item` among them | 110 / 86 |
| `non_landing_share` | `(hours - hours of landed runs) / hours` | 0.354 |
| `by_kind` | per `kind`: sessions, hours, usd, usd/hour | `fix-bug` 54.0 h $53.14; `coder` 52.2 h $78.23; `spec` 39.9 h $65.25; `adjudicate` 23.7 h $53.64; `correct` 19.7 h $27.24; `plan` 5.8 h $32.25 |
| `by_model` | per `model`: hours, usd | `claude-sonnet-5` 125.6 h $158.52; `claude-opus-5` 69.4 h $151.15 |
| `by_kind_model` | per `(kind, model)` cell: hours, usd | top cells: `fix-bug`×sonnet 53.8 h, `coder`×sonnet 52.2 h, `spec`×opus 39.9 h, `adjudicate`×opus 23.7 h |
| `repeat_items` | items with ≥ 3 ended runs; their share of `usd` and of `hours` | 21 items, 53 % of spend, 61 % of hours |
| `minutes_per_landed_item` | `Σ minutes / landed_items` | 136.2 |
| `usd_per_landed_item` | `Σ usd / landed_items` | 3.60 |
| `record_usd` | the same window's spend as the record's `cost:` blocks hold it | printed beside `usd` as the §1.2 footnote |

`table` takes runs and returns numbers. It touches no file and no clock, so every row above is a
unit test.

### 2.2 `asf/improve/classes.py` — the classes and their thresholds

A class is a name, a threshold, a measurement over `table(...)`, and one sentence with the number
in it. Defaults live here; a product overrides any of them under `improve:` in its yaml
(`improve: {thresholds: {non_landing_sessions: 0.30}, epic: E-0001, window_days: null}`).

| Class | Measured | Default threshold | Over? at the cut | `excess_usd` (the rank key) |
|---|---|---|---|---|
| `repeat_sessions` | share of spend on items with ≥ 3 ended sessions | 0.33 | 0.53 → yes | `(0.53-0.33) × usd` = $61.95 |
| `time_per_landed_item` | `minutes_per_landed_item` | 120 | 136.2 → yes | `(136.2-120) × landed_items / 60 × usd_per_hour` = $36.94 |
| `premium_model_in_kind` | the largest `by_kind_model` cell whose model is in `improve.premium_models` (default `['claude-opus-5']`), in hours | 8.0 | `adjudicate × claude-opus-5` 23.7 h → yes | `(23.7-8.0) × cell usd/hour` = $35.48 |
| `non_landing_sessions` | `non_landing_share` | 0.25 | 0.354 → yes | `(0.354-0.25) × usd` = $32.21 |

Four classes over threshold on the first run — the same four D-0050's sitting produced, ranked
by the spend their excess covers. `rank` on the proposed card is the position × 10 (10, 20, 30,
40), so the board sorts them the way this table does.

A class not over its threshold is still printed, with its distance from the threshold. A week
with nothing over threshold writes the page and proposes nothing.

### 2.3 `asf/improve/improve.py` — the command

```
asf improve [--product P] [--since YYYY-MM-DD] [--as-of ISO] [--dry-run] [--json]
```

1. Resolve the product and the record (`cli.resolve_record`, so the first line is `record: <path>`).
2. `runs = measure.ended_runs(product, since=…, as_of=…)`; `now = table(runs)`.
3. `before` = the last line of `<record>/improve/history.jsonl`, or `None`.
4. Render `<record>/improve/<date>.md` through `metrics.write_if_changed` — three parts, in the
   card's order:
   - **(a) the numbers**: the §2.1 table, one markdown table per block, the classes table last.
   - **(b) the movement**: for every scalar in `now`, `before`'s value, the delta and its sign
     (`35.4 % → 31.0 % (-4.4)`), or `first run — no movement to show` when `before` is `None`.
   - **(c) the proposals**: one block per class over threshold, each carrying its sentence, its
     `excess_usd`, and the card it proposes (id once filed, else `— proposed, not filed (<level>)`).
5. Append `now` (plus `date`, `product`, `sessions`, `as_of`) as one JSON line to
   `<record>/improve/history.jsonl`.
6. Propose, per §2.4.
7. Print the table to stdout (the tick log is where the operator reads it) and one last line:
   `improve <date>: 216 sessions, 195.2 h, $309.75 — 4 class(es) over threshold, 4 proposed, 0 bumped`.

`--dry-run` does 1–4 into memory and prints; it writes nothing and proposes nothing. `--json`
prints `now` as JSON instead of the table, for a caller that wants the numbers.

### 2.4 Proposing a card

The level is `approvals.level_of(product, 'propose_improvement')`:

- **`auto`** — file or bump in the record, the `file_bugs` shape exactly:
  - `find_open_by_source(canonical, 'improve:<class>')` — an item that `core.is_open` and whose
    typed `source:` matches. Found and its `last_seen` is today → unchanged (a second run the same
    day is a no-op). Found → write typed `measured: <the number as printed>`, `last_seen: <date>`,
    `rank`, and append one `## History` line
    `- <date> improve: <class> 0.31 → 0.354 (216 sessions)`. **Bumped, not filed.**
  - Not found → `ids.mint_id(root, canonical, 'feature')` and `ids.write_new_item(...)` with
    typed `title`, `parent` (`improve.epic`, else `conventions.default_bug_epic`),
    `source: improve:<class>`, `measured`, `last_seen`, `rank`, a `## Description` whose first
    line is the class's sentence with the measured number in it, and an `## Acceptance` naming
    the number that would close it (`non_landing_share below 0.25, measured over a full week`).
  - `do_index(root)` once, when anything was filed or bumped.
- **`groom`** (the default) — write one card per proposal into `conventions.intake_dir` as
  `improve-<class>.md`, carrying the same body and a `parent:` header. The groom's next run types
  it and files it, or asks its one question. Nothing under `features/` is touched by the pass
  itself. An intake file for that class that is already there is overwritten with the new number,
  so the groom never sees two.
- **`human-now`** — the page is written and nothing else; one line per proposal:
  `NEEDS OPERATOR: improve proposes <class> (<sentence>) — widen approvals: propose_improvement in products/<p>.yaml`.

`propose_improvement` joins `approvals.CLASSES` as
`ActionClass('propose_improvement', 'filing a card the improve pass proposes', 'groom', ('improve',))`,
with `_CODE_RECOGNISERS['propose_improvement'] = ("the improve pass's proposal filer",)` so
`asf doctor`'s "held but unrecognisable" check stays quiet at the default level.
`new.SETTABLE['feature'] |= {'source'}` so `asf new`/`asf set` can write the same field by hand.

### 2.5 The tick step

- `steps.STEPS` gains `'improve'` after `'daily'`; `ASF_CALLABLES['improve'] =
  'asf.tick.step_improve:run'`. A product yaml that declares `steps:` without it still resolves to
  `asf` (`resolve`: undeclared falls back to `asf` for a step asf implements), so no product
  config changes.
- `steps.improve_stamp_path` / `weekly_due(product, force=False, today=None, every_days=7)` /
  `write_improve_stamp` beside the daily three, over `~/.ASF/state/<product>/improve.stamp` — the
  stamp holds the last run's date, and the step is due when it is missing, unparseable, or
  `today - stamp >= 7` days.
- `tick._run_steps` gains the two lines the daily step has: skip with
  `tick: step improve not due until <date>` when it is not, and `steps.write_improve_stamp` when
  it ran clean. `asf tick --improve` forces it, as `--daily` does.
- `asf/tick/step_improve.py` is thin: `run(ctx)` calls `improve.cmd_improve` against
  `ctx.record_root()` with the product, writes `ctx.event('improve', ...)`, and returns its rc.
  The page it wrote goes to the trunk in the tick's own commit (`tick.finish`) — no push of its
  own.

### 2.6 The scorecard's first line

`metrics.scorecard_rows(ci, sessions, ticks, conv=None, landing=None)` gains a `landing`
argument and, when it is not `None`, puts this row **first**:

```
| landing | 35 % of session time landed nothing | $3.60 per landed item (86 landed, 7 days) |
```

`landing` is `(non_landing_share, usd_per_landed_item, landed_items)` from
`improve.measure.table` over the scorecard's own 7-day window. `render_daily(root, day, items,
conv=None, product=None)` computes it when a product is given and `cmd_rollup` passes the one it
already resolved. With no product the row still leads, reading `—` with the note `no product
resolved — the session registry is machine-local`, so the shape of the page never depends on
where it was rendered.

### 3.4 The first run reproduces the card's numbers

The fixture is the real registry, truncated at its 216th ended run and reduced to the fields the
pass reads (no account name, no worktree path, no log path — B-0023). Regenerate it, and confirm
it is faithful, with:

```bash
python - <<'EOF'
import json, os
from asf.workers import lifecycle
KEEP = ('job', 'kind', 'model', 'item', 'started', 'ended', 'end_reason', 'harvested', 'pid')
CUT = '2026-09-23T02:47:45Z'
src = os.path.expanduser('~/.ASF/state/asf/sessions.jsonl')
rows = [r for rs in lifecycle.runs(src).values() for r in rs
        if r.get('ended') and r['ended'] <= CUT]
rows.sort(key=lambda r: (r['started'], r['job']))
with open('tests/fixtures/improve/asf-2026-09-23.jsonl', 'w', encoding='utf-8') as f:
    for r in rows:
        f.write(json.dumps({k: r[k] for k in KEEP if k in r}, sort_keys=True) + '\n')
print(len(rows), 'runs')          # 216
EOF
```

## 4. Records

**Files.**

| Path | Written by | Shape |
| --- | --- | --- |
| `<record>/improve/<date>.md` | `cmd_improve` | §2.3 — the numbers, the movement, the proposals |
| `<record>/improve/history.jsonl` | `cmd_improve` | one JSON line per run: `date`, `product`, `as_of`, and every scalar of the §2.1 table |
| `<record>/features/F-xxxx.md` | `cmd_improve` at `auto` | a Feature carrying `source: improve:<class>`, `measured:`, `last_seen:`, `rank:` |
| `<record>/<intake_dir>/improve-<class>.md` | `cmd_improve` at `groom` | the same body as an intake card, overwritten each run |
| `<record>/metrics/daily/<day>.md` | `cmd_rollup` | as today, plus the `landing` row first in the Waste table |
| `~/.ASF/state/<product>/improve.stamp` | `steps.write_improve_stamp` | the last clean run's date, one line |

**Rows.** A proposed card's typed fields, and what each is for:

```yaml
source: improve:non_landing_sessions   # the dedupe key — one open card per class
measured: "0.354"                      # the number as this run measured it
last_seen: 2026-09-23                  # a second run the same day is a no-op
rank: 40                               # position by excess_usd, × 10
parent: E-0001                         # improve.epic, else conventions.default_bug_epic
```

and one `## History` line per bump:
`- 2026-09-30 improve: non_landing_sessions 0.354 → 0.310 (241 sessions)`.

**Events** — `<record>/metrics/events/<day>.jsonl`, through the `ctx.event` the step holds:

```json
{"kind": "improve_run", "sessions": 216, "hours": 195.2, "usd": 309.75,
 "non_landing_share": 0.354, "usd_per_landed_item": 3.6, "over_threshold": 4}
{"kind": "improve_proposal", "class": "repeat_sessions", "measured": 0.53,
 "threshold": 0.33, "excess_usd": 61.95, "action": "filed", "item": "F-0092"}
{"kind": "improve_proposal", "class": "non_landing_sessions", "measured": 0.354,
 "threshold": 0.25, "excess_usd": 32.21, "action": "held", "level": "groom"}
```

**Printed.** One line per class in the tick log, then the summary line of §2.3 step 7 — so the
numbers are in the tick's own output whether or not anyone opens the page.

## Stories

- S: Every run of the registry, its minutes, and whether it landed — acceptance: `tests.test_improve.RunsTests` (§3.1), including a 3-run job counting as 3 sessions
- S: A job's spend, read as the max `total_cost_usd` per `session_id` and summed — acceptance: `tests.test_improve.SpendTests` (§3.1), over a fixture log with two session ids and rising cumulative cost
- S: The table — hours and spend per kind, per model, per kind×model cell, the repeat-session items and the per-landed-item rates — acceptance: `tests.test_improve.TableTests` (§3.1)
- S: The four classes, their thresholds, and the rank their excess spend gives them — acceptance: `tests.test_improve.ClassTests` (§3.1), each class at, under and over threshold
- S: `asf improve` writes `improve/<date>.md` and appends the run to `improve/history.jsonl`, with the movement since the previous line — acceptance: `tests.test_improve.CommandTests` (§3.2)
- S: A proposal is filed, bumped, presented or held by the `propose_improvement` level, and never filed twice for the same class — acceptance: `tests.test_improve.ProposeTests` (§3.2) and `asf check` clean over the result
- S: The tick runs it weekly off its own stamp, and a product that declares no `improve` step still gets it — acceptance: `tests.test_tick_steps` and `tests.test_tick` (§3.3)
- S: The scorecard's first row carries the non-landing session share and the USD per landed item — acceptance: `tests.test_metrics` (§3.3), both the with-product and the no-product form
