# F-0158 — a session cannot end with its work unpushed

Over the 14 days to 2026-09-28, 144 runs of product `asf` ended `failed: not pushed` without
landing — 72 a week against a threshold of 5 — and $207.34 and 52.8 h went on them. Each one is
work that was done and then left where nobody could see it: the session exited, `health` looked
in its worktree, found files uncommitted or commits origin lacks, and wrote the run down as a
failure. The item it was working on then waits for a correction round, which is a second session,
a second launch cost and a second wall-clock hour for a piece of work that was already finished.

The factory has been round this loop twice already. B-0094 (19 % of sessions end `not pushed`)
put `lifecycle.commit_leftovers` in, so the factory commits what a finished session left in its
tree. B-0056 put `lifecycle.publish` in, so the factory pushes a branch the session did not.
F-0094 put `health.republish_steps` in, so a refused publish is tried again every pass instead of
once. All three are in and all three fire, and the number is still 72 a week. B-0075 said why in
one line: *prose cannot stop it*. Everything the factory has built so far runs **after** the
session is gone, and everything the session is told is a paragraph in a brief.

Reading the code, this spec finds the number has two distinct halves, and they need opposite
treatment.

**The half that is real.** Nothing stops a session from ending. `asf/hooks.py` has carried
`Stop` in its `EVENTS` tuple since F-0031 and no rule and no built-in has ever declared one, so
the only thing standing between a session and an unpushed exit is the sentence *"Push your own
branch before your turn ends"* in `asf/briefs/preamble.py:44`. A session that backgrounds its test
suite and exits, or that finishes with nothing to change and never pushes the empty branch, walks
straight past it. The gate exists in the runtime and the factory never armed it.

**The half that is measurement.** `metrics.append_event` keys a `sessions` line on
`(task, ts)` — the job and the run's `ended` — and when that key is already on the day's file it
returns `'exists'` and writes nothing (`asf/metrics/metrics.py:336`). A run's `ended` does not
move when the factory re-judges it. So the sequence that F-0094 was built to produce —
tick *N* judges `failed: not pushed`, tick *N+1* publishes the worktree and re-judges the run
`finished` in the registry — writes the failure to the stream and can never write the correction,
because the corrected event carries the same natural key. `sessions_from_registry` folds the
registry and yields the run's *current* verdict every tick; `append_event` throws it away every
tick. The scorecard reads the stream, so every run the factory successfully rescued is still
counted against this card.

This spec arms the gate, and makes the stream able to record a verdict that changed.

## 1. Decisions

### 1.1 Preconditions

- `asf/hooks.py` already carries `Stop` in `EVENTS`, and `merge()` already writes a `Stop` entry
  without the `matcher` key the tool-events need (`if event != 'Stop'`). The runtime contract for
  a hook is the one `approvals` uses: **rc 0 lets the stop through, rc 2 blocks it and feeds
  stderr back to the model**, which then keeps working instead of ending. Nothing new is needed
  from the runtime.
- `hooks.install` already writes a product-less built-in into *every worker account's own user
  settings* (`account_settings_path`), unconditionally, whether or not a rule card declares a
  hook — the precedent F-0031 §2.3 PD5 set for `approvals`, on the grounds that a guard binding
  every session cannot depend on a product repo having a rule card. The gate is that kind of
  guard and rides the same call.
- `approvals.run_hook` sets the shape a built-in hook has: return 0 at once when `ASF_JOB` is
  unset (not a factory session, D4), and fail closed on an exception while saying it was the hook
  that broke, not the policy (B-0125).
- `health.push_gap(worktree, branch, main)` already is the measurement: `git status --porcelain`
  for uncommitted files, `lifecycle.unpushed_commits` for commits whose patch is not on the
  branch's remote, and a branch with no remote head at all counts as unpushed. Its text is the
  `not pushed: <n> uncommitted file(s), <m> unpushed commit(s)` that `lifecycle.push_gap(ev)`
  formats from gathered evidence, and that `judge` writes into `end_reason`.
- `lifecycle.lands(run)` already decides whether a run's work is its branch: a `NO_LANDING_KINDS`
  run (`groom`, `groom-clerk`) rules into the state dir and is told the repository is not its
  work, and a correction launched on such a branch inherits that. The gate must ask the same
  question, never its own.
- `scorecard.score.failure_class` folds `end_reason` to its first two colon clauses with digits
  dropped, so `failed: not pushed: 3 uncommitted file(s), 0 unpushed commit(s)` is the class
  `failed: not pushed`. `diagnose.metric` counts runs in that class with `score.is_dead`, which
  requires `not run.landed`. This spec changes neither function.
- The run record already carries `publish_refused` in `RUN_FIELDS` — the line a publish the
  factory could not make left behind. It is written by `republish_steps` and read by nothing that
  reports.

### 1.2 In

- **`asf.workers.lifecycle.unpublished(wt, branch, main)`** — `(ok, detail)`, the git evidence
  for "is this worktree's work on origin", moved out of `health` so the session side and the
  judging side cannot drift apart. `health.push_gap` becomes a thin wrapper over it and keeps its
  name and signature.
- **`asf.workers.stopgate`** — a new module, the built-in `Stop` hook: `run_hook(stdin_text,
  environ, out, product)` returning 0 or 2, and `refusal_lines(...)` building what the session
  reads. Pure of the clock; git and the state dir are its only io.
- **`asf.conventions.stop_gate_rounds`** — a typed field, `DEFAULT_STOP_GATE_ROUNDS = 2`: how
  many times one run's stop may be refused before the gate stands aside.
- **`asf.hooks`** — `BUILTIN` gains `'unpushed': ('Stop',)`; `cmd_hook` dispatches on the name
  instead of sending every built-in to `approvals`; `install` writes `('Stop', 'unpushed')` into
  every worker account beside `('PreToolUse', 'approvals')`.
- **`asf.doctor`** — an `unpushed-gate` row beside `approvals-hook`, naming the accounts whose
  sessions would run with no gate.
- **`asf.metrics.metrics.append_event`** — a third status, `'updated'`: a `sessions` line whose
  natural key is already on the day's file and whose registry-owned fields have changed is
  rewritten in place. Every other stream stays append-only, byte for byte.
- **`asf.scorecard.diagnose`** — the `failure:failed: not pushed` cause's evidence gains one line
  naming the sub-causes behind the count. The cause key and title are untouched.
- Tests for each (§3).

### 1.3 Out

- **Renaming, re-classing or re-wording `not pushed`.** The card is verified by reading
  `failure:failed: not pushed` over the two weeks after this lands against the two before. Any
  change to the string `push_gap` writes, to `failure_class`, or to the cause key would drive the
  reading to zero without a single session pushing anything — a number that falls because the
  meter was replaced is a lie told to the loop that filed this card. The string is frozen for the
  length of this Feature, and §3.6 is the test that says so.
- **Blocking a stop forever.** A gate with no bound turns one stuck session into an infinite one
  and burns the window it was meant to save. Two refusals, then the gate stands aside and the
  factory's own publish remains the net (§2.3).
- **The gate committing or pushing for the session.** It refuses and names the commands. The
  factory already has the write path for after the session is gone
  (`commit_leftovers` / `publish`); a hook that commits from inside a live session would race the
  session's own git, and the session is the one that knows what its commit message should say.
- **Touching `commit_leftovers`, `publish`, `publish_gap` or `republish_steps`.** They work; they
  are the net under the gate. This spec adds a floor above them and does not move the floor below.
- **Judging a run whose result was not ok.** `publish_gap` rescues only a run whose result said
  ok, and that is right — a session that failed may have left a half-finished tree. Such a run's
  `end_reason` names its own failure, not `not pushed`, so it is not in this card's number.
- **A new stream, a new state file the record carries, or a new field on any card.** The gate's
  bound counter lives under `~/.ASF/state/<p>/`, which is the factory's own scratch and is not
  committed.
- **Rewriting history in the streams.** `'updated'` applies to the `sessions` stream only, on an
  unchanged natural key, and only for the fields the registry owns. A line is corrected, never
  moved, never deleted, and no other stream gains the path.
- **Chasing the sessions the gate cannot reach.** A run killed for quota, a dead pid, a crashed
  runtime: no `Stop` event fires and no hook runs. Those end under their own signatures and are
  other cards' numbers.

### 1.4 The choices

| Choice | Against | Why |
| --- | --- | --- |
| A `Stop` hook that refuses the exit | another paragraph in the brief; a louder REPORT contract | B-0075 already ruled on this: "Workers still background the test suite and end without pushing; prose cannot stop it". The runtime has carried the `Stop` event since F-0031 and the factory never armed it. A refusal the session must answer is the only thing here that is not advice. |
| Refuse while the session is alive | rescue it after it is gone | The three mechanisms already built all run post-mortem, and 72 a week survive them. A session that is still up fixes its own tree in one tool call, costs no correction round, no second launch and no second hour — which is the $207.34 and the 52.8 h the card is actually about. |
| Installed per worker account, product-less | a rule card declaring `hook: [Stop]` | A rule hook lands in the product repo's `.claude/settings.json` and so binds only sessions in a product repo that carries the card. The gate binds every factory session, which is exactly the argument F-0031 §2.3 PD5 made for `approvals`; it rides the same line in `install`. |
| Bounded at 2 refusals, then stand aside | refuse until the tree is clean | An unbounded Stop gate can hold a session that cannot satisfy it — a hook refusing its commit, a rebase it must not resolve — until its window is spent, which is a worse failure than the one being fixed. Two rounds is enough for "you forgot"; past that the factory's publish and the correction loop are the net, as today. |
| The bound is a counter file under `state/<p>/` **and** the payload's `stop_hook_active` | either alone | `stop_hook_active` is the runtime's own loop guard and is the honest signal that this stop was already blocked; a counter file survives a runtime that does not send it and makes the bound testable without a runtime. Belt and braces, because the failure mode of getting this wrong is a trapped session. |
| `lifecycle.unpublished` is the one owner | the gate measuring the tree its own way | The gate must refuse on exactly the condition `judge` will later fail the run on. Two implementations of "is this pushed" drift the day one of them changes a git flag, and then the gate passes a session the judge then fails — the worst of both. This is the move f-0103 made for `outcome_class`, for the same reason. |
| The gate refuses a clean tree on a branch never pushed | letting "nothing to change" exit quietly | `judge` fails that run `not pushed` today, and the standing rule already says push "once at the end even if nothing changed". It is a real and cheap slice of the number: one `git push` of an empty branch, and `judge` reaches `empty branch` instead, which D-0048 already routes properly. |
| `append_event` gains `'updated'` for `sessions` | leaving the stream append-only | A `sessions` line is one fact — *this run ended, and this is what it came to* — and the factory learned the verdict was wrong one tick later. The key does not change, so this is a correction in place, not a new fact. Left as it is, F-0094's whole purpose is invisible to every metric the factory keeps, and this card cannot be honestly verified either way. |
| Update only the registry-owned fields | rewriting the whole line | The stream carries fields no registry pass recomputes (item joins, token dimensions from the meter). A blanket overwrite would silently drop what a backfill with a different `items` index had enriched. |
| The sub-causes go in the cause's evidence | a new scorecard class per sub-cause | A class per sub-cause splits the very number this card is verified on, which is the renaming trap under another name. The evidence line is free, is read by whoever picks up the reopen, and moves no metric. |
| `stop_gate_rounds` is product config | a constant in the module | An operator watching a lane trap itself needs to set it to 0 and get the old behaviour back without a release. Every other bound in the factory is a typed convention with a documented default. |

## 2. The design

### 2.1 One owner for "is this on origin" — `asf/workers/lifecycle.py`

`health.push_gap`'s body moves beside `unpushed_commits` and `push_gap(ev)`, which already live
here:

```python
def unpublished(wt, branch, main='main'):
    """``(ok, detail)``: whether ``branch``'s work in worktree ``wt`` is on origin, and what is
    missing when it is not — ``not pushed: <n> uncommitted file(s), <m> unpushed commit(s)``,
    the same text :func:`push_gap` formats from gathered evidence (B-0051).

    ``n`` is ``git status --porcelain``; ``m`` is :func:`unpushed_commits`, by patch and above
    the trunk, so a branch harvest rebased after the session pushed it is not held forever
    (B-0053). A branch with no remote head at all is unpushed even with nothing to push: the
    session must publish the branch it was given (D-0048 then reads ``empty branch``)."""
```

`health.push_gap(worktree, branch, main)` keeps its name, its signature and its docstring's
reference, and becomes `return lifecycle.unpublished(worktree, branch, main)`. No caller changes;
`health` already imports `lifecycle`.

### 2.2 The gate — `asf/workers/stopgate.py`

```python
#: the built-in Stop hook: a factory session may not end with its branch's work off origin.
def run_hook(stdin_text, environ=None, out=sys.stderr, product=None):
    """``asf hook unpushed`` — the rc the runtime reads: 0 lets the stop through, 2 blocks it and
    feeds ``out`` back to the model, which then keeps working.

    0 at once when this is not a factory session (no ``ASF_JOB``, D4), when the run's work is not
    its branch (:func:`asf.workers.lifecycle.lands`), when there is no branch or it is the trunk,
    when the tree is published (:func:`asf.workers.lifecycle.unpublished`), or when the run's
    refusals are spent (§2.3). Every exception lets the stop through and says the hook broke, not
    the session (B-0125, inverted: a gate that breaks must not trap the session it cannot judge).
    """
```

In order:

1. `environ.get('ASF_JOB')` unset → `0`. The console and any non-factory session are untouched.
2. Load the product (`product` or `ASF_PRODUCT`) and the run for `ASF_JOB` from the registry.
   The run gives `worktree` and `branch` — authoritative, where the payload's `cwd` is wherever
   the session last wandered. No run and no `worktree` on disk → `0`.
3. `lifecycle.lands(run, pool.sessions_path(product))` false → `0`. A groom rules into the state
   dir's answers file and was told the repository is not its work.
4. No branch, a detached `HEAD`, or the branch is `product.main` → `0`. The gate never asks a
   session to push the trunk, and `refguard.listed` is consulted so a protected ref is never
   named in a refusal.
5. `ok, detail = lifecycle.unpublished(wt, branch, product.main)`; `ok` → `0`.
6. The bound (§2.3) spent → `0`, and one line to `out` saying the gate stood aside, so the
   transcript records that the session was warned and the factory let it go.
7. Otherwise: bump the counter, print `refusal_lines(...)` to `out`, return `2`.

`refusal_lines(branch, detail, item, kind)` is what the session reads. It names the evidence and
the exact commands, and nothing else:

```
REFUSED: your work is not on origin — not pushed: 2 uncommitted file(s), 1 unpushed commit(s)
This is branch spec/F-0158. Finish it before you end your turn:
  git add -A && git commit -s -m 'spec(F-0158): <what you did>'
  git push origin spec/F-0158
A commit subject must name F-0158 as a token. Never force-push, never --no-verify, never a
branch but this one. If the push is refused as non-fast-forward, stop there — do not merge and
do not force — and say `pushed: rebased <sha> — the factory publishes` in your REPORT (B-0056).
```

The uncommitted count and the unpushed count each drop their clause when zero, so a session that
committed and only forgot the push is not told to `git add`.

### 2.3 The bound

`~/.ASF/state/<p>/gates/<job>.stop` holds one integer: how many times this run's stop has been
refused. The gate refuses only while the count is under the bound:

```python
def spent(product, job, conv, payload):
    """True when this run's stop may no longer be refused: its counter has reached
    ``conv.stop_gate_rounds``, or the runtime says it has already blocked this stop once and the
    bound is one. The counter is the authority; ``stop_hook_active`` is the runtime's own loop
    guard, read as corroboration and never as permission to refuse again."""
    return refusals(product, job) >= max(0, conv.stop_gate_rounds)
```

The counter is written before the refusal is printed, so a gate that dies between the two refuses
one time fewer, never one more. A payload carrying `stop_hook_active: true` whose counter is
somehow behind (a counter file an operator removed mid-session) is refused at most up to the bound
and then stands aside, so the two signals can disagree without trapping anyone. `spawn` removes `gates/<job>.stop` when it launches a run under that job, so a
correction round arrives with a fresh bound; a reap removes it with the rest of the job's scratch.

`stop_gate_rounds: 0` disables the gate for a product entirely and is the operator's escape hatch.

### 2.4 Arming it — `asf/hooks.py`, `asf/doctor.py`

```python
BUILTIN = {'approvals': ('PreToolUse',), 'unpushed': ('Stop',)}
```

`cmd_hook` today sends *every* `BUILTIN` name to `approvals.run_hook`, so a second built-in would
run the approvals matrix on a `Stop` payload. It dispatches on the name instead:

```python
def cmd_hook(args):
    if args.name == 'approvals':
        from asf import approvals
        return approvals.run_hook(sys.stdin.read(), os.environ, product=args.product)
    if args.name == 'unpushed':
        from asf.workers import stopgate
        return stopgate.run_hook(sys.stdin.read(), os.environ, product=args.product)
    script = check_script(args.name, args.product)
    ...
```

`install`'s per-account write gains the entry:

```python
for account in accounts:
    _write_merged(account_settings_path(account),
                  [('PreToolUse', 'approvals'), ('Stop', 'unpushed')], asf_path, None)
```

`merge` needs no change: it already omits `matcher` for `Stop`, and `_is_ours` already recognises
`… hook unpushed` with no `--product` tail. The summary line becomes
`approvals and the unpushed gate in <n> worker accounts`.

`doctor` gains an `unpushed-gate` row built the way `approvals-hook` is, over a
`hooks.gate_missing(accounts)` that mirrors `hooks.approvals_missing`: green when every account's
settings file carries the command, and naming the accounts that do not.

### 2.5 A verdict that changed reaches the stream — `asf/metrics/metrics.py`

```python
#: The fields a `sessions` line's own registry pass owns, and may correct on a later tick. Only
#: `result` (the registry's `end_reason`) moves today: a run re-judged after the factory published
#: its worktree (F-0094) ends differently than it was first written, and its `ended` — the natural
#: key — does not move. A tuple, so a second such field joins it without touching the compare.
#: `reason` is the log's own last line and `usd` / `minutes` / the token dimensions are the
#: meter's: an ended run's log does not grow, so none of them is corrected here.
SESSION_OWNED = ('result',)


def append_event(root, stream, ev):
    """Append a normalised event to its day's file.
    Returns ``('appended'|'exists'|'updated', path)``."""
```

When the natural key is already on the day's file: for every stream but `sessions`, `'exists'`
exactly as today. For `sessions`, the stored line's `SESSION_OWNED` fields are compared with the
event's; equal → `'exists'` and not a byte written; different → those fields only are set on the
stored line, the day's file is rewritten from its parsed lines in order, and the status is
`'updated'`. Every other field of the stored line is left as it was (§1.4: a backfill's item joins
and token dimensions are not the registry's to drop).

The rewrite is the whole day's file through a temporary file in the same directory and an
`os.replace`, so a reader never sees a half-written stream.

`cmd_backfill`'s `put` already counts by status, so the tick's output gains
`sessions updated: N` with no change — the one line the operator needs to see that F-0094 is
working.

### 2.6 The residual, named but not re-classed — `asf/scorecard/diagnose.py`

The cause key stays `failure:failed: not pushed`, the title stays
`Sessions die with 'failed: not pushed' N times a week`, and `failure_class` is not touched. The
`Cause.detail` gains one line, built from the runs already gathered for the count:

```
of the 23 runs: 9 left files uncommitted, 6 committed and never pushed, 5 the factory could not
publish (4 hook refused, 1 rebase conflict), 3 had no worktree left to publish.
```

The sub-cause of a run is read off the evidence already recorded — the counts in its own
`end_reason` text, and its `publish_refused` line — and nothing new is computed or stored. A
sub-cause that no run has is not printed.

### 2.7 The prose stays, and says the gate is there

`asf/briefs/preamble.py:44` keeps its line and gains the half-sentence that makes it true rather
than hopeful:

```
- Push your own branch before your turn ends — after every commit, and once at the end even if
  nothing changed. A Stop gate refuses your exit while your work is off origin.
```

No other brief or template changes.

## 3. Acceptance tests

From the repository root, stdlib only, hermetic. The whole suite must stay green:

```bash
cd "$(git rev-parse --show-toplevel)"
python3 tools/run_tests.py
```

**T1 — one owner for the git evidence.** `lifecycle.unpublished` over a git fixture: a clean
worktree whose branch head is on origin → `(True, '')`; two uncommitted files → `(False, 'not
pushed: 2 uncommitted file(s), 0 unpushed commit(s)')`; one commit above a pushed head →
`0 uncommitted, 1 unpushed`; a branch that was never pushed with a clean tree and no commits →
`False` (the branch itself is missing from origin); a detached `HEAD` → `(False, 'no branch')`.
Its detail for gathered evidence is byte-identical to `lifecycle.push_gap(ev)` for the same
counts, so `failure_class` reads the same class as before. `health.push_gap` returns exactly what
`lifecycle.unpublished` does for the same worktree.

```bash
python3 -m unittest -v tests.test_lifecycle.UnpublishedTests
```

**T2 — the gate refuses a stop that would lose work.** `stopgate.run_hook` with `ASF_JOB` set and
a registry run on a worktree with two uncommitted files returns `2`, and its output names the
branch, the evidence text, `git commit -s`, `git push origin <branch>` and the item as a token. A
committed-but-unpushed worktree returns `2` and its output does **not** say `git add`. A clean,
pushed worktree returns `0` and prints nothing. A clean worktree on a branch never pushed returns
`2`. Returns `0` with no `ASF_JOB`; `0` for a `kind: groom` run; `0` for a run whose branch is the
product's `main`; `0` when the run has no worktree on disk; `0`, with the hook named as the
broken thing, when the registry cannot be read.

```bash
python3 -m unittest -v tests.test_unpushed_gate.GateTests
```

**T3 — the gate is bounded and never traps a session.** With `stop_gate_rounds: 2`, the same
unpublished worktree returns `2`, `2`, then `0` with a line saying the gate stood aside, and the
counter file holds `2`; a payload carrying `stop_hook_active: true` at the limit also returns `0`.
`stop_gate_rounds: 0` returns `0` on the first call and writes no counter. A counter written under
one job does not bound another job's stop, and `spawn` launching a run under a job removes that
job's counter file first.

```bash
python3 -m unittest -v tests.test_unpushed_gate.BoundTests
```

**T4 — every worker account's sessions run with the gate.** `hooks.install` over a config with
two worker accounts writes a `Stop` entry whose command is `<asf> hook unpushed` — no
`--product` tail and no `matcher` key — into both accounts' settings files beside the `PreToolUse`
approvals entry, leaves every unrelated key alone, and is idempotent over a second call. An entry
differing only in the `asf` path is replaced, not duplicated. `hooks._is_ours` recognises it and
does not recognise `asfmt hook unpushed`. `cmd_hook('unpushed')` reaches `stopgate.run_hook` and
`cmd_hook('approvals')` reaches `approvals.run_hook`. `doctor` reports `unpushed-gate` green when
both accounts carry it and names the account that does not when one is stripped.

```bash
python3 -m unittest -v tests.test_install.StopGateInstallTests tests.test_doctor.UnpushedGateRowTests
```

**T5 — a re-judged run's verdict reaches the stream.** `append_event` on a `sessions` event
returns `'appended'`; the same key with an unchanged `result` returns `'exists'` and leaves the
file byte-identical; the same key with `result` moved from `failed: not pushed: …` to `finished`
returns `'updated'`, leaves exactly one line for that key, carries the new `result`, and keeps the
stored line's `reason`, `usd`, `minutes` and token dimensions unchanged. The same key on a `ci`, `ticks`,
`landings` or `gates` stream returns `'exists'` and changes nothing. A day file with other events
keeps their order. Then end to end: a registry whose run is judged `failed: not pushed` and
backfilled, then re-judged `finished` and backfilled again, leaves a stream the scorecard counts
as zero runs in the class.

```bash
python3 -m unittest -v tests.test_metrics.SessionUpdateTests
```

**T6 — the meter is not moved.** `score.failure_class('failed: not pushed: 3 uncommitted
file(s), 0 unpushed commit(s)')` is `'failed: not pushed'`, and `lifecycle.unpublished`'s text
folds to that same class — the frozen string of §1.3. `diagnose.causes` over runs in the class
yields a cause whose key is `failure:failed: not pushed` and whose title is unchanged, and whose
detail carries the sub-cause line counting uncommitted, unpushed, could-not-publish (by refusal)
and no-worktree; a sub-cause with no runs is absent. `diagnose.metric` for that key returns the
same number as before this change for the same runs.

```bash
python3 -m unittest -v tests.test_scorecard.NotPushedCauseTests
```

## 4. Records

**Written by the gate.** `~/.ASF/state/<p>/gates/<job>.stop` — one integer, the refusals this run
has been given. Factory scratch: not committed, removed by `spawn` at launch and by the reap with
the rest of the job's files. Nothing else on disk changes while a session runs.

**Written to the transcript.** The refusal (§2.2) or the stood-aside line, to the hook's stderr,
which the runtime feeds to the model. The session's own transcript is the record that it was
told.

**Corrected in the record.** `metrics/sessions/<day>.jsonl` — an existing line's `result`, and
nothing else, when the factory re-judged the run after publishing its worktree. Same natural key,
same position in the file, every other field untouched. This is the only stream that gains the
path.

**Reported, not stored.** The sub-cause line in the `failure:failed: not pushed` cause's detail,
computed from each run's own `end_reason` and `publish_refused` at report time.

**Not written.** No new stream, no new metrics event, no new field on any card, no Bug filed by
this change, no change to `sessions`'s schema (`result` is already a string and `SCHEMAS` is
untouched). The `end_reason` vocabulary gains nothing and loses nothing.

## Stories

- S: `lifecycle.unpublished` — one owner for whether a worktree's work is on origin — acceptance: `python3 -m unittest -v tests.test_lifecycle.UnpublishedTests`
- S: A factory session's stop is refused while its branch's work is off origin — acceptance: `python3 -m unittest -v tests.test_unpushed_gate.GateTests`
- S: The gate is bounded per run and stands aside rather than trap a session — acceptance: `python3 -m unittest -v tests.test_unpushed_gate.BoundTests`
- S: The gate is installed into every worker account and the doctor sees it missing — acceptance: `python3 -m unittest -v tests.test_install.StopGateInstallTests tests.test_doctor.UnpushedGateRowTests`
- S: A run re-judged after the factory published it corrects its `sessions` line — acceptance: `python3 -m unittest -v tests.test_metrics.SessionUpdateTests`
- S: The `not pushed` class string is unchanged and its cause names its sub-causes — acceptance: `python3 -m unittest -v tests.test_scorecard.NotPushedCauseTests`
