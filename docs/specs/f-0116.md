# F-0116 — the history says who did the work

A worker session commits with the **operator's** name, the operator's e-mail, and a
`Signed-off-by:` trailer that says the operator certified work the operator never saw. This is not
a leak or an accident at the edges; it is what the launch is written to do. `seed_home` calls
`write_identity_gitconfig`, which reads the operator's global `user.name`/`user.email` and writes
exactly those two keys into the session's isolated HOME:

```
$ python3 -c "import inspect; from asf.workers import runtime; print(inspect.getdoc(runtime.write_identity_gitconfig))"
Give an isolated ``home`` a ``.gitconfig`` holding only the operator's ``user.name`` and
``user.email`` — nothing else from the operator's config (no credential helper, no
include). A ``.gitconfig`` that ``home_seed`` put there is left alone; ASF's own is
rewritten. Returns the path written, or None.
```

Run end to end in this checkout — an isolated home seeded from a synthetic operator home, the
product's `commit.signoff` on, the real `commit-msg` hook installed — a session's commit comes out
like this (the full probe is §3.0):

```
author: An Operator <an.operator@example.invalid>
committer: An Operator <an.operator@example.invalid>
--
spec(F-0116): do a thing

Signed-off-by: An Operator <an.operator@example.invalid>
```

Three fields, one person, and that person was asleep. The sign-off rule the factory already has
cannot see it: `commit.signoff`'s whole contract is *the trailer must match the author*
(`asf/workers/githooks.py:82-90`, `asf/harvest/lane.py:465-481`), and here it does. A commit
authored by the operator and signed off by the operator is, to every check the factory owns
today, perfectly well formed. **The rule that catches this is a different rule, and it does not
exist yet.**

The damage is to the one thing a git history is for. This product's trunk carries 1302 non-merge
commits under five distinct author e-mail domains: the agent's, an operator's personal domain on
406 of them, `@localhost` on nine, one whose domain is a personal machine's hostname, and one
where an agent's display name sits in front of a *human being's* work address. Nobody can read
that history for who did what, and the 406 are not a record of an operator's work — they are a
record of the factory's, filed under a name that did not do it.

The card names three things and this spec delivers all three: **the identity a launch configures**
is the agent's; **a brief that tells a session to author or sign as the operator is a defect**; and
**a read-only check** lists, one line per commit, every commit on a session branch in the last 24
hours whose author or sign-off is the operator's.

There is a fourth thing the card does not name and this spec will not do: it does not rewrite the
406. That history is published, referenced by every merged PR, and rewriting it would break every
sha in the record. The rule binds from the day it lands, forward.

## 1. Decisions

### 1.1 In

- **The launch configures an agent identity.** `asf/identity.py` owns what an agent commits as;
  `build_env` puts it in the session's environment through git's own `GIT_CONFIG_*` channel, which
  outranks every `.gitconfig` and every repo-local `user.name` on the box; `write_identity_gitconfig`
  writes the same identity into the session home instead of the operator's.
- **One identity across both lanes.** The `actions` cloud workflow stops hard-coding its own
  identity and renders the resolved one, so a commit made on a runner and a commit made on this
  host are authored by the same agent.
- **Per-account override.** `worker_pool.accounts[].identity: {name, email}`, validated on config
  load, for an operator who wants the code host's `noreply` form or one identity per account.
- **The check** — `asf identity --product <p>`: read-only, no fetch, over the checkout's existing
  refs for session branches, commits from the last 24 hours whose author **or** `Signed-off-by`
  is the operator's. One line per offending commit, and that line never repeats the identity it
  found. A doctor row carries the same lines.
- **The operator identity, named in config**: `operator: {name, email}` in `~/.ASF/config.yaml`,
  falling back to the operator's global git config when absent — so the check works on day one,
  against exactly the identity the old code would have written.
- **The brief rule as a guard**: a test that renders every brief kind and fails on any template or
  preamble telling a session to author, commit or sign as the operator.
- The two documents that today describe the old behaviour as correct: `docs/config.example.yaml`
  and `docs/guide/operating.md:401`.

### 1.2 Out

- **Rewriting published history.** No commit already on the trunk is re-authored. The check's
  window is 24 hours and its scope is session branches, so it reports work that has not landed and
  can still be corrected, not work that has.
- **Making the check a gate.** It does not block a commit, a push or a landing. The `commit-msg`
  hook cannot block one either (`asf/workers/githooks.py:14`, *"It never blocks"*), and a rule the
  factory can only discover after the fact is reported after the fact. Turning it into a lane
  refusal is a separate card, and it should not be written until the check has run clean for a
  while.
- **A rule card in the record.** A rule id comes from `asf new`, and the record is a different
  repository from this one. This spec delivers the Python owner and the CLI contract a card's
  `check:` script needs; minting `R-nnnn` is §5's operator line.
- **The core `rules/` directory.** It does not exist (P7). F-0056 and F-0069 each plan to create
  it. This card does not wait for either.
- **Forbidding `home_seed: [~/.gitconfig]`.** It is the operator's escape hatch and may carry
  configuration that has nothing to do with identity. The design makes it *harmless* instead:
  the environment channel outranks anything seeded (P5).
- **Per-session distinct authors.** Every session commits as the same agent. Which session did
  what is already recorded, in the `ASF-Session` trailer the same hook stamps (P8) — and an
  account name must never be written into the product (P6), which rules out the obvious
  alternative.

| # | Chosen | Against | Why |
| --- | --- | --- | --- |
| D1 | **The identity travels as `GIT_CONFIG_*` through `build_env`'s existing `git_config` channel**, and the session home's `.gitconfig` is written to match. | Writing only the `.gitconfig` (the smaller diff). | A `.gitconfig` is the *weakest* place to put it: `home_seed: [~/.gitconfig]` overwrites it (the code says so itself — *"a `.gitconfig` that `home_seed` put there is left alone"*), and a repo-local `user.name` from a product's `worktree_setup` beats it outright. P5 measures the environment channel beating both. Writing both means a session that somehow escapes `build_env` still does not author as the operator. |
| D2 | **One shared agent identity, defaulting to `asf worker <asf-worker@localhost>`.** | One identity per account, derived from the account name. | P6: an account name is a redaction pattern; putting it in an author field publishes the string the gate exists to suppress. | D3 | **The cloud lane renders the same resolved identity as the local lane.** | Leaving `actions.py`'s two hard-coded lines alone. | Two lanes of the same factory authoring under two different names is the same unreadable history in a smaller size, and it would make the check's output depend on which lane a row happened to take. | D4 | **`operator:` in `~/.ASF/config.yaml`, falling back to the operator's global git config.** | Requiring the key; or reading the git config only. | Requiring it means the check is dead until someone edits a file, and a check nobody turned on finds nothing. | D5 | **The check reports; it does not block.** | A `commit-msg` refusal, or a lane gate. | The `commit-msg` hook's stated contract is *"It never blocks"*, and a hook that refuses a commit strands a session mid-turn with work it cannot save. | D6 | **`--not <trunk ref>` — only a session branch's own commits.** | Every commit reachable from a session ref in the window. | P13: without it the check reports the operator's own trunk commits, which are allowed, and would be red on every factory from the first run. | D7 | **The line names the field that matched and never the value.** `<sha7> <branch> <author\|signoff\|author+signoff> <when> — <subject>`. | Printing the offending name and e-mail, which is friendlier to read. | P14. | D10 | **Published history is not rewritten.** | A one-off pass re-authoring the 406. | Every one of them is referenced by a merged PR and by shas in the record. The rule binds forward; §1.2 says so out loud so that a reviewer does not read the absence as an oversight. |

## 2. The design

### 2.1 `asf/identity.py` — the one owner

A new module, no dependency on `asf.workers`, so both the launch path and the doctor can import it.

```python
"""asf.identity — who a session commits as, and who it must not (F-0116)."""

#: What a worker session authors and signs off as when no account overrides it. Not an account
#: name (asf.redact builds its name patterns from those), not a person, not a host: the shape
#: asf.merge_queue.IDENT and asf.workers.spawn already mint for the factory's own commits.
AGENT_NAME = 'asf worker'
AGENT_EMAIL = 'asf-worker@localhost'


def agent_identity(acct=None):
    """``(name, email)`` a session of ``acct`` commits as: the account's ``identity:`` when it
    names one, else the defaults. Never the operator's, and never the account's own name."""


def operator_identity(cfg=None, operator_home=None):
    """``(name, email)`` the operator commits as: ``operator:`` in the shared config when it
    names one, else the operator's global ``user.name``/``user.email``
    (:func:`asf.workers.runtime.operator_git_identity`) — which is the identity a session was
    given before this card. Either half may be ``''``; an empty half matches nothing."""


def git_config_pairs(acct=None):
    """``[('user.name', …), ('user.email', …)]`` for :func:`asf.workers.runtime.build_env`'s
    ``git_config`` channel."""


def offenders(product, hours=24, now=None):
    """[:class:`Offender`] — read-only, no fetch. See §2.4."""


def violations(product, hours=24, now=None):
    """One line per offender, the shape D7 fixes. ``[]`` is a pass."""


def doctor_rows(product):
    """``[(ok, detail)]`` — one row per offender, or a single ok row saying how many commits in
    the window were checked."""
```

`operator_git_identity` stays where it is, in `asf/workers/runtime.py`; it is a git-config reader
and this module calls it. What moves is the *use*: nothing configures a session with its result
any more.

### 2.2 The launch — `asf/workers/runtime.py`, `asf/workers/pool.py`, `asf/env.py`

**`build_env`** gains the two pairs, beside the hook path it already passes:

```python
git_config = [('core.hooksPath', job.hooks_dir)] if job.hooks_dir else []
git_config += identity.git_config_pairs(acct)          # ← the session commits as itself
git_config += git_credential_config(auth)
```

By P5 this beats the session home's `.gitconfig`, a `home_seed`ed one, and a repo-local
`user.name` a `worktree_setup` may have set. By P3 the sign-off trailer follows with no change to
`ASF_HOOK`: the hook reads `git var GIT_AUTHOR_IDENT`, and that is now the agent.

**`write_identity_gitconfig(home, acct=None)`** writes the agent identity instead of the
operator's — same file, same marker line, same "a `home_seed`ed file is left alone" rule. Its
docstring and `GITCONFIG_MARK`'s comment both say *the operator's* today and must not. The
`operator_home` parameter goes; `_seed_home`'s call passes `acct`.

Keeping this file at all, given D1 makes the environment authoritative, is deliberate: it is what
an operator sees when they `cat` the session home to answer "what does this thing commit as", and
it is what covers any git invocation that reaches the session home without going through
`build_env`.

**`Account`** gains `identity` — a `{name, email}` map or `None` — parsed in `from_dict` from
`worker_pool.accounts[].identity`.

**`validate_worker_pool`** gains its arm, in the shape the others already have:

```
worker_pool.accounts[acct-a].identity   must map name and email to strings, not ['a']
worker_pool.accounts[acct-a].identity   name must be a string, not None
```

An account whose `identity` is malformed is a config problem at load, the same as a malformed
`auth_env` — not a silent fall back to the default, because falling back silently is how a
factory ends up authoring as something nobody chose.

### 2.3 Both lanes, one agent — `asf/workers/actions.py`

The rendered workflow's two literal lines become placeholders, substituted in `render_workflow`
from `identity.agent_identity()` the same way `@RUNS_ON@`, `@TIMEOUT@` and `@SECRET@` already are:

```yaml
          git config user.name "@IDENT_NAME@"
          git config user.email "@IDENT_EMAIL@"
```

The module docstring's *"Reinstall after changing cloud.runs_on, cloud.token_secret or
cloud.timeout_min"* gains the identity to that list, and `asf cloud doctor`'s existing
"the workflow on the default branch is the one ASF renders" comparison catches a stale one for
free.

The account-level override reaches the cloud lane through the row's account, as everything else
does; with no account resolved, the defaults.

### 2.4 The check — `offenders()`

Read-only and no fetch, in four steps, over whatever refs the checkout already has:

1. **The session refs.** `git for-each-ref --format='%(refname:short)' refs/heads refs/remotes/origin`,
   kept when the name — with a leading `origin/` stripped — starts with one of
   `product.conventions.all_prefixes()` (P11). Both local and remote-tracking, deduplicated by the
   commits they reach, because a lane branch may exist as either or both.
2. **The window, minus the trunk.**
   `git rev-list --since='<hours> hours ago' --no-merges <refs…> --not <trunk ref>`, where the
   trunk ref is `origin/<trunk>` when it resolves and `<trunk>` otherwise. D6/P13: the exclusion is
   what makes the result the session branches' *own* recent work.
3. **The fields.** One `git show -s --format=…` over every sha at once — author name, author
   e-mail, author date, subject, and the full body for the trailers.
4. **The judgement.** A commit offends when its author `(name, email)` equals the operator
   identity, **or** any `Signed-off-by:` trailer on it does. Comparison is case-insensitive and
   whitespace-trimmed on both halves; a half the operator identity leaves empty matches nothing,
   so a machine with no `user.email` set does not report every commit as a violation. Which of the
   two matched is carried on the `Offender` and named in the line.

An unreadable ref, a missing trunk, a repo that is not there: the module returns no offenders and
says why through the doctor row's detail. A check that cannot run says so; it never reports a pass
it did not establish, and it never raises into a tick.

### 2.5 The line, and the exit code — `asf identity`

```
<sha7> <branch> <author|signoff|author+signoff> <ISO-8601> — <subject>
```

No name, no e-mail, by D7/P14. Example, with the identity removed as the format requires:

```
a8a297d spec/F-0116 author+signoff 2026-09-30T10:28:10+02:00 — spec(F-0116): the identity of a session
```

`asf identity --product <p> [--hours 24]` prints one such line per offender to stdout and exits
**1**; prints nothing and exits **0** when there are none. That is the rule runner's check
contract verbatim (`asf/rules/rules.py:126-140`), so when a rule card is minted its `check:`
script is one line, and the surface table gains:

```python
'identity': ("scan the session branches for commits made under the operator's identity", None, None),
```

`None` for the effect: it reads and prints, and `scan` is already in `surface.VERBS` (P15).

### 2.6 The doctor row

In `run()`, beside the other per-product census rows:

```python
for ok, detail in identity.doctor_rows(product):
    rows.append(('session identity', False, ok, detail))
```

Not required (`False`): a red identity row is a thing to fix on a branch, not a reason to call the
whole factory broken. Clean, it is one row — `47 commits on 6 session branches in the last 24h,
none under the operator's identity` — which is also the row that proves the check ran at all.

### 2.7 The brief rule

The rule as it enters the record:

> A session authors and signs off its commits as itself — the agent identity the launch
> configures. The operator's name and e-mail appear only on commits the operator made. A brief
> template or preamble that tells a session to author or sign as the operator is a defect.

P10 says no template does today, so what lands is the guard: a test that renders a brief of every
kind in `asf.briefs.build.KINDS` — the machinery `doctor`'s `briefs` row already uses — and fails
on any rendered text matching *author/commit/sign* within a few words of *operator*, naming the
kind. The `git commit -s` lines in `preamble.py` stay exactly as they are: they name a flag, not a
person.

### 2.8 The two documents that currently describe the defect as the design

- `docs/guide/operating.md:401` — *"a `.gitconfig` with your `user.name` and `user.email` — none of
  your CLI logins"*. It becomes the agent identity, the override, and one sentence on why the
  operator's name is not there.
- `docs/config.example.yaml` — the `operator:` block, and `identity:` commented on an account
  beside `home_seed`, with the code host's `noreply` form as the worked example.

## 3. Acceptance tests

### 3.0 The precondition probe — **not an acceptance test**

lands it must stop passing, and it is not to be committed as a test — it is run once, pre-edit,

Read the four blocks in order and the design falls out of them. The first two are the defect: the
identity ASF writes is the operator's, and all three fields of the commit carry it. The third is
why a `.gitconfig` is not where the fix belongs — anything with a repo-local `user.name` already

fourth is the seam D1 chooses.

## 4. Records

What the change writes down, and where:

| What | Where | When |
| --- | --- | --- |
| The agent identity, as two git config keys | the session's environment, `GIT_CONFIG_COUNT`/`KEY_n`/`VALUE_n` | every launch, from `build_env` |
| The agent identity, as a file | `<ASF_HOME>/state/homes/<account>/.gitconfig`, under `GITCONFIG_MARK` | every launch, from `seed_home`; rewritten only when it differs |
| The agent identity, as two workflow lines | `.github/workflows/asf-worker.yml` in the product checkout | `asf cloud install`, which prints what to commit and pushes nothing |
| `author`, `committer` and `Signed-off-by:` | every commit a session makes, in both lanes | at commit time; the trailer by the existing `commit-msg` hook, unchanged |
| `ASF-Session:` — which session made it | every commit a session makes | already; unchanged, and this is what keeps attribution (P8) |
| One line per offending commit | stdout of `asf identity`, exit 1 | on demand, and from the rule runner once a card carries it |
| The `session identity` row | `asf doctor`'s table, not required | every doctor run |
| A config problem for a malformed `identity:` | `asf.env.load_config`'s problems, the `config` doctor row | config load |

Nothing is written to the record, and no commit already published is rewritten (§1.2, D10). The
check opens no network connection and mutates no ref: it reads `for-each-ref`, `rev-list` and
`show`, and nothing else.
