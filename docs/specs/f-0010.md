# F-0010 — the evidence pass reads a provider, not a vendor

`asf/evidence/evidence.py` is 1464 lines that know exactly one code host. `sh()` builds a shell
string and runs it in the product repo (`asf/evidence/evidence.py:80`); `_gh_json` prefixes every
query with the literal `gh` and the product's `repo_slug` (`:1289`); `pr_list` spells out a
`gh pr list … --json number,title,body,state,headRefName,mergedAt,mergeCommit` (`:203`);
`_newest_success` and `_newest_with_job` spell out `gh run list` and `gh api
repos/…/actions/runs/…/jobs` (`:394`, `:401`). There is no seam. A product on another host cannot
be read at all, and a *test* of the pass can only reach it by monkeypatching module attributes —
which is what the suite does: `mock.patch.object(evidence, "pr_list", …)` and
`mock.patch.object(evidence, "_gh_json", …)` (`tests/test_evidence.py:393`),
`mock.patch.object(ingest.evidence, 'load', …)` six times over (`tests/test_ingest.py:81`, `:372`,
`:584`, `:640`, `:851`, `:970`). Every one of those patches is a private name; every one of them
breaks when the private name moves, and none of them exercises the code that actually talks to the
host.

The repo already knows how to do this properly, twice. `asf/ci_queue.py:671` declares
`class Source` — "what the queue reads off the CI host" — with `GitHubSource(product, run=None)`
under it (`:731`), and eighteen tests construct it with a fake `run` instead of patching
(`tests/test_ci_queue.py:125`, `tests/test_ci_phantom.py:137`, …).
`asf/workers/runtime.py:501` declares `class Runtime` with `ClaudeCodeRuntime` and `FakeRuntime`
beside it (`:513`, `:556`), picked by config (`:613`). `asf/workers/quota.py:74` declares
`QuotaSource` with `FakeQuotaSource` (`:79`). Evidence is the one host-reading pass in the factory
that never got a seam.

This spec gives it three, because it reads three different things: **git** (refs, the object
store, the trunk log), **the code host's PR API** (pull requests and workflow runs), and **the
deployed sha** — which today has three independent readers in the tree
(`asf/evidence/evidence.py:394`, `asf/harvest/deploy.py:322`, `asf/views/prod.py:45`) and a
documented `deploy_sha.provider` key (`docs/products.example.yaml:237`) that no line of Python
reads. With the seams in place, two recorded fixtures replay both halves offline: a **redacted
snapshot of a live product** and the **sample product**, which carries `ci: {provider: none}` and
`deploy_sha: none` (`sample/product.yaml`) and so proves the no-host path.

Behind that seam, two derived fields that the factory already consumes but nothing produces.
`asf/feeder/rows.py:336` raises the `CONFLICT → REBASE` row off `item.get('mergeable') ==
CONFLICTING` — and `mergeable` appears nowhere in `asf/`, only hand-written into
`tests/fixtures/feeder/index.json:307`, so the row has never fired for a real PR.
`asf/feeder/render.py:43` runs the S1 incident clock off `stage_since or created` — but
`asf/record/ingest.py:334` moves `stage_since` on every state change, so launching a fix session
for an S1 Bug resets the clock that exists to catch a launch that failed, and the sample's own S1
Bug has no typed `created` to fall back to (`sample/backlog/bugs/B-0001.md`). F-0071 D7 already
ruled the clock must not restart (`docs/specs/f-0071.md:82`); the code reads the two keys in the
opposite order. `opened` is the immutable key that settles it.

## 1. Decisions

### 1.1 Preconditions

- **`class Source` in `asf/ci_queue.py:671` is the house shape for a host behind an interface**:
  a docstring-only base whose every method is `raise NotImplementedError` or a `None`-returning
  default, one concrete subclass taking `(product, run=None)`, and tests that construct the
  concrete class with a fake `run` rather than patching a module attribute. This spec copies that
  shape and does not invent a second one.
- **`asf/workers/runtime.py:613` is the house shape for *picking* an implementation**: a function
  reading the config block and returning the concrete instance, with `FakeRuntime(path=…)` chosen
  by the presence of a scripted file. The provider picker is the same function shape.
- **`discover()` is already the single gathering call** (`asf/evidence/evidence.py:416`) and
  `load()` is already the only cache in front of it (`:1421`, `EVIDENCE_TTL` 180s, one file per
  product under `env.state_dir(product)` — `_cache_file`, `:70`). Nothing else in the tree calls
  `sh`, `_batch` or `_gh_json`; `grep -rn "evidence\.sh\|evidence\._gh_json" asf/` is empty. The
  seam therefore goes in one place and no caller outside this module changes.
- **`ci_provider(product)` already returns `None` for `ci: none`, `ci: off` or no provider at
  all** (`:787`), and `ci_green_runs` already returns `[]` for a provider it does not know
  (`:795`), and `id_evidence` already has a whole no-CI branch that marks every landed commit
  green outright (`:1067`). "No host" is an existing, tested state, not a new one.
- **`deploy_sha.provider` is documented and unread.** `docs/products.example.yaml:237` offers
  `github-deployments | fly | vercel | script`; `grep -rn "github-deployments" asf/*.py
  asf/**/*.py` finds it only in `asf/views/prod.py:45`, and `asf/harvest/deploy.py:129` reads a
  *per-target* `source: vercel` instead. `asf/evidence/evidence.py` reads neither: it goes
  straight to `conventions.deploy_workflow`'s newest success. Three readers, one documented key,
  no owner.
- **`env.Product` already validates `deploy_sha`'s modes and targets** (`asf/env.py:500`, `:526`)
  and `asf/env.py:442` lists `ci` and `deploy_sha` as free-form blocks. The provider key needs a
  validator row, not a new config surface.
- **`asf/record/ingest.py:32` declares `MACHINE_KEY_ORDER` and its own contract**: "any other
  machine key … is someone else's and is carried through untouched — ingest never drops a key it
  does not itself derive". A key ingest *does* derive must be listed there, or it is dropped on
  the next write.
- **`_ingest_fields` skips the write when nothing but `updated` changed**
  (`asf/record/ingest.py:338`): `new_cmp == old_cmp` → `None`. A new derived key on every card
  would therefore rewrite every card once, with a `## History` line each.
- **`asf/schema.py:42` is the mechanism for a one-time backfill**: "A new schema adds one entry
  and bumps `SCHEMA_VERSION`", `MIGRATIONS = {1: _migrate_to_1}`, `SCHEMA_VERSION = 1` (`:31`),
  and `stamp_cards` rewrites only the cards below the target (`:82`).
- **Invariant I6 compares `{state, stage, evidence}` and nothing else**
  (`asf/invariants._derived_fields`, `asf/invariants.py:778`; I6 at `:797`). A sticky key is
  outside what I6 re-derives, so `opened` does not break it — but it is only safe *because* of
  that, and the spec says so rather than discovering it in review.
- **`asf/feeder/rows.py:336` already prefers the typed key** and falls back to grepping the
  evidence lines: `item.get('mergeable') == CONFLICTING or any(CONFLICTING in e for e in
  item.get('evidence') or [])`. Producing the key makes the first clause live; the fallback is
  what has been carrying the row.
- **`asf/feeder/render.py:31` `incidents()` is pure over the index** — it takes
  `(index, inflight, now, product)` and touches no host — so the clock is unit-testable the
  moment the key exists. `s1_hours` defaults to 2 (`:25`).
- **`tests/gitfixture.py` builds a real origin + clone once per module and `copytree`s it per
  test** (`Template.fresh`, `tests/gitfixture.py:36`). The git provider's tests run against a
  real repo through it; nothing about the git seam needs a recording.
- **`tests/test_sample_product.py` already runs the sample end to end** — `asf init`, `asf next`,
  `asf tick` against a copied `sample/` with `@REPO@`/`@BACKLOG@` filled in (`:68`–`:96`) — and
  already asserts the S1 Bug is launched on its `bugfix/` branch (`:166`). The sample fixture
  exists; it gains assertions, not a harness.
- **`asf.redact.scrub(text, pats, token)` already exists** (`asf/redact.py:235`) and
  `tools/check_generic.sh` runs `asf.redact --tree` over every tracked file against
  `tools/forbidden-names.txt`. A recorded snapshot of a live product is a tracked file and must be
  scrubbed before it is committed, or the build refuses it.
- **`tools/check_conventions.sh` forbids a path-shaped default from `asf.conventions` appearing
  literally in `asf/**/*.py`**, and `tools/check_generic.sh` forbids any product, company, person,
  vendor, account or host name in any tracked file but `LICENSE`. Both constrain what the fixture
  and the provider modules may contain.
- **The gate is** `python3 tools/run_tests.py`, `tools/check_generic.sh`,
  `tools/check_conventions.sh`, `asf plugin check`, and `python3 -m unittest tests.test_sample_product`.

### 1.2 In

- **`asf/evidence/sources.py`** (new, stdlib only) — the three interfaces and their
  implementations: `GitSource`/`LocalGit`, `HostSource`/`GitHubHost`/`NoHost`,
  `DeploySource`/`WorkflowDeploy`/`NoDeploy`, the `Recorded` replayer that satisfies all three
  from a JSON snapshot, and `for_product(product)` → `Sources(git, host, deploy)`.
- **`asf/evidence/evidence.py`** — `discover(product, sources=None, checked_file=None)` and
  `load(..., sources=None)`; every `sh`/`_batch`/`_gh_json` body becomes a call on
  `sources.git` or `sources.host`; the deploy-sha pair becomes one call on `sources.deploy`.
  `sh`, `resolve`, `read_blobs`, `read_trees`, `read_refs`, `remote_branches`, `pr_list`,
  `main_commits`, `ancestry` keep their present names and signatures, gaining an optional
  `sources=` — the pure functions below them (`plan_tasks`, `parse_rows`, `naming_ids`,
  `id_state`, `task_state`, `feature_stage`, …) are untouched.
- **`mergeable`** — `pr_list` reads the field, `id_evidence` carries it per id, `id_state` emits
  it, `ingest` writes it as a machine key, and `asf/feeder/rows.py:336`'s first clause goes live.
- **`opened`** — a sticky machine key ingest writes once and never moves, seeded for the existing
  record by `asf.schema.MIGRATIONS[2]`, and read first by `asf/feeder/render.py`'s S1 clock.
- **`asf/harvest/deploy.py` and `asf/views/prod.py`** — their deployed-sha reads go through
  `sources.deploy`; their own behaviour, output and config keys are unchanged.
- **`tests/fixtures/evidence/live/`** — a redacted recorded snapshot of a live product (git,
  host and deploy answers), and `tests/fixtures/evidence/sample/` for the sample's no-host shape.
- **Tests** — `tests/test_evidence_sources.py` (new), and the §3 blocks over
  `tests/test_evidence.py`, `tests/test_ingest.py`, `tests/test_feeder.py`,
  `tests/test_sample_product.py`.

### 1.3 Out

- **A second code host.** The card asks for the PR API *behind an interface*, not for a second
  implementation of it. `GitHubHost` and `NoHost` are the two that ship; the interface is what
  makes a third possible, and writing one without a product to test it against would be
  unverifiable code.
- **Folding `ci_queue.Source` into `HostSource`.** They answer different questions of the same
  host: the queue reads runners, attempts and live jobs to decide what may start
  (`asf/ci_queue.py:671`–`:730`); evidence reads pull requests and completed runs to decide what
  has landed. Merging them would give the evidence pass reach into runner admission, and give the
  queue a reason to import the record. They stay two interfaces over one host — §2.2 names the
  overlap explicitly so nobody re-derives it.
- **Changing what any state rule decides.** `task_state`, `story_state`, `feature_state`,
  `feature_stage`, `bug_state`, `epic_state`, `id_state`'s vocabulary and every evidence line's
  wording stay byte-identical, except for the one new `mergeable` line. The recorded live fixture
  exists to prove that: the machine block it derives is asserted whole.
- **The cache.** `load()` keeps its 180s TTL, its per-product path and its atomic replace. A
  `Recorded` source is fed to `discover` directly; recording is not a cache mode.
- **A new CLI command.** `asf evidence --json` grows `--record <dir>`; no subcommand is added.
- **Unticking or re-deriving `opened`.** It is written once. A card whose work restarts gets a
  new `stage_since`, never a new `opened` — that is the whole point.
- **`mergeable` for anything but an open PR.** A merged or closed PR has no meaningful mergeable
  state; the key is absent then, and `ingest` drops an absent derived key (§2.4).
- **Making `UNKNOWN` a conflict.** The host computes mergeability asynchronously and answers
  `UNKNOWN` while it is thinking. A `CONFLICT → REBASE` row launches a session; raising one off
  "not computed yet" would launch rebases against nothing.
- **Deploying anything.** `asf/harvest/deploy.py`'s dispatch logic, modes and holds are
  untouched; only where it *reads* a sha changes.
- **A schema surface for the fixtures.** The snapshot is a test fixture, not a supported
  interchange format, and carries no `schema_version`.

### 1.4 The choices

| # | Chosen | Against | Why |
| --- | --- | --- | --- |
| D1 | Three interfaces in one new module `asf/evidence/sources.py`, carried together as a `Sources(git, host, deploy)` namedtuple threaded through `discover` | one `EvidenceSource` with every method on it | The card names three, and they have three different failure modes and three different config keys: git is always present and local, the host is absent under `ci: none`, the deploy sha is absent under `deploy_sha: none`. One class would make "no host" mean "no git". A namedtuple keeps the call sites to one parameter. |

A passthrough would put a vendor's JSON field names in the caller and defeat the seam. |

| D9 | The live fixture is a *redacted* snapshot committed under `tests/fixtures/evidence/live/`, product name `live`, produced by `asf evidence --json --record` and passed through `asf.redact.scrub` | committing the raw snapshot, or synthesising one by hand | `tools/check_generic.sh` refuses any product, person or host name in a tracked file, so a raw snapshot cannot land (`asf/redact.py:235` is the scrubber that already exists for this). ## 2. The design

### 2.1 `asf/evidence/sources.py` — the three interfaces

Stdlib only. No path literal, no product name, no vendor string outside the one concrete class
that needs it. Docstring-only bases, in the shape of `asf/ci_queue.py:671`:

```python
Sources = collections.namedtuple('Sources', 'git host deploy')


class GitSource:
    """Every read of the product repo the evidence pass makes. Read-only: the one write it may
    do is `fetch --prune`."""

    def run(self, args, timeout=120):
        """`git <args>` in the product repo: stdout, stripped. '' on any failure."""
        raise NotImplementedError

    def cat_file(self, kind, requests):
        """One `cat-file --batch[-check]` for the whole list, answers in request order, None for
        a missing object. `kind` is 'check' (→ oid) or 'blob' (→ bytes)."""
        raise NotImplementedError

    def fetch(self):
        """`fetch --prune origin`. A no-op for a source that cannot fetch."""
        return None


class HostSource:
    """What the evidence pass reads off the code host. Never runners, never live jobs — those
    are `asf.ci_queue.Source`'s (§2.2)."""

    #: what `prs()` answers with, per pull request
    PR_FIELDS = ('number', 'title', 'body', 'state', 'headRefName', 'mergedAt',
                 'mergeCommit', 'mergeable', 'createdAt')

    def prs(self):
        """Every pull request, any state, newest first: [{PR_FIELDS}]. [] when there is none or
        it is unreadable."""
        raise NotImplementedError

    def runs(self, workflow, branch=None, status=None, limit=20):
        """[{headSha, conclusion, status, createdAt, updatedAt, databaseId}], newest first."""
        raise NotImplementedError

    def run_jobs(self, run_id):
        """[{name, conclusion}] of one run's jobs."""
        return []


class DeploySource:
    """The deployed sha per environment — the code host's deploy workflow, a vendor's API or a
    product script, behind one call."""

    def sha(self, env_name):
        """The sha deployed to `env_name` ('prod', 'dev', a named target), or None when the
        product names no way to read it."""
        raise NotImplementedError
```

`LocalGit(product, run=subprocess.run)` is `GitSource` over the resolved `product.repo_dir`,
carrying the two bodies that exist today: `run()` is `sh`'s `subprocess.run(..., cwd=repo_dir)`
with the argv form, and `cat_file` is `_batch`'s position-keyed parser verbatim
(`asf/evidence/evidence.py:92`–`:123`), comment included — the "answers arrive in request order,
and a missing object still costs one line" contract is the parser's whole correctness argument
and it moves with the parser.

`GitHubHost(product, run=subprocess.run)` is `HostSource` over `gh`, holding the only `gh`
strings left in the evidence half: `pr list -R <slug> --state all --limit 300 --json <PR_FIELDS>`,
`run list …`, `api repos/<slug>/actions/runs/<id>/jobs`. The per-PR cache moves here too —
`pr_list`'s `PR_TTL` file (`:203`) becomes `GitHubHost`'s, so a provider that needs no cache does
not carry one.

`NoHost()` answers `[]`, `[]`, `[]`. `for_product` returns it when `ci_provider(product) is None`,
so no `gh` process is started for a product with no host (D4).

`WorkflowDeploy(product, host)` reads `deploy_sha.<env>.workflow`'s newest success through the
*host* provider — the one place the two interfaces compose. `NoDeploy()` answers `None` for every
environment. `for_product` dispatches on `deploy_sha.provider`, defaulting to `WorkflowDeploy`
when a workflow is named and `NoDeploy` when nothing is.

`Recorded(snapshot)` satisfies all three. The snapshot is a directory of JSON files, one per
interface, each a flat map from a call key to its answer:

```json
{
  "git.run:rev-parse origin/main": "9f1c2b0…",
  "git.cat_file:check:origin/main:docs/specs/f-0002.md": "4b7a…",
  "host.prs": [{"number": 41, "state": "OPEN", "mergeable": "CONFLICTING", "...": "..."}],
  "deploy.sha:prod": "9f1c2b0…"
}
```

The key is `<interface>.<method>` plus the arguments joined by `:` — never a command line (D7).
`blob` answers are base64, because a blob is bytes. An unrecorded key raises
`KeyError("evidence fixture: no answer for host.runs:ci.yml:main")` (D8).

`for_product(product, git=None, host=None, deploy=None)` returns `Sources`, each argument
overriding the picked default — the shape of `asf/workers/runtime.py:613`.

### 2.2 What each interface owns, and the one it is not

`HostSource` and `asf.ci_queue.Source` both read the same host. The split is by question, and it
is written into both docstrings so it is not re-litigated:

| | reads | to decide | lives in |
| --- | --- | --- | --- |
| `HostSource` | pull requests, completed workflow runs, a run's job conclusions | what has landed, what is open, what is green | `asf/evidence/sources.py` |
| `ci_queue.Source` | runners, attempts, live jobs, busy runners, run files | what may start now | `asf/ci_queue.py:671` |

Neither imports the other. `asf/evidence/sources.py` imports `asf.env` and `asf.conventions` and
nothing else of `asf`; in particular it does not import `asf.record`, so the direction of the
passes (ingest reads evidence, never the reverse) is enforced by the import graph.

### 2.3 `evidence.py`: every host read behind the seam

`discover(product=None, sources=None, checked_file=None)` resolves `sources` once at the top and
threads it down. The mechanical changes, none of which alter a returned value:

| today | after |
| --- | --- |
| `sh(cmd, timeout, product)` — `shell=True` (`:80`) | splits and delegates to `sources.git.run(argv, timeout)`; signature kept (D3) |
| `_batch(kind, requests, product)` (`:92`) | `sources.git.cat_file(kind, requests)`; the parser moves into `LocalGit` |
