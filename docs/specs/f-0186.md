# F-0186 — the field exists; two readers of "is this a document" do not agree

The card asks for `conventions.doc_paths`: extra globs a product declares as documents, counting
for docs-only landing and for the doc lane, never for code gates, empty by default, listed by
doctor. It names two tests — a branch touching `specs_dir` plus a declared doc path lands
natively, an undeclared path does not.

Most of that is on the trunk already. At `d005de847` the field exists
(`asf/conventions.py:187-190`, `:714-715`), it is shape-checked (`validate_mapping`,
`asf/conventions.py:461-465`), it is documented (`docs/products.example.yaml:161`), and
`lane.landing_class` (`asf/harvest/lane.py:319-331`) already unions the three document
directories with the product's `doc_paths` globs. `asf/tick/land_spec.py:81` — the reader that
decides whether an approved spec branch lands as it stands or goes back to a session — reads
exactly that function. The card's two named tests **pass as written today**; the probe that ran
them against this checkout is in §3.1, and its outcome is why this spec does not re-mint the
field.

What is not true is the rest of the sentence. Three things:

**A second reader of "is this a document" disagrees with the first.** `asf.evidence.evidence`
keeps its own rule — `doc_dirs` (`:1061-1066`) returns the three directories and nothing else,
and `docs_only` (`:1068-1072`) matches them by `str.startswith`, with no globs at all. Against a
product that declares `doc_paths: [decisions/**]`, the two readers split:

```
landing_class(p, ['docs/specs/f-0186.md', 'decisions/0007-x.md'])  ->  docs
doc_dirs(p)                                                        ->  ('docs/specs/', 'docs/plans/', 'docs/reviews/')
docs_only(['docs/specs/f-0186.md', 'decisions/0007-x.md'], dirs)   ->  False
```

That reader is what keeps a document from being read as a Feature's code landing
(`asf/evidence/evidence.py:1238` for a trunk commit, `:1257` for a merged non-lane PR) — the
B-0059/B-0114 defect where landing eight specs closed four Features. A conforming subject
(`spec(F-0186): …`) is caught by `DOC_LANE_SUBJECT` (`:913`) before `docs_only` is consulted, so
the hole opens exactly where the subject is not the lane's: a merge queue composes its own
subject and `squash_subject` is dropped on `--auto`/`--rebase`, which `asf/harvest/lane.py:2918-2921`
says outright is fine because "a document lane is recognised by its paths instead
(`asf.evidence.evidence.docs_only`), which holds as long as it touches only documents". Declare a
doc path, land a spec that touches it through a queue, and that sentence stops holding: the merge
commit is taken as the Feature's landing, the Feature reads landed, and the feeder launches no
coder for it.

**doctor does not list them.** There is no `doc_paths` row (`asf/doctor.py` has no reader for the
key; `check_convention_shapes`, `:594-607`, reports only misshapen keys). An operator installing
a product cannot see from `asf doctor` which folders this product counts as documents, which is
the one question the card's first-customer story turns on.

**Nothing pins the landing.** The only coverage of the union is `tests/test_lane.py:312-318`,
which calls `landing_class` directly. No test says a spec branch touching a declared doc path
*lands natively* — so the property the card exists for can be narrowed again, at
`land_spec.why_not_as_is` or anywhere between, without a red test.

## Decisions

### In

1. One docs rule, in one list: `evidence.doc_dirs` returns what `lane` builds, and
   `evidence.docs_only` matches it the way `lane` matches — globs included.
2. `asf doctor` lists a product's declared doc paths, always green, never required.
3. The card's two named tests, plus the code fence, written at the level that proves them —
   `land_spec.why_not_as_is` and `land_spec.adopt`, not `landing_class` alone.

### Out

- Re-minting `conventions.doc_paths`. It exists, it is parsed, it is validated, it defaults to
  `()`, and it is documented. Nothing in §2 adds a convention key.
- `asf/scorecard/pairs.py:71-88` (`touched`), which strips the three document directories from a
  Feature's measured footprint. It measures what a Feature's *code* touches for pairing, not
  whether a branch lands as documents; widening it silently changes every scorecard number a
  product with `doc_paths` has recorded. If it should follow, that is its own card.
- `asf/evidence/evidence.py:1163` (`dirs = {"spec": …, "plan": …}`), which maps a document *kind*
  to the directory that holds it so a merged lane PR's spec file can be named. A `doc_paths` glob
  carries no kind and can be no spec or plan carrier, so it has no place there.
- The spec session's own writes footprint (`asf/roles/launch.py:57`:
  `{specs_dir}/** {plans_dir}/** <record>/**`). A session that must *write* a product's decision
  register needs that footprint widened; this card is about a branch that already carries such a
  file **landing**, not about minting one. Separate card.
- `docs/guide/product-config.md`. `doc_paths` is documented where a product is configured
  (`docs/products.example.yaml:161`); the guide's landing section describes the landing classes,
  which do not change.

## The design

### 2.1 One docs rule, one list

`asf/harvest/lane.py` — `_glob_hit` is renamed `path_hit` (D4), its two existing call sites
(`landing_class`, `shared_hits`) follow, and the docs roots move out of `landing_class` into a
function of their own:

```python
def path_hit(pattern, path):
    """True when ``path`` answers to ``pattern`` — the one path-vs-glob rule: a trailing ``/``
    is a root (prefix), anything else is an fnmatch glob that also matches as a directory
    prefix. Read by :func:`landing_class`, :func:`shared_hits` and
    :func:`asf.evidence.evidence.docs_only`."""
    pattern = str(pattern).strip()
    if not pattern:
        return False
    if pattern.endswith('/'):
        return path.startswith(pattern)
    return fnmatch.fnmatch(path, pattern) or path.startswith(pattern.rstrip('/') + '/')


def doc_matchers(product):
    """Every matcher a document path answers to: ``specs_dir``, ``plans_dir`` and ``reviews_dir``
    as roots, then each ``conventions.doc_paths`` glob the product declared. The one list of what
    counts as a document — :func:`landing_class` classes a branch by it and
    :func:`asf.evidence.evidence.doc_dirs` reads it, so the landing and the evidence cannot
    disagree about a folder."""
    conv = _conv(product)
    roots = tuple(str(conv.get(k)).strip('/') + '/'
                  for k in ('specs_dir', 'plans_dir', 'reviews_dir') if conv.get(k))
    return roots + tuple(g for g in (str(g).strip() for g in conv.get('doc_paths') or ()) if g)


def landing_class(product, files):
    """:data:`DOCS` when every path in ``files`` is a document (:func:`doc_matchers`) — else
    :data:`CODE`. The one rule for docs vs code."""
    matchers = doc_matchers(product)
    files = [f for f in files or () if f]
    if files and all(any(path_hit(m, f) for m in matchers) for f in files):
        return DOCS
    return CODE
```

`landing_class`'s behaviour is unchanged — same union, same all-files rule, same `CODE` for an
empty list. That is what keeps the fence the card asks for: one code path among the touched files
and the branch is `CODE`, so no `doc_paths` glob can make a code branch skip a gate
(`asf/harvest/lane.py:1002`) or skip a re-gate (`:1178`).

`asf/evidence/evidence.py` — the second reader becomes the first:

```python
def doc_dirs(product):
    """The matchers a document lane writes: ``specs_dir``, ``plans_dir``, ``reviews_dir`` and the
    product's ``conventions.doc_paths`` globs — :func:`asf.harvest.lane.doc_matchers`, so the
    evidence and the landing read one list. Computed once per pass and handed to
    :func:`docs_only`."""
    from asf.harvest import lane  # local: lane reads this module (§ the import direction)
    return tuple(lane.doc_matchers(product if product is not None else Conventions()))


def docs_only(paths, dirs):
    """True when every path a commit touched is a document — a spec, a plan, a review, or a path
    the product declared in ``conventions.doc_paths``. A commit whose paths are unknown (none
    read) is not judged docs-only — it stays landing evidence."""
    from asf.harvest import lane  # local: lane reads this module
    paths = [p for p in paths or () if p]
    return bool(paths) and all(any(lane.path_hit(d, p) for d in dirs) for p in paths)
```

`doc_dirs(None)` keeps returning the three default directories — `lane._conv` resolves a bare
`Conventions` the same way `doc_dirs` does today, so the `product=None` call shape does not
change. Both callers (`item_facts`, `:1229`) are untouched: `dirs` is still computed once and
passed down.

With `doc_paths` empty — every product that has not opted in — `doc_matchers` returns exactly the
three roots and `path_hit` on a trailing-`/` root is `str.startswith`, so `docs_only` is the same
function it is today, path for path.

### 2.2 doctor lists them

`asf/doctor.py` — one reader and one row:

```python
def check_doc_paths(product):
    """[(ok, detail)] — the ``doc paths`` row: the document folders this product declared in
    ``conventions.doc_paths`` beside its specs, plans and reviews directories. A branch touching
    only these lands as documents (:func:`asf.harvest.lane.landing_class`) and is not a Feature's
    code landing (:func:`asf.evidence.evidence.docs_only`), so the operator has to be able to read
    which folders those are. Always green: a misshapen value is the ``conventions`` row's red
    (:func:`check_convention_shapes`), and a glob that matches nothing today is not a fault."""
    conv = getattr(product, 'conventions', None)
    dirs = ', '.join(str(conv.get(k)).strip('/')
                     for k in ('specs_dir', 'plans_dir', 'reviews_dir') if conv.get(k)) \
        if conv is not None else ''
    declared = [str(g).strip() for g in (getattr(conv, 'doc_paths', None) or ())
                if str(g).strip()] if isinstance(getattr(conv, 'doc_paths', None), (list, tuple)) \
        else []
    if not declared:
        return [(True, f'doc paths: none declared — documents are {dirs or "unset"}')]
    return [(True, f'doc paths: {len(declared)} declared beside {dirs or "unset"} — '
                   f'{", ".join(declared)}')]
```

wired in `doctor.run` immediately after the `conventions` rows (`asf/doctor.py:869-871`):

```python
    for ok, detail in check_convention_shapes(product):
        rows.append(('conventions', True, ok, detail))
    for ok, detail in check_doc_paths(product):
        rows.append(('doc paths', False, ok, detail))
```

Two lines an operator can read on a fresh install:

```
doc paths    none declared — documents are docs/specs, docs/plans, docs/reviews
doc paths    2 declared beside docs/specs, docs/plans, docs/reviews — decisions/**, docs/guide/*
```
