# F-0135 — five of the card's six bullets are on the trunk; this spec is the complement

The card asks for "a native landing for the PR lane", on the premise that **"nothing in ASF merges
a PR once its checks are green"**. That premise is false in this checkout. The lane merges PRs
natively, on the approvals matrix, through the repo's merge method, in the card's own order, under
the card's own capacity keys, and sends a red PR back to its session — all of it with tests.

What is true is the card's fifth bullet, and only that one: **`steps.batch` is still mandatory.**
A product cannot simply stop declaring it. Undeclared, `batch` has no owner, and the two places
that ask refuse:

```
$ python3 -c "... env.Product('p', {'conventions': {'landing': 'pull-request'}}) ..."
check_owned RAISED: tick: step batch has no owner — declare it under steps in
                    products/p.yaml (asf | <command> | off)

SchedulerError: clock dispatch: tick: step batch has no owner — declare it under steps in
                products/p.yaml (asf | <command> | off)
```

So a PR-landing product that has deleted its merge-queue script must still write `batch: off` — a
value whose documented meaning is "*the operator says another job still runs it*"
(`asf/tick/steps.py:10`). For a product that lands natively that declaration is a false statement,
and it is the last line of the legacy the first customer is removing.

Making it optional is one condition in one function. The spec's real work is the **second** half:
`lane.landing()` infers `pull-request` from a set `steps.batch`, so the moment `batch` may be
absent, deleting that line silently re-points the product's landing at **fast-forward**, which
pushes straight to the trunk and opens no PR at all. Today that mistake is loud (the tick exits 2
and no clock loads). This change would make it silent and destructive. It is closed here.

### 1.4 In and out

**In.** `batch` optional (D1, D2); the inferred-landing doctor row (D4, D5); the corrected manifest
golden and resolution test (D6); a clock naming `batch` loading with `batch` absent (P3).

**Out, and why.**

- **The native PR landing itself** — §1.1: it is on the trunk, with tests. This spec re-specifies
  none of it and changes no merge behaviour, no approvals class, no capacity key, no order.
- **`conventions.landing` becoming required, or its default changing** (D3). Either is a silent
  landing-mode flip for products that exist. If the inference is ever to be retired, the sequence
  is: this spec's doctor row → operators declare `landing` → the limb goes. That last step is a
  new card, not a Story here.
- **`steps: {batch: false}`** — P6: `false` parses to the boolean `False`, which `resolve()`
  stringifies to `'False'` and runs as a **command named `False`**, while `lane.landing()` does
  read `batch is False` as off. A real latent inconsistency, pre-existing, not on the card's path,
  and not the documented spelling (`off` is). It wants its own bug card, not a widened footprint.
- **`asf/merge_queue.py`, `conventions.merge: queue`, `merge: auto`, `asf adopt-pr` (F-0125).**
  Untouched.
- **Any new product-yaml key.** `OPTIONAL_STEPS` is a constant in the package, not configuration.

## 2. The design

### 2.1 `asf/tick/steps.py` — one constant and one condition

```python
 ASF_STEPS = tuple(ASF_CALLABLES)

+#: Steps a product need not declare. ``batch`` is a product's *own* merge-queue script: a product
+#: that lands natively (``asf.harvest.lane.merge_prs`` merges its PRs on the approvals matrix and
+#: the required checks) has no script to name, and must not be made to write ``off`` — whose
+#: meaning is "another job still runs it" — to say so. Absent, an optional step is ``off``.
+OPTIONAL_STEPS = ('batch',)
+
 DEFAULT_LEGACY_TIMEOUT_S = 900
```

In `resolve()`, ahead of the existing branch (the order matters: the new test is on `text is None`
alone, so it must be asked before the `text is None or text == 'asf'` one):

```python
         value = decl.get(step)
         text = str(value).strip() if value is not None else None
-        if text is None or text == 'asf':
+        if text is None and step in OPTIONAL_STEPS:
+            # an optional step nobody declared is off, not ownerless (D1, D2): a PR product that
+            # lands natively has no merge-queue script to name. `batch: asf` is still a refusal —
+            # asf has no batch implementation to ask for.
+            owner, command = 'off', None
+        elif text is None or text == 'asf':
             # undeclared falls back to asf only for a step asf has; `asf` for a step
             # with no asf implementation is as ownerless as no declaration at all
             owner, command = ('asf' if step in ASF_STEPS else 'undeclared'), None
```

`check_owned` is **unchanged**: it never sees an `undeclared` `batch` again, because `resolve()` no
longer produces one from absence. The module docstring's "`batch` … has no `asf` implementation and
must be declared" (`:14`) becomes: it has no `asf` implementation, and may be left undeclared —
then it is off; declared as a command, it runs.

Both refusals of §0 are closed by this one edit, because both call `resolve()` + `check_owned()`:
the tick's own preflight (P2) and `scheduler._clock_refusal` (P3). No change in `asf/scheduler.py`.

### 2.2 `asf/doctor.py` — the `landing` row

```python
+def check_landing(product):
+    """[(ok, detail)] — one RED finding when the product's landing mode is *inferred* from
+    ``steps.batch`` instead of declared (D4, D5).
+
+    ``asf.harvest.lane.landing`` reads ``conventions.landing`` first and, with it unset, reads a
+    declared ``steps.batch`` command as ``pull-request``. Since ``batch`` is optional
+    (:data:`asf.tick.steps.OPTIONAL_STEPS`), deleting that one line moves such a product to
+    ``fast-forward`` — pushing the gated head straight onto the trunk, opening no PR — with no
+    refusal anywhere. This row is what makes that ambiguity visible while the line is still there.
+    A product that declares ``conventions.landing`` (either value), or whose ``batch`` is off or
+    absent, draws nothing."""
+    from asf.harvest import lane
+    from asf.tick import steps as tick_steps
+    if (product.conventions.get('landing') or '').strip():
+        return []
+    owner = dict((s, o) for s, o, _c in tick_steps.resolve(product)).get('batch')
+    if owner != 'command':
+        return []
+    line = env.key_line(env.product_path(product.name), 'steps.batch')
+    where = f'products/{product.name}.yaml:{line}: ' if line else ''
+    return [(False, f'{where}landing is inferred as {lane.landing(product)} from steps.batch — '
+                    f'declare conventions.landing in products/{product.name}.yaml; deleting '
+                    f'steps.batch would move this product to fast-forward and push to '
+                    f'{product.conventions.main} without a PR')]
```

Appended in the product section beside the other configuration rows (`asf/doctor.py:870`), red
when it fires (P9):

```python
     for ok, detail in check_convention_shapes(product):
         rows.append(('conventions', True, ok, detail))
+    for ok, detail in check_landing(product):
+        rows.append(('landing', True, ok, detail))
```

### 2.3 What it looks like when it is there

A PR-landing product's yaml, complete, with no merge-queue machinery of its own:

```yaml
conventions:
  landing: pull-request          # declared, never inferred
  landing_checks: [gate]
capacity:
  batch:
    per_run: 2                   # at most 2 merges a tick
    parallel: 1                  # at most 1 in the repo's merge queue at a time
steps:
  daily: off
                                 # no `batch:` line at all
clocks:
  dispatch:
    steps: [health, groom, wave, prs, harvest]
    every: 10m
```

`asf tick --manifest` on it prints `batch  off  -`; the clock loads; the lane opens each finished
branch's PR, gates it on the product's required checks, merges the green and approved through the
repo's merge method, sends the red back to its session, and keeps at most `capacity.batch.per_run`
merges a tick. A product that still has a script keeps `batch: bash ~/q/merge-queue.sh --once`,
and it still runs — unchanged, at the same point in `STEPS`.

## 4. Records

**What this change writes down.**

- **A new doctor row**, `landing`, in the product section of `asf doctor` — one line, red only on
  the inferred pair (D5), carrying `products/<name>.yaml:<line>` for `steps.batch` when the key's
  line is readable. It is a *rendered row*, not a stored record: recomputed at every read from the
  product file, like every other configuration row (`check_convention_shapes` is the precedent).
- **One more owner value in the `--manifest` table** — `batch  off  -` where `batch  undeclared  -`
  stood. The table is output, not a record.

**Deliberately not written.**

- **No state file, no ledger line, no event.** `OPTIONAL_STEPS` is a package constant; whether a
  step is optional is not per-product data and has nothing to go stale.
- **No new product-yaml key**, no new `conventions` key, no new `capacity` key, no new approval
  class, no new `index.json` field.
- **No lane record, no run-line field, and no change to any lane state.** `PUSHED`, `PR_OPEN`,
  `GATE`, `WAITING_CI`, `QUEUED`, `MERGING`, `MERGED` and every transition between them are
  exactly as they stand at `dca5d85f3`.
- **No change to `lane.landing()`** (D3), so no product's landing mode moves when this lands, and
  there is nothing to migrate.
- **No edit to `sample/product.yaml` or `tests/e2e/product/product.yaml`** (D7). `batch: off` stays
  valid and stays tested; the new default is covered by `ManifestTests`' own fixture.

**The follow-ups this spec does not take**, each a new card rather than a Story here: retiring the
`steps.batch` limb of `lane.landing()` once operators have declared `conventions.landing` (D3);
`steps: {batch: false}` resolving to a command named `False` (§1.4); and F-0125's `asf doctor`
line that counts the adopted queue down to zero before advising `steps.batch: off` — which this
