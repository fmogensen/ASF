# F-0225 — free means *free, and able to take these jobs*

The CI start queue decides whether to start a run by comparing two numbers per class: the jobs the
run is expected to want (`Queue.needs`, measured from history) and the runners that are free
(`Queue.free`, from one runners read). Both numbers are wrong in the same direction — they say
*more capacity* than exists — and the queue started a run on capacity that was not there.

On the operator's fleet (2026-09-28 04:31Z) `free_by_class` counted four heavy runners from a
second provider as free **heavy**, while most heavy PR jobs of that product ask for a
provider-scoped label those runners do not carry. The queue admitted a PR run whose seven heavy
jobs then sat queued behind another run on the five runners that *do* carry it. Two hours later
(06:26 CEST) the other half of the miscount showed: heavy read **0 free** where four were idle,
because a run admitted less than three minutes earlier was still being subtracted from the free
count while its jobs were already holding runners — counted once as a ledger claim and again as a
busy runner.

This card is: **the free count per class is computed against the label sets the product's jobs
actually ask for, and a run that has already picked up runners is counted once.**

## Decisions

### In

- `asf/ci_queue.py`: the supply count, the demand measure, the admission's comparison, and the
  `started` ledger.
- `tests/test_ci_queue.py`: the shared fake's runner labels, pool and in-flight runs; three new
  test classes.
- The module doc of `asf/ci_queue.py` and the queue section of `docs/guide/ci-runner-pool.md`.

### Out

- **Writing or removing any runner label.** ADR 0002 rules that a `runs-on` names a capability and
  `asf ci reconcile` owns the convergence; this card only *reads* labels. The doctor's drift rows
  (P11) are unchanged: the provider-scoped label stays flagged while it stands.
- **The reservation** (`ci.reserve`, `pr_runners`, `_pr_cap`): it already models one label (P6).
  This fix composes with it and re-solves nothing.
- `load_by_class`, `runners_text`, the status Runners row and `asf/capacity.py` — they stay
  class-keyed, and P5 is why that is safe.
- The `held` / `hold_s` work in flight under T-0714 (`worker/T-0714`, in review): it deprioritises a
  busy runner in the **reserve plan**, not in the start queue's count. No file overlap beyond
  `asf/ci_queue.py` itself and the `EXPECT_VERSION` constant (C10).
- A general bipartite matching solver (C4).

### The choices

| # | Chosen | Against | Why |
| --- | --- | --- | --- |
| C1 | **A requirement comes from the measured jobs' own `labels`** — what the host recorded each job as asking for. | Parsing the workflow's `runs-on` (`ci_pool.parse_runs_on`, the card's first suggestion); a new `ci.queue.labels` conventions map (its second). | The estimate already reads those jobs (P7), so the requirement costs no host call — `runs_on()` costs a workflow listing, one contents read per file and a variables read per pass. | C2 | **The key is a string: `heavy[alpha-heavy]`** — the class, and in brackets the labels asked for, `+`-joined and sorted. `fit_key(cls, asks)` builds it, `fit_asks(key)` inverts it. | A tuple or dataclass key. | Every consumer of these maps is a JSON value in the queue file (`expect`, `started`, a held entry's `free`) or a hold line a person reads. A string key serialises, sorts, round-trips and prints as `heavy[alpha-heavy] 0 free, needs 2` with no change to `fit_reason`, `save` or `load`. |
| C3 | **Only labels that *discriminate within a class* enter a key**: those some but not all of the class's online runners carry (`split_labels`). | Keying on the job's whole label set. | `self-hosted`, `linux` and the role itself are carried by every runner of the class and constrain nothing; keying on them would split every class into a key per job name and make each count a sample of one. It also gives P5 for free: a uniform fleet keeps the class key, so the change is inert where there is nothing to fix. |
| C4 | **A key's demand is the peak of the jobs that need *at least* its labels** — so `heavy` counts every heavy job (exactly today's number) and `heavy[alpha-heavy]` counts only the jobs that ask for `alpha-heavy`. | Partitioning the demand and then adding a roll-up pass; a real bipartite matching over runners and jobs. | The counts are then monotone by construction — a runner that serves the strict key serves the loose one, and the strict key's demand is already inside the loose key's — so "every key fits" *is* Hall's condition over the chain, and the existing `shortfall` checks it with no new code. Adding partitioned peaks would over-count two stages that never overlap, which is the bug `peak_concurrent` was written to avoid. A matching solver buys nothing here and cannot be measured from a p90. |
| C5 | **Add fit-keyed siblings; leave every class-keyed function as it is.** | Re-keying `load_by_class`/`free_by_class` and fixing up their readers. | The Runners row, `capacity.py` and the ceiling are about the fleet, not about one run's jobs, and a test already pins the row and `q.free()` to one source. `Queue.free(kind=None, keys=())` returns the class keys when asked for nothing, so every existing caller and every existing assertion is untouched. |
| C6 | **A started record is *netted*, not dropped whole: its demand is reduced by the slots its run already holds, and the record is dropped when nothing is left.** | Dropping the whole record the moment any one of its jobs is seen on a busy runner — the card's literal words. | Dropping whole replaces a 2× over-count with an under-count of the same shape: a run of seven heavy jobs that has placed one would stop claiming the other six, and the queue would start another run against runners that are about to be taken. Netting counts each of the run's jobs exactly once — a placed job as a busy runner, an unplaced one as ledger demand — which is what "counted once" means. The card's own Verify case (a started run whose job is on a busy runner is counted once) is the single-job case of it, and is asserted verbatim in A3. |
| C7 | **The busy read is lazy, and only while the ledger is not empty**; `Queue.busy` is reused when a caller already filled it; unreadable means today's behaviour. | Reading the busy map on every pass; passing it in from every caller. | `busy_runners()` is a listing per status per repo plus a jobs read per run — the cost belongs to the passes that have something to net. An empty ledger is the common case and pays nothing. Failing back to the un-netted count keeps the fix strictly safer than the state it replaces: it over-holds, never over-starts. |
| C8 | **`ci.queue.estimate` keyed by a bare class replaces that class's whole demand** (its fit keys are dropped); keyed by a fit key verbatim, it sets that key. | Applying a class override on top of the measured fit keys. | Left alone, an operator's `{heavy: 12}` would sit beside a measured `heavy[alpha-heavy]: 7` and hold 19 runners for a run that wants 12. ## The design

### A — supply: what a runner can actually take (`asf/ci_queue.py`)

```python
def split_labels(runners, pool):
    """``{class: frozenset(labels)}`` — per class, the labels some but not all of its online
    runners carry: the only labels that can make one runner of a class unable to take another's
    job. A class whose runners are alike splits on nothing, and keeps the plain class key. The
    host's own defaults never split (:data:`asf.ci_pool.DEFAULT_LABELS`)."""


def fit_key(cls, asks):
    """``'heavy'`` for no labels, ``'heavy[alpha-heavy+class-pr-heavy]'`` for some: the class, and
    the labels a job of it asks for beyond what every runner of the class carries."""


def fit_asks(key):
    """``(class, frozenset(labels))`` — :func:`fit_key` inverted."""


def load_by_fit(runners, pool, keys):
    """``{fit key: {'online': slots, 'busy': slots}}`` for each of ``keys``: the runners of the
    key's class carrying every label it names, at their slots, a busy runner holding all of them —
    :func:`load_by_class` with one predicate added. A bare class key counts the whole class, so
    :func:`load_by_class` and this agree wherever the class splits on nothing."""


def free_by_fit(runners, pool, keys):
    """``{fit key: free slots}`` — online, not busy, and carrying what the key asks for."""
```

`Queue.free` gains the keys it is being asked about:

```python
def free(self, kind=None, keys=()):
    """Free slots per class, and per fit key for each of ``keys``, less what started this pass
    and has not yet reached a runner (:meth:`_placed`). ``kind`` ``pr``: only the runners a PR run
    may land on (:func:`asf.ci_pool.pr_runners`) — so a reservation and a fit key compose, each
    narrowing the same read. ``keys`` empty: the class keys alone, as before."""
```

`admit` and `live_line` pass the keys the line's needs mention:

```python
needs = {k: self.entry_needs(entries[k]) for k in order}
free = self.free(kind, {c for n in needs.values() for c in n})
```

Nothing else in the admission changes: `decide`, `shortfall`, `backfill` and `fit_reason` are
generic in the key (P10), so a hold now reads

```
ci queue: T-0500 waits — heavy[alpha-heavy] 0 free, needs 2 (Task unranked, 1st in line)
```

### B — demand: measured per requirement

`peak_concurrent` gains the split map and, with it, fit keys:

```python
def peak_concurrent(jobs, by_name, labels, split=None):
    """``{fit key: peak jobs asked for at once}`` for one run's ``jobs`` … ``split``
    (:func:`split_labels`): a job's *asks* are its own ``labels`` intersected with what splits its
    class, and a key's peak is taken over the jobs asking for **at least** that key's labels — so
    the bare class key is exactly the class's peak as before, and each strict key is the subset
    that needs it. ``split`` None or empty: one key per class, today's map byte for byte."""
```

- `run_peaks(jobs, pool, runners=())` derives the split from the live `runners` it already takes
  and returns fit keys; with no live read there is no split and it returns class keys.
- `fit_caps(pool, runners, keys)` → `{key: slots}`, the slots that *could* serve a key (busy or
  not). `estimate` caps each key there instead of at `_caps(pool)`; with no live read a strict
  key falls back to its class's declared cap, which is never smaller.
- `Queue._measure` stores the fit-keyed maps under `EXPECT_VERSION = 6` (C10); `Queue.needs`
  applies `estimate_override` with C8's collapse.
- `entry_needs` caps a PR start per fit key. The keys are only known once the estimate is read, so
  the cap is asked for by key rather than precomputed: `_apply_runners` keeps today's class-keyed
  `_pr_cap`, and `entry_needs` asks `load_by_fit(pr_runners, pool, keys)` — over the pass's one
  runner read, memoised per key — for the strict ones. No reservation, no cap, exactly as now.

### C — the ledger: a started run is counted once

A started record gains what is needed to find its run, and what has been found:

```python
self.data['started'].append({'key': key, 'at': _iso(self.now), 'needs': needs[key],
                             'branch': branch, 'sha': e.get('sha'), 'workflow': workflow})
```

```python
def _placed(self):
    """``{started key: {fit key: slots}}`` — per started record, the slots its run already holds.
    A busy runner is its run's: the run matches a record when its ``head_branch`` is the record's
    branch, its workflow file is the record's ``workflow``, and its ``head_sha`` is the record's
    ``sha`` where the record carries one (a start re-set by a new push keeps its place but takes
    the new head). The runner's slots count against every fit key it satisfies, because that is
    every key whose supply already counts it busy. One :meth:`Source.busy_runners` read per pass,
    taken only while ``started`` is not empty and reused from :attr:`busy` when a caller (the
    relief pass) has already read it; ``{}`` when it is unreadable, which leaves the pass counting
    as it does today."""
```

`free` subtracts the residual — `max(0, need - placed)` per key. The netting also writes what it
learned into `self.data['started']`: each record keeps its `placed` map beside its `needs`, so the
queue file shows both the claim and what of it has landed, and a record whose every key is fully
placed is taken out of the list. Nothing new saves the file — `admit`'s existing write at the end
of the pass (admitted or held) persists it. `PICKUP_S` stays exactly as it is: the backstop for a
run that never appears at all.

### Footprint

`asf/ci_queue.py`, `tests/test_ci_queue.py`, `docs/guide/ci-runner-pool.md`.

The suite's shared fixtures in `tests/test_ci_queue.py` need five generic additions, used by all
three fences, each defaulting to today's behaviour:

- `FakeGh(pool=…)` — the pool to report runners for, instead of the module's `pool_data()`.
- `FakeGh(labels={runner: [label]})` — the labels the host reports per runner, instead of
  `self-hosted` + role.
- `FakeGh(running=[(run id, branch, sha, [runner names])])` — runs in progress and their jobs, so

- `product(pool=…)` — a list of pool entries, used as `ci.pool` verbatim (`pool=True` still means

- `product(reserve=…)` — a `ci.reserve` map, as `tests/test_ci_reserve.py:46-50` already builds

### A1 — supply: a runner that cannot take the job is not free

# tests/test_ci_queue.py
def fit_pool():
    return [{'runner': 'a1', 'provider': 'alpha', 'role': 'heavy'},
            {'runner': 'a2', 'provider': 'alpha', 'role': 'heavy'},
            {'runner': 'b1', 'provider': 'beta', 'role': 'heavy'},
            {'runner': 'b2', 'provider': 'beta', 'role': 'heavy'},
            {'runner': 'l1', 'provider': 'alpha', 'role': 'light', 'slots': 2}]


FIT_LABELS = {'a1': ['self-hosted', 'heavy', 'alpha-heavy'],
              'a2': ['self-hosted', 'heavy', 'alpha-heavy'],
              'b1': ['self-hosted', 'heavy'], 'b2': ['self-hosted', 'heavy'],
              'l1': ['self-hosted', 'light']}
ASKS = ['self-hosted', 'alpha-heavy']


def fit_history(runs=3):
    """Each run: two heavy jobs that ask for the provider-scoped label, one light job."""
    return [[job('a1', 0, 5, labels=ASKS), job('a2', 0, 5, labels=ASKS),
             job('l1', 0, 5, labels=['self-hosted', 'light'])] for _ in range(runs)]


class TestFitSupply(Base):
    def fit(self, **kw):
        p = product(pool=fit_pool())
        gh = FakeGh(pool=fit_pool(), labels=FIT_LABELS, history=fit_history(), **kw)
        return p, gh, self.queue(p, gh)

    def test_only_labels_that_split_a_class_make_a_key(self):
        from asf import ci_pool
        p, gh, q = self.fit()
        q._read_host()
        self.assertEqual(ci_queue.split_labels(q._runners, ci_pool.load_pool(p)),
                         {'heavy': frozenset({'alpha-heavy'}), 'light': frozenset()})
        self.assertEqual(ci_queue.fit_key('heavy', {'alpha-heavy'}), 'heavy[alpha-heavy]')
        self.assertEqual(ci_queue.fit_asks('heavy[alpha-heavy]'),
                         ('heavy', frozenset({'alpha-heavy'})))

    def test_a_free_runner_lacking_the_label_is_not_free_for_that_key(self):
        _p, _gh, q = self.fit(busy={'a1', 'a2'})
        free = q.free(keys={'heavy', 'heavy[alpha-heavy]', 'light'})
        self.assertEqual(free['heavy'], 2)              # b1, b2 are idle heavies
        self.assertEqual(free['heavy[alpha-heavy]'], 0)  # and neither carries the label
        _p, _gh, q = self.fit(busy={'b1', 'b2'})
        self.assertEqual(q.free(keys={'heavy[alpha-heavy]'})['heavy[alpha-heavy]'], 2)

    def test_a_class_that_splits_on_nothing_keeps_its_class_key(self):

        q = self.queue(product(), FakeGh(busy={'h1'}))
        self.assertEqual(q.free(), {'heavy': 2, 'light': 2})
        self.assertEqual(q.free(keys={'heavy', 'light'}), {'heavy': 2, 'light': 2})

    def test_the_reservation_and_the_fit_key_compose(self):
        # a PR start sees only the reserved subset, counted per key within it
        p = product(pool=fit_pool(), reserve={'label': 'class-pr-heavy', 'of': 'heavy',
                                              'keep_free': 1})
        labels = {k: v + (['class-pr-heavy'] if k in ('a1', 'b1', 'b2') else [])
                  for k, v in FIT_LABELS.items()}
        q = self.queue(p, FakeGh(pool=fit_pool(), labels=labels, history=fit_history()))
        self.assertEqual(q.free('pr', keys={'heavy', 'heavy[alpha-heavy]'}),
                         {'heavy': 3, 'heavy[alpha-heavy]': 1})

    def test_a_uniform_fleet_measures_exactly_as_before(self):

        self.assertEqual(q.needs('ci.yml'), {'heavy': 3, 'light': 1})

    def test_the_run_is_held_while_only_the_wrong_heavies_are_free(self):

        d = self.admit(q, 'pr:b', 'T-0500', branch='b')
        self.assertFalse(d.admitted)
        self.assertEqual(self.lines, ['ci queue: T-0500 waits — heavy[alpha-heavy] 0 free, '
                                      'needs 2 (Task unranked, 1st in line)'])
        self.assertEqual(q.data['entries']['pr:b']['free'], {'heavy[alpha-heavy]': 0})

    def test_the_same_run_starts_when_the_runners_it_needs_are_free(self):
        _p, _gh, q = self.fit(busy={'b1', 'b2'})

        _p, _gh, q = self.fit(minutes=2, busy={'a1', 'a2'},
                              running=[(9, 'b', 'sha1', ['a1', 'a2'])])
