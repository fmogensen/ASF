# F-0333 — the factory has no GitHub identity of its own

Every GitHub call the factory makes is made as the operator. The kernel's ports, the lane, the
CI queue, harvest, the forge clean-up and every worker session all present one personal token
with one 5,000 REST/hour bucket, and when it ran out at 07:25Z on 2026-10-10 the whole factory
went blind at once — the second time in eleven days, after the 07:41Z exhaustion of 2026-09-30
that `asf/gh_limit.py:1-21` was written for.

`asf.gh_limit` is the right answer to *being* rate limited: a refused call is Unknown, the
process latches, and no decision is made on an empty answer. What it cannot do is give the
factory more quota, because quota is attached to an identity and the factory has none. A GitHub
App installation has its own bucket — 5,000/hour at one repository, scaling with the
installation — and it is the identity a machine is supposed to use.

This spec gives the factory that identity: an operator-created App declared in the product file,
an installation token minted and refreshed by the host, and that token carried by the kernel's
ports, by every session, and by every other `gh` call the host makes. With no App declared,
every one of those paths runs exactly as it runs today.

The whole change hangs on one fact about this codebase: **there is already exactly one map that
answers "which token does this product's GitHub access use"** — `asf.env.product_auth_env`
(`asf/env.py:463-474`), read by eleven callers (P1), and behind it one builder of the
environment a `gh` child gets (`asf/ci_pool.py:906-918`, mirrored in
`asf/security/__init__.py:13-28`), read by ten more (P2). A token that joins that map is carried
by the kernel, by sessions, by the redaction scanner and by the doctor's row without any of those
twenty-one callers changing. The two things the map does not reach — the 30 `gh` call sites that
name no environment at all (P3), and the minting itself — are the only places this change adds
code.

### In scope

1. One new module, `asf/ghapp.py`: read the App's declaration, sign a JWT, mint an installation
   token, cache it with its expiry, and refresh it when it is close to expiring.
2. The minted token joins `env.product_auth_env`, which carries it to the twenty-one readers of
   P1 and P2 — the kernel's ports and gate, the CI queue, capacity, flight, trunk-red, flaky, the
   Actions backend, every session launch, the redaction scanner and the doctor's row.
3. A default identity in `asf.github` for the 30 calls of P3 that name no environment.
4. Two refresh doors in the host: the kernel tick, before it builds its ports; and the session
   spawn, before it reads the map.
5. The operator's surfaces: the shape check, the example product file, an `asf doctor` row, and
   the two guide pages that say how to create the App.

### Out of scope

* **Refreshing a token inside a running session.** A session is given a value at launch, not a
  file to re-read (P4, `asf/workers/runtime.py:467`), so a session that outlives its token's
  hour sees `gh` fail and the kernel reads that as Unknown, exactly as it reads an exhausted
  token today. D7 keeps the launch margin wide for this reason; a session-side refresh is a
  separate item.
* **`asf upgrade`'s reads.** It reads the *factory's own* repository, not the product's
  (`asf/upgrade.py:540`), so it keeps the ambient login — explicitly, by D6.
* **The 0.1 tick (`asf/tick/`).** Its steps are not given a refresh door; the kernel loop is
  (D8). A product still running the 0.1 tick with an App declared mints only at a session
  launch, and the doctor row says when the cached token is stale.
* **An App per account, or per repository group.** The declaration is per product, where
  `auth_env` already is and for the same reason (`asf/env.py:464-470`).
* **Writing the App's private key.** The operator creates the App and saves its key; the factory
  only ever reads that file, and never prints or copies its contents.
* **A new `asf` command.** The doctor row is the operator's surface (D10).

### Preconditions this work depends on

1. The map of P1 and the builder of P2 are the only paths by which a product's token reaches a
   `gh` child or a session — P1, P2 and P3 together enumerate every call site.
2. `asf/github.py` is the one client: its `_spawn` (`asf/github.py:126-130`) builds the
   environment for every call in the module, and the client ratchet
   (`tools/check_clients.py:44-61`) keeps it that way.
3. `conventions:` keeps unknown keys verbatim at every pinned reader (P5).
4. The package is stdlib-only (P6) and `openssl` is on the host (P7).
5. `mutation_guard` is how a dry run refuses a mutating call (`asf/github.py:147-150`).
6. `redact.auth_env_secrets` (`asf/redact.py:183-203`) is the only reason a session's token is
   scrubbed from what the factory writes, and it reads exactly the two maps of P1.

## The design

### §1 — `asf/ghapp.py`: the factory's own GitHub identity

One module, with no state but two files under `env.state_dir(product)` (`asf/env.py:1059-1063`).

```
App = namedtuple('App', 'app_id key_file installation_id')

settings(product)        -> App | None      conventions.github_app, expanded; None when unset
configured(product)      -> bool
token_path(product)      -> <state>/github-app.token      (0600, the token and nothing else)
meta_path(product)       -> <state>/github-app.json       (ids, expiry, last reason — no secret)
token(product)           -> str             the cached token, '' when there is none. No network.
expires_at(product)      -> str             the meta's ISO expiry, '' when unknown. No network.
signing_input(app, now)  -> bytes           base64url(header) + '.' + base64url(claims)
sign(app, data, run=)    -> (bytes, str)    openssl dgst -sha256 -sign; (None, why) on failure
jwt(app, now, run=)      -> (str, str)
installation(app, slug, bearer, http=) -> (int, str)
mint(product, now=, http=, run=)       -> (expires_at, str)
refresh(product, now=, http=, run=)    -> (expires_at, str)
```

`refresh` is the only entry a caller outside the module needs, and it never raises:

* no App declared → `('', 'no app configured')`, and nothing is read or written;
* a cached token with more than `REFRESH_MARGIN_S` (900) left → `(expires_at, '')`, no network;
* `mutation_guard.is_active()` → one `would mint an installation token for <slug>` line and
  `('', 'dry run')`, like every mutating `gh` call (`asf/github.py:147-150`);
* otherwise it mints: `jwt` → `installation` → `POST /app/installations/<id>/access_tokens`,
  writes the token file at `0o600` and the meta file, and returns the expiry. One log line:
  `github app: installation token minted for <slug> (app <id>, installation <id>), expires <iso>`.
* a failure at any step → `('', <why>)` and the reason in the meta file's `error`, where the
  doctor row reads it. The previous token file is left alone: a stale token is a better answer
  than none, and GitHub refusing it is Unknown, which the kernel already handles.

The JWT is `{"alg":"RS256","typ":"JWT"}` over `{"iat": now-60, "exp": now+540, "iss": app_id}`,
base64url with no padding, signed by `openssl dgst -sha256 -sign <key_file>` reading the signing
input on stdin (P7). `run` replaces `subprocess.run` and `http` replaces the one
`urllib.request.urlopen`, so every test in §3 runs with no key, no network and no App.

Three rules hold for every line in the module: a return value, a log line and the meta file carry
ids, paths, an expiry and a reason, never the token and never key material (D11); the only
`urllib.request` site in the package is here (D8), and a 403 or 429 body goes through
`gh_limit.inspect` before anything else is read from it; `openssl` is added to the client
ratchet's kinds with `asf/ghapp.py` as its sole owner (`tools/check_clients.py:44-61`), so the
second `openssl` call site anywhere fails the build.

### §2 — the token joins the one map

`env.product_auth_env` (`asf/env.py:463-474`) gains four lines, after the declared map is built:

```python
    out = {str(k): os.path.expanduser(str(v)) for k, v in auth.items()} if isinstance(auth, dict) else {}
    from asf import ghapp          # local: ghapp reads env.state_dir
    path = ghapp.token_path(product) if ghapp.configured(product) else ''
    if path and os.path.getsize(path) > 0:      # D5: never name a file that is not there
        out[ghapp.TOKEN_VAR] = path             # D4: the App is the identity
    return out
```

With no App declared, or before the first mint, the returned map is byte for byte what it is
today — which is what makes "without it, behaviour is unchanged" a property of one function
rather than of twenty-one call sites. With one declared and minted, the token is carried to:

* the kernel's GitHub port and gate, the Actions backend, the CI queue, capacity, flight,
  trunk-red and flaky, through `ci_pool._gh_env` and `security.gh_env` (P2);
* the rate-limit budget, which is keyed by the token (P10), so the App's remaining calls are what
  the kernel's `read_budget` and `gh_limit.low` measure;
* every session, through `spawn` (twice), `stall`, `heartbeat`, `credentials` and the doctor's
  relaunch probe (P1) — and, because the variable is `GH_TOKEN`, the session's git gets its HTTPS
  credential from the App too (`asf/workers/runtime.py:363`);
* `redact.auth_env_secrets`, so the token is a redaction pattern everywhere the factory writes
  (`asf/redact.py:183-203`);
* `doctor.check_worker_secrets`, which lists it by variable name and presence only
  (`asf/doctor.py:329-352`).

### §3 — a `gh` call that names no environment carries the factory's identity

`asf/github.py:126-130` is where every call in the one client builds its child's environment:

```python
def _spawn(run, args, timeout, env):
    kw = {'capture_output': True, 'text': True, 'env': hermetic.git_env(identity(env))}
```

where `identity(env)` returns `env` unchanged when the caller passed one — it already chose its
identity, and the ten readers of P2 pass one — and otherwise returns `os.environ` with the cached
App token over it, from a per-process memo of the ambient product (`$ASF_PRODUCT`, as every
session and the host already set it). No product load, no mint and no network on this path: when
there is no App, no token file or no readable product, it is `None` and the call runs exactly as
it does today.

That gives the factory's identity to the 30 sites of P3 — harvest's shim, the forge's clean-up,
the PR the metrics pass opens, the security feeds, and the connectors their callers hand no
environment. `asf/upgrade.py:540` passes `env=dict(os.environ)`: it reads the factory's own
repository, which the product's installation is not installed on (D6).

### §4 — the host refreshes, at two doors

* `kernel.loop.tick`, as its **first** statement, before `ports = ports or P.real_ports(product)`
  (`asf/kernel/loop.py:357`) — the port snapshots the environment in its constructor (P11), so
  this is the only point at which a refresh is visible to the tick that made it. A dry run reaches
  it too and `refresh` refuses itself there (`mutation_guard`), printing the `would mint` line
  with the rest of the plan.
* `workers/spawn`, immediately before each `product_auth_env` read
  (`asf/workers/spawn.py:1139`, `asf/workers/spawn.py:1222`), so a session launches with at least
  the margin's worth of token left.

Both doors ignore the return value except to log it: a refusal is already one line, and a tick
that cannot mint is a tick on the ambient login — today's behaviour, not a new failure.

### §5 — what the operator sees

* `conventions.validate_mapping` (`asf/conventions.py:580-666`) gains `github_app`: a map, whose
  `app_id` is a non-empty scalar, whose `key_file` is a non-empty string, and whose
  `installation_id` — when set — is a positive integer. The docstring's list of checked keys gains
  it. Nothing is added to `PRODUCT_FIELDS` or `NESTED_FIELDS` (D1, P5).
* `docs/products.example.yaml` gains a commented `github_app:` block under `conventions:`,

## Records

What this change writes down, and where:

* `~/.ASF/state/<product>/github-app.token` — the installation token, mode `0600`, one line, no
  trailing commentary. Written only by `ghapp.mint`, read by `ci_pool._gh_env`,
  `security.gh_env`, `runtime.auth_env_values`, `redact.auth_env_secrets` and
  `github._spawn`'s default. Outside the record repository and outside every checkout.
* `~/.ASF/state/<product>/github-app.json` — `{app_id, installation_id, slug, minted_at,
  expires_at, error}`. No secret, by D11. This is what the doctor row reads and the only place a
  failed mint's reason is kept.
* One tick log line per mint: `github app: installation token minted for <slug> (app <id>,
  installation <id>), expires <iso>`; one `would mint an installation token for <slug>` line
  under a dry run; one `github app: <why>` line when a mint failed.
* One `asf doctor` row, `github identity` — ids, expiry, a shadowed file's path, a reason.
* A new redaction pattern, for as long as the token is valid: `redact.auth_env_secrets` yields
  it under the name `GH_TOKEN`, so the scanner and the pre-push hook refuse any commit or log
  that carries it (`asf/redact.py:168-170`).
* Nothing in the record repository, nothing on a card, nothing in a session's ledger, brief or
  setup log — the property `tests.test_auth_env` already asserts for every `auth_env` value and
  S-120856 extends to this one.

## Stories

Five Stories, one per section of `## The design`. Each is **declared** below as a
`### S-…: <title>` heading with its acceptance lines under it. The ids are the first five of the
block claimed by the session that wrote them (`S:120855-120904`) and they stay as minted: the
record carries no Story for this Feature yet, so there is nothing to collide with, and
renumbering them would only break the review history that already cites them. That heading is
what `asf.record.idcheck.declared_stories` reads and what
`asf.record.plan_tasks` mints the card from, so a cited id with no declaration is a phantom and
the plan citing it is refused whole.

Each acceptance line is one physical line of plain text with no backticks, on purpose: the reader
is line-anchored (`asf.record.idcheck.CHECKBOX` matches a single line) and `_prose` replaces every
inline code span with one space before parsing, so a wrapped line reaches the minted card
truncated and an identifier inside backticks reaches it missing.

card's literal words (D6) and stands alone so it can be cut. S-120858 depends on S-120855 and

### S-120855: the factory's own GitHub identity — an App's installation token, minted and cached by the host

Design §1 — the new module (D2, D8, D9, D11, D12; P6, P7, P8). Acceptance is the first fenced
block of `## Acceptance tests`. Every case injects the signer and the HTTP call, so the Story's
whole proof runs with no key, no App and no network.

- [ ] a product declaring no github_app is unconfigured, and settings returns none
- [ ] a product declaring an app id and a key file gets both back, with the key path expanded from a leading tilde
- [ ] a declared installation id is read back as an integer, and an absent one leaves the field empty
- [ ] the signing input is two base64url segments joined by a dot, neither of them padded
- [ ] the claims carry the app id as the issuer, an issued-at one minute in the past and an expiry nine minutes in the future, measured off the clock passed in
- [ ] the signer is invoked as openssl, with the digest and the key file as arguments and the signing input on stdin
- [ ] a signer that fails returns no token and a reason that names the key path and carries no key material
- [ ] the minted token is the access token the mint response carried, and its expiry is the response's own
- [ ] the token file is written with mode 0600 and holds the token and nothing else
- [ ] the meta file holds the app id, the installation id, the slug, the mint time and the expiry, and no substring of the token or the key
- [ ] the installation id is discovered from the product's repo slug when the product declares none, and the discovered id is kept in the meta file
- [ ] a declared installation id is used as declared and no discovery call is made
- [ ] a refresh with a cached token further from expiry than the margin makes no call at all
- [ ] a refresh with a cached token inside the margin mints a new one
- [ ] a refresh with no cached token mints one
- [ ] a refresh on a product with no app configured makes no call, writes nothing and gives a reason
- [ ] a refresh while a dry run is active mints nothing, prints one would-mint line and gives the dry-run reason
- [ ] a mint that fails leaves the previous token file exactly as it was and records the reason in the meta file
- [ ] a mint answered with a rate-limit body latches the process the way a refused gh call does
- [ ] a mint answered with unparseable output is a reason, never a token
- [ ] no value the module returns, logs or writes contains the token or any line of the key file, over every failure path above
- [ ] the module holds the only urllib request site in the package
- [ ] the module holds the only openssl call site in the package, and the client ratchet names it as that kind's owner

### S-120856: the token joins the one auth map, and the map is unchanged when no App is declared

Design §2 — four lines in one function (D3, D4, D5; P1, P2, P4, P10). Acceptance is the second
fenced block. This is the Story the card's acceptance turns on: what it proves is that twenty-one
existing readers carry the new identity without being touched, and that a product with no App
gets the map it gets today.

- [ ] a product with no github_app returns exactly the map it returns today, for a product with an auth_env and for one without
- [ ] a product with a github_app but no token minted yet returns exactly the map it returns today
- [ ] a product with a github_app and a minted token gains one entry, naming the token file
- [ ] an empty token file adds no entry, because a named missing file refuses a launch
- [ ] the App's entry replaces a declared auth_env entry for the same variable
- [ ] a declared auth_env entry for any other variable is still returned beside the App's
- [ ] the environment a gh child gets carries the minted token as its code-host variable
- [ ] the environment the security pass builds carries it too, through the same map
- [ ] a launched session's child environment carries the minted token
- [ ] a launched session's git gets its HTTPS credential from the minted token, with nothing written to disk
- [ ] the rate-limit budget is read under the minted token's own key, so the App's remaining calls are not the operator's
- [ ] the redaction gate holds the minted token as a pattern, under the code-host variable's name
- [ ] no part of the minted token reaches the session ledger, the brief or the setup log
- [ ] the worker-secrets row lists the App's token file by variable name and presence only

### S-120857: a gh call that names no environment carries the factory's identity, and the one caller that must not opts out

Design §3 — the one client's default (D6; P3). Acceptance is the third fenced block. The Story is
bounded by its own first case: a caller that passed an environment is not touched, which is every
reader of P2 and every test that already pins one.

- [ ] a call that passes an environment runs with exactly that environment, whether or not an App is configured
- [ ] a call that passes none, with no App configured, runs with exactly the environment it runs with today
- [ ] a call that passes none, with an App configured and a token minted, runs with the minted token over the ambient environment
- [ ] a call that passes none, with an App configured and no token minted, runs with the ambient environment unchanged
- [ ] the default makes no mint, no product load per call and no network call: the ambient product is resolved once per process
- [ ] a product that cannot be resolved or loaded leaves the call on the ambient environment and raises nothing
- [ ] the harvest shim's calls carry the minted token
- [ ] the forge clean-up's calls carry the minted token
- [ ] the upgrade reader's calls carry the ambient login, because it reads the factory's own repository and passes its environment explicitly
- [ ] the git hook variables are still stripped from the environment the default builds

### S-120858: the host refreshes before it builds its ports and before it launches a session

Design §4 — two doors (D7; P11). Acceptance is the fourth fenced block. The first case is the
defect this ordering exists to prevent, written as a test rather than a comment.

- [ ] the kernel tick refreshes before it builds its ports, so the token the port snapshots is the one this tick minted
- [ ] a token minted after the ports are built is not the token that tick's port uses, which is why the door is where it is
- [ ] the kernel tick on a product with no App configured makes no mint call and runs unchanged
- [ ] a kernel dry run mints nothing and prints the would-mint line with the rest of the plan
- [ ] a failed refresh does not fail the tick: one line, and the tick runs on the ambient login
- [ ] a session launch refreshes before it reads the auth map, so the session's token has at least the margin left
- [ ] a session launch on a product with no App configured makes no mint call and launches unchanged
- [ ] a failed refresh at launch does not refuse the launch

### S-120859: the operator declares the App in the product file and reads its state in one doctor row

about where the key is *not*: a product file carrying the App must load under the oldest pinned

- [ ] a well-formed github_app block raises no shape problem
- [ ] a github_app that is not a map is named as a problem
- [ ] a github_app missing its app id or its key file is named as a problem
- [ ] a github_app whose installation id is not a positive integer is named as a problem
- [ ] the shape check's own list of checked convention keys names github_app
- [ ] no top-level product field and no checked section key is added, so the pinned-reader check still passes
- [ ] a product file carrying a github_app block loads clean under the oldest pinned reader, which validates it not at all and keeps it verbatim
- [ ] the example product file carries a commented github_app block and still parses into a product
- [ ] the example product file names the repository permissions an installation needs
- [ ] the doctor row for a product with no App configured is a skip that says not configured, never a red
- [ ] the row is red when the key file is missing or unreadable, naming the path
- [ ] the row is red when the last mint recorded an error, naming the reason
- [ ] the row is red when the cached token has expired
- [ ] the row is green naming the app id, the installation id and the expiry
- [ ] the row names the declared auth_env file the App shadows, when there is one
- [ ] no detail the row prints contains the token or any line of the key file
- [ ] the operating guide and the product-config guide each say how the App is created, what permissions it needs and where its key goes
