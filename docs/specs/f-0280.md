# F-0280 — the lane asked for a review round and the feeder had no row to give it

A lane branch is reviewed because the lane says so. `facts()` reads the branch's diff, calls it
`docs` or `code` (`landing_class`), and `conventions.lane.review` decides: `code` → `required`,
`docs` → `none`. A branch the lane calls `code` goes `PR_OPEN → REVIEW` (T3) and waits there for
a review of its exact head.

The feeder is the half that answers. `lane_rows` turns the lane's `REVIEW` state into the
`PUSHED → REVIEW` row one review session runs from — but only for a Task or a Bug, with one
exception bolted on for the direct lane:

```python
direct = (item.get('type') == 'feature'
          and _conventions(product).branch_kind(h.get('branch') or '') == DIRECT)
if item.get('type') not in ('task', 'bug') and not direct:
    continue
```

A Feature's own branches — `spec/F-xxxx`, `plan/F-xxxx` — are neither. So a document branch whose
diff touches code is held in `REVIEW` by the lane and spoken for by nobody: the Feature's document
row reads `WAITS ON landing: spec lane REVIEW PR #941`, no review session is ever launched, no
verdict is ever filed, and the state never moves. A docs-only document branch does not hit this —
`lane.review.docs` is `none`, so it goes straight to the gate and merges — which is why it took a
code-carrying one to show. Seen 2026-10-07 on a product: four PRs green and CLEAN for a day or
more (#941, #897, #885, #322), each on a Feature-keyed branch, each stuck at round 1.

`pushed_ids` is the same restriction stated a second time, and it costs a second symptom: the
Feature is not pushed work, so its row is not in `keep` and the capacity cut drops it without a
trace (P11), and `orphaned_pushed` — the invariant `asf doctor` prints as `pushed work` — does not
count it (P4). The factory could not see the hole it was in.

### In

1. **The feeder speaks for a Feature the lane holds** — `lane_rows` admits a Feature whose lane
   branch is the Feature's own (`spec`, `plan` or `direct`), so `REVIEW` draws its
   `PUSHED → REVIEW` row at the round the lane asks for and any other open state draws its
   `PUSHED → LAND`; the Feature's own document row steps aside for it, by one rule in one place
   (P8); and `pushed_ids`/`pushed_rows` count a Feature the lane names, so its row survives the
   cut and `asf doctor` can see it (P4, P9, P12).
2. **The review such a branch must pass covers its code** — a document branch of class `code`
   requires its document checklist **and** the code checklist, so the one review satisfies the
   lane and ingest at once (P10, P11, P14); the landing class is written on the lane record and
   carried through the occupancy to the row, so every reader has it without re-reading git (P17).
3. **The brief asks for that checklist** — the review brief renders the table for the branch in
   front of it instead of the code table alone, and its reading order names the document a
   Feature's branch carries rather than the Task's plan (P13).

### Out

- **No change to when the lane asks for a review.** `landing_class`, `conventions.lane.review`,
  `review_waived`, `docs_only_task` and T3 are untouched. This card answers the lane's question;
  it does not change the question. A docs-only document branch still merges as `review: none`.
- **No change to the review verdict, the review store or the filing.** `reviews.verdict`,
  `reviews.parse`, `review_store` and the lane's filing of a review off a branch already work for
  a Feature's slug (P14) and are the reason the fix is this small.
- **No new row kind, no new brief kind.** `PUSHED → REVIEW` and `brief_kind: review` carry it;
  P13 shows the brief already builds for a Feature.
- **No change to ingest.** The union keeps `required('spec')`/`required('plan')` satisfied, so the
  stage ladder (`spec-review rN` → `spec-approved`) reads the same review and needs nothing new.
- **No change to the direct lane.** `cloud/direct-` already works (P5); it stops being a special
  case and becomes one of three, with the same rows it draws today.
- **No change to the delivery review.** `delivery_checks` fires only for a branch delivering two
  or more items — always a code branch, always the six code checks.
- **Nothing read about *why* the lane is in `REVIEW`.** A document branch the lane holds because
  its diff carries code and one it holds because the product set `lane.review.docs: required`
  (P7) get the same row. The feeder honours the state; it does not re-derive it.
- **No rebase, no transplant, no waiver for a document branch.** `transplant_case` keeps its
  `('spec', 'plan', DIRECT)` refusal (P16).
- **No second review of a document already approved on the trunk.** `APPROVED → LAND` and
  `land_doc_row` keep their meaning; only a *lane state* makes the Feature's row step aside.

## The design

### 1. The feeder — `asf/feeder/rows.py`

Beside `DIRECT`, the branch kinds whose branch belongs to a Feature rather than a Task:

```python
#: the branch kinds a Feature's own lane branch carries (:func:`lane_rows`): the direct lane's
#: one branch, and the two document lanes. A Task's or Bug's branch is never one of these.
FEATURE_LANES = (DIRECT, 'spec', 'plan')
```

`lane_rows`' gate reads the branch, not the id:

```python
        feature_lane = (item.get('type') == 'feature'
                        and _conventions(product).branch_kind(h.get('branch') or '')
                        in FEATURE_LANES)
        if item.get('type') not in ('task', 'bug') and not feature_lane:
            continue
```

Everything after it is unchanged: `REVIEW` draws `PUSHED → REVIEW` at `int(h.get('round') or 1)`
with `brief_kind='review'`, any other open state draws `PUSHED → LAND` naming the state, and
`docs_only_task` still applies to Tasks and Bugs only (a Feature has no `writes:`).

One new fact, and one caller changed to read it:

```python
def lane_speaks(fid, occupancy):
    """True while the lane holds ``fid`` in a state :func:`lane_rows` draws a row for — its
    ``REVIEW`` (a session) or any other open landing state (a wait). The Feature's own document
    and landing rows step aside for that row: one item, one row."""
    occ = occupancy or {}
    return fid in (occ.get('review') or {}) or fid in (occ.get('landing') or {})
```

`direct_row`'s opening check becomes `if lane_speaks(fid, occ): return None`, and
`_one_feature_rows` drops the rows that would double it, after building them:

```python
    if lane_speaks(fid, occupancy):
        # the lane holds the Feature's own branch: its PUSHED → REVIEW / PUSHED → LAND row
        # (:func:`lane_rows`) is the row. A `building` Feature keeps its Task rows.
        out = [r for r in out if r.kind not in (PUSHED_LAND, APPROVED_LAND)]
```

`pushed_ids` counts a Feature the lane names, and nothing else about it changes:

```python
    return {iid for iid, v in (items or {}).items()
            if isinstance(v, dict) and is_open(v)
            and (v.get('type') == 'feature' and iid in named
                 or v.get('type') in ('task', 'bug') and (iid in named or open_pr_of(v)))}
```

`pushed_rows` reads the branch the lane recorded before it guesses one:

```python
def _pushed_branch(items, product, occupancy, iid):
    """The branch ``iid``'s pushed work sits on: the one the occupancy entry that named it
    carries (``review``, ``landing``, ``back``, or the lane's own ``lanes`` map), else the
    item's lane branch by its type (:func:`_branch_of`). A Feature's branch is only ever the
    lane's: nothing derives `spec/`/`plan/`/`direct` from the type alone (C5)."""
```

and a Feature no occupancy entry names a branch for gets no `pushed_rows` row — its own document
row already speaks for it.

### 2. The checklist — `asf/reviews.py`

```python
def required(*kinds):
    """The normalized mechanical names of every `CHECKLIST[kind]`, in checklist order, each name
    once: `required('code')` is the six code checks, `required('spec', 'code')` the five spec
    checks then those six — what a `spec/` branch carrying code must answer (F-0280)."""
```

and the evidence column the brief's skeleton has carried inline until now:

```python
#: What the evidence cell of each check asks for, by normalized check name — the hint the review
#: brief renders beside the row (`render_table`). A check with no entry here renders an empty cell.
EVIDENCE = {...}
```

`render_table(rows, evidence=None)` puts `evidence.get(normalize(name), '')` in the third cell;
called with no `evidence` it renders the empty cell it renders today.

### 3. The landing class, from the lane to the row

`Lane.record` writes the class it already computed:

```python
        if f.get('class'):
            rec['class'] = f['class']
```

`occupancy` carries it into both entries it builds — `out['review'][item]['class']` and
`out['landing'][item]['class']` — and `lane_rows` puts the kinds on the row:

```python
#: a PUSHED → REVIEW row only: the `asf.reviews` checklists the review must cover
review_kinds: tuple = ()
```

set from `lane.review_kinds(branch_kind, h.get('class') or lane.CODE)` (C10). In
`asf/harvest/lane.py`, beside `review_kind`:

```python
def review_kinds(kind, landing_class):
    """The `asf.reviews` checklists a branch's review must cover. A document branch
    (``spec``/``plan``) of class :data:`DOCS` answers its own checklist; of class :data:`CODE` it
    answers that checklist **and** `code` — the diff is what went unreviewed, and ingest scores
    the same file against the document's checklist (F-0280 C7). Anything else: ``('code',)``."""
    doc = review_kind(kind)
    if doc == CODE:
        return (CODE,)
    return (doc,) if landing_class == DOCS else (doc, CODE)
```

`facts()` calls `reviews.required(*review_kinds(f['kind'], f['class']))`; `transplant_case` calls
it with `f.get('class') or CODE`, which is `('code',)` by P16.

### 4. The brief — `asf/briefs/build.py`, `asf/briefs/templates/review.md`

The template's hardcoded table becomes one placeholder, and the reading order one more:

```
Read, in this order: the writer's report on `{branch}`, then the diff against `origin/{main}`,
then {review_reads}.

THE VERDICT IS A TABLE. Write `{review_path}` with exactly this shape — one row per check, and no
row without evidence; a result with no evidence counts as `fail`:

{checklist}{delivery_checks}
```

The builder fills them from the row:

- `checklist` — `reviews.render_table(reviews.required(*kinds), reviews.EVIDENCE)`, where `kinds`
  is `row.review_kinds` or `('code',)`.
- `review_reads` — `the plan `{plan_path}` for the Task it claims to deliver` for a Task or Bug;
  for a Feature, the document its branch carries: `the spec `{spec_path}` the branch writes` on a
  `spec/` branch, the plan on a `plan/` branch, and both on a direct branch.

Everything else in the brief — the verdict block, the round, `{review_path}`, the never-touch-the-
branch rule — is unchanged.

### What it looks like when it is there

The P1 facts draw one launching row:

```
PUSHED → REVIEW  F-0280  would launch   spec/F-0280   round 1
```

its brief asks for eleven checks — the five spec rows, then the six code rows — the session files
`docs/reviews/1-f-0280.md`, the lane reads `APPROVED` against `required('spec', 'code')` and goes
to the gate, and ingest reads the same file against `required('spec')` and moves the Feature to
`spec-approved`. A `changes` verdict is `REVIEW → BACK` (T5) and the writer's next round, as for
any other branch.

## Records

- **The lane record** (`state/<product>/sessions.jsonl`, the `lane` field on the run that owns the
  branch) gains one key, `class` — `docs` or `code`, the class `facts()` already read. No existing
  reader of that record changes meaning; a line without it reads as `code` (C10).
- **The occupancy** (`asf.workers.lifecycle.occupancy`) carries that `class` on its `review` and
  `landing` entries. No new key.
- **The row** gains `review_kinds`, a tuple, on a `PUSHED → REVIEW` row only — beside
  `review_round`, and read only by the brief builder.
- **`asf next`** shows one row per Feature the lane holds: `PUSHED → REVIEW … round N` in `REVIEW`,
  `WAITS ON landing: <state>` otherwise — never both (P8), and never silent at zero free seats
  (P12).
- **`asf doctor`**'s `pushed work` row now counts a Feature whose document branch the lane holds
  with no row and no session: the invariant that was blind to the four PRs in the card
  (`orphaned_pushed`, P4).
- **The review file** is written where it is written today — `docs/reviews/<n>-<slug>.md`, filed
  off the branch by the factory, bound to the head the reviewer read. Nothing new is written to
  the repository, and no new state file is created.
- **The Feature's stage** moves on that review as it does for any document: `spec-review rN` on
  `changes`, `spec-approved` on `approved` (`asf.evidence.evidence.feature_stage`, P14), which is
  also what lets `asf.workers.continuation` send the findings back to the writer's own session.
