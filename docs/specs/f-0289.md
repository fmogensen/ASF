# F-0289 — a correction whose answer is a rebase never leaves the host

The cloud lane has exactly one channel back: the session's last commit, carrying its
`ASF-Session` and `ASF-Report` trailers, pushed to `origin/<branch>`. A correction whose answer is
a *rebase* cannot use it. The session rebases the branch's own commits onto the trunk, resolves,
commits its report — and its push is refused as a non-fast-forward. The standing rules forbid the
force that would land it, and tell it to stop and say `pushed: rebased <sha> — the factory
publishes`. On the factory host that works: the session's worktree is on this host, and the
factory publishes that head itself. In the cloud it does not: the rebased head lives only in the
container, which is reclaimed, and the local worktree the factory would publish from holds
origin's own stale tip.

So the run ends, the report commit never appears, and the lane records the one thing it can see:

```
cloud    correct-t-0064           dead  run 998 ended success without the report commit
```

That is the card's sighting, twice on 2026-10-07 on an operator's host — correct-t-0064 at 15:57
and correct-t-51408 at 23:27 — each asked to rebase onto the trunk and resolve a real conflict,
each ending without the report commit, then parked by the relaunch cap. Run locally, the same
corrections worked.

Two defects, not one. **The row was in the cloud at all**: routing never asks what the session
must *do* to the branch, only what kind of session it is and whether the card says `local_only`
(P7, P8). And **the failure says nothing about itself**: the dead reason's clause names the lane's
own conflict correction, which reads as a correction still pending, and the one refusal that would
have named the cause — git's own rejection of the rewritten branch — is in the run's log, which is
read only when nothing else answers and has no pattern for it anyway (P13, P14).

This spec closes both: a correction whose answer rewrites its branch's history never leaves the
host, and a cloud run that nonetheless dies on a refused rewrite says so.

### In

1. **One rule, stated where the existing one is stated: a row whose session must REWRITE its
   branch's history never leaves the host.** It sits beside `LOCAL_KINDS` in
   `asf/workers/cloud.py`, for the same reason and in the same words — the lane has no channel
   back for that work (P1, P2) — as a closed list of correction kinds, `REWRITE_KINDS`:
   `('conflict', 'copies', 'naming')` (P11).
2. **The discriminator is the correction's own `kind`**, carried as a declared fact from the
   feeder row to the pool row on a new `correction_kind` field — never read out of the correction
   text (C2) and never confused with the item's `local_only: true`, which means something else on
   the ledger (C3).
3. **It is a floor, not a preference.** One predicate, `cloud.local_only`, closes both doors
   (P16): `cloud.mode: primary` sends such a row local first, `cloud.rows: any` never admits it to
   the overflow path, and no `cloud.accounts`, `cloud.rows` or `cloud.mode` setting opens either.
4. **The host-side surfaces name it**, so an operator reading `asf status` or `asf cloud doctor`
   can see why a correction stayed home (P16, P17).
5. **The residual is never silent.** Routing cannot cover a cloud run whose branch starts
   conflicting *after* it launched — the trunk moved under it, and the session rebased. For that
   one: `refusals` gains the kind `non-fast-forward` and a pattern for git's own rejection, and a
   cloud run dead `without the report commit` reads its log for that refusal even when the record
   already holds a correction of a rewrite kind — because there the record's answer describes the
   input and only the log holds the outcome (C7).

### Out

- **No change to the local lane.** The conflict correction, its text, its files, its rounds, the
  relaunch cap, `publish_gap` and `lifecycle.publish` all stand exactly as they are. The fix is
  which lane the row goes to, not what the session does once it is there.
- **The `rebase` brief kind stays cloud-eligible** (P12). Its brief merges the trunk in and never
  rebases, so its push is a fast-forward and the channel carries it. Named here because the card's
  title says "conflict rebases" and the CONFLICT → REBASE row is the thing with "rebase" in its
  name that is *not* in scope.
- **The `'merge'` correction kind stays cloud-eligible** for the same reason, though
  `refusals.CORRECTION_KINDS` lists it beside the three (P11).
- **No routing rule on the branch's state.** A coder row whose branch happens to conflict with the
  trunk is not sent home: its brief never asks it to rebase, it pushes a fast-forward, and the
  conflict becomes a correction on the next harvest — which this rule then routes local. The rule
  reads the work the row was *given*, never the shape of the branch at launch.
- **No force for a cloud session, and no publish of a container's head.** There is nothing on this
  host to publish (P6) and nothing is added to reach into the runner.
- **No new config key.** `REWRITE_KINDS` is a closed list in code, like `LOCAL_KINDS`;
  `cloud.local_only` already exists for an operator who wants to send more home.
- **No change to `classify`, to `REPORT_MISSING`, or to the cloud session states.** A run that
  dies this way is still DEAD without the report commit; only the clause after it gains a word.
- **No watchdog, no deadline, no operator card** for the residual (C6).
- **No change to `spawn._rebase_onto_trunk`, and no fix of `--quiet`** (P10, P19). That the
  pre-launch rebase aborts a conflict is what *makes* the session do the rebase, which is this
  card's premise, not its target; and git 2.43 is this container's, not the factory host's.
- **`correct.md`'s claim that "a rebase onto `origin/<main>` was started for you if the branch
  needed one — if `git status` shows a conflict it is still in place" is left as it stands.** It is
  false on both lanes after P10's abort. A brief that describes a state no session is handed is a
  real defect and a separate card; correcting it here would change what every correction session
  reads, for a reason this card did not measure.
- **No retro-routing of a live cloud run.** The rule decides a launch; a run already in flight
  drains as it does today, with its dead reason now naming the cause (In 5).

## The design

Four files change: `asf/workers/cloud.py`, `asf/feeder/rows.py`, `asf/tick/step_wave.py`,
`asf/workers/pool.py` for S-74804; `asf/workers/refusals.py` and `asf/workers/cloud.py` for
S-74805. Nothing else.

### 1. The rule — `asf/workers/cloud.py`, beside `LOCAL_KINDS`

```python
#: The correction kinds whose answer REWRITES the branch's history — the session rebases the
#: branch's own commits onto the trunk and the factory publishes the result (B-0056). The cloud
#: lane has no channel back for them, for the same reason it has none for :data:`LOCAL_KINDS`:
#: it collects a session by one commit pushed to ``origin/<branch>``
#: (:func:`report_commit`), a rewritten branch's push is a non-fast-forward the standing rules
#: refuse, and the factory's own publish (:func:`asf.workers.lifecycle.publish`) pushes a LOCAL
#: worktree's HEAD — which a cloud run's worktree never holds (:func:`catch_up` fast-forwards it
#: to origin and does nothing else). Run in the cloud, such a correction ends "without the
#: report commit" and the relaunch cap parks it (F-0289).
#:
#: ``conflict`` — the branch does not merge onto the trunk and the lane's own rebase conflicted
#:   (asf.harvest.lane.Lane.rebase_onto_trunk): the session rebases and resolves.
#: ``copies``   — the trunk-copies rebuild conflicted: the same rebase, by hand.
#: ``naming``   — commit subjects the lane refused, reworded: a rewrite of every commit on the
#:   branch.
#:
#: ``merge`` is NOT one of them, and neither is the ``rebase`` brief kind: both end in a merge
#: commit on top of origin's tip, which is a fast-forward push the cloud channel carries.
REWRITE_KINDS = ('conflict', 'copies', 'naming')
```

and the predicate the two doors already share:

```python
def local_only(row, s):
    """The row never leaves the host: its kind is a :data:`LOCAL_KINDS` one (the floor, both
    modes — F-0216 C3), a kind the operator added in ``cloud.local_only``, the correction it
    answers is a :data:`REWRITE_KINDS` one (the floor too — F-0289), or its item says
    ``local_only: true``. The kind is the canonical one: ``asf.tick.step_wave.worker_row``
    carries ``brief.kind``, which is :func:`asf.briefs.build.normalize_kind`'s output; the
    correction kind is the lane's own, as it wrote it on the hold.
    """
    kind = getattr(row, 'kind', None)
    return kind in LOCAL_KINDS or kind in s.local_only \
        or getattr(row, 'correction_kind', '') in REWRITE_KINDS \
        or truthy(getattr(row, 'local_only', False))
```

`eligible` and `first` are untouched: both already read `local_only` (P16), so the overflow door
and the primary door close together.

### 4. The residual, named — `asf/workers/refusals.py` and `cloud.sync`

A new kind and the pattern that recognises it, from the two lines git actually prints (P14):

```python
#: git's own refusal of a push that would rewrite the branch: the session rebased and the
#: standing rules forbid the force that would land it, so the head — and the report commit on
#: it — never reaches origin. On the factory host the factory publishes it (B-0056); in the
#: cloud lane there is nothing to publish from, and the run ends "without the report commit"
#: (F-0289). The routing rule keeps such work off the lane; this names the one case it cannot,
#: a trunk that moved under a live run.
NON_FAST_FORWARD = 'non-fast-forward'
KINDS = (NAMING, PRE_PUSH, REFGUARD, PUSH_ALLOW, REDACTION, NON_FAST_FORWARD)
```

```python
    (NON_FAST_FORWARD, re.compile(r'\(non-fast-forward\)|Updates were rejected because the tip')),
```

It goes **before** the `PRE_PUSH` fallback and after `PUSH_ALLOW`, by the ordering comment
already on `_PATTERNS`: the narrowest pattern first, the widest last.

And one predicate, so the lane knows when the record's answer is not the outcome:

```python
def describes_the_ask(refusal):
    """True when ``refusal`` came off the record as a correction whose answer rewrites the
    branch (:data:`asf.workers.cloud.REWRITE_KINDS`): it names what the lane asked the session
    for, never what stopped it. A dead cloud run carrying one is the case where the run's own
    log must be read as well — git's refusal of the rewritten push is only there (F-0289 C7)."""
```

In `cloud.sync`'s dead-reason step the guard widens by that predicate, and a refusal the log
yields replaces the record's for the clause:

            if refusals.CLAUSE_HEAD not in why:
                why += refusals.clause(refusal)
```

  ASF refusal (non-fast-forward): ! [rejected] worker/T-0064 -> worker/T-0064 (non-fast-forward)
```

## Records

- **Nothing new is written to the record.** No card, no History line, no ledger event, no state
  file, no convention key and no config key. `REWRITE_KINDS` is a closed list in code, as
  `LOCAL_KINDS` is (C4).
- **The feeder row gains `correction_kind`** — the lane's own `kind` for the hold the row answers,
  copied, not derived. It appears in the feeder's JSON row line and is read back by
  `pool.Row.from_dict`, so an operator's `asf workers spawn --row` routes as a tick's wave does.
- **The session ledger gains nothing.** `pool.Row.correction_kind` is a routing fact read at
  launch; `local_only` keeps its own meaning on the ledger (C3), and the launch's lane is already
  recorded by its `pid` (`cloudpid`).
- **The tick's own lines change in one way**: a correction whose kind rewrites the branch launches
  `local` where it would have launched `cloud`, and says so on its launch line as any local
  launch does. No new line is printed for the choice.
- **Two operator-facing strings change**: `asf status`'s cloud clause and `asf cloud doctor`'s
  primary-mode row, each naming the new floor beside the old (P16, P17).
- **A dead cloud run's reason gains a kind.** `refusals.NON_FAST_FORWARD` joins `KINDS`; a run
  that died on a refused rewrite carries `last ASF refusal (non-fast-forward): <git's own line>`
  in its `dead_why`, written where the clause is written today (`cloud.sync`, and composed again
  by `refusals.dead_reason`). Nothing else about the run's record changes.
- **One API call, moved, not added.** The run-log read already happens for a dead cloud run with
  no refusal on the record (`_run_log_tail`, F-0266 C11); C7 widens it to a run whose only
  refusal is a rewrite correction, and to nothing else.
