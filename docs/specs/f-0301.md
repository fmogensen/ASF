# F-0301 — the push is the gate: what the brief asks for, the hook checks

Repair load is 6.4 repair sessions per landed Feature over 7 days against a 1.0 target of ≤ 3 —
341 sessions in the window, of which 170 are `correct`, 93 `adjudicate` and 78 `review`, so the
correcting half is the half worth deleting — and the card names where most of it comes from:
correction rounds that fix what CI or the review would have caught **before** the push — a touched
package's tests never run, a schema or migration list left stale, a diff reaching outside
`writes:`.

Every one of those three is already asked for, in prose, in the brief the session reads. The
standing rule is `asf/briefs/preamble.py:102` — "every test module that covers a file you touched,
each module whole … green, or fixed before the push, never pushed for CI to find" — and its own
docstring carries the card's evidence: *"2026-10-05: ~half of a day's PR reds were a session's own
defect a touched module or a repo check names"*. The `writes:` boundary is asked for the same way,
in `asf/briefs/templates/coder.md:7`: "A file outside that list is a refusal, not a judgement
call".

Nothing checks either. The session's `pre-push` hook (`asf/workers/githooks.py`'s `ASF_HOOK`) runs
four things and none of them is the brief: the push-allow prefix test, the product's own `pre-push`
hook (`asf redact --pre-push` — names and secrets), `asf trunk-check --pre-push` (the *whole*
`pre_push_check` on the branch merged with the trunk), and the push log. So a brief rule is an
instruction a session may simply not have carried out, and the first reader of that fact is CI or
the reviewer — one red run, one correction round, one re-review, per miss.

This card closes that gap at the one place every session must pass through. It is deliberately
*not* a new pass and *not* a new session (C1): the push already stops in a hook, the hook already
knows which refs are going, and git already knows which paths they add.

Three parts, as the card names them:

1. the hook runs the checks **matched to the paths the push adds**, and refuses the push when one
   is red — so "package tests not run" and "schema list stale" stop being possible;
2. the hook refuses a push whose paths reach **outside the footprint the factory will widen for
   free** — so "write lists outside `writes:`" costs a local fix, not a round;
3. the brief carries the **rubric** naming exactly those checks, so the session knows before it
   pushes what the door will ask, and a **first-push-green** metric says whether any of it worked.

### In

1. **A product declares its path-matched pre-push checks, and the hook runs the matched ones.**
   A new convention `pre_push_checks` — an ordered list of `{paths, run, why}` rules — and a new
   pure module `asf/prepush.py` that answers *which rules a set of paths matches*, in declaration
   order. A new `asf pre-push` reads the hook's ref lines on stdin, asks git which paths each
   pushed head adds over `origin/<trunk>`, runs each matched rule in the session's own worktree,
   and refuses the push on the first red one — with the rule's own `why` and the command's last
   lines. A product that declares none is untouched: the hook gains one process that exits 0.
2. **The same door refuses a push reaching outside the footprint the factory widens for free.**
   The session's environment gains `ASF_WRITES`: the **Feature** footprint
   (`widen.delivery_footprint`) plus `footprint.shared_writes`, computed where `items` is already
   in hand (the brief), carried on the row as `card_digest` is, and read by `asf pre-push`. A
   pushed path outside it is refused, naming the path and the `needs writes:` line the brief
   already teaches. A path outside the *Task's* `writes:` but inside the Feature's is let
   through — `diff_facts` widens it with no hold and no correction (P10, C5).
3. **The code brief carries the rubric, and it names the checks the door will run.**
   `asf/briefs/build.py` gains one block built from the landed `asf/precheck.py`: the table
   skeleton for the brief's own derived level, its security rows for the classes the Task's
   `writes:` reach, and one row per `pre_push_checks` rule those `writes:` reach — so the row the
   session ticks and the command the hook runs are the same sentence, spelled once.
4. **A first-push-green metric, and the leading indicator beside it.**
   `window_row` gains a nested `first_push_green` row — per landed lane branch, did it need no
   second round — joined on the `landings` stream the scorecard starts reading, with the local
   gate and the PR CI both counted, so a send-back and a locally-gated red are not green. Beside
   it, `caught`: the pre-push refusals the hook made, written onto the run's ended record at
   health time, so the operator sees the door firing before the lagging number moves.

### Out

- **F-0060's pass.** No `PRECHECK` lane state, no precheck brief kind, no precheck session, no
  model for one, no bounce, no `Tq`/`Tq'` transition, no feeder row, no `asf precheck`
  subcommand, no reviewer brief change. Those are F-0060 Tasks 2–6 (P17) and this card neither
  lands nor pre-empts them (C2). This card uses F-0060 Task 1's landed module as a library and
  writes nothing in `asf/precheck.py`.
- **`asf/precheck.py` itself.** `DIMENSIONS`, `SECURITY_DIMENSIONS`, `CLASS_DIMENSION`,
  `level_for`, `parse`, `covered`, `findings`, `blocking`, `keys`, `faults`, `render_table`,
  `head_of` and `level_of` are read, not edited (P7, C3).
- **Parsing the filled rubric, or making it block anything.** The brief's table is a checklist
  the session fills and pastes in its report, read by a human and by the reviewer's eyes. The
  rows a machine can check are checked *by the hook*, which is the point: nothing is gated on a
  self-report (C4).
- **`asf trunk-check --pre-push`.** It keeps running the whole `pre_push_check` on the
  trunk-merge checkout, unchanged and before the new call (P2, C7). The new checks are the
  branch's own paths in the branch's own worktree; they do not replace it and it does not
  replace them.
- **Changing `pre_push_check`, `check_commands` or the `EXTERNAL_CI_RULE` prose.** The existing
  string command, the review/correct check list and the standing rule stay as they are; the
  rubric block is added beside the rule, not in place of it.
- **The lane, the review and `widen_footprint`.** `diff_facts`, `report_facts`,
  `refusal_facts`, `apply`, `revert_overlaps`, `lifecycle.footprint_hold` and
  `harvest.widen_candidates` are untouched: this card stops a class of push from happening, and
  what still happens is judged exactly as it is today (C5).
- **`first_pass` (both of them).** `throughput.first_pass` and `reds.first_pass_window` keep
  their definition, their keys and their thresholds (`first_pass_min`, `first_pass_window`). The
  new metric is a second number with a different unit — the branch, not the PR — and a different
  question (P12, C8); neither replaces the other.
- **A new metric stream.** `sessions`, `landings`, `ci` and `gates` already carry every key
  (P13); `landings` only needs reading (C9).
- **A new config key under `improve.scorecard.throughput`.** The metric's threshold is a
  `targets.yaml` row (`first_push_green.rate_pct`), which is where the ≤ 3 repair target already
  lives (P16, C10).
- **`docs/design`, `docs/KNOWN-ISSUES.md`, `CHANGELOG.md`, `docs/plans/f-0301.md`.** This session
  creates `docs/specs/f-0301.md` and nothing else.

## The design

Five files gain surface and one is new: **`asf/prepush.py`** (new — the matcher, the runner and
the command), **`asf/conventions.py`** (the convention and its validator),
**`asf/workers/githooks.py`** (one call in the shim), **`asf/briefs/build.py`** (the rubric block
and `ASF_WRITES`), **`asf/metrics`/`asf/scorecard`** (the metric). Two more gain one line each:
`asf/workers/spawn.py` (the env) and `asf/workers/health.py` (the `caught` count).

### 1. `asf/conventions.py` — the product declares what the door asks

```yaml
conventions:
  pre_push_checks:
    - paths: ['asf/**', 'tests/**']
      run: 'python3 tools/run_tests.py --touched origin/main --shards 2'
      why: 'every test module that covers a file you touched, each module whole'
    - paths: ['asf/schema.py', 'asf/record/**', 'asf/tick/migrate*.py']
      run: 'python3 -m asf.schema --check'
      why: 'the schema and migration lists the record reads'
```

`Conventions.pre_push_checks()` returns `[{paths: [glob], run: str, why: str}]` in declaration
order, `[]` when unset or not a list — the reader shape of `security_paths` (P5). The validator
(`asf/conventions.py`'s `_problems`, beside `security.paths` at `:671-680`) reports: a value that
is not a list; a rule that is not a map; a rule with no non-empty `run`; a `paths` that is not a
list of non-empty strings (through the existing `_path_list_problem`); a `why` that is not a
string. A malformed rule is a red `asf doctor` finding and is **dropped**, never run — a
half-read rule must not refuse a push. The key is documented in `docs/products.example.yaml`
beside `pre_push_check` (`tests.test_env` reads that file).

### 2. `asf/prepush.py` — the matcher, the runner, the command

Pure first, then the two impure edges. Nothing here knows about briefs or metrics.

```python
MAX_SHOWN = 10        # the paths a refusal names before the rest are counted
TAIL_LINES = 15       # trunkmerge's own answer for how much of a red check to quote (C13)
TIMEOUT_S = 900       # one rule's own clock, trunkmerge.TIMEOUT_S's peer

def rules(conv):                      # conventions.pre_push_checks, [] for none
def matched(rules_, paths):           # [(rule, [path])] — rules whose paths the push touches,
                                      # declaration order, a rule with no hit left out;
                                      # `customer_content.matches` per path (C11)
def reaching(rules_, writes):         # [rule] — the rules a Task's `writes:` globs reach, by
                                      # `footprint.globs_overlap` (P11) — what the brief prints
                                      # before any diff exists (§4)
def outside(paths, boundary):         # [path] — `widen.outside`, read through this module so the
                                      # door and the tick answer with one function (C5)
def added_paths(repo, sha, base):     # `git diff --name-only <base>...<sha>`; None when git
                                      # cannot tell (a base that is not there)
def run_rule(rule, cwd, timeout=None) # (ok, tail) — the command, its last TAIL_LINES on red,
                                      # None/`timed out` on its clock
def refusal(rule, tail)               # the one line the shim writes down, from `rule['why']`
def boundary_env(globs)               # {'ASF_WRITES': ' '.join(globs)} — `pushlog.env_for`'s shape
def boundary(value)                   # the env string back to a glob list; [] for unset/empty
```

`matched` is the whole of "path-matched": the paths the push adds, each tested against each rule's
globs, and a rule fires when any path hits. A rule whose globs match nothing in this push does not
run — that is the saving that makes running the rest affordable.

### 3. `asf pre-push` — the door

`asf pre-push [--product P]`, registered in `asf/cli.py` beside `trunk-check`, reading the hook's
ref lines on stdin through `trunkmerge.pushed_heads` (the landed parse: deletes, tags and the
trunk left out). For each pushed head, in ref order:

1. `added = prepush.added_paths(repo, sha, f'origin/{product.main}')`. `None` — git could not
   diff — prints `asf pre-push: cannot diff against origin/<trunk> — not checked` and exits 0: an
   unreadable base is not a finding, exactly as `trunk-check` treats an unloadable product.
2. **The footprint** (S-77505), first, because it is free: `left = prepush.outside(added,
   prepush.boundary(os.environ.get('ASF_WRITES')))`. With an empty boundary nothing is tested.
   Non-empty `left` refuses:

   ```
   asf: push refused — 2 path(s) outside this item's Feature footprint: asf/tune.py, tests/test_tune.py
     The footprint is what lets other sessions run beside you. Leave these untouched and report:
       needs writes: asf/tune.py tests/test_tune.py
     with `status: partial` — the factory widens `writes:` by them and sends this run back to you.
   ```
3. **The matched rules** (S-77504): `for rule, hit in prepush.matched(prepush.rules(conv), added)`,
   each run in the repo's own worktree. A green rule prints one line
   (`asf pre-push: asf/**, tests/** → \`python3 tools/run_tests.py …\` passes (41s)`); the first
   red one refuses, and no later rule runs:

   ```
   asf: push refused — every test module that covers a file you touched, each module whole
     matched by asf/**, tests/** (3 path(s): asf/prepush.py, tests/test_prepush.py, …)
     `python3 tools/run_tests.py --touched origin/main --shards 2` exited 1
     <the command's last 15 lines>
   ```
4. Exit 1 on either refusal, 0 otherwise. The exit status never depends on a write: the ledger
   write is `try`/`except OSError` and the refusal stands whatever it did (the shim's own F-0266
   C4 rule, pinned by `test_session_push_guard.py:219`).

The ledger, for S-77507's `caught`: one JSON object appended to `<state>/<p>/gates/<job>.prepush`
per refusal — `{at, kind: 'footprint'|'rule', rule: <run>, paths: [...]}` — path and `clear`
shaped exactly as `pushlog.path`/`refusals.path` (`os.path.basename(job)`, so no value walks out
of `gates/`), under `ASF_PREPUSH_LOG` set beside `ASF_PUSH_LOG` and `ASF_REFUSAL_LOG` and cleared
on the same launch line. The shim's own `asf_refused` still files the refusal under
`'hook refused'` as it does for `trunk-check` (P15) — this ledger is the *count*, typed, not a
second copy of the text.

### 4. `asf/workers/githooks.py` — one call in the shim

Inside the existing `pre-push` block, after the `trunk-check` call (`:182-193`) and before the push
log (`:194-199`), reusing the `cli` already resolved there:

```sh
    if [ "$rc" = 0 ] && [ -n "$input" ] && [ -n "$ASF_PRODUCT" ] && [ -n "$cli" ]; then
        out=$(printf '%s\n' "$input" | "$cli" pre-push --product "$ASF_PRODUCT" 2>&1)
        rc=$?
        [ -n "$out" ] && printf '%s\n' "$out" >&2
        [ "$rc" = 0 ] || asf_refused "hook refused" "$out"
    fi
```

`cli` is hoisted out of the `trunk-check` block so both calls share one `command -v`. Everything
else in the shim is byte-for-byte: the heartbeat skip still exits before any of it, the scratch-repo
test still turns the whole block off (a product test's fixture push is not a session's — the 2026-10-02
defect at `:131-138`), the push-allow refusal still comes first, and a session with no `ASF_PRODUCT`
reaches neither call.

### 5. `asf/briefs/build.py` — the rubric, and the footprint on the wire

**The rubric block.** One function, rendered into the code kinds' briefs (`coder`, `correct`,
`fixer`, `fix-bug`, `direct`) after the gate paragraph:

```python
def rubric_block(product, kind, facts):
    """The checklist the session ticks before its push: `precheck.render_table`'s skeleton for
    this brief's derived level and the classes the Task's `writes:` reach, then one row per
    `pre_push_checks` rule those `writes:` reach — the rows the door will check itself."""
```

* the level is `precheck.level_for(size_class, None, max_lines, security=bool(hit))` — no diff
  exists yet, which is `level_for`'s documented `changed_lines=None` case: `low` for a small
  Task, `high` otherwise, floored at `high` by a sensitive footprint;
* `hit` is `security.paths.classes(conv)` filtered by `footprint.globs_overlap` against the
  Task's `writes:` — the first caller `asf/security/paths.py` has had (P6) — and feeds
  `precheck.security_dimensions(hit)`;
* the rule rows are `prepush.reaching(rules, writes)`, each printed as its `why`, its `run` and
  its `paths` — so the sentence the session ticks is the sentence the refusal will print.

The block is a `## Before the push` section ending in the table and one line: *"The rows above with
a command are run by your `pre-push` hook: a red one refuses the push and prints what failed. Paste
the table, filled, in your report."* An unset `pre_push_checks` leaves the rule rows out; the
dimension rows stand on their own.

**The footprint on the wire** (C12). `Brief` gains `writes_boundary: list = dataclasses.field(default_factory=list)`,
set in `build` from `widen.delivery_footprint(index_items, item_id) + footprint.shared_writes(conv)`
(de-duplicated, first-seen order) for a code kind with a Task, `[]` otherwise.
`step_wave.worker_row` carries it onto `pool.Row(writes_boundary=…)` beside `card_digest`, and
`spawn`'s env dict gains `**prepush.boundary_env(row.writes_boundary)` and
`**prepush.env_for(product, row.job)` (the ledger path) beside `pushlog.env_for` and
`refusals.env_for`. `preview_row` passes nothing: it judges the relaunch cap and never launches.

### 6. The metric

**`asf/scorecard/facts.py`** — `Facts` gains `landings: list = field(default_factory=list)`, filled
by `_stream(root, 'landings')` in `load` (C9).

**`asf/scorecard/score.py`** — one function, modelled on `denials_row`:

```python
def first_push_green_row(facts, start, end):
    """Per lane branch landed in [start, end): did it need no second round? Green when the
    branch's sessions are one building session and no repair one (`repair_flags`), every `gates`
    reading naming it concluded success, and its PR's first head at attempt 1 was green. `caught`
    is the pre-push refusals those runs' records carry."""
```

Returns `{branches, green, rate_pct, by_kind: {kind: [green, n]}, caught, not_green: [...]}` —
`rate_pct` `None` over no branch (never 0.0 against no reading, `denials_row`'s own rule), and
`not_green` the three worst branches with the reason each failed, for the line. It goes on
`window_row` as `'first_push_green': first_push_green_row(facts, start, end)`, so
`asf scorecard --check` targets `first_push_green.rate_pct` with `>=` today (P16, C10), and
`headline_line` gains one clause: `first-push green: 61 % (38/62) — 14 caught at the hook`.

**`asf/workers/health.py`** — beside the push count (`:974-977`):

```python
        caught = prepush.caught(product, s.get('job'))
        ...
        pool_mod.update_session(product, job, pushes=pushes, prepush_refused=caught, **extra)
```

and `measure.Run` gains `prepush_refused: int = 0` (P14, C14), read by `first_push_green_row` and
by nothing else.

### What it looks like when it is there

A coder session opens its brief and reads, under `## Before the push`, a table whose last three
rows are the commands its own hook will run, each naming the paths that trigger it. It changes
`asf/tune.py`, forgets `tests/test_tune.py` entirely, and pushes. The push stops: *"push refused —
every test module that covers a file you touched, each module whole … `python3 tools/run_tests.py
--touched origin/main --shards 2` exited 1"*, with the failing module's last lines. It fixes the
test, commits, pushes again, and the push goes. No CI run was started, no red was notified, no
reviewer read it, no correction session was launched. A week later `asf scorecard` says
`first-push green: 71 % (44/62) — 31 caught at the hook`, and `repair_per_feature` is the number
the release gate reads.

Nothing is written to origin: no ref, no branch, no comment, no PR. The one new network call is

resolve is "not checked", never a refusal.
