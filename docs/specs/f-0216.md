# F-0216 — the cloud lane is built, and the host still gets the work

Every piece of the cloud lane is on the trunk: the runtime, the brief, the tracking, the doctor,
the readiness gate, the seat arithmetic, and a `cloud.default` switch that already says "the cloud
lane before the local one". What is not on the trunk is the **default**. `cloud.default` is
`false` (`asf/workers/cloud.py:133`, `:243`, `docs/config.example.yaml:154`), and even switched on
it reaches only eleven kinds off a hand-written allow-list — `DEFAULT_KINDS`
(`asf/workers/cloud.py:99`). The list has drifted from the kind registry it shadows in both
directions at once, and this checkout measures both:

```
$ python3 -c "from asf.workers import cloud; from asf.briefs.build import KINDS; \
  d=set(cloud.DEFAULT_KINDS); k=set(KINDS); print(sorted(k-d)); print(sorted(d-k))"
['close', 'delivery-code', 'delivery-plan', 'fixer', 'groom-clerk', 'rebase', 'replan',
 'reshape', 'spec-plan']
['task']
```

**Nine of nineteen kinds run on the factory host for no stated reason** — a `fixer`, a `rebase`, a
`reshape`, a `replan`, a `spec-plan`, a `delivery-plan`, a `delivery-code`, all of which commit
and push a branch exactly as a `coder` does, and all of which the cloud lane could take today. And
the one name on the list that is not a kind, `'task'`, is unreachable: `worker_row` sets
`kind=brief.kind` and `Brief.kind` is `normalize_kind`'s output, so an alias never gets as far as
`first()` (`asf/tick/step_wave.py:479`, `asf/briefs/build.py:587`, `:599`).

An allow-list is the wrong shape for "local only by exception". It fails **closed toward the
host**: a kind minted next month is local, silently, and nobody writes down why. This card turns
it over. **`LOCAL_KINDS` is the exception list** — three kinds, each with a reason in this
document — and every other kind, now and later, goes to the cloud.

The allow-list also holds a kind that must not be on it. `groom` is in `DEFAULT_KINDS` and the
groom brief says, in capitals: *"THE REPOSITORY IS NOT YOUR WORK. Do not commit, do not push"*
(`asf/briefs/templates/groom.md:32`). Its whole product is a file on this host, `{answers_file}`,
that the next tick reads. In the cloud that file is written to a runner that is then thrown away,
no commit is pushed, `report_commit` finds nothing, and `classify` returns **dead** after
`cloud.timeout_min` — four hours of a runner, and the day's groom answers gone. The operator's own
example config already carries the hand-written patch for this: `# local_only: [groom]`
(`docs/config.example.yaml:155`). A floor nobody can forget replaces it.

Two further things follow from making the cloud the normal case rather than the unusual one, and
they are the other two thirds of this spec.

**A local session must say why it is local.** Today nothing records the lane a session took, let
alone the reason: the run record has no lane key for a local launch, `ctx.event('launch', …)`
carries four fields and none of them is the lane (`asf/tick/step_wave.py:815-817`), and the
`launched` line prints `pid <n>` for local and `cloud <url>` for cloud and no reason either way.
An exception nobody can count is not an exception; it is a default in hiding.

**The host guard covers the local lane only — and the moment it does, it drops the S1 bypass.**
`split_hold` takes the host hold off the wave when the cloud lane is open and hands it back as
`local_hold` (`asf/tick/step_wave.py:565-572`). But `s1_bypass_open` is computed from the
*post-split* `host_held` (`:725-732`), which the split has already set to `False`, and
`wave.decide`'s `local_hold` branch has no S1 exception at all (`asf/workers/wave.py:219-220`). So
an S1 fix row whose cloud seat is taken waits behind the load of other sessions — the exact
outcome the bypass exists to prevent, and one that today is rare because the lane is usually shut
and, after this card, would be the normal case.

## The design

### §1 `asf/workers/cloud.py` — the exception list, and the default

```python
#: The cloud lane is where a row goes. ``cloud.default`` takes this when the config writes no
#: value; a written ``false`` still means overflow-only (F-0216 C5).
DEFAULT_CLOUD_FIRST = True

#: The closed list of kinds that never leave the factory host — the EXCEPTION, in both modes and
#: under every setting. A kind is here only when the cloud lane has no channel back for its work:
#: the lane collects a session by one pushed commit on the product branch and nothing else
#: (asf.workers.actions's workflow, :func:`report_commit`), and these three produce none.
#:
#: ``groom``, ``groom-clerk`` — the brief forbids the commit and the push in as many words ("THE
#:   REPOSITORY IS NOT YOUR WORK"), and the answers file it writes instead is a path on this host
#:   that the next tick reads. In the cloud the run ends ``dead`` and the day's answers are lost.
#: ``close`` — one report line, no commit, no push, and a brief that says to leave the branch
#:   alone; there is nothing for the lane to carry back.
#:
#: ``cloud.local_only`` adds to this list. Nothing takes from it (F-0216 C4).
LOCAL_KINDS = ('groom', 'groom-clerk', 'close')
```

`DEFAULT_KINDS` is deleted. The three predicates become:

```python
def local_only(row, s):
    """The row never leaves the host: its kind is a :data:`LOCAL_KINDS` one (the floor, both
    modes — F-0216 C3), a kind the operator added in ``cloud.local_only``, or its item says
    ``local_only: true``. The kind is the canonical one: ``asf.tick.step_wave.worker_row``

    return kind in LOCAL_KINDS or kind in s.local_only \
        or truthy(getattr(row, 'local_only', False))
```

### §2 `LOCAL_CAUSES` — why this session is on the host

```python
#: Why a session ran on the factory host instead of the cloud lane — one per local launch, from
#: this closed list, first match wins in this order. The structural reasons come before the
#: transient ones: a kind that cannot leave the host is not a lane that happened to be full.
LOCAL_CAUSES = ('lane-off', 'lane-unready', 'kind-local', 'item-local', 'tick-cap',
                'cloud-full', 'cloud-account')


def local_cause(row, s, ready, capped, cloud_reason=''):
    """The one :data:`LOCAL_CAUSES` entry for a row that took the local lane.

    ``ready``: the lane's readiness verdict this tick (:func:`readiness`, read once per wave).
    ``capped``: ``cloud.max_creates_per_tick`` is spent. ``cloud_reason``: what
    :meth:`asf.workers.pool.Pool.pick_cloud` said when it gave no seat — read only to tell a full
    lane from an account that could not take the launch, never re-parsed beyond its first word.
    """
```

| cause | when |
| --- | --- |
| `lane-off` | `not s.on` — `cloud.enabled` false, an unknown runtime, or no seat |
| `lane-unready` | the lane is on and `readiness` failed (the secret, the workflow, the runner, the account) |
| `kind-local` | `row.kind` is in `LOCAL_KINDS` — the floor |
| `item-local` | `cloud.local_only` names the kind, or the item carries `local_only: true` |
| `tick-cap` | `cloud.max_creates_per_tick` is spent this tick |
| `cloud-full` | `pick_cloud` said `cloud full — <n>/<max> in flight` |
| `cloud-account` | `pick_cloud` gave no seat for any other reason: no lane account, a quota band, the 5h headroom |

`wave.decide` sets it on the row the moment a local seat is taken, and the `launched` line names
it:

```
launched spec-f-0216            F-0216     → acct-a (opus) pid 40213 local: cloud-full
launched task-t-0700            T-0700     → acct-c (opus) cloud https://…/runs/9912
```

`spawn` writes it beside the fields the row already carries (C9, P14), and inverts the
`host_load_bypass` write so the ledger's one live bypass is always a local one (C12):

```python
record.update({k: v for k, v in (getattr(result, 'extra', None) or {}).items() if v is not None})
if not record.get('runtime_lane'):          # a local launch, and only one
    if getattr(row, 'local_cause', ''):
        record['local_cause'] = row.local_cause
    if getattr(row, 'host_load_bypass', False):
        # the S1 load-hold bypass: at most one live at a time, across every product. A cloud run
        # passed no host hold and runs nothing here, so it never holds this shut (F-0216 C12).
        record['host_load_bypass'] = True
```

and the wave step's launch event gains the two fields off that record (C10):

```python
ctx.event('launch', item=wrow.item, job=wrow.job, model=rec.get('model'),
          brief_kind=kinds[wrow.job],
          lane=rec.get('runtime_lane') or 'local', local_cause=rec.get('local_cause') or '')
```

### §3 The host guard: local only, and the bypass it keeps

Two lines. In `asf/tick/step_wave.py`, the bypass is decided from the hold **as the host reported
it**, before the split hands it to the local lane:

```python
raw_held, host_why, reading = host_hold(planned)
# a loaded host still starts cloud sessions: nothing of theirs runs here
host_held, local_hold, _extra = split_hold(cloud, ready, raw_held, host_why)
# the S1 bypass is the LOCAL lane's, so it is decided from the hold the host reported — the split
# has already taken that hold off the cloud rows, and reading it after the split retired the
# bypass for every tick the lane was open (F-0216 P15)
s1_bypass_open = (raw_held
                  and host_mod.load_only_hold(reading, host_mod.guards_from_config(env.load_config()))
                  and not s1_bypass_live())
```

and in `asf/workers/wave.py`, `decide()`'s hold branch lets that one row through:

```python
if local_hold and not getattr(row, 'host_load_bypass', False):
    acct, reason = None, f'held: {local_hold}'
```

Nothing else moves. `split_hold`'s shape, `local_seats`, the seat arithmetic and the
`wave: local lane held: …` line are what they are. The memory half is untouched: `load_only_hold`
is still `over_load and not over_mem`, so a host over its swap or memory guard holds every row,
S1 included.

The guard's scope is then a property of its three call sites (P16), and C13 fences it.

### What it looks like when it is there

An operator with `asf cloud install` run and a token secret set gets the cloud lane for every row
but a groom, a groom-clerk and a close, with no `cloud.default: true` to remember and no
`local_only: [groom]` to write. The host runs three clerical kinds and whatever the lane could not
take, each one saying which of the seven reasons it was. Under host pressure the wave keeps
launching into the cloud and says `wave: local lane held: host pressure load 34 (1m 32)/cores 10,
memory 91% — the cloud lane takes what it can`, and an S1 fix row whose cloud seat is gone still
gets its one local launch. An operator who wants the old behaviour writes `default: false` and
gets overflow exactly as today.
