# F-0326 — a row is not an owner

The reporting product's last Task of a Feature sat pushed, its PR open, with three Tasks blocked
behind it. `asf next` had a row for it — `PUSHED → LAND`, `reason: pushed work, no other row`,
which is the ownerless catch-all of `pushed_rows` and nothing else. Reproduced from the record in
this worktree, that row is one line of the plan and reads:

```
| 2 | PUSHED → LAND | T-0002 | F-0002 | WAITS ON landing: PR #1281 open, no run holds it — the lane takes it up |
```

Nothing moved. The operator landed it by hand with `asf land 1281 --priority`, and the lane
recorded the result as a landing it did not make (`method=external`).

Two things are wrong with that row, and they are the same thing twice.

It **asserts an actor nobody checks**. "The lane takes it up" is the catch-all arm of
`pushed_rows` (`asf/feeder/rows.py:2731-2758`, the arms at 2745-2754), reached precisely when the record can see an open
PR on the card and occupancy can see no lane state and no run for it. The claim is a guess about
what a different component will do on a future pass, written as a fact, and the one fact that
would have backed it — the lane record — is exactly the one that is missing. When the lane does
not take it up, nothing says so.

It **satisfies every view by existing**. `orphaned_pushed` counts pushed work with *no* row; this
item has one, so the count is zero and `asf doctor`'s `pushed work` row is green — *"every open
Task/Bug with an open PR has a NEXT row"* (P4 below, measured). The wave prints one `waits` line
and moves on. The invariant the sibling feature built to make pushed work un-silenceable was
honoured to the letter and the work still sat: a row was produced, and a row is not an owner.

The card's requirement is the sentence the row is missing: **when rows are waiting on pushed work
that no run and no lane state holds, the plan says how many, and names the command that lands
it** — the command the operator already had to find. Nothing is landed automatically, for a reason
measured in D3.

### Preconditions the work depends on

* The dependants come from `after:` edges rendered as `WAITS ON <id>` rows by `hold_unlanded`.
  A product whose record carries no `after:` has no rows behind anything, so nothing surfaces and
  nothing changes for it — the honest answer, since nothing is in fact waiting.
* The PR number comes from the card's own evidence (`PR #N OPEN`, `open_pr_of`,
  `rows.py:2709-2715`). A card whose evidence names no open PR gets no command (P11, D5).
* `conventions.merge: queue` is what makes `asf land` the door. A product that does not use the
  queue has no `asf land`; its ownerless landing wait keeps the text it has today, because the
  command the row would name does not exist there. The row is only ever rewritten when the
  record gives it a PR number, which is the same condition in practice.
* `_candidates` runs `hold_unlanded`, `blocked_row` and the blocked/parked holds *before* the
  surfacing step, so a row those have already claimed is not rewritten (D8's guard).

## The design

Two files. One new constant, two new fields, one new rule and one new reader in the feeder; one
argument and one line in the doctor. Plus `TableTests.test_json`'s pin (P9).

### 1. `asf/feeder/rows.py` — the row says what it knows

The threshold, beside `ROOTS_MIN_DEPENDANTS` and deliberately not it:

```python
#: F-0326: rows behind an ownerless landing wait that surface it. One, not
#: :data:`ROOTS_MIN_DEPENDANTS`' five: a landing nobody owns is already a stall at the first row
#: that waits on it (the incident had three), and unlike a park there is no person to wait for.
LANDING_MIN_DEPENDANTS = 1
```

Two fields on `Row`, in the shape its per-row-kind fields already use:

```python
    #: a PUSHED → LAND row only: the open PR the row speaks for, '' when the record names none
    pr: str = ''
    #: a PUSHED → LAND row only: no run and no lane state holds this pushed work
    ownerless: bool = False
```

`pushed_rows` marks the catch-all arm and types the number it already knows. Only the `else` arm
is marked — the `waiting[iid]` arm names a wait the lane or harvest owns, and the `back` arm names
a branch the lane re-reads:

```python
        else:
            action = f'{WAITS_LANDING}: {what} open, no run holds it — the lane takes it up'
            ownerless = True
        row = Row(tier=review_tier(item), kind=PUSHED_LAND, item_id=iid,
                  feature_id=f['id'] if f else '', action=action, brief_kind='review',
                  branch=_branch_of(item, product, kind), reason='pushed work, no other row',
                  pr=number, ownerless=ownerless)
```

The rule, beside `surface_stale_parks`:

```python
def surface_stale_landings(rows, least=LANDING_MIN_DEPENDANTS):
    """F-0326: an ownerless landing wait (:func:`pushed_rows`' catch-all — pushed work with an
    open PR that no run and no lane state holds) with at least ``least`` rows behind it
    (:func:`waiting_roots`) becomes ``NEEDS DECISION: <n> rows wait on this landing — asf land
    <pr> --priority``, first in its tier. Nothing is landed: the factory cannot say whether that
    head was ever reviewed — the missing lane record is exactly the fact that would have said so
    — so it names the command and a person decides (B-0042).

    A row with no PR number carries no command and is left as it is: a pushed branch with no PR
    is the dwell watchdog's ``branch_no_pr``, which already owns it."""
```

Its body is `surface_stale_parks`' body with the park's `since`/`days` test replaced by the
dependant count, the same `dataclasses.replace`, and the same reinsertion of each surfaced row at
the first row whose tier is at least its own.

The reader the doctor and the tests share:

```python
def stalled_landings(rows):
    """``{item: (pr, n)}`` — the ownerless landing waits :func:`surface_stale_landings` turned
    into a ``NEEDS DECISION``: work nobody owns with ``n`` rows behind it. ``asf doctor``'s
    ``pushed work`` row reads this back (F-0326)."""
```

And one line in `_candidates` — the function that holds the sort and the park rule, `rows.py:2599`
— immediately before the park call at `rows.py:2705` (D6):

```python
    ordered = surface_stale_landings(ordered)
    if roots:
        ordered = surface_stale_parks(ordered, items, product, park_since(occ, adjudicated), now)
```

### 2. `asf/doctor.py` — the invariant asks the second question

`pushed_work_line` takes the second half and keeps one row:

```python
def pushed_work_line(orphans, stalled=None):
    """``(ok, detail)`` for the pushed-work invariant: red while an open Task/Bug with an open PR
    has no NEXT row and no session (:func:`asf.feeder.rows.orphaned_pushed`), and red while one
    has only a row nothing owns — an ownerless landing wait with rows behind it
    (:func:`asf.feeder.rows.stalled_landings`, F-0326). A row is not the same as an owner: the
    first half was green through the whole incident this second half names."""
```

Green becomes `pushed work: every open Task/Bug with an open PR has a NEXT row and an owner`;
red joins the halves with `; `, so a product with both says both in one row. `check_pushed_work`
passes the second reader over the plan it already built (P10):

```python
        return pushed_work_line(feeder_rows.orphaned_pushed(index, plan, inputs.get('occupancy'),
                                                            inflight),
                                feeder_rows.stalled_landings(plan))
```

## Acceptance tests

They go in `tests/test_pushed_work.py`, whose docstring already owns this invariant — *"Pushed
work is never silent: an open Task/Bug with an open PR always has a NEXT row"* — and which this
card extends by one clause: and an owner. Its existing twelve cases stay green unchanged.

The fixture is the incident's, parameterised by how many rows wait behind the pushed Task:

```python
def index(dependants=3):
    """F-0002's last Task T-0002 is pushed with PR #1281 open; ``dependants`` Tasks of F-0003
    carry ``after: T-0002`` and so wait on its landing (the incident's shape)."""
    items = {'E-0001': {'id': 'E-0001', 'type': 'epic', 'rank': 1, 'state': 'Active'},
             'F-0002': {'id': 'F-0002', 'type': 'feature', 'parent': 'E-0001', 'rank': 2,
                        'stage': 'building 0/1', 'state': 'Active', 'decided': True,
                        'children': ['T-0002']},
             'T-0002': {'id': 'T-0002', 'type': 'task', 'parent': 'F-0002', 'rank': 1,
                        'state': 'Active', 'decided': True, 'writes': ['b.py'],
                        'evidence': ['PR #1281 OPEN', 'branch worker/T-0002']}}
    kids = [f'T-001{n}' for n in range(dependants)]
    items['F-0003'] = {'id': 'F-0003', 'type': 'feature', 'parent': 'E-0001', 'rank': 3,
                       'stage': f'building 0/{max(dependants, 1)}', 'state': 'Active',
                       'decided': True, 'children': kids}
    for n, iid in enumerate(kids):
        items[iid] = {'id': iid, 'type': 'task', 'parent': 'F-0003', 'rank': n + 1,
                      'state': 'New', 'decided': True, 'writes': [f'c{n}.py'],
                      'after': ['T-0002']}
    return {'items': items}


def plan(idx=None, occ=None, capacity=4):
    return rows.plan_rows(idx or index(), product(), [], capacity, occupancy=occ or {})
```

### S-91605: an ownerless landing wait with rows behind it names the count and the command, first in its tier

### S-91606: a landing the lane or harvest owns is never surfaced, and the row carries the PR and the ownerless mark as typed fields
