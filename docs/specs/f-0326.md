# F-0326 — a row is not an owner

The reporting product's last Task of a Feature sat pushed, its PR open, with three Tasks blocked
behind it. `asf next` had a row for it — `PUSHED → LAND`, `reason: pushed work, no other row`,
which is the ownerless catch-all of `pushed_rows` and nothing else. Reproduced from the record in
this worktree, that row is one line of the plan and reads:

```
| 2 | PUSHED → LAND | T-0002 | F-0002 | WAITS ON landing: PR #1281 open, no run holds it — the lane takes it up |
```

Nothing moved. The operator landed it by hand with `asf land 1281 --priority`, and the lane
recorded the result as a landing it did not make (`method=external`).

Two things are wrong with that row, and they are the same thing twice.

It **asserts an actor nobody checks**. "The lane takes it up" is the catch-all arm of
`pushed_rows` (`asf/feeder/rows.py:2731-2758`, the arms at `2746-2754`), reached precisely when the
record can see an open PR on the card and occupancy can see no lane state and no run for it. The
claim is a guess about what a different component will do on a future pass, written as a fact, and
the one fact that would have backed it — the lane record — is exactly the one that is missing. When
the lane does not take it up, nothing says so.

It **satisfies every view by existing**. `orphaned_pushed` counts pushed work with *no* row; this
item has one, so the count is zero and `asf doctor`'s `pushed work` row is green — *"every open
Task/Bug with an open PR has a NEXT row"* (`P4` below, measured). The wave prints one `waits` line
and moves on. The invariant the sibling feature built to make pushed work un-silenceable was
honoured to the letter and the work still sat: a row was produced, and a row is not an owner.

The card's requirement is the sentence the row is missing: **when rows are waiting on pushed work
that no run and no lane state holds, the plan says how many, and names the command that lands
it** — the command the operator already had to find. Nothing is landed automatically, for a reason
measured in `D3`, and the command is named only on the products where it is a door, for a reason
measured in `P16` and decided in `D11`.

### Preconditions the work depends on

* The dependants are **rows waiting on the item**, not only `after:` edges. `waiting_roots`
  (`rows.py:2433`) counts any row whose `action` is exactly `WAITS ON <id>` with a matching
  `waits_on` and an id-shaped target (`rows.py:2439-2441`), which `hold_unlanded` writes for an
  `after:` edge and `blocked_row` writes for a `blockedBy:` hold (`rows.py:1528-1533`, reached
  from `feature_rows` at `:1524` and from `pushed_rows` itself at `:2758`). So a Task blocked on
  the pushed item counts too — truer to the card's "3 rows waited on it", which is a count of
  what the operator saw waiting, not of one edge type. A product whose record carries neither
  kind of edge has no rows behind anything, so nothing surfaces and nothing changes for it — the
  honest answer, since nothing is in fact waiting.
* The PR number comes from the card's own evidence (`PR #N OPEN`, `open_pr_of`,
  `rows.py:2709-2715`). A card whose evidence names no open PR gets no command (`P11`, `D5`).
* **`conventions.merge: queue` is what makes `asf land` a door, and it is not the default.** The
  rule is gated on it (`D11`): `asf land` is registered on every product but refuses off-queue
  with `return 2` (`P16`), so on a `manual` or `auto` product the row and the doctor line stay
  exactly as they are today. A PR number and a queue are *not* the same condition — a `manual`
  product can hold a card whose evidence says `PR #N OPEN` — which is why the gate is a separate
  conjunct and not a consequence of `r.pr`.

## The design

Two files. One new constant, two new fields, one new rule and one new reader in the feeder; one
argument and one line in the doctor. Plus `TableTests.test_json`'s pin (`P9`).

### 1. `asf/feeder/rows.py` — the row says what it knows

The threshold, beside `ROOTS_MIN_DEPENDANTS` and deliberately not it:

```python
#: F-0326: rows behind an ownerless landing wait that surface it. One, not
#: :data:`ROOTS_MIN_DEPENDANTS`' five: a landing nobody owns is already a stall at the first row
#: that waits on it (the incident had three), and unlike a park there is no person to wait for.
LANDING_MIN_DEPENDANTS = 1
```

Two fields on `Row`, in the shape its per-row-kind fields already use:

```python

    pr: str = ''
    #: a PUSHED → LAND row only: no run and no lane state holds this pushed work

```

`pushed_rows` marks the catch-all arm and types the number it already knows — on every product,
whatever its merge mode (`D4`). Only the `else` arm is marked: the `waiting[iid]` arm names a wait
the lane or harvest owns, and the `back` arm names a branch the lane re-reads:

```python

            ...
        elif back:
```

The rule, beside `surface_stale_parks` and with its signature:

```python
def surface_stale_landings(rows, product, least=LANDING_MIN_DEPENDANTS):
    """F-0326: an ownerless landing wait (:func:`pushed_rows`' catch-all — pushed work with an
    open PR that no run and no lane state holds) with at least ``least`` rows behind it
    (:func:`waiting_roots`) becomes ``NEEDS DECISION: <n> rows wait on this landing — asf land
    <pr> --priority``, first in its tier. Nothing is landed: the factory cannot say whether that
    head was ever reviewed — the missing lane record is exactly the fact that would have said so
    — so it names the command and a person decides (B-0042).

    Only under ``conventions.merge: queue``: ``asf land`` is registered on every product but
    refuses off-queue (``not on conventions.merge: queue``, exit 2), and the default mode is
    ``manual``, so elsewhere the row keeps the text it has (D11). A row with no PR number carries
    no command for the same reason and is left as it is: a pushed branch with no PR is the dwell
    watchdog's ``branch_no_pr``, which already owns it (D5)."""
    if not product.conventions.merge_queue():
        return rows
```

Those two lines are the whole of the gate, and they come first — before `waiting_roots` is even
called, so a non-queue product pays nothing for the rule. `least` is a parameter for the same
reason `surface_stale_parks` takes its threshold through `roots_settings`: so the acceptance can
drive the boundary without a flag. **No caller passes it** — `_candidates` calls
`surface_stale_landings(ordered, product)` and nothing else does, which is `D2`/`D9`'s point that
this is not configurable. A coder who prefers the constant read inside the body may drop the
parameter; nothing in the acceptance passes it.

The rest of the body is `surface_stale_parks`' body (`rows.py:2470-2502`) with the park's
`since`/`days` test replaced by the dependant count, the same `dataclasses.replace`, and the same
reinsertion of each surfaced row at the first row whose tier is at least its own
(`s.tier <= r.tier`, `rows.py:2497`) — the reinsertion is not decoration: `P15` measures the row
it moves. Three differences from that body:

* the guard is `r.ownerless and r.action.startswith(WAITS_LANDING) and r.pr`, where the park rule
  tests `r.action.startswith(PARKED)` — same question, asked of the typed fields `D4` adds plus
  the action a later hold may have taken over (`D8`);
* the count is **pluralised**: `1 row waits on this landing`, `3 rows wait on this landing`.
  `surface_stale_parks` writes `{n} rows wait` unconditionally, because its own threshold is five
  and it can never render a one; this rule's threshold is one, so a body copied from it verbatim
  would print `1 rows wait on this landing`;
* **and the reason is pluralised with it**, which is the trap the park rule's suffix hides: its
  `reason=f"{r.reason} — {n} rows wait on it: …"` is the same unconditional plural, and at this
  rule's threshold — `n == 1`, the common case — a verbatim copy publishes
  `pushed work, no other row — 1 rows wait on it: T-0010`. Not an internal field:
  `render.rows_json` (`asf/feeder/render.py:96`) dumps `r.__dict__`, so `asf next --json` carries
  it. The reason reads `1 row waits on it: T-0010` and `3 rows wait on it: T-0010, T-0011,
  T-0012`, first five then `+N`, in the same words as the action. The acceptance pins both cells
  at both counts.

One pluralisation, written once and used in both cells, is the way to hold that: e.g.
`waits = f'{n} rows wait' if n != 1 else '1 row waits'`, then `f'{NEEDS_DECISION}: {waits} on this
landing — asf land {r.pr} --priority'` and `f"{r.reason} — {waits} on it: …"`.

The reader the doctor and the tests share. It is given here as a body and not only a docstring,
because the guard is the whole of it — a reader that selects on `ownerless and pr` alone turns
`asf doctor` red on every product that merely has a freshly pushed PR with nothing behind it,
which is the one case the `Out` table excludes and `D5`/`P11` hand to `branch_no_pr`, *and* on
every non-queue product, where `D11` decided nothing changes:

```python
def stalled_landings(rows):
    """``{item: (pr, n)}`` — the ownerless landing waits :func:`surface_stale_landings` turned
    into a ``NEEDS DECISION``: work nobody owns with ``n`` rows behind it. ``asf doctor``'s
    ``pushed work`` row reads this back (F-0326).

    Only rows the rule actually surfaced: ``ownerless`` and a PR number are what made the row a
    candidate, and the ``NEEDS DECISION`` action is what says the rule fired — a pushed row with
    nothing behind it keeps its ``WAITS ON landing`` action and is absent here, as is one a later
    hold took over, as is every row on a product that is not on ``conventions.merge: queue``
    (D11: the rule returned the rows untouched there). ``n`` is recounted from
    :func:`waiting_roots`, never re-parsed out of the action text (D4: that is what the typed
    fields exist to avoid)."""
    behind = waiting_roots(rows)
    return {r.item_id: (r.pr, len(behind.get(r.item_id) or ()))
            for r in rows
            if r.ownerless and r.pr and r.action.startswith(NEEDS_DECISION)}
```

The three conjuncts of that guard are the same three `surface_stale_landings` tests, with
`NEEDS_DECISION` where the rule has `WAITS_LANDING`: the rule reads rows it has not yet rewritten,
this reads the ones it has. So `stalled_landings` is `{}` on exactly the plans where the rule
surfaced nothing, and the acceptance pins that empty shape three times — for `dependants=0`, for
the no-PR arm, and for a `merge: manual` / `merge: auto` product.

And one line in `_candidates` — the function that holds the sort and the park rule, `rows.py:2599`

## Acceptance tests

They go in `tests/test_pushed_work.py`, whose docstring already owns this invariant — *"Pushed
work is never silent: an open Task/Bug with an open PR always has a NEXT row"* — and which this
card extends by one clause: and an owner. Its existing twelve cases stay green unchanged.

Four fixtures. `landing_product` is the queue product `D11` requires; `landing_index` is the
incident's shape, parameterised by how many rows wait behind the pushed Task; `nearer_pushed` is
that shape plus the second pushed row `P15` measures, and only the one ordering case uses it;
`landing_plan` draws the plan. **The index fixture is named `landing_index`, not `index`**:
`tests/test_pushed_work.py` already defines a module-level `def index()` (its own PR #7 shape,
line 20) and ten of its twelve cases call it, so a second module-level `def index(...)` in that
file would silently replace it and redden every one of them. Same for `landing_product` against
the module's own `product()` (`:16-17`), which stays the default-conventions product those twelve
cases use. `by_item()` is the module's own, used unchanged:

## Records

Nothing new is written anywhere. The change alters the four existing records below and adds no
file, no event and no state. Every one of them changes **only on a `conventions.merge: queue`
product, and only for a row with at least one row behind it** (`D11`) — except the two new JSON
keys, which are `Row` fields and so appear on every product's rows, defaulted.

| Record | What changes |
|---|---|
| `asf next` (the table, `render.table`) | The Action cell of an ownerless landing wait with rows behind it, and its place in its tier |
| `asf next --json` (`render.rows_json`) | Two new keys on every row, `pr` and `ownerless`, both defaulted — `P9`'s pinned key set grows by two. And, on a surfaced row, the published `reason`, which gains `— <n> row[s] wait[s] on it: <ids>` (first five, then `+N`) |
| `asf doctor`'s `pushed work` row | Red for the second half; its green text gains "and an owner" |
| The tick's wave log (`step_wave.screen`'s `waits` line) | Carries the rewritten action, with no change in `step_wave.py` |

No card is filed, no `## History` line is written, no ledger event is added, no file under
`state/<product>/` is read or written that is not read today, and no host call is made. The one
durable consequence of the change is that a person reading `asf next` or `asf doctor` on a queue
product is handed `asf land <pr> --priority`, and the decision to run it stays theirs.

## Stories

Three Stories, one per piece of `## The design` plus the typed-field half the other two both
stand on. Each is **declared** below as a `### S-…: <title>` heading with its acceptance lines
under it, with ids from the claimed block `S:91605-91654` (`D10`). That heading is what
`asf.record.idcheck.declared_stories` reads and what `asf.record.plan_tasks` mints the card from —
a cited id with no declaration is a phantom and the plan citing it is refused whole.

Each acceptance line is one physical line of plain text with no backticks, on purpose: the reader
is line-anchored (`asf.record.idcheck.CHECKBOX` matches a single line) and `_prose` replaces every
inline code span with one space before parsing, so a wrapped line reaches the minted card
truncated and an identifier inside backticks reaches it missing. For the same reason every local
id cited in the prose of a Story section below is written inside backticks: `decisions.normalise`
(`asf/record/decisions.py:94-112`) rewrites a bare `D7` into `D-0007` on the card it mints, and
the register holds `D-0001`…`D-0052` as real and unrelated decision cards. The first column of
the `### The choices` table stays bare (`| D11 |`) because that is the shape
`decisions._SPEC_TABLE_ROW_RE` (`:24`) reads this spec's own choices by.

### S-91605: an ownerless landing wait with rows behind it names the count and the command, first in its tier
