# F-0130 — the record cannot see anything that happened before it existed

Operator decision, 2026-09-24: adopting ASF on a product that was already partly built is the
normal case. That makes this a factory feature and not a per-product chore — and the first adopting
product shows exactly what the factory gets wrong.

Three symptoms, one cause:

- the pre-ASF migration marked shipped work `removed: history…`, and `ingest_into` skips a retired
  Feature outright (`asf/record/ingest.py:1100-1101`), so none of it counts as delivered and none of
  it is even *derived*;
- old Features, Stories and Tasks sit New/Active with no evidence either way;
- ~140 pre-ASF pull requests are still open — roughly 105 carrying clean unmerged work, 36
  conflicting, several report-only — and nothing in the factory will ever land or close them.

The cause is structural, and it is two lines of code. `main_commits` reads the trunk **only since the
record's first commit** (`asf/evidence/evidence.py:1035-1037`, `record_since` at `:1013-1029`), so
every pre-ASF merge is invisible to the trunk walk by construction. And the pull-request route that
could have covered them maps a PR to a card through `branch_ids(headRefName)` — a
`[EFSTBDR]-\d{4}` token — so a legacy branch name maps to nothing: measured in this checkout,
`naming_ids('Merge pull request #820 from o/feature/auth-flow-3')` is `[]`, and
`naming_ids('Add the auth flow (#820)')`, the squash form, is `[]` too.

So the factory is not mis-reading the history. **It is not reading it.**

The good news is how little has to be built, because the record already has the whole apparatus and
one piece of it is dead. `closing.RULES`' very first row is
`('any', 'reconciled', lambda ev: bool(ev.landed and ev.green), CLOSED, 'a typed landed sha and green CI')`,
`Ev.landed` is documented *"the typed reconciliation sha"*, `asf check` already validates a typed
`landed:` as a 7–40 hex sha, and `closing._TYPED_ANSWERS` names the three answers a card may carry
to the question *was this done before the record existed* — `landed`, `reconciled`, `removed`. What
is missing is a producer: today those answers are typed **one card at a time by a person answering a
groom question** (`groom_predates_section`, `asf/groom/groom.py:680-691`), which is precisely the
per-product chore the operator's decision rejects. And `landed=` is passed to `closing.Ev` nowhere
in `asf` — measured — so even a typed answer changes nothing.

`asf backfill` is the code that answers those questions from merged history, deterministically, with
no model in the loop: it reads the trunk and the host, maps what it finds to cards through the
product's own declared legacy conventions, types the record's own existing answer on each card it
can prove, gives every open pre-ASF pull request exactly one disposition, and prints what it could
not match as one table for the operator. The state itself is still `asf ingest`'s to derive, by the
rules that are already written.

### In

- **`asf backfill [--product <p>] [--apply] [--dry-run] [--since <rev>]`** — a new command in
  `asf/cli.py` and a new row in `asf/surface.py`, backed by a new package `asf/backfill/`.
  Read-only unless `--apply` is given (D6).
- **`asf/backfill/history.py`** — merged history → `{card: Landing}`. Walks every merge and every
  merged pull request that reaches the trunk, takes each one's **head branch name** (from the merge
  subject, or from the pull request's `headRefName`), and resolves it to a card through
  `match.match_event` plus the product's `conventions.legacy_branch` (D4, D5). Merge-queue batch
  commits are expanded to their member pull requests first.
- **`asf/backfill/prs.py`** — one disposition per open non-lane pull request: `on_trunk`, `adopt`,
  `report_only`, `conflicting_stale`, or `residue`. Pure over facts a reader gathered (D7).
- **`asf/backfill/apply.py`** — the writes, each one idempotent: the typed answer on a card, the
  un-retiring of a `removed: history…` Feature, the pull-request closes, and the hand-over of an
  adoptable branch to the lane.
- **`asf/backfill/report.py`** — the table, printed and written to `backfill/<date>.md` in the
  record, in the shape `asf groom` established for `groom/<date>.md`.
- **`conventions.legacy_branch`** — a regex with named groups `slug` and (optionally) `task`, read
  only when `match_event`'s own legacy path finds nothing; and **`conventions.legacy_review`** —
  `{glob, verdict_regex}`, the product's pre-ASF review files and the line that means APPROVED.
  Both become checked keys of `validate_mapping` (P15).
- **`ingest`'s Task loop hands `landed=` to `closing.Ev`**, with `_green_after` answering the green
  half — F-0106's C6, scoped to Tasks and Bugs exactly as its C7 scoped it (D2, D3).
- **`evidence.merge_branch(subject)`** — the head branch name `_MERGE_SUBJECT` already captures,
  exposed as a function so backfill can resolve it against the record without `naming_ids` learning
  to read the record (D4).

### Out

- **No model, no judgement, no prose read.** Every decision in this pass is a predicate over git,
  the host and the record. A case no predicate decides goes in the residue table for a person.
- **No new closing rule, no new state, no second definition of done.** `closing.RULES` is not
  edited. Backfill types an answer the record already defines; `asf ingest` derives the state, as it
  does for everything else.
- **Backfill never merges, never runs a gate, never launches a review session and never pushes to the
  trunk.** An adoptable pull request is handed to the lane and lands by the lane's normal
  review → gate → land path (D7). The `PR-<n>` route of P9 is left exactly as it is.
- **No typed `landed:` on a Story, a Feature or an Epic.** Those close on their children by today's
  rules; typing the answer on a parent jumps the ladder (F-0106's C7). The `reconciled` rule stays
  an `any` rule; only the Task/Bug loop hands it the field (D2).
- **Parity Stories are not closed by backfill.** A Story closes on its Tasks and its matrix row, as
  today — the product's *done = tests green* rule is `closing`'s `story matrix-done` /
  `tasks-closed`, and this card adds nothing to it.
- **`asf migrate` / `import-items` is not changed.** It creates the live item set; this pass
  reconciles history against the set that already exists. Re-running `migrate` is not part of it.
- **`pr_list`'s `--limit 300` is not raised** (P12): backfill walks its own paginated list, and
  every other caller keeps the cheap cached one.
- **No branch classification of its own.** A product's pre-ASF prefixes go in
  `branch_prefixes.legacy`, which `branch_kind` already honours (P8). Backfill adds no second
  notion of what a legacy branch is.
- **No history rewrite, no force-push, no `--no-verify`.** Nothing this pass does touches a commit
  that is already on the trunk.
- **`STORY_ID_RE`'s four-digit shape is not fixed here** (P17).
- **`surface.apply` is not wired to the parser here**, and `migrate → import-items` is not renamed:
  both are P14's separate debt, and doing either would put every existing command in this card's
  blast radius.

## The design

### 1. The two declarations, and a misshapen one being loud

Three keys, all in `asf/conventions.py` (P16's one legal home for convention knowledge):

```python
#: ``legacy_branch``: a regex over a pre-ASF branch name, with a named group ``slug`` and an
#: optional named group ``task``, read by ``asf backfill`` only when the record's own legacy
#: matcher (:func:`asf.record.match.match_event`, rule 4) resolved nothing for the name (F-0130,
#: D5). ``None`` — the default — means that fallback is not offered.
legacy_branch: str = None
#: ``legacy_review``: ``{glob, verdict_regex}`` — where a product's pre-ASF review files live and
#: the line that means APPROVED in one. Read only while adopting an open pre-ASF pull request, and
#: only ever to *skip* a review, never to hold one (F-0130, D14).
legacy_review: dict = None
```

`branch_prefixes.legacy` is not new (P8): a product declares its pre-ASF prefixes there and the
lane, retention and `branch_kind` all already read them.

`validate_mapping` gains both, in the shape it already uses for `full_suite_commands` (a regex that
must compile) and `branch_retention.legacy_prefixes` (a checked list):

- `legacy_branch` must be a non-empty string that `re.compile` accepts and whose group names
  include `slug`; anything else is one problem naming what is wrong;
- `legacy_review` must be a mapping; its `glob` a non-empty string; its `verdict_regex` a string
  `re.compile` accepts.

`asf/env.py:684-687` already turns each `(key, why)` into a dotted config problem, so this needs no
new call site and shows up wherever config problems already show up. P15 is the reason it matters:
today `legacy_branch: 12` is kept verbatim and reported nowhere.

### 2. `evidence.merge_branch(subject)` — the one text read the record needs

```python
def merge_branch(subject):
    """The head branch name a merge subject names, or ''. Exactly the group ``_MERGE_SUBJECT``
    already captures — ``Merge pull request #820 from o/<branch>``, ``Merge branch '<branch>'``,
    ``merge-queue: #752 (<branch> @ <sha>)`` — with ``refs/heads/`` and ``origin/`` stripped, and

```

`naming_ids` is refactored to call it for its own merge clause and is otherwise unchanged — the
same branch, read once, in one place. No behaviour of `naming_ids`, `pr_naming_ids` or
`id_evidence` changes: P2's three measurements read the same after this edit as before it.

### 3. `asf/backfill/history.py` — merged history becomes a landing per card

```python
@dataclasses.dataclass(frozen=True)
class Landing:
    """What backfill proved about one card: the merge that carried its work onto the trunk."""
    sha: str          #: the merge commit on the trunk, full
    pr: int = 0       #: the pull request number, 0 when the merge had none
    date: str = ''    #: the merge's committer date, ``YYYY-MM-DD``
    branch: str = ''  #: the head branch the mapping came from
    why: str = ''     #: which rule mapped it — ``legacy_id``, ``legacy_branch``, ``id token``, …
```

```python
def landings(product, items, walk, out=print):
    """``({card: Landing}, [Unmatched])`` over every merge that reaches the trunk.

    ``walk`` is the reader (:mod:`asf.backfill.read`) so this function is pure over facts and
    testable with no git and no host. For each merge, newest first:

    1. its member pull requests, when it is a merge-queue batch (``merge_queue.MERGE_SUBJECT``
       names one per member commit) — each member is then treated as its own merge;
    2. its head branch name: :func:`asf.evidence.merge_branch` over the subject, else the pull
       request's ``headRefName``;
    3. the card: :func:`asf.record.match.match_event` over that branch and the pull request's
       title, with ``prefixes=match.branch_prefixes(product)`` — the record's own rules, in their
       own order (P3); then, only when that found nothing and the product declares one,
       ``conventions.legacy_branch``'s ``slug``/``task`` groups fed back through
       ``match._find_legacy`` (D5);
    4. the newest landing per card wins; every merge that mapped to nothing, or to more than one
       card of the wanted type, becomes an ``Unmatched`` row.

    A merge whose diff is entirely documents or reports is not a landing
    (:func:`asf.evidence.docs_only`, D10): it names its card because a writer wrote it, not
    because the card's work reached the trunk (B-0059)."""
```

The reader, `asf/backfill/read.py`, is the only part that shells out: `git log --merges --first-parent
origin/<trunk>` with no `--since` (P1 is exactly the limit being lifted here), the paginated
pull-request walk of D12, and `git show --name-only` for the paths `docs_only` needs. `--since <rev>`
narrows the walk for a re-run; the default is the whole trunk.

### 4. The typed answer, and the closing rule waking up

`asf/backfill/apply.py`:

```python
def type_landings(root, product, items, found, out=print):
    """Type ``landed: <sha>`` on every Task and Bug in ``found`` that does not already carry it,
    each through :func:`asf.record.setfield.set_typed` under the ``backfill`` writer, with one
    ``## History`` line — ``- <date> backfill: landed → <sha> (PR #<n>, merged <date>)``. Returns
    the count written. Idempotent: a card whose typed ``landed:`` already equals the sha is
    skipped, so a second run writes nothing (D1, D2)."""
```

Nothing else is written to the card. The state, the stage, the `evidence:` lines and the `ingest:`
History line are `asf ingest`'s, at the next record step — which, by P13, is the very next writer.

For that to mean anything, `ingest`'s Task loop (`asf/record/ingest.py:757-766`) gains the one
keyword F-0106's C6 named:

```python
typed_landed = str(typed.get('landed') or '')
# a merged PR is its own green: a plan's Task never waited on CI to close
green = bool(iev.get('green')) if commit else bool(merged) or bool(typed_landed and green_after(typed_landed))
settle(iid, 'task', closing.Ev(commit=commit, green=green, merged_sha=merged, branch=branch,
                               pr_state=pr_state, landed=typed_landed,
                               open_prs=tuple(iev.get('open_prs') or ())), lines)
```

with `green_after = _green_after(ev, product)` hoisted once, as the Bug loop already does, and the
same two lines in the Bug loop. `closing`'s first rule then decides the card by name: its
`evidence:` reads `rule: reconciled` and its History line says so. A Task with no typed `landed:`
derives exactly as it does today — `Ev(landed='')` is falsy and `reconciled` does not fire — which
is what keeps this edit safe for every product that never runs backfill.

The roll-up needs no code at all: a Story whose Tasks are all Closed is `tasks-closed`, a Feature
whose children are all Closed is `children-closed`, and both already require `in_prod`. That is the
card's *"closing rules as today"*, kept literally.

### 5. The `removed: history…` Feature, un-retired on evidence

```python
def unretire(root, product, items, found, out=print):
    """Clear ``removed:`` from every Feature whose ``removed:`` text is a history marker and for
    which backfill proved a landing — the Feature's own ``legacy_id``, or at least one of its
    children (D9). Writes, through ``set_typed``: ``removed: None``, ``unretired: <date>`` and one
    ``## History`` line naming the evidence — ``- <date> backfill: unretired — <n> child
    landing(s), newest <sha> (<date>)``. A Feature with no landing found keeps its ``removed:``
    and goes in the residue table. Returns the ids un-retired."""
```

`removed:` has to be *cleared*, not annotated: P7 is that `is_retired` is what makes `ingest` skip
the card, so anything short of clearing it leaves the Feature hidden. `unretired:` is the durable
marker in the shape `reopen`'s `reopened:` established — a key `ingest` does not derive and
therefore never drops (invariant I1) — so the reversal is on the record forever and a second run
sees it and does nothing.

The derived state then arrives the ordinary way, with dates: the Feature's children carry
`landed: <sha>` from §4, `ingest` derives `children-closed` or `children-resolved`, and the
Feature's `evidence:` says which rule and its History says when. That is the card's *"turn
`removed: history…` Features into their derived landed state with dates instead of hiding them"* —
done by deriving, not by asserting.

### 6. `asf/backfill/prs.py` — one disposition per open pre-ASF pull request

Pure over facts, so the whole table is testable with no git and no host:

```python
#: The disposition of one open pre-ASF pull request. Total: every PR gets exactly one.
ON_TRUNK = 'on_trunk'                   #: its work is already on the trunk → close with evidence
ADOPT = 'adopt'                         #: mapped to a card and merges clean → hand to the lane
REPORT_ONLY = 'report_only'             #: its whole diff is documents or reports → close
CONFLICTING_STALE = 'conflicting_stale'  #: conflicts and its head is older than stale_after → close
RESIDUE = 'residue'                     #: nothing decided it → the operator's table

def disposition(pr):
    """The one disposition of ``pr`` (an :class:`OpenPr` of gathered facts), decided in this
    order — the first that holds wins, and ``RESIDUE`` is the total fallback:

    1. ``on_trunk``: ``already_on_trunk`` says every file it touched is identical on the trunk, or
       ``review.same_code`` says it carries the same own patch over the trunk (P10);
    2. ``report_only``: ``docs_only`` over its paths against the doc dirs and ``reports_dir``
       (P11, D10) — and never for a PR whose paths could not be read;
    3. ``adopt``: a card claims it, that card is open, and ``merges_clean`` is true;
    4. ``conflicting_stale``: ``merges_clean`` is false and its head is older than
       ``conventions.lane.stale_after``;
    5. ``residue``.
    """
```

A lane pull request — one whose head branch's `branch_kind` is a *current* kind, not `'legacy'`, or
one a run already holds — is not in this table at all: the lane owns it.

The two closing dispositions are one call each to the lane's own `close_pr`, with a reason line that
says which rule closed it and names its evidence:

- `on_trunk` — *"Closed by `asf backfill`: this work is already on `<trunk>` (<sha>, merged
  <date>) — every file it touches is identical there."*
- `report_only` — *"Closed by `asf backfill`: its whole diff is documents/reports under
  `<dirs>`; nothing to land."*
- `conflicting_stale` — *"Closed by `asf backfill`: it conflicts with `<trunk>` and its head has
  not moved since <date>. Its card `<id>` goes back to the feeder."*

`adopt` is one call to `Lane.adopt(branch, item, kind)` (P8/D7), after which the branch has a lane
registry row and the next lane pass takes it through review → gate → land like any other. Where the
product declares `legacy_review` and a file matching its glob on that branch carries a verdict its
`verdict_regex` reads as APPROVED, the adoption records that review so the lane does not spend a
fresh review session on work a person already approved (D14); anything other than APPROVED records
nothing.

Nothing in this file merges, gates or pushes to the trunk.

### 7. The command, the table, and `--apply`

`asf/cli.py` registers it beside the other record commands:

```python

```

The table is one code-generated block, printed and written to `backfill/<date>.md` in the record:

```
BACKFILL asf — 412 merges read, 287 open PRs read (no page truncated)

LANDINGS                                                              142
  T-0091  landed 9f2c1ab (PR #418, 2026-03-11)  legacy_id  feature/free-plan-t3
  …
UNRETIRED                                                               9
  F-0007  4 child landing(s), newest 9f2c1ab (2026-03-11)
  …
OPEN PRS                                                              287
  on_trunk           104   close with evidence
  adopt               96   hand to the lane
  report_only          7   close — documents only
  conflicting_stale   36   close — conflicts, head unmoved since <date>
  residue             44   the table below
RESIDUE                                                                44
  PR #523  hotfix-2025-11-02  no card claims it (no id, link or legacy_id)
  F-0044   removed: history…, no landing found for it or any child
  …

```

Without `--apply` the whole pass is read-only: the writers are never called, and
`asf.mutation_guard.active()` is held for the duration so that a mutating `gh` or `git push` refuses
on its own even if a call site forgets to thread the flag — the structural backstop that module
exists for. With `--apply` the card writes go through `stage.guarded(root, 'backfill', …)` (P13), so
an invariant violation refuses that writer's paths and leaves the rest of the record committable.
Every write is idempotent by construction, and the second run's table reads `0` on every line it
already did.
