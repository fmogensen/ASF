# F-0340 — the card is a JSON object, and one schema refuses every other shape

A record card is the factory's only durable memory of an item, and it is read by the kernel, the
feeder, the harvest, the groom, the reviews, the metrics and every session brief. Today that card
is Markdown with a hand-parsed YAML-like header plus machine-relevant values scattered through the
prose: a `stories:` line in a Task's body, a `**Gate**` fenced block, `## Acceptance` checkboxes.

Nothing enforces one shape at the moment of writing, and the harm the card measures all has the
same mechanism: **a value that the writer thought it wrote is not the value the reader reads, and
nobody is told.** Eight ASF cards became unreadable when a multi-line value landed inside a
one-line list and dropped out of the kernel's facts; `asf set writes="a, b"` stored an entry
`a,`; 36 of 38 Tasks carried an empty Acceptance while their tests sat in a body Gate block; one
product's record shows 645 validator errors. None of those is a parser bug. Each is a shape the
parser was never told to refuse.

This spec makes the card one JSON object in one file, declares its fields in one versioned JSON
Schema in the repo, validates that schema at the single door every card write already goes
through, and makes an invalid card loud in three places a person or a session will meet it: the
record's pre-commit, the product's CI, and the kernel's own LIMBO list.

The operator's decision of 2026-10-10 ("we need something solid") is what sets the form: the card
itself is JSON, not Markdown with frontmatter. The card's own title still says *frontmatter*; the
title is the record's and this spec does not rename it (D1).

## Decisions

### Preconditions — measured in this worktree at `55d9ec2f1`, 2026-10-10

The record itself is not on this host, so the four figures the card measured on the live record

### In

1. **One versioned card schema in the repo**: `asf/record/schema/card.2.json`, a JSON Schema over
   a closed keyword subset, naming every field a card may carry, which are required per type, and
   which are written by machine rather than by a person.
2. **A stdlib-only validator**: `asf/record/cardschema.py`, which reads that file and returns one
   finding per violation as `(pointer, message)`. No dependency (P13).
3. **The card as one JSON object per file**: `<folder>/<ID>.json`, prose in a `body` field as an
   array of lines, canonical bytes, exact round trip. `asf/record/card.py` is the one module that
   reads and writes it.
4. **Validation at the one door**: `card.write` / `card.merge` validate before the replace, and
   `asf.record.writer.write_card` refuses a payload that is not a validated card. An invalid card
   never reaches the disk, from any of the 21 modules that write one (P8).
5. **Three gates for every other writer**: `asf check` grows a schema pass (so the record's
   pre-commit `asf check --staged` refuses a hand edit, P11), and `tools/check_cards.sh` runs it
   over every record in this repo from CI.
6. **The kernel lists an invalid card in LIMBO with its schema error** and holds every edge that
   names it, through the `facts.unreadable` channel that already does this for a parse error (P10).
7. **The migration**: `asf record-repair --apply` converts a Markdown card to JSON, moves
   `stories:`, the `**Gate**` block and `## Acceptance` out of the body into fields, splits a
   comma-joined `writes:` entry, and is idempotent. `asf.schema.MIGRATIONS[2]` runs the same pass
   under `asf schema-migrate --drain`, which is how a product's record crosses over (P9).
8. **The readers of the three hoisted fields read the field, and the minters write it**:
   `asf.proves` (9 body readers, 20 call sites in 7 modules), `asf.kernel.dor.gate_lines`,
   `asf.kernel.ports.declared_stories_of`, `asf.record.check`, the two minters that render a
   machine value into prose today (`asf.record.plan_tasks`, `asf.record.ids.write_new_item` — the
   migration is a one-off, these are the ongoing producers), and the four plan-shaped brief
   templates that tell a session to write a Gate block (`plan`, `spec-plan`, `replan`, `reshape`).
9. **One card helper for the corpus**: `tests/cards.py`, and a test that refuses an inline card
   text (P12).

### Out

* **Any other document.** Specs, plans, reviews, briefs, inbox notes, `NOTES.asf.md`, the README
  and the tables stay Markdown. Only a *card* — a file in one of the seven item folders — becomes
  JSON.
* **A card renderer.** No `asf card <id>` that prints a card as Markdown for reading. The `body`
  array keeps a card legible under `cat`, `git diff` and a review (D2), and a renderer is a
  command, a surface row, a test module and a doc section for a convenience nothing in the
  factory reads. It is the obvious follow-on; it is not this Feature.
* **The proof semantics.** Acceptance line numbers stay ordinals, the `## History` proof entry
  keeps its grammar, `asf untick` keeps reversing it, and `Proves:` trailers already on the trunk
  keep meaning what they meant (D8).
* **`## Description`, `## History`, `## Children`, `## Backlinks`.** They stay prose in `body`.
  Children and Backlinks are re-derived from `index.json` every ingest and no reader parses them;
  History is a human audit log whose two machine readings are regexes over dated lines.
* **A kernel reader for `risk`.** The field is in the schema because the card names it (D19); the
  kernel's risk gate keeps reading its settings globs.
* **Running the migration on any product's record.** The command and the migration ship here; the
  operator runs them per product, drained (D5). Nothing in the tick runs them.
* **Removing the Markdown parser.** `asf/record/frontmatter.py` stays as the migration's reader
  (D16), lint-refused for any new import.
* **Validating specs, plans or reviews against a schema.** Different documents, different
  Feature.

### Preconditions the work depends on

1. `asf.record.writer` is the only module that opens a card for writing, and `tools/check_record_writers.sh` holds that line (P7). Every enforcement claim in this spec rests on it.
2. `asf.schema.require` refuses every writing command when the package, the record and the config disagree, and `asf schema-migrate --drain` waits for in-flight sessions, commits each step and stamps every card (P9).
3. `load_items` returns `(by_id, parse_errors)` with each error a `(path, line, why)` tuple, and `asf.kernel.ports.RealRecord.unreadable` turns those into the kernel's LIMBO lines (P10).
4. The record's pre-commit runs `asf check --staged`, and `asf init` writes it (P11).
5. Python 3 stdlib only (P13).
6. The repo carries records of its own to check in CI: `sample/backlog` (10 cards) and the fixture records under `tests/`.

### The choices

| | chosen | against | why |
|---|---|---|---|
| D1 | **The card is one JSON object in one file**, `<folder>/<ID>.json`, and the schema is a JSON Schema over it | The card's own staged wording: Markdown with a strict YAML subset and a round-trip guarantee | The operator's decision of 2026-10-10. It is also the cheaper half of the card: the round-trip guarantee the YAML subset would need is a property `json.loads(json.dumps(x)) == x` already has, while the subset needs the 711-line parser P4 measures, ten lines of which exist only to read back shapes an older writer left. A schema can only be enforced over a form whose text has exactly one reading. The card's title still says *frontmatter*; renaming a card is not a spec's job, so the title stands and this spec's own words are the correction |
| D2 | **Prose lives in a `body` field, an array of lines** | One string with `\n` escapes; a sibling `<ID>.md` next to the JSON | The array gives `git diff` one line per prose line, which is the whole reason a record is in git; a single escaped string makes every prose change one enormous diff line. A sibling file is two writes where P7 guarantees one, and two truths about one card. `'\n'.join(lines)` ↔ `text.split('\n')` is exact, trailing blank line included, so `rec['body']` keeps its current value for all 34 reading modules (P8) |
| D3 | **The object is closed**: `additionalProperties: false`, every field enumerated, plus a test that walks the writers and refuses a field the schema does not name | An open object with the known fields typed | P2 is the measured harm: `write:` instead of `writes:` parses, reads as nothing, and no gate anywhere has an opinion. An open schema cannot refuse that, which leaves the card's central claim unmet. The cost is one schema line per new field, paid by the person adding it, and named by a test before CI names it |
| D4 | **The card schema is versioned by the record's own `schema_version`**, and the cutover is `SCHEMA_VERSION = 2` with `MIGRATIONS[2]` | A separate card-schema counter inside the card | Three numbers already have to agree before anything writes, and `require` already prints `NEEDS OPERATOR: run asf schema-migrate` and exits 3 when they do not (P9). A second counter is a second drain contract, a second mismatch message and a second thing to forget. The schema file is named for the version it belongs to (`card.2.json`), so a later version is a new file and a `MIGRATIONS[3]` |
| D5 | **`asf record-repair --apply` is the migration**, and `MIGRATIONS[2]` calls the same function | Two passes: a schema migration and a separate repair | The card names `record-repair` as the migration and the operator is the one who runs it per product; `schema-migrate` is the gate that makes it unskippable. One pass behind two doors, so a record cannot cross over half-migrated. `record-repair` also gains the surface row it lacks today (P13) |
| D6 | **Which fields are machine-written is stated by the schema** (`"x-asf-machine": true` per property), and `card.split_machine` reads it | Keep the `# ---- machine ----` marker's successor: a nested `machine: {}` object in the card | Flat fields keep every `meta.get('state')` reader working unchanged across 34 modules (P8), and nesting would rewrite all of them for nothing. Whether a field is a person's or the factory's is a fact about the field, which belongs in the one place that declares fields — not in a marker line in each of thousands of files that a hand edit can move, which is what decides it today |
| D7 | **Three body fields are hoisted: `stories`, `gate`, `acceptance`** | Hoist everything the body carries, including Description, History, Children and Backlinks | The measured harm is exactly in those three (P5: tests in a Gate block beside an empty Acceptance; the `stories:` line). The other four are prose a person reads: two are re-derived every ingest and parsed by nobody, and History is an audit log read only by two regexes over dated lines. Hoisting them would add hundreds of lines of migration for no measured defect |
| D8 | **`acceptance` is an ordered array of `{line, test, proved, deferred}`, and "acceptance line N" is its Nth entry** | Key the entries by their text, or give each one an id | Every `Proves:` trailer on the trunk, every `proved line <n>` entry in a card's History and `asf untick <id> <n>` already mean the ordinal. Keying by text would turn a typo fix into an unprove; an id would need a minting rule and would make every trailer already landed unreadable. `line` keeps the card's own name for the sentence; the ordinal is its position |
| D9 | **`gate` is an array of command strings** | `[{command, cwd, …}]` | `dor.gate_lines` returns stripped lines and `test_refs` parses test paths out of them; nothing in the factory reads more than the line. A richer shape would be schema nobody validates against behaviour |
| D10 | **Canonical bytes**: `json.dumps(indent=2, ensure_ascii=False)` plus a trailing newline, fields in the schema's own property order | `sort_keys=True`; compact separators; whatever order the writer's dict happened to have | Two writers producing the same fields must produce the same bytes, or every diff carries noise and `asf check`'s "the card the record would write equals the card on disk" stops being a byte comparison. Schema order rather than alphabetical because `id`, `type`, `title` first is how a person reads a card. `ensure_ascii=False` because `asf redact` and `grep` must see the real characters — a protected name escaped to `é` would walk straight through the redaction gate |
| D11 | **A card carries no comments.** The migration prints every comment it drops and moves its text into the body | Invent a `_comment` field, or a `comments` map keyed by field | JSON has no comments, and a convention for them is a second grammar for the thing this Feature exists to make single. A remark about an item belongs in its prose, where a person reads it. Printing each dropped comment is what keeps the migration honest: nothing vanishes silently, which is the defect class this whole card is about |
| D12 | **The validation is in `card.write` / `card.merge`, and `writer.write_card` refuses an unvalidated payload** | A validate call at each of the 21 writing modules; a pre-write hook; validate on read only | P7 is the gift this design is built on: there is already exactly one door, held by a lint. One check at that door cannot be forgotten by the 22nd writer. Validating only on read is what the record does today in effect — the bad value is already on disk and already in git by then |
| D13 | **A refusal is an exception, `CardInvalid(path, findings)`** — the console commands print it and exit 2, the tick's writers let it reach the step's own refusal path | Print and `sys.exit` inside the writer; write the card and report | A writer deep inside a tick step must not take the process down, and `stage.guarded` already exists to turn a refused write into a named, staged non-change. An exception is also what a test can assert on without a subprocess |
| D14 | **A schema-invalid card is a `load_items` parse error**, so it is `facts.unreadable`, so it is a LIMBO line, so every edge naming it holds | A fourth channel in `Facts` for invalid-but-parseable cards | The kernel's own definition of unreadable is "on the record, yet absent from `items()`", and an invalid card is exactly that: it is not loaded, so nothing may silently decide over a half-read version of it. The line it prints is the one the card asks for, with the first finding as the reason, capped at 120 characters by `ports.RealRecord.unreadable` (`asf/kernel/ports.py:329`; P10) |
| D15 | **Three gates, no fourth**: the record's pre-commit (`asf check --staged`), the host's own `asf check` each tick, and this repo's CI over the records it carries (`tools/check_cards.sh`) | A GitHub workflow written into each record repository | A record repo in this factory has no runner of its own, and `asf` is not installed in one. The pre-commit is what a hand edit actually meets, the tick's check is what a session's write meets, and the in-repo records are what a *code* change can break — which is the only one of the three that CI can see |
| D16 | **The Markdown parser survives as the migration's reader**, with every other import lint-refused | Delete it with the cutover; keep it as a fallback reader forever | A forever fallback means two readings of a card, which is the defect. Deleting it means a record below schema 2 can never be migrated — and `stamp_cards` has to read Markdown cards on the way from 0 to 2 (design §7). So: it reads, it never decides, and `tools/check_record_writers.sh` grows the rule that only `card.py` and `repair.py` may import it |
| D17 | **A `.md` file in an item folder on a schema-2 record is a finding and a LIMBO line** | Ignore it; or load it | On a migrated record such a file is either an unmigrated card or a stray document, and both are things a person must see. Ignoring it is how eight cards went invisible |
| D18 | **The corpus builds cards through one helper**, `tests/cards.py`, and a test refuses an inline card text | Convert the 57 modules' literals to JSON literals and leave it there | The literals are the reason a schema change costs 57 modules (P12). One helper makes the next schema change cost one file, and the test is what keeps it that way. The three local helpers (P12) collapse into it |

## The design

Nine pieces. One new schema file, two new modules, one new shell check, one new test helper; every
other change is a redirect of an existing reader or writer onto the new door.

### 1. `asf/record/schema/card.2.json` — the schema

One JSON Schema document, named for the record schema version it belongs to (D4). It is data, not
code: it ships inside the package (`[tool.setuptools]` already includes the `asf` package; the
file is added to package data so an installed `asf` can read it) and `tests/test_card_schema.py`
validates it.

```json
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "$id": "asf/record/schema/card.2.json",
  "title": "ASF record card, record schema 2",
  "type": "object",
  "additionalProperties": false,
  "required": ["schema_version", "id", "type", "title", "state", "body"],
  "properties": {
```

Four things the excerpt above shows and the implementing Task completes:

* **`"$defs/path"` is where P3 dies.** A `writes:` or `creates:` entry matches `^[^\s,]+$`: one
  path, no comma, no whitespace. `asf set writes="a, b"` is then refused at the write with
  `/writes/0: "a," does not match ^[^\s,]+$` instead of storing a path named `a,`.
* **`x-asf-machine`** marks a property as the factory's rather than a person's (D6). It is an
  annotation: the validator ignores it, `card.split_machine` reads it, and `protected_fields`
  keeps scanning exactly the properties that lack it.
* **`state` and `priority` are the *record's* vocabularies, not the kernel's.** A card stores
  one of four states — `New`, `Active`, `Resolved`, `Closed` (`asf/evidence/closing.py:53`, whose
  `_DONE = (RESOLVED, CLOSED)` is the `('Resolved', 'Closed')` tuple repeated in 17 modules, 9 of
  them as their own `DONE_STATES`). `Ready`, `Review`, `Landing`, `Building`, `Done`, `Stuck` and
  `Parked` are `asf.kernel.model.State` (`asf/kernel/model.py:16-40`) — derived every tick from the record and
  never written onto a card, so a closed object (D3) that named them would refuse nothing and
  admit a value no writer may store. The three the schema adds beyond the four — `Rejected`,
  `Cancelled`, `Superseded` — are the ones `asf/release_preview.py:48` already tolerates in a
  card's `state`. `priority` is `need`, `nice`, `later` (`asf/record/new.py:100-101`, and
  `sample/backlog/features/F-0001.md:6`, `F-0002.md:6`, `epics/E-0001.md:5` carry `need`/`nice`),
  not the `now`/`next` of a roadmap: an enum that missed them would refuse three of the ten cards
  the sixth acceptance block migrates. Both enums are declared once here and read by
  `asf.record.check` and `asf.record.new` instead of their own literals, so the record cannot grow
  a fifth state in one module and not another.
* **The property list is complete, and a test proves it.** The enumeration is derived from the
  four declaration sites P6 measures (`new.SETTABLE` per type, `ports.KERNEL_KEYS`,
  `frontmatter.DERIVABLE_KEYS`, `new.BOOL_FIELDS`), plus the fields those sites do not declare but
  every card carries (`id`, `type`, `title`, `feature`, `created`, `updated`, `stage`,
  `stage_since`, `signature`, `removed`, `evidence`, `landing`, `blocked`, `blocked_by_open`,
  `links`, `delivers`, `delivered_by`, `cost`, `spend_usd`, `count`, `children`, `backlinks`),
  plus the per-type ones (`severity`, `lane`, `size`, `ab_pair`, `reshape_applied`, `scope`,
  `enforced`, `reason`, `check`, `supersedes`, `superseded_by`, `decided_by`, `date`, `area`,
  `legacy_id`, `local_only`, `blockedBy`). `tests/test_card_schema.py` walks those sites and the
  `card.merge` call sites and fails naming any field the schema does not declare — so the list is
  checked by a test rather than by a reviewer's memory.

### 2. `asf/record/cardschema.py` — the validator

Stdlib only (P13), about 200 lines, no network and no `$ref` outside the document.

```python
#: The only keywords the validator enforces. A schema using any other keyword is refused by
#: `check_schema`, so a keyword the validator would silently ignore can never enter the schema.
KEYWORDS = frozenset({
    'type', 'const', 'enum', 'pattern', 'minLength', 'minItems', 'maxItems', 'uniqueItems',
    'properties', 'required', 'additionalProperties', 'items', 'allOf', 'if', 'then',
    '$ref', '$defs', '$schema', '$id', 'title', 'description',
})

class Finding(typing.NamedTuple):
    pointer: str   # a JSON Pointer into the document: '', '/writes/0', '/acceptance/2/line'
    message: str   # 'is not one of New, Active, …', 'does not match ^[^\\s,]+$',
                   # 'line is required' — a required field's message names the field, because the
                   # pointer is the object that lacks it, not the absent field (§5)
    line: int = 0  # the source line, for a finding that has one: a JSON syntax error's `lineno`.
                   # 0 for a schema finding — `validate` is pure over a parsed object and has no
                   # text to count lines in, and the pointer is that finding's place. It is a
                   # field so `load_items` can fill its (path, line, why) tuple (§6, P10)
    def __str__(self): return f'{self.pointer or "/"}: {self.message}'

def load(version): ...        # the parsed schema for a record schema version (cached)
def check_schema(schema): ...  # [Finding] for a schema that uses a keyword outside KEYWORDS
def validate(doc, schema=None): ...  # [Finding], in document order, for one card object
def pointer_line(text, pointer): ...  # the 1-based line a pointer names in canonical card text,
                                      # or the deepest prefix of it reached; 1 for none (§5).
                                      # For reporting only: no check decides from it
```

The annotation keywords (`x-asf-machine` and anything else prefixed `x-`) are allowed and
ignored. `validate` is pure: it takes a parsed object and returns findings, so it is testable with
no filesystem and callable from the kernel, from `asf check` and from the writer.

### 3. `asf/record/card.py` — the one card document

```python
SUFFIX = '.json'
DERIVABLE_FIELDS = ('stage', 'evidence', 'blocked', 'blocked_by_open', 'landing')

class CardInvalid(Exception):
    """A card that does not validate. Carries ``path`` and ``findings``."""

def loads(text, path=None): ...          # (fields, body) — validates; raises CardInvalid
def dumps(fields, body): ...             # the canonical text (D10); validates first
def read(path): ...                      # (fields, body)
def write(path, fields, body): ...       # one os.replace, through asf.record.writer
def merge(path, updates, drop=()): ...   # read, update the named fields, write; True when changed
def split_machine(fields): ...           # (authored, machine) off the schema's x-asf-machine (D6)
```

* `fields` is a plain `dict`; `body` is the prose as one string, as every reader has it today
  (D2). `loads` joins the `body` array with `\n`; `dumps` splits on `\n`. There is no
  `FrontmatterDict`, no `entries`, no `machine_keys`, no `comments`, no `lenient`: a card has one
  reading, so there is nothing to remember about how it was written.
* `dumps` orders the fields by the schema's property order and emits
  `json.dumps(ordered, indent=2, ensure_ascii=False) + '\n'` (D10). `loads(dumps(f, b)) == (f, b)`
  and `dumps(*loads(t)) == t` for every card the schema accepts — both are acceptance lines.
* `merge` replaces `frontmatter.write_machine`, `merge_machine` and `write_typed` (12 call sites,
  P8). Its `order=` argument disappears: field order is the schema's, so there is nothing for a
  caller to say. `drop=` keeps the I1 rule — only a derivable field may be dropped, anything else
  raises `ValueError` — because that rule is about what a writer may forget, not about Markdown.
* A JSON syntax error becomes `CardInvalid` with one finding `'/': line 7 column 3: Expecting
  ","'`, taken from `json.JSONDecodeError`'s own `lineno`/`colno`, so a hand edit is told where.
  That finding's `line` is the `lineno` — the one place a finding has a line to carry, and what
  §6 hands `load_items` for its `(path, line, why)` tuple. A schema finding leaves `line` 0 and
  points with its pointer.

### 4. Every write goes through the one door

`asf.record.writer` keeps its atomic replace and gains the refusal:

```python
def write_card(path, fields, body):
    """A card's fields and prose at ``path``, atomically. Refuses an invalid card (F-0340)."""
    text = card.dumps(fields, body)      # raises CardInvalid before anything is written
    write_text(path, text)
```

`write_text` and `write_bytes` keep their current shape for the things that are not cards (a
staged copy, a restored card's bytes). `tools/check_record_writers.sh` grows two rules:

* only `asf/record/card.py` may call `writer.write_text` with a card path;
* only `asf/record/card.py` and `asf/record/repair.py` may import `asf.record.frontmatter` (D16).

The 21 writing modules (P8) change mechanically: `frontmatter.merge_machine(path, upd, order=…)`
and `frontmatter.write_typed(path, upd)` both become `card.merge(path, upd)`; the
`frontmatter.render(meta, body)` call sites (28, across 18 modules) become `card.dumps`. Nothing
in them gains a validation call — that is the point of D12.

### 5. `asf check`, the pre-commit and the CI check

`asf.record.check` grows one pass, `check_schema_findings`, that runs before every other check:
one finding per `cardschema.Finding` per card, as

```
stories/S-0003.json:9: S-0003: /acceptance/0: line is required
```

The pointer is the finding's own place: a missing field is one finding on the object that lacks it,
never on a field that is not there (§2). The line number is **not** the finding's `line` — a schema
finding's is 0, because `validate` is pure over a parsed object and has no text to count lines in
(§2). `check_schema_findings` resolves it from the text it just read, with
`cardschema.pointer_line(text, pointer)`:

* It walks the card's lines once, keeping the path each line is at — the key a line opens, read as
  `"<key>":`, pushed at that line's indentation, popped when the indentation falls back; an array
  element's index counted from its position under its key. Canonical bytes (D10) are what make
  that a line walk rather than a parse: `indent=2`, one member per line, so a line's depth is its
  indentation over two.
* It returns the 1-based line of the deepest prefix of the pointer it reached — so a pointer to a
  field that is not there resolves to the line of the object that should carry it, which is the
  line a person needs for `line is required`.
* It returns 1 when it reaches nothing, and for a file whose bytes are not canonical (a hand
  edit, which is exactly the writer these gates exist for) the same walk still resolves whatever
  prefix it can: the number is a place to look, never a fact the check depends on.

A finding whose `line` is non-zero — a JSON syntax error, which has no pointer to resolve — keeps
its own. This is the one place in the design that maps a pointer onto text; nothing decides
anything from the number.

The pass needs no new flag: `asf check` runs it over the whole record, and `asf check --staged`
(the record's pre-commit, P11) already judges the commit by what it stages, so a hand-edited card
that does not validate refuses the commit where it sits. `cmd_check_staged`'s existing
HEAD-versus-staged comparison keeps working unchanged: a schema finding is a finding like any
other.

A card that does not validate is **not loaded** (design §6), so every other check sees it as
absent rather than as half-read. A `.md` file in an item folder is its own finding (D17):

```
tasks/T-0123.md: a Markdown card on a schema 2 record — run asf schema-migrate
```

`tools/check_cards.sh` is the CI gate (D15): it runs the schema pass over every record directory
in the repo (`sample/backlog` and the fixture records), with no product config and no host state,
and prints `check_cards: ok` or one line per finding. It is wired into `.github/workflows/tests.yml`
beside the record-writer lint, in the `checks` job and in the docs-only fast path.

### 7. The migration — `asf record-repair --apply` and `MIGRATIONS[2]`

`asf/record/repair.py` keeps its shape (dry run by default, `--apply` writes, idempotent, one
record commit through `_published`) and its pass becomes the conversion:

1. **Read** `<folder>/<ID>.md` with `frontmatter.parse` — the one surviving use of the legacy
   reader (D16).
2. **Hoist the three body fields** (D7), each removed from the prose as it moves:
   * a Task's `stories:` line, by `plan_tasks.STORIES_LINE_RE`, into `stories`;
   * the `**Gate**` fenced block, by `dor.gate_lines`, into `gate`;
   * the `## Acceptance` bullets, by `proves.bullets`, into `acceptance` — one entry per bullet in
     order, `line` the bullet's text with the checkbox stripped, `proved` from `- [x]`, `test`
     from the first test reference in the text (`dor.test_refs`), `deferred` from the bullet's
     `deferred by D-…` marker if it carries one (`proves.deferred_lines`).
3. **Normalise the values P3 and P4 produced**: a `writes:`/`creates:`/`after:`/`stories:` entry
   carrying a comma or whitespace is split into the entries it names; a value carrying a raw
   newline keeps it, since a JSON string may hold one.
4. **Print what it drops**: every `#` comment in the header, with its field and the card, so
   nothing vanishes silently (D11), and append each comment's text to the body's `## History` as
   `- <date> record-repair: dropped comment on <field> — <text>`.
5. **Validate**, then **write** `<folder>/<ID>.json` through `card.write` and delete the `.md` with
   `git rm` semantics (the console command stages and commits; the migration leaves the deletion
   to `shadow.commit_local`).
6. **Report**: one line per card, and a count line. A card that cannot be made valid is named with
   its findings and left as `.md`, which D17 then makes loud on every subsequent check — a
   migration that silently skipped it would be the defect this Feature exists to remove.

`asf.schema` then gains:

```python
    """1 → 2: every card becomes one JSON object validated against card.2.json (F-0340)."""

```

and `stamp_cards` is routed by the file it finds: `card.merge` for a `.json` card,
`frontmatter.merge_machine` for a `.md` one — needed because a record at 0 reaches 2 through
`_migrate_to_1`, whose stamp runs while the cards are still Markdown.

`record-repair` also gains its surface row (P13), with the words of the migration it now is:
`('convert every card to the current schema and move machine values out of its prose', RECORD, '--apply')`.

### What it looks like when it is there

A Task card, whole:

```json
{
  "schema_version": 2,
  "id": "T-0001",
  "type": "task",
  "title": "Split on whitespace",
  "parent": "S-0001",
  "feature": "F-0001",
  "rank": 1,
  "writes": ["src/count.py", "tests/test_count.py"],
  "stories": ["S-0001"],
  "gate": ["python3 -m unittest -q tests.test_count"],
  "state": "New",
  "stage_since": "2026-01-01T09:00:00Z",
  "updated": "2026-01-01T09:00:00Z",
  "body": [
    "## Description",
    "Replace the byte count with a whitespace split.",
    "",
    "## History",
    "- 2026-01-01: created",
    "",
    "## Children",
    "",
    "## Backlinks"
  ]
}
```

* A person hand-edits it and mistypes `write:`; the pre-commit refuses the commit with
  `tasks/T-0001.json:8: T-0001: /write: is not a declared field`.
* A session runs `asf set writes="a, b"`; the command refuses before the card is opened, with
  `/writes/0: "a," does not match ^[^\s,]+$`.
* Something writes a card the schema refuses anyway — a bug in a tick step, a field a release
  forgot to declare; `card.write` raises, the step stages the refusal, the card on disk is the one
  that was there, and the next `asf check` says nothing because nothing changed.
* A card arrives invalid some other way — restored from a branch, written by a tool that is not
  `asf`; `asf check` names it, CI names it for the records in this repo, and the kernel prints
  `  limbo T-0123: card unreadable, invisible to the kernel: …` every tick while every item that
  waits on it holds.
* An operator moves a product's record across with `asf schema-migrate --drain`: the in-flight
  sessions drain, each card becomes JSON, `index.json` is stamped 2, each step is its own commit,
  and the pass is idempotent, so running it twice writes nothing the second time.

## Stories

Eight Stories, one per section of `## The design` (§1 and §2 are one Story: a schema nothing
validates and a validator with no schema are each half a thing). Each is **declared** below as a
`### S-…: <title>` heading with its acceptance lines under it, with ids from this session's range
`S:122705-122754` — that heading is what `asf.record.idcheck.declared_stories` reads and what
`asf.record.plan_tasks` mints the card from, so a cited id with no declaration is a phantom and
the plan citing it is refused whole.

Each acceptance line is one physical line of plain text with no backticks, on purpose: the reader
is line-anchored (`asf.record.idcheck.CHECKBOX` matches a single line) and `_prose` replaces every
inline code span with one space before parsing, so a wrapped line reaches the minted card
truncated and an identifier inside backticks reaches it missing.

Nothing below is true on the trunk today — P1 through P13 measure the opposite — except the lines
that say an existing behaviour is unchanged, which are the facts this change relies on rather than
adds.

### S-122705: the versioned card schema and a stdlib validator over a closed keyword set

Design §1 and §2 (D3, D4, D6, D19; P6, P13). Acceptance is the first block of
`## Acceptance tests`. One schema file, named for the record schema version; one validator that
enforces a closed keyword set and refuses a schema that uses anything outside it.

- [ ] the schema file parses as JSON and is itself validated by the validator's schema check
- [ ] the schema declares every field name the four declaration sites name, and the test fails naming any it does not
- [ ] the schema declares every field name the card writers write, and the test fails naming any it does not
- [ ] the schema is a closed object: a field it does not declare is a finding on the card that carries it
- [ ] a schema using a keyword the validator does not enforce is refused by the schema check, naming the keyword
- [ ] an annotation keyword prefixed x- is allowed by the schema check and ignored by the validator
- [ ] the validator imports nothing outside the Python standard library
- [ ] a finding carries a JSON Pointer to the value it is about and a message that names the rule
- [ ] findings come back in document order, and a card with no findings validates as valid
- [ ] a required field missing is one finding on the object, not on the field
- [ ] a Task without a writes footprint is a finding, and a Task with one is not
- [ ] a Story without an acceptance entry is a finding, and a Story with one is not
- [ ] a writes entry carrying a comma is a finding naming the pattern it fails
- [ ] a state outside the record's four states is a finding naming the values allowed, and a kernel-derived state such as Ready or Done is one of them
- [ ] a priority outside need, nice and later is a finding, and each of the three is accepted
- [ ] the state and priority vocabularies are declared only in the schema, and no other module carries its own literal list of them
- [ ] an id that does not match the record id grammar is a finding
- [ ] the risk field is accepted on any card and required on none

### S-122706: the card is one JSON object with its prose in body lines, canonical bytes, exact round trip

Design §3 (D1, D2, D10; P1, P4). Acceptance is the second block. The module that reads and writes
a card, and the two guarantees that make a schema enforceable: one reading of the text, and one
text per set of fields.

- [ ] a card file is one JSON object whose prose is an array of body lines
- [ ] reading a card gives the prose as one string, joined on newlines, as every reader has it today
- [ ] writing then reading a card returns the same fields and the same prose, trailing blank line included
- [ ] reading then writing a card returns the same bytes
- [ ] two writers giving the same fields in different dict order produce the same bytes
- [ ] the fields are written in the schema's own property order, not alphabetically and not in insertion order
- [ ] the text ends with exactly one newline
- [ ] a non-ASCII character is written as itself, not as an escape, so the redaction scan reads it
- [ ] a value carrying a newline round-trips exactly and never spills into another field
- [ ] a card with invalid JSON syntax raises the card refusal carrying the line and column of the syntax error
- [ ] a card that parses but does not validate raises the card refusal carrying every finding
- [ ] the machine fields of a card are the properties the schema marks as machine-written, and the authored fields are the rest
- [ ] merging fields into a card rewrites only those fields and leaves every other byte as it was
- [ ] merging may drop only a derivable field, and dropping any other field raises
- [ ] merging a field to the value it already has writes nothing and reports no change

### S-122707: every card write is validated at the one door, and an invalid card never reaches the disk

Design §4 (D12, D13; P7, P8). Acceptance is the third block. The lint already makes one module the
only writer of a card; this is the check at that door and the proof that no writer can get past it.

- [ ] writing a card that does not validate raises the card refusal and leaves no file behind
- [ ] writing a card that does not validate over an existing card leaves the existing bytes untouched
- [ ] the refusal carries the card's path and every finding, so a caller can print them without re-validating
- [ ] every module that writes a card goes through the one writer, and the lint refuses a second writer
- [ ] no module but the card module and the migration imports the legacy Markdown parser, and the lint refuses one that does
- [ ] setting a field through the typed-field command on a value the schema refuses fails before the card is opened
- [ ] a tick writer whose card is refused leaves the card as it was and reports the refusal rather than exiting
- [ ] minting a new card writes a card that validates, for every item type the record mints
- [ ] a card written by the kernel's record port validates
- [ ] a card written by the groom from an inbox note validates
- [ ] the index rewrite and the ingest derive write cards that validate

### S-122708: an invalid card refuses the commit and refuses the pull request

Design §5 (D15, D17; P11). Acceptance is the fourth block. Two gates that catch a writer the door
cannot: a person editing a card by hand, and a code change that breaks the records in this repo.

- [ ] the record check names every invalid card, one finding per violation, with the card's path and its id
- [ ] a finding names the field it is about by pointer, and the reported line is the one that pointer resolves to in the card's own text — the object's line for a field that is not there, and 1 rather than an error for a pointer into nothing
- [ ] the staged mode refuses a commit that stages an invalid card
- [ ] the staged mode does not refuse a commit for an invalid card the commit does not touch, and still warns about it
- [ ] a Markdown card in an item folder on a migrated record is its own finding naming the migration command
- [ ] the shell check validates every record carried in this repo and exits non-zero on a finding
- [ ] the shell check runs with no product config, no host state and no network
- [ ] the shell check is wired into the workflow beside the record-writer lint
- [ ] an invalid card is absent from the loaded record, so no other check reports a second finding about its missing values

### S-122709: the kernel lists an invalid card in LIMBO with its schema error and holds what waits on it

Design §6 (D14; P10). Acceptance is the fifth block. The kernel already has the channel; what is
new is that a schema-invalid card enters it, with the schema error as its reason.

- [ ] a card that does not validate is reported by the record loader as an error and is not loaded
- [ ] the kernel's unreadable map carries that card's id with its schema finding as the reason
- [ ] the tick's LIMBO list names the card, and the reason carries the pointer and the rule it failed
- [ ] the reason is capped at 120 characters by the record port and still names the card's path
- [ ] an item whose after edge names an invalid card waits, and the wait names the invalid card
- [ ] an invalid card is never in the kernel's items, so no state is decided from its values
- [ ] an invalid card's open pull requests are not closed as orphans
- [ ] the count on the tick line includes the invalid card
- [ ] a record with no invalid card prints no LIMBO line for this reason

- [ ] an Acceptance line deferred by a decision carries that decision in its entry

### S-122711: every reader of a hoisted value reads the field, and every minter writes it
