# F-0340 — One enforced card schema: the card is JSON, validated on every write, invalid cards visible

Epic E-0002 (ASF 0.2 — self-improvement). A card is markdown with a hand-parsed YAML-like
frontmatter (`asf/record/frontmatter.py`, 711 lines of parser) plus machine-relevant fields left
in the prose body — the test a Task is judged by, the commands its Gate runs, the Stories it
covers. Nothing refuses a bad card at the moment it is written, so a malformed one lands and is
found later, by hand, in the record: 8 ASF cards became unreadable and silently dropped out of
the kernel's facts, `asf set writes="a, b"` stored `"a,"` as an entry, 36 of 38 Tasks had an empty
Acceptance while their tests sat in a body `**Gate**` block.

The operator's decision of 2026-10-10 ("we need something solid") settles the format: **the card
itself is JSON**, one file per card, validated against a versioned JSON Schema on every write;
prose lives in string fields; humans read a generated view. And a second decision the same day
settles what the schema is for beyond shape — **referential integrity**: every reference field
resolves to a card that exists, retiring or superseding a card resolves its incoming edges in the
same record commit, and a reference the kernel cannot resolve is LIMBO with the reason, never a
silent park.

This spec takes both decisions whole and stages them into ten Stories. The order is not
arbitrary: the schema and the one write gate come first, because they are what stops the next bad
card; the JSON format and the migration come after, because converting 2 298 cards is only safe
once a validator can judge the result; referential integrity comes last, because it is a check
over the whole record and needs the typed reference fields the format gives it.

Three things these numbers say, and they are what the ten Stories answer:

1. **Nothing refuses a bad card at write time.** Today's zeros for split values and malformed list
   entries are not a healthy format — they are two repairs that already ran (`asf record-repair`
   for the split values, `B-121288` for `writes="a, b"`). Both classes were found *after* they
   landed, in the record, by a person. The 60 keys have no declared types, and two of them are
   written as two different types on different cards.
2. **The fields the kernel judges a Task by are in the prose for most Tasks.** 539 of 622 open
   Tasks have no acceptance line a reader can find; 158 keep their tests in a `**Gate**` block
   that one regex in `asf/kernel/dor.py` reads and nothing validates. The Definition of Ready
   reads both shapes and still finds nothing on 87% of them.
3. **The reference graph is the stuck-card engine.** 702 edges point at a retired card and 3 point
   at nothing at all. Some of that is already absorbed downstream (an `after:` onto a retired card
   reads as Done — F-0336), which is exactly the problem: the record stays wrong and each reader
   compensates in its own way. Nothing resolves the edge where it is written.

### 1.2 In scope

- One versioned card schema as a **JSON Schema file in the package**, with a stdlib-only
  validator for the subset it uses, and a test that validates the schema itself.
- **One card API** (`asf/record/card.py`): the only place a card is read, written, validated or
  rendered. Every reference to a card path goes through it.
- **The write gate**: `asf.record.writer.write_card` — the one card write, with 25 call sites and
  a lint that keeps it the only one — refuses a card that does not validate, naming the schema
  error, and writes nothing.
- **The card as JSON**: `<folder>/<id>.json` is the source of truth; `<folder>/<id>.md` beside it
  is a generated view, derived like `index.json` and parsed by nothing.
- **Machine fields out of the body**: typed `acceptance` and `gate` fields, written by the mint
  and groom-fill paths and read by the Definition of Ready and the `Proves:` gate.
- **Referential integrity at write**: a reference that resolves to no card is refused by the card
  API, by `asf check`, by the record pre-commit and by CI.
- **One operation** that closes, retires, supersedes or deletes a card and resolves its incoming
  edges in the same record commit.
- **The kernel**: an invalid card and an unresolvable reference are LIMBO with the schema error,
  never a silent drop and never a park.
- **The migration**: record schema version 2 — every card converted with a round-trip check, both
  copies of the record, `sample/backlog/**` with them; `asf record-repair --apply` is the same
  conversion over a record root given by path, for a dry run on a copy.
- **`asf show <id>`**: the card rendered for a person, from the JSON.

### 1.3 Out of scope

- **The prose's wording.** `description`, `history` and the other sections keep their text; the
  schema types them as strings and a list of strings, and judges nothing about what they say.
- **The documents under `docs/`.** A spec, a plan and a review are markdown written for a reader
  and for the record's own graders; they are not cards and get no schema.
- **Any new state machine.** States, stages, the Definition of Ready, the LIMBO rules and the
  landing gate are unchanged. The card's *format* and *validation* change, and one LIMBO reason
  is added.
- **Retiring any other `asf check` finding.** The 420 protected-name findings and the Active-Task
  overlap findings stay as they are.
- **A third-party JSON Schema library.** `pyproject.toml` declares `dependencies = []` and that
  stays true (D2).
- **Rewriting the record's git history.** The `.md` cards remain in history; the migration is one
  ordinary signed commit.
- **A stable per-line identity for an acceptance line.** `line <n>` stays the 1-based ordinal the
  `Proves:` trailer already counts (D7).
- **Changing which keys the kernel reads.** `asf/kernel/ports.py:item_from_card` reads the same
  fields afterwards; only `acceptance` and `gate` are added.

### 1.5 The choices

| # | chosen | against | why |
| --- | --- | --- | --- |
| D1 | **The card is one JSON file**, with a generated `.md` view beside it | markdown with a strict frontmatter (the card's own first plan); JSON with no view at all | The operator's decision of 2026-10-10 settles the first half: a strict subset of a YAML-like format is still a parser we own, and 711 lines of it is where the 8 unreadable cards came from. `json.loads` is the stdlib's, total and round-trippable. The view is kept because the record is a git repository a person reads: every card diff in every record commit, every PR, every review session reads cards as text, and GitHub renders markdown. A derived, unparsed `.md` costs one more file per card and buys back the whole human surface — and it makes the migration non-destructive (the `.md` that was the card becomes the view of the card). |
| D2 | the schema is a **JSON Schema file** validated by a **stdlib validator we own**, over the subset the schema uses (`type`, `enum`, `const`, `required`, `properties`, `additionalProperties`, `items`, `pattern`, `minimum`, `minItems`, `oneOf` for a nullable) | `jsonschema` from PyPI; a schema expressed in Python (a dict of validators) | `pyproject.toml` declares `dependencies = []` and the install is `pipx install` with no network beyond the repo — a dependency would change the install contract. A *file* rather than Python is what the card asks for and what makes the schema quotable in a brief, diffable in a PR and readable by a session that is not running `asf`. The subset is small and closed; `tests/test_card_schema.py` validates the schema file against itself and refuses a keyword the validator does not implement — so a schema can never claim more than the validator enforces. |
| D3 | the schema is **closed** (`additionalProperties: false`), and a product's own keys live under one declared `extra` object | an open schema; a per-product schema | A schema that accepts any key cannot catch a typo, which is half the class. The 60 keys of §1.1 are ASF's own vocabulary and are named in the schema with their types; `extra` is a flat map of scalars for a key ASF's code does not read, and `asf check` reports anything in it as a *warning*, so a product keeps its field and still gets a closed schema. |
| D4 | **typed vs machine is a property of the schema**, not of the file: the flat JSON object carries every key, and each property declares `"owner": "machine"` or nothing | keeping the two-part layout (`{"card": …, "machine": …}`) as the `# ---- machine ----` marker did | A flat object keeps `meta.get('title')`, `meta['writes']` and the hundreds of readers that index `meta` working unchanged, with `card.split_machine` reading the schema where `frontmatter.split_machine` read the marker. It also fixes a measured bug: `reshape_applied` is typed on 30 cards and machine on 1 (§1.1), because the marker's position decided — so the same key is scanned for protected names on 30 cards and skipped on 1. With the owner in the schema that cannot happen. |
| D5 | the write gate is **in `writer.write_card`** | a gate in the card API only, with every writer asked to call it; a gate in each of the 25 writers | P1: `write_card` is already the one card write, and `tools/check_record_writers.sh` already refuses any other. Putting the gate there makes all 25 writers — the fourteen under `record/` (three of them in `frontmatter` itself), the five in `groom/`, the four in `tick/` and the two in `kernel/ports.py` — inherit it with no call-site change, and makes the lint that protects the single writer also protect the single validation. |
| D6 | two named escapes from the gate, `write_card(..., validate=False)`, allowed from exactly the migration and `record-repair`, pinned by a lint | no escape; an environment variable | To repair an invalid card you must write it. Naming the two callers in a lint (the shape `check_record_writers.sh` and `DERIVABLE_KEYS` already use) keeps the escape auditable; an environment variable would be a switch a session could flip. |
| D7 | `acceptance` is an **array of `{text, test, done}`**, and `line <n>` is its **1-based index** | storing an explicit `line` per entry; a stable id per line | P8: `line <n>` in a `Proves:` trailer counts the nth bullet today, and that grammar is written by every coder session and read by the landing gate. An index *is* the line, so the two can never disagree — a stored `line` field could. A stable per-line id would change the trailer's grammar and the landing gate with it: out of scope (§1.3). |
| D8 | `gate` is an **array of command strings**; `risk` is an **enum** (`none`, `high`) | keeping the body `**Gate**` fence; a free-text risk | P7 and P12: the fence is a regex over prose with no validation, and 158 open Tasks depend on it. An array of strings is what the brief and CI already want. `risk` is the groom-fill verdict's own vocabulary (`dor.RISKS`), so the enum is already written down. |
| D9 | `history` is an **array of one-line strings**; the rest of the prose is an **ordered map of section → markdown** | one markdown blob for the whole body | Every writer that touches history appends one dated line; an array makes that an append instead of a text edit, and makes a multi-line value impossible by construction. The other sections are prose nobody parses, so one string each is enough. `## Children` and `## Backlinks` stop being card content at all — they are derived into the view only, which removes a whole finding class (`section is stale (run asf index)`) rather than porting it. |
| D10 | the record's version is the **existing `schema_version`**, and the conversion is **`MIGRATIONS[2]`** | a one-off `asf record-repair` mode as the only path | P4: that mechanism already drains sessions, migrates both copies of the record, commits each migration as its own pushed commit, stamps `index.json` and every card, and — the part that matters — `require()` already makes **every writing command refuse** against a record at the wrong version. That is precisely the card's "run it on each product's record before it moves to the kernel", and it needs no new coordination. `asf record-repair --apply` stays as the entry point that runs the same conversion over a record root given by path, with a dry run by default, so it can be run on a *copy* without stamping anything (the card's own acceptance). |
| D11 | the migration **round-trips every card**: convert, render back to the old text, compare; a card that does not compare equal stops the migration naming the card and the difference | a best-effort conversion with a report | 2 298 cards and 60 keys: a conversion that quietly loses a field is worse than no conversion, and invariant I1 (P10) says no writer strips a key. The round-trip is the only check that proves nothing was dropped, and stopping is right because the migration is one commit, re-runnable after the card is fixed by hand. |
| D12 | referential integrity is checked **at write**, by the card API, against the record the card is being written into | at check time only | P11: `asf set parent=` already does exactly this, and it is the only reference that never dangles. A write-time refusal names the one card the writer has in hand; a check-time finding names it a tick later, after the kernel has already read it. |
| D13 | an edge onto a **closed, retired or superseded** card is **resolved, not deleted** — marked satisfied where it stands, or re-pointed to `superseded_by` | deleting the edge | The edge is history: it says why this card waited. 702 edges (§1.1) point at retired cards, and deleting them would erase the order the work actually happened in. Satisfied-in-place keeps the record true and releases the dependent card; re-pointing is what the operator asked for superseded cards. |
| D14 | one operation closes/retires/supersedes/deletes a card **and resolves its incoming edges in the same record commit** | a nightly sweep | A sweep leaves a window in which the record points at a finished card and the kernel has to guess — which is the measured stuck-card class. One commit means the record is never observable in the broken state. The commit builder already commits a card with everything its change implies (P13). |
| D15 | an unresolvable reference is **LIMBO with the reason** | blocked, or parked | The operator's words. P3 shows the LIMBO path exists and that nothing but a parse error reaches it; a park is invisible and is how the 140 ASF edges went quiet. |
| D16 | four enforcement points: the **card API**, **`asf check`**, the **record pre-commit**, **CI** | the writer alone | The writers that are not `asf` — a hand edit, another tool, a session with an editor — are a third of the problem the card measures. P6 makes the hook free. CI is a workflow `asf init` writes into the record checkout, alongside the hooks it already writes there. |
| D17 | ten Stories, in the order of §2 | one Story per enforcement point; one big Story | Each of the ten lands on its own and leaves the record strictly better: the gate before the format, the format before the migration, the migration before the integrity rules that need its typed fields. The order is also the risk order — the two Stories that touch 2 298 cards (S-133158, S-133164) come after the validator that judges them exists. |

## 2. The design

### 2.1 The schema file, and the validator

**New: `asf/record/cards.v2.schema.json`** — the card schema, shipped as package data
(`[tool.setuptools.package-data]` gains `"asf.record" = ["*.schema.json"]`, P14) and read with the
`os.path.dirname(os.path.abspath(__file__))` idiom.

Its shape, in outline:

```json
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "$id": "asf/record/cards.v2.schema.json",
  "title": "ASF card, schema 2",
  "type": "object",
  "additionalProperties": false,
  "required": ["schema_version", "id", "type", "title", "state"],
  "properties": {
    "schema_version": {"const": 2, "owner": "machine"},
    "id": {"type": "string", "pattern": "^[A-Z]-[0-9]{4,}$"},
    "type": {"enum": ["epic", "feature", "story", "task", "bug", "decision", "rule"]},
    "title": {"type": "string", "minLength": 1},
    "state": {"enum": ["New", "Active", "Resolved", "Closed"], "owner": "machine"},
    "kernel_state": {"enum": ["new", "ready", "building", "review", "landing", "done", "stuck"],
                     "owner": "machine"},
    "parent": {"type": ["string", "null"], "pattern": "^[A-Z]-[0-9]{4,}$", "ref": "card"},
    "after":  {"type": "array", "items": {"type": "string", "pattern": "^[A-Z]-[0-9]{4,}$"},
               "ref": "card"},
    "stories": {"type": "array", "items": {"type": "string", "pattern": "^S-[0-9]{4,}$"},
                "ref": "card"},
    "writes": {"type": "array", "items": {"type": "string", "minLength": 1}},
    "creates": {"type": "array", "items": {"type": "string", "minLength": 1}},
    "acceptance": {"type": "array", "items": {
      "type": "object", "additionalProperties": false,
      "required": ["text"],
      "properties": {"text": {"type": "string", "minLength": 1},
                     "test": {"type": "string"},
                     "done": {"type": "boolean"}}}},
    "gate": {"type": "array", "items": {"type": "string", "minLength": 1}},
    "risk": {"enum": ["none", "high"]},
    "rank": {"type": ["integer", "null"], "minimum": 0},
    "priority": {"enum": ["need", "nice", "later", null]},
    "history": {"type": "array", "items": {"type": "string"}},
    "prose": {"type": "object", "additionalProperties": {"type": "string"}},
    "extra": {"type": "object", "additionalProperties":
              {"type": ["string", "integer", "number", "boolean", "null"]}}
  }
}
```

…and one property per remaining key: §1.1's 60, plus the seventeen `kernel_*` keys of
`ports.KERNEL_KEYS` that a record on the kernel carries and the measured record does not (P17),
each with its one type and its `owner`. Two of them are settled by the measurement rather than
carried over: `removed` is
`{"type": ["boolean", "string"]}` because both readings are meaningful today (`true`, or the
reason), and `blockedBy` is an array only — the string form is a writer's slip that `core.as_list`
absorbs, and the migration lifts it into a one-element array.

Two keywords are ASF's own, and the validator ignores them where JSON Schema would:
`"owner": "machine"` (D4 — what `card.split_machine` reads) and `"ref": "card"` (§2.5 — the
reference fields integrity is checked over). Both are annotations, so the file stays a valid
JSON Schema document.

The two state fields above are not a mistake and are not merged here. `state` is the record's own
(`New`, `Active`, `Resolved`, `Closed` — declared in `asf/evidence/closing.py:53`, and the four
values the measured record carries); `kernel_state` is the kernel's derived state
(`asf.kernel.model.State`'s lowercase values, written under `ports.STATE`), with
`ports.CLOSED_STATES` the bridge `item_from_card` reads when a card carries only the first. This
schema is the first place both vocabularies are written down together, which is the whole point
of the card; collapsing them into one field is a state-machine change and is out of scope (§1.3).

**New: `asf/record/validate.py`** — the validator, stdlib only, ~150 lines. `errors(instance,
schema)` returns a list of `(pointer, message)` in document order: `"/acceptance/2/test"`,
`"writes[1] is not a string"`. It implements exactly the keywords D2 names, and
`UNSUPPORTED` lists them, so `tests/test_card_schema.py` can assert that every keyword the schema
file uses is one the validator enforces — a schema can never promise more than it checks.

### 2.2 The card API

**New: `asf/record/card.py`** — the one way a card is addressed, read, validated and rendered.

| function | what it is |
| --- | --- |
| `SCHEMA` | the parsed schema, loaded once |
| `path(root, folder, iid)` | the card's file: `<root>/<folder>/<iid>.json` when that exists, else the `.md` (a schema-1 record) |
| `view_path(card_path)` | the generated `.md` beside a `.json` |
| `load(path)` | `(meta, body)` — `meta` the flat dict every reader already indexes, `body` the prose rendered as markdown, so `rec['body']` keeps working for the readers that only display it |
| `loads(text, path)` | the same from text, for the pre-commit's scratch tree |
| `validate(meta, root=None)` | `[(pointer, message)]` — shape against the schema, and when `root` is given, references against that record (§2.5) |
| `dumps(meta)` | the card's JSON text: 2-space indent, keys in schema order, `\n` at the end — one canonical form, so a card's diff is only what changed |
| `render(meta, derived)` | the `.md` view: the frontmatter block as today for continuity of the eye, then `## Description`, `## Acceptance` as `- [ ]` lines, `## Gate` as a fenced block, `## History`, and the derived `## Children` / `## Backlinks` |
| `split_machine(meta)` | `(typed, machine)` from the schema's `owner` (D4) — replaces `frontmatter.split_machine`, same signature, same return |
| `refs(meta)` | `[(field, index, id)]` for every property the schema marks `"ref": "card"` |

`core.load_items` (P2) gains the one branch that makes the migration survivable: in each item
folder, a `*.json` is a card read by `card.load`; a `*.md` **with** a sibling `.json` is that
card's view and is skipped; a `*.md` **without** one is a schema-1 card read by
`frontmatter.parse` exactly as today. So one `asf` reads a record before, during and after its
migration, which is what P4's drain-and-migrate needs.

`frontmatter.py` is not deleted and not reduced: it is the schema-1 reader the migration reads
with, and the renderer of the view's frontmatter block.

### 2.3 The write gate

`writer.write_card(path, text, validate=True)` (P1, D5) gains four lines of its own and one
import: when `validate` and the path is a card, parse `text` as a card for that path's extension
and run `card.validate`; on any error raise `CardInvalid(path, errors)` — whose `str` is the path,
the pointer and the message, one line each — and write nothing. The file on disk is untouched,
which is what makes a refused write safe for all 25 callers.

```
asf/record/writer.py:  CardInvalid; write_card(path, text, validate=True)
tools/check_card_gate.sh:  the two callers allowed `validate=False` (D6), and no others
```

`CardInvalid` reaches a console command as a non-zero exit with the error on stderr; it reaches a
tick or kernel apply through the paths that already catch a record write failure and leave a note.
The gate is not a silent skip: a write that cannot be made valid is an error, because the
alternative is the class this card exists to close.

### 2.4 Machine fields out of the body

| field | written by | read by |
| --- | --- | --- |
| `acceptance[{text, test, done}]` | `ports.fill_card` (a groom-fill verdict, P9), `ports.mint_story` / `record.ids` (a minted Story, from the spec's declared checkbox lines), `record.new`, `asf set` | `dor.missing` clause (i), `proves.bullets`, `rules.story_proof`, the briefs |
| `gate[commands]` | `record.new`, `asf set`, the plan's Task section | `dor.missing` clause (i), the brief's `GATE_LOCAL`, the review table |
| `risk` | a groom-fill verdict's `risk_raise` | the feeder's risk row |

`dor.acceptance_lines` and `dor.gate_lines` (P7) keep their names and their bodies — they become
the *migration's* readers, and `dor.missing` reads `card['acceptance']` and `card['gate']`
instead. That is the whole of "no hand-parsed format in the kernel's read path": the regexes stay
in the tree, used once, by the converter.

`proves.card_bullets` (P8) stops opening the `.md` and reads `card.load(...)[0]['acceptance']`;
`proves.bullets(body)` stays for a schema-1 card and for a `Proves:` claim against a card the
record no longer holds. `proves.tick` flips `acceptance[n-1]['done']` and appends the history
line, through `card.dumps` and the gate.

`tools/check_card_readers.sh` — a new lint in the shape of `check_record_writers.sh` — refuses a
card `.md` *read* outside `card.py`, the migration and `proves.bullets`'s schema-1 fallback. That
is what keeps D1's view from quietly becoming a parsed format again.

### 2.5 Referential integrity, and the one resolving operation

`card.validate(meta, root)` checks every `"ref": "card"` field (§2.1): an id that names no card in
`root` is an error, `/after/1: T-0412 names no card on the record`. The refusal is the writer's
(D12), so `asf set after+=T-0412`, a plan minting a Task, a groom answer and a kernel apply all
hit the same wall with the same words.

**Resolving an edge (D13).** A reference is not only present or absent — it is *satisfied* or
not:

| the target | the edge becomes |
| --- | --- |
| Done / Closed | satisfied in place: the id stays, and the card's `satisfied` array names the field and id, with the date |
| retired (`removed:` / `moved_to:`) | the same, and the history line says which |
| superseded (`superseded_by: X`) | re-pointed to `X`, the old id kept in `satisfied` |
| deleted | removed from the field, with a history line on the dependent card naming what it pointed at |

**New: `asf/record/resolve.py`** — `incoming(root, iid)` finds every card with an edge onto `iid`
(a scan of `card.refs` over the record), and `close(root, iid, how)` returns the cards it would
rewrite and the rewrite for each. `asf retire`, `asf record close`, the supersession path in
`asf/groom/conflicts.py` and the kernel's own close all call it, and the whole set lands in one
`publish.commit_paths` call (D14, P13) — one record commit, one pre-commit run, one push.

### 2.6 The kernel: invalid is LIMBO

`RecordPort.unreadable()` (P3) widens from "the parser refused it" to "the record cannot use it",
with the reason it already carries:

- a card whose JSON does not parse, or does not validate → `<path>: <pointer>: <message>`
- a card whose reference names no card → `<field> <id> names no card on the record`

Both land in `facts.unreadable`, so `decide.limbo` already prints them, `edge_open` already
treats a card in LIMBO as holding its dependents, and `loop.questions_line`'s `LIMBO n` already
counts them. The only new words are the reason strings. Nothing becomes parked, and nothing is
dropped: a card that cannot be used is *named* every tick until it is fixed.

### 2.7 Enforcement from any writer

| point | what changes |
| --- | --- |
| the card API / `writer.write_card` | §2.3 — every `asf` writer |
| `asf check` | one new finding class per schema error and per unresolved reference, at the card and the field's line; `after:` is checked for the first time (P5); a `.md` view that differs from `card.render` is `view is stale (run asf index)`, the shape `index.json is stale` already has |
| the record pre-commit | nothing — it runs `asf check --staged` already (P6), over the staged tree, so a hand edit and another tool are refused the day the finding class lands |
| CI | `asf init` writes `.github/workflows/record-check.yml` into the record checkout beside the hooks it already writes: install the pinned `asf`, `asf check`. Idempotent, and `asf doctor` gains the row that says whether it is there |

`asf index` learns to write the views, so the derivation that `publish.commit_paths` already runs
(P13) carries them into the same commit as the card.

### 2.8 The migration: record schema 2

`asf.schema` gains `MIGRATIONS[2] = _migrate_to_2` and `SCHEMA_VERSION = 2` (P4, D10).
`_migrate_to_2(record_dir)` walks every `*.md` card and, for each:

1. parses it with `frontmatter.parse` (the schema-1 reader);
2. lifts the body's machine meaning into fields — `## Acceptance` checkbox bullets into
   `acceptance` (text, and `test` when `dor.test_refs` finds one in the line), the `**Gate**`
   fence into `gate`, `## History` lines into `history`, every other section into `prose`,
   `## Children`/`## Backlinks` dropped (D9, derived);
3. normalises the two measured shape slips: a `blockedBy` string into a one-element array, a
   `reshape_applied` on either side of the marker into the one owner the schema declares;
4. puts any key the schema does not name into `extra` (D3);
5. **round-trips** (D11): renders the new card back to markdown and compares with the original,
   normalised for the derived sections; on a difference, stops and names the card, the field and
   the difference;
6. writes `<id>.json` and `<id>.md` (the view) through `write_card(..., validate=False)` for the
   view and the gate for the card, and `git rm`s nothing — the old `.md` *is* the view's path, so
   the diff a person reads is the body's machine fields leaving it.

`stamp_cards` already brings every card to the version (P4) and `migrate_product` already drains
sessions and does both copies of the record. `sample/backlog/**` is converted in the same PR, by
the same code, and `tests/test_card_migration.py` pins the converted sample byte for byte (P15).

`asf record-repair` keeps its name and its dry-run default and gains `--to-schema 2`: the same
conversion over a record root given by path, stamping nothing. That is the command the card's own
acceptance names, and it is runnable on a copy of any record.

### 2.9 The human view

`asf show <id>` — new subcommand — prints the card as `card.render` writes it, for a person or a
session at a terminal. The generated `<id>.md` is the same text, so GitHub, `git diff` and a
review session all see the card without parsing it.
