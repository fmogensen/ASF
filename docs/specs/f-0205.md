# F-0205 — NEXT drops S1/S2 bugs silently — show a WAITS row with the reason

On 2026-09-26 `B-1378` vanished from NEXT. Its fix session was running. Nothing said so: the row
was simply absent, and absence in NEXT is read by operators and by peer sessions as *the Bug was
lost*, which is a different and much worse fact than *the Bug is being worked*. The inbox note
that became this card lists the four branches of `asf/feeder/rows.py` `bug_rows()` that each ended
in a bare `continue` — a live session, blocked, `Active` with no branch row, past the attempt
limit.

Those four `continue`s are gone. `c0f84c778` (*"a decided S1/S2 Bug the feeder skips is a WAITS row
that says why"*, 2026-09-26, the day of the incident) turned each into a non-launching `WAITS ON`
row carrying its reason, and `tests/test_feeder.py::NoS1S2BugIsInvisible` holds nine tests over
them. The fix landed as a fix, without a spec; this Feature's card was minted from the same inbox
note and never tied to it. **The first thing this spec does is state the requirement the trunk is
already meeting, and adopt that test class as its acceptance** — a Feature whose behaviour lives
only in a fix commit's subject has no record, and the next person to touch `bug_rows` has nothing
to read.

The second thing it does is close what the fix left half-done. A WAITS row that says the wrong
thing is not better than no row; it is the same failure wearing the row's clothes. Today the busy
branch decides between *a session is running* and *the work is waiting to land* by looking for the
letters `land` in a human sentence:

```python
if b['id'] in busy:
    held = why.get(b['id']) or 'session running'
    on = 'landing' if 'land' in held else 'session'
    out.append(waits(on, held))
```

`asf/feeder/rows.py:606-610`. `held` is prose written elsewhere — `asf.workers.lifecycle.occupancy`
composes it from a lane state, a harvest wait or a run record — and none of those sentences was
written to be parsed. Three of them are read wrong today, reproduced against the trunk at
`c2bf7f7f9`:

| what actually holds `B-0001` | the row NEXT prints |
| --- | --- |
| `finished, awaiting harvest` (`lifecycle.FINISHED_WAIT` — the run ended, harvest has not got to it) | `WAITS ON session — S1 open, decided: finished, awaiting harvest` |
| `lane REVIEW PR #7: round 1` (a PR under review; a partial occupancy names it under `waiting_landing` alone) | `WAITS ON session — S1 open, decided: lane REVIEW PR #7: round 1` |
| a live session whose record says `job: fix-bug-b-0001` | `WAITS ON session — S1 open, decided: session running` |

No lane state's name contains a lowercase `land` (`PUSHED`, `PR_OPEN`, `REVIEW`, `GATE`,
`WAITING_CI`, `WAITING`, `QUEUED`, `MERGING`, `PARKED` — `asf/harvest/lane.py:130-143`), and
neither does `finished, awaiting harvest`. So the classifier's default — *a session is running* —
is what the operator is told in every one of those cases. It is the exact sentence `B-1378`'s
absence was misread as the negation of, and it is false. The third row is the card's own worked
example, `B-1378 — WAITS ON session fix-bug-b-1378 running`: the job name the incident wanted in
the row is carried by the in-flight record and thrown away by the caller.

## Decisions

### In

* **D1** — The four skip branches of `bug_rows()` for a decided, open S1/S2 Bug each emit a
  non-launching `WAITS ON` row whose `reason` states why. This is the card's requirement; the
  trunk meets it; this spec is the record of it and `NoS1S2BugIsInvisible` is its acceptance.
* **D2** — Every one of the four asserts its **reason text**, not only its `waits_on` field. The
  card's test line is *"a row with its reason"*; two of the four (`session`, `branch`) assert the
  field alone today, so the sentence an operator reads could go empty with the suite green.
* **D3** — The busy branch classifies the hold from the fact that produced it, not from a
  substring of the sentence that describes it. `candidates()` is the one place that knows which
  map an id came from, so it is the place that decides.
* **D4** — A live session is named by its job in the row's reason, on every path — the in-flight
  list alone, and `occupancy`'s `busy`. One sentence, built in one place, so the two cannot drift.
* **D5** — `harvest` joins `asf.feeder.tiers.WORKED`. A finished run awaiting harvest *is* being
  worked, by the harvest; minting the value without adding it would turn a correctly-progressing
  S1 into a false `NEEDS OPERATOR` line, which is the same class of wrong row this card exists to
  remove.

### Out

* **O1 — S3 and S4 Bugs.** The card says *"at minimum do this for S1/S2"*. `bug_rows()` mints no
  `BUG → FIX` row for an S3 at all (asserted at `tests/test_feeder.py:1306`), so an S3 that is
  busy or blocked is not *dropped* from NEXT — it was never NEXT work. A `WAITS ON` row for it
  would be a row about something that was never going to launch: noise in the S1 lane, not a
  recovered fact. Severity is the lever; `asf set <id> severity=S2` is the remedy and `_remedy()`
  already prints it.
* **O2 — Non-Bug card types.** Features, Tasks and deliveries have their own row functions with
  their own wait rules. Nothing here changes them.
* **O3 — What counts as busy.** `occupancy()` decides that, and its verdict is not touched. This
  changes only how the feeder *describes* a hold it is already given.
* **O4 — `lane_rows()`, `PUSHED → REVIEW`, `PUSHED → LAND`, and `PARKED`'s membership of
  `WORKED`.** When a full occupancy names the Bug under `review`/`landing`, `lane_rows()` emits
  the right row and `spoken_for` (`rows.py:1699-1700`) drops the Bug's WAITS row. Those rows are
  correct and stay as they are; this spec touches only the path where they do not speak.
* **O5 — Persisting anything.** No state file, no config key, no command, no card field, no
  schema change, no forge call.

### Preconditions

* **P1** — `c0f84c778` is on the trunk. The four branches, the `waits()` helper
  (`rows.py:597-601`), the `why`/`held_by` map, `spoken_for`, `tiers.WORKED`, `Gate.unworked` and
  `needs_operator()`'s remedies all exist. Verified: `git merge-base --is-ancestor c0f84c778
  HEAD`.
* **P2** — `lifecycle.inflight()` records carry `job` (`asf/workers/lifecycle.py:950-954`), and
  `occupancy()['busy']` already composes `f"session {s['job']} running"`
  (`lifecycle.py:1134-1135`). The job name needed by D4 is present on both paths; only the feeder
  discards it.
* **P3** — `occupancy()` puts a lane-state or harvest hold in `waiting_landing`, never in `busy`
  (`lifecycle.py:1157-1185`), and `candidates()` merges the two into one `held_by`
  (`rows.py:1672-1673`). The provenance D3 needs is available at the merge and lost immediately
  after it.
* **P4** — `waits_on` is the machine field the gate reads (`tiers.WORKED`, `Gate.unworked`,
  `_remedy()`); `reason` is the sentence the operator reads. Both already flow to the operator
  through `needs_operator()`.

### The choices

| # | Chosen | Against | Why |
| --- | --- | --- | --- |
| C1 | Specify the landed behaviour and adopt its test class | Write a spec for work as if unbuilt; or skip the spec because the code exists | A Feature with no spec has no record of *why* the four branches must never be silent, and re-specifying built behaviour as new invites a plan that mints Tasks to rebuild it. Stating it and pointing at its live acceptance costs one section and leaves the record whole. |
| C2 | `candidates()` hands `bug_rows()` a `(waits_on, sentence)` pair per held id | Keep the `{id: sentence}` map and improve the sniff (more substrings, case-folding) | A better sniff is still a parser for prose nobody promised to keep parseable; `lane` renaming a state or `lifecycle` rewording a wait silently breaks it again. | C3 | The pair's `waits_on` is one of `session`, `landing`, `harvest` | Reuse `landing` for a harvest wait | They are different facts with different remedies: a landing wait is the lane's, a harvest wait is the harvest's, and an operator debugging a stuck S1 needs to know which daemon to look at. Both are in `WORKED`, so the gate's verdict is unchanged either way (D5). |
| C4 | One helper builds the session sentence, used by the feeder and asserted against `lifecycle`'s wording | Duplicate the f-string in `candidates()` | Two copies of `session {job} running` drift, and the drift is invisible — the row still reads plausibly. One helper and one test that the two agree. |
| C5 | `bug_rows()`'s signature keeps one `why` argument, its values widened to the pair | Add a fifth positional argument | `why` is already *"what holds it"*; it stays one argument, and both of its callers are in `rows.py`. A tuple value is accepted alongside a bare string, so a caller that passes the old shape keeps the old classification and no test outside this file moves. |
| C6 | Assert the reason text in all four cases (D2) | Assert `waits_on` only, as today | The card asks for the reason. A field with no sentence behind it is what the incident already looked like from the operator's chair. |

## The design

### 1. `candidates()` says what kind of hold it is — `asf/feeder/rows.py`

`held_by` (`rows.py:1672-1673`) is built today from three sources flattened into one
`{id: sentence}` map, after which the kind of hold is unrecoverable. It becomes a
`{id: (waits_on, sentence)}` map, each entry labelled by the source that produced it:

* every in-flight record → `('session', session_wait(s))` — the sentence of §2, which names the
  job;
* `occ['waiting_landing']` whose sentence is `lifecycle.FINISHED_WAIT` → `('harvest', why)`;
* every other `occ['waiting_landing']` entry → `('landing', why)`;
* `occ['busy']` → `('session', why)`, its sentence kept as `occupancy` wrote it — it already names
  the job (P2), and `occupancy` is the authority on a live run.

The merge order is unchanged: `occ['busy']` last, so a live run's own words win over a stale
landing wait for the same id.

### 2. One sentence for a live session — `asf/feeder/rows.py`

A module-level helper beside `session_of()`:

```python
def session_wait(session):
    """``session <job> running`` — the sentence :func:`asf.workers.lifecycle.occupancy` writes
    into ``busy`` for a live run, built here for the in-flight list too so a Bug's WAITS row names
    the session that holds it whether or not the caller passed an occupancy (F-0205). A record
    with no job falls back to the bare ``session running``."""
    job = (session or {}).get('job')
    return f'session {job} running' if job else 'session running'
```

`occupancy()`'s own f-string is left where it is; a test asserts the two agree (§3, T5), so the
duplication is caught rather than assumed away.

### 3. `bug_rows()` reads the label instead of guessing it — `asf/feeder/rows.py:606-610`

```python
if b['id'] in busy:
    on, held = held_kind(why.get(b['id']))
    out.append(waits(on, held))
```

with a small reader that accepts both shapes, so C5 holds:

```python
def held_kind(held):
    """``(waits_on, sentence)`` for one :func:`candidates` ``why`` entry. A pair is the caller's
    own label (it knows which map the id came from); a bare string is a caller that passed none,
    and reads as a live session — the only hold an ``inflight``-only caller can have. Nothing is
    inferred from the sentence's words: the lane's state names carry no ``land``, and neither does
    ``finished, awaiting harvest`` (F-0205)."""
    if isinstance(held, tuple):
        return held
    return 'session', held or 'session running'
```

The three rows of the table above become:

| what holds it | the row |
| --- | --- |
| a live session, job `fix-bug-b-0001` | `WAITS ON session` — `S1 open, decided: session fix-bug-b-0001 running` |
| pushed, waiting to land | `WAITS ON landing` — `S1 open, decided: pushed, waiting to land` |
| finished, awaiting harvest | `WAITS ON harvest` — `S1 open, decided: finished, awaiting harvest` |
| a PR in review, occupancy partial | `WAITS ON landing` — `S1 open, decided: lane REVIEW PR #7: round 1` |

The other three branches — blocked, `Active`, over the limit — are untouched: they already name a
blocker id, `branch` and `operator` respectively, and each already carries its sentence.

### 4. A harvest wait is worked — `asf/feeder/tiers.py:29`

```python
WORKED = ('session', 'landing', 'harvest', 'branch', 'merge')
```

`Gate.unworked` collects tier-0 WAITS rows whose `waits_on` is *not* in `WORKED`, and
`needs_operator()` prints one `NEEDS OPERATOR:` line per entry. A Bug whose run finished and waits
on harvest is being worked; without this line it would gain a `NEEDS OPERATOR` line the moment its
classification became truthful — trading a wrong sentence for a wrong alarm. `_remedy()` needs no
case: it is never reached for a `WORKED` value.

### 5. What it looks like when it is there

An operator running the tick with `B-1378`'s fix session live reads

```
S1  BUG → FIX  B-1378  WAITS ON session  — S1 open, decided: session fix-bug-b-1378 running
```

and knows, without opening the ledger, that the Bug is neither lost nor idle, which lane is
holding it, and that there is nothing for them to do. When that session ends and its branch waits
for harvest, the same row reads `WAITS ON harvest — S1 open, decided: finished, awaiting harvest`,
and when harvest hands it to the lane, `WAITS ON landing`. Three different facts, three different
sentences, no `NEEDS OPERATOR` line for any of them — and if the Bug is instead blocked, `Active`
with nothing on its branch, or past the attempt limit, the row says that and the operator gets the
line with the command that clears it.
