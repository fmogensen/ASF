# F-0035 — the controller decides; the tick reads

On 2026-09-21 the controlling account reached 70 % of its weekly window, and it spent that window
on chores: `gh pr list` to see which branches were waiting, `ps` piped through `grep` to see which
sessions were alive, `tail` over a job log to see whether one was moving, `asf status` again two
minutes later. Every one of those is a read the tick could have done once, on its own clock, for
every product at the same time.

The factory is already built to do it. Six views render from the record
(`asf/tick/tick.py:114`), the in-flight and ended tables render from the session ledger
(`asf/tick/summary.py:126`), the probe set is `asf doctor`, and `harvest` has been a manifest
step owned by `asf` since 84b4671. What is missing is that **none of it is written down where the
console can read it**: `render_tables` and `write_tables` are called from one place,
`run_shadow` (`asf/tick/tick.py:229-230`), so a live tick writes no table at all, and
`summary.run` is documented as "best-effort console output: it writes nothing to the record"
(`asf/tick/summary.py:5-6`). The console therefore re-derives, by hand, on the operator's
account, what the tick had in memory ten minutes ago and threw away.

The chore side is worse: nothing anywhere records a command the controlling session ran, so the
sentence *"the commands it ran in the last day that a script already covers"* has no source. The
first half of this Feature moves the read loops into a `watch` step whose output is a file; the
second half gives the controller a ledger of its own commands, a classifier over it, and a rule
that turns a scriptable chore into a Bug once the weekly window is 60 % gone.

This changes code under `asf/`, `tests/`, `sample/product.yaml` and a new `rules/` directory in
this repository. It changes no card in any record: the rule's own card is minted in the record by
the Task that builds the check, from the record's own counter.

## 1. Decisions

### 1.1 In

- A **`watch` tick step** — `asf/tick/step_watch.py`, last in `steps.STEPS`
  (`record → health → wave → prs → harvest → batch → daily → **watch**`), owner `asf`, three
  parts in the shape `step_daily` already uses (§2.1): `tables`, `watch`, `probe`.
- **`tables`** — the six views rendered into the record clone's `tables/` on every tick, which is
  what `--shadow` has always done and a live tick has never done (§2.2). A table whose bytes did
  not change is not rewritten.
- **`watch`** — `summary.render`'s in-flight and ended blocks written to `tables/watch.md` beside
  them, so *what is each session doing* is a file read rather than a `ps`, a `tail` and a
  judgement (§2.3). The console's own summary line at the end of a tick is unchanged.
- **`probe`** — `asf doctor`'s rows on a throttle (`watch.probe_every`, default `1h`), written to
  `tables/doctor.md`, plus one `probe` event carrying the red rows (§2.4). Throttled because the
  doctor shells out to seven binaries and the dispatch clock ticks every ten minutes.
- **`harvest` held where it is** (§2.5): it is already a step, and nothing about it changes except
  that a test now says so — the acceptance names it, and a step that quietly went back to being a
  console command is the regression this card exists to prevent.
- **The chore ledger** (§2.6): a built-in `PostToolUse` hook, `asf hook chores`, appends one line
  per shell command a **controlling** session runs — `ASF_JOB` unset, the discriminator
  `approvals.run_hook` already uses (`asf/approvals.py:464`) — to
  `<ASF_HOME>/chores/<date>.jsonl`. It records the command line, redacted; it never blocks a call
  and never records output.
- **`asf chores`** (§2.7): the classifier and its table. The day's recorded commands split into
  `covered` (a script already does this — the coverage map names which), `repeated` (the same
  command three times or more, whatever it is) and `own` (nothing covers it). `--json` is the
  machine form the check script reads; `--days N` widens the window.
- **The rule and its check script** (§2.8): `rules/controller-chores.sh` in this repository — the
  first script in the core `rules/` directory that `asf.rules.rules.core_rules_dir()` and
  `asf.hooks.RULES_DIR` already name — and a rule card minted in the record, `check:
  tools/checks/controller-chores.sh`, resolved to the core script by `resolve_script`'s basename
  fallback so every product gets it without copying a file.
- **The gate**: the check is silent below `chores.window_pct` (default 60) of the controlling
  account's 7-day window, read through the quota source the pool already uses
  (`worker_pool.quota_command`, `seven_d_pct`). `controller.account` names the account.
- **Filing through the path that already files** (§2.9): nothing new. `asf file-bugs` turns every
  current rule violation into one Bug per rule, keyed `<rule>: rule violated`, and it runs on
  every tick from the `record` step (`asf/tick/file_bugs.py:114`, `tick.run_step0`).
- **The measure** (§2.10): one `controller_usage` event per tick, and `tables/controller.md` — the
  week's high-water mark of the controlling account's 7-day window, and scriptable chores per day
  for the last seven days. This is how the card's third acceptance is read next week.
- `sample/product.yaml`'s dispatch clock gains `watch`, and `asf doctor`'s existing
  `check_clock_steps` (`asf/doctor.py:423`, T-0098) then names `watch` on any product whose clocks
  do not tick it — including the operator's live one, which is a `NEEDS OPERATOR` line in this
  session's report and not a file this repository may edit.

### 1.2 Out

- **The groom's move onto the tick clock.** F-0099 owns that: a `groom` step between `health` and
  `wave`, `step_daily` reduced, the answers helpers moved to `asf/groom/answers.py`. Nothing here
  touches `asf/groom/`, `step_daily.py` or `steps.STEPS`' first seven names, and `watch` is
  appended last precisely so the two features do not edit the same line of `STEPS`.
- **A `retro` job.** The card's last paragraph names four daily jobs: groom, rollup, retro and
  stale sweep. Three of them are `step_daily.parts()` today and run on the `daily` clock, which
  is the scheduler, not a session — that half of the paragraph is already true. `retro` exists
  nowhere in this tree (`grep -rn retro asf/` is empty): there is no such command, no output it
  writes and no definition of what it retrospects. Inventing one inside this Feature would be a
  second Feature with no card. The report carries the `NEEDS OPERATOR:` line that files it.
- **Refusing or rewriting a chore.** The recorder is a `PostToolUse` hook and exits 0 always, even
  when it cannot write its own ledger. A recorder that can refuse a call is a boundary, and the
  boundary is the approvals matrix (F-0031); mixing the two would make a measurement into a gate
  that fails closed on a full disk.
- **Reading the controlling session's transcript, or the operator's shell history.** Both are
  outside `~/.ASF` (`tools/forbidden-conventions.txt` forbids `.claude/` and `/tmp/` in
  `asf/**/*.py` for exactly this reason), both carry text the operator never meant the factory to
  parse, and neither is a record of *what ran* — a transcript is a record of what was said.
- **Deciding what a chore *should* have been, beyond the coverage map.** The map says *this
  command is covered by that script*. It does not guess a script for an uncovered command: an
  `own` command is reported, counted and left alone. Turning "nobody scripted this" into a card
  is the groom's job, from the numbers in §2.10.
- **Counting the by-hand work the constitution requires.** R-0122 — *the controller does secrets
  and production by hand, through pipes that never print a value* — is a rule the chore rule must
  never contradict. The `chores.ignore` default holds those commands, and an ignored command is
  not a chore at any usage level.
- **Removing a console command.** `asf status`, `asf sessions`, `asf capacity`, `asf next` and
  `asf doctor` all stay exactly as they are, and still work on demand. What changes is that the
  cheap answer — the tick's table — exists, so the loop does not have to.
- **The third acceptance as a test in this repository.** "The controlling account's weekly usage
  falls below 50 % the following week" is an outcome of the operator's week. §2.10 makes it
  readable; no test in this repository can assert it, and a test that pretended to would be
  asserting a fixture.
- **Shortening or adding a clock.** The `watch` step runs on the clock the operator already has.

### 1.4 The choices

| Choice | Chosen | Against | Why |
|---|---|---|---|
| Where the read loops go | one `watch` step with three parts | a step per loop (`tables`, `watch`, `probe`); a part of `health` | The operator schedules steps, the manifest lists them and the tick times them. Three steps for three reads that always run together is three clock entries to keep in step. One step with parts is the shape `daily` already has, and `--steps watch` is then exactly the console's old loop, run by the machine. |
| Its place in the manifest | last, after `daily` | first; after `harvest`, before `batch` | What the tables say should be what this tick *left behind*, harvest, batch and daily included. ## 2. The design

### 2.1 `asf/tick/step_watch.py` — the step

```python
"""asf.tick.step_watch — the tick's ``watch`` step: the read loops the console used to run.

Last in the manifest, so what it writes is what this tick left behind. Three parts, in the shape
:mod:`asf.tick.step_daily` uses — each a thunk returning an exit code, a failing part never
stopping the others, one line each:

* ``tables`` — the six views into the record clone's ``tables/`` (:func:`asf.tick.tick.render_tables`);
* ``watch``  — the in-flight and ended blocks into ``tables/watch.md`` (:mod:`asf.tick.summary`);
* ``probe``  — ``asf doctor``'s rows into ``tables/doctor.md``, at most once every
  ``watch.probe_every``, plus one ``probe`` event for the red required rows.

``tables`` and ``probe`` share the throttle: the expensive views (``status``, ``prod``) and the
doctor read ``gh``, the quota command and seven binaries, and the dispatch clock ticks every ten
minutes. The cheap, record-only views are written every tick.
"""

PARTS = ('tables', 'watch', 'probe')


def parts(ctx, now=None):
    """``[(name, thunk)]`` in order; each thunk returns an exit code."""


def run(ctx, out=print):
    failed = []
    for name, thunk in parts(ctx):
        rc, last = step_daily.run_part(thunk)
        if rc:
            failed.append(name)
        out(f"watch: {name} {'FAILED' if rc else 'ok'}" + (f' — {last}' if last else ''))
    if failed:
        raise StepFailed(f"watch parts failed: {', '.join(failed)}")
    return 0
```

`run_part` is imported from `asf.tick.step_daily` — the one "a part's failure never stops the
other parts" implementation, unchanged and unmoved.

`asf/tick/steps.py`:

```python
STEPS = ['record', 'health', 'wave', 'prs', 'harvest', 'batch', 'daily', 'watch']
ASF_CALLABLES['watch'] = 'asf.tick.step_watch:run'
```

Nothing else in `steps.py` changes: an undeclared step with an `asf` implementation resolves to
`asf` (P1), so no product yaml is refused for not knowing the name, and `steps: {watch: off}` is
an operator who reads their tables another way.

`sample/product.yaml`'s dispatch clock becomes `steps: [health, wave, prs, harvest, batch,
watch]`. On any other product `asf doctor` says the rest (P6):

```
NEEDS OPERATOR: step watch is on no clock — add it to a clock in products/<p>.yaml (steps: [..., watch])
```

### 2.2 `tables` — the six views, on the tick

```python
def write_changed(root, tables):
    """``write_tables``, but a table whose bytes are already on disk is not rewritten.
    Returns the names actually written."""
```

`tick.write_tables` gains that behaviour and keeps its name and signature; `run_shadow` gets it
for free. The part itself is:

```python
def part_tables(ctx, probe_due):
    root = ctx.record_root()
    names = CHEAP if not probe_due else None        # None = every view
    written = tick.write_changed(root, tick.render_tables(root, ctx.product, only=names))
    return f'{len(written)} of {len(names or tick.VIEWS)} changed'
```

`render_tables` gains one keyword, `only=None`, and a module constant:

```python
VIEWS = ('roadmap', 'backlog', 'parity', 'prod', 'sessions', 'status')
CHEAP = ('roadmap', 'backlog', 'parity', 'sessions')   # the record and the ledger, no subprocess
```

`prod` and `status` are the two that shell out (`asf/views/prod.py:17`,
`asf/views/status.py:57`), so they sit with the probe on the hourly throttle. The throttle is one
stamp file, `<state dir>/watch-probe.stamp`, holding the last probe's ISO stamp; due is
`now - stamp >= watch.probe_every` (a duration string, parsed by the parser
`asf.tick.stale` already uses for `stage_limits`), and a missing or unreadable stamp is due.

### 2.3 `watch` — what each session is doing, in the record

```python
def part_watch(ctx, now):
    """``tables/watch.md``: ``summary.render``'s two blocks over the live ledger and the runs that
    ended in the last 24 hours, titled from the clone's index. Written only when changed."""
    product = ctx.product
    since = summary.window_start(None, now)          # a fixed 24h window, not a clock stamp
    text = summary.render(summary.inflight_rows(product, pid_alive),
                          summary.done_rows(product, since, now),
                          summary.titles(product), since, now, first=False)
```

The window is a plain 24 hours, not `summary`'s per-clock stamp: the stamp answers *what happened
since I last looked*, which is a question about one clock's reader, and this file answers *what is
happening now*. `summary.run`'s own console output, its stamp and its per-clock window are
untouched — the tick still ends with the same two tables it ends with today.

`tables/watch.md` is the file the console reads instead of a `ps`, and it is the one table with a
line per live session:

```
IN FLIGHT — 3 sessions
job              item    kind  feature  account  model  status   since  what
coder-t-0070     T-0070  task  F-0098   acct-a   opus   working  41m    the classifier's own table
spec-f-0035      F-0035  spec  F-0035   acct-b   opus   working  6m     Thin controller — every read loop …

DONE since 2026-09-23T01:12:00Z — 1 session
job            item    kind  result                    took   what
fix-b-0094     B-0094  fix   finished, landed 26cb764  18m    the sample test's correction session
```

### 2.4 `probe` — the doctor on the tick

```python
def part_probe(ctx, now):
    """``asf doctor``'s rows into ``tables/doctor.md`` and one ``probe`` event for the red
    required ones. Skipped (and says so) when the throttle is not due."""
    rows = doctor.run(ctx.product.name)
    red = [name for name, required, ok, _detail in rows if required and not ok]
    ctx.event('probe', red=red, rows=len(rows))
    write_stamp(ctx.product, now)
    return f'{len(rows)} rows, {len(red)} red'
```

The table is the doctor's own `format` output, so `tables/doctor.md` and `asf doctor` say the
same words. The event is for `metrics`, not for filing: a red row becomes a Bug through the rule
engine or not at all (§1.4).

### 2.5 `harvest` — held where it is

No code changes. `steps.STEPS` carries `harvest` in fifth place with
`ASF_CALLABLES['harvest'] = 'asf.tick.step_harvest:run'` (84b4671), and `tests/test_tick_steps.py`
already has `HarvestStepTests`. What this Feature adds is the assertion the card's acceptance
asks for, in T4: `harvest` and `watch` are both `asf`-owned manifest steps, both appear in
`--manifest` with their callables, and both run alone under `--steps`. The console's `asf harvest`
stays; the *loop* is the tick's.

### 2.6 `asf/chores.py` — the ledger and the recorder

```python
"""asf.chores — what the controlling session typed, and which of it a script already does.

Three things, in one leaf module: the ledger (append one line per command a controlling session
```

One line, and the whole line:

```json
{"ts": "2026-09-24T08:14:02Z", "cmd": "gh pr list --state open --limit 50",
 "cwd": "/Users/…/asf", "product": "asf", "redacted": false}
```

* `cmd` — `tool_input.command` of the `PostToolUse` payload, whitespace-collapsed, truncated to
  400 characters. When `redact.scan_text` finds anything in it (P14), only the first token is
  written and `redacted` is `true`.
* `product` — the product whose `repo_dir` or `backlog_dir` contains `cwd`, else `null`. Read from
  the operator's product files, never guessed from a path shape.
* Nothing else: no output, no exit code, no session id, no account.

Not recorded at all: a call whose `tool_name` is not `Bash`; a session with `ASF_JOB` set; a
command whose first token is `asf` (it *is* the script); a command matching `chores.ignore`.

When it resolves, `install` merges `('PostToolUse', 'chores')` into that account's own settings

The install's rc is unchanged by it: a missing recorder is a missing measurement, not a broken

### 2.7 `asf chores` — the classifier

```
asf chores [--days 1] [--json] [--product P]
```

```
== CHORES 2026-09-24 — 41 commands, 17 covered, 6 repeated, 18 own
covered  9  gh pr list …                     → asf prs / asf status        (tables/status.md)
covered  5  ps axeww | grep claude            → asf workers sessions       (tables/watch.md)
covered  3  tail -n 40 ~/.ASF/logs/jobs/…     → asf sessions              (tables/watch.md)
repeated 4  git -C … log --oneline -5
own      1  gh api repos/…/actions/…
```

The map, and how a row is matched:

```python
#: ``(name, regex, use, table)`` — the command a script already covers, the script, and the file
#: the tick writes it into. ``{logs}``, ``{record}`` and ``{repo}`` are expanded at match time
#: from ``env.log_dir()`` and the product's own directories, never written as literals (P12).
COVERED = (
    ('prs',      r'^gh\s+pr\s+(list|view|checks|status)\b',   'asf prs / asf status',    'status'),
    ('runs',     r'^gh\s+run\s+(list|view|watch)\b',          'asf status',              'status'),
    ('sessions', r'^ps\b.*\|\s*grep|^pgrep\b',                'asf workers sessions',    'watch'),
    ('joblog',   r'^(tail|cat|less|head)\b.*{logs}/jobs/',    'asf sessions',            'watch'),
    ('record',   r'^(cat|grep|rg|ls|find)\b.*{record}/',      'asf backlog / asf parity','backlog'),
    ('doctor',   r'^(which|command -v)\s+(git|gh|gcloud|az|aws)\b', 'asf doctor',        'doctor'),
)

#: Never a chore, whatever the usage: what the constitution says the controller does by hand.
IGNORE = (r'\b(secret|token|password|credential|keychain|1password|op\s+read)\b',
          r'^gh\s+secret\b', r'^(vercel|flyctl|gcloud)\s+.*\b(deploy|promote|rollback)\b')
```

`chores.covered:` and `chores.ignore:` in `~/.ASF/config.yaml` are laid over both — an entry with
the same `name` replaces a built-in one, a new `name` appends, and `name: off` drops one. Every
regex is compiled case-insensitively at load; a regex that does not compile is named in a
`ChoresError` and the whole call refuses rather than silently matching nothing.

```python
def classify(rows, cfg=None, product=None):
    """``{'covered': [Chore], 'repeated': [Chore], 'own': [Chore], 'ignored': n}``.

    A row is `covered` when it matches a `COVERED` entry; `repeated` when it does not and the same
    normalised command appears ``chores.repeat`` times or more (default 3); `own` otherwise. A row
    matching `IGNORE` is counted and returned in neither list — it is work the controller is
    supposed to do by hand (R-0122).
    """
```

The normalised form a repeat is counted on is the command with quoted strings, numbers and
absolute paths replaced by `·`, so `tail -n 40 <log-a>` and `tail -n 80 <log-b>` are the same
chore. `--json` prints `{'day', 'days', 'total', 'covered': [...], 'repeated': [...], 'own':
[...], 'ignored', 'window_pct', 'account'}`, which is what §2.8 reads.

### 2.8 The rule, and `rules/controller-chores.sh`

The card, minted in the record by the Task that builds this (`asf new rule --title …`, so the id
comes from the record's counter — §1.4):

```yaml
id: R-<minted>
type: rule
title: Every read loop is the tick's, and a chore a script covers is a defect
check: tools/checks/controller-chores.sh
```

Its four body sections, the ones `asf new rule` writes the skeleton for:

| Section | What it says |
|---|---|
| `## Statement` | The controlling session decides and briefs. A command the controlling account ran that a factory script already covers is a defect in the factory, not a habit of the operator's. |
| `## Why` | On 2026-09-21 the controlling account reached 70 % of its weekly window doing chores a script already did. The window is the factory's scarcest input: spent on reads, it is not there for decisions. |
| `## Check` | `tools/checks/controller-chores.sh` — silent below 60 % of the weekly window; above it, one line per scriptable chore of the last day. `asf file-bugs` files the Bug. |
| `## Source` | This spec, §2.8, and F-0035's card. |

The core script, `rules/controller-chores.sh` in this repository — the first file in the
directory `rules.core_rules_dir()` and `hooks.RULES_DIR` already name:

```bash
#!/usr/bin/env bash
# The thin-controller check: over `chores.window_pct` of the controlling account's weekly window,
# every chore a script already covers is a violation. Exit 0 = clean, 1 = violations (one line
# each, stdout), 2 = the check could not run. Paths and thresholds come from `asf`, never from here.
set -uo pipefail

json=$(asf chores --json --days 1 2>/dev/null) || { echo "asf chores failed" >&2; exit 2; }

python3 - "$json" <<'PY'
import json, sys
d = json.loads(sys.argv[1])
pct, cap, acct = d.get('window_pct'), d.get('window_cap'), d.get('account')
if pct is None:
    print(f'weekly window unreadable for {acct} — not judged', file=sys.stderr)
    sys.exit(0)                       # the rule reports chores, not the meter (§1.4)
if pct < cap:
    sys.exit(0)
rows = d.get('covered') or []
if not rows:
    sys.exit(0)
for r in rows:
    print(f"{r['count']}× {r['cmd']} → {r['use']} ({r['table']}) — "
          f"{acct} at {pct:g} % of the weekly window")
sys.exit(1)
PY
```

`asf rules check` prefixes each line with the rule id (`rules.run_check`), `--json` carries them
as `violations`, and a check that times out, cannot run, or exits anything but 0/1 is itself a
violation — the existing behaviour, and the reason the script's own failures exit 2.

### 2.9 Filing — nothing new

`asf file-bugs` runs `asf rules check --json` on every tick from the `record` step, folds every
violation of one rule into one signature — `R-<minted>: rule violated` — with each violation line
as an evidence line, files or bumps a Bug at S2 under `conventions.default_bug_epic`, and skips a
signature whose `last_filed` is already today (P7). So the card's *"files them as a factory Bug"*
needs no code: the Bug arrives on the next tick after the rule first fails, is bumped rather than
duplicated on the days after, and carries the offending commands in its own body.
