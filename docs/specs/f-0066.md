# F-0066 — silence is one way a session dies; standing still is the other

The stall check measures one thing: the modification time of the job's log
(`asf/workers/stall.py:88-92`). Past `stage_limits.silent_min` with no result and a live pid, the
run is `STALL`; otherwise it is healthy. That is a correct test for a session that has stopped
writing, and it is blind to every session that keeps writing and gets nowhere. A run looping on a
command its permission rules deny writes two log lines a second — a `tool_use`, a `tool_result`
saying no — for as long as anyone lets it. Its log is never silent. It is never `STALL`. It holds
its worker seat, its account's quota and its item's branch until a token cap or the wall-clock cap
ends it hours later. Two jobs did exactly that on 2026-09-21, and the tables called both of them
healthy the whole time.

The reason the check cannot see it is not the rule, it is the input. A stream-json log carries no
clock: an `assistant` record, its `tool_use` blocks, the `result` records — none of them is
timestamped (`asf/tokens.py:92-120` reads the whole stream and finds no time in it). The file's
mtime is the *only* time the factory has, and mtime answers one question — "did anything arrive?"
— which is the question that a loop answers yes to.

So this Feature stamps the time itself. Once a minute, for as long as a run is alive, a sampler
reads what is new in that run's log and writes down four cumulative measurements beside a clock of
its own: the commit its worktree sits on, a digest of the files it has changed, how many distinct
tool classes it has used, and how many of its tool calls were not a repeat of a call it had just
made. Four numbers that only move when work happens. A run whose four are identical to the ones
it had twenty minutes ago is stalled — whatever its log did in between — and the tick ends it and
lets its own row relaunch it from the branch it already pushed. A run whose result text says it is
blocked or waiting for an answer is the other row the card asks for: not a stall, a question, and
the one thing the factory cannot decide for itself.

## 1. Decisions

### 1.1 In

- **One leaf module, `asf/progress.py`** (§2.1). The sample record, its store, the incremental log
  read, the worktree probe, the pure judge, the sampler loop, and the result record a stopped run
  is given. It imports the stdlib and `asf.env` and nothing else — the licence `asf/tokens.py`
  took for the same reason (P5): `asf.workers.runtime` must be able to read its one constant
  without a cycle.
- **The sampler is the spawner's own child** (§2.2). `spawn.spawn` starts
  `[sys.executable, '-m', 'asf.cli', 'workers', 'progress', --product, --job, --watch]` through
  `asf.detach.spawn` right after it appends the launch line, for a local run only. It samples every
  `SAMPLE_EVERY_S = 60` seconds and exits when the run's log carries a result, when its pid is
  gone, or at `WATCH_MAX_H = 24` — whichever comes first. `worker_pool.progress_sampler: false`
  turns it off; the launch never fails because the sampler did not start.
- **The health step samples before it judges** (§2.5). Minute resolution is the sampler's;
  *existence* of a fresh sample is not left to it. The tick's health step takes one sample per live
  local run itself, in-process, before the stall check reads any. A sampler that died, was never
  started, or is a version behind costs resolution and nothing else.
- **Four signals, and a `STUCK` row when none of them moved** (§2.3, §2.4). `progress.judge`
  compares the newest sample with the newest one at least `stage_limits.progress_min` (default
  **20**) minutes older. Identical `(commit, files digest, tool classes, novel calls)` → `stuck`;
  any difference → `moving`; no old-enough sample, or a newest sample older than the limit →
  `unknown`, which raises nothing. `stall.classify` gains the row *after* `STALL`: a silent run is
  still `STALL`, and `STUCK` is the row for the one that is writing.
- **The fourth signal is the card's loop, named exactly** (D4). "No new tool class" alone flags a
  session that spent twenty honest minutes reading (a reviewer over a diff calls two classes and
  writes nothing). `novel` — a tool call whose `(name, input)` digest is not among the previous
  `RING = 8` — separates the two: a denied command repeated forever is never novel, and reading
  ten different files is novel ten times.
- **An `INPUT` row off the result text** (§2.6). `report.needs_input(text)` returns the question a
  run's own result declares — a `NEEDS OPERATOR:` line, or a typed REPORT whose `status:` is
  `blocked` — or None. The stall check raises `INPUT` for any run of the product carrying one that
  has not been raised yet, live or just ended, and the tick prints the `NEEDS OPERATOR` line and
  appends one `needs-operator` event, once, marking the run so no later tick repeats it.
- **The tick acts on `STUCK`: probe, stop, and let the branch relaunch it** (§2.5). The branch is
  probed first (`progress.probe` — the head, the unpushed commits, the dirty files, printed as the
  row's evidence), then the run is stopped exactly as a capped run is stopped: `stall.stop_session`,
  one factory `result` line carrying a structured `asf.no_progress` object, and
  `no_progress: {…}` on its registry line. Health ends it on the next pass as
  `failed: no progress`, and the item's own feeder row launches on the same branch, in the same
  worktree, rebased onto the trunk — the relaunch that already exists (P20). Nothing new routes
  the item.
- **The second stall on one item is a hold, not a question** (D8). A run whose branch was already
  stopped for no progress once is held through `lifecycle.hold(..., 'no progress', …)` instead:
  the round on the item, the correction on the run, the ADJUDICATE row at the cap — the path
  `died twice` already takes (P9). The operator is informed by the hold, not asked.
- **The sessions stream carries the class** (§2.7). `progress` joins the `sessions` schema
  (`str|null`, default None) and `session_event` copies it off the registry record. The stall check
  writes the class onto the run's registry line whenever it changes, so an ended run's line carries
  the last class it was judged at and the stream's row carries it per session — the card's third
  acceptance.
- **`asf workers progress`** (§2.8). `--job J --watch` is the sampler the spawner starts;
  `--product P` alone prints one line per live run — its class, its four signals, its last tool
  call, and the tool classes of the last `WINDOW_MIN = 10` minutes — which is what an operator
  needs to tell a loop from a long build. Exit 1 when any live run is `stuck`.
- **`stage_limits.progress_min`**, in `docs/products.example.yaml` and `sample/product.yaml`, read
  by the same duration grammar `silent_min` uses (an int is minutes, `20m`/`1h` work too).

### 1.2 Out

- **The silence rule is untouched.** `silent_min`, `classify`'s mtime read and the `STALL` row keep
  their behaviour to the letter. This card adds a row; it does not move the one that exists, and a
  product that sets `progress_min: 0` is back to today exactly.
- **No denied-command pattern.** Nothing here reads the text of a refusal, matches "permission
  denied", or counts tool errors. The four signals catch the loop the card names without knowing
  what a refusal looks like, and a refusal string is a CLI-version-coupled fixture that would rot
  (D5).
- **No cloud lane.** A cloud run has no local log to read and no worktree to probe; `classify`
  already returns nothing for it (P3). The sampler is never started for one, its class is
  `unknown`, and neither new row can be raised against it. Progress off this host is its own card.
- **`continuation.dead()` keeps its own heartbeat.** F-0039's liveness test reads the same log
  mtime and has the same blind spot, and a session it wrongly calls alive costs a continuation, not
  a run. Converting it is a separate change over a separate contract (P18).
- **The fifteen-minute push instruction is still an instruction.** F-0063 §1.2 leaves enforcing it
  to "whatever card owns the heartbeat". This card owns the heartbeat and still does not enforce
  it: a run that commits without pushing *is* making progress by every signal here, and its
  failure is already measured, at its end, by B-0051's push gate.
- **No new stream, no new counter.** `STUCK` counts in the `ticks` stream's existing `stalls` —
  the card's title says it is a stall — and `INPUT` counts in nothing: it is a question, and the
  `needs-operator` event is where questions are already recorded. No key is added to `ticks`.
- **No operator table.** `asf/views/sessions.py` and the status header keep their columns; the new
  read is its own command (§2.8). Widening a rendered table is a table's card.
- **No supervision of the sampler.** Nothing restarts a sampler that died, and no doctor check
  counts them. The health step's own sample (§2.5) is what makes that a resolution loss instead of
  a blind spot, and a supervisor would be a second process to supervise.
- **The token meter gains nothing.** `tokens.meter` still reads four numbers and no tool name
  (P5); the tool-class read is this module's own pass, resumed from a byte offset, because the
  meter's contract is one pass for the four dimensions and nothing else.

## 2. The design

### 2.1 `asf/progress.py` — the leaf: a sample, a store, a judge

```python
"""asf.progress — what a run has actually moved, once a minute, with a clock of its own.

A stream-json log carries no timestamp (F-0066 P4), so "nothing has happened for twenty minutes"
cannot be read out of one. This module writes the time down instead: every SAMPLE_EVERY_S a
sampler appends one line to ``<state>/<product>/progress/<job>.jsonl`` holding the four
measurements that only move when work happens —

* ``commit``  the sha the run's worktree sits on,
* ``digest``  a hash of ``git status --porcelain``: which files it has changed,
* ``classes`` how many distinct tool classes it has used, cumulative,
* ``novel``   how many of its tool calls were not a repeat of one of the last RING calls,

— beside the sample's own ``at``, the log offset it read to, and the classes it saw since the
previous sample. :func:`judge` compares the newest sample with the newest one at least ``limit``
minutes older: all four equal is ``STUCK``, any difference is ``MOVING``, and not enough evidence
is ``UNKNOWN`` — never a stall (F-0066 D6).

A leaf: the stdlib and ``asf.env``, exactly the licence :mod:`asf.tokens` takes, so
:mod:`asf.workers.runtime` may read :data:`NO_PROGRESS` with no cycle.
"""
```

Constants and the record:

```python
DEFAULT_PROGRESS_MIN = 20       #: stage_limits.progress_min — the card's twenty minutes
SAMPLE_EVERY_S = 60             #: a line a minute
WINDOW_MIN = 10                 #: the card's window for "the tool classes in the last ten minutes"
RING = 8                        #: how far back a call is still a repeat (D4)
KEEP_SAMPLES = 180              #: three hours of samples; the file is rewritten past 2x
KEEP_DAYS = 7                   #: a progress file untouched this long is swept
WATCH_MAX_H = 24                #: a sampler never outlives this, whatever the pid says
NO_PROGRESS = 'no progress'     #: the failure signature (runtime.failure_reason, D12)

MOVING, STUCK, UNKNOWN, BLOCKED = 'moving', 'stuck', 'unknown', 'blocked'

SIGNALS = ('commit', 'digest', 'classes', 'novel')

Verdict = collections.namedtuple('Verdict', 'cls minutes evidence')
```

A sample is a flat dict — `at`, `bytes`, `calls`, `novel`, `classes`, `seen`, `last_call_at`,
`ring`, `commit`, `files`, `digest`, `result` — written one per line, JSON, newest last:

```json
{"at": "2026-09-27T14:03:00Z", "bytes": 4182344, "calls": 412, "novel": 377, "classes": 5,
 "seen": ["Bash"], "last_call_at": "2026-09-27T14:02:00Z", "ring": ["9f1c4ab21b8e"],
 "commit": "3ac0e21", "files": 3, "digest": "6b1fd0c4", "result": false}
```

The store:

```python
def store_dir(product):
    """``<state>/<product>/progress``, made on demand."""


def store_path(product, job):
    """One file per job. ``job`` is used as a file name: a job name is already a path component
    everywhere else in the factory (its worktree, its log, its brief)."""


def read(product, job):
    """The samples, oldest first, malformed lines dropped. ``[]`` for no file — never raises."""


def append(product, job, sample, keep=KEEP_SAMPLES):
    """One line on. Past ``2 * keep`` lines the file is rewritten to its newest ``keep`` — a ring,
    so a week-long run cannot grow one (D2)."""


def sweep(product, days=KEEP_DAYS):
    """Progress files untouched for ``days``, removed; the job names, for the caller to print."""
```

### 2.2 The reader — incremental, resumable, and its own pass

The sampler must not re-read the log it has already read: a spent session's log is the largest
file the factory writes (F-0063 D7 measured it in hundreds of megabytes). So the pass starts at
the previous sample's `bytes` and carries the previous sample's counters and ring forward:

```python
def scan(log, prev=None):
    """One incremental pass: ``(bytes, calls, novel, classes, seen, ring, result)``.

    Starts at ``prev['bytes']`` (0 with no ``prev``), stops at the last complete line, and never
    parses a partial one — the runtime is appending to this file as we read it. Each ``tool_use``
    block of an ``assistant`` record counts one call; its class is ``name`` (capped at 40, ``'?'``
    when absent); a call is *novel* unless ``_digest(name, input)`` is already in ``ring``, and
    the ring keeps the newest ``RING`` digests either way. ``classes`` is the cumulative count of
    distinct classes, carried forward through ``prev['seen']`` unions; ``seen`` is the classes
    this pass saw, and ``result`` is True once a ``result`` record has arrived.

    A ``system``/``init`` record is a run boundary exactly as it is for ``read_result`` and
    ``tokens.meter`` (B-0028): everything resets, because the log now holds a second run and the
    first run's calls are not this run's. Never raises: an unreadable log is ``prev`` unchanged.
    """
```

`classes` is a count, not a list, so the sample stays small; the *names* live in `seen`, per
interval, which is what makes the card's ten-minute window derivable from the file alone:

```python
def window_classes(samples, now, minutes=WINDOW_MIN):
    """The distinct tool classes seen in the last ``minutes``: the union of ``seen`` over the
    samples at or after ``now - minutes``, in first-seen order."""
```

The worktree half is two git calls, both cheap and both allowed to fail into nothing:

```python
def probe(worktree):
    """``(commit, files, digest)`` — ``git rev-parse --short HEAD``, and the line count and an
    8-hex digest of ``git status --porcelain``. ``('', 0, '')`` for a worktree that is gone, not a
    checkout, or whose git call failed: a probe that cannot read says nothing, and `judge` reads
    that as no movement in that one signal, never as movement."""
```

And one sample is the two halves plus the clock:

```python

    store's newest. ``last_call_at`` is this sample's ``at`` when ``calls`` grew, else the
    previous sample's — so "the last tool call time" survives a restart of the sampler."""
```

### 2.3 The judge — two lines, four signals, one word

```python
def signals(sample):
    return tuple(sample.get(k) for k in SIGNALS)


def judge(samples, now, limit):
    """``Verdict(cls, minutes, evidence)`` for one run.

    ``UNKNOWN`` when there are fewer than two samples, when the newest is older than ``limit``
    (nobody has measured this run recently — D6), or when no sample is ``limit`` minutes older
    than the newest. Otherwise the newest sample's :func:`signals` against those of the newest
    sample at or before ``now - limit``: equal is ``STUCK``, different is ``MOVING``. ``minutes``
    is how long the four have stood still (``STUCK``) or the span compared (``MOVING``).

    Pure: no clock, no git, no file. ``now`` is a unix time, ``limit`` is minutes.
    """
```

`evidence` is the one line a row, a log and a hold text all print — the diagnosis of the card's
loop in a sentence:

```
no commit, 0 files changed, 1 tool class (Bash) and no new call in 23m — last tool call 0m ago
```

```python
def evidence_line(samples, verdict, now):

    the last :data:`WINDOW_MIN` minutes with their count, whether ``novel`` moved, and how long
    ago the last tool call was. The line every reader of a ``STUCK`` row is given."""
```

### 2.4 The sampler, and the spawner that starts it

```python
def watch(product, job, every=SAMPLE_EVERY_S, alive=None, now=None, max_h=WATCH_MAX_H):
    """Sample ``job`` every ``every`` seconds until it ends; returns the number of samples taken.

    Ends on: a sample whose ``result`` is True (the run wrote its result), a pid that is gone
    (``os.kill(pid, 0)``), a registry line that is no longer live, or ``max_h``. It judges
    nothing and stops nothing — a sampler that exits early costs resolution, and the tick's own
    sample (§2.5) is what guarantees a fresh one. Every iteration is wrapped: an OSError in one
    sample is skipped, not fatal.
    """


def start(product, record, cfg=None, spawn_fn=None):
    """Start the sampler for a launch, detached; returns its pid, or None when it was not started
    — a cloud run (no local log), ``worker_pool.progress_sampler: false``, or a failure. A launch
    is never refused because the sampler did not start."""
    argv = [sys.executable, '-m', 'asf.cli', 'workers', 'progress',
            '--product', product.name, '--job', record['job'], '--watch']
```

`spawn.spawn` gains three lines after `pool_mod.append_session(product, record)` — the last thing

## 3. Acceptance tests

All from the root of this repository, stdlib only, hermetic: every test points `ASF_HOME` at a
tmpdir and builds its own git fixture and its own logs, as `tests/test_workers.py`'s `Home` and
`FakeRuntime` already do. No network, no real agent, no `sleep` — every clock is injected (`now=`)
and `watch` is driven by a fake `alive` and a scripted clock. The whole suite stays green:

```bash
cd "$(git rev-parse --show-toplevel)"
python3 tools/run_tests.py
```

**T1 — the sample: what a log and a worktree say, read incrementally.** `scan` over a
stream-json log counts one call per `tool_use` block, names each class, counts a call novel unless
its `(name, input)` digest is in the previous `RING`, resets everything at a `system`/`init`
boundary, stops at the last complete line when the file ends mid-line, and resumes from a previous
sample's `bytes` with the counters carried forward — asserted by comparing an incremental scan of
three appends against one scan of the whole file. `probe` returns the short head, the changed-file
count and a digest that changes when a file changes and not when the clock does; a missing
worktree is `('', 0, '')` and raises nothing. `sample` appends one line, and `last_call_at` holds
its previous value across a sample in which `calls` did not grow.

```bash
python3 -m unittest -v tests.test_progress.ScanTests tests.test_progress.ProbeTests tests.test_progress.SampleTests
```

**T2 — the judge, and what it refuses to say.** `judge` over two samples twenty minutes apart with
identical signals is `stuck` with `minutes == 20`; with any one of the four different it is
`moving`; over one sample, over samples spanning nineteen minutes, and over a newest sample
twenty-one minutes old it is `unknown` in each case. A sample whose probe failed (`commit == ''`)
never turns a `moving` run `stuck` on its own. `window_classes` returns the union of `seen` over
the last ten minutes, in first-seen order, and drops the samples outside it. `minutes_of` reads
`20`, `'20m'`, `'90s'`, `'1h'`, `'1d'` and falls back on nonsense; `progress_min` defaults to 20
and `0` disables the row.

```bash
python3 -m unittest -v tests.test_progress.JudgeTests tests.test_progress.WindowTests tests.test_progress.LimitTests
```

**T3 — a job looping on a denied command is flagged inside twenty minutes.** The card's second
acceptance, as a fixture: a live run whose log is appended to every simulated minute with the same
`Bash` `tool_use` and a `tool_result` refusing it — a log that is never silent, a worktree that
never changes, a pid that is always alive. At minute 19 the stall check returns no row for it; at
minute 20 it returns `('loop', 'STUCK', 20)` and its evidence line names one tool class, no commit
and no new call. The same fixture with the command's argument changing each minute is `moving`
at minute 20 and every minute after (D4), and the same fixture with its log left alone is `STALL`

## 4. Records

**Files, in this repository** — §2.9's footprint and nothing else.

**Files, per product (under `<ASF_HOME>`, never in the record)**

- `state/<product>/progress/<job>.jsonl` — new. One JSON sample per line, oldest first, rewritten
  to its newest `KEEP_SAMPLES` past twice that, swept after `KEEP_DAYS` untouched. Keys: `at`,
  `bytes`, `calls`, `novel`, `classes`, `seen`, `last_call_at`, `ring`, `commit`, `files`,
  `digest`, `result`. Operator-readable, machine-written, and safe to delete at any time — its
  loss is one run's resolution until the next sample.
- `state/<product>/stall-ack.txt` — unchanged in grammar, and now also acks `<job> STUCK` and
  `<job> INPUT` (P13).
- `logs/jobs/<product>/<job>.jsonl` — unchanged, read only, and now read incrementally rather than
  from the top.

**Rows on the session ledger** (`state/<product>/sessions.jsonl`, folded onto the run)

- `progress: <class>` — the last class the run was judged at (`moving` | `stuck` | `unknown`);
  written only when it changes.
- `no_progress: {minutes, evidence, at}` — the run was stopped for standing still.
- `input_flagged: 1` — its question has been raised; never raised again.
- `progress_pid: <pid>` — which process is sampling it. A fact, never judged on.

**What the run's own log gains**

One `result` record, appended by the factory to a run it stopped: `is_error`, `subtype: error`,
and a structured `asf.no_progress` object — which `runtime.failure_reason` reads as the signature
`no progress` and `health.result_reason` turns into `end_reason: failed: no progress` (P7, D12).

**Events the console sees**

- `metrics/events/<day>.jsonl` — one `needs-operator` event per `INPUT` run, once, carrying the
  job, the item and the question; and the existing `held` event when a second no-progress stop
  holds the item.
- `sessions` stream — one new column, `progress`, per session row.
- the tick's own lines: `STUCK <job> no progress <n>m — <evidence>`, `INPUT <job> needs input —
  <question>`, and the probe line before a stop. `ticks.stalls` counts the `STUCK` rows with the
  `STALL` and `DEAD` ones; the `INPUT` rows are counted nowhere (§1.2).
