# F-0228 — the factory retries a refusal forever and pays the hook every time

`republish_steps` (`asf/workers/health.py:510-550`) is F-0094's answer to a real failure: a run
whose publish the factory refused kept its commits in its worktree and *no later pass ever tried
again*, so the item waited for a whole new session even after the refusal's cause was fixed. Every
health pass now publishes such a run's worktree again.

It retries with no memory. The whole of this card follows from four lines:

```python
    ev = lifecycle.gather(product, run, alive=alive)
    reason, ev, line = yield (product, run, ev, reason, alive)  # publish_gap, by run_steps
    ...
    if line == run.get('publish_refused'):
        return
```

The `yield` is the publish — `publish_gap` → `lifecycle.publish` → `gitpush.push`, and the
product's own pre-push hook. The memory check is *after* it. So a run refused by the hook has the
hook run again on the next tick, and the next, on a branch whose head has not moved and whose
`origin/<branch>` has not moved either: the same inputs, therefore the same refusal, therefore the
same wasted minutes. `run['publish_refused']` — recorded at `:544` — suppresses only the **print**
at `:550`. The push itself is unconditional.

The cost is measured, not estimated (2026-09-28, one host, after #186):

* `cloud/spec-mobile-pass` costs **~31 s of every tick** this way — one branch, one refusal, no
  change to either side of it.
* the hook takes **16–182 s** per run on that host.
* before #186 parallelised them, publish pushes were **77% of a sampled health step — 376 s of
  490 s**. Parallelising three at a time divided the wall clock; it did not stop the work. A
  refusal that will be refused identically is the one publish that should not be attempted at all.

There is a second half, and it is what makes the first half safe. Today the endless retry is also
the only thing keeping a refused run's fate visible: `:542`'s early return means the refusal is
printed **once**, and `:546` replaces the text of a pending `UNPUSHED` correction with the
factory's own refusal — but only when the run's correction is of that one kind. A run whose
correction was dropped (its card changed, its Feature re-planned) or whose correction is of another
kind records `publish_refused` and takes **no hold at all**. Today that run is at least retried
every tick, so a fixed cause eventually clears it. Stop retrying it and it becomes a silent dead
end: commits in a worktree, no push, no hold, no session, nothing printed. So the skip and the hold
are one change, and the card asks for both.

## Decisions

### In

* `Evidence` gains the worktree's own HEAD sha, so the "local head" half of the pair is a fact
  health already gathers rather than a new git call at the call site.
* A refused publish records the pair `(local head, origin tip)` it was refused at, beside the
  refusal line it already records.
* `republish_steps` skips its publish — the `yield`, so `publish_gap`, `lifecycle.publish` and the
  hook are never reached — while a refusal is remembered and both halves of that pair still read
  the same, and the worktree holds nothing uncommitted.
* Either half moving forgets the refusal: the publish is attempted again on that tick.
* Every newly recorded refusal leaves a hold carrying the refusal's own reason, routed by the same
  ladder the live end-of-run path already uses for the same texts.

### Out

* **`PUBLISH_WORKERS` and `run_steps`.** The parallelism of #186 is unchanged; this card removes
  work rather than re-arranging it. `tests/test_health_publish_steps.py`'s five existing tests hold
  byte for byte.
* **The live end-of-run path** (`health.steps`, `health.py:712-792`). A run ends once, so it makes
  one publish; there is no retry there to skip. Its `push_retry` ladder, its `hook_refusal_hold`
  and its rounds are untouched.
* **A refused `commit_leftovers`.** Its line is `commit <branch> refused: …`
  (`lifecycle.py:1297-1301`), so it is recorded as a refusal today and will be recorded as one
  after this card — but the worktree still holds uncommitted files, so the skip never applies to it
  and it is retried every tick exactly as now. That is a loop over the *commit* hook, on files that
  can change under it; naming it is not fixing it, and it is not this card's.
* **`asf.improve.measure.Run` and the scorecard.** `diagnose` reads `publish_refused`; it gains no
  reader for the new key and no new sub-cause. Nothing in `asf/scorecard/` changes.
* **Retiring `publish_refused`.** The existing key keeps its exact meaning and its exact writer.
  The pair is a second key beside it, never a replacement, so every ledger already on disk reads
  unchanged and `diagnose.sub_cause` is not touched.

| --- | --- | --- | --- |
| **D1** | The remembered pair is **one new `RUN_FIELDS` key**, `publish_refused_heads`, holding `'<head> <tip>'` — the origin tip written as `-` when the branch is not on origin. | A dict beside `publish_refused`; two separate keys; folding the pair into `publish_refused`'s own string. | One key is one comparison and one `grep` in the ledger. The `-` sentinel keeps the field two tokens always, so a truncated or hand-edited value can never compare equal by accident. |
| **D2** | The local head is read by **`gather`, into a new `Evidence.head`**. | `git rev-parse HEAD` at the call site in `republish_steps`, through `health._git`. | `Evidence` is the one answer to "what the world says about one run", and `gather` is already in that worktree running `git status` (P3). Every `Evidence` construction is keyword and nothing enumerates its fields (P2), so the field costs nothing. |
| **D3** | The skip is a **pure predicate**, `health.refusal_stands(run, ev)`, and the change to `republish_steps` is one `if … : return` before the `yield`. | Testing the skip only through the full git fixture in `tests/test_workers.py`; putting the comparison inline. | The card asks for a test *beside* `tests/test_health_publish_steps.py`, and that file is exactly this: unit tests of a `health` helper with no repo, no network, no clock. A pure predicate over `(run dict, Evidence)` is provable in milliseconds for every case — both halves unchanged, each half moved, no refusal recorded, an unreadable head, uncommitted files — where a git fixture can afford one or two. The fixture test then proves only the wiring: the publish is not called. |
| **D4** | **`publish_gap` re-gathers the evidence after a refused publish too**, so the `ev` it returns always describes the worktree as it stands after the attempt. | Remembering the pre-attempt pair; re-gathering inside `republish_steps` on the refusal branch. | P5: a successful rebase or an account-name rewrite moves HEAD and *then* refuses. Remembering the pre-attempt head would remember a sha the worktree no longer has, so the next tick would see a "moved" head, retry, pay the hook again, and only settle on the tick after — one wasted hook run per refusal of that shape, every time the cause recurs. Re-gathering in `republish_steps` would fix the pair and leave the returned `ev` wrong for anything else that reads it. The symmetry is one line at `health.py:414` and it makes the pair correct by construction. |
| **D5** | A refusal whose class is **`NETWORK_ERROR` is never remembered**: the pair is written only for a refusal `push_failure` calls `HOOK_REFUSED`, or calls nothing at all (a stale head, a rebase conflict, a refusal it does not name). | Remembering every refusal uniformly. | A transport error is not a property of the branch. Its `(head, tip)` pair is unchanged by definition, so remembering it would skip every later tick and turn a blip into a permanent stall — the exact failure F-0094 exists to prevent, re-introduced. The live path already treats a blip as "published again next pass" and spends no round (`health.py:725-727`); the republish path must agree. |
| **D6** | The skip also requires **`ev.uncommitted == 0`**. | Comparing the head and the tip alone. | A run that gains uncommitted files after its refusal has work `publish_gap`'s `commit_leftovers` would commit (B-0094) and a head that has not moved *yet*. Skipping on the pair alone would leave that work in the worktree forever. This is also what keeps a refused `commit_leftovers` retrying exactly as it does today (**Out**), with no special case for it. |
| **D7** | A newly recorded refusal takes a hold **only when no pending correction already carries it**, and the ladder is chosen from the refusal's own class: `HOOK_REFUSED` → `hook_refusal_hold`, a rebase conflict → `rebase_conflict_hold`, otherwise `hold(…, UNPUSHED, …)`. The existing `:546` behaviour — replacing a pending `UNPUSHED` correction's text with `refusal_text` — is unchanged and keeps its precedence. | Always writing a hold; always `hook_refusal_hold`; leaving the gap open. | Always writing one would re-hold a run whose hold already says the right thing and would spend a round on every recurrence. Always `hook_refusal_hold` would label a rebase conflict a hook refusal and route it into the redaction park. Choosing by `push_failure` is the same routing the live path performs on the same texts (P6, P7), so there is one ladder in the product, not two. Leaving the gap open is what makes the skip a dead end. |
| **D8** | A **skipped** tick prints nothing and writes nothing. | A line per skipped run per tick; a counter on the row. | The skip is the absence of a transition, and `health` reports transitions. A stuck run is already visible: it is `held`, with a correction, in `asf status` and in the session registry, and its refusal was printed on the tick it was recorded. A line per stuck run per tick would grow the health output forever and would re-introduce, in the log, exactly the noise this card removes from the network. |

## The design

Three files. `asf/workers/lifecycle.py` gains one field and one tuple entry; `asf/workers/health.py`
gains two small functions and six lines inside `republish_steps`; `tests/test_workers.py` has one
assertion corrected.

### 1. The fact — `asf/workers/lifecycle.py`

`Evidence` gains one field, after `uncommitted` and before `remote_sha`, so the local facts stay
together:

```python
    head: str = ''               #: the worktree's HEAD sha; '' when it could not be read
```

`gather` fills it in the block that has already proved the worktree readable — immediately after
`ev.uncommitted` is set and before the `if branch:` block:

```python
    ev.head = _git(['rev-parse', 'HEAD'], wt).stdout.strip()
```

Both of `gather`'s early returns (no worktree, `git status` failed) leave it `''`, and `''` is the
value `refusal_stands` refuses to compare (D3).

`RUN_FIELDS` gains the pair's key as its last entry:

```python
RUN_FIELDS = ('ended', 'end_reason', 'rc', 'corrected', 'operator_flagged', 'harvested',
              'harvest', 'correction', 'rounds', 'stop_tip', 'capped', 'runtime_session',
              'resumed', 'continued', 'publish_refused', 'publish_refused_heads')
```

### 2. The memory — `asf/workers/health.py`

Two pure functions, beside `refusal_text`:

```python
#: The pair a refused publish is remembered by: the worktree's own HEAD and origin's tip for the
#: branch. Both halves are what the refusal was a function of — the hook reads the commits being
#: pushed, the lease and the rebase read the tip — so while neither has moved the next push has
#: the same inputs and earns the same refusal. The tip is `-` when the branch is not on origin, so
#: the value is two tokens whatever the evidence says.
def refusal_heads(ev):
    return f'{ev.head} {ev.remote_sha or "-"}'


def refusal_stands(run, ev):
    """Whether ``run``'s recorded refusal still describes the worktree, so publishing again would
    run the product's pre-push hook (16-182 s) for inputs that cannot have changed the answer.
    Pure: no git, no clock. False when nothing was refused, when the head could not be read, when
    either half of the pair has moved, and when the worktree holds uncommitted work the factory
    would commit first (B-0094, D6)."""
    if not run.get('publish_refused') or not ev.head or ev.uncommitted:
        return False
    return bool(run.get('publish_refused_heads')) \
        and run['publish_refused_heads'] == refusal_heads(ev)
```

`republish_steps` gains the guard between its gather and its yield:

```python
     ev = lifecycle.gather(product, run, alive=alive)
+    if refusal_stands(run, ev):
+        return  # F-0228: same head, same tip — the same refusal, and the hook costs minutes
     reason, ev, line = yield (product, run, ev, reason, alive)  # publish_gap, by run_steps
```

The `return` is before the `yield`, so the generator ends there: `run_steps` pops it, no entry
reaches `publish_gap`, no thread is handed a publish, nothing touches the network. This is the
whole saving.

Its refusal branch records the pair and takes the hold:

```python
     if line == run.get('publish_refused'):
         return
-    fields = {'publish_refused': line}
+    why = line.split('refused: ', 1)[-1]          # never the whole line: HOOK_RE matches 'refused'
+    cls = lifecycle.push_failure(why)
+    fields = {'publish_refused': line,
+              'publish_refused_heads': None if cls == lifecycle.NETWORK_ERROR
+              else refusal_heads(ev)}             # a blip is never remembered (D5)
     corr = run.get('correction')
+    held = None
     if isinstance(corr, dict) and corr.get('kind') == lifecycle.UNPUSHED:
         fields['correction'] = dict(corr, text=refusal_text(branch, line))
+    elif lifecycle.pending_correction(run, registry) is None and cls != lifecycle.NETWORK_ERROR:
+        # nothing pending carries this refusal, and with the retry gone nothing else will
+        text, now = refusal_text(branch, line), pool_mod.now_iso()
+        if cls == lifecycle.HOOK_REFUSED:
+            more, held = lifecycle.hook_refusal_hold(registry, run, text, now)
+        elif lifecycle.rebase_conflict(line):
+            more, held = lifecycle.rebase_conflict_hold(registry, run, text, now,
+                                                        main=product.main)
+        else:
+            more, held = lifecycle.hold(registry, run, lifecycle.UNPUSHED, text, now,
+                                        main=product.main)
+        fields.update(more)
     pool_mod.update_session(product, job, **fields)

     found.append((job, 'published', line))
+    if held:
+        found.append((job, 'held', held.split(': ', 1)[1]))
```

`publish_refused_heads: None` for a network blip is the same clearing idiom `publish_refused: None`
already uses on the success branch (`:535`): `strip_nulls` (`lifecycle.py:261`) drops a `RUN_FIELDS`
key written `None`, so the pair is forgotten rather than stored empty.

Its success branch clears both keys together:

```python

-                  'publish_refused': None}
+                  'publish_refused': None, 'publish_refused_heads': None}
```

### What it looks like when it is there

One health pass, one branch whose hook refuses, over three ticks:

```
tick 1   published   —   publish cloud/spec-mobile-pass refused: pre-push hook declined: 3 findings
         held        —   your commits are on the branch; the factory could not publish them: …
tick 2   (nothing: the head and the tip both read the same — no push, no hook, ~31 s not spent)
tick 3   (nothing)
```

The session answers the hold and commits. `Evidence.head` moves, `refusal_stands` is False, the
publish is attempted on that tick, and it goes out:

```
tick 4   published   —   published cloud/spec-mobile-pass at 1a2b3c4d5 (rebased; lease held)
         re-judged   —   finished
```

Someone pushes onto `origin/<branch>` instead: the tip moves, the pair no longer matches, and tick 4
publishes for that reason alone — the lease and the rebase both read that tip, so a refusal that
depended on it is genuinely stale.

## Acceptance tests

Four blocks. The first is the card's own test, beside the file it names; the second is the wiring
through a real repository; the third and fourth are the regression surface.

### The skip and the forgetting — `tests/test_health_publish_steps.py`'s neighbour

A new file, `tests/test_health_republish_retry.py`. Unit tests of `health.refusal_heads` and
`health.refusal_stands` over hand-built `lifecycle.Evidence` and plain run dicts: no repository, no
network, no clock, and **no subclass of any `TestCase` harness** — a bare `unittest.TestCase`, so
the file runs only its own tests.

```bash
python3 -m unittest -v tests.test_health_republish_retry
```

Asserts:

* `refusal_heads` is `'<head> <tip>'`, and `'<head> -'` when `remote_sha` is `''`.
* A refusal recorded at a pair, evidence reading that same pair → `refusal_stands` is True.
* A new local commit (head moved, tip the same) → False.
* Origin's tip moved (head the same) → False.
* Both moved → False.
* No `publish_refused` on the run, whatever the pair says → False.
* No `publish_refused_heads` on the run — a refusal recorded by a build before this card → False,
  so the first tick after the upgrade publishes once and records the pair.
* `ev.head == ''` (an unreadable worktree) → False, even when the recorded value happens to be
  `' <tip>'`.
* `ev.uncommitted == 1` with the pair matching → False (D6).
* A branch not on origin, refused and unchanged (`'<head> -'` both sides) → True.

| The run row | the same | `publish_refused` keeps its exact meaning, its exact format and its one writer. `diagnose.sub_cause` reads it unchanged. |
| The correction | the run's `correction` object | unchanged when a pending `UNPUSHED` correction already carries the refusal — that text replacement is today's behaviour and keeps its precedence. Otherwise one new hold, kind `hook refused`, `rebase conflict` or `unpushed` by the refusal's own class (D7), with `refusal_text`'s text: the conflicting files, the lost commits, the `redact: <file>:<line>` finding or the hook's own last line — never the generic "commit and push what you have". |
| The health pass | `found` | `('<job>', 'held', …)` beside the existing `('<job>', 'published', <refusal line>)` when a hold is written. A **skipped** run adds nothing (D8). |
| Nothing written | — | no new file, no new state directory, no scorecard key, no cause card, no migration. A ledger written before this card reads correctly: a run carrying `publish_refused` and no `publish_refused_heads` publishes once more, records the pair, and is quiet after that. |
| The evidence | `asf.workers.lifecycle.Evidence` | `head` — the worktree's HEAD sha, `''` when unreadable. Read by `refusal_heads` and `refusal_stands`; every other reader of `Evidence` is unchanged. |

**A follow-up this card names but does not build:** a refused `commit_leftovers` is retried every
tick on unchanged uncommitted files, running the repo's *commit* hooks each time
(`lifecycle.py:1288-1302`). This card deliberately keeps that retry (D6) because the files can
change under it, and does not measure it.
