# F-0155 — a sha on the line, so "which copy is this" has an answer you can quote

The card: `asf next` and `asf status` read `product.backlog_dir` while the tick's wave reads its
own clone, so NEXT lags the tick by a cycle plus a pull, and two cards looked "missing" on
2026-09-26. Its **Expected** is an OR with a tail:

> next and status read the same record the tick acts on (the state clone), **or** pull it first
> **and** print the record sha they read.

The first branch of that OR — and the pull — are already a spec and a plan on the trunk, under
**F-0122** (`docs/specs/f-0122.md`, `docs/plans/f-0122.md`, plan landed `dbdfae8d0`). F-0122
makes the tables read whichever copy holds the newer `index.json`, fast-forwards the checkout on
every tick exit, gives every table's first line an age, and brings `asf next` into that set. None
of its six Tasks has been coded (P4). So the *queue lag itself* is not this card's work any more;
re-specifying it would put two plans on the same four files.

What F-0122 does **not** give is the tail: an **identity**. Its line says how *old* the index is
(`index generated 3m ago`) and never says *which commit* the copy sits at. Age answers "is this
fresh"; it does not answer "is this the same record you are looking at" — which is the question
the 2026-09-26 incident was actually diagnosed by, one operator holding two copies open and
comparing them by hand, with no handle printed by either.

So F-0155 is one clause: every table's first line names the short HEAD sha of the copy it read,
and when it read the tick's clone it names both shas. Two local `git rev-parse`, no fetch, no
network, and a missing sha can never stop a table printing.

    record: /…/record @ a1b2c3d — index generated 3m ago
    record: /…/state/<p>/record (the tick's clone) @ a1b2c3d — index generated 3m ago;
      your checkout /…/backlog @ 9f8e7d6 is 2h older — git -C /…/backlog pull

### In

- **`freshness.head_sha(root)`** — one local `git -C <root> rev-parse --short HEAD`, guarded the
  way `cli._checkout_git` is guarded (P7): `None` for a path that is not a work tree, a repo with
  no commit, a missing `git`, a non-zero exit, or a read that takes longer than five seconds.
- **`Fresh` carries the commit of each copy the line names** — `sha` for the copy picked, and
  `checkout_sha` for the operator's own copy, set only when the clone was taken.
- **The line carries them**: `@ <sha>` after the path, on both paths it names. When a sha is not
  readable the clause is simply **absent** and every other word of the line is unchanged.
- **At most two `rev-parse` per command**, both local, and never a `fetch`.
- **The guide says what the sha is for** — one paragraph in `docs/guide/operating.md`, with a
  prose assertion in `tests/test_readme.py`, the precedent P16 of F-0122 already relies on.

### Out

- **Everything F-0122 owns**, entire: which copy a table reads, `pick`, `generated_at`,
  `clone_index_root`, `ASF_RECORD=checkout`, the tick's fast-forward on every exit, the index age
  on the line, `asf next` joining the tables, the `doctor` row, and the guide's *pull before you
  read* paragraph. This spec edits F-0122's design; it does not restate it, and its plan must not
  mint a Task that writes what one of F-0122's six already writes (**Ordering**, below).
- **Any fetch, pull or network read in a view.** A table stays a read. The sha names the commit
  the copy *is at*, never whether that commit is current — F-0122's `generated` comparison is the
  only currency signal, and it needs no git (D2, P6).
- **`index.json` gaining a `record_sha`** — see D3.
- **The `--json` payload's shape.** See D4.
- **`asf status`'s **Record** row, and `asf doctor`.** status's first line carries the sha like
  every other table's; its rows are untouched, and the doctor's record row is F-0122's Story 4.

### Ordering — this is a hard dependency, not a preference

Every file this change touches is in the `writes:` of an F-0122 Task that has not landed (P4):
`asf/views/freshness.py` and `tests/test_views_freshness.py` are Task 3's, `asf/cli.py` and
`asf/feeder/render.py` are Task 4's, `docs/guide/operating.md` and `tests/test_readme.py` are
Task 6's. There is no ordering of this work that does not sit **after** F-0122's Tasks 3, 4 and 6
are on the trunk:

- Landing F-0155 **first**, on today's `cli.resolve_record`, puts `@ <sha>` on the nine tables and
  then *silently loses it* the moment Task 4 routes them through `freshness.view_record`, which
  builds its own line and calls `resolve_record(announce=lambda _l: None)` (P5). The clause would
  survive only on the record commands, which are exactly the ones it is not for (P9).
- Landing the two **in parallel** is two plans writing the same four files.

So the plan that follows this spec carries `after: F-0122` on every Task, and if F-0122's design
moves during its own coding — the namedtuple's fields, the wording of `line`, the entry point's
name — this design moves with it. That is the cost of the split, and it is stated here rather than
discovered in a rebase.

## The design

Everything below is a diff against **F-0122's design as specced**, which does not exist in the
tree yet (P4). Line numbers are into `docs/specs/f-0122.md`.

### `asf/views/freshness.py` — the module docstring stops promising no git

`docs/specs/f-0122.md:159`, the last paragraph of the module docstring:

```diff
-So: a table reads the checkout unless the clone's ``index.json`` was generated *later*, and its
-first line always carries the index's age, naming the copy and the operator's lag when it took
-the clone. Two file reads, no git, no network — safe to run in front of every table.
+So: a table reads the checkout unless the clone's ``index.json`` was generated *later*, and its
+first line always carries the index's age and the short commit of the copy it read, naming the
+copy, the operator's lag and their own commit when it took the clone. Two ``index.json`` reads
+decide *which* copy (no git: F-0122, D2); naming the copy then costs at most two local
+``git rev-parse --short HEAD`` — no fetch, no network, and a sha that will not read is dropped
+from the line rather than failing it (F-0155, D6).
```

### `asf/views/freshness.py` — `head_sha`

New, beside `generated_at`:

```python
def head_sha(root):
    """``root``'s short HEAD, or None — ``git -C <root> rev-parse --short HEAD``.

    What it is: the commit the copy *is at*, so two copies of the record can be named and
    compared by hand (F-0155). What it is not: a currency check. It runs no ``fetch`` and
    decides nothing — :func:`pick` chooses the copy from the two ``generated`` stamps, with no
    git at all (F-0122, D2).

    None for anything that does not answer: a path that is not a work tree, a repository with no
    commit yet, a missing ``git``, a non-zero exit, a read slower than five seconds. The caller
    drops the ``@ <sha>`` clause and prints the rest of the line — an identity clause must never
    be able to stop a table printing (D6).
    """
    try:
        out = subprocess.run(['git', '-C', root, 'rev-parse', '--short', 'HEAD'],
                             capture_output=True, text=True, timeout=5)
    except (OSError, subprocess.TimeoutExpired):
        return None
    return (out.stdout.strip() or None) if out.returncode == 0 else None
```

### `asf/views/freshness.py` — `Fresh` carries the two commits

`docs/specs/f-0122.md:173-176`:

```diff
 #: What :func:`pick` decided. ``source`` is ``'checkout'`` or ``'clone'``; ``older_s`` is how many
 #: seconds behind the clone's index the checkout's own is, and is None unless ``source`` is
-#: ``'clone'``.
-Fresh = collections.namedtuple('Fresh', 'root source generated age_s checkout older_s')
+#: ``'clone'``. ``sha`` is the short HEAD of ``root`` and ``checkout_sha`` that of ``checkout``;
+#: ``checkout_sha`` is None unless ``source`` is ``'clone'`` (otherwise it is ``sha``), and
+#: either is None when the copy is not a git work tree (F-0155).
+Fresh = collections.namedtuple(
+    'Fresh', 'root source generated age_s checkout older_s sha checkout_sha')
```

`pick` fills them as its last act, after it has decided the copy — one `head_sha` when it kept the
checkout, two when it fell back. Nothing about the decision itself changes: no branch of `pick`
reads a sha, and a `head_sha` returning None changes no outcome.

### `asf/views/freshness.py` — `line`

`docs/specs/f-0122.md:203-211`:

```diff
 def line(fresh):
-    """``record: <path> — index generated 3m ago``, and when the clone was taken:
+    """``record: <path> @ a1b2c3d — index generated 3m ago``, and when the clone was taken:

-    ``record: <clone> (the tick's clone) — index generated 3m ago; your checkout <path> is 2h
-    older — git -C <path> pull``
+    ``record: <clone> (the tick's clone) @ a1b2c3d — index generated 3m ago; your checkout
+    <path> @ 9f8e7d6 is 2h older — git -C <path> pull``

     An index with no readable ``generated`` says ``index age unknown`` rather than a made-up
     number. The ages are ``index_reader.span``'s buckets, the same ones every other table uses.
+
+    A sha that would not read is **dropped**, not guessed: that copy is named by its path alone
+    and every other word of the line is unchanged (F-0155, D6). Both clauses are dropped
+    independently — the clone's sha being unreadable does not cost the checkout its own.
     """
```

The clause is a suffix on the path, in one helper so the two sites cannot drift:

```python
def _at(path, sha):
    """``<path> @ <sha>``, or ``<path>`` when the sha would not read (D6)."""
    return f'{path} @ {sha}' if sha else path
```

```

```

```

```


— the third being a record root that is not a git work tree: the same line, one clause short.

## Records

This change writes **nothing** to the record, and nothing to disk.

- **No file.** No card, no `tables/` output, no state file.
- **No row and no key.** `index.json` gains nothing; `generated` stays the only provenance it
  carries (D3, P10). `schema.record_version` does not move, and no migration is needed.
- **No event.** Nothing is appended to `metrics/events/<day>.jsonl`.
- **No git write.** `rev-parse` is a read; no view fetches, pulls or commits.

What it writes is one line to a terminal, in one place —
`asf/views/freshness.line`, reached through `view_record` — and one paragraph to
`docs/guide/operating.md`. The only durable record of the change is those two files, their tests,
and the sign-off on the commits.

Two reads are added per command that prints the line: at most two `git rev-parse --short HEAD`,
both local and both five-second-bounded, in front of a `/asf:*` table that already does a file
