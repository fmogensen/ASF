# F-0286 — the watch that answers this card is written, and nothing says whether it is the one acting

The card's incident, as the operator recorded it on 2026-10-07 21:33 local — the host names
redacted, as this public repo requires:

```
STALL runner=<runner> job=gate-tests run=37670494471 elapsed=1206s silence=492s max=1183s cpu=18.3
ACT cancel run=37670494471
```

Three things are wrong in those two lines. The job was **using CPU** (18.3%), so it was working,
not hung; its **max was hand-kept** (1183 s, barely above the job's own normal length) in a JSON
file an operator edits when a job grows. The cancel was **never claimed** in `ci-cancels.json`,
so the run reads to the rest of the factory as a host cancel rather than as something the factory
chose, and it was **never re-run** — so a priority land-requested goal PR (#1070) sat on a
cancelled run with every heavy job dead, and the only trace of why was one line in a log file on
the box.

The watch that fixes all three is already in the tree, landed under this id. Measured in this
worktree at `78c06aa`:

- **`asf/ci_stall.py`** is the stall watch inside the package, wired as `asf ci stall-watch`
  (`asf/ci_queue.py:4672`) with five config keys under `ci.stall_watch`
  (`asf/config_keys.py:119-124`).
- A stall is **no longer a clock alone**: `judge` requires silence past `SILENCE_S` *and* elapsed
  past the job kind's **measured** p95 × `FACTOR` (`asf.ci_measure`'s green readings, the
  runner's own else the fleet's, re-measured daily) *and* a CPU rate under `CPU_FLOOR`. A slot
  first seen in a pass has no rate yet and is never a stall. The card's job — 18% CPU, 1206 s
  against a hand-kept 1183 s — is not a stall to this watch twice over.
- A cancel is **claimed before it is made**, then made the queue's one way
  (`ci_queue._cancel_run`) and claimed in `ci-cancels.json` as `stall`
  (`ci_queue.claim_cancel`); `stall` is a member of `ci_cancels.CAUSES` and of `HONOURED`.
- A cancelled run's failed jobs are **re-run once** when it completes (`_advance`).
- `tests/test_ci_stall.py` proves all of it and is green (51 tests with its two siblings).

So the code half of this card is closed, and it is easy to mistake that for all of it. What is
left is the half that decides whether any of the above ever runs on the host — and today the
answer is no.

The acting watcher is still the operator script the module was written to replace. While that
script keeps writing its `claims.json`, `asf ci stall-watch --apply` **degrades to report and
cancels nothing** (`LEGACY_QUIET_S`, "one watcher acts at a time") — correctly, because both
acting would cancel and re-run one stall twice. Moving the host's timer off the script is the
operator's step, and the module says so in as many words: *"this module never touches the script
or its timer."* Until that step is taken, every stall is still cancelled by the script, unclaimed
and un-re-run, exactly as the card describes.

Nothing in the product says which of those two states the host is in. `asf doctor` has a
`ci heartbeat` row for box freshness (`asf/doctor.py:1668,1907`) and no row for the watch at all;
`ci-stall.json` carries `claims`, `cpu` and `max` and no stamp of the last pass or the mode it
ran in, so there is nothing a row could read even if one existed. And in report mode the watch
does not merely withhold new cancels — `_advance` is behind the same gate, so a run this watch
already cancelled in `act` has its **owed re-run frozen**: measured below, it stays `cancelled`
with no re-run and not even a give-up, until the 48-hour prune drops the claim. That is the
card's second defect, intact, in the one mode the watch actually runs in today.

This feature closes that half: the pass records itself and its record survives, `asf doctor`
shows which watcher acts, and a cancel this watch made is always finished.

### In

1. **The pass records itself, and its record survives.** Every pass stamps one `pass` block into
   `ci-stall.json` — when it ran, the mode it ran in, what it found, and whether the legacy
   script held it back — and both `ci-stall.json` and `ci-heartbeat.json` are named in
   `asf.state.registry`, so the reaper never takes the claims the owed re-runs live in (P10).
2. **`asf doctor` carries a `ci stall` row.** The cutover's state is visible: red while the mode
   says `act` but the operator script still holds the timer (every stall is being cancelled
   unclaimed and un-re-run *right now*, P6), red when no pass has landed inside the staleness
   limit while `ci.pool` is not empty (nobody is watching at all), red once per cancel that was
   not re-run, and otherwise one ok row naming the mode, the last pass and the boxes read.
3. **A cancel this watch made is always finished.** The owed re-run is advanced whatever the mode
   (C1), a claim whose cancel or re-run was refused is retried on the next pass up to
   `RERUN_TRIES` (C3), and a claim still in a bad state is held past the 48-hour prune for
   `BAD_KEEP_S` and is a red doctor row for as long as it is held (C4).

### Out

  already the card's answer and no threshold moves here.
- **The box side.** `REMOTE`, the per-slot heartbeat files and `fetch` are unchanged; this
  feature adds no ssh and no new remote read.
- **The operator script and its timer.** The product still never writes, installs or deletes
  either (C7). `LEGACY_QUIET_S` and the yield it drives keep today's behaviour exactly — one
  watcher acts at a time.
- **`stall`'s group in `ci_cancels.GROUPS`** — see C6.
- **A per-job cancel** — see C2.
- **A new `asf ci` subcommand.** `stall-watch` and its `--apply` are the whole CLI surface; the
  doctor row is read where every other CI row is read (C7).
- **`docs/design` and `docs/KNOWN-ISSUES.md`.** This session creates `docs/specs/f-0286.md` and

## The design

### 1. The pass records itself, and its record survives the reaper

**`asf/ci_stall.py`** — `watch` counts what it read and stamps one block before its final `save`:

```python
data['pass'] = {'at': now, 'mode': md, 'stalls': stalls, 'cancels': cancels,
                'boxes': boxes_read, 'unreachable': unreachable,
                'legacy': None if legacy is None else int(legacy)}
```

`boxes_read` is the number of pool boxes that answered with at least one heartbeat and
`unreachable` the number that did not — both already decided inside the loop, now counted.
`load` adds `'pass'` to the keys it normalises, so an old file with no block reads as `{}` rather
than raising.

**`asf/state/registry.py`** — two lines in the CI block, beside `ci-cancels.json`:

```python
'ci-stall.json': _s('asf.ci_stall'),
'ci-heartbeat.json': _s('asf.ci_heartbeat'),
```

No TTL on either: the claims must outlive any window in which nobody looked (C4), and a box's
last beat is the `ci heartbeat` row's only input. `ci-heartbeat.json` is registered to
`asf.ci_heartbeat`, which owns `record` — the write this watch makes through it on every pass
(P12).

When it is there: `ci-stall.json` carries a `pass` block after every pass;
`registry.spec('ci-stall.json')` is a `Spec` owned by `asf.ci_stall`; and `store.reap` on a state
directory holding both files returns neither name.

### 2. `asf doctor` carries a `ci stall` row

**`asf/ci_stall.py`** gains the limit, its key, and the rows — in the shape
`ci_heartbeat.doctor_rows` already uses, so `asf doctor` reads this watch the way it reads every
other CI fact: off the file, with no ssh and no `gh` call.

```python
#: no stall-watch pass inside this long, with a non-empty pool, is nobody watching
PASS_STALE_S = 15 * 60
#: a claim whose cancel or re-run was refused is retried at most this many times
RERUN_TRIES = 3
#: a claim still in a bad state is held this long, long past the resolved claims' prune
BAD_KEEP_S = 14 * 24 * 60 * 60
#: the claim states that mean a cancel was made and its re-run did not happen
BAD_STATES = ('cancel-failed', 'rerun-failed', 'gave-up')
```

`TUNABLES` gains `'PASS_STALE_S': 'ci.stall_watch.pass_stale_s'`; `asf/config_keys.py` gains
`'ci.stall_watch.pass_stale_s': (NUM, 1, None)` in the `ci.stall_watch` block; and
`docs/config.example.yaml` gains one commented line beside the other five (P11):

```yaml
#     pass_stale_s: 900       # no stall-watch pass this long with a pool is nobody watching
```

`doctor_rows(product, now=None)` returns `[(required, ok, detail)]`:

- **no rows** when `ci_heartbeat.boxes(product)` is empty and the file holds no `pass` — a
  product this watch does not run on is not asked about;
- **red, required** — the cutover is unfinished and cancels are going unclaimed now:
  `the operator watchdog still holds the timer (claims.json 42s ago) — its cancels are not
  claimed in ci-cancels.json and not re-run; move the host timer to
  \`asf ci stall-watch --apply\``, drawn when the mode reads `act` and `legacy_active(now)` is
  not None, or when the last `pass` block recorded a `legacy` age in `act`;
- **red, required** — nobody is watching: `no stall-watch pass for 83 min (limit 15) — 4 box(es)
  of ci.pool are unwatched`, drawn when there is no `pass` block at all or
  `now - pass['at'] > tunable('PASS_STALE_S')`, with `never` in place of the age for the first
  case;
- **red, required** — one row per held bad-state claim (C4):
  `run 37670494471 (gate-tests on <runner>) was cancelled 19 min ago and is rerun-failed after 3
  tries — it has not been re-run`;
- **ok** otherwise: `mode act, last pass 2 min ago: 0 stalled, 0 cancelled over 4 box(es)`, and
  the mode's own word when it is `report`: `mode report, last pass 2 min ago (reporting only,
  nothing is cancelled): …`.

**`asf/doctor.py`** — `check_ci_stall` in the `check_ci_heartbeat` mould, and one line in the row
assembly immediately after the `ci heartbeat` rows:

```python
def check_ci_stall(product, now=None):
    """[(required, ok, detail)] — which watcher acts on a CI stall, when the last pass ran, and
    every cancel of this watch's that was not re-run (:func:`asf.ci_stall.doctor_rows`, off
    ``ci-stall.json``: no ssh, no ``gh``). No rows for a product with no pool and no pass."""
    from asf import ci_stall
    try:
        return ci_stall.doctor_rows(product, now=now)
    except Exception as e:  # noqa: BLE001 — an unreadable file is one unknown row
        return [(False, None, f'cannot read the ci stall file — {e}')]
```

```python
for required, ok, detail in check_ci_stall(product):
    rows.append(('ci stall', required, ok, detail))
```

When it is there: on a host where the script still holds the timer, `asf doctor` draws a red
`ci stall` row naming that fact and the command that ends it — the card's state, visible in the
one table an operator already reads; on a host that has cut over, one green row naming the mode
and the last pass; and on either, one red row for every cancel that was never re-run.

### 3. A cancel this watch made is always finished

**`asf/ci_stall.py`** — three changes, all inside `_advance` and the prune.

The call moves out from under the mode gate (C1), with the reason beside it:

```python
    data['cpu'] = cpu
    _advance(product, src, data, now, out)   # a cancel already made is finished in either mode
```

`_advance` keeps today's path for a `cancelled` claim — `run view … --json status`, then
`run rerun --failed` once the run is `completed`, then `gave-up` after `GIVE_UP_S` — and gains
the retry the bad states never had (C3). Each attempt bumps `c['tries']`; an exhausted claim
keeps its state and is stamped `given_up_at`, which is what makes it a doctor row rather than a
line nobody read (P8):

- `cancel-failed` → `ci_queue._cancel_run` again while `c.get('tries', 1) < RERUN_TRIES`; on
  success the claim becomes `cancelled` and `ci_queue.claim_cancel(..., 'stall', by='stall-watch')`
  is written, exactly as the first attempt would have written it;
- `rerun-failed` → `gh run rerun --failed` again under the same bound;
- `gave-up` → left alone: the run never completed, so there is nothing to re-run; the claim is
  held and surfaced.

The once-per-run guard in `watch` is **not** touched: a claim in `data['claims']` still stops the
loop from cancelling that run again, and the retrying belongs to `_advance`, which already owns
every claim after it is made. There is still exactly one cancel per run.

The prune keeps a bad-state claim for `BAD_KEEP_S` and everything else for today's window:

```python
    data['claims'] = {k: c for k, c in data['claims'].items()
                      if now - float(c.get('claimed_at') or now)
                      < (BAD_KEEP_S if c.get('state') in BAD_STATES else 2 * REFRESH_S)}
```

When it is there: a run this watch cancelled is re-run whichever mode the next pass runs in; a
refused cancel or re-run is tried again rather than abandoned on the first bad `gh` call; and a
cancel that genuinely could not be re-run is a red `asf doctor` row for a fortnight instead of a
log line that ages out in two days.

## Records

What the change writes down, and where:

| record | written by | shape |
| --- | --- | --- |
| the `pass` block | `ci_stall.watch` → `save` → `<state>/ci-stall.json` | `{'at': epoch, 'mode': 'act'\|'report', 'stalls': n, 'cancels': n, 'boxes': n, 'unreachable': n, 'legacy': seconds\|None}` — one block, overwritten each pass |
| the claim | `ci_stall.watch` (before the cancel) and `_advance` (after it) → the same file | `{'run', 'job', 'runner', 'claimed_at', 'state', 'cancelled_at', 'rerun_at', 'tries', 'given_up_at'}`; `state` ∈ `claimed`, `cancelled`, `rerun`, `cancel-failed`, `rerun-failed`, `gave-up` |
| the cancel's cause | `ci_queue.claim_cancel` → `<state>/ci-cancels.json` | `{'cause': 'stall', 'by': 'stall-watch', 'job', 'runner', 'at'}` — unchanged, and now also written by a retried cancel that succeeds |
| the registry lines | `asf.state.registry.REGISTRY` | `'ci-stall.json': _s('asf.ci_stall')`, `'ci-heartbeat.json': _s('asf.ci_heartbeat')` — no TTL; the reaper calls neither an orphan and `.schemas.json` records schema 1 for both |
| the doctor rows | `ci_stall.doctor_rows` → `doctor.check_ci_stall` → the `ci stall` label | `(required, ok, detail)`: the held-timer row, the no-pass row, one row per held bad-state claim, else one ok row naming the mode and the last pass |
| the pass's lines | `watch`'s `out` → the tick log, or the operator's terminal | today's `STALL …`, `ALARM …`, `cancelled run …`, `re-ran the failed jobs of run …` and `gave up on run …`, plus one line per retry naming the attempt and the bound |
| the box beat | `ci_heartbeat.record` → `<state>/ci-heartbeat.json` | unchanged `{box: epoch}`; now a registered name, so a reap leaves the `ci heartbeat` row's only input alone |
| the config key | `docs/config.example.yaml` + `config_keys.KEYS` | `ci.stall_watch.pass_stale_s`, `(NUM, 1, None)`, default 900 |

Nothing new is written to origin: no ref, no branch, no commit, no PR comment. Every `gh` call
this feature adds is a retry of one the watch already makes — `run cancel` or `run rerun
--failed` on a run it had already claimed — and never a second cancel of any run.

## Stories

- S-74254: The pass records itself, and its record survives the reaper — `watch` stamping one `pass`
  block into `ci-stall.json` (when it ran, the mode it actually ran in, the stalls and cancels it
  found, the boxes that answered, and the legacy age that held it back) with `load` normalising
  the new key, and `ci-stall.json` plus `ci-heartbeat.json` named in `asf.state.registry` with no
  TTL so `store.reap` stops calling the claims and the box beats orphans (P10, P12, C5) —
  acceptance: `python3 -m unittest -v tests.test_ci_stall tests.test_state_store`
- S-74255: The doctor table says which watcher acts on a CI stall — `ci_stall.doctor_rows`
  with `PASS_STALE_S` and its `ci.stall_watch.pass_stale_s` key (C8, documented in
  `docs/config.example.yaml`), red while the mode says `act` and the operator script still holds
  the timer (naming the command that ends it), red when no pass has landed inside the limit while
  `ci.pool` is not empty, red once per held bad-state claim, else one ok row naming the mode and
  the last pass; surfaced by `doctor.check_ci_stall` as the `ci stall` label beside `ci heartbeat`
  (P6, P9, C7) — acceptance:
  `python3 -m unittest -v tests.test_ci_stall tests.test_doctor tests.test_config_keys`
- S-74256: A cancel this watch made is always finished — `_advance` called whatever the mode so an owed
  re-run is never frozen (P7, C1), a refused cancel or re-run retried on the next pass up to
  `RERUN_TRIES` and stamped `given_up_at` when exhausted (P8, C3), and a claim still in
  `cancel-failed`, `rerun-failed` or `gave-up` held for `BAD_KEEP_S` instead of pruned at 48 h
  (C4) — while the once-per-run guard in `watch` is untouched, so there is still exactly one
  cancel per run — acceptance:
  `python3 -m unittest -v tests.test_ci_stall tests.test_ci_cancels tests.test_ci_queue`
