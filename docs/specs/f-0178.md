# F-0178 — "Artifact storage quota has been hit" is a red required job, and today only a human clears it

On 2026-09-26 a product's CI jobs failed with `Artifact storage quota has been hit`. An operator
pruned every artifact older than two days by hand at 11:15; at 14:47 the same required job
(`p1-e2e-b`, PR #846) failed on the same message. Between those two times the product's own CI
had refilled the quota.

Each hit turns a **required** job red. A required job that is red is not a slow build — it is the
landing gate refusing, so the branch does not merge, the trunk does not move, and prod does not
deploy. Nothing in the factory notices: the artifacts are not a runner, not a session and not a
check, so no clock reads them, no row shows them, and the only instrument is an operator with
`gh api` and a spare afternoon. The hand prune is not even a fix that holds for one day.

Read live on 2026-09-30, one product's repository carries **200 artifacts, 301,447,656 bytes —
0.30 GB accumulated in about sixteen hours** — on an account plan whose *included* Actions
storage is 0.5 GB. That is the whole shape of the problem in three numbers: the product makes
roughly 0.45 GB of artifacts a day, and it has 0.5 GB to put them in. The card's default
`retention_days: 2` alone would settle at about 0.9 GB — still over. So the two mechanisms the
card asks for are not one feature and its nicety: **the daily prune bounds the age, and the early
prune bounds the size, and on a small quota only the second one actually keeps the product
under.** Both are specified here, and the second is not optional.

This card is therefore: *the factory reads how much artifact storage it is using, prunes what it
may, and says both out loud* — with a protection rule that means a prune can never delete the
artifacts anyone is currently reading.

| C1 | **The used figure is the sum of `size_in_bytes` over the repository's non-expired artifacts** — the card's second option, promoted to the only one. | The card's first option, `billing/shared-storage`. | P1: it is HTTP 410, removed. P2: its replacement reports gigabyte-hours over a billing period with no allowance field and cannot produce either side of `X GB / Y GB`. The honest shape is the one the whole status view already uses — *say which key would fill this row* (`asf.views.status.not_configured`) — and degrade to the half that needs no denominator. | C4 | **The age test is `now - created_at > retention_days`, per artifact.** | `expires_at` (let GitHub's own clock decide); the workflow run's date. | `expires_at` is the *host's* retention, which P6 shows is 90 days by default and is set per upload step — it is the thing that failed, not a thing to read. `created_at` is on the artifact, needs no extra call, and is what "older than N days" means to the operator who ran the hand prune. |

Keeping only one run's artifacts would delete the deploy run's logs for the sha being deployed. The artifact payload carries `head_sha` (P4) and carries no `workflow_id`, so the per-sha rule is also the only one available without a second call per run. It is strictly more protective than the card's wording and costs nothing. |

| C8 | **One list read per pass, bounded at `MAX_PAGES = 20` (2000 artifacts), memoised on the pass object.** Past the cap the total is a **floor**, the pass says `(list truncated at 2000 — the figure is a floor)`, and the prune still runs on what it read. | An unbounded `--paginate`; a TTL cache across passes; a page cap that makes the pass refuse. | P14 puts the honest cost at ≈6 GETs a pass in the steady state; the cap exists for the first pass on a repository with a 90-day backlog, where the list could be tens of thousands. A floor is still actionable — a floor above the threshold is over the threshold — and refusing would leave the one case that most needs pruning unpruned. No cross-pass cache: the reading's whole job is to be current, and the monitor exists to catch a spike between two daily prunes. |

Ten points of hysteresis at the measured rate (≈0.45 GB/day, P4) is roughly two hours of headroom per early prune. It is a constant and not a key because an operator has no reason to want a different gap: the two numbers they *do* care about — when it starts and how much it may delete — are already keys (`prune_at_pct`, `per_pass`). |
| C11 | **The early prune obeys the same protection rule and ignores `retention_days`.** It will delete an artifact from an hour ago if that artifact is the oldest unprotected one left. | Refusing to prune below `retention_days`; a separate floor age. | Above the threshold the alternative is a red required job, which costs more than an artifact nobody has asked for. The protection rule is what makes this safe, and it is the *same* rule — the trunk's current artifacts and every open PR's current artifacts survive any prune, at any percentage. Without that, an age floor would be doing the protection rule's job badly. |

### In and out

**In.** `asf/ci_artifacts.py` — the list read, the used total, the protection set, the age rule,
the threshold rule, the capped delete, the state file, the lines and the doctor lines. The
`ci.artifacts` block (`retention_days`, `prune_at_pct`, `quota_gb`, `per_pass`), its shape check
and its field-table entry. One part in `step_daily.parts`. One sub-pass in `step_health.run`. A
clause on the status Runners row. Two doctor rows (the reading, and the advisory upload scan).
`asf ci artifacts [--prune] [--json]`. The example product file, the config guide and the CI
runner-pool guide. The tests.

**Out.** Caches and logs — `actions/caches` and a run's logs are a separate allowance with a
separate API, and nothing here touches them. Deleting *runs* (`DELETE /actions/runs/<id>`): a run
is the record of what CI did and this card is about storage, not history. GitHub's own retention
settings (P6): the factory reads neither `artifact-and-log-retention` endpoint and writes
neither — that is a repository setting and an operator's to make, and a prune makes it moot.
Editing any product's workflow file (C15). Any other product's storage: the reading is per
repository (C1). The runner pool, the CI start queue, the capacity ceilings — untouched; the
Runners row gains a clause and nothing else. Filing a Bug when the quota is hit: the monitor's job
is to keep it from being hit, and `asf file-bugs` already files from red CI when it is.

## The design

### 1. `asf/ci_artifacts.py` — the whole rule, in one module

```python
"""asf.ci_artifacts — how much Actions artifact storage a product holds, and what may go.

An artifact is the one thing a CI run leaves behind that nobody reclaims. A repository's
allowance fills, and then every job that uploads one fails on ``Artifact storage quota has been
hit`` — a *required* job, so the branch does not merge, the trunk does not move and prod does not
deploy (2026-09-26: a product hit it twice in one day, three and a half hours after a hand prune
of everything older than two days).

Two rules over one read, both here:

  age        the daily clock (:mod:`asf.tick.step_daily`) deletes every artifact older than
             ``ci.artifacts.retention_days`` (2) that the protection rule allows.
  threshold  every ``health`` tick (:mod:`asf.tick.step_health`) reads the used total; above
             ``ci.artifacts.prune_at_pct`` (80) of ``ci.artifacts.quota_gb`` it deletes the
             oldest allowed artifacts until the reading is :data:`HYSTERESIS_PCT` points under
             the threshold. Without ``quota_gb`` there is no denominator and no early prune
             (there is no API that reports the allowance) — the reading is still recorded.

**The protection rule.** An artifact is never deleted, by either rule, at any percentage, when
its ``workflow_run.head_sha`` is the head sha of the newest artifact-bearing run on the trunk, or
the head sha of the newest artifact-bearing run on an **open PR's** head branch. Those are the
artifacts somebody is reading right now. When the open-PR list cannot be read the protection set
is incomplete and **nothing is deleted** — the pass only reports (the rule
:mod:`asf.workers.retention` follows for the same reason).

**The reading** is the sum of ``size_in_bytes`` over the repository's artifacts that are not
already ``expired`` (an expired one holds no storage and deleting it frees nothing). It is not
``billing/shared-storage``: that endpoint answers 410 — moved — and the billing endpoint that
replaced it reports gigabyte-hours over a period with no allowance field, so neither side of
"X GB / Y GB" can come from billing.

Every delete goes through :func:`asf.harvest.harvest._gh`, so a dry run
(:mod:`asf.mutation_guard`) refuses it with one ``would`` line and no flag has to be threaded
here. Each pass writes :data:`STATE_FILE`; the status Runners row and the doctor read that file
and make no host call of their own.
"""
import datetime
import json
import os
import re
import time

from asf import env
from asf.harvest import harvest as H

#: The pass's reading and what it did, for the status row and the doctor.
STATE_FILE = 'ci-artifacts.json'
#: The most pages of 100 one pass lists. Past it the total is a floor, and the pass says so.
MAX_PAGES = 20
#: How far under ``prune_at_pct`` an early prune goes, in points — without a gap the next pass
#: would be over the threshold again and prune again, every ten minutes, for ever.
HYSTERESIS_PCT = 10
#: The lowest target an early prune will aim at, whatever the threshold is set to.
MIN_TARGET_PCT = 10
GB = 1_000_000_000
DAY_S = 86400
```

`Artifact` is a plain record of the six fields P4 gives:

```python
class Artifact(typing.NamedTuple):
    id: int
    name: str
    bytes: int
    created: int          # created_at, unix seconds
    run_id: int           # workflow_run.id — the host's own recency order for runs
    branch: str           # workflow_run.head_branch
    sha: str              # workflow_run.head_sha
```

**The read.** One paginated `gh api`, bounded, parsed off `--jq` lines so a partial page never
costs the whole read:

```python
def read(product, pages=MAX_PAGES):
    """``(artifacts, truncated, why)`` — every non-expired artifact of the product's repository,
    oldest field intact and nothing sorted (the host's order is by ``id`` and ``created_at`` does
    not follow it, so every caller sorts for itself). ``truncated`` is True when the read stopped
    at ``pages`` pages, and then the total these rows make is a floor. ``(None, False, why)``
    when the product has no repository or the host did not answer."""
    slug = getattr(product, 'repo_slug', None)
    if not slug:
        return None, False, 'the product has no repo_slug'
    rc, stdout, err = H._gh(['api', f'repos/{slug}/actions/artifacts?per_page=100',
                             '--paginate', '--jq',
                             '.artifacts[] | select(.expired | not) | [.id, .name, '
                             '.size_in_bytes, .created_at, .workflow_run.id, '
                             '.workflow_run.head_branch, .workflow_run.head_sha] | @tsv'])
    if rc != 0:
        return None, False, H.tail(err or stdout) or f'gh exit {rc}'
    ...
```

`--paginate` is capped by counting rows (`pages * 100`) and dropping the rest; the rows are
`@tsv`, so one malformed row is skipped and named rather than losing the pass.

**The protection set** — C6, and the one place the open-PR list is needed:

```python
def protected(product, artifacts, prs):
    """``({head sha}, why)``: the shas whose artifacts no rule may delete — the newest
    artifact-bearing run on the trunk, and the newest on each open PR's head branch. ``prs`` is
    the open PR head branches, or None when the host did not answer, and then this returns
    ``(None, why)`` and the caller deletes nothing (C7). A sha, not a run: a trunk commit
    usually carries several runs (CI, a deploy, a nightly) and an operator means all of them."""
    if prs is None:
        return None, 'the open PR list did not read'
    trunk = getattr(product, 'main', None) or 'main'
    newest = {}                     # branch -> (run id, head sha)
    for a in artifacts:
        if a.branch != trunk and a.branch not in prs:
            continue
        if a.run_id > newest.get(a.branch, (0, ''))[0]:
            newest[a.branch] = (a.run_id, a.sha)
    return {sha for _run, sha in newest.values() if sha}, None
```

**The two rules**, each producing the same thing — an ordered list of what may go:

```python
def older_than(artifacts, keep, days, now):
    """The deletable artifacts older than ``days``, oldest first (C4, C5)."""
    cut = now - days * DAY_S
    return sorted((a for a in artifacts if a.sha not in keep and a.created < cut),
                  key=lambda a: a.created)


def down_to(artifacts, keep, used, target_bytes):
    """The oldest deletable artifacts whose sizes bring ``used`` to ``target_bytes``, oldest
    first, and as many more as that takes — ``[]`` when it is already under, and every deletable
    artifact when even deleting them all would not reach it (the protection rule is never
    traded away for a target: it is better to be over and merging than under and blind)."""
    out = []
    for a in sorted((a for a in artifacts if a.sha not in keep), key=lambda a: a.created):
        if used <= target_bytes:
            break
        out.append(a)
        used -= a.bytes
    return out
```

**The delete**, capped and dry-run safe by P8:

```python
def delete_artifacts(slug, rows, cap, out=print):
    """``(deleted, freed bytes, failed, left)`` — at most ``cap`` deletes, one line each. A
    failure is named and the pass goes on; three failures with nothing deleted stops the pass
    (the host is refusing, not this artifact), as the retention sweep does."""
    deleted, freed, failed = [], 0, []
    for a in rows[:cap]:
        rc, stdout, err = H._gh(['api', '-X', 'DELETE',
                                 f'repos/{slug}/actions/artifacts/{a.id}'])
        if rc == 0:
            deleted.append(a)
            freed += a.bytes
        else:
            failed.append((a, H.tail(err or stdout) or f'gh exit {rc}'))
            if len(failed) >= 3 and not deleted:
                out(f'artifacts: three deletes refused — stopping this pass ({failed[-1][1]})')
                break
    return deleted, freed, failed, rows[cap:]
```

**The two entry points.** `prune(product, days=None, fix=True, out=print, now=None)` is the age
rule, and is what the daily part and `asf ci artifacts --prune` both call.
`monitor(product, fix=True, out=print, now=None)` is the threshold rule, and is what the health
sub-pass calls. Both call `read`, both call `protected`, both end in `write_state`, and both
return the same dict:

_UPLOAD = re.compile(r"^uses:\s*['\"]?[\w./-]*upload-artifact(?:[@'\"/\s]|$)")
_RETENTION = re.compile(r"^retention-days:\s*\S")


def unbounded_uploads(text):
    """The 1-based lines of the ``uses: …upload-artifact`` steps in one workflow file that set no
    ``retention-days``. A line reader, not a YAML parser (this package takes no dependency): a
    step is a ``- `` item and its body is every line indented past it, so a ``retention-days:``
