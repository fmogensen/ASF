# F-0266 — the factory refused the push, and then told nobody why the run died

A cloud run that ends without its report commit is recorded as `run <id> ended succeeded without
the report commit`. That sentence says what the factory *could not find*. It never says what
stopped the session, and it is the only sentence anyone gets: the run's own end record reads
`failed: dead pid`, its `dead_class` reads `gone`, and the words the sync wrote go to the tick log
and to a status file keyed by token that no view reads.

On 2026-10-07 a product's T-44931 lost two cloud coder runs that way. Both ended "succeeded
without the report commit". The real cause — `commits do not name T-44931` — is a refusal **ASF
itself gave**, in ASF's own words, and it was found by reading the lane by hand.

The galling part is that the factory knew. A naming refusal, a pre-push refusal and a protected-ref
refusal are each written down at the moment they are made. None of them is ever read back into the
one sentence an operator sees when the run that met them dies.

This card: the dead reason carries the session's last ASF refusal, from whichever of the four
places that refusal was recorded, and keeps carrying it after the pass that wrote it.

### In

1. **One owner for a refusal** — a new `asf/workers/refusals.py`: the kinds, the `Refusal` shape,
   the per-job ledger, the clause a dead reason carries, and the recogniser over raw text.
2. **A session's own refusal is written down** — the hook shim appends one line to a new
   `ASF_REFUSAL_LOG` at each of its three refusal points (P8), cleared per launch like
   `ASF_PUSH_LOG`.
3. **The factory's own refusals are read, not re-written** — `publish_refused` (P7) and a
   refusal-kind `correction` (P6) are already on the record; `refusals` reads them.
4. **The dead reason carries it** — `cloud.classify` takes a refusal and names it in the
   "without the report commit" reason; `cloud.sync` supplies it.
5. **A cloud session's own refusal is recognised from its run log** — one read per dead run, only
   when neither the ledger nor the record has anything (P9/P10/P11).
6. **The dead reason survives the pass** — `dead_why` on the end record, and one composed read
   (`refusals.dead_reason`) that the doctor's dead-session line and `asf sessions` print, so the
   cause is not re-lost to the tick log.

### Out

- **No change to any refusal's own behaviour.** The naming refusal still holds the branch and
  still routes to a correct round; a refused publish still refuses; refguard still refuses before
  any `git` runs; the shim still exits 1. This card only makes those refusals readable afterwards.
- **No new refusal, and no new refusal site.** The four places (P5–P8) are the whole list.
- **`end_reason` is not touched.** P3: it is matched by equality, so the refusal goes on a field
  of its own and never into that string.
- **No cross-run attribution.** A refusal earned by run *N* is run *N*'s dead reason, not run
  *N+1*'s. A relaunched run already carries the correction in its brief, and `pending_correction`
  cannot be the source anyway (P15).
- **No log scraping for a local run.** A local session's refusals come from the ledger (leg 2),
  which is on this host; only the cloud lane pays for a log read.
- **No second API call per pass.** The run log is read at most once per run, in the pass that ends
  it, and only after the ledger and the record have both answered nothing.
- **No new command.** Nothing new is typed: the refusal appears on the lines an operator already
  reads (`asf doctor`, `asf sessions`, the tick log).
- **No change to `cloud-sessions.json`'s shape.** It keeps `{token: {status, why, …}}`; the
  refusal rides inside `why`, as the sync already composes it.
- **Not the local lane's "no report" case.** A local run that ends with no typed REPORT is
  `report.UNPUSHED`/`finished_unrecorded` and has its own classifier; `dead_why` and the composed
  read are written for it too (they are just a field and a function), but no local classifier is
  changed.

## The design

### 1. `asf/workers/refusals.py` — the one owner

New module. It imports `env` and the constants that own the strings; it imports nothing of
`cloud`, `health` or `harvest`, so every one of them may read it.

```python
"""asf.workers.refusals — what ASF itself refused, and the one sentence that says so.

A run that ends without its report is recorded by what the factory could not find ("without the
report commit"), never by what stopped the session. When what stopped it was a refusal ASF made
— the naming check, a pre-push check, a protected ref — that refusal was written down at the
moment it was made, in four places, and read back into nothing.

This module is the one owner of a refusal's kind, its one-line text and the clause a dead reason
carries. Its four sources:

* the session's own refusals, appended by the hook shim to ``<state>/<p>/gates/<job>.refusals``
  (``ASF_REFUSAL_LOG``, cleared per launch beside ``ASF_PUSH_LOG``) — the push-allow refusal, the
  product's own ``pre-push`` hook, ``asf trunk-check --pre-push``;
* ``run['publish_refused']`` — the factory's own publish refusal (refguard, a redaction finding,
  the repo's hook), already on the registry line;
* ``run['correction']`` whose ``kind`` is one of :data:`CORRECTION_KINDS` — the lane's refusal of
  this run's branch, with its own ``at``;
* a cloud run's log, through :func:`recognise` — the one source that costs an API call, read only
  when the three above answer nothing (a cloud session runs no shim: F-0266 P9).

Only the dead run's own refusals are ever read: a refusal earned by the run before it is that
run's dead reason, not this one's.
"""
```

Surface:

```python
#: A refusal's kind. Each is the constant that already owns its string, so a rename there follows.
NAMING = lifecycle.NAMING                    # 'naming'
PRE_PUSH = lifecycle.HOOK_REFUSED            # 'hook refused'
REFGUARD = 'refguard'
PUSH_ALLOW = 'push-allow'
REDACTION = 'redaction'
KINDS = (NAMING, PRE_PUSH, REFGUARD, PUSH_ALLOW, REDACTION)

#: The correction kinds that are a refusal ASF made at the door, not a finding about the work (C6).
CORRECTION_KINDS = (lifecycle.NAMING, lifecycle.COPIES, 'merge', 'conflict',
                    lifecycle.HOOK_REFUSED, lifecycle.INCOMPLETE)

#: One line of a dead reason, at most.
CLAUSE_MAX = 200

class Refusal(NamedTuple):
    kind: str      #: one of KINDS
    line: str      #: the refusal's own first line, never this module's wording
    at: str = ''   #: ISO-8601, '' when the source carries none
    where: str = ''  #: 'ledger' | 'publish' | 'correction' | 'run log'

def path(product, job):        """<state>/<p>/gates/<job>.refusals (basename'd, as pushlog)."""
def env_for(product, job):     """{'ASF_REFUSAL_LOG': path(...)}; makes the directory."""
def clear(product, job):       """Remove the file at launch. Never raises."""
def ledger(product, job):      """Every Refusal the file holds, oldest first; [] for no file."""
def from_record(run):          """The Refusals on a registry line: publish_refused, correction."""
def recognise(text):           """The LAST Refusal in a blob of session or git output, or None."""
def last(product, job, run=None, text=None):
    """The newest Refusal of this run, by ``at`` (a Refusal with no ``at`` sorts oldest), out of
    the ledger, the record and — only when both are empty and ``text`` is given — ``text``."""
def clause(refusal, now=None):
    """`` — last ASF refusal (<kind>, <n>m before): <line>``, cut to CLAUSE_MAX; '' for None."""
def dead_reason(run, product=None, text=None):
    """``run['dead_why']`` plus :func:`clause` of :func:`last`, composed now (C14); '' when the
    run carries no ``dead_why``."""
```

`recognise`'s patterns, one per kind, each anchored on the string its site prints (P5, P6, P8):

| kind | pattern |
|---|---|
| `push-allow` | `asf: push refused — an ASF session pushes only to factory branches` |
| `refguard` | `REF GUARD(?: \(warn\))?: refused` |
| `naming` | `commits do not name ` |
| `redaction` | `redact: \S+:\d+ ` or `REDACTION REFUSED` |
| `pre-push` | `lifecycle.HOOK_RE` / `REDACT_REFUSAL_RE` / `HOOK_REDACTION_RE`, via `lifecycle.push_failure(line) == HOOK_REFUSED` |

`pre-push` is tried last: it is the widest pattern, and a `REF GUARD` line that also says
"push" must file as `refguard`.

### 2. The shim writes a session's own refusal

`asf/workers/githooks.py`'s `ASF_HOOK`, three one-line additions inside the `pre-push` arm. A
helper at the top of that arm:

```sh
asf_refused() {   # $1 kind, $2 line — never fails the hook (C4)
    [ -n "$ASF_REFUSAL_LOG" ] || return 0
    printf '{"at":"%s","kind":"%s","where":"shim","line":%s}\n' \
        "$(date -u +%Y-%m-%dT%H:%M:%SZ)" "$1" "$(printf '%s' "$2" | _json)" \
        >> "$ASF_REFUSAL_LOG" 2>/dev/null || :
}
```

and its three call sites, each right where the refusal already happens:

* after `echo "asf: push refused — an ASF session pushes only to factory branches…"` →
  `asf_refused push-allow "$msg"`;
* after the product's own `pre-push` returns non-zero → `asf_refused hook-refused "$out"`, with
  the hook's output captured instead of passed straight through (it is still printed);
* after `asf trunk-check --pre-push` returns non-zero → the same.

`_json` is a two-line `sed` that escapes `\` and `"` and strips control characters, so the file
stays one JSON object per line whatever a hook printed. `refusals.ledger` drops a line it cannot
parse rather than raising — a hook's output is not a contract.

`spawn` and `heartbeat` gain `refusals.clear(product, row.job)` beside `pushlog.clear`, and
`**refusals.env_for(product, row.job)` beside `**pushlog.env_for(...)` in `job.env` — so a cloud
job's `env` file carries `ASF_REFUSAL_LOG` too, harmlessly (nothing in the container writes it,
P9), and a local session's shim writes it.

### 3. `cloud.classify` names the refusal

```python
def classify(view, report, elapsed_min, timeout_min, run_id=None, lost_after_min=None,
             refusal=None):
    ...
    if state == 'completed':
        conclusion = (view or {}).get('conclusion') or 'unknown'
        return DEAD, (f'run {run_id} ended {conclusion} without the report commit'
                      + refusals.clause(refusal))
```

Only this one arm takes the clause. A `timed out`, a `stalled` and a "never appeared" are the
factory's own verdicts about the *run*, not about a refusal, and `cloud.sync` already branches on
those prefixes (`why.startswith(('timed out', heartbeat.STALLED))` → `stop_fn`): a clause there
would have to be parsed back off.

In `cloud.sync`, where `classify` is called:

```python
refusal = refusals.last(product, job, run)
status, why = classify(view, report, elapsed, timeout, run_id, refusal=refusal)
if status == DEAD and refusal is None and REPORT_MISSING in why:
    refusal = refusals.recognise(_run_log_tail(run, s, remote_client, gh))   # leg 5
    if refusal:
        why += refusals.clause(refusal)
```

`REPORT_MISSING = 'without the report commit'` is a module constant, so the one arm that earns a
log read is named, not matched on a sentence fragment at the call site.

### 4. The cloud leg: one log read per dead run

```python
def _run_log_tail(run, s, remote_client, gh):
    """The dead run's own output, as text, or '' — one read, through the runtime already in hand
    (F-0266 C11). Never raises: no log is no refusal."""
```

* `remote.is_remote(run)` → `remote.run_log_summary(run, s, remote_client)` (P11, unchanged).
* otherwise → `actions.Gh.log_tail(run_id)`, new:

```python
def log_tail(self, run_id, limit=LOG_TAIL_MAX):
    """The last ``limit`` chars of the run's failed-step log — ``gh run view <id> --log-failed``,
    falling back to ``--log`` when the run has no failed step (a session that exited 0 without
    its report). '' when gh cannot say. Never raises on a rate limit: '' is no refusal."""
```

`LOG_TAIL_MAX = 64 * 1024`. The read happens in the pass that ends the run and in no other: a run
with an `ended` line is not synced again (`cloud.sync`'s own filter), so the cost is one `gh run
view` per dead cloud run, once.

### 5. `dead_why` on the end record, composed at read time

`lifecycle.RUN_FIELDS` gains `dead_why`. `health`'s one write site, beside `dead_class`:

```python
dead_class = (ev.liveness or None) if reason == lifecycle.DEAD_PID else None
dead_why = cloudpid.why(s.get('pid')) if dead_class else None    # '' → None
pool_mod.update_session(product, job, ended=now, end_reason=reason, dead_class=dead_class,
                        dead_why=dead_why, runtime_session=…)
```

`cloudpid.why(tok)` is new and trivial: `(load().get(tok) or {}).get('why') or ''` — the sibling
of `cloudpid.status`. For a local run it answers `''`, so `dead_why` is written only where there
is something to write.

Readers call `refusals.dead_reason(run, product)`, never `run['dead_why']` directly (C14):

* **`health.dead_census`** gains `by_refusal`: for each counted death, `refusals.last(product,
  run['job'], run)` and its `kind`. `dead_census_line` appends `; refusals: naming 3, pre-push 1`
  when any is known, and nothing when none is. Its `ok` rule is untouched — an unexplained death
  is still the thing the line fails on.
* **`views.sessions`** gains a `Why` column on the Dead rows, `refusals.dead_reason(run, product)`
  cut to one line, `-` when empty.

What it looks like when it is there, for the run this card exists for:

```
cloud    coder-t-44931            dead: run 500 ended succeeded without the report commit
                                  — last ASF refusal (naming, 3m before): commits do not name
                                  T-44931: every commit subject on the branch names its item
```

```
dead sessions: 11 in 14 days — gone 6, unknown 4; refusals: naming 3, pre-push 1
```

## Records

- **`<state>/<product>/gates/<job>.refusals`** — new. One JSON object per line, appended by the
  session's hook shim: `{"at": "<ISO-8601>", "kind": "push-allow|hook refused", "where": "shim",
  "line": "<the refusal's own first line>"}`. Removed at each launch (`refusals.clear`, beside
  `pushlog.clear`), so the file holds one run's refusals. Absent for a cloud run (nothing in the
  container writes it) and for a run that was refused nothing.
- **`<state>/<product>/sessions.jsonl`, the run's own line** — one new key, `dead_why`: the cloud
  sync's `why` for the run, verbatim, written once by health beside `dead_class` and only for a
  death that had one. A new entry in `lifecycle.RUN_FIELDS`, so it belongs to one launch and never
  folds into the next. `end_reason` is unchanged, byte for byte.
- **`<ASF_HOME>/state/cloud-sessions.json`** — unchanged in shape. Its `why` for a run that ended
  without its report now carries the clause: `run 500 ended succeeded without the report commit —
  last ASF refusal (naming, 3m before): commits do not name T-44931: …`.
- **The session environment** — one new variable, `ASF_REFUSAL_LOG`, in `job.env` beside
  `ASF_PUSH_LOG`, and so also in a cloud job's pushed `env` file.
- **The tick log** — the existing `cloud    <job>    dead: <why>` line, now with the clause. No
  new line.
- **`asf doctor`** — the existing dead-sessions row gains a second clause:
  `dead sessions: 11 in 14 days — gone 6, unknown 4; refusals: naming 3, pre-push 1`.
- **`asf sessions`** — the Dead group gains a `Why` column.
- **No new state file beyond the ledger, no new command, no new ref, nothing written to origin.**
- **What is no longer written** — a bare `run <id> ended <conclusion> without the report commit`
  for a run whose refusal is on record, and a `dead pid` end record whose only account of itself
  is `dead_class: gone`.
