# F-0208 — the planner booked a band nobody had told it was taken

A plan's pull request landed a migration band `0289-0290` on the trunk while an open code branch,
already in a pull request of its own, held `0289`. Nothing refused it, because nothing had looked:
the planner read the trunk, booked one past what the trunk carried, and the branch that had booked
`0289` a day earlier was never in the picture. Two cards then needed unpicking by hand — the open
branch had to re-book, and a third Feature's floor had to move.

The factory already has the reader this wanted. `asf reserve` (B-0151) hands out one past the
highest number the trunk, every open lane branch and every claim ref on origin carries
(`asf/reserve.py:150-171`), and a product declares its numbered sequences as
`conventions.sequences` (`asf/conventions.py:387-395`). Three things kept that from closing this:

* **`asf reserve` is a command a session may call, and nothing checks that it did.** No pass reads
  what a branch booked, so a session that picked a number by reading the trunk is never caught.
* **Its own scan of "every open lane branch" is `code` and `fix` only** (`asf/reserve.py:134`), so
  a plan branch's booking is invisible to it — the very branch this incident was.
* **In this factory a plan branch cannot carry the numbered file at all.** A spec/plan lane branch
  is documents-only or the lane refuses it (`asf/harvest/lane.py:81-82` via
  `lane.landing_class`), so a plan does not book by adding a file: it books by writing a Task whose
  `writes:` names one. Nothing reads a number out of a footprint.

So this card is not "call `asf reserve` more". It is: **one map, built once per lane pass, of what
every open ref books in every declared sequence — from the files a branch adds, from the `writes:`
globs its cards declare, and from a product command for numbers no filename carries — with one
deterministic rule for which ref *holds* a number and which one must re-book, a mechanical hold on
the newcomer that names the holder, and that same map in the planner's brief before it books.**

### The choices

| # | Chosen | Against | Why |
| --- | --- | --- | --- |
| C1 | **One new module, `asf/reservations.py`, owns the whole question: what a ref books, which ref holds a number, and the refusal's words.** Every caller — the lane, the landing, the brief's gatherer, `asf reserve` — asks it and decides nothing itself. | Adding the clash test inside `lane.lane_refusal`; a second copy of the number-extraction in `asf/reserve.py`. | `lane_refusal` takes `(repo, trunk, branch, item, conv, members)` and has no product, no items and no pull-request numbers — everything this needs (P5). A predicate that four call sites must agree on is one module or it is four rules; B-0151 already paid for a second definition of "open lane branch" (P2) and this card exists partly because of it. |
| C2 | **A ref's booking has three sources, merged into one map: the files its diff *adds* under a sequence's directory, the numbers its cards' `writes:` globs name, and the lines a configured `conventions.reservations` command prints.** The trunk's holding is its whole tree under that directory. | Only reading trees (B-0151's shape); only reading `writes:`; only running a product command. | Trees alone cannot see a plan's booking at all — a plan branch is documents-only (P3), so the card's own incident is invisible to a tree reader. `writes:` alone cannot see a coder who added the file without declaring the number. A command alone makes every product write a program before any of this works, for the case the two declarations ASF already holds cover. Three readers, one merge, one decision. |
| C3 | **A booking from the tree is a file the branch *adds* (`git diff --diff-filter=A origin/<trunk>...origin/<branch>`), never one it changes.** | Reusing `f['files']` from `lane.touched_files` as it stands (P4). | `touched_files` lists edits too, so a branch that fixes a typo in a landed `0201_*.sql` would "book" `0201`, find the trunk holding it, and be refused for touching a file it did not claim. The false refusal is worse than one more `git diff` per branch in a pass that already makes several. The new reader lives in `asf/reservations.py`, next to a docstring naming `lane.touched_files` as its sibling and the one flag that separates them — not in `lane.py`, which would import back. |
| C4 | **A `writes:` booking is attributed to the branch that carries the plan of the card's Feature while that plan is off the trunk (`feeder_rows.plan_carrier`), and to the card's own lane branch once the plan has landed.** Only open cards count. | Attributing a Task's `writes:` always to the Task's own `worker/<id>` branch. | The card's incident is a *plan* booking a range, and in this factory a plan's only booking is its Tasks' footprints (P3). Attributing them to the Task's branch would hold nothing until a coder pushed — days after the plan was approved and landed, which is exactly the hole. Once the plan is on the trunk the booking is the Task's own, and the Task's branch is where a clash must be answered. One condition, both clauses, one reader (P12). |
| C5 | **The holder of a number is the lowest-ranked ref that books it, and rank is `(-1, '')` for the trunk, `(0, <pull-request number>)` for a ref with one, `(1, <ref name>)` for a ref without.** Every other ref booking that number is refused. | Refusing both sides of a clash; ordering by the introducing commit's date; ordering by the branch tip's date. | A clash is symmetric, so a rule that refuses both stalls two lanes and re-books a number nobody needed to move. The pull-request number is the only "who claimed first" the factory already has in hand (P7), it is stable under a rebase — which rewrites committer dates and moves a tip — and it is how the incident itself is legible: the lower number held, the higher one intruded. The trunk always holds: a number already landed is not negotiable. A ref with no pull request ranks last, which is right for a plan branch that has not opened one yet — the newcomer re-books. **Consequence, named not fixed:** two ref-less branches booking the same number are ordered by name, which is deterministic and arbitrary; the loser re-books. |
| C6 | **The refusal is a new correction kind, `reserved`, and it joins `lifecycle.MECHANICAL`.** | A plain refusal kind that spends a review round and can reach adjudication. | A number clash has nothing to adjudicate — the answer is always "book past it" — and a round spent on a renumber walks the Feature toward its stalemate cap for a defect no reviewer has an opinion about. `MECHANICAL` is precisely "no round, never adjudicate, routed to a `correct` session", and `same_head_loop` still parks and flags a clash that survives `LOOP_CAP` attempts (P6), so an unresolvable one reaches a human rather than looping. |
| C7 | **The refusal names the sequence, the numbers, the holding ref and its pull request, and says what to do:** `reserved: bands 0289, 0290 are held by worker/T-0361 (PR 844) — book past them: the next free number in bands is 0292. The next free number comes from the same merged map, so the session is handed the answer, not just the problem. |
| C8 | **The landing declines, it does not mint a session.** `land_spec.adopt` asks for the clash before `why_not_as_is` and, when there is one, adopts nothing, prints the clash and leaves the Feature where it is. | Adding the clash to `why_not_as_is`'s refusal string. | A non-empty `why_not_as_is` adopts the branch BACK with a `landing-gate` correction whose text is *"land the existing approved plan … don't rewrite it"* (`asf/tick/land_spec.py:115-118`) — the opposite of what a clash needs, and a session that cannot succeed. | C9 | **`conventions.reservations` is one command, run once per lane pass, in the product's repo, with every ref as argv, printing `<ref> <sequence> <lo>[-<hi>]` lines.** A non-zero exit, a timeout or an unreadable line is recorded and ignored — never a plan's refusal. | Running the command once per ref; running a lane branch's own copy of it; treating its failure as a hold. | One process per pass, in the operator's own checkout, so no unmerged branch's code runs inside the tick and the cost does not grow with the number of open branches; the command reads each ref itself with `git show`, which is the product's business. | C11 | **`asf reserve` moves onto this module's definition of "open lane branch" — every prefix the product declares, legacy ones included — and onto its merged holdings, so it books past a plan's declared range as well as past a file on a branch.** | Leaving `asf/reserve.py:134` as it is and letting the two disagree. | P2 is the second half of this incident: the command a session is *told* to call would have handed out `0289` again, because it cannot see a plan branch. | C12 | **No new command, no doctor row, no record card, no schema change, no view.** The operator surface is one config key, one line in the brief, one hold line in the tick and one state file. | An `asf reservations` listing; a doctor row for a stale snapshot. | Every number in the map is already printed where it matters — in the brief of the session that is about to book, and in the hold of the branch that booked wrong. A listing command would be a fourth reader of a map that already has three. |

### In, and out

**In.** `asf/reservations.py` — the three booking readers, the merge, the rank and holder rule, the
clash, the refusal text, the next-free-number answer, and the snapshot's writer, reader and words;
`lifecycle.RESERVED` joining `MECHANICAL`; the clash as a refusal in `Lane.facts` and the snapshot
written once per `lane_pass`; `land_spec.adopt` declining a clashing carrier; a tenth
`repo_facts` key and one line in `preamble.state_lines`; `reserve.open_branch_trees` and
`reserve.reserve` onto the one definition and the merged holdings; `conventions.reservations` with
its validation and its two lines in `docs/products.example.yaml`.

**Out, deliberately.** Renumbering anything — the hold asks a session to re-book and never rewrites
a file itself; the claim refs of B-0151 (`refs/heads/reservations/<sequence>/<n>`), which stay
exactly as they are and keep feeding `asf reserve`; numbers recorded as rows inside one shared
file, which `conventions.sequences` already declares unsupported (P1) and which a product's own
`reservations` command is the answer for; a glob whose number field is itself a pattern
(`029[01]_*.sql` books nothing — a `writes:` glob books only when its filename half matches the
sequence's own regex); any change to the gate, the merge queue, the review, or what a deploy
ships; and any new operator command or view (C12).

## The design

### 1. `asf/reservations.py` — one reader, one merge, one holder

```python
"""asf.reservations — what every open ref has booked in a product's declared sequences, merged
into one map, so a plan is never approved that books a number another open branch already holds
(F-0208: a plan landed a migration band 0289-0290 on the trunk while an open code branch, in a
pull request of its own, already held 0289 — the planner had read the trunk and nothing else).

Three readers feed one map, because no one of them can see a whole booking:

* **added** — a file the ref's own diff adds under a sequence's directory. A coder's booking.
* **writes** — a number a `writes:` glob of an open card names. A *plan's* booking: a spec/plan
  lane branch is documents-only (`asf.harvest.lane.landing_class`), so a plan cannot book by
  adding the file — it books by writing a Task whose footprint names the number.
* **command** — the lines `conventions.reservations` prints, for a number no filename carries.

The map decides nothing on its own: :func:`holder` names the one ref that keeps a number and
:func:`refusal` is the words for every other ref that booked it. The rank is the pull request's
number, so the older claim holds and the newcomer re-books.
"""
```

The vocabulary:

```python
#: A booking: one number, in one sequence, by one ref, read from one source.
Booking = collections.namedtuple('Booking', 'sequence number ref source')
ADDED, WRITES, COMMAND = 'added', 'writes', 'command'
#: The correction kind of a clash — :data:`asf.workers.lifecycle.RESERVED`, spelled once there.
FILE = 'reservations.json'
#: The most numbers one sequence contributes to the brief's line before it says how many are left.
BRIEF_LIMIT = 12


def sequences(conv):
    """``{name: (dirname, regex, width)}`` for every declared sequence whose pattern reads
    (:func:`asf.reserve.pattern_regex`); one that names no number field is skipped, not raised —
    a misdeclared sequence must not stop a lane pass."""


def open_refs(product, heads, prs):
    """``[ref]`` — the trunk first, then every open lane branch: a head under any prefix the
    product declares (``legacy`` included) that is not the trunk and has no MERGED pull request.
    One definition, shared with :func:`asf.reserve.open_branch_trees` (B-0151 read ``code`` and
    ``fix`` alone, so a plan's booking was invisible to it — half of F-0208)."""


def rank(ref, trunk, prs):
    """How old a ref's claim is, lowest first: ``(-1, '')`` for the trunk (a landed number is not
    negotiable), ``(0, <pr number>)`` for a ref with a pull request, ``(1, ref)`` for one
    without — a branch that has opened no pull request yet is the newcomer and re-books."""
```

The three readers, each returning `[Booking]`:

```python
def added_files(repo, trunk, ref):
    """The paths ``origin/<ref>``'s own commits *add* since it left the trunk —
    ``git diff --name-only --diff-filter=A origin/<trunk>...origin/<ref>``. The sibling of
    ``asf.harvest.lane.touched_files`` and different from it in one flag on purpose: that one
    lists edits too, and a branch that fixes a typo in a landed ``0201_*.sql`` books nothing."""


def added_bookings(product, seqs, refs):
    """A :data:`ADDED` booking per number a ref adds under a sequence's directory, plus the
    trunk's own: for the trunk the whole directory listing counts (``origin/<trunk>:<dirname>``
    through :func:`asf.evidence.evidence.read_trees`, the read B-0151 already makes), because
    everything on the trunk is held."""


def writes_bookings(product, items, seqs):
    """A :data:`WRITES` booking per number an open card's ``writes:`` glob names, attributed to
    the branch carrying that card's plan while the plan is off the trunk
    (:func:`asf.feeder.rows.plan_carrier`) and to the card's own lane branch once it has landed.
    A glob books only when its filename half matches the sequence's regex, so
    ``db/migrations/*`` and ``029[01]_*.sql`` book nothing."""


def command_bookings(product, refs):
    """``([Booking], error)`` from ``conventions.reservations``: one
    :func:`asf.harvest.harvest.sh_timed` run in ``product.repo_dir`` under
    :func:`asf.harvest.harvest.gate_env`, with every ref appended to the command's argv, capped by
    ``conventions.harvest.gate_timeout_s``. Each stdout line is ``<ref> <sequence> <lo>[-<hi>]``;
    a line that does not read is skipped and counted. A non-zero exit, a timeout or no command at
    all is ``([], <why>)`` — a product's broken script refuses no plan (C9); the other two
    readers carry the pass."""
```

The merge and the decision:

```python
def holdings(bookings, ranked):
    """``{sequence: {number: [ref, ...]}}`` — every ref that booked a number, its holder first
    (lowest :func:`rank`). Deterministic: the same bookings give the same order."""


def holder(holdings, sequence, number):
    """The one ref that keeps ``number``, or None."""


def clashes(holdings, ref):
    """``[(sequence, number, holder)]`` for every number ``ref`` booked that another ref holds —
    in sequence then number order, so the refusal's words are stable."""


def next_free(holdings, seqs, sequence):
    """One past the highest number anything holds in ``sequence``, zero-padded to the pattern's
    width: the answer the hold hands the session, from the same map that refused it."""


def refusal(snapshot, ref):
    """``(kind, text)`` for a ref that booked a number another ref holds, else None — the pair
    :func:`asf.harvest.lane.lane_refusal` returns and ``Lane.enter_back`` unpacks."""
```

which reads, for the card's own incident:

```
reserved: bands 0289, 0290 are held by worker/T-0361 (PR 844) — book past them: the next free
number in bands is 0292. Renumber on this branch (rename the files and every reference to them)
and push it again.
```

And the snapshot — one file, the same map three readers later share:

```python
def snapshot(product, items, heads, prs):
    """The whole map, once: ``{'at', 'trunk', 'refs', 'prs', 'sequences', 'errors'}``, where
    ``sequences`` is ``{name: {'width': int, 'held': {number: [ref, ...]}}}``."""


def save(state_dir, snap):
    """Write :data:`FILE` in the product's state dir, as ``asf.harvest.lane`` writes its own
    small json (a temp file, one rename)."""


def load(state_dir):
    """The last snapshot, or ``{}`` — a missing, truncated or unreadable file is no snapshot,
    never an error: the brief prints its ``(not known here)`` marker for it."""


def brief_lines(snap, limit=BRIEF_LIMIT):
    """The holdings in words for a planner's brief, at most ``limit`` numbers per sequence."""
```

### 2. The lane holds the newcomer, and writes the map down

`lane_pass` builds the map once, after its fetch (P7) and before it advances anything, and saves
it:

```python
snap = reservations.snapshot(product, lane.items, lane.remote_heads(), lane.host.prs())
reservations.save(lane.state_dir, snap)
```

`Lane.facts` asks for the clash where it already asks for a refusal (`asf/harvest/lane.py:1354`),
after `lane_refusal` and before `incomplete_refusal` — a branch whose commits do not even name
their item is not told about numbers yet:

```python
if not f['refusal']:
    f['refusal'] = reservations.refusal(self.reservations(), b)
```

`Lane.reservations()` is the pass's memoised snapshot. From there nothing is new: `enter_back`
unpacks `(kind, text)` into `hold_with_correction`, the branch goes BACK, and the correction
routes to a `correct` session with no round spent, because `reserved` is in `MECHANICAL` (P6):

```python
#: the lane's refusal of a branch that booked a number another open ref holds (F-0208,
#: asf.reservations): a mechanical renumber — no round, never adjudicate
RESERVED = 'reserved'
MECHANICAL = (NAMING, COPIES, RESERVED)
```

### 3. The landing declines a clashing carrier

`land_spec.adopt` asks before it adopts (C8):

```python
clash = reservations.refusal(reservations.load(state_dir), carrier)
if clash:
    out(f'land-{doc}: {fid} — approved {doc} on {carrier} is not landed: {clash[1]}')
    continue
```

so the approved plan stays where it is, the operator reads why in the tick, and the plan branch's
own `reserved` hold is what asks for the renumber.

### 4. The brief lists the holdings before the planner books

`facts.repo_facts` gains a tenth key, read from the snapshot — no fetch, no forge (P8):

```python
facts['reservations'] = reservations.load(env.state_dir(product))
```

and `preamble.state_lines` gains one line, directly under `Writes:` and above
`Sessions in flight:`, absent for a product that declares no sequence:

```
Reserved in flight: bands 0289, 0290 (worker/T-0361, PR 844); migrations 0512 (plan/F-0190) — book past these
```

`(none)` when the map is empty, `(not known here)` when no pass has written one yet, and at most
`BRIEF_LIMIT` numbers per sequence followed by `+N more`. The block is not trimmable (P9), so the
line a planner must read to book correctly cannot be cut to fit.

### 5. `asf reserve` books past what a plan holds

`reserve.open_branch_trees` takes its branch set from `reservations.open_refs` (every declared
prefix, not `code` and `fix` alone — P2), and `reserve.reserve` adds the merged holdings to the
numbers it already skips:

```python
held = reservations.snapshot(product, items, heads, prs)['sequences'].get(sequence) or {}
n, width = compute_next(pattern, trees, reserved + [int(k) for k in held.get('held', {})])
```

The claim ref half (`remote_reserved_numbers`, `claim`, `MAX_ATTEMPTS`) is untouched: it is what
makes two sessions racing the same second safe, and this card is about the branches that are
already pushed.

### 6. The config, and the docs

`conventions.reservations` is one string — the command, split with `shlex.split` — validated
beside the other scalar conventions: a non-string is a finding naming the key, and the module
docstring's yaml example gains it and `sequences:`. `docs/products.example.yaml` gains both under
`conventions:`, with the line format the command must print, and must keep validating clean (P15).

No round is spent, no adjudication is reached, and a clash that survives `LOOP_CAP` attempts parks
