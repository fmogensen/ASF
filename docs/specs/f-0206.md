# F-0206 — a row nobody on this host can judge

One row sat in a product's `sessions.jsonl` for five hours and more:

```
B-1381 | fix | <an account this host does not configure> | dead pid
```

Every status view printed it. Every harvest walked past it. Its work was long done — the fix was
pushed and sat on a pull request, and later sessions had run code and review on the same item —
so nothing was waiting for it. Health never wrote its `ended` line, and because the row stayed
live, `reap_verdict` never looked at its worktree either: a live run's worktree is `opening`, or
nothing at all (`asf/workers/lifecycle.py:2604-2605`).

There is exactly one route out of a live row today, and it is a liveness verdict:

```python
if ev.result is None:
    return None if ev.alive else DEAD_PID     # asf/workers/lifecycle.py:1929-1930
```

`ev.alive` is this host's answer about this host's processes: a pid number, the local process
table, a log path on this disk, `os.kill`. For a row **this host did not launch** every one of
those inputs is either missing or about some unrelated process that happens to hold the same
integer — and `liveness()` is deliberately generous with what it cannot place, answering `UNKNOWN`
(a live verdict) rather than killing a working session on a guess (`asf/workers/lifecycle.py:
596-632`, F-0234). Generous is right for our own workers. For someone else's row it is a verdict
that can read "alive" and never change, and there is no second route.

This card is not "make the liveness check smarter" — it cannot be made smarter about a process it
cannot see. It is: **a live row whose account this host does not configure is ended by evidence
that is true on every host — the item has a newer session, or the branch moved past the head the
row was handed — and never by a liveness verdict at all.**

## Decisions

### Preconditions — verified in this checkout at `e6f759fbd`

| # | What holds | Where |
| --- | --- | --- |
| P1 | **The dead-pid route is the only route out of a live row, and it is a liveness verdict.** `judge` returns `None` — "still running, write nothing" — for exactly one shape: no result line, and `ev.alive`. Every other shape ends the row. So a row stays live if and only if its log has no result and `alive(pid)` answers true. | `asf/workers/lifecycle.py:1918-1930` |
| P2 | **`alive` answering true for a row that is not running is enough to keep it live for ever, worktree included** — reproduced against the real harness in this checkout. Five hours of harvests is that loop, run more times. | run live, this checkout |

### The choices

| # | Chosen | Against | Why |
| --- | --- | --- | --- |
| C1 | **The new rule runs behind `judge`, only where it returns `None`** (`health.py:718-719`) — never before it, never instead of it. | Asking the orphan question first, so it can pre-empt a liveness verdict. | An orphan row whose branch *is* pushed and whose log *does* carry a result must still be judged `finished`, so harvest lands its work; a row whose result says failed must still be held. Pre-empting `judge` would end such a row as an orphan and throw its landing away. Behind `judge`, the rule is reachable only for the one shape that is stuck (P1), and it cannot change a single row the existing rules already decide. |
| C2 | **The gate is the account, not the pid: a live row whose `account` is not one of this host's configured worker-account names — an unrecorded account included.** | The card's disjunction as written ("whose pid is dead **or** whose account is unknown"). | P3: behind `judge`, `reason is None` *means* `alive(pid)` answered true, so the pid half can never fire there — it is already the existing `dead pid` route, which works and stays. Writing it a second time would be code no test can reach. The card's two clauses are one clause once the route's position is chosen, and this spec says so rather than shipping a dead branch. |
| C3 | **A row on a configured account is never touched, however superseded it looks.** | Applying the rule to every live row whose item has a newer session. | The factory launches a second session on a live item routinely — a `correct-` round beside a running `review-`, a wave that overlaps. Ending a row because a sibling exists would kill working sessions and lose their unpushed work. A configured account is this host's own; its liveness verdict is this host's to trust, and where that verdict is wrong the answer is F-0234's rules, not this one. |
| C4 | **Supersession is two facts, asked in this order: a newer session on the item, then the branch moved past the launch head.** `('session', <job>)` — another run of the item, under a different job, started no earlier than this row (`item_runs`, so a run before the item's newest reset does not count). `('branch', <sha>)` — the row recorded a `launch_head` and `origin/<branch>` is now a different sha, the empty string (origin does not hold the branch at all) included. | The branch fact alone; a merged-PR check; "the item is done on the record". | P6: a first launch on a fresh branch records no `launch_head`, so the branch fact cannot stand alone — and the card's own case is a `fix` whose branch was pushed and landed on a PR, which the session fact catches and the branch fact catches too. Session first because it is free (the registry is already folded) and answers for every row; the branch fact is one cached `ls-remote` (P7) and is what catches an orphan whose item never got another session. A record lookup would make this rule depend on the record clone being fresh, which a ledger question has no business doing. |
| C5 | **Two rows that supersede each other are both ended, and that is correct.** | A tie-break that keeps the newest of a mutually-superseding pair. | Both must already be past the account gate (C3) and the age floor (C6) — neither is this host's, and neither has moved for half an hour. Ending both is the honest reading; keeping one arbitrary row alive keeps a row nobody can answer for. |
| C6 | **An age floor: the row is ended only once it is at least `stall.silent_minutes(product)` old**, reusing the product's existing `stage_limits.silent_min` (default 30 min, P10). | No floor; a new `worker_pool.orphan_min` key. | The floor is what makes C3's converse safe: rename an account in `worker_pool` while a session runs under it and its row becomes unknown-account at once, still working. Half an hour of nothing is the product's own existing definition of "too quiet to be working", and reusing it adds no config, no validation and no second number to keep in step. The card's row had sat five hours. |
| C7 | **`end_reason` stays `dead pid` (`lifecycle.DEAD_PID`)** — no new outcome class. | A new reason, `orphaned` / `superseded`. | P8: `outcome_class`, `is_dead_reason`, `classify` and the scorecard all match that exact string, and a new one would read as `other` in every one of them — silently moving the `failure:dead pid` scorecard metric and mis-labelling the row in three views. `classify` then words it `dead: no end-of-run record, nothing pushed`, which is precisely true of this row. The *why* — that supersession ended it, not a liveness check — belongs in a field and in the printed line, where an operator reads it, not in a class four readers switch on. |
| C8 | **One new ledger field, `superseded_by: {rule, by, at}`**, added to `RUN_FIELDS`. | Two flat keys (`superseded_by` + `superseded_rule`); a free-text suffix on `end_reason`. | The field carries two facts that are only meaningful together, which is what `correction` and `lane` on this same ledger already are — a dict. `RUN_FIELDS` because the fold must not carry it into the job's next run (P9). A suffix on `end_reason` is C7's mistake wearing a different hat. |
| C9 | **The printed line is the card's words, in health's existing columns**: `ended     <job>   dead pid, superseded by <job>`, and `ended     <job>   dead pid, its branch moved past <sha9>` for the branch rule. | Inventing a new `what` (`orphaned`) for the transition list. | `ended` is what happened, and every reader of health's output — the tick digest, the operator — already knows that word. The `<job>:` in the card's `ended <job>: dead pid, …` is the shape of a `job: detail` line; health puts the job in its own column (P11), and the detail is the card's sentence verbatim. |
| C10 | **`RemoteHeads` is hoisted above the run pass and shared with the worktree pass.** | A fresh `ls-remote` per orphan candidate; reading `refs/remotes/origin/<branch>` out of the checkout. | One snapshot for the whole pass is what P7's class exists for, and hoisting it saves the second `ls-remote` the worktree pass would otherwise make. Its own docstring's precondition — nothing is pushed between its questions — does not hold across the run pass, which republishes branches (B-0056), so the orphan rule asks it **only for a row it is about to end**, whose branch this pass never pushes; a stale answer there can only say "moved", never "did not move", and a row that is wrongly *not* ended is simply ended on the next pass. A local remote-tracking ref would be stale in the other direction and could end a row on a branch that never moved. |
| C11 | **No new command, no config key, no doctor row, no state file, no record card, and no change to the reap rules.** | An `asf sessions --reap-orphans`; a doctor row counting orphan rows; loosening `reap_verdict`'s `pid still alive` guard so the worktree goes at the same moment. | Ending the row is the whole card: once `ended` is written, the worktree falls to the existing `reap_verdict` ladder unchanged, and the row leaves every live view. `reap_verdict`'s own `alive` guard (`asf/workers/lifecycle.py:2607-2608`) may still keep such a worktree on the pass that ends it — that is the same F-0234 question as C3, deliberately not reopened here; the row is out of the live views either way, and a row from another launcher usually has no worktree under this host's `worktrees_dir` at all. Named as out, not overlooked. |

### In, and out

**In.** `lifecycle.unknown_account(run, accounts)`; `lifecycle.superseded(path, run, head=None)` returning
`(rule, by)` or None; `lifecycle.orphan_end(path, run, accounts, head=None, now=None,
min_age_min=None)` returning the fields and the detail line, or None; `superseded_by` added to
`RUN_FIELDS`; health's run pass calling it behind `judge`'s `None`, with the host's account names
and the hoisted `RemoteHeads`; the module docstrings of `asf/workers/health.py` and
`asf/workers/lifecycle.py` gaining the rule.

**Out, deliberately.** Any change to `judge`, to the existing `dead pid` route (P3), or to what
`alive` answers (F-0234's question, C3); any change to `reap_verdict` (C11); any row on a
configured account (C3); a new outcome class (C7); any new command, config key or record (C11);
and the diagnosis of *which* liveness verdict kept the original row alive — the ledger and the
host's process table are not in this repo, so this spec does not claim to know, and the rule is
built not to need to (C1, C2).

## The design

### 1. `asf/workers/lifecycle.py` — the rule, pure

```python
#: A live row this host cannot answer for (:func:`unknown_account`) is ended by what moved past
#: it, never by a liveness verdict: the pid is a number on another machine, the log a path this
#: disk does not have, and :func:`liveness` is deliberately generous with a process it cannot
#: place (F-0234). ``superseded_by`` is the run field that records which fact ended it.
SUPERSEDED_SESSION = 'session'
SUPERSEDED_BRANCH = 'branch'


def unknown_account(run, accounts):
    """True when ``run``'s ``account`` is not one of ``accounts`` — the names this host's
    ``worker_pool`` configures (:func:`asf.workers.pool.accounts_from_config`). A run with no
    account recorded is unknown too: a launcher that wrote none is not this host's.

    ``accounts`` None means the question was not asked, and nothing is unknown."""
    if accounts is None:
        return False
    return (run or {}).get('account') not in set(accounts)


def superseded(path, run, head=None):
    """What moved past ``run``, or None — ``(rule, by)``.

    ``(SUPERSEDED_SESSION, <job>)``: another run of ``run``'s item, under a different job,
    started no earlier than it (:func:`item_runs`, so a run before the item's newest reset is
    not the item's and does not count). The factory launched a session on work this row still
    claims.

    ``(SUPERSEDED_BRANCH, <sha>)``: ``run`` recorded a ``launch_head`` — the sha of
    ``origin/<branch>`` the launch handed it (:func:`asf.workers.spawn._launch_head`) — and
    ``head``, ``origin/<branch>`` now, is a different sha. ``''`` is a different sha: origin
    does not hold the branch at all any more, which a landing and a delete both leave behind.
    ``head`` None means origin was not asked, and this rule does not fire.

    The session rule is asked first: a launch on a branch origin did not yet hold records no
    ``launch_head`` (P6), so the branch rule alone answers for no first launch."""
    item, job = (run or {}).get('item'), (run or {}).get('job')
    started = (run or {}).get('started') or ''
    if item and job and path:
        for r in item_runs(path, item):
            if r.get('job') != job and (r.get('started') or '') >= started:
                return SUPERSEDED_SESSION, r['job']
    launched = (run or {}).get('launch_head')
    if launched and head is not None and head != launched:
        return SUPERSEDED_BRANCH, head
    return None
```

and the one call health makes, which composes the three facts and formats the line:

```python
def orphan_end(path, run, accounts, head=None, now=None, min_age_min=None):
    """``(fields, detail)`` for a live row this host should end without a liveness verdict, or
    None. Three facts, all of them required:

    * :func:`is_live` — health has written no end for it;
    * :func:`unknown_account` — this host did not launch it, so its pid, its log and its
      worktree are all about some other machine;
    * :func:`superseded` — the item has a newer session, or the branch moved past the head the
      launch handed it.

    and one floor: the row is at least ``min_age_min`` minutes old (the product's
    ``stage_limits.silent_min``, :func:`asf.workers.stall.silent_minutes`). Rename an account in
    ``worker_pool`` and every row under it is unknown at once, working or not; nothing younger
    than the product's own bound on a quiet session is ever taken for an orphan.

    ``fields`` is what to append to the registry — ``ended``, ``end_reason`` (:data:`DEAD_PID`,
    unchanged: four readers match that exact string, C7) and ``superseded_by`` — and ``detail``
    is health's line: ``dead pid, superseded by <job>``."""
    if not is_live(run) or not unknown_account(run, accounts):
        return None
    now = now or now_iso_utc()
    if min_age_min is not None and _age_minutes(run, now) < min_age_min:
        return None
    found = superseded(path, run, head)
    if not found:
        return None
    rule, by = found
    detail = (f'{DEAD_PID}, superseded by {by}' if rule == SUPERSEDED_SESSION
              else f'{DEAD_PID}, its branch moved past {by[:9] or "no head on origin"}')
    return ({'ended': now, 'end_reason': DEAD_PID,
             'superseded_by': {'rule': rule, 'by': by, 'at': now}}, detail)
```

`RUN_FIELDS` gains `'superseded_by'` (P9), so a relaunch of the same job opens a run that does not
inherit it.

### 2. `asf/workers/health.py` — one branch, where the row is stuck

The run pass's `steps` today ends at `judge`'s `None`:

```python
reason = lifecycle.judge(s, ev, landing=lifecycle.lands(s, registry))
if reason is None:
    return
```

which becomes the only edit to the pass:

```python
reason = lifecycle.judge(s, ev, landing=lifecycle.lands(s, registry))
if reason is None:
    # judge said "still running", and for a row this host did not launch that is a verdict
    # about somebody else's pid: end it on what moved past it instead (F-0206)
    orphan = lifecycle.orphan_end(registry, s, accounts,
                                  head=heads.sha(product.repo_dir, s.get('branch')),
                                  min_age_min=silent_min)
    if orphan:
        fields, detail = orphan
        pool_mod.update_session(product, job, **fields)
        s.update(fields)
        found.append((job, 'ended', detail))
    return
```

`accounts`, `silent_min` and `heads` are read once for the pass, beside `registry` and `alive`:

```python
accounts = [a.name for a in pool_mod.accounts_from_config(spawn_mod.load_cfg())]
silent_min = stall_mod.silent_minutes(product)
heads = lifecycle.RemoteHeads()          # hoisted from the worktree pass (C10)
```

and the worktree pass below reuses the same `heads` rather than building a second one.

### What it looks like when it is there

The tick, today, for five hours:

```
IN FLIGHT — 3 sessions
item    kind  account                        status
B-1381  fix   <an account this host does not configure>   dead pid
…
```

and after, on the first health pass that sees it:

```
ended     fix-b-1381               dead pid, superseded by code-b-1381
```

The row leaves every live view, `asf sessions` counts it under Dead no more, and its worktree —
if there is one on this host — falls to the reap ladder that a live row had been keeping it out
of.

## Acceptance tests

Two new classes. The rule itself is pure and belongs beside the other judgement invariants in
`tests/test_lifecycle.py`; the pass that calls it belongs beside `TestHealth` in
`tests/test_workers.py`, whose `Home` fixture already gives a real git origin, a real registry
and a real spawn through the fake runtime.

**The rule, pure.** `OrphanRuleTests` in `tests/test_lifecycle.py`, over hand-built registry
lines: `unknown_account` is true for an account name the list does not carry, true for a run with
no `account` key at all, false for one the list carries, and false for every run when `accounts`
is None; `superseded` finds a newer session on the item and names its job, ignores the row's own
job, ignores a run of another item, ignores a run started strictly earlier, and ignores a run
before the item's newest reset (P5); with no newer session it falls to the branch rule, firing
when `head` differs from `launch_head`, firing when `head` is `''` (origin holds the branch no
more), not firing when `head` equals `launch_head`, not firing when `head` is None, and not
firing at all for a run with no `launch_head` (P6); `orphan_end` returns None for a live row on a
known account, None with no supersession, None below the age floor and fields at it, writes
`end_reason` exactly `lifecycle.DEAD_PID` (C7) and a `superseded_by` of `{rule, by, at}`, and its
detail reads `dead pid, superseded by <job>` for the session rule and `dead pid, its branch moved
past <sha9>` for the branch rule; and `'superseded_by'` is in `RUN_FIELDS`, with a fold over a
launch line following an ended superseded run asserting the new run does not carry it (P9).
