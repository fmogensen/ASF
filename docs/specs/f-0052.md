# F-0052 — the Epic's budget is a stop, not a column

An Epic's budget is typed on the card, summed by the rollup and printed by the roadmap, and
nothing anywhere reads it as a limit. `asf/budget.py` says so out loud: `of()` returns an empty
`Budget()` for anything typed `epic`, with the reason in its docstring — *"An Epic has no budget:
it launches no row, and its `budget_usd` is the subtree figure the rollup reports (F-0101), not a
stop"* (`asf/budget.py:51`). The roadmap prints `$512.40 / $500` in its **Spend / budget** column
(`asf/views/roadmap.py:55`) and the wave launches the next session under that Epic regardless. A
number an operator sets and the factory ignores is worse than no number: it reads as a control.

This makes it one. The Epic's accumulated subtree spend is judged against the `budget_usd` its own
card types, and an Epic past it starts **no new work** — its ready spec, plan, code, direct and
fix rows become `WAITS ON budget`, taking no session and no slot, while everything that *finishes*
what is already spent goes on: the reviews, the landings, the corrections, the rebases, the
rulings and an incident's fix. The wave raises one line per held Epic, the groom asks for the
ruling that raises or reshapes it, and the roadmap's own budget cell says the work is held — so
the hold is read in the table that shows the budget, not dug out of a tick log.

The budget is a field on the Epic card, so an operator sets it per Epic and per product without
touching the tool: enforcement is per product by construction, with no new convention key.

## 1. Decisions

### 1.1 Preconditions

- **The Epic's budget is already a typed field, and already read.** `budget_usd` on an Epic card
  is read by the roadmap (`asf/views/roadmap.py:56`) and by the rollup's daily `budget:` line
  (`asf/metrics/metrics.py:1457`). No new field, no new convention key, no schema change.
- **The subtree spend already has one owner.** `ix.usd(ix.subtree(items, epic))` — the sum of
  `cost.usd` over the Epic and everything beneath it (`asf/views/index_reader.py:42`, `:95`) — is
  the figure the roadmap prints. `metrics.subtree_cost` (`asf/metrics/metrics.py:434`) computes the
  same sum over the rollup's freshly-computed costs and writes it to the Epic's machine
  `spend_usd`. The gate reads the *index*, not `spend_usd`: `spend_usd` is a snapshot the daily
  rollup wrote and can be a day stale, while `cost.usd` on each card is what the record holds now.
- **`cost.usd` is `None` when nothing measured it.** `budget.spent` already rules that an
  unmeasured dollar is not a spent one (`asf/budget.py:76`), and `ix.usd` returns `None` when no
  item under the Epic carries a figure. Both keep that rule here: `None` is never over.
- **`asf/budget.py` is a leaf.** Its module docstring is explicit — *"the stdlib and
  `asf.conventions` only — so the feeder, the metrics writer, the health step and the board view
  may all import it"*. Every addition here obeys it: the verdict takes two numbers and returns
  one, and the caller does the summing through `ix`.
- **The feeder already has the hold shape, twice.** `hold_unlanded` (`asf/feeder/rows.py:1058`)
  and `hold_classes` (`:1091`) each rewrite a launching row into a `WAITS ON <what>` row with a
  `waits_on` and a `reason`, chained inside `candidates()` (`:1115`) so that `asf next`, the wave,
  the shadow tick and `asf status` all see the same answer. `hold_classes`' `HELD_KINDS` (`:1085`)
  is already the factory's enumeration of *new work*: `CARD → SPEC`, `STARVED → SPEC`,
  `STARVED → PLAN`, `PLAN → CODE`, `CARD → SPEC+PLAN`, `DIRECT → BUILD` and `BUG → FIX`, with the
  docstring *"new work only — a review, a correction, an adjudicate, the groom and landing are
  never held"*.
- **A non-launching tier-2 row is dropped by the cut when no seat is free.**
  `tiers.select` keeps a non-launching row only `if free > 0 or r.tier < TIER_REST`
  (`asf/feeder/tiers.py:51`). So the wave's line may **not** be counted off the planned rows —
  on the busiest tick, when the hold matters most, they are not there. §2.4 derives the line from
  the index instead.
- **`ctx.event(kind, **fields)` appends one free-form JSON line** to
  `metrics/events/<day>.jsonl` in the record clone (`asf/tick/tick.py:171`), with no schema to
  extend — unlike the five validated streams (`metrics.STREAMS`).
- **The groom already asks the item-budget question and takes a ruling.**
  `groom_over_budget_section` (`asf/groom/groom.py:634`) prints one line per open card over its
  budget with the three answers, and `ANSWER_BUDGET` (`:43`) parses `budget <n>` /
  `budget <n> $<usd>` into typed fields. It skips every Epic today only because
  `budget.spent` gives an Epic no budget to be over.
- **F-0092 is still in flight.** Its spec and plan landed (`docs/specs/f-0092.md`,
  `docs/plans/f-0092.md`) and two of its seven Tasks did — `conventions.budget` with
  `asf/budget.py` (`96248e18f`) and the groom's ruling (`cdccac22b`). Its Task 3 —
  `over_budget(rows, items, product)` in `asf/feeder/rows.py`, the **item** arm of the same hold —
  and its I14 invariant have not. §1.4 records how the two meet.
- **The gate is `python3 tools/run_tests.py`** (one module per process, `ASF_GATE_MODULES` to
  narrow it), `tools/check_generic.sh` (the redaction scan, `python3 -m asf.redact --tree`) and
  `tools/check_conventions.sh`.

### 1.2 In

- **`asf/budget.py`** — the Epic verdict as a leaf: `EpicSpend`, `epic_spend(epic_id, spend_usd,
  budget_usd)`, `epic_line(s)`, and `OVER_MARK` (the roadmap's word).
- **`asf/views/index_reader.py`** — `subtree_usd(items, item)`, one line: `usd(subtree(items,
  item))`, so the gate, the roadmap and the groom sum the subtree through one function.
- **`asf/feeder/rows.py`** — `BUDGET`, `BUDGET_HELD_KINDS`, `epic_verdicts(items)`,
  `epics_over_budget(items)` and `over_budget_epics(rows, items)`, the last chained in
  `candidates()` beside `hold_unlanded` and `hold_classes`.
- **`asf/tick/step_wave.py`** — `launch()` raises one `OVER BUDGET` line per held Epic and writes
  one `budget_hold` event, before the plan's own `waits` lines.
- **`asf/views/roadmap.py`** — the **Spend / budget** cell gains `· over — work held`.
- **`asf/groom/groom.py`** — `groom_over_budget_section` takes `derived` and asks the Epic
  question too; `ANSWER_BUDGET` gains the dollars-only form `budget $<usd>`; the history line and
  the event survive a ruling with no session count.
- Tests: §3.1–§3.5, plus the gate (§3.6).

### 1.3 Out

- **A `conventions.budget` key for an Epic.** An Epic's budget stays a per-record typed field. An
  Epic with no `budget_usd` is unlimited — a product-wide default would put every Epic of every
  product under a cap its operator never wrote, and the card asks for the opposite ("a per-record
  typed field, so enforcement is per product by construction").
- **A sessions budget on an Epic.** Dollars only. `budget_usd` is the measure the Epic's card
  types, the rollup accumulates and the roadmap prints; the session count of an Epic's subtree is
  the sum of items each already capped at `conventions.budget.sessions` by F-0092, and a second
  sessions cap above them would judge the same measure twice. A `budget <n>` answer on an Epic is
  refused with one line (§2.6) rather than silently writing a field nothing reads.
- **An invariant backstop.** F-0092's plan already assigns I14 to the budget hold
  (`docs/plans/f-0092.md`, P11) and mints the id there; a second invariant here would be a second
  copy of one judgement, under an id this session may not mint. The Epic arm joins I14 when it
  lands.
- **The item arm of the hold.** An item over *its own* budget is F-0092 Task 3's, unchanged here.
  §1.4.
- **Unholding by spending less.** The hold lifts when the budget is raised, the Epic is reshaped,
  or its work is closed. Nothing in this change lowers a recorded cost.
- **The rollup's daily `budget:` line.** It already names spend against budget
  (`asf/metrics/metrics.py:1457`); repeating "held" in a file written once a day adds nothing the
  roadmap and the wave line do not say sooner.
- **Holding what is already spent.** No review, landing, correction, rebase, stalemate, groom or
  S1/S2 fix is ever held — §1.4's first row.

### 1.4 The choices

| # | Chosen | Against | Why |
| --- | --- | --- | --- |
| D1 | The hold covers **new work only**: `BUDGET_HELD_KINDS`, the flattened union of `HELD_KINDS` | Holding every launching row under the Epic | A budget stops the factory *starting* more, not finishing what it bought. Holding a `PUSHED → REVIEW` abandons a pushed branch; holding `FIX → CORRECT` leaves a red PR open forever; holding `GROOM → ADJUDICATE` or `STALEMATE → ADJUDICATE` blocks the very session that answers the budget question — a deadlock the Feature would file against itself. Reusing `HELD_KINDS`' union rather than writing a second list means `feeder.hold` and the budget hold can never disagree on what "new work" is. |
| D2 | An **S1/S2 Bug's `BUG → FIX` row is exempt** even though `BUG → FIX` is in `HELD_KINDS` | Holding every `BUG → FIX` under the Epic | A production incident is not discretionary spend, and the S1 lane exists precisely to outrank ordinary ordering (`asf/feeder/tiers.py`). An operator who set a budget did not ask for an unfixed S1. S3/S4 fixes are new work and are held. |
| D3 | Spend is the **live subtree sum off the index** (`ix.subtree_usd`) | The Epic's machine `spend_usd`, written by the daily rollup | `spend_usd` is a snapshot up to a day old; `cost.usd` per card is what the record holds now. Reading the index also makes the gate and the roadmap cell arithmetically identical by construction — one function, one input — so the table can never show under-budget while the feeder holds. |
| D4 | The verdict is `>=`, matching `budget.spent` | `>` | `budget.spent` stops an item at `sessions >= budget.sessions` (`asf/budget.py:89`). One comparison for both halves of the same word "over". |
| D5 | The wave's line is derived from **the index**, not from the planned rows | Counting the held rows in `planned` | `tiers.select` drops a non-launching tier-2 row when no seat is free (`asf/feeder/tiers.py:51`), so a row-derived line would go silent on exactly the busy ticks where the hold changed the outcome. The line names the Epic and the two figures; the rows themselves say `WAITS ON budget` in `asf next` and in the wave's per-row `waits` lines. |
| D6 | The line is raised only for an Epic over budget **with open work beneath it** | One line per over-budget Epic, every tick | An Epic over budget whose work is all Closed has nothing held; a line every tick for it is noise that trains the operator to skip the word. The standing fact lives in the roadmap cell, which is not a per-tick line. |
| D7 | The roadmap marks the **Spend / budget** cell | The **State** cell, beside `· blocked` | The State column speaks for the Epic's own recorded state, which a budget does not change. The cell that already pairs the two numbers is where the reader's eye is when the question is "has it run out". |
| D8 | The groom's Epic question reuses `groom_over_budget_section`, fed `derived` | A section of its own | One section, one answer grammar, one place the operator reads "over budget". `derived[iid]['children']` is already computed and already passed to `build_groom_sections` (`asf/groom/groom.py:1009`), so the Epic's subtree is summed through `ix.subtree_usd` like everywhere else. |

The `$` is already optional-but-accepted in the two-value form, so the vocabulary does not grow. |
| D10 | The hold is **derived every tick**, nothing written to the Epic card | A machine `budget_state: over` field | A written flag goes stale the moment the operator raises the budget or a Task closes, and the record would then disagree with the feeder. `blocked` / `blocked_by_open` are derived the same way (`asf/feeder/rows.py:183`). The *event* is written (§4), because an event is a fact about a moment and cannot go stale. |

The plan cut from this spec should declare `after:` on F-0092's feeder Task if it is still open then: the two arms are branches of one function, and the second to land writes the smaller diff. |

## 2. The design

### 2.1 `asf/budget.py` — the Epic verdict, still a leaf

```python
#: an Epic's only budget: the typed field on its own card (D1.3 — no product default)
EPIC_USD = 'budget_usd'
#: what the roadmap's Spend / budget cell appends for an Epic past it
OVER_MARK = 'over — work held'


@dataclass(frozen=True)
class EpicSpend:
    """What an Epic's subtree has spent against the budget its own card types. ``usd`` is the sum
    of ``cost.usd`` beneath it (``None``: nothing under it was measured); ``budget`` is its
    ``budget_usd`` (``None``: no budget, so no stop)."""
    epic_id: str = ''
    usd: float = None
    budget: float = None

    @property
    def over(self):
        return (isinstance(self.usd, (int, float)) and isinstance(self.budget, (int, float))
                and self.usd >= self.budget)


def epic_spend(epic_id, spend_usd, budget_usd):
    """:class:`EpicSpend` for one Epic. Two numbers in, one verdict out: the caller sums the
    subtree (:func:`asf.views.index_reader.subtree_usd`), because this module reads no index.
    A non-numeric figure on either side is ``None`` — an unmeasured dollar is not a spent one,
    and a ``budget_usd:`` an operator typed as text is no budget at all."""


def epic_line(s):
    """The wave's line for a held Epic::

        OVER BUDGET E-0001 — $512.40/$500 spent, new work held

    The same first word as :func:`line`, so one grep finds every budget stop."""
    return f'{OVER} {s.epic_id} — ${_money(s.usd)}/${_money(s.budget)} spent, new work held'
```

`of()` keeps its Epic branch and its docstring gains the second half of the sentence: an Epic
still launches no row of its own and still has no *item* budget, and its `budget_usd` is now read
by :func:`epic_spend` as the subtree's stop.

### 2.2 One owner of the subtree sum

```python
# asf/views/index_reader.py
def subtree_usd(items, item):
    """The measured dollars at and under ``item`` — the figure the roadmap prints, the feeder
    gates on and the groom asks about, so the three can never disagree."""
    return usd(subtree(items, item))
```

`roadmap.render` swaps its `ix.usd(ix.subtree(items, e))` for this call; nothing else about the
sum changes.

### 2.3 The feeder holds the Epic's new work

```python
# asf/feeder/rows.py
#: the ``waits_on`` of a row an Epic's spent budget holds
BUDGET = 'budget'
#: what an Epic's spent budget holds: new work only, `HELD_KINDS`' own enumeration — one list, so
#: `feeder.hold` and the budget hold can never disagree on what "new work" means
BUDGET_HELD_KINDS = frozenset(k for ks in HELD_KINDS.values() for k in ks)


def epic_verdicts(items):
    """``{epic id: EpicSpend}`` for every Epic in the map — one subtree sum per Epic per pass."""
    return {e['id']: budget.epic_spend(e['id'], ix.subtree_usd(items, e), e.get('budget_usd'))
            for e in ix.of_type(items, 'epic')}


def epics_over_budget(items):
    """``[EpicSpend]`` in id order: every Epic past its budget that still has open work beneath
    it. Read from the index alone — the wave's line must not depend on how many held rows
    survived the capacity cut (§1.1)."""


def over_budget_epics(rows, items, verdicts=None):
    """F-0052: an Epic whose accumulated spend has passed its typed ``budget_usd`` starts nothing
    new. Each launching row of :data:`BUDGET_HELD_KINDS` under such an Epic becomes
    ``WAITS ON budget`` — no session, no slot, still shown — with the Epic and both figures in
    its ``reason``.

    Never held: every other kind (a review, a landing, a correction, a rebase, a stalemate, the
    groom), because a budget stops starting work, not finishing it; and an S1/S2 Bug's
    ``BUG → FIX``, because an incident is not discretionary spend. An item with no Epic above it
    has no budget to be over."""
    verdicts = epic_verdicts(items) if verdicts is None else verdicts
    out = []
    for r in rows:
        item = items.get(r.item_id) or {}
        epic = ix.epic_of(items, item)
        s = verdicts.get(epic['id']) if epic else None
        exempt = (r.kind == BUG_FIX and item.get('severity') in ('S1', 'S2'))
        if s is None or not s.over or not r.launches or exempt \
                or r.kind not in BUDGET_HELD_KINDS:
            out.append(r)
            continue
        out.append(dataclasses.replace(
            r, action=f'{WAITS_BUDGET}: {s.epic_id} over ${_money(s.budget)}',
            waits_on=BUDGET,
            reason=f'{s.epic_id} over budget: ${_money(s.usd)}/${_money(s.budget)} spent — '
                   f'raise it, reshape it or close its work'))
    return out
```

with `WAITS_BUDGET = 'WAITS ON budget'` beside the other `WAITS_*` actions (`:99`, `:102`). In
`candidates()` it is chained where the other holds are, after `hold_classes` and before the
attempt cap — so it is inside the one path `asf next`, `asf status`, the shadow tick and the wave
all take:

```python
    rows = hold_unlanded(rows, items, landed_shas)
    rows = hold_classes(rows, product)
    rows = over_budget_epics(rows, items)          # F-0052
```

A held row keeps its tier, its item and its Feature, so the NEXT table reads:

```
| Tier | Row | Item | Feature | Action |
|---|---|---|---|---|
| 2 | PLAN → CODE | T-0244 | F-0112 | WAITS ON budget: E-0001 over $500 |
```

### 2.6 The groom asks, and the ruling raises it

`groom_over_budget_section(canonical, derived, product)` keeps its item loop and gains the Epic
one. The item map the sum needs is the card record in the index's shape, built from what the
caller already has:

```python
def _index_view(canonical, derived):
    """``canonical`` as :mod:`asf.views.index_reader` reads an index — ``id``, ``type``,
    ``children``, ``cost`` — so an Epic's subtree spend is summed by the one function the roadmap
    and the feeder use, not a third copy of the walk."""
    return {iid: dict(rec['meta'], id=iid,
                      children=(derived.get(iid) or {}).get('children') or [])
            for iid, rec in canonical.items()}
```

The Epic's line names both figures, that the work is held, and the three answers:

```
- [ ] E-0001 ASF 0.1 — a working factory — $512.40/$500 spent, new work held: raise it
      (`budget $750`), reshape it (`reshape: <how>`) or close its work (`no: <why>`) → answer: ____
```

The grammar takes a dollars-only ruling, the `$` required (D9):

```python
ANSWER_BUDGET = re.compile(
    r'^budget\s+(?:(?P<sessions>\d+)(?:\s+\$?(?P<usd>\d+(?:\.\d+)?))?'
    r'|\$(?P<usd_only>\d+(?:\.\d+)?))$', re.I)
```

`answer_for` returns `('budget', {'budget_usd': 750})` for it, and the writer stops assuming a
session count was given:

```python
            parts = ([f"{value['budget_sessions']} sessions"] if 'budget_sessions' in value else []
                     ) + ([f"${value['budget_usd']}"] if 'budget_usd' in value else [])
```

`budget <n>` (sessions) answered against an Epic is refused with one line — *an Epic has no
session budget; answer `budget $<usd>`* — through the same refusal path a bad answer already
takes, because writing `budget_sessions` on an Epic would type a field `budget.of` deliberately
ignores (`asf/budget.py:59`).

## 3. Acceptance tests

### 3.1 The Epic verdict, and the line

`budget.epic_spend('E-0001', 512.40, 500)` is `over`, and `epic_line` of it is exactly
`OVER BUDGET E-0001 — $512.40/$500 spent, new work held`. Not over: `(499.99, 500)`; over at
equality: `(500, 500)` (D4). Never over, and never an exception: `(None, 500)` (nothing
measured), `(512.40, None)` (no budget), `(None, None)`, `('lots', 500)` and `(512.40, 'plenty')`.
`$10` prints as `$10` and `$512.4` as `$512.40` through the module's own `_money`. `EpicSpend` is
frozen, and `budget.of(Conventions(), {'type': 'epic', 'budget_usd': 500})` still returns an empty
`Budget()` — the Epic has an Epic budget and no item budget.

### 3.2 The feeder holds the new work and nothing else

Over a hand-built item map — `E-0001` with `budget_usd: 500` over two Features whose Tasks carry
`cost.usd` summing past it, and `E-0002` with no budget — `rows.candidates`:

- every `CARD → SPEC`, `STARVED → SPEC`, `STARVED → PLAN`, `SPEC → PLAN`, `PLAN → CODE`,
  `CARD → SPEC+PLAN`, `DIRECT → BUILD` and S3 `BUG → FIX` row under `E-0001` has
  `launches is False`, `waits_on == 'budget'`, an action naming the Epic and its budget, and a
  reason naming both figures;
- `PUSHED → REVIEW`, `PUSHED → LAND`, `FIX → CORRECT`, `CONFLICT → REBASE`,
  `STALEMATE → ADJUDICATE`, `GROOM → ADJUDICATE`, `GROOM → CLERK` and `STALE → CLOSE` rows under

- an S1 and an S2 `BUG → FIX` under it still launch (D2);
- no row under `E-0002` changes, and no row of a parentless Feature changes;
- `UNDECIDED → DECIDE` rows are untouched (they launch nothing already);
- at `$499.99` of `$500` nothing is held; raising `budget_usd` to `$750` in the map unholds

### 3.3 The wave's one line, and its event

exactly one line starting `OVER BUDGET E-0001`, whatever the number of held rows, and it precedes
every `waits` line for those rows. With **zero free seats** (in-flight sessions filling the
share), the `OVER BUDGET` line is still printed — the §1.1/D5 regression. One
`kind: budget_hold` event is appended to `metrics/events/<day>.jsonl` in the record clone, with
`item`, `spend`, `budget`, `product` and `ts`, and the file parses one JSON object per line. An
Epic under its budget prints no such line and writes no event. Two Epics over budget print two
lines, in id order, one event each.
