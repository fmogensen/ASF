# F-0162 — the marker is written for a commit nobody has

On 2026-09-26 an operator typed `asf upgrade --ref <sha>` with the right nine-character prefix
and garbage after it. The upgrade wrote `state/upgrade-pending.json` for that sha, parked every
product's tick behind it, and only then handed the string to `pipx`, which failed on a commit
that does not exist. The card's fix is one sentence: **resolve the ref before writing the
marker; refuse an unknown ref with a clear error.**

Two things have to be said about that sentence before this spec can be written, and both come
from reading the tree at `5304f6d16` rather than the card.

**The half the card describes is already fixed, and it is not the half that bites.** T-0408
(`f57fe2064`, 2026-09-28) put `resolve_ref` in front of the marker exactly as the card asks —
but only for a ref that is *not* forty hex characters. `HEX40.match(ref)` short-circuits it
(`asf/upgrade.py:358`), on the reasoning that a resolved commit is already a commit and
`--to`'s sha form should cost no round trip. A mistyped sha whose garbage is hex, and whose
length is still forty, is exactly the string that passes that gate untouched. The card's own
scenario — nine right characters, thirty-one wrong ones — is a forty-hex string. So the typo
the card proved is the one shape still going straight through, and the four other shapes of it
(wrong length, a non-hex character, a short sha, a tag) are all refused already.

**The card's proposed probe cannot answer the question.** `git ls-remote <url> <sha>` lists
*refs*, and a bare commit matches none of them: run against this product's own remote with its
own head, it prints nothing and exits 0 (P5). `git rev-parse` needs a local clone, and there is
none under a `pipx` install — `drift.factory_root()` returns `None` whenever `.git` does not sit
beside the package (P6). Neither of the card's two suggestions can tell an operator's typo from
a real commit on the machine where the defect happens. Something else has to answer, and the
answer has to be **three-valued**: yes, no, and *cannot tell* — because a probe that reads
"cannot tell" as "no" would refuse every upgrade the moment the network blinks.

That three-valued discipline is already in this module, one function above the bug. `ci_red`
returns False for "no `gh`, not a GitHub url, unparseable" — *the check is skipped, never
guessed* (`asf/upgrade.py:441-443`). This change adds the second check of the same shape, and
the same rule governs it: an answer that is not knowable never refuses an install and never
withholds a marker.

One more thing falls out of the same resolver, at no extra cost, and this spec takes it:
`docs/guide/upgrading.md:30` tells the operator `asf upgrade --to 7a5881d  # or any commit sha`,
and **that command is refused today** — a seven-character sha is not forty hex, so it goes to
`ls-remote`, matches no ref, and comes back `None` (P7). The same probe that says a mistyped sha
is not a commit says that a short one is, and hands back its full form. The guide's promise is
kept by the same call. It is a separate Story so it can be dropped separately.

### In

- **`known_ref(url, ref, run)`** — the install source's answer about one commit, three-valued:
  the **full sha** when the source confirms it, **`False`** when the source says it has no such
  commit, **`None`** when that cannot be known. One `gh api` call, the sha media type, a 30 s
  timeout, read from stdout.
- **`resolve_target(url, ref, run)`** — the one gate every `--to`/`--ref` passes: `(commit,
  refusal)`. It folds today's `resolve_ref` call and the new probe into a single answer, so
  `install` has one branch instead of two.
- **A refusal before anything is written** — before `other_ticks`, before `refuses`, before
  `write_pending`, before `drain`, before `pipx`. One line naming the ref and the source, exit
  **2**.
- **A short sha installs**, the way `docs/guide/upgrading.md:30` already says it does: the probe
  expands `7a5881d` to its commit, `pipx` still receives what the operator typed.
- **`_out(..., any_rc=True)`** — one keyword, default-off, so the probe can read a body that
  came with a non-zero exit (P10). Every existing caller is unchanged.
- **`_NWO`** — `ci_red`'s inline regex lifted to a module constant, used by both (P14).
- **The prose**: the module docstring's marker paragraph, and one sentence in
  `docs/guide/upgrading.md` with an assertion in `tests/test_readme.InstallSectionTests`.

### Out

- **Any change to the marker's lifecycle** — `PENDING_TTL_S`, the cool-down, the `pid` liveness
  drop, `waiting`, `held`, the expiry `NEEDS OPERATOR` line. This change decides only *whether a
  marker is written*, never how long one lives. B-0141 and `e40b244db` own the rest (P3).
- **Verifying a ref on a non-GitHub install source, or without `gh`.** There is no portable
  probe: `ls-remote` cannot see a commit (P5) and `git fetch --dry-run <url> <sha>` downloads a
  pack for every *good* ref — every real upgrade — to answer a question about the bad ones. Such
  an install keeps today's behaviour exactly, by the `None` rule.
- **Second-guessing the typo.** No nearest-prefix hint, no "did you mean". The refusal prints
  the ref as given and the url it was not found on; the operator's own `git log` is the
  correction.
- **A second probe inside `refuses()`.** The gate is upstream of it (P11), so a copy there would
  buy nothing and cost a second round trip on every deferral. `refuses()` is unchanged.
- **Caching a refusal.** A tick that refuses a force-pushed head re-reads the head next tick;
  nothing is remembered between runs.
- **`ci_red`'s own behaviour.** It keeps returning False for an unknowable answer. Only its
  regex moves.

## The design

Everything is in `asf/upgrade.py`, above `install`.

### `_NWO`, and `ci_red` reading it (P14)

```python
#: ``owner/repo`` from a GitHub url, http or ssh, with or without ``.git``
_NWO = re.compile(r'github\.com[/:]([^/]+/[^/]+?)(?:\.git)?/?$')
```

`ci_red`'s first two lines become `m = _NWO.search(url)` / `if not m: return False`. Nothing
else in it moves.

### `_out` gains one keyword (P10)

```python
def _out(run, cmd, timeout=60, any_rc=False):
    """stdout of ``cmd``, or ``None`` when it fails or cannot start. ``any_rc``: keep stdout
    even when the command exited non-zero — for a command whose *answer* is the body it prints
    with its failure (:func:`known_ref`)."""
    try:
        p = run(cmd, capture_output=True, text=True, timeout=timeout)
    except (OSError, subprocess.SubprocessError):
        return None
    return p.stdout if (any_rc or p.returncode == 0) and isinstance(p.stdout, str) else None
```

### `known_ref` — the install source's three-valued answer

```python
#: GitHub's answer for a well-formed sha the repo does not have — a mistyped one. A 404 is the
#: repo being unreadable, never the ref being wrong (D4).
NO_COMMIT_STATUS = '422'


def known_ref(url, ref, run=subprocess.run):
    """The commit ``ref`` names on ``url``, ``False`` when the install source says it has no
    such commit, ``None`` when that cannot be known — not a GitHub url, no ``gh``, no network,
    or any answer this does not recognise. Callers test ``is False`` and ``is None``.

    The check is skipped, never guessed, exactly as :func:`ci_red` is: a probe that read silence
    as a refusal would stop the factory upgrading itself the first time the network blinked
    (D3). ``git ls-remote`` cannot answer this — it lists refs, and a bare commit matches none
    of them — and a ``pipx`` install has no clone to ``rev-parse`` (D1)."""
    m = _NWO.search(url or '')
    if not ref or not m:
        return None
    text = _out(run, ['gh', 'api', '-H', 'Accept: application/vnd.github.sha',
                      f'repos/{m.group(1)}/commits/{ref}'], timeout=30, any_rc=True)
    got = (text or '').strip()
    if HEX40.match(got):
        return got if got.lower().startswith(ref.lower()) else None
    try:
        status = str((json.loads(got) or {}).get('status'))
    except (ValueError, AttributeError):
        return None
    return False if status == NO_COMMIT_STATUS else None
```

The success branch checks that the sha it got back *starts with* the ref asked for, so the
short-sha expansion (D8) is confirmed rather than assumed, and an answer about some other
commit is `None` rather than a wrong yes.

### `resolve_target` — one gate, one answer

```python
def resolve_target(url, ref, run=subprocess.run):
    """``(commit, refusal)`` for the ``--to``/``--ref`` the operator gave: the commit to pin and
    verify, else ``None`` and the one phrase saying why it is refused. ``(None, None)`` for no
    ref at all — ``_install`` reads ``main``'s head itself.

    A ref that is not a sha is a ref first: ``ls-remote`` decides a tag or a branch, as it has
    since T-0408. What that misses — a forty-hex sha (never looked up) and a short one (no ref
    matches it) — the install source is asked about directly, so that the marker, the CI guard
    and ``pipx`` all see a commit that exists (F-0162)."""
    if not ref:
        return None, None
    resolved = ref if HEX40.match(ref) else resolve_ref(url, ref, run)
    known = known_ref(url, resolved or ref, run)
    if known is False:
        return None, f'{ref} is not a commit on {url}'
    if resolved:
        return resolved, None
    if known:
        return known, None  # a short sha no ref matched, expanded by the source (D8)
    return None, f'{ref} does not resolve to a commit on {url}'
```

The fall-through keeps today's refusal for an unknown tag with no probe available, so nothing
that is refused today becomes installable.

### `install()`'s head

The block at `asf/upgrade.py:525-534` becomes:

```python
    marked = None
    pin = ref
    url = repo_url(run) if ref else None
    if ref:
        ref, refusal = resolve_target(url, ref, run)
        if refusal:
            out(f'upgrade: refused — {refusal}; no upgrade is pending and no tick is parked')
            return 2
    others = other_ticks(run)
    if others and (owner or wait_s):
        url = url or repo_url(run)
        ...
```

`others = other_ticks(run)` moves below the gate, so a refused ref costs no `pgrep`, and
`repo_url` is read once per call instead of twice. Nothing else in `install` changes: `pin`
still carries what the operator typed, `_install(ref, …, pin=pin)` still gives `pipx` the tag or
the short sha as given, and the post-install check still compares prefixes both ways
(`:602`), which is what makes a short pin verify against the full sha.

## Records

This change writes **nothing** new to the record, and its whole point is a file that is **not**
written.

- **No new file, no new state.** `state/upgrade-pending.json` keeps its three keys (`sha`,
  `owner`, `at`, plus `pid` for an operator's wait); `state/upgrade-last.json` and
  `state/upgrade-expired.json` are untouched. The change is that the pending marker is not
  created for a ref the install source does not have.
- **No row, no schema move.** `index.json` gains nothing, `schema.record_version` does not move,
  no migration.
- **No event.** Nothing is appended to `metrics/events/<day>.jsonl`.
- **One line to stdout**, in one place — `install()`'s refusal — which lands in the tick log
  when a tick's head has been force-pushed away, and on the operator's terminal otherwise.
- **Two readers stop being able to lie.** `asf doctor`'s `SCHEDULER` section
  (`asf/doctor.py:713-715`) and `asf status`'s `Cron` row (`asf/views/status.py:380-381`) render
  `held_label(marker)`; with no marker written for a bad ref, neither can report a hold that
  will never install.
- **One network call per upgrade attempt with a ref**, 40 bytes of answer, 30 s timeout, on the
  path that already makes one `gh run list` call for the CI guard. A run with no `--to` and no
  tick head — plain `asf upgrade` — makes none.

## Stories

- S: `known_ref` answers *is this a commit on the install source* three ways — the sha, `False` for the source's own 422, and `None` for everything it cannot know, including 404, no `gh` and a non-GitHub url — acceptance: `python3 -m unittest -v tests.test_install.KnownRefTests`
- S: `resolve_target` is the one gate every `--to` passes — a ref is a ref first (`ls-remote`), a sha is asked of the source, and the answer is `(commit, refusal)` — acceptance: `python3 -m unittest -v tests.test_install.ResolveTargetTests`
- S: a ref the install source does not have writes no pending marker, parks no tick, runs no `pipx`, leaves a marker it does not own alone, and exits 2 — acceptance: `python3 -m unittest -v tests.test_install.UnknownRefTests`
- S: `asf upgrade --to 7a5881d` installs, as `docs/guide/upgrading.md` has always said it does — the source expands the short sha and `pipx` still receives what was typed — acceptance: `python3 -m unittest -v tests.test_install.ShortShaTests`
- S: the guide and the module docstring say what a refused ref costs — nothing is pending and no tick is parked — acceptance: `python3 -m unittest -v tests.test_readme.InstallSectionTests`
