# B-82960 — spec: a factory that cannot unblock itself

The card is one deadlock, reported at a moment when the factory was wide open:

> At this check: 0 of 8 cloud seats busy and 1 row ready to launch. A factory fix for this is
> itself blocked, because its Task writes the same files.

Eight idle seats, ranked work on the record, and nothing launched. The 2026-10-08 scope freeze
set about 178 Features to `priority: later`; the Tasks already Active under them kept their
`writes:` footprints, every ranked Task touching the same hot files
(`asf/cli.py`, `asf/conventions.py`, `asf/feeder/rows.py`, `asf/record/core.py`) carried an
`after:` edge to one of them, and invariant I3 refused to remove those edges —
*"writes: intersects Active task …"*. T-79565 waited on 21 parked Tasks, T-80572 on 7, T-81129
on T-79565, and 16 more behind them.

The fix for the deadlock itself landed on the trunk (`landing.sha 14b963ba`, PR #1244:
`asf/invariants.py:249` and `asf/feeder/rows.py:644`). This spec answers the other half of the
card — the half the deadlock proved, and the half this branch (`fix/B-82960-kernel-0.2`,
PR #1266) delivers:

**the floor's rules were spread across the components that enforce them, so no one of them could
say why a seat was idle, and no test could ask.** A parked item still held a lane because
"parked" was a property the feeder read, the invariants read, and the lane read, each in its own
words. The deadlock was not a bug in one of those readers. It was the absence of a single place
where the question *what should run now, and why not* is answered.

That place is `asf/kernel/` — ASF 0.2's kernel. Its whole contract is one pure function.

## §1 The shape: one tick, one pure decision

```
read facts  ->  decide(facts, config) -> Plan  ->  apply(plan)
```

- `asf/kernel/model.py` — the facts as plain values: `Item`, `Session`, `PR`, `Branch`, `Check`,
  `Review`, `Answer`, `Facts`, `Config`, and `State` (`New -> Ready -> Building -> Review ->
  Landing -> Done`, or `Stuck`, or `Parked`). Nothing here reaches a disk, a network or a clock.
- `asf/kernel/decide.py` — `decide(facts, config) -> Plan`. Pure: same arguments, same plan. It
  reads nothing but its arguments and returns the state of every item plus the actions of one
  tick. Every rule the floor spread out lives in its module docstring, in the design's words.
- `asf/kernel/ports.py` — the only code that touches the world: the record, GitHub (`gh`), the
  session host. Every write goes through one guard, so a dry run cannot mutate anything.
- `asf/kernel/apply.py` — one applier per action type, and nothing else.
- `asf/kernel/loop.py` — lock, read, decide, apply. A second tick on the same product finds the
  lock held and returns at once.
- `asf/kernel/gate.py` — the proof gate: `silent stuck`, `first-push green`, `landed`, each
  criterion read from the product's own `kernel.gate` block.

The deadlock cannot recur in this shape for one reason: **`Parked` is derived every tick and
never stored.** An item whose own `priority`, or an ancestor's through `parent`, is `later` is
invisible everywhere at once — no launch, no PR upkeep, no mint, never Stuck, never counted in a
`blocked_count`, and it holds nobody through `after:` or `writes`. Un-parking it finds the card
exactly as it was. There is no second reader to disagree with.

## §2 What the 18 scenarios pin

`tests/kernel/test_scenarios.py` was written before the kernel, one test per scenario, each
building `Facts` by hand and asserting on the returned `Plan`. They name the floor's failures
directly: a `later` item holding a lane, waits nobody declared, a stateless PR, a skipped check
read as red, an approval lost to a rebase, a dead session holding its item, one bad item stalling
the lane. `decide` is pure, so each is a few lines of values and one assertion — the kind of test
the deadlock could never have had while the rules lived in three components.

## §3 The six corrections this round answers

A review of the branch at `e2d39a934` found six defects. They are recorded here because each one
is a case where the kernel's *documented* rule and its code had come apart, which is the one
failure mode this design is supposed to make impossible to hide.

### C1 — `failing_files` cut one dotted part too few (`asf/kernel/ports.py`)

Python 3.12 and later print a failing case as `FAIL: test_x (tests.test_mod.Case.test_x)` — four
dotted parts, the method appended. The cut was `n == len(parts) - 1`, which on that name yields
`tests/test_mod/Case.py`, a file no PR holds. `on_pr` (`decide.py`) then found a non-empty file
list meeting none of the PR's files, so every required red went Rerun → Stuck(owner=ci) instead
of to a fix round: a red the author could have fixed in one round became an operator's problem.
The module is now the prefix before the first capitalised part — the test class — so both the
three-part and the four-part form read as `tests/test_mod.py`.

### C2 — a container that *derives* `Parked` was read as a live holder (`asf/kernel/decide.py`)

`_parked` returns the ids that are `later` themselves or under one. A Feature that is **not**
`later` but whose every child is derives `State.PARKED` in pass two — correctly — yet it is not
in that set, so `_visible` called it live and a ranked Task with an `after:` edge to it stayed
New for ever. This is the card's own deadlock, one level up and inside the kernel:

```python
[B.item('F-0001'), B.task('T-0001', parent='F-0001', priority='later'),
 B.task('T-0002', rank=1, after=['F-0001'])]
# before: F-0001 PARKED, T-0002 NEW, launched []
```

A wait is now read off the target's **state** — neither Done nor Parked — not off `priority`
alone, in `_apply_waits` and in the idle alarm both.

### C3 — the two verdict forms in one brief (`asf/kernel/briefs.py`)

A review brief is the floor's `review.md` template plus the kernel's `VERDICT_RULE`. The template
asks for a fenced block whose line reads `verdict: approved`; the rule asks for a line
`VERDICT: approve`. The parser accepted only the second, so a reviewer who followed the template
had the review recorded as `NO_VERDICT`, and the second such review wedged the item
Stuck(owner=loop) at `max_attempts`. Both forms (and a trailing remark after either) now read as
the same verdict, `approved` normalised to `approve`, and a test takes the line out of the
template file itself so the two cannot drift again.

### C4 — an approved draft PR planned auto-merge for ever (`asf/kernel/ports.py`, `model.py`)

`PR_FIELDS` never asked GitHub for `isDraft`, so the model had no `draft` and an approved draft
reached Landing and planned `EnableAutoMerge` on every tick. GitHub refuses auto-merge on a
draft; the refusal raises through the write guard and — unlike `UpdateBranch` — records no
attempt, so the item sat in Landing silently for ever. PR #1266 is itself a draft, which is how
the review found it. The flag is now read, and an approved draft is held in Review with an item
note until its owner marks it ready. Every other reader in this product already reads `isDraft`
the same way (`asf/ci_queue.py`, `asf/dwell.py`, `asf/harvest/lane.py`).

### C5 — `_claimed_on_origin` promised a sha and discarded it (`asf/kernel/decide.py`)

Its docstring said "the origin branch is at that sha or has moved past it"; the code tested the
branch *name* and threw the sha away. So a push the pre-push hook refused, reported honestly as
`pushed: yes <sha>`, counted as a push and opened a PR on the previous round's head — a review of
code nobody wrote. The claim is now checked against `Branch.head_sha` (a short sha in a report
counts as a prefix); a head origin never read holds nothing against the claim.

### C6 — the work had no spec, no plan and no id in its commits

Eighteen commits read `kernel(0.2): …` with no item id, and `docs/specs/b-82960.md` and
`docs/plans/b-82960.md` did not exist, while B-82960 was already `state: Resolved` and landed.
Harvest refuses a branch whose commits do not name the item, and the id inside the branch name
does not count. This file and `docs/plans/b-82960.md` are that half of the answer; the other half
— whether this work keeps B-82960 (reopened) or is minted as its own Epic/Feature — is the
operator's to decide, and is asked as a `NEEDS OPERATOR` line, never guessed.

## §4 What is deliberately not settled here

- **The id.** Only an operator mints one. Until the answer lands, this spec and the plan sit
  under B-82960, which is the card the whole branch was built against and the card PR #1266 is
  titled with.
- **The floor.** The kernel runs beside the existing tick, not in place of it. Nothing in
  `asf/kernel/` replaces a floor component; the cutover is its own decision with its own gate
  (`asf kernel gate`), and the gate's criteria are read from the product's config, never from a
  literal in the code.
