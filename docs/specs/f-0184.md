# F-0184 — a runner is discovered, measured, tiered and paced, and no human writes a label

Today a runner exists because somebody typed it into `ci.pool`, and it answers to `heavy` because
somebody typed that too (`ci_pool.py:8-14`: *"That list is the single source of truth"*). Register a
box and nothing uses it until a product file is edited. Let a box get slow and nothing notices —
`heavy` is a word, not a measurement, and the slowest box in the fleet carries it exactly as long as
the yaml says so.

The card's shape is the fix in four moves, and the fifth follows from them:

1. **Discover** — the effective pool is the runners the host reports. `ci.pool: discover`, and the
   list goes.
2. **Measure** — every green CI job already lands in the metrics `ci` stream with its runner and its
   duration (`metrics.py:1696-1698`). Read per runner per job kind, that is a median, a ratio
   against the fleet's best, and a green rate. Nothing new is collected from the host.
3. **Place** — a runner's routing label *is* its measured tier. Two of them, `asf-fast` and
   `asf-bulk`, with a hysteresis band between so a box does not flap, a provisional tier for a box
   with too few readings, and a floor so the fast tier is never empty.
4. **Pace** — `capacity.ci` already follows the pool's slot sum, so discovery carries it for free.
   `capacity.batch`'s `parallel` and `runners`, and the queue's PR and head wait limits, stop being
   constants and follow the measure.
5. **Guards** — a timing baseline is a *number this box actually reached on this job kind*, published
   per runner with its tier's as the fallback; and a green job that has grown half again past its own
   baseline is a row before it is ever a red gate.

Two things this spec refuses, both loudly, both in **Out** with their reasons: it does not learn a
box's cores, memory or disk, and it does not add a landing gate. The first is the card's own words and
the honest answer is a decision only the operator can make — see D3 and the `NEEDS OPERATOR` note in
§1's Out table.

### The choices

| # | Chosen | Against | Why |
| --- | --- | --- | --- |
| D1 | `ci.pool` accepts the string `discover` beside today's list; `load_pool` on a discovered product returns the **last census read off `<state dir>/ci-census.json`**, and never calls the host | `load_pool` calling `backend.runners()` when the pool is discovered | P1 is decisive: `load_pool` is pure today and sits on the `asf status` path, in product validation, in `runner_ci_free` and in the queue. A network call there would put a `gh` round trip — and a `gh` failure — behind a dozen read paths that cannot fail. The census has exactly two writers (the tick and `asf ci census --apply`) and every reader is a file read |
| D2 | A discovered product whose census has never been taken has an **empty** effective pool | Raising, or refusing the config | An empty pool is already a fully-supported state everywhere: `pool_ci` returns `(None, None)`, `drift` returns no rows, `runner_ci_free` returns None and the in-flight formula decides (P4, P5). So the degradation is to today's no-pool behaviour rather than to a new failure, and one required doctor row says the next tick will take one |
| D3 | A box's shape is **measured as speed**, never inspected as hardware | Reading cores, memory and disk over a login to each box, as the card's stage 1 reads | O1. Cores are a proxy; the thing every consumer in stages 3, 4 and 5 actually wants is *how long this box takes on this job kind*, and §2.2 measures that from readings the factory already keeps. Adding a credentialed transport to every CI box (P11: there is none) is a new security surface for a strictly worse signal. The card's own acceptance list names no hardware figure — it names a new runner used within a tick, a slow box moved, no hand-written label, and the scorecard falling, and every one of those is reachable from the measure |
| D4 | `seconds` is added per job and `wall_minutes` per run; `minutes` is left exactly as it is | Changing `minutes` to a float | P9: `minutes` floors, and `score.per_item`, `window_row`, `cost_table` and every stored weekly row are built on the floored figure. Re-defining it would move every historical scorecard number for a precision this card needs elsewhere. A second, finer field costs nothing and changes no past row |
| D5 | The measure tolerates a job with no `seconds`, falling back to `minutes × 60`, and skips a run whose `wall_minutes` is 0 | Backfilling the new fields onto recorded runs | P9: `append_event` dedupes by `(run, attempt)`, so a recorded run cannot gain a field without rewriting the stream. The window is 14 days and the tick backfills every tick, so the readings fill themselves within the window, and a floored fallback is wrong by under a minute — enough to rank two boxes while the fine readings arrive |
| D6 | Promote to `asf-fast` at a ratio ≤ `PROMOTE_AT` (1.25), demote at ≥ `DEMOTE_AT` (1.60); a ratio **between** them keeps the tier the runner already carries | One threshold | One threshold makes a box sitting near it change tier on almost every tick, and each change is a label write, a trial and a log line. The band is the whole difference between a placement and a flap, and the previous tier comes off the census file, which is already being read |
| D7 | A runner with fewer than `MIN_READINGS` (5) green readings is **provisionally `asf-bulk`** | Leaving it out of the pool until it is measured, or trusting it with `asf-fast` | It has to be given work before it can be measured, and bulk work is where a mistake costs a slower suite rather than a red timing gate. It also makes the card's first acceptance true by construction: a runner registered a minute ago is in the pool and carrying a tier at the next tick, with no reading at all |
| D8 | After tiering, if no runner carries `asf-fast`, the best-ratio online runner is promoted **whatever its ratio**, with one line saying the tier was floored | Letting the fast tier empty when every box is slow | An empty tier makes every `runs-on` that asks for it unsatisfiable — the jobs queue forever and `drift` reports it after the fact. "No gate goes red because of which box a job landed on" is the card's fourth acceptance, and a job that lands on no box at all is the worst version of that failure. The floor is unconditional and does not read the workflow files, which is what keeps D9 possible |
| D9 | The tick writes **only** the tier labels of the runners it moved — add the new tier, remove the old — and touches no other label. `asf ci reconcile` stays the full sweep | Calling `plan`/`apply` from the tick | `plan` needs `runs_on`, and `runs_on` is `_workflow_texts`: one contents listing plus one raw read per workflow file, every tick, for a set of labels that changed for at most a runner or two. The narrow write needs no workflow read at all, cannot remove a label a job still needs (it removes only the tier it is replacing), and leaves the sweep to the command a human runs |
| D10 | A promotion to `asf-fast` goes through the **existing** trial: one job judged, kept or rolled back with a Bug | A placement of its own | P3 already built exactly this, for exactly this reason — a runner newly given a role is on probation for one job. The tier is the role, so the promotion is the trial with no new machinery, and a box promoted on a stale median is caught by its first real fast job |
| D11 | A job kind is the job's name with a trailing matrix suffix stripped — `test (3.12)` → `test` | The raw job name | A matrix leg's name carries its parameters, so the raw name splits one kind into as many series as the matrix has legs and each gets too few readings to cross `MIN_READINGS`. Stripping the suffix is what makes the readings comparable across boxes, which is the only thing the ratio is for |
| D12 | A ratio is computed only for a job kind that **two or more** runners have `MIN_READINGS` of | Ratio'ing every kind against the fleet's best | A kind only one box has ever run has no fleet best: its ratio is 1.0 by construction and tells nothing, and including it drags every specialised box's overall figure toward 1.0. A runner with no comparable kind at all scores nothing and stays provisional (D7) |
| D13 | A runner's one number is the **median** of its per-kind ratios | The worst kind, or the mean | The worst kind condemns a box for one job that happens to be badly matched to it; the mean lets many fine kinds hide one terrible one. The median is the figure the rest of this codebase reaches for in the same situation (`score.median`, `ESTIMATE_PERCENTILE`'s nearest rank) |
| D14 | The green rate's denominator is readings that concluded `success` or `failure`; a cancelled or skipped job counts in neither | Every reading | `ci_queue.MEASURED_CONCLUSIONS` made this call already: a run cut short says nothing about the box. Counting cancellations would make every box look flaky on a day the relief pass cancelled a lot |
| D15 | A flaky runner (green rate below `MIN_GREEN_RATE`, 0.85, over at least `MIN_READINGS`) is never `asf-fast`, whatever its ratio | Tiering on speed alone | A fast box that fails one job in four costs more than a slow one that always passes, because a red on a timing-sensitive job sends a Task back. And "a slow **or flaky** box surfaces by itself" is the card's own stage 2 |
| D16 | `capacity.batch`'s `parallel` and `runners` are measured only when the product declares **neither**; either one declared leaves both alone | Filling each key independently | The two are one shape: how many runners a run claims and how many runs fit beside each other. Measuring one against an operator's hand-set other produces a pair that was never chosen together, and it is the pair a batch run receives as `ASF_CAPACITY_*` (P6) |
| D17 | `pr_wait_min` and `head_wait_max_min` fall back to the measured p50 run wall minutes — ×2 and ×1 — clamped below by today's constants and above at 240 and 120 | A fixed constant, or an unclamped measure | The head guard's question is *has this entry waited longer than a whole run takes*; on a fleet where a run takes 8 minutes, 20 is too patient, and where it takes 70, 20 fires on every entry. The lower clamp is today's value, so no product's limit can get *shorter* than what is tuned now; the upper stops one pathological run from disabling the guard |
| D18 | A timing baseline is the runner's own p50 for that kind, and the **tier's** p50 across its runners when the runner has too few readings | The fleet's p50, or a fixed number | The card's stage 5 says "the runner's measured class". A fleet p50 across a mixed pool is a number no box reaches, which is precisely the constant this card is removing. The tier is the coarsest grouping that still means something, because it is defined by measured speed |
| D19 | The regression check compares the **latest** green reading to the baseline and is **advisory** | Failing the gate, or filing a Bug | The point is that the box surfaces before anything goes red. A required row would turn one slow-but-green job into a doctor red the operator cannot act on faster than the demotion already will, and the demotion (D6) is the action |
| D20 | `asf-` is a reserved label namespace: `pool_problems` refuses a declared `role` or `class` in it, `reserve_problems` refuses a `label` in it other than the default it generates, and `drift` reports any other non-default self-hosted `runs-on` label as a required red row | Documenting the convention | "No human-written routing label remains in any product's config" is an acceptance, and an acceptance nothing checks is a sentence. A refusal at product load and a red doctor row are the two places this codebase already enforces config rules (P1, P12) |
| D21 | `queue_s` on a run is the **worst** of its jobs' `queued_s` | Their sum, or their mean | The wait a Feature's author feels is the wait before the run's slowest-to-start job began; the sum double-counts jobs that queued in parallel, which on a fanned-out run is most of them |

## The design

### 2.1 Discover — the census

`asf/ci_pool.py` gains the discovered form and keeps everything else:

```python
#: ``ci.pool: discover`` — the pool is every runner the host reports, not a declared list
DISCOVER = 'discover'
#: ASF's own label namespace: a tier, a reserve's default label. A product file may not write one.
ASF_PREFIX = 'asf-'


def pool_mode(product):
    """``'discover'`` when ``ci.pool`` is :data:`DISCOVER`, ``'declared'`` for a list,
    ``'none'`` when there is no ``ci.pool`` at all."""
```

`pool_problems` accepts `pool: discover`, refuses any other string naming `discover`, and refuses a
declared `role` or `class` inside `ASF_PREFIX` (D20). `load_pool` gains one branch and stays pure
(D1):

```python
def load_pool(product):
    ci = product.ci if isinstance(getattr(product, 'ci', None), dict) else {}
    if ci.get('pool') == DISCOVER:
        from asf import ci_census
        return ci_census.cached(product)      # off the file; never `gh`, never raises
    ...                                       # today's list path, unchanged
```

`asf/ci_census.py` is new:

```python
CENSUS_FILE = 'ci-census.json'
PLACES_FILE = 'ci-places.jsonl'
CENSUS_VERSION = 1
#: a census older than this turns its doctor row amber — it is never discarded (D2)
CENSUS_STALE_S = 60 * 60
FAST, BULK = ASF_PREFIX + 'fast', ASF_PREFIX + 'bulk'
TIERS = (FAST, BULK)
#: promote at or below, demote at or above; the band between holds the tier already carried (D6)
PROMOTE_AT, DEMOTE_AT = 1.25, 1.60


def cached(product):
    """``[PoolEntry]`` from ``<state dir>/ci-census.json``: one entry per runner the last census
    saw, its ``role`` its tier, ``provider``/``box``/``size``/``class`` empty (O2, O5), ``slots``
    1. ``[]`` when there is no census, it is unreadable, or its ``v`` is not
    :data:`CENSUS_VERSION` (D2). Never raises, never calls the host."""


def taken_at(product):
    """The census's ISO stamp, or None — the doctor row's age."""


def refresh(product, backend, root=None, now=None, out=print):
    """Take a census: read the runners (P2), score them (:mod:`asf.ci_measure` over the ``ci``
    stream in ``root``), tier each one against the tier it already carries, floor the fast tier
    (D8), write the file and the placement history, and return the moves. No workflow file is
    read (D9)."""


def apply_tiers(product, backend, moves, out=print):
    """Write only the tier labels of the runners in ``moves``: add the new tier, remove the old,
    adds first. Every other label on the runner is untouched (D9). A promotion to :data:`FAST`
    is started as a trial (``ci_pool.start_trial``, D10)."""
```

`slots` is 1 on every discovered entry: a self-hosted runner takes one job at a time, which is what
the host's single `busy` flag means (P2).

Entries come back sorted by name, so the census file is diffable and `pool_ci`'s detail line is
stable.

With the census in place, **`capacity.py` needs no change for the CI ceiling** — `product_ci` already
sums the effective pool's slots through `load_pool` (P4). A five-runner fleet with no `capacity.ci`
has a ceiling of 5, and a sixth runner registered at 14:02 makes it 6 at the next tick.

### 2.2 Measure — the readings

The source is the metrics `ci` stream, and two things have to change before it can be read.

**The selector.** P8: `ci_from_api` keeps a run only when its display name equals
`conventions.ci_workflow`, which holds the file name. The listing's jq gains `path`, and the filter
matches either form:

```python
runs = [r for r in gh_lines([... '.workflow_runs[]|{id,name,path,head_branch,head_sha,conclusion,'
                             'created_at,updated_at,run_attempt,pr:[.pull_requests[].number]}|@json'])
        if r.get('name') == workflow or os.path.basename(r.get('path') or '') == workflow]
```

That is the whole of I3's first half. O6 says why it is not F-0154's resolver.

**The fields.** The jobs jq gains `created_at`, and each job dict gains two figures beside the
floored `minutes` it keeps (D4, D5):

```python
js = [{'name': j['name'], 'conclusion': ..., 'runner': j.get('runner_name'),
       'minutes': ...,                                    # unchanged: floored whole minutes
       'seconds': secs(j.get('started_at'), j.get('completed_at')),   # float, 1 dp, None when either is absent
       'queued_s': secs(j.get('created_at'), j.get('started_at')),
```

`asf/ci_measure.py` reads them:

```python

MEASURED = frozenset({'success'})

RATED = frozenset({'success', 'failure'})

#: a green reading this much past its own baseline is a row (D19)

_MATRIX = re.compile(r'\s*\([^()]*\)\s*$')


def job_kind(name):
    """``test (3.12)`` → ``test`` (D11); a name with no trailing parenthesis is itself."""


def readings(events, now=None, window_days=WINDOW_DAYS):
    """``{(runner, kind): Series}`` from ``ci`` events in the window: every job with a ``runner``,
    its ``seconds`` (``minutes * 60`` when absent — D5), its conclusion, its ``queued_s``."""


@dataclasses.dataclass(frozen=True)
class Score:
    runner: str
    medians: dict     # {kind: median green seconds}
    ratios: dict      # {kind: this runner's median / the fleet's best for that kind}, D12

    """``[(runner, kind, latest_s, baseline_s)]`` where the latest green reading is at least

def run_wall_p50(events, now=None, window_days=WINDOW_DAYS):
    """The p50 of the window's ``wall_minutes`` over runs that have one (D5), or None — what I10

```

### 2.3 Place — the tier

Tiering, in `ci_census`:

```python
def tier_of(score, carried=None):
    """The tier a runner belongs in. No score, no ratio, or fewer than MIN_READINGS: BULK (D7).
    Flaky: BULK (D15). ratio <= PROMOTE_AT: FAST. ratio >= DEMOTE_AT: BULK. Between: ``carried``
    — the tier the last census gave it — else BULK (D6)."""
```

`refresh` then, in order: tier every online runner; if no runner is `FAST`, promote the best-ratio
online one whatever its ratio and print the floor line (D8); write the file; append one
`ci-places.jsonl` line per move; return the moves. One line per move, naming the reading:

```
ci place: ci-3 asf-fast → asf-bulk — runs gate at 384s, 2.1× the fleet best (demote at 1.60×), 11 green readings in 14 d
ci place: ci-5 asf-bulk → asf-fast — 1.04× over 3 job kinds, 18 green readings in 14 d
ci place: ci-7 → asf-bulk — 2 green readings, fewer than 5: provisional
ci place: ci-2 → asf-fast — the fast tier would be empty; best ratio 2.4×
```

The card's second acceptance is that middle-out line: *"a runner that turns slow is moved off
timing-sensitive jobs by ASF, with one log line saying why"*.

`ci_pool.tick` gains the discovered branch, before the reserve it already applies:

```python
def tick(ctx, backend=None, out=print):

    if pool_mode(product) == DISCOVER:
        backend = backend or backend_for(product)
        if backend is not None:

            moves = ci_census.refresh(product, backend, root=ctx.record_root(), out=out)
            ci_census.apply_tiers(product, backend, moves, out=out)

```

One `backend.runners()`, one read of 14 days of `metrics/ci` day files (`read_stream(root, 'ci',
days=...)` — P13), and a label write only for a runner that moved. The record clone is already
ensured on every tick by the backfill (P8), so `ctx.record_root()` costs nothing here.

`asf ci census` is the same thing without the writes:

```
$ asf ci census
runner  tier       ratio  readings  green  move
ci-1    asf-fast    1.00        31   1.00  —
ci-3    asf-bulk    2.10        11   1.00  asf-fast → asf-bulk (demote at 1.60×)

census: 3 runners — asf-fast 1, asf-bulk 2 (dry run; --apply writes the labels)
```

Nothing else in the placement path changes. Because the tier *is* `PoolEntry.role`, `labels()`,
`plan`, `drift`, `class_key`, `load_by_class`, `label_classes`, `pool_ci` and `expected_run_needs`
all read it exactly as they read a declared role today (P3, P5) — which is the reason the tier was
made a role rather than a new field.

One accepted skew: `run_peaks` attributes a past job to its runner's **current** tier, so for a
window straddling a move the measured needs are slightly off. It self-corrects as the window rolls,
and the alternative — storing a tier per historical job — buys a sharper estimate of a number that is
already a p90 over ten runs.

### 2.5 Guards — the baseline

`<state dir>/ci-baselines.json`, written by `refresh` from the same readings:

```json
{"v": 1, "taken": "2026-09-30T11:04:07Z", "window_days": 14,
 "per": {"ci-1": {"gate": {"p50_s": 182.4, "n": 19}}},
 "tier": {"asf-fast": {"gate": {"p50_s": 188.1, "n": 34}}}}
```

and read two ways. For a product's own guard, a command that prints one number:

```bash
$ asf ci baseline --job gate --runner ci-1
182.4
$ asf ci baseline --job gate --runner ci-9   # too few readings: its tier's p50 (D18)
188.1
```

`--json` prints `{"seconds": 182.4, "n": 19, "from": "runner"}` (or `"from": "tier"`), and a job kind
with no reading on either exits 1 printing nothing — a guard that cannot get a baseline should skip
its check, not invent one.

And ASF's own after-the-fact reading, `check_ci_measure`'s third row (D19):

```
ci baseline: gate on ci-4 last ran 512s against its 318s baseline (1.6×) — 8 green readings
```

This is the part of the card's stage 5 that this codebase can hold: there is no timing guard in
`asf/` to re-baseline, so the baseline is *published* for a product's guard to read, and the
regression that a fixed constant would have missed is reported by ASF, which is the only party that
knows which box the job landed on.

### 2.6 No hand-written routing label

Three changes, all in `ci_pool` (D20):

1. `pool_problems` refuses a declared `role` or `class` beginning `asf-`:
   `ci.pool[0].role: 'asf-fast' is ASF's own namespace — a tier is placed, never declared`.
2. `reserve_problems` makes `label` optional (`RESERVE_REQUIRED = ('of', 'keep_free')`) and
   refuses a hand-written one in the namespace; `load_reserve` defaults it to `ASF_PREFIX + 'pr-' +
   of`. A reserve of `asf-fast` gets `asf-pr-asf-fast` — so the default strips a leading `asf-` from
   `of`: `asf-pr-fast`.
3. `drift` gains one required row per offending label on a discovered pool — a self-hosted `runs-on`
   asking for a non-default label that is neither a tier nor a reserve label:

```
runs-on: tests.yml:gate asks for 'heavy' — no tier ASF places (asf-fast, asf-bulk) and no reservation; ASF cannot route it
```

With those three, the card's third acceptance — *"no human-written routing label remains in any
product's config"* — is a thing the doctor asserts on every tick rather than a thing somebody
remembers.

### 3.2 The measure


`job_kind` strips one trailing parenthesised suffix and leaves a bare name, a name with an interior

### 3.4 The tier

