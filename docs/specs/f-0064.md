# F-0064 — the event is the record; the log is a view of it

The factory already has five validated streams and one that is not. `metrics/ci`, `sessions`,
`ticks`, `landings` and `gates` go through `metrics.validate` and `metrics.append_event`: a typed
schema, a natural key, one line per fact. `metrics/events` goes through neither. It is written by
two hands — `asf.tick.tick.Context.event` (`asf/tick/tick.py:178`) and
`asf.record.ingest.write_on_prod_event` (`asf/record/ingest.py:41`, which says in its own
docstring that it cannot use `append_event` because `natural_key` has no `events` branch and
raises `KeyError`) — with no schema, no key, no `product` on half its lines, and free-form
keyword fields that differ per call site.

Around that hole the same facts are recorded twice and neither copy is whole:

| The fact | What is written down | What is lost |
| --- | --- | --- |
| a wave launched a session | `ctx.event('launch', …)` **and** `ctx.counts['launches'] += len(launched)` (`asf/tick/step_wave.py:763`) | nothing joins the two: the count is kept by hand beside the events |
| a harvest landed a branch | `ctx.counts['merges'] += rec.get('merges', 0)` (`asf/tick/step_harvest.py:78`) | which branch, which sha, which item — only the integer survives |
| a session was relaunched | `ctx.counts['relaunches'] += 1` (`asf/tick/step_health.py:104`) | which job, and why |
| a session stalled | `ctx.counts['stalls'] += len(stalled)` (`asf/tick/step_health.py:180`) | which jobs |
| the hook refused an action | `ctx.counts['refusals'] += len(refused)` (`asf/approvals.py:1017`) | the class and the path reach `refused_files` only through the tick line |
| a person must decide something | `print('NEEDS OPERATOR: …')` at a dozen sites; exactly one of them (`asf/tick/tick.py:388`) also raises an event | every other one exists only in the tick's stdout |
| what one session cost | `usd` = the runtime's `total_cost_usd`, `None` whenever the final beat carries none (`asf/metrics/metrics.py:1509`) | the four token dimensions *are* recorded and nothing turns them into money |

And the one place ticks were ever reconstructed from prose is still in the tree:
`asf/metrics/import_sessions.py` — `parse_log`, `wave_centres`, `ticks_from_log`,
`batch_prs_from_log`, `--format legacy-log` — 120 lines of regex over `HH:MM <text>` that guess a
tick's boundaries from a nine-minute window around a `WAVE HHMM:` line and count `MERGE: `,
`RELAUNCH: `, `REFUSED` and `stall` by substring. It was the adapter for a pre-`asf` runner; it is
also the shape the factory's own prose still imitates, and while it exists the prose is a format
somebody could parse again.

This spec closes the hole from both ends. `events` becomes the sixth validated stream, every tool
appends its own event at the moment it acts, the tick line is *counted from those events* rather
than kept beside them, and a new `asf log` renders the human view — the format the parser used to
read — out of the streams. Then the parser is deleted. On top of that spine it adds the three
things the streams could not yet say: what a session cost, whether a brief hit the prompt cache,
and who was granted what.

## 1. Decisions

### 1.1 In

- `events` as a validated stream: a schema in `metrics.SCHEMAS`, a natural key, `product` on
  every line, `tick` on every line raised inside a tick.
- One append path (`asf/metrics/log.py:emit`) that every writer uses, including the two that
  write `metrics/events` by hand today.
- A `merge`, `relaunch`, `stall`, `refusal`, `grant` and `needs-operator` event at each of the
  sites that today only increments a counter or prints a line.
- The tick line's five counters derived from this tick's events.
- `asf log` — the rendered human view of a day, byte-stable.
- The deletion of `parse_log`, `wave_centres`, `ticks_from_log`, `batch_prs_from_log` and
  `--format legacy-log`.
- The model on a session's final beat, a dated price table in operator config, `usd` priced from
  the four dimensions when the runtime reported none, and a coverage measure for it.
- The brief split into a stable prefix and a variable row, and the cache-read share measured per
  session.
- The grant audit: every `--add-dir`, every allow/deny-rule change and every secret write is an
  event carrying its item and its account.

### 1.2 Out

- No change to how `ci`, `sessions`, `landings` or `gates` are *derived*. They gain a `product`
  key and (for `sessions`) `usd_source`, `model` from the log and nothing else.
- No new state file outside the record. The events stream lives where it already lives:
  `metrics/events/<day>.jsonl` in the tick's record clone.
- No vendor price, model id or account name in this repo. Prices are operator config
  (§2.6); accounts are the pool index `a<n>` (B-0023).
- `asf log` is read-only: it never clones, fetches, resets or commits. It is not a table and does
  not join `asf.views.header.TITLES` (§1.3).
- No retention or rotation policy for `metrics/events`. Daily files, as today.
- No change to `~/.ASF/logs/tick-<product>-<clock>.log`. That file stays what it is — the tick
  process's stdout, diagnostics included. It is not the human log; the human log is what
  `asf log` renders.

### 1.3 Preconditions

- `metrics.append_event` (`asf/metrics/metrics.py:336`) is already idempotent per day file against
  `natural_key`, and `metrics.validate` already fills `ts` and matches items. This spec extends
  both; it does not replace them.
- `asf.tokens` already reads the four dimensions in one pass (`tokens.meter`) and already records
  them on the `sessions` stream as `tokens_input`, `tokens_output`, `tokens_cache_read`,
  `tokens_cache_write`. Cost is the only thing missing from that record.
- `metrics.account_index` (`asf/metrics/metrics.py:1537`) already maps an account name onto
  `a<n>`. Every event that names an account uses it.
- `asf.tick.tick.Context.record_root()` makes the record clone at most once per tick, and
  `finish()` commits the tick's events and its tick line in one commit. Event appends stay inside
  that clone and inside that commit.
- `metrics/events` is already created by `asf init` (`asf/init.py:29`) and already read by the
  scorecard (`asf/metrics/metrics.py:731`) for `feature-on-prod`. Existing lines carry no
  `product`, no `key` and no `tick`; the reader tolerates them (§2.1).
- `asf.views.header.TITLES` gives a title line with a clock in it to every command it names.
  `asf log` must be byte-stable, so it stays out of that dict — a command not in it prints
  neither line, which is the existing contract.
- `asf/briefs/build.py` puts `Backlog item: <id> — <title>` on line 1. No runtime reader depends
  on that position; the only assertions are in `tests/test_sample_product.py:197`
  (`body.startswith`) and the golden briefs under `tests/fixtures/briefs/golden/`. Both change
  with §2.7.
- `tools/check_conventions.sh` exempts `asf/metrics/import_sessions.py` because its literals
  describe a foreign file. After §2.5 the module keeps only the `legacy-results` half; the
  exemption stays (the results file is still foreign), and `asf/conventions.py:6` is updated to
  say so.

### 1.4 The choices

| Choice | Chosen | Against | Why |
| --- | --- | --- | --- |
| Where the events schema lives | one more entry in `metrics.SCHEMAS`, beside the other five | a schema of its own in a new `asf/metrics/events.py` | one validator, one `append_event`, one idempotency rule. A sixth stream that validates differently is the hole this spec is closing |
| Kind-specific payload | a fixed head (`ts`, `kind`, `key`, `product`, `tick`, `item`, `job`, `account`, `branch`, `text`) plus a free `fields` dict | a per-kind schema for each of the fifteen kinds | `_apply` rejects unknown keys, and the existing call sites pass eleven different keyword sets. A fixed, rendered head and an unrendered `fields` bag types what the renderer and the counters read, without a schema per verb |
| The natural key | `(kind, key)`, the caller naming `key` | `(kind, ts)`, or a hash of the whole line | `ts` makes a retry a second line and a hash makes every line unique — neither is idempotent. `launch` keys on the job, `merge` on `branch@sha`, `feature-on-prod` on the item: the caller knows what "the same event twice" means |
| Joining an event to its tick | an explicit `tick` field (the tick's `HHMM`) on every event a tick raises | a time window around the tick's `ts`, as `ticks_from_log` did | a window is a parser. The tick knows its own id and stamps it |
| The tick's counters | derived by counting this tick's events | kept in `ctx.counts` as today, with events added beside them | "the tick stream's lines match the events stream with no parser between them" is only true if there is one source. Two counters that can disagree will |
| Whether `NEEDS OPERATOR:` keeps being printed | yes — printed *and* appended, through one helper `log.needs_operator` | only appended, and rendered later | the line is the operator contract: a person watching a tick must see it as it happens. What changes is that it is no longer *only* printed |
| The rendered log's clock | UTC, `HH:MM`, with the day as a `# <day>` header | the local wall clock with no date, as the legacy log had | byte-stability is an acceptance. A local clock makes the same day render differently on two machines and re-renders differently across a DST boundary |
| Where prices live | `~/.ASF/prices.yaml`, operator config, dated rows; this repo ships the loader and a commented example under `docs/` | a built-in table of rates in `asf/prices.py` | a vendor's price list is this operator's contract, not the product's, and `tools/check_generic.sh` is the standing reason. The repo ships the mechanism, the operator ships the numbers |
| What `usd` means when both sources exist | the runtime's `total_cost_usd` wins; the priced value is the fallback; `usd_source` says which | always price it ourselves, for consistency | the runtime's number is measured, ours is computed. Never overwrite a measurement — but say which one a row is |
| The model on a session | the last `assistant` beat's `message.model`, falling back to the registry's launch label | the registry label alone, as today | the label is what was *asked for*; the beat is what *ran*. Pricing the label prices a counterfactual |
| Cache-friendly brief order | one `<!-- row -->` marker per template; everything above it is stable and may hold no placeholder | two files per kind (`<kind>.md` + `<kind>.row.md`) | eighteen templates become thirty-six files and two loaders. One marker and one load-time check is the same guarantee |
| What the cache work promises | a byte-identical prefix per brief kind, and the cache-read share measured per session | a claimed hit rate | whether a prefix is cached is the runtime's and the provider's business. What this product can own is the stable prefix and the measurement |
| Grant paths in the record | relative to `ASF_HOME` or the product repo, else the basename | the absolute path the session was handed | a machine path in a public record is the standing refusal (B-0023, `asf.redact`) |

## 2. The design

### 2.1 `events` is the sixth stream

**`asf/metrics/metrics.py`.** `STREAMS` gains `'events'`, and `SCHEMAS` gains:

```python
'events': {
    'ts':      (('str',), TS),
    'kind':    (('str',), REQ),           # one of asf.metrics.log.KINDS
    'key':     (('str',), REQ),           # the natural key within (day, kind)
    'product': (('str', 'null'), PRODUCT),
    'tick':    (('int', 'null'), None),   # the HHMM of the tick that raised it
    'item':    (('str', 'null'), MATCH),
    'job':     (('str', 'null'), None),
    'account': (('str', 'null'), None),   # a<n> — never a name (B-0023)
    'branch':  (('str', 'null'), None),
    'text':    (('str', 'null'), None),   # the one-line human detail the renderer prints
    'fields':  (('dict',), {}),           # kind-specific payload; never rendered, never counted
},
```

`natural_key` gains `if stream == 'events': return (ev['kind'], ev['key'])` — so the `return
(ev['tick'],)` fall-through stops being the branch an `events` line lands in, which is what makes
`ingest.write_on_prod_event` hand-roll its own append today.

`PRODUCT` is a fourth sentinel beside `REQ`, `MATCH` and `TS`: `validate(stream, obj, items,
now=None, product=None)` fills it from `product` when the key is absent, and leaves `None` when no
product was passed. It is added to `ci`, `sessions`, `ticks`, `landings` and `gates` too (`ticks`
already carries a nullable `product`; its default becomes `PRODUCT`), so *every* event line
carries its product.

**A stream file never mixes products.** `append_event` reads the day file once already, to check
the natural key. In the same pass it collects the distinct `product` values that are strings; if
one of them differs from `ev['product']` it raises

```
SchemaError("events: metrics/events/2026-09-25.jsonl holds product 'other' — a stream file never mixes products")
```

Lines carrying `product: null` (every line written before this Feature) are ignored by the guard.

**`asf/metrics/log.py`** (new) owns the vocabulary and the one append path:

```python
KINDS = ('launch', 'merge', 'relaunch', 'stall', 'refusal', 'needs-operator', 'grant',
         'held', 'hold-resolved', 'ruling', 'triage', 'widened', 'reshape', 'reverted',
         'capacity', 'host_pressure', 'feature-on-prod')

def emit(root, product, kind, key, *, tick=None, item=None, job=None, account=None,
         branch=None, text=None, items=None, **fields): ...
```

`emit` builds the line, calls `metrics.validate('events', …, product=product)` and
`metrics.append_event(root, 'events', ev)`, and returns the stored event. A `SchemaError` is
printed and swallowed: an event that cannot be written never aborts the step that raised it.

`Context.event(kind, **fields)` becomes a call into `emit` with the tick's `product`, its record
root and its `HHMM`, and it appends the stored event to `ctx.events`.
`ingest.write_on_prod_event` becomes `log.emit(root, product, 'feature-on-prod', key=iid,
item=iid, from_stage=from_stage)` and its hand-rolled dedupe loop is deleted — `append_event`'s
natural key is the same guarantee.

### 2.2 Every tool appends its own event

| Site | Today | After |
| --- | --- | --- |
| `asf/tick/step_wave.py:763` | `ctx.event('launch', item=…, job=…, …)` + `ctx.counts['launches'] += len(launched)` | `ctx.event('launch', key=wrow.job, item=…, job=…, branch=…, account=account_index(…), text=…)`; the counter line goes |
| `asf/tick/step_harvest.py:78` | `ctx.counts['merges'] += rec.get('merges', 0)` | one `merge` event per landed branch: `key=f"{branch}@{sha}"`, `item`, `branch`, `fields.sha`, `fields.trunk` |
| `asf/tick/step_health.py:104` | `ctx.counts['relaunches'] += 1` | one `relaunch` event: `key=new_job`, `job=old_job`, `item`, `text=reason` |
| `asf/tick/step_health.py:180` | `ctx.counts['stalls'] += len(stalled)` | one `stall` event per stalled session: `key=job`, `item`, `text=reason` |
| `asf/approvals.py:1017` | `ctx.counts['refusals'] += len(refused)` | one `refusal` event per open hook refusal: `key=f"{item}/{cls}"`, `item`, `fields.class`, `fields.path` |
| every `NEEDS OPERATOR:` print site | `print(...)` | `log.needs_operator(out, text, product=…, root=…, item=…, key=…)` — prints the same line **and** appends a `needs-operator` event, `key` defaulting to the text's first 120 characters |
| `asf/record/ingest.py:41` | a hand-rolled append + dedupe | `log.emit(..., 'feature-on-prod', key=iid)` |
| `asf/tick/widen_footprint.py`, `step_groom.py`, `asf/approvals.py:1036,1042` | `ctx.event(kind, **fields)` with ad-hoc keys | the same kinds, now through the schema: a `key`, the head fields named, the rest under `fields` |

`log.needs_operator` is the *only* place in `asf/` that composes the string `NEEDS OPERATOR:` —
except `asf/briefs/` (that text is handed to a session, not written to the factory's log) and
`asf/cli.py:needs_operator_line`, which becomes a thin formatter `log.needs_operator` calls. The
rule is enforced by a test, not by convention (§3, `NoOtherWriterTests`).

### 2.3 The tick line is counted from the events

**`asf/tick/tick.py`.** `Context.counts` is deleted. `Context` keeps `self.events = []`, and:

```python
COUNTED = {'launches': 'launch', 'merges': 'merge', 'stalls': 'stall',
           'refusals': 'refusal', 'relaunches': 'relaunch'}

def tick_counts(self):
    kinds = collections.Counter(e['kind'] for e in self.events)
    return {name: kinds[kind] for name, kind in COUNTED.items()}
```

`tick_line` uses `ctx.tick_counts()` for the five counters and derives `refused_files` from the
`refusal` events that carry `fields.path`. `summary.digest(ran, ctx.tick_counts(), …)` and
`asf.tick.watch.digest_lines` are unchanged in shape — they read the same five keys.

The consequence is the acceptance: for any tick `T` of a day, `ticks[T][name] == len([e for e in
events if e['tick'] == T and e['kind'] == COUNTED[name]])`, with no window, no regex and no
substring match anywhere between them.

An event raised outside a tick (a console `asf harvest`, a `asf console-permissions`) carries
`tick: null` and is counted by no tick line. It still renders.

### 2.4 `asf log` — the human view

**`asf/metrics/log.py`**, second half. Registered in `asf/cli.py` as:

```
asf log [--product P] [--day YYYY-MM-DD | --days N] [--root DIR]
```

`--root` defaults to `shadow.record_dir(product)` — the tick's own clone, read **only**: never a
clone, fetch, reset or commit, the same discipline `asf watch` keeps.

The render, for one day:

```
# 2026-09-25
06:40 WAVE 0640: 3 launches, 1 merge, 0 stalls, 2 refusals, 1 relaunch, 74.2s
06:40 LAUNCH spec-f-0064 (spec, F-0064) on spec/F-0064 — a1
06:41 GRANT add-dir <record>/intake on F-0064 — a1
06:47 MERGE: worker/t-0279 → main 4f2c1ab (T-0279)
06:48 REFUSED touch_amendable_set on T-0281 — docs/specs/f-0055.md
06:52 RELAUNCH: code-t-0281 → code-t-0281-r2 (T-0281) — no heartbeat for 41 min

NEEDS OPERATOR: held merge_conflict on T-0281 — two lanes on docs/specs/f-0055.md — asf approvals resolve T-0281/merge_conflict granted|done|dropped
```

Rules that make it byte-stable:

1. Every line is `HH:MM <text>`, the `HH:MM` taken from the event's `ts` in **UTC**. No local
   clock is read anywhere in the renderer.
2. The day's lines are sorted by `(ts, kind, key)` — a total order over the stream, so two runs
   over the same files emit the same bytes in the same order.
3. One line per event whose `kind` is in `RENDER`, a `{kind: formatter}` map. A kind the map does
   not name is in the stream and not in the log. The `WAVE` line comes from the `ticks` stream,
   placed at its own `ts`.
4. `text` is what the emitter wrote; the renderer never re-derives it from `fields`, and it
   collapses whitespace and caps at 200 characters.
5. No machine path, no account name, no float without a fixed precision (`{:.1f}s`).
6. The footer: a blank line, then one `NEEDS OPERATOR:` line per `needs-operator` event of the
   window whose `key` has no later `hold-resolved` or `needs-operator-cleared` event, oldest
   first. No footer, and no blank line, when there are none.
7. Exactly one `\n` per line, no trailing spaces, the output ends with `\n`. `--days N` renders N
   day blocks, oldest first, separated by one blank line.

`log.render(root, product, days) -> str` is the pure function; `cmd_log` prints it. The fixture
day (§3) pins the bytes.

### 2.5 The parser is deleted

From `asf/metrics/import_sessions.py`: `LOG_LINE`, `CUT_LINE`, `WAVE_ID`, `WAVE_LINE`, `QUOTA`,
`TICK_WINDOW`, `STALL_LINE`, `parse_log`, `batch_prs_from_log`, `wave_centres`, `ticks_from_log`,
the `legacy-log` member of `FORMATS`, its branch in `import_file`, and the `--log` flag. The
module keeps `legacy-results`, `launch_ledger` and `sessions_from_results`; without `--log`, a
legacy session's start time comes from the brief mtime alone, which
`sessions_from_results` already falls back to. The module docstring loses its `legacy-log`
section.

`tests/test_metrics.py` loses `LOG`, `SAMPLE_LOG` and the five parser tests (lines 946–1003);
`tests/fixtures/` loses any log sample only they read.

### 2.6 Cost stops being null

**`asf/tokens.py`.** `Meter` gains `model: str = None`. In `meter()`, an `assistant` line sets
`m.model = rec['message'].get('model')` when it carries one, and a `system`/`init` boundary
clears it with the rest. The four dimensions are untouched; nothing is summed.

**`asf/prices.py`** (new), stdlib only:

```python
DEFAULT_PATH = os.path.join(env.ASF_HOME, 'prices.yaml')

def load(path=None) -> Table          # [] when the file is absent — never an error
def rate(table, model, day) -> dict | None
def cost(table, model, by_dim, day) -> float | None
```

The file:

```yaml
prices:
  - model: "<the model string a session's final beat reports>"
    from: 2026-01-01                 # the first day this row applies to
    usd_per_mtok: {input: 0.0, output: 0.0, cache_read: 0.0, cache_write: 0.0}
```

`rate` picks, among the rows whose `model` matches (exactly, else the longest `model` ending in
`*` whose stem the model starts with), the one with the greatest `from` that is `<= day`. `None`
when the model is unpriced. `cost` is
`sum(by_dim[d] / 1e6 * rate[d] for d in DIMENSIONS if by_dim[d] is not None)`, rounded to 4
decimals — `None` when the model is unpriced or every dimension is `None`. A dimension present in
`by_dim` and absent from the rate is a load-time error naming the row, not a silent zero.

`docs/prices.example.yaml` ships the shape with a comment saying the numbers are the operator's
and the file is never committed to a product repo.

**`asf/metrics/metrics.py`.** The `sessions` schema gains `'usd_source': (('str', 'null'), None)`.
`session_event` gains a `prices_table` argument and:

- `model` = `by_dim`'s meter model, else `record.get('model')`;
- `usd` = the result's `total_cost_usd` when it is a number → `usd_source: 'runtime'`;
  else `prices.cost(table, model, by_dim, ev['ts'][:10])` → `usd_source: 'priced'`;
  else `None` → `usd_source: None`.

`sessions_from_registry` loads the table once and passes it down.

**The measure.** `metrics.cost_coverage(sessions) -> (priced, total, share)` counts sessions with
`usd is not None`. `cmd_rollup` prints `cost: 47/49 sessions priced (96 %)`; `scorecard_rows`
gains a `cost coverage` row with the same numbers and, as its note, the models seen with tokens
and no price. `asf doctor` prints one line when the share is below
`conventions.cost_coverage_floor` (default `0.90`):

```
NEEDS OPERATOR: 22 of 49 sessions have tokens and no price — add their models to ~/.ASF/prices.yaml (see docs/prices.example.yaml)
```

### 2.7 The brief is stable text first, the variable row last

**`asf/briefs/build.py`.** `ROW_MARKER = '<!-- row -->'`. Every file under
`asf/briefs/templates/` gains the marker exactly once. `load_template` splits on it and raises
`BriefError` when the stable half holds a `{placeholder}` or the marker is missing.
`TAIL` splits into `TAIL_STABLE` (the heartbeat and standing-rules prose, no placeholder) and
`TAIL_ROW` (the branch paragraph and the REPORT block, which need `{branch}`, `{main}`,
`{item_id}`, `{kind}`).

`build()` composes, in this order:

```python
parts = [stable_text(kind),                                  # template head + TAIL_STABLE
         render(row_half(kind), ctx).rstrip() + correction_text(...) + customer_section(...)
             + foreign_review_text(...) + refusal_section(...),
         item_line(row, facts['item']),
         preamble_mod.build(...),
         render(TAIL_ROW, ctx)]
```

`stable_text(kind)` is a pure function of the kind: two briefs of the same kind, for two
different items, share it as a byte-identical prefix. It is `functools.lru_cache`d and asserted
by a golden file per kind.

The measure lives on the stream that already carries it: `tokens_cache_read`. `asf tokens`
(`asf/views/tokens.py`) gains a **cache read** column and a footer line
`cache-read: <n>/<m> sessions (<pct> %)`; `scorecard_rows` gains a `prompt cache` row with the
same share over the week. Nothing here claims a hit rate — the column is the evidence, and a
regression in it is visible the next day.

### 2.8 The grant audit

Three sites, one kind (`grant`), `fields.what` distinguishing them. Every one carries `item` and
`account` (`a<n>`, or `null` with `fields.actor: 'console'` when no session made it).

| `fields.what` | Site | `key` | `text` |
| --- | --- | --- | --- |

## 4. Records

**Written.**

- `metrics/events/<day>.jsonl` — one line per event, keys sorted, UTC `ts`. The head is
  `ts, kind, key, product, tick, item, job, account, branch, text`; `fields` carries the rest.
  Idempotent on `(kind, key)` within the day. One product per file.
- `metrics/ticks/<day>.jsonl` — unchanged in shape. Its five counters are now *derived* from the
  events of the same tick; `refused_files` from the `refusal` events' `fields.path`. Gains
  `product` as a filled key rather than a nullable one.
- `metrics/sessions/<day>.jsonl` — gains `usd_source` (`runtime` | `priced` | `null`) and
  `product`. `model` now prefers what ran over what was asked for. `usd` is non-null whenever the
  model is priced and any dimension was measured.
- `metrics/daily/<day>.md` — the scorecard's waste table gains two rows: `cost coverage` and
  `prompt cache`.
- The tick's single commit (`tick: state <ts>`) carries the day's events, the tick line and the
  derived state together, as it does today.

**Read and not written.**

- `~/.ASF/prices.yaml` — operator config, dated rows, never committed to a product repo. Absent
  is a legal state: `load` returns `[]` and every `usd` falls back to the runtime's number.
- `~/.ASF/logs/jobs/<product>/<job>.jsonl` — the session's beats. The meter reads the model and
  the four dimensions; nothing writes there.

**Deleted.**

- `asf/metrics/import_sessions.py`'s parser half (§2.5) and its tests.
- `asf.tick.tick.Context.counts`.
- `asf.record.ingest.write_on_prod_event`'s hand-rolled append and dedupe.

**Not written.** No new state file. No card, no Bug, no rule card. No change to
`~/.ASF/logs/tick-<product>-<clock>.log`, which stays the tick process's stdout.
