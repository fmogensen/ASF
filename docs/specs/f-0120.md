# F-0120 — adopting a record

The first customer install brought its own backlog with it. Dozens of the cards in it are not that
product's work: another product's cards, factory machinery that leaked in when ASF was adopted,
fragments left over from a migration. Nothing in the factory says so. They sit in the product's
queue, they are counted undecided in every view, an S1 among them holds the whole tier-2 lane
behind a Bug nobody will ever fix here, and the only way out is the procedure
`docs/guide/operating.md:345-350` writes down: pull the record, open each card, type a `removed:`
line into its typed block by hand, run `asf index`, commit. Per card. Dozens of times.

Three things are missing, and this card names all three. The groom never asks "does this card
belong to this product at all", so the question is never put. There is no command that writes
`removed:` or `moved_to:` — `asf set` refuses both fields on purpose (measured below), so the
factory's one safe writer of typed fields cannot write the two fields an adoption needs most. And
the feeder cannot tell an S1 that is this product's emergency from an S1 that is somebody else's,
so it freezes the lane for both.

After this change a product declares what its work *is* (`scope:` in its product file); the groom
reads every other registered product's scope plus the factory's own, flags each card that looks
like one of theirs with `belongs_to: <product>`, and asks about the whole set on **one** line;
`asf move` writes `removed:` or `moved_to:` across a named selection in one signed-off commit
through the record's parser, and for a move files each card into the target product's inbox,
deduped, so running it twice imports nothing twice; and a flagged S1 is a `NEEDS DECISION` row
naming `asf move` — which launches nothing, costs no slot, and lets the tier-2 rows behind it
through.

### In

- **A declared scope.** `scope: {paths: [...], terms: [...]}` in a product file (P17), plus the
  factory's own scope as a documented default in `asf/conventions.py` (P20) — so "what this
  product's work is" is operator config, never a literal in a matcher.
- **One judgement, in one module.** `asf/adopt.py`: read the scopes, decide whether a card matches
  one of them better than any other, and say why in a phrase short enough for a groom line.
- **`belongs_to: <product>` on the card,** written by the groom through P2's round-trip writer, with
  one History line. It is a *suspicion*, not a ruling: it does not retire the card, does not change
  a table, and is cleared by a `keep` answer, by `asf move`, or by hand.
- **One decision line per suspected owner** in the groom file, keyed on `belongs_to:<product>`
  (P11), counted as an open question so the adjudicator rules on it (P12), landing in the judgement
  half (P13). Its answers are `keep` and `remove: <reason>` — both applied in bulk, both writing
  only this record.
- **`asf move <ids…> | --query FIELD=VALUE` with `--to <product>` or `--remove "<reason>"`**: one
  commit through P3, every card written through P2, all-or-nothing, `--dry-run` to see it first.
- **The target's inbox import, deduped** on a `moved_from: <source>:<ID>` provenance ref that
  survives the target's groom minting the card (P15, P16).
- **A `NEEDS DECISION` row for a flagged item** in the S1/S2 lane and on a Feature's own launching
  row, naming the `asf move` command to run — which by P8/P9 lifts the tier-2 freeze.
- **The operator-facing text**: `docs/products.example.yaml`, `product-config.md`'s `scope:` section,
  and `operating.md`'s retire procedure, which stops telling an operator to edit cards by hand for
  the adoption case (P23).

### Out

- **Changing what `removed:` or `moved_to:` *mean*.** `is_retired` is untouched (P4); this card only
  gives the factory a safe way to write them. `asf set` keeps refusing both (P1): a closing is a
  decision with a reason, and it now has its own command.
- **Letting the groom run the move.** A move writes a *second* git checkout, the target product's
  record. The tick's groom runs unattended in its own clone of one record and has no business
  committing to another product's; and behaviour that differs between the tick's groom and an
  operator's `asf groom --apply` would be worse than either. A `move` answer therefore writes
  nothing and bars its own line with the exact command (see D6).
- **Holding a Task whose Feature is flagged.** The flag holds the Bug lane and the Feature's own
  launching row (want 3 plus D11's reason); a Task under a flagged Feature keeps its `PLAN → CODE`
  row. An adoption dump is cards, not approved plans with Tasks under them, and a second hold
  reachable only through a parent is a rule that would be hard to reason about from the row.
- **A free-text `--query`.** See D9: the selector is `FIELD=VALUE` over `index.json`, and nothing else.
- **Deleting a card.** Nothing this card writes ever removes a file from either record. The source
  card is retired in place and the target gets a new card; the link between them is `moved_to:` one
  way and `moved_from:` the other.
- **A schema migration.** `belongs_to:` and `moved_from:` are additive typed fields (P6); a record
  written before this lands simply has neither. `schema.require` stays uncalled (P22) — `asf move`
  follows `asf set` and `asf groom`, and does not become the one command that checks.
- **Guessing an owner when two scopes fit equally.** See D5.
- **Scoring a card's `## Description` prose for intent.** The judgement reads declared paths and
  declared terms (D3, D4). A matcher that reasoned about prose would flag cards nobody could
  predict, across a bulk write.

## The design

### 1. `scope:` — what a product's work is

`docs/products.example.yaml` gains the key, documented where `customer_paths:` sits:

```yaml
# what this product's work is about — read by the groom when it asks whether a card in this
# record belongs to another product at all (F-0120), and by `asf move`. Both lists are optional.
scope:
  # path globs (fnmatch) this product's work writes: matched against a Task's writes: entries and
  # against any path-shaped word in a card's title or description.
  paths:
    - src/billing/**
    - migrations/**
  # the words this product's work is about. A card matching two of them (or every one, for a
  # scope naming a single term) reads as this product's.
  terms: [billing, invoice, dunning, chargeback]
```

`asf/env.py`:

```python
PRODUCT_FIELDS['scope'] = _MAP
#: `scope:` is a map: what this product's work is (F-0120), read by the groom and by `asf move`.
SCOPE_FIELDS = {'paths': _LIST, 'terms': _LIST}
NESTED_FIELDS['scope'] = SCOPE_FIELDS
```

and one property beside `customer_paths`:

```python
@property
def scope(self):
    """``(paths, terms)`` — this product's declared scope, empty tuples when it declares none."""
```

`asf/conventions.py`:

```python
#: The factory's own scope (F-0120 D1, D2): the paths and the words an ASF machinery card carries.
#: A product's record adopted onto ASF often holds cards about the factory rather than the product,
#: and on a customer machine the factory has no product file of its own to declare this in.
DEFAULT_FACTORY_SCOPE = {'paths': ['asf/**', 'plugin/**', 'evals/**', 'tools/**'],
                         'terms': ['asf', 'tick', 'feeder', 'groom', 'harvest', 'worktree',
                                   'backlog', 'lane', 'adjudicate']}
#: The owner name the factory's own scope is flagged under (D2).
FACTORY_SCOPE_NAME = 'asf'
```

### 2. `asf/adopt.py` — the judgement

```python
"""asf.adopt — does a card in this record belong to this product at all (F-0120)?

One judgement, read by the groom (which writes `belongs_to:` and asks about the set on one line)
and by `asf move` (which clears it). Pure over the parsed cards and the scopes it is handed; the
only place a card is attributed to another product.
"""

Scope = collections.namedtuple('Scope', 'name paths terms')
Match = collections.namedtuple('Match', 'name paths terms why')

#: The History line a `keep` answer leaves, and the one the judgement reads back (D7).
KEPT_LINE = "kept as this product's own work"
```

| function | answers |
| --- | --- |
| `scopes(product, home=None)` | every `Scope` a card here may belong to *but* this product's: one per other `*.yaml` under `~/.ASF/products/` that declares a non-empty `scope:` (P18's enumeration, its skip-a-broken-sibling rule and all), plus `Scope(FACTORY_SCOPE_NAME, **DEFAULT_FACTORY_SCOPE)` when no registered product already carries that name (D2). Sorted by name |
| `hits(rec, scope)` | `(paths, terms)` — distinct globs matched (D3) and distinct terms present (D4) |
| `matched(rec, scope)` | `paths >= 1 or terms >= min(2, len(scope.terms))`, and `terms` never satisfies a scope with none |
| `owner(rec, scopes)` | the single best `Match`, or `None`: matched scopes ranked by `(paths, terms)`, and `None` on an exact tie (D5) or when the card's body carries `KEPT_LINE` (D7) |
| `flagged(canonical, product)` | `{id: Match}` for every open, non-retired card `owner` names — what the groom writes and asks about |

`Match.why` is the phrase the groom line carries: `writes: src/billing/**` for a path hit, else
`terms: billing, invoice` naming the matched terms in scope order, at most three then `…`.

### 3. `belongs_to:` — the flag on the card

The groom writes it, in `cmd_groom`, before the sections are built:

```python
for iid, match in adopt.flagged(canonical, product).items():
    if canonical[iid]['meta'].get('belongs_to') == match.name:
        continue                        # already flagged for this owner: nothing is written
    err = set_typed(canonical[iid], {'belongs_to': match.name}, writer='groom')
    ...  # one History line: `- <date> groom: looks like <name>'s work (<why>) — asf move`
```

and deletes a flag that no longer matches (`{'belongs_to': None}`, `write_typed`'s delete form),
with `- <date> groom: no longer looks like another product's work`. A card whose flag is unchanged
is not touched at all, so re-running the groom writes nothing and makes no commit (P3's
`publish_changes` commits only what changed).

`belongs_to` joins `_COMMON_SET` (P1), so `asf set <id> belongs_to=` clears a false positive by
hand and `asf set <id> belongs_to=<p>` puts one there. This is the deliberate difference from
`removed:`/`moved_to:`, which stay unsettable: a suspicion is safe to write, a closing is not.

What the flag does **not** do: it is not in `is_retired` (P4), so the card stays in every table, in
the queue and in the counts. The only behaviour it changes is §6's row.

### 4. The groom's one line

`GROOM_SECTIONS` gains one entry, after `('Inbox cards to decide', 'inbox')`:

```python
    ("Cards that look like another product's", 'foreign'),
```

built by `groom_foreign_section(canonical, product)` — one line per suspected owner, ids in id
order, at most ten named:

```
- [ ] belongs_to:acme 7 cards look like acme's work — F-0031 F-0032 F-0033 F-0034 F-0035 F-0036 F-0037 — terms: billing, invoice → answer: ____
```

By P11 its dedupe token is `belongs_to:acme` already, so `merge_groom_text` adds the line once a
day and never a second one for the same owner. Two things are widened so the line is a question
somebody answers:

- `policy.OPEN_QUESTION_RE`'s token alternation gains `belongs_to:\S+` beside `inbox:\S+` (P12), so
  the line counts open and a `GROOM → ADJUDICATE` row carries it. By P13 it lands in the judgement
  half, untouched.
- `apply_groom_answers` gains one applier, beside `INBOX_ANSWER_RE`'s:

```python
FOREIGN_ANSWER_RE = re.compile(
    r'^- \[[ xX]\]\s+belongs_to:(?P<name>\S+)\s.*→\s*answer:\s*(?P<answer>.*)$')
#: `keep` — these are this product's own work; `remove: <why>` — retire every one of them.
FOREIGN_KEEP = re.compile(r'^keep$', re.IGNORECASE)
FOREIGN_REMOVE = re.compile(r'^remove:\s*(?P<why>\S.*)$', re.IGNORECASE)
```

The applier **re-derives the set from the record** — every open card whose `belongs_to:` is the
line's owner — and never parses the ids printed on the line. The line is prose (and truncated at
ten); the record is the fact. Then:

| answer | what is written, per card | the History line |
| --- | --- | --- |
| `keep` | `belongs_to:` deleted | `- <date> groom: kept as this product's own work` (D7's `KEPT_LINE`) |
| `remove: <why>` | `removed: <why> (groom <date>)`, `belongs_to:` deleted | `- <date> groom: removed → <why> (belonged to <name>)` |
| anything else | nothing | none |

Each card goes through P2's `set_typed`, not P14's raw `write_typed` — the reason the card asks for
"through the record's parser" — and one `groom_answer` event per card is emitted through the
injected `event` (P14), with `section='foreign'`.

An unrecognised answer (D6) rewrites the slot in place, the way a barred line is rewritten today
(`asf/groom/groom.py:996`), and the groom prints one line:

```

```

By P12 that slot no longer matches `OPEN_QUESTION_RE`, so no further adjudicator is sent to it.

### 5. `asf move`

```
asf move [ID …] [--query FIELD=VALUE]… (--to PRODUCT | --remove REASON) [--product P] [--dry-run]
```

`asf/record/move.py`, `cmd_move(args, root)`, registered in `cli.build_parser` and dispatched through
`_published` (P3) so its whole write is one signed-off, pushed commit:

```python
return _published(cmd_move, args, resolve_record(args, announce=_announce_stderr),
                  f"move: {n} cards {'removed' if args.remove else 'moved to ' + args.to}")
```

`asf/surface.py` gains the row (P19), and `tests/test_surface.py:49`'s count becomes 50:

```python
    'move':                 ("write each card off to another product or out of this record, and file it in the target's inbox", RECORD, None),
```

`--to` and `--remove` are one mutually exclusive required group; ids and `--query` are refused
together (D8). The steps, in order, each refusing before anything is written:

1. **Select.** The ids as given, or every id `--query`'s `FIELD=VALUE` pairs select off the loaded
   cards (D9, AND-ed). An id that names no card refuses; a card already retired (P4) is dropped
   from the selection and counted, so a re-run of the same command is a no-op. An empty selection
   refuses (D8): `error: --query belongs_to=acme selects no card`.
2. **Resolve the target** (`--to` only). `env.load_product(args.to)` — a `ConfigError` is one
   `NEEDS OPERATOR` line through `cli.needs_operator_line` and exit 2. `--to` naming the source
   product refuses. And D16: `env.resolve_product(args.product)`'s product must be the one whose
   `backlog_dir` is `root`, else
   `error: --to needs the source product's own record — <root> is not <name>'s backlog_dir`.
3. **Round-trip every card** (D10): `set_typed(rec, updates, apply=False)` for each, collecting the
   reasons. Any reason at all refuses the whole command, naming each card and its reason, exit 2,
   nothing written in either record.
4. **`--dry-run`** prints the table and returns 0 here, having written nothing:

```
record: <the source record>
ID       TYPE     TITLE                        ACTION            TARGET
F-0031   feature  dunning retries              moved to acme     inbox/dunning-retries.md
F-0032   bug      invoice pdf is blank         moved to acme     already there (F-0104)
F-0033   feature  the tick's own clock         removed           —
3 cards, 1 already in the target
```

5. **Write the source cards** through `set_typed`, one History line each:

| flag | typed fields | History |
| --- | --- | --- |
| `--remove "<reason>"` | `removed: <reason>`, `belongs_to: None` | `- <date> move: removed — <reason>` |
| `--to <p>` | `moved_to: <p>` (P5), `belongs_to: None` | `- <date> move: moved to <p> — <p>:<intake file>` |

6. **File each card in the target's inbox** (`--to` only) — `<target backlog_dir>/<target
   conventions.intake_dir>/<slug>.md`, `-2`-suffixed the way `cmd_inbox` names a taken slug (P16),
   skipped when D14's ref is already there:

```markdown
# dunning retries
moved_from: sample:F-0031
type: feature

<the source card's ## Description, verbatim>

## Acceptance
- [ ] retries stop at the fourth attempt
```

   `type:` is the source card's type; a Bug also carries `signature:` and `severity:`, a Task its
   `writes:`; no `parent:`, ever (D13). The title goes through `inbox.scrub_title`'s redaction
   filter before it is written into another product's record.

7. **Commit the target** (D15): `publish.publish_changes(target_root, before, f"move: {n} cards from
   {source} — inbox")`, which signs off and pushes it, and warns on stdout when the push is refused
   exactly as it does for the source.

`dedupe(target_root, intake_dir, ref)` is one function: True when any `*.md` in the intake dir or
its `done/` subdirectory carries the `moved_from: <ref>` line, **or** when the target's `index.json`
holds an item whose `moved_from` is `<ref>` — falling back to `load_items(target_root)` when the
target has no `index.json` yet.

The last piece is what makes the dedupe survive minting (D14, P15): `INBOX_KV_RE` gains
`moved_from`, and `process_inbox`'s typed dict carries it onto the minted card:

```python
    typed = {'title': card.title, 'parent': parent, 'decided': False}
    if card.headers.get('moved_from'):
        typed['moved_from'] = card.headers['moved_from']   # F-0120 D14: the dedupe ref survives
```

### 6. The feeder — a flagged item decides nothing and holds nothing

One helper in `asf/feeder/rows.py`, beside `console_amend_row`:

```python
def foreign_row(product, item, tier, feature_id, brief_kind, kind):
    """The NEEDS DECISION row for an item flagged as another product's work (``belongs_to:``,
    F-0120), else None. It launches nothing and costs no slot (:mod:`asf.feeder.tiers`), so an
    S1 flagged this way no longer holds the tier-2 rows behind it."""
    name = (item or {}).get('belongs_to')
    if not name:
        return None
    return Row(tier=tier, kind=kind, item_id=item['id'], feature_id=feature_id,
               action=NEEDS_DECISION, brief_kind=brief_kind,
               branch=branch_for(product, 'fix' if kind == BUG_FIX else 'spec', item['id']),
               reason=f"looks like {name}'s work, not this product's: "
                      f"asf move {item['id']} --to {name} (or --remove)",
               waits_on='decision')
```

Called from two places (D11): the head of `bug_rows`' per-Bug ladder, ahead of the `busy` branch
(D12), and the Feature's own launching row. By P8 `hold_unlanded` leaves it alone, and by P9 —
measured — a flagged S1 stops cutting tier 2.

## Records

**On the cards, in the source record.** Four typed fields, three of them new to a card's life:

- `belongs_to: <product>` — the groom's suspicion. Written and deleted by the groom, settable by
  hand (`asf set`), deleted by `asf move`. Never part of `is_retired` (P4).
- `removed: <reason>` — written by `asf move --remove` and by the groom's `remove: <why>` answer
  (`<why> (groom <date>)`). The same field the hand procedure writes today, now written by a
  command that round-trips the card.
- `moved_to: <product>` — written by `asf move --to`. P5's form, product-only: the target's id does
  not exist until the target's groom mints it.
- One History line per card per write, with the exact texts §3, §4 and §5 give. `KEPT_LINE` is read
  back by the judgement (D7), so its wording is load-bearing and lives in `asf/adopt.py`.

**`index.json`** in the source record, rewritten by P3's commit: every one of those fields (P6), and
the Children/Backlinks a retired card no longer derives (P4).

**One commit in the source record** per `asf move` run and per `asf groom` that applies a foreign
answer, signed off and pushed by `publish_changes`:
`move: 7 cards moved to acme` / `move: 12 cards removed` / the groom's own message, unchanged.

**In the target record**, when `--to` is given: one `*.md` per imported card in its
`conventions.intake_dir`, carrying `moved_from: <source>:<ID>`; and **one commit of its own** (D15),
`move: 7 cards from <source> — inbox`, signed off and pushed. Later, when the target's groom types
that card, `moved_from:` lands in its typed block and from there in the target's `index.json` (P15,
D14) — the provenance ref, and the thing every future dedupe reads.

**The groom file**, `groom/<date>.md`: a new `## Cards that look like another product's` section,
one line per suspected owner, and a slot rewritten to `____ (operator: asf move …)` when the answer
was not one of the two the groom can apply.

**Events**: one `groom_answer` per card the foreign answer wrote, through the `event` callable the
tick already injects (P14) — `item`, `section='foreign'`, `field` (`removed` or `belongs_to`),
`value`, `by`. `asf move` runs from the console, where there is no tick context to emit into; its
record is the commit and its stdout table.

**Stdout**: the `record: <path>` first line every record command prints (`resolve_record`), the
table §5 shows, and — only when a person must act — one `NEEDS OPERATOR:` line from §4 or from an
unregistered `--to`.

**Operator config and docs**: `scope:` in `docs/products.example.yaml` and `product-config.md`;
`operating.md`'s adoption case. No migration, no new `~/.ASF` state, no change to any table's
columns.
