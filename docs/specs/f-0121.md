# F-0121 — the foreign hook is chained, not refused: `<hook>.local` behind ASF's gate, stdin buffered once

The first customer install hit this. `asf hooks install` writes the redaction gate's `pre-commit`
and `pre-push` into a product's real hooks directory, but a repo that already has its own hook
there gets a refusal instead — `NEEDS OPERATOR: <path> is not asf's — add the line: …` — and the
operator hand-merges ASF's line into each hook. For `pre-push` that hand-merge is not one line:
`asf redact --pre-push` reads the whole of stdin, so the existing hook stops receiving the pushed
refs unless the operator also rewrites it to buffer stdin and feed each consumer a copy. The guide
carries that example (`docs/guide/product-config.md:657-668`) because there was nothing else to
offer. It cost an approval plus hand edits in two repos.

This change makes chaining the default for the operator-facing install: the foreign hook is renamed
to `<hook>.local`, ASF writes its own hook at `<hook>`, and that hook runs the gate and then the
renamed one — same arguments, and for `pre-push` the same stdin, buffered once and read twice.
`asf hooks uninstall` puts the original back. The unattended caller that also runs this code — the
worker pool's spawn gate — keeps today's refusal, because renaming a file in the operator's repo
is not a thing a tick does while nobody is looking.

### In

- **Chaining, in `ensure_git_hooks`, behind one keyword argument.** `ensure_git_hooks(product,
  which=shutil.which, chain=False)`. When `chain` is true and a hook file is there that is neither
  ASF's nor an upgradable `asf init` hook, it is renamed to `<hook>.local` in the same directory
  and ASF's **chained** body is written at `<hook>`. The refusal path stays exactly as it is for
  `chain=False` (D1).
- **Two chained bodies, because only one of the two hooks gets stdin from git** (D2).
  `_git_hook_body(name, asf_path, product_name, chained=False)` grows the third form. For a hook
  in the new `STDIN_HOOKS = ('pre-push',)` the body buffers stdin once into a temp file and feeds
  both halves from it; for every other hook the body touches stdin at all and passes it through
  untouched. Both keep the `written by asf hooks install` comment P2 already writes, both forward
  `"$@"`, and both propagate the exit status of whichever half fails.
- **The renamed hook is found at run time, not baked in** (D3): `"$(dirname "$0")/<name>.local"`,
  guarded by `[ -x … ]`. A hooks directory may be tracked and committed (P4) — a baked absolute
  path in a tracked file names the install host's checkout, which is the sort of line the redaction
  gate exists to stop — and the `-x` guard keeps a hook git was already ignoring ignored.
- **`asf hooks install --chain` / `--no-chain`, chaining by default** (D4). `hooks_command` gains
  `uninstall` to its `choices`, `cmd_hooks` dispatches on it, and a mutually exclusive
  `--chain` / `--no-chain` pair sets `chain`, defaulting to true. `--chain` is therefore a no-op
  the card names so the operator can write what they mean; `--no-chain` is today's behaviour.
- **`asf init` chains; the spawn gate does not** (D5). `asf/init.py:317` passes `chain=True` — a
  repo ASF is adopting, at a terminal, with the operator watching, is the case the card was
  reported from. `asf/workers/spawn.py:441` passes nothing and keeps the `chain=False` default: a
  worker wave must never rename a file in the operator's repo unattended. Its `SpawnError` detail
  already names `asf hooks install --product <p>`, which now fixes it in one command.
- **A `<hook>.local` already there is never overwritten** (D6). The install refuses with
  `NEEDS OPERATOR: <path>.local is already there — asf hooks install cannot chain <path> without
  losing it; move it aside or merge the two`, leaves both files alone, and goes on to every other
  hook exactly as P1's refusals do.
- **Idempotence falls out of P3 and is asserted, not assumed.** After a chained install the file at
  `<hook>` contains `asf redact --<name>`, so the second run takes the "already ours" branch and
  changes nothing — not the hook, not the `.local`, not its mtime. `staged_check_upgrade` on a
  chained `pre-commit` finds no whole-record `asf check` line and returns None, so it does not
  rewrite it either (P12).
- **`asf hooks uninstall --product <p>`** (D7), a new function `uninstall(product)` returning
  `(rc, message)`. Per repo, per name in `GIT_HOOK_NAMES`: a hook carrying the new
  `HOOK_MARKER = 'written by asf hooks install'` is removed, and when `<hook>.local` is there it is
  moved back to `<hook>` first (`os.replace`, so the mode and the contents are the original's).
  Anything else — the operator's own hook, an `asf init` hook (`INIT_MARKER`), a hand-merged one —
  is left byte-for-byte as it is and named in the message. Idempotent: nothing there is nothing to
  do, `rc` 0.
- **The doctor accepts the chained form and is red on a broken chain** (D8). `is_git_hook_ours`
  already returns true for a chained body (P3), so `check_redaction_hooks` accepts it with no
  change at all. What is added is one `elif`: a hook that chains a `<name>.local` which is **not
  there** is `\<path> chains <name>.local, which is not there` — the operator's hook silently
  stopped running, which is the one failure the chain can hide. A `.local` that is there but not
  executable is **not** a problem: git was ignoring it before too (D3).
- **The approvals class keeps binding this install, and now binds the new file too** (D9). The
  `touch_amendable_set` Bash recogniser becomes `r'\basf\s+hooks\s+(?:un)?install\b'`, so
  `asf hooks uninstall` is held exactly as `install` is. A new constant
  `REAL_GIT_HOOK_GLOBS = ('.git/hooks/*',)` joins `_PATH_GLOBS['touch_security']`, so a session
  writing a real hook file — the chained `<hook>`, or the `<hook>.local` behind it, which runs on
  every commit and was unreachable by any recogniser before this change — is refused as
  `touch_security`.
- **The three guide passages that tell the operator to hand-merge** (P14) are rewritten to name the
  one command, keeping the hand-merge example as what `--no-chain` leaves you to do.
- **The two tests P13 names** are updated: `--no-chain` where the point is the refusal, plus the
  new chained assertions where the point is the install.

### Out

- **Removing anything from a settings file.** `asf hooks uninstall` touches git hooks only. The
  `approvals` PreToolUse hook in every worker account's settings is the guard that refuses
  human-now actions (`asf/hooks.py:317-319`), and a command that quietly disarmed it across every
  account would be the worst thing in this change. The message says so in one line.
- **Chaining any hook but the two in `GIT_HOOK_NAMES`.** ASF installs a `pre-commit` and a
  `pre-push`; it chains those and nothing else. A `commit-msg` or `post-checkout` the operator has
  is not ASF's business.
- **`git mv` for a rename inside a tracked hooks directory.** When `core.hooksPath` points at
  `.githooks/` (P4) the rename is an ordinary working-tree change the operator commits, exactly as
  the guide already says of the hooks ASF writes there. The install prints the two paths it moved
  so there is nothing to discover; it does not stage anything.
- **Folding the three upgrade paths into one `hook_upgrade`.** `docs/plans/f-0055.md:41` (PD11)
  already owns that refactor of the `init_hook_upgrade(…) or staged_check_upgrade(…)` chain. This
  change adds no fourth upgrade — chaining is a different branch, taken only when neither upgrade
  applies — so the two do not collide.
- **Adding `.git/hooks/*` to `hooks.GIT_HOOK_GLOBS`.** That constant is also the amendable set's
  `hooks` kind (P11), which is about tracked paths a pull request can touch; `.git/` is never
  tracked. Hence the separate `REAL_GIT_HOOK_GLOBS` in D9.
- **A `--chain` flag on `asf init` or on the spawn gate.** D5 fixes each caller's answer in code;
  neither grows a flag.

| --- | --- | --- | --- |

A future caller that forgets the argument gets today's refusal, not an unattended rename of a file in the operator's repo. The CLI's own default is still `--chain` (D4), which is what the card asks for. |
| D2 | Only the hooks in `STDIN_HOOKS = ('pre-push',)` buffer stdin; `pre-commit`'s chained body does not touch stdin | One chained body that buffers stdin for both hooks | Git does not feed `pre-commit` ref lines, and it does not reliably close that hook's stdin either — a `cat` in a `pre-commit` can sit waiting for EOF on a terminal and hang every commit in the repo. Passing stdin straight through is also *exactly* what the foreign hook saw before ASF arrived, whatever git does with it. ## The design

### `asf/hooks.py` — four constants, one keyword, one new function

Three new module constants beside `GIT_HOOK_NAMES` (`asf/hooks.py:51-63`):

```python
#: The real git hooks directory's own files — never tracked, so not part of the amendable set
#: (`GIT_HOOK_GLOBS`), but never a session's to write either: the hook asf installs, and the
#: `<hook>.local` behind it that runs on every commit (F-0121, D9).
REAL_GIT_HOOK_GLOBS = ('.git/hooks/*',)

#: What a foreign hook is renamed to when `asf hooks install --chain` chains it (F-0121).
LOCAL_SUFFIX = '.local'

#: The comment line every hook `_git_hook_body` writes carries — what `asf hooks uninstall` knows
#: this installer's own file by, and `asf init`'s (`asf.init.INIT_MARKER`) or the operator's
#: hand-merged one by its absence (D6).
HOOK_MARKER = 'written by asf hooks install'

#: The git hooks git feeds on stdin, whose chained body buffers it once so both halves read the
#: same bytes (D2). `pre-commit` is not one: git does not give it ref lines and does not reliably
#: close its stdin, and a `cat` there would hang every commit in the repo.
STDIN_HOOKS = ('pre-push',)
```

`_git_hook_body(name, asf_path, product_name, chained=False)`. `chained=False` returns today's
three lines byte for byte. `chained=True` and `name not in STDIN_HOOKS`:

```sh
#!/bin/sh
# written by asf hooks install — the redaction gate (F-0075), chaining pre-commit.local
# Your own pre-commit was renamed to pre-commit.local and runs below, with the same arguments
# and the same stdin. `asf hooks uninstall --product <p>` puts it back.
"/abs/asf" redact --pre-commit --product <p> || exit $?
own="$(dirname "$0")/pre-commit.local"
[ -x "$own" ] || exit 0
exec "$own" "$@"
```

`chained=True` and `name in STDIN_HOOKS`:

```sh
#!/bin/sh
# written by asf hooks install — the redaction gate (F-0075), chaining pre-push.local
# Your own pre-push was renamed to pre-push.local and runs below, with the same arguments and
# the same refs. `asf hooks uninstall --product <p>` puts it back.
# git writes the pushed refs on stdin and both halves need them: buffered once, read twice.
refs="$(mktemp "${TMPDIR:-/tmp}/asf-pre-push.XXXXXX")" || exit 1
trap 'rm -f "$refs"' EXIT HUP INT TERM
cat > "$refs"
"/abs/asf" redact --pre-push --product <p> < "$refs" || exit $?
own="$(dirname "$0")/pre-push.local"
[ -x "$own" ] || exit 0
"$own" "$@" < "$refs"
exit $?
```

Both satisfy `is_git_hook_ours` unchanged (P3): the gate command is there in the quoted-path form
the regex already accepts.

One new recogniser, used by the doctor and by `uninstall`:

```python
def chained_local(text, name):
    """``<name>.local`` when ``text`` is a chained hook this installer wrote for ``name`` — it
    carries :data:`HOOK_MARKER` and names ``<name><LOCAL_SUFFIX>`` — else None. The name only: the
    file sits beside the hook, in the directory the caller already has."""
```

`ensure_git_hooks(product, which=shutil.which, chain=False)`. The one branch that changes is the
foreign one at `asf/hooks.py:206-208`:

```python
if not is_git_hook_ours(text, name):
    if not chain:
        refusals.append(f'NEEDS OPERATOR: {path} is not asf\'s — add the line: '
                        f'"{asf_path}" redact --{name} --product {product.name}')
        continue
    local = path + LOCAL_SUFFIX
    if os.path.exists(local):
        refusals.append(f'NEEDS OPERATOR: {local} is already there — asf hooks install '
                        f'cannot chain {path} without losing it; move it aside or '
                        f'merge the two')
        continue
    os.rename(path, local)
    chained.append((path, local))
    _write_hook(path, _git_hook_body(name, asf_path, product.name, chained=True))
continue
```

`_write_hook(path, body)` is the `open`/`write`/`chmod 0o755` triple the function already does
twice, lifted so the three writes cannot drift. The success detail names what moved, so a tracked
hooks directory's operator sees what to commit (Out):

```
pre-commit, pre-push in 2 repos; chained <path>/pre-push → <path>/pre-push.local
```

`uninstall(product)` → `(rc, message)`, symmetric with `install`:

```python
def uninstall(product):
    """Returns ``(rc, message)``. Removes the redaction gate's git hooks *this installer* wrote
    (:data:`HOOK_MARKER`) from :func:`git_hooks_dir` of each of ``product.repo_dir`` and
    ``product.backlog_dir``, putting a chained ``<hook>.local`` back at ``<hook>`` first
    (``os.replace`` — the original's own bytes and mode). A hook that is not this installer's is
    left exactly as it is and named in the message: the operator's own, one `asf init` wrote
    (:data:`asf.init.INIT_MARKER`), one with the gate line hand-merged in. Idempotent — nothing
    there is rc 0 and nothing done. Writes no settings file: the worker accounts' ``approvals``
    hook is the guard over human-now actions and this command never removes it (Out)."""
```

Its message:

```
hooks uninstall: 1 restored, 1 removed in 2 repos; the approvals hook in 1 worker account is left
in place — it is the guard over human-now actions
```

and, for anything left alone, one line each:

```
<path> is not asf hooks install's — left as it is
```

`rc` is 0 whenever every hook this installer wrote is gone, which includes the case where there was
nothing to do; a hook left alone is reported, not a failure — there is nothing for a human to
decide, so it is not a `NEEDS OPERATOR`.

### `asf/hooks.py` — the parser and the dispatch

```python
p.add_argument('hooks_command', choices=['install', 'uninstall'])
p.add_argument('--product')
g = p.add_mutually_exclusive_group()
g.add_argument('--chain', dest='chain', action='store_true', default=True,
               help='chain a hook already there: rename it <hook>.local and run it after the '
                    'gate (the default)')
g.add_argument('--no-chain', dest='chain', action='store_false',
               help="refuse a hook that is not asf's instead of chaining it")
```

`cmd_hooks` dispatches:

```python
def cmd_hooks(args):
    product = env.load_product(args.product)
    if args.hooks_command == 'uninstall':
        rc, msg = uninstall(product)
    else:
        rc, msg = install(product, chain=args.chain)
    print(msg, file=sys.stderr if rc else sys.stdout)
    return rc
```
