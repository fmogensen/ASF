# F-0079 — Capacity is configuration: session workers and CI, per product and per operator

Epic: E-0001 — ASF 0.1 — a working factory

> As an operator, I want to set how many sessions and how many CI runs the factory may hold at
> once — per product, and as a total across products — so that a product's share of the workers
> and the runners is a line in a file, not a number typed into a launch script.

---

## 1 · Decisions

### In scope

- One `capacity:` block in `~/.ASF/config.yaml` (the operator's totals and the defaults) and one
  `capacity:` block in `~/.ASF/products/<name>.yaml` (that product's ceilings and its CI batch
  shape).
- One resolver — `asf/capacity.py` — that turns those two blocks plus what is in flight into the
  numbers every caller uses. No caller reads the raw keys.
- Two enforcement points ASF actually owns:
  1. the tick's `wave` step — the session cut, today `config.yaml feeder.capacity`;
  2. the tick's `batch` step — held back when the product is already at its CI-run ceiling.
- One publication point: a command step (`steps: {batch: <command>}`) is run with the resolved
  numbers in its environment, and `asf capacity --json` answers the same question for a script
  the tick does not launch.
- `asf capacity` — the table (R-0109) — and a `capacity` row in `asf doctor`.
- The S1 reserve moves from `worker_pool.reserve_for_s1` to `capacity.reserve_for_s1`; the old
  key keeps working.
- Validation: `capacity:` becomes a declared field of the product file, with its nested keys
  checked the way `ci:` already is.

### Out of scope

- **Changing what an account `cap` means.** `worker_pool.accounts[].cap` stays the pool's own
  ceiling on concurrent sessions per account. Capacity is a *budget*; `cap` is the *hardware*.
  They compose (see D5), neither replaces the other.
- **Auto-tuning.** Capacity is never derived from quota, spend, queue depth or time of day. It is
  a number in a file, changed by an operator.
- **Enforcing capacity inside a product's merge-queue script.** The `batch` step is the product's
  own program; ASF tells it its budget and refuses to start it over the ceiling. What the script
  does with `ASF_CAPACITY_BATCH_PARALLEL` is the script's business.
- **Launching CI.** ASF does not start runs; it counts them.
- **The S1 reserve's semantics.** Only its home moves.
- **Per-lane or per-model capacity** beyond the existing `accounts[].caps` — no new axis.
- **A record schema bump.** `schema_version` versions the *record*; these are operator-config
  keys, read with a fallback, so nothing migrates and `SCHEMA_VERSION` stays 1.

### Preconditions

| # | precondition | why it matters |
| --- | --- | --- |
| P1 | `asf/env.py`'s YAML subset already parses nested maps, inline lists and ints — no new parser. | The blocks below must stay inside that subset; nothing anchors, no multi-line strings. |
| P2 | `asf.env.validate_product_text` today special-cases exactly one nested section (`ci`). | Adding `capacity` means generalising that to a table, not adding a second special case. |
| P3 | `asf.tick.steps.run_command` runs a command step with the tick's inherited environment (no `env=`). | Publishing the numbers is an env overlay on that one call. |
| P4 | `asf.workers.quota.guards_from_config` already sets the precedent for "new key wins, old key honoured, nothing migrates". | D3's deprecation copies it exactly rather than inventing a second style. |
| P5 | `asf.feeder.tiers.free_slots` subtracts this product's in-flight sessions from the capacity it is handed. | The resolver must return a *ceiling*, not a free count, or the subtraction happens twice. |
| P6 | The plugin is generated from the CLI and `asf plugin check` is a gate step. | A new `asf capacity` subcommand is not done until `asf plugin build` has been run and its output committed. |
| P7 | `~/.ASF/products/*.yaml` is the list of products (the enumeration `asf.schema._all_products` already uses). | The cross-product total has a definition of "every product" that does not need a new registry. |
| P8 | The gate is `python3 -m unittest discover -s tests`, `bash tools/check_conventions.sh`, `bash tools/check_generic.sh`, `asf plugin check`. | Section 3's blocks are those commands, not new ones. |

### The choices

| # | the choice | chosen | against | why |
| --- | --- | --- | --- | --- |
| D1 | Where capacity is declared | a `capacity:` block in **both** files — totals and defaults in `config.yaml`, ceilings and batch shape in `products/<name>.yaml` | one block in `config.yaml` keyed by product name | The card asks for per product *and* per operator. A product's share belongs beside its other conventions, where the product's own owner edits it; the total belongs where the shared scheduler and pool already live. A per-product table inside `config.yaml` would make adding a product a two-file edit for no gain. |
| D2 | What a number means | a **ceiling**: "at most this many at once" | a reservation/floor, or a weighted share | A floor cannot be enforced without preempting a live session, and a weight cannot be checked by an operator reading the file. A ceiling is one integer with one meaning, and `asf doctor` can say when the ceilings oversubscribe the total. |
| D3 | The old keys | `feeder.capacity` and `worker_pool.reserve_for_s1` still read, new keys win, `asf doctor` prints one line naming the move | delete them; or migrate the config file in place | P4's precedent. A config a running factory depends on is not rewritten under it, and an operator who never edits again keeps today's behaviour exactly. |
| D4 | Resolution order for a product's session ceiling | `products/<n>.yaml capacity.sessions` → `config.yaml capacity.per_product.sessions` → `config.yaml feeder.capacity` (deprecated) → `DEFAULT_SESSIONS = 4` | product key only, with no operator default | An operator running five products should set the default once. The deprecated key sits between the default and the new ones so an untouched config is unchanged. |
| D5 | Capacity vs account caps | the **smallest wins**; capacity never raises what the pool allows | capacity overrides `cap` | Capacity is a budget over a pool that may be smaller than the budget. A budget that could conjure a session the accounts cannot host would turn a config typo into a spawn failure every tick. `pool.pick_account` keeps its own refusals unchanged. |
| D6 | The cross-product total | `capacity.total.sessions` minus the sessions in flight for **every other** product, then `min()` with this product's ceiling | a global queue, or round-robin across products | The tick runs per product, one product per invocation. Subtracting others' in-flight sessions is a read of files this machine already has (`state/<p>/sessions.jsonl`), needs no new daemon, and degrades to the per-product ceiling when the total is unset. It is first-come-first-served across products, and it says so. |
| D7 | Counting CI runs in flight | a small source object (`GhRuns` default, `NoCiRuns` when the product has no CI) returning an `int` or `None` | reading a ledger ASF writes | ASF does not launch CI, so any ledger it kept would be a guess. The provider is the truth. The source object is what makes it stubbable in a test — the shape `asf.workers.quota.source_from_config` already uses. |
| D8 | An unreadable CI count | **`None` = unknown, and unknown never blocks**: the batch step runs, the table prints `?` | treat unknown as "at the ceiling" and hold | A network blip must not stop the merge queue. The failure mode of over-running CI is a queued run; the failure mode of holding the queue on a blip is a factory that stops landing work. |
| D9 | How the CI total is paid for | the total is consulted **only when `capacity.total.ci` is set**; a product's own ceiling is consulted only when `capacity.ci` is set | always count | Counting costs one `gh` call per product per tick. An operator who has not asked for a CI budget pays nothing. |
| D10 | Telling the merge-queue script its shape | an env overlay on the command step (`ASF_CAPACITY_*`), plus `asf capacity --json` | a generated file the script sources; a flag appended to the command line | The overlay needs no change to any existing `steps:` declaration and cannot break a script that ignores it. Appending flags would break every script that does not accept them. Only keys that resolve are exported, so a script's own default still applies where ASF has no opinion. |
| D11 | The batch shape's home | `capacity.batch` in the **product** file, not `ci.budgets` | extend the existing `ci.budgets` map | `ci.budgets.minutes_per_day` is a spend budget for a whole day; `batch.per_run` / `parallel` / `runners` are a concurrency shape for one run. Putting the shape under `capacity` keeps one answer to "what limits this product at once" in one block. |
| D12 | Where the resolver lives | a new top-level `asf/capacity.py` | inside `asf/tick/step_wave.py` or `asf/workers/pool.py` | `asf.views.status`, `asf.doctor`, `asf.tick.steps`, `asf.tick.step_wave` and the new CLI all read it. A module owned by one step would make four of those import a step. |

## 2 · The design

### 2.1 The two blocks

`~/.ASF/config.yaml` — the operator's totals and the defaults (new section, added to
`docs/config.example.yaml`):

```yaml
# capacity: the ceilings the factory runs under. Every number is "at most this many at once".
# A key left out means "no opinion" — the next fallback applies (see docs/specs/f-0079.md).
capacity:
  total:              # across every product under ~/.ASF/products/
    sessions: 6       # concurrent worker sessions
    ci: 4             # concurrent CI runs
  per_product:        # the default for a product whose own file declares none
    sessions: 2
    ci: 1
  reserve_for_s1:     # the lane reserve, moved from worker_pool.reserve_for_s1
    local: 1
    cloud: 1
```

`~/.ASF/products/<name>.yaml` — this product's ceilings and its CI batch shape (new section,
added to `docs/products.example.yaml`):

```yaml
# capacity: this product's share of the factory. Each is a ceiling, capped in turn by
# config.yaml's capacity.total and by what worker_pool.accounts can host.
capacity:
  sessions: 3         # concurrent worker sessions for this product
  ci: 2               # concurrent CI runs for this product
  batch:              # the shape the product's own merge-queue script is told to run
    per_run: 8        # batches per run
    parallel: 2       # batches in flight at once
    runners: 4        # runner slots one run may claim
```

Both stay inside the YAML subset `asf.env.loads` reads (P1): nested maps, bare int scalars.

### 2.2 `asf/capacity.py` — the resolver

The one module that reads those keys. Nothing else does.

```
DEFAULT_SESSIONS = 4          # today's asf.tick.step_wave.DEFAULT_CAPACITY, moved here
DEFAULT_RESERVE  = {'local': 1, 'cloud': 1}   # today's asf.workers.pool.DEFAULT_RESERVE

class Resolved:
    sessions      : int          # the ceiling to hand the feeder
    sessions_bound: str          # 'product' | 'operator total' | 'default' | 'feeder.capacity'
    ci            : int | None   # None = no CI ceiling configured
    ci_bound      : str | None
    ci_inflight   : int | None   # None = unknown (D8)
    batch         : dict         # {'per_run': n, 'parallel': n, 'runners': n}, missing keys absent
    reserve       : dict         # {'local': n, 'cloud': n}

product_sessions(product, cfg)        -> (int, source)      # D4's chain
product_ci(product, cfg)              -> (int|None, source)
total_sessions(cfg)                   -> int | None
total_ci(cfg)                         -> int | None
inflight_sessions(product_name)       -> int                # live rows in state/<p>/sessions.jsonl
inflight_sessions_elsewhere(name)     -> int                # every OTHER product under ~/.ASF/products
batch_shape(product, cfg)             -> dict
reserve(cfg)                          -> dict               # capacity.reserve_for_s1, else the old key
ci_source(product, cfg)               -> CiRuns | NoCiRuns
resolve(product, cfg=None, ci_source=None) -> Resolved
deprecations(cfg)                     -> [str]              # one line per old key still in use
env_overlay(resolved, product)        -> dict               # the ASF_CAPACITY_* map
```

**The session law.** The number handed to the feeder is a *ceiling*, because
`asf.feeder.tiers.free_slots` subtracts this product's in-flight sessions itself (P5):

```
ceiling  = product_sessions(product, cfg)                      # D4's chain
headroom = total_sessions(cfg) - inflight_sessions_elsewhere(product.name)   # ∞ when unset
sessions = max(0, min(ceiling, headroom))
```

`sessions_bound` names whichever term won, so the table and the event can say *why* the factory
is not launching. The pool's own refusals (`pool full`, `reserved for S1`, `no account under
quota`) are untouched: D5's "smallest wins" is exactly the composition of this cut with
`Pool.pick_account`.

**The CI law.** Symmetrical, and entirely skipped when nothing is configured (D9):

```
ceiling  = product_ci(product, cfg)               # None -> no ceiling, no counting, no gh call
headroom = total_ci(cfg) - ci_inflight_elsewhere  # only computed when capacity.total.ci is set
ci       = min(...) of whichever terms exist, else None
```

`CiRuns.read(product)` runs

```
gh run list -R <repo_slug> --workflow <ci.workflow> --limit 50 \
   --json status --jq '[.[] | select(.status != "completed")] | length'
```

and returns the int, or `None` on any non-zero exit, timeout, unparsable output, `ci: none`, a
missing `repo_slug` or a missing `ci.workflow`. It never raises (D8). `NoCiRuns.read` returns
`None` always and is what a test injects.

### 2.4 `asf capacity`

```
asf capacity [--product <name> | --all] [--json]
```

The table (R-0109 — script-generated, never hand-typed):

```
CAPACITY — operator total: sessions 6, ci 4

product  sessions  in flight  free  bound by         ci   runs  free  batch
asf      3         2          1     product          2    1     1     8 per run × 2 parallel on 4 runners
web      2         2          0     operator total   1    ?     ?     4 per run × 1 parallel on 2 runners

deprecated: feeder.capacity is set — move it to capacity.per_product.sessions
```

`--json` prints one object per product: `{product, sessions: {ceiling, inflight, free, bound_by},
ci: {ceiling, inflight, free, bound_by}, batch: {per_run, parallel, runners}, deprecated: [...]}`.
A `?` in the table is `null` in the JSON. This is the call a merge-queue script makes when it is
not launched by the tick (D10).

### 2.5 The doctor row

`asf doctor` gains a `capacity` row, green when the block parses and the numbers are coherent,
amber-with-detail otherwise. It names, in one line each:

- the sum of every product's `capacity.sessions` exceeding `capacity.total.sessions` — the
  oversubscription D2 allows but wants said out loud;
- `capacity.total.sessions` exceeding the sum of `worker_pool.accounts[].cap` — a budget the pool
  cannot host (D5);
- any deprecated key still in use (D3), with the key to move it to.

None of these is a refusal. A doctor row is a report; the tick keeps running.

### 2.6 The batch step, end to end

```
tick --step batch
  └─ capacity.resolve(product)
       ├─ ci is None            -> run the command (nothing configured, D9)
       ├─ ci_inflight is None   -> run the command (unknown never blocks, D8)
       ├─ ci_inflight >= ci     -> `waits    batch — at ci capacity (2/2)`, skip, rc 0
       └─ otherwise             -> run the command with the env overlay:
              ASF_PRODUCT=asf
              ASF_CAPACITY_SESSIONS=3
              ASF_CAPACITY_CI=2
              ASF_CAPACITY_BATCH_PER_RUN=8
              ASF_CAPACITY_BATCH_PARALLEL=2
              ASF_CAPACITY_RUNNERS=4
```

A key whose value does not resolve is simply absent from the overlay, so the script's own default
still wins there (D10).

## 4 · Records

### 4.1 Files the change writes

| file | written by | what it holds |
| --- | --- | --- |
| `~/.ASF/config.yaml` | the operator, by hand | `capacity.total`, `capacity.per_product`, `capacity.reserve_for_s1` |
| `~/.ASF/products/<name>.yaml` | the operator, by hand | `capacity.sessions`, `capacity.ci`, `capacity.batch` |
| `plugin/skills/asf-capacity/SKILL.md` | `asf plugin build` | the generated skill for the new subcommand (P6) |

Nothing in `~/.ASF/state/` gains a file: capacity is read, never cached. The in-flight counts come
from the session ledgers that already exist (`state/<p>/sessions.jsonl`) and from the CI provider.

### 4.2 Lines the tick prints

| line | when |
| --- | --- |
| `waits    batch — at ci capacity (2/2)` | the `batch` step held back at the CI ceiling |
| `wave: nothing to launch` (unchanged) | the cut left no row — now possibly because the operator total is spent elsewhere |
| `capacity: feeder.capacity is set — move it to capacity.per_product.sessions` | `asf doctor`, once, per deprecated key in use |

### 4.3 The event

One `capacity` event per tick, appended by the `wave` step to
`metrics/events/<day>.jsonl` in the record clone, next to the `launch` events it already writes:

```json
{"kind": "capacity", "product": "asf", "sessions": 3, "sessions_inflight": 2,
 "sessions_bound_by": "operator total", "ci": 2, "ci_inflight": 1, "ci_bound_by": "product",
 "ts": "2026-09-22T09:00:00Z"}
```

It is written every tick, bound or not, so `asf metrics rollup` can answer "how often was the
factory capacity-bound, and by which limit" without a second source. `ctx.counts` gains no key —
the event carries it.
