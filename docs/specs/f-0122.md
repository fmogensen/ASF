# F-0122 — one record to read, an age on every table, and a doctor row when the checkout is stuck

The record exists twice on an operator's machine: their own checkout (`backlog_dir`) and the tick's
clone under the product's state directory. The tick derives state in its clone and pushes; the
`/asf:*` tables read the checkout. The first customer install had to learn that to understand what
it was looking at, and the guide still opens with *before you read a table, `git pull`* — a manual
step between every tick and every table, and a silent one: a table off a two-day-old checkout looks
exactly like a table off a fresh one.

One thing the card says is no longer true of the code, and the design below is cut to what is:

- **The tick does fast-forward the checkout.** `shadow.sync_operator_checkout` landed in
  `47c3e9d11` and runs from `commit_and_push` (P2). It is `--ff-only`, refuses a dirty tree or a
  non-trunk HEAD, and names the refusal in one line. So the card's second option is half-built.
  What is missing is that it is *reached* — it hangs off the record clone's commit path, so a tick
  that ran no record step, or whose record step failed, never calls it (P4) — that it is **tested**
  (nothing anywhere calls it but the tick: P3) — and that it says anything at all when it *works*,
  so the tick log has no record of the checkout having been moved.

And two the card asks for that do not exist: no table prints the record's age (P6, P7), and
`asf doctor` says nothing about the checkout beyond "it is a git worktree" (P5).

After this change: the checkout is fast-forwarded on **every** tick that could have moved origin,
however that tick exits, and the line says so. Every table's first line reads `record: <path> —
index generated 3m ago`. When the checkout *cannot* be fast-forwarded — the operator has local
changes, or is on a branch — the tables fall back to reading the tick's clone, read-only, and the
same first line names the copy, how much older the checkout's own index is, and the one command
that fixes it. `asf doctor` carries a `record` row that says behind, dirty, off-trunk or diverged.
And the guide stops telling the operator to pull before reading.

### In

- **`asf/views/freshness.py`** — the one answer to *which copy of the record does a table read, and
  how old is its index*. Read-only, stdlib only, **no git and no network**: two `index.json` reads
  and a comparison of their `generated` stamps (P9).
- **Newest `generated` wins.** A table reads the operator's checkout unless the tick's clone holds
  an `index.json` that is *strictly* newer, in which case it reads the clone. Ties, and a clone
  that is older, go to the checkout.
- **The clone is only ever considered for the product's own checkout**: when the resolved root is
  not `realpath(product.backlog_dir)` — a cwd-resolved record, another product's record — the
  fallback is off. A missing clone, or one with no `index.json` (a host that has never ticked),
  is simply not a candidate.
- **The `record:` line carries the age**, and names the fallback when it took one:
  `record: <root> — index generated 3m ago`, or
  `record: <clone> (the tick's clone) — index generated 3m ago; your checkout <path> is 2h older — git -C <path> pull`.
- **`asf next` joins the tables**: it resolves through the same function and prints the same first
  line (stderr under `--json`, as every table does).
- **The tick's fast-forward is reached on every exit.** One function, `tick.sync_checkout(ctx)`,
  idempotent per tick, called from `run`'s end and from both of `run_record_step`'s standalone
  returns — and removed from `commit_and_push`, so a raising commit no longer skips it (P4).
- **It says one line when it moves the checkout**: `record: <path> fast-forwarded to
  origin/<trunk>`. A refusal keeps the line it already prints; a checkout already current stays
  silent.
- **`env.state_path`** — the state directory's path *without* creating it (P11), with `state_dir`
  as that plus the `makedirs`. `shadow.record_dir` and `shadow.shadow_dir` become pure path
  functions, so a table asking where the clone would be does not create a directory.
- **An `asf doctor` `record` row**: current, behind, dirty, off-trunk or diverged, with the command
  that fixes each. Not required — it prints the finding and leaves `asf doctor`'s exit code alone.
- **The guide stops telling the operator to pull**: `operating.md`'s opening and its groom step, and
  `product-config.md`'s *The two copies of the record*, say what the factory does, what the table
  says when it could not, and what the operator's own writes still need.

### Out

- **Fast-forwarding the checkout at *read* time.** It would make every table a writer and put a
  `git fetch` in front of every `/asf:*` call. The tick owns the fast-forward; a table reads and
  reports (D3).
- **Making the tables read the clone unconditionally.** The checkout is the copy the operator can
  `git log`, `asf set` and hand-edit; the clone is reset hard to origin on every tick. Reading it
  only when it is provably fresher keeps one copy canonical and the fallback rare and named (D2).
- **`asf brief`'s index, and the brief preamble's card reads.** `briefs.build._load_index` and
  `preamble.card_path`/`card_sections` read `backlog_dir` too — a brief quoting a stale card is the
  same bug class with a worse consequence. They read *card files*, not the derived index, so P1's
  argument does not cover them and the fallback here must not be extended to them. Hardening the
  tick's fast-forward (S-33450) is what improves them, and it does so without touching their code;
  the residue is its own card.
- **The three absolute `generated` stamps** in `backlog`'s footer and `roadmap`'s and `parity`'s
  headers (P7). *When* it was generated and *how long ago* answer different questions, and the
  three lines are pinned by existing tests; the card asks for the age on the `record:` line, and
  that is where it goes.
- **`asf status`'s `Stale` row.** It answers "is the tick running" off a host-local file that
  survives a failed push (P8), which is a different question from "is this the freshest copy". It
  is not touched.
- **A new config key.** The fallback is on, and `ASF_RECORD=checkout` pins the old behaviour for a
  test or an operator debugging one read. A product-config knob would be a second place for two
  copies of the truth to be configured apart (D7).
- **Moving `resolve_record` out of `cli.py`.** B-0050 pinned one resolver for every command;
  `freshness` calls it rather than re-deriving the root (D8).
- **Anything that reaches the network on a read.** The tables' path runs no `git` at all.

## The design

### `asf/views/freshness.py` — which copy, and how old

```python
"""asf.views.freshness — which copy of the record a table reads, and how old its index is.

The record exists twice: the operator's checkout (``backlog_dir``), which they write and the
tables read, and the tick's clone under the product's state directory, which the tick derives in
and pushes from (:mod:`asf.tick.shadow`). The tick fast-forwards the checkout when it can, and
says so when it cannot — a dirty tree, a branch that is not the trunk. That refusal used to leave
every table reading a stale copy with nothing on the table to say so (F-0122).

So: a table reads the checkout unless the clone's ``index.json`` was generated *later*, and its
first line always carries the index's age, naming the copy and the operator's lag when it took
the clone. Two file reads, no git, no network — safe to run in front of every table.

Every file a table reads under the record root is tick-derived — ``index.json``,
``metrics/sessions/<day>.jsonl``, ``groom/<date>-digest.md`` — and no table reads a card, which is
why reading the clone cannot hide an operator's own edit (F-0122, D4).

``ASF_RECORD=checkout`` pins the checkout, for a test or an operator debugging one read.
"""
```

The picked copy, as data:

```python
#: What :func:`pick` decided. ``source`` is ``'checkout'`` or ``'clone'``; ``older_s`` is how many
#: seconds behind the clone's index the checkout's own is, and is None unless ``source`` is
#: ``'clone'``.
Fresh = collections.namedtuple('Fresh', 'root source generated age_s checkout older_s')


def generated_at(root):
    """``index.json``'s ``generated`` as an aware datetime, or None — a missing, unreadable or
    unstamped index is not an error here, it is simply not a candidate."""


def clone_index_root(root, product):
    """The tick's clone, when it is a candidate for ``root``: ``root`` must *be* this product's
    own record checkout (D5), and the clone must already hold an ``index.json`` — a host that has
    never ticked has no clone, and asking where it would be must not create one (D14)."""
    if product is None or not product.backlog_dir:
        return None
    if os.path.realpath(root) != os.path.realpath(product.backlog_dir):
        return None
    path = os.path.join(env.state_path(product), 'record')
    return path if os.path.isfile(os.path.join(path, 'index.json')) else None


def pick(root, product=None):
    """:class:`Fresh` for the copy a table should read: ``root``, unless the tick's clone holds a
    strictly newer index. A tie goes to the checkout — it is the copy the operator can `git log`."""
```

The line every table opens with, in one place:

```python
def line(fresh):
    """``record: <path> — index generated 3m ago``, and when the clone was taken:

    ``record: <clone> (the tick's clone) — index generated 3m ago; your checkout <path> is 2h
    older — git -C <path> pull``

    An index with no readable ``generated`` says ``index age unknown`` rather than a made-up
    number. The ages are ``index_reader.span``'s buckets, the same ones every other table uses."""


def view_record(args, announce=print):
    """The root a *table* reads, announced. ``resolve_record`` decides which record (B-0050,
    D8) — this adds which copy of it, and prints :func:`line` instead of the bare path."""
    from asf.cli import resolve_record
    root = resolve_record(args, announce=lambda _l: None)
    try:
        product = env.load_product(getattr(args, 'product', None))
    except env.ConfigError:
        product = None       # a cwd-resolved record with no product: no clone to consider
    fresh = pick(root, product)
    announce(line(fresh))
    return fresh.root
```

## Records

- **The `record:` line**, on every table's stdout (stderr under `--json`), written by
  `freshness.line` and by nothing else: the path of the copy read, the index's age, and — only
  when the clone was taken — the copy's name, the checkout's lag and the `git -C <path> pull` that
  ends it. It is the one place an operator learns there are two copies.
- **The tick log** gains one line per tick: `record: <path> fast-forwarded to origin/<trunk>` when
  the checkout moved; the existing `record: <path> not fast-forwarded — <why>` when it did not;
  nothing when it was already current. Printed by `shadow.sync_operator_checkout`, through
  `tick.sync_checkout`, once per tick.
- **The `record` doctor row** — `record  ok  current — index generated 3m ago`, or `record  skip
  <why, and the command>`. It never changes `asf doctor`'s exit code.
- **Nothing new on disk.** No state file, no metrics event, no record card, no config key. The one
  write this change makes is the fast-forward of the operator's checkout, which the tick already
  performed (P2) and which is `--ff-only` — it can create no commit and lose no work.
- **One side effect removed**: asking where the tick's clone is no longer creates
  `~/.ASF/state/<product>/` (`env.state_path`, D14).
- **The guide**: `docs/guide/operating.md`'s opening and its groom step; `docs/guide/product-config.md`'s
  *The two copies of the record*, including the two example `record:` lines and `ASF_RECORD`.
- **No migration.** A product whose checkout is already current, and a host with no clone yet, read
  exactly what they read today — with an age on the line.
