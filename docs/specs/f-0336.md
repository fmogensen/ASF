# F-0336 — the same red, on three changes that share nothing

Three open pull requests, three unrelated changes, one flaky test. The kernel today judges each
red on its own pull request and reaches the same verdict three times over — and the verdict is
never "a flake", because nothing in the kernel compares one head's red with another's. Measured
on the shipped `decide` (P4), those three heads become three Stuck items:

```
T-1: stuck — red off the PR after 1 rerun(s): tests (3.12)
T-2: stuck — red off the PR after 1 rerun(s): tests (3.12)
T-3: stuck — red off the PR after 1 rerun(s): tests (3.12)
```

and when the failed log was not read — the common case, since one tick reads at most ten failed
logs (`ports.py:1086`) — the same red reads as *the pull request's own* (`decide.on_pr`:
"none are known" is on the PR) and buys each item a fix round instead, two of them per item
before it is Stuck (P4b). Either way the cost is per head and the knowledge is nowhere: no row
says that one failure signature is standing on three changes at once.

The factory does have a quarantine, and it is good: `asf.flake` keeps per-job entries that the
harvest lane, the merge queue and `asf status` all already read (`flake.active`,
`views/status.py:915`). But its one door is a **green re-run on the same sha** (`flake.settle`,
P2) — a single head's evidence, read twice. The kernel never opens that door at all: its only
import from `asf.flake` is `INFRA_SIGNATURES`, in `mainline` (P2).

So the two halves fit: the correlation across heads is a fact only the kernel holds, once a tick,
and the quarantine it should write is one the factory already reads. This spec is that join —
**a failure signature red on `sources_min` unrelated heads inside `window_h` becomes a quarantine
entry, capped at `max_h`, plus one Bug a fix session can start on; a signature whose sources share
a changed file is a defect, and the kernel's ordinary red path keeps it.**

### In

1. **`asf/kernel/flake.py`** — a new pure module: the failure signature of a red check, the
   sightings of one tick, the window over the sightings the state file kept, the verdict
   (`watch` / `defect` / `main` / `flake`), and the actions and record lines a flake verdict
   produces. Facts and config in; actions and records out. No disk, no clock, no network.
2. **The two reads and the two writes** the judge needs: the sightings and the live quarantine
   entries read into `Facts` before `decide` (`loop.read_flakes`, beside `read_waits`), this
   tick's sightings appended after `apply` (`loop.measure_flakes`, beside `measure_waits`), and
   the entry itself written through the record port (`A.Quarantine`).
3. **The quarantine entry**, written into `state/<product>/flake-triage.json`'s own
   `quarantine` list, in the shape `asf.flake.active` and `asf.flake.status_cell` already read
   (P7), carrying `where: kernel`, its signature, its sources and the Bug that owns it.
4. **The cap**: an entry's `expires` is set once, at `first + max_h`, and no later sighting moves
   it; once it has expired and the Bug it filed is still open, that signature gets no second
   entry — the red is the heads' again.
5. **One Bug per flake cycle, startable as filed**: `A.FileBug` and `record.file_bug` gain the
   fields the Definition of Ready and intake read (`acceptance`, `writes`, `signature`,
   `severity`, `decided`), so `dor.missing` is empty and `intake.undecided` is False the moment
   the card lands (P5).
6. **The defect check**: the sources' changed files are intersected, and a non-empty intersection
   is the card's "defect, not a flake" — no entry, no Bug, the kernel's ordinary red path keeps
   the reds, and one record line says which file they share.
7. **The trunk check**: a signature the trunk's own newest commits are red on is main's red, never
   a flake — `mainline` owns it and already has a verdict for it (D5).
8. **A quarantined red never spends a fix round**: `decide._judge_pr` reads the live entries
   (`decide.quarantined`), so a quarantined signature's red takes the shipped off-PR path (rerun,
   then `Stuck(owner=ci)`, then the escalation's one more rerun) and leaves a note naming the Bug.
9. **The knobs**, with their documented defaults and every registration a kernel key needs:
   `kernel.flake` in `settings.SPEC` and its module block, the `Config` fields, `config_for`, and
   the block in `docs/products.example.yaml`. Off by default.
10. **The record of a tick**: `Plan.flakes`, one `FLAKE <sig> -> <action>` line per judged
    signature, and the tick's `flakes: N watched, M quarantined` summary line.

### Out

* **Re-running anything to prove a flake.** The evidence is correlation across heads, not a
  second run of one head; `asf.flake.triage`'s re-run path is untouched and still the floor's
  (D1).
* **The floor's seven-day job quarantine.** `settle`, `triage`, `infra_rerun` and
  `ci.quarantine_days` keep their behaviour exactly; the kernel's entries live beside them in the
  same list, told apart by `where: kernel` and their own cap (D8).
* **Fixing the flake.** The Bug is the fix session's; nothing here edits a test, skips one or
  marks one as expected to fail.
* **Dropping a quarantined check from the landing gate.** The required checks are GitHub's and
  stay GitHub's: a quarantined red still blocks the merge. The quarantine spends no sessions on
  it; it does not pretend it is green (D7).
* **A signature nothing was read off.** A red whose failed log yielded neither a failing case nor
  a test file has no signature: it is never counted, never quarantined, never filed (D3).
* **Products whose test paths `dor.test_refs` does not recognise.** It reads `*.py` paths and
  dotted Python modules only, so on a product with JavaScript tests the filled Bug still fails
  the Definition of Ready's test clause and a groom-fill fills it. Widening `test_refs` is not
  this card's (it is the record's grammar, read by every card).
* **Merge-queue batch reds and trunk reds as sources.** Only an open pull request's head counts
  as a source: those are the heads the kernel reads every tick, and "unrelated" is a statement
  about two changes, which a batch sha does not identify (D4).
* **A second Bug while the first is open**, and any editing of the open one. A repeat inside a
  cycle adds a source to the entry, not a line to the card; the groom's `add_evidence` path for
  repeats of one symptom class stays as it is.

### Preconditions the work depends on

1. `Facts.prs` carries, for every open pull request, its changed `files` and its head's checks
   with `failing_files`, `failed_step`, `log_tail`, `attempt` and `run_id`
   (`model.py:Check`/`PR`) — all of it read once a tick through the GitHub port.
2. At most ten failed logs are read per tick (`RealGitHub.LOG_LIMIT` = 10) and a slowed tick
   reads none, so `failing_files` and `log_tail` are empty for some reds. The design must count
   what it has and never assume a signature reads (D3).
3. `Facts.now` is the tick's time as ISO-8601 UTC, and `Facts.main` carries the trunk's newest
   commits with their checks — both already read for `waits` and `mainline`.
4. `Facts.trunk_files` is the trunk's path list (None when unread) — what the Definition of Ready
   checks a `writes:` against, so the filled Bug can be checked against the same fact that will
   judge it.
5. `Facts.items` carries each Bug's `signature` and `severity`, so the open-Bug lookup needs no
   new read.
6. `asf.feeder.widen.is_test_path` is the one owner of "is this path a test", and
   `asf.harvest.regression.failing_cases` of "which cases does this log say failed" — both pure,
   both shipped (`regression.py` landed at `55d9ec2f1`).
7. The record port holds `state_dir` and already writes a ledger there (`record_review`), so the
   entry write needs no new port.
8. `asf.flake.save` is atomic (`tmp` + `os.replace`) and `asf.flake.load` tolerates an absent or
   unparsable file by returning empty blocks.

### The choices

| # | Chosen | Against | Why |
|---|---|---|---|
| D1 | Correlation across heads is the evidence | A second run of the same head, as `settle` does | The per-sha re-run is the floor's and stays; it cannot see three heads, and the kernel cannot see a re-run it never asked for. Two different facts, two owners |
| D2 | The sightings live in `flake-triage.json`, beside the quarantine | A new `kernel-flakes.jsonl` ledger beside `kernel-waits.jsonl` | One file for all flake state, one atomic write, and pruning where pruning already is (`load`). The cost is one addition to `load` (P3), which is cheaper than a second file with its own reader, prune and failure mode |
| D3 | A red with no readable key is no signature | Falling back to the job name alone | Ten logs a tick (precondition 2) means job-only signatures would be the common case, and three unrelated heads red in one job with nothing read is exactly what a broken base branch looks like. A coarse key would quarantine on no evidence; no key means no verdict |
| D4 | A source is an open pull request (counted by number) | A head sha, or any red the factory sees | Two sightings on one pull request are one change, however many times it was pushed; and "unrelated" is a claim about two changes' files, which only a pull request gives us (its `files`) |
| D5 | A signature the trunk is red on is never a flake | Counting it like any other red | Otherwise the first broken base branch quarantines the test that caught it and files a Bug against a flake that is not one — the exact failure the card's defect check exists to prevent, in its other form. `mainline` already decides a red trunk; this one defers to it and says so |
| D6 | The sources' **intersection** is the defect test | Dropping any source that shares a file with any other, then counting | The card's words are "a signature whose sources share a changed file is a defect": a file every source changes is a cause they have in common. Pairwise collapsing is an independent-set problem over the sources, and its answer on three heads is not more trustworthy — only harder to explain in a record line |
| D7 | A quarantined red still blocks the landing | Dropping the check from `required_checks` while quarantined | The gate is GitHub's, and a kernel that lands on a red required check has broken the one invariant the whole factory rests on. The quarantine buys back sessions, not merges |
| D8 | The kernel's entry caps at `max_h` (48 h default), not `ci.quarantine_days` (7 d) | Reusing the floor's 7-day expiry | The floor's entry only re-runs a job; this one also stops fix rounds, which is a stronger silence. Two days is a fix session's reach; a week is how a real break hides |
| D9 | The Bug is filled as it is filed | Letting the Definition of Ready hold it and a groom-fill fill it | The kernel knows the test, the case and the files at the moment it files (P5); a groom-fill session to recover them is a seat spent re-deriving what was in hand. `decided: true` and a `signature:` likewise save intake a session each |
| D10 | One cycle, one Bug; the key carries the cycle's start | One Bug per signature forever | `file_bug` returns the existing id for any card carrying the key, so a key without the cycle could never file a second Bug — a flake that returns after its fix landed would have no owner. The card's `signature:` still folds every cycle into one symptom class for the groom |
| D11 | The cap is counted from the `first` the Bug's own marker line names | Counting it from the live entry alone | The entry is pruned the moment it expires, so an entry-only cap forgets it was ever spent and re-quarantines in an unbounded chain of `max_h` slices — a seven-day silence with extra steps. The card outlives the entry and already carries the cycle's start (D10), so one read of it closes the hole |
| D12 | The verdict is recorded even when it is not a flake | Recording only the flakes | A `defect` line naming the shared file, and a `main` line naming the sha, are the two answers an operator will ask the tick for. A silent "not a flake" is indistinguishable from a rule that never ran |
| D13 | Off by default (`kernel.flake.enabled: false`) | On, like `intake` | It files cards and changes how a red is judged. A product turns it on when its operator has read what it does — `dor`'s precedent, and the bare `Config()` default so a unit test opts in |
| D14 | `judge` is pure, and the tick writes | A module that reads the state file itself | Every rule the kernel has is a pure function over `Facts` (`mainline`, `needed`, `dor`, `intake`), tested by building a world. The two writes are a port call and a loop step, both already patterned |

## The design

Twelve files: one new module, one new test module, seven kernel files, `asf/flake.py`,
`tests/test_flake_triage.py` and the documented product block. Nothing outside `asf/kernel/`,
`asf/flake.py`, `docs/` and `tests/`.

### 1. `asf/kernel/flake.py` — the judge (new)

Pure, in the shape of `asf.kernel.mainline`: facts and config in, `(actions, records)` out.

```python
"""asf.kernel.flake — one failure signature on several unrelated heads (ASF 0.2).

A required check red on an open pull request's head is read every tick. Its *signature* is what
the failed log named, not which head it was on, so the same signature on several heads is one
failure standing on several changes. Three such heads (``config.flake_sources_min``) inside
``config.flake_window_h``, **sharing no changed file**, is a flake: a quarantine entry capped at
``config.flake_max_h`` and one Bug for a fix session. Sources that share a changed file are a
defect and keep the kernel's ordinary red path; so is a signature the trunk itself is red on
(:mod:`asf.kernel.mainline` owns that one).

Pure: no disk, no clock, no network. The sightings and the live entries are read into
``Facts.flake_seen`` / ``Facts.quarantine`` before ``decide`` (:func:`asf.kernel.loop.read_flakes`)
and this tick's sightings are appended after it (:func:`asf.kernel.loop.measure_flakes`).
"""
```

**1.1 The signature.** One function, one grammar:

```python
#: a signature's parts, in its text: ``<job> / <step>: <key>``
SIG = '%s / %s: %s'
#: the Bug card's ``signature:`` field, and so its symptom class (asf.groom.inbox.symptom_class)
CARD_SIG = 'flake %s'


def signature(check):
    """The failure signature of red ``check``: ``<job> / <step>: <key>``, or '' when the log
    named nothing to key on (D3). ``job`` is :func:`asf.flake.job_key` of its name (a matrix leg
    counts as its job), ``step`` its ``failed_step`` ('-' when unread), and ``key`` the first
    failing case :func:`asf.harvest.regression.failing_cases` reads off ``log_tail``, else the
    first test file among ``failing_files`` (:func:`asf.feeder.widen.is_test_path`)."""
```

* A case name is preferred over a file: it is what a flake is, and two heads failing *different*
  cases of one file are two signatures, not two sources of one.
* A head whose log yielded a case and another whose log yielded only the file are two signatures,
  so each counts one source short. The error is toward "not a flake", which is the safe side (and
  a tick that reads one head's log reads the others' too — the cap is per tick, not per head).
* `test_files(check)` is the small companion: the entries of `failing_files` that
  `widen.is_test_path` accepts, sorted. It names the Bug's `writes:` (§3).

**1.2 The sightings of one tick, and the window.**

```python
def rows(facts, config):
    """One sighting per red required check on an open pull request's head whose signature reads:
    ``{sig, item, pr, head, check, step, files, at}`` — ``files`` the pull request's own changed
    files, ``at`` ``facts.now``. A check that is not required, a merged pull request and a
    signature-less red are left out. Pure."""


def seen(facts, config):
    """``{sig: [sighting]}`` over ``config.flake_window_h``: the rows the state file kept
    (``facts.flake_seen``) and this tick's (:func:`rows`), deduplicated on
    ``(sig, pr, head)`` keeping the oldest ``at``, each list oldest first. A row older than the
    window, and one whose pull request is no longer open, is dropped."""
```

This tick's reds are counted from the facts, not from the ledger, so detection never lags the
tick that completes the evidence; the ledger is what carries a sighting from one tick to the next.

**1.3 The verdict.**

```python
#: the verdicts of one signature
VERDICTS = ('watch', 'defect', 'main', 'flake')


def sources(sightings):
    """The sightings of one signature, one per pull request (the oldest of each), by number."""


def shared(srcs):
    """The changed files every source of ``srcs`` has in common, sorted ([] when none do)."""


def on_main(sig, facts, config):
    """The sha of the newest trunk commit (``facts.main``) a check with signature ``sig`` is red
    on, or '' when none is: that red is the trunk's, never a flake (D5)."""


def verdict(sig, srcs, facts, config):
    """``(verdict, why)`` of one signature: ``watch`` under ``config.flake_sources_min``
    sources; ``defect`` when :func:`shared` is non-empty; ``main`` when :func:`on_main` names a
    sha; else ``flake``."""
```

The order is the card's own: count, then the defect check, then the trunk. A `defect` is reported
with the file the sources share, a `main` with the sha, a `watch` with how many sources it has.

**1.4 What a verdict does.**

```python
def live(sig, facts):
    """The live quarantine entry of ``sig`` (``facts.quarantine``), or None."""


def cycle(sig, facts):
    """``(bug id, first)`` of ``sig``'s own open flake cycle: the open Bug (not Done) whose
    ``signature:`` is of ``sig``'s symptom class (:func:`asf.groom.inbox.symptom_class` over
    :data:`CARD_SIG`) **and** whose body carries this signature's marker line, with the ``first``
    that line names. ``('', '')`` when none is open."""


def owned(sig, facts):
    """The id of an open Bug of ``sig``'s symptom class that is **not** this signature's own
    cycle (one the floor's flaky filer or an operator wrote), or '' when none is: the symptom
    already has an owner, so the kernel neither files a second card nor silences the red."""


def entry(sig, srcs, facts, config, first='', bug=''):
    """The :class:`asf.kernel.actions.Quarantine` of ``sig``: its job, check, step, test files,
    one row per source (``pr``, ``head``, ``item``, ``at``), ``first`` (the cycle's start —
    ``facts.now`` for a new one, the live entry's for a refresh) and ``expires`` =
    ``first`` + ``config.flake_max_h``, computed once and never moved (D11)."""


def bug_action(sig, srcs, facts, config):
    """The :class:`asf.kernel.actions.FileBug` of a new flake cycle — see §3 for its fields."""


def judge(facts, config):
    """``(actions, records)`` of this tick's flake rule over ``facts``; ``([], [])`` while
    ``config.flake`` is off. One record per judged signature: ``{'sig', 'verdict', 'action'}``,
    logged ``FLAKE <sig> -> <action>``."""
```

`judge` walks the signatures of `seen` in sorted order and, for each:

1. **a live entry** — refresh it with the sources it does not hold yet (`A.Quarantine` carrying
   the entry's own `first` and `expires`); record `quarantined until <expiry>, <n> head(s)`.
   Nothing else: no second Bug, no moved expiry.
2. **`flake`, no live entry, the symptom already owned** (`owned`) — nothing, recorded
   `waits on <bug>: its symptom class is already owned`. The kernel's bookkeeping is its own
   cycles; a card someone else filed is not one, and duplicating it would be the second card
   this rule exists to avoid.
3. **`flake`, no live entry, its own cycle open** (`cycle`) — the cap decides, from the `first`
   the card's own marker names, never from a clock the state file lost:
   * `first + max_h` is past: nothing, recorded `capped: <max_h>h spent, waits on <bug>` (D11).
     The red is the heads' again until the Bug lands.
   * it is not past (the entry was lost early — a cleared state directory): `A.Quarantine` for
     the remainder, carrying that same `first` and no new Bug; recorded `quarantined until
     <expiry>, bug <bug> already open`.
4. **`flake`, no live entry, no Bug at all** — `A.FileBug` (§3) and `A.Quarantine` with
   `first = facts.now`; recorded `quarantined <max_h>h on <n> unrelated head(s), bug <key>`.
5. **`defect`** — nothing, recorded `defect: <n> head(s) all change <file>`.
6. **`main`** — nothing, recorded `main's red at <sha>: mainline decides it`.
7. **`watch`** — nothing, and **no record**: a signature with one or two sources is the ordinary
   state of a busy repo, and a line per tick per red would drown the tick.

The flake Bug's fields, from the facts the judge already holds:

| field | value |
|---|---|
| `key` (the body's marker line) | `flake: <sig> since <first>` — one Bug per cycle (D10) |
| `title` | `flaky CI: <key part of the signature> (<job> / <step>)`, cut to 120 characters as `asf.tick.flaky.bug_title` cuts its own |
| `signature:` | `flake <sig>` — its symptom class folds every cycle and every instance token into one family (P7) |
| `severity:` | `S2` — it costs seats and blocks a landing, and it is not a stop |
| `decided: true` | the kernel decided it when it filed it; intake spends no session (P5) |

### 4. `asf/kernel/decide.py` — where the judge plugs in, and the red that stops costing

Three edits, all small:

1. `ORDER` gains `A.Quarantine`, right after `A.FileBug` — the Bug is filed before the entry that

2. `decide` calls the judge where it calls `mainline`'s, and carries its records:

3. The quarantined red:


### 5. `asf/kernel/apply.py` and `asf/kernel/ports.py` — the two writes

## Records

No branch is touched, no event is emitted, no metrics row is appended, and no file is created
outside the new module, the new test module and the documented block. What a tick writes:

| What | Where | What changes |
|---|---|---|
| the sightings | `state/<product>/flake-triage.json`, a new `sightings` block | **New shape**, in a file that already holds four blocks and prunes each on read. | the tick's log | stdout, the tick's own lines | **New lines**: one `FLAKE <sig> -> <action>` per record, and one `flakes: N watched, M quarantined` summary line |

| the required checks | GitHub's rules | **Untouched.** A quarantined red still blocks the merge (D7) |
| the fix rounds | the card's `kernel_fix_rounds` | **Not spent** on a quarantined red: the round that would have been written is not written (D7, §4.3) |
| the floor's triage state | `reruns`, `reds`, `infra` | **Untouched.** No re-run is asked for, no attempt counted, and `settle`/`triage`/`infra_rerun` read and write them exactly as today |

NEEDS OPERATOR: none. Every figure above was measured from this checkout, the three defaults are
this spec's to choose (D8, D13) and the knob ships off, so no product changes behaviour until its
operator turns it on.

## Stories

Six Stories, one per part of the rule: the signature and its window, the verdict, the entry, the
cap, the Bug, and the knobs with the fix round the quarantine saves. Each is **declared** below
as a `### S-…: <title>` heading with its acceptance lines under it, with ids from this session's
range `S:122805-122854` — that heading is what `asf.record.idcheck.declared_stories` reads and
what `asf.record.plan_tasks` mints the card from, so a cited id with no declaration is a phantom
and the plan citing it is refused whole.

Each acceptance line is one physical line of plain text with no backticks, on purpose: the reader
is line-anchored (`asf.record.idcheck.CHECKBOX` matches a single line) and `_prose` replaces every
inline code span with one space before parsing, so a wrapped line reaches the minted card
truncated and an identifier inside backticks reaches it missing.

Nothing below is true on the trunk today — P1 measures that the module, the fields and the knobs
do not exist — except the lines that say an existing behaviour is unchanged, which are the facts
this change relies on rather than adds.

### S-122805: the failure signature of a red check, and the window of unrelated heads it was seen on

Design §1.1 and §1.2 (D3, D4; preconditions 2 and 6). Acceptance is the first fenced block of
`## Acceptance tests`. The signature is what the log named, the sighting is which head it was
named on, and the window is both halves joined: what the state file kept plus what this tick
reads, counted once per pull request.

- [ ] a red check whose log tail names a failing case has that case as its signature key
- [ ] a red check whose log tail names no case takes its first test file as the signature key
- [ ] a red check whose failing files hold no test file and whose log tail names no case has no signature at all
- [ ] a signature carries the job name, the failed step and the key, and a matrix leg counts as its job
- [ ] a red check with no failed step read still has a signature, with a placeholder for the step
- [ ] two heads failing different cases of one test file are two signatures
- [ ] only the test files among a check's failing files become the signature's test files
- [ ] one tick's sightings hold one row per red required check on an open pull request's head
- [ ] a red on a check that is not required is no sighting
- [ ] a red on a merged pull request is no sighting
- [ ] a sighting carries the pull request, its head, its item, the check, the step, the pull request's changed files and the tick's time
- [ ] the window holds this tick's sightings without the state file having been written first
- [ ] a kept sighting older than the window is not counted
- [ ] a kept sighting whose pull request is no longer open is not counted
- [ ] two sightings of one signature on one pull request at two heads count as one source
- [ ] a source's time is the oldest sighting of that signature on that pull request
- [ ] the signatures of a window come back in sorted order, and each source list oldest first

### S-122806: one verdict per signature — a flake, a shared-file defect, or the trunk's own red

Design §1.3 (D5, D6, D12). Acceptance is the second fenced block. One signature, one verdict,
from a closed vocabulary, decided in the card's own order: count, then the shared file, then the
trunk.

- [ ] a signature with fewer sources than the configured minimum is watched, and its count is in the reason
- [ ] a signature with the minimum number of sources sharing no changed file is a flake
- [ ] a signature with more than the minimum number of sources sharing no changed file is a flake
- [ ] a signature whose sources all change one file in common is a defect, and the verdict names that file
- [ ] a signature whose sources share two files is a defect, and the verdict names both in sorted order
- [ ] a signature where only two of three sources share a file is a flake, because the third shares nothing
- [ ] a signature whose sources' changed files are unread is a flake on the count alone
- [ ] a signature a trunk commit is red on is the trunk's red, and the verdict names that commit
- [ ] a signature red on the trunk and on sources that share a file is reported as a defect, the shared file first
- [ ] the verdict vocabulary is closed, and every verdict the judge returns is one of its four names
- [ ] a watched signature produces no action and no record line
- [ ] a defect produces a record line and no action
- [ ] a trunk red produces a record line and no action
- [ ] the judge returns nothing at all while the knob is off

### S-122807: the quarantine entry, written where the lane and the status row already read it

Design §1.4, §5 and §6 (D2, D14; preconditions 7 and 8). Acceptance is the third fenced block.
The entry is the floor's own shape with the kernel's provenance beside it, and the sightings it
was decided from survive a floor write of the same file.

- [ ] a flake verdict with no live entry produces one quarantine action
- [ ] the action carries the signature, the job, the check, the step, the test files and one row per source
- [ ] the action's expiry is its first sighting plus the configured cap
- [ ] the applied entry is found by the lane's own live-entry lookup for that check
- [ ] the applied entry renders in the status row with its head count and its Bug
- [ ] the applied entry carries the kernel as its origin, so a floor entry and a kernel entry are told apart
- [ ] applying the same plan twice leaves one entry, not two
- [ ] a second tick with a new source refreshes the live entry's sources
- [ ] a refresh never rewrites the entry's first sighting or its expiry
- [ ] a refresh records that the signature is already quarantined, and files no second Bug
- [ ] a sighting block written by the kernel survives a floor write of the same state file
- [ ] a sighting block prunes rows past its age limit and never grows past its row cap
- [ ] a state directory that cannot be written leaves the tick green and the plan unchanged
- [ ] an unreadable state file leaves no sighting and no live entry, and every red is judged as before
- [ ] the entry read back by the next tick's facts is the entry that was written

### S-122808: the cap — one entry's life is set at its first sighting and never extended

Design §1.4 steps 1 and 2 (D8, D11). Acceptance is the fourth fenced block. The cap is what keeps
a flake quarantine from becoming a week of silence over a real break.

- [ ] an entry expires at its first sighting plus the configured cap, in hours
- [ ] a sighting inside a live entry's life never moves its expiry
- [ ] a signature whose entry has expired is no longer quarantined, and the lane's lookup no longer finds it
- [ ] a signature whose own Bug is still open and whose cap is spent gets no second entry
- [ ] the cap is counted from the start the open Bug names, not from the entry the state file lost
- [ ] a signature whose own Bug is open and whose entry was lost before its cap is quarantined for the remainder, with no new card
- [ ] that signature's record line says the cap is spent and names the Bug it waits on
- [ ] a red of a signature whose cap is spent is the pull request's own again
- [ ] a signature whose Bug is Done and whose sources reappear starts a fresh cycle with a fresh expiry
- [ ] a fresh cycle after a Done Bug files a new Bug, because its key carries the cycle's start
- [ ] the cap is read from the configuration, and a product that sets a different one gets it
- [ ] a cap of zero quarantines nothing and files nothing

### S-122809: one Bug per flake cycle, startable and decided as it is filed

Design §3 and §5 (D9, D10; preconditions 4 and 5). Acceptance is the fifth fenced block. The
kernel knows the test, the case and the files when it files; the card it writes carries all three,
so no session is spent recovering them.

- [ ] a flake verdict with no open Bug of its class files one Bug
- [ ] the filed card names a test in its acceptance, so the Definition of Ready finds no gap
- [ ] the filed card's writes are the signature's test files
- [ ] a test file that is not on the trunk is left out of the writes
- [ ] the writes hold every one of the signature's test files when the trunk file list is unread
- [ ] the filed card carries a signature field, and its symptom class folds the instance tokens away
- [ ] the filed card carries a severity and is marked decided, so intake asks nothing about it
- [ ] the filed card's body lists each source with its pull request, head, item, time and changed files
- [ ] the filed card's body carries the marker line that keeps it filed once
- [ ] the filed card's title names the failing case, the job and the step, and is cut to the record's title limit
- [ ] the filed card's rank is the lowest rank on the record, so a main-red Bug still outranks it
- [ ] a second tick of the same cycle files no second Bug
- [ ] a signature whose symptom class another filer's open Bug owns is recorded as owned, and is neither quarantined nor filed again
- [ ] an open Bug of the class that carries no marker line for this signature is not read as this signature's own cycle
- [ ] the quarantine entry written beside a Bug records that Bug's id
- [ ] a Bug whose filing failed leaves the entry with no id, and the next tick fills it
- [ ] a caller that passes none of the new fields writes exactly the card it writes today

### S-122810: the knobs, the tick's record, and a quarantined red that spends no fix round

Design §2, §4, §7 and §8 (D7, D13; P1 and P6). Acceptance is the sixth fenced block. The rule is
off until a product turns it on, every judged signature leaves a line, and the one thing the

- [ ] the knob is off in the bare configuration, so a unit test opts in
- [ ] the four keys are in the kernel settings with the documented defaults

- [ ] an unknown key under the block is a warning, not an error

- [ ] the tick logs one line per record and one summary line naming how many are watched and quarantined
