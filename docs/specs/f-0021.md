# F-0021 — the launch: four artefacts a stranger can read, run and check

The card, as the requirement: *the README as a one-page argument plus a twenty-minute quickstart on
the sample product; the 0.1 release; a public eval scorecard; and this record's roadmap page as the
demo.* Its acceptance is the phase's: *the phase's deliverable exists and the next phase can start
from it.*

Four artefacts, one audience: a stranger who has never seen this repository and owes it nothing.
The argument tells them why a factory is worth their twenty minutes; the quickstart spends those
twenty minutes and ends with a tick that ran; the scorecard lets them check the argument's numbers
instead of believing them; the roadmap page shows the factory's own work being done by the
mechanism the argument describes. A launch is not an announcement — it is the moment those four
stop being claims.

The state on 2026-09-27 is that three of the four have machinery and no content:

- `asf/views/readme.py` (F-0030) carries the span grammar, the facts builder, the renderer and the
  five checks, and its `HEADINGS` already names the three parts the page must have. The committed
  `README.md` has **none of them**: thirty-four lines, one `## Install` heading, no span, and no
  facts file (`docs/readme-numbers.json` does not exist). Because `readme.check` returns `None` for
  a page with no span, the whole instrument is **inert against the real page** — it passes today by
  not being pointed at anything.
- The README names `rules/` and `evals/` as directories of this repository. Neither exists in this
  checkout. That was true when F-0030 was specified and it is still true: a reader who runs `ls`
  learns in one second that the page cannot be trusted.
- `asf release-readiness` (`asf/release.py`) computes eight criteria for a framework release, and
  criterion 7 requires the trunk's README to carry the sections `Install`, `Quick start`,
  `Configuration`, `Upgrade`. Today the page has one of the four, so the gate that decides whether
   0.1 may ship is red on a heading.
- `asf roadmap` and `asf scorecard` render tables to a terminal. Nothing writes either one into the
  record, so "the record is the demo" is a sentence in the README, not a page anyone can open.

So the work is not new data paths. It is: write the page in the shape the code already checks, make
the quickstart a thing that runs rather than a thing that is described, publish the two views the
record already has the numbers for, and cut 0.1 on the gate's reading rather than on an opinion.

## 1. Decisions

### 1.1 In

- **`README.md`, rewritten** into the three parts `asf/views/readme.py` already enforces —
  `## The argument`, `## The mental model`, `## The manual` — inside the existing 150-line /
  10,000-byte budget, with every measurement in an `asf:n` or `asf:block` span and no typed number
  in prose. The manual's four sub-headings are `### Install`, `### Quick start`,
  `### Configuration`, `### Upgrade`, which is what closes the release gate's docs criterion (D3).
- **`docs/readme-numbers.json`**, the committed facts file, written by `asf readme --refresh`.
- **The argument's claims table** (§2.2): four claims, each with the span or the link that supports
  it. A claim with neither is not written.
- **`tools/quickstart.sh`** — the twenty-minute quickstart, executable: it materialises `sample/`
  into a temp directory with bare origins and a temp `ASF_HOME`, then drives the real command line
  (`asf init`, one `asf tick`, `asf next`, `asf doctor`, `asf roadmap`, `asf scorecard`) and prints,
  at each step, the artefact the reader should open. It touches nothing outside its own temp
  directory and needs no account, no network and no `gh` (the sample product is `ci: none` and the
  `fake` worker runtime).
- **`tests/test_quickstart.py`** — runs `tools/quickstart.sh` end to end, asserts it exits 0, that
  the artefacts it names exist, and that it finishes inside the bound the page promises.
- **`asf pages [--product P] [--check] [--refresh]`** (`asf/views/pages.py`) — writes two pages into
  the record: `ROADMAP.md` (from `asf.views.roadmap.render`) and `SCORECARD.md` (from
  `asf.views.scorecard` plus `asf.release`), each with a generated-stamp header and, per number, the
  record path it was read from. `--check` reports drift and writes nothing.
- **A fourth part in the tick's daily step** (`asf/tick/step_daily.py`), so the two pages are
  refreshed once a day in the record clone and carried by the tick's own commit — the same path
  `stale`, `rollup` and `scorecard` already take.
- **`tests/test_record_pages.py`** — the two pages over a fixture record: the shape, the sources,
  the honest-zero line (D5), idempotence, and that `--check` is read-only.
- **The 0.1 release**: a `## v0.1` section in `CHANGELOG.md` holding the launch notes, plus
  `docs/release-0.1.md` — the readiness reading that justified it, criterion by criterion, with the
  evidence string `asf release-readiness` printed. The tag and the GitHub Release are cut by the
  machinery that already cuts them, on an all-met reading, as one operator step (D6, D7).
- **`release:` thresholds in `docs/products.example.yaml`** — the `blocking` and `requires` lists
  spelled out as an example, so an operator reading the example file sees what a release gate is
  made of.

### 1.2 Out

- **A frozen eval set (`evals/`), eval tasks, a set hash or an `ASF-Eval:` trailer.** Prompt evals
  need a live model and a seeded fixture repository and are 0.2
  (`docs/research/prior-art-prototype.md`, "skip in 0.1"). This card publishes the readings the
  factory already produces and says plainly, on the page, what it does not measure (D5). The
  README's two dead paths — `rules/` and `evals/` — go with the rewrite; nothing is created to make
  a sentence true.
- **The clean-clone CI job.** F-0033's card owns running the quickstart from a fresh clone. This
  card delivers the script and a test in `tests/`, which the existing suite step runs either way.
- **A new metrics stream, event or matcher.** Every number on every page comes from readers that
  exist: `asf.views.index_reader`, `asf.metrics.metrics`, `asf.views.scorecard`, `asf.release`.
- **Rewriting `docs/guide/` or `plugin/skills/`.** The three-surfaces rule stands: the README makes
  the argument, the skills give the procedure, `docs/` holds the specification. Where the README
  would explain a mechanism it links to the guide.
- **A new versioning scheme.** `asf.metrics.metrics.next_tag` already cuts `v<major>.<minor>.<patch>`
  from the roadmap's active versioned Epic; the 0.1 line is E-0001's. No tag is invented here (D6).
- **Any automatic write to the trunk.** The tick writes the record's pages, never this repository's
  README. Page drift is a Bug a session fixes on a branch (D8).
- **Pushing the tag, publishing the GitHub Release, or announcing anywhere.** One operator step,
  raised as `NEEDS OPERATOR`, because a release is an outward-facing act (D7).
- **A web UI, a landing page, a demo video.** The record is the demo; that is the card's own claim.

## 2. The design

### 2.1 The four artefacts

| # | Artefact | Where | Written by | Checked by |
| --- | --- | --- | --- | --- |
| 1 | The one-page argument | `README.md` + `docs/readme-numbers.json` (this repo) | a session, once; the spans by `asf readme --refresh` | `asf readme --check`, T1–T3 |
| 2 | The twenty-minute quickstart | `tools/quickstart.sh` (this repo), invoked from `### Quick start` | a session | `tests/test_quickstart.py`, T4–T5 |
| 3 | The public scorecard | `SCORECARD.md` (the record root) | `asf pages --refresh`, daily, by the tick | `asf pages --check`, T6–T7 |

| — | The 0.1 release | `CHANGELOG.md` `## v0.1`, `docs/release-0.1.md` (this repo); the tag and the GitHub Release | a session writes the notes; the operator cuts the release | `asf release-readiness`, T8 |

### 2.2 The README — one page, three parts

The page keeps its existing title and its "Not the Apache Software Foundation" line. Its structure:

```
# ASF — Autonomous Software Factory
  <one sentence: what it is>

## The argument
  the four claims (below), each with its span or its link
  <!--asf:block scoreboard-->  the measured table
  the two links that let a reader check it: the record's ROADMAP.md and SCORECARD.md

## The mental model
  one record, typed intent, derived state · rules as checks · code decides what runs when,
  agents only write and judge · multi-product from day one · the factory builds itself
  through the same mechanism it offers you
  <!--asf:block cost_per_feature-->  what a Feature has cost

## The manual
  ### Install        the pipx line and the installer, as the page already carries them
  ### Quick start    one fenced block: bash tools/quickstart.sh — and what it will print
  ### Configuration  the two files under the operator's home, linking the guide
  ### Upgrade        the installer at a new ref, linking the guide
  <!--asf:block commands-->  one row per subcommand, read from the parser
  the repository's layout — only directories that exist
  license, credit
```

The four `###` names are not decoration: they are what `asf release-readiness`'s docs criterion
looks for (D3, P7), and they are what a first-time reader looks for.

The four claims, and what each one stands on. A claim's support is a span (a number the build
wrote) or a link (a page a reader can open). Nothing else may be claimed (D11).

| Claim | Support |
| --- | --- |
| The factory has done real work, and here is how much | the `scoreboard` block: items, Features shipped, sessions, session hours, spend, spend per shipped Feature, CI runs, CI green, ticks — every cell sourced in the facts file |
| Its work is auditable by a stranger | links to the public record, its `ROADMAP.md` and its `SCORECARD.md` |
| It costs a known amount per Feature | the `cost_per_feature` block and the `usd_per_feature` span |
| You can run it on your own product in twenty minutes | `### Quick start`, which invokes `tools/quickstart.sh`, which a test runs |

Constraints the existing code imposes, and which the page must be written inside:

- Three `##` part headings, exactly those, in that order (`readme.HEADINGS`).
- Every measurement in a span; no digit run in prose outside a span, inline code, a link target or
  `LITERALS` (`0.1`, `2.0`). So: *twenty minutes*, *eight criteria*, *three parts* — in words.
- Every relative link and every inline-code path containing `/` must resolve under the repo root.
  `rules/` and `evals/` are therefore removed from the layout list; `asf/`, `plugin/`, `docs/`,
  `sample/`, `tools/`, `tests/` stay.
- At most 150 lines and 10,000 bytes.
- The facts file and the page are byte-identical to what `asf readme --refresh` produces.

The manual's four `###` sections are each four to eight lines: `### Install` is the `pipx`/installer
lines the page already carries; `### Quick start` is D12's single invocation plus what the reader
will see; `### Configuration` names `~/.ASF/config.yaml` and `~/.ASF/products/<product>.yaml` and
links to `docs/guide/product-config.md`; `### Upgrade` is the re-run of the installer at a new ref,
linking `docs/guide/upgrading.md`.

Adding `asf pages` to the CLI changes the `commands` block (`readme._commands_rows` reads the
parser), so `asf readme --refresh` runs **after** the CLI change, not before.

### 2.3 `tools/quickstart.sh` — the twenty minutes

The script is the human form of what `tests/test_sample_product.py` already does in `setUpClass`. It
is `set -euo pipefail`, stdlib tools only, and every path it writes is under one temp directory it
prints first and removes on request (never automatically — the reader is meant to look inside).

```
usage: bash tools/quickstart.sh [<dir>]     # default: a fresh mktemp -d
```

Steps, each printing `quickstart: <n>/<total> <what>` and then the artefact to open:

1. **Check the host.** `git`, `python3`, and `asf --version`. No `gh`, no account, no network: the
   sample product is `ci: {provider: none}`, `deploy_sha: none`, and its workers are the `fake`
   runtime replaying `sample/fake_script.json`. A missing prerequisite exits 2 with the one line
   that fixes it.
2. **Materialise the product.** Copy `sample/` into `<dir>`, `git init` the repo and the record,
   create a bare origin for each and push `main` to it — the shape `_publish` makes in the test.
3. **Write the operator home.** `ASF_HOME=<dir>/.ASF`, with `config.yaml` and `products/sample.yaml`
   filled from `sample/config.yaml` and `sample/product.yaml` (`@REPO@`, `@BACKLOG@`, `@SAMPLE@`).
   The reader's own `~/.ASF` is never read or written.
4. **`asf init --product sample`** → the record's ten cards adopted, the intake directory,
   the console permissions. Points at `<dir>/backlog/index.json`.
5. **`asf next --product sample`** → the S1 Bug as the only row. This is the "what would it do"
   view, before anything runs.
6. **One `asf tick --product sample`** → the Bug launched as a fix on its `bugfix/` branch, the
   gate, the landing. Points at the tick's own commit in the record clone.
7. **`asf doctor --product sample`** → green.
8. **`asf roadmap --product sample`** and **`asf scorecard --product sample`** → the two views the
   record's pages are made of, so the reader has seen §2.4's pages before being sent to the public
   ones.
9. **Print what to read next**: the three paths inside `<dir>` worth opening, and
   `docs/guide/getting-started.md` for their own product.

The script prints its own elapsed seconds as its last line (`quickstart: done in <n>s`), which is
what T4 reads.

### 2.4 `asf pages` — the record's two pages

New module `asf/views/pages.py`. Read-only over the record except for the two files it writes;
stdlib only, in the style of `asf/views/readme.py`.

```
asf pages [--product P] [--check] [--refresh] [--json]
```

- `--refresh` renders both pages and writes each through `metrics.write_if_changed`, printing
  `pages: <file> rewritten|unchanged`.
- `--check` (the default) re-renders and reports, per page, whether the committed text differs —
  exit 1 on drift, writing nothing.
- `--json` prints `{"ok": bool, "pages": [{"path", "changed", "generated"}]}`.

**`ROADMAP.md`** — a generated header (the day, the record's `index.json` `generated` stamp, the
command that writes it) and `asf.views.roadmap.render`'s table in markdown: one row per Epic, with
its Features, their stage and what is next. Below it, one line saying the page is written by the
tick and naming this spec.

**`SCORECARD.md`** — four generated sections:

| Section | From | Shape |
| --- | --- | --- |
| `## Value` | `asf.views.scorecard.compute(root, product, weeks=4)` | the weekly table: value shipped, its cost, the lane split |
| `## Cost` | `asf.metrics.metrics.compute_costs` + `subtree_cost` | spend per shipped Feature, and the trimmed per-Feature table |
| `## Release readiness` | `asf.release.criteria` | one row per criterion: key, name, met, evidence |
| `## Not measured` | a table in `asf/views/pages.py`, one row per gap (D5) | what 0.1 has no instrument for, and the card that would add it |

Every row carries the record path its numbers were read from (`index.json`, `metrics/sessions`,
`metrics/ci`, `metrics/ticks`) — the same discipline `asf/views/readme.py`'s facts file keeps, and
the reason a stranger can check a number rather than take it.

The tick's daily step gains a fourth part, beside `stale`, `rollup` and `scorecard`:

```python
('pages', lambda: pages_daily(product, root)),
```

It runs in the record clone, so the two pages ride the tick's one commit. A failed part does not
stop the others — that is `step_daily.run_part`'s existing contract.

### 2.5 The 0.1 release

`docs/release-0.1.md` holds the reading that justified the release: the `asf release-readiness`
output, one line per criterion with its evidence string, the tag, the commit, and the day. It is
written by a session from the real reading, not composed.

`CHANGELOG.md` gains a `## v0.1` section above the newest patch section, holding the launch notes:
what 0.1 is, the four artefacts, what it does not do yet (the `Not measured` rows and the cards that
own them), and the install line. It is the line's announcement and does not replace the per-release
`## v0.1.<n>` sections the existing machinery writes.

One property of `asf.release.changelog_notes` to be deliberate about: it matches a tag as a prefix
(`^##\s+{tag}\b`), so today's `## v0.1.40` section already answers a query for `v0.1`, and the new
`## v0.1` section will answer a query for any `v0.1.<n>` tag whose own section is missing. That is
harmless for the gate — a release with notes is what the criterion wants — but it means the gate
cannot be used as proof that the launch section exists. T3 checks the exact heading itself.

`docs/products.example.yaml` gains a commented `release:` block showing `blocking` (the Feature ids
0.1 will not ship without) and `requires` (the ids each criterion depends on), so the gate is
legible to an operator reading the example.

The cut itself is one operator step, printed and not taken:

```
NEEDS OPERATOR: cut the 0.1 release — `asf release-readiness` must read eight of eight met, then
  publish the line's newest tag as a GitHub Release with the `## v0.1` notes
```

### 2.6 The order of the work

`asf pages` first (it changes the CLI, and the README's `commands` block is read from the parser),
then `tools/quickstart.sh` and its test, then the README and `asf readme --refresh`, then the
release notes. The reverse order means refreshing the facts file twice and a page that drifts
between two commits of the same branch.

## 3. Acceptance tests

Blocks run from the root of this repository unless marked **operator-run** (those need the real
record, which is a separate repository and absent from CI). Each exits non-zero on failure and
prints `ok`.

**T1 — the page is in the shape the code checks, and every number on it is machine-written.**

```bash
python3 - <<'EOF'
import json, os, sys
from asf.views import readme
root = os.getcwd()
text = open(os.path.join(root, 'README.md'), encoding='utf-8').read()
found = readme.spans(text)
if not found:
    sys.exit('README.md carries no span: the instrument is inert against the real page')
facts_path = os.path.join(root, 'docs', 'readme-numbers.json')
if not os.path.isfile(facts_path):
    sys.exit('docs/readme-numbers.json is missing — run `asf readme --refresh`')
data = json.load(open(facts_path, encoding='utf-8'))
```
