# F-0329 — the card must say what the spec said, backticks included

A session that cannot reach the record declares its Stories in the document: a `### S-…: <title>`
heading with its acceptance lines under it, from the session's own claimed block. When the plan
lands, `asf.record.plan_tasks` mints a card per declaration (F-0285) and writes those lines into
the card's `## Acceptance`. That is the only route by which a cloud session's Stories become
cards, and the card is what every later check reads: the coder's brief, the `Proves:` trailer, the
no-test-no-done gate.

Two lines decide what the card says:

```python
def _prose(text):
    return CODE_SPAN.sub(' ', FENCE.sub(' ', text or ''))
```

```python
def declared_stories(text):
    prose = _prose(text)
    ...
        lines = [c.group('line') for c in map(CHECKBOX.match, prose[m.end():end].splitlines()) if c]
```

(`asf/record/idcheck.py:27-28`, `99-109`.) The reader does not read the document. It reads a copy
of the document with every fenced block **and every inline code span** replaced by one space — and
takes the Story's title, the bounds of its section and every acceptance line out of that copy. The
fence half is deliberate: a `### S-…` heading inside a fenced example must declare nothing. The
code-span half is the defect in the card: `S-73204`–`S-73206` were minted from
`docs/specs/f-0280.md` with every backticked term gone — "a Feature at  ,   in lane   round 1" —
and were restored by hand.

It is worse than a strip. A line whose content is *only* a code span (`` - [ ] `python3 -m unittest
tests.test_x` ``) masks to `- [ ]` and blank, `CHECKBOX`'s `(?P<line>\S.*?)` finds nothing, and the
line disappears from the card altogether — including the four lines in `docs/specs/f-0294.md` that
each name the test that proves a Story (P3). And the damage is already written into the repo's own
habits: `docs/specs/f-0315.md` instructs its reader that acceptance lines are "one physical line of
plain text with no backticks, on purpose", naming `_prose` as the reason (P9). This card retires
that instruction.

The requirement is the card's: **a Story minted from a declaration keeps each acceptance line
byte-for-byte, code spans included — and a declaration inside a fenced code block still declares
nothing.**

Keeping the bytes also makes a code span in a card's *title* the normal shape rather than the
rare one, and `check_doc`'s redeclaration test compares a title one-sidedly: it reads the heading
through the same mask and the card through none, so the two stop agreeing. That is already live
in two of this checkout's documents, it refuses a plan whole, and it costs one line to close — so
it is In, as the third Story (P11, D8).

## The design

One function is rewritten, two four-line helpers arrive beside it, and one line of a second
function changes. No signature moves: `declared_stories(text)` returns the same
`{S-id: {'title', 'acceptance'}}` it returns today, `check_doc` returns the same list of finding
lines, and `plan_tasks` keeps calling both exactly where it does (`plan_tasks.py:194-195`).

### `asf/record/idcheck.py` — the fenced spans, and a reader that reads the document

```python
def _fenced(text):
    """The ``[start, end)`` spans of ``text``'s fenced code blocks — what a declaration inside
    one is checked against, instead of substituting it away (F-0329)."""
    return [m.span() for m in FENCE.finditer(text or '')]


def _outside(spans):
    """``pos -> True`` when that offset of the document is in no fenced block."""
    return lambda pos: not any(a <= pos < b for a, b in spans)


def declared_stories(text):
    """``{S-id: {'title', 'acceptance': [line, …]}}`` — every ``### S-…: <title>`` heading in
    ``text`` outside a fenced code block, with the checkbox lines under it up to the next such
    heading. Read out of ``text`` itself, so a line reaches the card it mints byte-for-byte,
    inline code spans included (F-0329): the card is what the coder is briefed from, and a
    backticked identifier is most of what an acceptance line has to say. Fenced blocks are
    excluded, not substituted away — a ``### S-…`` heading inside an example declares nothing,
    a ``- [ ]`` line inside one is not acceptance, and a ``#`` heading inside one does not end a
    Story's section."""
    text = text or ''
    outside = _outside(_fenced(text))
    bounds = [h.start() for h in HEADING.finditer(text) if outside(h.start())]
    out = {}
    for m in STORY_DECL.finditer(text):
        if not outside(m.start()):
            continue
        end = next((b for b in bounds if b > m.start()), len(text))
        lines, pos = [], m.end()
        for line in text[m.end():end].splitlines(keepends=True):
            c = CHECKBOX.match(line.rstrip('\r\n'))
            if c and outside(pos):
                lines.append(c.group('line'))
            pos += len(line)
        out.setdefault(m.group('id'), {'title': m.group('title').strip(' *'), 'acceptance': lines})
    return out
```

`_prose`, `CODE_SPAN`, `cited_stories` and `phantom_stories` are not edited (D2). `FENCE`,
`HEADING`, `STORY_DECL` and `CHECKBOX` are not edited either — the four patterns stay as they are
and are simply run against the document instead of a copy of it.

`_outside` is an `any()` over every fenced span, asked once per heading and once per candidate
line: O(headings × fences + lines × fences). At this scale that is nothing — the whole-checkout
sweep in `## Acceptance tests` runs over 799 documents in under a second — and the clause reads
as what it means. If a document ever grows a few hundred fences, `bisect.bisect_right` over a
list of span starts is the drop-in replacement and changes no behaviour.

### `asf/record/idcheck.py` — the same mask on both sides of the redeclaration test

The right-hand side of one comparison in `check_doc`, so that a heading is compared against the
card as `check_doc` is able to read it (D8, P11). `prose = _prose(text)` above it stays, the
finding's text stays, and the loop body is turned inside out only to keep the line short:

```python
    for m in DECL.finditer(prose):
        iid, title = m.group(1), m.group('title').strip(' *')
        rec = canonical.get(iid)
        if rec is None or not title:
            continue
        was = rec['meta'].get('title')
        # ``prose`` has already cost the heading its code spans; mask the card's title the same
        # way, or a card minted from a declaration that keeps its own (F-0329) never compares
        # equal to the heading that declared it.
        if _norm(title) != _norm(_prose(str(was or ''))):
            out.append(f"{iid} already exists in the record ({was!r})")
```

`if rec is None or not title: continue` is today's `if rec is not None and title and …`
(`idcheck.py:48`) with the guard lifted out; `str(was or '')` is what `_norm` already does to its
argument (`idcheck.py:31-32`), moved one call earlier so `_prose` is handed a string. Eight cases
were run against this shape in a scratch harness — a span on both sides with the same words, a
genuine reuse, no span and equal, no span and unequal, a card title of `None`, a card title that
is not a string, a fenced heading, and two titles differing only inside a span — and all eight
give the finding (or the silence) the Decisions above claim.
