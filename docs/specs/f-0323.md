# F-0323 — a second fix is impossible: the lane closes its PR and `asf reopen` is refused

On 2026-10-08 the factory closed fix PR #1244 (`fix/B-82960-parked-holder-row`, green, a real
diff) with the comment *"B-82960 is Resolved in the record"*. It was the **second** fix for
B-82960: #1239 had landed an incomplete one, the Bug derived `Resolved` from that landing, and the
follow-up was then thrown away by the lane as superseded work. The operator's way back —
`asf reopen B-82960 --reason …` — refused:

```
error: B-82960 — current evidence still says Resolved (rule: fixed): merge 14b963b … lands B-82960
```

Both refusals are correct in their own terms, and together they are a trap. The lane's rule
(`superseded_by`, B-0057) exists because a Bug that the record already calls done should not keep
a branch alive: that branch is the *older* attempt some other fix landed before it. `asf reopen`'s
rule exists because a card wrongly closed is corrected in code, never by hand: it re-derives from
current evidence and refuses when the fresh derivation still lands the item. Neither rule can tell
the two cases apart, because neither asks the one question that separates them:

> **does the branch in flight build on the landing the card's done state stands on?**

A duplicate attempt does not — it was cut before the fix landed, and everything it carries the
trunk already has by another route. A follow-up does — it was cut from a trunk that *contains* the
incomplete fix, and what it carries is new. That question is one `git merge-base --is-ancestor`,
and this Feature makes all three refusals ask it.

The answer is a derivation, not an override. `asf reopen --reason` stays unable to beat the
evidence (the operator's own rule: fix the software, or re-run its rule; never type the state).
What changes is that a follow-up fixer **is** evidence — evidence that the fix was incomplete — so
the Bug derives `Active` again from the ordinary `asf ingest`, and `asf reopen` is needed only
where `closing.sticky` holds a `Closed` (the quiet rule) against it.

## Decisions

### Preconditions

* **P1** — The follow-up branch's name carries the Bug's id (`fix/B-82960-…`): the
  `BRANCH_ID_TOKEN` match in `asf.evidence.evidence.id_evidence` is where the fact is derived.
  This is the lane's own convention for a fix branch (`conventions.branch_prefixes.fix`), enforced
  for every factory fix session.
* **P2** — The product repo has `origin/<main>` and the fixer's head fetched. Every `ancestor_of`
  read is against the product checkout the evidence pass already reads; an unresolvable rev
  answers False, which is the timid answer (no refix derived, today's behaviour).
* **P3** — The first fix really landed: the Bug carries a `landing:` stamp with a full sha, or the
  id evidence carries a `commit`. A done Bug with neither is outside this change (O3).
* **P4** — `Resolved` is not sticky. `closing.sticky` holds `Closed` only (§1.4), so a `Resolved`
  Bug moves back to `Active` through plain `asf ingest`, with no reopen and no bypass.
* **P5** — `id_evidence` has **two** returns: the no-CI early return (`evidence.py:1503-1506`,
  `if ci_provider(product) is None: … return merge_landed(...)`) and the final one
  (`evidence.py:1519`). "A final pass" is therefore not a safe instruction — a pass written after
  the green loop never runs for a product with `ci: none`, and the acceptance fixture has that
  arm (`ProductRepo.product(ci=None)`). §1 pins the placement instead.
* **P6** — The Bugs block of ingest has **two** evidence-line shapes, because it has two paths,
  and the incident's Bug took the *second*:
  * the **links** path (`ingest.py:1091-1096`, `bev['merged_sha']`) writes
    `fix merged (<sha9>)` (`ingest.py:1117`);
  * the **id** path (`ingest.py:1098-1105`, `lines = id_lines` from
    `evidence.id_state`) writes `merge <sha7> of <branch> lands <id>` or
    `commit <sha7> names <id>`, **plus** a second line when the commit is green
    (`evidence.py:1618-1625`) — `CI green on main at or after it`, or `no CI provider` for a
    product with no CI, because `match_ids` passes `has_ci=bool(ev.get('ci'))`
    (`ingest.py:367`, `evidence.py:1624`). A green id-path Bug therefore carries **two** lines
    and a not-green one carries **one**.

  B-82960's own refusal — *"merge 14b963b … lands B-82960"*, quoted on the card — is the id
  path's line, so the incident is an id-path Bug. Its line *count* is not pinned by the quote:
  `Resolved (rule: fixed)` is reached both by a not-green commit (one line) and by a green one
  whose signature was seen inside the limit (two lines, the arm
  `tests/test_ingest.py:1031-1034` fixes). Nothing in this spec depends on which: the refix line
  is appended last either way (D7), and §3's acceptance asserts `evidence[-2]`/`evidence[-1]`
  rather than a count. Both shapes
  are anchored prefixes that `scorecard.facts.landing_shas` parses (`_LANDING_RE` and
  `_MERGED_RE`, `facts.py:189-191`), which is what makes D7's "append, never rewrite" safe on
  either path; and the refix line, starting `a later fixer`, matches neither regex.

### In

* **D1 — A fixer that builds on the landed fix is evidence the fix was incomplete.** A new rule
  `('bug', 'refixing', …) -> Active` in `asf.evidence.closing.RULES`, ahead of `quiet` and
  `fixed`, firing on a new `Ev.refix` field. This is the whole of the record-side fix: with the
  rule in place, ingest derives `Active`, the lane's `superseded_by` sees a Bug that is no longer
  done, and `asf reopen`'s fresh derivation no longer lands it.
* **D2 — The fact is ancestry, not time.** `refix` is derived in `id_evidence` as: the id has a
  landing `commit`, and some live fixer head `H` (a branch on origin whose name carries the id, or
  an open PR's `headRefOid`) satisfies **both** `commit` is reachable from `H` *and* `H` is not
  reachable from `origin/<main>`. The second clause is what keeps a product that lands by
  fast-forward honest: there, the landing commit *is* the merged branch's head, so without it
  every just-landed fix branch would read as its own follow-up until the lane deleted it.
* **D3 — `Ev.refix` is a string: the fixer's name** (`fix/B-82960-parked-holder-row`, or
  `PR #1244`), empty when there is none. The rule reads `_landed(ev) and bool(ev.refix)`, and
  ingest writes the name into the evidence line, so the card says which branch reopened it.
* **D4 — The lane's three done-card refusals each exempt a branch that carries the landing.** One
  pure helper, `builds_on_landing(card, head, is_ancestor)`, reading the card's `landing.sha` from
  the index entry; `superseded_by` takes it as `follow_up=…`, and `Lane.branch_facts` (twice) and
  `Lane.orphan_facts` pass it. Three *reads*, two *methods*: `Lane.branch_facts`
  (`lane.py:1770`) holds both the `superseded_by` call (`:1860`) and the adoption guard
  (`:1814-1821`); `Lane.orphan_facts` (`:2045`) holds the third (`:2075`). The method is
  `Lane.branch_facts` and never `Lane.facts` — `lane.facts(product)` is a real module-level
  function (`lane.py:5670`) and a different thing, so the name matters when a coder resolves it. This is the belt to D1's braces: the lane reads an `index.json`
  snapshot and would otherwise still close the PR in the window before the next ingest — which is
  exactly what happened to #1244, a PR that had been green and open for hours.
* **D5 — A removed card still supersedes, always.** `builds_on_landing` is consulted only for the
  done-state clauses; B-0065's `removed` answer is returned before it is asked.
* **D6 — `asf reopen`'s refusal names the route.** When the fresh derivation still lands a Bug,
  the refusal keeps its first line (the state, the rule, the lines) and gains a second: a landing
  that stands is not undone by hand — push the follow-up on `<fix prefix><id>-…` cut from the
  trunk and ingest derives `Active` (rule `refixing`); `asf reopen` is for a close no evidence
  supports. The branch name comes from `Conventions.branch('fix', iid)`, never a literal
  (`tools/check_conventions.sh` refuses `'fix/` in `asf/**/*.py`).
* **D7 — Ingest keeps the landing line it writes today, whichever path wrote it, and appends the
  refix line after it.** Not "after `fix merged (…)`": by P6 that line is the links path's, and
  the incident is an id-path Bug whose lines are `merge <sha7> of <branch> lands <id>` and
  `CI green on main at or after it`. The refix line is appended to `lines` as the last evidence
  entry on both paths, and no existing line is rewritten —
  `asf.scorecard.facts.landing_shas` and `asf tick migrate-landing` recover a landing sha by
  matching those anchored prefixes, and rewriting either would blind them. Two readers, two
  *copies*: `facts.py:189-191` and `migrate_landing.py:32-33` each hold the same pair of regexes
  rather than sharing one, so a rewritten line breaks both independently. This matters past
  cosmetics because D9 drops the `landing:` stamp, so the evidence line becomes the *only* place
  the first landing's sha survives on the card.

  One exception, and it is a suppression rather than a rewrite: the links path's line is
  **state-dependent** — `ingest.py:1117-1118` appends `' -- pending 3-day quiet'` when the merge
  is in prod and the state is not yet `Closed`, and `refixing` (sitting ahead of `quiet`) makes
  that test False, so a refixed links-path Bug would otherwise read `fix merged (<sha9>) --
  pending 3-day quiet` while its state is `Active` and no quiet window is running. The suffix is
  therefore suppressed when the rule is `refixing` (§3). Nothing parses it — it is written at
  `:1118` and described in prose at `evidence.py:1847` — so this costs no reader; the anchored
  `fix merged (<sha9>)` prefix `landing_shas` matches is untouched either way.
* **D8 — No `reopened:` marker on the ingest path.** The `reopened:` list is `asf reopen`'s own
  marker for an operator correction. A refix is a derivation like any other: it writes `state`,
  `evidence`, `stage_since` and one `## History` ingest line. I14's `S-M15` clause (a reopened
  card closes on a *new* landing) is therefore **satisfied, not checked**, on this path: it is
  gated on `reopened is not None` (`invariants.py:627`), and with no marker `_last_reopen`
  returns None (`invariants.py:505-512`), so the `as_of <= reopened` comparison never runs. What
  makes that safe is D9 rather than the clause: the stale stamp is dropped when the card goes
  `Active`, so the second close must stamp afresh and there is no old `as_of` left for S-M15 to
  have caught. (The `asf reopen` path of D6 does write the marker, and there the clause fires as
  it does today.)
* **D9 — The landing stamp is dropped when the Bug goes `Active`**, by `_landing_update`'s
  existing `_DROP` for a non-done state. The incomplete fix's stamp is not the Bug's resolution
  and must not be read as one; the History line and the trunk keep the record of it, and the
  second fix stamps afresh. The lane's belt (D4) reads the stamp while it is still there, which is
  precisely the window the belt exists for.

### Out

* **O1 — Tasks and Stories.** The rule is `bug`-only. In this factory a follow-up to landed work
  *is* a Bug — that is what the `B-` ladder and `fix/` lane are — and the lane's done-state
  supersede (`superseded_by`) already applies to Bugs alone. The lane's belt (D4) is type-blind
  because `orphan_facts`' second done-card clause is, so an orphan branch that builds on any
  card's landing is left alone; no new rule is minted for those types.
* **O2 — A Bug whose fixer is linked only by `links:`** (`links.prs` / `links.branches`) with no
  id token in the branch name derives no `refix`: the fact comes from the id-token path. P1 is the
  factory's convention and the gap is the hand-linked card only. Naming it here so the next
  reader does not read silence as coverage.

  The gap has a **second** clause, and it is the id record's landing rather than the branch's name:
  `refix` is derived only where the id record carries a landing `commit` (§1's
  `if not r["commit"]: continue`). So a Bug whose landing merge names no id derives no `refix`
  even when its follow-up branch is conventionally named — and §3's "a card with `links:` *and* a
  conventionally-named fix branch is covered" holds only where an id-naming landing commit exists
  too. In this factory it normally does, because the lane's own fix subjects are `fix(B-xxxx): …`
  (this spec's own commits are `spec(F-0323): …`), so the clause bites only on a landing merged
  outside the convention. Stated because O2 exists to stop silence reading as coverage.
* **O2a — A branch whose PR was already closed unmerged is not a candidate, so B-82960 does not
  heal itself.** The `branches` set `id_evidence` receives has had dead branches removed before it
  arrives (`evidence.py:662`: `{b for b in heads if b not in dead and not b.startswith("archive/")}`,
  where `dead_branches` takes exactly those whose PR was closed unmerged). #1244 *is* closed, so
  `fix/B-82960-parked-holder-row` as it stands is dead and derives no `refix`. This is deliberate:
  a branch the lane threw away is not work in flight, and reviving a dead branch by ancestry alone
  would undo B-0057's own answer. Named here so the next reader does not expect the already-closed
  case to reopen on the next tick, with nothing pushed.

  "Dead" is a property of the head, though, not a life sentence on the name, and the recovery has
  therefore **two** routes rather than the one §6 walks. `dead_branches` calls a branch alive again
  once its head is neither the closed PR's `headRefOid` nor its `archive/pr-<N>` tag and was
  committed past `closedAt` (`evidence.py:325-329`, whose own comment reads *"committed past the
  close: new work, alive"*). So a commit pushed onto `fix/B-82960-parked-holder-row` today leaves
  it out of `dead`, back in `branches`, and a candidate like any other — and D4's adoption guard
  is what then gets it a PR, that branch having no open one. A **new** name
  (`fix/B-82960-parked-holder-row-2`) reaches the same place without depending on that rule, which
  is why §6 is written against it; neither route is required by this spec, and an acceptance test
  pins neither.
* **O3 — A Bug held `Closed` by a typed `landed:` sha** is `reconciled` by the `any` rule, which
  outranks every per-type row. That close is the operator's own typed answer, and untyping it is
  theirs too; this spec does not touch the typed answers (`landed`, `reconciled`, `removed`).
* **O4 — `asf reopen --force`.** Considered and refused: see the choice table.
* **O5 — Closing the duplicate case faster.** A branch that does *not* build on the landing is
  still closed exactly as today, after `lane.stale_after` where that applies. Nothing in this
  change makes B-0057 slower or faster.
* **O6 — The PR comment's wording** when the lane does close a superseded branch is unchanged.
* **O7 — `Lane.transplant_case`'s done-card refusal.** A fourth site reads a done card
  (`card.get('state') in lifecycle.DONE_STATES` → no transplant), and it is left alone. It is a
  *rescue* path — it re-lands an approved head for a branch already held `BACK` or `STALE` — so
  its refusal costs a follow-up nothing: the branch keeps its PR (D4) and the card is `Active` by
  the next ingest (D1), after which the clause does not fire. Named here so the next reader does
  not read three sites as all of them.

### The choices

| Choice | Chosen | Against | Why |
| --- | --- | --- | --- |
| How a second fix becomes legal | a derivation: the fixer is evidence (`refixing`) | an operator override (`asf reopen --force`, or `asf set state=`) | The card's second half is that *"a person's reopen can't override the evidence"*. Making the person stronger than the evidence is the wrong half to fix: the evidence was incomplete. With the rule in, the ordinary tick reopens the Bug and no one has to type anything. |
| The fact that separates follow-up from duplicate | ancestry: the fixer head contains the landing | a timestamp (`createdAt` > `mergedAt`), or the PR number being higher | Ancestry is the question itself, not a proxy for it: a branch rebased onto the fixed trunk reads as a follow-up because it now *is* one, and a stale attempt reads as a duplicate however recently it was pushed. Timestamps would also need a new `createdAt` field in the PR list. |
| Where ancestry is read | `ancestor_of(…)` per candidate | `ancestry(product, heads)`' shared rev-list | A shared reach set answers *"reachable from any of these heads"* and would let one Bug's fixer vouch for another Bug's landing. Candidates are ids with both a landing and a live non-doc fixer — a handful a tick — so one or two forks each is cheaper than the bug. |
| Whether the lane also changes | yes, all three done-card sites | rely on ingest moving the card to `Active` first | The lane reads an `index.json` snapshot; the incident's PR was closed while the record said `Resolved`. One `is_ancestor` on the stamp the card still carries closes the window without depending on step order inside the tick. |
| Where the refix line goes, given two paths | appended last on each path, leaving both landing lines as they are | normalising the id path onto the links path's `fix merged (<sha>)` so the card has one shape | The two shapes are an existing fact of the Bugs block (P6) and not this Feature's to settle: `landing_shas` parses both, and rewriting the id path's line would change what every already-landed Bug's card says — a migration, on a spec whose point is a second fix. The cost is that no acceptance test may assert a fixed index for both paths, which is stated where the tests are. |
| What the `Ev` field carries | the fixer's name (a string) | a bare bool | The evidence line has to say *which* branch reopened the Bug, or the card records a state change nobody can trace. Strings-truthy matches `Ev.commit` / `Ev.branch`. |

## The design

### 1. The fact — `asf/evidence/evidence.py`

`id_evidence`'s per-id record gains one key, `refix` (default `''`), derived in one pass over
`out` once `commit` is settled — placed **immediately after the merged-PR loop and before
`if ci_provider(product) is None:`** (`evidence.py:1503`), so both returns carry it (P5). Before
`merge_landed`, deliberately: an id whose only commit is a typed `landed:` sha is `reconciled`
and outranks `refixing` anyway (O3), so there is nothing for it to derive there.

The default is seeded in **both** per-id record literals, the same care P5 gives the two returns:
`rec()`'s `setdefault` (`evidence.py:1433-1435`) and `merge_landed`'s fallback copy
(`evidence.py:1393-1395`, reached by an id whose only evidence is a typed `landed:` sha). §1's
loop writes `r["refix"]` only on a match, so without both literals an id with no fixer carries no
`refix` key at all — product code survives that (ingest reads `iev.get('refix')`, §3) but
`RefixFactTests` subscripts `['refix']` expecting `''`, and a record that answers `KeyError`
instead of `''` is a different contract from the one stated here.

```python
#: a live fixer that builds on the landing and has not landed itself (F-0323): the branch or
#: PR that says the fix was incomplete, '' when there is none
for iid, r in out.items():
    if not r["commit"]:
        continue
    for name, ref in _fixer_heads(r, prs, prefixes):
        if ancestor_of(r["commit"], ref, product=product) \
                and not ancestor_of(ref, main_ref, product=product):
            r["refix"] = name
            break
```

`_fixer_heads(r, prs, prefixes)` yields `(name, ref)` for each candidate **in the order the
record already holds them**: first every branch in `r["branches"]` that is not a document lane
(`lane_kind(b, prefixes) is None`) as `(b, f"origin/{b}")`, in `r["branches"]`' own order — which
is the sorted branch list, because it is filled while iterating `sorted(branches)`
(`evidence.py:1437-1441`) — then every number in `r["open_prs"]` ascending, that list being
filled while iterating `sorted(prs, key=…number)` (`evidence.py:1476-1484`), as
`(f"PR #{n}", headRefOid)` looked up in `prs` by number. A PR whose head sha the checkout does
not know resolves to False in `ancestor_of` and is skipped (P2).

Not "newest first": neither `r["branches"]` nor `r["open_prs"]` carries a commit date or
`createdAt`, and the choice table refuses to add one, so there is no time to sort by. The order is
load-bearing anyway, because the loop `break`s on the first match and the name it stops at is what
goes on the card — so it is pinned to the two lists' existing order, which is deterministic for a
given set of branches and PRs. When a Bug has more than one live follow-up, the alphabetically
first branch wins, and a branch wins over a PR.

The two clauses, in that order, are the design: `commit` reachable from the head says *the fixer
builds on the fix*; the head not reachable from `origin/<main>` says *the fixer has not landed*.
The first is cheap to falsify for the common case (a lingering branch whose squash merge is not in
its own history), so the second fork is rarely made.

### 2. The rule — `asf/evidence/closing.py`

One field on `Ev`, one row in `RULES`, one line in the module's rule table:

```python
    refix: str = ''           #: a live fixer that builds on the landed fix (F-0323)
```

```python
    ('bug', 'refixing', lambda ev: _landed(ev) and bool(ev.refix), ACTIVE,
     'a fix merged, and a later fixer builds on it — the fix was incomplete'),
    ('bug', 'quiet', _quiet, CLOSED, …),
    ('bug', 'fixed', _landed, RESOLVED, 'a fix merged'),
```

Ahead of `quiet` and `fixed`, behind the two `any` rows. `parent-closed` cannot steal it: a refix
is own evidence by every reading (`_own_evidence` already sees the branch and the open PR).
`reconciled` still outranks it, by O3. The docstring table gains its line in the same order:

```
  bug      refixing           a fix merged, and a later fixer builds on it       -> Active
```

### 3. The derivation — `asf/record/ingest.py`

Both `closing.Ev(...)` constructions in the Bugs block take `refix=iev.get('refix') or ''` — the
`links`-matched branch as well as the id-matched one, so a card with `links:` *and* a
conventionally-named fix branch is covered (O2 is the branch with no id token). The evidence lines
keep every entry they have today and gain one at the end. It goes after the `if linked and
bev['merged_sha']` / `elif linked` chain (`ingest.py:1114-1120`), the one point where `lines` is
bound on all three paths — `:1105` for the id path, `:1117` for links-with-merge, `:1120` for
links alone (`:1119` is the `elif linked:` itself).

`ev_obj` is fully settled by `ingest.py:1113` (the signature and quiet fields are the last thing
written to it), so the settled state is read **once**, above the chain, and serves both the
suffix D7 suppresses and the new line — one `state_of` call where today's code makes one per
path:

```python
        st = closing.state_of('bug', ev_obj, new_state[iid])
        if linked and bev['merged_sha']:
            in_prod = reach(bev['merged_sha'])
            lines = [f"fix merged ({bev['merged_sha'][:9]})"
                     + (' -- pending 3-day quiet' if in_prod
                        and st.state != closing.CLOSED and st.rule != 'refixing' else '')]
        elif linked:
            lines = ['fixer branch/PR open']
        if st.rule == 'refixing':
            lines = lines + [f"a later fixer builds on it: {ev_obj.refix} — the fix was incomplete"]
        settle(iid, 'bug', ev_obj, lines)
```

The `quiet` local at `:1116` is replaced by `st`, not joined by it; `st.rule == 'refixing'` needs
no `ev_obj.refix and` guard, because only a truthy `refix` can reach that rule.

With that, an `asf ingest` over B-82960's evidence — an **id-path** Bug, by P6 — writes:

```yaml
state: Active
evidence:
  - "merge 14b963b of fix/B-82960-parked-holder-row lands B-82960"
  - "CI green on main at or after it"
  - "a later fixer builds on it: fix/B-82960-parked-holder-row — the fix was incomplete"
  - "rule: refixing"
```

The refix line is the **last** line before `rule:`, at whatever index the path's own lines leave
it — index 2 here, this id path's commit being green (P6: a not-green one writes no CI line and
leaves it at index 1), and index 1 for a links-path Bug whose single first line is
`fix merged (<sha9>)`.
An acceptance test asserts the position that way round, never a fixed index for both paths.

The card's `landing:` is dropped (D9), and `## History` gains
`- 2026-10-08 10:12 ingest: state Resolved → Active (rule: refixing; merge 14b963b of … lands
B-82960; CI green on main at or after it; a later fixer builds on it: …)`.

Downstream, nothing else needs a line. `asf.feeder.rows.bug_rows` already answers an `Active` Bug
with a non-launching `WAITS ON branch — Active — its fixer branch/PR is the work` row, so the
reopened Bug starts no second session; `asf.approvals.close_landed` stops closing its holds as
landed; the groom's "no test, no done" audit is untouched.

### 4. The lane — `asf/harvest/lane.py`

One helper beside `superseded_by`:

```python
def builds_on_landing(card, head, is_ancestor):
    """F-0323 — ``head`` already carries the landing the card's Resolved/Closed stands on, so
    the branch is a follow-up to that landing and not an attempt the landing superseded.

    False, and the supersede stands, in both timid cases: the card carries no landing sha
    (nothing to compare), or the checkout cannot resolve ``head`` or the sha — then
    ``git merge-base --is-ancestor`` exits non-zero and :meth:`Lane.is_ancestor` answers False
    (``lane.py:1684-1686``), the same answer :func:`ancestor_of` gives the fact side (P2)."""
    stamp = (card or {}).get('landing')
    sha = str(stamp.get('sha') or '') if isinstance(stamp, dict) else ''
    return bool(sha and head and is_ancestor(sha, head))
```

`superseded_by(items, item, follow_up=False)` returns `'removed'` first (D5) and skips the Bug's
done state when `follow_up`. The three callers pass it:

* `Lane.branch_facts` (`lane.py:1770`), `f['closed'] = superseded_by(self.items, item,
  follow_up=…)` at `lane.py:1860` — the site that closed #1244.
* the adoption guard, `lane.py:1814-1821` — the *second* done-card read inside that same
  method (`run is None and not foreign`), whose `card.get('state') in ('Resolved', 'Closed')`
  arm otherwise drops a follow-up branch that has no PR yet, so a refix pushed by a session the
  lane no longer holds would never get a PR opened at all.
* `Lane.orphan_facts` (`lane.py:2045`) — both clauses at `lane.py:2075`, `superseded_by(...)`
  and the type-blind `card.get('state') in ('Resolved', 'Closed')` one, behind the same
  `follow_up` (O1).

`follow_up` is computed once per branch, `builds_on_landing(card, head, self.is_ancestor)`, and
only where a done state would otherwise decide — one `merge-base` fork for a branch whose card is
done, none for any other.

### 5. The refusal — `asf/record/reopen.py`

  fix/B-82960-parked-holder-row lands B-82960
  a landing that stands is not undone by hand. Push the follow-up fix on a branch cut from the
  trunk (fix/B-82960-…) and ingest derives Active (rule: refixing); asf reopen is for a close no
  evidence supports.

The first line is unchanged — `'; '.join(c.lines)` of whatever the path wrote (`reopen.py:158`,

The second line only for a Bug whose rule is a landing rule (`fixed`, `quiet`, `reconciled`); the

### 6. What it looks like when it is there

A fixer session takes B-82960's second round and cuts a branch from the trunk that already carries
`14b963b` — a **new** name, `fix/B-82960-parked-holder-row-2`, the original sitting dead at its
closed PR's head (O2a: a commit pushed onto the old name would revive it too, and this walk-through
simply does not lean on that) — and pushes. The next tick:
`id_evidence` derives `refix: 'fix/B-82960-parked-holder-row-2'`, ingest moves the Bug
`Resolved → Active` with the rule, the path's own landing line(s) and the refix line on the card,
the lane opens a PR for the branch
and takes it through review and the gate like any fix, NEXT shows
`BUG → FIX B-82960 WAITS ON branch`, and when the PR merges the Bug derives `Resolved` again on
the *new* merge, with a fresh `landing:` stamp. Nobody types a state, and `asf reopen` is never
needed.

Rewind to the day of the incident, with PR #1244 still **open** — the case this change actually
prevents, and the reason the lane's belt (D4) is half of it. `fix/B-82960-parked-holder-row` is
live, so it is in `branches` and it is a candidate: `Lane.branch_facts` finds the card still
`Resolved` in its snapshot, asks whether the branch carries `14b963b` — it does — and leaves the
PR open instead of closing it; the ingest step in that same tick moves the card to `Active`, and
from then on `superseded_by` returns nothing to begin with. The PR is never closed, so the branch
never goes dead, so the new-name detour above is never needed. That detour is the cost of the
incident having already happened, not of the design.

And the case B-0057 was written for is unchanged: a branch cut before `14b963b` landed, carrying
work the fix superseded, does not contain it, so its PR is closed with
`B-82960 is Resolved in the record` exactly as today.
