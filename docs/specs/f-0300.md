# F-0300 — the disputes code rules, before any adjudicate session

The card counts 93 adjudicate sessions in 7 days — about one per two Features, each a full model
session — and says most of them rule on one of two things: **a cosmetic review demand** (squash
the commits, a wording preference) or **a question an existing decision or code pattern already
answers**. Neither is judgement. An adjudicate session is the most expensive row the feeder mints
and the only one with no round after it; spending it on "C1 asks for a squash" is the factory
paying a model to say *no*.

This is the same shape the trunk already answers once, for corrections:
`asf.harvest.mechanical` is "the causes code settles before any correction is written" — git
decides whether a branch rebases, the widening rule decides whether a footprint grows, and the
lane applies that table *before* it writes a hold. F-0300 is that table one level up: **the
disputes code rules before any adjudicate session is spawned.**

Most of the reading machinery is already on the trunk and already green. `asf.evidence.rulings`
knows how to match a C item against a standing ruling (`covers`) and how to answer "this review
only re-raises settled points" (`reraised_only`), and the lane's merge gate already asks it
(T5a', `asf/harvest/lane.py:1938`). `asf.evidence.precedent` reads the product's decision
register whole. `asf.tick.step_health.file_rulings` already writes a ruling onto a card as a
`## History` line that every later brief and the gate read back.

What is missing is in three places:

* **nothing classifies a finding as cosmetic.** `grep -rn cosmetic asf tools` prints no hit (P2).
  A C item asking for a squash is a finding like any other: it spends a round, repeats, hits the
  round cap and buys a session.
* **nothing consults either corpus at the moment the adjudicate row is screened.** The rulings
  reader is asked by the *gate*, about a review's verdict; it is never asked by the wave, about
  whether this row needs a model at all (P3, P8). The register reader is asked by nobody at all —
  `precedent.entries` and `precedent.brief_section` have tests and no caller (P5).
* **a ruling that is not a session's cannot be written.** `file_rulings` keys on an adjudicate
  *run*, and so do `lifecycle.settled` and `step_wave.adjudications` (P6, P7): there is no way for
  the factory to rule without first spending the session whose cost is the point.

### In

1. **One new module, `asf/evidence/rulepass.py`** — the rule table, beside `rulings` and
   `precedent` in the family that answers "what the record already settled". Two rules, each
   `(product, item, dispute) -> Ruling | None`:
   * **`cosmetic`** — every open finding is a demand about commit shape, wording or formatting,
     and nothing in the never-waive set matches. Overruled, nothing on the branch changes.
   * **`precedent`** — every open finding is covered by a standing ruling on this item
     (`rulings.covers`, the landed reader, now asked at screen time) or cites a decision the
     register confirms (`precedent.entries`, with a status that is not `STALE_STATUS`). Overruled,
     with the citation.
   A dispute is waived only when **every** open finding is — `reraised_only`'s own rule. One
   unwaived finding and the whole dispute goes to the session, unchanged.
2. **The pass runs in `screen()`, before any adjudicate row launches** (P9). A waived row files its
   ruling, takes no session and no seat, and is `Screened(row, why, RULED)`; the preview twin
   (`act=False`) says the same thing and writes nothing, so `asf status`' "Ready to launch" never
   counts a row the wave will rule. Behind `conventions.flags.rule_pass`, default off — the
   `mechanical` shape (P10), documented in `docs/products.example.yaml`.
3. **The waiver stops the row coming back.** The ruling carries the finding key it waived
   (P11), and one reader learns it: `plan_rows` gains a `waived` kwarg, threaded from
   `plan_inputs` like `adjudicated` (P13, C8). Both the `:1058` and the `:1509` branch test
   membership in that one map, and the match itself is made in `plan_inputs` — the only place
   that holds both the product and a filesystem (P19, C11). The branches stand down while the
   waiver covers the *current* finding — a new C item changes the key, the waiver no longer
   matches, and the row is STALEMATE as today. That is the loop bound: the pass can waive one
   finding once.
4. **What it saved is visible.** One `rule_pass` event per ruling and one tick line; one
   `asf status` row naming the rulings of the last 7 days by rule, so the card's own claim about
   the mix becomes a reading rather than an estimate (P15, P18).

### Out

- **The two attempts-exhausted adjudicate rows.** `bug_rows` at the attempt limit and `_capped`
  at and above it (P1) are about *three sessions failed*, not about a finding. There is no text
  to classify and no precedent to cite; a model session is the right cost, and a rule that fired
  there would be guessing. They launch exactly as today.
- **The code-pattern precedent.** "The product already does this once, somewhere" is the second
  precedent `precedent.brief_section` instructs a session to establish, and code cannot establish
  it: it needs a reading of the diff against the rest of the tree. The rule pass stands down and
  the session rules, as today. This is why the card says *most*, and why this spec claims a
  share of the 93, not all of them.
- **Any lexical or semantic guess at a decision match.** The `precedent` rule fires only when the
  finding's own text **names** the decision (a `D-nnnn`, or a `docs/decisions/` path) and the
  register confirms it. Matching a decision's title against a C item by word overlap would waive
  a real defect on a coincidence; standing down costs a session, which is today's cost.
- **Wiring `precedent.brief_section` into the adjudicate brief.** It is F-0262's residue (P6) and
  its own card: the session that the rule pass stands down for still gets no `IN-REPO PRECEDENT`
  block, which is a real gap and not this one. Named here so the plan does not read its absence
  as this spec's omission, and so a Bug can be filed against F-0262 rather than against F-0300.
- **Any change to `asf/evidence/rulings.py`.** P4 and P5 measured that a `rule-pass` ruling is
  already read back by `parse`, `covers`, `reraised_only`, `standing` and `brief_section`
  unchanged. The ruling's *wording* is this spec's contract with those readers (C4), not a change
  to them.
- **Any change to `file_rulings`.** A session's ruling is still filed exactly as it is. The rule
  pass writes its own line, in the same shape, from `screen()` — it does not route through the
  health step's run loop, which has no run to key on (P7).
- **Any change to `asf/workers/lifecycle.py`.** `corrections()`, `correction_of()` and
  `occupancy()` take the sessions path and no product, and the ruling is on the card under
  `backlog_dir` (P19): a `waived` key in there would mean threading a product through all three
  and their six callers, for one row. The waiver is computed once in `plan_inputs` instead (C8),
  so `corrections()` reads exactly as it does today — `finding_of`, `repeats` and `corrections`
  are read, never changed.
- **Clearing the correction, touching the lane, or moving the branch.** The ruling is the whole
  write. The landed gate (`reraised_only`, T5a') is what stops the branch being held and stops the
  round counting once the ruling is on the card; no `mechanical`-style publish, no lane state
  write, no `PUSHED`.
- **Overruling a finding in licence, money, security or customer-visible change.** The brief's
  four classes (P14) are the never-waive set's first four members, and they beat every cosmetic
  match.
- **A new state file, a new ledger, or a config key beyond the flag.** The card's `## History` is
  the record, because it is what every later reader already reads.
- **`docs/design`, `docs/KNOWN-ISSUES.md`, `CHANGELOG.md`.** This session creates
  `docs/specs/f-0300.md` and nothing else.

## The design

Four files: **`asf/evidence/rulepass.py`** (new — the table), **`asf/tick/step_wave.py`** (the
check, its preview twin and the `waivers` map), **`asf/feeder/rows.py`** (the waiver stops the
row), **`asf/views/status.py`** (the row that says what it saved); plus `tests/test_rulepass.py`
(new), `tests/test_feeder.py` and `tests/test_views.py`. `asf/workers/lifecycle.py` is read —
`finding_of`, `repeats`, `corrections` — and not changed (P19, Out).

### 1. `asf/evidence/rulepass.py` — the table

```python
"""asf.evidence.rulepass — the disputes code rules before any adjudicate session is spawned.

An adjudicate session is the most expensive row the feeder mints and the only one with no round
after it. Most of them rule on a cosmetic review demand (squash the commits, a wording
preference) or on a point an existing decision or a standing ruling already answers — neither is
judgement. This module is the one table of those disputes, applied by the wave
(:func:`asf.tick.step_wave.screen`) *before* it spawns anything:

* ``cosmetic``  → every open finding is a demand about commit shape, wording or formatting, and
  nothing in :data:`NEVER_WAIVE` matches. Overruled; nothing on the branch changes.
* ``precedent`` → every open finding is covered by a standing ruling on this item
  (:func:`asf.evidence.rulings.covers`) or names a decision the register confirms
  (:func:`asf.evidence.precedent.entries`). Overruled, with the citation.

A dispute is waived only when *every* open finding is (:func:`rule`) — one unwaived finding and
the whole dispute goes to the session unchanged. The ruling is one sentence per finding naming
that finding's own file, because that is what the landed reader covers and no more (C4): a
genuinely new C item in a later round still blocks.

The only write is the ruling, filed on the card exactly as
:func:`asf.tick.step_health.file_rulings` writes a session's — so the lane's merge gate
(:func:`asf.evidence.rulings.reraised_only`), every later brief
(:func:`asf.evidence.rulings.brief_section`) and this module's own idempotence
(:func:`waived`) read it back with no change to any of them.

Default off: ``conventions.flags.rule_pass`` (:func:`enabled`), the ``mechanical`` shape.
"""
```

**The dispute.** `dispute(product, row, items)` → `Dispute | None`: what is disputed, for the two
rows that have a finding (P1). For a correction row it is the pending correction and the review
body its finding came from; for a stage review-round row it is the item's newest
changes-requested review on the document branch. `None` for every other adjudicate row — the
attempts-exhausted ones (Out) and any row whose review cannot be read.

```python
@dataclasses.dataclass(frozen=True)
class Dispute:
    item: str          # the card the ruling is filed on
    branch: str
    finding: tuple     # lifecycle.finding_of's key — the C list's files (P11)
    entries: tuple     # [(label, text)] from rulings.c_entries
    where: str         # 'correction' | 'review-round', for the line and the event
```

**The classifier.** Three cosmetic classes, each named so the ruling can cite which; and the
never-waive set, which beats every one of them (C6).

```python
#: A finding about how the commits are arranged, not about the work in them.
COMMIT_SHAPE = ...   # squash, fixup, amend, reword, "one commit", "commit message|subject", "split the commit"
#: A finding about prose: a word, not a behaviour.
WORDING = ...        # typo, spelling, grammar, wording, phrasing, rephrase, capitalisation, punctuation, "the word"
#: A finding about layout.
FORMATTING = ...     # blank line, trailing whitespace, line length, columns, indentation, import order, alphabetise
COSMETIC = (('commit-shape', COMMIT_SHAPE), ('wording', WORDING), ('formatting', FORMATTING))

#: What no rule waives, whatever else matches. The first four are the adjudicate brief's own
#: ("FOUR THINGS ARE NEVER YOURS", P14); the rest are the words that make a finding a claim about
#: behaviour rather than about appearance.
NEVER_WAIVE = (
    LICENCE,    # licence, license, copyright, NOTICE, attribution
    MONEY,      # cost, spend, budget, billing, price, quota, usd
    SECURITY,   # security, credential, secret, token, password, auth, injection, redact, CVE
    CUSTOMER,   # customer, user-visible, UI, API contract, breaking change, migration, deprecat
    CORRECTNESS,# bug, defect, wrong, incorrect, crash, raise, exception, regression, race, leak, "does not", "never returns"
    COVERAGE,   # "no test", untested, "does not cover", "not pinned"
)
```

`classify(text)` → `'commit-shape' | 'wording' | 'formatting' | ''`: `''` the moment any
`NEVER_WAIVE` pattern matches, whatever a cosmetic pattern says; otherwise the first cosmetic
class that matches; `''` when none does.

**The rules.** Each takes the dispute and one finding and returns a `(rule, why, cite)` triple or
`None`. `rule(product, dispute, items)` runs them over every finding, in order, and returns a
`Ruling` only when every finding is answered (C5):

```python
@dataclasses.dataclass(frozen=True)
class Ruling:
    rules: tuple       # the rule names that fired, in finding order
    text: str          # the ruling paragraph — one sentence per finding (C4)
    cites: tuple       # the citations, for the [precedent: …] suffix
    finding: tuple     # the key this ruling waives (C7)
```

* `cosmetic(dispute, label, text)` — `classify(text)` is non-empty. `why`:
  `f'{label} is overruled as cosmetic ({cls}){over}: {CLASS_WHY[cls]}'`, where `over` is
  `` f' over `{path}`' `` for the first repo path the finding names (`review.C_PATH_RE`) and `''`
  when it names none — the per-file scoping P5 measured, and the one case where an unscoped
  sentence is correct because the finding is unscoped too.
* `precedent(dispute, label, text)` — in this order: `rulings.covers(standing, label, text)`
  returns a job → `cite` is that job and its stamp; else the finding's own text names a `D-nnnn`
  or a `docs/decisions/` path that `precedent.entries(product, items)` confirms with a status
  outside `STALE_STATUS` → `cite` is `f'{id} — {title} · {path}'`. A decision the register does
  not confirm, or confirms as superseded/rejected/withdrawn/draft/proposed, is not precedent and
  the rule stands down (`precedent.STALE_STATUS`'s own reason: a superseded decision reads as
  settled and is not).

**The line it files.** One function, so the shape is in one place and matches `file_rulings`':

```python
def history_line(ruling, now=None):
    """The ``## History`` line, in file_rulings' own shape with two bracketed suffixes:

        - 2026-10-08 10:30 adjudicate (rule-pass): <ruling.text> [rule: cosmetic; finding: asf/flake.py] [precedent: …]

    ``JOB = 'rule-pass'`` is the job every later reader sees — `rulings.HISTORY_RULING_RE` binds
    it as ``[^)\\s]+`` and `covers` answers with it (P4), so a review the gate reads says in one
    word that a rule, not a session, settled it."""
```

The `[precedent: …]` half is `precedent.history_note`'s own grammar, reused verbatim so
`precedent.named` reads a rule pass's citation exactly as it reads a session's, and
`[precedent: none]` when the `cosmetic` rule fired and there is nothing to cite.

**Idempotence.** `waived(product, item, finding)` → the stamp of the rule-pass ruling that already
waived this exact key, or `''`: `rulings.standing(product, item)` filtered to `job == JOB`, its
`[finding: …]` suffix parsed and compared to `finding` (C7). This is the one function both its
callers share — `screen()`, to skip a dispute it has already ruled, and `waivers`, which asks it
the same question for both feeder branches (C8, C11).

`apply(product, row, items, out, dry_run=False)` ties it together and is total: `enabled` →
`dispute` → `waived` (already ruled: stand down, quiet) → `rule` → the card write and the event,
or, under `dry_run`, the same answer with nothing written. Any exception inside it is one line and
a stand-down — a rule pass that cannot read a review never holds a row the wave would otherwise
launch.

### What it looks like when it is there

A spec branch at `spec-review r4` whose C list asks for a squash and a docstring rewording is not
handed to a model. The wave says
`ruled adjudicate-f-0312 F-0312 — rule pass: cosmetic (commit-shape, wording) over docs/specs/f-0312.md — ruled, no session`,
files `- 2026-10-08 10:30 adjudicate (rule-pass): C1 is overruled as cosmetic (commit-shape) over
`docs/specs/f-0312.md`: … C2 is overruled as cosmetic (wording) over `docs/specs/f-0312.md`: …
[rule: cosmetic; finding: docs/specs/f-0312.md] [precedent: none]` on the card, and takes no seat.
On the next pass the lane's merge gate reads the same review through `reraised_only`, finds every
C item settled, neither sends the branch BACK nor counts a round, and the branch goes on to land.
The next reviewer's brief carries the ruling as binding, so the point is not raised again.

A C list whose third item says `check_gate` drops a required check is not waived: the row launches
the adjudicate session exactly as today, and the session gets the whole dispute. A C list asking
for a wording change in a licence header is not waived either — `NEVER_WAIVE` beats the match, and
licence is never the adjudicator's, let alone a rule's.

A dispute the pass already ruled, whose C list then gains a new finding, is STALEMATE again and
buys its session: one waiver per finding, and the finding changed.

| the waiver's identity | the same line's `[finding: …]` suffix | `lifecycle.finding_of`'s key for the dispute — the C list's files (P11). Read back by `rulepass.waived` — the pass's own idempotence, and `plan_inputs`' `waivers` map, which asks it for both feeder branches (C7, C8, C11) |
| the event | `screen()` → `ctx.event('rule_pass', …)` → `metrics/events/<day>.jsonl` | `{kind: 'rule_pass', item, rule, finding, where, cite, product, ts}` — the only count of what the pass saved, and what S-77107's cell reads. No session is spawned, so the scorecard's repair load falls by construction (P15) |

Nothing is written to origin by the pass itself: no ref, no branch, no comment, no PR. The one
card write goes into the tick's own record clone, which the tick commits and pushes as it does

the landed merge gate does the rest from the ruling alone (Out).
