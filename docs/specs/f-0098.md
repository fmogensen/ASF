# F-0098 — one classifier for a run's state

On 2026-09-23 every session `asf status` and `asf sessions` called **dead** turned out to have
finished normally: `fix-bug-b-0080`, `fix-bug-b-0083`, `fix-bug-b-0069`, `coder-t-0052`. The next
tick recorded each as `finished` and landed most of them. The word was wrong, and for up to one
tick interval (10 minutes) the seat each one held was counted as taken.

The relabel is not the fix. Six readers derive a run's state independently, off different inputs:

| Reader | Derives from | Says |
| --- | --- | --- |
| `views.status.agents_cell` | `sessions.live_rows` → pid | `<n> working, <n> dead` |
| `views.sessions.render` | the registry + pid | the **Dead** table |
| `capacity.inflight_sessions` → `tiers.free_slots` | `lifecycle.is_live` (the ledger alone) | the seat is taken |
| `pool.Pool.load` / `wave` | `lifecycle.live_all` → `is_live` | the account is at its cap |
| `tick.summary.inflight_rows` | pid | `status: dead pid` |
| `workers.stall.classify` | the log + pid | `DEAD` |
| `workers.health.health` | the ledger + `lifecycle.judge` + git | writes `ended`, `end_reason` |

Only the last one looks at the evidence. The other six guess, they guess differently, and the
next state anyone adds will be guessed six more ways. This spec puts one function in
`asf.workers.lifecycle` between the evidence and every reader, and deletes each reader's own
derivation.

## 1. Decisions

### 1.1 In

- `lifecycle.classify(run, ev) -> Status` — pure, five states: `working` ·
  `ended-awaiting-tick(result)` · `finished` · `failed(reason)` · `dead(reason)`.
- `lifecycle.state_of(product, run, alive=None) -> Status` — the one impure entry point: gathers
  the evidence by the ladder of §2.2, then classifies. Every reader calls one of these two.
- `lifecycle.seats(rows)` / `holds_seat(status)` — the seat question, answered by the classifier
  and nobody else. `capacity.inflight_sessions`, `tiers.free_slots` and `Pool.load` route through
  it, so an ended run's seat frees the moment its process is gone.
- `lifecycle.derive` re-expressed over `classify`, so the branch lifecycle (`launched … reaped`)
  and the session state cannot contradict each other.
- The six readers above, each reduced to rendering what the classifier returned.
- `DEAD_PID` (`'dead pid'`) retired as a written `end_reason` in favour of the honest set of
  §4; both texts still read as dead, so ledgers already on disk classify correctly.
- `tests/test_lifecycle.py::SessionStateInvariants` (the classifier), and one structural test
  asserting no module outside `lifecycle` computes a state word.

### 1.2 Out

- **F-0089's end-of-run record.** The card names it as a source. It is not in the tree (no
  reference to it in `asf/` or `docs/`), so the classifier reads the end-of-run evidence that
  exists today: the log's last-run `result` line (`runtime.read_result`) and the typed REPORT it
  carries (`workers.report.parse`). `Evidence` is a dataclass with null defaults; when F-0089
  lands, its record is one more field on it and `classify`'s rule 3 reads it first. Nothing in
  this spec is blocked on it, and nothing here needs revisiting when it arrives.
- **Shortening the tick interval, or a watcher that records an end the moment a process exits.**
  The gap between ticks stays; this spec makes every reader honest *inside* it.
- **Freeing the item, the worktree or the branch early.** Only the *seat* is released at once.
  The item stays busy, `spawn.may_launch` still refuses the worktree, and the wave still says
  `already running`, until health writes the `ended` line — see the choice row on B-0025.
- **Changing what health writes, or when.** Health still writes exactly one `ended` line per run,
  at the tick. It now takes the reason from `classify` rather than computing its own.
- **`asf metrics`' `result` column.** It reads `end_reason` off the ledger
  (`metrics.py:916`) and keeps doing so; it sees the new reason texts and needs no change.

### 1.4 The choices

| Choice | Chosen | Against | Why |
|---|---|---|---|
| Where the classifier lives | `asf.workers.lifecycle`, beside `judge` and `derive` | a new `asf/workers/state.py`; `asf/views/` | The card names the module, and `judge` — the atom every state rests on — is already there. A second module would be a seventh place state is derived from. |
| One function or two | pure `classify(run, ev)` + impure `state_of(product, run, alive)` | one function that gathers its own evidence | A function that shells out to git cannot be unit-tested over generated evidence, and `derive`/`judge` are already pure-with-evidence. The split keeps the invariant tests (§3.1) free of git. |
| What "dead" now means | the process is gone with **no** end-of-run record and nothing pushed; or the operator stopped it | the pid is gone | This is the card's rule. The four sessions of 2026-09-23 all had a result line, so all four now read `ended, awaiting tick (finished)`. |
| A stopped session | `dead(stopped by the operator)` | a sixth state, `stopped` | The card fixes the state set at five. An operator stop is a real death with a known reason, which is exactly what `dead(reason)` is for. |
| A run with no result line but a pushed branch carrying its own commits | `ended-awaiting-tick(pushed, no report)` | `dead` | The card: "the view derives its result where it can: … or its pushed branch". Work is on origin; calling that lost is the defect being fixed. `has_commits` is required, so B-0076's empty branch is not mistaken for work. |
| A run with no result line, nothing on origin | `dead(no end-of-run record, nothing pushed)` | `ended-awaiting-tick(unknown)` | Nothing says it ended well and nothing survived it. This is the residue "dead" was always meant to name, and it is rare. |
| What frees at once | the **seat** only (`Pool.load`, `free_slots`, `capacity.inflight_sessions`) | the seat and the item together | Freeing the item reopens B-0025: the feeder would emit a fresh row for an item whose branch is finished but not yet gated by harvest, and `may_launch` reuses an ended run's worktree — a second session on top of unpushed work with no correction text. The seat is what the wave was waiting for; the item was never the constraint. |
| How the seat count is expressed | each row of `lifecycle.inflight` / `live_all` carries its `state`, and `seats(rows)` counts | a second list of "seat-holding runs" beside the live list | The wave's `already running` guard needs the *whole* unrecorded set, and `Pool.load` needs the seat subset. One list with a state per row answers both and keeps one owner for the word. |
| A hand-written `--inflight` row with no `state` | holds a seat | counts as free | `asf next --inflight` is a what-if a person writes; the conservative reading is the one that does not over-launch. |
| The evidence ladder | no git when the ledger or the pid already answers | gather for every run | A recorded run needs nothing, a live run needs only its pid. Git — an `ls-remote` per run — runs only for the handful whose process just went, so the pool's cross-product load stays a file read. |
| `DEAD_PID`'s text | retired as a *written* reason, kept as a *read* one | rewrite the ledger; keep writing `dead pid` | Ledgers on disk carry `dead pid` on runs that are months old and must keep classifying as dead. Nothing rewrites history; the reader accepts both texts and the writer emits one. |
| The "nothing else derives state" test | a structural test over `asf/**.py` for the state words | a review checklist; a docstring | The card asks for a test. The tokens are greppable, `tools/check_generic.sh` is the house precedent for a token rule, and a checklist is what let six derivations exist. |

## 2. The design

### 2.1 `asf/workers/lifecycle.py` — the classifier

```python
WORKING = 'working'
ENDED_AWAITING_TICK = 'ended-awaiting-tick'
FAILED = 'failed'
DEAD = 'dead'
#: FINISHED ('finished') is reused: it is already the end_reason health writes.
SESSION_STATES = (WORKING, ENDED_AWAITING_TICK, FINISHED, FAILED, DEAD)

PUSHED_NO_REPORT = 'pushed, no report'
NO_RECORD = 'no end-of-run record, nothing pushed'
STOPPED_BY_OPERATOR = 'stopped by the operator'
DEAD_REASONS = (NO_RECORD, STOPPED_BY_OPERATOR)
#: read, never written: ledgers on disk carry this on runs health judged before F-0098
DEAD_PID = 'dead pid'

@dataclasses.dataclass
class Status:
    name: str                 #: one of SESSION_STATES
    result: str = ''          #: 'finished' | 'failed: …' | PUSHED_NO_REPORT — what it came to
    reason: str = ''          #: why, for failed and dead
    source: str = ''          #: 'ledger' | 'report' | 'branch' | 'pid' — what decided it

    @property
    def label(self):
        """What every view prints. One place, so the six readers cannot word it six ways."""
```

| `name` | `label` |
| --- | --- |
| `working` | `working` |
| `ended-awaiting-tick` | `ended, awaiting tick (finished)` · `ended, awaiting tick (failed: not pushed: 0 uncommitted file(s), 2 unpushed commit(s))` · `ended, awaiting tick (pushed, no report)` |
| `finished` | `finished` |
| `failed` | `failed: <reason>` |
| `dead` | `dead: no end-of-run record, nothing pushed` · `dead: stopped by the operator` |

`classify(run, ev)` — pure, in this order:

1. **The ledger recorded it** (`run['ended']`):
   - `end_reason == FINISHED` → `Status(FINISHED, result=FINISHED, source='ledger')`
   - `end_reason == STOPPED` → `Status(DEAD, reason=STOPPED_BY_OPERATOR, source='ledger')`
   - `end_reason` in `(DEAD_PID, f'{DEAD}: {NO_RECORD}')` — a death health recorded:
     - `ev.result is not None` → `Status(ENDED_AWAITING_TICK, result=judge(run, ev), source='report')`
       — the result landed after the check and the next tick re-judges it (B-0028);
     - else → `Status(DEAD, reason=NO_RECORD, source='ledger')`
   - anything else → `Status(FAILED, reason=end_reason, result=end_reason, source='ledger')`
2. **No `ended` line, the process answers** (`ev.alive`) → `Status(WORKING, source='pid')`
3. **No `ended` line, the process is gone, a result line exists** →
   `Status(ENDED_AWAITING_TICK, result=judge(run, ev, landing=lands(run, path)), source='report')`
   — `judge` is unchanged and returns `finished` or `failed: <reason>`, so the state a view shows
   now is exactly the `end_reason` the tick will write.
4. **…no result line, but `ev.remote_sha` and `ev.has_commits`** →
   `Status(ENDED_AWAITING_TICK, result=PUSHED_NO_REPORT, source='branch')`
5. **…otherwise** → `Status(DEAD, reason=NO_RECORD, source='pid')`

`holds_seat(status)` is `status.name == WORKING` — the one definition of a taken slot.
`seats(rows)` counts the rows of an inflight list whose `state` holds a seat (a row with no
`state` counts as one, §1.4).

### 2.2 `state_of` — the evidence ladder

```python
def state_of(product, run, alive=None, path=None):
    """The one call a reader makes. Gathers no more evidence than the answer needs."""
```

| The run | Evidence gathered | Cost |
| --- | --- | --- |
| carries `ended`, and not a recorded death | none — `Evidence()` | nothing |
| carries a recorded death (`dead pid`, `dead: …`) | the log's result line only | one file read |
| no `ended`, `alive(pid)` is true | `Evidence(alive=True)` | one `kill(pid, 0)` |
| no `ended`, the process is gone | `gather(product, run, alive=alive)` | the full git read |

`alive` defaults to `health.pid_alive`; every caller that already resolved identity liveness
(`health.alive_for`, `observe.identity_alive`) passes it in, so the classifier inherits F-0076's
rule rather than restating it.

### 2.3 `derive`, re-expressed

`derive` keeps its nine branch states and its signature. Its two `judge`-derived arms now read
the classifier instead of re-testing `run.get('ended')` and `end_reason`:

```python
    status = classify(run, ev)
    if status.name == WORKING:
        return State(RUNNING if ev.has_commits else LAUNCHED)
    if status.result == FINISHED:
        return State(PUSHED, FINISHED, rounds)
    return State(ENDED, status.result or status.reason, rounds)
```

The `landed`/`held`/`corrected`/`adjudicate` arms are untouched — they are about the branch, not
the session. `TRANSITIONS` is unchanged. The existing `StateMachineInvariants` tests
(`test_lifecycle.py:225`) are the regression net: `derive` must keep yielding only named states
over generated runs and evidence.

### 2.4 The seat

Three call sites, one meaning:

- `lifecycle.inflight(path, product=None, alive=None)` — each dict gains `'state'` from
  `state_of`. The list itself is unchanged (every run the ledger has not closed), so
  `rows.inflight_ids`, `groom_row` and `groom.policy.suppress` keep holding their items busy.
- `feeder.tiers.free_slots(inflight, capacity)` → `max(capacity - lifecycle.seats(inflight), 0)`.
- `capacity.inflight_sessions(name)` → `lifecycle.seats(lifecycle.inflight(path))`; through it,
  `inflight_sessions_elsewhere` and the operator total.
- `lifecycle.live_all(state_root, alive=None)` — every unrecorded run across products, each
  carrying its `state`. `Pool.load` / `lane_load` count only seat-holders; `Pool.from_config`
  passes `observe.identity_alive(observed, registered)`, which it already computed for the
  extras, so the pool's load becomes "processes that answer" at no extra cost. An observed extra
  is a running process by construction and carries `state: working`.
- `wave`'s `running` set reads the whole `pool.live` list, seat-holding or not: a job whose run
  the ledger has not closed is still `already running`.

Net effect: the wave that used to wait up to one tick interval for a seat gets it as soon as the
process is gone, while nothing about the *item* moves earlier than it does today.

### 2.5 The views

- **`views.sessions`** — `live_rows(product, alive, session_source)` returns
  `(working, ended_awaiting, dead)` (was `(working, dead)`), splitting on `state_of`. The header
  becomes `**SESSIONS** — 2 working · 1 ended, awaiting tick · 0 dead · 14 ended · 0 other`, and
  the tables are `Working`, `Ended, awaiting tick`, `Dead`. The last two carry one extra column,
  `Result` for the middle table (the derived result) and `Why` for `Dead` (`status.reason`).
  The module docstring's four groups become five.
- **`views.status.agents_cell`** — `2 working, 1 ended (awaiting tick), 1 dead` — a clause is
  dropped when its count is 0, and the `no session registry yet` line is unchanged.
- **`tick.summary.inflight_rows`** — `row['status'] = state_of(...).label`; the IN FLIGHT table's
  `status` column widens accordingly. `done_rows` is untouched.
- **`workers.stall.classify`** — `DEAD` only when `state_of` says `dead`; a session that ended
  and is awaiting the tick is not a stall and is not reported. `STALL` (alive but silent) is
  unchanged.

### 2.6 Health and harvest

- `health.health` takes the `ended` line's reason from `classify` rather than calling `judge`
  directly: `status = classify(s, ev, ...)`; a `dead` status writes
  `end_reason: dead: <reason>`, everything else writes `status.result`. The `publish_gap`
  (B-0056), the unpushed hold (B-0051/B-0075) and the empty-branch hold (B-0076) all key off the
  same reason text they do today. The re-judge arm (`end_reason == DEAD_PID`) widens to
  `end_reason in (DEAD_PID, f'{DEAD}: {NO_RECORD}')`.
- `harvest.reap_hold` — `'no finished line in its record'` plus a live-pid check becomes one
  question: `state_of(...).name == WORKING` → hold. The other reap rules (`reap_verdict`) are
  evidence-based and untouched, so nothing with uncommitted or unpushed work becomes reapable.

### 2.7 The rule that keeps it one

`tests/test_lifecycle.py::OneClassifierTest` greps every `asf/**/*.py` but
`asf/workers/lifecycle.py` for the state words as string literals — `'dead'`, `'dead pid'`,
`'working'`, `'ended-awaiting-tick'` — and for a direct `end_reason ==` comparison. Views render
`Status.label`; the three table *headings* in `views/sessions.py` are the one allowed exception
and are listed by name in the test, so adding a seventh derivation fails the suite rather than a
review.

## 4. Records

**Rows.** `~/.ASF/state/<product>/sessions.jsonl` keeps its shape; one field's vocabulary
changes. `end_reason`, as written from now on:

```
finished                                              unchanged
failed: <reason>                                      unchanged
stopped                                               unchanged (lifecycle.STOPPED)
dead: no end-of-run record, nothing pushed            replaces `dead pid`
```

Nothing rewrites a line already on disk: `dead pid` stays readable and classifies as
`dead(no end-of-run record, nothing pushed)` forever. No new field, no new file, no new event.

**Printed.** The four surfaces an operator reads, before → after:

| Where | Was | Is |
| --- | --- | --- |
| `asf status`, Agents | `0 working, 4 dead` | `0 working, 4 ended (awaiting tick)` |
| `asf sessions`, header | `0 working · 4 dead · 12 ended · 0 other` | `0 working · 4 ended, awaiting tick · 0 dead · 12 ended · 0 other` |
| `asf sessions`, tables | `Dead` holds four rows | `Ended, awaiting tick` holds four, each with its `Result`; `Dead: none` |
| `asf tick`, IN FLIGHT | `status: dead pid` | `status: ended, awaiting tick (finished)` |
| `asf workers health` | `ended fix-bug-b-0080 dead pid` | `ended fix-bug-b-0080 finished` (the result was there; only the reader was blind) |
| `asf workers stall` | `DEAD fix-bug-b-0080 silent 3m` | nothing — it ended, it did not stall |

**Not written.** The classifier records nothing of its own. Its state is derived on every read
from the ledger, the pid, the log and origin — the one recorded transition stays health's `ended`
line, exactly as `lifecycle`'s module docstring already promises.

## Stories

- S: One classifier in `asf.workers.lifecycle` maps a run and its evidence to one of five states, with the result derived from the end-of-run record or the pushed branch — acceptance: `tests.test_lifecycle.SessionStateInvariants` (§3.1), every rule of §2.1 over hand-built evidence
- S: `state_of` gathers no more evidence than the answer needs — nothing for a recorded run, a pid for a live one, git only for a run whose process just went — acceptance: `tests.test_lifecycle.SessionStateInvariants` (§3.1), with a `gather` that raises if called
- S: `derive` is re-expressed over the classifier, so the branch lifecycle and the session state cannot disagree — acceptance: `tests.test_lifecycle.StateMachineInvariants` (§3.1), unchanged and green over the new body
- S: The seat an ended session holds is released the moment its process is gone — acceptance: `tests.test_capacity` and `tests.test_workers.TestPick` (§3.2), one alive and one ended run counting as one seat
- S: The wave launches into the freed seat in the same tick, and still refuses to launch a job whose own run the ledger has not closed — acceptance: `tests.test_workers.TestWave` (§3.2)
- S: The item, the worktree and the branch stay held until the tick records the end, so B-0025's relaunch loop stays fixed — acceptance: `tests.test_feeder` and `tests.test_lifecycle.AwaitingHarvestInvariants` (§3.3)
- S: `asf sessions` shows Working, Ended-awaiting-tick with its result, and Dead with its reason — acceptance: `tests.test_views.SessionsViewTests` (§3.4)
- S: `asf status`'s Agents row counts the three groups and drops the empty ones — acceptance: `tests.test_views.StatusViewTests` (§3.4)
- S: The tick digest and `asf workers stall` read the classifier — an ended session is labelled, not called dead and not reported as a stall — acceptance: `tests.test_tick_summary` (§3.4) and `tests.test_workers.TestStall` (§3.5)
- S: Health writes the reason the classifier named, harvest's reap hold asks it, and no module but lifecycle derives a state — acceptance: `tests.test_workers.TestHealth`, `tests.test_harvest` (§3.5) and `tests.test_lifecycle.OneClassifierTest` (§3.6)
