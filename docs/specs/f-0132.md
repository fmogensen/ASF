# F-0132 — the name stays on the card that holds it

One migrated title ending in an account name blocked a push on the first customer install. The
title itself was never the problem: the redaction gate refuses the *file being published*, and the
author of that push had touched neither the card nor the name. ASF had copied the title into
derived text — a `## Backlinks` line on another card — and the gate refused the card the author
did touch.

Half of that is already closed. `b191575fd` put `title_scrub` between the record and the
`## Children` / `## Backlinks` sections, and I11 stands behind it as the net. What the probe below
shows is that the same title still reaches **two other derived writers**, and that the card that
holds the name is still flagged by nothing:

- `index.json`'s entry carries the raw title — and `index.json` is tracked, so the leak is
  published, and every reader of it (the release notes, the daily rollup, the roadmap, the board,
  the budget lines) copies the name out again;
- every groom line carries the raw title, three times over in the probe, in a file the record
  commits;
- `asf check` says nothing at all about the card whose title holds the name, so nobody is ever
  told which card to rename.

So this card is three seams and a rename prompt: put the scrub where the entry is built and where
the groom line is rendered, and make the check name the card that holds the name, with its line, so
the operator can end the problem at its source instead of scrubbing copies of it forever.

## Decisions

### In

| # | What | Where |
| --- | --- | --- |
| 1 | `asf check` flags a protected name or a secret in any **typed** field, at the card that holds it, on that field's line, naming the field and the pattern source — never the matched text | `asf/record/check.py` |
| 2 | The same finding, as a groom **fix line** in a section rendered only when it has lines; no answer slot, so `--apply` never treats it as a question | `asf/groom/groom.py` |
| 3 | No rendered groom line copies a protected name: `render_groom_file` scrubs each line's text after its token, so every section — and the digest that reads the file back — is covered at one seam | `asf/groom/groom.py` |
| 4 | No `index.json` entry copies a protected name: the title is scrubbed where the entry is built, which closes the release notes, the daily rollup, the roadmap, the board and the budget lines with it | `asf/record/core.py` |
| 5 | Legacy slug resolution stays symmetric: `_find_legacy` scrubs the incoming slug, because the entry it compares against is now scrubbed | `asf/record/match.py` |
| 6 | The two halves already landed — derived `Children`/`Backlinks`, and inbox intake — are pinned as regression tests under this Feature's acceptance | `tests/` |

### Out

- **The card's own title.** The card that holds the name keeps it. Scrubbing it in place would
  edit the operator's words behind their back and lose the only copy of what the title said; the
  check finding and the groom fix line exist so the operator renames it. Until they do, the name
  is confined to one file.
- **The intake *file name*.** `asf inbox` builds the intake file's name from the raw title
  (`asf/groom/inbox.py:133`), so a protected name in a title becomes a protected name in a path.
  Want 3 of the card is about the *title* of an intake card, and that is already done
  (`scrub_title`, `asf/groom/inbox.py:118`). The file name is a separate leak, at a level the scrub
  cannot reach without breaking the `inbox:<file>` token the groom answers by; it is named here and
  not built.
- **Rewriting what is already published.** The gate refuses new lines; a cleanup of the record's
  published history is an operator action (F-0075's own Out).
- **Transcripts and stdout.** `asf roadmap` and `asf backlog` print to a terminal and write
  nothing; they come out clean here only because they read `index.json`. Redaction on what a
  session prints is F-0062.
- **PR titles and bodies.** F-0075 records this as out and unbuilt; nothing here changes it.
- **New patterns, new sources, a new scanner.** This card writes no pattern. `redact.patterns`,
  `redact.scrub` and `redact.SCRUB_TOKEN` are used exactly as they stand.

### The choices

| # | Choice | Chosen | Against | Why |
| --- | --- | --- | --- | --- |
| D1 | Where the index entry's title is scrubbed | In `build_index_data`, where the entry is built | At each of the five readers of `index.json` | One seam instead of five, and the next reader is covered before it is written. P12 makes the leverage real: the release notes and the rollup never see a raw title again. The alternative is a list nobody remembers to add to — which is how this defect arrived. |
| D2 | Where the groom's titles are scrubbed | In `render_groom_file`, per line, after the line's token | In `_card_line` (P9: one function, 13 callers) | `_card_line` has no `root` and so no patterns, and threading a `scrub` through ten section builders is churn. Rendering is the last seam before the bytes; scrubbing there also covers `_proposal_line`, the conflicts lines, the inbox question lines and every `EXTRA_SECTIONS` line — and the digest, which reads the rendered file back. |
| D3 | Why after the token and not the whole line | Scrub the text following `- [ ] <token>` | Scrub the whole line | An `inbox:<file>` token names a file on disk. Scrubbing it would break the settle match (`_OPEN_INBOX_LINE_RE`) and the answer round-trip against a real file name. An id token has nothing to scrub. |
| D4 | The card's own title | Left as the operator wrote it; flagged, never edited | Scrubbed in place at intake or by `asf index` | The record must keep what the operator said. An in-place scrub would destroy the only copy of the title and still leave the account name in git history — and `asf index` would then rewrite cards on a config change. Flagging it makes the rename a decision, taken once, at the source. |
| D5 | Finding or warning for a typed field | A finding | A warning | The card asks for a flag; and P13 means this cannot newly refuse a commit over a name the record already carries — `HEAD`'s findings print as warnings. Only a *newly introduced* protected name in a typed field blocks, which is exactly the write worth refusing. |
| D6 | Typed fields only, or the machine block too | Typed | Every field | The machine block is ASF's own — states, stamps, ids. It is not where an operator writes a name, and scanning it would flag ASF's own vocabulary. The card says "any typed field (title first)". |
| D7 | Legacy slug resolution | `_find_legacy` scrubs the incoming slug | Keep a second raw title in the entry for matching | P15 proves the regression is real and P16 proves the symmetric scrub closes it. A second, raw copy of the title in `index.json` would re-publish the very name this card removes from it. |
| D8 | What the finding says | The field name and the pattern source | The matched text | F-0075 D8: a finding never repeats the leak it reports, so it is safe in a tick log or a transcript. |

## The design

### 1. The check names the card that holds the name — `asf/record/check.py`

`record_findings` grows one parameter beside the `scrub` it already takes, for the same reason
(P14: it is run against a scratch copy that has no name lists of its own):

```python
def record_findings(root, scrub=None, layout=True, shared=(), pats=None):
    ...
    if pats is None:
        pats = redact.default_patterns(root)
```

and one pass per card, ordered so the title is reported first:

```python
#: The typed fields a protected name is looked for in, title first — the field an operator
#: writes, and the one derived text quotes (F-0132).
def _protected_field_findings(rec, pats, add, find_line):
    """One finding per typed field whose value carries a protected name or a secret, at the
    card that holds it, on that field's line. The value is never repeated (F-0075 D8): the
    finding names the field and which source matched."""
    if not pats:
        return
    typed, _machine = frontmatter.split_machine(rec['meta'])
    keys = ['title'] + [k for k in typed if k != 'title']
    for key in keys:
        parts = []
        _flatten_strings(typed.get(key), parts)
        for pat in pats:
            if any(pat.regex.search(p) for p in parts):
                add(rec, find_line(rec, key),
                    f"{key}: carries a {pat.kind} ({pat.source}) — rename the card; "
                    f"derived text quotes this field")
                break
```

Called from the per-card loop in `record_findings`, beside the `bug without severity` and
`blockedBy` checks. `cmd_check_staged` passes the real root's patterns through, next to the scrub
it already passes:

```python
    scrub = title_scrub(root)   # the record's own scrub: a scratch copy carries no name lists
    pats = redact.default_patterns(root)   # … and no name lists means no findings, either
    ...
        base = record_findings(os.path.join(head_dir, prefix), scrub, layout=False,
                               shared=shared, pats=pats)
```

With P13, a name already on `HEAD` prints as `features/F-0001.md:3: warning: title: carries a name
(worker_pool.accounts) — rename the card; derived text quotes this field`, and the commit stands. A
name the commit *introduces* is `blocking:` and the commit is refused — at the card that holds it,
which is the card the author is writing.

### 2. The groom's fix line — `asf/groom/groom.py`

A new `EXTRA_SECTIONS` entry, so it renders only when it has lines (P11):

```python
#: Rendered only when it has lines: the cards whose own typed fields carry a protected name
#: (F-0132). Not a question — there is nothing to answer, only a card to rename — so the line
#: carries no ``→ answer:`` slot and ``--apply`` skips it (P10).
PROTECTED_NAMES = ('Protected names to fix', 'protected_names')
EXTRA_SECTIONS = [INBOX_QUESTIONS, REFUSED_QUESTIONS, OVER_BUDGET_QUESTIONS, PROTECTED_NAMES]
```

built from the same judgement the check makes, over the cards the groom already has loaded:

```python
def groom_protected_names(canonical, pats):
    """One fix line per card whose typed fields carry a protected name: what to do, never the
    name itself. The title is rendered through the scrub like every other groom line (§3)."""
    lines = []
    for iid, rec in sorted(canonical.items()):
        for key, kind, source in protected_fields(rec, pats):
            lines.append(f"- [ ] {iid} {rec['meta'].get('title', '')} — {key} carries a "
                         f"{kind} ({source}); rename the card, then `asf index`")
    return lines
```

`protected_fields(rec, pats)` is the one judgement §1's finding and this line both read, so the
groom and `asf check` can never disagree about which card is at fault. `build_groom_sections`
gains `pats=None` and fills `'protected_names'`.

### 3. No rendered groom line carries a name — `asf/groom/groom.py`

One seam, at the last point before the bytes (D2, D3):

```python
_LINE_HEAD_RE = re.compile(r'^(- \[[ xX]\]\s+\S+\s)(.*)$')


def _scrub_line(line, scrub):
    """A groom line's text scrubbed, its token left alone: the token is an id, or an
    ``inbox:<file>`` naming a file on disk that the answer round-trip matches against (D3)."""
    m = _LINE_HEAD_RE.match(line)
    return (m.group(1) + scrub(m.group(2))) if m else scrub(line)


def render_groom_file(date, sections, scrub=None):
    scrub = scrub or (lambda s: s)
    ...
            out.append('\n'.join(_scrub_line(l, scrub) for l in lines) + '\n')
```

Its one caller passes the record's scrub, `core.title_scrub(root)` — the same function the derived
sections already use, so the groom and a card's `## Backlinks` render the same title the same way.
The digest needs no change: it reads the rendered groom file back
(`digest.render_digest(..., groom_text, ...)`), so it inherits the scrub.

### 4. No index entry carries a name — `asf/record/core.py`

```python
def build_index_data(canonical, derived, scrub=None):
    """… ``scrub``: the title scrub every reader of ``index.json`` inherits (F-0132) — the
    release notes, the daily rollup, the roadmap, the board and the budget lines all read the
    title from here (P12), so this is the one place they are all covered."""
    scrub = scrub or _plain
    ...
        entry = dict(typed)
        if entry.get('title'):
            entry['title'] = scrub(entry['title'])
```

`index.refresh` already resolves `scrub` for the cards it rewrites; `write_index_json` passes that
same callable down, so one `asf index` leaves the cards and the index agreeing. `asf check`'s
`index_wrong` comparison reads `build_index_data` too, so both sides of the staleness check scrub
and an unchanged record still reports clean.

When the operator adds a name to a list, `default_patterns`' cache key changes (P2), `index.json`
reads stale, and the next `asf index` rewrites it. That is the intended behaviour: a newly
protected name is removed from derived text by the next index, not left until someone notices.

### 5. Legacy slugs stay symmetric — `asf/record/match.py`

The entry's title is now scrubbed, so the slug computed from it is the scrubbed slug (P16). The
incoming slug is scrubbed the same way, and both sides converge (P15):

```python
def _find_legacy(items, slug):
    """… A Feature's title in ``index.json`` is scrubbed (F-0132 §4), so the slug it yields is
    the scrubbed one; the incoming slug is scrubbed before it is compared, and a branch cut from
    the raw title still resolves (P15, P16)."""
    ...
    from asf import redact
    want = {slug, slugify(redact.scrub(slug, redact.default_patterns(None)))}
    return sorted(i for i, it in items.items() if it.get('type') == 'feature'
                  and slugify(it.get('title')) in want)
```

`legacy_id` resolution is untouched and keeps working either way (P15).

## Records

- **`index.json`** — no new field. One existing field changes value: an entry's `title` is the
  scrubbed title. Every reader of it (P12) therefore stops copying a protected name, and
  `build_index_data` is the only writer. A record whose operator has no name lists is
  byte-identical to today's.
- **`<record>/groom/<date>.md`** — no new field, one new optional section, `## Protected names to
  fix`, rendered only when a card holds one, after the answerable sections; and every line's text
  is now the scrubbed text. Tracked and committed by the record step, which is why it mattered.
- **`<record>/groom/<date>-digest.md`** — unchanged code, changed content: it reads the groom file
  back, so its lines are scrubbed too.
- **Cards** — nothing written. A card's own typed fields are never edited by this change (D4);
  its derived sections were already scrubbed (P3).
- **`asf check` output** — one new finding text per offending typed field,
  `<relpath>:<line>: <field>: carries a <kind> (<source>) — rename the card; derived text quotes
  this field`. Never the matched value (D8). Under `--staged` it is `blocking:` when the commit
  introduces it and `warning:` when `HEAD` already carries it (P13).
- **No new event, no new ledger row, no schema bump, no new product-config key, no new command.**
  The refusal ledger (`redactions.jsonl`) is the gate's and is untouched: this card's whole point
  is that the gate stops being reached.
