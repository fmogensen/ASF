# F-0126 — no footprint, no launch: the re-cut, the plan the trunk never got, and the park

A first customer's tick launched PLAN → CODE twice in one wave for Tasks whose cards carry no
`writes:` — Tasks a `asf migrate` pass minted from a pre-ASF plan whose `### Task N:` sections
never had the machine-read lines `stories:`/`writes:`/`after:`. The coder brief then says
`writes: (none)`, so every file the session would touch is outside its footprint and the only
honest report is `status: blocked`. Two model sessions, two worktrees, two slots, nothing written.

The same Feature showed the other two halves of the defect. Its spec and its plan both still sat on
unmerged pre-ASF branches, so no coder could have read the plan it was being launched from even
with a footprint; and each blocked run ended with an empty branch, which the factory holds as work
that was never pushed and hands straight back to another session on the same head. One of those
Tasks was an old-process "integrator" task whose job was to drive the product's legacy merge queue
— work no coder brief can carry at all.

This change closes all three: a Task with no footprint is never handed to a coder and is instead
re-cut by one reshape session per Feature; a Feature whose plan is not on the trunk feeds no
PLAN → CODE row and its plan branch is landed by the same pass that already lands an approved spec;
and a run that ends with nothing to land while its own report declares a question for a person is
parked, with the park lifting by itself when the card it could not build changes.

### In

- **No footprint, no launch — on both paths** (D1). `task_rows` keeps the row P1 describes,
  word for word. `delivery_rows` gains the same gate: a delivery at a build stage whose
  `_delivery_union` is empty gets a non-launching `WAITS ON writes` row and its lead is **not**
  appended to `running` — an empty footprint claims nothing.
- **One re-cut per Feature** (D2, D3). The first no-writes Task of a Feature, in the loop's own
  `(rank, id)` order, also gets a launching `RESHAPE → PLAN` row on `plan/<task id>`, whose reason
  names the missing lines. Every later no-writes Task of the same Feature keeps its waiting row and
  gets **no** second reshape row: they all live in one plan document, which one session re-cuts on
  one branch.
- **A second mode in the reshape brief** (D4), because P5's split is the wrong deliverable for a
  Task that is not too wide but unreadable. The template's binding line stops asserting a split, and
  the deliverable splits into two keyed on the row's reason: the split it carries today, and — when
  the reason begins `no writes:` — "add `stories:`/`writes:`/`after:` to this Task's section of the
  plan; mint no ids, split nothing, add no scope, and leave the Task's own id in place". The
  template is in the amendable set (P6), so this half lands as a console amendment, not a coder.
- **A plan that is not on the trunk feeds no coder** (D5). `plan_carrier(feature)` reads a new
  `PLAN_ON_BRANCH_RE`, the exact mirror of `SPEC_ON_BRANCH_RE`. A Feature at `plan-approved` or
  `building` whose plan has a carrier gets `land_plan_row` — PUSHED → LAND while the lane is on
  that branch, else APPROVED → LAND, which launches nothing — instead of its `task_rows`. Active
  Tasks are untouched: their rows come from `branch_rows`, which this arm never reaches.
- **The plan is found where a migrated card says it is** (D6). `_plan_home(meta, fev, ev, product)`
  mirrors `_spec_home` (P10) and ingest writes `plan on <carrier>` for a plan reached only by a
  typed `links.plan`. The Feature block's `plan_approved` reads `_plan_home`'s `on_trunk` in place
  of the bare `fev['plan_on_main']`, so a plan the trunk really holds counts however it was matched.
- **The landing pass lands a plan branch as it lands a spec branch** (D7). `land_spec.wanted`
  returns `(feature id, carrier, doc)` and also names a `plan-approved`/`building` Feature whose
  plan is on a branch; `adopt` carries `doc` into `branch_for`, `Lane.adopt`, the job name
  (`land-plan-<id>`) and both messages. `why_not_as_is` and the `landing-gate` correction need no
  change (P11), and the feeder already routes that correction to a STARVED → PLAN session.
- **A run that ends with nothing to land and declares a question is parked** (D8). In health's
  ended-run pass, before the UNPUSHED and empty-branch holds, a result whose
  `report.needs_input` is not None parks the run instead: a pending correction of the new kind
  `lifecycle.BLOCKED`, `parked: True`, `operator_flagged: 1`, a reason that quotes the question and
  names `asf unpark <item>`, and `card:` — `lifecycle.card_fingerprint(item)`, a digest of the
  card fields a session's work is cut from.
- **The park lifts by itself when the card changes.** Beside P15's closed-state release, health
  clears a `BLOCKED` correction whose stored `card` digest no longer matches the item's. The
  ingest that recorded the re-cut ran in the same tick's earlier step, so the wave launches the
  Task again the moment its card carries a footprint — without a person, and without losing the
  park's protection while the card stands as it was.

### Out

- **Changing the words of P1's row.** `WAITS ON writes` and its reason stay as the hotfix wrote
  them; a `NEEDS FOOTPRINT` action would be a new non-launching kind for every reader, table and
  golden to learn for no new fact (D3).
- **Making `plan_tasks` refuse to mint a Task with no `writes:`.** A card that is not minted is a
  Task the plan states and the record denies; the feeder's job is to not *launch* it. `asf check`
  already calls it a violation (P16), and this change gives it a route out.
- **Widening a no-writes Task's footprint automatically.** `asf.feeder.widen` widens a footprint
  from facts a run produced — there is no run here, and inventing `writes:` from a plan section
  the migration could not read is guesswork dressed as a rule.
- **Deriving the plan carrier for every Feature stage.** D5 reads the carrier at `plan-approved`
  and `building` only. A Feature still writing its spec has no business being asked where its plan
  is.
- **Refusing on the *absence* of evidence.** A Feature with no `plan on …` line at all keeps
  today's behaviour (D5): the gate needs a named carrier, so a product whose ingest never emits the
  line is never wedged by this change.
- **Parking a run that pushed its work and flagged a question.** `status: done`, pushed, with a
  `NEEDS OPERATOR:` line is a finished session raising something; it goes to review as it does
  today, and `asf stall`'s INPUT row (P13) is what surfaces the question. Only a run with **nothing
  to land** is parked.
- **A second exit from the park.** `asf unpark` (P14) stays the person's way out, unchanged. The
  card digest is the automatic one; no new command, no new flag.

### The choices

| # | Chosen | Against | Why |
| --- | --- | --- | --- |
| D1 | Gate `delivery_rows` on an empty union too | gate `task_rows` only, as the hotfix did | The delivery path launches from the same missing fact (P3), and a lead speaking for members with no `writes:` claims an empty footprint against every other running item. One defect, two doors. |
| D2 | One RESHAPE → PLAN row per Feature | one per no-writes Task | Every Task of a Feature is a section of **one** plan document. Two reshape sessions would write `docs/plans/f-….md` on two branches and collide in the lane; and the second would re-cut a file the first had already rewritten. |
| D3 | Keep `WAITS ON writes`; add the missing launch | rename the row `NEEDS FOOTPRINT` | The card offers either. The row already says the true thing; what was missing was a session that fixes it. A rename costs `tests/test_feeder.py`, the `asf next` goldens and every operator's habit, and buys no new fact. |
| D4 | A second mode in the reshape brief | a new brief kind, or reuse `plan` | A new kind is a row kind, a template, a `KINDS` entry, a budget class and an `ID_RANGE_KINDS` decision. The `plan` brief writes the whole plan and mints Task ids, which would orphan the very cards being repaired (P16: `plan_tasks` leaves a Feature that already has Task children alone). Reshape is already "change how this Task is cut, add no scope" — this is that, with a smaller cut. |
| D5 | The carrier gates `plan-approved` **and** `building` | `plan-approved` only | `building` is the stage where the wasted launches happened: a Feature with one Task landed and three New reads `building n/m`, and its New Tasks would keep launching against a plan the trunk never got. |
| D6 | Mirror `_spec_home` in ingest | read `links.plan` in the feeder | The feeder is a pure function of the index (P5 of §2.5's own rule): it may not run `git cat-file`. Where a document lives is ingest's answer, and ingest already has the machinery and the precedent. |
| D7 | Generalise `land_spec` over the document kind | a second module beside it | `why_not_as_is`, `spoken_for` and `Lane.adopt` are already document-agnostic (P11); a `land_plan.py` would be a copy of 90 lines to keep in step, and a new module inside both whole-tree fences. `JOB_PREFIX` is kept for the spec so no product's ledger loses the job name it already carries. |
| D8 | Park on the run's **own** declaration | a phrase list, or a counter (park after N) | The grammar every brief hands a session is the one thing it declared on purpose (P13, D5/D11 of F-0066). A counter spends the wasted sessions first, which is the whole defect. |
| D9 | Lift the park on a card-field digest | lift it on any record change, or only on `asf unpark` | Any change would lift on a stage or evidence line the tick itself writes, which is a relaunch loop with extra steps. `asf unpark` alone leaves a Task whose card was re-cut sitting parked until a person notices. The digest is over the fields the work is cut from, so the re-cut lifts it and nothing else does. |

## The design

### 1. `asf/feeder/rows.py` — the footprint gate and the re-cut

`task_rows` keeps its loop; one local carries the Feature's re-cut, and the no-writes branch grows
the second row:

```python
def task_rows(items, product, feature, busy, running, landed_shas=None):
    ...
    recut = None     # the one Task of this Feature a reshape session re-cuts (D2)
    for t in sorted(tasks, key=lambda v: (ix.rank(v), v['id'])):
        ...
        writes = t.get('writes') or []
        if not writes:
            # a coder with no declared footprint can neither be checked against the others nor
            # know what it may touch: it reports blocked and the slot is spent (first customer)
            out.append(Row(tier=2, kind=PLAN_CODE, item_id=t['id'], feature_id=feature['id'],
                           action='WAITS ON writes', brief_kind='task',
                           branch=branch_for(product, 'code', t['id']),
                           reason='no writes: declared: the plan must name the files this Task '
                                  'writes before a coder can start', waits_on='writes'))
            if recut is None:   # one plan document, one session, one branch (D2)
                recut = t['id']
                out.append(Row(tier=2, kind=RESHAPE, item_id=t['id'], feature_id=feature['id'],
                               action=LAUNCH, brief_kind='reshape',
                               branch=branch_for(product, 'plan', t['id']),
                               reason=NO_WRITES_RECUT))
            continue
```

with the reason a module constant, because the brief reads it (P5):

```python
#: The RESHAPE → PLAN reason for a Task whose card carries no `writes:` — a Task migrated from a
#: plan written before the machine-read lines existed. The reshape brief keys its second mode on
#: the leading `no writes:` (F-0126 D4).
NO_WRITES_RECUT = ('no writes: declared — this Task came from a plan section with no '
                   'stories:/writes:/after: lines; re-cut that section so it carries them')
```

`delivery_rows` gains the same refusal, before the conflict check, in the `code_stage` branch:

```python
        elif code_stage:
            union = _delivery_union(items, lead)
            if not union:       # D1: an empty footprint claims nothing and can build nothing
                out.append(Row(tier=2, kind=kind, item_id=lid, feature_id=fid,
                               action='WAITS ON writes', brief_kind=brief, branch=branch,
                               reason='no writes: declared on any open member: the plan must name '
                                      'the files this delivery writes before a coder can start',
                               waits_on='writes'))
                continue
            other = footprint.first_conflict(union, running, ...)
```

`continue` here means the lead never reaches `running.append` — an empty footprint is not a claim.

### 2. `asf/feeder/rows.py` — the plan that is not on the trunk

Beside `SPEC_ON_BRANCH_RE` and `spec_carrier`:

plan being landed never take each other's turn.

## Acceptance tests

## Records

Nothing new is stored, and no file is created. What the change writes down:

- **`asf next` / the wave's plan.** Three rows change or appear: `PLAN → CODE  WAITS ON writes`
  (unchanged, P1) now sits beside one `RESHAPE → PLAN  would launch` per Feature;
  `DELIVERY → CODE  WAITS ON writes` for a delivery with no footprint; and
  `APPROVED → LAND  WAITS ON landing: plan approved on <branch>` where PLAN → CODE rows used to be.
  Every one carries its reason, so the table says why nothing launched.
- **The record's evidence.** A Feature whose plan is reached only by its typed `links.plan` gains
  the line `plan on <branch>` (or `plan on origin/<trunk>`); the stage it derives is unchanged
  except that a plan the trunk really holds now counts as approved however it was matched.
- **The sessions ledger.** A landed plan branch gets a synthetic run under the job
  `land-plan-<feature id>`, exactly as a spec gets `land-spec-<feature id>`; one that cannot land
  gets that run BACK with a `landing-gate` correction.
- **The park.** On the run that reported it: `correction: {kind: blocked, text: <the report's
  question>, at: <now>, parked: true, reason: <the text naming `asf unpark`>, card: <digest>}` and
  `operator_flagged: 1`. On the pass that lifts it: `correction: null`, and a `released` line
  naming the item and the card change. `asf unpark <item>` still appends its own `unparked` stamp.
- **No new command, no new configuration key, no new row kind.** `RESHAPE → PLAN`,
  `APPROVED → LAND`, `PUSHED → LAND` and `PARKED` are the rows this change reaches for, and each
  already exists.
