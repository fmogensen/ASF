# F-0146 — the card's ask landed five days ago without a trailer; the absent index was never the stale one

The card asks that the record pre-commit rebuild and stage a stale `index.json` instead of
refusing, as `asf set` already does, and still refuse any real record error.

**That landed on the trunk on 2026-09-25**, in `458d358f1` — *"fix(check): the record pre-commit
regenerates and stages the index.json a hand edit leaves stale"*. The commit carries no item
trailer at all, so nothing closed F-0146 and the card is still `New` while its own sentence is
live code: `cmd_check_staged` (`asf/record/check.py:428`) calls `stage_derived`
(`:434-484`), which derives every card's Children/Backlinks and `index.json` from the staged
cards, writes each rewritten path into the commit's own `GIT_INDEX_FILE` with `hash-object` +
`update-index`, rewrites the working-tree copy when it held what was staged, and prints
`<path>: regenerated from the staged cards and staged`. Four tests pin it
(`tests/test_check_staged.py:148-181`), they pass in this checkout, and a real record error is
still refused after the regeneration runs.

So this spec does not re-mint the hook. What survives is one seam and one false instruction.

**The hook heals the index it finds wrong; it cannot heal the index it does not find.** The
trigger is `if now[2] - base[2]` (`:427`) — the third member of `record_findings`'s return,
`index_wrong`, the set of entries that differ between the cards and `index.json`. That set is
built only in the `else` (`:369-387`) of `if not os.path.isfile(index_path)` (`:367`): when `index.json`
is **absent**, `record_findings` appends the finding ``index.json is missing (run `asf index`)``
and leaves `index_wrong` **empty**. An empty difference means `stage_derived` is never called, so
in a record that has no `index.json`:

```
# a record whose index.json was never committed, one card retitled and staged:
index.json:1: warning: index.json is missing (run `asf index`)
2 pre-existing errors already on HEAD — not blocking
  -> exit 0, the commit lands, and index.json is still absent

# the same record, a staged card that gains `blockedBy: D-0001`:
decisions/D-0001.md:23: blocking: ## Backlinks section is stale (run `asf index`)
1 blocking error(s) — this commit is refused (not on HEAD, or worse than HEAD's)
  -> exit 1, the commit is refused, and nothing was regenerated
```

The second block is the card's own complaint, word for word — a hand edit refused for derived
state the commit's own change implies, told to run `asf index`. It survived `458d358f1` because
the fix keyed on the entries of a file that was assumed to exist. The path is not exotic: the
whole-record `asf check` already calls a missing `index.json` a finding
(`tests/test_backlog.py:765-768`), and `refresh(create_index=True)` — which `stage_derived`
already passes (`:461`, `asf/record/index.py:43`) — would have written one had it ever been
reached.

**The guide still orders the step the hook removed.** `docs/guide/operating.md:350`, step 3 of
*Clearing a card that does not belong*: "Run `asf index` in the checkout, then commit and push
the card and `index.json`." Retiring a card is a hand edit of the typed block — `asf set` cannot
write `removed:`, which is why that procedure is hand-edit-only — and it is exactly the hand edit
the hook now derives for. The one operator-facing page that tells a human to run `asf index`
after a hand edit is telling them to do the hook's work.

### In

1. `record_findings` fills `index_wrong` when `index.json` is absent — every entry the staged
   cards imply, against nothing on disk — so the `:427` trigger reads "the derived index this
   commit leaves wrong" whether the file is stale, unparseable or missing. `stage_derived` then
   writes and stages it through the `create_index=True` it already passes.
2. The three behaviours that follow, each with a test: a record with no `index.json` gains one,
   staged, in the commit; a staged **deletion** of `index.json` is re-derived and re-staged; and a
   Children/Backlinks section left stale beside a missing index is healed instead of refusing.
3. The missing-index message becomes the named constant `INDEX_MISSING`, beside `INDEX_STALE`,
   because it is now a message two functions reason about rather than a literal in one branch.
4. `docs/guide/operating.md` step 3 stops ordering `asf index` and names the hook that derives
   `index.json`, with `asf index` kept as the fallback for a checkout whose hooks are not enabled
   (P10). A test in `tests/test_readme.py` holds the page to it.

### Out

- **The record's standing debt.** The hook heals the derived state *this commit's change implies*
  — `now[2] - base[2]`, not `now[2]`. An `index.json` that is already stale on `HEAD` for a card
  the commit never names stays a warning and is not rewritten, exactly as today; `asf index`
  remains how a human clears that. This holds for the absent file too: if the staged change moves
  no entry at all, no index is derived. Pinned by a test, not left to drift.
- **Widening the trigger to every derived-state finding** (any new `## Children`/`## Backlinks`
  staleness, not just a wrong index entry). By P8 an entry difference is already the wider signal
  while the file exists, and the absent file is what this spec fixes, so the broader trigger would
  add a second rule that never fires alone. Rejected below.
- **`stage_derived`'s silent staging failure.** When `hash-object` or `update-index` fails it
  `continue`s (`:467-468`, `:470-472`) and the operator sees only the surviving finding, with no line
  saying the hook tried. Real, but it needs a forced git failure to test and it never turns a
  refusal into an acceptance — a separate card, not this one.
- **Closing F-0146 by asserting `458d358f1`.** The landing is recorded in the card's History as a
  precondition (below), not as a `landed:` sha: the sha is not this branch's work, and the trunk
  commit that closes this card is the one that lands the Stories.
- Any change to the whole-record `asf check`, to `asf index`, or to the finding text ``index.json
  is missing (run `asf index`)`` as that check prints it (`tests/test_backlog.py:765` stays green).

### The choices

| Choice | Chosen | Against | Why |
| --- | --- | --- | --- |
| Where the absent index becomes visible to the trigger | In `record_findings`, by filling `index_wrong` on the missing branch | A second condition in `cmd_check_staged` (`or 'index.json is missing' in now[0]`) | One function owns "what the derived index gets wrong"; the caller keeps one trigger. A message match in the caller is a third reader of a string, and the thing the trigger needs is already the set's meaning. |
| What to put in the set | One member per expected entry, `(iid, entry, None)` | A single sentinel member, `('index.json', …)` | The members are what `_report_staged` subtracts to decide whether an entry is *this* commit's fault. Per-entry keeps that arithmetic honest: a missing index on both sides with no entry moved yields an empty difference, which is the Out boundary above. A sentinel would fire on every commit into such a record. |
| Whether the hook may create a file the record does not have | Yes | Leave a record without an index alone and only warn | The whole-record `asf check` already calls the absent file an error (P1's sibling, `tests/test_backlog.py:765`), and every other writer creates it — `asf set`, `asf new`, `asf index` all go through `refresh(create_index=True)`. A hook that warns about a file it is equipped to write is the extra step the card exists to remove. |
| Whether a staged `git rm index.json` is healed or refused | Healed — re-derived and re-staged | Keep today's refusal, so an explicit deletion is not silently undone | The control plane reads `index.json` (E-0004); a record without it is broken, and the refusal's own advice — run `asf index` — tells the operator to recreate the very file they staged for deletion. Consistency with `asf set` wins: the derived file is the record's, not the commit's to remove. Named here because it is the one case where the fix overrides an explicit operator action. |
| Trigger shape | Keep `now[2] - base[2]` | `any new derived-state finding` | P8: while the file exists the entry difference already covers the sections. Out, above. |
| Guide wording | Name the hook, keep `asf index` as the fallback | Delete step 3 outright | P10: the hook is per-checkout config. A page that claims the index is always derived would be false in a checkout that never ran `asf init`. |

## The design

### 1. `record_findings` — the absent index is a wrong index

`asf/record/check.py`. The message joins `INDEX_STALE` as a constant (`:162`):

```python
INDEX_STALE = 'index.json is stale (run `asf index`)'
INDEX_MISSING = 'index.json is missing (run `asf index`)'
```

and the missing branch (`:367-368`) says what it leaves wrong, instead of only that it is wrong:

```python
    if not os.path.isfile(index_path):
        findings.append(('index.json', 1, INDEX_MISSING))
        # an index the record does not have is an index that gets every entry wrong: the
        # pre-commit derives it exactly as it derives a stale one (`cmd_check_staged`), rather
        # than refusing the commit that exposed its absence
        for iid, entry in expected_index['items'].items():
            index_wrong.add((iid, _key(entry), _key(None)))
    else:
```

`expected_index` is already computed one line above (`:366`), and `_key` is already the set's
member encoding (`:391-392`). Nothing else in the function changes. The docstring's description
of `index_wrong` — "the ``index.json`` entries that differ from what the cards derive" — is
already true of the new members; it gains a clause saying an absent file differs in all of them.

`cmd_check_staged` is untouched: `now[2] - base[2]` now sees the difference, calls
`stage_derived`, which calls `refresh(staged_root, scrub=scrub, create_index=True)` and writes
`index.json` into the commit's index and the working tree like any other regenerated path. The
re-check at `:429-430` then finds the file present and correct, so on the healed path the finding
is gone before `_report_staged` ever sees it. That is why the four lines above are the whole fix,
and why the probe below was run with nothing else changed.

`_report_staged` gains one guard for the path that is left — the staging itself failing (`:467-468`,
`:470-472`), where the missing finding survives the regeneration. It should then be judged the way
`INDEX_STALE` is, by the entry difference rather than by counting the message against `HEAD`
(`:494`):

```python
        if msg in (INDEX_STALE, INDEX_MISSING):
            new = bool(index_wrong - base_index_wrong)
```

This line changes no tested behaviour today — with the trigger fixed, both sides of the `or` agree
on every case the fences below exercise. It is in scope because leaving the two derived-index
messages judged by two different rules is the shape the original defect had.

### 2. The guide stops ordering the step

`docs/guide/operating.md:350`, step 3 of *Clearing a card that does not belong*:

> 3. Commit and push the card. The record's pre-commit derives `index.json` from what you staged
>    and sweeps it into the commit — there is no separate `asf index` step. (In a checkout whose
>    hooks are not enabled, run `asf index` first and commit both files.)

### What it looks like when it is there

A record whose `index.json` was never committed, or was deleted, or is a merge conflict's
casualty, behaves like every other record: the hand edit is staged, `git commit` derives the
index and the sections beside it, prints one `regenerated from the staged cards and staged` line
per path, and lands. The refusal ``## Backlinks section is stale (run `asf index`)`` cannot be
reached by a commit whose own change caused it. A parse error, a missing parent, a duplicate id,
an Active `writes:` overlap — every real record error still refuses the commit, after the
regeneration has run and been printed.

Measured against a checkout at `457dde4a4` patched with §1's four lines and nothing else (the
`_report_staged` guard not applied), they turn the two fences in
the preamble into `exit 0` with `index.json: regenerated from the staged cards and staged`
(`index.json` present afterwards: `True`), leave a broken card's `blocking: missing closing '---'`
refusing at `exit 1`, and leave a stale-on-`HEAD` index a warning that is not rewritten.
`tests.test_check_staged`, `tests.test_record_stage`, `tests.test_shared_paths` →
`Ran 83 tests … OK`; `tests.test_backlog.CheckCommandTests` → `Ran 28 tests … OK`.

## Acceptance tests

### A1 — the absent index is derived and staged, and the refusal beside it is healed

New tests on `StagedCheckTests` in `tests/test_check_staged.py`, so they run under
`HandWrittenHookStagedCheckTests` too (the record whose own pre-commit was rewritten by
`asf hooks install`). Each drops `index.json` from the record with
`git rm index.json` + `git commit --no-verify` before staging its hand edit.

- `test_a_record_with_no_index_json_has_one_derived_and_staged` — after `git commit` of a
  retitled card: exit 0, `index.json: regenerated from the staged cards and staged` in the
  output, `git show HEAD:index.json` carries the new title, `git status --porcelain` empty.
- `test_a_backlink_left_stale_beside_a_missing_index_is_healed_not_refused` — the staged card
  gains `blockedBy: D-0001`: exit 0, **not** `blocking: ## Backlinks section is stale`, and
  `git show :decisions/D-0001.md` carries `F-0001`.
- `test_a_staged_deletion_of_the_index_is_re_derived` — `git rm index.json` against a record that
  has one: exit 0, the file is back in the index.
- `test_an_index_stale_only_on_head_stays_standing_debt` — the Out boundary: a stale entry for a
  card this commit never names is a `warning:`, exit 0, and `index.json` on disk is **not**
  rewritten.

### A3 — the guide no longer orders the extra step

A new `HandEditIndexProseTests` in `tests/test_readme.py`, reading `docs/guide/operating.md` from

## Records

Nothing here is new persisted state: no new file, no new event stream, no migration, no schema
change.

## Stories

- S: The hook derives the index it cannot find — `record_findings` fills `index_wrong` with every entry the staged cards imply when `index.json` is absent, so the one trigger `cmd_check_staged` already has reaches the missing file as well as the stale one: a record with no index gains one in the commit, a staged deletion of it is re-derived, the ``## Backlinks section is stale (run `asf index`)`` refusal beside a missing index is healed instead of refusing, and an index stale only on `HEAD` stays the record's standing debt — acceptance: `python3 -m unittest tests.test_check_staged tests.test_record_stage tests.test_shared_paths -v`
- S: The guide stops ordering the step the hook took over — step 3 of *Clearing a card that does not belong* names the pre-commit that derives `index.json` from the staged card instead of ordering `asf index`, keeps it as the fallback for a checkout whose hooks are not enabled, and is held there by the first test this repo has over that page — acceptance: `python3 -m unittest tests.test_readme -v`
