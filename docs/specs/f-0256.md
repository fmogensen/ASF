# F-0256 — the queue knows whose red it is two lines later, and for a Python test failure it never knows at all

A merge-queue batch of three PRs went red. The drop reason read

```
merge queue: batch batch/20261007-090725-ebb2746 dropped — red on gate (skipped), gate-tests (skipped)
```

and the operator went diff-grepping. That line is `_drop(lane, batch, f'red on {why}')`
(`asf/merge_queue.py:801`), and `why` is the failing checks' names and nothing else.

Two separate things are wrong, and the second is the one the card's own example trips on.

**1. The queue already knows, and does not say it in the drop reason.** `blame`
(`asf/merge_queue.py:1573`) maps the failing job's log to the members' diffs and names the culprit;
when it succeeds, a *later* line says so. Measured in this checkout (`tests.test_merge_queue.Culprit`,
instrumented — the whole captured output of that pass):

```
merge queue: batch batch/…-ebb2746 dropped — red on gate (skipped), gate-tests (skipped)
lane: push batch/…-ebb2746 0.0s (delete)
merge queue: batch/…-ebb2746 red on gate (skipped), gate-tests (skipped) — the failure is #1's (its files, named in the failing job's log); #2, #3 cut again without it
```

The drop reason is written at `:801`; the culprit is computed at `:824` and said at `:839`, with an
unrelated push line between them. The answer exists, one pass, three lines apart — and the reader
who stops at the word *dropped* never gets to it.

**2. For a Python test failure the queue knows nothing.** The card's case is a known-gap test that a
member's new audit writes broke. The failing job's log names the test's own file, in a traceback, and
`blame` reads neither the shape nor the hop. Measured here against a real unittest log:

| Log line | `_PATH_LINE_RE` | `_BARE_PATH_RE` |
| --- | --- | --- |
| `  File "/home/x/work/o/p/tests/test_audit.py", line 42, in t` | `[]` | `[]` |
| `FAIL: test_x (tests.test_audit.AuditGap.test_x)` | `[]` | `[]` |
| `tests/test_audit.py:42: AssertionError` (pytest's short traceback) | `[('tests/test_audit.py', '42')]` | — |
| `FAILED tests/test_audit.py::AuditGap::test_x` (pytest node id) | `[]` | `['tests/test_audit.py']` |
| `FAIL  src/audit.test.ts > writes nothing` (vitest) | `[]` | `['src/audit.test.ts']` |

`_PATH_LINE_RE` wants `path:line`; a traceback writes `", line 42"`. `_BARE_PATH_RE`'s lookbehind
`(?<![\w@./-])` cannot start a match after a `/`, so every segment of an absolute runner path is
blocked. `red_tests` (`asf/harvest/lane.py:5160`) reads node:test, vitest, jest and TAP marks and
returns `[]` for `FAIL:` with a colon. So `failure_findings` yields `paths: []`, `blame` returns
`{}`, and the batch is bisected blind — one level of split per CI run, the innocent members waiting
out every one.

And even in the three rows the readers *do* catch, the test file is in **no member's diff** — that is
why the test is a known gap: the member changed the source, not the test. `_owns`
(`asf/merge_queue.py:1534`) only matches a log path against a member's own changed files, so a test
file nobody in the batch touched owns nothing and names nobody.

The hop the queue is missing is one the product's own test gate already makes, in the other
direction. `tools/run_tests.py:touched_modules` selects the test modules a change touches: a module
that imports a changed source module, or is named after it. Read backwards, that is exactly *whose
files this failing test covers*. Measured here, the inverse predicate over this repo:

| Failing test module | Candidate changed files | Covers |
| --- | --- | --- |
| `tests/test_merge_queue.py` | `asf/merge_queue.py`, `asf/release.py`, `README.md` | `asf/merge_queue.py` |
| `tests/test_scorecard.py` | `asf/scorecard/score.py`, `asf/merge_queue.py` | `asf/scorecard/score.py` |
| `tests/test_hooks.py` | `asf/hooks.py`, `asf/redact.py` | `asf/hooks.py` |
| `tests/test_queue_reap.py` | `asf/merge_queue.py`, `asf/dwell.py` | `asf/merge_queue.py` (by import, not by name) |
| `tests/test_brief_facts.py` | `asf/briefs/facts.py`, `asf/tune.py` | `asf/briefs/facts.py` |

It discriminates: no decoy was named. That symmetry is the whole design — **if the product's own
`--touched` selection would have run this test for that member's diff, then this test failing blames
that member.**

### In

- **`merge_queue.test_paths(item)`** — the test files a failed check's log names, as
  `[(path, line, text)]`, read from the two shapes the current readers miss: a traceback's
  `File "<path>", line <n>` (absolute or relative) and a unittest/pytest header's dotted module
  (`FAIL: t (pkg.mod.Class.t)` → `pkg/mod.py`). It is a **new, separate** reading: `failure_findings`
  grows one key, `item['test_paths']`, and `item['paths']` is computed exactly as it is today (P4,
  P5).
- **`merge_queue.repo_path(lane, batch, path)`** — a log path reduced to a path in the batch's tree,
  by trying its suffixes from the longest against `git cat-file -e <base>:<suffix>`; `None` when
  none exists. This is what turns `/home/x/work/o/p/tests/test_audit.py` into
  `tests/test_audit.py` without `_owns`'s need for a member file to match against (P6, P16).
- **`merge_queue.covers(text, test_path, files)`** — of `files`, the ones a test file covers:
  `files` whose dotted form the test's text names, or whose leaf the test's own name is
  `test_<leaf>` / `test_<leaf>_*`. The inverse of the product's own touched-test selection (P13),
  implemented in the package because the queue may not reach for the product's tooling (P14).
- **`merge_queue.cover_blame(lane, batch, members, found)`** — `{branch: [(path, line, text)]}` from
  the cover hop: for each test path the log named, read that file at `batch['base']` and name the
  members whose changed files it covers. The recorded path is **the member's own covered file**, at
  line `0`, with the finding's line as its text — so `_send_back`'s `files` stays a list of files
  the culprit can act on (P9).
- **`blame` gains a fallback, not a widening** — the direct reading runs first and unchanged; the
  cover hop runs **only** when the direct reading named nobody, and its result goes through the same
  two no-verdict rules (nothing mapped, or every member named → `{}`, the batch splits as before,
  P7).
- **The drop reason names the culprit.** `run` computes the blame before it drops, and `_drop`'s
  `why` becomes `red on <why> — #N's (<how>)` for a single named culprit, where `<how>` is
  `its files, named in the failing job's log` or `the failing test <path> covers its files`. With no
  culprit it reads exactly as it does today. The one string reaches the operator's line and the
  cancel claim together (P2).
- **`culprit_text`'s `where` clause tells the truth about the hop** — the existing wording for a
  direct hit, and `the failing test <path> covers files only this PR changes, the others are cut
  again without it` for a cover hit (P8).
- **A cover-derived culprit is never held out of the queue.** `hold_culprits` is called only for
  culprits the log named directly; a cover hit is sent back and named, and its next head is batched
  as usual (P10).

### Out

- **The gate ledger line is not touched.** `_ledger`'s `line` is the scorecard's signature input, and
  P11 measures that a culprit clause changes `_sig_class` — one class becomes two, across a scheme
  boundary `diagnose.schemes` was built to see and that nothing writes (P12). The card asks for the
  *drop reason*; buying it at the price of a silent signature change is not the trade. Carrying the
  culprit into the gate ledger belongs behind `signature_scheme: 2`, and that is a card of its own.
- **`asf.harvest.lane.red_tests` is not widened.** It returns *test names* for the correct brief's
  `Failing tests:` block, and it is read by every red round in the factory, not only a batch's. Its
  blindness to `FAIL:` (P4) is a real adjacent gap, named here and fixed nowhere in this card: the
  new reading needs test *paths*, lives beside the blame that consumes them, and changes no brief
  that exists today.
- **No new `conventions.merge_queue` key.** The cover hop only ever fires where the batch would
  otherwise have been split blind, and a wrong answer there costs one send-back instead of one CI
  run per split level. There is nothing for a product to turn off that it would not rather have
  (P17).
- **The innocent members' wait text is unchanged.** Naming the culprit to the PRs that were cut
  again is a different line with a different reader, and the card is about the drop reason.
- **`post_queue_status` is unchanged** — it posts on a green batch only, just before the trunk push.
- **No bisect change.** When nothing names a member the batch still splits in halves, by the same
  arithmetic. This card only narrows how often that happens.
- **No product tooling is called or named from the package** (P14): the cover predicate is
  reimplemented in `asf/merge_queue.py`, and the symmetry with the product's own gate is an argument
  in this document, not an import.
- **No test directory, suffix or runner is hardcoded.** Every test path comes out of the log and is
  confirmed against the batch's own tree (P14).

### The choices

| # | Chosen | Against | Why |
| --- | --- | --- | --- |
| D1 | **Compute the blame before the drop, and put the culprit in `_drop`'s `why`** | Leave the order alone and add a second line after the drop | The second line already exists (P3) and is exactly what the card says is not enough: the reader who sees *dropped — red on gate* stops there. Moving the computation up is a reorder inside one branch of `run`; `_drop` is pure output and a cancel claim (P2), so nothing it does depends on running first. |
| D2 | **The culprit clause goes in the drop line and the cancel claim; the gate ledger keeps its text** | Put it in `_ledger`'s line too, so the durable record carries it | P11 is measured, not feared: the signature class changes, and P12 shows the field that would version it is read and never written. A card about a drop reason should not move the scorecard's grouping key as a side effect. |
| D3 | **A new reading (`test_paths`) beside `paths`, not a widened `_PATH_LINE_RE`** | Teach `_PATH_LINE_RE` the `", line N"` shape and let the traceback paths flow into `paths` | Those two sets want different handling. A path in `paths` is matched against members' diffs (`_owns`); a test path is the start of a hop *away* from the diffs. Merging them would feed traceback noise — every library frame in a stack — into the direct reading, whose precision is the reason a culprit can be sent back at all, and would trip the "every member named" rule (P7). |
| D4 | **The cover hop is a fallback, never a peer** | Run both readings and union the hits | A log that names a member's own file is the strongest evidence the queue has, and the current behaviour rests on it (P8, P10). A cover hit is weaker by construction — it says *this test exercises your code*, not *your code is in the error*. Unioning would let the weaker reading dilute the stronger one into "every member named", which is a blind split (P7): strictly worse than today. |
| D5 | **The inverse of the product's own touched-test predicate** | A coverage run (`coverage.py`, `--cov`) over the failing test; or the test's git history | A coverage run is a second CI run on the batch sha — the exact cost the blame exists to avoid — and needs a product-specific runner the queue may not name (P14). History is weaker still: a test and a source file that changed together once need not cover each other. The import-and-name predicate is one blob read, is already the selection the product's gate trusts, and discriminates on this repo (P13). |
| D6 | **The recorded path for a cover hit is the member's covered file, line 0** | Record the test's path, as the direct reading records the path it found | `_send_back` hands those paths to the session as the files to look at (P9). The test file is not the member's to change — that is what *known gap* means. Line `0` is the established "no line" marker the direct reading already uses for a bare path (P5). |
| D7 | **A cover-derived culprit is sent back but never held out of the queue** | Hold it like any other named culprit | P10: a hold freezes a PR out of every cut until its head moves. The direct reading earns that by naming the member's own file in the error; the cover hop does not. Sending back is reversible in one pass; a wrong hold needs a human or a push. |
| D8 | **`culprit_text`'s `where` clause states which hop found it** | One wording for both | The clause is a claim about evidence (P8), and a session told *the log names files only this PR changes* when the log did no such thing will go looking for a line that is not there. | D9 | **No new convention key** | A `merge_queue.cover_blame: on` switch, off by default | The hop fires only where the alternative is a blind split, and the blind split's cost is a CI run per level with the innocent members waiting through all of them. A default-off switch would mean nobody gets the card's fix; a default-on switch is a key that exists to be left alone (P17). |

## The design

### 1. `test_paths(item)` — the failing test's own file, read off the log

`failure_findings` keeps every line it keeps today and grows one key per check:

```
item = {'name', 'link', 'step', 'cmd', 'tests', 'lines', 'paths', 'test_paths'}
```

`test_paths` is filled from `item['lines']` by two patterns, in this order, each path once:

- `_TB_FILE_RE` — `File "(?P<p>[^"\n]+\.[A-Za-z0-9]{1,8})", line (?P<n>\d+)` — a Python traceback
  frame, absolute or relative. Gives `(path, line, the stripped line)`.
- `_TEST_DOTTED_RE` — `^(?:FAIL|ERROR):\s+\S+\s+\(([\w.]+)\)` — a unittest header's dotted test.
  The dotted name is reduced to a path by dropping trailing segments until one resolves in the tree
  (§2): `tests.test_audit.AuditGap.test_x` → `tests/test_audit.py`. Line `0`.

Whatever the direct reading already catches (pytest's short traceback, a node id, a vitest `FAIL`
line — the three rows of the table above) is caught here too, because those lines are in
`item['lines']` and the hop in §3 is a no-op when the path is already in a member's diff: a path the
direct reading owns never reaches the fallback (D4).

`item['paths']` is computed from the same lines by the unchanged code, including its
`if not item['paths']` bare-path fallback (P5). Neither reading can raise: a check whose log does not
read keeps `test_paths` empty, as it keeps `paths` empty today.

### 2. `repo_path(lane, batch, path)` — a log path, as the tree spells it

A runner writes `/home/x/work/<owner>/<repo>/tests/test_audit.py`; the tree holds
`tests/test_audit.py`. `_owns` solves this today by matching against a member's file list (P6), which
is precisely the list a known-gap test is not in.

```
repo_path(lane, batch, path) -> 'tests/test_audit.py' | None
```

Split the path on `/` and try the suffixes from the longest, each against
`git cat-file -e <batch['base']>:<suffix>` in `lane.repo`. The first that exists is the answer; none
exists, `None` — a path from a vendored checkout, a tool's own source, a frame in the standard
library. The same reduction serves the dotted form: `pkg.mod.Class.test` → try `pkg/mod/Class.py`,
`pkg/mod.py`, … against the tree, longest first.

The base is already fetched when `judge` returned `red`, and one `cat-file -e` per candidate is a
local read (P16). Results are memoised per pass.

### 3. `covers(text, test_path, files)` — whose files this test covers

Pure, no git, no host:

```
covers(text, test_path, files) -> [the files of `files` the test covers]
```

For each `f` in `files` that looks like a source module (a dotted extension, at least one `/`), with
`dotted = f` minus its extension, slashes to dots, a trailing `.__init__` dropped, and
`parent, leaf = dotted.rpartition('.')`:

- `text` matches `\b<dotted>\b` — the test imports or names the module; or
- `text` matches `^\s*from <parent> import [^\n]*\b<leaf>\b` — the `from … import` form; or
- the test file's own stem is `test_<leaf>` or starts with `test_<leaf>_` — named after it.

That is `touched_modules`' predicate, read backwards (P13), written out here because the package may
not reach for the product's tooling (P14). It is the one place the mapping lives.

### 4. `cover_blame(lane, batch, members, found)` — the hop

```
cover_blame(lane, batch, members, found) -> {branch: [(member file, 0, the finding's line)]}
```

For each `(path, line, text)` in every `item['test_paths']`:

1. `tp = repo_path(lane, batch, path)`; skip when `None`.
2. Skip when `tp` is in any member's own changed files — that is a direct hit, and the direct
   reading had its say (D4).
3. Read the test's text: `git show <batch['base']>:<tp>` in `lane.repo`. Unreadable (added on the
   batch ref, binary, gone) → skip.
4. For each member, `hits = covers(text, tp, _member_files(lane, batch, f))`. For each hit, record
   `(hit, 0, text)` under that member's branch, once (D6).

Never raises; every git read is `.ok`-checked and a failure is no hit.

### 5. `blame` — the fallback, and the two rules that still decide

```
named = <the direct reading, byte for byte as today>
if not named:
    named = cover_blame(lane, batch, members, found)
    covered = bool(named)
if not named or (len(members) > 1 and len(named) == len(members)):
    return {}, False
return named, covered
```

`blame` returns `(named, covered)`: the map as before, and whether it came from the hop. Both
no-verdict rules apply to the hop's result unchanged (P7) — a test that covers every member in the
batch tells nobody apart, and the batch splits exactly as it does today.

### 6. The drop reason

In `run`'s `state == 'red'` branch, the order becomes: ledger (unchanged text, D2) → read `found`
and `on_trunk` → compute `culprits` → **then** `_drop`, with the culprit in its `why`:

```
why_drop = f'red on {why}'
if len(culprits) == 1 and not on_trunk:
    how = ('the failing test <path> covers its files' if covered
           else 'its files, named in the failing job\'s log')
    why_drop = f"red on {why} — #{pr}'s ({how})"
```

so the operator's line reads

```
merge queue: batch batch/20261007-090725-ebb2746 dropped — red on gate (skipped), gate-tests (skipped) — #1's (its files, named in the failing job's log)
merge queue: batch batch/20261007-090727-84dd8df dropped — red on gate (failure) — #1122's (the failing test tests/test_audit.py covers its files)
```

and the same string reaches each cancelled run's claim (`why[:200]`, P2). With no culprit, with more
than one, or when the check is red on the trunk too, the line is byte for byte what it is today —
`on_trunk` is not this batch's defect and names nobody by design (`asf/merge_queue.py:806-823`).

`_red_on_trunk` and `_trunk_red_seen` keep first claim: the trunk check runs before the blame, as it
does now, and a trunk-red batch never reaches §5.

### 7. What the culprit is told, and what it is not

`culprit_text`'s `where` clause takes the hop (D8, P8):

```
3 PRs on main c9cca6bae; the failing test tests/test_audit.py covers files only this PR changes,
the others are cut again without it
```

and `hold_culprits` is called only when the culprit came from the direct reading (D7):

```
if fixed and culprits and not covered:
    hold_culprits(lane, [...], fixed)
```

### What it looks like when it is there

A batch of three goes red on a known-gap test. One pass: the drop line names `#1122` and the test
whose coverage named it, `#1122` goes back with the job, the step, the log lines and
`tests/test_audit.py` as the file that covers its change, `#1194` and `#1195` are cut again
immediately on the trunk, and nobody runs a `git diff | grep`. No extra CI run, no split level, no
hold on a PR the log never accused.
