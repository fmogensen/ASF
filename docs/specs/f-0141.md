# F-0141 — the second marker gate: what a session leaves switched on

The card is one line with an empty acceptance list, and the plan it was deferred from says only
what kind of thing it is: *"a new gate rule"* (`docs/plans/fix-package.md:565`, §8 out of scope).
So this spec's first job is to say what a **debug-toggle marker** is, and its second is to put the
refusal where the factory already refuses a marker.

The failure mode is not an untidy line. It is a **check that has been switched off**: a focused
test that makes a green suite cover one case, a disabled test that covers none, a breakpoint that
stops a run on a machine nobody is watching, a debug flag left `True`. Every one of them is a
session's own debugging aid, every one of them is invisible in a green result, and the branch that
carries it is the last place the factory can see it — after it lands, the suite is green and
smaller, and nothing in the record says why.

The factory already has this gate for the other kind of marker: `asf.customer_content` refuses a
branch that **adds** a line matching a forbidden marker under the pages a customer reads, before
review and again before the gate, and hands it back with every `file:line`
(`asf/customer_content.py:197` `refusal`, wired at `asf/harvest/lane.py:794` and `:2463`). This
spec is the same gate over a different marker set and a different scope: not one product's
customer pages, but **every file a branch touches that is not documentation**, on by default, for
every product.

Two things make that scope safe rather than a branch-refusing machine, and they are the real
design work here:

1. **the marker set is narrow and evidence-checked** — each default was run over this checkout's
   own `asf/`, `tests/`, `tools/`, `evals/`, `plugin/` and `sample/` trees and matches **nothing**
   (P8). A pattern that matches legitimate landed code is not a gate, it is a tax; two obvious
   candidates were dropped for exactly that reason (D4, D5);
2. **a per-line waiver that must carry a reason** — without one this feature cannot be landed by
   the factory that is specifying it, because the test that pins a marker matcher contains the
   marker (D6).

Verified in this worktree at `ed41d4ad3`.

### 1.4 The choices

| # | chosen | against | why |
| --- | --- | --- | --- |
| D1 | **on for every product by default**: `debug_toggles.paths` defaults to `('**',)` | `customer_content`'s posture — `paths` defaults to `()`, so nothing is checked until a product opts in | a debug toggle is not one product's convention, it is a switched-off check, and the same seven markers mean the same thing in every repo. Opt-in would ship a gate that refuses nothing until someone remembers it exists, which is the `asf.precheck` / `asf.credentials` failure: a contract with no pass behind it. The product can still turn it off (`paths: []`, D8) or narrow it |
| D2 | **documentation is excluded, through `lane.is_doc`** — a path under `specs_dir`, `plans_dir`, `reviews_dir` or a `conventions.doc_paths` glob is never scanned | scanning everything and relying on the waiver; or a new `debug_toggles.skip_paths` list | a spec, a plan and a review *quote* the markers they are about — this very file contains all seven — and a gate that refuses the document describing it is a joke. The product already declares where its documentation lives; reading that declaration is free and needs no second list to keep in step. `is_doc` is extracted from `landing_class` rather than copied, so there stays exactly one docs-vs-code rule (P7) |
| D3 | **tests are scanned** | excluding the test tree, which is where a focused or disabled test lives | the whole point. A focused test in the suite is the most expensive toggle there is: the result stays green and stops meaning anything. Excluding tests would leave the gate guarding only the code it was never about |
| D4 | `@unittest.skip`, `skipIf`, `skipUnless` and `expectedFailure` are **not** default markers | adding them, since a skipped test is a switched-off check | this repo lands them legitimately and often (P13): a root guard, a slow-test switch, a declared blocked test with its reason in the call, and an `expectedFailure` helper that is the structure of a whole e2e file. Every one would need a waiver, and a gate that must be waived on sight teaches a session to paste waivers. A product that wants them says so in `debug_toggles.markers` |
| D5 | `fit(` is **not** a default marker, though `fdescribe(`, `xdescribe(` and `xit(` are | the full jasmine/jest focus set | `fit` is a function in this package (P14) — the pattern would refuse the `asf` repo's own branches on sight. `xit(` is safe next to `exit(` because `\b` does not open inside a word |
| D6 | **a per-line waiver that must carry a reason**: a line also matching `debug_toggles.waiver` (default `(?i)\bdebug-ok:\s*\S`) is not a hit; a bare `debug-ok` with nothing after the colon still is | no waiver at all; a file-level or path-level exemption; a bare token with no reason | without a waiver the feature is unlandable by its own factory: `tests/test_debug_toggles.py` must contain `debugger;`, `it.only(` and the rest as fixtures, and the branch that adds them would be refused by the gate it adds (D3 keeps tests in scope). A file-level exemption would exempt the file where the real toggle is most likely to hide. Requiring a reason after the colon turns the escape into a statement a reviewer reads on the line itself, and costs the author one word |
| D7 | the waiver is **not counted, logged or metered** anywhere | a lane line or a ledger field naming N waived lines | `lane_refusal` is a pure `(repo, trunk, branch, conv) → pair | None` with no `out` to print to, and the count nobody reads is the failure named in §1.2/6. The waiver's audience is the reviewer, who is looking at the line |
| D8 | **`paths: []` with the block declared is a red doctor row**; the block absent is a green row reporting the defaults | both green; or both red | it mirrors `customer_content.findings` exactly — a declared block that checks nothing is a mistake someone made, an absent block is the default doing its job. A product that means to switch the gate off says so in one place and reads it back in `asf doctor` |
| D9 | **the same two seams, both of them** — `lane_refusal` and `precheck` | only the first, which is where a branch is normally caught | the second is why the existing gate has it (P3): the branches already past PUSHED on the tick this lands are refused at the gate instead of sailing through the one window the feature has. One extra `git diff -U0` per branch per lane pass, on a range the gate already reads — accepted, and the alternative (threading a shared diff through both gates) is a refactor of `customer_content.added_hits` for a cost nothing has measured |
| D10 | **a new module** importing `customer_content`'s primitives | generalising `customer_content` into one configurable marker engine both blocks read | the two gates share their *mechanics* and share nothing else: scope (one product's pages vs every non-doc file), default posture (off vs on), waiver (none vs required), the tree scan (deploy vs never), the review row (required vs none). One engine with five switches is harder to read than two modules and one import, and `asf/security/paths.py` already establishes import-from-`customer_content` as the way (P5). The one thing that would have been copied — the `-U0` read and its three-dot range — becomes a public `diff()` instead (P6) |
| D11 | the correction kind is `'debug-toggle'`, and the refusal is a **hold back to the session** | a gate failure; a NEEDS OPERATOR line | the session that switched the check off is the one that knows whether it meant to, and it can answer in one commit: remove the toggle, or waive the line with a reason. No registry to add it to (P4) |

## 2. The design

### 2.1 `asf/conventions.py` — the block and its three defaults

Beside the `customer_content` comment (`asf/conventions.py:221-234`), documented the same way —
one commented default per field:

```python
#: ``debug_toggles: {paths, markers, waiver}`` — a debug toggle is a check a session switched off
#: and forgot: a focused or disabled test, a breakpoint, a debug flag left on
#: (:mod:`asf.debug_toggles`). The landing gate refuses a branch that *adds* a line matching a
#: marker under ``paths``, documentation excluded. ``paths`` are globs (default: every file);
#: ``paths: []`` switches the gate off and ``asf doctor`` says so. ``markers`` are Python regexes
#: and replace the defaults below. ``waiver`` is the regex that makes a line legal: it must carry
#: a reason, so the default needs a non-space after the colon.
DEFAULT_DEBUG_TOGGLE_PATHS = ('**',)
DEFAULT_DEBUG_TOGGLE_WAIVER = r'(?i)\bdebug-ok:\s*\S'
DEFAULT_DEBUG_TOGGLES = (
    r'\bdebugger\s*;',                                            # a JS breakpoint
    r'\bbreakpoint\s*\(\s*\)',                                    # a Python breakpoint
    r'\b(?:i?pdb|pudb)\.set_trace\s*\(',                          # the older Python breakpoint
    r'\b(?:describe|context|it|test|suite|scenario)\.only\s*\(',   # a focused test
    r'\b(?:describe|context|it|test)\.skip\s*\(',                  # a disabled test
    r'\b(?:fdescribe|xdescribe|xit)\s*\(',                        # a focused or disabled suite
    r'\bDEBUG\s*[:=]\s*(?:True|true|1)\b',                        # a debug flag left on
)
```

The waiver default carries no `/`, `{` or `#`, so `forbidden_patterns()` emits nothing for it
(P9); the two tuples are not strings and are invisible to it either way, which is what §3.3's
walk is for (P12).

`validate_mapping` gains a `debug_toggles` block beside the `customer_content` one
(`asf/conventions.py:494-513`), and the new key is added to the **docstring's list of checked
keys** (P10):

* not a mapping → `('debug_toggles', 'must be a map (paths, markers, waiver), not …')`;
* `paths` → the shared `_path_list_problem` (a misshapen path list char-splits when nobody
  checks: a string where a list belongs becomes one matcher per character, one of them `*`);
* `markers` not a list → one problem; each entry that does not compile → one problem naming it;
* `waiver` not a string, or a string that does not compile → one problem.

### 2.2 `asf/debug_toggles.py` — the recogniser

```python
"""asf.debug_toggles — a branch never lands a check its session switched off.

A debug toggle is a focused or disabled test, a breakpoint, a debug flag left ``True``: the
session's own aid, invisible in a green result, and a smaller suite forever after. The landing
gate refuses a branch that *adds* one — before review (PUSHED) and again before the gate — and
hands it back with every ``file:line`` (:func:`refusal`).

On for every product; documentation is excluded through the product's own docs rule
(:func:`asf.harvest.lane.is_doc`), and one line is made legal by a waiver that carries a reason::

    it.only('the one case', ...)   # debug-ok: pinned while T-0001 bisects the flake

A product narrows, extends or switches the gate off in ``conventions.debug_toggles``
(:data:`asf.conventions.DEFAULT_DEBUG_TOGGLES`). ``asf doctor`` names what is checked, and a
declared block that checks nothing (:func:`findings`).
"""
```

with, in order — every one of `matches`, `scan_line`, `added_lines`, `describe`, `SHOW_HITS` and
the new `diff` imported from `asf.customer_content`, none of them re-implemented (P5, D10):

| function | what it answers |
| --- | --- |
| `KIND = 'debug-toggle'` | the correction kind a refused branch goes back with (P4) |
| `_block(conv)` / `configured(conv)` | the `debug_toggles` mapping, and whether the product wrote one at all |
| `paths(conv)` | the globs — `DEFAULT_DEBUG_TOGGLE_PATHS` when unset, `[]` when the product wrote `paths: []` (D8) |
| `markers(conv)` | the compiled markers — the defaults when unset; a pattern that does not compile is left out here and named by `asf doctor`, exactly as `customer_content.markers` does |
| `waiver(conv)` | the compiled waiver, `DEFAULT_DEBUG_TOGGLE_WAIVER` when unset, None when it does not compile — and a None waiver waives nothing |
| `waived(pat, text)` | True when the line carries the waiver with a reason |
| `scanned(conv, path)` | `matches(paths(conv), path)` **and not** `is_doc(conv, path)` — the doc exclusion (D2), with `asf.harvest.lane` imported inside the function, as `customer_content.findings` imports `asf.harvest.deploy` inside itself |
| `added_hits(repo, base, head, conv)` | `[(path, line, marker)]` — for every line the head adds since it left the base, under `scanned`, matching a marker and **not** waived. `[]` when `paths(conv)` is empty or the diff cannot be read |
| `refusal(repo, trunk, branch, conv)` | `(KIND, text)` or None, over `origin/<trunk>...origin/<branch>` |
| `findings(product)` | S-36751: the doctor's row (§2.4) |

The refusal text, one line, `describe`'s `path:line (marker)` list first and the way out last:

```
a check switched off: tests/test_pricing.py:41 (it.only(), app/api.py:12 (DEBUG = True) — a
debug toggle makes a green result smaller than it looks: remove the focused/disabled test,
the breakpoint and the debug flag, or mark the line `debug-ok: <why it stays>`, then push
```

```python
def is_doc(conv, path):
    """True when ``path`` lies under a docs root — ``specs_dir``, ``plans_dir``, ``reviews_dir``
    or a ``conventions.doc_paths`` glob. The one rule, per path."""
    conv = _conv(conv)
    roots = [str(conv.get(k)).strip('/') + '/' for k in ('specs_dir', 'plans_dir', 'reviews_dir')
             if conv.get(k)]
    return any(path.startswith(r) for r in roots) or any(_glob_hit(g, path)
                                                         for g in conv.get('doc_paths') or ())


def landing_class(product, files):
    """:data:`DOCS` when every path in ``files`` is documentation (:func:`is_doc`), else
    :data:`CODE`. The one rule for docs vs code."""
    files = [f for f in files or () if f]
    return DOCS if files and all(is_doc(product, f) for f in files) else CODE
```

## 3. Acceptance tests

### 3.1 The recogniser, the waiver and the two seams

`tests/test_debug_toggles.py` — its own temp-repo fixture (a `unittest.TestCase` base with a
`setUp` and no test methods of its own, as `tests/test_customer_content.py:39` `Repo` is), whose
`origin/main` holds clean code and whose `origin/worker/T-0001` adds lines to it. The classes and
what each pins:

* `Markers` — every one of the seven defaults matches its toggle (`debugger;`, `breakpoint()`,
  `pdb.set_trace(`, `it.only(`, `describe.skip(`, `xit(`, `DEBUG = True`) and none of them
  matches the lines this repo lands legitimately: `def fit(sections, limit):`, `fit({'kind': …})`,
  `@unittest.skipUnless(...)`, `unittest.expectedFailure(fn)`, `exit(2)`, `self.skipTest(...)`
  (D4, D5, P13, P14). Each fixture line carries the waiver with its reason, which is what makes
  this file landable (D6) — and §3.4 is the test that it does;
* `Waiver` — a marker line with `debug-ok: <reason>` is not a hit; the same line with a bare
  `debug-ok` (nothing after the colon) still is; a product waiver that does not compile waives
  nothing;
