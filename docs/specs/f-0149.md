# F-0149 — the scorecard's three attribution gaps, measured on its own first run

The scorecard ran for the first time on 2026-09-25 and answered three questions wrongly, each in the
same way: it had the fact and did not join it.

- **Where the money went.** The largest single row of *"where the last 14 days went"* on the factory
  product was `(none)` — $170 of $807 — and $81 on the other product. Those are not sessions spent on
  nothing: they are sessions on a Bug that hangs under an Epic (which the record explicitly allows),
  or on a job whose `item` never matched, run on a branch that names the card in its own name. The
  scorecard already knows how to read a Feature out of a Bug's text — `attributed_bugs` does exactly
  that for the bug **count** — and every session event already carries the `branch` the job ran on.
  Neither is read when the money is divided up.
- **Why CI is red.** One broken shared step makes a dozen `ci-job:*` causes — 13 over threshold on one
  product — because red is counted per job name. Thirteen inbox cards get filed for one root cause,
  each with its own marker, its own verification and its own reopen. The forge already tells us which
  step failed, and the CI job schema has carried `failed_step` since it was written; the local gate's
  half of the same ranking is *already* grouped by its first failing line.
- **How long a Feature took.** A card adopted by `asf migrate` has `- <the migration day>: created
  (migrate)` as its first History line, and `timeline` reads a card's first dated line as when it was
  carded. So its lead time is measured from the day the factory adopted it, not the day it was asked
  for — a number that is always too small, silently mixed into the median an operator judges the
  factory by.

All three are readings, not writings. Nothing new is collected, no stream gains a field, no command is
added; three joins that already have both sides are made.

### In

- **`score.feature_named_by(items, iid)`** — pure. The Feature a card's own text names, for a card type
  the record lets hang outside a Feature (a Bug, P3): the **newest-carded** live Feature named in its
  text and carded no later than it — `attributed_bugs`' own guard, read the other way (P4, D2).
- **`score.feature_of_card(items, iid)`** — pure. `feature_of(items, iid)` else `feature_named_by`.
- **`score.feature_of_session(items, ev)`** — pure. The Feature one `metrics/sessions` event is spent

- **`rank`'s `by_feature` reads that ladder**, and `rank` returns a new key **`unattributed`** —

- **`diagnose.ci_causes(facts, start, end)`** — pure. The window's red CI jobs and red gates grouped by

## The design

### `asf/scorecard/score.py` — the ladder, and the lead time that is not measured

Pure, beside `feature_of` and `attributed_bugs`, which are the two functions it is built out of.

```python
#: The card types the record lets hang outside a Feature (``asf.record.core.PARENT_TYPES``), and
#: so the types whose own text is read for the Feature they belong to. A card of any other type
#: that merely mentions a Feature is not work spent on it — see D3.
TEXT_ATTRIBUTED_TYPES = ('bug',)


def feature_named_by(items, iid):
    """The Feature card ``iid``'s own text names — :func:`attributed_bugs`' join, read the other
    way (D2). Only for a card of :data:`TEXT_ATTRIBUTED_TYPES`, and only a live Feature carded no
    later than the card itself, so an old Feature never absorbs a newer Bug's spend. When the text
    names several, the **newest-carded** wins (ties by id): a Bug is about the Feature it was filed
    after, not the one it compares against. ``None`` when none is named."""
    it = items.get(iid) or {}
    if it.get('type') not in TEXT_ATTRIBUTED_TYPES or it.get('removed'):
        return None
    named = []
    for fid in ids_in(it.get('text') or ''):
        f = items.get(fid) or {}
        if f.get('type') != 'feature' or f.get('removed'):
            continue
        if it.get('created') and f.get('created') and it['created'] < f['created']:
            continue
        named.append(fid)
    return max(named, key=lambda f: (items[f].get('created') or '', f)) if named else None


def feature_of_card(items, iid):
    """The Feature a card belongs to: up its ``parent`` chain, else the one its own text names."""
    return feature_of(items, iid) or feature_named_by(items, iid)


def feature_of_session(items, ev):
    """The Feature one ``metrics/sessions`` event's spend belongs to, by the first rung that
    answers:

    1. the event's ``item``, up its ``parent`` chain (:func:`feature_of`) — today's whole rule;
    2. that same card's own text (:func:`feature_named_by`) — a Bug may hang under an Epic;
    3. every card id the job's ``branch`` names (:func:`asf.scorecard.facts.ids_in`), in the order
       the branch names them, each through rungs 1 and 2.

    ``None`` when no rung answers — the spend is unattributed, and the scorecard says so rather
    than charging it to a Feature it cannot name."""
    found = feature_of_card(items, ev.get('item'))
    if found:
        return found
    for iid in ids_in(ev.get('branch') or ''):
        found = feature_of_card(items, iid)
        if found:
            return found
    return None
```

Rung 3 reads ids out of the branch **only** through `ids_in`; no branch prefix is written down (P8).
A branch that names one card behaves exactly as today, because the loop stops at the first id that
resolves.

Beside `days_between`, the one rule about a lead time that cannot be measured:

```python
def lead_days(item, to):
    """Days from a card's carding to ``to`` — ``None`` when the card was adopted by ``asf migrate``
    and its ``created`` is the day the factory took it over, not the day it was asked for
```

## Records

- **Nothing new is persisted, and no existing record is rewritten.** No stream, no stream field, no
  state file, no config key, no card, no event, no History line. Every number here is derived on each
  run from `metrics/sessions`, `metrics/ci`, `metrics/gates` and the record's cards, all unchanged.
- **`rank()` gains one key, `unattributed`** — `{usd, sessions, share}` over the window. It reaches
  `asf scorecard --json` through `compute()['rank']` (P22) and prints as one row of the
  *"where the last N days went"* table. The `(none)` row of `by_feature` keeps its name and its place.
- **`compute()` gains one key, `ci_causes`** — the regrouped red, printed as one row of that same
  table. `by_ci_job` keeps its name, its minutes and its per-job red rate.
- **Every `Facts` item gains `created_migrated`** — a boolean, derived, in memory only. No card is
  edited and no `created:` field is written anywhere.
- **A Feature or Task adopted by `asf migrate` reports no lead time.** `lead_days` and `prod_days` are
  `None`; `asf scorecard` prints `—` in its Lead column, as it already does for any missing value; the
  weekly `median_lead_days`, `median_prod_days` and `median_task_days` are medians over the landings
  that can be measured. `window_row`'s keys, and so the stored `state/<product>/scorecard.jsonl` row,
  are unchanged in name and shape (P21) — only the values move, toward the truth.
- **New cause keys appear**, in `state/<product>/scorecard-causes.json` and on the marker line of the
  inbox cards the loop files: `ci-step:<class of the failing step>` where thirteen `ci-job:*` keys used
  to be. One root cause is one key, one card, one marker, one verification and one reopen.
- **Every cause already filed keeps verifying against the number it was filed at.** A `ci-job:<name>`
  entry in `scorecard-causes.json` — and the card in a record carrying its marker — is read through
  `by_ci_job` exactly as it is today (D8). No state file is migrated, no key is renamed, no filed card
  is touched.
- **A filed `ci-step:` card names the failing step and the jobs it reddened**, and nothing else: no
  worker account, no machine path, no product name. It goes through `loop._scrub` like every other
  filed card.
- **The three Stories are sequential** (D13): their footprints share `asf/scorecard/diagnose.py` and
  `tests/test_scorecard.py`, so the plan that follows orders them and does not run them in parallel.
