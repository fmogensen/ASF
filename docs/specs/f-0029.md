# F-0029 — Roles: one file per role, five sections, model and access from config

Epic: E-0001 — ASF 0.1 — a working factory. Branch: `spec/F-0029`.

A session is launched today with a brief and nothing else. The brief is four parts
(`asf/briefs/build.py:26-33`): the item line, the generated preamble, one kind template
(`asf/briefs/templates/<kind>.md`), and the common tail. Every one of those parts is *the job* —
what to do on this card, this branch, this round. None of them is *who is doing it*. The
identity the old prototype carried in 14 role files — the doctrine with the incident behind each
rule, the output contract, the economy, the boundary — is either absent or smeared through the
templates: `review.md:21-24` carries the reviewer's one real rule about rounds, `fixer.md:4-6`
carries the fixer's boundary, and the other ten templates carry none at all. What a session may
*not* do is stated once per template, if at all, and nowhere as a property of the worker.

Two consequences, both already recorded. The first is that nothing pins what a session ran
under: the registry line carries `model`, `account`, `brief` and `kind`
(`asf/workers/spawn.py:307-311`), so a result can be attributed to a model but never to a
doctrine — the prior-art finding b60, *"nothing pins the brief, role file or rule set a session
ran under"* (`docs/research/prior-art-prototype.md:98`). The second is that identity and cost
are welded together: `DEFAULT_MODELS` maps a *brief kind* to a model label in package code
(`asf/briefs/build.py:50-52`), so "who reviews" and "what a review costs" are one table an
operator cannot re-point without editing the package.

This spec makes a role a file. Ten files under `asf/roles/`, each with the five sections, each
validated by a loader that refuses a file naming a model; a table binding every brief kind to
one role; model, effort and access resolved from operator config with the per-kind table kept as
the last fallback, so no label a product runs on changes; the role block rendered into the brief
ahead of the facts; and the role's name, its sha and the digest of the rule set written on the
launch line, folded onto the run, and carried into the `sessions` event — so a week of results
can be read per doctrine and not only per model.

## 1. Decisions

### What already holds (verified in this worktree at `47bab2d`)

- **A model label is already operator config, one level up.** `worker_pool.models: {<label>:
  <id>}` maps a label to a vendor id and refuses a label it has no entry for —
  `NEEDS OPERATOR: worker_pool.models has no entry for <label>` (`asf/workers/spawn.py:251-260`).
  No vendor id is written in the package, and this spec adds none.
- **A product may already re-point a kind's label**: `conventions.models.<kind>` beats
  `DEFAULT_MODELS` (`asf/briefs/build.py:164-167`, `tests/test_briefs.py:566-570`). This spec
  keeps that path first, so no existing product file changes meaning.
- **Access is already config, in two halves.** The directories a session may read outside its
  worktree come from the product's `job_grants`, plus the row's own grants
  (`asf/briefs/build.py:169-186`, `asf/workers/spawn.py:290-295`); the permission fence comes
  from `worker_pool.permission_mode` and `worker_pool.settings_file`, and a missing settings file
  is refused outright — *"a session launched without its deny rules is worse than no worker"*
  (`asf/workers/spawn.py:266-274`).
- **The brief is the only channel into a session.** The runtime pipes one brief on stdin and
  passes `--model` (`asf/workers/runtime.py:82-83`, `:194`). Nothing in the runtime selects an
  agent file, so a role reaches a worker as text in its brief or not at all.
- **A template that ships a name it should not is already a test failure**
  (`tests/test_briefs.py:594-610`, `tools/forbidden-names.txt`), and every brief is a golden
  (`tests/test_briefs.py:127`). Role files inherit both guards.
- **The registry line is append-only and the launch line opens a run**; every later line folds
  onto that run and a run's terminal fields never fold into the next (B-0041,
  `asf/workers/lifecycle.py:22-27`). So a field written once at launch is on the same folded run
  as the result — "recorded with its result" needs no second write.
- **The standing rules a session runs under are already rendered into its brief**:
  `conventions.rules_tail`, else the six defaults (`asf/briefs/preamble.py:445`, `rules_block`).
  The enforced rule *cards* are a different set, read from the record's `index.json`
  (`asf/rules/rules.py:64-80`). Both are "the rule set", and this spec digests both.

### Preconditions

- `47bab2d` is the base. `asf/briefs/build.py`'s `model_for`/`add_dirs_for`, `spawn.model_arg`'s
  refusal shape, `lifecycle.fold`'s launch-line boundary and the golden-brief fixtures are all
  built on, and none is rewritten.
- The ten role files are written from sources that exist: the templates
  (`asf/briefs/templates/*.md`), the constitution (`docs/CONSTITUTION.md`), and the incidents in
  the record. **A doctrine bullet must cite an incident that exists**; the writer of each file
  verifies its id against the record before it is committed (the validator checks the *shape* of
  a citation, never that the id is real).
- `docs/config.example.yaml` is the documented config surface; the `roles:` block lands there in
  the same change, or the feature ships undocumented.

### Choices

| # | Chosen | Against | Why |
| --- | --- | --- | --- |
| D1 | Role files live in the package, `asf/roles/*.md`, shipped as package data | the product's record, or `~/.ASF/roles/` | A role is the factory's identity, not a product's content. It must be the same on every product this install runs, and it must be readable with no record loaded — `asf roles` works before `asf init`. `pyproject.toml` gains `"asf.roles" = ["*.md"]` beside the templates' entry |
| D2 | The role reaches the worker as a block in its brief | a Claude-Code agent file under `.claude/agents/` | The runtime pipes a brief and passes `--model`; it selects no agent (`runtime.py:82-95`). An agent file would be a second identity nothing in the record could pin to a result, which is the whole of b60 |
| D3 | Frontmatter is exactly `name` and `purpose`; any other key is refused | a permissive frontmatter that ignores keys it does not know | This is where `model:` creeps back. A refusal on unknown keys is the enforcement of the card's second acceptance line, and it is one `set` comparison |
| D4 | "Names a model" is checked as a word ban: `model`, `backend`, `effort`, `tools`, and the two label constants `briefs.build.HEAVY`/`LIGHT`, case-insensitive, anywhere in the file | a regex for vendor model ids | A generic repo cannot list vendor names (`tools/check_generic.sh`), so a vendor-id regex would be both unenforceable and a forbidden name itself. The word ban is crisp, cheap and catches the near-miss ("prefer the heavier model for this") that a vendor regex would not |
| D5 | Resolution order for a label: `conventions.models.<kind>` → `roles.<role>.model` → `roles.defaults.model` → `DEFAULT_MODELS[kind]` | role-first, or replacing the kind table outright | Most specific wins, and the most specific thing that exists today is the product's per-kind override — putting the new global role entry ahead of it would silently re-point a product that already set one. The kind table stays as the floor so a kind added without a role still resolves |
| D6 | The bindings preserve today's labels exactly: writer(spec, plan, reshape) and reviewer(review) and interrogator(groom, adjudicate) are heavy; coder, fixer(fixer, correct, rebase), diagnostician(fix-bug), harvester(close) are light | binding by what reads best and re-tuning after | A change that moves identity *and* cost in one commit cannot be attributed if the week gets worse. T5 asserts every kind's label is unchanged; the tuning is a later card with the measure in hand |
| D7 | `adjudicate` and `groom` bind to `interrogator` | a new `adjudicator` role, or leaving them unbound | Both templates open with *"rule on …"* (`adjudicate.md:1`, `groom.md:1`): find the open question, close it, record what closed it — the interrogator's job as the prior art states it (`docs/research/prior-art-prototype.md:249`). The card's set is ten, and inventing an eleventh to avoid a binding is the thing the card forbids |
| D8 | `prober`, `security` and `documenter` ship as files with no kind bound, each naming its reason in `UNBOUND` | shipping only the seven bound roles | The card names all ten. An unbound role with a stated reason is honest; a missing one reads as a forgotten binding. The validator requires every role to be bound *or* listed, so the set can never drift quietly |
| D9 | The role's `## Output` names the side file only; a role that restates the REPORT envelope is refused | letting a role carry its own report contract | The envelope is generated once, in the tail (`build.py:63-96`). Two contracts in one brief is the prototype's D8 failure — *"a template writing its own is refused"* (`:223`) |
| D10 | `## Economy` is policy (what this role may open before it is paying to read), capped at six lines; the preamble stays the facts | dropping Economy because the preamble replaced it | The card requires five sections. The preamble answers *which files*; the Economy answers *whether to look at all*, which no generated fact can state. The cap is what stops it growing back into a survey |
| D11 | The rule set is one digest over two parts: the standing-rules text as rendered, and the sorted `<rule-id> <card-sha>` lines of the enforced rule cards | a digest of the cards only | A session obeys the text in its brief and is judged by the cards in the record. Pinning one and not the other leaves half the question open. The brief file holds the standing text verbatim, so the digest identifies and the brief recovers |
| D12 | A `roles:` entry naming a role with no file is a red doctor row and a red `asf roles --check`, not a launch failure | refusing the launch | A launch that dies on a config typo costs a wave; the config lint costs nothing and runs every tick's health step. The launch resolves through the order in D5 and carries on |

## 2. The design

### 2.1 The role file — `asf/roles/<name>.md`

Markdown with a two-key frontmatter and exactly five `##` sections, in this order:

```markdown
---
name: reviewer
purpose: one finding per acceptance criterion, each with the evidence for it
---

## Identity

You are the round that decides whether work is done. You read what was written and what the
plan asked for, and you answer both questions separately.

## Doctrine

- `status` says whether the review ran; `approved` says whether it passed. They are different
  questions, and a red review is a successful phase (B-0051).
- Round 1 finds everything: a later round that finds what round 1 could have found is the
  failure this rule exists to stop (B-0029).
- …

## Output

The named side file, and only it: the review at the path the brief gives you. The REPORT
envelope belongs to the brief's tail; do not restate it.

## Economy

Read what your brief names, then what those files reference. Do not survey. Every file you
open is re-sent on every turn after it.

## Boundaries

You write the review file and nothing else. You do not fix what you find.
```

**What the validator refuses** (`roles.validate` returns one problem string per breach, and an
empty list is a valid role):

| # | Refusal | Constant |
| --- | --- | --- |
| 1 | frontmatter missing `name` or `purpose`, or `name` not matching the file stem | — |
| 2 | any frontmatter key beyond those two (this is where `model:` would arrive) | — |
| 3 | a missing section, a section out of order, or a heading that is not one of the five | `SECTIONS` |
| 4 | the file over its line cap | `MAX_LINES = 60` |
| 5 | fewer than four or more than eight doctrine bullets | `DOCTRINE_MIN = 4`, `DOCTRINE_MAX = 8` |
| 6 | a doctrine bullet citing no incident — no match for `INCIDENT` | `INCIDENT = r'\b(?:[BDEFRST]-\d{4}\|b\d{1,3})\b'` |
| 7 | `## Economy` over its cap | `ECONOMY_MAX_LINES = 6` |
| 8 | a banned word anywhere in the file, case-insensitive (D4) | `FORBIDDEN = ('model', 'backend', 'effort', 'tools', HEAVY, LIGHT)` |
| 9 | `## Output` carrying a REPORT contract — a line matching `^REPORT$` or a fenced block containing `status:` (D9) | — |

### 2.2 `asf/roles/roles.py` — the loader

```python
ROLES_DIR = os.path.dirname(os.path.abspath(__file__))

@dataclasses.dataclass
class Role:
    name: str
    purpose: str
    sections: dict     # 'Identity' -> the section's text, in file order
    text: str          # the body below the frontmatter, verbatim
    sha: str           # sha256 of `text`, first 12 hex
    lines: int

def load(name) -> Role            # RoleError on a missing file
def load_all() -> dict            # name -> Role, every *.md in ROLES_DIR
def validate(role) -> list        # the nine refusals above, in order
def for_kind(kind) -> str | None  # BINDINGS[kind]; RoleError on a kind no table knows
def block(role, cap) -> str       # the rendered brief block (§2.5)
```

Frontmatter is read with `asf.record.frontmatter`, not a second parser. `sha` is over the body
only, so an editorial change to the frontmatter's `purpose` line does move it (the purpose is
identity) but the file's mtime and path never do.

### 2.3 The bindings — one table, read twice

```python
BINDINGS = {'spec': 'writer', 'plan': 'writer', 'reshape': 'writer',
            'review': 'reviewer', 'coder': 'coder',
            'fixer': 'fixer', 'correct': 'fixer', 'rebase': 'fixer',
            'fix-bug': 'diagnostician', 'close': 'harvester',
            'groom': 'interrogator', 'adjudicate': 'interrogator'}

UNBOUND = {'prober': 'no phase yet — the production probe is a view, not a session',
           'security': 'no phase yet — the panel it belongs to is not in this epic',
           'documenter': 'no phase yet — the docs surface has no lane of its own'}
```

`BINDINGS` covers `briefs.build.KINDS` exactly: a kind with no entry and a role in neither
`BINDINGS.values()` nor `UNBOUND` are both test failures (T3), so the set cannot drift by
addition or omission.

### 2.4 Model, effort and access — from config

`~/.ASF/config.yaml` gains one top-level block, documented in `docs/config.example.yaml`:

```yaml
# roles: what each role costs and what it may reach. The role files (`asf roles`) carry identity
# and doctrine and name none of this — the assignment is operator configuration.
roles:
  defaults:      {model: light}
  writer:        {model: heavy}
  reviewer:      {model: heavy}
  interrogator:  {model: heavy}
  coder:         {model: light}
  fixer:         {model: light}
  diagnostician: {model: light}
  harvester:     {model: light}
  # a role with no phase bound yet — the entry is read the day one lands
  security:      {model: heavy}
  documenter:    {model: light}
  prober:        {model: light}
  # per role, optional: `effort: <label>` mapped by worker_pool.effort_args, and `grants: [<dir>]`
  # appended to the product's job_grants.
```

- **Label** — `model_for(product, kind, cfg=None)` resolves in D5's order and returns a label,
  never an id. `spawn.model_arg` maps it as it does today and refuses an unmapped one.
- **Effort** — `effort_for(role, cfg)` returns the label or `None`. `worker_pool.effort_args:
  {<label>: [<arg>, …]}` maps it to runtime arguments, with the same refusal text shape as
  `model_arg`: `NEEDS OPERATOR: worker_pool.effort_args has no entry for <label> — add it to
  config.yaml`. No label configured means no argument and no change to any command line.
- **Access** — `add_dirs_for` appends `roles.<role>.grants` (expanded) after the product's
  `job_grants` and the row's own, de-duplicated, order preserved. A role grant only ever adds;
  the permission fence (`permission_mode`, `settings_file`) stays where it is.

`Brief` gains `role`, `role_sha` and `effort`; `step_wave.worker_row` copies them onto the
workers' `Row` beside `model`; `spawn` writes them and the rule digest onto the launch line.

### 2.5 The brief gains a role block

The brief becomes five parts, the new one second:

```
Backlog item: <id> — <title>
## Who you are — <role>            ← the role file's body, capped
<the preamble>                     the facts, generated not discovered
<the kind template>                the job
<the common tail>                  the heartbeat, the marker, the typed REPORT
```

The block is the file's body verbatim under a `## Who you are — <name>` heading, truncated to
`conventions.role_max_lines` (default 60) by whole sections, last section first, with the same
`fit` discipline the preamble uses (`preamble.py:447`) — a truncated block ends with
`… (role <name> truncated at <n> lines)` so a short brief is never mistaken for a short doctrine.
A kind whose role is unbound renders no block and no heading.

**The overlap is measured, not guessed.** The change prints, once, per kind, the lines of its
template that the role block now duplicates (`asf roles --overlap`), and the golden briefs carry
the growth. No template line is deleted in this change (In/out); the measurement is the input to
the card that cuts them.

### 2.6 What the record keeps

`spawn.spawn` writes three more keys on the launch line, beside `model` and `brief`:

```json
{"job": "review-f-0029", "kind": "review", "model": "heavy", "brief": "…/briefs/review-f-0029.md",
 "role": "reviewer", "role_sha": "9f2c41ab77d0",
 "rules": {"standing": "31ba0c8e5d12", "cards": "7a4e9911c0b3", "n": 14,
           "sha": "c5d7e0184a2f"}}
```

- `role_sha` is `Role.sha`; the brief file holds the rendered block, so the sha identifies and
  the brief recovers.
- `rules.standing` is the sha of the standing-rules text as rendered into this brief;
  `rules.cards` is the sha over the sorted `<rule-id> <card-sha>` lines of the enforced rule
  cards at launch (`asf.rules.rules.load_rules` + `partition`), `n` their count, and `sha` the
  digest over both (D11). A record with no rule cards gives `cards: null, n: 0` and a `sha` over
  the standing part alone — an unstamped record is not a failure.
- `lifecycle.fold` needs no change: the launch line opens the run, so the result folds onto the
  same object.

Downstream:

- `metrics.session_event` adds `'role': record.get('role')` and `'rules_sha': (record.get('rules')
  or {}).get('sha')`; the `sessions` schema entry adds `'role': (('str', 'null'), None)` and
  `'rules_sha': (('str', 'null'), None)`. Both nullable, so every registry line written before
  this change still validates.
- `asf sessions` ended table gains `role` between `kind` and `account`
  (`asf/views/sessions.py:153`); the live table is unchanged (it is already at its width).
- `asf roles` is a new view: one row per role — name, purpose, bound kinds (or `unbound: <reason>`),
  the label config resolves for it, its sha and its line count. `asf roles --check` runs
  `validate` over every file and exits 1 on any problem, printing `<file>: <problem>` per line.
- `asf doctor` gains one row: `roles  <n> valid, <k> kinds bound` — red with the first problem's
  text when any role is invalid, when a kind has no binding, or when `roles:` names a role with
  no file (D12).

### 2.7 The ten files

| Role | Purpose (frontmatter) | Kinds bound | Label today |
| --- | --- | --- | --- |
| `writer` | the document is the requirement, executable without asking anyone anything | `spec`, `plan`, `reshape` | heavy |
| `reviewer` | one finding per acceptance criterion, each with the evidence for it | `review` | heavy |
| `coder` | implement the plan inside the declared boundary, and nothing beside it | `coder` | light |
| `fixer` | close the binding list exactly as it is written, and widen nothing | `fixer`, `correct`, `rebase` | light |
| `diagnostician` | build the red loop first; a hypothesis carries its prediction | `fix-bug` | light |
| `harvester` | what landed, what did not, and the one line that says why | `close` | light |
| `interrogator` | rule on the open question and record what closed it | `groom`, `adjudicate` | heavy |
| `prober` | the state of what is running, reported as it is, absence reported as absence | — (D8) | light |
| `security` | attack the guarantee before a user does | — (D8) | heavy |
| `documenter` | the surface a reader meets, kept true to the code under it | — (D8) | light |

Each file is written from the template it inherits its rules from, the constitution, and the
incidents in the record; each stays under the cap; and none names a model.

## 3. Acceptance tests

All from the repository root, Python 3 stdlib only. The suite must be green:

```bash
cd "$(git rev-parse --show-toplevel)"
python3 tools/run_tests.py
```

**T1 — the file shape, and the nine refusals.** Every file in `asf/roles/` loads: frontmatter is
exactly `name` + `purpose`, `name` matches the stem, the five sections are present and in order,
the file is at or under 60 lines, doctrine is 4–8 bullets and every bullet matches `INCIDENT`,
Economy is at or under 6 lines. Then, over a temporary roles dir, each of the nine refusals is
produced by exactly one mutation of a valid file and names itself in the problem string.

```bash
python3 -m unittest -v tests.test_roles.ShapeTests tests.test_roles.ValidateTests
```

**T2 — no role file names a model, a backend or an effort.** Every shipped file is searched
case-insensitively for each word in `FORBIDDEN` and for the two label constants, and none hits;
a fixture file carrying `model: heavy` in its frontmatter is refused by refusal 2 *and* by
refusal 8. No role file carries a name from `tools/forbidden-names.txt`.

```bash
python3 -m unittest -v tests.test_roles.NoModelTests tests.test_roles.GenericTests
```

**T3 — ten files, every kind bound, every role accounted for.** `load_all()` returns exactly the
ten names of §2.7; `set(BINDINGS) == set(briefs.build.KINDS)`; every value of `BINDINGS` has a
file; every file is in `BINDINGS.values()` or in `UNBOUND` with a non-empty reason; `for_kind`
raises `RoleError` on `'preflight'`.

```bash
python3 -m unittest -v tests.test_roles.BindingTests
```

**T4 — the brief carries the block, in one place, capped.** For every kind, the built brief has
`## Who you are — <role>` exactly once, after the item line and before the preamble's first
heading, with the role's own Doctrine bullets in it; with `conventions.role_max_lines: 12` the
block is cut on a section boundary and ends with the truncation line; an unbound kind renders no
heading. The goldens are regenerated and read.

```bash
ASF_UPDATE_GOLDEN=1 python3 -m unittest tests.test_briefs
python3 -m unittest -v tests.test_briefs.RoleBlockTests tests.test_briefs.GoldenBriefTest
```

**T5 — the label comes from config, and nothing moves.** For every kind in `KINDS`,
`model_for(product, kind, cfg={})` returns the exact label it returns today (`heavy` for `spec`,
`plan`, `reshape`, `review`, `groom`, `adjudicate`; `light` for the rest). With
`cfg={'roles': {'reviewer': {'model': 'light'}}}`, `review` is `light` and `spec` is unchanged.
With both that and `conventions.models: {'review': 'heavy'}`, the product wins (D5). With neither
and `roles.defaults.model: 'heavy'`, an unconfigured role is `heavy`. A role named in `roles:`
with no file changes no label.

```bash
python3 -m unittest -v tests.test_briefs.RoleModelTests tests.test_briefs.KindModelGrantTest
```

**T6 — effort and access resolve from config and refuse cleanly.** `effort_for('reviewer', cfg)`
returns the label, `None` when unset; `spawn.effort_args('high', cfg)` returns the mapped list,
`[]` for `None`, and raises `SpawnError` starting `NEEDS OPERATOR:` for a label
`worker_pool.effort_args` has no entry for. `add_dirs_for` with `roles.coder.grants` appends the
expanded dir after the product's `job_grants`, de-duplicated, and a product with no grants and a

```bash
python3 -m unittest -v tests.test_briefs.RoleGrantTests tests.test_workers.EffortArgTests
```

**T7 — the launch line records the role and the rule set.** A spawned session's registry line
carries `role`, `role_sha` equal to `roles.load(<role>).sha`, and a `rules` object whose
`standing` is the sha of the rules block in the written brief, whose `cards` and `n` match the
enforced cards of the fixture record, and whose `sha` is the digest over both. A record with no
rule cards gives `cards: null, n: 0` and still a `sha`. Editing the role file between two
launches changes `role_sha` and nothing else.

```bash
python3 -m unittest -v tests.test_session_identity.RoleRecordedTests
```

**T8 — the result carries the role.** After a launch line and an `ended` line for the same job,
`lifecycle.fold` returns one run carrying `role`, `role_sha`, `rules` *and* `end_reason`;
`metrics.session_event` over that record emits `role` and `rules_sha` and validates against the
`sessions` schema; a registry line written before this change (no `role` key) emits `null` for
