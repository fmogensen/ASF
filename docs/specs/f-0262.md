# F-0262 — the answer was in the repo, and nobody read it

On 2026-10-06 an adjudicate session on a product (`adjudicate-t-42278`) did the first half of its
job exactly right: a web app read a credential straight out of the environment, the session
reverted it, and said why. Then it reached the last paragraph of its own brief —

```
FOUR THINGS ARE NEVER YOURS: licence, money, security, and anything that changes what the customer
sees. For those, leave the document as it is and write `NEEDS OPERATOR: <what> — <the question>`
```

— read *security*, and parked the Task on a person.

The repo already answered it. That product routes exactly this kind of call through a job: the web
app queues it, a worker claims it, and the worker is the one process that holds the credentials —
under decisions recorded in its own `docs/decisions/`. The ruling the session was asked for
followed from that pattern in one sentence. Instead the item sat parked, a person read the
question, and answered it out of the repo the session was already standing in.

Two things made that happen, and neither of them is the four-things rule, which is right.

**The session was never handed the repo's own precedent, so it would have had to go looking.**
Every other fact an adjudicator needs is generated into its brief and never searched for — the
card, the documents, the footprint, the last report, the branch, the newest review quoted whole,
and the item's own standing rulings (`asf/briefs/build.py:770-784`). That list is deliberate:
`asf/briefs/preamble.py`'s first paragraph puts 93 % of a run's cost on "the agent discovering
what the runner already knew". The product's decision register is the one body of settled fact
that is *not* in the list, though the factory already indexes it — `asf.record.decisions` reads
`docs/decisions/` on every ingest and every plan-tasks step, for ids alone
(`asf/record/decisions.py:28-55`).

**And nothing asked the session to look.** The brief's four-things paragraph names the classes that
go to a person; it does not say *first establish that the repo has not already settled it*. A
`NEEDS OPERATOR` line is not refused for lacking a precedent, and no field of the REPORT records
whether a search happened. So the park reaches the operator as a bare question, with no answer to
"did you check?" and no citation to check against.

The asymmetry is the defect. When the review loop raises a point an adjudicator already settled,
the factory reads the ruling back and refuses to spend a round on it — `asf.evidence.rulings`,
whose own docstring is this exact lesson ("Until now nothing read it back"). The adjudicator is
the one role with no such reading: it writes precedent and never reads any.

So this spec does not change what goes to a person. Licence, money, security and customer-visible
change stay the operator's, in those words. It changes what the session must have established
before it says so, and what the park says when it does: the decisions the repo carries are
generated into the brief; the template requires the search before the park; the REPORT gains one
`precedent:` line; and the citation rides the park's own sentence into `asf status` and the
ruling's line into the card's History, where `rulings.standing` reads it back for the next round.
A park becomes a question with its homework attached, or it does not happen.

## The design

### §1 `asf/evidence/precedent.py` — the register, and the citation's grammar

The module docstring states the asymmetry and the incident, in the shape `rulings.py` uses: what
went wrong, what is now read, and where.

**The register.**

```python
#: The head of a decision file read for its title and status — the same budget
#: :func:`asf.record.decisions.docs_ids` already reads for its id.
HEAD_BYTES = 2048
#: The decisions a brief lists (older ones are named by count). Twenty, not ten: a register is
#: the product's whole settled history, where a ruling list is one item's.
BRIEF_MAX = 20
#: A status that makes a decision *not* precedent — it reads as settled and is not (C5).
STALE_STATUS = ('superseded', 'rejected', 'withdrawn', 'draft', 'proposed')

TITLE_RE = re.compile(r'^title:\s*"?(?P<t>[^"\n]+?)"?\s*$', re.M)
HEADING_RE = re.compile(r'^#\s+(?P<t>\S.*?)\s*$', re.M)
STATUS_RE = re.compile(r'^(?:-\s*\*\*Status:\*\*|status:)\s*(?P<s>[^\s*]+)', re.M | re.I)


def entries(product, items=None):
    """Every in-repo decision, as ``[{'id', 'title', 'status', 'path'}]``, newest id first.

    Two sources, one register (:func:`asf.record.decisions.register`'s own pair): the product's
    ``docs/decisions/`` files, read through :data:`asf.record.decisions.DOCS_DIR` under
    :func:`asf.record.decisions.repo_dir`; and the record's own ``decision`` cards out of
    ``items`` (the index the brief already holds). ``path`` is record-relative for a file and
    ``''`` for a card.

    Pure and total: no git, no network, no clock. An unreadable directory, an unreadable file or
    a file with no title is skipped, never raised — no register is no precedent, never an error
    (:func:`asf.record.decisions.docs_ids`' own rule)."""
```

Each file contributes one row: its id by `decisions`' own three rules (`D-nnnn.md`, a front-matter
`id:`, a numbered stem), its title by `TITLE_RE` then `HEADING_RE` over `HEAD_BYTES`, its status by
`STATUS_RE` (`''` when absent — P4), its path as `os.path.join(decisions.DOCS_DIR, name)`. Each
`items` entry whose `type` is `decision` and which the index does not retire contributes
`{'id', 'title': entry['title'], 'status': entry.get('state') or '', 'path': ''}`. Rows are keyed
by `(id, path)`, so a file and a card of the same id both appear (Out (f)).

**The brief section.**

```python
def brief_section(entries):
    """The ``IN-REPO PRECEDENT`` block for an adjudicate brief — ``''`` when the register is
    empty (a product with no recorded decision gets no section and no instruction it cannot
    follow)."""
```

Its text, with `<n>` the count and the rows `BRIEF_MAX`-bounded, newest id first:

```
IN-REPO PRECEDENT — READ THIS BEFORE YOU PARK ANYTHING ON A PERSON. This product has already
settled <n> question(s) in writing. A dispute an entry below answers is not a question for a
person: it is a ruling you can write in one sentence, citing the entry. Read the entry itself —
the title is an index, not the decision.

- D-0003 — A Task's planned first review is not repair (accepted) · docs/decisions/0003-a-planned-first-review-is-not-repair.md
- …
(N older decision(s) not listed: the rest of docs/decisions/.)

The second precedent is the pattern already in the code: the product usually already does, once,
somewhere, the thing under dispute. Before any `NEEDS OPERATOR`, establish both — the decisions
above and the pattern — and say which in the report's `precedent:` line. A status that is not
`accepted` is not precedent: go read what replaced it.
```

The two greps the block names are the session's own (C8), in its own worktree: the dispute's
subject over `docs/decisions/`, and over the code the hold's text and the diff name.

**What the park and the card say.**

```python
def park_note(text):
    """The clause :func:`asf.workers.lifecycle.blocked_park_text` appends for an adjudicate run,
    or ``''``. Three shapes, and each is a different fact for the person who opens the park:

    * ``precedent: <citation>`` — it found one and still parked (a licence, money, security or
      customer-visible call the precedent did not settle);
    * ``no in-repo precedent: <what it searched>`` — it looked and the repo is silent;
    * ``its report names no precedent — the repo may already answer this`` — no ``precedent:``
      line at all, so nobody has established that the repo was read."""

def history_note(text):
    """``" [precedent: <citation>]"`` for a report that names one, else ``''`` — appended to the

    :func:`asf.evidence.rulings.standing` reads it back into every later brief."""
```

### §2 `asf/workers/report.py` — one field

`FIELDS` gains `'precedent'` after `'superseded_by'`; `FIELD_RE`'s alternation gains `precedent`
in the same place (P8 — no prefix collision with `proves`). One accessor, beside `ruling`:

```python
def precedent(text):
    """The ``precedent:`` line of an adjudicate session's REPORT, or '' — the in-repo precedent
    it established before it parked a question on a person (F-0262)."""

```

`needs_input`, `ruling_fields`, `failure` and `unpushed` are not touched: a `precedent:` line
neither asks a question nor answers one, and it is not a ruling field.

### §3 `asf/briefs/build.py` — the supply and the line

And the supply, in `rulings_section`'s own shape (P6):

#: The kinds whose brief carries the product's in-repo precedent (:mod:`asf.evidence.precedent`):
#: the one role that parks a question on a person for the factory, and the one that writes
#: precedent without reading any (F-0262).
PRECEDENT_KINDS = ('adjudicate',)


def precedent_section(product, kind, items):
    """The product's decision register (:func:`asf.evidence.precedent.brief_section`) for a
    :data:`PRECEDENT_KINDS` brief, or ''."""
    if kind not in PRECEDENT_KINDS or product is None:
        return ''
    from asf.evidence import precedent
    text = precedent.brief_section(precedent.entries(product, items))

wired as the next term of `build()`'s part 3, after `rulings_section` and before

### What it looks like when it is there

An adjudicate session on the incident's hold opens its brief and reads, above the review,
the product's seven recorded decisions — one of them the job-queue routing for privileged calls.
It greps the code for the pattern, finds the worker that holds the credentials, and rules:
*upheld; the web app's direct read is reverted, and the call goes through the job, as D-0004 and
`workers/jobs/claim.py` already do it.* Its REPORT reads
`precedent: D-0004, workers/jobs/claim.py` and carries no `NEEDS OPERATOR`. The tick files
`- 2026-10-06 14:02 adjudicate (adjudicate-t-42278): upheld; … [precedent: D-0004, workers/jobs/claim.py]`
onto the card, where the next reviewer reads it as binding. Nothing is parked, and no person is
asked.

When the repo really is silent, the same session writes `precedent: none — docs/decisions/ (7
entries, none on credentials), grep -rn "getenv" over the app` and its `NEEDS OPERATOR` stands.
The operator opens `asf status` and the `Parked` row reads
`T-42278 [item]: the session ended with nothing to land and declared: … — no in-repo precedent:
docs/decisions/ (7 entries, none on credentials) …` — so the first thing they know is that the
search was done, and where.

## Records

* **The brief** — one new section per adjudicate brief, `IN-REPO PRECEDENT`, generated from the
  product's `docs/decisions/` and the record's decision cards, bounded at `BRIEF_MAX` rows, and
  one new line in the shared REPORT block that every kind prints and only `adjudicate` fills. No
  other kind's brief gains a byte (Out (d)).
* **The REPORT** — one field, `precedent:`, in `report.FIELDS` and `FIELD_RE`. A session's own
  declaration, read by three callers (`park_note`, `history_note`, and the `else` branch of
