# F-0067 — every ephemeral thing has an owner, a row and a last day

The factory already sweeps three floors, each on its own, each knowing nothing of the others.
`asf.workers.worktrees.reap` removes an ended session's checkout when its work is safe and the
buffer is full. `asf.workers.retention.sweep` deletes origin's expired `archive/*` heads and
counts the ones no pattern owns. `asf.workers.trash`'s detached deleter empties the trash after
the tick. Each writes its own state file, each has its own doctor row, and between them sits
everything nobody enumerates at all:

| Thing | Where it is written | Who removes it today |
| --- | --- | --- |
| a session's brief | `<state>/briefs/<job>.md`, `<job>.setup.log` | nothing — `spawn` writes them, no code deletes one |
| a cloud run's brief ref | `refs/asf/briefs/<job>` on origin | `actions.delete_brief(worktree, ref)` — which needs the worktree, so a reaped worktree strands the ref for good |
| an id-range lease | a row in `<state>/id-ranges.tsv` | `spawn.release_id_range`, called only by a successful reap |
| a worktree the reaper refuses | `<state>/worktrees/<job>` | nothing: `N unpushed commit(s)` is a `keep` verdict for ever |
| the operator's own tooling | a directory of scripts | nothing, and a hand-made backup copy beside a file is how a mistake is undone |

The second column is the whole defect. A thing with no owner and no last day is not cleaned up;
it is *forgotten*, and it stays until a disk fills or a session mints against a lease that should
have been freed a week ago. The first three sweeps are right — they are just not a floor.

This spec makes the floor one thing: a **registry** of ephemeral classes, each with an owner, the
registry row that proves who owns it and a TTL; **one sweep** in the tick that judges every class
and routes what it finds — the safe classes removed, the rest raised as groom lines; **one row on
the health table** carrying the counts and the TTL violations per class; and a **hold branch**, so
the one class that could lose work — a dead job's worktree carrying commits nowhere else — can be
removed within a day without losing them. The operator's tooling becomes a checkout under the same
rule: a tool change is a commit, a mistake is a revert, and a backup copy beside a file is a
violation the doctor names.

## 1. Decisions

### 1.1 Preconditions

- `asf.workers.worktrees` already owns the worktree verdict: `plan` returns one `Verdict`
  (`live` / `keep` / `spare` / `remove`) per directory with the reason, `safety` decides whether
  removal loses anything, and `reap` moves a `remove` into the trash through
  `trash.discard`. This spec adds a TTL and a hold branch in front of it; it does not re-judge
  safety.
- `asf.workers.retention` already owns origin's heads: `remote_heads` lists them, `tip_dates`
  reads their committer dates, `candidates` applies `archive_days` / `legacy_days` with the four
  holds (open PR, open item, in-flight run, protected), and `delete` removes one under a lease.
  The floor calls it; it does not re-implement it.
- `asf.workers.trash` already renames a worktree out of git in O(1) and empties the trash in a
  detached, nice'd deleter. `pending(state_dir)` is the count still waiting.
- `asf.workers.pool` / `asf.workers.lifecycle` are the registry: `load_sessions(product)` is
  every run keyed by job, `by_worktree(registry)` keys them by path, `is_live` / `landed` /
  `pending_correction` / `eligible` say what a run still wants. "Has a registry row" is
  `lifecycle.by_worktree` or `load_sessions` answering; nothing else is a row.
- `asf.conventions.Conventions` already carries a map convention with a typed accessor and a
  shape check — `branch_retention` / `conv.retention(key)` / `_retention_problems` is the exact
  shape `floor` copies.
- `asf.doctor.run` already builds `[(row, required, ok, detail)]` in table order, and the
  `worktrees` and `branches` rows read a state file and measure nothing. A `floor` row does the
  same.
- `asf.groom.groom.EXTRA_SECTIONS` already renders a section only when it has lines, and
  `merge_groom_text` dedupes a line by `line_token` — the lead token of `- [ ] <token> …`, which
  `inbox:<file>` already proves need not be an item id.
- `asf.groom.policy.OPEN_QUESTION_RE` matches `- [ ] <id|inbox:…> … → answer: ____` only. A line
  whose token is neither an item id nor `inbox:` is **not** an open question by construction, so
  it mints no adjudicate row and no answer is ever expected for it.
- `asf.gitpush.push(..., refs_only=True)` is the bookkeeping push: `--no-verify`, timeout-bounded,
  process group killed past it. `asf.refguard.refusal` refuses the trunk and a protected ref
  before anything is sent.
- `ctx.event(kind, **fields)` appends a free-form line to `metrics/events/<day>.jsonl`; that
  stream has no schema to extend.
- `asf/tick/step_health.py`'s `run()` does **not** call the two sweeps together.
  `reap_worktrees(ctx)` is its fourth statement — before `file_rulings`, `widen_footprints`,
  `stall`, `handle_dead`, `hold_failed_corrections` and `ci_trials` — and
  `branch_retention(ctx, items)` is its last. There is no one place "where the two sweeps run":
  §2.8 picks one of the two and says which call moves.
- `handle_dead`'s `reaped_empty` comes from `health_mod.health`'s own `found` rows
  (`what == 'reaped'`), not from `reap_worktrees`. Nothing between the two call sites reads the
  reaper's result, so moving the worktree reap later in `run()` changes nothing a later step sees.
- `worktrees.safety(path, branch, main, heads, run=None, fetch=False)` takes no job: the job is
  `run['job']`, and `plan` already falls back to the directory name. It reaches
  `unpushed commit(s)` from **two** exits — `f'{m} unpushed commit(s)'` when the branch is on
  origin, and `f'{len(off_trunk)} unpushed commit(s) ({why})'` when `heads is None` (origin
  unreadable) or the branch is not on origin. Its other refusals — `N uncommitted file(s)`,
  `<x> in progress`, `origin/<b> not fetched`, `origin/<b> unreadable`, `<trunk> unreadable` —
  are not holdable, and the dirty check is the first of them.
- `retention.owned_patterns(conv)` composes `conv.all_prefixes()`, the *module constant*
  `ARCHIVE_PREFIX` and `conv.retention('legacy_prefixes')`. A head prefix the factory itself
  owns is already a constant of `retention`, never a product convention.
- `groom._SECTION_BY_TITLE` is built from `GROOM_SECTIONS + EXTRA_SECTIONS`, so a pair appended
  to `EXTRA_SECTIONS` is registered for the merge by its title with no second edit.
- `doctor.run`'s `branches` row is conditional (`if branches:`); `worktrees` is always appended.
  "After `branches`" is therefore "last in the table", and a product with no branches row has no
  gap.
- `plugin_build.skill_names()` is `VIEWS + DIALOGUES`, and `expected_files` renders one skill per
  name in it. A new command that is neither a view nor a dialogue leaves `asf plugin check` — a
  CI step — generated and green.
- `asf/workers/__init__.py`'s `cmd_health` is three calls, not two: `health.health(product,
  fix=args.fix)`, then `worktrees.reap(product)` with `--fix` or
  `worktrees.report(worktrees.dry_run(product)[0])` without it, then `retention.sweep(product,
  fix=args.fix)`.

**Two whole-tree fences already stand over `asf/**/*.py`, and a new module is inside both.** They
are preconditions, not consequences: a floor that ignores either one is red on `main` the day it
lands, whatever its own tests say.

- `tests.test_lifecycle.OneClassifierTest.test_no_module_but_lifecycle_derives_a_state_word` walks
  every `asf/**/*.py` except `asf/workers/lifecycle.py` and a closed `NOT_YET` tuple, and fails on
  a string literal equal to `lc.DEAD`, `lc.DEAD_PID`, `lc.WORKING` or `lc.ENDED_AWAITING_TICK`, or
  on **any** `==` / `!=` / `in` / `not in` against `end_reason`. `asf/floor.py` is not on `NOT_YET`
  and cannot join it: F-0098's plan empties that tuple to `()`.
- `tools/check_conventions.sh` is a CI step, and
  `tests.test_conventions.CheckConventionsScriptTests.test_the_whole_package_is_clean` asserts it
  exits 0 over the real tree. It fails any `asf/**/*.py` outside its four exempt files that
  carries a path-shaped convention default (generated from `python3 -m asf.conventions
  --forbidden`) or a `tools/forbidden-conventions.txt` pattern — among them
  `tools/<name>.(py|sh|json)`, `/tmp/`, `.claude/` and `cloud/`. `asf/floor.py` is not exempt.

### 1.2 In

- **`asf/floor.py`** — the registry and the sweep: `Klass` and `CLASSES` (eight classes, §2.1),
  `Thing`, `judge`, `sweep`, `hold`, `doctor_line`, `groom_lines`, `violations`.
- **`asf/conventions.py`** — a `floor:` map convention with `DEFAULT_FLOOR`, `conv.floor(key)`
  and `_floor_problems`, beside `branch_retention`.
- **`~/.ASF/config.yaml`** — `tool_dirs:`, the operator's own tooling directories (a machine path
  is never a product convention), read by the `tooling` class alone.
- **`asf/workers/worktrees.py`** — `safety` reads one more head: a worktree whose own commits are
  on `hold/<job>` is safe to remove, exactly as one whose commits are on `origin/<branch>` is.
- **`asf/workers/retention.py`** — `HOLD_PREFIX = 'hold/'` beside `ARCHIVE_PREFIX`, and it joins
  `owned_patterns`, so a hold branch is never counted as an unowned head.
- **`asf/doctor.py`** — the `floor` row (`required=False`), off the state file.
- **`asf/groom/groom.py`** — `FLOOR_FINDINGS` in `EXTRA_SECTIONS`, filled from the state file.
- **`asf/tick/step_health.py`** — `floor_sweep` at `branch_retention`'s place, the last statement
  of `run()`; the early `reap_worktrees(ctx)` call is deleted and the reaper becomes the worktree
  class's remover inside the sweep (§2.8).
- **`asf floor [--fix] [--check] [--json]`** — the command: the report, the sweep, and the
  rule-check contract (exit 1, one line per violation).
- Tests for the registry, the conventions, each probe, the routing, the hold branch, the doctor
  row, the groom section, the tooling class and the wiring (§3).

### 1.3 Out

- **A new tick step.** The floor runs inside `health`, printing the lines the two sweeps print
  there today. A step of its own would need a manifest entry in every product yaml for no
  acceptance.
- **Extending `NOT_YET`.** `asf/floor.py` obeys the one-classifier fence from its first line
  (§1.1): it asks `lifecycle` what a run is and never spells a state word or reads `end_reason`.
  Adding a tenth path to a tuple F-0098 is emptying would be this branch taking back that card's
  work.
- **Making `hold/` a convention.** It is a prefix the factory itself owns, like `archive/`; a
  product cannot rename it without renaming the code that reads it. It is a module constant, and
  §1.1's `check_conventions.sh` fence is the second reason: a convention default copied into
  `asf/floor.py` is a red gate.
- **Re-implementing a sweep that works.** The worktree reaper and the branch retention pass keep
  their code, their state files and their doctor rows. The floor adds the TTL, the count and the
  routing, and calls them as the two classes' removers.
- **Moving `archive_days` / `legacy_days` into `floor:`.** They stay in `branch_retention`. The
  floor reads them through `conv.retention`; moving them would silently drop the value of every
  product yaml that sets one.
- **Deleting anything the operator wrote.** The `tooling` class never removes a file. A backup
  copy is named, with the command that removes it; the hands are the operator's.
- **Deleting a hold branch.** A hold branch is the only copy of its commits. Its TTL raises a
  line; nothing unattended removes it.
- **Committing a session's uncommitted work.** A dirty dead worktree is raised, never committed:
  the factory cannot judge unstaged work, and a sign-off on it would be a lie.
- **A floor line that asks a question.** The lines are statements, not questions (§2.7): an
  answer verb per class (`delete` / `keep` / `land`) and an applier for it is a second Feature,
  and the card asks for lines.
- **A rule card.** The floor rule's *check* is `asf floor --check`, which already obeys the
  check contract in `asf/rules/rules.py` (exit 0 pass, exit 1 with one line per place). Minting
  `R-nnnn` and pointing it at that command is the record's, not this branch's.
- **Folding this Feature into the clean-floor Feature, or the other way.** The card says so
  itself: that is a groom question, and this spec is written to stand alone either way.
- **Measuring anything in the doctor.** The row reads `floor.json`. A `du` in a doctor row is how
  a health check becomes the thing that hangs.

### 1.4 The choices

| Choice | Against | Why |
| --- | --- | --- |
| One registry of classes, in `asf/floor.py` | a TTL added inside each owner's module | The acceptance is a *row per class with a count and its violations* — that needs one table something can iterate. Eight owners each with a private TTL is what exists today, and it is exactly what nothing can report on. |
| `asf/floor.py` at the package top, not `asf/workers/floor.py` | under `workers/` | The classes span `workers` (worktrees, briefs, leases), `harvest` (branches) and the operator's own tooling. No one owner's package can hold the registry without importing its siblings; the top level already holds the cross-cutting modules (`doctor`, `refguard`, `gitpush`). |
| The sweep calls the existing removers | one new remover per class | `worktrees.reap` and `retention.sweep` carry the four holds, the lease, the cap and the host refusals that took bugs to learn. A second remover would relearn them. |
| One sweep inside the `health` step | a ninth step | The two sweeps already run there, and every line a test or an operator reads today is a line the floor still prints. A step of its own buys nothing and costs a manifest entry per product. |
| The one call sits at `branch_retention`'s place — the last statement of `run()` — and the worktree reap moves there from its early slot | one call at the reaper's early slot, or two calls and "one sweep" in name only | The two call sites are five statements apart (§1.1), so *something* must move; the question is which way. Later is also the only correct way: the hold gate asks whether a correction or a relaunch still wants this checkout (§2.4), and `handle_dead` and `hold_failed_corrections` — which decide exactly that — run **between** the two sites. At the reaper's old slot those two predicates are not yet settled, so the floor would hold and reap a worktree the same tick's `handle_dead` was about to hand back to a correction. Nothing between the sites reads the reaper's result (§1.1), so moving it costs nothing else. |
| `HOLD_PREFIX` lives in `asf/workers/retention.py`, beside `ARCHIVE_PREFIX` | in `asf/floor.py`, with `owned_patterns` importing it | `owned_patterns` already composes `ARCHIVE_PREFIX` exactly this way, and `retention` is the module whose subject is origin's heads. The other direction is a cycle — `floor` imports `retention` as the archive class's remover — and it would put the `'hold/'` literal in the one module §1.1's convention fence watches hardest. |
| The floor asks `lifecycle` what a run is | reading `end_reason`, or matching a state word | Not a preference: `asf/floor.py` is inside the one-classifier fence (§1.1), so `run.get('end_reason') == …` is a red gate, not a style note. `is_live` / `landed` / `pending_correction` / `eligible` already answer everything the sweep asks, and the one classifier stays one. |
| The TTLs are a product map convention (`floor:`) | constants in `asf/floor.py` | A product that runs one tick an hour and one that runs four have different last days; `branch_retention` already set the precedent, and the doctor's `conventions` row already checks that shape. |
| `tool_dirs:` in the operator's config | a product convention, or reusing `legacy_paths` | A tooling directory is a path on one machine — it can never be a product convention (`tools/check_generic.sh` would refuse the default). And `legacy_paths` means *pre-ASF tools to retire*: pointing the new check at it would make every retirement a violation. |
| A dead job's commits go to `hold/<job>` before its worktree goes | keeping the worktree until a human looks, or forcing the reap | The reaper is right to refuse: the commits are nowhere else. Push them somewhere they are, and the refusal disappears with the work intact — which is what makes "gone within a day" safe to promise. |
| The hold push is `refs_only` (`--no-verify`) | an ordinary push | A hold branch is never reviewed, never CI'd, never merged; it is a copy. Retention already learned that a product's own pre-push hook runs a whole-tree lint per ref write and refuses it (2026-09-25), and that hook has nothing to say about a copy. |
| `hold/<job>`, keyed on the job | `hold/<branch>` | Two runs of one item share a branch and not a job, so the job is what makes the ref unique and names the run whose work it is. The branch is in the commit's own history. |
| `safety` learns the hold head | the floor removing the worktree itself | One owner for removal. `safety` already answers "is every own commit somewhere else"; the hold head is one more somewhere. The floor deciding to `rm` behind the reaper's back is how a `spare` worktree a correction wanted would vanish. |
| Only a worktree whose run ended, has no pending correction and is not eligible for a relaunch is held | every over-TTL worktree | A queued run reuses its worktree, its install and its session; holding and reaping it would throw all three away to save a gigabyte. Such a worktree is raised when its TTL is spent, not swept. |
| A dirty dead worktree is raised, not held | committing what is there, or `discard(check_clean=False)` | Nothing in the factory can say whether an uncommitted file is work or a scratch file, and `git worktree remove` refuses it for the same reason. The line names the files; the operator decides. |
| The floor's lines are stated, not asked | making each a `→ answer: ____` question | `OPEN_QUESTION_RE` accepts an item id or `inbox:` only, so a `floor:` question would be counted open by nobody and answered by nobody — a question with no reader. A statement in the groom file, and a red-free doctor row, is what the card asks for. |
| One line per class, dedupe token `floor:<class>` | one line per thing | Twelve stranded brief refs are one finding with a count and an oldest, not twelve lines. `merge_groom_text` then keeps one line per class per day, however the counts move. |
| The doctor row is `required=False` | red on any violation | Every floor finding is clutter, and clutter must never be the reason a doctor run fails a gate. `worktrees` and `branches` are already `False` for the same reason; the row's `ok` still turns `skip`, and the count is in the detail. |
| The tooling class's TTL is `tool_dirty_hours` on the *uncommitted* change | a TTL on the files | "A tool change is a commit" is the rule; the violation is a change that has not become one. A backup copy is a violation the moment it is seen (§2.6), with no TTL to wait out. |

## 2. The design

### 2.1 The registry — `asf/floor.py`

```python
"""asf.floor — the factory's ephemeral things: an owner, a registry row and a last day each.

One :class:`Klass` per class of thing the factory creates and nothing keeps. A class declares
who makes it (``owner``), the generic shape of where it lives (``where``), the convention that
gives its TTL, whether an expired one may be removed unattended (``safe``), and the two
callables that enumerate it and remove one. :func:`sweep` walks the table once a tick: the safe
classes' expired things go through their own owner's remover, and everything else becomes a line
(§2.7) and a count on the doctor's ``floor`` row (§2.5).
"""

@dataclasses.dataclass(frozen=True)
class Klass:
    name: str            #: the class, and the dedupe token's tail (``floor:<name>``)
    owner: str           #: the module that creates one — 'asf.workers.spawn'
    where: str           #: the generic shape: '<state>/worktrees/<job>', 'hold/<job>' on origin
    ttl: str             #: 'floor.worktree_days' | 'branch_retention.archive_days'
    safe: bool           #: may an expired one be removed with nobody watching
    probe: callable      #: probe(ctx) -> [Thing]
    remove: callable     #: remove(ctx, things) -> ([removed], [(thing, why)]); None when unsafe


@dataclasses.dataclass
class Thing:
    klass: str
    id: str              #: the class-local name: a directory, a branch, a job, a path
    age_s: float         #: how long it has existed, by the class's own clock (§2.3)
    owner: str = ''      #: the job whose it is, '' when the class has no job
    row: bool = True     #: the registry holds a row for it — False is an orphan
    why: str = ''        #: what the probe wants said about it
```

`CLASSES` is one tuple, in sweep order:

| `name` | `where` | `owner` | the registry row | `ttl` (default) | `safe` |
| --- | --- | --- | --- | --- | --- |
| `worktree` | `<state>/worktrees/<job>` | `asf.workers.spawn` | the ledger row at its path (`lifecycle.by_worktree`) | `floor.worktree_days` (1) | yes — `worktrees.reap`, behind §2.4 |
| `trash` | `<state>/trash/<name>-<stamp>` | `asf.workers.trash` | the stamp in its own name | `floor.trash_hours` (24) | yes — `trash.kick` |
| `brief` | `<state>/briefs/<job>.md`, `<job>.setup.log` | `asf.workers.spawn` | the ledger row of `<job>` | `floor.brief_days` (7) | yes — unlink |
| `brief-ref` | `refs/asf/briefs/<job>` on origin | `asf.workers.actions` | the ledger row of `<job>` | `floor.brief_days` (7) | yes — a ref delete from `repo_dir` |
| `id-range` | a row in `<state>/id-ranges.tsv` | `asf.workers.spawn` | the ledger row of `<job>` | `floor.id_range_days` (2) | yes — `spawn.release_id_range` |
| `archive-branch` | `archive/<b>` on origin | `asf.harvest.lane` | `branch-retention.json` | `branch_retention.archive_days` (14) | yes — `retention.sweep` |
| `hold-branch` | `hold/<job>` on origin | `asf.floor` (§2.4) | `floor.json`'s `held` list | `floor.hold_days` (30) | **no** |
| `tooling` | each `tool_dirs:` entry | the operator | the checkout's own history | `floor.tool_dirty_hours` (24) | **no** |

Every probe takes one `Ctx` — `(product, conv, now, sessions, heads, state_dir)`, built once per
sweep so eight probes share one `ls-remote` and one `load_sessions` — and returns `Thing`s
without touching anything. `remove` is `None` for an unsafe class, and `CLASSES` is checked at
import: a name twice, a `ttl` naming no convention, or `safe` with no remover is a `FloorError`.

### 2.2 The TTLs — `asf/conventions.py`

```yaml
conventions:
  floor:                    # asf.floor: how long an ephemeral thing of each class is kept
    worktree_days: 1        # an ended job's checkout; its commits go to hold/<job> first
    trash_hours: 24         # a discarded tree still waiting for the background deleter
    brief_days: 7           # a brief and its setup log, after the run ended
    id_range_days: 2        # an id-range lease, after the run ended
    hold_days: 30           # a hold branch — raised at the TTL, never deleted
    tool_dirty_hours: 24    # an uncommitted change in a tool_dirs checkout
    grace_hours: 1          # a thing younger than this is being created: never judged
```

`DEFAULT_FLOOR` holds those seven with a doc comment each; `floor` joins `MAP_CONVENTIONS`;
`conv.floor(key)` is `conv.retention(key)`'s twin — a missing, misshapen or negative value reads
as its default, and `_floor_problems` (called from the shape check, beside
`_retention_problems`) names it on the doctor's `conventions` row. `conv.floor_ttl_s(key)`
converts `_days` / `_hours` to seconds so `judge` never parses a unit.

### 2.3 The judgement — `floor.judge(klass, thing, conv, now)`

```python
OK, EXPIRED, ORPHAN = 'ok', 'expired', 'orphan'
```

One verdict per thing, pure:

- younger than `grace_hours` → `OK`, whatever else is true of it (it is being created);
- `thing.row` false → `ORPHAN`: nothing owns it, and no TTL applies — an orphan is a violation
  the moment the grace is past;
- `thing.age_s > ttl_s` → `EXPIRED`;
- else `OK`.

Each class's clock, once, so no probe invents one:

| class | `age_s` is measured from |
| --- | --- |
| `worktree` | the run's `ended`, else its `started`, else the directory's mtime |
| `trash` | the `-<stamp>` in its own name, else its mtime |
| `brief`, `brief-ref` | the run's `ended`, else the file's mtime / the ref's committer date |
| `id-range` | the run's `ended` (a row whose job has no ledger row is an orphan) |
| `archive-branch`, `hold-branch` | the tip's committer date (`retention.tip_dates`) |
| `tooling` | the oldest uncommitted change's mtime; a backup copy's own mtime |

"The run's `ended`" is the timestamp field, and it is the only thing about a run the floor reads
directly. *Whether* a run has ended, died, landed or still wants this checkout is never derived
here: the sweep asks `lifecycle.is_live`, `lifecycle.landed`, `lifecycle.pending_correction` and
`lifecycle.eligible`, and `asf/floor.py` contains no state word and no `end_reason` comparison —
the fence in §1.1, not a preference.

`violations(state)` is the pair `(expired, orphans)` summed over the classes — what the doctor
row and `--check` both read, so one number is never computed twice.

### 2.4 The hold branch — `floor.hold(ctx, verdict)`

The one class that could lose work. Before the worktree class calls `worktrees.reap`, the sweep
takes every verdict where **all** of these hold:

1. the reaper's action is `keep` and its reason carries `unpushed commit(s)` — a substring test,
   because `safety` reaches that text from two exits with different tails (§1.1), and the *only*
   refusal a hold can answer. `N uncommitted file(s)`, `<x> in progress`, `origin/<b> not
   fetched`, `origin/<b> unreadable` and `<trunk> unreadable` are all `keep` and none is holdable;
2. `heads` is not None — origin was readable. When it is None the hold ref cannot be read either,
   so a hold would be a blind push against a ref whose sha is unknown;
3. `lifecycle.is_live` is false, `lifecycle.pending_correction` is false and `lifecycle.eligible`
   is false — nothing queued will reuse this checkout (and §2.8 is why these are already settled
   by the time the sweep asks);
4. `judge` says `EXPIRED` (over `floor.worktree_days`) or `ORPHAN`.

and pushes the worktree's HEAD to `hold/<job>` — `HOLD_PREFIX` is `retention`'s constant (§1.4),
imported by `floor`, so the prefix has one owner and the import runs one way:

```python
from asf.workers.retention import HOLD_PREFIX   # 'hold/', beside ARCHIVE_PREFIX


def hold(ctx, verdict):
    """Push the worktree's own commits to ``hold/<job>`` so removing it loses nothing.
    ``(sha, why)``: the sha now on the hold branch, or ('' , why) and the worktree kept.

    Refused before anything is sent (:mod:`asf.refguard`) when the computed ref is the trunk or
    a protected one; refused when the tree is dirty (§1.3) or HEAD is already on the trunk
    (nothing to hold). The push is ``refs_only`` — a copy nobody reviews never runs the
    product's pre-push hook — and it is never a force: a hold ref that already exists at another
    sha is left alone and the worktree kept, so two runs of one job can never overwrite each
    other's work.
    """
```

`worktrees.safety` gains the matching read at **both** of its `unpushed commit(s)` exits (§1.1) —
the one where `origin/<branch>` exists and still lacks `m` commits, and the one where the branch
is not on origin at all. In each, before returning `False`, it looks up
`(heads or {}).get(HOLD_PREFIX + job)` — `job` is `(run or {}).get('job')`, the directory name when
there is no run, which is `plan`'s own fallback — and compares by ancestry, then by patch, exactly
as it does for `origin/<branch>`; a match is `True, 'held on hold/<job>'`. `heads` is the map
`plan` already fetched, so this costs no call. `retention` imports nothing from `floor`, so
`from asf.workers.retention import HOLD_PREFIX` is an ordinary module-level import here.

The pass is therefore: probe → hold the qualifying verdicts → `worktrees.reap(product)`, which
now returns them as `remove`. A dead job's worktree is gone in the same tick its TTL expires, its
commits on `hold/<job>`, and the hold branch is itself a class with a TTL that raises a line at
30 days. `retention.owned_patterns` adds `HOLD_PREFIX` to the prefix set beside `ARCHIVE_PREFIX`,
so the branch is owned, not unowned; and because `candidates` only ever proposes `ARCHIVE_PREFIX`
and the retired prefixes, no other pass can delete it either.

### 2.5 The row on the health table — `asf/doctor.py`

`run()` appends one row last — after `worktrees`, and after `branches` when that conditional row
is there at all (§1.1):

```python
ok, detail = check_floor(product)
rows.append(('floor', False, ok, detail))
```

reading `floor.json` alone — no listing, no `du`, no `ls-remote`:

```
floor   ok    floor: 8 classes, 41 things, 0 over TTL, 0 orphans — last sweep 2026-09-27T18:05:02Z
              (3 swept, 0 raised)
floor   skip  floor: 8 classes, 63 things, 4 over TTL, 2 orphans — worktree 7 (1 over TTL),
              brief 24 (2 over TTL), brief-ref 12 (2 orphans), hold-branch 3 (1 over TTL);
              last sweep 2026-09-27T18:05:02Z (3 swept, 4 raised)
```

`ok` is true only while `violations` is `(0, 0)`; a class with nothing to say is left out of the
detail, and before the first sweep the detail is `floor: no sweep yet`. The row is
`required=False`: clutter is never why a doctor run is red.

### 2.6 The tooling class — `tool_dirs:`

```yaml
# tool_dirs: the operator's own tooling. Each entry is a directory that must be a git checkout:
# a tool change is a commit and a mistake is a revert, so no backup copy is ever needed beside a
# file. `asf floor` names what breaks that; it never removes anything here.
# tool_dirs: [~/tools]
```

The probe yields one `Thing` per finding in each entry, expanded with `expanduser`:

| finding | `why` | verdict |
| --- | --- | --- |
| the directory is missing | `not a directory` | `ORPHAN` |
| no `.git` in it or above it inside the entry | `not a checkout — git init it and commit what is there` | `ORPHAN` |
| a checkout with no `origin` remote | `a checkout with no origin — a mistake is only a revert while a copy exists elsewhere` | `ORPHAN` |
| uncommitted or untracked files | `N uncommitted file(s), oldest <age>` | `EXPIRED` past `tool_dirty_hours` |
| a file whose name is a backup shape | `backup copy beside <file> — the history is the backup; rm it` | `ORPHAN` (no TTL) |

`BACKUP_PATTERNS` is the contract, matched case-insensitively on the base name:
`*.bak`, `*.bak[0-9]*`, `*.backup`, `*.orig`, `*.old`, `*.save`, `*.copy`, `*~`, `#*#`,
`*.[0-9][0-9][0-9][0-9][0-9][0-9][0-9][0-9]` (a date suffix) and `* copy*`. A path under `.git/`
is never walked. Nothing here is removed: every line names the command, and `git status` in the
entry is the whole evidence.

### 2.7 The lines — `asf/groom/groom.py`

```python
#: Rendered only when it has lines: what the floor sweep found and would not fix itself
#: (:func:`asf.floor.groom_lines`) — a statement per class, never a question (§1.4).
FLOOR_FINDINGS = ('Floor violations', 'floor')
EXTRA_SECTIONS = [INBOX_QUESTIONS, REFUSED_QUESTIONS, OVER_BUDGET_QUESTIONS, FLOOR_FINDINGS]
```

`cmd_groom` fills it beside the other three, from the state file the sweep wrote:

```python
sections[FLOOR_FINDINGS[1]] = floor.groom_lines(product)
```

One line per class with a finding, ordered as `CLASSES` is:

```markdown
## Floor violations

- [ ] floor:hold-branch 3 hold branches, 1 over its TTL — oldest hold/worker-t-0290, 41d
  (hold_days 30): land it, archive it (`asf harvest`) or delete it by hand
- [ ] floor:tooling 2 findings in 1 tooling directory — a backup copy beside tick.sh, and 3
  uncommitted file(s) 5d old: commit them, then rm the copy
- [ ] floor:worktree 1 over its TTL the sweep will not touch — spec-f-0041, 3 uncommitted
  file(s): read them, commit or discard them, then the next sweep reaps it
```

Appending the pair to `EXTRA_SECTIONS` is the whole registration: `_SECTION_BY_TITLE` is derived
from `GROOM_SECTIONS + EXTRA_SECTIONS` (§1.1), so the merge finds `## Floor violations` by its
title without a second edit.

The token is `floor:<class>`, so `merge_groom_text` keeps one line per class per day and a second
tick changes nothing; the grammar in §1.1 means no adjudicate row is ever minted from one and no
policy answers one. A class with nothing to say has no line, and the section is not rendered when
no class has one.

### 2.8 The wiring — the tick and the command

`asf/tick/step_health.py`: the two calls are five statements apart (§1.1), so the change is not a
substitution in place. `floor_sweep` takes `branch_retention`'s position — the last statement of
`run()` — the early `reap_worktrees(ctx, out=out)` call is deleted, and `worktrees.reap` becomes
the worktree class's remover *inside* the sweep. `run()`'s tail is therefore:

```python
    hold_failed_corrections(ctx, sessions, out=out, items=items)
    ci_trials(ctx, out=out)
    floor_sweep(ctx, items, out=out)          # was: branch_retention(ctx, items, out=out)
    return 0
```

The worktree reap thus happens later in the tick than it does today, and that is the point: the
hold gate asks whether a correction or a relaunch still wants the checkout (§2.4), and
`handle_dead` and `hold_failed_corrections` are what decide it. At the old slot the answer was not
yet written; at the new one it is. Nothing between the two sites reads the reaper's result — 
`handle_dead`'s `reaped_empty` comes from `health`'s own rows (§1.1) — so no other step changes,
and a worktree a correction is about to reuse is now kept instead of reaped and re-cloned.

`floor_sweep` keeps the guard both calls had — a sweep never stops a tick:

```python
def floor_sweep(ctx, items, out=print):
    """The floor (:func:`asf.floor.sweep`): every ephemeral class judged against its TTL, the
    safe ones swept through their own owner's remover, the rest raised. Printed, never raised:
    the next tick sweeps again."""
    from asf import floor
    try:
        return floor.sweep(ctx.product, fix=True, out=out, items=items, event=ctx.event)
    except Exception as e:  # noqa: BLE001 — the next tick sweeps again
        out(f'floor: skipped — {type(e).__name__}: {e}')
        return None
```

`sweep` drives the worktree class first and the branch class last — the two removers' own relative
order, unchanged — and prints what they print (`worktrees: reaped …`, `retention: deleted …`) plus one line per class it
judged itself and one summary line:

```
floor: held worker-t-0290 → hold/worker-t-0290 (3 commits)
floor: brief 24 things, 2 over TTL (brief_days 7) — 2 removed
floor: brief-ref 12 things, 2 orphans — 2 removed
floor: 8 classes, 41 things, 4 swept, 2 raised
```

`asf floor` (registered in `asf/cli.py`) is the same pass by hand:

| invocation | what it does |
| --- | --- |
| `asf floor` | the report: every class, its count, its violations — nothing touched |
| `asf floor --fix` | one sweep, as the tick runs it |
| `asf floor --json` | the state file's shape, for a reader |
| `asf floor --check` | the rule-check contract: exit 0 when clean, exit 1 with one line per violation, no writes |

`asf/workers/__init__.py`'s `cmd_health` is three calls today, not two (§1.1). Its
`health.health(product, fix=args.fix)` stays, and the `worktrees.reap` / `worktrees.report(...)`
pair and the `retention.sweep` after it become one `floor.sweep(product, fix=args.fix)`: with
`--fix` the sweep as the tick runs it, without `--fix` the report — which is what
`worktrees.report(worktrees.dry_run(product)[0])` and `retention.sweep(fix=False)` each already
printed, now for eight classes instead of two.
