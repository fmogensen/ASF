# F-0163 — the severity a lane is held by is the one field no command can change

On 2026-09-26 at 20:35 a session needed to take B-1382 from S1 to S2. The reasons were settled:
`main` was green without the fix, production was already deployed, and the card's S1 was the only
thing holding the S1 lane's grip on 8 Ready rows. The session ran the obvious command and got:

```
error: bug has no settable field 'severity' (one of area, blockedBy, decided, legacy_id, links, priority, rank)
```

So the card was hand-edited. That is the exact failure `asf set` exists to prevent — the module's
own first sentence is *"The typed block is a machine-read format; a hand edit that breaks it costs a
tick"* (`asf/record/setfield.py:3`). A hand edit also writes no `## History` line, so the record
keeps the new severity and loses the reason for it, which for a downgrade is the only part anyone
will later want.

The gap is one line of table. `SETTABLE` (`asf/record/new.py:18-26`) gives every type the same seven
common fields and then adds per-type ones for `rule`, `decision` and `feature`; `bug` gets nothing
of its own, and `severity` — the one field a Bug is required to carry (`asf/record/check.py:236`) and
the one the whole fix lane is ordered by — is on no type's list.

The factory already knows this. `asf/feeder/tiers.py` prints, as the remedy on a `NEEDS OPERATOR`
line for an S1 nothing is working:

```
NEEDS OPERATOR: B-0057 is S1 and nothing is working it — adjudicated after 4 sessions — the S1
lane holds 0 of 94 tier-2 rows behind it — asf set B-0057 severity=S2 --product asf
```

That command has never worked. It is pinned, verbatim, by `tests/test_s1_gate.py:73`. The S1 gate's
own advice is the failing command this card is about, and fixing the field without fixing the
remedy would leave the advice one flag short of runnable.

### In

- **`severity` on the Bug's settable list** — `SETTABLE['bug'] |= {'severity'}`, validated against
  the `SEVERITIES` constant that has sat unused since it was written (P3), through the `FIELD_WORDS`
  gate that already refuses a bad word before the card is touched (P4).
- **A dated `## History` line for every severity change**, written inside the **same** guarded write
  as the field (P10's shape, not P9's), so the record never holds the new severity without the
  sentence that explains it — not even for the width of one failed write.
- **`--why` on `asf set`**, required when the card leaves `S1` and carried verbatim into that
  History line. A downgrade off S1 releases the lane's hold on everything behind it; that is the one
  severity move whose reason is worth more than the field.
- **The S1 gate's remedy, made runnable** — `asf/feeder/tiers.py`'s two `severity=S2` strings gain
  the `--why` the new gate requires, and its pinning test (P17) follows.

### Out

- **Any other type gaining `severity`.** `SETTABLE['bug']` only. `asf new decision --set
  severity=S1` stays refused and P6's test stays green unedited — that is the check that this stayed
  a Bug field.
- **A `--why` that records anything but severity.** A general "reason for this set" would mean a
  History line for every field, which is a different card: the groom already writes one per field on
  its own route (P14), and no one asked for `rank` to grow a paper trail. `--why` with no severity
  assignment is **refused** rather than silently dropped — D6.
- **Gating an upgrade, or an S2 → S3 downgrade.** The card names one gate: leaving S1. An upgrade
  *into* S1 tightens the lane rather than releasing it and needs no defence; `S2 → S3` holds nothing
  up. Both still write their History line — D4.
- **Changing what severity *means*.** Tiering, the `decided` coupling, the attempt limit, the S1
  gate's arithmetic, `idle`, `render`, `harvest`'s ordering: untouched. This card changes who may
  write the field, not what reads it (P15).
- **The groom's severity route.** `asf groom --apply` keeps writing severity from an answer word
  with its own `- <date> groom: severity → S2 (operator)` line (P14). Two writers, two line shapes,
  each naming itself — D3.
- **Backfilling B-1382.** The hand edit of 2026-09-26 stands. A History line invented now would be
  written by nobody, on a date that is not the date.
- **`state`, `stage` and the machine block.** Still not settable, still derived, still `asf reopen`'s
  business (`asf/record/reopen.py:3-12`).
- **A new event, a new card, a new approval class.** A severity change raises none. It is a typed
  field written by a console command, and `_published`'s `record: set <id>` commit is its trace
  (P19).

| # | Chosen | Against | Why |
| --- | --- | --- | --- |
| D1 | `severity` joins `SETTABLE['bug']` and `FIELD_WORDS['severity'] = SEVERITIES` — the two tables that already exist | a bespoke branch in `cmd_set` for severity; a new per-type validator | the refusal in P1 is not a policy, it is an absent row. `FIELD_WORDS` already means "this field's value is one of these words, checked before the card is touched", which is exactly and entirely what `S1|S2|S3` is, and `SEVERITIES` has been sitting one file away waiting to be its tuple since it was written (P3). A branch in `cmd_set` would put a second validation idiom in a module that has one, and would validate *after* the parse rather than before |
| D2 | The field and its History line are written in **one** `stage.guarded` closure (P10's shape) | the existing two-write shape: `set_typed`, then re-read, append, re-render (P9, `widen` and the groom) | the two-write shape leaves a window in which the card holds a severity the record cannot explain, and a failure in the second write makes that window permanent. The guard exists to refuse a write before anyone commits it (P7); a History line written outside it is a line the guard never saw. `reopen` — the other reasoned hand correction — already does it in one closure, and it is the sibling this command is closest to. Cost: one optional argument on `set_typed`, whose body already has the parsed `meta`/`body` in hand at exactly the right line |
| D3 | The line is `- <date> set: severity S1 → S2 — <why>`, and `- <date> set: severity S2 → S3` without one | the card's literal `severity S1 → S2: <--why>`; the groom's `- <date> groom: severity → S2 (operator)`; reopen's timestamp | the clause is the card's, unchanged in words and arrow; three things are added and each is the record's existing rule. **The date**, because every History line in the record carries one and the groom's digest reads them by date (P12). **`set:`**, because the groom's line says `groom:` and a reader has to be able to tell which writer wrote which — D2 makes them two different writers with two different gates. **The em dash instead of the card's colon**, because `- … set: severity S1 → S2: why` puts two colons in one line and the tree's own reasoned-correction line is already `reason — old → new` (P10). No `(operator)` suffix: the groom needs one because its answers come from four attributions (`asf/groom/groom.py:146-163`), and `asf set` has exactly one — the person at the console, named by the commit |
| D4 | `--why` is required only to **leave S1**; every other change writes its line without one | require it for any downgrade; require it always; require it never | the card says "requiring `--why` for a downgrade from S1", and the reason it gives is structural rather than stylistic: S1 is the only severity that holds the whole tier-2 queue, so leaving it is the only severity move that spends something belonging to other work (P15, P16). `S2 → S3` costs the lane nothing anyone else is waiting on. Making it always required would make the remedy in P16 a two-part ceremony for a field the groom can set from a one-word answer, and the first thing anyone would do is type `--why x` |
| D5 | A severity assignment equal to the current value appends **no** History line and requires no `--why` | refuse it; write the line anyway | `asf set B-1382 severity=S1` when it is already S1 is not a downgrade and did not happen — a History line saying `severity S1 → S1` is a record of nothing, and the `--why` gate firing on it would refuse a command that changes nothing on the grounds that it is dangerous. Refusing outright would break the idempotence every other scalar field has, which is what lets a remedy line be pasted twice |
| D6 | `--why` with no severity assignment is **refused**, exit 2, card untouched | ignore it; record it somewhere else | the flag's whole content is a sentence a person typed to justify something. Accepting it and dropping it on the floor is the one outcome that is worse than refusing: the operator believes the reason is in the record. Refusing costs them one re-run and says which field the flag belongs to |
| D7 | The value is matched case-insensitively and the **canonical uppercase** form is written | exact match only, `s2` refused with the three words | the inbox already reads a severity case-insensitively and uppercases it (`asf/groom/inbox.py:201`, `:278`), so `s2` filing a Bug and `s2` downgrading one would otherwise disagree about the same word. The fold is scoped to `severity` alone, by name: `lane` and `size` keep exact matching (P4), because `DIRECT` is not a route anyone has ever typed and widening them is not this card's business |
| D8 | The S1 gate's remedy prints a **placeholder** — `--why "<why this is not S1>"` | interpolate the gate's own `reason` as the `--why`, shell-quoted | the gate's reason is `adjudicated after 4 sessions` — a description of the queue, not of the bug. Pasting it in would satisfy the gate with a sentence the machine wrote about itself, which is precisely the defence D4 exists to collect. A placeholder makes the line a template a person finishes, which is what a `NEEDS OPERATOR` line is |
| D9 | A card with no `## History` section has its severity change **refused**, card untouched | write the field and let the line vanish (P11's documented behaviour); create the section | `append_history_lines` returns the body unchanged when there is no such heading (P11), so on such a card the field lands and the reason evaporates silently — D6's failure again, by a different road. Every Bug the inbox mints has the section (`asf/record/ids.py:93`), so the refusal is unreachable in practice and cheap to state; creating a section would have this command inventing structure in a card `asf check` never asked it to |

## The design

### `asf/record/new.py` — the two table rows

```python
SETTABLE = {t: set(_COMMON_SET) for t in TYPES}
SETTABLE['rule'] |= {'scope', 'enforced', 'reason', 'check'}
SETTABLE['decision'] |= {'decided_by', 'date'}
#: A Bug's severity is settable (F-0163): it is the field the fix lane is ordered by
#: (:func:`asf.feeder.rows.bug_rows`), so a downgrade releases the S1 lane's hold on everything
#: behind it — and before this it was the one required field of a Bug no command could write, which
#: made every correction a hand edit of the typed block. ``asf set`` gates the S1 case behind
#: ``--why`` and records the move in ``## History``; see :func:`asf.record.setfield.cmd_set`.
SETTABLE['bug'] |= {'severity'}
SETTABLE['feature'] |= {'lane', 'size', 'ab_pair'}
#: The values a word-valued settable field takes; any other is refused before the card is touched.
FIELD_WORDS = {'lane': ('direct', 'full'), 'size': ('s', 'm', 'l'), 'severity': SEVERITIES}
#: The word fields whose value is case-folded to the canonical form before the check and on the way
#: in — the inbox reads a severity case-insensitively (:mod:`asf.groom.inbox`), so the console must
#: too (D7). ``lane`` and ``size`` are deliberately not in here.
FIELD_UPPER = frozenset({'severity'})
```

and the three lines of `_parse_sets` that read them:

```python
        value = frontmatter._parse_value(raw)
        if top in FIELD_UPPER and isinstance(value, str):
            value = value.upper()
        words = FIELD_WORDS.get(top)
        if words and value not in (None, '') and str(value) not in words:
            raise ValueError(f"{key}={raw!r} — one of {', '.join(words)}")
```

`asf set B-1382 severity=s4` is now refused with `error: severity='s4' — one of S1, S2, S3`, before
anything is rendered. `asf new decision --set severity=S1` is refused exactly as it is today (P6),
because `severity` is on no type's list but `bug`'s.

### `asf/record/setfield.py` — the gate and the line

The module docstring gains the paragraph that states the rule:

```python
A Bug's ``severity`` is settable here (F-0163), and it is the one field this command reasons about
rather than merely writing: it appends ``- <date> set: severity S1 → S2 — <why>`` to ``## History``
in the same guarded write as the field, and refuses a move **off** ``S1`` without ``--why``. S1 is
the severity that holds the whole tier-2 queue (:func:`asf.feeder.rows.bug_rows`), so leaving it
spends something that belongs to other work; the sentence that justifies it is worth more later
than the field.
```

Two module constants and one helper, beside `LIST_FIELDS`:

```python
#: The History line a severity change files on the Bug — the card's own words, dated like every
#: other line in the record and named for its writer (D3).
SEVERITY_HISTORY = '- {date} set: severity {old} → {new}'
#: …with the reason a move off S1 must carry.
SEVERITY_WHY = ' — {why}'


def severity_change(rec, updates, why):
    """``(history_line, None)`` for a severity assignment in ``updates``, ``(None, None)`` when
    there is none or the value is the one already on the card (D5), or ``(None, reason)`` when the
    change is refused.

    Refused when the card leaves ``S1`` without a ``--why`` (D4), when ``--why`` is given and no
    severity moves (D6), or when the card carries no ``## History`` section to write the line into
    (D9)."""
```

`cmd_set`, after the assignment loop and before `set_typed`:

```python
    history, err = severity_change(rec, updates, getattr(args, 'why', None))
    if err:
        print(f"error: {err}", file=sys.stderr)
        return 2

    err = set_typed(rec, updates, history=[history] if history else ())
```

and the `set` line it prints already names the field; the History line is echoed under it when one
was written, so the operator sees what went into the record:

```
B-1382: set severity
B-1382: history: severity S1 → S2 — main green without it, prod deployed; releases the S1 lane's hold on 8 Ready rows
```

`set_typed` gains the argument and four lines. The round-trip check is untouched — `history` lives
in the body, and `meta`/`body` are already parsed at exactly the point they are needed:

```python
def set_typed(rec, updates, writer='set', history=()):
    """Write ``updates`` (typed fields) onto the card ``rec`` … Returns None on success, else the
    reason the card is unchanged.

    ``history``: lines appended to ``## History`` in the **same** staged write as the fields
    (F-0163) — never a second write afterwards, so the guard that can refuse the change sees the
    whole change, and a card never holds a field whose reason failed to land."""
        ...
        for key, value in updates.items():
            if meta.get(key) != value:
                return (f"{key}={value!r} does not round-trip through the parser "
                        f"(it reads back as {meta.get(key)!r}); {rec['relpath']} is unchanged")
        if history:
            from asf.record.ingest import append_history_lines
            new_text = frontmatter.render(meta, append_history_lines(_body, list(history)))
    finally:
        os.unlink(scratch)
```

Every existing caller — `cmd_set`'s other fields, `widen` (`writer='widen'`) — passes no `history`
and is byte-identical in behaviour.

### `asf/cli.py` — one flag

### `asf/feeder/tiers.py` — the remedy that runs

Both `severity=S2` strings gain the flag the gate now requires, with the placeholder a person
finishes (D8):

```python
#: The remedy for an S1 nothing is working: the downgrade, with the reason `asf set` requires for a
#: move off S1 (F-0163) left as a placeholder — the gate's own `reason` describes the queue, not the
#: Bug, and a machine-written defence is not one (D8).
DOWNGRADE = 'asf set {item_id} severity=S2 --why "<why this is not S1>" --product {name}'
```

so the gate's line reads

```

lane holds 0 of 94 tier-2 rows behind it — asf set B-0057 severity=S2 --why "<why this is not S1>"
--product asf
```

and `tests/test_s1_gate.py:70-73`'s equality assertion follows it.

## Records

- **The Bug's card, one commit.** `severity:` in the typed block and one line in `## History`,
  written together and committed by `_published` as `record: set B-nnnn` (P19). Nothing else in the
  card moves — `updated:` and the machine block are ingest's, and `asf set` has never touched them.
- **The History line**, exactly: `- 2026-09-26 set: severity S1 → S2 — main green without it, prod
  deployed; releases the S1 lane's hold on 8 Ready rows` — dated, named for its writer, and
  distinguishable at a glance from the groom's `- <date> groom: severity → S2 (operator)` (D3, P14).
  A change that needs no reason writes the same line without its tail.
- **Nothing is written when anything is refused.** A bad word (D1), a missing `--why` (D4), a
  stray `--why` (D6), a card with no `## History` (D9), a stage invariant: exit 2, a message on
  stderr naming the field, and the card byte-identical — the existing contract of this command,
  extended to the new gates.
- **Two console lines**, the field and the line it filed, so the operator reads back what the record
  now says without opening the card.
- **The feeder's rows change on the next tick, from the card.** An S1 → S2 Bug moves from tier 0 to
  tier 1 and the S1 gate stops counting it; an S1 → S3 Bug leaves the fix lane entirely
  (`severity not in ('S1', 'S2')`, P15). No index, cache or state file records the downgrade — the
  card is the input, and there is nothing to invalidate.
- **The `NEEDS OPERATOR` line grows one flag.** The gate's remedy becomes a template with a
  placeholder rather than a command that fails; the line's shape, its arithmetic and the conditions
  that raise it are unchanged.
- **No event, no card, no round, no approval class.** A severity change spends nothing against the
  item and raises nothing for the groom.

## Stories

- S: `severity` is a settable field of a Bug and of nothing else, gated to `S1|S2|S3` before the card is touched — the refusal that sent a session to a hand edit becomes a written field, and the `SEVERITIES` constant that has been dead since it was written is what validates it — acceptance: `python3 -m unittest -v tests.test_backlog.SetSeverityFieldTests tests.test_backlog.NewSetFieldsTests`
