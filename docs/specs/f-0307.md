# F-0307 — while the product is on fire, the factory fixes it

The feeder has an S1 lane, and it is a *seating* rule, not a policy. `asf/feeder/tiers.py:63`
holds the tier-2 rows only while `s1_rows > free` — an S1 row that needs a session cannot get a
seat. The moment the S1 **has** a seat, every Feature card behind it launches beside it. That is
deliberate: the 2026-09-26 note at `asf/feeder/tiers.py:10-11` narrowed the lane from the whole
floor to the first seat, because two product waves launched 1 row with 7 seats free.

So today a product with an open S1 Bug and eight free seats puts one session on the Bug and seven
on new Features. Measured, not inferred (P8): a live session on the S1 and eight seats free, and
both Feature cards still read `would launch`.

This card is the other half of that correction. The lane answers *who gets the next seat*; it has
no answer for *what the factory should be spending its sessions on at all* while the product is
broken. Stability first is that answer, and it is a policy on which rows exist as launchable —
the same shape the product already uses for `feeder.max_features_in_build` ("no new Feature
starts", `asf/feeder/rows.py:2861`) and `feeder.max_specs_in_flight` ("finish before you start").
While an S1 Bug is open and work can go to it, no **new** Feature work starts: a Feature already
in build finishes, every Bug row runs, and the Features the product declared stability work run
in rank order. Everything else waits and says which Bug it is waiting for.

One thing the card does not get to assume. The record already holds a ruling that an S1 which
**nothing can work** must hold nothing: F-0113, `tests/test_s1_gate.py`, five cases and an
incident behind them. A blocked, parked, undecided or adjudicated S1 freezing every Feature does
not buy stability — it idles the product behind a Bug no session is allowed to touch. The freeze
therefore triggers on an S1 that is being worked or could be worked now, and F-0113's invariant
stands untouched (D3).

### In

* **The gate.** `asf/feeder/rows.py` — `stability_first(rows, items, inflight, held, occupancy,
  landed_shas)`, a sibling of `build_cap`, called from `plan_rows` **before** it, with four
  helpers: `open_s1_bugs(items)`, `freezing_s1s(items, rows, busy, held)`,
  `is_stability(items, item)` and `starts_a_feature(items, row, building)`.
* **One definition of "new Feature work".** `starts_a_feature` is lifted out of `build_cap`'s
  condition unchanged, and `build_cap` then calls it. The cap and the gate ask one question in
  one place.
* **The declaration.** `stability: true` on a Feature card, or on the Epic above it, is the
  product's statement that this Feature is stability work. `asf/record/new.py`: `SETTABLE`
  for `feature` and `epic`, and `BOOL_FIELDS` — which buys the `true`/`false` refusal and
  `asf check`'s type validation for free (P17).
* **The report.** `Row.s1` — the holders, carried on the row. `asf/feeder/tiers.py`: `gate()`
  counts the frozen rows off the demand pass and reads their holders off `Row.s1`, so the
  `S1 gate: B-0001 holds 3 rows (CARD → SPEC 3)` line F-0113 specified keeps telling the truth
  (P11 is why it cannot be a diff). `WORKED` becomes `rows.WORKED_WAITS`, one owner (P16).
* **The tests.** A new `tests/test_s1_feature_gate.py` (25 cases, run green), and the 13 cases
  of P21 rewritten to the new ruling.

### Out

* **The seating rule is not touched.** `s1_waiting` (P1) stays exactly as it is. It answers a
  different question — who takes the next seat under pressure — and the 2026-09-26 ruling (P2)
  that narrowed it is not reopened. The two compose: the gate decides which rows are launchable,
  `select` seats what is left.
* **No config key, no `conventions` flag.** The card says the gate is policy, in code. The two
  release valves are the ones the product already has and already prints: downgrade the Bug
  (`asf set <id> severity=S2 --why "…"`, which `tiers.DOWNGRADE` already hands the operator) or
  declare the Feature stability work. A key that can switch stability-first off is a key that
  will be off.
* **No migration, no backfill.** `stability` is absent from every card today, and absent reads
  as not-stability. A product that wants a stable-core Epic marks it once, after this lands.
* **Wiring `gate_line` into a view.** It has no caller (P10) and this card does not give it one:
  that is a separate card about where the line belongs (`asf next`'s footer, the wave's log, or
  both). What this change owes is that the function stays truthful when the gate it describes
  changes — not a new surface.
* **The S2 case.** The card says S1. An open S2 freezes nothing here.
* **`capacity.reserve_for_s1` and `worker_pool.reserve_for_s1`.** Seat reservation for the fix
  is a different mechanism and is untouched.
* **Holding a Feature whose Tasks have started.** Out by construction (D2): stranding a
  half-built Feature's branches to rot and conflict is itself a stability cost.

```python
def open_s1_bugs(items):
    """The product's open S1 Bugs, oldest card first — the trigger of :func:`stability_first`.
    A Bug flagged as another product's work (``belongs_to:``, F-0120) is not one: its row
    launches nothing here and already holds no tier-2 row (:func:`foreign_row`). Severity alone
    and ``state`` alone: an S1 the groom has not decided yet is still a product on fire."""
    return [b['id'] for b in sorted(ix.of_type(items, 'bug'), key=lambda v: (_age_key(v), v['id']))
            if b.get('severity') == 'S1' and is_open(b) and not b.get('belongs_to')]


def freezing_s1s(items, rows, busy=(), held=()):
    """The open S1 Bugs that freeze new Feature work (:func:`stability_first`): the ones a
    session is on or whose work waits to land (``busy``), whose branch, landing or merge is the
    work, and the ones a row would launch a fix or an adjudication for now.

    An open S1 that nothing is working and no row launches — blocked, parked by an approval,
    undecided, past the attempt limit, or flagged as another product's work — freezes nothing.
    Holding every Feature behind such a Bug buys no stability and idles the product: that is
    F-0113's invariant and the incident behind it. It already has the louder remedy — its own
    ``NEEDS OPERATOR`` line and the downgrade that answers it
    (:func:`asf.feeder.tiers.needs_operator`)."""
    busy, held = set(busy or ()), set(held or ())
    by_item = {}
    for r in rows:
        by_item.setdefault(r.item_id, []).append(r)
    out = []
    for b in open_s1_bugs(items):
        if b in busy:
            out.append(b)
            continue
        if b in held:   # parked for a person: F-0113's `held` case freezes nothing
            continue
        if any(r.launches or r.waits_on in WORKED_WAITS for r in by_item.get(b, ())):
            out.append(b)
    return out
```

The exemption (D5), one card field read through one function:

```python
def is_stability(items, item):
    """True for a Feature the product declared stability work: ``stability: true`` on the card,
    or on the Epic above it — a whole stable-core Epic is marked once, the way a product already
    puts a whole Epic first by ranking the Epic (:func:`feature_order`). These are the Features
    that run *during* an S1 freeze (F-0307)."""
    if not item:
        return False
    if item.get('stability') is True:
        return True
    epic = item if item.get('type') == 'epic' else epic_of(items, item)
    return bool(epic) and epic.get('stability') is True
```

and the gate itself, shaped like `build_cap` and `finish_first`:

```python
def stability_first(rows, items, inflight, held=(), occupancy=None, landed_shas=None):
    """F-0307 — stability first: while any S1 Bug is open and work can go to it
    (:func:`freezing_s1s`), no *new* Feature work starts. Each launching row that would start a
    Feature (:func:`starts_a_feature`), and the ``EPIC → FEATURES`` session that drafts new
    Feature cards, becomes ``WAITS ON S1 <id>: …`` — it launches nothing, costs no slot
    (:mod:`asf.feeder.tiers`), and every view prints it with the Bug that holds it.

    Never held: every Bug row (the fix is the work this gate exists to let run), every row that
    finishes a Feature already in build, a correction the lane asked for, a parked item's row,
    and a Feature the product declared stability work (:func:`is_stability`) — "Bug fixes and
    ranked stability Features run first", in that rank order, which is already the tier-2 order
    (:func:`feature_order`).

    No freezing S1: the rows are returned untouched."""
    held = set(held or ())
    busy = inflight_ids(inflight) | occupied(occupancy)
    s1 = freezing_s1s(items, rows, busy, held)
    if not s1:
        return rows
    building = set(features_in_build(items, busy, landed_ids(items, landed_shas)))
    named = ', '.join(s1[:3]) + (f' +{len(s1) - 3}' if len(s1) > 3 else '')
    verb = 'is' if len(s1) == 1 else 'are'
    reason = f"{named} {verb} open: Bug fixes and ranked stability Features run first"
    out = []
    for r in rows:
        f = items.get(r.feature_id) or items.get(r.item_id) or {}
        if (r.launches and not r.correction and r.item_id not in held
                and not is_stability(items, f)
                and (r.kind == EPIC_FEATURES or starts_a_feature(items, r, building))):
            r = dataclasses.replace(r, waits_on='S1', s1=tuple(s1),
                                    action=f'{WAITS_S1} {named}: no new Feature work while an '
                                           f'S1 Bug is open',
                                    reason=f'stability first — {reason}')
        out.append(r)
    return out
```

## Records

The change writes no new row, no new event and no new ledger. It adds one optional card field and
changes what the feeder's own output says:

* **`stability: true`, on a Feature or an Epic card's typed block.** Optional, absent everywhere
  today, absent reads as not-stability (D5). Written by `asf set <id> stability=true` and
  `asf new --set stability=true`, refused as anything but `true`/`false`, and type-checked on
  every card by `asf check` (P17). It is the only thing a person must write for this card, and
  only when they want a Feature to run during a freeze.
* **A held row's `action`, `waits_on` and `reason`.** `WAITS ON S1 <ids>: no new Feature work
  while an S1 Bug is open`, `waits_on='S1'`, and `reason` naming the Bugs and the rule. Every
  view that prints rows prints these: `asf next`'s table (`render.action_cell`), `asf next
  --json`, `asf status`, and `asf.feeder.idle`'s `waiting` bucket — whose `other` bucket exists
  so that "a gate added later is visible the tick it starts hiding cards", and which needs no
  change because a `WAITS ON …` action is already what it buckets on.
* **`Row.s1`.** A new tuple field on the feeder's row, so `asf next --json` gains an `s1` key
  (empty on every row the freeze did not hold). This is what `test_json` pins and why it is in
  the amended 13.
* **`tiers.gate_line`'s one line.** `S1 gate: <ids> hold <n> rows (<kind> <n>, …)` — the same
  sentence, now counting the rows the freeze held rather than a diff that could not see them
  (P11). It still has no caller in `asf/` (P10); keeping it truthful is in scope, giving it a
  view is not.
* **The product's recorded demand.** `demand.json`'s `wanted` for a frozen product falls to its
  Bug rows, its in-build Features and its stability Features (D7), so the factory's capacity
  goes to a product that can use it instead of being reserved for sessions that cannot start.

No `docs/` page, no scorecard metric and no CHANGELOG entry follows from this beyond the release

`asf/feeder/rows.py:stability_first`'s docstring and `asf/feeder/tiers.py`'s module docstring,
