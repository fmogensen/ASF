## Installing ASF

What a new user still meets on a clean machine, with what to do about it. Each one was found by
the clean-install jobs (`install-clean-linux`, `install-clean-macos` in
`.github/workflows/install-clean.yml`, running `tools/install-clean.sh`); anything those jobs hit
is either fixed or listed here.

| what you see | why | what to do |
| --- | --- | --- |
| `install: NEEDS OPERATOR: step 1 installs the package and needs a terminal` when a Claude Code session runs the installer | by design (F-0109): the session's runtime refuses a network package install, and the session cannot grant itself the rule | the operator runs the printed `--package-only` line in a terminal once; the session finishes with `--no-package` |
| `step 7: the hooks: WITHHELD …` | the product repo versions its hooks directory or `.claude/settings.json`, and the approval matrix has `touch_security` above `auto` | answer the question on a terminal, or `asf hooks install --product <p> --approve` |
| doctor rows `cli:gh`, `worker env`, `worker push auth`, `console permissions` read `skip — not configured: …` | no `gh auth login`, no worker token, no console allow list yet — each a login or a choice only you can make | run the command each row names; the row turns `ok` |
| `gh run list failed: To get started with GitHub CLI …` printed above the doctor table before `gh auth login` | a metrics read calls `gh` and prints its error to stderr | harmless; it stops after `gh auth login` |
| `install: no scheduler — no clock will tick <p> …` on Linux | no systemd user manager answers (`systemctl --user` fails): a container, a CI runner, or a server with no login session | on a server, `loginctl enable-linger $USER`, then rerun with `--scheduler systemd`; in a container, tick by hand (`asf tick --product <p>`) |
| launchd clocks fail to load over SSH on macOS | `launchctl bootstrap gui/<uid>` needs a logged-in GUI session | run the installer from a terminal in the logged-in desktop session |
| pipx warns that `~/.local/bin` is not on `PATH` | a fresh pipx | `pipx ensurepath`, then open a new shell |
| `install: in the Claude Code session for this product, add the plugin once: …` | the runtime CLI on this machine offers no non-interactive plugin install | run the two `/plugin` lines in that product's Claude Code session |
| the record clock's first tick: `tick: state committed, push refused` (`asf doctor`'s SCHEDULER row then reads it RED) | `backlog_dir` is a plain local checkout, not a bare repo: a push needs `receive.denyCurrentBranch=updateInstead` on it, and `asf init`'s adopt lands uncommitted (the docs above: commit it yourself) — skip either and the tick's own commit collides with adopt's untracked files | `git -C <backlog_dir> config receive.denyCurrentBranch updateInstead`, then commit the freshly adopted layout, before any clock ticks |
