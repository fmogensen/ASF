### C2 — `asf/record/idcheck.py:109-137`: a bullet with no `- [ ]` lines mints a Story card `asf check` refuses

`_bullet_stories` returns a bullet whose `acceptance` list is empty, and `plan_tasks._mint` writes
that card anyway (`asf/record/plan_tasks.py:210-215`, `acceptance=d['acceptance'] or ()`). The card
comes out with a bare `- [ ]`, which the record's own shape check refuses:
`asf/record/check.py:388-392` → `story without an acceptance list (a Story is one PR with one
acceptance list)`. Run directly against this checkout, with a spec whose `## Stories` section is the
shape the `STORIES_FIRST` brief tells a session to leave behind (`asf/briefs/build.py:719`, "so
each line carries its minted id"):

```

      - S-29501: the reader reads — proven by tests/test_reader.py
      - S-29502: the writer writes

made: ['S-29501', 'S-29502', 'T-0001', 'T-0002']
record findings:
    ('stories/S-29501.md', 2, 'S-29501: story without an acceptance list (a Story is one PR with one acceptance list)')
    ('stories/S-29502.md', 2, 'S-29502: story without an acceptance list (a Story is one PR with one acceptance list)')
```

The stage guard does not hold them back — both cards are written and both ids come back in `made`,
so the mint itself turns the record red, and `file_bugs` then files a `Record error` Bug for the
class (`asf/tick/file_bugs.py:296-316`). It also defeats the gate it is meant to open:
`asf/feeder/rows.py:421-424` promises "a Story child is a Story with checkbox acceptance lines", and
`has_stories` now returns true for a card that has none.

This is not hypothetical on this tree. Over `docs/specs` and `docs/plans` at this head, the widening
adds **370** declarations the heading form did not see, **160** of them with no card in the record
and **150** of those with no acceptance line at all. Three of their Features are eligible to mint
right now (no Task child, not done/retired), and every new declaration on all three is
acceptance-less:

```
F-0071 state=Active  new=S-5750..S-5755    no-acceptance=all 6
F-0087 state=Closed  new=S-7600..S-7610    no-acceptance=all 11
F-0254 state=Active  new=S-71504..S-71507  no-acceptance=all 4
```

F-0254 is one of the seven Features the card's own Description names as stalled.

**The fix:** in `_bullet_stories`, keep only a bullet that carries at least one indented checkbox
line — which is what the docstring at `asf/record/idcheck.py:110-111` and the new docstring at
`:141-144` already say the bullet form is ("its acceptance the `- [ ]` lines indented beneath it").
Concretely, build each entry into a local dict and, at the end, `return {sid: d for sid, d in
out.items() if d['acceptance']}`. A bare `- S-…: <title>` line then stays what it was before this
commit: a citation, not a declaration. Add the case to `tests/test_plan_tasks.py` beside
`test_declared_stories_reads_bullets_and_stops_at_a_sibling`: a `## Stories` section of two bare
bullets declares nothing, and `mint` writes no `stories/S-*.md`.

### C3 — `asf/record/check.py:427-430` and `tests/test_t10_gate.py:188-190`: the demoted finding is now observed by nothing, and the comment that says otherwise is wrong

The test comment reads "The uncovered Story is a warning since F-0318 (groom reports it), so no Bug
is filed for it". Groom does not report it. `record_findings` returns `(findings, warnings,
index_wrong)`, and every caller of the warnings half either prints it or throws it away:

- `asf/record/check.py:194-195` — `asf check` prints it to stdout.
- `asf/record/check.py:589-592` — `asf check --staged` prints it, for staged paths only.
- `asf/tick/file_bugs.py:296` — `findings, _warnings, _index_wrong = record_findings(...)`: discarded.

`grep -rln 'warning:' asf/` returns exactly `asf/record/check.py` and `asf/record/setfield.py`.
There is no groom step, no feeder row and no Bug behind this condition any more, so an uncovered
Story under a building Feature is now tolerated for ever and nothing in the factory acts on it —
the test change from `3 filed` to `2 filed` is that loss, measured.

**The fix:** make the demotion conditional instead of total, at `asf/record/check.py:427-430` —
`warn` only while the Feature has no Task card at all (the state the commit message is about: "a
Story for a building Feature must exist before a Task's `stories:` can name it"), and keep `add`
once the Feature has at least one Task, because from then on a Task *can* list the Story and one
that does not is the real defect the finding was for:

```python
has_task = any(canonical[c]['meta'].get('type') == 'task'
               and not canonical[c]['meta'].get('removed')
               for c in derived[iid]['children'])
(add if has_task else warn)(rec, find_line(rec, 'id'),
                            f"story {cid} has no Task listing it in stories:")
```

Then correct the comment at `tests/test_t10_gate.py:188-190` to say what actually happens, and keep
a case for each side: a Feature with no Task warns, a Feature with a Task and an uncovered Story
still fails `asf check` and still files its Bug.

### C4 — `asf/feeder/rows.py:421-431`, `asf/record/plan_tasks.py:132-148`: the deadlock the card names is still there for a Feature that is not `building`

Nothing in this diff changes either half of the loop. `has_stories` still counts Story **cards**
(`asf/feeder/rows.py:421-424`), and the only code that mints a declared Story is still
`plan_tasks._mint`, which reaches a Feature only through `plan_ref(fev)` — a **landed plan**
(`asf/record/plan_tasks.py:132-134`, `continue` when there is none). The spec is read only as a
second source once that plan is a candidate (`:144-147`, gated on `fev.get('spec_on_main')`). So a
cloud session's declarations, heading-form or the new bullet-form, still mint only when a plan
lands, and the plan still never starts because the gate holds. The `STORIES_FIRST` brief still tells
the session exactly that: `asf/briefs/build.py:710` — "The record mints those cards from the claimed
block when the plan lands."

The demoted check at `asf/record/check.py:415-430` only ever fired for a Feature whose stage starts
with `building` (`:420-421`, `if not stage.startswith('building'): continue`). Of the seven Features the
card's Description names, three are there and are unblocked by this commit; four are not, and for
them nothing changed:

```
F-0280  stage: building 0/3     unblocked by this commit
F-0295  stage: building 1/4     unblocked by this commit
F-0306  stage: building 1/6     unblocked by this commit
F-0254  stage: spec-approved    still deadlocked
F-0290  stage: spec-approved    still deadlocked
F-0293  stage: landed           still deadlocked
F-0303  stage: landed           still deadlocked
```

**The fix:** break one side of the loop for a Feature with no landed plan. The smallest change that
does it is to mint from a **landed spec** as well as a landed plan — in `plan_tasks._mint`, add a
second pass over Features with `fev.get('spec_on_main')` and no plan, minting the spec's
`declared_stories` (claim-checked, exactly as `:202-215` already does) and no Tasks. Then
`asf/briefs/build.py:708-711` stops being a lie and reads "the record mints those cards from the
claimed block when the spec lands". If the operator would rather scope F-0318 to the two changes
this commit makes, that is their call — then this needs its own card before F-0254, F-0290, F-0293
and F-0303 move, and the card's Description should be narrowed to say so, because as written the
item is not delivered.

## I — would change, will not block

- **I1 — `asf/record/idcheck.py:123-124`:** `if m and not CHECKBOX.match(line)` — the second half is
  dead. `STORY_BULLET` requires `[-*][ \t]+` then optional `*`s then `S-\d{4,}`, and a checkbox line
  has `[` at that position, so no line can match both. Drop it, or keep it and say in a word why.
- **I2 — `asf/record/idcheck.py:113-120`:** the `## Stories` section ends only at the next `## `
  heading. `line.startswith('## ')` is false for `# `, `#### ` and the rest, so an H1 after the
  Stories section leaves `inside` true and later bullets keep being read as declarations. Measured
  over every file in `docs/specs` and `docs/plans` at this head, no document actually leaks, so this
  is latent, not live. Resetting on any heading of level ≤ 2 (`len(line) - len(line.lstrip('#'))`)
  closes it.
- **I3 — `asf/record/idcheck.py:101-102`:** the separator class is `[:.—-]`, without `\s`, while
  `STORY_DECL:88-89` accepts `[:.\s—-]*`. So `### S-29501 the reader reads` declares and
  `- S-29501 the reader reads` does not — which is what keeps
  `tests/test_plan_tasks.py:141-145` passing, so the divergence is load-bearing. It deserves the
  one sentence that says so, next to the regex, or the next reader will "fix" it and break that
  test.
- **I4 — `asf/record/idcheck.py:101`:** `S-\d{4,}` is written out where the module has
  `core.ID_DIGITS` for exactly this (`asf/record/core.py:45`). `ID_TOKEN:20`, `DECL:21`,
  `STORY_DECL:88` and `STORY_TOKEN:90` all hardcode it too, so the new line is consistent with the
  file and not worse — but F-0293 is open against this very duplication, and this is one more site
  for it to fix.
- **I5 — `asf/record/plan_tasks.py:210-215`:** the minted card's `title` is whatever follows the
  separator, so a bullet amended the way the brief asks — `- S-29501: the reader reads — proven by
  tests/test_reader.py` — mints a Story titled `the reader reads — proven by tests/test_reader.py`.
  The proof citation belongs on the acceptance line, not in the title. Splitting the title at
  ` — proven by ` would do it.
