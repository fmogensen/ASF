## C list

- **C1** `asf/prepush.py:118-124` (`refusal`) + `asf/cli.py:243-246` (`cmd_pre_push`'s red-rule
  branch) — a rule with an empty or unset `why` (schema-valid: `validate_mapping` only checks
  `why` is a string when present, `asf/conventions.py:680-682`, and `pre_push_checks()` defaults
  it to `''`, `:1349-1352`) loses its "`<cmd>` exited 1" line from the refusal's body. `refusal()`
  builds `lines = [rule.get('why') or '', f"\`{run}\` exited 1"]` then
  `'\n'.join(l for l in lines if l)`, which drops the first (empty) element; `cmd_pre_push` then
  takes `why_line, rest_lines = lines[0], lines[1:]` off that already-filtered text, so the
  "exited 1" line becomes the *header* instead of a body line. Reproduced directly in this
  session:
  ```
  >>> prepush.refusal({'run': 'echo boom && exit 1', 'why': ''}, 'boom')
  '`echo boom && exit 1` exited 1\nboom'
  ```
  which prints as `asf: push refused — \`echo boom && exit 1\` exited 1` — the spec's own
  illustration (`docs/specs/f-0301.md:253-255`) always shows the header as the rule's prose `why`
  and "exited 1" as a separate body line; with `why` empty the header instead becomes the command
  echoed back, conflating two things the acceptance bullet ("the refusal carries the rule's
  `why`, the command, ... and tail", `docs/specs/f-0301.md:387-388`) keeps distinct. No test in
  `tests/test_prepush.py` exercises an empty/unset `why` on a red rule (every case in `RedRule`
  and `RefusalTests` supplies one) — the gap matches the bug exactly.
  Fix: in `refusal()`, only `tail` is optional — e.g.
  `lines = [rule.get('why') or '', f"\`{rule.get('run')}\` exited 1"]`, append `tail` only
  `if tail`, then `return '\n'.join(lines)` **unfiltered** (never drop the first two). An empty
  `why` then reads as a blank header remainder and `cmd_pre_push`'s `lines[0]`/`lines[1:]` split
  keeps working unchanged.
