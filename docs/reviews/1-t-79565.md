- `asf/workers/githooks.py:181-208` — the new door call is guarded with `[ -x "$cli" ]`
  (line 203), not the plan's literal `-n "$cli"` (`docs/plans/f-0301.md:260`, copied from the
  spec's §4 fence, `docs/specs/f-0301.md:276`). The deviation is correct and necessary, not a
  defect: `cli` is now a hoisted *literal path string*, always non-empty whether or not a
  dispatcher exists there, so `-n "$cli"` would be true unconditionally and the new block would
  try to exec a missing `$cli` on any worker with no `asf` installed yet — refusing every push.
  Verified: with the literal `-n` guard, `tests/test_session_push_guard.py`'s pre-existing
  `TrunkCheckRunsThePinOrRefuses.test_no_file_at_the_path_skips_the_trunk_check_as_today`
  (no dispatcher installed, line 301) goes red, since the new block would run right after
  trunk-check's own graceful skip. `-x "$cli"` restores that skip for the door call too, while a
  stale/non-dispatcher `$cli` is still caught by the existing trunk-check block first (`rc` stays
  nonzero, the door is never reached). The coder recorded this as an Assumption in the report;
  record it here too since it is the one place the Step was not implemented byte-for-byte.
