## C list

**C1 — `tests/test_ci_pool.py:11`: the new test's `import yaml` is a third-party dependency this
product declares it does not take, and nothing installs it in CI — the module will fail to
import on a clean matrix leg.**

`pyproject.toml:1-2` states the project's own constraint in its first line: "Python 3 stdlib
only — no dependencies" (`dependencies = []`, `pyproject.toml:15`). `asf/ci_pool.py` already
parses this exact file — workflow YAML — without a YAML library: `parse_job_names`
(`asf/ci_pool.py:732`) and `parse_runs_on` (`:766`) are both documented "A line reader, not a
YAML parser (this package takes no dependency)" / "this package takes no dependency" verbatim.
The new test instead does `import yaml` (`tests/test_ci_pool.py:11`) and
`yaml.safe_load(f)` (`:346`) to read the same `.github/workflows/tests.yml`. `grep -rln "import
yaml" --include="*.py" .` finds exactly one file in the whole tree — this one; PyYAML is not
listed anywhere (`grep -i yaml pyproject.toml` → empty) and nothing in
`.github/workflows/tests.yml` installs it — the only install step is `python -m pipx install
--python "$(which python)" .` against `dependencies = []` (`:31-33`). `actions/setup-python`
provisions a fresh, minimal 3.12/3.13 build for the matrix leg with no third-party packages
preinstalled; the test passed in this review only because this host's ambient `python3` happens
to already have PyYAML (`python3 -c "import yaml; print(yaml.__version__)"` → `6.0.3`, installed
for unrelated reasons, not by this repo). On an actual CI runner, `import yaml` at module scope
raises `ModuleNotFoundError` at collection time, taking down all 69 tests in
`tests/test_ci_pool.py` — not just the new one — which is the same "a healthy job reads red"
failure mode this very card exists to stop the watchdog from mishandling. Fix: read
`strategy.fail-fast` the same way the file's two existing functions read this file — a plain-text
line scan for `fail-fast:` under `jobs.tests.strategy` (or extend `parse_job_names`/add a sibling
helper in `asf/ci_pool.py`) — and drop the `import yaml` line.
