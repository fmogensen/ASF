## C — must change

1. **`asf/ci_queue.py:902` — `live_runs` lists two statuses, not the module's own four.**
   Plan Step 4: *"the product's own repo, both statuses (`QUEUED_STATUSES | {'in_progress'}` —
   spelled from the module's own constant, `:1907`), from the memo."* The landed code is
   `for status in ('queued', 'in_progress')`, which is `QUEUED_STATUSES`'s `'queued'` alone, not
   the full `frozenset({'queued', 'waiting', 'pending', 'requested'})` the module itself uses at
   `:2575`, `:2748` and elsewhere for "not yet running." A GitHub Actions run sitting in
   `waiting`, `pending` or `requested` is invisible to `live_runs()`, contradicting its own
   docstring — *"The product's own runs not completed"* — and the module docstring's new
   sentence, which frames the memo as covering the same ground `busy_runners()` covers. This is
   silent: `tests/test_ci_phantom.py`'s `Host` fixture only ever puts runs in `queued` or
   `in_progress`, so `SeamTests` cannot see the gap. Fix: iterate
   `sorted(ci_queue.QUEUED_STATUSES | {'in_progress'})` (or the unsorted set — order is
   irrelevant since results are deduped into a dict) instead of the literal two-tuple, and add a
   fixture run in one of the other three statuses to `Host` so the gap can't reopen unnoticed.
