## I list

- `asf/env.py:967` (`Product.references`) — `if declared:` treats an explicit `references: []` the
  same as no `references:` key at all, so a product that writes `references: []` to opt out of the
  legacy `matrix_path` synthesis (C2) still gets the synthesised `parity` reference when
  `matrix_path` is set. C2's own wording is "`matrix_path` with no `references:`", which reads as
  key-absence, not emptiness. Neither the spec nor PD3 calls out this shape as a required case and
  no test exercises it, so it isn't a regression against anything promised — but it's worth a line
  in `Product.references`'s docstring, or a follow-up Task, since it's the one input where
  "declares none" and "declares an empty list" diverge from what C2's prose implies.
- `docs/products.example.yaml:369` — the new `references:` example's `epic: E-0001` is a literal,
  not a placeholder, where the plan's Files section for this Task says "a comment placeholder,
  never a literal `E-nnnn`" (`docs/plans/f-0188.md:95-96`). No gate catches it either way:
  `check_conventions.sh`'s `\bE-[0-9]{4}\b` pattern (`tools/forbidden-conventions.txt:28`) only
  scans `asf/**/*.py`, and the file already uses the identical literal at `docs/products.example.yaml:138`
  (`default_bug_epic: E-0001`, pre-existing, untouched by this diff) — so the choice matches the
  file's own established convention even though it contradicts the plan's stated reasoning for this
  particular block.
- `tests/test_env.py:534-540` (`test_references_must_be_a_list`) — uses `assertTrue(problems)` and
  a per-item key check rather than an exact list equality, so unlike every sibling test in this
  class it would not catch a future `_reference_problems` that reports the non-list case twice.
  Harmless today since the function returns a one-element list unconditionally for that branch,
  but step 9 asks for "assert the whole list, not `in`" uniformly.
