## C

- `asf/hooks.py:303` — `_is_ours`'s basename branch, `(^|/)asf[A-Za-z0-9._+-]*`, has no boundary
  stopping it from consuming an unrelated command that merely starts with `asf` (e.g. `asfmt`), so
  `_is_ours('/dir/asfmt hook approvals', 'approvals', None)` is `True` and
  `hooks.approvals_missing` reports such an account's approvals hook as present. This is exactly
  the case the plan's Step 6 (`docs/plans/f-0111.md:217`) requires to read as *not* ours. Fix: give
  the basename alternative the same boundary Step 1's `is_git_hook_ours` intends (or reuse Task 1's
  `ENTRY_NAME_RE`/resolved entry name once it lands) so a name like `asfmt` cannot satisfy it, then
  restore the plan's literal `asfmt` case in the tests below instead of `notasf`.
- `tests/test_hooks_recognise.py:98` and `:207` — replace `/dir/notasf hook approvals` with the
  plan's own near-miss, `/dir/asfmt hook approvals` (`docs/plans/f-0111.md:217`); `notasf` cannot
  exercise the boundary the plan is testing and currently masks the bug above.
