### F1 — `ports.py:1540` is not `archive_and_reset`

Design decision D1.4/D10: *"`archive_and_reset` already exists for a branch that cannot land
(`ports.py:1540`)."* Line 1540 of `asf/kernel/ports.py` at the cited head (`cb47b17c8`) is inside
the `revert` method's merge-conflict branch (`raise PortError('revert %s conflicts with the
trunk: %s' % (sha, m.reason))`), not `archive_and_reset`. The method the sentence means is
declared at `ports.py:144` (the abstract: `def archive_and_reset(self, pr, branch, head_sha,
comment) -> str: ...`) and implemented at `ports.py:1711`. The claim itself — that the method
exists and does what D10 needs — holds; only the line number is wrong.

**Fix**: `ports.py:1540` → `ports.py:1711` (or `:144` for the abstract).

### F2 — `_hold_high_risk` is not a function in this repository

Precondition P11: *"`decide` strips `EnableAutoMerge`/`MergePR` for a held pull request and
leaves a `why` note, in `_hold_high_risk` (`:860-864`)."* Lines 860-864 of `asf/kernel/decide.py`
are exactly the code described (the list-comprehension that strips `A.EnableAutoMerge`/`A.MergePR`
for ids in `held`), but that code lives in a function named `hold_risky` (`decide.py:821`), not
`_hold_high_risk` — no function of that name exists anywhere in the module. Design §2.4 repeats
the same precedent correctly in prose ("P11, `decide.py:860-864`") without naming the function
again, so the error is confined to P11's own sentence.

**Fix**: `_hold_high_risk` → `hold_risky`.

Both are citation errors in supporting precondition text, not in the shape of the design itself —
the behavior each precondition claims exists and does exist at the function named correctly
elsewhere or one line away. Still, the brief's own test is "every fact it states … is true in
this repository," and a wrong function name or line number is a fact a future reader (or a coder
session building S-135959/S-135958 from this spec) would follow straight into the wrong code.
