## C list

- **C1** `asf/record/ids.py:158-161` — the local fallback's "step over a claimed block" guard
  reads `idclaim.claims(root)` without ever refreshing the local mirror of `refs/asf/ids/*` for
  this call, so a block another job claimed by push (a ref only, no committed card) is invisible
  and the next local-fallback mint can land on an id that origin already holds — exactly what this
  Task's own module docstring and P9/P11 exist to prevent. Reproduced: clone origin at `B-0267`,
  register the checkout's product with `conventions.flags.id_claim: off`, have a second checkout
  `idclaim.claim_one(c2, 'B', 'other-job', floor=267)` (claims `B-0268` on origin with no file
  written, so `origin_top` still reads `267`), then `ids.mint_id(c1, {}, 'bug')` also returns
  `B-0268` — a collision. Fix: before reading `blocks = idclaim.claims(root)` at `:161`, refresh
  the mirror when there is an origin to read it from, e.g.
  ```python
      if has_git and idclaim.has_origin(root):
          try:
              idclaim.fetch(root)
          except idclaim.ClaimError:
              pass
      blocks = idclaim.claims(root) if has_git else []
  ```
  (swallowing the error the same way an unreachable origin is already tolerated elsewhere in this
  function — a fetch that fails leaves the mirror exactly as stale as today, never a new refusal).

## I list

- `asf/record/ids.py:146` — the gate is `if has_git and idclaim.has_origin(root) and
  _claims_enabled(root):`, but the plan's Step 2 (`docs/plans/f-0260.md:495`) and the spec's §4
  (`docs/specs/f-0260.md:345`) both write the gate as `if idclaim.has_origin(root) and
  _claims_enabled(root):` — no `has_git`. `has_git` was already computed pre-Task for the local
  fallback's claims-mirror guard, and reusing it here appears to be a defensive guard against
  `idclaim.has_origin` picking up an ancestor repo's remote when `root` has no `.git` of its own
  (plausible when `git` walks up past a non-repo directory) rather than a behavioural change — no
  test distinguishes the two forms, and every production caller's `root` is a real checkout with a
  `.git` entry either way. Worth a line in the next report either reconciling the text with the
  code or noting the deviation as deliberate, so round 2 does not have to re-derive this.
