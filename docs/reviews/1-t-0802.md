## I — noted, not blocking

1. **`asf/proves.py:497-498,506` — `refused_why(n) or why` would silently fall through on an
   empty-string refusal text.** `refused.get(n)` (dict form) returns whatever the caller put
   there; if that value were ever `''` rather than a real sentence, `or` would treat it as falsy
   and report `why` (e.g. `NO_PROOF`) instead, swallowing the refusal silently rather than
   raising. Today's one caller (`asf/record/ingest.py`'s planned `unproved_of`, Task 4, not yet
   landed) always falls back to `proves.PARTIAL_CLAIM` when `why` is empty (spec §4, L413-414:
   `c.get('why') or proves.PARTIAL_CLAIM`), so the empty string never actually reaches `unproved`
   in practice — but `unproved` itself has no such guard, and `UnprovedReasonTests` never exercises
   an empty-string entry in the mapping form. A future caller that fills `refused` more loosely
   would hit this with no test anywhere to catch it. Worth a case in `UnprovedReasonTests` (and
   `is not None` instead of `or`) when this file is next open, not a reason to hold this Task,
   since nothing in Task 1's own footprint calls `unproved` with such a value.
