## C list

### C1 — a git read that did not answer is read as "the branch proves nothing"

`asf/harvest/lane.py:1144-1145`. Both reads take `gitops.git(...).stdout` and never look at
`.ok`. `asf.github.Result` defaults `stdout` to `''` (`asf/github.py:83`) and its own docstring
says *"ok false: the answer is Unknown … never read it as 'nothing there'"*. So a timed-out or
non-zero `git log` yields no claims, `proves.validate` returns `['no claim']`, and the lane
refuses the branch with kind `proves` — a correction round against a session whose commits may
carry a perfectly good trailer, with `hold_with_correction`'s round counter bumped toward
adjudication. Confirmed:

```
$ python3 -I probe.py          # gitops.git patched to return Result(False, reason='timeout')
timeout Result .stdout = '' | .ok = False
proves_refusal on a timed-out git = proves
no claim
add a trailer to one of your commits naming the line your tests prove, e.g.
  Proves: <S-id> line <n> — <the test path that proves it>
then push; the factory publishes the rewritten branch
```

The `ls-tree` half fails the same way in the other direction: a non-zero `ls-tree` gives
`tree == []`, so every *valid* claim collects `no such test: <raw>` and the correction tells the
coder its test path is not on the branch when it is.

**The fix.** Capture both Results and refuse nothing when either is Unknown:

```python
log = gitops.git(['log', '--format=%B', f'origin/{trunk}..origin/{branch}'], repo)
ls = gitops.git(['ls-tree', '-r', '--name-only', f'origin/{branch}'], repo)
if not (log.ok and ls.ok):
    return None   # a git read that did not answer is not evidence of a missing trailer
claims, tree = proves.parse(log.stdout), ls.stdout.split()
```

(`proves.claims_on_branch` cannot carry this — its injected callable returns text, not a
`Result` — so `proves_refusal` reads the range itself, which is the same single `git log
--format=%B` over `origin/<trunk>..origin/<branch>` that `claims_on_branch` runs.) Add a case to
`ProvesRefusalTests` patching `lane.gitops.git` to an Unknown `Result` and asserting
`assertIsNone`.

### C2 — the shipped-script test asserts a literal against itself

### C3 — `asf proves check` with no resolvable product exits 0 having checked nothing

`asf/rules/story_proof.py:83`: `ev = evidence.load(product=product) if product else {}`, with
`_product` swallowing `env.ConfigError` and returning `None` (`:70-78`). With `ev == {}`,

read no evidence at all**. The plan's own P13 settles the direction: *"`${ASF_PRODUCT:?}` makes
bash exit non-zero with nothing on stdout, which `run_check` reports as a violation line —
fail-loud, and the right way round for a rule."* The one silent-green path this module adds is

**The fix**, at `asf/rules/story_proof.py:81-83`:


### C4 — a claim whose PR named no Task id is counted against no Task

`asf/rules/story_proof.py:52-53`:
`[c for c in proven.get(sid) or [] if c.get('task') == iid]`. `landed_proves` sets each entry's
`task` with `next((i for i in pr_naming_ids(p) if i.startswith("T-")), None)`

(`:1588`) — both fall back to `None`. The two sources are keyed by `(story, line, test)` and the
pull-request entry is read **first**, so it shadows the commit entry (`:1552-1565`); a Task landed
inside a delivery pull request whose title and branch name only the Feature — this repo's own
F-0102 cross-item delivery shape — therefore stores its claim with `task: None` while
`ev['ids'][<T-id>]['commit']` is set from the member commit's own subject. `violations` then emits
`task landed proving nothing <T-id> (<S-id>)` for a Task whose claim is right there in the
evidence, and `asf file-bugs` files it as a Bug (`asf/tick/file_bugs.py:227`, over `asf rules check --json`'s `violations`, `:152`).

```python

task_claims = {sid: [c for c in proven.get(sid) or []
```

with a `StoryProofViolationsTests` case: a claim carrying `task: None` and the Task's own
