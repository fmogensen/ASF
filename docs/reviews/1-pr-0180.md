## C — must fix

none.

The four rewritten sites map one-for-one onto the calls they replace, and each asked the same
base (`ev['prod_sha']`), so one `reach` per derive is sound. `evidence.ancestry`
(`asf/evidence/evidence.py:1274-1292`) degrades correctly where the speed-up cannot apply: a
base the repo cannot resolve leaves `reach = None` and an abbreviated sha fails
`FULL_SHA_RE.fullmatch`, and both fall back to `ancestor_of` per question — the old cost, the
old answer. `rev-list <base>` includes `base` itself, which is what `merge-base --is-ancestor`
reports for `sha == base`; `tests/test_ingest.py:1474` covers that case.

The one real behaviour change is deliberate and is the description's own: these questions now
resolve against the **passed** product's `repo_dir` instead of `env.load_product()`'s. For the
default product that is byte-identical (the goldens and the 4747-test suite agree); for any
other product the old code was answering from the wrong repo.

## I — would change, not blocking

1. `tests/test_ingest.py:1409-1413` — the new class sits *after* the module's
   `if __name__ == '__main__': unittest.main()` guard. Under `python -m unittest` (what
   `tools/run_tests.py` and CI use) it loads fine, but anyone running the module as a script
   with `PYTHONPATH` set gets `unittest.main()` at line 1410 and the two new tests silently
   never exist. Move the class above the guard and leave the guard last, as it was.
2. `asf/record/ingest.py:413` and `:442` — the product-less defaults (`reach or _prod_reach(ev)`)
   still reach `env.load_product()` through `ancestor_of`. That is the intended
   backward-compatible path, but it means the wrong-product bug this PR fixes survives for any
   caller of `_in_prod`/`_merged_in_prod` that does not thread `reach`. Today only tests do.
   Worth a `product=None` parameter on both so the fix is not conditional on the caller.
3. `tests/test_ingest.py:1467` — `c.args[0][:1] == ['git']` only counts list-form calls. A git
   fork made through `evidence.sh()` (`asf/evidence/evidence.py:80-85`, `shell=True`, a string)
   would not be counted, so the bound is on `ancestor_of`-shaped forks rather than on git
   generally. That is enough to prove *this* change (both `ancestry` and `ancestor_of` are
   list-form, and seven unanswered questions could not hide behind one call), but the assertion
   is narrower than "the git calls are bounded to 1" reads.
4. `tests/test_ingest.py:1465` — `mock.patch.object(ingest.evidence.subprocess, 'run', ...)`
   patches the stdlib `subprocess` module, not an evidence-local alias, so the count is
   process-global. Harmless under `run_tests.py` (one module per process, serial within it), but
   it makes the assertion sensitive to any unrelated code that starts forking git.
5. `tests/test_ingest.py:1421` and `:1463` — `import subprocess` twice inside methods, where the
   module imports everything else at the top (`:1-17`). Hoist it.
6. Neither new test exercises the `product is None` branch of `_prod_reach`
   (`asf/record/ingest.py:396-398`), which is the path the description promises is unchanged.
   One assertion that it forks one `merge-base` per question would pin it.
