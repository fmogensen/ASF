## C (block)

**C1 — `asf/record/move.py:85-104` (`resolve_target`): the `--to` source-identity check compares
realpath strings, not directory identity, contradicting both its own docstring and the plan's D16.**

The plan is explicit (`docs/plans/replans/f-0120-53be601e3f22.md:359-361`, Step 5): `--to`'s source
product "must be the one whose `backlog_dir` is `root` — compared by directory identity the way
`product_of_dir` compares (`:430-460`), not by spelling." `resolve_target`'s own docstring repeats
this verbatim intent (`move.py:90-91`: "compared by directory identity, not by spelling, the way
`asf.env.product_of_dir` compares"). But the code at `move.py:101` is:

```python
if not sbd or os.path.realpath(sbd) != os.path.realpath(root):
```

`product_of_dir` (`asf/env.py:434-477`) does not compare realpath strings — it `os.stat()`s each
candidate and keys on `(st.st_dev, st.st_ino)` precisely so that "a root that differs only by
case on a case-insensitive filesystem still matches" (`asf/env.py:439-440`, P11's own words).
`os.path.realpath()` resolves symlinks but never folds case, so on a case-insensitive filesystem
(macOS's default APFS, a platform real operators run this tool from) two spellings of the same
directory that differ only in case produce two different `realpath()` strings and this check refuses with `error: --to needs the source
product's own record — <root> is not <name>'s backlog_dir` even though `root` genuinely *is* that
product's `backlog_dir`. This is the opposite of a security hole (it over-refuses, it never
under-refuses), but it is a reachable operator-facing false refusal on exactly the host this
product runs on, for exactly the comparison the plan calls out by name and line range as the one
to replicate.

No test exercises a case-difference or an alternate path to the same directory —
`MoveToTargetTests.test_to_refuses_when_the_resolved_source_product_is_not_this_record` uses two
genuinely different directories, which both methods refuse alike, so it does not catch this.

**Fix.** Reuse `product_of_dir`'s own identity primitive instead of `os.path.realpath` equality,
e.g.:

```python
def _same_dir(a, b):
    try:
        sa, sb = os.stat(a), os.stat(b)
    except OSError:
        return False
    return (sa.st_dev, sa.st_ino) == (sb.st_dev, sb.st_ino)
...
if not sbd or not _same_dir(sbd, root):
```

so the docstring's claim and the plan's D16 are actually true of the code, not just of its prose.

nothing currently reaches the gap.** `cmd_move`'s per-card write loop (`move.py:313-325`) carries
the comment `# unreachable after check(): the selection is left unexplained, never half-written`

apply=False)` (`move.py:107-118`), which by design (Step 1, `asf/record/setfield.py:360-361`)
returns *before* `stage.guarded`'s record-scope invariants (I1, I2, I3, I10, I11, I14) ever run,
while the real write (`apply=True`, the default) *does* run them. So `check()` cannot actually
predict every reason `stage.guarded` might refuse the real write. Today this is provably inert for
`move`'s own fields: `belongs_to` is a TYPED field, not a MACHINE one (`asf/record/new.py` — it is
meant to join `_COMMON_SET`, not `frontmatter`'s machine block), so I1's "machine key stripped"
check never sees `belongs_to: None`; I3 only judges `writes:`/`after:` changes, which `move` never
touches; I2/I10/I11/I14 are schema-stamp/Feature-landing/redaction/close-transition checks that
`removed`/`moved_to`/`belongs_to` cannot trigger. So no card can currently cause `cmd_move` to
write some of a selection and not the rest. Worth a one-line note in `check`'s or `cmd_move`'s
docstring saying the guarantee depends on no `stage.guarded` invariant ever keying off these three
fields, so the next invariant author knows to check `asf/record/move.py` before adding one that
might.

**I3 — `intake_file`/`_rows_and_dedupe` scrub the title with the *target* product's redaction
patterns, not the source's.** `_scrubbed_title(meta.get('title'), root)` is called with

unlikely to bite today, and the spec genuinely doesn't say which root to pass — flagging for a
