## I — would change, will not block

- **I1 — the reason-in-parens only reaches the one step this bug named.** `asf/tick/tick.py:468`
  (`ran.append({'step': step, 'ok': not step_rc, 'seconds': ...})`, the per-step loop for
  `record`/`health`/`groom`/`wave`/`prs`/`harvest`) never sets a `'reason'` key, so
  `_step_word` (`asf/tick/summary.py:170`) falls through to the bare `f"{step} FAILED"` for all
  six of them — the card's "Wanted in code" reads generally ("a failed step", not "the commit
  step"), and today only the new `commit` entry gets the parenthetical. Not a blocker: the actual
  bug (a step invisible in the line at all) is fixed, and these six already agreed with the exit
  code before this change — `run_asf_step` already prints `[step:<name>] FAILED <reason>` to the
  log (`:572`) and sets `ctx.stale_reason` for `record` (`:576`), but that reason is never carried
  into the `ran` entry the digest reads. Worth a follow-up: thread the same `_first_line(detail)`
  already computed at `:572`/`:578` into the `ran.append` at `:468` so every step's `FAILED` in
  the TICK line carries its reason, not just the tick's own commit.
- **I2 — the hermetic CI leg (`env -i`, operator home, foreign default branch) did not run this
  round**, for the sandbox reason in the Gate row above. The diff's own code has no
  environment-reading surface, so the risk is low, but the row rests on that inference rather
  than a run; worth having the next round (or the PR's own CI, which does run it) confirm.
