- `docs/specs/f-0031.md:326` — the §3 test list still reads
  ``- `test_classifier_exception_fails_closed` — `classify` patched to raise → rc 2 (D7);``, which
  names a test that no longer exists and describes the behaviour the same file's amended D7 row now
  contradicts. Fix: ``- `test_classifier_exception_is_an_error_not_a_refusal` — `classify` patched
  to raise → rc 2 with the hook-error wording, never a refusal's (D7);``.
- `asf/approvals.py:784` — `HOOK_ERROR_LINE.format(why=e or type(e).__name__)`: the
  `or type(e).__name__` fallback is dead code, because `BaseException` defines no `__bool__` or
  `__len__` and an exception instance is therefore always truthy. Verified: `RuntimeError()` gives
  `'approvals hook error: ; not a refusal — retry'` — the session is told nothing at all — and
  `KeyError('ASF_PRODUCT')` gives `approvals hook error: 'ASF_PRODUCT'; not a refusal — retry`,
  naming no type. These are precisely the message-less internal failures the card is about, and
  they leave the session's line and the log disagreeing, since `record_hook_error` at `:755` gets
  it right with `str(exc)[:200] or type(exc).__name__`. Fix: `why=str(e) or type(e).__name__` —
  the same idiom `asf/tick/step_wave.py:103` already uses.
- `asf/approvals.py:763-766` — `_log_traceback` appends to `approvals-hook.log` with no size cap
  and no rotation, on the one path that fires on every `Bash`, `Write`, `Edit`, `MultiEdit` and
  `NotebookEdit` call of every session. A systematic break (an unreadable product file, say) writes
  a full traceback per tool call and the file grows without bound. The repo's own precedent for a
  log under `env.log_dir()` is `asf/harvest/harvest.py:755-772` `keep_red_output`, which caps at
  `GATE_RED_MAX_BYTES = 4 << 20` and rotates to `path + '.1'`. Fix: in `_log_traceback`, before
  opening, `if os.path.exists(p) and os.path.getsize(p) > HOOK_ERROR_LOG_MAX_BYTES:
  os.replace(p, p + '.1')`, with `HOOK_ERROR_LOG_MAX_BYTES = 4 << 20` beside `HOOK_ERROR_LOG` at
  `:733`.
- `docs/plans/b-0125.md` and `docs/specs/b-0125.md` (both missing) — with no plan there is no Task,
  no Steps and no Acceptance, so three rows of this table cannot pass on evidence. Fix: add the plan
  naming the one Task (an internal hook failure reports itself as an error, not a refusal, logs its
  traceback, opens no hold, and a run of them surfaces once in the tick), and give its Acceptance as
  the three tests already at `tests/test_approvals.py:387`, `:396` and `:731`.
- The card's investigation clause is unanswered: "Investigate the likely causes under load (the hook
  re-reads config and product files on every call; concurrent writes to `approvals.jsonl`; a slow
  start of the installed binary)." Nothing in the branch reports it. It is answerable from this

  refusal is diagnosed rather than re-investigated.
