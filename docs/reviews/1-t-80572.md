## C — must fix before approval

**C1 — `clear_history_line` glues filler directly onto the kept id token, so `core.ID_TOKEN_RE` (the very regex the module's docstring and design cite) can no longer re-find the reference it claims to keep.** `asf/rehearsal.py:81-101`. The function clears the text *around* an id match with `clear_line(gap)` and concatenates the pieces with no separator, so whichever filler word lands at the edge runs straight into the kept id with no non-word character between them — e.g. the committed `tests/rehearsal/record/bugs/B-00001.md:19` reads `- 2026-02-11: groom:ipsum nisi incididunT-00001` (verified reproducible: `rehearsal.clear_history_line('- 2026-02-11: groom: priority -> P1, see T-00001')` → `'- 2026-02-11: groom:laboris esse mollit uT-00001'`, and `core.ID_TOKEN_RE.findall(...)` on that output → `[]`). This is not cosmetic: `asf/groom/policy.py:774` (`_ITEM_ID_RE = ID_TOKEN_RE`) and `asf/record/replan.py:96` (`ID_RE = ID_TOKEN_RE`) are exactly the regex Task 3's `record` act drives ("a groom pass and a replan over the laid-down record") to find backlink/reference ids in card text — on this snapshot every one of the 185 cards' groom History line fails that match (`grep -rlE '[a-z][A-Z]-[0-9]{4,}' tests/rehearsal/record/ | wc -l` → `185`), so groom/replan over this fixture cannot see any of the id references the design says a History line keeps. Fix: when building the gap around a kept id (and the tail after the last one), preserve the gap's own leading/trailing non-word character literally (whitespace or punctuation) instead of handing the whole gap to `clear_line`, so the boundary `\b` needs still holds, e.g. split each gap into `(edge, inner, edge)` by `str.isalnum()`/`_`, filler only `inner`, and keep each non-word edge byte as-is — confirmed this preserves length and restores the match (`core.ID_TOKEN_RE.findall(...)` → `['T-00001']`) without touching anything else in the function.
