I list (non-blocking):

- `tests/test_env.py:474-478` — the card names `unittest.skipUnless` for the case-insensitive-filesystem test; the writer used an inline `self.skipTest(...)` guard inside the test body instead of the decorator. Behaviour is identical (the probe runs, the test skips on a case-sensitive filesystem), so this is a style deviation from the card's own wording, not a defect.
- `tests/test_env.py:711-717` (`test_none_answering_names_all_four`) asserts `self.tmp.name` (the pre-`realpath` path) is a substring of the `ConfigError` message, while the message is built from `os.path.realpath(path or os.getcwd())`. On this host `os.getcwd()` after `os.chdir(self.tmp.name)` already returns the resolved path and the raw `self.tmp.name` happens to be a substring of it, so the test passes here — but unlike every other test in this file (which derives `root = os.path.realpath(self.tmp.name)` in `setUp`) this one skips that step, so it is one filesystem layout away (e.g. a `TMPDIR` under a symlink where the raw name is *not* a substring of its own realpath) from failing on a differently configured host or CI image.
