## C — must fix

- `asf/feeder/tiers.py:89` — `behind_rows` (and therefore `Gate.held`, `Gate.behind`, `Gate.by_kind`
  at `:91-109`) must exclude rows whose `item_id` is in `held`, per the plan's Step 3 and the
  module's own docstring ("[a held row] holds no tier back... it cannot start whatever the
  capacity, so a slot given to it is a slot no session gets" — `asf/feeder/tiers.py:12-16`).
  Fix: `behind_rows = [r for r in uncut if r.tier == TIER_REST and r.launches and r.item_id not in held]`.
  Without this, `gate_line`'s "S1 gate: ... holds N rows" and `needs_operator`'s "holds `<held>`
  of `<behind>`" both overcount whenever a tier-2 item is separately parked by an approval hold
  while the S1 lane is also cutting — attributing a hold's own stall to the S1 lane, which is the
  exact confusion this card exists to remove. Add a case to `S1GateTests` with a held tier-2 row
  behind an unseated S1 to pin the corrected count.
