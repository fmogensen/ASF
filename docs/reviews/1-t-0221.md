## I — noted, not blocking

1. **`tools/run_tests.py:103-262` deadlocks under its own parallel pool on this host whenever a
   module pair's combined stdout exceeds the OS pipe buffer before the process exits** —
   `run_modules` hands each `Popen` a `stdout=PIPE` and the scheduling loop polls with
   `p.poll()` but never reads from the pipe until `communicate()` is called on a process `poll()`
   already found finished, so a process that fills the pipe first blocks on `write()` forever
   and the parent blocks forever on `poll()` for it — a classic pipe deadlock, confirmed live via
   `/proc/<pid>/wchan == anon_pipe_write`. It reproduces identically on a clean `origin/main`
   checkout and is unrelated to `asf/metrics/metrics.py`/`tests/test_metrics.py`; nothing in
   `writes:` for this card could fix it, and the card's own Standing Rules say the full suite
   runs off this host anyway. Worth its own card against `tools/run_tests.py` (read with
   incremental draining, e.g. `select`/a reader thread per pipe, or `bufsize`-bounded chunks)
   since any sandboxed review session with fewer than ~8 cores will hit the same wall every time
   this gate command is asked for.
2. **`tests.test_workers`, `tests.test_sample_product` and `tests.test_snapshot` are red on
   `origin/main` too** (`failures=10, errors=6, skipped=1` combined, run directly to bypass I1's
   deadlock) — pre-existing and untouched by this diff, consistent with the writer's own report
