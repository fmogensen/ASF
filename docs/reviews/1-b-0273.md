## C — blocking

### C1 — `asf/metrics/metrics.py:72`: the gate downstream of the fixed regex still rejects 5-digit ids, so the card's own landing is dropped instead of attributed

`metrics.ID_RE` is not an independent `\d{4}` site to defer: it validates the output of the very
regex this card widens, on the very stream the card's incident is about. `validate()` resolves the
id with `match.match_event` (`metrics.py:296` for `landings`, `:285` `sessions`, `:270` `ci`) and
then immediately re-checks it at `metrics.py:318-322`:

```python
if stream in ('ci', 'sessions', 'landings'):
    ids = ev['items'] if stream == 'ci' else ([ev['item']] if ev['item'] else [])
    for i in ids or []:
        if not isinstance(i, str) or not ID_RE.match(i):
            raise SchemaError(f"{stream}: {i!r} is not an item id")
```

Before this diff `match_event` returned `[]` for `T-32850`, so the row was written with
`item: null` / `item_reason: 'no rule matched (branch)'` — the card's complaint. After it,
`match_event` returns `['T-32850']`, `ID_RE` refuses it, and the caught `SchemaError`
(`metrics.py:2309-2313`, `import_sessions.py:236-240`) discards the whole event. Net effect on
the three streams, for every 5-digit id: `landings` rows vanish (so does the `branch`/`sha` join
key the Feature's wait is read off), `sessions` rows vanish (`metrics.py:1852` leaves `item`
unset, the schema default `MATCH` then triggers the same path), `ci` rows vanish
(`metrics.py:270`).

**The exact fix** — `asf/metrics/metrics.py:72`:

```python
ID_RE = re.compile(r'^[EFSTBDR]-\d{4,}$')
```

and a test in `tests/test_metrics.py` asserting
`metrics.validate('landings', {'ts': '2026-10-06T22:00:00Z', 'job': '<job>', 'sha': '<sha>',
'branch': 'cloud/T-32850'}, {'T-32850': {...}})['item'] == 'T-32850'` — it raises `SchemaError` on
this head.

Keep `asf/scorecard/facts.py:31` out of it (I2): that one only fails to match, and nothing this
diff changes feeds it.
