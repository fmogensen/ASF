## C

**C1 — `asf/tick/file_bugs.py:196`: a possessive apostrophe is read as an opening quote, so the
`writes:` overlap error splits into one class per glob — the exact "one Bug per card" noise this
source exists to prevent.**

`_QUOTED_RE = re.compile(r"'[^']*'|\"[^\"]*\"")` scans left to right with no guard on what
precedes the opening `'`. The Active-`writes:` overlap message (`asf/record/check.py:366`) is
`f"writes: {g1!r} intersects Active task {t2['meta'].get('id')}'s {g2!r}"`, so a rendered message
carries three apostrophe runs: the `!r` quotes around `g1`, the possessive in `T-0001's`, and the
`!r` quotes around `g2`. The regex consumes `'g1'`, then pairs the possessive `'` with `g2`'s
*opening* `'` — matching the four characters `'s '` — and leaves `g2` and a dangling `'` in the
class. Verified directly:

```
>>> error_class("writes: 'asf/a.py' intersects Active task T-0001's 'asf/b.py'")
"writes: … intersects Active task ……asf/b.py'"
>>> error_class("writes: 'asf/c.py' intersects Active task T-0002's 'docs/x.md'")
"writes: … intersects Active task ……docs/x.md'"
```

Two overlaps that are the same defect become two signatures, two Bugs, two groom decisions — and
a record with *k* distinct second globs files *k* Bugs, which is what `RECORD_ERROR_PLACES` and
the per-class `setdefault` were written to avoid. `tests/test_t10_gate.py` does not catch it: its
fixture carries exactly one overlap, so one class is indistinguishable from one place.

The fix — a possessive or contraction apostrophe never opens a quoted span, so require the
opening `'` not to follow a word character:

```python
_QUOTED_RE = re.compile(r"(?<![A-Za-z0-9])'[^']*'|\"[^\"]*\"")
```

Verified against the same inputs, both overlaps now collapse to one class and the two classes the
new tests already assert are byte-unchanged:

```
"writes: … intersects Active task …'s …"      # both overlap messages
'bare decision reference …; write it as [[D-nnnn]]'
'id … does not match filename ….md'
```

Add a test next to `test_two_error_classes_are_two_bugs` that gives two Active Task pairs
overlapping on *different* globs and asserts one signature — the case the present fixture cannot
distinguish.

## I

**I1 — `asf/tick/file_bugs.py:243`: the "and N more" overflow line is appended to `evidence`, and
the bump path quotes `evidence[-1]` as the place it saw.** `_file_or_bump_bug` builds its History
line from `latest = info['evidence'][-1]` (`asf/tick/file_bugs.py:344`), so every bump of a class
with more than `RECORD_ERROR_PLACES` places writes `- <date> file-bugs: count 1 → 2 (and 40 more)`
— a history entry that names no place at all. Carry the overflow count in the Bug body (or in the
typed `places`, which already holds it) rather than as the last evidence bullet, or have the bump
read `evidence[0]`. Related: the bump path refreshes typed `places` but never the body's evidence
list, so a Bug that grew from 3 places to 50 still shows the original three — pre-existing for the
rule-violation source, not introduced here.

**I2 — `asf/tick/file_bugs.py:226`: `filed_here` skips every card this tool ever filed, which is
wider than the loop it is guarding against.** The predicate is "carries a typed `signature`", which
is true of all four sources' Bugs. The docstring justifies only one case — an unparented Bug,
already reported once by `usable_bug_epic` — but the skip also hides a genuinely malformed
auto-filed Bug (wrong parent type, stale `## Children`, missing severity) from this source for
ever, so `file-bugs` can never see its own bad output. Narrowing it to the class that actually
loops (`is missing a parent` on a card this tool filed) keeps the guard and closes the blind spot.

**I3 — messages that keep an unquoted specific split into more classes than they should, and one
mangles.** `asf/record/check.py:210` (`does not match folder {rec['folder']}`) and `:234`
(`has wrong type {ptype}`) leave the folder and type bare, so they yield one class per folder and
per type. `asf/record/check.py:329`'s `that is a Task's/Bug's shape` contains `'s/Bug'`, which
`_QUOTED_RE` eats whole — the class reads `that is a Task…s shape`. Neither splits a class the way
C1 does (both specifics come from a small fixed set), but the Bug titles read oddly. Quoting the
folder and type in the check messages would fix both, and would also make them uniform with the
`!r` every neighbouring message already uses.

**I4 — `record_error_signatures` recomputes the whole record check even though its caller has
already loaded the record.** `cmd_file_bugs` passes `canonical=` but never `findings=`
(`asf/tick/file_bugs.py:491`), so `record_findings(root, layout=False)` re-runs `load_items`,
`canonicalize`, `compute_derived` and the O(n²) Active-`writes:` overlap scan on every tick.
Threading the findings in from a single check would halve `file-bugs`' record work.

**I5 — the filed Bug carries `found_in: 'ci'`** (`asf/tick/file_bugs.py:354`): a standing record
error was not found in ci. Shared with the rule-violation and refusal sources, so pre-existing —
but this source makes the mislabel more visible, since a record error has no run to point at.

**I6 — `tests/test_t10_gate.py:188,193` assert `3 filed` and four Bug files, coupling the T10 gate

**I7 — neither `docs/specs/b-0132.md` nor `docs/plans/b-0132.md` exists, and the card declares no
`writes:`.** Three rows of this table had nothing to judge against and are recorded `fail` for

`writes:` line, if only so the scope row can be answered.

**I8 — a check message containing a backtick breaks the evidence line's own code span.** The
evidence line is `f"`{path}:{line}: {message}`"`, and the guard that keeps the Bug from becoming an
instance of the class it reports is that `asf/record/check.py:265` strips `` `...` `` spans before
scanning for a bare decision reference. `asf/record/check.py:213`'s message already embeds

leaves fragments of the message exposed to the scan. Harmless for every message that exists today
(none of the backtick-bearing ones carries a `D<n>`), but it is the same self-reference C1's
neighbour comment is guarding, one message away from biting. Escaping or stripping backticks out
of the quoted message would close it.
