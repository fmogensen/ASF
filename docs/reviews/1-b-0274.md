**I2 — `asf/flake.py:404-406`: up to two `gh api` calls to settle one refused re-run.** When
`required` is set and the refusal text itself doesn't say the run is still going, `triage` calls
`run_live(slug, run_id, gh)` (unfiltered) and then, only if that says live, calls it again with
`required=required` (filtered) — two network calls where the filtered answer alone would settle
it for the common case. This looks deliberate, not accidental: the filtered call's `None`

call would need its own fallback story. Not a correctness problem; worth a second look only if
this path turns out to be hot (the merge queue's own red-retry pass, not every poll).
