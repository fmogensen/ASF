## C

- `tools/spike/f-0065/session.sh:124` — `passthrough=asf_env.env_passthrough(cfg)` never varies with `variant`, so `grant-net` and `grant-net-passthrough` legs get byte-identical settings (confirmed: `diff tools/spike/f-0065/settings/coder.grant-net.json tools/spike/f-0065/settings/coder.grant-net-passthrough.json` differs only in the header comment's filename) and byte-identical environments. This defeats §3.9 outright — Task 4's "does a proxied egress need names `hermetic.WORKER_ALLOW` strips" pair has nothing to distinguish its two legs by. Fix: branch on `variant == 'grant-net-passthrough'` and add the extra name(s) a proxied egress needs to the passthrough tuple for that leg only, matching the contract the settings templates themselves already state.
- `tools/spike/f-0065/session.sh:75-77` — `os.remove(LOG_PATH)` runs before every refusal check that follows (no local account at `:82`, no credential at `:88-91`, PD6's account-settings carry at `:101-103`, PD7's render checks later in the file). A refused invocation — e.g. a temporarily unset credential, or an account settings file that transiently carries a sandbox key — deletes a leg's previously-recorded, already-paid-for log before refusing to launch a replacement. §4's "a re-run of a leg overwrites its own file and no other" describes a completed re-run, not an aborted one. Fix: move the removal to immediately before the actual `runtime.ClaudeCodeRuntime().run(...)` call (or write the new log to a temp path and rename over `LOG_PATH` only on completion), so a refusal path never touches an existing log.
