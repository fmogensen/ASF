## I

**I1 — `check_worker_push_auth` makes 1-2 live network calls per configured worker account on
every `asf doctor` invocation.** `git ls-remote origin` and (on success) `git push --dry-run
--no-verify` both hit the real remote (`asf/doctor.py:314-323`), each with a 15s timeout. This
is exactly what the card's `## Fix` asks for ("probes `git ls-remote` + a push --dry-run from a
worker env per account"), and `doctor.run()` is operator-invoked only (`asf/cli.py:520`, no
scheduler/tick path calls it), so it does not sit on any hot path — but an operator running
`asf doctor` with several accounts and a slow or rate-limited remote will notice the added
latency where every other row today is local-only. Not blocking: the card asked for exactly this
probe.

**I2 — the probe ref name (`PUSH_AUTH_PROBE_REF = 'refs/heads/asf-doctor-push-probe'`) is fixed
and unnamespaced.** Two products sharing one GitHub org's audit log, or a repo with branch
protection rules keyed on `refs/heads/*` patterns, would see this literal name appear in dry-run
push attempts from every account, every doctor run. `--dry-run` means the ref is never actually
created, so this is cosmetic, not a correctness issue.
