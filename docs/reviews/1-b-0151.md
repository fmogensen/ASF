## C list

- C1 — `asf/reserve.py:135-138` (`reserve`): the persisted claim — the half of this fix that is
  supposed to close "two sessions each seeing only main, and both picking the same migration
  number" *before* either branch is pushed — is written to `env.state_dir(product)`, a path under
  `ASF_HOME` on whatever host the `asf reserve` process happens to run on. The incident this card
  describes is entirely `cloud/*` branches (`cloud/T-0383`, `cloud/T-0386`, `cloud/direct-F-0112`,
  `cloud/direct-F-0113`), and `asf/workers/cloud.py`'s own module docstring is explicit that the
  cloud lane "moves the whole session off the host" onto "the product's own CI runners" — a fresh
  GitHub Actions runner per session, with its own empty `~/.ASF` and no code anywhere in
  `asf/workers/actions.py` (or this diff) that shares or syncs `ASF_HOME`/the reservations file
  between runners or back to the factory host. Two concurrent cloud sessions calling
  `asf reserve migrations` each see zero prior reservations and, if neither has pushed yet, the
  git-scan half (`open_branch_trees`) sees nothing either — the exact collision this fix exists to
  close reopens for precisely the class of session the card's incident report names. Only a cloud
  session racing against an *already-pushed* branch is caught (by `open_branch_trees`); the
  pre-push race — the one `test_second_call_does_not_repeat_the_first_before_any_branch_is_pushed`
  claims to cover — is not, whenever either side is a cloud session. Fix: persist the claim
  somewhere every runner can reach (e.g. a small pushed commit/lock on `origin`, or a service
  outside any one runner's disk), not a local `ASF_HOME` path.
- C2 — `asf/reserve.py:25-48` (`pattern_regex`), `asf/conventions.py:70-71`: the card's own example
  config names two sequence shapes — `migrations: db/migrations/NNNN_*.sql` and
  `bands: docs/decisions/bands.md` — and the incident text itself treats them as distinct
  ("0297/0298 unbanded" vs. the migration numbers). This diff implements and documents only the
  first shape (one number embedded in each filename of a directory); `bands.md` has no `N` run at
  all, so `pattern_regex` raises `ValueError: sequence pattern 'docs/decisions/bands.md' names no
  number field (NNNN)` the first time any product configures `bands` as the card literally shows
  it. Nothing in the diff, the new doc comment, or the commit message says the second shape was
  descoped or why. Fix: either support a "numbers recorded inside one file" sequence shape, or
  state explicitly (in a plan/spec, since none exists — C3) that `bands` needs a different
  `conventions.sequences` value than the card's own example and what that value must look like.
- C3 — `docs/plans/b-0151.md` / `docs/specs/b-0151.md` (missing): neither exists anywhere in
  history, so "every Step" and "byte-identical acceptance tests" (rows above) cannot be checked,
  and the two scope cuts in C1/C2 are undocumented decisions rather than recorded ones. Add a plan
  naming the Task this diff delivers (`asf reserve`'s git-scan + persisted-claim number
  reservation), its Steps (`pattern_regex`/`compute_next`/`reserve` in `asf/reserve.py`, the
  `sequences` convention in `asf/conventions.py:329-332,580-583`, the CLI wiring in
  `asf/cli.py:267-270,527-529`), and its Acceptance pointing at `tests/test_reserve.py` — and use
  it to record C1 and C2 as either fixed or as an explicitly accepted, reasoned scope cut.

  fine given the incident this closes, but worth naming as an accepted cost once C3's plan exists.
