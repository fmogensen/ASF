## C list

- **C1** — `asf/ci_vm.py:421` (`REMOTE_START`'s `setsid sh "$rundir/run.sh" ... &`): replace the
  `setsid`-based detach with something that does not require a Linux-only binary on the remote
  machine — e.g. `(exec sh "$rundir/run.sh" </dev/null >/dev/null 2>&1 &)` run from a subshell
  that is itself backgrounded (dissociates the child from the parent's job-control group without
  `setsid(1)`), or detect `setsid`'s absence and fall back. The feature's own premise is "any
  ssh-reachable machine" (no OS stated), and the fixture that is supposed to prove the detach
  works runs the real scripts on whatever host executes the test suite — which can be (and here,
  is) non-Linux. `REMOTE_CANCEL`'s `kill -TERM -<pgid>` only isolates the right process tree if
  the detach actually gave it its own pgid, so this is not cosmetic: on a host without `setsid`, a
  cancel or timeout would send `SIGTERM` to the caller's own process group instead.
- **C2** — `tests/test_ci_vm.py::Wiring` (ends at tests/test_ci_vm.py:588): T-0710's own Acceptance
  text (docs/plans/replans/f-0194-87b236e237ad.md:424-425) requires **"`scheduler.clocks()`
  installs no `ci-vm` clock for a vm product" — the cut is asserted, not merely absent, so a later
  session reading the plan's PD8 does not add one back without a card.** No such test exists in
  `Wiring` (or anywhere in tests/test_ci_vm.py) — it is missing entirely, not just failing. (Carried
  forward: an earlier review session on a prior head of this same branch raised this as its own
  C1 and it was never addressed by the two "correct" commits that followed.)
