## C

- `asf/views/readme.py:403` — `cmd_readme`'s `--refresh` branch calls `env.load_product(product_name)`
  before reading the page or checking `spans(text)`, with no `try/except env.ConfigError` (contrast
  the default/`--check` branch two lines down, which already has this fallback). On a repo whose
  README carries no span and whose product config does not resolve, this raises an uncaught
  `ConfigError` instead of Task 3 Step 6's `readme: no spans — nothing to render`, exit 0 "on every
  form including `--refresh`". Fix: resolve `repo_dir`/`conv` the same way the check path does
  (`env.load_product` in a `try/except ConfigError`, falling back to `_git_root(root)` and
  `conventions_mod.Conventions()`), read the page and check `spans(text)` first, and only call
  `resolve_record`/require the product config once there is something to actually refresh.

  span in the page") beyond the spec's five-item list in §2.1/the Task's Step 2 (only "a span whose
  body differs from the fact" is named there). Not wrong and not caught by any test either way, but
  worth confirming this extra check is wanted rather than trimming it for exact spec parity.
