## C list

- **C1** `tests/test_tick.py:487-498` (the `at()` helper inside
  `StaleRowCadenceTests.test_a_13_3m_tick_silences_the_row_through_20m_and_it_still_stales_at_40m`)
  — this is the actual, still-live cause of the CI run B-0403's own Evidence names
  (`37550936590`, job `112565977061`). Traced it: `at()` deletes only
  `metrics/ticks/<day-of-this-call>.jsonl` (line 492-494) before writing. When the two `at(20)`
  and `at(40)` calls straddle a UTC-midnight boundary (the failing run logged at `00:27:25Z`),
  `at(20)`'s simulated timestamp lands just after midnight (e.g. `00:05` today) while `at(40)`'s
  lands just before it (e.g. `23:45` yesterday) — an earlier simulated moment that is nonetheless
  a *later* wall-clock day-file write. `at(40)` only clears yesterday's file, so today's leftover
  entry from `at(20)` survives in a second `metrics/ticks/*.jsonl` file.
  `status._last_record_tick` (`asf/views/status.py:245`) globs across both files and picks the
  line with the largest `ts` — today's `00:05` leftover beats yesterday's `23:45` fresh write —
  so `status.stale_cell` computes `age_s` against the stale-but-chronologically-later leftover
  (~20m old) instead of the fresh `40m`-old entry, stays under the 2196s threshold, and returns
  `None` where the test expects the STALE string. Fix: at the top of `at()`, remove every file
  under `metrics/ticks/` (e.g. `for p in glob.glob(os.path.join(self.operator, 'metrics', 'ticks', '*.jsonl')): os.remove(p)`)
  instead of only the single day-matched `path`, so no cross-midnight leftover from the previous
  `at()` call can ever outrank the one just written. This diff — a legitimate, separate fix for
  the `_RebaseShape` git-housekeeping race already flagged in `1-b-0356.md`'s I list — leaves this
  one untouched, so the Acceptance bullet ("fails in no CI run for 24h") has no reason to hold.
