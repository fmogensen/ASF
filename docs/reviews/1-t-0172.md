## C list

- **C1** `asf/groom/delivery.py:237` — `releasable`'s lead-uncommitted branch returns an already-landed (`Resolved`) member as if it were still open, because it tests `_state(r) != 'Closed'` instead of "still open" (`state: New`, no evidence). Fix: make the condition match the sibling branch at `:246` —
  ```python
  if r is not None and _state(r) == 'New' and not r['meta'].get('evidence'):
      out.append((lead, i))
  ```
  Without this, Task 2's release rule (plan `docs/plans/f-0102.md:231-235`) will clear `delivered_by:` and drop a member *that already landed through this delivery* from the lead's `delivers:`, writing a `delivery: released <member> from <lead> — the delivery landed without it` History line that is false, and corrupting the rollup's delivered-vs-single accounting (S-64811) for that item.
