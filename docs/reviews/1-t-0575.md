## C list

- **C1** — `tests/test_cloud.py:581` (`DefaultPlacement.test_local_only_kinds_and_items_stay_local`), `:1027` (`PrimaryMode.test_what_must_run_here_stays_local`), `:1140` (`PrimaryMode.test_the_mode_flips_on_the_next_tick`). Each of these calls `Lanes.run_wave` (`tests/test_cloud.py:420-428`) **twice** in one test method, each time against a fresh hand-built `Pool`. Before this diff, `wave.py` called `pool.take(...)` and threw the bool away (PD9), so the second call's row launched regardless of what `take` found. Now that the take site acts on a refusal (Step 1), the second call's row is correctly refused: `Pool.take`'s `_refresh` (`asf/workers/pool.py:613-614`) re-derives `self.live` from the on-disk claims ledger every call, and `claim_rows` (`asf/workers/pool.py:292-295`) re-attaches *this process's own* claim from the first `run_wave` call — written by the first call's successful `take` and never released, because `runtime_mod.FakeRuntime` never calls `pool_mod.append_session`, so the claim never becomes a "registered" row that `claim_rows` would drop (`asf/workers/pool.py:287-291`). The second row's account then reads as already at cap and the row waits forever instead of launching — this is the intended Task 2 behavior (a same-pid claim must survive a pool rebuild, PD2) colliding with a test fixture that was only ever accidentally green. The fix belongs in `tests/test_cloud.py`, which is outside Task 3's `writes:` — `Lanes.run_wave` needs to release each launched row's claim before returning (e.g. `for row, rec in launched: pool.untake(accounts_by_name[rec['account']], rec['model'], job=row.job, product=self.product.name, kind=row.kind, lane=(rec.get('runtime_lane') if rec.get('runtime_lane') == 'cloud' else None))`), or the three tests need to share one `Pool`/one `run_wave` call across their two placements. Either way this needs a footprint decision an operator or the plan has to make before it can land, since the Task that could fix it writes to a file none of the four Tasks in this plan ever touches.
