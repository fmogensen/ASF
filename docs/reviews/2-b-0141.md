## Missed in round 1

**M1 — `asf/upgrade.py:505-508`: the refusal branch clears *another* operator's live pending
marker, because `wait.get('owner') == owner` is `None == None` for two operator waits.** An
operator's `asf upgrade --wait` writes `{'owner': None, 'pid': <its own>}` (`asf/upgrade.py:111-124`).
A second `asf upgrade --wait` that hits a refusal reads that marker, matches it on the
`owner is None` side of the predicate, and deletes it — even for a different sha, and even though
the first process is alive and still draining for it. Reproduced against a temp `ASF_HOME`,
process A holding `aaaaaaa`, process B refusing the moved red head `bbbbbbb`:

```
A marker sha: aaaaaaa owner: None
B out[0]: upgrade: no pending mark — remote CI is red at bbbbbbb; the other ticks run
A's marker (sha aaaaaaa) after B refused sha bbbbbbb: None
```

Every other product's ticks then resume underneath A, which is precisely the parking A's drain
exists to get. This is visible in round 1's diff, so by the round rule it is an I and not a C —
but it is a new destructive clear that the old code did not have, and it is the one I would fix
next. The fix is to make the operator case match on identity rather than on the shared `None`:

```python
mine = (wait.get('owner') == owner if owner is not None
        else wait.get('pid') == os.getpid())
if wait is not None and (mine or wait.get('sha') == ref):
    clear_pending()
```

with a test that a second operator wait's refusal leaves a live first one's marker alone. Narrow
(two concurrent `asf upgrade --wait` on one host), which is why it does not block.
