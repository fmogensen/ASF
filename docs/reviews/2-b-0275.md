### C2 — `asf/harvest/lane.py:2562-2579`: the new green read is not pinned to `exact_head(f)`, so it writes a green down for a sha the PR is not at

The gate makes this exact read and pins it, with the reason in the code:

```python

                                          head=exact_head(f), ...)

        # it, and a carry onto a sha the PR is not at would be a green for nothing
```

(`asf/harvest/lane.py:4927-4935`.) `exact_head(f)` (`lane.py:5108-5112`) is `None` when the PR's
`headRefOid` (`f['pr']['head']`, set at `lane.py:4329`) is a sha other than the branch head, and
`remember_green` returns early on a falsy head (`lane.py:4460-4470`, the guard at `:4465-4466`) — so the gate writes nothing
in that case, on purpose. `reword_held` passes the raw `f['head']` to both `pr_checks` (line 2573)

* `pr_graph.checks_for(slug, number, head)` answers `None` unless the snapshot's head *is* that

  attributed to the branch head;
* `remember_green` then writes `{head: <branch head>, tree: tree_at(repo, <branch head>), passed:
  …}` into `tree-green.json`, a green row for content that never ran those checks;
