**I3 — `asf/tick/file_bugs.py:200`: `_ITEM_ID_RE = re.compile(r'\b[A-Z]-[0-9]{4}\b')` only erases
ids in the canonical four-digit form, so a message whose specific is a *malformed* id splits one
defect into one class per bad reference — C1's failure mode for a different specific.** The
messages that interpolate a reference bare are `asf/record/check.py:230` (`parent {parent} does not
exist`), `:241` (`blockedBy references missing item {b}`) and `:245` (`stories references missing
item {s}`), and a missing reference is exactly the case where the id need not be well formed.
Verified:

```
>>> error_class('parent F-1 does not exist')                      'parent F-1 does not exist'
>>> error_class('parent F-2 does not exist')                      'parent F-2 does not exist'
>>> error_class('blockedBy references missing item T-99999')      'blockedBy references missing item T-99999'
>>> error_class('blockedBy references missing item T-88888')      'blockedBy references missing item T-88888'
```

Four bad references, four classes, four Bugs for one defect. Widening the pattern to the shape a
reference can take rather than the shape a valid id takes — `r'\b[A-Za-z]-[0-9]+\b'` — folds them
into one. (Round 1's I3 covered the neighbouring split, `does not match folder {folder}` and `has
wrong type {ptype}`, whose specifics come from a small fixed set; this one is unbounded.)

**I4 — `asf/tick/file_bugs.py:235`: `truncate(f"Record error: {klass}", 120)` cuts the longest real
class mid-sentence, and the shape it cuts is the explanation.** `asf/record/check.py:329`'s feature

truncating, rather than through it, would read better.
