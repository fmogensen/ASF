## I — would change, will not block

Round 3's I2, I3, I6 and I7 are all still open at this head; they were non-blocking then and are
non-blocking now, restated here with what this round added to them.

- **I1 — `asf/harvest/lane.py:1527-1530`: the `--subject` fallback is still silent** (round 3's
  I2, unchanged). When an old `gh` rejects the flag the merge is retried without it and the lane
  reports `landed` with no line saying the subject was dropped, so the trunk quietly carries a
  non-conforming subject and nobody can attribute it. The two protections are not symmetric: the
  merged-PR scan at `asf/evidence/evidence.py:986` checks the lane branch prefix, but the
  trunk-commit scan at `:973` skips only on `DOC_LANE_SUBJECT.match(subject)` **or**
  `docs_only(paths, dirs)`. A document lane that touched one path outside
  `specs_dir`/`plans_dir`/`reviews_dir`, merged by a `gh` too old for `--subject`, is back at the
  bug this card names. The trade against a silent stall is still the right one; one
  `lane.out(f'{b}: merged without --subject — this gh does not know the flag')` before the retry
  would make the degrade visible rather than inferred.
- **I2 — `asf/harvest/lane.py:1528`: the retry strips the subject by value, not by position.**
  `[a for a in args if a not in ('--subject', subject)]` also drops any *other* element of `args`
  that happens to equal `subject`. Nothing can collide today — the other elements are `pr`,
  `merge`, the PR number, `-R`, the slug, the method and `--delete-branch`, while `subject` is
  always `kind(item): … (#N)` — so this is latent, not live. `args[:-2]` inside the
  `method in SUBJECT_METHODS` branch says the same thing without depending on that argument.
- **I3 — `asf/harvest/lane.py:1297`: one of the four alternatives in `SUBJECT_UNKNOWN_RE` is
  dead** (round 3's I3, unchanged). `flag provided but not defined` is Go's stdlib `flag`
  package, which prints the flag single-dashed (`flag provided but not defined: -subject`), while
  `_rejects_subject` (`:1304`) additionally requires the literal `'--subject'` in the same text.
  `gh` is cobra/pflag and says `unknown flag: --subject`, which is what `tests/test_harvest.py:1613`
  feeds it, so nothing is wrong today; the alternative simply can never fire alongside the
  conjunct. Either drop it or relax the conjunct to `'subject' in err`.
- **I4 — `tests/test_hermetic.py:230,244`: two literal `'python3'` spawns, not `sys.executable`**
  (round 3's I6, and this round's commit made it the second site exactly as I6 predicted). CI runs
  a 3.12/3.13 matrix where `setup-python` puts the matrix interpreter first on `PATH`, so it
  resolves correctly there; under a venv whose `python3` differs from the interpreter running the
  suite, both children would silently probe the wrong one — and the C1 guard would then be
  proving hermeticity of an interpreter nobody is testing. The rest of `tests/` uses
  `sys.executable` in the modules that care. Two lines.
- **I5 — the gate's own invocations keep needing substitutes, and the reason changed this round.**
  `bash tools/check_conventions.sh` was refused outright in rounds 2 and 3; this round it ran
  literally and is `clean`, so that half is now better evidence than round 3 had. What replaced it
  is worse: `asf` on `PATH` resolves to a `~/.local/bin/asf` outside this checkout — a stale
  global install reporting
  `asf 0.1.0 (47c3e9d)` — a different commit from this checkout entirely. Run literally, the
  `asf --version` and `asf plugin check` steps would have gated **the wrong build**, silently. I
  used `python3 -m asf.cli` (the same entry point, resolved from the checkout) for both:
  `asf v0.1.7+73 (b1394c2)` and `plugin: up to date with the CLI`. The row is a pass on that
  evidence, but a reviewer who had not checked `which asf` would have recorded a green gate for a
  build that is not this branch. Worth an operator line.
- **I6 — `DOC_LANE_KINDS` absorbed one of the copies of the kind tuple, and there are more than
  round 3 counted** (round 3's I7, widened). Round 1's I5 asked for one shared constant;
  `asf/evidence/evidence.py:816` created it and `lane_kind` (`:826`) and `squash_subject`
  (`asf/harvest/lane.py:1325`) read it. But `('spec', 'plan')` is still spelled literally in
  **eight** places across **five** modules — `asf/evidence/evidence.py:502,513`,
  `asf/harvest/lane.py:264,619`, `asf/invariants.py:452,661`, `asf/record/ingest.py:98`,
  `asf/feeder/rows.py:355` — two of them in the very file that now owns the constant. Round 3 put
  this at three places in one file; it is not. The membership is identical at every site, so a
  third document kind would have to be added nine times. Not this card's job to fix all eight, but
  the two inside `asf/evidence/evidence.py` are free and finish round 1's I5 where it was filed.
