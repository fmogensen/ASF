## C — blocking

- `asf/evidence/sources.py:332`–`345` — `for_product`'s deploy dispatch never reads
  `deploy_sha.provider`, so the explicit opt-out the validator row exists to make possible does
  nothing. Reproduced:

  ```python
  >>> product = env.Product('t', {'repo_dir': '/tmp', 'deploy_sha': {'provider': 'none'}})
  >>> type(sources.for_product(product).deploy)
  <class 'asf.evidence.sources.WorkflowDeploy'>   # PD14 says this must be NoDeploy
  ```

  and, more consequentially, when a stale workflow key sits beside an explicit opt-out —
  `{'provider': 'none', 'prod': {'workflow': 'deploy-prod.yml'}}` — `for_product` still returns a
  live `WorkflowDeploy` that will call `host.runs(...)` for a product that said `none`. Fix
  `_deploy_configured` (or fold the check into `for_product` directly) to treat a normalized
  `provider == 'none'` as `NoDeploy` before falling back to "does a workflow exist", e.g.:

  ```python
  def _deploy_configured(product):
      d = product.deploy_sha
      if not isinstance(d, dict) or not d:
          return False
      if str(d.get('provider') or '').strip().lower() == 'none':
          return False
      return True
  ```

  No test in `ForProductTests`/`DeployTests` exercises `deploy_sha.provider` at all — the gap in
  coverage matches the gap in the code.
