## I list

- `asf/tick/tick.py:536-548` `_OFFLINE_MARKERS` is a second, narrower classifier for a network failure than the one this repo already has: `asf/workers/lifecycle.py:106` `NETWORK_RE` also matches `unable to access`, `connection (?:reset|refused|timed out|closed)`, `ssl_error`, `gnutls`, none of which are in the new tuple. A real record failure with one of those signatures (e.g. an SSL handshake drop, or `unable to access 'https://...'` with no DNS phrase in it) would print the raw git error instead of `"offline"`. Reusing `lifecycle.NETWORK_RE` would keep the two in sync.
- `asf/views/status.py`'s fallback path in `stale_cell` (the index's own age against twice the record clock's period, for "a dead cron, not just an offline host") has no test coverage — `RecordHealthStaleStatusTests` only exercises the `record_health` stamp path.
- `asf/tick/tick.py:tick_line()` (`:571-576`) doesn't carry `ctx.stale_reason` into the `metrics/ticks` JSONL line, so `asf watch`'s replay of a past tick (`asf/tick/watch.py:digest_lines`) — once the offline streak's lines do get pushed — reprints `"TICK — record FAILED"` without the STALE annotation the live tick and `asf status` both show. Only the live per-tick digest carries the line the card asks for.
