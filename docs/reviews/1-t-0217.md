## C list

- **C1** `asf/metrics/metrics.py:696-697` (`_ci_split`) and `:728` (`_red_split`) — `ci_waste_numbers`
  crashes with `TypeError: '<' not supported between instances of 'str' and 'NoneType'` when a
  `red` run's `jobs` list contains an entry with no `'name'` key, as long as any other job in the
  window does have a name. `totals[j.get('name')] += 1` at `:728` puts the dict key `None` into
  the `Counter` when `name` is absent; `sorted((k, v) for k, v in totals.items() if v)` at `:696`
  then has to compare that `None` against a string key and raises immediately (the two tuples'
  first elements differ, so Python never even reaches the count). This is not a far-fetched input:
  the function's own docstring (`:713-714`) says it "Read[s] with `.get` and a default throughout:
  the fourth source (`file_bugs.ci_target_signatures`) hands this function unvalidated lines" —
  i.e. this Task's own contract is that a malformed `jobs` entry costs its contribution, not a
  crash, exactly the failure mode P7 (`docs/plans/f-0043.md:33`) says this function exists to
  avoid. Repro (ran against this head):
  ```python
  from asf.metrics import metrics
  ci = [{'minutes': 1, 'jobs': [{'conclusion': 'failure'}]},
        {'minutes': 1, 'jobs': [{'name': 'e2e', 'conclusion': 'failure'}]}]
  metrics.ci_waste_numbers(ci)
  # TypeError: '<' not supported between instances of 'str' and 'NoneType'
  ```
  Fix: default the missing name the same way the existing `byjob`/`bycause` readers already
  default a missing `failed_step` (`asf/metrics/metrics.py:855`, `(j.get('failed_step') or '?')`)
  — change `:728` to `totals[j.get('name') or '?'] += 1`.
