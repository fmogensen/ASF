**C1 — `tests/test_ci_pool.py:344-347` imports a third-party module this project does not
depend on, and it is red on the PR's own required checks because of it.**

```
        import yaml
        with open('.github/workflows/tests.yml', encoding='utf-8') as f:
            doc = yaml.safe_load(f)
        self.assertEqual(doc['jobs']['tests']['strategy'].get('fail-fast'), False)
```

`pyproject.toml:2,16` — "Python 3 stdlib only — no dependencies" / `dependencies = []` — and the
CI install (`.github/workflows/tests.yml:29-32`, `pipx install --python "$(which python)" .`)
installs exactly that: no PyYAML. On this exact head, both required jobs fail with
`ModuleNotFoundError: No module named 'yaml'` at this line
(`gh api repos/fmogensen/ASF/actions/runs/37847079797`, jobs `113550504939` "tests (3.13)" and
`113550505164` "tests (3.12)", both `completed`/`failure`, ending `red: test_ci_pool`). This file
already imports the project's own stdlib-only reader for this exact purpose —
`tests/test_ci_pool.py:11`: `from asf import capacity, ci_census, ci_pool, env` — and every other
test in this suite that parses `.github/workflows/tests.yml` uses it instead of PyYAML
(`tests/test_workflow.py:17-18`: `self.data = env.loads(self.text)`; similarly
`tests/test_ci_class.py:84`, `tests/test_hermetic.py:236`, `tests/test_install.py:208`,
`tests/test_release.py:218`).

Fix: use the already-imported `env.loads` instead of `yaml.safe_load`:

```

```

Verified locally that this reads the fixed file correctly: `env.loads(open('.github/workflows/tests.yml').read())['jobs']['tests']['strategy'].get('fail-fast')` → `False`. No other change is
