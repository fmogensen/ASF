## I list

- `asf/workers/health.py:965-973` with `asf/workers/lifecycle.py:3229-3233` — the other half of the
  loop the card describes is still open, one step further along. A review run judged
  `failed: empty branch: nothing to land` — a judgement the diff makes reachable for an *unpushed*
  review too, at `lifecycle.py:2569-2571`, where before it needed a pushed one — falls through
  every earlier arm of that `elif` chain and is held with `lifecycle.empty_branch_text()`:
  *"empty branch: nothing to land — commit and push what you have, or say why not in the report"*.
  That is word for word the instruction B-0276's own Description calls the defect — a correction
  "telling it to commit what its brief forbids" — and a review that obeys it moves the PR head and
  restarts the PR's CI, the exact harm `OFF_BRANCH_KINDS` exists to prevent. The machinery for the
  right answer is already there and simply does not list this kind:
  `lifecycle.delivered_off_branch` (`lifecycle.py:3068-3100`) gives `adjudicate` and `correct` their
  own off-branch deliverable, and `review` is in neither arm. The fix is one of two one-liners —
  add a `review` arm to `delivered_off_branch` keyed on the verdict block, or give
  `lifecycle.hold(..., lifecycle.EMPTY, ...)` a review-specific text ("write the review at
  `docs/reviews/<n>-<item>.md` and leave it uncommitted; do not push"). Half pre-existing, narrow in
  reach (it needs a review with no commits *and* no filed review, i.e. one that wrote nothing), so
  it is not worth holding an S1 fix for — but it is the next card.
- `asf/workers/health.py:473-490` — `lands()` going False does not keep a review out of
  `publish_gap`. `result_ok` there is true for `reason == lifecycle.FINISHED`, which is now exactly
  what a healthy review is judged, so a finished review still enters, and any uncommitted leftover
  in its worktree is committed by `lifecycle.commit_leftovers` and pushed to the branch. This is
  not a regression — before the diff the same run arrived with `failed: not pushed: …`, which
  matches `UNPUSHED_REASON_PREFIXES` and entered identically — and in practice `file_review`
  (`health.py:442-464`) empties the worktree first, so `ev.unpushed` is 0 and it returns at
  `health.py:488` having done nothing. It is still the one remaining path by which the factory
  itself can move a reviewed PR's head, and it is worth closing in the same card as the one above.
- `asf/evidence/review_store.py:196-208` with `asf/workers/cloud.py:658` — a cloud review lane files
  no review at all. `catch_up` fast-forwards the run's host worktree to `origin/<branch>` as soon as
  the run stops being `working`, so by the time `review_store.take` runs, `head == remote_sha` and
  the "commits above `remote_sha` that touch nothing but the reviews directory" arm at `:196` is
  skipped; the untracked-file arm at `:209` then finds nothing, because a cloud session's brief
  tells it to commit the review. `review_filed` is never set, and the run is saved from the
  `empty branch` judgement only by `ev.has_commits`. Outside this diff, but directly next to it, and
  it is why a cloud review round leaves no entry in the review store.
- `asf/workers/lifecycle.py:2569` — the condition mixes `run.get('branch')` with
  `(run or {}).get('kind')` in one expression; if `run` could be `None` the first call has already
  raised. `run.get('kind')`, as the line two above it writes it, says what is meant.
- `asf/workers/lifecycle.py:2543` — `judge`'s docstring still opens "A result that says ok is
