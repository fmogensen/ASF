## I — would change, will not block

- **I1 — `asf/harvest/lane.py:1467`: the merge-queue path names no subject.** `has_queue()` takes
  `gh pr merge --auto` and never passes `subject`, so a product with a merge queue still lands its
  doc lanes under whatever subject the queue composes. It is safe today only because a plan lane's
  diff is docs-only and `docs_only` (`asf/evidence/evidence.py:805`) catches it by paths; a doc
  lane that ever touches one non-document path on a queue repo is back at the bug this card names.
  Worth a line in the docstring saying the queue's subject is the queue's, or passing `--subject`
  alongside `--auto` and letting the queue ignore it.
- **I2 — `asf/harvest/lane.py:1280`: it takes the branch's *newest* subject, not its newest
  conforming one.** A doc lane whose first commit is `plan(F-0047): the plan` and whose last is
  `docs: address review` lands as `plan(F-0047): docs: address review (#41)` — correct, since the
  prefix is added, but it buries the subject the lane actually wrote. Preferring the newest subject
  that already matches `DOC_LANE_SUBJECT`, and only prefixing when none does, reads better on the
  trunk for the same cost.
- **I3 — `asf/harvest/lane.py:1471-1479`: no fallback if `gh` rejects `--subject`.** The retry loop
  advances to the next method only on `not allowed`; a `gh` old enough to call `--subject` an
  unknown flag returns `(None, tail(err))` and the doc lane simply stops merging, with no hint that
  one flag is the cause. Low odds (`gh pr merge --subject` is long-standing), but the failure mode
  is a silent stall rather than a degraded merge.
- **I4 — the suite is not hermetic on this machine, at any commit.** Every one of the 40 failures
  is hook- or home-shaped, and the detail names the operator's real home:
  `NEEDS OPERATOR: ~/.ASF/state/asf/githooks/pre-commit is not asf's` (the home spelled in full in
  the run's output, redacted here) from
  `tests/test_install.py:622`, though `tests/test_00_home.py:14 hermetic_home` is supposed to have
  pinned `ASF_HOME` to a temp directory. Unsetting `ASF_PRODUCT`, `ASF_JOB`, `ASF_SESSION` and
  `ASF_HOME` changes nothing, and `git config --global --get core.hooksPath` is unset, so the leak
  is inside the resolution, not the caller's environment. It reproduces identically at
  `origin/main`, so it belongs to a card of its own, not to B-0114 — but until it is filed, no
  session on this host can show a green `tools/run_tests.py`.
- **I5 — `asf/harvest/lane.py:1275` duplicates the kind tuple.** `('spec', 'plan')` here and
  `("spec", "plan")` in `asf/evidence/evidence.py:819 lane_kind` have to agree; a third document
  lane would have to be added twice. One shared constant would make the two halves of this fix
  drift-proof.
