## I (non-blocking)

- The plan's step 4 describes `prior` as "the number of `stalls` recorded for the same
  `(branch, sha)` across the `relief` records and the `stalls` history." The landed code counts
  only from `data['stalls']` (`ci_queue.py:1505-1507`), never scanning `data['relief']`. This is
  not a bug — every successful cancel appends to `data['stalls']` unconditionally and
  synchronously, before the cap check, so by the time a second stall on the same `(branch, sha)`
  is evaluated (same pass or a later one) the first is already counted, and `ReRunTests` exercises
  exactly this (`test_the_cap_is_counted_per_branch_and_sha_not_per_run`,
  `test_the_third_stall_on_one_sha_is_cancelled_and_not_re_run`) and is green. Worth a one-line
  note in the docstring or a future spec pass reconciling the wording with the simpler
  implementation, so a later reader does not go looking for a `data['relief']` scan that was never
  needed.
