## Context

`fix/B-0016` reached adjudication as a reviewer/fixer stalemate after three holds, but there is no
dispute on the record to settle: `docs/reviews/1-b-0016.md`, `docs/specs/b-0016.md` and
`docs/plans/b-0016.md` have never existed on any ref — `git log --all --oneline --` over all three
returns nothing — so no reviewer ever returned a change and no fixer ever answered one. The hold
reason was `conflict`, and it is mechanical: the `-s ours` merge `59e8ebf`, which a previous ruling
made to get the branch pushed without forcing, pulled the superseded pre-`lifecycle` variant of the
fix (`6fcb8df`) into `origin/main..HEAD`. Harvest flattens merges when it rebases, so it replays
that variant on top of the current one and conflicts in `asf/workers/spawn.py` — the same hold,
three times.

## Decision

**Open review findings: none — none upheld, none overruled, because none was ever written.** Any
finding raised against round 1 after this card is out of time: it does not reopen this loop and
must be filed as its own item against `main`.

**The fix itself stands as committed. No edit to it.** Checked against the checkout rather than
either party's claim: `make_worktree` (`asf/workers/spawn.py:164-215`) runs its entire `add`
closure — fetch, takeover, held-branch reuse, reaped-branch remake, fresh branch — inside
`_with_repo_lock` (`asf/workers/spawn.py:143-161`), which takes an exclusive `fcntl.flock` on the
per-repo `.git/asf-worktree.lock` (`_repo_lock_path`, `asf/workers/spawn.py:139-140`) and retries
the closure once when the error names `lock config file`. That is exactly the "serialise worktree
creation per repo (a lock dir or a per-repo mutex) and retry once" the item asks for.
`tests/test_workers.py:332` drives eight concurrent `make_worktree` calls against one repo and
asserts all eight land; `tests/test_workers.py:350` pins the retry over a half-made worktree. Both
pass: `python3 -m unittest tests.test_workers` → `Ran 57 tests … OK`.

**The prior rulings' substance is affirmed; the prior ruling's *remedy* is overruled.** `f8bfe5b`
and `4289238` were right that there is nothing to answer and that the lock is what the item asked
for. But the `-s ours` merge they leaned on to make the push a fast-forward is itself the defect
that now holds the branch, and it is overruled as a remedy: a merge that carries a superseded
variant into a branch's history makes that branch un-harvestable, because harvest does not preserve
merges. Verified, not assumed — merging `origin/main` into the branch is clean, and
`git rebase origin/main` afterwards *still* stops at `Could not apply 6fcb8df…` with
`UU asf/workers/spawn.py`. Being up to date with the trunk does not save it; only removing
`6fcb8df` from the history does.

**The branch must be rebuilt without `6fcb8df`, and that is an operator action.** Cherry-picking
the three real commits (`4690ba0`, `f8bfe5b`, `4289238`) onto `origin/main` applies with no
conflict, leaves `asf/workers/spawn.py` and `tests/test_workers.py` byte-identical to what the
branch already holds, and makes `git rebase origin/main` report `HEAD is up to date.` — harvest
then has nothing to replay. The rebuilt history is not a descendant of `origin/fix/B-0016`, so
publishing it needs `--force-with-lease`, which the standing rules forbid a session. It is prepared
on the local branch `fix/B-0016-clean` and handed over; see the NEEDS OPERATOR line in this
session's report.

## Consequences

- `fix/B-0016` leaves review. No further review round is opened for it, and a reviewer returning
  changes on round 1 is to be refused by reference to this card.
- The `conflict` hold is not a defect in the fix and must stop being routed as one. Until the
  branch's history is rebuilt, every harvest of it holds at `conflict in asf/workers/spawn.py`
  (`asf/harvest/harvest.py:290-292`) no matter what any session does to the working tree.
- **`-s ours` is not a way out of a non-fast-forward push.** It buys the push and sells the
  harvest, because `rebase_and_resolve` (`asf/harvest/harvest.py:285`) runs a plain
  `git rebase origin/<trunk>` that drops merges and replays both sides. A branch that has diverged
  is an operator matter, not something a session should merge its way around.
- The asymmetry behind all of this is now recorded twice. Harvest may `--force-with-lease` a worker
  branch (`asf/harvest/harvest.py:346`) and lands from the **local** ref
  (`asf/harvest/harvest.py:375`), while a session may not force its own; a session that rewrites
  its local ref to escape the trap must then report `pushed: no` and is failed for it. D-8050 left
  this standing for the operator on `fix/B-0053`; B-0016 is the second branch it has trapped.
- `6fcb8df`'s tree is deliberately not in the result. Anyone reading `asf/workers/spawn.py` history
  should take `4690ba0` as the fix; `6fcb8df` is the same fix written before `lifecycle.py` landed,
  and is superseded, not lost.
- `BACKLOG_ID_RANGE` hands worker sessions `S`, `T` and `B` bands only, so an adjudication that must
  mint a decision id has no allocation. This card takes `D-7850` from the head of this session's
  band (`7850-7899`), matching how `D-7800` and `D-8050` were minted, and the gap goes to the
  operator rather than being left unminted as `4289238` left it.
