## Context

`fix/B-0016` came back to adjudication as a reviewer/fixer stalemate "held 3 times (conflict)",
after [D-7850](D-7850.md) and [D-7851](D-7851.md) had each ruled that there is no open finding and
that the hold comes from the branch's history, not from any review dispute. The session found the
same things D-7851 described: no review file on any ref, and the worktree left mid-`rebase` onto
`895539c` with `asf/workers/spawn.py` conflicted. This is the third stray rebase this item has left
behind, and it came from replaying the superseded `6fcb8df` after `4690ba0`.

## Decision

**Open review findings: none — none upheld, none overruled.** Checked, not inherited:
`git log --all --oneline -- docs/reviews/1-b-0016.md` returns nothing. The round-1 review this
session was told to answer has never existed. D-7851 already closed that round, and this card
confirms it. A finding raised after this card is a new item against `main`, never a reopening of
this loop.

**The fix stands as committed. No edit to it.** Anchors re-checked against this checkout:
- `_repo_lock_path` is at `asf/workers/spawn.py:139`.
- `_with_repo_lock` (`:143-161`) takes an exclusive `fcntl.flock` (`:152`) and retries once only on
  `lock config file` (`:157`).
- `make_worktree` (`:164`) sends its whole `add` path through that lock (`:215`).
- `tests/test_workers.py:332` (eight concurrent adds) and `:350` (a retry over a half-made worktree)
  pin the fix.

Result: `env -u ASF_PRODUCT -u ASF_JOB -u BACKLOG_ID_RANGE python3 -m unittest tests.test_workers`
→ `Ran 57 tests … OK`.

**The conflict is not in the tree. It is in the history, and no fast-forward commit can remove
it.** `git merge-tree --write-tree origin/main origin/fix/B-0016` exits 0, so the branch merges
cleanly. The conflict appears only when the branch is rebased. Harvest runs a plain
`git rebase origin/{trunk}` (`asf/harvest/harvest.py:285`) and aborts on any conflict it does not
own (`:290-292`). A plain rebase drops the merge `59e8ebf` and replays both of its parents' commits.
From any descendant of `59e8ebf`, it replays `6fcb8df` on top of `4690ba0`, and those two collide in
`spawn.py`. So no commit a session is allowed to push can clear the hold. The only fix is the
rebuild in D-7851, which ends in `--force-with-lease`, and sessions may not run that.

**D-7850 and D-7851 are affirmed in full.** D-7851's handover formula still applies unchanged. It
reads origin refs only, and `--first-parent --no-merges` now also picks up this card's commit:

```sh
git fetch origin
git checkout -B fix/B-0016-clean origin/main
git cherry-pick $(git rev-list --reverse --first-parent --no-merges origin/main..origin/fix/B-0016)
git push --force-with-lease origin fix/B-0016-clean:fix/B-0016
```

## Consequences

- B-0016 is **blocked on the operator**, not in review. No review or adjudication round on
  `fix/B-0016` follows this card, and a later `conflict` hold on it is answered by pointing to this
  card, not by starting another session.
- Until the rebuild runs, every harvest holds at `conflict in asf/workers/spawn.py`. Five sessions
  have now spent a cycle each re-deriving the same answer. The defect is in the routing: a
  `conflict` hold that repeats on the same file and the same sha pair is sent to "adjudicate",
  which cannot resolve it. That fix lives outside this branch's footprint and is left to the
  operator (see the session report).
- No commit on this branch changes the fix. This card is the only file it adds.
- `BACKLOG_ID_RANGE` still gives adjudication only `S`, `T` and `B` bands (`7850-7899`). As with
  D-7850 and D-7851, this card takes the next free id in the matching `D` band. The missing `D`
  allocation is the operator's to close.
