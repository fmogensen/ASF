## Context

`fix/B-0016` was routed to adjudication a fourth time, as a reviewer/fixer stalemate held three
times on `conflict`, after [D-7850](D-7850.md) had already closed the loop with no finding. There is
still no dispute on the record to settle — `docs/reviews/1-b-0016.md`, `docs/specs/b-0016.md` and
`docs/plans/b-0016.md` have never existed on any ref — and the re-route arrived with the worktree
left mid-`rebase`, replaying the superseded `6fcb8df` over the current fix with four conflicted
hunks in `asf/workers/spawn.py`: the second such stray rebase this item has produced, and the
proof that D-7850's diagnosis was not a prediction but a recurrence.

## Decision

**Open review findings: none — none upheld, none overruled, because none was ever written.**
Verified here rather than inherited: `git log --all --oneline --diff-filter=A` over all three paths
returns nothing. Round 1 is out of time permanently. A finding raised against it after this card
does not reopen this loop and must be filed as its own item against `main`.

**The fix stands as committed. No edit to it.** Every anchor checked against this checkout, not
against either party's claim: `_repo_lock_path` (`asf/workers/spawn.py:139-140`) names the per-repo
`.git/asf-worktree.lock`; `_with_repo_lock` (`asf/workers/spawn.py:143-161`) takes an exclusive
`fcntl.flock` on it and retries the closure once when the error names `lock config file`;
`make_worktree` (`asf/workers/spawn.py:164-215`) passes its entire `add` closure — fetch, takeover,
held-branch reuse, reaped-branch remake, fresh branch — through that lock at line 215. That is the
"serialise worktree creation per repo (a lock dir or a per-repo mutex) and retry once" the item
asks for. `tests/test_workers.py:332` drives eight concurrent `make_worktree` calls against one
repo; `tests/test_workers.py:350` pins the retry over a half-made worktree. Both pass:
`env -u ASF_PRODUCT -u ASF_JOB -u BACKLOG_ID_RANGE python3 -m unittest tests.test_workers` →
`Ran 57 tests in 15.488s … OK`.

**D-7850's substance is affirmed in full. Nothing in it is overruled.** The `-s ours` merge
`59e8ebf` is the blocker; `6fcb8df` is superseded, not lost; the branch must be rebuilt without it;
that rebuild needs `--force-with-lease` and is an operator action.

**What is overruled is the *form* of D-7850's handover.** It parked its remedy on the local branch
`fix/B-0016-clean`, inside a single disposable worktree, visible to no one who could act on it —
which is why nothing happened and the item came back. A remedy that exists only as local state in a
worktree is not a handover. It is replaced by a formula over origin refs, which depends on no local
branch and stays correct as the branch grows:

```sh
git fetch origin
git checkout -B fix/B-0016-clean origin/main
git cherry-pick $(git rev-list --reverse --first-parent --no-merges origin/main..origin/fix/B-0016)
git push --force-with-lease origin fix/B-0016-clean:fix/B-0016
```

`--first-parent --no-merges` is what drops `6fcb8df`: it is reachable only as `59e8ebf`'s second
parent, so excluding merges from the first-parent chain leaves exactly the real commits and nothing
else. Run end to end after this card was committed, not reasoned about: the five commits
(`4690ba0`, `f8bfe5b`, `4289238`, `10604dc`, `8dfcb3e`) cherry-pick onto `895539c` with no
conflict; `git diff origin/fix/B-0016 <rebuilt> --` over `asf/workers/spawn.py`,
`tests/test_workers.py`, `docs/reviews/1-b-0016-ruling.md`, `docs/decisions/D-7850.md` and
`docs/decisions/D-7851.md` is empty; `git rebase origin/main` on the result reports
`Current branch … is up to date.`, so harvest has nothing to replay; and the rebuilt branch carries
the gate on current trunk —
`env -u ASF_PRODUCT -u ASF_JOB -u BACKLOG_ID_RANGE python3 -m unittest discover -s tests` →
`Ran 809 tests in 261.175s … OK (skipped=13)`. The operator's push is pre-gated; `fix/B-0016-clean`
now points at that verified commit.

**Adjudication is refused for this item from here.** Three rulings and this session have each
reached the same answer; a fifth cannot reach a different one, because the blocker is in the
branch's history and the only remedy is a command sessions are forbidden to run. B-0016 is not in
review and is not disputed — it is **blocked on the operator**, and must be routed as that until
the command above has run.

## Consequences

- No further review or adjudication round is opened on `fix/B-0016`. A `conflict` hold on it is
  refused by reference to this card, not answered with another session.
- Until the rebuild runs, every harvest of the branch holds at `conflict in asf/workers/spawn.py`
  (`asf/harvest/harvest.py:290-292`) no matter what any session does to the working tree — and
  leaves a conflicted worktree behind it, which is a hazard for whatever session lands there next.
  Two such stray rebases have now been aborted by adjudication sessions that had nothing else to
  fix.
- **Routing a hold whose cause is the branch's history to adjudicate is itself a defect**, and it
  is not B-0016's. It burns a session per cycle on a question no session may answer. It wants its
  own item; the operator's recommendation is in this session's report rather than minted here,
  because the routing lives outside this branch's footprint.
- The handover form generalises: a session that cannot publish a remedy must hand over a command
  that runs from origin refs, never a local branch. `fix/B-0016-clean` is left in place as a
  convenience, but nothing depends on it existing.
- `-s ours` remains what D-7850 made it: not a way out of a non-fast-forward push. It buys the push
  and sells the harvest.
- `BACKLOG_ID_RANGE` hands this session `S`, `T` and `B` bands only, so an adjudication minting a
  decision id has no allocation. This card takes `D-7851`, the next free id after D-7850 in the same
  band (`7850-7899`), matching how `D-7800`, `D-7850` and `D-8050` were minted. The gap is the
  operator's to close.
