## Context

`fix/B-0016` came to adjudication an eighth time as "held 3 times (conflict)". As before, no review
file exists on any ref. The worktree was stopped mid-rebase onto `6517bb2`, with
`asf/workers/spawn.py` conflicted, because trunk commit `6517bb2` (B-0056) rewrote the same
`make_worktree` body that the fix wraps in its lock. Trunk `6517bb2` also changed the rules
[D-7853](D-7853.md) and [D-7854](D-7854.md) relied on. Harvest now refuses a merge commit on a lane
branch, and the factory itself publishes a branch that a session rebased (`lifecycle.publish`,
`--force-with-lease`). The branch carried the `-s ours` merge `59e8ebf`.

## Decision

**Open review findings: none. None upheld, none overruled.** I checked this in the checkout:
`git log --all --oneline -- docs/reviews/1-b-0016.md docs/specs/b-0016.md` returns nothing. A
finding raised against round 1 after this card is out of time. It is a new item against `main` and
never reopens this loop. Every earlier overruling ([D-7850](D-7850.md), the retry's "known limit")
stands and does not come back.

**The fix stands, carried onto the new trunk with both sides kept.** The conflict was resolved
this way: the fix's `add()` closure runs under `_with_repo_lock`
(`asf/workers/spawn.py:143-161`, `:213`), and both of its rebase sites now call the trunk's
`_rebase_onto_trunk` (`:189`, `:197`, defined at `:216`) in place of the bare `git rebase` the
fix was written against. The lock serialises the per-repo worktree creation that B-0016 asks for.
The factory's B-0056 publish now also runs inside that lock.

**The remedy changes. D-7853's and D-7854's `git merge --no-ff` handover is superseded.** Under
`6517bb2`, a merge is the thing that gets a branch refused, and the trunk now touches `spawn.py`.
The branch was finished as a linear rebase:
- `4690ba0` is replayed as `1ff0979`, with the conflict resolved as described above;
- the superseded pre-`lifecycle` variant `6fcb8df` is dropped rather than replayed (per D-7850);
- `59e8ebf` falls out, as a rebase flattens it, so `git log --merges origin/main..fix/B-0016` is
  empty;
- the ruling commits are replayed unchanged on top.

This leaves nothing for the operator to merge by hand. The session's plain push is refused as
non-fast-forward, which is expected. B-0056's rule for that case is that the factory publishes a
clean, ok run with `--force-with-lease` (`asf/workers/health.py`, `publish_gap`). After that,
harvest lands the branch like any other.

**Gate.** The full suite, with the caller's identity unset, is recorded in the commit that files
this card. `tests/test_workers.py:335` (eight concurrent adds all land) and `:353` (the retry runs
the add path again over a half-made worktree) pass.

## Consequences

- B-0016 is no longer blocked on the operator. It waits on the factory's publish of the rebased
  head, and then on harvest.
- No later adjudication of `fix/B-0016` is warranted. If this branch is held again, the cause is
  a new trunk change. That goes to a correction session, which rebases, not to a ninth ruling.
- The spawn-side defect that D-7854 named (a plain rebase that flattens merges and cannot be
  published) is closed by B-0056 on the trunk, not here.
- The session's worktree `worktrees/fix-bug-b-0016` was removed while this session was still live
  and running the suite. The rebased branch ref survived, and the ruling was finished in a private
  worktree. Something reaped a live session's worktree. That is outside this footprint, and it is
  reported to the operator.
- The `D` band is still missing from `BACKLOG_ID_RANGE`. This id is the next free one in the
  `7850` block, as with D-7850 to D-7854.
