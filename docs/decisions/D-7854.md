## Decision

**Open review findings: none. None upheld, none overruled.** I checked this in the checkout
myself: `git log --all --oneline --diff-filter=A -- docs/reviews/1-b-0016.md docs/specs/b-0016.md
docs/plans/b-0016.md` returns nothing. The round-1 review has never existed, so there is no
reviewer reading or fixer reading to choose between. A finding raised against round 1 after this
card is out of time. It is a new item against `main` and never reopens this loop.

**The fix stands as committed, with no edit.** Anchors re-read at `e01397b`:
- `_repo_lock_path`, `asf/workers/spawn.py:139-140`: one `.git/asf-worktree.lock` per repo.
- `_with_repo_lock`, `:143-161`: an exclusive `fcntl.flock` at `:152`, one retry only when the
  error names `lock config file` (`:157-159`), and an unlock in `finally` at `:161`.
- `make_worktree` sends its whole `add` closure through that lock at `:215`.
- Two tests pin it: `tests/test_workers.py:332` (concurrent adds all succeed) and `:350` (the
  retry runs the add path again over a half-made worktree).

**D-7853's remedy is re-verified against the current trunk, and it holds.** `origin/main` has
moved from `b0a50d2` to `cc168ab`. None of the new commits touch `asf/workers/spawn.py`,
`tests/test_workers.py` or `asf/harvest/harvest.py`.

```sh
git merge-tree --write-tree origin/main origin/fix/B-0016  # exit 0 -> 647c0fa
git rev-parse 647c0fa:asf/workers/spawn.py                 # 44ee4df  = branch tip
git rev-parse 6fcb8df:asf/workers/spawn.py                 # 69b7fb3  (superseded, not present)
```

The operator's step is unchanged:
`git fetch origin && git checkout main && git merge --no-ff origin/fix/B-0016 && git push origin main`.

**What is new: where the stray rebase comes from.** D-7851 through D-7853 each found the worktree
mid-rebase and aborted it as leftover debris. It is not debris. Spawn produces it on purpose:
`make_worktree` rebases a branch that is already on origin onto `origin/<main>` and leaves any
conflict in place for the session (`spawn.py:198-199`, and `:189` for a reused worktree, per
B-0025/B-0046). A plain rebase drops the `-s ours` merge `59e8ebf` and replays both variants of
the fix, so every session on this branch starts inside the same conflict that harvest reports as
`conflict in asf/workers/spawn.py` (`asf/harvest/harvest.py:285`, `:292`). The routing, the hold
and the worktree state are one defect seen three times. Adjudication cannot clear it, and neither
can a session, because the only in-branch cure is a history rewrite, and a force-push is not a
session's to make.

## Consequences

- B-0016 stays **blocked on the operator for one merge**. D-7853's command still applies at
  `cc168ab`. A later `conflict` hold on `fix/B-0016` is answered by pointing at this card, not by
  an eighth session.
- The stray rebase was aborted again, so the branch is level with origin. It will come back on the
  next spawn onto this branch, for the reason above. The next session should expect it and abort
  it without investigating.
- The defect lives outside this footprint, in two places: harvest's plain `git rebase`
  (`harvest.py:285`) and spawn's same rebase on relaunch (`spawn.py:189`, `:198`). Both flatten
  merges, so any branch that carries a merge commit is unharvestable and is re-dispatched into an
  unresolvable conflict. The cure is `--rebase-merges`, or falling back to a merge when
  `git merge-tree` exits 0. That needs its own bug, and it is not changed here.
- No code changes. This card and a pointer in `docs/reviews/1-b-0016-ruling.md` are the only
  files touched.
- The id is the next free one in the `D-7850` band, as with D-7850 to D-7853. The missing
  `D`-band allocation in `BACKLOG_ID_RANGE` is still the operator's to close.
