# Plan F-0138 — three Tasks, three waves: the kind and its window's dollars, then every window projected at that scale, then the reset credit over the run's own span

Epic: E-0002 — ASF 0.2 — self-improvement. Spec: `docs/specs/f-0138.md` (approved). Branch:
`plan/F-0138`.

**Three Tasks, three waves — strictly serial.** The spec's three Stories are three layers of one
arithmetic, and each needs the one below it in the tree, not beside it. Task 2's per-window loop
calls the `share(kind, model, provider, window)` Task 1 builds; Task 3's reset credit is a factor
inside the very expression Task 2 writes. There is no honest parallel cut: Tasks 1 and 3 both edit
`asf/workers/headroom.py`, Tasks 1, 2 and 3 all edit `asf/workers/pool.py`, and all three edit
`tests/test_quota_provider.py`. The `writes:` sets therefore intersect by construction and the
queue is accepted rather than worked around — a Task 2 that landed beside Task 1 would be a
per-window loop over a `share` that does not exist yet.

| wave | Task | after | what lands |

| 1 | Task 1 | none | the provider kind on the account, and a window's dollars read and learned per kind |
| 2 | Task 2 | Task 1 | every readable window projected at that account's scale, the binding one naming itself |
| 3 | Task 3 | Task 2 | a reset inside the run's span credited, and the span taken from history |

Wave order: **1** → **2** → **3**. Verified through the record's own reader,

### PD3 — the printed `committed` keeps the running allowance inside it

The spec's `## The design` §3 gives the arithmetic as:

```python
committed = sum(share(k, m, provider, w) for (k, m) in self._taken[account.name])
total = p + round(committed + running * self.costs.allowance, 1) + c * held
```

and then prints `f'+{committed:g}% committed'`. **That reddens `:145`.** In
`test_running_sessions_hold_an_allowance` the account has *four live sessions and zero taken
launches*, and the pinned string is:

```
headroom: a would exceed 65% (now 40%, +20% committed, +10% this launch)
```

The `20` is `4 × 10 × 0.5` — the running allowance alone. Today's code prints one number that is
both, `round(self._committed.get(name, 0.0) + running * self.costs.allowance, 1)`
(`asf/workers/pool.py:390-391`), and the operator has read that number for weeks as "what this
account is already spoken for". Printing only the taken sum would make it `+0% committed` and
break P11 and D4 — the two decisions this card is most careful about.

**What holds:** the name in the message is the combined, rounded figure. Keep the spec's own
variable for the list sum, and print the sum of both:

```python
taken = sum(shares for the (kind, model) pairs in self._taken[account.name])
committed = round(taken + running * self.costs.allowance, 1)   # the number the line prints
total = p + committed + c * held
```

With `held == 1` and no reset this is byte-identical to today for `five_h`, which is the whole of
P11. Do not reorder the rounding: today's `round(...)` wraps the *sum* of the taken commitment and
the allowance, and rounding the two separately moves the last digit on a real wave.

### PD4 — `over`'s overshoot needs the binding window's stop, and the public triple does not carry it

D5 makes `over` carry `(projected − guard, why, projected)`. But `projected` is the *binding
window's* projection, and the binding window may be `seven_d` with its own stop, while the three
call sites only have `self.guards['stop']['five_h']` to subtract. Computing `total − guard_5h` for
a `seven_d` miss is not an overshoot of anything: with a `seven_d` reading of 92 against a stop of
95 and a 5h stop of 65, it is `+27`, and D5's whole point is that the number must be comparable
across accounts and windows.

The spec also fixes `headroom`'s signature — "same name, same signature, same triple" — and
`tests/test_quota_headroom.py:396` unpacks exactly three values. So the overshoot cannot simply be
appended to the return.

**What holds:** `headroom` keeps its public three-tuple and delegates. Add one private method that
returns what the callers need, and make the public one a wrapper:

```python
def _headroom_over(self, account, kind, model):
    """``(fits, why, projected, overshoot)`` — :meth:`headroom` plus ``projected − stop`` for the
    window that bound, the figure ``pick_account`` orders its misses by (F-0138 D5)."""

def headroom(self, account, kind, model):
    fits, why, projected, _over = self._headroom_over(account, kind, model)
    return fits, why, projected
```

`overshoot` is `0.0` when it fits. Three call sites move together, and they are all of them:
`pick_cloud_account` (`asf/workers/pool.py:436`, `:438`, `:448`), `pick_account` (`:491`, `:493`,
`:513-514`) and `full_reason` — whose **docstring at `:535` names the old shape** ("``over`` is the
headroom misses as ``(projected, why)``") and must be corrected to the triple in the same edit.
`min(over)[1]` stays `min(over)[1]` on all three. With equal guards the ordering is identical to
today's (D5), which is why `TestPlacement` and `TestTheRealLimiterIsNamed` stay green.

### PD5 — `estimate` must keep filling `shares` and `source`

§2 says `estimate` "now records medians in **dollars and minutes** … rather than baking one scale

### PD6 — a derived long-window share is rounded to one decimal and never clamped to 1

`estimate` floors a learned share at one point: `max(1, _num(round(pct * 2) / 2))`
(`asf/workers/headroom.py:248`). That floor is a *5h* floor. Applied to the derived long-window
share it is wrong by more than 3×: a spec's `seven_d` share is `10 / 33.6 = 0.2976`, and clamping
it to `1` charges the weekly window three and a half times what the run spends. Left unrounded it
is just as bad in the other direction, because it reaches the operator's wait line through `:g`:

```
headroom: acct-a seven_d would exceed 95% (now 92%, +0.297619% this launch)
```

**What holds:** a derived share (`cost(kind, model) / WINDOW_RATIO[window]`) is rounded to one
decimal place — `round(x, 1)`, giving `0.3` — and is never passed through `max(1, …)`. The
configured and learned paths (`usd × 100 / window_usd`) keep `_num`, which already rounds to one
decimal for a non-integer (`asf/workers/headroom.py:96-97`). This is also what keeps PD7 green.
