# B-0110 — plan: don't re-gate a green record-repo branch for a docs-only trunk move

Item: B-0110 — Harvest re-gates a green code branch when main moved only by docs commits. Epic:
E-0002 — ASF 0.2 — self-improvement. Branch: `fix/B-0110`. No spec exists; the Acceptance below
is the record.

## Cause

`harvest_branch`'s retry rebases onto `origin/<trunk>` and, for a record repo, always re-runs the
full gate on the second attempt — even when the only thing that moved on `trunk` between the
green gate and the retry was a docs, spec, plan or backlog commit that touches none of the
branch's own files. A 10-minute gate then loses to any landing in between, so a code branch can
livelock against docs traffic that could never have turned its tests red.

## Task 1 — skip the retry's gate for a docs-only trunk move

writes: `asf/harvest/harvest.py` `tests/test_harvest.py`

- Step 1: in `asf/harvest/harvest.py`, add `docs_only_move(tmp, since, until, branch_sha, conv)`,
  returning `True` when every path `origin/<trunk>` gained between the sha the last green gate
  ran against (`since`) and its current tip (`until`) is documentation per
  `asf.harvest.lane.landing_class` (`specs_dir`/`plans_dir`/`reviews_dir`/`doc_paths`) and none of
  those paths intersect the paths the branch itself changed (`since...branch_sha`).
- Step 2: in `harvest_branch`, track `gated_sha` — the trunk sha the last green gate ran against,
  for a record repo — across the two-attempt retry loop. Before the second attempt's gate, compute
  `skip_gate = is_record and gated_sha and docs_only_move(...)` against the freshly fetched
  `origin/<trunk>` tip; when true, skip `run_gate` and print that the branch was green at its head
  and the trunk moved on docs only, then proceed straight to landing. Re-gate, updating
  `gated_sha` to the new trunk tip, whenever `docs_only_move` returns `False`.
- Step 3: tests, in `tests/test_harvest.py`:
  - `test_b0110_docs_only_trunk_move_lands_without_re_gating` — a spec commit races onto
    `origin/main` between the gate and the push; the branch still lands in the same harvest, the
    gate runs once, and the output names the skip.
  - `test_b0110_code_trunk_move_still_re_gates` — a `tools/` commit races onto `origin/main` the
    same way; the branch still lands, but the gate runs twice.

## Acceptance

- [x] A docs-only commit landing on `trunk` between a green gate and the retry does not trigger a
      second gate run, and the branch still lands in the same harvest
      (`test_b0110_docs_only_trunk_move_lands_without_re_gating`).
- [x] A code commit landing on `trunk` the same way still triggers a second gate run before the
      branch lands (`test_b0110_code_trunk_move_still_re_gates`).

## Accepted costs

`docs_only_move`'s notion of "docs" is whatever `lane.landing_class` classifies from
`conventions.doc_paths` plus `specs_dir`/`plans_dir`/`reviews_dir` — `doc_paths` is empty by
default, so a product that keeps its backlog (or other docs) outside those configured roots will
still see those commits force a re-gate. Left as a follow-up, not blocking, per the round-1
review's I list.
