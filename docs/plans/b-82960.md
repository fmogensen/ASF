# B-82960 — plan: the 0.2 kernel, and the six corrections its own review found

Item: B-82960 — Active Tasks still hold their footprint after a scope freeze; I3 keeps ranked
Tasks waiting on them for ever. Severity S1. Epic: E-0001 — ASF 0.1 — a working factory.
Branch: `fix/B-82960-kernel-0.2` (PR #1266). Spec: `docs/specs/b-82960.md` — the deadlock, the
kernel's shape, and each of the six corrections in the review's words.

## Cause

The deadlock's own fix is on the trunk (`14b963ba`, PR #1244: `asf/invariants.py:249`,
`asf/feeder/rows.py:644`). What this branch answers is why it could happen: *"parked"*, *"holds a
lane"* and *"may launch"* were each decided in a different component, in different words, with no
single place to ask **what should run now, and why not** — and no way to test the answer without
a record, a network and a clock. Eight idle seats and one ready row is what that costs.

`asf/kernel/` is that place: `decide(facts, config) -> Plan`, pure, with every rule in one
module docstring and one test per rule.

## Task 2 — the six corrections the review of `e2d39a934` asked for

writes: `asf/kernel/ports.py` `asf/kernel/decide.py` `asf/kernel/briefs.py` `asf/kernel/model.py`
`tests/kernel/test_ports.py` `tests/kernel/test_decide.py` `tests/kernel/test_go_live.py`
`tests/kernel/test_open_pr.py` `docs/specs/b-82960.md` `docs/plans/b-82960.md`

- Step 1 (C1): `failing_files` cuts the dotted name at the prefix before the first capitalised
  part, so the four-part `FAIL: test_x (tests.test_mod.Case.test_x)` this product's Python prints
  reads as `tests/test_mod.py` and not `tests/test_mod/Case.py`. A name with no capitalised part
  keeps the old cut.
- Step 2 (C2): a wait is read off the target's state — neither Done nor Parked — in
  `_apply_waits` and in the idle alarm, through one predicate (`_held_by`), so a container that
  *derives* `Parked` from its children holds nobody.
- Step 3 (C3): `VERDICT_RE` reads `approve`, `approved` and `changes`, with a trailing remark
  allowed, and `parse_verdict` normalises `approved` to `approve`. `VERDICT_RULE` says the review
  template's own block is the same verdict.
- Step 4 (C4): `isDraft` in `PR_FIELDS`, `PR.draft` in the model, filled in `_open_pr`; an
  approved draft is held in Review with a `NoteItem` instead of planning an auto-merge GitHub
  refuses. Reviews and fix rounds on a draft are untouched.
- Step 5 (C5): `_claimed_on_origin` checks the claimed sha against `Branch.head_sha` (a report's
  short sha counts as a prefix; an unread head holds nothing against the claim), and its
  docstring promises exactly that.
- Step 6 (C6): this plan and `docs/specs/b-82960.md`; every commit subject from this round on
  names B-82960. Which id the work finally belongs to is the operator's (see §Open below).

## Accepted costs

- **An approved draft is held in `Review`, not in a state of its own.** `Review` already means
  "an open PR whose head is not landing yet", and its docstring now says so; a `Stuck` would be
  recorded on the card and would not be re-judged when the owner marks the PR ready, which is a
  worse wedge than the one being fixed. The note is what makes the hold visible in
  `asf kernel status`.
- **`_claimed_on_origin` cannot tell "origin moved past the claimed sha" from "origin never got
  there".** `Branch` carries a head, not an ancestry, and asking GitHub for one would put a
  network call inside a decision that must stay pure. Equality (prefix-wise) is therefore the
  test, and the docstring no longer promises more than that. The cost is one false
  `done without a push` in the case where a later session really did push past the claimed sha
  and its own report is no longer in the facts — recoverable, and loud, which is the direction
  this product errs in.
- **A dotted name that cannot be a module path yields no test file at all**, because
  `failing_files` now skips it rather than cutting it: unittest's synthetic
  `unittest.loader._FailedTest.test_x` (an import that failed, no capitalised part — the old cut
  turned it into `unittest/loader/_FailedTest.py`) and a name whose first part is the class, not
  a module (`Case.test_x` → `Case.py`). Python modules are lower-case by convention; the
  conservative result — no known failing files — reads as "on the PR" and gets a fix round,
  which is the safe side.
