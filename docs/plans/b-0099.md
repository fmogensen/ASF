# B-0099 — plan: file-bugs runs rule checks against a freshly built index

Item: B-0099 — A removed or moved rule card still runs its check and files S2 'rule violated'
Bugs. Epic: E-0001 — ASF 0.1 — a working factory. Branch: `fix/B-0099`. No spec exists; the
Acceptance below is the record.

## Cause

`cmd_file_bugs` (`asf/tick/file_bugs.py`) read the rule list from `index.json`. A rule card
removed (`removed:`), moved or deleted after the last `asf index` still sat in that stale index,
so its check ran and filed an S2 `R-NNNN: rule violated` Bug for a rule that no longer exists.

## Task 1 — rebuild the index before the rule check

writes: `asf/tick/file_bugs.py` `tests/test_file_bugs.py`

- Step 1: in `cmd_file_bugs`, after the parse-error gate, call `do_index(root)` and reload the
  items, so the rule check reads the cards as they are now.
- Step 2: tests, in `tests/test_file_bugs.py`:
  - `test_a_rule_retired_since_the_last_index_files_no_bug` — index, then mark the card
    `removed:`, run file-bugs, no Bug.
  - `test_a_rule_card_deleted_since_the_last_index_files_no_bug` — index, then delete the card,
    run file-bugs, no Bug.

## Acceptance

- [x] A rule card marked `removed:` after the last index files no Bug.
- [x] A rule card deleted after the last index files no Bug.
- [x] A violated live rule still files its Bug (the existing tests in `tests/test_file_bugs.py`).

## Accepted costs

The index is written once more per file-bugs tick (and again after a filing). The reload drops
`parse_errors`, which the first load already gated on. Both are accepted.
