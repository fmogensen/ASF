# Plan F-0113 — the S1 gate says its own name, and one plan feeds every view

Epic: E-0001 — ASF 0.1 — a working factory. Spec: `docs/specs/f-0113.md` (approved). Branch: `plan/F-0113`.

Five Tasks, cut the way the spec's **In** is cut — by the module that gains the surface. Task 1 is
`asf/feeder/tiers.py`: the `Gate` record, the pure function that builds it by diffing the cut plan
against the uncut one, the one formatter that writes the card's line, and the `NEEDS OPERATOR` lines
for an S1 nothing is working. Task 2 is `asf/tick/step_wave.py`'s **one plan** — `Plan`,
`reader_root`, `behind`, `plan_index`, `plan_now` — and `launch` rebuilt on it. Task 3 is what the
wave *says*: the gate line, the `NEEDS OPERATOR` lines, and the ninety-four `waits` lines capped at
five. Task 4 is `asf next` through the one plan, with the card's third acceptance — next and the wave
produce the same rows — as its own test. Task 5 is `asf status`: one plan per table and an `S1 gate`
row that is absent when nothing holds.

Only Task 1 starts at once; it invents the fact every other Task prints. Task 2 needs Task 1's
`tiers.gate`, because `Plan.gate` is what that function returns. Tasks 3, 4 and 5 each need Task 2's
`plan_now` — Task 3 prints its `gate` and its `dropped`, Task 4 plans `asf next` from it, Task 5
hands one of them to three status cells.

Wave order: **1 → 2 → 3 ‖ 4 ‖ 5**.

Tasks 1, 2, 3 and 4 all write the new `tests/test_s1_gate.py` and run one after the other whatever
their `after:` says — see PD4. Tasks 1 and 4 both write `tests/test_feeder.py` and queue the same
way. Task 5 intersects nothing and runs beside whichever of 3 and 4 the queue lets through. The
queue costs nothing here: 3 and 4 already wait on 2, and 1 is first whatever happens.

§Acceptance tests' last fence — the whole suite as CI runs it — binds every Task, so every Gate below
runs `python3 tools/run_tests.py` beside its own.

### Task 1: `tiers.Gate` — what the S1 lane's cut dropped, said in one string
stories: S-32900, S-32905
writes: asf/feeder/tiers.py, tests/test_feeder.py, tests/test_s1_gate.py
after: none

The spec's first **In** bullet and its `asf/feeder/tiers.py` design block: a `Gate` record built by a
pure function that diffs the cut plan against the same plan at `s1_first=False`, one formatter that
owns the card's line, and one that writes a `NEEDS OPERATOR` line per S1 nothing is working. `select`
is not touched (D1, D2); nothing in this Task has a caller yet.

**Files**

- `asf/feeder/tiers.py` — `WORKED`, `Gate`, `gate`, `gate_line`, `needs_operator`
- `tests/test_feeder.py` — `S1GateTests` (new); `TiersTest` untouched
- `tests/test_s1_gate.py` — new module, `AnUnworkedS1HoldsNothing`

**Steps**

1. `WORKED = ('session', 'landing', 'branch', 'merge')` with the spec's comment: a tier-0 `WAITS` row
   whose `waits_on` is one of these is being worked; every other reason is a person's (D5). The four
   are `bug_rows`' own strings (`asf/feeder/rows.py:579-592`) plus the merge wait at `:704`.
2. `Gate = collections.namedtuple('Gate', 'holders held behind by_kind unworked')` with the field
   comments the spec's design block gives, byte for byte.
3. `gate(cut, uncut, held=())` — pure, over two row lists, no product and no I/O. `holders`: the ids
   of `cut`'s tier-0 rows with `action == NO_SLOT` that are not in `held`, in `cut`'s order, deduped
   (`dict.fromkeys`) — the same expression `left_out` already uses (`asf/tick/step_wave.py:371-372`).
   `behind`: the tier-2 launching rows of `uncut` not in `held`. `held` (the count): those of them
   whose `(item_id, kind)` is not among `cut`'s. `by_kind`: `[(kind, n)]` over the held rows in
   `uncut`'s order (D3) — feeder order, never sorted by count. `unworked`: `[(id, waits_on, reason)]`
   for each tier-0 row of `uncut` that does not launch and whose `waits_on` is not in `WORKED`, plus
   each tier-0 launching row whose `item_id` is in `held` (parked by an approval hold), in `uncut`'s
   order. Returns `None` when `holders` is empty and `unworked` is empty.
4. `gate_line(g)` — the card's line and the only place that string exists:
   `S1 gate: B-0057 holds 94 rows (PLAN → CODE 47, CARD → SPEC 27, STARVED → PLAN 12, STARVED → SPEC 8)`.
   Two or more holders read `B-0057, B-0061 hold 94 rows`. `None` when `g` is `None` or `g.held` is 0
   — a gate with nothing behind it is not news. The kinds are the row kinds as the feeder writes them
   (`asf.feeder.rows.BUG_FIX` and its siblings), never re-spelled here.
5. `needs_operator(g, product, skip=())` — `[]` when `g` is `None`; otherwise one line per entry of
   `g.unworked` whose id is not in `skip` (D8, PD13), in `unworked`'s order:
   `NEEDS OPERATOR: <id> is S1 and nothing is working it — <reason> — the S1 lane holds <g.held> of
   <g.behind> tier-2 rows behind it — <command>`. The count is always `held of behind` (D7), so a
   not-launchable S1 reads `0 of 94` and not `0 rows`. The reason and the command come from the
   spec's remedy table, switched on `waits_on`: `decision` → `undecided <age>` and
   `asf set <id> decided=true --product <p>`; `operator` → `adjudicated after <n> sessions` and
   `asf set <id> severity=S2 --product <p>` — or close it; a blocker id or `blocked` →
   `blocked by <ids>` and `asf set <id> blockedBy= --product <p>` — or close the blocker; a parked
   item → `held <class>` and `asf approvals resolve <id>/<class> granted|done|dropped`; anything else
   → the row's own `reason` and `asf set <id> severity=S2 --product <p>`. The `<age>` and the `<n>`
   are read off the row's `reason`, which already carries both (`asf/feeder/rows.py:595`, `:1201`),
   never off the item — `gate` takes no index and this function takes none either beyond `product`
   for the `--product` token.
6. `TIER_S1`, `TIER_S2`, `TIER_REST`, `NO_SLOT`, `free_slots` and `select` keep their meaning and
   their bodies exactly. `gate` reads them; nothing writes them.
7. `S1GateTests` in `tests/test_feeder.py`, over `plan_rows` on the module's existing fixtures
   (`ten_features_and_an_s1`, `s1_bugs`, `fixture_index`) so the rows are real feeder rows: a single
   unseated S1 with ten Features behind it gives `holders == ['B-0001']`, a `held` equal to the
   tier-2 launching rows of the uncut plan, a `behind` equal to it, and a `by_kind` in feeder order;
   two unseated S1s and one seat give `hold` in the line and both ids; a plan with no S1 at all gives
   `gate(...) is None` and `gate_line(None) is None`; a gate whose `held` is 0 — an S1 with no seat
   and no tier-2 row behind it — gives a `Gate` whose `gate_line` is `None`, so the view prints
   nothing; a held (parked) S1 is not a holder and does not appear in `holders`. One case asserts the
   card's line character for character for the incident's own shape.
8. `tests/test_s1_gate.py` is created with the module docstring the suite's style asks for and one
   class, `AnUnworkedS1HoldsNothing` — P4's invariant, asserted directly against `plan_rows` so the
   day someone widens `s1_rows` past `r.launches` the suite says so. Five cases, one per way an S1
   goes unworked: blocked by an open item, `state: Active`, past the attempt limit, undecided, and
   parked by a hold. Each builds an index with that S1 and ten tier-2 rows behind it, plans at a
   capacity with no free seat, and asserts that every tier-2 row the uncut plan launches is still in
   the cut plan — and that `gate(...)` reports `held == 0` with the S1 in `unworked`.

### Task 2: `step_wave.plan_now` — one plan, over one set of inputs, and `launch` made from it
stories: S-32901
writes: asf/tick/step_wave.py, tests/test_s1_gate.py, tests/test_tick_steps.py
after: Task 1

The spec's "One plan, one set of inputs" bullet and its `asf/tick/step_wave.py` design block: the
`Plan` record and the four functions that make it, and `launch` losing its hand-made plan for a call
to `plan_now`. The wave's own behaviour is bit-for-bit today's (D12) — that is the property this Task
is judged on. Nothing prints anything new here; the lines are Task 3's.

**Files**

- `asf/tick/step_wave.py` — `Plan`, `FETCH_TIMEOUT`, `reader_root`, `behind`, `plan_index`,
  `plan_now`; `fresh_index` bounded; `cloud_readiness` gains `run_cmd`; `launch` rebuilt on `plan_now`
- `tests/test_s1_gate.py` — `NextReadsTheRecordCloneTests`
- `tests/test_tick_steps.py` — the wave's plan asserted to be unchanged, in `WaveStepTests`' idiom

**Steps**

1. `Plan` as the spec's dataclass, field for field and comment for comment: `rows`, `gate`,
   `dropped`, `items`, `inputs`, `capacity`, `inflight`, `root`, `source`. `FETCH_TIMEOUT = 15` with
   the spec's comment.
2. `reader_root(product)`: `shadow.record_dir(product)` when that directory holds a `.git`, else
   `product.backlog_dir` or `None` (PD7). It never calls `ensure_clone` and never resets — a view
   that reset the clone would discard the uncommitted record work of a tick running beside it
   (`asf/tick/shadow.py:69-80`, D14). The `None` answer is what lets `status` fall back to its own
   root and what makes a product with neither honest rather than crashing.
3. `behind(root)`: `git -C <root> merge-base --is-ancestor origin/<default branch> HEAD` — `True`
   when it exits non-zero, `False` when it exits 0 and `False` when the question cannot be asked (no
   `origin/<branch>`, not a repo, the subprocess fails). The branch is `shadow._default_branch`, the
   one `fresh_index` already uses. By ancestry a clone reset at a tick's start, with or without the
   tick's own commits on top, is never behind (D12) — which is why the wave's map does not move.
4. `plan_index(product, root, index=None)`: `index` when given, else `index_reader.load(root)[0]`
   when `root` holds an `index.json`, else `{}`. Then `fresh = fresh_index(root)` when `root` is a
   repo; when `behind(root)` and `fresh` is not `None`, `fresh` is the base map (D13 — the fresher
   record wins, one level up from `blockedBy`), otherwise `overlay_blockers(items, fresh)` exactly as
   the wave applies it today. Then `plan_order.overlay(items, plan_order.trunk_reader(product))` when
   `product.repo_dir`. Returns `(items, source)`, `source` being one of the spec's three strings.
5. `fresh_index` gains `timeout=FETCH_TIMEOUT` on its `git fetch` and one
   `except subprocess.TimeoutExpired: return None` — the answer it already gives for a fetch that
   fails, so "origin unreadable" stays its single failure contract. The `git show` is local and keeps
   no timeout.
6. `cloud_readiness(product, cloud, run_cmd=None)` passes `run_cmd` through to
   `cloud_mod.readiness(cfg, product, run_cmd=run_cmd)`. Its `except Exception` is unchanged: an
   unreadable lane is an unready one, and an unready lane adds no seats.
7. `plan_now(product, root=None, items=None, capacity=None, inflight=None, decision_limit=None,
   out=None)` with the spec's docstring. Every argument is an override for a caller that has the
   answer; what is not given is read here. `root` defaults to `reader_root(product)`; `items` and
   `source` come from `plan_index`; `inflight` defaults to `inflight(product)`;
   `inputs = plan_inputs(product, root, items)` — the loaded map handed in, so the index is read
   once; `capacity` defaults to `capacity_mod.resolve(product).sessions` plus the cloud lane's seats
   from `split_hold(cloud_settings(product), cloud_readiness(product, cloud, run_cmd=_bounded), False,
   '')[2]` (P9, PD9, PD10), where `_bounded` is a module-level runner lowering every subprocess it is
   handed to `FETCH_TIMEOUT` (`kw['timeout'] = min(kw.get('timeout') or FETCH_TIMEOUT,
   FETCH_TIMEOUT)`; `Gh.call` already passes a `timeout=` of its own, so the runner overrides rather
   than adds). Rows and drops come from `gated_plan(items, product, running, capacity, plan_kw,
   out=out or (lambda _l: None))` (P8), where `plan_kw` is `inputs` itself, or
   `dict(inputs, decision_limit=decision_limit)` when one is given (PD11). The gate comes from
   `tiers.gate(rows, uncut, held=inputs.get('held'))` over a second plan made at the same capacity
   with `s1_first=False` and the same `exclude`, so the two lists differ in exactly one thing.
   Returns the `Plan`.
8. `launch` keeps every line it has. Its four plan-making lines (`index_reader.load`,
   `overlay_blockers(…, fresh_index(…))`, `plan_order.overlay`, `plan_inputs`, and the `gated_plan`
   call) become one `plan_now(product, root=ctx.record_root(), inflight=running,
   capacity=r.sessions + extra, out=out)`, unpacked as
