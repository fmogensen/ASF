# Plan F-0207 — the debt, the lock, the window, the proof, and the two views

Epic: E-0001 — ASF 0.1 — a working factory. Spec: `docs/specs/f-0207.md` (approved). Branch:
`plan/F-0207`.

Five Tasks. The spec's own shape is a chain inside `asf/upgrade.py` — a record nothing reads, then
the attempt that reads it, then the window that parks for it — with the end-to-end proof last and
the two views hanging off the record alone:

1. **The debt** — `upgrade-due.json` and its seven functions, written by `install()`'s
   floor-deferral and settled at every terminal outcome. Nothing reads it yet; the factory's
   behaviour is byte-identical.
2. **The lock, and the last one out** — `install_lock`, `installing()`, `install_due()`, the exit
   attempt on every `cmd_tick` path and on the background harvest's `main`. **This is the Task that
   fixes the card**: the moment it lands, a floor that is busy at every aligned minute is still
   empty at some process's exit, and that process installs.
3. **The window** — `DUE_GRACE_S`/`DUE_PARK_MAX_S`/`DUE_RESUME_S`, `draining()`, `waiting()`'s
   third clause, and the harvest suppression moved onto the debt. The gap is made, not waited for.
4. **The card, end to end** — `StarvedUpgradeTest`, the test the card names, driving `cmd_tick`
   over N passes against a floor that is never empty at a tick start.
5. **The two views** — the doctor's `SCHEDULER` row and the status `Cron` cell naming a debt when
   no park is showing.

Wave order: **1 → {2, 5} → 3 → 4**. Task 5's footprint (`asf/doctor.py`, `asf/views/status.py` and
their two test modules) is disjoint from every other Task's, and it needs only `read_due()` and
`due_label()` from Task 1 — so it runs beside Task 2. Tasks 1–4 all write `tests/test_install.py`
and 1–3 also write `asf/upgrade.py`, so they are queued against each other whatever `after:` says;
that costs nothing, because 1 → 2 → 3 → 4 is the dependency order anyway (PD1).

**Four places the spec ships broken, all measured at this checkout and all decided below.**
**PD2**: a module-level `def due()` is shadowed by a local named `due` inside `batch_hold`
(`asf/upgrade.py:313`) — the local is renamed in Task 1, or the first reader of the new function
from inside that block is a `TypeError`. **PD3**: the spec's `cmd_tick` wrapper silently flips
today's `--shadow` / `--dry-run` precedence. **PD4**: `draining()` and `bump_due()` are two
read-modify-write writers of one file, and a lost update restarts a park stretch — which is
exactly B-0141's "a stuck upgrade never stops the factory" failing; the stretch is derived from
`at` instead, which reproduces every fenced number and makes both writes idempotent. **PD5**: the
`NEEDS OPERATOR` remedy lines the spec writes name a seven-character sha, and
`asf upgrade --to <7 chars> --wait` exits 2 — verified live against this origin.

| PD2 | **`batch_hold`'s local `due` shadows the new module-level `due()` — the local is renamed in Task 1** | Measured: `asf/upgrade.py:313` is `due = last['at'] + min_interval_s(cfg)`, and `:314`/`:316` read it. Python resolves `due` inside `batch_hold` to that local for the whole function body, so a module-level `def due(installed=None, …)` is invisible there — silently today (nothing in `batch_hold` calls it), and as a `TypeError: 'float' object is not callable` the first time anyone adds a debt check to the batching interval. | PD3 | **`--shadow` still wins over `--dry-run`, and the dry-run guard is the only one that leaves `_tick`** | Both flags exist on the `tick` parser (`asf/tick/tick.py:643-647`) and can be given together. Today `cmd_tick` tests `shadow` first (`:345`) and `dry_run` second (`:348`), so `asf tick --shadow --dry-run` runs the shadow clock. The spec's wrapper keeps only the `dry_run` guard above the `try:` and moves everything else — including the shadow guard — into `_tick`, which reverses that: the same command would take the dry-run path. Nothing asked for it and no test covers the pair (`tests/test_tick.py:28`'s Namespace carries `shadow=False` and no `dry_run` key at all), so it would land unnoticed. **Decided:** the wrapper's one guard is `if getattr(args, 'dry_run', False) and not getattr(args, 'shadow', False):`, with the comment naming today's precedence; `_tick` keeps the shadow guard as its first statement. The spec's two rules both hold unchanged — `--dry-run` is structurally unreachable by the exit attempt (it returns before the `try:`), and the `--shadow` return is inside `_tick` and therefore inside the `finally`. |
| PD4 | **The park stretch is derived from `at`, not carried in a mutable `parked_at` — two writers, one file** | `draining()` writes `parked_at`/`loud` and `bump_due()` writes `owner`/`passes`, both as read-modify-write over `upgrade-due.json`. During a stretch *every parked tick calls `install_due` at its exit* (that is C2's whole point — "a parked tick is the cheapest installer the factory has"), and a busy exit calls `bump_due`. Under cron every clock fires on the same aligned minute, so the colliding writes are not rare: a `bump_due` that read the record before `draining` stamped `parked_at` writes it back without one, `draining`'s next call sees no `parked_at` and stamps a fresh stretch — the park extends by another `DUE_PARK_MAX_S`, the `NEEDS OPERATOR` line never prints, and the factory is stopped indefinitely for an install that cannot land. That is precisely the rule C6 says it is honouring (B-0141: a stuck upgrade never stops the factory), lost to a lost update. **Decided:** `draining()` computes the stretch arithmetically from the one field no writer ever changes, `at` — `elapsed = now - data['at'] - DUE_GRACE_S`; `cycle = DUE_PARK_MAX_S + DUE_RESUME_S`; `start = data['at'] + DUE_GRACE_S + (elapsed // cycle) * cycle`; parked iff `now - start <= DUE_PARK_MAX_S` — and writes `parked_at = start` (not `now`) only when the stored value differs, clearing `loud` in the same write. Every write is then idempotent and identical from any process, so a lost update is recomputed rather than compounded. **It reproduces the spec's fenced numbers exactly**, which is how it was checked: with `DUE_GRACE_S = 300` and `DUE_PARK_MAX_S = DUE_RESUME_S = PENDING_TTL_S = 600`, a debt parks from `at+300`, lifts at `at+900`, and the line it prints there reads `int((now - at) // 60) == 15` — the spec's own `has not found an empty floor in 15 min`. `parked_at` is still "stamped once and not re-stamped on the next call", still cleared-and-reset on a new stretch, and `loud` still prints once per stretch: `DrainWindowTest` is unchanged by this decision. |
| PD5 | **The new `NEEDS OPERATOR` lines name the full sha in the command they tell an operator to run** | The spec writes `rerun asf upgrade --to {ref[:7]} --wait` (`settle_due`) and `(asf upgrade --to {data["sha"][:7]} --wait)` (`draining`). `install()` resolves a ref that is not 40 hex through `resolve_ref` → `git ls-remote <url> <ref>` (`asf/upgrade.py:353-365`), and `ls-remote` matches **refs, not object names**. Verified live at this checkout: `git ls-remote origin 046c9eb` and `git ls-remote origin 046c9eb71` both print nothing. So the command those lines hand an operator returns `upgrade: refused — 5cab3a2 does not resolve to a commit on <url>` and exits 2 — an operator line that is wrong about the one thing it exists to say. **Decided:** both new lines keep the seven-character sha wherever they *name* the target (the prose, and `due_label`), and print `data['sha']` in full inside the parenthesised command. `DueRecordTest` asserts the failure line contains `the install of 5cab3a2 failed (exit 1)` *and* the full sha after `--to`. **The identical defect at `asf/upgrade.py:199-200`** — the marker's expiry line, `(asf upgrade --ref {data["sha"][:7]} --wait)` — is **left alone**: it belongs to the pending marker, which C1 and the spec's "Out, deliberately" keep untouched, and fixing it here would be a quiet widening. No test pins that string (`grep -rn 'never found a gap' tests/` → empty), so it is a one-line Bug for the record, not a change this card makes. |
| PD6 | **`StarvedUpgradeTest` and `ExitInstallTest` inject the scripted `run` by patching `upgrade.cmd_upgrade` and `upgrade.install_due` with delegating wrappers — a default argument cannot be patched** | The whole module signs `run=subprocess.run` as a *default*, which Python binds at `def` time: `mock.patch('subprocess.run')` replaces the attribute on the `subprocess` module and changes nothing about a default already captured. Every existing test gets around this by passing `run=` explicitly (`DrainTest.upgrade`, `UpgradeTest.run_upgrade`), and that works because they call `cmd_upgrade` themselves. The two call sites this card adds are *inside the product*: `_run_steps`'s `run_upgrade` closure calls `upgrade.cmd_upgrade(_ns(...))` (`asf/tick/tick.py:404-407`) and the new `finally` calls `upgrade.install_due(product.name)` — neither passes a `run`, and a test that drives `cmd_tick` end to end would therefore reach the host's real `pgrep`, the real `gh` and a real `pipx install --force`. **Decided:** a test that drives `cmd_tick` wraps both module attributes — `real = upgrade.install_due; mock.patch.object(upgrade, 'install_due', lambda name, **kw: real(name, run=fake, out=out, sleep=noop))`, and the same shape for `cmd_upgrade` — so everything inside `install_due`, `install` and `_install` runs for real against the scripted `SequencedRun`, and only the argument binding is stubbed. The binding itself is `ExitInstallTest`'s own assertion (`install_due` patched to a plain `Mock` and asserted called once with `product.name` on each `cmd_tick` path), so no line is left unpinned. Both modules already set `env.ASF_HOME` to a temp directory in `setUp` (`tests/test_install.py:124-135`, `tests/test_tick.py:93-95`, `tests/test_views.py:30-32`, `tests/test_doctor.py:727-743`), so the new `read_due()` in the two views and the new exit attempt in every `cmd_tick` read an empty temp home and return `None` before any subprocess — this was checked for all four modules, because an unguarded `install_due` under the operator's real home would run a real `pipx install --force` from a unit test. |
| PD7 | **The exit install writes no pending marker, deliberately — `install_lock` plus `waiting()`'s `installing()` clause is the whole protection there, and `install_due` bypasses the batching interval on purpose** | Two things a reader of Task 2 will go looking for and not find. **(a) No marker.** `install()` writes `upgrade-pending.json` only inside `if others and (owner or wait_s):` (`asf/upgrade.py:549`); `install_due` calls it only when `other_ticks(run)` came back empty, so `others` is empty and that branch never runs. The install therefore parks nobody. That is narrower than the marker, and C8 says so — a tick that passed `waiting()` a moment before the lock was taken still starts. Re-checking it at the exit would re-hold a head the factory has already decided to take, which is the card's own defect wearing a different hat. |

### Task 1: the owed install becomes a durable record beside the park
stories: S-37000
writes: asf/upgrade.py, tests/test_install.py
after: none

The spec's §1 — `upgrade-due.json` and the seven functions that own it — plus the two ends of
`install()` that write and settle it. Nothing else reads the record when this lands: `due()` has no
caller in the package until Task 2, `due_label()` none until Task 5, and `DUE_GRACE_S` does not
exist yet.

**What changes for the machine when this lands.** One new file appears in `~/.ASF/state/` the first
time a tick's upgrade is deferred by a busy floor, and one new line is printed there
(`upgrade: due 5cab3a2 — pass 1, owed by asf`). Nothing reads either, so no tick behaves
differently, no install is taken that was not taken before, and no product is parked that was not
parked before. A debt written while Tasks 2 and 3 are still unlanded is inert on disk and is
removed by the first `due()` call after them, or by any `install()` of that sha in the meantime
(`settle_due`) — it can neither park a product nor trigger an install on its own.

**Files**

- `asf/upgrade.py` — the module docstring gains the paragraph the spec's "In" names (the debt, its
  lifetime, and that it is *not* a park: paid by an install, cancelled by a refusal or a failure,
  never by age). New: `due_path`, `read_due`, `clear_due`, `_write_due`, `bump_due`, `due`,
  `due_label`, `settle_due`, placed together after `record_last` and before `_config_number` so the
  file reads park-then-debt-then-config. Changed: `install()`'s floor deferral (`:573-583`) gains
  the `bump_due` call, its tail (`:584-589`) gains `settle_due`, and `batch_hold`'s local `due` is
  renamed `at` (PD2). `pending()`, `held()`, `held_label()`, `write_pending()`, `cooling()`,
  `refuses()`, `drain()` and `_install()` are untouched.
- `tests/test_install.py` — `DueRecordTest(HomeCase)` added after `DrainTest`. No existing class is
  touched.

**Steps**

1. `due_path()` is `os.path.join(env.ASF_HOME, 'state', 'upgrade-due.json')` — beside
   `pending_path`, `expired_path` and `last_path`, the same shape as all three.
2. `read_due()` is the spec's: open, `json.load`, return the dict only when it is a dict with a
   truthy `sha` and an `at`, `None` on `OSError`/`ValueError`. **No clearing, no git, no
   `installed_commit`** — its docstring says so and names the views as the reason (P11: a
   `git merge-base` does not belong in a view, which is why `held()` skips the same check).
3. `clear_due()` is `os.remove` under a bare `except OSError: pass`, exactly as `clear_pending`.
   `_write_due(data)` is `_write_json(due_path(), data)` then `return data` — one writer, and the
   existing `_write_json` is already atomic (`os.replace` over a pid-named temp).
4. `bump_due(sha, owner, now=None)` is the spec's, verbatim in behaviour: a record for the same sha
   keeps its `at` and every other key and gains `owner=owner, passes=passes+1`; a record for a
   different sha, or no record, starts fresh at `passes: 1` with `at = now or time.time()` and
   **no `parked_at`/`loud`**. The docstring carries the spec's sentence about why it is never
   refused where `write_pending` is: a cool-down suppresses the *park*, and the debt is not a park.
   Note explicitly in the docstring that it merges over whatever is on disk and never writes
   `parked_at` or `loud` itself — Task 3's `draining()` owns those two, and PD4 is why that matters.
5. `due(installed=None, out=print, run=subprocess.run)`: `read_due()`, `None` out; resolve
   `installed` from `drift.installed_commit()` only when the caller gave none (the lazy import of
   `asf.drift` inside the function, as `pending()` does at `:181-183` — `asf.drift` imports
   `asf.upgrade`); `_installed(data['sha'], installed, run)` → `clear_due()` and `None`; else the
   record. **Never removed by age** — the docstring says it, and `DueRecordTest` asserts it at
   `10 * PENDING_TTL_S`.
6. `due_label(data)` is the spec's string, unchanged:
   `upgrade to <sha7> due since HH:MM — pass N (owner <product>)`, with `owner` falling back to
   `operator` exactly as `held_label` does at `:233-239`.
7. `settle_due(rc, ref, out=print)`: return when there is no record or its `sha` is not `ref`
   (a debt for a *different* target is left alone — asserted); otherwise `clear_due()`, and for an
   `rc` that is neither `0` nor `DEFERRED` print
   `NEEDS OPERATOR: the install of <sha7> failed (exit <rc>) — the ticks resume; rerun asf upgrade --to <full sha> --wait`
   — **the full sha after `--to`** (PD5). `DEFERRED` clears it silently: a red or unreadable head is
   refused and the next green head becomes due on its own (B-0141).
8. `install()`'s floor deferral, inside the existing `if others:` block at `:573`, after the
   `describe` loop and **before** the `if not owner:` branch:
   ```python
        if owner and ref:
            data = bump_due(ref, owner)   # the debt outlives the park and its cool-down (C1)
            out(f'upgrade: due {ref[:7]} — pass {data["passes"]}, owed by {owner}')
   ```
   `owner and ref` is the guard the spec writes and it is the right one: an operator's `--wait` run
   (`owner is None`) owes the factory nothing, and a tick always has a `ref` (`drift.report` passes
   `d.head`, `asf/drift.py:157`).
9. `install()`'s tail: `settle_due(rc, ref, out)` between `record_last(ref)` and the
   `if owner or marked is not None: clear_pending()` at `:587`. Every outcome past the floor check
   settles — success, a pipx non-zero, the verification mismatch, `_install`'s red-CI `DEFERRED`,
   and the unreadable-head `2`. The early `return DEFERRED` at `:583` is the only path that keeps a
   debt, and it is the only path on which nothing was installed *because of the floor*.
10. `batch_hold`'s local rename (PD2): `:313` `at = last['at'] + min_interval_s(cfg)`, `:314`
    `if (now or time.time()) >= at or urgent(repo, installed, head):`, `:316` `return at`. Three
