### Task T-0441: `asf status` — one plan per table, and an `S1 gate` row that only speaks when it holds
writes: asf/views/status.py, tests/test_views.py
after: none

The spec's `asf/views/status.py` block, D10 and D15, over T-0437's landed `tiers.gate` and
`tiers.gate_line` instead of over the `Plan` that left with T-0438: the three feeder cells stop
making three independent plans and take one, a fourth cell prints the gate and disappears when
nothing holds, and the three existing cells print what they printed before, to the character.
`after:` is `none` — T-0437 landed, and nothing else this Task reads is unbuilt.

**Files**

- `asf/views/status.py` — `Plan`, `_plan`, `s1_gate_cell`; `ready_cell`, `build_cell` and
  `decisions_cell` taking the `Plan`; `render` building it once
- `tests/test_views.py` — `StatusViewTests` gains the `S1 gate` row's answers, its place and the
  one-plan count; `DecisionsCellTests` and both `test_no_index_names_the_backlog` cases follow the
  cells' new argument

**Steps**

1. `import collections` and
   `Plan = collections.namedtuple('Plan', 'product items rows inputs capacity inflight gate')`,
   one comment per field. It carries `product` because `build_load`, `undecided_rows` and
   `decision_rows` all take it, and the cells now take the `Plan` alone. A comment says what it is:
   the view's own one plan, in `status.py` until `step_wave.plan_now` exists — the work F-0113's
   reshape dropped — at which point `_plan` becomes a call to it and this record goes.
2. `_plan(root, product)` returns `None` when `root` is falsy or holds no `index.json` — the
   condition the three cells test today, kept verbatim so their `not_configured` answer is
   unchanged. Otherwise, in one body: `items, _generated = ix.load(root)`;
   `inputs = step_wave.plan_inputs(product, root)`; `running = step_wave.inflight(product)`;
   `cap = step_wave.capacity(product)`;
   `rows = feeder_rows.plan_rows(items, product, running, cap, **inputs)`; the uncut plan
   `feeder_rows.plan_rows(items, product, running, len(items) + len(running or []), s1_first=False,
   **inputs)` (RD2, with RD2's reason as the comment); and
   `tiers.gate(rows, uncut, held=inputs.get('held'))`. It catches nothing (RD6) and writes nothing.
3. `render` memoises it: before the row tuple, a one-slot cache with a sentinel and a nullary
   closure over `_plan(root, product)`; the four feeder lambdas call it
   (`lambda: ready_cell(plan())`). Every other cell keeps the arguments it has — `root` still goes
   to `stale_cell`, `value_cell`, `ab_pairs_cell`, `release_cell`, `record_cell` and `groom_cell`,
   which are about the operator's checkout and are not feeder plans.
4. `ready_cell(plan)`, `build_cell(plan)` and `decisions_cell(plan)` lose their own `ix.load`,
   `plan_inputs`, `inflight`, `capacity` and `plan_rows` calls and read the `Plan`'s fields
   instead. Each keeps `not_configured('backlog_dir (no index.json)')` for a `None` plan and every
   string it prints to the character: `ready_cell` counts `plan.rows` and names the first launching
   row; `build_cell` calls `build_load(plan.items, plan.product, plan.capacity, plan.inflight,
   plan.inputs.get('occupancy'), …)` with the same five keyword facts it passes today;
   `decisions_cell` takes `plan.inflight`, `plan.inputs['occupancy']` and `plan.items`, and keeps
   `undecided_rows(..., limit=0)` and its ranking.
5. `s1_gate_cell(plan)` with the spec's docstring: `None` when `plan` is `None` or `plan.gate` is
   `None`. Otherwise the clauses, joined by ` · ` (RD10) — the first being `tiers.gate_line`'s
   string with its `S1 gate: ` head stripped (the row's own name says it), and **only when
   `plan.gate.holders` is non-empty** (RD3: the formatter has no guard of its own and renders a
   headless line); then one sentence per entry of `plan.gate.unworked`:
   `B-0005 S1, nothing working it (blocked by B-0099)`, whose parenthesis is the entry's own
   `reason` after its first `': '` — the split `tiers._remedy` already makes
   (`asf/feeder/tiers.py:141`), never re-derived off the item. `None` when no clause is produced, so
   the row is a row that only speaks up when something is wrong — the `Stale` row's own pattern
   (P11). No `skip`: the status table has no `raise_holds` pass to duplicate (PD13).
6. The row joins `render`'s list as `('S1 gate', lambda: s1_gate_cell(plan()))`, between
   `Ready to launch` and `Decisions`, so the gate sits beside the count it explains. The existing
   `Gate` row — the product's own CI gate — keeps its name and its place (P11).
7. `StatusViewTests` gains RD8's holding fixture as a helper (five open S1 Bugs, the fifth blocked
   by an open item, seven decided cards, `capacity: {sessions: 3}` on the product, nothing in
   flight) and these cases: the `| S1 gate |` row carries
   `B-0004 holds 7 rows (CARD → SPEC 7) · B-0005 S1, nothing working it (blocked by B-0099)`; the
   class's default record renders **no** `S1 gate` row at all and its other rows are unchanged line
   for line — `Ready to launch` still `1 — first: CARD → SPEC F-0001`
   (`tests/test_views.py:194`) and `Features in build` still matching its regex (`:201`); in the
   holding record the row sits between `Ready to launch` and `Decisions` (RD7); a record whose S1s
   are all seated — `holders == []` with `held > 0` — renders the unworked sentence and **no** held
   clause (RD3); and one case patches `asf.tick.step_wave.plan_inputs` to count its calls and
   asserts **1** for a render whose four feeder rows are all filled (D15, RD5).
8. `DecisionsCellTests`' direct cell calls and both classes' `test_no_index_names_the_backlog` go
   through `status._plan(root, product)` for their argument, and keep every expectation they have —
   including that a missing index gives `decisions_cell` and `ready_cell` the same string.
