## What the cut costs less than it looks like

Task 3's own text bundles two halves — "every worker account's sessions run with the gate, **and**
the doctor says when they do not" — and the first half is not actually open. A Bug fix already on
`main`, outside F-0158's own task tracking, delivered it:

- `41458d30a` — `fix(exit-contract): the Stop gate is wired; a released stop is an unpushed
  defect; the lane writes the trailers (#605)` — added `hooks.BUILTIN`'s `'unpushed': ('Stop',)`
  entry and `ACCOUNT_HOOKS` (`asf/hooks.py:65,70`), rewrote `install`'s per-account write to merge
  `ACCOUNT_HOOKS` (`:446`), added `ensure_account_hooks` so **every launch** re-merges the entry
  into the account's own settings before the session starts (`:470`, called from
  `asf/workers/spawn.py:1180`), and made `cmd_hook` dispatch `'unpushed'` to
  `asf.workers.stopgate.run_hook` (`:537-540`). Its own `tests/test_exit_contract.py` (213 lines)
  covers the wiring end to end.

So the gate the spec describes is already armed and already refusing stops on `main` — the
Feature's actual mechanism, verified by its own test file, under a Bug id this card's record never
names. What is left of Task 3's declared footprint (`asf/hooks.py, asf/doctor.py,
tests/test_install.py, tests/test_doctor.py`) is, measured against the tree at this sha:

- `asf/hooks.py` — no `gate_missing` function exists (`grep -n gate_missing asf/hooks.py` is
  empty); `approvals_missing` (`:491-507`) is the only "missing" helper, and it answers for
  `approvals`, not `unpushed`.
- `asf/doctor.py` — no `unpushed-gate` row and no `check_unpushed_gate` function
  (`grep -n unpushed asf/doctor.py` is empty); `check_approvals_hook` (`:217-230`) and its row
  beside `redaction-hooks` (`:1348-1349`) are the only hook-coverage row the doctor prints.
- `tests/test_install.py`, `tests/test_doctor.py` — neither carries a Stop-gate case; the
  install-side coverage that exists lives in `tests/test_exit_contract.py` instead, under the Bug
  fix's own name.

So the one piece of Task 3 that is genuinely undelivered is doctor-side observability: a row
telling an operator which worker account's settings lost the `unpushed` entry. And that gap is
narrower than a missing row usually is, because `ensure_account_hooks` self-heals it: every
`spawn` re-merges `ACCOUNT_HOOKS` into the account's settings before the session runs
(`asf/workers/spawn.py:1180`), so an account that lost the entry — by hand-edit, by a settings
file an operator overwrote — carries it again at the very next launch, with no operator step. A
doctor row here would catch a gap that exists for, at most, the time between an edit and the next
spawn. The decision's cut lands on exactly that residue.
