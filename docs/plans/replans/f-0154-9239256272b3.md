## Reading the decision

F-0154's own spec measured I4 (the lane's `touched_files`, `already_on_trunk` and `own_commits`)
honestly and well — P9's "450 diffs, 270 cat-files and 225 rev-lists are repeats" is real and
D11's resolved-sha cache is a sound fix for it, read on its own. What changes the scope is a
second card in this epic that measured the *same* branches with a *different* instrument and
chose a *different*, more general fix for the *same* duplication, and whose own precondition
table inventories `asf/harvest/lane.py` by name without `own_commits` ever appearing in it:

> `touched_files` ran **105 times** for ~30 branches; `already_on_trunk` **105 times**;
> `branch_facts` **108**. (`docs/specs/f-0177.md:28-29`)

F-0177's own choice (D2) is explicit about the alternative it is refusing — the alternative this
card's I4 already is:

> **Chosen:** Cache at the two subprocess wrappers, keyed by `(cwd, argv)` … **Against:** Cache at
> the fact functions, keyed by `(branch, fact)` … Keying by fact would need every one of the
> card's per-branch functions to grow a cache parameter and every caller to thread it, and would
> still miss the duplicate that arrives through a fourth path. (`docs/specs/f-0177.md` D2)

`READ_SUBCOMMANDS` — the set F-0177's cache serves — is `{rev-parse, rev-list, log, diff,
merge-base, for-each-ref, cat-file, show, cherry}` (`docs/specs/f-0177.md` §*The design* 1). That
is every subcommand all three of I4's functions issue: `touched_files` and `already_on_trunk` are
each one `diff`; `own_commits` is `rev-parse`, `merge-base`, `rev-list --merges`,
`log --reverse --topo-order` and `cherry` — five processes, every one of them inside the set. Once
F-0177's pass-scoped cache is in `harvest.sh`, a second call to any of the three from anywhere in
one pass is already served from it, unconditionally, with no caller having to know the cache
exists. A bespoke fact-level cache over the same three functions, keyed on resolved ref shas, buys
nothing F-0177 has not already bought more generally, and is a second invalidation story
(D11's "a moved ref is a different key") to maintain for a saving of zero once both are in the
tree. That is what "cut it to the two" removes: not a narrower I4, but all of it, because the
measurement that would justify doing it twice is the same measurement F-0177 already acted on.

**What is left is the two Stories nothing else in this epic touches.** S-55705 (T-0660) is the
health pass's own `git status --porcelain` — `asf/workers/lifecycle.py` and
`asf/workers/health.py`, reached from `health.health`, never through `harvest.sh` and never a

**The reading rejected.** "Cut to the two" could be read as keeping exactly two *Task cards* and

### Drop T-0662: superseded by F-0177's own fix for the same duplicate `git` calls

The design this Task would have built is D11's: a `_FACTS` cache in `asf/harvest/lane.py`, keyed
on `_ref_shas(repo, trunk, branch)`, wrapping `touched_files`, `already_on_trunk` and
`own_commits`. F-0177 (same epic, `docs/specs/f-0177.md`) independently measured the exact same
duplication — `touched_files` 105 times, `already_on_trunk` 105 times, for ~30 branches
(`docs/specs/f-0177.md:28-29`) — and chose, by name, a *different* mechanism for it: a pass-scoped
cache at `harvest.sh`/`harvest._gh`, keyed on `(cwd, argv)`, explicitly against "cache at the fact
functions, keyed by `(branch, fact)`" (F-0177 D2) — which is this Task's own design. F-0177's
`READ_SUBCOMMANDS` (`rev-parse`, `rev-list`, `log`, `diff`, `merge-base`, `for-each-ref`,
`cat-file`, `show`, `cherry`) covers every subcommand all three of this Task's target functions
issue, `own_commits` included. Once F-0177 lands, a second call to any of the three from anywhere
in one pass is already served from its cache, with no caller — and no second invalidation
story — needed. Building this Task's own fact-level cache on top would duplicate that work for no
further saving, and carry D11's "a moved ref is a different key" as a second mechanism to reason
about for the same guarantee F-0177's complement-of-reads rule already gives. S-55707 — "the
lane's git facts about a branch are read once per resolved pair of ref shas" — is left uncovered
by this decision; if F-0177 stalls or its own card is itself re-scoped away from the lane's `git`
calls, this Task's design is still in `docs/specs/f-0154.md` §4 and can be re-opened against
whatever F-0177 actually lands, rather than built in parallel with it now.
