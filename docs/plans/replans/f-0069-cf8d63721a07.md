### Task T-0363: `sev=` and `sig=` — a place's own severity, and a place as its own Bug

3. `rule_violation_signatures` (`:156`): per violation, `text, sev, sig = line_fields(line)`; the

   severity is `sev` when valid, else `'S2'`. A per-place Bug's title is `truncate(text, 120)`,
   its evidence that one line, its acceptance ``asf rules check`` reporting no violation carrying
   that signature; a rule-level Bug's title, evidence, `places` and acceptance are unchanged.
4. The "One Bug per RULE, not per place" comment (`:164`) stays with its reason, and gains its
   exception in two sentences: a place carrying a stable key from a source outside this record —
   an alert number — *is* its own defect, and folding it into one Bug per rule loses the one thing
   that makes it actionable.
5. Nothing else on the filing path: `_file_or_bump_bug` (`:328`) already carries `severity` per
   signature and day-keys `last_filed` (P19), so an S1 needs no new route and a signature filed
   today is not filed again today.
6. `RuleViolationFieldTests` per §3's T6: `line_fields` splits the fields off, keeps `foo=bar` in
   the text, ignores `sev=S9`; two lines with distinct `sig=` file two Bugs, one S1 and one S2,
   each keyed `R-0009: <sig>` with its own line as evidence; two lines with none file exactly one
   S2 Bug per rule with both lines as evidence, asserted byte for byte against today's output; a
   second run the same day files nothing and bumps nothing.
7. `SecretAlertTests` — **the card's surviving acceptance** ("a planted test secret in a branch is
   filed within one tick"), hermetic per PD10: a fake host plants one open secret alert,
   `alerts.violations(product, host=FakeHost())` produces the line, that line is handed to
