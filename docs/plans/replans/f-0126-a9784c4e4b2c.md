## Reading the decision

The plan cut F-0126 into six Tasks by the module that gains the surface, and **Task 1 is the card's
own defect**: the feeder's footprint gate on the Task path and the delivery path, plus the one
RESHAPE → PLAN row per Feature that repairs the plan section. That is what the card asks for in as
many words — *Expected: a Task with no `writes:` is never launched; it shows a non-launching row …
so the groom/plan session re-cuts it with the machine lines* — and it is the whole of the card's
`Acceptance`: *feeder test — a migrated Task with no writes: yields no launching row.*

The other five Tasks are surfaces the spec grew on top of that defect, each from a different one of
the incident's three halves. Four of them (Tasks 2–5) have landed and stay landed. Task 6 —
`asf/briefs/templates/reshape.md`'s second mode — is the one the decision can still cut, and it is
outside Task 1 on every axis the plan itself names: a different file, a different Story (S-33602), a
different tree, and not a coder's Task at all but the operator's console amendment (PD11, re-measured
as RD8). Nothing in the card's title, its Expected list or its Acceptance names the brief.

**The reading rejected.** "Cut to Task 1" could be read as *rewrite the remaining work down into
Task 1's scope* — fold the brief's second mode into the Task that already landed. Against: T-0477 is
landed and a replan does not reopen a landed Task (`_apply`'s `own_open` skips it and says so:
`not an open Task of F-0126 — kept as it is`, `asf/record/replan.py:260-263`), and the template is in
the amendable set, so bundling it with a coder's file would drag that file to the console with it —
the plan's own PD11 and the reason Task 6 was ever a Task of its own. There is nowhere for that work
to go inside Task 1. The decision is therefore a drop, and the Feature closes on the five Tasks that
landed.

## What the cut leaves undone

The drop is clean against every fence (RD3) but it is not clean against the defect, and this is
stated here so it is never read later as an accident. Measured, not argued:

T-0477 landed the launching `RESHAPE → PLAN` row whose reason is `NO_WRITES_RECUT`
(`asf/feeder/rows.py:194`, emitted at `:1127` and `:1503`). The brief that row launches is the split
brief, and nothing else — rendered at this sha through `tests/test_briefs.py`'s own fixture with that
reason substituted (RD5), it tells the session its binding is "the groom's approved split", asks for
one Task per area from `BACKLOG_ID_RANGE`, each `split_from:`, with the Task marked
`removed: split into <ids>`, and interpolates `{writes}` as the literal `(none declared)` — so the
sentence a session actually reads is *its `writes:` (the part of T-nnnn's `(none declared)` in that
area)*.

A session reading that brief correctly answers `NO SPLIT:` — a Task with no footprint is not a Task
that is too wide. `asf.tick.rejudge.take_no_split` takes that answer and writes
`reshape_declined: ['no split']` (`asf/tick/rejudge.py:131-145`), after which
`feeder_rows.recut_declined` suppresses the re-cut row for ever (`asf/feeder/rows.py:203-205`,
guarding `:1120` and `:1497`). Measured at this sha (RD6): a no-writes Task carrying
`reshape_declined: ['no split']` yields exactly one row —
`('PLAN → CODE', 'WAITS ON writes', waits_on='writes')` — and **no** reshape row. That is P1's
"waits on nobody for ever", the condition this Feature exists to close, restored by one answer.

This is a defect of the trunk after the cut, not scope this replan may add: minting a Task for it
under F-0126 is precisely the Task the decision drops, and minting a card elsewhere is not a
replan's to do. It is on the line below.
