## What the cut keeps

The whole of the spec's §1, §2, §4 and §5's second half: `state/upgrade-due.json` and the functions
that own it, `install()` writing the debt on a floor-deferral and settling it at every terminal
outcome, `state/upgrade.lock` and the two readers of it, `install_due()`, and the last-one-out
attempt at every `cmd_tick` path and at the background harvest's `main`. C1, C2, C3, C7, C8 and C9
are untouched; C4, C5, C6 and C10 are what the cut removes.

**The card's named cause is still the thing fixed.** The card says the install starves because
*"every owner (asf) tick that started logged `upgrade: deferred to the next tick`"* — one attempt
per tick, at the tick's start, which under cron is the aligned minute when the floor is fullest
(P2, P3). The cut keeps the whole of the answer to that: the attempt is made again at every exit,
the emptiest moment the factory has, and the debt that says an install is owed outlives the park
marker that forgot it. Of the card's three suggested remedies it keeps the second — *"the install
runs from whichever tick finishes last"* — which is the one the spec chose (C2, C7).

**What the cut costs, stated plainly.** Three things:

1. *A floor that never empties at any exit still starves.* The window was the "make the gap rather
   than wait for it" half (C4). Without it, a factory whose processes genuinely overlap end to end
   — a 30-minute harvest gate straddling every tick — owes an install nobody takes. The debt is now
   durable, so it is not forgotten, and every exit re-attempts it; but nothing parks the floor to
   force a gap.
2. *The marker's ten-minute TTL still lets a gate rejoin the floor.* C5 moved the harvest
   suppression onto the debt because the marker dies at the TTL while the debt lives on (P7). Under
   the cut it stays on the marker, so after ten minutes `step_harvest.run` may spawn a gate again.
   That gate is, by C3, the longest-lived process on the floor and makes the install attempt as its
   own last act — which is the cut's own answer, and the reason this is a cost and not a hole.
3. *The incident stays invisible in both views, and the card's Test is unwritten.* RD13.

### Task T-0594: the owed install becomes a durable record, and whichever process finishes last takes it
writes: asf/upgrade.py, asf/tick/tick.py, asf/tick/step_harvest.py, tests/test_install.py
after: none

The spec's §1, §2, §4 and §5's second half, as one card — the old plan's Tasks 1 and 2, which the
record already holds as one footprint (RD2). **This is the Task that fixes the card.** On the trunk
today an install is attempted at exactly one moment per tick, the aligned minute when the floor is
fullest (P2, P3); when this lands a durable record says an install is owed, and the attempt is made
again at the emptiest moment the factory has — the instant a process leaves the floor, by the one
process that knows the floor just lost a member.

**The spec's §3, §5's first half and §6 are cut** (see *What the cut removes*): no `DUE_GRACE_S`,
no `draining()`, no third clause on `waiting()`, no `parked_at`/`loud`, no `due_label()`, no
suppression on the debt, no `StarvedUpgradeTest`, no view. `step_harvest.run`'s suppression and
`held()` are not touched at all.

Read **RD5** before writing a line in `asf/upgrade.py` (the module's own new function is
unreachable from `batch_hold` without the rename), **RD6** before touching `cmd_tick` (`--shadow`
wins over `--dry-run` today and must keep winning), **RD7** (the operator command needs the full
sha or it exits 2), **RD8** (every line number in `docs/plans/f-0207.md` has moved) and **RD9**

a real `pipx install --force`). Ignore **PD4** of `docs/plans/f-0207.md`: it is moot under the cut,
and RD4 says what brings it back.

**What changes for the machine when this lands.** The card's twenty minutes end. A floor that is
busy at 06:25's aligned minute is empty at 06:27 when one of those ticks exits, and that tick
installs — `upgrade: the floor is empty at this exit — installing 5cab3a2`. Every exit that still
finds the floor busy counts a pass and says so by name, against a record that outlives the park
marker and its cool-down, so the debt is no longer thrown away with the ten-minute TTL. A new line
appears at a tick's start while an install is running (`tick: waiting — an install is running`), and
two installs can no longer overlap. Nothing is parked that was not parked before: the exit install
writes no pending marker (PD7), and no product is parked for the debt at all (that was the cut §3).
A floor that never empties at any exit is still not drained on purpose — RD13's first cost.

10. `lock_path()` is `os.path.join(env.ASF_HOME, 'state', 'upgrade.lock')`, beside the other path
    helpers. It is free in this module (RD11); the four `lock_path`s elsewhere are never imported
    into this namespace.
11. `install_lock()` is the spec's `@contextlib.contextmanager`: `os.makedirs` the state dir,
    `open(lock_path(), 'a+', encoding='utf-8')`, `fcntl.flock(f, LOCK_EX | LOCK_NB)` in a `try` that
    yields `None` and returns on `OSError`, else yields `f`, with `f.close()` in the `finally`.
    Non-blocking, and it dies with its process, so a killed install parks nobody. It is deliberately
    **not** `asf.tick.tick._flock` (`:273-285`): that helper is a *waiting* poll loop for a product
    lock, and importing `asf.tick.tick` from `asf.upgrade` would tangle two modules for four lines
    (C8).
12. `installing()` is `with install_lock() as f: return f is None`. Its docstring carries C8's
    sentence in full: it *narrows* the window rather than closing it — a tick that read this a
    moment before the lock was taken still starts, and for a process already running it is the floor
    check, not this, that protects it.

    for and not find:** no pending marker is written here and none should be — `install()` writes
    one only inside `if others and (owner or wait_s):` (`:582`), and `install_due` reaches `install`
    only when `other_ticks` came back empty, so that branch never runs. A marker written at an exit
    would be a ten-minute park for a thirty-second install, and the TTL it left behind would arm
    `cooling()` against the next real park. The protection here is the lock (step 11) and
    `waiting()`'s reading of it (step 13), and that is narrower on purpose. Nor is `batch_hold`
    consulted: the debt exists *because* `drift.report` already cleared the batching interval for
    this head (`asf/drift.py:151-156`) and then the floor refused the install; re-checking it at the
    exit would re-hold a head the factory has already decided to take.
15. `cmd_tick` (RD6):
    ```python
    def cmd_tick(args, root=None):
        product = env.load_product(getattr(args, 'product', None))
        # --shadow wins over --dry-run, as it has since both flags existed: the shadow guard is
        # _tick's own first statement. Only the dry-run path returns above the try — it installs
        # nothing, ever, and must make no attempt.
        if getattr(args, 'dry_run', False) and not getattr(args, 'shadow', False):
            from asf.tick import dry_run
            return dry_run.run(product, fresh=getattr(args, 'fresh', False))
        try:
            return _tick(args, product)
        finally:
            # F-0207: the tick's last act. Every clock fires on the minute, so this exit is the
            # emptiest the floor gets — emptier than the start, where the install is tried today.
            # It runs after every step, the state commit and the summary, and nothing in the tick
            # imports after it: the package may be a new one by the time it returns.
            from asf import upgrade
            try:
                upgrade.install_due(product.name)
            except Exception as e:  # noqa: BLE001 — an install at the exit never fails a tick
                print(f'upgrade: the exit install did not run ({type(e).__name__}: {e})')
    ```
    `_tick(args, product)` is today's `cmd_tick` from `fresh = getattr(args, 'fresh', False)`
    (`:343`) down, with the `product = env.load_product(...)` line dropped (the wrapper owns it) and
    the `dry_run` branch dropped (the wrapper owns it). The `finally` covers every return: the
    shadow one, the `StepError` one, the `manifest` one, the parked one (`upgrade.waiting`), the
    `another tick of <p> is running — skipped` one, the ordinary one, and a raise. Because the whole
    body moves, the product tick lock (`lock.close()` at `:380`) is already released when the
    attempt runs — an install must not hold a lock the next tick waits `DAILY_LOCK_WAIT_S` for. A
    parked tick is the cheapest installer the factory has: it does no work at all, and it exits into
    a floor one process smaller than when it started. Note for the reader of `_run_steps`: the
    "the install was upgraded under this tick; its steps run on the next tick" line
    (`asf/tick/tick.py:417-420`) belongs to the *start* install and is unaffected — an install at
    the exit has no steps left to spoil.
