## What the cut costs, measured

The spec's C7 is the argument against this cut, in the spec's own words: *"Otherwise the guard is
theatre: the launch defers, and the lane pass minutes later rebuilds the branch on the trunk and
pushes it — the same supersede, one call site over."* The lane half is `T-0585`, and it is going.
So the question the cut raises is whether `T-0584` still buys anything. Measured in this checkout,
it does, and the bound is exact.

`Lane.drop_copies` (`asf/harvest/lane.py:2278-2340`) rebuilds a branch carrying **either** of the
two reasons the launch guard would defer for — copies of trunk commits, or a merge of the trunk
(`:2301-2305`) — which is the same set, so there is no shape of branch where the lane cannot
undo the launch's deferral. But it refuses to do it **while a session holds the branch**:

```

        if f.get('live'):
            self.out(f'trunk history on {b} ({what}): a live session holds it — the rebuild '
                     f'waits for it to end')
            return None
```

A launch deferral is immediately followed by a live session on that branch — the launch *is* the
session starting. So for the window the card is about, the run the launch deferred to runs to a
verdict, and the lane cannot take its place. **`T-0584` alone fixes the card's own incident**: the
18:23Z push that re-dated all five of PR #858's commits with no content change is a launch rebase,
and it does not happen while run `36262385912` is in flight.

What the cut leaves behind is the *other* window: a branch with trunk history and **no** live
session — sitting in `PUSHED` or `BACK` between rounds — is still rebuilt and pushed by the next
lane pass, and whatever run is going there is still thrown away. That is the residual, it is
exactly `T-0585`'s scope, and the Drop section names it as uncovered rather than as fixed.

**The cut introduces no livelock.** C9's argument for the fourth Task was that a deferred push can
strand a PR for ever: with `strict` branch protection on, a behind branch cannot merge, and the
push that would update it is the one the guard defers. It does not bite on `T-0584`, because the
launch rebase no longer fires for a branch that is merely behind the trunk at all —
`trunk_rebase_needed` returns `''` for the `plain` shape, pinned case by case at
`tests/test_workers.py:605-614`. The only exception the launch site can claim is `CONFLICT`, and
`verdict` admits it for an S1 too (`asf/ci_flight.py:101-105`). So there is no branch whose only
route to mergeable is a push this Task defers; every deferral here is a wait of one CI run, and the
next launch on a concluded run does the rebase.
