## The one thing the drop leaves broken on the trunk

This is the only part of the cut that is not simply "less", and it is why the drop below carries a
`NEEDS OPERATOR` beside it.

Task 2 landed the *reader* of the product key, and Task 5 was to land its *declaration*. With Task 5
dropped, the two halves are split across the cut:

- `step_silence_seconds(product)` reads `_qcfg(product).get('step_silence_min')` (`:477`) and
  honours it — `'off'` gives `0`, the watch down.
- `step_silence_min` is **not** in `FIELDS` (`:304-306`), and `config_problems` reports every
  `ci.queue` key outside that closed list (`:751-753`).
- `env.load_product` **raises** `ConfigError` on any problem (`asf/env.py:881`).

Measured here:

```
FIELDS has step_silence_min: False
config_problems: [('ci.queue.step_silence_min', 'is not a field of ci.queue (mode, history, …)')]
step_silence_seconds reads it anyway: 0
default for a product that cannot declare it: 600
```

So a product file that writes `ci.queue.step_silence_min: off` does not stand the watch down — it
stops loading at all, and every `asf` command against that product raises. For every product that
*does* load, the key is absent and the limit is the module default, ten minutes, hard-wired. D12 is
the decision this contradicts, in its own words: a rule that cancels CI runs needs one key to stand
down *without giving up the queue*. The only stand-down left is `ci.queue.mode: off`, which gives up
the queue entirely.

The suite is green over this, and the reason is worth recording: the three landed tests that drive
the key build the product in memory — `env.Product('p', {'ci': {'queue': {'step_silence_min': …}}})`
at `tests/test_ci_step_silence.py:96`, `:101`, `:259` — exactly as the plan's Task 2 step 5 asked,
"so the judge is tested with no file and no `config_problems` in the way". Nothing puts the key
through the validator, so nothing fails. Task 5's `ConfigTests` was the class that would have.

**This replan does not fix it**, because the fix is Task 5's first step and the decision is the
scope: adding it back as a new Task would be re-minting the card the cut removes. It is one line in
`FIELDS` plus the validator clause PD8 specifies, it is not covered by any Story left with a Task,
and it needs an operator's ruling on whether to carry it as a Bug against the landed watch or to
leave the threshold a constant. The `NEEDS OPERATOR` line in this session's report says so.
