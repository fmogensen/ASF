## What the cut leaves standing

The landed half is whole, and it is the card's second Expected bullet in full: `asf doctor` prints
one `clock install` row per product clock naming the install, its sha, its distance from
`origin/main`, and RED on an editable, checkout, unplaceable or unmerged one — `check_clock_installs`
(`asf/doctor.py:413-453`) over `asf/clockinstall.py`, with the repair named on the row
(`install.sh <product> <ref>`, `:426`). Nothing in it depends on the dropped Task: `clockinstall`'s
only product-code consumer is `doctor` (`grep -rn clockinstall asf/`: `asf/doctor.py:39`, `:60`,
`:419`, `:423`, `:429` and nothing else), so the cut leaves no dead module and no dead function.

What the cut leaves **unbuilt**, measured at this sha rather than quoted from the card:

- **`asf upgrade` still reinstalls one venv.** `upgrade_command(url, ref)` is still
  `['pipx', 'install', '--force', f'git+{url}@{ref}']` (`asf/upgrade.py:354-355`) and
  `PACKAGE_NAME = 'asf-factory'` (`:54`) is still the only venv it touches or verifies. On a host
  that ticks from a suffixed pinned install, an upgrade still prints a new sha for an install no
  clock runs. The doctor now *says so* on every run — that is the whole of the Feature's answer.
- **`docs/guide/upgrading.md:37-38` stays false as written** on such a host: *"The package is
  shared across products — one `asf upgrade` upgrades it for all of them."* It is in no Task's
  `writes:` after this cut.
- **The rollback sha is still not recorded or printed.** `record_last` writes `{'sha', 'at'}` and
  overwrites the sha before it (`asf/upgrade.py:267-268`); `read_last` (`:257-264`) is unchanged.
  `asf upgrade --to <sha>` — the card's rollback *command* — already exists and is already
  documented (`docs/guide/upgrading.md:25-34`), so what is missing is only the sha to type.
- The card's other two Expected bullets were already true before this Feature and stay true: the
  scheduled step runs (`asf/tick/tick.py:409`, the tick's drift report calling `upgrade.cmd_upgrade`
  under `upgrade: auto`), and refusing while sessions are in flight is F-0207's, spec'd out of this
  card from the start (C16, spec `## Out` (a)).
- One knowing residue: `ClockInstall.suffix` (`asf/clockinstall.py:34`, set at `:153`) is now read
  by no caller but its own tests — its one planned consumer was `targets()`. It is landed work on a
  landed dataclass and is **not** removed here.
