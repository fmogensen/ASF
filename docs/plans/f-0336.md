# Plan F-0336 — one Task, because every cut either strands a Story's fence or lands a module nothing calls

Epic: E-0003 — ASF 0.3 — autonomous delivery. Spec: `docs/specs/f-0336.md` (approved on
`spec/F-0336` at `76a9debed`, not yet on the trunk). Branch: `plan/F-0336`, cut from `origin/main`
at `dce5aac92`.

**One Task, one wave.** The spec joins two halves that only exist together: a correlation across
open pull-request heads that only the kernel holds, and a quarantine the factory already reads.
Measured, every candidate cut through it either strands a Story's fenced acceptance across two
Tasks or lands a pure module with no caller in the package — the second being the defect this
product files cards about (**PD1**).

Wave order: **1**. One wave, one Task. Nothing waits on anything and nothing runs beside it.

The plan carries the spec's scope and no more. Fourteen rows below correct or complete it; the
corrections are measurements, not widenings. The four that change what a coder writes first: the
footprint is **thirteen** files, not §4's twelve, because `tests/kernel/fakes.py`'s record port has
neither the five new `file_bug` keywords nor a `quarantine` method, and 43 test modules build on it
(**PD2**); `asf/record/ids.py` needs **no** edit, because `write_new_item` already takes
`acceptance=` and a free typed-field dict — but `file_bug` hardcodes the main-red Bug's History
reason and the field filter lets `False` through, so each new field is written only when truthy
(**PD3**); a kernel entry in the shared `quarantine` list changes the **floor's outcomes** without
touching a line of the floor's code, because `asf.flake.active` matches on the *job* and `triage`
reads it to triple its re-run budget (**PD5**); and `save_plan` does not write `Plan.flakes`, which
the spec's Records table says lands in `kernel-plan.json` (**PD6**).

## What this plan leaves unbuilt, and why

Everything in the spec's **Out** stands untouched and this plan adds nothing to it: **no re-run is
asked for to prove a flake** (the evidence is correlation across heads, D1, and `asf.flake.triage`'s
re-run path is the floor's); **the floor's seven-day job quarantine keeps its behaviour** —
`settle`, `triage`, `infra_rerun` and `ci.quarantine_days` are not edited, and the kernel's entries
live beside theirs in the same list, told apart by `where: kernel` and their own 48-hour cap
(**PD5** records what that sharing does change, which is an outcome and not a line of their code);
**the flake is not fixed** here — the Bug is the fix session's and nothing edits, skips or xfails a
test; **a quarantined check is never dropped from the landing gate** (D7); **a red with no readable
key is no signature** and is never counted, quarantined or filed (D3); and **only an open pull
request's head counts as a source** — no batch sha, no trunk red (D4).

Five things this plan deliberately does not do:

- **It does not touch `docs/specs/f-0336.md`.** PD2 through PD14 correct or complete the spec on
  points of fact and all of them are recorded above, in this plan's decisions, as the binding told
  this session to do. The spec's six Story declarations are what the record mints the cards from
  (measured: `idcheck.declared_stories` over the spec at `76a9debed` returns exactly
  `S-122805 … S-122810`), so editing it is the one change that could strand this Feature's Stories.
- **It does not widen `asf.flake.active` to match a signature.** Its per-job match (**PD5**) is
  what the floor's own `settle`/`triage` rely on, and narrowing it would change the lane's verdict
  on every floor entry. The kernel reads its own entries by signature instead, which costs one
  function (`flake.live`) and leaves the floor exactly as it is.
- **It does not widen `dor.test_refs`.** The spec's Out says so, and it is the record's grammar read
  by every card: on a product whose tests are not `*.py` the filled Bug still fails the Definition
  of Ready's test clause and a groom-fill fills it.
- **It does not add a second state file, a ledger, an event or a metrics row.** The sightings live in
  `flake-triage.json` beside the quarantine (D2), pruned where pruning already is, and the only new
  write paths are one port method and one loop step, both already patterned.
- **It does not edit an open flake Bug.** A repeat inside a cycle adds a source to the entry, never
  a line to the card, and the groom's `add_evidence` path for repeats of one symptom class stays as
  it is. A signature whose symptom class someone *else*'s open Bug owns gets no card and no entry at
  all (§1.4 step 2).
