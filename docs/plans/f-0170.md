# Plan F-0170 — the definition first, then the tick that writes the order

Epic: E-0001 — ASF 0.1 — a working factory. Spec: `docs/specs/f-0170.md` (approved). Branch:
`plan/F-0170`.

Three Tasks, one per Story, cut so that **the rule that decides what an overlap is lands before
anything writes an order under it**:

1. **one definition, two readers** — `invariants.unordered_overlaps`, `check_i3`'s `after:`-aware
   guard, and `asf/record/check.py`'s own Active×Active loop deleted in favour of the same call.
   A **narrowing only**: nothing new is refused, and no card is written. After it lands the audit
   still reads 54 (PD2) — the four findings it drops are the two pairs the record has already
   ordered — and the rest wait for Task 2.
2. **the tick writes the order** — `widen_footprint.serialize_overlaps`, run by the health step
   after `revert_overlaps`, giving the later-minted card of every unordered Active overlap
   `after: <the earlier>`, one History line and one commit. This is the Task that takes the audit
   to zero.
3. **a step no clock runs fails the install that left it there** — `doctor.clockless_steps` and
   step 8's use of it. Independent of the other two in every way: no shared file, no shared
   concept, no order.

Wave order: **Task 1 and Task 3 together, then Task 2.** Tasks 1 and 3 both carry `after: none`
and their `writes:` are disjoint, so they run in one wave; Task 2 waits on Task 1 because
`serialize_overlaps` calls `unordered_overlaps` and there is nothing to call until Task 1 lands.
All three footprints are pairwise disjoint, so the queue never serialises them for the footprint's
sake — only Task 2's `after:` orders anything.

**Read PD3 and PD4 before writing a line of Task 2**, and **PD5 before touching `check.py`**.
PD3 is a measured defect in C4's cycle-freedom argument: it holds only if the pass re-reads
reachability after every edge it writes, and a coder who computes the candidate list once writes
three edges too many and loses the proof. PD4 is a measured disagreement between the record and
the index about which pairs are already ordered — the tick pass must read the record, which is one
sentence of the spec's `## The design` §1 corrected. PD5 is that P4 undercounts `check.py`.

**PD7 retires half of the card's second half:** the operator's `products/asf.yaml` already carries
`groom` on its clock, so `asf doctor` prints no `NEEDS OPERATOR` line today and C8's operator edit
is already done. Story 3 is still wanted — it is the guard that would have caught it — but no
`NEEDS OPERATOR` line is printed by this session.

The whole-tree fences of the spec's acceptance block 5 bind all three Tasks, so all three Gates
carry them beside their own commands.

### Task 1: one definition of the overlap that violates I3, and both of its existing readers on it
stories: S-36850
writes: asf/invariants.py, asf/record/check.py, tests/test_invariants.py, tests/test_record_stage.py, tests/test_backlog.py
after: none

The spec's `## The design` §1 in full: `_intersecting` becomes the public `unordered_overlaps`,
reading the pair's order as well as its paths (C1); `check_i3` calls it and gains C3's `after:`
clause; and `asf/record/check.py`'s four-deep Active×Active loop is deleted in favour of the same
call (C2).

**This Task writes no card and refuses nothing new.** It is a narrowing in three directions and
only three: an ordered pair stops being a finding, a `removed:` card stops being judged by the
plain check, and a pair intersecting on several globs stops printing a line per glob (PD5). On the
live record it takes the audit from 58 findings to 54 — the two pairs the record has already
ordered (PD2) — and everything else waits for Task 2. Nothing is refused that is not refused
today: `new = unordered(after) - unordered(before)` is a set *difference*, and every current writer
of `after:` is additive (P9), so an added edge only ever removes pairs from that set.

Read **PD5** before writing `CheckOverlapTests` — the count a pair produces today is not 1 — and
**PD3** for the shape of `ordered()`, whose contract the pass in Task 2 depends on: it answers
against the edge map it is handed, at the moment it is asked.

`record_audit` is **not** changed: it is the read-only view of the same rule, and its
`{p: None for p in paths}` staging (which makes every standing pair "new") is what a whole-record
audit means. `cmd_check_invariants`' line format and exit code are untouched. `core.writes_intersect`
is untouched — widening the path test would *create* violations, which is the spec's `## Out`.

**Files**

- `asf/invariants.py` — `_after_edges(tasks)`, `ordered(edges, a, b)` and `unordered_overlaps(tasks)`
  as the spec's §1 writes them, with its three docstrings; `_intersecting` is **replaced** by
  `unordered_overlaps`, not kept beside it (C2: one implementation). `check_i3` builds
  `{id: {'type', 'state', 'writes', 'after', 'removed'}}` from `_record(ctx)` and
  `_before_record(ctx)` through the existing `_state`/`_machine` helpers, compares the two as sets
  of **pairs**, and its `continue` guard at `:240` compares `after:` as well as `writes:`. Its
  docstring says which of the two facts each half of the guard is there for. `_active_writes`,
  `_writes_of`, `_finding`, `record_audit` and every other invariant are untouched.
- `asf/record/check.py` — the `# Active task writes: overlap` block (`:352-366`) becomes a loop
  over `unordered_overlaps(...)` built from `canonical`, keeping its own finding text
  (`writes: {g1!r} intersects Active task {t2_id}'s {g2!r}`) byte for byte and its line number from
  `find_line(rec, 'writes')`, filed at the lower id of the pair as it is today. `writes_intersect`
  stays in the import list only if something else in the module still uses it — if nothing does,
  it comes out, and `asf.invariants` goes in (no cycle: PD11).
- `tests/test_invariants.py` — a new `class OrderedOverlapTests`, matching the module's existing
  base-class convention for a test that needs a record on disk, and never a subclass of another
  test class in the module.
- `tests/test_backlog.py` — a new `class CheckOverlapTests`, same rule.
- `tests/test_record_stage.py` — expected **unchanged**. It is in `writes:` because
  `I3NeverIntersectingWrites` (`:210-247`) is the proof that a seeded unordered pair is still
  refused before commit, and a coder who finds it needs a word changed must be able to change it
  rather than widen a footprint mid-Task. A diff that touches it is a fact to report, not a
  failure.

**Steps**

1. `_after_edges(tasks)` — `{id: [after ids]}` over **every** Task in the mapping, Active or not.
   A Closed or removed Task is no pair of its own but is a link in a chain (PD4 is the live proof:
   `T-0058 → T-0057 (removed) → T-0056`).
2. `ordered(edges, a, b)` — reachability in **either** direction, transitively, memoised, and
   evaluated against the `edges` it is given. Do not cache on the module or on `tasks`: Task 2
   mutates the map between calls (PD3), and a memo that outlives an added edge is that Task's bug
   planted here.
3. `unordered_overlaps(tasks)` — `[(a, b, glob_a, glob_b)]` with `a < b`, the **first** intersecting
   glob pair, over Active non-`removed:` Tasks carrying `writes:`, filtered by `ordered()`.
   Reachability runs only for a pair whose globs already intersect, so the cost is the number of
   intersecting pairs, not the square of the record.
4. `check_i3`'s guard: `if before and _writes_of(before) == _writes_of(after) and _after_of(before)
   == _after_of(after): continue`. This is C3 — without it, one `after` removal silences a live
   overlap for good.
5. `check_i3`'s diff over **pairs**: `{(a, b) for a, b, *_globs in unordered_overlaps(...)}` before
   and after. Diffing the 4-tuples would re-report a pair whenever a different glob of the same two
   cards happened to be found first. The message, the two-findings-per-pair shape and the paths are
   unchanged (P1).
6. `check.py`: delete the four-deep loop, call `unordered_overlaps`, map each returned id back to
   its `canonical` rec for `add(rec, find_line(rec, 'writes'), …)`. One finding per pair now
   (PD5).
7. `OrderedOverlapTests` — the spec's acceptance 1, five rows:
   - a pair with no order → **two** findings, one at each card.
   - the same pair with `after:` naming the other, **each direction tried** → none.
   - a chain through a **Closed** Task (`A ← C ← B`, C Closed) → ordered, none. Add the removed-card
     variant beside it: it is the live case (PD4) and costs one line.
   - a writer that **removes** the `after:` id while the `writes:` still intersect → refused at the
     card it wrote. This is C3, and it is the only row that fails if step 4 is skipped.
   - a writer that only **adds** to `after:` → not refused, as every current writer does (P9).
8. `CheckOverlapTests` — the spec's acceptance 2, four rows: one `intersects Active task` line for
   an unordered pair; **exactly one** for an unordered pair that intersects on **two** globs (PD5 —
   this row is two lines today); none for an ordered pair; none for a `removed:` card that is
   otherwise Active with intersecting `writes:` (PD5: this case does not occur in any real record
   today and must be built).
9. Do not add a cap, a config key, a new module or a `shared_paths` exemption. All four are the
   spec's `## Out`.
