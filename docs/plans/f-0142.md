# Plan F-0142 — the pair of lines, the reader that reads them, the prose that says both

Epic: E-0001 — ASF 0.1 — a working factory. Spec: `docs/specs/f-0142.md` (approved). Branch: `plan/F-0142`.

Three Tasks, cut the way the spec's `## The design` is sectioned — and the way the card itself is: a
writer, a reader, and the page that documents the contract between them. Task 1 is
`asf/tick/tick.py`: `step_timing_line` becomes `step_end_line`, gains `step_start_line` as its pair,
and `_run_steps` prints the start line at each of the two points a step actually begins. Task 2 is
`asf/doctor.py`: one bounded tail reader that `_log_tail` is rewritten over, `current_step` scanning
that tail backwards for a dangling start line, and one field plus one `OK → YELLOW` transition on the
SCHEDULER job row. Task 3 is the two guide pages both shapes are already documented in, and the test
that reads them back from the checkout.

The chain is linear because the reader reads what the writer writes and the prose describes both.
Task 2 waits on Task 1 not only for the shape but because one of its own cases feeds
`tick.step_start_line`'s real output into `current_step` (T2 step 8) — the one assertion that stops
`_STEP_START_RE` and the formatter drifting apart. Task 3 waits on both, because the sentences it
writes quote what Tasks 1 and 2 print.

Wave order: **1 → 2 → 3** — in `after:` terms, 1 with `none`; 2 after 1; 3 after 1 and 2. The three
`writes:` sets are disjoint, so the queue costs nothing beyond the dependency itself.

§Acceptance tests' last fence — the whole suite and both tree fences, as the pull request's CI runs
them — binds every Task, so every Gate below runs `python3 tools/run_tests.py` beside its own.

**Steps**

1. Two imports (P12, re-verified in PD12): `re` in the stdlib block at `:52-55`, and
   `from asf.workers import lifecycle` beside `from asf.workers import pool` at `:58`. `pool` already
   imports `lifecycle`, so no cycle is opened and nothing new is pulled into the doctor's import
   graph.
2. `LOG_TAIL_BYTES = 1024 * 1024`, `_STEP_START_RE` and `_STEP_END_RE`, all three with the spec's
   comments byte for byte, beside `NEVER_EXITED_INTERVALS` (`:657`).
   `_STEP_END_RE = r'^\[step:([a-z-]+)\] \d+\.\ds'` matches the pre-F-0142 line as well as the new

3. `_log_lines(path, limit=LOG_TAIL_BYTES)` with the spec's docstring byte for byte, and **PD5's

   `os.path.getsize`, `open(path, 'rb')`, `seek(max(0, size - limit))`, read, decode `utf-8` with
