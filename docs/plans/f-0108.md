# Plan F-0108 — release 0.1 for feedback: the first-user docs, the feedback channel, and the gate a tag is cut behind

Epic: E-0001 — ASF 0.1 — a working factory. Spec: `docs/specs/f-0108.md` (approved). Branch: `plan/F-0108`.

Eleven Tasks. The spec's §2 is sectioned by the instrument that gains the surface, and the cut
follows it, with one rule laid over the top: **each of `asf docs check`'s five checks lands in the
same Task as the page that satisfies it.** Check 1 (the pages exist) and check 2 (the links
resolve) land with the reader itself, because the move makes them true in one commit; check 3 (a
`###` per doctor row) lands with the troubleshooting page that carries the 34 headings; checks 4
and 5 (every command, skill and config key named) land with the operator page that names them. A
check written before its page would be red on this repository from the moment it landed until the
prose caught up — and §3's `RepoIsCleanTests` fence would be red between two Tasks of one plan
(PD9).

Task 1 is `asf/docs.py` — the command, the resolver, the anchors and the `--at` tree form (§2.2).
Task 2 is `doctor.ROWS` and the `ast` reader that holds it to the source (§2.3). Task 3 is the
move: four `git mv`s, every inbound and intra-page link, and the README blocks (§2.1, D1). Task 4
is the two pages that are new writing, `docs/quickstart.md` and `docs/concepts.md`, and the bound
(D4). Task 5 is `docs/operator.md` and checks 4 and 5. Task 6 is `docs/troubleshooting.md` and
check 3. Task 7 is the four issue templates (§2.4). Task 8 is `asf feedback sync`'s in half and
the `issue:` intake header (§2.5). Task 9 is the out half and the `groom` step's call (§2.6).
Task 10 is the tag gate and the two CI steps (§2.7, §2.8). Task 11 is `release-readiness`'s docs
criterion (§2.9).

Three Tasks need nothing landed and start at once — Task 1 (the new module), Task 2 (a constant
and a test over one file nobody else writes) and Task 7 (four yaml files in a directory that does
not exist yet).

Wave order: **1 ‖ 2 ‖ 7 → 3 ‖ 8 → 4 ‖ 9 ‖ 11 → 5 → 6 → 10**.

The four docs Tasks (3, 4, 5, 6) run one after another whatever their `after:` says: they all
write `tests/test_docs.py`, and three of them write `asf/docs.py`. That is the same queue F-0107's
plan accepted for `tests/test_install.py` (PD11) and the wave above is the dependency order, not a
promise of concurrency. One more pair queues for the same reason: Tasks 3 and 8 are in the same
wave and both write `docs/products.example.yaml` — Task 3 re-points its one `guide/operating.md`
reference, Task 8 adds the `feedback:` block. Every other pair inside a wave has a disjoint
`writes:`, checked line by line.

§3's last fence — `asf docs check`, both shell gates and the docs and feedback suites — binds
every Task, so every Gate below runs `python3 tools/run_tests.py` beside its own.

### Task 1: `asf/docs.py` — the resolver, the anchors, the tree at a sha, and `asf docs check`

  `anchors(text)`, `link_complaints(pages, read, exists)`, `check(root, conv)`,
  `check_at(repo, sha, conv)`, `cmd_docs`, `register`
- `asf/cli.py` — one `from asf import docs` / `docs.register(sub)` pair beside `ci_pool`'s
  (`asf/cli.py:350-353`)

- `asf/conventions.py` — `DEFAULT_DOC_PAGES` beside `DEFAULT_DOC_PATHS` (`:182`) and

**Steps**

1. `asf/conventions.py`: `DEFAULT_DOC_PAGES = ('README.md', 'docs/README.md',
   'docs/quickstart.md', 'docs/concepts.md', 'docs/operator.md', 'docs/troubleshooting.md',
   'docs/guide/*.md')`, and `doc_pages` on `Conventions` reading it. It is **not** `doc_paths`,
   whose job is to classify a landing branch and which would sweep every spec, plan and review
   into the link check (§2.2). The docstring says which is which.
2. `asf/docs.py`, stdlib only, read-only, opening nothing outside the repo root. The module
   docstring names the single meaning of "the docs build" in this repository: `asf docs check`
   exits 0. No HTML, no site, no theme (§1.2).
3. `_skip_target(t)` — the rule `asf.views.readme._skip_target` (`asf/views/readme.py:272`) states,
   lifted as a function of its own so both readers state it once: empty, a bare `#anchor`,
   absolute, `~`- or `$`-prefixed, or carrying a URL scheme.
4. `anchors(text)` — every `#`-heading slugged GitHub's way (D2): lower-case, drop everything that
   is not a word character, a hyphen or a space, then one hyphen per space. **Runs are not
   collapsed** — PD13 is the measured reason, and a comment on the line says so, because the next
   reader's instinct will be to collapse them.
5. `link_complaints(pages, read, exists)` — the one resolver, taking its two readers as arguments
   so the worktree form and the `--at` form share every rule and neither can drift. A target
   resolves relative to `os.path.dirname` of the page that carries it; a fragment resolves against
   `anchors()` of the target page, or of the carrying page when the target is the page itself.
   Inline-code paths are not checked at all (D2). Each complaint is `(path, line, what)` with the
   line of the **carrying** page.
6. `check(root, conv)` — the worktree form: `read` is `open`, `exists` is `os.path.exists`, and
   the page set is `conv.doc_pages` expanded with `glob`. Returns the complaint list.
7. `check_at(repo, sha, conv)` — every read through `git show <sha>:<path>` and every target
   through `git cat-file -e <sha>:<target>`, the shape `asf.customer_content.tree_hits`
   (`asf/customer_content.py:152-164`) uses to scan a tree at a sha: no checkout, and a tree that
   cannot be read is not a clean one — it returns `None`, which Task 10's gate reads as "could not
   decide" and never as "clean".
8. `cmd_docs` — `asf docs check [--product P] [--at <sha>] [--json]`. One line per complaint,
   `path:line: what`, then `docs: N complaint(s)` and exit 1; or `docs: clean — <n> pages, <m>
   links` and exit 0. `--json` prints
   `{"ok": bool, "complaints": [{"path", "line", "what"}], "pages": n, "links": m}`. Nothing is
   written on any form.
9. `asf/cli.py` registers it; `asf/surface.py` declares it (PD5) and `tests/test_surface.py`'s
   count goes to 50. `asf --help` must still build: `surface.apply` raises `SurfaceError` on a
   command registered and not declared.
10. `tests/test_docs.py`: `LinkTests` over fixtures — a page-relative target resolves
    (`docs/guide/a.md` → `b.md` is `docs/guide/b.md`, not `b.md`); a missing file is one complaint
    with the carrying page's line; a URL, an absolute path, a `~` path, a `$VAR` and a bare
    `#anchor` are skipped; an anchor is matched under D2's slug rule with
    `` ### `/asf:status` — FACTORY STATUS `` → `asfstatus--factory-status` pinned as its own case;
    inline code holding a slash is never a complaint. `TreeTests` — `--at <sha>` over a fixture
    repo reports the same complaints as the worktree form on the same content and opens no working
    tree.
11. Not in this Task: `RepoIsCleanTests` (Task 3 — the four pages do not exist yet, so check 1
    would be red), `CoverageTests` (Tasks 5 and 6), `PageSetTests` (Task 3).
