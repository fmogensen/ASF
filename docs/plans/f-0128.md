example yaml, and the two other guide lines that spell the key set as `paths` and `commands`.

asserts a barred card in a real digest, Task 4 describes a bound that does not exist until the clause
does. Tasks 3 and 4 are independent of each other and their footprints are disjoint, so they run

Wave order: **1 → 2 → 3 ‖ 4**.

### Task 1: `areas:` — a third declared recogniser, and `area_class` over it
stories: S-34000
writes: asf/approvals.py, tests/test_approvals.py
after: none

The spec's `## The design` §1, whole and alone. `signals()` accepts one more key, `recognisers()`
lists it so `asf approvals` prints it and `asf doctor` counts the class as recognised, and a new
`area_class()` resolves an area string to the first non-`auto` class that declared it. No caller in
this Task: nothing in the product behaves differently until Task 2 reads it.

**Files**

- `asf/approvals.py` — `signals()`'s key set and per-class dict; `recognisers()`'s `signal area:`
  words; `GROOM_CLASSES`; `area_class(product, area)`
- `tests/test_approvals.py` — the key set's cases beside `test_signal_under_an_unknown_class_is_a_config_error`
  (`:81-86`), `area_class`'s cases, the `asf approvals` row, and the doctor's `blind` list

**Steps**

1. `signals()` (`asf/approvals.py:199-219`): the validation set becomes `{'paths', 'commands',
   'areas'}` and the per-class dict gains `'areas': list(spec.get('areas') or [])`. The
   `ConfigError` message becomes `keys must be 'paths'/'commands'/'areas', not <bad>` — the same
   grammar, one key longer, still naming every offending key. The docstring's return shape gains
   `'areas': [...]`. Nothing else in the function moves: an unknown class is still an error, and a
   class the product does not name is still simply absent.
2. `GROOM_CLASSES = tuple(c.name for c in CLASSES if c.read_by == ('groom',))`, beside
   `MERGE_CLASSES` (`:568-569`) and derived the same way, so the two classes D5 skips are read off
   the catalogue rather than spelled twice. Verified here to be exactly `decide_feature`,
   `decide_bug`.
3. `recognisers()` (`:1306-1319`): one line after the `signal command:` line —
   `words += [f'signal area: {a}' for a in spec.get('areas') or []]`, the spec's own expression byte
   for byte. Order is `paths`, `commands`, `areas`, which is the order `signals()` returns and the
   order the guide documents. `_builtin_recognisers` is **not** touched: `areas` are declared, never
   built in.
4. `area_class(product, area)`, shaped on `path_class` (`:542-565`) and placed beside it, with the
   spec's docstring byte for byte. It walks `CLASSES` in catalogue order; skips `c.name in
   GROOM_CLASSES`; takes `sig.get(c.name, {}).get('areas', [])`; matches with case-insensitive
   `fnmatch` (D8 — `fnmatch.fnmatch` on `area.strip().lower()` against `glob.strip().lower()`, not
   `fnmatchcase`, and not `_match_glob`, which is a path helper and would split on `/`); and returns
   `(c.name, level)` for the first match whose `level_of` is not `auto`, else `None`. It fails soft
   exactly as `path_class` does — `try: sig = signals(product) except env.ConfigError: sig = {}` —
   because a groom that cannot parse the config must still render a file.
5. An empty or whitespace `area` matches nothing and returns `None` before any walk: `fnmatch('', '*')`
   is true, and a product that declares `areas: ['*']` must not thereby bar every card that carries
   no area. Task 2's clause already guards on `typed.get('area')`, but `area_class` is a public
   function and must not depend on its caller for that.
6. `tests/test_approvals.py`, the key set: `areas` under a known class loads and comes back as a
   list; `{'globs': ['x']}` is still a `ConfigError` (`:85-86` unchanged) and its message names
   `globs`; a class declaring all three keys returns all three; `areas: []` and an absent `areas:`
   both give `[]`; a non-dict spec and an unknown class are still errors.
7. `area_class`'s cases: `spend_money.areas: ['billing']` at `human-now` resolves `billing` →
   `('spend_money', 'human-now')`; `Billing`, `BILLING` and ` billing ` resolve the same (D8);
   `billing/*` matches `billing/invoices` and not `billing`; `pay*` matches `payments` and
   `payroll`; an undeclared area is `None`; an empty area is `None`; `spend_money: auto` with the
   same declaration is `None` (the "not `auto`" half); two classes declaring the same area resolve
   to the **earlier one in `CLASSES`**, asserted with `spend_money` and `touch_legal` so catalogue
   order is pinned; `decide_feature.areas` and `decide_bug.areas` resolve `None` however the level
   is set (D5, both directions); `touch_amendable_set.areas` always resolves, since that class takes
   no other level (PD10); and a product whose `approval_signals` is malformed enough to raise from
   `signals()` gives `None` rather than propagating.
8. The printed surface: `format_matrix` for the yaml above prints `signal area: billing` in
   `spend_money`'s `recognisers` cell, after its `signal path:` cell and in declaration order for
   several areas; and `check_doctor` does **not** list `spend_money` under `held but unrecognisable`
   once it declares only `areas` — the "counted as recognised, not blind" half of the Story. The two
   decide classes are still absent from that list whatever they declare, because `_CODE_RECOGNISERS`
   already gives them a word (`:1277-1278`), asserted so the spec's P13 is held by a test rather
   than by a measurement.
