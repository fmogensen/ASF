# Plan F-0283 — six Tasks: the hook's own guard, the tick that puts the dispatcher back, the shim, one `which_asf`, the stale-body report, and the record's own hooks

Epic: E-0001 — ASF 0.1 — a working factory. Spec: `docs/specs/f-0283.md` (approved).
Branch: `plan/F-0283`.

**Six Tasks, six Stories, three waves.** The spec's `## The design` is six sections over six
surfaces and C13 already settles the split: one Task per Story, because four of the six write
`asf/hooks.py` and are serialised by footprint whatever the split, while a split by surface gives
each Task one question and one fenced test command. Two of the six — the tick's re-assertion
(`asf/dispatch.py`, `asf/tick/tick.py`) and the session shim (`asf/workers/githooks.py`) — touch
no path the other four touch, so they run in parallel with wave 1 from the first tick.

Wave order: **wave 1 — Task 1, Task 2, Task 3** in parallel (disjoint footprints, all
`after: none`); **wave 2 — Task 4**; **wave 3 — Task 5, then Task 6**. Tasks 1, 4, 5 and 6 all
write `asf/hooks.py`, so the queue runs them one at a time in any case; the `after:` lines fix
*which* order, because one of the four is a real code edge the spec's own ordering gets backwards
(PD1).

**Every precondition and every decision below was measured in this worktree at `9a3a897d6`, on the
real code, by throwaway probes under the scratchpad (six scripts, deleted before this commit; the
branch's diff is `docs/plans/f-0283.md` alone).** P1–P21 of the spec were measured at `b0d41d9a4`,
`b540c2fe1` and `2d855e8e6`; every row this plan leans on was re-measured here, and they all still
hold (PD6). The probes found four things the spec could not: one ordering inversion in its own
stated Task order (PD1), one latent regression in its §6 rewrite that turns a file `asf hooks
install` just wrote into one it calls foreign (PD2), one acceptance arm that cannot be proven in a
cloud container at all (PD3), and one of the six fenced acceptance commands that is **already red
at the trunk head**, for two reasons that have nothing to do with F-0283 (PD4).
