# B-0101 — plan: file-bugs mints Bugs with a real Description and Acceptance

Item: B-0101 — file-bugs mints Bugs with an empty Acceptance and no statement of what is wrong.
Epic: E-0001 — ASF 0.1 — a working factory. Branch: `fix/B-0101`. No spec exists; the Acceptance
below is the record.

## Cause

`_file_or_bump_bug` (`asf/tick/file_bugs.py`), the one write path every filer shares (CI,
refusal, rule-violation and invariant signatures), opened a freshly filed Bug's Description with
a bare evidence list — no line stating what was wrong. The Acceptance half was already correct:
`acceptance=info.get('acceptance') or [f"\`{sig}\` is not seen again"]` predates this fix and
every signature builder always supplies a non-empty `acceptance`, so a filed Bug never actually
carried the empty `- [ ]` the title describes — only the Description was bare.

## Task 1 — open the Description with the statement of what is wrong

writes: `asf/tick/file_bugs.py` `tests/test_file_bugs.py`

- Step 1: in `_file_or_bump_bug`, build the Description body as `info['title']` followed by a
  blank line and the `Evidence:` list, instead of the evidence list alone.
- Step 2: test, in `tests/test_file_bugs.py`:
  - `test_the_filed_bug_states_what_is_wrong_and_carries_a_real_acceptance` — files a Bug and
    checks the Description opens with the title (not a bare `- ` evidence line) and carries the
    evidence, and that the Acceptance is never the empty `- [ ]`.

## Acceptance

- [x] A filed Bug's Description opens with a line stating what is wrong (the title), before the
      evidence list — never a bare list of evidence lines
      (`tests/test_file_bugs.py::test_the_filed_bug_states_what_is_wrong_and_carries_a_real_acceptance`).
- [x] A filed Bug's Acceptance is never the empty `- [ ]`
      (same test).

## Accepted costs

None — the fix is a three-line change to one shared write path; both halves of the title were
already covered by the one new test.
