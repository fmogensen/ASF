# Plan F-0055 — the instrument is built before anything is measured with it

Epic: E-0002 — ASF 0.2 — self-improvement. Spec: `docs/specs/f-0055.md` (approved). Branch:
`plan/F-0055`.

Seven Tasks, cut by the spec's own §3 fences, because each fence is one `unittest` class family and
every Task's Acceptance is a fence copied byte for byte (PD1). Task 1 is the set and the loader and
the two hashes (§2.1, §2.2 — §3.1, §3.2), Task 2 the scorer, the exemption and the CLI (§2.4 —
§3.5), Task 3 the two pure levers and the one extraction (§2.3's first two adapters, §1.1's
`detect_kind` — §3.3), Task 4 the rules family, its adapter and the fixture product's first rule
card (§2.3's third adapter, §2.4's discovery — §3.4), Task 5 the determinism guard over all three
adapters (§1.4's purity row — §3.6), Task 6 the stream, the daily part and the `## Evals` section
(§2.5, §2.6, §4 — §3.7), Task 7 the freeze and the product hook (§2.7 — §3.8).

**The wave order is 1 → 2 → {3, 4, 6, 7} → 5** by `after:`, and one file by the queue: six of the
seven Tasks write `tests/test_evals.py`, because §3 puts eight acceptance classes in that one
module and names them byte for byte (PD4). Nothing here is shaped to run in parallel and nothing
is lost by that.

§3.9's fence binds every Task, so every Gate below runs `python3 tools/run_tests.py` and
`bash tools/check_generic.sh` beside its own — the second matters more here than anywhere: an eval
fixture is the easiest place for a name to hide, because it looks like data (§3.9, P12).

Every line, line number and behaviour cited below was read in this checkout at `cc5e77197`. The
Acceptance fences are the spec's bytes and say `python`; the Gates say `python3`, and why is PD13.

### Task 1: `evals/` and `asf/evals/set.py` — the set, the loader, the two hashes
stories: S-66954, S-66955
writes: evals/README.md, evals/manifest.json, evals/exemptions.json, asf/evals/__init__.py, asf/evals/set.py, tests/test_evals.py
after: none

§2.1 and §2.2: the directory that is not the suite, and the one module that reads it. Nothing
scores anything yet — the roster is empty (PD5) — and that is the point: the loader and the hash
are the instrument's identity, and they are provable with no adapter in the tree.

**Files**

- `evals/README.md` — why this is not the suite; how to add a lever; why a task is never edited
  (§2.1's own list). The three sentences that must be in it: an eval is frozen and scored as a
  rate; a wrong task is **deleted and replaced**, never edited, and the hash records that as a new
  instrument; a lever with only one polarity measures half an instrument.
- `evals/manifest.json` — `{"levers": [], "min_tasks": 2, "require_both_polarities": true}`, with
  no comment key: JSON, stdlib, the precedent being `sample/fake_script.json`.
- `evals/exemptions.json` — `{"exemptions": []}`; an entry is
  `{"lever": "<id>", "reason": "<why there is no pair yet>", "card": "<id>"}`, both strings
  required and non-empty.
- `asf/evals/__init__.py` — the package docstring: what a lever is, what a task is, and the one
  rule that separates this package from `tests/` (an eval is never edited to make it pass).
- `asf/evals/set.py` — `EvalError`; `Task`, `Lever`, `Set` exactly as §2.2's three frozen
  dataclasses; `ADAPTERS = ('matcher', 'brief-kind', 'rule-check')`; `default_root()`;
  `load(root=None)`; `lever_hash(lever)`; `set_hash(levers)`.
- `tests/test_evals.py` — new module; `SetLoadTests`, `SetHashTests`.

**Steps**

1. `asf/evals/__init__.py` and `asf/evals/set.py`, stdlib only (`dataclasses`, `fnmatch` is Task
   7's, `glob`, `hashlib`, `json`, `os`). No product name, no branch prefix, no `tools/*.sh` path
   literal and no `E-nnnn` id: `tools/check_generic.sh` and `tools/check_conventions.sh` refuse all
   four, and the `tools/[A-Za-z0-9_-]+\.(py|sh|json)` pattern (`tools/forbidden-conventions.txt`)
   is why a check script's path lives in `evals/manifest.json` and never in this package.
2. `default_root()` — `$ASF_EVALS_DIR`, else `evals/` beside the package's parent, the shape
   `rules.core_rules_dir` already has (`asf/rules/rules.py:56`); `None` when neither is a
   directory, which the caller reports (PD10). A product's own set is not this function's: it is
   `os.path.join(record_root, conv.evals_dir)`, passed in by the caller, and `conventions.evals_dir`
   is read for it — never the literal (PD10).
3. `Task`, `Lever` and `Set` as §2.2 writes them, `frozen=True`, `Lever.tasks` and
   `Lever.implements` tuples, `Set.set_hash` twelve hex characters.
4. `load(root=None)`: the manifest first (`levers`, `min_tasks`, `require_both_polarities`), then
   every `*.json` under each lever's `tasks` directory in **sorted path order**, then
   `exemptions.json`. A family entry (`"family": true`) expands to one lever per subdirectory of
   its `tasks` template's parent, the id being `rule:<dir name>` — with an empty roster this is
   dead code until Task 4, so write it once and let Task 4's fixtures be its first exercise.
5. The refusals, each an `EvalError` naming **the file and the key** (§2.2's list, and §3.1 asserts
   every one): an unknown `adapter` (not in `ADAPTERS`); an `expect` that is neither `fire` nor
   `no-fire`; a missing or empty `why`, `given` or `want`; a `lever` field disagreeing with the
   directory; a `*.json` under no lever's directory; a duplicate task `id`; an exemption for a
   lever that has a pair; an exemption with no `reason` or no `card`.
6. `lever_hash(lever)` — `sha256` over, per task in path order, the task's repo-relative path and
   the canonical bytes of its JSON (`json.dumps(obj, sort_keys=True, separators=(',', ':'))`),
   then the lever's own manifest entry canonicalised the same way; first 12 hex characters.
   `set_hash(levers)` folds each lever's hash in lever-id order the same way. Canonical, not raw:
   a reformat that changes no value must not fake a new instrument, and any change to a value must
   (§1.4, §3.2).
7. The hash is returned and **stored in no file** — `load` writes nothing, and neither
   `evals/manifest.json` nor `evals/exemptions.json` carries a hash field (§1.4).
8. `tests/test_evals.py` with `SetLoadTests` and `SetHashTests`, §3.1 and §3.2 assertion by
   assertion. Both build their fixtures in a `tempfile.TemporaryDirectory` — a miniature `evals/`
   of two levers is what §3.2's "leaves the other levers' alone" needs, and an empty shipped roster
   cannot provide it. `SetLoadTests` also loads the shipped `evals/` and asserts it loads, that
   every task's `lever` agrees with its directory, and that every task carries `why`, `given` and
   `want` — vacuous today, binding from Task 3 (PD5). `SetHashTests`' last case greps `evals/` and
   `asf/` for the hash it just computed and asserts it appears in neither.

### Task 2: `asf/evals/run.py` — the reading, the exemption, and the loud unrecorded lever
stories: S-66959
writes: asf/evals/run.py, asf/evals/adapters.py, asf/cli.py, tests/test_evals.py
after: Task 1

§2.4 and §1.4's exemption row: the scorer, the three-row table of what a lever without a pair
does, and `asf evals run | check | hash`. This is acceptance #4's whole machinery, and it lands
before any lever has a task — which is the honest order: the rule that a gap must be *recorded*
is what makes every later Task's exemption removal visible.

**Files**

- `asf/evals/adapters.py` — `Broken`; `ADAPTERS = {}`; `fires(lever, task)` — the dispatch, raising
  `EvalError` for an adapter name with no function. The two pure adapters are Task 3's, the rule
  adapter Task 4's.
- `asf/evals/run.py` — `Reading`, `LeverReading`, `Failure`; `score(eval_set, product=None,
  record_root=None)`; `print_reading(reading, out=print)`; `cmd_evals(args, ...)`.
- `asf/cli.py` — the `evals` subparser and its dispatch.
- `tests/test_evals.py` — `CoverageTests`.

**Steps**

1. `asf/evals/adapters.py`: `Broken(Exception)` carrying the line a check printed when it could
   say neither (§2.3); `ADAPTERS` as `{name: fires_fn}`; `fires(lever, task)` looking the lever's
   adapter up and calling it with `(task.given, task.want)`. An adapter that raises anything but
   `Broken` is the scorer's problem, not this module's — it does not catch.
2. `asf/evals/run.py`: the three record types of §2.4 — `Reading(set_hash, levers)`,
   `LeverReading(lever, lever_hash, passed, total, exempt, exempt_reason, unrecorded, failures,
   seconds)`, `Failure(task_id, why, expected, got, detail)`.
3. `score`: per lever, in manifest order, then the discovered `rule:<id>` levers (Task 4 writes
   that half; here the parameter exists and the roster is the manifest's). Per task: `fires` →
   `(fired, detail)`, `passed` when `fired == (task.expect == 'fire')`. `Broken` is a **fail** with
   `got: 'broken'` whichever polarity was expected (§1.4) — never a no-fire, never excluded from
   the total. Any other exception is a fail whose `detail` is the exception's first line.
4. The coverage rule, exactly §2.4's table: a lever with fewer than `min_tasks` tasks or missing a
   polarity is **not scored** — `passed = total = 0`, `exempt = True`, `lever_hash = None`; it is
   `unrecorded = True` as well when `exemptions.json` has no entry for it. A lever with a pair and
   an exemption entry is Task 1's loader error, so the two states cannot both be recorded.
5. `print_reading` — §2.4's printed shape byte for byte: the `== EVALS set <hash> — <p>/<t> passed,
   <n> lever(s) exempt, <n> unrecorded` header, one line per lever with its rate and lever hash, a
   `FAIL <task id>  expected <e>, got <g>` line and its `why:` under the lever it belongs to, and
   `exempt — <reason> (<card>)` for an exempt one. A rate is never printed for an exempt lever
   (§2.6's second rule; here it is `0/0` and the hash column is `—`).
6. `cmd_evals`: `run` scores, prints, and exits 1 when any task failed **or** any lever is
   unrecorded — the reading doubles as a gate (§2.4). `check` scores nothing: it loads, applies the
   coverage rule and exits 1 on an unrecorded lever, naming it and nothing else. `hash` prints the
