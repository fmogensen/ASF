# F-0076 — Session identity: every asf worker is distinguishable from every other, and from sessions that are not asf's — the plan

Binding spec: `docs/specs/f-0076.md`. This plan adds nothing it does not carry.

Every acceptance test the spec names lives in **one new file**, `tests/test_session_identity.py`,
and every Story's acceptance command addresses a class in it. So every Task writes that file, and
the `writes:` rule runs them one after another. Splitting the file into one module per Task would
change the spec's acceptance commands, so this plan does not split it and accepts the queue. The
order follows the dependencies the queue would impose anyway. The id comes first, because
everything else reads `session`. Observation comes next, because the pool and the alive rule both
read it. Then the pool, then the alive rule, and last the views that print all of it.

Five Tasks, five waves, one after another:

| 1 | T-9450 | the id, the registry line, the environment, the log line, the commit trailer | S-8150, S-8151, S-8152 |

| 3 | T-9452 | pool load across products and foreign sessions; the wave's per-product running check | S-8154 |
| 4 | T-9453 | alive means the same session — health, stall, the sessions view, harvest's reap hold | S-8155 |

### Task 9450: one id per run — minted at launch, on the line, in the environment, the log and every commit

stories: S-8150, S-8151, S-8152
writes: asf/workers/lifecycle.py, asf/workers/spawn.py, asf/workers/stall.py, asf/workers/runtime.py, asf/hermetic.py, asf/workers/githooks.py, tests/test_session_identity.py

**Files**

- `asf/workers/lifecycle.py`: `session_id`, `parse_session`, the derived id in `read_lines`,
  `live_all`.
- `asf/workers/spawn.py`: `started` before the run, the id, the hook dir, the record's two new

- `asf/workers/stall.py`: `correct_once` only (D10).
- `asf/workers/runtime.py`: `Job.session` / `Job.hooks_dir`, `build_env`, the identity line in

- `asf/hermetic.py`: `build(..., git_config=())`, `CALLER_IDENTITY`, the module docstring.
- `asf/workers/githooks.py` (new): `HOOKS`, `ensure`, the `asf-hook` shim.
- `tests/test_session_identity.py` (new): `SessionIdTest`, `LaunchIdentityTest`,
  `CommitTrailerTest`.

**Steps**

1. `lifecycle.session_id(product, job, started)` and `parse_session(sid)` exactly as the spec's
   design block. The parse splits on the first `/` and the last `@`, and returns None for anything
   that does not split into three non-empty parts.
2. `read_lines(path)`: for each launch line (`is_launch`) with no `session`, set `product` from the
   registry's directory (D12) when the line has none. Then set `session = session_id(product, job,
   started)` when `product` is known. Update lines are untouched, and `fold` carries both fields
   through as ordinary fields. They are not `RUN_FIELDS`, and a run's own launch line sets them.
3. `live_all(state_root)`: every `state_root/*/sessions.jsonl` → `latest(path)`, keep
   `is_live`, and each run carries `product` and `session` from step 2.
4. `hermetic.build(..., git_config=())`: `_git_config(env, [('init.defaultBranch', …), *git_config])`,
   so `init.defaultBranch` stays pair 0 (`tests/test_workers.py:106` asserts `KEY_0`).
   `CALLER_IDENTITY = ('ASF_PRODUCT', 'ASF_JOB', 'ASF_SESSION', 'BACKLOG_ID_RANGE')`. Update the
   module docstring's identity sentence.
5. `runtime.Job` gains `hooks_dir=None` and the property `session` → `self.env.get('ASF_SESSION')`.
   `build_env` passes `git_config=[('core.hooksPath', job.hooks_dir)]` when `hooks_dir` is set. The
   identity already takes `job.env`, so `ASF_SESSION` arrives through it. A job with neither
   produces the same env as today, which keeps `test_env_isolates_the_account_and_carries_the_id_range`
   green unchanged.
6. `ClaudeCodeRuntime.run` and `FakeRuntime.run`: when `job.session` is set, write the one
   `{"type": "asf", "subtype": "session", "session", "product", "job", "started"}` line to the log
   before the Popen or the scripted lines. `started` is parsed back from the id's stamp as
   `YYYY-MM-DDTHH:MM:SSZ`, so the line and the registry agree without a new `Job` field.
   `read_result` is untouched. It already ignores the type.
7. `githooks.py`: `HOOKS` as the spec lists them. `ensure(product) -> dir` writes
   `env.state_dir(product)/githooks/asf-hook` (mode 755) and one `<name>` file per hook
   (`#!/bin/sh\nexec "$(dirname "$0")/asf-hook" <name> "$@"\n`, mode 755). It rewrites a file only
   when its bytes differ. The `asf-hook` body is the spec's four numbered steps in POSIX sh. Its
   "resolves to this dir" check compares `cd "$own" && pwd -P` against the shim's own dir. It
   passes stdin through by `exec`.
8. `spawn()`: `started = pool_mod.now_iso()` before `runtime.run`. `sid = lifecycle.session_id(
   product.name, row.job, started)`. `hooks_dir = githooks.ensure(product)`. The `Job` gets
   `env={'BACKLOG_ID_RANGE': id_range, 'ASF_SESSION': sid}` and `hooks_dir=hooks_dir`. The record
   uses that same `started` and gains `'session': sid, 'product': product.name`.
9. `stall.correct_once` as D10.
10. `tests/test_session_identity.py`: the three classes below. `LaunchIdentityTest` and
    `CommitTrailerTest` subclass `tests.test_workers.Home` and spawn with the fake runtime.
    `CommitTrailerTest` commits with `runtime.build_env(job)` over a base that carries a
    `user.name`/`user.email` pair via `GIT_CONFIG_*` or `-c`, never the operator's global config.

### Task 9451: `asf.workers.observe` — every session on the machine, whose it is, which account

stories: S-8153
writes: asf/workers/observe.py, tests/test_session_identity.py, docs/config.example.yaml

Depends on T-9450: `observe` parses the id with `lifecycle.parse_session`.

**Files**

- `asf/workers/observe.py` (new): `Observed`, `ObserveError`, `SessionSource`, `ProcessSource`,
  `CommandSource`, `FakeSource`, `source_from_config`, `read`, `identity_alive`.
- `tests/test_session_identity.py`: `ObserveTest`, plus a `fake_ps(directory, table)` helper that
  writes an executable `ps` stub printing `table`, or exiting 1. This is the `fake_launchctl`
  pattern (`tests/test_scheduler.py:63`). Tests put its directory first on `PATH` through
  `mock.patch.dict(os.environ, …)`.
- `docs/config.example.yaml`: the three `worker_pool` keys, commented.

**Steps**

1. `Observed = namedtuple('Observed', 'pid ppid account session product job owner cwd')`. `cwd` is
   None from every source here. The spec names the field and no source can read it with one `ps`
   call, so it stays None and nothing reads it.
2. `ProcessSource(binary, match)`: one `subprocess.run(['ps', 'axeww', '-o', 'pid=,ppid=,command='])`.
   `FileNotFoundError` or a non-zero exit → `ObserveError(<why>)`. Each line is `pid ppid rest`.
   It is a candidate when `re.search(match, rest)`, with `match` defaulting to
   `^(\S*/)?<binary>(\s|$)`. Drop a candidate whose ppid chain through the *full* table reaches
   another candidate, and guard the walk against cycles. The env comes from the `KEY=VALUE`
   tokens of `rest` for the five keys, and the last occurrence wins.
3. `CommandSource(cmd)`: `shlex.split`, run, one JSON object per non-empty line
   `{"pid", "ppid", "env": {…}}`. Non-zero exit or unparsable output → `ObserveError`.
   `FakeSource(entries)` returns those entries as they stand (D3).
4. `source_from_config(cfg)`: `worker_pool.sessions` (`process` default | `command` | `fake`).
   `command` with no `sessions_command` → `ObserveError` at read time, which is D10, not a crash
   at config load. `binary` = `worker_pool.binary` or `runtime.DEFAULT_BINARY`.
5. `read(cfg, accounts, source=None) -> ([Observed], why)`. The account is assigned by spec D7,
   in that order, with realpath on both sides (D11). `owner` is `asf` iff `ASF_SESSION` is
   set. `product`/`job` come from `parse_session`, else None. An `ObserveError` → `([], str(e))`,
   never raised.
6. `identity_alive(observed, runs)` exactly as the spec's bullet (D11 of the spec). Nothing calls
   it yet. T-9453 wires it in.
7. `docs/config.example.yaml`: under `worker_pool:`, after `accounts`, add the three keys commented
   out, with one comment line each: `sessions: process   # process | command | fake`,
   `sessions_command: …   # prints one JSON object per session: {"pid", "ppid", "env"}`, and
   `session_match: …   # default: the runtime binary as argv[0]`. Nothing else in the file moves.
8. `ObserveTest` as below.
