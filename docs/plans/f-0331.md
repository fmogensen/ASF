# Plan F-0331 — the registry and the stub first, then the wait, the retry, the read-back, the cutover

Epic: E-0001 — ASF 0.1 — a working factory. Spec: `docs/specs/f-0331.md` (approved). Branch:
`plan/F-0331`.

Five Tasks, one per Story, as the spec's D10 says. The cut inside them is forced rather than
chosen, and three measurements taken in this session decide it. Task 1 is the **wait with the two
things it cannot land without**: §6's fake `launchctl` that models launchd holding a job, and §5's
registration triple — because `wait_unloaded` reads both bounds through `scheduler.tunable()`, and
`tests/test_config_keys.py` refuses a `TUNABLES` entry whose key is not in `config_keys.TYPED`
(**PD1**, measured). Task 2 is the **retry**. Task 3 is §3 **whole** — `unloaded_clocks`, the
`asf/install.py` delegation, and the install tail's read-back, operator line and `return 1`
together, because splitting the tail would put a trunk on the floor that prints
`NEEDS OPERATOR: clock(s) not loaded after install` and still exits 0, which is this card
(**PD2**). Task 4 is the **cutover and the exit-status pin**. Task 5 is the **guide**.

Wave order: **1 → 2 → 3 → (4 ∥ 5)**. Four waves. Tasks 2 and 3 both declare `after: Task 1` and
would start together, but both write `asf/scheduler.py` and `tests/test_scheduler.py`, so the record
queues them one after the other whatever this plan says (**PD8**). **Task 5 is the only Task whose
`writes:` intersect nothing** — `docs/guide/upgrading.md`, `docs/guide/troubleshooting.md`,
`tests/test_readme.py` against every other footprint, checked pairwise — so it is ordered by
`after:` alone, and `after: Task 1, Task 3` puts it alongside Task 4 in the last wave. That pair is
the only concurrency this plan has, and it does not pretend to more.

The plan carries the spec's scope and no more. Three rows below correct it on a point of fact:
its §3/S-104408 boundary assigns the install tail to a Story whose own acceptance lines cannot be
written without it (**PD2**); `docs/guide/upgrading.md:125`, the row §5 rewrites, is `:159` at this
branch's base (**PD3**); and its §4 instruction to add the failed-install case *to* `AppliedTest`
meets a shared fixture that is already past its cutover with the marker written (**PD10**). None of
the three widens the work. Two more rows record measurements the spec could not make, both in the
coder's favour: §6's stub landed alone reddens nothing across 737 tests (**PD4**), and the status
read in front of the bootout costs exactly the one argv amendment (**PD5**).

## What this plan leaves unbuilt, and why

Everything in the spec's **Out** stands untouched, and this plan adds nothing to it: refusing to
install while a tick is running or draining first (the guide licenses the interruption and nothing
is lost by it; the drain machinery that exists costs a bounded wait on the whole floor plus a pause
record per clock); a periodic out-of-band check that a product's clocks are loaded (the doctor row
already says it, and a product whose tick clock is gone cannot notice its own absence — a host-level
watcher is a Feature of its own); `asf install` step 8's own read-back and retry, which stays byte
for byte; the `--host` install's exit status, which already returns 1 on a `failed` line and
inherits the wait and the retry through `_launchd_install`; a read-back for the systemd connector or
any non-launchd kind, which needs the exit-status-3 contract rethought first; a pid in the "it was
running" line, which the product's own `print` reader does not parse; changing `bootstrap()`,
`resume()`, `pause()` or `uninstall()`; a new card, record row, metrics row or event; and cleaning
up the card's own host, where the second install already loaded the clock.

Three things this plan deliberately does not do:

- **It does not touch `docs/specs/f-0331.md`.** PD2, PD3 and PD10 correct the spec on three points

  five Story declarations are what the record mints from (**PD9**), so editing it is the one change

  files are byte-identical from its tree to this one, so its numbers are statements about this base.
