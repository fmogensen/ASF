# Plan F-0321 — the owner first, then the three committers and the row in parallel, then the trunk copy

Epic: E-0001 — ASF 0.1 — a working factory. Spec: `docs/specs/f-0321.md` (approved, on the trunk).
Branch: `plan/F-0321`.

Six Tasks in three waves, and the shape is forced by one fact: all three committers, the doctor row
and this repo's ignore entry have to agree on the same list of names, and the spec's D5 makes that
list one module. So `asf/workers/scratch.py` lands first and alone — nothing imports it yet, so it
is green by construction — and then the four call sites land **in parallel**, because their
footprints are disjoint and each one's only dependency is that module (**PD1**). Task 6 is the
operator's ruling of 2026-10-10: the copy already tracked on the reporting product's trunk comes
off as an ordinary pull request on that product, sequenced last, after the doctor row that names it
has shipped (**PD12**).

Wave order: **1 → (2, 3, 4, 5) → 6**. Three waves. Tasks 2–5 have pairwise disjoint `writes:` and
all carry `after: Task 1`, so the record queues none of them behind another; Task 6 names
`.gitignore`, which Task 1 also names, and the intersection costs nothing because `after: Task 5`
already puts it behind the whole plan (**PD12**).

This plan carries the spec's scope and no more. Five rows below correct it, and one of them is the
only thing in this document a coder could lose a session to: **`tests.test_workers` is already red
at this branch's base**, five failures, all in `TestSpawn`, reproducing twenty commits back — and
`TestSpawn` is exactly the class Task 4 touches (**PD6**). Beside it: two of the spec's line-number

**Files**

- `asf/workers/scratch.py` — new. Module-level imports `os` and `subprocess` and **nothing from

  ':(exclude,top,glob)**/.b[0-9][0-9][0-9][0-9]_*']`: the whole-tree magic first, then one exclude
  per name, a literal as `:(exclude,top)<name>` and a name holding a glob character as
  `:(exclude,top,glob)**/<name>`. Every exclude carries `top` — **PD3** measured both entries being
  swept in without it. `exclude(wt)` appends each name of `PATHS` that is not already a line of
  `<git-common-dir>/info/exclude` to that file, creating `info/` if needed (D4), and returns the
  names it added; it reads and writes under `try`/`except OSError` and returns "added nothing" on
  failure, never raising — it is a hardening step and a worktree that cannot be hardened still has
  to run.

  the agreement assertion (below) and the both-orders import of **PD5**. `ExcludeFileTests` over

  `.b[0-9][0-9][0-9][0-9]_*` at line **13**, the last line of the file, under the comment P11

  `git check-ignore` in whatever checkout it runs in — **PD7** is why.
