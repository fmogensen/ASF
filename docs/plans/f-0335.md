# Plan F-0335 — one Task, because every cut of it strands a fence

Epic: E-0004 — Control plane — the factory's dashboard, served from the record. Spec:
`docs/specs/f-0335.md` (approved). Branch: `plan/F-0335`.

**One Task, one wave.** The spec's six paths are one new module, one new test module, a one-line
regex widening, six lines of parser, one declared row and one digit of a shipped assertion. There is
no second Task to cut, and that is measured rather than preferred: all five of the spec's acceptance
fences name classes in the **one** new file `tests/test_reconcile_proofs.py`, so every candidate Task
writes that one path and the record queues them whatever this plan says (**PD1**); §1.4 landing
without §2 does not merely leave the proof uncredited, it appends a **new** `## History` entry on
every run — three entries after three passes, measured (**PD2**); three of the five fences reach
§1.4 or §1.5, so no reader-only Task can pass its own acceptance (**PD1**); and both of the spec's
regression blocks name `tests.test_reconcile_proofs`, so neither is runnable by any Task landing
before that file exists (**PD1**).

Wave order: **1**, one wave of one Task. Nothing waits on anything, and nothing runs beside it.

The plan carries the spec's scope and no more. Six rows below correct or complete it, and none
widens the work: §1.3 step 1 names a reader whose signature `reconcile` cannot call (**PD4**); the
admit path's task extraction is measured to need no product, so the signature stands as written and
a coder must not add a parameter (**PD5**); S-121159's verb line is asserted by nothing that ships
today and lands in the new test file (**PD7**); a Story card with no `## History` section ticks its
bullet and gets no entry — pre-existing, measured, and a case the Stories do not name (**PD3**); a
host with no product configured reaches `product.main` through `None` (**PD8**); and `evidence.load`
reads a 180-second cache, which can move a verdict's label but — measured against the design — can
never move a tick (**PD11**).

from asf.record import ingest

WITH = ("## Acceptance\n- [ ] one\n- [ ] two\n\n## History\n- 2026-01-01: created\n")

def one_pass(body, line, stamp):           # reconcile_proofs.apply's per-card loop (spec §1.4)

          f"credited {sorted(proves.proved_lines(body))}, "
          f"4th pass identical {one_pass(body, 2, '2026-10-10 12:09')[0] == body}")

for pattern, name in ((r'^-[^\n]*?\bingest: proved line (\d+)\b', 'as it stands'),

    three(WITH, f'{name}, a History section')

## What this plan leaves unbuilt, and why

Everything in the spec's **Out** stands untouched, and this plan adds nothing to it: `landed_proves`,
its `--limit 300` window and its two sources; the pull-request-side parse that P2 measures at zero
claims, whose fix is every `Proves:` reader in the factory and its own card; writing the ledger file,
which is the parent's (F-0334) and the lane's; closing anything, which is `asf ingest`'s one job over
the whole record (D7); unticking, reversing, or reconciling in the other direction, `asf untick`
staying the one reverse; a tick step, a clock, or a `proves.claims_file` config key (D8); the inline
`proven by` proofs, the deferrals and the review-claim path; and executing, resolving or trusting the
file's `test` text.

Four things this plan deliberately does not do:

- **It does not touch `docs/specs/f-0335.md`.** PD3, PD4, PD5, PD7, PD10 and PD11 correct or complete
  the spec on points of fact and all six are recorded here, in the plan's decisions, as the binding
  told this session to do. The spec's five Story declarations are what the record mints the cards
  from (**PD9**), so editing it is the one change that could strand this Feature's Stories.
- **It does not change `PROVED_ENTRY_RE` further than the spec's one line**, and it does not touch
  `UNTICK_ENTRY_RE`. The widening is `(?:ingest|reconcile)` and is measured to move no shipped
  assertion across the eight modules that read the entry.
- **It does not fix the no-`## History`-section case** (**PD3**). `tick_proven` has written a tick
  with no entry on such a card since it shipped; the reconcile matches it byte for byte and pins it
  with a test, so the next card that wants to fix it has a measurement to start from rather than a
  surprise.
- **It does not make `evidence.load` fresh** (**PD11**). The staleness is traced through every step
  of §1.3 and bounded: it can read `admitted` where a fresh scan would have read `confirmed`, and it
  cannot tick a line the trunk does not carry, because every ledger-only path re-reads the trunk.

The spec's own `NEEDS OPERATOR` line is `none`, and nothing here waits on a person. The one figure a
checkout cannot replay is P1, the pull-request window; nothing in the design turns on its exact
value — the window being finite is the only thing the reconcile needs to be true — and the spec
prints the read-only command for it beside the claim.

coverage: 5/5 stories; uncovered: none
