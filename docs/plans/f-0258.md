# Plan F-0258 — the check runs at the pre-push moment, and the number the card reserves is the number the branch books

Epic: E-0001 — ASF 0.1 — a working factory. Spec: `docs/specs/f-0258.md` (approved). Branch:
`plan/F-0258`.

Three Tasks, cut so that **the predicates are provable before the command that runs them and the
brief that states them**:

1. **the readers, in `asf/reservations.py`** — `declared` lifted out of `writes_bookings`'s inner
   loop, `_added`/`booked`/`pending_added`/`_numbers_under` so any revision can be read at the
   pre-push moment, and the pure honour pair `unhonoured`/`honour_refusal`. One existing module and
   one existing test module; nothing in the factory behaves differently when it lands, which is why
   it can go first and must.
2. **`asf reservations`, the command** — `cmd_reservations` in `asf/reservations.py`, one
   registration and one dispatch line in `asf/cli.py`, and the new `tests/test_reservations_cmd.py`.
   The clash, the honour, `--heads`, and the two clean cases.
3. **the brief** — the reservation stated as a reservation in `state_lines`, and the standing rule
   naming the command in the `rules` Section, both conditional on a declared sequence.

They run **1 → (2 | 3)**. Tasks 2 and 3 each need Task 1's landed readers — Task 2 calls `booked`,
`pending_added` and `unhonoured`, Task 3 calls `declared` — and neither needs anything of the other;
their `writes:` are disjoint (`asf/reservations.py` + `asf/cli.py` + the new test module against
`asf/briefs/preamble.py` + `tests/test_briefs.py`), so they are one wave, not a queue. Task 1 is
serialising against both because D10's whole argument is that the brief and the check read one
function, and a function two parallel Tasks each reach for is the defect this card exists to close.

**Read PD1, PD2, PD3 and PD4 before writing a line.** Each is a place where following the spec's
design literally ships a red test or a silent no-op: `refusal(snap, branch)` refuses nothing at the
pre-push moment (PD1), A1's fixture declares a sequence A1's own paths do not belong to (PD2),
`brief_lines(snap, limit=0)` prints nothing rather than everything (PD3), and an unconfigured
product's `warning:` line fires on every push and makes one acceptance test vacuous (PD4).

The fences of §*The fences, and the suite* bind every Task, so every Gate and Acceptance block
below carries them beside its own.

### Task 1: the readers the brief states and the check enforces, in one function each
stories: S-59304, S-59306, S-59307
writes: asf/reservations.py, tests/test_reservations.py
after: none

The spec's `## The design` §1 in full, and A1 whole. No caller changes and nothing in the factory
behaves differently when this lands — `declared` is `writes_bookings`' own inner loop with a name,
`booked`/`pending_added` are `added_files`' command pointed at a revision instead of a remote ref,
and `unhonoured`/`honour_refusal` have no caller until Task 2. That is exactly why it goes first:
D10's argument is that the brief that states a reservation and the check that enforces it read one
function, and a function Tasks 2 and 3 each wrote for themselves is the defect this card closes.

Read **PD2** (A1's fixture declares a sequence A1's own paths do not belong to — the one byte of the
block the Task changes), **PD4** (`NO_COMMAND`, so an unconfigured product is not a standing
warning), **PD9** (the three fixture methods A1 calls do not exist) and **PD14** (the forbidden
tokens, in a module that is not one of the three exceptions) before starting. **PD1** names the
`extra=()` keyword this Task adds to `snapshot`; Task 2 is its only caller, and it is here because
`snapshot` is in this Task's footprint and not in Task 2's reach without it.

**Files**

- `asf/reservations.py` — `declared`, `_added`, `added_files` (refactored onto `_added`, signature
  and docstring unchanged), `booked`, `pending_added`, `_numbers_under`, `unhonoured`,

**Steps**

1. `declared(item, seqs)` exactly as the spec's §1 writes it, docstring included — the `set` and the

   `(sequence, number)` twice from two globs, and the brief's line must be stable.

   cases each declare at most one numbered glob per card, so none of them moves.
3. `_added(repo, trunk, rev)` and `added_files(repo, trunk, ref)` exactly as the spec writes them:

   `return _added(repo, trunk, f'origin/{ref}')`.
4. `_numbers_under(paths, seqs)` — for each sequence, the basenames of `paths` whose `os.path.dirname`
