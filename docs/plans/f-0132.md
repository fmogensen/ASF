# Plan F-0132 — the name stays on the card that holds it: four Tasks, two waves

Epic: E-0004 — Control plane, the factory's dashboard, served from the record. Spec:
`docs/specs/f-0132.md` (approved). Branch: `plan/F-0132`.

**Four Tasks, two waves.** The spec's five seams split three ways and then pin what already landed:
§1 builds the one judgement (`protected_fields`) that §2 reads, so the check comes first; §4 and §5
are one change to `index.json`'s entry and its mirror in legacy slug resolution; Decision 6's
regression pins depend on nothing. The waves are **(1, 4) → (2, 3)**.

Each Task lands something whole. After Task 1 `asf check` names the card that holds the name and
nothing else has changed — the derived copies are still made, so the operator is told which card to
rename before any of the copying stops, which is the order that ends the problem at its source.
After Task 4 the two halves already landed are pinned and cannot silently regress under the other
three. Every order of landing is legible, never broken.

**Read PD2, PD4 and PD8 before writing a line of any Task.** They are the three places a coder who
copies the spec's snippets and runs the spec's own §3 fences lands a green local suite and a broken
product:

- **PD2** — §1's snippet names two things `asf/record/check.py` does not have: `_flatten_strings`
  is private to `asf/record/core.py`, and `redact` is not imported as a module. Two `NameError`s on
  the first call.
- **PD4** — **`render_groom_file` is not the last seam before the bytes.** The every-tick groom
  writes through `merge_groom_text`, which the spec's §3 never touches, so the leak survives on
  every tick after the first of the day — the pass that runs most often.
- **PD8** — `asf/record/check.py:366` calls `build_index_data` too, and §4's prose promises it
  scrubs while no snippet makes it. Left alone, every entry reads stale forever and `--staged`
  refuses every commit.

**Read PD10 before Task 3** — §5's snippet silently widens legacy matching for every branch whose
slug is not already slugified. **Read PD7 before Task 1** — `default_patterns` is effectively never
empty, so a test that removes a name list proves nothing. **Read PD15 and PD17 before any Gate** —
three test modules the spec's fences never run bind on the two signatures this card changes, and
the spec's own gate line is a `PermissionError`.

```python
#: The typed fields a protected name is looked for in, title first — the field an operator
#: writes, and the one derived text quotes (F-0132).
def protected_fields(rec, pats):
    """``[(field, kind, source)]`` for each typed field of ``rec`` whose value carries a
    protected name or a secret, ``title`` first, one entry per field (the first pattern that
    matches it). The matched value is never returned (F-0075 D8): the caller names the field and
    which source matched, so a finding is safe in a tick log or a transcript. The machine block
    is never scanned — it is ASF's own vocabulary, not where an operator writes a name (D6)."""
    if not pats:
        return []
    typed, _machine = frontmatter.split_machine(rec['meta'])
    out = []
    for key in ['title'] + [k for k in typed if k != 'title']:
        parts = []
        _flatten_strings(typed.get(key), parts)
        for pat in pats:
            if any(pat.regex.search(p) for p in parts):
                out.append((key, pat.kind, pat.source))
                break
    return out
```

pats: return []` guard is for a patched or degraded `default_patterns`, not the common case (PD7).
