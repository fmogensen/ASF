# Plan F-0176 — a result record is never a death, and a ready ruling is a publish instruction

Epic: E-0001 — ASF 0.1 — a working factory. Spec: `docs/specs/f-0176.md` (approved). Branch:
`plan/F-0176`.

Three Tasks, one per Story, cut along the three modules the spec's three design sections name:

1. **the words** — `asf/tick/step_health.py`. `wrote_a_result` and `outcome_text`, and the two text
   producers that branch on them. Nothing the factory *does* changes: a hold that landed still
   lands, on the same run, spending the same round. Only its sentence stops contradicting the
   evidence stapled to it.
2. **the publish** — `asf/workers/health.py`. `ruling_ready`, and the third opener it becomes for
   `publish_gap` and `republish_steps`. This is the half that ends the loop: the branch six
   adjudications did not put on origin goes out on the first tick after it lands.
3. **the refusal's text** — `asf/workers/lifecycle.py`. `git_error`, and the two refusal sites that
   stop returning `why[-1]`.

They run **in one wave**. Their footprints are disjoint — one package module and one test module
each, no file shared — and none calls another's new code (PD12). The order the spec presents them
in is an argument, not a dependency, and sequencing Task 2 behind Task 3 would delay the only Task
that stops B-0123 going round for a message that is merely poorer, never wrong.

**Read PD1 before opening any file: not one line number in the spec is usable as written.** The
spec was written against `d005de847`; this branch point is `2d1286490`, twelve commits later, and
every anchor has moved. The Files blocks below carry the current ones, each re-read here.

**PD2 is the one thing a coder will get wrong without being told.** The branch a ruling-ready
adjudicate run publishes is *the item's own fix branch*, not an `adjudicate/…` branch — that is why
publishing it lands B-0123 at all, and it is what `RulingReadyPublishTests` has to set up.

The fences of §*The tree's fences, and the suite* bind every Task, so every Gate and Acceptance
block below carries them beside its own.

### Task 1: a log that ends in a result record is never called a death
stories: S-37150
writes: asf/tick/step_health.py, tests/test_quota_headroom.py, tests/test_tick_steps.py
after: none

The spec's `## Decisions → In` bullet 1 and `## The design` §1 in full: `wrote_a_result`,
`outcome_text`, and the two text producers rewritten to branch on them. This is the half of the
card that stops the ledger lying — the hold that quoted the record it said did not exist.

Nothing the factory *does* changes when this lands. The same run is held, in the same pass, for the
same round, with the same `correction.kind` of `died`; `ran_to_its_end` and B-0150's skip are not
touched, so a correction that wrote a *clean* result still holds nothing at all. Only the sentence
moves. That is why this Task can land beside the other two and be proven on its own.

Read **PD3** (the hold stays — do not try to make the card's "nothing is held" true here),
**PD4** (`tests/test_tick_steps.py` is expected to need no edit, and why), and **PD14**
(`outcome_text`'s three branches, and which one B-0123 actually takes) before starting.

3. `error_text` (`:40`) keeps its `log_tail` line and its `; the last lines of its log:` /`.` tail

   {outcome_text(session)}` when `wrote_a_result(session)`, else today's `died before it wrote a
   result` sentence, verbatim.
4. `died_text` (`:46`) takes the spec's shape: bind `last` from `error_text(session)`'s last
   stripped line (today's `tail[-1]` with the same `'no log lines'` default, written as the spec

   — {last}` when the log holds one, else the existing `died twice: …` string **byte for byte**.
   That string is asserted at `tests/test_tick_steps.py:244`; retyping it is how it breaks.
5. Its docstring gains the spec's second sentence — that the phrase "without a result" is never
   written about a log that holds one — because the invariant lives in this function and a third

6. `AResultIsNeverADeathTests(HomeCase)` in `tests/test_quota_headroom.py`. Copy `TestExhaustedRun`'s

### Task 3: a publish refusal names git's own error, not its hint or its summary
stories: S-37152
writes: asf/workers/lifecycle.py, tests/test_lifecycle.py

The spec's `## Decisions → In` bullet 3 and `## The design` §3 in full: `git_error`, and the two
refusal sites that stop returning the last non-empty output line. git prints its fast-forward hint

one line that carries no information — which is how `hook_refusal_hold` came to hold sessions on a
message with nothing in it to act on.

the text survived), **PD9** (both streams, and the redaction branch that must still win) and
**PD10** (`push_failure`'s classification, the one thing this can silently break).

  (`:1274-1275`) rewritten through it
- `tests/test_lifecycle.py` — `GitErrorTests`, a new class

**Steps**
