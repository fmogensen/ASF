# Plan F-0224 — narrow what a later round reads, bound the loop at both ends, and stop the number falling for the wrong reason

Epic: E-0001 — ASF 0.1 — a working factory. Spec: `docs/specs/f-0224.md` (approved). Branch:
`plan/F-0224`.

Four Tasks, one per Story, cut along the spec's four design sections:

1. **a later round reads the increment** — `preamble.collect` carrying `prior_head`, `build.context`
   building the read order from it, and `review.md`'s one line splitting in two. Round 1's brief is
   unchanged **byte for byte**, and the tree already has the test that proves it (PD1).
2. **no second reviewer for a head that filed nothing** — `lifecycle.review_attempts`, the count on
   `occupancy`'s `review` entry, and the non-launching `WAITS ON hold` row in `lane_rows`.
3. **the review loop has the ceiling the document lane has** — the `STALEMATE → ADJUDICATE` row
   above the floor in the same `lane_rows` branch, **and the one tuple entry in `asf/invariants.py`
   without which the feeder's own I4 gate drops that row every tick** (PD5).
4. **a mechanical pass in front of the round is repair** — one string in `REPAIR_PREFIXES`.

They run **{1, 2, 4} together, then 3**. Tasks 1, 2 and 4 have disjoint `writes:` and `after: none`.
Task 3 is `after: Task 2` because both write `asf/feeder/rows.py` and `tests/test_feeder.py` — their
`writes:` intersect by construction, so the queue is real whatever the `after:` line said — and
because the spec's §3 puts the ceiling **above** §2's guard in the same code block: the floor lands
first, the ceiling is inserted over it, and S-36504's *"the ceiling is tested before the floor"*
assertion is meaningful at the moment it is written rather than vacuous (PD4).

**Read PD1, PD3 and PD5 before writing a line.** Each is a place where a literal reading of the
spec's design ships something that cannot pass or cannot work: §1's snippet changes a punctuation
mark that an existing golden test pins (PD1); `occupancy` has no place to call `review_attempts`
from inside its own loop and must patch after it (PD3); and §3's adjudicate row launches on a branch
the lane holds in `REVIEW`, which `LANE_LAUNCH_KINDS` allows exactly one kind on — so the feeder
drops the row, the branch gets no row at all, and the ceiling silently strands every branch that
reaches it (PD5).

| **PD2** | **`read_order` is assembled in `build.context`, which today is a single `return {…}` literal — and its value must arrive with no braces left in it** | `render(text, ctx)` is `text.format(**ctx)` (`asf/briefs/build.py:193-199`) and raises `BriefError` on a placeholder the context has no key for. The `if` is not cosmetic: it is what stops a tick with nothing in review paying for a second `marshal.loads` of the fold. That second unmarshal is the whole cost of this Story on a tick that does have something in review — `_folded(path)` is cached and `by_branch` already warmed it, so no file is read twice. |

### Task 1: a later review round reads the increment, not the whole diff against the trunk again
stories: S-36502
writes: asf/briefs/preamble.py, asf/briefs/build.py, asf/briefs/templates/review.md, tests/test_brief_facts.py, tests/test_briefs.py
after: none

The spec's §1 whole. When this lands, a round-1 review brief is byte-identical to today's — the
golden fixture proves it — and a later round is sent to the previous round's C list, then the
increment since the head that round read, then a name-only diff for the scope row. The verdict
table, its six rows and the rounds rule do not move (D2).

Read **PD1** (the colon stays; the golden is not regenerated), **PD2** (where `read_order` is
assembled and why it cannot be an f-string in the dict literal), **PD11** (`prior_head` mirrors
`stored_review_section`'s guards), **PD12** (the sha is unabbreviated) and **PD13** (the switch is
`prior_head`, not the round) before starting.

**Files**

- `asf/briefs/preamble.py` — `prior_head` in `collect`'s returned dict (`:429-463`), beside
  `round`/`next_round`. `review_store` is imported locally in the function, as `build.py` does
  (`build.py:538`), so the module gains no import-time dependency on the evidence package.
- `asf/briefs/build.py` — `READ_ORDER_FIRST` and `READ_ORDER_LATER` beside `GATE_REMOTE`/
  `GATE_LOCAL`; `read_order(ctx)`; `context` gaining `'prior_head'` and, after the literal,
  `'read_order'` (PD2).
- `asf/briefs/templates/review.md` — line 3-4 becomes `Read, in this order: {read_order}`. Nothing
  else in the file changes.
- `tests/test_brief_facts.py` — **new class** `PriorHeadTests`.
- `tests/test_briefs.py` — **new class** `LaterRoundReadOrderTests`.

`tests/fixtures/briefs/golden/review.md` is **not** on this list and must not change (PD1).

**Steps**

1. `asf/briefs/preamble.py`, in `collect`, above the returned dict: compute `prior_head` under
   exactly PD11's guards — `''` unless `product is not None and item_id and item_id != 'none'` and
   the row's branch is non-empty; otherwise
   `(review_store.newest(review_store.root(product), str(item_id).lower(), branch) or {}).get('head') or ''`.
   Wrap nothing in a `try`: `review_store.entries` already returns `[]` on `OSError`
   (`review_store.py:93-96`), so a missing store directory is `''` by construction. Add
   `'prior_head': prior_head,` to the dict with the spec's comment byte for byte:
   `# the head the previous review round read (review_store), '' when none`.
2. `asf/briefs/build.py`: `READ_ORDER_FIRST` is today's sentence, tail only, **including the line
   break after the comma** —
   ``"the writer's report on `{branch}`, then the diff against `origin/{main}`,\nthen the plan `{plan_path}` for the Task it claims to deliver."`` —
   so that `Read, in this order: ` + it is byte-identical to `review.md:3-4` as it stands (PD1).
3. `READ_ORDER_LATER` is the spec's later-round paragraph: the newest review quoted at the end of
   the brief and its C list as what the round is for, then ``**`git diff {prior_head}...HEAD`**``
   as everything the correcting session did about it, then
   ``` `git diff --name-only origin/{main}...HEAD` ``` for the scope row, then the explicit refusal
   — *Do **not** re-read the whole diff against `origin/{main}`: round {round} already read it, and
   this brief's rounds rule below says what you may do with anything you would find there.* Then
   the recut clause as its own sentence: *If `{prior_head}` is not on this branch, the branch was
   recut — read the whole diff as round 1 does, and say so in the review's evidence.* No code
   decides the recut case; the session that runs the command sees the failure.
4. `read_order(ctx)` returns `(READ_ORDER_LATER if ctx['prior_head'] else READ_ORDER_FIRST).format(**ctx)`.
   `context` becomes `ctx = {…, 'prior_head': facts['prior_head'], …}` then
   `ctx['read_order'] = read_order(ctx)` then `return ctx` (PD2). Both keys are in the flat context
   for every kind; only `review.md` reads `read_order`, and an unused context key is not an error
   (`render` only rejects a *placeholder* with no key).
5. `asf/briefs/templates/review.md`: replace lines 3-4 with the single line
   `Read, in this order: {read_order}`. Do not touch the table, the six rows, the rounds rule at
   `:21-24`, or the never-touch-the-branch paragraph.
6. `tests/test_brief_facts.py` `PriorHeadTests`: `collect` carries `prior_head` equal to the `head`
   of the entry `stored_review_section` quotes (assert against the section's own text, so the two
   readers are pinned to one entry — PD11); `''` when the store holds nothing for the branch, when
   the row has no branch, when `item_id` is empty or `'none'`, and for a first round.
7. `tests/test_briefs.py` `LaterRoundReadOrderTests`: build a review brief with an empty store and
   assert its read-order line is byte-identical to today's two lines; build one with a round-1 entry
   filed for the branch and assert the text contains `git diff {prior_head}...HEAD` with the real
   sha, contains `git diff --name-only origin/main...HEAD`, contains the recut clause, and does
   **not** contain `then the diff against \`origin/main\`,`; and assert the verdict table, its six
   rows and the rounds rule are byte-identical between the two briefs.
8. Run the golden test and confirm `tests/fixtures/briefs/golden/review.md` is unchanged in
   `git status`. If it diffs, step 2's constant is wrong — fix the constant, never the fixture, and
   never set `ASF_UPDATE_GOLDEN`.
