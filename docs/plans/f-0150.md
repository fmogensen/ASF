# Plan F-0150 — the third verdict, the revert card, the Decision, and the keyword that lets it be Closed

Epic: E-0001 — ASF 0.1 — a working factory. Spec: `docs/specs/f-0150.md` (approved). Branch: `plan/F-0150`.

Four Tasks, cut exactly the way the spec's `## Stories` are cut and the way `## The design` is
sectioned: the **third verdict** (`loop.direction`, pure, nothing calls it yet), the **shared
minting keyword** (`ids.write_new_item(state=)`, one defaulted parameter, no caller changed), the
**revert card** (`card_text(reverts=…)`, `facts.children` made public, `verify`'s third branch), and
the **Decision** (the third queue kind, minted at drain time, deduped, linked back, indexed).

Task 1 owns `asf/scorecard/loop.py`'s new pure function and its test class. Task 2 owns
`asf/record/ids.py` and one case in `tests/test_new_publish.py` — the only Task that touches the
shared minting path every other writer in the tree uses, and it lands alone and provably
behaviour-neutral. Task 3 owns `asf/scorecard/facts.py` and `verify`'s third branch. Task 4 owns
`drain` and the queue's third kind.

Wave order: **{1, 2} → 3 → 4** — in `after:` terms, 1 with `none`, 2 with `none`, 3 after 1, 4 after
2 and 3. Tasks 1 and 2 share no file and run together. Tasks 1, 3 and 4 all touch
`asf/scorecard/loop.py` and `tests/test_scorecard.py`, which costs nothing because each already
waits on its predecessor for a name that does not exist until it lands: Task 3 calls `direction`,
Task 4's `drain` writes a card through `write_new_item(state='Closed')` and drains an entry only
Task 3's `verify` ever enqueues.

§`## Acceptance tests`' last fence, `tests.test_scorecard tests.test_backlog tests.test_new_publish`,
binds every Task, so every Gate below carries it beside its own.

**The two things this plan makes exact that the spec leaves as a placeholder, and that a coder
cannot guess:** PD1 is the one line of `verify` a mechanical swap of `moved` for `direction` gets
wrong in a way that silently deletes a shipped behaviour. PD5 turns the spec's
`canonical = ...  # load_items + canonicalize` and `acceptance=[...]` into the exact calls, measured
against `mint_id`'s own folder scan. Read both before Tasks 3 and 4.

### Task 1: the third verdict — one pure function beside the one it does not replace
stories: S-35700
writes: asf/scorecard/loop.py, tests/test_scorecard.py
after: none

`## The design` §1's first half and nothing else. `direction` is added; `moved` is untouched; **no
caller changes** — `verify` still calls `moved` at the end of this Task, exactly as it does today.
That is deliberate: the pure half lands provable first, and on this Task alone the only observable
change in the whole tree is that a new name exists. Task 3 is what makes `verify` use it.

**Files**

- `asf/scorecard/loop.py` — `direction`, immediately below `moved` (`:323-329`)
- `tests/test_scorecard.py` — `DirectionTests`

**Steps**

1. `asf/scorecard/loop.py`, directly after `moved`: `direction(before, after, min_move)`, the
   spec's §1 code block byte for byte — docstring included, including its last sentence ("A zero
   that stayed zero moved; any rise off zero got worse"), which is the only place D2's `before <= 0`
   reading is written down in the code.
2. Do not touch `moved`, do not add a deprecation note to it, and do not rewrite it over `direction`
   — PD2. Do not touch `verify`: `:362-363` still read `verdict = moved(...)` when this Task lands.
3. The module docstring's step-3 paragraph (`:12-15`) says the verdict is "``moved`` or ``didn't
   move``". Leave it: it is still true of what the loop *does* after this Task, and Task 3 is the one
   that changes the behaviour it describes. Changing it here would document a branch that does not
   exist yet.
4. `tests/test_scorecard.py` — `DirectionTests(unittest.TestCase)`, beside `VerifyTests`. No fixture,
   no `Prod`, no clock. It pins, one assertion per line, exactly the eight the spec names:
   `direction(10, 8, 0.2) == 'moved'`; `direction(10, 12, 0.2) == 'got worse'`;
   `direction(10, 11, 0.2) == "didn't move"`; `direction(10, 8.5, 0.2) == "didn't move"`;
   `direction(0, 0, 0.2) == 'moved'`; `direction(0, 1, 0.2) == 'got worse'`;
   `direction(None, 1, 0.2) is None` — and, in a second method, that `loop.moved` still answers as
   `test_moved_needs_a_fifth` asserts today (`moved(10, 8, 0.2)` true, `moved(10, 8.5, 0.2)` false,
   `moved(0, 0, 0.2)` true, `moved(None, 1, 0.2)` None). The two `"didn't move"` cases are the band
   between the thresholds and are the reason this is not a boolean; the `(0, 1)` case is D2's second
   half and has no multiplicative reading at all.
5. Also pin `direction(1, None, 0.2) is None` — the symmetric missing reading. `moved` has only the
   `before is None` case asserted today, and both arms of the same guard are cheap to hold.
