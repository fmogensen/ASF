# Plan F-0095 — the trunk answers before a coder launches, and a Task that writes nothing twice is parked

Epic: E-0002 — ASF 0.2 — self-improvement. Spec: `docs/specs/f-0095.md` (approved). Branch: `plan/F-0095`.

Four Tasks, cut by module so no two diffs meet. Task 1 is the feeder — the three new rows and the
one helper, every one of them a pure function of an argument that defaults to `None`, so the
package still runs unchanged the moment it lands. Task 2 is the lifecycle: the new correction
kind, the counter and the park. Task 4 is `asf unpark`, which depends on neither. Task 3 is last
and is where the two halves are wired to the tick: `step_wave` gathers the trunk fact Task 1's
parameter is waiting for, `health` passes Task 2's kind and cap, and `step_health` says the park
out loud.

Wave order: **(1, 2, 4) → 3**.

### Task 1: the feeder's three gates — on the trunk, after: counts the trunk, and parked
stories: S-15001, S-15002, S-15004
writes: asf/feeder/rows.py, tests/test_feeder.py

§2.2, whole. One helper and three rows, every one a pure function of a `landed_shas` argument that
defaults to `None`. The feeder still reads no git and no filesystem (P3 of the spec); with no fact
handed in, this Task changes nothing anybody sees (P5).

**Files**

- `asf/feeder/rows.py` — `ON_TRUNK`, `landed_ids`, the `ON TRUNK` gate in `task_rows`, the
  `landed_ids` substitution in `task_rows` and `hold_unlanded`, the `parked` branch of
  `correction_rows`, the `landed_shas=None` parameter threaded through `candidates`, `plan_rows`,
  `feature_rows` and `task_rows`, and the `hold_unlanded` exemption of P8.
- `tests/test_feeder.py` — `AlreadyOnTrunkTests`, `AfterCountsTheTrunkTests`,
  `ParkedCorrectionTests`, and a case for `landed_ids` itself.

**Steps**

1. `ON_TRUNK = 'ON TRUNK'` beside the other action constants (`rows.py:41-51`).
2. `landed_ids(items, landed_shas=None)` exactly as §2.2 fences it: the record's
   `DONE_STATES` ids, union every key of `landed_shas`. Its docstring is the one in the spec.
   Note in the module what the fold buys — it runs over *all* items, not `ix.feature_tasks`, so an
   `after:` naming a Task of another Feature is answerable at all.
3. Thread `landed_shas=None` through `plan_rows` → `candidates` → `feature_rows` → `task_rows`,
   and into `hold_unlanded(rows, items, landed_shas=None)`. Keyword-only in spirit: every existing
   positional call site stays byte-identical.
4. **Gate one.** In `task_rows`, first thing in the loop body — before the `after:` check — a Task
   whose own id is a key of `landed_shas` gets the non-launching row §2.2 fences: `tier=2`,
   `kind=PLAN_CODE`, `action=f'{ON_TRUNK} {sha[:12]}'`, `waits_on='trunk'`, and the `reason`
   naming the sha, the subject and the card's state. `continue`. `tasks` is already filtered to
   `state == 'New'`, so an Active or Closed Task named by the trunk mints nothing extra.
5. **Gate two.** `task_rows`'s `landed` becomes `landed_ids(items, landed_shas)`, and so does
   `hold_unlanded`'s. One substitution in each; no other line of either moves.
6. **Gate three.** In `correction_rows`, before the `rounds >= CORRECTION_ROUNDS` branch, a
   correction carrying `parked` gets the non-launching `PARKED …` row §2.2 fences, with
   `waits_on='operator'`, and `continue`. It is neither `FIX → CORRECT` nor
   `STALEMATE → ADJUDICATE`, at any round count.
7. P8: `hold_unlanded` leaves a row alone when its action starts with `ON_TRUNK` or `PARKED`,
   the same way it already leaves `GROOM_ADJUDICATE` alone, with the reason in a comment.
8. Tests, in this module's idiom (a hand-built item map, no temp dirs, no git):
   `AlreadyOnTrunkTests` (§3.2), `AfterCountsTheTrunkTests` (§3.3), `ParkedCorrectionTests` (§3.5's
   feeder third), and `landed_ids` over the two disagreements the docstring names.
9. Confirm the existing `DeclaredOrderIsADependency` and
   `NoRowLaunchesBehindAnUnlandedPredecessor` are untouched — they are the regression, and neither
   may change.

**Steps**

8. `TrunkItemsTests` against a real git fixture (`tests/gitfixture.py`, a `Template` as this module

9. `TestEmptyPark` in `tests/test_workers.py`, in `TestHealth`'s idiom: `feature_row` gives both

### Task 4: `asf unpark <item>` — the operator's way out, recorded beside the park
stories: S-15005
writes: asf/workers/unpark.py, asf/cli.py, tests/test_cli.py

§2.5. A park is permanent by construction (P7 of the spec: `pending_correction` is cleared only by
a later run starting, and a park launches no run), so the exit has to be explicit, recorded and
runnable. It depends on neither of the other halves (P14) and runs in the first wave.

**Files**

- `asf/workers/unpark.py` — new: `cmd_unpark(args)` and `register(sub)`.
- `asf/cli.py` — one `from asf.workers.unpark import register as register_unpark` /
  `register_unpark(sub)` pair beside the other `register_*` calls (`cli.py:125-143`). The
  `set_defaults(func=…)` dispatch at `cli.py:341` already handles it; no `if args.command ==` arm.
- `tests/test_cli.py` — `UnparkTests`.

**Steps**

1. `register(sub)`: `asf unpark <item> [--why TEXT] [--product P]`, `env.add_product_arg(p)`,
   `p.set_defaults(func=cmd_unpark)`.
2. `cmd_unpark` reads `lifecycle.corrections(pool_mod.sessions_path(product))` to find the item's
   pending correction and the job that holds it, then appends one line through
   `pool_mod.update_session(product, job, correction=None, unparked=<iso>, unpark_why=<text>)` —
   the same writer every other caller uses. Nothing is rewritten: the park line and its undo are
   two appended lines, and the run's own `end_reason` is untouched.
3. It prints what it cleared — the item, the job, and the park's `reason`.
4. It exits `1`, with a line saying so, for an item with no pending correction, and `1` for an id
   the ledger does not know. Nothing to undo is an operator error worth hearing, not a silent
   no-op.
5. `UnparkTests` over a hand-written parked ledger, in `tests/test_cli.py`'s idiom (`env.ASF_HOME`
   redirected to a temp dir, `cli.main(argv)` under `redirect_stdout`): the clear, the rc, the
   appended line, `lifecycle.corrections()` afterwards, the feeder minting its launching row
   again, `--why`, the two refusals, and the park line still being in the file.
