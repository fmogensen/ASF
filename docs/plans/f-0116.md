# Plan F-0116 — the history says who did the work: the launch's own identity, both lanes, the check, the guard

Epic: E-0004 — Control plane — the factory's dashboard, served from the record. Spec:
`docs/specs/f-0116.md` (approved). Branch: `plan/F-0116`.

**Four Tasks, four waves — a serial chain, and the chain is honest rather than tidy.** The spec
names one test file for all four of its acceptance classes (`tests/test_session_identity.py`), so
every Task's footprint intersects every other Task's on that one path and the queue runs them one
after another whatever `after:` says (PD14). Splitting the file would buy a wider wave at the cost
of breaking the spec's fenced commands byte for byte, which is not a trade a plan gets to make.
So: one Task per Story, each landing something whole, each with its own fence.

After Task 1 a local session authors and signs off as `asf worker`, and it does so through the one
channel that beats a seeded `~/.gitconfig` and a product's own repo-local `user.name`. After Task 2
the `actions` cloud lane renders the same identity instead of its two hard-coded lines. After
Task 3 `asf identity --product <p>` exits 1 with one line per offending commit and 0 in silence,
which is the rule runner's check contract verbatim, and `asf doctor` carries the row that proves
the check ran. After Task 4 no brief kind can tell a session to author or sign as the operator
without a test naming the kind and the line.

**Read PD1 before writing a line of Task 1.** The spec's §2.2 snippet — the two-line change the
whole card turns on — cannot run as written: `build_env` already has a local variable called
`identity`, and `identity.git_config_pairs(acct)` asks a dict for a function. **Read PD7 before
Task 2**: `render_workflow` takes the cloud settings, which carry no account, and the workflow file
is written once by `asf cloud install` long before any row exists — so §2.3's "the override reaches
the cloud lane through the row's account" cannot hold for a static file, and PD7 says what does.
**Read PD3, PD4 and PD9 before Task 1 and Task 3**: three files the spec's *"Nothing else"*
footprint does not list must change, and one of them is inside a fence the spec itself names as
acceptance.

Every anchor the spec cites was re-read in this worktree at `cc5e5038c`, thirteen commits past the
spec's own `b21116e00`. **Every precondition still holds.** One cited anchor is simply wrong
(`asf/hermetic.py:55-57` is not where `git_config` is exported) and five are off by a line; PD17
carries the corrected numbers. Two of the spec's *claims about existing machinery* are false, and
both are load-bearing for a reviewer rather than for a coder — PD5 and PD6. Measured here, before
any edit:

  tests.test_session_identity` → `Ran 129 tests in 39.653s` / `OK`.

  `Ran 130 tests in 9.581s` / `OK`.
