# Plan F-0272 — the reader for the edge the order pass writes

Epic: E-0001 — ASF 0.1 — a working factory. Spec: `docs/specs/f-0272.md` (approved). Branch:
`plan/F-0272`.

**One Task.** The spec's whole change is two pure functions and two constants in
`asf/feeder/widen.py`, one pass of about forty lines in `asf/tick/widen_footprint.py`, one line in
`run()`, and two test classes — one beside `SerializeOverlapTests` in `tests/test_widen.py`, one in
a new `tests/test_serialization_dropped.py`. The regression cannot be built before the pass it
replays exists, so a rule/pass/regression split is strictly serial whatever its `writes:` say: the
second Task would wait on the first having **landed**, buying a second PR and a second review round
and no parallelism at all (**PD2**).

Wave order: **Task 1** — one wave, one Task, `after: none`, starts at once.

Nothing in the spec's `## Out` is touched: `serialize_overlaps`, `unordered_overlaps`, the
pushed-work tie-break and the shared-path exemption keep every rule they have; the feeder's wider
footprint gate keeps holding the pairs it holds, recomputed and never written onto a card; the
`after:` `revert_overlaps` writes is never dropped; a plan-declared or operator-written `after:` is
never dropped; no new `after:` is ever written; nothing is read about the owner's state; and
`asf check`, I3, `asf set` and `rows.dead_after` are all left exactly as they are.

This plan corrects the approved spec in four places, all measured in this worktree at `c599985a2`
and none of them a widening: the regression's two cards must sit in **different** deliveries or the
row the card exists for never appears (**PD5**); `after: []` stays on the card rather than being
dropped (**PD6**); "`asf check` is clean" is not assertable in the harness the spec names
(**PD8**); and the ruling's two blockers — an operator mint and a four-digit Story regex — are both
gone at this head, so this card needs no operator at all (**PD3**, **PD4**).

the end-to-end replay of the incident. Each is **declared** below as a `### S-…: <title>` heading

### S-63154: A serialization whose overlap has gone is dropped

`## The design` §1 and §2 — `widen.UNSERIALIZED`, `widen.SERIALIZED_RE`, `widen.serialized_edges`
and `widen.stale_serializations`, plus `widen_footprint.drop_serializations` wired into `run()`
between `revert_overlaps` and `serialize_overlaps`. Acceptance is the spec's first fenced block.
The rule is a pure function over plain values because that is the module split this package already
keeps (C11), and because the pass's idempotence is one line of it (PD7).

- [ ] serialized_edges reads the owner and the glob off every serialized behind <owner>: writes: overlaps <glob> History line a card carries, in first-seen order, one entry per owner
- [ ] serialized_edges reads nothing off a serialization dropped line and nothing off a footprint widening reverted line
- [ ] stale_serializations names the edge when the overlapping path left the owner's writes, and when it left the held card's
- [ ] stale_serializations names nothing while any non-shared glob pair of the two footprints still intersects
- [ ] stale_serializations names nothing for an after entry no serialization History line names: a plan's order, an operator's, and the wait the revert pass writes
- [ ] stale_serializations names nothing for an owner the others map does not hold, and nothing for an owner the card's after no longer lists
- [ ] stale_serializations names the edge when the only remaining common glob is one the product's shared paths cover
- [ ] drop_serializations takes the owner out of after, files one serialization dropped History line, and commits that one card alone with the note as its subject
- [ ] a second pass over the same record writes no commit and leaves after as it was, and a pair whose overlap still stands is left with its edge and gets no commit
- [ ] a drop the record stage refuses leaves the card byte-identical, prints a not dropped line naming the finding, and does not fail the tick
- [ ] a Closed held card and a removed held card are both skipped, and a pair whose overlap comes back is re-serialized and dropped again once the path leaves
- [ ] python3 -m unittest -v tests.test_widen.DroppedSerializationTests is green

### S-63155: The held card and everything bundled with it launch once the overlap goes

**Steps**

1. Add the two constants to `asf/feeder/widen.py` beside `SERIALIZED`, with the spec's own
   comments:

   ```python
   #: The History line that drops a serialization whose overlap has gone.
   UNSERIALIZED = 'serialization dropped: {owner} — writes: no longer overlaps {glob}'
   #: A serialization's History line, read back: the owner it waits on and the glob it named.
   SERIALIZED_RE = re.compile(r'serialized behind ([A-Z]-\d{4,}): writes: overlaps (\S+)')
   ```

   The `\d{4,}` is the house form for an id regex (`asf/facts/landing.py:58`, P12), and the word in
   `UNSERIALIZED` is `serialization`, not `serialized`: `widenings` counts reverts by substring and
   three existing tests assert `serialized` is absent from a card this pass writes, so the drop line
   must not contain it (C10, PD10).

2. `serialized_edges(body)` — `[(owner, glob)]`, first-seen order, one entry per owner (C4), built
   the way `widened_paths` (`:314-321`) is built: `finditer` over the compiled regex, a list and an
   `if owner not in seen` guard rather than a dict, so the order is the document's. It reads nothing
   off a drop line, because the regex needs the literal `serialized behind`.

3. `stale_serializations(after, body, writes, others, shared=())` — the decision, and the exact
   inverse of the write (C1). For each `(owner, glob)` of `serialized_edges(body)` whose `owner` is
   in `after` **and** in `others`, normalise both footprints through `norm_writes` and keep the edge
   when no non-shared glob pair intersects:

   ```python
   mine = norm_writes(writes)
   theirs = norm_writes(others[owner])
   live = any(writes_intersect(x, y) for x in mine if not footprint.is_shared(x, shared)
              for y in theirs if not footprint.is_shared(y, shared))
   ```

   That expression is `unordered_overlaps`' own loop (`asf/invariants.py:334-345`, P6) written as a
   comprehension, skipping a shared glob on **either** side as it does — not
   `footprint.globs_overlap`, whose wider reach (P7) would hold some edges the narrow test calls
   dead, which is this defect again in a smaller corner (C1). The recorded `glob` is carried for the
   message only and never tested (C2). The `owner in after` half is load-bearing and is its own
   acceptance line: it is the whole of the pass's idempotence (PD7).

4. `drop_serializations(ctx, items, out=print)`, with the spec's docstring. It reads the record the
   way `serialize_overlaps` does (C8) — `load_items` → `canonicalize` → `invariants.overlap_tasks`
   over `{iid: rec['meta'] …}` — and takes `writes_of = {iid: t['writes'] for iid, t in
   shaped.items()}` as the `others` map and `footprint.shared_globs(product)` as `shared`. For each
   Task in id order that is not `removed:` and whose state is neither `Resolved` nor `Closed`
   (C9), it re-reads the card with `_card` for its History text, asks the rule, and for each edge:

   ```python
   after = [a for a in rec['meta'].get('after') or () if a != owner]
   err = write_card(root, iid, {'after': after}, stamp,
                    widen.UNSERIALIZED.format(owner=owner, glob=glob), product=product)
   ```

   The card is re-read between edges of the same card, as `serialize_overlaps` re-reads between
   pairs. On `err`: `out(f'widen: {iid} not dropped — {err}')` and on to the next — the record stage
   is the one definition of "no two Active Tasks' `writes:` left unordered" and it validates before
   the commit with the card unchanged (C6, P5/P11), so there is no second copy of that reachability
   here. On success: `ctx.event('unserialized', item=iid, text=f'-after: {owner} — writes: no
   longer overlaps {glob}')`, `out(f'dropped  {iid}: after: -{owner} — writes: no longer overlaps

## What this plan leaves unbuilt, and why

Everything in the spec's `## Out`, and nothing else. The order pass keeps every rule it has: this
card adds the reader, never a second writer, so `unordered_overlaps`' pushed-work tie-break and its
shared-path exemption decide exactly the pairs they decided before. The feeder's footprint gate
keeps its wider test (P7) and keeps holding at launch the pairs it holds, with the row
`writes: overlaps <other>` recomputed every tick and never written onto a card — a wait that is
already recomputed is not a sticky edge. The `after:` the revert pass writes is never this pass's:
its paths left `writes:` by construction, so the overlap is gone by construction too, and the edge
is the wait that lets the rule re-decide once the owner is done. A plan-declared or
operator-written `after:` is never touched, because no History line names it. Nothing is read about
the owner's state: a Closed, Resolved or removed owner whose `writes:` still intersect keeps its
edge, because the feeder already stops waiting on a landed id and a dead edge is
`rows.dead_after`'s question.

`asf check` and I3 are not changed: P5 is the measurement that the guard this pass needs is already
there, and a drop that would un-order a live overlap is refused by the record stage with the card
untouched. `asf/tick/file_bugs.py`'s `RECORD_ERROR_SELF_HEALED` exemption (`:274-275`) is not
changed either — it names the I3 message as self-healing because the order pass clears it every
tick, and a pass that only removes edges cannot create an instance of it. No new command, no new
state file, no new convention, and `conventions.shared_paths` is read where the pass already reads
it.

Two things this plan found and does not fix. `set_typed` leaves an emptied `after:` on the card as
`after: []` rather than dropping the field (PD6); it is harmless everywhere this card can see, and
whether an emptied list field should be dropped is a question for `asf/record/setfield.py` and every
writer that goes through it. And the widen module's docstring numbers three of its four passes, the
order pass having never been given an entry (PD11); writing one would be a doc change to a pass the
spec puts in `## Out`.
