# Plan F-0080 — closing is derived and total

Epic: E-0001 — ASF 0.1 — a working factory. Spec: `docs/specs/f-0080.md` (approved). Branch: `plan/F-0080`.

Six Tasks, cut by the thing that changes. Task 1 is the table itself — `Closing`, `Ev`, `RULES`,
`state_of`, `sticky` — a new module with no caller, so the definition of done can be asserted
total before anything depends on it. Task 2 moves `ingest` onto it and adds descent, which is the
whole of "the five arms become one". Task 3 is reconciliation: the marker, the one groom question
and the three answers. Task 4 is the other end of that thread — a typed `landed:` sha read as
ordinary evidence, so a reconciled item closes through the ordinary rules. Task 5 is the feeder's
cap over every launching kind. Task 6 makes the residue visible in `asf status` and `asf check`.

Tasks 2, 3 and 4 all write `asf/record/ingest.py` and run one after another; that is also their
dependency order. Tasks 5 and 6 write nothing any other Task writes and run beside Task 3.

Wave order: **1 → 2 → 3 ∥ 5 ∥ 6 → 4**.

### Task 1: the table — one definition of done, total, with no caller yet
stories: S-15550, S-15551, S-15552, S-15553, S-15556
writes: asf/evidence/closing.py, tests/test_closing.py

§2.1: a new module holding `Closing`, `Ev`, `RULES`, `state_of` and `sticky`. Nothing calls it
when this Task lands — that is deliberate. Totality is a property of the table taken together, and
this Task is where it is asserted, over hand-built evidence, before any caller can hide a hole
behind a fallback.

**Files**

- `asf/evidence/closing.py` (new) — the module docstring of §2.1; `NEW`/`ACTIVE`/`RESOLVED`/
  `CLOSED`/`NO_RULE`; `Closing`; `Ev`; `RULES`; `state_of`; `sticky`; `BUG_QUIET_DEFAULT = '3d'`
  (P7). Imports `dataclasses` and nothing from `asf` (P8).
- `tests/test_closing.py` (new) — `TotalityTests`, every bullet of §3.1.

**Steps**

1. `Closing(state, rule, lines=())` and `Ev`, frozen and null-per-field exactly as §2.1 fences
   them, so a test states only the evidence it means.
2. `RULES` as a tuple of `(type, name, predicate, state)`, in the order §2.1's table lists them —
   the two `any` rows first, then task, story, bug, feature, epic. Each row carries its prose (the
   table's "holds when" column) as a fourth element read by the module docstring and by nothing
   else yet (P19). The predicates are written out; no `evidence.*_state` is called (P5).
3. `state_of(type_, ev, current)` walks the rows for `type_` (after the two `any` rows), returns
   the first `Closing` whose predicate holds, and otherwise `Closing(current, NO_RULE)` — the item
   keeps the state it had and is named residue. It raises for no input and returns for every one.
4. The four holes, as rules rather than as arms: `any/parent-closed` reaching a Story with no Task
   and a Task with nothing; `feature/landed-green` and `feature/landed` for a Feature with no
   children; `bug/quiet` for a Bug at `Resolved` forever; `epic/children-closed` for an Epic that
   only ever closed by hand. `epic/typed-closed` stays, read as the *early* close (§1.4).
5. `bug/quiet`: `(ev.merged_sha or ev.commit)` and `ev.green` and (`not ev.signature` or
   `ev.quiet_for >= ev.quiet_limit`). A Bug with no signature closes on green alone (§1.4); a
   signature seen inside the limit stays at `fixed` → `Resolved`.
6. `sticky(old, closing)` exactly as §2.1 fences it: `Closed` plus a rule saying anything else
   yields `Closed` with rule `closed-terminal` and one evidence line naming what the rule would
   have said. Every other pair passes through untouched, both directions.
7. `TotalityTests` per §3.1: the generated cross-product of the five types and the presence or
   absence of each `Ev` field — `state_of` returns one of the four states for every pair, never
   raises, and every `rule` it returns is a name in `RULES` for that type or `NO_RULE`; one test
   per hole asserting the state *and* the rule name; the two Bug quiet cases; the Epic early
   close with an Active child; `sticky` both ways; and the order test B-0074 asserts — a Task with
   both a merged trunk commit and an open PR is `Closed`, not `Active`.

`TotalityTests` covers, over hand-built `Ev`s, with no git and no clock:

- `state_of` returns a `Closing` whose `state` is one of the four states for **every** `(type,
  Ev)` pair the generator produces — types crossed with the presence/absence of each `Ev` field
  — and never raises;
- every returned `rule` is a name in `RULES` for that type, or `NO_RULE`;
- the four holes of the opening table, each as one test: a Story with no Task and a closed
  parent; a Feature with no children and no naming commit; a Bug with `merged_sha` and green CI
  past `bug_quiet`; an Epic whose every child is `Closed` with no `closed: true` typed — all
  four return `Closed`, and each names its rule (`parent-closed`, `landed-green`/`reconciled`,
  `quiet`, `children-closed`);
- a Bug with no `signature` closes on green alone; one with a signature seen `quiet_for` under
  the limit stays `Resolved`;
- an Epic with `closed: true` typed and an Active child is `Closed` by `typed-closed` — the
  early close is still honoured;
- `sticky`: `Closed` + a rule saying `Active` yields `Closed` with rule `closed-terminal` and an
  evidence line naming what the rule would have said; every other transition passes through
  untouched, both directions;
- the rule *order* is what B-0074 asserts: a Task with both a merged trunk commit and an open PR
  is `Closed`, not `Active`.

**Steps**

1. Per type, build a `closing.Ev` from what the block already matched: the Task block from `tev`

   `_in_prod` over those Tasks (P9); the Bug block from `bev`, `merged_in_prod`, the typed

6. `IngestDerivesNothing`: an AST walk over `asf/record/ingest.py` asserting no `Attribute` call

7. The rest of §3.2's new cases: every closed item's `evidence:` ends with `rule: <name>`; the

### Task 3: reconciliation — the marker, one question, three answers that write evidence
stories: S-15557, S-15558
writes: asf/evidence/closing.py, asf/record/ingest.py, asf/groom/groom.py, tests/test_closing.py, tests/test_groom.py, tests/test_groom_policy.py

§2.5: work that predates `conventions.id_in_subject_since` is asked about exactly once, in one new
groom section, and the answer writes evidence — `landed: <sha>`, `reconciled: <date>` or
`removed:` — never a state.

**Files**

- `asf/evidence/closing.py` — `PREDATES_LINE` (the constant prefix), `predates(item, ev, since)`
  (pure, §2.5's four clauses) and `predates_marked(item)`, the record-side reader (P13).
- `asf/record/ingest.py` — the marker line appended to an item's `ev_lines` when `predates` holds,
  with the marker date read from `conventions.id_in_subject_since` (unset → never).
- `asf/groom/groom.py` — `ANSWER_LANDED` and `ANSWER_OPEN`; `_parse_answer`'s two new words;
  `apply_groom_answers`' `reconciled` date fill, beside the `removed` one it already has (`:319`);
  `groom_predates_section(canonical, since)`; the `GROOM_SECTIONS` entry
  `('Landed before the id convention', 'predates')` after `no_tasks`; `build_groom_sections`
  taking the marker date; `cmd_groom` passing it from the product.
- `tests/test_closing.py` — `PredatesTests` (new).
- `tests/test_groom.py`, `tests/test_groom_policy.py` — §3.4's cases beside
  `AnswerParsingTests` (`:102`), `GroomApplyIntegrationTests` (`:243`) and
  `GroomSectionCoverageTests` (`:293`), which cover the grammar this section joins.

**Steps**

1. `closing.predates(item, ev, since)`: `since` set, the item's `created` (falling back to
   `stage_since`) earlier than it, `ev` carrying no commit, no PR and no branch, the state not
   `Closed`, and none of `landed:`, `reconciled:`, `removed:` typed. `since` unset → always false,
   which is the timid default (§1.4).
2. `ingest` appends `closing.PREDATES_LINE % created` to that item's `ev_lines` when the predicate
   holds, and nothing when it does not. `predates_marked(item)` is the one reader of that prefix.
3. `groom_predates_section(canonical, since)` renders one line per marked item, in `created` order,
   in the file's existing grammar — `- [ ] <id> <title> — created <date>, before the id convention
   (<since>); no commit, PR or branch names it → answer: ____` — so `OPEN_QUESTION_RE`,
   `ANSWER_LINE_RE` and `_SUPPRESSABLE_RE` read it with no change. The section is printed like
   every other, `(none)` when empty (P17).
4. `policy.suppress` runs over the new section unchanged (P6 of the spec): an item the feeder would
   launch on is rewritten `(spoken for: <ROW KIND>)`. No policy answers this section — it is added
   to no `POLICIES` row — so an unanswered question goes to the adjudicate row and, above
   `groom.adjudicate_attempts`, to the operator's digest.
5. `_parse_answer` gains `landed <sha>` → `('landed', <sha>)` for a 7–40 character hex sha, and
   `open` → `('reconciled', None)`, the date filled by the caller exactly as `removed`'s reason
   text is (`asf/groom/groom.py:318-319`). `no` keeps writing `removed: groom <date>`. Each goes
   through `frontmatter.write_typed` with the usual History line and the usual `groom_answer`
   event, whose `section` is `predates` because `_line_sections` reads the new heading.
6. All three answers make `predates` false permanently (clause four of step 1), so the next
   `asf ingest` writes no marker line and the next `asf groom` renders no line — asked once.
