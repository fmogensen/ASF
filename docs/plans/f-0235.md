# Plan F-0235 — the hook's verdict, moved to where the session can still answer it

Epic: E-0001 — ASF 0.1 — a working factory. Spec: `docs/specs/f-0235.md` (approved). Branch:
`plan/F-0235`.

Three Tasks, cut so that **the session is told the shape before the factory reads it back**:

1. **the gate, and the words for a refusal** — `hooks.pre_push_hook`, `repo_facts['pre_push']`, and
   the two new lines of `### Standing rules`. Every edit that changes brief *text* is here, in one
   Task, because all of it lands in one file and regenerates the same eighteen golden briefs (PD1).
   Nothing the factory *does* changes: the two rules are text a session reads.
2. **the retry the factory never spends twice** — `report.hook_retried`, and `retried` through
   health into `hook_refusal_hold`'s cap test. From here a session that says it retried is routed on
   the first hold instead of costing a second run.
3. **the class that refused** — `corr['refusal']` on the correction, `footprint` kept as
   `widen_footprint`'s own claim, and the scorecard pinned *unchanged* so the card can verify itself.

They run **1 → 2 → 3**, one at a time. The order is the card's own argument, not a convenience:
Task 2 teaches the factory to believe `hook refused twice`, and Task 1 is what tells a session to
write it. Landing 2 first would read back a shape no brief had asked for — harmless, but it would
route nothing, and the card's saving would not start. The footprints confirm the serialisation
independently: Tasks 2 and 3 both write `asf/workers/lifecycle.py`, `asf/workers/health.py` and
`tests/test_lifecycle.py`.

**Read PD1 and PD2 before writing a line of Task 1.** The spec's footprint omits the eighteen
golden brief fixtures that an unconditional new rule rewrites, and the preamble's untrimmable floor
is measured here at *exactly* the number one existing test asserts as its cap — so Task 1 lands red
in two places the spec does not mention, both of them expected and both of them named below.

The fences of §*The fences, and the suite* bind every Task, so every Gate and Acceptance block
below carries them beside its own.
