# Plan F-0129 — the product file says what is wrong with it: one schema Task, one reader, one writer, one pointer, one page

Epic: E-0001 — ASF 0.1 — a working factory. Spec: `docs/specs/f-0129.md` (approved). Branch: `plan/F-0129`.

Five Tasks, cut the way the spec's `## The design` is sectioned — by the module that gains the
surface, and in the order each one's ground has to exist. Task 1 is `asf/env.py`: `x-unmapped:`
declared so that a parked key does not refuse the load it was parked to permit, and a declared shape
for `ci:` and `deploy_sha:` so a wrong-shaped block stops being a silently ignored section. Task 2 is
the new module's read-only half — the three tables, the derived key list, the suggester, `findings`
— and `asf config check` with its registration. Task 3 is the writing half: `blocks`, `rewrite`,
`effect`, the three refusals, and `asf config migrate`. Task 4 is the pointer, in the three places a
load failure surfaces, plus the doctor's advisory `config keys` row. Task 5 is the guide: the rename
table split in two, the `x-unmapped:` section, the troubleshooting row, and the test that the code
table and the prose table cannot drift apart.

The chain is near enough linear because each layer needs the one below it: nothing can park a key
until `x-unmapped:` is a declared field (PD12), nothing can rewrite until `findings` can say what is
wrong, the doctor cannot count parked keys until something can read them, and the drift test needs
both the code table and the split prose table to exist. Tasks 3 and 4 are independent in substance
and queue only on `tests/test_install.py` (PD8).

Wave order: **1 → 2 → 3 ‖ 4 → 5** — in `after:` terms, 1 with `none`; 2 after 1; 3 after 2; 4 after 2
(queued behind 3 by its footprint); 5 after 3 and 4.

§Acceptance tests' last fence — both tree fences and the whole suite, as the pull request's CI runs
them — binds every Task, so every Gate below runs it beside its own.
