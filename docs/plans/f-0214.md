| PD3 | **A configured directory that does not exist yet is `absent`, not a `problem` — it reads green** | `cache_dirs`' docstring lists "not a directory" among the reasons a path may not be pruned, and the doctor is red for any directory carrying a `problem`. ## What no Task does

Nothing changes what a session's build tool does (the spec's §*Out of scope*): no `--summarize`
equivalent, no run-summary variable, no cache flag into `DEFAULT_WORKER_ENV` (`asf/env.py:360`),
no change to `test_command` and none to the gate. P3 is why that fence is safe to hold — the
gate runs the product's tests in a temp worktree under `harvest.gate_env`, whose environment
carries no cache variable, so the gate is a cold miss today and stays one, and a prune in the
tick can never race it. Turning summaries on is the operator's line below, not a code change.

The cache directory's path is not derived, not defaulted and not written into this package — the
pass reads the resolved worker environment and nothing else (C1, P1), so an operator who moves
the cache to another disk gets a refusal by **PD2** rather than a pruner aimed at a path the
sessions abandoned. No `dirs:` list of paths is added to the conventions block; no
`allow_outside: true` opt-in is added either, because the only thing it buys is the ability to
point an unlinker at an arbitrary directory, which is the risk and not the feature (C2).

No metric stream event, no record card, no ledger row, no event, no new CLI command (C9): a tick
every five minutes would add some 8 600 rows a month to a committed file to serve one status
cell, and the same 24-hour window already sits in the state file for free. The trend is a later
card with a window and a consumer.

This pass never inspects an entry: no dedupe, no archive verification, no repair of a corrupt
cache. It removes whole entries by date and by size, and by **PD7** it does that without
following a symlink and without a recursive delete anywhere in the module — the Gate greps for
`rmtree` because C2's boundary is the only thing between this code and the state dir's worktrees.
Other growing trees in the state dir keep their own passes: the worktree reaper
(`asf/workers/worktrees.py`), the trash deleter (`asf/workers/trash.py`), branch retention
(`asf/workers/retention.py`), briefs and logs. The `pnpm` store is untouched — it is per *user*,
not per product, and no product's `worker_env` points it into a state dir (`worktrees.pnpm_note`,
`:348-369`). Nothing prunes at spawn time or inside a wave: the health step is the only caller.

Read but not touched: `asf/env.py` — `worker_env` and `DEFAULT_WORKER_ENV` are read, and neither
gains a variable. `asf/workers/worktrees.py` — `du_kb` (`:269`), `_gb` (`:282`) and
`SIZE_MEASURES_PER_PASS` (`:55`) are the precedent this module copies in spirit and imports
nowhere; `caches._gb` takes bytes where that one takes kilobytes (**PD6**), and this pass needs
no `du` at all because C6 keeps the directory flat (**PD5**). `asf/workers/retention.py` —
`write_state`/`read_state` (`:326-339`) are the shape copied, `STATE_FILE` (`:33`) the precedent
that a state file name is a plain literal and not a product convention (P10).
`asf/conventions.py`'s `ZERO_OK` (`:297`) — read, and neither extended nor imported
(**PD12**). `tools/check_conventions.sh`'s four exemptions — unchanged; `asf/workers/caches.py`
is **not** added to them, and it does not need to be, because every path-shaped default it uses
it reads from `asf.conventions`. `asf/record/plan_tasks.py`'s four-digit `STORY_ID_RE`
(**PD14**). `asf/views/status.py`'s twenty-one existing rows and `asf/doctor.py`'s existing
