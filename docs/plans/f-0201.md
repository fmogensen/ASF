# Plan F-0201 — the verdict reads the tree, then the pass reads the branch

Epic: E-0001 — ASF 0.1 — a working factory. Spec: `docs/specs/f-0201.md` (approved). Branch:
`plan/F-0201`.

Two Tasks, a strict chain, one Story each. The spec's own shape is a pure function and the pass
that calls it, and the two are separable in exactly one direction:

1. **`asf/workers/lifecycle.py`, the verdict** — `branch_landings`, and `reap_verdict` reordered so
   that what the tree holds is asked before what origin has, with the new `branch_landed` ground
   behind it. **This is the Task that closes the card as it was observed**: the two 293 MB trees of
   lane-N had fast-forwarded heads (`in_trunk=True`), and the `in_trunk` rule alone reaps them the
   next pass — with health still passing no `branch_landed` at all.
2. **`asf/workers/health.py`, the pass** — each tree's branch resolved once (the orphan's second
   `gather` gone), that branch's landing handed to the verdict, and the end-to-end proof over the
   adopted-document landing sequence in both shapes.

Wave order: **1 → 2**, one Task per wave. `after: Task 2 → Task 1` is forced by the call, not
chosen: Task 2 passes `branch_landed=` and calls `lifecycle.branch_landings`, neither of which
exists on the trunk until Task 1 lands. Their `writes:` are disjoint, so nothing else queues them.

**The whole diff of both Tasks was applied in this worktree and run before this plan was written**
(PD12): `tests.test_lifecycle tests.test_workers tests.test_worktree_reaper tests.test_land_spec
tests.test_harvest` → **585 tests, OK**, with the pin corrected exactly as PD3 writes it, and the
four end-to-end cases of Task 2 reproduced green including the branch prune and the id-range
release. The working tree was then reverted; this branch carries the plan and nothing else.

**Read PD3 before touching `tests/test_lifecycle.py`** — the corrected pin block is given here in
full, and it resolves all five of its rows rather than only the two the spec names. **Read PD7
before writing the end-to-end class**: `Home` carries none of `TestHealth`'s helpers, and
subclassing `TestHealth` to borrow them re-runs its whole suite. **Read PD9**: the reap detail
carries the **full** sha, not the abbreviation the spec's illustration prints.

### Task 1: the verdict asks what the tree holds before it asks what origin has
stories: S-36750
writes: asf/workers/lifecycle.py, tests/test_lifecycle.py, docs/design/lane-state-machine.md
after: none

The spec's §1 in full: `lifecycle.branch_landings`, and `reap_verdict` reordered with one new
keyword. Nothing calls the helper and nothing passes the keyword when this lands — and yet **this
is the Task that closes the card**: a clean spec/plan worktree whose head the lane fast-forwarded
onto the trunk is `in_trunk=True`, and the reordered function reaps it on the next health pass with
`branch_landed` still defaulting to `''`. Task 2 adds the shape that needs the ledger.

**What changes for the machine when this lands.** One class of worktree that was kept forever is
reaped on the next pass — a clean tree, a finished-or-absent run, a dead pid, commits of its own,
and the trunk holding every one of them, whose branch origin no longer has (or whose HEAD origin's
branch does not contain). `prune_branches`, unchanged, takes the freed local branch in the same
pass, and `release_id_range` releases the job's block — for these trees, for the first time.
Nothing is written to the session registry (C6). Every other verdict and every keep reason is what
it was, with the one rename PD4 names.

**Files**

- `asf/workers/lifecycle.py` — new `branch_landings(path)`, placed immediately after
  `NOT_A_LANDING` and before `landed_earlier` (the two readers of that constant stay together);
  `reap_verdict` gains `branch_landed=''` and its tail is reordered. The module header's state
  table line for `reaped` gains the second ground. `by_branch`, `by_worktree`, `landed`,
  `landed_earlier`, `gather`, `Evidence` and every other function are untouched.
- `tests/test_lifecycle.py` — `ALandingOnTheBranch(unittest.TestCase)` added; the B-0019 block
  inside `LaunchAndReapInvariants.test_reap_on_landed_or_empty_and_only_then` corrected. No other
  existing test is touched.
- `docs/design/lane-state-machine.md` — the *is this worktree reapable?* row of the "who owns
  what" table (`:58`), three grounds to four (PD2).

**Steps**

1. `branch_landings(path)`, the spec's snippet verbatim, with the spec's docstring:

   ```python
   def branch_landings(path):
       """``{branch: the sha its latest run landed at}`` — the landings the ledger records, by
       branch. The *latest* run on each branch (:func:`by_branch`) and no earlier one: a branch
       whose last run carries no landing has work on it that has not landed, whoever landed it a
       round ago. An archival (:data:`NOT_A_LANDING`) is no landing.

       A lane branch is landed on the run the lane held for it, which is not always the run that
       owns the worktree sitting on that branch: an approved spec or plan the lane adopted lands
       on a synthetic run with no session and no worktree (:mod:`asf.tick.land_spec`), and the
       session that wrote the document keeps a row with no ``harvested``. This is how that tree's
       reap finds the landing (F-0201)."""
       return {b: r['harvested'] for b, r in by_branch(path).items()
               if r.get('harvested') and r['harvested'] not in NOT_A_LANDING}
   ```

   The docstring's second paragraph is the decision, not decoration — it is the sentence that stops
   a later reader from "simplifying" the helper to any run on the branch (PD6). Keep every mention
   of a document kind unquoted and unprefixed: `['"]spec/` and `['"]plan/` are generated fence
   patterns over `asf/**/*.py` (PD12/P9), and so is a bare `cloud/`.
2. `reap_verdict` gains `branch_landed=''` as the **last** parameter with a default, so all five
   existing positional call sites — one in `asf/workers/health.py`, four assertion shapes in
   `tests/test_lifecycle.py` — keep working unchanged. Its docstring becomes the spec's four-rule
   version, naming `branch_landed` as "the sha the ledger says this worktree's *branch* landed at
   (:func:`branch_landings`), '' when it says none".
3. The tail, from `if ev.uncommitted:` down, becomes exactly this — the three lines above it
   (`is_live`, the alive pid, `landed(run)`, the ended-not-finished block) are untouched:

   ```python
       if ev.uncommitted:
           return 'keep', f'{what}: uncommitted changes'
       if not ev.has_commits:  # B-0019: a fresh branch is an ancestor of the trunk too — opening
           return 'keep', f'{what}: {"no commits yet" if ev.remote_sha else "branch not pushed"}'
       if ev.in_trunk:  # the trunk holds every commit this tree has: nothing here is only here
           return 'reapable', what
       if branch_landed:  # the lane landed this branch on another run — a rebase or a squash
           return 'reapable', f'landed {branch_landed} on its branch'
       if not ev.remote_sha:
           return 'keep', f'{what}: branch not pushed'
       if not ev.head_on_remote:
           return 'keep', f'{what}: local commits not pushed'
       return 'keep', f'{what}: not in origin/{main}'
   ```

   Three orderings are load-bearing and none may be rearranged: `uncommitted` above everything
   (C4 — the card's "never a tree with uncommitted files", and `remove_worktree` would refuse it
   silently otherwise); `has_commits` above `in_trunk` (C8 — a fresh branch is an ancestor of the
   trunk, and that is "opening", never "merged", which is what forces PD4's rename); `in_trunk`
   and `branch_landed` above both origin proxies (C2 — with `not remote_sha` first the new grounds
   never fire, which is the whole defect). The full sha in the new detail is PD9.
4. The module header's state table (`asf/workers/lifecycle.py:18`) reads
   ``reaped     landed (or empty) and the worktree is gone``. It becomes the same line plus the
   second ground — the trunk holding what the tree holds, whatever origin still has of the branch,
   and a landing the ledger recorded on another run of it. One line; the table's column alignment
   is preserved.
5. `docs/design/lane-state-machine.md:58`'s row becomes four grounds in the order the code tests
   them: ``reap_verdict``: landed (B-0049) · ended-not-finished and empty (B-0025) · clean, with
   commits, the trunk holding them — whatever origin still has of the branch (B-0019, F-0201) ·
   clean, with commits, its branch landed under another run (F-0201); never a live run, never an
   alive pid``. The word *pushed* leaves that row, because after this Task the rule does not ask
   origin anything.
6. `ALandingOnTheBranch(unittest.TestCase)`, the spec's four bullets, no git — a `tempfile.mkdtemp`
   and a hand-written `sessions.jsonl`, the idiom `LaunchAndReapInvariants.setUp`/`write` already
   uses (`tests/test_lifecycle.py:1265-1275`):
   - **`branch_landings` over a written registry.** A branch whose latest run carries `harvested`
     maps to that sha. A branch whose latest run is a *newer* run with no `harvested` is **absent**
     though an earlier run on it landed — write the earlier landing and the later empty run with
     explicit, ordered `started` stamps, and assert the key is not in the dict (C3, PD6). A branch
     whose latest run carries `harvested: 'superseded'` is absent (C5). A branch nobody landed is
     absent. A run with no `branch` contributes nothing.
   - **The `in_trunk` ground.** `fin` finished, `Evidence(remote_sha='', head_on_remote=False,
     has_commits=True, in_trunk=True)` → `('reapable', 'ended')`; the same with `uncommitted=1` →
     `('keep', 'ended: uncommitted changes')`; with `has_commits=False` → `('keep', 'ended: branch
     not pushed')`.
   - **The `branch_landed` ground.** `fin`, `Evidence(has_commits=True, in_trunk=False)`,

     naming the uncommitted count (C4).
