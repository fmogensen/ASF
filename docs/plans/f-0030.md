# Plan F-0030 — the README carries the argument, the model and the manual, and a machine writes every number on it

Epic: E-0001 — ASF 0.1 — a working factory. Spec: `docs/specs/f-0030.md` (approved). Branch: `plan/F-0030`.

Six Tasks, cut along the spec's own build order: the thing that parses the page (Task 1), the thing
that reads the record (Task 2), the command and the two conventions that let any product own a page
(Task 3), the page itself with its committed numbers and the four checks that hold it (Task 4), the
quickstart run verbatim (Task 5), and the three surfaces that make drift visible without a human
reading the page (Task 6).

Four of the six write `asf/views/readme.py`, so they queue — which is also the honest order: nothing
can render a page before the grammar parses one, and no check can run against a page that is not
written yet. Task 6 is the one that escapes: it reads the module and writes `asf/doctor.py`,
`asf/tick/file_bugs.py` and `sample/`, so it runs beside Task 4.

Wave order: **1 → 2 → 3 → 4 ‖ 6 → 5**.

The spec is met where it actually lands in this tree, and four places are not where it says. PD4 (the
two path defaults fail `check_conventions.sh` in the module §2.1 puts them in), PD5 (§2.5's quickstart
fence names a flag and an output line that do not exist), PD6 (§2.1's link rule would let §3.4's own
regression case pass) and PD10 (§3 has no fence for the test S-17903's acceptance names) are each
closed inside the Task that causes them. No scope is added: every one of them is a section of the
spec, met against the tree as it stands.

§3.9's rule that the whole suite stays green and no product-specific name reaches a tracked file
binds every Task, so every Gate below runs `python3 tools/run_tests.py`, `bash tools/check_generic.sh`
and `bash tools/check_conventions.sh` beside its own fence.

### Task 1: the span grammar and the renderer
stories: S-17900, S-17901
writes: asf/views/readme.py, tests/test_readme.py
after: none

§2.1's first half: the module, its docstring, and the two functions that turn a page into spans and
spans back into a page. No record is read here and no command exists yet — this Task is the parser
and nothing else, so every malformed form has a test before anything depends on the grammar.

**Files**

- `asf/views/readme.py` — **new**: §2.1's module docstring (the two markers shown as they appear in
  a page, and "read-only over the record, stdlib only"); `MAX_LINES = 150`, `MAX_BYTES = 10_000` and
  `LITERALS = ('0.1', '2.0')` with the comment §2.1 gives each; `Span` (`kind`, `key`, `start`,
  `end`, `body`); `spans(text)`; `render(text, facts)`. The two path constants are **not** here
  (PD4) — they arrive in Task 3, on `asf.conventions`.
- `tests/test_readme.py` — **new**: `SpanTests`, `RenderTests`.

**Steps**

1. The module docstring per §2.1, byte for byte where the spec fences it: both markers shown in a
   page, the inline one in a sentence and the block one with its markers alone on their lines.
2. `spans(text) -> [Span]` — every span in document order. An `<!--asf:n <key>-->` may sit anywhere
   in a line; an `<!--asf:block <key>-->` and its close must each be alone on their line. Each error
   is raised naming the key or the 1-based line number, never swallowed: an unclosed marker, a close
   with no open, a span opened inside another, a key used twice, and a block marker sharing its line.
3. `render(text, facts) -> str` — each span's body replaced by `facts['numbers'][key]['text']`,
   splicing by the offsets `spans` returned so nothing outside a span can move. A key with no fact
   and a fact with no span are both errors naming the key; neither is rendered blank and neither is
   dropped.
4. `SpanTests`: a page with one inline span, one block span and prose between them round-trips
   (`render(text, facts_from(spans(text)))` is `text`); each of the five malformed forms raises, and
   the message carries the key or the line; a page with no marker gives `[]`.
5. `RenderTests`: a value replaced in the middle of a sentence leaves the sentence; a block's rows
   are replaced whole and its markers stay; a missing fact names the key it is missing; an unused
   fact names the key nobody asked for; rendering twice is the same bytes.

**Gate**

```sh
bash tools/check_generic.sh && bash tools/check_conventions.sh && python3 -m asf.cli check
```

### Task 2: the facts — every number, and the record reader that produced it
stories: S-17902
writes: asf/views/readme.py, tests/test_readme.py
after: Task 1

§2.2: one pass over the record builds every value the page can show, each carrying the reader that
produced it. Directive 10 holds — no new stream, no new event, no new matcher: `index_reader.load`
and `metrics.read_stream` are the only doors, and they are the ones the daily scorecard already uses.

**Files**

- `asf/views/readme.py` — `facts(record_root, repo_root, product=None, now=None) -> dict`; the
  per-key builders behind it; `_commands_rows(parser)` reading `asf.cli.build_parser()`.
- `tests/test_readme.py` — `FactsTests`.

**Steps**

1. `facts()` returns §2.2's envelope: `generated` (UTC, `metrics.iso`/`now_utc`), `record` (the
   record root's basename), `record_generated` (`index.json`'s `generated` stamp), `day`, and
   `numbers`.
2. Each entry of `numbers` is `{'value': …, 'text': …, 'source': …}`. Every key of §2.2's table is
   built and none other: `window`, `items`, `features_shipped`, `sessions`, `session_hours`,
   `spend_usd`, `usd_per_feature`, `ci_runs`, `ci_green_pct`, `ticks`, and the three block keys
   `scoreboard`, `cost_per_feature`, `commands`.
3. The readers are the existing ones, called as the rollup calls them: `index_reader.load(root)` for
   the cards and for `stage` in `('landed', 'on-prod')`; `metrics.read_stream(root, s)` for `ci`,
   `sessions` and `ticks`; `metrics.compute_costs` + `metrics.subtree_cost` for `usd_per_feature`;
   `metrics.cost_table(items, ci, sessions)` for `cost_per_feature`, trimmed to the five costliest
   shipped Features with its header and separator kept.
4. `window` is the first and last day carrying an event in any stream, rendered
   `<first> … <last> (<n> days)`. A record with no event at all renders `—`.
5. The no-events rule, applied to every key: a number with nothing behind it is `—`, never a `0`
   dressed as a measurement. `value` stays `None` in that case, so a reader of the facts file can
   tell "none measured" from "measured zero".
6. `commands` is one row per subcommand `build_parser()` registers, with its `help`, and is the one
   entry whose `source` is `cli` rather than a record path. It reads the parser, not the record, and
   `facts()` opens nothing under `repo_root` beyond importing it.
7. `FactsTests` per §3.2, against `sample/backlog` plus a metrics fixture written into a temp record:
   every key of §2.2 present; every entry carries a `source`; every source but `commands`' names a
   path under the record; an empty stream renders `—` and not `0`; `facts()` opens no path outside
   the record root (asserted by a patched `open`/`os.walk` guard, as the module's own test helper).

### Task 3: `asf readme` — refresh, check, json — and the two conventions that make it generic
stories: S-17903
writes: asf/views/readme.py, asf/conventions.py, asf/cli.py, docs/products.example.yaml, tests/test_readme.py, tests/test_conventions.py, tests/test_cli.py
after: Task 2

§2.1's checker and §2.3's command. The page's path and its facts file become conventions (PD4), so
the command is safe in front of any product — including one whose README carries no span, which is
the case that makes it safe to wire into `doctor` in Task 6.

**Files**

- `asf/conventions.py` — `DEFAULT_README = 'README.md'` and `DEFAULT_README_FACTS =
  'docs/readme-numbers.json'`, each with the one-line comment the module's style requires; the
  `readme` and `readme_facts` fields on `Conventions` (PD4). Both are relative to the product's
  repo dir, which the comment says.
- `asf/views/readme.py` — `complaints(text, facts, root) -> [str]`; `check(repo_root, conv)` reading
  the committed page and facts; `cmd_readme(args, root=None)`.
- `asf/cli.py` — `p_readme = sub.add_parser('readme', …)` with `--product`, `--check`, `--refresh`,
  `--json`, registered beside the other view parsers; its own dispatch block (PD7).
- `docs/products.example.yaml` — the two keys in the `conventions:` block, commented as the others
  are, shown at their defaults.
- `tests/test_readme.py` — `CommandTests` (PD10).
- `tests/test_conventions.py` — the two new fields load from a mapping and default when absent.
- `tests/test_cli.py` — `asf readme --help` parses; the subcommand is in `build_parser()`.

**Steps**

1. The two defaults and the two fields in `asf/conventions.py`, then `asf/views/readme.py` reads
   `conv.readme` and `conv.readme_facts` and carries neither literal (PD4).
2. `complaints(text, facts, root)` — §2.1's five checks, one string each, in the spec's order:
   a span whose body differs from its fact; a digit run in prose outside a span, inline code, a link
   target and `LITERALS`; a relative path that does not resolve under `root` (PD6's two forms); the
   line and byte budget; the three part headings absent or out of order. Empty list is a sound page.
3. `--refresh`: resolve the repo through `env.load_product(args.product).repo_dir` and the record
   through `resolve_record(args)`, build the facts, `metrics.write_if_changed` the facts file, then
   `write_if_changed` the rendered page. One line per file — `readme: <path> rewritten` or
   `readme: <path> unchanged`. Exit 0.
4. Default and `--check`: read the *committed* facts file, re-render, print every complaint, exit 1
   when there is one and 0 when there is none. No record is touched on this path, and no product
   config is required — the git root is the fallback repo root (PD7).
5. `--json`: `{"ok": bool, "complaints": [...], "day": "...", "stale_days": n}` on stdout and
   nothing else, where `stale_days` is the committed facts' `day` against today.
6. A README with no span: `readme: no spans — nothing to render`, exit 0, on every form including
   `--refresh` and `--json` (`ok: true`, no complaints). A missing facts file beside a spanned page
   is a complaint, not a crash.
7. `CommandTests` per PD10: `--refresh` writes both files and is a no-op the second time (the same
   bytes, and the "unchanged" line); `--check` on a page whose span was hand-edited exits 1 naming
   the key; `--check` needs no record (run with no product config resolvable); `--json` is the shape
   above and parses; a spanless README is exit 0 on all three forms.

### Task 5: the quickstart, executed verbatim
stories: S-17908
