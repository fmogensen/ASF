# Plan F-0229 — one reader of a branch's PR number, a bounce that terminates, and an I9 event said once per branch

Epic: E-0001 — ASF 0.1 — a working factory. Spec: `docs/specs/f-0229.md` (approved). Branch:
`plan/F-0229`.

Two Tasks, one per Story, cut along the two failures the spec holds apart:

1. **a merge is never attempted under a PR number nobody has** — `pr_number` and `back_to_pushed`
   in `asf/harvest/lane.py`, their two call sites (`merge_prs` before `MERGING` is written,
   `precheck` before the gate is spent), the `PR_OPEN → PUSHED` row that stops an unnamed branch
   reaching the gate at all, and the two docstring table rows.
2. **a merge found outside the lane is recorded once per branch** — `I9_SEEN`, `_i9_path`,
   `i9_seen` and `i9_unseen` in `asf/invariants.py`, one line of `lane_report`, one clause of
   `asf/record/check.py`'s docstring.

They run **together, as one wave**. Both are `after: none` and their `writes:` are disjoint — Task 1
is `asf/harvest/lane.py` + `tests/test_lane.py`, Task 2 is `asf/invariants.py` +
`asf/record/check.py` + `tests/test_invariants.py`. Nothing in Task 1 needs `asf/invariants.py`,
and **PD9** is the check that says so: the hazard F-0224's PD5 found — a new lane transition whose
feeder row the feeder's own I4 gate then drops — does not apply here, because the bounce launches
nothing.

**Read PD2, PD4 and PD5 before writing a line.** Each is a place where a literal reading of the
spec's design does something the spec's own text forbids: §5's body derives the ledger's path
*before* it looks at whether there are any events, inside the one `try` that would then swallow the
I8 findings the spec says it must keep (PD2); the bounce to `PUSHED` has to be shown to terminate,
because a landing wait that no clock can change is the exact defect this card exists to close
(PD4); and `pr_number`'s first term reads a PR list that is `--state all`, so a coder who "fixes" it
by filtering for `OPEN` puts the merged number and the recorded number back out of step (PD5).

### Task 1: a merge is never attempted under a PR number nobody has
stories: S-36700
writes: asf/harvest/lane.py, tests/test_lane.py
after: none

The spec's §1, §2, §3 and §4 whole. When this lands, `MERGING` is never written without a number a
merge can use: the number is read once through `pr_number` (the facts' live PR, then the lane
record, then the host's own open PR for the branch at this head, written back onto the facts), a
branch that has none anywhere goes back to `PUSHED` to be given one, and the `PR_OPEN → PUSHED` row
stops an unnamed branch reaching the gate at all.

Read **PD4** first — the bounce has to terminate, and the trace is the thing this Task is judged on
— then **PD5** (no state filter on the first two terms), **PD6** (what the lookup costs and why the
guard sits above the room check), **PD7** (the forward references, and why `merge_prs` needs no host
test) and **PD8** (the incident's own branch needs no migration).
