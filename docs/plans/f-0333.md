# Plan F-0333 — the factory gets a GitHub identity of its own

Epic: E-0002 — ASF 0.2 — self-improvement. Spec: `docs/specs/f-0333.md` (approved, landed at
`92afd4b9f`). Branch: `plan/F-0333`.

Four Tasks in two waves, cut along the one dependency the spec's design carries: **everything
reads the module, and the module reads nothing**. Task 1 is `asf/ghapp.py` — the declaration, the
JWT, the mint, the cache and the refresh, plus `openssl` as a new kind in the client ratchet with
that module as its only owner. Tasks 2, 3 and 4 are the three seams that read it, and they touch
no file in common: **Task 2** puts the token into the one auth map (`asf/env.py`) and opens the
host's two refresh doors (`asf/kernel/loop.py`, `asf/workers/spawn.py`); **Task 3** gives the one
`gh` client a default identity for the 30 call sites that name no environment
(`asf/github.py`, `asf/upgrade.py`); **Task 4** is everything the operator touches — the shape
check, the example file, the doctor row and the two guide pages.

Wave order: **1 → (2, 3, 4)**. Tasks 2, 3 and 4 each import names that do not exist on the trunk
(`ghapp.configured`, `ghapp.token_path`, `ghapp.TOKEN_VAR`, `ghapp.refresh`, `ghapp.token`,
`ghapp.settings`, `ghapp.expires_at`), so all three wait on Task 1 and none waits on another:
their `writes:` sets are pairwise disjoint (`PD1`), so the record runs the three of them together.

| PD7 | **`refresh` raises exactly one exception, and both doors must catch it by name** | The spec says `refresh` "never raises", and also that a 403/429 body goes through `gh_limit.inspect` so "a rate limit latches the process exactly as a `gh` call's would". Both cannot be literally true: `gh_limit.inspect` (`asf/gh_limit.py:104-111`) calls `trip` (`:94-101`), which latches **and raises** `RateLimited` — and `RateLimited` is a **`BaseException`** (`asf/gh_limit.py:40-42`), *"a BaseException on purpose: never caught by an ``except Exception`` fallback"*. So the contract Task 1 must implement is: **`refresh` returns `('', why)` for every failure and raises `RateLimited` and nothing else.** Concretely, `ghapp` catches `Exception`, never `BaseException` and never a bare `except:` — the language already does the right thing, and writing `except BaseException` is the one way to break S-120855's *"a mint answered with a rate-limit body latches the process the way a refused gh call does"*. The consequence at the doors is the part the spec's §4 misses, and it is a regression if missed: `asf/kernel/loop.py` has **no** `RateLimited` handler of its own — the kernel's is inside `facts.read_facts` (`asf/kernel/facts.py:152`, *"a blind tick, never a crash"*), which runs **after** the door — and above `tick` the only handler is `asf/cli.py:772`, which returns `EX_TEMPFAIL` and decides nothing. So an unguarded door turns a rate-limited mint into an **aborted** tick where today the same exhausted quota gives a *blind* one that still plans everything not read from GitHub. That is the exact failure this card exists to fix, re-introduced one layer up. Both doors therefore wrap `refresh` in `except gh_limit.RateLimited` (the spelling `facts.py:152` already uses), log the one line and carry on; the latch then makes the port calls below self-refuse, which is today's blind tick. This is what S-120858's *"a failed refresh does not fail the tick"* and *"a failed refresh at launch does not refuse the launch"* are asserting, and each wants a rate-limit case, not only a generic-failure one. |

The spec's design §1 whole, and nothing else: one new module that reads the App's declaration,
signs a JWT with `openssl`, mints an installation token, caches it with its expiry and refreshes

a name from it and it imports nothing from them: at this head `grep -rn 'app_id\|installation_id\|installations' asf | wc -l`
is `0` (`P8`), so no existing reader is extended and no existing test can go red from this Task —
a red in its Gate is its own. It writes no `asf/env.py`, no `asf/github.py` and no doctor row:
those are Tasks 2, 3 and 4.

**Gate** nor the **Acceptance** below reaches it; the card's `links.plan` is this file. Four

**Steps**

1. `settings`, `configured`, `token_path`, `meta_path`, `token`, `expires_at` — the whole no-network
   half of the module, and the four declaration cases of the Story. `app_id` is accepted as any
   non-empty scalar and kept as the string the JWT's `iss` needs; `installation_id` is an `int`
   when set and the field is empty when not. Build the paths from `env.ASF_HOME` (`PD11`).
2. `signing_input` and `sign`. Two base64url segments joined by `.`, **unpadded** (strip `=`);
   header `{"alg":"RS256","typ":"JWT"}`, claims `{"iat": now-60, "exp": now+540, "iss": app_id}`
   off the clock passed in, never `time.time()` read inside. `sign` invokes
   `['openssl', 'dgst', '-sha256', '-sign', key_file]` with the signing input on **stdin** and
   returns `(None, why)` on a non-zero exit, the `why` naming the key *path* and carrying no line
   of the key (`D11`). `P7` is the shape to write the failure case against: `openssl`'s own refusal
   names the path and nothing else, on both hosts the spec measured and on this one.
3. `jwt`, then `installation` (`GET /repos/<slug>/installation`, skipped entirely when the product
   declares an `installation_id` — `D2`), then `mint`:
   `POST /app/installations/<id>/access_tokens` through the module's one
   `urllib.request.urlopen`. Write the token file at `0o600` holding the token and nothing else,
   and the meta file holding `{app_id, installation_id, slug, minted_at, expires_at, error}` —
   **no secret**, which the Story asserts as "no substring of the token or the key".
4. `refresh`, in the spec's own order: no App → `('', 'no app configured')` with nothing read or
   written; a cached token further from expiry than `REFRESH_MARGIN_S` → `(expires_at, '')` and
   **no call at all**; `mutation_guard.is_active()` → one `would mint an installation token for
   <slug>` line and `('', 'dry run')`; otherwise mint. A failed mint leaves the **previous token
   file exactly as it was** and records the reason in the meta file's `error`.
5. **The exception contract, written deliberately** (`PD7`): a 403 or 429 body goes through
   `gh_limit.inspect` *before* anything else is read from it, and `inspect` latches and raises
   `RateLimited` — a `BaseException` by design (`asf/gh_limit.py:40-42`). So catch `Exception`
   around the mint, never `BaseException` and never a bare `except:`. `inspect(args, returncode,
   stdout, stderr)` returns quietly on a zero `returncode` (`:107-108`), so pass a non-zero one
   and the response body as its text. The Story's *"latches the process the way a refused gh call
   does"* is the case this step exists for; assert the latch (`gh_limit.latched()`) and the raise,
   not just a reason string.
6. The ratchet: `PATTERNS`, `OWNERS`, the docstring list. Then
   `bash tools/check_clients.sh --against origin/main` — it must read
   `ok — gh 14, git 298, claude 0, launchctl 0, systemctl 0, openssl 0` (`PD3` is the baseline, and
   the new column is expected). `tools/clients-baseline.txt` is expected unchanged (`PD6`).
7. Write `tests/test_ghapp.py`. The two cases easiest to get wrong, both measured: the
   *"only urllib request site"* line must grep for **`urllib.request`**, because
   `asf/clockinstall.py` uses `urllib.parse` three times and a `urllib` grep fails on a module
   that makes no request (`PD6`); and the *"ratchet names it as that kind's owner"* line asserts
   `check_clients.OWNERS['openssl'] == frozenset({'asf/ghapp.py'})` by loading
   `tools/check_clients.py` the way `tests/test_github.py:20-22` already does. The secrecy line
   (*"no value the module returns, logs or writes contains the token or any line of the key file,
   over every failure path above"*) is a loop over the failure paths of steps 2-5 asserting the
   token and a key line appear in no return value, no captured log and neither file — write it as
   one case over all of them, not one assertion per path.
8. Run the Gate.
