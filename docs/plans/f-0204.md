# Plan F-0204 — a missing check is Actions' to skip only if the head's own workflows say so

Epic: E-0001 — ASF 0.1 — a working factory. Spec: `docs/specs/f-0204.md` (approved). Branch:
`plan/F-0204`.

**One Task.** The spec's whole change is a scan function, a memo method, one `for n in missing:`
loop, a sixth element on one return tuple, two call sites, and three sentences of prose. C10 says
it lands whole and **PD2** walks the only cut available and refuses it: the reader alone is a
function with no caller on the trunk, the rule alone is the defect, and the two could not run in
parallel anyway because the rule's tests are written against the reader.

**Every precondition of the spec was re-read in this worktree and all seventeen hold** (PD11) —
including the one that mattered most, P8: the spec's own `parse_job_names` body was run here
against this repo's `.github/workflows/tests.yml` and against the trap fixture, and it returns
`['tests']` and `['gate', 'e2e', 'm8-e2e', 'call', 'dyn', 'flow']` — byte for byte what the spec
claims. The design is buildable as written.

Four things the spec does not say, and a coder who types `## The design` would meet as surprises:

- **The `WORKFLOW_DIR` lift is not free.** The spec promises `runs_on` "keeps working word for
  word"; it reads `self.WORKFLOW_DIR`, so removing the class attribute is a `AttributeError`
  unless that line changes too. **PD3**, two words.
- **The test stub answers anything it does not recognise `1, '', 'unexpected'`** — so the first
  `/contents/` call breaks not one test but **all eight** in the class. **PD9** names the shape the
  harness needs before any new test is written.
- **A job whose `name:` is an expression loses its rendered check name**, so one real class of
  genuinely-path-filtered Actions check is now refused where today it is satisfied. **PD5** — the
  honest cost of C3, not an oversight, and it degrades to a wait, never to a false merge.
- **The protection is time-boxed.** A refused name stays in `missing` and reaches the
  `landing_checks_missing: wait` clock; after `landing_checks_wait_min` the PR is gated locally and
  lands anyway. The spec puts that Out of scope and is right to, but **PD6** states it so nobody
  reads this card as "a third-party check can never be bypassed".
