# Plan F-0186 — the residue: the second docs reader, the doctor row, the pinned landing

Epic: E-0001 — ASF 0.1 — a working factory. Spec: `docs/specs/f-0186.md` (approved). Branch:
`plan/F-0186`.

The spec's D1 is the shape of this plan: `conventions.doc_paths` is on the trunk, the landing
decision already honours it, and the card's own two tests pass as written today. What is left is
three separate things that touch three disjoint sets of files:

1. **the evidence half stops disagreeing with the landing** — `lane.path_hit` and
   `lane.doc_matchers` become the one rule and the one list, and `evidence.doc_dirs`/`docs_only`
   read them, so a spec landed through a merge queue beside a declared doc folder is no longer
   taken as its Feature's code landing;
2. **`asf doctor` lists the folders a product declared** — one always-green, never-required row;
3. **the native landing is pinned** — three methods on the existing `LandTheApprovedSpec`, test
   code only, no product code at all.

They run **1 ‖ 2 ‖ 3** — one wave, three coders. No `after:` edge is real (PD1), and no two
`writes:` lines intersect, so nothing serialises them.

**Read PD2 before writing `doc_matchers`.** The spec's §2.1, typed verbatim, turns one misshapen
`doc_paths` into a matcher per character — one of which is `*` — and hands that to
`evidence.docs_only`, where it would make every commit docs-only and no Feature ever read landed.
It is one `isinstance`, and it is the one place this plan knowingly departs from the spec's "
`landing_class`'s behaviour is unchanged". **PD3** corrects P2's mechanism (`shape_findings`
returns `[]` for `doc_paths`; the refusal is `env.load_product`'s, and it is louder than P2
claims). **PD7** is why `tests/test_lane.py` is in no Task's `writes:`.
