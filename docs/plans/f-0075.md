### Task 8350: the one scanner — `asf/redact.py` and `asf redact`

stories: S-7050
writes: asf/redact.py, asf/cli.py, tests/test_redact.py

**Files**

- `asf/redact.py` (new)
- `asf/cli.py` (one registration)
- `tests/test_redact.py` (new)

**Steps**

1. New `asf/redact.py` with exactly the surface of §2.1: `Finding` (a `NamedTuple` of `path`,
   `line`, `kind`, `source`), `Refused` (carrying `findings`), `patterns`, `scan_text`,
   `scan_staged`, `scan_unpublished`, `scan_tree`, `gate`, `format_findings`.
2. `patterns(repo=None, cfg=None, environ=None, extra=())` merges, each pattern carrying its
   `kind`, its `source` and a case-insensitive compiled regex:
   - *names* (D5) — every `worker_pool.accounts[].name` of the config as `\b<re.escape(name)>\b`,
     source `worker_pool.accounts`; every line of `$ASF_HOME/redact-names.txt` and of the scanned
     repo's tracked `tools/forbidden-names.txt` as an extended regex, blank lines and `#` comments
     skipped — the format `check_generic.sh` reads today; `extra` is `--names <file>`.
   - *secrets* (D6) — the eight built-in rules of §2.1 (`private-key`, `aws-access-key`,
     `github-token`, `anthropic-key`, `openai-style-key`, `slack-token`, `jwt`, `url-password`),
     each with its id as `rule:<rule-id>`, and each written so its own source text does not match
     it.
   - *environment values* (D6) — every variable of `environ` (default `os.environ`) whose name
     matches `TOKEN|SECRET|KEY|PASSWORD|PASS|CREDENTIAL` and whose value is ≥ 12 characters, the
     value as a literal, source `env:<VAR>` — the name, never the value.
   No config, no private list and no repo list is an **empty** pattern set, not an error
   (Preconditions). `ASF_HOME` is the one `asf/env.py:18` already resolves.
3. What is read, per §2.1:
   - `scan_staged` — the `+` lines of `git diff --cached -U0 --no-color --no-ext-diff`, their
     new-file line numbers taken from the hunk headers; binary files skipped.
   - `scan_unpublished(repo, head, pats)` — `git rev-list <head> --not --remotes=origin` (D4:
     every commit reachable from the pushed sha and from no `refs/remotes/origin/*` ref), and per
     commit the `+` lines of `git show -U0 --format= <sha>` plus its message `%B` with the trailer
     block removed as `git interpret-trailers --parse` reports it — so the sign-off and
     `Co-Authored-By:` are never scanned (Out).
   - `scan_tree` — every file of `git ls-files` except `LICENSE`, every line.
4. `format_findings` renders `<file>:<line>: <kind> (<source>)` and nothing else (D8): the matched
   text never reaches stdout, stderr, a log or the ledger. There is no inline allow marker and no
   code path that reads one (D7).
5. `gate(findings, where, product=None)` — clean is a no-op; otherwise it appends one line per
   finding to `<env.state_dir(product)>/redactions.jsonl` when a product resolves, with the §4
   fields (`ts`, `where`, `repo`, `path`, `line`, `kind`, `source`, optional `job`) and never the
   matched text, then raises `Refused(findings)`. No product → no file, and the scan still runs.
6. The command, the five modes of §2.1 — `--staged`, `--pre-commit`, `--unpublished [REV]`
   (`REV` defaults to `HEAD`), `--pre-push`, `--tree`, with `[--product p]` and repeatable
   `[--names FILE]`. It runs in the cwd's repo, is **not** a record command, does not call
   `cli.resolve_record` and prints no `record: <path>` line. Clean → `redact: clean`, exit 0.
   Findings → one `format_findings` line each, then
   `redact: refused — N finding(s); no line above is printed as it was`, exit 1. Not a git repo,
   or an unreadable list → exit 2 with the reason. `--pre-commit` is `--staged` recorded as
   `where='hook-pre-commit'`. `--pre-push` reads git's
   `<local ref> <local sha> <remote ref> <remote sha>` lines from stdin, skips a deletion (local
   sha all zeros) and runs `scan_unpublished` for each remaining local sha.
7. Register the subparser in `asf/cli.py` beside the other `register(sub)` calls. Per P3 nothing
   under `plugin/` changes.
8. Give the module a `__main__` entry so `python3 -m asf.redact …` works from a checkout — D11
   and §2.5 invoke it that way.
9. `tests/test_redact.py` with the classes of §3.1. Each test makes its own temporary repo,
   config home and environment; none reads the operator's real `~/.ASF`. Every name and token a
   test needs is built from parts, so the test file itself passes the gate — as
   `tests/test_check_generic.py` already does for names.
   `test_a_finding_never_prints_the_matched_text` asserts that neither the account name, nor the
   secret, nor the env value occurs anywhere in stdout or stderr of a refused `asf redact`.
   `test_a_refusal_appends_one_ledger_line_per_finding_without_the_text` asserts the same of the
   ledger file.
10. Check `bash tools/check_conventions.sh` passes with the new module (P6), and keep `/tmp/`,
    `.claude/` and a hardcoded item id out of it — the script fails `asf/*.py` on all three.

### Task 8351: the tick cannot skip the gate — `asf/tick/shadow.py`

stories: S-7051

- `asf/tick/step_wave.py` — the stale docstring at line 14
- `tests/test_shadow.py`, `tests/test_tick.py`

**Steps**

1. `commit_local(path, message, product=None)` (P5): after `git add -A` and the no-change check,
   and before `git commit`, build the patterns once for `path` and call
   `redact.gate(redact.scan_staged(path, pats), where='tick-commit', product=product)`. On
   `Refused`, run `git reset -q` and re-raise — the index is left as it was found and **no commit
   is made**.
2. `push(path, out=None, retries=PUSH_RETRIES, product=None)`: call
   `redact.gate(redact.scan_unpublished(path, 'HEAD', pats), where='tick-push', product=product)`
   before **each** `_push_once` — the first one, and the one at the end of every retry round.
   Scanning once at entry is not enough and the code must not be written that way: a round
   fetches, rebases onto a moved `origin/<branch>` and may re-derive the tree through
   `_resolve_by_ownership`, so the shas the later `_push_once` publishes are new ones no earlier
   scan saw (D4).
3. `tick.commit_and_push` catches `Refused` and prints, verbatim in shape:

   ```
   tick: commit refused — redaction: 1 finding
     metrics/events/2026-09-22.jsonl:3: name (worker_pool.accounts)
   NEEDS OPERATOR: a line the tick wrote carries an operator name or a secret — find its writer; `git add -A && asf redact --staged` in <clone> shows it again
   ```

   and returns 1. The clone is derived state — the next run resets it, and the lines the steps
   appended are lost exactly as they already are on a refused push. `run_shadow` and `schema.py`'s
   migrate print the same lines and return 1.
4. Thread the product through those three call sites so the ledger resolves (P5).
5. Correct the docstring at `asf/tick/step_wave.py:14`: a launch event carries item, job, model
   and brief kind — no account. (`03728fd` took `account` out of the event; the docstring still
   claims it.)
6. `tests/test_shadow.py` gains `RedactionGateTests` and `tests/test_tick.py` gains
   `CommitAndPushTests`, per §3.2. The first test reproduces 2026-09-21: an `events` line carrying
   a configured account name, written through `Context.event`, and `commit_and_push` refusing it
   with the origin unchanged. `test_every_retry_round_scans_before_its_push_once` drives `push`
   with an origin that moves under the first attempt and asserts **one scan per `_push_once`** —
   not one scan for the call.

   the session that wrote the line is the one that removes it. A docs branch is handed back the
   same way: `send_back`'s DOCS branch is only for kinds `gate` and `conflict` (`:2431`). When a
   set has more than one member each finding is attributed to the member whose own commits carry
   it; under `harvest.gate: per-branch` the set is one branch (`:2535-2537`).
4. No special case at the cap: at `ROUND_CAP` `lifecycle.hold` already stops climbing, marks the
   correction `at_cap` for the ADJUDICATE row and flags the operator on a second hold at the cap
   (B-0048). A redaction hold goes through that rule like any other hold — do not add a branch for
   it, and nothing has to be registered for the new `kind` (PS5).
5. `tests/test_harvest.py` gains four more `RedactionTests` methods, per §3.3.
   `test_the_hold_hands_the_findings_back_as_the_correction` asserts the run's `correction` has

   Absent → written, mode 0755. Present and not installed → **not touched**; the caller gets
   `NEEDS OPERATOR: <path> is not asf's — add the line: "<asf>" redact --pre-push --product <p>`.
   Running it twice changes nothing.
4. `install(product, …)` calls `ensure_git_hooks` **before** the `'hooks: 0 rules declare a hook'`

   alongside the others.
