# F-0083 — plan: scheduler clocks are configuration

Feature: F-0083 — Scheduler clocks are configuration: each job group on its own interval, per
product. Epic: E-0001 — ASF 0.1 — a working factory. Branch: `plan/F-0083`.

Binding spec: `docs/specs/f-0083.md`. This plan adds no scope that the spec doesn't already
carry. Where the spec needed a narrower reading or a clarification to be buildable, the decisions
below say so.

## Decisions

- **P1 — The callers that break move in the same Task as the scheduler.** Removing
  `--steps`/`--interval` (spec D6) and `interval_s()` breaks `tools/cutover.sh`, which calls
  `install --steps … --interval …`, `tests/test_cutover.py`, and `asf/doctor.py:261`, which calls
  `scheduler.interval_s(cfg)`. A Task that removed them and left those callers to a later wave
  would put a red suite on the trunk between waves. So Task 1 carries the cutover migration
  (S-7206) and the one-line D11 change in `asf/doctor.py`. That is the spec's own "the callers
  that read the old clock move with it". Task 2 builds doctor's new rows on top.
- **P2 — `steps_slug` stays.** The spec removes `DEFAULT_INTERVAL_S`, `DAILY_CALENDAR`,
  `interval_s()` and the two flags. It doesn't remove `steps_slug`, and
  `docs/specs/f-0078.md:381` asserts against `scheduler.steps_slug`. Labels and logs stop using
  it (spec D3), but the function is kept.
- **P3 — Doctor's clock rows sit behind the launchd kind check.** `scheduler_rows` returns early
  for a non-launchd kind, because nothing can be read back. The spec's "declared but not
  loaded" and "declares no clocks" rows go after that check. The yellow `scheduler.interval_s`
  row goes before it, since it is about config, not launchd. This also keeps
  `tests/test_sample_product.py::test_doctor_is_clean` green, because the sample's
  `config.yaml` has `scheduler.kind: none`. The spec is silent on this, so this is a reading,
  not new scope.
- **P4 — A 24-hour interval renders `0 0 * * *` in cron.** Spec D9 accepts "whole hours that
  divide 24". For h = 24, `0 */24 * * *` is outside cron's hour range (0–23), so it renders as
  midnight daily. Every other divisor (1, 2, 3, 4, 6, 8, 12) renders `0 */h * * *`.
- **P5 — The `needs_operator` text names the duration in the file's syntax.** `Clock` holds
  seconds (the spec's `Clock` tuple is fixed by `test_the_card_example_parses`). The marker
  turns seconds back into the largest whole unit (`5400` → `90m`, `7200` → `2h`), which is what
  `test_inexpressible` looks for.
- **P6 — A shadow clock passes cutover's ownership check.** A shadow clock has no `steps`, and
  cutover's `manifest_owns ""` is vacuously true, so it is installed. The spec's cutover section
  only speaks of "its steps". This is the literal reading, not an addition.
- **P7 — Cutover's `RECORD_LOG` comes from the rendered job.** `tools/cutover.sh` hard-codes
  `tick-$PRODUCT-record.log`. Under spec D3 the log is named after the clock, so gate 3 reads
  the `log` of the first clock whose steps include `record`, from `render --json`.
- **P8 — A `SchedulerError` from `clocks()` is one line per refused clock.** The spec says "one
  `clock <name>: <why>` clause each" and "its line(s) on stdout". The message joins the clauses
  with newlines, in file order.
- **P9 — Gate command.** The spec's whole-suite gate (`… | tail -3`) shows test stdout, not the
  verdict: on `origin/main` at `ba2942d` its last three lines are a tick's log. Each Gate below
  keeps the spec's command in Acceptance, byte for byte, and also runs `… 2>&1 | grep -E
  '^(Ran|OK|FAILED)'` to read the verdict. The baseline on `ba2942d` is `Ran 830 tests`,
  `OK (skipped=13)`.
- **P10 — No card ids in this plan.** The record mints Task card ids from the `### Task N:`
  headings (`asf/record/plan_tasks.py`, `mint_id`). A session never mints one, so this plan
  names none.

## Tasks

### Task 1: The clock moves from argv into the product file — scheduler, CLI, and the callers that break with it
stories: S-7200, S-7201, S-7202, S-7203, S-7204, S-7206
writes: asf/env.py, asf/scheduler.py, asf/doctor.py, tools/cutover.sh, tests/test_clocks.py, tests/test_scheduler.py, tests/test_cutover.py

**Files**

- `asf/env.py` — `PRODUCT_FIELDS['clocks'] = _MAP`.
- `asf/scheduler.py` — `Clock`, `clocks()`, the new `render` / `tick_argv` / `label_for` /
  `log_path`, `retire_candidates`, the CLI.
- `asf/doctor.py` — only line 261, the never-ran interval (spec D11). The rest of doctor is
  Task 2.
- `tools/cutover.sh` — iterate the declared clocks (spec D12).
- `tests/test_clocks.py` (new), `tests/test_scheduler.py`, `tests/test_cutover.py`.

**Steps**

1. `asf/env.py`: add `'clocks': _MAP` to `PRODUCT_FIELDS` (`asf/env.py:222-227`). The deep checks
   live in the scheduler.
2. `asf/scheduler.py`, removals: `DEFAULT_INTERVAL_S`, `DAILY_CALENDAR`, `interval_s()`. Keep
   `DAILY_STEP` and `steps_slug` (P2). Rewrite the module docstring: logs are
   `tick-<product>-<clock>.log`, and the clocks come from `products/<p>.yaml`'s `clocks:`.
3. `Clock = namedtuple('Clock', 'name steps shadow interval_s calendar')`.
   `clocks(product) -> [Clock]` in file order:
   - `clocks:` absent or empty → `SchedulerError('NEEDS OPERATOR: products/<p>.yaml declares
     no clocks — add a clocks: block (see docs/products.example.yaml)')`.
   - Per entry, collect every refusal (spec D8) as `clock <name>: <why>`:
     - a name not matching `[a-z0-9][a-z0-9-]*`;
     - an entry that isn't a map;
     - any key outside `steps`, `shadow`, `every`, `at`, refused by name (`evrey`);
     - `shadow` together with `steps`;
     - `steps` missing or empty on a non-shadow clock;
     - a step not in `asf.tick.steps.STEPS`;
     - a step with no owner: `steps.resolve(product, [s])` + `steps.check_owned`, catching
       `StepError` and naming the step. `off` is owned; only `undeclared` is refused;
     - both or neither of `every`/`at`;
     - an `every` that `asf.tick.stale.limit_seconds` rejects, or one under 60 s;
     - an `at` that isn't `HH:MM` 24 h (`([01]?\d|2[0-3]):[0-5]\d`).
   - Any refusal → one `SchedulerError`, one clause per line (P8).
   - Import `asf.tick.steps` / `asf.tick.stale` inside the function, which keeps
     `asf.scheduler`'s import graph as it is.
   - The steps keep the order they are written in. The tick puts them in manifest order itself.
   - `calendar` is `{'Hour': h, 'Minute': m}` for `at`; `interval_s` is seconds for `every`. The
     other field is `None`. A shadow clock has `steps == []`.
4. `tick_argv(product_name, clock)` → `--shadow` for a shadow clock, `--daily` for
   `steps == ['daily']`, else `--steps a,b,c`. `label_for(product_name, clock_name, cfg)` →
   `<prefix>.<product>.<clock_name>`. `log_path(product_name, clock_name)` →
   `<ASF_HOME>/logs/tick-<product>-<clock_name>.log`.
5. `render(product, clock, cfg=None)`: the job dict as today, plus `clock`, `steps`, and
   `every_s` or `at`.
   - launchd: `StartInterval` or `StartCalendarInterval`.
   - cron (spec D9):
     - `*/m * * * *` for whole minutes under 60;
     - `0 */h * * *` for whole hours with h in 1, 2, 3, 4, 6, 8, 12, and `0 0 * * *` for
       24 h (P4);
     - `m h * * *` for `at`;
     - anything else: no `line`, and `needs_operator` naming the duration (P5).
   - Other kinds: the existing marker, now naming `every <dur>` or `at HH:MM`.
6. `retire_candidates(product_name, declared_labels, cfg)`: labels from `loaded_jobs(cfg=cfg)`
   that start with `<prefix>.<product>.` and are not declared. The trailing dot keeps
   `asf.other.*` and a `legacy_labels` match out.
7. The CLI:
   - `register`: drop `--steps` / `--interval`, add `--clock`, keep `--label` (status only) and
     `--json`.
   - `cmd_scheduler`, `list`: unchanged.
   - Every other command first calls `clocks(product)`. On `SchedulerError`, print its lines on
     stdout and exit 2 without writing anything.
   - An unknown `--clock` → `scheduler: no clock <name> in products/<p>.yaml (clocks: a, b)`,
     exit 2.
   - `render`: `--json` gives a list of job dicts, even for one clock. Plain output gives one
     `# <label>` header per clock, then its plist, cron line or marker.
   - `install`, no `--clock`: render every clock first, then `install(job)` each. For launchd,
     then `uninstall(label)` each `retire_candidates` label and print `scheduler: retired
     <label> (not a clock in products/<p>.yaml)`.
   - `install --clock`: that clock only, and no retirement.
   - `install` exits 0 for launchd, 3 otherwise.
   - `status`: `--label` reads that label as today. `--clock` reads one clock. With neither, it
     prints one line per declared clock and exits 1 if any clock is not loaded. `--json` gives
     the info dict, or a list of them for all clocks.
8. `asf/doctor.py:261`: `interval = data.get('StartInterval') or (86400 if
   data.get('StartCalendarInterval') else None)`, and skip the never-ran check when it is
   `None`. Nothing else in doctor changes in this Task.
9. `tools/cutover.sh`:
   - Drop `DISPATCH_STEPS` and `INTERVAL`. Where they were defined (line 166, before gate 1),
     list the clocks with `run_scheduler render --product "$PRODUCT" --json` into name, label,
     log and steps per clock.
   - A nonzero exit there prints the scheduler's stdout (the NEEDS OPERATOR line) and exits
     nonzero before gate 2 or the old-job retirement touches anything.
   - `install_job <clock>`: label from the listing, `run_scheduler install --product "$PRODUCT"
     --clock <clock>`, and the same `record_manifest scheduler_install` row as today.
   - Loop over the clocks: `manifest_owns "<steps,comma-joined>"` → `install_job`. Otherwise print
     `<clock> (<steps>): the manifest does not own these steps — leaving the legacy job loaded`.
     A shadow clock's empty steps pass (P6).
   - Gate 3: `RECORD_LABEL` / `RECORD_LOG` come from the first clock whose steps contain
     `record` (P7), and `job_completed` calls `status --clock <that clock>`. With no such clock,
     gate 3 fails with `NEEDS OPERATOR: products/<p>.yaml has no clock that ticks record — add
     one (see docs/products.example.yaml)`.
10. Tests:
    - `tests/test_scheduler.py`: `SchedulerTestCase` gains a `write_product(clocks_yaml)`
      helper that writes `products/sample.yaml` under the temp `ASF_HOME`, so `test_clocks`
      reuses it with `fake_launchctl` / `fake_loaded`.
    - Move every `render('sample', [...], 600)` and `--steps` call to a clock. `test_no_steps_refuses`
      becomes a `clocks()` refusal, and `test_daily_is_a_calendar_job` becomes an `at:`
      clock.
    - `parse_print`, `parse_list`, `loaded_jobs`, `jobs_using`, `install`/`uninstall` keep their
      assertions.
    - `tests/test_clocks.py`: every test listed in Acceptance, by class and name.
    - `tests/test_cutover.py`: the fixture's `products/sample.yaml` gains `record`, `dispatch`,
      `daily` clocks. `test_apply_splits_the_clock_into_record_dispatch_and_daily` and
      `test_dispatch_is_not_installed_when_the_manifest_does_not_own_it` become the spec's
      `test_cutover_installs_the_declared_clocks` and `test_cutover_skips_an_unowned_clock`.
      Add `test_cutover_without_clocks_stops_before_changing_anything`. The gate-3 tests read
      the record clock's label.
