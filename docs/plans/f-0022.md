# F-0022 — plan: the preamble opens with the facts the runner already holds

Feature: F-0022 — The preamble: every brief opens with facts the runner already knows. Epic:
E-0001 — ASF 0.1 — a working factory. Branch: `plan/F-0022`.

Binding spec: `docs/specs/f-0022.md`. This plan adds no scope the spec does not already carry.
Where the spec needed a narrower reading, a correction, or a detail it left out to be buildable,
the decisions below say so.

The spec's whole shape is already in the code: `preamble.collect` reads five facts off a
`repo_facts` dict and `_doc_line` already renders `(N lines)` when it finds one. What is missing is
a caller that fills the dict, and a reading that proves the fill was worth the change. This plan
cuts that into four Tasks: the gatherer and its key contract, the launch path that uses it, the
token fields on the `sessions` stream, and the view that prints the before and the after.

Everything below was re-checked in this worktree on 2026-09-23 against `origin/main` at `d95905a`.
Where a line count or a line number differs from the spec's (which was checked at `c8dff94`), the
number here is the current one.

## Decisions

- **P1 — The spec's Story ids are not in the record, and as written no code can read them. They
  are carried verbatim anyway, and the operator mints the Stories.** Two facts, both checked here
  on 2026-09-23. First, the record (`product:backlog_dir`) holds four Stories, `S-0001` through
  `S-0004`, and not one Story whose parent is F-0022 — which is what the brief that opened this
  session meant by `The Stories: (none yet)`. Second, `asf.record.plan_tasks.STORY_ID_RE` is
  `\bS-\d{4}\b`, and a five-digit id does not match it: `re.findall(r'\bS-\d{4}\b', 'S-14150')`
  returns `[]`, because the boundary between `5` and `0` is not a word boundary. `stories_of` then
  keeps only ids the record already holds, so even a matching id would be dropped. The consequence
  is concrete: when this plan lands on the trunk, `mint_plan_tasks` will cut four Task cards whose
  `stories` list is empty.

  This plan carries `S-14150`–`S-14156` on its `stories:` lines regardless. They are the spec's own
  ids, in the spec's own order, and substituting ids of my own is precisely what the standing rule
  forbids — `mint_id` formats `{prefix}-{n:04d}` off the record's high-water mark, so the next
  Story would be `S-0005`, but that is a prediction until `asf new` actually runs and this session
  must not write in the operator's record checkout. The operator line under Task 1 gives the seven
  commands. Once they have run, the `stories:` lines are edited to the minted ids — a one-line
  change per Task, in the commit that lands Task 1 or sooner.

- **P2 — Four Tasks, and their footprints are disjoint by construction.** Task 1 owns
  `asf/briefs/**`, `asf/conventions.py`, `docs/products.example.yaml` and the brief tests and
  goldens; Task 2 owns `asf/tick/step_wave.py` and `tests/test_tick_steps.py`; Task 3 owns
  `asf/metrics/metrics.py` and `tests/test_metrics.py`; Task 4 owns `asf/views/tokens.py`,
  `asf/cli.py` and `tests/test_tokens.py`. Checked against `footprint.globs_overlap`: the only
  open-ended globs in the plan are Task 1's `asf/briefs/**` and
  `tests/fixtures/briefs/golden/**`, and neither literal head nests inside any other Task's paths,
  so the feeder sees no overlap and queues nothing.

- **P3 — Task 1 cannot be split, because its acceptance holds both sides of one contract.**
  `ContractTests.test_keys_match_what_the_preamble_reads` asserts
  `set(facts.repo_facts(...)) == set(preamble.REPO_FACT_KEYS)`. A Task that ships only
  `asf/briefs/facts.py` has no `REPO_FACT_KEYS` to compare against; a Task that ships only the
  preamble half has no `facts` module to import, and `tests/test_brief_facts.py` fails at import
  time. The same holds for the sizes: `_test_line` reads `facts['files']`, which `collect` does not
  carry today and `facts.line_counts` is the only thing that fills. The drift between two dicts is
  the defect this card exists to close; a Task boundary drawn through the contract would ship the
  defect again in a new place.

- **P4 — `collect` does not carry `files` forward today, and must.** `asf/briefs/preamble.py:225-249`
  builds its facts dict with `spec_lines` and `plan_lines` resolved through `_line_count`, and no
  `'files'` key at all. `wanted_paths` and `_test_line` both need the raw map, so
  `'files': dict((repo_facts or {}).get('files') or {})` is an addition, not a rename. This is the
  one line of `collect` the spec's "needs no change to `collect` itself beyond carrying `files`
  forward" is pointing at, and it is easy to skip because `spec_lines` already works without it.

- **P5 — `(new)` is claimed only when the tree was read.** A test path absent from `files` can mean
  two different things: the rev does not carry the file, or nothing was measured at all (an
  unreachable repository, `repo_facts=None`). `_test_line` distinguishes them by whether
  `facts['files']` has any entry: an empty map means the bare name is printed, a non-empty one
  means `(new)`. Without this the `asf brief` preview and every test that passes `repo_facts=None`
  would assert that every test file in the card is new, which is a guess — and the rule the module
  was built on is that a fact nobody passed is printed as unknown, never guessed
  (`asf/briefs/preamble.py:23-27`).

- **P6 — Task 2 runs a test file it may not write.** S-14151's acceptance names both
  `tests.test_brief_facts.HeadTests` and `tests.test_tick_steps.WaveStepTests`. `HeadTests` proves
  `facts.head_of` and belongs beside the module it tests, so it is written by Task 1 and is inside
  Task 1's footprint. Task 2 runs it as a gate and does not edit it. The Story is on Task 2's
  `stories:` line because Task 2's landing is what makes it true of a real brief: until
  `step_wave.run` passes the row, `head_of` is correct code nobody calls.

- **P7 — The goldens are regenerated, and the diff is read before it is committed.** Seven files
  under `tests/fixtures/briefs/golden/` are the committed record of the brief's shape. Their diff
  in this change is the before-and-after of the card, so it is read as evidence: every
  `(not known here)` gone, `(N lines)` on the documents, sizes or `(new)` on the tests. A golden
  whose *shape* moved — a section reordered, a heading changed — is a defect, not an update: the
  spec puts "changing what the preamble says" out of scope, and `ASF_UPDATE_GOLDEN=1` will happily
  bless a regression that nobody looked at.

- **P8 — Measure what the brief prints, and never expand a glob.** `wanted_paths` takes the spec,
  the plan, the review file for a review kind, each named test with any `::node` suffix cut, and
  each `writes:` entry that carries **no wildcard** — deduped in that order, cut to
  `preamble_max_files` (12). A `writes:` line is globs (`asf/briefs/**`), and expanding one can
  mean thousands of paths for a line the preamble never writes. The cap is what makes the cost of a
  launch a constant rather than a function of the card's footprint.

- **P9 — The gatherer never fetches, and every step may fail into nothing.** One
  `git ls-remote --heads origin <branch>` per launching row — the call `step_wave.repo_facts`
  already makes today (`asf/tick/step_wave.py:118`) — and everything else read from refs the clone
  already has. A launch must not wait on a `git fetch`, and a missing repository, an unpushed
  branch and a rotated log are all normal. A fact that cannot be read is left out of the dict, the
  preamble prints its existing `(not known here)` marker, and `facts_unknown` on the `launch` event
  turns the silent gap into a number.

- **P10 — Task 4 does not touch `asf/metrics/metrics.py`.** `asf tokens` is a reader:
  `asf/views/sessions.py` shows the pattern — it opens `metrics/sessions/<day>.jsonl` and
  `json.loads` each line, importing nothing from `asf.metrics`. Task 4 does the same over a
  `--days` window each side of `--split`, so it neither writes the record nor shares a file with
  Task 3. That is what lets the two run in different waves without a queue.

- **P11 — No Task ids in this plan.** The record mints Task ids from the `### Task N:` headings
  (`asf.record.plan_tasks.mint_plan_tasks` → `asf.record.ids.mint_id`); a session never mints one.
  This session was handed no `BACKLOG_ID_RANGE` value, which is consistent: it has none to spend.

**Steps**

1. **`preamble.REPO_FACT_KEYS`.** `('head', 'branch_exists', 'files', 'tests', 'last_report')`,
   with a docstring naming `asf.briefs.facts.repo_facts` as the one function that fills it and the
   contract test as what holds them equal. These are exactly the keys `collect` reads today
   (`asf/briefs/preamble.py:235-247` via `_line_count`, `named_tests`, and three `.get` calls).
2. **`collect` carries `files`** (P4): add `'files': dict((repo_facts or {}).get('files') or {})`
   to the returned dict. `spec_lines`/`plan_lines` keep resolving through `_line_count` as they do.
3. **`preamble.wanted_paths(facts, limit=None)`** — new, pure, no filesystem. In order:
   `facts['spec_path']`, `facts['plan_path']`, `facts['review_path']` when `facts['kind']` is in
   `REVIEW_KINDS` (`asf/briefs/preamble.py:129`), each entry of `facts['tests']` with any `::node`
   suffix cut, then each entry of `facts['writes']` that contains no wildcard character. Dedupe
   preserving that order, then cut to `limit or conventions(product).preamble_max_files`. A glob
   never survives (P8).
4. **`preamble._test_line(name, files)`** — new, pure. `f'{name} ({files[path]} lines)'` when the
   path (suffix stripped) is a key of `files`; `f'{name} (new)'` when `files` is non-empty and the
   path is not a key; the bare `name` when `files` is empty (P5). `state_lines` joins them with
   `'; '` on the existing `Tests named by the card:` line — one line stays one line.
5. **`preamble.unknown_count(text)`** — new, pure: the number of occurrences of `UNKNOWN`
   (`asf/briefs/preamble.py:32`) in the text. Task 2 is its only production caller; it lives here
   because the marker does.
6. **`asf/briefs/facts.py`.** Five functions, the docstring the spec fixes:

   - `head_of(repo, branch, main) -> (head, branch_exists, rev)` —
     `git ls-remote --heads origin <branch>` gives `branch_exists`;
     `git rev-parse --verify -q origin/<branch>^{commit}` picks `rev`, falling back to
     `origin/<main>`; `git log -1 --format=%h %s <rev>` gives the line, to which the ref is
     appended: `… (origin/fix/B-0001)` when the branch is pushed, and
     `… (origin/main — fix/B-9999 is not on origin yet)` when it is not. The parenthetical is the
     whole point — without it the sha reads as the branch's own tip, which it is not.
   - `line_counts(repo, rev, paths) -> {path: lines}` — **one** `git cat-file --batch` fed
     `<rev>:<path>` per wanted path, newlines counted from each blob. A path the rev does not carry
     answers `missing` and is simply absent from the map — never `0`, which would read as an empty
     file.
   - `tests_under(tree_paths, writes, limit=6) -> [path]` — pure. A path under the item's `writes:`
     footprint by `footprint.globs_overlap` (`asf/feeder/footprint.py:21`, a pure fnmatch — a
     concrete path is a glob with no wildcard) whose basename looks like a test file. Sorted, cut
     to six.
   - `last_report(product, item_id) -> str` — `lifecycle.item_runs(path, item)`
     (`asf/workers/lifecycle.py:228`) filtered to runs that have an `ended`, newest first;
     `runtime.read_result(log)` (`asf/workers/runtime.py:126`) for its result text;
     `report.parse(text)` (`asf/workers/report.py:31`) for the typed fields. Render
     `<job> ended <ts> — <end_reason>` then `status`, `pushed`, `tests`, `left out`, `ruling` — each
     of those five capped at 200 characters — and nothing above the REPORT block. No ended run →
     `''`. A log that is gone → the one `<job> ended <ts> — <end_reason>` line and no fields.
   - `repo_facts(product, row, index, inflight=None) -> dict` — the five keys, in this order, every
     step allowed to fail into nothing (P9): `preamble.collect(product, row, index, inflight)` with
     no facts (the cheap pass that says which documents and tests this brief will name) →
     `head_of` → `line_counts(repo, rev, preamble.wanted_paths(facts))` →
     `tests_under(ls_tree(repo, rev), facts['writes'])`, whose results join the wanted paths for the
     same `cat-file` batch so they arrive sized → `last_report(product, row.item_id)`. The returned
     dict always has all five keys.

7. **`conventions.preamble_max_files`** — `DEFAULT_PREAMBLE_MAX_FILES = 12` and the dataclass field.
   `Conventions.from_mapping` keeps unknown keys in `extra` (`asf/conventions.py:168`), so this
   breaks no existing product file. Add the commented line to `docs/products.example.yaml`.
8. **`build.cmd_brief` fills the facts** — `build(product, row, index, inflight,
   repo_facts=facts_mod.repo_facts(product, row, index, inflight))`, so what an operator previews
   is what a session is handed.
9. **Write `tests/test_brief_facts.py`** — the six classes of the Acceptance block below, in that
   order. `PreambleIsCodeTests` are AST scans, not string greps: an import of `http`, `urllib`,
   `socket` or `requests` in either module, or of `subprocess`/`os.popen` in `preamble.py`, fails.
10. **Add the five tests to `tests/test_briefs.py`** — `test_sized_tests_line`,
    `test_unknown_head_still_says_unknown`, `test_wanted_paths`, `test_unknown_count`, and
    `CmdBriefTests.test_asf_brief_fills_the_facts` (a stub `facts.repo_facts`, asserted called once
    with the row).
11. **Regenerate the goldens** — `ASF_UPDATE_GOLDEN=1 python3 -m unittest tests.test_briefs -v` —
    then **read the seven diffs** before staging them (P7). Print the diffstat as a heartbeat line.
    If a heading moved or a section changed order, stop: that is out of scope and a defect in the
    change, not in the fixture.
12. **Run the gate**, commit with `git commit -s`, push the branch.

### Task 4: `asf tokens` — the before and the after, per brief kind
stories: S-14156
writes: asf/views/tokens.py, asf/cli.py, tests/test_tokens.py

Runs after Task 3: the two keys it reads do not exist on the stream until Task 3 lands.

**Files**

- `asf/views/tokens.py` — **new**. A reader over `metrics/sessions/<day>.jsonl`, modelled on
  `asf/views/sessions.py`'s `_ended_rows`: open the file, `json.loads` each non-blank line, skip a
  line that does not parse. It imports nothing from `asf.metrics` and writes nothing (P10).
- `asf/cli.py` (350 lines) — the `tokens` subparser beside `sessions`
  (`asf/cli.py:156`), and `'tokens'` added to the `('roadmap', 'backlog', 'parity', 'prod',
  'sessions', 'status')` tuple at `asf/cli.py:309` with its `cmd_tokens(args, view_root)` branch.
- `tests/test_tokens.py` — **new**. `TokensViewTests` over a temp record.

**Steps**

1. **The subparser.** `asf tokens [--product P] [--split DAY] [--days N] [--json]`. `--split`
   defaults to today, `--days` to 14. A session **on** the split day counts as *after*.
2. **The window.** `--days` each side of `--split`: the before window is the `--days` days ending
   the day before the split, the after window is the split day and the `--days - 1` days after it.
   A day with no file is not an error.
3. **The rows.** One row per brief kind present in either window, plus an `all` row over every
   session of both. Each cell is a **median**, not a mean — one 12-million-token session would
   otherwise be the whole reading. Columns: kind, before count, before in/session, after count,
   after in/session, Δ, turns (`before → after`).
4. **The empty window.** A window with no session prints `—` in its cell and `—` in the delta.
   There is no division by zero anywhere: the delta is computed only when both medians are numbers
   and the before is non-zero.
5. **`--json`** prints the same rows as a list of objects — the same numbers, unformatted.
6. Run the gate, commit with `git commit -s`, push.
