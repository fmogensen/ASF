# B-0294 — plan: name the API's own overloaded/5xx error instead of leaving it OTHER

Item: B-0294 — 21 % of sessions end "other" (threshold 10 %, 85 of 407 in 24h). Epic: E-0001 —
ASF 0.1 — a working factory. Branch: `fix/B-0294`. No spec exists — the Acceptance below is the
record.

## Cause

A session whose CLI run ends with the provider's own overloaded/5xx error (`overloaded_error`,
`internal_server_error`, `service_unavailable_error`, `bad_gateway_error`, or the plain
`API Error: 5xx` text `headroom.LIMIT_RE` already reads `API Error: 429` the same way) had nothing
in `FAILURE_SIGNATURES` naming it, so `failure_reason` fell through to `OTHER` with every other
unnamed failure. That is one retryable, provider-side cause hiding inside the generic bucket, not
a defect in the session's own work.

## Task 1 — give the overloaded/5xx error its own outcome class

writes: `asf/workers/runtime.py` `tests/test_lifecycle.py` `tests/test_workers.py`

- Step 1: in `asf/workers/runtime.py:608-627`, add `OVERLOADED = 'overloaded'` and
  `OVERLOADED_RE`, a regex matching `overloaded_error`, `internal_server_error`,
  `service_unavailable_error`, `bad_gateway_error`, or `API Error: 5\d\d` (case-insensitive).
- Step 2: in the same block, add `(OVERLOADED, OVERLOADED_RE)` to `FAILURE_SIGNATURES` so
  `failure_reason` names the class instead of leaving it to the `OTHER` fallback.
- Step 3: tests —
  - `tests/test_workers.py::TestSpawn::test_b0294_an_overloaded_api_error_is_named_not_left_bare` —
    a result record carrying a bare `API Error: 529 {... "type":"overloaded_error" ...}` is
    `result_ok() is False` and `failure_reason()` returns `runtime_mod.OVERLOADED`.
  - `tests/test_lifecycle.py::OutcomeClassTests::test_b0294_an_overloaded_api_error_is_its_own_class_not_other` —
    `lc.outcome_class(f'failed: {lc.runtime_mod.OVERLOADED}')` returns `lc.runtime_mod.OVERLOADED`,
    which is in both `lc.OUTCOME_CLASSES` and `lc.FAILING_CLASSES`.
  - Update the two vocabulary-order tests that enumerate the full class tuple so `'overloaded'`
    is in the list where the new `FAILURE_SIGNATURES` entry places it: `OutcomeClassTests::test_the_vocabulary_is_the_specs_in_the_specs_order`
    and `NothingToLandTests` (the `OUTCOME_CLASSES[3:-1]` membership check).

## Out of scope

The card's Description evidence block is `stalled: no beat Nm` lines — stalled sessions, not
sessions whose `result` carries a bare provider 5xx. This plan does not claim the fix accounts for
the full 85/407; it names and classes the one cause the record can actually point to from the
code (an unnamed API 5xx falling to `OTHER`), and leaves it to be checked against fresh
`metrics/sessions/*.jsonl` data before the card is called closed, same as review round 1's I-list
already asks.
