# Plan F-0203 — the reader, the launch, the three rewrites, and the update at merge time

Epic: E-0001 — ASF 0.1 — a working factory. Spec: `docs/specs/f-0203.md` (approved). Branch:
`plan/F-0203`.

Four Tasks. The spec's shape is a module nothing calls, then four call sites that call it, and the
Stories map one-to-one onto four landable commits:

1. **`asf/ci_flight.py`, the reader and the verdict** — `run_in_flight`, `Flight`, `urgent`, the
   three exception constants, `verdict`. Nothing calls it when this lands; the factory's behaviour
   is byte-identical.
2. **The launch rebase asks first** — `spawn._rebase_onto_trunk` consults the verdict before it
   rebases, and `severity` is threaded from `pool.Row` to it. **This is the Task that fixes the
   card's own supersede**: the 18:23Z push that re-dated all five commits does not happen.
3. **The lane's three content-free rewrites** — `repair_naming` and `drop_copies` wait for the run,
   `repair_signoff` claims `RED` and goes through unless the branch is S1.
4. **The update moves to merge time** — `_protection`/`protected_strict` off the one cached payload,
   and `update_for_merge` in `merge_prs`, the one rebase this card allows.

Wave order: **1 → (2 ∥ 3) → 4**. Task 2 and Task 3 are disjoint in `writes:` and independent on the
merits, so they run together; Task 4 shares `asf/harvest/lane.py` with Task 3 and would queue behind
it whatever `after:` said, and it depends on Task 3's `Lane.flight` anyway (PD1).

**Read PD2 before writing Task 3's `repair_signoff` guard**: the spec's `return None` is not a
deferral — it is a hold, and it sends the S1 the card is about BACK to a session with a red-checks
correction, which is worse than both the status quo and the wait C4 asked for. **Read PD3 before
writing `run_in_flight`**: `gh run list --json` has no `id` field; the run id is `databaseId`.
**Read PD4 before writing Task 2's `CONFLICT` case**: a conflicting rebase aborts and moves nothing,
so the head cannot tell a taken exception from a deferral — only the line can. **PD5** is the
fixture lift Task 2 needs to be its own test class at all.

| PD8 | **`update_for_merge` rebases in the pass's own `ref_checkout()`, reset to `origin/<trunk>` on entry — no second throwaway-worktree lifecycle — and `push_branch` is a safe vehicle because `lost_commits` is patch-id based** | The spec names `H.rebase_and_resolve` and `H.push_branch` but not where the worktree comes from, and that is the whole of the step's risk. ### Task 1: one reader of a branch's live run, one verdict, three named exceptions
stories: S-36600
writes: asf/ci_flight.py, tests/test_ci_flight.py
after: none

The spec's §1 entire, and nothing else — a new module with two functions, a class and four
constants, and no state. Nothing imports it when this lands, so the factory's behaviour is
byte-identical.

This Task exists so that the rule the card implies is written **once**: `spawn` and `lane` must
answer alike about one branch (C7), and the only way two call sites in two subsystems that import
neither each other nor `ci_queue` can do that is to read one function.

**What changes for the machine when this lands.** Nothing observable. No `gh` call is made that was
not made before, because nothing calls `run_in_flight` until Tasks 2–4.

**Files**

- `asf/ci_flight.py` — new. The module docstring is the spec's, verbatim from its §1 block.
  `CONFLICT`, `RED`, `STRICT`, `URGENT_EXCEPTIONS`, `CI_FLIGHT_TIMEOUT_S`, `DEFER_FMT`;
  `run_in_flight`, `urgent`, `verdict`, `Flight`.
- `tests/test_ci_flight.py` — new. `RunInFlight`, `Urgent`, `Verdict`.

**Steps**

1. The four constants and the two format strings exactly as the spec's §1 block writes them,
   `#:` comments included — `CONFLICT = 'conflicting'`, `RED = 'a required check is red on this
   head'`, `STRICT = 'the host requires an up-to-date branch'`,
   `URGENT_EXCEPTIONS = (CONFLICT,)`, `CI_FLIGHT_TIMEOUT_S = 30`,
   `DEFER_FMT = '{what} deferred: {branch} CI in flight (run {run})'`. `URGENT_EXCEPTIONS` is a
   tuple so no caller can widen C4's rule for the whole process.
2. `run_in_flight(product, branch, run=None, timeout=CI_FLIGHT_TIMEOUT_S)`, on
   `capacity.ci_runs_in_flight`'s discipline (`asf/capacity.py:502-525`) and never on its `--jq`:
   - `ci = product.ci if isinstance(getattr(product, 'ci', None), dict) else {}`,
     `workflow = ci.get('workflow')`, `repo_slug = getattr(product, 'repo_slug', None)`;
     `if not workflow or not repo_slug or not branch: return None`. This is the P8 guard that makes
     the whole card inert for every product in the suite — write the reason into the docstring.
   - the argv is **PD3's**: `['gh', 'run', 'list', '-R', repo_slug, '--workflow', workflow,
     '--branch', branch, '--limit', '20', '--json', 'databaseId,status,createdAt']`, through
     `(run or subprocess.run)(…, capture_output=True, text=True, timeout=timeout,
     env=ci_pool._gh_env(product))`, with `from asf import ci_pool` inside the function as
     `capacity` does.
   - `except (OSError, subprocess.TimeoutExpired): return None`; `if p.returncode != 0: return
     None`; `json.loads` inside a `try` for `ValueError`/`TypeError` → None; a payload that is not
     a list → None. **Never raises** is a promise of the docstring and of six tests.
   - the rows kept are `isinstance(r, dict) and r.get('status') != 'completed' and
     r.get('databaseId')`; the newest is `max` by `(str(r.get('createdAt') or ''),
     int(r.get('databaseId') or 0))`, the tree's own ordering key (`asf/ci_queue.py:2242`,
     `:2751`) — never "the first row gh printed", which is gh's default order and not a contract.
   - the return is `{'id': r['databaseId'], 'status': r.get('status') or ''}` (PD3: the `gh` field
     is `databaseId`, the public key is `'id'` because `DEFER_FMT` reads `run`), else `None`.
3. `urgent(branch, severity=None, item=None, items=None)` — C5, one definition:
   `if items: from asf import ci_queue; return ci_queue.priority(item, items, branch=branch)[0]
   == ci_queue.S1`, else `'hotfix' in (branch or '').lower() or severity == 'S1'`. The import is
   lazy, as C5 says and as `lane_pass` already reaches `ci_queue`. The docstring says why there is
   no second severity test here: `ci_queue.priority` is the tree's one definition of the tier and a
   copy would drift.
4. `verdict(product, branch, what, needed=None, severity=None, item=None, items=None, flight=None)`:
   - `flight = flight or Flight()`; `run = flight.read(product, branch)`;
     `if not run: return ''` — **the only question asked when nothing is in flight**, so a pass over
     a quiet product costs one `gh` read per branch and no argument is evaluated. The docstring's
     table is the spec's, copied.

     run still in flight it defers with `update deferred: …` (C4). The caller turns that into a
     wait (step 4).
   - `expected = H.sh(['git', 'rev-parse', f'origin/{b}'], …)` — **before** the rebase, per
     `push_branch`'s docstring; `wt = lane.ref_checkout()`, and `if not wt: return False` with
     `lane.ref_wt_error` said.
   - PD8's rebase: `H.sh(['git', 'checkout', '-q', '--detach', f'origin/{lane.trunk}'], cwd=wt)` —
     required, not hygiene: the checkout may have been left detached elsewhere by another step this
     pass — then `head = rev-parse HEAD`, then `ok, reason = H.rebase_and_resolve(wt, lane.trunk,
     onto=head, tip=f'origin/{b}')`, exactly `combined_head`'s call (`:2553`).
   - a conflict is `send_back`'s: `if not ok: send_back(lane, f, 'conflict', <the text merge_prs'
     conflict path writes, naming the rebase onto origin/<trunk> and never a merge>,
     conflict_files(lane.repo, lane.trunk, b)); return None`. `None` is distinguishable from
     `False`, and the caller must `continue` on it rather than merge.
   - `new = rev-parse HEAD` in `wt`; `ok, why = H.push_branch(lane.repo, new, b, expected,
     lane.trunk, refguard.listed(lane.conv))`; a refused push says why and `return False` — the
     next pass reads origin again. PD8: `lost_commits` is `git cherry`, so a clean rebase's
     patch-equivalent commits are not read as a loss and the push is made.
   - on success, **PD9's record**: `f['head'] = new`, then
     `lane.set(f, WAITING_CI, f'updated onto origin/{lane.trunk} for the merge', result='waiting')`
     — `lane.set`, not `wait()`, so no previous record's `green` is carried onto a head that never
     had one; and `return True`.
4. `merge_prs`, between the `if stale:` block and `lane.set(f, MERGING, …)`:
   ```python
           upd = update_for_merge(lane, f, number)
           if upd is not False:
               continue   # updated (WAITING_CI at the new head), deferred, or sent back
   ```
   `continue`, never a merge: this pass merges nothing for that PR, and the next green pass merges
   it — the card's *once*. The three non-`False` answers all mean "not this pass", and the one
   `False` means "nothing to do, carry on to MERGING", which is every product here today.
5. `UpdateAtMergeTime(LaneFixture)`, the spec's paragraph, in two halves:
   - **the payload**, against a faked `H.gh_json` and a real temp `state_dir`:
     `{'strict': True, 'contexts': ['ci']}` gives `protected_checks() == ('ci',)` and

     fake's calls); a cache entry holding `at` and `checks` and **no** `strict` is re-read even

     called); a `404 Branch not protected` payload — `H.gh_json`'s `{}` — gives `((), False)`
     exactly as this product sees it (P6); and the entry written back carries all three keys.
   - **the step**, on a real `LaneFixture` origin with a branch two commits behind the trunk and a
     green PR fact: with `strict` **false**, nothing is pushed, `update_for_merge` returns `False`,

     attempted). With `strict` **true**: `origin/<branch>` is rebased once onto the trunk, the
     branch is `WAITING_CI` at its new head, **no merge was attempted**, and a second pass on the

     **once**, which is the card's word, asserted by running the pass twice and counting pushes.
     With `strict` true, a run still in flight and the record carrying `severity: S1`,
