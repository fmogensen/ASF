# Plan F-0188 — the reference is the product's, the mechanism is the factory's

Epic: E-0001 — ASF 0.1 — a working factory. Spec: `docs/specs/f-0188.md` (approved). Branch:
`plan/F-0188`.

**Four Tasks, two waves.** The spec's `## The design` is four numbered sections and its `## Stories`
is four bullets, one per section, and they cut apart cleanly on one joint: §1 builds
`Product.references`, and §2, §3 and §4 are three independent readers of it. So Task 1 is §1 alone,
and Tasks 2, 3 and 4 are §2, §3 and §4 with `after: Task 1` and footprints that do not intersect —
wave 2 is three coders at once. **PD4** walks the two edges a reviewer will expect and shows why
neither exists: the table reads the record rather than recomputing it (C12), so §3 never runs §2's
closing rules, and the groom policy reads a Story's Tasks rather than a state §2 derives.

**Nothing has moved under the spec.** `git log 83df873f6..HEAD` over the nine files this card edits
is empty: the twelve commits since the spec was written touched `CHANGELOG.md`,
`asf/scorecard/{diagnose,loop}.py`, `asf/workers/lifecycle.py`, `tests/test_{lifecycle,scorecard}.py`
and eight documents, and not one line of `asf/env.py`, `asf/evidence/closing.py`,
`asf/record/ingest.py`, `asf/views/parity.py`, `asf/surface.py`, `asf/cli.py`, `asf/groom/policy.py`,
`asf/groom/groom.py` or `asf/views/header.py`. Every line number in the spec is exact here, and the
eight preconditions worth re-running were re-run rather than trusted (**PD2**).

**Three things a coder cannot discover by typing the spec's `## The design`**, and they are the
reason this plan is longer than the cut:

- **`Conventions` declares `matrix_path: str = DEFAULT_MATRIX_PATH`, and `DEFAULT_MATRIX_PATH` is
  `None`.** The declaration reads like a filled default. If it were one, C2 would synthesise a
  legacy reference for *every* product, C7's fall-through would be dead and P5's "no fixture churn"
  would be false. It is not one — but only if `Product.references` tests the value for **truth**.
  **PD3.**
- **The spec's acceptance block 2 names two test classes, and one of the two assertions its own P4
  pins lives in neither.** `test_the_documented_example_validates` is a method of
  `TestProductSchema`, not of `DocumentedModelsTests` or `ProductValidation`. Block 2 as written
  runs the other one only. **PD5.**
- **The Story loop in `ingest.derive` already has a `review_claims` local, and it is not the
  collection §2 wants.** `review_proven` is review-derived; `ev['proves']` is `landed_proves`,
  trunk-derived. Reusing the local in scope would make `ref_proven` true for a claim that never
  landed — which is the one thing P10 says a claim is not. **PD7.**

### Task 1: the product declares its references — one declared key, one per-entry checker, one resolved property, and the example that documents it
stories: S-35900
writes: asf/env.py, docs/products.example.yaml, tests/test_env.py
after: none

The spec's `## The design` §1 whole, in one commit. After it lands, a product file may carry a
top-level `references:` list, every misshapen entry is refused with a dotted key at the right line,
`Product.references` resolves the declared order with defaults filled, a product that declares only
`conventions.matrix_path` still yields the one synthesised legacy reference with `evidence: merge`,
and `docs/products.example.yaml` documents the block and still validates clean. Nothing reads
`Product.references` yet — the three readers are Tasks 2, 3 and 4, and this Task is the trunk all
three stand on.

**Read PD3 before writing `Product.references`.** `DEFAULT_MATRIX_PATH` is `None` and
`Conventions.matrix_path` is therefore always *present* and usually `None`; a presence test
synthesises a legacy reference for every product on this trunk and silently kills C7. Then **PD5**
(acceptance block 2 does not run `test_the_documented_example_validates` — its class is
`TestProductSchema`, and the Gate says so) and **PD1** (the Story id is the spec's, and it will not
link).

**Files**

- `asf/env.py` — `'references': _LIST` added to `PRODUCT_FIELDS` (`:515-522`, the last row beside
  `'credentials': _LIST`); the four new module constants `REFERENCE_SOURCES`, `REFERENCE_DECIDES`,
  `REFERENCE_EVIDENCE` and `REFERENCE_FIELDS` from the spec, with the spec's `#:` comment above
  them; `_reference_problems(references)` in the `_deploy_problems` (`:577-604`) /
  `_target_problems` (`:607`) shape — a function returning `[(dotted key, why)]` and nothing else;
  one call appended in `validate_product_text` beside `_deploy_problems` (`:673`) and
  `ci_pool.pool_problems` (`:676`); the frozen `Reference` dataclass from the spec; and
  `Product.references` / `Product.reference(ref_id=None)` as properties/methods beside
  `Product.conventions` (`:768`). `NESTED_FIELDS` (`:548-556`) is **not** touched — P3 is exactly
  why: it is keyed by section name and its checker iterates `mapping.items()`, so a list-of-maps
  section cannot ride it.
- `docs/products.example.yaml` — a new documented top-level `references:` block, and one added
  sentence to `conventions.matrix_path`'s comment (`:131`) saying it now reads as one `source: file`
  reference and that `references:` supersedes it. The Epic id in the block is a **comment
  placeholder**, never a literal `E-nnnn` — the file is a tracked file and P19's pattern is scanned
  over `asf/**/*.py`, but the same discipline is what keeps the example copy-pasteable rather than
  a record reference.
- `tests/test_env.py` — a new `class ReferenceFieldTests(unittest.TestCase)`, a plain `TestCase`
  subclassing **no** harness in the module (a subclass would re-run its host's suite under a second
  name). `TestProductSchema` (`:212`), `DocumentedModelsTests` (`:31`) and `ProductValidation`
  (`:288`) are not edited.

`sample/product.yaml` and `tests/e2e/product/product.yaml` are **not** edited and are not in
`writes:` — P5 is the reason, and `tests/test_sample_product.py:247` asserts in those words that the
sample declares no `matrix_path`. `tests/test_sample_product.py` and `tests/test_conventions.py`
are run by the Gate and written by nobody here.

**Steps**

1. `'references': _LIST` in `PRODUCT_FIELDS`. This alone turns P2's refusal into acceptance, and
   every later step is about what the shape check then says.
2. The four constants, from the spec verbatim. `REFERENCE_FIELDS` is `{'id', 'name', 'source',
   'epic', 'path', 'decide', 'evidence'}`, all `_STR` — the allow-list the unknown-key refusal reads.
3. `_reference_problems`, refusing the eight shapes the spec lists, each with its dotted key: a
   non-list `references:`; a non-map entry; a missing or empty `id`; a duplicate `id`; a key outside
   `REFERENCE_FIELDS`; a `source`/`decide`/`evidence` outside its tuple, worded `must be one of a |
   b, not <v>`; `source: stories` with no `epic`; `source: file` with no `path`; and the two
   would-silently-do-nothing keys, `path` on a `source: stories` entry and `epic` on a `source:
   file` entry, worded `is not read when source: <s>`. A `None` value is "not filled in yet" and is
   not a problem — the rule the rest of the table already follows. The dotted key is
   `references[<n>]` before an `id` is known and `references.<id>.<key>` after, which is what makes
   the message findable in a file with six references.
4. The call site in `validate_product_text`, appended in the same loop shape as `_deploy_problems`
   and `pool_problems`, so the line number reported is the section's line as those two report theirs.
5. The `Reference` dataclass, frozen, with the spec's field order and its three defaults.
6. `Product.references` — declared order, `source: stories` / `decide: ask` / `evidence: test` and
   `name` falling back to `id`, all applied **here** and not in the checker (the spec is explicit).
   Then C2's fallback: when the yaml declares no `references:` **and**
   `self.conventions.get('matrix_path')` is **truthy** (PD3), one
   `Reference(id='parity', name='parity', source='file', path=<matrix_path>, evidence='merge',
   decide='ask')`; otherwise `()`. `evidence='merge'` is the load-bearing default and the reason a
