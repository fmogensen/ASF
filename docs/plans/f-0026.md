# Plan F-0026 — the boundary holds, and footprint is not grant

Epic: E-0001 — ASF 0.1 — a working factory. Spec: `docs/specs/f-0026.md` (approved). Branch: `plan/F-0026`.

Six Tasks, cut by the module that changes, which is also the order the pieces can be proven in:
the leaf module and the convention it reads (Task 1), the record's side of `grant:` (Task 2),
harvest's screen and the hold (Task 3), the two places harvest must stop losing work (Task 4), the
groom's list and its one answer word (Task 5), the briefs that tell every session which of the two
fields binds it (Task 6).

Everything depends on Task 1 — `asf/boundary.py` is what the check, the screen, the groom's refusal
and the preamble all call — so wave 1 is Task 1 alone. Four Tasks then run together on four
disjoint file sets, and Task 4 follows Task 3 because both write `asf/harvest/harvest.py` and the
re-admission needs the screen it clears a correction from.

Wave order: **1 → 2 ‖ 3 ‖ 5 ‖ 6 → 4**.

The spec's §3.7 rule — the suite and the checks are the gate the branch lands behind — binds every
Task, so every Gate below runs `python3 tools/run_tests.py` and the three checks beside its own fence.

### Task 1: `asf/boundary.py` — the matcher, the grant resolver, the law, and `conventions.boundary`
stories: S-17800
writes: asf/boundary.py, tests/test_boundary.py, asf/conventions.py, tests/test_conventions.py, docs/products.example.yaml, asf/harvest/harvest.py
after: none

§2.2 and §2.3, plus §4's convention. One leaf module of pure functions over strings — `import re`
and `asf.conventions`, no git and no filesystem — and one typed field with one documented default.
Nothing calls it yet: the screen, the check, the groom and the preamble are Tasks 2–6. `covers` errs
toward False, which is the only safe direction when nothing is ever discarded (§1.4).

**Files**

- `asf/boundary.py` — **new**. `covers(glob, path)`, `outside(paths, grant)`, `within(inner, outer)`,
  `deliverable_of(conv, branch, item)` (moved, PD13), `grant_for(conv, branch, item, card)`,

  `outside_of(edge)` (PD5), `HOLD`/`WARN`/`OFF`, `MODES`, `mode(conv)`, `mode_warning(conv)` (PD7).
  The module docstring says what the two words mean and which of the two this module is about.
- `asf/conventions.py` — `DEFAULT_BOUNDARY = 'hold'` with the comment §4 fences, and
  `boundary: str = DEFAULT_BOUNDARY` on the dataclass beside `harvest_gate` (`:151`). `'hold'` is
  not path-shaped, so `forbidden_patterns()` (`:110`) generates nothing new for it (P12).
- `docs/products.example.yaml` — the `conventions:` block gains §4's four commented lines and the
  `boundary: hold` line, beside `area_depth`/`batch_max_globs` (`:46-49`).
- `asf/harvest/harvest.py` — `deliverable_of` (`:850-856`) deleted; `from asf import boundary` and
  `already_on_trunk` (`:870`) calling `boundary.deliverable_of`. Nothing else.
- `tests/test_boundary.py` — **new**: `CoversTests`, `OutsideTests`, `GrantForTests`, `WithinTests`,
  and `ModeTests` for §3.7's first sentence.
- `tests/test_conventions.py` — `boundary` in `DefaultsTests`' documented-defaults assertion, and a
  `FromMappingTests` case for `conventions: {boundary: warn}`.

**Steps**

1. `covers(glob, path)`: one cached regex per glob — `**` → `.*`, `*` → `[^/]*`, `?` → `[^/]`,
   `[...]` kept as a class, every other character escaped, anchored both ends; then the
   directory-prefix rule, a wildcard-free glob that is a prefix of `path` at a `/` boundary
   (`asf/harvest` and `asf/harvest/` both cover `asf/harvest/harvest.py`, `asf/x` covers nothing of
   `asf/xy.py`). `fnmatch` is not imported — P6 is why, and the docstring says so.
2. `outside(paths, grant)`: the members of `paths` no glob of `grant` covers, in `paths` order,
   deduplicated. `grant` empty or None is the caller's problem, not this function's — it returns
   every path, and `refusal` is what never asks with `None`.
3. `within(inner, outer)`: the first glob of `inner` that no glob of `outer` contains, or None. The
   conservative test is `covers(outer_glob, inner_glob)` over the inner glob's own text, so
   `asf/harvest/**` is inside `asf/**` and `asf/other.py` is not inside `asf/harvest/**`.
4. `deliverable_of` moved verbatim from harvest, and `already_on_trunk` re-pointed at it (PD13).
5. `grant_for(conv, branch, item, card)`, §2.3's four rules in order: the card's `grant:`; else, for
   a `spec` or `plan` branch, `[deliverable_of(...), conv.review_path(item.lower(), '*')]`; else the
   card's `writes:`; else **None**. The docstring states that `None` and `[]` are different answers
   and that no card can express `[]` today.
6. `refusal(conv, branch, item, card, touched)`: `None` when the grant is None or nothing is
   outside; else `Edge(BOUNDARY_KIND, text)` with `.outside` carrying the whole list. The text is
   §2.3's one line — at most five paths, then `(+N more)`, the grant named, then the sentence that
   nothing is reverted and the two ways out, with the item id in the `grant: <glob>` hint.
7. `mode`/`mode_warning` per PD7, and `MODES = ('hold', 'warn', 'off')`.
8. The convention field, its default comment, and the example yaml block.
9. `CoversTests` and `OutsideTests` per §3.1: an exact path; a directory with and without a trailing
   slash; a sibling sharing a prefix but not a segment; `asf/*.py` **not** covering `asf/a/b.py`
   (P6's leak, asserted closed); `**` crossing `/`; `?`; a character class; an empty glob list; a
   path with no directory at all; `outside` preserving order, deduplicating, and returning `[]` for
   a fully covered list.
10. `GrantForTests` and `WithinTests` per §3.2's first half: the card's grant; the footprint; the
    deliverable and the review glob for a `spec/` and a `plan/` branch with no card grant; `None` —
    not `[]` — for a card with neither, and `refusal` on that returning None; `within` accepting
    `asf/harvest/harvest.py` inside `asf/harvest/**` and rejecting `asf/other.py`.
11. `ModeTests`: the three values, `hold` as the default, an unknown value read as `hold` with
    `mode_warning` naming it (PD7).

### Task 4: nothing is discarded — extras are archived, and a widened grant lands the held branch
stories: S-17805, S-17807
writes: asf/harvest/harvest.py, tests/test_harvest.py
after: Task 3

§2.5 and §2.7 — the card's second acceptance line, and the hold that costs no second session. The
one path in this factory that discards content today (`land_already`'s `dropped with the branch`)
stops doing so, and a hold whose question the record has answered is cleared by harvest itself.

**Files**

- `asf/harvest/harvest.py` — `land_already` (`:878-890`): with `extras`, `archive_commit` +
  fast-forward push to `refs/heads/archive/<branch>` before the lane branch is deleted, and the
  line naming where the extras went; with no extras the path is byte-for-byte what it is today.
  The re-admission block in the first loop, immediately above the `is_eligible` screen (`:1282`,
  PD9), as §2.7 fences it.
- `tests/test_harvest.py` — `ProductHarvestTests` methods carrying `discard` in their names, and
  the re-admission case in the `f0026` set Task 3 started.

**Steps**

1. `land_already`: when `extras`, `sha = archive_commit(repo, branch, f'archive({item}): {branch} —
   its deliverable is on {trunk}; kept for …  [skip ci]')`; an empty sha or a refused push leaves
   the lane branch in place and prints one line — the branch is never deleted before its archive
   exists. Only then `mark_session`, the delete, and
   `landed {branch}: already on {trunk} at {tip}; not its deliverable — {files} kept on
   archive/{branch}`. `dry_run` prints and writes nothing, as it does today.
2. `land_already` needs the item id for the archive message; it is already computed at the call
   site (`:1272`) and is passed in rather than re-derived.
3. The re-admission: read `lifecycle.pending_correction(record, sessions_path(state_dir))`; when its
   `kind` is `boundary.BOUNDARY_KIND` and `boundary.refusal(...)` over the current diff is None,
   `mark_session(..., correction=None)` (P3), update the in-memory record so the `is_eligible` call
   below sees the cleared state, and print `re-admitted {branch}: its grant now covers the diff`.
   `rounds` is left as it stands — the round already spent is not refunded (§1.4). A dry run prints
   the line and writes nothing.
4. `-k discard` (§3.4): for a held branch, `git rev-parse origin/<branch>` and
   `git rev-list --count origin/main..origin/<branch>` are identical before and after the tick, and
   every file the session wrote is readable at that sha; a branch held at the boundary in three
   consecutive harvests still has all of its commits; `land_already` with extras pushes
   `archive/<branch>` whose tree contains the extra file, deletes the lane branch only after that
   push succeeds, keeps the lane branch when the archive push is refused, and prints the line naming
   where the extras went.
5. The re-admission case in the `f0026` set: the same held branch, with the card's `grant:` widened
   between two harvests, lands in the second with no new session, printing `re-admitted`, its
   correction cleared and its `rounds` unchanged.
