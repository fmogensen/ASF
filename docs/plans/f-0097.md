# Plan F-0097 — the status table learns to say what the factory is working on

Epic: E-0001 — ASF 0.1 — a working factory. Spec: `docs/specs/f-0097.md` (approved). Branch: `plan/F-0097`.

Five Tasks, cut along the spec's own §1.1 file list by what each piece serves: the two things both
cells need before either can render — `span` and `land_window_days` (Task 1); the counting module
itself, pure, with no caller yet (Task 2); the two cells and the two rows in the table (Task 3); the
tick's `WORK since` block (Task 4); and the failure paths that prove neither row nor the block can
cost its reader anything (Task 5).

The spec is small and its footprint is smaller: eight files, four of them tests. The cut is therefore
not about parallelism — three of the five queue on `tests/test_views.py` and two on
`asf/views/work.py` — it is about what can be *proven* on its own. Task 2 ships a module with no
caller and a test class that reads it directly, so the counts are asserted before a table's markdown
is in the way; Task 3 then asserts the rendered cell against the same fixture. Tasks 3 and 4 are the
one genuine fork: the cells and the tick block read the same functions and write disjoint files.

Wave order: **1 → 2 → 3 ‖ 4 → 5**.

§3.6's rule binds every Task: besides its own fence, each Gate runs `python3 tools/run_tests.py`,
`bash tools/check_generic.sh` and `bash tools/check_conventions.sh`. Nothing in this plan writes to
the record, to a card or to the state directory — §4 of the spec, kept.

### Task 2: `asf/views/work.py` — the counts, and the digest's two lines
stories: S-17300
writes: asf/views/work.py, tests/test_views.py
after: Task 1

§2.1: the one place that counts the work. Pure functions over `(items, runs, now)` and nothing else —
no git, no `gh`, no subprocess, no clock but the `now` they are given. No caller yet: the cells are
Task 3's and the tick block is Task 4's, and this Task's test class reads the functions directly, so
the counts are asserted before a markdown table is in the way.

**Files**

- `asf/views/work.py` — **new**: §2.1's module docstring verbatim; the constants (`DONE = rows.DONE_STATES`,
  `SEVERITIES`, `UNTYPED`, `SPEC_PLAN_STAGES`, `LANDED_STAGES`, and
  `DEFAULT_LAND_WINDOW_DAYS` taken from `asf.conventions` — PD4); the `Bugs` and `Features`
  dataclasses; the four predicates `is_open`, `severity`, `on_day`, `within`; `bugs`, `features`,
  `time_to_land`, `digest`.
- `tests/test_views.py` — `WorkCountsTests` (new, §3.1) and the fixture builder both it and Task 3's
  `StatusWorkRows` read (PD8, PD11): `work_fixture(now)` returning the index dict and the ledger
  lines, every `stage_since` and `started` relative to the `now` it is given.

**Steps**

1. Write the module docstring and the constants. `DONE` is `rows.DONE_STATES` (P7) — the import is
   `from asf.feeder import rows`, and `is_open` is spelled here because `work.py` must not depend on
   the feeder's row-planning machinery for a predicate this short.
2. `severity(bug)`: a `severity` in `SEVERITIES`, else `UNTYPED` (§1.4 — an untyped Bug is its own
   clause, never silently an S3).
3. `on_day(ts, now)`: `ix.parse_ts`, then `t.astimezone().date() == now.astimezone().date()` — the
   operator's local day (§1.4), and False for an absent or unparseable `ts`.
4. `within(ts, since, now)`: both sides through `ix.parse_ts`, half-open `since < t <= now`, False
   when `ts` does not parse (PD7).
5. `bugs(items, runs, now)`: one walk of `ix.of_type(items, 'bug')` for `total`, `open_by_sev`
   (every key present, zeros included), `fixed_today` (`not is_open` and `on_day(stage_since, now)`),
   and the oldest open S1/S2 by the earliest `parse_ts(stage_since)` with ties to the lower id.
   `oldest` is `(id, severity, seconds)` off the injected `now`, or `()` (PD6). `in_fix` is the
   sorted intersection of the Bug ids in the index with the `item` of every run `lifecycle.is_live`
   accepts (PD10), each id once; `in_fix_s1` is its S1 subset.
6. `features(items, runs, now, window_days)`: one walk of `ix.of_type(items, 'feature')` for `total`,
   `landed_today` (`stage in LANDED_STAGES` and `on_day(stage_since, now)`, sorted newest
   `stage_since` first), `building` (`stage == 'building'`), `spec_plan` (`stage in SPEC_PLAN_STAGES`),
   `decided_waiting` and `undecided` per PD9.
7. `first_started(items, runs)`: one pass over the ledger to `{item id: earliest started}`, folded up
   to the Feature by the run's own `feature` field and, failing that, by walking `parent` through the
   index until a `feature` is reached — so a Task's run counts for its Feature (§2.1).
8. `time_to_land(feature_id, items, first_started)`: §2.1's docstring, `(seconds, landed_at)` from the
   earliest session to the Feature's `stage_since`, or `None` when the ledger never saw it. A
   negative difference (a ledger run started after the recorded landing) is `None`, not a negative
   sample.
9. The median: over the Features whose `stage_since` is inside `window_days` of `now` and whose
   `time_to_land` is not None; even samples take the mean of the two middles (§1.4); `measured` is
   the sample size and `median_to_land` is `None` when it is 0.
10. `digest(items, runs, since, now)`: the two strings §2.1 shows, `filed` / `fixed` / `landed` over
    `within(stage_since, since, now)` and `started` over distinct Features with a run whose `started`
    is in the window. The newest landed id is named in parentheses; the two lines' labels are padded
    as §2.5's fence prints them (`bugs      ` / `features  `).
11. Write `WorkCountsTests` and the shared `work_fixture(now)` builder (PD8): four Bugs plus a
    `removed` one, seven Features, a ledger with two live runs on the S1 Bug, one ended run, and a
    Task's run under a landed Feature.
12. Run the Gate.

**Gate**

```bash

python3 tools/run_tests.py
bash tools/check_generic.sh
bash tools/check_conventions.sh
```

**Acceptance** (§3.1, §3.6 — the spec's fences)

```bash

```

Covers, over an index carrying four Bugs (S1 open, S2 open, S3 open, S2 Closed with `stage_since`
today) and five Features (one `card` decided, one `card` undecided, one `spec-review`, one
`building`, one `landed` today) plus a ledger with two live runs and one ended:

- `open_by_sev` is `{'S1': 1, 'S2': 1, 'S3': 1, 'S?': 0}` — the Closed S2 is not open, and a
  `removed` Bug in the raw index is not in `items` at all (P1);
- a Bug with no `severity` lands in `S?` and is not silently an S3;
- `fixed_today` counts the Closed Bug whose `stage_since` is today and not the one closed
  yesterday, with `now` injected — the boundary is the **local** midnight, asserted from both sides
  with a fixed `now` and a `stage_since` one minute either side of it;
- `in_fix` holds each Bug id once for a Bug with two live runs, excludes an ended run, and excludes
  a live run whose `item` is not a Bug in the index; `in_fix_s1` is the S1 subset;
- `oldest` is the open S1/S2 with the earliest `stage_since`, and ties break to the lower id;
- `features`: `building`, `spec_plan` (all six stage words, each asserted), `decided_waiting`
  (`stage == 'card'` and `decided is True`), `undecided` (`decided` absent **and** `decided: false`),
  and `landed_today` for a Feature at `landed` *and* one at `on-prod` today;
- `median_to_land`: three Features landed in the window with ledger runs 1d, 3d and 6d before their
  `stage_since` → `3d` and `measured == 3`; a fourth with no run is skipped and `measured` stays 3;
  an even sample takes the mean of the two middles; a Feature landed 9 days ago is outside the
  7-day window; a Task's run counts for its parent Feature; with no measurable Feature the median
  is `None`;
- every function is pure: called twice with the same arguments it returns the same thing, and it
  opens no subprocess (asserted by patching `subprocess.run` to raise).
