# Plan F-0177 — the reads the pass already made, then the reads it is about to make

Epic: E-0002 — ASF 0.2 — self-improvement. Spec: `docs/specs/f-0177.md` (approved). Branch:
`plan/F-0177`.

Three Tasks, in the order the spec forces — *the store, then what fills it, then what it says*:

1. **the pass-scoped read cache** — `READ_SUBCOMMANDS`, `read_cache()`/`drop_reads()`/`read_stats()`,
   `sh(cache=)`, `_gh` served from it, the three drop sites, the dozen `cache=True` marks in the
   lane, and the two windows. From here a read the pass already made costs no second process.
2. **the prefetch** — `PREFETCH_WIDTH`, `prefetch`, `Lane.prefetch_facts`, `Lane.prefetch_checks`.
   From here the reads go out eight at a time, *into* Task 1's store, and the sequential loop reads
   them back out of it.
3. **the line** — `reads_line`, printed once per pass, with its seconds only when the pass is not a
   rehearsal.

They run **1 → 2 → 3**, one at a time. The serialisation is not a convenience: all three write
`asf/harvest/harvest.py`, so no two may be in one wave, and the dependency is the same order —
Task 2's prefetch has nothing to fill without Task 1's store, and Task 3's line reports counters
both of the others keep.

**Read PD2, PD3 and PD4 before writing a line of any Task.** They are the three places this plan
departs from the spec's design, each for a measured reason:

- **PD2** — the `gh pr checks` calls the card measured are in `gate_pass`, not `lane_pass`. The
  spec calls `prefetch_checks` from `lane_pass`, whose window closes before any reader of them
  exists. Moved.
- **PD3** — `GitHubHost.recheck` exists to see a required check that went red *while the pass ran*.
  A cache around `gate_pass`'s whole body, which the spec's §3 asks for, makes it structurally
  incapable of that. The window in `gate_pass` ends before `gate_set`.
- **PD4** — `PassReadsTests` on three plain lane branches proves nothing: measured, such a pass
  spawns 23 reads and all 23 are distinct, so the spec's assertion (a) is green against unmodified
  code and its assertion (b) is false. It needs a fourth branch, an orphan the lane picks back up —
  the one place a `lane_pass` over `LaneFixture` reads the same fact twice.

The fences of §*The fences* bind every Task; every Gate below carries them beside its own.

## The fences

Every Task's Gate ends with these. No new module is added, so nothing newly enters them (P11);
they are run because each walks the whole of `asf/**/*.py` and the files every Task edits are
inside all three.

```bash
bash tools/check_conventions.sh
bash tools/check_generic.sh
python3 -m unittest tests.test_lifecycle -v
python3 -m asf.cli redact --unpublished
```

The product's full suite (`python3 tools/run_tests.py`) is the pull request's, run by the external
CI, and it is never skipped — only run off this host. Each Task's Gate runs the targeted modules
below in the foreground first.

### Task 1: a read the pass already made costs no second process, and anything that writes empties the cache
stories: S-36500
writes: asf/harvest/harvest.py, asf/harvest/lane.py, asf/gitpush.py, asf/ci_queue.py, tests/test_harvest.py, tests/test_lane.py

The spec's §*The design* §1 in full: `READ_SUBCOMMANDS`, `read_cache()`, `drop_reads()`,
`read_stats()`, `sh(cache=…)`, `_gh` served from and stored in the store, the drop at all three
`mutation_guard` chokepoints, the `cache=True` marks at the lane's per-branch readers, and the two
windows.

This is the half that pays first and the half everything else rests on. Nothing the factory
*decides* changes: a hit returns what the miss returned, and every write empties the store before it
runs.

Read **PD3** (the window in `gate_pass` ends before `gate_set`, and why), **PD4** (the fixture needs
a fourth branch or the test is green before you start), **PD5** (`:1482` is missing from the spec's
list), **PD6** (a module-level import here is a cycle), **PD7** (thread-shared store, lock off the
subprocess) and **PD14** (what a non-`git` argv does) before starting.

**Files**

- `asf/harvest/harvest.py` — beside `sh` (**:79**) and `_gh` (**:900**):
  - `READ_SUBCOMMANDS = frozenset({'rev-parse', 'rev-list', 'log', 'diff', 'merge-base',
    'for-each-ref', 'cat-file', 'show', 'cherry'})`, with the spec's docstring: the complement is
    listed, not the writes (D4); `merge-tree --write-tree` and `commit-tree` are deliberately
    absent though they move no ref; `ls-remote` is absent as the one read whose answer moves with
    no local write.
  - `read_cache()` — a `contextlib.contextmanager` over a module-global, thread-shared store
    `{(cwd, tuple(argv)): (returncode, stdout, stderr)}` and counters, under a `threading.Lock`
    (PD7). Nests on a depth counter the way `mutation_guard.active()` nests (:34): only the
    outermost exit closes it.
  - `drop_reads()` — empty the store, leave the window open.
  - `read_stats()` — `{'git': int, 'gh': int, 'hits': int, 'process_s': float}`; `process_s` is the
    sum of each child's own elapsed (PD11). Safe to call with no window open.
  - `sh(cmd, cwd=None, env=None, cache=False)` — the three branches of the spec's §1, in order:
    window open and `cache` and `env is None` → key `(cwd, tuple(cmd))`, a hit rebuilds a

### Task 2: the reads go out eight at a time, and the pass does not depend on it
