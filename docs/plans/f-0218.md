# Plan F-0218 — one call, one Task: every park released and what is left named

Epic: E-0001 — ASF 0.1 — a working factory. Spec: `docs/specs/f-0218.md` (approved). Branch:
`plan/F-0218`.

**One Task.** The spec has two Stories and they are not separately landable — not as a judgement
call, but by the spec's own acceptance: Story 1's fifth test,
`test_a_park_under_a_newer_plain_hold_is_released_and_the_hold_is_named`, asserts Story 2's output
(`released 1 park`, `1 correction still holds it`, `still held`). A Task carrying Story 1 alone
therefore ships a test that cannot pass, and — worse — puts on the trunk the exact defect this card
is about: a park released, exit 0, a success line, and an item still held with nothing saying so
(PD1).

The footprint is one module of 57 lines, one test class, and one clause of prose:

1. **`asf/workers/unpark.py`** — `parked_jobs` and `still_holding` replacing `parked_job`,
   `cmd_unpark` releasing every park it gathered, the `released N park(s)` line, the
   `still held` / `still parked` lines from one re-read, the module docstring's last sentence, and
   the parser's `help=`.
2. **`tests/test_cli.py`** — `UnparkTests`' harness extracted to a base class carrying **no test
   methods**, its seven tests kept byte for byte, and `UnparkReleasesEveryPark` with the spec's nine.
3. **`docs/guide/operating.md:210-212`** — one clause on the park bullet.

Wave order: **1**, alone, `after: none` — it starts at once.

**Read PD1 before arguing for a split, PD3 before writing
`test_still_holding_reads_the_file_again_after_the_appends`** (the spec names the test and not the
seam it needs), **and PD5 before touching `UnparkTests`** — the one way this Task can turn green
tests into a silently doubled suite.

### Task 1: one call releases every park the item holds, and names what still holds it
stories: S-36500, S-36501
writes: asf/workers/unpark.py, tests/test_cli.py, docs/guide/operating.md
after: none

The spec's `## The design` §1, §2 and §3 in full, and nothing else. After this lands, `asf unpark
<item>` returns only when no park on that item is holding it, and its last lines are the truth
about what is: a count, and one named line per correction the command was never allowed to touch.

Three things are load-bearing and each has a precondition behind it. The parks are gathered
**once, before the first append** (C6) and the loop iterates that fixed list — not a
recompute-after-each-release, which would make the count the operator is told a moving number.
Every appended line carries the **one** `now` and the **one** `--why` of this call (C5), because
that is what the lane's "launches since the item's latest unpark" guard reads as a single release.
And `left` comes from a **second read of the file** after the last append (P6), so the report names
what the next tick will see rather than what was predicted.

Read **PD5** before moving a single line of `UnparkTests`, **PD3** before writing the re-read test,
and **PD1** if the size of this Task looks like it should have been two.

**Files**

- `asf/workers/unpark.py` — `parked_job` (`:14-27`) is **replaced** by `parked_jobs` and
  `still_holding`, both exactly as §1 writes them, with their docstrings. `cmd_unpark` (`:30-47`)
  is rewritten exactly as §2 writes it. The module docstring's last sentence (`:5-6`) and
  `register()`'s `help=` (`:52`) change as §2 and §3 say. `lifecycle`, `pool as pool_mod`, `env`
  and `datetime` are already imported; no import is added or removed.
- `tests/test_cli.py` — `class UnparkTests(unittest.TestCase)` (`:163`) becomes `class
  UnparkHome(unittest.TestCase)` holding only the harness plus two new helpers, `class
  UnparkTests(UnparkHome)` holding only the seven existing tests unchanged, and `class
  UnparkReleasesEveryPark(UnparkHome)` holding the nine new ones. Inserted where `UnparkTests` is
  today, above `ReadmeParserTests` (`:276`). No other class in the file is touched.
- `docs/guide/operating.md` — the park bullet at `:210-212` gains §3's clause. No other line moves.

**Steps**

1. **`parked_jobs`** — §1 verbatim. Over `lifecycle.item_runs(path, item)` (C8: the reader
   `correction_of` uses, so the command and the row it clears see the item's runs the same way, and
   a reset item's closed runs drop out for free). Keep every park, one entry per job, newest `at`
   winning the dedupe; return `sorted(..., key=lambda jc: ((jc[1].get('at') or ''), jc[0]))` —
   **oldest first**, the job name breaking a tie so the output order is deterministic. The dedupe is
   belt and braces: P4 measured that only one park per job is ever pending, and this makes the
   function true whatever the ledger holds.
2. **`still_holding`** — §1 verbatim. Same walk, same sort, but **no `parked` filter**: it answers
   *every* correction still pending, which is the point (C2 leaves a plain hold standing, and the
   report is what makes that honest). It takes its own `lifecycle.item_runs` read; do not thread the
   gather's result into it and do not memoise between the two calls — the re-fold is the feature
   (P6, PD3).
3. **`cmd_unpark`** — §2 verbatim, in that order. The `known` gate stays on the **raw**
   `lifecycle.runs(path)` scan (C8): `item_runs` hides runs from before a reset, and an item whose
   only runs are those must keep saying `not parked` (code 1), not start saying `not in the ledger`
   — P8 pins both strings and both codes. Then `parks = parked_jobs(...)`, the `not parked` refusal
   when it is empty, one `now` and one `why`, the loop of `update_session(product, job,
   correction=None, unparked=now, unpark_why=why)` + today's `unparked …` print unchanged, then
   `left = still_holding(...)`, the `released N park(s) on <ITEM>` line with its
   `— N correction(s) still hold(s) it` tail, one `still held` / `still parked … run \`asf unpark
   <ITEM>\` again` line per remaining correction, `why: …` when `--why` was given, and `return 0`.
4. **The two one-liners** — `register()`'s `help='release every park an item is holding'` (§3).
   `asf/surface.py` and the README are **not touched** (C9): P9 measured that the parser's `help=` is
   the string `asf --help` prints, `surface.apply` has no caller, and the surface row reads
   'release an item the pool is holding', which stays true. Then the guide's park bullet gains §3's
   clause, as prose under the existing command line.
5. **The harness split** (PD5) — move `PARK`, `LAUNCH`, `setUp`, `tearDown`, `_ledger`, `_parked`,
   `_run`, `_read`, `_lines` onto `UnparkHome` **unchanged**, and add the spec's two helpers:
   `_park(at, reason, parked=True)` returning a correction dict, and `_run_row(job, kind, started,
   ended)` for a second run on the same item. Leave `UnparkTests`' seven bodies byte for byte — a
   diff that shows only the `class` line and the indentation of what moved is the diff to aim for.
   **Nothing named `test*` on the base.**
6. **`UnparkReleasesEveryPark`** — the spec's nine tests, one per row of its acceptance table.
   P2's two-park ledger is the fixture most of them share: two runs of `T-0017` (`started` 09:00 and
   09:05, both ended), each given a `parked` correction (`at` 10:00 and 10:05) — reproduced at this
   branch point, both pending together. For
   `test_still_holding_reads_the_file_again_after_the_appends`, build the seam PD3 specifies. For
   `test_parked_jobs_is_oldest_first_and_one_entry_per_job`, the second half needs P4's ledger: two
   generations of one job, the second `started` 11:00 after the first park's `at` 09:31, so only the
   11:31 park reads pending and `parked_jobs` returns exactly one entry.
7. Run the Gate. The arithmetic is part of it: `UnparkTests` alone still `Ran 7 tests`, the two
   classes together `Ran 16 tests`.

**Not in this Task** — the spec's `## Out`, each for its own reason: health's park lift and
everything else that writes a park (P10); the two refusals' strings, exit code 1, and the `known`

feeder does not hold the row on (P11); clearing a pending correction that is not a park (C2);
