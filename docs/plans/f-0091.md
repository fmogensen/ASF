# Plan F-0091 — `asf improve`, a weekly tick step

Epic: E-0001 — ASF 0.1 — a working factory. Spec: `docs/specs/f-0091.md` (approved). Branch: `plan/F-0091`.

Four Tasks, cut by module. Task 1 is the arithmetic (`asf/improve/measure.py`,
`asf/improve/classes.py`) and the fixtures every later Task reads. Task 2 is the command, the
proposals and the approval class. Task 3 is the weekly tick step. Task 4 is the scorecard's first
row. Tasks 2 and 4 both need only Task 1, write disjoint files, and run together; Task 3 needs
Task 2's `cmd_improve` and runs last.

Wave order: **1 → (2, 4) → 3**.

### Task 1: the arithmetic — every run, its spend, the table and the four classes
stories: S-14250, S-14251, S-14252, S-14253
writes: asf/improve/__init__.py, asf/improve/measure.py, asf/improve/classes.py, asf/env.py, tests/test_improve.py, tests/fixtures/improve/**, tests/test_env.py

The two pure modules of §2.1 and §2.2: they take a ledger path and a directory of job logs and
return numbers. No clock, no record, no card. The fixtures every later Task reads are cut here,
including the frozen 216-run copy of the registry that makes acceptance #4 a test.

**Files**

- `asf/improve/__init__.py` — new, one docstring line. `[tool.setuptools.packages.find]` already
  includes `asf.*`, so the package needs no pyproject change.
- `asf/improve/measure.py` — new. `Run`, `ended_runs`, `job_spend`, `table` (§2.1).
- `asf/improve/classes.py` — new. The four classes, their default thresholds, `excess_usd`, the
  sentence each carries, and the product override read (§2.2).
- `asf/env.py` — `PRODUCT_FIELDS` gains `'improve': _MAP`; `IMPROVE_FIELDS` and its
  `NESTED_FIELDS` entry beside `CI_FIELDS` / `CAPACITY_FIELDS` (`asf/env.py:222-237`, P8).
- `tests/test_improve.py` — new: `RunsTests`, `SpendTests`, `TableTests`, `ClassTests`.
- `tests/fixtures/improve/` — new: a hand-written registry and two job logs for the unit tests,
  `asf-2026-09-23.jsonl` (the frozen cut), and `regenerate.py` (§3.4's generator, verbatim).
- `tests/test_env.py` — one case: a product file with a well-formed `improve:` block validates, and
  one with an unknown key under it is reported as `improve.<key>`.

**Steps**

1. `measure.Run` exactly as §2.1 fences it: `job, kind, model, item, started, ended, minutes,
   landed, end_reason, usd`, frozen.
2. `measure.ended_runs(product, *, ledger=None, logs_dir=None, since=None, as_of=None)`. The spine
   is `lifecycle.runs(ledger or pool.sessions_path(product))` — every run of every job, flattened,
   never `lifecycle.latest` (P1 of the spec: folding `latest` gives 197 ended, not 216). A run
   counts when it carries `ended`; `since` keeps `ended[:10] >= since`, `as_of` keeps
   `ended <= as_of`. `minutes = max(0, (ended - started) / 60)` to 1 dp, an unparseable pair is 0.
   `landed = bool(run.get('harvested'))`.
3. `measure.job_spend(job, logs_dir)`: read the log's `type: result` lines, group by `session_id`
   (a line with none forms the group `'none'`), take each group's **max** `total_cost_usd`, sum the
   groups. No log, or no line carrying the field → `None`. This is deliberately *not*
   `metrics._result_line`'s last-line read (§1.2) and does not touch it.
4. `usd` on a `Run` is the job's spend split over that job's ended runs pro rata by `minutes`;
   `None` when the job has no log. A job whose ended runs sum to 0 minutes splits evenly.
5. `measure.table(runs)` returns the flat dict of §2.1's key table: `sessions`, `hours`, `usd`,
   `landed_sessions`, `landed_items`, `non_landing_share`, `by_kind`, `by_model`, `by_kind_model`,
   `repeat_items`, `minutes_per_landed_item`, `usd_per_landed_item`. `record_usd` is the same
   window as the record's `cost:` blocks hold it, carried beside `usd` as §1.2's footnote; it is
   `None` when no record was given. `table` opens no file and reads no clock.
6. `classes.py`: `CLASSES` as `(name, threshold, measure_fn, sentence_fn)` with the four defaults
   `repeat_sessions` 0.33, `time_per_landed_item` 120, `premium_model_in_kind` 8.0,
   `non_landing_sessions` 0.25, and `DEFAULT_PREMIUM_MODELS = ('claude-opus-5',)`.
   `evaluate(table, conv_improve)` returns one record per class — name, measured, threshold, over,
   `excess_usd`, sentence — every class, over threshold or not, so the page can print the distance
   of the ones that are not. Order by `excess_usd` descending; `rank` is position × 10.
7. The product override: `improve: {thresholds: {...}, epic: ..., window_days: ..., premium_models:
   [...]}` read off the `Product`, each key falling back to the default in this module. The
   `env.py` field declarations of P8 land with it.
8. Generate `tests/fixtures/improve/asf-2026-09-23.jsonl` with §3.4's snippet, committed as
   `regenerate.py`; confirm the run count it prints is 216 and that `bash tools/check_generic.sh`
   is clean over the tracked fixture (P14).
9. Tests, with the repo's existing `tests/` idiom (temp dirs, no network, no `~/.ASF`).

### Task 4: the scorecard's first line carries the two numbers this exists to move
stories: S-14257
writes: asf/metrics/metrics.py, tests/test_metrics.py

§2.6, and the smallest Task here: one new row, one new argument on each of three functions. Needs
only Task 1's `measure.table`, writes nothing any other Task writes, and runs beside Task 2.

**Files**

- `asf/metrics/metrics.py` — `scorecard_rows` gains `landing=None` (`asf/metrics/metrics.py:405`);
  `render_daily` gains `product=None` and computes it (`:501-515`); `cmd_rollup` passes the product
  it already resolved (`:835-848`).
- `tests/test_metrics.py` — the two forms of the row.

**Steps**

1. `scorecard_rows(ci, sessions, ticks, conv=None, landing=None)`: when `landing` is not `None`,

   `| landing | 35 % of session time landed nothing | $3.60 per landed item (86 landed, 7 days) |`,

2. `render_daily(root, day, items, conv=None, product=None)`: with a product, compute `landing`
