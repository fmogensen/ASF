# Plan F-0092 — an item has a budget, and a run has a cap

Epic: E-0001 — ASF 0.1 — a working factory. Spec: `docs/specs/f-0092.md` (approved). Branch: `plan/F-0092`.

Seven Tasks, cut by the module that changes, following the spec's own §2 sections. Task 1 is the
config and the one leaf module every other Task imports — `conventions.budget` and `asf/budget.py`,
both verdicts, pure. Task 2 is the card: the rollup writing the budget and the verdict into the
`cost:` block, and the one `capped` cell that counts either cap. Task 3 is the gate the Feature
exists for — `feeder.rows.over_budget`, the wave's line, and I15 behind it. Task 4 is the run caps:
the meter's turn counter, `stall.capped` judging the two run measures, and the two new outcome
classes. Task 5 wires the caps to the only thing that can enforce them — `step_health` calling
`capped()`, the first caller in the package. Task 6 is the ruling: the groom's question and the
`budget <n> [$<usd>]` answer. Task 7 is the view.

Tasks 1 and 7 need nothing landed and start at once. Tasks 2, 3, 4 and 6 each need only Task 1's
`asf/budget.py`, write disjoint production files, and run together. Task 5 needs Task 4's
`stall.capped` before it can assert the end reason it records.

Two pairs share a test module and therefore queue — Task 1 and Task 4 on `tests/test_budget.py`,
Task 3 and Task 5 on `tests/test_tick_steps.py` — and in both pairs the queue is the dependency
order the plan already states, so it costs nothing (P4, P5).

Wave order: **(1 ∥ 7) → (2 ∥ 3 ∥ 4 ∥ 6) → 5**.

### Task 1: the config and the leaf — `conventions.budget` and `asf/budget.py`
stories: S-29050, S-29051
writes: asf/conventions.py, asf/budget.py, tests/test_conventions.py, tests/test_budget.py
after: none

The two pure pieces of §2.1 and §2.2: the four numbers in one place, and the one module that
owns both verdicts — what an item may spend against what its card says it has spent, and what one
run may take against what it has taken. No clock it is not handed, no io, no git. Every later
Task imports this one and adds no copy of a default.

**Files**

- `asf/conventions.py` — `DEFAULT_BUDGET`, the `Conventions.budget` field, `'budget'` in
  `MAP_CONVENTIONS`, `budget_for(conv, key)` beside `savings_for` (`asf/conventions.py:792`), and
  the `conventions:` block in the module docstring's example.
- `asf/budget.py` — new. The module docstring §2.2 fences, the four constants, `Budget`, `Spent`,
  `of`, `spent`, `line`, `run_caps`, `run_over`, `run_cap_text`, `run_cap_result`.
- `tests/test_conventions.py` — `BudgetConventionTests` (T1), including the one-place grep (P8).
- `tests/test_budget.py` — new: `ItemBudgetTests` (T2) and `RunCapTests`' pure half (T7's first
  five sentences). Task 4 extends the same class with the wired half (P4).

**Steps**

1. `DEFAULT_BUDGET = {'sessions': 3, 'usd': 10, 'run_minutes': 180, 'run_turns': 600}` with §2.1's
   comment verbatim, beside `DEFAULT_SAVINGS`; `budget: dict = field(default_factory=lambda:
   dict(DEFAULT_BUDGET))` on `Conventions`; `'budget'` appended to `MAP_CONVENTIONS` so a
   misshapen block is a red doctor row and never a silent default (P7).
2. `budget_for(conv, key)` — one line, `savings_for`'s body: the product's own entry when it named
   one, else `DEFAULT_BUDGET`'s. Every other module in this plan reads the four numbers through it
   and holds no copy.
3. The module docstring's `conventions:` example gains §2.1's yaml block, comments included.
4. `asf/budget.py`: the docstring §2.2 fences, then `SESSIONS, USD, MINUTES, TURNS`, `OFF`,
   `RUN_CAP`, `OVER`.
5. `Budget` and `Spent` as fenced — frozen dataclasses, `Spent.over` the `bool(self.measure)`
   property. `source` is whichever of `default` / `product` / `item` set the **lowest** measure,
   for the groom line to name.
6. `of(conv, item)`: `budget_for` for each of `sessions` and `usd`, then the card's own
   `budget_sessions:` / `budget_usd:` over it, each independently; `off` on either is `None` (no
   limit). An item whose `type` is `epic` gets a bare `Budget()` whatever its `budget_usd` — that
   number is the subtree figure the rollup reports (F-0101), not a stop.
7. `spent(conv, item)`: `cost.sessions` and `cost.usd` off the item's machine block against
   `of()`. `sessions` is judged before `usd`, and `>=` is over — the third session is the last one
   the budget buys. A `None` on either side of a comparison is never over: no `cost:` block is
   nothing spent, and `cost.usd: None` (no log carried a cost) is an unmeasured dollar, not a
   spent one.
8. `line(item_id, s)` — `OVER BUDGET T-0021 — 9/3 sessions, $13.53/$10`, both measures always,
   `—` in place of a cap that is off. One format, no branch (§1.4).
9. `run_caps(conv)` → `(minutes, turns)`, each an int or `None` for `off`. `run_over(elapsed_min,
   turns, caps)` → `(measure, value, limit)` for the first cap exceeded, the wall clock before the
   turns, else `None`; a `None` on either side of a comparison is never over, so a run whose
   `started` the ledger lost is judged on its turns alone.
10. `run_cap_text` and `run_cap_result` exactly as §2.2 fences them — no `duration_ms`, no
    `total_cost_usd`: nothing was measured.
11. `tests/test_conventions.BudgetConventionTests`: the four defaults; `from_mapping({'budget':
    {'sessions': 5, 'run_minutes': 'off'}})` overriding two and keeping two; `budget_for` on a key
    the product did not name; a string `budget:` named by `shape_findings()`, raising nothing, and
    `budget_for` still reading the defaults (P7); `'budget' in MAP_CONVENTIONS`; and the grep case
    of P8 — the four literals appear under `asf/` only in `asf/conventions.py`.
12. `tests/test_budget.ItemBudgetTests`: §3's T2 sentence by sentence — the three-level resolution,
    the Epic, the two over-measures, `>=` at exactly 3, the unmeasured dollar, the missing `cost:`
    block, `sessions: off`, and the two line formats.
13. `tests/test_budget.RunCapTests`, pure half: 214 over 180; 180 exactly not over; 601 over 600;
    the wall clock named first when both are over; a `None` elapsed judged on turns; `off` on both
    never over; the two texts and the `asf.run_cap` object's shape.

spent becomes one non-launching `OVER BUDGET` row, inside `candidates()` so that `asf next`, the

budget is spent" a checked property of the plan rather than of one function.

**Files**

- `asf/feeder/rows.py` — `OVER_BUDGET`, `BUDGET`, `FINISHING_KINDS`, `over_budget(rows, items,
  product)` (§2.4), and its call in `candidates()` after `hold_classes` (`:968`).
- `asf/invariants.py` — `FeederContext.items` (`:363-368`), `feeder_context` passing it (`:718`),
  `check_i15`, and the `Invariant('I15', 'feeder', _feeder_only(check_i15))` registration
  (`:609-611`); the module docstring's `feeder` list becomes `(I4, I5, I7, I15)`.
- `asf/tick/step_wave.py` — the non-launching branch of `launch()` (`:666-668`).
- `tests/test_feeder.py` — `NoWorkRowLaunchesForASpentBudget` (T4).
- `tests/test_invariants.py` — `I15Tests` (T5, second half).
- `tests/test_tick_steps.py` — `OverBudgetWaveTests` (T5, first half).

**Steps**

1. `FINISHING_KINDS = (PUSHED_REVIEW, CONFLICT, STALE)` with §2.4's comment: each ends the
   spending on work already done. A review of a branch already pushed is the last step before it
   lands; a rebase and a close are housekeeping on a branch that exists.
2. `over_budget(rows, items, product)` as §2.4 fences it, with one addition the fence omits and its
   own paragraph requires: `GROOM_ADJUDICATE` is exempt beside `FINISHING_KINDS`, the same

   passed through untouched — `PUSHED → LAND`, `ON TRUNK`, `APPROVED → LAND`, `WAITS ON …` say
   what the lane is doing and must not be overwritten by this one.
3. One line per item, not per row: the first launching row in emit order becomes the
   `OVER BUDGET` row (`waits_on='budget'`, the reason naming the three answers), every later
   launching row of that item is dropped.
4. The verdicts are memoised per item id inside the call: `budget.spent` is pure over the item's
   `cost:` block, and an item with a correction row, a PLAN → CODE row and a bug row is judged

5. `candidates()` gains `rows = over_budget(rows, items, product)` as the last hold, after
   `hold_classes` (`:968`) — anywhere later and the four callers that use `candidates()` directly

6. `step_wave.launch()`: the `if not row.launches` branch prints `row.action` whole when

   `ctx.product`, through the same `_conventions` the rows use.
9. Registered as `Invariant('I15', 'feeder', _feeder_only(check_i15))`; the docstring's `feeder`
   list updated. Both `feeder_waits` and `feeder_gate` then run it, which is right (P11).

    and `STALE → CLOSE` still launching; `PUSHED → LAND` / `ON TRUNK` passed through unchanged; a

11. `tests/test_tick_steps.OverBudgetWaveTests`: `asf tick --steps record,wave` over a fixture
