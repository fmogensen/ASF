# B-0088 — plan: `asf backlog` collapses to what still needs a look

Item: B-0088 — `asf backlog` is 339 lines / 67 KB: the console truncates the board. Epic:
E-0002 — ASF 0.2 — self-improvement. Branch: `fix/B-0088`. No spec exists; the Acceptance below
is the record.

## Cause

`asf.views.board.render` grew one full table row per Feature with no cap and no bucketing, so on
a mature record the board was 339 lines / 67 KB. Every console that caps its own output — the
operator's terminal, an agent's tool result — cuts that off partway, and what it cuts is
arbitrary: the Feature anyone is actually looking for may sit below the cut, so the view silently
answers the wrong question. Most of those rows are also inert: a Feature that shipped, was closed,
or has not been decided by groom yet carries nothing to act on, and a count is all an operator
needs about it. Nothing in the view distinguished those from the Features in flight.

## Task 1 — the board's default collapses, `--all` opts out, `--epic` narrows

writes: `asf/views/board.py` `asf/cli.py` `tests/test_views.py`

- Step 1: in `asf/views/board.py`, add `feature_status(f)` — one Feature's bucket, read from the
  index alone: `'done'` when `state: Closed` or stage `on-prod` (shipped or dead, nothing to act
  on), else `'undecided'` when groom has not set `decided: true` on it
  (`asf.groom.policy._undecided`'s rule, read again here since this module stays index-only),
  else `'moving'` (decided, still in the pipeline — `landed` included, the stage right before
  `on-prod`). `'done'` is tested **first**, independent of `decided`: a Feature that shipped or
  was closed before groom ever marked it needs no look either, and reading it as `'undecided'`
  would put it in the one summary line an operator does still scan.
- Step 2: in `render()`, default (`show_all=False`) to full rows for the `'moving'` Features
  only, grouped per Epic as before, with the `'undecided'` and `'done'` Features folded into one
  summary line each — the label, the count, and `` (`--all` to list) `` as the way out.
- Step 3: `render(..., show_all=True)` is the opt-out: every Feature gets a full row and no
  summary line is emitted — the board exactly as it was before this default.
- Step 4: `render(..., epic=<id>)` (case-insensitive) narrows the output to that one Epic's
  group, on top of whatever `show_all` already chose — it never widens it, and the collapsed
  summary counts narrow with it.
- Step 5: in `asf/cli.py`, add `--epic` and `--all` to the `backlog` parser and pass both through
  `cmd_backlog` into `render()`.
- Step 6: tests, in `tests/test_views.py`:
  - `RetirementRuleTests.test_epic_filter_keeps_only_that_epics_group` — `--epic` keeps that
    Epic's rows and drops every other Epic's, while the header still counts the whole backlog.
  - `BoardCollapsingTests.test_the_default_collapses_done_and_undecided_to_one_line_each` — the
    `'moving'` Features get rows; the on-prod, Closed and undecided ones do not, and each bucket
    is one summary line carrying its count.
  - `BoardCollapsingTests.test_all_opts_out_of_the_collapsing` — with `--all` every Feature is
    present and neither summary line is.
  - `BoardCollapsingTests.test_epic_narrows_the_collapsed_summaries_too` — `--epic` narrows the
    summary counts too, not just the rows.
  - `BoardCollapsingTests.test_closed_counts_as_done_even_when_groom_never_decided_it` — a
    Closed Feature with `decided: false`, and an `on-prod` one with no `decided` key at all,
    both bucket as `'done'` and count under `Closed / on-prod`, not under `Undecided`.

## Out of scope

The summary counts are computed once over the whole (possibly `--epic`-narrowed) scope, so with
no `--epic` given they read as one backlog-wide line per bucket rather than one per Epic group.
That is the intended shape here — the line exists to say "N more, ask for them" — and a per-Epic
breakdown is not part of this fix.

`asf board`'s other callers and the remaining long views (`asf status`, the daily rollup) are
untouched: this card names the Feature board, and its default is the whole fix.

## Acceptance

- [x] The default `asf backlog` prints full rows only for Features `feature_status` calls
      `'moving'`, with one summary line each for the `'undecided'` and `'done'` buckets
      (`tests/test_views.py::BoardCollapsingTests::test_the_default_collapses_done_and_undecided_to_one_line_each`).
- [x] `--all` restores every Feature's row and emits no summary line
      (`tests/test_views.py::BoardCollapsingTests::test_all_opts_out_of_the_collapsing`).
- [x] `--epic <id>` narrows to that one Epic's group — its rows and its summary counts — and
      never widens what `--all` chose
      (`tests/test_views.py::BoardCollapsingTests::test_epic_narrows_the_collapsed_summaries_too`,
      `tests/test_views.py::RetirementRuleTests::test_epic_filter_keeps_only_that_epics_group`).
- [x] A Feature that shipped or was closed without groom ever deciding it counts as `'done'`,
      not `'undecided'` — three Features on the live record (`F-0009`, `F-0011`, `F-0012`:
      `Closed`, stage `landed`, `decided: false`) are exactly that shape
      (`tests/test_views.py::BoardCollapsingTests::test_closed_counts_as_done_even_when_groom_never_decided_it`).

## Accepted costs

`feature_status` restates groom's `decided` rule rather than calling
`asf.groom.policy._undecided`, because this module stays index-only; the two can drift, and that
is noted here rather than fixed by a dependency from a view onto groom.
