Epic: E-0001 — ASF 0.1 — a working factory. Spec: `docs/specs/f-0303.md` (approved). Branch:
`plan/F-0303`.

**One Task.** The spec's whole change is eight lines of `asf/upgrade.py` — one module constant,

**Steps**

1. Add the constant next to `HEX40`, which is the other thing this module knows about the shape of
   a resolved commit, with the spec's own comment:

   ```python
   #: The suffix ``git ls-remote`` puts on the extra line that names the commit an annotated tag
   #: points at. An unfiltered listing prints that line unasked; a listing given ref patterns
   #: prints it only for a pattern that matches it, so it is asked for by name (F-0303).
   PEEL = '^{}'
   ```

2. `resolve_ref` asks for both patterns and scans with the same constant. Three lines move — the
   docstring's command, the new `patterns` line, and the literal at `deref`; the
   `deref or lines[0]` preference and the `None` on no match are as they were, and now reachable:

   ```python
   def resolve_ref(url, ref, run=subprocess.run):
       """``ref`` as a commit, for the CI guard, ``write_pending`` and the marker (PD12): unchanged
       when it already is a 40-hex sha, else the commit ``git ls-remote <url> <ref> <ref>^{}`` names
       — the dereferenced commit on the ``^{}`` line for an annotated tag, else the line's own sha.
       ``None`` when ``ref`` matches nothing on ``url``. The peel is asked for by name: a filtered
       ``ls-remote`` prints it only for a pattern that matches it (F-0303)."""
       if not ref or HEX40.match(ref):
           return ref
       patterns = [ref] if ref.endswith(PEEL) else [ref, f'{ref}{PEEL}']
       text = _out(run, ['git', 'ls-remote', url, *patterns])
       lines = [ln for ln in (text or '').splitlines() if ln.strip()]
       deref = next((ln for ln in lines if ln.endswith(PEEL)), None)
       line = deref or (lines[0] if lines else '')
       return line.split('\t')[0].strip() or None
   ```

   The `endswith` guard is load-bearing and is its own acceptance line: `<ref>^{}^{}` matches
   nothing, so appending unconditionally would make a caller that passed an already-peeled ref
   resolve to the unpeeled line — the defect, inverted.

## What this plan leaves unbuilt, and why

Everything in the spec's `## Out`, and nothing else. `resolve_target` keeps its order — a branch
name resolved against a checkout behind origin is a real hazard and a judgement about which answer
wins, not a wrong answer to a right question, and `--to <tag>` is immune. A bare 40-hex `--to`
that names a tag object still 422s, now with the sha and `HTTP 422` in the line, which is the
remedy S-81157 ships; peeling it would cost a network round trip on the one form `HEX40` exists to
keep free, for a spelling nobody has used. `ci_verdict` still returns before the `/status` fallback
on an unreadable read, and `ci_state` still reads "no runs at all" as `clear` — with the sha
correct there is nothing to recover from, and making either stricter would defer every install at
a head CI has not started on. `asf/cli.py:166` and `asf/install.py:newest_tag` read tag names and
discard the shas, so neither is in the footprint.

The two reds `tests.test_install` carries on this host are not fixed here and are not this card's
(PD4). They are also not the two the spec predicted, which is why step 10 of the Task is to
measure the baseline rather than to trust a list — and why the operator line below asks whether
the pre-push gate can be passed at all while they stand.

No record, schema, config key, event or migration is involved: the spec's `## Records` table is
three existing fields whose **value** changes and one line of operator-facing output, and no
record holds a tag-object sha today, because every run that would have written one refused or
failed first.
