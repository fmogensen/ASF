# Plan F-0040 — the claim, the refusal, and the tick

Epic: E-0001 — ASF 0.1 — a working factory. Spec: `docs/specs/f-0040.md` (approved). Branch: `plan/F-0040`.

Seven Tasks, one per Story, because the spec's §2 is already cut that way: each section is one
module, each Story names one test module, and no two of them write the same file. Task 1 is
`asf/proves.py` — the grammar, the parser, the validator, the bullet reader and the tick. It is
what the other six import, so it is wave 1 alone. Task 2 is the brief that asks for the claim.
Task 3 is the refusal that will not land a Task without one. Task 4 is the pull-request body.
Task 5 is the evidence. Task 6 is the tick on the Story card. Task 7 is the rule's check and its
shipped script.

Tasks 2, 4 and 5 need only Task 1's module and write three disjoint trees; they are wave 2. Task 3
waits on Task 2 as well — the spec's §1.3 says so in as many words: *"The brief change (S-18751)
and the refusal (S-18752) must land in that order"*, because a refusal that lands before the brief
asks for the trailer refuses every in-flight coder for a requirement it was never told. Task 6 and
Task 7 both read `ev['proves']` and wait on Task 5: an ingest pass over a key nobody fills ticks
nothing, and a rule check that cannot see a landed claim reports every landed Task as a violation.

Wave order: **1 → (2, 4, 5) → (3, 6, 7)**.

| P3 | **`CLAIM_RE` as the spec writes it cannot parse the spec's own example** | §2.1 fences `(?P<story>[A-Za-z]+-\d{4})` and §2.2's example claim is `Proves: S-18750 line 1 — …`. Verified: `re.findall` with that pattern over that line returns `[]` — `\d{4}` is *exactly* four digits, and `\b`-free as it is, `S-1875` cannot be followed by the required `[ \t]+`. Task 1 writes `\d{4,}`, and §2.1's comment *"any prefix, four digits"* becomes *"any prefix, four digits or more"*. | P4 | **`plan_tasks.STORY_ID_RE` will drop every `stories:` line below** | `re.compile(r'\bS-\d{4}\b')` (`asf/record/plan_tasks.py:25`) has the same five-digit blindness as P3 — verified: `re.findall(r'\bS-\d{4}\b', 'S-18750')` is `[]`. That in turn silences the refusal of Task 3 for those very cards (§2.5 skips a Task whose card lists no Story, D5). It is a defect in the record's own plumbing, not in this spec, and it is not in F-0040's In list: this plan names it, writes its `stories:` lines correctly so they work the moment the regex is widened, and files it as a `NEEDS OPERATOR` line at the foot. |
| P5 | **The Story cards may not exist yet** | `docs/specs/f-0040.md`'s frontmatter names `stories: [S-18750 … S-18756]` and its `## Stories` block carries seven bare `- S:` bullets, but this session was handed *"The Stories: (none yet)"* — the record holds no Story card for this Feature. | P7 | **What `bullets()` counts, and the two regexes §2.1 calls "the same"** | §2.1's docstring says `bullets()` reads *"the same bullet shape `asf.record.check.ACCEPTANCE_ITEM_RE` requires of a Story, and the same one `asf.tick.step_prs.acceptance` reads"* — those two are not the same shape. `check.ACCEPTANCE_ITEM_RE` is `(?m)^- \[[ x]\]\s+\S`: a checkbox, at column 0, lowercase `x`. `step_prs.ACCEPT_RE` is `^\s*[-*]\s*(?:\[[ xX]\]\s*)?(.+?)\s*$`: any bullet, checkbox optional. `bullets()` follows the first: it counts `- [ ]`, `- [x]` and `- [X]` bullets only, with leading whitespace tolerated, so that **every number the grammar can carry names a bullet the tick can flip**. | P9 | **`lane_refusal` has no `conv` argument today** | §2.5 grows the signature to `lane_refusal(repo, trunk, branch, item, conv=None, items=None, root=None)` and says the one call site *"already has in hand"* what it passes. ### Task 1: the claim and its parser — `asf/proves.py`
stories: S-18750
writes: asf/proves.py, tests/test_proves.py
after: none

§2.1 whole, and the grammar of §2.2. One new top-level module and its test module — pure functions
over text, with `git` injected as a callable where a branch must be read (D11). Every later Task
imports it, so it lands alone and first. It touches nothing that exists: two new files, no
caller wired yet, and the suite is green the moment the module parses.

**Files**

- `asf/proves.py` — new. `CLAIM_RE`, `Claim`, `parse`, `bullets`, `card_bullets`, `validate`,
  `claims_on_branch`, `tick`, `render`, with §2.1's docstrings copied and a module docstring
  naming F-0040 and the four callers to come.
- `tests/test_proves.py` — new. `ParseTests`, `BulletsTests`, `ValidateTests`, `TickTests`,
  `BranchTests`, covering every case §3.1 lists.

**Steps**

1. `CLAIM_RE` as §2.1 fences it, with `\d{4,}` in place of `\d{4}` and its comment reading *"any
   prefix, four digits or more"* — **P3**, and the one correction this plan makes to the spec. The
   rest of the pattern is byte for byte: the `^[ \t>*-]*` lead that lets a claim be found under a
   `## Proves` bullet or a quoted body, `re.M | re.I`, and the three dashes of D12 with surrounding
   space optional.
2. `Claim`, a frozen dataclass: `story` upper-cased, `line` an `int`, `test` as written, `raw` the
   line as found for the refusal text.
3. `parse(text)` — every claim in first-seen order, duplicates collapsed on `(story, line, test)`.
   A line that says `Proves` but names no id, no number or no test yields nothing and raises
   nothing.
4. `bullets(body)` — the `## Acceptance` bullets of a card body, in order, counting checkbox
   bullets only (**P7**): `- [ ]`, `- [x]`, `- [X]`, leading whitespace tolerated, the checkbox
   stripped from the returned text. A section between two acceptance sections is not counted, and a
   body with no `## Acceptance` heading yields `[]`.
5. `card_bullets(root, item)` — `bullets` of `root/<folder>/<id>.md`, the `folder`/`id` pair
   `step_prs.card_relpath` uses (`asf/tick/step_prs.py:125-126`); `[]` for an unreadable or absent
   path, never an exception.
6. `validate(claims, task, items, root, tree=None)` → `(good, problems)`, the five problem kinds of
   §2.1 in the order found, each a one-line string naming `claim.raw` and what is wrong: `no
   claim`, `unknown story` (not in `items`, or its `type` is not `story`), `not this Task's`, `no
   such line`, `no such test` (only when `tree` is given; the path before `::` is what is looked
   up). A Task passes when `problems` is empty and `good` is non-empty — one malformed claim beside
   one good one is a rejection (D3).
7. `claims_on_branch(git, trunk, branch)` — exactly one call through the injected callable,
   `['log', '--format=%B', f'origin/{trunk}..origin/{branch}']`, its output parsed. No
   `subprocess` and no `os` in this function (D11).
8. `tick(body, line_no, note)` → `(new_body, changed)`. Flip the `line_no`-th acceptance bullet
   from `- [ ]` to `- [x]` and leave every other character of the body alone — the same leading
   whitespace, the same text, the same trailing newline. `changed` is False when the bullet does
   not exist or is already `- [x]`. `note` is the caller's History text and this function does not
   write it (D7).
9. `render(claims)` — the `## Proves` block's bullets, one per claim, the text the trailer had.
10. Tests, in the repo's `tests/` idiom (temp dirs, no network, no `~/.ASF`): the trailer parsed
    off a commit message with a `Signed-off-by:` after it; a claim under a `## Proves` bullet in a
    pull-request body; all three dashes and a bare hyphen (D12); a line with no dash parsed as
    nothing; duplicates collapsed in first-seen order; a five-digit and a four-digit Story id both
    parsed (**P3**); `bullets()` over a body with `- [ ]`, `- [x]` and a non-acceptance section
    between them; `card_bullets` returning `[]` for an unreadable path; each of `validate`'s five
    problem kinds by name; a Task with one good and one malformed claim rejected; `tick` flipping
    exactly the nth bullet with the rest of the body byte-identical, twice in a row with the second
    a no-op, and on a line that does not exist; `claims_on_branch` with a stub `git` callable,
    asserting the one argv it is handed.

