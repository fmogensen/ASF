# Plan F-0263 — one command for the four-step escape, and the three places that must honour the branch it carries

Epic: E-0001 — ASF 0.1 — a working factory. Spec: `docs/specs/f-0263.md` (approved). Branch:
`plan/F-0263`.

Three Tasks, cut so that **the carry is honoured everywhere before the command that performs it
exists**:

1. **the lane's two guards, in `asf/harvest/lane.py`** — `carried_ids(items, item)` and
   `lane_refusal`'s new `carried=()`, so a carried branch's commits are neither refused nor
   reworded (P8, C6); and the pure `reslot_closed(run, pr)` with the one line in `branch_facts`
   that drops the carry's own closed pull request from the facts (P7, C7). One existing module,
   one existing test module. Nothing in the factory behaves differently when it lands — no card
   declares `links.supersedes` on a lane branch today and no registry line carries a `reslot`
   record — which is why it can go first and must.
2. **the carry reaching the session, in `asf/feeder/rows.py`** — `task_rows` reading
   `_branch_of(t, product, 'task')` at all **nine** of its code-row sites, so a New Task's
   launching *and* non-launching rows name the branch its work is actually on (P2, C8). One
   existing module, one existing test module, and the same property: no New Task declares
   `links.branches` today, so every landed row is byte-identical after it.
3. **`asf reslot`, the command** — a new `asf/workers/reslot.py`, one registration and one
   `_published` dispatch in `asf/cli.py`, one row and one count in `asf.surface` and
   `tests/test_surface.py`, and the new `tests/test_reslot.py`. The eight refusals, then C3's four
   writes in C3's order, in one signed-off record commit.

They run **(1 | 2) → 3**. Tasks 1 and 2 need nothing of each other and nothing of Task 3: their
`writes:` are disjoint (`asf/harvest/lane.py` + `tests/test_lane.py` against `asf/feeder/rows.py`
+ `tests/test_feeder.py`), so they are one wave. Task 3 is `after: Task 1, Task 2` and the reason
is **safety, not compilation**: `cmd_reslot` calls neither `carried_ids` nor `_branch_of`, so it
builds and its own tests pass against the trunk as it stands — and shipped first it would be a
command that retires a card and closes its pull request while the carry it just wrote is silently
dropped by `task_rows` (P2), the branch's every commit reworded by `repair_naming` (P8) and the
branch sent to terminal `STALE` by the pull request the command itself closed (P7). That is the
hand sequence's own damage with a single command to type it. The dependency is the one thing that
makes the order a queue rather than a preference.

**Read PD1, PD2, PD3, PD6 and PD15 before writing a line.** Each is a place where following the
spec's design literally ships something red, something silent or something that destroys work:
`_published` calls its command with two arguments and cannot know the id the command mints (PD1),
a `set_defaults(func=…)` registration bypasses the record commit entirely (PD2), `_branch_of`
ignores the lane it is given and would put a reshape session on the code branch (PD3), the C7
guard stops holding the moment a session launches on the carried branch (PD6), and §4's snippet
elides the line it would be pasted over (PD15).

The fences of §*The fences, and the suite* bind every Task, so every Gate and Acceptance block
below carries them beside its own.

| PD1 | **`_published` calls its command with *two* arguments, and the commit subject the spec records names an id that does not exist until the command has run** | The spec's §1 writes `cmd_reslot(args)` and `_published(cmd_reslot, args, resolve_record(args), f'record: reslot {old} → {new}')`. Measured: `_published(cmd, args, record, message)` is `before = publish.snapshot(record)`, `rc = cmd(args, record)`, `publish.publish_changes(record, before, message)` (`asf/cli.py:540-550`) — every command it wraps takes `(args, root)`, as `cmd_retire(args, root)` (`asf/record/retire.py:50`) and `cmd_new(args, root)` (`asf/record/new.py:79`) do. And `{new}` is minted *inside* the command (`mint_id`, §1 step 1), so an f-string at the dispatch site can only render it empty: Python evaluates the argument before `cmd` runs. **Decided, two parts.** (a) `cmd_reslot(args, root)`, the shape of every command `_published` wraps; `root` is the record root the dispatcher resolved, and the product comes from `env.load_product(getattr(args, 'product', None))` as `cmd_correct` gets it (`asf/workers/correct.py:82`). (b) `_published`'s `message` is allowed to be a callable — one clause, `publish.publish_changes(record, before, message() if callable(message) else message)` — and the dispatch passes `lambda: f'record: reslot {old} → {getattr(args, "reslot_new", "?")}'`, which `cmd_reslot` answers by setting `args.reslot_new` to the minted id before it returns. Measured safe: `publish_changes(root, before, message)` passes `message` to `commit_paths(root, rels, message)` and into one `f"warning: {message!r} …"` (`asf/record/publish.py:184-203`), so a resolved `str` is byte-identical to today, and **no landed caller passes a callable** (`grep -n '_published(' asf/cli.py` → `set`, `retire`, `reopen`, `untick`, `audit-proofs`, each an f-string). The alternative — `f'record: reslot {args.item}'`, losing the new id — is cheaper by one clause and loses the one thing the subject is for; the spec's `## Records` names the subject and no test pins it, so this is the smaller of the two debts. |
| PD2 | **A `set_defaults(func=…)` registration would bypass the record commit entirely — the cards would be written and never committed or pushed** | Every neighbour the spec points at registers that way: `asf/workers/correct.py:275` (`p.set_defaults(func=cmd_correct)`), `:387` (`cmd_reset`), `asf/workers/unpark.py:183`/`:189`, `asf/workers/answer.py:150`.
