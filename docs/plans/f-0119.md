# Plan F-0119 — the hygiene lanes as data, the flag that prints them, and the contract that names it

Epic: E-0001 — ASF 0.1 — a working factory. Spec: `docs/specs/f-0119.md` (approved). Branch: `plan/F-0119`.

Three Tasks, cut the way the spec's `## The design` is sectioned — by the file that gains the
surface. Task 1 is `asf/harvest/pr_hygiene.py` as a **library**: the `LANES` table that holds the
whole four-token vocabulary, the one new key on `rows` (`since`), and `lanes()` — the listing as
data, which is the thing a test asserts and a future caller imports. Task 2 is the same module as a
**command** plus `asf/cli.py`: `--lanes` prints one `json.dumps(…, sort_keys=True)` per line, it
gets its own exit 2 on an unreadable product, and the flag finally reaches the module through the
`asf` surface, which it never has (P3). Task 3 is `docs/guide/product-config.md`: the rule-check
contract names the command as the supported way for a product check to ask *does ASF own this PR?*,
with the five keys, the three exit codes and a check script a test proves parses.

Only Task 1 starts at once. Task 2 needs Task 1's `lanes()` and its `_entries` helper, because
`main`'s `--lanes` branch is nothing but a print loop over them (D11). Task 3 waits on Task 2 — not
for a test, which would pass alone, but because the paragraph it writes states three exit codes of a
flag that argparse still refuses until Task 2 lands (PD6).

Wave order: **1 → 2 → 3**.

Tasks 1 and 2 both write `asf/harvest/pr_hygiene.py` and `tests/test_pr_hygiene.py` and therefore
queue whatever their `after:` says — see PD5. That costs nothing here: 2 waits on 1 for its code
anyway, and 3 intersects neither. Task 3's footprint is disjoint from both.

§Acceptance tests' last fence — the whole suite and both tree fences, as CI runs them — binds every
Task, so every Gate below runs it beside its own.

### Task 1: `pr_hygiene.lanes` — the hygiene lanes as data, and the one table that names them
stories: S-32500
writes: asf/harvest/pr_hygiene.py, tests/test_pr_hygiene.py
after: none

The spec's first three **In** bullets and the library half of its `asf/harvest/pr_hygiene.py` design
block: the `LANES` table that is the only place the four tokens a product's rule check switches on
exist, one more key on the rows `rows()` already builds, and the listing as a function beside it.
Nothing in this Task has a caller yet — `main` is Task 2's, `render` is not touched, and the
module's default output does not move by a character.

**Files**

- `asf/harvest/pr_hygiene.py` — `LANES`, `rows`' `since` key and its docstring, `_entries`, `lanes`
- `tests/test_pr_hygiene.py` — `LaneListing` (new class); `HygieneView` untouched

**Steps**

1. `LANES` under the two display strings, with the spec's comment byte for byte — row kind → (the
   listing's `lane` token, its `action`), the whole vocabulary in one place (D5, D6):
   `STALE_CLOSE: ('stale', 'close')`, `CONFLICT_REBASE: ('conflict', 'rebase')`. Keyed by the
   existing module constants, never by a repeated literal, so a renamed display string cannot leave
   the table pointing at a kind `rows` no longer yields.
2. `rows` gains exactly one key on both of its two appends: `'since': rec.get('at') or
   rec.get('head_at')` — the lane record's own account of when the branch entered the state it is
   in, `None` when the registry line carries neither (D2, D3). Nothing is computed here and no clock
   is read: the lane stamps `at` on a transition and `advance` declines to rewrite it while the
   state and the reason hold (P6), which is what makes it the right field. `rec` is
   `lane.snapshot_at`'s record, already in hand — no second read (D12). The docstring's first line
   becomes `` ``[{kind, branch, item, pr, why, since}]`` `` and gains the spec's `since` paragraph.
   The two branches, their order, their condition and `render` are untouched.
3. `_entries(rows_)` — private, pure, no product and no I/O: for each row in order, skip it when
   `not r.get('pr')` (D4), look up `LANES[r['kind']]`, and append
   `{'pr': …, 'branch': …, 'lane': …, 'since': r.get('since'), 'action': …}`. A `KeyError` here is a
   kind added to `rows` without a row in `LANES`, which is the table's whole point, so it is not
   caught and not defaulted.
4. `lanes(product, state_dir=None)` — `return _entries(rows(product, state_dir))`, carrying the
   spec's docstring byte for byte: the five keys, the same order, what it is for, that it reads the
   registry the `prs` step already wrote and makes no network call, and that a row with no PR number
   is absent. The split into `_entries` is PD4: the public signature, the docstring and every value
   are the spec's, and Task 2's `main` needs the mapping over rows it has already read rather than a
   second trip to disk.
5. `LaneListing` in `tests/test_pr_hygiene.py`, built on `HygieneView`'s own `run_` fixture writer
   (a `sessions.jsonl` under a temp dir, handed to `rows`/`lanes` as `state_dir` — no patching, no
   network): two PRs in two lanes give two entries with exactly the five keys and in `rows`' branch
   order; each entry's `lane` and `action` are `LANES[kind]` read from the table rather than
   re-spelled; `since` is the record's `at`; a record with `head_at` and no `at` falls back to it; a
   record with neither is `None` and the key is still present (D3); a `BACK kind=conflict` row with
   no `pr` is absent (D4); and a `BACK kind=gate` row, a `MERGED` one and a `REVIEW` one contribute
   nothing, because the view does not hold them (§Out, "A new lane"). One case asserts
   `set(LANES.values()) == {('stale', 'close'), ('conflict', 'rebase')}` so the vocabulary cannot
   grow without a test saying so.

### Task 2: `--lanes` prints the listing, owns its exit code, and reaches the module
stories: S-32501
writes: asf/harvest/pr_hygiene.py, asf/cli.py, tests/test_pr_hygiene.py
after: Task 1

The spec's remaining **In** bullets and both the `main` and the `asf/cli.py` design blocks: the flag
prints one JSON object per line and nothing else on stdout, it exits 2 — with the reason on stderr
and stdout empty — when the product or its state cannot be read, every other argv keeps the exit 0
it has today, and `asf pr-hygiene --lanes` stops being refused by argparse.

**Files**

- `asf/harvest/pr_hygiene.py` — `import json`, the module docstring's `--lanes` line, `main`
- `asf/cli.py` — `p_pr_hygiene`'s new flag and the dispatch that forwards it
- `tests/test_pr_hygiene.py` — `LanesOnStdout`, `LanesExitCodes`, `LanesThroughTheCli` (new);
  `HygieneView`'s one `--lanes` expectation rewritten

**Steps**

1. `import json` above `import sys` (PD7), and the module docstring's usage line becomes the new
   shape — `pr_hygiene.py --lanes    one JSON object per PR in a lane: {pr, branch, lane, since,
   action}`. The other three usage lines and the two rendered-row lines above them are untouched.
2. `main` takes `listing = '--lanes' in argv` before the `try`, so the error path can see it.
3. The `except` keeps its four exception types, keeps printing `pr_hygiene: <e>` on **stderr**, and
   returns `2 if listing else 0`, with the spec's comment byte for byte: a listing's caller must be
   able to tell "ASF owns nothing" from "ASF could not be read", and 2 is a *check failure* to the
   rule contract, never a pass (D7, D8, P14). Every other argv keeps exit 0 exactly as it has it
   (D9, P7) — a session or an operator reading the rows is not a rule check.
4. The `--lanes` branch becomes `for entry in _entries(found): print(json.dumps(entry,
   sort_keys=True))`, **inside the `try`** and over the rows already read (PD4) — one read of the
   lane registry per invocation, and no exception from a second one escaping to `cli.main` to print
   a `NEEDS OPERATOR` sentence into the middle of a listing (P8). `sort_keys=True` and no `indent`
   make the line byte-stable (D10). Nothing else reaches stdout on this path: no header, no count,
   no trailing blank. No row prints nothing and returns 0.
5. `--close` and the default rendering keep every line and every exit code they have (§What stays
   exactly as it is).
6. `asf/cli.py:262`: `p_pr_hygiene.add_argument('--lanes', action='store_true', help=…)` with the
   spec's help string. `asf/cli.py:522`: `if args.lanes: pr_hygiene_args.append('--lanes')` before
   the call, so the module's rc is the command's rc. `asf/surface.py` is not touched — `pr-hygiene`
   stays read-only and `flag` names what makes a command *write* (P9, D1's §Out); `tests/test_surface.py`
   reads the table with no reach into the parser (PD10), so a new argparse flag moves no row and the
   plugin, which names `pr-hygiene` nowhere (P10), is not regenerated.
7. `LanesOnStdout` — the card's own test, through `main` with `env.load_product` and `env.state_dir`
   patched to the fixture the way `HygieneView` already patches them: a cached state with two PRs in
   two lanes prints exactly two lines, each parses with `json.loads`, each has exactly the five keys,
   and the two carry the two lanes; and stdout is byte-equal to
   `''.join(json.dumps(e, sort_keys=True) + '\n' for e in pr_hygiene.lanes(product))`, which pins
   the encoding rather than re-describing it. An empty cache prints nothing — `''`, not a blank
   line — and returns 0.
8. `LanesExitCodes` — `env.load_product` patched to raise `env.ConfigError`: with `--lanes` the rc is
   **2**, stdout is `''` and the reason is on **stderr**; the same failure with no flag is rc **0**
   (D9); an `OSError` from the state read takes the same two paths. And no network call on any of
   them: every case runs with `asf.harvest.lane`'s host reader patched to raise if it is touched, so
   a listing that reached for `gh` would fail the test rather than merely be slow (P5).
9. `LanesThroughTheCli` — `asf pr-hygiene --lanes` through `cli.main`: the flag is accepted (not the
   `unrecognized arguments` of P3), it is forwarded to the module — asserted on the argv the patched
   `pr_hygiene.main` receives, `['--lanes']` and, with `--product p`, `['--product', 'p', '--lanes']`
   in that order — and the command's rc is the module's, for 0 and for 2 alike. One case runs
   `asf pr-hygiene` with no flag and asserts the rows print as they do today.
10. `HygieneView`'s `(['--lanes'], '4')` tuple becomes the JSON line its own fixture produces (PD8);
    the default-output tuple beside it and the class's other test are untouched.

### Task 3: the rule-check contract says how a product check asks what ASF already owns
stories: S-32502

in prose — the `check:` script, the exit codes, the timeout, `asf rules check` (P15, D14). The
paragraph goes where the spec puts it: after the `exit 0` / `exit 1` sentence

**Files**

- `docs/guide/product-config.md` — `## Rule cards`: the paragraph, the two-line example, the
  five-key table, the three exit codes, the `--product` sentence and the check script
- `tests/test_readme.py` — `RuleCheckContractProseTests` (new class)

**Steps**

1. Insert the spec's block byte for byte into `## Rule cards` at the position above: the **Asking
   what ASF already owns** paragraph naming the false positive it removes and
   `asf pr-hygiene --product <p> --lanes` as the supported way to ask; the two example lines; the
   five-key table (`pr`, `branch`, `lane`, `since`, `action`) with the spec's wording for each; the
   sentence that it reads the state the tick's `prs` step already cached and makes no network call,
   so a check may call it every run; the three exit codes — 0 with output, 0 with none when ASF owns
   nothing, 2 when the product or its state cannot be read — and that propagating the 2 makes the
   check a *check failure* rather than a rule the product broke (P14); and the `--product` sentence,

2. The check script fence, byte for byte, including its `product=your-product` line and that line's

3. `RuleCheckContractProseTests` in `tests/test_readme.py`, following `ProductResolutionProseTests`'
   pattern exactly — read `docs/guide/product-config.md` from `REPO_ROOT`, never a fixture (P16,
   D15): the `## Rule cards` section contains `asf pr-hygiene`, `--lanes`, all five key names and
   the three exit codes it promises; the example lines parse with `json.loads` and each has exactly

   `sh` fence is written to a temp file and run through `bash -n`, which must exit 0 — a snippet the
   guide tells an operator to copy is at least known to parse (D15). The script is not *executed*:
   it calls `your_conflicting_prs`, which is the product's to write.
