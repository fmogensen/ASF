# Plan F-0163 — the severity a lane is held by becomes a field a command can write, and a reason the record keeps

Epic: E-0001 — ASF 0.1 — a working factory. Spec: `docs/specs/f-0163.md` (approved). Branch: `plan/F-0163`.

Two Tasks, cut where the spec's own acceptance fences cut:

1. **the command** — `severity` joins `SETTABLE['bug']` and `FIELD_WORDS`, `set_typed` learns to write
   a `## History` line inside the guarded write, `severity_change` decides whether there is a line
   and whether it is allowed, and `asf set` grows `--why`. Three of the spec's four Stories, and all
   three of its new test classes.
2. **the remedy** — `asf/feeder/tiers.py`'s two `severity=S2` strings gain the `--why` Task 1 now
   requires, and the gate's advice is proven to be a command that runs.

They run **1 → 2**. The order is not a convenience and it is not a footprint collision: the two
diffs are disjoint in the product (`new.py`/`setfield.py`/`cli.py` against `tiers.py`), and Task 2
waits because its acceptance is *the printed remedy executed against a real record, exit 0* — a
command that does not exist until Task 1 lands. The string-shape half could land first; the half
that makes the card worth writing could not.

**The cut is the spec's, not a preference.** §Acceptance tests gives `SetSeverityFieldTests` as
*"setting severity on a Bug writes the field **and** the history"* — one fence over both halves, so
a Task that lands the settable row without the History line cannot go green on its own fence (PD1).
Splitting `new.py` from `setfield.py` would mean writing `severity_change` twice, once without the
`--why` it exists to enforce. Task 1 is therefore one idea end to end: *`asf set` can write a Bug's
severity, and the record keeps why.*

**Read PD5 before writing the `--why` gate.** A `--why` is copied verbatim into a structured
`## History` line, and a multi-line one injects a second line into the section — measured here, and
one crafted line forges the `— shape:` reading `asf check` reads that section for. Two lines of
guard, inside the flag this card adds.

**Read PD6 before writing Task 2's test.** The spec's fence puts the executed remedy in
`tests/test_s1_gate.py`, which is a pure unit test over dicts with no record, no subprocess and no
route to either; nothing in the tree imports one test module from another. The assertion still gets
written — in the file that already has the harness.

The last fence of §Acceptance tests — the whole suite plus both tree fences — binds both Tasks, so
each Gate and Acceptance block below carries it beside its own.

### Task 1: a Bug's severity is settable, and the record keeps the reason it moved
stories: S-36200, S-36201, S-36202
writes: asf/record/new.py, asf/record/setfield.py, asf/cli.py, tests/test_backlog.py
after: none

The spec's first three **In** bullets and `## The design` §`asf/record/new.py`, §`asf/record/setfield.py`
and §`asf/cli.py` in full. One row of table makes the field writable; one function decides whether
the move is allowed and what sentence records it; one argument on `set_typed` puts that sentence in
the **same** guarded write as the field. After this Task, the command the 2026-09-26 session ran and
the remedy the S1 gate prints are the same command — Task 2 only makes the gate print it correctly.

Read **PD3** (`render` round-trips only while `meta` is untouched), **PD4** (D9's section test),
**PD5** (the multi-line `--why` — this is the one thing here the spec does not carry) and **PD2**
(three callers of `set_typed` the spec does not name) before starting.

**Files**

- `asf/record/new.py` — `SETTABLE['bug'] |= {'severity'}` with the spec's `#:` comment (after `:21`,
  before `:22-26`'s Feature block); `FIELD_WORDS` gains `'severity': SEVERITIES` (`:28`);
  `FIELD_UPPER` beside it; the two new lines in `_parse_sets` (`:42-44`)
- `asf/record/setfield.py` — the module docstring's new paragraph (`:1-11`); `SEVERITY_HISTORY` and
  `SEVERITY_WHY` beside `LIST_FIELDS` (`:21`); `severity_change`; the call and the echo in `cmd_set`
  (`:134`, `:144-146`); `set_typed`'s `history` argument, docstring and four lines (`:150-171`)
- `asf/cli.py` — `p_set.add_argument('--why', …)` between `:198` and `:199`
- `tests/test_backlog.py` — `SetSeverityFieldTests`, `SetSeverityHistoryTests`, `SetSeverityWhyTests`

**Steps**

1. `asf/record/new.py`: `SETTABLE['bug'] |= {'severity'}` with the spec's four-line `#:` comment byte
   for byte — it names F-0163, `asf.feeder.rows.bug_rows` and `asf.record.setfield.cmd_set`, and it
   is the answer to *"why is this one type's field special"* for the next reader. Nothing else on
   any type's list moves: `SETTABLE['decision']` in particular is untouched, which is what keeps P6
   green.
2. `FIELD_WORDS` (`:28`) gains `'severity': SEVERITIES` — the constant at `:15`, referenced for the
   first time since it was written (P3). Do not re-type the three words; the point of D1 is that the
   tuple already exists. Keep `'lane'` and `'size'` exactly as they are.
3. `FIELD_UPPER = frozenset({'severity'})` beside it, with the spec's `#:` comment — citing
   `asf/groom/inbox.py:278`, the answer grammar, **not** `:201` (PD8). The comment's last sentence,
   that `lane` and `size` are deliberately not in here, stays: it is D7's scope statement.
4. `_parse_sets` (`:42-44`) gains the two lines the spec writes, between `value =
   frontmatter._parse_value(raw)` and `words = FIELD_WORDS.get(top)`: `if top in FIELD_UPPER and
   isinstance(value, str): value = value.upper()`. The `isinstance` guard is not decoration —
   `_parse_value` coerces scalars, so a bare `severity=` reaches here as `None` and `.upper()` would
   raise instead of being refused. The refusal message below is unchanged and reads `raw`, so
   `severity=s4` still refuses with the operator's own spelling: measured, `error: severity='s4' —
   one of S1, S2, S3`.
5. `asf/record/setfield.py`'s module docstring gains the spec's paragraph byte for byte, below the
   list-field paragraph: severity is the one field this command reasons about rather than writing.
6. `SEVERITY_HISTORY = '- {date} set: severity {old} → {new}'` and `SEVERITY_WHY = ' — {why}'` beside
   `LIST_FIELDS` (`:21`), each with the spec's `#:` comment. `{date}` is `asf.record.core.today()`
   — a UTC `%Y-%m-%d` (`asf/record/core.py:63-64`), the same clock the groom's line uses (P12), not
   `reopen`'s minute-resolution stamp (D3).
7. `severity_change(rec, updates, why)` with the spec's docstring byte for byte, returning
   `(history_line, reason)`. In this order, so the cheapest refusal fires first and no branch can be
   reached with a half-checked input:
   - `new = updates.get('severity')`; `old = rec['meta'].get('severity')`. `updates` is already
     validated and upper-cased by step 4 — this function never re-validates the word.
   - `why` is present and `new` is None, or `new == old` → refused, D6: *`--why` records why a
     severity moved; no severity assignment in this command*. (D5 first: a no-op assignment is not a
     move, so a `--why` beside it is a stray `--why`.)
   - `why` contains a newline → refused (**PD5**), naming the flag: a reason is one line, because it
     is written as one line of `## History`. Check this *before* anything is written and before the
     S1 gate, so a multi-line reason can never satisfy D4.
   - `new` is None, or `new == old` → `(None, None)`: no line, no gate, nothing else to decide (D5).
     A `severity=S1` on a card already at `S1` is idempotent exactly like `rank=5` is.
   - `old == 'S1' and new != 'S1'` and no `why` → refused, D4, with the message naming what leaving
     S1 costs: it releases the lane's hold on everything behind it. An upgrade **into** S1, and
     `S2 → S3`, reach this clause and pass it (the spec's §Out).
   - the card's body has no `## History` section → refused, D9, using `parse_sections` from
     `asf.record.core` and the exact heading test `append_history_lines` uses (**PD4**), over
     `rec['body']`, which `load_items` already parsed. Last, because it is the one refusal that is
     unreachable on a card the inbox minted.
   - otherwise `(SEVERITY_HISTORY.format(date=today(), old=old, new=new) + (SEVERITY_WHY.format(why=why)
     if why else ''), None)`. An `old` of None (a Bug that somehow carries no severity — `asf check`
     flags it, `asf/record/check.py:236`) renders as `None` in the line; write it as the card reads,
     do not invent a previous value.
8. `cmd_set` (`:134`): the spec's four lines, **after** the assignment loop and **before**
   `set_typed` — `history, err = severity_change(rec, updates, getattr(args, 'why', None))`, print
   `error: {err}` to stderr and `return 2` if refused, then `err = set_typed(rec, updates,
   history=[history] if history else ())`. `getattr` rather than `args.why` because `set_typed`'s
   module is imported by callers that build their own `args` (`slice`, the tick) — PD2.
9. The echo, under the existing `set` line (`:144-146`): when a history line was written, print
   `{args.id}: history: ` and the line's text without its `- {date} set: ` prefix, so the operator
   reads back `B-1382: history: severity S1 → S2 — main green without it…`. It prints only when a
   line was actually filed — a no-op severity (D5) prints the `set` line and nothing more.
10. `set_typed` (`:150`) becomes `def set_typed(rec, updates, writer='set', history=())` with the
    spec's added docstring paragraph. `history` goes **after** `writer`, which is safe because no
    caller in the tree passes a third positional (PD2). Inside the `try`, after the round-trip loop
