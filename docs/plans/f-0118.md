# Plan F-0118 — the tick writes it down, the session reads it: four Tasks, two waves

Epic: E-0004 — Control plane, the factory's dashboard, served from the record. Spec:
`docs/specs/f-0118.md` (approved). Branch: `plan/F-0118`.

**Four Tasks, two waves.** The spec's D12 is the split and it is the right one: the writer and the
reader share one file format and must land in that order, the install and the doctor row are the two
sides of one setting. What D12 gets wrong is that the four footprints are disjoint — the writer and
the reader both live in `asf/views/status.py`, so Tasks 1 and 2 queue (PD10). The waves are
**(1, 3) → (2, 4)**.

Each Task lands something whole. After Task 1 the tick leaves `state/<product>/status.txt` behind
it every pass, and nothing reads it yet. After Task 3 `asf hooks install` writes the setting and a
session's status line runs a command that says `no tick yet` until Task 1 has ticked — every order
of landing is legible, never broken.

**Read PD2, PD4 and PD5 before writing a line of any Task.** They are the three places a coder who
copies the spec's snippets and runs the spec's own §3.5 gate lands a green local suite and a red CI:

- **PD2** — two snippets name a module their file does not import: `json` in `asf/doctor.py`,
  `sys` in `asf/views/status.py`. Both are a `NameError` on the first call.
- **PD4** — `.claude/` is a **forbidden convention** and `asf/doctor.py` is not one of
  `tools/check_conventions.sh`'s four exempt files. The spec's §6 docstring, copied byte for byte,
  fails that gate. Measured here: rc 1.
- **PD5** — the spec's §3.5 gate omits `tools/check_conventions.sh`, which is exactly the gate PD4
  trips, and CI runs it. Its other line, `tools/check_generic.sh`, is a `PermissionError`: the file
  is not executable.

**Read PD6 before Task 3** — two existing `assertEqual`s on the hooks summary string break, and the
spec's §Out names neither. **Read PD7 before Task 3** — the card introduces a read of a file the
operator hand-edits, and an unparseable one currently takes `asf install` down before the clocks.
**Read PD8 before Task 1** — §2's prose promises a cleanup no snippet performs, and fence 3.1
asserts the very artifact that cleanup removes.

## The fences, the format, and the Gate every Task shares

The snapshot's format is Task 1's to define and every later Task reads it. Written once, in
`asf/views/status.py`, exactly as §2 gives it:

```python
SNAPSHOT = 'status.txt'
STAMP_FORMAT = '%Y-%m-%dT%H:%M:%SZ'

#: The snapshot's first line. ``ts`` is when the tick rendered it; ``stale_after_s`` is the
#: horizon *it* resolved (D3) — the reader never recomputes either.
_HEADER_RE = re.compile(r'^# asf status (?P<product>\S+) ts=(?P<ts>\S+) stale_after_s=(?P<horizon>\d+)$')
```

`re` and `datetime` are already imported (`asf/views/status.py:36-40`); `sys` is not, and is not
needed (PD2).

Each Task's tests go in the class the spec names, in the file the spec names, and **no Task edits
another's class**. The four are `tests/test_tick.StatusSnapshotTests`,
`tests/test_views.StatusLineTests`, `tests/test_hooks_recognise.StatusLineSettingTests` and
`tests/test_doctor.StatusLineRowTests`.

`StatusSnapshotTests` subclasses `TickTestCase` (`tests/test_tick.py:59-127`), which sets
`env.ASF_HOME` to a temp directory for the duration of each test — so `env.state_dir('sample')` is
`<tmp>/home/state/sample` and **no patch of `env.state_dir` is needed**; the existing
`record_path()` helper (`:126-127`) shows the shape. `StatusLineSettingTests` is built the same way
as `SecondInstallChangesNothingTests` (`tests/test_hooks_recognise.py:109-140`) — a temp
`ASF_HOME`, a real `git init` repo as `repo_dir`, a suffixed `asf-live` executable, a `_bytes`
helper — with that `setUp` **copied into the new class, not refactored out of the old one**: the
existing class's three-run byte assertion is one of the fifteen this card must leave meaningful, and
it stays untouched.

Every Task's Gate ends with the same three commands — the card's whole surface against PD1's 513,
and **both** lints, through `bash`, as CI runs them (PD5):

That suite prints an argparse help block to stdout from one `--help` test; `Ran 513 tests … OK
