# Plan F-0122 — one record to read: the path, the tick's every exit, the copy, the line, the row, the prose

Epic: E-0001 — ASF 0.1 — a working factory. Spec: `docs/specs/f-0122.md` (approved). Branch: `plan/F-0122`.

Six Tasks, one per section of the spec's `## The design`, which is already cut by the module that
gains the surface. Task 1 is *a path is a path*: `env.state_path`, the two `shadow` path functions
that stop creating a state directory, and the one success line `sync_operator_checkout` has never
printed. Task 2 is `asf/tick/tick.py` — `sync_checkout(ctx)`, idempotent per tick, reached from
every exit and removed from `commit_and_push`, which is the card's P4. Task 3 is the new module
`asf/views/freshness.py`: `pick`, `line`, `view_record` — two file reads, no git, no network.
Task 4 wires it in: the nine-command dispatch branch and `cmd_next`, and the B-0050 matrix grows
the third kind that makes the age clause an assertion. Task 5 is the doctor's `record` row. Task 6
is the two guide passages that today tell the operator to pull.

Only Task 1 starts at once: Task 3 needs its `env.state_path` (a table asking where the clone is
must not create one), and Task 2 needs its success line to have something to assert. Task 4 needs
both halves landed — its `AfterATickTheNextViewIsFresh` is the card's own test and exercises the
tick's fast-forward *and* the table's fallback in one fixture. Task 5 needs Task 3's age
vocabulary for its `current — index generated 3m ago` detail. Task 6 is prose about what Tasks 4
and 5 print on a terminal, so it waits for both.

Wave order: **1 → 2 ‖ 3 → 4 ‖ 5 → 6**.

Tasks 3 and 4 both write `tests/test_views_freshness.py` and therefore queue whatever their
`after:` says — see PD6. It costs nothing: Task 4 is `after: Task 3` on its own merits. Every
other pair of footprints is disjoint.

§Acceptance tests' last fence — the whole suite and both tree fences, as CI runs them — binds
every Task, so every Gate below runs it beside its own.

### Task 1: a path is a path, and the fast-forward says when it moves
stories: S-33450, S-33451
writes: asf/env.py, asf/tick/shadow.py, tests/test_env.py, tests/test_shadow.py
after: none

The spec's `asf/env.py` and `asf/tick/shadow.py` design section, whole: the non-creating path
function every later Task reads, the two `shadow` helpers that stop creating a state directory as
a side effect of being asked a question, and the one line `sync_operator_checkout` has never
printed when it succeeds. No behaviour changes for any existing caller — `ensure_clone` already
`makedirs` its own parent (P11) — and nothing new is called from anywhere yet.

**Files**

- `asf/env.py` — `state_path(product=None)`; `state_dir(product=None)` delegates to it
- `asf/tick/shadow.py` — `shadow_dir` and `record_dir` become pure path functions;
  `sync_operator_checkout` gains its success line
- `tests/test_env.py` — new `StatePath`
- `tests/test_shadow.py` — new `ClonePathsCreateNothing`, new `OperatorCheckoutSync`

**Steps**

1. `env.state_path(product=None)` beside `state_dir` (`asf/env.py:882`), exactly as the spec's
   block writes it: the `product.name if isinstance(product, Product) else (product or
   default_product_name())` line lifted from `state_dir`, then
   `os.path.join(ASF_HOME, 'state', name)` — and **no** `makedirs`. Its docstring says what it is
   for: a *read* that only wants to know whether something is there uses this one.
2. `state_dir` becomes `path = state_path(product)` plus the `os.makedirs(path, exist_ok=True)`
   and `return path` it already has. Byte for byte the same return value for every caller; the
   `~/.ASF/state/<name>` layout now exists in one function, not two (D14).
3. `shadow.shadow_dir` and `shadow.record_dir` swap `env.state_dir` for `env.state_path`
   (`asf/tick/shadow.py:24,44`). Nothing else in either line changes. Re-verified before the
   swap that every one of the nine call sites of the two either clones into the path — where
   `ensure_clone` does its own `makedirs` (`shadow.py:78-84`) — or reads a file under it; if any
   call site turns out to rely on the directory existing, it gets an explicit `state_dir` call and
   the Task says which, rather than the swap being narrowed.
4. `sync_operator_checkout` gains one line and loses nothing: after the `--ff-only` merge returns
   0, `out(f'record: {repo} fast-forwarded to origin/{trunk}')` immediately before `return True`
   (`asf/tick/shadow.py:227-228`). Every guard above it is untouched — the missing `.git`, the
   `realpath` equality with the clone, the failed fetch, the `behind == 0` silent return, the
   non-trunk HEAD, the dirty tree, the refused merge — and each keeps the line it already prints
   or the silence it already keeps. In particular the *already current* path still returns False
   before the trunk check and still prints nothing.
5. `StatePath` in `tests/test_env.py`: `state_path` returns `<ASF_HOME>/state/<name>` and the
   directory does **not** exist afterwards; `state_dir` returns the same string and the directory
   does; both accept a `Product`, a bare name and `None`; calling `state_path` twice creates
   nothing either time. `ASF_HOME` is pointed at a `tempfile.mkdtemp()` so the assertion on
   non-existence is real and not an accident of the operator's home.
6. `ClonePathsCreateNothing` in `tests/test_shadow.py`: `record_dir(product)` and
   `shadow_dir(product)` both return their paths with no `~/.ASF/state/<product>/` on disk
   afterwards — the side effect the spec's `## Records` says this change removes.
7. `OperatorCheckoutSync` in `tests/test_shadow.py`, over real git repositories built in a temp
   directory (a bare origin, a checkout, a clone): it moves a clean checkout on the trunk and the
   captured `out` carries `fast-forwarded to origin/<trunk>`; it refuses and names a dirty tree;
   it refuses and names a non-trunk HEAD; it refuses and names a diverged one; it is **silent and
   returns False** when the checkout is already current; and it returns False without printing
   when `backlog_dir` resolves to the tick's own clone. Untracked files are asserted *not* to
   block the fast-forward — `--untracked-files=no` is the guard as written (`shadow.py:221`) and
   the operator's untracked scratch is the common case.

**Gate**

```bash
python3 -m unittest -v tests.test_env.StatePath tests.test_shadow.ClonePathsCreateNothing
python3 -m unittest -v tests.test_shadow.OperatorCheckoutSync
python3 -m unittest -v tests.test_env tests.test_shadow tests.test_tick tests.test_tick_summary
bash tools/check_conventions.sh && bash tools/check_generic.sh && python3 tools/run_tests.py
```

**Acceptance**

The tick's fast-forward: it moves a clean checkout on the trunk and says so, refuses and names a
dirty tree, a non-trunk HEAD and a diverged one, stays silent when already current, and refuses
when `backlog_dir` is the clone itself:

```bash

```


### Task 2: reached on every exit, at most once a tick
stories: S-33450
writes: asf/tick/tick.py, tests/test_tick.py
after: Task 1

The spec's `asf/tick/tick.py` design section, whole, and the card's P4: three tick exits reach no
`commit_and_push` and therefore never fast-forward the checkout, and every one of them is a tick
after which origin may have moved. One function with a flag on the context, called from the
places that actually end a tick, and removed from the commit path where a raising commit skipped

**Files**

- `asf/tick/tick.py` — `sync_checkout(ctx)`; `Context.__init__` gains `checkout_synced`; the call
  removed from `commit_and_push`; two calls in `run_record_step`; one at `run`'s end
- `tests/test_tick.py` — new `CheckoutSyncOnEveryExit`

**Steps**

1. `sync_checkout(ctx)`, with the spec's docstring: return False at once when
   `getattr(ctx, 'checkout_synced', False)`, set the flag, import `shadow` inside the function as
   the module already does at its other call sites, and return
   `shadow.sync_operator_checkout(ctx.product, out=print)`. The `getattr` guard, not a bare
   attribute read — a `Context` built by an older path, or a stand-in in a test, must not raise
   here (D12).
2. `Context.__init__` gains `self.checkout_synced = False`, so the attribute is real on every
   context and the `getattr` default is a belt, not the mechanism.
3. Remove the two-line comment and the `shadow.sync_operator_checkout(...)` call from the end of
   `commit_and_push` (`asf/tick/tick.py:232-233`), leaving `return rc`. The `from asf.tick import
   shadow` at the top of that function stays — `commit_local` and `push` still need it. This is

4. `run`'s end (`asf/tick/tick.py:489-492`): `sync_checkout(ctx)` on its own line after the

   for the clone's commit. This closes P4a (a `--steps prs,health` tick) and P4c (a commit that

5. `run_record_step`'s two standalone exits (`asf/tick/tick.py:206-214`): in the `except`, after

   `if not alone: return 0` / `rc = commit_and_push(ctx)` / `sync_checkout(ctx)` / `return rc`.
   The non-standalone path still returns 0 without syncing: it is inside a tick, and step 4 syncs
   at that tick's end. This closes P4b.
6. `CheckoutSyncOnEveryExit` in `tests/test_tick.py`, one case per hole plus the idempotence,
   asserting on what reached the tick log and on how many times `sync_operator_checkout` was
   called (patched, so no git and no network in this module): a tick with **no record step**

   failed** syncs; a **refused push** syncs; a **commit that raised** inside `finish` syncs; and a

   it never decides a tick's result.
7. One case asserts the negative that the old position hid: with `commit_and_push` raising
   `subprocess.CalledProcessError`, the sync still happens. That is P4c stated as a test, and it
   is the one that fails against `main`.

### Task 3: `asf/views/freshness.py` — which copy, and how old
stories: S-33451, S-33452
writes: asf/views/freshness.py, tests/test_views_freshness.py
after: Task 1

The spec's `asf/views/freshness.py` design section, whole: the one answer to which copy of the
record a table reads and how old its index is. Read-only, stdlib plus `asf.env` and
`asf.views.index_reader`, **no git and no network** — two `index.json` reads and a comparison of
their `generated` stamps. Nothing calls it yet; Task 4 wires it in.

**Files**

- `asf/views/freshness.py` — new module: the docstring, `Fresh`, `generated_at`,
  `clone_index_root`, `pick`, `line`, `view_record`
- `tests/test_views_freshness.py` — new module: `PickTheCopy`, `TheRecordLine`

**Steps**

1. The module docstring, byte for byte as the spec writes it — it is the one place the two copies,
   the rule, the D4 argument (no table reads a card) and `ASF_RECORD=checkout` are explained to
   the next reader.
2. `Fresh = collections.namedtuple('Fresh', 'root source generated age_s checkout older_s')` with
   the spec's comment above it. `source` is `'checkout'` or `'clone'`; `older_s` is None unless
   `source` is `'clone'`.
3. `generated_at(root)` — `index.json`'s `generated` through `index_reader.parse_ts`, or None. A
   missing file, an unreadable one, malformed JSON and a missing or unparseable `generated` all
   return None and raise nothing: the docstring says why (*not an error here, it is simply not a
   candidate*). Catches `OSError`, `ValueError` and `TypeError`, named — not a bare `except`.
4. `clone_index_root(root, product)` exactly as the spec's block writes it: None when `product` is
   None or has no `backlog_dir`; None when `os.path.realpath(root) != os.path.realpath(
   product.backlog_dir)` — D5's whole guard, which also settles the case `sync_operator_checkout`
   guards against, `backlog_dir` *being* the clone; then `os.path.join(env.state_path(product),
   'record')` and the path only when it already holds an `index.json`. `env.state_path`, not
   `state_dir` — Task 1 exists so that asking this question creates nothing (D14).
5. `pick(root, product=None)` — `Fresh` for the copy a table should read. `ASF_RECORD=checkout`
   short-circuits to the checkout before anything else (D7). Otherwise: `clone_index_root`, then
   the clone only when its `generated` is **strictly** newer than the checkout's. A tie goes to
   the checkout, and so does a checkout with no readable stamp *unless* the clone has one — an
   unstamped checkout beside a stamped clone is the clone being provably newer. `age_s` is
   measured against `dt.datetime.now(dt.timezone.utc)` and is None when there is no stamp.
6. `line(fresh)` — the two forms, and the third for an unstamped index:
