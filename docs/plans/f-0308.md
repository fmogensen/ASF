# Plan F-0308 — the two channel heads: one module, five edits, six Tasks

Epic: E-0001 — ASF 0.1 — a working factory. Spec: `docs/specs/f-0308.md` (approved). Branch:
`plan/F-0308`.

Six Tasks, one per Story, cut along the spec's own design sections. Task 1 is the **resolver**:
the new module's constants, `version_key`, the pure `channel_tag`, `resolve`, and the one
documented settings key the other five Tasks read their thresholds from. Task 2 is the **log** —
`state/<product>/channels.json`, its registry line, and the trim — because every later Task
measures something from it. Task 3 is **edge**: the candidate rule and the one fast-forward through
the guard. Task 4 is the **stable gate**: four rows and the S1 window, with its own record fixture.
Task 5 is the **mover and the report**: the daily part, and `asf channels`. Task 6 is the **two
consumers**: `asf upgrade --to <channel>` and the bootstrap's default ref.

The cut is the spec's §1–§5, with §1 split four ways because §1 is four separate rules behind one
module name — the resolver, the log, the edge admission and the stable gate — each with its own
fenced acceptance, its own red and its own Story. A single Task carrying all of §1 could not be
reviewed for any one of them, and §1 is where every claim of this card lives.

Wave order: **1 → 2 → (3, 4, 6) → 5**.

That is the dependency order, not a parallelism claim: the spec's acceptance fences name
`tests.test_channels.<Class>` byte for byte, so there is exactly **one** test module and every
Task's `writes:` intersects every other Task's. The lane runs intersecting Tasks one after
another, so all six are serial whatever their `after:` says — accepted, not worked around
(**PD9**). Tasks 3, 4 and 6 become available together once Task 2 lands, and the queue picks their
order; Task 5 is last because it wires the two rules the gate and the report print.

## Tasks

### Task 1: the resolver and the settings — one listing, read by the peel
stories: S-81204
writes: asf/channels.py, asf/env.py, docs/products.example.yaml, tests/test_channels.py
after: none

The spec's **In** 1 and 2 and its design §1, down to `resolve` — the new module's constants, the
ordering key, the pure rule every consumer shares, the one call that feeds it, and the settings
key the five later Tasks read their thresholds from. Nothing is published here and nothing is
written: this Task is the answer to *"what tag does this channel name"*, and nothing else.

Four decisions bind this Task: **PD3** (`version_key` is defined here and the three existing
copies of the newest-tag rule are left alone), **PD4** (`channels` imports `cli`, never the other
way), **PD7** (one documented key, five defaults under it) and **PD9** (`tests/test_channels.py`
is one module six Tasks write in turn — run it whole).

**The trap this Task exists to avoid.** The peel line is printed only for a ref pattern that
matches it. Measured on origin at this head: `git ls-remote origin 'refs/tags/v0.1.261'` prints
**one** line and it is the *tag object's* sha; `git ls-remote origin 'refs/tags/v0.1.261*'` prints
**two**. The trailing `*` of `refs/tags/v*` is therefore load-bearing, and so is `--refs`' absence
— that flag is what hides the peel. A coder who narrows the pattern to an exact ref, or who adds
`--refs` back for tidiness, gets tag-object shas that match no commit and a channel that resolves
to nothing, with every test still green unless the fixture's tags are really annotated. They are:
the fixture builds a real bare repo and really annotates them.

**Files**

- `asf/channels.py` — **new**, the resolver half only. The module docstring of §1; `NAMES`,
  `PREFIX`, `REF`, `PEEL` and `DEFAULTS` as §1 writes them (five keys — `stable_every_days` 7,
  `edge_dwell_h` 48, `rehearsal_check` `'rehearsal'`, `lookback_tags` 10, `log_keep` 60);
  `version_key(tag)`, the integer tuple of the tag's digits, which is the ordering
  `install.newest_tag` (`:63`) and `cli.latest_release` (`:149`) already use and which this module
  does not rewrite them to call (**PD3**); `channel_tag(lines, name)`, pure — no network, no clock,
  no config — exactly the body §1 gives; `resolve(url, name, run=subprocess.run)`, the one
  `git ls-remote <url> 'refs/heads/releases/*' 'refs/tags/v*'`; and `settings(product)`, `DEFAULTS`
  overlaid with the product's `release.channels` map, unknown keys ignored. `from asf import cli`
  at module scope, for `cli.RELEASE_TAG` (**PD4**). Stdlib plus `asf` only.
- `asf/env.py` — `DOCUMENTED_UNCHECKED_FIELDS` (`:577`) gains `'release.channels'`, one entry,
  with the comment block above it extended the way its neighbours are. **Not** `RELEASE_FIELDS`
  (`:559`) and **not** `NESTED_FIELDS` (`:563-566`): registering it there is what the pinned
  reader refuses (**PD7**, P16, D11).
- `docs/products.example.yaml` — the five thresholds documented in the commented `release:` block
  (`:623-660`), beside the `ci_steps` line (`:635`), with their defaults shown the way that block
  shows its others. Commented, so no shipped product file carries the key.
- `tests/test_channels.py` — **new**. `tagged_remote(tmp)`: a real bare repo with real **annotated**
  version tags — `v0.1.0`, `v0.2.0`, `v0.10.0`, the stray `v0.2.0-rc1` — and a real
  `releases/stable` head at `v0.2.0`'s commit, so the lines under test are the ones real git
  prints (P4). Hermetic, no network, the same shape `ReleaseRefTests` already builds (P3). Then
  `ResolveTest`, one case per checkbox line of S-81204: the published head resolving to the tag
  whose peel names its commit; the argv of the one call, both patterns, in order; an unpublished
  channel as `(None, None)` with the listing exiting 0; a head at a commit no version tag names as
  `(None, commit)`; the tag-object sha never returned; the stray dropped; two version tags on one
  commit resolving to the higher one by integer tuple and not lexically (`v0.10.0` over `v0.2.0`);
  and an unreadable listing as `(None, None)`, never a guess.

**Steps**

1. Write `tagged_remote` first and print what it lists, so the fixture is proved to carry peel
   lines before any rule is written against them.
2. `NAMES`, `PREFIX`, `REF`, `PEEL`, `DEFAULTS`, `version_key`, `channel_tag` — `ResolveTest`
   red, then green.
3. `resolve`, with the argv assertion over an injected `run`; then the unreadable-listing case.
4. `settings`, the `env.py` entry and the example block; check the doctor stops calling the key

5. The Gate, in the foreground.
