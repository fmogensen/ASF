### Task 1: the lane writes down what the branch carried
stories: S-37800
writes: asf/harvest/lane.py, tests/test_lane.py
after: none

The spec's design §1: one `own` field on the lane record, and the `ON_TRUNK` constant that names the
one landing the DONE table may not credit. Nothing in `asf/tick/summary.py` is touched here — this
Task only makes the fact readable; Task 2 reads it.

Read **PD1** (every anchor in this file is stale), **PD7** (why the two-argument `.get` is exact)
and **PD5** (the fixture cannot push an empty branch; this Task adds the helper) before starting.

**Files**

- `asf/harvest/lane.py` — `ON_TRUNK` constant; `Lane.record` gains `own`; the three `on-trunk`
  literals re-spelled through the constant
- `tests/test_lane.py` — the new `OwnCommits` class; the `push_lane_empty` helper on `LaneFixture`

**Steps**

1. `ON_TRUNK = 'on-trunk'` in `asf/harvest/lane.py`, beside the other lane constants near
   `HEAVY_DROPS` (`:161`), with the `#:` comment **byte for byte** from the spec's §1 block:

   ```python
   #: `method` on a MERGED record whose sha is the trunk tip, not a merge of this branch: the
   #: branch's work was already there. The one landing the DONE table may not credit (F-0191).
   ON_TRUNK = 'on-trunk'
   ```

   It must be module-level and importable — Task 2 reads `lane.ON_TRUNK`.
2. `Lane.record` (**`:1811`**, not the spec's `:1736`) gains the `own` field exactly as the spec's
   §1 snippet has it: after `prev = f.get('prev') or {}` and **before** the `heavy` block, so it
   sits ahead of `rec.update(extra)` and any explicit `own=` passed by a caller would still win.

   ```python
   # what the branch carried of its own, counted while origin/<trunk>..origin/<b> still shows
   # it (PD6). A branch gone from origin cannot be counted: the last pass that could, stands.
   own = f.get('ahead', prev.get('own'))
   if own is not None:
       rec['own'] = own
   ```

   The two-argument `.get` is the whole of C3 and C4 and is **not** interchangeable with
   `f.get('ahead') or prev.get('own')`, which would carry a stale count forward over a real `0`
   and leave the defect in place (PD7). The `if own is not None` guard is what makes "absent"
   distinct from `0` — do not collapse it to a plain assignment.
3. Re-spell the three `'on-trunk'` literals through the constant: `_judge`'s two returns at
   **`:1203`** and **`:1208`** become `return MERGED, f'method={ON_TRUNK}'`, and `enter_merged`'s
   test at **`:1996`** becomes `method in (ON_TRUNK, 'ff')`. Nothing else changes in either
   function; `method` is still `reason.split('=', 1)[-1]` (`:1974`), so it still reads `'on-trunk'`
   for those reasons and every existing test of the reason string stays green. `'ff'` is left a
   literal — the spec mints one constant, not two.
4. `tests/test_lane.py`: add `push_lane_empty(self, branch)` to `LaneFixture`, beside `push_lane`
   (`:388`) — a fetch then `git push origin origin/main:refs/heads/<branch>`, per PD5. It pushes a
   ref at the trunk tip and makes no commit. Task 2 uses it too.
5. The new `OwnCommits` class over `LaneFixture`, with the spec's four cases from A1:
   a branch with one commit records `own: 1` on every lane record through to `MERGED method=ff`;
   a branch pushed at the trunk tip (step 4's helper) records `own: 0` on its
   `MERGED method=on-trunk`; a branch gone from origin carries the previous record's count forward;
   a record with neither has **no `own` key at all** — assert `'own' not in rec`, not
   `rec.get('own') is None`, since C3 turns on the key's absence. Read the record back through
   `self.lane_of(branch)` (`:415-417`), which is the fixture's own accessor. For the third case,
   drive a pass that reaches `gone_merged` (PD7): the branch deleted from origin with the previous
   record's `head` an ancestor of the trunk.

### Task 2: the DONE table credits the run that earned it
stories: S-37801
writes: asf/tick/summary.py, tests/test_lane.py
after: Task 1

The spec's design §2: `credits_landing` keeps its name and its one caller, its body becomes
`claims_landing`, `own_landing` is the new question, and the renderer says the second half of the
card's sentence. `asf/harvest/lane.py` is **not** touched here — Task 1 landed `ON_TRUNK` and `own`.

Read **PD4** (the local import is not about a cycle), **PD6** (A3 needs the earlier item commit on
the trunk or it passes for the wrong reason), **PD8** (no truncation) and **PD3** (both arms
reproduce today) before starting.

**Files**

- `asf/tick/summary.py` — `claims_landing` and `own_landing` added; `credits_landing` re-bodied;
  the `done` loop's `elif`
- `tests/test_lane.py` — `FeederAndOutcomes::test_the_done_table_credits_only_a_run_with_its_own_commits`
  extended; the new `EmptyLaneBranchIsNotCredited` class

**Steps**

1. `asf/tick/summary.py`: the three predicates **byte for byte** from the spec's §2 block —
   `claims_landing`, `own_landing`, `credits_landing` — replacing today's `credits_landing`
   (`:124-132`). Keep the order the spec prints them in, and keep every docstring whole: they carry
   C3's rule (absent is unknown, and unknown is credited) and C5's (`trunk_closed` is never
   credited), and those are the two answers a future reader will otherwise re-derive wrongly.
2. In `own_landing`, keep the function-local `from asf.harvest import lane`, and make its comment
   say **import weight**, not *cycle* — PD4 measured that no cycle exists in either direction, and
   `asf/harvest/pr_hygiene.py:41` is the in-repo precedent for reading `lane` this way. The order
   inside the function is load-bearing and is the spec's: `trunk_closed` first, then `lane_of`,
   then the `method` test, then `rec.get('own') != 0`. That last comparison must stay `!= 0` and
   not `> 0` or truthiness — an absent `own` is `None`, which is `!= 0`, and that is C3.
3. The renderer's `done` loop (`:148-152`): add the `elif` exactly as the spec's block has it, so a
   row that claims a landing it did not earn reads `nothing of its own` instead of falling through
   silent:

   ```python
   for r in done:
       result = r.get('end_reason')
       if credits_landing(r):
           result = f"{result}, landed {r['harvested'][:7]}"
       elif claims_landing(r):
           result = f'{result}, nothing of its own'
   ```

   Nothing else in the loop moves — `done_records.append(...)` and every other column stay as they
   are. A run with no `harvested:`, an archived run and an adopted row claim no landing and keep
   today's bare result (PD8: no width or column change is needed for the longer string).
4. Extend `FeederAndOutcomes::test_the_done_table_credits_only_a_run_with_its_own_commits`
   (**`:2477`**, not the spec's `:2319`) with the spec's A2 table, keeping its four existing
   assertions untouched: `{method: on-trunk, own: 0}` **not** credited; `{method: on-trunk, own: 1}`
   credited; `{method: ff, own: 0}` credited; a `trunk_closed` run **not** credited; a run with no
   `lane` record at all credited (unknown, C3). Build each as a `lane` dict on the run, the way
   `lifecycle.lane_of` reads it. Then assert the **rendered text**, as A2 requires: the refused row
   reads `finished, nothing of its own`, and a run with no `harvested:` still reads a bare
   `finished` — that second one is what catches an `elif` written as an `if`.
5. The new `EmptyLaneBranchIsNotCredited` class over `LaneFixture`, reproducing P1 in the order
   PD5 and PD6 give:
   (a) `push_main({...}, 'feat(T-0001): a')` — the earlier commit naming the item on the trunk,
   **required** (PD6) or the branch never reaches `MERGED` and the test passes vacuously;
   (b) `push_lane_empty('worker/T-0001')` — Task 1's helper, the branch ref at the trunk tip;
   (c) `self.session('correct-t-0001', 'T-0001', 'worker/T-0001')` — the run ended `finished`;
   (d) `push_main({...}, 'plan(F-0999): another item entirely')` — another item's commit, now the
   trunk tip. Capture it with `self.origin_main()`.
   Then one `harvest.run_product_harvest(...)` pass, then `summary.render` over the run. Assert on
   **the run's row**, isolated from the rendered text by its job name — not on the whole string,
   which also carries the IN FLIGHT block and the table titles: the row contains
   `nothing of its own`, and contains neither `landed` nor `self.origin_main()[:7]`.
   `tests/test_lane.py` already imports both `summary` and `harvest`, so no new import is needed.
