# Plan F-0312 — the test that would have caught it: the predicate, the grafted run, the hold, the waiver, the flags, the brief

Epic: E-0001 — ASF 0.1 — a working factory. Spec: `docs/specs/f-0312.md` (approved). Branch:
`plan/F-0312`.

Six Tasks, one per Story and one per section of the spec's `## The design`. Task 1 is the
**predicate**: the four pure functions of `asf/harvest/regression.py` — `gated`, `test_files`,
`failing_cases`, `verdict` — which every other Task calls and which need no git and no test run.
Task 2 is the **grafted run**: the throwaway worktree detached at the pre-fix tree, the branch's
test files grafted on and committed inside it, the detached job, the `flock` and the result store,
written function for function after `asf/harvest/rebuild_check.py`. Task 3 is the **hold**: the ask
in `lane.branch_facts` beside `f['refusal']`, `hold_text`, and the new `lifecycle.REGRESSION`
cause. Task 4 is the **waiver**: the `Regression-waived:` trailer read against the decision
register, and nothing else. Task 5 is the **flags**: the four `regression.*` names in
`conventions.KNOWN_FLAGS`, off by default, with a malformed one said rather than acted on. Task 6
is the **brief**: the pre-fix base and the command printed in `fix-bug.md`, so a session runs the
lane's own check before it pushes instead of learning the rule from a hold.

Wave order: **1 → (2, 5) → (3, 6) → 4**.

The cut is the spec's own §1–§6, one section per Task, and the seam is the one the spec draws: the
pure predicate first because the other five sections read their verdict from it, and the parse in
its own module because widening `lane._FAIL_RE` would move what the factory calls a red test on the
**trunk** (**PD6**). Tasks 2, 3, 4 and 5 all touch `tests/test_regression_gate.py`, and 2, 3 and 4
all touch `asf/harvest/regression.py`, so those four are queued one after another whatever their
`after:` says — accepted, not worked around (**PD7**). Task 6 is disjoint from every other Task on
both sides and is the one that genuinely runs beside another.

Nothing in this plan changes any product's behaviour on the day it lands: `regression.check`
defaults to `off`, and a product that takes the release has to set it before its incident lane
holds a single branch (**PD9**).

## Tasks

### Task 1: the predicate — `gated`, `test_files`, `failing_cases` and `verdict`, with no git and no test run
stories: S-80454
writes: asf/harvest/regression.py, tests/test_regression_gate.py
after: none

The four pure functions the other five Tasks call. `verdict` is the one place the four states are
decided, so the hold's text and the tick line cannot disagree about the same branch; `gated`
returns its own `why` so a fix branch the gate skips says why it was skipped — a silent skip is how
the gap the spec's P1 measures went unnoticed.

**Files**

- `asf/harvest/regression.py` — new. The module docstring, and `gated`, `test_files`,
  `failing_cases`, `verdict` with the spec's §1 docstrings. No git, no subprocess, no product
  import beyond `asf.feeder.widen` and the `conv` passed in.
- `tests/test_regression_gate.py` — new. `PredicateTest` only; the other four classes are the
  later Tasks'.

**Steps**

1. `gated(conv, items, item, branch, files)` → `(True, '')` or `(False, why)`: `False` unless
   `conv.branch_kind(branch) == 'fix'` (`asf/conventions.py:1276`), with `why` naming the kind it
   saw; `False` when the card's `found_in` is in `flags.regression.exempt_found_in` (default
   `('ci',)`), with `why` naming the value (`found_in: ci`); a card with **no** `found_in` is
   gated, because an absent field is not a licence; `False` when `test_files(files)` is empty, and
   `False` when it equals `files` — a diff that is all tests has no change to be red against (D11).
   The card is read off the index entry, `found_in` and nothing else.
2. `test_files(files)` → the branch's test files in first-seen order, each `widen.is_test_path`
   (`asf/feeder/widen.py:101`). One owner for what a test file is; no second definition here.
3. `failing_cases(log, pattern=None)` → the case names a run reports as not passing, in order, each
   once: `unittest`'s `FAIL: <case>` and `ERROR: <case>` added beside the node:test `✖`, vitest
   `✗`/`×` and TAP `not ok N -` shapes, or `pattern`'s first group when the product sets one. The
   name is the case's own — the trailing parenthesised dotted path and any duration stripped. Its
   own regex, in this module; `lane._FAIL_RE` is not imported and not touched (PD6).
4. `verdict(before, after, pattern=None)` → `(state, cases, line)` over the two runs'
   `(rc, output)`: `proved` with the case names red before and absent after (D5); `not-red` when
   the pre-fix run exited 0 naming no case; `inconclusive` when it exited non-zero naming none
   (D4); `red-both` when every case red before is red after. `line` is the one sentence the tick
   and the hold both quote.
5. Write `PredicateTest` to the eleven acceptance lines of S-80454, one assertion each, with a
   fake `conv` and literal captured output — no git, no worktree, no product yaml.

### Task 2: the branch's tests on the pre-fix tree — the grafted worktree, the lock, the store, the detached job
stories: S-80455
writes: asf/harvest/regression.py, tests/test_regression_gate.py
after: Task 1

`asf/harvest/rebuild_check.py`'s shape, function for function. The graft is committed **inside**
the throwaway worktree and pushed nowhere, which is what makes the pre-fix sha a real base for
`--touched {base}` to diff against (PD3).

**Files**

- `asf/harvest/regression.py` — `store`, `key`, `result_path`, `read_result`, `write_result`,
  `prune`, `try_lock`, `running`, `spawn`, `check`, `run_job`, `main`, beside Task 1's four. The
  store is `state/<product>/regression-check/`, its lock `running.lock`, and `prune` keeps results
  two days as `rebuild_check.KEEP_S` already does.
- `tests/test_regression_gate.py` — `GraftedRunTest`, over a real git fixture.

**Steps**

1. `key(repo, trunk_sha, branch_sha, command)` → `<pre-fix tree>-<test tree>-<command hash>`: the
   three facts that decide the answer, read as **trees** and not shas, so a rebase that changes no
   content is a cache hit and a changed test file is a miss.
2. `run_job(...)`, under the one `flock`: `git worktree add --detach` at `origin/<trunk>` as the
   gate measures it (D2 — the lane rebases before it gates, so the trunk tip is both the product
   without this fix and the tree the fix will land on), the product's `worktree_setup`, then
   `git checkout <branch sha> -- <each test file>` and
   `git -c user.name=asf -c user.email=asf@local commit -q -m "regression check: the branch's tests on the pre-fix tree"`.
   Then the command with `{base}` substituted, `failing_cases` of its output, `verdict` against the
   head run's own, `write_result`. The worktree is removed in a `finally`, as
   `lane.pre_push_check_at` (`asf/harvest/lane.py:1007`) already does, and the process group is
   killed on timeout the same way.
3. `check(product, repo, state_dir, trunk_sha, branch_sha, …)` → `(state, line)`: the stored
   verdict when a job has judged this content, else `(None, why)` — started now, or another check
   holds the lock, naming the sha that is running — and the caller goes on without waiting (D6).
4. `spawn` / `main`: `python3 -m asf.harvest.regression --product <p> --trunk <sha> --branch <sha>
   --key <k>`, detached, appending to `logs/regression-check-<product>.log`, one
   `regression check <sha>: <state>` line per run.
5. The head run is **not** a second test run: the gate already runs the product's command on the
   rebased head, and its output is what `verdict` reads as `after`.
6. Write `GraftedRunTest` to the seven acceptance lines of S-80455: a repo whose `origin/main`
   holds the defect and a test module, a branch whose commits fix it and add a failing case; assert
   the worktree is detached at the trunk sha, that the only files differing from it are the
   branch's test files, that the grafted commit is reachable from no ref (`git branch --contains`
   empty), that the command received the pre-fix sha where `{base}` stood, `key`'s stability across
   a content-free rebase, the second `check` returning no verdict and naming the running sha, and
   the worktree gone afterwards pass or fail.

### Task 4: a waiver is a decision the register holds, or it is not a waiver
stories: S-80457

The one escape hatch, and the same one `asf.proves.unproved` already honours for a deferred
acceptance line: a human's recorded decision, never a session's prose. A free-text excuse the lane
accepts is not a mechanical check — it is the convention the spec's P3 measures as unread.

**Files**

- `asf/harvest/regression.py` — the trailer read and the `waived` / unknown-id branches of `ask`
  and `hold_text`.
- `tests/test_regression_gate.py` — `WaiverTest`.

**Steps**

1. Read `Regression-waived: D-nnnn` as a commit **trailer** off the branch's own commits, with the
   message parse the lane already uses for a trailer, and resolve the id against

   correction.
3. A trailer naming an id the register lacks → held, with the text naming that id as not in the
   register. A trailer is not a password: an id nobody recorded is no waiver.
4. No trailer at all → held as a plainly missing test, whatever prose the branch carries.
5. Write `WaiverTest` to the four acceptance lines of S-80457, over the git fixture Task 2 built

## What this plan leaves unbuilt, and why

The spec's replay block — the whole mechanism by hand against the one real `fix(` commit the
sixty-day window holds — is on **no** Task's Acceptance, on purpose. It passes today (PD3), it
proves the mechanism rather than the code, and a Gate built on one commit is a Gate that goes red
when that commit leaves the window or its module is renamed. It stays what the spec makes it:
evidence, run by hand, re-measured in this session and quoted in PD3. Each Task proves itself on
its own fixture instead (PD11).

Everything in the spec's `## Out` stays out, and no Task touches any of it: `lane.red_tests` and
`_FAIL_RE` (PD6), running a single test case by name, a gate on any lane but `fix`, a gate on a
Bug whose `found_in` is `ci`, a new metrics stream or `gates.jsonl` row, a write to the card or its
acceptance bullets, and any judgement of the test's quality beyond "fails before, passes after".

The duplicate Story cards the spec's stale `### S-…` headings will mint when this plan lands
(PD1) are not fixed here: the deliverable is one file, and the headings are in a doc this job may
not edit. The operator line below asks for the record to be read first; the repair, if the record
confirms it, is an amend of the spec's frontmatter and headings under its own card, not a
widening of this one.
