# Plan F-0264 — the ruling is found item-wide, the lane's own rewrites stop answering it, and no adjudication outranks it

Epic: E-0001 — ASF 0.1 — a working factory. Spec: `docs/specs/f-0264.md` (approved). Branch:
`plan/F-0264`.

Three Tasks, cut so that **the three causes die together and the reasons become visible beside
them**:

1. **the three causes, in `asf/workers/lifecycle.py` and `asf/harvest/lane.py`** — the item-wide,
   branch-scoped read (`pending_on_branch`, §1), the `head_at` carry across the lane's own
   rewrites (`head_since`/`Lane.record`/`lane_built`, §2), and the guard that stops an
   adjudication's overrule outranking a later operator ruling (`later_operator_ruling` inside
   `overruling`, §3). Two existing modules, three existing test modules. These three are **one**
   Task and not three because P4 measured that each fixed alone still loses the ruling, and
   because fixes 1 and 3 both edit `branch_facts` while fix 2 edits `Lane.record` in the same
   file: split, their `writes:` intersect and the queue serialises them anyway — with two
   intermediate landings that deliver no Story.
2. **the cause named, in `asf/feeder/rows.py` and `asf/views/status.py`** — `correction_cause`
   with its four answers, read by `pushed_rows`, `bug_rows` and the new `Held corrections` status
   cell (§5). Disjoint from Task 1 in every file, and it needs nothing of Task 1: it reads the
   occupancy facts the feeder already has and names the state it finds (**PD12**), which is true
   before Task 1 lands and after.
3. **the two regressions, test-only** — the 2026-10-06 replay (`tests/test_ruling_launches.py`,
   §6/S-62859) and the withdraw's pin (`tests/test_merge_queue.py`, §4/S-62857). No code change in
   either (C13), and both read behaviour Task 1 creates.

They run **(1 | 2) → 3**. Tasks 1 and 2 need nothing of each other and their `writes:` are
disjoint, so they are one wave. Task 3 is `after: Task 1` only — **not** `after: Task 2`: the
replay asserts a `FIX → CORRECT` row and the absence of `PUSHED → LAND`, and measured on this
checkout the item is already in `spoken` by the time `pushed_rows` runs (`asf/feeder/rows.py:2475`
passes `live | {r.item_id for r in rows}`, and `correction_rows` has emitted the row by then), so
Task 2's row text is not what the replay reads. Task 3 may therefore run while Task 2 is still in
flight; their files do not meet.

**Read PD1, PD3, PD4 and PD5 before writing a line.** Each is a place where following the spec's
design literally ships something red or something that silently does not fix the bug the card
exists for: §2's three append sites **miss `repair_signoff`**, whose push sets `f['head']` itself
and which the Acceptance names by word (PD1); §5's `correction_cause` has no parameter for the
fact its own CAUSE_CAP is defined by (PD3); §5's `pushed_rows` snippet reads an `attempts` that
`pushed_rows` does not have, which is a `NameError` (PD4); and §2's `Lane.record` snippet reads a
`prev` that is defined *below* the line it would be pasted over (PD5).

The fences of *The fences, and the suite* bind every Task, so every Gate and Acceptance block
below carries them beside its own.

### Where the spec is wrong

Four findings above are defects in the approved spec, not choices this plan is making, and they
are listed here so the next reader does not have to infer which is which. **This plan adds no
scope for any of them**: each is the minimum change that makes the spec's own acceptance line
true.

- **PD1** — §2 and P11 miss `repair_signoff` as a `lane_built` site. The acceptance line names
  sign-off, so the spec contradicts itself; the plan adds the fourth site, one line.
- **PD2** — §2's signature says `lane_heads`, S-62855's prose says `lane_built`. The plan keeps
  the signature.
- **PD3** — §5's `correction_cause` signature cannot answer its own `CAUSE_CAP` definition. The
  plan adds one defaulted argument.
- **PD4** — §5's `pushed_rows` snippet references an undefined local. The plan adds two defaulted
  arguments and threads them from the one in-product call site.

Everything else below is the spec as approved.
