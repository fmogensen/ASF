# Plan F-0104 — the install that ticks, not the install that upgrades

Epic: E-0002 — ASF 0.2 — self-improvement. Spec: `docs/specs/f-0104.md` (approved). Branch:
`plan/F-0104`.

Three Tasks, cut so that **one reader of "which install ticks" exists and is proven before either
caller reads it**:

1. **`asf/clockinstall.py`, whole** — the plist reader, the five kinds, the pipx venv and its
   suffix, the per-venv commit read off disk, the trunk on this host, and the behind/merged answer.
   One new module and one new test module; nothing else in the tree moves and nothing in the
   factory behaves differently when it lands. Both other Tasks are callers of this one.
2. **`asf doctor` names the install each clock runs, and is RED when what ticks is not pinned and
   merged** — one `required=True` row per clock beside the `clock code` row that it does not
   replace, the R1–R4 rule in one place, and the two `skip` rows that are statements about the host
   rather than about an install.
3. **`asf upgrade` reinstalls the venvs the clocks name, and the sha a rollback needs is recorded
   and printed** — the target set, `--suffix=`, the per-venv url and verification, the "not the one
   that ticks" lines, `previous`/`venvs` in the record, the `rollback:` line, and the guide.

They run **1 → 2 → 3**, a strict chain. Tasks 2 and 3 touch disjoint source files (`asf/doctor.py`
against `asf/upgrade.py`) and could otherwise be one wave, but the spec binds **one** new test
module — `tests/test_clock_install.py` carrying all five classes (`## In`) — so their `writes:`
intersect whatever else is done and the lane queues them. Given a queue, `after: Task 1, Task 2`
on Task 3 makes the order deterministic rather than arbitrary: the doctor row is read-only and
lands first, so the operator can *see* which install ticks before the upgrade changes what
installs, and Task 3's coder rebases onto a tree whose test module already has three classes
instead of resolving a conflict in it. Putting `asf/upgrade.py` last also gives F-0207 — in flight
over that exact file — the most room (PD15).

**Read PD1, PD3, PD4, PD5 and PD8 before writing a line.** Each is a place where following the
spec's design literally ships something that does not work, cannot be filled in, or fails a gate
the spec itself lists in §F: `record_last`'s `venvs` has no source (PD1), the row text the spec
prints is a forbidden token in `asf/**/*.py` (PD3), `drift.trunk_head` cannot answer for
`factory_root()` (PD4), `venv_commit` returns no sha for the one kind this card exists for (PD5),
and the reader reaches the operator's real `~/Library/LaunchAgents` from inside three test suites
(PD8).

The fences of §*The fences, and the suite* bind every Task, so every Gate and Acceptance block
below carries them beside its own.

| PD1 | **`record_last`'s new `venvs` key has no source: `_install` knows which venvs it moved and `record_last` is called by someone else** | The spec's §5 writes `venvs` as `{venv: sha}`, "every venv this call moved", and its §4 puts the loop that moves them inside `_install`. Measured: `_install(ref, run, out, pin=None)` (`asf/upgrade.py:592`) returns an **int rc** and never records anything; `record_last(ref)` is called by its caller, `install()`, at `asf/upgrade.py:585-586` — `rc = _install(…)` then `if rc == 0: record_last(ref)`. So the venv map is computed in one function and needed in another, with an `int` between them. `grep -rn '_install(' asf/ tests/` finds **no other caller** — `tests/test_clocks.py`'s `_install` is its own unrelated helper method. **Decided:** `_install` grows a fifth keyword, `moved=None`, a caller-supplied list it appends `(venv, sha)` to as each venv verifies; `install()` passes a fresh list and calls `record_last(ref, venvs=dict(moved))`. The **return shape does not change**, so `install()`'s own contract, its `DEFERRED`/`rc` paths and every existing test of it hold unread. A returned tuple would have been the other way and is rejected for exactly that: `rc = _install(…)` at `:584-585` is two call sites in one line and both would have to move. |
| PD2 | **The `rollback:` line cannot be printed where the spec puts it without reading the record back, and must not print on `--skip-pipx`** | The spec's §5 says `cmd_upgrade` prints `rollback: asf upgrade --to <previous>` "after a successful install", and §E asks for it "exactly once after a successful install and not at all after a deferral". Measured: `cmd_upgrade` (`asf/upgrade.py:656-666`) never sees a sha — it calls `install(…)`, and `previous` only comes into existence inside `record_last`, two frames down. **Decided:** the line is printed **inside** `cmd_upgrade`'s `if not args.skip_pipx:` block, immediately after the `if rc != 0: return rc` guard, from `(read_last() or {}).get('previous')`, and omitted when that is absent or empty. The placement does all three jobs at once: `DEFERRED` and every non-zero rc return before it (so no deferral prints it), `--skip-pipx` never enters the block (so a schema-table-only run prints no rollback for an install it did not make), and it prints once per run because there is one such block. Do **not** print it from `install()` or `_install()` — `install()` is called by the tick's auto-upgrade (`asf/tick/tick.py:404-406`) through `cmd_upgrade` as well, and a second print site is a second answer. |

| PD4 | **`trunk()` cannot reach `drift.trunk_head` for the `factory_root()` half — that function takes a Product, and `factory_root()` returns a path** | The spec's §2 says `trunk()` is "`drift.factory_root()` first (the running package's own tree), else the first configured product whose `repo_dir` is the factory's source (`drift.is_factory_source`)", and that the ref is read locally. | PD5 | **`venv_commit` as specified returns no sha for an `editable` install — the one kind this card exists for — because PEP 610 gives an editable install no `vcs_info`** | The spec's §1 says `venv_commit` reads *"`vcs_info.commit_id` and `dir_info.editable`"* from one `direct_url.json`, and its §3 then prints `editable asf-factory @ 3f2a1c9 (<checkout>)` — a sha and a checkout path. Those two cannot both come from that file as read: PEP 610 makes `dir_info` and `vcs_info` mutually exclusive, so a local-directory install (what `pipx install --editable <checkout>` is) records `{"url": "file:///…", "dir_info": {"editable": true}}` and **no `commit_id` at all**. Read as specified, the editable row prints an empty sha and an empty checkout. The codebase already solved the same problem the same way: `cli._source_commit(root, direct_url)` (`asf/cli.py:108-116`) takes *"a checkout's own HEAD, else a pipx git install's `direct_url.json` (`vcs_info.commit_id`)"* — the checkout **first**. **Decided:** `venv_commit(venv_dir)` returns **`(sha, editable, repo)`**, three values: for a pinned install `(vcs_info.commit_id, False, '')`; for an editable one `(<the HEAD of the tree at `url`>, True, <that tree>)`, the path taken off the `file://` URL and the sha through `snapshot.head_sha`, which already raises `SnapshotError` rather than returning junk (`asf/snapshot.py:81-87`). `('', False, '')` when the file, the dist or the tree is not there. `ClockInstall.repo` then carries the editable checkout as well as the snapshot/checkout one, which is what §3's `(<checkout>)` prints, and R3's merged test gets a real sha to measure for an editable clock instead of silently skipping it. This is the one place the reader shells git per venv; it is at most one call per **editable** venv and the memo of §2 does not cover it, so say so in the docstring. |

**Steps**

1. `upgrade_command(url, ref, suffix='')` → `['pipx', 'install', '--force'] + ([f'--suffix={suffix}']
   if suffix else []) + [f'git+{url}@{ref}']`. The default keeps `tests/test_install.py:562-564`'s
   pinned two-argument assertion true unread, which matters while F-0207 is in flight over this
   file (PD15). `--suffix=<s>` is **one** argv entry and the `=` is not a style choice: the
   two-argv form fails to parse for any suffix beginning with `-` (**PD11**). Say so in a comment
   with the reason, or the next reader will "tidy" it.
2. `repo_url(run=subprocess.run, venv=PACKAGE_NAME)`: the only change is that the
   `['venvs'][PACKAGE_NAME]` lookup becomes `['venvs'][venv]`. Default unchanged, so every existing
   caller and `FakeRun`'s `('pipx','list')` answer (which carries only `asf-factory`) keep working;
   a venv `pipx list` does not know falls through the existing `KeyError` guard to
   `ASF_REPO_URL`/`DEFAULT_REPO_URL`, which is the right answer for a venv this host cannot
   describe.
3. `new_install_commit(run=subprocess.run, venv=PACKAGE_NAME)`: `os.path.join(venvs, venv, 'bin',
   'python')` instead of `PACKAGE_NAME`, and — per C14 — `clockinstall.venv_commit(<venvs>/<venv>)[0]`
   as the **fallback** when the spawn answers nothing, so the two readers can never disagree
   silently. The spawn stays first and stays exactly as it is: it must read what an *import*
   resolves immediately after `pipx install --force` in this same process (P2), and
   `FakeRun` pins that `(<venvs>/asf-factory/bin/python, -c)` pair by name.
4. `targets(cfg=None, run=subprocess.run)` → `([(venv, suffix)], [ClockInstall])`, the spec's §4
   docstring byte for byte. `from asf import clockinstall` **in the body** (**PD10**). For each

   in label order, then `(PACKAGE_NAME, '')` for the venv this process runs from; deduplicated on
   the venv name, order preserved. An `editable` clock venv is **never** a target (C11) and an
   install whose `venv` is `''` (snapshot, checkout, unknown) cannot be one. The second element is
   every clock whose install this upgrade will **not** move — every non-`pinned` clock, plus any
   `pinned` clock whose venv was dropped. Falls back to exactly `([(PACKAGE_NAME, '')], [])` when
   there is no plist to read, no `pipx`, or the config does not load: wrap the whole body so that
   `env.ConfigError` and an unexpected `OSError` both land there. Today's behaviour, exactly.
5. `_install(ref, run, out, pin=None, moved=None)` (**PD1**): after the CI guard, loop the spec's
   §4 snippet over `targets(run=run)[0]`, with `moved` a caller-supplied list the loop appends
   `(venv, ref)` to as each venv verifies:
   ```python
   for venv, suffix in venvs:
       url = repo_url(run, venv=venv)
       cmd = upgrade_command(url, pin or ref, suffix)
       out('upgrade: ' + ' '.join(cmd))
       rc = run(cmd).returncode
       if rc != 0:
           return rc                       # the line above names which venv
       got = new_install_commit(run, venv=venv)
       if not got or not (got.startswith(ref) or ref.startswith(got)):
           out(f'upgrade: FAILED — {venv} is at {(got or "unknown")[:7]}, not {ref[:7]}')
           return 1
       if moved is not None:
           moved.append((venv, ref))
       out(f'upgrade: installed {ref[:7]} in {venv}')
   ```

   swaps files under it — the hazard `install()`'s own docstring already names — and the install

   the first `run(cmd)` (`:604-607`, *"pipx is not on PATH"*) stays and keeps its wording; keep it
   outside the loop or repeat it — a missing `pipx` is the same answer for every venv.
