# Plan F-0206 — the rule pure, then the one branch in the pass

Epic: E-0001 — ASF 0.1 — a working factory. Spec: `docs/specs/f-0206.md` (approved). Branch:
`plan/F-0206`.

Two Tasks, a strict chain. The spec's shape is a pure rule and one call site, and the rule is
worth landing on its own because it is the half that can be argued about without running a
factory:

1. **`asf/workers/lifecycle.py`, the rule** — `unknown_account`, `superseded`, `orphan_end`,
   the two rule constants, `_age_minutes`, and `superseded_by` in `RUN_FIELDS`. Nothing calls it
   when this lands; no health pass behaves differently by one byte.
2. **`asf/workers/health.py`, the one branch where the row is stuck** — behind `judge`'s `None`,
   with this host's account names, the product's silent bound and the run pass's own
   `RemoteHeads`. **This is the Task that ends the card's row**, and the two docs pages that
   answer "what `ended` line does this run get?" gain the second route with it.

Wave order: **1 → 2**, one Task per wave. Their `writes:` are disjoint, so the queue is the
`after:` chain and nothing else.

Five things measured here that the spec does not have right, all of them in the four lines of new
code the spec writes out:

* **PD2** — `lifecycle._age_minutes` does not exist, and lifecycle may not import the module that
  has the same computation (`stall` imports `health` imports `lifecycle`).
* **PD3** — the spec's `unknown_account` reads an **empty** account list as "everything is
  unknown". On this repo's own test fixture, and on any host whose config will not parse,
  `accounts_from_config` returns `[]`: the rule would arm itself against every live row the
  factory has. This is the one change that must not ship as written.
* **PD5** — the detail string is **load-bearing, not cosmetic**: `asf/tick/step_health.py:61`
  selects the jobs it sends to `handle_dead` on `detail == 'dead pid'` exactly. If the orphan's
  line were tidied to that string, the next tick would launch a cold retry in a worktree this
  host does not have, and hold another launcher's item when it failed.
* **PD6/PD7** — C10's hoisted `RemoteHeads` gives the *worktree* pass a pre-publish snapshot, and
  the spec's own snippet asks `ls-remote` for every live row, which is what C10 says it must not
  do.
* **PD8** — P12 is wrong: `superseded_by` is already two other things in this tree, one of them
  read in the very module that gains the field.

### Task 1: an unknown account and what moved past it, as one pure rule nothing calls yet
stories: S-37050, S-37051
writes: asf/workers/lifecycle.py, tests/test_lifecycle.py
after: none

The spec's §1 — `SUPERSEDED_SESSION`, `SUPERSEDED_BRANCH`, `unknown_account`, `superseded`,
`orphan_end`, the private `_age_minutes` PD2 adds, and `superseded_by` in `RUN_FIELDS`. No caller
exists when this lands.

**Read PD3 before writing `unknown_account`**: an empty account list means *the question was not
asked*, not *every row is a stranger's*, and the difference is every live session on a host whose
config will not parse. **Read PD2 before writing the age floor**: the helper the design calls does
not exist, and the module that has it cannot be imported from here.

**What changes for the machine when this lands.** Nothing. No pass calls these four functions; the
only reachable change is one more name in `RUN_FIELDS`, which drops a `superseded_by: null` on the
fold and stops a field no writer writes from crossing a relaunch.

**Files**

- `asf/workers/lifecycle.py` — `import calendar` at the top of the stdlib block; `superseded_by`
  appended to `RUN_FIELDS` (`:108-110`); the two rule constants with their `#:` comment; `_age_minutes`;
  `unknown_account`; `superseded`; `orphan_end`. All four functions go beside the other
  no-git judgements, under the `# ---- the recorded transition, and the questions that need no git`
  banner, after `is_live` (`:574`) — `orphan_end` reads `is_live` and `item_runs` and belongs with
  them. The module docstring gains the rule. `judge`, `liveness`, `reap_verdict` and every other
  function are untouched.
- `tests/test_lifecycle.py` — `OrphanRuleTests(unittest.TestCase)` added, on the module's existing
  temp-registry idiom (`SameHeadLoopGuard`, `:1173-1180`: a `tempfile.mkdtemp`, a `s.jsonl`, a
  `write(*lines)` that appends json). No existing class is touched.

**Steps**

1. `superseded_by` is appended to `RUN_FIELDS` (P9), and the `#:` comment above the tuple is left
   as it is — the new entry's own words go on the constants below. `pool.RUN_FIELDS` is an alias
   (`asf/workers/pool.py:231-233`) and needs no edit.
2. `SUPERSEDED_SESSION = 'session'` and `SUPERSEDED_BRANCH = 'branch'`, with the spec's `#:`
   comment verbatim — a live row this host cannot answer for is ended by what moved past it, never
   by a liveness verdict; the pid is a number on another machine, the log a path this disk does not
   have, and `liveness` is deliberately generous with a process it cannot place (F-0234). Add
   PD8's sentence to it: `superseded_by` here is the **session row's** field, not the card key
   `asf.groom` writes on a superseded card and not the REPORT trailer a ruling may claim
   (`asf.workers.report`, read in `overruling`).
3. `_age_minutes(run, now)` (PD2): `calendar.timegm(time.strptime(str(at), '%Y-%m-%dT%H:%M:%SZ'))`
   over `run['started']` and `now`, `None` when either does not parse or `started` is missing,
   otherwise `int((at - began) / 60)`. `now` is the iso string the caller already holds — no
   second grammar, no float seconds path (the callers in this module all carry iso). The docstring
   names `asf.workers.stall.elapsed_min` as the same computation in a module this one may not
   import, and says why (the import cycle), so the next reader does not "de-duplicate" it into an
   `ImportError`.
4. `unknown_account(run, accounts)` — the spec's body with PD3's guard as the **first** line:
   `if not accounts: return False`. Then `(run or {}).get('account') not in set(accounts)`, so a
   run that records no account at all is unknown (a launcher that wrote none is not this host's).
   The docstring carries both halves: what the list is (`pool.accounts_from_config`'s names, this
   host's `worker_pool`), and that an empty or absent list is *"the question was not asked"* — a
   host that configures no accounts cannot know whose a row is, and `load_cfg` answers `{}` for a
   config it cannot parse (`asf/workers/spawn.py:982-986`). Write that reason into the docstring,
   not only the code: it is the line a later reader is most likely to simplify away.
5. `superseded(path, run, head=None)` exactly as the spec's design has it, in the spec's order —
   the session rule over `item_runs(path, item)` first (a different `job`, `started` no earlier,
   `item_runs` so a run before the item's newest reset is not the item's), then the branch rule
   (`launch_head` recorded, `head is not None`, `head != launched`, `''` a different sha). Returns
   `(rule, by)` or None. Two things go in the docstring because they are the rule's edges and not
   its body: why the session rule is first (P6 — a first launch on a branch origin did not hold
   records no `launch_head`, so the branch rule answers for no first launch), and that `head` None
   means origin was not asked.
6. `orphan_end(path, run, accounts, head=None, now=None, min_age_min=None)` as the spec's design
   has it: `is_live` and `unknown_account` first, then `now = now or now_iso_utc()`, then the floor
   (`min_age_min is not None` and `_age_minutes(...)` below it → None; an unreadable age is **not**
   below the floor and does not block the rule — a row with no usable `started` is judged on the
   other three facts), then `superseded`. The detail is the spec's two sentences byte for byte:
   `f'{DEAD_PID}, superseded by {by}'`, and for the branch rule
   `f'{DEAD_PID}, its branch moved past {by[:9] or "no head on origin"}'`. The fields are
   `{'ended': now, 'end_reason': DEAD_PID, 'superseded_by': {'rule': rule, 'by': by, 'at': now}}`.
   The docstring says the three facts and the one floor, and — PD5 — that the detail always carries
   its clause: the ended row is deliberately not one `asf.tick.step_health.dead_jobs` selects, so no
   cold retry is aimed at a worktree on another machine.
7. The module docstring gains one short paragraph where it describes the ended line: a live row
   whose account this host does not configure is ended by evidence that is true on every host — the
   item has a newer session, or the branch moved past the head the launch handed it — never by a
   liveness verdict, because every input to one is about another machine's process.
8. `OrphanRuleTests`, the spec's bullets one test each, over hand-built registry lines:
   - `unknown_account`: true for a name the list does not carry, true for a run with no `account`
     key at all, false for one it carries; false for every run when `accounts` is `None` **and**
     when it is `[]` (PD3 — both, and the `[]` case asserted for a run whose account name is
     plainly not a member, so the test fails if the guard is dropped);
   - `superseded`, the session rule: finds a newer run of the item under another job and names its
     job; ignores the row's own job; ignores a run of another item; ignores one started strictly
     earlier; ignores a run before the item's newest reset (P5 — write a reset line, the idiom
     `lifecycle.is_reset` reads, and assert the pre-reset run does not supersede);
   - `superseded`, the branch rule, all five: fires when `head != launch_head`, fires when `head`
     is `''`, does not fire when they are equal, does not fire when `head` is None, does not fire
     at all for a run with no `launch_head` (P6) — and, with both facts available, the session rule
