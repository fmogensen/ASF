# Plan F-0337 — the fourth stage, cut so that the knob is the last thing to land

Epic: E-0002 — ASF 0.2 — self-improvement. Spec: `docs/specs/f-0337.md` (approved on
`origin/spec/F-0337` at `899acc6181`, not yet on the trunk). Branch: `plan/F-0337`.

Five Tasks, **one per Story, one per seam**, in the spec's own division (`## Stories`: "one per seam
the design has"):

1. **the queue** — `asf/kernel/sweep.py`'s skeleton: the kind, the classes, `age_days`,
   `parked_by` and `candidates`, with the two `Item` fields and the six `Config` knobs the queue
   reads. Pure, and provable with nothing but builders.
2. **the seats** — `sweep.plan`, the three lines of `decide` and `Plan.sweep`. After this the
   kernel can plan a sweep; nothing can turn it on.
3. **the verdict and the brief** — `sweep.parse_verdict` over `dor`'s grammar (made public), the
   `groom-sweep` brief, and the kind in `NO_LANDING_KINDS`.
4. **the applier** — `apply.groom_sweep`, the launch's budget line, the two machine keys and the
   one new record writer, `unpark`.
5. **the knobs and the view** — the `groom:` section, its six `config_for` lines, the product
   file's block, the parked-age histogram in `asf kernel waits` and the tick's `sweep:` line.

They run **1 → 2 → 3 → 4 → 5**, one at a time. Four of the five write `asf/kernel/sweep.py` and
all five write `tests/kernel/test_sweep.py` — the spec's `## In` binds both to one module each
("one new module `tests/kernel/test_sweep.py` (five classes, one per Story)") — so the queue
serialises them whatever their `after:` lines say. The `after:` lines below name only the landed
code each Task genuinely needs, and the one place that ordering is a *safety* requirement rather
than a convenience is **Task 5, which is `after: Task 4` because it is the Task that makes the
stage reachable at all** (PD7).

**Read PD2, PD3, PD4 and PD5 before writing a line of Task 1.** The spec's design is sound and
every one of its preconditions still holds — re-measured here, all of them — but four of its
snippets are incomplete in ways that are silent rather than loud: an exclusion whose test cannot be
`unready` membership (PD2), an acceptance line that is not implementable as written (PD3), three
brief fields that cannot be computed where the brief is built (PD4), and a snippet that must now
sit below a block the trunk grew after the spec was measured (PD5). None of them changes the
design. All four become a session debugging the kernel on the trunk if they are met for the first
time while coding.
