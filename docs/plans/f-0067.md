# Plan F-0067 — every ephemeral thing has an owner, a row and a last day

Epic: E-0001 — ASF 0.1 — a working factory. Spec: `docs/specs/f-0067.md` (approved). Branch: `plan/F-0067`.

Five Tasks. Task 1 is the one file with no dependency at all — `conventions.py`'s `floor:` map,
beside `branch_retention`. Task 2 is the leaf: the whole of `asf/floor.py` — the registry, the
judgement, all eight probes, the six safe classes' removers (each an existing owner's function),
the hold branch (§2.4, which is a function *inside* `floor.py` reading a constant `floor.py`
imports from `retention.py`) and the tooling class — plus the two other files the hold branch
touches, `asf/workers/retention.py` (`HOLD_PREFIX`) and `asf/workers/worktrees.py` (`safety`'s
matching read). Tasks 3, 4 and 5 are the three callers of the finished leaf, each its own module,
each writing a disjoint set of files: the doctor row, the groom section, and the wiring (the tick
step, `cmd_health`, the `asf floor` command).

Task 1 writes disjoint files from every other Task and starts alone. Task 2 needs Task 1 landed —
`judge` reads the TTL through `conv.floor_ttl_s`/`conv.retention`, which does not exist before
Task 1. Tasks 3, 4 and 5 each need Task 2 landed (the `floor.json` shape, `floor.groom_lines`,
`floor.sweep`) and none needs another: `asf/doctor.py`, `asf/groom/groom.py` and
`asf/tick/step_health.py` + `asf/workers/__init__.py` + `asf/cli.py` share no file, so the three
run together.

Wave order: **1 → 2 → 3 ‖ 4 ‖ 5**.

§3's rule that the whole suite stays green binds every Task, so every Gate below runs
`python3 tools/run_tests.py`. `asf/floor.py` is a **new** module, so Task 2's Gate — the only Task
that creates it — also runs the two whole-tree fences the spec's §1.1 states as preconditions: the
one-classifier AST fence (`tests.test_lifecycle.OneClassifierTest`) and `check_conventions.sh`
(`tests.test_conventions.CheckConventionsScriptTests`, `ForbiddenPatternsTests`), plus
`asf plugin check` (§1.1's third fence: `floor` is neither a view nor a dialogue, so
`plugin_build.skill_names()` does not change — verified against `asf/plugin_build.py:34,38`,
neither tuple names `floor`). Tasks 1, 3, 4 and 5 touch no new module and no path-shaped literal,
so their own Gate is the suite alone; S-32759's acceptance is proven once, at Task 2.

## Decisions

| # | Question | Decided |
|---|---|---|
| PD1 | How the work is cut | By the module that owns the surface, same rule `docs/plans/f-0066.md` used: the leaf (`asf/floor.py`, all of §2.1–§2.4 and §2.6), its one dependency (`asf/conventions.py`, §2.2), and the three independent callers (`asf/doctor.py` §2.5, `asf/groom/groom.py` §2.7, the tick + CLI wiring §2.8). |
| PD2 | Task card ids | Not minted here. `asf.record.plan_tasks.mint_plan_tasks` turns each `### Task N:` heading of the landed plan into a card with an id from `asf.record.ids.mint_id` once the Feature's own lane PR lands this plan (`asf/record/plan_tasks.py:62-125`), and then writes each card's `after:` through `asf.record.plan_order.backfill`. This plan's headings are therefore the parser's ordinals `1…5`; no id is invented here. |
| PD3 | Which Story is which | The spec's `## Stories` bullets are bare `- S:`; the ids live only in its frontmatter (`stories: [S-32750 … S-32759]`, ten ids, one per bullet). The mapping is positional, first bullet to first id: S-32750 the registry, S-32751 `conventions.floor`, S-32752 the probes, S-32753 the sweep, S-32754 the hold branch, S-32755 the doctor row, S-32756 the groom section, S-32757 the tooling class, S-32758 the wiring, S-32759 the fences. |
| PD4 | **Why `asf/floor.py` is one Task and not five** | The registry (§2.1), the judgement (§2.3), the eight probes (§2.1's table) and the hold branch (§2.4) all live in the one new module and its one test file (`tests/test_floor.py`), and T1's own acceptance (`floor.CLASSES` has eight entries, checked at import) cannot be proven with only some of the probes written — a `Klass` with `safe=True` and no `remove` is a `FloorError` by construction (§2.1), so a partial `CLASSES` table fails its own registry test, not just an unwritten one. Splitting by class (`worktree` vs `tooling` vs `hold-branch`) would put every split Task on the same file with the same test module and no way to land one without the others compiling — the T-0317 ruling's shape (`origin/plan/F-0067`'s own sibling case, commit `111165f56`): a thing that does not split is one Task whole, not five that would only relearn the coupling the spec already named (§1.4: "One registry of classes … that needs one table something can iterate"). |
| PD5 | The hold branch's two satellite files ride with the leaf, not with the wiring Task | `worktrees.safety`'s new read (§2.4, the matching `hold/<job>` lookup at both `unpushed commit(s)` exits) and `retention.py`'s `HOLD_PREFIX` (§1.4: "beside `ARCHIVE_PREFIX`") are both read *by* `floor.hold()` and *by* `floor.py`'s own `hold-branch` probe (which lists `hold/*` heads via `retention.tip_dates`) before either is exercised by anything else. Verified against the checkout: `worktrees.safety(path, branch, main, heads, run=None, fetch=False)` (`asf/workers/worktrees.py:129`) already threads `heads` — the map `plan()` fetches once (`:204`) — through to every exit, so the new read costs no extra call, exactly as §2.4 states; and `retention.owned_patterns` (`:125-134`) already composes `ARCHIVE_PREFIX` the same way `HOLD_PREFIX` joins it. Neither file gains a caller until Task 2's own tests exercise them, so carrying them on Task 2 adds no risk a later Task would have carried instead. |
| PD6 | Task 2's Gate proves S-32759 for the whole plan | `asf/floor.py` is the only new module any Task creates; Tasks 1, 3, 4 and 5 each add functions to an existing module. So the two whole-tree fences (§1.1) are asserted once, in Task 2's own Gate, over the tree with the new module in it — proving them again in Tasks 3–5 would check a fact those Tasks cannot change. |
| PD7 | The tooling class touches no repo file | `tool_dirs:` lives in the operator's own `~/.ASF/config.yaml` (`asf/env.py:260,267`, `spawn.load_cfg` at `asf/workers/spawn.py:770`), which this branch never writes — §1.2 lists it as an "in" item because the probe *reads* the key, not because a file in this repo defines it. Task 2's tooling probe reads `spawn_mod.load_cfg().get('tool_dirs') or []`, each entry `os.path.expanduser`-ed, exactly as `spawn.py` already expands operator paths elsewhere (`:604,703-705`). Nothing is written to the sample product or any yaml for this class. |
| PD8 | **The `stories:` lines below read back as empty, and this is not this plan's defect** | `asf.record.plan_tasks.STORY_ID_RE` is `\bS-\d{4}\b` (`asf/record/plan_tasks.py:29`) — four digits, anchored on both sides — and the spec's ids are five (`S-32750 … S-32759`): `STORY_ID_RE.findall('S-32750')` is `[]`, verified against the checkout. Every Task card minted from this plan will therefore carry no `stories:` field however this plan writes the line, exactly as `docs/plans/f-0062.md`, `f-0063.md`, `f-0102.md` and a dozen others already recorded for the same reason at this same head. Not fixed here: the id grammar is a record-wide change, not this Feature's footprint. The `stories:` lines below are the plan's own coverage statement, read against the spec's positional mapping (PD3). |
