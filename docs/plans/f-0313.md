# Plan F-0313 — the recovery, in five pieces: a text, a filing, a cap, a line, and the harvest that calls them

Epic: E-0001 — ASF 0.1 — a working factory. Spec: `docs/specs/f-0313.md` (approved). Branch:
`plan/F-0313`.

Five Tasks, one per section of the spec's `## The design` and one per Story, cut along the spec's
own file boundaries — which are already disjoint, so nothing queues on a shared footprint. What
orders them is four real edges, and the one departure this plan makes from the spec's reading
order is to put the **cap** before the **harvest** (**PD1**), so that the card's fourth acceptance
— "a test builds a review worktree whose gitdir is missing, runs the harvest, and asserts a review
entry exists or a relaunch is queued, **and the row is not parked**" — is assertable end to end in
the one test the spec names for it, instead of split across two Tasks that land a wave apart.

* **Task 1** — the text: `review.recovered_review` and `review.RECOVERED`, a finished session's
  REPORT verdict as a review text that reads the same under every `verdict_block` setting
  (S-84455).
* **Task 2** — the cap and the reader: `relaunch.UNFILED_FREE`, `counted`'s third exclusion, the
  claim swap in `_assess`, `review_unfiled` in `lifecycle.RUN_FIELDS`, and
  `lifecycle.unfiled_review` (S-84458).
* **Task 3** — the filing: `review_store.recover`, with a head of its own chosen by a stated
  order, beside the `take` whose refusal it answers (S-84456).
* **Task 4** — the line: the clause inside `lane.review_reason` and the one fact `branch_facts`
  reads for it (S-84459).
* **Task 5** — the harvest: `health.recover_review`, called from inside `file_review`'s existing
  `except (OSError, ValueError, subprocess.SubprocessError)` — the clause is never narrowed to
  `NotACheckout`, which is itself a `ValueError` (`review_store.py:142`) and so already lands
  there — the defect's own line, and the Task that binds the other four together (S-84457).

Wave order: **{1, 2} → {3, 4} → {5}**.

Three waves, two Tasks wide at the top. Task 1 and Task 2 share nothing — the text builder knows
nothing of the cap, and the cap reads a field by name, not by import — so both start at once
(`after: none`). Task 3 calls Task 1's builder and Task 4 calls Task 2's reader, so each declares
the one edge it has and they run together in wave 2. Task 5 is last because it calls Task 3's
`recover` and needs Task 2's exemption landed to assert the unparked row.

Every `writes:` set is disjoint from every other, so the record never serialises two of these on a
shared path: the ordering above is entirely `after:`, which is the honest shape of this change —
a text, a filing and a cap, then one caller that uses all three.

## Tasks

### Task 1: the text — a finished session's REPORT verdict, as a review every reader reads alike
stories: S-84455
writes: asf/evidence/review.py, tests/test_review_reader.py
after: none

The spec's design §1 and its In row 4 (D5; P10, P11). One pure text builder beside the block
reader it calls: a finished review session's REPORT carries its verdict and nothing else, and this
turns that into a review text the store can file and every reader can read. It touches no git, no
store and no registry — given a string it returns a string.

The three statements of one verdict are the whole point and must not be trimmed to one: at
`verdict_block: off` (the default, `review.block_mode`, `:119`) `verdict_of` asks the **check
table** first, and a recovered review has no table, so `reviews.verdict` returns `''` and the
`verdict:` line at `review.py:264-271` is what answers; past `off` the block answers; and
`head_of` (`:287-298`) reads a `head:` **line** unless `block` is set. P11 measured all three
agreeing on one text that carries all three.

**Files**

- `asf/evidence/review.py` — `RECOVERED = 'Recovered verdict'` and
  `recovered_review(report, head, item='', n=0, source='the session REPORT')` added beside
  `verdict_block` (`:149`) and `block_problem` (`:194`), with the spec's docstring verbatim.
  Returns `''` when `verdict_block(report)` is `None` — a report with no block, or one whose
  `verdict` is not exactly `approved`/`changes` or whose `head` is not a sha, both of which
  `verdict_block` already rejects (`:163-165`). No existing function changes: `verdict_of`,
  `head_of`, `asks_nothing`, `worktree_review` (`:205-225`) and `verdict_block` are read by the
  new builder and not edited.
- `tests/test_review_reader.py` — `RecoveredFromAReport` added beside `VerdictBlock` (`:330`),
  which already carries the fenced-block fixtures this needs (PD9). The module's other ten classes
  are untouched.

**Steps**

1. Add `RECOVERED`, then `recovered_review`. Call `verdict_block(report)`; `return ''` on `None`.
   Build the text from the `Verdict` it returns: an `# {RECOVERED} — {item} review round {n}`
   heading, a provenance paragraph naming `source` and F-0313, then the three keys —
   `verdict: <kind>`, `head: <head>`, `asks: none` or the block's asks — then the block itself,
   verbatim, in a fenced ````verdict```` block. The spec's `## The design` §1 shows the exact
   shape; reproduce it.
2. The `head:` line carries the **caller's** `head`, not the block's. They are the same sha in the
   measured case (P2), but the caller is the one that resolved it against the repo (Task 3's D3
   order), and S-84455's last acceptance line asserts precisely this: "the head the text is bound
   to is the one the caller passed, not one the report mentions elsewhere".
3. Carry the block's `asks` into the text as list items, so a correction brief built from a
   recovered `changes` review has something to name. `verdict_block` already reads an `approved`
   block that still asks as `CHANGES` (`:166-167`), so a `changes` text and an asking-`approved`
   text are the same text here.
4. Write no check table and no `read as the customer` row — the spec's `## Out` forbids both, and
   `lane.incomplete` (`:1442-1448`) is *supposed* to read a customer-touching diff's recovered
