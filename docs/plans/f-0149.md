# Plan F-0149 — the ladder and the share it leaves, one cause per failing step, and a lead time that is not measured

Epic: E-0001 — ASF 0.1 — a working factory. Spec: `docs/specs/f-0149.md` (approved). Branch: `plan/F-0149`.

Three Tasks, cut exactly the way the spec's `## Stories` are cut: the **attribution ladder** and the
unattributed share it reports (`score.feature_of_session`, `rank`'s `by_feature`, one view row), the
**CI regrouping** (`diagnose.ci_causes`, `causes`, `metric`'s two branches, one view row), and the
**migrated lead time** (`facts.MIGRATED_RE`, `score.lead_days`, the lead-time cause's gate).

They run **1 → 2 → 3**, one at a time, because D13 already said so and the footprints confirm it:
all three write `asf/scorecard/diagnose.py` and `tests/test_scorecard.py`, and Tasks 1 and 3 both
write `asf/scorecard/score.py`. There is no cut of this card that yields two disjoint Tasks, so no
attempt is made to manufacture one — a serialised plan is the honest shape here.

§Acceptance tests' last four fences — `tests.test_scorecard tests.test_direct_lane`, the metrics
trio, and the whole-suite-plus-both-fences one — bind every Task, so every Gate and every Acceptance
block below carries them beside its own.

**The one thing every Task must know before it writes a line:** `tests/test_scorecard.py:538-542`
builds a **literal** `rank` dict and hands it to `view.render`. Task 1 adds a key `render` reads out
of that dict, and Task 2 adds another beside it. PD1 has the measurement. A coder who does not read
it lands a `KeyError` in a test class that has nothing to do with this card.

### Task 1: the ladder — a Bug under an Epic, a branch that names the card, and the share left over

writes: asf/scorecard/score.py, asf/scorecard/diagnose.py, asf/views/scorecard.py, tests/test_scorecard.py

The spec's first four **In** bullets and `## The design` §`asf/scorecard/score.py` (the ladder half
only — `lead_days` is Task 3) and §`asf/scorecard/diagnose.py` (the `by_feature` half only —

**Files**

**Steps**

1. `asf/scorecard/score.py`, directly after `attributed_bugs` (`:137`): `TEXT_ATTRIBUTED_TYPES =
   ('bug',)` with the spec's `#:` comment byte for byte. It is a constant and not a literal so that
   the next type that needs the rung is one edit with D3's reason attached to it.
2. `feature_named_by(items, iid)` with the spec's docstring and body byte for byte. Three things in
   it are load-bearing and must not be simplified away: the `type not in TEXT_ATTRIBUTED_TYPES or
   removed` guard is D3 (an Epic that mentions a Feature is not work spent on it); the
   `it['created'] < f['created']` skip is P4's guard read the other way, so an old Feature can never
   absorb a newer Bug's spend; and `max(named, key=lambda f: (items[f].get('created') or '', f))` is
   D2 — newest-carded wins, ties by id, never a split and never a first-named.
3. `feature_of_card(items, iid)` — one line, `feature_of(items, iid) or feature_named_by(items, iid)`.
4. `feature_of_session(items, ev)` with the spec's docstring byte for byte: the three rungs are named
   in it, in the order they are tried, and that docstring is the whole reason D1 made this a function

   `feature_of_card` on `ev.get('item')`, then each id of `ids_in(ev.get('branch') or '')` through
   the same `feature_of_card`, first answer wins, `None` otherwise.
5. `asf/scorecard/diagnose.py`: `UNATTRIBUTED = '(none)'` as a module constant with the spec's `#:`
   comment. The string keeps the value it has today — an operator reads that row beside real
   Features, and renaming it would move a row nobody asked to move.
6. `rank`'s `by_feature` accumulation (`:120-127`) becomes the spec's block: `feats, unplaced = {},
   {'usd': 0.0, 'sessions': 0}`; `fid = score.feature_of_session(facts.items, s)`; on `None`, `fid =
   UNATTRIBUTED` and the two counters move. The `feats.setdefault(...)` line and the three lines
   under it are **unchanged** — same keys, same rounding, same `repair` test. After the loop,
   `unplaced['usd'] = round(unplaced['usd'], 2)` and `unplaced['share'] = round(unplaced['usd'] /
   usd, 3) if usd else 0.0` — the `if usd` is the empty-window case the fence names, and there is no
   other division in the block.
7. `rank`'s returned dict gains `'unattributed': unplaced`. Every existing key keeps its name, its
   shape and its position in the dict; `by_ci_job`, `by_kind` and `by_failure` are not read or
   written by this Task.
8. `asf/views/scorecard.py`: one row appended to the four `| By |` rows (`:104-109`), with the spec's
   expression byte for byte — `_m(...)`, the share as `{… * 100:.0f} %`, the session count, and the
   trailing clause *"no Feature from the card, its text or the branch"*; `'none'` when
   `rk['unattributed']['sessions']` is falsy. It goes **under** the four, so the existing rows keep
   their order. The row names no product, no account and no path (`check_generic.sh` is in the Gate).
9. **PD1** — in the same edit, `tests/test_scorecard.py:541-542`'s literal `rank` dict gains

10. `SessionAttributionTests(unittest.TestCase)` in `tests/test_scorecard.py`, over hand-built

### Task 2: one broken shared step is one cause, one card and one verification
stories: S-35651
writes: asf/scorecard/diagnose.py, asf/views/scorecard.py, tests/test_scorecard.py
after: Task 1

The spec's fifth, sixth and seventh **In** bullets, `## The design` §`asf/scorecard/diagnose.py`'s CI
half, and the second row of §`asf/views/scorecard.py`. Thirteen inbox cards for one root cause become
one. It waits on Task 1 because both write `asf/scorecard/diagnose.py` and `tests/test_scorecard.py`,
and because Task 1's `render` row lands in the same table this Task adds its second row to.

The whole difficulty of this Task is what must **not** change: a `ci-job:` cause already filed in
somebody's record keeps its key, its title, its marker and the number it is verified against (D8,
P12). Read PD4, PD6 and PD8 before writing `metric`.

**Files**

- `asf/scorecard/diagnose.py` — `CI_STEP`; `ci_causes(facts, start, end)` beside `_sig_class`
  (`:62-65`); `causes`' CI loop (`:197-204`); `metric`'s CI dispatch (`:157-161`)
- `asf/views/scorecard.py` — `compute`'s `'ci_causes'` key (`:50`); one row in `render`'s table
- `tests/test_scorecard.py` — `CiCauseTests`; the hand-built `d` at `:538-542` (PD1)

**Steps**

1. `CI_STEP = 'ci-step:'` as a module constant with the spec's `#:` comment byte for byte — it states
   D7 (a red job with no step named keeps its per-job key) and that a gate was already grouped.
2. `ci_causes(facts, start, end)` with the spec's docstring byte for byte, placed beside `_sig_class`
   which it reuses. Its body, exactly as `## The design` states it:
   - for each `metrics/ci` event in the window (`score.in_window(run.get('ts'), start, end)`, and the
     `isinstance(j, dict)` guard `rank` already uses at `:101-102`), for each job whose `conclusion`
     is outside `('success', 'skipped', 'neutral', 'cancelled')` — the **same** four-name green list
     `rank` uses, not a new one: key on `CI_STEP + _sig_class(j['failed_step'])` when `failed_step`
     is a **non-empty string**, else on `f"ci-job:{name}"` (D7);
   - add the job's `score._num(j.get('minutes'))`, count one `red`, record the job's `name`;
   - for each gate in the window whose `conclusion != 'success'`, key on
     `f"gate:{_sig_class(g.get('signature'))}"` and add `score._num(g.get('seconds')) / 60`;
   - each row is `{'name', 'red', 'minutes', 'jobs', 'scope'}` with `jobs` the **distinct** names

   **rate** stay in `rank`'s `by_ci_job`, which this Task does not touch at all.
3. `causes` (`:197-204`): `for c in r['by_ci_job']:` becomes `for c in ci_causes(facts, start, end):`,

   whole point of the regrouping. The `Cause`'s **key, scope, value, threshold, unit and title are

4. `metric` (`:157-161`): the one branch becomes two, in the spec's order — `key.startswith((CI_STEP,

5. `asf/views/scorecard.py`: `compute` gains `'ci_causes': diagnose.ci_causes(facts, start, end)`

6. `render` gains the `| CI red cause |` row with the spec's expression byte for byte, under Task 1's

   and after this change they are the only place that per-job denominator appears.
7. **PD1** — the hand-built `d` at `tests/test_scorecard.py:538-542` gains `'ci_causes': []` beside
   `'rank'`.
8. `CiCauseTests(unittest.TestCase)`, over its own `ci`/`gates` events (PD3: do **not** add a
   `failed_step` to the shared `facts_fixture`). One case per clause of the third fence:
   - **five jobs failing on one step yield exactly one cause** — the card's second acceptance, and

   - a red gate is still one `gate:<class>` cause, and a **green** gate and a green job make no row;

### Task 3: the day the factory adopted a card is not the day it was asked for

stops being a number that is always too small and always in the same direction. It waits on Tasks 1
and 2 because it writes `asf/scorecard/diagnose.py` and `tests/test_scorecard.py` too, and on Task 1
