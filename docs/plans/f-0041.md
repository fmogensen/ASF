# Plan F-0041 — the footprint decides the size, and a small Task rides a train

Epic: E-0001 — ASF 0.1 — a working factory. Spec: `docs/specs/f-0041.md` (approved). Branch: `plan/F-0041`.

Ten Tasks, one per Story, cut along the spec's own §2 — because §2's sections and §3's fences and
the `## Stories` bullets are already the same ten-way cut, and any other cut would have a Task
proving half a fence.

The shape of the card is two halves that land in order. The **derivation** — the classifier
(Task 1), its configuration (Task 2), the field on every card (Task 3) — is safe for every
product, changes no behaviour, and is what an operator reads before switching the other half on
(D15). The **train** — the registry (Task 4), the coder's row (Task 5), the append (Task 6), the
cut (Task 7), the red Task (Task 8), the review (Task 9) — is dark until a lane is named, and each
of its Tasks needs the one before it to have landed. The **measurement** (Task 10) hangs off the
cut and runs beside the red Task.

Wave order: **1 → 2 → {3, 4} → 5 → 6 → 7 → {8, 10} → 9**. Tasks 3 and 4 are footprint-disjoint and
both need only Task 2's configuration; Tasks 8 and 10 are footprint-disjoint and both need only
Task 7's cut. Everything else is a straight line, and it is a dependency line rather than a file
collision: Tasks 6, 7, 8 and 9 all write `asf/tick/step_train.py`, which is the cutter, built one
pass at a time.

§3.9 binds every Task, so every Gate below runs `python3 tools/run_tests.py` and the two check
scripts beside its own fence. `check_conventions.sh` is named there for a reason this plan takes
seriously (PD7): adding a `train` branch prefix makes `train/` a *forbidden literal* in
`asf/**/*.py` from Task 2 onwards, and the four Tasks that build train branches must derive every
one of them from `conv.branch('train', …)`.

### Task 1: the classifier — a footprint and a threshold table become a class, a kind and a sentence
stories: S-18800
writes: asf/size.py, tests/test_size.py
after: none

§2.1. One pure module: three class names, five kind names, and the fixed four-step order that
makes a blocker beat a small count. No filesystem, no `Product`, no path literal of its own — it
takes plain lists and a resolved config, and everything downstream reads what it returns.

**Files**

- `asf/size.py` — **new**: the module docstring, `SMALL`/`MEDIUM`/`LARGE`, `CLASSES`, `KINDS`,
  the `SizeConfig` dataclass, `kind_of(writes, kind_globs)`, `countable(writes)` and
  `classify(writes, cfg)`, each with §2.1's docstring.
- `tests/test_size.py` — **new**: §3.1.

**Steps**

1. `SMALL, MEDIUM, LARGE = 'small', 'medium', 'large'`; `CLASSES = (SMALL, MEDIUM, LARGE)`;
   `KINDS = ('docs', 'test', 'config', 'copy', 'code')`, most specific first with `code` the
   fallback (D8). These names are what the card, the index, the feeder and the cutter all switch
   on, so the test asserts the tuples themselves.
2. `SizeConfig` — a frozen dataclass holding `small_max_files`, `small_max_files_by_kind`,
   `medium_max_files`, `kind_globs` and `never_small_globs`, with every field defaulted, so the
   module is usable with no product at all. It is defined here rather than in `conventions` so
   that `conventions` imports `size` and not the other way round; `Conventions.size_config()`
   (Task 2) builds one.
3. `countable(writes)` → `(n, None)` or `(None, why)`. No count for: an empty or absent footprint
   (`no writes: footprint`), any entry carrying `*`, `?` or `[` (`'asf/**' is a glob, not a file`,
   D1), or any entry with a `<repo>:` prefix (`'record:features/**' names another repository`,
   D6). Otherwise `n` is `len(writes)` — the number of `writes:` entries, which is D1's whole
   ruling, and never an expansion against a tree this module cannot see.
4. `kind_of(writes, kind_globs)` → the one kind of `KINDS` that **every** entry matches, else
   `'code'` (D8). Matching is `asf.feeder.footprint.globs_overlap` — the repository's one
   footprint-matching rule, borrowed rather than reimplemented, so `writes:` and `kind_paths:`
   are the same kind of glob. A footprint no glob matches is `'code'`; so is a footprint of nine
   documents and one module.
5. `classify(writes, cfg)` → `(class, kind, why)`, in §2.1's fixed order, and no other:
   1. an entry matching `cfg.never_small_globs` → at least `MEDIUM`, `why` naming that entry;
   2. `countable` with no count → `LARGE`, `why` the blocker;
   3. `n <= cfg.small_max_files_by_kind.get(kind, cfg.small_max_files)` → `SMALL`;
   4. `n <= cfg.medium_max_files` → `MEDIUM`; else `LARGE`.
   Step 1 raising the floor to `MEDIUM` rather than returning it outright is what lets a blocked
   sixteen-file footprint still be `LARGE`.
6. `why` is one sentence, always: `3 files ≤ 3 (code)`, `'db/migrate/001.sql' is never small`,
   `'asf/**' is a glob, not a file count`. It is what the card's history line, the coder's brief
   and `asf train status` all print, so it is written for a person and asserted as a substring,
   never as a whole string.
7. `tests/test_size.py` per §3.1, as a table of cases: three literal paths → `small`; sixteen →
   `large`; ten → `medium`; the boundaries at exactly 3 and exactly 15; a wildcard entry among two
   literals → never small (D1); `record:features/**` → `large`; an empty footprint → `large`;
   `never_small_paths` matching one entry of two → `medium` with the entry in `why`; a config
   whose `never_small_globs` carries an `amendable_paths` entry that is in no `never_small_paths`
   (D6 — the union is Task 2's, this asserts the classifier honours whatever it is handed);
   `kind_of` → `docs` for all documents, `code` for nine documents and one module (D8), `code` for
   a footprint no glob matches; fifteen documents → `small` under `small_max_files_by_kind` while
   fifteen modules → `medium` (D7); and `CLASSES`/`KINDS` holding exactly those names.

**Gate**

```sh
python3 -m unittest -v tests.test_size
python3 -m unittest -v tests.test_feeder tests.test_conventions
python3 tools/run_tests.py 2>&1 | tail -3
bash tools/check_generic.sh && bash tools/check_conventions.sh && python3 -m asf.cli check
```

**Acceptance**

```bash

```

2. The seven defaults, each on its own documented line: `DEFAULT_SMALL_MAX_FILES = 3`,

4. `'train': 'train/'` in `DEFAULT_BRANCH_PREFIXES`. Three consequences to hold in the same diff:
   `all_prefixes()` gains it, so `harvest.remote_branches` now *sees* train branches (PD14, safe —
   they carry no session record); `conv.branch('train', name)` yields `train/<name>`; and
   `python3 -m asf.conventions --forbidden` now emits `['"]train/`, so `check_conventions.sh` in
   this Task's own Gate is the proof that no package file writes it (PD7).
5. `docs/products.example.yaml` gains both blocks with the comments §2.2 gives, unedited — they
   are the operator's only documentation of what `never_small_paths` is for and why

6. `tests/test_conventions.py`: `size:` and `train:` folded onto their flat fields; an unknown key
   inside either kept in `extra`; every field at its documented default with both blocks absent;
   `size_config()` unioning `never_small_paths` with `amendable_paths`, and doing so when
   `never_small_paths` is absent entirely; `train_lanes` defaulting to `[]`; `conv.branch('train',
   'code-20260924-0930')` → `train/code-20260924-0930`; and `all_prefixes()` containing `train/`.
7. `tests/test_env.py`: the example product validates clean with both blocks, and a product yaml

   a partial block is a partial block, not a reset.

### Task 3: every Task carries its size — derived by the ingest, carried by `index.json`
stories: S-18802
writes: asf/record/ingest.py, tests/test_ingest.py, tests/test_backlog.py
after: Task 2

§2.3. One derivation, in the machine block, for Tasks only. `build_index_data` copies the machine
block wholesale (`asf/record/core.py:270`), so the feeder, the board and the cutter all read the
same two keys without another line being written anywhere. This is the half of the card that is
safe for every product and switches nothing on.

**Files**

- `asf/record/ingest.py` — `MACHINE_KEY_ORDER` gains `'size'` and `'size_kind'` (`:19`);
  `cmd_ingest` binds the product it already loads and resolves `conv.size_config()` once (`:230`,
  PD9); `_ingest_fields` gains `size_pair=None` and writes the two fields and the history line;
  the write loop passes the pair for a Task and `None` for everything else (`:449`).
- `tests/test_ingest.py` — §3.3's cases over a temporary record.
- `tests/test_backlog.py` — the index the ingest writes still equalling the index
  `build_index_data` derives (`asf/record/check.py:213`).

**Steps**

1. `MACHINE_KEY_ORDER = [… , 'size', 'size_kind', 'updated']` — after the derived fields and
   before `updated`, which is where the key order puts everything the ingest derives. Without this
   the fields are silently discarded by the filter at `:208` (PD5), so this line and the next are
   one change.
2. `cmd_ingest` binds `product = env.load_product(name) if name else None` to a name, passes it to
   `evidence.load` as today, and takes `size_cfg = (product.conventions if product else
   Conventions()).size_config()` once, before the loops (PD9).
3. In the write loop, for `type_ == 'task'` only: `cls, kind, why = size.classify(rec['meta'].get(
   'writes') or [], size_cfg)`, then the floor — a card carrying `size_floor` never derives below
   it, and `why` gains `` (floor: size_floor) `` when the floor is what decided. The pair
   `(cls, kind, why)` goes to `_ingest_fields`; every other type passes `None` and is untouched
   (§3.3: a Feature and a Bug get no `size` at all).
4. `_ingest_fields` puts `size` and `size_kind` into `fields` **before** the `old_cmp/new_cmp`
   comparison at `:205`, so a Task whose class is unchanged still writes nothing on a second
   ingest (§3.3's last case) and one whose class moved writes once.
5. `tracked_changed` (`:203`) is left exactly as it is: a size change is not a stage change and
   must not reset `stage_since` (PD6). The history line is appended beside the state and stage
   ones — `- <stamp> ingest: size small → medium (size_floor)` — and only when the old machine
   block already carried a `size` to move from. The first ingest after this lands adds the field
   to every Task card with one line each; that is the migration, and it happens once.
6. `tests/test_ingest.py` per §3.3: a Task with a two-file footprint → `size: small`,
   `size_kind: code` in the machine block and in `index.json`; the same Task with
   `size_floor: medium` → `medium`, the floor named in the history line; a Feature and a Bug with
   no `size` key at all; a second ingest with nothing changed writing no second history line and
   no second `updated`; a Task whose `writes:` grew from two entries to sixteen writing one
   history line and **not** moving `stage_since` (PD6).
7. `tests/test_backlog.py`: `asf check` green over a record carrying the two new fields — the
   index the ingest wrote equals the one `build_index_data` derives, because `do_index` re-derives
   nothing (§2.3).
