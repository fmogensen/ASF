# Plan F-0084 — six Tasks: the table, the two renamed tables, the importer's name, the post-pass, the emptied strings

Epic: E-0001 — ASF 0.1 — a working factory. Spec: `docs/specs/f-0084.md` (approved). Branch:
`plan/F-0084`.

Six Tasks. Task 1 is the declared table alone (`asf/surface.py`), inert until something reads it.
Tasks 2, 3 and 4 are the spec's three renames, each end to end — `backlog` → `board`,
`parity` → `stories`, `migrate` → `import-items` — with the retired-name guard landing on the last
of them, because `surface.RENAMED` retires all three at once and a guard that lands early refuses
two commands that still work (PD5). Task 5 is the post-pass: `surface.apply`, the epilog, and the
four gate classes. Task 6 empties the 49 typed `help=` strings, so the table is the only place in
the tree that describes a command (§4's first Record).

**The wave order is five waves: (1, 2) → 3 → 4 → 5 → 6.** Tasks 1 and 2 share no path and run
together; everything after that is a queue on `asf/cli.py`, `plugin/skills/**` and
`tests/test_surface.py`, and PD5 and PD6 are why the queue is the plan's own rather than the
scheduler's.

§3's fences bind every Task twice over: the whole-suite fence (`python3 tools/run_tests.py`) has no
Story of its own and is copied into every Task's **Acceptance**, and every **Gate** runs
`tools/check_generic.sh`, `tools/check_conventions.sh` and `asf plugin check` — the last because
`tests/test_plugin.py:38` asserts the committed plugin is exactly what the CLI generates, so four
of these six Tasks regenerate it (PD6).

Each Task's own **Acceptance** is the §3 fence its Story names, copied byte for byte.
