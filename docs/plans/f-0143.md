# Plan F-0143 — the confine, the twins that cannot drop it, and the net under both

Epic: E-0001 — ASF 0.1 — a working factory. Spec: `docs/specs/f-0143.md` (approved). Branch: `plan/F-0143`.

Three Tasks, cut exactly the way the spec's `## Stories` are cut and the way `## The design` is
sectioned: the **rail** (the variable, the refusal, and the tests that pin both), the **install** (the
two suite twins that set it, and the proof neither can be left behind), and the **net** (the runner's
backstop, for a write that never asked git where the hooks dir was).

Task 1 owns `asf/hermetic.py` whole — all three additions, including `confine_hooks_to_temp`, which
only Task 2 calls — plus `asf/hooks.py` and the new `GitHookDirConfineTests`. Task 2 owns the three
test-package files. Task 3 owns the runner and the runner's own tests. The three `writes:` sets are
disjoint, so nothing is queued behind anything it does not actually need.

Wave order: **1 and 3 together, then 2** — in `after:` terms, 1 with `none`, 3 with `none`, 2 after 1.
Task 2 waits on Task 1 because it calls `hermetic.confine_hooks_to_temp` and asserts on
`hermetic.HOOKS_CONFINE`, neither of which exists until Task 1 lands. Task 3 waits on nothing: the
backstop resolves its dirs with `git rev-parse` itself and never goes through `asf.hooks`, so it is
green before and after the rail (P8 — no suite site leaks today, re-verified below).

§Acceptance tests' last two fences — the three tree fences and the whole suite as CI runs it — bind
every Task, so every Gate below carries them beside its own.

**The one thing this plan adds to the spec's design, and why the card is red without it:** the confine
as `## The design` writes it turns the suite red the moment Task 2 lands. PD1 has the measurement and
the four-word fix. Read it before Task 1.

The spec's first **In** bullet and `## The design` §`asf/hermetic.py` and §`asf/hooks.py` whole, plus
PD1's one added condition. `asf/hermetic.py` gains the variable name and the two functions that own
it; `asf/hooks.py` gains one exception class and four lines at the tail of `git_hooks_dir`. Nothing
sets the variable yet — Task 2 does — so on this Task alone the branch never fires and the suite's
behaviour is unchanged to the byte. That is the point: the rail lands inert and provable first.

**Files**

- `asf/hermetic.py` — `import tempfile` beside `os` and `re` (`:28-29`); `HOOKS_CONFINE`;
  `hooks_confine(env=None)`; `confine_hooks_to_temp(env=None)`
- `asf/hooks.py` — `HookDirOutsideConfine`; the confine branch replacing `git_hooks_dir`'s single
  `return` (`:82-83`); the one sentence added to `git_hooks_dir`'s docstring (`:67-70`)
- `tests/test_install.py` — `GitHookDirConfineTests`

**Steps**

1. `asf/hermetic.py`: add `import tempfile` to the module's imports (`os`, `re` today, `:28-29`), in
   alphabetical order after `re`.
2. `HOOKS_CONFINE = 'ASF_HOOKS_CONFINE'` with the spec's `#:` comment block byte for byte
   (`## The design` §`asf/hermetic.py`) — the review-b-0111 account, the `core.hooksPath` sentence,
   the "environment variable, not a monkeypatch" paragraph and the `gate`/`worker` sentence. Place it
   beside the other suite-wide rules (`CALLER_IDENTITY` `:34`, `GIT_HOOK` `:40`), which is D7.
3. `hooks_confine(env=None)` with the spec's docstring and body byte for byte: read `HOOKS_CONFINE`
   from `env` (default `os.environ`), return `os.path.realpath(root) if root else None`. The
   `realpath` is D4 and PD11 reproduced why it is load-bearing — a raw prefix compare passes today by
   luck on this platform and refuses a legitimate temp repo the moment either side is resolved.
4. `confine_hooks_to_temp(env=None)` with the spec's docstring and body byte for byte: set
   `env[HOOKS_CONFINE] = tempfile.gettempdir()` and return it. It has **no caller in this Task** —
   Task 2's two lines are its only ones (PD3). Do not add one here.
5. `asf/hooks.py`: `HookDirOutsideConfine(RuntimeError)` with the spec's docstring byte for byte,
   including the D3 paragraph on why it raises rather than returning `None`. Place it at module level
   above `git_hooks_dir`.
6. Replace `git_hooks_dir`'s single `return` (`:82-83`) with the spec's block, with **one condition
   added** (PD1):

   ```python
       out = p.stdout.strip()
       out = out if os.path.isabs(out) else os.path.join(repo, out)
       # F-0143: under the suite's confine, a hooks dir that resolves outside the temp root is the
       # defect review-b-0111 was — a fixture's hook in a directory another session's commit runs.
       # git answers here, not the caller: `core.hooksPath` can point anywhere, so the repo being a
       # temp one is not enough. The offending test fails at its own line, with all three paths.
       # os.devnull is exempt and is not a hole: a fixture sets `core.hooksPath=/dev/null` to mean
       # "this repo runs no hooks" (tests/gitfixture.py:_disable_hooks, B-0073), git answers with it,
       # and no hook file can ever exist under a character device — ENOTDIR, not a directory.
       confine = hermetic.hooks_confine()
       if confine and out != os.devnull and not os.path.realpath(out).startswith(confine + os.sep):
           raise HookDirOutsideConfine(
               f'{out} is outside {confine} — git resolved it for {repo}. A test installs hooks only '
               f'into its own git-init\'d temp repo: a hook left anywhere else is run by every commit '
               f'in that repo (review-b-0111). See tests/gitfixture.py:executable_asf.')
       return out
   ```

   The message is the spec's, byte for byte. `from asf import hermetic` is already in this function's
   body (`:76`) for the `GIT_HOOK` strip, so nothing new is imported (D7). The `+ os.sep` is the
   spec's own note: the root itself is no repo's hooks dir, and a sibling whose name merely starts
   with the root's must not pass.
7. `git_hooks_dir`'s docstring (`:67-70`) gains the spec's sentence, narrowing its "it never raises"
   promise (P19): *"Raises :class:`HookDirOutsideConfine` when :data:`asf.hermetic.HOOKS_CONFINE` is
   set and the answer falls outside it — the suite only."* Add one clause naming the `os.devnull`
   exemption, since the docstring is the contract a caller reads.
8. `GitHookDirConfineTests(unittest.TestCase)` in `tests/test_install.py`, beside `GitHookTests`.
   Every case builds **two** `mkdtemp` trees — a confine root and an outside root — and never names a
   path that is not temp (PD2); `mock.patch.dict(os.environ, …)` with an explicit
   `pop(hermetic.HOOKS_CONFINE, None)` is how the module already drives environment cases
   (`tests/test_install.py:1397-1410`). The cases, one per clause of the spec's S-34600 fence:
   - **unset changes nothing**: with `HOOKS_CONFINE` absent, `git_hooks_dir` on a repo in the outside
     root returns that repo's own hooks dir and raises nothing — the operator install, untouched.
   - **inside resolves**: with the variable set to the confine root, a `git init`'d repo under it
     resolves normally.
   - **outside raises**: a repo under the outside root raises `HookDirOutsideConfine`, and the
     message carries all three of the repo, the dir git answered with, and the root.
   - **`os.sep`**: a repo whose path is the confine root's string plus a suffix (`<root>-sibling`,
     created beside it) is refused, proving the `+ os.sep`.
   - **`core.hooksPath` out of the root**: a repo *inside* the confine with
     `git config core.hooksPath <outside>/hooks` is refused — the factory-host case, and the one the
     repo being temp cannot catch.
   - **resolved, not raw** (D4): the confine root is set to the unresolved `tempfile.gettempdir()`
     form while the repo is reached through it, and the call is **not** refused. On a platform where
     the two forms coincide this case is a tautology and still correct; on this one it is the case
     that fails without `realpath`.
   - **`/dev/null` is exempt** (PD1): a repo inside the confine with
     `git config core.hooksPath /dev/null` returns `/dev/null` and raises nothing — the suite's own
     fixture idiom, and without this case Task 2 turns `tests.test_cutover` red.
   - **review-b-0111, reproduced and caught**: the fixture of `tests/test_check_staged.py:365-386`
     built verbatim — a hand-written `pre-commit` naming `/x/asf` — in a repo under the **outside**
     root, asserting the resolution is refused before the hook can be written. The same fixture in a
     repo under the confine stays green, which is the second S-34600 fence below.
9. `tests/test_check_staged.py` is **not** edited (PD7): its `/x/asf` fixture is the regression case
   and `## Out` refuses to touch it. Neither is `asf/doctor.py` — PD1's exemption is what keeps
   `check_redaction_hooks` (`:461`) working, so it needs no `try`.

write that never asked git where the hooks dir was — review-b-0111's own hook was a bare

**Files**

- `tools/run_tests.py` — `hook_dirs(root)`, `hook_digest(dirs)`, `hook_leaks(before, after)`; the
  `before` capture and the four lines in `run`'s exit path (`:152-196`)
- `tests/test_run_tests.py` — `HookLeakTests`

**Steps**

1. `hook_dirs(root)` with the spec's docstring byte for byte. It resolves, never reads a configured
   list (D11), and writes no path into the file: `git -C <root> rev-parse --git-path hooks` made
   absolute against `root`, plus `git -C <root> config core.hooksPath` made absolute when the repo
   sets one. Returns a de-duplicated list, and `[]` when `root` is not a git repo (either command
   exiting non-zero), which is what makes it inert over the module's fixture trees (PD9). Use
   `hermetic.build()` for the child env — the module already imports it (`:37`) — so a leaked
   `GIT_DIR` cannot redirect the answer, the same reason `git_hooks_dir` strips it (P4).
2. `hook_digest(dirs)` with the spec's docstring byte for byte: `{path: {name: sha256}}` for each of
   `dirs` that exists, one digest per **file** (D10 — an overwritten hook is the worst case and a
   count cannot see it). A dir that is missing, or is not a directory at all, contributes nothing and
   does not raise — `/dev/null` reaches here whenever a repo disables its hooks (PD1), and it must be
   silently empty. Skip sub-directories; hash bytes, not text. `import hashlib` joins the module's
   imports (`:24-31`).
3. `hook_leaks(before, after)` with the spec's docstring byte for byte: the lines naming every hook
   file **added, changed or removed** between two digests, empty when every one is byte-identical.
   One line per file, shaped `<dir>/<name> <added|changed|removed>` — the `Records` block's format —
   sorted, so the output is stable. A dir present in one digest and absent from the other is handled
   as every one of its files added or removed, never a `KeyError`.
4. In `run` (`:152`), after `root, package = os.path.split(tests_dir)` (`:155`) and before the pool
   starts, capture `dirs = hook_dirs(root)` and `before = hook_digest(dirs)`. `root` is **`run`'s
   own**, never the module-level `ROOT` — PD9 is why, and the spec's docstring says so.
5. In the exit path, the spec's four lines byte for byte, replacing `:196`:

