Epic: E-0004 — Control plane — the factory's dashboard, served from the record. Spec:
`docs/specs/f-0205.md` (approved). Branch: `plan/F-0205`.

**One Task.** The spec's two Stories are one landable change, and not as a judgement call. The
spec puts its D4 assertion — the live-session row reading `session fix-bug-b-0001 running` — inside
`NoS1S2BugIsInvisible`, which is S-38000's acceptance class; that sentence is built by
`session_wait`, which is S-38001's code. Measured at this head, with an in-flight record carrying
`job='fix-bug-b-0001'`:

```

```

So a Task carrying S-38000 alone either lands red or lands its acceptance class with the one
assertion the card was filed for left out. The two halves also write the same two files (PD10).

The second half is measured too. Every row of the spec's misclassification table reproduces here,
un-edited, at `917addba1`:

| what actually holds `B-0001` | what NEXT prints today |
| --- | --- |
| `finished, awaiting harvest` | `WAITS ON session` — `S1 open, decided: finished, awaiting harvest` |
