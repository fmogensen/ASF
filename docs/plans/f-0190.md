# Plan F-0190 — the reader, the count, the words, and the config that refuses

Epic: E-0001 — ASF 0.1 — a working factory. Spec: `docs/specs/f-0190.md` (approved). Branch:
`plan/F-0190`.

Four Tasks, a strict chain. The spec's own shape is a chain — a reader nothing calls, then the one
`rev-list` that calls it, then the lines that read the predicate the reader introduced, then the
config keys that make all three reachable from a product file — and each link is unusable without
the one before it:

1. **`asf/harvest/deploy.py`, the reader** — `DEFAULT_EXCLUDES`, `excludes(product, env)` and
   `filtered(f)`. Nothing calls them when this lands; the factory's behaviour is byte-identical.
2. **The count grows its second half** — `pathspecs()` emits `:(exclude,glob)`, `_behind()` takes
   both lists, `_set_behind`/`_blank`/`_done` carry the `exclude` fact. **This is the Task that
   fixes the card**: the `playwright.config.ts`-only commit counts 0 the moment it lands.
3. **The words follow the count** — `_lag` (both branches), `_manual`, `decide`'s zero branch,
   the findings line, and `asf prod`'s header, all on the one predicate.
4. **The product file loads, or it refuses** — `paths`, `exclude` and `exclude_defaults`
   shape-checked on dev, prod and every named target, and the example config documenting them.

Wave order: **1 → 2 → 3 → 4**, one Task per wave. All four extend `tests/test_deploy.py`, so the
feeder queues them against each other whatever `after:` says — and that costs nothing here, because
1 → 2 → 3 → 4 is the dependency order anyway (PD1).

**Read PD2 before writing `filtered()`**: the spec's `bool(f['paths'] or f['exclude'])` raises
`KeyError` against the suite's one hand-built facts dict (`tests/test_prod_view.py:81`), a module
the spec's own regression run names. **Read PD3 before touching `pathspecs()`**: a shipped
assertion at `tests/test_deploy.py:431` reads the *last* element of the `rev-list` argv, and the
argv legitimately grows a tail — the assertion moves, the pathspec order does not. **PD4** is the
real `origin/main` and the linear history `RelevanceAgainstGit`'s fixture needs before its numbers
mean anything.

### Task 1: the exclude list resolves once, and the defaults never make a filter on their own
stories: S-36050
writes: asf/harvest/deploy.py, tests/test_deploy.py
after: none

The spec's §1 reader half, and nothing else — `DEFAULT_EXCLUDES`, `_globs`, `excludes()` and
`filtered()`. No caller exists when this lands, so the factory's behaviour is byte-identical. This
Task exists so that the two rules an operator will argue about — *the defaults are added, not
substituted* and *the defaults never create a filter where none was asked for* — are written once,
before two call sites start asking them.

**What changes for the machine when this lands.** Nothing observable. No count moves, no line
moves, no config key is read that was not read before: `excludes()` is called by nobody until Task
2 and `filtered()` by nobody until Task 2's `_set_behind`.

**Files**

- `asf/harvest/deploy.py` — `DEFAULT_EXCLUDES` as a module constant beside the other module
  constants; `_globs(v)` lifted out of today's `paths()` body; `paths()` rewritten to call it,
  behaviour unchanged; new `excludes(product, env)`; new `filtered(f)`. `pathspecs`, `_behind`,
  `_blank`, `_done`, `_set_behind` and every renderer are untouched.
- `tests/test_deploy.py` — `RelevanceFilter(unittest.TestCase)` added, beside `NamedTargets` which
  owns this code today. No existing class is touched.

**Steps**

1. `DEFAULT_EXCLUDES` is the card's seven globs, **in the card's order**, as a tuple:
   `('**/*.test.*', '**/*.spec.*', '**/e2e/**', '**/playwright.config.*', '**/vitest.config.*',
   '**/__tests__/**', '**/*.md')`. A tuple, not a list, so no caller can mutate the default set for
   every product in the process. Its `#:` docstring says what the spec's design says: paths a
   deploy never ships, added to an environment's own `exclude` list unless `exclude_defaults:
   false`, and engaged only where the environment already has a filter — never on its own. C3 fixes
   this list; it is not per-product config and no card has asked for `*.stories.*` or
   `cypress.config.*`.
2. `_globs(v)` is today's `paths()` body verbatim — a bare string becomes a one-element list, a
   list keeps its non-empty string members, anything else is `[]` — and `paths()` becomes
   `return _globs(env_cfg(product, env).get('paths'))`. This is a refactor with no behaviour
   change; the lenient coercion is what the validator's strictness is deliberately at odds with
   (C9), and neither half moves here.
3. `excludes(product, env)`, the spec's snippet with PD5's dedupe:
   - `own = _globs(cfg.get('exclude'))`.
   - **The C2 guard first**: `if not own and not paths(product, env): return []`. This is the line
     that stops the defaults from silently making prod `0 relevant` on a docs-only trunk commit for
     every product on the machine. Write the reason into the docstring, not only into the code — it
     is the decision a later reader is most likely to undo.
   - `if cfg.get('exclude_defaults') is False: return list(dict.fromkeys(own))`. Identity against
     `False`, never truthiness: `exclude_defaults: 0` is not `false`, and a missing key must not
     read as one.
   - otherwise `list(DEFAULT_EXCLUDES) + [g for g in dict.fromkeys(own) if g not in
     DEFAULT_EXCLUDES]` — defaults first, in their own order, the environment's own globs after
     them, each once (PD5).
4. `filtered(f)` is `bool(f.get('paths') or f.get('exclude'))` — **`.get`, not subscription**
   (PD2). Its docstring names it as the one predicate every line and every count asks, so the two
   can never disagree about whether an environment is filtered.
5. `RelevanceFilter(unittest.TestCase)`, the spec's bullets one test each, built on the module's
   existing `_site()` helper (`tests/test_deploy.py:404-409`) and `_modes()` (`:26-33`) — no new
   product factory:
   - a target with `paths` and no `exclude` resolves to exactly `list(DEFAULT_EXCLUDES)`;
   - `exclude: ['apps/site/fixtures/**']` resolves to the seven then that one, in that order;
   - an `exclude` that repeats a default appears once, and so does one that repeats **itself**
     (PD5 — assert the length, not just membership);
   - `exclude_defaults: false` leaves the environment's list alone, and with `exclude: []` leaves
     `[]` while `paths` still makes the environment filtered;
   - an environment with **neither** key resolves to `[]` even though `DEFAULT_EXCLUDES` is
     non-empty — the C2 guard, asserted for a named target, for `deploy_sha.prod` and for
     `deploy_sha.dev`;
   - a bare string `exclude: 'docs/**'` coerces to `['docs/**']` as `paths` does, and `exclude: 7`
     reads as no exclude at all;
   - `paths` and `exclude` read the same under `deploy_sha.prod` as under `targets.site` (P1 —
     put the keys under `_modes(prod='manual')`'s prod block and assert both readers);
   - `filtered()` is `True` for paths-only, exclude-only and both, `False` for neither, and
     `False` for `{}` and for a dict carrying only `{'paths': []}` — the PD2 case, asserted
     directly so a later strict subscription is caught here rather than in `tests.test_prod_view`.

### Task 2: relevance counts only commits under `paths` and outside the excludes
stories: S-36051
writes: asf/harvest/deploy.py, tests/test_deploy.py
after: Task 1

The spec's §1 counting half — `pathspecs()`, `_behind()`, `_blank`, `_done`, `_set_behind` — and
its `RelevanceAgainstGit` proof against real git. **This is the Task that fixes the card**: when it
lands, the trunk commit that changed only `apps/site/playwright.config.ts` counts 0 and a `mode:
auto` target stops dispatching a real deploy workflow for it, with no config change at all — the
target's existing `paths:` is the opt-in (C2).

**Read PD3 before touching `pathspecs()`**: the includes come first, the excludes after, and the
shipped assertion at `tests/test_deploy.py:431` moves off `[-1]` rather than the order moving to
spare it. **Read PD4 before building the fixture**: a real bare `origin` and a linear history, or
the numbers are not numbers.

**What changes for the machine when this lands.** The card's defect is gone. Every paths-scoped
environment's `relevant` count drops the commits that touch only test, e2e, test-config and
Markdown files; `decide()`'s zero branch stops the `MANUAL:` shouting and stops an `auto` target
dispatching. Nothing prints differently in *wording* — `N relevant commits behind main (M in all)`
is today's sentence with a smaller N — and an environment with neither `paths:` nor `exclude:` is
byte-for-byte untouched (C2).

**Files**

- `asf/harvest/deploy.py` — `_dir(g)` lifted out of `pathspecs`; `pathspecs(globs, exclude=())`;
  `_behind(product, base, sh, globs=None, exclude=None)`; `_blank` gains `'exclude':
  excludes(product, env)`; `_done`'s guard becomes `not filtered(f)`; `_set_behind` counts on
  `filtered(f)` and passes both lists. The module docstring's **Named targets** paragraph gains the
  filter's second half (the seven defaults, the `exclude:` list, `exclude_defaults: false`, that
  the keys read for dev and prod too, and that with neither key an environment has no filter at
  all). No renderer is touched — they are Task 3's.
- `tests/test_deploy.py` — `RelevanceAgainstGit` added; the `gitfixture` import idiom added at
  module top; the one assertion at `:431` rewritten per PD3. No other existing test changes.

**Steps**

1. `_dir(g)` is today's inline `g + '**' if g.endswith('/') else g`, lifted so both halves of
   `pathspecs` share one rule — a trailing-slash `exclude: [apps/site/e2e/]` must exclude the
   directory exactly as a trailing-slash `paths:` includes it.
2. `pathspecs(globs, exclude=())` returns `[':(glob)' + _dir(g) for g in globs] +
   [':(exclude,glob)' + _dir(g) for g in exclude]` — includes first, excludes after (PD3). The
   docstring says what the exclude magic buys: git drops those files from the match, so a commit
   touching only excluded files matches nothing and is not counted, and a commit touching one
   shipped file among ten test files still is. The default `()` keeps every existing caller of
   `pathspecs` working unchanged.
3. `_behind(product, base, sh, globs=None, exclude=None)`: the guard becomes `if globs or exclude:`
   and the tail `argv += ['--'] + pathspecs(globs or [], exclude or [])`. Everything else —
   the `if not base: return None`, the range, the `int(count) if count and count.isdigit() else
   None` — is untouched. An exclude-only call therefore emits `--` followed by exclude pathspecs
   alone, which git reads as "everything except" (P3, re-verified in PD11).
4. `_blank` gains `'exclude': excludes(product, env)` beside `'paths'`. Every facts dict `deploy`
   builds now carries both keys; `filtered()` still uses `.get` (PD2), because the predicate is
   public and `tests/test_prod_view.py:81` is not the only dict that could ever reach it.
5. `_done`: `if f['relevant'] is None and not filtered(f): f['relevant'] = f['behind']`. An
   environment that is filtered but whose count did not read keeps `relevant: None`, which every
   view already renders as `?` — unchanged behaviour for an unreadable count.
6. `_set_behind`: `if filtered(f):` rather than `if f['paths']:`, and the filtered call becomes
   `_behind(product, f['deployed'], sh, f['paths'], f['exclude'])`. The `0 if f['behind'] == 0`
   short-circuit stays exactly as it is — an environment level with the trunk spends no second
   `rev-list`.
7. The `tests/test_deploy.py` import bootstrap, the suite's own idiom
   (`tests/test_evidence_sources.py:10-13`): `try: from gitfixture import Template` /
   `except ImportError: from tests.gitfixture import Template`, so the module runs both under
   `unittest discover -s tests` and under `-m tests.test_deploy`.
