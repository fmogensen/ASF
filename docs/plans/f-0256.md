# Plan F-0256 — one Task, one file's seam: the log gives up the failing test, the test names the member, and the drop line says so

Epic: E-0001 — ASF 0.1 — a working factory. Spec: `docs/specs/f-0256.md` (approved, 502 lines,
read in full here). Branch: `plan/F-0256`.

**One Task, three Stories, one wave.** The spec's design is three layers of one hop, and all three
live in one module's seam — `asf/merge_queue.py` with its own test module:

1. **the log gives up the failing test's own file** (§1–§2, S-58804) — `failure_findings`' per-check
   item grows one key, `test_paths`, filled by two readers the current ones miss (a traceback frame
   and a unittest header's dotted id), and `repo_path` reduces a log path to the spelling the
   batch's tree holds. `item['paths']` is untouched.
2. **the test names the member whose files it covers** (§3–§5, §7's hold gate, S-58805) — `covers`
   (pure, the inverse of the product's own touched-test selection), `cover_blame` (the hop), and
   `blame`'s fallback, which runs **only** when the direct reading named nobody and goes through
   both no-verdict rules unchanged — landed with its bound: a cover-derived culprit is sent back
   and never held out of the queue.
3. **the drop reason names the culprit and how it was found** (§6–§7, S-58806) — the computation
   moves above `_drop` in `run`'s red branch, `_drop`'s `why` grows the clause, and `culprit_text`'s
   `where` tells the truth about which hop found it. This is the line the card is about.

**It is one Task because the record will not mint three.** This plan was first cut as three Tasks,
one per Story, in a serial chain. Measured against the real parser here (PD1), that cut mints
**one** card: all three Tasks write the same two files, `plan_tasks.STORY_ID_RE` is `\bS-\d{4}\b`
and matches none of this Feature's five-digit Story ids, so all three carry an empty `stories` into
`idcheck.task_key` and Tasks 2 and 3 are refused as duplicates of Task 1 — *"same parent, stories
and writes — not minted"*. The three layers would land as one coder's diff anyway (identical
`writes:` serialise in the queue whatever `after:` says); the only thing the three-card cut would
have bought is three gates, and that is bought back below as three gated steps inside one Task.

**Read PD2 and PD3 before writing a line of code.** Every one of the spec's eighteen preconditions
holds — re-measured here, one at a time — and the design is sound. But two of its snippets cannot
be coded as written: §6's culprit test names a lone member for evidence that does not exist, in a
state a landed test already reaches (PD2), and §1's dotted reduction reads the tree from a function
that has no repository in scope (PD3). Neither changes the design; both turn into a session
debugging the trunk if they are met for the first time while coding. PD4 through PD11 are eight
smaller places where the spec's prose, its anchors or its acceptance text says something the code
does not — corrected here, never widened.

## Decisions

**PD1 — one Task, because three is one card. Measured, not assumed.** The first cut of this plan was
three Tasks, one per Story, `after:` chained. Run against the real parsers in this worktree, that
cut mints one card and refuses two:

```
T1 stories -> [] | key dup of: none
T2 stories -> [] | key dup of: T1
T3 stories -> [] | key dup of: T1
```

Two facts compose into it. `plan_tasks.stories_of` keeps only ids matching
`STORY_ID_RE = re.compile(r'\bS-\d{4}\b')` (`asf/record/plan_tasks.py:34`) — exactly four digits
between word boundaries, so `S-58804` matches nothing and every Task's `stories` is empty (PD11).
And `idcheck.duplicate_task` (`asf/record/idcheck.py:68-83`) refuses any Task whose
`task_key(parent, stories, writes)` — sorted sets, so order buys nothing — equals one already
minted *in the same pass* (`extra=keys`). Three Tasks with the same parent, the same empty stories
and the same two `writes:` paths are one key. Every alternative that would make the `writes:` sets
disjoint was refused: moving a layer's tests into a new test module contradicts the spec's fenced
acceptance, which names `tests.test_merge_queue.TestPathsTests`, `…CoversTests`, `…CoverBlameTests`
and `…DropReasonTests` byte for byte; moving a layer's code into a new `asf/*.py` module
contradicts the spec's In section, which names `merge_queue.test_paths`, `merge_queue.repo_path`,
`merge_queue.covers` and `merge_queue.cover_blame`, and buys nothing because the test module would
still be shared. So: one Task, three Stories, and the three layers kept apart as three gated steps
inside it — step 7, step 12 and step 18 each run their own acceptance class before the next layer
starts, which is the whole of what three cards would have given.

**PD2 — the drop clause gates on `blame`'s own answer, not on `culprits`.** §6 reads `if
len(culprits) == 1 and not on_trunk`. At `:825-826` a one-member batch whose blame named nobody is
given `culprits = {members[0]['branch']: []}` — a *membership* fact, not an evidence fact — and
§6's `how` would then claim `its files, named in the failing job's log` for a log with no paths in
it. Measured above: a landed test reaches exactly that state. The plan's reading, which is D8's own
rule applied one line further: keep `named, covered = blame(...)` and gate the clause on
`len(named) == 1`, taken **before** the `len(members) == 1` fallback. Every acceptance bullet of
S-58806 still holds — a lone member whose own file *is* in the log gives `len(named) == 1` and the
clause fires truthfully (`Culprit.test_a_lone_culprit_is_told_the_failed_upstream_job_not_only_the_
skipped_ones`, `:480-491`, is that case) — and `DropReasonTests` gains one bullet for the lone
blind case, which the spec's own *"with no culprit … the drop line is unchanged"* already demands
in substance.

**PD3 — `test_paths` emits the dotted form's candidates; `repo_path` picks.** §1 says the dotted
name *"is reduced to a path by dropping trailing segments until one resolves in the tree (§2)"*,
and S-58804's bullet says `FAIL: test_x (tests.test_audit.AuditGap.test_x)` *"gives a `test_paths`
entry for `tests/test_audit.py` at line 0"*. Those two cannot both be read as *resolved inside
`test_paths`*: the spec's own In section declares `test_paths(item)` — one argument, the item — and
the function that fills the key is `failure_findings(slug, roots)`, which has neither `lane` nor
`batch` and therefore no repository to resolve against. The spec's other bullet settles the
reading: the traceback entry is asserted as `('/home/x/work/o/p/tests/test_audit.py', 42, <the
line>)`, the absolute path **verbatim**, unresolved. So `test_paths` is pure over the item and
emits, for a dotted id, every `<prefix>.py` candidate longest-first — `tests/test_audit/AuditGap/
test_x.py`, `tests/test_audit/AuditGap.py`, `tests/test_audit.py` — each at line 0; `repo_path`
(§2, §4 step 1) drops the ones the tree does not hold. S-58804's bullet holds as written: one of
the entries *is* `tests/test_audit.py`. A candidate that resolves to nothing is already the
behaviour S-58805's last-but-one bullet asks for.

**PD4 — `repo_path` takes the memo as an argument.** §2 ends *"Results are memoised per pass"*, and
the declared signature `repo_path(lane, batch, path)` has nowhere to keep one. A module-level dict
would be state that outlives a pass and leaks between the suite's tests — the hardest kind of flake
to find in a module this size. So: `repo_path(lane, batch, path, memo=None)`, keyed
`(lane.repo, batch['base'], path)`, with `cover_blame` building one dict per call and passing it to
every lookup. The declared three-argument call still works, un-memoised, which is what
`TestPathsTests` drives.

**PD5 — the candidate list is bounded.** A 400-line window (`FINDING_LINES = 400`, `:1106`) of a
Python traceback names a frame per stack level, each one a path with up to a dozen segments, and
each segment is one `git cat-file -e`. Unbounded that is hundreds of local git reads per red batch
— a cost the blame exists to avoid. The Task adds `TEST_PATHS_MAX = 20` beside `FINDING_LINES` and
caps `test_paths` at that many distinct paths in first-seen order, exactly as
`lane.RED_TESTS_MAX = 20` caps `red_tests` (`asf/harvest/lane.py:5157`). This is a bound the spec
does not state; it is stated here rather than left to a coder's judgement, and it changes no
acceptance bullet (every fixture names one or two paths).

**PD6 — three anchors are off, and nothing follows from it.** P2 cites
`asf/merge_queue.py:2241-2244` for the operator's drop line and `:2098-2126` for the cancel: `_drop`
is `:2084-2088`, `_cancel_live` is `:2098-2126` (exact), and `:2241` is `_ledger`. P3 cites
`tests/test_merge_queue.py:432` for the later culprit line: that is the `'cut again without it'`
assertion *inside* `Culprit`, whose `class` line is `:383`. P12 says the grep is four hits; it is
three, all reads, which is the claim that matters. Every fact each precondition asserts is true.

**PD7 — `blame` becomes a 2-tuple at one call site.** Measured above: one caller, no test
reference. Step 13 changes `:824` to `culprits, covered = blame(...)` and leaves `:825-826`'s
one-member fallback untouched, which is what PD2 then reads around. `blame`'s docstring gains the
second value; the module docstring's claims at `:31-34` and `:72` describe the direct reading and
stay true.

**PD8 — the hold bound lands with the hop it bounds, in the same step.** §7's gate — `if fixed and
culprits and not covered:` — is in S-58806's acceptance list (*"a deterministic red writes
`merge-queue-culprits.json` for a direct culprit and not for a hop culprit"*), but its *code*
belongs with `cover_blame`'s wiring into `blame` (step 13), not with the drop line (step 15).
Between the two there must be no state in which the queue freezes a PR out of every cut on the
strength of the weaker hop — exactly what D7 refuses, and a wrong hold needs a human or a push to
clear. One Task makes the window zero; the step order keeps it zero even for a coder who commits
per step, and `CoverBlameTests` asserts the bound at step 14 rather than waiting for
`DropReasonTests` at step 18.

**PD9 — the dotted reduction is written again, not reused.** `harvest.gate_files` already does it
(`asf/harvest/harvest.py:844-857`) and is wrong for this use three ways: its `DOTTED_RE` hardcodes
`tests?` — the thing P14 forbids `asf/merge_queue.py` to carry — it assumes a two-segment module,
and it caps a mixed list of paths and ids at 20. The Task writes its own reduction, resolves every
candidate against the batch's own tree, and calls nothing in `harvest` but the log readers the
module already calls.

**PD10 — `covers`' shape test admits a document, and that is left alone.** §3 selects a candidate
by *"a dotted extension, at least one `/`"*. `docs/x.md` passes both. CoversTests' bullet (*"a
changed non-source file (`README.md`, `docs/x.md`) is covered by nothing"*) still holds —
`README.md` fails the `/` test, and `docs/x.md`'s dotted form `docs.x` is named by no test and its
leaf `x` is not the fixture test's stem — but it holds *contingently*, not by construction. Named
here so a coder does not close the gap with a hardcoded extension list: the design is deliberately
extension-agnostic (`src/audit.test.ts` is one of the shapes §1's table reads), and
`tools/run_tests.py`'s own `.py` test is the forward map's privilege, not this one's. The `.py`
suffix appears in exactly one place in this card's code — PD3's dotted candidates, where the dotted
form only ever comes from a Python unittest header — and that literal has precedent in the package
(`asf/briefs/facts.py:156`, `asf/feeder/widen.py:157`, `asf/harvest/harvest.py:856`) and matches no
forbidden pattern (measured under P14).

**PD11 — the minted Task card will carry no `stories`, and that is the record's, not this plan's.**
`STORY_ID_RE` is four digits (PD1); this Feature's Stories are five (`S-58804`, `S-58805`,
`S-58806`, minted through `asf new story` per P18). So `stories_of` returns `[]` and the Task card
lands with an empty `stories` field however this plan writes its `stories:` line. The line below is
written correctly anyway: it is the plan's coverage record, it is what the plan is approved
against, and it is what a human reads. The record's regex is a defect of
`asf/record/plan_tasks.py`, outside this card's spec, outside its `writes:` and outside this
session's scope — it mints no card here and this plan does not widen to fix it.

### Task 1: the queue names the culprit PR in the drop reason — out of the log it already reads, and out of the test that covers the member's files
stories: S-58804, S-58805, S-58806
writes: asf/merge_queue.py, tests/test_merge_queue.py
after: none

The spec's design in full, §1 through §7. Three layers, landed in order inside one diff: the
failing test's own file comes out of the log (§1–§2); a test file no member changed names the
member whose files it covers, as a fallback and never as a peer, and is never held against it
(§3–§5, §7); and the drop reason says who and how (§6–§7). When this lands, a red three-PR batch's
first line names the PR, and nobody runs `git diff | grep`.

Read **PD1** (why this is one card and not three), **PD2** (the clause gates on `blame`'s map, not
on `culprits`) and **PD3** (`test_paths` resolves nothing against the tree) before starting.

**Files**

- `asf/merge_queue.py` — `_TB_FILE_RE`, `_TEST_DOTTED_RE` and `TEST_PATHS_MAX` beside
  `_PATH_LINE_RE`/`_BARE_PATH_RE` (`:1100-1106`); `test_paths(item)`, new, pure; the one new key in
  `failure_findings`' item literal (`:1494-1495`) and the one new call at the end of its per-check
  body (after `:1519`); `repo_path(lane, batch, path, memo=None)` and `covers(text, test_path,
  files)`, new, beside `_member_files` (`:1523`); `cover_blame(lane, batch, members, found)`, new,
  beside `blame`; `blame`'s fallback and 2-tuple return (`:1573-1594`); `run`'s red branch — the
  unpack, the `not covered` hold gate, the reorder and the `why_drop` clause (`:799-830`);
  `culprit_text`'s `where` and its new argument (`:1597-1606`, called at `:834-835`)
- `tests/test_merge_queue.py` — `TestPathsTests`, `CoversTests`, `CoverBlameTests` and
  `DropReasonTests`, four new classes

**Steps**

Three layers, in order. Each layer ends with its own acceptance class green before the next begins
— that is what the refused three-card cut would have bought, and it is bought here instead (PD1).

*Layer 1 — §1 and §2, the failing test's own file (S-58804).*

1. Run the six modules whole first and keep the number. It is `Ran 192 tests in 98.768s` / `OK` at
   `f467e7ed4`; if yours differs, find out why before editing.
2. Add the two patterns beside the existing two, each with the one-line comment that says which log
   shape it reads and which reader misses it:
   `_TB_FILE_RE = re.compile(r'File "(?P<p>[^"\n]+\.[A-Za-z0-9]{1,8})", line (?P<n>\d+)')` — a
   Python traceback frame, absolute or relative, which `_PATH_LINE_RE` cannot see because a
   traceback writes `", line 42"` and not `:42`; and
   `_TEST_DOTTED_RE = re.compile(r'^(?:FAIL|ERROR):\s+\S+\s+\(([\w.]+)\)')` — a unittest header,
   which `_BARE_PATH_RE` cannot see because it names no path at all. Both byte for byte from §1.
   Then `TEST_PATHS_MAX = 20` with PD5's reason on it: a stack frame per level × a `cat-file` per
   segment is the cost this cap exists to bound, and `lane.RED_TESTS_MAX` is the precedent.
3. `test_paths(item)` — pure over the item, no git, no host, cannot raise. Over `item['lines']` in
   order: every `_TB_FILE_RE` match gives `(the path verbatim, int(n), text.strip())`; every
   `_TEST_DOTTED_RE` match gives, for the dotted id, its `<prefix>.py` candidates **longest-first**
   (`tests.test_audit.AuditGap.test_x` → `tests/test_audit/AuditGap/test_x.py`,
   `tests/test_audit/AuditGap.py`, `tests/test_audit.py`), each `(candidate, 0, text.strip())`.
