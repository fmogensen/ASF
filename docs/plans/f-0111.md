# Plan F-0111 — the install a hook names

Epic: E-0001 — ASF 0.1 — a working factory. Spec: `docs/specs/f-0111.md` (approved). Branch:
`plan/F-0111`.

Four Tasks, one per Story, cut along the four blocks of the spec's **The design**. Task 1 is the
resolver — `running_asf`, the three-route ladder, and the three writers that take its answer. Task 2
is reading back: both recognisers widened to every form asf can write, plus `hook_entry`. Task 3 is
repair without downgrade — `entry_point_source`, `prefer_entry`, and its two call sites. Task 4 is
the doctor's `redaction-hooks` row and the operator-facing text.

Tasks 1 and 2 need nothing landed and are declared `after: none` — the resolver does not read a hook
and the recognisers do not resolve one. They both write `asf/hooks.py`, so the feeder queues them
whatever their `after:` says (PD10); either order works. Task 3 needs Task 1's resolved `Entry` and
Task 2's `hook_entry`, which are the two arguments `prefer_entry` compares. Task 4 calls
`hooks.hook_entry` (Task 2) and `hooks.entry_point_source` (Task 3).

Wave order: **1 ‖ 2 → 3 → 4**.

§Acceptance tests' last fence — the whole suite as CI runs it — binds every Task, so every Gate below
runs `python3 tools/run_tests.py` beside its own. Its second-to-last fence (`tests.test_install
tests.test_check_staged tests.test_quickstart`, the regression P13 names) binds Tasks 1 and 3, which
are the two that change what those modules assert.

### Task 1: `hooks.running_asf` — the entry point a hook names is the install that wrote it
stories: S-32650
writes: asf/hooks.py, tests/test_hooks_entry.py, tests/test_install.py, docs/guide/troubleshooting.md
after: none

The spec's first two **In** bullets and the `asf/hooks.py — the resolver` block: three routes in
order, `argv[0]` first (D1, D2), the venv script behind the `same_install` guard (D3), `PATH` last
(D4), and the three writers of P2 taking its answer.

**Files**

- `asf/hooks.py` — `ENTRY_POINT_NAME`, `ENTRY_NAME_RE`, `Entry`, `running_asf`, `same_install`,
  `runnable_asf` rewritten over it, `install`'s summary line
- `tests/test_hooks_entry.py` — new module: `RunningAsfLadderTests`, `RunnableAsfRefusalTests`,
  `SameInstallGuardTests`, `WrittenCommandsNameTheRunningInstallTests`
- `tests/test_install.py` — the two summary-line equality assertions (PD8)
- `docs/guide/troubleshooting.md` — the `not on PATH` row at `:43`

**Steps**

1. `ENTRY_POINT_NAME = 'asf'` and `ENTRY_NAME_RE = re.compile(r'^asf[A-Za-z0-9._+-]*$')`, each with
   the comment the spec's design block gives: the declared script name is what a pipx `--suffix`
   install appends to (P3), so both spellings may be written and both must be read back.
   `Entry = collections.namedtuple('Entry', 'path route')`.
2. `running_asf(argv0=None, executable=None, which=shutil.which)` → `Entry` or `None`. `argv0`
   defaults to `sys.argv[0]`, `executable` to `sys.executable`; both are parameters so each route is
   drivable from a test without touching the process. The three routes in the spec's order:
   - `argv0` — made absolute, a bare name resolved through `which`. Counts when its basename matches
     `ENTRY_NAME_RE`, does not end `.py`, and the path is an executable file. The `.py` exclusion
     and the shape test are what keep `pytest`, `run_tests.py` and `asf/cli.py` out (D2, PD7).
   - `venv` — `os.path.join(dirname(abspath(executable)), ENTRY_POINT_NAME)`. Counts when it is an
     executable file, its `#!` line names `executable` or its realpath, **and** `same_install()`.
   - `path` — `which(ENTRY_POINT_NAME)`, made absolute. Counts when it is an executable file.
3. `same_install()` — `importlib.metadata.distribution(drift.PACKAGE_NAME)` (`'asf-factory'`,
   `asf/drift.py:20`), then either its `locate_file('asf/__init__.py')` is the same file as
   `asf.__file__` (`os.path.samefile`, guarded for `OSError`) or its `direct_url.json` is editable
   with a url path equal to `drift.factory_root()` (P17). `False` when the distribution is not found,
   and `False` for a `PYTHONPATH` shadow — which is the snapshot case the guard exists for (P12, D3).
   It raises nothing: every lookup failure is `False`.
4. `runnable_asf(which=shutil.which, argv0=None, executable=None)` keeps its name and its
   `(path, refusal)` contract, so P2's three writers and PD7's twenty-three call sites are untouched
   in shape. It returns `running_asf(...)`'s `path`, or:
   - nothing answered — `NEEDS OPERATOR: this asf install has no entry point to name (argv[0]
     <argv0>, none beside <executable>, none on PATH) — pipx install asf-factory`;
   - a route answered with a path that is not an executable file — today's line, byte for byte:
     `NEEDS OPERATOR: <path> is not an executable asf — no hook is written naming it; pipx install
     asf-factory`. `tests/test_install.py:1270` asserts this one and it does not move.
5. The three writers take the resolved path unchanged: `_git_hook_body`'s `exec "<asf>" redact`, the
   foreign-hook refusal's `add the line: "<asf>" redact …`, and `hook_command`'s `<asf> hook <name>`.
   None of their surrounding text changes — only the first word of the command each writes.
6. `install`'s summary gains the route and the path: `hooks: … ; entry: <path> (<route>)`, the route
   being the `Entry.route` literal (`argv0`, `venv`, `path`). `rc` stays 0/2. The clause is appended
   to the existing string, so `assertIn` on any earlier clause still holds (PD8 is about the two
   `assertEqual`s only).
7. `tests/test_install.py:1087-1089` and `:1098-1100` take the new summary, with the `entry:` clause
   built from the same `self.asf` the case injects and the route `path` — the injected `which` is
   what answers under the suite (PD7). Nothing else in `HooksInstallTest` is touched; `:1126`'s
   refusal `startswith` moves to the new no-entry-point line, and `:1270`'s does not move at all.
8. `RunningAsfLadderTests`: a temp bin dir holding `asf`, `asf-live` and a `pytest` stub. Each route
   is driven alone — `argv0` pointing at `asf-live` with `which` returning `asf` answers
   `Entry(<…>/asf-live, 'argv0')`; an `argv0` of `pytest`, of `asf/cli.py`, of a non-executable
   `asf`, and of a directory each fall through to the next route; with `argv0` falling through and a
   fixture venv whose script and shebang line up, the answer is `('venv')`; with both falling
   through, `which`'s answer and `('path')`. Each case asserts the route as well as the path, so an
   answer reached by the wrong ladder step fails.
9. `RunnableAsfRefusalTests`: nothing on any route gives the new line, and the line names all three
   inputs (`argv[0]`, the interpreter dir, `PATH`); a route answering with a missing path, a
   non-executable file and a directory each give today's `is not an executable asf` line, byte for
   byte, and write nothing.
10. `SameInstallGuardTests`: a fixture venv with a real `asf` script and a matching shebang, whose
    `asf-factory` dist-info `locate_file` points at another tree, is refused by the `venv` route and
    the ladder falls through to `PATH`; the same venv whose dist-info resolves to the running
    package is taken. The snapshot shape (P12) is built as a `PYTHONPATH` shadow — the package
    importable from a tree the distribution does not name — and asserted to fall through, which is
    D3's whole reason.
11. `WrittenCommandsNameTheRunningInstallTests`: with the ladder answering `<bin>/asf-live`, the git
    hook body's `exec` line, the foreign-hook refusal line and every settings command all name
    `<bin>/asf-live`, suffix and all, and none of the three names the `asf` that `which` returns.
    The foreign-hook case is built the way `tests/test_install.py:1332-1341` builds one, so the card's
    own report — a live install printing the dev install's path — is the assertion that fails
    without this Task.
12. `docs/guide/troubleshooting.md:43`: the `asf is not on PATH` row becomes the new refusal and its
    remedy (rerun the installer, or `pipx install asf-factory`, from the install the hook should
    name). `:45`'s quoted foreign-hook line keeps its shape — only the path inside it is now the
    running install's, which the row already writes as `<asf>`. `:16`'s installer row is a different
    string (`asf is not on PATH after pipx install`) and is not touched.

### Task 3: repair without downgrade — one rule, two call sites
stories: S-32652
writes: asf/hooks.py, tests/test_hooks_entry.py, tests/test_install.py, tests/test_check_staged.py
after: Task 1, Task 2

The spec's fourth **In** bullet and the `repair without downgrade` block: `entry_point_source` reads
editability off files (D8), `prefer_entry` answers the one question (D6, D7), and `ensure_git_hooks`
and `merge` both ask it. The repair edits the line, never the file (PD4), and never the bare form
(PD5).

**Files**

- `asf/hooks.py` — `entry_point_source`, `prefer_entry`, `repair_entry` (the line substitution),
  `ensure_git_hooks`'s third upgrade, `merge`'s gated replacement
- `tests/test_hooks_entry.py` — `EntryPointSourceTests`, `HookRepairTests`, `NeverDowngradesTests`
- `tests/test_install.py` — `test_a_moved_asf_replaces_its_own_entry` restated (PD6)
- `tests/test_check_staged.py` — the record pre-commit's third line asserted to survive a repair

**Steps**

1. `entry_point_source(path)` → `('editable', <checkout>)` | `('installed', <site-packages>)` |
   `None`. It reads `path`'s first line for `#!<interpreter>`, takes that interpreter's prefix, and
   globs `lib/python*/site-packages/asf_factory-*.dist-info/direct_url.json` and
   `lib/*/site-packages/…`. `dir_info.editable` true → `('editable', <url path>)`; a dist-info
   without it → `('installed', <dir>)`. `None` for an unreadable or absent dist-info, a `#!/bin/sh`
   wrapper, a line that is not a shebang, and an unreadable `path`. It executes nothing (the spec's
   **Out**) and raises nothing: every failure is `None`.
2. `prefer_entry(written, running)` → `True` when `running` should replace `written` (D7): a
   `written` that is `None`, missing or not an executable file loses to any usable `running`; an
   `editable` `written` loses to a non-editable `running`; an unknown source on either side, or an
   equal pair, keeps `written`. `False` when `running` itself is not usable. `written is None`
   through PD5's bare-name rule reaches this as "no candidate", and the caller skips before asking —
   both paths agree, and the test pins it.
3. `repair_entry(text, name, entry)` — PD4's substitution: the matched line with its entry-point
   token replaced by `entry`, quoted the way `_git_hook_body` quotes it, and **every other byte of
   the file unchanged**. `None` when no line matches or the token is already `entry`. Built over the
   same match `hook_entry` returns, so the two cannot disagree about which line is the hook's.
