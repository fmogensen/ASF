# Plan F-0024 — the factory proposes; a person approves and merges

Epic: E-0001 — ASF 0.1 — a working factory. Spec: `docs/specs/f-0024.md` (approved). Branch:
`plan/F-0024`.

Five Tasks, cut along the spec's own §2 sections and its §3 fences: the set named once (Task 1),
the tenth class and the hook that refuses (Task 2), `asf propose` and the card it files (Task 3),
the merge gate that names that card (Task 4), and the three surfaces plus the config (Task 5).

The cut is almost entirely sequential, and honestly so: four of the five write `asf/approvals.py`
and four write `tests/test_amendable.py`, because the spec adds one class, one hook arm, one ledger
event and one doctor row to a module that already holds all four of those things. Splitting them
across disjoint files would mean inventing a module the spec does not name. The queue is declared
rather than dodged.

Wave order: **1 → 2 → 3 → 4 ‖ 5** — Tasks 4 and 5 are both eligible once Task 3 lands and queue
against each other on `tests/test_amendable.py`.

§3.7's rule that the whole suite and both generic gates stay green binds every Task, so every Gate
below runs `python3 tools/run_tests.py` and `bash tools/check_generic.sh` beside its own fence.

3. `asf/amendable.py`, the data: `Kind`, and `kinds(product)` returning the six in §2.1's order —

   because §2.1's signature list names it; its test is Task 5's (PD9).
9. `merge_class` and the two `approvals` edits of PD8 and PD13.
10. `SetTests` per §3.1: the six kinds and their order; every glob asserted **equal to the constant
    it came from** — `core.TYPES['rule'][0]`, `hooks.CHECKS_DIR`, `hooks.GIT_HOOK_GLOBS`,
    `hooks.RUNTIME_SETTINGS_GLOBS`, `conv.briefs_dir`, `conv.evals_dir`,
    `briefs.build.TEMPLATES_DIR` — so a literal copied into `amendable.py` fails the test before it
    fails `check_conventions.sh`; `paths` unset → the defaults, a list → that list, `[]` → empty;
    `kind_of` for one path in each kind and `None` for `docs/specs/f-0024.md`,
    `plugin/skills/status/SKILL.md` and `asf/approvals.py` (§1.2: the descriptions are not the set);
