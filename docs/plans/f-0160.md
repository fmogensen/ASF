# Plan F-0160 — a session ends only when its process is gone, and the process is stopped rather than assumed gone

Epic: E-0001 — ASF 0.1 — a working factory. Spec: `docs/specs/f-0160.md` (approved). Branch: `plan/F-0160`.

Three Tasks, cut so that **the stop lands before the rule that needs it**:

1. **the bill** — `health.settle_quiesced`, the identity guard both settle passes share, and its
   wiring before the judge loop. Nothing about `judge` changes, so nothing about the factory's
   behaviour changes: under today's `judge` a live run with a result is ended in the same pass it
   first has one, so it never has an `ended`-less run with a five-minute-quiet log to find. The
   function is live, tested, and idle.
2. **the rule** — `lifecycle.judge` never judges a live pid, plus the two other call sites that
   guard does not survive on its own (PD1). From here a finished-but-lingering process holds its
   seat until it is gone — and Task 1 is what makes it go.
3. **the visibility and the prose** — `stall.classify` stops treating a result as the end, and the
   four places the tree still writes the old rule down.

They run **1 → 2 → 3**, one at a time, and the order is not a convenience: landing the rule (2)
before the stop (1) would leave every lingering process holding its seat with nothing in the tree
able to end it and — until 3 — nothing able to report it. The footprints confirm the serialisation
independently: Tasks 1 and 2 both write `asf/workers/health.py`; Tasks 2 and 3 both write
`tests/test_workers.py`.

**Read PD1 before writing a line of Task 2.** The spec's design block says of `lifecycle.py`
*"Nothing else in the module moves"*, and it is wrong twice: one other caller of `judge` writes its
answer straight onto the ledger, and a second renders it. Neither is covered by a test that would go
red, which is why the measurement is here.

The last two fences of §Acceptance tests — `tests.test_workers.TestHealth` and the
whole-suite-plus-both-fences one — bind every Task, so every Gate and Acceptance block below carries
them beside its own.

### Task 1: health stops a live process that wrote its result and will not exit
stories: S-50901
writes: asf/workers/health.py, tests/test_ended_run_liveness.py
after: none

The spec's second and third **In** bullets and `## The design` §`asf/workers/health.py` in full —
`own_process`, `QUIESCE_GRACE_S`, `quiet_for`, `settle_quiesced`, `stopped_pids`, `not_alive`, and
the call in `health()` before the per-run loop. This is the bill the card's rule runs up, and it
lands **first** so the rule never ships without it.

Nothing the factory does changes when this Task lands, and that is by design: today's `judge` ends a
live run at its first result, so a run with no `ended` line, a result, and a log quiet for five
minutes does not exist to be found. `settle_quiesced` is live, tested against real processes, and
idle until Task 2.

Read **PD4** (the candidate walk comes before the observation read), **PD5** (no `alive`, no `now`),
**PD6** (the `isinstance` guard), **PD10** and **PD11** (what the tests need) before starting.

**Files**

- `asf/workers/health.py` — `own_process` lifted out of `settle_ended`'s loop (`:217-220`);
  `QUIESCE_GRACE_S`; `quiet_for`; `settle_quiesced` beside `settle_ended` (`:161-228`);
  `stopped_pids` and `not_alive` lifted from the wiring at `:724-728`; the new call and rewrap after
  `:594`; one new paragraph in the module docstring at `:22` (PD3)
- `tests/test_ended_run_liveness.py` — `QuiescedLiveRunTests`

**Steps**

1. `own_process(run, pid, observed_by_pid, cmdline, binary)` with the spec's body and docstring byte
   for byte, placed above `settle_ended`. Three clauses, and all three are the safety argument, not
   style (P10, D10): no observed session at the pid, or one whose `owner` is not `asf`, or a run with
   no `session`, or an observed session whose `session` is not this run's → `False`; then
   `is_print_worker(cmdline(pid), binary)`. The `not run.get('session')` clause lives **inside** the
   helper even though `settle_ended` also filters on it at `:200` — a caller that forgets it must not
   be able to signal anything.
2. `settle_ended`'s loop (`:217-220`) is rewritten over the helper: `if not own_process(run, pid,
   by_pid, cmdline, binary): continue`. Its behaviour is unchanged — the four cases pinned at
   `tests/test_ended_run_liveness.py:161-181` are the proof, and they must pass without being
   touched.
3. `QUIESCE_GRACE_S = LINGER_GRACE_S` beside `LINGER_GRACE_S` (`:74-77`), with the spec's three-line
   `#:` comment byte for byte — it is D3's whole argument (the same question, a different anchor,
   because a live run has no `ended` stamp) and a constant with that comment attached is what stops
   the next reader adding a config key for it.
4. `quiet_for(log_path, now)` — `now - os.path.getmtime(log_path)`, `None` on `OSError`/`TypeError`,
   which is the same guard `stall.classify` (`:87-90`) and `continuation.dead` use. No log, an
   unreadable log or a log in the future is never a candidate.
5. `settle_quiesced(product, sessions, now=None, fix=True, session_source=None, cmdline=None,
   wait_s=STOP_WAIT_S, grace_s=QUIESCE_GRACE_S)` with the spec's docstring byte for byte, placed
   directly after `settle_ended`. Its shape is `settle_ended`'s, in this order (PD4):
   - walk `sessions.items()` and collect `(job, run, int(pid))` for a run with **no** `ended`, a pid
     that is **not** `cloudpid.is_token` (D6 — a cloud log is quiet by design and a cloud result
     already implies a terminal token, P15/P18), a `session` id, `runtime_mod.read_result(run.get('log'))
     is not None`, and `quiet_for(run.get('log'), now) >= grace_s`; `int(pid)` in a
     `try/except (TypeError, ValueError): continue` exactly as `:198-201` does;
   - `if not local: return found` — **before** `load_cfg()` and `observe.read` (PD4);
   - one `spawn_mod.load_cfg()`, one `observe.read(cfg, [], source=session_source)` with `if why:
     return found`, the `by_pid` dict, `cmdline = cmdline or command_line`, `binary` from
     `worker_pool.binary` — the five lines at `:204-215`, unchanged;
   - per candidate: `if not own_process(...): continue`; `mins = int(quiet_for(log, now) // 60)`;
     without `fix`, append `(job, 'lingering', f'pid {pid}: its run closed with a result and its log
     has been quiet {mins}m, still running')` and continue; with `fix`, `how = stop_process(pid,
     wait_s)` and append `(job, 'stopped', f'pid {pid} ({how}): its run closed with a result and its
     log has been quiet {mins}m, still running')`.
   The pid is the detail's **second whitespace-separated token** in both rows, which is what
   `stopped_pids` reads (P12). Nothing here writes to the ledger — no `update_session`, no field, no
   `end_reason` (Records, D4). The run is ended by `judge` on the next gather, on its own evidence.
6. `stopped_pids(rows)` and `not_alive(alive, pids)` with the spec's docstrings, lifted from
