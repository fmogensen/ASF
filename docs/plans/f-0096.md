# Plan F-0096 — the wave says why it is idle, and which decisions would end it

Epic: E-0002 — ASF 0.2 — self-improvement. Spec: `docs/specs/f-0096.md` (approved). Branch: `plan/F-0096`.

Five Tasks, cut along the spec's own §1.1 list by the module that changes: the row an undecided
card gets (Task 1), the accounting and its render (Task 2), the wave step that prints it and
remembers that it did (Task 3), `asf next`'s footer and `--all` (Task 4), and the status table's
`Decisions` row (Task 5).

Everything downstream reads `rows.decision_rows(product)` and `rows.undecided_rows(...)` — the one
cap and the one ranking (D6) — so Task 1 lands first and alone. Tasks 2, 4 and 5 then have disjoint
footprints and run together; Task 3 needs both the cap and the module, so it is last.

Wave order: **1 → 2 ‖ 4 ‖ 5 → 3**.

§3.6's rule binds every Task: the whole suite stays green and both gates stay clean, so every Gate
below runs `python3 tools/run_tests.py`, `bash tools/check_generic.sh` and
`bash tools/check_conventions.sh` beside its own fence.

### Task 1: the undecided card's ranked, non-launching row, and the one cap
stories: S-17250
writes: asf/feeder/rows.py, tests/test_feeder.py, tests/fixtures/feeder/next-s1-held.md, tests/fixtures/feeder/next-s1-unheld.md

§2.1 and §2.6: `UNDECIDED → DECIDE` joins the row kinds, `conventions.decision_rows` (default 5) is
the one knob for how many get one, and `candidates()`/`plan_rows()` take `decision_limit` so a
caller can ask for all of them. Nothing launches: the row is the sentence *this card is what a free
slot is waiting for*, in the one table that says what the tick would start (P2, P3).

**Files**

- `asf/feeder/rows.py` — `UNDECIDED`, `NEEDS_DECISION` and `DECISION_ROWS = 5` beside the other
  kind constants (`:41-62`); `decision_rows(product)` beside `attempt_limit` (`:134`);
  `undecided_rows(items, product, busy, limit=None)`; `hold_unlanded`'s `keeps` grows
  `NEEDS_DECISION` (`:465`, D11); `candidates(..., decision_limit=None)` appends
  `undecided_rows(...)` after `feature_rows` and before `hold_unlanded` (`:496-497`);
  `plan_rows(..., decision_limit=None)` passes it through (`:508`); the module docstring's row-kind
  list (`:9-30`).
- `tests/test_feeder.py` — `UndecidedRowsTests` (new, §3.1); `RowsTest.test_undecided_and_removed_cards_emit_nothing`
  split (PD5); `CliTest.test_next_json`'s expected ids; `RenderTest` renamed `TableTests` (PD6).
- `tests/fixtures/feeder/next-s1-held.md`, `tests/fixtures/feeder/next-s1-unheld.md` — regenerated
  per PD5: two new rows and one, counted by hand before the file is written.

**Steps**

1. The three constants, and `decision_rows(product)` — `_conventions(product).get('decision_rows')`,
   falling back to `DECISION_ROWS` when the value is not an `int >= 0`, the shape `attempt_limit`
   has (PD4). `0` means *every one*.
2. `undecided_rows(items, product, busy, limit=None)`: the roots are every open Feature and every
   open S1/S2 Bug (`ix.of_type`, `is_open`) whose `decided` is not `True` and whose id is not in
   `busy`; a `blocked:` one is skipped — it is the accounting's `blocked` bucket, and two rows for
   one card would be two answers to one question (§2.1). Tier is `0` for an S1 Bug, `1` for an S2,
   `2` for a Feature (D10). Order: tier, then `ix.rank`, then id — an unranked card last (P7). The
   cut is `limit` when given, else `decision_rows(product)`; `0` returns all.
3. Each row: `kind=UNDECIDED`, `action=NEEDS_DECISION`, `waits_on='decision'`,
   `brief_kind='spec'` for a Feature and `'fix-bug'` for a Bug, `branch` the one that kind's session
   would use (`branch_for(product, 'spec'|'fix', id)`), `feature_id` the Feature above a Bug or the
   card itself, and
   `reason=f"undecided {ix.age(v.get('stage_since'))} — {CARD_SPEC if … else BUG_FIX} waits for decided: true"`.
   No new `Row` field is added: the dataclass already carries every one of these.
4. `hold_unlanded`: `keeps` grows `NEEDS_DECISION` beside `ON_TRUNK` and `PARKED` (D11) — an
   unlanded `after:` is a second reason, and overwriting the first with it hides the row the gate
   exists to print.
5. `candidates(..., decision_limit=None)` appends the rows where §2.1 says, before `hold_unlanded`,
   so the tier sort (`:499-505`) places them; `plan_rows(..., decision_limit=None)` threads it.
   Emit order within tier 0 keeps `bug_rows`' launching rows ahead of a decision row (P9).
6. `UndecidedRowsTests`, as §3.1 lists it: six open Features, one decided and five not, give one
   `CARD → SPEC` and five `UNDECIDED → DECIDE` rows whose `action` is `NEEDS DECISION`, whose
   `launches` is False and whose `reason` names the age and `decided: true`; the five in `ix.rank`
   order with the unranked one last; an undecided S1 Bug at tier 0 and an S2 at tier 1; a `blocked:`
   undecided Feature gets no decision row; a decided-but-unstarted card, a Closed card and a Task
   are absent; `conventions.decision_rows: 2` cuts it to two and `decision_limit=0` returns five;
   `tiers.select` keeps the rows while `tiers.free_slots(inflight, capacity)` is unchanged; and
   `hold_unlanded` leaves a decision row's action alone when the card has an unlanded `after:`.
7. PD5's three existing cases, then the two goldens: run the suite, read the two new tables, check
   each added line against §2.1's row before writing it into the fixture.
8. PD6's rename, in the same diff as the goldens those cases assert.

### Task 2: `asf/feeder/idle.py` — the accounting, its residue, and the three lines
stories: S-17251, S-17252
writes: asf/feeder/idle.py, tests/test_idle.py
after: Task 1

§2.2: every root the feeder starts work from lands in exactly one bucket, and the last bucket is
`other` — a root that matched no rule is *named*, not dropped, so a gate added later is visible the
tick it starts hiding cards (D3). Plus the one-to-three line render and the operator sentence. The
module is reachable from a view without importing the tick (D2), which is what makes `asf next`,
`asf status` and the wave say the same thing.

**Files**

- `asf/feeder/idle.py` — **new**: §2.2's module docstring, `BUCKETS`, the `Idle` dataclass with
  its `dry` property, `account(...)`, `lines(...)` and `needs_operator(...)`.
- `tests/test_idle.py` — **new**: `AccountingTests`, `ResidueTests`, `LinesTests` (§3.2).

**Steps**

1. The module docstring §2.2 fences, and `BUCKETS` in classification order:
   `('launching', 'in flight', 'no slot', 'held', 'blocked', 'undecided', 'waiting', 'landed',
   'other')`.
2. `Idle`: `slots`, `launched`, `buckets` (`{bucket: [(id, why)]}` in `BUCKETS` order, empty ones
   kept), `undecided` (`[(id, rank, age)]`, every one, uncut), `shown`; `dry` is
   `self.slots > 0 and self.launched == 0`.
3. `account(items, product, candidates, selected, inflight, busy, capacity, held=None)`: the roots
   are D4's — every open Feature and open S1/S2 Bug. Per root, `mine = [r for r in candidates if
   r.item_id == R['id'] or r.feature_id == R['id']]`, so a Feature's Tasks answer for it, and the
   first rule of §2.2's table that holds wins. `held` defaults to `{}` for the views, which have no
   ledger of holds to read.
4. The `why` strings exactly as §2.2's table gives them: `T-0031 PLAN → CODE`,
   `task-t-0030 12m` / `awaiting harvest`, `would launch: capacity {n}`,
   `held touch_production (human-now)`, `blocked by B-0031` (from the item's `blocked_by_open`,
   `asf/record/ingest.py:194`), `undecided 6d, rank 3`, the row's own `waits_on`
   (`WAITS ON T-0029`), `landed`, `no row, no reason`. `in flight` tests the root and everything in
   `ix.subtree(items, R)` against `inflight` and `busy`.
5. `slots` is `tiers.free_slots(inflight, capacity)` less the launches already counted; `undecided`
   is built through `rows.undecided_rows(items, product, busy, limit=0)` so its order is D6's one
   ranking (PD8, PD13), with `ix.rank` and `ix.age` read off the items; `shown` is
   `rows.decision_rows(product)`.
6. `lines(idle, product=None, top=None)`: line 1 lists only the non-empty buckets in `BUCKETS`
   order, `launching` first, after `0 launched, 4 slots free`; line 2 only when something is
   undecided, naming `top or rows.decision_rows(product)` ids with rank and age, `·`-joined, ending
   `— +70 more (asf next --all)` when the cap hid any; line 3 only when `other` is non-empty, with
   its ids and `(no row and no reason: a gate this accounting does not know)`. Never none, never
   four.
7. `needs_operator(idle, product, groom_file)`: §2.2's sentence — the count, the idle slots, the
   groom file the next tick applies, and the runnable `asf set <top id> decided=true --product <p>`
   (`asf/record/setfield.py`); `None` when nothing is undecided.
8. `AccountingTests`: one index carrying a root for every bucket — a launching Feature, one whose
   Task is in flight, one whose row the capacity cut dropped, one held by `touch_production`, one
   `blocked:`, three undecided, one `WAITS ON T-0029`, one at stage `landed` — each in its own
   bucket with the `why` above, and `sum(len(v) for v in idle.buckets.values()) == len(roots)`.
9. `ResidueTests`, the standing test of D3: over that same index `other` is empty and `lines()`
   prints two lines, not three; then one root is mutated into a state no rule matches (decided,
   open, unblocked, no row, stage `spec-draft` with its live session removed) and the test asserts
   it appears in `other`, that its id is in the third line, and that nothing else moved.
10. `LinesTests`: the counts line lists only non-empty buckets in `BUCKETS` order; the decisions
    line names `decision_rows` ids with rank and age and ends `+70 more`; nothing undecided means no
    second line; `dry` is true at `slots=4, launched=0` and false at `slots=0` and at `launched=2`;
    `needs_operator` names the groom file, the count, the idle slots and a runnable
    `asf set … decided=true --product <p>`, and is `None` when nothing is undecided.

**Files**

- `tests/test_tick_steps.py` — `WaveSaysWhyTests` (new, §3.3), with `WaveStepTests.test_nothing_to_launch`
  folded into it; `WaveStepTests.test_rows_briefed_launched_and_logged` and `WaveStep`'s three
  `self.lines` assertions extended with the counts line they now print (PD10).

**Steps**

1. `run()` keeps its shape. After the launch loop and the `capacity` event, build the accounting
   from what is already in hand: `feeder_rows.candidates(items, product, running,
   **plan_inputs(product, ctx.record_root()))` for the uncut list (PD12), `planned` for the

2. The launches are counted first, so `idle.launched` is the wave's own result and `idle.slots` is

   `asf/tick/tick.py:167` computes it (PD11); True when any line is an `idle` event with

5. `flag = bool(idle.undecided) and not _flagged_today(ctx.record_root())`; when it is true, and
   only then, `out(idle_mod.needs_operator(idle, product, groom_file))` — the groom file from
   `plan_inputs`' `groom_state` when there is one, and the day's expected name when there is not.
6. The `idle` event, only on a dry tick (D9), with exactly §4's fields: `slots`, `undecided`, `top`
   (the first `feeder_rows.decision_rows(product)` ids), `buckets` (`{k: len(v)}` for the non-empty
   ones) and `flagged`. `ctx.event` adds `kind`, `product` and `ts` and needs no `metrics.SCHEMAS`
   entry (P5).
7. `WaveSaysWhyTests`, as §3.3 lists it: 73 undecided cards and four free slots give output with no
   `wave: nothing to launch` line at all, a counts line naming `73 undecided`, a decisions line
   naming the three top-ranked ids in rank order, and exactly one `NEEDS OPERATOR:` line; a second
   run the same day prints the counts and decisions lines again and **no** second `NEEDS OPERATOR`,
   because the day's events file already holds an `idle` event with `flagged: true`; a tick that
   launches two of six still prints the counts line; a tick with no free slot prints `0 slots free`
   and writes no `idle` event; and the event's fields are `slots`, `undecided`, `top`, `buckets`,
   `flagged`, asserted by reading the file back.
8. PD10's five existing assertions, extended in the same diff — each gains the line §2.3 now makes
   it print, and `test_nothing_to_launch`'s subject becomes `WaveSaysWhyTests`' first case.

### Task 4: `asf next` — the footer for what the cap hid, and `--all`
stories: S-17255
writes: asf/feeder/render.py, tests/test_feeder.py, tests/fixtures/feeder/index-undecided.json
after: Task 1

§2.4: the `NEXT` table's footer names the undecided cards the cap hid, and `asf next --all` prints
every one. One flag, one meaning — the table as the feeder sees it, uncut (D12).

**Files**

- `asf/feeder/render.py` — `table(rows, header=None, hidden=0)` grows the footer line;
  `cmd_next` passes `decision_limit=0` when `--all` and computes what the cap hid; `register()`

- `tests/test_feeder.py` — `NextAllTests` (new, §3.4), beside Task 1's `TableTests` (PD6).

**Steps**

   --all)`. The header's `N rows · M would launch` is unchanged, and the `| — | nothing to start |`
   empty row is unchanged.
2. `cmd_next`: `--all` passes `decision_limit=0` into `plan_rows`; without it the product's
   `decision_rows` applies. The hidden count is the difference between the undecided roots and the

   table, not a row.
4. `register()`: `p.add_argument('--all', action='store_true', help=…)` — one flag, no `--limit`

5. `tests/fixtures/feeder/index-undecided.json`: an Epic and eight open undecided Features, ranked,
   nothing else — the shared `index.json` is not touched (PD7).
6. `NextAllTests`: over that fixture `asf next` prints five decision rows and the footer
   `— 3 more cards await a decision (asf next --all)`; `asf next --all` prints all eight and no
   footer; `--json` carries exactly the rows the table showed in each case.
