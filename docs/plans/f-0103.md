# Plan F-0103 — the factory reads its own ledger

Epic: E-0002 — ASF 0.2 — self-improvement. Spec: `docs/specs/f-0103.md` (approved). Branch: `plan/F-0103`.

Five Tasks, cut by owner — the module that gains the surface, as the spec's own §2 is cut. Task 1
is the outcome vocabulary in `lifecycle` (§2.1), Task 2 the four thresholds in `conventions` (§2.2),
Task 3 what the wave writes down and the ticks schema that carries it (§2.3), Task 4 the two
sources over the `sessions` stream (§2.4, §2.5) and the `found_in` seam in `_file_or_bump_bug`
(§2.7), Task 5 the source over the `ticks` stream (§2.6) and the whole-module test that says the
daily guard, the `file_bug` approval and the three old sources are unchanged (§3.6/T7).

Tasks 1, 2 and 3 write three disjoint sets and start at once. Tasks 4 and 5 both write
`asf/tick/file_bugs.py` and `tests/test_file_bugs.py`, so they queue; Task 4 needs Tasks 1 and 2
landed (it calls `outcome_class` and reads `conv.outcome_share_pct`), and Task 5 needs Task 4's
`found_in` seam and its window helper.

Wave order: **1 ‖ 2 ‖ 3 → 4 → 5**.

§3's rule that the whole suite stays green binds every Task, so every Gate below runs
`python3 tools/run_tests.py` beside its own fence.

Task 3 adds `wave` and **only** `wave`, as §1.2 lists. Widening the schema to the two keys the tick has always written is a real defect and not this card's; it is named here so nobody reads its absence as an oversight. |
| PD7 | **`end_reason: stopped` is an operator's decision, not a failing outcome** | §1.1 enumerates the vocabulary `lifecycle` owns and omits `STOPPED` (`asf/workers/lifecycle.py:87`), which `lifecycle.stop` writes on every session a person ends. Under §2.1's rules as written it falls through to `other` — so an operator stopping ten sessions in a quiet hour files an `outcome: other` S2 Bug against the factory for doing what they asked. Task 1 adds one line to §2.1's rule list: `stopped` → `None`, on the same ground as `running` — the line describes no outcome *of the factory's own*. This drops it from numerator and denominator alike, which is the only reading that leaves the rate honest. `OUTCOME_CLASSES` is unchanged (`stopped` was never in it) and T1 is unaffected. |
| PD8 | `OUTCOME_CLASSES` is built, not re-typed | §2.1 shows the tuple as literals, five of which are already constants in the same module (`FINISHED`, `DEAD_PID`, `PUSHED_AFTER_STOP`, `EMPTY_BRANCH`) or in one it already imports at module level (`runtime as runtime_mod`, `asf/workers/lifecycle.py:51`): the four CLI names are `runtime_mod.FAILURE_SIGNATURES`' first fields and `unpushed work` is `runtime_mod.report.UNPUSHED`. Task 1 composes the tuple from those, in §2.1's order, so the value is byte-identical and the day `runtime` renames `quota` the class follows. Two new literals only: `NOT_PUSHED = 'not pushed'` (which `push_gap` then interpolates, so the prefix has one owner) and `OTHER = 'other'`. |
| PD9 | `empty branch` is matched by prefix, because the constant is longer than the class | `EMPTY_BRANCH` is `'empty branch: nothing to land'` (`asf/workers/lifecycle.py:89`), and `judge` writes `failed: empty branch: nothing to land`. The class is the part before the colon, derived (`EMPTY_BRANCH.split(':')[0]`), and matched by prefix exactly as §2.1 says — as `not pushed…` is, whose text carries two counts. |
| PD10 | The share is compared unrounded and printed rounded | §2.4's title says `14 %` for 7 of 49 (14.28…). The threshold test is on the exact fraction (`100 * n / total > conv.outcome_share_pct`), the title's number is `round()` of it. Comparing the rounded value would file at a true 10.4 % under a 10 % threshold and print `10 % (threshold 10 %)`, which reads as a bug in the Bug. |
| PD11 | Every new `info` dict carries `runs: []` | `_file_or_bump_bug` reads `info['runs']` unguarded (`asf/tick/file_bugs.py:176`, `:193`). A source that omits it raises `KeyError` on the first bump. §2.5 already says `links: {}` for the repeat; Tasks 4 and 5 give all three sources `'runs': []`, and none of them writes `links`. |
| PD12 | `EVIDENCE_CAP` binds all three new sources | §2.4 names `EVIDENCE_CAP = 20` for the rate only. A repeat group and an idle streak are each unbounded from above — a signature bumped across a bad week would carry a body of hundreds of lines. All three cap at `EVIDENCE_CAP`, keeping the newest: for the rate and the repeat that is §2.4's own rule, for the streak it keeps the ticks nearest the present and the New-Task line. T6's *one evidence line per tick* holds unchanged for its six-tick streak. |
| PD13 | What `new_tasks` counts | §2.3 says "the record's New Tasks — the work that exists and did not start", and `wave_state` is pure over `items`, so it counts every item whose `type` is `task` and whose `state` (defaulting to `New`) is `New`. It is deliberately *not* the feeder's own narrower filter (`asf/feeder/rows.py:350`, which also drops `busy` and `blocked` ids): a Task the wave declined to launch because it is blocked is precisely the work this card exists to notice. |
| PD14 | Where the gate name comes from | `Row.waits_on` is already set on every non-launching row the feeder makes — `trunk` for `ON TRUNK` (`asf/feeder/rows.py:364`), `operator` for `PARKED` (`:263`), the id for `WAITS ON <id>` (`:374`), `reshape` / `confirm` (`:381`, `:391`). The first-word-of-the-action fallback in §2.3 is therefore a guard against a future row, not a path any current one takes; it is implemented and tested as a guard. A row whose item is in `held` is `held <class>`, taken from `approvals.raise_holds`' `{item: (cls, level)}`. |
| PD15 | `ctx.wave` when the wave step did not run, or raised | `Context.__init__` sets `self.wave = {}` (§2.3), and `run` sets it before each of its two returns — the `not worker_rows` early return and the end. A step that raises therefore leaves `{}`, which §2.6 reads as a break in the streak rather than as an idle wave. That is the safe default in both directions: a crashed wave does not file a stalled-wave Bug, and does not silently continue one. |
| PD16 | The fixtures need a `metrics/sessions` directory | `tests/test_file_bugs.make_repo` makes `metrics/ci` and `metrics/ticks` and no more (`tests/test_file_bugs.py:34`). Task 4 adds `metrics/sessions` there and a `write_session_line` helper beside `write_tick_line`, which Task 5's integration test then reuses. |

PD6 and PD7 are the two places this plan says the spec is wrong. PD6 declines to widen a schema the
spec's own §1.2 does not list; PD7 adds one rule the spec's §1.1 enumeration missed, and says why
the rate is wrong without it.

### Task 1: `outcome_class` — one owner for what a session's end means
stories: S-17350
writes: asf/workers/lifecycle.py, tests/test_lifecycle.py
after: none

§2.1: the classes a session's `end_reason` falls into, and the one pure function from a string to
one of them. `lifecycle` writes every one of those strings, so it is the module that reads them
back (§1.4). Nothing calls it yet — Task 4 is its first caller.

**Files**

- `asf/workers/lifecycle.py` — `NOT_PUSHED`, `OTHER`, `OUTCOME_CLASSES`, `FAILING_CLASSES`,
  `outcome_class`; `push_gap` interpolating `NOT_PUSHED` instead of spelling it
- `tests/test_lifecycle.py` — `OutcomeClassTests`

**Steps**

1. Beside `EMPTY_BRANCH` (`asf/workers/lifecycle.py:89`): `NOT_PUSHED = 'not pushed'` and
   `OTHER = 'other'`, each with the doc comment §2.1 shows.
2. `OUTCOME_CLASSES` composed, not re-typed (PD8), in §2.1's order: `FINISHED`, `NOT_PUSHED`,
   `EMPTY_BRANCH.split(':')[0]`, `DEAD_PID`, `PUSHED_AFTER_STOP`, `runtime_mod.report.UNPUSHED`,
   the four `name`s of `runtime_mod.FAILURE_SIGNATURES`, `OTHER`. Then
   `FAILING_CLASSES = tuple(c for c in OUTCOME_CLASSES if c != FINISHED)`.
3. `push_gap` becomes `f'{NOT_PUSHED}: {ev.uncommitted} uncommitted file(s), {ev.unpushed} unpushed commit(s)'`
   — same bytes out, one owner for the prefix the classifier matches on.
4. `outcome_class(result)`, pure, no clock and no io, with §2.1's rules in order: strip and
   lowercase; empty / `None` / `running` / `unknown` → `None`; **`stopped` → `None` (PD7)**;
   `finished` → `FINISHED`; `dead pid` → `DEAD_PID`; else strip one leading `failed: ` — a bare
   `failed` → `OTHER` — and match the rest: `NOT_PUSHED` and the `empty branch` class by prefix,
   the remaining names exactly, anything else → `OTHER`.
5. `OutcomeClassTests`: T1's table, each row one assertion — `finished`, `dead pid`,
   `f'failed: {lc.push_gap(ev)}'` for a real `Evidence`, `f'failed: {lc.EMPTY_BRANCH}'`,
   `failed: quota`, `failed: unpushed work`, `failed: something nobody named`, bare `failed`,
   and `running` / `unknown` / `''` / `None` → `None`. Plus `stopped` → `None`, named as PD7's
   rule and not as a class.
6. The vocabulary invariant T1 asks for: every string `judge` can return classes to a member of
   `OUTCOME_CLASSES` — built as the set `{FINISHED, DEAD_PID, 'failed'}` ∪
   `{f'failed: {s}' for s in (push_gap(ev), EMPTY_BRANCH, report.UNPUSHED, *FAILURE_SIGNATURES names)}`,
   asserted class-by-class; and `set(FAILING_CLASSES) == set(OUTCOME_CLASSES) - {FINISHED}`.
7. Whitespace and case: `'  FAILED: Quota  '` classes as `quota`.

### Task 3: the wave writes down what held it, and the tick line carries it
stories: S-17354
writes: asf/tick/step_wave.py, asf/tick/tick.py, asf/metrics/metrics.py, tests/test_tick_steps.py, tests/test_metrics.py
after: none

§2.3: the one fact the wave knows and nothing else does — that it launched nothing, that New Tasks
existed anyway, and which gate held the rows it planned but did not launch. A pure function for the
answer, one key on the tick line, one key in the ticks schema. No printed line changes,
`wave: nothing to launch` included.

**Files**

- `asf/tick/step_wave.py` — `GATE_CAP`, `NO_ROW`, `wave_state`; `run` collecting the held and
  non-launching rows it already iterates and setting `ctx.wave` before each return
- `asf/tick/tick.py` — `Context.__init__` gains `self.wave = {}`; `tick_line` carries `wave=ctx.wave`
- `asf/metrics/metrics.py` — `SCHEMAS['ticks']['wave'] = (('dict',), {})`
- `tests/test_tick_steps.py` — `WaveStateTests`
- `tests/test_metrics.py` — `TickWaveSchemaTests`

**Steps**

1. `GATE_CAP = 10` and `NO_ROW = 'no row planned'` at module level in `step_wave`, with §2.3's
   doc comments.
2. `wave_state(planned, held, items, launching=0)`, pure, returning
   `{'idle': bool, 'new_tasks': int, 'new_task_ids': [...], 'gates': {gate: items}}`:
   - `idle` is `not launching`;
   - `new_tasks` / `new_task_ids` from `items` per PD13, ids sorted, capped at `GATE_CAP`, the
     count uncapped;
   - a gate per non-launching row: `held <class>` when the row's item is in `held`, else
     `row.waits_on`, else the first word of `row.action` (PD14); counted, not listed;
   - `gates = {NO_ROW: new_tasks}` when `planned` is empty and New Tasks exist; `{}` when neither.
3. `run` collects the rows it skips in the loop it already has — the `not row.launches` branch and
   the `row.item_id in held` branch — and sets `ctx.wave = wave_state(planned, held, items, launching=len(worker_rows))`
   before the `not worker_rows` return **and** before the final return (PD15). The `out()` calls,
   the `capacity` event, the `launch` events and `ctx.counts['launches']` are untouched.
4. `Context.__init__`: `self.wave = {}` beside `self.counts` (`asf/tick/tick.py:149`).
5. `tick_line`: `wave=ctx.wave` in the returned dict (`asf/tick/tick.py:415`). Nothing else on the
   line moves, and `write_tick_line` is unchanged.
6. `SCHEMAS['ticks']` gains `'wave': (('dict',), {})` and only that (PD6). No new rule in
   `validate`'s `ticks` branch: a `dict` is all the key promises.
7. `WaveStateTests` per T5: the three-row planned list (one `WAITS ON T-0044`, one `ON TRUNK`, one
   row whose item is in `held` as `('merge_pr', 'human-now')`) with `launching=0` →
   `idle: True`, the record's New Task count and ids capped at 10, and
   `gates == {'T-0044': 1, 'trunk': 1, 'held merge_pr': 1}`; the same with `launching=1` →
   `idle: False`; `planned=[]` with `n` New Tasks → `gates == {NO_ROW: n}`; a row with neither
   `waits_on` nor a launching action → the first word of its action.
8. In `WaveStepTests`: a tick over the existing fixture with `plan_rows` returning `[]` still
   prints exactly `wave: nothing to launch` and leaves `ctx.wave['idle']` true. In the tick's own
   end-to-end fixture: `asf tick --steps record,wave` writes a `metrics/ticks` line whose
   `wave.idle` is true, and `asf tick --steps record` writes one whose `wave` is `{}`.
9. `TickWaveSchemaTests` per T5: `metrics.validate('ticks', line, {})` accepts a line carrying
   `wave` and returns it unchanged; a line without `wave` comes back with `{}`; a `wave` that is

**Steps**

   §1.4 gives for 24 (a rate over a week hides a bad day and files late).

   must not.
4. `repeat_signatures(root, now, conv)`: group the same pass by `(ev.get('item') or ev.get('task'), cls)`
   over the failing classes; a group of at least `conv.repeat_failure_n` yields
   `signature: f'repeat: {key}: {cls}'`, `severity: 'S3'`, `found_in: 'dev'`, `runs: []`, no

6. `cmd_file_bugs`: the two `signatures.update(...)` lines of §2.7, after the three that are

7. The module docstring's source list gains the two new bullets, naming the stream each reads.
8. `make_repo` makes `metrics/sessions`; `write_session_line(root, day, obj)` beside
   `write_tick_line` (PD16).
9. `OutcomeRateTests` per T3: 49 events in window, 7 of them `failed: not pushed: 2 uncommitted
   file(s), 1 unpushed commit(s)` → one Bug, `signature: outcome: not pushed`, `severity: S2`,

   nothing; an event older than 24 h in neither numerator nor denominator; `result: running` lines
   changing no percentage. Then the guard: a second run the same day → `0 filed, 0 bumped`; a run
   dated the next day → `count: 2`, one new `## History` line, the title as first filed.
10. `RepeatFailureTests` per T4: two `dead pid` events for `T-0091` → one Bug,
    `signature: repeat: T-0091: dead pid`, `severity: S3`, `decided: false`, the title naming the
    Task and the result, both events in the body. Then: one event → nothing; one `dead pid` and one

    `task` (`spec-f-0096`); `repeat_failure_n: 3` turning the two-event case into nothing filed.
