# Plan F-0130 — merged history becomes each card's typed answer, and every open pre-ASF pull request gets one disposition

Epic: E-0004 — Control plane — the factory's dashboard, served from the record. Spec:
`docs/specs/f-0130.md` (approved). Branch: `plan/F-0130`.

Six Tasks, one per Story, cut so that **nothing writes a card until the record can read what was
written**:

1. **the two declarations** — `conventions.legacy_branch`, `conventions.legacy_review`, and both as
   checked keys of `validate_mapping`. One file, no reader yet; a misshapen declaration stops being
   silent (P15).
2. **the merge, read once** — `evidence.merge_branch`, and `asf/backfill/`'s reader and history pass.
   The trunk walk loses its `--since` and a legacy head branch resolves to a card. Still no write.
3. **the typed answer, and the rule waking up** — `apply.type_landings`, and `ingest`'s Task and Bug
   loops handing `landed=` to `closing.Ev`. This is the Task that makes the card pay: `closing`'s
   first rule has been dead since it was written (P5), and here it starts deciding cards.
4. **the `removed:` Feature, un-retired on evidence** — `apply.unretire`. It needs Task 3's landings
   on the children, because the evidence that un-retires a Feature *is* its children's typed answer.
5. **one disposition per open pull request** — `prs.disposition`, and the two lane calls that act on
   it. Pure over gathered facts; the lane still does every landing.
6. **the command, the table, and `--apply`** — `asf backfill`, its `surface` row, `report.py`, and
   the read-only default.

They run **1 → 2 → 3 → 4 → 5 → 6**, one at a time. The order is the card's own argument, not a
convenience: a declaration nothing reads is harmless, a mapping pass with no typed answer delivers
nothing, and a typed answer no `ingest` reads is PD5's measured dead end all over again. The
footprints confirm the serialisation independently — **five of the six Tasks write
`tests/test_backfill.py`**, because the spec's fences name five classes in that one module
(`HistoryMapping`, `TypedAnswers`, `UnretireRule`, `OpenPrDisposition`, `DryRunAndApply`) and the
fences are binding. Tasks 3 and 4 also both write `asf/backfill/apply.py`. There is no parallel
wave to be had here and the plan does not pretend there is one.

**Read PD1 through PD6 before writing a line of Task 2.** The spec's design carries four places
where following it literally ships something that cannot work: `merge_branch`'s signature cannot
satisfy its own acceptance test (PD2), `match._find_legacy` is the wrong entry point and silently
resolves a Task to its Feature (PD3), the merge-queue "batch expansion" is a subsystem that does not
need to exist (PD4), and §7's CLI block registers a parser with no dispatch arm, so
`asf backfill` would parse and do nothing (PD6). All four are named below with the correction.

The fences of §*The fences, and the suite* bind every Task, so every Gate and Acceptance block below
carries them beside its own.
