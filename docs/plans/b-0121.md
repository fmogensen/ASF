# B-0121 — plan: the console shows FACTORY STATUS on its own clock, by code

Item: B-0121 — Every product console shows the FACTORY STATUS table every 5 minutes, by code.
Epic: E-0001 — ASF 0.1 — a working factory. Branch: `fix/B-0121`. No spec exists; the Acceptance
below is the record.

## Cause

Each console got the FACTORY STATUS table on a clock only when an operator remembered to type
`/loop 5m /asf:status` by hand. Nothing in the plugin or the CLI started that loop itself, so a
fresh console showed nothing until someone typed the command — the console half of B-0087 (the
per-tick digest and `asf watch`), which already wires `asf watch` into the console but leaves the
table itself to memory.

## Task 1 — a configurable console-feed command, wired into the CLI and the generated plugin

writes: `asf/console_feed.py` `asf/cli.py` `asf/conventions.py` `asf/plugin_build.py` `asf/views/header.py` `.claude-plugin/marketplace.json` `plugin/.claude-plugin/plugin.json` `plugin/hooks/hooks.json` `plugin/skills/console-feed/SKILL.md` `tests/test_console_feed.py` `tests/test_plugin.py` `tests/test_env.py`

- Step 1: `asf/console_feed.py` — `parse_every(value)` turns a bare number (minutes), a
  unit-suffixed duration (`30s`/`5m`/`1h`), `off`/`0`/`none`, or an unreadable value into seconds
  or `None` (`off`), falling back to `DEFAULT_EVERY` (`5m`) rather than silently going quiet on a
  typo. `resolve_every(product, config)` reads the product's own
  `conventions.flags.console_status_every` first, else the operator's `config.yaml`
  `console.status_every`, else the default. `due(last, now, interval_seconds)` is `True` with no
  marker yet (`last is None`) so the first call of a session always shows the table, and
  otherwise compares the elapsed seconds to the interval. `run_once(product, root, now,
  render_status=None)` renders the FACTORY STATUS table (`asf.views.status.render`, injectable for
  a fixed-clock test) plus `_ticks_since(product, since)` — the tick digest lines
  (`asf.tick.watch.digest_lines`) landed after the last marker — and advances a per-product
  marker (`state/<product>/console-feed.json`) on every print; returns `''` when not due.
- Step 2: `asf/cli.py` — register `console-feed` (`--product`) and, via
  `console_feed.register_hint`, `console-feed-hint` (`--product`), both dispatched from `_main`
  (`console-feed` alongside the other view commands, through `resolve_record`; `console-feed-hint`
  runs `cmd_console_feed_hint`, which prints `hint_line(seconds)` — the one line that starts the
  loop — only when a product resolves and its feed is not `off`).
- Step 3: `asf/conventions.py` — add `console_status_every` to `KNOWN_FLAGS`: a product-file flag
  under `conventions.flags`, never a new top-level `PRODUCT_FIELDS` key (same reasoning as
  `upgrade` — a product file is read by whichever `asf` is pinned to it, and only `flags` is read
  verbatim at every pinned version).
- Step 4: `asf/plugin_build.py` — add `'console-feed'` to `VIEWS` so `asf plugin build` writes its
  skill; add `FEED_HOOK_COMMAND` and a second `SessionStart` hook group in `render_hooks_json()`
  that runs `console-feed-hint` after the existing console-rules hook, so no session has to
  remember to start the loop — the hook's own stdout is the instruction. `asf/views/header.py`
  gains the `'console-feed'` → `FACTORY STATUS` title the view prints under, and `asf plugin
  build`'s own output lands in the tree with it: `plugin/skills/console-feed/SKILL.md` (the new
  skill), the second `SessionStart` group in `plugin/hooks/hooks.json`, and the command list in
  `plugin/.claude-plugin/plugin.json` and `.claude-plugin/marketplace.json` — generated files, in
  `writes:` for the same reason `docs/plans/b-0090.md` carries its own `plugin/hooks/hooks.json`.
- Step 5: tests —
  - `tests/test_console_feed.py`: `ParseEveryTests`, `ResolveEveryTests`, `HintLineTests`,
    `RunOnceTests` (first call always due with no deltas, a call inside the interval prints
    nothing, a call past the interval prints the table and the deltas since the last one, `off`
    never prints), `HintCommandTests` (no product resolves prints nothing, a resolved product with
    the feed off prints nothing, a resolved product prints the hint).
  - `tests/test_plugin.py::test_b0121_plugin_ships_a_hook_that_starts_the_status_feed` — the
    generated `plugin/hooks/hooks.json` carries a `SessionStart` hook whose command names
    `console-feed-hint`, both `console-feed` and `console-feed-hint` are registered CLI commands,
    and `plugin_build.diff()` is empty.
  - `tests/test_env.py` — `console_status_every` is a planned flag value (`'5m'`), read back
    verbatim through `conventions.flags` like every other flag.

## Acceptance

- [x] A console with `ASF_PRODUCT` (or `default_product`) set and `console.status_every` not
      `off` starts the FACTORY STATUS feed with no operator action, via the plugin's generated
      `SessionStart` hook (`tests.test_plugin.PluginTests.test_b0121_plugin_ships_a_hook_that_starts_the_status_feed`).
- [x] The interval is configurable per product (`conventions.flags.console_status_every`) and
      operator-wide (`config.yaml`'s `console.status_every`), defaults to 5 minutes, and `off`/`0`
      disables it (`tests.test_console_feed.ParseEveryTests`, `tests.test_console_feed.ResolveEveryTests`).
- [x] `/asf:console-feed` prints the FACTORY STATUS table plus the tick digest deltas since the
      last print, nothing when not yet due (`tests.test_console_feed.RunOnceTests`).

## Accepted costs

`_ticks_since` reads only the clock's own UTC day's tick-trace file, so a feed gap spanning
midnight shows fewer deltas than actually landed — the smallest cost of the smallest fix, not
blocking.
