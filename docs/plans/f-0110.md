# Plan F-0110 — the product a view shows, and saying so

Epic: E-0001 — ASF 0.1 — a working factory. Spec: `docs/specs/f-0110.md` (approved). Branch: `plan/F-0110`.

Five Tasks, cut the way the spec's **In** is cut — by the seam that gains the surface. Task 1 is
`asf/env.py`: the one function that owns the order and the containment test that replaces the string
compare. Task 2 is `cli.resolve_record` and the four call sites that spell the order out by argument
position — every record command and the nine views dispatched through it. Task 3 is the four
commands that bypass `resolve_record` — `next`, `brief`, `capacity`, `doctor`. Task 4 is the
installer's closing lines. Task 5 is the generated skills, the README and the guide.

Three need nothing landed and start at once — Task 1 (the function), Task 4 (a heredoc and its first
assertions) and Task 5 (prose and a regenerated tree; #198 already made the four-step order true, so
the sentence it writes is not a promise about unlanded code). Task 2 needs Task 1's
`resolve_product`, because the source token it prints is that function's second field. Task 3 needs
Task 2's `product_line`, which is the formatter all four of its commands call.

Wave order: **1 ‖ 4 ‖ 5 → 2 → 3**.

Tasks 2 and 3 both write `tests/test_path_resolution.py` and run one after the other whatever their
`after:` says — see PD4, which is the one place this plan says the spec is wrong about its own
footprint.

§Acceptance tests' last fence — the whole suite as CI runs it — binds every Task, so every Gate
below runs `python3 tools/run_tests.py` beside its own.

### Task 1: `env.resolve_product` — one function owns the order, and the cwd match compares directories
stories: S-32600, S-32601
writes: asf/env.py, tests/test_env.py
after: none

The spec's first two **In** bullets and its `asf/env.py` design block: the four-step order becomes
one function returning what chose the product, `default_product_name` becomes a wrapper, and
`product_of_dir`'s string prefix becomes containment by directory identity (P11, D4).

**Files**

- `asf/env.py` — `Resolution`, `PRODUCT_SOURCES`, `resolve_product`, `default_product_name` reduced
  to a wrapper, `product_of_dir`'s comparison replaced
- `tests/test_env.py` — `ProductResolutionOrderTests` (new), `ProductOfCwdTests` extended

**Steps**

1. `Resolution = collections.namedtuple('Resolution', 'name source')` and
   `PRODUCT_SOURCES = ('--product', '$ASF_PRODUCT', 'cwd', 'default_product')`, with the comment the
   spec's design block gives: the token is printed in every view's first line, so a wrong fallback
   is visible.
2. `resolve_product(explicit=None, path=None)` walks `explicit`, then `os.environ['ASF_PRODUCT']`
   (non-empty, as today), then `product_of_dir(path)`, then `load_config()`'s `default_product`,
   returning `Resolution(name, source)` with `source` one of the four literals. When none answers it
   raises `ConfigError` naming all four in order — today's message names three
   (`asf/env.py:471-473`) and gains the cwd clause: `no --product, no $ASF_PRODUCT, no product whose
   repo or record holds <cwd>, and config.yaml has no default_product`.
3. `default_product_name()` becomes `return resolve_product().name`. Its twenty-odd callers and its
   signature are untouched; nothing that needs only a name learns a tuple.
4. `product_of_dir(path=None)` keeps its signature, its docstring's contract and its two tolerances —
   a product file that does not parse is skipped, and a `path` that cannot be resolved returns
   `None`. Only the comparison changes, to the spec's design block: build
   `ids: (st_dev, st_ino) -> (name, len(root))` over every candidate root of every product
   (`repo_dir`, `backlog_dir`, `<ASF_HOME>/state/<name>`), skipping a root that does not exist or
   whose `os.stat` raises; then walk `os.path.realpath(path or os.getcwd())` and its parents once,
   returning the first level whose `(st_dev, st_ino)` is in `ids`, and `None` at the filesystem root.
5. The tie-break is unchanged and stays measured the same way: the deepest matching root wins by the
   length of the root's realpath, so two roots that are one directory collapse to one key and the
   longer spelling keeps the name.
6. `ConfigError` is still what a failure is; `load_product` and `state_dir` keep their current
   signatures (a name or a `Product`) and are not touched.
7. `ProductResolutionOrderTests`: two products over a temp `ASF_HOME` built the way
   `ProductOfCwdTests.setUp` builds one. `resolve_product('bot')` from inside `asf`'s repo with
   `ASF_PRODUCT=asf` set answers `('bot', '--product')`; with no `explicit`, `ASF_PRODUCT=asf` from
   inside `bot`'s repo answers `('asf', '$ASF_PRODUCT')`; with neither, from inside `bot`'s repo,
   `('bot', 'cwd')`; from a cwd no product claims, `('asf', 'default_product')`; with
   `default_product` removed from `config.yaml` and nothing else set, `ConfigError` whose message
   contains each of `--product`, `$ASF_PRODUCT`, the cwd, and `default_product`. One assertion that
   `default_product_name()` returns `resolve_product().name` for each of those cases, so the wrapper
   cannot drift from the function.
8. `ProductOfCwdTests` gains, beside its three existing cases: a nested product (`bot`'s `repo_dir`
   inside `asf`'s tree resolves to `bot`, the deeper root); **a root spelled in another case** — the
   product file's `repo_dir` written with a case-different spelling of a path component, skipped with
   `unittest.skipUnless` when the temp directory's filesystem is case-sensitive (probed by creating
   one directory and `os.path.isdir`-ing its other-case spelling), asserting `product_of_dir` inside
   it answers the product where `os.path.commonpath` over the two realpaths would not; a root that
   does not exist, which is skipped rather than raising; and the state-dir root
   `<ASF_HOME>/state/<name>`, which resolves its product.

### Task 2: `cli.product_line` — every record command and the nine views name the product they show

  `scorecard` and `release-readiness` gain rows

**Steps**

1. `product_line(product, source, record=None)`: with a record, `record: <path> · product <p>
   (<source>)`; without one, `product <p> (<source>)`; with `product` `None`,

   `env.product_of_dir(cwd)`, source `cwd` — and `product (none) (cwd is a record)` when none claims

   `ConfigError`.
5. `cmd_approvals`, `asf/scheduler.py:805` and `asf/schema.py:233` replace
   `args.product or env.default_product_name()` with `env.resolve_product(args.product).name` — the

   `approvals` and `scheduler` are repo commands (the spec's **Out**) and `schema-migrate` reports

6. `asf/cli.py`'s module docstring (`:3-6`) states the four steps — `--product`, else
   `$ASF_PRODUCT`, else the product whose repo or record holds the working directory, else
   `default_product` in `~/.ASF/config.yaml` — and names the new first line.
7. `tests/test_path_resolution.py`: the `kind` column becomes the expected first-line shape (PD9).
   Every row that is `record` today stays `record` and its assertion becomes the full line for
   `--product sample`: `record: {self.record} · product sample (--product)`. `tokens`, `scorecard`
   and `release-readiness` are added as `record` rows — they dispatch through `resolve_record`
   (`asf/cli.py:539-540`) and were the three views the matrix never covered. `next`, `brief` and
   `doctor` keep their exemption until Task 3 makes them true, and `capacity` is Task 3's row (PD4).
   The `repo` rows are unchanged and assert no first line.
8. `tests/test_path_resolution.py:151`'s equality — the record command run from a product repo cwd —
   takes the same full line. The matrix's other two invariants are untouched: every command leaves
   the cwd empty, and a command step runs in the product's repo.
9. `RecordCommandUsesTheProductRecordTests` in `tests/test_cli.py`: the four equality assertions at
   `:123`, `:134`, `:140` and `:160` take the line their case now prints —
   `(--product)` for the explicit one, `($ASF_PRODUCT)` for the env-var one, `(cwd)` for the bare
   run from the product's repo, and for the bare record checkout at `:160` the record's own product
   with `(cwd)`. Two cases are added: a record no product claims, which prints
   `product (none) (cwd is a record)`; and PD5's case — the cwd is one product's record while
   `ASF_PRODUCT` names another — which must groom that record and name *its* product, never the
