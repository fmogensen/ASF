# Plan F-0280 — the row, the checklist, the brief

Epic: E-0001 — ASF 0.1 — a working factory. Spec: `docs/specs/f-0280.md` (approved). Branch:
`plan/F-0280`.

Three Tasks, one per Story and one per half of the spec's `## The design`. Task 1 is the **row**:
`asf/feeder/rows.py` alone — `FEATURE_LANES`, the branch-keyed gate in `lane_rows`, the one
`lane_speaks` rule that `direct_row` and `_one_feature_rows` both read, and a Feature admitted to
`pushed_ids`/`pushed_rows` on the branch the lane recorded. After it lands, the four PRs the card
names draw the review row they have been waiting for. Task 2 is the **checklist**:
`reviews.required(*kinds)`, `lane.review_kinds(kind, landing_class)`, `class` on the lane record
and on the occupancy's `review`/`landing` entries, and `Row.review_kinds` set from it — so the one
review a document branch's reviewer files satisfies the lane and ingest at once. Task 3 is the
**brief**: `reviews.EVIDENCE`, `render_table(rows, evidence=None)`, and the two placeholders in
`asf/briefs/templates/review.md` filled from `row.review_kinds` — so the reviewer is asked for the
table of the branch in front of them instead of the code table alone.

Wave order: **1 → 2 → 3**, strictly serial.

The cut is the spec's own §1 | §2+§3 | §4, and the serialisation is not a compromise: all three
Tasks write the one new test module C14 asks for, Tasks 1 and 2 both write `asf/feeder/rows.py`,
and Tasks 2 and 3 both write `asf/reviews.py`, so no two of them could run together whatever
their `after:` said (**PD7**). Each `after:` therefore names what the Task's code actually needs
landed, and the three happen to be the same chain: Task 2's `('spec', 'code')` acceptance needs a
Feature's `PUSHED → REVIEW` row to exist at all, which is Task 1's; Task 3's eleven-row brief
needs `row.review_kinds` and the varargs `required`, which are Task 2's.

Task 1 is also the whole of the recovery. The spec's `## What it looks like when it is there`
turns on C10 — a `REVIEW` record written before this card carries no `class` and reads as `code` —
and C10 costs nothing until Task 2, because a row with no `review_kinds` renders the code table
the brief renders today. So the order is not only safe to land in pieces, it is the order that
unblocks the four stuck PRs first and improves their review afterwards (**PD10**).
