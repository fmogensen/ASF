# Plan F-0121 — the foreign hook is chained, not refused: the body, the command, the row, the class, the prose

Epic: E-0001 — ASF 0.1 — a working factory. Spec: `docs/specs/f-0121.md` (approved). Branch: `plan/F-0121`.

Five Tasks, cut the way the spec's **In** is cut — by the module that gains the surface. Task 1 is
the library half of `asf/hooks.py`: the four constants, the two chained bodies, the recogniser that
reads one back, and the one branch of `ensure_git_hooks` that renames a foreign hook and writes ASF's
over it. Task 2 is the same module's operator half — `uninstall`, the parser's second `hooks_command`,
the `--chain` / `--no-chain` pair, and the one line in `asf/init.py` that makes adoption chain. Task 3
is the doctor's `redaction-hooks` row: one `elif`, red only when the `<hook>.local` the chain names is
gone. Task 4 is `asf/approvals.py` — the command recogniser widened to `uninstall`, and a real
`.git/hooks` file made `touch_security`. Task 5 is the four guide passages that today tell the
operator to hand-merge.

Only Task 1 starts at once; it invents every constant and every body the other four read, print or
classify. Tasks 2, 3 and 4 each need Task 1 landed — Task 2 dispatches to its `ensure_git_hooks`,
Task 3 calls its `chained_local`, Task 4 imports its `REAL_GIT_HOOK_GLOBS`. Task 5 is prose about
what Tasks 2 and 3 say on a terminal, so it waits for both.

Wave order: **1 → 2 ‖ 3 ‖ 4 → 5**.

Tasks 1, 2 and 3 all write the new `tests/test_hook_chain.py` and therefore run one after another
whatever their `after:` says — see PD2. Tasks 4 and 5 intersect nothing and run beside whichever of
2 and 3 the queue lets through. The queue costs little here: 2, 3 and 4 all wait on 1 anyway, and 5
waits on 2 and 3.

§Acceptance tests' last fence — the whole suite as the pull request's CI runs it — binds every Task,
so every Gate below runs `python3 tools/run_tests.py` beside its own.

### Task 1: the two chained bodies, and the branch that renames a foreign hook behind them
stories: S-32700, S-32701, S-32702
writes: asf/hooks.py, tests/test_hook_chain.py, tests/test_install.py
after: none

The spec's first three **In** bullets and the first half of its `asf/hooks.py` design block: four
constants, a third form of `_git_hook_body`, the recogniser that reads it back, and the one branch of
`ensure_git_hooks` that changes. No CLI, no `uninstall`, no caller — `chain` defaults to `False`, so
nothing in the product behaves differently until Task 2 passes it.

**Files**

- `asf/hooks.py` — `REAL_GIT_HOOK_GLOBS`, `LOCAL_SUFFIX`, `HOOK_MARKER`, `STDIN_HOOKS`;
  `_git_hook_body(name, asf_path, product_name, chained=False)`; `chained_local`; `_write_hook`;
  `ensure_git_hooks(product, which=shutil.which, chain=False)`
- `tests/test_hook_chain.py` — new module: `ForeignPreCommitIsChainedTests`,
  `ForeignPrePushIsChainedTests`, `StdinReachesBothTests`, `ChainingIsIdempotentTests`,
  `ChainingIsNeverUnattendedTests` (its two unattended cases, PD3)
- `tests/test_install.py` — `test_a_foreign_hook_is_not_touched_and_is_one_needs_operator_line`
  gains `chain=False`, and one sibling case for the chained outcome on the same fixture

**Steps**

1. The four constants beside `GIT_HOOK_NAMES` (`asf/hooks.py:51-63`), with the spec's comments
   byte for byte, and one correction: `REAL_GIT_HOOK_GLOBS = ('.git/hooks/*', '*/.git/hooks/*')`
   (PD7 — the second glob is what matches from a linked worktree, and the comment says so).
   `LOCAL_SUFFIX = '.local'`, `HOOK_MARKER = 'written by asf hooks install'`,
   `STDIN_HOOKS = ('pre-push',)`. Nothing in this Task reads `REAL_GIT_HOOK_GLOBS`; it is declared
   here because the constant is this module's to own (Task 4 imports it).
2. `_git_hook_body(name, asf_path, product_name, chained=False)`. `chained=False` returns today's
   three lines **byte for byte** — the existing `GitHookTests` compare them. `chained=True` returns
   the spec's two bodies, chosen by `name in STDIN_HOOKS`, with the renamed hook found at run time
   as `"$(dirname "$0")/<name>.local"` and guarded by `[ -x … ]` (D3, D5). Both keep the comment
   carrying `HOOK_MARKER`, both forward `"$@"`, both propagate the failing half's status. The gate
   command stays on a line of its own that is not a comment (PD6): the comment above it explains,
   and only the real line is matched.
3. The `pre-push` body buffers once and reads twice, exactly as the spec writes it: `mktemp` into
   `${TMPDIR:-/tmp}`, `|| exit 1` on failure (D4 — fail closed), a `trap 'rm -f "$refs"' EXIT HUP
   INT TERM`, `cat > "$refs"`, the gate with `< "$refs"`, then the renamed hook as a **child** with
   `< "$refs"` and `exit $?`. Not `exec`: an `exec` never returns, so the `EXIT` trap never fires
   and the temp file leaks on every push (D3). The `pre-commit` body, having nothing to clean up,
   ends in `exec "$own" "$@"` and never touches stdin (D2).
4. `chained_local(text, name)` → `f'{name}{LOCAL_SUFFIX}'` when `text` carries `HOOK_MARKER` and
   names `<name><LOCAL_SUFFIX>`, else `None`. The name only — the file sits beside the hook, in the
   directory the caller already has. It is the one reader Task 3 and Task 2 share, so neither can
   disagree with the other about what a chained hook is.
5. `_write_hook(path, body)` — the `open` / `write` / `os.chmod(path, 0o755)` triple the function
   already does twice (`asf/hooks.py:257-260`, `:265-268`), lifted so the three writes cannot drift.
   Both existing call sites are rewritten to use it; neither changes a byte it writes.
6. `ensure_git_hooks` grows `chain=False` and one branch, at `asf/hooks.py:261-264`, exactly as the
   spec's block writes it: not chaining is today's refusal and today's `continue`; chaining with a
   `<hook>.local` already there is the second refusal (D7), both files left alone and every other
   hook in the same call still written (P1); otherwise `os.rename(path, local)` and `_write_hook`
   with `chained=True`. The upgrade branch above it (`:255-260`) and the "already ours" branch are
   untouched — in particular the ours branch stays a no-op, so a later repair is a line
   substitution and not a rewrite (PD10).
7. The success detail names what moved, so an operator whose `core.hooksPath` is a tracked
   directory knows what to commit (Out): `pre-commit, pre-push in 2 repos; chained <path>/pre-push
   → <path>/pre-push.local`, one clause per rename, in the order they were made. With nothing
   chained the string is today's, unchanged.
8. `tests/test_hook_chain.py` is created with the module docstring the suite's style asks for, a
   `setUp` following `GitHookTests` (`tests/test_install.py:1262-1281`) — a tmpdir, real `git init`
   repos, a stand-in `asf` of its own (PD9) — and a second helper writing the **foreign** hook: a
   script that appends its `$@` and all of its stdin to a log file and exits 0, plus a variant that
   exits 1, so "both ran" and "the second half's failure is the hook's failure" are both bytes on
   disk.
9. `ForeignPreCommitIsChainedTests`: a repo with its own executable `pre-commit`; after
   `ensure_git_hooks(product, which=…, chain=True)` the original is at `pre-commit.local` byte for
   byte and with its mode, `pre-commit` is ASF's and is `is_git_hook_ours`, and the detail names
   the move. Then a **real `git commit`** runs both: the gate's stand-in passes, the log file shows
   the foreign half ran; a commit carrying the marker is refused by the gate and the log shows the
   foreign half did **not** run; a foreign half that exits 1 fails the commit. One case asserts the
   whole thing again with `core.hooksPath` set to a tracked `.githooks/` directory, which is where
   `dirname "$0"` has to be right (D5), and one runs `sh -n` over both generated bodies.
10. `ForeignPrePushIsChainedTests`: the same for `pre-push` against a bare origin, driven by a real
    `git push` — the rename, the chained body, both halves run, a marker in the pushed commit
    refused by the gate with the foreign half never reached, and a foreign half exiting 1 failing
    the push.
11. `StdinReachesBothTests`: the pushed refs, byte for byte, on both sides. The gate stand-in
    records the stdin it read and the foreign hook logs its own; the two are compared to each other
    and to the four-field lines git wrote. Cases: one ref; two refs in one push; a deletion, whose
    all-zero local sha the gate drops (P8) while the foreign half still sees the line; an **empty**
    stdin, which reaches the foreign half as zero bytes and not as one blank line (D3's reason for
    a temp file over `refs="$(cat)"`); and the hook's own `"$@"` — git's `<remote> <url>` — arriving
    at the foreign half unchanged. One case asserts no temp file is left under `TMPDIR` after a
    push, and one that a `TMPDIR` that cannot be written to refuses the push rather than running an
    unbuffered gate (D4).
12. `ChainingIsIdempotentTests`: a second `ensure_git_hooks(…, chain=True)` over the result of the
    first changes nothing — the hook's bytes, the `.local`'s bytes and **both mtimes** are equal
    before and after (the file is not rewritten with identical content), and the detail no longer
    names a rename. A third run likewise. A chained `pre-commit` is not an upgrade candidate:
    `init_hook_upgrade` and `staged_check_upgrade` both return `None` for it (PD6), asserted
    directly so a later change to either is caught here.
13. `ChainingIsNeverUnattendedTests`, its two unattended cases (PD3): `ensure_git_hooks(product,
    which=…, chain=False)` over a foreign hook is today's refusal with the file untouched; and the
    spawn gate's own call — `asf/workers/spawn.py:441` passes no `chain`, so the default refuses —
    asserted by calling `ensure_git_hooks(product, which=…)` with no keyword and byte-comparing the
    foreign file. `asf/workers/spawn.py` is not edited by this plan at all (D5).
14. A `<hook>.local` already in the way (D7): the refusal names both paths and the two words
    `move it aside or merge the two`, neither file is touched, and the **other** hook of the same
    repo is still written — the assertion P1 exists for.
15. `tests/test_install.py:1365` gains `chain=False` in its `ensure_git_hooks` call and keeps every
    assertion it has, since its point is the refusal. Beside it, one sibling case on the same
    fixture with `chain=True`: the refusal is gone, `rc`/`ok` is true, the foreign bytes are now at
    `pre-push.local`, and `pre-commit` — which was never in the way — is written as before.

### Task 2: `asf hooks uninstall`, the `--chain` pair, and the adoption that chains
stories: S-32703, S-32702
writes: asf/hooks.py, asf/init.py, tests/test_hook_chain.py
after: Task 1

The spec's fourth, seventh and eighth **In** bullets and its `## The design`'s parser block: the
command the operator types. `uninstall` puts a chained hook's original back and refuses to touch
anything this installer did not write; the parser gains a second `hooks_command` and the
`--chain` / `--no-chain` pair, chaining by default; `asf init` chains, and the spawn gate does not.

**Files**

- `asf/hooks.py` — `uninstall(product, cfg=None)`; `install(…, chain=True)`; `cmd_hooks` dispatch;
  `register`'s `hooks_command` choices and mutually exclusive group
- `asf/init.py` — one line: `ensure_git_hooks(product, chain=True)` at `:317`
- `tests/test_hook_chain.py` — `UninstallRestoresTests` (new class), and the CLI case appended to
  `ChainingIsNeverUnattendedTests` (PD3)

**Steps**

1. `uninstall(product, cfg=None)` → `(rc, message)`, with the spec's docstring. Per repo in
   `[r for r in (product.repo_dir, product.backlog_dir) if r]`, per name in `GIT_HOOK_NAMES`,
   against `git_hooks_dir(repo)`: a hook file carrying `HOOK_MARKER` is this installer's — when
   `chained_local(text, name)` names a `.local` that is there, `os.replace` moves it back over the
   hook (the original's own bytes and mode, one atomic call, counted `restored`); otherwise the
   hook is removed (counted `removed`). Anything else is left **byte for byte** and named in the
   message. `cfg` exists only so the account count is real in a test (PD8).
2. What "anything else" covers, each with its own case: the operator's own hook, an `asf init` hook
   (`asf.init.INIT_MARKER`), and a hand-merged hook carrying the gate line but not the marker. The
   marker and not `is_git_hook_ours` is the test (D6) — the loose recogniser is true of the last
   two, and removing either would delete work ASF did not write.
3. The message: `hooks uninstall: <n> restored, <m> removed in <k> repos`, then the line saying the
   worker accounts' `approvals` hook is deliberately left in place — it is the guard over human-now
   actions and this command never removes it (Out) — with the account count from
   `pool.accounts_from_config(cfg or env.load_config())`, then one `<path> is not asf hooks
