# Plan F-0334 — ASF 0.3: the pull request's own clock, intake decided by code, parked work swept, the console's share measured, and one host's seats shared across products

Epic: E-0003 — ASF 0.3 — autonomous delivery. Spec: `docs/specs/f-0334.md` (approved, **landed on
the trunk** at `cb47b17c8`). Branch: `plan/F-0334`, cut from `origin/main` at `cb47b17c8`.

**Ten Tasks in four waves**, cut along the one seam the spec's design actually carries: *the keys
come first, then the readers*. Every new behaviour in this release sits behind a
`kernel.<section>.<key>` whose default the spec states, and `asf/kernel/settings.py` is the one
file every section touches — so **Task 1** lands the whole config surface (ten keys, each with its
documented comment and its line in the example file) plus the one default the release flips as a
behaviour, the Definition of Ready. Nothing else writes `settings.py`, so the other nine Tasks
read a surface that is already there and none of them queues behind another for it.

Then the six independent readers, all in wave 2: **Task 2** is the pull request's own clock and
everything the ledger does with it (`model.py`, `ports.py`, `waits.py`, `gate.py`); **Task 4** is
intake's last human step and its measurement; **Task 5** is the Stage-4 sweep; **Task 7** is one
host's seats across products; **Task 8** is the parity list (Stories-first, the pace cap, and the
two capabilities the kernel already has, held by a test); **Task 9** is the incident ledger the
Stage-5 trigger reads. Wave 3 is the two Tasks that need a wave-2 surface: **Task 3**, the lead
breach, needs Task 2's `PR.opened_at`; **Task 6**, the console's share, needs Task 4's undecided
count on the per-tick record. Wave 4 is **Task 10**, the release's own documentation, written once
every other Task has landed and the gate can be read whole.

Wave order: **1 → (2, 4, 5, 7, 8, 9) → (3, 6) → 10**.

| PC1 | **§6's fenced `capacity()` cuts the host's seats to four — read this before touching `asf/kernel/ports.py`** | The spec fences `capacity()` as `lanes = sum(lane_seats(self.product, self.cfg()))` then `min(lanes, r.sessions) if r.sessions is not None else lanes`. Two things are wrong with it, both measured. **First, `r.sessions` is never `None`.** `Resolved.sessions` is typed `int` (`asf/capacity.py:85`) and `resolve` assigns it `max(0, min(ceiling, headroom))` or `max(0, ceiling)` (`:676-681`) — every path is an int. `product_sessions` (`:165-184`) falls through its four sources to `return DEFAULT_SESSIONS, 'default'`, and `DEFAULT_SESSIONS` is **`4`** (`:70`). So for a product that declares seats in its `kernel:` block and no `capacity:` block — the factory's own shape, and the shape `docs/products.example.yaml` shows — the fence resolves to `min(lanes, 4)`. Probed on `env.Product('sample', {'kernel': {'launch': {'local_max': 10, 'cloud_max': 12}}})` with `cfg={}`: `sessions = 4`, `sessions_bound = 'default'`, `ceiling = 4`, `fair_share = None`, and the fence returns **`4`** against a declared `lanes` of `10`. On the factory's own measured host (22 configured, 16 real, `asf/kernel/ports.py:1866-1888`'s docstring) that is a seat count cut by four times, on the release whose first two criteria are a 60-minute median and a 4-hour p90. S-131013's last acceptance line — *"a product alone on a host reads the same number it reads today"* — is exactly this test, and it fails under the fence. **Second, `sum(lane_seats(...))` is not today's number.** Today's `capacity()` (`:1866-1888`) is the configured sum *corrected*: the cloud lane's breaker, the live cloud runs, the lane accounts' free seats and the accounts' caps together — the docstring records the measurement that bought it (*"22 configured seats … the breaker tripped: 16 real, so 6 'free' seats only failed their launches"*). `sum(lane_seats(...))` throws that correction away and `min` with an unrelated ceiling does not restore it. **The fix, which Task 7 writes out in full:** keep the existing body whole as the lane number, and bound it by `resolve` only where `resolve` read a real declaration — `if r.sessions is not None and r.sessions_bound != 'default': seats = min(seats, r.sessions)`. The spec's *instruction* (`D17` — every ceiling `asf.capacity` knows should bound a kernel launch) is right, and is satisfied: `'default'` is the one `sessions_bound` that means *nobody declared anything*, and every other bound (`'product'`, `'operator default'`, `'operator total'`, `'feeder.capacity'`, `'fair share'`) is a declaration and binds. Probed: with `capacity: {sessions: 22}` declared, `resolve` returns `sessions=22`, `sessions_bound='product'`, and the bound applies. This is recorded here rather than amended into the approved spec. |
