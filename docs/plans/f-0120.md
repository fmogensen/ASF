# Plan F-0120 — adopting a record: the groom flags what belongs elsewhere, and `asf move` clears it

Epic: E-0001 — ASF 0.1 — a working factory. Spec: `docs/specs/f-0120.md` (approved). Branch: `plan/F-0120`.

Seven Tasks, cut the way the spec's **In** and its `## The design` are cut — by the module that gains
the surface. Task 1 is what a product's work *is* and the judgement that reads it: `scope:` in the
product file, the factory's own default in `asf/conventions.py`, and the new `asf/adopt.py`. Task 2 is
the groom's half of the flag — `belongs_to:` on the card and one decision line per suspected owner,
counted as an open question. Task 3 is what that line's answers do. Task 4 is `asf move` against the
source record: the selector, the all-or-nothing round-trip, `--remove`, `--dry-run`, and the declared
command surface. Task 5 is the target record: `--to`, the inbox import, the `moved_from:` ref and the
dedupe that survives the target's groom minting the card. Task 6 is the feeder's `NEEDS DECISION` row.
Task 7 is the guide.

Three Tasks start at once and they are the three halves that invent something: Task 1 (the judgement),
Task 4 (the command) and Task 6 (the row). Task 6 needs nothing from either of the others — by P6 a
typed field reaches `index.json` untouched, so the row reads `belongs_to` off the index whether or not
anything writes it yet, and its tests write the field into their own fixture. Task 2 needs Task 1's
`asf.adopt.flagged`. Task 3 needs Task 2's line, its section key and its regex. Task 5 needs Task 4's
`asf move`. Task 7 waits on Task 5 so the guide describes a command that exists whole.

Wave order: **1 ‖ 4 ‖ 6 → 2 ‖ 5 → 3 ‖ 7**.

The footprints are disjoint except along those `after:` edges: Tasks 1, 2 and 3 share
`tests/test_adopt.py` and 2 and 3 share `asf/groom/groom.py`, Tasks 4 and 5 share `asf/record/move.py`
and `tests/test_move.py`. Each of those pairs is already ordered by `after:`, so the queue costs
nothing. No two Tasks that could run together write the same path.

§Acceptance tests' last three fences — the conventions and genericity fences and the whole suite as CI
runs it — bind every Task, so every Gate below runs them beside its own.

### Task 1: `scope:` — what a product's work is, and the judgement that reads it
stories: S-32550, S-32551
writes: asf/env.py, asf/conventions.py, asf/adopt.py, docs/products.example.yaml, tests/test_adopt.py, tests/test_env.py
after: none

The spec's §1 and §2: the declared scope in the product file, the factory's own scope as a documented
default in the one module allowed to hold such a literal (D1, P20), and `asf/adopt.py` — the only place
in the package where a card is attributed to another product. Pure over the parsed cards and the scopes
it is handed; nothing calls it yet.

**Files**

- `asf/env.py` — `PRODUCT_FIELDS['scope']`, `SCOPE_FIELDS`, `NESTED_FIELDS['scope']`, `Product.scope`
- `asf/conventions.py` — `DEFAULT_FACTORY_SCOPE`, `FACTORY_SCOPE_NAME`
- `asf/adopt.py` — new module: `Scope`, `Match`, `KEPT_LINE`, `scopes`, `hits`, `matched`, `owner`, `flagged`
- `docs/products.example.yaml` — §1's block, where `customer_paths:` sits (`:308-311`)
- `tests/test_adopt.py` — new module: `ScopeTests`, `JudgementTests`
- `tests/test_env.py` — the new key validates, and a bad shape is refused

**Steps**

1. `asf/env.py`: `'scope': _MAP` in `PRODUCT_FIELDS` (`:515-522`), then §1's two lines —
   `SCOPE_FIELDS = {'paths': _LIST, 'terms': _LIST}` with the spec's comment, and
   `NESTED_FIELDS['scope'] = SCOPE_FIELDS` (`:548-551`). `validate_product_text`'s `_shape_ok` checks
   both levels with no further change (P17): a `scope:` that is not a map, or a `paths:` that is not a
   list, is a named problem and the product does not load.
2. `asf/env.py`: the `scope` property beside `customer_paths` (`:817-818`), with §1's docstring —
   `(paths, terms)` as two tuples, both empty when the product declares none or declares `scope:` with
   only one of the two keys.
3. `asf/conventions.py`: `DEFAULT_FACTORY_SCOPE` and `FACTORY_SCOPE_NAME` exactly as §1 gives them,
   comments included. This module is one of `tools/check_conventions.sh`'s three documented exceptions
   (`tools/forbidden-conventions.txt:4-6`), which is why the path literals may be here and nowhere else
   under `asf/` (D1).
4. `asf/adopt.py`: §2's module docstring byte for byte, then `Scope`/`Match` as §2 declares them and
   `KEPT_LINE = "kept as this product's own work"` with its comment (D7). The module imports
   `fnmatch`, `os`, `collections`, `asf.env`, `asf.conventions` and `record.core.tokenize` — and
   nothing from `asf.groom` or `asf.feeder`, which import it.
5. `scopes(product, home=None)`: enumerate `*.yaml` under `os.path.join(home or env.ASF_HOME,
   'products')` the way `product_of_dir` does (`asf/env.py:436-448`) — `env.load_file` per file inside
   a bare `except Exception: continue`, so a broken sibling product is skipped and never raises (P18).
   Drop the file whose name is `product.name`; keep each remaining product that declares a non-empty
   `scope:` as `Scope(name, tuple(paths), tuple(terms))`. Append
   `Scope(FACTORY_SCOPE_NAME, **DEFAULT_FACTORY_SCOPE)` only when no `*.yaml` in that directory is
   named `FACTORY_SCOPE_NAME` (D2) — including the file this product was loaded from, so a machine
   where ASF is itself a registered product gets one scope under that name and not two. Return the
   list sorted by `name`.
6. `hits(rec, scope)` → `(paths, terms)`, both ints (D3, D4). Paths: the distinct globs of
   `scope.paths` that `fnmatch.fnmatch` matches against any entry of the card's `writes:` **or** any
   path-shaped token — a whitespace-free token containing `/` — in the card's title plus its
   `## Description`. Terms: the distinct members of `scope.terms` present in
   `record.core.tokenize(title + ' ' + description)` (P21), compared lowercased.
7. `matched(rec, scope)`: `paths >= 1 or (scope.terms and terms >= min(2, len(scope.terms)))` — a
   scope with no terms is never matched on terms, whatever the card says.
8. `owner(rec, scopes)` → the single best `Match` or `None` (D5): `None` at once when the card's body
   carries `KEPT_LINE` (D7); else rank the matched scopes by `(paths, terms)` descending and return
   `None` when the top two are equal on both. `Match.why` is `writes: <the first matched glob>` when
   `paths` is non-zero, else `terms: <the matched terms in scope order>` — at most three, then `…`.
9. `flagged(canonical, product)` → `{id: Match}` for every open, non-retired card (`is_open` and not
   `is_retired`) that `owner` names, against `scopes(product)` computed once.
10. `tests/test_adopt.py`: the module docstring naming F-0120 and this Task, then `ScopeTests` — a
    temp `ASF_HOME` with two product files, one declaring a scope and one not; this product excluded;
    a broken sibling skipped; the factory scope offered when no product is named `asf` and withheld
    when one is; the list sorted by name; and `Product.scope` reading `(paths, terms)` off a loaded
    product. `JudgementTests` — a path hit through a Task's `writes:`, a path hit through a path-shaped
    word in a description, one term never matching, two terms matching, `min(2, len(terms))` letting a
    one-term scope match on one, the best match winning on paths then terms, an exact tie returning
    `None`, and a body carrying `KEPT_LINE` returning `None`.
11. `tests/test_env.py`: one case that a product file with §1's `scope:` block validates and loads, and
    one that `scope: [a, b]` (a list where a map is declared) is a named problem.

### Task 2: `belongs_to:` on the card, and one decision line per suspected owner
stories: S-32552
writes: asf/groom/groom.py, asf/groom/policy.py, asf/record/new.py, tests/test_adopt.py

The spec's §3 and the first half of §4: the groom writes the flag through P2's round-trip writer with
one History line, deletes a flag that no longer matches, and asks about the whole set on **one** line
keyed on `belongs_to:<owner>` — counted as an open question, landing with the adjudicator, added once a
day by `merge_groom_text` and never twice.

**Files**

- `asf/groom/groom.py` — `_write_card_checked`, the flagging loop in `cmd_groom`,
  `groom_foreign_section`, the `GROOM_SECTIONS` entry
- `asf/groom/policy.py` — `OPEN_QUESTION_RE`'s token alternation
- `asf/record/new.py` — `belongs_to` joins `_COMMON_SET`
- `tests/test_adopt.py` — `GroomFlagsForeignCardsTests`

**Steps**

1. `asf/record/new.py:19`: `'belongs_to'` into `_COMMON_SET`, with the comment §3 gives — a suspicion
   is safe to set by hand, a closing is not, which is why `removed` and `moved_to` stay out (PD11).
2. `asf/groom/groom.py`: `_write_card_checked(rec, fields, hist)` beside `_write_card` (`:168-179`) —
   `setfield.set_typed(rec, fields, writer='groom')`, and on a reason returned, print
   `groom: <id>: <reason>` and change nothing; on success append the one History line the way
   `_write_card` does and mirror `fields` into `rec['meta']` (PD10). Returns True when it wrote.
3. `cmd_groom`: after `derived = compute_derived(canonical)` (`:1196`) and before
   `build_groom_sections`, §3's loop — skip entirely when `product is None` (PD6); for each
   `adopt.flagged(canonical, product)` entry whose card already carries that owner, write nothing; else
   `_write_card_checked(rec, {'belongs_to': match.name}, f"- {date} groom: looks like {match.name}'s
   work ({match.why}) — asf move")`. Then the reverse pass: every open card whose `belongs_to:` is set
   and which `flagged` no longer names gets `{'belongs_to': None}` (`write_typed`'s delete form, which
   round-trips through `set_typed` as `None == None`) and
   `- {date} groom: no longer looks like another product's work`. A card whose flag is unchanged is not
   opened, so a second groom in the same day writes nothing and `publish_changes` makes no commit (P3).
4. `groom_foreign_section(canonical, product)`: one line per suspected owner, owners in name order, ids
   in id order, at most ten named — §4's line, byte for byte:
   `- [ ] belongs_to:<name> <n> cards look like <name>'s work — <ids…> — <why> → answer: ____`.
   The `why` is the `Match.why` of the first card in id order. Built off the record's `belongs_to:`
   fields, not off `flagged`'s return, so the section says what the cards now carry. `[]` when
   `product is None`.
5. `GROOM_SECTIONS`: `("Cards that look like another product's", 'foreign')` immediately after
   `('Inbox cards to decide', 'inbox')` (`:839-855`). `_SECTION_BY_TITLE` is derived from that list
   (`:919`), so the section key needs no second registration. Call the builder in `cmd_groom` beside
   the other three `sections[...] =` lines (`:1209-1211`).
6. `asf/groom/policy.py:31-32`: `belongs_to:\S+` into `OPEN_QUESTION_RE`'s alternation, beside
   `inbox:\S+`. Nothing else changes: `run_policy_pass` and `policy.suppress` both already leave a line
   whose token is not a card id alone (PD7), and `rows._split_lines` sends it to the judgement half
   because the token does not start `inbox:` (P13).
7. `tests/test_adopt.py`: `GroomFlagsForeignCardsTests` — a record of several cards with a temp
   `ASF_HOME` declaring one other product's scope; `cmd_groom` writes `belongs_to:` on the foreign ones
   through the round-trip writer and one History line each; the groom file carries **one** line for the
   owner naming every flagged id, not one line per card (the card's third named test); a second run
   over the same record writes no card and adds no second line; `policy.open_questions` counts the line;
   `rows._split_lines` puts it in the judgement half; a card that stops matching loses its flag with the
   second History line; and `cmd_groom` with no product flags nothing.
