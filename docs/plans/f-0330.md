# Plan F-0330 — the declared outcome is written onto the card

Epic: E-0001 — ASF 0.1 — a working factory. Spec: `docs/specs/f-0330.md` (approved). Branch:
`plan/F-0330`.

Four Tasks, one per section of the spec's `## The design`. Task 1 is the **applier**: the whole of
`asf/tick/apply_rulings.py` — its three arms, the six-clause supersession gate, the once-loaded
`canonical` record and its mirror, the write-back into the step's shared `items` — plus the one
keyword `widen_footprint.write_card` needs and the one line and wrapper `step_health.run` needs.
Task 2 is the **row**: one branch in `asf/feeder/rows.py`, so an Active Task whose `reshape:` is
pending gets the pair a New one already gets. Task 3 is the **claim**: `report_facts` loses its
`FINISHED` gate, narrows its `pending_correction` gate to a *parked* correction, and carries the
surviving correction's text into the hold that replaces it. Task 4 is the **field**: one line of
the shared brief TAIL, the 19 goldens it changes, the one test line that pins it, and the
`FixKindTests` that hold the TAIL's wording and the applier's own table against each other.

Wave order: **(1, 2) → (3, 4)**.

Task 1 and Task 2 are genuinely parallel: Task 1 writes `asf/tick/*` and `tests/test_apply_rulings.py`
and `tests/test_tick_steps.py`; Task 2 writes `asf/feeder/rows.py` and `tests/test_feeder.py`; their
`writes:` are disjoint on both sides, source and test. Task 3 intersects Task 1 on
`asf/tick/widen_footprint.py` and Task 4 intersects it on `tests/test_apply_rulings.py`, so both are
queued behind it whatever their `after:` said (`PD1`), and `after: Task 1` makes the spec's ordering
the record's. Task 3 and Task 4 are disjoint from each other, source and test, so they run together
in wave 2.

## Decisions

Nothing below widens the card: each row is the spec's own In/Choices carried out on the tree as it
stands, or a mechanical fact about how this plan lands. Three rows are land-refusal or
land-corruption mechanics a plan of this shape has to get right and that no acceptance line names:
`PD3`/`PD4` (the six Story ids are the **spec's**, and this plan must cite them without
re-declaring them), `PD6` (where `## Stories` may sit) and `PD7` (a bare `D<n>` in a Task body is
silently rewritten to an unrelated product decision — measured). `PD4` — whether citing the six
Story ids can refuse this plan — was parked for a person in an earlier round and is now **measured**
instead: the real `idcheck.check_doc` over this file returns zero findings, so no row here needs an
operator.

`PD8` is the row that changed most in this round, and it changes nothing about the work: the trunk
moved 68 files under the base the previous round measured at, so most of this plan's `file.py:NNNN`
anchors had gone stale while every construct they name stayed byte-identical. `PD8` re-measures all
of them at this base and says which commit moved which file by how much; `PD9`, `PD10` and `PD13`
re-measure the baselines and counts that moved with them. It also **withdraws** both corrections
that round made to the spec's own citations — the spec was right twice and the plan was wrong twice
— so no Task below carries a false correction. The spec's design, its decisions and its acceptance
are untouched by all of this; what changed is only where to look.
