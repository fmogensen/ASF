# Plan F-0221 — one Task: the Stale row measures the cadence the tick has, and the hold speaks where it can

Epic: E-0004 — Control plane — the factory's dashboard, served from the record. Spec:
`docs/specs/f-0221.md` (approved). Branch: `plan/F-0221`.

**One Task.** The five Stories are one expression in one function. `S-38100`'s threshold cannot be
computed without `S-38101`'s reader — the duration term *is* the last landed record tick's
`duration_s`, and there is nowhere else on disk to read it; `S-38103` is the bound on both (the
duration term at `0` is today's `2 ×` the clock, byte for byte); `S-38102`'s clause is three lines
after the threshold comparison and by `D8` only runs once it has been crossed; and `S-38104`'s
replay exercises all four. Every one of them writes `asf/views/status.py` and
`tests/test_tick.py`, so a split buys no parallelism and would serialise anyway (PD10).

Wave order: **1**, alone — it starts at once.

new test classes:

   `_stale_after_s` beside `_record_period_s` (`:211-218`, unchanged), and the fallback half of
   `stale_cell` (`:242-245`) replaced. The first clause (`:232-234`) and the `index.json` guards

   (`:378-420`), which is itself **not edited**: it is the floor `S-38103` asserts.

### Task 1: the Stale row reads the cadence the tick measured, and an upgrade hold names itself
stories: S-38100, S-38101, S-38102, S-38103, S-38104
writes: asf/views/status.py, tests/test_tick.py, tests/fixtures/ticks/2026-09-27.jsonl
after: none

The spec's `## The design` §1, §2 and §4 in full, with PD4's bool exclusion and PD9's import, and
nothing else. After this lands, a product on `record every: 5m` whose last landed record tick took
13.3m has a threshold of 36.6m rather than 10m, so the row says nothing through a tick of that
length — measured on the spec's own fixture, `20m old: today='STALE …' after=None` — and still
says `STALE` at 40m. Where the age has crossed the threshold and an upgrade marker parks this
product, the row is

```
| Stale | waiting on upgrade to f5aa236 since 12:10 (owner other) — no fresh record in 15m |
```

and where it has crossed with no marker, it is unchanged in shape:

```
| Stale | STALE since 00:56 — no fresh record in 1h |
```

Both are this session's measured output, not a derivation. **No tick changes, and nothing is
written.** `metrics/ticks` gains no field and no line; `index.json`, `record-health.json` and
`upgrade-pending.json` are read only. If the diff reaches `asf/tick/`, `asf/metrics/`,
`asf/upgrade.py` or `cron_cell`, it has left the card.

Three things are load-bearing. The freshest signal is **the newer of two** (`D2`) and never the
older, because a checkout may hold `index.json` without `metrics/ticks` and the row must work on
both; the `since` then names whichever won (`D10`), or the sentence contradicts itself. The
duration term **defaults to zero** (`D5`), so a checkout with no readable cadence keeps today's
`2 ×` the clock exactly — that is the floor `S-38103` asserts, and it is why an unreadable metrics
directory cannot silence the stall detector. And the hold clause is tested **only through
`upgrade.held(product.name)`** (`D7`), which returns `None` for the marker's owner, so the two rows
that report a hold cannot disagree about who is parked.

Read **PD1** before transcribing the fifth acceptance test, **PD2** for the stall moment,
**PD3** for the replay's truncation and shift, **PD4** for the `duration_s` guard, and **PD13**
before writing any expected `since`.

**Steps**

1. **`_stale_after_s`** — §1 verbatim but for PD4: the guard is
   `isinstance(duration_s, (int, float)) and not isinstance(duration_s, bool) and duration_s > 0`.
   It returns `2 * (_record_period_s(product) + duration)`. Measured: `2 × (300 + 798) = 2196.0s`,
   `2 × (600 + 798) = 2796.0s`, and `None`/`0`/`-5`/`'x'`/`True` all give `600s`.
2. **`_last_record_tick`** — §1's docstring, then: glob `<root>/metrics/ticks/*.jsonl`, sort by
   name, keep the last `STALE_TICK_DAYS`. Read each file and parse **line by line, each in its own
   `try/except`** (PD7) — a torn line is skipped and the valid lines around it are kept. Keep a row
   only when it is a `dict`; when its `product` equals `getattr(product, 'name', None)` or is
   absent or `None`; and when its `steps` is a list holding a `dict` with `step == 'record'` and
   `ok is True` (`D3` — `ok: False` does not count, and that case belongs to the first clause).
   Return the `(ts, duration_s)` of the greatest `ix.parse_ts(ts)`, or `None`. Every `OSError` and
   `ValueError` is caught inside the function; nothing escapes to `render`'s net.
3. **`stale_cell`** — §2's body from `last = _last_record_tick(root, product)` down. The freshest
   signal is the newer of the tick stamp and `generated`, with `stamp` following it (`D10`); the
   comparison becomes `age_s <= _stale_after_s(product, duration_s)`; past it,
   `upgrade.held(getattr(product, 'name', None))` decides between `D9`'s sentence and `STALE`. Add
   `from asf import upgrade` to the function's local imports beside `record_health` and
   `index_reader`, as §2 has it.
4. **The fixture** — write `tests/fixtures/ticks/2026-09-27.jsonl` as the Files block describes.
   One JSON object per line, keys sorted, no trailing blank line beyond the final newline.
5. **`StaleRowCadenceTests`** (`S-38100`, and `test_a_real_stall_fires` for `S-38103`) — a
   `TickTestCase` subclass with `product_yaml` declaring `clocks: {record: {steps: [record],
   every: 5m}}`. Each test writes `index.json` and a `metrics/ticks` day file into `self.operator`
   at ages relative to the real clock (PD3(b): never a frozen one), patches `record_health.line`
   to `None` so the first clause stands aside, and asserts the row. The cases the spec names: 20m
   old is `None` and 40m old is `STALE` where today both are `STALE`; `every: 10m` with the same
   duration gives 46.6m; `None`, `0`, a negative, a missing key, a non-numeric **and `True`**
   (PD4) each give exactly `2 ×` the clock; no `clocks:` block at all falls back to
   `DEFAULT_RECORD_CLOCK_S` through the `SchedulerError` `_record_period_s` catches.
   `test_a_real_stall_fires` is the hour-old case with a 13-minute last tick →
   `STALE since <ix.local_stamp(...)> — no fresh record in 1h`.
6. **`StaleRowRecordSignalTests`** (`S-38101`) — the two-signal cases: a tick line 4m old against a
   `generated` 17m old is silent; `generated` newer wins and `since` names it (`D10`); `steps` with
   no `record`, and `record` with `ok: False`, do not count; another product's line does not count
   and an absent `product` does; yesterday's file is read when today's does not exist and a third
   day back is not; an absent `metrics/`, an unreadable day file, a non-JSON line and a line with
   no `ts` each leave today's behaviour with no exception escaping. The torn-line case asserts
   PD7's per-line guard: a file whose last line is truncated **and** whose first line is a fresh
   landed record reads as fresh, not as no line.
7. **`StaleRowUpgradeHoldTests`** (`S-38102`) — PD5's fixture: one landed record tick with
