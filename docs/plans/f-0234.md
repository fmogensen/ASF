# Plan F-0234 — the OS asked first, the deferral bounded, the class written down

Epic: E-0001 — ASF 0.1 — a working factory. Spec: `docs/specs/f-0234.md` (approved). Branch:
`plan/F-0234`.

Three Tasks, cut so that **the trunk is never carrying a deferral nothing bounds**:

1. **the four words** — `lifecycle.liveness`, `LIVENESS`, `LIVE_VERDICTS`, and the table that pins
   one row per verdict. A pure function with **no caller**: the factory's behaviour is byte for
   byte what it is today when this lands, and every later Task is wiring.
2. **both doors, and the bound, in one commit** — `observe.liveness_for`, `identity_alive`
   re-expressed on top of it, and `health.alive_for` supplying the three measurements. This is the
   Task that stops killing live workers, and it is also the Task that says how long a worker may
   answer without writing anything. They land **together**, deliberately (PD1).
3. **the class on the ledger, and the key left alone** — `Evidence.liveness`, `gather(liveness=)`,
   `dead_class` in `RUN_FIELDS`, the death write, `health.dead_census` and the doctor row; plus the
   stale `DEAD_PID` comment corrected.

They run **1 → 2 → 3**, one at a time. Task 1 and Task 2 have disjoint footprints and could in
principle run together, but Task 2 calls a function only Task 1 ships, so `after:` chains them
anyway. Tasks 2 and 3 both write `asf/workers/health.py` and `tests/test_workers.py`; Tasks 1 and 3
both write `asf/workers/lifecycle.py` and `tests/test_lifecycle.py`. The footprints confirm the
serialisation independently of the argument.

**Read PD1 and PD2 before writing a line of Task 2.** PD1 is why the silence bound is not its own
Task even though it is its own Story; PD2 is the one place the spec's `## The design` contradicts
the spec's own cost claim, and a coder who follows §2 literally ships a `ps` per pid per tick.

The whole-tree fences of §*The fences* bind every Task, so every Gate below carries them beside its
own commands.

| PD1 | **The silence bound is its own Story but not its own Task: splitting it would put an unbounded deferral on the trunk** | S-35801 ("the deferral bounded by the log") is a Story of its own, and the obvious cut gives it a Task of its own. That cut is wrong, and the spec says why without drawing the conclusion: `liveness` returns `UNKNOWN` — which `LIVE_VERDICTS` treats as **alive** — whenever a pid answers, nothing matched it, and `silent_min`/`silent_for` were not supplied (spec §1, the last two lines of the body). So a Task that lands `observe.liveness_for` + `identity_alive` *without* `health._measurements` puts a factory on the trunk in which **a run whose observation cannot name it is never ended at all** — immortal, holding its ledger line, judged `None` by `judge` every pass, forever. That is a worse defect than the one this card fixes, and it would be live for however many hours or days separate two Tasks landing. Task 2 therefore carries **both** Stories' code: the wiring (S-35800's second and third fences) and the bound (S-35801's), in one diff that is correct at every point. Task 1 carries the bound's *semantics* — `liveness` is written with `silent_min`/`silent_for` in its signature and `LivenessVerdictTests` pins the `UNKNOWN` row — but Task 1 has no caller, so nothing is unbounded there either. |
| PD2 | **`is_ours` is a bool (C5) *and* must be measured lazily (the cost claim) — the two are reconciled by calling `liveness` twice, not by duplicating the match rule** | The spec asserts both, one section apart, and they pull against each other. C5: *"'Is this one of ours' arrives as a **bool argument** (`is_ours`)"*, and §1's body reads `if is_ours is False:` — a bool, and `LivenessVerdictTests` will pin it as one. §2: *"`command_line` is one `ps` per **unmatched** pid — the ordinary tick matches every pid on the first rule and shells out for none of them."* But `observe.liveness_for` builds one `verdict(pid)` closure and hands `liveness` its arguments; if it evaluates `is_ours(pid)` to a bool before the call, it shells out `ps -o command= -p <pid>` for **every** recorded pid on **every** tick — the exact cost §2 says is not paid. Re-deriving "was this pid matched?" inside `liveness_for` to decide whether to measure would copy the identity rule (`not run.get('session') or run.get('session') == o.session`) into a second place, which is what P4/D11 exist to prevent. **Decided: `verdict(pid)` calls `liveness` twice.** First with the cheap facts only — `lifecycle.liveness(run, o, exists)`, no `is_ours`, no `silent_min` — which returns `GONE`, `ALIVE` or `REUSED` for every pid the first three rules decide, and `UNKNOWN` for **exactly the unmatched set**. Only on `UNKNOWN` does it measure and call again with everything: `lifecycle.liveness(run, o, exists, is_ours=..., silent_min=..., silent_for=...)`. The match rule stays in one place, `liveness` stays pure and bool-typed, and the `ps` fires only for a pid nothing named. Note the argument order matters here and the naive two-call shape is wrong: passing `silent_min` on the *first* call would return `GONE` for a silent unmatched pid before `is_ours` was ever asked, so a recycled pid would be recorded `gone` instead of `reused` — the first call must carry **neither** measurement. Memoise `exists(pid)` in the closure so the second call does not repeat the `os.kill`. |
| PD3 | **`identity_alive`'s cloud branch must stay *ahead* of the recorded/unrecorded split, which the spec's §2 rewrite moves** | Today (`asf/workers/observe.py:229-239`) `alive(pid)` tests `cloudpid.is_token(pid)` **first, for every pid**, and only then splits on whether a run recorded it. The spec's §2 rewrite reads `if pid not in run_pids: return pid in by_pid` before anything else, and puts the cloud branch inside `liveness`, which is reached only for a recorded pid. That is a behaviour change the spec does not intend and does not name: a cloud token that **no run recorded** would stop being answered by `cloudpid.alive` and start being answered by `pid in by_pid` — and a cloud run is no process on this host, so it is never in `by_pid`, so it would read dead. `tests/test_cloud.py:236` calls `observe.identity_alive([], [run])` with a recorded cloud run and passes either way, so no fence catches it. **Decided:** `identity_alive` keeps `if cloudpid.is_token(pid): return cloudpid.alive(pid)` as its **first** line, before the `run_pids` test, exactly where it is today. `liveness` keeps its own cloud branch too (spec §1) — the two agree, and the one in `liveness` is what serves `liveness_for`'s direct callers. Neither is redundant. |
| PD4 | **`_measurements` is called with `product=None` by three live callers, and `stall.silent_minutes(None)` raises** | `asf/harvest/harvest.py:210`, `:222` and `:677` all call `health_mod.alive_for(**None**, sessions, session_source)`. `stall.silent_minutes(product)` is `(product.stage_limits or {}).get(...)` — `AttributeError` on None, and `alive_for` catches nothing. ### Task 1: the four words, and nothing that reads them yet
stories: S-35800
writes: asf/workers/lifecycle.py, tests/test_lifecycle.py
after: none

The spec's `## The design` §1 in full, and nothing else: `ALIVE`, `GONE`, `REUSED`, `UNKNOWN`,
`LIVENESS`, `LIVE_VERDICTS` and the pure `liveness(run, observed, exists, is_ours=None,
silent_min=None, silent_for=None)`, beside `pid_alive` in the one module the fence allows to name a
session state (C4, PD9).

**Nothing the factory does changes when this Task lands.** The function has no caller: `alive_for`
still returns `identity_alive`, `judge` still reads `ev.alive`, `stall.classify` still asks the same
bool. That is the point of cutting it here — the four words can be pinned one row at a time, against
a factory whose behaviour is provably identical, and Task 2 is then a wiring diff with no new logic
in it.

Write the signature **whole**, including `silent_min` and `silent_for`, even though no caller
supplies them until Task 2 (PD1): the bound is part of what `liveness` *means*, and a second Task
widening a signature is a second chance to get the argument order wrong — and the order is the
argument here (spec §1, closing paragraph: the OS is asked before the observation is believed).

Read **PD2** before writing the docstring: `is_ours` is a **bool**, not a callable, and the reason
it can be a bool without costing a `ps` per pid per tick lives in Task 2.

**Files**

- `asf/workers/lifecycle.py` — the six new module constants and `liveness`, placed immediately after
  `pid_alive` (`:580-595`) and before `occupies` (`:598`), carrying the spec's `#:` comments byte for
  byte. `cloudpid` is already imported in this module (`pid_alive` uses it). No existing line moves.
- `tests/test_lifecycle.py` — a new `class LivenessVerdictTests(unittest.TestCase)`, a plain
  `TestCase` and **never** a subclass of a harness in this module — subclassing one re-runs its
  host's whole suite under a second name.

**Steps**

1. Add the constants. `LIVENESS = (ALIVE, GONE, REUSED, UNKNOWN)` is the full vocabulary;
   `LIVE_VERDICTS = (ALIVE, UNKNOWN)` is the pair a run keeps running under, and is the single line
   Task 2's `identity_alive` will read. Keep the spec's `#:` comment on the block, including its
   `(F-0234)` tag.
2. Add `liveness` exactly as §1 writes it, in that order: cloud token → `exists` → observation →
   `is_ours is False` → the silence bound → `UNKNOWN`. Do not reorder to put the observation first;
   the whole defect is that the OS was never asked (P3).
3. `LivenessVerdictTests` — one test per row, each stating only the facts it means and leaving every
   other argument at its default, the way `Evidence`'s null defaults let a test state one fact
   (`:1049-1050`):
   - a pid the OS does not answer for is `GONE` **whatever the observation says** — pass an
     `Observed` at the pid carrying the run's own session and `exists=lambda p: False`, and assert
     `GONE`. This is the row that proves the order.
   - an observed session carrying the run's own id, with `exists` True, is `ALIVE`.
   - a run with no `session` of its own, observed at all, with `exists` True, is `ALIVE` — F-0076's
     rule for a run recorded before sessions existed, kept whole.
   - an observed session naming a **different** id is `REUSED`.
   - `exists` True, observation `None`, `is_ours=False` is `REUSED`.
   - `exists` True, observation `None`, `is_ours=True`, `silent_min=30`, `silent_for=5.0` is
     `UNKNOWN` — the live worker that is no longer a corpse, the card's whole reason.
   - `exists` True, observation `None`, `is_ours=True`, `silent_min=30`, `silent_for=31.0` is
     `GONE` — the bound. (Task 2 proves the same bound through the real callable; this pins the
     function's own contract, so a later refactor cannot quietly drop it.)
   - a cloud token follows `cloudpid.alive`, both ways, with `exists` patched to a callable that
     would answer the opposite — so the test proves the cloud branch comes first.
   - `is_ours=True` with `silent_min=None` or `silent_for=None` is `UNKNOWN`, not `GONE`: an
     unmeasured silence is not a silence (this is the row PD1 and PD4 both rest on).
4. Assert `set(LIVENESS) == {ALIVE, GONE, REUSED, UNKNOWN}` and `set(LIVE_VERDICTS) <= set(LIVENESS)`
   so a fifth word cannot be added without a test noticing.

### Task 2: both doors shut at the callable, and the deferral bounded by the log
stories: S-35800, S-35801
writes: asf/workers/observe.py, asf/workers/health.py, tests/test_workers.py
after: Task 1

The spec's `## The design` §2 in full: `observe.liveness_for`, `identity_alive` re-expressed on top
of it, and `health.alive_for` supplying `is_ours`, `silent_min` and `silent_for`. **This is the Task
that pays.** After it lands, a worker whose `ps` line carried no readable env is judged again next
pass instead of being ended — and no cold retry is started in the worktree it is still writing
(P7) — while a worker that answers but has written nothing for longer than the product's
`silent_min` is ended exactly as today.

The wiring and the bound are one commit by construction, not by convenience: see **PD1**. Read
**PD2** (the two-call shape, and why the first call carries neither measurement), **PD3** (the cloud
branch stays first), **PD4** (`product` is None on three shipped call sites) and **PD5**
(`_observe`, so Task 3 costs no second `ps`) before starting.

Neither `asf/workers/stall.py` nor `asf/tick/step_health.py` is edited, and neither gains a
state-word literal — that is the point of fixing this at the callable (P6): `judge` reaches it
through `gather`, `stall.classify` calls it directly, and one line closes both.

**Files**

- `asf/workers/observe.py` — new `liveness_for(observed, runs, exists=None, is_ours=None,
  silent_min=None, silent_for=None)`; `identity_alive` re-expressed on top of it, keeping its
  signature, its docstring's D11 rule, its cloud-first line and its "a pid no run recorded" branch.
  `lifecycle` is already imported here.
- `asf/workers/health.py` — new private `_measurements(product, runs)` and `_observe(product, runs,
  session_source)`; `alive_for` rewritten on the latter with its own signature, callers and `why`
  fallback unchanged.
- `tests/test_workers.py` — new `class LivenessForTests(unittest.TestCase)` and
  `class LivenessSilenceBoundTests(unittest.TestCase)`, both plain `TestCase`s.

**Steps**

1. `observe.liveness_for` returns a `verdict(pid)` closure over `by_pid = {o.pid: o for o in
   observed}` and `run_by_pid` built the way `identity_alive` builds it today (first run wins for a
   repeated pid). `exists` defaults to `lifecycle.pid_alive`. Memoise `exists` per pid in the
   closure (PD2).
2. `verdict(pid)` is the two-call shape of **PD2**:
   `v = lifecycle.liveness(run, o, exists_memo)`; then `if v == lifecycle.UNKNOWN:` re-call with
   `is_ours=is_ours(pid) if is_ours else None`, `silent_min=silent_min`, and
   `silent_for=silent_for(pid) if silent_for else None`. The first call carries **neither**
   measurement — passing `silent_min` there would record a recycled pid as `gone` instead of
   `reused`.
3. `identity_alive(observed, runs, **kw)` keeps `if cloudpid.is_token(pid): return
