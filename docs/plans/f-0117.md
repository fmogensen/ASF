# Plan F-0117 — the command center: the read layer that cannot write, the table, the merged tail, the conversation, the console's own command, and the fence

Epic: E-0004 — Control plane — the factory's dashboard, served from the record. Spec:
`docs/specs/f-0117.md` (approved). Branch: `plan/F-0117`.

**Six Tasks, five waves.** The spec's §*The design* is almost the split: one new package of four
modules, one new module for the receiving side, one edit each in six existing files. What it does
not settle is the *order*, and here the order is not a convenience — it is the card's own
guarantee. C13 says *"no control inversion is a test, not a sentence"*, and the test it specifies
cannot pass against this tree as it stands: **three of the functions the spec's own read model
calls create a directory in another product's state tree before they read anything** (PD1). So the
first Task is not a cell of the table. It is the correction that makes every later Task's read
path structurally incapable of the write C2 forbids, with its own fence at the moment it lands.

After that the chain is the spec's: the read model and the table, then the merged tail beside an
unchanged `asf watch`, then the conversation and the config it is governed by, then the console's
own command and the guide, and last the tree digest that proves the whole of it wrote nothing.

Each Task lands something whole. After Task 1 no reader in `capacity`, `pool` or `approvals`
creates a directory, and a fresh `ASF_HOME` survives a full read. After Task 2 `asf center` prints
one row per product on the machine with every cell's age. After Task 3 `asf center follow` merges
four streams per product and `asf watch`'s six tests are still byte-identical. After Task 4 the
operator can ask one product a question and read its answer back.

**Read PD1 before writing a line of the read model (Tasks 1 and 2).** It is the place the spec's
own read-model table names three functions that violate the spec's own C2, and it is why the split
starts where it does. **Read PD2 and PD3 before the machine block (Task 2)** — they are the two
places C12's *"the same word the wave will act on, stale reading rule and all"* is not achievable
from the cached samples as written, one of them fatal to a fenced assertion. **Read PD8 before the
`deliver` path (Task 4)** — the fenced write-scope assertion in the spec is only true for a product
that names no `deliver`, and the Task that writes `deliver` must not break it. **Read PD5 before
Task 5** — three registries have an ordering constraint between them that an existing test
enforces.

| PD1 | **Three functions the spec's read model calls create a directory in another product's state tree, and two of the spec's own fenced assertions fail because of it. The fix is in the owning modules, not in the center: the path helper composes and the writer makes its own directory.** | P3 is measured and the spec builds C2 and C13 on it: `env.state_dir` calls `os.makedirs`, so *"any reader that reaches another product's state through it is therefore a writer."* The spec then names P9's `approvals.open_holds` as the one function that inherits P3. Measured here, it is not one of three but one of **seven**, and **three of them are in the spec's own read-model table and machine block**: (a) `capacity._demand_path` (`asf/capacity.py:357`) is `os.path.join(env.state_dir(name), DEMAND_FILE)` — so `capacity.read_demand_record(name)`, which the `demand` cell names, creates `state/<name>/`; and so does `capacity.claim`, and therefore `capacity.fair_share`, which the `share` cell needs. (b) `pool.sessions_path` (`asf/workers/pool.py:220-221`) is `os.path.join(env.state_dir(product), 'sessions.jsonl')` — so `capacity.inflight_sessions` / `live_sessions`, which `fair_share` reaches through `claim`, create it too. (c) `approvals.ledger_path` (`:626-627`) — P9's own case. P8's sentence *"`inflight_sessions` / `claim` / `read_demand_record` are file reads only"* is true about the network and false about the filesystem; that is the half the spec missed. The consequence is not cosmetic: the spec's WriteScope fence asserts *"`state_dir` monkeypatched to raise, with the whole read pass still green"* and *"a product whose state directory is absent before the pass still absent after it"*, and **both fail** while any of the three is in the read path. Three ways out. **Rejected: the center reads and folds all three itself from composed paths.** It would duplicate `DEMAND_FRESH_S` and the demand record's parse, the forty-line hold fold, *and* — because `fair_share` is unreachable — the `ceil(usable × weight / Σ weights)` share arithmetic with its borrow rule. Duplicating load-bearing arithmetic is exactly what C5 refuses for the tailer, for the same reason. **Rejected: path-taking siblings (`read_demand_at`, `open_holds_at`) beside the product-taking ones.** It leaves `fair_share` unusable, so the share arithmetic is still duplicated, and it adds a second spelling of three paths. **Chosen: the three path helpers compose the path exactly as `scheduler.pause_path` (`asf/scheduler.py:518-519`) and `headroom.samples_path` (`:298-299`) already do — `os.path.join(env.ASF_HOME, 'state', <name>, …)` — and the `os.makedirs` moves to each one's writer**, of which there are three: `capacity.write_demand` (`:364`), `pool.append_session` (`:228-231`, which `update_session` calls) and `approvals.append` (`:630-632`). Six lines. No existing caller changes behaviour, because every existing caller either writes through one of those three or reads a file whose absence it already handles. It is a strict improvement of the same class P3 names — a reader that creates a directory is the defect, not the convention — and it is what makes C2's claim structural rather than a rule the center alone remembers. Two precedents in this tree for the composed form and one (`asf/harvest/harvest.py:134`, `sessions_path(state_dir)`) for a path-taking session reader. |
| PD2 | **The cached quota sample carries no `polled_at`, so `quota.band` reads a sample of any age as current — C12's stale rule never fires, and the Read fence's third band case cannot pass. The center supplies `polled_at` from the sample's own `ts`.** | C12 reuses the real `quota.band` *"so the word the center prints is the word the wave acts on, stale reading rule and all"*, and the Read fence asserts a third case for it: *"a sample older than `stale_after_min` that was over its stop → `stop` to its reset"*. The whole stale path hangs off one key: `quota.stale_since` is `polled = polled_at(usage); if polled is None: return None` — and its docstring is explicit, *"A reading that names no `polled_at` is taken as current"* (`asf/workers/quota.py:88-97`). `headroom.record_samples` writes `{'ts', 'account', 'five_h_pct'}` and nothing else (`:302-315`). So a usage dict built straight off a sample has no `polled_at`, `stale_since` is None, `stale_stop` is None, and a three-day-old 38% reading bands `free` with no staleness of any kind — a monitor telling the operator an account is free on evidence from Tuesday. Settled: `read.py`'s sample-to-usage step is `{'five_h_pct': rec['five_h_pct'], 'polled_at': rec['ts']}` — the sample's own write time *is* when the vendor was last asked, which is precisely what `polled_at` means. With it, all three fenced band cases are reachable and the stale rule fires at `stale_after_min` exactly as the wave's does. This is a correction to the spec's §1 `machine()` paragraph, which says only *"turned into a `usage` dict"*; the key it must carry is named here because without it one third of a fenced assertion is unsatisfiable. |
| PD3 | **The cached samples carry only the 5-hour window, so the center's band can never see a 7-day stop the wave would — the row says which window it read, and the guide says so; it does not claim parity.** | `record_samples` keeps one percentage per account, `five_h_pct`, and drops `seven_d_pct` and `seven_d_model_pct` (`:308-310`) — while `quota.band` judges all three of `WINDOW_KEYS` for stop and then for cooldown (`:159-166`). An account at 40% on 5h and 97% on 7d is `stop` to the wave and `free` to the center, and no amount of care in the center changes that: the number is not on disk. C3 forbids the fix that would close it (running the quota command centrally — *"a monitor that re-reads a vendor on every glance is a monitor that spends money and rate limit to tell you what the last wave already knew"*), and C12 is right that re-deriving a band would be worse. So the gap is **named rather than closed**: the machine block's per-account cell renders the band with the window it was read from — `lane-1  free (5h 38%, read 4m ago)`, which is the spec's own mock-up format and already says `5h` — and `docs/guide/command-center.md` (Task 5) carries the one sentence that a band here is the 5-hour window off the last wave's sample, and that `asf capacity` on the product is what asks the vendor. `headroom.active_limits()` covers the other half honestly and completely: a session-limit stop is a real machine-wide fact on disk, and `Pool.band` consults it *before* the reading (`asf/workers/pool.py:357-361`), so a stopped account shows `stop — until <t>` whatever its 5h sample says. Widening `record_samples` to cache all three windows is the right fix and is a Bug of its own: it changes a file the wave writes on every pass, it belongs to `headroom`, and it is out of this card's footprint. **`NEEDS OPERATOR`** is not raised for it — nothing here is blocked, and the row is honest as specified. |
