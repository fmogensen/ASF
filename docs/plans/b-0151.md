# B-0151 — plan: ASF reserves a sequence's next number across every open lane

Item: B-0151 — Lane branches collide on sequential numbers (migrations, bands); ASF should
reserve them. Epic: E-0001 — ASF 0.1 — a working factory. Branch: `fix/B-0151`. No spec exists;
the Acceptance below is the record.

## Cause

Two lane branches built in parallel each computed a sequence's next number (a migration file, a
decision band) by looking only at their own checkout, so both picked the same number and one's
merge went red against the other's already-landed migration file. Nothing in the factory
reserved a number across branches, and nothing reserved it across runners either — a local file
would only ever be seen by the one runner that wrote it, and a cloud session's runner is fresh
every time.

## Task 1 — `asf reserve <sequence>` claims the next number on origin

writes: `asf/reserve.py` `asf/conventions.py` `asf/cli.py` `tests/test_reserve.py`

- Step 1: add `asf/reserve.py`. `pattern_regex(filename_pattern)` turns a declared pattern
  (`NNNN_*.sql`) into `(regex, width)`, raising `ValueError` on a pattern naming no `N` run — the
  card's bands sequence must be a `NNNN`-shaped path, not a single shared file. `compute_next`
  takes the max number found across a mapping of source -> filenames plus any already-claimed
  numbers, and returns one past it.
- Step 2: in `asf/reserve.py`, `claim(product, sequence, n)` pushes a fresh, parentless commit
  (the well-known empty-tree sha) to `refs/heads/reservations/<sequence>/<n>` on `origin`; git
  itself refuses whichever of two racing pushes arrives second, since neither is a fast-forward
  of the other. `remote_reserved_numbers` reads every such ref back with one `ls-remote` — the
  same view every runner gets, a fresh cloud checkout included, closing the race a local
  reservations file could not.
- Step 3: `open_branch_trees(product, dirname)` reads `origin/<main>` plus every open lane branch
  (an unmerged code/fix branch on origin, via `asf.evidence.evidence`) for the sequence's
  directory, and `reserve(product, sequence)` combines Steps 1-2: recompute the candidate, attempt
  `claim`, retry on a lost race up to `MAX_ATTEMPTS`, and return the zero-padded number.
- Step 4: in `asf/conventions.py:329-336,580-588`, add the `sequences` convention
  (`DEFAULT_SEQUENCES = {}`, the `sequences` field) — a product declares
  `{migrations: 'db/migrations/NNNN_*.sql', bands: 'docs/decisions/NNNN-*.md'}`; `'sequences'` is
  in `MAP_CONVENTIONS` so a misshapen block is a red doctor row.
- Step 5: in `asf/cli.py:267-270,527-529`, add the `reserve` subcommand (`asf reserve <sequence>
  [--product]`), wired to `asf.reserve.cmd_reserve`.
- Step 6: tests, in `tests/test_reserve.py`:
  - `PatternRegexTests` — a pattern's number field and width are captured; a pattern naming no
    `N` run raises.
  - `ComputeNextTests` — an open lane branch's own numbers count, not just main's; prior
    reservations count too; the result is zero-padded to the pattern's width.
  - `ReservationRefTests` — the ref name carries the sequence and the number.
  - `RemoteReservedNumbersTests` — `ls-remote` output parses into the claimed numbers; no claims
    yet is empty.
  - `ClaimTests` — a push that lands is a claim; a push refused (another session's claim already
    holds the ref) is not.
  - `ReserveTests` — an undeclared sequence refuses; a second call made before either session's
    branch is pushed does not repeat the first; a lost race moves on to the next candidate; heavy,
    sustained contention gives up loudly instead of looping forever.

## Out of scope

The card's Ask has a second half — "the rebase-before-publish step re-checks and renumbers a
collision against main automatically, instead of a correct round" — for the case where two
sessions claimed numbers before either one existed as an open branch (`open_branch_trees` cannot
see a branch that has not been pushed yet) and one lands after the other. This plan scopes that
out: `reserve` closes the incident this card names (two sessions racing the same number), and the
publish/rebase path is unchanged by this Task. Renumbering a landed collision at publish time is
tracked separately, not silently dropped.

## Acceptance

- [x] `asf reserve <sequence>` returns a number one past the highest any of origin's trunk, every
      open lane branch, or any prior claim for that sequence carries
      (`tests/test_reserve.py::ComputeNextTests`, `::ReserveTests`).
- [x] The returned number is claimed on `origin` before `reserve` returns, so a second call made
      before either session's branch is pushed does not repeat it — a fresh cloud runner with an
      empty `ASF_HOME` included (`tests/test_reserve.py::RemoteReservedNumbersTests`,
      `::ClaimTests`, `::ReserveTests::test_second_call_does_not_repeat_the_first_before_any_branch_is_pushed`).
- [x] A sequence conventions does not declare, or a pattern naming no `NNNN` run (a single shared
      file, not a numbered one), refuses rather than reserving nonsense
      (`tests/test_reserve.py::PatternRegexTests::test_no_number_field_is_an_error`,
      `::ReserveTests::test_unknown_sequence_refuses`).
- [x] Two sessions racing the same number: one claims it, the other moves on to the next
      candidate rather than colliding (`tests/test_reserve.py::ReserveTests::test_a_collision_moves_on_to_the_next_candidate`).

## Accepted costs

Claim refs accumulate on `origin` forever by design (an abandoned claim is never cleaned up) —
the same cost the old local reservations file had, now visible as ordinary branches instead of a
hidden local file. An operator cleanup story is unwritten. Publish-time renumbering (see "Out of
scope" above) is a separate, unscheduled piece of the card's Ask.
