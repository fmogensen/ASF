# Plan F-0158 — the gate the runtime already carried, its bound, its arming, and a stream that can say it was wrong

Epic: E-0001 — ASF 0.1 — a working factory. Spec: `docs/specs/f-0158.md` (approved). Branch: `plan/F-0158`.

Five Tasks, cut the way the spec's `## Stories` are cut and the way `## The design` is sectioned:
the **one owner for the git evidence** (§2.1), the **gate itself** — module, bound, convention, the
`spawn` clear and the half-sentence in the preamble that stops the prose from being a lie (§2.2,
§2.3, §2.7), the **arming** (§2.4), the **stream that can record a corrected verdict** (§2.5), and
the **meter that is not moved, whose cause now names its sub-causes** (§2.6).

Task 1 owns `asf/workers/lifecycle.py` and the four-line delegation in `asf/workers/health.py`.
Task 2 owns the new `asf/workers/stopgate.py`, one field in `asf/conventions.py`, one line in
`asf/workers/spawn.py`, the one bullet in `asf/briefs/preamble.py` and every golden brief fixture
that bullet appears in. Task 3 owns `asf/hooks.py` and the `unpushed-gate` row in `asf/doctor.py`.
Task 4 owns `asf/metrics/metrics.py`. Task 5 owns `asf/scorecard/diagnose.py` and two defaulted
fields on `asf.improve.measure.Run` (PD1).

Wave order: **{1, 4} → {2, 5} → 3** — in `after:` terms, 1 and 4 with `none`, 2 after 1, 5 after 1,
3 after 2. No two Tasks' `writes:` intersect, so every wave runs its Tasks side by side.

The spec's whole-suite fence binds every Task, so it is the last line of every Gate and the last
Acceptance block of every Task below.

**The three things this plan adds to the spec, and why each of the spec's own sentences is false
without it:** PD1 — §2.6 says the sub-causes are "read off the evidence already recorded … its
`publish_refused` line", and `asf.improve.measure.Run`, the only run object `diagnose` ever sees,
carries neither `publish_refused` nor `worktree`. PD2 — the spec's own §1.4 row "the gate refuses a
clean tree on a branch never pushed" produces a `not pushed: 0 uncommitted file(s), 0 unpushed
commit(s)` run that falls in none of §2.6's four sub-causes. PD8 — `append_event`'s third status
reaches `cmd_append`, which would print `appended to …` for a rewrite. Read PD1, PD2 and PD8 before
Task 5 and Task 4.

| PD1 | **§2.6's sub-causes cannot be read off the evidence the spec names: `measure.Run` carries neither `publish_refused` nor `worktree`** | §2.6: *"The sub-cause of a run is read off the evidence already recorded — the counts in its own `end_reason` text, and its `publish_refused` line — and nothing new is computed or stored"*, and §1.1's last precondition says `publish_refused` *"is written by `republish_steps` and read by nothing that reports"*. So **Task 5 adds two fields with defaults** — `publish_refused: str = ''` and `worktree: str = ''` — and populates them in `ended_runs` from `r.get('publish_refused') or ''` and `r.get('worktree') or ''`. | PD2 | **A fifth sub-cause, or the line does not add up: the branch that was never pushed at all** | §1.4's own row — *"The gate refuses a clean tree on a branch never pushed"* — and `push_gap`'s body (`asf/workers/health.py:266-274`) agree that a clean worktree whose branch origin does not hold is `not pushed: 0 uncommitted file(s), 0 unpushed commit(s)`. | PD3 | Where the sub-cause numbers live, and why they are counts and never runs | `rank`'s `by_failure` entry gains one key, `sub`, a `{name: int}` dict; `causes` formats §2.6's line from it. The entries must **not** carry the `Run` objects they were counted from: `cmd_scorecard` serialises the whole view dict — `rank`'s output included (`asf/views/scorecard.py:50`) — with `json.dumps(d, indent=1, default=str)` (`:216-230`), so a list of dataclasses would land in that JSON as `repr` strings, and `Run` carries `job`, which is a lane job name. A dict of ints is JSON-safe and says everything the line needs. The existing renderer of `by_failure` (`asf/views/scorecard.py:104-105`) reads `name`, `runs` and `usd` by name, so a sixth key changes no rendered byte. |
| PD4 | What `stop_hook_active` actually adds, since the counter is the authority | §1.4's *"belt and braces"* row wants both signals, and §2.3's own `spent()` body reads only the counter — correctly, because *"`stop_hook_active` is … never permission to refuse again"*. The one case where the payload is load-bearing is the one that would trap a session: a counter that cannot be **written** (an unwritable or full state dir) never advances, and an unbounded refusal loop is exactly the failure §1.3 forbids. So `bump` returns whether the count reached disk, and `spent(product, job, conv, payload)` is true when `refusals() >= bound`, **or** when the last `bump` could not be written and the payload says `stop_hook_active` is true. The counter stays the authority in every case where it works; the payload is the escape when it does not. This is testable without a runtime (T3 drives `spent` directly) and satisfies T3's *"a payload carrying `stop_hook_active: true` at the limit also returns `0`"* either way. |
| PD5 | Where the refusal's commit-subject prefix comes from, and that the run's `kind` really is the brief kind | §2.2's refusal names `spec(F-0158)` for a spec session, so the gate needs the subject prefix, and the one owner of that mapping is `asf.briefs.preamble.SUBJECT_KIND` (`asf/briefs/preamble.py:82-83`), read by `subject_rule` (`:86-91`) to write the very line the session was already given. ### Task 1: one owner for "is this on origin" — `lifecycle.unpublished`
stories: S-35950
writes: asf/workers/lifecycle.py, asf/workers/health.py, tests/test_lifecycle.py
after: none

§2.1 and nothing else. `health.push_gap`'s body moves down to `asf/workers/lifecycle.py` beside
`unpushed_commits` and `push_gap(ev)`, and `health.push_gap` becomes a one-line delegation that
keeps its name, its signature and every caller. This is the move f-0103 made for `outcome_class`,
for the reason §1.4 gives: the gate must refuse on exactly the condition `judge` will later fail the
run on, and two implementations of "is this pushed" drift the day one of them changes a git flag.
On this Task alone the only observable change in the tree is which module the function's body lives
in — byte for byte the same answer for the same worktree, which is what the last clause of the T1
fence asserts.

**Files**

- `asf/workers/lifecycle.py` — `unpublished(wt, branch, main='main')`, new, beside `push_gap(ev)`
  (`:1584`)
- `asf/workers/health.py` — `push_gap(worktree, branch, main)` (`:257-274`) becomes the delegation
- `tests/test_lifecycle.py` — `UnpublishedTests`

**Steps**

1. `asf/workers/lifecycle.py`: add `unpublished(wt, branch, main='main')` with the spec's docstring
   byte for byte (§2.1's fenced block, all four paragraphs including the B-0051, B-0053 and D-0048
   references). Place it after `push_gap(ev)` in `# ---- the derived state ----`, so the two
   spellings of the same sentence — the one over gathered `Evidence` and the one over a live
   worktree — sit together and a later edit to either is visible in one screen.
2. The body is `health.push_gap`'s current body (`asf/workers/health.py:266-274`) verbatim, with
   `_git` now resolving to `lifecycle._git` (`asf/workers/lifecycle.py:921-922`, the same
   `subprocess.run(['git', *args], cwd=…, capture_output=True, text=True)`) and
   `lifecycle.unpushed_commits(...)` called as a module-local name. Do not change the order of the
   three git calls, the `if st.returncode != 0` fallback of `n` to `0`, or the
   `if n == 0 and m == 0 and remote` condition — every one of them is a behaviour some run in the
   registry depends on, and this Task's whole claim is that nothing moved.
3. One addition the spec's T1 fence requires and the current body does not have: a detached `HEAD`
   or an empty `branch` must answer `(False, 'no branch')`. Today `push_gap` with `branch=''` skips
   the `ls-remote` (`:268`), leaves `remote` empty and returns the counted form, so the fence's last
   case would read `not pushed: 0 uncommitted file(s), N unpushed commit(s)`. Add, before anything
   else: resolve an empty `branch` from `git rev-parse --abbrev-ref HEAD` (the shape
   `health.pushed` and `health.has_commits` both already use, `asf/workers/health.py:238-242` and
   `:288-294`), and return `(False, 'no branch')` when it is still empty or is `HEAD`. This is the
   same sentence `health.pushed` already returns for that case (`:242`), so the vocabulary gains
   nothing.
4. `asf/workers/health.py`: replace `push_gap`'s body with
   `return lifecycle.unpublished(worktree, branch, main)`. Keep the name, the signature, the
   docstring (it is the caller-facing text and `result_reason` cites it) and the position;
   `lifecycle` is imported at the top of the module already. Nothing else in `health.py` moves in
   this Task — `publish_gap`, `republish_steps` and `push_retry` are §1.3's "the net under the gate"
   and are not touched.
5. `UnpublishedTests(unittest.TestCase)` in `tests/test_lifecycle.py`, over a real git fixture
   (`tests/gitfixture.py`, the helper the rebase cases in this module already use), one case per
   clause of the T1 fence: a clean worktree whose branch head is on origin → `(True, '')`; two
   uncommitted files → `(False, 'not pushed: 2 uncommitted file(s), 0 unpushed commit(s)')`, the
   string asserted whole; one commit above a pushed head → `0 uncommitted, 1 unpushed`; a branch
   never pushed with a clean tree and no commits above the trunk → `ok` is `False` (the branch
   itself is missing from origin, which is the D-0048 slice §1.4 counts on); a detached `HEAD` →
   `(False, 'no branch')`.
6. Two more cases in the same class, both of which are the point of the Task: `unpublished`'s detail
   for a given `(n, m)` is byte-identical to `lifecycle.push_gap(Evidence(uncommitted=n,
   unpushed=m))` — assert the two strings equal, do not re-spell the format in the test — and
   `health.push_gap(wt, branch, main)` returns exactly `lifecycle.unpublished(wt, branch, main)`
   for the same worktree in at least the clean and the two-uncommitted cases.
7. Run `python3 -m unittest tests.test_lifecycle tests.test_health_publish_steps` before the suite:
   those two modules are every caller of `push_gap` under test, and `tests/test_lifecycle.py:1906-1912`
   already pins `push_gap(ev)`'s bytes — the frozen string of §1.3 — from the other side.
