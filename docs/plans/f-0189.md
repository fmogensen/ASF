# Plan F-0189 — the ledger, the compare-and-set, the row that re-decides, and the two waves

Epic: E-0001 — ASF 0.1 — a working factory. Spec: `docs/specs/f-0189.md` (approved). Branch:
`plan/F-0189`.

Four Tasks, a strict chain. The spec's shape is already a chain — a ledger nothing reads, then the
one reader that turns it into a decision, then the two call sites that act on the decision, then the
card's own two-process proof over all three — and each link is unusable without the one before it:

1. **`asf/workers/seats.py`** — the claim file, its lock, and the one definition of when a claim is
   alive. Nothing imports it yet; landing it changes no behaviour at all.
2. **`Pool.take` is the compare-and-set** — `from_config` counts every other product's outstanding
   claim, `take` re-reads under the lock and may refuse, `untake` frees the claim with the seat,
   `retake` moves a held claim's model. This is the Task that closes the card's measurement.
3. **The two launch paths act on a refusal** — the wave re-decides the row through its existing
   re-decide path and prints the two new lines; `asf workers spawn` claims before it spawns.
4. **Two real processes, one account, four seats** — the card's own test, which can only be written
   once 1–3 are on the trunk.

Wave order: **1 → 2 → 3 → 4**, one Task per wave. All four write `tests/test_seat_claims.py`, so the
feeder queues them against each other whatever `after:` says — and that costs nothing here, because
1 → 2 → 3 → 4 is the dependency order anyway (PD1).

**Read PD2 before writing a line of Task 2**: the spec's `_refresh` rebuild (`registered + extras +
claim rows`) silently discards a hand-built pool's `live`, and six wave tests in `tests/test_cloud.py`
— a module the spec's own regression run names — pass `live=[…]` into a real wave. **PD3** is the two
sets besides `extras` that the rebuild must keep from the build, or a dead-pid-but-`ps`-visible run
stops counting at the first take. **PD4** is why "spends no cloud try" needs an explicit rollback:
`cloud_tries` is spent inside `decide()`, before the take. **PD7** is the whole-tree AST fence a new
module under `asf/` is inside and the spec does not name.

| PD3 | **The rebuild keeps three things from the build, not one: `extras`, `seen_pids` and `seen_sessions`** | §2 says the rebuild's `registered` is *"`lifecycle.live_all(...)` filtered exactly as `from_config` filters it"* and that `extras` are *"the `ps`-observed rows kept from the build"*. | PD4 | **`cloud_tries` is spent inside `decide()`, before the take — the refusal must roll it back, and the retry must not spend a second one** | §3 says a refused row *"must not hold its branch or spend a cloud try"*, and lists `running`, `branches`, `local_taken` and `cloud_tries` together as things advanced only after a successful take. ### Task 1: the claim ledger — one file, one lock, and one definition of a live claim
stories: S-35850
writes: asf/workers/seats.py, tests/test_seat_claims.py
after: none

The spec's §1 in full, and nothing else. No module imports `asf.workers.seats` when this lands, so
the factory's behaviour is byte-identical — this Task exists so that the rule about *when a claim is
alive* is written once, before two call sites start asking it.

**What changes for the machine when this lands.** Nothing observable. One new module, one new test
class. No file is created under `ASF_HOME` until something calls `held()`, and nothing does yet.

**Files**

- `asf/workers/seats.py` — **new**. The module docstring names F-0189 and states the one invariant:
  a seat is claimed where every product on the host can see it, and the claim is tested against the
  cap in the same atomic step. Public surface exactly as the spec fixes it: `LEDGER`, `LOCK`,
  `CLAIM_TTL_S`, `LOCK_WAIT_S`, `POLL_S`, `FIELDS`, `Busy`, `Unusable`, `root()`, `ledger_path()`,
  `lock_path()`, `held(wait_s=LOCK_WAIT_S)`, `read(registered=None, now=None)`, and the `Ledger`
  class with `claims`, `add(claim)` and `remove(product, job)`.
- `tests/test_seat_claims.py` — **new**, the module the next three Tasks extend. A module docstring
  naming the card and the four classes to come, the `sys.path` + `from test_workers import Home,
  feature_row` idiom of `tests/test_dead_run_load.py:15-16` (PD8), and `SeatLedger(Home)`.

**Steps**

1. Paths resolved **per call**, never at import (P7): `root()` is `os.path.join(env.ASF_HOME,
   'state')`, and `ledger_path()`/`lock_path()` join `LEDGER`/`LOCK` onto it. A test that swaps
   `env.ASF_HOME` between two calls must get two answers — that is how every fixture in the suite
   works, and a module-level constant would make the ledger unswappable.
2. `held(wait_s=LOCK_WAIT_S)`: a context manager. Create `root()` if it is missing; any `OSError`
   from that, or from opening `lock_path()` for append, raises `Unusable` carrying the reason as its
   `str`. Then `fcntl.flock(f, LOCK_EX | LOCK_NB)` polled at `POLL_S` to a `time.monotonic()`
   deadline, `Busy` on timeout — the `tick._flock` shape (P9), not an import of it: that function is
   bound to a product's tick path and returns `None` rather than raising. Yield a `Ledger` **already
   swept**; a sweep that dropped rows writes the file on the way in, so a crashed claimer's seats are
   collected by the next writer even if that writer then decides not to claim. Release the lock and
   close the file in a `finally`, whatever the body did.
3. `Ledger.add(claim)` and `Ledger.remove(product, job)`: mutate `self.claims`, then write the whole
   list as `json.dumps` to `seats.json.tmp` in the same directory and `os.replace` it onto
   `ledger_path()`. Whole-file, never append: a claim is removed as often as it is added, and a
   partial write of a list is not a list. The lock is on a **separate** file (C1), so `os.replace`
   never swaps the inode a waiter is blocked on. `add` stores exactly `FIELDS` and nothing else.
4. The sweep — one function, used by both `held()` and `read()`, so the lock-free reader and the
   writer can never disagree about which claims are alive. A claim dies when any of: (a)
   `not lifecycle.pid_alive(c['pid'])`; (b) `now - parse(c['at']) > CLAIM_TTL_S`; (c) `(c['product'],
   c['job'])` is the key of a live registered run. For (c) the run list is the caller's
   `registered` when it passed one, else `lifecycle.live_all(root())` — `read`'s `registered=`
   parameter exists so `Pool.from_config`, which has just computed that list, does not walk every
   registry twice (P4). An unparseable `at` is treated as expired, not as an exception: a claim whose
   timestamp is garbage is not a seat.
5. `read(registered=None, now=None)` → `(claims, why)`, lock-free and never raising. A missing file
   is `([], '')` — no claims is the normal state of a quiet host, not a fault. A file that will not
   parse, or will not open, is `([], <the reason>)`; the reason is what the wave prints (C6, PD5).
   `read` does **not** write: rewriting a garbage file is a writer's job, done under the lock by
   step 3, and a lock-free rewrite would race one.
6. The sweep and the rules ask `lifecycle` for both questions (`pid_alive`, `live_all`) and derive no
   session state of their own — which is what keeps the module clear of the whole-tree fence at
   `tests/test_lifecycle.py:803` (PD7). No `STATE_WORDS` literal, no `end_reason` comparison, in code
   or in a constant.
7. `SeatLedger(Home)`, the spec's bullets one test each: a claim round-trips through `add` then
   `read`; a second `held()` while one is open raises `Busy` inside `LOCK_WAIT_S` (open the first in
   the test and assert the second raises — with a short `wait_s` so the case is fast); a claim whose
   pid is dead is swept (`dead_pid()` from `tests/test_dead_run_load.py:29-32` — `subprocess.Popen(
   ['true'])` then `wait()`); a claim older than `CLAIM_TTL_S` is swept; a claim whose
   `(product, job)` has a live registered run is neither counted by `read` nor kept by `held`; a
   garbage `seats.json` reads as `([], why)` with a non-empty `why` and is rewritten by the next
   writer; a state root that cannot be written raises `Unusable` carrying its reason. Also pin
   `ledger_path()` moving when `env.ASF_HOME` moves — step 1's whole point.

**Gate**

```bash

python3 -m unittest -v tests.test_lifecycle tests.test_capacity
python3 -m unittest -v tests.test_workers tests.test_dead_run_load

```

**Acceptance**

3. `_refresh(ledger)`: `base = self._reread() if self._reread is not None else self._base`, then

   both is the mirror of the defect. A claim whose `pid` is `os.getpid()` becomes the **exact** 7-key

5. `take(account, model, job='', product=None, kind=None, lane=None)` → `True`/`False`, with the

   the line). Under the lock: `self._refresh(ledger)`; then `if lane != 'cloud' and not

   `ledger.add(...)` with `pid=os.getpid()` and `at=now_iso()`, append the seat to `self.live`, add

   writes nothing — no claim, no live row, no committed cost.
6. `untake`: same signature, same `True`/`False`, and now `ledger.remove(product, job)` under the
   lock so a failed spawn frees the seat now rather than in `CLAIM_TTL_S` (C5). `Busy` or `Unusable`
   there loses only the eager release — sweep rule (a) or (b) collects it — so neither raises out of
   `untake`, and the in-memory half runs either way.
7. `retake(account, seat, model)` (C8): one lock, no cap test, never refused — the claim's `model`
   and the live row's are replaced together and the new seat dict is returned. It is a correction of
   a held claim for a launch that has already succeeded; refusing there would free a seat for a
   running session, which is the overcommit inverted. `wave.py`'s call site is Task 3's.
8. `PoolClaims(Home)`, the spec's bullets: the opening reproduction inverted — `a`'s pool takes 4 on

   per-model `caps` ceiling refuses the same way; `untake` returns the seat and the claim in one step
   and a rebuilt pool sees the account free; `untake` still finds its seat **after** a `_refresh`
   (P11 — the case that catches a rebuilt dict with one wrong key); `retake` swaps the model on both
   the claim and the live row and is never refused; a `Busy` lock makes `take` return `False`; an

### Task 3: the row whose seat went, and the hand launch that claims before it spawns
stories: S-35852
writes: asf/workers/wave.py, asf/workers/__init__.py, tests/test_seat_claims.py
after: Task 2

The spec's §3 and §4. After this Task a refusal is acted on rather than ignored, which is what makes
Task 4's assertion — two waves, four launches, never six — true.

**Read PD4 before touching the take site**: `cloud_tries` is spent inside `decide()` at
`asf/workers/wave.py:244`, before the take, so "spends no cloud try" needs an explicit rollback and
the retry must not spend a second one. **PD5** is why the degraded line is wired to `from_config`'s
`seats_degraded`, and **PD6** is the `already running` case to assert rather than fix.

**What changes for an operator when this lands.** Two new lines, and one fewer overcommit. A row
whose seat was claimed under it is decided again, silently, up to twice; if it then finds nothing it
waits with `seat claimed elsewhere — <acct> <load>/<cap>` instead of launching onto a full account.
A host that cannot use the ledger at all says so once, before the first row, and launches anyway.

**Files**

- `asf/workers/wave.py` — the take site at `:301` becomes the refusal branch; `running`, `branches`,

  back on a refusal (PD4); `settle`'s `untake` + `take` swap at `:255-256` becomes one `pool.retake`

  `spawn.spawn(...)`, prints the refusal and returns 1, and `untake`s when the spawn raises.
- `tests/test_seat_claims.py` — `WaveRefusedSeat(Home)` added.

**Steps**

1. The take site, at `asf/workers/wave.py:301` (**not** `:296-306` — PD13 drift 1). The seat dict is
   built as it is today, then:

   ```python
   if not pool.take(acct, **seat):           # another product claimed it between the pick and now
   ```

### Task 4: two real waves, one account, four seats — the card's own test

The card's test, and nothing else: *two concurrent waves never exceed an account cap.* Against the
