# Plan F-0175 — the pass that reaches its own watermark, the row that reads its age, and the window the policy already had

Epic: E-0001 — ASF 0.1 — a working factory. Spec: `docs/specs/f-0175.md` (approved). Branch:
`plan/F-0175`.

Three Tasks, one per Story, cut exactly where the spec's §*The three Stories' footprints* cuts
them — because that cut is the one that makes the only real edge explicit:

1. **the pass** — `metrics.ci_facts` as the one parser, the watermark window, the held-run cache,
   the `ci:` line, and `groom.trunk_ci_runs` reduced to reversing `ci_facts`. Everything the
   record does with a trunk CI fact after this Task goes through one function.
2. **the row** — `doctor.check_ci_facts`, `conventions.ci_stale_factor`, and the guide row.
   **After Task 1**: `check_ci_facts` calls `metrics.ci_facts`, which does not exist until Task 1
   lands.
3. **the window** — one guard in `decide_or_close_ci_red`, moved off the failure branch onto the
   job's newest fact. Depends on neither of the others and may land beside them.

They run **wave 1: Task 1 ‖ Task 3**, then **wave 2: Task 2**. The three `writes:` sets are
disjoint (PD5 widens Task 1's by one test module and keeps it so), so wave 1 is a real
parallel wave and not a queue.

**Read PD1 and PD2 before writing a line of Task 1.** PD1 is a variable the spec's design does
not see: `cmd_backfill`'s `since` is shared with the `sessions` half, so `--days` becoming
optional makes `days_back(today(), None)` raise on the first tick. PD2 is the spec's own claim
that the shipped `Backfill.test_ci_backfill_and_idempotence` "keeps passing unchanged" — it does
not, in three separate ways, and a coder who believes it will land a red module. **Read PD6
before writing a line of Task 2**: the spec's P15 names a `_get` that does not exist in
`asf/conventions.py`, so the new int key is read raw and a misshapen one crashes `asf doctor`'s
whole table.

Read here: `cmd_backfill` computes `since = days_back(today(), args.days)[0]` **once** (`asf/metrics/metrics.py:1723`) and passes it to `sessions_from_registry(product, since_day=since, items=items)` (`:1745`) as well as to `ci_from_api`. | PD3 | **`ci_facts` must order so that `tuple(reversed(ci_facts(...)))` is byte for byte today's `trunk_ci_runs`, and a `reverse=True` sort does not give that** | D10 collapses two readers into one and keeps `trunk_ci_runs`'s "exact contract". Today (`asf/groom/groom.py:1021-1038`): `_jsonl_lines` walks `sorted(glob(…/metrics/ci/*.jsonl))` — ascending by day — and `runs.sort(key=lambda r: r['ts'])` is Python's **stable** sort, so two facts with an equal `ts` keep their file order. `sorted(…, reverse=True)` is also stable, so it keeps that same relative order for ties — and reversing *that* puts tied facts in the **opposite** order from today, which moves `runs[-1]` and therefore which sha `decide_or_close_ci_red` names. **Decided:** `ci_facts` never sorts globally. It walks the day files **newest day first**, sorts each day's own facts ascending by `ts` (stable, exactly as today), reverses that day's list, and extends the output — stopping as soon as `limit` facts are in hand. Reversing the whole result then reproduces "ascending days, each stably ascending", which is today's tuple. stories: S-37100

**Steps**

1. The four constants and `ci_age`. `ci_age` is the `s`/`m`/`h`/`d` ladder, in the module that owns
   the fact; **do not** import `asf.doctor` from `asf.metrics.metrics` to reach `format_age`, and

2. `ci_facts(root, conv, limit=None)` — the spec's docstring verbatim, and **PD3's** body: walk
   `sorted(glob(os.path.join(root, 'metrics', 'ci', '*.jsonl')))` **reversed**; per day file, parse

3. `ci_watermark(root, conv)` → `ci_facts(root, conv, limit=1)[0]['ts']`'s day as `YYYY-MM-DD`, or

   `days_back(day or today(), CI_CATCH_UP_DAYS)[0]`. Re-listing the watermark's **own** day is
   deliberate and must not be "fixed" to the day after: that day is the only one the stream may
   hold partially, and `append_event`'s first-write-wins makes the overlap free (P4).
5. `ci_runs_held(root, days)` → `{(e['run'], e['attempt']) for e in read_stream(root, 'ci', days)}`,
   with the day list built as **PD4** writes it.
6. `gh_lines_answered(args, timeout=300)` → `(lines, answered)`: `out = gh(args, timeout)`, the same

   `gh_lines` becomes the two-line wrapper. Every existing `gh_lines` call site stays byte-identical
