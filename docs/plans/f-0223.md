# Plan F-0223 — name it from the field the runtime already wrote, then stop throwing the work away

Epic: E-0001 — ASF 0.1 — a working factory. Spec: `docs/specs/f-0223.md` (approved). Branch:
`plan/F-0223`.

Four Tasks, cut the way D6 asks: **the naming lands first and alone**, and each of the three
mechanisms that follow is one predicate in `asf/workers/health.py`.

1. **the runtime's own word, read, recorded and printed** — `runtime.error_subtype`,
   `lifecycle.FAILED_BARE`, `runtime_error` on the run row and in `measure.Run`, and the `failed`
   class's sub-cause line in `diagnose`. One new test module. The cause key, the `end_reason` and
   `failure_class` are asserted **unchanged** (D1), so this Task changes what the card *says* and
   nothing about what it *counts*.
2. **a dead run's branch is published** — the publish gate, and the two sibling gates behind it
   that S-36551's own fence names (PD1, PD2).
3. **the item goes back** — the new arm on health's end-of-run ladder, `lifecycle.died_text`, and
   the question arm's gate, which does not cover a bare `failed` today and must (PD3).
4. **a cut-off session is resumed once** — `RESUMABLE`, the resume before the ladder, and the one
   thing health does not have today: a runtime (PD5, PD6, PD7).

They run **1 → 2 → 3 → 4**, a strict chain. That is not a preference: all four Tasks write
`asf/workers/health.py`, so their `writes:` intersect by construction and the queue is real
whatever the `after:` lines said. It is also the order the spec argues for — D6 lands the naming
first so S-36553's `RESUMABLE` table is set against a measured split rather than a guess, and
Task 3's correction text reads the `runtime_error` key Task 1 writes.

**Read PD1, PD3, PD5 and PD7 before writing a line.** Each is a place where following the spec's
design literally ships a fence that cannot pass or a hold that fires while a resume is running:
the publish gate is three gates, not one (PD1); the question arm's condition excludes bare `failed`
today, so "still parked" is a change, not a property (PD3); `health()` has no runtime and never
launches anything (PD5); and a resumed run is judged off the **old** result line until its child
writes its first `init` (PD7).

### Task 1: the runtime's own word — read, recorded, and printed as the `failed` class's sub-causes
stories: S-36550
writes: asf/workers/runtime.py, asf/workers/lifecycle.py, asf/workers/health.py, asf/improve/measure.py, asf/scorecard/diagnose.py, tests/test_dead_run_reason.py, tests/test_scorecard.py

The spec's §1 and §2 whole, plus `lifecycle.FAILED_BARE` (PD11). When this lands the factory
behaves identically — nothing is published that was not, nothing is held that was not, no run ends

**Steps**

1. `asf/workers/runtime.py`: `ERROR_SUBTYPES = {'error_max_turns': 'max turns',

4. `asf/workers/health.py`: add `runtime_error=runtime_mod.error_subtype(ev.result) or ''` to the

5. `asf/improve/measure.py`: `runtime_error: str = ''` after `worktree`, with the spec's comment

6. `asf/scorecard/diagnose.py`: `DEAD_SUBS = ('max turns', 'during execution', 'runtime error')`

   execution', 'runtime error': 'hit a runtime error', 'not recorded': 'ended before this was
   recorded'}`, each with the `#:` comment that says the names are **open** and why (PD10).
7. `dead_sub_cause(run)` — pure and total, the spec's two-step precedence and nothing else: a
