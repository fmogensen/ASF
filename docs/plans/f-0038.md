# Plan F-0038 — a factory-only CI class

Epic: E-0001 — ASF 0.1 — a working factory. Spec: `docs/specs/f-0038.md` (approved). Branch: `plan/F-0038`.

Six Tasks, cut along the spec's own sections by the thing that changes: the classifier (Task 1),
the configuration key (Task 2), the command CI calls (Task 3), the doctor row (Task 6), the
workflow re-cut into five jobs (Task 4) and the mirror that holds its copy of the class honest
(Task 5).

The classifier and the key touch nothing of each other and start together. The command needs
both — a class to return and a product key to read when `--globs-from` is absent. The doctor row
needs the same two and nothing else, so it runs beside the command. The workflow lands only after
`asf ci class` exists, because the `classify` job calls it on the very push that adds it (PD11).
The mirror lands last, over the workflow as it actually stands.

Wave order: **1 ‖ 2 → 3 ‖ 6 → 4 → 5**.

§3.7's gate — the whole suite green, plus the two checks and `asf check` — binds every Task, so
every Gate below runs it beside its own fence.

Four things the spec says are met differently here, each argued below and none of them a widening:
the mirror cannot read the workflow's glob block through `env.loads` (PD4), the factory-test job
cannot make the spec's own five-minute bound with a serial `unittest` invocation (PD5), the
module list the spec fixes is one module short of the rule the spec states for it (PD6), and one
line of the fenced workflow parses to the wrong thing (PD10).

| PD4 | **`env.loads` cannot read the workflow's glob block, and §3.4/§2.5 both have to** | Measured against this checkout: `env.loads` parses a block scalar's *introducer* and skips its body, so `FACTORY_ONLY_PATHS: \|` comes back as the one-character string `'\|'` and the globs are gone. | PD5 | **The factory-test job runs the repo's own parallel runner, not a serial `unittest`** | §2.4 fences the job as `python3 -m unittest -v tests.test_run_tests tests.test_cutover tests.test_check_generic tests.test_workflow`. Timed on a ten-core dev machine, alone, warm: `test_cutover` 83s, `test_check_generic` 8s, `test_run_tests` 3s, `test_workflow` 0.2s — ~95s serially, ~163s with PD6's fifth module (`test_conventions`, 68s). So the job is one step, `ASF_GATE_MODULES: <the modules>` in the step's `env:` and `python3 tools/run_tests.py` as its command, and the mirror reads the module list out of that variable (Task 5). Wall time becomes the slowest single module, not their sum. |
| PD6 | **The spec's module list is one short of the spec's own rule** | §3.4/4 states the rule: *the test of a factory script and the script itself travel together, or the class is a way to skip a test*. `tools/**` is on the list, and `tests/test_conventions.py` is the only test of `tools/check_conventions.sh` and `tools/forbidden-conventions.txt` — it runs the script as a subprocess over fixture repositories (`tests/test_conventions.py:170`, `:217`, `:229`). The `lint` job *runs* the script, so a script that crashes is caught — but a script edited into a no-op passes lint green and goes untested, which is the hole the rule exists to close. ### Task 1: the classifier — `asf/ci.py`, two class names, three pure functions and the workflow's glob block
stories: S-18150
writes: asf/ci.py, tests/test_ci_class.py
after: none

§2.1, plus the reader PD4 gives a home to. Pure functions over plain lists: no filesystem, no
configuration, no product convention, and — PD8 — not one path literal, in code or in a docstring.

**Files**

- `asf/ci.py` — **new**: the module docstring (what a class is and what it is not: what a push
  *owes CI*, never what may *land* — §1.2's boundary against harvest's gate, named so the next
  reader does not fold the two), `FACTORY_ONLY`, `FULL`, `CLASSES`, `matches`, `classify`,
  `unmatched`, `globs_from_workflow`.
- `tests/test_ci_class.py` — **new**: §3.1's cases and `globs_from_workflow`'s.

**Steps**

1. `FACTORY_ONLY = 'FACTORY_ONLY'`, `FULL = 'FULL'`, `CLASSES = (FACTORY_ONLY, FULL)` — the two
   names in the order §2.1 fences them, and `CLASSES` as the tuple the mirror and any future
   caller read rather than writing the strings again.
2. `matches(path, globs)` — D6's rule, `fnmatch.fnmatchcase` over the repo-relative path, the
   base name when the glob carries no `/`. This is `asf/approvals.py:158`'s `_match_glob` by
   another name and deliberately so: one matching rule per repository. Do not import it from
   `approvals` — that module is the approval matrix's, and a classifier that imports it inherits
   its configuration reach; the four lines are copied with a comment naming the original as the
   rule's home.
3. `classify(paths, factory_only_globs)` — `FACTORY_ONLY` when `paths` is non-empty **and** every
   path matches; `FULL` for everything else, including an empty `paths` and an empty glob list
   (D5). No normalisation of `paths` beyond stripping a leading `./`: the caller passes
   repo-relative, forward-slash paths, which is what `git diff --name-only` prints.
4. `unmatched(paths, factory_only_globs)` — the paths that forced `FULL`, first-seen order, no
   de-duplication beyond first-seen.
5. `globs_from_workflow(text)` (PD4) — the lines of the `FACTORY_ONLY_PATHS:` block scalar in a
   workflow's text, stripped, comments and blanks dropped, in file order. It reads the block by
   its key and the indentation of the line after it, and returns `[]` when the key is absent —
   a workflow without the block is a workflow with no class, not an error. The key name is a
   module constant so the workflow, the doctor row and the mirror all spell it once.
6. `tests/test_ci_class.py` per §3.1: every path matched → `FACTORY_ONLY`; one unmatched among
   ten matched → `FULL`; empty paths → `FULL`; empty globs → `FULL`; `unmatched()` returning
   exactly the forcing paths in first-seen order; the glob rule over a bare name, a directory
   glob, a nested one and a path matching none; `CLASSES` holding exactly the two names.
7. The same module covers `globs_from_workflow`: a block read back as a list, a workflow with no
   block → `[]`, a comment line inside the block dropped, and the block read out of the real
   `.github/workflows/tests.yml` — which at this Task returns `[]`, and after Task 4 returns the
   list. Write that last assertion as "whatever the file holds, every line of it is a non-empty
   string with no leading dash", so it is true before and after Task 4 and never needs editing.

**Gate**

```sh

python3 tools/run_tests.py 2>&1 | tail -3
bash tools/check_conventions.sh && bash tools/check_generic.sh && python3 -m asf.cli check
```

**Acceptance**


### Task 3: the command — `asf ci class`, a diff range or a path list, the class on stdout, exit 0 either way
stories: S-18152
writes: asf/ci.py, asf/cli.py, tests/test_cli.py
after: Task 1, Task 2

§2.3. The command CI calls, and the only place in this card that touches git. It writes `asf/ci.py`
again (PD7), so it queues behind Task 1 — which it waits for anyway.

**Files**

- `asf/ci.py` — under a `# ---- the command ----` rule: `changed_paths(base, head, cwd)`,
  `cmd_class(args)`, `register(sub)`.
- `asf/cli.py` — `from asf import ci` then `ci.register(sub)` beside `plugin_build.register(sub)`
  (`:180-181`); no arm in `_main`, because `set_defaults(run=…)` is already dispatched (`:384`).
- `tests/test_cli.py` — `CiClassTests`, over a temporary git repository.

**Steps**

1. `register(sub)`: `sub.add_parser('ci', help=…)` with a nested `class` action, the
   `plugin_build.register` shape (`asf/plugin_build.py:163-168`) — a group with room for the next
   question CI asks the factory, per §2.3. Flags: `--product`, `--base`, `--head`,
   `--paths-from`, `--globs-from`, `--json`. `set_defaults(run=cmd_class)`.
2. `changed_paths`: `git diff --name-only <base>..<head>`, or `<base>...<head>` when `--base`
   ends in `...` (D10 — the workflow passes the range it wants, the command does not guess the
   event). A base of forty zeros, an empty base, or a ref that does not resolve: no paths, a
   reason on stderr, and therefore `FULL` (D5) — never a traceback and never exit non-zero.
3. Paths: `--paths-from` wins (a file, or `-` for stdin, one path per line, blanks dropped) and
   git is not invoked at all in that case. Otherwise `changed_paths`.
4. Globs: `--globs-from` wins (a file, or `-`), which is how the runner passes the workflow's copy
   with no operator home. Otherwise the resolved product's `Product.factory_only_paths` (Task 2).
5. Output: the class alone on stdout, one line; the reason always on stderr, §2.3's shape —
   how many paths changed, how many matched, and the paths, with `unmatched` named when the class
   is `FULL`. `--json` puts §2.3's object on stdout instead and nothing else.
6. Exit `0` for either class (D12). Exit `2` only for a bad invocation or an unreadable
   repository, which is the `ConfigError` path `asf/cli.py:257-262` already owns — the command
   raises `env.ConfigError`, it does not print its own operator line.
7. `CiClassTests` per §3.3, over a temporary git repository built with the suite's own fixture
   helpers: a two-point range of documents only → `FACTORY_ONLY`, exit 0; the same range with one
   `asf/` file → `FULL`, exit 0; `--paths-from -` reading stdin with no git call; `--globs-from`
   beating the product's configuration; forty zeros → `FULL` with the reason on stderr; an
   unresolvable base → `FULL`, no traceback; `--json` carrying `class`, `paths`, `unmatched`,
   `globs`, `base` and `head`.
