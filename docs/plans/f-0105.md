# Plan F-0105 — five Tasks: the switch first, the timings second, then the verdict and its human half

Epic: E-0002 — ASF 0.2 — self-improvement. Spec: `docs/specs/f-0105.md` (approved). Branch:
`plan/F-0105`.

**Five Tasks, one per Story, a chain with one fork.** The spec's `## Out` is what makes the
sequence safe: *"`gate_where` defaults to `local`; a product that does not set it behaves exactly
as it does today, down to the transcript. Every Story below is inert on the trunk until an operator
turns it on, which is what makes them safe to land in sequence."* That sentence is load-bearing —
it is why a half-built CI gate on the trunk is not a defect, and it is checked in every Task's
Gate by the suites of the products that have not switched.

1. **Task 1 — the switch, the ref, the wait.** `conventions.gate_where`, `MAP_CONVENTIONS`'
   `ci_gate`, the workflow's `gate/**` push trigger, `asf/ci_gate.py` with its `DEFAULTS`,
   `settings`, `enabled`, state file and `cut`, and the two `asf/harvest/lane.py` edits that make
   `H.product_gate` unreachable under the switch. `after: none`.
2. **Task 2 — the timings, from either gate.** `tools/run_tests.py`'s one `slowest modules:` line,
   `ci_gate.module_seconds`, `product_gate`'s additive `on_modules=`, `record_gate`'s `modules`
   key. `after: Task 1` (the parser's module is Task 1's). Second on purpose — PD1.
3. **Task 3 — the rollup names them.** `metrics.gate_modules`, `render_daily(slow_modules=)`,
   `cmd_rollup`'s one read. `after: Task 2`. Writes nothing Task 4 writes: the two run together.
4. **Task 4 — green lands, red holds.** `ci_gate.judge`'s ladder, `land`, the red path's one job
   log, the split. `after: Task 2` — it writes the ci gate's own `record_gate(… modules=…)` line,
   whose key Task 2 shipped (PD1).
5. **Task 5 — a gate that cannot run says so, and leaves no refs.** Both `NEEDS OPERATOR` causes,
   the state file's `needs_operator` cause, `doctor.check_ci_gate`, and the per-pass sweep.
   `after: Task 4`.

Wave order: **1**, then **2**, then **3 and 4 together**, then **5**.

Read **PD1** before questioning the order — the timings Task is second for two reasons, one of
them a dependency that would otherwise be circular. **PD4 before touching `asf/conventions.py`** —
the enum check the spec asks for is two edits, not one. **PD5 before moving `'gate/'` anywhere near
`asf/conventions.py`** — it is measured now, not argued. **PD8 before writing §3.2** — the spec's
green path is silent about the read its own §6 depends on. **PD9 before writing `module_seconds`** —
a CI log carries the line **twice**. **PD10 before landing a gated sha** — the trunk push is a CI
start like any other.

### Task 1: the landing gate can be moved to the product's CI, and then starts no suite on this host
stories: S-37750
writes: asf/conventions.py, asf/ci_gate.py, asf/harvest/lane.py, .github/workflows/tests.yml, docs/products.example.yaml, docs/guide/product-config.md, tests/test_ci_gate.py
after: none

The spec's `## The design` §1, §2, §3's `DEFAULTS`/`settings`/`enabled`/state file/`cut`, and §5's
two edits. After this lands, a product that writes `harvest: {gate_where: ci}` gets a landing pass
that builds the combined head, pushes it once as `gate/<stamp>-<sha9>`, leaves every member
`WAITING_CI`, and **starts no test process on this host** — a fact about control flow, because
`gate_one_set` returns before `confirmed_group`, `red_on_trunk`, `push_set` and every path to
`H.product_gate` are reached. A product that writes nothing behaves exactly as it does today.

Three things are load-bearing. `gate_where` must be **orthogonal** to `harvest.gate`: the taken key
keeps its two words and `per-branch` + `ci` has to parse as a legitimate pair (D1) — the switch
reads at `gate_one_set`'s top, which is downstream of `gate_set`'s `harvest_gate` branch at `:2741`,
so both are already true if the edit goes where §5 puts it. The **slug** is the one thing a
fast-forward lane does not have: `lane.slug` is None off `self.mode == 'pr'` (P5), so every forge
read here starts `slug = lane.slug or lane_mod.repo_slug(lane.product)`. And the gate's cross-tick
memory is the **file**, never the lane record (D13): `wait()` keeps three named fields and drops
everything else (P7, measured), so a ref remembered on a `WAITING_CI` record is a ref forgotten on
the next pass.

Read **PD4** before the conventions edit, **PD5** before putting a ref prefix anywhere near
`asf/conventions.py`, **PD6** before adding an import to `asf/harvest/lane.py`, and **PD7** before
touching `held_by_host`.
