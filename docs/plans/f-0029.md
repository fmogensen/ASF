# Plan F-0029 — Roles: one file per role, five sections, model and access from config

Epic: E-0001 — ASF 0.1 — a working factory. Spec: `docs/specs/f-0029.md` (approved). Branch: `plan/F-0029`.

Six Tasks, cut along the spec's own §4 file table by the thing that changes: the roles package and
its ten files (Task 1), the brief that carries the block (Task 2), the config that resolves the
label, the effort and the access (Task 3), the launch line that records what ran (Task 4), the
result that carries it through (Task 5), and the two views that read the roster (Task 6).

The cut is also the dependency order. Task 2 cannot render a block before a loader returns one;
Task 3 resolves a label for a role name Task 1 defines; Task 4 writes a role onto a line whose
value Task 2 and Task 3 produce; Task 5 folds what Task 4 wrote. Only Task 6 is free: it reads
Task 1's loader and Task 3's resolver and writes nothing either of them writes, so it runs beside
Task 4.

Three Tasks write `asf/briefs/build.py` or `asf/workers/spawn.py` and so queue on each other.
That is the honest order anyway — see PD4 and PD9 for why each pair cannot be interleaved.

Wave order: **1 → 2 → 3 → 4 ‖ 6 → 5**.

§3's T10 — the repo stays generic and the suite stays green — binds every Task, so every Gate below
runs `bash tools/check_generic.sh` and `python3 tools/run_tests.py` beside its own fence.

| PD2 | Task card ids | Not minted here. `asf.record.plan_tasks.mint_plan_tasks` turns each `### Task N:` heading of the landed plan into a card with an id from `asf.record.ids.mint_id` (`asf/record/plan_tasks.py:48`), so this plan's headings are the parser's ordinals `1…6`. This session's `BACKLOG_ID_RANGE` `T:18600-18649` is therefore unused; no Task id is invented. |
| PD3 | **Which Story is which, when the record holds none** | The spec's `## Stories` are nine bare `- S:` bullets with no ids, and F-0029 has no Story child in the record — the session brief says so (`Stories: (none yet)`). Nothing in the tree mints Stories from a spec's `## Stories` section. The nine are therefore reserved here, positionally, from this session's `BACKLOG_ID_RANGE` (`S:18600-18649`), in the spec's order — S-18600 the file shape and the nine refusals, S-18601 no model/backend/effort/forbidden name, S-18602 the ten files and the bindings, S-18603 the brief block, S-18604 the label from config, S-18605 the effort and the access, S-18606 the launch line, S-18607 the result, S-18608 the views. A `stories:` line with no id cannot be checked for coverage, and an id outside this session's range would be a guess. |
| PD3b | **Those ids are five digits, and the record holds four** | `asf check` holds every id to `^[A-Z]-\d{4}$` (`asf/record/core.py:40`) and `plan_tasks.stories_of` only recognises `\bS-\d{4}\b` (`asf/record/plan_tasks.py:22, 29-34`). `S-18600` matches neither, so the Task cards this plan mints will carry **no** `stories:` field until Story cards exist under ids the record can hold — `stories_of` drops what it does not recognise rather than failing, so nothing breaks; the field is simply absent. F-0023's plan hit the same wall and recorded it the same way (`docs/plans/f-0023.md:20`). This plan does not widen it: an id is never invented in a document, and a plan that pretended the range were usable would put an unparseable id into the record. The `NEEDS OPERATOR` line in this session's report is the ask. |
| PD4 | **`build()` has no operator config, and §2.4 needs one** | `model_for(product, kind)` reads the *product* yaml only (`asf/briefs/build.py:164-167`); `roles:` lives in `~/.ASF/config.yaml`, which `asf.briefs.build` has never opened — its contract is that it "never guesses a fact nobody gave it" (`build.py:5-8`). Decision: `model_for(product, kind, cfg=None)` and `build(…, cfg=None)` treat `None` as `{}`, which is today's behaviour exactly, and the two callers that *have* an operator config pass it — `step_wave.run` loads it once per tick (`asf/tick/step_wave.py:171`, `_build` at `:141`) and `build.cmd_brief` loads it too, so `asf brief` prints the brief that would launch. A missing or unreadable config is `{}` and never an error, the shape `spawn.load_cfg` already uses (`asf/workers/spawn.py:317-321`). Task 2 adds the parameter; Task 3 is the first to read a key from it. |
| PD5 | **`role_max_lines` is a conventions key, not a config key** | §2.5 caps the block with `conventions.role_max_lines`, and §4's file table lists only `docs/config.example.yaml`. A `conventions:` key is a field of `asf.conventions.Conventions` and is documented in `docs/products.example.yaml` (`:25-52`, where `preamble_max_lines` sits), not in the operator config. Task 2 writes both — the field beside `preamble_max_lines` with `DEFAULT_ROLE_MAX_LINES = 60`, and the commented line in the products example. `docs/config.example.yaml` still gets §2.4's `roles:` block and the `worker_pool.effort_args` line; that is Task 3's. |
| PD6 | **§2.1's `INCIDENT` regex, read literally, matches nothing** | The spec prints `INCIDENT = r'\b(?:[BDEFRST]-\d{4}\|b\d{1,3})\b'`. In a regex `\|` is a *literal* pipe character, so that pattern would require the text `B-0051|b60` and every doctrine bullet in the ten files would fail refusal 6. The `\|` is the markdown table's escape of the alternation pipe. Task 1 writes `INCIDENT = r'\b(?:[BDEFRST]-\d{4}|b\d{1,3})\b'` and asserts it matches `B-0051` alone and `b60` alone. This is the spec's rule, spelled as it was meant. |
| PD7 | **A doctrine bullet's id must be checkable inside the worktree** | The preconditions require that a cited incident exists, and say the validator checks the *shape* only — there is no oracle in this repository for "this id is real", and the record lives outside it (`~/.ASF/products/`). Decision: every id the ten files cite is one this repository's own tracked text already cites, so the check is `grep -rn '<id>' docs/ asf/` and needs no record. The `B-` ids in `docs/` and `asf/` and the `b<n>` prior-art findings in `docs/research/prior-art-prototype.md` are the pool. Task 1's step 4 is that grep, run over the ten files, and a bullet whose id has no in-repo citation is rewritten before it is committed. |
| PD8 | **The word ban is checked over the frontmatter too** | §2.1's refusal 8 says "anywhere in the file"; that is what makes T2's fixture — `model: heavy` in the frontmatter — trip refusal 2 *and* refusal 8 as the test requires. So `validate` runs the ban over the raw file text, not over `Role.text`. The consequence the ten files are written to: no role file may say "the tools you are given", "the effort this costs" or "prefer the heavier model", because `tools`, `effort` and `model` are banned words (D4). A role names what it may read and what it may write; the phase supplies the rest. |
| PD9 | **The rule digest's standing half is recomputed, not carried on the Brief** | §2.6 wants `rules.standing` to be "the sha of the standing-rules text as rendered into this brief". Parsing it back out of the written brief is a text search over generated prose. Threading it on `Brief` would put `asf/briefs/build.py` into a fourth Task's footprint. Decision: `spawn` calls the same pure function the preamble calls, with the same argument — `preamble.rules_block(product, getattr(product, 'main', 'main'))` (`asf/briefs/preamble.py:70-74`, called at `:445` with `main` from `:427`) — so the two texts are equal by construction, and T7's assertion over the *written brief* is what proves it. No Brief field, no new parameter, and `asf/briefs/` stays out of Task 4. |
| PD10 | **`ROLES_DIR` must be overridable, and §2.2 fences it as a constant** | §3/T9 requires `asf doctor` to go red "when `ASF_ROLES_DIR` points at the broken one", which a module constant cannot do. D1 requires `asf roles` to work "before `asf init`": it reads the package directory and `~/.ASF/config.yaml` and nothing else. Task 6 dispatches it on its own branch, above the record-view block, and it never calls `resolve_record`. Its parser takes `--check` and `--overlap` and no `--product`. |
| PD12 | **The events path in §4 is not the path the code writes** | §4 puts the `sessions` events in `<record>/metrics/events/<day>.jsonl`. `metrics.stream_path` writes `<record>/metrics/<stream>/<day>.jsonl` (`asf/metrics/metrics.py:251-252`) and the ended table reads `metrics/sessions/<day>.jsonl` (`asf/views/sessions.py:24-39`); `metrics/events/` is the tick's own event log (`asf/tick/tick.py:159-168`), a different stream with a different schema. Re-pointing that key to the label is a change to what every existing reader of the registry and of the `sessions` stream sees, and no acceptance line asks for it. ### Task 1: the roles package — the loader, the nine refusals, the bindings, the ten files
stories: S-18600, S-18601, S-18602
writes: asf/roles/__init__.py, asf/roles/roles.py, asf/roles/*.md, pyproject.toml, tests/test_roles.py
after: none

§2.1, §2.2, §2.3 and §2.7. A role becomes a file with a two-key frontmatter and five sections in
order; a loader reads it with `asf.record.frontmatter` and a validator returns one problem string
per breach, nine of them; one table binds every brief kind to a role and one names the reason of
every role no kind binds. Ten files ship. Nothing outside `asf/roles/` reads any of it yet — the
package is complete and inert until Task 2 renders it.

**Files**

- `asf/roles/__init__.py` — **new**: the package, and the module docstring saying what a role is
  (identity, doctrine with the incident behind each rule, the output contract, the economy, the
  boundary) and what it is not (a model, a backend, an effort, a tool list — those are the
  operator's config and the phase's).
- `asf/roles/roles.py` — **new**: §2.2's `ROLES_DIR`, `roles_dir()` (PD10), `RoleError`, the
  `Role` dataclass, `load`, `load_all`, `validate`, `for_kind`, `block`; the nine refusal
  constants `SECTIONS`, `MAX_LINES = 60`, `DOCTRINE_MIN = 4`, `DOCTRINE_MAX = 8`, `INCIDENT`
  (PD6), `ECONOMY_MAX_LINES = 6`, `FORBIDDEN`; `BINDINGS` and `UNBOUND` exactly as §2.3 fences
  them. `block(role, cap)` is written here and first called by Task 2.
- `asf/roles/writer.md`, `reviewer.md`, `coder.md`, `fixer.md`, `diagnostician.md`,
  `harvester.md`, `interrogator.md`, `prober.md`, `security.md`, `documenter.md` — **new**, ten
  files, the purposes of §2.7's table verbatim in `purpose:`.
- `pyproject.toml:27-28` — `"asf.roles" = ["*.md"]` beside `"asf.briefs" = ["templates/*.md"]`.
- `tests/test_roles.py` — **new**: `ShapeTests`, `ValidateTests`, `NoModelTests`, `GenericTests`,
  `BindingTests`.

**Steps**

1. `asf/roles/roles.py`: `Role` per §2.2 — `name`, `purpose`, `sections` (an ordered dict,
   heading → the section's text in file order), `text` (the body below the frontmatter,
   verbatim), `sha` (`hashlib.sha256(text)` first 12 hex), `lines`. `load(name)` reads
   `roles_dir()/<name>.md`, parses with `asf.record.frontmatter.parse` (`asf/record/frontmatter.py:184`)
   and raises `RoleError` on a missing file. `load_all()` returns `{name: Role}` over every
   `*.md` in `roles_dir()`, sorted. `sha` is over the body only, so the path and the mtime never
   move it and an edit to `purpose:` does (the purpose is identity).
2. `validate(role)` returns a list of problem strings, the nine of §2.1's table in that order,
   each naming itself: frontmatter keys not exactly `{name, purpose}` (two refusals — missing,
   and unknown); a missing section, a section out of order, or a heading that is not one of
   `SECTIONS = ('Identity', 'Doctrine', 'Output', 'Economy', 'Boundaries')`; over `MAX_LINES`;
   doctrine bullets outside `DOCTRINE_MIN..DOCTRINE_MAX`; a doctrine bullet with no `INCIDENT`
   match; `## Economy` over `ECONOMY_MAX_LINES`; a `FORBIDDEN` word case-insensitively anywhere
   in the **raw file text**, frontmatter included (PD8); a `## Output` carrying a line matching
   `^REPORT$` or a fenced block containing `status:`. An empty list is a valid role.
   `FORBIDDEN = ('model', 'backend', 'effort', 'tools', build.HEAVY, build.LIGHT)` with the two
   label constants imported from `asf.briefs.build` inside the function, so the roles package
   does not import the briefs package at module load.
3. `BINDINGS` and `UNBOUND` byte for byte from §2.3. `for_kind(kind)` returns `BINDINGS[kind]` and
   raises `RoleError` on a kind the table does not know. `block(role, cap)` renders
   `## Who you are — <name>` and the body, truncating by whole sections, last section first, and
   appending `… (role <name> truncated at <n> lines)` when it cut — the `fit` discipline of
   `asf/briefs/preamble.py:337-349`, written here over sections rather than over `Section`
   objects, and first called by Task 2.
4. The ten files, each written from the template it inherits its rules from
   (`asf/briefs/templates/<kind>.md`), `docs/CONSTITUTION.md`, and the incidents this repository
   already cites. Every doctrine bullet's id is checked with `grep -rn '<id>' docs/ asf/` before
   the file is committed (PD7); a bullet whose id has no in-repo citation is rewritten, never
   invented. `reviewer.md` carries `review.md:21-24`'s rule about rounds and B-0051's
   `status`/`approved` distinction; `fixer.md` carries `fixer.md:4-6`'s boundary. Each file is at
   or under 60 lines, its Economy at or under 6, its doctrine 4–8 bullets, and none carries a
   `FORBIDDEN` word or a name from `tools/forbidden-names.txt`.
5. `pyproject.toml`: the package-data entry, so an installed copy ships the ten files and
   `asf roles` works from an install and not only from a checkout.
6. `ShapeTests` per §3/T1's first half: over `load_all()`, every file's frontmatter is exactly
   `name` + `purpose`, `name` matches the stem, `SECTIONS` are present and in order, `lines <= 60`,
   doctrine is 4–8 bullets and every bullet matches `INCIDENT`, Economy is at or under 6 lines,
   and `validate` returns `[]`.
7. `ValidateTests`: a temporary roles dir (`$ASF_ROLES_DIR`, PD10) holding one valid file, and
   nine copies each carrying exactly one mutation — each produces exactly one problem, and the
   problem string names itself. Plus PD6's two assertions: `INCIDENT` matches `B-0051` and `b60`
   each on its own.
8. `NoModelTests` and `GenericTests` per §3/T2: every shipped file searched case-insensitively
   for each word of `FORBIDDEN` and for `build.HEAVY`/`build.LIGHT`, none hits; a fixture file
   with `model: heavy` in its frontmatter yields both refusal 2 and refusal 8; no file carries a
   `tools/forbidden-names.txt` pattern (the regex helper of `tests/test_briefs.py:117-125`).
9. `BindingTests` per §3/T3: `set(load_all()) ` is exactly §2.7's ten names;
   `set(BINDINGS) == set(asf.briefs.build.KINDS)`; every `BINDINGS` value has a file; every file
   is in `BINDINGS.values()` or in `UNBOUND` with a non-empty reason; `for_kind('preflight')`
   raises `RoleError`.

### Task 3: the label, the effort and the access resolve from operator config
stories: S-18604, S-18605
writes: asf/briefs/build.py, asf/workers/spawn.py, asf/workers/runtime.py, docs/config.example.yaml, tests/test_briefs.py, tests/test_workers.py
