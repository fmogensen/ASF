# Plan F-0279 — the brief stops asking for the beat, the refusal stops being a question, and the parks come back

Epic: E-0001 — ASF 0.1 — a working factory. Spec: `docs/specs/f-0279.md` (approved). Branch:
`plan/F-0279`.

Three Tasks, one per Story and one per section of the spec's `## The design`. Task 1 is the
**brief**: the local lane stops being handed a precondition its sandbox may refuse, and the one
loop block that remains — the Actions lane's — says in its own block that a refusal is
survivable. Task 2 is the **reading**: `report.needs_input` stops counting a heartbeat-start
refusal as a question, a new `report.declared_question` keeps the raw reading the relaunch cap's
mark depends on, and health's park is never reached. Task 3 is the **release**: the parks already
written come back on the next tick, with their own reason and no `asf unpark`.

Wave order: **(1, 2) → 3**.

The cut is the spec's own §1–§3, one section per Task, and the seam is the one the spec draws.
Task 1 and Task 2 share no file and no dependency: the brief's text and the report's reading are
two different ends of the same bug, and either is useful without the other. Task 3 waits on
Task 2 for two reasons that are both real rather than bookkeeping — `release_answered` only
reaches its release once `needs_input` is already `None` for such a run, and the `why` line it
gains calls `report.heartbeat_refused`, which does not exist in `report` until Task 2 moves it
there (**PD11**).

What the plan does **not** do is split Task 2. The spec's §2 touches three modules, and measuring
it here showed the three cannot land apart: narrowing `report.needs_input` on its own turns an
existing green test red (**PD3**). That measurement, and one more about *how* the narrowing must
be written (**PD4**), are the two things this plan adds to the spec — neither widens it.

## What this plan leaves unbuilt, and why

- **The beat's machinery, and every heartbeat config key.** `SCRIPT`, `Beats`, `observe`,
  `last_beat`, `land_snapshot`, `delete_ref`, `clear_ended`, `resume`, `launch`, the
  continuation's CONTINUE block, and `heartbeat_min` / `heartbeat_missed` /
  `heartbeat_grace_min` / `heartbeat_resumes` are all untouched, as the spec's Out requires. A
  beat ref written by a run launched before this lands is still read, landed and deleted exactly
  as today, and `interval_min * missed` is still the quiet limit every lane is judged by.
- **Dropping the loop from the Actions lane** (C1). An Actions run has no event-level liveness
  (P3), so the beat ref is its only proof of movement short of a branch push, and its runner
  allows a background process. Task 1 makes the ask survivable there; it does not remove it.
- **The stalled-path order** (C4). `observe` still runs before the run's own signal, so branch
  movement is still recorded in `heartbeat.json`.
- **`asf/tick/step_health.py`, `asf/workers/stall.py` and `asf/workers/lifecycle.py`.** All three
  consume the narrowed reading through `report` with no edit of their own (P11, **PD9**,
  **PD10**); only their tests are touched, and only where a Story line needs proving.
- **`asf/briefs/` and the 19 goldens** (**PD6**), including the TAIL sentence that becomes vacuous
  for a local brief.
- **`docs/design` and `docs/KNOWN-ISSUES.md`.** The design note follows the code, not this plan.
- **The five `tests.test_workers.TestSpawn` failures a cloud sandbox shows** (**PD5**). They are in
  the fence S-74455 names, they are green on the factory host — the operator verified
  `Ran 34 tests, OK` at `origin/main`, and this session re-measured the whole fence there at
  `0f5f36037` as `Ran 682 tests … OK` — and nothing F-0279 touches is near a spawn's rebase. So
  there is no trunk red for this plan to carry: Task 2's Gate excuses nothing on the host and

  own breakage. Making those cases pass inside a sandbox is its own card, not this one.
