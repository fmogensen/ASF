# Plan F-0230 — the half of the instrument that is still missing: which supersede was waste

Epic: E-0002 — ASF 0.2 — self-improvement. Spec: `docs/specs/f-0230.md` (approved). Branch:
`plan/F-0230`.

**Read PD1 and PD2 before writing a line of any Task.** Between the spec's sha (`44f5667dd`) and
this branch point (`e1723481c`), commit `59eb2dfb8` (#482) landed **the whole claim half of this
card** — a durable cancel ledger, all four factory claim sites, and an inference pass the spec never
knew existed. The spec's §3 is therefore not to be built: building it as written would put a second
ledger named `ci-cancels.jsonl` beside the landed `ci-cancels.json` in the same state directory.
And the landed inference pass writes `superseded` claims that, read as claims, would shadow this
card's entire reason for existing.

What is genuinely missing is the discrimination the card was filed for: **`explain_cancels` calls
every host cancel `superseded` and never asks whether the superseding head carried any work.** That
is the difference between *waste* and *sound*, it is the number the card's Description asks for
("Measure which source dominates"), and nothing in the tree computes it. The three Tasks below build
that — `head_kind`, the nine-cause classifier over it, and the table that prints the shares — on top
of the ledger that already exists rather than beside a rival one.

Three Tasks, run **1 → 2 → 3**, one at a time. They serialise by construction: all three write
`asf/ci_cancels.py` and `tests/test_ci_cancels.py`, which is one module and its one suite (PD9).

The fences of §*The fences, and the suite* bind every Task, so every Gate and Acceptance block below
carries them beside its own.

2. The rule, in `head_kind`, exactly as §2 states it and in this order:
   - `old` and `new` equal, or either falsy → decide before any git runs: equal shas are `'rewrite'`
     (a re-push of the same head carries nothing), a falsy sha is `'unresolved'`.
   - resolve both, copying PD12's shape: `cat-file -e <sha>^{commit}` for each; on failure, if
     `fetch`, **one** `git fetch -q origin <sha>` for that sha and re-check; still failing →
     `'unresolved'`. Fetch by **sha**, never by branch — the sha this wants is the one the branch no
     longer points at (C7).

     patch-equivalent in `new` means the work changed, which is never a content-free re-push
     (the spec's `test_a_dropped_commit_is_a_newhead`).

     `'rewrite'` (a reword, a sign-off).

     is None → `'unresolved'`. **Never raises** — the docstring says so and the fence asserts it.
3. `'unresolved'` is a returned string on its own footing (C6), never folded into `'newhead'` and
   never assumed `'rewrite'`. Say in the docstring what C6 says: this is the one place the measure can
   lie, so it is the one place it is loud, and the table prints its share.
4. `cause(run, claims, runs, timeouts, prs, repo, trunk, fetch)` — one member of `CAUSES` for one
   cancelled run row, first match wins, in C4's order:
   1. **the claim.** `claims.get(str(run id))`; if its cause is in `HONOURED`, return
      `HONOURED[cause]`. If it is in `REREAD`, fall through — the run is re-classified from here
      (PD2). If it is in neither, return `'unclaimed'` and count it a stray (PD3).
   2. **`timeout`.** The run holds a job whose `started_at → completed_at` reaches its declared limit

      the waste number with the host's own failures.
   3. **`merged`, inferred.** The run's PR has a `merged_at` at or before the run's `updated_at`.
   4. **`dedupe`, inferred.** The run's `event` is `push`, its branch is not the trunk, and a

      stronger than P6's flag. Its head sha and this run's go to `head_kind`, which returns
