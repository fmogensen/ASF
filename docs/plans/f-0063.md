# Plan F-0063 — the branch is the handover, and one filler delivers it

Epic: E-0001 — ASF 0.1 — a working factory. Spec: `docs/specs/f-0063.md` (approved).
Branch: `plan/F-0063`.

Seven Tasks. **Task 1 is the correction's, not the spec's**: this plan's own pull request went red
on `tests (3.13)` while `tests (3.12)` was green on the identical tree, and nothing lands until the
gate is green. The red is a race in the end-to-end harness — git's background maintenance pruning
loose objects out of the shared template while `Factory.fork` copies it — which no document diff can
cause and no other Task of this Feature can survive either, because every Gate below runs the whole
suite (PD18). It is test-harness code only, and it goes first.

The six after it are cut the way the spec's own §2 is cut — by the module that gains the surface, and
inside `asf/briefs/facts.py` by what the new read touches. Task 2 is the wiring: `step_wave`'s second
filler goes and both launch sites call the one the contract test covers (§2.1, §3/T1). Task 3 is
the git half of the facts — the head origin holds and the commits above the trunk (§2.2, §3/T2).
Task 4 is the log-and-ledger half — the last progress line, the predecessor whose log it is read
from, and the report scoped to the branch with the review verdict behind it (§2.3, §2.4, §3/T3,
§3/T4). Task 5 is the block: the three new keys, the section, and the trim rule (§2.5, §3/T5).
Task 6 asserts what already holds — a relaunch's first commit sits on the old head (§3/T6). Task 7
is the measure (§2.6, §3/T7).

Tasks 1, 2, 3, 6 and 7 write five disjoint sets and start at once. Task 4 writes Task 3's two files,
so it queues behind it; Task 5 writes Task 4's `asf/briefs/facts.py` and `tests/test_brief_facts.py`
and needs `commits_on`, `last_progress` and `predecessor` landed to fill its three keys, so it
queues behind Task 4. Task 2 is independent of all of them: its test holds the wave's dict equal to
`preamble.REPO_FACT_KEYS`, which is true at six keys and still true at nine. Task 1 writes nothing
under `asf/` and nothing any other Task writes, so it gates none of them (PD19) — it is first in the
wave because the sooner it lands the fewer of their pull requests bounce on a green-on-retry suite.

Wave order: **(1 ‖ 2 ‖ 3 ‖ 6 ‖ 7) → 4 → 5**.

§3's rule that the whole suite stays green binds every Task, so every Gate below runs
`python3 tools/run_tests.py` and the two checks beside its own fence.

| PD4 | **§2.2's `head_of` snippet, taken as written, inverts the parenthetical of every pushed branch** | The tail of `head_of` that §2.2 elides with `...` decides the parenthetical by comparing the rev to a ref name: `where = f'({rev})' if rev == f'origin/{branch}' else f'({rev} — {branch} is not on origin yet)'` (`asf/briefs/facts.py:86-88`). Once `rev` is a bare sha that comparison is false for a pushed branch, so a branch that *is* on origin would print `(<sha> — <branch> is not on origin yet)` — the exact opposite of the truth, in the one line this Feature exists to make trustworthy. Task 3 therefore carries the fact that the rev is the branch's own head in a local (`own = bool(sha) and bool(rev)`) and keys the parenthetical off that, not off the string: `(origin/<branch>)` when `own`, `(origin/<main> — <branch> is not on origin yet)` when the trunk stood in. | PD5 | **`repo_facts` needs no new flag to know the rev fell back to the trunk** | §2.2 says `commits` is filled "whenever `rev` is the branch's own head" and left empty "when `rev` fell back to the trunk" — but PD4 makes `rev` a sha, so the caller can no longer tell the two apart by inspection, and `head_of` keeps its three-tuple. | PD7 | **`last_report`'s `review=` argument is a `(round, path, text)` triple the caller computes** | §2.4 gives `last_report(product, item_id, branch='', review=None)` and then says the review file is found through `conventions.review_path(slug, n)` and read with `git cat-file -p <rev>:<path>` — but `last_report` today runs no git at all (it reads the ledger and the log), and making it the first git caller in the function would hand it a repo, a rev and a slug it has no other use for. ### Task 1: the end-to-end harness — no background git writer, and a fork that never hands back a half copy
stories: none
writes: tests/gitfixture.py, tests/e2e/factory.py, tests/test_gitfixture.py, tests/test_e2e_lane.py
after: none

PD18: the gate was red on `tests (3.13)` and green on `tests (3.12)` for the identical tree, in
`tests.test_e2e_lane`'s `setUp`, because `Factory.fork` copies a shared template that git's detached
`gc`/`maintenance` is pruning loose objects out of at that moment. This Task turns that writer off
where the fixture repos are made, and makes the copy fail loudly rather than partially if one ever
appears again. Test-harness only: no `asf/**` file changes, no product behaviour moves, and nothing
here is a Story of this Feature (PD19).

**Files**

- `tests/gitfixture.py` — `_no_housekeeping`, called from `publish` (the tree *and* the bare origin)
  and from `Template._ensure`
- `tests/e2e/factory.py` — `Factory.fork`: the `*.lock`/`gc.pid` ignore and the one retry
- `tests/test_gitfixture.py` — `HousekeepingOffTests`
- `tests/test_e2e_lane.py` — `ForkUnderPruneTests`

**Steps**

1. Add `_no_housekeeping(repo)` to `tests/gitfixture.py`: three `git config` calls — `gc.auto 0`,
   `gc.autoDetach false`, `maintenance.auto false` — with one comment naming the reason (a detached
   `gc` or `git maintenance run --auto`, started by a fixture's own commit or push, repacks and
   prunes while a copy of that fixture walks its `objects/`; the suite already met its lock file at
   `tests/gitfixture.py:44-49`).
2. Call it in `publish` (`tests/gitfixture.py:96-114`) on the bare origin right after its
   `git init --bare` — `receive-pack` runs the same `--auto` hook on every push it receives — and on
   the tree right after its `git init`, i.e. **before** the first `git add`/`commit`, so no commit in
   a fixture repo can ever start one. `publish` is the only `git init` the end-to-end harness makes,
   so this one call covers `repo`, `record` and both origins; a worktree added later by a tick shares
   the repo's config file and inherits it.
3. Call it in `Template._ensure` beside `_disable_hooks(root)` for every repo under the template
   root: `_working_tree_roots(root)` gives the working trees, and the bare ones are the directories
   whose `git rev-parse --is-bare-repository` says true (or, equivalently, the `*.git` dirs the
   builders make). The non-e2e fixtures fork templates too, and this is the same race.
4. `Factory.fork` (`tests/e2e/factory.py:200-223`) keeps its contract — a complete copy with every
   path rewritten — and changes how it copies. Factor the per-entry walk into a local helper and
   call it under one retry:
   - directories go through
     `shutil.copytree(src, dst, symlinks=True, ignore=shutil.ignore_patterns('*.lock', 'gc.pid'))`,
     the same ignore and the same reason as `gitfixture.fresh`;
   - on `shutil.Error` or `OSError` whose every entry is `ENOENT`, delete what was copied under
     `dest` and copy the whole tree once more; a second failure is re-raised unchanged.
   - **A missing source is never skipped.** A loose object pruned into a pack the walk has already
     passed leaves a repo that resolves nothing, so tolerating the gap would trade a loud flake for a
     silent corruption. With step 2 in place there is no writer left to race; the retry is the second
     line of defence, for a writer the harness does not own.
   - one comment, naming what it defends against and that the first line of defence is the config.
5. `HousekeepingOffTests` in `tests/test_gitfixture.py`: a tree through `publish` reads
   `gc.auto == '0'`, `gc.autoDetach == 'false'` and `maintenance.auto == 'false'`, and so does its
   bare origin; a `Template().fresh()` copy reads the same on every repo under it. The existing hooks
   cases (`tests/test_gitfixture.py:38-39`) stay green unedited.
6. `ForkUnderPruneTests` in `tests/test_e2e_lane.py`, over a plain `Factory(tmp).setup()` and not the
   `ready` template — the case is the copy, not the scenario:
   - the four repos the factory publishes (`repo`, `record_dir`, `repo_origin`, `record_origin`) all
     read `gc.auto == '0'`;
   - `fork` survives a source that vanishes mid-walk: patch the copy so its first call removes a
     loose-object directory under the source's `record/.git/objects` and then delegates, and assert
     the fork returns a factory whose record repo resolves `HEAD` and whose `snapshot()` reads back —
     i.e. the retry produced a whole copy, not a patched-over one;
   - the retry is bounded: a source that keeps vanishing (the patch removes one on every call) raises
     rather than looping or returning a half copy.
7. No `asf/**` file is touched by this Task. If a case cannot be made to pass without one, stop and
   report it rather than editing product code from here — the writes line is the footprint.

**Gate**
