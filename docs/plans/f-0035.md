# Plan F-0035 — Thin controller: the read loops become a tick step, and a rule flags scriptable chores

Epic: E-0001 — ASF 0.1 — a working factory. Spec: `docs/specs/f-0035.md` (approved). Branch: `plan/F-0035`.

Five Tasks, cut along the spec's own `## The design` headings — but folded where two headings write
one file, because `writes:` is the cut that matters: two Tasks whose globs intersect never run
together. The spec names four new or rewritten *files* of substance (`asf/tick/step_watch.py`,
`asf/chores.py`, `rules/controller-chores.sh`, `asf/hooks.py`) and one measure that needs two of
them at once. That is the five.

Wave order: **1 ‖ 2 → 3 ‖ 4 → 5**. Tasks 1 and 2 share no file and start at once; Tasks 3 and 4 then
run beside each other; Task 5 is last because its `writes:` intersect all three of Tasks 1, 2 and 3
(PD14) as well as needing their code.

Task 1 is the whole tick half (§2.1–§2.5): the step, the manifest, the tables, the watch table, the
harvest assertion. Task 2 is `asf/chores.py` as a leaf module and its command (§2.6 recorder, §2.7
classifier) — no hook wiring, so it has no file in common with anything else in its wave. Then
Task 3 adds the check script and the filing test, Task 4 wires the recorder into `asf/hooks.py` and
the install, and Task 5 adds the measure, which is the one Story that needs both halves and is
therefore last.

Nothing in Task 2 is reachable from a running session until Task 4 lands: `asf hook chores` with no
`BUILTIN['chores']` falls through to `check_script('chores')`, finds nothing and returns 0
(`asf/hooks.py:258-266`). That is a silent no-op, not a red state, and it is what makes Tasks 3–5
safe to land in any order after Task 2.

The spec's §3 preamble binds every Task: each Gate below runs its own fence, then
`python3 tools/run_tests.py`, `bash tools/check_generic.sh` and `bash tools/check_conventions.sh`.
