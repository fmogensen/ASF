# B-0092 — plan: a NEEDS OPERATOR line is a ruling, not a still-open question

Item: B-0092 — Groom digest says '55 for you' for items the adjudicator already ruled; removals
are not surfaced. Epic: E-0002 — ASF 0.2 — self-improvement. Branch: `fix/B-0092`. No spec
exists; the Acceptance below is the record.

## Cause

`render_digest`'s pass-through `NEEDS OPERATOR` answers and its `Spoken for` bucket both read
from the same still-open groom line: `_classify_groom_lines` put every undecided card into
`open_`, and a card a session had already escalated with a `NEEDS OPERATOR:` line in
`answers_done_texts` was never removed from `open_` before `open_` fed both
`spoken_for_lines`/`housekeeping_lines` and the digest's totals. The same card then counted
twice — once under `Spoken for` as if nobody had looked at it yet, and once under the session's
own `NEEDS OPERATOR` line — inflating the digest's `for you`-adjacent counts every time a session
escalated a question instead of answering it.

The title's second clause — "removals are not surfaced" — is already covered by existing,
untouched code: `_rule_and_adjudicator_lines` (`asf/groom/digest.py:76-88`) matches any `field`
in a dated History line, including `removed`, and surfaces it under "Ruled by the adjudicator"
regardless of kind. No second fix was needed for that clause.

## Task 1 — drop a NEEDS-OPERATOR'd id out of the still-open set

writes: `asf/groom/digest.py` `tests/test_groom_policy.py`

- Step 1: add `NEEDS_OPERATOR_ID_RE`, matching a `NEEDS OPERATOR: <id>` line at the start of an
  `answers_done_texts` line and capturing the id.
- Step 2: in `render_digest`, after `_classify_groom_lines` returns `open_`, collect the ids any
  `answers_done_texts` line names with `NEEDS OPERATOR:` and filter `open_` to drop them, so a
  card the session already ruled belongs to the operator is not also queued back onto
  `Spoken for`/`Housekeeping`.
- Step 3: test, in `tests/test_groom_policy.py`:
  - `test_needs_operator_escalation_is_not_also_spoken_for` — a card with one `NEEDS OPERATOR:`
    answer and no other action renders `0 answered by rule · 0 ruled by the adjudicator · 0
    spoken for · 1 for you`, the id is absent from the `## Spoken for` section, and the
    `NEEDS OPERATOR:` line itself still renders.
