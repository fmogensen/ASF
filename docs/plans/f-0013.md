# Plan F-0013 — the feeder and the tick

Epic: E-0001 — ASF 0.1 — a working factory. Spec: `docs/specs/f-0013.md` (approved). Branch: `plan/F-0013`.

Eight Tasks, cut by the module that owns the surface — the cut the spec's own §2 already makes.
Task 1 is the conventions (§2.6, §2.7), Task 2 the one hook-variable list and the three
environments that stop building their own (§2.2), Task 3 the runner itself (§2.1), Task 4 the
tick's eight call sites (§2.3), Task 5 the trunk's name on both sides of ingest's sentence (§2.5),
Task 6 the five stage-limit readers and the feeder's four policy numbers (§2.6, §2.7), Task 7 the
rule pass in process (§2.4), Task 8 S-0001's proof that the daily work starts no process (§3.6).

Tasks 1, 2 and 5 write three disjoint sets and start at once. Task 3 needs Task 1's
`git.read_timeout_s` and Task 2's `hermetic.git_env`; Task 6 needs Task 1's fields and queues
behind Task 5 (both write `asf/feeder/rows.py`); Task 7 needs Task 1's two `file_bugs` fields.
Task 4 needs Task 3's module. Task 8 is last because its proof is only *true* once Tasks 4 and 7
have landed (PD15).

Wave order: **1 ‖ 2 ‖ 5 → 3 ‖ 6 ‖ 7 → 4 → 8**.

§3.8 binds every Task, so every Gate below runs the four gate commands beside its own fence.

### Task 7: the bug filer runs the rule pass in process
stories: S-29353, S-29354
writes: asf/rules/rules.py, asf/tick/file_bugs.py, tests/test_rules.py, tests/test_file_bugs.py
after: Task 1

§2.4 — a live silent failure. `file_bugs.rule_check_results` runs the factory's own rule pass as a
subprocess of itself with `timeout=60`, while inside it each check gets 60 s and eight run at a
time: a record with nine rule cards needs two batches, and `$ASF_RULE_CHECK_TIMEOUT` raises the
inner budget without touching the outer one. When the outer timeout fires, `rule_check_results`
returns `None`, `rule_violation_signatures` returns `{}`, and the tick files no Bug for any
violation, reports no broken check and prints nothing at all. The whole rule → Bug loop the
module's docstring describes is lost without a word. The fix is to stop spawning: `rules` is
already callable in process — `load_rules`, `partition` and `run_all` all take `root`, are
stdlib-only, and `asf.rules.rules` imports nothing from `asf`, so there is no cycle. Also §2.6's
two `file_bugs` numbers, since this is the Task that owns the file.
