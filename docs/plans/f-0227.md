# Plan F-0227 — one grace and one predicate first, then the pool stops believing a corpse

Epic: E-0001 — ASF 0.1 — a working factory. Spec: `docs/specs/f-0227.md` (approved). Branch:
`plan/F-0227`.

**Two Tasks, a strict chain.** The spec's shape is a rule moved down into `lifecycle` and one
reader of it in `pool`, and the split is forced rather than chosen: `Pool.from_config` cannot call
`lifecycle.spent_sessions` before it exists.

1. **`asf/workers/lifecycle.py` and `asf/workers/health.py` — the grace, the predicate, the index,
   and the stop reading them.** `LINGER_GRACE_S` moves down and `health.LINGER_GRACE_S` becomes its
   alias; `linger_spent` and `spent_sessions` are new; `settle_ended`'s own arithmetic becomes a
   call to the predicate. Nothing the factory does changes by one byte when this lands — the same
   runs are stopped, at the same minute, under the same three proofs. It is the half that can be
   argued about without running a factory, and C5's "one number" is only true from the moment the
   alias exists, so the move and the alias are one commit or they are two numbers.
2. **`asf/workers/pool.py` and `asf/workers/wave.py` — a spent run's leftover process is load,
   never a running job.** The synthesis drops `job` and `product`, the wave's `running` set skips a
   live entry with no job. **This is the Task that ends the card's line**: `waits review-t-0196
   T-0196 — already running`, on every tick for 54 minutes, on a job whose run the ledger had
   ended.

Wave order: **1 → 2**, one Task per wave. Their `writes:` are disjoint, so the queue is the
`after:` chain and nothing else.

**Read PD1, PD2 and PD8 before writing a line.** PD1 is the one place the spec's acceptance
describes a mechanism that does not happen — the relaunch case's `spent_sessions` is **empty**,
measured, and a coder who asserts the spec's prose there will chase a bug that is not one. PD2 is
the one line of the design worth placing differently, and why that is not a widening. PD8 is an
unlanded card that writes the same four lines of `health.py` and the only correct way to resolve
that conflict.

| PD1 | **The relaunch acceptance case does not work the way the spec describes: `spent_sessions` is empty there, because `latest()` folds one run per job** | Measured at this head. `spent_sessions` walks `latest(path).values()` (the spec's own design, §1), and `latest` is *"``{job: its latest run}`` — what every reader of the registry means by 'the session'"* (`asf/workers/lifecycle.py:371-373`). So when a job is relaunched, the registry holds two runs under one key and **only the newer is in the index**. Built here — run 1 ended (session `…@A`, pid 67546), run 2 live (session `…@B`) — `runs()` shows both, `latest()` shows `…@B` alone, and `spent_sessions` returns **`set()`**: the old run's id is not in it. The spec's bullet *"the old run ended and spent … keeps the **new** run's seat and its job"* therefore states an outcome that is right for a reason it does not give. What actually happens, measured end to end: the old process falls through as an extra, is **not** in `spent`, keeps `job: 'review-t-0196'`, the new run's registry entry carries the same job, `running == {('sample', 'review-t-0196')}`, `load == 2`, and the wave answers `[('review-t-0196', 'already running')]` — a third launch refused, which is exactly what the acceptance demands. **Write that case asserting the outcome** (`job` kept, `running` holds the tuple, `launched == []`), **and name the reason in a comment** — never assert that the old session is in `spent_sessions`, which is the assertion a reader of the spec would write and which is false. Do **not** switch the index to `runs(path)` to make the prose literal: it is scope the spec does not carry, it changes nothing about this acceptance (the live run holds the job either way), and `latest` is the choice that keeps the index and the stopper agreeing by construction — `health.settle_ended` reads `pool.load_sessions(product)`, which *is* `lifecycle.latest` (`asf/workers/pool.py:236-238`). The residual, named as out: if the *newer* run is also ended and spent, an older run's leftover process keeps its dead job name and blocks the row — the card's own bug, surviving for a relaunched job, and equally invisible to the stop that would have killed the process. That is one predicate away from this one, it is a Bug of its own, and it is not fixed inside this footprint. |
