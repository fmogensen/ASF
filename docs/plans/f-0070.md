# Plan F-0070 — the steps reach the judge, the judge cancels, the cancel is re-run, the line says which

Epic: E-0001 — ASF 0.1 — a working factory. Spec: `docs/specs/f-0070.md` (approved).
Branch: `plan/F-0070`.

Seven Tasks, one per Story of the spec, in the spec's own order. The cut is **by the surface each
Story names**, not by file: §2.8's footprint puts six of the seven Stories inside `asf/ci_queue.py`,
so a cut by file would collapse the card into one Task nobody can review. The cut this plan makes
is the one the spec already made when it wrote §2.1 (the seam), §2.2 (the judge), §2.3 (the watch),
§2.4 (the cancel and the re-run), §2.5 (the configuration), §2.6 (the rows) and §2.7 (the stream) as
seven sections with seven acceptance fences.

The price of that cut is stated up front (PD2): every Task's `writes:` carries `asf/ci_queue.py`, so
the queue runs all seven one after another. That costs nothing here, because six of the seven are
serial by dependency anyway — the watch cannot be written before the judge and the seam, the re-run
cannot be written before the cancel, the stream join cannot be written before the record it joins.

Wave order: **(1 ‖ 2 ‖ 5) → 3 → (4 ‖ 6) → 7**.

Task 1 is the seam (the steps travel on the read the pass already makes). Task 2 is the rule itself,
a pure function over a job dict with no host and no clock. Task 5 is the product's key, which needs
neither. Task 3 is the watch and the cancel, and it needs both 1 and 2. Task 4 is the durability of
the cancel — the history list, the cap, the re-run line — and Task 6 is the doctor row and the
status clause; both read what Task 3 writes. Task 7 joins the class onto the `ci` stream from the
history list Task 4 adds.

§3.1 is "the whole gate", so every Task's Gate runs `python3 tools/run_tests.py`,
`bash tools/check_conventions.sh` and `bash tools/check_generic.sh` beside its own fence, and every
Acceptance block below carries §3.1's two fences byte for byte after the Story's own.

### Task 2: the rule itself — `step_silence`, and the limit at the module's own level
stories: S-33001
writes: asf/ci_queue.py, tests/test_ci_step_silence.py
after: none

**Files**

- `asf/ci_queue.py`
- `tests/test_ci_step_silence.py`

**Steps**

1. The constants, beside `PHANTOM_RED_S` (`:313`): `DEFAULT_STEP_SILENCE_MIN = 10`, and
   `MOVING, STEP_SILENCE, BUDGET, UNKNOWN = 'moving', 'step-silence', 'budget', 'unknown'`, each
   with the `#:` comment §2.2 gives it.
2. `step_silence(job, now, limit_s)` — `(class, step name, since)` for one job, §2.2's docstring
   verbatim. The body is the spec's table and nothing else: take the job's `steps` (absent, not a
   list, or empty → `(UNKNOWN, None, None)`); parse each `started_at` and `completed_at` through
   the module's `_parse` (`:325`); the *newest parsed start* is the step it is inside, ties broken
   by the later position in the provider's own order, never by name; `(UNKNOWN, None, None)` when
   no step has a parsable start; `(MOVING, name, start)` when any step's parsed `completed_at` is
   at or after that start, or when `(now - start).total_seconds() <= limit_s`; else
   `(STEP_SILENCE, name, start)`. No clock, no host, no configuration, no import.
3. `_minutes(v, default)` — the duration grammar at this module's level (D11, P17): a bool is the
   default, an int or float is minutes, a string matching `^\s*(\d+(?:\.\d+)?)\s*([smhd]?)\s*$`
   scales by `{'s': 1/60, 'm': 1, '': 1, 'h': 60, 'd': 1440}`, anything else is the default. The
   same table as `asf/workers/stall.py:52-60`, which `ci_queue` may not import.
4. `step_silence_seconds(product)` — §2.2's docstring: `_qcfg(product).get('step_silence_min')`
   (`:350`) through `_minutes` with `DEFAULT_STEP_SILENCE_MIN`, as seconds. `0`, and the strings
   `off`, `none`, `false` (case- and space-insensitive), and a literal `False`, all return `0` —
   the watch off (D12). A negative number returns `0` too: a limit below zero is not a shorter
   watch, it is no watch.
5. `JudgeTests` in `tests/test_ci_step_silence.py`, one case per row of §2.2's table, named exactly
   as §3.2 names them:
   - `test_a_step_started_past_the_limit_with_no_completion_since_is_step_silence`
   - `test_the_named_step_is_the_newest_started_one`
   - `test_a_completion_after_the_newest_start_is_moving`
   - `test_a_step_under_the_limit_is_moving`
   - `test_a_job_between_steps_is_moving_not_stalled` — §2.2's fourth row: `build` completed 12 min
     ago and `test` has not started, so the newest *start* is `build`'s and `build` completed at or
     after it. `moving`, named `build` (§1.2).
   - `test_no_steps_is_unknown_and_claims_nothing` — `steps: []`, `steps` absent, and `steps: None`.
   - `test_steps_with_no_start_are_unknown`
   - `test_an_unparsable_stamp_is_unknown_never_stalled`
   - `test_a_tie_on_started_at_names_the_later_step_in_provider_order`
   - `test_the_limit_is_read_from_the_product_and_defaults_to_ten_minutes` — the product built in
     memory (`env.Product('p', {...})`, as `tests/test_ci_queue.py:27-36` builds one), so the judge
     is tested with no file and no `config_problems` in the way.
   - `test_zero_and_off_turn_the_watch_off` — `0`, `'0'`, `'off'`, `'none'`, `'false'`, `False` and
     a negative all give `0`.
   - `test_the_duration_grammar_matches_stall_silent_minutes_over_one_table` — one table of inputs
     (`45`, `'45'`, `'45m'`, `'1h'`, `'30s'`, `'2d'`, `'nonsense'`, `''`, `True`) asserted equal
     against `asf.workers.stall.silent_minutes` over a product carrying the same value in
     `stage_limits.silent_min`, so the two grammars cannot drift apart silently (D11). The off
     words are asserted as this module's own extension and are not put to `silent_minutes`.

### Task 3: the watch and the cancel — a job hung inside a step goes by the twelfth minute
stories: S-33002
writes: asf/ci_queue.py, tests/test_ci_step_silence.py
after: Task 1, Task 2

**Files**

- `asf/ci_queue.py`
- `tests/test_ci_step_silence.py`

**Steps**

1. The constants: `STALL_PASSES = 2` and `STALL_GAP_S = 10 * 60`, beside `PHANTOM_PASSES` and
   `PHANTOM_GAP_S` (`:309-312`) and with the same `#:` comments in this module's voice.
2. `load` (`:1160`): `'stalled'` joins the key tuple as a dict (PD11).
3. `update_stalls(product, src, items=None, out=print, dry_run=False, now=None)` — §2.3, mirroring
   `update_phantoms` (`:1227`) step for step, reading and writing the queue file directly through
   `load`/`save` rather than through a `Queue` (PD3). Returns the number cancelled.
   - `m = mode(product)`; `off` or no `repo_slug` → `0`, no host call. `dry_run = dry_run or
     m == 'dry-run'`.
   - `limit = step_silence_seconds(product)`; `0` → `0`, no host call (D12).
   - `runs = src.live_runs()` inside a bare `except Exception` the way `update_phantoms` guards
     `busy_runners` (`:1236`); None → `0`, and **the records already in the file stand** — an
     unreadable read learns nothing and forgets nothing.
   - For each run: `jobs = src.live_jobs(run['id'])`; None skips that run only. For each job with
     `status == 'in_progress'`: `cls, step, since = step_silence(job, now, limit)`.
   - `cls == STEP_SILENCE` → the record under `f"{run['id']}:{job['name']}"`, §2.3's shape:
     `run`, `job`, `step`, `since` (the step's own start, D9), `last` (`_iso(now)`), `passes`,
     `branch`, `sha`, `item`, `label`, `workflow`. `item` is `_item_of_run(branch, None, items)`
     (`:2235`) and `prio, label` are `priority(item, items, branch, product=product)` (`:612`);
     `workflow` is the run's own (PD4). A previous record whose `last` is within `STALL_GAP_S`
     **and** whose `step` and `since` are unchanged counts `passes + 1`; anything else starts at
     `passes: 1` — the job moved.
   - Every other class, and every run and job no longer in the listing, leaves the watch: the new
     map replaces `data['stalled']` wholesale, as `update_phantoms` replaces `data['phantom']`.
   - `passes == STALL_PASSES` → step 4. Otherwise, on the first pass that records it, §2.3's line:
     `ci queue: stalled in-progress {kind} run {rid} ({item}, {label}) — its job {job} has been
     inside step "{step}" for {n} min with no step completed since`.
4. The cancel, per confirmed record, in `since` order (longest-stuck first), §2.4 — and no
   exemption is consulted: not the trunk's, not an S1's, not `relief_exempt_paths` (D6).
   - `mode: on` → `src._gh(['run', 'cancel', str(rid), '-R', product.repo_slug])`. None → the
     refused line, the record kept with `passes` at the cap, and the next pass tries again.
   - `mode: dry-run` → the `would cancel` line, no call, and nothing written (the function returns
     before `save`, as `Queue.write` is false in dry-run).
   - A successful cancel → the cancelled line, and the `relief` record of P10 (`:2657-2661`) with
     `trunk_id`/`trunk_sha`/`trunk_created` absent and two keys of its own, `stall: STEP_SILENCE`
