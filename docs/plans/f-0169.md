# Plan F-0169 — the guard first, then the key it guards

Epic: E-0001 — ASF 0.1 — a working factory. Spec: `docs/specs/f-0169.md` (approved). Branch:
`plan/F-0169`.

Two Tasks, cut so that **no key change is ever on the trunk that the scheme integer cannot
distinguish**:

1. **the guard, before the thing it guards** — `Cause.scheme`, `diagnose.schemes`, the `scheme=`
   kwarg on the gate cause, and both sites in `loop.py` that write a cause's entry. A **behavioural
   no-op** when it lands: today's ledger carries no `signature_scheme`, so `schemes()` answers `{1}`
   for every window with a red gate, every gate cause is filed with `scheme: 1`, and `1 in {1}`
   sends `verify` down the ordinary comparison it takes today. Nothing the factory measures changes.
2. **the reader, the key, the count and the scheme, in one commit** — `first_failing_line`'s three
   tiers, `_sig_class`'s dotted-id reduction, `rank`'s occurrence counting with `red_runs`, and
   `SIGNATURE_SCHEME = 2` on every new ledger line and through the `gates` stream. This is the Task
   that changes what a red gate is keyed on and what its number means, and it lands **whole** —
   deliberately, and against the obvious four-way split (PD1).

They run **1 → 2**, one after the other. Both write `asf/scorecard/diagnose.py` and
`tests/test_scorecard.py`, so the footprints serialise them independently of the argument, and
`after:` says the same thing for the reason that matters: Task 2 is only safe once Task 1's clause
is on the trunk to catch it.

**Read PD1 before deciding this is under-cut, and PD2 and PD3 before writing a line of Task 2.**
PD1 is why four Stories are one commit. PD2 is a measured defect in the spec's `## The design`: the
120-character cut the `gates` stream already applies to a signature defeats `UNITTEST_FAIL_RE`'s
`$` anchor for **exactly the two tests this card was filed about**, so a coder who types the spec's
regex verbatim ships a card key that is still not a test name. PD3 is the spec's C4 arithmetic,
which is wrong by 22 characters.

The whole-tree fences of §*The fences* bind both Tasks, so both Gates carry them beside their own
commands.

### Task 1: the guard, armed, before anything it guards changes
stories: S-36354
writes: asf/scorecard/diagnose.py, asf/scorecard/loop.py, tests/test_scorecard.py
after: none

The spec's `## The design` §5 in full, plus the two things in `diagnose.py` that arm it:
`diagnose.SCHEME_1`, `diagnose.schemes`, `Cause`'s eighth field, the `scheme=` kwarg on the gate
cause's construction, `file_causes`'s entry key, `verify`'s `scheme changed` clause, and the
`scheme` on the reopened entry (C10).

**Nothing the factory measures changes when this Task lands.** No row in the gate ledger carries
`signature_scheme` (PD11: measured, 402 rows, none), so `schemes()` answers `{1}` for every window
holding a red gate and `set()` for one holding none; every gate cause is filed with `scheme: 1`;
and `verify`'s new clause finds `1 in {1}` and falls through to the comparison it makes today. The
`re_gated` half of the detail sentence and `red_runs` are **not** here — they are Task 2's, and
`Cause`'s detail string is byte for byte unchanged by this Task.

The `scheme=` kwarg is in **this** Task and not Task 2, and that is the whole point of the cut: a
`Cause` whose `scheme` is `None` puts `'scheme': None` on the entry, `verify`'s clause reads
`filed_scheme is None` and skips, and the guard is inert. A card filed in the gap between the two
Tasks would then be closed silently by Task 2 — this card's own defect, one Task later. Arm it here
or the Task is decoration.

Read **PD8** (the docstring to edit is the module's, and it is two additions), **PD9** (`after:
None` reaches a view and renders `—`) and **PD10** (no coercion; the schema is the guard).

**Files**

- `asf/scorecard/diagnose.py` — `SCHEME_1 = 1` with the spec's `#:` comment, beside
  `UNITTEST_FAIL_RE`'s eventual home above `_sig_class`; `schemes(facts, start, end)` as the spec
  writes it, placed after `_weeks` and before `_sig_class`; `Cause` gains
  `scheme: int | None = None` with the spec's two-sentence `#:` comment — the field is added, the
  `@dataclasses.dataclass(frozen=True)` decorator is **not** touched (P9, C8); the gate cause's
  `Cause(...)` in `causes()` (`:200-205`) gains the trailing
  `scheme=(max(schemes(facts, start, end), default=None) if c['name'].startswith('gate:') else None)`.
  `rank`, `metric` and the thresholds are untouched.
- `asf/scorecard/loop.py` — `file_causes`'s `state[cause.key]` literal (`:309-312`) gains
  `'scheme': cause.scheme`; `verify` gains the `scheme changed` clause between the `clutter:`
  baseline override (`:375-376`) and `verdict = moved(...)` (`:377`); the reopen's `state[key]`
  literal (`:398-401`) gains its `scheme`; the module docstring's verdict list (`:13`) grows by two
  words (PD8). `moved`, `direction`, `card_text` and every threshold are untouched.
- `tests/test_scorecard.py` — a new `class SchemeChangeTests(unittest.TestCase)`, a plain
  `TestCase` and **never** a subclass of a harness in this module.

**Steps**

1. `SCHEME_1 = 1`. One integer, named, so no call site writes a bare `1` for "what a row with no
   scheme on it was written under".
2. `schemes(facts, start, end)` exactly as the spec writes it: the set over the window's **red**
   gates only, `int(g.get('signature_scheme') or SCHEME_1)`, empty when the window holds no red
   gate to ask. One helper, not two — `max(schemes(...), default=None)` is "the scheme of this
   window" at both call sites, and `n in schemes(...)` is "does this window still speak *n*".
3. `Cause.scheme: int | None = None`, last. All eight construction sites are positional (P9), so a
   defaulted trailing field is source-compatible and the seven that pass nothing keep `None`.
4. `causes()`: only the `by_ci_job` loop's `Cause` gains `scheme=`, and only for a `gate:` key —
   a `ci-job:` cause's scheme is `None`, which `verify`'s clause treats as "nothing to compare"
   because its `key.startswith('gate:')` test fails first anyway. Belt and braces, deliberately:
   the kwarg is guarded *and* the clause is guarded, so neither alone is load-bearing.
5. `file_causes`: one key on the entry literal. The entry grows from twelve keys to thirteen (P14);
   nothing reads it by length.
6. `verify`'s clause, placed **after** the `try`/`except KeyError` that reads `before` and `after`
   and after the `clutter:` override, **before** `verdict = moved(...)`. `key.startswith('gate:')`
   and `key.startswith('clutter:')` are disjoint, so the order between those two lines is free;
   the order against `moved` is not — the clause must `continue` before a verdict is computed.
   It enqueues exactly one `history` item, appends `line[2:]` to `entry['log']` the way the
   ordinary path does, sets `verdict='scheme changed'`, `verified`, `before`, `after=None`, appends
   to `done`, and **does not reopen** (C9).
7. The reopen (`:398-401`): `'scheme': (max(diagnose.schemes(facts, landed, landed + span),
   default=None) if key.startswith('gate:') else None)`. The window is `[landed, landed + span)` —
   the after-window it just measured, which is where the new `baseline` (`after`) came from, so the
   entry's scheme and its number always come from one reading.
8. `SchemeChangeTests` — the spec's class, six rows, over `verify` and the two filing sites:
   - a `gate:` entry filed with `scheme: 1` whose after-window holds only scheme-2 red gates →
     verdict `scheme changed`, `after is None`, exactly **one** `history` enqueue whose line names
     both schemes (`from 1 to 2`) and the before-number, and **no** `inbox` enqueue.
   - the same entry with scheme-1 red gates still in the after-window → judged the ordinary way
     (`moved` or `didn't move`, whichever the numbers give).
   - an entry with **no** `scheme` key → judged the ordinary way. This is F-0169's own row (PD14).
   - an after-window with **no red gate at all** → `schemes()` is empty, `if after_schemes` is
     False, judged the ordinary way, so a genuine fall to zero still reads `moved`.
   - `file_causes` on a `gate:` cause writes `scheme` equal to the scheme of the window it was
     ranked over, and on a non-`gate:` cause writes `None`.
   - a `gate:` cause that **didn't move** carries `scheme` on its **reopened** entry, and verifying
     that reopened entry a cycle later reaches the `scheme changed` clause instead of the
     no-scheme fallback — C10, and the one row that makes the reopen's key more than a decoration.
     A non-`gate:` cause's reopened entry carries `None`.
9. Do not add a `'got worse'` path, a reopen under a new key, or a backfill of an existing entry's
   scheme. All three are the spec's `## Out` or C9.
