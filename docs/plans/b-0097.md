# B-0097 — plan: publish retries a transient network refusal in place, with backoff

Item: B-0097 — A network blip on push scores finished work as 'failed: not pushed' and costs a
correction round. Epic: E-0002 — ASF 0.2 — self-improvement. Branch: `fix/B-0097`. No spec
exists; the Acceptance below is the record.

## Cause

A DNS blip ("Could not resolve host: github.com", resolved within a minute) made
`publish plan/F-0101 refused`, and the session that had otherwise finished its work ended
`failed: not pushed`, costing a correction round for a refusal that had already cleared by the
time anyone looked at it.

`e48caa821ccda3b4c970924ba28df3baf80fba6d` (2026-09-24, *fix(lane,feeder): the PR lane is one
state machine; the feeder reads one occupancy answer*) had already given this card half its
acceptance, and names it: its message carries a `Fixes: B-0097` line. That line sits in the
message body, above the final trailer block, so `git log --grep=B-0097` finds it and a reader of
git's parsed trailers (`git log --format='%(trailers)'`) does not — the distinction is worth
keeping straight, because reading it as a trailer and finding none has already been mistaken for
the citation being false.

That commit introduced `asf.workers.lifecycle.push_failure`, which classifies a push refusal's
text into `NETWORK_ERROR` (DNS failure, connection reset/refused/timed out/closed, network
unreachable, early EOF, remote hung up, SSL/TLS errors — `asf/workers/lifecycle.py:137-144`) or
`HOOK_REFUSED`, and `asf.workers.health.push_retry`, whose `NETWORK_ERROR` branch
(`asf/workers/health.py:950-952`) treats such a retry as a blip — retried, no round: it returns
without marking the session ended or opening a correction, so the next tick's health pass
re-gathers the same worktree and republishes through the same path
(`asf.workers.lifecycle.publish`, called from `health.publish_gap`). That gave the card its
*next-tick* retry. The acceptance also asks for an *in-tick* retry, backed off, before the
refusal is even handed to the next tick — that half had never been built, and a first pass on
this branch (`ee2138a`) closed the card on the classification alone, citing `8066ecf4e` — an
unrelated spec commit — for the classification.

Verifying either citation needs this repository's full history. A shallow clone — the depth a
cloud session is handed — resolves neither sha, and `git blame` inside one credits the
classification lines to whatever commit its shallow boundary happens to be, which is a different
commit at every depth. A sha here that will not resolve is a clone to deepen
(`git fetch --unshallow`), not a sha to correct.

## Task 1 — retry the branch's own push in place, with backoff

writes: `asf/workers/lifecycle.py` `tests/test_lifecycle.py`

- Step 1: in `asf/workers/lifecycle.py`, add `PUBLISH_RETRY_BACKOFF_S = (1.0, 2.0)`, the in-tick
  backoff schedule for `publish`'s own retry of a transient network refusal — short enough
  together never to hold a health tick, long enough for the DNS-blip signature this card was
  filed on (resolved within a minute) to clear within it.
- Step 2: add `_push_retrying(args, wt, limit, guard, sleep=time.sleep,
  backoff=PUBLISH_RETRY_BACKOFF_S)`: calls `gitpush.push` once, then, while the returncode is
  non-zero and `NETWORK_RE` matches the combined stderr/stdout, sleeps the next backoff step and
  calls `gitpush.push` again, up to `len(backoff)` more times. A refusal that doesn't match
  `NETWORK_RE` (the hook, auth, a rejected ref) returns on the first try, same as before this
  retry existed.
- Step 3: give `publish` a `sleep=time.sleep` parameter (so tests can override it, matching
  `lifecycle.stop`'s own pattern) and call `_push_retrying` in place of the branch's own
  `gitpush.push` call. Exhausted, the refusal falls through to the caller unchanged — the
  next-tick path (`health.push_retry`'s `NETWORK_ERROR` branch) is what picks it up from there.
  `asf.harvest.mechanical.publish_worktree` calls `lifecycle.publish` directly and gets the same
  retry with no change of its own.
- Step 4: tests, in `tests/test_lifecycle.py`, class `UnpushedAfterARebaseTest`
  (`tests/test_lifecycle.py:2028-2088` as this branch stands — grep the names below once
  the lines move):
  - `test_b0097_a_network_blip_is_retried_in_place_with_backoff_and_then_succeeds` — two
    network-blip refusals, then a real push; `publish` succeeds, three push attempts, both
    backoff delays slept.
  - `test_b0097_a_hook_refusal_is_never_retried` — a pre-push-hook refusal; `publish` fails on
    the first attempt, nothing slept.
  - `test_b0097_a_network_blip_that_outlasts_the_backoff_falls_through` — every attempt blips;
    `publish` fails after `1 + len(PUBLISH_RETRY_BACKOFF_S)` attempts, both delays slept, and the
    refusal still classifies as `lifecycle.NETWORK_ERROR` for the next tick's health pass to
    retry from.

The existing `tests.test_lane.FeederAndOutcomes.test_b0097_a_network_blip_is_retried_and_a_hook_refusal_carries_its_output`
covers the next-tick half this card already had before this Task.

## Acceptance

- [x] A push or publish that fails with a transient network error (DNS resolution, connection
      refused or reset, timeout, HTTP 5xx from the remote — git reports that one as
      `unable to access`, which `NETWORK_RE` matches) is retried with backoff within the same
      tick (`_push_retrying`, `PUBLISH_RETRY_BACKOFF_S`), and on later ticks, by the tick itself
      from the session's worktree (`health.push_retry`'s `NETWORK_ERROR` branch,
      `asf/workers/health.py:950-952`). What that branch records is one tick-status line,
      `network error: <detail> — published again next pass`, and then it returns: the run is
      never marked failed, and no correction session is launched. It is not marked ended either
      — no `ended` or `end_reason` is written — so the run stays open and the next health pass
      publishes the same worktree again.
- [x] Only a non-transient refusal (auth, a rejected non-fast-forward after rebase, a hook
      refusal) is a failure.
- [x] Tests classify each error class.
