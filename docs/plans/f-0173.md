# Plan F-0173 — one ruler for the review and the ruling

Epic: E-0001 — ASF 0.1 — a working factory. Spec: `docs/specs/f-0173.md` (approved). Branch:
`plan/F-0173`.

**One Task.** The spec says what this card is in one line — *"a one-measure change, not a new
mechanism: the ruling is measured with the same ruler its review is measured with"* — and the whole
of it is a signature, a nine-line loop, a docstring paragraph, a lambda, a doc row, and the tests
that pin them. It lands whole. **PD3** is why it is not two Tasks, and it is the shorter argument:
either half alone is a trunk on which the card's own acceptance test cannot be written.

**Two of the spec's preconditions have gone stale since it was written, both because F-0157 landed
in between** (`b9b45b734`, task T-0519, #360 — the only commit to touch any file this card names
since the spec's `d6a2206d5`). One is in this card's favour and one is a trap:

- **P6 is spent** — the `finished(r)` guard the spec promises not to touch already reads
  `delivered(r)`. D7's own instruction covers it exactly: it stays. **PD2.**
- **P1 is false** — `overruling` is no longer callerless in `tests/`. F-0157 added three calls, one
  of them passing **`unchanged_since=` by keyword**, so the rename this card makes is a `TypeError`
  on a green test unless that line is edited in the same commit. **PD1, and it is the one thing in
  this plan a coder cannot discover by typing the spec's `## The design`.**

### Task 1: the ruling is measured with the review's ruler — one predicate, both shas, the lane hands over `same_code`
stories: S-35800
writes: asf/workers/lifecycle.py, asf/harvest/lane.py, tests/test_lifecycle.py, tests/test_lane.py
after: none

The spec's `## The design` §1 and §2 in one commit. After it lands, a lane branch that is waiting on
a ruling and gets restacked onto a moved trunk keeps the ruling: the review is still current
(B-0147) and the ruling still stands (this card), the branch goes `REVIEW → GATE` with
`reviews/1-t-0001.md overruled by adjudicate-t-0001's ruling`, and the feeder is never asked for the
second adjudicate that the loop guard used to park one session later.

**Read PD1 before running the suite and concluding the change broke something.** Renaming
`unchanged_since` to `same_code` breaks `tests/test_lifecycle.py:2106-2108`, which passes it by
keyword — that line is edited in this commit, and it is the only pre-existing test line this Task
touches. Then **PD2** (the `delivered(r)` guard at `:768` is F-0157's and stays; every `lifecycle.py`
line number in the spec is `+8`), **PD7** (the new lane tests run twice, by design) and **PD9** (why

**Steps**

1. The signature: `unchanged_since` → `same_code`, keeping the `=None` default. The default is what
   makes `tests/test_harvest.py:2679`'s three-argument call and `DeliveredReadersTests`' first two
   cases keep their meaning — no predicate, sha identity only — which is the fifth row of block C.
2. The docstring's last paragraph, from the spec, verbatim. It is the record of the rule (the spec's

   by sha, and that the ruler is `asf.evidence.review.same_code`, the same one B-0147 measures the
   review with. Keep the `:func:` reference — it is how the two halves stay findable from each other.
3. The body tail, from the spec, verbatim:
   `ruled` is the `pushed:` sha when `PUSHED_SHA_RE` finds one, then `launch_head` appended **only**

   the same `run.get('job')`. Keep `head.lower().startswith(sha)` rather than `==`: the `pushed:`

   equality. Do not add a timestamp comparison, a "no commit the ruling did not see" test, or any

4. The lane's lambda. It is the `is_current` call seven lines above it with the same `repo`, `conv`,
