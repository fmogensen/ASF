# Plan F-0064 — eight Tasks in four waves: the stream, the writers, the one helper, the render, the deletion, the money, the prefix, the grants

Epic: E-0001 — ASF 0.1 — a working factory. Spec: `docs/specs/f-0064.md` (approved). Branch:
`plan/F-0064`.

Eight Tasks, four waves, real parallelism. The spec's thirteen Stories fall into two groups that
share almost nothing: the events spine (`asf/metrics/metrics.py`, `asf/metrics/log.py`, the tick
and its steps, `asf/approvals.py`) and the three things bolted onto it afterwards (cost, the
brief's prefix, the grant audit). The spine is a chain — every Task in it rewrites the same
validator or the same `Context` — but the parser deletion touches none of it and starts at once,
and the cost work, the brief work and the grant work each sit behind exactly one predecessor
rather than behind all of them.

**The wave order:**

| wave | Tasks | why they run together |
| --- | --- | --- |
| 1 | **Task 1** (the stream, the key, `emit`) ∥ **Task 5** (the parser deleted) | disjoint: Task 5 touches `asf/metrics/import_sessions.py`, `asf/conventions.py` and `tests/test_metrics.py`, none of which Task 1 writes |
| 2 | **Task 2** (every writer emits; the tick counts) ∥ **Task 6** (cost) | disjoint: Task 2 is the tick and its steps, Task 6 is `metrics.py`, `tokens.py`, `prices.py` and `conventions.py` |
| 3 | **Task 3** (one `NEEDS OPERATOR:` helper) ∥ **Task 7** (the brief's stable prefix) | disjoint: Task 3 is eighteen printers, Task 7 is the briefs, the templates and the TOKENS view. Task 3 waits on Task 6 as well as Task 2, because Task 6's `cost coverage` line is the nineteenth printer and `asf/doctor.py` is in both footprints |
| 4 | **Task 4** (`asf log`) ∥ **Task 8** (the grant audit) | disjoint: Task 4 is `log.py`'s second half and the fixture day, Task 8 is `spawn.py`, `console_perms.py` and `redact.py` |

Every `after:` below is the smallest set that makes the Task's own Gate runnable, and
`asf.feeder.footprint.globs_overlap` was run pairwise over all eight footprints in this worktree.
Thirteen pairs intersect — (1, 2) on `asf/tick/tick.py` and `tests/test_events_stream.py`;
(1, 3) on `asf/metrics/log.py` and `asf/tick/tick.py`; (1, 4) on `asf/metrics/log.py`;
(1, 6) and (1, 7) and (6, 7) on `asf/metrics/metrics.py`; (1, 8) and (2, 8) on
`tests/test_events_stream.py`; (2, 3) on `asf/approvals.py`, `asf/tick/step_health.py` and
`asf/tick/tick.py`; (3, 4) on `asf/metrics/log.py`, `asf/cli.py` and `tests/test_log_render.py`;
(3, 6) on `asf/doctor.py`; (3, 8) on `asf/approvals.py` and `asf/console_perms.py`; (5, 6) on
`asf/conventions.py` and `tests/test_metrics.py` — and every one of the thirteen is ordered by a
declared `after:` edge, transitively, so the scheduler never has to discover a conflict. The
(3, 6) edge is the one the run found and this plan was corrected for: `asf/doctor.py` is in both
footprints, so Task 3's `after:` names Task 6 as well as Task 2.

Each Task's **Acceptance** is the §3 fence its Story names, copied byte for byte, plus the two
gates this repo runs before a push and the suite fence (`python3 tools/run_tests.py`) that this
product's external CI runs on the pull request and never on the session's host — the standing rule
(`approvals.full_suite_command`, `asf/approvals.py`).
