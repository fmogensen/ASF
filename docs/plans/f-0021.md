# Plan F-0021 — the launch: four artefacts a stranger can read, run and check

Epic: E-0001 — ASF 0.1 — a working factory. Spec: `docs/specs/f-0021.md` (approved). Branch: `plan/F-0021`.

Four Tasks, cut along the spec's own build order (§2.6): the two pages the record gains and the
command that writes them (Task 1), the quickstart as a thing that runs (Task 2), the page that makes
the argument and carries the machine-written numbers (Task 3), and the release the gate justifies
(Task 4).

Task 1 and Task 2 write disjoint trees and start together. Task 3 waits on both — its `commands`
block is read from the parser, so `asf pages` must be registered before `asf readme --refresh` runs
(§2.6), and its `### Quick start` section names a script T5 requires to exist and be executable.
Task 4 waits on Task 3: its fence (T3) reads the page's headings and the CHANGELOG in one block, and
only the Task that lands the CHANGELOG can make that block pass.

Wave order: **(1 ‖ 2) → 3 → 4**.

No scope is added. Six places where the spec's design does not meet this tree as it stands are closed
inside the Task that causes them — PD3 (`asf.release.criteria` does not exist), PD4 (the two doctor
rows must be advisory or they break the quickstart's own doctor step), PD5 (the roadmap renderer
reaches for `gh`, and a page that is `--check`ed must be deterministic), PD6 (the quickstart must own
`HOME`, not only `ASF_HOME`, or step 7 is red or the reader's console settings are rewritten), PD7
(T7's card regex admits no id for the largest gap the scorecard must name) and PD9 (the Story ids
this plan carries will mint nothing). Each is a section of the spec met against the tree, not a
widening.

`docs/specs/f-0021.md` is in the spec's declared footprint (§4) and is **not** in any Task's
`writes:`: the corrections this plan makes to the spec are this decisions block, which is where the
plan template puts them. Nothing rewrites the approved spec.

The spec's declared footprint (§4) minus that one file is exactly the union of the four `writes:`
lines below, and no two Tasks that run together intersect.

No id is invented, and this session's `BACKLOG_ID_RANGE` is therefore unused. |
| PD3 | **`asf.release.criteria` does not exist** | §2.4's `## Release readiness` row names `asf.release.criteria` as its source. `asf/release.py` has no such name: it offers `KEYS` (the eight keys), `Criterion` (`key`, `name`, `met`, `evidence`), `evaluate(f, cfg)` over gathered facts, and `compute(root, product, **kw)` which returns `{'product', 'as_of', 'window_days', 'ready', 'criteria': [asdict(c)…]}`. | PD4 | **The two drift rows are advisory, not required** | D8 puts `asf pages --check` and `asf readme --check` in `asf doctor`. A *required* row (`required=True`) turns `asf doctor`'s exit code red — `doctor.is_red` is `any(required and ok is False)` — and two things break at once: every product whose record has never been written by `asf pages` goes red on a page it never asked for, and Task 2's quickstart, whose step 7 asserts `asf doctor` exits 0, fails the moment Task 1 lands beside it. Both rows are therefore `required=False`, which is where `clock code`, `rule-checks`, `capacity` and `savings` already sit: the drift is visible in the table, and the *enforcement* is D8's own — a drifted page is a Bug a session fixes on a branch, filed through the existing path. That the row cannot change the exit code is what makes Task 1 and Task 2 safe to run in the same wave. |
| PD5 | **The roadmap renderer reaches for `gh`, and `--check` cannot** | `asf.views.roadmap.render(root, product)` calls `pr_annotate.pr_states(product)` when any named Feature has a PR — one `gh pr list` subprocess with a 60 s timeout (`asf/views/pr_annotate.py:17-35`). Two reasons Task 1 renders with `product=None` (`states = {}`, the `if (product and named_prs)` guard): a page the tick writes must not be able to hang the tick on a network call, and a page `--check` re-renders must be a pure function of the record or `--check` reports drift every time the forge's answer changes. The page loses the `#118 merged` annotation and keeps the `#118` the record itself holds. |
| PD6 | **The quickstart owns `HOME`, not only `ASF_HOME`** | §2.3 step 3 sets `ASF_HOME=<dir>/.ASF`, which is enough to keep the reader's own product config out of it. It is not enough for step 7. `tests/test_sample_product.py:88` has to run `asf console-permissions install --product sample --scope user` before `doctor`'s `console permissions` row is green (B-0131), and `console_perms.settings_paths(product, home=None)` resolves `home` from `os.path.expanduser('~')` — so on a real reader's machine that step would rewrite their own console settings, which §2.3 forbids outright ("touches nothing outside its own temp directory"). Task 2 therefore exports `HOME=<dir>/home` for every `asf` call beside `ASF_HOME`, and with it `GIT_AUTHOR_NAME`/`GIT_AUTHOR_EMAIL`/`GIT_COMMITTER_NAME`/`GIT_COMMITTER_EMAIL` (a temp `HOME` has no `.gitconfig`, and the tick's own commit in the record clone needs an identity — the same four the test fixture sets). The reader's real `~` is read for nothing and written for nothing. |
| PD7 | **T7's card regex admits no id for the biggest gap** | T7 requires every `NOT_MEASURED` row's `card` to match `^[FB]-\d{4}$`. Two of D5's three gaps have such a card in this record — per-lever attribution is F-0091 (`asf improve` — the self-improvement pass as a tick step) and model comparison is F-0093 (model routing argued from minutes-per-landing). **Prompt evals have none**: no spec under `docs/specs/` carries them, `docs/research/prior-art-prototype.md` parks them at 0.2, and this session may not mint a Feature (and could not: a five-digit id from `BACKLOG_ID_RANGE` fails T7's own regex). | PD8 | The sample's tick never runs the daily step, so the quickstart does not exercise `asf pages` | `sample/product.yaml` carries `steps: {batch: off, daily: off}`. §2.3 already reads this correctly — step 8 runs `asf roadmap` and `asf scorecard` directly, "so the reader has seen §2.4's pages before being sent to the public ones" — and Task 2 adds nothing to make the daily step run. | PD9 | **This plan's `stories:` lines will mint no stories, and that is not this plan's to fix** | This Feature's Story ids are five digits (`S-28250 … S-28258`, the spec's frontmatter), because `asf.record.ids.mint_id` formats `f"{n:04d}"` and the namespace has passed 9999. `asf.record.plan_tasks.STORY_ID_RE` is `\bS-\d{4}\b` (`asf/record/plan_tasks.py:25`) and matches none of them — `\b` cannot fall between the fourth and fifth digit — so `stories_of` returns `[]` and every Task card minted from this plan carries no `stories`; `asf.record.core.ID_RE` (`^[A-Z]-\d{4}$`, `asf/record/core.py:40`) rejects such an id outright. `asf.record.plan_order.CARD_ID_RE` is `\b[A-Z]-\d{4,}\b` and does read them, so the `after:` lines below mint correctly. | PD10 | `ROADMAP.md` and `SCORECARD.md` are not made conventions | F-0030's PD4 had to move `README.md` and `docs/readme-numbers.json` into `asf.conventions` because `tools/check_conventions.sh` generates an anchored regex for every `DEFAULT_*` string containing `/`, `{` or `#` (`asf/conventions.py:299-315`). | PD12 | What Task 4 may write into `docs/release-0.1.md`, and what it may not | §2.5 says the page "is written by a session from the real reading, not composed", and T8 is marked operator-run because the gate reads the factory's own record, which is a separate repository. ### Task 1: `asf pages` — the record's two pages, the daily part, and the two drift rows
stories: S-28255, S-28256, S-28257
writes: asf/views/pages.py, tests/test_record_pages.py, asf/cli.py, asf/tick/step_daily.py, asf/doctor.py
after: none

§2.4 whole, plus D8's visible half. A new module writes `ROADMAP.md` and `SCORECARD.md` into the
record, the CLI registers it, the tick's daily step gains a fourth part so the pages ride the tick's
one commit, and `asf doctor` gains two advisory rows so drift is seen without a human reading a page.

**Files**

- `asf/views/pages.py` — new.
- `tests/test_record_pages.py` — new.
- `asf/cli.py` — the `pages` subparser and its dispatch.
- `asf/tick/step_daily.py` — the fourth part.
- `asf/doctor.py` — the `pages` and `readme` rows.

**Steps**

1. `asf/views/pages.py`, stdlib only, in the style of `asf/views/readme.py`: a module docstring that
   says what the two pages are for and names this spec. Module constants `ROADMAP = 'ROADMAP.md'`,
   `SCORECARD = 'SCORECARD.md'` (PD10), `SCORECARD_SECTIONS = ('## Value', '## Cost',
   '## Release readiness', '## Not measured')` in that order, and `NOT_MEASURED` — a tuple of dicts,
   each `{'what', 'why', 'card'}`, with the two rows PD7 has cards for: per-lever attribution
   (F-0091) and model comparison (F-0093).
2. `header(root, command)` — the generated stamp every page opens with: the day, the record's
   `index.json` `generated` stamp read through `asf.views.index_reader.load`, and the command that
   writes the page. One shape, both pages.
3. `render_roadmap(root)` — `header` + `asf.views.roadmap.render(root, None)` (PD5: `product=None`,
   so no `gh` call and a page that is a pure function of the record) + one closing line saying the
   page is written by the tick and naming `docs/specs/f-0021.md`.
4. `render_scorecard(root, product, **kw)` — `header` + the four sections of §2.4's table, in
   `SCORECARD_SECTIONS` order:
   - `## Value` from `asf.views.scorecard.compute(root, product, weeks=4, facts=...)` — the weekly
     table: value shipped, its cost, the lane split.
   - `## Cost` from `asf.metrics.metrics.compute_costs` and `subtree_cost` — spend per shipped
     Feature and the trimmed per-Feature table.
   - `## Release readiness` from `asf.release.compute(root, product, **kw)['criteria']` (PD3) — one
     row per criterion: key, name, met, evidence.
   - `## Not measured` from `NOT_MEASURED` — one row per gap and the card that would add it, and
     beneath the table the one generated line PD7 requires, naming prompt evals as a gap with no
     card yet and linking `docs/research/prior-art-prototype.md`.

   Every row carries the record path its numbers were read from — `index.json`, `metrics/sessions`,
   `metrics/ci`, `metrics/ticks` — the discipline `asf/views/readme.py`'s facts file keeps, and the
   reason a stranger can check a number instead of taking it. `**kw` is passed to
   `release.compute`/`gather` (`git`, `gh_json`, `log_dir`, `facts`) so the test renders the page
   with no git and no network (PD3).
5. `cmd_pages(args, root)`: `--refresh` renders both and writes each through
   `asf.metrics.metrics.write_if_changed`, printing `pages: <file> rewritten|unchanged`; `--check`
   (the default) re-renders, reports per page whether the committed text differs, writes nothing and
   returns 1 on drift; `--json` prints `{"ok": bool, "pages": [{"path", "changed", "generated"}]}`.
   `pages_daily(product, root)` is the thunk the tick calls — a `--refresh` with no argv.
6. `asf/cli.py`: `p_pages = sub.add_parser('pages', …)` with `--product`, `--check`, `--refresh`,
   `--json`, and `'pages'` added to the record-resolving tuple at the `roadmap`/`scorecard` dispatch
   (the command reads the record, so it resolves one), dispatching to `cmd_pages(args, view_root)`.
   `asf.plugin_build.VIEWS` is **not** touched (D10).
7. `asf/tick/step_daily.py`: a fourth entry in `parts`, after `scorecard` —
   `('pages', lambda: pages_daily(product, root))` — with the import beside the other three. `root`
   is `ctx.record_root()`, so the two pages are written in the record clone and carried by the tick's
   one commit. `run_part`'s existing contract stands: a failed part does not stop the others.
8. `asf/doctor.py`: two rows appended in `run`, both with `required=False` (PD4) —
   `('pages', False, ok, detail)` from a `check_pages(product)` that calls the module's check over
   `product.backlog_dir` and names each drifted page, and `('readme', False, ok, detail)` from a
   `check_readme_page(product)` that calls `asf.views.readme.check(product.repo_dir,
   product.conventions)` and reports `no spans — nothing to render` for the `None` case, which is
   what keeps the row quiet in front of a product with no page.
9. `tests/test_record_pages.py`: a fixture record in a temp dir on the shape
   `tests/test_readme.py:113` writes (an `index.json` with `generated` and `items`, and
   `metrics/<stream>/<day>.jsonl` per stream), an `env.Product('p', {...})` on the shape
   `tests/test_release.py:273` uses, and the injected `git`/`gh_json`/`log_dir`/`facts` that keep it
   off git and off the network. Cases: both pages render; the header carries the day and the record's
   `generated`; every `SCORECARD.md` row names its record path; the four sections appear in
   `SCORECARD_SECTIONS` order; the honest-zero line — `NOT_MEASURED` is non-empty, every row names a
   gap and a card, and the prompt-eval line is rendered (D5); `--refresh` twice writes the same bytes
   and reports `unchanged` the second time (idempotence); `--check` on a drifted page returns 1 and
   leaves both files byte-identical (read-only); and `ROADMAP.md` renders with no `gh` on `PATH`
   (PD5).

### Task 2: `tools/quickstart.sh` — twenty minutes on the sample product, run by a test
stories: S-28253
writes: tools/quickstart.sh, tests/test_quickstart.py
after: none

§2.3 whole. The script is `tests/test_sample_product.py`'s `setUpClass` in the form a stranger runs:
`set -euo pipefail`, stdlib tools only, one temp directory it prints first and never removes on its
own, and no account, no network and no `gh`.

**Files**

- `tools/quickstart.sh` — new, mode `0755`.
- `tests/test_quickstart.py` — new.

**Steps**

1. `tools/quickstart.sh`, `usage: bash tools/quickstart.sh [<dir>]`, default a fresh `mktemp -d`. It
   prints the directory as its first line, `set -euo pipefail`, and every path it writes is under it.
   Nine steps, each printing `quickstart: <n>/<total> <what>` and then the artefact to open.
2. Step 1 — check the host: `git`, `python3`, and `asf --version`. When `asf` is not on `PATH` it
   falls back to `python3 -m asf.cli` with `PYTHONPATH` set to this checkout's root, which is how a
   contributor runs it from a clone and how the test runs it. A missing prerequisite exits 2 with the
   one line that fixes it. No `gh`: the sample product is `ci: {provider: none}`, `deploy_sha: none`,
   and its workers are the `fake` runtime replaying `sample/fake_script.json`.
3. Step 2 — materialise the product: copy `sample/` into `<dir>/sample`, `git init -b main` the repo
   and the record, commit, make a bare origin for each, push `main` and `git remote set-head origin
   main` — the shape `_publish` makes in the test.
4. Step 3 — write the operator home: `ASF_HOME=<dir>/.ASF` with `config.yaml` and
   `products/sample.yaml` filled from `sample/config.yaml` and `sample/product.yaml` by substituting
   `@REPO@`, `@BACKLOG@` and `@SAMPLE@`. Beside it, and for the reason PD6 gives, `HOME=<dir>/home`
   and the four `GIT_AUTHOR_*`/`GIT_COMMITTER_*` variables, exported for every `asf` call. The
   reader's own `~` and `~/.ASF` are read for nothing and written for nothing.
5. Step 4 — `asf init --product sample`: the record's ten cards adopted, the intake directory, the
   console permissions. Because `HOME` is the temp one (PD6), the step that installs the console's
   own allow list writes under `<dir>/home`, which is what makes step 7 green. Points at
   `<dir>/sample/backlog/index.json`.
6. Step 5 — `asf next --product sample`: the S1 Bug as the only row, the "what would it do" view
   before anything runs.
7. Step 6 — one `asf tick --product sample`: the Bug launched as a fix on its `bugfix/` branch, the
   gate, the landing. Points at the tick's own commit in the record clone under
   `<dir>/.ASF/state/sample/record`.
8. Step 7 — `asf doctor --product sample`: the table is printed in full, and the script requires exit
   0. A non-zero doctor exits 3, reprinting the rows that are `RED` and the line that fixes each — a
   quickstart that hides a red doctor teaches the reader to ignore it. Advisory rows (`skip`) never
   fail it, which is `doctor.is_red`'s own reading and why PD4's two new rows cannot break this step.
9. Step 8 — `asf roadmap --product sample` and `asf scorecard --product sample`: the two views the
   record's pages are made of, so the reader has seen them before being sent to the public ones. The
   sample's `steps: {daily: off}` means the tick wrote no pages (PD8), and the script says so in one
   line rather than pointing at a file that is not there.
10. Step 9 — print what to read next: the three paths inside `<dir>` worth opening, and
    `docs/guide/getting-started.md` for their own product. Last line: `quickstart: done in <n>s`,
    from the elapsed seconds the script measured itself.
