# Plan F-0274 — the guard reads the rows that were drawn, then the counter says when none was

Epic: E-0001 — ASF 0.1 — a working factory. Spec: `docs/specs/f-0274.md` (approved). Branch:
`plan/F-0274`.

Two Tasks, one per Story, exactly the cut the spec's own C11 and its `## Records` footprints block
make. Task 1 is the **row**: `held_feature_row`'s occupancy-key guard replaced by one test over the
rows already drawn, `spoken` threaded to it from `_candidates`, so a Feature held by its own session
with a correction pending on it keeps the one row that says what holds it (S-72054). Task 2 is the
**counter**: `rows.silent_features`, `doctor.silent_work_line`, and `check_pushed_work` widened to
`check_plan_silence` so `pushed work` and the new `silent work` row come off one draw of the plan
(S-72055).

Wave order: **1 → 2**.

The two are serial and there is no parallelism to buy. Their `writes:` intersect on
`asf/feeder/rows.py`, so the record would run them one after another whatever they declared, and
the real edge is declared beside it: Task 2's own test asserts the row Task 1 draws — a counter
that reports `[]` only because the held row speaks cannot be written against a tree where it does
not — so Task 2 carries `after: Task 1` (C11, **PD2**).

Nothing in this plan widens the spec. Every `## In`, `## Out`, Choice and design section is carried
out as written, and the `## Acceptance tests` fences are copied into the Tasks byte for byte. Where
this plan has something of its own to say it is a measurement, in the Decisions below: the spec's
line anchors have drifted (**PD3**), two of its preconditions reproduce only on a fixture cut the
Preconditions table does not spell out (**PD4**, **PD6**), and one case the design is silent about
gains a row (**PD5**).
