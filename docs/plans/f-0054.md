# Plan F-0054 — the class is decided before anything is launched again

Epic: E-0001 — ASF 0.1 — a working factory. Spec: `docs/specs/f-0054.md` (approved). Branch:
`plan/F-0054`.

Seven Tasks, cut by the spec's own §2 sections — the module that gains the surface, then the two
callers that route on it, then the read. Task 1 is the pure classifier (§2.1), Task 2 the three
pattern constants that become references plus the counter the classes are counted in (§2.2, §2.8's
first half), Task 3 the session's last beat and the class on every stall line (§2.3, §2.4),
Task 4 the credential stop, the lane it stops and the class of a refused launch (§2.6, §2.7,
§2.5's credential branch), Task 5 the quota route (§2.5's quota branch), Task 6 the transport
retry and the guard that a work failure is untouched (§2.5's two transport branches, §3.7),
Task 7 the read the card's third acceptance line is measured on (§2.8's second half).

**The wave order is one file: 1 → 2 → 3 → 4 → 5 → 6 → 7.** Nothing here runs in parallel, and that
is a consequence of the spec, not a choice — see PD4. Every Task after the first writes
`tests/test_failure.py`, because §3 puts all eight acceptance classes in that one module and names
them byte for byte in its fences; Tasks 4, 5 and 6 additionally write the same function,
`step_health.handle_dead`. Two Tasks whose `writes:` intersect queue, so the queue is the whole
plan.

§3.9's gate binds every Task, so every Gate below runs `python3 tools/run_tests.py`,
`tools/check_generic.sh` and `tools/check_conventions.sh` beside its own fence.

Every Task's **Acceptance** is the fence of §3 that the Task's Story names, copied byte for byte,
and every one of them is green at the end of that Task — that is the constraint the cut was
built to satisfy, and PD5 is where it moved a piece of §2.8 out of its own Task to hold.

### Task 1: `asf/failure.py` — four classes, three patterns, one policy
stories: S-29750
writes: asf/failure.py, tests/test_failure.py
after: none

§2.1: the whole classifier, pure. Stdlib only, importing nothing of `asf` — the property §3.1
asserts with `ast` over the module's own source, and the reason it can be imported by `runtime`,
`headroom`, `lifecycle`, `spawn`, `wave`, `stall`, `step_health` and a view alike (D1). Nothing
calls it yet: Task 2 is its first importer.

**Files**

- `asf/failure.py` — the module docstring §2.1 gives verbatim; `CREDENTIAL`, `QUOTA`,
  `TRANSPORT`, `WORK`, `CLASSES`, `RETRIES`; `AUTH_RE`, `MODEL_RE`, `PERMISSION_RE`,
  `AUTH_ENV_RE`, `CREDENTIAL_RE`, `QUOTA_RE`, `TRANSPORT_RE`, `SIGNATURE_CLASS`,
  `ACCOUNT_SCOPE_RE`; `of_signature`, `of_text`, `classify`, `retries`, `may_relaunch`, `label`,
  `operator_text`, `account_scoped`
- `tests/test_failure.py` — new module; `ClassTests`

**Steps**

1. `asf/failure.py` with §2.1's docstring copied as it stands, `import re` and nothing else.
   No `Product`, no `os`, no path literal, no product name — `tools/check_generic.sh` and
   `tools/check_conventions.sh` refuse all four, and `asf.size`, `asf.budget` and `asf.tokens`
   are the shape to follow.
2. The four class names and `CLASSES` in §2.1's order; `RETRIES = {CREDENTIAL: 0, QUOTA: 0,
   TRANSPORT: 1, WORK: None}` with §2.1's comment on why `work` is `None`.
3. The four credential patterns, split so `FAILURE_SIGNATURES` can keep its own three names
   (§2.2) and so PD7 holds:
   - `AUTH_RE` — `invalid api key|please run /login|authentication[_ ]error|oauth token`
   - `MODEL_RE` — `issue with the selected model|model .* (?:not found|does not exist)`
   - `PERMISSION_RE` — `permission denied|not permitted to use`, the pattern
     `runtime.FAILURE_SIGNATURES`' `permission` entry carries today, byte for byte
   - `AUTH_ENV_RE` — `auth_env \S+ file .* (?:does not exist|is empty|cannot be read)`
   - `CREDENTIAL_RE` — the union of `AUTH_RE`, `MODEL_RE`, `AUTH_ENV_RE` and
     `not permitted to use`: §2.1's literal exactly, and **not** `permission denied` (PD7). Its
     doc comment says so and names the reason, so nobody widens it back.
   All `re.I`, each with the doc comment §2.1 gives.
4. `QUOTA_RE` and `TRANSPORT_RE` byte for byte as §2.1 writes them — which is byte for byte what
   `headroom.LIMIT_RE` (`asf/workers/headroom.py:41`) and `lifecycle.NETWORK_RE`
   (`asf/workers/lifecycle.py:128`) hold today, so Task 2's rewiring is behaviour-free. Each
   carries the `:data:` cross-reference §2.1 shows.
5. `SIGNATURE_CLASS` exactly as §2.1's dict, thirteen names.
6. `of_signature(name)` — `SIGNATURE_CLASS.get(name)` over a stripped string, None for `''`,
   None, `finished` and any name the table does not hold. It never falls back to `work`: the
   caller's text is read instead, which is what makes an unknown signature safe.
7. `of_text(text)` — `CREDENTIAL_RE`, then `QUOTA_RE`, then `TRANSPORT_RE`, first match wins,
   None when none does. The order is the ranking §2.1 documents and §3.1 asserts.
8. `classify(signature=None, text='', default=WORK)` → `(cls, why)`: `of_signature` first
   (`why` = `f'signature {signature}'`), else `of_text` (`why` = `f'text: {cls}'`), else
   `(default, 'no signature')`. Pure, no clock, no io. `why` is built from a pattern or class
   *name* and never from `text` (D3) — that is the invariant, stated in the docstring.
9. `retries(cls)` → `RETRIES.get(cls)`; `may_relaunch(cls, tried)` → True for `WORK` at any
   `tried`, else `tried < (retries(cls) or 0)`.
10. `label(cls, why)` → `f'class {cls} ({why})'`, one owner for the suffix every failure line
    prints.
11. `operator_text(cls, product, item, job, lane='', why='')` — §2.1's sentence, in the shape its
    worked example gives: the product, the lane only as the caller passed it (the caller passes
    `lane-N`, never an account: PD16, PD18), the class and its `why`, the item and its job, and
    "was not relaunched". No path, no value, no matched text, and the clearing command is the
    console caller's to add beside it, never this string's.
12. `account_scoped(text)` → `bool(ACCOUNT_SCOPE_RE.search(text))`, matching the
    `worker account <name>` scope `AuthEnvError`'s message already carries
    (`asf/workers/runtime.py:337`) and not the product's `conventions.auth_env`. It is the
    text-only fallback; Task 4's own path reads `AuthEnvError.scope` (PD8).
13. `tests/test_failure.py` with `ClassTests`, §3.1 assertion by assertion: `of_signature` over
    every key of `SIGNATURE_CLASS`, then over `''`, `None`, `finished` and `wat`; `of_text` over
    the six strings §3.1 names; both ranking cases; `classify(signature='auth',
    text='connection reset')`; `classify(text='')`; `RETRIES`; `may_relaunch` at each of the five
    points; `label`; `operator_text` over an `AuthEnvError`-shaped message carrying an account
    name and an absolute home-directory path, asserting that neither the name nor the path nor
    any fragment of the input appears in the output; and that no `why` any function returns
    contains a character of matched text.
14. The import invariant: `ast.parse` over `asf/failure.py`'s own source, asserting no
    `Import`/`ImportFrom` node names `asf` or any `asf.` module.
