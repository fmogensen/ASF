## Stories

Three Stories, one per limb of the spec's `## The design`. Each is **declared** below as a
`### S-…: <title>` heading with its acceptance lines under it, before the Task that cites them: a
cited id with no card and no declaration is a phantom and the plan citing it is refused whole
(PD3). Every title is copied byte for byte from the spec's own `### S-…` heading.

The acceptance lines are the spec's claims rewritten backtick-free, one physical line each, for the
reason PD4 measures: `_prose` replaces every inline code span with one space before `CHECKBOX`
parses the line, so an identifier in backticks reaches the minted card missing and a wrapped line
reaches it truncated. No claim is added or dropped in the rewrite.

Nothing here is already true on the trunk: PD7 measures four of the five lane cases and the harvest
case red at this head, and the fifth is the pin that limb 1 must not break.

### S-91405: the lane never reads a branch with no diff as already on the trunk, and lands its proof commits

Limb 1 of the design. `already_on_trunk` answers a no-diff branch on `item_on_trunk` — the evidence
`empty_branch_landed` already demands of a branch with no commits of its own — instead of on a tree
test with nothing in it, and both of its callers take the change from the function (PD5). The branch
then walks the ordinary lane and its proof commit reaches the trunk, which is what makes the card
closeable and the row stop coming back.

- [ ] a branch whose only commit is empty has no touched files, and already_on_trunk answers False with no extras
- [ ] one lane pass over such a branch leaves it at the gate rather than merged, and records no on-trunk method
- [ ] the branch is still on origin after that pass, and no lane line says the branch is already on main
- [ ] the same branch, once a trunk commit names its item, still lands by the on-trunk method and is deleted, so the real on-trunk landing is not broken
- [ ] one harvest of a proof-only branch puts its commit subject on the trunk, records harvested at the sha the trunk holds, and deletes the branch only then
- [ ] a second harvest of the same product finds nothing left to do

### S-91406: a rebuild of a lane branch keeps every commit that was already empty

Limb 2. `drop_trunk_copies` drops a pick that adds nothing only when the commit itself carried
something — a change the trunk has caught up with. A commit that was empty against its own parent is
rebuilt as an empty commit, so neither of the two rebuild paths (`drop_copies` and
`rebase_onto_trunk`, PD5) deletes the evidence the record reads.

- [ ] a branch carrying one real commit and one empty proof commit rebuilds to both commits, in order, with none of them counted as empty
- [ ] a proof-only branch with the trunk merged into it rebuilds to the trunk plus its proof commit, its merge dropped
- [ ] a commit whose own change the trunk already holds under another patch is still dropped, and still counted as empty
- [ ] the lane test module runs whole and green, its report-commit and trunk-copy rebuild classes included

### S-91407: a branch whose diff against the trunk is empty spends no review round

Limb 3. A review verdict needs a diff to be a verdict about something. `review_waived` gains the
branch's diff as a last keyword parameter and answers for an empty one; the waiver is printed where
every other waiver is, in the record's own reason. A verdict already given still holds the branch —
the waiver skips asking for a round, never a refusal already on the head (PD5).

- [ ] review_waived called with an empty file list answers that there is no diff against the trunk and nothing to review
- [ ] with the code review required by convention, a proof-only branch walks to the gate carrying that waiver as its reason and asks for no review round
- [ ] a branch with a diff is unaffected, so the direct-lane waiver and the skip-under-lines waiver answer exactly as before
- [ ] the direct-lane test module runs whole and green with its five positional calls unchanged

## What changes for every later reader

No new record key, no new lane state, no new card field. What changes is which rows get written for
a proof-only branch. The run line's `state: MERGED` with `reason: method=on-trunk` and the trunk tip
as `sha` is replaced by the ordinary walk — `PUSHED`, `PR_OPEN`, `GATE`, then `MERGED` with the
product's own landing method and the sha the trunk now holds; `harvested:` becomes that sha
(measured `method=ff` on a branch behind the trunk, PD7). The trunk gains one empty commit whose
subject names the item, which is the row `asf.evidence.evidence.merge_facts` needs: PD5 traces why
it yields nothing today — `_needs_tip` is True for an `on-trunk` record and `_tip_on_main` is asked
about the deleted proof commit — so with the proof on the trunk the ordinary closing rule closes the
card, and `item_on_trunk` finds it if the item is ever cut again. `landed <b>: already on main at
<sha>` no longer appears for such a branch, and `review: none (no diff against the trunk: nothing to
review)` appears in the record's `reason` where a review round was required and is waived. The
rebuild's `dropped N trunk copies …` count stops including a commit that was already empty, so the
number tells the truth about what was dropped.
