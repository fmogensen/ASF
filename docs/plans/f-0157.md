# Plan F-0157 — a word for the outcome, the three readers taught to read it, the park wired to its switch

Epic: E-0001 — ASF 0.1 — a working factory. Spec: `docs/specs/f-0157.md` (approved). Branch: `plan/F-0157`.

Three Tasks, cut exactly the way the spec's `## Stories` are cut and the way `## The design` is
sectioned: **the word and the proof** (`NOTHING_TO_LAND`, the four vocabulary edits, `classify`,
`derive`, and `delivered_off_branch` — the pure judgement), **the three readers** (`delivered(run)`
swapped into `_settling_run`, `overruling` and `review_answered`, each proved reachable through the
lane and the feeder arms that read it), and **health** (the `elif` that rewrites the verdict, and the
one argument that arms `EMPTY_CAP`).

Task 1 owns `asf/workers/lifecycle.py`'s vocabulary half and `tests/test_lifecycle.py`. Task 2 owns
the three readers in those same two files, plus the two fence classes in `tests/test_harvest.py` and
`tests/test_feeder.py` — the lane and feeder arms are what make the readers *proved* reachable
rather than merely rewritten, so they belong to the Task that rewrites them. Task 3 owns
`asf/workers/health.py` and `tests/test_workers.py`, and touches neither of the other two.

Wave order: **1 → {2, 3}** — in `after:` terms, 1 with `none`, 2 after 1, 3 after 1. Tasks 2 and 3
share no file and run together. Both need Task 1 and only Task 1: Task 2 calls `delivered`, which
needs `NOTHING_TO_LAND`; Task 3's `elif` calls `lifecycle.delivered_off_branch` and writes
`lifecycle.NOTHING_TO_LAND`, both of which Task 1 lands, and its park argument `lifecycle.EMPTY`
already exists at `asf/workers/lifecycle.py:1860`.

§Acceptance tests' last two fences —
`python3 -m unittest tests.test_lifecycle tests.test_workers tests.test_harvest tests.test_feeder`
and the whole-tree fences — bind every Task, so every Gate and every Acceptance block below carries
them beside its own.

**The four things this plan corrects in the spec, two of which would ship a broken tree:** PD1 —
`OUTCOME_CLASSES` is indexed positionally by `outcome_class`, so *where* the new class goes in the
tuple is load-bearing and "beside `FINISHED`" silently breaks the empty-branch and dead-pid arms.
PD2 — a second test in `OutcomeClassTests` breaks and the spec names only one. PD3 —
`review_answered` never calls `finished()`; the swap is over an inline equality. PD5 — the spec's own
fence command cannot run, because `tools/check_generic.sh` is tracked non-executable. Read PD1 and
PD2 before Task 1 and PD3 before Task 2.

### Task 1: the word, and the proof — a fourth thing an ended run can be
stories: S-35900
writes: asf/workers/lifecycle.py, tests/test_lifecycle.py
after: none

The spec's first two **In** bullets, `## The design` §1 whole, and `delivered_off_branch` from §2 —
the pure half of §2; health's `elif` is Task 3. Plus the `EMPTY_CAP` comment (PD6). Nothing in the
factory behaves differently when this Task lands on its own: no caller writes the new `end_reason`
yet, `delivered_off_branch` has no caller, and `judge` is untouched, so every run still ends exactly
as it does today. That is the point — the vocabulary and the judgement land provable first, and the
two Tasks that change behaviour both build on them.

**Files**

- `asf/workers/lifecycle.py` — `NOTHING_TO_LAND` (beside `FINISHED`, `:112`); `OUTCOME_CLASSES`
  (`:150`); `FAILING_CLASSES` (`:153`); `SESSION_STATES` (`:162`); `outcome_class` (`:1589`);
  `classify` (`:1701`); `derive` (`:1775`); `delivered_off_branch`; `EMPTY_CAP`'s comment (`:1861`)
- `tests/test_lifecycle.py` — `NothingToLandTests`, `DeliveredOffBranchTests`; the two edits in
  `OutcomeClassTests` (`:1953-1954`, `:1956-1960`)

**Steps**

1. `asf/workers/lifecycle.py`, immediately below `FINISHED = 'finished'` (`:112`): the spec's
   constant with its four-line `#:` comment, byte for byte —

   ```python
   #: A session whose deliverable was never a commit, and which delivered it: not a failure, and not
   #: a landing. `finished` means "pushed commits"; this means "there was nothing to push, the session
   #: said so, and what it did produce is somewhere the branch cannot show" — an adjudicate ruling on
   #: the item's card, or a review finding the lane's own restack already cleared (F-0157).
   NOTHING_TO_LAND = 'nothing to land'
   ```

2. **PD1 — read it before this step.** `OUTCOME_CLASSES` (`:150`) gains `NOTHING_TO_LAND`
   **immediately before `OTHER`**, as the second-to-last element, and nowhere else. Not beside
   `FINISHED`. `outcome_class` indexes this tuple at `[2]` and `[3:-1]`; any earlier position shifts
   both and sends every `failed: empty branch: …` reason to `OTHER`, which regroups this card's own
   cause key — the one thing `## Out` forbids. The `#:` comment above the tuple gains a clause: it
   says today *"``finished`` is the only one that is not a failure"*, and that is no longer true.
3. `FAILING_CLASSES` (`:153`) becomes
   `tuple(c for c in OUTCOME_CLASSES if c not in (FINISHED, NOTHING_TO_LAND))`.
4. `SESSION_STATES` (`:162`) gains `NOTHING_TO_LAND`, after `FINISHED`. Its position is free here —
   nothing indexes this tuple; `tests/test_lifecycle.py:624` asserts every `classify` result's name
   is a member, which is why the constant has to be in it at all.
5. `outcome_class` (`:1589`): the early equality, directly under the `FINISHED` one at `:1596` —
   `if text == NOTHING_TO_LAND: return NOTHING_TO_LAND`. PD1's placement means the `[3:-1]`
   membership arm at `:1607` would already return it; the explicit line is the legible statement of
   a fact the slice makes by arithmetic, and it is what the spec asks for. Both are correct and they
   agree — do not delete either.
6. `classify` (`:1701`): one arm, directly under the `FINISHED` one at `:1706`, so it is decided
   before `is_dead_reason` and before the `FAILED` fall-through of P9 —
   `if reason == NOTHING_TO_LAND: return Status(NOTHING_TO_LAND, result=NOTHING_TO_LAND, source='ledger')`.
   `Status.label` needs no edit: its `return self.name` fall-through (`:1699`) prints
   `nothing to land` verbatim, which is what every view shows.
7. `derive` (`:1775`): beside `if status.result == FINISHED: return State(PUSHED, FINISHED, rounds)`,
   the same for the new outcome — `State(PUSHED, NOTHING_TO_LAND, rounds)`. PD10: `PUSHED`'s legal
   successors are `(HELD, LANDED)` and `ENDED`'s include `LAUNCHED`, so this is the state that
   cannot be read as "relaunch it".
8. `EMPTY_CAP`'s comment (`:1861`) loses `(conventions.empty_cap)` — the key does not exist (P7,
   re-verified) — and names `hold`'s own `empty_cap=` parameter instead. One line, PD6.
9. `delivered_off_branch(path, run, text)`, placed directly **after** `review_answered` (`:2122`):
   it reuses that function's REVIEW-hold lookup verbatim, and the module-level `CORRECT` (`:1942`)
   and `REVIEW` (`:2043`) it reads are both defined above that point. The spec's docstring byte for
   byte. The body, in this order:
   - `rep = report.parse(text or '')` — `from asf.workers import report as report_mod` inside the
     function, the way `overruling` already does it at `:665`;
   - return `None` unless `(rep.get('status') or '').strip().lower().split(' ')[0] == 'done'`, and
     `report_mod._claim(rep.get('commits'))` is falsy, and `report_mod.needs_input(text or '')` is
     falsy. That last clause is F-0126's blocked park keeping its win (`## Out`), belt and braces to
     Task 3's ordering;
   - then dispatch on `run.get('kind')`:
     - `'adjudicate'` → `ruling = report_mod.ruling(text or '')`; `f'ruling filed: {ruling[:60]}…'`
       when it is non-empty, else `None`. A ruling session with no ruling did fail, and
       `file_rulings` already marks it `adjudicated: none` (P3);
     - `CORRECT` → the item's latest `REVIEW` correction, found exactly as `review_answered` finds
       it (`:2107-2113`): every run's `correction`, kept where `kind == REVIEW` and `at` is truthy,
