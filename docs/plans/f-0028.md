# F-0028 — Prompt budget: four token dimensions itemised, never summed, with a cap per job — the plan

Binding spec: `docs/specs/f-0028.md`. This plan adds nothing it does not carry.

The spec's shape is a leaf module and four callers. `asf/tokens.py` is the meter, the cap table and
the verdict; nothing else reads a `usage` key. So the meter comes first, alone, and everything else
is a caller of it: the stop in `stall`, the four keys and the four columns in `metrics`, the
`token_caps:` block in the config files and doctor, and last the tick step that raises the cap and
ends the run in one pass.

Three of the five Tasks touch disjoint files and run together. The two that share
`tests/test_tokens.py` — the stop and the tick step — run one after the other, and they would have
had to anyway: the tick step calls `stall.capped`.

### Task 14650: the meter — four dimensions, one pass over a log, a cap table and a verdict

stories: S-14300, S-14302
writes: asf/tokens.py, asf/env.py, tests/test_tokens.py

**Files**

- `asf/tokens.py` (new): `DIMENSIONS`, `USAGE_KEYS`, `DEFAULT_CAPS`, `STOP_GRACE_S`,
  `TokenCapError`, `usage_of`, `Meter`, `meter`, `of_result`, `caps`, `cap_for`, `over`,
  `cap_text`, `cap_result`.
- `asf/env.py`: `PRODUCT_FIELDS['token_caps'] = _MAP`, and nothing else (PD6).
- `tests/test_tokens.py` (new): `UsageTest`, `MeterTest`, `CapsTest`. The later Tasks add
  `CapStopTest` and `HealthStepTest` to the same file.

**Steps**

1. The module docstring says what the module is for in the card's own words: four dimensions,
   never summed, one pass, one cap table. It imports `asf.env` and the stdlib only (PD7).
2. The four constants exactly as the spec's design block writes them — `DIMENSIONS`, `USAGE_KEYS`,
   `DEFAULT_CAPS`, `STOP_GRACE_S`. `DEFAULT_CAPS` carries the `default` row only; D12's numbers are
   runaway ceilings and the comment beside them says so.
3. `usage_of(rec)`: `rec['message']['usage']` for `rec.get('type') == 'assistant'`, `rec['usage']`
   for `'result'`, `{}` otherwise; a non-dict `rec` or a non-dict usage is `{}`. Each dimension is
   `u.get(USAGE_KEYS[d])` when that is an `int` (and not a `bool`) and `>= 0`, else `None` — `0`
   stays `0` (D4), a negative and a string are both `None`.
4. `Meter` as a dataclass with `result`, `by_dim`, `lines`, `runs`. `meter(log_path)` opens the file
   once with `errors='replace'` and walks it: a `system`/`init` line sets `result = None`, resets the
   tally to four `None`s and adds one to `runs`; an `assistant` line folds `usage_of` into the tally
   (a dimension stays `None` until the first number arrives, then accumulates); a `result` line is
   kept. A blank line, a `JSONDecodeError` and a non-dict record are skipped, and a missing or
   unreadable file gives `Meter(None, four Nones, 0, 0)`. It never raises.
5. After the walk: when `result` is not None and `usage_of(result)` has at least one dimension that
   is not `None`, that dict *replaces* the tally wholesale (D2). Nothing adds the two.
6. `of_result(rec)` is `usage_of(rec)` under a name that says what the caller has.
7. `caps(product)`: read `product.data.get('token_caps')` (`None` → `DEFAULT_CAPS` copied). Collect
   **every** bad entry before raising, in the order the spec's four rules list them, and join them
   into one `TokenCapError` — a block with five faults names five. Then merge: per kind, the
   `default` row under the built-in `default`, and the kind's own row over that. `off` (the string
   `_scalar` leaves, `env.py:33-46`) becomes `None`.
8. `cap_for(product, kind)`: the kind's resolved row, else `default`'s, else four `None`s.
9. `over(by_dim, cap)`: walk `DIMENSIONS` in order and return the first
   `(dimension, tokens, limit)` whose tally is an `int` strictly greater than an `int` cap; a `None`
   on either side is never over. Order is the tie-break, so the verdict is deterministic.
10. `cap_text` and `cap_result` exactly as the spec's design block writes them. `cap_result`'s
    `usage` is built from `by_dim` through `USAGE_KEYS`, omitting a `None` dimension, and it carries
    no `duration_ms` and no `total_cost_usd`.
11. `env.PRODUCT_FIELDS` gains `'token_caps': _MAP`. `NESTED_FIELDS` does not (PD6).
12. `tests/test_tokens.py`: the three classes below. A log fixture is a temp file written line by
    line with `json.dumps`; nothing here needs an `ASF_HOME`, a registry or a process.

### Task 14651: the stop — a run over any one dimension is signalled, gets a cap result line, and is marked on its registry line

stories: S-14303
writes: asf/workers/stall.py, asf/workers/runtime.py, asf/workers/lifecycle.py, tests/test_tokens.py

Depends on T-14650: `capped` is `tokens.meter` + `tokens.over` + `tokens.cap_result`.

**Files**

- `asf/workers/stall.py`: `_signal`, `stop_session`, `capped`; the module docstring gains the cap's
  half of "a live session the factory must end". One new module-level import (PD7).
- `asf/workers/runtime.py`: `failure_reason`'s first clause.
- `asf/workers/lifecycle.py`: `'capped'` in `RUN_FIELDS` (PD10).
- `tests/test_tokens.py`: `CapStopTest`.

**Steps**

1. `runtime.failure_reason(rec)` gains, before the text signatures, exactly the spec's clause: an
   `asf` value that is a dict whose `cap` is a dict returns `'token cap'`. The docstring gains one
   sentence saying the structured field is read first and why (D9: a session's own report text
   lands in `result` and is forgeable; the factory's field is not). `result_ok` is untouched — it is
   already False for an `is_error` record.
2. `lifecycle.RUN_FIELDS` gains `'capped'`, so a cap never folds onto the next run of the same job
   (B-0041).
3. `stall._signal(pid, sig)`: `os.killpg(os.getpgid(int(pid)), sig)`. The one line a test patches
   (PD5).
4. `stall.stop_session(session, alive, grace_s=tokens.STOP_GRACE_S)`: `_signal(pid, SIGTERM)`, then
   poll `alive(pid)` every 0.5 s up to `grace_s`, then `_signal(pid, SIGKILL)` if it is still there.
   `ProcessLookupError` and `PermissionError` are caught and are not errors — the run is gone or is
   not ours, and the caller still writes the cap line.
5. `stall.capped(product, now=None, alive=None, caps=None, stop=True, out=print)`, the spec's eight
   numbered steps in order:
   1. `caps` defaults to `tokens.caps(product)`; a `TokenCapError` prints `token cap: <why>` and
      returns `[]` — nothing signalled, nothing appended, every other health duty untouched (D13).
   2. `live = pool_mod.live_sessions(product)`; `alive` defaults to
      `health_mod.alive_for(product, live)` (PD9). For each session, `m = tokens.meter(s['log'])`;
      `m.result is not None` → skip, whatever it spent.
   3. `tokens.over(m.by_dim, tokens.cap_for(product, metrics_mod.session_kind(s)))`; `None` → skip.
   4. `alive(s['pid'])` is False → nothing is signalled and the run is left to health's `dead pid`
      path.
   5. `stop` → `stop_session(s, alive)`.
   6. `runtime_mod.read_result(s['log'])` again. Still `None` → append one line,
      `tokens.cap_result(kind, dimension, tokens_, limit, m.by_dim, now)`. A result that arrived in
      the meantime is left alone and the row carries a `finished first` detail instead.
   7. `pool_mod.update_session(product, s['job'], capped={'dimension': …, 'tokens': …,
      'limit': …, 'at': now})`.
   8. `out(f'CAP   {job}  {dimension} {tokens} over {limit} ({kind})')` per row, and `cap: none`
      when there are none.
   The return is `[(job, dimension, tokens, limit)]`, in `live_sessions` order.
6. `CapStopTest` as below. Its fixtures are `tests/test_workers.py`'s `Home` (a temp `ASF_HOME`) with
   a registry written through `pool_mod.append_session` and a hand-written job log; `_signal` is
   patched, so no real process is ever signalled and the runner's own pid is never used.
